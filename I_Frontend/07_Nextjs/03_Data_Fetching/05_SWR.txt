1. WHAT IS SWR?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

SWR (Stale-While-Revalidate) is a React hooks library built by Vercel for
client-side data fetching. The name comes from the HTTP cache-control strategy:
"serve stale data, then revalidate in the background".

  Install: npm install swr

Core features:
  - Automatic caching (same key = same data, deduplication)
  - Auto-revalidation (on focus, reconnect, interval)
  - Loading and error states
  - Mutations and optimistic updates
  - Pagination and infinite loading
  - SSR/SSG pre-population
  - TypeScript support

2. BASIC USAGE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  'use client';
  import useSWR from 'swr';

  // Fetcher function — global or per-request
  const fetcher = (url: string) => fetch(url).then(res => {
    if (!res.ok) throw new Error('Network error');
    return res.json();
  });

  interface User {
    id: string;
    name: string;
    email: string;
  }

  function UserProfile({ userId }: { userId: string }) {
    const { data, error, isLoading, isValidating, mutate } = useSWR<User>(
      `/api/users/${userId}`,  // cache key (also the URL here)
      fetcher,
      {
        // Options:
        revalidateOnFocus: true,     // re-fetch when window is focused
        revalidateOnReconnect: true, // re-fetch when browser reconnects
        revalidateIfStale: true,     // re-fetch if data is stale
        refreshInterval: 0,          // poll every N ms (0 = disabled)
        dedupingInterval: 2000,      // deduplicate requests within 2s window
        errorRetryCount: 3,          // retry on error
      }
    );

    if (isLoading) return <Skeleton />;
    if (error) return <ErrorMessage error={error} />;
    if (!data) return null;

    return (
      <div>
        <h1>{data.name}</h1>
        <p>{data.email}</p>
        <button onClick={() => mutate()}>Refresh</button>
      </div>
    );
  }

3. SWR KEY — THE CACHE KEY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

The first argument is the key — used as the cache key AND passed to the fetcher.
Identical keys across components are deduplicated (only one request).

  // String key
  useSWR('/api/users', fetcher);

  // Array key (useful for dynamic data)
  useSWR(['/api/users', page, filter], ([url, page, filter]) =>
    fetch(`${url}?page=${page}&filter=${filter}`).then(r => r.json())
  );

  // Null key = disable fetch
  const { data } = useSWR(userId ? `/api/users/${userId}` : null, fetcher);

  // Function key (re-evaluated; if throws, disables fetch)
  const { data } = useSWR(
    () => (isLoggedIn ? `/api/profile` : null),
    fetcher
  );

  // Deduplication: if two components use the same key at the same time,
  // SWR fires only ONE request and shares the result
  function Header() { const { data } = useSWR('/api/user', fetcher); }
  function Sidebar() { const { data } = useSWR('/api/user', fetcher); }
  // Only ONE fetch to /api/user

4. MUTATIONS (useSWRMutation + mutate)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

A) Local mutate (revalidate and update local data):
  const { data, mutate } = useSWR('/api/user', fetcher);

  // Revalidate (re-fetch from server)
  await mutate();

  // Optimistic update (update UI immediately, then revalidate)
  await mutate(
    async (currentUser) => {
      const updatedUser = await updateUser({ name: 'Alice' });
      return updatedUser;
    },
    { optimisticData: { ...data, name: 'Alice' }, rollbackOnError: true }
  );

B) Global mutate (invalidate by key from anywhere):
  import { mutate } from 'swr';

  // Invalidate a specific key (re-fetch on next access)
  await mutate('/api/user');

  // Invalidate all keys matching a pattern
  await mutate(key => typeof key === 'string' && key.startsWith('/api/users'));

C) useSWRMutation (for POST/PUT/DELETE operations):
  import useSWRMutation from 'swr/mutation';

  async function updateUser(url: string, { arg }: { arg: Partial<User> }) {
    return fetch(url, {
      method: 'PUT',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify(arg),
    }).then(r => r.json());
  }

  function EditProfile() {
    const { trigger, isMutating } = useSWRMutation('/api/user', updateUser);

    async function handleSubmit(formData: Partial<User>) {
      try {
        const updatedUser = await trigger(formData);
        // SWR automatically revalidates '/api/user' after mutation
      } catch (error) {
        console.error(error);
      }
    }

    return <form onSubmit={...}>{/* ... */}</form>;
  }

5. GLOBAL CONFIGURATION (SWRConfig)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  // app/layout.tsx (or pages/_app.tsx)
  'use client';
  import { SWRConfig } from 'swr';

  const globalFetcher = (url: string) =>
    fetch(url, {
      headers: { Authorization: `Bearer ${getToken()}` },
    }).then(res => {
      if (!res.ok) throw new Error(res.statusText);
      return res.json();
    });

  export function SWRProvider({ children }: { children: React.ReactNode }) {
    return (
      <SWRConfig
        value={{
          fetcher: globalFetcher,        // default fetcher for all useSWR calls
          revalidateOnFocus: false,      // don't re-fetch on tab focus (optional)
          errorRetryCount: 2,            // retry errors 2 times
          onError: (error, key) => {
            console.error(`SWR error for ${key}:`, error);
          },
          onErrorRetry: (error, key, config, revalidate, { retryCount }) => {
            if (error.status === 404) return;   // don't retry 404s
            if (retryCount >= 3) return;        // max 3 retries
            setTimeout(() => revalidate({ retryCount }), 5000);
          },
        }}
      >
        {children}
      </SWRConfig>
    );
  }

  // pages/_app.tsx (Pages Router)
  export default function App({ Component, pageProps }) {
    return (
      <SWRConfig value={{ fallback: pageProps.fallback ?? {} }}>
        <Component {...pageProps} />
      </SWRConfig>
    );
  }

  // pages/profile.tsx
  export const getServerSideProps = async (ctx) => {
    const user = await getUser(ctx.req.cookies.token);
    return {
      props: {
        fallback: {
          '/api/user': user,  // key → initial data
        },
      },
    };
  };

  // In the component — SWR uses server data as initial, then revalidates

    const { data: user } = useSWR('/api/user', fetcher);

7. INFINITE LOADING (useSWRInfinite)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  import useSWRInfinite from 'swr/infinite';

  const PAGE_SIZE = 10;

  function PostList() {
    const { data, size, setSize, isLoading, isValidating } = useSWRInfinite(
      (pageIndex, previousPageData) => {
        if (previousPageData && !previousPageData.length) return null; // end
        return `/api/posts?page=${pageIndex}&limit=${PAGE_SIZE}`;
      },
      fetcher
    );

    const posts = data?.flat() ?? [];
    const isEnd = data?.[data.length - 1]?.length < PAGE_SIZE;

    return (
      <div>
        {posts.map(post => <PostCard key={post.id} post={post} />)}
        {!isEnd && (
          <button onClick={() => setSize(size + 1)} disabled={isValidating}>
            Load More
          </button>
        )}
      </div>
    );
  }

Q1: What is SWR and what problems does it solve?
A:  SWR is a data-fetching hook library that solves: (1) request deduplication
    (multiple components with same key = one request), (2) automatic caching
    (data persists between renders), (3) background revalidation (auto-refresh
    on focus/reconnect), (4) loading/error state boilerplate, (5) race conditions.

Q2: What does "stale-while-revalidate" mean in SWR?
A:  When data is requested, SWR immediately returns the cached (possibly stale)
    data so the UI renders instantly, while simultaneously fetching fresh data
    in the background. Once the fresh data arrives, the UI updates. Users always
    see content immediately — no loading spinner on repeated visits.

Q3: How does SWR handle request deduplication?
A:  If multiple components call useSWR with the same key within the deduping
    interval (default 2s), SWR fires only ONE fetch and shares the response with
    all subscribers. This is a huge performance win for shared data like user
    info, which might be needed in header, sidebar, and main content simultaneously.

Q4: When would you use useSWRMutation instead of the regular mutate function?
A:  useSWRMutation is for triggered mutations (POST/PUT/DELETE) that shouldn't
    fire on component mount — only when explicitly triggered (e.g., button click).
    It provides isMutating state and doesn't auto-revalidate until trigger() is
    called. The bound mutate() function from useSWR is for re-validating existing
    data (re-fetching GET requests).

Q5: How do you pre-populate SWR with server-side data to avoid loading flicker?
A:  Pass data through fallback in SWRConfig. In getServerSideProps or
    getStaticProps, fetch the data and pass it via pageProps. In _app.tsx,
    wrap with <SWRConfig value={{ fallback: pageProps.fallback }}>.
    SWR will use this as initial data and revalidate in background.

Q6: What is the difference between isLoading and isValidating in SWR?
A:  isLoading: true when there is no data yet AND the request is in flight
              (true on first load, false once any data is available)
    isValidating: true whenever a request is in flight (first load OR background
              revalidation — even if data is already available)
    Use isLoading for skeleton UIs; use isValidating for subtle refresh indicators.
