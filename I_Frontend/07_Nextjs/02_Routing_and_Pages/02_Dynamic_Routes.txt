1. WHAT ARE DYNAMIC ROUTES?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Dynamic routes allow a single page/component to match multiple URL paths.
Instead of creating one file per product, you create one file with a dynamic
segment in brackets: [id] or [slug].

  pages/products/[id].tsx    matches → /products/1, /products/42, /products/abc
  app/products/[id]/page.tsx matches → /products/1, /products/42, /products/abc

Dynamic segments are replaced by the actual URL value at runtime.

2. DYNAMIC ROUTES IN PAGES ROUTER
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

File: pages/products/[id].tsx

  import { useRouter } from 'next/router';

  export default function ProductPage() {
    const router = useRouter();
    const { id } = router.query;  // 'id' matches the [id] segment name

    return <h1>Product: {id}</h1>;
  }

Accessing multiple dynamic segments:
  // pages/shop/[category]/[id].tsx → /shop/electronics/42
  const { category, id } = router.query;
  // category = 'electronics', id = '42'

3. DYNAMIC ROUTES IN APP ROUTER
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

File: app/products/[id]/page.tsx

  // Server Component (default) — params passed as prop
  interface Props {
    params: { id: string };
    searchParams: { [key: string]: string | string[] | undefined };
  }

  export default async function ProductPage({ params, searchParams }: Props) {
    const product = await getProduct(params.id);
    return <h1>{product.name}</h1>;
  }

  // Client Component — use useParams() hook
  'use client';
  import { useParams } from 'next/navigation';

  export default function ProductPage() {
    const { id } = useParams<{ id: string }>();
    return <h1>Product: {id}</h1>;
  }

IMPORTANT: In Next.js 15, params is now a Promise (async):
  export default async function ProductPage({
    params,
  }: {
    params: Promise<{ id: string }>;
  }) {
    const { id } = await params;  // must await
    const product = await getProduct(id);
    return <h1>{product.name}</h1>;
  }

4. generateStaticParams — STATIC GENERATION FOR DYNAMIC ROUTES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

App Router equivalent of getStaticPaths. Tells Next.js which param values
to pre-render at build time.

  // app/products/[id]/page.tsx
  export async function generateStaticParams() {
    const products = await fetch('https://api.example.com/products').then(r => r.json());

    return products.map((product) => ({
      id: String(product.id),
    }));
  }

  export default async function ProductPage({ params }) {
    const product = await getProduct(params.id);
    return <h1>{product.name}</h1>;
  }

Dynamic params behavior (dynamicParams):
  export const dynamicParams = true;   // (default) generate on-demand if not
                                        // in generateStaticParams list
  export const dynamicParams = false;  // 404 for params not in the list

Nested dynamic params:
  // app/shop/[category]/[id]/page.tsx
  export async function generateStaticParams() {
    const categories = await getCategories();
    // Return all combinations
    return categories.flatMap(cat =>
      cat.products.map(p => ({ category: cat.slug, id: String(p.id) }))
    );
  }

5. getStaticPaths — PAGES ROUTER EQUIVALENT
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Required when using getStaticProps with dynamic routes in Pages Router.

  // pages/products/[id].tsx
  export async function getStaticPaths() {
    const products = await fetch('/api/products').then(r => r.json());
    return {
      paths: products.map(p => ({ params: { id: String(p.id) } })),
      fallback: false,       // 404 for unknown paths
      // fallback: true,     // show fallback UI while generating
      // fallback: 'blocking' // SSR-like generation, no fallback UI
    };
  }

  export async function getStaticProps({ params }) {
    const product = await fetch(`/api/products/${params.id}`).then(r => r.json());
    return {
      props: { product },
      revalidate: 60,  // ISR
    };
  }

fallback values explained:
  false        → Only pre-generated paths exist; others return 404
  true         → Unknown paths show fallback UI (router.isFallback = true)
                 while Next.js generates the page in background
  'blocking'   → Unknown paths cause SSR-like generation (no fallback UI,
                 user waits); then cached like static

7. ROUTE PRIORITY & CONFLICTS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Static routes take priority over dynamic routes:
  pages/products/featured.tsx  → /products/featured  (MATCHES FIRST)
  pages/products/[id].tsx      → /products/:id        (fallback)

  /products/featured → uses featured.tsx (static wins)
  /products/42       → uses [id].tsx

Nested dynamic vs static:
  app/users/me/page.tsx         → /users/me  (static wins)
  app/users/[username]/page.tsx → /users/:username (dynamic fallback)

Parallel routes with dynamic segments:
  app/@modal/(.)products/[id]/page.tsx → intercepted dynamic route

8. GENERATE METADATA FOR DYNAMIC ROUTES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  // app/products/[id]/page.tsx
  import type { Metadata } from 'next';

  export async function generateMetadata({ params }): Promise<Metadata> {
    const product = await getProduct(params.id);
    return {
      title: `${product.name} | Shop`,
      description: product.description,
      openGraph: {
        title: product.name,
        images: [{ url: product.image }],
      },
    };
  }

generateMetadata runs on the server, can fetch data, and generates SEO tags
per dynamic page — essential for e-commerce and blog SEO.

9. NOT-FOUND HANDLING FOR DYNAMIC ROUTES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  // app/products/[id]/page.tsx
  import { notFound } from 'next/navigation';

  export default async function ProductPage({ params }) {
    const product = await getProduct(params.id);
    if (!product) notFound();   // Renders not-found.tsx in the nearest scope
    return <h1>{product.name}</h1>;
  }

  // app/products/not-found.tsx (product-specific 404)
  export default function ProductNotFound() {
    return <h1>Product not found!</h1>;
  }

10. COMMON INTERVIEW QUESTIONS & ANSWERS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q1: How do you create a dynamic route in Next.js?
A:  Wrap a segment in square brackets: [id] in the folder/file name.
    Pages Router: pages/products/[id].tsx — access via router.query.id
    App Router: app/products/[id]/page.tsx — access via params.id prop

Q2: What is getStaticPaths and why is it needed?
A:  When you use getStaticProps with a dynamic route, Next.js needs to know
    which paths to pre-render at build time. getStaticPaths returns an array
    of params objects and a fallback strategy. Without it, Next.js doesn't
    know how many pages to generate.

Q3: Explain the fallback options in getStaticPaths.
A:  false: any path not in the list returns 404
    true: unknown paths show fallback UI (isFallback=true) while page is
          generated server-side in background; cached for future requests
    'blocking': unknown paths are server-side rendered on first request
          (no fallback UI, user sees loading), then cached statically.
    Use 'blocking' or true for large datasets where you can't generate all
    paths at build time.

Q4: What is the App Router equivalent of getStaticPaths?
A:  generateStaticParams(). It returns an array of param objects. Combined
    with dynamicParams = true (default), any path not returned by
    generateStaticParams is still rendered on-demand (ISR-like behavior).

Q5: How does route priority work when you have both /users/me and /users/[id]?
A:  Static routes take priority. /users/me will always match the static
    users/me/page.tsx (or pages/users/me.tsx), while /users/alice will
    match the dynamic [id] route.

Q6: How do you handle 404 for a dynamic route if the ID doesn't exist in DB?
A:  App Router: call notFound() from 'next/navigation' inside the Server
    Component after a failed DB lookup. This renders the nearest not-found.tsx.
    Pages Router: return { notFound: true } from getStaticProps or
    getServerSideProps.

Q7: What changed in Next.js 15 regarding dynamic route params?
A:  In Next.js 15, params and searchParams became async (Promises). You must
    await them: const { id } = await params; This aligns with the async-first
    model of App Router and allows for future optimizations.
