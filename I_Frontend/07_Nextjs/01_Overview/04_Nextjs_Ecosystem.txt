2. VERCEL — THE OFFICIAL PLATFORM
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

What is Vercel?
  - Cloud platform created by the same team that built Next.js
  - Optimized specifically for Next.js (first-class support)
  - Serverless functions, Edge functions, CDN, analytics built-in

Key Vercel Features for Next.js:
  1. Automatic deploys from Git (push to main → production deploy)
  2. Preview deployments for every PR/branch
  3. Edge Network — 70+ global PoPs for static assets
  4. Serverless Functions — API routes auto-deployed as Lambdas
  5. Edge Functions — Middleware runs at Edge, not cold-start Lambda
  6. ISR support — Vercel's KV-backed ISR revalidation
  7. Image Optimization API — automatic WebP/AVIF, caching
  8. Analytics — Web Vitals, audience metrics
  9. Speed Insights — real-user monitoring
  10. Blob, KV, Postgres, Queue — Vercel Storage products

Vercel vs Self-Hosting:
  Vercel:
    ✓ Zero config, automatic scaling
    ✓ ISR and Middleware work perfectly out of the box
    ✓ Preview environments for every PR
    ✗ Can be expensive at scale
    ✗ Vendor lock-in risk

  Self-hosted (Docker + Node.js):
    ✓ Full control, no vendor lock-in
    ✓ Cost predictable at scale
    ✗ Must configure ISR, image optimization manually
    ✗ Need to manage your own CDN/infrastructure

  next.config.js for standalone Docker output:
    output: 'standalone'  // Creates a minimal Docker-ready build

3. DATABASE & ORM ECOSYSTEM
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

A) PRISMA (most popular ORM for Next.js)
   - Type-safe ORM with auto-generated TypeScript types from schema
   - Works with PostgreSQL, MySQL, SQLite, MongoDB, SQL Server
   - Prisma Client used in Server Components and API routes

   // lib/prisma.ts
   import { PrismaClient } from '@prisma/client';
   const globalForPrisma = global as unknown as { prisma: PrismaClient };
   export const prisma = globalForPrisma.prisma || new PrismaClient();
   if (process.env.NODE_ENV !== 'production') globalForPrisma.prisma = prisma;

   // Server Component usage
   const users = await prisma.user.findMany({ where: { active: true } });

B) DRIZZLE ORM (fast-growing alternative)
   - Lightweight, SQL-like syntax, TypeScript-first
   - Extremely fast (closer to raw SQL)
   - Works well with Edge (serverless-friendly)

C) MANAGED DATABASES:
   - Neon (serverless PostgreSQL, great with Next.js + Edge)
   - PlanetScale (serverless MySQL, branching model)
   - Supabase (PostgreSQL + Auth + Storage + Realtime)
   - Turso (SQLite at the edge via libSQL)
   - MongoDB Atlas (document database, Mongoose ORM)
   - Upstash Redis (serverless Redis, used for rate limiting, caching)

4. AUTHENTICATION ECOSYSTEM
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

A) NEXT-AUTH / AUTH.JS (v5) — most popular
   - Open-source, supports 50+ OAuth providers (Google, GitHub, etc.)
   - JWT or database sessions
   - Works with both Pages and App Router
   - Middleware integration for protected routes

   // auth.ts (Auth.js v5)
   import NextAuth from 'next-auth';
   import GitHub from 'next-auth/providers/github';
   export const { handlers, signIn, signOut, auth } = NextAuth({
     providers: [GitHub],
   });

   // middleware.ts — protect routes
   export { auth as middleware } from './auth';
   export const config = { matcher: ['/dashboard/:path*'] };

B) CLERK
   - Fully managed auth with prebuilt UI components
   - Drop-in solution (no auth logic to write)
   - Supports MFA, org management, social logins
   - Slightly opinionated but fastest time-to-production

C) LUCIA AUTH
   - Minimal, framework-agnostic auth library
   - Full control over auth logic
   - Good for learning how auth works under the hood

D) SUPABASE AUTH
   - Part of Supabase ecosystem
   - JWT-based, Row Level Security (RLS) integration
   - Good if already using Supabase DB

5. STYLING ECOSYSTEM
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

A) TAILWIND CSS — industry standard with Next.js
   - Utility-first CSS framework
   - PostCSS plugin, works with Next.js natively
   - JIT compilation — only generates CSS that is used
   - Used by shadcn/ui, Radix Themes, and most modern Next starters

B) CSS MODULES (built-in)
   - Scoped CSS, no class conflicts
   - Zero runtime overhead
   - Supported out of the box in Next.js

C) SHADCN/UI — component collection
   - NOT a component library — you copy components into your project
   - Built on Radix UI primitives + Tailwind CSS
   - Fully customizable, accessible
   - Extremely popular in Next.js App Router projects

D) CSS-IN-JS (styled-components, emotion)
   - Requires special config with Next.js App Router (RSC doesn't support
     runtime CSS-in-JS)
   - Must use "use client" for styled-components
   - Consider Vanilla Extract or Linaria as RSC-compatible alternatives

E) VANILLA EXTRACT
   - Type-safe, zero-runtime CSS-in-TS
   - Works with Server Components

6. STATE MANAGEMENT ECOSYSTEM
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

With App Router / RSC, state management needs have changed:
  - Server state (data from DB/API) → Server Components + TanStack Query
  - Client state (UI state, forms) → useState, Zustand, Jotai

A) TANSTACK QUERY (formerly React Query)
   - Server state management: caching, refetching, deduplication
   - Works on client side; integrates with Next.js for SSR hydration
   - Ideal for data that needs background refetching

B) ZUSTAND
   - Lightweight client state (global UI state, user preferences)
   - Works seamlessly with Next.js (no context providers needed)
   - Works with App Router without issues

C) JOTAI
   - Atomic state management
   - Very simple API, minimal boilerplate

D) REDUX TOOLKIT
   - Large-scale apps with complex client state
   - Requires client-side providers (works with App Router via 'use client')

E) REACT CONTEXT (built-in)
   - Simple cases; requires 'use client' in App Router for context providers

7. DATA VALIDATION & FORMS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

A) ZOD — most popular schema validation
   - TypeScript-first schema validation
   - Used with Server Actions, API routes, tRPC
   - Runtime type checking from TypeScript schemas

   import { z } from 'zod';
   const UserSchema = z.object({
     name: z.string().min(1),
     email: z.string().email(),
     age: z.number().min(18),
   });
   type User = z.infer<typeof UserSchema>; // TypeScript type from schema

B) REACT HOOK FORM — most popular form library
   - Performance-first (minimal re-renders)
   - Works with Zod via @hookform/resolvers
   - Client Component (uses refs + state)

C) SERVER ACTIONS + ZOD (App Router pattern)
   // app/actions.ts
   'use server';
   export async function createUser(formData: FormData) {
     const validated = UserSchema.safeParse({
       name: formData.get('name'),
       email: formData.get('email'),
     });
     if (!validated.success) return { error: validated.error.flatten() };
     await db.users.create({ data: validated.data });
   }

8. API LAYER ECOSYSTEM
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

A) TRPC — end-to-end type-safe APIs
   - Define procedures on the server, call them from the client with full
     TypeScript type safety
   - No code generation, no schema files
   - Popular in T3 Stack (Next.js + tRPC + Prisma + Tailwind + Auth.js)

   // server procedure
   const appRouter = router({
     getUser: publicProcedure.input(z.string()).query(async ({ input }) => {
       return await prisma.user.findUnique({ where: { id: input } });
     }),
   });

   // client call (fully typed!)
   const { data: user } = trpc.getUser.useQuery(userId);

B) GRAPHQL — apollo-server, graphql-yoga
   - Rich querying, good for complex data graphs
   - GraphQL endpoint in API route handler

C) REST — vanilla fetch / axios
   - API routes as REST endpoints
   - Works great for simple CRUD

9. CMS (CONTENT MANAGEMENT) ECOSYSTEM
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Headless CMSs that pair well with Next.js:
  - Contentful (enterprise, API-first)
  - Sanity (real-time, great Dev UX, GROQ query language)
  - Strapi (self-hosted, Node.js, REST + GraphQL)
  - Payload CMS (open-source, self-hosted, TypeScript, works inside Next.js)
  - Hygraph (GraphQL CMS)
  - Keystatic (Git-based, Markdown/YAML, open-source)

Pattern: Next.js + Headless CMS + ISR
  - CMS hosts content (editors use CMS UI)
  - Next.js fetches content at build time → SSG
  - On publish → CMS triggers Next.js revalidation webhook → ISR updates
  - No rebuild needed on every content change

10. THE T3 STACK — POPULAR FULL-STACK TEMPLATE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  T3 Stack = Next.js + TypeScript + tRPC + Prisma + Tailwind CSS + NextAuth

  Created by Theo (t3.gg), extremely popular for full-stack TypeScript apps.
  Bootstrapped with: npx create-t3-app@latest

  Key principle: "typesafety is not optional"
  - End-to-end type safety from DB schema → API → UI
  - Minimal boilerplate, maximal productivity

11. BUILD & DEV TOOLS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

A) TURBOPACK (Vercel's new bundler, replacing Webpack)
   - 10x faster than Webpack in local dev (written in Rust)
   - Incremental builds — only rebuilds what changed
   - Enabled in Next.js 13+ dev mode: next dev --turbo
   - Production Turbopack is stable in Next.js 15

B) WEBPACK (legacy, still default production bundler pre-v15)
   - Configured via next.config.js webpack() function
   - Supports all webpack plugins/loaders

C) SWC (Speedy Web Compiler)
   - Rust-based compiler that replaces Babel in Next.js 12+
   - 17x faster compilation than Babel
   - Handles JSX, TypeScript, styled-components transforms
   - Configured via .swcrc or next.config.js swcMinify option

13. COMMON INTERVIEW QUESTIONS & ANSWERS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q1: What is Turbopack and why does it matter?
A:  Turbopack is a Rust-based bundler by Vercel that replaces Webpack in
    Next.js. It's up to 10x faster in development (incremental builds, only
    recompiles changed modules). Stable in Next.js 15 for production.

Q2: What is the T3 Stack and what problems does it solve?
A:  T3 Stack = Next.js + TypeScript + tRPC + Prisma + Tailwind + NextAuth.
    It solves the "boilerplate hell" of setting up a full-stack TypeScript app
    with end-to-end type safety. create-t3-app bootstraps everything in minutes.

Q3: Why is tRPC popular with Next.js?
A:  tRPC provides end-to-end type safety between your Next.js server (API
    routes/Server Actions) and client. No code generation, no schema files —
    just TypeScript. If you rename a backend procedure, TypeScript immediately
    flags the client call as broken. This eliminates a whole class of runtime
    errors.

Q4: How do you connect a database in Next.js?
A:  In development: use Prisma with a local PostgreSQL (or SQLite for quick
    prototyping). In production: connect to a managed database (Neon, Supabase,
    PlanetScale). In App Router, access Prisma Client in Server Components or
    API route handlers. Always use a singleton pattern for PrismaClient to avoid
    connection pool exhaustion in hot-reload dev.

Q5: What is SWC and how does it affect Next.js performance?
A:  SWC is a Rust-based JavaScript/TypeScript compiler that replaced Babel in
    Next.js 12. It's ~17x faster for compilation. It handles TypeScript
    transpilation, JSX transformation, and minification. It also has a SWC
    plugin API for custom transforms (e.g., styled-components, emotion).

Q6: How do you protect routes in Next.js?
A:  Multiple approaches:
    (1) Middleware: check auth token in middleware.ts, redirect if invalid
        (runs at Edge, most efficient — no page render for unauthorized users)
    (2) Server Components: check auth in layout.tsx, redirect() if not logged in
    (3) Client-side: check auth in component with useSession() (less secure)
    Best practice: Middleware for route-level protection + Server Component
    checks for data-level authorization.
