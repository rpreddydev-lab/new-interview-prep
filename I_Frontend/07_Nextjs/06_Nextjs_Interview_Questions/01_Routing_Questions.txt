SECTION 1: FILE-BASED ROUTING FUNDAMENTALS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: How does file-based routing work in Next.js App Router?
A: In the App Router, the directory structure under app/ defines routes.
   A folder named "blog" creates the /blog URL segment. A page.tsx file inside
   a folder is what renders at that URL. Special files like layout.tsx,
   loading.tsx, and error.tsx handle shared UI and states for that segment.
   Folders without a page.tsx do not create routes — they can be used for
   code organization (route groups, private folders).

Q: What is the difference between page.tsx and route.ts in a folder?
A: page.tsx renders UI for a URL (can have layouts, loading, error).
   route.ts creates an HTTP API endpoint. They CANNOT coexist in the same folder
   as they would conflict on the same URL path.

Q: What are route groups (folder with parentheses)?
A: Route groups use the (folderName) convention. The group name is excluded from
   the URL path. Used to: (1) organize routes without affecting URL structure,
   (2) apply different layouts to different groups of routes at the same path level,
   (3) enable multiple root layouts.
   Example: app/(marketing)/page.tsx and app/(dashboard)/dashboard/page.tsx —
   both can have different root layouts without affecting their URLs.

Q: What are private folders (underscore prefix)?
A: Folders prefixed with _ (e.g., _components) are excluded from the routing
   system entirely. Used to co-locate component, hook, or utility files alongside
   routes without accidentally creating URL paths.

Q: How does the Link component work for navigation?
A: <Link href="/blog"> renders as an <a> tag but intercepts clicks for client-side
   navigation (no full page reload). It automatically prefetches routes when the
   link enters the viewport (in production). Use prefetch={false} to disable.
   For navigation after events (form submit, etc.), use useRouter().push('/path').

SECTION 2: DYNAMIC ROUTES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: How do dynamic routes work in the App Router?
A: Create a folder with a name in square brackets: [id] or [slug].
   The folder name becomes the parameter name. Access it via the params prop:
   // app/products/[id]/page.tsx
   export default async function Page({ params }: { params: Promise<{ id: string }> }) {
     const { id } = await params; // Next.js 15: params is a Promise
   }

Q: What is generateStaticParams?
A: generateStaticParams replaces getStaticPaths from Pages Router.
   It returns an array of param objects to pre-render at build time.
   export async function generateStaticParams() {
     const posts = await getPosts();
     return posts.map(p => ({ slug: p.slug }));
   }
   At build time, each returned slug gets its own static HTML file.

Q: What happens when someone requests a path NOT returned by generateStaticParams?
A: Controlled by export const dynamicParams. Default: true → the page is rendered
   dynamically on-demand (like fallback: 'blocking' in Pages Router).
   Set to false → returns 404 for any ungenerated path.

Q: What is route priority when static and dynamic routes conflict?
A: Static routes take priority over dynamic: /blog/create (static segment)
   matches before /blog/[slug] (dynamic). More specific routes win over catch-all.

Q: Why must you await params in Next.js 15?
A: In Next.js 15, params (and searchParams) are Promises to support async
   param computation and streaming. You MUST await them:
   const { id } = await params;
   In Next.js 14, params was a plain object (no await needed).

SECTION 3: MIDDLEWARE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: What is Middleware and where does it run?
A: Middleware runs before every request is processed. It's a function in
   middleware.ts at the project root. It ALWAYS runs on Edge Runtime (V8 isolates
   at CDN edge). It can inspect/modify requests and responses: redirect, rewrite,
   add headers, set cookies.

Q: What can and can't you do in Middleware?
A: CAN: redirect, rewrite, add response headers, read/set cookies, read request
   body (limited), use Edge-compatible libraries (jose for JWT, Upstash for Redis).
   CANNOT: access Node.js APIs (fs, path, crypto), use Prisma, perform long-running
   DB queries (Middleware must be fast, runs on every request).

Q: How do you restrict Middleware to specific routes?
A: Export a config object with a matcher array:
   export const config = {
     matcher: ['/dashboard/:path*', '/admin/:path*'],
   };
   Matcher uses path patterns. Negative lookahead to exclude paths:
   matcher: ['/((?!api|_next|favicon.ico).*)']

Q: What is the difference between redirect and rewrite in Middleware?
A: redirect: changes the URL in the browser (302 by default) — user sees new URL.
   rewrite: internally rewrites the request to a different URL — user sees original URL.
   Use rewrite for A/B testing (show different content on the same URL) or
   proxying requests. Use redirect for auth protection, URL normalization.

Q: How do you pass data from Middleware to Server Components?
A: Via request headers. Middleware adds headers via request.headers (which is
   immutable — create a new Headers object):
   const requestHeaders = new Headers(request.headers);
   requestHeaders.set('x-user-id', userId);
   return NextResponse.next({ request: { headers: requestHeaders } });
   In Server Component: headers().get('x-user-id')

SECTION 4: NESTED LAYOUTS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: How do nested layouts work in the App Router?
A: Each directory can have a layout.tsx. Layouts are nested automatically.
   The root layout (app/layout.tsx) must include <html> and <body> tags.
   A layout at app/dashboard/layout.tsx wraps all routes under /dashboard/*.
   Layouts receive a children prop (the inner layout or page) and are persistent —
   they don't re-render on navigation within their segment.

Q: What is the difference between layout.tsx and template.tsx?
A: layout.tsx: persistent — does NOT re-render on navigation (maintains state,
   keeps context, preserves scroll position, doesn't remount).
   template.tsx: re-mounts on EVERY navigation — used when you need fresh state
   per route (e.g., enter animations, tracking page views via useEffect).

Q: How do you handle authentication at the layout level?
A: In a Server Component layout, call auth() or getServerSession() to check
   the session. If not authenticated, redirect():
   import { redirect } from 'next/navigation';
   export default async function DashboardLayout({ children }) {
     const session = await auth();
     if (!session) redirect('/login');
     return <div>{children}</div>;
   }

Q: How do you provide React context in App Router since the layout is a Server Component?
A: Create a Client Component provider ('use client') and wrap it around children
   in the layout. The provider is a Client Component but children (Server Components)
   can still be passed as RSC payload:
   // layout.tsx (Server Component)
   return <ThemeProvider>{children}</ThemeProvider>;
   // ThemeProvider.tsx ('use client') — Client Component provider

Q: How does error.tsx work?
A: error.tsx creates a React Error Boundary for its route segment.
   It MUST be a Client Component ('use client') to use the reset() function.
   It receives the error object and a reset() function (re-renders the segment).
   It catches errors thrown in page.tsx and child layouts.
   For root layout errors, use app/global-error.tsx.

SECTION 5: ADVANCED ROUTING
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: What is the difference between [...slug] and [[...slug]]?
A: [...slug]: required catch-all — /docs must have at least one segment.
   /docs itself would 404 (no match).
   [[...slug]]: optional catch-all — /docs matches with slug = undefined,
   /docs/a/b matches with slug = ['a', 'b'].

Q: What are Parallel Routes and how do you define them?
A: @folderName syntax creates a "slot" that the parent layout receives as a prop.
   Allows multiple pages to render simultaneously in the same layout:
   layout.tsx receives ({ children, @team }) → renders both side by side.
   Each slot has independent loading/error states.

Q: What are Intercepted Routes? Give a practical example.
A: Intercepted routes render a route in a different context during client-side
   navigation. (.) prefix intercepts at the same level. Classic example:
   Photo gallery — clicking a photo shows it in a modal (intercepted route @modal)
   while the underlying feed stays visible. Direct URL access or refresh shows
   the full photo page (not the modal).

Q: What hooks are available for navigation in App Router?
A: From 'next/navigation' (NOT 'next/router' which is Pages Router):
   - useRouter(): push(url), replace(url), back(), forward(), refresh()
   - usePathname(): current URL path as string
   - useSearchParams(): URLSearchParams object for query params
   - useParams(): dynamic route params as { key: string } object
   All are Client Component hooks (require 'use client').
