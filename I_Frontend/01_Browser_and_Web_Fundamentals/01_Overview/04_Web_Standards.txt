1. WHAT ARE WEB STANDARDS?
────────────────────────────────────────────────────────────────────────────────

Web standards are specifications and guidelines that ensure interoperability
across browsers, devices, and platforms. They define:
  • How HTML should be written and parsed
  • How CSS is applied
  • How JavaScript APIs work in browsers
  • How web resources are transmitted (HTTP)
  • Accessibility requirements

Without standards, each browser implements features differently, breaking
cross-browser compatibility.

2. STANDARDS ORGANIZATIONS
────────────────────────────────────────────────────────────────────────────────

  W3C (World Wide Web Consortium) — www.w3.org
    Founded: 1994 by Tim Berners-Lee
    Scope: HTML, CSS, SVG, WCAG, WebXR, Web Payments, Web Components
    Process: Working Draft → Candidate Recommendation → Recommendation
    Members: Google, Apple, Microsoft, Mozilla, Adobe, + thousands more

  WHATWG (Web Hypertext Application Technology Working Group)
    Founded: 2004 by browser vendors (Apple, Mozilla, Opera)
    Scope: "Living Standards" — HTML, DOM, Fetch, Encoding, URL, Streams
    Key insight: WHATWG publishes living standards (continuously updated)
                 W3C publishes versioned snapshots
    HTML5 started as a WHATWG spec; now jointly maintained
    NOTE: WHATWG's HTML spec is the primary reference for browsers

  TC39 (ECMA Technical Committee 39)
    Organization: Ecma International
    Scope: ECMAScript (JavaScript) language standard
    Process:
      Stage 0 → Strawperson (idea)
      Stage 1 → Proposal (formal spec needed)
      Stage 2 → Draft (complete spec)
      Stage 3 → Candidate (complete, needs real-world feedback)
      Stage 4 → Finished (ready for inclusion)
    Releases: Annual (ES2015/ES6, ES2016, ..., ES2025)

  IETF (Internet Engineering Task Force)
    Scope: Internet protocols (HTTP, TLS, DNS, QUIC, WebSocket)
    Documents: RFC (Request for Comments) — the official specifications
    Key RFCs:
      RFC 9110/9111 → HTTP Semantics and Caching
      RFC 7540 → HTTP/2
      RFC 9114 → HTTP/3
      RFC 8446 → TLS 1.3
      RFC 6455 → WebSocket
      RFC 7159 → JSON

  IEEE (Institute of Electrical and Electronics Engineers)
    Scope: Physical/data link networking standards
    Key: IEEE 802.3 (Ethernet), IEEE 802.11 (Wi-Fi)

  IANA (Internet Assigned Numbers Authority)
    Scope: IP address allocation, port numbers, MIME types
    Delegates to: ICANN, Regional Internet Registries (RIRs)

  ISO/IEC:
    Scope: OSI model, encryption standards (AES, SHA)

3. HTML STANDARDS
────────────────────────────────────────────────────────────────────────────────

  HTML5 (Current Living Standard):
    Key features added over HTML4:
      • Semantic elements: <header>, <footer>, <nav>, <main>, <article>,
        <section>, <aside>, <figure>, <figcaption>, <time>, <mark>
      • Form enhancements: input types (email, url, date, range, color),
        validation attributes (required, pattern, min, max)
      • Multimedia: <video>, <audio>, <source>, <track>
      • Graphics: <canvas>, <svg>
      • APIs: Web Storage, Geolocation, Web Workers, History API,
               Drag and Drop, WebSocket, File API
      • Removed: <font>, <center>, <frame>, <frameset>, <big>

  DOCTYPE Declaration:
    <!DOCTYPE html>
    - Tells browser to render in standards mode (not quirks mode)
    - HTML5 doctype is intentionally simple

  Quirks Mode vs Standards Mode:
    Quirks Mode: Browser emulates old IE4/Netscape behaviors
                 (different box model, etc.) — no DOCTYPE triggers this
    Standards Mode: Correct modern rendering — triggered by <!DOCTYPE html>
    Almost Standards: Minor quirks, some older doctypes trigger this

  Important HTML Concepts:
    Void elements:   <br>, <hr>, <img>, <input>, <link>, <meta> — no closing tag
    Boolean attrs:   <input disabled> — presence = true
    data-* attrs:    Custom data attributes for JS use
    ARIA attributes: For accessibility (role, aria-label, aria-hidden, etc.)

4. CSS STANDARDS
────────────────────────────────────────────────────────────────────────────────

  CSS versions are now module-based (CSS3 and beyond):

  Key CSS Modules and Their Status:
    ┌─────────────────────────────┬─────────────────────────────────────┐
    │ Module                      │ Key Features                        │
    ├─────────────────────────────┼─────────────────────────────────────┤
    │ CSS Selectors Level 4       │ :is(), :where(), :has()             │
    │ CSS Cascade Level 5         │ @layer, cascade layers              │
    │ CSS Grid Layout Level 2     │ Subgrid, masonry (experimental)     │
    │ CSS Flexbox (Level 1)       │ flex layout, align/justify          │
    │ CSS Custom Properties       │ --variable syntax                   │
    │ CSS Transitions             │ transition property                 │
    │ CSS Animations              │ @keyframes, animation property      │
    │ CSS Transforms              │ transform: rotate/scale/translate   │
    │ CSS Containment             │ contain, content-visibility         │
    │ CSS Color Level 5           │ oklch, color-mix()                  │
    │ CSS Nesting                 │ & selector (now native in browsers) │
    └─────────────────────────────┴─────────────────────────────────────┘

  CSS Specificity:
    Inline styles          → 1,0,0,0
    ID selectors           → 0,1,0,0
    Class/pseudo-class/attr → 0,0,1,0
    Element/pseudo-element  → 0,0,0,1
    Universal (*)          → 0,0,0,0
    !important             → Overrides everything (use sparingly)

  Box Model:
    content → padding → border → margin
    box-sizing: content-box (default — width = content only)
    box-sizing: border-box  (width = content + padding + border)

  Cascade Resolution Order (highest to lowest):
    1. !important + transition
    2. !important + browser (user agent)
    3. !important + author
    4. Animation
    5. Author normal
    6. Cascade Layer order (last layer wins)
    7. User agent normal

5. JAVASCRIPT STANDARDS (ECMAScript)
────────────────────────────────────────────────────────────────────────────────

  ECMAScript Timeline:
    ES1 (1997)  → Initial standard
    ES3 (1999)  → Regex, exceptions, try/catch
    ES5 (2009)  → JSON, Array methods, strict mode
    ES6/ES2015  → Classes, modules, arrows, let/const, Promises,
                  template literals, destructuring, generators, Map/Set
    ES2016      → Array.includes, ** operator
    ES2017      → async/await, Object.entries/values, SharedArrayBuffer
    ES2018      → Rest/spread for objects, Promise.finally, async iterators
    ES2019      → Array.flat/flatMap, Object.fromEntries, optional catch
    ES2020      → Optional chaining (?.), Nullish coalescing (??),
                  BigInt, Promise.allSettled, globalThis
    ES2021      → String.replaceAll, Promise.any, logical assignment (&&=, ||=, ??=)
    ES2022      → Array.at(), Object.hasOwn(), class fields, top-level await
    ES2023      → Array.findLast, toSorted/toReversed/toSpliced (immutable)
    ES2024      → Object.groupBy, Promise.withResolvers, ArrayBuffer.transfer
    ES2025      → import attributes, Set methods (union, intersection, etc.)

  Strict Mode:
    "use strict"
    - Disallows undeclared variables
    - this is undefined in non-method functions
    - No with statement, no octal literals
    - Required for ES6 modules (always strict)

  Modules (ESM):
    <script type="module">
    - Always strict mode
    - import/export syntax
    - Deferred by default (like defer attribute)
    - Own scope (variables not global)
    - CORS-restricted

6. WEB API STANDARDS
────────────────────────────────────────────────────────────────────────────────

  Key Web APIs standardized by W3C/WHATWG:

  Fetch API (WHATWG Fetch Standard):
    - Modern replacement for XMLHttpRequest
    - Promise-based
    - fetch(url, options) → Promise<Response>
    - Supports streaming, AbortController, CORS mode

  Service Workers (W3C):
    - Script that acts as a proxy between browser and network
    - Runs in background, separate thread
    - Enables offline, push notifications, background sync

  Web Workers (WHATWG):
    - Background threads for JS
    - No DOM access; communicate via postMessage
    - Dedicated Workers, Shared Workers

  Intersection Observer (W3C):
    - Observe when elements enter/exit viewport
    - Replaces expensive scroll event listeners
    - Use: lazy loading images, infinite scroll, animation triggers

  MutationObserver (WHATWG DOM Standard):
    - Watch for DOM changes (attributes, children, subtree)
    - Async callback via microtask queue

  ResizeObserver (W3C):
    - Observe element size changes
    - Better than window.resize for individual elements

  Performance API (W3C):
    - performance.now() — high-resolution timestamp
    - performance.mark(), performance.measure()
    - PerformanceObserver for metrics (LCP, FID, CLS)
    - Navigation Timing, Resource Timing entries

  Web Animations API (WAAPI):
    - Animate elements via JS (element.animate())
    - Same model as CSS animations

  Web Components (W3C):
    - Custom Elements: define new HTML elements
    - Shadow DOM: encapsulated DOM subtree
    - HTML Templates: <template> + <slot>

7. ACCESSIBILITY STANDARDS (WCAG)
────────────────────────────────────────────────────────────────────────────────

  WCAG (Web Content Accessibility Guidelines) — W3C standard:

  4 Principles (POUR):
    Perceivable   — Users can perceive content (alt text, captions)
    Operable      — Users can operate UI (keyboard nav, enough time)
    Understandable — Content is understandable (readable, predictable)
    Robust        — Works with assistive technologies

  Conformance Levels:
    A   → Minimum (must-do)
    AA  → Standard target (legally required in many jurisdictions)
    AAA → Highest (ideal)

  Key Requirements (Level AA):
    • Sufficient color contrast (4.5:1 for normal text, 3:1 for large)
    • Keyboard navigable (focus management, tab order)
    • Screen reader support (ARIA roles, labels, landmarks)
    • Alt text for images
    • No keyboard traps
    • Form labels
    • Focus visible

  ARIA (Accessible Rich Internet Applications):
    role="button"            → identifies custom buttons
    aria-label="Close"       → accessible name
    aria-hidden="true"       → hide from screen readers
    aria-expanded="false"    → state of collapsible
    aria-live="polite"       → announce dynamic updates
    aria-describedby="id"    → associates description

8. BROWSER COMPATIBILITY AND STANDARDS SUPPORT
────────────────────────────────────────────────────────────────────────────────

  Baseline (Google/W3C initiative):
    - "Newly available": recently supported in all major browsers
    - "Widely available": available for 30+ months in all major browsers
    - Helps developers know what's safe to use

  Can I Use (caniuse.com):
    - Shows browser support for web features
    - Usage statistics per feature per browser version

  Polyfills:
    - JavaScript code that implements a feature missing in older browsers
    - Example: core-js polyfills ES6+ features for IE
    - Loaded conditionally or bundled

  Progressive Enhancement vs Graceful Degradation:
    Progressive Enhancement:
      - Start with a baseline that works everywhere
      - Enhance for more capable browsers
      - Recommended approach

    Graceful Degradation:
      - Build for modern browsers first
      - Degrade gracefully for older browsers

  Vendor Prefixes (historical, mostly phased out):
    -webkit- → Chrome/Safari
    -moz-    → Firefox
    -ms-     → Internet Explorer
    -o-      → Opera
    Example: -webkit-transform (now just transform)

9. HTTP/WEB SECURITY STANDARDS
────────────────────────────────────────────────────────────────────────────────

  TLS (RFC 8446 — TLS 1.3):
    - Encryption for all web traffic
    - TLS 1.0/1.1 deprecated; TLS 1.2 minimum, 1.3 preferred

  CORS (Cross-Origin Resource Sharing — WHATWG Fetch):
    - Controls which origins can access resources
    - Enforced by browsers, not servers

  CSP (Content Security Policy — W3C):
    - HTTP header restricting resource origins
    - Mitigates XSS

  HSTS (HTTP Strict Transport Security — RFC 6797):
    - Forces HTTPS for a domain

  SRI (Subresource Integrity — W3C):
    - Verify external scripts/styles haven't been tampered
    - <script integrity="sha256-...">

10. INTERVIEW QUESTIONS & ANSWERS
────────────────────────────────────────────────────────────────────────────────

Q: What is the difference between W3C and WHATWG?
A: W3C publishes versioned snapshots of standards (HTML4, HTML5).
   WHATWG publishes "living standards" that evolve continuously.
   For HTML and DOM, WHATWG's specifications are now the primary
   references browsers implement from. They collaborate on HTML.

Q: What are the stages in the TC39 proposal process?
A: Stage 0 (Strawperson) → Stage 1 (Proposal) → Stage 2 (Draft) →
   Stage 3 (Candidate, complete spec, needs feedback) → Stage 4
   (Finished, included in next spec release).

Q: What is WCAG and what does AA compliance mean?
A: WCAG (Web Content Accessibility Guidelines) by W3C defines
   accessibility standards. Level AA is the standard target for legal
   compliance. It covers contrast ratios (4.5:1 for normal text),
   keyboard navigation, screen reader support, and more.

Q: What is the CSS specificity order?
A: Inline styles > IDs > Classes/pseudo-classes/attributes >
   Elements/pseudo-elements. !important overrides all. When
   specificity is equal, last rule wins (cascade).

Q: What is the difference between progressive enhancement and graceful degradation?
A: Progressive enhancement starts with a baseline (semantic HTML, basic CSS)
   that works for all, then enhances for modern browsers. Graceful
   degradation builds for modern browsers first and provides fallbacks
   for older ones. Progressive enhancement is generally recommended.

Q: What is a polyfill?
A: JavaScript code that implements a web API or language feature
   not natively supported by older browsers. Example: polyfilling
   Promise for IE11 or fetch API. Usually loaded conditionally
   based on feature detection.

Q: What is SRI (Subresource Integrity)?
A: An attribute on <script> and <link> that contains a cryptographic
   hash of the file's expected content. If the CDN-hosted file is
   tampered with, the hash won't match and the browser blocks it.
   Example: integrity="sha256-abc123=="

Q: What is the difference between quirks mode and standards mode?
A: Quirks mode emulates old browser behavior (e.g., different box model)
   for backward compatibility. Standards mode uses correct modern
   rendering. <!DOCTYPE html> triggers standards mode. Missing or
   incorrect doctype triggers quirks mode.

Q: What ECMAScript version introduced async/await?
A: ES2017 (ES8) introduced async/await. Promises were introduced in
   ES2015 (ES6). async/await is syntactic sugar over Promises.

Q: Name 3 semantic HTML5 elements and their purpose.
A: <main> — main content of the page (only one per page),
   <nav> — navigation links,
   <article> — self-contained content (blog post, news item),
   <section> — themed grouping of content,
   <aside> — sidebar content tangentially related to main content.

  KEY TAKEAWAYS
================================================================================
  • W3C = versioned; WHATWG = living standards (primary HTML/DOM reference)
  • TC39: 5 stages (0-4) for ECMAScript proposals, annual releases
  • WCAG AA = legal accessibility standard (contrast, keyboard, ARIA)
  • CSS specificity: inline > ID > class > element
  • Progressive enhancement > graceful degradation
  • TLS, CORS, CSP, HSTS are security-related web standards
