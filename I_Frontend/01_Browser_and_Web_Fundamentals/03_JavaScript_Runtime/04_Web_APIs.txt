────────────────────────────────────────────────────────────────────────────────
1. WHAT ARE WEB APIs?
────────────────────────────────────────────────────────────────────────────────

  Web APIs are interfaces provided by the BROWSER (not part of JS language itself)
  that allow JavaScript to interact with the browser and the outside world.

  Key distinction:
    JavaScript Engine (V8): executes JS code, manages stack/heap
    Web APIs (Browser):     timer, network, DOM, events, storage, etc.
    
  When you call setTimeout, fetch, or addEventListener, you're using
  BROWSER APIs, not core JavaScript.

────────────────────────────────────────────────────────────────────────────────
2. TIMER APIs
────────────────────────────────────────────────────────────────────────────────

  setTimeout(fn, delay, ...args):
    - Schedules fn to run after at least delay milliseconds
    - Returns a numeric timer ID
    - NOT guaranteed exact timing (depends on task queue, long tasks)
    - HTML spec: minimum 4ms for nested/repeated timers
    - Background tabs: minimum 1000ms (throttled for battery)
    
    const id = setTimeout(() => console.log('hi'), 500);
    clearTimeout(id); // cancel

  setInterval(fn, interval, ...args):
    - Schedules fn to run repeatedly every interval ms
    - Skips intervals if previous callback takes too long
    - Same throttling rules as setTimeout
    
    const id = setInterval(() => console.log('tick'), 1000);
    clearInterval(id);

  queueMicrotask(fn):
    - Schedules fn as a MICROTASK (higher priority than setTimeout)
    - Equivalent to Promise.resolve().then(fn) but cleaner
    - Useful for: deferring to end of current task without full task round-trip
    
    queueMicrotask(() => console.log('microtask'));

  requestAnimationFrame(fn):
    - Schedules fn to run BEFORE next browser paint
    - Runs at display refresh rate (usually 60fps = ~16.67ms)
    - Paused when tab is hidden (saves battery, CPU)
    - Returns ID (cancelable)
    
    function animate(timestamp) {
      updatePosition(timestamp);
      requestAnimationFrame(animate); // loop
    }
    requestAnimationFrame(animate);

  requestIdleCallback(fn, options):
    - Schedules fn during browser idle time
    - Receives IdleDeadline: { timeRemaining(), didTimeout }
    - options.timeout: max ms to wait before forcing execution
    
    requestIdleCallback((deadline) => {
      while (deadline.timeRemaining() > 0 && tasks.length > 0) {
        tasks.shift()();
      }
    }, { timeout: 1000 });

3. FETCH API
────────────────────────────────────────────────────────────────────────────────

  Modern replacement for XMLHttpRequest. Promise-based.

  Basic usage:
    const response = await fetch('https://api.example.com/data');
    const data = await response.json();

  Complete fetch with options:
    const response = await fetch('/api/users', {
      method: 'POST',
      headers: {
        'Content-Type': 'application/json',
        'Authorization': `Bearer ${token}`
      },
      body: JSON.stringify({ name: 'Alice' }),
      credentials: 'include',   // send cookies
      mode: 'cors',              // cors | no-cors | same-origin
      cache: 'no-cache',
      signal: abortController.signal, // for cancellation
    });

  Response object:
    response.ok          → true if status 200-299
    response.status      → 404, 200, etc.
    response.statusText  → "OK", "Not Found"
    response.headers     → Headers object
    response.json()      → Promise<any>
    response.text()      → Promise<string>
    response.blob()      → Promise<Blob>
    response.arrayBuffer() → Promise<ArrayBuffer>
    response.formData()  → Promise<FormData>
    response.clone()     → clone response (body can only be read once!)
    response.body        → ReadableStream (for streaming)

  Cancellation with AbortController:
    const controller = new AbortController();
    const timeoutId = setTimeout(() => controller.abort(), 5000);
    
    try {
      const response = await fetch('/api/slow', { signal: controller.signal });
      clearTimeout(timeoutId);
    } catch (err) {
      if (err.name === 'AbortError') console.log('Request cancelled');
    }

  Fetch gotchas:
    • fetch does NOT reject on HTTP error status (4xx, 5xx)!
      Must check response.ok manually
    • fetch does NOT send cookies by default cross-origin
      Use credentials: 'include' for cross-origin cookies
    • Network failure → rejects with TypeError

  fetch vs XMLHttpRequest:
    ┌────────────────────┬────────────────────┬────────────────────┐
    │ Feature            │ fetch              │ XMLHttpRequest     │
    ├────────────────────┼────────────────────┼────────────────────┤
    │ API style          │ Promise-based      │ Event-based        │
    │ Progress events    │ No (use streams)   │ Yes (onprogress)   │
    │ Abort              │ AbortController    │ .abort()           │
    │ Streaming          │ Yes (ReadableStream)│ Limited           │
    │ Service Worker     │ Yes (interceptable)│ No                 │
    │ Credentials        │ opt-in             │ opt-in             │
    └────────────────────┴────────────────────┴────────────────────┘

4. XMLHTTPREQUEST (XHR)
────────────────────────────────────────────────────────────────────────────────

  Legacy but still common in interviews:
  
    const xhr = new XMLHttpRequest();
    xhr.open('GET', '/api/data', true); // true = async
    xhr.setRequestHeader('Accept', 'application/json');
    xhr.timeout = 5000;
    
    xhr.onload = function() {
      if (xhr.status === 200) {
        console.log(JSON.parse(xhr.responseText));
      }
    };
    xhr.onerror = function() { /* network error */ };
    xhr.ontimeout = function() { /* timed out */ };
    xhr.onprogress = function(e) {
      if (e.lengthComputable) {
        const percent = (e.loaded / e.total) * 100;
      }
    };
    
    xhr.send(JSON.stringify({ key: 'value' }));
    xhr.abort(); // cancel

5. DOM EVENTS API
────────────────────────────────────────────────────────────────────────────────

  Event Registration:
    element.addEventListener(type, handler, options);
    element.removeEventListener(type, handler, options);

  Options object:
    {
      capture: false,  // event listener phase (false = bubble, true = capture)
      once: true,      // auto-removes after first call
      passive: true,   // hints handler won't call preventDefault() (perf opt)
      signal: ac.signal // AbortController to remove listener
    }

  Event Propagation (3 phases):
    1. Capture phase:  Event travels DOWN from window → document → ...→ target
    2. Target phase:   Event at target element
    3. Bubble phase:   Event travels UP from target → ... → document → window

    document.addEventListener('click', fn, true);  // capture phase
    document.addEventListener('click', fn, false); // bubble phase (default)

  Event Object:
    event.target          → element that triggered event
    event.currentTarget   → element listener is attached to
    event.type            → event type string
    event.preventDefault() → stop default browser action
    event.stopPropagation() → stop event from propagating
    event.stopImmediatePropagation() → stop propagation AND other handlers on same element
    event.bubbles         → boolean
    event.timeStamp       → high-res timestamp

  Custom Events:
    const event = new CustomEvent('my-event', {
      detail: { message: 'hello' },
      bubbles: true,
      cancelable: true
    });
    element.dispatchEvent(event);
    element.addEventListener('my-event', e => console.log(e.detail.message));

  Event Delegation:
    - Attach ONE listener to parent instead of many to children
    - Works because events bubble up
    - Handles dynamically added elements automatically
    
    // Good: one listener handles all buttons
    document.getElementById('list').addEventListener('click', (e) => {
      if (e.target.matches('button.delete')) {
        handleDelete(e.target.closest('li'));
      }
    });
    
    // Bad: listener on every button (expensive, no dynamic support)
    document.querySelectorAll('button.delete').forEach(btn => {
      btn.addEventListener('click', handleDelete);
    });

6. INTERSECTION OBSERVER
────────────────────────────────────────────────────────────────────────────────

  Observes when elements enter/exit the viewport (or a custom root).
  Replaces expensive scroll event + getBoundingClientRect() patterns.

  Usage:
    const observer = new IntersectionObserver((entries, observer) => {
      entries.forEach(entry => {
        if (entry.isIntersecting) {
          // element is visible
          entry.target.classList.add('visible');
          observer.unobserve(entry.target); // stop observing if once
        }
      });
    }, {
      root: null,          // null = viewport
      rootMargin: '0px',   // margin around root (like CSS margin)
      threshold: 0.5       // callback when 50% visible; array for multiple
    });
    
    observer.observe(element);
    observer.unobserve(element);
    observer.disconnect(); // stop all observations

  Use cases:
    • Lazy loading images (load when near viewport)
    • Infinite scrolling (load more when sentinel element visible)
    • Animation triggers (animate when scrolled into view)
    • Ad impression tracking
    • Sticky header/nav behavior

7. MUTATION OBSERVER
────────────────────────────────────────────────────────────────────────────────

  Observes DOM changes asynchronously (callbacks are microtasks).
  Replacement for deprecated DOM Mutation Events (synchronous, slow).

  Usage:
    const observer = new MutationObserver((mutations, observer) => {
      mutations.forEach(mutation => {
        console.log(mutation.type); // 'childList', 'attributes', 'characterData'
        mutation.addedNodes;        // NodeList
        mutation.removedNodes;      // NodeList
        mutation.attributeName;     // for 'attributes'
        mutation.oldValue;          // if attributeOldValue: true
      });
    });
    
    observer.observe(targetNode, {
      childList: true,          // watch for child additions/removals
      subtree: true,            // watch entire subtree
      attributes: true,         // watch attribute changes
      attributeOldValue: true,  // include old attribute value
      characterData: true,      // watch text content changes
      characterDataOldValue: true
    });
    
    observer.disconnect();
    observer.takeRecords(); // get pending mutations and clear queue

  Use cases:
    • React/Vue/Angular's DOM abstraction layers
    • Custom element lifecycle emulation
    • Detecting third-party DOM modifications
    • Rich text editor (watch for contenteditable changes)

────────────────────────────────────────────────────────────────────────────────
8. RESIZE OBSERVER
────────────────────────────────────────────────────────────────────────────────

  Observes changes to element dimensions.
  More efficient than window.resize (only triggers for changed elements).

  Usage:
    const observer = new ResizeObserver(entries => {
      entries.forEach(entry => {
        const { width, height } = entry.contentRect;
        console.log(entry.target, width, height);
        entry.borderBoxSize;    // border-box dimensions
        entry.contentBoxSize;   // content-box dimensions
      });
    });
    
    observer.observe(element);
    observer.unobserve(element);
    observer.disconnect();

  Use cases:
    • Responsive components (not just page)
    • Container queries (before CSS container queries)
    • Canvas resizing for DPI-correct rendering
    • Virtualized lists calculating item dimensions

9. PERFORMANCE API
────────────────────────────────────────────────────────────────────────────────

  High-resolution timing:
    performance.now()           → float ms since page load (sub-ms precision)
    performance.timeOrigin      → Unix ms when performance timeline started
    Date.now()                  → ms since Unix epoch (lower precision)

  Custom marks and measures:
    performance.mark('start');
    doWork();
    performance.mark('end');
    performance.measure('doWork duration', 'start', 'end');
    
    const entries = performance.getEntriesByName('doWork duration');
    console.log(entries[0].duration); // ms

  Navigation Timing:
    const nav = performance.getEntriesByType('navigation')[0];
    nav.domContentLoadedEventEnd - nav.startTime  // DCL time
    nav.loadEventEnd - nav.startTime              // Full load time
    nav.responseStart - nav.startTime             // TTFB

  Resource Timing:
    performance.getEntriesByType('resource').forEach(res => {
      console.log(res.name, res.duration, res.transferSize);
    });

  PerformanceObserver:
    const obs = new PerformanceObserver(list => {
      list.getEntries().forEach(entry => console.log(entry));
    });
    obs.observe({ type: 'largest-contentful-paint', buffered: true });
    obs.observe({ type: 'longtask', buffered: true });
    obs.observe({ type: 'layout-shift', buffered: true });
    obs.observe({ type: 'first-input', buffered: true });

10. HISTORY API
────────────────────────────────────────────────────────────────────────────────

  Manipulate browser history without page reload (SPA routing):

  history.pushState(state, title, url):
    - Adds new history entry
    - Changes URL WITHOUT page reload
    - state: serializable object stored with entry
    
    history.pushState({ page: 1 }, '', '/page/1');

  history.replaceState(state, title, url):
    - REPLACES current history entry (no new entry)
    - Same URL as pushState but replaces instead of adding

  history.back(), history.forward(), history.go(n):
    - Programmatic navigation
    - history.go(-2) → go 2 pages back

  popstate event:
    window.addEventListener('popstate', (e) => {
      console.log(e.state); // state passed to pushState/replaceState
      // re-render based on current URL
    });
    // Note: popstate fires on back/forward, NOT on pushState/replaceState!

11. BROADCAST CHANNEL API
────────────────────────────────────────────────────────────────────────────────

  Communication between same-origin tabs/windows/workers:
  
    // In all tabs:
    const channel = new BroadcastChannel('my-app');
    channel.postMessage({ type: 'USER_LOGOUT' });
    channel.onmessage = (e) => { if (e.data.type === 'USER_LOGOUT') logout(); };
    channel.close();

12. GEOLOCATION API
────────────────────────────────────────────────────────────────────────────────

  navigator.geolocation.getCurrentPosition(success, error, options);
  navigator.geolocation.watchPosition(success, error, options);

    navigator.geolocation.getCurrentPosition(
      pos => {

13. INTERVIEW QUESTIONS & ANSWERS
────────────────────────────────────────────────────────────────────────────────

Q: What is the difference between Web APIs and the JavaScript engine?
A: The JS engine (V8, SpiderMonkey) executes JS code, manages memory and
   the call stack. Web APIs are provided by the BROWSER (not V8) — timer,
   fetch, DOM events, storage. When you call setTimeout, you're calling a
   browser API that registers a callback; V8 doesn't handle the timing.

Q: What is Event Delegation and why use it?
A: Attaching a single event listener to a parent instead of individual
   listeners on every child. Works because events bubble up. Benefits:
   1) Fewer listeners = less memory. 2) Automatically handles dynamically
   added children. 3) Simpler setup for lists/tables.

Q: What is the difference between stopPropagation and preventDefault?
A: stopPropagation: stops the event from bubbling/capturing further up/down
   the DOM tree. preventDefault: cancels the browser's default action
   (e.g., prevents link navigation, form submission, right-click menu).
   They can be called independently or together.

Q: What is an AbortController?
A: A browser API for cancelling async operations. Create a controller,
   pass its signal to fetch() (or addEventListener). Call controller.abort()
   to cancel. The fetch Promise rejects with AbortError. Can share one
   signal across multiple fetch requests to cancel all at once.

Q: What is the Intersection Observer and when would you use it?
A: API for asynchronously observing when elements enter/exit a viewport.
   Use cases: lazy loading images, infinite scroll, animation on scroll,
   ad impression tracking. Much more performant than scroll events +
   getBoundingClientRect() (no forced synchronous layout).

Q: What is the difference between requestAnimationFrame and setTimeout?
A: rAF fires at display refresh rate (~60fps, ~16.67ms) synchronized with
   the browser's rendering. Pauses when tab is hidden. setTimeout has no
   display sync, minimum 4ms delay, doesn't pause in background (until
   throttled). Use rAF for visual animations; setTimeout for delayed execution.

Q: Why does fetch not reject on HTTP errors?
A: fetch only rejects on network failures (no connection, DNS failure).
   HTTP error status codes (4xx, 5xx) are valid HTTP responses — the fetch
   "succeeded" in getting a response. Check response.ok or response.status
   manually to handle HTTP errors.

Q: What is BroadcastChannel?
A: An API for messaging between same-origin tabs, windows, and workers.
   Create a named channel, postMessage to it, all pages with the same
   channel name receive the message via onmessage. Use for cross-tab
   state sync (e.g., logout in one tab → logout all tabs).

Q: What is the History API and how does a SPA use it?
A: History API (pushState/replaceState) lets JS change the URL without
   page reload and add entries to browser history. SPAs use it for routing:
   clicking a link → pushState changes URL → render new "page" in JS →
   popstate event fires on back/forward → re-render from new URL.

================================================================================
  KEY TAKEAWAYS
================================================================================
  • Web APIs = browser-provided (not JS engine): timers, fetch, events, DOM
  • Event delegation: one parent listener for many children (bubble-based)
  • stopPropagation: stops event bubbling; preventDefault: stops default action
  • AbortController: cancel fetch/event listeners with a signal
  • IntersectionObserver: efficient viewport visibility tracking (no scroll events)
  • rAF: before each paint, synchronized to display; best for animations
  • fetch: rejects only on network error, not HTTP errors (check response.ok)
  • History API: pushState/replaceState for SPA routing without reload
