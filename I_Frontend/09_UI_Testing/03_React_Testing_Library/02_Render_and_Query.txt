1. THE RENDER() FUNCTION
================================================================================

render(ui, options?) mounts a React component into a jsdom container and
provides query functions to interact with the rendered DOM.

BASIC USAGE:
  import { render } from '@testing-library/react';
  render(<MyComponent />);

RENDER WITH PROPS:
  render(<Button variant="primary" disabled>Submit</Button>);

RENDER WITH WRAPPER (Providers):
  render(<Component />, {
    wrapper: ({ children }) => (
      <ThemeProvider theme={theme}>
        <Router>{children}</Router>
      </ThemeProvider>
    ),
  });

RENDER OPTIONS:
  render(ui, {
    // Custom container (default: document.body > div)
    container: document.getElementById('my-container'),

    // Wraps the component (for providers)
    wrapper: AllProviders,

    // Base element for queries (default: document.body)
    baseElement: document.body,

    // Hydrate existing server-rendered HTML (SSR)
    hydrate: true,

    // Query configuration options
    queries: { ...customQueries },
  });


================================================================================
2. RENDER() RETURN VALUES
================================================================================

render() returns an object with:

CONTAINER:
  const { container } = render(<Component />);
  // container → The div element that wraps the rendered component
  // Usually prefer using screen.* instead

BASEELEMENT:
  const { baseElement } = render(<Component />);
  // baseElement → document.body (default)

ASFRAGMENT():
  const { asFragment } = render(<Component />);
  const snapshot = asFragment();
  // Returns a DocumentFragment for snapshots
  expect(snapshot).toMatchSnapshot();

DEBUG():
  const { debug } = render(<Component />);
  debug(); // Prints current DOM to console
  // Equivalent to screen.debug()

RERENDER():
  const { rerender } = render(<Component count={1} />);
  rerender(<Component count={2} />);
  // Re-renders the component with new props without unmounting

UNMOUNT():
  const { unmount } = render(<Component />);
  unmount(); // Removes component from DOM

QUERIES (shorthand, but prefer screen):
  const { getByRole, getByText, queryByRole } = render(<Component />);
  // These are scoped to the render's container
  // screen.* is preferred because it's always current

CLEANUP:
  RTL automatically calls cleanup() after each test (via afterEach).
  cleanup() removes the rendered component from the DOM.
  This is why tests are isolated — each test gets a fresh DOM.

  // Manual cleanup (rarely needed):
  import { cleanup } from '@testing-library/react';
  afterEach(() => cleanup());

3. QUERY TYPES DEEP DIVE
================================================================================

SUMMARY TABLE:
  ┌───────────────┬────────────────────────────┬───────────────────────────────┐
  │ Query         │ 0 matches                  │ 1+ matches                    │
  ├───────────────┼────────────────────────────┼───────────────────────────────┤
  │ getBy         │ Throws error               │ Returns element               │
  │ queryBy       │ Returns null               │ Returns element               │
  │ findBy        │ Throws after timeout       │ Returns element (async)       │
  ├───────────────┼────────────────────────────┼───────────────────────────────┤
  │ getAllBy       │ Throws error               │ Returns array                 │
  │ queryAllBy    │ Returns empty array []     │ Returns array                 │
  │ findAllBy     │ Throws after timeout       │ Returns array (async)         │
  └───────────────┴────────────────────────────┴───────────────────────────────┘

WHEN TO USE EACH:

  getBy*:
    For elements that should definitely be in the DOM right now.
    Throws immediately if not found — fast failure, clear error message.
    const button = screen.getByRole('button', { name: /submit/i });

  queryBy*:
    ONLY for asserting something is NOT in the DOM.
    Returns null (doesn't throw) if element isn't found.
    expect(screen.queryByRole('alert')).not.toBeInTheDocument();
    expect(screen.queryByText(/error/i)).toBeNull();

  findBy*:
    For elements that will appear asynchronously (after fetch, timeout, etc.)
    Returns a Promise, so you must await.
    const username = await screen.findByText('Alice');
    // Waits up to 1000ms (configurable)

  CHOOSING THE RIGHT ONE:
    "I expect it to be there"    → getBy*
    "I expect it NOT to be there" → queryBy*
    "It will be there eventually" → await findBy*

4. BYROL QUERIES (MOST IMPORTANT)
================================================================================

getByRole(role, options?) queries by ARIA role.
This is the #1 recommended query method.

ROLES ARE IMPLICIT FROM HTML SEMANTICS:
  <button>          → role="button"
  <a href="...">    → role="link"
  <input type="text"> → role="textbox"
  <input type="checkbox"> → role="checkbox"
  <input type="radio"> → role="radio"
  <select>          → role="combobox"
  <textarea>        → role="textbox"
  <h1>–<h6>        → role="heading" (with level attribute)
  <img>             → role="img"
  <ul>, <ol>        → role="list"
  <li>              → role="listitem"
  <nav>             → role="navigation"
  <main>            → role="main"
  <header>          → role="banner"
  <footer>          → role="contentinfo"
  <form>            → role="form" (only with accessible name)
  <table>           → role="table"

EXPLICIT ARIA ROLES:
  <div role="dialog">   → role="dialog"
  <div role="alert">    → role="alert"
  <div role="tab">      → role="tab"
  <div role="tabpanel"> → role="tabpanel"
  <div role="status">   → role="status"

GETBYROLE OPTIONS:
  screen.getByRole('button', {
    name: /submit/i,          // Accessible name (text, aria-label, aria-labelledby)
    hidden: false,            // Include hidden elements (default: false)
    selected: true,           // For tabs/options: checked/selected state
    checked: true,            // For checkboxes/radios
    pressed: false,           // For toggle buttons
    expanded: true,           // For disclosure widgets (accordion, menu)
    level: 2,                 // For headings: specific h1-h6 level
    exact: true,              // For name: exact match (default: true)
    description: /hint text/, // Match aria-describedby
  });

EXAMPLES:
  // Find a submit button
  screen.getByRole('button', { name: /submit/i });

  // Find a specific heading
  screen.getByRole('heading', { level: 1, name: /products/i });

  // Find an open dialog
  screen.getByRole('dialog', { name: /confirm deletion/i });

  // Find a checked checkbox
  screen.getByRole('checkbox', { name: /agree to terms/i, checked: true });

  // Find navigation link
  screen.getByRole('link', { name: /home/i });

  // Find email input
  screen.getByRole('textbox', { name: /email address/i });

  // Find a combobox (select)
  screen.getByRole('combobox', { name: /country/i });

ACCESSIBLE NAME DETERMINATION:
  The "name" option matches the accessible name, which is determined by:
  1. aria-labelledby attribute
  2. aria-label attribute
  3. <label> element linked via htmlFor/id
  4. Text content of the element (for buttons, links)
  5. alt attribute (for images)
  6. title attribute

  <button aria-label="Close">X</button>  → name="Close"
  <button>Submit</button>               → name="Submit"
  <label for="email">Email</label>
  <input id="email" />                  → name="Email"

5. BYTEXT, BYLABELTEXT, BYPLACEHOLDERTEXT
================================================================================

ByText:
  Find elements by their visible text content.
  Works with any element that has text.

  screen.getByText('Hello World');             // Exact match
  screen.getByText(/hello world/i);            // Case-insensitive regex
  screen.getByText('$1,234.50');               // Currency text
  screen.getByText(/\d+ items/);               // Regex with numbers

  OPTIONS:
    exact: false  → Substring match
    selector: 'p' → Only match <p> elements
    ignore:      → HTML elements to ignore (default: 'script, style')

  screen.getByText('Submit', { exact: false }); // Matches "Submit Form"
  screen.getByText('Submit', { selector: 'button' }); // Only buttons

ByLabelText:
  Find form inputs by their associated <label> text.
  Tests that inputs are properly labeled (accessibility!).

  // Matches <label for="email">Email Address</label>
  // paired with <input id="email" />
  screen.getByLabelText('Email Address');
  screen.getByLabelText(/email/i);

  // Also works with:
  // aria-label: <input aria-label="Email Address" />
  // aria-labelledby: <span id="lbl">Email</span> <input aria-labelledby="lbl" />
  // Wrapped label: <label>Email <input /></label>

  OPTIONS:
    exact: true/false
    selector: 'input' → Only match input elements (not textarea, etc.)

ByPlaceholderText:
  Find inputs by their placeholder text.
  Lower priority than ByLabelText because placeholders are not labels.

  <input placeholder="Enter your email" />
  screen.getByPlaceholderText(/enter your email/i);

  WHEN TO USE: When the input doesn't have an associated label (legacy forms).
  BETTER: Add a proper label and use getByLabelText.

6. BYDISPLAYVALUE, BYALTTEXT, BYTITLE, BYTESTID
================================================================================

ByDisplayValue:
  Find inputs (input, select, textarea) by their CURRENT value.

  // For a pre-filled input:
  <input defaultValue="alice@example.com" />
  screen.getByDisplayValue('alice@example.com');
  screen.getByDisplayValue(/alice/i);

  // For a select:
  <select><option value="us" selected>United States</option></select>
  screen.getByDisplayValue('United States');

  WHEN TO USE: When you need to find a form element by what it currently shows.

ByAltText:
  Find images by their alt attribute.
  Important for accessibility testing.

  <img src="avatar.jpg" alt="User profile photo" />
  screen.getByAltText('User profile photo');
  screen.getByAltText(/profile photo/i);

ByTitle:
  Find elements by their title attribute.
  Used for SVGs and elements with tooltip-style titles.

  <svg title="Close icon">...</svg>
  <button title="Delete item">×</button>
  screen.getByTitle(/close/i);

ByTestId (Last Resort):
  Find elements by data-testid attribute.
  Use ONLY when no other accessible query works.

  // In component:
  <div data-testid="user-stats-panel">...</div>

  // In test:
  screen.getByTestId('user-stats-panel');

  WHEN TO USE ByTestId:
    ✅ Complex charts/visualizations with no accessible text
    ✅ Third-party component that renders no accessible attributes
    ✅ Dynamic list items where text/role isn't unique

  HOW TO ADD data-testid:
    // React:
    <div data-testid="my-element">
    // With TypeScript:
    // data-testid is a valid HTML attribute, no TS errors

  CAUTION: Using data-testid everywhere:
    ❌ Leads to tests that don't check accessibility
    ❌ Tests that pass even for screen-reader inaccessible UIs
    ✅ Use accessible queries to also validate accessibility

7. GETALLBY* — QUERYING MULTIPLE ELEMENTS
================================================================================

When you expect multiple elements matching the same query, use getAllBy*, etc.

SYNTAX:
  getAllByRole(role, options?)      → returns HTMLElement[] (throws if empty)
  queryAllByRole(role, options?)   → returns HTMLElement[] (returns [] if empty)
  findAllByRole(role, options?)    → returns Promise<HTMLElement[]>

EXAMPLES:
  // All list items
  const items = screen.getAllByRole('listitem');
  expect(items).toHaveLength(3);

  // Verify specific items
  const buttons = screen.getAllByRole('button');
  expect(buttons).toHaveLength(2);
  expect(buttons[0]).toHaveTextContent('Save');
  expect(buttons[1]).toHaveTextContent('Cancel');

  // Check all items have something in common
  const checkboxes = screen.getAllByRole('checkbox');
  checkboxes.forEach(cb => expect(cb).not.toBeChecked());

  // Count links
  const navLinks = screen.getAllByRole('link');
  expect(navLinks.length).toBeGreaterThanOrEqual(3);

  // Verify table rows
  const rows = screen.getAllByRole('row');
  expect(rows).toHaveLength(6); // 1 header + 5 data rows

COMMON PATTERN: Render a list and verify each item
  render(<ProductList products={mockProducts} />);
  const items = screen.getAllByRole('article'); // Each product is an <article>
  expect(items).toHaveLength(mockProducts.length);
  expect(items[0]).toHaveTextContent(mockProducts[0].name);

8. QUERY OPTIONS (exact, hidden, selector)
================================================================================

exact (default: true)
  Controls whether the match must be exact.
  For strings: exact requires whole-string match.
  For regex: always works as regex.

  screen.getByText('Hello World');           // Exact: must be "Hello World"
  screen.getByText('Hello', { exact: false }); // Matches "Hello World", "Say Hello"
  screen.getByText(/hello/i);                // Regex: always flexible

  // Useful when button text contains spaces or extra punctuation:
  screen.getByRole('button', { name: /submit/i }); // Handles "Submit Form" etc.

selector (for ByText)
  Restrict to specific element types:

  screen.getByText('Click here', { selector: 'a' }); // Only links with this text
  screen.getByText('Title', { selector: 'h1' });      // Only h1 elements

hidden (default: false)
  Include hidden elements (display:none, visibility:hidden, aria-hidden=true):

  // By default, getByRole ignores hidden elements:
  screen.getByRole('button', { hidden: true }); // Includes hidden buttons

  WHEN TO USE: If you're testing that something is hidden/visible.

normalizer
  Custom function to normalize text before matching:

  screen.getByText('  Hello  ', {
    normalizer: (text) => text.trim(),
  });

9. WITHIN() — SCOPED QUERIES
================================================================================

within() scopes all queries to a specific container element.
Very useful when the same text appears in multiple places.

IMPORT: import { within } from '@testing-library/react';

BASIC USAGE:
  const nav = screen.getByRole('navigation');
  const homeLink = within(nav).getByRole('link', { name: /home/i });

  // Instead of (which might match the wrong "Home"):
  screen.getByRole('link', { name: /home/i }); // Could match footer link too

REAL-WORLD EXAMPLES:

  // Testing a table row
  const row = screen.getByRole('row', { name: /alice/i });
  expect(within(row).getByText('admin')).toBeInTheDocument();
  await userEvent.click(within(row).getByRole('button', { name: /delete/i }));

  // Testing a card component
  const productCard = screen.getByRole('article', { name: /widget/i });
  expect(within(productCard).getByText('$9.99')).toBeInTheDocument();
  expect(within(productCard).getByRole('button', { name: /add to cart/i }))
    .toBeEnabled();

  // Testing a specific section
  const filterPanel = screen.getByRole('region', { name: /filters/i });
  const priceFilter = within(filterPanel).getByLabelText(/price range/i);
  await userEvent.clear(priceFilter);
  await userEvent.type(priceFilter, '50');

COMBINING with getAllByRole:
  // Test each list item independently
  const items = screen.getAllByRole('listitem');
  items.forEach((item, index) => {
    expect(within(item).getByRole('button', { name: /remove/i }))
      .toBeInTheDocument();
  });

10. DEBUGGING QUERIES
================================================================================

SCREEN.DEBUG():
  screen.debug();           // Print entire document body
  screen.debug(element);    // Print specific element
  screen.debug(undefined, 30000); // Print without 7000 char truncation

SCREEN.LOGTESTINGPLAYGROUNDURL():
  screen.logTestingPlaygroundURL();
  // Logs a URL to open Testing Playground with your current DOM
  // Opens at https://testing-playground.com/ with your DOM pre-loaded
  // Let's you interactively figure out the right query

prettyDOM():
  import { prettyDOM } from '@testing-library/react';
  console.log(prettyDOM(element));    // Format a specific element
  console.log(prettyDOM(document.body)); // Format entire body

COMMON DEBUGGING SCENARIOS:

  // Can't find element? Use debug to see the DOM:
  render(<MyComponent />);
  screen.debug(); // Shows full DOM — find your element here

  // "Found multiple elements" error? Narrow with options:
  // Error: Found 3 elements with role="button"
  screen.getByRole('button', { name: /submit/i }); // Be specific with name

  // "Unable to find element" error? Check:
  // 1. Is it actually rendered? (debug)
  // 2. Is it hidden? (hidden: true option)
  // 3. Is the role correct? (check ARIA roles)
  // 4. Is text matching? (check exact option)

USING TESTING PLAYGROUND:
  Visit: https://testing-playground.com/
  Paste your component HTML into the playground.
  It suggests the best RTL query for each element.

  Or in your test:
  screen.logTestingPlaygroundURL(); // Auto-opens with your rendered DOM
