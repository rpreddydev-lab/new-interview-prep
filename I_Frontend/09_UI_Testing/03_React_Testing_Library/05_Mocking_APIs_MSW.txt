1. WHY MOCK APIS IN TESTS
================================================================================

When testing components that fetch data, you have several options:

  OPTION A: Let tests hit the real server
    ❌ Slow (network latency)
    ❌ Flaky (server may be down)
    ❌ Hard to test error states, loading states, edge cases
    ❌ Not isolated — tests depend on external data

  OPTION B: Mock fetch/axios at the module level
    ✅ Fast
    ❌ Bypasses request construction, URL params, headers
    ❌ Doesn't test that your code makes the RIGHT request
    ❌ Verbose jest.mock() boilerplate everywhere

  OPTION C: Use MSW (Mock Service Worker) ✅ RECOMMENDED
    ✅ Intercepts real network requests (at the network level)
    ✅ Tests that your code constructs requests correctly
    ✅ Same handlers can be reused in development mode (browser)
    ✅ Handlers defined by URL pattern — realistic API simulation
    ✅ Works the same in tests and in the browser


================================================================================
2. WHAT IS MSW (MOCK SERVICE WORKER)
================================================================================

MSW intercepts outgoing HTTP/GraphQL requests at the network layer using:
  - Service Workers in the browser (development / manual testing)
  - Node.js request interception (in Jest/Vitest unit/integration tests)

Request lifecycle:
  Component → fetch/axios → ← MSW intercepts → Handler → Returns mock response

KEY CONCEPTS:
  Handlers:    Functions that match URLs and return mock responses
  Worker:      Browser-side MSW (for Storybook, dev mode, Chrome extension)
  Server:      Node-side MSW (for Jest/Vitest tests)

MSW v2 (current) — Changes from v1:
  - New: `http.get()` instead of `rest.get()`
  - New: `HttpResponse` instead of `res(ctx.json(...))`
  - New: `http.resolve()` and `http.passthrough()`
  - New: handlers can be async functions
  - Cleaner, more standard API

3. MSW V2 SETUP AND INSTALLATION
================================================================================

INSTALL:
  npm install --save-dev msw@latest

REQUIRED msw VERSION: 2.x

CHECK VERSION:
  npx msw --version

DIRECTORY STRUCTURE:
  src/
  ├── mocks/
  │   ├── handlers.ts      ← request handlers
  │   └── server.ts        ← test server setup
  └── setupTests.ts        ← configure server lifecycle

FILES TO CREATE:

  --- src/mocks/handlers.ts ---
  import { http, HttpResponse } from 'msw';

  export const handlers = [
    http.get('/api/users', () => {
      return HttpResponse.json([
        { id: 1, name: 'Alice' },
        { id: 2, name: 'Bob' },
      ]);
    }),

    http.post('/api/users', async ({ request }) => {
      const newUser = await request.json();
      return HttpResponse.json({ id: 3, ...newUser }, { status: 201 });
    }),
  ];

  --- src/mocks/server.ts ---
  import { setupServer } from 'msw/node';
  import { handlers } from './handlers';

  export const server = setupServer(...handlers);

  --- src/setupTests.ts (add these lines) ---
  import { server } from './mocks/server';

  // Start server before all tests in the suite
  beforeAll(() => server.listen({ onUnhandledRequest: 'error' }));

  // Reset handlers after each test (so overrides don't leak)
  afterEach(() => server.resetHandlers());

  // Close server after all tests
  afterAll(() => server.close());

JEST CONFIG (if not already set):
  // jest.config.ts
  export default {
    setupFilesAfterFramework: ['<rootDir>/src/setupTests.ts'],
    testEnvironment: 'jsdom',
  };

4. DEFINING HANDLERS (http, HttpResponse)
================================================================================

IMPORT:
  import { http, HttpResponse } from 'msw';

HTTP METHODS:
  http.get(path, resolver)
  http.post(path, resolver)
  http.put(path, resolver)
  http.patch(path, resolver)
  http.delete(path, resolver)
  http.head(path, resolver)
  http.options(path, resolver)

PATH PATTERNS (use URL path without base URL):
  '/api/users'              → Exact path
  '/api/users/:id'          → Dynamic path parameter
  '*/api/users'             → Wildcard prefix (any base URL)
  'https://api.example.com/users' → Full URL

RESOLVER FUNCTION:
  The second argument: ({ request, params, cookies }) => HttpResponse

  http.get('/api/users/:id', ({ params }) => {
    const { id } = params; // e.g., '42'
    return HttpResponse.json({ id: Number(id), name: 'Alice' });
  });

  http.post('/api/login', async ({ request }) => {
    const body = await request.json(); // Parse request body
    if (body.password === 'secret') {
      return HttpResponse.json({ token: 'abc123' });
    }
    return HttpResponse.json({ error: 'Invalid credentials' }, { status: 401 });
  });

HTTPRESPONSE METHODS:
  HttpResponse.json(data, init?)         → JSON response
  HttpResponse.text('plain text')        → Text response
  HttpResponse.xml('<root/>')            → XML response
  HttpResponse.arrayBuffer(buffer)       → Binary response
  HttpResponse.error()                   → Network error (fetch fails)
  new HttpResponse(body, init)           → Custom response

  // With status and headers:
  HttpResponse.json(data, {
    status: 201,
    headers: { 'Content-Type': 'application/json', 'X-Custom': 'value' },
  });

READING REQUEST DATA:
  http.post('/api/orders', async ({ request }) => {
    const body = await request.json();     // JSON body
    const text = await request.text();    // Text body
    const formData = await request.formData(); // FormData
    const params = new URL(request.url).searchParams; // Query params
    const authHeader = request.headers.get('Authorization'); // Headers
    // ...
  });

READING URL PARAMS AND QUERY STRING:
  http.get('/api/search', ({ request }) => {
    const url = new URL(request.url);
    const query = url.searchParams.get('q');
    return HttpResponse.json({ results: [{ title: `Result for ${query}` }] });
  });

  http.get('/api/users/:userId/posts/:postId', ({ params }) => {
    const { userId, postId } = params;
    return HttpResponse.json({ userId, postId, content: 'Post content' });
  });

PASSTHROUGH (don't intercept):
  import { passthrough } from 'msw';

  http.get('/api/public', () => {
    return passthrough(); // Let the request go through to the real server
  });

5. SERVER SETUP (setupServer)
================================================================================

  import { setupServer } from 'msw/node';
  import { handlers } from './handlers';

  export const server = setupServer(...handlers);

SERVER METHODS:
  server.listen(options?)      → Start intercepting requests
  server.close()               → Stop intercepting
  server.resetHandlers()       → Remove runtime handlers (added with use())
  server.use(...handlers)      → Add handlers at runtime (override)
  server.listHandlers()        → Returns all active handlers (debug)

LISTENER OPTIONS:
  server.listen({
    onUnhandledRequest: 'error',  // Error if no handler matches (strict mode)
    // 'warn' → Console warning (default)
    // 'bypass' → Allow through silently
  });

  RECOMMENDATION: Use 'error' in tests — catches typos in API paths early.

6. INTEGRATING MSW WITH JEST/VITEST
================================================================================

FULL setupTests.ts:
  import '@testing-library/jest-dom';
  import { server } from './mocks/server';

  beforeAll(() => server.listen({ onUnhandledRequest: 'error' }));
  afterEach(() => server.resetHandlers());
  afterAll(() => server.close());

WRITING A TEST WITH MSW:
  // Default handlers (from handlers.ts) are always active.
  // No need to mock fetch/axios — MSW intercepts automatically.

  it('displays users from API', async () => {
    render(<UserList />);
    // Component fetches /api/users — MSW intercepts and returns mock data

    const alice = await screen.findByText('Alice');
    const bob = await screen.findByText('Bob');

    expect(alice).toBeInTheDocument();
    expect(bob).toBeInTheDocument();
  });

7. PER-TEST HANDLER OVERRIDES
================================================================================

Use server.use() to override handlers for a specific test.
resetHandlers() in afterEach removes these overrides.

OVERRIDE FOR ONE TEST:
  it('shows error state when API fails', async () => {
    // Override the default handler with an error response:
    server.use(
      http.get('/api/users', () => {
        return HttpResponse.json(
          { error: 'Internal Server Error' },
          { status: 500 }
        );
      })
    );

    render(<UserList />);
    expect(await screen.findByRole('alert')).toHaveTextContent(/failed to load/i);
  });

  // After this test, resetHandlers() restores the original /api/users handler

OVERRIDE WITH DIFFERENT DATA:
  it('shows empty state when no users', async () => {
    server.use(
      http.get('/api/users', () => HttpResponse.json([]))
    );

    render(<UserList />);
    expect(await screen.findByText(/no users found/i)).toBeInTheDocument();
  });

ADDING A NEW HANDLER FOR JUST ONE TEST:
  it('creates a new user', async () => {
    const user = userEvent.setup();
    let capturedBody;

    server.use(
      http.post('/api/users', async ({ request }) => {
        capturedBody = await request.json();
        return HttpResponse.json({ id: 99, ...capturedBody }, { status: 201 });
      })
    );

    render(<CreateUserForm />);
    await user.type(screen.getByLabelText(/name/i), 'Carol');
    await user.click(screen.getByRole('button', { name: /create/i }));

    await waitFor(() => {
      expect(capturedBody).toEqual({ name: 'Carol' });
    });
    expect(screen.getByText('User created!')).toBeInTheDocument();
  });

PERSISTENT OVERRIDE (doesn't reset after each test):
  server.use(
    http.get('/api/config', () => HttpResponse.json({ theme: 'dark' })),
    { once: false } // Keep handler forever until resetHandlers()
  );

ONE-TIME HANDLER (auto-removes after first use):
  server.use(
    http.get('/api/data', () => HttpResponse.json({ value: 42 }), { once: true })
  );
  // First request → returns { value: 42 }
  // Second request → falls through to default handler (or unhandled)

8. SIMULATING ERRORS AND EDGE CASES
================================================================================

400 BAD REQUEST (validation error):
  server.use(
    http.post('/api/register', () => {
      return HttpResponse.json(
        { errors: { email: 'Email already exists' } },
        { status: 400 }
      );
    })
  );

401 UNAUTHORIZED:
  server.use(
    http.get('/api/profile', () => {
      return HttpResponse.json({ message: 'Unauthorized' }, { status: 401 });
    })
  );

404 NOT FOUND:
  server.use(
    http.get('/api/users/:id', ({ params }) => {
      if (params.id === '999') {
        return HttpResponse.json({ message: 'Not found' }, { status: 404 });
      }
      return HttpResponse.json({ id: params.id, name: 'Alice' });
    })
  );

500 SERVER ERROR:
  server.use(
    http.get('/api/data', () => {
      return new HttpResponse(null, { status: 500, statusText: 'Internal Server Error' });
    })
  );

NETWORK ERROR (fetch throws):
  server.use(
    http.get('/api/data', () => {
      return HttpResponse.error(); // Simulates network failure
    })
  );

  // Test for network error:
  it('handles network failure', async () => {
    server.use(
      http.get('/api/users', () => HttpResponse.error())
    );
    render(<UserList />);
    expect(await screen.findByText(/network error/i)).toBeInTheDocument();
  });

CONDITIONAL ERROR (first call fails, second succeeds):
  let callCount = 0;
  server.use(
    http.get('/api/data', () => {
      callCount++;
      if (callCount === 1) return HttpResponse.error();
      return HttpResponse.json({ items: [1, 2, 3] });
    })
  );

9. SIMULATING DELAYS AND LOADING STATES
================================================================================

MSW doesn't add delays by default. To simulate slow APIs:

MANUAL DELAY:
  import { delay } from 'msw';

  http.get('/api/data', async () => {
    await delay(1500); // Wait 1500ms before responding
    return HttpResponse.json({ data: 'here' });
  });

DELAY MODES:
  await delay();         // Default (50ms — realistic)
  await delay(1000);     // Specific ms
  await delay('infinite'); // Never responds (test infinite loading)
  await delay('real');   // Realistic random delay

TESTING LOADING STATES:
  it('shows loading spinner then data', async () => {
    server.use(
      http.get('/api/users', async () => {
        await delay(100);
        return HttpResponse.json([{ id: 1, name: 'Alice' }]);
      })
    );

    render(<UserList />);
    expect(screen.getByRole('progressbar')).toBeInTheDocument();

    await waitForElementToBeRemoved(() => screen.queryByRole('progressbar'));
    expect(screen.getByText('Alice')).toBeInTheDocument();
  });

TESTING INFINITE LOADING (never resolves):
  it('shows loading skeleton when data is not ready', () => {
    server.use(
      http.get('/api/data', async () => {
        await delay('infinite');
        return HttpResponse.json({});
      })
    );

    render(<DataWidget />);
    expect(screen.getByRole('status', { name: /loading/i })).toBeInTheDocument();
  });

WITH FAKE TIMERS:
  jest.useFakeTimers();
  server.use(
    http.get('/api/data', async () => {
      await delay(5000);
      return HttpResponse.json({ value: 1 });
    })
  );

  render(<Component />);
  act(() => jest.advanceTimersByTime(5000));
  await screen.findByText('Loaded');
  jest.useRealTimers();

10. MSW VS OTHER MOCKING STRATEGIES
================================================================================

  ┌─────────────────────────────────┬────────────┬──────────────┬───────────────┐
  │ Approach                        │ Realistic  │ Test setup   │ Error testing │
  ├─────────────────────────────────┼────────────┼──────────────┼───────────────┤
  │ Real API calls                  │ ✅ Yes     │ ❌ Hard      │ ❌ Hard       │
  │ jest.mock('axios')              │ ❌ Low     │ ✅ Easy      │ ✅ Medium     │
  │ jest.spyOn(global, 'fetch')     │ ❌ Low     │ ✅ Easy      │ ✅ Medium     │
  │ MSW (recommended)               │ ✅ High    │ ✅ Medium    │ ✅ Easy       │
  └─────────────────────────────────┴────────────┴──────────────┴───────────────┘

MOCKING FETCH MANUALLY (comparison):
  // Less preferred — bypasses URL routing logic
  global.fetch = jest.fn().mockResolvedValue({
    ok: true,
    json: async () => ({ data: 'mocked' }),
  });

MSW ADVANTAGES:
  - Works regardless of HTTP client (fetch, axios, XMLHttpRequest, ky, etc.)
  - Shared handlers between tests, Storybook, and browser dev mode
  - Request inspection (verify correct URL, headers, body were sent)
  - Real network behavior (status codes, response headers)

11. COMMON MSW PATTERNS
================================================================================

PATTERN: CREATE FACTORY FOR MOCK DATA
  // src/mocks/factories.ts
  export const createUser = (overrides = {}) => ({
    id: Math.random(),
    name: 'Test User',
    email: 'test@example.com',
    role: 'viewer',
    ...overrides,
  });

  // In handler:
  http.get('/api/users', () => {
    return HttpResponse.json([
      createUser({ name: 'Alice', role: 'admin' }),
      createUser({ name: 'Bob' }),
    ]);
  });

PATTERN: HANDLER UTILITIES
  // src/mocks/handlers.ts
  const withDelay = (ms, response) => async () => {
    await delay(ms);
    return response;
  };

  http.get('/api/slow', withDelay(1000, HttpResponse.json({ data: 'slow' })));

PATTERN: VERIFY REQUEST WAS MADE WITH RIGHT DATA
  it('sends correct payload on form submit', async () => {
    let requestBody;

    server.use(
      http.post('/api/contact', async ({ request }) => {
        requestBody = await request.json();
        return HttpResponse.json({ success: true }, { status: 200 });
      })
    );

    const user = userEvent.setup();
    render(<ContactForm />);
    await user.type(screen.getByLabelText(/name/i), 'Alice');
    await user.type(screen.getByLabelText(/message/i), 'Hello!');
    await user.click(screen.getByRole('button', { name: /send/i }));

    await waitFor(() => {
      expect(requestBody).toEqual({ name: 'Alice', message: 'Hello!' });
    });
  });

PATTERN: TYPE-SAFE HANDLERS WITH TYPESCRIPT
  import { http, HttpResponse, RequestHandler } from 'msw';

  interface User { id: number; name: string; }

  const handlers: RequestHandler[] = [
    http.get<{}, {}, User[]>('/api/users', () => {
      return HttpResponse.json([{ id: 1, name: 'Alice' }]);
    }),
  ];
