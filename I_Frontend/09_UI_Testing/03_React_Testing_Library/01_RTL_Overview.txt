1. WHAT IS REACT TESTING LIBRARY?
================================================================================

React Testing Library (RTL) is a testing utility for React components.
It provides a set of helpers to render components and query the DOM
in a way that closely resembles how real users interact with your app.

CREATED BY: Kent C. Dodds (2018)
OFFICIALLY RECOMMENDED BY: React team
WEBSITE: https://testing-library.com

CORE PACKAGE: @testing-library/react
COMPANION: @testing-library/user-event (realistic user events)
MATCHERS: @testing-library/jest-dom (custom DOM matchers)

INSTALLATION:
  npm install --save-dev \
    @testing-library/react \
    @testing-library/user-event \
    @testing-library/jest-dom

IMPORT: import { render, screen, waitFor } from '@testing-library/react';

ENVIRONMENT: RTL renders to a jsdom environment (fake DOM).
             Does NOT require a real browser.


================================================================================
2. CORE PHILOSOPHY
================================================================================

THE GUIDING PRINCIPLE:
  "The more your tests resemble the way your software is used,
   the more confidence they can give you."
                                              — Kent C. Dodds

WHAT THIS MEANS:
  - Query elements the way users find them (by text, role, label)
  - Interact with components the way users do (click, type, submit)
  - Assert what users see (visible text, states, feedback)
  - Don't test internal implementation details

THREE ANTI-PATTERNS RTL PREVENTS:
  1. Direct access to component state
     ❌ wrapper.state('isOpen') — does the dialog appear?
     ✅ screen.getByRole('dialog') — yes, it's visible

  2. Accessing component internals
     ❌ component.instance().handleClick()
     ✅ userEvent.click(screen.getByRole('button'))

  3. Shallow rendering (mocking children)
     ❌ shallow(<UserCard />) — doesn't test how children render
     ✅ render(<UserCard />) — tests full real rendering

BENEFIT OF THIS APPROACH:
  You can freely refactor internals (class → hooks, Redux → Context,
  state structure changes) WITHOUT changing your tests, as long as the
  user-visible behavior stays the same.

================================================================================

npm install --save-dev \
  @testing-library/react \
  @testing-library/user-event \
  @testing-library/jest-dom

SETUP FILE (src/setupTests.ts):
  import '@testing-library/jest-dom';
  // This globally adds all jest-dom matchers to expect()

JEST CONFIG:
  // jest.config.ts
  {
    setupFilesAfterFramework: ['./src/setupTests.ts'],
    testEnvironment: 'jsdom',
  }

VITEST CONFIG:
  // vitest.config.ts
  {
    test: {
      globals: true,
      environment: 'jsdom',
      setupFiles: ['./src/setupTests.ts'],
    }
  }

PACKAGE VERSIONS TO KNOW:
  @testing-library/react:      v14+ for React 18
  @testing-library/user-event: v14+ for new API (setup-based)
  @testing-library/jest-dom:   v6+ (latest)

4. THE SCREEN OBJECT
================================================================================

The screen object is the primary way to query the rendered DOM.
It's globally maintained and always reflects the current state of the DOM.

PREFER SCREEN OVER DESTRUCTURING:
  // ✅ PREFERRED: screen is always up-to-date
  render(<Component />);
  const button = screen.getByRole('button');

  // ❌ AVOID: Destructured queries can become stale
  const { getByRole } = render(<Component />);
  const button = getByRole('button');

WHY screen IS BETTER:
  screen.debug() prints the current DOM state (great for debugging)
  screen.logTestingPlaygroundURL() opens the Testing Playground UI
  screen is always synchronized with the latest DOM

screen.debug():
  screen.debug();              // Print entire DOM
  screen.debug(element);       // Print specific element
  screen.debug(undefined, Infinity); // Print without truncation

5. QUERIES OVERVIEW
================================================================================

RTL queries follow this naming pattern:
  [getBy | queryBy | findBy][All?][ByRole | ByText | ByLabelText | ...]

THREE QUERY VARIANTS:
  ┌──────────────┬───────────────────────────────────────────────────────────┐
  │ getBy*       │ Returns element or THROWS if not found.                   │
  │              │ Use for elements you EXPECT to be present.                │
  ├──────────────┼───────────────────────────────────────────────────────────┤
  │ queryBy*     │ Returns element or NULL if not found.                     │
  │              │ Use to ASSERT an element is NOT present.                  │
  ├──────────────┼───────────────────────────────────────────────────────────┤
  │ findBy*      │ Returns a PROMISE. Waits up to 1000ms.                    │
  │              │ Use for ASYNCHRONOUS elements (appear after fetch/event). │
  └──────────────┴───────────────────────────────────────────────────────────┘

MULTIPLE ELEMENTS:
  getByRole → throws if multiple found (use getAllByRole)
  getAllByRole, queryAllByRole, findAllByRole → return arrays

QUERY METHODS:
  ByRole          → getByRole('button', { name: /submit/i })
  ByLabelText     → getByLabelText(/email/i)
  ByPlaceholderText → getByPlaceholderText(/enter email/i)
  ByText          → getByText(/welcome back/i)
  ByDisplayValue  → getByDisplayValue('alice@example.com')
  ByAltText       → getByAltText(/profile picture/i)
  ByTitle         → getByTitle(/close dialog/i)
  ByTestId        → getByTestId('submit-button') ← use as last resort


================================================================================
6. QUERY PRIORITY GUIDE
================================================================================

This is the official RTL recommended priority order:

PRIORITY 1: Accessible to Everyone (Screen Readers + Sighted Users)
  ┌────────────────────┬──────────────────────────────────────────────────┐
  │ ByRole             │ Recommended #1. Uses ARIA roles.                 │
  │                    │ getByRole('button', { name: /submit/i })         │
  │                    │ getByRole('textbox', { name: /email/i })         │
  ├────────────────────┼──────────────────────────────────────────────────┤
  │ ByLabelText        │ Best for form inputs with <label>.               │
  │                    │ getByLabelText(/email address/i)                 │
  ├────────────────────┼──────────────────────────────────────────────────┤
  │ ByPlaceholderText  │ For inputs with placeholder text.                │
  │                    │ getByPlaceholderText(/enter your email/i)        │
  ├────────────────────┼──────────────────────────────────────────────────┤
  │ ByText             │ Find by visible text content.                    │
  │                    │ getByText(/welcome back/i)                       │
  │                    │ getByText('Submit', { exact: true })             │
  ├────────────────────┼──────────────────────────────────────────────────┤
  │ ByDisplayValue     │ Find select/input by its current displayed value.│
  │                    │ getByDisplayValue('United States')               │
  └────────────────────┴──────────────────────────────────────────────────┘

PRIORITY 2: Semantic (Screen Reader Only)
  ┌────────────────────┬──────────────────────────────────────────────────┐
  │ ByAltText          │ For images with alt attributes.                  │
  │                    │ getByAltText(/user profile photo/i)              │
  ├────────────────────┼──────────────────────────────────────────────────┤
  │ ByTitle            │ For elements with title attribute.               │
  │                    │ getByTitle(/close dialog/i)                      │
  └────────────────────┴──────────────────────────────────────────────────┘

PRIORITY 3: Test IDs (Last Resort)
  ┌────────────────────┬──────────────────────────────────────────────────┐
  │ ByTestId           │ Only when other queries are not possible.        │
  │                    │ getByTestId('unique-test-id')                    │
  │                    │ Add data-testid="..." to the HTML element.       │
  └────────────────────┴──────────────────────────────────────────────────┘

WHY ROLE IS #1:
  getByRole('button') → Tests that the element IS a button (accessible)
  getByTestId('my-btn') → Just finds an element, doesn't test anything about it

  Role-based queries simultaneously:
  - Find the element
  - Verify it has the correct semantic role
  - Verify it's accessible

COMMON ROLES:
  button, link, heading (h1-h6), textbox, checkbox, radio,
  combobox (select), listbox, option, dialog, alert, alertdialog,
  navigation, main, banner, contentinfo, article, list, listitem,
  img, progressbar, status, form, table, row, cell, columnheader

7. RTL vs ENZYME
================================================================================

ENZYME (OLD APPROACH):
  import { shallow, mount } from 'enzyme';

  it('toggles on click', () => {
    const wrapper = shallow(<Toggle />);
    expect(wrapper.state('isOn')).toBe(false); // Internal state!
    wrapper.find('button').simulate('click');
    expect(wrapper.state('isOn')).toBe(true);  // Internal state!
  });

RTL (NEW APPROACH):
  it('toggles on click', async () => {
    render(<Toggle />);
    expect(screen.getByRole('button')).toHaveTextContent('Off');
    await userEvent.click(screen.getByRole('button'));
    expect(screen.getByRole('button')).toHaveTextContent('On');
  });

ENZYME's shallow() PROBLEM:
  shallow(<Parent />) renders Parent but NOT Child components.
  This means you're testing Parent in isolation from its children.
  When children fail, the unit test might not catch it.
  RTL renders the full tree by design.

8. THE TESTING MINDSET SHIFT
================================================================================

SHIFT FROM "HOW does it work?" TO "WHAT does the user see/do?"

BEFORE (implementation thinking):
  "Does the component set the `isLoading` state to true when the
   fetch starts and false when it finishes?"

AFTER (user thinking):
  "Does the user see a loading spinner while data is being fetched?
   Does the spinner disappear when data is displayed?"

PRACTICAL TRANSLATION:

  ❌ Implementation test:
    const { result } = renderHook(() => useProducts());
    expect(result.current.isLoading).toBe(true);
    await waitFor(() => expect(result.current.isLoading).toBe(false));

  ✅ Behavior test:
    render(<ProductList />);
    expect(screen.getByRole('progressbar')).toBeInTheDocument();
    expect(await screen.findByText('Widget')).toBeInTheDocument();
    expect(screen.queryByRole('progressbar')).not.toBeInTheDocument();

9. COMMON RTL UTILITIES
================================================================================

render(ui, options?)
  → Renders a React component to jsdom
  → Returns { container, baseElement, debug, asFragment, rerender, unmount, ...queries }

  const { rerender, unmount } = render(<Button disabled />);
  // Later:
  rerender(<Button disabled={false} />);
  unmount();

screen
  → Global query object for the rendered DOM
  → All get/query/find queries available as screen.getBy* etc.
  → screen.debug() for debugging

waitFor(callback, options?)
  → Polls until callback stops throwing
  → Default timeout: 1000ms, interval: 50ms

  await waitFor(() => {
    expect(screen.getByText('Saved!')).toBeInTheDocument();
  });

waitForElementToBeRemoved(callback)
  → Waits for element to disappear from DOM

  await waitForElementToBeRemoved(() => screen.queryByRole('progressbar'));

act(callback)
  → Wraps state updates that aren't handled automatically
  → Usually handled automatically by userEvent and render

within(element)
  → Scope queries to a specific container

  const nav = screen.getByRole('navigation');
  const links = within(nav).getAllByRole('link');
  expect(links).toHaveLength(3);

fireEvent
  → Low-level event firing (prefer userEvent instead)
  → fireEvent.click(element) — fires click event directly

  // fireEvent vs userEvent:
  fireEvent.click(button);              // Fires only the click event
  await userEvent.click(button);        // Fires mousedown, focus, mouseup, click, etc.

10. FULL EXAMPLE: TESTING A COMPONENT
================================================================================

COMPONENT:
  // LoginForm.tsx
  export function LoginForm({ onSuccess }) {
    const [email, setEmail] = useState('');
    const [password, setPassword] = useState('');
    const [error, setError] = useState('');
    const [isLoading, setIsLoading] = useState(false);

    const handleSubmit = async (e) => {
      e.preventDefault();
      if (!email) { setError('Email is required'); return; }
      if (!password) { setError('Password is required'); return; }
      setIsLoading(true);
      try {
        await login(email, password);
        onSuccess();
      } catch {
        setError('Invalid credentials');
      } finally {
        setIsLoading(false);
      }
    };

    return (
      <form onSubmit={handleSubmit}>
        <label htmlFor="email">Email</label>
        <input id="email" type="email" value={email} onChange={e => setEmail(e.target.value)} />
        <label htmlFor="password">Password</label>
        <input id="password" type="password" value={password} onChange={e => setPassword(e.target.value)} />
        {error && <p role="alert">{error}</p>}
        <button type="submit" disabled={isLoading}>
          {isLoading ? 'Logging in...' : 'Log In'}
        </button>
      </form>
    );
  }

TESTS:
  import { render, screen, waitFor } from '@testing-library/react';
  import userEvent from '@testing-library/user-event';
  import { LoginForm } from './LoginForm';
  import { login } from '../api/auth';

  jest.mock('../api/auth');

  describe('LoginForm', () => {
    const user = userEvent.setup();
    const mockOnSuccess = jest.fn();

    beforeEach(() => {
      jest.clearAllMocks();
      render(<LoginForm onSuccess={mockOnSuccess} />);
    });

    describe('validation', () => {
      it('shows error when email is missing', async () => {
        await user.click(screen.getByRole('button', { name: /log in/i }));
        expect(screen.getByRole('alert')).toHaveTextContent('Email is required');
      });

      it('shows error when password is missing', async () => {
        await user.type(screen.getByLabelText(/email/i), 'test@test.com');
        await user.click(screen.getByRole('button', { name: /log in/i }));
        expect(screen.getByRole('alert')).toHaveTextContent('Password is required');
      });
    });

    describe('successful submission', () => {
      it('calls onSuccess after successful login', async () => {
        (login as jest.Mock).mockResolvedValue({ token: 'abc' });

        await user.type(screen.getByLabelText(/email/i), 'user@test.com');
        await user.type(screen.getByLabelText(/password/i), 'pass123');
        await user.click(screen.getByRole('button', { name: /log in/i }));

        await waitFor(() => expect(mockOnSuccess).toHaveBeenCalled());
        expect(login).toHaveBeenCalledWith('user@test.com', 'pass123');
      });

      it('shows loading state during submission', async () => {
        (login as jest.Mock).mockImplementation(() => new Promise(r => setTimeout(r, 100)));

        await user.type(screen.getByLabelText(/email/i), 'user@test.com');
        await user.type(screen.getByLabelText(/password/i), 'pass123');
        await user.click(screen.getByRole('button', { name: /log in/i }));

        expect(screen.getByRole('button')).toHaveTextContent('Logging in...');
        expect(screen.getByRole('button')).toBeDisabled();
      });
    });

    describe('failed submission', () => {
      it('shows error message when credentials are invalid', async () => {
        (login as jest.Mock).mockRejectedValue(new Error('Unauthorized'));

        await user.type(screen.getByLabelText(/email/i), 'user@test.com');
        await user.type(screen.getByLabelText(/password/i), 'wrongpass');
        await user.click(screen.getByRole('button', { name: /log in/i }));

        expect(await screen.findByRole('alert')).toHaveTextContent('Invalid credentials');
        expect(mockOnSuccess).not.toHaveBeenCalled();
      });
    });
  });
