1. WHAT IS CYPRESS
================================================================================

Cypress is a JavaScript-based E2E testing framework that runs INSIDE the browser.

KEY FEATURES:
  - Time-travel debugging: See exactly what happened at each command
  - Real-time reloads: Tests re-run automatically on file save
  - Automatic waiting: No explicit sleeps — commands wait automatically
  - Network stubbing: cy.intercept() to mock HTTP calls
  - Screenshot + video on failure
  - Component testing mode (Cypress 10+)
  - Detailed Cypress Dashboard for CI insights

RUNS IN: Chrome, Firefox, Edge, Electron
NOT SUPPORTED: Safari (use Playwright for cross-browser + Safari)

ARCHITECTURE: Test code runs inside the browser alongside the app.
  This means: no cross-origin issues (same domain), direct DOM access.

COMMAND CHAINING:
  Cypress commands are queued and run asynchronously.
  You NEVER await in Cypress — the queue handles ordering.

  cy.get('button').click(); // Queued
  cy.contains('Success');   // Queued — runs after click completes

2. INSTALLATION AND SETUP
================================================================================

INSTALL:
  npm install --save-dev cypress

OPEN CYPRESS GUI:
  npx cypress open
  # Launches the Test Runner — choose E2E Testing or Component Testing

FIRST LAUNCH — It creates:
  cypress/
  ├── e2e/           ← Your test files
  ├── fixtures/      ← Mock data (JSON files)
  ├── support/
  │   ├── commands.ts  ← Custom commands
  │   └── e2e.ts       ← Global config, imports
  └── downloads/     ← Downloaded files
  cypress.config.ts  ← Cypress configuration

TYPESCRIPT SETUP:
  npm install --save-dev typescript

  // cypress/tsconfig.json:
  {
    "compilerOptions": {
      "target": "es5",
      "lib": ["es5", "dom"],
      "types": ["cypress", "node"]
    },
    "include": ["**/*.ts"]
  }

4. WRITING YOUR FIRST TEST
================================================================================

FILE: cypress/e2e/login.cy.ts

  describe('Login Page', () => {
    beforeEach(() => {
      cy.visit('/login');
    });

    it('allows a user to log in with valid credentials', () => {
      cy.get('[data-testid="email-input"]').type('alice@example.com');
      cy.get('[data-testid="password-input"]').type('password123');
      cy.get('[data-testid="login-button"]').click();

      cy.url().should('include', '/dashboard');
      cy.contains('Welcome, Alice').should('be.visible');
    });

    it('shows error for invalid credentials', () => {
      cy.get('[data-testid="email-input"]').type('alice@example.com');
      cy.get('[data-testid="password-input"]').type('wrongpassword');
      cy.get('[data-testid="login-button"]').click();

      cy.get('[role="alert"]').should('contain.text', 'Invalid credentials');
      cy.url().should('include', '/login');
    });

    it('shows validation errors for empty form', () => {
      cy.get('[data-testid="login-button"]').click();
      cy.contains('Email is required').should('be.visible');
      cy.contains('Password is required').should('be.visible');
    });
  });

5. CORE CYPRESS COMMANDS
================================================================================

NAVIGATION:
  cy.visit('/path')               → Navigate to URL
  cy.visit('https://example.com') → Full URL
  cy.go('back')                   → Browser back
  cy.go('forward')                → Browser forward
  cy.reload()                     → Reload page

QUERYING:
  cy.get(selector)                → CSS selector (most common)
  cy.contains(text)               → Find element containing text
  cy.contains(selector, text)     → Scoped: element with text
  cy.find(selector)               → Child of current subject
  cy.within(() => { ... })        → Scope queries to an element
  cy.first()                      → First matched element
  cy.last()                       → Last matched element
  cy.eq(n)                        → nth matched element
  cy.filter(selector)             → Filter current set
  cy.not(selector)                → Exclude from current set

INTERACTION:
  .click()                        → Click element
  .click({ force: true })         → Click even if covered
  .dblclick()                     → Double click
  .rightclick()                   → Right click (context menu)
  .type('text')                   → Type into input
  .type('hello{enter}')           → Type with special keys
  .clear()                        → Clear input value
  .check()                        → Check checkbox/radio
  .uncheck()                      → Uncheck checkbox
  .select('value')                → Select dropdown option
  .focus()                        → Focus element
  .blur()                         → Blur element
  .hover()                        → Hover (limited — use trigger)
  .trigger('mouseover')           → Trigger any event
  .scrollTo('bottom')             → Scroll element/page
  .scrollIntoView()               → Scroll element into view

BROWSER:
  cy.clearCookies()               → Clear all cookies
  cy.clearLocalStorage()          → Clear localStorage
  cy.setCookie(name, value)       → Set a cookie
  cy.getCookie(name)              → Get a cookie
  cy.window()                     → Access window object
  cy.document()                   → Access document
  cy.title()                      → Get page title
  cy.url()                        → Get current URL
  cy.hash()                       → Get URL hash

FILE:
  cy.readFile('path')             → Read file contents
  cy.writeFile('path', content)   → Write to file

6. SELECTORS AND INTERACTING WITH ELEMENTS
================================================================================

SELECTOR PRIORITY:
  1. data-testid (most stable):
     cy.get('[data-testid="submit-btn"]').click();

  2. Role (accessible and stable):
     cy.get('[role="button"][aria-label="Submit"]').click();

  3. Text content:
     cy.contains('Submit').click();
     cy.contains('button', 'Submit').click(); // Scoped to <button>

  4. CSS selectors (fragile, avoid if possible):
     cy.get('.submit-button').click();         // Tied to class name
     cy.get('#email').type('...');             // ID — more stable

  5. Form-related:
     cy.get('input[name="email"]').type('...');
     cy.get('select[name="country"]').select('US');
     cy.get('input[type="checkbox"]').check();

CHAINING cy.within():
  cy.get('[data-testid="user-card"]').within(() => {
    cy.get('[data-testid="username"]').should('have.text', 'alice');
    cy.get('[data-testid="delete-btn"]').click();
  });

cy.contains() EXAMPLES:
  cy.contains('Sign in');                      // Any element with this text
  cy.contains('h1', 'Dashboard');              // h1 with text "Dashboard"
  cy.contains('[data-testid="alert"]', 'Error'); // Specific element with text
  cy.contains(/welcome/i);                     // Regex match

SPECIAL TYPE KEYS:
  cy.get('input').type('Hello World');         // Type text
  cy.get('input').type('{enter}');             // Enter key
  cy.get('input').type('{backspace}');         // Backspace
  cy.get('input').type('{selectall}');         // Select all text
  cy.get('input').type('{ctrl}a');             // Ctrl+A
  cy.get('input').type('{cmd}k');              // Cmd+K (Mac)

7. ASSERTIONS (SHOULD, EXPECT, ASSERT)
================================================================================

.should() — CHAINABLE ASSERTIONS (most common in Cypress):
  cy.get('h1').should('have.text', 'Dashboard');
  cy.get('.alert').should('be.visible');
  cy.get('button').should('be.disabled');
  cy.get('input').should('have.value', 'alice@example.com');
  cy.get('[data-testid="count"]').should('contain.text', '5');
  cy.url().should('include', '/dashboard');
  cy.url().should('eq', 'http://localhost:3000/dashboard');
  cy.get('.item').should('have.length', 3);

CHAI ASSERTIONS IN .should():
  .should('exist')                   → Element exists in DOM
  .should('not.exist')               → Element not in DOM
  .should('be.visible')              → Element is visible
  .should('not.be.visible')          → Element is hidden
  .should('be.enabled')              → Form element is enabled
  .should('be.disabled')             → Form element is disabled
  .should('be.checked')              → Checkbox/radio is checked
  .should('have.class', 'active')    → Has CSS class
  .should('not.have.class', 'error') → Doesn't have CSS class
  .should('have.attr', 'href', '/') → Has attribute with value
  .should('have.css', 'color', 'rgb(0, 0, 0)')
  .should('have.text', 'Exact text') → Exact text content
  .should('contain.text', 'partial') → Contains substring
  .should('have.value', 'input val') → Input value
  .should('have.length', 5)          → Array/jQuery length

CHAINING MULTIPLE ASSERTIONS:
  cy.get('button')
    .should('be.visible')
    .and('be.enabled')
    .and('have.text', 'Submit');

CALLBACK ASSERTIONS (complex):
  cy.get('[data-testid="price"]').should(($el) => {
    const price = parseFloat($el.text().replace('$', ''));
    expect(price).to.be.greaterThan(0);
    expect(price).to.be.lessThan(1000);
  });

8. HOOKS: BEFORE, BEFOREEACH, AFTER, AFTEREACH
================================================================================

describe('User Management', () => {
  before(() => {
    // Runs ONCE before all tests in this describe block
    cy.task('db:seed');      // Seed the database
    cy.login('admin@example.com', 'adminpass'); // Login once
  });

  beforeEach(() => {
    // Runs before EACH test
    cy.visit('/admin/users');
    cy.clearLocalStorage(); // Reset state
  });

  afterEach(() => {
    // Runs after EACH test
    cy.task('db:cleanup:users'); // Clean up created users
  });

  after(() => {
    // Runs ONCE after all tests
    cy.task('db:reset'); // Full DB reset
  });

  it('creates a new user', () => { ... });
  it('deletes a user', () => { ... });
});

COMMON beforeEach PATTERNS:
  beforeEach(() => {
    cy.visit('/');                         // Navigate to home
    cy.intercept('GET', '/api/**').as('apiCall'); // Set up intercept
  });

  beforeEach(() => {
    // Programmatic login (much faster than UI login):
    cy.request('POST', '/api/login', {
      email: 'alice@example.com',
      password: 'password123',
    }).then(({ body }) => {
      window.localStorage.setItem('token', body.token);
    });
    cy.visit('/dashboard');
  });

9. CY.INTERCEPT() — NETWORK INTERCEPTION
================================================================================

cy.intercept() intercepts outgoing network requests and can:
  - Stub responses (return mock data)
  - Spy on requests (verify they were made)
  - Modify requests/responses

SYNTAX:
  cy.intercept(method, url, response?)

STUB A RESPONSE:
  cy.intercept('GET', '/api/users', {
    statusCode: 200,
    body: [{ id: 1, name: 'Alice' }, { id: 2, name: 'Bob' }],
  });

  cy.intercept('POST', '/api/users', {
    statusCode: 201,
    body: { id: 99, name: 'New User' },
  });

STUB WITH FIXTURE FILE:
  // cypress/fixtures/users.json
  cy.intercept('GET', '/api/users', { fixture: 'users.json' });

SIMULATE ERROR:
  cy.intercept('GET', '/api/users', { statusCode: 500, body: { error: 'Server Error' } });
  cy.intercept('GET', '/api/users', { forceNetworkError: true });

ALIASING INTERCEPTS (to wait for them):
  cy.intercept('GET', '/api/users').as('getUsers');
  cy.visit('/users');
  cy.wait('@getUsers'); // Wait for the request to complete
  cy.get('[data-testid="user-list"]').should('be.visible');

WAIT AND INSPECT THE REQUEST:
  cy.intercept('POST', '/api/contact').as('contactForm');
  cy.get('[data-testid="submit"]').click();
  cy.wait('@contactForm').then((interception) => {
    expect(interception.request.body).to.deep.equal({
      name: 'Alice',
      message: 'Hello',
    });
    expect(interception.response.statusCode).to.equal(200);
  });

DYNAMIC STUB (function as response):
  cy.intercept('GET', '/api/users/*', (req) => {
    const id = req.url.split('/').pop();
    req.reply({
      statusCode: 200,
      body: { id: Number(id), name: 'Dynamic User' },
    });
  });

WILDCARD PATTERNS:
  cy.intercept('GET', '/api/**')   → All GET requests to /api/
  cy.intercept('*', '/api/users') → Any method to /api/users

SIMULATE NETWORK DELAY:
  cy.intercept('GET', '/api/slow', (req) => {
    req.on('response', (res) => { res.setDelay(2000); });
  });

10. CY.TASK() AND CY.FIXTURE()
================================================================================

cy.task() — EXECUTE NODE.JS CODE FROM TESTS:
  Tasks run in the Node.js process (not the browser).
  Used for: seeding DB, reading files, making raw HTTP requests.

  // cypress.config.ts:
  on('task', {
    'db:seed': () => { return seedDatabase(); },
    'db:cleanup': () => { return cleanupDatabase(); },
    'generate:token': (userId) => { return generateToken(userId); },
  });

  // In test:
  cy.task('db:seed').then(() => { cy.visit('/'); });
  cy.task('generate:token', 1).then((token) => {
    cy.window().then(w => w.localStorage.setItem('token', token));
  });

cy.fixture() — LOAD FIXTURE DATA:
  Loads data from cypress/fixtures/ directory.

  // cypress/fixtures/user.json:
  // { "id": 1, "name": "Alice", "email": "alice@example.com" }

  cy.fixture('user').then((user) => {
    cy.get('[data-testid="name"]').type(user.name);
    cy.get('[data-testid="email"]').type(user.email);
  });

  // Or use as alias:
  cy.fixture('products').as('productData');
  cy.get('@productData').then((products) => {
    // use products...
  });

  // With intercept:
  cy.intercept('GET', '/api/users', { fixture: 'users' }).as('getUsers');

11. ALIASES (as)
================================================================================

.as('name') stores a value for later use with cy.get('@name').

ALIASING ELEMENTS:
  cy.get('[data-testid="save-button"]').as('saveBtn');
  cy.get('@saveBtn').click();
  cy.get('@saveBtn').should('be.disabled');

ALIASING INTERCEPTS:
  cy.intercept('POST', '/api/checkout').as('checkoutRequest');
  // After user action:
  cy.wait('@checkoutRequest');

ALIASING FIXTURES:
  cy.fixture('users').as('usersData');
  cy.get('@usersData').then((users) => { /* ... */ });

ALIASING WITHIN HOOKS (SHARE BETWEEN TESTS):
  before(() => {
    cy.fixture('user').as('testUser'); // Available as @testUser
  });

  it('uses shared fixture', function () {
    // Note: use function() not arrow function to access this
    cy.get('[data-testid="name"]').type(this.testUser.name);
  });

12. CYPRESS COMMANDS (CUSTOM COMMANDS)
================================================================================

Custom commands extend the cy object.
Define in cypress/support/commands.ts.

DEFINE:
  // cypress/support/commands.ts
  declare global {
    namespace Cypress {
      interface Chainable {
        login(email: string, password: string): Chainable<void>;
        dataCy(value: string): Chainable<JQuery<HTMLElement>>;
      }
    }
  }

  Cypress.Commands.add('login', (email: string, password: string) => {
    cy.request('POST', '/api/auth/login', { email, password })
      .then(({ body }) => {
        window.localStorage.setItem('auth_token', body.token);
      });
  });

  Cypress.Commands.add('dataCy', (value: string) => {
    return cy.get(`[data-cy="${value}"]`);
  });

USE:
  cy.login('alice@example.com', 'password123');
  cy.dataCy('submit-btn').click();

COMMON CUSTOM COMMANDS:
  // Log in via API (fast):
  Cypress.Commands.add('loginAs', (role) => {
    const users = { admin: { email: 'admin@...', pass: '...' }, user: { ... } };
    cy.request('POST', '/api/login', users[role]);
  });

  // Visit as authenticated user:
  Cypress.Commands.add('visitAuthenticated', (path) => {
    cy.login('user@example.com', 'password');
    cy.visit(path);
  });

        on('task', {
          'db:seed': () => { /* ... */ return null; },
        });
        return config;
      },
    },
  });

14. RUNNING TESTS
================================================================================

OPEN INTERACTIVE MODE (GUI):
  npx cypress open

RUN HEADLESSLY (CI):
  npx cypress run
  npx cypress run --browser chrome
  npx cypress run --spec 'cypress/e2e/auth/login.cy.ts'
  npx cypress run --headed                 # With browser UI visible

PARALLEL RUNS (Cypress Cloud):
  npx cypress run --record --key <key> --parallel

package.json SCRIPTS:
  {
    "scripts": {
      "cy:open": "cypress open",
      "cy:run": "cypress run",
      "cy:run:chrome": "cypress run --browser chrome",
      "test:e2e": "start-server-and-test start http://localhost:3000 cy:run"
    }
  }

ENVIRONMENT VARIABLES:
  CYPRESS_BASE_URL=https://staging.example.com npx cypress run
  # Or in cypress.config.ts env section
