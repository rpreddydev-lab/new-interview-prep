1. THE CASCADE EXPLAINED
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

The "C" in CSS stands for "Cascading." The cascade is the algorithm browsers use
to resolve conflicts when multiple CSS rules target the same element and property.

The cascade evaluates rules in this order (each step only used if previous ties):

  Step 1: Origin and Importance
  Step 2: Context (shadow DOM scoping)
  Step 3: Style Attribute (inline styles)
  Step 4: Cascade Layer order
  Step 5: Specificity
  Step 6: Order of appearance (source order)

2. ORIGIN CATEGORIES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Three origins for CSS:

A) User-Agent (Browser) Stylesheet:
   • Default styles applied by the browser (h1 is bold, links are blue, etc.)
   • Lowest priority in normal declarations
   • Reset/Normalize CSS targets this origin

B) User Stylesheet:
   • CSS added by the user (e.g., browser accessibility settings, user style extensions)
   • Between user-agent and author in priority

C) Author Stylesheet:
   • CSS written by web developers
   • Highest priority in normal declarations
   • Includes: external, internal, inline, CSS-in-JS

Priority order for NORMAL declarations (lowest to highest):
  User-Agent → User → Author

Priority order for !IMPORTANT declarations (REVERSED! lowest to highest):
  Author!important → User!important → User-Agent!important

⚠ This reversal ensures users can override author styles with !important
  for accessibility (e.g., large-text user stylesheet).

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
3. COMPLETE CASCADE PRIORITY (Highest to Lowest)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  1. Transitions (overrides everything during active transition)
  2. User-Agent !important
  3. User !important
  4. Author !important
     a. @layer (last layer wins for !important — reversed layer order)
     b. Unlayered !important
  5. Animations (@keyframes active frames)
  6. Author normal
     a. Inline style (specificity A column)
     b. @layer (later layer = higher priority)
     c. Unlayered styles (beat all layers)
     d. Specificity (higher = wins)
     e. Source order (later = wins)
  7. User normal
  8. User-Agent normal

4. CASCADE LAYERS (@layer)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Introduced in CSS 2022, @layer lets you explicitly control cascade priority
without relying on specificity tricks.

Declaring layers (the order establishes priority — LAST declared wins):
  @layer base, components, utilities;

  @layer base {
    /* Lowest priority */
    body { font-size: 16px; margin: 0; }
    a { color: blue; }
  }

  @layer components {
    /* Middle priority */
    .btn { padding: 8px 16px; background: blue; color: white; }
  }

  @layer utilities {
    /* Highest priority (of layered styles) */
    .mt-0 { margin-top: 0 !important; }
  }

Unlayered styles beat ALL layers:
  /* This ALWAYS wins over layered styles (regardless of specificity) */
  .force-red { color: red; }

Anonymous layers (no name — cannot be extended):
  @layer { .some-style { ... } }

Importing into a layer:
  @import url("bootstrap.css") layer(bootstrap);
  /* All of Bootstrap is sandboxed in the 'bootstrap' layer */

Nested layers:
  @layer framework {
    @layer base { ... }
    @layer components { ... }
  }
  /* Access: framework.base, framework.components */

5. INHERITANCE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Inheritance is the mechanism by which child elements automatically receive
certain CSS property values from their parent elements.

Properties that ARE inherited by default:
  Typography: font-family, font-size, font-weight, font-style, font-variant,
              line-height, letter-spacing, word-spacing, text-align,
              text-indent, text-transform, text-decoration (partially),
              white-space
  Color:      color
  List:       list-style, list-style-type, list-style-position
  Table:      border-collapse, border-spacing, caption-side, empty-cells
  Visual:     visibility, cursor, direction, unicode-bidi, quotes
  Other:      word-break, overflow-wrap, tab-size

Properties that are NOT inherited (each element starts from initial value):
  Layout: margin, padding, border, width, height, min/max-width/height
          display, position, top, right, bottom, left, float, clear
          overflow, z-index, flex/grid properties
  Visual: background, border-color, border-style, box-shadow
  Others: opacity, transform, transition, animation

How to check if a property inherits:
  Look at "Inherited: yes/no" in MDN documentation or browser DevTools.

6. INHERITANCE CONTROL KEYWORDS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Every CSS property can use these keywords to control inheritance:

inherit:
  • Forces the property to take the same value as the parent
  • Works on BOTH inherited and non-inherited properties
  .child { color: inherit; }          /* takes parent's color */
  .child { border: inherit; }         /* non-inherited — forces inheritance */

initial:
  • Resets the property to its specification-defined initial value (not browser default)
  • This is different from the browser stylesheet default!
  .element { color: initial; }        /* initial for color = black (not browser blue for links) */
  .element { display: initial; }      /* initial for display = inline (not block like <div>) */

unset:
  • If the property is naturally inherited: acts like inherit
  • If the property is NOT inherited: acts like initial
  .element { color: unset; }          /* inherited prop → acts as inherit */
  .element { padding: unset; }        /* non-inherited prop → acts as initial */

revert:
  • Rolls back the property to the browser stylesheet value (user-agent default)
  • More useful than initial because it uses browser defaults, not spec defaults
  .element { font-weight: revert; }   /* e.g., headings get browser bold back */

revert-layer:
  • Rolls back to the value from the previous cascade layer
  • Only relevant when using @layer

all shorthand (resets ALL properties at once):
  .element { all: initial; }  /* everything reset to initial */
  .element { all: unset; }    /* everything unset */
  .element { all: revert; }   /* everything reverted to browser defaults */

7. THE COMPUTED VALUE PROCESS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

For every CSS property on every element, the browser goes through:

1. Declared Values — all values from all stylesheet origins
2. Cascaded Value — winner after applying the cascade algorithm
3. Specified Value — cascaded value, or inherited value, or initial value
4. Computed Value — absolute value (e.g., em → px, currentColor → actual color)
5. Used Value — final value after layout (e.g., percentages → exact px)
6. Actual Value — value after constraints (rounding for display)

In DevTools:
  • "Inherited from parent" → shows inherited properties
  • Strikethrough → overridden property
  • Light text → property comes from browser stylesheet
  • Computed tab → shows computed values in absolute units

8. SHORTHAND vs LONGHAND PROPERTIES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Shorthand properties set multiple related properties at once:

  /* Shorthand */
  margin: 10px 20px 30px 40px;  /* top right bottom left */
  padding: 16px;                 /* all sides = 16px */
  border: 1px solid #ccc;
  background: url(img.png) no-repeat center / cover;
  font: italic bold 16px/1.5 'Arial', sans-serif;
  transition: all 0.3s ease;
  animation: spin 1s linear infinite;
  flex: 1 1 auto;
  grid: auto-flow / 1fr 1fr;

⚠ Shorthand resets unspecified sub-properties to their initial values:
  .box { border: 2px solid red; }
  .box { border-color: blue; }   /* only color overridden, still solid & 2px */

  .box { border: 2px solid red; }
  .box { border: ; }             /* ERROR: invalid; would reset everything */

  .box { transition: color 0.3s; }
  .box:hover { transition: all 0.5s; }  /* overwrites color transition! */
  /* Fix: list all transitions explicitly */

9. KEY INTERVIEW QUESTIONS — CASCADE AND INHERITANCE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: What is the cascade in CSS?
A: The cascade is the algorithm that resolves conflicts when multiple CSS rules
   apply to the same element's property. It considers (in order): origin and
   importance, cascade layers, specificity, and source order.

Q: What is the difference between inherit, initial, and unset?
A: inherit → use the parent element's value (works on any property)
   initial  → use the CSS specification's initial value for the property
   unset    → acts as inherit if the property naturally inherits,
              otherwise acts as initial (resets based on property nature)

Q: What is the difference between initial and revert?
A: initial resets to the CSS specification's initial value (e.g., display: initial
   = inline for all elements).
   revert rolls back to what the browser stylesheet (user-agent) would set
   (e.g., display: revert on a <div> = block).
   revert is generally more useful for "reset to normal browser default."

Q: Why are some CSS properties inherited and others not?
A: By design. Text-related properties (color, font-family) inherit because it
   would be tedious to set them on every text node. Box model properties
   (margin, padding) don't inherit because each element needs its own spacing.

Q: What does !important do and why should it be avoided?
A: !important overrides all normal cascade rules for that declaration.
   It should be avoided because it breaks the natural cascade, making code hard
   to maintain ("!important wars" where each override needs another !important).
   Use @layer or better specificity management instead.

Q: What are CSS @layer cascade layers?
A: @layer lets you define named layers with an explicit priority order. Rules in
   later-declared layers win over earlier ones, regardless of specificity. Unlayered
   styles win over all layers. They solve the problem of third-party library
   specificity conflicts by sandboxing styles into layers.

Q: What is the difference between the cascade and inheritance?
A: Cascade resolves CONFLICTS between rules targeting the same element/property.
   Inheritance is when a child element receives a property value from its parent
   when no explicit value is set for that child. They're separate mechanisms:
   cascade picks the "winning" declared value; inheritance applies when there's
   no winning declaration.
