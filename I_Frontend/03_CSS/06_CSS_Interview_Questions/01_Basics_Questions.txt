SECTION 1 — WHAT IS CSS & HOW IT WORKS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q1: What is CSS and what is it used for?
A:  CSS (Cascading Style Sheets) is a stylesheet language used to describe the
    presentation of HTML/XML documents. It controls layout, colors, typography,
    spacing, animations, and responsive behavior — separating content (HTML)
    from presentation.

Q2: Explain the CSS rendering pipeline (browser rendering process).
A:  1. HTML is parsed into the DOM (Document Object Model)
    2. CSS is parsed into the CSSOM (CSS Object Model)
    3. DOM + CSSOM are combined into the Render Tree (only visible nodes)
    4. Layout (reflow): browser calculates the geometry (size/position)
    5. Paint: pixels are drawn for each layer
    6. Composite: layers are composited in correct order on screen

Q3: What are the three ways to add CSS to an HTML document?
A:  1. External stylesheet: <link rel="stylesheet" href="styles.css">
       Best for performance — cached, separated from HTML
    2. Internal style block: <style> ... </style> inside <head>
       Used for page-specific styles or small sites
    3. Inline styles: <div style="color: red;">
       Highest specificity — hard to maintain, avoid in production

Q4: What does "cascading" mean in CSS?
A:  Cascading refers to the algorithm that resolves which styles apply when
    multiple rules target the same element. Resolution order:
    1. Origin (user-agent < user < author)
    2. Importance (!important inverts this)
    3. Cascade layers (@layer)
    4. Specificity
    5. Source order (last declaration wins)

Q5: What is the difference between a class and an ID in CSS?
A:  Class (.name): can be applied to multiple elements, lower specificity (0,1,0).
    ID (#name): must be unique per page, higher specificity (1,0,0).
    Use classes for styling (reusable). Reserve IDs for JS anchoring, not CSS.

Q6: What is the difference between visibility:hidden and display:none?
A:  display:none — element removed from flow, takes no space, not accessible
    visibility:hidden — element invisible but still occupies space in flow
    opacity:0 — element invisible, in flow, still interactable by mouse/keyboard

Q7: What is the CSS box model?
A:  Every element is a box with four layers:
    Content → Padding → Border → Margin (outside to inside)
    box-sizing: content-box (default): width = content only
    box-sizing: border-box:  width = content + padding + border (much more predictable)
    Best practice: * { box-sizing: border-box; }

Q8: What is the difference between margin and padding?
A:  Margin: space OUTSIDE the border — creates distance from other elements.
    Transparent, cannot have a background.
    Padding: space INSIDE the border — between border and content.
    Background applies to padding area.

Q9: What causes margin collapse and how do you prevent it?
A:  Margin collapse: when the top and bottom margins of adjacent block elements
    merge into the larger of the two margins instead of adding.
    Happens:
    1. Adjacent siblings — bottom margin of one + top margin of next → larger wins
    2. Parent and first/last child — if no border/padding separating them
    3. Empty blocks — top and bottom margin of same element collapse

    Prevention:
    • Add padding or border to parent
    • Use overflow: hidden on parent
    • Make parent a flex/grid container
    • Use display: flow-root
    • Use margin-top instead of margin-bottom (or vice versa)

Q10: What is CSS specificity?
A:  Specificity determines which CSS rule applies when multiple rules match.
    Calculated as a 4-column score: (A, B, C, D)
    A = inline styles (1,0,0,0)
    B = IDs (0,1,0,0)
    C = classes, attributes, pseudo-classes (0,0,1,0)
    D = elements, pseudo-elements (0,0,0,1)
    Higher number in leftmost column wins. Example:
    #nav .link:hover → (0,1,1,0) → beats .nav .link:hover → (0,0,2,0)

SECTION 2 — CSS UNITS AND COLORS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q11: What is the difference between em and rem units?
A:   em: relative to the CURRENT ELEMENT'S font-size. Compounds with nesting.
     rem: relative to the ROOT element (<html>) font-size. Does not compound.
     Example: if html { font-size: 16px } then 1rem = 16px everywhere.
     Use rem for font-sizes and global spacing, em for component-local scaling.

Q12: What is the difference between px, em, rem, %, vw, vh?
A:   px  — absolute pixels, not affected by user font preferences
     em  — relative to current element's font-size
     rem — relative to root font-size (consistent, predictable)
     %   — relative to parent element (width, usually)
     vw  — 1% of viewport WIDTH
     vh  — 1% of viewport HEIGHT
     For font-size: prefer rem. For layout: %, vw/vh, or rem.

Q13: What is clamp() and when would you use it?
A:   clamp(min, preferred, max) — constrains a value between a minimum and maximum.
     font-size: clamp(1rem, 2.5vw, 2rem) — scales with viewport but never
     below 1rem (mobile) or above 2rem (desktop). Used for fluid typography
     and spacing without media query breakpoints.

SECTION 3 — CSS VARIABLES AND INHERITANCE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q14: What are CSS custom properties (CSS variables)?
A:   CSS variables are custom property values defined with -- prefix.
     :root { --primary: #007bff; }
     .button { color: var(--primary); }
     They inherit through the DOM, are visible in DevTools, and can be
     read/written with JavaScript. Unlike SASS variables, they are runtime.

Q15: What CSS properties are inherited by default?
A:   Inherited: color, font-*, line-height, letter-spacing, text-align,
     text-transform, visibility, cursor, list-style-*, word-spacing
     Not inherited: margin, padding, border, background, display, position,
     width, height, box-shadow, opacity (most box-model and layout properties)

Q16: What do inherit, initial, unset, and revert do?
A:   inherit  — forces element to inherit the property from parent
     initial  — resets to CSS specification default (may differ from browser default)
     unset    — if property is inherited, act like inherit; else, act like initial
     revert   — reverts to browser's user-agent stylesheet value

SECTION 4 — COMMON PRACTICAL QUESTIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q17: How do you vertically center an element?
A:   Multiple approaches:
     1. Flexbox: parent → display:flex; align-items:center; justify-content:center
     2. Grid: parent → display:grid; place-items:center
     3. Absolute: position:absolute; top:50%; left:50%; transform:translate(-50%,-50%)
     4. Absolute + margin auto: position:absolute; inset:0; margin:auto;
        (requires element to have a defined width and height)

Q18: How do you create a responsive two-column layout?
A:   Modern: CSS Grid — grid-template-columns: 1fr 1fr (or repeat(2, 1fr))
     Flex: display:flex; and children flex:1
     Old way: float-based (now discouraged)
     Responsive (mobile-first): start with grid-template-columns:1fr,
     then @media(min-width:768px) { grid-template-columns: 1fr 1fr }

Q19: What is z-index and when does it not work?
A:   z-index controls stacking order on the z-axis. Higher = in front.
     It only works on POSITIONED elements (position != static).
     It also doesn't work when a STACKING CONTEXT exists. A stacking context
     is created by: opacity<1, transform, filter, isolation:isolate,
     position:fixed/sticky, will-change, etc. Elements inside a stacking context
     are ordered only relative to siblings INSIDE that same context.

Q20: What is the difference between reset CSS and normalize CSS?
A:   CSS Reset: removes ALL browser default styles — margins, paddings, headings,
     etc. Results in a blank slate. More work to add needed defaults back.
     (e.g., Eric Meyer's reset)
     Normalize CSS: preserves useful browser defaults but corrects inconsistencies
     between browsers. Less aggressive, keeps useful defaults.
     (e.g., normalize.css, modern-normalize)
