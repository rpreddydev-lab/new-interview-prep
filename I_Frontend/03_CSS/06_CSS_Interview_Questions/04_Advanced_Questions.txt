SECTION 1 — SELECTORS AND SPECIFICITY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q1: What is the :is() selector and how does it affect specificity?
A:  :is() matches any element that matches any of the selector list inside.
    p:is(h1, h2, h3) { } = matches h1, h2, h3.
    Specificity: :is() takes the specificity of its MOST SPECIFIC argument.
    :is(#id, .class) has specificity (1,0,0) because #id is most specific.

Q2: What is the difference between :is() and :where()?
A:  Both match a list of selectors, but:
    :is() takes the specificity of its highest-specificity argument.
    :where() ALWAYS has zero specificity — it's a specificity-free filter.
    Use :where() in reusable CSS libraries/design systems where you want
    authors to easily override styles.

Q3: What is the :has() pseudo-class?
A:  :has() is a "parent selector" — selects an element based on its children.
    a:has(img) — selects <a> elements that contain an <img>
    .card:has(.badge) — selects .card when it contains a .badge
    h1:has(+ p) — selects h1 followed by a p sibling
    Supported in all modern browsers. One of the most powerful CSS features
    added in recent years.

Q4: What is the difference between :nth-child() and :nth-of-type()?
A:  :nth-child(n) — counts ALL siblings and selects the nth one
                     (then also checks if it matches the selector)
    :nth-of-type(n) — counts only siblings of the SAME TYPE
    Example: p:nth-child(2) selects the 2nd child of its parent only if it's a <p>
    p:nth-of-type(2) selects the 2nd <p> among siblings regardless of position

Q5: How do you calculate which CSS rule wins?
A:  Specificity comparison (A, B, C, D):
    A = inline styles, B = IDs, C = classes/attributes/pseudo-classes, D = elements
    Compare from left to right. First non-tie wins.
    Same specificity? Source order — last declaration wins.
    !important overrides all (except !important in a higher-origin source).

SECTION 2 — CSS FEATURES AND MODERN CSS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q6: What are cascade layers (@layer)?
A:  @layer lets you organize CSS into ordered layers where lower layers win
    over higher by default:
    @layer reset, base, components, utilities;
    @layer base { ... }
    @layer components { ... }
    The declaration order determines priority: utilities > components > base > reset.
    Unlayered styles always beat layered styles (regardless of specificity).
    Useful for managing third-party CSS and design systems without specificity wars.

Q7: What is the contain property?
A:  CSS Containment tells the browser that an element is independent of its
    surroundings — enabling rendering optimizations:
    contain: layout — element's layout doesn't affect outside layout
    contain: paint  — element's contents don't render outside its box
    contain: size   — element's size is independent of its contents
    contain: strict — all of the above
    Used with container queries (container-type: inline-size implies containment).

Q8: What is the @property rule?
A:  @property lets you register a CSS custom property with a type, default,
    and inheritance:
    @property --rotation {
      syntax: '<angle>';
      initial-value: 0deg;
      inherits: false;
    }
    This enables ANIMATING custom properties (normally not animatable),
    type checking, and better tooling support.
    @keyframes spin { to { --rotation: 360deg; } }

Q9: What is the difference between CSS animations and JavaScript animations?
A:  CSS Animations: Defined in stylesheets, run on compositor thread (transform/opacity),
    no JavaScript needed, browser can optimize. Limited to predefined keyframes.
    JS Animations (requestAnimationFrame / Web Animations API): Full control, dynamic
    values, complex sequencing, physics-based motion. May run on main thread
    (can be janky if main thread is busy). WAAPI (Web Animations API) can run
    on compositor like CSS animations.

Q10: What is will-change and what are its caveats?
A:   will-change hints to the browser that an element will change, enabling it
     to pre-promote the element to a GPU layer.
     will-change: transform, opacity; → GPU layer before animation starts
     Caveats:
     • Use sparingly — every GPU layer consumes memory
     • Apply only right before an animation, remove after
     • Don't apply to too many elements
     • Not a general performance fix — misuse causes memory pressure

SECTION 3 — PERFORMANCE AND BEST PRACTICES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q11: What CSS properties trigger layout, paint, or composite?
A:   Layout (reflow) — most expensive: width, height, margin, padding,
     top/left/right/bottom, font-size, display
     Paint — medium: color, background-color, border-color, box-shadow, outline
     Composite — cheapest (GPU): transform, opacity
     Stick to transform/opacity for animations to stay on the compositor thread.

Q12: What is Critical CSS?
A:   Critical CSS is the minimal CSS needed to render above-the-fold content.
     Inline it in <head> so the page renders without waiting for full CSS.
     Non-critical CSS is loaded asynchronously:
     <link rel="preload" href="styles.css" as="style" onload="this.rel='stylesheet'">
     Tools: critical (npm), Penthouse automatically extract critical CSS.

Q13: How does CSS selector performance work?
A:   Browsers read selectors RIGHT TO LEFT. The rightmost part is the "key selector."
     .nav ul li a — browser finds all <a> elements, then filters by <li> parent, etc.
     Performance guidelines:
     • Keep selectors short (1-3 components)
     • Avoid universal selector (*) as key selector
     • Avoid deeply nested selectors
     • ID selectors are fastest (unique), class selectors are fast
     Modern browsers are very fast — selector optimization is rarely the bottleneck.

Q14: What is the FOUC (Flash of Unstyled Content)?
A:   FOUC happens when HTML renders before CSS is loaded, showing unstyled
     content briefly. CSS in <head> (not deferred) prevents this. Inline
     critical CSS eliminates it entirely.

Q15: How does content-visibility: auto work?
A:   content-visibility: auto tells the browser to skip rendering off-screen
     elements until they're near the viewport. Can dramatically improve initial
     render performance on long pages.
     .article { content-visibility: auto; contain-intrinsic-size: 0 500px; }
     contain-intrinsic-size provides a placeholder size estimate for layout.

SECTION 4 — COMMON GOTCHAS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q16: Why does 100vh not work correctly on mobile browsers?
A:   Mobile browsers include the browser UI (address bar, toolbar) in their
     height when calculating vh. As users scroll, the UI hides, changing the
     actual visible height. 100vh = full height including hidden UI bars.
     Solutions:
     • Use dvh (dynamic viewport height) — adjusts as UI shows/hides
     • Use svh (small viewport height) — smallest possible viewport (UI shown)
     • Use lvh (large viewport height) — largest possible viewport (UI hidden)
     • Use min-height: 100vh instead of height: 100vh

Q17: Why does transform break position:fixed?
A:   When ANY ancestor element has a transform applied (including translate(0,0)
     or scale(1)), it creates a new containing block. Fixed-position descendants
     position relative to this ancestor, not the viewport.
     This is spec-compliant but unexpected. Solution: move the fixed element
     outside of any transformed ancestor.

Q18: Why are my flex items not shrinking below their content size?
A:   By default, flex items won't shrink smaller than their min-content size.
     min-width/min-height defaults to auto for flex items, not 0.
     Fix: .flex-item { min-width: 0; } or overflow: hidden/auto.
     This is the most common Flexbox gotcha.

Q19: What is the difference between shorthand resets?
A:   .element { margin: 0; } → resets only margin shorthand (all 4 sides)
     .element { all: initial; } → resets ALL CSS properties to initial values
     .element { all: unset; } → same but uses inherit for inherited properties
     Be careful with all — it also resets display, box-sizing, etc.

Q20: What is the contain-intrinsic-size property?
A:   When using content-visibility: auto, the browser needs a size estimate
     for off-screen elements for layout purposes. contain-intrinsic-size
     provides this estimate:
     contain-intrinsic-size: 500px → estimate the element is 500px tall
     contain-intrinsic-size: auto 500px → use last known size, fallback to 500px
     Without it, all off-screen elements collapse to 0, causing scroll jumps.
