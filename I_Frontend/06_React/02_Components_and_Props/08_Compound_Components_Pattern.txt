1. WHAT IS THE COMPOUND COMPONENTS PATTERN?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Compound Components is a pattern where multiple components work together
sharing implicit state via Context. The parent manages shared state; children
are sub-components that consume it without explicit prop drilling.

Real-world examples of compound components:
  <select>
    <option value="1">Option 1</option>
    <option value="2">Option 2</option>
  </select>

  // HTML <select> and <option> are compound components — they work TOGETHER.
  // <option> doesn't need you to pass which option is currently selected;
  // it gets that context from <select> implicitly.

React compound component equivalent:
  <Tabs>
    <Tabs.List>
      <Tabs.Tab>Profile</Tabs.Tab>
      <Tabs.Tab>Settings</Tabs.Tab>
    </Tabs.List>
    <Tabs.Panels>
      <Tabs.Panel>Profile content</Tabs.Panel>
      <Tabs.Panel>Settings content</Tabs.Panel>
    </Tabs.Panels>
  </Tabs>

2. IMPLEMENTATION — CONTEXT-BASED COMPOUND COMPONENTS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  import { createContext, useContext, useState } from 'react';

  // 1. Create context for shared state
  const TabsContext = createContext(null);

  // 2. Parent component holds state, provides context
  function Tabs({ children, defaultIndex = 0 }) {
    const [activeIndex, setActiveIndex] = useState(defaultIndex);

    return (
      <TabsContext.Provider value={{ activeIndex, setActiveIndex }}>
        <div className="tabs">{children}</div>
      </TabsContext.Provider>
    );
  }

  // 3. Sub-components consume context
  function TabList({ children }) {
    return <div className="tab-list" role="tablist">{children}</div>;
  }

  function Tab({ children, index }) {
    const { activeIndex, setActiveIndex } = useContext(TabsContext);
    const isActive = activeIndex === index;

    return (
      <button
        role="tab"
        aria-selected={isActive}
        className={isActive ? 'tab active' : 'tab'}
        onClick={() => setActiveIndex(index)}
      >
        {children}
      </button>
    );
  }

  function TabPanels({ children }) {
    return <div className="tab-panels">{children}</div>;
  }

  function TabPanel({ children, index }) {
    const { activeIndex } = useContext(TabsContext);
    if (activeIndex !== index) return null;
    return <div role="tabpanel">{children}</div>;
  }

  // 4. Attach sub-components as static properties (nice API)
  Tabs.List   = TabList;
  Tabs.Tab    = Tab;
  Tabs.Panels = TabPanels;
  Tabs.Panel  = TabPanel;

  // 5. Usage
  function App() {
    return (
      <Tabs defaultIndex={0}>
        <Tabs.List>
          <Tabs.Tab index={0}>Profile</Tabs.Tab>
          <Tabs.Tab index={1}>Settings</Tabs.Tab>
          <Tabs.Tab index={2}>Billing</Tabs.Tab>
        </Tabs.List>
        <Tabs.Panels>
          <Tabs.Panel index={0}><ProfileForm /></Tabs.Panel>
          <Tabs.Panel index={1}><SettingsForm /></Tabs.Panel>
          <Tabs.Panel index={2}><BillingInfo /></Tabs.Panel>
        </Tabs.Panels>
      </Tabs>
    );
  }

3. AUTO INDEX INJECTION (advanced — children traversal)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

We can auto-inject the index prop so consumers don't pass it manually:

  function TabList({ children }) {
    return (
      <div className="tab-list" role="tablist">
        {React.Children.map(children, (child, index) =>
          React.cloneElement(child, { index })
        )}
      </div>
    );
  }

  // Now usage is cleaner — no manual index:
  <Tabs.List>
    <Tabs.Tab>Profile</Tabs.Tab>
    <Tabs.Tab>Settings</Tabs.Tab>
  </Tabs.List>

4. ACCORDION EXAMPLE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  const AccordionContext = createContext(null);

  function Accordion({ children }) {
    const [openId, setOpenId] = useState(null);
    return (
      <AccordionContext.Provider value={{ openId, setOpenId }}>
        <div className="accordion">{children}</div>
      </AccordionContext.Provider>
    );
  }

  function AccordionItem({ children, id }) {
    const { openId, setOpenId } = useContext(AccordionContext);
    const isOpen = openId === id;

    return (
      <div className="accordion-item">
        {React.Children.map(children, child =>
          React.cloneElement(child, { isOpen, onToggle: () => setOpenId(isOpen ? null : id) })
        )}
      </div>
    );
  }

  function AccordionHeader({ children, onToggle, isOpen }) {
    return (
      <button className="accordion-header" onClick={onToggle}>
        {children} <span>{isOpen ? '▲' : '▼'}</span>
      </button>
    );
  }

  function AccordionBody({ children, isOpen }) {
    if (!isOpen) return null;
    return <div className="accordion-body">{children}</div>;
  }

  Accordion.Item   = AccordionItem;
  Accordion.Header = AccordionHeader;
  Accordion.Body   = AccordionBody;

  // Usage — fully flexible layout:
  <Accordion>
    <Accordion.Item id="faq1">
      <Accordion.Header>What is React?</Accordion.Header>
      <Accordion.Body>React is a JavaScript library...</Accordion.Body>
    </Accordion.Item>
    <Accordion.Item id="faq2">
      <Accordion.Header>What are Hooks?</Accordion.Header>
      <Accordion.Body>Hooks are functions that...</Accordion.Body>
    </Accordion.Item>
  </Accordion>

5. BENEFITS AND TRADE-OFFS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Benefits:
  ✅ Flexible: consumers can rearrange, omit, or replace sub-components
  ✅ Implicit state sharing: no prop drilling
  ✅ Clean API: reads like HTML (semantic, expressive)
  ✅ Separation of concerns: each sub-component owns its piece of UI
  ✅ Easy to extend: add new sub-components without breaking existing API

Trade-offs:
  ❌ More initial boilerplate to set up
  ❌ Sub-components only work within their parent (context coupling)
  ❌ React.Children traversal has edge cases (Fragment wrapping, etc.)
  ❌ TypeScript typing can be complex

6. COMMON INTERVIEW QUESTIONS ON COMPOUND COMPONENTS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: What are Compound Components?
A: A design pattern where multiple components work together via shared implicit
   state (provided via Context). The parent holds state; sub-components consume
   it without explicit prop passing. Examples: Tabs, Accordion, Select, Modal.

Q: What is the advantage of Compound Components over a single monolithic component?
A: Flexibility. Instead of passing everything as props, consumers can rearrange,
   omit, or replace sub-components. E.g., swap out TabList position or add
   custom elements between panels — impossible with a single <Tabs tabs={[...]} />.

Q: How is state shared in Compound Components?
A: Via React Context. The parent creates a Context, provides shared state,
   and all sub-components consume it via useContext().

Q: What is React.cloneElement used for in this pattern?
A: To inject props (like index, isOpen) into children without the consumer
   explicitly passing them. The parent clones each child and merges new props.

Q: When would you use Compound Components over a single component with props?
A: When you want high flexibility in layout/composition. If consumers need to
   control the exact structure and ordering of sub-elements, Compound Components
   are ideal. For simpler use cases, a single component with props is sufficient.
