1. WHAT IS CLIENT-SIDE ROUTING
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Traditional server-side routing: Every URL change makes a full HTTP request.
The server responds with a new HTML document. Full page reload every time.

Client-side routing (SPA): The browser downloads one HTML file. JavaScript
intercepts URL changes, renders different components — no page reload, instant
navigation.

React Router uses the browser's History API:
  - history.pushState()    → changes URL without server request
  - history.replaceState() → changes URL without adding history entry
  - popstate event         → browser back/forward button

  - HashRouter      — uses URL hash (#/about) — no server config needed
  - MemoryRouter    — stores history in memory (testing, React Native)
  - StaticRouter    — for SSR (server-side rendering)

3. CORE COMPONENTS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  <Routes>    — container for all <Route> elements, renders the first match
  <Route>     — maps a path to a component
  <Link>      — renders an <a> tag without a page reload
  <NavLink>   — like Link, adds active class when the link's path matches
  <Outlet>    — placeholder for nested route components
  <Navigate>  — programmatic redirect (replaces <Redirect> from v5)

  // Basic App.jsx
  import { Routes, Route, Link } from 'react-router-dom';

  function App() {
    return (
      <div>
        <nav>
          <Link to="/">Home</Link>
          <Link to="/about">About</Link>
          <Link to="/users">Users</Link>
        </nav>

        <Routes>
          <Route path="/" element={<Home />} />
          <Route path="/about" element={<About />} />
          <Route path="/users" element={<Users />} />
          <Route path="/users/:id" element={<UserDetail />} />
          <Route path="*" element={<NotFound />} />   {/* catch-all 404 */}
        </Routes>
      </div>
    );
  }

4. HOOKS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  useParams():
    Read dynamic URL segments (:param)
    function UserDetail() {
      const { id } = useParams();   // /users/42 → { id: '42' }
      return <div>User ID: {id}</div>;
    }

  useNavigate():
    Programmatic navigation
    const navigate = useNavigate();
    navigate('/dashboard');         // push new history entry
    navigate(-1);                   // go back (like browser back button)
    navigate('/login', { replace: true });  // replace current entry

  useLocation():
    Get current URL info: pathname, search, hash, state
    const location = useLocation();
    console.log(location.pathname);   // '/users/42'
    console.log(location.search);     // '?sort=name'
    console.log(location.state);      // data passed via navigate(path, { state })

  useSearchParams():
    Read/write URL query parameters
    const [searchParams, setSearchParams] = useSearchParams();
    const page = searchParams.get('page') ?? '1';
    setSearchParams({ page: '2', sort: 'name' });

  useMatch():
    Check if the current URL matches a pattern
    const match = useMatch('/users/:id');
    if (match) console.log(match.params.id);

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  <Link to="/about">About</Link>
  // Renders: <a href="/about">About</a>
  // Prevents default behavior, uses History API

  <NavLink to="/about" className={({ isActive }) => isActive ? 'active' : ''}>
    About
  </NavLink>
  // Adds 'active' class automatically when current URL matches

  NavLink style prop:
  <NavLink
    to="/about"
    style={({ isActive }) => ({ color: isActive ? 'red' : 'black' })}
  >
    About
  </NavLink>

Q: What is the difference between BrowserRouter and HashRouter?
A: BrowserRouter uses the HTML5 History API — URLs look like /about. Requires
   server configuration to redirect all paths to index.html. HashRouter uses
   the URL hash (#/about) — no server config needed, works on any static host.

Q: What replaced <Switch> in React Router v6?
A: <Routes> replaced <Switch>. Routes renders the FIRST match (exclusive),
   uses better matching by default (exact match is the default behavior now),
   and enables relative paths in nested routes.

Q: What is the difference between Link and a regular anchor tag?
A: An <a href> causes a full page reload (server request). React Router's
   <Link> uses the History API to change the URL and re-render components
   without any server request or page reload.

Q: How do you programmatically navigate in React Router v6?
A: Use the useNavigate hook. Call navigate('/path') to push, navigate('/path',
   { replace: true }) to replace, or navigate(-1) to go back.

Q: How do you access URL query parameters?
A: Use the useSearchParams hook, which returns a [searchParams, setSearchParams]
   tuple. searchParams.get('key') reads a parameter, setSearchParams({...}) 
   updates the URL query string.
