1. MAJOR CHANGES: v5 → v6
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  | Feature                 | v5                        | v6                          |
  |-------------------------|---------------------------|-----------------------------|
  | Route container         | <Switch>                  | <Routes>                    |
  | Exact matching          | exact prop required       | Default (always exact)      |
  | Nested routes           | Separate <Route> anywhere | Nested in JSX config        |
  | Child rendering         | component/render props    | element={<Component />}     |
  | Outlet for nested       | Not available             | <Outlet />                  |
  | Redirect component      | <Redirect to="/login" />  | <Navigate to="/login" />    |
  | Navigation hook         | useHistory                | useNavigate                 |
  | Route matching          | First match wins (Switch) | Best match wins (Routes)    |
  | Relative paths          | Absolute only             | Relative by default         |
  | Optional path params    | /users/:id? (possible)    | /users/:id (no ? in v6)     |
  | useRouteMatch           | Available                 | Replaced by useMatch        |

2. MIGRATION EXAMPLES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  === Route definition ===
  v5:
    <Switch>
      <Route exact path="/" component={Home} />
      <Route path="/about" render={() => <About extra="prop" />} />
      <Route path="/users/:id" component={UserDetail} />
    </Switch>

  v6:
    <Routes>
      <Route path="/" element={<Home />} />
      <Route path="/about" element={<About extra="prop" />} />
      <Route path="/users/:id" element={<UserDetail />} />
    </Routes>

  === Navigation ===
  v5:
    const history = useHistory();
    history.push('/dashboard');
    history.replace('/login');

  v6:
    const navigate = useNavigate();
    navigate('/dashboard');
    navigate('/login', { replace: true });

  === Redirect ===
  v5:
    import { Redirect } from 'react-router-dom';
    if (!isAuth) return <Redirect to="/login" />;

  v6:
    import { Navigate } from 'react-router-dom';
    if (!isAuth) return <Navigate to="/login" replace />;

3. REACT ROUTER v6.4+ DATA API
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  New in v6.4: loaders, actions, errorElement, useLoaderData, Form component
  Requires createBrowserRouter (not BrowserRouter)

  New hooks:
  - useLoaderData()    → data returned by the route's loader function
  - useActionData()    → data returned after form action submission
  - useNavigation()    → navigation state (idle/loading/submitting)
  - useFetcher()       → fetch data without navigating
  - useRouteError()    → error caught by errorElement

4. COMMON INTERVIEW QUESTIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: What replaced <Switch> in React Router v6?
A: <Routes>. It has the same exclusive-match behavior (renders the first/best
   match) but also uses relative paths by default and doesn't require the exact
   prop (all paths are exact by default).

Q: What replaced the component and render props on <Route> in v6?
A: The element prop. You pass JSX directly: element={<MyPage />} instead of
   component={MyPage} or render={() => <MyPage />}. This makes prop passing
   much cleaner and consistent.

Q: What replaced useHistory in v6?
A: useNavigate. navigate('/path') for push, navigate('/path', { replace: true })
   for replace, navigate(-1) for browser back.

Q: What is the advantage of v6's nested route config over v5?
A: In v5, nested routes were declared anywhere in the component tree. In v6,
   they're declared in one place (usually App.jsx), making the route hierarchy
   clear. <Outlet> enables shared layouts without messy route composition.
