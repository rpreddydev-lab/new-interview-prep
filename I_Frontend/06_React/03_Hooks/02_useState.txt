1. WHAT IS useState?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

useState is a Hook that lets you add state to functional components.

  const [state, setState] = useState(initialValue);

  - state: the current state value (read-only within this render)
  - setState: function to update the state
  - initialValue: initial state (only used on the FIRST render)

  // Simple counter example
  import { useState } from 'react';

  function Counter() {
    const [count, setCount] = useState(0);

    return (
      <div>
        <p>Count: {count}</p>
        <button onClick={() => setCount(count + 1)}>+</button>
        <button onClick={() => setCount(count - 1)}>-</button>
        <button onClick={() => setCount(0)}>Reset</button>
      </div>
    );
  }

2. HOW STATE UPDATES WORK
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Calling setState does NOT immediately update the state. It:
  1. Schedules a state update
  2. Triggers a re-render
  3. On the next render, the new state value is available

State is a SNAPSHOT — within a single render, state is fixed:
  function Counter() {
    const [count, setCount] = useState(0);

    function handleClick() {
      setCount(count + 1); // count is 0 here
      setCount(count + 1); // count is STILL 0 here (not updated yet!)
      setCount(count + 1); // count is STILL 0 here!
      // Result: count becomes 1, NOT 3
    }
    ...
  }

  // React 18 BATCHES all three setCount calls into ONE re-render
  // But since count is the same snapshot (0) in all three calls,
  // the result is setCount(1) three times = count becomes 1

3. FUNCTIONAL UPDATES (UPDATER FUNCTION)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

To update based on the PREVIOUS state (avoids stale closure bugs):

  // Direct update (can have stale closure problem):
  setCount(count + 1);

  // Functional update (always uses the latest state):
  setCount(prevCount => prevCount + 1);

  // Now this works correctly (result is 3, not 1):
  function handleClick() {
    setCount(c => c + 1); // c is 0
    setCount(c => c + 1); // c is 1 (latest)
    setCount(c => c + 1); // c is 2 (latest)
    // Result: count = 3
  }

  // Always use functional updates when:
  // - New state depends on previous state
  // - Inside async code or callbacks (stale closure risk)
  // - Inside useEffect with state in dependencies

4. LAZY INITIALIZATION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

If initial state is expensive to compute, pass a FUNCTION to useState.
The function runs ONLY ONCE on the initial render.

  // BAD: computeExpensiveValue() runs on EVERY render
  const [data, setData] = useState(computeExpensiveValue());

  // GOOD: function only runs on initial render
  const [data, setData] = useState(() => computeExpensiveValue());

  // Practical example: read from localStorage once
  const [theme, setTheme] = useState(() => {
    return localStorage.getItem('theme') ?? 'light';
  });

5. STATE WITH OBJECTS AND ARRAYS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Unlike class component setState, useState does NOT shallowly merge state.
You must spread existing state manually.

  // Object state — must spread to merge:
  const [user, setUser] = useState({ name: 'Alice', age: 30, city: 'NY' });

  // WRONG: replaces entire state object
  setUser({ age: 31 }); // now user = { age: 31 } (name and city lost!)

  // CORRECT: spread existing state, then override
  setUser(prev => ({ ...prev, age: 31 })); // { name: 'Alice', age: 31, city: 'NY' }

  // Array state — never mutate directly:
  const [items, setItems] = useState([1, 2, 3]);

  // WRONG: direct mutation
  items.push(4); // BAD: mutates array, React won't detect change, no re-render
  setItems(items); // still won't re-render (same reference)

  // CORRECT: create new array
  setItems([...items, 4]);         // add to end
  setItems(prev => [...prev, 4]);  // functional (safer)
  setItems(items.filter(i => i !== 2));  // remove item
  setItems(items.map(i => i === 2 ? 99 : i)); // update item

6. BATCHING OF STATE UPDATES (React 18)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

React batches multiple setState calls into a single re-render:

  function handleClick() {
    setCount(c => c + 1);  // }
    setName('Alice');       // } only ONE re-render total
    setLoading(false);      // }
  }

In React 18, this batching works EVERYWHERE (setTimeout, Promises, etc.).
Use flushSync() to force immediate synchronous update when needed.

7. WHEN STATE DOESN'T CAUSE RE-RENDER
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

React uses Object.is() to compare old vs new state.
If the value is the same, React skips re-render ("bailout").

  const [count, setCount] = useState(5);
  setCount(5); // same value → no re-render

  const [obj, setObj] = useState({ a: 1 });
  setObj({ a: 1 }); // NEW object reference → re-render! (Object.is fails for objects)
  setObj(obj);       // SAME reference → no re-render

8. PRACTICAL PATTERNS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Toggle boolean:
  const [isOpen, setIsOpen] = useState(false);
  const toggle = () => setIsOpen(prev => !prev);

Input handling:
  const [value, setValue] = useState('');
  <input value={value} onChange={e => setValue(e.target.value)} />

Multiple form fields:
  const [form, setForm] = useState({ name: '', email: '', password: '' });
  const handleChange = (e) => {
    setForm(prev => ({ ...prev, [e.target.name]: e.target.value }));
  };
  <input name="name" value={form.name} onChange={handleChange} />

List management:
  const [todos, setTodos] = useState([]);
  const addTodo = (text) => setTodos(prev => [...prev, { id: Date.now(), text, done: false }]);
  const toggleTodo = (id) => setTodos(prev =>
    prev.map(todo => todo.id === id ? { ...todo, done: !todo.done } : todo)
  );
  const deleteTodo = (id) => setTodos(prev => prev.filter(todo => todo.id !== id));

9. COMMON INTERVIEW QUESTIONS ON useState
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: What is useState and how does it work?
A: A hook for adding local state to functional components. It returns a tuple
   [currentValue, setterFunction]. Calling the setter schedules a re-render
   with the new value.

Q: What is the difference between direct update and functional update in useState?
A: Direct: setCount(count + 1) — uses the state value from the current render.
   Functional: setCount(c => c + 1) — receives the LATEST state value.
   Use functional when: new state depends on previous, or in async contexts.

Q: How does useState handle objects vs class component setState?
A: useState does NOT merge state — calling setUser({ age: 31 }) replaces the
   entire state. You must manually spread: setUser(prev => ({ ...prev, age: 31 })).

Q: What is lazy initialization in useState?
A: Passing a function to useState: useState(() => expensiveComputation())
   ensures the function only runs once on mount, not on every re-render.

Q: What is batching and how does it affect useState?
A: React batches multiple setState calls in the same event into one re-render.
   In React 18, this extends to async code too. Use flushSync() to bypass.

Q: Why is mutating state directly wrong?
A: React uses referential equality to detect state changes. Mutating an array
   or object directly keeps the same reference → React sees no change → no
   re-render. Always return a new reference.

Q: What is a "stale closure" in React state?
A: When a closure (like an event handler or async callback) captures a state
   value from an older render, it uses a stale (outdated) value. Fix: use
   functional updater setState(prev => ...) or useRef to hold the latest value.
