RE-RENDERS AND MEMOIZATION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q1: What causes a React component to re-render?
A: (1) Its own state changes. (2) Its parent re-renders (even if props didn't
   change). (3) Context it consumes changes. (4) A hook (useSelector, etc.)
   returns a new value. The default behavior is: parent re-renders → all
   children re-render. React.memo breaks this cascade for memoized components.

Q2: What is React.memo and when should you use it?
A: React.memo is a HOC that memoizes a functional component. It shallowly
   compares props and skips re-rendering if they haven't changed.
   Use it when: a component is expensive to render, its parent re-renders
   frequently, and it usually receives the same props. Don't use it for
   cheap components (comparison overhead > render cost) or components that
   always receive new prop values.

Q3: Why doesn't React.memo work when you pass an inline function?
A: Inline functions create a new reference on every render. React.memo uses
   shallow equality (===). {} !== {} and () => {} !== () => {}, so the
   prop always looks "changed." Fix with useCallback for functions and useMemo
   (or stable variables) for objects.

Q4: What is the difference between useMemo and React.memo?
A: React.memo memoizes a COMPONENT — prevents re-rendering when props are
   unchanged. useMemo memoizes a COMPUTED VALUE — prevents recalculating
   an expensive expression between renders. They're complementary — use
   both together for maximum effect.

Q5: How does useCallback help with React.memo?
A: If a parent passes a function to a memoized child component, the function
   must have a stable reference for memo to work. useCallback(fn, deps) returns
   the same function reference when deps haven't changed. Without it,
   React.memo is defeated because the function prop is always a new reference.

CODE SPLITTING AND BUNDLE SIZE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q6: What is code splitting and how do you implement it?
A: Code splitting breaks the JS bundle into smaller chunks loaded on demand.
   In React: use React.lazy(() => import('./Page')) with <Suspense fallback={...}>.
   The bundler creates a separate file per dynamic import, loaded only when
   that component first renders.

Q7: What is tree shaking?
A: Tree shaking removes dead code — exports that are never imported.
   It works with ES modules (import/export). Named imports allow the bundler
   to remove unused exports. Use { fn } from 'lib' instead of import * to
   enable tree shaking.

Q8: What is the initial bundle and how do you reduce its size?
A: The initial bundle is the JS downloaded before the app becomes interactive.
   Reduce it by: (1) Code splitting routes with React.lazy. (2) Replacing large
   libraries with smaller alternatives (date-fns instead of moment.js).
   (3) Lazy loading components not needed on initial render.
   (4) Analyzing the bundle with vite-plugin-visualizer or webpack-bundle-analyzer.

VIRTUALIZATION AND LISTS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q9: How would you render a list of 50,000 items in React?
A: Virtualize with react-window or @tanstack/react-virtual. Only render the
   items visible in the viewport (~20-30). As the user scrolls, unmount items
   that leave the viewport and mount new ones. The DOM always has a small,
   constant number of nodes regardless of total list size.

Q10: What is the key prop and why does it matter for performance?
A: keys help React's reconciliation algorithm identify which items in a list
   changed, were added, or removed. With stable keys, React can move/update
   existing DOM nodes instead of destroying and recreating them. Using index
   as key is problematic for reordered or filtered lists.

PROFILING

Q11: How do you identify performance problems in a React app?
A: (1) React DevTools Profiler — record an interaction, look for wide bars
   (slow renders) and "Why did this render?" to find causes.
   (2) Browser Performance tab — identify long tasks (>50ms) blocking the main thread.
   (3) DevTools "Highlight Updates" — see which components flash on interaction.
   Profile in production mode for accurate numbers.

Q12: What is the React <Profiler> component?
A: A built-in React component that calls an onRender callback with timing
   data (actualDuration, baseDuration) after each commit. Use it to send
   real-user monitoring data to an analytics service.

Q13: What is the difference between useTransition and debouncing?
A: Debouncing delays the update by a fixed time (e.g., 300ms always).
   useTransition has no fixed delay — React defers only when the render
   is too slow to complete synchronously and immediately commits if it's fast.
   Use useTransition for in-memory filtering; use debouncing for API calls
   to avoid too many requests.

Q14: What is useDeferredValue?
A: It creates a deferred copy of a value. While the deferred render is pending,
   it keeps returning the previous value. The deferred render is interruptible.
   Use it when you receive a value as a prop and can't access the state setter
   (where you'd use useTransition instead).

Q15: "Our app loads slowly on mobile. How would you improve it?"
A: Multi-step approach:
   (1) Measure first: Lighthouse audit, bundle analyzer, network tab.
   (2) Code split routes and heavy components with React.lazy.
   (3) Replace large libraries (moment.js 67KB → date-fns tree-shakeable).
   (4) Lazy load images (loading="lazy" or IntersectionObserver).
   (5) Add a service worker for caching static assets.
   (6) Server-side render the initial page for First Contentful Paint.
   (7) Move API data to TanStack Query for caching and background refetch.

Q16: "A list of items lags when users type in a filter input. How do you fix it?"
A: (1) Wrap the filter state update in startTransition (useTransition) so
   typing stays responsive. (2) Memoize the filtered list with useMemo.
   (3) Wrap the list with React.memo. (4) If still too many items visible,
   use react-window to virtualize. (5) Use useCallback for row event handlers.
