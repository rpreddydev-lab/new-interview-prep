ARCHITECTURE AND PATTERNS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q1: What is the Container/Presentational pattern?
A: Separate components into:
   - Container (smart): Fetches data, manages state, contains logic
   - Presentational (dumb): Only receives props and renders UI
   Benefits: Reusable UI components, easier testing, clear separation.
   Hooks largely replaced this pattern — custom hooks handle the logic,
   components stay presentational. The pattern is still useful for clarity.

Q2: What is the Compound Components pattern?
A: Components that work together and share implicit state via Context.
   The parent manages state; children are sub-components that access it
   without props being explicitly passed. Example: <Select>, <Tabs>.
   Provides a natural, JSX-readable API while keeping implementation hidden.

Q3: What is the Render Props pattern and when would you still use it?
A: A component accepts a function prop (render or children) that it calls
   with data, returning JSX. Example: <Mouse render={({x,y}) => <Dot x={x} y={y} />}.
   Custom hooks replaced most render props use cases. Still useful when:
   you need to scope logic to a specific part of the JSX tree, or for
   headless component libraries (Downshift, Radix UI's Slot concept).

Q4: What is a Higher-Order Component (HOC)?
A: A function that takes a component and returns a new enhanced component.
   withAuth(Dashboard) → AuthenticatedDashboard.
   Problems: wrapper hell (DevTools nesting), props collision, composition is
   less clear. Hooks replaced most HOC use cases, but HOCs still work well
   for cross-cutting concerns that need to intercept rendering (React.memo is a HOC).

Q5: What are React Server Components (RSC)?
A: Components that render only on the server (never in the browser). They can
   directly access databases, file systems, and sensitive APIs. Their output
   (serialized JSX) is streamed to the client.
   - Server Components: no hooks, no event handlers, async functions, zero JS sent
   - Client Components: "use client" directive, hooks work, normal React
   Used in Next.js App Router. RSC significantly reduces client JS bundle size.

REACT INTERNALS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q6: What is React Fiber?
A: Fiber is React's reimplemented reconciliation algorithm (React 16).
   It replaces the old synchronous stack reconciler with an interruptible,
   priority-based fiber (linked list) structure. Each component has a fiber
   node. Rendering can be paused, resumed, or aborted. Enables Concurrent Mode.

Q7: What is the difference between render phase and commit phase?
A: Render phase: React calls component functions, builds new VDOM, diffs it
   against previous VDOM. Pure/interruptible in Concurrent Mode. No side effects.
   Commit phase: React applies DOM mutations, runs useLayoutEffect, browser
   paints, runs useEffect. Synchronous and non-interruptible.

Q8: What is double buffering in React Fiber?
A: React maintains two fiber trees: current (what's on screen) and
   work-in-progress (being built). During rendering, React builds the WIP tree.
   On commit, it atomically swaps them by moving the finishedWork pointer.
   This ensures the displayed tree is always consistent.

Q9: What is Concurrent Mode?
A: Concurrent Mode (enabled by createRoot in React 18) allows React to:
   - Interrupt and pause a render
   - Prioritize urgent updates (user input) over non-urgent ones
   - Render multiple UI states in the background
   - Transition between states without blocking the main thread
   Previously, all renders were synchronous and couldn't be interrupted.

Q10: How does Suspense work internally?
A: When a component "suspends" it throws a Promise. React catches it,
   walks up the tree to the nearest Suspense boundary, renders the fallback,
   and attaches a .then() to the thrown Promise. When it resolves,
   React retries rendering the suspended component from scratch.

Q11: What is forwardRef and when do you need it?
A: forwardRef allows a parent to pass a ref to a DOM element inside a child
   component. By default, refs on functional components don't work (you get
   a warning). Use forwardRef + useImperativeHandle to expose a curated API.
   Required when building reusable component libraries.

Q12: What is useImperativeHandle?
A: Works with forwardRef to customize what a parent sees when using a ref
   on a child component. Instead of exposing the raw DOM node, you expose
   a specific set of methods. Useful for input focus(), scroll(), form reset().

Q13: What is the key-as-reset pattern?
A: Changing a component's key prop causes React to unmount and remount it,
   resetting all state. Useful when you want to completely reinitialize
   a component based on an external change:
   <UserForm key={selectedUserId} userId={selectedUserId} />
   When selectedUserId changes, UserForm gets a fresh instance with cleared state.

Q14: How do you implement SSR with React?
A: Server: renderToString(<App />) or renderToPipeableStream() generates HTML.
   Client: ReactDOM.hydrateRoot() attaches event listeners to existing HTML
   (hydration — fast, no DOM recreation). React 18 supports streaming SSR with
   selective hydration — Suspense boundaries stream HTML progressively.

Q15: What is hydration mismatch and how do you fix it?
A: When the server-rendered HTML differs from the first client render, React
   warns about a hydration mismatch and re-renders on the client (slow, flicker).
   Causes: accessing browser APIs (window, localStorage) during render, random
   data/dates, improperly nested HTML. Fix: use useEffect for browser APIs,
   suppress with suppressHydrationWarning (for timestamps), or use dynamic
   with ssr:false in Next.js.

DESIGN QUESTIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q16: How would you design a reusable Modal component?
A: Use React portals (ReactDOM.createPortal) to render outside the normal
   DOM hierarchy (avoids z-index/overflow issues). Accept isOpen, onClose,
   title, children, size as props. Trap focus inside (for accessibility).
   Close on Escape key (useEffect listening to keydown). Close on backdrop
   click. Use useId for aria-labelledby associations.

Q17: How would you build a drag-and-drop list?
A: Options: (1) react-dnd (complex, full control), (2) @dnd-kit/core (modern,
   accessible, minimal), (3) HTML5 Drag and Drop API with refs (low-level).
   State: array of items with unique IDs. On drag end, reorder array by
   removing from old index and inserting at new index. Key the items to
   ensure React preserves component state during reorder.
