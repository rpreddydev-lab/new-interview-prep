1. WHAT IS JAVASCRIPT?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

JavaScript (JS) is a:
  • High-level          – abstracts over hardware; no manual memory management
  • Interpreted/JIT     – compiled at runtime by the JS engine (e.g., V8)
  • Single-threaded     – one call stack, one thread of execution
  • Dynamic             – types resolved at runtime, not compile time
  • Weakly typed        – implicit type coercion allowed
  • Prototype-based OOP – inheritance via prototype chains, not classical classes
  • Multi-paradigm      – supports procedural, OOP, and functional styles
  • Event-driven        – execution driven by user/system events via event loop
  • Garbage-collected   – memory freed automatically via mark-and-sweep GC

Official spec: ECMAScript (ES) — maintained by TC39 (Technical Committee 39)
  - ES5  (2009) – strict mode, JSON, Array methods
  - ES6  (2015) – let/const, arrow functions, classes, modules, Promises
  - ES2017       – async/await
  - ES2020       – optional chaining, nullish coalescing, BigInt
  - ES2022       – at(), Object.hasOwn, top-level await
  - ES2023       – findLast, toSorted, toReversed (non-mutating array methods)

3. KEY CHARACTERISTICS (Deep Dive)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

A) SINGLE-THREADED
  - One call stack → only one piece of code runs at a time.
  - Concurrency is achieved via the EVENT LOOP (not true parallelism).
  - Web Workers allow background threads but they can't access the DOM.

B) DYNAMIC TYPING
  let x = 42;        // number
  x = "hello";       // now a string — valid in JS, not in TypeScript
  x = { key: "v" };  // now an object

C) FIRST-CLASS FUNCTIONS
  - Functions are values: they can be stored in variables, passed as arguments,
    returned from other functions.

  const greet = function(name) { return `Hi ${name}`; };
  const result = [1,2,3].map(n => n * 2); // function passed as argument

D) GARBAGE COLLECTION
  - Mark-and-sweep algorithm: GC traverses from root objects and marks all
    reachable objects. Unreachable ones are collected.
  - Closures can inadvertently prevent GC (memory leaks if not careful).

4. JS vs OTHER LANGUAGES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  JS vs Java:
  - JS is dynamically typed; Java is statically typed
  - JS has prototype-based OOP; Java has class-based OOP
  - JS runs in browser/Node; Java runs on JVM

  JS vs Python:
  - Both dynamically typed
  - JS is event-driven & async by nature; Python uses threading/asyncio
  - JS uses {} for blocks; Python uses indentation

  JS vs TypeScript:
  - TypeScript is a superset of JS with static typing
  - TS compiles to JS; browser can't execute TS directly

5. EXECUTION CONTEXT
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Every time JavaScript runs code, it creates an Execution Context.
There are 3 types:

  1. Global Execution Context (GEC)
     - Created when the script first runs
     - In browser: `this` = window; in Node: `this` = {}
     - Sets up global scope

  2. Function Execution Context (FEC)
     - Created for each function call
     - Has its own `this`, arguments, local variables

  3. Eval Execution Context
     - Created by eval() – avoid in production

Each execution context has two phases:
  Phase 1 – Creation Phase:
    - Variable Object (VO) created
    - Scope chain established
    - `this` value set
    - var declarations hoisted (set to undefined)
    - function declarations fully hoisted

  Phase 2 – Execution Phase:
    - Code executes line by line
    - Variables are assigned values

6. CALL STACK
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  - LIFO (Last-In-First-Out) data structure
  - Tracks function invocations
  - When a function is called, it's pushed; when it returns, it's popped

  function a() { b(); }
  function b() { c(); }
  function c() { console.log("hi"); }

  a();
  // Stack: GEC → a() → b() → c()
  // After c() returns: GEC → a() → b()
  // After b() returns: GEC → a()
  // After a() returns: GEC

  Stack Overflow: infinite recursion exceeds stack limit
  RangeError: Maximum call stack size exceeded

7. COMMON INTERVIEW QUESTIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: Is JavaScript compiled or interpreted?
A: Both. JS engines use JIT (Just-In-Time) compilation. Code is first parsed
   into an AST, then interpreted (via bytecode), and hot code paths are
   compiled to optimized machine code at runtime.

Q: What makes JavaScript asynchronous if it's single-threaded?
A: The EVENT LOOP. Browser/Node Web APIs handle async tasks (timers, I/O,
   network) outside the call stack. When done, callbacks are queued and
   processed by the event loop when the stack is empty.

Q: What is the difference between null and undefined?
A: undefined – variable declared but not assigned any value (JS default)
   null – intentionally assigned "no value" (explicit empty value)

   typeof undefined  // "undefined"
   typeof null       // "object"  ← famous JS bug, preserved for compat

Q: Is JS pass-by-value or pass-by-reference?
A: Primitives are passed by value (copy).
   Objects/arrays are passed by reference (reference copy — changes to the
   object inside a function affect the original, but reassigning the
   parameter variable doesn't).

   function mutate(obj) { obj.x = 99; }     // modifies original
   function reassign(obj) { obj = {}; }     // doesn't affect original

Q: What is NaN and how do you check for it?
A: NaN (Not-a-Number) is the result of invalid numeric operations.
   typeof NaN === "number" (!) — the only value not equal to itself.
   Check: Number.isNaN(value)   // preferred (strict)
          isNaN(value)          // coerces to number first (less reliable)

   Number.isNaN(NaN)       // true
   Number.isNaN("hello")   // false  ← correct
   isNaN("hello")          // true   ← because isNaN("hello") coerces first
