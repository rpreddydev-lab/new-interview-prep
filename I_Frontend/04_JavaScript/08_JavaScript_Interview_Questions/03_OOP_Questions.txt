SECTION 1: PROTOTYPES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q1: How does prototypal inheritance work in JavaScript?
A:
  Every object has an internal [[Prototype]] link. When you access a property
  not on the object, JS walks up the chain to [[Prototype]], then its prototype,
  until reaching null. Methods on a prototype are shared across all instances.

Q2: What does the new keyword do?
A:
  Four steps:
  1. Creates a new empty object
  2. Sets its [[Prototype]] to Constructor.prototype
  3. Executes the constructor with this = new object
  4. Returns the new object (unless constructor returns a non-null object)

Q3: What is the difference between __proto__ and prototype?
A:
  prototype — property on FUNCTION objects; becomes the [[Prototype]] of
              objects created by that constructor
  __proto__ — the actual [[Prototype]] link on INSTANCES (non-standard, use
              Object.getPrototypeOf() instead)

Q4: What does instanceof check?
A:
  Whether Constructor.prototype exists anywhere in the object's prototype chain.
  It doesn't check the constructor function itself — it checks the chain.
  This can be fooled if you change Constructor.prototype after instantiation.

SECTION 2: CLASSES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q5: Are JavaScript classes "real" classes?
A:
  No. They are syntactic sugar over prototype-based inheritance.
  typeof SomeClass === "function". The object model is still prototypal —
  classes provide a cleaner syntax but don't change the underlying mechanism.

Q6: What does super() do?
A:
  In a derived class constructor, super() calls the parent class constructor.
  It MUST be called before using `this` in the derived constructor.
  super.method() calls a method from the parent prototype.

Q7: What are private class fields?
A:
  Fields/methods prefixed with # (e.g. #balance) are truly private.
  They cannot be accessed outside the class body — not even by subclasses.
  Attempting external access is a SyntaxError. Unlike _name convention,
  this is enforced by the language.

Q8: Are class methods enumerable?
A:
  No. Class body methods are defined as non-enumerable on the prototype.
  They won't show up in for...in loops or Object.keys() on the prototype.

Q9: Why must you call super() before `this` in a derived class?
A:
  In JS, the derived class does not create the object — the base class
  constructor does (via new.target). Until super() is called, `this` is
  uninitialized. Accessing `this` before super() throws a ReferenceError.

SECTION 3: COMPOSITION AND PATTERNS

Q10: What is "composition over inheritance"?
A:
  Instead of deep class hierarchies, build objects from small reusable
  behavior units (functions/mixins). Avoids the fragile base class problem,
  tight coupling, and JS's single-inheritance limitation.

Q11: What is a mixin?
A:
  An object/function that provides reusable methods copied into a class
  without using extends. Applied with Object.assign(Target.prototype, mixin).

Q12: What is Object.create() used for?
A:
  Creates an object with a specific prototype. Object.create(proto) creates
  an object whose [[Prototype]] is proto — the cleanest way to set up
  prototypal inheritance. Object.create(null) creates a prototype-less
  dictionary object.

SECTION 4: PROXY AND REFLECT

Q13: What is a Proxy and when would you use it?
A:
  A Proxy wraps an object and intercepts fundamental operations via traps.
  Use cases: validation (intercept set), logging (intercept get/set),
  default values, read-only objects, API mocking, reactive programming
  (Vue 3 reactivity system uses Proxy).

Q14: Why use Reflect inside Proxy traps?
A:
  Reflect methods mirror trap semantics correctly — they pass the receiver
  for correct `this` binding, return the right types (set returns boolean),
  and preserve language invariants. Always prefer Reflect.get/set/etc.
  over direct target property access in traps.

SECTION 5: GETTERS AND SETTERS

Q15: What are getters and setters?
A:
  Accessor properties that execute functions when a property is read (getter)
  or written (setter). They look like regular property accesses to callers
  but allow computed values, validation, and encapsulation.

Q16: How do you prevent infinite recursion in a setter?
A:
  Use a private backing field (#value) or a prefixed field (_value) for
  actual storage. The setter should write to the backing field, not to
  the same property name (which would recursively call the setter again).
