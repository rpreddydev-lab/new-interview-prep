1. WHAT ARE DISCRIMINATED UNIONS?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  A discriminated union (also called tagged union or algebraic data type) is a
  union of types where EACH member has a common literal property (the discriminant)
  that uniquely identifies it. TypeScript uses this property to narrow the type.

  Three requirements:
    1. A union of related types.
    2. Each member has a common "tag" property with a UNIQUE LITERAL type value.
    3. You check the tag to know which member you're dealing with.

  type Shape =
    | { kind: "circle";   radius: number }
    | { kind: "square";   side: number }
    | { kind: "rect";     width: number; height: number };

  function area(shape: Shape): number {
    switch (shape.kind) {
      case "circle": return Math.PI * shape.radius ** 2;
      case "square": return shape.side ** 2;
      case "rect":   return shape.width * shape.height;
    }
  }

2. THE DISCRIMINANT PROPERTY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  The discriminant must be a LITERAL type — not just `string` or `number`:

  // ❌ Bad discriminant — string is too wide:
  type Bad = { status: string; code: number } | { status: string; msg: string };
  // TypeScript can't distinguish them by status alone

  // ✅ Good discriminant — literal string types:
  type Good =
    | { status: "success"; code: number }
    | { status: "error";   msg: string };

  // ✅ Works with other literal types too:
  type NumTag =
    | { type: 1; data: string }
    | { type: 2; data: number };

  type BoolTag =
    | { loading: true }
    | { loading: false; data: string; error: null }
    | { loading: false; data: null;   error: Error };

3. EXHAUSTIVENESS CHECKING WITH `never`
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  After handling all known cases in a switch/if, assign the variable to `never`
  in the default branch. If a new variant is added to the union, TypeScript will
  produce a compile-time error for the unhandled case.

  type Shape =
    | { kind: "circle"; radius: number }
    | { kind: "square"; side: number };

  function getArea(shape: Shape): number {
    switch (shape.kind) {
      case "circle": return Math.PI * shape.radius ** 2;
      case "square": return shape.side ** 2;
      default:
        // If all cases handled, `shape` is `never` here — safe assignment
        const _never: never = shape;
        throw new Error(`Unhandled shape: ${JSON.stringify(_never)}`);
    }
  }

  // Now add a new variant:
  type Shape =
    | { kind: "circle"; radius: number }
    | { kind: "square"; side: number }
    | { kind: "triangle"; base: number; height: number }; // NEW

  // TypeScript error on `const _never: never = shape`:
  // Type '{ kind: "triangle"; ... }' is not assignable to type 'never' ✅

  // Reusable exhaustive check helper:
  function assertNever(x: never): never {
    throw new Error(`Unexpected value: ${JSON.stringify(x)}`);
  }

  function getArea(shape: Shape): number {
    switch (shape.kind) {
      case "circle":   return Math.PI * shape.radius ** 2;
      case "square":   return shape.side ** 2;
      default:         return assertNever(shape); // compile error if incomplete
    }
  }

4. REAL-WORLD PATTERNS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  a) Result / Either type (success or failure):
     ────────────────────────────────────────────
     type Result<T, E = Error> =
       | { success: true;  value: T }
       | { success: false; error: E };

     function divide(a: number, b: number): Result<number, string> {
       if (b === 0) return { success: false, error: "Division by zero" };
       return { success: true, value: a / b };
     }

     const result = divide(10, 2);
     if (result.success) {
       console.log(result.value);  // ✅ number
     } else {
       console.log(result.error);  // ✅ string
     }

  b) Loading states (common in React):
     ─────────────────────────────────
     type LoadingState<T> =
       | { status: "idle" }
       | { status: "loading" }
       | { status: "success"; data: T }
       | { status: "error";   error: Error };

     function render<T>(state: LoadingState<T>) {
       switch (state.status) {
         case "idle":    return "Not started";
         case "loading": return "Loading...";
         case "success": return JSON.stringify(state.data); // ✅ data available
         case "error":   return state.error.message;        // ✅ error available
       }
     }

  c) Redux-style actions:
     ────────────────────
     type Action =
       | { type: "INCREMENT"; amount: number }
       | { type: "DECREMENT"; amount: number }
       | { type: "RESET" }
       | { type: "SET";       value: number };

     function reducer(state: number, action: Action): number {
       switch (action.type) {
         case "INCREMENT": return state + action.amount; // ✅ amount available
         case "DECREMENT": return state - action.amount;
         case "RESET":     return 0;                     // ✅ no extra props
         case "SET":       return action.value;          // ✅ value available
         default:          return assertNever(action);
       }
     }

  d) Network request / Response modeling:
     ──────────────────────────────────────
     type HttpResponse<T> =
       | { status: 200; body: T }
       | { status: 201; body: T; location: string }
       | { status: 400; errors: string[] }
       | { status: 404 }
       | { status: 500; message: string };

     function handleResponse<T>(res: HttpResponse<T>): T | null {
       switch (res.status) {
         case 200: return res.body;
         case 201: return res.body;
         case 400: console.error(res.errors); return null;
         case 404: return null;
         case 500: throw new Error(res.message);
         default:  return assertNever(res);
       }
     }

5. DISCRIMINATED UNIONS vs. OPTIONAL PROPERTIES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  ❌ Anti-pattern — using optional properties leads to unclear combinations:
  type Response = {
    loading?: boolean;
    data?: User;
    error?: Error;
  };
  // What combination is valid? Is loading=true + data=User valid? Unknown!

  ✅ Discriminated union — mutually exclusive, clear:
  type Response =
    | { status: "loading" }
    | { status: "success"; data: User }
    | { status: "error";   error: Error };
  // Each state is completely defined and mutually exclusive.

  Benefits:
  - Self-documenting — you can see every possible state
  - No impossible states (can't have both data and error at once)
  - Exhaustiveness checking prevents handling bugs
  - Each case has exactly the right properties available

6. HELPER UTILITIES FOR DISCRIMINATED UNIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  // Extract a specific variant by discriminant value:
  type Extract<T, U> = T extends U ? T : never;

  type Circle = Extract<Shape, { kind: "circle" }>;
  // { kind: "circle"; radius: number }

  // Get all discriminant values:
  type ShapeKind = Shape["kind"]; // "circle" | "square" | "rect"

  // Create a discriminated union from a record of variants:
  type FromRecord<T extends Record<string, object>> = {
    [K in keyof T]: { type: K } & T[K];
  }[keyof T];

  type Actions = FromRecord<{
    add:    { item: string };
    remove: { id: number };
    clear:  {};
  }>;
  // { type: "add"; item: string } | { type: "remove"; id: number } | { type: "clear" }

7. NARROWING WITHOUT switch
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Both switch and if-else work for discriminated union narrowing:

  // if-else:
  function handle(shape: Shape) {
    if (shape.kind === "circle") {
      return shape.radius; // ✅ narrowed
    } else if (shape.kind === "square") {
      return shape.side;   // ✅ narrowed
    } else {
      return shape.width;  // ✅ only rect left
    }
  }

  // Callbacks / functional style:
  const handlers: { [K in Shape["kind"]]: (s: Extract<Shape, { kind: K }>) => string } = {
    circle:   s => `circle r=${s.radius}`,
    square:   s => `square s=${s.side}`,
    rect:     s => `rect ${s.width}x${s.height}`,
  };

  function describe(shape: Shape): string {
    return handlers[shape.kind](shape as any);
  }

8. INTERVIEW QUESTIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q1: What is a discriminated union in TypeScript?
    A union of types where each member has a common property (the discriminant)
    with a unique LITERAL type value. TypeScript uses this tag to narrow the type
    inside conditionals. Also called tagged unions or algebraic data types.

Q2: What are the three requirements for a discriminated union?
    1. It must be a union type (A | B | C).
    2. Each member must have a common "tag" property.
    3. That tag property must hold a unique LITERAL type per member
       (not just `string` — each must be a specific string literal).

Q3: How do you perform exhaustiveness checking with discriminated unions?
    In the default branch of a switch, assign the discriminated union to a
    `never` variable or pass it to an `assertNever` function. If any variant
    is not handled, TypeScript will report a type error because the value
    can't be assigned to `never`.

Q4: What is the `assertNever` pattern?
    function assertNever(x: never): never { throw new Error(JSON.stringify(x)); }
    When passed a value that should be `never` (all cases handled), TypeScript
    confirms this. If a new union member is added but not handled, the compile-
    time error flags the missing case.

Q5: Why are discriminated unions better than optional properties for state?
    Optional properties can represent impossible states (e.g., both `data` and
    `error` defined at the same time). Discriminated unions make each state
    explicit, mutually exclusive, and type-safe. Each variant carries exactly
    the properties valid for that state.

Q6: How do you model a Result type with discriminated unions?
    type Result<T, E = Error> =
      | { success: true;  value: T }
      | { success: false; error: E };
    Checking `if (result.success)` narrows to the success variant and makes
    `result.value` available.

Q7: How is Extract<T, U> useful with discriminated unions?
    It filters a union to members that match a specific pattern:
    type Circle = Extract<Shape, { kind: "circle" }>
    This gives you the exact Circle variant type without redefining it.

Q8: Can discriminated unions use numeric literals as the discriminant?
    Yes. type Variant = { type: 1; data: string } | { type: 2; count: number }
    Any literal type (string, number, boolean, symbol) can be a discriminant.

Q9: How do discriminated unions relate to Redux reducers?
    Redux actions are naturally modeled as discriminated unions, with `type` as
    the discriminant. The reducer's switch on `action.type` narrows to each
    specific action, giving type-safe access to action-specific payload.

Q10: What pattern gets all discriminant values from a discriminated union?
     Use indexed access: type AllKinds = Shape["kind"]
     This extracts the union of all literal values of the `kind` property,
     giving: "circle" | "square" | "rect".
