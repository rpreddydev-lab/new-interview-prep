1. FOUNDATIONAL HTML QUESTIONS
================================================================================

Q1: What does HTML stand for and what is its purpose?
A: HTML stands for HyperText Markup Language. It is the standard markup language
   used to create the structure and content of web pages. "HyperText" refers to
   text that links to other documents (hyperlinks); "Markup Language" means you
   annotate content with tags that describe meaning and structure. HTML defines
   the skeleton of a web page — the browser then renders it visually, with
   CSS handling presentation and JavaScript handling behavior.

Q2: What is the difference between HTML and HTML5?
A: HTML5 (released 2014) is the fifth major revision. Key additions over
   earlier HTML: new semantic elements (<article>, <section>, <nav>, <header>,
   <footer>, <aside>, <main>); native multimedia (<video>, <audio>, <canvas>,
   <svg>); form enhancements (new input types: email, url, date, range;
   validation attributes: required, pattern, min, max); APIs (localStorage,
   sessionStorage, Geolocation, Web Workers, WebSocket, History API);
   removal of presentational elements (<font>, <center>, <big>); and
   MathML/SVG inline support.

Q3: What is the DOCTYPE declaration and why is it needed?
A: <!DOCTYPE html> is the first line of every HTML5 document. It tells the
   browser to use standards mode (as opposed to quirks mode — where browsers
   emulate old, inconsistent rendering behavior for legacy compatibility).
   Without DOCTYPE, browsers may render pages in quirks mode, causing layout
   and JavaScript inconsistencies across browsers. The HTML5 DOCTYPE is simple
   — older doctypes referenced DTD schema files. <!DOCTYPE html> is
   case-insensitive and must be the very first line before even whitespace.

Q4: What is the difference between an element and a tag?
A: A tag is the markup notation: <p> is an opening tag, </p> is a closing tag.
   An element is the complete structure: the opening tag + content + closing tag.
   <p>Hello world</p> is a paragraph element. Some elements are void elements
   (self-closing, no content): <br>, <img>, <input>, <hr>, <meta>, <link>.
   In HTML5, void elements don't require the self-closing slash (though it's
   valid): <br> or <br />.

Q5: What are block-level and inline elements? Give examples.
A: Block-level elements start on a new line, take up full width, and can
   contain block or inline elements. Examples: <div>, <p>, <h1>-<h6>, <ul>,
   <ol>, <li>, <table>, <form>, <header>, <main>, <section>, <article>,
   <blockquote>, <pre>. Inline elements flow within text content, take only
   as much width as needed, and generally shouldn't contain block elements.
   Examples: <span>, <a>, <strong>, <em>, <img>, <button>, <input>, <label>,
   <abbr>. Note: in HTML5, the terminology shifted to "flow content" vs
   "phrasing content" — more nuanced categories, but block/inline remains
   useful conceptual shorthand.

2. DOCUMENT STRUCTURE QUESTIONS
================================================================================

Q6: Describe the basic structure of an HTML document.
A: A valid HTML5 document has: (1) <!DOCTYPE html> — must be first;
   (2) <html lang="en"> — root element, lang attribute sets page language;
   (3) <head> — machine-readable metadata: <meta charset="UTF-8">,
   <meta name="viewport" content="width=device-width, initial-scale=1.0">,
   <title>, CSS links, fonts; (4) <body> — all visible page content.
   The head is not rendered visually; it configures the document for
   browsers, search engines, and social media scrapers.

Q7: What is the purpose of the <meta charset="UTF-8"> declaration?
A: It declares the character encoding of the document. UTF-8 is a Unicode
   encoding that supports virtually every character from every language
   (over 140,000 characters). Without declaring the charset, browsers may
   misinterpret character bytes, causing garbled text (mojibake) for
   non-ASCII characters like accented letters, Chinese characters, emojis.
   It must appear within the first 1024 bytes of the document (as early as
   possible in <head>) so the browser knows how to decode the rest of the file.

Q8: What is the viewport meta tag and why is it essential?
A: <meta name="viewport" content="width=device-width, initial-scale=1.0">
   tells mobile browsers not to simulate a desktop viewport and then zoom out.
   Without it, mobile browsers render the page at ~980px width and scale it
   down — text becomes tiny and unusable. width=device-width sets the viewport
   to the device's physical width. initial-scale=1.0 prevents initial zoom.
   This tag is essential for responsive design — CSS media queries won't work
   correctly without it because the viewport width would be 980px, not the
   actual device width.

Q9: What is the difference between <head> and <body>?
A: <head> contains metadata about the document that is not displayed directly:
   <title>, charset, viewport, CSS links, script references, meta tags for
   SEO and social media, favicon links, preload/prefetch hints. <body> contains
   all visible content: text, images, links, forms, scripts that modify the DOM.
   Some elements can appear in both (like <script> and <template>). The
   distinction matters because rendering engines process head metadata before
   building the visual layout.

Q10: What is the purpose of the <title> element?
A: <title> sets the document title displayed in: browser tab, window title bar,
   bookmarks, browser history, search engine results pages (as the blue link
   title), and social media link previews. It must be unique per page
   (WCAG 2.4.2), descriptive of the page content, and ideally under 60
   characters to avoid truncation in SERPs. Best pattern: "Page Name | Site Name"
   or "Site Name - Page Description". It is the strongest on-page SEO signal
   after content quality.

3. ELEMENTS AND ATTRIBUTES QUESTIONS
================================================================================

Q11: What is the difference between id and class attributes?
A: id must be unique within a page — only one element per page should have
   a given id value. Used for: URL fragment identifiers (#section), JavaScript
   getElementById(), CSS single-element targeting, label/input association
   (for attribute), aria-labelledby references. class can be applied to multiple
   elements and an element can have multiple classes (space-separated).
   Used for: CSS styling groups, JavaScript querySelectorAll(), component
   variants. In CSS: #id has higher specificity (0,1,0,0) than .class (0,0,1,0).

Q12: What is the difference between href and src attributes?
A: href (Hypertext Reference) specifies the destination URL of a link or
   resource relationship: used on <a> (navigation), <link> (CSS files, icons),
   <area> (image maps), <base>. src (Source) specifies the URL of a resource
   to be embedded: used on <img>, <script>, <audio>, <video>, <iframe>, <source>,
   <track>, <input type="image">. href creates a reference/relationship;
   the user navigates to it. src embeds content; it's fetched and rendered
   inline automatically.

Q13: What are data attributes and how are you used?
A: data-* attributes store custom data on HTML elements without relying on
   non-standard attributes or class hacks. The name must be lowercase, start
   with data-, and contain no uppercase letters. Example:
   <button data-user-id="42" data-role="admin">Edit</button>.
   In JavaScript: element.dataset.userId ("42"), element.dataset.role ("admin")
   — camelCase in JS, kebab-case in HTML. Use cases: storing IDs for event
   delegation, feature flags, configuration for vanilla JS components, targeting
   in tests (data-testid). They are accessible via CSS with attribute selectors:
   [data-role="admin"] { }. Don't use for security-sensitive data — they're
   visible in DOM.

Q14: What is the difference between <strong> and <b>? Between <em> and <i>?
A: <strong> indicates strong importance — semantic meaning that this text is
   critical. Screen readers may change tone. <b> is for stylistically bold text
   without implying importance (keywords in text, product names). <em> indicates
   emphasis that changes sentence meaning — screen readers may stress it.
   <i> is for idiomatic text, technical terms, foreign phrases, thoughts —
   visually italic, no semantic emphasis. In HTML5, all four are valid with
   these distinct semantic purposes. Choosing correctly communicates meaning
   to assistive technologies and search engines, not just visual styling.

Q15: What is the difference between absolute and relative URLs?
A: Absolute URLs contain the full path including protocol and domain:
   https://example.com/page/image.jpg. They work from anywhere. Relative
   URLs are relative to the current document's location. Types:
   relative path: images/photo.jpg (from current directory),
   root-relative: /images/photo.jpg (from site root),
   protocol-relative: //example.com/image.jpg (uses page's protocol).
   Use relative URLs within a site for portability (works on dev and prod);
   use absolute URLs for external resources, canonical meta tags, og:url,
   JSON-LD structured data, and sitemap entries.

4. HTML5 FEATURES QUESTIONS
================================================================================

Q16: What are semantic HTML elements and why do they matter?
A: Semantic elements have meaningful names that describe their content's role:
   <header>, <nav>, <main>, <article>, <section>, <aside>, <footer>,
   <figure>, <figcaption>, <time>, <mark>, <summary>, <details>.
   They matter because: (1) Accessibility — screen readers use landmarks to
   help users navigate; headings provide structure; (2) SEO — search engines
   weight semantic structure; <article> signals main content; (3) Maintainability
   — code is self-documenting; (4) Browser features — <details> is native
   accordion, <dialog> is native modal; (5) They define the accessibility
   tree. Non-semantic <div> and <span> have no inherent meaning.

Q17: What is the difference between <article> and <section>?
A: <article> is a self-contained piece of content that makes sense independently
   and could be syndicated: blog post, news article, comment, product card,
   forum post. Ask: "Would this still make sense extracted from context and
   republished elsewhere?" If yes → <article>. <section> groups thematically
   related content within a page but is not self-contained: a chapter in a
   guide, tabs panel, a group of related items. <section> should generally have
   a heading. They can be nested: an <article> can contain <section>s, and
   a <section> can contain <article>s (e.g., blog roll section with articles).

Q18: What are Web Storage APIs (localStorage and sessionStorage)?
A: Both are key-value stores in the browser, storing strings only.
   localStorage: persists until explicitly cleared — survives closing browser;
   shared across all tabs for same origin; 5-10MB limit. sessionStorage:
   persists only for the tab's session — cleared when tab closes; isolated
   per tab; 5MB limit. Usage: localStorage.setItem('key', JSON.stringify(data));
   JSON.parse(localStorage.getItem('key')). Use cases: user preferences,
   shopping cart draft, auth tokens (use httpOnly cookies for security-sensitive
   tokens instead). Neither is secure — visible in DevTools; don't store
   passwords or sensitive data.

Q19: What is the difference between <canvas> and <svg>?
A: Canvas is a raster-based immediate mode API — you draw pixels on a 2D
   context; there's no memory of what was drawn once rendered (no scene graph).
   SVG is a vector-based retained mode markup language — elements remain as
   DOM nodes, can be styled with CSS, accessed by JavaScript, and scale
   infinitely without quality loss. Canvas: better for game rendering, complex
   animations, image processing, per-pixel manipulation, WebGL. SVG: better
   for logos, icons, illustrations, data visualization (D3.js), interactive
   diagrams. Accessibility: SVG elements can have aria-label, <title>, <desc>;
   Canvas requires accessible fallback content.

Q20: What are HTML templates (<template> element)?
A: The <template> element holds inert HTML that is parsed but NOT rendered —
   it doesn't display, scripts don't run, images don't download. It's a
   client-side content template. Access the cloneable content via
   template.content (a DocumentFragment). Usage pattern:
   const clone = document.importNode(template.content, true);
   document.body.appendChild(clone);
   Used for: Web Components (Shadow DOM stamping), list item templates
   in JavaScript, reusable UI fragments. Unlike script-tag templates, it's
   proper DOM — parsed and validated by the browser, free of XSS risks
   from innerHTML.

5. MEDIA AND EMBEDDING QUESTIONS
================================================================================

Q21: What attributes are important for the <img> element?
A: src — image URL (required); alt — text alternative (required for
   accessibility — empty for decorative, descriptive for informative);
   width and height (in CSS pixels) — prevent layout shift (CLS); loading
   — "lazy" for below-fold images, "eager" for above-fold; decoding — "async"
   for non-critical images; srcset — comma-separated image candidates for
   responsive images: <img srcset="img-480.jpg 480w, img-800.jpg 800w"
   sizes="(max-width: 600px) 480px, 800px" src="img-800.jpg" alt="...">
   fetchpriority — "high" for LCP image, "low" for low-priority.

Q22: How do you embed video in HTML5? What attributes matter?
A: Use <video controls src="..."></video> for simple cases, or <source>
   elements for multiple formats:
   <video controls width="640" height="360" poster="thumbnail.jpg">
     <source src="video.mp4" type="video/mp4">
     <source src="video.webm" type="video/webm">
     <track kind="captions" src="captions.vtt" srclang="en" label="English" default>
     <p>Your browser doesn't support HTML5 video. <a href="video.mp4">Download</a></p>
   </video>
   Key attributes: controls (show native controls), autoplay (avoid or mute),
   muted (required for autoplay), loop, poster (thumbnail), preload (none/
   metadata/auto). <track> provides captions/subtitles — required for WCAG.

Q23: What is the difference between <iframe> and <embed>/<object>?
A: <iframe> embeds an external HTML document — a full browsing context.
   Modern use: YouTube embeds, Google Maps, payment forms (sandboxed third-party
   content). Key attributes: src, title (required for accessibility), sandbox
   (restricts permissions), allow (feature policy), loading="lazy". <embed> and
   <object> are older elements for embedding plugins (Flash, PDF). Modern
   recommendation: use <iframe> for HTML documents, native <video>/<audio> for
   media. <object> can still be used for embedding PDFs in supporting browsers.
   PDFs: <iframe src="file.pdf" title="Annual Report PDF">

Q24: What is the picture element used for?
A: <picture> provides art direction — different image versions for different
   viewport conditions, not just different resolutions like srcset:
   <picture>
     <source media="(min-width: 800px)" srcset="hero-wide.jpg">
     <source media="(max-width: 799px)" srcset="hero-narrow.jpg">
     <img src="hero-fallback.jpg" alt="Hero image">
   </picture>
   The browser picks the first matching <source>; <img> is the fallback.
   Also used for modern format support with type:
   <source srcset="image.avif" type="image/avif">
   <source srcset="image.webp" type="image/webp">
   <img src="image.jpg" alt="...">
   The browser picks the first format it supports.

Q25: What is the defer vs async attribute on <script>?
A: Both attributes apply only to external scripts and control download/execution
   relative to HTML parsing:
   
   No attribute (default):
     HTML parsing PAUSES → script downloads AND executes → parsing resumes
   
   defer:
     Script downloads in parallel → executes AFTER HTML parsing completes
     → executes in document order → best for scripts that depend on DOM
   
   async:
     Script downloads in parallel → executes AS SOON AS it's downloaded
     (can interrupt parsing) → execution order NOT guaranteed → best for
     independent scripts (analytics, ads)
   
   Inline scripts: defer and async are ignored.
   Modern recommendation: Place scripts in <head> with defer instead of
   at end of <body> (same effect but semantically cleaner and enables
   early download). Use async for tracking/analytics only.
