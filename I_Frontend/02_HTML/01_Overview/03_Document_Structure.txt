1. FULL DOCUMENT STRUCTURE TEMPLATE
================================================================================

<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <meta name="description" content="Page description for SEO (150-160 chars)">
    <meta name="author" content="Author Name">
    <title>Page Title — Site Name</title>

    <!-- Favicon -->
    <link rel="icon" href="/favicon.ico" type="image/x-icon">
    <link rel="apple-touch-icon" href="/apple-touch-icon.png">

    <!-- Preconnect for performance -->
    <link rel="preconnect" href="https://fonts.googleapis.com">

    <!-- Stylesheets (render-blocking; in head for correct initial paint) -->
    <link rel="stylesheet" href="/css/main.css">

    <!-- Structured data -->
    <script type="application/ld+json">
    { "@context": "https://schema.org", "@type": "WebPage" }
    </script>
</head>
<body>
    <header>
        <nav aria-label="Main navigation">...</nav>
    </header>
    <main id="main-content">
        <article>...</article>
        <aside>...</aside>
    </main>
    <footer>...</footer>

    <!-- Scripts at bottom (or use defer in head) -->
    <script src="/js/main.js" defer></script>
</body>
</html>

2. DOCTYPE DECLARATION
================================================================================

  <!DOCTYPE html>

Rules:
- Must be the VERY FIRST line (before <html>); no whitespace before it
- Case-insensitive
- Not an HTML element — it's a "processing instruction" / "prolog"
- Does NOT have a closing tag
- Only ONE doctype per document

Why it matters:
- Without DOCTYPE → browser enters "quirks mode"
  - IE-era box model (width includes padding and border — now standard in CSS3)
  - Different CSS calculation rules per browser
  - Inconsistent layout behavior

- With <!DOCTYPE html> → browser enters "standards mode" (also "no-quirks mode")
  - Consistent CSS box model behavior
  - Predictable rendering

Browser Rendering Modes:
  1. Quirks mode     — emulates old IE5/Netscape behavior (no DOCTYPE)
  2. Almost standards mode — minor differences (table cell height)
  3. Standards mode  — full standards compliance (<!DOCTYPE html>)

3. THE <html> ELEMENT
================================================================================

<html lang="en">

Attributes:
  lang      — language of the document content (BCP 47 tag)
              Critical for screen readers, spell checkers, translation tools
              Examples: "en", "en-US", "fr", "es", "zh-CN", "ar", "ja"

  dir       — text direction: "ltr" (default) or "rtl" (Arabic, Hebrew)
              Can be overridden per element

  xmlns     — XML namespace; required for XHTML (not needed for HTML5)

Example with RTL:
  <html lang="ar" dir="rtl">

Why lang matters:
- Screen readers use lang to select the correct TTS engine/pronunciation
- CSS :lang() pseudo-class
- Browser UI translation prompts
- SEO (Google uses lang for regional search targeting)

4. THE <head> ELEMENT & ITS CHILDREN
================================================================================

The <head> contains METADATA — information ABOUT the document, not displayed
content.

REQUIRED in every document:
  <meta charset="UTF-8">      — MUST be first in <head>, within first 1024 bytes
  <title>Page Title</title>   — Shown in browser tab; used by search engines

ESSENTIAL for responsive design:
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  Options: minimum-scale, maximum-scale, user-scalable=no (avoid: bad UX)

Commonly used <meta> tags:
  <meta name="description"   content="...">   SEO snippet (150-160 chars)
  <meta name="keywords"      content="...">   Largely ignored by Google now
  <meta name="author"        content="...">   Document author
  <meta name="robots"        content="index, follow">  Crawling hints
  <meta name="theme-color"   content="#ffffff"> Mobile browser chrome color
  <meta http-equiv="X-UA-Compatible" content="IE=edge"> IE rendering mode

Open Graph (for social sharing):
  <meta property="og:title"       content="Article Title">
  <meta property="og:description" content="Article description">
  <meta property="og:image"       content="https://example.com/image.jpg">
  <meta property="og:url"         content="https://example.com/article">
  <meta property="og:type"        content="article">

Twitter Cards:
  <meta name="twitter:card"    content="summary_large_image">
  <meta name="twitter:title"   content="Article Title">
  <meta name="twitter:image"   content="https://example.com/image.jpg">

<link> elements:
  rel="stylesheet"    — CSS file (render-blocking; load in head)
  rel="icon"          — Favicon
  rel="apple-touch-icon" — iOS home screen icon
  rel="canonical"     — Canonical URL (prevent duplicate content)
  rel="alternate"     — Alternate version (RSS feed, language)
  rel="preload"       — High-priority resource hint
  rel="prefetch"      — Low-priority future navigation hint
  rel="preconnect"    — Open TCP connection early to external origin
  rel="dns-prefetch"  — Resolve DNS early for external origin
  rel="manifest"      — PWA web app manifest

Resource Hints (Performance):
  <link rel="preload" href="hero.jpg" as="image">
  <link rel="preload" href="font.woff2" as="font" crossorigin>
  <link rel="prefetch" href="/next-page.html">
  <link rel="preconnect" href="https://cdn.example.com">
  <link rel="dns-prefetch" href="https://cdn.example.com">

<base> element:
  <base href="https://example.com/" target="_blank">
  - Sets default URL for relative links and forms
  - Sets default target for links
  - Maximum ONE per document; must be in <head>

<noscript>:
  Can appear in <head> or <body>. Content rendered when JavaScript is
  disabled. In <head>, can only contain <link>, <style>, <meta>.
  <noscript>
    <meta http-equiv="refresh" content="0; url=/no-js-version">
  </noscript>

================================================================================
5. THE <body> ELEMENT & PAGE LAYOUT
================================================================================

<body> contains all DISPLAYED content. There is exactly ONE <body> per document.

Body attributes (deprecated; use CSS instead):
  bgcolor, text, link, vlink, alink, background, marginwidth, marginheight

ONLOAD vs DOMContentLoaded:
  window.onload          = fires after ALL resources loaded (images, CSS)
  document.addEventListener('DOMContentLoaded', ...) = fires after HTML parsed

Script loading in body:
  <!-- Traditional: at end of body (DOM is ready) -->
  <script src="app.js"></script>

  <!-- Modern: in head with defer (equivalent to end-of-body; document order) -->
  <script src="app.js" defer></script>

  <!-- Async: in head, but runs ASAP (not order-guaranteed) -->
  <script src="analytics.js" async></script>

6. SEMANTIC PAGE LAYOUT WITH HTML5
================================================================================

COMPLETE PAGE LAYOUT EXAMPLE:

<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <title>Blog - My Site</title>
</head>
<body>

  <!-- Site-wide header -->
  <header>
    <a href="/" aria-label="Home">
      <img src="logo.svg" alt="My Site">
    </a>
    <nav aria-label="Main">
      <ul>
        <li><a href="/blog">Blog</a></li>
        <li><a href="/about">About</a></li>
      </ul>
    </nav>
  </header>

  <!-- Main content landmark (unique per page) -->
  <main id="main-content">

    <!-- Breadcrumb navigation -->
    <nav aria-label="Breadcrumb">
      <ol>
        <li><a href="/">Home</a></li>
        <li><a href="/blog">Blog</a></li>
        <li aria-current="page">Article Title</li>
      </ol>
    </nav>

    <!-- Independent, self-contained content -->
    <article>
      <header>
        <h1>Article Title</h1>
        <p>Published by <address><a rel="author" href="/author">Author</a></address>
           on <time datetime="2026-04-08">April 8, 2026</time></p>
      </header>

      <section>
        <h2>Introduction</h2>
        <p>Content...</p>
        <figure>
          <img src="diagram.png" alt="Architecture diagram showing three layers">
          <figcaption>Fig 1: Three-tier architecture</figcaption>
        </figure>
      </section>

      <section>
        <h2>Details</h2>
        <p>Content...</p>
        <aside>
          <h3>Did You Know?</h3>
          <p>Related fact...</p>
        </aside>
      </section>

      <footer>
        <p>Tags: <a href="/tag/html">HTML</a>, <a href="/tag/css">CSS</a></p>
      </footer>
    </article>

    <!-- Related articles (tangentially related to main) -->
    <aside aria-label="Related articles">
      <h2>Related</h2>
      <ul>...</ul>
    </aside>

  </main>

  <!-- Site-wide footer -->
  <footer>
    <nav aria-label="Footer navigation">...</nav>
    <p><small>&copy; 2026 My Site</small></p>
  </footer>

</body>
</html>

KEY RULES:
- <main> must be UNIQUE per page; do NOT place inside header/nav/aside/footer
- <header>/<footer> can appear multiple times (inside <article>/<section>)
- <nav> should wrap MAJOR navigation blocks; use aria-label to distinguish multiple
- <article> vs <section>: article is self-contained (syndicate alone);
  section is a thematic grouping within a document
- Heading hierarchy: one <h1> per page (or per <article>); h2→h3→h4 in order
  (never skip heading levels)

7. NESTING RULES & CONTENT MODELS
================================================================================

HTML5 defines CONTENT CATEGORIES for each element:

Category            Examples
-----------         -----------------------------------------
Flow content        Most elements that can appear in <body>
Phrasing content    Inline content: <span>, <a>, <em>, <strong>, text
Heading content     <h1>–<h6>
Sectioning content  <article>, <aside>, <nav>, <section>
Embedded content    <img>, <video>, <audio>, <canvas>, <iframe>
Interactive content <a>, <button>, <input>, forms, <details>
Transparent content Inherits content model from parent: <a>, <ins>, <del>
Metadata content    <link>, <meta>, <script>, <style>, <title>

CRITICAL NESTING RULES:
  - <p> cannot contain block-level elements (<div>, <ul>, <h1>, <p>)
  - <a> CANNOT nest another <a>
  - <button> CANNOT nest <input> or other interactive elements
  - <ul>/<ol> direct children must be <li> only
  - <dl> direct children must be <dt>/<dd> only (or <div> wrapping them)
  - <table> direct child must be <thead>, <tbody>, <tfoot>, <tr>, <caption>,<col>
  - <select> direct children must be <option> or <optgroup>
  - <head> can ONLY contain metadata elements

TRANSPARENT CONTENT MODEL:
  <a> inherits the content model of its parent.
  If parent allows flow content, <a> can wrap block elements:
    <a href="/"> <div>Card</div> </a>  ← valid in HTML5!
  If parent only allows phrasing, <a> can only contain phrasing content.

8. WHITE SPACE & FORMATTING
================================================================================

HTML COLLAPSES whitespace:
- Multiple spaces → single space
- Tabs → space
- Newlines → space
- Use &nbsp; for non-breaking space, or CSS white-space property

Pre-formatted text:
  <pre>   — preserves whitespace including newlines
  <code>  — inline code (monospace by default)
  <kbd>   — keyboard input
  <samp>  — sample output

white-space CSS property:
  normal    — collapse whitespace (default)
  pre       — preserve all whitespace
  pre-wrap  — preserve whitespace, wrap at container width
  pre-line  — collapse spaces, preserve newlines
  nowrap    — no wrapping

9. COMMENTS
================================================================================

HTML Comment Syntax:
  <!-- This is a comment -->
  <!-- 
    Multi-line
    comment
  -->

Important notes:
- Comments are visible in page source (never store secrets/passwords!)
- Comments CAN appear before DOCTYPE (but DOCTYPE should be first line)
- Comments DO appear in the DOM (as Comment nodes, nodeType=8)
- Conditional comments (IE-specific):
    <!--[if IE]> IE-specific content <![endif]-->
    <!--[if lt IE 9]> ... <![endif]-->
    <!--[if IE 9]><!--> Modern content <!--<![endif]-->

10. CHARACTER REFERENCES (ENTITIES)
================================================================================

Named entities (most common):
  &amp;     = & (ampersand — MUST escape in attributes and text)
  &lt;      = < (less-than — MUST escape in text/attributes)
  &gt;      = > (greater-than — recommended to escape)
  &quot;    = " (quote — escape inside double-quoted attributes)
  &apos;    = ' (apostrophe — escape inside single-quoted attributes)
  &nbsp;    = non-breaking space
  &copy;    = © (copyright)
  &reg;     = ® (registered trademark)
  &trade;   = ™
  &mdash;   = — (em dash)
  &ndash;   = – (en dash)
  &hellip;  = … (ellipsis)
  &laquo;   = « &raquo; = »
  &larr;    = ← &rarr; = → &uarr; = ↑ &darr; = ↓

Numeric entities:
  &#169;    = © (decimal code point)
  &#xA9;    = © (hexadecimal code point)
  &#8212;   = — (em dash decimal)

WHEN to escape:
  Always escape & < in text content and attribute values
  Escape " inside double-quoted attributes
  Escape > in text content (recommended; not strictly required)
  Never need to escape in <script> or <style> content

11. IMPORTANT INTERVIEW Q&A
================================================================================

Q1: What is the minimum valid HTML5 document?
A:  <!DOCTYPE html>
    <html lang="en">
    <head><meta charset="UTF-8"><title>Title</title></head>
    <body></body>
    </html>
    Technically the browser will parse even "hello world" as a valid document
    by implicitly creating html/head/body, but this is not recommended.

Q2: Why should <meta charset> be the first element in <head>?
A: The browser needs to know the encoding BEFORE it reads anything else (to
   avoid misinterpreting characters). It must be within the first 1024 bytes.
   Placing it first ensures no characters are misread.

Q3: Why is the viewport meta tag needed?
A: Without it, mobile browsers render the page at desktop width (~980px) and
   then scale it down, making text tiny. viewport tells the browser to set
   the CSS viewport width to the device's actual width.
   content="width=device-width, initial-scale=1.0" is the standard value.

Q4: What is the difference between <article> and <section>?
A: <article>: Independently distributable/syndicate-able content (blog post,
   news article, forum post, tweet). Makes sense on its own, out of context.
   <section>: Thematic grouping of content within a document. Should have a
   heading. Use when content belongs to a larger whole.
   Rule of thumb: If you could share it as a standalone piece, use <article>.
   If it's a chapter/division of a document, use <section>.

Q5: Can a page have multiple <h1> elements?
A: Technically yes in HTML5 (one per <article>/<section> with the "outline
   algorithm"), but the HTML5 outline algorithm was never implemented by
   browsers. For accessibility and SEO, best practice is ONE <h1> per page,
   followed by a strict hierarchy (h1 → h2 → h3 — never skip levels).

Q6: What is the difference between <head> and <header>?
A: <head> is a metadata container (inside <html>; not visible to users).
   <header> is a semantic element for introductory content (visible to users;
   can contain logo, nav, title; appears in <body>).

Q7: Why put scripts at the bottom of <body>?
A: Scripts without async/defer block HTML parsing. By placing them at the
   bottom, the DOM is fully constructed before the script runs. Modern best
   practice is to use <script defer> in <head>, which achieves the same result
   more cleanly and allows preloading to begin earlier.

Q8: What is the purpose of the <base> tag?
A: Sets the base URL for all relative URLs on the page and the default target
   for all links. Example: <base href="https://example.com/blog/">
   A relative link <a href="post.html"> would resolve to
   https://example.com/blog/post.html. Only one <base> allowed per page.

Q9: What is the difference between id and class attributes?
A: id must be UNIQUE per page (one element per id); used for anchor links,
   JS getElementById, and high-specificity CSS. class can be shared by many
   elements and one element can have multiple classes. Use id sparingly
   (mainly for landmarks/skip links/form labels); use class for styling.

Q10: What are data-* attributes and where do they live structurally?
A: Custom attributes on any HTML element that store extra information not
   visible to users. They appear in the element's opening tag as
   data-{name}="value" and are accessible via element.dataset.{name} in JS.
   Example: <button data-product-id="42" data-action="add-to-cart">Add</button>
   JS: button.dataset.productId → "42" (camelCase conversion of kebab-case)
