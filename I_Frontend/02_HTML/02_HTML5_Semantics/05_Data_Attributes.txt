1. WHAT ARE DATA ATTRIBUTES?
================================================================================

Data attributes (also called "custom data attributes") are HTML attributes
that allow you to store EXTRA INFORMATION on HTML elements. They are intended
for use by the page's OWN scripts, not for conveying semantic meaning.

Syntax:
  data-{name}="{value}"

Example:
  <button data-product-id="42"
          data-action="add-to-cart"
          data-price="29.99"
          data-category="electronics">
    Add to Cart
  </button>

Key properties:
  - The "data-" prefix is required
  - Can be placed on ANY HTML element
  - Values are always STRINGS (even numbers are stored as strings)
  - They are valid HTML5 — no validation errors
  - They appear in the DOM and are accessible via CSS and JavaScript
  - They are visible in page source (DON'T store sensitive data)
  - They do NOT affect rendering by default (no visual change)

================================================================================
2. SYNTAX & NAMING RULES
================================================================================

Format:  data-{name}="{value}"

Naming rules (the {name} part):
  ✓ Lowercase letters (a-z)
  ✓ Digits (0-9)
  ✓ Hyphens (-)
  ✓ Dots (.) — allowed but unusual
  ✓ Colons (:) — allowed but unusual
  ✓ Underscores (_) — allowed but unusual

  ✗ Uppercase letters (technically invalid; some browsers accept but avoid)
  ✗ Must NOT start with "xml" (any case) — reserved
  ✗ Must NOT contain semicolons

VALID examples:
  data-user-id="123"
  data-index="0"
  data-is-active="true"
  data-api-url="https://api.example.com"
  data-v="2.0"
  data-toggle-target="modal-1"

INVALID examples:
  data-XML-id="123"        ← starts with xml
  data-userId="123"        ← uppercase (technically invalid per spec)
  data-="value"            ← empty name

Naming convention:
  Use kebab-case in HTML: data-user-name="John"
  It auto-converts to camelCase in JavaScript: element.dataset.userName
  
  Conversion rules (HTML → JS):
    data-user-name    → dataset.userName
    data-product-id   → dataset.productId
    data-is-active    → dataset.isActive
    data-max-value    → dataset.maxValue

3. ACCESSING DATA ATTRIBUTES IN JAVASCRIPT
================================================================================

Two approaches:
  1. dataset API (modern, recommended)
  2. getAttribute/setAttribute (works on all attributes)

METHOD 1: dataset API

  HTML: <div id="item" data-user-id="42" data-is-active="true" data-score="9.5">

  const el = document.getElementById('item');

  // READ
  el.dataset.userId    // → "42"    (string!)
  el.dataset.isActive  // → "true"  (string!)
  el.dataset.score     // → "9.5"   (string!)

  // WRITE
  el.dataset.userId = "99";
  el.dataset.newProp = "hello";   // Creates data-new-prop attribute

  // DELETE
  delete el.dataset.isActive;    // Removes data-is-active attribute

  // CHECK existence
  'userId' in el.dataset  // → true
  el.dataset.hasOwnProperty('userId')  // → true

  // ITERATE over all data attributes
  for (const [key, value] of Object.entries(el.dataset)) {
    console.log(`${key}: ${value}`);
  }

  // Spread to plain object
  const data = { ...el.dataset };  // { userId: "42", isActive: "true", score: "9.5" }

IMPORTANT: All values are STRINGS. Type conversion is your responsibility:
  const id    = parseInt(el.dataset.userId, 10);     // 42 (number)
  const score = parseFloat(el.dataset.score);         // 9.5 (number)
  const flag  = el.dataset.isActive === 'true';       // true (boolean)
  const obj   = JSON.parse(el.dataset.config);        // parsed object

METHOD 2: getAttribute / setAttribute

  el.getAttribute('data-user-id')         // → "42"
  el.setAttribute('data-user-id', '99')   // Sets value
  el.removeAttribute('data-user-id')      // Removes attribute
  el.hasAttribute('data-user-id')         // → true/false

When to use getAttribute vs dataset:
  - dataset is preferred for data-* attributes (cleaner, more readable)
  - getAttribute works for ALL attributes, not just data-*
  - getAttribute needed for attributes with characters invalid in JS identifiers

4. ACCESSING DATA ATTRIBUTES IN CSS
================================================================================

Two ways: attribute selectors and the attr() function.

ATTRIBUTE SELECTORS:
  /* Select elements with any value */
  [data-active] { border: 2px solid green; }
  
  /* Select elements with specific value */
  [data-theme="dark"]  { background: #1a1a1a; color: white; }
  [data-size="large"]  { font-size: 1.5rem; }
  
  /* Prefix match */
  [data-icon^="arrow"] { /* all icons starting with "arrow" */ }
  
  /* Substring match */
  [data-id*="admin"] { /* all elements with "admin" in data-id */ }
  
  /* Suffix match */
  [data-url$=".pdf"] { color: red; }

  Example: toggle state via data attribute
  .accordion-item[data-open="true"] .accordion-content {
    display: block;
  }
  .accordion-item[data-open="false"] .accordion-content {
    display: none;
  }

attr() FUNCTION (display attribute values in CSS):
  /* Show the data value in a tooltip via ::before/::after */
  [data-tooltip]::before {
    content: attr(data-tooltip);
    /* position, style as tooltip */
    position: absolute;
    background: #333;
    color: white;
    padding: 4px 8px;
    border-radius: 4px;
    white-space: nowrap;
    top: -30px;
    left: 50%;
    transform: translateX(-50%);
  }

  HTML: <button data-tooltip="Save document">💾</button>

  /* Progress bar using data-percent */
  .progress-fill {
    width: 0%;
    transition: width 0.3s;
  }
  /* JS: el.dataset.percent = 70; */
  /* CSS can't dynamically read the value — use CSS custom property approach */
  /* or: calculate width via JS directly */

CSS custom property bridge (data attribute → CSS variable):
  element.style.setProperty('--progress', `${percent}%`);
  
  CSS:
  .progress-fill {
    width: var(--progress, 0%);
  }

5. DATA ATTRIBUTES vs OTHER STORAGE OPTIONS
================================================================================

Option            Scope         Persistence    Notes
--------------    ----------    -----------    ------------------------------------
data-* attribute  One element   DOM lifetime   Visible in source; best for per-element
JavaScript vars   Module scope  Session        Not in DOM; fast; no DOM sync
localStorage      Per origin    Permanent      5-10MB; across sessions/tabs
sessionStorage    Per tab       Tab session    Tab-specific; cleared on tab close
cookie            Per path      Configurable   4KB; sent to server on every request
IndexedDB         Per origin    Permanent      Large data; async API; complex

When to use data attributes:
  ✓ Small pieces of data tied to a SPECIFIC ELEMENT
  ✓ Data set by server-side rendering (embed in HTML)
  ✓ Data consumed by JavaScript or CSS
  ✓ Passing config/state to JavaScript widgets
  ✓ Marking elements for behavior (data-toggle, data-target)

When NOT to use data attributes:
  ✗ Storing sensitive information (visible in source/DevTools)
  ✗ Large amounts of data (better in JS variables or localStorage)
  ✗ Data not related to a DOM element
  ✗ Application-level state (use JS state management)
  ✗ Data needed across pages (use localStorage/sessionStorage)

Data attributes vs class names:
  Classes: For STYLING and state that affects presentation
  data-*: For BEHAVIOR, METADATA, and non-presentational state
  
  Blurring the line:
    <button class="btn is-active" data-state="active">  ← using both
    
  Prefer data attributes for state that JS changes dynamically
  and CSS targets via attribute selectors (avoids CSS class manipulation).

6. PERFORMANCE CONSIDERATIONS
================================================================================

1. dataset access is slightly slower than direct property access:
   el.dataset.userId    → calls getter, hyphen-camelCase conversion
   el._userId           → direct property (non-standard; avoid)
   
   In practice, the difference is negligible for typical UI interactions.
   Only matters in performance-critical tight loops.

2. DOM attribute changes trigger reflow/repaint if CSS attribute selectors
   match:
   el.dataset.theme = 'dark';  → if [data-theme] CSS exists → style recalc
   
   Batch updates and be aware of which data changes trigger CSS changes.

3. Reading data attributes is synchronous and blocks the main thread if done
   excessively in tight loops. For performance-critical code, read once and
   store in a variable.

4. JSON in data attributes:
   el.dataset.config = JSON.stringify(configObj);
   // Later:
   const config = JSON.parse(el.dataset.config);
   
   Be careful with size and escaping. For complex data, prefer JS variables.

7. REAL-WORLD USE CASES
================================================================================

USE CASE 1: Tooltips via data attribute
  <button data-tooltip="Save your changes (Ctrl+S)">Save</button>

  [data-tooltip] {
    position: relative;
    cursor: pointer;
  }
  [data-tooltip]:hover::after,
  [data-tooltip]:focus::after {
    content: attr(data-tooltip);
    position: absolute;
    bottom: 100%;
    left: 50%;
    transform: translateX(-50%);
    background: rgba(0,0,0,0.8);
    color: white;
    padding: 6px 10px;
    border-radius: 4px;
    white-space: nowrap;
    font-size: 0.875rem;
    pointer-events: none;
  }

USE CASE 2: UI component configuration
  <div
    class="carousel"
    data-autoplay="true"
    data-interval="3000"
    data-show-dots="true"
    data-slide-count="5">
  </div>

  // JS component reads config from data attributes
  const carousel = document.querySelector('.carousel');
  const { autoplay, interval, showDots, slideCount } = carousel.dataset;
  initCarousel({
    autoplay: autoplay === 'true',
    interval: parseInt(interval, 10),
    showDots: showDots !== 'false',
    slideCount: parseInt(slideCount, 10)
  });

USE CASE 3: Click handler delegation
  <ul id="product-list">
    <li data-product-id="101" data-action="view">Product A</li>
    <li data-product-id="102" data-action="view">Product B</li>
    <li data-product-id="103" data-action="edit">Product C</li>
  </ul>

  document.getElementById('product-list').addEventListener('click', (e) => {
    const item = e.target.closest('[data-product-id]');
    if (!item) return;
    const { productId, action } = item.dataset;
    handleAction(action, productId);
  });

USE CASE 4: Server-rendered data for JavaScript
  <!-- Server renders user data into the page -->
  <div id="app"
       data-user-id="456"
       data-user-role="admin"
       data-api-base="/api/v2"
       data-csrf-token="abc123def456"
       hidden>
  </div>

  const app = document.getElementById('app');
  const { userId, userRole, apiBase, csrfToken } = app.dataset;
  initApp({ userId: parseInt(userId), userRole, apiBase, csrfToken });

USE CASE 5: Tracking and analytics
  <button
    data-track-event="button_click"
    data-track-category="checkout"
    data-track-label="place_order"
    data-track-value="49.99">
    Place Order
  </button>

  document.addEventListener('click', (e) => {
    const tracked = e.target.closest('[data-track-event]');
    if (!tracked) return;
    const { trackEvent, trackCategory, trackLabel, trackValue } = tracked.dataset;
    analytics.track(trackEvent, {
      category: trackCategory,
      label: trackLabel,
      value: parseFloat(trackValue)
    });
  });

USE CASE 6: Drag and Drop
  <div draggable="true"
       data-drag-id="item-1"
       data-drag-type="task"
       data-source-column="todo">
    Task Item
  </div>

  <div class="column"
       data-column-id="in-progress"
       data-accepts="task,bug">
    Drop zone
  </div>

  el.addEventListener('dragstart', (e) => {
    const { dragId, dragType, sourceColumn } = e.target.dataset;
    e.dataTransfer.setData('application/json',
      JSON.stringify({ dragId, dragType, sourceColumn }));
  });

USE CASE 7: State management for CSS
  <!-- Toggle accordion open/closed -->
  <div class="accordion-item" data-open="false">
    <button class="accordion-header">Section Title</button>
    <div class="accordion-content">...</div>
  </div>

  .accordion-content { display: none; }
  [data-open="true"] .accordion-content { display: block; }

  document.querySelectorAll('.accordion-header').forEach(header => {
    header.addEventListener('click', () => {
      const item = header.closest('.accordion-item');
      const isOpen = item.dataset.open === 'true';
      item.dataset.open = isOpen ? 'false' : 'true';
    });
  });

8. COMMON PATTERNS & TECHNIQUES
================================================================================

Pattern 1: Data attribute as selector hook
  // Avoid: document.querySelector('.js-modal-trigger')
  // Better: <button data-modal-trigger="login">
  document.querySelectorAll('[data-modal-trigger]').forEach(trigger => {
    trigger.addEventListener('click', () => {
      openModal(trigger.dataset.modalTrigger);
    });
  });

Pattern 2: Avoiding magic numbers with data attributes
  // Instead of: if (index === 42) { ... }
  // Use: <li data-product-id="42">
  // Then: productId = parseInt(el.dataset.productId)

Pattern 3: Data attributes as feature flags
  <body data-feature-new-checkout="true"
        data-feature-dark-mode="false">
  
  const features = document.body.dataset;
  if (features.featureNewCheckout === 'true') {
    loadNewCheckout();
  }

Pattern 4: Linking elements (toggle pattern)
  <button data-toggle="menu-nav" aria-expanded="false" aria-controls="menu-nav">
    Menu
  </button>
  <nav id="menu-nav" data-toggleable hidden>
    <!-- nav content -->
  </nav>

  document.querySelectorAll('[data-toggle]').forEach(btn => {
    btn.addEventListener('click', () => {
      const targetId = btn.dataset.toggle;
      const target = document.getElementById(targetId);
      const isOpen = btn.getAttribute('aria-expanded') === 'true';
      btn.setAttribute('aria-expanded', !isOpen);
      target.hidden = isOpen;
    });
  });

9. IMPORTANT INTERVIEW Q&A
================================================================================

Q1: What are HTML5 data attributes and what are they for?
A: data-* attributes store custom metadata on HTML elements. They're designed
   for use by the page's own scripts — not for accessibility, styling, or
   SEO purposes. They allow embedding data directly in the HTML that JavaScript
   can read (via element.dataset) without requiring hidden form fields or
   JSON in comments.

Q2: How do you access data attributes in JavaScript?
A: Two ways: (1) element.dataset.{camelCaseName} — returns the string value.
   The HTML attribute data-user-name becomes dataset.userName (camelCase).
   (2) element.getAttribute('data-user-name') — also returns string value.
   You can also set: element.dataset.userId = '99' (creates/updates the attr)
   and delete: delete element.dataset.userId.

Q3: What are the naming rules for data attributes?
A: The name after "data-" must be at least one character, can contain lowercase
   letters, digits, and hyphens. It must NOT start with "xml" (reserved), must
   NOT contain uppercase letters (technically), and must be preceded by "data-".
   In JavaScript, the kebab-case name converts to camelCase automatically.

Q4: Are data attribute values always strings?
A: Yes. The DOM stores all attribute values as strings. When you read
   element.dataset.price = "29.99", you get the string "29.99". You must
   explicitly convert: parseFloat(element.dataset.price), JSON.parse(),
   or element.dataset.isActive === 'true'. This is a common source of bugs.

Q5: What is the difference between data attributes and ARIA attributes?
A: ARIA attributes (aria-*) communicate ACCESSIBILITY information to assistive
   technologies. They're standardized and have defined semantic meaning.
   data-* attributes are CUSTOM and purely for scripts — they have no semantic
   meaning to browsers or screen readers. Never use data attributes to replace
   ARIA attributes for accessibility.

Q6: Can CSS access data attributes?
A: Yes, in two ways: (1) Attribute selectors: [data-theme="dark"] { ... }
   (2) The attr() function in content property: content: attr(data-label).
   You cannot (yet) use attr() for arbitrary CSS properties in standard CSS
   (though CSS Values Level 5 is working on expanding attr()).

Q7: Should you store sensitive data in data attributes?
A: NEVER. Data attributes are visible in the page source, browser DevTools,
   and to any JavaScript on the page (including injected scripts). Never store:
   passwords, tokens, PII, API keys, credit card numbers. Use server-side
   sessions, HTTP-only cookies, or server API calls for sensitive data.

Q8: When would you use data attributes instead of localStorage?
A: Use data attributes when the data is SCOPED TO A SPECIFIC ELEMENT (config
   for a widget, product ID on a card, state of a toggle). Use localStorage
   when data needs to PERSIST across sessions or be accessed globally.
   Data attributes live only as long as the DOM element; localStorage persists.

Q9: How do you pass complex objects through data attributes?
A: Serialize to JSON: element.dataset.config = JSON.stringify({ a: 1, b: [2,3] })
   Deserialize: const config = JSON.parse(element.dataset.config).
   Alternatives: store complex data in a WeakMap keyed by the element (cleaner),
   or use a module-level Map. JSON in attributes has size limits and parsing
   overhead — for complex data, JS variables are better.

Q10: What is event delegation and how do data attributes enable it?
A: Event delegation means attaching ONE event listener to a parent element
   instead of many listeners on individual children. When an event fires, you
   check which child was the target using e.target.closest('[data-action]').
   Data attributes identify the action, so you don't need separate handlers per
   element. This is more memory-efficient and works for dynamically added elements.
