1. BLOCK-LEVEL ELEMENTS
================================================================================

Block-level elements:
  - Start on a NEW LINE
  - Take up the FULL WIDTH available (width: 100% by default)
  - Can contain other block-level AND inline elements
  - Respect width, height, margin, padding fully
  - Stack vertically

Complete list of block-level elements:
  Structural:   <div>, <p>, <pre>, <blockquote>, <hr>
  Headings:     <h1>, <h2>, <h3>, <h4>, <h5>, <h6>
  Lists:        <ul>, <ol>, <dl>, <li>, <dt>, <dd>
  Table:        <table>, <thead>, <tbody>, <tfoot>, <tr>, <th>, <td>, <caption>
  Semantic:     <header>, <footer>, <main>, <nav>, <article>, <section>, <aside>
                <address>, <figure>, <figcaption>
  Form:         <form>, <fieldset>, <legend>
  Media:        <video>, <audio>, <canvas>
  Other:        <details>, <summary>, <dialog>

Visual behavior:
  ┌─────────────────────────────────────────────────────┐
  │  <p> always takes full available width               │
  └─────────────────────────────────────────────────────┘
  ┌─────────────────────────────────────────────────────┐
  │  <div> also takes full width                         │
  └─────────────────────────────────────────────────────┘

Block elements in series:
  <h1>Heading</h1>   → new line, full width
  <p>Paragraph</p>   → new line, full width
  Each stacks below the previous.

================================================================================
2. INLINE ELEMENTS
================================================================================

Inline elements:
  - Do NOT start on a new line
  - Take only as much width as their CONTENT requires
  - Cannot have block-level children (in most cases)
  - Width and height properties have NO EFFECT
  - Top/bottom margins have no effect; left/right margins work
  - Top/bottom padding renders but does NOT affect surrounding line height layout
  - Flow within text

Complete list of inline elements:
  Text semantics:  <a>, <em>, <strong>, <b>, <i>, <u>, <s>, <del>, <ins>
                   <mark>, <cite>, <q>, <abbr>, <dfn>, <sub>, <sup>
  Technical:       <code>, <kbd>, <samp>, <var>
  Generic:         <span>
  Media:           <img>, <svg>, <video>*, <audio>*, <canvas>*
  Form:            <input>, <button>, <select>, <textarea>, <label>, <output>
  Other:           <br>, <wbr>, <small>, <ruby>, <rt>, <rp>, <time>, <data>
  
  (*video/audio/canvas are replaced elements with special rendering rules)

Visual behavior:
  <p>
    This is normal text with an <a href="#">inline link</a> and
    <em>inline emphasis</em> flowing within the paragraph.
  </p>
  → Renders on same line, wraps naturally.

Inline elements in series:
  <span>Hello</span><span>World</span>  → "HelloWorld" (no space between)
  <span>Hello</span> <span>World</span> → "Hello World" (space in HTML)

================================================================================
3. KEY DIFFERENCES
================================================================================

Property           Block                  Inline
-----------------  ---------------------  ---------------------------------
New line           YES (starts new line)  NO (flows with text)
Default width      100% of parent         Content width only
width / height     Takes effect           NO EFFECT (except replaced)
Margin top/bottom  Takes effect           NO EFFECT on layout
Padding top/bottom Takes effect, pushes   Renders but DOESN'T affect flow
Can contain        Block + Inline         Phrasing content only
Nesting            Block can contain both <a> rule: cannot nest another <a>

Padding on inline elements (IMPORTANT):
  <span style="padding: 20px; background: yellow;">
  The top and bottom padding RENDERS (visible as background color) but does
  NOT push content above/below out of the way. It overlaps adjacent lines.
  Left and right padding DOES affect flow.

Margin on inline elements:
  margin-left and margin-right work (create space horizontally)
  margin-top and margin-bottom do NOT work on inline elements

4. THE display PROPERTY & ITS VALUES
================================================================================

Every HTML element has a default display value set by the browser stylesheet.
You can override it with CSS: display: <value>

display: block
  - Element behaves like a block element
  - Stacks vertically; takes full width
  - <div>, <p>, <h1> default to this

display: inline
  - Element behaves like an inline element
  - Flows with text; no width/height control
  - <span>, <a>, <em> default to this

display: inline-block
  - Inline: flows with text, doesn't start new line
  - Block: respects width, height, margin, padding
  - Example use cases: nav items, icon buttons, image grids

display: none
  - Element is completely hidden and REMOVED from layout
  - Takes NO space; not in accessibility tree
  - Compare: visibility: hidden (still takes space; in a11y tree)

display: flex
  - Creates a flex container; children become flex items
  - Powerful 1D layout system (row or column)

display: inline-flex
  - Like flex but the container itself is inline

display: grid
  - Creates a grid container; 2D layout system

display: inline-grid
  - Like grid but the container itself is inline

display: contents
  - Element itself generates no box; children render as-is
  - Useful for wrappers you want "invisible" to layout
  - WARNING: removes element from a11y tree in some browsers (use with care)

display: table / table-cell / table-row
  - Emulates table layout behavior
  - Rarely needed now (use Grid instead)

display: list-item
  - Like block but also generates a list marker
  - <li> defaults to this

display: flow-root
  - Creates a new block formatting context (BFC)
  - Useful for containing floats without clearfix hacks

display: none vs visibility: hidden:
  display: none      — removed from layout + a11y tree; no space taken
  visibility: hidden — invisible but KEEPS its space; still in a11y tree
  opacity: 0         — invisible; KEEPS space; still in a11y tree; still clickable!

================================================================================
5. INLINE-BLOCK BEHAVIOR
================================================================================

display: inline-block = the "best of both worlds"

  Inline behavior:
    - Sits inline with text (no forced line break)
    - Can be part of text flow

  Block behavior:
    - Respects width and height
    - Respects all margin and padding (including top/bottom)

Classic use case — navigation items:
  nav a {
    display: inline-block;
    padding: 10px 20px;    /* Works! Top/bottom padding pushes items */
    margin: 0 5px;          /* Works! All margins work */
    width: 100px;           /* Works! Fixed width */
  }

The "ghost white-space" problem:
  <span style="display:inline-block">A</span>
  <span style="display:inline-block">B</span>
  A small gap appears between them due to whitespace in HTML.
  
  Solutions:
    a) Remove whitespace in HTML (ugly): <span>A</span><span>B</span>
    b) font-size: 0 on parent; reset on children
    c) Use flexbox instead (preferred modern approach)

vertical-align with inline/inline-block:
  vertical-align: top | middle | bottom | baseline | text-top | text-bottom
  Controls alignment relative to the surrounding line box.
  Most useful with inline-block and vertical centering of adjacent elements.

6. THE CSS BOX MODEL IN CONTEXT
================================================================================

Every element generates a "box":

BLOCK BOX:
  ┌──────────────────────────────────────┐
  │  Margin                              │
  │  ┌──────────────────────────────┐   │
  │  │  Border                       │   │
  │  │  ┌────────────────────────┐  │   │
  │  │  │  Padding                │  │   │
  │  │  │  ┌──────────────────┐  │  │   │
  │  │  │  │  Content         │  │  │   │
  │  │  │  └──────────────────┘  │  │   │
  │  │  └────────────────────────┘  │   │
  │  └──────────────────────────────┘   │
  └──────────────────────────────────────┘

box-sizing:
  content-box (default): width = content only
    Total width = content + padding + border
  border-box: width = content + padding + border
    Content shrinks to accommodate padding/border
  
  Best practice: * { box-sizing: border-box; } — easier mental model

INLINE BOX:
  - Width is determined by content only
  - Height is determined by line-height (not height property!)
  - Top/bottom padding overlaps adjacent lines (doesn't expand layout)
  - Top/bottom margin is ignored

Line box:
  The browser creates invisible "line boxes" for each line of text.
  Inline elements live within line boxes.
  Line height determines the height of each line box.

7. BLOCK vs INLINE IN HTML5 CONTENT MODELS
================================================================================

HTML5 doesn't use "block" and "inline" categories — it uses CONTENT CATEGORIES:

Old model (HTML4):  Block | Inline
New model (HTML5):  Flow | Phrasing | Interactive | Sectioning | etc.

Mapping:
  Block elements roughly → Flow content elements
  Inline elements roughly → Phrasing content elements

Important implication — <a> with block children:
  HTML4: <a href="/"><div>Card</div></a>  ← INVALID (inline containing block)
  HTML5: <a href="/"><div>Card</div></a>  ← VALID (transparent content model)
  
  <a> is a transparent element — it inherits its parent's content model.
  If parent allows flow content, <a> can contain flow content (including divs).

  But: <a> CANNOT be nested:
  ✗ <a href="/"><a href="/other">link</a></a>

8. REPLACED vs NON-REPLACED ELEMENTS
================================================================================

REPLACED elements: content defined by external resource or browser
  - <img>, <video>, <audio>, <canvas>, <iframe>, <embed>, <object>, <input>
  - Browser replaces the element tag with the actual content
  - Have intrinsic dimensions (natural width/height)
  - Can have width/height applied even when inline
  - <img> is inline but respects width/height like a block

NON-REPLACED elements: rendered directly by browser based on HTML/CSS
  - <span>, <p>, <div>, <h1>, etc.
  - Width and height controlled entirely by CSS display value

The <img> oddity:
  <img> is an inline element (flows with text) BUT behaves like inline-block:
  - Respects width and height properties
  - Respects vertical-align
  - Creates a "whitespace gap" below (due to inline baseline alignment)
  
  Fix for image bottom gap:
    img { display: block; }  ← most common fix
    OR
    img { vertical-align: bottom; }

================================================================================
9. ANONYMOUS BOXES
================================================================================

The browser sometimes creates "anonymous boxes" to satisfy block formatting rules.

Anonymous block box:
  <div>
    Some text  ←  browser wraps this in anonymous block box
    <p>Paragraph</p>
    More text  ←  browser wraps this in anonymous block box
  </div>

  The block formatting context requires that block containers only contain
  block children (or only inline children). When mixed, text nodes are wrapped.

Anonymous inline box:
  <p>Some <em>emphasized</em> text</p>
  "Some " and " text" become anonymous inline boxes alongside <em>.

Understanding this helps debug layout issues — the browser adds structure
you don't explicitly write.

10. IMPORTANT INTERVIEW Q&A
================================================================================

Q1: What is the difference between block and inline elements?
A: Block elements start on a new line, take the full available width, and
   can contain both block and inline children. Inline elements flow within
   text, take only as much width as their content, and generally only contain
   phrasing content. Block elements respect all CSS box model properties
   (width, height, margin, padding). Inline elements ignore width/height and
   top/bottom margin.

Q2: What is display: inline-block?
A: An element that flows inline (doesn't start a new line) but also respects
   width, height, and all padding/margin values like a block element. It's
   the best of both worlds — useful for navigation items, image grids, and
   any inline element that needs dimension control.

Q3: What is the difference between display: none and visibility: hidden?
A: display: none completely removes the element from the layout and the
   accessibility tree — it takes no space. visibility: hidden makes the
   element invisible but it STILL occupies space, and it's still in the
   accessibility tree (though screen readers may or may not read it).
   opacity: 0 also keeps space and is still clickable/interactive.

Q4: Can an inline element contain a block-level element?
A: In HTML4, no. But in HTML5, <a> (and other "transparent" content model
   elements like <del>, <ins>) can contain block elements if the parent
   context allows flow content. So <a href="/"><div>Card</div></a> is valid
   HTML5. However, two interactive elements (like <a> inside <a>) are never
   allowed, regardless of the content model.

Q5: Why does <img> have a whitespace gap below it?
A: <img> is an inline-replaced element. By default it aligns to the text
   BASELINE of the surrounding line box, which leaves a small gap below for
   descenders (letters like g, p, y). Fix: set display: block on the image
   (removes it from inline formatting context) or set vertical-align: bottom.

Q6: What does display: contents do?
A: The element itself generates no visual box — its children "replace" it
   in the layout as if the parent element weren't there. Useful when you
   want a semantic wrapper element that shouldn't affect flex/grid layout.
   WARNING: display: contents removes the element from the accessibility tree
   in some browsers — avoid on elements with semantic meaning.

Q7: What is the box-sizing property and why use border-box?
A: box-sizing: content-box (default) means width sets only the content area —
   padding and border add to the total size. box-sizing: border-box means
   width includes content + padding + border. border-box is much more
   intuitive: setting width: 300px means the element is exactly 300px total.
   Best practice: * { box-sizing: border-box; } globally.

Q8: What happens when you apply margin-top to an inline element?
A: It has NO visual effect. Top and bottom margins are ignored for inline
   elements. Only left and right margins work. If you need top/bottom margin
   on an inline element, change it to inline-block or block, or use
   padding (which renders but doesn't affect surrounding layout).

Q9: Explain vertical-align for inline elements.
A: vertical-align controls how an inline or inline-block element aligns
   relative to the LINE BOX it's in. Values: baseline (default — aligns to
   text baseline), top (aligns to top of tallest element in line), middle
   (aligns to middle of line), bottom, text-top, text-bottom, and length/%.
   It does NOT center elements vertically in a container (use flexbox for that).

Q10: What is a "block formatting context" (BFC)?
A: A BFC is a region where block boxes are laid out independently — elements
   inside don't affect elements outside. Created by: display: flow-root,
   overflow (non-visible), float, position (absolute/fixed), display: flex/grid.
   Key behaviors of a BFC:
   - Contains its floated children (prevents float collapsing)
   - Prevents margin collapsing with adjacent elements
   - Doesn't wrap around floats outside it
   Understanding BFC is critical for float-based layouts and clearfix alternatives.
