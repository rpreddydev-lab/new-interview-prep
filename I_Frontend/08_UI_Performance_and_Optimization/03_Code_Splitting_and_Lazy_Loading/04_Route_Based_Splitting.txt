================================================================
ROUTE-BASED CODE SPLITTING
================================================================

WHAT IS ROUTE-BASED SPLITTING?
────────────────────────────────
Route-based splitting divides your application bundle by route (page).
Each route's code is only loaded when the user navigates to that route.

This is the MOST IMPACTFUL form of code splitting because:
  - Routes are natural boundaries for code separation
  - Users only visit a subset of routes in a session
  - Route components are often large (full pages with all their dependencies)
  - The split is predictable and easy to implement

TYPICAL BUNDLE REDUCTION:
  Before route splitting: main.js = 2.5MB (ALL pages)
  After route splitting:
    initial.js = 200KB (routing + common code)
    home.chunk.js = 150KB
    dashboard.chunk.js = 500KB (charts, tables)
    admin.chunk.js = 800KB (admin tools)
    settings.chunk.js = 100KB
  → User only downloads initial.js + current route's chunk

REACT ROUTER V6 WITH CODE SPLITTING
================================================================

BASIC ROUTE-BASED SPLITTING:
──────────────────────────────
import React, { lazy, Suspense } from 'react';
import { BrowserRouter, Routes, Route } from 'react-router-dom';

// Lazy load each route component
const Home = lazy(() => import('./pages/Home'));
const About = lazy(() => import('./pages/About'));
const Dashboard = lazy(() => import('./pages/Dashboard'));
const Products = lazy(() => import('./pages/Products'));
const ProductDetail = lazy(() => import('./pages/ProductDetail'));
const Cart = lazy(() => import('./pages/Cart'));
const Checkout = lazy(() => import('./pages/Checkout'));
const AdminPanel = lazy(() => import('./pages/AdminPanel'));

// Page-level loading component
function PageLoader() {
  return (
    <div className="page-loading">
      <Skeleton variant="page" />
    </div>
  );
}

function App() {
  return (
    <BrowserRouter>
      <Navigation />
      
      <Suspense fallback={<PageLoader />}>
        <Routes>
          <Route path="/" element={<Home />} />
          <Route path="/about" element={<About />} />
          <Route path="/dashboard" element={<Dashboard />} />
          <Route path="/products" element={<Products />} />
          <Route path="/products/:id" element={<ProductDetail />} />
          <Route path="/cart" element={<Cart />} />
          <Route path="/checkout" element={<Checkout />} />
          <Route path="/admin/*" element={<AdminPanel />} />
        </Routes>
      </Suspense>
      
      <Footer />
    </BrowserRouter>
  );
}

NEXT.JS PAGES ROUTER (automatic):

// Next.js AUTOMATICALLY code splits every file in /pages
// No manual lazy() needed!

// pages/index.js → loaded for /
// pages/about.js → loaded for /about
// pages/dashboard.js → loaded for /dashboard

// Next.js creates a separate chunk per page automatically
// Only the current page's code is loaded on navigation

// However, for HEAVY components within a page, use next/dynamic:
import dynamic from 'next/dynamic';

const HeavyChart = dynamic(
  () => import('../components/HeavyChart'),
  { loading: () => <ChartSkeleton /> }
);

export default function DashboardPage() {
  return (
    <div>
      <PageHeader />
      <HeavyChart data={chartData} />  {/* Loaded separately */}
    </div>
  );
}

NEXT.JS APP ROUTER (React Server Components):
─────────────────────────────────────────────
// app/page.tsx → loaded for /
// app/about/page.tsx → loaded for /about
// app/dashboard/page.tsx → loaded for /dashboard

// Each route segment is automatically code-split
// Server components never ship JS to client (even better than code splitting!)

// Client components in App Router:
// 'use client' directive marks a component as client-side
'use client';
import { useState } from 'react';

// Still auto-code-split per route by Next.js

// For additional splitting within App Router routes:
import { lazy, Suspense } from 'react';

const HeavyChart = lazy(() => import('./HeavyChart'));

export default function DashboardPage() {
  return (
    <div>
      <ServerSideHeader />  {/* Server component, no JS sent */}
      <Suspense fallback={<ChartSkeleton />}>
        <HeavyChart />  {/* Client component, split into own chunk */}
      </Suspense>
    </div>
  );
}

================================================================
ROUTE PREFETCHING (Loading Next Routes in Advance)
================================================================

WHY PREFETCH ROUTES:
  - User hovers over a link → likely to click it
  - Prefetch the target route → instant navigation
  - Eliminates the loading spinner for fast/expected navigations

REACT ROUTER V6 PREFETCHING:
──────────────────────────────
// Manual prefetch on hover
function PrefetchLink({ to, children, lazyComponent }) {
  const prefetchRef = useRef(false);
  
  const handleMouseEnter = () => {
    if (!prefetchRef.current) {
      prefetchRef.current = true;
      // Trigger the import — webpack caches the chunk
      lazyComponent._payload?._result || lazyComponent._init?.(lazyComponent._payload);
    }
  };
  
  return (
    <Link to={to} onMouseEnter={handleMouseEnter}>
      {children}
    </Link>
  );
}

// Better approach: call the import() directly
const checkoutImport = () => import('./pages/Checkout');
const LazyCheckout = lazy(checkoutImport);

function CartPage() {
  return (
    <div>
      <CartItems />
      {/* Prefetch checkout page when user hovers over button */}
      <button
        onMouseEnter={() => checkoutImport()} // Start loading
        onClick={() => navigate('/checkout')}
      >
        Proceed to Checkout
      </button>
    </div>
  );
}

NEXT.JS LINK COMPONENT (Automatic Prefetching):
─────────────────────────────────────────────────
import Link from 'next/link';

// Next.js <Link> AUTOMATICALLY prefetches linked pages
// when the link enters the viewport (in production builds)

function Navigation() {
  return (
    <nav>
      <Link href="/">Home</Link>           {/* Prefetched when visible */}
      <Link href="/about">About</Link>     {/* Prefetched when visible */}
      <Link href="/dashboard">Dashboard</Link>
    </nav>
  );
}

// Disable prefetching for specific links (e.g., admin, rarely visited)
<Link href="/admin" prefetch={false}>Admin</Link>

// Manual programmatic prefetch
import { useRouter } from 'next/navigation'; // or next/router

const router = useRouter();

// Prefetch programmatically
router.prefetch('/checkout');

// On hover
<button onMouseEnter={() => router.prefetch('/checkout')}>
  Checkout
</button>

MANAGING LOADING STATES FOR ROUTE TRANSITIONS

APPROACH 1: SUSPENSE WITH SKELETON
─────────────────────────────────────
// Skeleton matches target page layout
const routeSkeletons = {
  dashboard: DashboardSkeleton,
  products: ProductListSkeleton,
  profile: ProfileSkeleton,
};

function RouteLoader({ path }) {
  const SkeletonComponent = routeSkeletons[path] || DefaultSkeleton;
  return <SkeletonComponent />;
}

APPROACH 2: NPROGRESS BAR (GitHub-style)
─────────────────────────────────────────
import NProgress from 'nprogress';
import 'nprogress/nprogress.css';

// Configure NProgress
NProgress.configure({ showSpinner: false, speed: 200 });

// React Router v6 integration
function App() {
  return (
    <BrowserRouter>
      <RouterProgressBar />
      <Suspense fallback={null}> {/* No jarring spinner — progress bar handles it */}
        <Routes>...</Routes>
      </Suspense>
    </BrowserRouter>
  );
}

function RouterProgressBar() {
  const location = useLocation();
  const navigation = useNavigation();
  
  useEffect(() => {
    if (navigation.state === 'loading') {
      NProgress.start();
    } else {
      NProgress.done();
    }
  }, [navigation.state, location]);
  
  return null;
}

APPROACH 3: KEEP PREVIOUS ROUTE VISIBLE (React 18 useTransition)
──────────────────────────────────────────────────────────────────
import { useTransition } from 'react';
import { useNavigate } from 'react-router-dom';

function NavigationLink({ to, children }) {
  const navigate = useNavigate();
  const [isPending, startTransition] = useTransition();
  
  const handleClick = (e) => {
    e.preventDefault();
    startTransition(() => {
      navigate(to);  // Navigation wrapped in transition
    });
  };
  
  return (
    <a href={to} onClick={handleClick}
       style={{ opacity: isPending ? 0.5 : 1 }}>
      {children}
    </a>
  );
}

// Current page stays visible while new route loads
// Avoids blank screen during chunk download
// Only shows new page when ready

NESTED ROUTE SPLITTING
================================================================

SPLITTING NESTED ROUTES INDEPENDENTLY:
────────────────────────────────────────
// App structure:
// /dashboard → loads Dashboard shell
// /dashboard/analytics → loads Analytics tab (additionally)
// /dashboard/users → loads Users tab (additionally)
// /dashboard/settings → loads Settings tab (additionally)

const Dashboard = lazy(() => import('./pages/Dashboard'));
// Dashboard itself is split (shell only)

// Inside Dashboard component:
const Analytics = lazy(() => import('./tabs/Analytics'));
const Users = lazy(() => import('./tabs/Users'));
const Settings = lazy(() => import('./tabs/Settings'));

function Dashboard() {
  return (
    <div className="dashboard">
      <DashboardSidebar />
      
      <main>
        <Suspense fallback={<TabContentSkeleton />}>
          <Routes>
            <Route path="analytics" element={<Analytics />} />
            <Route path="users" element={<Users />} />
            <Route path="settings" element={<Settings />} />
          </Routes>
        </Suspense>
      </main>
    </div>
  );
}

// Loading sequence:
// 1. Navigate to /dashboard: loads dashboard.chunk.js (~50KB shell)
// 2. Navigate to /dashboard/analytics: loads analytics.chunk.js (~200KB)
// 3. Navigate to /dashboard/users: loads users.chunk.js (~150KB)
// Each tab is independently split and cached

================================================================
INTERVIEW ANSWERS
================================================================

Q: What is route-based code splitting and why is it the highest-impact approach?
A: Route-based splitting creates a separate JavaScript chunk for each route/page.
   It's the highest-impact approach because routes are natural code boundaries,
   users only visit a subset of pages, and route components often contain the
   bulk of page-specific code and dependencies. In React Router, you wrap each
   route component with React.lazy(). In Next.js, it's automatic per page file.

Q: How does Next.js handle route-based code splitting automatically?
A: Every file in Next.js pages/ or app/ directory is automatically code-split
   into its own chunk. When a user navigates to a route, only that route's chunk
   is downloaded. Additionally, Next.js Link components automatically prefetch
   linked pages when they enter the viewport, eliminating loading states for
   most navigations. This gives near-instant navigation without any manual
   configuration.

Q: How do you handle the loading state during route transitions?
A: Three approaches: (1) Suspense with skeleton screens — show a skeleton that
   matches the target page structure, providing layout continuity; (2) Progress
   bar (NProgress) — a thin bar at the top like GitHub uses, less intrusive
   than spinners; (3) React 18 useTransition — keep the current page visible
   while the new route loads, only switching when ready (best UX). The choice
   depends on expected load times and UX preferences.

Q: How do you prefetch routes to make navigation feel instant?
A: In Next.js, Link components automatically prefetch when visible in viewport —
   no configuration needed. In React Router, I manually trigger the import()
   function (which webpack caches) on mouseenter events on navigation links.
   I also use Webpack's webpackPrefetch magic comment for routes that are
   likely to be visited next (e.g., checkout after cart). This starts loading
   the chunk in browser idle time before the user clicks.

Q: How do you split nested routes (dashboard with tabs)?
A: I use multiple levels of lazy loading. First, the dashboard shell is lazy.
   Then, inside the Dashboard component, each tab (analytics, users, settings)
   is also lazy-loaded with its own Suspense boundary. This means navigating
   to /dashboard downloads the shell only, and each tab downloads its code
   the first time it's visited. Each tab's chunk can be independently cached.
