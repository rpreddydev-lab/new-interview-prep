================================================================
FONT OPTIMIZATION
================================================================

WHY FONTS IMPACT PERFORMANCE:
──────────────────────────────────
  - Fonts are render-blocking — browser can't paint text until font loads
  - Custom fonts: 50-500KB per file (or more for variable fonts)
  - Multiple weights/styles = multiple network requests
  - Font loading causes FOIT or FOUT (invisible or shifted text)
  - Font swap can cause CLS if metrics differ from fallback font

TYPICAL FONT LOADING TIMELINE (unoptimized):
  HTML starts loading
    → Parse HTML → Discover <link> to CSS
    → Load CSS → Parse CSS → Discover @font-face
    → Start loading font file (BLOCKING! — text hidden or invisible)
    → Font loaded → Text renders
  Total delay: 300ms - 2s of invisible or unstyled text!

================================================================
FOIT vs FOUT vs FOFT
================================================================

FOIT (Flash of Invisible Text):
  - Browser hides text while font loads
  - Default behavior in Chrome (waits up to 3 seconds)
  - BAD: users see blank content → frustrating, looks broken

FOUT (Flash of Unstyled Text):
  - Browser shows fallback font immediately, swaps to custom font when ready
  - Can cause layout shift (CLS) if fonts have different metrics
  - Better than FOIT — content is always visible

FOFT (Flash of Faux Text):
  - Advanced technique: load only the Roman weight first
  - Apply faux-bold/italic using CSS while actual variants load
  - More complex but fastest perceived loading

================================================================
font-display PROPERTY — THE MOST IMPORTANT SETTING
================================================================

@font-face {
  font-family: 'MyFont';
  src: url('/fonts/myfont.woff2') format('woff2');
  font-display: swap;  /* ← This one setting matters MOST */
}

font-display VALUES:
  
  auto:      Browser default (usually block with timeout)
  
  block:     FOIT: hide text for up to 3s, then FOUT
             Use for: icon fonts where fallback looks broken
  
  swap:      Show fallback IMMEDIATELY, swap when font ready (FOUT)
             Use for: body text, headers — content visible right away
             ⚠️ Can cause CLS!
  
  fallback:  Show fallback for 100ms, then if font not ready, use
             fallback for rest of page life (no late swap)
             Use for: fonts that heavily affect layout
  
  optional:  Show fallback for ~100ms, then IF font is already cached
             use it; otherwise continue with fallback FOREVER
             Use for: decorative fonts where loading is "nice to have"
             Best CLS impact — no swap at all!

RECOMMENDATION:
  - Body text: font-display: swap (always visible, CLS tolerable)
  - Decorative/hero fonts: font-display: optional (no CLS)
  - Icon fonts: font-display: block (fallback chars are meaningless)

================================================================
PRELOADING FONTS — CRITICAL FOR LCP
================================================================

Without preload, font discovery happens late:
  HTML → CSS → @font-face → font download (LATE!)

With preload, font download starts immediately:
  HTML → (parallel) preload + CSS → font already loading!

  <!-- In <head> — MUST be early in the document -->
  <link
    rel="preload"
    href="/fonts/inter-regular.woff2"
    as="font"
    type="font/woff2"
    crossorigin="anonymous"   <!-- REQUIRED even for same-origin fonts! -->
  />
  
  <!-- Only preload fonts visible in initial viewport -->
  <!-- Preloading unused fonts wastes bandwidth -->
  
  /* In CSS @font-face: */
  @font-face {
    font-family: 'Inter';
    src: url('/fonts/inter-regular.woff2') format('woff2');
    font-weight: 400;
    font-style: normal;
    font-display: swap;
  }

WHAT TO PRELOAD:
  ✅ Fonts used for above-the-fold text
  ✅ Your primary body font (regular weight)
  ✅ Fonts that affect LCP element text
  ❌ Don't preload every variant — only what's needed immediately
  ❌ Don't preload italic/bold if they're not in initial viewport

================================================================
FONT SUBSETTING — REDUCE FILE SIZE DRAMATICALLY
================================================================

Full Latin + Unicode font: 200-500KB
Subset for Latin only: ~30-80KB
Subset for specific characters: < 10KB

GOOGLE FONTS SUBSETTING via URL:
  <!-- Only load Latin characters -->
  https://fonts.googleapis.com/css2?family=Inter&subset=latin
  
  <!-- Unicode range — even more granular -->
  https://fonts.googleapis.com/css2?family=Inter&text=ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789

CSS unicode-range for self-hosted:
  @font-face {
    font-family: 'Inter';
    src: url('inter-latin.woff2') format('woff2');
    unicode-range: U+0000-00FF, U+0131, U+0152-0153, U+02BB-02BC;
    /* Only Latin characters → browser only downloads this file if
       these characters are present on the page */
  }

TOOLS:
  - glyphhanger: Analyzes page and generates minimal font subset
  - pyftsubset (fonttools): CLI subsetting tool
  - Google Fonts: Automatic subsetting by unicode-range

================================================================
VARIABLE FONTS — ONE FILE FOR ALL WEIGHTS
================================================================

Traditional approach: One file per weight/style
  inter-thin.woff2      (100) — separate download
  inter-light.woff2     (300) — separate download
  inter-regular.woff2   (400) — separate download
  inter-bold.woff2      (700) — separate download
  Total: 4 requests, ~200KB+

Variable font: ONE file, any weight:
  inter-variable.woff2  — 1 request, ~100-150KB
  
  @font-face {
    font-family: 'Inter';
    src: url('/fonts/inter-variable.woff2') format('woff2-variations');
    font-weight: 100 900;  /* Supports full range! */
    font-style: normal;
    font-display: swap;
  }
  
  /* Use any weight in CSS: */
  h1 { font-weight: 700; }
  p { font-weight: 400; }
  .subtle { font-weight: 300; }
  .fine { font-weight: 150; } /* ← Traditional fonts can't do this! */
  
  /* Even animated weights (CSS transitions!): */
  .hover-bold:hover {
    font-weight: 700;
    transition: font-weight 0.2s;
  }

VARIABLE FONT AXES:
  wght: Weight (100-900)
  wdth: Width/condensed
  ital: Italic
  slnt: Slant
  opsz: Optical size
  Custom axes vary by font

================================================================
FONT METRIC OVERRIDES — PREVENT CLS FROM FONT SWAP
================================================================

When font-display: swap swaps from fallback to custom font, if the
fonts have different metrics (x-height, ascent, descent), text reflowing
causes CLS.

CSS font metric overrides let you adjust the FALLBACK font metrics
to MATCH the custom font — eliminating the layout shift on swap!

  @font-face {
    font-family: 'Inter Fallback';   /* Custom name for the adjusted fallback */
    src: local('Arial');             /* Use system Arial as base */
    
    /* Adjust metrics to match Inter's metrics exactly */
    ascent-override: 90%;
    descent-override: 22%;
    line-gap-override: 0%;
    size-adjust: 107%;               /* Scale to match x-height */
  }
  
  /* Use adjusted fallback BEFORE custom font in stack */
  body {
    font-family: 'Inter', 'Inter Fallback', Arial, sans-serif;
  }
  
  /* Result: When Inter swaps in, text doesn't shift at all!
     CLS from font loading = 0 */

TOOLS TO GENERATE THESE VALUES:
  - next/font: Generates these automatically! (see below)
  - fontpie: CLI tool to calculate override values
  - Font Style Matcher: Visual tool to match metrics

================================================================
NEXT/FONT — AUTOMATIC FONT OPTIMIZATION
================================================================

Next.js 13+ next/font is the best-in-class font optimization:
  ✅ Zero layout shift (automatic font metric overrides)
  ✅ Self-hosted (no Google Fonts privacy/GDPR concerns)
  ✅ Automatic subsetting to characters used on the page
  ✅ Built-in caching with immutable headers
  ✅ No external network request at runtime

  // ─── app/layout.tsx (Next.js 13+ App Router) ───
  import { Inter, Playfair_Display } from 'next/font/google';
  
  const inter = Inter({
    subsets: ['latin'],       // Subset automatically
    display: 'swap',          // font-display: swap
    variable: '--font-inter', // Expose as CSS variable
  });
  
  const playfair = Playfair_Display({
    subsets: ['latin'],
    weight: ['400', '700'],   // Only these weights downloaded
    display: 'optional',      // Decorative: no swap if not cached
    variable: '--font-playfair',
  });
  
  export default function RootLayout({ children }) {
    return (
      <html className={`${inter.variable} ${playfair.variable}`}>
        <body className={inter.className}>
          {children}
        </body>
      </html>
    );
  }
  
  // CSS usage:
  // .heading { font-family: var(--font-playfair); }
  
  // ─── Local fonts: ───
  import localFont from 'next/font/local';
  
  const brandFont = localFont({
    src: [
      { path: './fonts/brand-400.woff2', weight: '400' },
      { path: './fonts/brand-700.woff2', weight: '700' },
    ],
    display: 'swap',
    variable: '--font-brand',
  });

SYSTEM FONT STACK — ZERO DOWNLOAD
================================================================

For maximum performance: use system fonts (already on device!):

  /* System font stack used by GitHub, Bootstrap, etc. */
  body {
    font-family:
      -apple-system,            /* macOS/iOS: San Francisco */
      BlinkMacSystemFont,       /* macOS Chrome */
      'Segoe UI',               /* Windows */
      Roboto,                   /* Android */
      Oxygen,                   /* Linux KDE */
      Ubuntu,                   /* Ubuntu Linux */
      Cantarell,                /* Linux GNOME */
      'Helvetica Neue',         /* macOS fallback */
      sans-serif;               /* Final fallback */
  }
  
  /* Result: 0KB font download, instant text rendering, native look */

WHEN TO USE SYSTEM FONTS:
  ✅ Admin dashboards (performance > branding)
  ✅ B2B/internal tools
  ✅ Apps where typography is functional, not brand identity
  ❌ Brand-heavy marketing sites where typography IS the brand

================================================================
INTERVIEW ANSWERS
================================================================

Q: What is FOIT, FOUT, and how do you prevent them?
A: FOIT (Flash of Invisible Text) is when the browser hides text while
   loading a custom font — users see blank space. FOUT (Flash of Unstyled
   Text) is when text shows immediately in a fallback font, then visibly
   swaps to the custom font. FOIT is worse for perceived performance since
   content is invisible; FOUT causes layout shift. Fix FOIT: set font-display:
   swap or fallback. Fix FOUT/CLS: use CSS font metric overrides (ascent-override,
   descent-override, size-adjust) to make fallback font match the custom font's
   dimensions — no shift on swap. Or use font-display: optional which never
   swaps (no CLS, no FOUT). Next.js next/font handles this automatically.

Q: Why does preloading a font require crossorigin="anonymous" even for same-origin?
A: Fonts are always fetched with CORS mode — even for same-origin requests.
   This is a browser design decision to ensure consistent caching behavior
   across origins. If you omit crossorigin="anonymous" on the preload hint,
   the browser makes a preload request WITHOUT CORS headers, then when the
   CSS @font-face tries to use the font, it makes a NEW request WITH CORS
   headers — and these are treated as different cache entries, so the preload
   is wasted. Always include crossorigin="anonymous" on font preload links.

Q: What's the advantage of variable fonts for performance?
A: Variable fonts contain the full weight range (100-900) in a SINGLE file
   using math/interpolation between defined "masters." For a project using
   4 weights (regular, medium, semibold, bold), a variable font typically uses
   ~120KB vs ~200KB for 4 separate files. Beyond file size, there's reduced
   HTTP requests and no FOUT for additional weight variants loading late.
   Variable fonts also enable CSS animations on font-weight (smooth weight
   transitions), and with font-display: optional, subsequent visits have the
   full weight range cached — perfect user experience with a single fetch.

Q: How does next/font achieve zero layout shift?
A: next/font analyzes the custom font's metrics at build time (x-height,
   ascent, descent, cap-height), then generates CSS font metric overrides
   for a matching fallback font (typically Arial or Times) that make the
   fallback have identical dimensions to the custom font. It inlines this
   @font-face for the adjusted fallback into the CSS. When font-display: swap
   occurs, the visual metrics are identical, so no text reflow happens and
   CLS stays at 0. It also self-hosts Google Fonts, eliminating the DNS lookup
   to fonts.googleapis.com and the privacy implications of Google tracking font
   loads across domains.
