================================================================
CLS - CUMULATIVE LAYOUT SHIFT
================================================================

DEFINITION
──────────
CLS measures the total sum of all unexpected layout shift scores that occur
throughout the entire lifespan of the page.

A layout shift occurs when a visible element moves from one position to
another between frames without being caused directly by user interaction.

In simple terms: "Do elements jump around on the page unexpectedly?"

THRESHOLDS:
  ✅ Good:              ≤ 0.1
  ⚠️  Needs Improvement: 0.1 – 0.25
  ❌ Poor:              > 0.25
  
  Measured at: 75th percentile of all page visits
  
  Note: CLS is unitless (it's a score, not time)

================================================================
WHY CLS MATTERS
================================================================

CLS IS A UX DISASTER:
  - You're reading an article → ad loads → text shifts down → you lose your place
  - You're about to click "Cancel" → button shifts up → you click "Buy Now" instead
  - Form fills text → image loads → fields move → you're filling wrong field
  - Medical/financial apps: clicking wrong button due to shift = serious error

REAL COST OF HIGH CLS:
  - Mis-clicks → user frustration
  - Accidental purchases/actions → support costs
  - Loss of reading context → abandonment
  - Google ranks you lower

================================================================
HOW CLS IS CALCULATED
================================================================

Each layout shift score = Impact Fraction × Distance Fraction

  IMPACT FRACTION:
  - The fraction of the viewport area affected by the shift
  - If an element occupies 50% of viewport and shifts → impact = 0.5
  
  DISTANCE FRACTION:
  - The fraction of the viewport the element moved
  - If element moves 10% of viewport height → distance = 0.1
  
  Single shift score = 0.5 × 0.1 = 0.05

  CLS = sum of all individual layout shift scores

SESSION WINDOWS (2021 update):
  - CLS was originally a sum across entire page life
  - Updated to use "session windows" with 5s gap between shifts
  - Each session window = consecutive shifts with < 1s gap
  - Session window total = sum of shifts in that window
  - CLS = MAXIMUM session window score
  - This prevents infinite-scroll pages from being penalized unfairly

WHAT DOES NOT COUNT AS A LAYOUT SHIFT:
  - Shifts within 500ms of user interaction (click, tap, key press)
  - Animations that use transform (no layout shift)
  - CSS transitions using transform/opacity (GPU composited, no reflow)
  - Shifts where element enters viewport for first time (new element)

================================================================
COMMON CAUSES OF HIGH CLS
================================================================

1. IMAGES WITHOUT DIMENSIONS
──────────────────────────────
Problem: Browser doesn't know image size until downloaded → reserves no space
Result: Page "jumps" when image loads

<!-- ❌ No dimensions → CLS -->
<img src="hero.jpg" alt="Hero">

<!-- ✅ Dimensions set → browser reserves space -->
<img src="hero.jpg" alt="Hero" width="800" height="600">

<!-- ✅ Responsive with aspect ratio preserved -->
<img src="hero.jpg" alt="Hero"
     width="800" height="600"
     style="max-width: 100%; height: auto;">

<!-- ✅ CSS aspect-ratio approach -->
<div style="aspect-ratio: 4/3;">
  <img src="hero.jpg" alt="Hero" style="width: 100%; height: 100%;">
</div>

2. ADS / EMBEDS / IFRAMES WITHOUT RESERVED SPACE
───────────────────────────────────────────────────
Problem: Ad slot injected dynamically → pushes content down

<!-- ❌ Ad inserted without reserved space -->
<div id="ad-container"></div> <!-- empty, then ad makes it 250px tall -->

<!-- ✅ Reserve space for ad slot -->
<div id="ad-container" style="min-height: 250px; width: 300px;">
  <!-- Ad loads here, already has space reserved -->
</div>

/* ✅ Or use aspect-ratio for responsive ad slots */
.ad-slot {
  min-height: 90px;   /* Leaderboard height */
  /* OR */
  aspect-ratio: 728 / 90;
}

3. DYNAMICALLY INJECTED CONTENT ABOVE EXISTING CONTENT
────────────────────────────────────────────────────────
Problem: Cookie banner, notification bar, chat widget loads and pushes page down

Solutions:
  a) Reserve space at the top before content loads
  b) Use position: fixed/sticky for injected banners (don't affect layout)
  c) Animate from bottom, not top
  d) Use skeleton placeholders that match the final content height

<!-- ✅ Cookie banner fixed to bottom (doesn't shift content) -->
<div id="cookie-banner" style="position: fixed; bottom: 0; width: 100%;">
  Cookie notice...
</div>

4. FONTS CAUSING FLASH OF INVISIBLE/UNSTYLED TEXT (FOIT/FOUT)
───────────────────────────────────────────────────────────────
Problem: Custom font loads → fallback font swapped → text reflows

/* ✅ font-display: optional — no FOUT, just uses fallback if slow */
@font-face {
  font-family: 'MyFont';
  src: url('my-font.woff2') format('woff2');
  font-display: optional;  /* Best for CLS */
}

/* ✅ font-display: swap — shows fallback, then swaps (may cause CLS) */
@font-face {
  font-family: 'MyFont';
  src: url('my-font.woff2') format('woff2');
  font-display: swap;  /* Better for user, may cause small CLS */
}

/* ✅ Size-adjust: match fallback font metrics to custom font */
@font-face {
  font-family: 'FallbackFont';
  src: local('Arial');
  size-adjust: 107%;          /* Adjust size to match custom font */
  ascent-override: 90%;       /* Match ascent metrics */
  descent-override: 22%;
  line-gap-override: 0%;
}

/* ✅ Preload fonts to reduce swap time */
<link rel="preload" href="/fonts/my-font.woff2" as="font" type="font/woff2" crossorigin>

5. ANIMATIONS THAT TRIGGER LAYOUT
────────────────────────────────────
/* ❌ Layout-triggering animation → CLS */
@keyframes slideIn {
  from { margin-top: -100px; }
  to { margin-top: 0; }
}

/* ✅ Transform-based animation → no CLS, GPU composited */
@keyframes slideIn {
  from { transform: translateY(-100px); }
  to { transform: translateY(0); }
}

/* ✅ Similarly for width/height animations: */
/* Use max-height or scale transform instead */

6. SKELETON SCREENS THAT DON'T MATCH CONTENT SIZE
────────────────────────────────────────────────────
Problem: Skeleton is 100px, real content is 250px → CLS when content loads

Solutions:
  - Match skeleton dimensions to actual content as closely as possible
  - Use CSS aspect-ratio based on expected content
  - Load content with SSR so dimensions are known from HTML

================================================================
CLS IN REACT APPLICATIONS
================================================================

COMMON REACT CLS ISSUES:
  - useEffect-driven content that pushes page layout after initial render
  - Images in components without width/height props
  - Loading states that render different height content than loaded state

PREVENTING CLS IN REACT:
──────────────────────────

// ✅ Reserve space for async content
function UserProfile({ userId }) {
  const { data: user, isLoading } = useUser(userId);
  
  return (
    // Fixed min-height prevents CLS when content loads
    <div style={{ minHeight: '200px' }}>
      {isLoading ? (
        <UserProfileSkeleton /> {/* Same dimensions as loaded state */}
      ) : (
        <UserProfileContent user={user} />
      )}
    </div>
  );
}

// ✅ Next.js Image component with fill or dimensions
import Image from 'next/image';

// Approach 1: explicit dimensions
<Image src="/photo.jpg" width={400} height={300} alt="..." />

// Approach 2: fill parent container (container must have defined dimensions)
<div style={{ position: 'relative', height: '300px', width: '400px' }}>
  <Image src="/photo.jpg" fill alt="..." style={{ objectFit: 'cover' }} />
</div>

// ✅ CSS containment to limit CLS scope
.card {
  contain: layout; /* Shifts inside won't affect outside */
}

================================================================
DETECTING AND DEBUGGING CLS
================================================================

DETECTING LAYOUT SHIFTS IN DEVTOOLS:
  1. Chrome DevTools → Rendering → ✅ Layout shift regions
     → Blue borders appear around shifted elements in real-time
  
  2. Chrome DevTools → Performance panel → record → look for red/purple
     "Layout Shift" markers in the Experience row
  
  3. Lighthouse → shows CLS score and elements causing shifts

DETECTING IN CODE:
──────────────────
const observer = new PerformanceObserver((list) => {
  for (const entry of list.getEntries()) {
    if (!entry.hadRecentInput) {
      console.log('Layout shift:', {
        score: entry.value,
        sources: entry.sources?.map(source => ({
          element: source.node,
          previousRect: source.previousRect,
          currentRect: source.currentRect,
        })),
        time: entry.startTime,
      });
    }
  }
});
observer.observe({ entryTypes: ['layout-shift'] });

// Web Vitals library with attribution:
import { onCLS } from 'web-vitals/attribution';

onCLS(({ value, attribution }) => {
  console.log('CLS:', value);
  console.log('Largest shift element:', attribution.largestShiftTarget);
  console.log('Largest shift source:', attribution.largestShiftSource);
});

================================================================
CLS OPTIMIZATION CHECKLIST
================================================================

✅ Set width and height on all images and video elements
✅ Reserve space for ads, embeds, and iframes (min-height)
✅ Use CSS aspect-ratio for media containers
✅ Don't insert content above existing content without reserving space
✅ Place cookie banners / notification bars with position: fixed
✅ Use CSS transforms for animations (not margin/top/left/width/height)
✅ Use font-display: optional or match fallback font metrics
✅ Preload critical fonts to minimize font swap time
✅ Use skeleton screens with matching dimensions
✅ Server-side render content so dimensions are known upfront
✅ Test with Rendering panel "Layout shift regions" enabled
✅ Use CSS contain: layout where appropriate

================================================================
INTERVIEW ANSWERS
================================================================

Q: What is CLS and how is it calculated?
A: CLS (Cumulative Layout Shift) measures the total sum of unexpected layout
   shifts during the page's lifetime. Each shift score = Impact Fraction ×
   Distance Fraction (how much of the viewport shifted × how far it moved).
   CLS reports the maximum "session window" score — consecutive shifts with
   < 1s between them. Good CLS: ≤ 0.1. It's a unitless score.

Q: What are the most common causes of CLS?
A: (1) Images without width/height attributes — browser reserves no space,
   so content shifts when image loads; (2) Ads/banners without reserved
   space; (3) Dynamically injected content above existing content (cookie
   banners, notification bars); (4) Custom fonts causing text reflow when
   they swap in (FOUT); (5) Animations using layout-triggering CSS properties
   instead of transforms.

Q: How do you fix CLS caused by images?
A: Always set width and height attributes on <img> tags. The browser uses
   these to calculate aspect-ratio and reserve space before the image loads.
   For responsive images, add style="max-width: 100%; height: auto;" which
   maintains the aspect ratio. Alternatively, use the CSS aspect-ratio
   property on a container. In Next.js, the Image component handles this
   automatically.

Q: How do you fix CLS caused by fonts?
A: (1) Use font-display: optional to avoid FOUT entirely (falls back to
   system font if custom font isn't cached); (2) Preload the font file so
   it loads faster; (3) Use size-adjust, ascent-override, descent-override
   CSS properties to make the fallback font metrics match the custom font,
   minimizing the reflow when the custom font swaps in (CSS Font Metrics
   Override); (4) Use system fonts when CLS is critical.

Q: What's the difference between a layout shift and an animation?
A: A layout shift is an unexpected movement of DOM elements that causes
   reflow (changes to width, height, top, left, margin, padding). An
   animation using CSS transform (translateX, translateY, scale) doesn't
   trigger layout — it's composited by the GPU, causes zero CLS, and is
   also better for performance overall. Always use transforms for animations
   instead of animating layout properties.
