================================================================
WHY PERFORMANCE MATTERS - DEEP DIVE
================================================================

PERFORMANCE IS A FEATURE
─────────────────────────
Performance is not an afterthought — it's a core feature that determines
whether users stay, convert, and return. A beautiful, feature-rich app is
worthless if it never finishes loading.

"The best request is the one that never happens."
"The fastest code is the code that never runs."
"Performance is about respect for the user's time."

================================================================
USER PERCEPTION OF PERFORMANCE
================================================================

THE 100ms–10s SCALE:
  0–100ms    → Feels INSTANT (users perceive as no delay)
  100ms–300ms → Slight delay noticed but still fast
  300ms–1s   → User senses a delay; machine is working
  1s–3s      → User's flow is interrupted; they notice
  3s–10s     → Users start to leave / abandon
  10s+       → Users have mentally moved on; likely lost forever

ATTENTION & ABANDONMENT:
  - 53% of mobile users abandon sites that take > 3 seconds to load
    (Google/SOASTA research)
  - Users form performance opinions in the first 0.05 seconds (50ms)
  - Once users experience a slow site, trust is damaged

THE JAKOB NIELSEN RESPONSE TIME RULES (still relevant today):
  - 0.1s: System seems to react instantly
  - 1.0s: User loses flow but can regain it
  - 10s: User loses attention entirely

================================================================
SEO IMPACT
================================================================

WHY GOOGLE CARES ABOUT PERFORMANCE:
  - Google's mission: Organize the world's information and make it USEFUL
  - A slow page is less useful → ranked lower

CORE WEB VITALS AS RANKING SIGNALS (since June 2021):
  - LCP (Largest Contentful Paint): Loading quality
  - INP (Interaction to Next Paint): Interactivity quality [replaced FID in 2024]
  - CLS (Cumulative Layout Shift): Visual stability

PAGE EXPERIENCE SIGNALS:
  - Core Web Vitals
  - Mobile-friendliness
  - Safe browsing
  - HTTPS
  - No intrusive interstitials

PRACTICAL SEO IMPACT:
  - Meeting "Good" thresholds for all CWV = positive ranking boost
  - AMP (Accelerated Mobile Pages) was Google's previous solution
    → Being replaced by CWV-based ranking
  - Sites with better CWV rank higher for same-quality content

================================================================
ACCESSIBILITY & INCLUSIVITY
================================================================

PERFORMANCE IS AN ACCESSIBILITY ISSUE:
  - Not everyone has fiber/5G — many users on 2G/3G networks
  - Not everyone has a new iPhone — many use $50-100 Android devices
  - Data costs money — 1MB JS bundle costs real money in some regions
  - Battery drain — inefficient JS = shorter battery life

GLOBAL INTERNET REALITY:
  - 3.7 billion people are online for the first time via mobile
  - Average connection speed in India: ~10 Mbps (vs ~150 Mbps in US)
  - Median mobile page weight: ~2MB — costs $0.15 in India, $0.60 in Canada
  - 45% of global internet connections are 2G or 3G

LOW-END DEVICE PERFORMANCE:
  - Median Android phone has 1/5th the CPU power of an iPhone
  - 6x CPU throttling in Chrome DevTools simulates mid-tier Android
  - JS parse/compile time is proportional to CPU speed, NOT connection speed
  - 1MB of JS takes ~52ms to parse on fast laptop, ~1000ms on Moto G4

================================================================
DEVELOPER EXPERIENCE AND MAINTENANCE
================================================================

PERFORMANCE DEBT:
  - Like technical debt, performance debt accumulates over time
  - Each new feature/dependency can slow things down incrementally
  - Harder to fix later when the site has grown complex

PERFORMANCE CULTURE BENEFITS:
  - Forces discipline: "Do we really need this library?"
  - Encourages better architecture decisions
  - Reduces infrastructure costs (smaller payloads = less bandwidth)
  - Improves developer productivity (fast builds, fast dev server)

================================================================
PERFORMANCE PSYCHOLOGY
================================================================

PERCEIVED PERFORMANCE vs ACTUAL PERFORMANCE:
  A 5-second load that shows content progressively FEELS faster than
  a 3-second load that shows nothing until complete.

TECHNIQUES FOR BETTER PERCEIVED PERFORMANCE:
  1. Skeleton screens (show layout before content arrives)
  2. Optimistic UI updates (update UI before server confirms)
  3. Progressive loading (above-the-fold first)
  4. Loading indicators (spinners, progress bars)
  5. Instant feedback on interactions
  6. Preloading on hover/intent (guess what user will do next)

COGNITIVE LOAD:
  - Slow responses increase cognitive load
  - Users have to "hold" their intent in working memory
  - After ~1s, users lose context about what they were doing

================================================================
INTERVIEW ANSWERS
================================================================

Q: Why does performance matter for a business?
A: Performance directly impacts conversion rates, revenue, and user retention.
   Studies show that even 100ms-500ms delays cause measurable revenue loss.
   For Amazon, 100ms latency added = 1% revenue loss. For BBC, every 1s adds
   10% more users abandoning the page. Additionally, Core Web Vitals are
   Google ranking signals, so poor performance = worse SEO.

Q: Why does performance matter for users?
A: Users expect instant responses (< 100ms feels instant). After 3 seconds,
   53% of mobile users abandon the page. Slow performance also creates
   cognitive friction — users lose flow and trust in the product. It's also
   an accessibility issue: users on slow networks or low-end devices are
   disproportionately affected.

Q: What is perceived vs actual performance?
A: Actual performance is the real time measured in milliseconds. Perceived
   performance is how fast the site *feels* to the user. You can improve
   perceived performance without improving actual performance using techniques
   like skeleton screens, optimistic UI updates, and progressive rendering.
   Both matter, but perceived performance is what users experience directly.

Q: How does performance affect SEO?
A: Since June 2021, Google uses Core Web Vitals (LCP, INP, CLS) as ranking
   signals. Pages meeting "Good" thresholds get a ranking boost. Poor CWV
   scores can result in lower search rankings, reducing organic traffic.

Q: How would you convince a team to prioritize performance?
A: I'd present business data: show how current performance metrics correlate
   with bounce rate and conversion. Use Lighthouse scores and CrUX data to
   show where we stand vs competitors. Frame performance improvements as
   potential revenue increases using industry benchmarks. Then establish a
   performance budget to prevent regression going forward.
