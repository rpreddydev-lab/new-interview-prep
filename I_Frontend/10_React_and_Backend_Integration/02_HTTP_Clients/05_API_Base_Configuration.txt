================================================================
API BASE CONFIGURATION — ENVIRONMENT, VERSIONING & MULTI-API
================================================================

================================================================
1. THE PROBLEM
================================================================

React apps deployed to multiple environments (dev, staging, prod)
need different API base URLs. Hard-coding URLs is a bad practice.

Also, large apps may call multiple APIs (internal, payment, content, etc.)
that need separate Axios instances with different configurations.

================================================================
2. ENVIRONMENT VARIABLES IN VITE & CRA
================================================================

VITE:
  - Variables must start with VITE_
  - Access via: import.meta.env.VITE_VARIABLE_NAME
  - Built into the JS bundle at build time (NOT runtime)
  - .env files supported: .env, .env.development, .env.production, etc.

CREATE REACT APP (CRA):
  - Variables must start with REACT_APP_
  - Access via: process.env.REACT_APP_VARIABLE_NAME
  - Same build-time injection

IMPORTANT: These are NOT server-side environment variables.
They are substituted as string literals at build time.
Never put secrets in them — they are visible in the browser bundle.

FILE: .env.development
  VITE_API_BASE_URL=http://localhost:8080/api
  VITE_WS_URL=ws://localhost:8080/ws
  VITE_TIMEOUT=15000
  VITE_ENV=development

FILE: .env.production
  VITE_API_BASE_URL=https://api.example.com/api
  VITE_WS_URL=wss://api.example.com/ws
  VITE_TIMEOUT=10000
  VITE_ENV=production

FILE: .env.staging
  VITE_API_BASE_URL=https://staging-api.example.com/api
  VITE_WS_URL=wss://staging-api.example.com/ws
  VITE_TIMEOUT=10000
  VITE_ENV=staging

FILE: .env.test (used by Vitest/Jest)
  VITE_API_BASE_URL=http://localhost:8080/api
  VITE_ENV=test

BUILD COMMANDS:
  npm run build               → uses .env.production
  npm run build -- --mode staging → uses .env.staging
  npm run dev                 → uses .env.development

3. API ENDPOINT CONSTANTS
================================================================

Never scatter raw strings like '/api/users' across services.
Centralize in one file:

FILE: src/api/endpoints.js

  const BASE = import.meta.env.VITE_API_BASE_URL;

  export const ENDPOINTS = {
    AUTH: {
      LOGIN:    '/auth/login',
      LOGOUT:   '/auth/logout',
      REFRESH:  '/auth/refresh',
      REGISTER: '/auth/register',
    },
    USERS: {
      BASE:        '/users',
      BY_ID:       (id) => `/users/${id}`,
      AVATAR:      (id) => `/users/${id}/avatar`,
      PREFERENCES: (id) => `/users/${id}/preferences`,
    },
    PRODUCTS: {
      BASE:    '/products',
      BY_ID:   (id) => `/products/${id}`,
      SEARCH:  '/products/search',
      BY_CATEGORY: (cat) => `/products/category/${cat}`,
    },
    ORDERS: {
      BASE:    '/orders',
      BY_ID:   (id) => `/orders/${id}`,
      CANCEL:  (id) => `/orders/${id}/cancel`,
      HISTORY: '/orders/history',
    },
  };

USAGE IN SERVICES:
  import { ENDPOINTS } from '../api/endpoints';

  export const getUser = (id) => apiClient.get(ENDPOINTS.USERS.BY_ID(id));
  export const getProducts = () => apiClient.get(ENDPOINTS.PRODUCTS.BASE);

4. SINGLE API INSTANCE CONFIGURATION (Full)
================================================================

FILE: src/api/axiosConfig.js

  import axios from 'axios';

  const API_BASE_URL = import.meta.env.VITE_API_BASE_URL;

  if (!API_BASE_URL) {
    throw new Error('VITE_API_BASE_URL environment variable is not set.');
  }

  const apiClient = axios.create({
    baseURL: API_BASE_URL,
    timeout: Number(import.meta.env.VITE_TIMEOUT) || 10_000,
    headers: {
      'Content-Type': 'application/json',
      'Accept': 'application/json',
    },
  });

  // Request interceptor
  apiClient.interceptors.request.use(
    (config) => {
      const token = localStorage.getItem('accessToken');
      if (token) config.headers.Authorization = `Bearer ${token}`;
      return config;
    },
    (error) => Promise.reject(error)
  );

  // Response interceptor
  apiClient.interceptors.response.use(
    (response) => response,
    (error) => Promise.reject(error)
  );

  export default apiClient;

5. MULTI-API CONFIGURATION
================================================================

For apps with multiple backends:

FILE: src/api/clients.js

  import axios from 'axios';
  import { attachAuthInterceptors } from './interceptors/authInterceptor';
  import { attachErrorInterceptors } from './interceptors/errorInterceptor';

  // Internal API — authenticated, all interceptors
  const internalApiClient = axios.create({
    baseURL: import.meta.env.VITE_INTERNAL_API_URL,
    timeout: 10_000,
    headers: { 'Content-Type': 'application/json' },
  });
  attachAuthInterceptors(internalApiClient);
  attachErrorInterceptors(internalApiClient);

  // Payment API — different base URL and timeout
  const paymentApiClient = axios.create({
    baseURL: import.meta.env.VITE_PAYMENT_API_URL,
    timeout: 30_000,
    headers: { 'Content-Type': 'application/json' },
  });
  attachAuthInterceptors(paymentApiClient);

  // Public CDN / CMS API — no auth
  const contentApiClient = axios.create({
    baseURL: import.meta.env.VITE_CONTENT_API_URL,
    timeout: 5_000,
  });

  export { internalApiClient, paymentApiClient, contentApiClient };

FILE: src/api/interceptors/authInterceptor.js

  export const attachAuthInterceptors = (client) => {
    client.interceptors.request.use((config) => {
      const token = getAccessToken();
      if (token) config.headers.Authorization = `Bearer ${token}`;
      return config;
    });
  };

6. API VERSIONING IN CONFIGURATION
================================================================

APPROACH 1: Version in baseURL
  const apiClient = axios.create({
    baseURL: 'https://api.example.com/v1',
  });

APPROACH 2: Version in endpoint constants
  export const ENDPOINTS = {
    USERS: { BASE: '/v1/users' },
  };

APPROACH 3: Custom header version
  const apiClient = axios.create({
    baseURL: 'https://api.example.com',
    headers: { 'API-Version': '1' },
  });

APPROACH 4: Multiple versioned clients
  const apiV1 = axios.create({ baseURL: '.../v1' });
  const apiV2 = axios.create({ baseURL: '.../v2' });

  // Use v2 for new features, v1 for legacy
  export const getUsers = () => apiV2.get('/users');
  export const getLegacyOrders = () => apiV1.get('/orders');

7. VITE DEV SERVER PROXY (Eliminates CORS in Development)
================================================================

Instead of configuring CORS on the backend during development,
use Vite's built-in proxy to forward API requests.

FILE: vite.config.js

  import { defineConfig } from 'vite';
  import react from '@vitejs/plugin-react';

  export default defineConfig({
    plugins: [react()],
    server: {
      port: 3000,
      proxy: {
        '/api': {
          target: 'http://localhost:8080',
          changeOrigin: true,
          // Optionally rewrite paths:
          // rewrite: (path) => path.replace(/^\/api/, '')
        },
        '/ws': {
          target: 'ws://localhost:8080',
          ws: true,        // WebSocket proxy
          changeOrigin: true,
        },
      },
    },
  });

With this setup:
  - React runs on http://localhost:3000
  - Requests to http://localhost:3000/api/* are proxied to http://localhost:8080/api/*
  - Browser sees them as same-origin → no CORS preflight
  - .env.development can use: VITE_API_BASE_URL=/api

CRA PROXY (in package.json):
  "proxy": "http://localhost:8080"
  - Only proxies non-GET, non-HTML requests
  - Less configurable than Vite's proxy

8. CONFIG VALIDATION
================================================================

Fail fast if required env vars are missing:

  // src/api/config.js
  const required = [
    'VITE_API_BASE_URL',
    'VITE_WS_URL',
  ];

  required.forEach(key => {
    if (!import.meta.env[key]) {
      throw new Error(`Missing required environment variable: ${key}`);
    }
  });

  export const config = {
    apiBaseUrl: import.meta.env.VITE_API_BASE_URL,
    wsUrl: import.meta.env.VITE_WS_URL,
    timeout: Number(import.meta.env.VITE_TIMEOUT) || 10_000,
    isDevelopment: import.meta.env.DEV,
    isProduction: import.meta.env.PROD,
  };

================================================================
9. INTERVIEW QUESTIONS
================================================================

Q: How do you manage different API URLs for development, staging,
   and production in a React app?
A: Use .env files (.env.development, .env.staging, .env.production)
   with VITE_ or REACT_APP_ prefixed variables. The build tool
   injects the correct values at build time. In axiosConfig,
   use import.meta.env.VITE_API_BASE_URL as the baseURL.

Q: What is the Vite proxy and why is it useful?
A: The Vite dev server proxy forwards requests matching a path prefix
   to a different target (your backend). This makes React and the API
   appear same-origin to the browser, eliminating CORS preflight
   entirely during development without any backend changes.

Q: How do you centralize API endpoint strings?
A: Create an endpoints.js file that exports a constants object with
   all endpoint paths (using functions for dynamic segments like IDs).
   Services import from endpoints.js instead of using raw strings.
   This means changing an endpoint path only requires one file edit.

Q: Why shouldn't you put API keys or secrets in .env files for React?
A: .env variables are injected at build time and become literal strings
   in the JavaScript bundle. Anyone can inspect the bundle and read them.
   Secrets should live only on the server. Use a backend proxy to
   call third-party APIs that require secrets.

Q: How do you configure multiple Axios instances in a large app?
A: Create separate instances with axios.create() for each API, each
   with its own baseURL, timeout, and headers. Attach interceptors
   per-instance (e.g., auth interceptor only on internal APIs).
   Export each instance and use the appropriate one in each service file.
