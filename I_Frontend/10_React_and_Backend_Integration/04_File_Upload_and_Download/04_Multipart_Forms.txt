================================================================
MULTIPART FORMS IN REACT
================================================================

Multipart form data is the encoding used to send files mixed with
regular text fields in a single HTTP request. Understanding this
encoding is essential for any file upload feature.

================================================================
1. WHAT IS MULTIPART/FORM-DATA?
================================================================

Standard form encoding (application/x-www-form-urlencoded) converts
form values to key=value pairs in the request body. It can't carry
binary data.

multipart/form-data splits the request body into multiple parts
separated by a "boundary" string. Each part has its own headers
(Content-Disposition, Content-Type) and body.

Example raw request:
  POST /upload HTTP/1.1
  Content-Type: multipart/form-data; boundary=----FormBoundaryXYZ

  ------FormBoundaryXYZ
  Content-Disposition: form-data; name="title"

  My Document
  ------FormBoundaryXYZ
  Content-Disposition: form-data; name="file"; filename="report.pdf"
  Content-Type: application/pdf

  <binary PDF data here>
  ------FormBoundaryXYZ--

The browser/Axios sets the Content-Type header with the correct
boundary automatically when you pass a FormData object.

2. FORMDATA API
================================================================

  // Creating FormData
  const formData = new FormData();

  // Append a text field
  formData.append('username', 'alice');

  // Append a file
  formData.append('avatar', fileInput.files[0]);

  // Append with custom filename
  formData.append('report', blob, 'custom-name.pdf');

  // Check if key exists
  formData.has('username'); // true

  // Get a value
  formData.get('username'); // 'alice'

  // Get all values for a key (e.g., multiple files with same key)
  formData.getAll('files');

  // Delete a key
  formData.delete('username');

  // Iterate
  for (const [key, value] of formData.entries()) {
    console.log(key, value);
  }

⚠️  NEVER manually set Content-Type to multipart/form-data!
    Axios must set it (with the boundary) automatically.
    Setting it manually will break the boundary and the server
    will reject the request.

3. MIXING FILES AND FIELDS
================================================================

  function SubmitDocumentForm() {
    const [title, setTitle] = useState('');
    const [description, setDescription] = useState('');
    const [file, setFile] = useState(null);
    const [tags, setTags] = useState([]);

    const handleSubmit = async (e) => {
      e.preventDefault();

      const formData = new FormData();
      formData.append('title', title);
      formData.append('description', description);
      formData.append('file', file);

      // Multiple values for same key (array)
      tags.forEach(tag => formData.append('tags', tag));

      // Nested data — must JSON-stringify
      const metadata = { visibility: 'public', category: 'finance' };
      formData.append('metadata', JSON.stringify(metadata));

      await apiClient.post('/documents', formData);
    };

    return (
      <form onSubmit={handleSubmit}>
        <input value={title} onChange={e => setTitle(e.target.value)} placeholder="Title" />
        <textarea value={description} onChange={e => setDescription(e.target.value)} />
        <input type="file" onChange={e => setFile(e.target.files[0])} />
        <button type="submit">Submit</button>
      </form>
    );
  }

SPRING BOOT BACKEND:
  @PostMapping("/documents")
  public ResponseEntity<DocumentDto> createDocument(
      @RequestParam("title") String title,
      @RequestParam("description") String description,
      @RequestParam("file") MultipartFile file,
      @RequestParam(value = "tags", required = false) List<String> tags,

  ) {
      // Parse the JSON string back to an object
      Metadata metadata = objectMapper.readValue(metadataJson, Metadata.class);

  ALTERNATIVE — use @ModelAttribute with a DTO:
  @PostMapping(consumes = MediaType.MULTIPART_FORM_DATA_VALUE)
  public ResponseEntity<DocumentDto> createDocument(
      @ModelAttribute CreateDocumentRequest request
  ) {
      // request.getFile() is MultipartFile
      // request.getTitle() etc. are bound automatically
  }

  public class CreateDocumentRequest {
      private String title;
      private String description;
      private MultipartFile file;
      private List<String> tags;
      // getters/setters
  }

4. REACT HOOK FORM + FILE UPLOAD
================================================================

  import { useForm } from 'react-hook-form';

  function HookFormUpload() {
    const {
      register,
      handleSubmit,
      formState: { errors },
    } = useForm();

    const onSubmit = async (data) => {
      const formData = new FormData();
      formData.append('title', data.title);
      formData.append('file', data.file[0]); // file input returns FileList

      await apiClient.post('/documents', formData);
    };

    return (
      <form onSubmit={handleSubmit(onSubmit)}>
        <input
          {...register('title', { required: 'Title is required' })}
          placeholder="Title"
        />
        {errors.title && <span>{errors.title.message}</span>}

        <input
          type="file"
          {...register('file', {
            required: 'File is required',
            validate: {
              maxSize: (files) =>
                files[0]?.size < 5 * 1024 * 1024 || 'Max size is 5MB',
              acceptedTypes: (files) =>
                ['image/jpeg', 'image/png', 'application/pdf'].includes(
                  files[0]?.type
                ) || 'Only JPEG, PNG, or PDF allowed',
            },
          })}
        />
        {errors.file && <span>{errors.file.message}</span>}

        <button type="submit">Submit</button>
      </form>
    );
  }

5. SENDING JSON + FILE (TWO APPROACHES)
================================================================

APPROACH A — Send file and JSON as separate parts:

  const formData = new FormData();
  formData.append('file', file);
  formData.append('data', new Blob(
    [JSON.stringify({ title, tags })],
    { type: 'application/json' }
  ));

  SPRING BOOT:
  @PostMapping(consumes = MediaType.MULTIPART_FORM_DATA_VALUE)
  public ResponseEntity<?> create(
      @RequestPart("file") MultipartFile file,
      @RequestPart("data") CreateRequest data
  ) { ... }

APPROACH B — Upload file first, then send metadata JSON:

  Step 1: Upload the file, get back a file reference/ID
    const { data: { fileId } } = await apiClient.post('/files/upload', formData);

  Step 2: Send JSON with the file reference
    await apiClient.post('/documents', {
      title,
      tags,
      fileId, // reference to the uploaded file
    }, {
      headers: { 'Content-Type': 'application/json' }
    });

  SPRING BOOT Step 2:
  @PostMapping("/documents")
  public ResponseEntity<DocumentDto> create(@RequestBody CreateDocumentRequest req) {
      // Fetch file by req.getFileId() from temp storage
  }

Approach B is cleaner — it keeps file upload and metadata submission
separate, making each independently retryable.

================================================================
6. NATIVE HTML FORM VS JAVASCRIPT FORMDATA
================================================================

NATIVE FORM SUBMIT (no JavaScript):
  <form action="/upload" method="POST" enctype="multipart/form-data">
    <input type="text" name="title" />
    <input type="file" name="file" />
    <button type="submit">Upload</button>
  </form>

  - Causes a full page reload
  - No progress tracking
  - No custom headers (can't add Authorization)
  - Not suitable for SPAs with JWT auth

JAVASCRIPT FORMDATA (Axios/Fetch):
  - No page reload
  - Full control over request (headers, progress, cancel)
  - Can inject auth headers
  - Required for React SPAs

Always use the JavaScript approach in React apps.

================================================================
7. FORM SUBMIT WITH MULTIPART — EDGE CASES
================================================================

1. Empty file input:
   formData.append('file', '') sends an empty string, not a file.
   Always validate that file exists before appending.

2. File vs Blob:
   Both work with FormData.append(). Blob is useful for
   programmatically created content (canvas image, JSON export).

3. Array fields in FormData vs URL-encoded:
   formData.append('tags', 'a'); formData.append('tags', 'b');
   — Spring Boot reads as List<String> tags automatically
   — URL-encoded: tags=a&tags=b (same behavior)

4. Date fields:
   Dates must be sent as strings. Use ISO format:
   formData.append('scheduledAt', new Date().toISOString());

5. Boolean fields:
   formData.append('published', true) — but FormData converts to
   the string "true". The backend must parse the string.

6. Large metadata objects:
   Don't try to model complex objects in FormData keys. Use the
   @RequestPart approach with a JSON blob, or Approach B above.

8. SPRING BOOT MULTIPART CONFIGURATION
================================================================

application.yml:
  spring:
    servlet:
      multipart:
        enabled: true
        max-file-size: 50MB
        max-request-size: 55MB  # must be >= max-file-size
        file-size-threshold: 2KB  # spool to disk if bigger

For multiple files at once on the backend:
  @PostMapping("/upload-multiple")
  public ResponseEntity<List<String>> uploadMultiple(
      @RequestParam("files") List<MultipartFile> files
  ) {
      return ResponseEntity.ok(
          files.stream().map(this::saveFile).toList()
      );
  }

================================================================
9. INTERVIEW QUESTIONS
================================================================

Q: Why must you NOT manually set Content-Type to multipart/form-data?
A: When Axios constructs the multipart body, it generates a unique
   boundary string and includes it in the Content-Type header:
   Content-Type: multipart/form-data; boundary=----XXXX.
   If you manually set the header, you overwrite the boundary.
   The server then can't parse the parts, resulting in a 400 error.

Q: How do you send both a file and JSON data in one request?
A: Two approaches: (1) Use FormData — append the file and JSON-stringify
   the object into a Blob part with type application/json, then use
   @RequestPart on the Spring Boot side. (2) Two-step: upload file first
   to get a fileId, then POST JSON with that fileId. Approach 2 is
   cleaner and more resilient.

Q: How does FormData handle arrays (multiple values for same key)?
A: Call formData.append('tags', value) multiple times with the same
   key. Spring Boot reads @RequestParam("tags") List<String> and
   automatically collects all values.

Q: What is the difference between enctype="multipart/form-data" and
   application/x-www-form-urlencoded?
A: url-encoded sends key=value pairs with percent-encoding (no binary).
   multipart/form-data splits the body into parts with boundaries,
   allowing binary file data alongside text fields. Use multipart
   whenever you are uploading files.

Q: How do you use React Hook Form with file inputs?
A: Register the file input normally with register(). File inputs
   return a FileList (array-like), not a string. In onSubmit, access
   data.file[0] to get the actual File object. Add validate functions
   for size and type checks. Construct FormData manually in onSubmit
   before calling apiClient.
