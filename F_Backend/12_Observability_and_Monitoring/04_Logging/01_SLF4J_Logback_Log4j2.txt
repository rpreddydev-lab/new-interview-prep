LOGGING — SLF4J, LOGBACK, LOG4J2, STRUCTURED LOGGING
======================================================

=== SLF4J (Simple Logging Facade for Java) ===

- Logging facade — abstracts the underlying logging implementation
- Code against SLF4J API; switch implementation (Logback, Log4j2) without code changes
- Like JDBC for databases, but for logging

Usage:
  import org.slf4j.Logger;
  import org.slf4j.LoggerFactory;

  public class OrderService {
      private static final Logger log = LoggerFactory.getLogger(OrderService.class);
      // Using Lombok: @Slf4j annotation creates 'log' field automatically

      public void process(Order order) {
          log.debug("Processing order: {}", order.getId());
          log.info("Order {} received for customer {}", order.getId(), order.getCustomerId());
          log.warn("Order {} taking too long", order.getId());
          log.error("Failed to process order {}", order.getId(), exception);
      }
  }

Always use parameterized logging (log.info("{}", val)) not string concatenation
(log.info("" + val)) — avoids String construction when log level disabled.

=== LOGBACK (Spring Boot Default) ===

Spring Boot uses Logback by default (via spring-boot-starter-logging).

logback-spring.xml in src/main/resources:
  <configuration>
    <include resource="org/springframework/boot/logging/logback/defaults.xml"/>

    <appender name="CONSOLE" class="ch.qos.logback.core.ConsoleAppender">
      <encoder class="net.logstash.logback.encoder.LogstashEncoder"/>
    </appender>

    <appender name="FILE" class="ch.qos.logback.core.rolling.RollingFileAppender">
      <file>logs/app.log</file>
      <rollingPolicy class="ch.qos.logback.core.rolling.TimeBasedRollingPolicy">
        <fileNamePattern>logs/app.%d{yyyy-MM-dd}.%i.gz</fileNamePattern>
        <maxHistory>30</maxHistory>
        <totalSizeCap>1GB</totalSizeCap>
      </rollingPolicy>
      <encoder class="net.logstash.logback.encoder.LogstashEncoder"/>
    </appender>

    <root level="INFO">
      <appender-ref ref="CONSOLE"/>
      <appender-ref ref="FILE"/>
    </root>

    <logger name="com.myapp.order" level="DEBUG"/>
  </configuration>

=== LOG4J2 ===

- Higher performance than Logback (async logging via LMAX Disruptor)
- More configuration options
- Requires excluding spring-boot-starter-logging and adding log4j2 starter

When to prefer Log4j2:
- Very high-throughput applications
- Async logging requirement
- Complex logging routing needs

Note: Log4Shell vulnerability (CVE-2021-44228) in Log4j2 2.x (< 2.15) —
always use latest patched version.

=== STRUCTURED LOGGING (JSON) ===

WHY: In microservices + log aggregation (ELK, Splunk, CloudWatch Logs Insights),
plain text is hard to parse. JSON logs are machine-readable and filterable.

Structured log output:
  {
    "timestamp": "2024-01-15T10:30:45.123Z",
    "level": "ERROR",
    "logger": "com.myapp.OrderService",
    "message": "Failed to process order",
    "traceId": "abc123",
    "spanId": "def456",
    "orderId": "ORD-789",
    "customerId": "CUST-456",
    "exception": "PaymentGatewayTimeoutException"
  }

Setup with logstash-logback-encoder:
  <dependency>
    <groupId>net.logstash.logback</groupId>
    <artifactId>logstash-logback-encoder</artifactId>
    <version>7.4</version>
  </dependency>

  Encoder: <encoder class="net.logstash.logback.encoder.LogstashEncoder"/>

Adding custom fields to logs:
  // MDC (Mapped Diagnostic Context) — per-thread key-value pairs
  MDC.put("orderId", order.getId());
  log.info("Processing order");
  MDC.remove("orderId");

  // Or use try-with-resources:
  try (MDC.MDCCloseable closeable = MDC.putCloseable("orderId", id)) {
      log.info("Processing");
  }

  // Spring: trace ID auto-added to MDC by Micrometer Tracing

=== LOG LEVELS — BEST PRACTICES ===

TRACE: Very detailed — method entry/exit, loop iterations (rarely used in prod)
DEBUG: Diagnostic info — request params, business logic decisions
INFO:  Significant business events — order placed, payment processed, service started
WARN:  Recoverable issues — slow DB query, retry attempt, deprecated usage
ERROR: Failures requiring attention — exception in service, external API down

Production: INFO level for app, WARN for third-party libs
  logging.level.root: WARN
  logging.level.com.myapp: INFO
  logging.level.org.springframework.web: WARN

=== LOGGING ANTI-PATTERNS ===

❌ Logging sensitive data (passwords, credit card numbers, PII)
❌ String concatenation in log statements (use {})
❌ Logging in tight loops (performance killer)
❌ Catching and swallowing exceptions without logging
❌ Using System.out.println instead of logger
❌ Not including context (what order? which user? which transaction?)
❌ Same message at multiple log levels
❌ ERROR for expected business exceptions (use WARN)

=== LOGGING IN PRODUCTION ===

Log rotation: essential — prevent disk fill
  - TimeBasedRollingPolicy: roll daily
  - SizeAndTimeBasedRollingPolicy: roll by size + time
  - maxHistory: keep N days
  - totalSizeCap: overall disk limit

Async logging (critical for high throughput):
  <appender name="ASYNC" class="ch.qos.logback.classic.AsyncAppender">
    <appender-ref ref="FILE"/>
    <queueSize>1024</queueSize>
    <discardingThreshold>0</discardingThreshold>
  </appender>

  LMAX Disruptor (Log4j2): add log4j2-async dependency — 10x faster than sync
