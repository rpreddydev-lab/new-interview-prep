DISTRIBUTED TRACING — OPENTELEMETRY, JAEGER, ZIPKIN
=====================================================

=== WHY DISTRIBUTED TRACING? ===

In microservices, a single user request may touch 10+ services.
When something is slow or fails:
- Which service is responsible?
- Where exactly in the call chain is time being spent?
- What was the full path of the request?

Logs and metrics alone can't answer these — you need tracing.

=== CORE CONCEPTS ===

Trace:
- Represents the entire journey of a single request across all services
- Identified by a unique trace ID (propagated via headers)

Span:
- A single unit of work within a trace
- Has: spanId, parentSpanId, operation name, start time, duration, status, tags
- Root span: the first span in a trace (no parent)
- Child spans: created for each downstream call (DB, HTTP, Kafka)

Span Context:
- trace ID + span ID + flags — propagated in HTTP headers
- Formats: B3 (Zipkin), W3C TraceContext (OpenTelemetry standard)

=== OPENTELEMETRY (OTel) ===

OpenTelemetry is the CNCF standard for telemetry:
- Unified SDK for metrics, logs, and traces
- Vendor-neutral — works with Jaeger, Zipkin, Datadog, AWS X-Ray
- Replacing Zipkin and Sleuth in Spring Boot 3.x

Components:
- OTel API: interfaces for instrumenting code
- OTel SDK: implementation of the API
- OTel Collector: receives, processes, and exports telemetry data
- OTel Agent: Java agent for zero-code instrumentation

=== SPRING BOOT 3 TRACING SETUP ===

Dependencies:
  <dependency>
    <groupId>io.micrometer</groupId>
    <artifactId>micrometer-tracing-bridge-otel</artifactId>
  </dependency>
  <dependency>
    <groupId>io.opentelemetry.instrumentation</groupId>
    <artifactId>opentelemetry-spring-boot-starter</artifactId>
  </dependency>
  <!-- Export to Jaeger/Zipkin -->
  <dependency>
    <groupId>io.opentelemetry</groupId>
    <artifactId>opentelemetry-exporter-otlp</artifactId>
  </dependency>

application.yml:
  management:
    tracing:
      sampling:
        probability: 1.0   # sample all requests (use 0.1 in production = 10%)
  spring:
    application:
      name: order-service

OTel auto-instruments:
- All incoming HTTP requests (Spring MVC, WebFlux)
- All outgoing HTTP calls (RestTemplate, WebClient, Feign)
- JPA queries
- Kafka producer/consumer
- Scheduled tasks

=== TRACE PROPAGATION ===

Spring Boot 3 uses W3C TraceContext by default:
  HTTP header: traceparent: 00-{traceId}-{spanId}-{flags}

B3 format (Zipkin legacy):
  HTTP headers: X-B3-TraceId, X-B3-SpanId, X-B3-Sampled

When a service receives a request with traceparent header:
1. It extracts the trace ID and parent span ID
2. Creates a new child span
3. Propagates the trace context to downstream calls

=== CUSTOM SPANS ===

@Service
public class OrderService {

    private final Tracer tracer;   // io.micrometer.tracing.Tracer

    public Order processOrder(OrderRequest request) {
        Span span = tracer.nextSpan().name("process-order").start();
        try (Tracer.SpanInScope ws = tracer.withSpan(span.start())) {
            span.tag("orderId", request.getId());
            span.tag("customerId", request.getCustomerId());
            // ... processing
            return order;
        } catch (Exception e) {
            span.error(e);
            throw e;
        } finally {
            span.end();
        }
    }
}

=== JAEGER ===

- Open-source distributed tracing backend
- Stores and visualizes traces
- Good for self-hosted deployments

Local setup:
  docker run -d --name jaeger \
    -p 16686:16686 \   # UI
    -p 4317:4317 \     # OTLP gRPC
    -p 4318:4318 \     # OTLP HTTP
    jaegertracing/all-in-one:latest

Configure Spring Boot to export to Jaeger:
  otel.exporter.otlp.endpoint: http://jaeger:4317

=== ZIPKIN ===

- Older distributed tracing system (pre-OTel standard)
- Still widely used
- Spring Cloud Sleuth (deprecated in Boot 3.x) used Zipkin

Spring Boot 3 Zipkin export:
  <dependency>
    <groupId>io.micrometer</groupId>
    <artifactId>micrometer-tracing-reporter-wavefront</artifactId>
  </dependency>
  management.zipkin.tracing.endpoint: http://zipkin:9411/api/v2/spans

=== LOG-TRACE CORRELATION ===

Spring Boot 3 auto-injects trace ID into MDC:
  logging.pattern.level: "%5p [${spring.application.name},%X{traceId},%X{spanId}]"

Log output: INFO [order-service,abc123traceId,def456spanId] OrderService - Processing order

This enables: given a trace ID from Jaeger, find all related log lines in Kibana/ELK.

=== SAMPLING STRATEGIES ===

Always-on sampling: sample every request (only for dev/test)
Probabilistic: sample N% of requests (e.g., 10%)
Rate-limiting: sample up to N traces/second
Tail-based: decide after seeing the whole trace (export errors always)

Production recommendation:
- Sample 1-10% of healthy traffic
- Always sample error traces (tail-based sampling)
- Always sample slow traces (> threshold)
