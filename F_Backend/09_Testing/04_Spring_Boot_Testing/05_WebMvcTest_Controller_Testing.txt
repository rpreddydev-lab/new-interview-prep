================================================================
SPRING BOOT TESTING — @WebMvcTest CONTROLLER TESTING
Complete Interview Preparation Guide
================================================================

1. WHAT IS @WebMvcTest?
================================================================

@WebMvcTest is a test slice for testing the WEB LAYER ONLY.

What it loads:
  ✅ @Controller, @RestController
  ✅ @ControllerAdvice, @ExceptionHandler
  ✅ @JsonComponent
  ✅ Filter, WebMvcConfigurer, HandlerInterceptor
  ✅ @Converter, @Formatter
  ✅ MockMvc (auto-configured)
  ✅ Spring Security (if on classpath)

What it does NOT load:
  ❌ @Service, @Component
  ❌ @Repository
  ❌ Database / JPA / Hibernate
  ❌ Messaging (Kafka, RabbitMQ)

Dependencies of the controller must be provided via @MockBean.

COMPARISON: @WebMvcTest vs @SpringBootTest + @AutoConfigureMockMvc
  
  @WebMvcTest:
    → Only web layer: very fast (< 1 second typically)
    → Controller dependencies MUST be @MockBean'd
    → Best for: unit-style controller tests
  
  @SpringBootTest + @AutoConfigureMockMvc:
    → Full context: slower
    → Real service and repository beans
    → Best for: integration tests through HTTP layer

2. BASIC SETUP
================================================================

  @WebMvcTest(UserController.class)
  class UserControllerTest {
      
      @Autowired MockMvc mockMvc;
      @Autowired ObjectMapper objectMapper;
      
      @MockBean UserService userService;           // mandatory
      @MockBean JwtTokenValidationService jwtSvc;  // if controller uses JWT
      
      @Test
      void getUser_shouldReturnOk() throws Exception {
          User user = new User("user-1", "alice@test.com", "Alice");
          when(userService.findById("user-1")).thenReturn(user);
          
          mockMvc.perform(get("/users/user-1"))
              .andExpect(status().isOk())
              .andExpect(jsonPath("$.email").value("alice@test.com"));
      }
  }

TIP: When no controller is specified, @WebMvcTest loads ALL controllers.
This is useful for verifying that the whole web layer wires up correctly,
but usually you specify one controller for focused tests:
  @WebMvcTest  // loads all controllers
  @WebMvcTest(UserController.class)  // focused

3. TESTING REQUEST MAPPING AND PATH VARIABLES
================================================================

CONTROLLER:
  @RestController
  @RequestMapping("/api/v1/products")
  class ProductController {
      
      private final ProductService productService;
      
      @GetMapping("/{id}")
      ResponseEntity<ProductResponse> getById(@PathVariable String id) {
          Product product = productService.findById(id);
          return ResponseEntity.ok(ProductResponse.from(product));
      }
      
      @GetMapping
      ResponseEntity<Page<ProductResponse>> search(
          @RequestParam(required = false) String category,
          @RequestParam(defaultValue = "0") int page,
          @RequestParam(defaultValue = "20") int size
      ) { ... }
      
      @PostMapping
      ResponseEntity<ProductResponse> create(
          @RequestBody @Valid CreateProductRequest request
      ) {
          Product created = productService.create(request);
          URI location = URI.create("/api/v1/products/" + created.getId());
          return ResponseEntity.created(location).body(ProductResponse.from(created));
      }
  }

TESTS:
  @WebMvcTest(ProductController.class)
  class ProductControllerTest {
      
      @Autowired MockMvc mockMvc;
      @Autowired ObjectMapper objectMapper;
      @MockBean ProductService productService;
      
      @Test
      void getById_shouldReturn200WithProduct() throws Exception {
          Product product = new Product("p-1", "Laptop", "Electronics", new BigDecimal("999.99"));
          when(productService.findById("p-1")).thenReturn(product);
          
          mockMvc.perform(get("/api/v1/products/p-1"))
              .andExpect(status().isOk())
              .andExpect(jsonPath("$.id").value("p-1"))
              .andExpect(jsonPath("$.name").value("Laptop"))
              .andExpect(jsonPath("$.category").value("Electronics"))
              .andExpect(jsonPath("$.price").value(999.99));
      }
      
      @Test
      void search_shouldPassQueryParamsToService() throws Exception {
          Page<Product> page = new PageImpl<>(List.of(product1, product2));
          when(productService.search(eq("Electronics"), any(Pageable.class)))
              .thenReturn(page);
          
          mockMvc.perform(get("/api/v1/products")
                  .param("category", "Electronics")
                  .param("page", "0")
                  .param("size", "20"))
              .andExpect(status().isOk())
              .andExpect(jsonPath("$.content", hasSize(2)))
              .andExpect(jsonPath("$.totalElements").value(2));
          
          verify(productService).search(eq("Electronics"), 
              argThat(p -> p.getPageNumber() == 0 && p.getPageSize() == 20));
      }
      
      @Test
      void create_shouldReturn201WithLocationHeader() throws Exception {
          CreateProductRequest request = new CreateProductRequest(
              "Laptop Pro", "Electronics", new BigDecimal("1499.99"), 50
          );
          Product created = new Product("p-new", "Laptop Pro", "Electronics", new BigDecimal("1499.99"));
          when(productService.create(any(CreateProductRequest.class))).thenReturn(created);
          
          mockMvc.perform(post("/api/v1/products")
                  .contentType(MediaType.APPLICATION_JSON)
                  .content(objectMapper.writeValueAsString(request)))
              .andExpect(status().isCreated())
              .andExpect(header().string("Location", endsWith("/api/v1/products/p-new")));
      }
  }

5. TESTING EXCEPTION HANDLING
================================================================

  // ControllerAdvice:
  @RestControllerAdvice
  class GlobalExceptionHandler {
      
      @ExceptionHandler(ProductNotFoundException.class)
      @ResponseStatus(HttpStatus.NOT_FOUND)
      Map<String, String> handleNotFound(ProductNotFoundException ex) {
          return Map.of("error", "NOT_FOUND", "message", ex.getMessage());
      }
      
      @ExceptionHandler(DuplicateProductException.class)
      @ResponseStatus(HttpStatus.CONFLICT)
      Map<String, String> handleDuplicate(DuplicateProductException ex) {
          return Map.of("error", "CONFLICT", "message", ex.getMessage());
      }
  }
  
  // Tests:
  @Test
  void getById_shouldReturn404WhenProductNotFound() throws Exception {
      when(productService.findById("bad-id"))
          .thenThrow(new ProductNotFoundException("bad-id"));
      
      mockMvc.perform(get("/api/v1/products/bad-id"))
          .andExpect(status().isNotFound())
          .andExpect(jsonPath("$.error").value("NOT_FOUND"))
          .andExpect(jsonPath("$.message").value(containsString("bad-id")));
  }
  
  @Test
  void create_shouldReturn409WhenDuplicate() throws Exception {
      CreateProductRequest req = new CreateProductRequest("Laptop", "Electronics", 
          new BigDecimal("999"), 10);
      
      when(productService.create(any()))
          .thenThrow(new DuplicateProductException("Laptop already exists"));
      
      mockMvc.perform(post("/api/v1/products")
              .contentType(MediaType.APPLICATION_JSON)
              .content(objectMapper.writeValueAsString(req)))
          .andExpect(status().isConflict())
          .andExpect(jsonPath("$.error").value("CONFLICT"));
  }

10. TESTING RESPONSE STRUCTURE — MvcResult
================================================================

For complex assertions, extract the full response:
  @Test
  void searchProducts_shouldReturnPaginatedResult() throws Exception {
      Page<Product> mockPage = new PageImpl<>(
          List.of(product1, product2),
          PageRequest.of(0, 10),
          2
      );
      when(productService.search(any(), any(Pageable.class))).thenReturn(mockPage);
      
      MvcResult result = mockMvc.perform(get("/api/v1/products")
              .param("page", "0")
              .param("size", "10"))
          .andExpect(status().isOk())
          .andReturn();
      
      String body = result.getResponse().getContentAsString();
      
      // Use Jackson for complex object mapping
      @SuppressWarnings("unchecked")
      Map<String, Object> responseMap = objectMapper.readValue(body, Map.class);
      
      assertEquals(2, ((List<?>) responseMap.get("content")).size());
      assertEquals(2, responseMap.get("totalElements"));
      assertFalse((Boolean) responseMap.get("last"));
  }

11. INTERVIEW QUESTIONS
================================================================

Q: What is @WebMvcTest and what does it load?
A: @WebMvcTest is a Spring Boot test slice that loads only the web layer:
   @Controller, @ControllerAdvice, Filters, WebMvcConfigurer.
   It auto-configures MockMvc and Spring Security (if present).
   Services and repositories are NOT loaded — must be @MockBean'd.

Q: When would you prefer @WebMvcTest over @SpringBootTest?
A: @WebMvcTest is faster (< 1 second) and focused on the controller.
   Use it for testing request/response mapping, validation, exception handling,
   and security annotations without loading the full application.
   Use @SpringBootTest when you need real service/repository behavior.

Q: How do you handle Spring Security in @WebMvcTest?
A: Spring Security is auto-configured in @WebMvcTest. Use @WithMockUser for
   simple user roles, or .with(user("name").roles("ROLE")) per request.
   You may need to @Import your SecurityConfig or @MockBean security-related beans.

Q: What happens to @ControllerAdvice in @WebMvcTest?
A: @ControllerAdvice is loaded automatically in @WebMvcTest. This means
   your exception handling and validation error handling IS tested — you
   can verify the HTTP status and response body for exceptions.

Q: How do you test a controller method that has @Valid on the request body?
A: Send a request with invalid data (e.g., blank required field). The controller
   will reject it with 400 Bad Request before even calling the service.
   Use verify(service, never()).method(any()) to confirm the service wasn't called.

Q: How do you test that a controller sets the correct Location header?
A: Use .andExpect(header().string("Location", endsWith("/resource/id")));
   The controller should return ResponseEntity.created(uri).body(dto).
