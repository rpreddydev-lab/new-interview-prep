INTEGRATION TESTING — TESTCONTAINERS
Complete Interview Preparation Guide
================================================================

1. WHAT IS TESTCONTAINERS?
================================================================

Testcontainers is a Java library that provides REAL Docker containers
for use in tests. It programmatically starts Docker containers before
your tests and tears them down afterwards.

WHY use Testcontainers instead of H2/embedded databases?
  - Real database → no compatibility gaps (JSON, arrays, procedures)
  - Tests match production environment exactly
  - Works for ANY Docker image: PostgreSQL, MySQL, Kafka, Redis, MongoDB, etc.
  - Containers start on a random port → no port conflicts

REQUIREMENT: Docker Desktop (or Docker Engine) must be running.

3. BASIC POSTGRESQL SETUP
================================================================

  @DataJpaTest
  @AutoConfigureTestDatabase(replace = Replace.NONE)  // disable H2 replacement
  @Testcontainers
  class UserRepositoryTest {
      
      @Container
      static PostgreSQLContainer<?> postgres = new PostgreSQLContainer<>("postgres:15")
          .withDatabaseName("testdb")
          .withUsername("testuser")
          .withPassword("testpass");
      
      @DynamicPropertySource
      static void configureDataSource(DynamicPropertyRegistry registry) {
          registry.add("spring.datasource.url", postgres::getJdbcUrl);
          registry.add("spring.datasource.username", postgres::getUsername);
          registry.add("spring.datasource.password", postgres::getPassword);
          registry.add("spring.datasource.driver-class-name",
              () -> "org.postgresql.Driver");
      }
      
      @Autowired UserRepository userRepository;
      @Autowired TestEntityManager entityManager;
      
      @Test
      void shouldPersistUser() {
          User user = entityManager.persistAndFlush(
              new User(null, "alice@test.com", "Alice")
          );
          
          Optional<User> found = userRepository.findByEmail("alice@test.com");
          
          assertTrue(found.isPresent());
          assertEquals(user.getId(), found.get().getId());
      }
  }

4. CONTAINER LIFECYCLE STRATEGIES
================================================================

STRATEGY 1: @Container as static field (shared per test CLASS)
  @Testcontainers
  class MyTest {
      
      @Container
      static PostgreSQLContainer<?> pg = new PostgreSQLContainer<>("postgres:15");
      // ↑ Starts ONCE per test class, shared between all tests in class
      // Container lifecycle: startClass → allTests → stopClass
  }

STRATEGY 2: @Container as instance field (new container per TEST METHOD)
  @Testcontainers
  class MyTest {
      
      @Container
      PostgreSQLContainer<?> pg = new PostgreSQLContainer<>("postgres:15");
      // ↑ New container started for EACH test method — very slow!
      // Use only if tests truly need fresh containers
  }

STRATEGY 3: Static container (NO auto-lifecycle) — shared across CLASSES
  // Declare in a central place:
  public class SharedContainers {
      
      public static final PostgreSQLContainer<?> POSTGRES = 
          new PostgreSQLContainer<>("postgres:15")
              .withReuse(true);
      
      static {
          POSTGRES.start();  // starts once per JVM lifecycle
      }
  }
  
  // Use in multiple test classes:
  @DataJpaTest
  @AutoConfigureTestDatabase(replace = NONE)
  class UserRepositoryTest {
      
      @DynamicPropertySource
      static void props(DynamicPropertyRegistry r) {
          r.add("spring.datasource.url", SharedContainers.POSTGRES::getJdbcUrl);
          r.add("spring.datasource.username", SharedContainers.POSTGRES::getUsername);
          r.add("spring.datasource.password", SharedContainers.POSTGRES::getPassword);
      }
  }

STRATEGY 4: Ryuk-free reuse (.withReuse(true))
  @Container
  static PostgreSQLContainer<?> pg = new PostgreSQLContainer<>("postgres:15")
      .withReuse(true);
  // Container is NOT stopped after the test class — Testcontainers reuses it
  // Requires: ~/.testcontainers.properties → testcontainers.reuse.enable=true
  // Great for local dev; reset programmatically between runs

5. MULTIPLE CONTAINERS — DIFFERENT SERVICES
================================================================

  @SpringBootTest
  @Testcontainers
  @ActiveProfiles("test")
  class FullStackIT {
      
      @Container
      static PostgreSQLContainer<?> postgres = 
          new PostgreSQLContainer<>("postgres:15");
      
      @Container
      static GenericContainer<?> redis = 
          new GenericContainer<>("redis:7-alpine")
              .withExposedPorts(6379);
      
      @Container
      static KafkaContainer kafka = 
          new KafkaContainer(DockerImageName.parse("confluentinc/cp-kafka:7.4.0"));
      
      @DynamicPropertySource
      static void configureAll(DynamicPropertyRegistry r) {
          // PostgreSQL
          r.add("spring.datasource.url", postgres::getJdbcUrl);
          r.add("spring.datasource.username", postgres::getUsername);
          r.add("spring.datasource.password", postgres::getPassword);
          
          // Redis
          r.add("spring.redis.host", redis::getHost);
          r.add("spring.redis.port", () -> redis.getMappedPort(6379));
          
          // Kafka
          r.add("spring.kafka.bootstrap-servers", kafka::getBootstrapServers);
      }
      
      @Autowired UserService userService;
      @Autowired OrderService orderService;
      
      @Test
      void endToEndOrderFlow() { ... }
  }

6. GENERIC CONTAINER — ANY DOCKER IMAGE
================================================================

  // Any Docker image works:
  GenericContainer<?> mailhog = new GenericContainer<>("mailhog/mailhog")
      .withExposedPorts(1025, 8025)  // SMTP and HTTP UI
      .waitingFor(Wait.forHttp("/").forPort(8025));
  
  // ElasticSearch
  GenericContainer<?> elastic = new GenericContainer<>(
          DockerImageName.parse("elasticsearch:8.11.0"))
      .withEnv("discovery.type", "single-node")
      .withEnv("xpack.security.enabled", "false")
      .withExposedPorts(9200)
      .waitingFor(Wait.forHttp("/_cluster/health"));
  
  // MongoDB
  @Container
  static MongoDBContainer mongo = new MongoDBContainer("mongo:6.0");
  
  // MySQL
  @Container
  static MySQLContainer<?> mysql = new MySQLContainer<>("mysql:8.0")
      .withDatabaseName("testdb")
      .withUsername("user")
      .withPassword("pass");

7. WAIT STRATEGIES — CONTAINER READINESS
================================================================

Testcontainers needs to know when the container is READY:

  // HTTP health check (most common)
  .waitingFor(Wait.forHttp("/health").forStatusCode(200))
  
  // Log message detection
  .waitingFor(Wait.forLogMessage(".*Started.*\\n", 1))
  
  // Port is open
  .waitingFor(Wait.forListeningPort())
  
  // Custom wait (multiple conditions)
  .waitingFor(new WaitAllStrategy()
      .withStrategy(Wait.forListeningPort())
      .withStrategy(Wait.forLogMessage(".*ready.*\\n", 1)));
  
  // No wait (the container starts fast enough)
  .waitingFor(Wait.defaultWaitStrategy())
  
  // With timeout override:
  .waitingFor(Wait.forHttp("/health")
      .withStartupTimeout(Duration.ofMinutes(2)))

8. EXECUTING COMMANDS INSIDE CONTAINER
================================================================

  @Test
  void shouldRunPsqlInsideContainer() throws Exception {
      Container.ExecResult result = postgres.execInContainer(
          "psql", "-U", "testuser", "-d", "testdb",
          "-c", "SELECT COUNT(*) FROM users"
      );
      
      assertEquals(0, result.getExitCode());
      assertTrue(result.getStdout().contains("count"));
  }

9. TESTCONTAINERS SPRING BOOT SUPPORT (3.x)
================================================================

Spring Boot 3.1+ has built-in Testcontainers support:
  
  // Using @ServiceConnection (Spring Boot 3.1+):
  @Testcontainers
  @SpringBootTest
  class ModernIT {
      
      @Container
      @ServiceConnection  // ← auto-configures datasource, no @DynamicPropertySource needed!
      static PostgreSQLContainer<?> postgres = new PostgreSQLContainer<>("postgres:15");
      
      @Container
      @ServiceConnection
      static RedisContainer redis = new RedisContainer("redis:7");
      
      @Container
      @ServiceConnection
      static KafkaContainer kafka = new KafkaContainer("confluentinc/cp-kafka:7.4");
      
      // Spring Boot auto-detects container type and configures properties!
  }
  
  // @ServiceConnection uses ConnectionDetails beans to configure datasource, etc.
  // Supported out of the box: PostgreSQL, MySQL, MongoDB, Redis, Kafka, RabbitMQ, etc.

10. DEVSERVICES — AUTOMATIC CONTAINERS IN DEVELOPMENT
================================================================

Spring Boot DevServices (with Testcontainers on classpath):
  When running tests without a datasource configured, Spring Boot automatically
  starts a Testcontainers container for you (PostgreSQL, MongoDB, etc.).
  
  # Opt out if you want manual control:
  # spring.devtools.restart.enabled=false
  # spring.testcontainers.service-connections.enabled=false

11. BEST PRACTICES
================================================================

  DO:
    ✅ Use static containers — started once per class (not per test)
    ✅ Use .withReuse(true) for faster local development
    ✅ Use @ServiceConnection (Spring Boot 3.1+) to remove boilerplate
    ✅ Pin specific Docker image versions (postgres:15.2, not postgres:latest)
    ✅ Set startup timeouts appropriate to the image
    ✅ Use base test class to share containers across test classes
  
  DON'T:
    ❌ Use instance-level @Container (restarts container every test)
    ❌ Use latest tags in CI/CD — non-deterministic
    ❌ Start containers in @BeforeEach — use static lifecycle
    ❌ Forget @AutoConfigureTestDatabase(replace = NONE) with @DataJpaTest

12. INTERVIEW QUESTIONS
================================================================

Q: What is Testcontainers and why would you use it?
A: Testcontainers is a Java library that starts real Docker containers
   in tests. Used to test against a real database (PostgreSQL, MySQL),
   message broker (Kafka), cache (Redis), etc. — avoiding compatibility
   gaps between embedded tools (H2) and the production database.

Q: What is @Testcontainers and @Container?
A: @Testcontainers is a JUnit 5 extension that manages container lifecycle.
   @Container marks a field as a managed container — it starts before tests
   and stops after. Static @Container = shared per class;
   Instance @Container = new container per test method.

Q: What is @DynamicPropertySource?
A: A static method to register Spring properties dynamically before the
   ApplicationContext is created. Used with Testcontainers to register
   the container's JDBC URL, host, and port that are known only at runtime.

Q: What is @ServiceConnection in Spring Boot 3.1+?
A: When used with @Container, Spring Boot auto-detects the container type
   and auto-configures the corresponding Spring properties (datasource URL,
   Redis host/port, Kafka bootstrap-servers) — no @DynamicPropertySource needed.

Q: What is withReuse(true)?
A: Tells Testcontainers NOT to stop the container after the test class.
   On the next test run, the same container is reused if still running.
   Requires testcontainers.reuse.enable=true in ~/.testcontainers.properties.
   Greatly speeds up local development iteration.

Q: How do you share a container across multiple test classes?
A: Use a static container in a shared base class, or use a utility class
   with a static block to start the container once. All test classes
   that use @DynamicPropertySource pointing to the same container will
   share it (and Spring will cache the context too).
