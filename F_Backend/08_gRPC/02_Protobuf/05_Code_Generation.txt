1. THE PROTOC COMPILER
----------------------------------------------------------------

protoc is the Protocol Buffer compiler — it reads .proto files and
generates source code in the target language.

Installation:
  macOS:   brew install protobuf
  Ubuntu:  apt-get install protobuf-compiler
  
  Verify: protoc --version
  Current: libprotoc 25.x (as of 2024)

Basic usage:
  protoc [OPTIONS] [PROTO_FILES]
  
  Options:
    --proto_path=PATH      (-I PATH): Search path for imports
    --java_out=DIR:        Output directory for Java code
    --python_out=DIR:      Output directory for Python code
    --go_out=DIR:          Output directory for Go code
    --cpp_out=DIR:         Output directory for C++ code
    --csharp_out=DIR:      Output directory for C# code
    --js_out=DIR:          Output directory for JavaScript code

Example compilation:
  protoc \
    --proto_path=src/main/proto \
    --java_out=src/main/java \
    src/main/proto/order/v1/order.proto

For gRPC, you need the gRPC plugin in addition to protoc:
  protoc \
    --proto_path=src/main/proto \
    --java_out=src/main/java \
    --grpc-java_out=src/main/java \     ← gRPC Java plugin
    src/main/proto/order/v1/order.proto

2. JAVA CODE GENERATION
----------------------------------------------------------------

Generated artifacts from a .proto file with service:
  1. Message classes (one .java file per message by default)
     - If java_multiple_files=true: OrderRequest.java, OrderResponse.java
     - If java_multiple_files=false: OrderProto.java (outer class with inner classes)
  
  2. Service stub class: OrderServiceGrpc.java
     - OrderServiceGrpc.OrderServiceBlockingStub (synchronous client)
     - OrderServiceGrpc.OrderServiceFutureStub (future-based client)
     - OrderServiceGrpc.OrderServiceStub (async client)
     - OrderServiceGrpc.OrderServiceImplBase (abstract server base)
     - OrderServiceGrpc.bindService() (service descriptor registration)

Example generated stub structure:
  public final class OrderServiceGrpc {
    
    // Service descriptor (used for registration and reflection)
    public static ServiceDescriptor getServiceDescriptor() { ... }
    
    // Channel factory methods
    public static OrderServiceBlockingStub newBlockingStub(Channel channel) { ... }
    public static OrderServiceStub newStub(Channel channel) { ... }
    public static OrderServiceFutureStub newFutureStub(Channel channel) { ... }
    
    // Blocking stub (synchronous, easy to use)
    public static class OrderServiceBlockingStub extends ... {
      public Order createOrder(CreateOrderRequest request) { ... }
      public Order getOrder(GetOrderRequest request) { ... }
      public Iterator<Order> streamCustomerOrders(GetOrderRequest request) { ... }
      // Note: no blocking bidirectional or client-streaming stubs
    }
    
    // Async stub (callback-based)
    public static class OrderServiceStub extends ... {
      public void createOrder(CreateOrderRequest req, StreamObserver<Order> resp) { ... }
      public StreamObserver<CreateOrderRequest> batchCreateOrders(StreamObserver<BatchResult> resp) { ... }
      public StreamObserver<OrderEvent> processOrderEvents(StreamObserver<OrderResult> resp) { ... }
    }
    
    // Future stub (returns ListenableFuture)
    public static class OrderServiceFutureStub extends ... {
      public ListenableFuture<Order> createOrder(CreateOrderRequest request) { ... }
    }
    
    // Server implementation base class
    public static abstract class OrderServiceImplBase implements BindableService {
      public void createOrder(CreateOrderRequest req, StreamObserver<Order> resp) {
        // Default: UNIMPLEMENTED error
        resp.onError(Status.UNIMPLEMENTED.asException());
      }
      // ... other methods
    }
  }

Generated message class (simplified):

    private volatile Object customerId_;

    public String getOrderId() { ... }
    public String getCustomerId() { ... }

    public static Order parseFrom(byte[] data) throws InvalidProtocolBufferException { ... }
    public static Order parseFrom(InputStream input) { ... }
    public static Order parseFrom(ByteString data) { ... }
    
    // Builder factory
    public static Builder newBuilder() { ... }
    public Builder toBuilder() { ... }  // mutable copy
    
    // Equality
    public boolean equals(Object obj) { ... }
    public int hashCode() { ... }
    
    // Debugging
    public String toString() { ... }  // human-readable (like JSON)
    
    // Builder (mutable, not thread-safe)
    public static final class Builder extends GeneratedMessageV3.Builder<Builder> {
      public Builder setOrderId(String value) { ... }
      public Builder setCustomerId(String value) { ... }
      public Builder addItems(OrderItem value) { ... }
      public Builder addAllItems(Iterable<OrderItem> values) { ... }
      public Builder clearItems() { ... }
      public Order build() { ... }          // creates immutable message
      public Order buildPartial() { ... }   // no validation
    }
  }

Builder pattern usage:
  // Immutable message objects — use Builder to construct
  Order order = Order.newBuilder()
      .setOrderId("ORD-001")
      .setCustomerId("CUST-123")
      .setStatus(OrderStatus.ORDER_STATUS_PENDING)
      .addItems(OrderItem.newBuilder()
          .setProductId("P1")
          .setQuantity(2)
          .build())
      .build();
  
  // Modify an existing message (creates new Builder, then builds new instance)
  Order updatedOrder = order.toBuilder()
      .setStatus(OrderStatus.ORDER_STATUS_CONFIRMED)
      .build();
  
  // Check equality
  order.equals(anotherOrder);    // deep equality (compares all fields)
  order.getSerializedSize();     // bytes when serialized

    <dependency>
      <groupId>io.grpc</groupId>

      <version>1.62.2</version>
    </dependency>
    
    <!-- Protobuf Java runtime -->
    <dependency>
      <groupId>com.google.protobuf</groupId>

      <version>3.25.3</version>
    </dependency>
    
    <!-- For JSON format support -->
    <dependency>

    <!-- gRPC API annotations -->
    <dependency>
      <groupId>io.grpc</groupId>
      <artifactId>grpc-api</artifactId>
      <version>1.62.2</version>
    </dependency>
  </dependencies>
  
  <build>
    <extensions>
      <extension>
        <groupId>kr.motd.maven</groupId>

      </extension>
    </extensions>
    <plugins>
      <plugin>
        <groupId>org.xolstice.maven.plugins</groupId>

        <configuration>
          <protocArtifact>
            com.google.protobuf:protoc:3.25.3:exe:${os.detected.classifier}
          </protocArtifact>
          <pluginId>grpc-java</pluginId>
          <pluginArtifact>
            io.grpc:protoc-gen-grpc-java:1.62.2:exe:${os.detected.classifier}
          </pluginArtifact>
        </configuration>
        <executions>
          <execution>
            <goals>
              <goal>compile</goal>
              <goal>compile-custom</goal>
            </goals>
          </execution>
        </executions>
      </plugin>
    </plugins>
  </build>

Proto file location: src/main/proto/
Generated code goes to: target/generated-sources/protobuf/

6. BUF BUILD TOOL (MODERN ALTERNATIVE TO protoc)
----------------------------------------------------------------

buf is a modern replacement for protoc with better UX:

Installation:
  brew install bufbuild/buf/buf

buf.yaml (configuration):
  version: v2
  modules:
    - path: proto
  deps:
    - buf.build/googleapis/googleapis

buf.gen.yaml (code generation config):
  version: v2
  plugins:
    - remote: buf.build/protocolbuffers/java
      out: src/main/java
    - remote: buf.build/grpc/java
      out: src/main/java

Commands:
  buf generate        # generate code
  buf lint            # lint .proto files
  buf breaking .      # check for breaking changes vs latest in BSR
  buf format -w       # format .proto files
  buf push            # push to Buf Schema Registry

Breaking change detection:
  # Check if your changes break wire compatibility
  buf breaking --against https://github.com/company/protos.git#branch=main

Lint rules (buf defaults):
  - Names follow conventions (PascalCase for messages, snake_case for fields)
  - Enums have UNSPECIFIED first value
  - RPC request/response types are not reused
  - Service methods use correct naming conventions
  - File has package declaration

7. CODE GENERATION FOR OTHER LANGUAGES
----------------------------------------------------------------

Go:
  protoc \
    --go_out=. \
    --go_opt=paths=source_relative \
    --go-grpc_out=. \
    --go-grpc_opt=paths=source_relative \
    order.proto
  
  Generated: order.pb.go (messages) + order_grpc.pb.go (service)

Python:
  python -m grpc_tools.protoc \
    --proto_path=. \
    --python_out=. \
    --grpc_python_out=. \
    order.proto
  
  Generated: order_pb2.py (messages) + order_pb2_grpc.py (service)

Node.js (TypeScript with ts-proto):
  protoc \
    --plugin=./node_modules/.bin/protoc-gen-ts_proto \
    --ts_proto_out=./src/generated \
    --ts_proto_opt=outputServices=grpc-js \
    order.proto

C#/.NET:
  protoc \
    --csharp_out=./Generated \
    --grpc_out=./Generated \
    order.proto

Kotlin (uses grpc-kotlin plugin):
  protoc \
    --kotlin_out=./src/main/kotlin \
    --grpc-kotlin_out=./src/main/kotlin \
    order.proto

8. GENERATED CODE: UNDERSTANDING WHAT YOU GET
----------------------------------------------------------------

From this service definition:
  service OrderService {
    rpc GetOrder (GetOrderRequest) returns (Order);
    rpc StreamOrders (GetOrderRequest) returns (stream Order);
    rpc BatchCreate (stream CreateOrderRequest) returns (BatchResult);
    rpc ProcessEvents (stream OrderEvent) returns (stream OrderResult);
  }

Generated OrderServiceGrpc.java contains:

1. METHOD DESCRIPTORS (routing info):
   static final io.grpc.MethodDescriptor<GetOrderRequest, Order> METHOD_GET_ORDER
   static final io.grpc.MethodDescriptor<GetOrderRequest, Order> METHOD_STREAM_ORDERS
   // etc.

2. BLOCKING STUB (for sync calls):
   blockingStub.getOrder(request);         // returns Order
   blockingStub.streamOrders(request);     // returns Iterator<Order>
   // Note: NO blocking stub for client-streaming or bidi-streaming!

3. ASYNC STUB (for all patterns):
   asyncStub.getOrder(request, responseObserver);
   asyncStub.streamOrders(request, responseObserver);
   StreamObserver<CreateOrderRequest> reqObserver = 
       asyncStub.batchCreate(responseObserver);
   StreamObserver<OrderEvent> reqObserver = 
       asyncStub.processEvents(responseObserver);

4. FUTURE STUB (for Guava ListenableFuture):
   ListenableFuture<Order> future = futureStub.getOrder(request);
   // Note: only works for unary RPCs

5. SERVER IMPLEMENTATION BASE:
   abstract class OrderServiceImplBase {
     void getOrder(GetOrderRequest req, StreamObserver<Order> resp);
     void streamOrders(GetOrderRequest req, StreamObserver<Order> resp);
     StreamObserver<CreateOrderRequest> batchCreate(StreamObserver<BatchResult> resp);
     StreamObserver<OrderEvent> processEvents(StreamObserver<OrderResult> resp);
   }

9. INTELLIJ IDEA IDE INTEGRATION
----------------------------------------------------------------

IDE support for .proto files:
  - Install "Protocol Buffer Editor" plugin
  - Provides: syntax highlighting, auto-complete, error checking,
    code formatting, find usages, rename refactoring

Proto file workflow in IntelliJ:
  1. Add .proto files in src/main/proto/
  2. Run Maven/Gradle "generate-sources" or "generateProto"
  3. Mark generated sources as "Generated Sources Root":
     Right-click target/generated-sources → Mark Directory As → Generated Sources Root

Useful IDE shortcuts:
  - Ctrl+Click on message type → go to definition
  - Ctrl+Click on imported proto → open imported file
  - Right-click → Generate → Builder pattern helpers

10. PROTOBUF REFLECTION AND SELF-DESCRIBING
----------------------------------------------------------------

Protobuf supports server reflection (ServiceReflectionInfo):
  - Server exposes its own proto schema at runtime
  - Tools like grpcurl can discover available services without .proto files
  
  Enable in Java:
    Server server = ServerBuilder.forPort(8080)
        .addService(new OrderServiceImpl())
        .addService(ProtoReflectionService.newInstance())  // enables reflection
        .build();

Programmatic reflection:
  // Get descriptor for a message type
  Descriptor descriptor = Order.getDescriptor();
  for (FieldDescriptor field : descriptor.getFields()) {
    System.out.println(field.getName() + ": " + field.getType());
  }
  
  // Dynamic message (parse without knowing the type at compile time)
  DynamicMessage msg = DynamicMessage.parseFrom(descriptor, bytes);

11. INTERVIEW KEY POINTS
----------------------------------------------------------------

Q: What files does protoc generate for a Java gRPC service?
A: For a .proto file containing a service, protoc generates:
   - Message classes (one per message if java_multiple_files=true)
   - OrderServiceGrpc.java which contains the BlockingStub,
     AsyncStub, FutureStub, and the ImplBase abstract class.
   The message classes are generated by the protoc Java plugin.
   The gRPC stubs are generated by the grpc-java plugin.

Q: What is the difference between the three client stubs?
A: BlockingStub: synchronous, blocks calling thread until response arrives.
   Easy to use but wastes threads.
   AsyncStub: callback-based (StreamObserver), non-blocking. Used for
   streaming and high-throughput scenarios.
   FutureStub: returns ListenableFuture, usable with async frameworks.
   Only works for unary RPCs.

Q: What happens if you change a protobuf field type in the .proto file?
A: The generated code will change, causing compilation errors in existing
   code that uses the old type. On the wire, if an old client sends
   the old type and a new server receives it with the new type, the
   behavior is unpredictable (sometimes partially decoded, sometimes
   errors). This is a BREAKING change. To change types safely, use
   a new field number.
