━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1. ALL DDL-AUTO VALUES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

spring.jpa.hibernate.ddl-auto=<value>

none       — Hibernate does nothing to the schema.
             Requires an external tool (Flyway/Liquibase) or manual DDL.
             RECOMMENDED for production.

validate   — Hibernate checks that the DB schema matches entity mappings.
             Throws SchemaManagementException if they don't match.
             No DDL changes are made.
             GOOD for staging/pre-production to catch drift early.

update     — Hibernate compares entities to schema and issues ALTER statements
             to add missing columns/tables. NEVER drops columns or tables.
             ONLY for development convenience — NEVER production!

create     — Drops all tables and recreates them on every startup.
             All data is lost. For unit testing and dev resets.

create-drop— Same as create, but also drops the schema when the SessionFactory
             closes (application shuts down). Ideal for integration tests.

2. ENVIRONMENT-BASED RECOMMENDATIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Environment     | Recommended ddl-auto | Notes
────────────────|──────────────────────|──────────────────────────────────────────
Development     | update               | Convenient but can accumulate schema debt
Unit Tests      | create-drop          | Clean DB every test run (H2/TestContainers)
Integration Tests| create             | Explicit fresh schema
Staging/Pre-prod| validate             | Validates schema without changes
PRODUCTION      | none + validate      | Flyway/Liquibase handles DDL; validate confirms

3. SPRING BOOT DEFAULT BEHAVIOR
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Spring Boot's default depends on data source type:
  Embedded (H2, HSQL, Derby): create-drop
  Non-embedded (PostgreSQL, MySQL): none

So with a real DB (PostgreSQL), Spring Boot defaults to none.
With H2 in tests, it defaults to create-drop (clean each run).

5. VALIDATE IN ACTION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

spring.jpa.hibernate.ddl-auto=validate

On startup, Hibernate checks:
  - All @Entity tables exist in DB
  - All @Column fields have matching DB columns (correct type/nullable)
  - All @JoinColumn FK columns exist

If mismatch found:
  org.hibernate.tool.schema.spi.SchemaManagementException:
    Schema-validation: missing column [email_address] in table [users]

Common mismatches:
  - Renamed field in Java but forgot to migrate DB column
  - Column type mismatch (TEXT vs VARCHAR)
  - Missing index after adding @Index to @Table

6. USING DDL-AUTO WITH FLYWAY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Recommended production setup:
  spring.jpa.hibernate.ddl-auto=validate
  spring.flyway.enabled=true

Flow on startup:
  1. Flyway runs migrations (creates/updates schema)
  2. Hibernate validates entities match the schema
  3. Application starts only if both steps succeed

If Flyway is enabled, set ddl-auto=none or validate — never update/create.

# application.properties (production)
spring.jpa.hibernate.ddl-auto=validate
spring.datasource.url=jdbc:postgresql://prod-db:5432/mydb
spring.flyway.locations=classpath:db/migration
spring.flyway.baseline-on-migrate=false   # Don't auto-baseline existing DBs

7. INTERVIEW QUICK HITS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: What is the difference between create and create-drop?
A: create drops and recreates all tables on startup and leaves the
   schema in place when the application stops. create-drop does the
   same on startup but also drops the schema when the application
   shuts down. create-drop is typically used in embedded-DB tests.

Q: Why is ddl-auto=update dangerous in production?
A: It only adds new columns/tables — it never removes columns, renames
   them, changes types, or handles complex schema changes. There's no
   audit trail, no rollback capability, and it can corrupt existing
   data or create inconsistent states. Flyway/Liquibase provide safe,
   reversible, auditable migrations.

Q: What does ddl-auto=validate do?
A: It makes Hibernate verify that every @Entity has a corresponding table
   and every @Column has a matching DB column. It throws an exception if
   there's any mismatch, preventing the application from starting with
   a mismatched schema — without making any changes to the DB.

Q: What is the default ddl-auto in Spring Boot with PostgreSQL?
A: Spring Boot defaults to none for non-embedded (production) databases
   and create-drop for embedded databases like H2. Always explicitly
   set it in your application.properties to avoid surprises.
