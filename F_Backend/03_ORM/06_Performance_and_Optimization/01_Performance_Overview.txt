1. WHY ORM PERFORMANCE MATTERS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

JPA/Hibernate simplifies persistence, but it can generate:
- Too many SQL queries (N+1 problem)
- Oversized result sets (fetching too much data)
- Expensive joins (Cartesian products from EAGER collections)
- Memory pressure (loading thousands of entities for batch ops)
- Lock contention (bad transaction boundaries)

Performance topics are among the TOP interview questions for any
Java backend role that uses Spring/Hibernate.

2. HIERARCHY OF OPTIMIZATIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Priority 1 (most impact): Fix N+1 queries
  → Use JOIN FETCH, @EntityGraph, or @BatchSize
  → Switch to DTO projections for read-only data

Priority 2: Fetch only what you need
  → DTO/interface projections instead of full entity loads
  → Select-specific columns with constructor JPQL expressions
  → Use @Transient for fields not needed in all contexts

Priority 3: Batch writes
  → Enable JDBC batching (hibernate.jdbc.batch_size=50)
  → Use saveAll() rather than looping save()
  → Use bulk UPDATE/DELETE JPQL for mass operations

Priority 4: Caching
  → First-level cache: automatic, no config needed
  → Second-level cache (EhCache, Redis): for frequently read static data
  → Query cache: for the same query with same params

Priority 5: Database-level
  → Ensure DB indexes on FK columns, search predicates
  → Use read replicas for reporting queries
  → Connection pooling (HikariCP) tuning

Enable SQL logging (see actual queries):
  spring.jpa.show-sql=true
  spring.jpa.properties.hibernate.format_sql=true
  logging.level.org.hibernate.SQL=DEBUG
  logging.level.org.hibernate.type.descriptor.sql=TRACE   # binds

Count queries with Hibernate Statistics:
  spring.jpa.properties.hibernate.generate_statistics=true
  logging.level.org.hibernate.stat=DEBUG
  // Then use: Statistics stats = sessionFactory.getStatistics();
  // stats.getQueryExecutionCount(), stats.getEntityLoadCount()

5. INTERVIEW QUICK HITS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: What is the first thing you check when Hibernate is running slow?
A: Enable SQL logging and count query executions. Most Hibernate slowness
   stems from N+1 queries or fetching too much data. Once you see the
   actual SQL, N+1 becomes obvious and can be fixed with JOIN FETCH.

Q: What is the N+1 problem?
A: When loading N entities, Hibernate then issues N additional SQL queries
   to load each entity's LAZY association — giving N+1 total queries.
   Example: 1 query for 100 users + 100 queries for their orders = 101 queries.

Q: How do you batch Hibernate queries?
A: Set spring.jpa.properties.hibernate.jdbc.batch_size=50 to enable JDBC
   batching. Then use saveAll() or flush+clear in loops. For SELECT batching,
   use @BatchSize on associations to load them in batches of N instead of one-by-one.
