1. WHAT ARE LIFECYCLE CALLBACKS?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

JPA lifecycle callbacks allow you to hook into the entity lifecycle
and execute custom logic at specific points (before/after persist,
update, remove, load).

Use cases:
  - Auto-set timestamps (createdAt, updatedAt)
  - Data validation before save
  - Logging/auditing
  - Setting default values
  - Hashing passwords before persist
  - Clearing sensitive data after load

2. THE SEVEN CALLBACK ANNOTATIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Annotation       | When it fires
─────────────────|────────────────────────────────────────────
@PrePersist      | Before em.persist() (before INSERT)
@PostPersist     | After INSERT executes (ID is now set)
@PreUpdate       | Before UPDATE (dirty check detected change)
@PostUpdate      | After UPDATE executes
@PreRemove       | Before DELETE
@PostRemove      | After DELETE executes
@PostLoad        | After entity is loaded from DB (SELECT / refresh)

Rules for callback methods:
  ✓ Return type: void
  ✓ No arguments
  ✓ Can be in entity class itself or in a separate EntityListener
  ✓ May throw only unchecked exceptions (no checked exceptions)
  ✗ Cannot call em.persist(), em.remove(), etc. (context modification forbidden)

3. CALLBACKS DIRECTLY ON ENTITY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

@Entity
@Table(name = "products")
public class Product {

    @Id @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    private String name;
    private BigDecimal price;

    @Column(updatable = false)
    private LocalDateTime createdAt;
    private LocalDateTime updatedAt;

    @Transient
    private String tempToken;   // sensitive data

    @PrePersist
    protected void onCreate() {
        this.createdAt = LocalDateTime.now();
        this.updatedAt = LocalDateTime.now();
        validatePrice();
    }

    @PreUpdate
    protected void onUpdate() {
        this.updatedAt = LocalDateTime.now();
        validatePrice();
    }

    @PostPersist
    protected void afterPersist() {
        System.out.println("Product persisted with id: " + id);
        // ID is now available
    }

    @PostLoad
    protected void afterLoad() {
        this.tempToken = null;  // clear any sensitive computed data on load
    }

    @PreRemove
    protected void beforeDelete() {
        System.out.println("About to delete product: " + name);
    }

    @PostRemove
    protected void afterDelete() {
        System.out.println("Product deleted: " + name);
    }

    private void validatePrice() {
        if (price != null && price.compareTo(BigDecimal.ZERO) < 0) {
            throw new IllegalStateException("Price cannot be negative");
        }
    }
}

4. ENTITY LISTENERS — EXTERNAL CALLBACK CLASSES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Preferred for cross-cutting concerns (audit, logging) shared across
multiple entities.

Listener class (can be a Spring bean in Spring Boot):
  public class AuditEntityListener {

      @PrePersist
      public void prePersist(Object entity) {
          if (entity instanceof Auditable) {
              Auditable a = (Auditable) entity;
              a.setCreatedAt(LocalDateTime.now());
              a.setCreatedBy(getCurrentUser());
          }
      }

      @PreUpdate
      public void preUpdate(Object entity) {
          if (entity instanceof Auditable) {
              Auditable a = (Auditable) entity;
              a.setUpdatedAt(LocalDateTime.now());
              a.setUpdatedBy(getCurrentUser());
          }
      }

      private String getCurrentUser() {
          // Get from Spring Security context
          return SecurityContextHolder.getContext()
              .getAuthentication().getName();
      }
  }

Apply to entity:
  @Entity
  @EntityListeners(AuditEntityListener.class)
  public class Order {
      @Id @GeneratedValue(strategy = GenerationType.IDENTITY)
      private Long id;
      // ...
  }

Apply to multiple entities via @MappedSuperclass:
  @MappedSuperclass
  @EntityListeners(AuditEntityListener.class)
  public abstract class AuditableEntity {
      @Column(updatable = false) private LocalDateTime createdAt;
      @Column private LocalDateTime updatedAt;
      @Column(updatable = false) private String createdBy;
      @Column private String updatedBy;
  }

  @Entity public class Order extends AuditableEntity { ... }
  @Entity public class User extends AuditableEntity { ... }

5. SPRING DATA JPA AUDITING (PREFERRED APPROACH)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Spring Boot provides built-in auditing with @EnableJpaAuditing.
It registers AuditingEntityListener automatically.

Setup:
  @Configuration
  @EnableJpaAuditing(auditorAwareRef = "auditorProvider")
  public class JpaConfig {

      @Bean
      public AuditorAware<String> auditorProvider() {
          return () -> Optional.ofNullable(
              SecurityContextHolder.getContext().getAuthentication()
          ).map(Authentication::getName);
      }
  }

Entity:
  @MappedSuperclass
  @EntityListeners(AuditingEntityListener.class)
  public abstract class BaseEntity {

      @CreatedDate
      @Column(updatable = false)
      private LocalDateTime createdAt;

      @LastModifiedDate
      private LocalDateTime updatedAt;

      @CreatedBy
      @Column(updatable = false)
      private String createdBy;

      @LastModifiedBy
      private String updatedBy;

      @Version
      private Long version;
  }

6. EXCLUDING LISTENERS — @EXCLUDEDEFAULTLISTENERS / @EXCLUDESUPERCLASSLISTENERS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

// Exclude inherited listeners from superclass
@Entity
@ExcludeSuperclassListeners
public class ReadOnlyView extends AuditableEntity { ... }

// Exclude default (globally registered) listeners
@Entity
@ExcludeDefaultListeners
public class SystemLog { ... }

7. EXECUTION ORDER (When multiple listeners exist)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Order of @PrePersist execution:
  1. Default entity listeners (registered in orm.xml globally)
  2. Superclass @EntityListeners (inherited up the hierarchy)
  3. Entity's own @EntityListeners
  4. Entity's own @PrePersist method

Q: What are JPA lifecycle callbacks?
A: Methods that fire at specific points in an entity's lifecycle:
   @PrePersist, @PostPersist, @PreUpdate, @PostUpdate, @PreRemove,
   @PostRemove, @PostLoad. Use them for auditing, validation, or
   setting computed fields.

Q: What is the difference between @PrePersist and @PreUpdate?
A: @PrePersist fires before an INSERT (new entity being saved).
   @PreUpdate fires before an UPDATE (existing entity being modified).
   For setting createdAt, use @PrePersist only.
   For setting updatedAt, use both @PrePersist and @PreUpdate.

Q: What is an EntityListener?
A: A separate class annotated with JPA lifecycle annotations that can be
   attached to entities via @EntityListeners. Useful for cross-cutting
   concerns (auditing, logging) shared across many entity types.

Q: How does Spring Data JPA's @CreatedDate differ from @PrePersist?
A: @CreatedDate (Spring) is handled by the AuditingEntityListener and
   integrates with AuditorAware for user tracking. @PrePersist is a raw
   JPA callback that you implement manually. @CreatedDate is cleaner and
   integrates with Spring Security automatically via AuditorAware.

Q: Can you call EntityManager methods from a lifecycle callback?
A: No. JPA forbids calling persist(), merge(), remove(), refresh() from
   lifecycle callbacks because the context is in an intermediate state.
   Only reading/modifying the current entity's state is safe.
