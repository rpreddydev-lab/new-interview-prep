SECTION 1: COMMUNICATION MODELS
================================================================================

CLIENT-SERVER MODEL
--------------------
- Client sends a REQUEST; server sends a RESPONSE
- Stateless by default in HTTP (each request is independent)
- HTTP/1.1 introduced persistent connections (Connection: keep-alive)

REQUEST-RESPONSE vs STREAMING vs EVENT-DRIVEN
----------------------------------------------
1. Request-Response  : Classic HTTP; client polls for data
2. Long Polling      : Client holds connection open; server responds when data available
3. Server-Sent Events: One-way stream from server to client over HTTP
4. WebSockets        : Full-duplex, persistent TCP connection
5. Event-Driven      : Pub/Sub (Kafka, RabbitMQ) — server pushes events

SECTION 2: KEY PROTOCOLS AT A GLANCE
================================================================================

PROTOCOL   LAYER      DESCRIPTION
---------  ---------  -----------------------------------------------------------
IP         Network    Routing packets across networks; unreliable delivery
TCP        Transport  Reliable, ordered delivery with handshake and ACKs
UDP        Transport  Fast, connectionless; no guarantee of delivery or order
TLS        Session    Encryption layer over TCP (used by HTTPS)
HTTP/1.1   App        Text-based, persistent connections, head-of-line blocking
HTTP/2     App        Binary framing, multiplexing, header compression, server push
HTTP/3     App        UDP-based (QUIC), solves head-of-line blocking at transport level
WebSocket  App        Upgrade over HTTP; full-duplex persistent connection
DNS        App        Resolves domain names to IP addresses
SMTP/FTP   App        Email / File Transfer

SECTION 3: MENTAL MODEL FOR INTERVIEW DISCUSSIONS
================================================================================

When asked a networking/API design question, structure your answer around:

  1. PROTOCOL CHOICE     — HTTP vs WebSocket vs gRPC vs message queue
  2. DATA FORMAT         — JSON vs XML vs Protobuf vs Avro
  3. RELIABILITY         — Retries, idempotency, timeouts, circuit breakers
  4. SCALABILITY         — Load balancing, rate limiting, caching, CDN
  5. SECURITY            — TLS, OAuth2, API keys, input validation
  6. OBSERVABILITY       — Logs, metrics, distributed tracing (Zipkin/Jaeger)

QUICK REFERENCE — HTTP STATUS CODES
================================================================================

2xx SUCCESS
  200 OK                  - Standard success
  201 Created             - Resource created (POST/PUT)
  202 Accepted            - Async processing started
  204 No Content          - Success, no body (DELETE)

3xx REDIRECTION
  301 Moved Permanently   - Permanent redirect, update bookmarks
  302 Found               - Temporary redirect
  304 Not Modified        - Conditional GET; use cached version

4xx CLIENT ERROR
  400 Bad Request         - Malformed request / validation failure
  401 Unauthorized        - Missing/invalid authentication
  403 Forbidden           - Authenticated but not authorized
  404 Not Found           - Resource doesn't exist
  405 Method Not Allowed  - Wrong HTTP method
  409 Conflict            - Resource state conflict (duplicate, stale write)
  410 Gone                - Resource permanently deleted
  422 Unprocessable Entity- Semantic validation error
  429 Too Many Requests   - Rate limit exceeded

5xx SERVER ERROR
  500 Internal Server Error - Unexpected server failure
  502 Bad Gateway           - Upstream server returned invalid response
  503 Service Unavailable   - Server down / overloaded
  504 Gateway Timeout       - Upstream server didn't respond in time
