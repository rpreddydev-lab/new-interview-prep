================================================================================
  EXCLUSIONS — REMOVING UNWANTED TRANSITIVE DEPENDENCIES
================================================================================

WHY EXCLUDE DEPENDENCIES?
───────────────────────────
• Remove conflicting logging implementations (commons-logging, log4j, etc.)
• Avoid pulling in a vulnerable or broken transitive version
• Reduce classpath size / fat JAR size
• Replace a transitive with a different implementation (SLF4J bridges)
• Remove unused heavy deps like an embedded database you won't use

─────────────────────────────────────────────────────────────────────────────────
MAVEN — EXCLUSIONS
─────────────────────────────────────────────────────────────────────────────────

  Per-dependency exclusion:
  ─────────────────────────
  <dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web</artifactId>
    <!-- Switch from Tomcat to Undertow -->
    <exclusions>
      <exclusion>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-tomcat</artifactId>
      </exclusion>
    </exclusions>
  </dependency>

  <dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-undertow</artifactId>
  </dependency>

  Wildcard exclusion (Maven 3.x only):
  ──────────────────────────────────────
  <dependency>
    <groupId>com.some.library</groupId>
    <artifactId>some-library</artifactId>
    <version>1.0.0</version>
    <exclusions>
      <exclusion>
        <groupId>*</groupId>
        <artifactId>*</artifactId>
      </exclusion>
    </exclusions>
  </dependency>
  <!-- WARNING: Removes ALL transitives from this dep — use with care -->

  Exclude commons-logging globally (common pattern):
  ────────────────────────────────────────────────────
  <!-- Each dep that brings in commons-logging must be excluded individually in Maven.
       There is no global exclude in Maven by default — use Enforcer bannedDependencies
       to catch if it slips back in, and exclude from each known source. -->

  <dependency>
    <groupId>org.springframework</groupId>
    <artifactId>spring-core</artifactId>
    <exclusions>
      <exclusion>
        <groupId>commons-logging</groupId>
        <artifactId>commons-logging</artifactId>
      </exclusion>
    </exclusions>
  </dependency>

  <dependency>
    <groupId>commons-beanutils</groupId>
    <artifactId>commons-beanutils</artifactId>
    <exclusions>
      <exclusion>
        <groupId>commons-logging</groupId>
        <artifactId>commons-logging</artifactId>
      </exclusion>
    </exclusions>
  </dependency>

  Then add the bridge:
  <dependency>
    <groupId>org.slf4j</groupId>
    <artifactId>jcl-over-slf4j</artifactId>
    <version>2.0.9</version>
  </dependency>

  Ban a dependency with Enforcer (prevents it from slipping back in):
  ────────────────────────────────────────────────────────────────────
  <plugin>
    <groupId>org.apache.maven.plugins</groupId>
    <artifactId>maven-enforcer-plugin</artifactId>
    <executions>
      <execution>
        <goals><goal>enforce</goal></goals>
        <configuration>
          <rules>
            <bannedDependencies>
              <excludes>
                <exclude>commons-logging:commons-logging</exclude>
                <exclude>log4j:log4j</exclude>
                <exclude>org.apache.logging.log4j:log4j-core:[2.0,2.17)</exclude>
              </excludes>
            </bannedDependencies>
          </rules>
        </configuration>
      </execution>
    </executions>
  </plugin>

  Verify exclusions worked:
  ──────────────────────────
  mvn dependency:tree -Dincludes=commons-logging:commons-logging
  # Should show no results if exclusion is complete

─────────────────────────────────────────────────────────────────────────────────
GRADLE — EXCLUSIONS
─────────────────────────────────────────────────────────────────────────────────

  Per-dependency exclusion:
  ─────────────────────────
  dependencies {
      implementation("org.springframework.boot:spring-boot-starter-web") {
          exclude(group = "org.springframework.boot", module = "spring-boot-starter-tomcat")
      }
      implementation("org.springframework.boot:spring-boot-starter-undertow")
  }

  Global exclusion (applies to ALL configurations):
  ──────────────────────────────────────────────────
  configurations.all {
      exclude(group = "commons-logging", module = "commons-logging")
  }
  // Much more convenient than Maven's per-dep exclusions

  Exclude from a specific configuration only:
  ────────────────────────────────────────────
  configurations.runtimeClasspath {
      exclude(group = "com.example", module = "dev-tools")
  }

  Using resolutionStrategy.dependencySubstitution (replace, not just exclude):
  ─────────────────────────────────────────────────────────────────────────────
  configurations.all {
      resolutionStrategy.dependencySubstitution {
          // Replace commons-logging with SLF4J bridge
          substitute(module("commons-logging:commons-logging"))
              .using(module("org.slf4j:jcl-over-slf4j:2.0.9"))
      }
  }

  Force dependency constraints instead of excluding:
  ────────────────────────────────────────────────────
  dependencies {
      constraints {
          implementation("org.apache.logging.log4j:log4j-core") {
              version { reject("[2.0, 2.17)") }
              because("CVE-2021-44228 Log4Shell — reject vulnerable range")
          }
      }
  }

COMMON EXCLUSION PATTERNS
─────────────────────────────────────────────────────────────────────────────────

  1. Switch embedded server (Tomcat → Undertow or Jetty):
  ─────────────────────────────────────────────────────
  Maven:
  <dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web</artifactId>
    <exclusions>
      <exclusion>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-tomcat</artifactId>
      </exclusion>
    </exclusions>
  </dependency>
  <dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-jetty</artifactId>
  </dependency>

  2. Exclude Spring Boot's default logging (use Log4j2):
  ────────────────────────────────────────────────────────
  <dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter</artifactId>
    <exclusions>
      <exclusion>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-logging</artifactId>
      </exclusion>
    </exclusions>
  </dependency>
  <dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-log4j2</artifactId>
  </dependency>

  3. Exclude Hibernate's bundled connection pool (use HikariCP):
  ────────────────────────────────────────────────────────────────
  <dependency>
    <groupId>org.hibernate</groupId>
    <artifactId>hibernate-core</artifactId>
    <exclusions>
      <exclusion>
        <groupId>org.hibernate</groupId>
        <artifactId>hibernate-c3p0</artifactId>
      </exclusion>
    </exclusions>
  </dependency>

  4. Exclude javax.* from Spring Boot 3 app (Jakarta only):
  ───────────────────────────────────────────────────────────
  <dependency>
    <groupId>some.legacy</groupId>
    <artifactId>legacy-lib</artifactId>
    <exclusions>
      <exclusion>
        <groupId>javax.servlet</groupId>
        <artifactId>javax.servlet-api</artifactId>
      </exclusion>
    </exclusions>
  </dependency>

─────────────────────────────────────────────────────────────────────────────────
VERIFYING EXCLUSIONS
─────────────────────────────────────────────────────────────────────────────────

  Maven — search for excluded artifact after exclusion:
  ──────────────────────────────────────────────────────
  mvn dependency:tree -Dincludes=commons-logging:commons-logging
  # Should show nothing if fully excluded

  mvn dependency:tree -Dverbose | grep "commons-logging"
  # With -Dverbose, shows even omitted deps

  Gradle:
  ────────
  ./gradlew dependencyInsight --dependency commons-logging
  # Shows if it still appears anywhere, or "No dependencies matching" if excluded

INTERVIEW QUICK-HITS
─────────────────────────────────────────────────────────────────────────────────

Q: How do you exclude a transitive dependency in Maven?
A: Use the <exclusions> block within the <dependency> declaration that pulls in
   the unwanted transitive. Specify <groupId> and <artifactId>. Maven 3 also supports
   wildcard exclusion (<groupId>*</groupId><artifactId>*</artifactId>) to exclude
   all transitives from a specific dep. Verify with mvn dependency:tree.

Q: Can you apply a global exclusion in Maven?
A: Not directly in pom.xml — Maven requires exclusions per-dependency. However,
   you can use the maven-enforcer-plugin's bannedDependencies rule to FAIL the build
   if the excluded artifact somehow slips back in (via a new transitive path).
   In Gradle, configurations.all { exclude(group="...", module="...") } applies
   globally to all configurations, which is much more convenient.

Q: When would you use an exclusion vs a version override?
A: Use exclusion when you want to completely remove a transitive (e.g., replace
   commons-logging with SLF4J bridge — you don't want both). Use version override
   (via <dependencyManagement> in Maven or resolutionStrategy.force() in Gradle)
   when you want the dependency but at a specific version. Exclusion removes it;
   version override keeps it but changes the selected version.

Q: What is the difference between excluding a dependency and banning it with Enforcer?
A: Excluding removes it from the resolution result. Banning with Enforcer fails the
   build if the artifact appears anywhere in the resolved graph (even after exclusions).
   Use both together: exclude where you know it comes from, and ban it to catch any
   new transitive paths that might reintroduce it in the future.
