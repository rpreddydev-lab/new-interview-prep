================================================================================
  MAVEN BUILD LIFECYCLE — IN DEPTH
================================================================================

OVERVIEW
────────
Maven has THREE built-in lifecycles:
  1. default  (also called "build") — the main lifecycle for building and deploying
  2. clean                          — for removing the previous build output
  3. site                           — for generating project documentation

Each lifecycle is composed of ordered PHASES.
Each phase can have GOALS (from plugins) bound to it.
Running a phase runs all preceding phases first.

─────────────────────────────────────────────────────────────────────────────────
1. DEFAULT LIFECYCLE — ALL PHASES
─────────────────────────────────────────────────────────────────────────────────

  Phase                   Description
  ─────────────────────── ──────────────────────────────────────────────────────
  validate                Validate project is correct and all info is available
  initialize              Initialize build state (set properties, create dirs)
  generate-sources        Generate source code (e.g., from WSDL or Avro schemas)
  process-sources         Process source code (e.g., filter values)
  generate-resources      Generate resources (e.g., JAXB, protobuf)
  process-resources       Copy/process resources to target/classes
  compile                 Compile source code into target/classes
  process-classes         Post-compile processing (e.g., bytecode enhancement)
  generate-test-sources   Generate test source code
  process-test-sources    Process test sources
  generate-test-resources Generate test resources
  process-test-resources  Copy test resources to target/test-classes
  test-compile            Compile test source code into target/test-classes
  process-test-classes    Post-process test classes
  test                    Run unit tests using a suitable framework (Surefire)
  prepare-package         Pre-packaging preparation
  package                 Package compiled code into JAR/WAR/EAR
  pre-integration-test    Set up environment for integration tests
  integration-test        Deploy to environment and run integration tests
  post-integration-test   Tear down environment after integration tests
  verify                  Run checks to verify package is valid and meets criteria
  install                 Install the package into local repo (~/.m2/repository)
  deploy                  Copy the final package to the remote repository

  KEY INSIGHT: Running "mvn deploy" runs ALL phases above it automatically.
  Running "mvn package" runs up to and including package, but NOT install/deploy.

─────────────────────────────────────────────────────────────────────────────────
2. CLEAN LIFECYCLE
─────────────────────────────────────────────────────────────────────────────────

  Phase             Default Bound Goal        Description
  ───────────────── ──────────────────────── ──────────────────────────────────
  pre-clean         (none)                    Executes processes before cleaning
  clean             maven-clean-plugin:clean  Delete target/ directory
  post-clean        (none)                    Executes processes after cleaning

  Usage: mvn clean
  The clean lifecycle is NOT part of the default lifecycle, so:
  • "mvn package" does NOT delete target/ first
  • "mvn clean package" explicitly cleans and then packages (most common CI pattern)

─────────────────────────────────────────────────────────────────────────────────
3. SITE LIFECYCLE
─────────────────────────────────────────────────────────────────────────────────

  Phase             Description
  ───────────────── ──────────────────────────────────────────────────────────
  pre-site          Executes processes needed before generating the site
  site              Generate the project's site documentation
  post-site         Executes processes needed to finalise the site generation
  site-deploy       Deploy the generated site documentation to the specified server

  Usage: mvn site
  Generates HTML documentation from pom.xml metadata, Javadocs, test reports, etc.

─────────────────────────────────────────────────────────────────────────────────
PHASES vs GOALS — THE CRITICAL DISTINCTION
─────────────────────────────────────────────────────────────────────────────────

  PHASE: A named step in a lifecycle. Phases do nothing by themselves — they are
         just hook points. Work happens when a GOAL is bound to a phase.

  GOAL:  The actual unit of work provided by a PLUGIN.
         Format: pluginId:goalName  (e.g., compiler:compile, surefire:test)

  DEFAULT GOAL BINDINGS (packaging = jar):
  ──────────────────────────────────────────
  Phase                   Bound Goal
  ─────────────────────── ────────────────────────────────────────────────────
  process-resources       resources:resources
  compile                 compiler:compile
  process-test-resources  resources:testResources
  test-compile            compiler:testCompile
  test                    surefire:test
  package                 jar:jar
  install                 install:install
  deploy                  deploy:deploy

  Note: Different packaging types (war, ear, maven-plugin) bind different goals.
  For WAR packaging, "package" is bound to war:war instead of jar:jar.

─────────────────────────────────────────────────────────────────────────────────
RUNNING SPECIFIC PHASES AND GOALS
─────────────────────────────────────────────────────────────────────────────────

  # Run a specific phase (runs all preceding phases too)
  mvn compile
  mvn test
  mvn package

  # Run a specific goal directly (bypasses lifecycle ordering)
  mvn compiler:compile          # Just compile, no prior phases
  mvn surefire:test             # Just test
  mvn dependency:tree           # Show dependency tree (no lifecycle needed)
  mvn help:effective-pom        # Show merged POM

  # Run multiple phases/goals in one command
  mvn clean package             # clean lifecycle, then package (default lifecycle)
  mvn clean test jacoco:report  # clean, test, then generate coverage report

  # Skip specific phases
  mvn package -DskipTests       # Skip test execution (compiles tests)
  mvn package -Dmaven.test.skip=true  # Skip test compilation AND execution

─────────────────────────────────────────────────────────────────────────────────
BINDING GOALS TO PHASES IN pom.xml
─────────────────────────────────────────────────────────────────────────────────

  You can bind additional goals to existing phases via plugin configuration:

  <build>
    <plugins>
      <plugin>
        <groupId>org.jacoco</groupId>
        <artifactId>jacoco-maven-plugin</artifactId>
        <version>0.8.11</version>
        <executions>
          <!-- Bind "prepare-agent" goal to the "initialize" phase -->
          <execution>
            <id>prepare-agent</id>
            <goals><goal>prepare-agent</goal></goals>
            <!-- defaults to "initialize" phase if not specified -->
          </execution>
          <!-- Bind "report" goal to the "verify" phase -->
          <execution>
            <id>report</id>
            <phase>verify</phase>
            <goals><goal>report</goal></goals>
          </execution>
        </executions>
      </plugin>
    </plugins>
  </build>

  Now "mvn verify" will automatically run Jacoco's prepare-agent and report.

─────────────────────────────────────────────────────────────────────────────────
PACKAGING TYPES AND THEIR LIFECYCLES
─────────────────────────────────────────────────────────────────────────────────

  Packaging    Phase → Goal
  ──────────── ──────────────────────────────────────────────────────────────
  jar          package → jar:jar  (default)
  war          package → war:war
  ear          package → ear:ear
  pom          package → (no compilation, just POM handling — for parent POMs)
  maven-plugin package → plugin:addPluginArtifactMetadata + jar:jar

  You declare packaging in pom.xml:
  <packaging>war</packaging>  <!-- defaults to jar if omitted -->

─────────────────────────────────────────────────────────────────────────────────
PRACTICAL LIFECYCLE SCENARIOS
─────────────────────────────────────────────────────────────────────────────────

  Scenario                              Command
  ───────────────────────────────────── ──────────────────────────────────────
  Development: just compile              mvn compile
  Development: run tests quickly         mvn test
  Development: skip tests (fast build)   mvn package -DskipTests
  CI/CD pipeline: full build+test        mvn clean verify
  CI/CD pipeline: deploy to Nexus        mvn clean deploy
  CI/CD pipeline: deploy, skip tests     mvn clean deploy -DskipTests (avoid!)
  Release build                          mvn release:prepare release:perform
  Check code coverage                    mvn clean verify   (JaCoCo bound to verify)
  Multi-module: build only one module    mvn -pl service-impl -am package

─────────────────────────────────────────────────────────────────────────────────
COMMON MISTAKES TO AVOID
─────────────────────────────────────────────────────────────────────────────────

  ❌ mvn install -DskipTests in CI   → Artifacts in local repo untested (dangerous)
  ❌ Not running "clean" between builds → Stale .class files can cause subtle bugs
  ❌ Confusing "phase" with "goal"   → Phases are ordered; goals can be run directly
  ❌ Running "mvn deploy" locally    → Pollutes the remote repo with dev versions
  ❌ Using SNAPSHOT versions in release builds → Non-reproducible; avoid in prod

─────────────────────────────────────────────────────────────────────────────────
INTERVIEW QUICK-HITS
─────────────────────────────────────────────────────────────────────────────────

Q: What are the three Maven lifecycles?
A: default (build), clean, and site.

Q: What is the difference between a phase and a goal?
A: A phase is a named step in a lifecycle (like "compile" or "test"). A goal
   is the actual work unit provided by a plugin (like "compiler:compile").
   Goals are bound to phases; running a phase executes its bound goals.

Q: What happens when you run "mvn package"?
A: Maven runs all default lifecycle phases from validate through package:
   validate → initialize → generate-sources → process-sources →
   generate-resources → process-resources → compile → process-classes →
   generate-test-sources → ... → test → prepare-package → package

Q: What is the difference between "install" and "deploy"?
A: "install" copies the artifact to the local Maven repository (~/.m2).
   "deploy" uploads it to a remote/shared repository (Nexus, Artifactory).
   "deploy" is for sharing with other developers or CI/CD pipelines.

Q: Can you skip a specific phase?
A: You cannot skip a phase directly, but you can skip the work a phase does.
   For example, -DskipTests skips test execution (surefire:test), and
   -Dmaven.test.skip=true skips both test compilation and execution.

Q: What is the difference between -DskipTests and -Dmaven.test.skip=true?
A: -DskipTests: Tests are still compiled but not executed.
   -Dmaven.test.skip=true: Tests are neither compiled nor executed.
   Use -DskipTests during development; never skip tests in final CI artifacts.
