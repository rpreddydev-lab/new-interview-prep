================================================================================
  MAVEN WRAPPER (mvnw)
================================================================================

WHAT IS THE MAVEN WRAPPER?
───────────────────────────
The Maven Wrapper is a small script bundled with your project that downloads and
uses a specific, pinned version of Maven — without requiring Maven to be installed
on the machine running the build.

It is analogous to Gradle's Wrapper (gradlew). Spring Initializr generates Maven
Wrapper files by default in every new Spring Boot project.

─────────────────────────────────────────────────────────────────────────────────
FILES IN THE MAVEN WRAPPER
─────────────────────────────────────────────────────────────────────────────────

  myproject/
  ├── mvnw                         ← Shell script for Unix/macOS/Linux
  ├── mvnw.cmd                     ← Batch script for Windows
  └── .mvn/
      └── wrapper/
          ├── maven-wrapper.properties   ← Configuration: Maven version + download URL
          └── maven-wrapper.jar          ← Bootstrap JAR (for older wrapper versions)
                                         (optional in Maven Wrapper 3.2.0+)

  These files SHOULD be committed to version control.

─────────────────────────────────────────────────────────────────────────────────
maven-wrapper.properties
─────────────────────────────────────────────────────────────────────────────────

  distributionUrl=https://repo.maven.apache.org/maven2/org/apache/maven/apache-maven/3.9.6/apache-maven-3.9.6-bin.zip
  wrapperUrl=https://repo.maven.apache.org/maven2/org/apache/maven/wrapper/maven-wrapper/3.2.0/maven-wrapper-3.2.0.jar

  Key properties:
  ─────────────────────────────────────────────────────────────────────────────
  distributionUrl      URL to download the Maven distribution ZIP
  wrapperUrl           URL to download the wrapper JAR itself (bootstrap)
  distributionSha256Sum  SHA-256 checksum for download verification (security!)

  Checksum verification example (for tamper detection):
  distributionSha256Sum=706f01b20dec0305a822ab614d51f32b07ee11d0218175e55450242e49d2156d

─────────────────────────────────────────────────────────────────────────────────
USAGE
─────────────────────────────────────────────────────────────────────────────────

  # Instead of: mvn clean install
  # Use:
  ./mvnw clean install              # Unix/macOS
  mvnw.cmd clean install            # Windows

  # Any mvn command works with the wrapper:
  ./mvnw test
  ./mvnw dependency:tree
  ./mvnw spring-boot:run
  ./mvnw -pl service -am package

  First run: If Maven is not already downloaded, the wrapper:
  1. Creates ~/.m2/wrapper/dists/<version>/ directory
  2. Downloads the Maven ZIP from distributionUrl
  3. Extracts it
  4. Uses it for this and all future builds (cached)

  Subsequent runs: Maven is already cached, starts immediately.

─────────────────────────────────────────────────────────────────────────────────
HOW TO ADD THE WRAPPER TO AN EXISTING PROJECT
─────────────────────────────────────────────────────────────────────────────────

  # Method 1: Using the Maven Wrapper plugin (preferred)
  mvn wrapper:wrapper

  # Specify a particular Maven version:
  mvn wrapper:wrapper -Dmaven=3.9.6

  # Method 2: If Maven Wrapper plugin isn't available, use the plugin goal directly:
  mvn org.apache.maven.plugins:maven-wrapper-plugin:3.2.0:wrapper

  This creates the mvnw, mvnw.cmd, and .mvn/wrapper/ files automatically.

  After adding, commit all wrapper files to Git:
  git add mvnw mvnw.cmd .mvn/
  git commit -m "chore: add Maven Wrapper"

─────────────────────────────────────────────────────────────────────────────────
HOW TO UPDATE THE WRAPPER
─────────────────────────────────────────────────────────────────────────────────

  # Update to the latest Maven version:
  ./mvnw wrapper:wrapper

  # Update to a specific version:
  ./mvnw wrapper:wrapper -Dmaven=3.9.8

  # Verify the Maven version being used:
  ./mvnw --version

─────────────────────────────────────────────────────────────────────────────────
WHY USE THE MAVEN WRAPPER?
─────────────────────────────────────────────────────────────────────────────────

  Problem                          Wrapper Solution
  ──────────────────────────────── ─────────────────────────────────────────────
  "Works on my machine" syndrome   Pins exact Maven version for all environments
  CI/CD machine setup overhead     No Maven installation needed on build agents
  Version drift across dev team    Everyone uses the same Maven version
  Upgrading Maven globally risky   Project-specific Maven upgrade, isolated
  New developer onboarding         Clone + ./mvnw build — no setup required
  Security/reproducibility         Checksum verification prevents tampering

─────────────────────────────────────────────────────────────────────────────────
MAVEN WRAPPER vs SYSTEM MAVEN
─────────────────────────────────────────────────────────────────────────────────

  Feature                System Maven        Maven Wrapper
  ─────────────────────── ──────────────────── ────────────────────────────────
  Installation required   Yes                  No (auto-downloaded)
  Version control         OS-wide, shared      Per-project, committed to Git
  Version consistency     Varies by machine    Guaranteed same for all
  CI/CD setup             Install Maven step   Just use ./mvnw
  Command                 mvn                  ./mvnw

─────────────────────────────────────────────────────────────────────────────────
USING MAVEN WRAPPER IN CI/CD
─────────────────────────────────────────────────────────────────────────────────

  GitHub Actions:
  ────────────────
  jobs:
    build:
      runs-on: ubuntu-latest
      steps:
        - uses: actions/checkout@v4
        - uses: actions/setup-java@v4
          with:
            java-version: '21'
            distribution: 'temurin'
        - name: Build with Maven
          run: ./mvnw clean verify     # No need to install Maven separately!

  Jenkins:
  ────────
  pipeline {
    agent any
    stages {
      stage('Build') {
        steps {
          sh './mvnw clean verify'
        }
      }
    }
  }

  GitLab CI:
  ──────────
  build:
    stage: build
    image: eclipse-temurin:21-jdk
    script:
      - chmod +x mvnw   # Ensure executable on fresh checkout
      - ./mvnw clean verify

  NOTE: Always ensure mvnw has execute permissions. On Linux/macOS:
  git update-index --chmod=+x mvnw
  This commits the executable bit to Git so CI doesn't need chmod.

─────────────────────────────────────────────────────────────────────────────────
OFFLINE MODE
─────────────────────────────────────────────────────────────────────────────────

  Once Maven has downloaded all dependencies, you can build offline:
  ./mvnw --offline clean install   # or -o flag
  ./mvnw -o clean install

  Useful for: air-gapped environments, Docker builds without network,
  testing reproducibility.

─────────────────────────────────────────────────────────────────────────────────
.MVNRC AND ENVIRONMENT VARIABLE MVNW_REPOURL
─────────────────────────────────────────────────────────────────────────────────

  Override the download URL via environment variable (useful in corporate proxies):

  export MVNW_REPOURL=https://nexus.company.com/repository/maven-public
  ./mvnw clean install   # Maven wrapper downloaded from Nexus instead of Central

  Override via .mvnrc file in user home directory:
  MVNW_REPOURL=https://nexus.company.com/repository/maven-public

  MAVEN_OPTS environment variable sets JVM args for Maven itself:
  export MAVEN_OPTS="-Xmx2g -XX:+UseG1GC"
  ./mvnw clean install

─────────────────────────────────────────────────────────────────────────────────
.mvn/jvm.config
─────────────────────────────────────────────────────────────────────────────────

  You can commit JVM options for Maven into the project repository:

  .mvn/jvm.config:
  ─────────────────
  -Xmx2g
  -XX:+UseG1GC
  -Dfile.encoding=UTF-8

  This ensures all developers and CI use the same JVM settings for Maven.

  .mvn/maven.config:
  ───────────────────
  --batch-mode
  --errors
  --show-version

  Equivalent to passing those flags every time you run ./mvnw.
  -B / --batch-mode is important for CI to suppress interactive prompts.

─────────────────────────────────────────────────────────────────────────────────
INTERVIEW QUICK-HITS
─────────────────────────────────────────────────────────────────────────────────

Q: What is the Maven Wrapper?
A: A small shell script (mvnw / mvnw.cmd) committed to the project repository that
   automatically downloads and uses a specific Maven version, eliminating the need
   to install Maven globally. The version is pinned in .mvn/wrapper/maven-wrapper.properties.

Q: Why should you use the Maven Wrapper instead of a system-installed Maven?
A: The wrapper guarantees all developers and CI/CD pipelines use the exact same Maven
   version, eliminating "works on my machine" issues. It requires no pre-installation,
   simplifies CI setup, and enables safe, isolated Maven upgrades per project.

Q: What files does the Maven Wrapper create and should they be committed to Git?
A: It creates: mvnw (Unix script), mvnw.cmd (Windows script), and
   .mvn/wrapper/maven-wrapper.properties (version config).
   All of these SHOULD be committed to Git. The maven-wrapper.jar (older versions)
   can optionally be committed or re-downloaded each time.

Q: How do you add the Maven Wrapper to an existing project?
A: Run: mvn wrapper:wrapper  (or mvn wrapper:wrapper -Dmaven=3.9.6 for a specific version)
   Then commit the generated files to version control.

Q: How do you use Maven Wrapper in GitHub Actions?
A: Just use ./mvnw instead of mvn in the run step. GitHub Actions provides Java
   with actions/setup-java, and the wrapper downloads Maven automatically. No
   separate "install Maven" step needed.
