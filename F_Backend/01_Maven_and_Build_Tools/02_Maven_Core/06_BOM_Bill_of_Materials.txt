  MAVEN BOM — BILL OF MATERIALS
================================================================================

WHAT IS A BOM?
──────────────
A Bill of Materials (BOM) is a special Maven POM file (with <packaging>pom</packaging>)
that centralizes dependency VERSION management. A BOM defines a curated set of
dependency versions that are tested and known to work together.

KEY INSIGHT: A BOM does NOT add dependencies to your project.
It only manages VERSIONS. You still declare which dependencies you want.

─────────────────────────────────────────────────────────────────────────────────
WHY USE A BOM?
─────────────────────────────────────────────────────────────────────────────────

  WITHOUT BOM:
  ─────────────
  <dependencies>
    <dependency>
      <groupId>org.springframework.boot</groupId>
      <artifactId>spring-boot-starter-web</artifactId>
      <version>3.2.0</version>     ← Must specify every version
    </dependency>
    <dependency>
      <groupId>org.springframework.boot</groupId>
      <artifactId>spring-boot-starter-data-jpa</artifactId>
      <version>3.2.0</version>     ← Must keep versions in sync
    </dependency>
    <dependency>
      <groupId>com.fasterxml.jackson.core</groupId>
      <artifactId>jackson-databind</artifactId>
      <version>2.15.3</version>    ← Must know what version works with Spring Boot 3.2!
    </dependency>
  </dependencies>

  WITH BOM:
  ──────────
  <!-- Import BOM once -->
  <dependencyManagement>
    <dependencies>
      <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-dependencies</artifactId>
        <version>3.2.0</version>
        <type>pom</type>
        <scope>import</scope>
      </dependency>
    </dependencies>
  </dependencyManagement>

  <!-- Now declare without versions — Spring Boot's BOM provides them -->
  <dependencies>
    <dependency>
      <groupId>org.springframework.boot</groupId>
      <artifactId>spring-boot-starter-web</artifactId>      <!-- no version! -->
    </dependency>
    <dependency>
      <groupId>org.springframework.boot</groupId>
      <artifactId>spring-boot-starter-data-jpa</artifactId> <!-- no version! -->
    </dependency>
    <dependency>
      <groupId>com.fasterxml.jackson.core</groupId>
      <artifactId>jackson-databind</artifactId>             <!-- no version! -->
    </dependency>
  </dependencies>

─────────────────────────────────────────────────────────────────────────────────
HOW TO CREATE YOUR OWN BOM
─────────────────────────────────────────────────────────────────────────────────

  A BOM is just a POM with:
  • <packaging>pom</packaging>
  • A <dependencyManagement> section listing all managed artifacts

  company-bom/pom.xml:
  ─────────────────────
  <?xml version="1.0" encoding="UTF-8"?>
  <project>
    <modelVersion>4.0.0</modelVersion>

    <groupId>com.example</groupId>
    <artifactId>company-bom</artifactId>
    <version>1.5.0</version>
    <packaging>pom</packaging>   <!-- MUST be pom -->

    <name>Company BOM</name>
    <description>Curated dependency versions for Example Corp projects</description>

    <properties>
      <spring.boot.version>3.2.0</spring.boot.version>
      <jackson.version>2.16.0</jackson.version>
      <testcontainers.version>1.19.3</testcontainers.version>
    </properties>

    <dependencyManagement>
      <dependencies>

        <!-- Re-export Spring Boot BOM -->
        <dependency>
          <groupId>org.springframework.boot</groupId>
          <artifactId>spring-boot-dependencies</artifactId>
          <version>${spring.boot.version}</version>
          <type>pom</type>
          <scope>import</scope>
        </dependency>

        <!-- Internal libraries -->
        <dependency>
          <groupId>com.example</groupId>
          <artifactId>common-utils</artifactId>
          <version>2.1.0</version>
        </dependency>
        <dependency>
          <groupId>com.example</groupId>
          <artifactId>security-lib</artifactId>
          <version>1.3.0</version>
        </dependency>

        <!-- Curated third-party versions -->
        <dependency>
          <groupId>com.fasterxml.jackson.core</groupId>
          <artifactId>jackson-databind</artifactId>
          <version>${jackson.version}</version>
        </dependency>
        <dependency>
          <groupId>org.testcontainers</groupId>
          <artifactId>testcontainers-bom</artifactId>
          <version>${testcontainers.version}</version>
          <type>pom</type>
          <scope>import</scope>
        </dependency>

      </dependencies>
    </dependencyManagement>

  </project>

  Using this BOM in a project:
  ────────────────────────────
  <dependencyManagement>
    <dependencies>
      <dependency>
        <groupId>com.example</groupId>
        <artifactId>company-bom</artifactId>
        <version>1.5.0</version>
        <type>pom</type>
        <scope>import</scope>
      </dependency>
    </dependencies>
  </dependencyManagement>

─────────────────────────────────────────────────────────────────────────────────
BOM vs PARENT POM (spring-boot-starter-parent)
─────────────────────────────────────────────────────────────────────────────────

  Spring provides two ways to integrate its dependency management:

  Option A: Inherit from spring-boot-starter-parent
  ──────────────────────────────────────────────────
  <parent>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-parent</artifactId>
    <version>3.2.0</version>
  </parent>

  What you get EXTRA (beyond just the BOM):
  ✔ Java version configured (source/target)
  ✔ UTF-8 encoding set
  ✔ Resource filtering configured (uses @...@ delimiters)
  ✔ Surefire/Failsafe configured
  ✔ spring-boot-maven-plugin configured with repackage

  LIMITATION: Java only has single inheritance. If you use this, you can't
  extend your company's parent POM.

  Option B: Import spring-boot-dependencies BOM
  ──────────────────────────────────────────────
  <dependencyManagement>
    <dependencies>
      <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-dependencies</artifactId>
        <version>3.2.0</version>
        <type>pom</type>
        <scope>import</scope>
      </dependency>
    </dependencies>
  </dependencyManagement>

  What you get: ONLY the dependency version management
  What you must configure manually: Java version, encoding, plugins

  USE CASE:
  • Simple project → use spring-boot-starter-parent
  • Enterprise multi-module with company parent → use BOM import

─────────────────────────────────────────────────────────────────────────────────
MULTIPLE BOM IMPORTS — ORDER MATTERS
─────────────────────────────────────────────────────────────────────────────────

  You can import multiple BOMs. If the same artifact appears in multiple BOMs,
  the FIRST import wins:

  <dependencyManagement>
    <dependencies>
      <!-- If spring-boot-dependencies and spring-cloud-dependencies both define
           a version for an artifact, spring-boot-dependencies wins here -->
      <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-dependencies</artifactId>
        <version>3.2.0</version>
        <type>pom</type>
        <scope>import</scope>
      </dependency>
      <dependency>
        <groupId>org.springframework.cloud</groupId>
        <artifactId>spring-cloud-dependencies</artifactId>
        <version>2023.0.0</version>
        <type>pom</type>
        <scope>import</scope>
      </dependency>
    </dependencies>
  </dependencyManagement>

  Best practice: Declare the most authoritative/specific BOM FIRST.

  OVERRIDE: You can always override a BOM version by declaring the dependency
  explicitly ABOVE the BOM import (explicit declarations in dependencyManagement
  always win over imported BOM versions):

  <dependencyManagement>
    <dependencies>
      <!-- This explicit version overrides anything in the BOM below -->
      <dependency>
        <groupId>com.fasterxml.jackson.core</groupId>
        <artifactId>jackson-databind</artifactId>
        <version>2.16.1</version>  <!-- override BOM version -->
      </dependency>
      <!-- BOM import after the explicit override -->
      <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-dependencies</artifactId>
        <version>3.2.0</version>
        <type>pom</type>
        <scope>import</scope>
      </dependency>
    </dependencies>
  </dependencyManagement>

FLATTEN MAVEN PLUGIN — DISTRIBUTING BOMs
─────────────────────────────────────────────────────────────────────────────────

  When you publish a BOM that uses ${revision} or other CI-friendly versioning,
  the flatten plugin "resolves" all variables in the POM before publishing:

  <plugin>
    <groupId>org.codehaus.mojo</groupId>
    <artifactId>flatten-maven-plugin</artifactId>
    <version>1.5.0</version>
    <configuration>
      <flattenMode>bom</flattenMode>   <!-- Special mode for BOM flattening -->
    </configuration>
    <executions>
      <execution>
        <id>flatten</id>
        <phase>process-resources</phase>
        <goals><goal>flatten</goal></goals>
      </execution>
      <execution>
        <id>flatten.clean</id>
        <phase>clean</phase>
        <goals><goal>clean</goal></goals>
      </execution>
    </executions>
  </plugin>

INTERVIEW QUICK-HITS
─────────────────────────────────────────────────────────────────────────────────

Q: What is a Maven BOM?
A: A Bill of Materials is a POM file (packaging=pom) that centralizes dependency
   version management. It defines a set of curated, compatible versions for a group
   of related dependencies. By importing a BOM into <dependencyManagement>, projects
   can declare dependencies without specifying versions.

Q: What is the difference between spring-boot-starter-parent and spring-boot-dependencies?
A: spring-boot-starter-parent is a parent POM that provides both dependency version
   management AND build configuration (Java version, encoding, plugin config).
   spring-boot-dependencies is just a BOM — it only provides version management.
   Use starter-parent for simple projects; import the BOM when you have your own
   parent POM you need to extend.

Q: How do you override a version from an imported BOM?
A: Declare the dependency explicitly in <dependencyManagement> BEFORE the BOM import.
   Explicit declarations in dependencyManagement always take precedence over BOM imports.

Q: Can you import multiple BOMs?
A: Yes. Import them in order of priority — if the same artifact appears in multiple
   BOMs, the first import wins. You can override specific versions by declaring them
   explicitly before any BOM imports.

Q: What packaging type must a BOM have?
A: <packaging>pom</packaging>. A BOM is a "pom artifact" — it has no compiled code,
   just POM metadata. When you import it with <type>pom</type><scope>import</scope>,
   Maven merges its <dependencyManagement> section into yours.
