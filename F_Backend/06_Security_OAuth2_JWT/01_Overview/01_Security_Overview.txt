================================================================
SECURITY OVERVIEW — Web Application & API Security
================================================================

WHAT IS SECURITY?
-----------------
Security in software refers to protecting systems, data, and resources from
unauthorized access, misuse, modification, or destruction. It encompasses:
  - Confidentiality  : only authorized parties can access data
  - Integrity        : data is not tampered with
  - Availability     : systems are available when needed (CIA Triad)

WHY DOES SECURITY MATTER?
--------------------------
- Data breaches cost organizations millions (GDPR fines, reputation damage)
- APIs are the most targeted attack surface in modern apps
- Misconfigured security is the #1 cause of breaches (OWASP Top 10)

CORE PILLARS OF APPLICATION SECURITY
--------------------------------------
1. Authentication  — Who are you? (verify identity)
2. Authorization   — What can you do? (enforce permissions)
3. Encryption      — Protect data in transit and at rest
4. Input Validation — Prevent injection attacks
5. Auditing/Logging — Detect and investigate incidents
6. Principle of Least Privilege — Give minimum necessary access

SECURITY LAYERS (Defense in Depth)
------------------------------------
Layer 1: Network Security    — Firewalls, WAF, DDoS protection
Layer 2: Transport Security  — TLS/HTTPS
Layer 3: Application Security— Input validation, output encoding
Layer 4: Authentication      — OAuth2, OIDC, MFA
Layer 5: Authorization       — RBAC, ABAC, Scopes
Layer 6: Data Security       — Encryption at rest, masking

OWASP TOP 10 (2021)
---------------------
A01 - Broken Access Control       ← #1 threat
A02 - Cryptographic Failures
A03 - Injection (SQL, LDAP, OS)
A04 - Insecure Design
A05 - Security Misconfiguration
A06 - Vulnerable & Outdated Components
A07 - Identification & Authentication Failures
A08 - Software & Data Integrity Failures
A09 - Security Logging & Monitoring Failures
A10 - Server-Side Request Forgery (SSRF)

KEY SECURITY CONCEPTS
-----------------------
THREAT         : A potential cause of an unwanted incident
VULNERABILITY  : A weakness that can be exploited
EXPLOIT        : Code or method that takes advantage of a vulnerability
ATTACK SURFACE : All possible ways an attacker can interact with a system
ZERO-DAY       : Unknown vulnerability with no patch available
PENETRATION TEST: Authorized simulated attack to find vulnerabilities
CVE            : Common Vulnerabilities and Exposures (public database)

SECURITY IN MICROSERVICES
---------------------------
- Each service should authenticate/authorize independently
- Use service mesh (Istio/Linkerd) for mTLS between services
- API Gateway enforces authentication at the edge
- Secrets management via Vault or cloud KMS
- Zero Trust Network Architecture: never trust, always verify

INTERVIEW TIPS
--------------
Q: What is the CIA Triad?
A: Confidentiality (only authorized access), Integrity (data not tampered),
   Availability (system accessible when needed).

Q: What is defense in depth?
A: Layered security approach — multiple independent controls so a breach of
   one layer does not compromise the entire system.

Q: What is the principle of least privilege?
A: Grant only the minimum permissions required to perform a function. Reduces
   blast radius of a compromised account/service.

Q: How is security different in a microservices architecture?
A: Each service is an attack surface. Services need to authenticate each other
   (mTLS or JWT), secrets must be managed centrally, and zero-trust is the
   recommended model — trust no one implicitly, even internal traffic.
