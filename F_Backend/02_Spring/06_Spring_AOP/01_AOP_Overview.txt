  1. WHAT IS AOP?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Aspect-Oriented Programming (AOP) is a programming paradigm that
addresses cross-cutting concerns — functionality that is needed in
many places across the application but does not belong to any single
class's core responsibility.

Cross-cutting concerns:
  - Logging and auditing
  - Security / authorization checks
  - Transaction management (@Transactional)
  - Performance monitoring
  - Caching (@Cacheable)
  - Error handling
  - Rate limiting

Without AOP:
  public class OrderService {
      public Order placeOrder(OrderRequest req) {
          logger.info("placeOrder called");                    // logging
          securityCheck(req.getUserId());                      // security
          long start = System.currentTimeMillis();              // timing
          Order order = /* business logic */;
          auditLog.record("ORDER_PLACED", order.getId());      // audit
          logger.info("placeOrder done in {}ms", ...);         // logging
          return order;
      }
  }

With AOP:
  public class OrderService {
      public Order placeOrder(OrderRequest req) {
          return /* pure business logic */;  // clean!
      }
  }
  // Logging, security, timing moved to Aspects

  2. KEY AOP TERMINOLOGY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Term            | Definition
  ────────────────┼──────────────────────────────────────────────────────
  Aspect          | Module encapsulating a cross-cutting concern (class)
  Advice          | The ACTION to take (before/after/around a method)
  Pointcut        | PREDICATE that identifies where advice applies
  Join Point      | A specific point in execution (method call, field access)
  Target          | The original bean being proxied
  Weaving         | Process of applying aspects to the target code
  Proxy           | Wrapper created by Spring around the target bean
  Introduction    | Adding new methods/fields to existing classes

In Spring AOP:
  - Join points are limited to METHOD EXECUTIONS (not field access)
  - Weaving happens at runtime via proxies (not compile-time)
  - Only Spring-managed beans can be advised

  3. SPRING AOP VS ASPECTJ
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Feature              | Spring AOP          | Full AspectJ
  ─────────────────────┼─────────────────────┼─────────────────────────────
  Weaving              | Runtime (proxy)     | Compile-time / load-time
  Join point types     | Method execution    | Method, field, constructor,
                       |                     | static init, exception handler
  Performance overhead | Small (proxy call)  | Minimal (bytecode woven)
  Self-invocation      | ❌ Not supported    | ✅ Supported
  Spring integration   | Native              | Via @EnableAspectJAutoProxy
  Complexity           | Simple              | Complex

Spring AOP uses AspectJ ANNOTATIONS but NOT the AspectJ weaver.
It uses AspectJ's pointcut expression language only for defining
pointcuts, while actual interception is done via JDK/CGLIB proxies.

  4. ENABLING AOP
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Spring Boot automatically enables AOP when:
  - spring-boot-starter-aop is on the classpath
  - OR any class has @Aspect

Dependency:
  <dependency>
      <groupId>org.springframework.boot</groupId>
      <artifactId>spring-boot-starter-aop</artifactId>
  </dependency>

Explicit enabling (not needed in Boot):
  @Configuration
  @EnableAspectJAutoProxy(proxyTargetClass = true)
  public class AopConfig {}

  5. ADVICE TYPES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  @Before         → runs BEFORE the method
  @After          → runs AFTER (whether exception or not) — like finally
  @AfterReturning → runs AFTER SUCCESSFUL return (accesses return value)
  @AfterThrowing  → runs AFTER exception is thrown (accesses exception)
  @Around         → wraps the method — most powerful, controls execution

Execution order (normal flow):
  @Around (before proceed)
    @Before
      METHOD EXECUTES
    @AfterReturning / @AfterThrowing
  @After
  @Around (after proceed)

Q: What is Aspect-Oriented Programming?
A: AOP is a paradigm that separates cross-cutting concerns (logging,
   security, transactions) from business logic. These concerns are
   modularized in Aspects, which are applied to designated methods
   (join points) based on predicates (pointcuts) without modifying
   the original code.

Q: What is the difference between Spring AOP and AspectJ?
A: Spring AOP uses runtime proxies and only supports method-level
   join points on Spring beans. AspectJ uses compile-time or load-time
   bytecode weaving and supports all join point types (fields,
   constructors, etc.). Spring uses AspectJ annotation syntax
   (@Aspect, @Before, etc.) but not the AspectJ weaver.

Q: What types of cross-cutting concerns does Spring AOP handle natively?
A: @Transactional (transaction management), @Cacheable/@CacheEvict
   (caching), @Async (async execution), @Scheduled (scheduling),
   @PreAuthorize (security). All of these are implemented via AOP.

Q: What are the limitations of Spring AOP?
A: (1) Only method execution join points (not fields, constructors).
   (2) Only works on Spring-managed beans.
   (3) Self-invocation (calling a method within the same class) bypasses
   the proxy — aspect advice is not applied. Fix: inject the bean
   from context or use compile-time AspectJ weaving.
