Both Filters and Interceptors provide hooks to execute code BEFORE
and AFTER an HTTP request reaches your controller logic.

Common use-cases:
  • Authentication / Authorization checks
  • Logging & audit trails
  • Request/Response transformation (compression, encoding)
  • CORS handling
  • Rate limiting
  • Caching headers
  • Request ID / Correlation ID injection

  2. SERVLET FILTER  (javax.servlet.Filter / jakarta.servlet.Filter)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

2.1 What is a Filter?
  • Part of the Servlet spec — NOT Spring-specific.
  • Lives at the Servlet Container level (Tomcat, Jetty, etc.)
  • Executes BEFORE the DispatcherServlet even sees the request.
  • Can intercept ANY servlet request, not just Spring MVC handlers.
  • Works with raw HttpServletRequest / HttpServletResponse.

2.2 Filter Lifecycle
  1. init(FilterConfig)   – called once at startup
  2. doFilter(request, response, chain) – called per request
  3. destroy()            – called at shutdown

2.3 Filter Interface

  public interface Filter {
      default void init(FilterConfig filterConfig) throws ServletException {}

      void doFilter(ServletRequest request,
                    ServletResponse response,
                    FilterChain chain)
              throws IOException, ServletException;

      default void destroy() {}
  }

2.4 Key Pattern in doFilter()

  @Override
  public void doFilter(ServletRequest request,
                       ServletResponse response,
                       FilterChain chain) throws IOException, ServletException {
      // PRE-PROCESSING (before controller)
      HttpServletRequest httpReq = (HttpServletRequest) request;
      System.out.println("Incoming: " + httpReq.getMethod() + " " + httpReq.getRequestURI());

      chain.doFilter(request, response);   // passes to next filter / DispatcherServlet

      // POST-PROCESSING (after controller, before response sent)
      HttpServletResponse httpResp = (HttpServletResponse) response;
      httpResp.setHeader("X-Custom-Header", "value");
  }

2.5 Registering Filters in Spring Boot

  Option A — @Component (applies to all URLs):
    @Component
    @Order(1)
    public class LoggingFilter implements Filter { ... }

  Option B — FilterRegistrationBean (full control):
    @Bean
    public FilterRegistrationBean<MyFilter> myFilter() {
        FilterRegistrationBean<MyFilter> reg = new FilterRegistrationBean<>();
        reg.setFilter(new MyFilter());
        reg.addUrlPatterns("/api/*");
        reg.setOrder(1);
        return reg;
    }

  Option C — @WebFilter + @ServletComponentScan:
    @WebFilter(urlPatterns = "/api/*")
    public class MyFilter implements Filter { ... }

    // Main class:
    @SpringBootApplication
    @ServletComponentScan
    public class App { ... }

2.6 OncePerRequestFilter (Spring convenience class)
  Guarantees the filter runs only once per request (important with
  async / forward scenarios). Most Spring Security filters extend this.

  @Component
  public class CorrelationIdFilter extends OncePerRequestFilter {
      @Override
      protected void doFilterInternal(HttpServletRequest request,
                                      HttpServletResponse response,
                                      FilterChain filterChain)
              throws ServletException, IOException {
          String correlationId = UUID.randomUUID().toString();
          response.setHeader("X-Correlation-ID", correlationId);
          MDC.put("correlationId", correlationId);
          try {
              filterChain.doFilter(request, response);
          } finally {
              MDC.remove("correlationId");
          }
      }
  }

  3. SPRING MVC INTERCEPTOR (HandlerInterceptor)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

3.1 What is an Interceptor?
  • Spring MVC specific — runs INSIDE the DispatcherServlet pipeline.
  • Has access to the resolved Handler (controller method), ModelAndView.
  • Three callback points:
      preHandle  → before the controller executes
      postHandle → after controller, before view rendering
      afterCompletion → after view rendered (always called if preHandle returned true)

3.2 HandlerInterceptor Interface

  public interface HandlerInterceptor {

      // Return TRUE to continue chain, FALSE to abort (send response yourself)
      default boolean preHandle(HttpServletRequest request,
                                HttpServletResponse response,
                                Object handler) throws Exception {
          return true;
      }

      // Only called if preHandle returned true AND controller completed normally
      default void postHandle(HttpServletRequest request,
                              HttpServletResponse response,
                              Object handler,
                              ModelAndView modelAndView) throws Exception {}

      // Always called if preHandle returned true (even if exception was thrown)
      default void afterCompletion(HttpServletRequest request,
                                   HttpServletResponse response,
                                   Object handler,
                                   Exception ex) throws Exception {}
  }

3.3 Example — Execution Time Logger

  @Component
  public class TimingInterceptor implements HandlerInterceptor {

      private static final String START_TIME = "startTime";

      @Override
      public boolean preHandle(HttpServletRequest request,
                               HttpServletResponse response,
                               Object handler) {
          request.setAttribute(START_TIME, System.currentTimeMillis());
          return true;
      }

      @Override
      public void afterCompletion(HttpServletRequest request,
                                  HttpServletResponse response,
                                  Object handler, Exception ex) {
          long start = (Long) request.getAttribute(START_TIME);
          long elapsed = System.currentTimeMillis() - start;
          System.out.printf("Handler [%s] took %d ms%n", handler, elapsed);
      }
  }

3.4 Registering Interceptors

  @Configuration
  public class WebConfig implements WebMvcConfigurer {

      @Autowired
      private TimingInterceptor timingInterceptor;

      @Override
      public void addInterceptors(InterceptorRegistry registry) {
          registry.addInterceptor(timingInterceptor)
                  .addPathPatterns("/api/**")
                  .excludePathPatterns("/api/health", "/api/public/**")
                  .order(1);
      }
  }

  4. FILTER vs INTERCEPTOR — DETAILED COMPARISON
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Feature                  | Filter                    | Interceptor
  ─────────────────────────┼───────────────────────────┼────────────────────────────
  Spec                     | Servlet spec (J2EE/Jakarta)| Spring MVC
  Execution layer          | Before DispatcherServlet  | Inside DispatcherServlet
  Access to Spring beans   | Via ApplicationContext     | Native (Spring-managed)
  Access to Handler info   | No                        | Yes (HandlerMethod)
  Access to ModelAndView   | No                        | Yes (postHandle)
  Scope                    | All requests (any servlet)| Only Spring MVC requests
  Exception handling       | Must catch manually        | afterCompletion gets Exception
  Short-circuit request    | Yes (not call chain)      | Return false from preHandle
  URL pattern config       | FilterRegistrationBean     | InterceptorRegistry
  Order                    | @Order / setOrder()        | .order() in registry
  Can wrap request/response| Yes (wrapping decorators)  | No (limited)

6.1 Request Logging Filter

  @Component
  @Order(Ordered.HIGHEST_PRECEDENCE)
  public class RequestLoggingFilter extends OncePerRequestFilter {

      private static final Logger log = LoggerFactory.getLogger(RequestLoggingFilter.class);

      @Override
      protected void doFilterInternal(HttpServletRequest request,
                                      HttpServletResponse response,
                                      FilterChain chain) throws ServletException, IOException {
          long start = System.currentTimeMillis();
          try {
              chain.doFilter(request, response);
          } finally {
              long duration = System.currentTimeMillis() - start;
              log.info("{} {} {} {}ms",
                      request.getMethod(),
                      request.getRequestURI(),
                      response.getStatus(),
                      duration);
          }
      }
  }

6.2 Authentication Interceptor (check JWT header, no Spring Security)

  @Component
  public class AuthInterceptor implements HandlerInterceptor {

      @Autowired
      private TokenService tokenService;

      @Override
      public boolean preHandle(HttpServletRequest request,
                               HttpServletResponse response,
                               Object handler) throws Exception {
          // Skip non-controller resources
          if (!(handler instanceof HandlerMethod)) return true;

          // Check for @Public annotation → allow through
          HandlerMethod hm = (HandlerMethod) handler;
          if (hm.hasMethodAnnotation(Public.class)) return true;

          String authHeader = request.getHeader("Authorization");
          if (authHeader == null || !authHeader.startsWith("Bearer ")) {
              response.sendError(HttpServletResponse.SC_UNAUTHORIZED, "Missing token");
              return false;
          }
          String token = authHeader.substring(7);
          if (!tokenService.isValid(token)) {
              response.sendError(HttpServletResponse.SC_UNAUTHORIZED, "Invalid token");
              return false;
          }
          request.setAttribute("userId", tokenService.getUserId(token));
          return true;
      }
  }

6.3 Rate Limiting Filter

  @Component
  public class RateLimitFilter extends OncePerRequestFilter {

      // Simple in-memory (use Redis in production)
      private final Map<String, AtomicInteger> counts = new ConcurrentHashMap<>();
      private static final int MAX_REQUESTS_PER_MINUTE = 100;

      @Override
      protected void doFilterInternal(HttpServletRequest req,
                                      HttpServletResponse res,
                                      FilterChain chain) throws ServletException, IOException {
          String ip = req.getRemoteAddr();
          int count = counts.computeIfAbsent(ip, k -> new AtomicInteger()).incrementAndGet();
          if (count > MAX_REQUESTS_PER_MINUTE) {
              res.setStatus(HttpStatus.TOO_MANY_REQUESTS.value());
              res.getWriter().write("Rate limit exceeded");
              return;
          }
          chain.doFilter(req, res);
      }
  }

6.4 Content Caching — Read Request Body Multiple Times

  // Problem: HttpServletRequest.getInputStream() can only be read once.
  // Solution: Wrap with ContentCachingRequestWrapper.

  @Component
  public class CachingFilter extends OncePerRequestFilter {
      @Override
      protected void doFilterInternal(HttpServletRequest request,
                                      HttpServletResponse response,
                                      FilterChain chain) throws ServletException, IOException {
          ContentCachingRequestWrapper wrappedRequest =
                  new ContentCachingRequestWrapper(request);
          ContentCachingResponseWrapper wrappedResponse =
                  new ContentCachingResponseWrapper(response);

          chain.doFilter(wrappedRequest, wrappedResponse);

          // Log request body after filter chain
          byte[] requestBody = wrappedRequest.getContentAsByteArray();
          System.out.println("Request body: " + new String(requestBody));

          // Must copy response body back!
          wrappedResponse.copyBodyToResponse();
      }
  }

  7. ORDERING FILTERS AND INTERCEPTORS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Filter ordering:
  • Lower number = runs FIRST (processes request first, processes response last)
  • Use Ordered.HIGHEST_PRECEDENCE (Integer.MIN_VALUE) for absolute first
  • @Order(1), @Order(2), ... or reg.setOrder(n)

Interceptor ordering:
  • Registered in order of addInterceptor() calls
  • preHandle: order 1→2→3
  • postHandle: reverse order 3→2→1
  • afterCompletion: reverse order 3→2→1

  Recommended filter order for a typical app:
    1. CorrelationId / TraceId filter (HIGHEST_PRECEDENCE)
    2. Request Logging filter
    3. Rate Limiting filter
    4. Security filters (Spring Security handles its own chain)

  8. WHEN TO USE FILTER vs INTERCEPTOR
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Use FILTER when:
    • You need to intercept ALL requests (including static resources)
    • You need to wrap/modify the request or response stream
    • You're doing low-level work (GZIP compression, multipart parsing)
    • You want to handle cross-cutting concerns at the Servlet container level
    • You are implementing Spring Security-like authentication
    • Cross-origin (CORS) handling

  Use INTERCEPTOR when:
    • You need access to the resolved controller/handler
    • You need to check method-level annotations (@RoleRequired, etc.)
    • You want to add data to the Model (for MVC views)
    • You want to measure controller-specific execution times
    • You want to interact with Spring's ModelAndView

  9. SPRING SECURITY FILTER CHAIN
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Spring Security is implemented entirely as a chain of filters.
The main filter is FilterChainProxy (delegated to from DelegatingFilterProxy).

Key built-in filters in order:
  1.  SecurityContextPersistenceFilter   – restores SecurityContext from session
  2.  WebAsyncManagerIntegrationFilter   – async support
  3.  HeaderWriterFilter                 – security headers (X-Frame-Options, etc.)
  4.  CorsFilter                         – CORS
  5.  CsrfFilter                         – CSRF token check
  6.  LogoutFilter                       – handles /logout
  7.  UsernamePasswordAuthenticationFilter – form login
  8.  BasicAuthenticationFilter          – HTTP Basic
  9.  BearerTokenAuthenticationFilter    – OAuth2 Bearer
  10. RequestCacheAwareFilter
  11. SecurityContextHolderAwareRequestFilter
  12. AnonymousAuthenticationFilter      – sets anonymous user if no auth
  13. SessionManagementFilter
  14. ExceptionTranslationFilter         – converts security exceptions → HTTP 401/403
  15. AuthorizationFilter                – final authorization decision

  10. INTERVIEW QUESTIONS & ANSWERS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q1: What is the difference between a Filter and an Interceptor?
  A: Filter is a Servlet API component that executes before the
     DispatcherServlet; it can handle ALL URLs. Interceptor is a
     Spring MVC component that runs inside DispatcherServlet; it
     has access to the handler (controller method) and ModelAndView.

Q2: Can a Filter access Spring beans?
  A: Yes — a Filter registered as @Component is itself a Spring bean
     and can @Autowire other beans. Alternatively, use
     WebApplicationContextUtils.getWebApplicationContext(filterConfig
     .getServletContext()) to get the context.

Q3: What is OncePerRequestFilter? Why use it?
  A: It's an abstract Spring class that ensures doFilter runs only
     once per request. Without it, in async dispatch or forward
     scenarios, the filter could be invoked multiple times.

Q4: How do you abort a request in a Filter vs Interceptor?
  A: In a Filter: simply do NOT call chain.doFilter(); write
     directly to the response.
     In an Interceptor: return false from preHandle(); the
     DispatcherServlet will not proceed.

Q5: In what order are multiple interceptors executed?
  A: preHandle is called in registration order; postHandle and
     afterCompletion are called in reverse registration order
     (like a stack).

Q6: What happens if preHandle throws an exception?
  A: The exception propagates through the interceptor chain;
     afterCompletion is NOT called for that interceptor.
     afterCompletion IS called for interceptors where preHandle
     returned true successfully.

Q7: Can you read the request body in a Filter?
  A: The InputStream can be read only once. To re-read it,
     wrap the request with ContentCachingRequestWrapper and call
     getContentAsByteArray() after the filter chain completes.

Q8: What is DelegatingFilterProxy?
  A: A Servlet Filter that acts as a bridge between the Servlet
     container and a Spring-managed bean. It delegates doFilter()
     calls to a Spring bean named "springSecurityFilterChain"
     (FilterChainProxy). This lets Spring Security filters be
     managed as Spring beans while still being servlet filters.

Q9: How do you apply a filter to specific URL patterns?
  A: Use FilterRegistrationBean.addUrlPatterns("/api/*") or
     @WebFilter(urlPatterns="/api/*").

Q10: How is CORS best implemented — filter or interceptor?
  A: As a Filter (or use Spring's CorsFilter/CorsConfigurationSource).
     CORS preflight OPTIONS requests may not reach the DispatcherServlet
     (Spring Security intercepts them earlier), so a Filter guarantees
     early handling.
