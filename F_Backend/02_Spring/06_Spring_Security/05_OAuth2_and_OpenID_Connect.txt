  1. OAUTH2 OVERVIEW
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

OAuth2 = Authorization framework (RFC 6749)
  - Allows third-party applications to access protected resources
    on behalf of a user WITHOUT sharing credentials
  - Delegates authorization to an Authorization Server

Roles:
  Resource Owner  → the user (grants access)
  Client          → the application requesting access
  Authorization Server → issues access tokens (e.g., Google, Okta, Keycloak)
  Resource Server → hosts protected resources, validates tokens

OpenID Connect (OIDC) = Authentication layer ON TOP of OAuth2
  - Adds an ID Token (JWT) for authentication
  - Provides /userinfo endpoint for profile data
  - Enables SSO (Single Sign-On)
  - OAuth2 → Authorization, OIDC → Authentication

  2. OAUTH2 GRANT TYPES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Grant Type               | Use Case
  ─────────────────────────┼────────────────────────────────────────────
  Authorization Code       | Web apps (server-side redirect) — SECURE
  Authorization Code + PKCE| SPAs, mobile apps — SECURE (no secret)
  Client Credentials       | Machine-to-machine (no user context)
  Device Authorization     | Smart TVs, CLIs (limited input)
  Refresh Token            | Getting new access tokens
  ~~Implicit~~             | DEPRECATED — replaced by PKCE
  ~~Resource Owner Password~~| DEPRECATED — insecure

Authorization Code Flow (most common):
  1. User clicks "Login with Google"
  2. App redirects to AS: /authorize?response_type=code&client_id=...&redirect_uri=...
  3. User authenticates at AS (Google)
  4. AS redirects back to app with ?code=AUTH_CODE
  5. App POSTs to /token: code + client_id + client_secret
  6. AS returns: { access_token, id_token, refresh_token }
  7. App uses access_token to call Resource Server

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-oauth2-client</artifactId>
</dependency>

application.properties:
  spring.security.oauth2.client.registration.google.client-id=YOUR_CLIENT_ID
  spring.security.oauth2.client.registration.google.client-secret=YOUR_SECRET
  spring.security.oauth2.client.registration.google.scope=openid,email,profile
  spring.security.oauth2.client.registration.google.redirect-uri={baseUrl}/login/oauth2/code/{registrationId}

  spring.security.oauth2.client.registration.github.client-id=...
  spring.security.oauth2.client.registration.github.client-secret=...

Security config:
  @Bean
  public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
      http
          .authorizeHttpRequests(a -> a
              .requestMatchers("/", "/login").permitAll()
              .anyRequest().authenticated())
          .oauth2Login(oauth2 -> oauth2
              .loginPage("/login")
              .defaultSuccessUrl("/dashboard")
              .userInfoEndpoint(ui -> ui
                  .userService(customOAuth2UserService)));  // custom user loading
      return http.build();
  }

  @Service
  public class CustomOAuth2UserService extends DefaultOAuth2UserService {
      @Override
      public OAuth2User loadUser(OAuth2UserRequest request)
              throws OAuth2AuthenticationException {
          OAuth2User oAuth2User = super.loadUser(request);
          // Create/update user in your DB
          String email = oAuth2User.getAttribute("email");
          User user = userRepo.findByEmail(email)
              .orElseGet(() -> createNewUser(oAuth2User));
          return new SecurityUserOAuth2Adapter(user, oAuth2User.getAttributes());
      }
  }

  4. SPRING OAUTH2 RESOURCE SERVER (JWT Validation)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Used when your app validates JWTs issued by an external AS (Keycloak, Okta).

<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-oauth2-resource-server</artifactId>
</dependency>

application.properties:
  # Using JWK Set URI (fetches public keys from AS)
  spring.security.oauth2.resourceserver.jwt.jwk-set-uri=
      https://keycloak.example.com/realms/myrealm/protocol/openid-connect/certs

  # Or issuer URI (auto-discovers jwk-set-uri from /.well-known/openid-configuration)
  spring.security.oauth2.resourceserver.jwt.issuer-uri=
      https://keycloak.example.com/realms/myrealm

Security config:
  @Bean
  public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
      http
          .authorizeHttpRequests(a -> a
              .requestMatchers("/api/public/**").permitAll()
              .anyRequest().authenticated())
          .oauth2ResourceServer(oauth2 -> oauth2
              .jwt(jwt -> jwt.jwtAuthenticationConverter(jwtAuthConverter())));
      return http.build();
  }

  @Bean
  public JwtAuthenticationConverter jwtAuthConverter() {
      JwtGrantedAuthoritiesConverter converter = new JwtGrantedAuthoritiesConverter();
      converter.setAuthoritiesClaimName("roles");         // Keycloak claim name
      converter.setAuthorityPrefix("ROLE_");

      JwtAuthenticationConverter jwtConverter = new JwtAuthenticationConverter();
      jwtConverter.setJwtGrantedAuthoritiesConverter(converter);
      return jwtConverter;
  }

Used for service-to-service calls with no user context.

application.properties:
  spring.security.oauth2.client.registration.my-service.client-id=service-a
  spring.security.oauth2.client.registration.my-service.client-secret=secret
  spring.security.oauth2.client.registration.my-service.authorization-grant-type=client_credentials
  spring.security.oauth2.client.registration.my-service.scope=api.read
  spring.security.oauth2.client.provider.my-as.token-uri=https://as.example.com/token

  // WebClient with auto token injection
  @Bean
  public WebClient webClient(OAuth2AuthorizedClientManager manager) {
      ServletOAuth2AuthorizedClientExchangeFilterFunction oauth2 =
          new ServletOAuth2AuthorizedClientExchangeFilterFunction(manager);
      oauth2.setDefaultClientRegistrationId("my-service");
      return WebClient.builder().apply(oauth2.oauth2Configuration()).build();
  }

Spring Authorization Server (since 0.1.0) lets you build your
own OAuth2/OIDC authorization server:

<dependency>
    <groupId>org.springframework.security</groupId>
    <artifactId>spring-security-oauth2-authorization-server</artifactId>
</dependency>

Exposes standard endpoints:
  /oauth2/authorize   → Authorization endpoint
  /oauth2/token       → Token endpoint
  /oauth2/introspect  → Token introspection
  /oauth2/revoke      → Token revocation
  /.well-known/openid-configuration → OIDC discovery

Q: What is the difference between OAuth2 and OpenID Connect?
A: OAuth2 is an authorization framework — it grants access to
   resources without sharing credentials. It does NOT define identity.
   OpenID Connect (OIDC) is an authentication layer built on OAuth2 —
   it adds the concept of identity through an ID Token (JWT), /userinfo
   endpoint, and discovery document.

Q: When would you use Authorization Code flow vs Client Credentials?
A: Authorization Code is used when a user is involved — the user
   grants the application permission to access their data. Client
   Credentials is used for server-to-server (machine-to-machine)
   communication where there is no user context.

Q: What is PKCE and why is it needed?
A: PKCE (Proof Key for Code Exchange) is an extension to Authorization
   Code flow for public clients (SPAs, mobile) that cannot securely
   store a client_secret. The client generates a code_verifier and
   sends its hash (code_challenge). The AS verifies this on token
   exchange, preventing authorization code interception attacks.

Q: What is a Resource Server in OAuth2?
A: The server that hosts protected resources and validates access tokens.
   In Spring, spring-boot-starter-oauth2-resource-server configures
   your API to validate JWTs (checking signature, expiry, issuer)
   issued by an external authorization server.

Q: How does Spring Resource Server validate JWT tokens?
A: By fetching the JWK Set (public keys) from the AS's JWK URI
   (configured via jwk-set-uri or derived from issuer-uri via
   OpenID Connect discovery). Tokens are validated against these
   public keys using the algorithm specified in the JWT header.

Q: What is the JwtAuthenticationConverter used for?
A: It converts a validated JWT into a Spring Authentication object.
   Specifically, it extracts roles/scopes from the JWT claims and
   maps them to GrantedAuthority objects so that @PreAuthorize and
   hasRole() checks work against Keycloak/Okta roles.
