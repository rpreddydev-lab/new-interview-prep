  1. WHAT IS SPRING SECURITY?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Spring Security is a powerful, highly customizable authentication and
access-control framework for Spring applications. It is the de-facto
standard for securing Spring-based applications.

Core capabilities:
  - Authentication    → Who are you? (identity verification)
  - Authorization     → What can you do? (access control)
  - Protection        → CSRF, CORS, clickjacking, session fixation
  - Cryptography      → Password encoding, key management
  - OAuth2 / OIDC     → Social login, resource server, authorization server
  - Method Security   → @PreAuthorize, @PostAuthorize on service methods

  2. CORE CONCEPTS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Concept                      | Description
  ─────────────────────────────┼─────────────────────────────────────────
  SecurityContext              | Thread-local container for Authentication
  SecurityContextHolder        | Stores/retrieves the SecurityContext
  Authentication               | Represents the currently logged-in user
  Principal                    | Core identity (usually UserDetails)
  GrantedAuthority             | Single permission/role (e.g., ROLE_ADMIN)
  UserDetails                  | Interface for user information
  UserDetailsService           | Loads UserDetails by username
  PasswordEncoder              | Hashes and verifies passwords
  AuthenticationManager        | Orchestrates authentication
  AuthenticationProvider       | Performs actual authentication logic
  SecurityFilterChain          | Ordered chain of security filters

SecurityContext flow:
  HTTP Request
      │
  SecurityContextPersistenceFilter  ← loads SecurityContext from session
      │
  UsernamePasswordAuthenticationFilter (if form login)
      │  or
  BearerTokenAuthenticationFilter (if JWT)
      │
  SecurityContextHolder.setContext(SecurityContext)
      │
  Controller / Service
      │
  SecurityContextHolder.getContext().getAuthentication()
      │
  SecurityContextPersistenceFilter  ← saves SecurityContext to session

Once on classpath, Spring Boot auto-configures:
  - A single in-memory user (username: "user", password: random UUID printed to log)
  - All endpoints require authentication
  - Form login enabled
  - HTTP Basic enabled
  - CSRF protection enabled

  4. MINIMUM SECURITY CONFIGURATION (Spring Security 6.x)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

@Configuration
@EnableWebSecurity
public class SecurityConfig {

    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        http
            .csrf(csrf -> csrf.disable())              // disable for stateless APIs
            .sessionManagement(session -> session
                .sessionCreationPolicy(SessionCreationPolicy.STATELESS))
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/api/auth/**").permitAll()
                .requestMatchers("/api/admin/**").hasRole("ADMIN")
                .requestMatchers(HttpMethod.GET, "/api/products/**").permitAll()
                .anyRequest().authenticated()
            )
            .addFilterBefore(jwtAuthFilter, UsernamePasswordAuthenticationFilter.class);

        return http.build();
    }

    @Bean
    public AuthenticationManager authManager(
            AuthenticationConfiguration config) throws Exception {
        return config.getAuthenticationManager();
    }

    @Bean
    public UserDetailsService userDetailsService(UserRepository userRepo) {
        return username -> userRepo.findByEmail(username)
            .map(SecurityUserAdapter::new)
            .orElseThrow(() -> new UsernameNotFoundException("User not found: " + username));
    }

    @Bean
    public PasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder();
    }
}

  5. UserDetails AND UserDetailsService
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

// Adapter pattern — wrap your User entity
public class SecurityUserAdapter implements UserDetails {

    private final User user;

    public SecurityUserAdapter(User user) { this.user = user; }

    @Override
    public Collection<? extends GrantedAuthority> getAuthorities() {
        return user.getRoles().stream()
            .map(role -> new SimpleGrantedAuthority("ROLE_" + role.name()))
            .collect(Collectors.toList());
    }

    @Override public String getPassword() { return user.getPasswordHash(); }
    @Override public String getUsername() { return user.getEmail(); }
    @Override public boolean isAccountNonExpired() { return true; }
    @Override public boolean isAccountNonLocked() { return !user.isLocked(); }
    @Override public boolean isCredentialsNonExpired() { return true; }
    @Override public boolean isEnabled() { return user.isActive(); }
}

  6. ACCESSING CURRENT USER
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

// In any Spring component
Authentication auth = SecurityContextHolder.getContext().getAuthentication();
String username = auth.getName();
SecurityUserAdapter user = (SecurityUserAdapter) auth.getPrincipal();

// In controller via @AuthenticationPrincipal
@GetMapping("/me")
public UserResponse currentUser(
        @AuthenticationPrincipal SecurityUserAdapter user) {
    return new UserResponse(user.getUser());
}

// Via Principal (simpler)
@GetMapping("/me")
public String me(Principal principal) {
    return principal.getName();
}

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Spring Security 6 (Spring Boot 3.x) breaking changes:
  - WebSecurityConfigurerAdapter REMOVED → use SecurityFilterChain bean
  - authorizeRequests()  DEPRECATED → use authorizeHttpRequests()
  - antMatchers()        REMOVED → use requestMatchers()
  - mvcMatchers()        REMOVED → use requestMatchers()
  - Servlet API: javax.servlet → jakarta.servlet
  - Default CSRF: cookie-based CSRF token
  - matches() in RequestMatcher now uses PathPatternParser

Q: What happens when you add spring-boot-starter-security?
A: Spring Boot auto-configures a default SecurityFilterChain that:
   - Requires authentication for all endpoints
   - Enables HTTP Basic and form login
   - Enables CSRF protection
   - Generates a random password for the default "user" account
   - Logs the password on startup

Q: What is SecurityContextHolder?
A: A thread-local container that holds the SecurityContext for the
   current thread. The SecurityContext contains the Authentication
   object (identity + authorities). It is populated by authentication
   filters and cleared after each request.

Q: What is the role of UserDetailsService?
A: It is a single-method interface (loadUserByUsername) that Spring
   Security calls during authentication to load user details from
   any data source (DB, LDAP, etc.). You implement it to provide
   your application's user model to the security framework.

Q: What is the difference between Authentication and Principal?
A: Authentication extends Principal and represents the full
   authentication token — it contains the principal (identity),
   credentials (password — cleared after auth), and granted
   authorities (roles/permissions). Principal is just the identity
   part (usually the UserDetails object).

Q: What changed from WebSecurityConfigurerAdapter in Spring Security 6?
A: WebSecurityConfigurerAdapter was removed. Now you declare a
   @Bean of type SecurityFilterChain and use the HttpSecurity DSL.
   Also antMatchers/mvcMatchers were replaced with requestMatchers.
