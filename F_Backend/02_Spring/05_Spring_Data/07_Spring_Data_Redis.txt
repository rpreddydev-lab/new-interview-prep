  1. REDIS OVERVIEW
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Redis = Remote Dictionary Server
  - In-memory data structure store
  - Sub-millisecond read/write latency
  - Persistence options: RDB snapshots, AOF logging
  - Replication: master-replica
  - Clustering: automatic sharding

Data structures:
  String      → simple value, counters, locks, sessions
  Hash        → object fields (user profile)
  List        → ordered collection, queues
  Set         → unique members, tags, relationships
  Sorted Set  → leaderboards, priority queues
  Stream      → event log / message queue
  HyperLogLog → cardinality estimation
  Geo         → geospatial indexing

Use cases in Spring apps:
  - Caching (@Cacheable)
  - Session storage (Spring Session)
  - Rate limiting
  - Distributed locks (Redisson)
  - Pub/Sub messaging
  - Leaderboards / real-time counters

  3. RedisTemplate — LOW-LEVEL OPERATIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

@Configuration
public class RedisConfig {

    @Bean
    public RedisTemplate<String, Object> redisTemplate(
                                    RedisConnectionFactory factory) {
        RedisTemplate<String, Object> template = new RedisTemplate<>();
        template.setConnectionFactory(factory);

        // Key serializer — human-readable keys
        template.setKeySerializer(new StringRedisSerializer());
        template.setHashKeySerializer(new StringRedisSerializer());

        // Value serializer — JSON
        Jackson2JsonRedisSerializer<Object> jsonSerializer =
            new Jackson2JsonRedisSerializer<>(Object.class);
        template.setValueSerializer(jsonSerializer);
        template.setHashValueSerializer(jsonSerializer);

        template.afterPropertiesSet();
        return template;
    }
}

// Usage
@Service
public class CacheService {
    private final RedisTemplate<String, Object> redisTemplate;

    // String operations
    public void setString(String key, String value, long ttlSeconds) {
        redisTemplate.opsForValue()
            .set(key, value, Duration.ofSeconds(ttlSeconds));
    }

    public String getString(String key) {
        return (String) redisTemplate.opsForValue().get(key);
    }

    // Hash operations (good for objects)
    public void setUserField(String userId, String field, Object value) {
        redisTemplate.opsForHash().put("user:" + userId, field, value);
    }

    public Object getUserField(String userId, String field) {
        return redisTemplate.opsForHash().get("user:" + userId, field);
    }

    // List operations (queue / stack)
    public void pushToQueue(String queue, Object item) {
        redisTemplate.opsForList().rightPush(queue, item);
    }

    public Object popFromQueue(String queue) {
        return redisTemplate.opsForList().leftPop(queue);
    }

    // Sorted Set (leaderboard)
    public void updateScore(String board, String member, double score) {
        redisTemplate.opsForZSet().add(board, member, score);
    }

    public Set<Object> getTopN(String board, int n) {
        return redisTemplate.opsForZSet()
            .reverseRange(board, 0, (long) n - 1);
    }

    // TTL management
    public void expire(String key, long ttlSeconds) {
        redisTemplate.expire(key, Duration.ofSeconds(ttlSeconds));
    }

    public boolean exists(String key) {
        return Boolean.TRUE.equals(redisTemplate.hasKey(key));
    }

    public void delete(String key) {
        redisTemplate.delete(key);
    }
}

public class RedisPubSubConfig {

    @Bean
    public RedisMessageListenerContainer container(
            RedisConnectionFactory factory,
            MessageListenerAdapter listenerAdapter) {
        RedisMessageListenerContainer container = new RedisMessageListenerContainer();
        container.setConnectionFactory(factory);
        container.addMessageListener(listenerAdapter,
            new PatternTopic("orders.*"));  // subscribes to pattern
        return container;
    }

    @Bean
    public MessageListenerAdapter listenerAdapter(OrderEventListener listener) {
        return new MessageListenerAdapter(listener, "handleMessage");
    }
}

@Component
public class OrderEventListener {
    public void handleMessage(String message, String channel) {
        System.out.println("Received on " + channel + ": " + message);
    }
}

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Simple implementation with SET NX EX (SET if Not eXists + Expire):

  public boolean acquireLock(String lockKey, String ownerId, long ttlSeconds) {
      Boolean acquired = stringRedisTemplate.opsForValue()
          .setIfAbsent(lockKey, ownerId, Duration.ofSeconds(ttlSeconds));
      return Boolean.TRUE.equals(acquired);
  }

  public boolean releaseLock(String lockKey, String ownerId) {
      // Must check owner before release (Lua script for atomicity)
      String script = "if redis.call('get',KEYS[1])==ARGV[1] then " +
                      "return redis.call('del',KEYS[1]) else return 0 end";
      Long result = stringRedisTemplate.execute(
          new DefaultRedisScript<>(script, Long.class),
          List.of(lockKey), ownerId);
      return Long.valueOf(1L).equals(result);
  }

Production recommendation: use Redisson (implements Redlock algorithm):
  RLock lock = redisson.getLock("myLock");
  lock.lock(10, TimeUnit.SECONDS);
  try { /* critical section */ } finally { lock.unlock(); }

Q: What serializer should you use for RedisTemplate values?
A: Jackson2JsonRedisSerializer for objects (human-readable, inspectable
   with redis-cli). GenericJackson2JsonRedisSerializer adds type
   information to support polymorphism. JdkSerializationRedisSerializer
   (default) is opaque/binary — avoid unless you need Java-native
   serialization. StringRedisSerializer for string-only values.

Q: What is the difference between RedisTemplate and StringRedisTemplate?
A: StringRedisTemplate extends RedisTemplate<String, String> with
   String serializers pre-configured for both key and value.
   RedisTemplate<String, Object> is generic and requires explicit
   serializer configuration for values.

Q: How does Spring Data Redis Repository work internally?
A: @RedisHash objects are stored as Redis Hashes (HSET).
   The key is "hashName:id". @Indexed fields create secondary index
   sets (SET with all IDs having that value). TTL is set via EXPIRE.
   CrudRepository operations map to Redis commands (HGETALL, HSET, DEL).

Q: What is a TTL index in Redis and how do you set it?
A: TTL (Time-To-Live) is set on a key using EXPIRE command.
   Spring Data: @RedisHash(timeToLive = 3600). RedisTemplate:
   redisTemplate.expire(key, Duration.ofHours(1)). When TTL expires,
   Redis automatically evicts the key.

Q: What is the Redlock algorithm?
A: Redlock is a distributed locking algorithm for Redis clusters.
   It acquires a lock on a majority of N independent Redis nodes
   (e.g., 3 out of 5), ensuring the lock is safe even if some nodes
   fail. Implemented by the Redisson library for Spring.

Q: When would you use Redis Pub/Sub vs Redis Streams?
A: Pub/Sub is fire-and-forget — no message persistence, no consumer
   groups, messages lost if subscriber is offline. Streams persist
   messages, support consumer groups, acknowledgment, replay — like
   a lightweight Kafka. Use Pub/Sub for ephemeral events (invalidation
   signals), Streams for durable event processing.
