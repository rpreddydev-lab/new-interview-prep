WHAT IS SPRING BOOT?
================================================================

  Spring Boot is an opinionated, convention-over-configuration
  extension of the Spring Framework that makes it easy to:
    • Create stand-alone, production-grade Spring applications
    • Embed HTTP servers (Tomcat, Jetty, Undertow) — no WAR/EAR
    • Auto-configure Spring and third-party libraries
    • Provide production-ready features: metrics, health, config

  Released: 2014 (1.0), current major: 3.x (requires Java 17+)

================================================================
SPRING BOOT CORE FEATURES
================================================================

  Feature                | Description
  -----------------------|--------------------------------------------
  Auto-configuration     | Configures beans based on classpath/props
  Starter POMs           | Curated dependency bundles (spring-boot-starter-*)
  Embedded Server        | No external Tomcat needed; JAR includes it
  Actuator               | /actuator/health, /metrics, /env, etc.
  @SpringBootApplication | Single entry-point annotation
  Externalised Config    | application.properties/yaml, env vars, CLI args
  Developer Tools        | Hot reload (spring-boot-devtools)
  Spring Boot CLI        | Run Groovy scripts quickly

@SpringBootApplication — THE ENTRY POINT
================================================================

  @SpringBootApplication
  public class MyApp {
      public static void main(String[] args) {
          SpringApplication.run(MyApp.class, args);
      }
  }

  @SpringBootApplication is a composed annotation:
    @SpringBootConfiguration       // = @Configuration
    @EnableAutoConfiguration       // activate auto-config
    @ComponentScan                 // scan current package + sub-packages

  Customizing the component scan:
    @SpringBootApplication(scanBasePackages = "com.example")
    @SpringBootApplication(exclude = {DataSourceAutoConfiguration.class})

================================================================
SpringApplication.run() — WHAT HAPPENS
================================================================

  1. Creates a SpringApplication instance
  2. Detects application type: SERVLET, REACTIVE, NONE
  3. Loads SpringFactories (auto-configs, initializers, listeners)
  4. Creates and configures Environment (properties + profiles)
  5. Prints the Spring banner (can be customized or disabled)
  6. Creates the ApplicationContext
  7. Loads BeanDefinitions
  8. Refreshes the context (initializes all singleton beans)
  9. Calls ApplicationRunner and CommandLineRunner beans
  10. Publishes ApplicationReadyEvent
  11. Returns the running ApplicationContext

================================================================
SpringApplication CUSTOMIZATION
================================================================

  // Programmatic customization
  SpringApplication app = new SpringApplication(MyApp.class);
  app.setBannerMode(Banner.Mode.OFF);
  app.setDefaultProperties(Map.of("server.port", "9090"));
  app.addListeners(new MyApplicationListener());
  app.setWebApplicationType(WebApplicationType.NONE); // non-web
  app.run(args);

  // Fluent builder
  new SpringApplicationBuilder(MyApp.class)
      .bannerMode(Banner.Mode.OFF)
      .profiles("prod")
      .properties("server.port=9090")
      .run(args);

APPLICATION RUNNERS — POST-STARTUP LOGIC
================================================================

  // ApplicationRunner (receives ApplicationArguments)
  @Component
  public class DataLoader implements ApplicationRunner {

      @Autowired
      private ProductRepository repo;

      @Override
      public void run(ApplicationArguments args) {
          if (repo.count() == 0) {
              repo.saveAll(loadDefaultProducts());
          }
      }
  }

  // CommandLineRunner (receives raw String[] args)
  @Component
  @Order(1)                   // multiple runners → use @Order
  public class StartupLogger implements CommandLineRunner {

      @Override
      public void run(String... args) {
          log.info("Application started with args: {}", Arrays.toString(args));
      }
  }

SPRING BOOT vs SPRING FRAMEWORK
================================================================

  Aspect               | Spring Framework          | Spring Boot
  ---------------------|---------------------------|----------------------
  Config approach      | Explicit beans            | Auto-configured
  Embedded server      | No (deploy WAR to Tomcat) | Yes (Tomcat in JAR)
  Dependency mgmt      | Manual version choosing   | spring-boot-parent BOM
  Production features  | Manual setup              | Actuator included
  Startup boilerplate  | High                      | Near zero
  Learning curve       | Steeper                   | Gentler

================================================================
EMBEDDED SERVER — JAR vs WAR
================================================================

  JAR (default, recommended):
    java -jar myapp.jar
    → Tomcat embedded, listens on port 8080

  WAR (traditional deployment):
    1. Extend SpringBootServletInitializer
    2. Set packaging to <packaging>war</packaging>
    3. Deploy myapp.war to external Tomcat

    @SpringBootApplication
    public class MyApp extends SpringBootServletInitializer {
        @Override
        protected SpringApplicationBuilder configure(SpringApplicationBuilder builder) {
            return builder.sources(MyApp.class);
        }
    }

  management.endpoints.web.exposure.include=health,info,metrics
  management.endpoint.health.show-details=always

SPRING BOOT 3.x KEY CHANGES
================================================================

  • Requires Java 17 minimum
  • Requires Spring Framework 6.x
  • Migrated from javax.* → jakarta.* (Jakarta EE 9+)
  • Native image support via Spring Native / GraalVM
  • @HttpExchange replaces @FeignClient (declarative HTTP client)
  • Improved Observability (Micrometer Tracing replaces Sleuth)
  • Problem Details (RFC 7807) built-in via ProblemDetail
  • Virtual thread support with Project Loom (3.2+)

INTERVIEW QUESTIONS — SPRING BOOT OVERVIEW
================================================================

  Q: What is Spring Boot and how does it differ from Spring?
  A: Spring Boot is an opinionated wrapper around Spring Framework
     that provides auto-configuration, embedded servers, starter
     dependencies, and production features (Actuator) out of the
     box — drastically reducing boilerplate configuration.

  Q: What does @SpringBootApplication do?
  A: It's a composed annotation that combines @SpringBootConfiguration
     (marks as config), @EnableAutoConfiguration (activates auto-config),
     and @ComponentScan (scans the current package and sub-packages).

  Q: What is the difference between ApplicationRunner and
     CommandLineRunner?
  A: Both run code after application startup. ApplicationRunner
     receives ApplicationArguments (structured); CommandLineRunner
     receives raw String[] args.

  Q: How would you create a Spring Boot application without
     an embedded web server?
  A: Set spring.main.web-application-type=none in properties,
     or app.setWebApplicationType(WebApplicationType.NONE) programmatically.

  Q: What changed in Spring Boot 3.x?
  A: Java 17 minimum, jakarta.* namespace (from javax.*), GraalVM
     native image support, improved observability with Micrometer,
     built-in RFC 7807 problem details, and virtual thread support.
