================================================================
EXTERNALIZED CONFIGURATION
================================================================

  Spring Boot externalizes configuration so you can work with
  the same application code in different environments.

  Property sources, in ORDER OF PRECEDENCE (highest → lowest):
  (later overrides earlier)

  17. @TestPropertySource (tests only)
  16. @SpringBootTest properties attribute
  15. Command-line arguments (--key=value)
  14. SPRING_APPLICATION_JSON env var / system property
  13. ServletConfig init parameters
  12. ServletContext init parameters
  11. java:comp/env JNDI attributes
  10. Java system properties (-Dkey=value)
   9. OS environment variables
   8. Profile-specific application-{profile}.properties (outside jar)
   7. application.properties (outside jar)
   6. Profile-specific application-{profile}.properties (inside jar)
   5. application.properties (inside jar)
   4. @PropertySource annotations on @Configuration classes
   3. Default properties (SpringApplication.setDefaultProperties)

================================================================
application.properties FORMAT
================================================================

  # Basic key=value
  server.port=8080
  server.servlet.context-path=/api

  # Nested (dot notation)
  spring.datasource.url=jdbc:postgresql://localhost:5432/mydb
  spring.datasource.username=admin
  spring.datasource.password=${DB_PASSWORD}  # read from env var

  # Lists
  spring.profiles.active=dev,metrics
  my.allowed-origins[0]=https://example.com
  my.allowed-origins[1]=https://app.example.com

  # Maps
  my.headers[Content-Type]=application/json
  my.headers[X-Custom]=value

  # Multiline (backslash continuation)
  my.long.value=This is a very \
    long value

  # References other property
  my.base-url=https://api.example.com
  my.users-url=${my.base-url}/users

================================================================
application.yaml FORMAT
================================================================

  # application.yaml (equivalent to above)
  server:
    port: 8080
    servlet:
      context-path: /api

  spring:
    datasource:
      url: jdbc:postgresql://localhost:5432/mydb
      username: admin
      password: ${DB_PASSWORD}

  my:
    allowed-origins:
      - https://example.com
      - https://app.example.com
    headers:
      Content-Type: application/json
      X-Custom: value

  YAML advantages:
    ✓ Hierarchical — less repetition of prefixes
    ✓ Support for lists/maps natively
    ✓ Multi-document support (--- separator)
  YAML disadvantages:
    ✗ Indentation-sensitive (tabs not allowed)
    ✗ Cannot use @PropertySource to load YAML files

================================================================
YAML MULTI-DOCUMENT (PROFILES IN ONE FILE)
================================================================

  # application.yaml
  spring:
    application:
      name: myapp

  ---
  spring:
    config:
      activate:
        on-profile: dev
  server:
    port: 8081
  spring:
    datasource:
      url: jdbc:h2:mem:devdb

  ---
  spring:
    config:
      activate:
        on-profile: prod
  server:
    port: 8080
  spring:
    datasource:
      url: jdbc:postgresql://prod-server/mydb

================================================================
PROFILE-SPECIFIC FILES
================================================================

  application-{profile}.properties (or .yaml)

  application.properties        -- shared (always loaded)
  application-dev.properties    -- loaded when "dev" profile active
  application-prod.properties   -- loaded when "prod" profile active

  Profile-specific properties OVERRIDE application.properties.

  Activation:
    # in application.properties
    spring.profiles.active=dev

    # command line
    java -jar app.jar --spring.profiles.active=prod

    # environment variable
    export SPRING_PROFILES_ACTIVE=prod

================================================================
@ConfigurationProperties — TYPE-SAFE BINDING
================================================================

  # application.properties
  mail.host=smtp.example.com
  mail.port=587
  mail.username=admin
  mail.password=secret
  mail.retry.max-attempts=3
  mail.retry.delay-ms=1000

  @ConfigurationProperties(prefix = "mail")
  @Component  // or @Bean/@EnableConfigurationProperties
  @Validated  // enable javax/jakarta validation
  public class MailProperties {

      @NotBlank
      private String host;

      @Min(1) @Max(65535)
      private int port = 25;

      private String username;
      private String password;

      private Retry retry = new Retry();

      // getters + setters

      public static class Retry {
          private int maxAttempts = 3;
          private long delayMs = 500;
          // getters + setters
      }
  }

  // Enable globally:
  @SpringBootApplication
  @EnableConfigurationProperties(MailProperties.class)
  public class App { ... }

  Relaxed binding rules:
    mail.maxAttempts  ≡ mail.max-attempts  ≡ MAIL_MAX_ATTEMPTS

================================================================
@Value vs @ConfigurationProperties
================================================================

  Feature                 | @Value              | @ConfigurationProperties
  ------------------------|---------------------|-------------------------
  Single vs group         | Single value        | Group of values
  Type safety             | Limited             | Full
  Validation              | Manual              | @Validated + JSR-303
  Nested objects          | No                  | Yes
  SpEL support            | Yes (#{...})        | No
  IDE metadata            | No                  | Yes (with processor)
  Relaxed binding         | No                  | Yes

================================================================
PROPERTY PLACEHOLDER AND DEFAULT VALUES
================================================================

  @Value("${app.name}")                   // required; fails if absent
  @Value("${app.name:MyDefaultApp}")      // with default
  @Value("${app.name:${APP_NAME:Unknown}}")  // cascading default

  # Access list as comma-separated string
  @Value("${my.servers}")
  private String serversCsv;              // "host1,host2,host3"

  @Value("${my.servers}")
  private List<String> serversList;       // Spring auto-splits on comma

  @Value("#{${my.map}}")                  // SpEL map literal
  private Map<String, String> myMap;

================================================================
ENVIRONMENT AND PROPERTY SOURCES PROGRAMMATIC ACCESS
================================================================

  @Component
  public class ConfigInspector {

      @Autowired
      private Environment environment;

      public void inspect() {
          // Get property (with default)
          String url = environment.getProperty("spring.datasource.url",
                                               "jdbc:h2:mem:default");

          // Check active profiles
          String[] profiles = environment.getActiveProfiles();

          // Check if property exists
          boolean hasApiKey = environment.containsProperty("stripe.api-key");

          // Type conversion
          int port = environment.getProperty("server.port", Integer.class, 8080);
      }
  }

================================================================
CUSTOM PROPERTY FILE
================================================================

  @Configuration
  @PropertySource("classpath:custom.properties")
  @PropertySource("file:/etc/myapp/secrets.properties")
  @PropertySource(value = "classpath:optional.properties",
                  ignoreResourceNotFound = true)
  public class AppConfig { ... }

  NOTE: @PropertySource does NOT support YAML files.
        Use spring.config.additional-location for YAML override.

================================================================
SPRING_APPLICATION_JSON — ENVIRONMENT VARIABLE
================================================================

  export SPRING_APPLICATION_JSON='{"server":{"port":9090},"spring":{"profiles":{"active":"prod"}}}'
  java -jar app.jar

  Or as system property:
  java -Dspring.application.json='{"server":{"port":9090}}' -jar app.jar

================================================================
INTERVIEW QUESTIONS
================================================================

  Q: What is the order of Spring Boot property source precedence?
  A: Command-line args > OS env vars > application-{profile}.properties
     (outside jar) > application.properties (outside jar) >
     application-{profile}.properties (inside jar) >
     application.properties (inside jar). Higher-priority sources win.

  Q: What is the difference between @Value and @ConfigurationProperties?
  A: @Value injects single properties with SpEL support.
     @ConfigurationProperties binds an entire prefix group to a POJO,
     supports nested objects, relaxed binding, and JSR-303 validation.

  Q: How do you override properties for a specific environment?
  A: Use application-{profile}.properties/yaml files and activate
     the profile via spring.profiles.active or SPRING_PROFILES_ACTIVE.

  Q: What is relaxed binding?
  A: Spring Boot binds mail.max-attempts, mail.maxAttempts, and
     MAIL_MAX_ATTEMPTS to the same property. This makes it easy to
     set properties via environment variables (uppercase/underscore).

  Q: Can you load YAML with @PropertySource?
  A: No. @PropertySource only works with .properties files. For YAML,
     use spring.config.import or spring.config.additional-location.
