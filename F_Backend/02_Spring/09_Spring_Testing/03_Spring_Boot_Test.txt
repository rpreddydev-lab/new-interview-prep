@SpringBootTest loads the FULL Spring ApplicationContext, including
all beans, auto-configurations, and configurations.

Use it for:
  - Full integration tests (multiple layers together)
  - Testing @Configuration classes
  - Testing security, AOP, transactions with real beans
  - Smoke tests (does the application start up at all?)

Trade-off: slower (loads entire context) vs slice tests (load only one layer).
Spring caches ApplicationContext across tests — reuse the same context
if tests use the same configuration.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

@SpringBootTest                              // loads full context, no web server
@SpringBootTest(webEnvironment = SpringBootTest.WebEnvironment.RANDOM_PORT)  // starts real HTTP server
@SpringBootTest(webEnvironment = SpringBootTest.WebEnvironment.MOCK)         // mock servlet (default)
@SpringBootTest(webEnvironment = SpringBootTest.WebEnvironment.DEFINED_PORT) // uses server.port
@SpringBootTest(webEnvironment = SpringBootTest.WebEnvironment.NONE)         // no web

WebEnvironment options:
  MOCK      → loads WebApplicationContext with mock servlet; use with MockMvc
  RANDOM_PORT → starts real embedded server on a random port; use with TestRestTemplate/WebTestClient
  DEFINED_PORT → starts real server on configured port
  NONE     → no web layer (for service/repository tests)

@SpringBootTest
class ApplicationSmokeTest {

    @Test
    void contextLoads() {
        // Empty test — just verify context starts without errors
    }
}

  3. TEST WITH REAL HTTP SERVER — TestRestTemplate
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

@SpringBootTest(webEnvironment = SpringBootTest.WebEnvironment.RANDOM_PORT)
@AutoConfigureTestDatabase(replace = AutoConfigureTestDatabase.Replace.ANY) // use H2
class OrderControllerIntegrationTest {

    @LocalServerPort
    private int port;

    @Autowired
    private TestRestTemplate restTemplate;

    @Test
    void shouldReturnOrderById() {
        ResponseEntity<OrderResponse> response = restTemplate.getForEntity(
            "/api/orders/1", OrderResponse.class);

        assertThat(response.getStatusCode()).isEqualTo(HttpStatus.OK);
        assertThat(response.getBody()).isNotNull();
        assertThat(response.getBody().getId()).isEqualTo(1L);
    }

    @Test
    void shouldCreateOrder() {
        CreateOrderRequest request = new CreateOrderRequest(1L, 2, new BigDecimal("49.99"));

        ResponseEntity<OrderResponse> response = restTemplate.postForEntity(
            "/api/orders", request, OrderResponse.class);

        assertThat(response.getStatusCode()).isEqualTo(HttpStatus.CREATED);
        assertThat(response.getBody().getStatus()).isEqualTo("PENDING");
    }

    @Test
    void shouldReturn404ForMissingOrder() {
        ResponseEntity<ProblemDetail> response = restTemplate.getForEntity(
            "/api/orders/9999", ProblemDetail.class);
        assertThat(response.getStatusCode()).isEqualTo(HttpStatus.NOT_FOUND);
    }
}

  4. TEST WITH WebTestClient (REACTIVE)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

@SpringBootTest(webEnvironment = SpringBootTest.WebEnvironment.RANDOM_PORT)
class OrderControllerWebFluxTest {

    @Autowired
    private WebTestClient webTestClient;

    @Test
    void shouldGetOrder() {
        webTestClient.get()
            .uri("/api/orders/1")
            .accept(MediaType.APPLICATION_JSON)
            .exchange()
            .expectStatus().isOk()
            .expectBody(OrderResponse.class)
            .value(order -> assertThat(order.getId()).isEqualTo(1L));
    }

    @Test
    void shouldCreateOrder() {
        var request = new CreateOrderRequest(1L, 2, new BigDecimal("49.99"));

        webTestClient.post()
            .uri("/api/orders")
            .contentType(MediaType.APPLICATION_JSON)
            .bodyValue(request)
            .exchange()
            .expectStatus().isCreated()
            .expectBody()
            .jsonPath("$.status").isEqualTo("PENDING")
            .jsonPath("$.total").isEqualTo(49.99);
    }
}

  5. REPLACING BEANS WITH @MockBean / @SpyBean
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

@SpringBootTest
class OrderServiceIntegrationTest {

    @Autowired
    private OrderService orderService;

    @MockBean                           // replaces PaymentService bean in context
    private PaymentService paymentService;

    @MockBean
    private EmailService emailService;

    @Test
    void shouldPlaceOrder() {
        given(paymentService.charge(any())).willReturn("TX-001");

        Order order = orderService.placeOrder(new CreateOrderRequest(1L, 1, BigDecimal.TEN));

        assertThat(order.getStatus()).isEqualTo(OrderStatus.CONFIRMED);
        verify(emailService).sendOrderConfirmation(anyString());
    }
}

// @SpyBean — wraps a real bean but allows partial mocking
@SpyBean
private PaymentService paymentService;

doReturn("TX-FAST").when(paymentService).charge(any());  // spy, not when()

  7. CONTEXT CACHING
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Spring caches the ApplicationContext between tests to avoid recreating it
for every test class. Same context is reused when:
  - Same @SpringBootTest configuration
  - Same profiles (@ActiveProfiles)
  - Same properties
  - No @DirtiesContext annotation

Context is DIRTY (recreated) when:
  - @DirtiesContext is used on the test class or method
  - @MockBean or @SpyBean is used (creates a new context variant)
  - Different @SpringBootTest configuration or properties

Tip: Minimize @MockBean usage to reduce context cache misses.
     Create a common base test class with shared @MockBean declarations.

// Base test class pattern:
@SpringBootTest
@ActiveProfiles("test")
public abstract class BaseIntegrationTest {
    @MockBean protected EmailService emailService;
    @MockBean protected NotificationService notificationService;
}

class OrderIntegrationTest extends BaseIntegrationTest {
    // inherits @MockBeans — same context as other tests using BaseIntegrationTest
}

Q: What is the difference between @SpringBootTest and @WebMvcTest?
A: @SpringBootTest loads the full application context (all beans). It's
   slow but covers all layers. @WebMvcTest loads only the web layer
   (controllers, filters, converters) — no service or repository beans.
   Use @SpringBootTest for integration tests; @WebMvcTest for controller
   unit tests.

Q: What is @MockBean and how does it differ from @Mock?
A: @MockBean creates a Mockito mock AND registers it as a Spring bean in
   the test ApplicationContext, replacing the real bean. @Mock (Mockito)
   creates a mock but doesn't interact with Spring. Use @MockBean in
   @SpringBootTest or @WebMvcTest; use @Mock in @ExtendWith(MockitoExtension).

Q: What is context caching and why does it matter?
A: Spring reuses the ApplicationContext between tests with the same
   configuration to avoid the startup overhead. This makes test suites
   much faster. Using @MockBean or different @ActiveProfiles creates a
   new context variant. Minimize unique context configurations to maximize
   cache hits.

Q: When should you use RANDOM_PORT vs MOCK webEnvironment?
A: RANDOM_PORT starts a real embedded server and is used with
   TestRestTemplate or WebTestClient for black-box HTTP testing. MOCK
   creates a mock servlet environment and is used with MockMvc for in-
   process controller testing (faster, no actual HTTP networking). MOCK
   is preferred for most tests; RANDOM_PORT is better for full integration
   tests including filters and interceptors.

Q: How do you load different configuration values in a test?
A: Use @SpringBootTest(properties={"key=value"}) for inline overrides,
   @ActiveProfiles("test") with a test-specific application-test.yml, or
   @TestPropertySource(locations="...") for property files. For test-only
   beans, use @TestConfiguration with @Import.
