  1. TESTING PYRAMID
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

               ┌──────────────────────┐
               │   E2E / UI Tests     │  ← slow, few, full stack
               ├──────────────────────┤
               │  Integration Tests   │  ← medium speed, real infra
               ├──────────────────────┤
               │    Unit Tests        │  ← fast, many, mocked deps
               └──────────────────────┘

Unit Tests        → test a single class/method in isolation; mock dependencies
Integration Tests → test the interaction of multiple components (e.g., Controller + Service + DB)
E2E Tests         → test the full system as a user would (Selenium, Playwright)

  5. ASSERTJ VS HAMCREST
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

// JUnit Assertions (basic, less fluent)
assertEquals(expected, actual);
assertNotNull(result);
assertTrue(list.isEmpty());

// AssertJ (fluent, readable, more powerful — PREFERRED)
assertThat(order.getTotal()).isEqualByComparingTo(new BigDecimal("99.99"));
assertThat(order.getStatus()).isEqualTo(OrderStatus.PENDING);
assertThat(orders).hasSize(3)
                  .extracting(Order::getStatus)
                  .containsExactly(PENDING, SHIPPED, DELIVERED);
assertThat(exception).isInstanceOf(IllegalArgumentException.class)
                     .hasMessageContaining("invalid email");

// Exception testing
assertThatThrownBy(() -> service.createOrder(null))
    .isInstanceOf(IllegalArgumentException.class)
    .hasMessage("Order cannot be null");

assertThatCode(() -> service.cancelOrder(orderId))
    .doesNotThrowAnyException();

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Annotation           | What it loads                        | Use for
---------------------|--------------------------------------|-------------------
@WebMvcTest          | Spring MVC layer only (no DB)        | Controller tests
@WebFluxTest         | Spring WebFlux layer only            | Reactive controller
@DataJpaTest         | JPA repos + in-memory DB             | Repository tests
@DataMongoTest       | MongoDB repos                        | Mongo repo tests
@DataRedisTest       | Redis repos                          | Redis tests
@JsonTest            | JSON serialization only              | DTO JSON tests
@RestClientTest      | RestTemplate + MockRestServer        | Client tests
@SpringBootTest      | FULL application context             | Integration tests

Slice tests are FASTER than @SpringBootTest because they only load
the slice they care about (e.g., @WebMvcTest skips JPA/Redis entirely).

Q: What is the testing pyramid and why does it matter?
A: The testing pyramid recommends having many fast unit tests at the
   base, fewer integration tests in the middle, and very few slow E2E tests
   at the top. This keeps the test suite fast overall, provides quick
   feedback, and reduces flakiness (E2E tests are inherently fragile).

Q: What is a test slice in Spring Boot?
A: A test slice loads only the layer needed for the test. @WebMvcTest
   loads only Spring MVC beans (controllers, filters, etc.) without the
   service/repository layer. @DataJpaTest loads only JPA infrastructure.
   This makes tests faster and more focused than loading the full context.

Q: What is the difference between @Mock (Mockito) and @MockBean (Spring)?
A: @Mock (Mockito) creates a mock without Spring context — used in pure
   unit tests with @ExtendWith(MockitoExtension.class). @MockBean creates
   a mock AND registers it as a Spring bean in the ApplicationContext —
   used in Spring slice tests (@WebMvcTest, @SpringBootTest) to replace
   real beans with mocks.

Q: Why prefer AssertJ over JUnit assertions?
A: AssertJ provides a fluent, readable API (assertThat(x).isEqualTo(y)),
   better error messages showing actual vs expected, and powerful collection
   assertions (extracting, filteredOn, hasSize, etc.). JUnit assertEquals
   swaps expected/actual in its message (confusing), and the API is less
   expressive.

Q: What is the use of @BeforeAll vs @BeforeEach?
A: @BeforeAll runs once before ALL tests in the class (e.g., start a
   database, parse a large file). Must be static (or use @TestInstance(PER_CLASS)).
   @BeforeEach runs before EACH test method (e.g., set up test data, reset
   mocks). Use @BeforeAll for expensive setup that can be shared; @BeforeEach
   for test-specific state that must be fresh.
