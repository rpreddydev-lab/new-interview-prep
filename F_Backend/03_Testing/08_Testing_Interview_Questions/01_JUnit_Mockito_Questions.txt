INTERVIEW QUESTIONS — JUNIT 5 AND MOCKITO
Complete Interview Preparation Guide
================================================================

================================================================
JUNIT 5 QUESTIONS
================================================================

Q1: What are the three main modules of JUnit 5?
A: JUnit Platform — foundation layer; discovers and runs tests; integrates
   with IDEs and build tools via TestEngine SPI.
   JUnit Jupiter — new programming model with @Test, @BeforeEach, etc.
   JUnit Vintage — backward compatibility layer for JUnit 4 and 3 tests.

---

Q2: What is the difference between @BeforeEach and @BeforeAll?
A: @BeforeEach runs before EACH test method (fresh state per test).
   @BeforeAll runs once before ALL tests in the class — the method must
   be static (unless @TestInstance(Lifecycle.PER_CLASS) is used).
   @BeforeAll is good for expensive setup: starting servers, DB connections.
   @BeforeEach is good for resetting state: clearing mocks, seeding test data.

---

Q3: What is @TestInstance(Lifecycle.PER_CLASS)?
A: By default, JUnit creates a new test class instance per test method
   (PER_METHOD). With PER_CLASS, a single instance is shared across all
   test methods. This allows @BeforeAll/@AfterAll to be non-static. Useful
   for @Nested tests and when setup is expensive. Risk: test order dependency.

---

Q4: How do you write a parameterized test in JUnit 5?
A: Use @ParameterizedTest with a source annotation:
   @ParameterizedTest
   @CsvSource({"1,1,2", "2,3,5", "0,-1,-1"})
   void testAdd(int a, int b, int expected) {
       assertEquals(expected, calculator.add(a, b));
   }
   Other sources: @ValueSource, @MethodSource, @EnumSource, @ArgumentsSource.

---

Q5: What is the difference between assertThrows and assertDoesNotThrow?
A: assertThrows(ExceptionClass.class, () -> method()) — asserts that the
   lambda throws an exception of the specified type. Returns the exception
   for further assertions.
   assertDoesNotThrow(() -> method()) — asserts no exception is thrown.
   Both are preferable to @Test(expected=...) from JUnit 4 because they
   scope the assertion to exactly the line that should throw.

---

Q6: How do JUnit 5 Extensions work? Name two built-in extensions.
A: Extensions implement extension interfaces like BeforeEachCallback,
   AfterEachCallback, ParameterResolver, etc. Registered via
   @ExtendWith(MyExtension.class). Built-in examples:
   MockitoExtension — initializes @Mock, @Spy, @InjectMocks fields.
   SpringExtension — integrates Spring ApplicationContext.
   TimingExtension (custom) — measures test execution time.

---

Q7: What is assertAll() and when should you use it?
A: assertAll() groups multiple assertions and runs ALL of them, even if
   earlier ones fail. Regular assertions fail fast (stop at first failure).
   Use assertAll() when you want to see all failures at once, like
   verifying multiple fields on a response object:
   assertAll(
       () -> assertEquals("John", user.getName()),
       () -> assertEquals("ACTIVE", user.getStatus()),
       () -> assertNotNull(user.getCreatedAt())
   );

---

Q8: How do you run tests in parallel in JUnit 5?
A: In junit-platform.properties:
   junit.jupiter.execution.parallel.enabled=true
   junit.jupiter.execution.parallel.mode.default=concurrent
   Then annotate tests with @Execution(ExecutionMode.CONCURRENT) or
   set mode to concurrent globally. Requires thread-safe test state.
   Caution: avoid shared mutable state; use @TestInstance(PER_METHOD).

---

Q9: What is a @DynamicTest?
A: @TestFactory returns a Stream/Collection of DynamicTest instances at
   runtime. Unlike @ParameterizedTest, test cases are created dynamically
   — useful when test case count isn't known at compile time.
   @TestFactory
   Stream<DynamicTest> generateTests() {
       return Stream.of("Alice", "Bob")
           .map(name -> dynamicTest("Test for " + name,
               () -> assertNotNull(userService.findByName(name))));
   }

---

Q10: Why is assertThrows preferred over @Test(expected = ...) in JUnit 4?
A: With @Test(expected=...), if any line throws the expected exception,
   the test passes — even if a SETUP line throws instead of the line you're
   testing. assertThrows() scopes the assertion to exactly the lambda,
   so you know exactly which code threw. Also, you can inspect the exception:
   Exception ex = assertThrows(...);
   assertEquals("expected message", ex.getMessage());

================================================================
MOCKITO QUESTIONS
================================================================

Q11: What is the difference between @Mock and @Spy?
A: @Mock creates a complete mock where ALL methods return default values
   (null, 0, false, empty) unless stubbed. @Spy wraps a REAL object —
   unstubbed methods delegate to the real implementation. Use @Mock when
   you want full control; use @Spy when you want to test a real object but
   stub only specific methods.

---

Q12: What is STRICT_STUBS mode and why is it recommended?
A: MockitoExtension (for JUnit 5) enables STRICT_STUBS by default. It:
   (1) Fails tests that declare stubs that are never used (likely a mistake).
   (2) Prevents stubbing the same method multiple times unnecessarily.
   (3) Detects unnecessary stubbings that indicate test bloat.
   This prevents tests with stubs that "pass" even though the stubbed code
   isn't reached. Cleaner, more reliable tests.

---

Q13: What is the difference between when().thenReturn() and doReturn().when()?
A: when(mock.method()).thenReturn(value) — standard stubbing. The method is
   actually called during the stubbing line (fine for mocks, problematic for spies).
   doReturn(value).when(spy).method() — doesn't call the real method during
   stubbing. REQUIRED for spies when the real method has side effects or throws.
   Also required for void methods: doNothing().when(mock).voidMethod().

---

Q14: How does ArgumentCaptor work?
A: Captures arguments passed to a mock method for later inspection.
   @Captor ArgumentCaptor<OrderEvent> captor;
   verify(eventPublisher).publish(captor.capture());
   OrderEvent event = captor.getValue();
   assertEquals("CREATED", event.getType());
   Use when you need to verify complex objects passed to a dependency,
   not just that the method was called.

---

Q15: How do you mock static methods in Mockito?
A: Use MockedStatic (available since Mockito 3.4 with mockito-inline):
   try (MockedStatic<UUID> mockedUUID = mockStatic(UUID.class)) {
       mockedUUID.when(UUID::randomUUID).thenReturn(fixedUUID);
       // code under test that calls UUID.randomUUID()
   }
   The MockedStatic is thread-local and scoped to the try block.
   Design note: excessive static mocking indicates poor design — prefer
   wrapping static calls in injected collaborators.

---

Q16: What does verify() check? What is verifyNoInteractions()?
A: verify(mock).method(args) — asserts a method was called with specific args.
   verify(mock, times(2)).method() — exactly 2 calls.
   verify(mock, never()).method() — never called.
   verifyNoInteractions(mock1, mock2) — no methods were called on these mocks.
   verifyNoMoreInteractions(mock) — no ADDITIONAL calls beyond already verified.

---

Q17: What is InOrder verification?
A: InOrder ensures methods were called in a specific sequence:
   InOrder inOrder = inOrder(paymentService, inventoryService);
   inOrder.verify(paymentService).charge(any());
   inOrder.verify(inventoryService).reserve(any());
   Fails if inventory was reserved BEFORE payment was charged.

---

Q18: What happens when you call a method on a mock that hasn't been stubbed?
A: For regular mocks: returns default values (null for objects, 0 for numbers,
   false for booleans, empty collections). This is the RETURNS_DEFAULTS answer.
   For STRICT_STUBS mode: still returns defaults but records the call.
   If using RETURNS_SMART_NULLS: returns a SmartNull that throws a helpful
   NullPointerException with a descriptive message.

---

Q19: How do you stub consecutive calls to return different values?
A: Use chained thenReturn() calls:
   when(service.fetch("id"))
       .thenReturn("first")
       .thenReturn("second")
       .thenThrow(new RuntimeException("no more"));
   First call returns "first", second returns "second", third throws.
   Or: thenAnswer() with InvocationOnMock for dynamic responses.

---

Q20: How do you use @InjectMocks? What are its injection strategies?
A: @InjectMocks creates an instance and injects @Mock / @Spy fields into it.
   Injection order: Constructor injection (tries largest constructor first),
   then Setter injection, then Field injection.
   IMPORTANT: @InjectMocks silently fails if injection doesn't work —
   always verify your setup with a test that would fail if injection failed.
   Prefer constructor injection for clarity and reliability.
