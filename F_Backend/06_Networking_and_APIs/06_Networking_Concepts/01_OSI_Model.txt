================================================================================
OSI MODEL — IN DEPTH
================================================================================

WHAT IS THE OSI MODEL?
-----------------------
The Open Systems Interconnection (OSI) model is a conceptual framework that
standardizes the functions of a communication system into 7 abstract layers.
It was developed by ISO in 1984.

It is a MODEL (not an implementation). Real-world networking uses TCP/IP
(4 layers) but OSI helps explain and troubleshoot network behavior.

================================================================================
1. THE 7 LAYERS (Top to Bottom)
================================================================================

Layer 7 — APPLICATION
  What    : Provides network services directly to applications.
  PDU     : Data (message)
  Who     : HTTP, HTTPS, FTP, SMTP, DNS, DHCP, SNMP, WebSocket
  Examples: Browser making an HTTP request; email client sending SMTP
  
  "This is where humans and apps interact with the network."

Layer 6 — PRESENTATION
  What    : Data translation, encryption, compression.
  PDU     : Data
  Who     : SSL/TLS (often considered here), JPEG, MPEG, ASCII, Unicode
  Examples: TLS encryption of HTTP data; JPEG image compression
  
  "Format negotiation — makes sure sender and receiver agree on data format."

Layer 5 — SESSION
  What    : Manages sessions (establish, maintain, terminate connections).
  PDU     : Data
  Who     : NetBIOS, RPC, SQL sessions
  Examples: Authentication handshake; session tokens; half-duplex vs full-duplex
  
  "Keeps track of which conversation is which."

Layer 4 — TRANSPORT
  What    : End-to-end communication, error checking, flow control.
  PDU     : Segment (TCP) / Datagram (UDP)
  Who     : TCP, UDP, SCTP, QUIC
  Key     : Port numbers (source and destination), multiplexing
  Examples: TCP connection establishment; UDP DNS query; flow control windowing
  
  "Delivers data reliably (TCP) or fast (UDP) between processes."

Layer 3 — NETWORK
  What    : Logical addressing, routing between networks.
  PDU     : Packet
  Who     : IP (IPv4, IPv6), ICMP, OSPF, BGP
  Key     : IP addresses; routers operate here
  Examples: IP routing; ping (ICMP); BGP routing tables
  
  "Finds the best path through the network."

Layer 2 — DATA LINK
  What    : Physical addressing, framing, error detection on a link.
  PDU     : Frame
  Who     : Ethernet, WiFi (802.11), ARP, MAC addresses
  Key     : MAC addresses; switches operate here
  Examples: Ethernet frame with source/destination MAC; ARP resolving IP→MAC
  
  "Transfers frames between directly connected nodes."

Layer 1 — PHYSICAL
  What    : Transmits raw bit streams over physical medium.
  PDU     : Bit
  Who     : RJ45, fiber optic, WiFi radio, Bluetooth, coax cable
  Examples: Electrical signals on copper wire; optical pulses on fiber; RF waves
  
  "Actual hardware — cables, connectors, modulation."

3. TCP/IP MODEL vs OSI MODEL
================================================================================

OSI (7 layers)        TCP/IP (4 layers)      Examples
---------------------+--------------------+----------------------------------
Application (7)      | Application        | HTTP, SMTP, DNS, FTP
Presentation (6)     | Application        | SSL/TLS, encoding
Session (5)          | Application        | Session management
Transport (4)        | Transport          | TCP, UDP, QUIC
Network (3)          | Internet           | IP, ICMP, ARP (sometimes L2)
Data Link (2)        | Network Access     | Ethernet, WiFi, MAC
Physical (1)         | Network Access     | Cables, radio signals

TCP/IP is the practical internet model. OSI is theoretical reference model.
Layers 5, 6, 7 of OSI are collapsed into the single Application layer in TCP/IP.

5. DATA ENCAPSULATION (Sender Side)
================================================================================

As data travels down the OSI stack, each layer adds a header (encapsulation):

Application: [HTTP Message]
Transport:   [TCP Header | HTTP Message]
Network:     [IP Header | TCP Header | HTTP Message]
Data Link:   [Ethernet Header | IP Header | TCP Header | HTTP Message | Ethernet Trailer]
Physical:    [Bits transmitted over wire]

De-encapsulation on receiver side: each layer strips its header and passes up.

Headers added at each layer:
  Transport (TCP): source port, dest port, seq#, ack#, flags, checksum
  Network (IP)   : source IP, dest IP, TTL, protocol (6=TCP, 17=UDP)
  Data Link (Eth): source MAC, dest MAC, EtherType, FCS

6. LAYER 4 vs LAYER 7 LOAD BALANCING
================================================================================

L4 LOAD BALANCING (Transport layer):
  Operates on TCP/UDP packets.
  Sees: source IP, dest IP, source port, dest port.
  Does NOT see: HTTP headers, URL path, cookie, request body.
  Decision: based on IP + port only (round-robin, hash).
  
  Speed: very fast (no deep packet inspection)
  Examples: AWS NLB, HAProxy (TCP mode), hardware load balancers

L7 LOAD BALANCING (Application layer):
  Operates on HTTP/HTTPS content.
  Sees: URL path, HTTP method, headers, cookies, session IDs.
  Decision: route /api/users/* to user-service, /api/orders/* to order-service
  
  Features: SSL termination, URL-based routing, sticky sessions (cookie),
            A/B testing, header manipulation, WAF integration
  Examples: AWS ALB, Nginx (HTTP mode), Spring Cloud Gateway, Kong

WHEN TO USE WHICH:
  L4: Raw TCP/UDP, non-HTTP protocols (database connections, game servers)
      Maximum performance, minimum latency
  L7: HTTP services needing content-based routing, SSL termination, auth offload

================================================================================
7. WHERE SECURITY HAPPENS
================================================================================

Layer 7 (Application):
  HTTPS, OAuth2/JWT, CORS, input validation, rate limiting, WAF rules
  Application-level authentication and authorization

Layer 6 (Presentation):
  TLS encryption/decryption (SSL/TLS operates between 4 and 7 practically)

Layer 4 (Transport):
  TCP/UDP firewall rules (port-based access control)
  DDoS protection (SYN flood mitigation at TCP level)

Layer 3 (Network):
  IP firewall rules, IP allowlisting/blocklisting
  Network ACLs in AWS VPC, security groups

Layer 2 (Data Link):
  MAC filtering on local network
  802.1X port-based authentication

8. PRACTICAL EXAMPLES FOR INTERVIEWS
================================================================================

"What happens when you type google.com?"
  1. [L7] Browser resolves google.com via DNS
  2. [L4] Browser opens TCP connection to 142.250.x.x:443 (3-way handshake)
  3. [L6/L7] TLS handshake (negotiate cipher, exchange certificates)
  4. [L7] HTTP/2 GET request sent
  5. [L3] Packets routed through internet backbone
  6. [L2] Each router strips L2 header, re-encapsulates for next hop
  7. [L1] Electrical/optical/radio signals transmitted

"What does a router do vs a switch?"
  Switch: L2 device — forwards frames between devices on same LAN using MAC addresses
  Router: L3 device — forwards packets between different networks using IP addresses

"At what layer does a firewall operate?"
  Stateless firewall: L3/L4 (IP + port rules)
  Stateful firewall: L4 (tracks TCP connection state)
  Application firewall (WAF): L7 (HTTP content inspection)

9. INTERVIEW QUESTIONS — OSI MODEL
================================================================================

Q1: What is the OSI model and why is it useful?
    The OSI model is a 7-layer conceptual framework for network communication.
    It's useful because it provides a common vocabulary for troubleshooting and
    discussion, clarifies where specific protocols operate, and helps identify
    where in the stack a problem originates. When a network issue occurs, you can
    systematically check: physical layer (cable?), data link (MAC/switch?),
    network (IP/routing?), transport (TCP/firewall?), application (config?).

Q2: What is the difference between Layer 4 and Layer 7 load balancing?
    L4 operates on TCP/UDP at the transport layer — routes by IP and port without
    inspecting content. Very fast, no HTTP awareness. L7 operates on application
    content (HTTP headers, URL, cookies). Can route /users to UserService,
    /orders to OrderService. Supports SSL termination, sticky sessions, WAF.
    Use L4 for raw TCP protocols and maximum performance; L7 for HTTP services
    needing content-based routing.

Q3: What is the difference between a router and a switch?
    Switch operates at L2 (Data Link) — connects devices on the same local network,
    forwards Ethernet frames based on MAC addresses, builds a MAC address table.
    Router operates at L3 (Network) — connects different networks, routes IP packets
    based on routing table and IP addresses. In a home network: the WiFi router is
    actually a router + switch + DHCP server combined.

Q4: At which OSI layer does TLS operate?
    This is debated — TLS sits between the Transport layer (L4) and Application
    layer (L7). It operates on top of TCP (L4) but below HTTP (L7). Some say
    it belongs to L6 (Presentation) because it handles encryption/decryption and
    data format. Practically, you can answer: TLS operates at L4-L6, encrypting
    the TCP stream before handing data to the application.

Q5: What is the PDU (Protocol Data Unit) at each layer?
    L7 Application: Message/Data
    L6 Presentation: Data
    L5 Session: Data
    L4 Transport: Segment (TCP) / Datagram (UDP)
    L3 Network: Packet
    L2 Data Link: Frame
    L1 Physical: Bit
    Memory aid: "Data, Data, Data, Segment, Packet, Frame, Bit"
