1. BASIC @KafkaListener
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  @Component
  public class OrderListener {

    // Simplest form
    @KafkaListener(topics = "orders", groupId = "order-service")
    public void handleOrder(String message) {
      System.out.println("Received: " + message);
    }

    // With full ConsumerRecord (all metadata)
    @KafkaListener(topics = "orders", groupId = "order-service")
    public void handleOrder(ConsumerRecord<String, Order> record) {
      log.info("topic={} partition={} offset={} key={} value={}",
        record.topic(), record.partition(), record.offset(),
        record.key(), record.value());
    }

    // With Spring Kafka headers
    @KafkaListener(topics = "orders")
    public void handleOrder(
        Order order,
        @Header(KafkaHeaders.RECEIVED_TOPIC) String topic,
        @Header(KafkaHeaders.RECEIVED_PARTITION) int partition,
        @Header(KafkaHeaders.OFFSET) long offset,
        @Header(KafkaHeaders.RECEIVED_KEY) String key,
        @Header(KafkaHeaders.RECEIVED_TIMESTAMP) long timestamp) {
      // ...
    }
  }

2. BATCH LISTENER
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Process all records returned by a single poll() call together:

  // Enable batch mode on the factory:
  factory.setBatchListener(true);

  @KafkaListener(topics = "orders")
  public void handleOrders(List<ConsumerRecord<String, Order>> records, Acknowledgment ack) {
    log.info("Processing batch of {} records", records.size());
    
    List<Order> orders = records.stream()
      .map(ConsumerRecord::value)
      .collect(Collectors.toList());
    
    orderRepository.saveAll(orders); // batch DB write → efficient
    ack.acknowledge();
  }

  // Or simpler form (just values):
  @KafkaListener(topics = "orders")
  public void handleOrders(List<Order> orders) {
    orderRepository.saveAll(orders);
  }

Benefits of batch mode:
  - Batch database inserts (much faster than per-record)
  - Single commit for the entire batch
  - More efficient for high-throughput scenarios

3. MULTIPLE TOPICS AND PARTITIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  // Multiple topics in one listener
  @KafkaListener(topics = {"orders", "returns"}, groupId = "fulfillment")
  public void handleEvent(ConsumerRecord<String, String> record) {
    if (record.topic().equals("orders")) {
      processOrder(record);
    } else {
      processReturn(record);
    }
  }

  // Topic patterns (regex)
  @KafkaListener(topicPattern = "order.*", groupId = "analytics")
  public void handleAllOrderTopics(ConsumerRecord<String, String> record) { }

  // Explicit partition assignment (manual assign, no group rebalancing)
  @KafkaListener(
    topicPartitions = @TopicPartition(topic = "orders", partitions = {"0", "1"}),
    groupId = "dedicated-consumer"
  )
  public void handlePartitions(ConsumerRecord<String, Order> record) { }

  // Partition with offset start (seek to specific offset)
  @KafkaListener(
    topicPartitions = @TopicPartition(
      topic = "orders",
      partitionOffsets = {
        @PartitionOffset(partition = "0", initialOffset = "1000"),
        @PartitionOffset(partition = "1", initialOffset = "0")
      }
    )
  )
  public void handleFromOffset(ConsumerRecord<String, Order> record) { }

4. CONCURRENT LISTENERS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  // Via annotation (overrides factory concurrency for this listener)
  @KafkaListener(topics = "orders", concurrency = "3")
  public void handleOrder(ConsumerRecord<String, Order> record) { }

  // Via factory
  factory.setConcurrency(3);

  // Dynamically change concurrency at runtime:
  @Autowired
  KafkaListenerEndpointRegistry registry;
  
  public void scaleTo(int threads) {
    ConcurrentMessageListenerContainer<?, ?> container =
      (ConcurrentMessageListenerContainer<?, ?>) registry.getListenerContainer("order-listener");
    container.setConcurrency(threads);
  }

  // Name the listener for registry access:
  @KafkaListener(id = "order-listener", topics = "orders")
  public void handleOrder(ConsumerRecord<String, Order> record) { }

  @Autowired
  private KafkaListenerEndpointRegistry registry;

  // Stop all listeners
  public void pauseAll() {
    registry.getListenerContainers().forEach(MessageListenerContainer::pause);
  }

  // Resume all listeners
  public void resumeAll() {
    registry.getListenerContainers().forEach(MessageListenerContainer::resume);
  }

  // Stop a specific listener
  public void stopListener(String listenerId) {
    registry.getListenerContainer(listenerId).stop();
  }

  // Start a specific listener
  public void startListener(String listenerId) {
    registry.getListenerContainer(listenerId).start();
  }

  // Listeners can be configured to NOT auto-start:
  @KafkaListener(id = "manual-listener", topics = "orders", autoStartup = "false")
  public void handleOrder(ConsumerRecord<String, Order> record) { }
  // Start manually via registry.getListenerContainer("manual-listener").start();

  // Apply a record filter before calling the listener method
  factory.setRecordFilterStrategy(record -> {
    // Return true to DISCARD the record (not delivered to listener)
    Order order = (Order) record.value();
    return order.getStatus() != OrderStatus.PAID; // only process PAID orders
  });

  // With acknowledgment for filtered records:
  factory.setAckDiscarded(true); // auto-commit discarded records

Q: What are the different method signatures supported by @KafkaListener?
A: @KafkaListener supports many signatures: (1) plain value type (e.g., String, Order);
   (2) ConsumerRecord<K,V> for full metadata (topic, partition, offset, headers);
   (3) List<ConsumerRecord<K,V>> for batch mode; (4) individual value + @Header params
   for header injection (KafkaHeaders.RECEIVED_TOPIC, OFFSET, etc.); (5) with
   Acknowledgment parameter for manual offset control (requires MANUAL ack mode).
   Spring introspects the signature and injects the appropriate data.

Q: How do you make a @KafkaListener process records from specific partitions?
A: Use the topicPartitions attribute with @TopicPartition and optionally
   @PartitionOffset: @KafkaListener(topicPartitions = @TopicPartition(topic="orders",
   partitions={"0","1"})). This uses consumer.assign() instead of consumer.subscribe(),
   bypassing group rebalancing. For specific starting offsets, use partitionOffsets
   within @TopicPartition. This is useful for one-off replay scenarios or when you
   need direct partition assignment.

Q: How do you dynamically start and stop a @KafkaListener at runtime?
A: Give the listener an id attribute and use KafkaListenerEndpointRegistry:
   registry.getListenerContainer("my-listener").stop() / .start() / .pause() /
   .resume(). Pause/resume is preferred for temporary stops — it keeps the consumer
   active (sending heartbeats) but stops delivering records to the listener.
   Stop/start fully destroys and recreates the consumer. Use autoStartup="false" to
   prevent a listener from starting on application startup.

Q: What is the purpose of setRecordFilterStrategy on a listener factory?
A: RecordFilterStrategy lets you discard records before they reach the listener method,
   without the listener code needing to handle that logic. Return true from the filter
   to discard a record. Set setAckDiscarded(true) to auto-commit filtered records
   (otherwise their offsets won't advance). Useful for: filtering by record value,
   skip-and-commit for specific message types without custom error handling.

Q: What is KafkaListenerEndpointRegistry and what is it used for?
A: It's the Spring registry of all @KafkaListener containers created in the application
   context. You can inject it and use it to: look up containers by ID, start/stop/pause
   individual listeners at runtime, get a list of all containers, and check container
   state (running, paused). Essential for operational control — e.g., pausing consumers
   during a deployment, or dynamically scaling concurrency based on load.
