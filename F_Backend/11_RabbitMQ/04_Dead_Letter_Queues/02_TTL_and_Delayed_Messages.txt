TTL AND DELAYED MESSAGES IN RABBITMQ
=====================================

TTL (Time-To-Live)
------------------
TTL controls how long a message or queue exists before expiration.
Two scopes:
  1. Message TTL — per-message or queue-wide policy
  2. Queue TTL (x-expires) — queue deleted after inactivity

Queue-wide Message TTL (applied to all messages in queue):
  Map<String, Object> args = new HashMap<>();
  args.put("x-message-ttl", 30000); // 30 seconds
  args.put("x-dead-letter-exchange", "dlx.exchange");
  channel.queueDeclare("orders.queue", true, false, false, args);

Per-Message TTL (overrides queue TTL if lower):
  AMQP.BasicProperties props = new AMQP.BasicProperties.Builder()
      .expiration("5000") // 5 seconds, as a string
      .build();
  channel.basicPublish("", "orders.queue", props, messageBytes);

Queue Expiry (x-expires):
  args.put("x-expires", 60000); // queue deleted after 60s of no consumers

Spring AMQP TTL Declaration:
  @Bean
  Queue ordersQueue() {
      return QueueBuilder.durable("orders.queue")
          .ttl(30_000)
          .deadLetterExchange("dlx.exchange")
          .deadLetterRoutingKey("orders.dead")
          .build();
  }

TTL + DLX Flow:
  Message arrives → sits in queue → TTL expires → moved to DLX → routed to DLQ

Delayed Message Exchange Plugin
---------------------------------
Default RabbitMQ does not support scheduled/delayed delivery natively.
The rabbitmq_delayed_message_exchange plugin enables this.

Install Plugin:
  rabbitmq-plugins enable rabbitmq_delayed_message_exchange

Declare Delayed Exchange:
  Map<String, Object> args = new HashMap<>();
  args.put("x-delayed-type", "direct");
  channel.exchangeDeclare("delayed.exchange", "x-delayed-message", true, false, args);

Publish with Delay:
  Map<String, Object> headers = new HashMap<>();
  headers.put("x-delay", 10000); // 10 second delay
  AMQP.BasicProperties props = new AMQP.BasicProperties.Builder()
      .headers(headers)
      .build();
  channel.basicPublish("delayed.exchange", "my.key", props, body);

Spring AMQP Delayed Exchange:
  @Bean
  CustomExchange delayedExchange() {
      Map<String, Object> args = new HashMap<>();
      args.put("x-delayed-type", "direct");
      return new CustomExchange("delayed.exchange", "x-delayed-message", true, false, args);
  }

  @Bean
  Binding delayedBinding(Queue myQueue, CustomExchange delayedExchange) {
      return BindingBuilder.bind(myQueue).to(delayedExchange).with("my.key").noargs();
  }

  // Send with delay header
  rabbitTemplate.convertAndSend("delayed.exchange", "my.key", message, msg -> {
      msg.getMessageProperties().setDelay(10_000);
      return msg;
  });

Delayed Message vs TTL+DLQ Approach:
  | Feature              | Delayed Plugin         | TTL + DLQ              |
  |----------------------|------------------------|------------------------|
  | Precision            | Millisecond accurate   | Approximate            |
  | Message ordering     | Not guaranteed         | Not guaranteed         |
  | Plugin required      | Yes                    | No                     |
  | Complexity           | Low                    | Medium                 |
  | Use for retry delays | Yes                    | Yes                    |

Practical Patterns
------------------

Retry with Exponential Backoff via TTL+DLQ:
  Queue: orders.queue (DLX → orders.retry.queue)
  Retry Queue TTL: 5s, 10s, 30s (separate queues per backoff level)
  Each retry queue DLX → back to original queue

  Flow:
    Process fails → NACK → DLQ (retry-1, TTL=5s) → re-queued → fail again →
    DLQ (retry-2, TTL=10s) → ... → final DLQ (no requeue) → alerting

Scheduled Jobs via Delayed Exchange:
  - Send reminder emails 1 hour before event
  - Schedule payment retries
  - Implement webhook retry with increasing delays
