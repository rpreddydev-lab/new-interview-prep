1. WHAT IS SPRING KAFKA?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Spring Kafka is the official Spring Integration for Apache Kafka.
It wraps the native kafka-clients library with Spring idioms:
  - Template pattern (KafkaTemplate) for producers
  - Annotation-driven consumers (@KafkaListener)
  - Spring Boot auto-configuration
  - Integration with Spring Transaction Manager
  - Error handling and retry abstractions

Maven dependency:
  <dependency>
    <groupId>org.springframework.kafka</groupId>
    <artifactId>spring-kafka</artifactId>
  </dependency>
  <!-- or Spring Boot starter: -->
  <dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-kafka</artifactId>
  </dependency>

  @Configuration
  public class KafkaProducerConfig {
    
    @Bean
    public ProducerFactory<String, Order> orderProducerFactory() {
      Map<String, Object> configProps = new HashMap<>();
      configProps.put(ProducerConfig.BOOTSTRAP_SERVERS_CONFIG, "localhost:9092");
      configProps.put(ProducerConfig.KEY_SERIALIZER_CLASS_CONFIG, StringSerializer.class);
      configProps.put(ProducerConfig.VALUE_SERIALIZER_CLASS_CONFIG, JsonSerializer.class);
      configProps.put(ProducerConfig.ACKS_CONFIG, "all");
      configProps.put(ProducerConfig.ENABLE_IDEMPOTENCE_CONFIG, true);
      configProps.put(ProducerConfig.RETRIES_CONFIG, Integer.MAX_VALUE);
      configProps.put(ProducerConfig.COMPRESSION_TYPE_CONFIG, "lz4");
      return new DefaultKafkaProducerFactory<>(configProps);
    }

    @Bean
    public KafkaTemplate<String, Order> orderKafkaTemplate() {
      return new KafkaTemplate<>(orderProducerFactory());
    }
  }

4. CONSUMER CONFIGURATION (JAVA)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  @Configuration
  @EnableKafka
  public class KafkaConsumerConfig {
    
    @Bean
    public ConsumerFactory<String, Order> orderConsumerFactory() {
      Map<String, Object> props = new HashMap<>();
      props.put(ConsumerConfig.BOOTSTRAP_SERVERS_CONFIG, "localhost:9092");
      props.put(ConsumerConfig.GROUP_ID_CONFIG, "order-processors");
      props.put(ConsumerConfig.KEY_DESERIALIZER_CLASS_CONFIG, StringDeserializer.class);
      props.put(ConsumerConfig.VALUE_DESERIALIZER_CLASS_CONFIG, JsonDeserializer.class);
      props.put(ConsumerConfig.ENABLE_AUTO_COMMIT_CONFIG, false);
      props.put(ConsumerConfig.AUTO_OFFSET_RESET_CONFIG, "earliest");
      props.put(JsonDeserializer.TRUSTED_PACKAGES, "com.mycompany.model");
      return new DefaultKafkaConsumerFactory<>(props);
    }

    @Bean
    public ConcurrentKafkaListenerContainerFactory<String, Order> kafkaListenerContainerFactory() {
      ConcurrentKafkaListenerContainerFactory<String, Order> factory =
        new ConcurrentKafkaListenerContainerFactory<>();
      factory.setConsumerFactory(orderConsumerFactory());
      factory.setConcurrency(3);  // 3 consumer threads
      factory.getContainerProperties()
        .setAckMode(ContainerProperties.AckMode.MANUAL_IMMEDIATE);
      return factory;
    }
  }

5. ACK MODES IN SPRING KAFKA
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Spring Kafka provides multiple ACK modes (how offsets are committed):

  RECORD           → commit after each record (very slow)
  BATCH            → commit after processing all records in current poll batch
  TIME             → commit every N milliseconds
  COUNT            → commit every N records
  COUNT_TIME       → whichever comes first of COUNT or TIME
  MANUAL           → commit when Acknowledgment.acknowledge() is called
  MANUAL_IMMEDIATE → commit immediately when Acknowledgment.acknowledge() is called
                     (doesn't wait for next batch; use with care on high-throughput)

Recommended for production:
  factory.getContainerProperties().setAckMode(ContainerProperties.AckMode.MANUAL_IMMEDIATE);

  // In listener:
  @KafkaListener(topics = "orders")
  public void processOrder(ConsumerRecord<String, Order> record, Acknowledgment ack) {
    try {
      orderService.process(record.value());
      ack.acknowledge(); // commit after successful processing
    } catch (Exception e) {
      // Don't acknowledge → record will be reprocessed
      log.error("Failed to process: {}", record.offset(), e);
    }
  }

6. KEY INTERVIEW QUESTIONS

Q: What does @EnableKafka do in Spring?
A: It enables the detection of @KafkaListener annotations on Spring-managed beans.
   Without @EnableKafka (or the equivalent auto-configuration from Spring Boot),
   @KafkaListener annotations are ignored. In Spring Boot apps with
   spring-boot-starter-kafka, @EnableKafka is auto-configured; for plain Spring
   apps, you must explicitly add it to a @Configuration class.

Q: What is ConcurrentKafkaListenerContainerFactory.setConcurrency()?
A: This sets the number of concurrent consumer threads per @KafkaListener. Each
   thread creates its own Kafka consumer instance. With concurrency=3 and a topic
   with 6 partitions, 3 threads will each get 2 partitions assigned. The maximum
   useful concurrency = topic partition count. Spring manages the consumer threads
   and handles shutdown gracefully.

Q: What is the difference between MANUAL and MANUAL_IMMEDIATE ack mode?
A: MANUAL batches acknowledgements and commits at the end of each poll loop
   iteration. MANUAL_IMMEDIATE commits the offset synchronously as soon as
   Acknowledgment.acknowledge() is called, regardless of when the next poll fires.
   MANUAL_IMMEDIATE is safer for individual record tracking; MANUAL is slightly
   more efficient for batch use cases.

Q: How does Spring Kafka's @KafkaListener relate to native Kafka consumers?
A: Under the hood, each @KafkaListener creates a MessageListenerContainer, which
   runs a Kafka consumer (or pool of consumers with concurrency > 1) in a background
   thread. The container manages the poll loop, offset committing (via AckMode),
   error handling, and graceful shutdown. @KafkaListener is syntactic sugar over
   this container infrastructure, letting you focus on the processing method.

Q: How do you configure multiple @KafkaListener containers with different configs?
A: Use different ConcurrentKafkaListenerContainerFactory beans and reference them
   via containerFactory attribute: @KafkaListener(topics="orders",
   containerFactory="highThroughputFactory"). You can have one factory for high-
   throughput topics (large poll, BATCH ack) and another for critical topics (small
   poll, MANUAL_IMMEDIATE ack, EOS).
