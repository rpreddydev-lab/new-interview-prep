================================================================
  OTHER OOP PRINCIPLES — OVERVIEW
================================================================

  Beyond SOLID, these principles guard against the most common
  design mistakes in everyday code. They are simpler to state
  than SOLID but equally important in practice.

----------------------------------------------------------------
QUICK REFERENCE TABLE
----------------------------------------------------------------

  Principle                  One-liner
  -------------------------  ------------------------------------------
  DRY                        Every piece of knowledge has one place
  KISS                       Simplest solution that works
  YAGNI                      Don't build what you don't need yet
  Composition over Inherit.  Prefer HAS-A over IS-A for behavior
  Encapsulate What Varies    Isolate changing parts from stable parts
  Program to Interface       Declare variables/params as interfaces
  Law of Demeter (LoD)       Only talk to immediate friends
  Tell Don't Ask             Tell objects what to do; don't ask state
  Fail Fast                  Detect and report errors as early as possible
  Principle of Least Astonishment  Code should do what reader expects

----------------------------------------------------------------
HOW THESE RELATE TO SOLID
----------------------------------------------------------------

  DRY           -- supports SRP (if two classes do the same thing, one has extra responsibility)
  KISS          -- opposes premature OCP abstraction (don't abstract what doesn't need it)
  YAGNI         -- keeps OCP in check (don't add extension points you won't use)
  Composition   -- enables OCP and DIP (swap behavior via interface without inheritance)
  Encapsulate   -- foundation of OCP (identify what changes; close it)
  LoD           -- supports low coupling (ISP at the instance level)
  Tell Don't Ask-- supports SRP (behavior in the class that owns the data)

----------------------------------------------------------------
WHICH ONES COME UP MOST IN INTERVIEWS
----------------------------------------------------------------

  Rank   Principle                  Why
  -----  -------------------------  ----------------------------------
  1      DRY                        Every developer knows it; easy to violate
  2      KISS                       "Over-engineering" is a common critique
  3      Composition over Inherit   Inheritance is Java's biggest pitfall
  4      Tell Don't Ask             Anemic model antipattern is common
  5      YAGNI                      Premature abstraction = common interview red flag
  6      LoD / Law of Demeter       Train wreck code is instantly recognizable
  7      Fail Fast                  Shows production awareness
