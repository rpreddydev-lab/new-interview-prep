================================================================
  ABSTRACT FACTORY PATTERN
================================================================

  Category:   Creational
  Intent:     Provide an interface for creating FAMILIES of related or
              dependent objects without specifying their concrete classes.
  Also known as: Kit
  GoF:        Yes — one of the original 23 patterns.
  Frequency:  High in interviews involving multi-platform or provider-agnostic design.

----------------------------------------------------------------
PROBLEM SOLVED
----------------------------------------------------------------

  When a system must be independent of how its products are created,
  composed, and represented — AND when the system is configured with one
  of MULTIPLE FAMILIES of products.

  Example:
    UI toolkit that must render on Windows, macOS, and Linux.
    Button + Checkbox + TextField for each platform — must stay consistent.
    Client code should not know or care which OS it's running on.

  Without Abstract Factory:
    Client creates new WindowsButton(), new MacCheckbox() — mixed families.
    Changing the OS requires touching every creation point.

  With Abstract Factory:
    Client asks UIFactory.createButton() — gets the correct platform implementation.
    Swap the factory object, entire family changes consistently.

----------------------------------------------------------------
PARTICIPANTS
----------------------------------------------------------------

  AbstractFactory   -- Interface declaring create methods for each product type.
  ConcreteFactory   -- Implements AbstractFactory; creates a specific product family.
  AbstractProduct   -- Interface for each kind of product.
  ConcreteProduct   -- Specific product; created by ConcreteFactory.
  Client            -- Uses AbstractFactory and AbstractProduct interfaces only.

----------------------------------------------------------------
STRUCTURE VISUALIZATION
----------------------------------------------------------------

  AbstractFactory
    + createButton()      --> AbstractButton
    + createCheckbox()    --> AbstractCheckbox
           |                        |
    ------------------       ------------------
    |                |       |                |
  WinFactory      MacFactory  WinButton    MacButton
  createButton()  createButton()  draw()   draw()
  createCheckbox() createCheckbox()

  Client holds reference to AbstractFactory.
  When factory = new WinFactory(), all created products are Windows-style.
  When factory = new MacFactory(), all created products are Mac-style.

----------------------------------------------------------------
FULL JAVA EXAMPLE — CROSS-PLATFORM UI
----------------------------------------------------------------

  // AbstractProducts
  public interface Button    { void render(); }
  public interface Checkbox  { void check(); }

  // ConcreteProducts — Windows family
  public class WindowsButton  implements Button   { public void render() { System.out.println("[ Windows Button ]"); } }
  public class WindowsCheckbox implements Checkbox { public void check()  { System.out.println("[X] Windows Checkbox"); } }

  // ConcreteProducts — Mac family
  public class MacButton    implements Button   { public void render() { System.out.println("( Mac Button )"); } }
  public class MacCheckbox  implements Checkbox { public void check()  { System.out.println("[*] Mac Checkbox"); } }

  // AbstractFactory
  public interface UIFactory {
      Button   createButton();
      Checkbox createCheckbox();
  }

  // ConcreteFactories
  public class WindowsUIFactory implements UIFactory {
      public Button   createButton()   { return new WindowsButton(); }
      public Checkbox createCheckbox() { return new WindowsCheckbox(); }
  }

  public class MacUIFactory implements UIFactory {
      public Button   createButton()   { return new MacButton(); }
      public Checkbox createCheckbox() { return new MacCheckbox(); }
  }

  // Client
  public class Application {
      private final Button   button;
      private final Checkbox checkbox;

      public Application(UIFactory factory) {
          this.button   = factory.createButton();
          this.checkbox = factory.createCheckbox();
      }

      public void renderUI() {
          button.render();
          checkbox.check();
      }
  }

  // Wiring (e.g., in main or config)
  public class Main {
      public static void main(String[] args) {
          String os = System.getProperty("os.name");
          UIFactory factory = os.contains("Windows") ? new WindowsUIFactory() : new MacUIFactory();
          Application app = new Application(factory);
          app.renderUI();
      }
  }

DATABASE PROVIDER EXAMPLE (REAL-WORLD JAVA)
----------------------------------------------------------------

  Often asked in interviews: design a DB-agnostic persistence layer.

  // AbstractProducts
  public interface Connection { void connect(); }
  public interface Command    { void execute(String sql); }

  // AbstractFactory
  public interface DatabaseFactory {
      Connection createConnection(String url);
      Command    createCommand();
  }

  // Concrete — MySQL family
  public class MySQLFactory implements DatabaseFactory {
      public Connection createConnection(String url) { return new MySQLConnection(url); }
      public Command    createCommand()              { return new MySQLCommand(); }
  }

  // Concrete — PostgreSQL family
  public class PostgreSQLFactory implements DatabaseFactory {
      public Connection createConnection(String url) { return new PostgreSQLConnection(url); }
      public Command    createCommand()              { return new PostgreSQLCommand(); }
  }

  // Client is DatabaseService; injected with DatabaseFactory — no DB-specific code.

----------------------------------------------------------------
ABSTRACT FACTORY IN JAVA / SPRING
----------------------------------------------------------------

  Java Standard Library:
    - DocumentBuilderFactory / TransformerFactory (XML parsing — choose SAX vs DOM)
    - javax.xml.parsers.DocumentBuilderFactory.newInstance()

  Spring Framework:
    - ApplicationContext acts as an Abstract Factory for all beans.
    - DataSourceFactory, TransactionManagerFactory — swap implementations per environment.
    - JPA: EntityManagerFactory is the abstract factory; Hibernate provides concrete factory.

  Spring Boot Example:
    @Configuration
    public class PersistenceConfig {
        @Bean
        public DataSource dataSource() {
            // Returns H2 in test, MySQLDataSource in prod — factory method
        }
    }

----------------------------------------------------------------
COMPARING ABSTRACT FACTORY TO FACTORY METHOD
----------------------------------------------------------------

  Dimension           Factory Method           Abstract Factory
  ------------------  -----------------------  --------------------------------
  Products created    ONE type                 FAMILY of related types
  Mechanism           Subclassing (override)   Object composition (inject factory)
  Extensibility       New subclass per type    New ConcreteFactory per family
  Consistency         Not enforced             Products within family always consistent
  Complexity          Lower                    Higher — more classes/interfaces

  Example contrast:
    Factory Method:  NotifierFactory.createNotifier() -- creates ONE Notifier.
    Abstract Factory: CloudFactory.createStorage() AND createQueue() AND createDatabase().
                      AWSFactory vs AzureFactory -- family of related cloud products.

----------------------------------------------------------------
ADDING A NEW FAMILY vs NEW PRODUCT TYPE
----------------------------------------------------------------

  Adding a new FAMILY (e.g., Linux UI):
    - Add LinuxButton, LinuxCheckbox (ConcreteProducts).
    - Add LinuxUIFactory implementing UIFactory.
    - No changes to existing code. OPEN/CLOSED. ✅

  Adding a new PRODUCT TYPE (e.g., Scrollbar to UIFactory):
    - Must add Scrollbar to AbstractFactory interface.
    - ALL ConcreteFactories must implement createScrollbar().
    - Breaking change to all existing factories. ❌ (downside of Abstract Factory)

  KEY TRADE-OFF: Abstract Factory makes adding families easy but adding new
  product types hard. Opposite of what many patterns do.

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: What is the Abstract Factory pattern?
  A: It provides an interface for creating families of related objects without
     specifying concrete classes. The client uses the abstract factory and abstract
     product interfaces — the concrete factory decides which concrete products to create.
     Swapping the factory swaps the entire product family.

  Q: How is Abstract Factory different from Factory Method?
  A: Factory Method creates ONE product; the type is decided by subclassing.
     Abstract Factory creates a FAMILY of related products; the factory is
     an object passed by composition. Abstract Factory is often implemented
     using multiple Factory Methods.

  Q: Give a real-world analogy.
  A: IKEA vs Ashley Furniture. Both sell the same product types (sofa, table, lamp).
     But if you choose IKEA (factory), all your furniture looks consistent/matches.
     Abstract Factory ensures product families are consistent.

  Q: What happens if you need to add a new product type to an Abstract Factory?
  A: You must modify the AbstractFactory interface AND update all ConcreteFactory
     implementations. This is the main drawback — adding product types is a
     breaking change. Adding families (new ConcreteFactory) is easy.

  Q: How does Spring use Abstract Factory?
  A: ApplicationContext is an Abstract Factory — it creates beans of different types.
     EntityManagerFactory in JPA is an Abstract Factory for EntityManager instances.
     DataSourceFactory creates DataSource objects; swap provider by changing the factory.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------

  - Draw the factory diagram: AbstractFactory with 2 create methods, 2 ConcreteFactories,
    2 product hierarchies. It's a 2×2 grid of concrete classes.
  - Be able to code the full structure in ~30 lines (as shown above).
  - Key trade-off: easy to add families, hard to add product types.
  - Contrast with Factory Method every time you explain Abstract Factory.
  - Mention JPA/Spring DataSource as a real example — shows practical knowledge.
