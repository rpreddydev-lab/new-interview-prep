================================================================
  BEHAVIORAL PATTERNS — OVERVIEW
================================================================

  Behavioral patterns describe how objects COMMUNICATE and distribute
  responsibility among themselves.
  They define algorithms, control flow, and patterns of interaction.

  Core question answered: "How do objects collaborate and distribute work?"

----------------------------------------------------------------
THE 11 GoF BEHAVIORAL PATTERNS + BONUS
----------------------------------------------------------------

  Pattern               Problem Solved                                    Key Mechanism
  --------------------  -----------------------------------------------  ---------------------------
  Chain of Responsibility  Route request through handler chain           Linked handler list
  Command               Encapsulate request as an object                 Command interface + Invoker
  Interpreter           Define grammar and interpreter for a language    Abstract syntax tree
  Iterator              Sequential access without exposing internals     Cursor + hasNext/next
  Mediator              Centralize many-to-many communication            Central mediator object
  Memento               Save and restore object state (undo)             Opaque state snapshot
  Observer              One-to-many event notification                   Subscriber list + notify
  State                 Behavior changes based on internal state         State object per state
  Strategy              Interchangeable family of algorithms              Algorithm interface injection
  Template Method       Skeleton algorithm; vary steps in subclasses     Abstract base + overrides
  Visitor               Separate operation from object structure          Double dispatch

  Null Object (bonus):  Replace null checks with do-nothing object       NullObject implements interface

----------------------------------------------------------------
QUICK PATTERN SELECTION GUIDE
----------------------------------------------------------------

  Need to pass a request through a chain of handlers?             --> Chain of Responsibility
  Need undo/redo, queueing, logging of operations?                --> Command
  Need to interpret a language/grammar?                           --> Interpreter
  Need sequential access to collection without exposing internals? --> Iterator
  Need to reduce coupling between many communicating objects?     --> Mediator
  Need to save and restore state (undo)?                          --> Memento
  Need event/change notification across many listeners?           --> Observer
  Need object behavior to change with internal state?             --> State
  Need to swap algorithms or policies at runtime?                 --> Strategy
  Have an algorithm skeleton with steps that vary by subclass?    --> Template Method
  Need to add operations to an object structure without changing it? --> Visitor
  Want to avoid null checks across the codebase?                  --> Null Object

----------------------------------------------------------------
COMMON CONFUSIONS
----------------------------------------------------------------

  Strategy vs Template Method:
    Strategy: COMPOSITION — algorithm injected via interface reference.
    Template Method: INHERITANCE — base class defines skeleton, subclass fills steps.
    Both define interchangeable algorithms; differ in mechanism.

  Observer vs Mediator:
    Observer: one-to-many broadcasting — publisher notifies all subscribers.
    Mediator: many-to-many coordination — all communicate through central mediator.
    Observer is decentralized (publisher knows nothing about subscribers' types).
    Mediator is centralized (mediator knows all participants).

  Command vs Strategy:
    Strategy: selects HOW to execute an operation (algorithm choice).
    Command: encapsulates a specific REQUEST as an object (supports undo, queue).

  State vs Strategy:
    Strategy: algorithm swapped externally by CLIENT.
    State: state transitions managed internally by STATE OBJECTS.
    Both use composition to vary behavior; differ in who manages the variation.

  Chain of Responsibility vs Decorator:
    Chain: passes request to next handler; only ONE handler processes it.
    Decorator: ALL decorators in chain process the request (stack of wrappers).

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: How is Strategy different from Template Method?
  A: Template Method uses inheritance — base class defines skeleton, subclasses override steps.
     Strategy uses composition — algorithm is a separate object injected into the context.
     GoF recommendation: prefer composition (Strategy) over inheritance (Template Method).

  Q: How is Observer different from Mediator?
  A: Observer is decentralized broadcasting: Subject notifies all Observers.
     Mediator centralizes communication: objects talk through a mediator, not directly.
     Mediator is better when many objects need to interact with each other (not just one source).

  Q: What is the most common behavioral pattern in Spring?
  A: Observer (ApplicationEvent), Template Method (JdbcTemplate), and
     Chain of Responsibility (Security FilterChain) are all heavily used.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------

  - Know Observer and Strategy cold — they appear in almost every Java interview.
  - Template Method appears whenever a base class provides a "framework" and subclasses fill in details.
  - Chain of Responsibility is the mechanism behind Spring Security's filter chain.
  - For each pattern: know the GOF name, one Java library example, one Spring example.
