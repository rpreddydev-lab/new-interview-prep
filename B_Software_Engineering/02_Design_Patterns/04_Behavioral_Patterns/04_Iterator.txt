================================================================
  ITERATOR PATTERN
================================================================

  Category:   Behavioral
  Intent:     Provide a way to sequentially access elements of an aggregate
              object without exposing its underlying representation.
  GoF:        Yes — one of the original 23 patterns.
  Frequency:  Very common. java.util.Iterator and Iterable are built-in.
              Often tested implicitly through Java collections.

----------------------------------------------------------------
PROBLEM SOLVED
----------------------------------------------------------------

  Collections have different internal structures (array, linked list, tree, hash table).
  Client code shouldn't need to know the internal structure to iterate.
  Provide a uniform interface for traversal regardless of collection type.

  Without Iterator:
    Traversing an ArrayList requires index-based loop.
    Traversing a LinkedList requires following next pointers.
    Traversing a BST requires recursive traversal.
    Different traversal logic for each collection.

  With Iterator:
    All traversals: while(iterator.hasNext()) { item = iterator.next(); }
    Same code works for any collection.

----------------------------------------------------------------
PARTICIPANTS
----------------------------------------------------------------

  Iterable<T>      -- The aggregate; returns an Iterator<T> from iterator().
  Iterator<T>      -- hasNext(), next(); optionally remove().
  ConcreteIterable -- Specific collection (ArrayList, LinkedList, Tree).
  ConcreteIterator -- Specific traversal (forward, backward, level-order, filtered).

----------------------------------------------------------------
JAVA ITERATOR INTERFACE
----------------------------------------------------------------

  public interface Iterator<E> {
      boolean hasNext();
      E next();
      default void remove() { throw new UnsupportedOperationException(); }
      default void forEachRemaining(Consumer<? super E> action) {
          while (hasNext()) action.accept(next());
      }
  }

  public interface Iterable<T> {
      Iterator<T> iterator();
      // Enables for-each loop for the class
  }

  Enhanced for-loop is syntactic sugar for Iterator:
    for (String s : list) { ... }
    // compiles to:
    Iterator<String> it = list.iterator();
    while (it.hasNext()) { String s = it.next(); ... }

----------------------------------------------------------------
IMPLEMENTING CUSTOM ITERABLE — WORD RANGE
----------------------------------------------------------------

  // Custom Range: iterates integers from start to end
  public class Range implements Iterable<Integer> {
      private final int start;
      private final int end;

      public Range(int start, int end) {
          this.start = start;
          this.end   = end;
      }

      @Override
      public Iterator<Integer> iterator() {
          return new Iterator<Integer>() {
              private int current = start;

              @Override
              public boolean hasNext() { return current < end; }

              @Override
              public Integer next() {
                  if (!hasNext()) throw new NoSuchElementException();
                  return current++;
              }
          };
      }
  }

  // Usage
  Range range = new Range(1, 6);
  for (int n : range) {
      System.out.print(n + " ");   // 1 2 3 4 5
  }

TREE ITERATOR EXAMPLE (BINARY TREE IN-ORDER)
----------------------------------------------------------------

  public class BinaryTree<T> implements Iterable<T> {
      private Node<T> root;

      // Node class
      static class Node<T> {
          T value;
          Node<T> left, right;
          Node(T v) { value = v; }
      }

      @Override
      public Iterator<T> iterator() {
          return new InOrderIterator();
      }

      private class InOrderIterator implements Iterator<T> {
          private final Deque<Node<T>> stack = new ArrayDeque<>();

          public InOrderIterator() {
              pushLeft(root);
          }

          private void pushLeft(Node<T> node) {
              while (node != null) {
                  stack.push(node);
                  node = node.left;
              }
          }

          @Override
          public boolean hasNext() { return !stack.isEmpty(); }

          @Override
          public T next() {
              if (!hasNext()) throw new NoSuchElementException();
              Node<T> node = stack.pop();
              T value = node.value;
              pushLeft(node.right);   // push right subtree's left spine
              return value;
          }
      }
  }

JAVA ITERATOR IN PRACTICE — FAIL-FAST vs FAIL-SAFE
----------------------------------------------------------------

  FAIL-FAST Iterator (ArrayList, HashMap, etc.):
    - Throws ConcurrentModificationException if collection modified during iteration.
    - Uses modCount counter; throws if modCount changes between next() calls.
    - Purpose: detect bugs where collection is modified unsafely.

    List<String> list = new ArrayList<>(List.of("a","b","c"));
    Iterator<String> it = list.iterator();
    list.add("d");           // modifies list
    it.next();               // ConcurrentModificationException!

  FAIL-SAFE Iterator (CopyOnWriteArrayList, ConcurrentHashMap):
    - Works on a copy of the collection (or snapshot).
    - Does NOT throw ConcurrentModificationException.
    - May not reflect modifications made during iteration.

    CopyOnWriteArrayList<String> cowal = new CopyOnWriteArrayList<>();
    cowal.add("a"); cowal.add("b");
    for (String s : cowal) {
        cowal.add("c");   // safe — no exception, but "c" not seen in this iteration
    }

  Correct removal during iteration: use iterator.remove(), not list.remove():
    Iterator<String> it = list.iterator();
    while (it.hasNext()) {
        if (it.next().startsWith("a")) it.remove();  // safe removal
    }

    Or use removeIf (Java 8+):
    list.removeIf(s -> s.startsWith("a"));

----------------------------------------------------------------
EXTERNAL vs INTERNAL ITERATOR
----------------------------------------------------------------

  EXTERNAL (Java Iterator<T>):
    Client controls iteration — calls hasNext()/next() manually.
    + Client controls when to stop.
    + Multiple iterators can be active simultaneously.

  INTERNAL (forEach, Stream, each{}):
    The collection controls iteration — client passes behavior.
    + Simpler code.
    + Enables parallel iteration (Stream.parallel()).
    - Less control over stopping (need exception or terminal ops).

    // External
    Iterator<String> it = list.iterator();
    while (it.hasNext()) process(it.next());

    // Internal
    list.forEach(this::process);
    list.stream().filter(...).forEach(this::process);

ITERATOR IN SPRING
----------------------------------------------------------------

  ResourcePatternResolver: iterates over classpath resources.
  BeanDefinitionRegistry: iterate over registered bean definitions.
  Spring Batch: chunk-based processing uses ItemReader as an Iterator.

----------------------------------------------------------------
COMPLEXITY
----------------------------------------------------------------

  Space: O(1) for array-backed iterators. O(h) for tree iterators (stack depth).
  Time:  O(1) per hasNext() and next() call for most implementations.
         O(n) to iterate all elements.

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: What is the Iterator pattern?
  A: Provides sequential access to elements of an aggregate without exposing
     its internal representation. Java's Iterator<T> and Iterable<T>
     implement this pattern. For-each loops compile to Iterator calls.

  Q: What is the difference between fail-fast and fail-safe iterators?
  A: Fail-fast: throws ConcurrentModificationException if the collection is
     modified during iteration. Uses a modCount counter. ArrayList, HashMap.
     Fail-safe: works on a copy; no exception. CopyOnWriteArrayList, ConcurrentHashMap.

  Q: How do you safely remove elements during iteration?
  A: Use Iterator.remove() instead of Collection.remove(). Or use Java 8's
     collection.removeIf(predicate). Direct collection modification during
     Iterator-based iteration causes ConcurrentModificationException.

  Q: What's the difference between external and internal iterator?
  A: External: client drives iteration (hasNext/next). Allows pausing/stopping.
     Internal: collection drives iteration (forEach, Stream). Simpler code.

  Q: How does the for-each loop relate to Iterable?
  A: The Java compiler translates `for (T x : collection)` into an Iterator.
     The collection must implement Iterable<T> which returns Iterator<T>.
     If a class implements Iterable, it supports for-each loops.

INTERVIEW TIPS
----------------------------------------------------------------

  - Implement a custom Iterable class in interviews — shows understanding of the pattern.
  - The in-order tree iterator with a stack is a classic coding interview problem.
  - Know fail-fast vs fail-safe — very commonly asked in Java interviews.
  - Know iterator.remove() vs collection.remove() for safe removal.
  - Mention for-each compilation to Iterator — shows deep Java knowledge.
