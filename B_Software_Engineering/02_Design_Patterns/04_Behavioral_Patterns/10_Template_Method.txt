================================================================
  TEMPLATE METHOD PATTERN
================================================================

  Category:   Behavioral
  Intent:     Define the skeleton of an algorithm in an operation, deferring
              some steps to subclasses. Template Method lets subclasses
              redefine certain steps of an algorithm without changing the
              algorithm's structure.
  GoF:        Yes — one of the original 23 patterns.
  Frequency:  HIGH. Abstract classes in Java heavily use this pattern.
              Spring's JdbcTemplate, AbstractMessageListenerContainer,
              AbstractController, Servlet.service() all use it.

----------------------------------------------------------------
PROBLEM SOLVED
----------------------------------------------------------------

  Multiple classes share the SAME algorithmic structure but differ in specific steps.
  Without Template Method: either duplicate the entire algorithm or leave it to each
  subclass to implement (risking divergence or forgetting steps).

  With Template Method:
    Base class defines the INVARIANT skeleton (the template method).
    Abstract "hook" methods defer VARIANT steps to subclasses.
    Invariant logic written once. Subclasses only customize what differs.

  Core principle: "Don't call us, we'll call you" — Hollywood Principle.
                  Framework calls your overridden methods; you don't call the framework.

----------------------------------------------------------------
PARTICIPANTS
----------------------------------------------------------------

  AbstractClass  -- Defines the template method (final, usually).
                    Contains invariant steps as concrete methods.
                    Declares abstract primitive operations (steps).

  ConcreteClass  -- Extends AbstractClass.
                    Implements each abstract primitive operation.
                    Does NOT change the overall algorithm.

----------------------------------------------------------------
DATA MINING EXAMPLE
----------------------------------------------------------------

  // Abstract class with template method
  public abstract class DataMiner {

      // TEMPLATE METHOD — final: subclasses cannot alter the algorithm structure
      public final Report mine(String filePath) {
          String rawData    = extractData(filePath);   // step 1: variant
          String parsedData = parseData(rawData);       // step 2: variant
          String analyzed   = analyzeData(parsedData);  // step 3: invariant
          sendReport(analyzed);                          // step 4: invariant (hook)
          return generateReport(analyzed);               // step 5: invariant
      }

      // Abstract steps — subclasses MUST implement
      protected abstract String extractData(String filePath);
      protected abstract String parseData(String rawData);

      // Concrete invariant steps — shared by all subclasses
      private String analyzeData(String parsedData) {
          return "Analyzed: " + parsedData.toUpperCase();
      }

      // Hook — subclasses MAY override, but don't have to
      protected void sendReport(String analysis) {
          System.out.println("Saving report: " + analysis);
      }

      private Report generateReport(String analysis) {
          return new Report(analysis);
      }
  }

  // Concrete subclass: CSV miner
  public class CsvDataMiner extends DataMiner {
      @Override
      protected String extractData(String filePath) {
          return readCsvFile(filePath);
      }

      @Override
      protected String parseData(String rawData) {
          return parseCsvRows(rawData);
      }
  }

  // Concrete subclass: PDF miner
  public class PdfDataMiner extends DataMiner {
      @Override
      protected String extractData(String filePath) {
          return extractPdfText(filePath);
      }

      @Override
      protected String parseData(String rawData) {
          return parsePdfStructure(rawData);
      }

      @Override
      protected void sendReport(String analysis) {
          emailReport(analysis);   // override hook: email instead of save
      }
  }

  // Usage — client doesn't care which miner is used
  DataMiner miner = new CsvDataMiner();
  Report    report = miner.mine("/data/sales.csv");

----------------------------------------------------------------
HOOKS — OPTIONAL EXTENSION POINTS
----------------------------------------------------------------

  A "hook" is a concrete method with default (usually empty) implementation.
  Subclasses MAY override it — but don't have to.
  Used for optional steps in the algorithm.

  Example in Data Mining:
    protected void sendReport(String analysis) { }  // default: do nothing
    // PdfDataMiner can override to email; CsvDataMiner doesn't have to.

  // Another example: ordering with optional logging
  public abstract class OrderProcessor {
      public final void process(Order order) {
          validate(order);         // abstract — must implement
          beforeProcess(order);    // hook — optional
          executePayment(order);   // abstract — must implement
          afterProcess(order);     // hook — optional
          notifyCustomer(order);   // concrete — always runs
      }

      protected abstract void validate(Order order);
      protected abstract void executePayment(Order order);

      protected void beforeProcess(Order order) { }  // optional hook
      protected void afterProcess(Order order)  { }  // optional hook

      private void notifyCustomer(Order order) {
          System.out.println("Notification sent for order " + order.getId());
      }
  }

----------------------------------------------------------------
JAVA STDLIB EXAMPLES
----------------------------------------------------------------

  java.io.InputStream:
    int read(byte[] b) = template method
    int read()         = abstract primitive operation subclasses implement

  java.util.AbstractList<E>:
    size(), get() are abstract — subclasses implement (ArrayList, etc.)
    add(), remove(), iterator() build on top of get()/size()

  java.util.AbstractMap<K,V>:
    entrySet() is abstract — subclasses implement
    Template methods like containsKey(), values(), keySet() use entrySet()

  javax.servlet.HttpServlet:
    service(request, response) = template method
    doGet(), doPost(), doPut() = abstract/hook methods subclasses override

  Spring:
    JdbcTemplate.query() = template method
    RowMapper.mapRow() = abstract step (callback passed as parameter)

    AbstractController / SimpleFormController — processFormSubmission() template.
    AbstractMessageListenerContainer — executeListener() template.

----------------------------------------------------------------
COMPARING TEMPLATE METHOD IMPLEMENTATIONS
----------------------------------------------------------------

  CLASSIC (Inheritance):                 FUNCTIONAL (Composition — Java 8+):
  -----------------------------------------------
  abstract class base                    Pass behavior as lambdas/callbacks
  Subclasses override steps             Inject Function<A,B> parameters
  compile-time                          Runtime configurable
  Cannot reuse across class hierarchies  Reusable — no inheritance needed
  -----------------------------------------------

  // Functional equivalent (no inheritance needed):
  public class DataMiner {
      private final Function<String, String> extractor;
      private final Function<String, String> parser;

      public DataMiner(Function<String, String> extractor,
                       Function<String, String> parser) {
          this.extractor = extractor;
          this.parser    = parser;
      }

      public Report mine(String filePath) {
          String raw      = extractor.apply(filePath);
          String parsed   = parser.apply(raw);
          String analyzed = analyzeData(parsed);
          return generateReport(analyzed);
      }

      private String analyzeData(String data)     { return "Analyzed: " + data; }
      private Report generateReport(String data)  { return new Report(data); }
  }

  // Usage — lambdas replace subclasses
  DataMiner csvMiner = new DataMiner(
      path -> readCsvFile(path),
      raw  -> parseCsv(raw)
  );

  // Rule: Prefer functional/Strategy when Java 8+. Use abstract class Template
  // when steps have shared state or complex interactions.

----------------------------------------------------------------
TEMPLATE METHOD vs STRATEGY
----------------------------------------------------------------

  Template Method:                    Strategy:
  -----------------------------------------------
  INHERITANCE (IS-A)                  COMPOSITION (HAS-A)
  Algorithm structure in base class   Algorithm entirely in strategy class
  Steps overridden in subclasses      Whole algorithm swapped
  Compile-time binding                Runtime binding
  Abstract class required             Interface used
  Less flexible (single inheritance)  More flexible
  Simpler for shared state            Better for stateless algorithms
  -----------------------------------------------

  If the steps need access to base class state/helper methods: Template Method.
  If the algorithm is self-contained and swappable: Strategy.
  Modern Java: prefer Strategy with lambdas (avoids inheritance).

----------------------------------------------------------------
COMPLEXITY
----------------------------------------------------------------

  Space: O(1) — no extra state. One class per variant.
  Time:  O(1) dispatch — method override resolved at compile time.

  Class count: O(n) for n variants — can lead to class proliferation.
               Functional approach eliminates this.

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: What is the Template Method pattern?
  A: Defines the skeleton of an algorithm in an abstract class. Invariant steps
     are concrete methods. Variant steps are abstract methods that subclasses
     implement. The template method (often final) calls the steps in order.
     Subclasses fill in the blanks without changing the overall algorithm.

  Q: What is the Hollywood Principle?
  A: "Don't call us, we'll call you." The framework (base class) calls the
     subclass methods — not the other way around. The base class is in control
     of when to call the overridden steps.

  Q: What are hooks in Template Method?
  A: Hooks are concrete methods with a default (empty) implementation that
     subclasses may optionally override. They provide extension points within
     the algorithm without making them mandatory. Example: beforeProcess(),
     afterProcess() in an order processor.

  Q: Template Method vs Strategy?
  A: Template Method: inheritance; skeleton in base class; steps overridden.
     Strategy: composition; entire algorithm in strategy class; runtime swappable.
     Modern Java prefers Strategy + lambdas (avoids inheritance limitations).

  Q: Name Java stdlib examples of Template Method.
  A: javax.servlet.HttpServlet (service() calls doGet()/doPost()),
     java.util.AbstractList (get/size abstract; other methods use them),
     Spring JdbcTemplate (query template, RowMapper for mapping step).

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------

  - HttpServlet is the most widely known Java Template Method example.
  - Show a custom abstract class with final template method + abstract steps.
  - Demonstrate hooks (optional steps with empty default).
  - Know the functional alternative (Strategy + lambdas) as the modern approach.
  - Template Method vs Strategy contrast is very commonly asked.
