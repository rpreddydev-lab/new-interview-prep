================================================================
  INTERPRETER PATTERN
================================================================

  Category:   Behavioral
  Intent:     Given a language, define a representation for its grammar along
              with an interpreter that uses the representation to interpret
              sentences in the language.
  GoF:        Yes — one of the original 23 patterns.
  Frequency:  Low-moderate. Complex to implement. Used in compilers, rule
              engines, query parsers, regular expressions, expression evaluators.
              Often replaced by ANTLR, SpEL, JEXL, or scripting engines.
  Also known: Grammars, Language Interpreter, Expression Tree.

----------------------------------------------------------------
PROBLEM SOLVED
----------------------------------------------------------------

  You need to interpret sentences in a simple, well-defined language or grammar.
  Examples:
    - SQL/HQL filter expressions
    - Boolean rule expressions (age > 18 AND country == "US")
    - Mathematical expression evaluators
    - Regular expression matching
    - Configuration DSLs

  With Interpreter:
    Grammar rules → class hierarchy.
    Terminal expressions: leaf nodes (numbers, variables).
    Non-terminal expressions: composite nodes (operators, logical AND/OR).
    interpret(context) walks the expression tree.

----------------------------------------------------------------
GRAMMAR STRUCTURE
----------------------------------------------------------------

  An expression grammar (simplified):

  expression ::= number
               | variable
               | expression '+' expression
               | expression '-' expression
               | expression '*' expression
               | '(' expression ')'

  Interpreter maps each grammar rule to a class.
  Each class implements interpret(context) → value.

----------------------------------------------------------------
MATHEMATICAL EXPRESSION INTERPRETER
----------------------------------------------------------------

  // Context — holds variable bindings
  public class Context {
      private final Map<String, Integer> variables = new HashMap<>();

      public void set(String var, int value)  { variables.put(var, value); }
      public int  get(String var)             { return variables.get(var); }
  }

  // Abstract Expression interface
  public interface Expression {
      int interpret(Context context);
  }

  // Terminal Expression: literal number
  public class NumberExpression implements Expression {
      private final int value;
      public NumberExpression(int value) { this.value = value; }

      @Override
      public int interpret(Context context) { return value; }
  }

  // Terminal Expression: variable
  public class VariableExpression implements Expression {
      private final String name;
      public VariableExpression(String name) { this.name = name; }

      @Override
      public int interpret(Context context) { return context.get(name); }
  }

  // Non-terminal Expression: addition
  public class AddExpression implements Expression {
      private final Expression left;
      private final Expression right;

      public AddExpression(Expression left, Expression right) {
          this.left  = left;
          this.right = right;
      }

      @Override
      public int interpret(Context context) {
          return left.interpret(context) + right.interpret(context);
      }
  }

  // Non-terminal Expression: multiplication
  public class MultiplyExpression implements Expression {
      private final Expression left;
      private final Expression right;

      public MultiplyExpression(Expression left, Expression right) {
          this.left  = left;
          this.right = right;
      }

      @Override
      public int interpret(Context context) {
          return left.interpret(context) * right.interpret(context);
      }
  }

  // Non-terminal Expression: subtraction
  public class SubtractExpression implements Expression {
      private final Expression left;
      private final Expression right;

      public SubtractExpression(Expression left, Expression right) {
          this.left  = left;
          this.right = right;
      }

      @Override
      public int interpret(Context context) {
          return left.interpret(context) - right.interpret(context);
      }
  }

  // Build and interpret: (a + b) * (a - 3)
  Context context = new Context();
  context.set("a", 10);
  context.set("b", 5);

  Expression a       = new VariableExpression("a");
  Expression b       = new VariableExpression("b");
  Expression three   = new NumberExpression(3);

  Expression sum     = new AddExpression(a, b);          // a + b = 15
  Expression diff    = new SubtractExpression(a, three); // a - 3 = 7
  Expression product = new MultiplyExpression(sum, diff);// (a+b) * (a-3) = 105

  System.out.println(product.interpret(context));  // 105

  Tree visualization:
          (*)
         /   \
       (+)   (-)
       / \   / \
      a   b a   3

BOOLEAN RULE ENGINE EXAMPLE
----------------------------------------------------------------

  // Boolean expression interpreter for business rules
  public interface BooleanExpression {
      boolean evaluate(Map<String, Object> context);
  }

  public class GreaterThan implements BooleanExpression {
      private final String field;
      private final int    threshold;

      public GreaterThan(String field, int threshold) {
          this.field     = field;
          this.threshold = threshold;
      }

      @Override
      public boolean evaluate(Map<String, Object> context) {
          return ((Integer) context.get(field)) > threshold;
      }
  }

  public class AndExpression implements BooleanExpression {
      private final BooleanExpression left;
      private final BooleanExpression right;

      public AndExpression(BooleanExpression left, BooleanExpression right) {
          this.left  = left;
          this.right = right;
      }

      @Override
      public boolean evaluate(Map<String, Object> context) {
          return left.evaluate(context) && right.evaluate(context);
      }
  }

  // Rule: age > 18 AND score > 700
  BooleanExpression rule = new AndExpression(
      new GreaterThan("age",   18),
      new GreaterThan("score", 700)
  );

  Map<String, Object> user = Map.of("age", 25, "score", 750);
  System.out.println(rule.evaluate(user));  // true

  // Add new rules (OrExpression, NotExpression) without modifying existing.

REAL-WORLD IMPLEMENTATIONS
----------------------------------------------------------------

  java.util.regex.Pattern:
    Regular expressions are compiled into an expression tree.
    Pattern.compile("\\d+") builds an interpreter.
    Matcher.matches() is the interpret() call.

  Spring SpEL (Spring Expression Language):
    ExpressionParser parser = new SpelExpressionParser();
    Expression expr = parser.parseExpression("#age > 18 and #country == 'US'");
    boolean result  = expr.getValue(context, Boolean.class);

  Spring Security SpEL:
    @PreAuthorize("hasRole('ADMIN') and #user.id == principal.id")
    Parsed and interpreted by Spring Security's expression evaluator.

  Hibernate HQL / JPQL:
    String hql = "FROM Customer c WHERE c.age > :age";
    HQL parsed into an expression tree, interpreted against the database schema.

  Apache Commons JEXL:
    JexlEngine jexl = new JexlBuilder().create();
    JexlExpression e = jexl.createExpression("price * 0.9 + shipping");

  Java Scripting API (JSR 223):
    ScriptEngine engine = new ScriptEngineManager().getEngineByName("js");
    engine.eval("var x = 10 + 5;");

----------------------------------------------------------------
WHEN TO USE vs ALTERNATIVES
----------------------------------------------------------------

  USE Interpreter when:
    - Grammar is simple and stable.
    - Sentences are few and performance is not critical.
    - Building a DSL or rule engine from scratch.

  DON'T USE (use alternatives) when:
    - Grammar is complex or changes often — use ANTLR, JavaCC, or a parser library.
    - Performance matters — parse once to AST, evaluate with Visitor not Interpreter.
    - Expression language already exists — use SpEL, JEXL, Groovy scripting, MVEL.

  ANTLR (ANother Tool for Language Recognition):
    Industry-standard parser generator. Generates lexer + parser + visitor.
    Used by Hibernate, Drools, Kotlin (for their DSLs).

----------------------------------------------------------------
COMPOSITE WITH VISITOR PATTERN (MODERN APPROACH)
----------------------------------------------------------------

  Expression trees often separate:
    1. BUILDING the tree (Interpreter pattern — expression classes).
    2. TRAVERSAL/OPERATIONS (Visitor pattern — interpret, typecheck, optimize).

  This separates tree structure from operations.
  New operations (optimize, print, compile) → new Visitors.
  Expression classes stay unchanged.

  Expression tree = Composite pattern for structure.
  Visitor for operations over the tree.
  Combined: the AST pattern used in all compilers.

----------------------------------------------------------------
COMPLEXITY
----------------------------------------------------------------

  Space: O(n) — n nodes in the expression tree. Each node = one object.
  Time:  O(n) interpret — visit every node in the tree.

  Grammar with k rules: k expression classes (one per grammar production).
  Large grammars = class explosion — main drawback.

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: What is the Interpreter pattern?
  A: Defines a grammar for a language and implements an interpreter that uses
     a class hierarchy to represent grammar rules. Each class implements
     interpret(context). Composes into an expression tree. Walking the tree
     evaluates the expression. Used for DSLs, rule engines, expression evaluators.

  Q: What are terminal vs non-terminal expressions?
  A: Terminal: leaf nodes. No sub-expressions. (NumberExpression, VariableExpression).
     Non-terminal: composite nodes. Have sub-expressions. (AddExpression, AndExpression).
     Non-terminals call interpret() on children recursively.

  Q: Where is Interpreter used in Java?
  A: java.util.regex.Pattern (regex), Spring SpEL, Hibernate HQL/JPQL parser,
     Apache JEXL, Java Scripting API (JSR 223).

  Q: When NOT to use Interpreter?
  A: Complex grammars — class explosion, hard to maintain.
     Use ANTLR, JavaCC for complex grammars.
     Use existing expression languages (SpEL, Groovy) instead of building your own.

  Q: How does Interpreter relate to Composite and Visitor?
  A: Expression tree IS a Composite (leaf nodes and composite nodes with same interface).
     Operations over the tree (interpret, typecheck, optimize) are often implemented
     as Visitors for flexibility (separate operations from structure).

INTERVIEW TIPS
----------------------------------------------------------------

  - Show a simple math expression evaluator — clean implementation is impressive.
  - Mention Spring SpEL as the most relevant real-world Java example.
  - Know when NOT to use: complex grammars → ANTLR.
  - Describe the tree structure clearly: terminal (leaves) vs non-terminal (composites).
  - Mention the relationship with Composite and Visitor for AST patterns.
