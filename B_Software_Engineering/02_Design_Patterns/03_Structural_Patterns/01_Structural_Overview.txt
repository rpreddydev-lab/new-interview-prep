================================================================
  STRUCTURAL PATTERNS — OVERVIEW
================================================================

  Structural patterns describe how classes and objects are COMPOSED
  to form larger, more flexible structures.
  They use INHERITANCE and OBJECT COMPOSITION to create relationships
  between entities.

  Core question answered: "How should objects be assembled?"

----------------------------------------------------------------
THE 7 GoF STRUCTURAL PATTERNS
----------------------------------------------------------------

  Pattern     Problem Solved                                       Key Mechanism
  ----------  ---------------------------------------------------  ---------------------------
  Adapter     Incompatible interfaces must work together           Wrapper with translated calls
  Bridge      Abstraction + implementation vary independently      Composition over inheritance
  Composite   Part-whole tree hierarchies, uniform treatment       Recursive component structure
  Decorator   Add behavior at runtime without subclassing          Wrapper + same interface
  Facade      Simplify complex subsystem with single interface     Single entry-point class
  Flyweight   Share objects to avoid memory overhead               Intrinsic vs extrinsic state
  Proxy       Control access to another object                     Surrogate with same interface

----------------------------------------------------------------
QUICK PATTERN SELECTION GUIDE
----------------------------------------------------------------

  Need to make two incompatible interfaces work together?
    --> Adapter

  Need abstraction and implementation to vary independently?
    --> Bridge

  Need to treat single objects and groups of objects uniformly?
  Have tree-like structures (file system, UI hierarchy)?
    --> Composite

  Need to add behavior (logging, auth, retry) at runtime?
  Want to avoid deep inheritance hierarchy?
    --> Decorator

  Have a complex subsystem with many classes/methods?
  Want to expose a simple API hiding complexity?
    --> Facade

  Have thousands of similar objects eating too much memory?
  Objects share a lot of the same data?
    --> Flyweight

  Need lazy initialization, access control, caching, logging of method calls?
  Want AOP-style cross-cutting concerns?
    --> Proxy

----------------------------------------------------------------
COMMON CONFUSIONS AND HOW TO DISTINGUISH
----------------------------------------------------------------

  Decorator vs Proxy:
    Both wrap an object and share the same interface.
    Decorator: adds NEW behavior/functionality (wraps to enhance).
    Proxy:     controls ACCESS to existing behavior (wraps to guard/delay/cache).

  Adapter vs Decorator:
    Adapter: wraps to CHANGE the interface (make incompatible things compatible).
    Decorator: wraps with the SAME interface (add behavior transparently).

  Adapter vs Bridge:
    Adapter: makes EXISTING incompatible interfaces work (post-hoc fix).
    Bridge: DESIGNS for independent variation upfront (planned separation).

  Facade vs Adapter:
    Facade: simplifies a subsystem for CONVENIENCE.
    Adapter: makes an interface COMPATIBLE with what client expects.

  Composite vs Decorator:
    Composite: tree structure (many children). Uniform treatment of leaf/composite.
    Decorator: linear wrapping (single component wrapped in layers).

STRUCTURAL PATTERNS IN JAVA STANDARD LIBRARY
----------------------------------------------------------------

  Pattern     Java Standard Library Example
  ----------  -------------------------------------------------------
  Adapter     Arrays.asList(), InputStreamReader(InputStream), Collections.list()
  Bridge      JDBC drivers (java.sql.Driver abstraction + vendor impl)
  Composite   Component in Swing (JPanel contains JButton which is also Component)
  Decorator   Java I/O: BufferedReader(FileReader), GZIPOutputStream(FileOutputStream)
  Facade      SLF4J Logger, java.util.Calendar (wraps complex date logic)
  Flyweight   Integer.valueOf(-128..127) cache, String.intern()
  Proxy       java.lang.reflect.Proxy (JDK dynamic proxy), RMI stubs

----------------------------------------------------------------
STRUCTURAL PATTERNS IN SPRING
----------------------------------------------------------------

  Pattern     Spring Example
  ----------  -------------------------------------------------------
  Adapter     Spring MVC HandlerAdapter (adapts different controllers)
  Bridge      Spring's PlatformTransactionManager (bridges to JPA/JDBC)
  Composite   CompositeValidator, CompositeFilter
  Decorator   Spring Security HttpSecurity filter wrapping
  Facade      JdbcTemplate, RestTemplate, RedisTemplate (facade over complex APIs)
  Flyweight   Spring bean caching, JSR-107 cache annotations
  Proxy       @Transactional, @Cacheable, @Async, @Retryable (AOP proxies via CGLIB/JDK)

----------------------------------------------------------------
STRUCTURAL PATTERN COMPLEXITY COMPARISON
----------------------------------------------------------------

  Pattern     Implementation Complexity   Runtime Overhead    Memory Impact
  ----------  -------------------------   ----------------    ---------------
  Adapter     Low                         Minimal             Minimal
  Bridge      Medium                      Minimal             Low
  Composite   Medium                      Minimal             Proportional to tree
  Decorator   Low-Medium                  1 extra call/layer  Low
  Facade      Low                         Minimal             Minimal
  Flyweight   High                        Low                 Reduced significantly
  Proxy       Medium                      1 extra call        Low

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: What is the difference between Decorator and Proxy?
  A: Both share the same interface as the wrapped object.
     Decorator adds NEW behavior to enhance the wrapped object.
     Proxy controls ACCESS — may lazy-initialize, check permissions, cache, or log.
     Decorator focuses on "what extra does this do?"
     Proxy focuses on "should I even call this / how do I call this?"

  Q: When would you use Facade over Adapter?
  A: Facade: when you want to simplify your own complex subsystem for convenience.
     Adapter: when you must work with an EXTERNAL incompatible interface that you
     can't change. Adapter makes things compatible; Facade makes things simple.

  Q: Is Composite a Structural or Behavioral pattern?
  A: Structural — it defines how objects are composed into tree structures.
     The uniformity of treatment (same interface for leaf and composite)
     is a structural relationship, not a behavioral algorithm.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------

  - Know the pattern for each: Decorator = Java I/O, Proxy = Spring AOP, Adapter = Java Collections.
  - Always give a real-world Java/Spring example for each pattern.
  - Distinguish confusable pairs: Decorator vs Proxy, Adapter vs Decorator.
  - Proxy is the most interview-important structural pattern for Spring developers.
