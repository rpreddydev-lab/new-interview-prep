================================================================
  FACADE PATTERN
================================================================

  Category:   Structural
  Intent:     Provide a unified, simplified interface to a complex subsystem.
              Facade hides the subsystem's complexity without changing it.
  GoF:        Yes — one of the original 23 patterns.
  Frequency:  Very common. Seen in almost every framework. Easy to implement.

----------------------------------------------------------------
PROBLEM SOLVED
----------------------------------------------------------------

  A complex subsystem has many classes with complex interactions.
  Client code shouldn't need to know all the internal classes to get work done.
  Clients want a SIMPLE ENTRY POINT that handles common use cases.

  Without Facade: Client must know and interact with:
    VideoDecoder, AudioDecoder, BitrateReader, FrameMapper, CodecFactory...

  With Facade:
    VideoConverter.convert("video.avi", "mp4") — one method, done.
    Facade orchestrates all the subsystem classes internally.

  Real-world analogy:
    A hotel concierge is a Facade for the hotel's subsystems:
    rooms, housekeeping, restaurant, transportation, etc.
    Guest talks to ONE person; concierge coordinates all departments.

----------------------------------------------------------------
PARTICIPANTS
----------------------------------------------------------------

  Facade         -- Simple interface over the subsystem.
                    Delegates to appropriate subsystem classes.
  Subsystem      -- The complex set of classes.
                    Knows nothing about the Facade.
                    Client CAN still access subsystem directly if needed.
  Client         -- Uses Facade instead of dealing with subsystem directly.

  Key: Facade DOES NOT prevent direct access to subsystem. It's a convenience layer.

----------------------------------------------------------------
FULL JAVA EXAMPLE — HOME THEATER SYSTEM
----------------------------------------------------------------

  // Subsystem classes (complex, many)
  public class DVDPlayer {
      public void on()               { System.out.println("DVD on"); }
      public void play(String movie) { System.out.println("Playing: " + movie); }
      public void stop()             { System.out.println("DVD stop"); }
      public void off()              { System.out.println("DVD off"); }
  }

  public class Projector {
      public void on()        { System.out.println("Projector on"); }
      public void wideScreen(){ System.out.println("Projector: wide screen mode"); }
      public void off()       { System.out.println("Projector off"); }
  }

  public class SoundSystem {
      public void on()              { System.out.println("Sound on"); }
      public void setVolume(int v)  { System.out.println("Volume: " + v); }
      public void off()             { System.out.println("Sound off"); }
  }

  public class Lights {
      public void dim(int level) { System.out.println("Lights dimmed to " + level + "%"); }
      public void on()           { System.out.println("Lights on"); }
  }

  // FACADE — one simple interface
  public class HomeTheaterFacade {
      private final DVDPlayer   dvd;
      private final Projector   projector;
      private final SoundSystem sound;
      private final Lights      lights;

      public HomeTheaterFacade(DVDPlayer dvd, Projector p, SoundSystem s, Lights l) {
          this.dvd = dvd; this.projector = p; this.sound = s; this.lights = l;
      }

      public void watchMovie(String movie) {
          System.out.println("--- Watch Movie Mode ---");
          lights.dim(10);
          projector.on();
          projector.wideScreen();
          sound.on();
          sound.setVolume(8);
          dvd.on();
          dvd.play(movie);
      }

      public void endMovie() {
          System.out.println("--- End Movie Mode ---");
          dvd.stop();
          dvd.off();
          sound.off();
          projector.off();
          lights.on();
      }
  }

  // Client — one method call does everything
  HomeTheaterFacade theater = new HomeTheaterFacade(dvd, projector, sound, lights);
  theater.watchMovie("Inception");
  // ...
  theater.endMovie();

----------------------------------------------------------------
FACADE IN JAVA STANDARD LIBRARY
----------------------------------------------------------------

  SLF4J Logger:
    - Client calls: Logger.info("message")
    - Internally: may delegate to Log4j, Logback, JUL, etc.
    - Client never knows or cares which logging implementation is used.

  java.util.Calendar:
    - Wraps complex date/time computation, locale awareness, timezone.
    - Client calls: Calendar.getInstance().get(Calendar.DAY_OF_WEEK)

  java.net.URL / HttpURLConnection:
    - Hides TCP, HTTP protocol, DNS lookup, etc.
    - Client calls: new URL("http://...").openStream()

  javax.faces.context.FacesContext (JSF):
    - Facade over servlet request, response, session, application context.

----------------------------------------------------------------
FACADE IN SPRING
----------------------------------------------------------------

  JdbcTemplate:
    - Facade over raw JDBC.
    - Handles: get connection, create statement, execute, handle exceptions,
               close connection — all hidden.
    - Client calls: jdbcTemplate.queryForList("SELECT * FROM users")

  RestTemplate / WebClient:
    - Facade over HTTP client internals.
    - Handles serialization, error handling, connection management.

  RedisTemplate:
    - Facade over Jedis/Lettuce Redis clients.

  SpringApplication.run():
    - Facade that starts embedded server, loads beans, runs initializers.
    - One call hides entire Spring Boot startup sequence.

  @Transactional (conceptually):
    - Facade over begin/commit/rollback transaction management.

----------------------------------------------------------------
FACADE FOR LAYERED ARCHITECTURE
----------------------------------------------------------------

  In real applications, Facade often appears as a Service layer:

    Controller --> OrderFacade --> OrderService + PaymentService + InventoryService + NotificationService

  public class OrderFacade {
      private final OrderService     orderService;
      private final PaymentService   paymentService;
      private final InventoryService inventoryService;
      private final NotificationService notifyService;

      // Constructor injection

      public OrderConfirmation placeOrder(OrderRequest request) {
          // Orchestrates all subsystem calls:
          inventoryService.reserve(request.getItems());
          PaymentResult payment = paymentService.charge(request.getPayment());
          Order order = orderService.create(request, payment);
          notifyService.sendConfirmation(order);
          return new OrderConfirmation(order.getId(), payment.getTransactionId());
      }
  }

  Controller calls ONE method; Facade handles all coordination.

----------------------------------------------------------------
FACADE vs ADAPTER vs MEDIATOR
----------------------------------------------------------------

  Facade:
    - Simplifies an existing subsystem for convenience.
    - One-to-many: Facade --> multiple subsystem classes.
    - Subsystem classes don't know about each other.

  Adapter:
    - Makes incompatible interfaces work together.
    - Translates one interface to another.
    - Focused on interface conversion, not simplification.

  Mediator:
    - Objects communicate through a central mediator.
    - Many-to-many: mediator knows ALL participants; they know mediator.
    - Reduces coupling BETWEEN subsystem components (they communicate through mediator).

  Key difference from Mediator:
    Facade: client → facade → subsystems (one-directional convenience layer).
    Mediator: components ↔ mediator ↔ components (bidirectional coordination).

----------------------------------------------------------------
FACADE vs SERVICE LAYER PATTERN
----------------------------------------------------------------

  Service Layer (Enterprise Architecture) is very similar to Facade but:
    - Service Layer defines APPLICATION OPERATIONS (use cases).
    - Facade just SIMPLIFIES an existing interface.

  In practice, the Facade and Service Layer patterns overlap heavily in Spring apps.
  @Service classes often act as both — simplify subsystem and define use cases.

----------------------------------------------------------------
COMPLEXITY
----------------------------------------------------------------

  Facade method: O(sum of all internal calls) — no additional overhead.
  Space: O(1) — Facade just holds references to subsystem objects.
  Development: Reduces client code complexity significantly.
               Adds one indirection level (very minor overhead).

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: What is the Facade pattern?
  A: It provides a single simplified interface to a complex subsystem.
     Client talks to the Facade instead of dealing with many subsystem classes.
     Facade coordinates the subsystem internally; client code is simpler and
     less coupled to subsystem internals.

  Q: Does Facade prevent access to subsystem classes?
  A: No — Facade is optional. Clients CAN still access subsystem classes
     directly if they need fine-grained control. Facade just provides convenience.

  Q: How is Facade different from Adapter?
  A: Adapter makes incompatible interfaces compatible (interface translation).
     Facade simplifies a compatible but complex subsystem (convenience layer).
     Adapter changes "what the interface looks like"; Facade hides "how complex it is."

  Q: Give a Spring example of Facade.
  A: JdbcTemplate is a Facade over raw JDBC. It hides connection management,
     statement creation, exception handling, and resource cleanup. Client just
     provides SQL and parameters. RestTemplate is similar for HTTP clients.

  Q: Is the Service layer in Spring Boot a Facade?
  A: Yes, conceptually. @Service classes often act as Facades over multiple
     repositories and domain services, providing a simplified API to controllers.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------

  - JdbcTemplate is the must-know Spring Facade example.
  - Home theater or hotel concierge are intuitive real-world analogies.
  - Facade is easy to implement and code in interviews — just one class with injected dependencies.
  - Distinguish from Adapter (interface change) and Mediator (bidirectional coordination).
  - Facade naturally appears in any layered architecture — service layer, API gateway.
