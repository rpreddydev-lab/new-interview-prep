================================================================
  COUNTING SORT
================================================================

----------------------------------------------------------------
HOW IT WORKS
----------------------------------------------------------------
Non-comparison sort. Count occurrences of each value.
Compute prefix sums for positions. Place elements in output array.

  int[] countingSort(int[] arr, int k) {  // values in [0, k)
    int[] count = new int[k];
    for (int x : arr) count[x]++;

    // Prefix sum: count[i] = number of elements <= i
    for (int i = 1; i < k; i++) count[i] += count[i-1];

    // Build output (iterate right to left for stability)
    int[] output = new int[arr.length];
    for (int i = arr.length - 1; i >= 0; i--) {
      output[--count[arr[i]]] = arr[i];
    }
    return output;
  }

  Time:  O(n + k)  where k = range of values
  Space: O(n + k)  for count array and output
  Stable: Yes (if iterating right-to-left in output step)
  Comparison-based: No

  When to use: k = O(n) -- values in a bounded range.
  When NOT to use: k >> n (range much larger than count -- waste of space).

----------------------------------------------------------------
SIMPLIFIED COUNTING SORT (just count, no stability)
----------------------------------------------------------------
  If you just need sorted values (not stable placement):
    int[] count = new int[k];
    for (int x : arr) count[x]++;
    int idx = 0;
    for (int v = 0; v < k; v++)
      while (count[v]-- > 0) arr[idx++] = v;

  O(n + k) time, O(k) space. Simple but not stable.

----------------------------------------------------------------
COUNTING SORT WITH NEGATIVE VALUES
----------------------------------------------------------------

    int max = Arrays.stream(arr).max().getAsInt();
    int k = max - min + 1;

----------------------------------------------------------------
INTERVIEW QUESTIONS
----------------------------------------------------------------

Q: What is the time complexity of Counting Sort and when is
   it better than O(n log n) comparison sorts?
A: Counting Sort is O(n + k) where n = number of elements,
   k = range of values. It beats comparison sorts when k = O(n),
   i.e., the range is proportional to the count. For example,
   sorting n ages (0-150): k = 151, much better than O(n log n).
   But for sorting n 32-bit integers: k = 2^32 = 4 billion, which
   would require 4GB of space -- impractical. The comparison-sort
   lower bound of Omega(n log n) doesn't apply because Counting
   Sort doesn't compare elements.

Q: Why do you iterate right-to-left for stability in Counting Sort?
A: We want equal elements to maintain their original left-to-right
   order. By iterating the input from right to left and decrementing
   the position counter, the rightmost occurrence of a value gets
   placed at the rightmost available position. This ensures that
   the relative order of equal elements is preserved, making
   the sort stable.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. Counting Sort is O(n + k) -- useful when k is O(n)
  2. It's the base sort for Radix Sort (must be stable)
  3. Use cases: sort characters, sort ages, sort grades, sort digits
  4. Java's Arrays.sort is NOT Counting Sort; use it manually
     when you know the value range is small
  5. The prefix-sum trick for placement: count[i] gives the
     index AFTER the last occurrence of i in the output
