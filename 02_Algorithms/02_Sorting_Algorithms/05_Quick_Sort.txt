================================================================
  QUICK SORT
================================================================

----------------------------------------------------------------
HOW IT WORKS
----------------------------------------------------------------
Divide and Conquer: choose a pivot, partition array so elements
< pivot are left, > pivot are right. Recurse on both sides.

  void quickSort(int[] arr, int left, int right) {
    if (left >= right) return;
    int pivotIdx = partition(arr, left, right);
    quickSort(arr, left, pivotIdx - 1);
    quickSort(arr, pivotIdx + 1, right);
  }

  // Lomuto partition: pivot at right
  int partition(int[] arr, int left, int right) {
    int pivot = arr[right];
    int i = left - 1;            // i tracks last element <= pivot
    for (int j = left; j < right; j++) {
      if (arr[j] <= pivot) {
        i++;
        int tmp = arr[i]; arr[i] = arr[j]; arr[j] = tmp;
      }
    }
    int tmp = arr[i+1]; arr[i+1] = arr[right]; arr[right] = tmp;
    return i + 1;
  }

  Time: O(n log n) avg, O(n^2) worst   Space: O(log n) stack avg
  In-place: Yes   Stable: No

----------------------------------------------------------------
HOARE vs LOMUTO PARTITION
----------------------------------------------------------------
  Lomuto (above): simpler, always puts pivot at final position.
    3x more swaps than Hoare on average.

  Hoare: two pointers from both ends, fewer swaps.
    int partitionHoare(int[] arr, int left, int right) {
      int pivot = arr[left + (right - left) / 2];
      int i = left - 1, j = right + 1;
      while (true) {
        do { i++; } while (arr[i] < pivot);
        do { j--; } while (arr[j] > pivot);
        if (i >= j) return j;
        int tmp = arr[i]; arr[i] = arr[j]; arr[j] = tmp;
      }
    }
    // Recurse: quickSort(arr, left, j) and quickSort(arr, j+1, right)
    // Note: Hoare returns j, NOT the final pivot position

----------------------------------------------------------------
RANDOMIZED QUICK SORT
----------------------------------------------------------------
Swap a random element with arr[right] before partitioning.
This eliminates the O(n^2) worst case for adversarial inputs.

  void quickSortRandom(int[] arr, int left, int right) {
    if (left >= right) return;
    int randIdx = left + (int)(Math.random() * (right - left + 1));
    int tmp = arr[randIdx]; arr[randIdx] = arr[right]; arr[right] = tmp;
    int pivot = partition(arr, left, right);
    quickSortRandom(arr, left, pivot - 1);
    quickSortRandom(arr, pivot + 1, right);
  }
  Expected time: O(n log n)  with probability 1 - 1/n

----------------------------------------------------------------
3-WAY PARTITION (Dutch National Flag) for duplicates
----------------------------------------------------------------
When there are many duplicates, standard partition is O(n^2).
3-way partition handles equal elements in O(n) per pass.

  void quickSort3Way(int[] arr, int left, int right) {
    if (left >= right) return;
    int lo = left, hi = right, mid = left;
    int pivot = arr[left];
    while (mid <= hi) {
      if (arr[mid] < pivot)        swap(arr, lo++, mid++);
      else if (arr[mid] > pivot)   swap(arr, mid, hi--);
      else                         mid++;  // equal to pivot
    }
    // arr[left..lo-1] < pivot, arr[lo..hi] == pivot, arr[hi+1..right] > pivot
    quickSort3Way(arr, left, lo - 1);
    quickSort3Way(arr, hi + 1, right);
  }

  Time: O(n log n) expected, O(n) when all elements equal
  Used by Java's dual-pivot QuickSort for many-duplicate cases.

----------------------------------------------------------------
JAVA'S DUAL-PIVOT QUICKSORT
----------------------------------------------------------------
Java 7+ Arrays.sort(int[]) uses Dual-Pivot QuickSort (Yaroslavskiy):
  - Two pivots: pivot1 <= pivot2
  - Partitions into 3 parts: <p1, p1<=x<=p2, >p2
  - ~10% fewer comparisons than single-pivot QuickSort
  - Better cache performance than 3-way partition
  - O(n log n) average, NOT stable (hence not used for objects)

----------------------------------------------------------------
WHY QUICKSORT IS PREFERRED IN PRACTICE
----------------------------------------------------------------
  1. Cache friendly: sequential memory access patterns during partition
  2. In-place: no extra memory allocation
  3. Small constant factor: fewer comparisons/operations vs merge sort
  4. Randomized: O(n^2) worst case is astronomically unlikely
  5. Works best when: random data, no duplicates, not pre-sorted

  When QuickSort struggles:
    Many duplicates -> use 3-way partition
    Already sorted -> randomize pivot or use insertion sort fallback
    Small arrays -> switch to insertion sort (< 10 elements)

----------------------------------------------------------------
INTERVIEW QUESTIONS
----------------------------------------------------------------

Q: What is the worst case of QuickSort and how is it avoided?
A: O(n^2) occurs when the pivot is always the smallest or largest
   element -- this creates partitions of size 0 and n-1, leading
   to n levels of recursion each doing O(n) work. Common trigger:
   sorted or reverse-sorted input with first/last element pivot.
   Solutions:
   1. Random pivot: makes O(n^2) exponentially unlikely
   2. Median of three: pick pivot as median of first, mid, last
   3. Introsort: switch to Heap Sort if recursion depth exceeds
      2*log(n) (used in C++ STL std::sort)

Q: Is QuickSort stable? How would you make it stable?
A: No, standard QuickSort is not stable -- the partition step can
   move equal elements past each other. To make it stable, you'd
   need extra space (O(n)) to maintain relative order during
   partitioning, essentially making it merge-sort-like.
   In practice, when stability is needed, use Merge Sort or TimSort.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. Java's Arrays.sort for primitives uses dual-pivot QuickSort,
     NOT stable -- know this distinction
  2. For many duplicates: always mention 3-way partition
  3. Hoare partition: returns the partition index j, NOT the pivot
     position -- a common misunderstanding
  4. Stack depth: O(log n) average with random pivot;
     can be made O(log n) worst case by always recursing on smaller side
  5. Introsort = QuickSort + HeapSort fallback: best of both worlds
