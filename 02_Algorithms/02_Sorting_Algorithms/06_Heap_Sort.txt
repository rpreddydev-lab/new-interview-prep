================================================================
  HEAP SORT
================================================================

----------------------------------------------------------------
HOW IT WORKS
----------------------------------------------------------------
  1. BUILD MAX-HEAP from array: O(n)
     (Start from last internal node, heapify down to root)
  2. EXTRACT MAX repeatedly: swap root with last, heapify down: O(n log n)

  Result: array sorted in ascending order.

  void heapSort(int[] arr) {
    int n = arr.length;
    // Build max-heap (bottom-up, O(n))
    for (int i = n/2 - 1; i >= 0; i--)
      heapifyDown(arr, n, i);
    // Extract elements one by one
    for (int i = n - 1; i > 0; i--) {
      int tmp = arr[0]; arr[0] = arr[i]; arr[i] = tmp;  // move max to end
      heapifyDown(arr, i, 0);  // heapify reduced heap
    }
  }

  void heapifyDown(int[] arr, int n, int i) {
    int largest = i, left = 2*i+1, right = 2*i+2;
    if (left < n && arr[left] > arr[largest])   largest = left;
    if (right < n && arr[right] > arr[largest]) largest = right;
    if (largest != i) {
      int tmp = arr[i]; arr[i] = arr[largest]; arr[largest] = tmp;
      heapifyDown(arr, n, largest);
    }
  }

  Time:  O(n log n) all cases (best/avg/worst guaranteed)
  Space: O(1) in-place (O(log n) recursion stack)
  In-place: Yes   Stable: No

----------------------------------------------------------------
WHY BUILD-HEAP IS O(n)
----------------------------------------------------------------
  Heapify down at level k takes O(k) time.
  Number of nodes at level k from bottom: n / 2^k
  Total: sum_{k=1}^{log n} (n/2^k * k) = n * sum_{k=1}^inf k/2^k = 2n = O(n)

  This is a key insight: O(n) build vs O(n log n) if you inserted n times.

----------------------------------------------------------------
HEAP SORT vs QUICK SORT vs MERGE SORT
----------------------------------------------------------------
  Feature          Heap Sort     Quick Sort    Merge Sort
  -------------------------------------------------------
  Best case        O(n log n)    O(n log n)    O(n log n)
  Average case     O(n log n)    O(n log n)    O(n log n)
  Worst case       O(n log n)    O(n^2)        O(n log n)
  Space            O(1)          O(log n)      O(n)
  Stable           No            No            Yes
  Cache friendly   Poor          Good          OK
  Practical speed  Slowest       Fastest       Middle

  Heap Sort: guaranteed O(n log n) and O(1) space -- optimal on paper.
  BUT: poor cache performance (heap access pattern is scattered across memory)
  causes many cache misses. QuickSort is 2-3x faster in practice.

  Why Java doesn't use Heap Sort:
  1. Cache unfriendly -> slower despite O(n log n) guarantee
  2. Not stable
  3. Java uses Introsort (dual-pivot QS + insertion) for primitives
     and TimSort for objects -- both outperform Heap Sort

----------------------------------------------------------------
INTERVIEW QUESTIONS
----------------------------------------------------------------

Q: Why is build-heap O(n) and not O(n log n)?
A: Most nodes in a heap are at the bottom levels and require
   very little heapify work. Only the root requires O(log n)
   work. The total work is: sum of (nodes at level k) * k,
   which telescopes to O(n). This is the key insight. If you
   INSERT n elements one by one, each insertion is O(log n)
   and total is O(n log n). But bottom-up build-heap leverages
   the shallow positions of most nodes.

Q: When would you choose Heap Sort over other O(n log n) sorts?
A: When you need O(n log n) worst case AND O(1) extra space AND
   instability is acceptable. This combination is rare in
   practice. Merge Sort gives O(n log n) worst case but uses O(n)
   space. QuickSort is faster but O(n^2) worst case (without
   randomization). In systems where memory is extremely
   constrained and worst-case guarantees matter (embedded), Heap
   Sort is the choice. In most other cases, TimSort or
   randomized QuickSort is preferred.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. Build-heap is O(n), not O(n log n) -- explain WHY
  2. Heap Sort is NOT used in Java despite being optimal in theory
     due to poor cache performance
  3. Array indexing: parent = (i-1)/2, left = 2i+1, right = 2i+2
  4. Heap Sort is unstable: swapping root with last element can
     change relative order of equal elements
  5. Good for: finding k largest/smallest elements (partial sort)
     Stop after k extractions: O(n + k log n)
