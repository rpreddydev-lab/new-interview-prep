  EXPONENTIAL SEARCH
================================================================

----------------------------------------------------------------
WHAT IS EXPONENTIAL SEARCH?
----------------------------------------------------------------
Exponential Search finds the range where the target lies by
doubling the index (1, 2, 4, 8, ...), then applies binary
search within that range.

  int exponentialSearch(int[] arr, int target) {
    int n = arr.length;
    if (arr[0] == target) return 0;
    int i = 1;
    while (i < n && arr[i] <= target) i *= 2;  // double until overshoot
    // Binary search in [i/2, min(i, n-1)]
    return binarySearch(arr, target, i / 2, Math.min(i, n - 1));
  }

  int binarySearch(int[] arr, int target, int left, int right) {
    while (left <= right) {
      int mid = left + (right - left) / 2;
      if (arr[mid] == target) return mid;
      else if (arr[mid] < target) left = mid + 1;
      else right = mid - 1;
    }
    return -1;
  }

  Time:  O(log i) where i = position of target
         O(log n) worst case
  Space: O(1) iterative

----------------------------------------------------------------
WHEN EXPONENTIAL SEARCH BEATS BINARY SEARCH
----------------------------------------------------------------
  Binary search: O(log n) -- always searches entire array range
  Exponential:   O(log i) -- finds range first, then binary searches

  Exponential is BETTER when:
  - Array is UNBOUNDED (size unknown or infinite stream)
  - Target is near the BEGINNING of the array (i << n)

  For unbounded sorted arrays:
    Cannot compute n, so can't set right = n-1 for binary search.
    Exponential doubling finds the upper bound: O(log i)
    Then binary search in [i/2, i]: O(log i)
    Total: O(log i) -- optimal for this case.

  Example: search in an infinite sorted stream -- only exponential
  search is directly applicable.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. Exponential search is specifically designed for UNBOUNDED
     sorted arrays -- mention this as its primary use case
  2. For bounded sorted arrays of known size: binary search is simpler
  3. Time is O(log i) where i is the target's actual position,
     not O(log n) -- this is its advantage when target is early
  4. Rare in standard interviews; know the concept
