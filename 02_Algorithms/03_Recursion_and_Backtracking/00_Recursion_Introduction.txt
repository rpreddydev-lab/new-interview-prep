  RECURSION -- INTRODUCTION
================================================================

----------------------------------------------------------------
WHAT IS RECURSION?
----------------------------------------------------------------
A function that calls itself to solve a smaller version of the
same problem. Every recursive solution requires:
  1. BASE CASE -- stops the recursion (prevents infinite loop)
  2. RECURSIVE CASE -- reduces the problem towards the base case
  3. PROGRESS -- each call must move closer to the base case

  int factorial(int n) {
    if (n <= 1) return 1;              // base case
    return n * factorial(n - 1);       // recursive case: n reduced by 1
  }

  factorial(5) --> 5 * factorial(4)
               --> 5 * 4 * factorial(3)
               --> 5 * 4 * 3 * factorial(2)
               --> 5 * 4 * 3 * 2 * factorial(1)
               --> 5 * 4 * 3 * 2 * 1 = 120

----------------------------------------------------------------
CALL STACK MECHANICS
----------------------------------------------------------------
Each recursive call creates a new STACK FRAME containing:
  - Local variables
  - Parameters
  - Return address

  factorial(5) stack at deepest point:
  [factorial(1)] <- top of stack
  [factorial(2)]
  [factorial(3)]
  [factorial(4)]
  [factorial(5)] <- bottom
  [main]

  Stack unwinds from top to bottom, each frame computes its result
  and passes it to the caller.

  Java default thread stack size: ~512KB - 1MB
  Typical usable depth: ~10,000 - 15,000 frames
  Stack overflow: java.lang.StackOverflowError at ~5K-10K depth

----------------------------------------------------------------
RECURSION VARIANTS
----------------------------------------------------------------
  Linear recursion:  one recursive call per invocation
  Binary recursion:  two recursive calls (e.g., merge sort, Fibonacci)
  Mutual recursion:  A calls B, B calls A (e.g., even/odd)
  Tail recursion:    recursive call is the LAST operation (no pending work)
  Tree recursion:    branches > 2 (e.g., combination enumeration)

----------------------------------------------------------------
THINKING RECURSIVELY -- TEMPLATE
----------------------------------------------------------------
  1. Identify the simplest base case(s)
  2. Assume the function works correctly for smaller input (inductive step)
  3. Use that assumption to build the answer for the current input

  Example: sum of array
    sumArray(arr, n) = arr[n-1] + sumArray(arr, n-1)  (n > 0)
    sumArray(arr, 0) = 0                               (base case)

  This "trust the recursion" mindset is key for backtracking too.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. Always define base case FIRST -- prevents infinite recursion
  2. Trust that the recursive call returns the correct result
     for smaller input; build on it
  3. Trace small examples by hand (n=0, n=1, n=2) to verify
  4. Stack overflow: O(n) call depth -> potentially dangerous for n=10^5
     Consider iterative version with explicit stack
  5. Recursion = DFS by nature; many tree/graph problems are naturally
     recursive
