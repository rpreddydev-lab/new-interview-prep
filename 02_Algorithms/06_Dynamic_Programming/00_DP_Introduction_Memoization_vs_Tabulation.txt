----------------------------------------------------------------
WHAT IS DP?
----------------------------------------------------------------
DP solves optimization problems by breaking them into overlapping
subproblems and storing results to avoid recomputation.

  Two required properties:
  1. OPTIMAL SUBSTRUCTURE: optimal solution = combination of
     optimal solutions to subproblems
  2. OVERLAPPING SUBPROBLEMS: same subproblems appear repeatedly
     (unlike D&C where subproblems are independent)

  DP = smart recursion + memoization
  Or equivalently: bottom-up table filling

----------------------------------------------------------------
TOP-DOWN: MEMOIZATION
----------------------------------------------------------------
Write the recursive solution, add a cache (memo array or HashMap).

  int fib(int n, int[] memo) {
    if (n <= 1) return n;
    if (memo[n] != -1) return memo[n];
    return memo[n] = fib(n-1, memo) + fib(n-2, memo);
  }

  Pros:
    Natural to write (follow the recursion)
    Only computes needed subproblems (lazy evaluation)
    Easier to handle irregular state spaces
  Cons:
    Recursion overhead (function calls, call stack)
    Risk of StackOverflowError for large n
    Less cache-friendly than bottom-up

----------------------------------------------------------------
BOTTOM-UP: TABULATION
----------------------------------------------------------------
Fill a table iteratively from smallest to largest subproblem.

  int fib(int n) {
    if (n <= 1) return n;
    int[] dp = new int[n + 1];
    dp[0] = 0; dp[1] = 1;
    for (int i = 2; i <= n; i++)
      dp[i] = dp[i-1] + dp[i-2];
    return dp[n];
  }

  // Space optimized:
  int fib(int n) {
    if (n <= 1) return n;
    int prev2 = 0, prev1 = 1;
    for (int i = 2; i <= n; i++) { int cur = prev1 + prev2; prev2 = prev1; prev1 = cur; }
    return prev1;
  }

  Pros:
    No recursion overhead
    Cache-friendly (sequential access)
    Easier to optimize space
  Cons:
    Must compute ALL subproblems (even unused ones)
    Less intuitive for some problems
    Need to determine correct fill order

----------------------------------------------------------------
COMPARISON TABLE
----------------------------------------------------------------
  Feature                Memoization (TD)        Tabulation (BU)
  ---------------------------------------------------------------
  Intuition              Follows recursion       Requires bottom-up order
  Computation            Lazy (only needed)      Eager (all subproblems)
  Stack usage            O(depth) recursion      O(1) stack
  Space optimization     Harder                  Easy (sliding array)
  Debugging              Easier to trace         Harder to trace
  LeetCode preference    Either works            Preferred for interviews

----------------------------------------------------------------
DP PROBLEM IDENTIFICATION CHECKLIST
----------------------------------------------------------------
  1. Asks for MAXIMUM / MINIMUM / COUNT / EXISTS?
  2. Can you break it into smaller versions of the same problem?
  3. Do subproblems overlap (same state reached multiple ways)?
  4. Optimal choice at each step depends on future (not just current)?

  If YES to all -> likely DP.

  DEFINE STATE: what information fully describes a subproblem?
    1D: dp[i] -- first i items, up to index i, etc.
    2D: dp[i][j] -- using items 1..i with capacity j, substring i..j, etc.
    Bitmask DP: dp[mask][i] -- visited set + current position

  DEFINE TRANSITION: how dp[i] relates to previous states

  IDENTIFY BASE CASES: smallest subproblem values

  ANSWER: dp[n] or dp[m][n] or max over dp[*]

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. Start by defining the DP state clearly before coding
  2. For 1D DP: try to reduce space to O(1) or O(n) at end
  3. For 2D DP: reduce space by keeping only 1-2 rows when
     dp[i] only depends on dp[i-1]
  4. If memoization leads to stack overflow: convert to tabulation
  5. Common interview mistake: wrong base case or wrong fill order
     --> Always trace through a small example before coding
