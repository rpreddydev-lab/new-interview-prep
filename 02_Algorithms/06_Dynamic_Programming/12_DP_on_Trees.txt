CORE CONCEPT
----------------------------------------------------------------
Tree DP: compute answers for tree problems using post-order DFS.
Each node's value depends on children's values.
Return relevant information (tuple/array) from each subtree.

  Template:
    int[] dfs(TreeNode node) {
      if (node == null) return base_case;
      int[] left = dfs(node.left);
      int[] right = dfs(node.right);
      // combine: current node's result based on children
      return new int[]{ result_including_node, result_excluding_node };
    }

----------------------------------------------------------------
HOUSE ROBBER III (LC 337) -- Classic Tree DP
----------------------------------------------------------------
Rob houses in a binary tree. Can't rob directly connected nodes.

  int[] rob(TreeNode root) {
    if (root == null) return new int[]{0, 0};
    int[] left = rob(root.left);
    int[] right = rob(root.right);
    // [0] = max if we DO rob this node
    // [1] = max if we DON'T rob this node
    int robThis = root.val + left[1] + right[1];
    int skipThis = Math.max(left[0], left[1]) + Math.max(right[0], right[1]);
    return new int[]{robThis, skipThis};
  }

  int houseRobber3(TreeNode root) {
    int[] res = rob(root);
    return Math.max(res[0], res[1]);
  }

  Time: O(n)  Space: O(h) where h = height

BINARY TREE CAMERAS (LC 968) -- Greedy + Tree DP
----------------------------------------------------------------
Min cameras to monitor all nodes. Camera monitors itself,
parent, and children.

  States: 0 = uncovered, 1 = has camera, 2 = covered (no camera)
  DFS returns state of each node.
  Place camera at PARENT when child is uncovered (greedy).

  int cameras = 0;
  int minCameraCover(TreeNode root) {
    return dfs(root) == 0 ? ++cameras : 0;  // root uncovered: add camera
  }
  int dfs(TreeNode node) {
    if (node == null) return 2;   // null is considered covered
    int left = dfs(node.left), right = dfs(node.right);
    if (left == 0 || right == 0) { cameras++; return 1; }  // child uncovered: place camera here
    if (left == 1 || right == 1) return 2;    // child has camera: covered
    return 0;   // both children covered but no camera: this node uncovered
  }

DIAMETER OF BINARY TREE (LC 543)
----------------------------------------------------------------
Longest path between any two nodes (may not pass through root).

  int maxDiameter = 0;
  int diameterOfBinaryTree(TreeNode root) {
    height(root);
    return maxDiameter;
  }
  int height(TreeNode node) {
    if (node == null) return 0;
    int left = height(node.left), right = height(node.right);
    maxDiameter = Math.max(maxDiameter, left + right);  // path through this node
    return 1 + Math.max(left, right);  // height contribution to parent
  }

  Key pattern: return one value (for parent), update global with another.

----------------------------------------------------------------
MAXIMUM PATH SUM (LC 124)
----------------------------------------------------------------
Path sum through any nodes. Path can start/end anywhere.

  int maxPath = Integer.MIN_VALUE;
  int maxPathSum(TreeNode root) { maxGain(root); return maxPath; }
  int maxGain(TreeNode node) {
    if (node == null) return 0;
    int left = Math.max(0, maxGain(node.left));   // discard negatives
    int right = Math.max(0, maxGain(node.right));
    maxPath = Math.max(maxPath, left + right + node.val);  // update global
    return node.val + Math.max(left, right);               // return best single path
  }

  The `Math.max(0, gain)` discards negative subtrees (don't extend path there).

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. Return array/pair from DFS for "include node vs exclude node" problems
  2. Global variable pattern: update global (diameter, maxPath) in DFS;
     return something different (height, maxGain) to parent
  3. Discard negatives with max(0, ...) when path value can be negative
  4. Tree DP is always post-order: children first, then parent
  5. For cameras/coloring: think of states and transitions carefully;
     draw the state machine before coding
