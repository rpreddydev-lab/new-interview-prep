================================================================
  UNBOUNDED KNAPSACK
================================================================

----------------------------------------------------------------
PROBLEM
----------------------------------------------------------------
Knapsack capacity W. Items with weight[i] and value[i].
Each item can be used UNLIMITED times.
Maximize total value.

----------------------------------------------------------------
DP FORMULATION
----------------------------------------------------------------
  State: dp[w] = max value achievable with capacity w
  Transition: for each item i, for each capacity w:
    dp[w] = max(dp[w], dp[w - weight[i]] + value[i])
  Iterate w FORWARD (opposite of 0-1).

  int unboundedKnapsack(int W, int[] weight, int[] value) {
    int[] dp = new int[W + 1];
    for (int i = 0; i < weight.length; i++)
      for (int w = weight[i]; w <= W; w++)  // FORWARD: allow reuse!
        dp[w] = Math.max(dp[w], dp[w - weight[i]] + value[i]);
    return dp[W];
  }

  Why forward? When computing dp[w], dp[w-weight[i]] already
  includes item i's contribution -> item can be used multiple times.

  Time: O(nW)  Space: O(W)

----------------------------------------------------------------
COIN CHANGE (LC 322) -- min coins, unlimited use
----------------------------------------------------------------
  dp[0] = 0; dp[i] = min coins to make amount i
  dp[i] = min over all coins c where c <= i: dp[i-c] + 1

  int coinChange(int[] coins, int amount) {
    int[] dp = new int[amount + 1];
    Arrays.fill(dp, amount + 1);   // "infinity"
    dp[0] = 0;
    for (int i = 1; i <= amount; i++)
      for (int coin : coins)
        if (coin <= i) dp[i] = Math.min(dp[i], dp[i - coin] + 1);
    return dp[amount] > amount ? -1 : dp[amount];
  }

  Time: O(n * amount)  Space: O(amount)

  Note: loop order here is AMOUNT outer, COIN inner.
  Alternative: COIN outer, AMOUNT inner (both correct for min coins).

----------------------------------------------------------------
COIN CHANGE II (LC 518) -- count combinations (order doesn't matter)
----------------------------------------------------------------
  dp[0]=1; dp[i] = count of ways to make amount i
  Key: to avoid counting same combination with different orders:
  iterate COINS in outer loop, AMOUNTS in inner loop.

  int change(int amount, int[] coins) {
    int[] dp = new int[amount + 1];
    dp[0] = 1;
    for (int coin : coins)              // outer: coins (fix order)
      for (int i = coin; i <= amount; i++)  // inner: amounts (forward)
        dp[i] += dp[i - coin];
    return dp[amount];
  }

  vs Combination Sum IV (LC 377) -- count permutations (order MATTERS):
    dp[0]=1; for amounts outer, coins inner -> each ordering counted
    int combinationSum4(int[] nums, int target) {
      int[] dp = new int[target + 1];
      dp[0] = 1;
      for (int i = 1; i <= target; i++)   // outer: amounts
        for (int num : nums)              // inner: items
          if (i >= num) dp[i] += dp[i - num];
      return dp[target];
    }

  CRITICAL: coins outer = combinations (order ignored)
            amounts outer = permutations (each ordering counted)

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. Unbounded vs 0-1: only difference is iteration direction (W)
     0-1: W in reverse; Unbounded: W forward
  2. Coin Change (322): min coins; Coin Change II (518): count ways
  3. LC 518 vs LC 377: same formulas, different loop order!
     Combinations (order ignored) = coin outer
     Permutations (order matters) = amount outer
  4. Initialize dp[0]=1 (base) and dp[1..n] = infinity or 0
     depending on min or count problem
  5. Coin Change has no solution: return -1 when dp[amount] > amount
