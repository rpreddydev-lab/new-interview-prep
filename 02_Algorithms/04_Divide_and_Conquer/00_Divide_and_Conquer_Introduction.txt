================================================================
  DIVIDE AND CONQUER -- INTRODUCTION
================================================================

----------------------------------------------------------------
CORE IDEA
----------------------------------------------------------------
Solve a problem by recursively breaking it into SMALLER subproblems,
solving each independently, then COMBINING the results.

  Three steps:
    1. DIVIDE:   Split problem into smaller subproblems
    2. CONQUER:  Solve subproblems recursively (base case: solve directly)
    3. COMBINE:  Merge subproblem solutions into full solution

  Requirement: subproblems must be INDEPENDENT (no overlap).
  If subproblems OVERLAP: use Dynamic Programming instead.

----------------------------------------------------------------
CLASSIC EXAMPLES
----------------------------------------------------------------
  Algorithm           Divide         Conquer           Combine
  ---------------------------------------------------------------
  Merge Sort          Split halves   Sort each half    Merge O(n)
  Quick Sort          Partition      Sort two parts    Trivial O(1)
  Binary Search       Find midpoint  Search one half   Trivial O(1)
  Strassen Matrix     7 submatrices  Multiply 7x7      Add/subtract
  Closest Pair        Split on x     Closest in each   Strip merge
  Fast Power          n/2 subproblem Compute x^(n/2)   Square O(1)
  Karatsuba Multiply  3 sub-products Multiply smaller  Combine O(n)

----------------------------------------------------------------
WHEN TO USE DIVIDE AND CONQUER
----------------------------------------------------------------
  --> Problem can be split into independent subproblems of same type
  --> Combining is efficient (O(n) or O(n log n))
  --> Base case is trivial
  --> Subproblems are INDEPENDENT (otherwise: DP)

  Sign that DP is better: subproblems overlap (same subproblem
  computed multiple times) -- memoize instead of recompute.

----------------------------------------------------------------
COMPLEXITY ANALYSIS -- MASTER THEOREM
----------------------------------------------------------------
  T(n) = a * T(n/b) + f(n)
    a = number of subproblems
    b = factor by which input shrinks
    f(n) = cost of divide + combine step

  log_b(a) = critical exponent
    Case 1: f(n) = O(n^(log_b(a) - epsilon))  -> T(n) = O(n^log_b(a))
    Case 2: f(n) = O(n^log_b(a))              -> T(n) = O(n^log_b(a) * log n)
    Case 3: f(n) = Omega(n^(log_b(a) + epsilon)) and af(n/b) <= cf(n) -> T(n) = O(f(n))

  Examples:
    Merge Sort:    T(n) = 2T(n/2) + O(n) -> Case 2 -> O(n log n)
    Binary Search: T(n) = T(n/2) + O(1)  -> Case 2 -> O(log n)
    Strassen:      T(n) = 7T(n/2) + O(n^2) -> log_2(7) ~ 2.81 -> O(n^2.81)
    Fast Power:    T(n) = T(n/2) + O(1)  -> Case 2 -> O(log n)

----------------------------------------------------------------
DIVIDE AND CONQUER vs DYNAMIC PROGRAMMING
----------------------------------------------------------------
  Feature                D&C                    DP
  ----------------------------------------------------------
  Subproblems            Independent             Overlapping
  Result reuse           No (recompute)          Yes (memoize/tabulate)
  Approach               Top-down recursive      Bottom-up or top-down+memo
  Space                  O(log n) stack           O(n) or O(n^2) table
  Examples               Merge Sort, Binary Search  Fibonacci, Knapsack

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. State the three steps (Divide/Conquer/Combine) for any D&C problem
  2. Independent subproblems = D&C; overlapping = DP
  3. Recurrence relation and Master Theorem: know by heart
  4. The combining step is often where the trick is:
     Merge Sort: O(n) merge; Closest Pair: O(n) strip merge
  5. D&C algorithms often have natural parallel implementations
     (each half can be computed independently on separate cores)
