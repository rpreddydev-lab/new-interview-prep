================================================================
  QUICKSELECT -- KTH LARGEST/SMALLEST (LC 215)
================================================================

----------------------------------------------------------------
PROBLEM
----------------------------------------------------------------
Find the kth largest element in an unsorted array in O(n) average.

----------------------------------------------------------------
QUICKSELECT ALGORITHM
----------------------------------------------------------------
Similar to QuickSort's partition step but only recurse on ONE side.

  int findKthLargest(int[] nums, int k) {
    // kth largest = (n-k)th smallest (0-indexed)
    return quickSelect(nums, 0, nums.length - 1, nums.length - k);
  }

  int quickSelect(int[] nums, int left, int right, int k) {
    if (left == right) return nums[left];
    // Random pivot to avoid O(n^2) worst case
    int randIdx = left + (int)(Math.random() * (right - left + 1));
    swap(nums, randIdx, right);
    int pivotIdx = partition(nums, left, right);  // Lomuto partition
    if (pivotIdx == k)      return nums[pivotIdx];
    else if (pivotIdx < k)  return quickSelect(nums, pivotIdx + 1, right, k);
    else                    return quickSelect(nums, left, pivotIdx - 1, k);
  }

  int partition(int[] nums, int left, int right) {
    int pivot = nums[right], i = left - 1;
    for (int j = left; j < right; j++)
      if (nums[j] <= pivot) swap(nums, ++i, j);
    swap(nums, i + 1, right);
    return i + 1;
  }

  Time: O(n) average, O(n^2) worst (mitigated by random pivot)
  Space: O(log n) average recursion depth

  Why O(n): n + n/2 + n/4 + ... = 2n = O(n)
  Each level the problem halves on average.

----------------------------------------------------------------
ALTERNATIVE: MIN-HEAP APPROACH
----------------------------------------------------------------
  Maintain a min-heap of size k.
  For each element: add to heap, pop if size > k.
  Answer = heap.peek().

  Time: O(n log k)  Space: O(k)
  When k << n: this is better than QuickSelect (guaranteed no worst case)
  When k = n/2: QuickSelect O(n) avg beats O(n log n) heap approach

  PriorityQueue<Integer> heap = new PriorityQueue<>();
  for (int num : nums) {
    heap.offer(num);
    if (heap.size() > k) heap.poll();
  }
  return heap.peek();

----------------------------------------------------------------
MEDIAN OF MEDIANS (GUARANTEED O(n))
----------------------------------------------------------------
Worst-case O(n) for kth element -- used in theoretical contexts.
  1. Split into groups of 5; find median of each group
  2. Recursively find median of medians (pivot)
  3. Partition using this pivot
  4. Recurse on appropriate side

  Guarantees pivot eliminates at least n/4 elements per step.
  T(n) = T(3n/4) + T(n/5) + O(n) -> O(n)
  In practice: large constant, QuickSelect with random pivot is preferred.

----------------------------------------------------------------
COMPARISON TABLE
----------------------------------------------------------------
  Method              Time Avg    Time Worst   Space   Notes
  ----------------------------------------------------------------
  Sort + index        O(n log n)  O(n log n)   O(1)    Simple, not optimal
  Min-Heap size k     O(n log k)  O(n log k)   O(k)    Good for streaming
  QuickSelect         O(n)        O(n^2)       O(log n) Best avg, not guaranteed
  Median of Medians   O(n)        O(n)         O(log n) Guaranteed but slow const

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. LC 215 is one of the most common interview questions
  2. QuickSelect: O(n) avg but O(n^2) worst -- always randomize pivot
  3. Min-heap size k: O(n log k) -- mention as alternative when
     k is small or when guaranteed time is needed
  4. Partial sort: QuickSelect modifies the array; if preserving input
     is required, copy first
  5. Median of Medians: mention as the theoretical O(n) guaranteed
     approach but note it's not used in practice due to large constants
