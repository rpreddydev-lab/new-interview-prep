================================================================
  GREEDY vs DYNAMIC PROGRAMMING
================================================================

----------------------------------------------------------------
KEY DIFFERENCES
----------------------------------------------------------------
  Property               Greedy                   DP
  ----------------------------------------------------------
  Decision scope         Current only             All future options
  Reconsider choices     Never                    No (but considers all)
  Subproblem overlap     Not needed (independent) Required (overlapping)
  Optimal substructure   Required                 Required
  Time complexity        O(n) to O(n log n)       O(n^2) to O(n^3) typical
  Implementation         Usually simpler          More complex
  When optimal           Greedy choice property   Always (if correct DP)

----------------------------------------------------------------
SAME PROBLEM, DIFFERENT APPROACHES
----------------------------------------------------------------
  Coin Change:
    Greedy: pick largest coin <= remaining. ONLY works for
    canonical coin systems (US: 1,5,10,25).
    Fails for arbitrary denominations (e.g., 1,3,4 -> target 6).
    DP: dp[i] = min coins to make i. O(n*amount).

  Shortest Path:
    Greedy (Dijkstra): works for non-negative weights.
    DP (Bellman-Ford): handles negative weights, detects negative cycles.

  Knapsack:
    Fractional: greedy by value/weight ratio -> optimal
    0-1: greedy fails -> DP required

  Interval Scheduling:
    Max non-overlapping intervals: greedy (sort by end) -> O(n log n)
    Weighted interval scheduling (max profit): DP + binary search -> O(n log n)

----------------------------------------------------------------
DECISION FRAMEWORK
----------------------------------------------------------------
  1. Does a locally optimal choice always lead to a globally optimal solution?
     Yes -> Try greedy, prove exchange argument
     No  -> Try DP

  2. Do subproblems overlap (same subproblem computed multiple times)?
     Yes -> DP with memoization
     No  -> Divide and conquer (or greedy)

  3. Can you define an ordering/greedy criterion?
     Sorting by end time, ratio, frequency, etc.?
     Yes -> Strong greedy candidate

  4. Multiple constraints simultaneously?
     Usually needs DP

JUMP GAME (LC 55) -- Classic Greedy
----------------------------------------------------------------
  boolean canJump(int[] nums) {
    int maxReach = 0;
    for (int i = 0; i < nums.length; i++) {
      if (i > maxReach) return false;   // can't reach position i
      maxReach = Math.max(maxReach, i + nums[i]);
    }
    return true;
  }

JUMP GAME II (LC 45) -- Minimum jumps
  int jump(int[] nums) {
    int jumps = 0, curEnd = 0, farthest = 0;
    for (int i = 0; i < nums.length - 1; i++) {
      farthest = Math.max(farthest, i + nums[i]);
      if (i == curEnd) {  // must jump from this boundary
        jumps++;
        curEnd = farthest;
      }
    }
    return jumps;
  }

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. Greedy requires proof; DP requires recurrence definition
  2. When uncertain: implement DP first (always correct if formulation
     is right); then optimize to greedy if provable
  3. Many interval problems: greedy; many optimization with constraints: DP
  4. Jump Game is the canonical greedy proof of concept:
     locally track max reachable position
  5. Telling sign of DP: "minimum/maximum" + overlapping subproblems
     + multi-step decisions that affect future options
