================================================================
  IN-PLACE vs OUT-OF-PLACE ALGORITHMS
================================================================

----------------------------------------------------------------
DEFINITIONS
----------------------------------------------------------------
  In-Place:  the algorithm modifies the input data structure
             directly, using O(1) extra space (or O(log n) for
             recursion stack -- this is still considered in-place).

  Out-of-Place: creates a new data structure for the result,
                using O(n) or more extra space.

  Strict in-place: O(1) extra space (no recursion, no auxiliary array)
  Practical in-place: O(log n) extra (recursive algorithms allowed)

----------------------------------------------------------------
EXAMPLES
----------------------------------------------------------------
  Algorithm           In-Place?   Extra Space
  -----------------------------------------------
  Bubble Sort         Yes         O(1)
  Selection Sort      Yes         O(1)
  Insertion Sort      Yes         O(1)
  Quick Sort          Yes         O(log n) stack
  Heap Sort           Yes         O(1)
  Merge Sort          No          O(n) auxiliary array
  Counting Sort       No          O(k) count array
  Radix Sort          No          O(n+k) buckets
  Reverse Array       Yes         O(1) swap in-place
  Two Pointers        Yes         O(1)
  Extra HashMap       No          O(n)

----------------------------------------------------------------
IN-PLACE TECHNIQUES
----------------------------------------------------------------
  1. SWAP: exchange elements using temp or XOR
     int tmp = a[i]; a[i] = a[j]; a[j] = tmp;

  2. TWO POINTERS: partition array in-place
     Dutch National Flag: O(n) time, O(1) space
     sort 0s, 1s, 2s in one pass with low/mid/high pointers

  3. CYCLIC SORT: for problems where elements are in range [1, n]
     Place each element at index element-1.
     Then scan for mismatches.
     Find all duplicates / missing numbers in O(n) time, O(1) space.

     for (int i = 0; i < n; ) {
       int correct = nums[i] - 1;
       if (nums[i] != nums[correct]) swap(nums, i, correct);
       else i++;
     }

  4. BIT MANIPULATION: mark visited using sign
     For duplicate detection in [1..n] arrays:
     nums[Math.abs(nums[i]) - 1] *= -1  -- negate as visited marker

  5. IN-PLACE REVERSAL of linked list:
     ListNode prev = null, curr = head;
     while (curr != null) {
       ListNode next = curr.next;
       curr.next = prev;
       prev = curr;
       curr = next;
     }
     return prev;

----------------------------------------------------------------
WHEN EACH IS PREFERRED
----------------------------------------------------------------
  Prefer IN-PLACE:
    - Memory-constrained environments (embedded, mobile)
    - When the problem says "O(1) extra space"
    - Modifying large datasets in-place avoids GC pressure in Java

  Prefer OUT-OF-PLACE:
    - Immutability required (functional programming)
    - Parallel processing (avoid race conditions)
    - When original data must be preserved
    - When algorithm logic is cleaner with a new array

----------------------------------------------------------------
INTERVIEW QUESTIONS
----------------------------------------------------------------

Q: Is QuickSort truly in-place?
A: Practically yes -- it sorts in-place using O(1) extra space
   for swaps. However, it uses O(log n) stack space for recursive
   calls (O(n) worst case for degenerate pivot choice). The sort
   itself doesn't allocate extra arrays, so it's considered
   in-place in the standard definition.

Q: How does cyclic sort work for finding duplicates?
A: Cyclic sort assumes elements are in range [1, n]. For each
   position i, if nums[i] != i+1, swap nums[i] with nums[nums[i]-1]
   (place each number at its correct index). After sorting,
   any index where nums[i] != i+1 has the answer. This is O(n)
   time O(1) space -- better than sorting or using a HashSet.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. O(1) space often implies in-place technique -- look for
     two pointers, cyclic sort, or sign-negation tricks
  2. Merge Sort O(n) space is often forgotten -- mention it
  3. "In-place" in practice usually allows O(log n) for recursion
  4. Cyclic sort pattern: problems with values in [1..n] range
     are often solvable in O(n)/O(1) with cyclic sort
  5. Sign negation trick: use negative sign as a visited marker
     (only works for positive integer arrays)
