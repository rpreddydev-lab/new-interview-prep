================================================================
  ITERATIVE vs RECURSIVE
================================================================

----------------------------------------------------------------
DEFINITIONS
----------------------------------------------------------------
  Iterative: uses loops (for, while) to repeat operations.
    State explicitly managed in variables.
    Execution stays within same stack frame.

  Recursive: function calls itself with smaller subproblems.
    State implicitly managed on the call stack.
    Each call has its own stack frame.

  Every recursive algorithm can be converted to iterative
  using an explicit stack (simulating the call stack).

----------------------------------------------------------------
COMPARISON TABLE
----------------------------------------------------------------
  Feature              Iterative             Recursive
  ---------------------------------------------------------------
  Space                O(1) typical          O(depth) call stack
  Speed                Faster (no func calls) Slower (overhead)
  Readability          Lower for complex      Higher for tree/graph
  Stack overflow risk  None                  Yes (deep recursion)
  Memoization          Manual map            Natural with DP
  Best for             Loops, linear algos   Trees, graphs, D&C

----------------------------------------------------------------
CALL STACK AND STACK OVERFLOW
----------------------------------------------------------------
  Each recursive call pushes a stack frame containing:
    - Local variables
    - Parameters
    - Return address

  Java default stack size: 512KB - 1MB (~10,000 frames typical)
  Deep recursion on n = 100,000 can cause StackOverflowError.

  Solutions:
    1. Convert to iterative (explicit stack)
    2. Increase JVM stack: java -Xss4m MyClass
    3. Use tail recursion (Java does NOT optimize tail calls!)
       -- Java JVM doesn't support TCO, unlike Scala/Kotlin

----------------------------------------------------------------
CONVERTING RECURSIVE DFS TO ITERATIVE
----------------------------------------------------------------
  Recursive preorder traversal:
    void preorder(Node root) {
      if (root == null) return;
      process(root.val);
      preorder(root.left);
      preorder(root.right);
    }

  Iterative preorder with explicit stack:
    void preorderIterative(Node root) {
      if (root == null) return;
      Stack<Node> stack = new Stack<>();
      stack.push(root);
      while (!stack.isEmpty()) {
        Node node = stack.pop();
        process(node.val);
        if (node.right != null) stack.push(node.right);  // push right FIRST
        if (node.left != null)  stack.push(node.left);   // left processed next
      }
    }

  Iterative inorder (trickier -- needs null check loop):
    void inorderIterative(Node root) {
      Stack<Node> stack = new Stack<>();
      Node curr = root;
      while (curr != null || !stack.isEmpty()) {
        while (curr != null) { stack.push(curr); curr = curr.left; }
        curr = stack.pop();
        process(curr.val);
        curr = curr.right;
      }
    }

----------------------------------------------------------------
TAIL RECURSION
----------------------------------------------------------------
A function is tail-recursive if the recursive call is the
LAST operation (result of recursive call returned directly,
no further computation after it).

  NOT tail recursive (multiply after recursion):
    int factorial(int n) {
      if (n <= 1) return 1;
      return n * factorial(n - 1);  // multiply happens AFTER return
    }

  Tail recursive (accumulator pattern):
    int factTail(int n, int acc) {
      if (n <= 1) return acc;
      return factTail(n - 1, n * acc);  // nothing after recursive call
    }
    int factorial(int n) { return factTail(n, 1); }

  NOTE: Java does NOT perform tail call optimization (TCO).
  The tail-recursive version still consumes O(n) stack space in Java.
  Use iteration for O(1) space in Java.

  Languages with TCO: Scala, Kotlin (@TailRec annotation), Haskell, Clojure.

----------------------------------------------------------------
WHEN TO PREFER EACH
----------------------------------------------------------------
  Prefer RECURSIVE:
    - Tree traversal (naturally recursive structure)
    - Graph DFS
    - Divide & Conquer (merge sort, quicksort)
    - Backtracking (subsets, permutations)
    - When depth is bounded and code clarity matters

  Prefer ITERATIVE:
    - Linear sequences (array processing)
    - When depth is unbounded (risk of StackOverflow)
    - Performance-critical code
    - When the problem is naturally iterative (sliding window)

----------------------------------------------------------------
INTERVIEW QUESTIONS
----------------------------------------------------------------

Q: Why doesn't Java support tail call optimization?
A: The JVM specification doesn't require TCO, and the Java
   language designers chose not to implement it. This is partly
   by design -- Java stack traces are deeply important for
   debugging, and TCO would collapse stack frames, making traces
   harder to read. Scala's @tailrec annotation achieves TCO
   by transforming tail-recursive code to a loop at compile time.

Q: How do you convert recursive DFS to iterative?
A: Use an explicit stack. Push the root. While the stack is not
   empty: pop a node, process it (or defer), push its children.
   The order of pushing children matters: for preorder, push
   right before left (so left is processed first). For inorder,
   keep a "current" pointer and push nodes while going left.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. In Java: recursive solutions can cause StackOverflowError
     for n > ~10,000 -- mention this and offer iterative alternative
  2. Recursive solutions are often cleaner -- start with
     recursion, then optimize to iterative if asked
  3. DFS on graphs MUST handle cycles (use visited set)
  4. Converting to iterative = simulating the call stack manually
  5. Space complexity of recursion = O(max call stack depth)
