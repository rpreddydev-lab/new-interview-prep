================================================================
  WHAT IS AN ALGORITHM?
================================================================

----------------------------------------------------------------
DEFINITION
----------------------------------------------------------------
An algorithm is a finite, unambiguous, step-by-step procedure
that takes an input, performs operations, and produces an output.

  5 Properties of a well-defined algorithm (Knuth):
    1. Finiteness      -- must terminate after finite steps
    2. Definiteness    -- each step is precisely defined
    3. Input           -- zero or more inputs
    4. Output          -- one or more outputs
    5. Effectiveness   -- each step is basic enough to be carried out

  Algorithm vs Program:
    Algorithm: abstract, language-independent, platform-independent
    Program:   concrete implementation of an algorithm in a language

----------------------------------------------------------------
WHY ALGORITHMS MATTER IN INTERVIEWS
----------------------------------------------------------------
  - Same problem can have solutions ranging from O(n!) to O(n log n)
  - Space-time trade-offs: use more memory to gain speed
  - Correct approach to the right problem = passing the interview
  - Companies measure: problem decomposition, code correctness,
    edge case handling, and complexity analysis

----------------------------------------------------------------
ALGORITHM CLASSIFICATION
----------------------------------------------------------------
  By STRATEGY:
    Brute Force         -- try all possibilities
    Greedy              -- make locally optimal choice at each step
    Divide & Conquer    -- split into subproblems, solve, combine
    Dynamic Programming -- memoize overlapping subproblems
    Backtracking        -- explore all paths, prune dead ends
    Randomized          -- use randomness for efficiency (QuickSort avg)

  By DATA STRUCTURE used:
    Array-based, Tree-based, Graph-based, Hash-based

  By TERMINATION:
    Deterministic  -- same input always produces same output
    Probabilistic  -- output or runtime may vary (randomized)

  By PURPOSE:
    Searching, Sorting, Graph traversal, Optimization, Compression

----------------------------------------------------------------
ALGORITHM CORRECTNESS
----------------------------------------------------------------
  Proof by loop invariant:
    1. Initialization: invariant holds before the first iteration
    2. Maintenance:    if true before iteration k, holds after k
    3. Termination:    when loop ends, invariant gives correctness proof

  Example: Insertion Sort invariant
    At start of each iteration: A[0..i-1] is sorted.
    Initialization: A[0..0] is trivially sorted.
    Maintenance: insert A[i] into correct position in sorted prefix.
    Termination: A[0..n-1] is sorted.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. State the algorithm approach BEFORE coding (greedy? DP? two pointers?)
  2. Always analyze time AND space complexity
  3. Mention trade-offs: "This is O(n) time but O(n) space;
     if space is a concern we could do O(1) space with O(n^2) time"
  4. Test with: empty input, single element, duplicates, negative numbers
  5. "Brute force first, then optimize" is a valid interview strategy
