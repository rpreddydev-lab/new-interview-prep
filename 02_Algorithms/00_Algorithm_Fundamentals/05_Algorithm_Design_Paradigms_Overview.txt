================================================================
  ALGORITHM DESIGN PARADIGMS
================================================================

----------------------------------------------------------------
1. BRUTE FORCE
----------------------------------------------------------------
  Try all possible solutions; return the first that satisfies
  the constraints.

  Characteristics:
    - Simplest to implement
    - Guaranteed correct (exhaustive)
    - Usually too slow for large input

  Example: Find two numbers in array summing to target
    Brute force: check all pairs O(n^2)
    Optimized: sort + two pointers O(n log n) or HashMap O(n)

  Use when: n is very small (n <= 15 or so) or as a starting point.

----------------------------------------------------------------
2. GREEDY
----------------------------------------------------------------
  Make the locally optimal choice at each step, hoping it leads
  to a globally optimal solution.

  Requirements:
    - Greedy choice property: local optimum leads to global optimum
    - Optimal substructure: optimal solution contains optimal sub-solutions

  Examples:
    Activity Selection (sort by end time, pick earliest end)
    Dijkstra's shortest path (always pick minimum distance node)
    Huffman encoding (always merge two lowest frequency trees)
    Fractional Knapsack (sort by value/weight ratio)

  CANNOT always be applied:
    0/1 Knapsack: greedy fails, need DP
    Coin change with arbitrary denominations: greedy can fail
      (e.g., coins=[1,3,4], target=6: greedy gives 4+1+1=3 coins
       but optimal is 3+3=2 coins)

  How to recognize greedy problems:
    "Schedule to maximize / minimize"
    "Assign tasks with deadlines"
    "Choose items to fill capacity"
    Proof of greedy: exchange argument (show swapping greedy choice
    for any other never improves the solution)

----------------------------------------------------------------
3. DIVIDE AND CONQUER
----------------------------------------------------------------
  Divide the problem into smaller subproblems, solve each
  recursively, then combine their solutions.

  Pattern:
    divide(problem) -> [sub1, sub2, ...]
    solve each subproblem recursively
    combine results

  Examples:
    Merge Sort: divide array, sort halves, merge -> O(n log n)
    QuickSort:  partition, recurse on parts -> O(n log n) avg
    Binary Search: check mid, recurse on half -> O(log n)
    Strassen's Matrix Multiply -> O(n^2.81)
    Closest Pair of Points -> O(n log n)

  Recurrence: T(n) = aT(n/b) + f(n) -- use Master Theorem.

----------------------------------------------------------------
4. DYNAMIC PROGRAMMING
----------------------------------------------------------------
  Break problem into overlapping subproblems.
  Store results of subproblems (memoization / tabulation).
  Build solution from smaller to larger subproblems.

  Requires:
    - Overlapping subproblems: same subproblem solved multiple times
    - Optimal substructure: optimal solution built from optimal sub-solutions

  Approaches:
    Top-Down (Memoization): recursive + cache
    Bottom-Up (Tabulation): iterative, fill DP table

  Classic DP problems:
    Fibonacci, Knapsack, LCS, LIS, Edit Distance,
    Coin Change, Matrix Chain, DP on Grids/Trees

  DP vs Greedy:
    DP: considers ALL choices, remembers results
    Greedy: makes ONE choice per step, no backtracking
    DP is more powerful but slower; Greedy is faster but not always applicable

----------------------------------------------------------------
5. BACKTRACKING
----------------------------------------------------------------
  Explore all possible solutions using DFS.
  Abandon a path as soon as it violates a constraint (pruning).

  Template:
    void backtrack(state) {
      if (isGoal(state)) { record(state); return; }
      for (choice : choices(state)) {
        makeChoice(choice);
        backtrack(newState);
        undoChoice(choice);  // undo to restore state
      }
    }

  Examples:
    N-Queens, Sudoku, Subsets, Permutations, Combinations,
    Word Search, Maze solving

  Key optimization: prune early to avoid exploring invalid paths.

----------------------------------------------------------------
6. RANDOMIZED ALGORITHMS
----------------------------------------------------------------
  Use random choices to improve expected performance or simplify.

  Las Vegas: always gives correct result; randomness affects runtime
    Example: Randomized QuickSort -- O(n log n) expected

  Monte Carlo: may give incorrect result; randomness affects correctness
    Example: Miller-Rabin primality test (probabilistic)

  Practical use:
    Randomized pivot in QuickSort prevents O(n^2) worst case on sorted input
    Reservoir sampling for random selection from a stream
    Skip List (probabilistic O(log n))

----------------------------------------------------------------
CHOOSING THE RIGHT PARADIGM
----------------------------------------------------------------
  Problem asks for:          Consider:
  ---------------------------------------------------------------
  All valid solutions        Backtracking
  Minimum/maximum value      Greedy (if exchange arg holds) or DP
  Overlapping subproblems    DP
  Sorted input advantage     Binary Search / Two Pointers
  Split into equal halves    Divide & Conquer
  Single optimal choice      Greedy
  Count distinct solutions   DP
  Explore state space        BFS (shortest) or DFS

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. Always state which paradigm you're using and WHY
  2. For DP: define the state clearly before writing the recurrence
  3. Greedy requires a correctness proof; if you can't prove it,
     try DP as a safer fallback
  4. Backtracking time = O(b^d) where b=branching factor, d=depth
  5. D&C and DP both use optimal substructure but D&C subproblems
     DON'T overlap (if they do, DP is better)
