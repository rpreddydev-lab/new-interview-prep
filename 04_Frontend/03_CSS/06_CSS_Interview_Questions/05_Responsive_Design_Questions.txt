SECTION 1 — FUNDAMENTALS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q1: What is responsive web design?
A:  Responsive web design (RWD) creates layouts that adapt to the user's
    device screen size, orientation, and capabilities. It's achieved through:
    1. Flexible grid layouts (%, fr units, flex/grid)
    2. Flexible media (max-width:100%, srcset)
    3. Media queries (conditional CSS per viewport)
    Originally coined by Ethan Marcotte (2010). The goal: one codebase,
    optimal experience on any device.

Q2: What is mobile-first design?
A:  Mobile-first means writing base CSS for the smallest screen and using
    min-width media queries to progressively add complexity for larger screens.
    Benefits: forces content prioritization, better performance on mobile
    (no need to override desktop styles), aligns with Google's mobile-first
    indexing. Contrast: desktop-first uses max-width media queries to strip
    desktop styles for mobile.

Q3: What does the viewport meta tag do?
A:  <meta name="viewport" content="width=device-width, initial-scale=1">
    Without it, mobile browsers assume a ~980px wide viewport and scale down.
    width=device-width → use actual device width, not 980px
    initial-scale=1   → no default zoom
    ⚠️ Never use maximum-scale=1 or user-scalable=no — violates WCAG 2.1.

Q4: What is the difference between min-width and max-width media queries?
A:  min-width (mobile-first): styles apply at this width AND ABOVE.
    @media (min-width: 768px) — applies from 768px up (tablet+)
    max-width (desktop-first): styles apply at this width AND BELOW.
    @media (max-width: 768px) — applies up to 768px (mobile)
    Mixing both: range query → @media (min-width: 600px) and (max-width:1200px)

SECTION 2 — RESPONSIVE LAYOUT TECHNIQUES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q5: How do you create a responsive card grid without media queries?
A:  Using CSS Grid with auto-fill/auto-fit and minmax():
    .grid {
      display: grid;
      grid-template-columns: repeat(auto-fill, minmax(250px, 1fr));
      gap: 16px;
    }
    Cards automatically wrap — 3 columns on wide screens, 2 on medium,
    1 on narrow — with zero media queries.

Q6: What is the difference between auto-fill and auto-fit?
A:  Both create as many columns as fit given the minmax() min-width.
    auto-fill: keeps empty column tracks (grid stays at max columns)
    auto-fit: collapses empty tracks; existing items stretch to fill the row
    Practical difference only visible when there are fewer items than max columns.
    auto-fit is usually preferred for card grids.

Q7: How do you make a two-column layout go single column on mobile?
A:  /* Mobile-first grid: single column */
    .grid { display: grid; gap: 16px; }

    @media (min-width: 768px) {
      .grid { grid-template-columns: 1fr 1fr; }
    }
    Or with Flexbox:
    .row { display: flex; flex-wrap: wrap; gap: 16px; }
    .row > * { flex: 1 1 300px; }  /* wraps below 300px natural size */

Q8: What is fluid typography?
A:  Fluid typography scales font sizes continuously with viewport width instead
    of jumping at fixed breakpoints.
    h1 { font-size: clamp(1.5rem, 4vw, 3rem); }
    • At narrow viewports: 1.5rem (minimum)
    • Scales with viewport via 4vw
    • At wide viewports: 3rem (maximum)
    This eliminates the need for multiple font-size media query overrides.

SECTION 3 — IMAGES AND MEDIA
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q9: How do you make images responsive?
A:  /* Basic responsive image */
    img { max-width: 100%; height: auto; display: block; }
    For serving different file sizes: use srcset with w descriptors + sizes:
    <img src="img.jpg" srcset="img-400.jpg 400w, img-800.jpg 800w, img-1200.jpg 1200w"
         sizes="(max-width: 600px) 100vw, 50vw">
    The browser picks the most appropriate size based on viewport and device pixel ratio.

Q10: What is the difference between srcset and the <picture> element?
A:   srcset — multiple versions of the SAME image at different sizes/densities.
              The browser autonomously picks the best option. Resolution switching.
     <picture> — ART DIRECTION: show DIFFERENT images for different conditions
                 (different crops, subjects, or formats). You control which is shown.
     Use <picture> for design-controlled image switching and format negotiation.

Q11: What is object-fit and how does it help with responsive images?
A:   object-fit controls how an <img> fills its box (like background-size):
     cover — fills box, crops to maintain aspect ratio (most useful)
     contain — fits whole image inside box (may letterbox)
     Use case: card grids where all images must have the same displayed height
     without distortion.
     .card-image { width: 100%; height: 200px; object-fit: cover; }

Q12: What is lazy loading and when should you NOT use it?
A:   <img loading="lazy"> defers image loading until the image is near the
     viewport. Reduces initial page load time and network requests.
     DO NOT use on above-the-fold images (hero, banner, logo) — it delays
     Largest Contentful Paint (LCP), hurting Core Web Vitals. Apply it to
     images below the fold.

SECTION 4 — CONTAINER QUERIES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q13: What are container queries and how do they differ from media queries?
A:   Media queries respond to the VIEWPORT dimensions.
     Container queries (@container) respond to the size of a PARENT ELEMENT.
     A card component with container queries can adapt its layout based on
     how wide its container is — making it truly reusable regardless of where
     it's placed.
     .wrapper { container-type: inline-size; }
     @container (min-width: 500px) { .card { flex-direction: row; } }

Q14: What is container-type?
A:   container-type establishes an element as a query container:
     inline-size — respond to container's inline (width) dimension
     size         — respond to container's width AND height
     normal       — creates a container for style queries only (no size queries)
     Most common: container-type: inline-size.

SECTION 5 — ACCESSIBLE RESPONSIVE DESIGN
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q15: How do you handle reduced motion preferences?
A:   @media (prefers-reduced-motion: reduce) {
       *, *::before, *::after {
         animation-duration: 0.01ms !important;
         transition-duration: 0.01ms !important;
       }
     }
     Users with vestibular disorders or motion sensitivity set this in their OS.
     Always respect it to avoid causing nausea or seizures.

Q16: How do you implement a dark mode with CSS?
A:   Using prefers-color-scheme media query:
     /* Option 1: CSS variables */
     :root { --bg: white; --text: black; }
     @media (prefers-color-scheme: dark) {
       :root { --bg: #121212; --text: #e0e0e0; }
     }
     body { background: var(--bg); color: var(--text); }

     /* Option 2: .dark class (for user toggle) */
     .dark { --bg: #121212; --text: #e0e0e0; }
     Toggle: document.documentElement.classList.toggle('dark')

Q17: What are the minimum touch target sizes?
A:   • WCAG 2.5.8 (AA): 24×24 CSS pixels minimum
     • WCAG 2.5.5 (AAA): 44×44 CSS pixels minimum
     • Apple HIG: 44×44 points
     • Google Material: 48×48dp
     Practical: set min-height/min-width: 44px on interactive elements.
     Ensure enough spacing between adjacent targets.

Q18: What is content reflow and why is it important at 400% zoom?
A:   WCAG 1.4.10 requires that content at 400% zoom (equivalent to 320px
     viewport) doesn't require horizontal scrolling to read. This means
     your mobile layout must work at 320px wide. Test by setting viewport
     to 320px. Use min() or clamp() instead of fixed widths to prevent overflow.

SECTION 6 — PERFORMANCE AND CORE WEB VITALS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q19: How does CSS affect Core Web Vitals?
A:   LCP (Largest Contentful Paint):
       • Preload hero images, inline critical CSS
       • Don't lazy-load above-the-fold images
       • Avoid render-blocking CSS in <body>
     CLS (Cumulative Layout Shift):
       • Set width/height on images and videos (or aspect-ratio)
       • Don't inject content above existing content
       • Use font-display: swap carefully (fallback → web font causes shift)
     INP (Interaction to Next Paint):
       • Avoid expensive CSS triggered on interaction
       • Prefer transform/opacity animations (compositor thread)

Q20: What is the best strategy for loading CSS for performance?
A:   1. Inline critical CSS in <head> (above-the-fold styles)
     2. Load full CSS asynchronously:
        <link rel="preload" href="styles.css" as="style"
              onload="this.rel='stylesheet'">
        <noscript><link rel="stylesheet" href="styles.css"></noscript>
     3. Split CSS by route (only load what the page needs)
     4. Use HTTP/2 — multiple CSS files don't hurt as much
     5. Compress with Brotli/gzip, set far-future cache headers
     6. Minify CSS in production
