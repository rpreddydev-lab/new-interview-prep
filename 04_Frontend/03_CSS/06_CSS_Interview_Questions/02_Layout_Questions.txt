SECTION 1 — DISPLAY AND BLOCK FORMATTING CONTEXT
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q1: What is the difference between block, inline, and inline-block?
A:  block       — takes full available width, starts on new line,
                  respects all margin/padding/width/height
    inline      — flows with text, ignores width/height, vertical
                  margin/padding don't affect layout
    inline-block— flows with text but respects width/height and all margin/padding

Q2: What is a Block Formatting Context (BFC)?
A:  A BFC is an independent rendering region that follows specific rules:
    • Contains its floated children (prevents float collapse)
    • Prevents margin collapse with children
    • Does not overlap adjacent floated elements
    Created by: overflow != visible, display: flow-root, float, absolute/fixed
    position, inline-flex/grid, and more.
    display: flow-root is the cleanest way to trigger a BFC.

Q3: What is display:contents?
A:  display:contents makes an element act as if it doesn't exist in the DOM —
    its children are treated as direct children of the element's parent.
    Use case: a wrapper div in a flex/grid container that you want to "see through"
    without restructuring HTML.
    ⚠️ Accessibility warning: some screen readers may skip the element entirely.

SECTION 2 — POSITIONING
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q4: Explain all five position values.
A:  static   — default, in normal flow, top/left/etc. have no effect
    relative  — stays in flow, top/left/etc. move it FROM its original position
    absolute  — removed from flow, positioned relative to nearest positioned ancestor
    fixed     — removed from flow, positioned relative to the VIEWPORT
    sticky    — hybrid: in-flow until it crosses a threshold, then sticks

Q5: What makes an element a "positioned ancestor"?
A:  Any element with position: relative, absolute, fixed, or sticky.
    Not position: static.
    Absolutely positioned children are placed relative to their nearest
    positioned ancestor. If none exists, they're positioned relative to
    the initial containing block (<html>).

Q6: When does position:fixed fail?
A:  position:fixed positions relative to the viewport, but if ANY ancestor
    has a transform, filter, or perspective property, the fixed element
    positions relative to THAT ancestor instead of the viewport.
    This is a well-known CSS bug/gotcha — transforms create a new containing block.

Q7: What are the requirements for position:sticky to work?
A:  All of these must be true:
    1. The element has at least one of top/right/bottom/left set
    2. The parent/scrollable ancestor has enough height to scroll
    3. No ancestor has overflow:hidden or overflow:auto (that clips it)
    4. The element doesn't span the full height of its parent

Q8: What is the inset property?
A:  Shorthand for top, right, bottom, left:
    inset: 0  → top:0; right:0; bottom:0; left:0
    Also logical: inset-inline (left+right), inset-block (top+bottom)
    Useful for full-bleed positioning:
    position: absolute; inset: 0; → fills the positioned parent completely

SECTION 3 — STACKING AND Z-INDEX
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q9: What creates a stacking context?
A:  A stacking context is an independent z-index scope. Elements inside it
    are z-indexed only relative to each other, not to elements outside.
    Created by:
    • position != static AND z-index != auto
    • opacity < 1
    • transform (any non-none value)
    • filter (any non-none value)
    • isolation: isolate
    • will-change (with certain values)
    • clip-path (non-none)
    • position: fixed or sticky (always creates one)
    • flex/grid children with z-index != auto

Q10: How do you prevent z-index issues in a component?
A:   isolation: isolate on the component's root element. This creates a new
     stacking context, containing all internal z-index values within the
     component. Elements inside cannot accidentally compete with z-index
     of elements outside the component.

SECTION 4 — OVERFLOW AND FLOAT
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q11: What is the clearfix technique and why was it needed?
A:   When all children of a container are floated, the container collapses to
     zero height (float collapse). Clearfix was a hack to fix this:
     .clearfix::after { content: ""; display: block; clear: both; }
     Modern solution: give the container display:flow-root or use
     Flexbox/Grid, which both contain floats automatically.

Q12: What is the difference between overflow:hidden, scroll, auto, and clip?
A:   visible — (default) content can overflow, no scrollbar
     hidden  — clips overflow, creates BFC, no scrollbar
     scroll  — always shows scrollbars (even if not needed)
     auto    — scrollbars appear only when content overflows
     clip    — clips overflow like hidden but does NOT create a BFC
     overflow:clip is new and useful when you want clipping without the BFC side effects.

SECTION 5 — PRACTICAL LAYOUT PATTERNS

Q13: How do you create a sticky footer that stays at the bottom?
A:   /* Method 1: Flexbox */
     body { min-height: 100vh; display: flex; flex-direction: column; }
     main { flex: 1; }  /* pushes footer down */

     /* Method 2: Grid */
     body { min-height: 100vh; display: grid; grid-template-rows: auto 1fr auto; }

Q14: How do you implement a full-page layout with sidebar, header, and footer?
A:   CSS Grid with named areas:
     .layout {
       display: grid;
       min-height: 100vh;
       grid-template-areas: "header header" "sidebar main" "footer footer";
       grid-template-columns: 240px 1fr;
       grid-template-rows: auto 1fr auto;
     }
     Each section gets: grid-area: header/sidebar/main/footer

Q15: What is the aspect-ratio property?
A:   aspect-ratio defines a preferred ratio between width and height.
     .video { aspect-ratio: 16 / 9; width: 100%; }
     When width is known, height is calculated automatically.
     Replaces the old "padding-bottom hack" for responsive iframes.
