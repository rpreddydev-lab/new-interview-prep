1. WHAT IS SASS?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

SASS (Syntactically Awesome Style Sheets) is a CSS preprocessor that adds
features to CSS — variables, nesting, mixins, functions, inheritance, and more.
It compiles to plain CSS.

Two syntaxes:
  • SCSS (.scss) — superset of CSS, uses braces and semicolons (more popular)
  • Sass (.sass) — indentation-based, no braces (older)

  /* SCSS syntax (superset of CSS) */
  $primary: #007bff;
  .button { color: $primary; }

  // Sass syntax (indentation-based)
  $primary: #007bff
  .button
    color: $primary

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
2. VARIABLES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  $primary-color: #007bff;
  $spacing-unit: 8px;
  $font-stack: 'Inter', sans-serif;
  $breakpoint-md: 768px;

  body { font-family: $font-stack; }
  .button { background: $primary-color; padding: $spacing-unit * 2; }

  vs CSS Custom Properties (variables):
  ┌─────────────────────────┬─────────────────────────────┐
  │  SASS Variables ($)      │  CSS Custom Properties (--)  │
  ├─────────────────────────┼─────────────────────────────┤
  │  Compile-time            │  Runtime                     │
  │  Not in browser DevTools │  Visible in DevTools         │
  │  Not dynamic (no JS)     │  Can be changed by JS        │
  │  No scope (global)       │  Inherit through DOM         │
  │  Can be used in @media   │  Cannot be used in @media    │
  │  Concatenation possible  │  Requires calc()             │
  └─────────────────────────┴─────────────────────────────┘

  Best practice: Use SASS variables for compile-time constants (breakpoints,
  base sizes). Use CSS custom properties for runtime theming/dynamic values.

3. NESTING
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  .nav {
    display: flex;
    gap: 16px;

    &:hover { background: rgba(0,0,0,0.05); }  /* & = parent selector */

    a {
      color: black;
      text-decoration: none;

      &:hover { color: $primary-color; }
      &.active { font-weight: bold; }
    }

    &--dark {           /* BEM modifier: .nav--dark */
      background: #111;
      a { color: white; }
    }
  }

  The & character references the parent selector:
    .nav &   → compiles to .nav .nav (rarely used)
    &:hover  → .nav:hover
    &--dark  → .nav--dark (BEM pattern)
    &_item   → .nav_item

  ⚠️ Don't nest more than 3 levels deep — leads to overly specific selectors.

4. MIXINS — REUSABLE STYLE BLOCKS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  /* Define a mixin */
  @mixin flex-center {
    display: flex;
    justify-content: center;
    align-items: center;
  }

  /* Mixin with parameters */
  @mixin respond-to($breakpoint) {
    @if $breakpoint == 'md' {
      @media (min-width: 768px) { @content; }
    } @else if $breakpoint == 'lg' {
      @media (min-width: 1024px) { @content; }
    }
  }

  /* Use the mixin */
  .hero {
    @include flex-center;
    min-height: 100vh;

    @include respond-to('md') {
      min-height: 60vh;
    }
  }

  /* Default parameter values */
  @mixin button($color: blue, $padding: 8px 16px) {
    background: $color;
    padding: $padding;
    border-radius: 4px;
    border: none;
    cursor: pointer;
  }

  .btn-primary { @include button(#007bff); }
  .btn-small   { @include button(#28a745, 4px 8px); }

5. @extend — SELECTOR INHERITANCE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  %button-base {  /* % = placeholder (not output to CSS unless extended) */
    display: inline-flex;
    padding: 8px 16px;
    border-radius: 4px;
    font-weight: 600;
    cursor: pointer;
    border: none;
  }

  .btn-primary {
    @extend %button-base;
    background: $primary-color;
    color: white;
  }

  .btn-secondary {
    @extend %button-base;
    background: transparent;
    border: 2px solid $primary-color;
  }

  /* Compiles to: */
  .btn-primary, .btn-secondary { display: inline-flex; padding: 8px 16px; ... }
  .btn-primary { background: #007bff; color: white; }
  .btn-secondary { background: transparent; border: 2px solid #007bff; }

  Mixin vs @extend:
    @include (mixin) — duplicates the CSS in each class (larger file, more flexible)
    @extend          — groups selectors (smaller file, can cause selector issues in media queries)
    Prefer @include for most cases. @extend with placeholder selectors is safe.

6. FUNCTIONS AND BUILT-INS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  /* Custom function */
  @function rem($px) {
    @return ($px / 16px) * 1rem;
  }

  h1 { font-size: rem(32px); }  /* outputs: 2rem */

  Built-in SASS functions:
    Color: lighten($color, 10%), darken($color, 10%), mix($c1, $c2, 50%)
           adjust-color(), rgba(), desaturate(), complement()
    Math:  math.abs(), math.ceil(), math.floor(), math.round(), math.max()
    String: string.quote(), string.unquote(), string.length()
    List:  list.nth(), list.length(), list.join()
    Map:   map.get($map, key), map.merge(), map.keys()

7. MAPS AND LOOPS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  $colors: (
    'primary': #007bff,
    'success': #28a745,
    'danger':  #dc3545,
    'warning': #ffc107,
  );

  @each $name, $value in $colors {
    .text-#{$name} { color: $value; }
    .bg-#{$name}   { background-color: $value; }
  }
  /* Generates: .text-primary, .bg-primary, .text-success, ... */

  /* @for loop */
  @for $i from 1 through 5 {
    .mt-#{$i} { margin-top: #{$i * 4}px; }
  }

  /* @while loop */
  $i: 1;
  @while $i <= 5 {
    .col-#{$i} { width: percentage($i / 5); }
    $i: $i + 1;
  }

8. PARTIALS AND @use / @forward
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  File naming: Prefix partial files with underscore → _variables.scss
  Partial files are not compiled independently; they're imported.

  Modern approach (@use — Dart Sass):
    @use 'variables' as v;         /* namespace: v.$primary-color */
    @use 'mixins' as *;            /* no namespace (use with care) */
    @use 'colors' with ($primary: red);  /* configure module */

  @forward — re-exports from a module:
    /* _index.scss */
    @forward 'variables';
    @forward 'mixins';
    @forward 'colors';

    /* Then in main.scss: */
    @use 'path/to/index' as design;
    .button { color: design.$primary; }

  Old approach (deprecated):
    @import 'variables';  /* deprecated — global scope, runs multiple times */

9. KEY INTERVIEW QUESTIONS — SASS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: What is SASS and why use it over plain CSS?
A: SASS is a CSS preprocessor that adds features like variables, nesting, mixins,
   functions, loops, and partials. It compiles to standard CSS. Benefits:
   better code organization with partials, reusability via mixins, computed
   values, and generated utility classes. With native CSS adding variables and
   nesting, SASS's advantage is narrowing, but it remains valuable for
   compile-time logic, mixins, and loops.

Q: What is the difference between a mixin and @extend?
A: @include (mixin): copies the CSS into every class that uses it — more CSS
   output but works anywhere including inside @media.
   @extend: groups selectors together — less CSS output but can cause issues
   inside @media queries. Use placeholder selectors (%) with @extend to avoid
   outputting unwanted rules.

Q: What is the difference between SASS variables and CSS custom properties?
A: SASS variables are compile-time — resolved when SCSS compiles to CSS,
   invisible to the browser, and cannot be changed by JavaScript.
   CSS custom properties (--var) are runtime — visible in DevTools, can be
   changed by JS, inherit through the DOM, and support theming without recompile.

Q: What is the difference between @use and @import in SASS?
A: @import is deprecated — it puts everything in global scope and files can
   be imported multiple times. @use creates module namespaces, ensures files
   are loaded once, and supports configuration. It's the modern approach.

Q: What does the & selector do in SCSS nesting?
A: & refers to the parent selector. It's used for modifiers (& .active),
   pseudo-classes (&:hover), pseudo-elements (&::before), and BEM modifiers
   (&--variant, &__element). Without &, nesting adds a descendant combinator.
