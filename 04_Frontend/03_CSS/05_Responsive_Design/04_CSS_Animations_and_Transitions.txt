1. CSS TRANSITIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Transitions animate a property change from one state to another.
They are triggered by state changes (:hover, :focus, class toggling via JS).

  /* Longhand */
  .button {
    background: blue;
    transition-property: background, transform;
    transition-duration: 200ms;
    transition-timing-function: ease-out;
    transition-delay: 0ms;
  }

  /* Shorthand */
  .button {
    transition: background 200ms ease-out,
                transform 200ms ease-out 50ms; /* 50ms delay on transform */
  }

  .button:hover {
    background: darkblue;
    transform: scale(1.05);
  }

  Transition shorthand order:
    transition: <property> <duration> <timing-function> <delay>;

  /* Transition all properties (use with caution — can affect unexpected props) */
  .card { transition: all 300ms ease; }

  /* Better: transition only what you animate */
  .card { transition: transform 300ms ease, opacity 300ms ease; }

2. TIMING FUNCTIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Keyword         | cubic-bezier equivalent     | Feel
  ───────────────────────────────────────────────────────────────────
  ease            | cubic-bezier(0.25,0.1,0.25,1)| Slow start, fast middle, slow end
  ease-in         | cubic-bezier(0.42,0,1,1)    | Slow start, fast end (enter)
  ease-out        | cubic-bezier(0,0,0.58,1)    | Fast start, slow end (exit)
  ease-in-out     | cubic-bezier(0.42,0,0.58,1) | Slow start and end
  linear          | cubic-bezier(0,0,1,1)       | Constant speed
  step-start      | steps(1, start)             | Jump immediately
  step-end        | steps(1, end)               | Jump at end
  steps(4, end)   | —                           | 4 discrete steps

  Custom:
  .spring { transition-timing-function: cubic-bezier(0.34, 1.56, 0.64, 1); }
  /* Goes past the end slightly then comes back — spring/bounce effect */

  Modern:
  .smooth { transition-timing-function: linear(0, 0.25, 1); }
  /* CSS linear() — piece-wise linear approximation of any curve */

3. CSS ANIMATIONS WITH @keyframes
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Unlike transitions (which need a trigger), animations run automatically.

  @keyframes fadeIn {
    from { opacity: 0; transform: translateY(20px); }
    to   { opacity: 1; transform: translateY(0); }
  }

  @keyframes pulse {
    0%   { transform: scale(1); }
    50%  { transform: scale(1.1); }
    100% { transform: scale(1); }
  }

  .alert {
    animation-name: pulse;
    animation-duration: 1s;
    animation-timing-function: ease-in-out;
    animation-delay: 0s;
    animation-iteration-count: infinite;  /* or a number */
    animation-direction: normal;          /* normal | reverse | alternate | alternate-reverse */
    animation-fill-mode: both;            /* none | forwards | backwards | both */
    animation-play-state: running;        /* running | paused */
  }

  /* Shorthand */
  .element { animation: fadeIn 500ms ease-out 200ms both; }
  /* name duration timing delay fill-mode */

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
4. animation-fill-mode EXPLAINED
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  none      — Element returns to original styles before and after animation
  forwards  — Element KEEPS styles from the last keyframe after animation ends
  backwards — Element APPLIES first keyframe styles during the delay period
  both      — Applies both: first keyframe during delay, last keyframe after end

  Example (why fill-mode matters):
  @keyframes slideIn {
    from { transform: translateX(-100%); opacity: 0; }
    to   { transform: translateX(0); opacity: 1; }
  }

  /* Without fill-mode: element is visible for 500ms delay, then jumps */
  .item { animation: slideIn 500ms 500ms; }

  /* With backwards: element starts at -100% translateX during the delay */
  .item { animation: slideIn 500ms 500ms backwards; }

5. WHICH PROPERTIES TO ANIMATE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  The browser rendering pipeline:
    1. Layout (reflow)  — geometry changes trigger this (width, height, margin, padding, position)
    2. Paint (repaint)  — visual changes (color, background, border, box-shadow)
    3. Composite        — layer compositing only (transform, opacity)

  CHEAPEST — Composite layer only (GPU-accelerated, no layout/paint):
  ✅ transform: translate, scale, rotate, skew
  ✅ opacity

  MEDIUM — Paint only (no layout reflow):
  ⚠️ color, background-color, border-color, box-shadow, filter, text-shadow

  EXPENSIVE — Triggers layout reflow:
  ❌ width, height, margin, padding, top, left, right, bottom
  ❌ font-size, line-height
  ❌ display, overflow

  Best practice:
    • Animate transform/opacity for smooth 60fps animations
    • Animate color/background only for short, non-repeated transitions
    • Never animate layout properties in continuous loops

6. will-change — HINTING THE BROWSER
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  .animated-element {
    will-change: transform, opacity;
  }

  • Tells the browser to promote the element to its own compositor layer in advance
  • Enables the GPU to handle animations without triggering main-thread work
  • CAUTION: Overusing will-change wastes GPU memory — only apply to elements
    that will actually animate
  • Remove will-change after animation completes (via JS class removal)
  • Don't apply to too many elements — every "layer" costs memory

7. ACCESSIBLE ANIMATIONS — prefers-reduced-motion
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Users with vestibular disorders, epilepsy, or motion sensitivity can set
  their OS to reduce motion. Always respect this preference.

  /* Global reset for reduced motion */
  @media (prefers-reduced-motion: reduce) {
    *, *::before, *::after {
      animation-duration: 0.01ms !important;
      animation-iteration-count: 1 !important;
      transition-duration: 0.01ms !important;
      scroll-behavior: auto !important;
    }
  }

  /* Targeted: disable non-essential animations */
  .spinner { animation: spin 1s linear infinite; }

  @media (prefers-reduced-motion: reduce) {
    .spinner { animation: none; }
  }

  /* Better pattern: motion-safe (enable) vs motion-reduce (disable) */
  @media (prefers-reduced-motion: no-preference) {
    .card { transition: transform 300ms ease; }
  }

8. PRACTICAL ANIMATION PATTERNS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  /* Staggered list animation */
  @keyframes slideUp {
    from { opacity: 0; transform: translateY(16px); }
    to   { opacity: 1; transform: translateY(0); }
  }

  .list-item { animation: slideUp 400ms ease-out both; }
  .list-item:nth-child(1) { animation-delay: 0ms; }
  .list-item:nth-child(2) { animation-delay: 75ms; }
  .list-item:nth-child(3) { animation-delay: 150ms; }
  .list-item:nth-child(4) { animation-delay: 225ms; }

  /* Loading spinner */
  @keyframes spin { to { transform: rotate(360deg); } }
  .spinner {
    width: 24px; height: 24px;
    border: 3px solid rgba(0,0,0,0.1);
    border-top-color: blue;
    border-radius: 50%;
    animation: spin 800ms linear infinite;
  }

  /* Pause animation on hover */
  .spinner:hover { animation-play-state: paused; }

9. KEY INTERVIEW QUESTIONS — ANIMATIONS AND TRANSITIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: What is the difference between a CSS transition and a CSS animation?
A: Transitions animate between two states (from → to) and require a trigger
   (hover, focus, class change). Animations use @keyframes and can run
   automatically, repeat infinitely, go through multiple steps, and have
   complex timing.

Q: Which CSS properties are cheapest to animate and why?
A: transform and opacity — they only trigger compositing, not layout or paint.
   The browser can handle these on the GPU (compositor thread) without
   blocking the main thread, enabling consistent 60fps. Properties like
   width/height/margin trigger layout (reflow), which is expensive.

Q: What is animation-fill-mode and why is "both" commonly used?
A: fill-mode controls element state before/after animation.
   "forwards" — retains last keyframe styles after animation ends.
   "backwards" — applies first keyframe styles during the delay.
   "both" — does both. It's commonly used so the element starts in the
   "from" state during the delay and stays in the "to" state after.

Q: What is will-change and when should you use it?
A: will-change hints to the browser that an element will be animated, allowing
   it to pre-promote the element to a GPU layer. Use sparingly, only on
   elements that will definitely animate, because each layer consumes GPU memory.
   Overusing it can hurt performance.

Q: How do you make animations accessible?
A: By respecting the prefers-reduced-motion media query. Users with motion
   sensitivity can set their OS to reduce motion. CSS should disable or
   simplify animations in this case:
   @media (prefers-reduced-motion: reduce) { * { animation-duration: 0.01ms !important; } }
