CSS CONTAINER QUERIES — INTERVIEW PREPARATION

1. WHAT ARE CONTAINER QUERIES?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Container Queries allow a component to style itself based on the size of its
PARENT CONTAINER — not the viewport width (which is what media queries use).

BROWSER SUPPORT: All modern browsers as of Chrome 105, Firefox 110, Safari 16
(released 2022–2023). Baseline 2023 — safe to use in production.

THE PROBLEM MEDIA QUERIES DON'T SOLVE:
  Imagine a ProductCard component used in:
  - A 3-column grid on a wide page → card is narrow
  - A 1-column full-width layout on the same viewport → card is wide

  With media queries, you'd check the viewport width — but the card's actual
  width depends on its grid context, not the viewport. Container queries let
  the card respond to its OWN available width.

2. SYNTAX
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

STEP 1 — Define a containment context on the parent:
  .card-container {
    container-type: inline-size;  /* Enable containment on inline axis (width) */
    container-name: card;         /* Optional: name the container */
  }

  /* Shorthand: */
  .card-container {
    container: card / inline-size;  /* name / type */
  }

CONTAINER-TYPE VALUES:
  inline-size  → Containment on inline dimension (width in horizontal writing)
  size         → Containment on both inline and block dimensions
  normal       → No containment (default)

STEP 2 — Write container query:
  /* Styles applied when .card-container is at least 400px wide */
  @container card (min-width: 400px) {
    .card {
      display: flex;
      flex-direction: row;
    }
    .card__image {
      width: 200px;
      flex-shrink: 0;
    }
  }

  /* Anonymous container query (no name — targets nearest ancestor with containment): */
  @container (min-width: 300px) {
    .card__title {
      font-size: 1.25rem;
    }
  }

3. REAL EXAMPLE — PRODUCT CARD
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  /* The wrapper that establishes the container context */
  .product-wrapper {
    container: product-card / inline-size;
  }

  /* Default (small): stacked layout */
  .product-card {
    display: grid;
    grid-template-rows: auto auto auto;
  }

  /* When wrapper >= 350px: side-by-side layout */
  @container product-card (min-width: 350px) {
    .product-card {
      grid-template-columns: 120px 1fr;
      grid-template-rows: auto auto;
    }
    .product-card__image {
      grid-row: 1 / 3;  /* Image spans both rows */
    }
  }

  /* When wrapper >= 600px: expanded detail layout */
  @container product-card (min-width: 600px) {
    .product-card {
      grid-template-columns: 200px 1fr auto;
    }
    .product-card__actions {
      display: flex;
      flex-direction: column;
      gap: 8px;
    }
  }

In React (same component, multiple contexts):
  // ProductCard renders identically — container query handles layout
  function Sidebar() {
    return (
      <aside className="product-wrapper">  {/* container context */}
        <ProductCard />  {/* → narrow layout triggered */}
      </aside>
    );
  }

  function MainGrid() {
    return (
      <div className="product-wrapper" style={{ width: '100%' }}>
        <ProductCard />  {/* → wide layout triggered */}
      </div>
    );
  }

4. CONTAINER QUERY UNITS (cqw, cqh, cqi, cqb)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Similar to viewport units (vw, vh) but relative to the container:

  cqw   → 1% of container's width
  cqh   → 1% of container's height
  cqi   → 1% of container's inline size (width in horizontal writing)
  cqb   → 1% of container's block size (height in horizontal writing)
  cqmin → smaller of cqi and cqb
  cqmax → larger of cqi and cqb

EXAMPLE:
  .card__title {
    font-size: clamp(1rem, 5cqi, 2rem);
    /* Font scales with container width, clamped between 1rem and 2rem */
  }

5. STYLE CONTAINER QUERIES (Experimental)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Style queries allow styling based on a parent's COMPUTED STYLE (CSS custom properties):

  /* Parent sets a custom property */
  .theme-dark {
    --theme: dark;
    container-type: style;
  }

  /* Child responds to parent's custom property value */
  @container style(--theme: dark) {
    .card {
      background: #1a1a1a;
      color: white;
    }
  }

  Currently supported in Chrome 111+. Still experimental in other browsers.

6. CONTAINER QUERIES vs MEDIA QUERIES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Aspect              Media Queries                Container Queries
  ──────────────────────────────────────────────────────────────────────
  Based on            Viewport dimensions          Parent container dimensions
  Component reuse     Context-aware styles hard    ✅ Same component, adapts to context
  Component isolation ❌ Depends on global viewport ✅ Truly encapsulated
  Page-level layout   ✅ Excellent                  Overkill
  Reusable components ❌ Hacky                      ✅ Natural fit
  Browser support     Universal                    Baseline 2023 (all modern)

WHEN TO USE WHICH:
  - Overall page layout (header, sidebar, main): Media Queries
  - Component internal layout (cards, widgets, nav items): Container Queries
  - Font size scaling globally: Media Queries
  - Font size within a component: Container Queries or cqi units

7. INTERVIEW QUESTIONS — CONTAINER QUERIES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: What are CSS Container Queries and how do they differ from Media Queries?
A: Media queries respond to the viewport size — they're global. Container
   queries respond to the size of a specific parent element. The key difference
   is context: if a ProductCard is used in a narrow sidebar AND in a wide main
   grid on the same page, media queries can't distinguish these cases because
   the viewport is the same. Container queries let the card respond to its
   available space within its container — making components truly context-aware
   and reusable. You define a containment context with container-type: inline-size
   on the parent, then use @container (min-width: Xpx) { } to style children.

Q: What does container-type: inline-size mean?
A: It establishes a query containment context on the inline dimension (typically
   width in horizontal writing modes). The element's children can then use
   @container queries based on this element's computed inline size. "inline-size"
   is the most commonly used value because width-based queries are most needed.
   "size" establishes containment on both dimensions (width and height) but is
   rarely needed and has performance implications. You must set container-type
   on the PARENT — not on the element you want to style.

Q: What are container query units?
A: Units relative to the query container: cqw (1% of container width), cqh
   (1% of container height), cqi (1% of container inline size). Similar to vw/vh
   but scoped to the container. Useful for fluid typography within a component:
   font-size: clamp(1rem, 4cqi, 1.5rem) makes text scale with container width
   while clamping to sensible min/max values.
