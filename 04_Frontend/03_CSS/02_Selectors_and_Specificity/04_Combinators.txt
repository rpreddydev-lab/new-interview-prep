CSS COMBINATORS — In-Depth Interview Preparation Guide
================================================================================

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1. WHAT ARE COMBINATORS?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Combinators explain the RELATIONSHIP between two selectors. They combine two
simple selectors to describe structural relationships in the DOM.

There are 4 CSS combinators:
  A B    → Descendant combinator (space)
  A > B  → Child combinator
  A + B  → Adjacent sibling combinator
  A ~ B  → General sibling combinator

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
2. DESCENDANT COMBINATOR (space)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Syntax: A B
Selects: All B elements that are ANYWHERE inside A (any depth of nesting)

  nav a { text-decoration: none; }
  /* All <a> elements anywhere inside <nav>, however deeply nested */

  .sidebar .widget h3 {
    color: blue;
  }
  /* h3 inside .widget, which is inside .sidebar */

HTML:
  <nav>
    <ul>
      <li><a href="#">Link 1</a></li>   ← matched
      <li>
        <div><a href="#">Deep Link</a></div>  ← also matched
      </li>
    </ul>
  </nav>

Performance note: Descendant combinator is the most powerful but can be the
slowest because the browser must check all ancestors. For performance, prefer
direct child (>) where possible.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
3. CHILD COMBINATOR (>)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Syntax: A > B
Selects: B elements that are DIRECT children of A (not deeper levels)

  ul > li { list-style: disc; }
  /* Only <li> elements that are direct children of <ul>, not nested <li>s */

  .nav > .nav__item { display: inline-block; }
  /* Only direct .nav__item children */

HTML:
  <ul>
    <li>Item 1   ← matched by ul > li
      <ul>
        <li>Sub-item</li>   ← NOT matched by ul > li (it's a grandchild)
      </ul>
    </li>
    <li>Item 2   ← matched by ul > li
  </ul>

Use cases:
  • Styling direct navigation items without affecting nested menus
  • Controlled scoping in component styles
  • Slightly faster than descendant combinator

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
4. ADJACENT SIBLING COMBINATOR (+)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Syntax: A + B
Selects: B element that IMMEDIATELY follows A, sharing the same parent.
         Only ONE element is selected — the very next sibling.

  h2 + p { font-size: 1.1em; font-weight: 500; }
  /* First <p> immediately after an <h2> — intro paragraph */

  .checkbox:checked + label { color: blue; }
  /* Label immediately following a checked checkbox */

  li + li { margin-top: 8px; }
  /* All li except the first (no space above first item) */

  input + .error-message { display: block; }
  /* Error message immediately after input */

HTML:
  <h2>Title</h2>
  <p>Intro para</p>   ← matched by h2 + p
  <p>Second para</p>  ← NOT matched

Practical patterns:
  /* Lobotomized owl — spacing between all adjacent elements */
  * + * { margin-top: 1em; }

  /* Skip first child's top margin */
  .stack > * + * { margin-top: 1rem; }

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
5. GENERAL SIBLING COMBINATOR (~)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Syntax: A ~ B
Selects: ALL B elements that follow A at the same level (same parent),
         not necessarily immediately adjacent.

  h2 ~ p { color: gray; }
  /* ALL <p> elements that come after <h2>, same parent */

  .tab-radio:checked ~ .tab-content { display: block; }
  /* CSS-only tab system */

HTML:
  <h2>Title</h2>
  <div>Something else</div>
  <p>Para 1</p>   ← matched
  <p>Para 2</p>   ← matched
  <p>Para 3</p>   ← matched

  Compare to + which would only match "Para 1"

Real-world pattern — CSS-only toggle:
  <input type="checkbox" id="menu-toggle" class="menu-toggle">
  <label for="menu-toggle">☰ Menu</label>
  <nav class="nav">...</nav>

  .menu-toggle { display: none; }
  .menu-toggle:checked ~ .nav { display: block; }
  /* The nav comes AFTER the checkbox in DOM — ~ combinator works! */

6. COMBINATORS SUMMARY TABLE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Combinator | Syntax | Relationship             | Selects
───────────┼────────┼──────────────────────────┼──────────────────────────────
Descendant | A B    | B anywhere inside A       | All B descendants
Child      | A > B  | B direct child of A       | Only direct children B
Adjacent   | A + B  | B immediately after A     | Only 1 element (next sibling)
General    | A ~ B  | B sibling after A         | All following B siblings

7. PRACTICAL COMBINATOR PATTERNS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Pattern 1 — Navigation without first/last margin:
  .nav li + li { margin-left: 16px; }
  /* Adds left margin to every li EXCEPT the first one */

Pattern 2 — Form label float animation (with :focus and +:
  .form-field { position: relative; }
  .form-field label {
    position: absolute;
    top: 12px;
    left: 0;
    transition: all 0.2s;
  }
  .form-field input:focus + label,
  .form-field input:not(:placeholder-shown) + label {
    top: -20px;
    font-size: 0.75em;
    color: blue;
  }

Pattern 3 — Disclosure widget / Accordion (pure CSS):
  details > summary { cursor: pointer; }
  details[open] > summary { color: blue; }
  details[open] > .content { display: block; }

Pattern 4 — Direct child styling in components:
  .card > .card__header { border-bottom: 1px solid #eee; }
  .card > .card__body { padding: 1rem; }
  /* Prevents accidentally styling nested cards */

Pattern 5 — Owl selector (spacing without first margin):
  .stack > * + * {
    margin-block-start: 1rem;
  }

8. THERE IS NO PARENT SELECTOR (Pre-:has())
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

CSS combinators only move DOWN the DOM (child, descendant) or SIDEWAYS (siblings).
There was NO way to select an ancestor/parent based on a child — until :has():

  /* Style the <li> that contains a checked checkbox */
  li:has(input:checked) { background: lightgreen; }

  /* Style form that has an invalid input */
  form:has(:invalid) { border: 2px solid red; }

  /* Style section that has an h2 */
  section:has(h2) { padding-top: 2rem; }

:has() is now supported in all modern browsers (Chrome 105+, Safari 15.4+, Firefox 121+).

9. KEY INTERVIEW QUESTIONS — COMBINATORS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: What is the difference between A B and A > B?
A: A B (descendant) selects B elements ANYWHERE inside A, at any depth.
   A > B (child) selects B elements that are DIRECT children of A only.
   Example: ul li matches nested lis too; ul > li only matches direct lis.

Q: What is the difference between A + B and A ~ B?
A: A + B (adjacent) selects only the SINGLE element B that immediately follows A.
   A ~ B (general sibling) selects ALL B elements that follow A at the same level.
   Example: h2 + p matches only the first p after h2;
            h2 ~ p matches ALL p elements after the h2.

Q: Can you use CSS to style a parent element based on its child?
A: Previously no — CSS combinators only select downstream. Now yes, with :has():
   .parent:has(.child) { ... } — styles .parent when it contains .child.
   This is called a "relational" or "parent selector" and is supported in all
   modern browsers since 2023.

Q: What is the "owl selector" and why is it useful?
A: * + * { margin-top: 1em; } (or > * + * for direct children).
   It adds margin to every element that has a preceding sibling, effectively
   creating spacing between all adjacent elements without adding margin to the
   first one. This avoids needing to manually strip margin-top from first children.

Q: How do you select all list items EXCEPT the first?
A: li + li { ... }    → adjacent sibling: every li after another li
   li:not(:first-child) { ... }  → also works

Q: How would you implement a CSS-only accordion/toggle?
A: Use a hidden checkbox and the ~ general sibling combinator:
   <input type="checkbox" id="toggle">
   <label for="toggle">Click to expand</label>
   <div class="content">Hidden content</div>

   #toggle { display: none; }
   #toggle:checked ~ .content { display: block; }
