1. WHAT IS SPECIFICITY?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Specificity is the weight/score assigned to a CSS selector that determines which
rule wins when multiple rules target the same element and property.

Higher specificity → wins over lower specificity (regardless of source order).
Equal specificity → last declared rule wins (source order matters).

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
2. THE SPECIFICITY COLUMN SYSTEM
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Specificity is represented as 4 columns: (A, B, C, D) or written as (a,b,c,d):

  Column A — Inline styles:         1,0,0,0  (highest)
  Column B — ID selectors:          0,1,0,0
  Column C — Classes, pseudo-classes, attribute selectors: 0,0,1,0
  Column D — Type selectors, pseudo-elements:              0,0,0,1
  (Universal *, combinators +, >, ~, space, :is(), :not(), :has() = 0,0,0,0)

Comparison is done left to right (like comparing multi-digit numbers):
  0,1,0,0 beats 0,0,10,0 (no matter how many class selectors)
  "There's no number large enough in column D to beat an ID in column B"

Visual representation:
  A    B    C    D
  │    │    │    └─ type selectors, pseudo-elements
  │    │    └────── classes, pseudo-classes, attributes
  │    └─────────── ID selectors
  └──────────────── inline styles

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
3. SPECIFICITY VALUES BY SELECTOR TYPE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Selector                     | Specificity  | Notes
─────────────────────────────┼──────────────┼────────────────────────────────
*                            | 0,0,0,0      | Universal selector
div                          | 0,0,0,1      | Element/type
::before                     | 0,0,0,1      | Pseudo-element (double colon)
:first-line                  | 0,0,0,1      | Pseudo-element (legacy single :)
.class                       | 0,0,1,0      | Class selector
[type="text"]                | 0,0,1,0      | Attribute selector
:hover                       | 0,0,1,0      | Pseudo-class
:nth-child(2)                | 0,0,1,0      | Pseudo-class (structural)
#id                          | 0,1,0,0      | ID selector
style="..."                  | 1,0,0,0      | Inline style
!important                   | N/A          | Overrides everything (separate)

Compound examples:
  div p                      | 0,0,0,2      | 2 type selectors
  .nav a                     | 0,0,1,1      | 1 class + 1 type
  #header .nav               | 0,1,1,0      | 1 ID + 1 class
  #header .nav a:hover       | 0,1,2,1      | 1 ID + 2 class-like + 1 type
  .form input[type]:focus    | 0,0,3,1      | 3 class-level + 1 type

4. WORKED SPECIFICITY EXAMPLES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Example 1:
  <p id="intro" class="text">Hello</p>

  p { color: green; }             /* 0,0,0,1 */
  .text { color: blue; }          /* 0,0,1,0 */
  #intro { color: red; }          /* 0,1,0,0 */

  Result: RED (ID wins)

Example 2:
  <a class="link active" href="#">Click</a>

  .link { color: gray; }          /* 0,0,1,0 */
  .link.active { color: blue; }   /* 0,0,2,0 */
  a.link { color: green; }        /* 0,0,1,1 */

  .link.active = (0,0,2,0) vs a.link = (0,0,1,1)
  Compare C column: 2 > 1 → .link.active wins → BLUE

Example 3:
  <div id="app">
    <p class="text">Hello</p>
  </div>

  #app p { color: red; }          /* 0,1,0,1 */
  p.text { color: blue; }         /* 0,0,1,1 */

  #app p = (0,1,0,1), p.text = (0,0,1,1)
  Compare B column: 1 > 0 → #app p wins → RED

Example 4 — :not() and :is() specificity:
  :not(p) { color: blue; }        /* same as 0,0,0,0 — :not itself = 0 */
                                  /* but argument p = 0,0,0,1 */
                                  /* so :not(p) = 0,0,0,1 */

  :is(#id, .class) { color: red; }/* highest in list = 0,1,0,0 (ID) */
  :where(#id, .class) { color: green; } /* 0,0,0,0 — :where always = 0 */

5. !IMPORTANT
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

!important overrides ALL specificity rules:
  p { color: green !important; }
  /* Wins over #id rule, inline styles, everything — unless opponent also has !important */

!important vs !important: specificity decides again, then source order.

Use cases for !important (sparingly):
  • Utility classes that must always apply (e.g., .hidden { display: none !important; })
  • Overriding third-party CSS you can't edit
  • Accessibility overrides

Anti-patterns with !important:
  • Using it to "fix" specificity wars → leads to !important chain
  • Using it in component styles → breaks overridability
  • Never use in reusable libraries

6. STRATEGIES TO MANAGE SPECIFICITY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1) Keep specificity LOW and FLAT:
   • Always use single classes (.btn, .card__title)
   • Avoid ID selectors for styling (reserve IDs for JS anchors)
   • Avoid deep selector chains (nav > ul > li > a → .nav__link)

2) BEM naming to avoid nesting:
   .card { }
   .card__title { }
   .card--featured { }
   /* All specificity = 0,0,1,0 — easy to override */

3) Use :where() for base styles (specificity = 0):
   :where(h1, h2, h3) { font-weight: bold; }
   /* Any single-class override wins */

4) CSS Layers (@layer) for explicit order:
   @layer base, components, utilities;
   /* utilities always win over components, always win over base */
   /* No need to fight specificity */

5) Avoid inline styles in HTML (use classes)

6) Use specificity calculators during debugging:
   • https://specificity.keegan.st/
   • Chrome DevTools highlights specificity in computed styles

7. SOURCE ORDER AS TIEBREAKER
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

When specificity is equal, the LAST declared rule wins:
  .btn { color: blue; }
  .btn { color: red; }   /* RED wins — declared later */

This applies across stylesheets in the order they are loaded:
  <link rel="stylesheet" href="base.css">    /* loaded first, lower priority */
  <link rel="stylesheet" href="theme.css">   /* loaded later, wins on equal specificity */

8. SPECIFICITY AND PSEUDO-CLASSES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Common gotcha — link pseudo-class order (LoVe-HA):
  a:link    { }     /* unvisited */
  a:visited { }     /* visited */
  a:hover   { }     /* hovering */
  a:active  { }     /* clicking */

  All have same specificity (0,0,1,1). Order matters.
  If :hover comes before :visited, hovering over visited links won't change.
  Rule: L-V-H-A (or LoVe HAte) — always in this order.

9. KEY INTERVIEW QUESTIONS — SPECIFICITY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: What is specificity in CSS?
A: Specificity is the algorithm browsers use to decide which CSS rule applies to
   an element when multiple rules conflict. It's calculated as (A,B,C,D):
   A=inline, B=IDs, C=classes/pseudo-classes/attributes, D=elements/pseudo-elements.
   Compared left to right; higher wins.

Q: Which has higher specificity: #id or 100 classes?
A: #id (0,1,0,0) always beats 100 classes (0,0,100,0) because ID is in column B
   while classes are in column C, and columns are compared left to right with no
   carry-over. "100 pennies ≠ 1 dollar" in different columns.

Q: When should you use !important?
A: Sparingly. Good use cases: utility override classes (.sr-only, .hidden),
   overriding third-party styles you can't modify, and accessibility overrides.
   Avoid in component styles — it makes overriding from the outside impossible.

Q: What does :where() do to specificity?
A: :where() always evaluates to specificity 0,0,0,0 regardless of the selectors
   inside it. This makes it ideal for base styles or CSS resets that should never
   win specificity battles. Any single class override will beat :where() styles.

Q: How do CSS layers affect specificity?
A: @layer creates named cascade layers. Rules in later-declared layers win over
   earlier layers regardless of specificity. Un-layered styles beat ALL layers.
   This gives you control over priority without specificity wars.

Q: What is the LoVe-HA order for link styles?
A: a:link, a:visited, a:hover, a:active — in that order.
   Since all have the same specificity, order determines which state overrides which.
   Without this order, hover/active states may not work on visited links.

Q: What is the specificity of :not()?
A: :not() itself contributes 0 to specificity, but its argument does.
   :not(.active) = 0,0,1,0 (class inside contributes)
   :not(#id)     = 0,1,0,0 (ID inside contributes)
   CSS4 :not() accepts lists: :not(.a, .b) = 0,0,1,0
