1. WHY MOCK?
================================================================================

Mocking replaces real implementations with controlled substitutes.

REASONS TO MOCK:
  ✅ Isolate the unit under test from external dependencies
  ✅ Control return values to test different scenarios
  ✅ Track how functions were called (calls, arguments, return values)
  ✅ Prevent real network calls, database writes, or file I/O
  ✅ Simulate errors and edge cases
  ✅ Speed up tests by removing slow operations

WHAT TO MOCK:
  ✅ Network requests (API calls)
  ✅ Database operations
  ✅ File system operations
  ✅ Third-party SDK calls (analytics, payment providers)
  ✅ System time (Date.now(), new Date())
  ✅ Random values (Math.random())

WHAT NOT TO MOCK:
  ❌ The component you're testing
  ❌ Simple utilities you control (test them directly)
  ❌ React itself, RTL, or other test utilities

2. JEST.FN() — MOCK FUNCTIONS
================================================================================

jest.fn() creates a mock function that:
  - Returns undefined by default
  - Records every call (arguments, return values, this context)
  - Can have implementations or return values configured

BASIC USAGE:
  const mockCallback = jest.fn();

  // Call it
  mockCallback('hello', 42);
  mockCallback('world');

  // Inspect calls
  console.log(mockCallback.mock.calls);
  // [['hello', 42], ['world']]

  console.log(mockCallback.mock.results);
  // [{ type: 'return', value: undefined }, ...]

  console.log(mockCallback.mock.calls.length);
  // 2

ASSERTIONS:
  expect(mockCallback).toHaveBeenCalled();
  expect(mockCallback).toHaveBeenCalledTimes(2);
  expect(mockCallback).toHaveBeenCalledWith('hello', 42);
  expect(mockCallback).toHaveBeenLastCalledWith('world');
  expect(mockCallback).toHaveBeenNthCalledWith(1, 'hello', 42);

MOCK FUNCTION AS A PROP:
  it('calls onSubmit when form is submitted', async () => {
    const mockOnSubmit = jest.fn();
    render(<LoginForm onSubmit={mockOnSubmit} />);

    await userEvent.click(screen.getByRole('button', { name: /submit/i }));

    expect(mockOnSubmit).toHaveBeenCalledOnce();
    expect(mockOnSubmit).toHaveBeenCalledWith({
      email: expect.any(String),
      password: expect.any(String),
    });
  });

THE .MOCK PROPERTY:
  mockFn.mock.calls         // Array of arrays of arguments per call
  mockFn.mock.results       // Array of { type: 'return'|'throw', value }
  mockFn.mock.instances     // Array of `this` context for each call
  mockFn.mock.lastCall      // Arguments of the most recent call
  mockFn.mock.calls[0][0]   // First argument of the first call

3. JEST.MOCK() — MODULE MOCKING
================================================================================

jest.mock() replaces an entire module with a mock version.
It is AUTOMATICALLY HOISTED to the top of the file by Babel/ts-jest,
so you can reference mock functions defined later.

AUTO-MOCKING (replace all exports with jest.fn()):
  jest.mock('./userService');
  // All exports become jest.fn() returning undefined

  // Now configure return values:
  import { getUser } from './userService';
  (getUser as jest.Mock).mockResolvedValue({ id: 1, name: 'Alice' });

FACTORY FUNCTION MOCK (provide custom implementation):
  jest.mock('./auth', () => ({
    login: jest.fn(),
    logout: jest.fn(),
    getToken: jest.fn().mockReturnValue('mock-token'),
    isAuthenticated: jest.fn().mockReturnValue(true),
  }));

PARTIAL MOCK (keep some real implementations):
  jest.mock('./utils', () => ({
    ...jest.requireActual('./utils'),  // Keep all real implementations
    formatDate: jest.fn().mockReturnValue('2024-01-01'), // Override only this one
  }));

MOCKING DEFAULT EXPORTS:
  jest.mock('./MyComponent', () => {
    const MockMyComponent = ({ children }) => <div>{children}</div>;
    MockMyComponent.displayName = 'MockMyComponent';
    return { default: MockMyComponent };
  });

  // Or using __esModule:
  jest.mock('./config', () => ({
    __esModule: true,
    default: { apiUrl: 'http://localhost:3000' },
  }));

SCOPING WITHIN A TEST:
  // jest.mock() applies for the ENTIRE file
  // To override for a specific test, use mockImplementationOnce() or
  // reassign the mock inside the test

IMPORTANT: jest.mock() is hoisted regardless of where you write it.
  import { getUser } from './userService';
  jest.mock('./userService'); // This actually executes FIRST, before the import

  // This works because of hoisting:
  const mockGetUser = getUser as jest.Mock;

4. JEST.SPYON() — SPYING ON EXISTING FUNCTIONS
================================================================================

jest.spyOn() creates a spy on an EXISTING object method.
Unlike jest.mock(), the original implementation is preserved by default.

BASIC USAGE:
  const spy = jest.spyOn(object, 'methodName');

EXAMPLES:
  // Spy on a class method
  const consoleSpy = jest.spyOn(console, 'error').mockImplementation(() => {});
  // Suppress console.error in tests, then verify it was called:
  expect(consoleSpy).toHaveBeenCalledWith(expect.stringContaining('error'));
  consoleSpy.mockRestore(); // Restore original console.error

  // Spy on a module export
  import * as userModule from './userService';
  const getUserSpy = jest.spyOn(userModule, 'getUser');
  getUserSpy.mockResolvedValue({ id: 1, name: 'Alice' });

  // Spy on a class instance method
  const instance = new MyClass();
  const methodSpy = jest.spyOn(instance, 'doSomething');
  methodSpy.mockReturnValue('mocked value');
  instance.doSomething();
  expect(methodSpy).toHaveBeenCalled();
  methodSpy.mockRestore();

SPY WITHOUT CHANGING BEHAVIOR:
  // Track calls without replacing the real implementation
  const fetchSpy = jest.spyOn(window, 'fetch');
  // fetchSpy records calls but still calls real fetch

  // Verify real fetch was called with correct URL:
  expect(fetchSpy).toHaveBeenCalledWith(
    expect.stringContaining('/api/users'),
    expect.objectContaining({ method: 'GET' })
  );

MOCKING GETTERS:
  const mockDate = new Date('2024-01-15');
  jest.spyOn(global, 'Date').mockImplementation(() => mockDate as any);

  // Or mock a property getter:
  jest.spyOn(navigator, 'onLine', 'get').mockReturnValue(false);

5. MANUAL MOCKS (__MOCKS__ DIRECTORY)
================================================================================

Manual mocks are files you create to replace modules automatically.

DIRECTORY STRUCTURE:
  src/
    __mocks__/
      axios.ts          ← Mocks node_modules/axios (sibling to node_modules)
      fileMock.ts       ← Mocks static files
    services/
      __mocks__/
        userService.ts  ← Mocks ./services/userService
    components/

MANUAL MOCK EXAMPLE (axios):
  // src/__mocks__/axios.ts
  const axios = {
    get: jest.fn(),
    post: jest.fn(),
    put: jest.fn(),
    delete: jest.fn(),
    create: jest.fn().mockReturnThis(),
    interceptors: {
      request: { use: jest.fn(), eject: jest.fn() },
      response: { use: jest.fn(), eject: jest.fn() },
    },
    defaults: { headers: { common: {} } },
  };
  export default axios;

ACTIVATING MANUAL MOCKS:
  - For node_modules: Auto-activated when jest.mock('moduleName') is called
  - For user modules: Must call jest.mock('./path/to/module')

FILE MOCK (for imports of non-JS files):
  // src/__mocks__/fileMock.ts
  export default 'test-file-stub';

  // SVG with React component support:
  // src/__mocks__/svgMock.tsx
  import React from 'react';
  const SvgMock = (props) => <svg {...props} />;
  export const ReactComponent = SvgMock;
  export default 'test-file-stub';

6. MOCKING RETURN VALUES
================================================================================

mockReturnValue(value)
  → Always returns the same value
  const mock = jest.fn().mockReturnValue(42);
  mock(); // 42
  mock(); // 42

mockReturnValueOnce(value)
  → Returns value ONCE, then falls back
  const mock = jest.fn()
    .mockReturnValueOnce('first')
    .mockReturnValueOnce('second')
    .mockReturnValue('default');

  mock(); // 'first'
  mock(); // 'second'
  mock(); // 'default'
  mock(); // 'default'

mockResolvedValue(value)
  → Returns a resolved Promise (for async functions)
  const mockFetch = jest.fn().mockResolvedValue({ data: [], status: 200 });
  const result = await mockFetch();
  // result = { data: [], status: 200 }

mockResolvedValueOnce(value)
  → Resolved Promise, once only
  jest.fn()
    .mockResolvedValueOnce({ users: [] })
    .mockResolvedValueOnce({ users: [{ id: 1 }] });

mockRejectedValue(error)
  → Returns a rejected Promise (simulates errors)
  const mockFetch = jest.fn().mockRejectedValue(new Error('Network Error'));
  await expect(mockFetch()).rejects.toThrow('Network Error');

mockRejectedValueOnce(error)
  → Rejected Promise, once only

7. MOCKING IMPLEMENTATIONS
================================================================================

mockImplementation(fn)
  → Provides a custom implementation function
  const mock = jest.fn().mockImplementation((x) => x * 2);
  mock(5); // 10

mockImplementationOnce(fn)
  → Custom implementation for ONE call
  const mock = jest.fn()
    .mockImplementationOnce(() => 'loading...')
    .mockImplementation(() => 'loaded!');

  mock(); // 'loading...'
  mock(); // 'loaded!'
  mock(); // 'loaded!'

PRACTICAL EXAMPLES:

  // Mock a function that filters data:
  const mockFilter = jest.fn().mockImplementation((items, query) =>
    items.filter(item => item.name.includes(query))
  );

  // Mock a function that throws on specific input:
  const mockValidate = jest.fn().mockImplementation((data) => {
    if (!data.email) throw new Error('Email required');
    return true;
  });

  // Mock setTimeout:
  jest.useFakeTimers();
  const callback = jest.fn();
  setTimeout(callback, 1000);
  jest.advanceTimersByTime(1000);
  expect(callback).toHaveBeenCalled();

MOCKING CLASSES:
  jest.mock('./UserService', () => {
    return jest.fn().mockImplementation(() => ({
      getUser: jest.fn().mockResolvedValue({ id: 1, name: 'Alice' }),
      createUser: jest.fn().mockResolvedValue({ id: 2, name: 'Bob' }),
    }));
  });

  // Then in test:
  const UserService = require('./UserService');
  const instance = new UserService();
  expect(instance.getUser).toBeDefined();

8. CLEARING, RESETTING, AND RESTORING MOCKS
================================================================================

There are three different levels of cleanup:

LEVEL 1: mockFn.mockClear()
  → Clears: call history (mock.calls, mock.instances, mock.results)
  → Does NOT reset: implementation or return values
  → Use when: You want to verify calls in isolation but keep the mock behavior

  const mock = jest.fn().mockReturnValue('hello');
  mock('first');
  mock.mockClear();
  expect(mock.mock.calls.length).toBe(0); // Cleared
  mock('second');
  expect(mock).toReturnWith('hello'); // Implementation kept

LEVEL 2: mockFn.mockReset()
  → Clears: call history AND implementations/return values
  → Does NOT restore: original implementation (for spies)
  → Use when: You want a completely clean mock for the next test

  const mock = jest.fn().mockReturnValue('hello');
  mock.mockReset();
  mock(); // Returns undefined (implementation cleared)

LEVEL 3: mockFn.mockRestore()
  → Only works on jest.spyOn() spies
  → Restores the original implementation
  → Use when: You're done spying and want real behavior back

  const consoleSpy = jest.spyOn(console, 'error').mockImplementation(() => {});
  // ... test that triggers console.error ...
  consoleSpy.mockRestore(); // console.error works normally again

GLOBAL CLEANUP METHODS:
  jest.clearAllMocks()    → Equivalent to calling .mockClear() on all mocks
  jest.resetAllMocks()    → Equivalent to calling .mockReset() on all mocks
  jest.restoreAllMocks()  → Equivalent to calling .mockRestore() on all spies

RECOMMENDED GLOBAL SETUP:
  // In jest.config.ts:
  clearMocks: true,     // clearAllMocks after each test (recommended)
  // OR
  resetMocks: true,     // resetAllMocks after each test
  // OR
  restoreMocks: true,   // restoreAllMocks after each test

  // In setupTests.ts (if not using config):
  afterEach(() => {
    jest.clearAllMocks();  // Most commonly used
  });

9. MOCKING MODULES: COMMON PATTERNS
================================================================================

MOCKING REACT ROUTER:
  jest.mock('react-router-dom', () => ({
    ...jest.requireActual('react-router-dom'),
    useNavigate: () => mockNavigate,
    useParams: () => ({ id: '123' }),
    useLocation: () => ({ pathname: '/products/123', search: '', state: null }),
  }));

  const mockNavigate = jest.fn();

MOCKING NEXT.JS ROUTER:
  jest.mock('next/router', () => ({
    useRouter: () => ({
      push: jest.fn(),
      replace: jest.fn(),
      back: jest.fn(),
      pathname: '/test',
      query: {},
      asPath: '/test',
      isReady: true,
    }),
  }));

MOCKING ENVIRONMENT VARIABLES:
  // jest.config.ts
  testEnvironmentOptions: {
    env: { NODE_ENV: 'test', NEXT_PUBLIC_API_URL: 'http://test.com' }
  }

  // Or in a test:
  const originalEnv = process.env;
  beforeEach(() => {
    process.env = { ...originalEnv, FEATURE_FLAG: 'true' };
  });
  afterEach(() => {
    process.env = originalEnv;
  });

MOCKING DATE:
  const mockDate = new Date('2024-01-15T10:00:00Z');
  jest.useFakeTimers().setSystemTime(mockDate);

  // After tests:
  jest.useRealTimers();

MOCKING WINDOW METHODS:
  // localStorage
  const localStorageMock = (() => {
    let store: Record<string, string> = {};
    return {
      getItem: jest.fn((key) => store[key] ?? null),
      setItem: jest.fn((key, value) => { store[key] = String(value); }),
      removeItem: jest.fn((key) => { delete store[key]; }),
      clear: jest.fn(() => { store = {}; }),
    };
  })();
  Object.defineProperty(window, 'localStorage', { value: localStorageMock });

  // window.location
  delete (window as any).location;
  window.location = { ...window.location, href: 'http://localhost/', assign: jest.fn() };

MOCKING THIRD-PARTY LIBRARIES:
  // Stripe.js
  jest.mock('@stripe/stripe-js', () => ({
    loadStripe: jest.fn().mockResolvedValue({
      elements: jest.fn().mockReturnValue({
        create: jest.fn().mockReturnValue({ mount: jest.fn() }),
      }),
      confirmCardPayment: jest.fn().mockResolvedValue({ paymentIntent: { status: 'succeeded' } }),
    }),
  }));

10. MOCKING ES MODULES
================================================================================

ES Modules (import/export) have different mocking behavior than CommonJS.

ISSUE: jest.mock() works differently with native ESM.
Jest's default behavior transforms ES modules to CommonJS via Babel/ts-jest,
so most of the time jest.mock() works fine.

NATIVE ESM (experimental):
  If using "type": "module" in package.json AND --experimental-vm-modules:
  - Use jest.unstable_mockModule() instead of jest.mock()
  - Dynamic imports must be used in tests

WORKAROUND WITH BABEL (most common):
  Just ensure @babel/preset-env has { modules: 'commonjs' } or
  ts-jest handles the transformation.

MOCK NAMED EXPORTS:
  // module.ts
  export const add = (a, b) => a + b;
  export const multiply = (a, b) => a * b;

  // In test:
  jest.mock('./module', () => ({
    add: jest.fn().mockReturnValue(5),
    multiply: jest.fn().mockReturnValue(10),
  }));

MOCK DEFAULT + NAMED EXPORTS:
  jest.mock('./auth', () => ({
    __esModule: true,                          // Required for default exports
    default: jest.fn(),                        // Default export mock
    getToken: jest.fn().mockReturnValue('abc'), // Named export mock
  }));
