1. WHY ASYNC TESTING IS DIFFERENT
================================================================================

Synchronous tests execute completely in a single tick.
Async tests involve operations that complete in the future (promises, timers).

THE CORE PROBLEM:
  If you don't properly handle async operations, tests will:
  - Complete before the async code finishes
  - Show false positives (test passes but nothing was actually tested)
  - Show confusing "cannot read property of undefined" errors

BASIC EXAMPLE OF THE PROBLEM:
  // ❌ WRONG — test completes before fetch resolves
  it('fetches user data', () => {
    fetchUser(1).then(user => {
      expect(user.name).toBe('Alice'); // Never actually executed!
    });
  });
  // This test will ALWAYS pass because Jest doesn't wait for the Promise!

  // ✅ CORRECT — return the Promise or use async/await
  it('fetches user data', async () => {
    const user = await fetchUser(1);
    expect(user.name).toBe('Alice');
  });

2. RETURNING PROMISES
================================================================================

If you return a Promise from a test, Jest will wait for it to resolve or reject.

  it('resolves with user data', () => {
    // Return the Promise — Jest waits for it
    return fetchUser(1).then(user => {
      expect(user.name).toBe('Alice');
    });
  });

  it('rejects when user not found', () => {
    return expect(fetchUser(999)).rejects.toThrow('User not found');
  });

  // Chained promises:
  it('fetches and transforms data', () => {
    return fetchProducts()
      .then(products => products.map(p => p.name))
      .then(names => {
        expect(names).toContain('Widget');
      });
  });

WARNING: If you forget return and the promise rejects, the test may pass
         because Jest doesn't know about the unhandled rejection.

3. ASYNC/AWAIT PATTERN (RECOMMENDED)
================================================================================

Using async/await is the clearest and most readable approach.

  it('fetches user data', async () => {
    const user = await fetchUser(1);
    expect(user.name).toBe('Alice');
    expect(user.role).toBe('admin');
  });

  it('handles fetch errors', async () => {
    await expect(fetchUser(999)).rejects.toThrow('User not found');
  });

REAL-WORLD ASYNC TEST EXAMPLES:

  // Testing an API service
  it('getProducts returns array of products', async () => {
    // Arrange
    server.use(
      http.get('/api/products', () =>
        HttpResponse.json([{ id: 1, name: 'Widget' }])
      )
    );

    // Act
    const products = await getProducts();

    // Assert
    expect(products).toHaveLength(1);
    expect(products[0]).toMatchObject({ id: 1, name: 'Widget' });
  });

  // Testing error handling
  it('getUser throws error when API fails', async () => {
    server.use(
      http.get('/api/users/:id', () =>
        new HttpResponse(null, { status: 500 })
      )
    );

    await expect(getUser('1')).rejects.toThrow(/server error/i);
  });

MULTIPLE AWAITS IN ONE TEST:
  it('creates and then fetches a user', async () => {
    const created = await createUser({ name: 'Bob', email: 'bob@test.com' });
    expect(created.id).toBeDefined();

    const fetched = await getUser(created.id);
    expect(fetched.name).toBe('Bob');
  });

4. RESOLVES AND REJECTS MATCHERS
================================================================================

Jest provides .resolves and .rejects for asserting promise outcomes inline.

.RESOLVES:
  it('resolves with user', async () => {
    await expect(fetchUser(1)).resolves.toEqual({ id: 1, name: 'Alice' });
    await expect(fetchUser(1)).resolves.toMatchObject({ name: 'Alice' });
    await expect(fetchUser(1)).resolves.toBeDefined();
  });

.REJECTS:
  it('rejects with error', async () => {
    await expect(fetchUser(999)).rejects.toThrow('User not found');
    await expect(fetchUser(999)).rejects.toThrow(Error);
    await expect(fetchUser(999)).rejects.toMatchObject({
      message: 'User not found',
      statusCode: 404,
    });
  });

IMPORTANT: Always await .resolves and .rejects:
  // ❌ WRONG — test completes before promise settles
  expect(fetchUser(1)).resolves.toBe('Alice');

  // ✅ CORRECT
  await expect(fetchUser(1)).resolves.toBe('Alice');

USING WITH EXPECT.ASSERTIONS:
  When testing async errors, use expect.assertions(n) to ensure
  your assertion actually ran:

  it('handles error response', async () => {
    expect.assertions(1); // Ensures exactly 1 assertion ran
    try {
      await fetchUser(999);
    } catch (error) {
      expect(error.message).toBe('User not found');
    }
  });

  // Without expect.assertions, if the code doesn't throw,
  // the catch block is skipped and the test passes vacuously!

5. CALLBACK-BASED ASYNC (Legacy Pattern)
================================================================================

For code that uses callbacks rather than promises (older APIs, Node.js events):

  // Callback-based function:
  function getUser(id, callback) {
    setTimeout(() => {
      if (id === 1) callback(null, { id: 1, name: 'Alice' });
      else callback(new Error('Not found'), null);
    }, 100);
  }

  // Testing with done():
  it('calls callback with user data', (done) => {
    getUser(1, (error, user) => {
      expect(error).toBeNull();
      expect(user.name).toBe('Alice');
      done(); // Signal that the test is complete
    });
  });

  it('calls callback with error for unknown user', (done) => {
    getUser(999, (error, user) => {
      expect(error).not.toBeNull();
      expect(error.message).toBe('Not found');
      expect(user).toBeNull();
      done();
    });
  });

PROMISIFYING CALLBACKS FOR CLEANER TESTS:
  // Promisify the function first, then test with async/await
  function getUserAsync(id): Promise<User> {
    return new Promise((resolve, reject) => {
      getUser(id, (error, user) => {
        if (error) reject(error);
        else resolve(user);
      });
    });
  }

  it('gets user', async () => {
    const user = await getUserAsync(1);
    expect(user.name).toBe('Alice');
  });

6. DONE() CALLBACK
================================================================================

The done() callback tells Jest that an async test is complete.

BASIC USAGE:
  it('async test with done', (done) => {
    setTimeout(() => {
      expect(1 + 1).toBe(2);
      done(); // Test complete
    }, 100);
  });

ERROR HANDLING WITH DONE:
  If you pass an error to done(), Jest marks the test as failed:

  it('async test with error handling', (done) => {
    asyncOperation((error, result) => {
      if (error) {
        done(error); // Marks test as FAILED with the error
        return;
      }
      expect(result).toBe('expected');
      done(); // Marks test as PASSED
    });
  });

TIMEOUT WITH DONE:
  If done() is never called, Jest times out after testTimeout (default 5000ms):

  // jest.config.ts: testTimeout: 10000
  // Or per-test:
  it('slow async test', (done) => {
    // ... slow operation
    done();
  }, 10000); // 10 second timeout for this specific test

IMPORTANT: Don't mix async/await with done():
  ❌ WRONG:
    it('broken test', async (done) => {
      const result = await fetch('/api');
      expect(result).toBeDefined();
      done();
    });

  ✅ Just use async/await alone:
    it('correct test', async () => {
      const result = await fetch('/api');
      expect(result).toBeDefined();
    });

7. MOCKING ASYNC FUNCTIONS
================================================================================

MOCK RESOLVED VALUE:
  const mockFetchUser = jest.fn().mockResolvedValue({
    id: 1, name: 'Alice', role: 'admin'
  });

  it('displays user name', async () => {
    render(<UserProfile fetchUser={mockFetchUser} userId={1} />);
    expect(await screen.findByText('Alice')).toBeInTheDocument();
  });

MOCK REJECTED VALUE (ERROR SIMULATION):
  const mockFetchUser = jest.fn().mockRejectedValue(
    new Error('Failed to load user')
  );

  it('shows error when fetch fails', async () => {
    render(<UserProfile fetchUser={mockFetchUser} userId={1} />);
    expect(await screen.findByRole('alert')).toHaveTextContent('Failed to load user');
  });

MOCK DIFFERENT RESPONSES SEQUENTIALLY:
  const mockFetch = jest.fn()
    .mockResolvedValueOnce({ status: 'loading' })  // 1st call
    .mockResolvedValueOnce({ data: users })          // 2nd call
    .mockRejectedValueOnce(new Error('Network'));    // 3rd call

MOCK WITH DELAY (simulate slow network):
  const mockSlowFetch = jest.fn().mockImplementation(() =>
    new Promise(resolve => setTimeout(() => resolve({ data: 'ok' }), 200))
  );

  // Use fake timers to control timing:
  jest.useFakeTimers();
  const fetchPromise = mockSlowFetch();
  jest.advanceTimersByTime(200);
  const result = await fetchPromise;

8. FAKE TIMERS
================================================================================

Jest can replace real timers with fake versions you control.
This lets you test code with setTimeout, setInterval, Date without waiting.

ENABLING FAKE TIMERS:
  jest.useFakeTimers();  // At top of test or in beforeEach

  // Reset after tests:
  jest.useRealTimers();

FAKE TIMER METHODS:
  jest.advanceTimersByTime(ms)  → Fast-forward by ms
  jest.runAllTimers()           → Run all pending timers to completion
  jest.runOnlyPendingTimers()   → Run only currently pending timers
  jest.clearAllTimers()         → Remove all pending timers
  jest.getTimerCount()          → How many timers are pending

TESTING DEBOUNCE:
  // A debounced function waits 300ms after last call before executing
  it('debounces search input', () => {
    jest.useFakeTimers();
    const mockSearch = jest.fn();
    const debouncedSearch = debounce(mockSearch, 300);

    debouncedSearch('h');
    debouncedSearch('he');
    debouncedSearch('hel');

    expect(mockSearch).not.toHaveBeenCalled(); // Not yet!

    jest.advanceTimersByTime(300);
    expect(mockSearch).toHaveBeenCalledTimes(1); // Called once!
    expect(mockSearch).toHaveBeenCalledWith('hel');
  });

TESTING POLLING / INTERVALS:
  it('polls API every 5 seconds', () => {
    jest.useFakeTimers();
    const mockPoll = jest.fn().mockResolvedValue({ data: [] });
    startPolling(mockPoll, 5000);

    expect(mockPoll).toHaveBeenCalledTimes(1); // Initial call

    jest.advanceTimersByTime(5000);
    expect(mockPoll).toHaveBeenCalledTimes(2);

    jest.advanceTimersByTime(10000);
    expect(mockPoll).toHaveBeenCalledTimes(4);
  });

MOCKING DATE WITH FAKE TIMERS:
  it('shows correct date', () => {
    jest.useFakeTimers();
    jest.setSystemTime(new Date('2024-01-15T10:00:00Z'));

    render(<DateDisplay />);
    expect(screen.getByText('January 15, 2024')).toBeInTheDocument();

    jest.useRealTimers();
  });

FAKE TIMERS WITH ASYNC CODE:
  it('shows loading state then content', async () => {
    jest.useFakeTimers();

    render(<AsyncComponent delay={1000} />);
    expect(screen.getByRole('progressbar')).toBeInTheDocument();

    // Advance time AND flush promises:
    await act(async () => {
      jest.advanceTimersByTime(1000);
    });

    expect(screen.queryByRole('progressbar')).not.toBeInTheDocument();
    expect(screen.getByText('Content loaded')).toBeInTheDocument();
  });

9. COMMON ASYNC PITFALLS
================================================================================

PITFALL 1: Forgetting to await
  ❌ expect(asyncFn()).resolves.toBe(true); // Missing await
  ✅ await expect(asyncFn()).resolves.toBe(true);

PITFALL 2: Not returning the Promise
  ❌ it('test', () => { asyncFn().then(r => expect(r).toBe(1)); });
  ✅ it('test', () => { return asyncFn().then(r => expect(r).toBe(1)); });
  ✅ it('test', async () => { const r = await asyncFn(); expect(r).toBe(1); });

PITFALL 3: Mixing async/await and done()
  ❌ it('bad', async (done) => { await asyncFn(); done(); });
  ✅ it('good', async () => { await asyncFn(); });

PITFALL 4: Not asserting in try/catch
  ❌ it('catches errors', async () => {
       try { await failingFn(); } catch (e) { /* forgot expect! */ }
     });
     // This passes even if no error is thrown!

  ✅ it('catches errors', async () => {
       expect.assertions(1); // Forces at least 1 assertion
       try {
         await failingFn();
       } catch (e) {
         expect(e.message).toBe('expected error');
       }
     });

PITFALL 5: Test completes before assertion
  ❌ it('updates UI', () => {
       userEvent.click(button); // async but not awaited
       expect(screen.getByText('Updated')).toBeInTheDocument(); // runs too early
     });

  ✅ it('updates UI', async () => {
       await userEvent.click(button);
       expect(await screen.findByText('Updated')).toBeInTheDocument();
     });

PITFALL 6: Open handles (test doesn't stop)
  If Jest warns about "open handles", you have async operations that
  didn't complete:
  - Close server connections in afterAll
  - Clear intervals/timeouts in afterEach
  - Call jest.useRealTimers() if using fake timers

  Use --detectOpenHandles flag to find the culprit:
  npx jest --detectOpenHandles

10. ASYNC TESTING PATTERNS REFERENCE
================================================================================

─────────────────────────────────────────────────────────────────────────────
PATTERN                           WHEN TO USE
─────────────────────────────────────────────────────────────────────────────
async/await                       Always preferred for clarity

await expect(fn()).resolves       Assert resolved promise value

await expect(fn()).rejects        Assert rejected promise

expect.assertions(n)             Ensure async assertions ran

done() callback                  Legacy callbacks (event emitters, old APIs)

jest.useFakeTimers()             setTimeout, setInterval, Date testing

jest.advanceTimersByTime(ms)     Fast-forward fake timers

jest.runAllTimers()              Complete all pending timers at once

await act(async () => {...})     Flush async state updates in RTL

await screen.findByText(...)     Wait for element to appear in DOM

await waitFor(() => {...})       Wait for any condition to become true

await waitForElementToBeRemoved  Wait for element to disappear
─────────────────────────────────────────────────────────────────────────────


COMPLETE ASYNC TEST EXAMPLE:
  import { render, screen, waitFor } from '@testing-library/react';
  import userEvent from '@testing-library/user-event';
  import { http, HttpResponse } from 'msw';
  import { server } from '../mocks/server';
  import UserDashboard from './UserDashboard';

  describe('UserDashboard', () => {
    it('loads and displays user data', async () => {
      // Arrange: Setup mock API
      server.use(
        http.get('/api/user', () =>
          HttpResponse.json({ name: 'Alice', role: 'admin' })
        )
      );

      // Act: Render the component
      render(<UserDashboard userId="1" />);

      // Assert: Loading state first
      expect(screen.getByRole('progressbar')).toBeInTheDocument();

      // Assert: Data loads
      expect(await screen.findByText('Alice')).toBeInTheDocument();
      expect(screen.getByText('admin')).toBeInTheDocument();
      expect(screen.queryByRole('progressbar')).not.toBeInTheDocument();
    });

    it('shows error when API fails', async () => {
      server.use(
        http.get('/api/user', () =>
          new HttpResponse(null, { status: 500 })
        )
      );

      render(<UserDashboard userId="1" />);

      const errorAlert = await screen.findByRole('alert');
      expect(errorAlert).toHaveTextContent(/something went wrong/i);
    });

    it('handles refresh button click', async () => {
      const user = userEvent.setup();
      let callCount = 0;

      server.use(
        http.get('/api/user', () => {
          callCount++;
          return HttpResponse.json({ name: 'Alice', callCount });
        })
      );

      render(<UserDashboard userId="1" />);
      await screen.findByText('Alice');

      expect(callCount).toBe(1);

      await user.click(screen.getByRole('button', { name: /refresh/i }));

      await waitFor(() => expect(callCount).toBe(2));
    });
  });
