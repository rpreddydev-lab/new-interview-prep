================================================================
AUTH0 INTEGRATION WITH REACT
================================================================

Auth0 is a cloud-based Identity-as-a-Service (IDaaS) platform
that implements OAuth2 + OpenID Connect. It handles authentication,
MFA, social login, and user management as a managed service.

================================================================
1. WHY AUTH0?
================================================================

Pros:
  ✅ No need to set up/maintain your own auth server
  ✅ Social login providers built-in (Google, GitHub, Apple, etc.)
  ✅ MFA support out of the box
  ✅ PKCE flow handled by the SDK
  ✅ Generous free tier
  ✅ Excellent documentation and React SDK

Cons:
  ❌ Third-party dependency / vendor lock-in
  ❌ Cost at scale
  ❌ Data hosted by Auth0 (compliance concerns for some enterprises)

3. AUTH0 DASHBOARD SETUP
================================================================

1. Create an account at auth0.com
2. Create an Application: Single Page Application (SPA)
3. Note down:
   - Domain: dev-xxxx.us.auth0.com
   - Client ID: xxxx
4. Set Allowed Callback URLs: http://localhost:3000
5. Set Allowed Logout URLs: http://localhost:3000
6. Set Allowed Web Origins: http://localhost:3000
7. Create an API: set identifier (audience), e.g. https://api.example.com

================================================================
4. SETUP IN REACT
================================================================

FILE: .env
  VITE_AUTH0_DOMAIN=dev-xxxx.us.auth0.com
  VITE_AUTH0_CLIENT_ID=your-client-id
  VITE_AUTH0_AUDIENCE=https://api.example.com

FILE: src/main.jsx
  import { Auth0Provider } from '@auth0/auth0-react';
  import { useNavigate } from 'react-router-dom';

  function Auth0ProviderWithNavigate({ children }) {
    const navigate = useNavigate();

    const onRedirectCallback = (appState) => {
      navigate(appState?.returnTo || window.location.pathname);
    };

    return (
      <Auth0Provider
        domain={import.meta.env.VITE_AUTH0_DOMAIN}
        clientId={import.meta.env.VITE_AUTH0_CLIENT_ID}
        authorizationParams={{
          redirect_uri: window.location.origin,
          audience: import.meta.env.VITE_AUTH0_AUDIENCE,
          scope: 'openid profile email read:users',
        }}
        onRedirectCallback={onRedirectCallback}
        useRefreshTokens={true}           // enables silent refresh
        cacheLocation="memory"            // 'memory' (secure) or 'localstorage'
      >
        {children}
      </Auth0Provider>
    );
  }

  root.render(
    <BrowserRouter>
      <Auth0ProviderWithNavigate>
        <App />
      </Auth0ProviderWithNavigate>
    </BrowserRouter>
  );

6. LOGIN AND LOGOUT
================================================================

  // Basic login button
  function LoginButton() {
    const { loginWithRedirect } = useAuth0();
    return (
      <button onClick={() => loginWithRedirect()}>
        Sign In
      </button>
    );
  }

  // Login with specific connection (social)
  <button onClick={() => loginWithRedirect({
    authorizationParams: { connection: 'google-oauth2' }
  })}>
    Sign in with Google
  </button>

  // Login with pre-filled email
  <button onClick={() => loginWithRedirect({
    authorizationParams: { login_hint: 'user@company.com' }
  })}>
    Sign In
  </button>

  // Logout
  function LogoutButton() {
    const { logout } = useAuth0();
    return (
      <button onClick={() => logout({
        logoutParams: { returnTo: window.location.origin }
      })}>
        Sign Out
      </button>
    );
  }

7. GETTING THE ACCESS TOKEN FOR API CALLS
================================================================

  import { useAuth0 } from '@auth0/auth0-react';

  function UserProfile() {
    const { getAccessTokenSilently } = useAuth0();

    const fetchUserData = async () => {
      const token = await getAccessTokenSilently();
      // token is the opaque access token (or JWT if configured)
      const response = await fetch('/api/user', {
        headers: { Authorization: `Bearer ${token}` },
      });
      return response.json();
    };
  }

  getAccessTokenSilently():
    - Returns a cached token if still valid
    - Silently refreshes using refresh token / silent iframe if needed
    - Throws if refresh fails (user must re-login)
    - Use getAccessTokenSilently({ authorizationParams: { audience } })
      to get a token for a specific API

8. AXIOS INTEGRATION WITH AUTH0
================================================================

FILE: src/api/axiosConfig.js
  import axios from 'axios';
  // Auth0 getAccessTokenSilently can't be called outside React,
  // so we use a workaround: inject the function from a component

  const apiClient = axios.create({
    baseURL: import.meta.env.VITE_API_BASE_URL,
    timeout: 10_000,
  });

  export default apiClient;

FILE: src/api/AxiosSetup.jsx (Component to inject the Auth0 token function)
  import { useEffect } from 'react';
  import { useAuth0 } from '@auth0/auth0-react';
  import apiClient from './axiosConfig';

  export function AxiosSetup() {
    const { getAccessTokenSilently } = useAuth0();

    useEffect(() => {
      const interceptorId = apiClient.interceptors.request.use(async (config) => {
        try {
          const token = await getAccessTokenSilently();
          config.headers.Authorization = `Bearer ${token}`;
        } catch (e) {
          // Token refresh failed; request proceeds without auth
          console.error('Failed to get token', e);
        }
        return config;
      });

      return () => apiClient.interceptors.request.eject(interceptorId);
    }, [getAccessTokenSilently]);

    return null; // renders nothing
  }

  // Place in App.jsx:
  <AxiosSetup />

ALTERNATIVE: getAccessTokenSilently outside React (Auth0 SDK trick)
  Let the Auth0Provider store the function and access it outside hooks.

9. PROTECTED ROUTE WITH AUTH0
================================================================

  import { withAuthenticationRequired } from '@auth0/auth0-react';

  // Method 1: HOC
  const ProtectedDashboard = withAuthenticationRequired(Dashboard, {
    onRedirecting: () => <Spinner />,
  });

  <Route path="/dashboard" element={<ProtectedDashboard />} />

  // Method 2: Custom component (more control)
  import { useAuth0 } from '@auth0/auth0-react';
  import { Navigate, Outlet } from 'react-router-dom';

  function ProtectedRoute() {
    const { isAuthenticated, isLoading, loginWithRedirect } = useAuth0();

    if (isLoading) return <Spinner />;

    if (!isAuthenticated) {
      loginWithRedirect({
        appState: { returnTo: window.location.pathname },
      });
      return null;
    }

    return <Outlet />;
  }

10. ROLES/PERMISSIONS VIA AUTH0
================================================================

Auth0 permissions are configured in the Auth0 dashboard (API → Scopes → Permissions).
They are included in the access token if "Add Permissions in the Access Token" is enabled.

  // Decode access token (if JWT) or use getIdTokenClaims
  const { getIdTokenClaims } = useAuth0();
  const claims = await getIdTokenClaims();
  // claims['https://example.com/roles'] (custom claim via Action)

  // Add permissions to access token via Auth0 Action:
  // (Auth0 Dashboard → Actions → Library → Create Action → Login)
  exports.onExecutePostLogin = async (event, api) => {
    const namespace = 'https://api.example.com';
    if (event.authorization) {
      api.accessToken.setCustomClaim(`${namespace}/roles`, event.authorization.roles);
    }
  };

  // Then in React:
  const token = await getAccessTokenSilently();
  const decoded = jwtDecode(token);
  const roles = decoded['https://api.example.com/roles'] || [];

================================================================

Enterprise SSO        | Yes (SAML, OIDC)         | Yes (SAML, OIDC)
Customization         | Limited (Actions)        | Full control
Compliance            | SOC2, HIPAA (paid)       | Full control

12. INTERVIEW QUESTIONS
================================================================

Q: How does @auth0/auth0-react handle token refresh?
A: When using useRefreshTokens: true and cacheLocation: 'memory',
   Auth0 uses refresh token rotation. getAccessTokenSilently()
   automatically uses the cached token if valid, or silently refreshes
   using the refresh token. If refresh fails, it throws and the user
   must re-authenticate.

Q: What is the difference between cacheLocation 'memory' vs 'localstorage'?
A: memory: tokens stored in JavaScript variables, invisible to XSS,
   lost on page refresh (silent refresh restores them). localstorage:
   tokens survive refresh but are vulnerable to XSS. 'memory' is
   recommended for security. Pair with useRefreshTokens for seamless UX.

Q: How do you make API calls with Auth0 tokens in Axios?
A: Since Auth0 hooks only work inside React components, inject the
   getAccessTokenSilently function into an Axios interceptor via
   a setup component mounted in the app. The interceptor calls
   getAccessTokenSilently() before each request and attaches the
   Bearer token.

Q: What is withAuthenticationRequired?
A: A Higher-Order Component from @auth0/auth0-react that wraps any
   component and redirects to Auth0 login if not authenticated.
   When the user returns from Auth0, they are sent back to the
   original page. It also shows a loading component during auth.

Q: What audience parameter is for in Auth0?
A: The audience identifies WHICH API the access token is intended for.
   It's the API identifier configured in Auth0 dashboard. Without
   audience, Auth0 returns an opaque token. With audience, it returns
   a JWT that your API can verify. This enables multiple APIs with
   separate access control.
