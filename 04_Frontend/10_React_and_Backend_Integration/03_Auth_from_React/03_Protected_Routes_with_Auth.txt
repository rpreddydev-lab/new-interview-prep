================================================================
PROTECTED ROUTES WITH AUTH IN REACT
================================================================

Protected routes guard pages/components behind authentication.
Unauthenticated users are redirected to the login page.
Authorized routes also check roles/permissions.

================================================================
1. BASIC PROTECTED ROUTE
================================================================

The simplest approach: a wrapper component that checks auth state.

FILE: src/components/ProtectedRoute.jsx
  import { Navigate, Outlet } from 'react-router-dom';
  import { useAuth } from '../context/AuthContext';
  import Spinner from './Spinner';

  function ProtectedRoute() {
    const { user, loading } = useAuth();

    // Show spinner while checking auth (e.g., during silent refresh)
    if (loading) return <Spinner />;

    // Not authenticated → redirect to login
    if (!user) return <Navigate to="/login" replace />;

    // Authenticated → render child routes
    return <Outlet />;
  }

  export default ProtectedRoute;

FILE: src/App.jsx
  import { BrowserRouter, Routes, Route } from 'react-router-dom';
  import ProtectedRoute from './components/ProtectedRoute';
  import LoginPage from './pages/LoginPage';
  import Dashboard from './pages/Dashboard';
  import ProfilePage from './pages/ProfilePage';
  import AdminPage from './pages/AdminPage';

  function App() {
    return (
      <BrowserRouter>
        <Routes>
          {/* Public routes */}
          <Route path="/login" element={<LoginPage />} />
          <Route path="/register" element={<RegisterPage />} />

          {/* Protected routes — require authentication */}
          <Route element={<ProtectedRoute />}>
            <Route path="/dashboard" element={<Dashboard />} />
            <Route path="/profile" element={<ProfilePage />} />
          </Route>

          {/* Default */}
          <Route path="/" element={<Navigate to="/dashboard" replace />} />
        </Routes>
      </BrowserRouter>
    );
  }

2. ROLE-BASED PROTECTED ROUTE
================================================================

FILE: src/components/RoleRoute.jsx
  import { Navigate, Outlet } from 'react-router-dom';
  import { useAuth } from '../context/AuthContext';

  function RoleRoute({ allowedRoles }) {
    const { user, loading } = useAuth();

    if (loading) return <Spinner />;

    if (!user) return <Navigate to="/login" replace />;

    const hasRole = allowedRoles.some(role => user.roles?.includes(role));
    if (!hasRole) return <Navigate to="/forbidden" replace />;

    return <Outlet />;
  }

  export default RoleRoute;

USAGE:
  <Routes>
    {/* Any authenticated user */}
    <Route element={<ProtectedRoute />}>
      <Route path="/dashboard" element={<Dashboard />} />
    </Route>

    {/* Admin only */}
    <Route element={<RoleRoute allowedRoles={['ADMIN']} />}>
      <Route path="/admin" element={<AdminPage />} />
      <Route path="/admin/users" element={<UserManagement />} />
    </Route>

    {/* Admin or Manager */}
    <Route element={<RoleRoute allowedRoles={['ADMIN', 'MANAGER']} />}>
      <Route path="/reports" element={<ReportsPage />} />
    </Route>
  </Routes>

3. AUTH CONTEXT — FULL IMPLEMENTATION
================================================================

FILE: src/context/AuthContext.jsx
  import { createContext, useContext, useState, useEffect, useCallback } from 'react';
  import axios from 'axios';
  import { jwtDecode } from 'jwt-decode';

  let _accessToken = null;
  export const getToken = () => _accessToken;

  const AuthContext = createContext(null);

  export function AuthProvider({ children }) {
    const [user, setUser] = useState(null);
    const [loading, setLoading] = useState(true);

    const processToken = (token) => {
      _accessToken = token;
      const decoded = jwtDecode(token);
      setUser({
        id: decoded.sub,
        email: decoded.email,
        name: decoded.name,
        roles: decoded.roles ?? [],
      });
    };

    const login = useCallback(async (email, password) => {
      const { data } = await axios.post(
        '/api/auth/login',
        { email, password },
        { withCredentials: true }
      );
      processToken(data.accessToken);
    }, []);

    const logout = useCallback(async () => {
      try {
        await axios.post('/api/auth/logout', {}, { withCredentials: true });
      } catch {}
      _accessToken = null;
      setUser(null);
    }, []);

    useEffect(() => {
      // Silent refresh on mount
      axios.post('/api/auth/refresh', {}, { withCredentials: true })
        .then(({ data }) => processToken(data.accessToken))
        .catch(() => setUser(null))
        .finally(() => setLoading(false));

      // Forced logout from interceptor
      const onLogout = () => { _accessToken = null; setUser(null); };
      window.addEventListener('auth:logout', onLogout);
      return () => window.removeEventListener('auth:logout', onLogout);
    }, []);

    const hasRole = useCallback((role) =>
      user?.roles?.includes(role) ?? false, [user]);

    const hasAnyRole = useCallback((roles) =>
      roles.some(r => user?.roles?.includes(r)) ?? false, [user]);

    return (
      <AuthContext.Provider value={{
        user, loading, login, logout, hasRole, hasAnyRole,
        isAuthenticated: !!user,
      }}>
        {children}
      </AuthContext.Provider>
    );
  }

  export const useAuth = () => {
    const ctx = useContext(AuthContext);
    if (!ctx) throw new Error('useAuth must be used within AuthProvider');
    return ctx;
  };

4. SAVE "INTENDED DESTINATION" ON REDIRECT
================================================================

When an unauthenticated user visits /dashboard, redirect them to
/login, then send them BACK to /dashboard after successful login.

FILE: src/components/ProtectedRoute.jsx
  import { Navigate, Outlet, useLocation } from 'react-router-dom';
  import { useAuth } from '../context/AuthContext';

  function ProtectedRoute() {
    const { user, loading } = useAuth();
    const location = useLocation();

    if (loading) return <Spinner />;

    if (!user) {
      // Save current path in location state
      return <Navigate to="/login" state={{ from: location }} replace />;
    }

    return <Outlet />;
  }

FILE: src/pages/LoginPage.jsx
  import { useNavigate, useLocation } from 'react-router-dom';
  import { useAuth } from '../context/AuthContext';

  function LoginPage() {
    const { login } = useAuth();
    const navigate = useNavigate();
    const location = useLocation();
    const from = location.state?.from?.pathname || '/dashboard';

    const handleLogin = async (email, password) => {
      await login(email, password);
      navigate(from, { replace: true }); // ← redirect to original destination
    };

    return (
      <form onSubmit={...}>
        {/* email, password fields */}
      </form>
    );
  }

5. UI-LEVEL ROLE GUARDS (Show/Hide Components)
================================================================

  // Hide elements the user can't access
  function AdminMenu() {
    const { hasRole } = useAuth();

    return (
      <nav>
        <Link to="/dashboard">Dashboard</Link>
        {hasRole('ADMIN') && (
          <Link to="/admin">Admin Panel</Link>
        )}
        {hasRole('MANAGER') && (
          <Link to="/reports">Reports</Link>
        )}
      </nav>
    );
  }

  // Generic permission guard component
  function Can({ role, children, fallback = null }) {
    const { hasRole } = useAuth();
    return hasRole(role) ? children : fallback;
  }

  // Usage
  <Can role="ADMIN" fallback={<p>Access denied</p>}>
    <DeleteButton />
  </Can>

================================================================
7. ROUTE GUARDING STRATEGIES COMPARISON
================================================================

STRATEGY             | APPROACH                       | USE WHEN
---------------------|--------------------------------|-------------------
ProtectedRoute       | Redirect wrapper component     | All auth-required pages
RoleRoute            | Role-check wrapper              | Admin/role-specific pages
Component-level Can  | Conditionally render elements  | Partial UI hiding
enabled in useQuery  | Skip query when unauthenticated| Prevent data leaks
API 401 interceptor  | Redirect to login on token     | Session expiry

================================================================
8. INTERVIEW QUESTIONS
================================================================

Q: How do you implement protected routes in React Router v6?
A: Create a ProtectedRoute component that reads auth state from context.
   If loading (during silent refresh), show a spinner. If no user,
   return <Navigate to="/login" replace />. If authenticated, return
   <Outlet /> to render child routes. Nest the protected routes inside
   <Route element={<ProtectedRoute />}>.

Q: How do you redirect a user back to their intended page after login?
A: In the ProtectedRoute, pass the current location as state in the
   Navigate: <Navigate to="/login" state={{ from: location }} replace />.
   In the login page, read location.state?.from?.pathname and navigate
   there on successful login using navigate(from, { replace: true }).

Q: How do you handle roles in a React app?
A: Extract roles from the JWT payload (decoded in the auth context).
   Create a hasRole(role) function in the context. For routes, create
   a RoleRoute wrapper that checks if the user has any of the allowed roles.
   For UI, use a Can component or conditional rendering with hasRole().

Q: What happens if a user navigates directly to a protected route
   and the app is still refreshing the token on load?
A: The ProtectedRoute must show a loading state while the silent refresh
   is in progress. If it renders <Navigate to="/login"> before the refresh
   completes, the user gets incorrectly logged out. The loading state in
   AuthContext prevents this race condition.

Q: How do you clear cached data when a user logs out?
A: Call queryClient.clear() from React Query to clear all cached queries.
   This prevents data leakage where the next user (on a shared device) sees
   the previous user's data. Also clear any Zustand stores and token memory.
