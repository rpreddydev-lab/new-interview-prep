1. WHAT IS INDEXEDDB?
────────────────────────────────────────────────────────────────────────────────

  IndexedDB is a low-level, transactional, asynchronous NoSQL database
  built into the browser.

  Key features:
    ✓ Stores large amounts of structured data (including Blobs, Files)
    ✓ Asynchronous — non-blocking, event-driven
    ✓ Supports indexes for fast querying
    ✓ Transactional (ACID-like within a session)
    ✓ Available in Web Workers and Service Workers
    ✓ Same-origin restricted
    ✓ Storage quota: typically 60% of disk space (much larger than cookies/localStorage)

  When to use IndexedDB:
    • Large datasets (thousands of records)
    • Need for structured querying (indexes)
    • Offline-capable apps (with Service Workers)
    • Storing binary data (Blobs, ArrayBuffers)
    • Background workers needing storage

────────────────────────────────────────────────────────────────────────────────
2. CORE CONCEPTS
────────────────────────────────────────────────────────────────────────────────

  DATABASE:
    Top-level container. Has a name and version number.
    Opening a database creates it if it doesn't exist.

  OBJECT STORE:
    Equivalent to a "table" in a relational DB.
    Each store holds records (JS objects).
    Each record has a key.

  KEY:
    Unique identifier for a record in an object store.
    In-line key: key stored inside the record (e.g., id field)
    Out-of-line key: key provided separately (auto-generated or manual)
    Key generator: auto-increment integer keys

  INDEX:
    Alternative way to look up records by a property other than the key.
    Example: index on 'email' field → fast lookup by email.

  TRANSACTION:
    All operations happen within a transaction.
    Ensures data integrity — either all ops succeed or none do.
    Types: 'readonly', 'readwrite', 'versionchange'

  CURSOR:
    Used to iterate over multiple records in an object store or index.

3. OPENING A DATABASE
────────────────────────────────────────────────────────────────────────────────

  const request = indexedDB.open('MyDatabase', 1); // name, version

  request.onupgradeneeded = (event) => {
    const db = event.target.result;
    const oldVersion = event.oldVersion; // 0 if new
    const newVersion = event.newVersion; // current requested version

    // Create schema on first create or version upgrade
    if (oldVersion < 1) {
      const store = db.createObjectStore('users', {
        keyPath: 'id',           // use 'id' field as key
        autoIncrement: true      // auto-generate id
      });
      store.createIndex('email', 'email', { unique: true });
      store.createIndex('name', 'name', { unique: false });
    }
    // Add new stores in version 2
    if (oldVersion < 2) {
      db.createObjectStore('products', { keyPath: 'sku' });
    }
  };

  request.onsuccess = (event) => {
    const db = event.target.result;
    // db is the IDBDatabase instance — store it for later use
  };

  request.onerror = (event) => {
    console.error('IndexedDB error:', event.target.error);
  };

4. CRUD OPERATIONS
────────────────────────────────────────────────────────────────────────────────

  4.1 ADD (Create)
    function addUser(db, user) {
      const tx = db.transaction('users', 'readwrite');
      const store = tx.objectStore('users');
      const request = store.add(user); // fails if key already exists
      // OR: store.put(user); // add or update (upsert)
      
      request.onsuccess = () => console.log('Added:', request.result); // returns key
      request.onerror = () => console.error(request.error);
      tx.oncomplete = () => console.log('Transaction committed');
      tx.onerror = () => console.error('Transaction error:', tx.error);
    }

  4.2 GET (Read by key)
    function getUser(db, id) {
      return new Promise((resolve, reject) => {
        const tx = db.transaction('users', 'readonly');
        const store = tx.objectStore('users');
        const request = store.get(id);
        request.onsuccess = () => resolve(request.result);
        request.onerror = () => reject(request.error);
      });
    }

  4.3 GET by Index
    function getUserByEmail(db, email) {
      return new Promise((resolve, reject) => {
        const tx = db.transaction('users', 'readonly');
        const store = tx.objectStore('users');
        const index = store.index('email');
        const request = index.get(email);
        request.onsuccess = () => resolve(request.result);
        request.onerror = () => reject(request.error);
      });
    }

  4.4 GET ALL
    function getAllUsers(db) {
      return new Promise((resolve, reject) => {
        const tx = db.transaction('users', 'readonly');
        const store = tx.objectStore('users');
        const request = store.getAll();
        request.onsuccess = () => resolve(request.result);
        request.onerror = () => reject(request.error);
      });
    }

  4.5 UPDATE
    function updateUser(db, user) {
      return new Promise((resolve, reject) => {
        const tx = db.transaction('users', 'readwrite');
        const store = tx.objectStore('users');
        const request = store.put(user); // put: add or update
        request.onsuccess = () => resolve();
        request.onerror = () => reject(request.error);
      });
    }

  4.6 DELETE
    function deleteUser(db, id) {
      return new Promise((resolve, reject) => {
        const tx = db.transaction('users', 'readwrite');
        const store = tx.objectStore('users');
        const request = store.delete(id);
        request.onsuccess = () => resolve();
        request.onerror = () => reject(request.error);
      });
    }

  4.7 CURSOR (Iterate all records)
    function iterateUsers(db) {
      const tx = db.transaction('users', 'readonly');
      const store = tx.objectStore('users');
      const request = store.openCursor(); // or index.openCursor()
      
      request.onsuccess = (event) => {
        const cursor = event.target.result;
        if (cursor) {
          console.log(cursor.key, cursor.value);
          cursor.continue(); // advance to next record
        } else {
          console.log('All records processed');
        }
      };
    }

5. IDB WRAPPERS (Simplify the API)
────────────────────────────────────────────────────────────────────────────────

  Raw IndexedDB is verbose. Popular wrappers:

  idb (by Jake Archibald):
    import { openDB } from 'idb';
    
    const db = await openDB('MyDatabase', 1, {
      upgrade(db) {
        const store = db.createObjectStore('users', { keyPath: 'id', autoIncrement: true });
        store.createIndex('email', 'email', { unique: true });
      }
    });
    
    // Write
    await db.add('users', { name: 'Alice', email: 'alice@example.com' });
    
    // Read
    const user = await db.get('users', 1);
    
    // Read by index
    const user = await db.getFromIndex('users', 'email', 'alice@example.com');
    
    // All
    const users = await db.getAll('users');
    
    // Transaction
    const tx = db.transaction('users', 'readwrite');
    await tx.store.add({ name: 'Bob', email: 'bob@example.com' });
    await tx.done;

  Dexie.js:
    Another popular wrapper with a more ORM-like API.

6. RANGE QUERIES
────────────────────────────────────────────────────────────────────────────────

  IDBKeyRange lets you query ranges of keys:

    IDBKeyRange.only(value)        // equals value
    IDBKeyRange.lowerBound(x)      // >= x
    IDBKeyRange.lowerBound(x, true)// > x (exclusive)
    IDBKeyRange.upperBound(y)      // <= y
    IDBKeyRange.upperBound(y, true)// < y (exclusive)
    IDBKeyRange.bound(x, y)        // x <= key <= y
    IDBKeyRange.bound(x, y, true, true) // x < key < y

    Example: Get all users with age between 18 and 65
    const index = store.index('age');
    const range = IDBKeyRange.bound(18, 65);
    const request = index.openCursor(range);

7. TRANSACTIONS AND ACID PROPERTIES
────────────────────────────────────────────────────────────────────────────────

  Atomicity: All operations in a transaction succeed or all roll back.
  
  Transactions auto-commit when all their requests complete successfully.
  Transactions auto-abort if any request fails or the transaction errors.
  
  Transaction lifetime:
    Transactions are short-lived. They commit when there are no more
    pending requests. Long transactions (e.g., waiting for user input
    inside a transaction) will auto-commit and may fail.
    
    // WRONG: awaiting inside transaction — transaction may close
    const tx = db.transaction('users', 'readwrite');
    const user = await fetchFromAPI(); // transaction may expire here!
    tx.objectStore('users').add(user);
    
    // RIGHT: complete async work before opening transaction
    const user = await fetchFromAPI();
    const tx = db.transaction('users', 'readwrite');
    tx.objectStore('users').add(user);

8. VERSIONING AND SCHEMA MIGRATIONS
────────────────────────────────────────────────────────────────────────────────

  Schema changes require a version bump + onupgradeneeded handler.
  
  onupgradeneeded fires when:
    • Database opened for the first time (oldVersion=0)
    • Database version increases
  
  Multiple devices:
    If user has same app open on multiple tabs, upgrading will cause
    a "blocked" event. Old connection must close first.
    
    request.onblocked = () => {
      alert('Please close other tabs before upgrading');
    };
    
    // In the old connection:
    db.addEventListener('versionchange', () => {
      db.close();
      location.reload();
    });

9. INTERVIEW QUESTIONS & ANSWERS
────────────────────────────────────────────────────────────────────────────────

Q: What is IndexedDB and when would you use it over localStorage?
A: IndexedDB is an async, transactional, NoSQL browser database supporting
   large structured data, indexes, and Blobs. Use it over localStorage when
   you need: more than 5MB of data, async non-blocking I/O, indexes/querying,
   binary data storage, access from Web Workers or Service Workers, or offline
   app data for PWAs.

Q: What is a transaction in IndexedDB?
A: A transaction groups one or more database operations that should succeed or
   fail together. All reads and writes happen inside transactions. They have
   modes: 'readonly' (concurrent reads OK) or 'readwrite' (exclusive write
   lock). Transactions auto-commit when all requests complete and auto-abort
   on errors.

Q: What is onupgradeneeded and when does it fire?
A: It fires when a database is opened with a version higher than the stored
   version (including first-time creation where old version is 0). It's the
   ONLY place where you can create or delete object stores and indexes (schema
   migrations). Version must be an integer; incrementing the version triggers
   this handler.

Q: What is the difference between store.add() and store.put()?
A: add() will fail (throw ConstraintError) if a record with the same key
   already exists. put() will add a new record or overwrite an existing one
   (upsert behavior). Use add() for strict insert, put() for insert or update.

Q: How do indexes work in IndexedDB?
A: An index is a secondary key structure on an object store field.
   You create it in onupgradeneeded: store.createIndex('name', 'fieldName', {unique: false}).
   Then query via: store.index('name').get(value). This enables efficient
   lookup by any field, not just the primary key.

Q: Why is IndexedDB preferred in Service Workers over localStorage?
A: Service Workers run in a separate thread with no access to the window
   object, so localStorage (which is window-based and synchronous) is
   unavailable. IndexedDB is Promise-based, asynchronous, and accessible
   from any worker context, making it ideal for background operations in PWAs.

================================================================================
  KEY TAKEAWAYS
================================================================================
  • IndexedDB: async, transactional, NoSQL browser DB; large capacity
  • objectStore = table; key = primary key; index = secondary lookup
  • All operations happen inside transactions ('readonly' or 'readwrite')
  • onupgradeneeded = schema migration; fires when version increases
  • add() = strict insert; put() = upsert
  • Use wrappers (idb, Dexie) to avoid verbose raw API
  • Available in Web Workers & Service Workers (unlike localStorage)
