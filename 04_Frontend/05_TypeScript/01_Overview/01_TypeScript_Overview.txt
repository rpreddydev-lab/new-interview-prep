1. WHAT IS TYPESCRIPT?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

TypeScript is a STRONGLY TYPED, STATICALLY TYPED superset of JavaScript developed
and maintained by Microsoft (Anders Hejlsberg, 2012). It compiles down to plain
JavaScript and runs anywhere JavaScript runs (browsers, Node.js, Deno, etc.).

Key Characteristics:
  • Superset of JS   → every valid JS file is a valid TS file
  • Static typing    → types are checked at compile time, not runtime
  • Structural typing → type compatibility based on shape, not name
  • Type inference   → types can be auto-inferred without annotations
  • Open source      → Apache 2.0 license, GitHub: microsoft/TypeScript

2. WHY TYPESCRIPT? (THE BUSINESS CASE)

  ┌─────────────────────────────────────────────────────────────────────────┐
  │ JavaScript Problem              │ TypeScript Solution                  │
  ├─────────────────────────────────┼──────────────────────────────────────┤
  │ Runtime type errors             │ Caught at compile time               │

  • Self-documenting code (types serve as inline docs)
  • Superior tooling (VS Code, WebStorm powered by TS language server)
  • Safer refactoring in large codebases (Angular, Vue 3, NestJS all use TS)
  • Better team collaboration (explicit contracts via types)

3. HOW TYPESCRIPT WORKS — THE COMPILATION PIPELINE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  .ts / .tsx files
       │
       ▼
  ┌──────────────────────────────────────────────────────────┐
  │              TypeScript Compiler (tsc)                    │
  │                                                           │
  │  1. Scanner → Tokens                                      │
  │  2. Parser  → AST (Abstract Syntax Tree)                  │
  │  3. Binder  → Symbols, Scopes                             │
  │  4. Checker → Type Checking & Type Inference              │
  │  5. Emitter → JavaScript output (.js) + type defs (.d.ts) │
  └──────────────────────────────────────────────────────────┘
       │                    │
       ▼                    ▼
  .js (runnable)       .d.ts (type declarations)

Important: TypeScript types are ERASED at runtime. No type info exists in the
compiled JS. TypeScript is purely a development-time tool.

5. CORE CONCEPTS AT A GLANCE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

a) Static vs. Dynamic Typing
   --------------------------
   // JavaScript (dynamic — error only at runtime)
   function add(a, b) { return a + b; }
   add("5", 3); // "53" — silently wrong!

   // TypeScript (static — error at compile time)
   function add(a: number, b: number): number { return a + b; }
   add("5", 3); // ❌ Compile Error: Argument of type 'string' is not assignable to 'number'

b) Structural Typing (Duck Typing)
   ---------------------------------
   // TS uses shape-based compatibility, NOT name-based
   interface Point { x: number; y: number; }
   interface Coordinate { x: number; y: number; }

   let p: Point = { x: 1, y: 2 };
   let c: Coordinate = p; // ✅ Same shape = compatible

c) Type Erasure
   -------------
   // TypeScript at development time:
   const greet = (name: string): string => `Hello, ${name}`;

   // After compilation to JavaScript:
   const greet = (name) => `Hello, ${name}`;
   // All types are stripped — zero runtime cost

d) Gradual Adoption
   -----------------
   TypeScript supports gradual migration:
   • allowJs: true → compile JS alongside TS
   • checkJs: true → type-check JS files
   • // @ts-check → opt-in type checking in JS files
   • // @ts-ignore → suppress specific errors
   • // @ts-nocheck → disable checking for a file

7. INSTALLATION AND BASIC USAGE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Install:
  npm install -g typescript          # global install
  npm install --save-dev typescript  # project-local install (recommended)

Check version:
  tsc --version    # e.g. Version 5.5.0

Initialize project:
  tsc --init       # creates tsconfig.json with defaults

Compile:
  tsc              # compile all files per tsconfig.json
  tsc index.ts     # compile single file (ignores tsconfig)
  tsc --watch      # watch mode

Run TypeScript directly:
  npx ts-node index.ts
  npx tsx index.ts   # faster alternative

8. MENTAL MODEL: HOW TO THINK IN TYPESCRIPT
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. "Types are sets"
   Every type is a set of possible values.
   • never   = empty set {}
   • unknown = universal set (all values)
   • number  = {0, 1, -1, 3.14, NaN, Infinity, ...}
   • "hello" = {"hello"} (literal type, set of one)

2. "TypeScript is a type-level language"
   You can write programs at the type level using mapped types,
   conditional types, template literals, etc.

3. "Types flow through your program"
   TypeScript tracks types through assignments, function calls,
   conditionals (type narrowing), and returns.

4. "Prefer structural contracts over nominal names"
   Two types with the same shape are interchangeable in TS.

9. COMMON INTERVIEW QUESTIONS — OVERVIEW LEVEL
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q1: What is TypeScript and why would you use it over JavaScript?
    TypeScript is a statically typed superset of JavaScript. It adds type
    safety that catches errors at compile time rather than runtime, provides
    better tooling (autocomplete, refactoring), and makes large codebases
    more maintainable. It compiles to plain JS so it works everywhere JS does.

Q2: Does TypeScript replace JavaScript?
    No. TypeScript compiles TO JavaScript. Browsers and Node.js run JS, not TS.
    TypeScript is a development tool only — all types are erased at runtime.

Q3: Is TypeScript purely a compile-time tool?
    Yes. TypeScript types are completely erased during compilation. There is
    zero TypeScript-specific code in the output. This means no runtime overhead.

Q4: What does "structural typing" mean in TypeScript?
    TypeScript checks type compatibility based on the structure (shape) of
    types, not their names. If two objects have the same properties and types,
    they are considered compatible — this is called duck typing.

Q5: What is the difference between `any` and `unknown`?
    `any` turns off type checking entirely — you can do anything with an `any`
    value. `unknown` is the type-safe alternative: you can assign anything to
    it, but you must narrow the type before using it. Always prefer `unknown`
    over `any`.

    let a: any = "hello";
    a.toUpperCase(); // ✅ no error, but unsafe

    let u: unknown = "hello";
    u.toUpperCase(); // ❌ Error: Object is of type 'unknown'
    if (typeof u === "string") u.toUpperCase(); // ✅ after narrowing

Q6: What is `never` in TypeScript?
    `never` represents values that never occur. It's the bottom type (empty
    set). Used for:
    • Functions that always throw (never return)
    • Exhaustiveness checking in discriminated unions
    • Unreachable code detection

    function fail(msg: string): never {
      throw new Error(msg); // function never returns normally
    }

Q7: What is the TypeScript compilation process?
    .ts → Scanner (tokenize) → Parser (AST) → Binder (symbols/scopes)
    → Checker (type verification) → Emitter (output .js + .d.ts)

Q8: What is the difference between tsc and ts-node?
    `tsc` compiles TypeScript to JavaScript files. `ts-node` lets you execute
    TypeScript directly in Node.js without a separate compilation step —
    useful for scripts, CLIs, and development.

Q9: Can TypeScript work with existing JavaScript code?
    Yes. With `allowJs: true` in tsconfig, TypeScript can compile JS files
    alongside TS files. With `checkJs: true`, it also type-checks JS.
    You can gradually migrate JS projects to TS.

Q10: What is DefinitelyTyped?
     DefinitelyTyped (@types/*) is a community repository of TypeScript
     type definitions for JavaScript libraries that don't ship their own
     types. e.g., `@types/react`, `@types/lodash`, `@types/node`.
