================================================================================
  The `infer` Keyword — Complete Interview Preparation Guide
================================================================================

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1. WHAT IS `infer`?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  `infer` is a TypeScript keyword used exclusively inside the `extends` clause
  of a conditional type. It introduces a NEW type variable that TypeScript
  automatically fills in (infers) from the matched pattern.

  Syntax: T extends Pattern<infer X> ? UseX : Fallback

  Think of it as: "If T matches this pattern, CAPTURE the matching part as X."

  Without infer, you'd have to guess or hard-code what part of a complex type
  you want to extract. With infer, TypeScript does the extraction for you.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
2. CORE RULES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  1. `infer` can ONLY appear inside `extends` in a conditional type.
  2. The inferred variable (R, P, U, etc.) can ONLY be used in the TRUE branch.
  3. Multiple `infer` sites in the same pattern are allowed.
  4. If the pattern doesn't match, the false branch is taken (inferred var
     is not available there).
  5. `infer` variables can shadow outer type parameters of the same name.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
3. EXTRACTING FUNCTION TYPES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  a) Return type:
     type ReturnType<T> = T extends (...args: any[]) => infer R ? R : never;
     type R1 = ReturnType<() => string>;           // string
     type R2 = ReturnType<(n: number) => boolean>; // boolean
     type R3 = ReturnType<typeof Math.sqrt>;       // number

  b) Parameter types (as a tuple):
     type Parameters<T> = T extends (...args: infer P) => any ? P : never;
     type P1 = Parameters<(a: string, b: number) => void>; // [string, number]
     type P2 = Parameters<() => void>;                     // []

  c) First parameter only:
     type FirstParam<T> =
       T extends (first: infer F, ...rest: any[]) => any ? F : never;
     type F = FirstParam<(name: string, age: number) => void>; // string

  d) Last parameter:
     type LastParam<T> =
       T extends (...args: [...any[], infer L]) => any ? L : never;
     type L = LastParam<(a: string, b: number, c: boolean) => void>; // boolean

  e) Constructor parameter types:
     type ConstructorParams<T> =
       T extends new (...args: infer P) => any ? P : never;
     class User { constructor(id: number, name: string) {} }
     type CP = ConstructorParams<typeof User>; // [number, string]

  f) Instance type from constructor:
     type InstanceType<T> =
       T extends new (...args: any[]) => infer I ? I : never;
     type I = InstanceType<typeof User>; // User

4. EXTRACTING FROM ARRAYS AND TUPLES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  a) Element type of an array:
     type ElementType<T> = T extends (infer E)[] ? E : never;
     type E = ElementType<string[]>; // string

  b) First element of a tuple:
     type Head<T extends any[]> = T extends [infer F, ...any[]] ? F : never;
     type H = Head<[1, 2, 3]>; // 1 (literal type)

  c) Last element of a tuple:
     type Tail<T extends any[]> = T extends [...any[], infer L] ? L : never;
     type T = Tail<[1, 2, 3]>; // 3

  d) Remove first element (tail of tuple):
     type Rest<T extends any[]> = T extends [any, ...infer R] ? R : never;
     type R = Rest<[1, 2, 3]>; // [2, 3]

  e) Flatten one level of array:
     type Flatten<T> = T extends Array<infer Item> ? Item : T;
     type F = Flatten<string[]>;     // string
     type G = Flatten<string[][]>;   // string[] (one level)

  f) Recursively flatten:
     type DeepFlatten<T> = T extends Array<infer Item>
       ? DeepFlatten<Item>
       : T;
     type DF = DeepFlatten<string[][][]>; // string

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
5. EXTRACTING FROM PROMISE / ASYNC TYPES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  // One level:
  type Awaited<T> = T extends Promise<infer U> ? U : T;
  type A = Awaited<Promise<string>>; // string

  // Fully recursive (matches TypeScript's built-in Awaited<T>):
  type DeepAwaited<T> = T extends Promise<infer U> ? DeepAwaited<U> : T;
  type B = DeepAwaited<Promise<Promise<Promise<number>>>>; // number

  // Async function return (unwrap both async and return):
  type AsyncReturnType<T extends (...args: any[]) => Promise<any>> =
    T extends (...args: any[]) => Promise<infer R> ? R : never;

  async function fetchUser(): Promise<{ id: number; name: string }> { ... }
  type User = AsyncReturnType<typeof fetchUser>; // { id: number; name: string }

6. EXTRACTING FROM OBJECT SHAPES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  // Extract type of a specific property:
  type PropType<T, K extends string> = T extends { [key in K]: infer V }
    ? V
    : never;
  type Id = PropType<{ id: number; name: string }, "id">; // number

  // Extract value type from object type (all properties):
  type ValueOf<T> = T[keyof T];
  // (This uses indexed access, not infer — simpler when possible)

  // Extract the "data" property of a nested response:
  type ExtractData<T> = T extends { data: infer D } ? D : never;
  type D = ExtractData<{ data: { users: User[] }; status: number }>;
  // { users: User[] }

7. INFER WITH TEMPLATE LITERAL TYPES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  `infer` can extract parts of string literal types when used with template
  literal patterns:

  // Remove "on" prefix:
  type RemoveOn<S extends string> = S extends `on${infer Rest}` ? Rest : S;
  type R = RemoveOn<"onClick">; // "Click"

  // Extract second segment:
  type Second<S extends string> =
    S extends `${infer _}.${infer Mid}.${infer _2}` ? Mid : never;
  type M = Second<"a.middle.b">; // "middle"

  // Get file extension:
  type Extension<T extends string> =
    T extends `${infer _}.${infer Ext}` ? Ext : never;
  type E = Extension<"file.ts">; // "ts"

  // Infer route params:
  type Params<T extends string> =
    T extends `${infer _}:${infer Param}/${infer Rest}`
      ? Param | Params<Rest>
      : T extends `${infer _}:${infer Param}`
        ? Param
        : never;
  type P = Params<"/users/:userId/posts/:postId">;
  // "userId" | "postId"

8. MULTIPLE infer IN ONE CONDITION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  You can have multiple `infer` sites in a single condition:

  // Extract function's single argument and return type:
  type UnaryFn<T> = T extends (arg: infer A) => infer R
    ? { arg: A; return: R }
    : never;

  type Info = UnaryFn<(x: string) => number>;
  // { arg: string; return: number }

  // Extract key-value pair type from Map:
  type MapTypes<T> = T extends Map<infer K, infer V>
    ? { key: K; value: V }
    : never;
  type M = MapTypes<Map<string, User>>;
  // { key: string; value: User }

9. INFER IN SAME POSITION → INTERSECTION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  If the SAME infer variable is used in multiple positions with contravariance
  (e.g., function parameters), TypeScript infers the INTERSECTION:

  type UnionToIntersection<U> =
    (U extends any ? (x: U) => void : never) extends (x: infer I) => void
      ? I
      : never;

  type I = UnionToIntersection<{ a: string } | { b: number }>;
  // { a: string } & { b: number }

  Explanation:
  1. Distribute: ({ a } => void) | ({ b } => void)
  2. Both must be assignable to (x: I) => void
  3. Since params are contravariant, I must be the intersection

10. INTERVIEW QUESTIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q1: What is the `infer` keyword in TypeScript?
    `infer` is a special keyword used inside `extends` clauses of conditional
    types. It introduces a type variable that TypeScript automatically infers
    from the matched pattern, allowing you to "extract" parts of complex types.

Q2: Where can `infer` be used?
    Only inside the `extends` clause of a conditional type:
    T extends Pattern<infer X> ? X : Fallback
    The inferred variable X is only accessible in the TRUE branch.

Q3: How is ReturnType<T> implemented using `infer`?
    type ReturnType<T> = T extends (...args: any[]) => infer R ? R : never;
    If T is a function, R is inferred as the return type. Otherwise, never.

Q4: How do you extract the element type from an array type?
    type ElementType<T> = T extends (infer E)[] ? E : never;
    type E = ElementType<string[]>; // string

Q5: Can you use `infer` multiple times in one conditional?
    Yes. Each infer introduces a separate type variable:
    type UnaryFn<T> = T extends (arg: infer A) => infer R ? { arg: A; return: R } : never;
    Both A and R are captured independently.

Q6: How do you get the first element of a tuple with `infer`?
    type Head<T extends any[]> = T extends [infer F, ...any[]] ? F : never;

Q7: How does the UnionToIntersection utility type use `infer`?
    By placing the infer variable in function parameter position (contravariant),
    TypeScript must infer the intersection of all union members to satisfy the
    constraint: (U extends any ? (x: U) => void : never) extends (x: infer I) => void

Q8: What's the relationship between `infer` and template literal types?
    `infer` can match and extract substrings from string literal types when
    combined with template literal patterns:
    type Ext<S> = S extends `${string}.${infer E}` ? E : never;

Q9: How do you write an AsyncReturnType utility?
    type AsyncReturnType<T extends () => Promise<any>> =
      T extends () => Promise<infer R> ? R : never;
    This unwraps the Promise layer from an async function's return type.

Q10: What happens when infer appears in a covariant vs contravariant position?
     Covariant (return types, property types): multiple same-named infer sites
     → the resulting type is a union.
     Contravariant (function parameters): multiple same-named infer sites
     → the resulting type is an intersection. This is the trick used in
     UnionToIntersection.
