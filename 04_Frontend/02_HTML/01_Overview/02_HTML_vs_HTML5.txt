1. WHAT CHANGED IN HTML5?
================================================================================

HTML5 is the 5th major version of HTML (published as a W3C recommendation in
October 2014; now a living standard under WHATWG). It was designed to:

- Make web pages richer WITHOUT requiring plugins (Flash, Silverlight)
- Improve semantic meaning of page structure
- Add native multimedia (audio, video)
- Introduce powerful JavaScript APIs (geolocation, storage, workers)
- Standardize browser behavior for error handling
- Enable mobile-first design patterns
- Support offline and application-like functionality

Key Philosophy: "Don't break the web" — HTML5 is 100% backwards compatible.
Existing HTML4 pages still work in HTML5 browsers.

2. NEW STRUCTURAL / SEMANTIC ELEMENTS
================================================================================

HTML4 had only generic containers (<div>, <span>). HTML5 introduces elements
that carry semantic meaning — they describe the PURPOSE of content.

Element         Description
-----------     ----------------------------------------------------------
<header>        Introductory content; page or section header
<nav>           Navigation links block
<main>          Main content of the document (unique per page)
<article>       Self-contained content (blog post, news article)
<section>       Thematic grouping within a document
<aside>         Tangentially related content (sidebars, callouts)
<footer>        Footer of page or section
<figure>        Self-contained media with optional caption
<figcaption>    Caption for <figure>
<mark>          Highlighted / search-result text
<time>          Machine-readable date/time
<summary>       Visible heading for <details>
<details>       Disclosure widget (expand/collapse)
<dialog>        Inline dialog or modal window
<meter>         Scalar value within a known range (gauge)
<progress>      Task progress indicator
<output>        Result of a calculation
<template>      Client-side template (not rendered initially)
<slot>          Shadow DOM slot (Web Components)
<wbr>           Word break opportunity hint

WHY IT MATTERS FOR INTERVIEWS:
- Semantic HTML improves SEO (search engines understand page structure)
- Screen readers rely on semantic elements for navigation
- Code is more readable and maintainable
- Enables better accessibility without ARIA overrides

3. NEW FORM ELEMENTS & INPUT TYPES
================================================================================

HTML4 input types: text, password, checkbox, radio, submit, reset, file, hidden

HTML5 added input types:
  email, url, tel, number, range, date, time, datetime-local,
  month, week, color, search

HTML5 added form elements:
  <datalist>  — Predefined options for text input (autocomplete dropdown)
  <output>    — Result of a form calculation
  <progress>  — Progress bar
  <meter>     — Gauge/measurement bar

HTML5 added form attributes:
  placeholder, required, pattern, autofocus, autocomplete,
  min, max, step, multiple, novalidate, formaction, formmethod

These enable NATIVE browser validation without JavaScript.

================================================================================
4. MULTIMEDIA WITHOUT PLUGINS
================================================================================

HTML4 required Flash/QuickTime plugins for audio and video.

HTML5 Multimedia:
  <video> — Embed video natively
    <video controls width="640" height="360">
      <source src="movie.mp4"  type="video/mp4">
      <source src="movie.webm" type="video/webm">
      <track src="sub.vtt" kind="subtitles" srclang="en" label="English">
      Your browser does not support video.
    </video>

  <audio> — Embed audio natively
    <audio controls>
      <source src="song.mp3"  type="audio/mpeg">
      <source src="song.ogg"  type="audio/ogg">
    </audio>

  <canvas> — Scriptable 2D drawing surface (API via JavaScript)
  <svg>    — Inline scalable vector graphics

Benefits:
  - No plugin required (mobile-friendly; iOS never supported Flash)
  - Native controls accessible via keyboard/screen readers
  - Responsive by default with CSS
  - APIs for scripted playback, seeking, playback rate control

6. DEPRECATED / REMOVED ELEMENTS & ATTRIBUTES
================================================================================

REMOVED (invalid in HTML5):
  Element/Attribute   Reason & HTML5 Replacement
  -----------------   --------------------------------------------------
  <font>              Use CSS font-family, font-size, color
  <center>            Use CSS text-align: center; or margin: auto
  <big>, <small>*     Use CSS font-size  (*<small> still valid but semantic)
  <strike>            Use <del> (deleted text) or CSS text-decoration
  <tt>                Use <code> or <kbd>
  <frame>, <frameset> Use CSS layouts, <iframe> if needed
  <noframes>          N/A
  <applet>            Use <object> or JavaScript
  <acronym>           Use <abbr>
  <basefont>          Use CSS
  align=, bgcolor=    Use CSS
  border= on table    Use CSS border
  cellpadding/        Use CSS padding/border-spacing
  cellspacing

DEPRECATED ATTRIBUTES:
  - charset on <a>/<link> (use <meta charset>)
  - name on <img> (use id)
  - language on <script> (use type or omit)
  - type="text/javascript" on <script> (unnecessary; JS is default)
  - type="text/css" on <link> (unnecessary; CSS is default)

STILL VALID but semantically changed:
  <b>     = Bold (now "stylistically offset" without importance)
  <i>     = Italic (now "alternative voice or mood")
  <s>     = Strikethrough (now "no longer accurate" content)
  <u>     = Underline (now "unarticulated annotation")

7. DOCTYPE SIMPLIFICATION
================================================================================

HTML 4.01 Strict:
  <!DOCTYPE HTML PUBLIC "-//W3C//DTD HTML 4.01//EN"
  "http://www.w3.org/TR/html4/strict.dtd">

HTML 4.01 Transitional:
  <!DOCTYPE HTML PUBLIC "-//W3C//DTD HTML 4.01 Transitional//EN"
  "http://www.w3.org/TR/html4/loose.dtd">

XHTML 1.0 Strict:
  <!DOCTYPE html PUBLIC "-//W3C//DTD XHTML 1.0 Strict//EN"
  "http://www.w3.org/TR/xhtml1/DTD/xhtml1-strict.dtd">

HTML5:
  <!DOCTYPE html>

Purpose of DOCTYPE:
- Signals to the browser which HTML version is used
- Triggers "standards mode" vs "quirks mode"
- HTML5 DOCTYPE is the shortest possible string that triggers standards mode
- HTML5 DOCTYPE does NOT reference a DTD (HTML5 is not SGML-based)

================================================================================
8. CHARACTER ENCODING SIMPLIFICATION
================================================================================

HTML 4.01:
  <meta http-equiv="Content-Type" content="text/html; charset=UTF-8">

HTML5:
  <meta charset="UTF-8">

- Must appear within first 1024 bytes of the file
- Must be the FIRST element in <head> (before <title>)
- UTF-8 is recommended for all HTML5 documents
- Prevents browser sniffing attacks (MIME sniffing)

9. BACKWARDS COMPATIBILITY
================================================================================

HTML5 was designed to be 100% backwards compatible:

1. All valid HTML4 markup is valid in HTML5
2. Old deprecated elements still render (browser ignores unknown elements)
3. HTML5 parser is more forgiving than XHTML

HTML5 Shiv/Polyfill for IE8 and below:
  IE8 doesn't understand HTML5 semantic elements and won't style them.
  Solution: html5shiv creates the elements in the DOM so CSS can target them.
  <!--[if lt IE 9]>
    <script src="html5shiv.js"></script>
  <![endif]-->

11. IMPORTANT INTERVIEW Q&A
================================================================================

Q1: What is the main difference between HTML and HTML5?
A: HTML5 adds semantic elements, native audio/video support, a rich set of
   JavaScript APIs (Canvas, Web Storage, Geolocation, Web Workers, etc.),
   improved form controls, and a simplified DOCTYPE. Most importantly, HTML5
   removes the need for browser plugins like Flash for multimedia.

Q2: Is HTML5 backwards compatible with HTML4?
A: Yes. All valid HTML4 documents are valid HTML5 documents. HTML5 also
   handles malformed HTML more gracefully and consistently.

Q3: Why was Flash deprecated in favor of HTML5?
A: Flash required a proprietary plugin, didn't work on iOS/mobile, was a
   major security vulnerability, and consumed high CPU/battery. HTML5 provides
   native video, audio, canvas, and animation APIs without plugins.

Q4: What is the difference between <b> and <strong>? <i> and <em>?
A: <b> = visually bold (no semantic importance)
   <strong> = strong IMPORTANCE (semantic; screen readers emphasize)
   <i> = visually italic (alternate voice, technical term, idiom)
   <em> = STRESS emphasis (semantic; screen readers change tone)
   Use <strong>/<em> for meaningful emphasis; <b>/<i> for pure styling.

Q5: What HTML5 features improved SEO?
A: Semantic elements (<article>, <section>, <nav>, <header>, <footer>),
   <time datetime="">, structured data support (via microdata/schema.org),
   and the improved heading hierarchy helped search engines better understand
   page structure and content relationships.

Q6: What is the <template> element?
A: Holds client-side HTML template fragments that are NOT rendered when the
   page loads. They are inert (scripts don't run, images don't load) until
   cloned and inserted into the DOM with JavaScript.
   document.querySelector('template').content.cloneNode(true)

Q7: What does contenteditable do?
A: An HTML5 global attribute that makes any element editable in the browser.
   <div contenteditable="true">Edit me!</div>
   Used for rich text editors without needing <textarea>.

Q8: What is the difference between localStorage and sessionStorage?
A: Both are Web Storage APIs (5-10MB per origin):
   localStorage  — persists until explicitly cleared; shared across tabs
   sessionStorage — cleared when the browser tab is closed; tab-specific

Q9: Can you explain the async and defer attributes on <script>?
A: Both attributes allow the HTML parser to continue while the script is
   fetched. With async, the script executes as soon as it downloads
   (potentially before HTML is fully parsed). With defer, execution is
   deferred until parsing is complete, and scripts run in document order.
   Scripts without either attribute block parsing.

Q10: What are Web Components and how do they relate to HTML5?
A: Web Components are a set of HTML5 APIs:
   - Custom Elements   : define new HTML tags (<my-button>)
   - Shadow DOM        : encapsulated DOM & styles
   - HTML Templates    : <template> and <slot> for reusable markup
   They allow creating reusable, encapsulated components natively without
   frameworks, using standard HTML5 APIs.
