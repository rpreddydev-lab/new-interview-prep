SECTION 1: PROMISES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q1: What is a Promise?
A:
  An object representing the eventual completion or failure of an async
  operation. Three states: pending, fulfilled, rejected. Once settled,
  a promise is immutable — state cannot change again.

Q2: What is the difference between Promise.all and Promise.allSettled?
A:
  Promise.all(promises)       — resolves when ALL resolve; rejects IMMEDIATELY
                                if any reject ("fail-fast")
  Promise.allSettled(promises) — always resolves with an array of result objects
                                ({status: "fulfilled", value} or
                                {status: "rejected", reason}).
                                Never rejects — waits for all.
  Use Promise.all for dependent operations; allSettled when you need all results.

Q3: What is the difference between Promise.race and Promise.any?
A:
  Promise.race  — resolves/rejects with the FIRST settled promise (fulfilled or rejected)
  Promise.any   — resolves with the first FULFILLED promise; rejects with
                  AggregateError only if ALL reject.

Q4: What is a common Promise mistake?
A:
  Not returning the promise in .then() chains — breaks the chain.
  fetch(url).then(res => { res.json(); })  // WRONG — implicit undefined
  fetch(url).then(res => res.json())       // CORRECT — returns promise

Q5: What does Promise.resolve(value) return?
A:
  A promise already fulfilled with value. If value is itself a promise,
  it is returned as-is (not wrapped). Useful for converting values to promises.

SECTION 2: ASYNC/AWAIT
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q6: What is async/await?
A:
  Syntactic sugar on top of Promises. async functions always return a Promise.
  await pauses the function's execution (as a microtask) until the awaited
  Promise resolves. Makes async code look like synchronous code.

Q7: What is the output?
  async function main() {
    console.log("A");
    await Promise.resolve();
    console.log("B");
  }
  main();
  console.log("C");
A:
  A, C, B.
  "A" is sync inside main(). await suspends main(), yielding execution.
  "C" runs synchronously. Then microtask queue: main() resumes → "B".

Q8: Why doesn't async work with forEach?
A:
  forEach doesn't await the promise returned by the async callback — it
  fires all callbacks but ignores their results. The loop completes before
  any async work finishes. Use for...of (awaits each) or
  Promise.all(arr.map(async item => ...)) for parallel execution.

Q9: How do you run async operations in parallel with async/await?
A:
  const [a, b] = await Promise.all([fetch(url1), fetch(url2)]);
  Start both fetches before awaiting — they run concurrently.
  Awaiting them sequentially (await fetch(url1); await fetch(url2)) is slower.

SECTION 3: EVENT LOOP

Q10: What is the Event Loop?
A:
  The mechanism that enables async JavaScript. When the call stack is empty,
  the event loop drains ALL microtasks first, then picks ONE macrotask,
  then drains microtasks again, and so on.

Q11: What is the output?
  console.log("1");
  setTimeout(() => console.log("2"), 0);
  Promise.resolve().then(() => console.log("3"));
  console.log("4");
A:
  1, 4, 3, 2.
  Sync: 1, 4. Microtask: 3 (Promise.then). Macrotask: 2 (setTimeout).

Q12: What is the difference between microtasks and macrotasks?
A:
  Microtasks (Promise.then, queueMicrotask) have higher priority and drain
  COMPLETELY after each macrotask before the next macrotask runs.
  Macrotasks (setTimeout, setInterval, I/O) run one at a time, each followed
  by draining all microtasks.

Q13: What is microtask starvation?
A:
  When microtasks continuously enqueue new microtasks (infinite microtask loop),
  no macrotask ever gets to run. The event loop is stuck draining microtasks.

SECTION 4: FETCH AND NETWORK
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q14: Does fetch() reject on HTTP errors like 404?
A:
  No. fetch() only rejects on NETWORK failures (no connection, DNS error).
  HTTP errors (4xx, 5xx) are RESOLVED — you must check response.ok or
  response.status manually and throw accordingly.

Q15: How do you cancel a fetch request?
A:
  Use AbortController:
  const controller = new AbortController();
  fetch(url, { signal: controller.signal });
  controller.abort(); // cancels — throws AbortError
  Check err.name === "AbortError" to distinguish from other errors.

Q16: What is the difference between response.json() and JSON.parse()?
A:
  response.json() asynchronously reads the response body stream and parses
  it as JSON (returns Promise). JSON.parse() is synchronous and works on a
  string. response.json() is the correct method for fetch responses.

Q17: What is callback hell and how do you avoid it?
A:
  Nested callbacks that create the "pyramid of doom" — deeply nested code
  that's hard to read and maintain. Solutions:
  1. Named functions instead of anonymous inline callbacks
  2. Promises (flat .then() chains)
  3. async/await (reads like synchronous code)

Q18: What is the error-first callback convention?
A:
  Node.js convention: first parameter of a callback is always an error (or null).
  function(err, data) { if (err) throw err; ... }
  Allows consistent error checking at every async step.
