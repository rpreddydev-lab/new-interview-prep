TRICKY INTERVIEW QUESTIONS — JAVASCRIPT INTERVIEW PREP

These are classic "gotcha" questions frequently asked to test deep JS knowledge.
For each: read the code, predict the output, then verify understanding.

SECTION 1: TYPE COERCION TRAPS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q1: What is the output?
  console.log([] + []);
  console.log([] + {});
  console.log({} + []);
A:
  ""          — [] → "" + "" → ""
  "[object Object]" — [] → "" + {} → "[object Object]"
  "[object Object]" — when {} starts a statement, it's a block; + [] = 0?
    ACTUALLY: in a statement context {} is a code block, +[] = +"" = 0
    So {} + [] = 0. BUT in console.log({} + []) it's an EXPRESSION context,
    so {} is an object: "[object Object]"

Q2: What is the output?
  console.log(typeof NaN);
  console.log(NaN === NaN);
  console.log(Number.isNaN(NaN));
  console.log(isNaN("hello"));
A:
  "number"  — NaN is technically type "number"
  false     — NaN is NOT equal to itself (only value not reflexive)
  true      — Number.isNaN strictly checks for NaN
  true      — isNaN("hello") coerces to NaN first, then checks

Q3: What is the output?
  console.log(0.1 + 0.2 === 0.3);
A:
  false — IEEE 754 floating point. 0.1 + 0.2 = 0.30000000000000004.
  Fix: Math.abs(0.1 + 0.2 - 0.3) < Number.EPSILON

Q4: What is the output?
  console.log(null == undefined);
  console.log(null === undefined);
  console.log(null > 0);
  console.log(null == 0);
  console.log(null >= 0);
A:
  true   — == only: null == undefined special case
  false  — different types
  false  — null coerced to 0, 0 > 0 = false
  false  — null only equals undefined in == (not 0)
  true   — null coerced to 0, 0 >= 0 = true
  (null >= 0 is true but null == 0 is false — notorious JS inconsistency!)

SECTION 2: SCOPE AND HOISTING TRAPS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q5: What is the output?
  var x = 1;
  function foo() {
    console.log(x);
    var x = 2;
    console.log(x);
  }
  foo();
A:
  undefined, 2.
  Inside foo(), var x is hoisted to the top of foo (shadows outer x).
  First log: x is declared but not yet assigned → undefined.
  Second log: x = 2 is now assigned.

Q6: What is the output?
  console.log(foo());
  function foo() { return "hello"; }

  console.log(bar());
  var bar = function() { return "world"; };
A:
  "hello" — function declarations are fully hoisted.
  TypeError: bar is not a function — bar is hoisted as undefined (var),
  calling undefined() throws TypeError.

Q7: What is the output?
  let x = 1;
  {
    console.log(x);  // ?
    let x = 2;
  }
A:
  ReferenceError. The inner let x is hoisted to the start of the block
  (TDZ). Accessing x before the declaration line inside the block throws,
  even though x = 1 exists in the outer scope.

SECTION 3: CLOSURE AND this TRAPS

Q8: What is the output?
  for (var i = 0; i < 3; i++) {
    setTimeout(() => console.log(i), 0);
  }
A:
  3, 3, 3. var is function scoped; all callbacks share the same i,
  which is 3 when callbacks fire. Fix: use let or wrap in an IIFE.

Q9: What is the output?
  const obj = {
    value: 42,
    getValue: function() { return this.value; }
  };
  const fn = obj.getValue;
  console.log(fn());
A:
  undefined (non-strict) or TypeError (strict).
  Implicit binding is lost when assigning to a variable.
  Fix: const fn = obj.getValue.bind(obj);

Q10: What is the output?
  const obj = {
    name: "Alice",
    arrow: () => this.name,
    regular: function() { return this.name; }
  };
  console.log(obj.arrow());
  console.log(obj.regular());
A:
  undefined (arrow function captures `this` from the DEFINING scope —
  at object literal time, `this` is the outer scope / undefined in strict)
  "Alice" (regular function: implicit binding → this = obj)

Q11: What is the output?
  async function fetchData() {
    return 42;
  }
  console.log(fetchData());
A:
  Promise {<fulfilled>: 42}
  All async functions return Promises — even if the return value is a plain number.

Q12: What is the output?
  console.log("start");
  setTimeout(() => console.log("timeout"), 0);
  Promise.resolve().then(() => console.log("promise 1"))
                   .then(() => console.log("promise 2"));
  console.log("end");
A:
  start, end, promise 1, promise 2, timeout.
  Sync: start, end. Microtasks drain: promise 1, then promise 2.
  Then macrotask: timeout.

Q13: What is the output?
  console.log([1, 2, 3].toString());
  console.log(typeof []);
  console.log([] instanceof Array);
  console.log(Array.isArray([]));
A:
  "1,2,3"  — arrays have custom toString
  "object" — arrays are objects (typeof doesn't distinguish)
  true     — [] is an instance of Array
  true     — recommended way to check for array

Q14: What is the output?
  const a = [1, 2, 3];
  const b = a;
  b.push(4);
  console.log(a);
A:
  [1, 2, 3, 4]. a and b reference the SAME array. Objects/arrays are
  assigned by reference. Mutation via b also changes a.

Q15: What does this return?
  typeof function(){}
  typeof class {}
A:
  "function" for both. Classes are technically functions in JavaScript.

Q16: What is the output?
  function test() {
    return {
      value: 42
    };
  }
  function broken() {
    return
    {
      value: 42
    };
  }
  console.log(test());
  console.log(broken());
A:
  { value: 42 }
  undefined
  Automatic Semicolon Insertion (ASI) inserts a semicolon after return
  on its own line. broken() returns undefined, then { value: 42 } is a
  code block (never executed as return value).
  LESSON: always put { on the same line as return.

Q17: What does delete do?
  const obj = { a: 1, b: 2 };
  delete obj.a;
  console.log(obj.a);
  console.log("a" in obj);
A:
  undefined — property is removed
  false — no longer in object
  delete removes own properties. Cannot delete variables, inherited properties,
  or non-configurable properties.

Q18: What is the output of Array sorting without a comparator?
  console.log([10, 9, 2, 21, 3].sort());
A:
  [10, 2, 21, 3, 9] — sort() converts elements to STRINGS and sorts
  lexicographically by default! "10" < "2" lexicographically.
  Always provide a comparator for numbers: arr.sort((a, b) => a - b)
