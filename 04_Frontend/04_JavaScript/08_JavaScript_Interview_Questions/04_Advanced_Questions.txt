SECTION 1: MEMORY AND PERFORMANCE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q1: What is a memory leak in JavaScript? Name common causes.
A:
  Memory that is no longer needed but not garbage collected. Causes:
  1. Global variables — never collected if window.x = data
  2. Forgotten timers — setInterval callback holds references
  3. Detached DOM nodes — removed from DOM but JS still references them
  4. Closures holding large data — inner function references outer scope vars
  5. Event listeners not removed — handler keeps reference to element/data
  Prevention: use WeakMap/WeakRef for DOM references, always clear intervals,
  and remove event listeners in cleanup.

Q2: How does the JavaScript garbage collector work?
A:
  Modern engines use Mark-and-Sweep: starting from "roots" (global variables,
  stack), they mark all reachable objects. Anything unmarked is garbage.
  V8 divides the heap into young generation (minor GC, frequent, fast) and
  old generation (major GC, less frequent). Incremental and concurrent
  techniques minimize pauses.

Q3: What is layout thrashing and how do you prevent it?
A:
  Repeatedly reading and writing DOM properties that trigger reflow/layout.
  Each read after a write flushes pending styles, forcing reflow.
  Prevention: batch all reads first, then all writes. Use requestAnimationFrame.

Q4: What is a generator function?
A:
  A function that can pause execution with yield and resume later. Declared
  with function*. Returns a Generator object that implements both the
  iterator and iterable protocols (has next() method).

  function* range(start, end) {
    for (let i = start; i <= end; i++) yield i;
  }
  [...range(1, 5)]  // [1, 2, 3, 4, 5]

Q5: What is the difference between an iterator and an iterable?
A:
  Iterator — object with next() returning {value, done}
  Iterable — object with [Symbol.iterator]() that returns an iterator
  Generators return objects that are BOTH. for...of, spread, and destructuring
  work with any iterable.

Q6: What is currying?
A:
  Transforming a function that takes multiple arguments into a sequence of
  functions each taking one argument.
  add(1, 2) → curry(add)(1)(2)

  const curry = (fn) => (...args) =>
    args.length >= fn.length
      ? fn(...args)
      : (...more) => curry(fn)(...args, ...more);

Q7: What is memoization?
A:
  Caching the results of expensive function calls based on input.
  On subsequent calls with the same args, return the cached result.

  function memoize(fn) {
    const cache = new Map();
    return function(...args) {
      const key = JSON.stringify(args);
      if (cache.has(key)) return cache.get(key);
      const result = fn.apply(this, args);
      cache.set(key, result);
      return result;
    };
  }

Q8: What is function composition?
A:
  Combining functions where output of one is input of next.
  const compose = (...fns) => x => fns.reduceRight((v, f) => f(v), x);
  const pipe    = (...fns) => x => fns.reduce((v, f) => f(v), x);
  compose(f, g, h)(x) === f(g(h(x)))

Q9: What is debounce vs throttle?
A:
  Debounce — delays calling fn until input stops for N ms (search input).
             Each new call resets the timer.
  Throttle — ensures fn is called at most once per N ms (scroll handler).
             Ignores calls during the cooldown period.

  // Debounce:
  function debounce(fn, ms) {
    let timer;
    return (...args) => {
      clearTimeout(timer);
      timer = setTimeout(() => fn(...args), ms);
    };
  }

  // Throttle:
  function throttle(fn, ms) {
    let last = 0;
    return (...args) => {
      if (Date.now() - last >= ms) { fn(...args); last = Date.now(); }
    };
  }

Q10: What is a WeakMap used for?
A:
  Stores key-value pairs where keys are objects and are weakly referenced —
  they don't prevent garbage collection. Common uses:
  - Private data for objects (before private class fields)
  - Memoization cache keyed by object
  - Tracking DOM node metadata without preventing GC
  - Open/closed state for class instances

Q11: What is tree shaking?
A:
  Dead code elimination — bundlers (Webpack, Rollup, Vite) statically analyze
  ESM import/export to identify unused exports and exclude them from the final
  bundle. Requires ES modules (static structure). Not possible with CommonJS.

Q12: What is the difference between CommonJS and ESM live bindings?
A:
  CJS: exports are copied values — changes to the export in the source module
  don't propagate to importers.
  ESM: imports are live bindings — if the source updates the exported variable,
  all importers see the updated value immediately.

Q13: What is the purpose of a source map?
A:
  Maps minified/transpiled code back to original source. Allows debugging
  original code in browser DevTools even when production code is minified.
  Should be kept private in production or only accessible to error monitoring tools.

Q14: What is XSS (Cross-Site Scripting)?
A:
  Injecting malicious scripts into a web page viewed by other users.
  Prevention: use textContent instead of innerHTML for user data;
  sanitize HTML with DOMPurify; set Content-Security-Policy headers;
  never use eval() with untrusted data.

Q15: What is CORS?
A:
  Cross-Origin Resource Sharing — browser security mechanism restricting
  requests to different origins (scheme + domain + port). Server must send
  Access-Control-Allow-Origin header. The browser blocks responses that don't
  match. Preflight OPTIONS request is sent for non-simple requests.
