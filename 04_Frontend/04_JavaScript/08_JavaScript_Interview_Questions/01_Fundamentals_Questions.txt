SECTION 1: VARIABLES AND TYPES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q1: What is the difference between var, let, and const?
A:
  var   — function scoped, hoisted (initialized to undefined), can be
          re-declared, creates property on globalThis
  let   — block scoped, hoisted but in TDZ (not initialized), not re-declarable
  const — block scoped, same as let but binding cannot be reassigned;
          the VALUE of an object/array can still be mutated

Q2: What is the Temporal Dead Zone (TDZ)?
A:
  The period between the start of a block and the initialization of a
  let/const declaration. Accessing the variable in this window throws
  a ReferenceError. This prevents using variables before they are declared.

Q3: What are JavaScript's primitive types?
A:
  string, number, boolean, null, undefined, Symbol, BigInt — 7 primitives.
  Everything else is an object (Array, Function, Date, etc.).

Q4: What does typeof return for null?
A:
  "object" — this is a historical JavaScript bug. null is a primitive,
  but typeof null === "object". Use val === null to check for null.

Q5: What is the difference between null and undefined?
A:
  undefined — variable declared but not assigned; function returns nothing;
              missing object property
  null      — intentional absence of value; explicitly set by programmer
  null == undefined is true (loose equality), null === undefined is false.

Q6: What is type coercion?
A:
  Automatic type conversion JavaScript performs during operations.
  "5" - 1 → 4 (string coerced to number).
  "5" + 1 → "51" (number coerced to string — + is also concatenation).
  Use strict equality (===) and explicit conversions to avoid surprises.

SECTION 2: HOISTING
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q7: What is hoisting?
A:
  During compilation, declarations are moved to the top of their scope.
  - var: hoisted AND initialized to undefined
  - function declarations: hoisted WITH body — callable before declaration
  - let/const: hoisted but NOT initialized (TDZ) — access throws ReferenceError
  - class: hoisted but NOT initialized (TDZ)

Q8: What is the output?
  console.log(a);
  var a = 5;
  console.log(a);
A:
  undefined then 5.
  var a is hoisted (declaration moves up), initialized to undefined,
  then assigned 5 on the actual line.

Q9: Can you call a function before it's declared?
A:
  Only FUNCTION DECLARATIONS — they are fully hoisted.
  Function expressions (const fn = function(){}) and arrow functions are NOT.

SECTION 3: SCOPE AND CLOSURES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q10: What is a closure?
A:
  A closure is a function that remembers variables from its outer (lexical)
  scope even after the outer function has returned.

  function counter() {
    let count = 0;
    return () => ++count;
  }
  const inc = counter();
  inc(); // 1 — count persists in the closure

Q11: Classic closure bug — what does this log?
  for (var i = 0; i < 3; i++) {
    setTimeout(() => console.log(i), 0);
  }
A:
  3, 3, 3 — because var is function scoped; all callbacks share the same i,
  which is 3 after the loop. Fix with let (block scoped) or an IIFE.

Q12: What is the scope chain?
A:
  When a variable is accessed, JS looks in the current scope, then the outer
  scope, then outer's outer, all the way to global scope. If not found:
  ReferenceError. This chain of scopes is the scope chain.

Q13: What determines the value of `this`?
A:
  4 rules (priority order):
  1. new binding: new Fn() → this = new object
  2. Explicit: .call(obj) / .apply(obj) / .bind(obj)
  3. Implicit: obj.method() → this = obj
  4. Default: regular function → undefined (strict) or global (non-strict)
  Arrow functions: lexically capture this from enclosing scope; no own this.

Q14: What is the output?
  const obj = {
    name: "Alice",
    greet: function() { return this.name; }
  };
  const fn = obj.greet;
  fn();
A:
  undefined (or error in strict mode). Assigning obj.greet to fn loses the
  implicit binding. `this` in fn() defaults to global/undefined. Fix:
  fn.call(obj) or const fn = obj.greet.bind(obj).

Q15: What is the difference between call, apply, and bind?
A:
  All three set `this` explicitly.
  .call(thisArg, arg1, arg2)  — invokes immediately, args as list
  .apply(thisArg, [arg1, arg2]) — invokes immediately, args as array
  .bind(thisArg, ...args)     — returns NEW function with this bound; does NOT invoke

SECTION 5: EQUALITY AND COERCION

Q16: What is the difference between == and ===?
A:
  === (strict equality) — same type AND same value. No coercion.
  == (loose equality) — coerces types before comparing. Can produce
  surprising results: [] == 0 is true, null == undefined is true.
  Best practice: always use ===.

Q17: What are falsy values in JavaScript?
A:
  false, 0, -0, 0n (BigInt), "" (empty string), null, undefined, NaN
  Everything else is truthy (including [], {}, "0", function(){}).

Q18: What does !! do?
A:
  Double negation — converts any value to its boolean equivalent.
  !!0 → false, !!"hello" → true, !![] → true.
  Same as Boolean(value).

Q19: What is the difference between map, filter, and reduce?
A:
  map(fn)    — transforms each element, returns new array of same length
  filter(fn) — returns new array of elements where fn returns truthy
  reduce(fn, init) — reduces array to a single value by accumulation

Q20: How do you remove duplicates from an array?
A:
  const unique = [...new Set(arr)];          // Set removes duplicates
  const unique = arr.filter((v, i) => arr.indexOf(v) === i); // index check

Q21: What is the difference between shallow and deep copy?
A:
  Shallow copy copies the top-level structure. Nested objects still share
  references. Deep copy creates fully independent nested copies.
  Shallow: {...obj}, Object.assign({}, obj), [...arr]
  Deep: structuredClone(obj), or JSON.parse(JSON.stringify(obj)) (with caveats)
