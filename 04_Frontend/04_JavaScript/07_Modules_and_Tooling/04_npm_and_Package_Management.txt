  npm (Node Package Manager) is the default package manager for Node.js.
  Alternatives: yarn, pnpm

  - npm registry: public repository of ~2M+ packages
  - package.json: project manifest (metadata, deps, scripts)
  - package-lock.json: locked dependency tree (exact versions)
  - node_modules/: installed packages

    "name": "my-app",
    "version": "1.0.0",
    "description": "A web application",
    "main": "index.js",            // entry point for library consumers
    "type": "module",              // treat .js as ESM
    "scripts": {
      "start": "node src/index.js",
      "dev": "vite",
      "build": "vite build",
      "test": "jest",
      "lint": "eslint src"
    },
    "dependencies": {              // required in production
      "react": "^18.0.0",
      "express": "~4.18.0"
    },
    "devDependencies": {           // only needed for development
      "vite": "^4.0.0",
      "jest": "^29.0.0",
      "eslint": "^8.0.0"
    },
    "peerDependencies": {          // expected to be installed by consumer
      "react": ">=17.0.0"
    },
    "engines": { "node": ">=18" }
  }

3. SEMANTIC VERSIONING (semver)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Format: MAJOR.MINOR.PATCH  (e.g. 18.2.0)

  MAJOR — breaking changes (not backward compatible)
  MINOR — new features (backward compatible)
  PATCH — bug fixes (backward compatible)

  Range specifiers:
  "1.2.3"   — exact version
  "^1.2.3"  — compatible: >=1.2.3 <2.0.0 (most common — allows minor + patch)
  "~1.2.3"  — approx: >=1.2.3 <1.3.0 (allows patch only)
  ">=1.0.0" — specific range
  "*"       — any version
  "1.x"     — 1.anything

  // ^ is the default when you npm install — allows updates that don't break API.
  // pin exact versions in production for reproducibility (or use lock files).

4. COMMON npm COMMANDS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  npm init                      # create package.json interactively
  npm init -y                   # create with defaults

  npm install                   # install all deps from package.json
  npm install react             # add to dependencies
  npm install -D jest           # add to devDependencies
  npm install -g typescript     # install globally

  npm uninstall lodash          # remove package
  npm update                    # update all deps within semver range
  npm outdated                  # list outdated packages

  npm run build                 # run script
  npm start                     # shortcut for npm run start
  npm test                      # shortcut for npm run test

  npm ci                        # clean install from lock file (CI/CD use)
  npm audit                     # check for security vulnerabilities
  npm audit fix                 # auto-fix vulnerabilities
  npm ls                        # list installed packages
  npm pack                      # create tarball for publishing

5. package-lock.json
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  - Locks the EXACT versions of ALL dependencies (direct + transitive)
  - Generated automatically by npm install
  - Should be COMMITTED to version control
  - npm ci installs exactly what's in the lock file (no resolution)

  // npm install vs npm ci:
  // npm install — resolves versions, may update lock file
  // npm ci      — strictly follows lock file, fails if mismatched
  //               faster, used in CI/CD pipelines

7. YARN AND PNPM
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  YARN (by Meta):
  - Faster (parallel installs), deterministic (yarn.lock)
  - Yarn PnP (Plug'n'Play) — no node_modules, zero-installs
  - Workspaces support for monorepos

  PNPM:
  - Most disk-efficient — uses a global content-addressable store
  - Packages are symlinked, never duplicated across projects
  - Strict: prevents accessing packages not in your package.json
  - Significantly faster than npm on large projects

8. COMMON INTERVIEW QUESTIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: What is the difference between dependencies and devDependencies?
A: dependencies are needed to RUN the application in production (express, react).
   devDependencies are only needed during development/build (jest, eslint, vite).
   npm install --production skips devDependencies.

Q: What is the difference between npm install and npm ci?
A: npm install resolves dependencies and may update package-lock.json.
   npm ci (clean install) strictly installs from package-lock.json, fails if
   it doesn't match package.json, and is designed for CI/CD environments.

Q: What does ^ mean in semver?
A: Caret (^) allows compatible updates: any version >= the specified and
   < the next major. "^1.2.3" allows 1.2.4, 1.3.0 but NOT 2.0.0.

Q: Should package-lock.json be committed to git?
A: Yes. The lock file ensures everyone on the team (and CI) installs the
   exact same dependency tree, making builds reproducible.

Q: What is npx?
A: npx runs a package's executable without globally installing it. It first
   looks in local node_modules, then in npm's cache, then downloads temporarily.

Q: What is pnpm's advantage over npm?
A: pnpm uses a content-addressable store and hard links, so packages are
   stored once globally. It's significantly faster and saves disk space,
   especially with monorepos. It also enforces strict access (no phantom deps).
