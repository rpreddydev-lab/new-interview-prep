1. COMPARISON TABLE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  ┌────────────────────┬───────────────────────┬───────────────────────────┐
  │ Feature            │ Microtask             │ Macrotask                 │
  ├────────────────────┼───────────────────────┼───────────────────────────┤
  │ Also called        │ Job Queue             │ Task Queue / Callback Q   │
  │ Priority           │ HIGH (runs first)     │ LOW (runs after micro)    │
  │ Drains             │ Completely each tick  │ One at a time per tick    │
  │ Sources            │ Promise.then/catch    │ setTimeout / setInterval  │
  │                    │ queueMicrotask()      │ setImmediate (Node)       │
  │                    │ MutationObserver      │ I/O callbacks             │
  │                    │ async/await           │ UI rendering events       │
  │                    │                       │ MessageChannel            │
  └────────────────────┴───────────────────────┴───────────────────────────┘

  Rule: After EVERY macrotask (and after initial script), drain ALL microtasks
        before picking the next macrotask.

2. EXECUTION ORDER EXAMPLES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  // Example 1 — Basic:
  console.log("start");

  setTimeout(() => console.log("macrotask"), 0);

  Promise.resolve().then(() => console.log("microtask 1"))
                   .then(() => console.log("microtask 2"));

  console.log("end");

  // Output:
  // start         ← sync
  // end           ← sync
  // microtask 1   ← microtask (Promise.then)
  // microtask 2   ← microtask (chained .then)
  // macrotask     ← macrotask (setTimeout)

  // Example 2 — Microtask spawns microtask:
  Promise.resolve()
    .then(() => {
      console.log("micro 1");
      Promise.resolve().then(() => console.log("micro 1.1")); // nested
    })
    .then(() => console.log("micro 2"));

  // Output:
  // micro 1       ← first .then runs
  // micro 1.1     ← nested microtask drains before next outer .then
  // micro 2       ← second .then

  // Example 3 — Full mix:
  console.log("1");

  setTimeout(() => {
    console.log("2");
    Promise.resolve().then(() => console.log("3"));
  }, 0);

  setTimeout(() => console.log("4"), 0);

  Promise.resolve().then(() => console.log("5"));

  console.log("6");

  // Output: 1, 6, 5, 2, 3, 4
  // Explanation:
  // Sync:      1, 6
  // Microtask: 5
  // Macrotask: 2 → then microtasks from inside: 3
  // Macrotask: 4

3. queueMicrotask()
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  // Schedule a function as a microtask without creating a Promise:
  queueMicrotask(() => {
    console.log("microtask via queueMicrotask");
  });

  // Useful for library authors who need microtask semantics
  // without the overhead of creating a Promise.

  // Same priority as Promise.then callbacks.

4. STARVATION — MICROTASK LOOP PITFALL
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  If microtasks keep adding more microtasks, macrotasks NEVER run.
  This is called "microtask starvation".

  // DANGEROUS — infinite microtask loop:
  function badLoop() {
    Promise.resolve().then(badLoop);  // always adds new microtask
  }
  badLoop();
  // setTimeout callbacks will NEVER fire!

  // Contrast with:
  function safeLoop() {
    setTimeout(safeLoop, 0);  // macrotask — yields to other tasks
  }

5. process.nextTick (Node.js only)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  process.nextTick(fn) is NOT a microtask but behaves similarly.
  It runs BEFORE any microtasks (Promise.then callbacks).
  It has the HIGHEST priority in Node.js async scheduling.

  process.nextTick(() => console.log("nextTick"));
  Promise.resolve().then(() => console.log("Promise"));
  setTimeout(() => console.log("timeout"), 0);

  // Output (Node.js):
  // nextTick   ← process.nextTick first
  // Promise    ← microtask
  // timeout    ← macrotask

  // Use case: emit events after constructor runs:
  class MyEmitter extends EventEmitter {
    constructor() {
      super();
      process.nextTick(() => this.emit("ready"));  // ensures listeners attached
    }
  }

6. async/await AND THE MICROTASK QUEUE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Every await suspends the function and schedules resumption as a microtask.

  async function main() {
    console.log("A");
    await Promise.resolve();
    console.log("B");   // microtask — runs after sync code
  }

  main();
  console.log("C");

  // Output: A, C, B
  // "await Promise.resolve()" → pauses main(), continues sync ("C"),
  // then microtask queue: resumes main() → "B"

7. COMMON INTERVIEW QUESTIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: What is the difference between microtasks and macrotasks?
A: Microtasks (Promise.then, queueMicrotask) have higher priority. After
   each macrotask (setTimeout, I/O), ALL microtasks drain before the next
   macrotask runs. Microtasks are processed entirely each loop tick.

Q: Name sources of microtasks and macrotasks.
A: Microtasks: Promise.then/catch/finally, queueMicrotask(), MutationObserver.
   Macrotasks: setTimeout, setInterval, setImmediate, I/O callbacks, UI events.

Q: What is the output?
   setTimeout(() => console.log("A"), 0);
   Promise.resolve().then(() => console.log("B"));
   console.log("C");
A: C → B → A. Sync first, then microtask, then macrotask.

Q: What is microtask starvation?
A: When microtasks continuously schedule new microtasks in an infinite loop,
   preventing any macrotasks (like setTimeout) from ever running.

Q: What does process.nextTick do in Node.js?
A: Schedules a callback to run before any I/O events and before Promise
   microtasks in the current iteration of the event loop. It has the
   highest priority among async callbacks in Node.js.

Q: Why does code after await run asynchronously?
A: await schedules the continuation of the async function as a microtask.
   Even await Promise.resolve() yields execution — control returns to the
   caller, then the continuation runs as a microtask after sync code finishes.
