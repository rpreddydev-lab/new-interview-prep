1. WHAT IS STORYBOOK?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Storybook is an open-source tool for building UI components and pages in
isolation. It allows developers to develop, test, and document components
independently from the application — no need to spin up a full app or navigate
to a specific screen to work on a component.

WEBSITE: https://storybook.js.org
SUPPORTED FRAMEWORKS: React, Vue, Angular, Svelte, Next.js, Ember, and more
CURRENT VERSION: Storybook 8.x (2024)

CORE VALUE PROPOSITIONS:
  1. Develop components in isolation (no app context needed)
  2. Document component variants and states
  3. Enable design system governance — single source of truth for UI
  4. Visual testing and regression detection
  5. Collaboration tool between design, QA, and engineering

CSF = Component Story Format — the current standard for writing stories.

  // src/components/Button/Button.stories.tsx
  import type { Meta, StoryObj } from '@storybook/react';
  import { Button } from './Button';

  // META: Component-level configuration
  const meta: Meta<typeof Button> = {
    title: 'Components/Button',    // Sidebar navigation path
    component: Button,
    parameters: {
      layout: 'centered',          // 'centered' | 'fullscreen' | 'padded'
    },
    tags: ['autodocs'],            // Auto-generate documentation page
    argTypes: {
      variant: {
        control: 'select',
        options: ['primary', 'secondary', 'danger'],
        description: 'Visual style variant of the button',
      },
      size: {
        control: 'radio',
        options: ['sm', 'md', 'lg'],
      },
      onClick: { action: 'clicked' },  // Log click events in Actions tab
    },
  };

  export default meta;
  type Story = StoryObj<typeof meta>;

  // STORIES: Named exports = individual stories
  export const Primary: Story = {
    args: {
      variant: 'primary',
      children: 'Primary Button',
      size: 'md',
    },
  };

  export const Secondary: Story = {
    args: {
      variant: 'secondary',
      children: 'Secondary Button',
      size: 'md',
    },
  };

  export const Danger: Story = {
    args: {
      variant: 'danger',
      children: 'Delete Account',
      size: 'sm',
    },
  };

  export const Disabled: Story = {
    args: {
      ...Primary.args,
      disabled: true,
    },
  };

  // Story with custom render (complex scenarios):
  export const WithIcon: Story = {
    render: (args) => (
      <div style={{ display: 'flex', gap: '8px' }}>
        <Button {...args} />
        <Button {...args} variant="secondary" />
      </div>
    ),
    args: {
      children: 'Save',
    },
  };

DECORATORS: Wrappers applied to all (or specific) stories.

  // .storybook/preview.ts — global decorators
  import type { Preview } from '@storybook/react';
  import { ThemeProvider } from '../src/components/ThemeProvider';
  import '../src/styles/globals.css';  // Import global styles

  const preview: Preview = {
    decorators: [
      (Story) => (
        <ThemeProvider theme="light">
          <Story />
        </ThemeProvider>
      ),
    ],
    parameters: {
      actions: { argTypesRegex: '^on[A-Z].*' },  // Auto-action for event props
      controls: {
        matchers: {
          color: /(background|color)$/i,           // Auto color picker for color props
          date: /Date$/,
        },
      },
    },
  };

  export default preview;

STORY-LEVEL DECORATOR:
  export const WithDarkTheme: Story = {
    decorators: [
      (Story) => (
        <ThemeProvider theme="dark">
          <Story />
        </ThemeProvider>
      ),
    ],
    args: { children: 'Dark Mode Button' },
  };

PLAY FUNCTIONS (interaction testing inside Storybook):
  import { userEvent, within } from '@storybook/testing-library';
  import { expect } from '@storybook/jest';

  export const ClickTest: Story = {
    args: { children: 'Click Me' },
    play: async ({ canvasElement }) => {
      const canvas = within(canvasElement);
      const button = canvas.getByRole('button', { name: /click me/i });
      await userEvent.click(button);
      await expect(button).toBeDisabled(); // Assert state after interaction
    },
  };

REUSE STORIES IN JEST/RTL TESTS:
  // Button.test.tsx
  import { composeStories } from '@storybook/react';
  import { render, screen } from '@testing-library/react';
  import * as stories from './Button.stories';

  const { Primary, Disabled } = composeStories(stories);

  test('Primary button renders correctly', () => {
    render(<Primary />);
    expect(screen.getByRole('button', { name: /primary button/i })).toBeInTheDocument();
  });

  test('Disabled button is not interactive', () => {
    render(<Disabled />);
    expect(screen.getByRole('button')).toBeDisabled();
  });

6. AUTODOCS — AUTO-GENERATED DOCUMENTATION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Adding tags: ['autodocs'] to the meta config auto-generates a documentation
page for the component using:
  - JSDoc comments from the component source
  - TypeScript prop types (via react-docgen-typescript)
  - Story args as interactive examples

The generated page shows:
  - Component description (from JSDoc)
  - Live interactive prop controls (Controls panel)
  - All stories as examples
  - Prop table with types, defaults, descriptions

Q: What is Storybook and why would you use it in a React project?
A: Storybook is a tool for building and documenting UI components in isolation.
   Instead of navigating through a running app to reach a specific component
   state, you define "stories" — small, self-contained scenarios for each
   component variant (Button primary, Button disabled, Button loading). Benefits:
   (1) Faster development — no need to set up app state to work on a component;
   (2) Living documentation — stories are always up to date with code;
   (3) Design-engineering collaboration — designers can view all states in one
   place; (4) Enables visual regression testing via tools like Chromatic;
   (5) The @storybook/addon-a11y panel runs axe on each story for quick a11y checks.

Q: What is the Component Story Format (CSF)?
A: CSF is the standardized way to write Storybook stories. Each story file
   has a default export (meta) with component-level config and named exports
   for individual stories. In CSF3 (current standard), stories use an "args"
   object to define props, and a render function for complex scenarios. This
   format works with TypeScript (Meta<typeof Component> provides full type
   safety), generates prop tables via react-docgen-typescript, and enables
   story reuse in Jest tests via composeStories().

Q: How can stories be reused in unit tests?
A: Using @storybook/react's composeStories() function. You import all stories
   from a .stories.tsx file, then composeStories() applies decorators, args,
   and parameters so each story renders just as it does in Storybook. This
   means you write the component setup once (in the story) and use it in both
   Storybook (for visual QA and documentation) and in Jest (for behavior
   assertions). It avoids duplicating test setup and keeps stories and tests
   in sync.

Q: How does Storybook help with accessibility?
A: The @storybook/addon-a11y addon runs axe-core on every story during
   development and shows violations in an "Accessibility" panel below the
   canvas. Developers get immediate a11y feedback without running a separate
   test suite. This encourages fixing a11y issues at the component level
   before they propagate. You can also combine this with play functions that
   simulate keyboard navigation and with Chromatic's a11y scanning in CI.
