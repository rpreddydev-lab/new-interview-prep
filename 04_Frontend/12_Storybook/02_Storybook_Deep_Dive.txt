SECTION 1 — STORYBOOK FUNDAMENTALS
================================================================================

Q1: What is Storybook and why do teams use it?

A: Storybook is an open-source tool for developing, documenting, and testing
   UI components in isolation — independent of the application.

   CORE VALUE PROPOSITIONS:
   1. ISOLATED DEVELOPMENT: Build components without running the full app
   2. VISUAL DOCUMENTATION: Living docs that stay in sync with code
   3. VISUAL TESTING: Catch UI regressions via screenshot comparisons
   4. DESIGN-DEVELOPER COLLABORATION: Share component states with designers
   5. ACCESSIBILITY TESTING: Built-in a11y addon checks every story

   WITHOUT STORYBOOK PROBLEMS:
   - "Works in my app but not in yours" — undiscovered props/states
   - Difficult to test edge cases (empty state, loading, error)
   - No visual documentation for design system components
   - Regression bugs when component is reused across the app

   WITH STORYBOOK:
   - Every state of every component is explicitly defined as a story
   - New developers can browse all components without opening the app
   - Design system has living, interactive documentation

   STORYBOOK SUPPORTS:
   React, Vue, Angular, Svelte, Web Components, Ember, HTML

Q2: What is Component Story Format (CSF) and how do you write stories?

A: CSF (Component Story Format) is the standard way to write Storybook stories
   in modern Storybook (v6+). Stories are ES module exports.

   BASIC STORY STRUCTURE (CSF3 with TypeScript):

   // Button.stories.tsx
   import type { Meta, StoryObj } from '@storybook/react';
   import { Button } from './Button';

   // Meta: component-level configuration
   const meta: Meta<typeof Button> = {
     title: 'Components/Button',   // folder path in sidebar
     component: Button,
     tags: ['autodocs'],           // auto-generate docs page
     argTypes: {
       variant: {
         control: 'select',
         options: ['primary', 'secondary', 'danger'],
         description: 'Visual style of the button',
       },
       onClick: { action: 'clicked' },  // log clicks in Actions panel
     },
     parameters: {
       layout: 'centered',
     },
   };
   export default meta;

   type Story = StoryObj<typeof Button>;

   // Each named export = one story
   export const Primary: Story = {
     args: {
       label: 'Submit',
       variant: 'primary',
       disabled: false,
     },
   };

   export const Loading: Story = {
     args: {
       label: 'Saving...',
       variant: 'primary',
       loading: true,
     },
   };

   export const Disabled: Story = {
     args: {
       label: 'Not available',
       variant: 'primary',
       disabled: true,
     },
   };

   // Story with complex setup (render function)
   export const WithDropdown: Story = {
     render: (args) => (
       <div style={{ position: 'relative' }}>
         <Button {...args} />
         <DropdownMenu items={['Option 1', 'Option 2']} />
       </div>
     ),
     args: { label: 'Open Menu', variant: 'secondary' },
   };

SECTION 2 — ARGS AND CONTROLS
================================================================================

Q3: Explain Args, ArgTypes, and Controls in Storybook.

A: ARGS:
   - Plain JavaScript objects passed as props to the story component
   - Can be shared from meta (default args) or overridden per story
   - Enables the Controls panel to interactively modify props
   - Args are composable: ...Primary.args can be spread into another story

   ARGTYPES:
   - Describe how each arg should be displayed in the Controls panel
   - Define: type, description, default value, control type
   - TypeScript: argTypes are often inferred automatically from prop types

   CONTROL TYPES:
   control: 'text'            → text input
   control: 'number'          → number input
   control: 'boolean'         → toggle
   control: 'select'          → dropdown (use with options: [...])
   control: 'radio'           → radio buttons
   control: 'color'           → color picker
   control: 'date'            → date picker
   control: 'object'          → JSON editor for complex objects
   control: 'file'            → file upload

   EXAMPLE:
   argTypes: {
     size: {
       control: 'radio',
       options: ['sm', 'md', 'lg'],
       defaultValue: 'md',
       table: {
         category: 'Appearance',
         type: { summary: 'string' },
         defaultValue: { summary: 'md' },
       }
     }
   }

   ARGS COMPOSITION (avoid duplication):
   export const PrimaryLoading: Story = {
     args: {
       ...Primary.args,   // inherit from Primary
       loading: true,
     }
   };

SECTION 3 — ADDONS
================================================================================

Q4: What are the most important Storybook addons?

A:
   BUILT-IN / OFFICIAL ADDONS:

   @storybook/addon-essentials (bundled pack):
   - Controls: interactive prop editing in UI
   - Actions: log events (clicks, changes) in Actions panel
   - Docs:    auto-generated documentation from JSDoc + PropTypes/TypeScript
   - Viewport: simulate mobile/tablet screen sizes
   - Backgrounds: preview component on different background colors
   - Toolbars: add custom toolbar items (locale switcher, theme switcher)

   @storybook/addon-a11y:
   - Runs axe-core accessibility checks on every story
   - Shows violations, warnings, passes in the a11y panel
   - Critical for design system teams; fail CI if accessibility issues found

   @storybook/addon-interactions:
   - Write interaction tests using play functions
   - Simulate user events (click, type, focus) and assert outcomes
   - Tests run automatically in the Storybook UI

   storybook-addon-designs:
   - Embed Figma designs alongside the Storybook story
   - Designers and developers see spec + implementation side-by-side

   MSW Addon (Mock Service Worker):
   - Mock API calls within Storybook using MSW handlers
   - Stories can have different API states: success, loading, error

   INSTALLING ADDONS:
   // .storybook/main.ts
   export default {
     addons: [
       '@storybook/addon-essentials',
       '@storybook/addon-a11y',
       '@storybook/addon-interactions',
       'msw-storybook-addon',
     ],
   };

SECTION 4 — TESTING WITH STORYBOOK
================================================================================

Q5: How do you write interaction tests (play functions) in Storybook?

A: Play functions allow you to write browser-based interaction tests that run
   automatically when a story loads.

   // InvoiceForm.stories.tsx
   import { within, userEvent, expect } from '@storybook/test';

   export const FilledForm: Story = {
     play: async ({ canvasElement }) => {
       const canvas = within(canvasElement);

       // Find elements
       const msisdnInput = canvas.getByLabelText(/phone number/i);
       const submitButton = canvas.getByRole('button', { name: /submit/i });

       // Simulate user typing
       await userEvent.type(msisdnInput, '+447700900001');

       // Simulate button click
       await userEvent.click(submitButton);

       // Assert outcome
       await expect(
         canvas.getByText(/invoice generated/i)
       ).toBeInTheDocument();
     },
   };

   RUNNING PLAY FUNCTIONS IN JEST:
   // Uses @storybook/test-runner to run all stories as tests
   // package.json:
   "scripts": {
     "test:storybook": "test-storybook"
   }

   // Runs all stories + executes play functions as automated tests
   // Integrates with CI: test-storybook --ci

Q6: How do you use Storybook with Mock Service Worker (MSW) for API mocking?

A:
   // .storybook/preview.ts
   import { initialize, mswLoader } from 'msw-storybook-addon';
   initialize();
   export const loaders = [mswLoader];

   // InvoiceList.stories.tsx
   import { http, HttpResponse, delay } from 'msw';

   export const Success: Story = {
     parameters: {
       msw: {
         handlers: [
           http.get('/api/invoices', () =>
             HttpResponse.json([
               { id: '1', amount: 4599, date: '2024-11-01', status: 'PAID' },
               { id: '2', amount: 5200, date: '2024-10-01', status: 'UNPAID' },
             ])
           ),
         ],
       },
     },
   };

   export const Loading: Story = {
     parameters: {
       msw: {
         handlers: [
           http.get('/api/invoices', async () => {
             await delay('infinite'); // hang forever to show loading state
             return HttpResponse.json([]);
           }),
         ],
       },
     },
   };

   export const Error: Story = {
     parameters: {
       msw: {
         handlers: [
           http.get('/api/invoices', () =>
             HttpResponse.json({ message: 'Server error' }, { status: 500 })
           ),
         ],
       },
     },
   };

SECTION 5 — CHROMATIC AND VISUAL REGRESSION TESTING
================================================================================

Q7: What is Chromatic and how does it integrate with Storybook?

A: Chromatic (by Storybook maintainers) is a cloud service that:
   1. Publishes Storybook online for team review
   2. Takes screenshots of every story on every PR
   3. Diffs screenshots against the baseline (approved state)
   4. Blocks PRs if unexpected visual changes are detected

   WORKFLOW:
   1. Developer pushes a PR
   2. Chromatic CI step runs: chromatic --project-token=...
   3. Chromatic renders all stories in real browsers
   4. Compares screenshots pixel-by-pixel with baseline
   5. On change: shows diff; requires designer/developer approval
   6. On approval: new screenshots become the new baseline

   CHROMATIC CI SETUP (GitHub Actions):
   - name: Publish to Chromatic
     uses: chromaui/action@v1
     with:
       projectToken: ${{ secrets.CHROMATIC_PROJECT_TOKEN }}
       exitOnceUploaded: true

   ACCEPTING CHANGES:
   - Intentional change → review diff in Chromatic UI → click "Accept"
   - Unintentional regression → fix the code; re-push

   SELF-HOSTED ALTERNATIVE: reg-suit + storycap (open source)

SECTION 6 — STORYBOOK WITH DESIGN SYSTEMS
================================================================================

Q8: How do you use Storybook to build and document a design system?

A: DESIGN SYSTEM STORYBOOK STRUCTURE:
   stories/
   ├── Introduction.mdx          (Welcome/overview page)
   ├── design-tokens/
   │   ├── Colors.stories.tsx    (Color palette grid)
   │   ├── Typography.stories.tsx
   │   └── Spacing.stories.tsx
   ├── components/
   │   ├── Button/
   │   │   ├── Button.stories.tsx
   │   │   └── Button.mdx        (Written documentation page)
   │   └── Input/
   └── patterns/
       └── LoginForm.stories.tsx

   MDX DOCUMENTATION PAGE:
   {/* Button.mdx */}
   import { Canvas, Meta, Controls } from '@storybook/blocks';
   import * as ButtonStories from './Button.stories';

   <Meta of={ButtonStories} />

   # Button

   The Button component is used for primary actions. It supports three variants:
   primary, secondary, and danger.

   ## Interactive Preview
   <Canvas of={ButtonStories.Primary} />

   ## Controls
   <Controls of={ButtonStories.Primary} />

   ## Accessibility
   Buttons use semantic `<button>` elements and support keyboard navigation.
   Always provide a meaningful label (not just "Click here").

   THEME SWITCHER (light/dark mode):
   // .storybook/preview.tsx
   import { ThemeProvider } from '../src/theme';
   export const decorators = [
     (Story, context) => (
       <ThemeProvider theme={context.globals.theme ?? 'light'}>
         <Story />
       </ThemeProvider>
     ),
   ];
   export const globalTypes = {
     theme: {
       name: 'Theme',
       toolbar: { icon: 'paintbrush', items: ['light', 'dark'], dynamicTitle: true },
     },
   };

QUICK REFERENCE CHEAT SHEET
================================================================================

STORYBOOK CORE CONCEPTS:
  Story = a named component state (exported function/object from *.stories.tsx)
  Args = props passed to the story (interactive via Controls panel)
  ArgTypes = metadata about args (control type, description, options)
  Decorators = wrappers around stories (ThemeProvider, Router, Redux store)
  Parameters = story-level config (layout, backgrounds, MSW handlers)

CSF3 SYNTAX:
  export default meta (Meta<typeof Component>)
  export const StoryName: Story = { args: {...}, play: async ({canvasElement}) => {...} }
  tags: ['autodocs'] → auto-generates Docs page from prop types + JSDoc

ESSENTIAL ADDONS:
  @storybook/addon-essentials  → Controls + Actions + Docs + Viewport + Backgrounds
  @storybook/addon-a11y        → accessibility checks (axe-core)
  @storybook/addon-interactions → play functions + userEvent testing
  msw-storybook-addon          → mock API calls per story

TESTING:
  play functions:  userEvent.click/type + expect assertions; runs in browser
  test-storybook:  run all story play functions as automated Jest-like tests
  Chromatic:       visual regression testing; screenshot diff on every PR

DESIGN SYSTEM USE:
  token stories (colors, spacing), component stories, MDX docs, theme decorator
  Chromatic: publish + visual approval workflow for design reviews
