━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q1: Why were Hooks introduced? What problem do they solve?
A: Hooks solve three class component problems:
   (1) Stateful logic was hard to reuse — HOCs and render props created wrapper hell.
   (2) Lifecycle methods mixed unrelated logic (subscriptions + data fetching in
       componentDidMount).
   (3) Classes are confusing — "this" binding, boilerplate constructors, and 
       poor minification. Hooks let you extract stateful logic into reusable
       functions without changing component hierarchy.

Q2: What are the Rules of Hooks?
A: (1) Only call hooks at the top level — not inside conditions, loops, or nested
   functions. This ensures hooks are called in the same order every render.
   (2) Only call hooks from React functions — functional components or custom hooks.
   The eslint-plugin-react-hooks enforces both rules.

Q3: What is the difference between useState and useReducer?
A: useState is a simplified version of useReducer for single values.
   Use useReducer when: state has multiple sub-values, next state depends on
   previous state in complex ways, or you want to extract logic from the
   component. useReducer's dispatch is stable and can be passed down without
   useCallback.

Q4: Why does useState setState not immediately update the variable?
A: useState is asynchronous from the component's perspective. After calling
   setState, the current render cycle still uses the old value — state is a
   snapshot. The new value is used in the next render. Use the functional
   updater form (setState(prev => prev + 1)) to safely work with the previous
   state.

Q5: What is the closure (stale closure) problem with useEffect?
A: useEffect captures variables from the render they were created in.
   If a dependency changes but isn't in the dependency array, the effect
   continues using the stale captured value. Fix: add the variable to the
   dependency array, or use a ref to access the latest value without
   subscribing to changes.

Q6: What is the difference between useEffect and useLayoutEffect?
A: useEffect fires AFTER the browser paints (async). useLayoutEffect fires
   synchronously AFTER DOM mutations and BEFORE the browser paints. Use
   useLayoutEffect only when you need to measure the DOM and prevent a visual
   flicker. Default to useEffect for everything else.

Q7: What does the useEffect cleanup function do?
A: It runs before the effect re-runs (when deps change) and when the component
   unmounts. Use it to cancel subscriptions, timers, or fetch requests to
   prevent memory leaks and state updates on unmounted components.

Q8: When would you use useRef over useState?
A: Use useRef when you need to track a value that should NOT trigger re-renders
   when it changes. Common cases: timer IDs, previous values, mutable flags
   (isMounted), and DOM element references.

Q9: What is the difference between useMemo and useCallback?
A: useMemo memoizes a COMPUTED VALUE — the result of a function.
   useCallback memoizes a FUNCTION REFERENCE itself.
   useCallback(fn, deps) is equivalent to useMemo(() => fn, deps).
   Use useMemo to avoid re-computing expensive values. Use useCallback to
   provide stable function references to memoized child components or
   effect dependency arrays.

Q10: What is a custom hook? When would you create one?
A: A custom hook is a function whose name starts with "use" that calls
   other hooks. Create one to: extract reusable stateful logic shared
   between components, abstract away complex effect management, or provide
   a clean API over browser APIs (useLocalStorage, useWindowSize).

Q11: How does React track hook call order internally?
A: React maintains a linked list of "memoized state" nodes per component
   fiber. Each hook call corresponds to a node in the list, accessed by
   index. If hooks are called conditionally, the indices shift, corrupting
   all subsequent hooks. This is why hooks must be called unconditionally
   and in the same order every render.

Q12: What is the useTransition hook and when would you use it?
A: useTransition marks a state update as non-urgent (a "transition"). React
   processes urgent updates first (user typing) and defers the transition
   update. This keeps the UI responsive. Returns [isPending, startTransition].
   Use for tab switching, filtering large lists, page navigations.

Q13: What is the useId hook?
A: useId generates a stable, unique ID that is consistent between server and
   client renders. Used for accessible form label-input associations
   (htmlFor/id) in components that might be rendered multiple times.

Q14: What is useInsertionEffect?
A: A hook that fires synchronously BEFORE any DOM mutations — designed for
   CSS-in-JS library authors to inject styles at the right time. Application
   developers should not use it.

Q15: What is useSyncExternalStore?
A: A hook for subscribing to external stores (non-React state like browser
   APIs, Zustand, or custom event emitters) in a way that's compatible with
   Concurrent Mode. Replaces the old "tearing" problem where concurrent renders
   could see different snapshots of external state.

Q16: Write a custom useFetch hook.
A:
  function useFetch(url) {
    const [data, setData] = useState(null);
    const [loading, setLoading] = useState(true);
    const [error, setError] = useState(null);

    useEffect(() => {
      const controller = new AbortController();
      setLoading(true);
      setError(null);

      fetch(url, { signal: controller.signal })
        .then(r => { if (!r.ok) throw new Error(r.statusText); return r.json(); })
        .then(setData)
        .catch(err => { if (err.name !== 'AbortError') setError(err.message); })
        .finally(() => setLoading(false));

      return () => controller.abort();  // cleanup cancels the request
    }, [url]);

    return { data, loading, error };
  }

Q17: What does this code print?
  function Counter() {
    const [count, setCount] = useState(0);
    function handleClick() {
      setCount(count + 1);
      setCount(count + 1);
    }
    return <button onClick={handleClick}>{count}</button>;
  }
A: Clicking the button changes count by 1, not 2. Both setCount calls use
   the same stale closure value of count (0). Both set it to 0+1=1.
   Fix: setCount(c => c + 1) twice → will correctly reach 2.

Q18: What is wrong with this useEffect?
  useEffect(() => {
    fetchUser(userId).then(setUser);
  });  // no dependency array
A: Missing dependency array means the effect runs after EVERY render.
   This creates an infinite loop: mount → fetch → setUser → re-render →
   fetch again → setUser → re-render...
   Fix: add [userId] as the dependency array.
