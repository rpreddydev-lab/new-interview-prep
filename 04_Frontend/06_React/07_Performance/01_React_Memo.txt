1. WHY COMPONENTS RE-RENDER
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

A React component re-renders when:
  1. Its own state changes
  2. Its parent re-renders (even if props didn't change)
  3. Its context value changes
  4. A hook it uses returns a new value

The default behavior: Parent re-renders → all children re-render.
This is fine for most cases but can be wasteful for heavy child components.

2. React.memo
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

React.memo is a HOC that memoizes a component. It skips re-rendering if props
haven't changed (shallow comparison of each prop).

  // WITHOUT memo:
  function ExpensiveList({ items }) {
    return <ul>{items.map(i => <ExpensiveItem key={i.id} item={i} />)}</ul>;
  }
  // Parent re-renders → ExpensiveList always re-renders, even if items didn't change

  // WITH memo:
  const ExpensiveList = React.memo(function ExpensiveList({ items }) {
    return <ul>{items.map(i => <ExpensiveItem key={i.id} item={i} />)}</ul>;
  });
  // Parent re-renders → ExpensiveList only re-renders if `items` reference changes

  Usage pattern:
  function ParentComponent() {
    const [count, setCount] = useState(0);
    const [items] = useState([...]);  // stable reference

    return (
      <div>
        <button onClick={() => setCount(c => c + 1)}>Count: {count}</button>
        <ExpensiveList items={items} />  {/* won't re-render on count change */}
      </div>
    );
  }

3. SHALLOW COMPARISON — THE TRAP
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

React.memo uses shallow equality: each prop value is compared with ===.
For objects and arrays, === checks REFERENCE (identity), not content.

  // PROBLEM: New object on every render defeats memo
  function Parent() {
    const [count, setCount] = useState(0);

    return (
      <MemoChild
        style={{ color: 'red' }}       // ❌ New object every render → always re-renders
        onClick={() => console.log()}  // ❌ New function every render → always re-renders
      />
    );
  }

  // FIX: Stable references
  const style = { color: 'red' };                    // outside component
  const handleClick = useCallback(() => console.log(), []);  // useCallback
  <MemoChild style={style} onClick={handleClick} />

4. CUSTOM COMPARISON FUNCTION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

React.memo accepts an optional second argument for custom comparison.
Returns true to SKIP re-render (props are considered equal),
returns false to re-render.

  const TodoItem = React.memo(
    function TodoItem({ todo, onToggle }) {
      return (
        <li onClick={() => onToggle(todo.id)}
            style={{ textDecoration: todo.done ? 'line-through' : 'none' }}>
          {todo.text}
        </li>
      );
    },
    (prevProps, nextProps) => {
      // Only re-render if todo or onToggle identity changes
      return prevProps.todo === nextProps.todo &&
             prevProps.onToggle === nextProps.onToggle;
    }
  );

5. WHEN TO USE (AND NOT USE) React.memo
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  USE React.memo when:
  - Component renders frequently with the same props
  - Component is expensive to render (long lists, heavy computation in render)
  - Pure presentational component with stable props
  - Component is a child of a frequently-updating parent

  DO NOT use React.memo when:
  - Component almost always re-renders with new props (memo adds overhead)
  - Props include functions/objects without useCallback/useMemo (memo is pointless)
  - The component is lightweight (re-rendering is cheap anyway)
  - Premature optimization before profiling shows a real issue

  React.memo cost: shallow comparison on every parent render.
  If comparison is more expensive than a cheap re-render, it's counterproductive.

6. React.memo vs useMemo vs useCallback
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  React.memo:     Memoizes a COMPONENT — skips re-render if props didn't change
  useMemo:        Memoizes a COMPUTED VALUE — skips recalculation between renders
  useCallback:    Memoizes a FUNCTION — returns the same function reference

  They work together:
    const sortedItems = useMemo(() => [...items].sort(), [items]);     // stable value
    const handleClick = useCallback(() => doSomething(id), [id]);     // stable function
    <MemoChild items={sortedItems} onClick={handleClick} />           // memo can skip

7. COMMON INTERVIEW QUESTIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: What does React.memo do?
A: React.memo is a higher-order component that memoizes a functional component.
   It shallowly compares props on each parent render and skips re-rendering the
   child if no props changed.

Q: Why doesn't React.memo work when I pass an inline function or object?
A: Because inline functions and objects create new references on every render.
   Shallow equality (===) compares references, so {} !== {} even if they look
   the same. Use useCallback for functions and useMemo (or stable variables) for
   objects.

Q: What is the difference between React.memo and shouldComponentUpdate?
A: Both prevent unnecessary re-renders. shouldComponentUpdate is a class
   component lifecycle method where you manually compare props/state.
   React.memo is a HOC for functional components that automatically does
   shallow prop comparison.

Q: Should you wrap every component with React.memo?
A: No. React.memo adds the overhead of a prop comparison on every parent render.
   For cheap components, this overhead can exceed the benefit of skipping the
   render. Profile first, then memoize where there's a measured performance issue.
