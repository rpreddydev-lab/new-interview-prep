1. i18n CONCEPTS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

i18n (internationalization): process of designing software to support multiple
  languages and regions. "i18n" = i + 18 letters + n.

l10n (localization): adapting a product for a specific locale — translating
  strings, formatting dates/numbers/currencies according to regional conventions.

KEY CONCERNS:
  - Text translation (string keys → locale strings)
  - Pluralization (1 item vs 2 items vs 5 items — rules differ by language)
  - Date/time formatting (US: MM/DD/YYYY, Europe: DD/MM/YYYY)
  - Number formatting (1,234.56 in US, 1.234,56 in Germany)
  - Currency (USD, EUR, JPY — symbol position differs)
  - RTL (Right-to-Left) support (Arabic, Hebrew, Persian)
  - Dynamic string interpolation ("Hello, {{name}}")

2. REACT-I18NEXT
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Most popular i18n library for React.
npm install react-i18next i18next i18next-http-backend i18next-browser-languagedetector

SETUP:
  // src/i18n.js
  import i18n from 'i18next';
  import { initReactI18next } from 'react-i18next';
  import LanguageDetector from 'i18next-browser-languagedetector';
  import Backend from 'i18next-http-backend';

  i18n
    .use(Backend)              // Load translations from /public/locales/{lang}/{ns}.json
    .use(LanguageDetector)     // Detect user language from browser/cookie/localStorage
    .use(initReactI18next)     // Pass i18n instance to react-i18next
    .init({
      fallbackLng: 'en',       // Fallback if translation missing
      debug: process.env.NODE_ENV === 'development',
      interpolation: {
        escapeValue: false,    // React already escapes by default
      },
      backend: {
        loadPath: '/locales/{{lng}}/{{ns}}.json',
      },
    });

  export default i18n;

  // src/index.js
  import './i18n'; // Initialize before App renders
  import App from './App';

USING IN COMPONENTS:
  import { useTranslation } from 'react-i18next';

  function Header({ userName }) {
    const { t, i18n } = useTranslation('common'); // 'common' = namespace

    return (
      <header>
        <h1>{t('welcome', { name: userName })}</h1>      {/* Interpolation */}
        <p>{t('items', { count: 5 })}</p>                {/* Pluralization */}
        <nav>
          <a href="/">{t('nav.home')}</a>               {/* Nested key */}
          <a href="/products">{t('nav.products')}</a>
        </nav>
        <select
          value={i18n.language}
          onChange={(e) => i18n.changeLanguage(e.target.value)}
        >
          <option value="en">English</option>
          <option value="de">Deutsch</option>
          <option value="ar">العربية</option>
        </select>
      </header>
    );
  }

TRANS COMPONENT (for JSX-embedded translations):
  import { Trans } from 'react-i18next';
  // Translation: "Read our <1>privacy policy</1>"
  // en.json: "readPolicy": "Read our <1>privacy policy</1>"

  <Trans i18nKey="readPolicy">
    Read our <a href="/privacy">privacy policy</a>
  </Trans>

3. NEXT.JS INTERNATIONALIZATION (next-intl)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

next-intl is the standard for Next.js 13+ App Router i18n.

  npm install next-intl

SETUP (App Router):
  // middleware.ts — handle locale routing
  import createMiddleware from 'next-intl/middleware';

  export default createMiddleware({
    locales: ['en', 'de', 'ar'],
    defaultLocale: 'en',
  });

  export const config = {
    matcher: ['/((?!api|_next|.*\\..*).*)']
  };

FILE STRUCTURE:
  app/
  ├── [locale]/          ← Dynamic locale segment
  │   ├── layout.tsx
  │   ├── page.tsx
  │   └── products/
  │       └── page.tsx
  messages/
  ├── en.json
  ├── de.json
  └── ar.json

  // app/[locale]/layout.tsx
  import { NextIntlClientProvider } from 'next-intl';
  import { getMessages } from 'next-intl/server';

  export default async function LocaleLayout({ children, params: { locale } }) {
    const messages = await getMessages();
    return (
      <html lang={locale} dir={locale === 'ar' ? 'rtl' : 'ltr'}>
        <body>
          <NextIntlClientProvider messages={messages}>
            {children}
          </NextIntlClientProvider>
        </body>
      </html>
    );
  }

  // Server Component usage:
  import { getTranslations } from 'next-intl/server';

  export default async function ProductsPage() {
    const t = await getTranslations('Products');
    return <h1>{t('title')}</h1>;
  }

  // Client Component usage:
  'use client';
  import { useTranslations } from 'next-intl';

  export default function AddToCart() {
    const t = useTranslations('Cart');
    return <button>{t('addButton')}</button>;
  }

4. DATE, NUMBER, AND CURRENCY FORMATTING
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Always use the native Intl API — never hardcode formats.

DATE FORMATTING:
  const date = new Date('2026-04-09');

  // US English: April 9, 2026
  new Intl.DateTimeFormat('en-US', { dateStyle: 'long' }).format(date);

  // German: 9. April 2026
  new Intl.DateTimeFormat('de-DE', { dateStyle: 'long' }).format(date);

  // Relative time:
  const rtf = new Intl.RelativeTimeFormat('en', { numeric: 'auto' });
  rtf.format(-1, 'day'); // "yesterday"
  rtf.format(-3, 'day'); // "3 days ago"

NUMBER FORMATTING:
  new Intl.NumberFormat('en-US').format(1234567.89); // "1,234,567.89"
  new Intl.NumberFormat('de-DE').format(1234567.89); // "1.234.567,89"

CURRENCY FORMATTING:
  new Intl.NumberFormat('en-US', {
    style: 'currency', currency: 'USD'
  }).format(99.99); // "$99.99"

  new Intl.NumberFormat('de-DE', {
    style: 'currency', currency: 'EUR'
  }).format(99.99); // "99,99 €"

  new Intl.NumberFormat('ja-JP', {
    style: 'currency', currency: 'JPY'
  }).format(9999); // "¥9,999"

5. RTL (RIGHT-TO-LEFT) SUPPORT
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

RTL languages: Arabic (ar), Hebrew (he), Persian (fa), Urdu (ur)

HTML:
  <html lang="ar" dir="rtl">  // Sets text direction for the whole page

CSS LOGICAL PROPERTIES (RTL-safe, preferred over left/right):
  /* Instead of: */          /* Use: */
  margin-left: 16px;         margin-inline-start: 16px;
  margin-right: 16px;        margin-inline-end: 16px;
  padding-left: 8px;         padding-inline-start: 8px;
  border-left: 1px solid;    border-inline-start: 1px solid;
  text-align: left;          text-align: start;
  text-align: right;         text-align: end;

CSS DIRECTION-SPECIFIC OVERRIDES:
  /* If you must write RTL-specific styles: */
  [dir="rtl"] .icon {
    transform: scaleX(-1); /* Flip directional icons like arrows */
  }

TAILWIND RTL:
  <div className="ml-4 rtl:mr-4 rtl:ml-0">  // Tailwind RTL variant

REACT COMPONENT EXAMPLE:
  function Layout({ locale }) {
    const isRTL = ['ar', 'he', 'fa', 'ur'].includes(locale);
    return (
      <div dir={isRTL ? 'rtl' : 'ltr'} lang={locale}>
        {/* content */}
      </div>
    );
  }

6. INTERVIEW QUESTIONS — i18n
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: What is the difference between i18n and l10n?
A: i18n (internationalization) is the engineering process of building software
   so it CAN support multiple languages and regions — designing with string
   externalization, flexible layouts, locale-aware formatting. l10n (localization)
   is the process of actually adapting the software for a specific locale —
   translating strings, adjusting date/number formats, cultural adaptation.
   i18n is done once by engineers; l10n is done per-locale, often by translators.

Q: How do you handle pluralization in i18n?
A: Different languages have very different plural rules. English has two forms
   (1 item, 2+ items). Arabic has six forms. Russian has three. Libraries like
   react-i18next use the ICU message format and the CLDR plural rules to handle
   this. In react-i18next, you define keys like "items_one", "items_other" (or
   "items_zero", "items_two", "items_few", "items_many" for complex languages).
   The library automatically selects the right form based on the count value
   and the current locale's plural rules.

Q: What are CSS logical properties and why do they matter for i18n?
A: CSS logical properties (margin-inline-start, padding-inline-end, etc.) define
   spacing relative to the document flow direction rather than physical sides.
   margin-inline-start means "left in LTR, right in RTL" — automatically adapts.
   Without them, RTL support requires CSS overrides like [dir="rtl"] .foo { margin-right: 16px; }
   for every rule that uses margin-left. Logical properties eliminate this
   duplication and make RTL just a matter of setting dir="rtl" on the HTML element.

Q: How does Next.js handle internationalized routing?
A: With the App Router + next-intl, you use a [locale] dynamic segment at the
   root of the app directory. A middleware intercepts all requests, detects
   the user's preferred locale (from Accept-Language header, cookie, or URL),
   and redirects/rewrites to the correct locale path. URLs become /en/products
   and /de/products. Server Components use getTranslations() which reads from
   the messages/{locale}.json files. This is SEO-friendly (each locale has its
   own URL), and the server renders each locale's content directly.
