1. THE TWO RULES OF HOOKS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

RULE 1: Only call Hooks at the TOP LEVEL
  - Don't call hooks inside loops, conditions, or nested functions
  - Always call hooks in the same order on every render

RULE 2: Only call Hooks from REACT FUNCTIONS
  - Call from functional components
  - Call from custom hooks (functions starting with 'use')
  - NOT from regular JavaScript functions, class components, or global code

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
2. WHY RULE 1 EXISTS: THE ORDER PROBLEM
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

React tracks hooks by their ORDER OF CALL. Internally, React stores hook state
in a linked list indexed by call order (hook #1, hook #2, etc.).

  // On each render, React expects the SAME number of hooks in SAME order:
  function Counter({ condition }) {
    const [count, setCount] = useState(0);      // Hook #1
    const [name, setName] = useState('Alice');  // Hook #2
    // React: hook #1 → count, hook #2 → name (consistent)
  }

  // VIOLATION: Conditional hook — different number of hooks based on condition
  function Counter({ showExtra }) {
    const [count, setCount] = useState(0);       // Hook #1 always

    if (showExtra) {
      const [extra, setExtra] = useState(null);  // SOMETIMES Hook #2 ← WRONG!
    }

    const [name, setName] = useState('');  // Sometimes Hook #2, sometimes Hook #3!
    // React gets confused about which hook state belongs to which hook!
  }

  // What happens: React might assign 'name' state to the 'extra' hook slot
  // → completely wrong state values → bugs that are very hard to debug

3. EXAMPLES OF VIOLATIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

VIOLATION: Hook inside if statement
  function MyComponent({ isAdmin }) {
    // WRONG:
    if (isAdmin) {
      const [adminData, setAdminData] = useState(null); // conditional hook!
    }
    // ...
  }

  // FIX: Call hook unconditionally, use condition INSIDE the hook's effect:
  function MyComponent({ isAdmin }) {
    const [adminData, setAdminData] = useState(null); // always called
    useEffect(() => {
      if (isAdmin) fetchAdminData().then(setAdminData); // condition inside
    }, [isAdmin]);
  }

VIOLATION: Hook inside loop
  function MyComponent({ items }) {
    // WRONG: number of hook calls changes with items.length
    items.forEach(item => {
      const [selected, setSelected] = useState(false); // WRONG!
    });
  }

  // FIX: Lift state out, use an object/array indexed by item:
  function MyComponent({ items }) {
    const [selectedMap, setSelectedMap] = useState({});
    // or extract each item to its own component (each with its own useState)
  }

VIOLATION: Hook inside nested function
  function MyComponent() {
    // WRONG:
    function handleClick() {
      const [data, setData] = useState(null); // WRONG — not top-level of component
    }
  }

  // FIX: Hooks must be at the top level of the component function
  function MyComponent() {
    const [data, setData] = useState(null); // top level ✓
    function handleClick() {
      setData(/* ... */);
    }
  }

VIOLATION: Hook in class component
  class MyClass extends Component {
    render() {
      const [count, setCount] = useState(0); // WRONG — hooks can't be in classes
    }
  }

VIOLATION: Hook in regular function
  function regularFunction() {
    const [x, setX] = useState(0); // WRONG — not a hook or React component
  }

Install: npm install eslint-plugin-react-hooks

Rules:
  "react-hooks/rules-of-hooks": "error"  // enforces the two rules
  "react-hooks/exhaustive-deps": "warn"  // enforces correct dependency arrays

These rules are enabled by default in Create React App and most modern setups.
They catch violations at compile time before they cause runtime bugs.

5. HOW REACT TRACKS HOOKS INTERNALLY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Each component instance has an internal "fiber" which contains a linked list
of hook state objects (called the "memoized state" queue):

  Component renders for first time:
    useState(0)    → memoized state slot #1 = { state: 0, next: → }
    useState('')   → memoized state slot #2 = { state: '', next: → }
    useEffect(...) → memoized state slot #3 = { effect: {...}, next: null }

  Component renders again:
    useState(0)    → React reads slot #1 → state is 0 (or updated value)
    useState('')   → React reads slot #2 → state is '' (or updated value)
    useEffect(...) → React reads slot #3 → compares deps, runs if changed

  If a hook is added/removed/reordered:
    The linked list gets out of sync → wrong state assigned to wrong hook → bugs

6. COMMON INTERVIEW QUESTIONS ON RULES OF HOOKS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: What are the Rules of Hooks?
A: 1. Call hooks only at the top level (not in loops, conditions, or nested functions)
   2. Call hooks only from React functional components or custom hooks.

Q: Why can't you call hooks inside if statements?
A: React tracks hooks by their call ORDER. A conditional hook would change the
   number of hooks called between renders, causing React to map the wrong state
   to the wrong hook. The result is corrupted state and unpredictable behavior.

Q: How does React know which state belongs to which hook call?
A: Hooks are stored in order in a linked list per component fiber. Each render,
   React goes through the same list in the same order. The nth useState call
   always maps to the nth slot. Order must be consistent.

Q: How can you conditionally run hook logic?
A: Call the hook unconditionally, put the condition INSIDE:
   useEffect(() => {
     if (condition) { /* do something */ }
   }, [condition]);
   Or put the condition inside the state initialization, or move the conditional
   component to its own component and conditionally render it.

Q: What is the eslint-plugin-react-hooks?
A: An ESLint plugin that statically analyzes code to enforce the Rules of Hooks
   and validate useEffect dependency arrays. Prevents hook-related bugs at dev time.
