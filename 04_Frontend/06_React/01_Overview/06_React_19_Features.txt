================================================================================
REACT 19 FEATURES - INTERVIEW PREPARATION
================================================================================

React 19 was officially released in December 2024. It builds on React 18's
concurrent model and introduces first-class support for async operations,
a new compiler, and improved ergonomics for server-driven applications.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1. REACT COMPILER (FORMERLY "REACT FORGET")
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

WHAT IT IS:
  A build-time compiler that automatically memoizes components, hooks, and
  values — eliminating the need to manually write useMemo, useCallback, and
  React.memo in most cases.

HOW IT WORKS:
  The compiler analyzes your component code and inserts memoization
  automatically where it is safe to do so, based on React's rules of hooks
  and purity constraints.

BEFORE (React 18 — manual memoization):
  function ProductList({ products, onSelect }) {
    const sorted = useMemo(
      () => products.sort((a, b) => a.name.localeCompare(b.name)),
      [products]
    );
    const handleSelect = useCallback(
      (id) => onSelect(id),
      [onSelect]
    );
    return sorted.map(p => (
      <ProductCard key={p.id} product={p} onSelect={handleSelect} />
    ));
  }

AFTER (React 19 with compiler — no manual memoization needed):
  function ProductList({ products, onSelect }) {
    const sorted = products.sort((a, b) => a.name.localeCompare(b.name));
    return sorted.map(p => (
      <ProductCard key={p.id} product={p} onSelect={onSelect} />
    ));
  }
  // Compiler automatically figures out what to memoize

SETUP:
  npm install babel-plugin-react-compiler
  // or with Next.js 15+:
  // experimental: { reactCompiler: true } in next.config.js

REQUIREMENTS:
  - Components and hooks must follow the Rules of React (no mutations, pure render)
  - TypeScript or JavaScript — both supported
  - Opt-out: add 'use no memo'; directive at top of component

KEY POINT FOR INTERVIEWS:
  The compiler does NOT change runtime behavior. It only optimizes re-renders.
  Code that was incorrect before (violating Rules of React) will still be incorrect.

2. NEW HOOK: use()
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

WHAT IT IS:
  A new primitive that lets you "unwrap" a Promise or Context inside a
  component — without needing a separate useEffect + useState pattern.

  Unlike regular hooks, use() CAN be called conditionally.

READING CONTEXT WITH use():
  // Before (React 18):
  const theme = useContext(ThemeContext);

  // React 19 — equivalent but more flexible:
  import { use } from 'react';
  const theme = use(ThemeContext);

  // use() can be called conditionally (unlike useContext):
  function Component({ showTheme }) {
    if (showTheme) {
      const theme = use(ThemeContext); // ✅ legal with use()
    }
  }

READING PROMISES WITH use() + Suspense:
  // Fetch function (returns a Promise)
  function fetchUser(id) {
    return fetch(`/api/users/${id}`).then(r => r.json());
  }

  // Parent: creates the promise and passes it down
  function UserPage({ userId }) {
    const userPromise = fetchUser(userId); // Promise created outside component
    return (
      <Suspense fallback={<Spinner />}>
        <UserProfile promise={userPromise} />
      </Suspense>
    );
  }

  // Child: unwraps the promise with use()
  function UserProfile({ promise }) {
    const user = use(promise); // Suspends until resolved; throws on rejection
    return <h1>{user.name}</h1>;
  }

WHY THIS MATTERS:
  - No more boilerplate: loading state + error state + data state pattern
  - Works seamlessly with Suspense and Error Boundaries
  - Enables data passing from Server Components to Client Components via promises

IMPORTANT RULES:
  - The Promise must be created OUTSIDE the component (or cached), not inside
  - If created inside the component, a new Promise is created every render → infinite loop
  - Always pair with an Error Boundary to handle promise rejections

3. NEW HOOK: useOptimistic()
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

WHAT IT IS:
  A hook for optimistic UI updates — showing the user an expected result
  immediately while a server operation is in flight, then reverting or
  confirming once the server responds.

SIGNATURE:
  const [optimisticValue, addOptimistic] = useOptimistic(
    serverValue,          // The actual server state
    updateFn              // (currentState, optimisticData) => newState
  );

EXAMPLE — Optimistic Like Button:
  function LikeButton({ postId, initialLikes }) {
    const [likes, setLikes] = useState(initialLikes);
    const [optimisticLikes, addOptimisticLike] = useOptimistic(
      likes,
      (currentLikes, increment) => currentLikes + increment
    );

    async function handleLike() {
      addOptimisticLike(1); // Immediately show +1 like
      try {
        const newLikes = await likePost(postId); // Wait for server
        setLikes(newLikes); // Confirm with real value
      } catch {
        // useOptimistic automatically reverts to `likes` on error
      }
    }

    return (
      <button onClick={handleLike}>
        ❤️ {optimisticLikes}
      </button>
    );
  }

HOW IT WORKS INTERNALLY:
  - While a transition is pending: shows the optimistic value
  - When the transition completes: shows the real server value
  - If the transition fails: automatically reverts to original value
  - Must be used inside startTransition or an Action

4. ACTIONS AND NEW FORM HOOKS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

ACTIONS:
  React 19 introduces the concept of "Actions" — async functions that handle
  user interactions (like form submissions) with built-in pending, error, and
  optimistic state management.

  By convention, functions that use async transitions are called Actions.

FORM ACTIONS (Native HTML Integration):
  // React 19: pass an async function directly to form's action prop
  async function createUser(formData) {
    'use server'; // (Next.js Server Action) OR client-side async function
    const name = formData.get('name');
    await db.users.create({ name });
  }

  function NewUserForm() {
    return (
      <form action={createUser}>
        <input name="name" placeholder="Username" />
        <button type="submit">Create</button>
      </form>
    );
  }
  // React handles pending state, resets form on success automatically

useFormStatus():
  A hook that reads the status of a parent <form> — whether it is pending
  submission. Must be called in a component that is a CHILD of the form.

  import { useFormStatus } from 'react-dom';

  function SubmitButton() {
    const { pending } = useFormStatus();
    return (
      <button type="submit" disabled={pending}>
        {pending ? 'Saving...' : 'Save'}
      </button>
    );
  }

  function MyForm() {
    return (
      <form action={submitAction}>
        <input name="title" />
        <SubmitButton /> {/* SubmitButton is child of form — can read status */}
      </form>
    );
  }

  // useFormStatus() returns: { pending, data, method, action }

useActionState():
  Combines form state management + actions into one hook.
  Replaces the old useFormState() (react-dom) with a cleaner API.

  import { useActionState } from 'react';

  async function updateName(prevState, formData) {
    const name = formData.get('name');
    if (!name) return { error: 'Name is required' };
    await db.updateName(name);
    return { success: true };
  }

  function ProfileForm() {
    const [state, formAction, isPending] = useActionState(
      updateName,
      { error: null, success: false } // initial state
    );

    return (
      <form action={formAction}>
        <input name="name" />
        {state.error && <p className="error">{state.error}</p>}
        {state.success && <p>Updated!</p>}
        <button disabled={isPending}>
          {isPending ? 'Updating...' : 'Update'}
        </button>
      </form>
    );
  }

5. REF AS A PROP (No More forwardRef)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

BEFORE (React 18 — required forwardRef for custom components):
  const FancyInput = React.forwardRef((props, ref) => {
    return <input ref={ref} {...props} />;
  });
  // Usage: <FancyInput ref={myRef} />

REACT 19 — ref is just a regular prop:
  function FancyInput({ ref, ...props }) {
    return <input ref={ref} {...props} />;
  }
  // Usage: <FancyInput ref={myRef} /> — same, but no forwardRef needed!

  // forwardRef still works for backward compatibility, but is deprecated.

CLEANUP FUNCTIONS IN REFS:
  React 19 also supports returning a cleanup function from a ref callback:
  <input
    ref={(node) => {
      // Setup
      node?.addEventListener('focus', handler);
      // Cleanup (runs when element unmounts)
      return () => node?.removeEventListener('focus', handler);
    }}
  />

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

BEFORE (React 18 — needed react-helmet or Next.js Head):
  import { Helmet } from 'react-helmet';
  function ProductPage({ product }) {
    return (
      <>
        <Helmet>
          <title>{product.name}</title>
          <meta name="description" content={product.description} />
        </Helmet>
        <ProductDetails product={product} />
      </>
    );
  }

REACT 19 — use metadata tags anywhere in the tree:
  function ProductPage({ product }) {
    return (
      <>
        <title>{product.name}</title>
        <meta name="description" content={product.description} />
        <link rel="canonical" href={`https://example.com/products/${product.id}`} />
        <ProductDetails product={product} />
      </>
    );
  }
  // React automatically hoists <title>, <meta>, <link> to <head>

WORKS WITH SERVER RENDERING:
  - On SSR, tags are collected and rendered into <head> in the HTML response
  - On client navigation, React manages <head> updates automatically
  - Deduplication: if two components render the same <meta name="...">, React
    keeps only the last one

7. IMPROVED ERROR HANDLING
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

React 19 improves error reporting in several ways:

BETTER ERROR MESSAGES:
  - Errors now include the component stack in a more readable format
  - Hydration errors show a diff between server and client HTML
  - "Owner" component stack (who created the failing element) is shown separately
    from the "parent" component stack

NEW ROOT OPTIONS FOR ERROR HANDLING:
  const root = createRoot(container, {
    onCaughtError(error, errorInfo) {
      // Called when Error Boundary catches an error
      logToSentry(error, errorInfo.componentStack);
    },
    onUncaughtError(error, errorInfo) {
      // Called when an error is NOT caught by an Error Boundary
      showCriticalErrorUI(error);
    },
    onRecoverableError(error, errorInfo) {
      // Called when React automatically recovers from an error
      // (e.g., hydration mismatch that React could fix)
      logWarning(error);
    }
  });

  preconnect('https://cdn.example.com');

11. INTERVIEW QUESTIONS — REACT 19
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: What is the React Compiler and what problem does it solve?
A: The React Compiler (formerly React Forget) is a build-time tool that
   automatically memoizes components, values, and callbacks. Before React 19,
   developers had to manually write useMemo, useCallback, and React.memo to
   avoid unnecessary re-renders — which is error-prone and verbose. The
   compiler statically analyzes component code and inserts memoization
   automatically where it's safe, based on React's purity rules. It does NOT
   change runtime semantics — code that violated Rules of React before is
   still wrong. The benefit is less boilerplate and fewer performance bugs.

Q: How does use() differ from useEffect for data fetching?
A: useEffect for data fetching requires: (1) a loading state, (2) an error
   state, (3) the data state, and (4) cleanup logic — typically 15–20 lines.
   use() is a primitive that "unwraps" a Promise — if the Promise is pending,
   the component suspends (propagates to the nearest Suspense boundary);
   if it rejects, the error propagates to the nearest Error Boundary; if it
   resolves, the value is returned synchronously. The result is much less
   boilerplate. The critical rule: the Promise must be created outside the
   component or memoized — not created inside, which would create a new
   Promise every render causing an infinite loop.

Q: What is useOptimistic and when would you use it?
A: useOptimistic is a React 19 hook for optimistic UI — showing the user an
   expected outcome immediately while a server operation runs in the background.
   It takes the real server state and an update function, returning an
   optimistic state value. When addOptimistic is called, the UI immediately
   reflects the change. When the underlying async operation completes,
   useOptimistic syncs to the real value. If the operation fails, it reverts
   automatically. Classic use case: a Like button — you immediately show +1
   like without waiting for the server, improving perceived performance.

Q: Why was forwardRef deprecated in React 19?
A: forwardRef was always a workaround — React historically treated ref
   specially and did not pass it through props, requiring the forwardRef
   wrapper. In React 19, ref is treated as a regular prop, so you can simply
   destructure { ref, ...props } in your function component. forwardRef still
   works for backward compatibility but is no longer necessary and will
   eventually be removed. This simplifies the component API and eliminates
   a common source of confusion for newer developers.

Q: What are Actions in React 19?
A: Actions are async functions passed to form action props (or startTransition)
   that handle user interactions. React 19 adds first-class support: you can
   pass an async function to <form action={fn}>, and React manages the pending
   state, error state, and form reset automatically. This pairs with
   useFormStatus() (to read pending state in child buttons) and
   useActionState() (to manage form state + action results). The pattern
   reduces the need for manual loading/error state management in forms.
