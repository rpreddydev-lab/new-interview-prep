1. OVERVIEW OF REACT 18
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

React 18 was released in March 2022. It introduces Concurrent React as stable,
which is the most significant change to React's rendering model since Hooks.

Key theme: Better performance and user experience through concurrent rendering.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
2. createRoot() — NEW RENDERING API
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

React 17 and below:
  import ReactDOM from 'react-dom';
  ReactDOM.render(<App />, document.getElementById('root'));

React 18:
  import { createRoot } from 'react-dom/client';
  const root = createRoot(document.getElementById('root'));
  root.render(<App />);

Why the change?
  - createRoot() opts into Concurrent Mode
  - Old ReactDOM.render() still works but opts into legacy mode (no concurrent features)
  - Concurrent features (useTransition, etc.) only work with createRoot()

Hydration (SSR):
  import { hydrateRoot } from 'react-dom/client';
  hydrateRoot(document.getElementById('root'), <App />);
  // Replaces ReactDOM.hydrate()

3. AUTOMATIC BATCHING
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Batching = grouping multiple setState calls into a single re-render.

React 17 behavior:
  - Batched setState calls ONLY inside React event handlers
  - NOT batched in: setTimeout, Promises, async code, native events

  // React 17: causes 2 re-renders (not batched in setTimeout)
  setTimeout(() => {
    setCount(c => c + 1);  // render 1
    setFlag(f => !f);      // render 2
  }, 0);

React 18 behavior (AUTOMATIC BATCHING):
  - ALL setState calls are batched, regardless of where they happen
  - setTimeout, Promises, native event listeners — ALL batched automatically

  // React 18: causes only 1 re-render (automatically batched)
  setTimeout(() => {
    setCount(c => c + 1);  // }
    setFlag(f => !f);      // } only 1 re-render
  }, 0);

Opting OUT of batching (if needed — rare):
  import { flushSync } from 'react-dom';

  flushSync(() => {
    setCount(c => c + 1); // renders immediately
  });
  // DOM is now updated
  flushSync(() => {
    setFlag(f => !f);     // renders immediately
  });

4. TRANSITIONS — useTransition & startTransition
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Transitions let you mark UI updates as NON-URGENT, allowing React to
prioritize urgent updates (like typing) over expensive ones (like filtering).

useTransition (inside component):
  import { useTransition } from 'react';

  function SearchPage() {
    const [query, setQuery] = useState('');
    const [results, setResults] = useState([]);
    const [isPending, startTransition] = useTransition();

    function handleChange(e) {
      const value = e.target.value;
      setQuery(value);                         // urgent (sync)
      startTransition(() => {
        setResults(filterLargeList(value));    // non-urgent (can be interrupted)
      });
    }

    return (
      <>
        <input value={query} onChange={handleChange} />
        {isPending && <Spinner />}
        <ResultList results={results} />
      </>
    );
  }

startTransition (outside component — no isPending):
  import { startTransition } from 'react';

  startTransition(() => {
    setTab('settings'); // low-priority navigation
  });

Key behaviors:
  - Urgent updates (direct setQuery) render immediately
  - Transition updates can be interrupted if new urgent input arrives
  - isPending = true while transition is in progress
  - Transitions are great for: tab switching, search filtering, route transitions

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
5. useDeferredValue
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

useDeferredValue creates a deferred version of a value. The UI renders with
the deferred (lagging) value while urgent updates are processed.

  import { useDeferredValue } from 'react';

  function SearchPage({ query }) {
    const deferredQuery = useDeferredValue(query);
    // deferredQuery updates AFTER the urgent query update
    // During the transition: query = new value, deferredQuery = old value

    const isStale = query !== deferredQuery;

    return (
      <div style={{ opacity: isStale ? 0.7 : 1 }}>
        <SearchResults query={deferredQuery} />
      </div>
    );
  }

Difference between useTransition and useDeferredValue:
  - useTransition: YOU control which update is the transition (wrap setter)
  - useDeferredValue: You receive a value from outside and defer it
    (useful when you don't control the source of the update, e.g., a prop)

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
6. useId
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

useId generates a stable, unique ID that is consistent between server and client
renders (prevents SSR hydration mismatches).

  import { useId } from 'react';

  function FormField({ label }) {
    const id = useId();
    return (
      <div>
        <label htmlFor={id}>{label}</label>
        <input id={id} type="text" />
      </div>
    );
  }
  // id will be something like ":r0:", ":r1:" — stable across SSR + hydration

DO NOT use for list keys — use only for accessibility attributes (id, aria-*).

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
7. SUSPENSE IMPROVEMENTS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

React 16 introduced Suspense for lazy loading. React 18 extends it to support
data fetching (with frameworks like Next.js, Relay, TanStack Query).

  import { Suspense, lazy } from 'react';
  const HeavyComponent = lazy(() => import('./HeavyComponent'));

  function App() {
    return (
      <Suspense fallback={<Spinner />}>
        <HeavyComponent />
      </Suspense>
    );
  }

Suspense with concurrent features:
  - With startTransition, React won't show the fallback during transition updates
    (avoids flickering). It shows the old content until the new content is ready.
  - Without transition, updating suspended content will show the fallback again.

Suspense in React 18 for data:
  // Frameworks/libraries signal "suspended" state by throwing a Promise
  // React catches it, shows fallback, retries when Promise resolves

8. NEW HOOKS IN REACT 18
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

React 18 introduced several new hooks:

  useTransition   — covered above
  useDeferredValue — covered above
  useId           — covered above

  useSyncExternalStore:
    For library authors. Safely subscribe to external (non-React) stores
    and ensure consistent snapshots during concurrent renders.

    import { useSyncExternalStore } from 'react';
    const value = useSyncExternalStore(store.subscribe, store.getSnapshot);

  useInsertionEffect:
    For CSS-in-JS library authors. Fires before DOM mutations.
    Used to inject <style> tags at the right time.
    Runs BEFORE useLayoutEffect. Not for app-level code.

9. CONCURRENT MODE vs LEGACY MODE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  | Feature                  | Legacy Mode          | Concurrent Mode        |
  |--------------------------|----------------------|------------------------|
  | API                      | ReactDOM.render()    | createRoot()           |
  | Automatic Batching       | Event handlers only  | All async code         |
  | useTransition            | No                   | Yes                    |
  | useDeferredValue         | No                   | Yes                    |
  | Suspense (data)          | Partial              | Full                   |
  | Interruptible renders    | No                   | Yes                    |
  | Breaking changes         | None                 | Potential (StrictMode) |

React 18 DOES NOT force Concurrent Mode — it's opt-in via createRoot().
Old apps using ReactDOM.render() continue to work exactly as before.

10. STRICT MODE CHANGES IN REACT 18
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

In React 18's Strict Mode (development only):
  - React intentionally double-invokes component functions AND effects
  - Components run: render → cleanup → render (effects mount, unmount, mount again)
  - Purpose: prepare for React's upcoming "Offscreen" feature where components
    can be hidden/shown without being destroyed (state must survive unmount)
  - If your effect breaks with double-invocation, you have a cleanup bug

  // Strict Mode (wrapping App):
  root.render(
    <React.StrictMode>
      <App />
    </React.StrictMode>
  );

11. REACT 19 PREVIEW (2024)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

React 19 (stable as of late 2024) builds further on React 18:
  - React Compiler (auto-memoization — no more manual useMemo/useCallback)
  - Actions (simplify server mutations and form handling)
  - New hooks: useActionState, useFormStatus, useOptimistic
  - Document metadata API (native <title>, <meta> without Helmet)
  - Asset loading APIs (preload, prefetch scripts/styles)
  - Improved error messages and hydration error reporting
  - forwardRef no longer needed — ref is now a regular prop

12. COMMON INTERVIEW QUESTIONS ON REACT 18
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: What are the major features introduced in React 18?
A: createRoot() API, Automatic Batching (all async code), useTransition,
   useDeferredValue, useId, useSyncExternalStore, Suspense improvements,
   Concurrent Mode stable.

Q: What is Concurrent Mode?
A: A rendering model where React can prepare multiple versions of the UI at once,
   interrupt renders for higher-priority updates, and keep the UI responsive.
   Enabled by using createRoot() instead of ReactDOM.render().

Q: What is Automatic Batching in React 18?
A: React now batches all setState calls (in timeouts, promises, event handlers, etc.)
   into a single re-render automatically. Previously, only React event handler
   setState calls were batched. Use flushSync() to opt out if needed.

Q: What is the difference between useTransition and useDeferredValue?
A: Both defer non-urgent updates. useTransition wraps the state setter call —
   you control which state update is deferred. useDeferredValue receives a value
   (often a prop) and defers it — useful when you can't control the update source.

Q: Why was createRoot() introduced?
A: To provide a clean opt-in mechanism for Concurrent Mode features. Using
   ReactDOM.render() keeps legacy synchronous behavior; createRoot() enables
   all React 18 concurrent features.

Q: What is useId used for?
A: Generating stable unique IDs that match between server-side rendering and
   client-side hydration. Used for accessibility attributes (htmlFor/id pairs,
   aria-describedby, etc.). Not for list keys.

Q: Why does React 18 Strict Mode double-invoke effects?
A: To simulate future React behavior where components can be unmounted and
   remounted (hidden/shown) without destroying state. This surfaces bugs where
   effects don't properly clean up. It only happens in development mode.

Q: What is useSyncExternalStore?
A: A hook for safely subscribing to external stores (Redux, Zustand, browser APIs)
   in Concurrent Mode. It ensures consistent state snapshots during renders that
   might be interrupted and retried.
