1. WHAT IS QIANKUN?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

qiankun (乾坤, meaning "universe" in Chinese) is a production-ready micro-
frontend framework built by Ant Group (Alibaba). It is based on single-spa
but adds opinionated features for enterprise use, including:
  - JS sandbox for global variable isolation
  - CSS sandbox to prevent style conflicts
  - Pre-fetching of sub-application resources
  - Simpler API than raw single-spa

GitHub: https://github.com/umijs/qiankun
Language: TypeScript
Used by: Alibaba, Ant Group, many large Chinese tech companies

2. KEY FEATURES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

JS SANDBOX (JavaScript Isolation):
  Prevents sub-applications from polluting the global window object.
  Two modes:
  a) Snapshot Sandbox: takes a snapshot of window before mount, restores on unmount
     (single sub-app at a time)
  b) Proxy Sandbox (default): uses ES6 Proxy to intercept all window operations
     for each sub-app — enables multiple sub-apps running simultaneously

  Without sandbox:
    SubApp A: window.config = { theme: 'dark' }
    SubApp B: window.config = { theme: 'light' }  // clobbers SubApp A's config!

  With Proxy sandbox:
    Each sub-app has its own virtual window — no conflicts.

CSS SANDBOX (Style Isolation):
  Two modes:
  a) Strict mode (Shadow DOM): full CSS isolation using Shadow DOM
  b) Scoped mode (default): adds unique attribute selectors to all CSS rules
     at runtime to prevent leakage

PRE-FETCHING:
  Sub-apps can be pre-fetched in background after the main app loads:
  prefetchApps([{ name: 'cart', entry: 'https://cart.example.com' }]);
  // Resources downloaded in idle time → faster first render when user navigates

MAIN APP (Shell):
  import { registerMicroApps, start } from 'qiankun';

  registerMicroApps([
    {
      name: 'products',                          // Unique name
      entry: 'http://localhost:8081/',            // Sub-app URL (HTML entry)
      container: '#sub-app-container',           // DOM element where it mounts
      activeRule: '/products',                   // Route to activate on
      props: {                                   // Props passed to sub-app
        authToken: getToken(),
        userId: getCurrentUser().id,
      },
    },
    {
      name: 'cart',
      entry: 'http://localhost:8082/',
      container: '#sub-app-container',
      activeRule: '/cart',
    },
  ]);

  start({
    prefetch: true,                              // Pre-fetch sub-apps
    sandbox: { strictStyleIsolation: false },    // CSS isolation mode
  });

SUB-APP (React):
  // src/public-path.js — must be first import in sub-app entry
  if (window.__POWERED_BY_QIANKUN__) {
    __webpack_public_path__ = window.__INJECTED_PUBLIC_PATH_BY_QIANKUN__;
  }

  // src/index.js
  import './public-path';
  import React from 'react';
  import ReactDOM from 'react-dom';
  import App from './App';

  function render(props = {}) {
    const { container } = props;
    ReactDOM.render(
      <App />,
      // Mount inside qiankun's container OR standalone in dev
      container
        ? container.querySelector('#root')
        : document.querySelector('#root')
    );
  }

  // Standalone mode (running without qiankun — for local dev):
  if (!window.__POWERED_BY_QIANKUN__) {
    render();
  }

  // qiankun lifecycle exports:
  export async function bootstrap() {
    console.log('Products app bootstrapped');
  }

  export async function mount(props) {
    render(props);
  }

  export async function unmount(props) {
    ReactDOM.unmountComponentAtNode(
      props.container.querySelector('#root')
    );
  }

  // webpack.config.js adjustments for sub-app:
  module.exports = {
    output: {
      library: 'products',           // Expose as global variable
      libraryTarget: 'umd',          // UMD format required by qiankun
      jsonpFunction: 'webpackJsonp_products', // Avoid conflicts
    },
    devServer: {
      headers: {
        'Access-Control-Allow-Origin': '*',  // Required for cross-origin loading
      },
    },
  };

4. COMMUNICATION IN QIANKUN
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

METHOD 1 — initGlobalState (built-in event bus):
  // Main app:
  import { initGlobalState } from 'qiankun';

  const actions = initGlobalState({ user: null, cartCount: 0 });

  actions.onGlobalStateChange((state, prev) => {
    console.log('Global state changed:', state, prev);
  });

  actions.setGlobalState({ user: { id: 1, name: 'Alice' } });

  // Sub-app (via props):
  export async function mount(props) {
    props.onGlobalStateChange((state) => {
      // React to global state changes
      setUser(state.user);
    });
    props.setGlobalState({ cartCount: 3 }); // Update global state
    render(props);
  }

METHOD 2 — Props:
  Direct data passing from shell to sub-app via the props field in
  registerMicroApps. Good for static data like auth tokens.

METHOD 3 — Custom Events:
  window.dispatchEvent(new CustomEvent('app:cart-updated', { detail: {...} }));
  // JS sandbox allows window events to propagate normally

5. QIANKUN vs single-spa vs MODULE FEDERATION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Aspect               qiankun              single-spa          Module Federation
  ───────────────────────────────────────────────────────────────────────────────
  Based on             single-spa           —                   Webpack 5
  JS isolation         ✅ Proxy sandbox     ❌ Manual            ❌ Not built-in
  CSS isolation        ✅ Built-in          ❌ Manual            ❌ Not built-in
  HTML entry           ✅ Yes (URL)         ❌ JS entry          ❌ JS entry
  Framework agnostic   ✅ Yes               ✅ Yes               Partial
  Pre-fetching         ✅ Built-in          ❌ Manual            ❌ Manual
  Setup complexity     Medium              Medium-High          Medium
  Community            Large (Asia)         Large (global)       Large (global)
  Best for             Enterprise, polyglot Large enterprise     Same-framework teams

6. COMMON PITFALLS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. FORGETTING public-path.js:
   Sub-app static assets (images, lazy chunks) reference wrong URLs when
   loaded inside qiankun. Always set __webpack_public_path__ first.

2. GLOBAL STYLE POLLUTION:
   CSS reset or global styles in sub-apps can bleed into shell.
   Use strictStyleIsolation or scope all global styles carefully.

3. REACT SINGLETON ISSUE:
   If shell and sub-app both bundle React separately, hooks may break.
   Solution: externalize React in sub-app webpack config and let shell provide it.

4. EVENT LISTENER LEAKS:
   Sub-apps adding window event listeners must clean them up in unmount.
   Proxy sandbox cannot automatically clean custom event listeners.

5. ROUTER CONFLICTS:
   Sub-app must use hash router OR configure basename to match its active route.
   E.g., if sub-app mounts at /products, use <BrowserRouter basename="/products">.
