1. WHAT IS ZUSTAND
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Zustand (German for "state") is a small, fast, unopinionated state management
library for React. Created by Poimandres (same team as react-three-fiber).

  Key characteristics:
  - No Provider wrapper needed (store lives outside React tree)
  - Minimal boilerplate (stores are functions, not classes)
  - Selectors prevent unnecessary re-renders
  - Works with React and vanilla JS
  - Middleware support (persist, devtools, immer)
  - ~1KB gzipped

  Install:
    npm install zustand

2. BASIC STORE CREATION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  // store/useCounterStore.js
  import { create } from 'zustand';

  const useCounterStore = create((set, get) => ({
    // State
    count: 0,

    // Actions (methods that call set/get)
    increment: () => set(state => ({ count: state.count + 1 })),
    decrement: () => set(state => ({ count: state.count - 1 })),
    reset: () => set({ count: 0 }),
    incrementBy: (amount) => set(state => ({ count: state.count + amount })),

    // get() reads current state inside actions
    doubleCount: () => get().count * 2,
  }));

  export default useCounterStore;

  // Usage in components (no Provider needed):
  function Counter() {
    const count = useCounterStore(state => state.count);       // selector
    const increment = useCounterStore(state => state.increment);
    const decrement = useCounterStore(state => state.decrement);

    return (
      <div>
        <button onClick={decrement}>-</button>
        <span>{count}</span>
        <button onClick={increment}>+</button>
      </div>
    );
  }

3. SELECTORS AND RE-RENDERS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Zustand re-renders a component ONLY when the selected value changes.

  // Component A only re-renders when count changes
  const count = useCounterStore(state => state.count);

  // Component B only re-renders when user changes, not count
  const user = useUserStore(state => state.user);

  // AVOID selecting the whole store (re-renders on ANY state change):
  const store = useCounterStore();    // ❌ too broad

  // For multiple values, use shallow comparison:
  import { useShallow } from 'zustand/react/shallow';

  const { count, user } = useMyStore(
    useShallow(state => ({ count: state.count, user: state.user }))
  );
  // Re-renders only if count OR user changes (not on other state changes)

4. COMPLETE CART STORE EXAMPLE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  // store/useCartStore.js
  import { create } from 'zustand';

  const useCartStore = create((set, get) => ({
    items: [],   // { id, name, price, quantity }

    addItem: (product) => set(state => {
      const existing = state.items.find(item => item.id === product.id);
      if (existing) {
        return {
          items: state.items.map(item =>
            item.id === product.id
              ? { ...item, quantity: item.quantity + 1 }
              : item
          ),
        };
      }
      return { items: [...state.items, { ...product, quantity: 1 }] };
    }),

    removeItem: (id) => set(state => ({
      items: state.items.filter(item => item.id !== id),
    })),

    updateQuantity: (id, quantity) => set(state => ({
      items: quantity <= 0
        ? state.items.filter(item => item.id !== id)
        : state.items.map(item =>
            item.id === id ? { ...item, quantity } : item
          ),
    })),

    clearCart: () => set({ items: [] }),

    // Derived (computed) values using get():
    get totalItems() { return get().items.reduce((sum, i) => sum + i.quantity, 0); },
    get totalPrice() { return get().items.reduce((sum, i) => sum + i.price * i.quantity, 0); },
  }));

  export default useCartStore;

5. ASYNC ACTIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Async actions in Zustand are just async functions:

  const useUserStore = create((set) => ({
    user: null,
    loading: false,
    error: null,

    fetchUser: async (id) => {
      set({ loading: true, error: null });
      try {
        const response = await fetch(`/api/users/${id}`);
        const user = await response.json();
        set({ user, loading: false });
      } catch (err) {
        set({ error: err.message, loading: false });
      }
    },

    logout: () => set({ user: null }),
  }));

  // Usage:
  function Profile({ userId }) {
    const { user, loading, fetchUser } = useUserStore(
      useShallow(state => ({ user: state.user, loading: state.loading, fetchUser: state.fetchUser }))
    );

    useEffect(() => { fetchUser(userId); }, [userId]);

    if (loading) return <Spinner />;
    return <div>{user?.name}</div>;
  }

6. MIDDLEWARE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  a) devtools — connects to Redux DevTools browser extension:
    import { devtools } from 'zustand/middleware';
    const useStore = create(devtools((set) => ({ ... }), { name: 'CartStore' }));

  b) persist — syncs state to localStorage/sessionStorage:
    import { persist } from 'zustand/middleware';
    const useStore = create(persist(
      (set) => ({ count: 0, increment: () => set(s => ({ count: s.count + 1 })) }),
      { name: 'counter-storage' }   // localStorage key
    ));

  c) immer — enables direct mutations (like RTK's createSlice):
    import { immer } from 'zustand/middleware/immer';
    const useStore = create(immer((set) => ({
      items: [],
      addItem: (item) => set(state => { state.items.push(item); }),  // direct mutation OK
    })));

  d) Combine middleware:
    const useStore = create(
      devtools(
        persist(
          immer((set) => ({ ... })),
          { name: 'my-store' }
        ),
        { name: 'MyStore' }
      )
    );

7. ZUSTAND vs REDUX TOOLKIT
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  | Feature              | Zustand              | Redux Toolkit         |
  |----------------------|----------------------|-----------------------|
  | Boilerplate          | Minimal              | Moderate              |
  | Bundle size          | ~1KB                 | ~15KB                 |
  | Provider required    | No                   | Yes (<Provider>)      |
  | DevTools             | Via middleware       | Built-in              |
  | Async handling       | Plain async fn       | createAsyncThunk      |
  | Middleware           | Yes (compose)        | Yes (thunk, RTK Query)|
  | TypeScript           | Excellent            | Excellent             |
  | Learning curve       | Very low             | Medium                |
  | Time-travel debug    | Via devtools         | Yes                   |
  | Best for             | Small-medium apps    | Large apps, teams     |

Q: How does Zustand differ from React Context?
A: Zustand stores live outside the React component tree and use subscription-
   based updates. Only components that subscribe to a specific slice of state
   re-render when it changes. Context re-renders ALL consumers when the
   provider's value changes. Zustand is much better for frequently-updated state.

Q: Do you need a Provider with Zustand?
A: No. Zustand stores are module-level singletons. Just import and use the hook
   anywhere. However, if you need multiple instances (like for SSR or testing),
   you can use createStore with a Provider (optional advanced pattern).

Q: How do you prevent over-rendering in Zustand?
A: Use granular selectors (select only the state you need). For selecting
   multiple values as an object, use useShallow to compare them shallowly.

Q: How do you handle async operations in Zustand?
A: Just define async functions inside the store. Call set() before and after
   the async operation to update loading/error/data state. No special thunk
   middleware is needed.

Q: What is the persist middleware used for?
A: It synchronizes the Zustand store state to localStorage (or another storage
   adapter). When the page reloads, the stored value is rehydrated automatically.
   Useful for persisting user preferences, cart contents, auth tokens, etc.
