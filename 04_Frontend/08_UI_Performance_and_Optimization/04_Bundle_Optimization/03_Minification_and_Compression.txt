================================================================
MINIFICATION AND COMPRESSION
================================================================

OVERVIEW
─────────
Before serving JavaScript, CSS, and HTML to users, we apply two
distinct optimization steps:

  1. MINIFICATION: Remove unnecessary characters from source code
     (whitespace, comments, long variable names) without changing behavior.
     Happens at BUILD TIME. Result stored on disk/CDN.

  2. COMPRESSION: Encode the minified file using a compression algorithm
     to reduce transfer size. Happens at SERVE TIME (or pre-compressed).
     Result sent over HTTP. Browser decompresses before parsing.

IMPACT:
  A typical React app:
  - Original source: 500KB JS
  - After minification: 250KB
  - After gzip: 80KB  ← what browser downloads
  - After brotli: 65KB ← even better!
  
  That's 87% reduction from original → user pays 65KB not 500KB.

================================================================
JAVASCRIPT MINIFICATION
================================================================

WHAT MINIFICATION DOES TO JS:
  1. Remove whitespace, newlines, comments
  2. Rename variables to shorter names (a, b, c...)
  3. Simplify expressions (true → !0, false → !1)
  4. Remove unreachable code (code after return)
  5. Inline constants
  6. Remove dead branches (if (false) {...} → removed)
  7. Collapse string concatenation ('hello ' + 'world' → 'hello world')

// Original:
function calculateTax(price, taxRate) {
  // Apply the tax rate to the price
  const taxAmount = price * taxRate;
  const totalPrice = price + taxAmount;
  return totalPrice;
}

// Minified by Terser:
function calculateTax(e,t){return e+e*t}

JS MINIFICATION TOOLS:
────────────────────────

1. TERSER (industry standard)
  # Most widely used, good compression, supports modern JS
  npm install --save-dev terser-webpack-plugin
  
  // webpack.config.js
  const TerserPlugin = require('terser-webpack-plugin');
  
  module.exports = {
    optimization: {
      minimizer: [
        new TerserPlugin({
          terserOptions: {
            compress: {
              drop_console: true,     // Remove console.log
              drop_debugger: true,    // Remove debugger statements
              pure_funcs: ['console.log'],  // Remove specific calls
            },
            mangle: {
              safari10: true,         // Fix Safari 10 bug
            },
            format: {
              comments: false,        // Remove all comments
            },
          },
          extractComments: false,     // Don't extract license comments
        })
      ]
    }
  };

2. SWC (Rust-based, 10-70x faster than Terser)
  # Used by Next.js 12+, Vite, Turbopack
  npm install --save-dev @swc/core
  
  // For webpack:
  npm install swc-loader
  // .swcrc:
  {
    "jsc": {
      "minify": {
        "compress": { "unused": true, "drop_console": true },
        "mangle": true
      }
    }
  }

3. ESBUILD (Go-based, extremely fast)
  # Used by Vite (dev server), Remix, Create React App (via CRACO)
  # Slightly less optimization than Terser but 100x faster
  npm install --save-dev esbuild-loader
  
  // webpack.config.js (replace babel-loader + Terser):
  const { EsbuildPlugin } = require('esbuild-loader');
  
  module.exports = {
    module: {
      rules: [{
        test: /\.[jt]sx?$/,
        loader: 'esbuild-loader',
        options: { target: 'es2015' }
      }]
    },
    optimization: {
      minimizer: [new EsbuildPlugin({ target: 'es2015' })]
    }
  };

4. GOOGLE CLOSURE COMPILER (most aggressive)
  # Advanced mode renames across file boundaries
  # Great compression but requires strict code style
  # Used by Google, Angular
  # Rarely used in regular React apps due to complexity

================================================================
CSS MINIFICATION
================================================================

WHAT CSS MINIFICATION DOES:
  - Remove whitespace and comments
  - Merge duplicate rules
  - Shorten hex colors (#ffffff → #fff)
  - Remove zero units (0px → 0)
  - Merge shorthand properties

// Original:
.button {
  /* Primary button */
  background-color: #ffffff;
  padding-top: 10px;
  padding-right: 20px;
  padding-bottom: 10px;
  padding-left: 20px;
  margin: 0px;
}

// Minified:
.button{background-color:#fff;padding:10px 20px;margin:0}

================================================================
HTTP COMPRESSION
================================================================

HOW IT WORKS:
  1. Server compresses the response body
  2. Sets Content-Encoding: gzip (or br for Brotli)
  3. Browser decompresses after download
  4. Browser parses and executes the original content

  // HTTP Headers:
  // Request:  Accept-Encoding: gzip, deflate, br
  // Response: Content-Encoding: br
  //           Content-Type: application/javascript

COMPRESSION ALGORITHMS COMPARISON:
  Algorithm  | Compression | CPU Cost  | Browser Support
  ──────────────────────────────────────────────────────
  Gzip       | Good        | Low       | 99.9% (all browsers)
  Brotli (br)| Better      | Medium    | 95%+ (all modern)
  Zstd       | Best        | Low       | <70% (newer only)
  
  Brotli at level 11 compresses ~15-20% better than Gzip level 9.
  Brotli was designed specifically for text (HTML/CSS/JS).

GZIP vs BROTLI ON A REAL APP:
  File           Gzip (level 9)  Brotli (level 11)
  ─────────────────────────────────────────────────
  main.js (250KB)   80KB              67KB
  styles.css (50KB) 12KB              10KB
  Total savings:    ~37% vs minified  ~47% vs minified

SERVER CONFIGURATION:
────────────────────────

NGINX:
  # /etc/nginx/nginx.conf
  
  # Gzip
  gzip on;
  gzip_vary on;
  gzip_types text/plain text/css application/json 
             application/javascript text/xml 
             application/xml application/xml+rss text/javascript;
  gzip_comp_level 6;     # 1-9, higher = smaller but slower
  gzip_min_length 256;   # Don't compress tiny files
  
  # Brotli (requires nginx-module-brotli)
  brotli on;
  brotli_comp_level 6;
  brotli_types text/plain text/css application/json
               application/javascript;

EXPRESS.JS:
  npm install compression
  
  const compression = require('compression');
  const app = express();
  
  // Use compression for all routes
  app.use(compression({
    level: 6,       // gzip compression level (1-9)
    threshold: 1024 // Only compress responses > 1KB
  }));
  
  // For Brotli support in Express (Node 12+):
  const zlib = require('zlib');
  app.use(compression({
    filter: (req, res) => {
      if (req.headers['x-no-compression']) return false;
      return compression.filter(req, res);
    },
    brotli: { enabled: true, zlib: { level: 4 } }
  }));

CLOUDFLARE / CDN:

  # Just enable "Compression" in Cloudflare dashboard
  # Level 9 Gzip + Brotli available for free tier

================================================================
PRE-COMPRESSION (STATIC FILE OPTIMIZATION)
================================================================

Instead of compressing on every request, pre-compress files at build time.
Server then serves the pre-compressed file with Content-Encoding header.
This eliminates runtime CPU cost for compression.

WEBPACK PRE-COMPRESSION:
  npm install --save-dev compression-webpack-plugin
  
  const CompressionPlugin = require('compression-webpack-plugin');
  const zlib = require('zlib');
  
  module.exports = {
    plugins: [
      // Gzip
      new CompressionPlugin({
        filename: '[path][base].gz',
        algorithm: 'gzip',
        test: /\.(js|css|html|svg)$/,
        compressionOptions: { level: 9 },
        threshold: 1024,   // Only files > 1KB
        minRatio: 0.8,     // Only if compression ratio > 80%
      }),
      // Brotli
      new CompressionPlugin({
        filename: '[path][base].br',
        algorithm: 'brotliCompress',
        test: /\.(js|css|html|svg)$/,
        compressionOptions: {
          params: { [zlib.constants.BROTLI_PARAM_QUALITY]: 11 }
        },
      }),
    ]
  };

NGINX SERVING PRE-COMPRESSED FILES:
  # Serve .br first, fall back to .gz, then uncompressed
  location ~* \.(js|css|html|svg)$ {
    gzip_static on;    # Serve .gz if exists
    brotli_static on;  # Serve .br if exists (needs nginx-brotli module)
    expires 1y;
    add_header Cache-Control "public, immutable";
  }

================================================================
SCOPE HOISTING (MODULE CONCATENATION)
================================================================

Webpack's scope hoisting (ModuleConcatenationPlugin) merges all
ES modules into a single scope, reducing module wrapper overhead:

  // Without scope hoisting: each module wrapped in function
  (function(module, exports, require) { // wrapper adds overhead
    var add = function(a, b) { return a + b; };
    module.exports = { add };
  });
  
  // With scope hoisting: modules merged, no wrapper overhead
  var math_add = function(a, b) { return a + b; };
  
  // Benefits: smaller bundle, faster execution
  // Enabled by default in production mode

MEASURING MINIFICATION/COMPRESSION EFFECTIVENESS
================================================================

// Check actual file sizes:
ls -la dist/js/  # Stat size
gzip -l dist/js/main.js  # Gzip ratio

// Node.js measurement:
const fs = require('fs');
const zlib = require('zlib');

const original = fs.readFileSync('dist/main.js');
const gzipped = zlib.gzipSync(original);
const brotli = zlib.brotliCompressSync(original);

console.log(`Original: ${(original.length / 1024).toFixed(1)}KB`);
console.log(`Gzip: ${(gzipped.length / 1024).toFixed(1)}KB`);
console.log(`Brotli: ${(brotli.length / 1024).toFixed(1)}KB`);

// "Size" = compressed transfer size (what was downloaded)

================================================================
INTERVIEW ANSWERS
================================================================

Q: What's the difference between minification and compression?
A: Minification removes unnecessary characters from source code (whitespace,
   comments, renames variables to shorter names) at build time — it changes
   the file content but not the logic. Compression (gzip/Brotli) is an
   encoding applied when serving files over HTTP — the file content is
   compressed for transfer and the browser decompresses it. You apply both:
   minify first, then compress. Minification helps compression by making
   patterns more repetitive (compression algorithms love repetition).

Q: Gzip vs Brotli — which should you use?
A: Both. Serve Brotli to browsers that support it (all modern browsers, ~95%)
   and Gzip as fallback. Brotli compresses ~15-20% better than Gzip and was
   designed specifically for web text content (HTML/CSS/JS). It uses a
   pre-built dictionary of common web strings. The browser advertises support
   via Accept-Encoding: br, gzip in request headers. For static assets, I
   pre-compress at build time to eliminate per-request CPU cost.

Q: What are the most effective JS minification options?
A: The key options in Terser are: (1) compress.drop_console to remove all
   console.log calls in production; (2) mangle to rename variables to
   single letters; (3) compress.dead_code to remove unreachable code;
   (4) compress.passes: 2 for multiple optimization passes. For build speed,
   I use SWC or esbuild which are 10-100x faster than Terser with only
   slightly worse compression. For Next.js, SWC minification is built-in and
   enabled by default since Next.js 12.

Q: Why does minification improve compression effectiveness?
A: Minification creates more consistent, repetitive patterns that compression
   algorithms can exploit. For example, variable mangling turns all variable
   names to short letters (a, b, c) — these repeat throughout the file and
   compress very well. Dead code removal means less content to compress.
   Whitespace removal reduces entropy. The combination typically achieves
   better compression ratios than compressing unminified code.

Q: How do you verify compression is working correctly?
A: In Chrome DevTools Network tab, there are two size columns: "Size" (the
   actual bytes transferred = compressed) and "Content" (bytes after
   decompression). If they're the same, compression isn't working. I also
   check the Response Headers for Content-Encoding: gzip or Content-Encoding:
   br. For static assets, I verify the .gz and .br files exist in the build
   output. End-to-end I run WebPageTest and check the "Compress Transfer"
   optimization for any opportunities.
