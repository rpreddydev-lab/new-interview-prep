================================================================
IMPROVING WEB VITALS - COMPREHENSIVE STRATEGIES
================================================================

OVERVIEW
─────────
Improving Core Web Vitals requires a systematic approach across all three
dimensions: Loading (LCP), Interactivity (INP), and Visual Stability (CLS).
This file brings together cross-cutting strategies and practical workflows.

================================================================
THE WEB VITALS IMPROVEMENT WORKFLOW
================================================================

STEP 1: DIAGNOSE (Measure First)
─────────────────────────────────
  1. Check Google Search Console → Core Web Vitals report
     (Real user data, shows failing URLs)
  
  2. Run PageSpeed Insights on failing URLs
     (Shows both field data from CrUX + lab data from Lighthouse)
  
  3. Run Chrome DevTools → Performance panel
     (Detailed timeline to identify specific bottlenecks)
  
  4. Check Coverage panel for unused code
  5. Check Network panel for large resources
  6. Enable Rendering → Layout shift regions for CLS debugging

STEP 2: PRIORITIZE
───────────────────
  - Focus on the metric that scores "Poor" first
  - LCP is often the highest-impact fix
  - CLS fixes are usually quick wins
  - INP requires deeper investigation of user interactions

STEP 3: FIX AND VERIFY
────────────────────────
  - Fix one thing at a time (isolate impact)
  - Verify in Lighthouse (quick lab check)
  - Deploy to staging → run WebPageTest
  - Wait 28 days for CrUX/Search Console to reflect field data

================================================================
LCP IMPROVEMENT CHECKLIST
================================================================

CRITICAL PATH OPTIMIZATIONS:
─────────────────────────────
□ Ensure LCP element is HTML-discoverable (not JS-injected late)
□ Add fetchpriority="high" to LCP image
□ Add <link rel="preload"> for LCP image
□ Never set loading="lazy" on LCP element
□ Use SSR/SSG so LCP content is in initial HTML

SERVER & NETWORK:
─────────────────
□ TTFB < 800ms (CDN, server-side caching, fast backend)
□ Use HTTP/2 or HTTP/3
□ Enable Brotli compression (better than gzip for text)
□ Use CDN for all static assets
□ Add preconnect for CDN domain

IMAGE OPTIMIZATION:
────────────────────
□ Convert to WebP (30-40% smaller than JPEG) or AVIF (50% smaller)
□ Compress images appropriately (target: < 100KB for hero images)
□ Use responsive images (srcset, sizes) — serve right-sized image
□ Serve images from CDN with auto-optimization (Cloudinary, Imgix)

RENDER-BLOCKING RESOURCES:
───────────────────────────
□ Inline critical CSS (above-the-fold styles)
□ Defer non-critical CSS
□ Add defer/async to scripts
□ Preload critical fonts

================================================================
INP IMPROVEMENT CHECKLIST
================================================================

REDUCE INPUT DELAY:
────────────────────
□ Break long tasks into < 50ms chunks
□ Use scheduler.yield() or setTimeout(fn, 0) in long loops
□ Reduce JavaScript bundle size loaded at startup
□ Lazy load non-critical scripts (3rd party widgets, analytics)
□ Use Web Workers for CPU-intensive work

REDUCE PROCESSING TIME:
────────────────────────
□ Profile event handlers — identify expensive functions
□ Use React useTransition() for non-urgent state updates
□ Use useDeferredValue() for expensive derived state
□ Debounce/throttle expensive event handlers
□ Optimize heavy React component renders (useMemo, useCallback)
□ Avoid synchronous data operations in event handlers

REDUCE PRESENTATION DELAY:
───────────────────────────
□ Reduce DOM size (< 1500 nodes recommended)
□ Avoid layout thrashing (batch DOM reads/writes)
□ Use CSS containment (contain: layout style)
□ Virtualize long lists (react-virtual, react-window)
□ Use CSS transforms for animations (not layout properties)

================================================================
CLS IMPROVEMENT CHECKLIST
================================================================

IMAGES & MEDIA:
────────────────
□ Add width/height attributes to all img elements
□ Use CSS aspect-ratio for media containers
□ Don't lazy-load above-the-fold images

DYNAMIC CONTENT:
─────────────────
□ Reserve min-height for dynamic content areas (ads, embeds)
□ Use skeleton screens that match final content dimensions
□ Place cookie banners with position: fixed (bottom)
□ Don't insert content above existing content dynamically

FONTS:
───────
□ Use font-display: optional or swap
□ Preload critical fonts
□ Use CSS font metric overrides (size-adjust) to match fallback

ANIMATIONS:
────────────
□ Use CSS transforms instead of layout-triggering properties
□ Use will-change: transform only when needed (creates compositor layer)

ADVANCED LCP TECHNIQUES
================================================================

1. SPECULATION RULES API (Chrome 109+)
────────────────────────────────────────
// Prefetch/prerender next likely page
<script type="speculationrules">
{
  "prerender": [
    { "where": { "href_matches": "/product/*" }, "eagerness": "moderate" }
  ],
  "prefetch": [
    { "where": { "selector_matches": ".prefetch-link" }, "eagerness": "eager" }
  ]
}
</script>

// Programmatic speculative loading
const rules = {
  prerender: [{ urls: ['/checkout'] }]
};
document.querySelector('script[type="speculationrules"]').textContent =
  JSON.stringify(rules);

2. 103 EARLY HINTS
────────────────────
# Server sends 103 before full response
# Browser starts preloading critical resources immediately
HTTP/2 103 Early Hints
Link: </hero.webp>; rel=preload; as=image
Link: </styles.css>; rel=preload; as=style

3. PRIORITY HINTS
──────────────────
<!-- LCP image: highest priority -->
<img src="hero.webp" fetchpriority="high" alt="Hero">

<!-- Below-fold image: lower priority -->
<img src="related-product.webp" fetchpriority="low" alt="Product">

<!-- Script that blocks render: high priority -->
<script src="critical.js" fetchpriority="high"></script>

<!-- Analytics: low priority, doesn't block -->
<script src="analytics.js" fetchpriority="low" defer></script>

4. EDGE RENDERING FOR TTFB
────────────────────────────
// Next.js Edge Runtime (runs at CDN edge, ~0ms cold start)
export const runtime = 'edge';

export default async function handler(req) {
  const data = await getDataFromCache(req);
  return new Response(renderTemplate(data), {
    headers: { 'Content-Type': 'text/html' },
  });
}

================================================================
ADVANCED INP TECHNIQUES
================================================================

1. ISINPUTPENDING (Check if input is waiting)
───────────────────────────────────────────────
// Yield if there's pending user input
async function processBigTask(items) {
  for (let i = 0; i < items.length; i++) {
    processItem(items[i]);
    
    // Check if user input is waiting
    if (navigator.scheduling?.isInputPending()) {
      await new Promise(resolve => setTimeout(resolve, 0));
    }
  }
}

2. REACT 18 CONCURRENT FEATURES
─────────────────────────────────
// All rendering in React 18 is interruptible
// Transitions allow non-urgent renders to be interrupted

import { startTransition, useTransition } from 'react';

// Option 1: useTransition (inside component, provides isPending)
function Component() {
  const [isPending, startTransition] = useTransition();
  
  function handleSearch(query) {
    startTransition(() => {
      setSearchResults(search(query)); // Can be interrupted by input
    });
  }
  
  return (
    <>
      <input onChange={e => handleSearch(e.target.value)} />
      {isPending && <Spinner />}
    </>
  );
}

// Option 2: startTransition (outside component)
import { startTransition } from 'react';

function handleClick() {
  startTransition(() => {
    setHeavyState(computeHeavyResult());
  });
}

3. LONG TASK DETECTION
────────────────────────
// Monitor for long tasks (PerformanceObserver)
const observer = new PerformanceObserver((list) => {
  for (const entry of list.getEntries()) {
    console.log('Long task detected:', {
      duration: entry.duration,
      startTime: entry.startTime,
      attribution: entry.attribution,
    });
    
    // Send to analytics to track
    analytics.track('long-task', { duration: entry.duration });
  }
});
observer.observe({ entryTypes: ['longtask'] });

PUTTING IT ALL TOGETHER - REAL WORLD STRATEGY
================================================================

CASE STUDY: E-COMMERCE PRODUCT PAGE
──────────────────────────────────────

Current state:
  - LCP: 4.2s (Poor)
  - INP: 350ms (Needs Improvement)
  - CLS: 0.18 (Needs Improvement)

Root cause analysis:
  LCP:
  → Hero image is 1.2MB JPEG, served from origin (no CDN)
  → 3 render-blocking scripts before the image loads
  → No preload for the hero image
  
  INP:
  → "Add to cart" button triggers expensive inventory check
  → Large React tree re-renders on every interaction
  → 450KB third-party ad script executes during user interaction
  
  CLS:
  → Product images load without dimensions
  → Promo banner injected dynamically at top of page
  → Custom font with font-display: block causes FOUT

Fixes:
  LCP fixes:
  ✅ Compress hero image → WebP, 80KB (93% reduction!)
  ✅ Serve from CDN with proper Cache-Control
  ✅ Add <link rel="preload"> for hero image
  ✅ Add fetchpriority="high" to hero img element
  ✅ Defer 3 render-blocking scripts with defer attribute
  
  INP fixes:
  ✅ Move inventory check to optimistic update (show added immediately)
  ✅ Wrap non-critical cart state in useTransition()
  ✅ Defer ad script with lazy loading (loads after user idle)
  ✅ Memoize product list with React.memo, useMemo
  
  CLS fixes:
  ✅ Add width/height to all product images
  ✅ Reserve 90px for promo banner (or use fixed positioning)
  ✅ Switch to font-display: optional

Result after fixes:
  - LCP: 1.8s (Good ✅)
  - INP: 120ms (Good ✅)
  - CLS: 0.04 (Good ✅)

================================================================
INTERVIEW ANSWERS
================================================================

Q: Walk me through how you would audit and improve a page's Core Web Vitals.
A: First, I'd check Google Search Console for field data to identify which
   URLs are failing and which metrics. Then run PageSpeed Insights for a
   combined lab + field view with specific recommendations. For LCP, I'd
   look at the 4 sub-parts (TTFB, resource load delay, resource load time,
   element render delay) to find the bottleneck. Common fixes: preloading
   the LCP image with fetchpriority="high", serving optimized WebP from CDN,
   eliminating render-blocking resources. For INP, I'd use DevTools Performance
   panel to find long tasks during interaction, then use useTransition(),
   debouncing, or Web Workers to address them. For CLS, I'd enable Layout
   shift regions in DevTools to identify shifting elements, then add
   dimensions to images, reserve space for dynamic content, and use
   font-display: optional for fonts.

Q: What quick wins give the biggest CWV improvement?
A: For LCP: (1) Compress and convert hero images to WebP/AVIF — often a
   90%+ file size reduction; (2) Add fetchpriority="high" and preload link for
   LCP image — essentially free to do; (3) Add CDN. For CLS: add width/height
   to all images — one line of HTML per image. For INP: defer heavy third-party
   scripts (analytics, ads) — moving them to defer or lazy loading can shave
   hundreds of ms from input delay.

Q: How do you balance performance improvements with developer velocity?
A: I automate enforcement so it doesn't slow developers down. Lighthouse CI
   in the PR pipeline catches regressions automatically. I set up bundle size
   checks (size-limit) to flag large dependency additions. I create performance-
   first component abstractions (like a wrapped Image component that auto-handles
   dimensions/format/fetchpriority) so developers get correct defaults without
   thinking about it. Performance becomes part of the system rather than a
   manual checklist.
