================================================================
REACT.LAZY AND SUSPENSE - DEEP DIVE
================================================================

WHAT ARE REACT.LAZY AND SUSPENSE?
───────────────────────────────────
React.lazy() is a React API that lets you render a dynamically imported
component as if it were a regular component. It wraps a dynamic import()
call, turning it into a React component that automatically handles loading.

React.Suspense is a boundary component that catches lazy-loading promises
and renders a fallback UI while the component is loading.

Together they provide a declarative way to do code splitting in React.

BASIC USAGE:
──────────────
import React, { lazy, Suspense } from 'react';

// ✅ React.lazy wraps a dynamic import that returns a DEFAULT export
const LazyChart = lazy(() => import('./HeavyChart'));
const LazyModal = lazy(() => import('./HeavyModal'));

function App() {
  return (
    <Suspense fallback={<div>Loading...</div>}>
      <LazyChart data={data} />
    </Suspense>
  );
}

================================================================
HOW REACT.LAZY WORKS INTERNALLY
================================================================

React.lazy() REQUIREMENTS:
  1. Must receive a function that returns a Promise
  2. The Promise must resolve to a module with a DEFAULT export
  3. The default export must be a React component

WHAT HAPPENS WHEN LAZY COMPONENT RENDERS:
  1. React encounters <LazyChart />
  2. React.lazy() checks: is the module loaded?
  3. If NO: throws a Promise (this is how Suspense works!)
  4. Suspense catches the thrown Promise
  5. Suspense renders the fallback UI
  6. When Promise resolves (module loaded), React re-renders
  7. LazyChart renders normally

This "throw a promise" mechanism is React's internal protocol
(called "Suspense protocol" or "React suspense contract").

HANDLING NAMED EXPORTS:
────────────────────────
// React.lazy requires default exports
// For named exports, create a wrapper:

// ❌ Won't work directly
const { Chart } = lazy(() => import('./Charts'));

// ✅ Option 1: Re-export as default in Charts.js
// Charts.js:
export default function Chart() { ... }
// export function OtherExport() { ... }

// ✅ Option 2: Wrap the named import
const Chart = lazy(() =>
  import('./Charts').then(module => ({ default: module.Chart }))
);

// ✅ Option 3: Create a re-export file
// LazyChart.js:
export { Chart as default } from './Charts';
// Then:
const LazyChart = lazy(() => import('./LazyChart'));

================================================================
SUSPENSE FUNDAMENTALS
================================================================

SUSPENSE BOUNDARIES:
────────────────────
<Suspense> works like a try/catch for loading states:
  - Components "throw" promises when they're loading
  - The nearest Suspense boundary catches it
  - Renders fallback until promise resolves
  - Re-renders the children when promise resolves

MULTIPLE SUSPENSE BOUNDARIES:
───────────────────────────────
function Dashboard() {
  return (
    <div>
      {/* Each section has its own fallback */}
      <Suspense fallback={<HeaderSkeleton />}>
        <LazyHeader />
      </Suspense>
      
      <Suspense fallback={<ContentSkeleton />}>
        <LazyContent />
      </Suspense>
      
      <Suspense fallback={<SidebarSkeleton />}>
        <LazySidebar />
      </Suspense>
    </div>
  );
}
// Each section loads independently with its own skeleton

NESTED SUSPENSE:
─────────────────
function Page() {
  return (
    <Suspense fallback={<PageSkeleton />}>  {/* Outer: entire page */}
      <PageHeader />
      
      <Suspense fallback={<ChartSkeleton />}>  {/* Inner: just chart */}
        <HeavyChart />
      </Suspense>
      
      <PageFooter />
    </Suspense>
  );
}
// If HeavyChart is slow: page header/footer show, chart shows skeleton
// If entire page is loading: outer shows full page skeleton

================================================================
SUSPENSE WITH DATA FETCHING (React 18)
================================================================

In React 18, Suspense works for DATA FETCHING too, not just code splitting.

// Libraries like React Query, SWR support Suspense mode:
import { useSuspenseQuery } from '@tanstack/react-query';

function UserProfile({ userId }) {
  // useSuspenseQuery throws a promise if data isn't ready
  // Suspense boundary above catches it and shows fallback
  const { data: user } = useSuspenseQuery({
    queryKey: ['user', userId],
    queryFn: () => fetchUser(userId),
  });
  
  // This code only runs when data is ready (no loading checks needed)
  return <div>{user.name}</div>;
}

function App() {
  return (
    <Suspense fallback={<UserSkeleton />}>
      <UserProfile userId={1} />
    </Suspense>
  );
}

// Clean pattern: no loading/error states inside UserProfile component
// All handled declaratively by Suspense + Error Boundary above

================================================================
ERROR BOUNDARIES WITH LAZY LOADING
================================================================

WHAT ARE ERROR BOUNDARIES?
───────────────────────────
React Error Boundaries catch errors during rendering (including chunk
loading failures) and display a fallback UI.

REQUIRED: Wrap Suspense in an Error Boundary for robust code splitting:

// ErrorBoundary.jsx
import { Component } from 'react';

class ErrorBoundary extends Component {
  constructor(props) {
    super(props);
    this.state = { hasError: false, error: null };
  }
  
  static getDerivedStateFromError(error) {
    return { hasError: true, error };
  }
  
  componentDidCatch(error, errorInfo) {
    console.error('Error caught:', error, errorInfo);
    // Send to error tracking (Sentry, etc.)
    logErrorToService(error, errorInfo);
  }
  
  render() {
    if (this.state.hasError) {
      return this.props.fallback || (
        <div>
          <h2>Something went wrong.</h2>
          <button onClick={() => this.setState({ hasError: false })}>
            Try Again
          </button>
        </div>
      );
    }
    return this.props.children;
  }
}

// Usage with lazy loading:
const LazyComponent = lazy(() => import('./HeavyComponent'));

function App() {
  return (
    <ErrorBoundary fallback={<ErrorFallback />}>  {/* Catches chunk errors */}
      <Suspense fallback={<LoadingSpinner />}>     {/* Shows loading state */}
        <LazyComponent />
      </Suspense>
    </ErrorBoundary>
  );
}

// Modern React (React 19+ or with use-error-boundary library):
import { useErrorBoundary } from 'react-error-boundary';
// Or the popular library:
import { ErrorBoundary } from 'react-error-boundary';

function App() {
  return (
    <ErrorBoundary
      FallbackComponent={ErrorFallback}
      onReset={() => window.location.reload()}
    >
      <Suspense fallback={<LoadingSpinner />}>
        <LazyComponent />
      </Suspense>
    </ErrorBoundary>
  );
}

================================================================
BEST PRACTICES FOR REACT.LAZY + SUSPENSE
================================================================

1. GOOD FALLBACK UI (Skeleton Screens)
────────────────────────────────────────
// ❌ Bad fallback (jarring spinner, no layout context)
<Suspense fallback={<Spinner />}>
  <LazyPage />
</Suspense>

// ✅ Better fallback (skeleton matches content shape)
<Suspense fallback={<ProductPageSkeleton />}>
  <LazyProductPage />
</Suspense>

// ProductPageSkeleton.jsx - matches real page structure:
function ProductPageSkeleton() {
  return (
    <div className="product-page">
      <div className="skeleton skeleton-image" />
      <div className="skeleton skeleton-title" />
      <div className="skeleton skeleton-price" />
      <div className="skeleton skeleton-description" />
    </div>
  );
}

// CSS for skeletons:
.skeleton {
  background: linear-gradient(90deg, #f0f0f0 25%, #e0e0e0 50%, #f0f0f0 75%);
  background-size: 200% 100%;
  animation: shimmer 1.5s infinite;
  border-radius: 4px;
}

@keyframes shimmer {
  0% { background-position: 200% center; }
  100% { background-position: -200% center; }
}

2. PRELOADING LAZY COMPONENTS
───────────────────────────────
// Preload on hover (before user clicks)
function NavLink({ to, lazyImport, children }) {
  const handleMouseEnter = () => {
    // Start loading the chunk before click
    lazyImport();
  };
  
  return (
    <Link to={to} onMouseEnter={handleMouseEnter}>
      {children}
    </Link>
  );
}

// Alternative: preload after initial load
const LazyDashboard = lazy(() => import('./Dashboard'));

// After initial page load, preload likely next page
window.addEventListener('load', () => {
  setTimeout(() => {
    import('./Dashboard'); // Start loading Dashboard
  }, 2000);
});

3. AVOID LAZY LOADING ABOVE-THE-FOLD CONTENT
──────────────────────────────────────────────
// ❌ Don't lazy-load content users see immediately
const Hero = lazy(() => import('./Hero')); // Bad! Hero is above fold

// ✅ Do lazy-load below-fold content
const Footer = lazy(() => import('./Footer')); // Good! Not visible initially
const CommentsSection = lazy(() => import('./Comments')); // Good! Scroll required

4. GRANULAR SUSPENSE BOUNDARIES
─────────────────────────────────
// ❌ One big Suspense: entire page shows loading
<Suspense fallback={<PageSpinner />}>
  <Header />
  <MainContent />
  <HeavyChart />
  <Footer />
</Suspense>

// ✅ Targeted Suspense: only heavy part shows loading
<Header />
<MainContent />
<Suspense fallback={<ChartSkeleton />}>
  <HeavyChart />
</Suspense>
<Footer />

REACT.LAZY WITH TYPESCRIPT
================================================================

// The lazy import must return a module with default export typed correctly
const LazyComponent: React.LazyExoticComponent<
  React.ComponentType<ComponentProps>
> = lazy(() => import('./Component'));

// Cleaner:
interface ComponentProps {
  title: string;
  onClose: () => void;
}

const Modal = lazy<React.FC<ComponentProps>>(
  () => import('./Modal')
);

// With named exports in TypeScript:
const Chart = lazy(
  () => import('./Charts').then(m => ({ default: m.Chart }))
);

SUSPENSE IN NEXT.JS APP ROUTER (React Server Components)
================================================================

// Next.js 13+ App Router uses Suspense extensively
// loading.tsx file = automatic Suspense boundary for the route segment

// app/dashboard/loading.tsx
export default function DashboardLoading() {
  return <DashboardSkeleton />;
}

// app/dashboard/page.tsx
// This component can be async - Suspense handles loading
export default async function DashboardPage() {
  const data = await fetchDashboardData(); // Can suspend
  return <Dashboard data={data} />;
}

// Nested route loading states handled automatically:
// app/layout.tsx → wraps all routes
// app/dashboard/layout.tsx → wraps dashboard routes
// app/dashboard/loading.tsx → loading for this segment

================================================================
INTERVIEW ANSWERS
================================================================

Q: How does React.lazy() work?
A: React.lazy() takes a function that returns a Promise (dynamic import).
   When the lazy component first renders, React.lazy() triggers the import.
   Internally, it "throws" the promise, which Suspense catches. Suspense
   renders the fallback UI. When the promise resolves (module loaded), React
   re-renders and shows the actual component. The "throw a promise" mechanism
   is React's Suspense protocol.

Q: What's the relationship between Suspense and lazy loading?
A: Suspense is the catch mechanism for asynchronous React operations. When
   a lazy component is loading (or a Suspense-enabled data fetch is pending),
   the component throws a Promise. Suspense catches this and renders the
   fallback until the Promise resolves. Suspense can be nested; each boundary
   catches the nearest pending async operation below it.

Q: Why must you combine Error Boundary with Suspense for lazy loading?
A: Suspense handles the "loading" state. But if the chunk fails to load
   (network error, file missing), it throws an Error, not a Promise. Suspense
   doesn't catch errors — only Error Boundaries do. Without an Error Boundary,
   a failed chunk load crashes the app silently. The Error Boundary catches
   the error and can show a "Something went wrong" UI with a retry option.

Q: What's the best fallback UI for Suspense?
A: Skeleton screens that match the shape of the actual content. A spinner
   is jarring and provides no layout context. A skeleton that mirrors the
   real content structure reduces layout shift, looks professional, and
   gives users a sense of what's loading. It should match the final content
   dimensions closely to avoid CLS when the real content loads.

Q: How does Suspense work with React Server Components in Next.js?
A: In Next.js App Router, you can create a loading.tsx file alongside
   any page.tsx — this automatically wraps the page in a Suspense boundary
   with your loading component as fallback. async Server Components can
   await data and Next.js uses streaming to send the shell immediately
   while suspended components stream in when their data is ready.
