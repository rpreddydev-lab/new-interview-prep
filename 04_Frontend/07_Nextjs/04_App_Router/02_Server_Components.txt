1. WHAT ARE REACT SERVER COMPONENTS?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

React Server Components (RSC) are React components that render exclusively
on the server. Their output (HTML) is sent to the browser but their source
code and any imports are NEVER included in the client JavaScript bundle.

Key properties:
  - Render on the server (Node.js or Edge)
  - Zero JavaScript sent to the client
  - Can be async functions (await data directly)
  - Can access server resources: databases, file system, env secrets
  - Cannot use browser APIs: window, document, localStorage
  - Cannot use React state or lifecycle: useState, useEffect
  - Cannot use event handlers (onClick, onChange, etc.)

In Next.js App Router: all components in app/ are Server Components by DEFAULT.
Add 'use client' to opt into Client Component behavior.

2. SERVER COMPONENT EXAMPLES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  // app/products/page.tsx — Server Component
  // No 'use client' = Server Component

  import { prisma } from '@/lib/prisma';

  export default async function ProductsPage() {
    // Direct database access — no API call needed
    const products = await prisma.product.findMany({
      where: { published: true },
      orderBy: { createdAt: 'desc' },
      take: 20,
    });

    return (
      <main>
        <h1>Products</h1>
        <ul>
          {products.map(product => (
            <li key={product.id}>
              <a href={`/products/${product.id}`}>{product.name}</a>
              <span>${product.price}</span>
            </li>
          ))}
        </ul>
      </main>
    );
  }

  // This component:
  // - Sends zero JS to the client for itself
  // - Prisma code NEVER reaches the browser
  // - Renders the full HTML on the server

3. WHAT SERVER COMPONENTS CAN AND CANNOT DO
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  ✓ CAN DO:
    - async/await (be async functions)
    - Import and use server-only packages (prisma, bcrypt, fs)
    - Access environment variables (including PRIVATE ones without NEXT_PUBLIC_)
    - Read from file system (fs.readFile)
    - Direct database queries
    - Cache and revalidate data
    - Render other Server Components or Client Components

  ✗ CANNOT DO:
    - useState, useReducer (no client state)
    - useEffect, useLayoutEffect (no lifecycle hooks)
    - onClick, onChange (no event handlers)
    - useContext (can read context provided by Client Components)
    - window, document, localStorage, navigator
    - Hooks from third-party libraries (unless they support RSC)

4. HOW SERVER COMPONENTS WORK UNDER THE HOOD
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

React renders the Server Component tree to a special format:
  "RSC Payload" — a JSON-like wire format encoding:
    - The rendered HTML of the server components
    - Placeholders for Client Components (with their props)
    - References to Client Component modules to lazy-load

For the initial page load:
  RSC Payload → converted to HTML → sent to browser
  Browser shows HTML (fast FCP)
  React hydrates only the Client Component boundaries

For subsequent navigations:
  Next.js fetches only the RSC Payload (not full HTML)
  React diffs the new payload against current UI
  Only changed parts of the DOM update

5. COMPOSING SERVER AND CLIENT COMPONENTS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

The Component Tree can mix Server and Client Components:

  // Server Component (outer, fetches data)
  // app/page.tsx
  import { LikeButton } from '@/components/like-button'; // Client Component

  export default async function Page() {
    const posts = await getPosts();  // server-only data fetch
    return (
      <div>
        {posts.map(post => (
          <article key={post.id}>
            <h2>{post.title}</h2>
            {/* Client Component can receive serializable props from Server */}
            <LikeButton postId={post.id} initialLikes={post.likes} />
          </article>
        ))}
      </div>
    );
  }

  // LikeButton.tsx — Client Component
  'use client';
  function LikeButton({ postId, initialLikes }) {
    const [likes, setLikes] = useState(initialLikes);
    return <button onClick={() => setLikes(l => l + 1)}>♥ {likes}</button>;
  }

CRITICAL RULE: Props from Server → Client must be SERIALIZABLE
  ✓ Strings, numbers, booleans, plain objects, arrays
  ✗ Functions, class instances, Dates (must serialize: date.toISOString())
  ✗ Promise objects (pass as children pattern, or use Suspense)

6. SERVER COMPONENTS INSIDE CLIENT COMPONENTS (CHILDREN PATTERN)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Client Components CANNOT import Server Components (would bundle server code).
But Server Components CAN be passed as children to Client Components.

  // ThemeWrapper.tsx — Client Component
  'use client';
  function ThemeWrapper({ children }: { children: React.ReactNode }) {
    const [theme, setTheme] = useState('light');
    return (
      <ThemeContext.Provider value={{ theme, setTheme }}>
        <div data-theme={theme}>{children}</div>
      </ThemeContext.Provider>
    );
  }

  // app/layout.tsx — Server Component
  import { ThemeWrapper } from '@/components/theme-wrapper';
  import { ServerContent } from '@/components/server-content'; // Server Component

  export default function Layout({ children }) {
    return (
      <ThemeWrapper>
        {/* children is a Server Component — it renders on server,
            then passed as an already-rendered RSC payload to ThemeWrapper */}
        {children}
      </ThemeWrapper>
    );
  }

  // This works because the Server Component renders FIRST,
  // its output is passed as children to ThemeWrapper, not imported by it.

7. SERVER-ONLY PACKAGE (PREVENTING ACCIDENTAL CLIENT USE)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  // Install: npm install server-only
  // lib/db.ts
  import 'server-only';  // throws build error if imported in client code

  export async function getUser(id: string) {
    return prisma.user.findUnique({ where: { id } });
  }

  // If a Client Component accidentally imports lib/db.ts, build fails.
  // This prevents leaking DB logic to the client bundle.

  // Similarly: client-only package for browser-only code
  import 'client-only'; // prevents this file being imported in server code

8. ASYNC SERVER COMPONENT PATTERNS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  // Sequential fetch (necessary when second depends on first)
  async function UserPosts({ userId }: { userId: string }) {
    const user = await getUser(userId);
    const posts = await getUserPosts(user.id);  // depends on user
    return <PostsList posts={posts} />;
  }

  // Parallel fetch (independent data)
  async function Dashboard({ userId }: { userId: string }) {
    const [user, stats, notifications] = await Promise.all([
      getUser(userId),
      getUserStats(userId),
      getNotifications(userId),
    ]);
    return <DashboardUI user={user} stats={stats} notifications={notifications} />;
  }

  // Progressive streaming (separate Suspense for each)
  export default async function Page() {
    return (
      <main>
        <Suspense fallback={<UserSkeleton />}>
          <UserProfile />   {/* fetches user data */}
        </Suspense>
        <Suspense fallback={<StatsSkeleton />}>
          <UserStats />     {/* fetches stats — independent */}
        </Suspense>
        <Suspense fallback={<FeedSkeleton />}>
          <ActivityFeed />  {/* fetches feed — independent */}
        </Suspense>
      </main>
    );
  }
  // All three fetch in parallel, each streams in as it's ready.

9. COMMON INTERVIEW QUESTIONS & ANSWERS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q1: What are React Server Components and what's their main benefit?
A:  RSCs render entirely on the server; their code never reaches the browser.
    Main benefits: (1) reduced JavaScript bundle size (server code tree-shaken),
    (2) direct access to databases/file system without an API layer,
    (3) access to private environment variables, (4) improved performance
    (less JS to parse/execute on client), (5) async data fetching directly
    in the component tree.

Q2: Can a Server Component use useState?
A:  No. Server Components have no client-side lifecycle. They execute once on
    the server and return HTML. useState is a React hook for managing
    client-side state — it requires a browser environment to run. Use
    'use client' to add interactivity via hooks.

Q3: Can a Client Component import a Server Component?
A:  No. If a Client Component imports a Server Component, the server-only
    code would be bundled for the client (security risk, bundle bloat).
    The solution is the "children pattern": pass Server Component output as
    children to Client Components. Server renders first, its output is passed
    as props, not imported.

Q4: What happens to environment variables in Server Components?
A:  Server Components can access ALL environment variables (including secrets
    without NEXT_PUBLIC_ prefix). These never reach the browser. In Client
    Components, only NEXT_PUBLIC_ variables are accessible. This is a major
    security advantage — database passwords, API keys stay server-only.

Q5: What must be true about props passed from Server to Client Components?
A:  They must be serializable — able to be sent over the network as JSON.
    Strings, numbers, booleans, plain objects, arrays are fine.
    Functions, class instances, non-serializable objects are not. Dates
    must be serialized as strings. This is because React serializes server
    component output to the RSC payload format before sending to the client.

Q6: What is the server-only package and when would you use it?
A:  import 'server-only' in a file that should NEVER be imported in client code
    (e.g., database utilities, secret-using functions). If a Client Component
    accidentally imports it, the build fails with a clear error — preventing
    accidental exposure of server-only logic to the browser.

  MENTAL MODEL: Think of Server Components as the "backend" of your React app.
  They render HTML on the server with zero runtime on the client.
  Add Client Components at the "leaves" of your tree for interactivity.
