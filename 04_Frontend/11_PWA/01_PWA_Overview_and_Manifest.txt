1. WHAT IS A PWA?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

A Progressive Web App is a web application that uses modern browser APIs to
deliver an app-like experience. The term was coined by Google's Alex Russell in 2015.

CORE CHARACTERISTICS (the PWA checklist):
  - Progressively enhanced (works for all browsers, enhanced for modern ones)
  - Responsive (works on any screen size)
  - Works offline or on low-quality network (Service Worker + cache)
  - Installable (added to home screen without app store)
  - App-like interactions (full-screen, no browser chrome)
  - Fresh (always up to date via Service Worker)
  - Safe (HTTPS only)
  - Discoverable (identified as app via manifest)
  - Linkable (shareable via URL)

THREE PILLARS OF A PWA:
  1. Web App Manifest — enables installability
  2. Service Worker — enables offline and push notifications
  3. HTTPS — required for Service Worker and security

REAL-WORLD PWA EXAMPLES:
  Twitter Lite, Starbucks, Pinterest, Alibaba, Uber, Google Maps

2. WEB APP MANIFEST
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

A JSON file that tells the browser metadata about the app for installation.

    "display": "standalone",          // "standalone" | "fullscreen" | "minimal-ui" | "browser"

    "theme_color": "#007bff",         // Browser toolbar color (Android)
    "orientation": "portrait",
    "scope": "/",                     // Navigation scope — links outside = open in browser
    "icons": [
      {
        "src": "/icons/icon-192.png",
        "sizes": "192x192",
        "type": "image/png",
        "purpose": "any maskable"     // "maskable" = safe area for adaptive icons

        "sizes": "512x512",
        "type": "image/png"
      }
    ],
    "screenshots": [                  // Shown in install dialog (newer browsers)

        "src": "/screenshots/home.png",

        "type": "image/png",
        "form_factor": "wide"
      }
    ],
    "categories": ["shopping", "lifestyle"],

      {

DISPLAY MODES:
  browser    → Regular browser tab (no PWA feel)
  minimal-ui → Browser-like but minimal chrome (back button etc.)
  standalone → Looks like native app — no browser UI, has OS status bar
  fullscreen → Full screen, no OS chrome (games)

3. SERVICE WORKER FOR OFFLINE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

See also: 01_Browser_and_Web_Fundamentals/03_JavaScript_Runtime/05_Service_Workers.txt

CACHING STRATEGIES:
  1. Cache First (fastest, stale risk):
     Check cache → if hit, return; else fetch network and update cache.
     Best for: static assets, fonts, images.

  2. Network First (always fresh, fails offline):
     Try network → if success, cache and return; if fail, return cache.
     Best for: API responses where freshness matters but offline fallback needed.

  3. Stale While Revalidate (best UX):
     Return cached version immediately, then fetch from network in background
     and update cache for next request. Fast AND eventually fresh.
     Best for: content that changes but doesn't need to be instant.

  4. Cache Only:
     Only serve from cache — never network. Good for pre-cached static assets.

  5. Network Only:
     Never cache. Analytics, non-idempotent requests.

IMPLEMENTATION WITH WORKBOX:
  // public/service-worker.js
  import { precacheAndRoute } from 'workbox-precaching';
  import { registerRoute } from 'workbox-routing';
  import { StaleWhileRevalidate, CacheFirst, NetworkFirst } from 'workbox-strategies';
  import { ExpirationPlugin } from 'workbox-expiration';

  // Pre-cache build assets (auto-injected by workbox CLI/webpack plugin)
  precacheAndRoute(self.__WB_MANIFEST);

  // Cache-first for images (long-lived)
  registerRoute(
    ({ request }) => request.destination === 'image',
    new CacheFirst({
      cacheName: 'images',
      plugins: [
        new ExpirationPlugin({ maxEntries: 60, maxAgeSeconds: 30 * 24 * 60 * 60 })
      ],
    })
  );

  // Network-first for API calls with offline fallback
  registerRoute(
    ({ url }) => url.pathname.startsWith('/api/'),
    new NetworkFirst({
      cacheName: 'api-cache',
      plugins: [
        new ExpirationPlugin({ maxEntries: 100, maxAgeSeconds: 60 * 60 }) // 1hr
      ],
    })
  );

  // Stale-while-revalidate for pages
  registerRoute(
    ({ request }) => request.mode === 'navigate',
    new StaleWhileRevalidate({ cacheName: 'pages' })
  );

4. INSTALL PROMPT (beforeinstallprompt)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  // Capture the install prompt event (fired by browser when installable)
  let deferredPrompt;

  window.addEventListener('beforeinstallprompt', (event) => {
    event.preventDefault();         // Prevent automatic browser prompt
    deferredPrompt = event;         // Save it for later
    showInstallButton();            // Show your custom install button
  });

  // When user clicks your install button:
  async function installApp() {
    if (!deferredPrompt) return;
    deferredPrompt.prompt();        // Show the browser's install dialog
    const { outcome } = await deferredPrompt.userChoice;
    if (outcome === 'accepted') {
      console.log('User installed the app');
    }
    deferredPrompt = null;
    hideInstallButton();
  }

  // Detect when app is launched from home screen (not browser):
  window.addEventListener('appinstalled', () => {
    console.log('App was installed');
    analytics.track('pwa_installed');
  });

  // Check if running as standalone (installed):
  const isStandalone = window.matchMedia('(display-mode: standalone)').matches
    || window.navigator.standalone === true; // iOS Safari

REACT COMPONENT EXAMPLE:
  function InstallBanner() {
    const [prompt, setPrompt] = useState(null);

    useEffect(() => {
      const handler = (e) => { e.preventDefault(); setPrompt(e); };
      window.addEventListener('beforeinstallprompt', handler);
      return () => window.removeEventListener('beforeinstallprompt', handler);

    if (!prompt) return null;
    return (
      <div className="install-banner">
        <p>Add this app to your home screen!</p>
        <button onClick={() => { prompt.prompt(); setPrompt(null); }}>
          Install
        </button>
      </div>
    );
  }

5. PUSH NOTIFICATIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  // 1. Request permission
  const permission = await Notification.requestPermission();
  if (permission !== 'granted') return;

  // 2. Subscribe to push service (get a PushSubscription)
  const registration = await navigator.serviceWorker.ready;
  const subscription = await registration.pushManager.subscribe({
    userVisibleOnly: true,          // Required: must show notification to user
    applicationServerKey: urlBase64ToUint8Array(VAPID_PUBLIC_KEY)
  });

  // 3. Send subscription to your server
  await fetch('/api/push-subscribe', {
    method: 'POST',
    body: JSON.stringify(subscription),
    headers: { 'Content-Type': 'application/json' }
  });

  // 4. In Service Worker — handle push event:
  self.addEventListener('push', (event) => {
    const data = event.data.json();
    event.waitUntil(
      self.registration.showNotification(data.title, {
        body: data.body,
        icon: '/icons/icon-192.png',
        data: { url: data.url }
      })
    );
  });

  // 5. Handle notification click:
  self.addEventListener('notificationclick', (event) => {
    event.notification.close();
    event.waitUntil(clients.openWindow(event.notification.data.url));
  });

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: What are the three core components of a PWA?
A: 1. Web App Manifest: JSON file that enables installability — defines app name,
      icons, start URL, display mode, and theme. Linked in <head> with
      <link rel="manifest">.
   2. Service Worker: A JavaScript file that runs in a background thread,
      intercepts network requests, and manages caching for offline support.
      Also enables push notifications and background sync.
   3. HTTPS: Required for Service Workers to run (security requirement).
      Service Workers can only be registered on secure origins (localhost is exempt).

Q: What is the difference between Cache First and Network First strategies?
A: Cache First: checks the cache first; if found, returns cached response
   (ignoring network). Falls back to network if not cached. Fastest response,
   but content may be stale. Best for static assets that change rarely (fonts, icons).
   Network First: tries the network; if successful, caches the response and
   returns it. If the network fails (offline), falls back to cache. Always
   fresh when online, but adds network latency. Best for API data where
   freshness matters. Stale-While-Revalidate combines both: return cache
   immediately (fast) while updating cache from network in background.

Q: How does the install prompt work?
A: The browser fires a "beforeinstallprompt" event when it determines a PWA
   is installable (has a valid manifest, HTTPS, Service Worker). By default,
   the browser may show its own prompt. Best practice: capture the event with
   event.preventDefault(), save the event object, and show your own custom
   "Install App" button in your UI. When the user clicks it, call
   deferredEvent.prompt() to show the browser's native install dialog, then
   await userChoice to know if they accepted. This gives you full control
   over timing and UX of the install prompt.

Q: What is VAPID in push notifications?
A: VAPID (Voluntary Application Server Identification) is a protocol that
   allows your server to identify itself to the push service (Chrome's FCM,
   Firefox's autopush). You generate a VAPID key pair: the public key is
   sent to the browser when subscribing (applicationServerKey), and the
   private key signs push messages your server sends. This proves to the
   push service that messages come from your server, preventing unauthorized
   parties from sending pushes to your users' subscriptions.
