================================================================
  SCHEDULER PATTERN
================================================================

  Category:   Concurrency
  Intent:     Control the order in which threads access shared resources,
              or execute tasks at specified times or intervals.
  Also known: Time-Based Trigger, Cron Job, Task Scheduler

----------------------------------------------------------------
PROBLEM SOLVED
----------------------------------------------------------------

  You need to execute tasks:
    - After a delay (deferred execution).
    - At fixed intervals (periodic execution).
    - At specific calendar times (cron-like scheduling).
    - In priority order (priority scheduling).

  Without a scheduler: manual Thread.sleep(), complex timing logic, error-prone.
  With a scheduler: declarative, reliable, lifecycle-managed.

----------------------------------------------------------------
JAVA SCHEDULEDEXECUTORSERVICE
----------------------------------------------------------------

  // Create a scheduled thread pool
  ScheduledExecutorService scheduler = Executors.newScheduledThreadPool(4);

  // 1. ONE-SHOT DELAYED EXECUTION — run once after delay
  scheduler.schedule(
      () -> System.out.println("Delayed task!"),
      5, TimeUnit.SECONDS
  );

  // 2. FIXED-RATE — run every N ms, regardless of execution duration
  //    Next execution = previous SCHEDULE TIME + period
  //    If task takes longer than period: next runs immediately (catch-up)
  ScheduledFuture<?> fixedRate = scheduler.scheduleAtFixedRate(
      () -> System.out.println("Fixed-rate tick"),
      0,        // initial delay
      1, TimeUnit.SECONDS
  );

  // 3. FIXED-DELAY — run N ms AFTER previous execution COMPLETES
  //    Next execution = previous COMPLETION TIME + delay
  //    If task is slow, next runs later — no catch-up
  ScheduledFuture<?> fixedDelay = scheduler.scheduleWithFixedDelay(
      () -> System.out.println("Fixed-delay tick"),
      0,        // initial delay
      1, TimeUnit.SECONDS
  );

  // Cancel periodic task
  fixedRate.cancel(false);    // false = don't interrupt if running
  fixedDelay.cancel(true);    // true = interrupt if running

  // Shutdown
  scheduler.shutdown();

----------------------------------------------------------------
FIXED-RATE vs FIXED-DELAY (KEY DISTINCTION)
----------------------------------------------------------------

  scheduleAtFixedRate(task, initialDelay, period):
    t=0:  task starts    (schedule time: 0)
    t=2:  task ends      (duration: 2s)
    t=3:  task starts    (next scheduled: 0+3=3s)
    If task takes 5s (> period 3s):
    t=0:  task starts
    t=5:  task ends
    t=5:  IMMEDIATELY starts next (was overdue at t=3)
    Use for: monitoring, heartbeats, regular reporting.

  scheduleWithFixedDelay(task, initialDelay, delay):
    t=0:  task starts
    t=2:  task ends
    t=5:  task starts    (end + delay = 2 + 3 = 5)
    If task takes 5s:
    t=0:  task starts
    t=5:  task ends
    t=8:  task starts    (end + delay = 5 + 3 = 8)
    Use for: polling, retry-on-failure, processing pipelines where
             next run shouldn't start before current completes.

----------------------------------------------------------------
EXCEPTION HANDLING IN SCHEDULED TASKS
----------------------------------------------------------------

  CRITICAL: If a scheduled task throws an unchecked exception,
  the periodic scheduling SILENTLY STOPS. No error logged!

  // BAD — exception kills the schedule
  scheduler.scheduleAtFixedRate(() -> {
      throw new RuntimeException("Oops");  // kills future executions silently
  }, 0, 1, SECONDS);

  // GOOD — catch-all wrapper
  scheduler.scheduleAtFixedRate(() -> {
      try {
          doWork();
      } catch (Exception e) {
          log.error("Scheduled task failed", e);
          // task continues to be scheduled
      }
  }, 0, 1, SECONDS);

  // Or wrap in a utility method:
  Runnable safe(Runnable task) {
      return () -> {
          try { task.run(); }
          catch (Exception e) { log.error("Task error", e); }
      };
  }
  scheduler.scheduleAtFixedRate(safe(() -> doWork()), 0, 1, SECONDS);

SPRING @SCHEDULED
----------------------------------------------------------------

  // Enable scheduling
  @Configuration
  @EnableScheduling
  public class SchedulingConfig { }

  // Scheduled task methods
  @Component
  public class ReportScheduler {

      // Fixed rate: every 5 seconds
      @Scheduled(fixedRate = 5000)
      public void generateReport() {
          System.out.println("Generating report at " + LocalDateTime.now());
      }

      // Fixed delay: 3s after last completion
      @Scheduled(fixedDelay = 3000, initialDelay = 10000)
      public void cleanupTempFiles() {
          System.out.println("Cleaning temp files...");
      }

      // Cron expression: every day at 2:30 AM
      @Scheduled(cron = "0 30 2 * * ?")
      public void dailyBackup() {
          System.out.println("Running daily backup...");
      }

      // Cron from property
      @Scheduled(cron = "${app.backup.cron:0 0 3 * * ?}")
      public void configuredBackup() { ... }
  }

  CRON FORMAT (Spring):
    second  minute  hour  dayOfMonth  month  dayOfWeek
    0       30      2     *           *      ?
    ↑ at second 0, minute 30, hour 2, every day, every month

  Common cron expressions:
    "0 * * * * *"       -- every minute
    "0 */5 * * * *"     -- every 5 minutes
    "0 0 * * * *"       -- every hour
    "0 0 0 * * *"       -- every day at midnight
    "0 0 9 * * MON-FRI" -- weekdays at 9 AM
    "0 0 12 1 * *"      -- 1st of month at noon

  By default Spring's @Scheduled runs in a SINGLE-THREAD pool.
  Configure custom executor:

  @Configuration
  @EnableScheduling
  public class SchedulingConfig implements SchedulingConfigurer {
      @Override
      public void configureTasks(ScheduledTaskRegistrar registrar) {
          registrar.setScheduler(Executors.newScheduledThreadPool(4));
      }
  }

----------------------------------------------------------------
DYNAMIC SCHEDULING (PROGRAMMATIC)
----------------------------------------------------------------

  @Component
  public class DynamicScheduler {
      @Autowired private TaskScheduler taskScheduler;

      private ScheduledFuture<?> scheduledFuture;

      public void startTask(long intervalMs) {
          scheduledFuture = taskScheduler.scheduleAtFixedRate(
              this::doWork,
              Duration.ofMillis(intervalMs)
          );
      }

      public void stopTask() {
          if (scheduledFuture != null) {
              scheduledFuture.cancel(false);
          }
      }

      private void doWork() {
          System.out.println("Working...");
      }
  }

  @Bean
  public TaskScheduler taskScheduler() {
      ThreadPoolTaskScheduler scheduler = new ThreadPoolTaskScheduler();
      scheduler.setPoolSize(4);
      scheduler.setThreadNamePrefix("scheduler-");
      return scheduler;
  }

QUARTZ SCHEDULER (ENTERPRISE SCHEDULING)
----------------------------------------------------------------

  For complex scheduling requirements:
    - Clustered scheduling (only one node runs job in cluster).
    - Persistent jobs (survive server restart).
    - Job dependencies, listeners, priority.

  Key Quartz concepts:
    Job          -- Interface: execute(JobExecutionContext context)
    JobDetail    -- Configures a Job (name, group, durability)
    Trigger      -- When to run (SimpleTrigger=interval, CronTrigger=cron)
    Scheduler    -- Orchestrates Job + Trigger execution
    JobStore     -- RAM (volatile) or JDBC (persistent)

  @Component
  public class QuartzJobExample implements Job {
      @Override
      public void execute(JobExecutionContext context) {
          System.out.println("Quartz job running");
      }
  }

  When to use Quartz:
    - Multiple nodes running same app (clustered jobs).
    - Jobs must survive restarts.
    - Complex job dependencies or chaining.
    - Rich management UI needed.

----------------------------------------------------------------
COMPLEXITY
----------------------------------------------------------------

  Space: O(n) — n pending scheduled tasks in the delay queue.
  Time:  O(log n) — ScheduledExecutorService uses a heap (DelayQueue internally).
         O(1) per task once dequeued and executed.

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: What is the Scheduler pattern?
  A: Controlling when tasks execute — after a delay, at fixed intervals, or
     based on time expressions (cron). Java: ScheduledExecutorService,
     Spring: @Scheduled. Decouples the task logic from timing control.

  Q: Difference between scheduleAtFixedRate and scheduleWithFixedDelay?
  A: fixedRate: period is from start of previous execution. May run immediately
     if previous overran. fixedDelay: period is from END of previous execution.
     Previous must finish before delay countdown starts. Use fixedDelay when
     task duration is variable and overlapping would be problematic.

  Q: What happens if a scheduled task throws an exception?
  A: The periodic scheduling silently stops — no error logged!
     Always wrap scheduled tasks in try-catch. Log errors and let the schedule
     continue. This is a common production bug.

  Q: Spring @Scheduled — how do you make tasks run in parallel?
  A: By default, @Scheduled uses a single thread. Add @Async on the method
     and configure a ThreadPoolTaskExecutor. Or configure SchedulingConfigurer
     to set a ScheduledThreadPoolExecutor with multiple threads.

  Q: When to use Quartz vs @Scheduled?
  A: @Scheduled: simple, single-node, in-process scheduling. Good for most apps.
     Quartz: clustered deployments (only one node fires), persistent jobs
     (survive restart), complex triggers, management API.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------

  - Know fixedRate vs fixedDelay — frequently confused in interviews.
  - ALWAYS mention the silent exception-kills-schedule gotcha.
  - Know common cron expressions cold.
  - Spring @Scheduled + @Async combo for concurrent scheduled tasks.
  - Quartz for enterprise/clustered scheduling.
