================================================================
SECURITY BEST PRACTICES — Application & API Security
================================================================

================================================================
1. SECURE PASSWORD HANDLING
================================================================

NEVER:
  ✗ Store passwords in plain text
  ✗ Use reversible encryption for passwords
  ✗ Use MD5 or SHA1 for passwords
  ✗ Use the same hash for identical passwords (no salt)

ALWAYS:
  ✓ Use adaptive hashing: BCrypt, Argon2id, PBKDF2
  ✓ Use a unique salt per password (bcrypt does this automatically)
  ✓ Use sufficient cost factor (bcrypt: 10-12, Argon2: tuned to ~300ms)
  ✓ Enforce minimum password complexity
  ✓ Check passwords against known breach databases (HaveIBeenPwned API)

// Spring Security BCrypt
@Bean
public PasswordEncoder passwordEncoder() {
    return new BCryptPasswordEncoder(12);
}

// Verify during login
boolean valid = passwordEncoder.matches(rawPassword, storedHash);

BCrypt Hash Format: $2a$12$<22 char salt><31 char hash>

================================================================
2. INPUT VALIDATION
================================================================

PRINCIPLES:
  - Validate on the SERVER — never trust client-side validation alone
  - Whitelist (allow known-good) is better than blacklist (block known-bad)
  - Validate type, length, format, range

JAVA / SPRING VALIDATION:
  @NotNull, @NotBlank, @Size, @Pattern, @Email, @Min, @Max
  Use @Valid on controller method parameters to trigger Bean Validation.

@PostMapping("/users")
public ResponseEntity<User> createUser(@Valid @RequestBody CreateUserRequest request) {
    ...
}

public class CreateUserRequest {
    @NotBlank
    @Size(min = 3, max = 50)
    private String username;

    @Email
    private String email;

    @Pattern(regexp = "^(?=.*[A-Z])(?=.*[0-9]).{8,}$")
    private String password;
}

OUTPUT ENCODING:
  Always encode output before rendering to prevent XSS.
  - HTML context: HTML entity encode (< > & " ')
  - JavaScript context: JavaScript escape
  - URL context: URL encode

================================================================
3. AUTHENTICATION BEST PRACTICES
================================================================

  ✓ Implement MFA for sensitive accounts (TOTP, hardware tokens)
  ✓ Use short-lived tokens (access token: 15min, refresh: days/weeks)
  ✓ Implement proper session management:
      - Generate new session ID after login (prevent fixation)
      - Invalidate session on logout
      - Short absolute and idle timeouts
  ✓ Rate limit login attempts (prevent brute force)
  ✓ Account lockout after N failed attempts (with CAPTCHA to prevent DoS)
  ✓ Secure password reset:
      - Time-limited, single-use tokens
      - Send to verified email/phone only
  ✓ Use OAuth2/OIDC for delegated authentication (don't reinvent the wheel)

================================================================
4. AUTHORIZATION BEST PRACTICES
================================================================

  ✓ Deny by default — reject unless explicitly allowed
  ✓ Enforce authorization in the service layer (not just UI)
  ✓ Use RBAC or ABAC consistently
  ✓ Validate ownership: user can only access THEIR resources
  ✓ Audit privileged operations
  ✓ Principle of least privilege: minimum permissions for every role/service
  ✓ Scope OAuth2 tokens narrowly (read:orders, not admin:all)

// Spring Security: deny by default
http.authorizeHttpRequests(auth -> auth
    .requestMatchers("/public/**").permitAll()
    .anyRequest().authenticated()  // deny everything else
);

================================================================
5. HTTPS & TRANSPORT SECURITY
================================================================

  ✓ HTTPS everywhere — redirect HTTP to HTTPS
  ✓ Use TLS 1.2+ (disable TLS 1.0/1.1)
  ✓ Use strong cipher suites (prefer ECDHE for forward secrecy)
  ✓ Enable HSTS header (Strict-Transport-Security)
  ✓ Renew certificates before expiry (automate with Let's Encrypt + ACME)
  ✓ Check certificate chain is complete and valid

================================================================
6. SECURE HTTP HEADERS
================================================================

Header                          Purpose
-----------------------------------------------------------------------
Content-Security-Policy         Prevent XSS by whitelisting script sources
X-Content-Type-Options: nosniff Prevent MIME-type sniffing
X-Frame-Options: DENY           Prevent clickjacking
Strict-Transport-Security       Force HTTPS
Referrer-Policy                 Control referrer information
Permissions-Policy              Restrict browser features
Cache-Control: no-store         Prevent caching of sensitive responses

In Spring Security:
http.headers(headers -> headers
    .contentSecurityPolicy(csp -> csp
        .policyDirectives("default-src 'self'; script-src 'self'"))
    .frameOptions(frame -> frame.deny())
    .contentTypeOptions(Customizer.withDefaults())
    .httpStrictTransportSecurity(hsts -> hsts
        .includeSubDomains(true)
        .maxAgeInSeconds(31536000))
);

================================================================
7. SECRETS MANAGEMENT
================================================================

NEVER:
  ✗ Hardcode secrets in source code
  ✗ Commit secrets to git
  ✗ Use secrets in URLs (logged by servers)
  ✗ Store secrets in plain text config files

TOOLS:
  - HashiCorp Vault             : Enterprise secrets manager
  - AWS Secrets Manager         : Cloud-native
  - Azure Key Vault             : Azure-native
  - Kubernetes Secrets          : (base64 encoded, use with encryption at rest)
  - Spring Cloud Config Vault   : Spring integration

APPROACHES:
  ✓ Environment variables (injected at runtime)
  ✓ Secrets Manager API calls at startup
  ✓ Rotate secrets regularly and on compromise
  ✓ Audit all secret access

# Spring Boot + environment variable
spring.datasource.password=${DB_PASSWORD}

# Vault integration
spring.cloud.vault.token=${VAULT_TOKEN}
spring.cloud.vault.uri=https://vault.example.com

================================================================
8. LOGGING & MONITORING
================================================================

DO LOG:
  ✓ Authentication events (login success/failure, logout)
  ✓ Authorization failures (403 errors — possible intrusion)
  ✓ Privilege escalation events
  ✓ Admin actions (user created, deleted, role changed)
  ✓ API errors, unusual patterns
  ✓ Timestamps, user ID, IP, request ID (for correlation)

DO NOT LOG:
  ✗ Passwords (even failed attempts should not log the attempted password)
  ✗ API keys, tokens, secrets
  ✗ PII (SSN, credit cards) unless required and encrypted
  ✗ Full request/response bodies by default

ALERTING:
  - Multiple failed logins from same IP (brute force)
  - Login from new geography for existing user
  - Token used after revocation
  - Unusual API call volume (rate spike)

================================================================
9. DEPENDENCY SECURITY
================================================================

  ✓ Keep dependencies up to date (Maven, npm, pip)
  ✓ Use dependency vulnerability scanners:
      - OWASP Dependency-Check (Java)
      - Snyk
      - Dependabot (GitHub)
      - npm audit
  ✓ Pin dependency versions
  ✓ Use official, well-maintained packages
  ✓ Review what you import (supply chain attacks)

# Maven OWASP plugin
<plugin>
    <groupId>org.owasp</groupId>
    <artifactId>dependency-check-maven</artifactId>
    <version>9.0.9</version>
</plugin>

================================================================
10. API SECURITY BEST PRACTICES
================================================================

  ✓ Use HTTPS always
  ✓ Authenticate every request (stateless JWT or session)
  ✓ Validate and authorize every request (no trust by default)
  ✓ Rate limit to prevent abuse (per user, per IP)
  ✓ Use API versioning (/v1/resource)
  ✓ Return appropriate HTTP codes:
      200 OK, 201 Created, 400 Bad Request,
      401 Unauthorized, 403 Forbidden, 404 Not Found, 429 Too Many Requests
  ✓ Never expose stack traces to clients
  ✓ Sanitize error messages (don't leak internals)
  ✓ Document security requirements in API design

GLOBAL EXCEPTION HANDLER (Spring Boot):
@RestControllerAdvice
public class SecurityExceptionHandler {
    @ExceptionHandler(AccessDeniedException.class)
    public ResponseEntity<ErrorResponse> handleAccessDenied(AccessDeniedException e) {
        return ResponseEntity.status(403)
            .body(new ErrorResponse("Access denied"));  // No internal details
    }

    @ExceptionHandler(Exception.class)
    public ResponseEntity<ErrorResponse> handleGeneral(Exception e) {
        log.error("Unexpected error", e);  // Log full stack trace
        return ResponseEntity.status(500)
            .body(new ErrorResponse("Internal server error"));  // Generic message to client
    }
}

================================================================
11. SECURITY IN CI/CD
================================================================

PIPELINE SECURITY CHECKS:
  ✓ Static Application Security Testing (SAST): SpotBugs, Checkmarx, SonarQube
  ✓ Software Composition Analysis (SCA): OWASP Dependency-Check, Snyk
  ✓ Dynamic Application Security Testing (DAST): OWASP ZAP
  ✓ Container image scanning: Trivy, Snyk Container
  ✓ Secret scanning: GitGuardian, truffleHog
  ✓ Infrastructure as Code scanning: tfsec, Checkov

SHIFT LEFT SECURITY:
  Find vulnerabilities early (in code review / CI) rather than in production.
  Cheaper and faster to fix early.

================================================================
COMMON INTERVIEW QUESTIONS
================================================================

Q: What are OWASP's top security best practices for APIs?
A: Use HTTPS, authenticate all requests, validate/sanitize input, implement
   proper authorization, rate limit, log security events, keep dependencies
   updated, and never expose internal errors to clients.

Q: How do you prevent secrets from leaking into git?
A: Use .gitignore, pre-commit hooks (git-secrets, detect-secrets),
   environment variables at runtime, secrets managers (Vault, AWS Secrets
   Manager). Scan git history regularly.

Q: What security headers should every web app return?
A: Content-Security-Policy (XSS), X-Frame-Options (clickjacking),
   X-Content-Type-Options (MIME sniffing), Strict-Transport-Security (HTTPS),
   Referrer-Policy (privacy). These are all configurable in Spring Security.

Q: What is "shift left" in security?
A: Integrating security practices earlier in the development lifecycle (design,
   coding, CI/CD) rather than only testing in production. Cheaper and faster
   to fix security issues early.

Q: How would you secure a Spring Boot microservice?
A: HTTPS with TLS, JWT-based authentication via Spring Security Resource Server,
   role/scope-based authorization with @PreAuthorize, input validation with
   Bean Validation, secure headers, rate limiting, secrets via Vault/env vars,
   actuator endpoints secured, dependency scanning in CI, and structured
   security logging.
