================================================================
GRAPHQL INTROSPECTION — IN DEPTH
================================================================

1. WHAT IS INTROSPECTION?
--------------------------
Introspection is the ability of a GraphQL schema to describe itself. Every
GraphQL server exposes a built-in introspection system that clients can query
to discover:
  - All types in the schema
  - Fields and their types
  - Arguments and their types
  - Directives
  - Deprecations
  - Descriptions/documentation

The schema IS the documentation. No separate doc system needed.

2. HOW INTROSPECTION WORKS
---------------------------
Introspection queries look like regular GraphQL queries but use special
meta-fields and meta-types that start with double underscores (`__`):

  __schema    → Information about the whole schema
  __type      → Information about a specific type
  __typename  → The runtime type of an object (available on all types)

Built-in introspection types:
  __Schema        → schema metadata
  __Type          → type info (name, kind, fields, etc.)
  __Field         → field info
  __InputValue    → argument / input field info
  __EnumValue     → enum value info
  __Directive     → directive info
  __DirectiveLocation → where a directive can be used

3. INTROSPECTION QUERIES
-------------------------

  3.1 Get all types
  -----------------
  ```graphql
  {
    __schema {
      types {
        name
        kind
        description
      }
    }
  }
  ```

  Response includes built-in types like __Schema, Boolean, String, etc.
  Filter by kind to see user-defined types:
  ```graphql
  {
    __schema {
      types {
        name
        kind
      }
    }
  }
  ```

  3.2 Get all query fields
  -------------------------
  ```graphql
  {
    __schema {
      queryType {
        name
        fields {
          name
          description
          type {
            name
            kind
          }
          args {
            name
            type { name kind }
            defaultValue
          }
        }
      }
    }
  }
  ```

  3.3 Get details about a specific type
  ---------------------------------------
  ```graphql
  {
    __type(name: "User") {
      name
      kind
      description
      fields {
        name
        description
        isDeprecated
        deprecationReason
        type {
          name
          kind
          ofType {          # For NON_NULL and LIST wrappers
            name
            kind
          }
        }
        args {
          name
          type { name kind ofType { name kind } }
          defaultValue
        }
      }
    }
  }
  ```

  3.4 Get mutation type fields
  ------------------------------
  ```graphql
  {
    __schema {
      mutationType {
        fields {
          name
          description
          args {
            name
            type { name kind ofType { name } }
          }
        }
      }
    }
  }
  ```

  3.5 Get all directives
  -----------------------
  ```graphql
  {
    __schema {
      directives {
        name
        description
        locations
        args {
          name
          type { name kind }
          defaultValue
        }
      }
    }
  }
  ```

  3.6 The FULL Introspection Query (used by tools like GraphiQL)
  ---------------------------------------------------------------
  The full introspection query is a large, standardized query that retrieves
  the entire schema structure. Tools like GraphiQL, Apollo Studio, and
  graphql-codegen use it to understand your schema:

  ```graphql
  query IntrospectionQuery {
    __schema {
      queryType { name }
      mutationType { name }
      subscriptionType { name }
      types {
        ...FullType
      }
      directives {
        name
        description
        locations
        args { ...InputValue }
      }
    }
  }

  fragment FullType on __Type {
    kind
    name
    description
    fields(includeDeprecated: true) {
      name
      description
      args { ...InputValue }
      type { ...TypeRef }
      isDeprecated
      deprecationReason
    }
    inputFields { ...InputValue }
    interfaces { ...TypeRef }
    enumValues(includeDeprecated: true) {
      name
      description
      isDeprecated
      deprecationReason
    }
    possibleTypes { ...TypeRef }
  }

  fragment InputValue on __InputValue {
    name
    description
    type { ...TypeRef }
    defaultValue
  }

  fragment TypeRef on __Type {
    kind
    name
    ofType {
      kind
      name
      ofType {
        kind
        name
        ofType { kind name ofType { kind name ofType { kind name } } }
      }
    }
  }
  ```

4. TYPE KINDS
--------------
The `kind` field on __Type returns one of:

  SCALAR        → Int, String, Boolean, ID, custom scalars
  OBJECT        → type User { ... }
  INTERFACE     → interface Node { ... }
  UNION         → union SearchResult = ...
  ENUM          → enum Status { ... }
  INPUT_OBJECT  → input CreateUserInput { ... }
  LIST          → [Type]
  NON_NULL      → Type!

NON_NULL and LIST are "wrapping types" — they have an `ofType` field pointing
to the wrapped type. This nesting can be multiple levels deep:
  `[String!]!` → NON_NULL → LIST → NON_NULL → SCALAR(String)

5. __TYPENAME IN PRACTICE
--------------------------
The `__typename` meta-field is available on every Object, Interface, and Union:

```graphql
query {
  user(id: "1") {
    __typename    # Returns "User"
    name
  }
  search(q: "alice") {
    __typename    # Returns "User" or "Product" or "Article"
    ... on User { name }
    ... on Product { name price }
  }
}
```

Apollo Client automatically adds `__typename` to all queries for cache
normalization. You can see it in every Apollo request.

6. USING INTROSPECTION FOR TOOLING
------------------------------------

  Tools that use introspection:
  - GraphiQL / GraphQL Playground   → auto-complete, docs browser
  - Apollo Sandbox                   → schema explorer
  - Apollo Client DevTools           → cache inspection
  - graphql-codegen                  → generates TypeScript types from schema
  - Postman, Insomnia                → schema import for auto-complete
  - SchemaInspector                  → schema diffing, breaking change detection

7. DISABLING INTROSPECTION IN PRODUCTION
------------------------------------------
Introspection exposes your entire API contract. In production:
  - Attackers can enumerate all types, fields, mutations
  - Reveals internal naming conventions, business domain model
  - Makes targeted attacks easier

Disable introspection in production (Spring Boot):

```yaml
# application-production.yml
spring:
  graphql:
    schema:
      introspection:
        enabled: false
```

Or use a validation rule:
```java
@Bean
public Instrumentation noIntrospectionInstrumentation() {
  return new SimpleInstrumentation() {
    @Override
    public InstrumentationValidationParameters beginValidation(
        InstrumentationValidationParameters parameters) {
      if (isProduction()) {
        // Add NoSchemaIntrospectionCustomizer rule
      }
      return super.beginValidation(parameters);
    }
  };
}
```

Best practice:
  - Disable full introspection in production
  - Allow `__typename` (needed by Apollo Client's cache — hard to disable)
  - Use schema registry (Apollo Studio) for documentation instead
  - Optionally: allow introspection for authenticated admin users only

8. INTROSPECTION AND CODE GENERATION
--------------------------------------
graphql-codegen reads your schema via introspection (or a .graphql file)
and generates:
  - TypeScript types for all schema types
  - Typed hooks for each query/mutation
  - Type-safe mock data

```yaml
# codegen.yml
schema: "http://localhost:8080/graphql"    # Via introspection
documents: "src/**/*.graphql"              # Your queries/mutations
generates:
  src/generated/graphql.ts:
    plugins:
      - typescript
      - typescript-operations
      - typescript-react-apollo
```

This eliminates TypeScript boilerplate and keeps frontend in sync with schema.

9. SCHEMA INTROSPECTION IN JAVA
---------------------------------
You can query your own schema programmatically:

```java
@Autowired
private GraphQL graphQL;

public List<String> getAllTypeNames() {
  ExecutionResult result = graphQL.execute(
    ExecutionInput.newExecutionInput()
      .query("{ __schema { types { name } } }")
      .build()
  );
  // Parse result...
}
```

Or access the GraphQLSchema directly:
```java
@Autowired
private GraphQLSchema graphQLSchema;

public void inspectSchema() {
  // Get all types
  Map<String, GraphQLNamedType> types = graphQLSchema.getTypeMap();

  // Get a specific type
  GraphQLObjectType userType = (GraphQLObjectType) graphQLSchema.getType("User");

  // Get fields
  userType.getFieldDefinitions().forEach(field ->
    System.out.println(field.getName() + ": " + field.getType())
  );
}
```

10. INTROSPECTION AS A SECURITY CONCERN
----------------------------------------
Even with introspection disabled, attackers can:
  - Use field suggestion (GraphQL suggests similar field names on typo)
  - Try common field names (id, name, email, createdAt, etc.)
  - Use Apollo's @deprecated information

Additional hardening:
  - Disable field suggestions (some servers have this option)
  - Apply rate limiting to ALL GraphQL requests
  - Monitor for introspection-shaped queries even if disabled

11. INTERVIEW QUESTIONS & ANSWERS
-----------------------------------

Q: What is GraphQL introspection and how does it work?
A: Introspection allows clients to query the schema itself using special
   meta-fields (__schema, __type, __typename). The GraphQL runtime handles
   these automatically without any user resolver code. Tools use the full
   introspection query to build IDEs, auto-complete, code generators, and
   schema documentation.

Q: Should introspection be enabled in production? Why?
A: No, or at least with restrictions. Introspection exposes your entire API
   surface — all types, fields, mutations, and their structure. This helps
   attackers enumerate attack vectors, understand your business model, and
   craft targeted exploits. Disable it in production; use a schema registry
   (Apollo Studio) or API gateway for documentation.

Q: What is __typename and can it be disabled?
A: __typename is a meta-field on every Object, Interface, and Union type
   that returns the runtime type name. Apollo Client requires it for cache
   normalization. It's technically part of the GraphQL spec and very hard
   to disable without breaking clients. Most implementations keep __typename
   enabled even when disabling full introspection.

Q: What is graphql-codegen and how does it use introspection?
A: graphql-codegen is a tool that reads a GraphQL schema (via introspection
   or SDL files) and generates typed code (TypeScript, Java, etc.) for your
   queries, mutations, and types. It keeps client code in sync with the schema
   and eliminates manual type writing. It uses the full introspection query
   to understand the complete schema structure.

Q: What does the `ofType` field in introspection represent?
A: NON_NULL and LIST are wrapping types that don't have a name — they wrap
   another type. `ofType` traverses the wrapper chain. For example,
   `[String!]!` is represented as: NonNull → List → NonNull → Scalar(String).
   Each level has `kind` and `ofType` fields to traverse the chain.

Q: How do you build an autocomplete feature using introspection?
A: Query `__type(name: "TypeName") { fields { name type { name } } }` to
   get all fields of a type. When a user types a field name, filter against
   the returned field names. GraphiQL and IDE plugins (Apollo VS Code) use
   this exact mechanism for autocomplete and validation in real-time.
