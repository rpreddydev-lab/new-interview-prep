SPRING FOR GRAPHQL — FRAMEWORK OVERVIEW
================================================================

1. WHAT IS SPRING FOR GRAPHQL?
--------------------------------
Spring for GraphQL is the official Spring integration for GraphQL (as of
Spring Boot 2.7 / Spring Framework 5.3). It builds on top of the
graphql-java library and integrates deeply with the Spring ecosystem:
Spring MVC, Spring WebFlux, Spring Security, Spring Data, and more.

Key features:
  - Annotation-based controllers (@QueryMapping, @MutationMapping, etc.)
  - HTTP & WebSocket transport support
  - Built-in DataLoader integration
  - Schema inspection and bootstrapping
  - Testing support (GraphQlTester)
  - Spring Security integration
  - Auto-configuration via Spring Boot

GitHub: https://github.com/spring-projects/spring-graphql
Docs:   https://docs.spring.io/spring-graphql/

2. ADDING SPRING FOR GRAPHQL TO A PROJECT
-------------------------------------------
  2.1 Maven Dependencies
  -----------------------
  ```xml
  <dependencies>
    <!-- Core Spring for GraphQL over HTTP (Spring MVC) -->
    <dependency>
      <groupId>org.springframework.boot</groupId>
      <artifactId>spring-boot-starter-graphql</artifactId>
    </dependency>

    <!-- Web layer (choose one) -->
    <dependency>
      <groupId>org.springframework.boot</groupId>
      <artifactId>spring-boot-starter-web</artifactId>          <!-- MVC -->
    </dependency>
    <!-- OR -->
    <dependency>
      <groupId>org.springframework.boot</groupId>
      <artifactId>spring-boot-starter-webflux</artifactId>      <!-- WebFlux -->
    </dependency>

    <!-- WebSocket for subscriptions -->
    <dependency>
      <groupId>org.springframework.boot</groupId>
      <artifactId>spring-boot-starter-websocket</artifactId>
    </dependency>

    <!-- Testing -->
    <dependency>
      <groupId>org.springframework.graphql</groupId>
      <artifactId>spring-graphql-test</artifactId>
      <scope>test</scope>
    </dependency>
  </dependencies>
  ```

  2.2 Gradle
  -----------
  ```groovy
  dependencies {
    implementation 'org.springframework.boot:spring-boot-starter-graphql'
    implementation 'org.springframework.boot:spring-boot-starter-web'
    testImplementation 'org.springframework.graphql:spring-graphql-test'
  }
  ```

3. SCHEMA SETUP
----------------
By default, Spring for GraphQL loads schema files from:
  `src/main/resources/graphql/*.graphqls`

```
src/main/resources/
  graphql/
    schema.graphqls        # Main schema
    user.graphqls          # User types (can split into multiple files)
    post.graphqls          # Post types
```

All .graphqls files in the graphql folder are automatically merged.

```yaml
# application.yml
spring:
  graphql:
    schema:
      locations: classpath:graphql/**   # default
      file-extensions: .graphqls,.gql  # default
    graphiql:
      enabled: true                     # Enable GraphiQL browser at /graphiql
      path: /graphiql
    path: /graphql                      # GraphQL HTTP endpoint
    websocket:
      path: /graphql                    # Same path works for both
```

4. CONTROLLER-BASED RESOLVERS
-------------------------------
@Controller + @QueryMapping / @MutationMapping / etc. is the preferred style.

  4.1 Query Resolver
  -------------------
  ```java
  @Controller
  public class UserController {
    private final UserService userService;

    @QueryMapping                        // maps to "Query.users"
    public List<User> users() {
      return userService.findAll();
    }

    @QueryMapping                        // maps to "Query.user"
    public User user(@Argument Long id) {
      return userService.findById(id)
        .orElseThrow(() -> new ResourceNotFoundException("User", id));
    }
  }
  ```

  4.2 Mutation Resolver
  ----------------------
  ```java
  @Controller
  public class UserMutationController {
    @MutationMapping
    public User createUser(@Argument CreateUserInput input) {
      return userService.create(input);
    }

    @MutationMapping
    public User updateUser(@Argument Long id, @Argument UpdateUserInput input) {
      return userService.update(id, input);
    }

    @MutationMapping
    public Boolean deleteUser(@Argument Long id) {
      userService.delete(id);
      return true;
    }
  }
  ```

  4.3 Subscription Resolver
  --------------------------
  ```java
  @Controller
  public class MessageController {
    private final MessageService messageService;

    @SubscriptionMapping
    public Flux<Message> messageAdded(@Argument Long channelId) {
      return messageService.streamMessagesForChannel(channelId);
    }
  }
  ```

  4.4 Field Resolver (@SchemaMapping)
  -------------------------------------
  ```java
  @Controller
  public class PostController {
    @SchemaMapping(typeName = "Post", field = "author")
    public User author(Post post) {
      return userService.findById(post.getAuthorId()).orElse(null);
    }

    // Or shorthand (typeName inferred from parent type param)
    @SchemaMapping
    public List<Comment> comments(Post post) {    // typeName = "Post", field = "comments"
      return commentService.findByPostId(post.getId());
    }
  }
  ```

5. GRAPHQL RUNTIME WIRING
---------------------------
For programmatic control over the schema (custom scalars, type resolvers,
directive wiring):

```java
@Configuration
public class GraphQLConfig {

  @Bean
  public RuntimeWiringConfigurer runtimeWiringConfigurer() {
    return builder -> builder
      .scalar(ExtendedScalars.Date)
      .scalar(ExtendedScalars.DateTime)
      .scalar(ExtendedScalars.Json)
      .directive("auth", new AuthDirectiveWiring())
      .type("Query", wiring -> wiring
        .dataFetcher("search", new SearchDataFetcher()));
  }
}
```

6. SCHEMA INSPECTION AND TYPE SYSTEM HOOK
-------------------------------------------
```java
@Configuration
public class SchemaConfig {

  @Bean
  public GraphQlSourceBuilderCustomizer customizer() {
    return builder -> builder
      .schemaFactory((typeDefinitionRegistry, runtimeWiring) -> {
        // Modify schema before it is used
        SchemaGenerator generator = new SchemaGenerator();
        return generator.makeExecutableSchema(typeDefinitionRegistry, runtimeWiring);
      });
  }
}
```

7. GRAPHIQL BROWSER
---------------------
Spring for GraphQL ships with GraphiQL (the interactive query editor).

Enable in properties:
```yaml
spring:
  graphql:
    graphiql:
      enabled: true
      path: /graphiql
```

Access at: http://localhost:8080/graphiql

GraphiQL provides:
  - Schema documentation explorer
  - Query autocompletion
  - Query history
  - Variable and headers panels

8. EXCEPTION HANDLING (OVERVIEW)
----------------------------------
```java
@Component
public class GraphQLExceptionResolver extends DataFetcherExceptionResolverAdapter {
  @Override
  protected GraphQLError resolveToSingleError(Throwable ex, DataFetchingEnvironment env) {
    if (ex instanceof ResourceNotFoundException) {
      return GraphqlErrorBuilder.newError(env)
        .message(ex.getMessage())
        .errorType(ErrorType.NOT_FOUND)
        .build();
    }
    return null; // Use default error handling
  }
}
```

9. DEFAULT ENDPOINTS
----------------------

  GET /graphiql              → GraphiQL browser (if enabled)
  GET /actuator/graphql      → Actuator health/info (if enabled)

10. COMPARISON: SPRING GRAPHQL vs PURE GRAPHQL-JAVA
------------------------------------------------------
  Feature                  Spring for GraphQL      Pure graphql-java
  -----------------------------------------------------------------
  Annotations              ✅ @QueryMapping etc.   ❌ Manual wiring
  Schema loading           ✅ Auto from classpath   ⚠️ Manual
  DataLoader integration   ✅ @BatchMapping          ⚠️ Manual registry
  Security integration     ✅ Built-in               ❌ Manual
  Testing support          ✅ GraphQlTester           ❌ DIY
  WebSocket                ✅ Built-in               ❌ Manual
  Spring Boot autoconfigure ✅ Full                  ❌ None
  Complexity               Low                      High
  Control                  Medium                   Full

11. INTERVIEW QUESTIONS & ANSWERS
-----------------------------------

Q: What is Spring for GraphQL and how does it differ from graphql-java?
A: Spring for GraphQL is the official Spring integration that builds on top
   of graphql-java. graphql-java provides the core execution engine but
   requires manual wiring. Spring for GraphQL adds: annotation-based
   controllers (@QueryMapping), automatic schema loading, DataLoader
   integration via @BatchMapping, Spring Security support, GraphQlTester
   for tests, and WebSocket support — all with Spring Boot autoconfiguration.

Q: Where does Spring for GraphQL expect schema files to be placed?
A: By default in `src/main/resources/graphql/` with `.graphqls` or `.gql`
   extensions. All files in that directory are merged automatically.
   The location and extensions can be customized in application.yml.

Q: How do you expose a GraphQL query in Spring for GraphQL?
A: Annotate a @Controller method with @QueryMapping. The method name (or
   value attribute) maps to the field name on the Query type. Arguments
   are injected with @Argument. Return types are automatically coerced.

Q: What is RuntimeWiringConfigurer used for?
A: For programmatic schema wiring: registering custom scalars, directive
   wirings, type resolvers for interfaces/unions, and manual DataFetchers.
   It's a @Bean that receives a RuntimeWiring.Builder.

Q: How does Spring for GraphQL handle subscriptions?
A: Subscription methods annotated with @SubscriptionMapping return
   Flux<T> (Project Reactor). Spring for GraphQL transports these via
   WebSocket using the graphql-ws protocol. You need
   spring-boot-starter-websocket on the classpath.

Q: What HTTP method does GraphQL use?
A: Primarily POST (query + variables in JSON body). GET is also supported
   for simple queries (query parameters). Spring for GraphQL handles both.
   The endpoint is /graphql by default.
