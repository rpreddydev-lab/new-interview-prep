1. TRADITIONAL FORM SUBMISSION
================================================================================

When a form is submitted the traditional way (no JavaScript):
  1. Browser validates form (unless novalidate)
  2. Serializes form data based on enctype
  3. Sends HTTP request (GET or POST)
  4. Page navigates to the response URL
  5. Browser renders the new page

How data is serialized for GET:
  <form method="get" action="/search">
    <input type="text" name="q" value="html forms">
    <input type="number" name="page" value="1">
    <button type="submit">Search</button>
  </form>
  
  → Browser navigates to: /search?q=html+forms&page=1
  
  URL encoding rules:
    Spaces → + (or %20)
    Special chars → percent-encoded (%40 for @, etc.)
    Multiple values → name=val1&name=val2

What gets submitted:
  ✓ Named inputs that are NOT disabled
  ✓ Checked checkboxes and selected radios (by name + value)
  ✓ Selected <option> values (by select's name)
  ✓ Textarea contents (by name)
  ✓ Submit button that was clicked (if it has a name attribute)
  ✗ Unchecked checkboxes (no key/value sent)
  ✗ Disabled inputs
  ✗ Inputs without a name attribute
  ✗ Inputs outside the form (unless they have the form attribute)

Including submit button value (for multiple submit buttons):
  <button type="submit" name="action" value="save">Save Draft</button>
  <button type="submit" name="action" value="publish">Publish</button>
  
  Clicking "Save Draft" submits: action=save
  Clicking "Publish" submits: action=publish

2. THE action, method, AND enctype ATTRIBUTES
================================================================================

action — Where to submit the form:
  <form action="/api/register">         Absolute path
  <form action="https://api.example.com/register">   Full URL
  <form action="">                      Current URL (default)
  <form action="./submit">             Relative path
  
  Can be overridden per submit button with formaction:
  <button type="submit" formaction="/api/save-draft">Save</button>
  <button type="submit" formaction="/api/publish">Publish</button>

method — HTTP method:
  GET  — Appends data to URL; for idempotent, non-sensitive actions
  POST — Sends data in body; for creating/updating/deleting data, files, passwords
  
  Note: HTML forms only support GET and POST.
  For PUT/DELETE/PATCH (REST APIs), use JavaScript fetch.
  
  formmethod override:
  <button type="submit" formmethod="post" formaction="/delete">Delete</button>

enctype — How POST body is encoded:

  1. application/x-www-form-urlencoded (DEFAULT for POST)
     - Key=value pairs URL-encoded, & separated
     - Request body: name=John+Doe&email=john%40example.com
     - OK for text data; NOT for files

  2. multipart/form-data (REQUIRED for file uploads)
     - Body split into parts with a boundary string
     - Each part has its own Content-Disposition header
     - Binary data transmitted intact
     - Required when form has <input type="file">

  3. text/plain (DEBUGGING ONLY)
     - Minimal encoding; not reliable for production
     - Values may contain characters that corrupt other values

  Example — POST with file:
  <form method="post" enctype="multipart/form-data" action="/upload">
    <input type="text" name="title">
    <input type="file" name="image">
    <button type="submit">Upload</button>
  </form>

3. SUBMITTING WITH JAVASCRIPT (fetch + FormData)
================================================================================

Modern approach: Intercept submit, send with fetch, update DOM without page reload.

  const form = document.querySelector('#contact-form');
  
  form.addEventListener('submit', async (e) => {
    e.preventDefault();  // Prevent traditional navigation
    
    const submitBtn = form.querySelector('[type="submit"]');
    submitBtn.disabled = true;
    submitBtn.textContent = 'Sending...';
    
    try {
      const formData = new FormData(form);
      
      const response = await fetch(form.action, {
        method: form.method,
        body: formData,
        // No Content-Type header — fetch sets it automatically with boundary
      });
      
      if (!response.ok) {
        const error = await response.json();
        throw new Error(error.message || 'Submission failed');
      }
      
      const result = await response.json();
      showSuccess('Form submitted successfully!');
      form.reset();
      
    } catch (err) {
      showError(err.message);
    } finally {
      submitBtn.disabled = false;
      submitBtn.textContent = 'Submit';
    }
  });

IMPORTANT: Do NOT manually set Content-Type when using FormData with fetch!
  ✗ headers: { 'Content-Type': 'multipart/form-data' }  // BUG: no boundary
  ✓ Let fetch set it automatically (it includes the boundary string)

For JSON submission (when server expects JSON):
  form.addEventListener('submit', async (e) => {
    e.preventDefault();
    
    const data = Object.fromEntries(new FormData(form));
    
    const response = await fetch('/api/contact', {
      method: 'POST',
      headers: {
        'Content-Type': 'application/json',
        'Accept': 'application/json',
      },
      body: JSON.stringify(data),
    });
    // ...
  });

4. THE FormData API
================================================================================

FormData is a built-in class for constructing key/value pairs for form submission.

Creating FormData:
  // From a form element — captures all valid fields
  const formData = new FormData(formElement);
  
  // Empty — add fields manually
  const formData = new FormData();
  formData.append('name', 'John Doe');
  formData.append('email', 'john@example.com');
  formData.append('avatar', fileInput.files[0], 'avatar.jpg');

FormData methods:
  formData.append(name, value[, filename])  — Add field (allows duplicates)
  formData.set(name, value[, filename])     — Set field (replaces existing)
  formData.get(name)                        — Get first value for name
  formData.getAll(name)                     — Get all values for name (for multi-select, checkboxes)
  formData.has(name)                        — Check if name exists
  formData.delete(name)                     — Remove field
  formData.keys()                           — Iterator of field names
  formData.values()                         — Iterator of values
  formData.entries()                        — Iterator of [name, value] pairs

Converting FormData to plain object:
  // Works for forms WITHOUT duplicate field names
  const data = Object.fromEntries(formData);
  // { name: "John", email: "john@..." }

  // Handle duplicate names (checkboxes with same name):
  const data = {};
  formData.forEach((value, key) => {
    if (key in data) {
      data[key] = [].concat(data[key], value);
    } else {
      data[key] = value;
    }
  });
  
  // Or more elegantly:
  const data = [...formData.entries()].reduce((acc, [key, value]) => {
    if (acc[key]) {
      acc[key] = [].concat(acc[key], value);
    } else {
      acc[key] = value;
    }
    return acc;
  }, {});

Inspecting FormData contents:
  for (const [key, value] of formData) {
    console.log(`${key}: ${value}`);
  }
  
  // Convert to array for debugging
  console.log([...formData.entries()]);

FormData with files:
  const fileInput = document.querySelector('input[type="file"]');
  const formData = new FormData();
  
  // Single file
  formData.append('photo', fileInput.files[0]);
  
  // Multiple files
  for (const file of fileInput.files) {
    formData.append('photos', file);
  }
  
  // With custom filename (overrides original file.name)
  formData.append('avatar', file, 'profile.jpg');

5. AJAX FORM SUBMISSION PATTERN
================================================================================

Complete production-ready pattern with loading state, error handling, CSRF:

  async function submitForm(form) {
    const formData = new FormData(form);
    
    // Get CSRF token from meta tag
    const csrfToken = document.querySelector('meta[name="csrf-token"]')?.content;
    
    const headers = {
      'Accept': 'application/json',
      'X-CSRF-Token': csrfToken,
      'X-Requested-With': 'XMLHttpRequest',
    };
    
    // Don't set Content-Type for FormData (multipart boundary)
    // Set it for JSON
    
    const response = await fetch(form.action || window.location.href, {
      method: form.method.toUpperCase() || 'POST',
      headers,
      body: formData,
      credentials: 'same-origin',  // Include cookies for session
    });
    
    const contentType = response.headers.get('Content-Type') || '';
    const data = contentType.includes('application/json')
      ? await response.json()
      : await response.text();
    
    if (!response.ok) {
      const error = new Error(data?.message || `HTTP error ${response.status}`);
      error.status = response.status;
      error.data = data;
      throw error;
    }
    
    return data;
  }

Handling validation errors from server (422 Unprocessable Entity):
  try {
    const result = await submitForm(form);
    showSuccess(result.message);
  } catch (err) {
    if (err.status === 422 && err.data?.errors) {
      // Server returned field-level errors
      Object.entries(err.data.errors).forEach(([field, messages]) => {
        const input = form.querySelector(`[name="${field}"]`);
        if (input) {
          input.setCustomValidity(messages[0]);
          showFieldError(input, messages[0]);
        }
      });
    } else {
      showGlobalError(err.message);
    }
  }

6. HANDLING SERVER RESPONSES
================================================================================

HTTP status codes and form handling:
  200 OK       — Success; process response body
  201 Created  — Resource created; redirect or show success
  400 Bad Request — Client error; show message
  401 Unauthorized — Not logged in; redirect to login
  403 Forbidden — Logged in but not allowed; show error
  404 Not Found — Endpoint wrong; developer bug
  409 Conflict  — Duplicate (e.g., email taken); show field error
  422 Unprocessable Entity — Validation errors; show field errors
  429 Too Many Requests — Rate limited; show retry message
  500 Internal Server Error — Server bug; show generic error

Redirect after successful POST (PRG pattern):
  Traditional forms use Post/Redirect/Get (PRG) to prevent double-submit on refresh.
  Browser submits POST → Server processes and returns 303 See Other → Browser GETs
  new URL (e.g., success page). This way, refreshing the success page doesn't
  resubmit the form.
  
  With fetch/AJAX, you handle this in JavaScript:
  if (response.ok) {
    window.location.href = '/dashboard';  // Manual redirect
    // Or update the page without redirecting:
    updateUI(result);
  }

7. FILE UPLOAD WITH FETCH
================================================================================

Simple file upload:
  const fileInput = document.querySelector('input[type="file"]');
  const form = document.querySelector('form');
  
  form.addEventListener('submit', async (e) => {
    e.preventDefault();
    
    if (!fileInput.files.length) {
      alert('Please select a file');
      return;
    }
    
    const formData = new FormData();
    formData.append('file', fileInput.files[0]);
    formData.append('title', document.querySelector('#title').value);
    
    const response = await fetch('/api/upload', {
      method: 'POST',
      body: formData,
      // NO Content-Type header! fetch adds multipart/form-data with boundary
    });
    
    const result = await response.json();
    console.log('Uploaded:', result.url);
  });

Upload with progress tracking (XMLHttpRequest):
  const xhr = new XMLHttpRequest();
  
  xhr.upload.addEventListener('progress', (e) => {
    if (e.lengthComputable) {
      const percent = (e.loaded / e.total) * 100;
      progressBar.value = percent;
      progressText.textContent = `${Math.round(percent)}%`;
    }
  });
  
  xhr.addEventListener('load', () => {
    if (xhr.status === 200) {
      const result = JSON.parse(xhr.responseText);
      showSuccess(result);
    }
  });
  
  xhr.open('POST', '/api/upload');
  xhr.send(formData);

Upload with progress using fetch (streams — modern):
  // fetch doesn't have upload progress in most browsers yet
  // Use XMLHttpRequest for reliable upload progress tracking

Chunked upload for large files:
  const CHUNK_SIZE = 1 * 1024 * 1024;  // 1MB chunks
  const file = fileInput.files[0];
  const chunks = Math.ceil(file.size / CHUNK_SIZE);
  
  for (let i = 0; i < chunks; i++) {
    const start = i * CHUNK_SIZE;
    const end = Math.min(start + CHUNK_SIZE, file.size);
    const chunk = file.slice(start, end);
    
    const formData = new FormData();
    formData.append('chunk', chunk);
    formData.append('chunkIndex', i);
    formData.append('totalChunks', chunks);
    formData.append('filename', file.name);
    
    await fetch('/api/upload-chunk', { method: 'POST', body: formData });
    
    const progress = ((i + 1) / chunks) * 100;
    progressBar.value = progress;
  }
  
  // Tell server to assemble the chunks
  await fetch('/api/assemble', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ filename: file.name, totalChunks: chunks })
  });

8. FORM SERIALIZATION
================================================================================

Converting form data to various formats:

To URL-encoded string (like GET params):
  const formData = new FormData(form);
  const params = new URLSearchParams(formData);
  const queryString = params.toString();
  // "name=John&email=john%40example.com"

To JSON:
  const data = Object.fromEntries(new FormData(form));
  const json = JSON.stringify(data);
  // '{"name":"John","email":"john@example.com"}'
  
  // Handling arrays (checkboxes with same name):
  function formToJSON(form) {
    const result = {};
    new FormData(form).forEach((value, key) => {
      if (result[key] !== undefined) {
        result[key] = [].concat(result[key], value);
      } else {
        result[key] = value;
      }
    });
    return result;
  }

To URLSearchParams (for fetch with application/x-www-form-urlencoded):
  const response = await fetch('/api/search', {
    method: 'POST',
    headers: { 'Content-Type': 'application/x-www-form-urlencoded' },
    body: new URLSearchParams(new FormData(form)),
  });

9. PREVENTING DOUBLE SUBMISSION
================================================================================

Double submission causes duplicate orders, duplicate users, etc.

Strategy 1: Disable submit button on submit
  form.addEventListener('submit', (e) => {
    const btn = form.querySelector('[type="submit"]');
    btn.disabled = true;
    btn.textContent = 'Submitting...';
    // Re-enable on error:
    // btn.disabled = false;
    // btn.textContent = 'Submit';
  });

Strategy 2: Track submission state with a flag
  let isSubmitting = false;
  
  form.addEventListener('submit', async (e) => {
    e.preventDefault();
    if (isSubmitting) return;  // Ignore repeat clicks
    isSubmitting = true;
    
    try {
      await submitForm(form);
    } finally {
      isSubmitting = false;
    }
  });

Strategy 3: Server-side idempotency key
  // Generate a unique token per form load
  const idempotencyKey = crypto.randomUUID();
  const hiddenInput = form.querySelector('[name="_idempotency_key"]');
  hiddenInput.value = idempotencyKey;
  
  // Server caches response by key and returns same result for duplicate requests

Strategy 4: PRG (Post/Redirect/Get)
  Server returns 303 See Other after successful POST → browser GETs a new page.
  Refreshing the success page only repeats the GET, not the POST.

10. SECURITY: CSRF, XSS, SANITIZATION
================================================================================

CSRF (Cross-Site Request Forgery):
  Attack: Malicious site tricks user's browser into making requests to your app
  using the user's authenticated session.
  
  Prevention — CSRF Token:
  1. Server generates a secret token and stores it in user session
  2. Token included in form as hidden field (or meta tag for AJAX)
  3. Server validates token on every POST/PUT/DELETE
  
  <meta name="csrf-token" content="{{ csrf_token }}">
  <input type="hidden" name="_csrf" value="{{ csrf_token }}">
  
  For AJAX:
  fetch('/api/submit', {
    method: 'POST',
    headers: {
      'X-CSRF-Token': document.querySelector('meta[name="csrf-token"]').content
    },
    body: formData
  });
  
  Also: SameSite cookie attribute prevents CSRF without tokens:
  Set-Cookie: session=xyz; SameSite=Strict; Secure; HttpOnly

XSS (Cross-Site Scripting) via form input:
  Attack: User injects JavaScript through form fields
  
  Prevention:
  1. NEVER insert raw user input into innerHTML:
     ✗ div.innerHTML = userInput;          // Dangerous!
     ✓ div.textContent = userInput;        // Safe — treats as text
     ✓ span.innerText = userInput;         // Safe
  
  2. Sanitize on the server before storing and rendering
  
  3. Use Content Security Policy (CSP):
     <meta http-equiv="Content-Security-Policy" content="default-src 'self'">

Input sanitization (client-side utility):
  function sanitize(str) {
    const temp = document.createElement('div');
    temp.textContent = str;
    return temp.innerHTML;
    // "<script>alert('xss')</script>" becomes
    // "&lt;script&gt;alert('xss')&lt;/script&gt;"
  }

SQL Injection — server-side concern but worth knowing:
  Never concatenate user input into SQL queries.
  Use parameterized queries / prepared statements on the server.

11. IMPORTANT INTERVIEW Q&A
================================================================================

Q1: What is the difference between GET and POST form submission?
A: GET appends form data to the URL as a query string — it's visible in browser
   history/bookmarks/server logs and limited in length. POST sends data in the
   request body — suitable for sensitive data (passwords), large data, and file
   uploads. GET should be used for idempotent operations (search, filter);
   POST for actions that change state (login, register, purchase).

Q2: What does enctype="multipart/form-data" do?
A: It changes the encoding of the POST request body from URL-encoded key=value
   pairs to a multi-part message where each form field is a separate "part"
   with its own headers. This allows binary file data to be sent intact. It's
   required whenever a form includes <input type="file">. If you forget this
   attribute, the file data is corrupted or only the filename is sent.

Q3: How do you prevent a form from submitting with JavaScript?
A: Call event.preventDefault() in the submit event handler:
   form.addEventListener('submit', (e) => { e.preventDefault(); ... });
   This cancels the browser's default navigation behavior, allowing you to
   validate and/or submit via fetch instead. Note: Don't call e.stopPropagation()
   unless you also need to stop bubbling.

Q4: What is FormData and how do you use it?
A: FormData is a built-in API for constructing key/value pairs representing
   form fields. new FormData(formElement) automatically captures all valid named
   fields. You can manually append, set, delete, or iterate entries. It supports
   File objects directly (for file uploads). It can be passed directly as the
   body of a fetch call — the browser automatically sets the correct
   multipart/form-data Content-Type with boundary.

Q5: Why should you never manually set Content-Type when sending FormData with fetch?
A: Because multipart/form-data requires a boundary string in the Content-Type
   header to delimit the parts: Content-Type: multipart/form-data; boundary=----xyz.
   When you set Content-Type manually without the boundary, the server can't
   parse the body and the request fails. When you omit the header, fetch
   generates the boundary automatically and includes it correctly.

Q6: What is the PRG (Post/Redirect/Get) pattern?
A: After a successful POST request, the server responds with 303 See Other
   redirect to a GET URL (e.g., success page). The browser then GETs that page.
   This prevents the browser "confirm resubmission" dialog that appears when
   users refresh a page after a POST — refreshing a GET page is safe and only
   re-fetches the confirmation page, not the POST action. This prevents accidental
   duplicate form submissions.

Q7: What is a CSRF token and why is it needed?
A: Cross-Site Request Forgery is an attack where a malicious website tricks a
   user's browser into making requests to your app using their active session.
   A CSRF token is a random secret generated server-side and included in forms
   (and checked on POST). Since the attacker's site can't read this token from
   your domain (same-origin policy), it can't forge valid requests. It's required
   for all state-changing POST/PUT/DELETE endpoints.

Q8: What data is included in form submission?
A: Only named, enabled form controls are submitted. Unchecked checkboxes and
   unselected radios are NOT submitted — they simply don't appear in the request.
   Only the clicked submit button's name/value is included (not all submit
   buttons). Inputs outside the <form> element are not included unless they
   use the form attribute to reference the form's ID.

Q9: How do you track file upload progress?
A: fetch does not have stable upload progress support yet. Use XMLHttpRequest
   instead: xhr.upload.addEventListener('progress', (e) => { if
   (e.lengthComputable) { percent = (e.loaded / e.total) * 100; } }). For large
   files, implement chunked upload — slice the file into pieces with file.slice()
   and upload each chunk sequentially, updating a progress indicator after each.

Q10: How do you handle server-side validation errors returned as JSON after fetch?
A: Have the server return HTTP 422 with a JSON body containing field errors
   (e.g., { errors: { email: ["already taken"] } }). In the catch block, check
   err.status === 422, then iterate the errors object, find each field by name
   in the form, call setCustomValidity(message) on it, and display the error
   message element. This makes the field appear invalid and blocks re-submission
   until the user corrects it.
