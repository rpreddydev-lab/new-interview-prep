1. CONSTRAINT VALIDATION OVERVIEW
================================================================================

The Constraint Validation API is a browser-native system that:
  - Provides a unified interface to inspect why a field is invalid
  - Allows custom error messages to be set via JavaScript
  - Prevents form submission when any control is invalid
  - Fires events (invalid) on invalid controls during submission attempt
  - Exposes CSS pseudo-classes (:valid, :invalid, :required, etc.)

Applies to these elements:
  HTMLInputElement     — <input>
  HTMLTextAreaElement  — <textarea>
  HTMLSelectElement    — <select>
  HTMLButtonElement    — <button type="submit"> (limited)
  HTMLOutputElement    — <output> (read-only validity)
  HTMLFieldSetElement  — <fieldset> (checkValidity aggregates children)
  HTMLFormElement      — <form> (checkValidity aggregates all)

Does NOT apply to:
  - <div>, <span>, or other non-form elements
  - Inputs with type="hidden" (always valid)
  - Disabled inputs (always considered valid — not checked)
  - Read-only inputs (not validated for most constraints)
  
  Note: Disabled fields pass validation automatically but are not submitted.

2. BUILT-IN CONSTRAINTS RECAP
================================================================================

Attribute constraints (review):
  required     → valueMissing (field is empty + required)
  minlength    → tooShort (string too short)
  maxlength    → tooLong (string too long — also prevents typing)
  min          → rangeUnderflow (number/date below min)
  max          → rangeOverflow (number/date above max)
  step         → stepMismatch (value not a valid step from min)
  pattern      → patternMismatch (value doesn't match regex)
  type=email   → typeMismatch (not a valid email format)
  type=url     → typeMismatch (not a valid URL format)
  type=number  → typeMismatch / badInput (not parseable as number)
  type=date    → typeMismatch / badInput (incomplete or invalid date)

When all constraints pass: validity.valid === true
When any constraint fails: validity.valid === false

3. THE ValidityState OBJECT (DEEP DIVE)
================================================================================

Access: element.validity — returns a ValidityState object (read-only)

Properties (all boolean):

  valueMissing
    When: required attribute is set AND value is empty
    Input types: text → empty string; checkbox → not checked;
                 radio → none in group checked; file → no file selected
    
    if (input.validity.valueMissing) {
      // required field left blank
    }

  typeMismatch
    When: Value doesn't match the expected format of the type attribute
    
    type="email" → input doesn't contain "@" and domain
    type="url"   → input doesn't start with a protocol (http://, https://)
    type="date"  → incomplete date (partial entry)
    
    if (emailInput.validity.typeMismatch) {
      // e.g., user typed "notanemail"
    }

  patternMismatch
    When: pattern attribute present and value doesn't match
    Remember: Pattern is implicitly anchored (^...$)
    
    <input pattern="[A-Z]{3}" value="abc">  → patternMismatch: true
    <input pattern="[A-Z]{3}" value="ABC">  → patternMismatch: false

  tooShort
    When: minlength set and value.length < minlength
    Note: Only triggers when the field has a non-empty value
          (use required + minlength for "must have at least N chars")
    
    <input minlength="8" value="hi">  → tooShort: true

  tooLong
    When: maxlength exceeded — NOTE: maxlength also blocks typing, so this
    state is rare; happens when value is set programmatically
    
    input.value = 'a'.repeat(1000);  // → tooLong if maxlength < 1000

  rangeUnderflow
    When: min attribute set and value < min
    
    <input type="number" min="18" value="10">  → rangeUnderflow: true

  rangeOverflow
    When: max attribute set and value > max
    
    <input type="number" max="100" value="150">  → rangeOverflow: true

  stepMismatch
    When: step set and value is not a valid step interval
    
    <input type="number" min="0" step="5" value="3">  → stepMismatch: true
    (Valid values: 0, 5, 10, 15... — 3 is not valid)

  badInput
    When: Browser can't convert the user's input into the expected value type
    
    type="number" with partial input "12." or "1e" → badInput: true
    type="date" with partial date entry → badInput: true
    
    Tip: Check badInput before rangeUnderflow/rangeOverflow because
    badInput means the value is undefined.

  customError
    When: setCustomValidity() was called with a non-empty string
    
    input.setCustomValidity('Username already taken.');
    input.validity.customError  → true
    
    input.setCustomValidity('');  // Clear → customError: false

  valid
    True ONLY when ALL other validity properties are false.
    The single most important flag to check.
    
    if (input.validity.valid) {
      // All good!
    }

Accessing validationMessage:
  input.validationMessage  — Localized error string (same as native tooltip)
  
  Examples (Chrome, English):
    valueMissing  → "Please fill out this field."
    typeMismatch  → "Please enter an email address."
    patternMismatch → "Please match the requested format."
    rangeUnderflow → "Value must be greater than or equal to 0."
  
  If customError is set: returns the custom message string
  If valid: returns "" (empty string)

4. setCustomValidity() — CUSTOM BUSINESS RULES
================================================================================

setCustomValidity(message) is the primary way to add business logic validation
beyond what HTML attributes support.

When called with non-empty string:
  - Sets validity.customError = true
  - Sets validity.valid = false
  - Sets validationMessage = the provided message
  - Prevents form submission
  - The field reports as invalid in all validity checks

When called with empty string "":
  - Clears the custom error
  - customError = false
  - valid returns to its natural state

CRITICAL RULE: Always call setCustomValidity('') first before re-validating.
If you set a custom error, it STAYS until you explicitly clear it.

  input.addEventListener('input', () => {
    input.setCustomValidity('');  // Clear — then check
  });

Pattern 1: Async availability check (username/email)
  async function validateEmail(email) {
    const response = await fetch(`/api/check-email?email=${encodeURIComponent(email)}`);
    const { available } = await response.json();
    return available;
  }

  const emailInput = document.querySelector('#email');
  
  emailInput.addEventListener('blur', async () => {
    // 1. Clear previous custom error
    emailInput.setCustomValidity('');
    
    // 2. Let built-in constraints handle format errors first
    if (!emailInput.validity.valid) return;
    
    // 3. Check business rule (email uniqueness)
    const available = await validateEmail(emailInput.value);
    
    if (!available) {
      emailInput.setCustomValidity('This email address is already registered.');
    }
    
    // 4. Show validation state
    if (emailInput.validity.customError) {
      showError(emailInput, emailInput.validationMessage);
    }
  });

Pattern 2: Password confirmation
  const password = document.querySelector('#password');
  const confirm = document.querySelector('#confirm-password');
  
  function validatePasswordMatch() {
    confirm.setCustomValidity(
      confirm.value !== password.value
        ? 'Passwords do not match.'
        : ''  // Valid
    );
  }
  
  password.addEventListener('input', validatePasswordMatch);
  confirm.addEventListener('input', validatePasswordMatch);

Pattern 3: Cross-field date validation
  const startDate = document.querySelector('#start-date');
  const endDate = document.querySelector('#end-date');
  
  function validateDateRange() {
    endDate.setCustomValidity('');  // Reset
    
    if (startDate.value && endDate.value) {
      if (new Date(endDate.value) <= new Date(startDate.value)) {
        endDate.setCustomValidity('End date must be after start date.');
      }
    }
  }
  
  startDate.addEventListener('change', validateDateRange);
  endDate.addEventListener('change', validateDateRange);

Pattern 4: File type validation
  fileInput.addEventListener('change', () => {
    fileInput.setCustomValidity('');
    
    const file = fileInput.files[0];
    if (!file) return;
    
    const allowedTypes = ['image/jpeg', 'image/png', 'image/webp'];
    
    if (!allowedTypes.includes(file.type)) {
      fileInput.setCustomValidity(`Only JPG, PNG, or WebP files allowed.`);
    } else if (file.size > 5_000_000) {
      fileInput.setCustomValidity(`File must be under 5MB. Your file: ${(file.size / 1e6).toFixed(1)}MB`);
    }
  });

5. checkValidity() vs reportValidity()
================================================================================

checkValidity()
  - Available on: input, textarea, select, fieldset, form
  - Returns: true (all valid) or false (at least one invalid)
  - Side effects: fires the 'invalid' event on each invalid element
  - Does NOT show any visual error UI
  
  if (form.checkValidity()) {
    submitData();
  } else {
    // 'invalid' events already fired on each invalid field
  }
  
  if (input.checkValidity()) {
    input.classList.add('valid');
  }

reportValidity()
  - Available on: input, textarea, select, form (and in Chrome: fieldset)
  - Returns: true (all valid) or false
  - Side effects: fires 'invalid' events AND shows browser's native error UI
    (focuses first invalid field, shows tooltip)
  - Use when you want the browser's native error bubbles but want to
    trigger it programmatically
  
  // Trigger native validation UI programmatically
  if (!form.reportValidity()) {
    return;  // Browser focuses + shows error bubble for first invalid field
  }

When to use which:
  checkValidity(): Custom validation UI — you handle showing errors yourself
  reportValidity(): Quick validation with native UI, or for testing

Calling on the form vs individual inputs:
  form.checkValidity()     // Checks ALL controls; fires 'invalid' on each invalid one
  input.checkValidity()    // Checks just this one input
  
  // Manual field-by-field check with custom UI:
  [...form.elements].forEach(el => {
    if (el.checkValidity && !el.checkValidity()) {
      showError(el, el.validationMessage);
    }
  });

6. THE 'invalid' EVENT
================================================================================

The 'invalid' event fires on an element when:
  1. checkValidity() is called and the element is invalid
  2. reportValidity() is called and the element is invalid
  3. The user tries to submit a form without novalidate

  input.addEventListener('invalid', (e) => {
    e.preventDefault();  // Prevent browser's native error tooltip
    showCustomError(input);
  });

Important properties:
  e.target           — The invalid form element
  e.target.validity  — ValidityState for error details
  e.target.validationMessage — Localized error message

Aggregate with form:
  form.addEventListener('submit', (e) => {
    e.preventDefault();
    if (!form.checkValidity()) {
      // 'invalid' fires on each invalid element — handled by individual listeners
      form.querySelector(':invalid').focus();
      return;
    }
    submitData();
  });

  // Per-field invalid handling
  document.querySelectorAll('input, select, textarea').forEach(el => {
    el.addEventListener('invalid', (e) => {
      e.preventDefault();
      displayError(e.target);
    });
  });

7. FORM-LEVEL VALIDATION
================================================================================

Complete novalidate form with full custom validation:

  <form id="form" novalidate>
    <div class="field">
      <label for="username">Username *</label>
      <input type="text" id="username" name="username"
             required minlength="3" maxlength="20"
             pattern="[a-z0-9_]+"
             autocomplete="username"
             aria-describedby="username-error"
             title="Lowercase letters, numbers, and underscores, 3–20 characters">
      <span id="username-error" role="alert" class="error"></span>
    </div>
    <button type="submit">Register</button>
  </form>

  const form = document.getElementById('form');
  
  // Error message generator
  function getErrorFor(input) {
    const v = input.validity;
    const label = input.labels?.[0]?.textContent?.replace('*','').trim() || input.name;
    
    if (v.valueMissing)     return `${label} is required.`;
    if (v.tooShort)         return `${label} must be at least ${input.minLength} characters.`;
    if (v.tooLong)          return `${label} must be no more than ${input.maxLength} characters.`;
    if (v.patternMismatch)  return input.title || `${label} has an invalid format.`;
    if (v.typeMismatch) {
      if (input.type === 'email') return 'Please enter a valid email address.';
      if (input.type === 'url')   return 'Please enter a valid URL (e.g., https://example.com).';
      return `${label} is not in the correct format.`;
    }
    if (v.rangeUnderflow)   return `${label} must be at least ${input.min}.`;
    if (v.rangeOverflow)    return `${label} must be at most ${input.max}.`;
    if (v.stepMismatch)     return `${label} must be a multiple of ${input.step}.`;
    if (v.customError)      return input.validationMessage;
    if (v.badInput)         return `${label} contains an invalid value.`;
    return 'Invalid value.';
  }
  
  function showFieldError(input) {
    const errorId = input.getAttribute('aria-describedby');
    const errorEl = errorId && document.getElementById(errorId);
    
    const msg = getErrorFor(input);
    if (errorEl) errorEl.textContent = msg;
    input.setAttribute('aria-invalid', 'true');
    input.classList.add('error');
  }
  
  function clearFieldError(input) {
    const errorId = input.getAttribute('aria-describedby');
    const errorEl = errorId && document.getElementById(errorId);
    
    if (errorEl) errorEl.textContent = '';
    input.removeAttribute('aria-invalid');
    input.classList.remove('error');
    input.setCustomValidity('');
  }
  
  // Validate on blur
  form.querySelectorAll('input, select, textarea').forEach(el => {
    el.addEventListener('blur', () => {
      el.setCustomValidity('');  // Reset custom errors
      if (!el.checkValidity()) {
        showFieldError(el);
      } else {
        clearFieldError(el);
      }
    });
    
    el.addEventListener('input', () => {
      if (el.hasAttribute('aria-invalid')) {
        el.setCustomValidity('');
        if (el.checkValidity()) clearFieldError(el);
        else showFieldError(el);
      }
    });
  });
  
  // Submit handler
  form.addEventListener('submit', async (e) => {
    e.preventDefault();
    
    let firstInvalid = null;
    
    form.querySelectorAll('input, select, textarea').forEach(el => {
      el.setCustomValidity('');
      if (!el.checkValidity()) {
        showFieldError(el);
        if (!firstInvalid) firstInvalid = el;
      } else {
        clearFieldError(el);
      }
    });
    
    if (firstInvalid) {
      firstInvalid.focus();
      return;
    }
    
    // All valid — submit
    await submitData(new FormData(form));
  });

8. CUSTOM VALIDATION PATTERNS
================================================================================

Dependent field validation (field B required when field A = "other"):
  const contactMethod = document.querySelector('[name="contact"]');
  const otherContact = document.querySelector('[name="other-contact"]');
  
  function updateOtherContactRequirement() {
    if (contactMethod.value === 'other') {
      otherContact.required = true;
    } else {
      otherContact.required = false;
      otherContact.setCustomValidity('');
    }
  }
  
  contactMethod.addEventListener('change', updateOtherContactRequirement);
  updateOtherContactRequirement();  // Run on page load

Minimum age from birth date:
  const birthDate = document.querySelector('#birth-date');
  
  birthDate.addEventListener('change', () => {
    birthDate.setCustomValidity('');
    
    if (!birthDate.value) return;
    
    const today = new Date();
    const dob = new Date(birthDate.value);
    const age = today.getFullYear() - dob.getFullYear() -
      (today < new Date(today.getFullYear(), dob.getMonth(), dob.getDate()) ? 1 : 0);
    
    if (age < 18) {
      birthDate.setCustomValidity('You must be at least 18 years old.');
    }
  });

Credit card number (Luhn algorithm check):
  function luhnCheck(cardNumber) {
    const digits = cardNumber.replace(/\D/g, '').split('').reverse().map(Number);
    const sum = digits.reduce((acc, digit, i) => {
      if (i % 2 !== 0) {
        digit *= 2;
        if (digit > 9) digit -= 9;
      }
      return acc + digit;
    }, 0);
    return sum % 10 === 0;
  }
  
  cardInput.addEventListener('blur', () => {
    cardInput.setCustomValidity('');
    if (cardInput.value && !luhnCheck(cardInput.value)) {
      cardInput.setCustomValidity('Please enter a valid credit card number.');
    }
  });

9. ElementInternals FOR CUSTOM FORM CONTROLS
================================================================================

For custom elements that need to participate in form validation:

  class StarRating extends HTMLElement {
    static formAssociated = true;  // Mark as form-associated
    
    constructor() {
      super();
      this._internals = this.attachInternals();  // Get ElementInternals
      this.attachShadow({ mode: 'open' });
      this._value = '';
    }
    
    connectedCallback() {
      this.shadowRoot.innerHTML = `
        <style>:host { display: inline-flex; }</style>
        ${[1,2,3,4,5].map(n => `
          <button type="button" data-value="${n}" part="star">★</button>
        `).join('')}
      `;
      this.shadowRoot.querySelectorAll('button').forEach(btn => {
        btn.addEventListener('click', () => this.value = btn.dataset.value);
      });
      
      this._updateValidity();
    }
    
    get value() { return this._value; }
    set value(v) {
      this._value = v;
      this._internals.setFormValue(v);  // Submit with form
      this._updateValidity();
    }
    
    _updateValidity() {
      if (this.hasAttribute('required') && !this._value) {
        this._internals.setValidity(
          { valueMissing: true },  // ValidityStateFlags
          'Please select a rating.',  // Custom message
          this.shadowRoot.querySelector('button')  // Anchor element for tooltip
        );
      } else {
        this._internals.setValidity({});  // Clear — valid
      }
    }
    
    static get observedAttributes() { return ['required']; }
    attributeChangedCallback() { this._updateValidity(); }
    
    // Form lifecycle callbacks
    formResetCallback() {
      this.value = '';
    }
    formStateRestoreCallback(state) {
      this.value = state;
    }
  }
  
  customElements.define('star-rating', StarRating);

ElementInternals API:
  internals.setFormValue(value)       — Set submitted value
  internals.setValidity(flags, msg, anchor) — Set validity state
  internals.reportValidity()          — Show validation UI
  internals.checkValidity()           — Check validity
  internals.validity                  — ValidityState
  internals.validationMessage         — Error message

10. VALIDATION UX BEST PRACTICES
================================================================================

1. Don't show errors on page load — wait for interaction
2. Validate on blur, re-validate on input (live feedback after first touch)
3. Validate on submit for fields not yet touched
4. Focus the first invalid field after submit
5. Error messages should be:
   - Specific: "Email must include @" not "Invalid email"
   - Actionable: "Enter at least 8 characters" not "Too short"
   - Associated: aria-describedby linking input to error
6. Don't use color alone — include text + icon
7. For async validation (username check), debounce 300-500ms
8. Clear custom validity before re-checking
9. Use role="alert" on dynamically injected error messages
10. Inline errors (near the field) > modal or summary for individual fields
    Summary at top > inline for submit attempt with many errors

11. IMPORTANT INTERVIEW Q&A
================================================================================

Q1: What is the Constraint Validation API?
A: It's a browser-native API on form elements that exposes validation state
   and allows programmatic validation control. Key members: validity
   (ValidityState object with boolean flags), validationMessage (localized
   error string), checkValidity() (validate + fire invalid event),
   reportValidity() (validate + show browser UI), and setCustomValidity()
   (set a custom error message). It enables you to build custom validation
   UI while leveraging the browser's built-in constraint system.

Q2: What is the ValidityState object and what are its properties?
A: It's the object returned by input.validity, containing boolean flags:
   valueMissing (required + empty), typeMismatch (type constraint failed),
   patternMismatch (pattern failed), tooShort/tooLong (minlength/maxlength),
   rangeUnderflow/rangeOverflow (min/max), stepMismatch (step), badInput
   (browser can't parse), customError (setCustomValidity called with non-empty),
   and valid (all others are false). Use these to provide specific, tailored
   error messages rather than generic "invalid".

Q3: How does setCustomValidity() work?
A: setCustomValidity(message) sets a custom error on a form element.
   Non-empty message → validity.customError = true, validity.valid = false,
   validationMessage = message, blocks form submission.
   Empty string → clears the custom error. CRITICAL: custom errors persist
   until explicitly cleared. Always call setCustomValidity('') before
   re-validating to avoid stale errors.

Q4: What is the difference between checkValidity() and reportValidity()?
A: checkValidity() returns true/false and fires 'invalid' events on invalid
   elements — but shows NO visual error UI. It's used for silent programmatic
   validation where you control the error display. reportValidity() does
   everything checkValidity does PLUS shows the browser's native error tooltip
   and focuses the first invalid field. Use checkValidity for custom UI;
   reportValidity when you want native browser error bubbles.

Q5: When does the 'invalid' event fire and how do you use it?
A: It fires on each invalid form element when: (1) checkValidity() finds it
   invalid, (2) reportValidity() finds it invalid, (3) user tries to submit
   a form without novalidate. Call e.preventDefault() to suppress the browser's
   native tooltip. Use it to trigger custom error display logic per field,
   especially when combined with novalidate on the form.

Q6: How do you implement cross-field validation (e.g., password confirmation)?
A: There's no built-in HTML attribute for this. Use setCustomValidity in
   JavaScript: listen for 'input' on both fields, compare values, call
   confirmInput.setCustomValidity('') when matching and set an error message
   when not. Because the form won't submit while customError is set, this
   effectively blocks submission until the fields match.

Q7: How do you validate fields only after user interaction, not on page load?
A: Three common patterns: (1) Add a .touched class on blur, only show errors
   for .touched elements. (2) Use CSS :not(:placeholder-shown) — only targets
   fields that have been interacted with and have no placeholder showing.
   (3) Add a .was-validated class to the form on first submit attempt — then
   style .was-validated :invalid. CSS-only techniques are simpler; class-based
   gives more control for complex multi-step forms.

Q8: What is ElementInternals and how does it relate to form validation?
A: ElementInternals is an API accessed via this.attachInternals() in a custom
   element constructor (requires static formAssociated = true on the class).
   It allows custom elements to participate in HTML forms: setFormValue()
   sets the submitted value, setValidity(flags, message, anchor) sets validity
   state, checkValidity() and reportValidity() work the same as on native inputs.
   This enables form controls like custom date pickers, star ratings, and rich
   text editors to integrate seamlessly with form validation and submission.

Q9: How do you handle the case where a form field should only be required
    based on another field's value?
A: Use JavaScript to dynamically set the required attribute. Listen for
   'change' on the controlling field, then set field.required = true/false
   based on its value. Also call field.setCustomValidity('') when making
   the field not required to clear any existing custom errors. Run this
   logic on page load too (e.g., for pre-filled forms).

Q10: What is the difference between aria-invalid and the CSS :invalid pseudo-class?
A: :invalid is set automatically by the browser based on constraint validation —
   it's purely CSS and doesn't affect screen readers. aria-invalid="true" is an
   ARIA attribute that announces to screen readers that a field is in an error
   state when it receives focus. Both should be used together for full
   accessibility: :invalid for CSS styling, aria-invalid for screen readers.
   Important: aria-invalid should only be set AFTER the user has interacted
   (to avoid announcing errors before the user types anything).
