1. WHAT IS SEO AND WHY HTML MATTERS
================================================================================

SEO (Search Engine Optimization) is the practice of optimizing web content so
that search engines like Google can discover, understand, index, and rank it
appropriately for relevant queries.

HTML is the FOUNDATION of SEO because:
  - HTML is what search engine crawlers read
  - HTML structure signals importance and hierarchy of content
  - Semantic HTML helps engines understand the PURPOSE of content
  - HTML controls indexability, canonicalization, and metadata

Key HTML factors that directly impact SEO:
  1. <title> — most important on-page SEO signal
  2. <meta name="description"> — controls SERP snippet
  3. Heading tags (h1–h6) — signal content hierarchy
  4. Semantic elements — help engines understand structure
  5. Alt text on images — allows images to appear in image search
  6. Internal links — distribute PageRank; help crawlers discover pages
  7. Page speed (HTML structure affects CRP) — Core Web Vitals
  8. Mobile-friendliness (viewport meta) — Google mobile-first indexing
  9. Structured data (JSON-LD) — rich results
  10. rel="canonical" — consolidate duplicate content signals

2. HOW SEARCH ENGINES WORK
================================================================================

3 Core Processes:

1. CRAWLING
   - Crawlers (Googlebot, Bingbot) discover URLs via:
     a) Links from known pages (following <a href>)
     b) Sitemaps submitted in Google Search Console
     c) Direct URL submission
   - Crawlers fetch HTML (and execute JS via Chrome headless for Google)
   - Rate-limited by crawl budget
   - robots.txt and noindex/nofollow control crawling

2. INDEXING
   - Fetched content is parsed, analyzed, and added to the index
   - Google now uses "mobile-first indexing" — uses mobile version of page
   - JavaScript-rendered content can be indexed but may be delayed
   - Content behind login, CAPTCHA, or blocked by robots.txt is NOT indexed

3. RANKING
   - Algorithm determines which pages to show for which queries
   - 200+ ranking factors including: relevance, authority, E-E-A-T, UX
   - E-E-A-T: Experience, Expertise, Authoritativeness, Trustworthiness
   - HTML signals that influence ranking:
     → Keyword presence in title, h1, meta description, body
     → Site structure (internal links, breadcrumbs)
     → Page speed (Core Web Vitals)
     → Mobile-friendliness
     → Structured data for rich results

3. TITLE TAG OPTIMIZATION
================================================================================

<title>Primary Keyword — Secondary Keyword | Brand Name</title>

Rules:
  - 50-60 characters (Google truncates ~580px rendered width)
  - Include primary keyword NEAR THE BEGINNING
  - Every page must have a unique title
  - Don't keyword-stuff; write for humans
  - Brand name at end (not beginning, unless it's the primary brand query)

Patterns:
  Blog post:   How to Learn HTML5 in 30 Days — Web Dev Blog
  Product:     Nike Air Max 270 | Running Shoes | Nike
  Category:    Web Development Books — O'Reilly Media
  Homepage:    GitHub: Let's Build from Here · GitHub
  Local:       Best Pizza in New York City — Joe's Pizzeria

Bad examples:
  <title>Home</title>                     ← Not descriptive
  <title>HTML HTML5 HTML tutorial learn</title>  ← Keyword stuffed
  <title>My Website</title>               ← No keyword value

Google may rewrite your title if it's:
  - Too long or too short
  - Stuffed with keywords
  - Doesn't match page content well
  - Boilerplate across multiple pages

================================================================================
4. META DESCRIPTION
================================================================================

<meta name="description" content="Learn HTML5 from scratch with this comprehensive
guide. Covers semantic elements, forms, accessibility, and SEO best practices.">

Rules:
  - 150-160 characters (Google truncates ~920px)
  - NOT a direct ranking signal (but affects CTR, which influences ranking)
  - Unique per page
  - Include call to action (Learn, Discover, Get, Download, etc.)
  - Naturally include primary keyword (Google bolds matched keywords in SERP)
  - Summarize the page accurately (reduces bounce rate from mismatched expectations)

Google may IGNORE your description and generate its own snippet if:
  - Your description doesn't match the user's query well
  - The page has better matching content elsewhere
  - The description is too short or keyword-stuffed

When description is missing:
  Google extracts text from the page (often first paragraph or h1 text).
  This is unpredictable — always write a meta description.

5. HEADING HIERARCHY (h1–h6)
================================================================================

<h1>Primary Page Topic</h1>
  <h2>Major Section</h2>
    <h3>Subsection</h3>
      <h4>Sub-subsection</h4>

Rules:
  1. ONE <h1> per page (or per <article> in HTML5, but practically one per page)
  2. NEVER skip heading levels (h1 → h3 is invalid; must go h1 → h2 → h3)
  3. <h1> should contain the primary keyword
  4. Headings should describe the content below them
  5. Don't use headings for visual styling (use CSS instead)
  6. Don't use headings for every paragraph (overusing dilutes signals)

SEO implications:
  - Search engines use headings to understand page structure and topics
  - <h1> gets the most weight; weight decreases through h6
  - Keywords in headings carry more weight than body text
  - Headings are used for featured snippet extraction
  - Screen readers use headings for page navigation (accessibility)

Bad heading usage:
  <h3>About Us</h3>  ← No h1 or h2 before it
  <h2 style="font-size:14px">Small text header</h2>  ← Styling abuse
  <p><b>Introduction</b></p>  ← Bold paragraph pretending to be heading

6. SEMANTIC HTML & SEO
================================================================================

Semantic elements help Google understand the PURPOSE of content:

  <header>   — page/section header; logo and navigation
  <nav>      — navigation; Google uses for site links
  <main>     — primary content; helps Google identify the core content
  <article>  — standalone content; candidate for featured snippets
  <section>  — thematic grouping; with heading helps topic clustering
  <aside>    — supplementary content (not main topic)
  <footer>   — footer content; often contains legal/contact info
  <time datetime="2026-04-08">April 8, 2026</time>
              — machine-readable dates; used in rich results

BREADCRUMBS (important for SEO):
  <nav aria-label="Breadcrumb">
    <ol itemscope itemtype="https://schema.org/BreadcrumbList">
      <li itemprop="itemListElement" itemscope
          itemtype="https://schema.org/ListItem">
        <a itemprop="item" href="/"><span itemprop="name">Home</span></a>
        <meta itemprop="position" content="1">
      </li>
      <li itemprop="itemListElement" itemscope
          itemtype="https://schema.org/ListItem">
        <a itemprop="item" href="/blog"><span itemprop="name">Blog</span></a>
        <meta itemprop="position" content="2">
      </li>
    </ol>
  </nav>
  Google shows breadcrumbs in SERP instead of raw URL.

Address and Contact:
  <address>
    <a href="mailto:contact@example.com">contact@example.com</a>
    <a href="tel:+14155552671">+1 (415) 555-2671</a>
  </address>

7. URL STRUCTURE & CANONICAL
================================================================================

SEO-Friendly URL characteristics:
  ✓ Short and descriptive
  ✓ Lowercase
  ✓ Hyphens (-) to separate words (NOT underscores _)
  ✓ Keywords in URL
  ✓ Logical hierarchy matching site structure

  Good:   /blog/html5-semantic-elements
  Bad:    /p?id=123&cat=5&page=html
  Bad:    /blog/HTML5_Semantic_Elements_Complete_Guide_2024

Canonical URL:
  <link rel="canonical" href="https://example.com/blog/html5-semantic-elements">

Use canonical when the same content is accessible at multiple URLs:
  - www.example.com vs example.com
  - https vs http
  - Trailing slash: /page vs /page/
  - Query parameters: /page?utm_source=email
  - Pagination: /articles?page=2
  - Syndicated content on multiple domains

rel="nofollow" on links:
  <a href="/sponsored-link" rel="nofollow">Sponsored</a>
  <a href="/sponsored-link" rel="sponsored">Sponsored</a>  ← more specific
  <a href="/user-comment-link" rel="ugc">User link</a>
  Tells Google not to pass PageRank through this link.

8. IMAGE OPTIMIZATION FOR SEO
================================================================================

<img src="html5-semantic-elements-diagram.jpg"
     alt="Diagram showing HTML5 semantic elements: header, nav, main, article, aside, footer"
     width="800"
     height="450"
     loading="lazy">

alt attribute (MOST IMPORTANT for SEO):
  - Describes the image content for search engines and screen readers
  - Google Image Search ranking depends heavily on alt text
  - Be descriptive but concise (125 chars max)
  - Don't start with "Image of" or "Picture of"
  - Decorative images: alt="" (empty, not missing)
  - Product images: include model name, color, key features

width and height attributes:
  - ALWAYS specify — prevents Cumulative Layout Shift (CLS), a Core Web Vital
  - Use actual image dimensions or CSS will be applied proportionally

loading="lazy":
  - Defers loading of off-screen images (below the fold)
  - Improves initial page load time and LCP
  - Do NOT use on above-the-fold images (delays LCP)
  - Use loading="eager" for above-the-fold images (default behavior)

fetchpriority="high":
  - Tells browser to prioritize this image's download
  - Use on LCP (Largest Contentful Paint) element:
    <img src="hero.jpg" alt="Hero" fetchpriority="high">

Image file naming:
  html5-semantic-elements.jpg  ← descriptive, hyphenated
  img001.jpg                   ← NOT descriptive

<figure> and <figcaption>:
  <figure>
    <img src="chart.png" alt="Bar chart showing 40% growth in 2026">
    <figcaption>Fig 1: Revenue growth 2024–2026</figcaption>
  </figure>
  figcaption text is crawlable and adds keyword context around the image.

Modern image formats:
  WebP    — 25-35% smaller than JPG/PNG; supported by all modern browsers
  AVIF    — 50% smaller than JPG; newer, less browser support
  SVG     — Best for logos, icons, illustrations
  Use <picture> for format negotiation:
  <picture>
    <source srcset="image.avif" type="image/avif">
    <source srcset="image.webp" type="image/webp">
    <img src="image.jpg" alt="Description" width="800" height="600">
  </picture>

9. STRUCTURED DATA (SCHEMA.ORG / JSON-LD)
================================================================================

Structured data tells search engines EXACTLY what your content is, enabling
"rich results" (enhanced SERP appearances with ratings, images, FAQs, etc.)

Three formats: JSON-LD (recommended), Microdata, RDFa

JSON-LD in <head>:
  <script type="application/ld+json">
  {
    "@context": "https://schema.org",
    "@type": "Article",
    "headline": "Complete Guide to HTML5 Semantic Elements",
    "description": "Learn all HTML5 semantic elements...",
    "author": {
      "@type": "Person",
      "name": "Jane Developer",
      "url": "https://example.com/about/jane"
    },
    "publisher": {
      "@type": "Organization",
      "name": "Web Dev Blog",
      "logo": {
        "@type": "ImageObject",
        "url": "https://example.com/logo.png"
      }
    },
    "datePublished": "2026-04-08",
    "dateModified": "2026-04-08",
    "image": "https://example.com/articles/html5-guide.jpg",
    "mainEntityOfPage": {
      "@type": "WebPage",
      "@id": "https://example.com/html5-semantic-elements"
    }
  }
  </script>

Common Schema types and their rich results:
  Article / BlogPosting       → Publication date, author in SERP
  FAQPage                     → Expandable Q&A below result
  HowTo                       → Step-by-step instructions
  Product                     → Price, availability, reviews
  Review / AggregateRating    → Star ratings
  LocalBusiness               → Map pack, business info
  Event                       → Date, location
  Recipe                      → Cook time, calories, ratings
  VideoObject                 → Video thumbnail in search
  BreadcrumbList              → Breadcrumb path in SERP
  SiteLinksSearchBox          → Search box in SERP
  Person / Organization       → Knowledge Panel

Test structured data:
  → https://search.google.com/test/rich-results
  → https://validator.schema.org/

10. INTERNAL LINKING
================================================================================

Internal links:
  - Help crawlers discover all pages on your site
  - Distribute PageRank (link equity) through the site
  - Tell search engines which pages are most important (hub pages get more links)
  - Help users navigate
  - Contextual anchor text carries keyword signals

Best practices:
  <a href="/blog/html5-forms">Learn about HTML5 Form Validation</a>
  ← Descriptive anchor text (not "click here" or "read more")

  Crawl depth: Important pages should be reachable within 3 clicks from homepage
  Broken links (404): Detected by Google; hurt crawl efficiency; fix promptly
  Internal nofollow: Use sparingly; pages with nofollow on all incoming links
                     may be discovered but get no PageRank

rel values on links:
  rel="nofollow"  — don't pass PageRank
  rel="sponsored" — paid/affiliate links
  rel="ugc"       — user-generated content (comments, forum posts)
  rel="noopener noreferrer" — security for target="_blank" links

Target blank security:
  <a href="https://external.com" target="_blank" rel="noopener noreferrer">
  Without rel="noopener", the opened page can access window.opener and redirect
  the original page (tab-napping attack). noopener prevents this.

11. CORE WEB VITALS & PAGE EXPERIENCE
================================================================================

Google's Page Experience ranking factors:

1. LCP — Largest Contentful Paint (loading performance)
   - Target: ≤ 2.5 seconds
   - Measures: time until largest visible element renders
   - Common LCP elements: hero image, large text block, video thumbnail
   - HTML optimizations:
     → <img fetchpriority="high"> on LCP image
     → <link rel="preload"> for LCP image
     → Don't use lazy loading on LCP image
     → Inline critical CSS

2. INP — Interaction to Next Paint (interactivity — replaced FID in 2024)
   - Target: ≤ 200ms
   - Measures: latency from user interaction to visual response
   - HTML optimizations:
     → Use <button> for interactive elements (not <div onclick>)
     → Proper event handling patterns
     → Avoid long tasks blocking main thread

3. CLS — Cumulative Layout Shift (visual stability)
   - Target: ≤ 0.1
   - Measures: unexpected layout shifts during page life
   - HTML optimizations:
     → Always specify width and height on <img> and <video>
     → Reserve space for ads/dynamic content with CSS aspect-ratio
     → Don't insert content above existing content dynamically
     → Use font-display: optional or font-display: swap for web fonts

4. FCP — First Contentful Paint (perceived load)
   - Target: ≤ 1.8 seconds
   - HTML optimizations:
     → Minimize render-blocking CSS/JS
     → Inline critical CSS
     → Put <link rel="stylesheet"> in head (not body)

12. MOBILE-FRIENDLINESS
================================================================================

Google uses MOBILE-FIRST INDEXING (since 2023, for all sites):
  - Google primarily uses the MOBILE version for indexing and ranking
  - If your mobile page has less content than desktop, rankings may suffer

Mobile-first checklist:
  ✓ <meta name="viewport" content="width=device-width, initial-scale=1.0">
  ✓ Don't disable zooming (user-scalable=no)
  ✓ Font size ≥ 16px (prevent iOS auto-zoom on form focus)
  ✓ Touch targets ≥ 48×48px (Google recommendation; WCAG requires 44×44px)
  ✓ No horizontal scrolling
  ✓ Responsive images (<picture>, srcset, sizes)
  ✓ No intrusive interstitials/popups (Google penalizes these on mobile)
  ✓ Mobile-friendly navigation (hamburger menus, accordions)

Test mobile-friendliness:
  → Google Search Console > Mobile Usability report
  → Chrome DevTools Device Mode
  → Google's Mobile-Friendly Test

13. INDEXABILITY CONTROLS
================================================================================

robots meta tag (per-page crawl/index control):
  <meta name="robots" content="noindex, nofollow">
  
  noindex    — Don't add this page to search index
  nofollow   — Don't follow links on this page
  noarchive  — Don't show cached version
  nosnippet  — Don't show text snippet in SERP
  noimageindex — Don't index images on this page

Specific crawler control:
  <meta name="googlebot"  content="noindex, nofollow">
  <meta name="bingbot"    content="noindex">
  <meta name="slurp"      content="noindex">  ← Yahoo

X-Robots-Tag HTTP header (alternative to meta, can apply to any file type):
  X-Robots-Tag: noindex, nofollow

When to use noindex:
  - Thank you / confirmation pages
  - Admin pages
  - Duplicate content (prefer canonical instead)
  - Search results pages (site:internal search)
  - Staging/test sites (use password protection instead)
  - Pages with thin/no content
  - Tag/category pages with little unique content

noindex vs robots.txt:
  robots.txt   — blocks CRAWLING (crawler never visits)
                 BUT: page can still be indexed if it has backlinks
  noindex      — blocks INDEXING (crawler can visit but won't index)
                 Cannot use noindex if robots.txt blocks crawling

14. SITEMAP & ROBOTS.TXT
================================================================================

XML Sitemap:
  Referenced in <head>? No — but submit via Google Search Console.
  Can reference in robots.txt: Sitemap: https://example.com/sitemap.xml

  <urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
    <url>
      <loc>https://example.com/</loc>
      <lastmod>2026-04-08</lastmod>
      <changefreq>weekly</changefreq>
      <priority>1.0</priority>
    </url>
  </urlset>

  Sitemap limits: max 50,000 URLs or 50MB (use sitemap index for larger sites)
  Image sitemap extension: helps Google discover images

robots.txt (at domain root: /robots.txt):
  User-agent: *            ← Apply to all crawlers
  Disallow: /admin/        ← Block all crawlers from /admin/
  Disallow: /private/
  Allow: /admin/public/    ← Allow specific sub-path

  User-agent: Googlebot
  Disallow: /no-google/   ← Only block Googlebot

  User-agent: *
  Sitemap: https://example.com/sitemap.xml  ← Tell crawlers where sitemap is

15. ACCESSIBILITY AND SEO OVERLAP
================================================================================

SEO and Accessibility are closely aligned — both require meaningful, semantic HTML:

  Feature              Accessibility Benefit        SEO Benefit
  -------              --------------------         ----------------------
  alt text on images   Screen readers announce      Image search indexing
  Heading hierarchy    Screen reader navigation     Content structure signal
  Semantic HTML        Proper landmarks for nav     Structured content parsing
  Link anchor text     Screen readers read links    Keyword signal for linked page
  lang attribute       TTS pronunciation            Language/regional targeting
  ARIA labels          Non-visual element labels    Minimal direct SEO impact
  Keyboard navigation  Keyboard users               Better UX → lower bounce rate
  Page title           Browser tab, screen reader   Primary ranking signal
  Skip links           Keyboard/screen reader UX    Internal link structure
  Form labels          Screen reader form filling   Longer session engagement

16. IMPORTANT INTERVIEW Q&A
================================================================================

Q1: What are the most important HTML elements for SEO?
A: In order of importance:
   1. <title> — primary on-page ranking signal
   2. <h1> — main topic signal
   3. <meta name="description"> — controls click-through rate
   4. <img alt="..."> — image search and contextual signal
   5. <a href="...">anchor text</a> — link equity and keyword signal
   6. Semantic structure (<article>, <section>, <nav>, <main>)
   7. Structured data (<script type="application/ld+json">)

Q2: Why doesn't Google use the meta keywords tag?
A: Google officially stopped using meta keywords in 2009 because it was
   heavily abused for keyword stuffing. Google's algorithm now determines
   relevance from page content, backlinks, user behavior, and E-E-A-T
   signals. Bing also ignores it. Keep it out of your pages.

Q3: What is the difference between noindex and robots.txt disallow?
A: robots.txt disallow prevents crawling (Googlebot never visits the page),
   but Google can still INDEX the page if it has backlinks (it just won't
   read the content). noindex allows crawling but prevents indexing.
   To prevent both crawling AND indexing: disallow in robots.txt, but
   understand Google won't even read the noindex tag if it's blocked.
   For sensitive pages you don't want indexed: use noindex + robots allow.

Q4: What is a canonical URL and when do you use it?
A: A canonical URL (<link rel="canonical">) specifies the "master" URL for
   duplicate or near-duplicate content. Use it when:
   - Same content accessible at multiple URLs (www/non-www, http/https)
   - URL parameters create duplicates (?sort=price, ?utm_source=email)
   - Paginated content
   - Syndicating content on multiple sites (point to original)
   It consolidates ranking signals to the canonical URL.

Q5: What are Core Web Vitals and how does HTML affect them?
A: Core Web Vitals are Google's UX metrics: LCP (loading), INP (interactivity),
   CLS (visual stability). HTML affects all three:
   LCP: Use fetchpriority="high" on hero images, preload, avoid lazy loading LCP
   INP: Use semantic interactive elements (<button>), avoid heavy event handlers
   CLS: Always set width/height on images and videos, reserve space for dynamic content

Q6: What is mobile-first indexing?
A: Google crawls and indexes the MOBILE version of a page as the primary
   version for determining rankings (since 2023). If mobile has less content
   than desktop, rankings can drop. Key: viewport meta tag, responsive design,
   equal content on both versions.

Q7: What is structured data and how does it improve SEO?
A: Structured data (Schema.org markup via JSON-LD) provides explicit,
   machine-readable descriptions of page content. It doesn't directly boost
   rankings but enables "rich results" (star ratings, FAQ dropdowns, breadcrumbs,
   video thumbnails in SERP) that dramatically improve CTR (click-through rate).

Q8: How does page speed affect SEO?
A: Google uses Core Web Vitals (LCP, INP, CLS) as ranking signals. Poor page
   speed also increases bounce rate, which correlates negatively with rankings.
   Key speed improvements in HTML: preload critical resources, defer non-critical
   scripts, specify image dimensions, lazy-load below-fold images, inline critical CSS.

Q9: What is an hreflang attribute and when is it used?
A: hreflang tells Google which language/region variant of a page to show to
   which users. Used for international sites with content in multiple languages
   or for different regions (en-US vs en-GB). Must be reciprocal (every page
   in the set must reference all others). Set via <link rel="alternate"
   hreflang="fr" href="https://example.com/fr/">.

Q10: How do you optimize images for SEO?
A: Five key factors:
   1. Descriptive filename: html5-semantic-elements.jpg
   2. Meaningful alt text: "Diagram of HTML5 semantic layout"
   3. Always specify width and height (prevents CLS)
   4. Use modern formats: WebP/AVIF (faster load = better LCP)
   5. Lazy-load below-fold images; preload or fetchpriority="high" for LCP image
