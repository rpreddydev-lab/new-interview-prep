1. WHAT IS HTML?
================================================================================

HTML (HyperText Markup Language) is the standard markup language used to create
web pages. It describes the STRUCTURE and CONTENT of a page using a system of
elements represented by TAGS.

Key points:
- HTML is NOT a programming language — it is a MARKUP language
- HTML elements tell the browser how to display content
- HTML is interpreted, not compiled
- HTML is case-insensitive (but lowercase is best practice)

Basic HTML element anatomy:
  <tagname attribute="value"> Content </tagname>
  └── opening tag ──┘              └── closing tag ──┘

Void (self-closing) elements have no content or closing tag:
  <br>, <img>, <input>, <hr>, <meta>, <link>

2. HISTORY & EVOLUTION
================================================================================

Year    Version   Key Highlights
------  --------  -------------------------------------------------------
1991    HTML 1.0  Tim Berners-Lee's original spec; ~18 elements; no images
1995    HTML 2.0  First formal spec via IETF; forms introduced
1997    HTML 3.2  Tables, scripting, applets added
1997    HTML 4.0  CSS separation, frames, internationalization
1999    HTML 4.01 Bug fixes; three doctypes (Strict/Transitional/Frameset)
2000    XHTML 1.0 XML-strict version of HTML; required closing tags
2014    HTML5     Living standard; semantic elements, APIs, multimedia

HTML5 is not a version bump — it's a "living standard" maintained by WHATWG
(Web Hypertext Application Technology Working Group). W3C and WHATWG now
collaborate on a single HTML spec (since 2019).

3. HOW BROWSERS PARSE HTML
================================================================================

Step 1: BYTES → CHARACTERS
   Browser receives raw bytes; converts to characters using declared charset
   (usually UTF-8 from <meta charset="UTF-8">)

Step 2: CHARACTERS → TOKENS
   Tokenizer converts character stream into tokens:
   - StartTag token  (<div class="foo">)
   - EndTag token    (</div>)
   - Character token (text content)
   - Comment token   (<!-- ... -->)
   - DOCTYPE token   (<!DOCTYPE html>)

Step 3: TOKENS → NODES
   Each token becomes a Node object

Step 4: NODES → DOM TREE
   Nodes are linked into a tree based on parent-child relationships

IMPORTANT: HTML parsing is INCREMENTAL and FORGIVING
   - Browser doesn't wait for full file to start parsing
   - Invalid HTML is corrected (missing closing tags, wrong nesting)
   - Parser pauses when it encounters <script> (unless async/defer)

4. THE DOM (DOCUMENT OBJECT MODEL)
================================================================================

The DOM is a programming interface for HTML documents. It represents the page
as a tree of objects that can be manipulated with JavaScript.

DOM Tree Structure:
  Document
  └── html
      ├── head
      │   ├── title
      │   └── meta
      └── body
          ├── header
          ├── main
          └── footer

Key DOM Concepts:
- Node: every item in the tree (elements, text, comments) is a Node
- Element: a Node that is an HTML element (<div>, <p>, etc.)
- TextNode: the actual text content inside an element
- Attribute: key-value pairs on elements (class, id, href, etc.)

Node Types (nodeType property):
  1  = ELEMENT_NODE
  3  = TEXT_NODE
  8  = COMMENT_NODE
  9  = DOCUMENT_NODE
  10 = DOCUMENT_TYPE_NODE
  11 = DOCUMENT_FRAGMENT_NODE

DOM vs HTML:
- HTML is the raw text source
- DOM is the in-memory representation after parsing
- JavaScript operates on the DOM, not the raw HTML
- DOM can differ from HTML (browser auto-corrections, JS mutations)

5. CRITICAL RENDERING PATH
================================================================================

1. HTML → DOM construction (parser builds tree incrementally)
2. CSS → CSSOM construction (render-blocking; must complete before paint)
3. DOM + CSSOM → Render Tree (only visible nodes; excludes display:none)
4. Layout (Reflow) → calculate geometry of each node
5. Paint → fill in pixels layer by layer
6. Composite → layers combined onto screen

Blocking Resources:
- CSS is RENDER-BLOCKING (browser stops rendering until CSS is parsed)
- JS with no async/defer is PARSER-BLOCKING (stops HTML parsing)

Optimization Implications:
- Put <link rel="stylesheet"> in <head> (avoid FOUC)
- Put <script> at end of <body> OR use async/defer
- Minimize render-blocking resources for better FCP (First Contentful Paint)

7. BROWSER COMPATIBILITY
================================================================================

Checking Support:
- caniuse.com — check feature support by browser version
- MDN compatibility tables
- Feature detection (preferred over browser detection)

Feature Detection (preferred):
  if ('IntersectionObserver' in window) { /* use it */ }

Polyfills:
  Scripts that implement modern features for older browsers.
  Examples: html5shiv (IE8 semantic elements), respond.js (IE8 media queries)

Graceful Degradation vs Progressive Enhancement:
- Graceful Degradation: Build for modern → provide fallback for old
- Progressive Enhancement: Build for baseline → layer enhancements on top
  (PREFERRED approach)

8. IMPORTANT INTERVIEW Q&A
================================================================================

Q1: What is the difference between HTML elements and HTML tags?
A: Tags are the raw syntax (<p>, </p>). An element is everything from the
   opening tag to the closing tag, including the content. An element can be
   thought of as an "instance" defined by its tags.

Q2: What are void elements in HTML?
A: Elements that cannot have children and therefore have no closing tag.
   Examples: <br>, <hr>, <img>, <input>, <link>, <meta>, <source>, <track>,
   <wbr>, <col>, <embed>, <area>, <base>, <param>

Q3: Is HTML case-sensitive?
A: No. HTML tag names and attribute names are case-insensitive, though
   attribute VALUES can be case-sensitive (e.g., class names used in
   CSS selectors ARE case-sensitive).

Q4: What happens if you don't provide a DOCTYPE?
A: The browser switches to "quirks mode" — it emulates old browser behavior
   with buggy CSS box model handling and inconsistencies across browsers.
   Always use <!DOCTYPE html> to trigger "standards mode."

Q5: What is the difference between the DOM and the BOM?
A: DOM (Document Object Model) = interface to the HTML document (document,
   elements, etc.). BOM (Browser Object Model) = interface to the browser
   window (window, navigator, history, location, screen, etc.). The DOM is
   standardized; BOM is partially standardized.

Q6: Can a web page have multiple <html>, <head>, or <body> tags?
A: No. These are unique structural elements. Browsers may auto-correct
   duplicate tags, but having multiple is invalid HTML. Only one <html>,
   one <head>, and one <body> element should exist per document.

Q7: What is the difference between an attribute and a property?
A: Attributes are defined in HTML source (<input value="hello">).
   Properties are the current state in the DOM (input.value = "world").
   They start as the same but can diverge. getAttribute('value') always
   returns the HTML attribute; .value returns the current DOM property.

Q8: What is a "living standard" in HTML context?
A: HTML5 (now just "HTML") is maintained as a living standard by WHATWG —
   it is continuously updated rather than having versioned releases like
   HTML 4.01. This means features are added incrementally and
   browsers implement them progressively.

Q9: Explain the difference between defer and async on script tags.
A: Both allow HTML parsing to continue while the script downloads.
   - async: executes as soon as downloaded (may be out of order)
   - defer: executes after HTML is fully parsed, in document order
   Use async for independent scripts (analytics); use defer for scripts
   that depend on DOM or need to run in order.

Q10: What is document.readyState?
A: Indicates the loading state of the document:
   - "loading"     → DOM is still being parsed
   - "interactive" → DOM is parsed; sub-resources still loading
   - "complete"    → everything (images, CSS) is fully loaded
   Corresponds to the DOMContentLoaded and load events.
