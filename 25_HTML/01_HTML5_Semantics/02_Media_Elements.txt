1. OVERVIEW OF HTML5 MEDIA
================================================================================

HTML5 introduced native media support, eliminating the need for Flash, 
QuickTime, and other plugins.

Key media elements:
  <video>   — Embeds video content natively
  <audio>   — Embeds audio content natively
  <picture> — Responsive image container
  <img>     — Bitmap/vector image
  <canvas>  — Scriptable 2D drawing surface
  <svg>     — Inline scalable vector graphics
  <iframe>  — Embedded external document
  <embed>   — Plugin-based embedded content
  <object>  — External resource container

Before HTML5:
  <object type="application/x-shockwave-flash">
    <param name="movie" value="video.swf">
  </object>

After HTML5:
  <video controls>
    <source src="video.mp4" type="video/mp4">
  </video>

2. THE <video> ELEMENT
================================================================================

Basic usage:
  <video controls>
    <source src="movie.mp4"  type="video/mp4">
    <source src="movie.webm" type="video/webm">
    <p>Your browser does not support HTML5 video.
       <a href="movie.mp4">Download the video</a>.</p>
  </video>

Attributes:
  controls         — Show browser default controls (play, pause, volume, fullscreen)
  autoplay         — Start playing automatically (muted required on many browsers)
  loop             — Loop playback indefinitely
  muted            — Start muted (required for autoplay on most browsers)
  preload          — "none" | "metadata" | "auto"
                     none: don't load until user plays
                     metadata: only load duration/dimensions/tracks
                     auto: load enough to start playing immediately (default)
  poster           — URL of image shown before video loads/plays
  width            — Video player width (px; use CSS for responsive)
  height           — Video player height
  src              — Direct video URL (use <source> for multiple formats)
  playsinline      — Play inline on iOS (instead of fullscreen takeover)
  crossorigin      — CORS: "anonymous" | "use-credentials"

FULL EXAMPLE with all best practices:
  <video
    controls
    playsinline
    preload="metadata"
    poster="thumbnail.jpg"
    width="800"
    height="450"
    style="max-width: 100%; height: auto;"
    aria-label="Product demo video">
    
    <source src="demo.av1.mp4"  type="video/mp4; codecs=av01.0.05M.08">
    <source src="demo.h265.mp4" type="video/mp4; codecs=hev1.1.6.L93.B0">
    <source src="demo.h264.mp4" type="video/mp4">
    <source src="demo.webm"     type="video/webm">
    
    <track kind="subtitles"  src="sub-en.vtt" srclang="en" label="English" default>
    <track kind="subtitles"  src="sub-fr.vtt" srclang="fr" label="Français">
    <track kind="captions"   src="cap-en.vtt" srclang="en" label="English (CC)">
    <track kind="chapters"   src="chapters.vtt" srclang="en">
    
    <p>Your browser doesn't support HTML5 video.
       <a href="demo.h264.mp4">Download MP4</a></p>
  </video>

Responsive video (aspect ratio):
  /* CSS approach (modern) */
  video {
    width: 100%;
    height: auto;
    aspect-ratio: 16 / 9;
  }

  /* Older hack (padding trick) */
  .video-wrapper { position: relative; padding-top: 56.25%; /* 16:9 */ }
  .video-wrapper video { position: absolute; top: 0; left: 0; width: 100%; height: 100%; }

Autoplay policy (browsers):
  - Most browsers block autoplay UNLESS:
    a) Video is muted (<video autoplay muted>)
    b) User has interacted with the domain
    c) Media Engagement Index is high (Chrome)
  - Use JavaScript Media Session API for rich playback control

3. THE <audio> ELEMENT
================================================================================

Basic usage:
  <audio controls>
    <source src="podcast.mp3"  type="audio/mpeg">
    <source src="podcast.ogg"  type="audio/ogg">
    <source src="podcast.aac"  type="audio/aac">
    Your browser doesn't support HTML5 audio.
  </audio>

Attributes (same as video except no poster/width/height/playsinline):
  controls  — Show browser default audio controls
  autoplay  — Autoplay (subject to same browser restrictions as video)
  loop      — Loop audio
  muted     — Start muted
  preload   — none | metadata | auto
  src       — Direct audio URL

  <audio controls preload="metadata" aria-label="Episode 42: HTML Deep Dive">
    <source src="episode-42.mp3" type="audio/mpeg">
    <source src="episode-42.aac" type="audio/aac">
    <a href="episode-42.mp3">Download MP3</a>
  </audio>

Audio with track (for transcripts/descriptions):
  <audio controls>
    <source src="speech.mp3" type="audio/mpeg">
    <track kind="descriptions" src="speech-desc.vtt" srclang="en">
  </audio>

4. THE <picture> ELEMENT (RESPONSIVE IMAGES)
================================================================================

<picture> is a container that lets you specify MULTIPLE image sources.
The browser picks the most suitable one based on media queries and format support.

Use cases:
  a) Serve modern formats (WebP, AVIF) with fallback to JPEG/PNG
  b) Art direction (different crop/composition for different screen sizes)
  c) Different image sizes for different viewports

Format negotiation (browser picks first supported format):
  <picture>
    <source srcset="hero.avif" type="image/avif">
    <source srcset="hero.webp" type="image/webp">
    <img src="hero.jpg" alt="Hero image" width="1200" height="600"
         fetchpriority="high">
  </picture>

Art direction (different image per viewport):
  <picture>
    <!-- Landscape crop for desktop -->
    <source media="(min-width: 1024px)" srcset="hero-landscape.jpg">
    <!-- Square crop for tablet -->
    <source media="(min-width: 768px)" srcset="hero-square.jpg">
    <!-- Portrait crop for mobile — img tag is fallback -->
    <img src="hero-portrait.jpg" alt="Hero image" width="400" height="600">
  </picture>

Combining art direction + format:
  <picture>
    <source media="(min-width: 1024px)" 
            srcset="hero-desktop.avif" type="image/avif">
    <source media="(min-width: 1024px)" 
            srcset="hero-desktop.webp" type="image/webp">
    <source media="(min-width: 1024px)" 
            srcset="hero-desktop.jpg">
    <source srcset="hero-mobile.avif" type="image/avif">
    <source srcset="hero-mobile.webp" type="image/webp">
    <img src="hero-mobile.jpg" alt="Hero" width="400" height="600">
  </picture>

IMPORTANT: The <img> inside <picture> is ALWAYS required:
  - Provides final fallback
  - alt, width, height attributes MUST be on <img>, not <source>
  - Is the element used for SEO, styling, and accessibility

5. THE <img> ELEMENT (IN-DEPTH)
================================================================================

<img src="profile.jpg" 
     alt="Jane Doe, CEO of Example Corp, smiling in office"
     width="400" 
     height="400"
     loading="lazy"
     decoding="async"
     fetchpriority="low">

Core attributes:
  src          — Image URL (required)
  alt          — Alternative text (required for accessibility; empty for decorative)
  width        — Intrinsic width in pixels (prevents CLS)
  height       — Intrinsic height in pixels (prevents CLS)

Loading attributes:
  loading="lazy"    — Defer loading until near viewport (below-fold images)
  loading="eager"   — Load immediately (default; use for above-fold LCP images)
  
  When NOT to use loading="lazy":
    - LCP (Largest Contentful Paint) image — delays the key metric
    - Images above the fold
    - Images in initial viewport on mobile

  fetchpriority="high"  — Boost download priority (use for LCP image)
  fetchpriority="low"   — Lower priority (use for below-fold, off-screen)
  fetchpriority="auto"  — Browser decides (default)

  decoding="sync"   — Decode before rendering (may block; use for critical imgs)
  decoding="async"  — Decode off main thread (default for most images)
  decoding="auto"   — Browser decides

CORS:
  crossorigin="anonymous"       — Include credentials if same-origin CORS
  crossorigin="use-credentials" — Always include credentials

  Needed for:
    - Images used in WebGL or canvas (tainted canvas prevention)
    - Images loaded by service workers

srcset and sizes (responsive images without <picture>):
  <!-- Width descriptor: browser picks based on sizes attribute -->
  <img
    src="photo-400.jpg"
    srcset="photo-400.jpg 400w, photo-800.jpg 800w, photo-1200.jpg 1200w"
    sizes="(max-width: 600px) 100vw,
           (max-width: 1200px) 50vw,
           400px"
    alt="Responsive photo">

  sizes attribute tells browser what size the image will render at (in CSS px):
    "(max-width: 600px) 100vw" — on mobile, image is 100% of viewport width
    "(max-width: 1200px) 50vw" — on tablet, image is 50% of viewport width
    "400px"                    — on desktop, image is 400px

  Browser calculates: sizes value × device pixel ratio → chooses from srcset

  <!-- Pixel density descriptor: for HiDPI displays -->
  <img
    src="logo.png"
    srcset="logo.png 1x, logo@2x.png 2x, logo@3x.png 3x"
    alt="Logo">

alt text rules:
  - Informative image: describe what the image shows and its purpose
  - Functional image (link/button): describe the action/destination
  - Decorative image: alt="" (empty string — tells screen reader to skip)
  - Complex image (chart/diagram): alt="" + nearby text description or aria-describedby
  
  DO:    alt="Bar chart showing 40% revenue increase from 2024 to 2026"
  DON'T: alt="image" or alt="chart.png" or alt="chart of stuff"

  For <img> as the only content of a link:
    <a href="/home"><img src="logo.png" alt="Company Name — Home"></a>
    The alt describes the LINK DESTINATION, not just the image.

6. THE <source> ELEMENT
================================================================================

<source> specifies multiple media resources for <video>, <audio>, or <picture>.
It's a VOID element (no closing tag).

Attributes:
  src      — URL (for video/audio)
  srcset   — URLs with descriptors (for picture)
  type     — MIME type with optional codecs
  media    — Media query (for picture; rarely for video)
  sizes    — Sizes hint (for picture)

MIME types:
  Video:  video/mp4, video/webm, video/ogg
  Audio:  audio/mpeg (mp3), audio/ogg, audio/aac, audio/flac, audio/wav
  Image:  image/webp, image/avif, image/jpeg, image/png, image/gif

Type with codec parameter:
  <source src="video.mp4" type="video/mp4; codecs=avc1.42E01E,mp4a.40.2">
  Specifying codecs helps browser skip format if codec is unsupported,
  avoiding wasted network request.

Browser selection order:
  Browser evaluates <source> elements TOP TO BOTTOM and picks the FIRST one
  it can handle. Order matters — put most-preferred format first.

7. THE <track> ELEMENT (SUBTITLES/CAPTIONS)
================================================================================

<track> adds text tracks to <video> and <audio> elements.
Uses WebVTT format (.vtt files).

  <video controls>
    <source src="video.mp4" type="video/mp4">
    <track kind="subtitles"     src="subs-en.vtt" srclang="en" label="English" default>
    <track kind="subtitles"     src="subs-fr.vtt" srclang="fr" label="Français">
    <track kind="captions"      src="cc-en.vtt"   srclang="en" label="English (CC)">
    <track kind="descriptions"  src="desc-en.vtt" srclang="en" label="Audio Description">
    <track kind="chapters"      src="chapters.vtt" srclang="en">
    <track kind="metadata"      src="metadata.vtt">
  </video>

Attributes:
  kind      — Track type (see below)
  src       — URL of .vtt file
  srclang   — BCP 47 language tag
  label     — User-visible name in language menu
  default   — This track is enabled by default

kind values:
  subtitles     — Translation of dialogue (for those who don't understand language)
  captions      — Includes dialogue + sound effects (for deaf/hard of hearing)
  descriptions  — Audio descriptions of video content (for blind users)
  chapters      — Chapter markers for navigation
  metadata      — Hidden track used by scripts; not displayed

WebVTT (.vtt) format:
  WEBVTT

  00:00:01.000 --> 00:00:04.000
  Hello and welcome to this tutorial.

  00:00:05.500 --> 00:00:09.000
  Today we'll learn about HTML5 media elements.

  NOTE: You can also add positioning and styling
  
  00:00:10.000 --> 00:00:14.000 position:50% line:80%
  <c.yellow>This text is yellow and positioned.</c>

Accessibility requirement:
  WCAG 1.2.2 (Level A): Captions REQUIRED for prerecorded synchronized video
  WCAG 1.2.3 (Level A): Audio description or media alternative required
  WCAG 1.2.5 (Level AA): Audio descriptions required for prerecorded video

8. THE <iframe> ELEMENT
================================================================================

<iframe> embeds another HTML document within the current page.

  <iframe
    src="https://www.youtube.com/embed/VIDEO_ID"
    width="560"
    height="315"
    title="YouTube video: HTML5 Tutorial"
    allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share"
    allowfullscreen
    loading="lazy"
    referrerpolicy="strict-origin-when-cross-origin">
  </iframe>

Attributes:
  src              — URL to embed
  title            — Accessible name (REQUIRED for screen readers)
  width/height     — Dimensions
  allow            — Feature policy (which browser features the iframe can use)
  allowfullscreen  — Allow fullscreen API
  loading="lazy"   — Lazy-load the iframe (improves page load)
  sandbox          — Restrict iframe capabilities
  referrerpolicy   — Controls Referer header sent to iframe
  name             — Browsing context name (target for links)
  srcdoc           — HTML content directly in attribute (instead of src)

sandbox attribute values (restrictions):
  ""                        — All restrictions enabled
  allow-scripts             — Allow JavaScript execution
  allow-forms               — Allow form submission
  allow-same-origin         — Allow same-origin access (CORS, cookies)
  allow-popups              — Allow window.open, target="_blank"
  allow-top-navigation      — Allow navigation of top-level browsing context
  allow-downloads           — Allow file downloads

Security notes:
  - iframes from untrusted origins should ALWAYS have sandbox
  - sandbox without allow-same-origin is safest (can't break out)
  - X-Frame-Options or CSP frame-ancestors header prevents your page from
    being iframed (clickjacking protection)
  - title attribute is REQUIRED for accessibility (screen readers announce it)

Responsive iframe (16:9):
  .iframe-container {
    position: relative;
    padding-top: 56.25%; /* 16:9 aspect ratio */
    height: 0;
    overflow: hidden;
  }
  .iframe-container iframe {
    position: absolute;
    top: 0; left: 0;
    width: 100%; height: 100%;
  }

  Modern CSS (no padding hack needed):
  .iframe-container {
    aspect-ratio: 16 / 9;
    width: 100%;
  }
  .iframe-container iframe {
    width: 100%; height: 100%;
  }

9. THE <embed> AND <object> ELEMENTS
================================================================================

<embed> (HTML5):
  Embeds external content (mostly legacy use).
  <embed src="document.pdf" type="application/pdf" width="100%" height="600">
  <embed src="animation.swf" type="application/x-shockwave-flash" width="500" height="400">

<object> (HTML4/HTML5):
  More flexible embedded content with fallback support.
  <object data="document.pdf" type="application/pdf" width="100%" height="600">
    <p>PDF could not be displayed. <a href="document.pdf">Download PDF</a>.</p>
  </object>

Modern usage:
  Both <embed> and <object> are largely replaced by:
  - <video>/<audio> for media
  - <iframe> for external documents
  - <canvas>/<svg> for graphics
  PDF: use <iframe src="doc.pdf"> or link to it

10. MEDIA FORMATS & BROWSER SUPPORT
================================================================================

VIDEO FORMATS:
  Format  Container  Codec     Support          Notes
  ------  ---------  -------   ---------------  -----------------------
  MP4     .mp4       H.264     Universal        Most compatible; standard
  MP4     .mp4       H.265     Chrome/Edge/iOS  50% better compression than H.264
  WebM    .webm      VP9       Chrome/Firefox   Google's format
  WebM    .webm      VP8       All modern       Older WebM codec
  MP4     .mp4       AV1       Chrome/Firefox   Best quality/size ratio; slow encode
  OGG     .ogv       Theora    Firefox          Legacy; avoid

  RECOMMENDATION:
    Primary:  MP4 (H.264) — universal compatibility
    Offer:    WebM (VP9) or AV1 for better compression on supporting browsers

AUDIO FORMATS:
  Format   MIME type       Support              Notes
  ------   ----------      ------------------   ----------------
  MP3      audio/mpeg      Universal            Standard compressed audio
  AAC      audio/aac       Universal            Better quality than MP3 at same bitrate
  OGG      audio/ogg       Firefox/Chrome       Open source; not Safari by default
  Opus     audio/ogg       Chrome/Firefox       Best quality/size for voice
  FLAC     audio/flac      Most modern          Lossless; large files
  WAV      audio/wav       Universal            Uncompressed; huge files (avoid)
  WebM     audio/webm      Chrome/Firefox       WebM container with Opus

  RECOMMENDATION:
    Primary:   AAC (.m4a) or MP3 — universal
    Secondary: Opus (.ogg) for voice/podcast quality

IMAGE FORMATS:
  Format  MIME type     Support         Best For
  ------  ----------    ----------      ----------------------------
  JPEG    image/jpeg    Universal       Photos; lossy; no transparency
  PNG     image/png     Universal       Graphics/logos; lossless; transparency
  GIF     image/gif     Universal       Simple animations; 256 colors only
  SVG     image/svg+xml Universal       Icons, logos, illustrations; scalable
  WebP    image/webp    All modern      Photos+graphics; 25-35% smaller than JPEG
  AVIF    image/avif    Chrome/Firefox  50% smaller than JPEG; slow encode
  HEIF    image/heif    Safari/iOS      Apple's format; not widely supported
  ICO     image/x-icon  Universal       Favicons

11. MEDIA API (JAVASCRIPT)
================================================================================

HTMLMediaElement API (shared by <video> and <audio>):

Properties:
  media.src              — Current media URL
  media.currentSrc       — Resolved URL being played
  media.currentTime      — Playback position in seconds (get/set)
  media.duration         — Total duration in seconds (NaN until loaded)
  media.paused           — Boolean: is it paused?
  media.ended            — Boolean: has playback ended?
  media.muted            — Boolean: is audio muted?
  media.volume           — Volume 0–1 (get/set)
  media.playbackRate     — Speed multiplier (1 = normal, 2 = 2x speed)
  media.buffered         — TimeRanges object of buffered data
  media.seekable         — TimeRanges object of seekable range
  media.readyState       — 0=HAVE_NOTHING, 1=HAVE_METADATA, 2=HAVE_CURRENT_DATA,
                            3=HAVE_FUTURE_DATA, 4=HAVE_ENOUGH_DATA
  media.networkState     — 0=EMPTY, 1=IDLE, 2=LOADING, 3=NO_SOURCE
  media.videoWidth/.videoHeight — (video only) intrinsic dimensions
  media.textTracks       — TextTrackList object

Methods:
  media.play()           — Returns Promise (resolves when playing starts)
  media.pause()          — Pause playback
  media.load()           — Reset and reload
  media.canPlayType(mime) — "", "maybe", "probably"
  media.addTextTrack()   — Programmatically add text track
  media.fastSeek(time)   — Fast seek (may not be precise)

Events:
  loadstart    — Network request begun
  durationchange — Duration known
  loadedmetadata — Metadata loaded (duration, dimensions)
  loadeddata   — Current frame data loaded
  canplay      — Can start playing (may stall)
  canplaythrough — Can play without buffering
  playing      — Actually started playing
  pause        — Paused
  ended        — Reached end of media
  timeupdate   — currentTime changed (fired 4x/sec while playing)
  volumechange — Volume or muted changed
  seeked/seeking — Seek completed/started
  waiting      — Paused to buffer
  error        — Error occurred
  stalled      — Browser waiting for data

JavaScript example:
  const video = document.querySelector('video');

  // Play/pause toggle
  document.getElementById('toggleBtn').addEventListener('click', () => {
    video.paused ? video.play() : video.pause();
  });

  // Current time display
  video.addEventListener('timeupdate', () => {
    const progress = (video.currentTime / video.duration) * 100;
    progressBar.style.width = progress + '%';
    timeDisplay.textContent = formatTime(video.currentTime);
  });

  // Seek on click
  progressContainer.addEventListener('click', (e) => {
    const rect = progressContainer.getBoundingClientRect();
    const ratio = (e.clientX - rect.left) / rect.width;
    video.currentTime = ratio * video.duration;
  });

  // Check playback capability
  if (video.canPlayType('video/mp4; codecs=av01') === 'probably') {
    video.src = 'video-av1.mp4';
  }

12. ACCESSIBILITY FOR MEDIA
================================================================================

VIDEO accessibility checklist:
  ✓ Controls are keyboard accessible (native controls are by default)
  ✓ Captions/subtitles available (<track kind="captions">)
  ✓ Audio descriptions for visual-only information
  ✓ Transcript available for deaf/blind users
  ✓ poster image has no essential information (visible only before play)
  ✓ No video auto-plays with sound (WCAG 1.4.2)
  ✓ No flashing content (WCAG 2.3.1: no more than 3 flashes per second)

AUDIO accessibility checklist:
  ✓ Native controls present and keyboard accessible
  ✓ Transcript provided
  ✓ No auto-play with sound
  ✓ Volume control accessible

IFRAME accessibility:
  ✓ title attribute always present: <iframe title="Google Maps showing office location">
  ✓ sandbox used for untrusted content

IMAGE accessibility:
  ✓ All <img> have alt attribute (even if empty for decorative)
  ✓ Complex images: long description via aria-describedby or nearby text
  ✓ Linked images: alt describes destination ("Company Name — Home")
  ✓ CAPTCHA has audio alternative

WCAG SC for Media:
  1.2.1 (A)  — Audio-only: transcript required
  1.2.1 (A)  — Video-only: transcript or audio description required
  1.2.2 (A)  — Captions for prerecorded video
  1.2.3 (A)  — Audio description or text alternative for prerecorded video
  1.2.4 (AA) — Captions for live video
  1.2.5 (AA) — Audio descriptions for prerecorded video
  1.2.6 (AAA)— Sign language interpretation
  1.4.2 (A)  — Audio control: if audio auto-plays >3s, user must be able to stop/mute

13. PERFORMANCE OPTIMIZATION
================================================================================

Images:
  1. Use modern formats: WebP (universal) → AVIF (where supported)
  2. Use responsive images: srcset + sizes or <picture>
  3. Specify width + height (prevent CLS)
  4. loading="lazy" for below-fold images
  5. fetchpriority="high" for LCP image
  6. Compress images: target <100KB for content images, <500KB for heroes
  7. Use <picture> for art direction to serve smaller images on mobile

Video:
  1. Compress video: target 1-5Mbps for 1080p HD web video
  2. preload="metadata" (not "auto") — avoid unnecessary bandwidth
  3. poster attribute: show thumbnail immediately
  4. loading="lazy" for below-fold iframes (YouTube embeds)
  5. Serve via CDN
  6. Use streaming (HLS/DASH) for long videos
  7. Consider background video only on desktop (prefers-reduced-motion)

Respect user preferences:
  @media (prefers-reduced-motion: reduce) {
    video[autoplay] { display: none; } /* hide autoplay background video */
  }

Lazy-loading YouTube embeds (avoid iframe until user clicks):
  <!-- Lightweight YouTube Embed pattern -->
  <div class="youtube-lite" data-id="VIDEO_ID">
    <img src="https://img.youtube.com/vi/VIDEO_ID/hqdefault.jpg"
         alt="Video thumbnail">
    <button aria-label="Play video">▶</button>
  </div>
  <!-- Replace with <iframe> on click via JavaScript -->

14. IMPORTANT INTERVIEW Q&A
================================================================================

Q1: Why does HTML5 <video> require multiple <source> elements?
A: Because no single video format is universally supported across all browsers.
   By providing multiple sources (MP4/H.264, WebM/VP9, etc.), the browser picks
   the first format it supports. The browser evaluates <source> elements top-to-
   bottom and uses the first compatible one.

Q2: What is the difference between <video> src attribute and <source> element?
A: The src attribute on <video> specifies a single source. Using <source> elements
   allows multiple fallback formats. If multiple formats are needed (for browser
   compatibility), always use <source>. If only one format is needed (e.g., MP4
   for modern browsers), either approach works.

Q3: What is the difference between autoplay and preload?
A: autoplay starts playback immediately when ready. preload controls how much
   the browser downloads before user interaction: none (nothing), metadata
   (only duration/dimensions), auto (enough to start playing without pause).
   Most browsers ignore autoplay unless the video is muted or user has
   engaged with the site.

Q4: What is the difference between <picture> and srcset on <img>?
A: srcset with sizes gives the browser a CHOICE based on viewport size and
   pixel density — the browser picks the best size for performance.
   <picture> is for ART DIRECTION (different crop/composition per screen)
   or FORMAT negotiation (AVIF first, WebP fallback, JPEG last). With <picture>
   you're dictating exactly which source to use; with srcset the browser decides.

Q5: What is the purpose of the <track> element and why is it important?
A: <track> provides WebVTT text track files (subtitles, captions, descriptions,
   chapters) for video and audio. Captions and subtitles are required by WCAG
   2.0 Level A (SC 1.2.2) for all prerecorded synchronized video content —
   making it a legal accessibility requirement in many jurisdictions. It also
   enables chapter navigation and searchable video content.

Q6: What is the difference between subtitles and captions?
A: Subtitles are TRANSLATIONS of dialogue for viewers who don't understand the
   language. Captions are for DEAF or hard-of-hearing viewers — they include
   dialogue AND non-verbal audio cues (music, sound effects, speaker labels).
   In HTML5: kind="subtitles" vs kind="captions".

Q7: What are the security concerns with <iframe>?
A: (1) Clickjacking: malicious site can iframe your page and overlay invisible
   elements to trick clicks. Prevent with X-Frame-Options: SAMEORIGIN or
   CSP frame-ancestors directive.
   (2) Embedded malicious content: sandbox attribute restricts what the iframe
   can do (disable scripts, popups, same-origin access).
   (3) Always add title attribute for accessibility.
   (4) referrerpolicy controls Referer header sent to embedded page.

Q8: How does loading="lazy" work for images?
A: The browser defers downloading images until they are within a threshold
   distance from the viewport (a few hundred pixels based on connection speed).
   It requires IntersectionObserver under the hood. Don't use on above-fold
   images or LCP elements — it delays the most important visual paint.
   Always specify width and height so the browser can reserve space before load.

Q9: What is fetchpriority and when should you use it?
A: fetchpriority hints to the browser about the relative download priority of a
   resource. Use fetchpriority="high" on the LCP image (the most important
   visual element) to ensure it's downloaded as soon as possible, improving
   LCP score. Use fetchpriority="low" for below-fold images. Available on
   <img>, <link rel="preload">, <script>, and fetch().

Q10: How do you make a video responsive in HTML/CSS?
A: Two approaches:
   Modern CSS: video { width: 100%; height: auto; aspect-ratio: 16/9; }
   Legacy padding hack: Wrapper has padding-top: 56.25% (9/16) and position:
   relative; the video is position: absolute filling 100%/100%.
   Always specify intrinsic width/height attributes on <video> to prevent CLS,
   then override with CSS for responsiveness.
