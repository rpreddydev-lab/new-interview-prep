1. WHEN TO USE TABLES
================================================================================

Tables are for TABULAR DATA — data that has a meaningful relationship in
two dimensions (rows AND columns). The test: does each cell make sense in
relation to both its row header and its column header?

CORRECT uses:
  ✓ Financial reports (revenue by quarter by product)
  ✓ Comparison tables (features vs pricing tiers)
  ✓ Sports standings / league tables
  ✓ Class schedules / timetables
  ✓ Data grids (spreadsheet-like content)
  ✓ HTML entity reference charts

INCORRECT uses (use CSS layout instead):
  ✗ Page layout (header, sidebar, content, footer)
  ✗ Form alignment (use CSS Grid/Flexbox)
  ✗ Visual grid of cards (use CSS Grid)
  ✗ Side-by-side columns of text (use CSS columns or Flexbox)
  ✗ Navigation menus

Why using tables for layout is bad:
  - Screen readers read tables as data tables (announcing row/column headers)
  - Ruins accessibility — visually impaired users hear confusing cell announcements
  - Fixed layout doesn't adapt to mobile
  - Hard to maintain
  - Slow rendering (browser must compute entire table before paint)
  - Bad SEO — content order in source may not match visual order

2. BASIC TABLE STRUCTURE
================================================================================

Minimal valid table:
  <table>
    <tr>
      <td>Cell 1</td>
      <td>Cell 2</td>
    </tr>
    <tr>
      <td>Cell 3</td>
      <td>Cell 4</td>
    </tr>
  </table>

Complete table with all semantic elements:
  <table>
    <caption>Annual Revenue by Region (USD Millions)</caption>
    <colgroup>
      <col class="col-region">
      <col class="col-q1">
      <col class="col-q2">
      <col class="col-q3">
      <col class="col-q4">
    </colgroup>
    <thead>
      <tr>
        <th scope="col">Region</th>
        <th scope="col">Q1</th>
        <th scope="col">Q2</th>
        <th scope="col">Q3</th>
        <th scope="col">Q4</th>
      </tr>
    </thead>
    <tbody>
      <tr>
        <th scope="row">North America</th>
        <td>45.2</td>
        <td>52.1</td>
        <td>48.9</td>
        <td>61.3</td>
      </tr>
      <tr>
        <th scope="row">Europe</th>
        <td>38.4</td>
        <td>41.7</td>
        <td>39.2</td>
        <td>50.8</td>
      </tr>
    </tbody>
    <tfoot>
      <tr>
        <th scope="row">Total</th>
        <td>83.6</td>
        <td>93.8</td>
        <td>88.1</td>
        <td>112.1</td>
      </tr>
    </tfoot>
  </table>

Core elements:
  <table>   — Container; creates table formatting context
  <tr>      — Table Row
  <td>      — Table Data cell
  <th>      — Table Header cell (bold, centered by default; semantic header)
  <thead>   — Header rows group
  <tbody>   — Body rows group (can have multiple tbody elements!)
  <tfoot>   — Footer rows group
  <caption> — Table title/description
  <colgroup>— Column group
  <col>     — Column definition (within colgroup)

3. COLUMN GROUPING (<colgroup> AND <col>)
================================================================================

<colgroup> groups columns for styling purposes. It comes right after <caption>
and before <thead>.

<col> is a void element representing a single column.

  <colgroup>
    <col>                          <!-- column 1: no special styling -->
    <col span="3" class="quarter"> <!-- columns 2-4: apply same class -->
    <col class="total">            <!-- column 5 -->
  </colgroup>

span attribute on <colgroup> or <col>:
  <colgroup span="3"> ← this colgroup covers 3 columns
  <col span="2">      ← this col definition applies to 2 columns

What <col> can style (limited!):
  ✓ background-color
  ✓ border
  ✓ width
  ✗ Most other CSS properties (they don't cascade to cells from col)

Practical use case:
  <style>
    .highlight-col { background-color: #fef3c7; }
  </style>
  <colgroup>
    <col>
    <col>
    <col class="highlight-col">  <!-- Highlight Q3 column -->
    <col>
  </colgroup>

4. TABLE HEADERS AND ACCESSIBILITY
================================================================================

The scope attribute on <th>:
  scope="col"   — This header applies to the column below it
  scope="row"   — This header applies to the row to its right
  scope="colgroup" — Header for a group of columns (complex tables)
  scope="rowgroup" — Header for a group of rows (complex tables)

ALWAYS use scope on <th> elements. Without scope, screen readers may not
correctly associate headers with data cells.

  <!-- Column headers -->
  <tr>
    <th scope="col">Name</th>
    <th scope="col">Age</th>
    <th scope="col">Role</th>
  </tr>

  <!-- Row headers (leftmost column) -->
  <tr>
    <th scope="row">Alice</th>
    <td>30</td>
    <td>Engineer</td>
  </tr>

headers attribute (for complex multi-level headers):
  Used when a cell is associated with MULTIPLE header cells.
  
  <table>
    <tr>
      <td></td>
      <th id="h-clothes" scope="colgroup" colspan="3">Clothes</th>
      <th id="h-acc" scope="colgroup" colspan="2">Accessories</th>
    </tr>
    <tr>
      <td></td>
      <th id="h-trousers" scope="col">Trousers</th>
      <th id="h-skirts"   scope="col">Skirts</th>
      <th id="h-dresses"  scope="col">Dresses</th>
      <th id="h-bracelets" scope="col">Bracelets</th>
      <th id="h-rings"    scope="col">Rings</th>
    </tr>
    <tr>
      <th id="h-belgium" scope="rowgroup">Belgium</th>
      <td headers="h-belgium h-clothes h-trousers">56</td>
      <td headers="h-belgium h-clothes h-skirts">22</td>
      ...
    </tr>
  </table>

The headers attribute takes a space-separated list of id values of all
header cells that apply to the data cell.

id vs scope:
  For simple tables: scope is sufficient and simpler
  For complex tables (multi-level headers, irregular structures): use id + headers

================================================================================
5. COMPLEX TABLES (colspan / rowspan)
================================================================================

colspan: cell spans multiple COLUMNS
rowspan: cell spans multiple ROWS

  <table border="1">
    <caption>Employee Skills Matrix</caption>
    <thead>
      <tr>
        <th scope="col" rowspan="2">Employee</th>
        <th scope="colgroup" colspan="2">Technical</th>
        <th scope="colgroup" colspan="2">Soft Skills</th>
      </tr>
      <tr>
        <!-- No cell for Employee (it has rowspan=2) -->
        <th scope="col">JavaScript</th>
        <th scope="col">Python</th>
        <th scope="col">Communication</th>
        <th scope="col">Leadership</th>
      </tr>
    </thead>
    <tbody>
      <tr>
        <th scope="row">Alice</th>
        <td>Expert</td>
        <td>Intermediate</td>
        <td>Expert</td>
        <td colspan="1">Advanced</td>
      </tr>
    </tbody>
  </table>

Rules for colspan/rowspan:
  - colspan="2" means the cell occupies 2 column slots
  - The cells that would normally fill those slots are OMITTED from HTML
  - rowspan="2" means the cell occupies 2 row slots
  - Those rows below also have that cell slot OMITTED

COUNTING CELLS:
  If a row has cells with colspan values, the sum of all (non-rowspan-empty)
  cell colspans in that row must equal the total number of columns.

  <!-- 5 columns total -->
  <tr>
    <td colspan="2">Col 1-2</td>  ← occupies 2
    <td>Col 3</td>                  ← occupies 1
    <td colspan="2">Col 4-5</td>  ← occupies 2
    <!-- Total: 2+1+2 = 5 ✓ -->
  </tr>

6. CAPTION ELEMENT
================================================================================

<caption> provides a visible title/description for the table.
  - Must be the FIRST child of <table>
  - Appears above the table by default (control with caption-side CSS)
  - Read by screen readers before table content
  - Helps SEO by describing the table content

  <table>
    <caption>
      <strong>Table 1:</strong> Monthly sales by product category (USD)
    </caption>
    ...
  </table>

CSS for caption positioning:
  table { caption-side: top; }    /* default */
  table { caption-side: bottom; }

When caption isn't enough (complex tables):
  Use aria-describedby to link to a longer description:
  <table aria-describedby="table1-desc">
    <caption>Sales Data</caption>
    ...
  </table>
  <p id="table1-desc">
    This table shows monthly sales figures for each product category
    from January through December 2026.
  </p>

7. TABLE SECTIONS (thead, tbody, tfoot)
================================================================================

<thead>:
  - Header rows (usually column headers)
  - Optional but recommended for accessibility
  - When table scrolls vertically, <thead> may be "sticky" in some browsers
  - Screen readers announce "header" context for cells within

<tbody>:
  - Main data content
  - Browser auto-creates anonymous tbody if not specified
  - MULTIPLE <tbody> allowed in one table (useful for grouping rows)
  
  <tbody>
    <tr><th colspan="2" scope="rowgroup">Q1</th></tr>
    <tr><th scope="row">Jan</th><td>100</td></tr>
    <tr><th scope="row">Feb</th><td>120</td></tr>
  </tbody>
  <tbody>
    <tr><th colspan="2" scope="rowgroup">Q2</th></tr>
    <tr><th scope="row">Apr</th><td>130</td></tr>
    <tr><th scope="row">May</th><td>115</td></tr>
  </tbody>

<tfoot>:
  - Summary/total rows
  - Always rendered at BOTTOM regardless of HTML position (browser moves it)
  - Screen readers announce it after tbody content

DOM order vs rendering order:
  Even if you write <tfoot> before <tbody> in HTML, browsers always render:
  thead → tbody → tfoot (in that visual order)

8. RESPONSIVE TABLES
================================================================================

Problem: Wide tables overflow on narrow screens.

Solution 1: Horizontal scroll wrapper (simplest, most accessible):
  <div style="overflow-x: auto; -webkit-overflow-scrolling: touch;" 
       role="region" aria-labelledby="tbl-caption" tabindex="0">
    <table>
      <caption id="tbl-caption">Monthly Sales Data</caption>
      ...
    </table>
  </div>

  Note: role="region" + aria-labelledby makes the scroll container a
  navigable landmark. tabindex="0" makes it keyboard scrollable.

Solution 2: Column priority (hide less important columns):
  @media (max-width: 600px) {
    .col-optional { display: none; }
  }
  Use aria-hidden="true" on hidden headers too.

Solution 3: Card layout (stacked rows on mobile):
  @media (max-width: 600px) {
    table, thead, tbody, th, td, tr { display: block; }
    thead tr { position: absolute; top: -9999px; left: -9999px; }
    tr { border: 1px solid #ccc; margin-bottom: 8px; }
    td {
      border: none;
      position: relative;
      padding-left: 50%;
    }
    td::before {
      content: attr(data-label); /* set data-label on each td via JS or HTML */
      position: absolute;
      left: 6px;
      width: 45%;
      font-weight: bold;
    }
  }

  HTML with data-label:
    <td data-label="Product">Widget A</td>
    <td data-label="Q1">45.2</td>

9. STYLING TABLES
================================================================================

Border collapsing:
  table { border-collapse: collapse; }  /* Merge adjacent cell borders (recommended) */
  table { border-collapse: separate; border-spacing: 4px; } /* Keep separated */

Striped rows:
  tbody tr:nth-child(even) { background-color: #f2f2f2; }
  tbody tr:hover { background-color: #e8f4f8; }

Column width control:
  table { table-layout: fixed; width: 100%; }
  th:first-child { width: 200px; }
  /* fixed: browser uses first row to determine column widths — faster rendering */
  /* auto (default): adjusts widths based on content — slower */

Sticky header:
  table { border-collapse: collapse; }
  thead th {
    position: sticky;
    top: 0;
    background: white;
    z-index: 1;
  }

  Note: position:sticky doesn't work on <thead>/<tr> in some browsers.
  Apply directly to <th> cells for consistent behavior.

Full example CSS:
  table {
    width: 100%;
    border-collapse: collapse;
    table-layout: fixed;
    font-size: 0.9rem;
  }
  caption {
    caption-side: top;
    font-weight: bold;
    margin-bottom: 0.5rem;
    text-align: left;
  }
  th, td {
    padding: 12px 16px;
    text-align: left;
    border-bottom: 1px solid #e5e7eb;
  }
  th {
    background-color: #f9fafb;
    font-weight: 600;
    color: #374151;
  }
  tbody tr:hover {
    background-color: #f0f9ff;
  }
  tfoot td {
    font-weight: bold;
    border-top: 2px solid #374151;
  }

10. TABLES vs CSS LAYOUT
================================================================================

Historical context:
  Before CSS Grid and Flexbox, tables were widely used for page layout
  (float-based layouts were also common). This was "table-based layout"
  and is now considered bad practice.

NEVER use tables for:
  - Page layout (header/footer/sidebar/content)
  - Any layout that could be achieved with Grid or Flexbox
  - Navigation menus

ALWAYS use tables for:
  - Genuinely tabular data (rows AND columns have meaningful relationship)
  - Financial data, schedules, comparisons, scores

Quick decision guide:
  Does the data have rows AND columns where both axes have headers?  → table
  Is it just a visual arrangement of content?                         → CSS Grid/Flex
  Is it a list of items (even if displayed in columns)?               → ul/ol + CSS
  Is it a form layout?                                                → Grid/Flex

11. ACCESSIBILITY FOR TABLES
================================================================================

For SIMPLE tables (no merged cells):
  1. Add <caption> (or aria-label if no caption)
  2. <th scope="col"> for column headers
  3. <th scope="row"> for row headers
  4. Keep structure simple — avoid unnecessary merges

For COMPLEX tables (merged cells, multi-level headers):
  1. Add id to each <th>
  2. Add headers attribute to each data cell (space-separated th ids)
  3. Consider splitting into multiple simple tables instead

When a table is for LAYOUT (legacy code):
  <table role="presentation">
  role="presentation" tells screen readers to ignore the table structure
  and treat contents as plain content flow. Use only as last resort.

Summary attribute (deprecated in HTML5):
  <table summary="...">  — was used to describe table for screen readers
  Replace with: <caption>, aria-describedby, or surrounding text.

Testing table accessibility:
  - VoiceOver (macOS/iOS): VO+left/right to navigate cells
  - NVDA (Windows): Table mode with T key
  - Browser: right-click → Inspect → Accessibility tab

12. IMPORTANT INTERVIEW Q&A
================================================================================

Q1: When should you use a <table> vs CSS Grid/Flexbox for layout?
A: Tables should ONLY be used for tabular data (data with a meaningful
   two-dimensional structure where rows and columns have defined headers).
   CSS Grid/Flexbox should be used for layout. Using tables for layout
   breaks accessibility (screen readers interpret table semantics literally),
   makes responsive design harder, and is poor practice.

Q2: What is the difference between <th> and <td>?
A: <th> is a table HEADER cell — semantically marks the cell as a header for
   the row or column it describes. Rendered bold/centered by default.
   <td> is a table DATA cell — contains the data. The scope attribute on <th>
   (scope="col" or scope="row") tells screen readers which cells the header
   describes, enabling correct reading in both visual and non-visual modes.

Q3: What is the scope attribute on <th>?
A: scope="col" means this header applies to all cells in its column below it.
   scope="row" means this header applies to all cells in its row to the right.
   scope="colgroup"/"rowgroup" applies to a group of columns/rows.
   Without scope, screen readers may fail to associate headers with cells,
   especially when navigating a table cell-by-cell.

Q4: What does border-collapse: collapse do?
A: By default (border-collapse: separate), adjacent cell borders are drawn
   separately, creating a double border. border-collapse: collapse merges
   adjacent borders into one shared border, which is usually the desired
   visual appearance. It also affects border-spacing (irrelevant when collapsed).

Q5: How do colspan and rowspan work?
A: colspan="n" makes a cell span n consecutive columns. rowspan="n" makes it
   span n consecutive rows. The rows and columns "consumed" by the spanning
   cell must NOT have cells in those positions — they are simply omitted from
   the HTML. The sum of all colspans in a row must equal the total column count.

Q6: What is the purpose of <thead>, <tbody>, and <tfoot>?
A: They group table rows semantically and provide functional benefits:
   <thead> marks header rows — they may be repeated on each printed page and
   can be made sticky with CSS. <tbody> marks data rows — can be multiple per
   table for row grouping. <tfoot> marks summary rows — always displayed after
   <tbody> regardless of HTML position. Screen readers use them for context.

Q7: How do you make a table accessible?
A: (1) <caption> describing what the table shows.
   (2) <th> elements with scope="col" for column headers, scope="row" for row headers.
   (3) For complex tables: id on each <th> and headers attribute on <td>
       listing the ids of all applicable headers.
   (4) Avoid using tables for layout; if legacy layout table, use role="presentation".
   (5) Ensure the table is readable in linearized order (screen readers read row by row).

Q8: What is the difference between <caption> and the title attribute on <table>?
A: <caption> is a visible title displayed above/below the table, read by screen
   readers before the table content. title attribute on <table> creates a tooltip
   (hover-only), which is inaccessible to keyboard users and most mobile users.
   Always use <caption>; title attribute should not be relied upon for accessibility.

Q9: How do you make a table responsive?
A: Best approach: wrap the table in a div with overflow-x: auto and make it
   a focusable scrollable region. Alternative: use CSS to "stack" cells on mobile
   (display: block on all table elements, use data-label attributes with ::before
   pseudo-elements to show the column header next to each value in card layout).
   Avoid hiding columns unless they are truly non-essential.

Q10: What is table-layout: fixed and when should you use it?
A: With table-layout: auto (default), the browser scans all content to determine
   column widths — slow for large tables. With table-layout: fixed, column widths
   are determined by the first row only (or explicit widths on <col>) — much
   faster rendering. Use fixed when you have many rows, need predictable column
   widths, or need text-overflow: ellipsis on cells (requires fixed width).
