1. OVERVIEW: CANVAS vs SVG
================================================================================

Both allow 2D graphics in the browser, but they work very differently:

Feature           Canvas                    SVG
-----------       ----------------------    -------------------------
Type              Raster (pixel-based)       Vector (math-based)
DOM               No (single element)        Yes (each shape = element)
Scalability       Degrades at high DPI/zoom  Perfect at any size
Interactivity     Manual (hit detection)     Built-in (CSS/JS events)
Animation         requestAnimationFrame      CSS/JS animation on elements
Memory            Low (flat bitmap)          Higher (DOM nodes per shape)
Text rendering    Low quality (bitmap)       High quality (vector)
Export            PNG/JPEG bitmap            SVG, PDF (lossless)
Accessibility     Poor (requires work)       Better (title/desc, ARIA)
Browser support   IE9+                       IE9+ (inline); IE8+ (file)
Best for          Games, image manipulation  Icons, charts, UI illustrations

2. THE <canvas> ELEMENT
================================================================================

HTML:
  <canvas id="myCanvas" width="800" height="400">
    Fallback content for browsers that don't support canvas.
  </canvas>

Attributes:
  width   — Intrinsic width in CSS pixels (default: 300)
  height  — Intrinsic height in CSS pixels (default: 150)

IMPORTANT: Separate size from display size:
  <!-- Intrinsic (buffer) size: 200x100 -->
  <canvas id="c" width="200" height="100"
          style="width: 400px; height: 200px;">
  </canvas>
  CSS width/height scales the canvas element; canvas width/height sets the
  actual pixel buffer. Setting them differently results in stretched graphics.

  For HiDPI/Retina displays:
  const canvas = document.getElementById('c');
  const dpr = window.devicePixelRatio || 1;
  // Set CSS size (display)
  canvas.style.width = '400px';
  canvas.style.height = '200px';
  // Set buffer size (2x for retina)
  canvas.width = 400 * dpr;
  canvas.height = 200 * dpr;
  // Scale context to match
  const ctx = canvas.getContext('2d');
  ctx.scale(dpr, dpr);

Getting the rendering context:
  const ctx = canvas.getContext('2d');            // 2D drawing
  const gl  = canvas.getContext('webgl');         // WebGL 1
  const gl2 = canvas.getContext('webgl2');        // WebGL 2
  const bm  = canvas.getContext('bitmaprenderer'); // ImageBitmap
  
  if (!ctx) { /* fallback — browser doesn't support canvas */ }

3. CANVAS 2D DRAWING API
================================================================================

COORDINATE SYSTEM:
  Origin (0,0) is TOP-LEFT
  X increases to the right
  Y increases DOWNWARD (opposite of math convention)

DRAWING RECTANGLES:
  // Fill rectangle
  ctx.fillStyle = '#3b82f6';
  ctx.fillRect(x, y, width, height);

  // Stroke rectangle
  ctx.strokeStyle = '#1d4ed8';
  ctx.lineWidth = 2;
  ctx.strokeRect(x, y, width, height);

  // Clear rectangle (make transparent)
  ctx.clearRect(x, y, width, height);

DRAWING PATHS:
  ctx.beginPath();          // Start new path
  ctx.moveTo(50, 50);       // Lift pen and move to
  ctx.lineTo(150, 50);      // Draw line to
  ctx.lineTo(100, 120);     // Draw line to
  ctx.closePath();           // Close path (line to beginPath point)
  ctx.fill();                // Fill the path
  ctx.stroke();              // Stroke the path

DRAWING ARCS AND CIRCLES:
  ctx.beginPath();
  // arc(x, y, radius, startAngle, endAngle, anticlockwise)
  // Angles in radians: 0 = right; Math.PI/2 = bottom; Math.PI = left
  ctx.arc(100, 100, 50, 0, Math.PI * 2);  // Full circle
  ctx.fillStyle = 'coral';
  ctx.fill();

  // Semicircle
  ctx.beginPath();
  ctx.arc(200, 100, 50, 0, Math.PI);     // Half circle (bottom)
  ctx.stroke();

CURVES:
  // Quadratic Bezier
  ctx.beginPath();
  ctx.moveTo(50, 200);
  ctx.quadraticCurveTo(200, 50, 350, 200);  // (cpX, cpY, x, y)
  ctx.stroke();

  // Cubic Bezier
  ctx.beginPath();
  ctx.moveTo(50, 200);
  ctx.bezierCurveTo(150, 50, 250, 350, 350, 200);  // (cp1X, cp1Y, cp2X, cp2Y, x, y)
  ctx.stroke();

STYLES:
  ctx.fillStyle   = '#ff0000';           // Color
  ctx.fillStyle   = 'rgba(255,0,0,0.5)'; // Semi-transparent
  ctx.strokeStyle = '#0000ff';
  ctx.lineWidth   = 4;
  ctx.lineCap     = 'round';    // butt | round | square
  ctx.lineJoin    = 'round';    // miter | round | bevel
  ctx.globalAlpha = 0.8;        // Opacity for all drawing (0-1)
  ctx.globalCompositeOperation = 'source-over';  // Blending mode

GRADIENTS:
  // Linear gradient
  const grad = ctx.createLinearGradient(0, 0, 200, 0);
  grad.addColorStop(0, 'blue');
  grad.addColorStop(0.5, 'white');
  grad.addColorStop(1, 'red');
  ctx.fillStyle = grad;
  ctx.fillRect(0, 0, 200, 100);

  // Radial gradient
  const radGrad = ctx.createRadialGradient(100, 100, 10, 100, 100, 50);
  radGrad.addColorStop(0, 'white');
  radGrad.addColorStop(1, 'black');
  ctx.fillStyle = radGrad;

TEXT:
  ctx.font = 'bold 24px Arial, sans-serif';
  ctx.textAlign    = 'center';   // start | end | left | right | center
  ctx.textBaseline = 'middle';   // top | hanging | middle | alphabetic | bottom
  ctx.fillStyle = 'black';
  ctx.fillText('Hello Canvas', x, y);
  ctx.strokeText('Outlined Text', x, y);

  // Measure text
  const metrics = ctx.measureText('Hello');
  console.log(metrics.width);  // Width in pixels

IMAGES:
  const img = new Image();
  img.src = 'photo.jpg';
  img.onload = () => {
    // Draw image at (x, y)
    ctx.drawImage(img, 0, 0);
    // Draw scaled image
    ctx.drawImage(img, 0, 0, 200, 150);
    // Draw cropped and scaled (9 params)
    ctx.drawImage(img, sx, sy, sw, sh, dx, dy, dw, dh);
  };

TRANSFORMS:
  ctx.save();                // Save current transform state
  ctx.translate(100, 100);   // Move origin
  ctx.rotate(Math.PI / 4);   // Rotate 45°
  ctx.scale(2, 2);           // Scale 2x
  ctx.transform(a, b, c, d, e, f);  // Arbitrary matrix
  ctx.setTransform(1, 0, 0, 1, 0, 0); // Reset to identity
  ctx.restore();             // Restore saved state

CLIPPING:
  ctx.save();
  ctx.beginPath();
  ctx.arc(100, 100, 50, 0, Math.PI * 2);
  ctx.clip();                // Everything drawn after is clipped to circle
  ctx.drawImage(img, 50, 50, 100, 100);
  ctx.restore();

PIXEL MANIPULATION:
  // Get pixel data
  const imageData = ctx.getImageData(x, y, width, height);
  const pixels = imageData.data;  // Uint8ClampedArray [r,g,b,a, r,g,b,a, ...]

  // Invert colors
  for (let i = 0; i < pixels.length; i += 4) {
    pixels[i]   = 255 - pixels[i];     // R
    pixels[i+1] = 255 - pixels[i+1];   // G
    pixels[i+2] = 255 - pixels[i+2];   // B
    // pixels[i+3] = alpha (unchanged)
  }
  ctx.putImageData(imageData, x, y);

  // Create ImageData
  const newData = ctx.createImageData(100, 100);

EXPORT:
  const pngDataUrl  = canvas.toDataURL('image/png');
  const jpegDataUrl = canvas.toDataURL('image/jpeg', 0.8);  // 80% quality
  
  // Download
  const a = document.createElement('a');
  a.download = 'canvas.png';
  a.href = canvas.toDataURL();
  a.click();
  
  // Blob (for FormData upload)
  canvas.toBlob((blob) => {
    const formData = new FormData();
    formData.append('image', blob, 'canvas.png');
  }, 'image/png');

4. CANVAS ANIMATIONS
================================================================================

Basic animation loop using requestAnimationFrame:
  let x = 0;
  let animationId;

  function animate(timestamp) {
    ctx.clearRect(0, 0, canvas.width, canvas.height);  // Clear frame
    
    // Update state
    x = (x + 2) % canvas.width;
    
    // Draw
    ctx.fillStyle = 'coral';
    ctx.fillRect(x, 100, 50, 50);
    
    animationId = requestAnimationFrame(animate);  // Schedule next frame
  }

  animationId = requestAnimationFrame(animate);  // Start

  // Stop animation
  cancelAnimationFrame(animationId);

requestAnimationFrame (rAF) vs setInterval:
  rAF:
    - Synced to display refresh rate (usually 60fps = 16.67ms per frame)
    - Pauses when tab is hidden (saves CPU/battery)
    - Better performance than setInterval
    - Passes timestamp parameter (milliseconds since page load)

  setInterval:
    - Runs on a timer regardless of display sync
    - Continues when tab is hidden (wastes CPU)
    - Can accumulate drift over time

Delta time (frame-rate independent animation):
  let lastTime = 0;
  const SPEED = 100;  // pixels per second

  function animate(timestamp) {
    const deltaTime = (timestamp - lastTime) / 1000;  // seconds
    lastTime = timestamp;
    
    x += SPEED * deltaTime;  // Move at constant speed regardless of FPS
    
    ctx.clearRect(0, 0, canvas.width, canvas.height);
    ctx.fillRect(x, 100, 50, 50);
    
    requestAnimationFrame(animate);
  }

OffscreenCanvas (Web Worker rendering):
  // In main thread:
  const offscreen = canvas.transferControlToOffscreen();
  worker.postMessage({ canvas: offscreen }, [offscreen]);
  
  // In worker:
  self.onmessage = (e) => {
    const canvas = e.data.canvas;
    const ctx = canvas.getContext('2d');
    // Draw without blocking main thread
  };

5. THE <svg> ELEMENT
================================================================================

Inline SVG:
  <svg xmlns="http://www.w3.org/2000/svg"
       viewBox="0 0 100 100"
       width="200"
       height="200"
       aria-label="Red circle"
       role="img">
    <title>Red circle</title>
    <circle cx="50" cy="50" r="40" fill="red" stroke="darkred" stroke-width="3"/>
  </svg>

SVG Attributes:
  xmlns       — Namespace (required for standalone SVG files; optional inline)
  viewBox     — "minX minY width height" — defines coordinate system
  width/height — Display size (CSS units or px)
  preserveAspectRatio — How to fit content when aspect ratio differs

viewBox explained:
  viewBox="0 0 100 100" means:
    - Internal coordinate system is 100x100 units
    - SVG content uses coordinates 0–100
    - Displayed at whatever size width/height specifies
    - This makes SVG fully scalable regardless of display size

preserveAspectRatio:
  "xMidYMid meet" (default) — maintain aspect ratio; letterbox if needed
  "xMidYMid slice" — maintain aspect ratio; crop to fill
  "none" — stretch to fit (distorts)

6. SVG BASIC SHAPES & PATH
================================================================================

<rect> — Rectangle
  <rect x="10" y="10" width="80" height="60"
        rx="5" ry="5"                    ← rounded corners
        fill="#3b82f6" stroke="#1d4ed8" stroke-width="2"/>

<circle> — Circle
  <circle cx="50" cy="50" r="40"
          fill="none" stroke="black" stroke-width="3"/>

<ellipse> — Ellipse
  <ellipse cx="50" cy="50" rx="40" ry="25" fill="coral"/>

<line> — Line
  <line x1="10" y1="10" x2="90" y2="90"
        stroke="black" stroke-width="2" stroke-linecap="round"/>

<polyline> — Open polygon
  <polyline points="10,10 50,80 90,10 130,80"
            fill="none" stroke="blue" stroke-width="2"
            stroke-linejoin="round"/>

<polygon> — Closed polygon
  <polygon points="50,5 90,95 10,95" fill="gold" stroke="orange"/>

<path> — Arbitrary shape (most powerful)
  Path commands (d attribute):
    M x,y     — Move to (absolute)
    m dx,dy   — Move to (relative)
    L x,y     — Line to (absolute)
    l dx,dy   — Line to (relative)
    H x       — Horizontal line to
    V y       — Vertical line to
    C c1x,c1y c2x,c2y x,y — Cubic Bezier
    S c2x,c2y x,y — Smooth cubic Bezier
    Q cx,cy x,y   — Quadratic Bezier
    T x,y         — Smooth quadratic Bezier
    A rx,ry xRot, largeArcFlag, sweepFlag, x,y — Arc
    Z             — Close path

  Example — chevron right arrow:
  <path d="M 10 20 L 30 40 L 10 60" fill="none" stroke="black" stroke-width="3"/>

  Example — heart shape:
  <path d="M 10,30 A 20,20,0,0,1,50,30 A 20,20,0,0,1,90,30
           Q 90,60,50,90 Q 10,60,10,30 Z"
        fill="red"/>

7. SVG TEXT, GRADIENTS, FILTERS
================================================================================

TEXT:
  <text x="50" y="50"
        font-family="Arial, sans-serif"
        font-size="16"
        font-weight="bold"
        text-anchor="middle"    ← start | middle | end
        dominant-baseline="central"  ← alignment
        fill="black">
    Hello SVG
  </text>

  Text along a path:
  <defs>
    <path id="curve" d="M 10,80 Q 95,10 180,80"/>
  </defs>
  <text font-size="12">
    <textPath href="#curve">Text follows the curve path</textPath>
  </text>

GRADIENTS (defined in <defs>):
  <defs>
    <linearGradient id="grad1" x1="0%" y1="0%" x2="100%" y2="0%">
      <stop offset="0%"   stop-color="#3b82f6" stop-opacity="1"/>
      <stop offset="100%" stop-color="#8b5cf6" stop-opacity="1"/>
    </linearGradient>
    
    <radialGradient id="grad2" cx="50%" cy="50%" r="50%">
      <stop offset="0%"   stop-color="white" stop-opacity="1"/>
      <stop offset="100%" stop-color="black" stop-opacity="1"/>
    </radialGradient>
  </defs>
  <rect fill="url(#grad1)" x="0" y="0" width="200" height="50"/>
  <circle fill="url(#grad2)" cx="50" cy="50" r="40"/>

FILTERS (blur, shadow, etc.):
  <defs>
    <filter id="blur">
      <feGaussianBlur stdDeviation="3"/>
    </filter>
    <filter id="shadow">
      <feDropShadow dx="2" dy="2" stdDeviation="2" flood-color="rgba(0,0,0,0.4)"/>
    </filter>
  </defs>
  <rect filter="url(#blur)" .../>
  <rect filter="url(#shadow)" .../>

GROUPS AND TRANSFORMS:
  <g id="group" transform="translate(50,50) rotate(45) scale(2)">
    <rect x="-25" y="-25" width="50" height="50" fill="teal"/>
    <circle cx="0" cy="0" r="10" fill="white"/>
  </g>

CLIP PATH:
  <defs>
    <clipPath id="clip1">
      <circle cx="50" cy="50" r="40"/>
    </clipPath>
  </defs>
  <image href="photo.jpg" x="10" y="10" width="80" height="80"
         clip-path="url(#clip1)"/>

SYMBOLS (reusable components):
  <defs>
    <symbol id="icon-star" viewBox="0 0 24 24">
      <polygon points="12,2 15.09,8.26 22,9.27 17,14.14 18.18,21.02
                        12,17.77 5.82,21.02 7,14.14 2,9.27 8.91,8.26"/>
    </symbol>
  </defs>
  
  <!-- Reuse the symbol -->
  <use href="#icon-star" x="10" y="10" width="24" height="24" fill="gold"/>
  <use href="#icon-star" x="50" y="10" width="48" height="48" fill="orange"/>

8. INLINE SVG vs EXTERNAL SVG
================================================================================

Method 1: INLINE SVG (inside HTML)
  <svg viewBox="0 0 24 24" width="24" height="24">...</svg>
  
  Pros:
    ✓ No additional HTTP request
    ✓ CSS can target SVG internals (fill, stroke, etc.)
    ✓ JavaScript can manipulate SVG DOM
    ✓ ARIA attributes accessible directly
    ✓ Dynamic changes possible (change color on hover/focus)
  Cons:
    ✗ Not cacheable separately
    ✗ Increases HTML size
    ✗ Can't reuse across pages (without JS include)

Method 2: <img src="icon.svg">
  <img src="icon.svg" alt="Settings icon" width="24" height="24">
  
  Pros:
    ✓ Cacheable
    ✓ Simple to use
    ✓ Responsive with width: 100%
  Cons:
    ✗ Cannot style SVG internals with CSS
    ✗ No JavaScript interaction with SVG
    ✗ Requires additional HTTP request (unless cached)

Method 3: CSS background-image: url(icon.svg)
  .icon { background-image: url('icon.svg'); width: 24px; height: 24px; }
  
  Pros:
    ✓ Cacheable; easy for decorative icons
  Cons:
    ✗ Not accessible (no alt text)
    ✗ Cannot style SVG internals

Method 4: <use> with external file (SVG sprite)
  <svg style="display:none">
    <symbol id="icon-home" viewBox="0 0 24 24">...</symbol>
    <symbol id="icon-star" viewBox="0 0 24 24">...</symbol>
  </svg>
  
  <svg width="24" height="24" aria-label="Home" role="img">
    <use href="icons.svg#icon-home"/>
  </svg>
  
  Pros:
    ✓ Single file for all icons (one HTTP request)
    ✓ Individual icons cacheable
    ✓ Accessible
  Cons:
    ✗ External file cannot be styled with page CSS in some browsers

Method 5: <object> (for interactive SVG)
  <object data="animated.svg" type="image/svg+xml" width="200" height="200">
    <img src="fallback.png" alt="...">
  </object>

Recommendation for icon systems:
  - Inline SVG sprites: best for icons used on current page (CSS controllable)
  - External SVG <img>: best for standalone illustrations
  - Data URI SVGs in CSS: for simple, small decorative SVGs

9. CANVAS vs SVG: WHEN TO USE WHICH
================================================================================

USE CANVAS WHEN:
  ✓ Real-time games or simulations (hundreds/thousands of moving objects)
  ✓ Image manipulation (filters, pixel editing, color correction)
  ✓ Particle systems (many simple objects)
  ✓ Video frame processing
  ✓ Complex animations with many elements (canvas redraws whole frame)
  ✓ HiDPI image generation for download
  ✓ WebGL 3D graphics

USE SVG WHEN:
  ✓ Logos, icons, illustrations (need to scale to any size perfectly)
  ✓ Interactive diagrams (hover, click, focus per element)
  ✓ Data visualizations (charts, graphs) where elements need events
  ✓ Text-heavy graphics (SVG renders crisp text at any size)
  ✓ Animations controlled by CSS or GSAP
  ✓ Any graphic that needs to be indexed/accessible/SEO-friendly

GREY AREA:
  Charts: SVG (D3.js) for interactive; Canvas for performance with big data
  Maps: SVG for vector tiles; Canvas for raster tiles (Google Maps)
  Animations: SVG+CSS for simple; Canvas+rAF for complex/real-time

10. CANVAS & SVG ACCESSIBILITY
================================================================================

CANVAS accessibility:
  Canvas is an opaque black box to accessibility tools.
  
  Solutions:
  1. Provide fallback content inside <canvas> tags:
     <canvas width="600" height="400">
       <p>Bar chart showing Q1–Q4 revenue: Q1: $45M, Q2: $52M...</p>
     </canvas>

  2. Add aria attributes:
     <canvas role="img" aria-label="Revenue chart: Q1 $45M, Q2 $52M, Q3 $49M">
     </canvas>

  3. Maintain a parallel accessible DOM tree (hit regions API — experimental)
  
  4. Use a table or list as the accessible alternative; hide canvas from AT:
     <canvas aria-hidden="true">...</canvas>
     <table class="sr-only"><!-- accessible data --></table>

  5. For interactive canvas (games/tools), manage ARIA live regions and
     keyboard events manually.

SVG accessibility:
  SVG is inherently more accessible because it's a DOM tree.
  
  1. Add <title> (short name) and <desc> (longer description):
     <svg role="img" aria-labelledby="chart-title chart-desc">
       <title id="chart-title">Monthly Revenue 2026</title>
       <desc id="chart-desc">Bar chart showing monthly revenue from Jan to Dec 2026</desc>
       ...
     </svg>
  
  2. For decorative SVG (icons without text):
     <svg aria-hidden="true" focusable="false">...</svg>
     focusable="false" needed for IE/Edge (they wrongly make SVG focusable)

  3. For interactive SVG:
     <circle tabindex="0" role="button" aria-label="January: $45M"
             onclick="handleClick()" onkeydown="handleKeydown(event)">
     </circle>

11. PERFORMANCE CONSIDERATIONS
================================================================================

CANVAS performance:
  - Only redraw changed regions (dirty rectangle optimization):
    ctx.clearRect(changedX, changedY, changedW, changedH);
    Only redraw the parts that changed.
  
  - Use multiple layered canvases (background, game objects, UI):
    Background (static) → rarely redrawn
    Game objects → redrawn every frame
    UI/HUD → only redrawn when UI changes
  
  - Use OffscreenCanvas for Web Workers
  
  - Pre-render complex static graphics to an off-screen canvas then
    drawImage from it (faster than re-drawing complex paths every frame)
  
  - Avoid canvas 2D state changes in tight loops (setters are slow):
    Group operations with same fill/stroke color together.
  
  - Use integer coordinates (avoid sub-pixel rendering overhead)

SVG performance:
  - Minimize DOM nodes (group elements with <g>, use <use> for repetition)
  - Avoid too many SVG filters (expensive GPU operations)
  - Use CSS transforms over SVG attribute transforms for animation
    (CSS transforms use the GPU compositor thread)
  - will-change: transform on animated SVG elements hints to browser
  - For hundreds of data points in charts, switch to Canvas

12. IMPORTANT INTERVIEW Q&A
================================================================================

Q1: What is the difference between Canvas and SVG?
A: Canvas is a bitmap (raster) drawing surface — you draw pixels, and the result
   is a flat image. It has no DOM of its own. SVG is vector-based — each shape
   is a DOM element. Canvas is better for games, real-time animation, and image
   manipulation. SVG is better for scalable graphics, icons, interactive charts,
   and anything needing CSS styling or accessibility.

Q2: Is SVG or Canvas better for charts?
A: For interactive charts with few data points: SVG (D3.js uses SVG; each bar/
   line/dot is a DOM element you can hover, click, animate).
   For charts with thousands of data points: Canvas (plotting 10,000 points in
   SVG creates 10,000 DOM nodes — slow. Canvas draws it all as pixels — fast).

Q3: How do you make a Canvas element accessible?
A: (1) Add fallback content inside <canvas> tags (read by screen readers if
   canvas unsupported). (2) Use role="img" and aria-label on the canvas.
   (3) For complex content, provide an accessible alternative (table, list)
   outside the canvas and use aria-hidden="true" on the canvas.
   (4) For interactive canvas, manage keyboard events and ARIA live regions
   manually in JavaScript.

Q4: What is viewBox in SVG and why is it important?
A: viewBox defines SVG's internal coordinate system. viewBox="0 0 100 100"
   means the SVG content uses a 100x100 unit space. The SVG can then be
   displayed at any size (50px, 200px, 1000px) and the content scales
   proportionally. Without viewBox, SVG won't scale with CSS. It's the
   key to making SVG truly resolution-independent.

Q5: What does requestAnimationFrame do and why is it better than setInterval?
A: requestAnimationFrame schedules a callback before the browser's next repaint
   (synchronized to the display refresh rate, usually 60fps). It pauses
   automatically when the tab is hidden (saving CPU/battery). setInterval runs
   on a fixed timer regardless of tab visibility or display sync, causing
   wasted work and choppy animation. rAF produces smoother animations and
   is the standard approach for canvas animation loops.

Q6: How do you handle HiDPI/Retina displays in Canvas?
A: The canvas buffer size must be multiplied by window.devicePixelRatio. Set
   canvas.width/height to logical_size × DPR, set CSS width/height to logical
   size (via style attribute), then ctx.scale(DPR, DPR) so your drawing
   coordinates remain the same. This makes graphics crisp on Retina displays
   where DPR is 2 or 3.

Q7: What is the difference between <svg> inline and <img src="*.svg">?
A: Inline SVG is part of the HTML DOM — CSS can target internal elements
   (change fill colors), JavaScript can manipulate it, and ARIA is directly
   accessible. <img src="*.svg"> is treated as an opaque image — cannot style
   internals with CSS, cannot manipulate with JS, but is cacheable and simple.
   Use inline SVG for icons that change color on interaction; use <img> for
   standalone static illustrations.

Q8: How do you animate SVG?
A: Multiple approaches:
   (1) CSS animation/transition on SVG elements (most performant — GPU composited)
   (2) SMIL (SVG Declarative Animation) — deprecated, avoid
   (3) JavaScript: element.setAttribute() in requestAnimationFrame loop
   (4) Web Animations API: element.animate([{...}], options)
   (5) GSAP (library) — most powerful and consistent cross-browser animation
   For simple animations (color, opacity, transform): CSS. Complex sequences: GSAP.

Q9: What is an SVG sprite and why use it?
A: An SVG sprite is a single SVG file containing multiple symbols (icons) via
   the <symbol> element, referenced with <use href="sprite.svg#icon-name">.
   Benefits: one HTTP request for all icons; icons are cacheable; each can
   have its own viewBox and be used at any size; accessible with ARIA.
   Alternative to font icons and individual SVG files.

Q10: Can you draw text on Canvas? What are its limitations?
A: Yes. ctx.fillText(text, x, y) and ctx.strokeText(). Limitations:
   (1) Text is rendered as pixels — not selectable, not searchable, not
   accessible to screen readers. (2) No built-in text wrapping (must implement
   manually by measuring words). (3) Lower quality than HTML/CSS text especially
   at small sizes or when zoomed. (4) Font loading must be handled manually.
   For accessible text, prefer HTML/SVG over Canvas text.
