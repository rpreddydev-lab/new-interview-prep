1. WHAT IS ARIA?
================================================================================

ARIA (Accessible Rich Internet Applications) is a W3C specification that
defines a set of HTML attributes (roles, properties, states) that can be
added to elements to modify their representation in the accessibility tree.

ARIA does NOT:
  - Change visual appearance
  - Add keyboard behavior
  - Change element semantics in the DOM
  - Make non-focusable elements focusable (tabindex does that)

ARIA DOES:
  - Change what role the element announces to screen readers
  - Add state information (checked, expanded, invalid)
  - Provide labels, descriptions, relationships
  - Control live region announcements

Three attributes of ARIA:
  role            — What the element IS (e.g., role="button", role="dialog")
  aria-*          — Properties and states (e.g., aria-label, aria-expanded)
  (combined)      — Together they define the accessible name, role, state, value

2. THE FIVE RULES OF ARIA
================================================================================

Rule 1 — Don't use ARIA if you can use native HTML
  ✗ <div role="button" tabindex="0">Submit</div>
  ✓ <button type="submit">Submit</button>

Rule 2 — Don't change native semantics unless absolutely necessary
  ✗ <h2 role="tab">Tab Title</h2>   // Destroys heading semantics
  ✓ <div role="tab"><h2>Tab Title</h2></div>  // Preserves both

Rule 3 — All interactive ARIA controls must be keyboard accessible
  If you give an element role="button", you must ensure it's focusable
  (tabindex="0") and responds to Enter and Space keys via JavaScript.
  ARIA does not add keyboard behavior automatically.

Rule 4 — Don't use role="presentation" or aria-hidden="true" on focusable elements
  Hidden but focusable elements create invisible keyboard traps.
  ✗ <button aria-hidden="true">Skip</button>  // Still tab-focusable, silent!
  ✓ Either remove from tab order OR don't hide it

Rule 5 — All interactive elements must have an accessible name
  Screen readers announce the name. Without it, a button may announce as
  just "button" with no context.
  ✓ <button aria-label="Close dialog">X</button>

3. ARIA ROLES — CATEGORIES OVERVIEW
================================================================================

Landmark roles      — Navigable page regions (nav, main, banner, etc.)
Widget roles        — Interactive controls (button, tab, slider, menu, etc.)
Document structure  — Non-interactive document organization (heading, list, table)
Live region roles   — Dynamic content (alert, status, log, timer)
Window roles        — Dialog overlays (dialog, alertdialog)
Abstract roles      — Base categories (not used directly in HTML)

4. LANDMARK ROLES
================================================================================

Landmarks provide navigation shortcuts for screen reader users.
Screen readers let users jump between landmarks with a single key press.

  ARIA role             Equivalent HTML element    Notes
  --------------------  -------------------------  ----------------------------
  role="banner"         <header>                   Top of page header; one per page
  role="navigation"     <nav>                      Nav regions; label each one
  role="main"           <main>                     Primary content; one per page
  role="complementary"  <aside>                    Tangentially related content
  role="contentinfo"    <footer>                   Footer of page; one per page
  role="search"         <search> (HTML5.3)         Search functionality
  role="form"           <form> with label          Form landmark; needs aria-label
  role="region"         <section> with label       Generic region; needs aria-label

Important: When using HTML5 landmark elements (<nav>, <main>, etc.), the
browser maps them to ARIA landmark roles automatically.
Using both is redundant but harmless:
  ✓ <nav>                              // Implicitly role="navigation"
  ✓ <nav aria-label="Primary">        // Labeled for multiple navs
  ✗ <nav role="navigation">           // Redundant but okay
  ✗ <div role="navigation">           // Use <nav> instead

Multiple landmarks of the same type must be labeled:
  <nav aria-label="Primary navigation">
    <!-- main nav links -->
  </nav>
  <nav aria-label="Breadcrumb navigation">
    <!-- breadcrumbs -->
  </nav>

5. WIDGET ROLES
================================================================================

Widget roles define interactive UI components. These require JavaScript to
implement full keyboard behavior and state management.

BUTTON AND LINK:
  role="button"     — Actionable element. Keyboard: Enter and Space activate.
  role="link"       — Navigates somewhere. Keyboard: Enter activates.
  
  <span role="button" tabindex="0"
        onkeydown="if(event.key==='Enter'||event.key===' ') this.click()">
    Custom Button
  </span>

FORM CONTROLS:
  role="textbox"          — Single-line text input
  role="searchbox"        — Search text input (searchbox > textbox for search)
  role="combobox"         — Input + listbox popup (autocomplete dropdowns)
  role="listbox"          — List of selectable options
  role="option"           — An option inside listbox
  role="checkbox"         — Toggle on/off (tristate: checked/unchecked/mixed)
  role="radio"            — One selection from group
  role="radiogroup"       — Group of radio buttons (use <fieldset> or this role)
  role="slider"           — Numeric range control
  role="spinbutton"       — Numeric input with increment/decrement
  role="switch"           — Toggle (like checkbox but on/off semantics)

  <!-- Custom checkbox example -->
  <div role="checkbox" 
       aria-checked="false" 
       tabindex="0"
       aria-label="Subscribe to newsletter">
  </div>
  // JavaScript must toggle aria-checked between "true" and "false"

MENUS:
  role="menu"             — List of actions/commands
  role="menubar"          — Row of menu items (like a desktop app menu bar)
  role="menuitem"         — An option in a menu
  role="menuitemcheckbox" — Checkable menu item
  role="menuitemradio"    — Radio-type menu item

  Keyboard pattern for menus:
    - Arrow keys navigate between items
    - Enter/Space activates
    - Escape closes and returns focus to trigger
    - Home/End go to first/last item

TABS:
  role="tablist"          — Container for tab buttons
  role="tab"              — A single tab button
  role="tabpanel"         — Content associated with a tab
  
  aria-selected="true/false" on tab
  aria-controls="panelId" on tab
  aria-labelledby="tabId" on tabpanel
  
  <div role="tablist" aria-label="Product information">
    <button role="tab" id="tab1" aria-selected="true" 
            aria-controls="panel1">Description</button>
    <button role="tab" id="tab2" aria-selected="false" 
            aria-controls="panel2" tabindex="-1">Reviews</button>
  </div>
  <div role="tabpanel" id="panel1" aria-labelledby="tab1">
    Tab 1 content
  </div>
  <div role="tabpanel" id="panel2" aria-labelledby="tab2" hidden>
    Tab 2 content
  </div>

  Keyboard pattern: Arrow keys switch tabs, Tab moves into panel.

TREE AND GRID:
  role="tree"             — Hierarchical list
  role="treeitem"         — Item in tree
  role="group"            — Container for children of a treeitem
  role="treegrid"         — Grid with expandable rows
  role="grid"             — Interactive table
  role="gridcell"         — Cell in a grid
  role="row"              — A row in grid/tree
  role="rowgroup"         — Group of rows (<thead>, <tbody>, <tfoot>)
  role="columnheader"     — Column header cell in grid
  role="rowheader"        — Row header cell in grid

TOOLTIP AND DIALOG:
  role="tooltip"          — Informational popup triggered by hover/focus
  role="dialog"           — Modal/non-modal dialog
  role="alertdialog"      — Dialog containing critical, timed, or error message

6. DOCUMENT STRUCTURE ROLES
================================================================================

These describe content structure but are not interactive:

  role="heading"        — Heading (use aria-level="1-6")
  role="list"           — Unordered or ordered list
  role="listitem"       — Item in list
  role="table"          — Data table
  role="cell"           — Cell in table
  role="figure"         — Figure (image + caption)
  role="img"            — Image or group of elements forming an image
  role="note"           — Advisory information
  role="definition"     — Definition of a term
  role="term"           — Term being defined
  role="separator"      — Dividing line
  role="presentation"   — Removes element from accessibility tree
  role="none"           — Alias for "presentation"

  <!-- Removing semantics with presentation role -->
  <!-- Use when HTML structure is needed for layout but semantics are unwanted -->
  <table role="presentation">  <!-- Layout table, not data table -->
    <tr><td>Column 1</td><td>Column 2</td></tr>
  </table>

7. LIVE REGION ROLES
================================================================================

Live regions announce dynamic content changes to screen readers without
requiring focus to move to the changed element.

  role="alert"     — Critical, time-sensitive information (errors, confirmations)
    aria-live="assertive" — Interrupts the current announcement immediately
    aria-atomic="true"    — Reads the entire region content

  role="status"    — Non-critical status updates
    aria-live="polite"   — Waits for current announcement to finish

  role="log"       — Chronological sequence (chat log, error log)
    aria-live="polite", aria-relevant="additions text"

  role="timer"     — Countdown or elapsed timer
  role="marquee"   — Scrolling content (not recommended)

  <!-- Alert pattern (form error) -->
  <div role="alert" id="error-msg" aria-live="assertive">
    <!-- Inject error text here via JavaScript -->
  </div>
  
  <!-- Status pattern (form success) -->
  <div role="status" aria-live="polite" id="status-msg">
    <!-- Inject success text here via JavaScript -->
  </div>

  How live regions work:
    1. Element must exist in DOM before being updated (not created dynamically)
    2. Screen reader monitors for content changes
    3. When content changes, announces based on aria-live policy

  aria-live values:
    off         — Don't announce (default for most elements)
    polite      — Announce after current utterance finishes
    assertive   — Announce immediately, interrupting current speech

  aria-atomic="true":
    Reads the entire live region as one unit when any part changes.
    Without it, only the changed portion is read.

  aria-relevant (rarely needed):
    additions   — Announce when nodes are added (default)
    removals    — Announce when nodes are removed
    text        — Announce text content changes
    all         — All changes
    additions text — (default value)

8. ESSENTIAL ARIA PROPERTIES
================================================================================

LABELING:
  aria-label="string"
    Provides an accessible name directly on the element.
    Use when no visible label exists or label text would be redundant.
    
    <button aria-label="Close dialog">
      <svg aria-hidden="true">...</svg>
    </button>

  aria-labelledby="id1 id2"
    References one or more element IDs as the accessible name.
    Can concatenate multiple IDs (space-separated).
    Takes priority over aria-label.
    
    <h2 id="modal-title">Confirm Delete</h2>
    <dialog aria-labelledby="modal-title">...</dialog>

  aria-describedby="id"
    References elements that provide additional description (not the name).
    Read after the name and role in most screen readers.
    
    <input id="pwd" type="password" aria-describedby="pwd-hint">
    <p id="pwd-hint">Must be 8+ characters with one number</p>

RELATIONSHIPS:
  aria-controls="id"
    Indicates this element controls another element.
    Used on buttons that expand/collapse, tabs controlling panels.
    
  aria-owns="id"
    Indicates ownership when DOM structure doesn't reflect it.
    Use sparingly — usually a sign of poor DOM structure.
    
  aria-flowto="id"
    Provides an alternative reading order. Rarely needed.

CONTENT INFO:
  aria-haspopup="true|menu|listbox|tree|grid|dialog"
    Indicates element will open a popup.
    
  aria-autocomplete="none|inline|list|both"
    For comboboxes and textboxes with autocomplete behavior.
    
  aria-placeholder="text"
    Provides hint text (use HTML placeholder attribute instead).
    
  aria-valuemin / aria-valuemax / aria-valuenow / aria-valuetext
    For sliders, spinbuttons, scrollbars.
    
    <div role="slider" aria-valuemin="0" aria-valuemax="100"
         aria-valuenow="50" aria-valuetext="50 percent">
    </div>

  aria-rowcount / aria-colcount / aria-rowindex / aria-colindex
    For virtual (partially rendered) grids and tables.
    
  aria-setsize / aria-posinset
    For virtual lists (when not all items are in DOM).
    
    <li role="option" aria-setsize="100" aria-posinset="5">Item 5 of 100</li>

9. ESSENTIAL ARIA STATES
================================================================================

Boolean states toggle on/off:

  aria-hidden="true/false"
    Removes element and all children from accessibility tree.
    Does NOT remove from DOM or prevent keyboard focus.
    Use on decorative images, icon fonts, hidden UI sections.
    
    <svg aria-hidden="true" focusable="false">...</svg>
    <div aria-hidden="true"><!-- off-screen decorative -->
    
    WARNING: Never set aria-hidden on an element that receives focus.

  aria-disabled="true/false"
    Communicates disabled state without removing from focus order.
    Different from HTML disabled attribute (which removes focus).
    Use when you want disabled but still keyboard-discoverable.
    
  aria-invalid="true/false/grammar/spelling"
    Indicates the field value is invalid.
    
    <input aria-invalid="true" aria-describedby="error1">
    <span id="error1" role="alert">Invalid email format</span>

  aria-required="true/false"
    Indicates field is required. Supplement with HTML required attribute.
    
  aria-checked="true/false/mixed"
    State of checkbox, menuitemcheckbox, switch.
    "mixed" = indeterminate state.
    
  aria-selected="true/false"
    For option, tab, row, treeitem — indicates current selection.
    
  aria-pressed="true/false/mixed"
    For toggle buttons.
    
    <button aria-pressed="false">Dark Mode</button>
    // JavaScript toggles between "true" and "false"

  aria-expanded="true/false"
    Whether a controlled element is expanded.
    Use on buttons controlling accordions, menus, trees.
    
    <button aria-expanded="false" aria-controls="menu1">Menu</button>
    <ul id="menu1" hidden><!-- items --></ul>
    
  aria-current="page/step/location/date/time/true/false"
    Indicates the current item in a set.
    Most commonly: aria-current="page" on active nav links.
    
    <nav>
      <a href="/home" aria-current="page">Home</a>
      <a href="/about">About</a>
    </nav>

10. ACCESSIBLE NAME COMPUTATION
================================================================================

Screen readers announce an element's accessible name. Browsers compute it
using the Accessible Name Computation algorithm (in priority order):

For most elements:
  1. aria-labelledby (concatenates referenced elements' text)
  2. aria-label (explicit string)
  3. Native semantics (button text content, img alt, input label, etc.)
  4. title attribute (last resort — also shown as tooltip)

For images:
  1. aria-labelledby
  2. aria-label
  3. alt attribute
  4. title attribute
  5. Empty alt="" → ignored (decorative)
  6. No alt attribute → announces filename (bad)

For inputs:
  1. aria-labelledby
  2. aria-label
  3. <label for="id"> association
  4. <label> wrapping the input
  5. title attribute
  6. placeholder (NOT accessible name — do not rely on it)

Examples:
  <!-- Name from content -->
  <button>Save Document</button>  
  // Name: "Save Document"
  
  <!-- Name from aria-label (overrides content) -->
  <button aria-label="Save document to cloud">Save</button>
  // Name: "Save document to cloud"
  
  <!-- Name from aria-labelledby (highest priority) -->
  <span id="lbl">Upload Profile Photo</span>
  <input type="file" aria-labelledby="lbl">
  // Name: "Upload Profile Photo"
  
  <!-- Multiple IDs concatenated -->
  <span id="f">First</span> <span id="l">Last</span>
  <button aria-labelledby="f l">Submit</button>
  // Name: "First Last"
  
  <!-- Name from label association -->
  <label for="email">Email address</label>
  <input id="email" type="email">
  // Name: "Email address"

11. PRACTICAL PATTERNS WITH ARIA
================================================================================

TOGGLE BUTTON:
  <button id="menu-btn" 
          aria-expanded="false" 
          aria-controls="nav-menu"
          aria-label="Toggle navigation menu">
    ☰
  </button>
  <nav id="nav-menu" hidden>
    <!-- navigation links -->
  </nav>
  
  <script>
    const btn = document.getElementById('menu-btn');
    const menu = document.getElementById('nav-menu');
    btn.addEventListener('click', () => {
      const isExpanded = btn.getAttribute('aria-expanded') === 'true';
      btn.setAttribute('aria-expanded', String(!isExpanded));
      menu.hidden = isExpanded;
    });
  </script>

MODAL DIALOG:
  <div role="dialog"
       aria-modal="true"
       aria-labelledby="dialog-title"
       aria-describedby="dialog-desc"
       id="confirm-dialog">
    <h2 id="dialog-title">Confirm Action</h2>
    <p id="dialog-desc">Are you sure you want to delete this item?</p>
    <button id="dialog-confirm">Delete</button>
    <button id="dialog-cancel">Cancel</button>
  </div>
  // Also: trap focus inside, move focus to dialog on open,
  // return focus to trigger on close, Escape key closes

ACCORDION:
  <div class="accordion">
    <h3>
      <button aria-expanded="false" aria-controls="section1">
        Section One
      </button>
    </h3>
    <div id="section1" hidden role="region" aria-labelledby="btn1">
      <p>Content here...</p>
    </div>
  </div>

COMBOBOX (autocomplete):
  <label for="fruit-input">Fruit</label>
  <input id="fruit-input"
         type="text"
         role="combobox"
         autocomplete="off"
         aria-expanded="false"
         aria-autocomplete="list"
         aria-controls="fruit-listbox"
         aria-activedescendant="">
  <ul id="fruit-listbox" role="listbox" aria-label="Fruits" hidden>
    <li id="opt1" role="option">Apple</li>
    <li id="opt2" role="option">Banana</li>
    <li id="opt3" role="option">Cherry</li>
  </ul>

BREADCRUMB:
  <nav aria-label="Breadcrumb">
    <ol>
      <li><a href="/">Home</a></li>
      <li><a href="/products">Products</a></li>
      <li><a href="/products/shoes" aria-current="page">Shoes</a></li>
    </ol>
  </nav>

SKIP LINK:
  <!-- First element inside <body> -->
  <a href="#main-content" class="skip-link">Skip to main content</a>
  
  <main id="main-content" tabindex="-1">
    <!-- main content -->
  </main>
  
  CSS (visually hidden until focused):
  .skip-link {
    position: absolute;
    top: -40px;
    left: 0;
    padding: 8px;
    background: #000;
    color: #fff;
    z-index: 9999;
  }
  .skip-link:focus {
    top: 0;
  }

12. IMPORTANT INTERVIEW Q&A
================================================================================

Q1: What is ARIA and when should you use it?
A: ARIA (Accessible Rich Internet Applications) is a set of HTML attributes
   that modify the accessibility tree — how screen readers understand page
   structure and interactive components. You should use ARIA when native HTML
   semantics are insufficient, such as for custom widgets (tabs, dropdowns,
   sliders, dialogs). The first rule of ARIA is: don't use it if native HTML
   provides the needed semantics. ARIA adds roles, properties, and states but
   does NOT add keyboard behavior or visual changes.

Q2: What is the difference between aria-label and aria-labelledby?
A: Both provide an accessible name. aria-label="string" sets a name directly
   on the element as an attribute string — used when there's no visible text
   label. aria-labelledby="id" references another element's text content as
   the name — used when a visible element already serves as the label. aria-
   labelledby takes priority and can reference multiple IDs (space-separated)
   to concatenate names. aria-labelledby is preferred when a visible label
   exists because it links to existing text rather than duplicating it.

Q3: What is the difference between aria-hidden and display:none?
A: display:none and visibility:hidden remove elements from both visual
   rendering AND the accessibility tree. aria-hidden="true" removes the
   element from the accessibility tree only — it remains visible on screen
   and still receives keyboard focus. This is useful for decorative icons,
   visual flourishes, or duplication. Critical: Never put aria-hidden="true"
   on an element that can receive keyboard focus, as it becomes a silent
   keyboard trap.

Q4: What are ARIA live regions and when do you use them?
A: Live regions announce dynamic content changes to screen readers without
   the user's focus moving to the changed area. role="alert" / aria-live=
   "assertive" announces immediately (for errors, critical messages). role=
   "status" / aria-live="polite" announces after the current speech finishes
   (for success messages, loading indicators). The live region element must
   exist in the DOM before content is injected — not created dynamically.
   aria-atomic="true" reads the entire region, not just changed parts.

Q5: What is aria-expanded used for?
A: aria-expanded indicates whether an element (typically a button) controls
   another element that is currently shown (true) or hidden (false). Used on
   accordion triggers, navigation toggles, dropdown menus, tree nodes. The
   button should also have aria-controls referencing the controlled element's
   ID. JavaScript must toggle aria-expanded between "true" and "false" when
   the state changes, and the controlled element should use hidden or CSS
   display to show/hide accordingly.

Q6: What is the difference between role="button" and <button>?
A: A native <button> element provides: keyboard focus by default, activation
   by Enter and Space, correct accessible role ("button"), integration with
   forms, disabled state via attribute, and programmatic focus management.
   role="button" on a <div> or <span> only adds the accessibility tree role
   — you must manually add tabindex="0" for focusability, JavaScript for
   keyboard event handling (Enter, Space), and manually manage disabled state.
   Native <button> is always preferable.

Q7: What is aria-current used for?
A: aria-current indicates the current item within a set or container. The
   most common use is aria-current="page" on the active navigation link —
   this tells screen readers "you are currently on this page." Other values:
   "step" (current step in a multi-step process), "location" (current page
   in a breadcrumb), "date" (current date in a calendar), "time" (current
   time indicator). It's preferred over aria-selected for navigation because
   it implies a concept of "current location" rather than "selection."

Q8: How do you make a custom checkbox accessible?
A: Use role="checkbox" on the element, tabindex="0" to make it focusable,
   aria-label or associated label for the accessible name, aria-checked=
   "false" initially (toggle to "true"/"false" via JavaScript on click and
   keydown for Space key), and aria-checked="mixed" for indeterminate state.
   The element should be inside or associated with a <label> or use
   aria-label. For groups of checkboxes, wrap in role="group" with an
   aria-labelledby pointing to a group label. Better approach: use a visually
   styled native <input type="checkbox"> with CSS to customize appearance.

Q9: What is aria-describedby and how does it differ from aria-labelledby?
A: aria-labelledby provides the accessible name (what the element is called).
   aria-describedby provides additional descriptive information announced
   AFTER the name and role. For example, a password input might have a label
   ("Password") via aria-labelledby and a description ("Must be 8+ characters")
   via aria-describedby. Screen readers say: "[name], [role], [description]".
   Multiple IDs can be space-separated. aria-describedby is ideal for hints,
   error messages, format instructions.

Q10: What are landmark roles and why are they important?
A: Landmark roles identify major navigational regions on a page: banner
   (header), navigation (nav), main (primary content), complementary (aside),
   contentinfo (footer), search, form, and region. Screen reader users can
   jump directly between landmarks using shortcut keys (D in NVDA, R in JAWS)
   rather than reading the entire page sequentially. Native HTML5 elements
   (<nav>, <main>, <header>, <footer>, <aside>, <section>) map to ARIA
   landmark roles automatically. When multiple same-type landmarks exist
   (e.g., two <nav> elements), each should have an aria-label to distinguish.
