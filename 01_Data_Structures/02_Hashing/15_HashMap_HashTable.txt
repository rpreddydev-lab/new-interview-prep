----------------------------------------------------------------
WHAT IS A HASHMAP?
----------------------------------------------------------------
A HashMap is a key-value store that uses hashing to achieve
O(1) average-case insert, delete, and lookup.

  Key properties (Java HashMap):
    - Keys must be unique
    - Values can be duplicated
    - One null key allowed
    - Null values allowed
    - NOT thread-safe
    - Does NOT maintain insertion or sorted order
    - Backed by an array of LinkedList/TreeNode buckets

  Visualization:
    Key       Hash % 8   Bucket
    "alice"   2          buckets[2] -> ("alice", 30)
    "bob"     5          buckets[5] -> ("bob", 25)
    "carol"   2          buckets[2] -> ("alice",30) -> ("carol",22)

----------------------------------------------------------------
HASHMAP vs HASHTABLE vs CONCURRENTHASHMAP
----------------------------------------------------------------
  Feature              HashMap       Hashtable     ConcurrentHashMap
  ---------------------------------------------------------------
  Thread safety        No            Yes (synced)  Yes (segment lock)
  Null key             1 null key    Not allowed   Not allowed
  Null value           Allowed       Not allowed   Not allowed
  Performance          Fast          Slow          Moderate
  Iterator             Fail-fast     Fail-safe     Weakly consistent
  Java version         Java 2        Legacy        Java 5+
  Use in interviews    Yes           Never         Concurrency topics

  Hashtable is legacy — avoid it. Use ConcurrentHashMap for
  thread-safe access in production. Use HashMap otherwise.

----------------------------------------------------------------
JAVA HASHMAP — ALL KEY METHODS
----------------------------------------------------------------
  Map<String, Integer> map = new HashMap<>();

  PUT / GET / REMOVE:
    map.put(key, value)             -- O(1) avg, insert or update
    map.get(key)                    -- O(1) avg, null if absent
    map.remove(key)                 -- O(1) avg
    map.remove(key, value)          -- remove only if value matches

  EXISTENCE CHECKS:
    map.containsKey(key)            -- O(1) avg
    map.containsValue(value)        -- O(n) -- linear scan

  SIZE:
    map.size()                      -- O(1)
    map.isEmpty()                   -- O(1)

  DEFAULT VALUE PATTERNS:
    map.getOrDefault(key, 0)        -- get value or 0 if absent
    map.putIfAbsent(key, value)     -- put only if key missing
    map.computeIfAbsent(key, k -> new ArrayList<>())
                                    -- compute and store if absent
    map.getOrDefault + put pattern for frequency counting:
      map.put(key, map.getOrDefault(key, 0) + 1)
    Or simpler:
      map.merge(key, 1, Integer::sum)

  ITERATION:
    for (Map.Entry<String, Integer> entry : map.entrySet())
      entry.getKey(), entry.getValue()

    for (String key : map.keySet())
    for (Integer val : map.values())

  UPDATE PATTERNS:
    map.put(key, map.get(key) + 1)        -- update existing
    map.replace(key, newValue)            -- replace if key exists
    map.replace(key, oldVal, newVal)      -- conditional replace
    map.compute(key, (k, v) -> v == null ? 1 : v + 1)

  BULK OPERATIONS:
    map.putAll(otherMap)
    map.clear()

  STREAM-FRIENDLY:
    map.forEach((k, v) -> process(k, v))
    map.entrySet().stream()
       .sorted(Map.Entry.comparingByValue())
       .collect(Collectors.toList())

----------------------------------------------------------------
INTERNAL IMPLEMENTATION (Java 8+)
----------------------------------------------------------------
  Backing array: Node<K,V>[] table
  Default initial capacity: 16
  Default load factor: 0.75
  Resize trigger: size > capacity * 0.75
  Resize action: double capacity, rehash all entries

  Bucket structure evolution:
    Empty bucket:    null
    1-7 entries:     LinkedList of Node<K,V>
    8+ entries:      Red-Black Tree (TreeNode<K,V>)
    Drop below 6:    Convert back to LinkedList

  Hash spreading (Java HashMap.hash()):
    (key == null) ? 0 : (h = key.hashCode()) ^ (h >>> 16)
    XOR upper 16 bits into lower 16 bits to improve distribution.

  Index computation:
    (capacity - 1) & hash   -- fast modulo using power-of-2 capacity

----------------------------------------------------------------
LINKEDHASHMAP — ORDERED HASHMAP
----------------------------------------------------------------
  LinkedHashMap<K, V> maintains insertion order (or access order).
  Extends HashMap and adds a doubly linked list through all entries.

  Insertion order (default):
    Map<String, Integer> map = new LinkedHashMap<>();
    Iteration visits entries in the order they were inserted.

  Access order (for LRU Cache):
    Map<Integer, Integer> lru =
        new LinkedHashMap<>(16, 0.75f, true);
    Most recently accessed entry moves to the end.
    Override removeEldestEntry() to auto-evict.

  LRU Cache with LinkedHashMap:
    class LRUCache extends LinkedHashMap<Integer, Integer> {
      int capacity;
      LRUCache(int cap) {
        super(cap, 0.75f, true);  // accessOrder = true
        this.capacity = cap;
      }
      int get(int key) {
        return super.getOrDefault(key, -1);
      }
      void put(int key, int val) {
        super.put(key, val);
      }
      protected boolean removeEldestEntry(Map.Entry e) {
        return size() > capacity;
      }
    }
  Time: O(1) get and put   Space: O(capacity)

  Extra cost vs HashMap:
    O(n) extra space for the doubly linked list pointers
    Slightly slower due to list maintenance on each access

----------------------------------------------------------------
TREEMAP — SORTED HASHMAP
----------------------------------------------------------------
  TreeMap<K, V> implements SortedMap and NavigableMap.
  Backed by a Red-Black Tree. All operations are O(log n).

  TreeMap<String, Integer> map = new TreeMap<>();

  Sorted access:
    map.firstKey()              -- smallest key
    map.lastKey()               -- largest key
    map.floorKey(key)           -- largest key <= given key
    map.ceilingKey(key)         -- smallest key >= given key
    map.lowerKey(key)           -- largest key < given key
    map.higherKey(key)          -- smallest key > given key
    map.headMap(toKey)          -- keys < toKey
    map.tailMap(fromKey)        -- keys >= fromKey
    map.subMap(from, to)        -- keys in [from, to)
    map.descendingMap()         -- reverse order view

  Use TreeMap when:
    - You need keys in sorted order
    - You need range queries (headMap, tailMap, subMap)
    - You need floor/ceiling lookups
    - You need the min or max key in O(log n)

  HashMap vs TreeMap:
    HashMap:  O(1) avg insert/get, unordered
    TreeMap:  O(log n) insert/get, sorted, range queries

KEY INTERVIEW PATTERNS USING HASHMAP
----------------------------------------------------------------

  1. FREQUENCY COUNTING
     Map<Character, Integer> freq = new HashMap<>();
     for (char c : s.toCharArray())
       freq.merge(c, 1, Integer::sum);
     Use case: anagram check, top-k frequent, ransom note

  2. TWO SUM PATTERN
     Map<Integer, Integer> seen = new HashMap<>();
     for (int i = 0; i < nums.length; i++):
       int complement = target - nums[i];
       if (seen.containsKey(complement))
         return new int[]{seen.get(complement), i};
       seen.put(nums[i], i);
     Time: O(n)   Space: O(n)

  3. PREFIX SUM + HASHMAP (Subarray Sum Equals K)
     Map<Integer, Integer> prefixCount = new HashMap<>();
     prefixCount.put(0, 1);   // empty prefix
     int sum = 0, count = 0;
     for (int num : nums):
       sum += num;
       count += prefixCount.getOrDefault(sum - k, 0);
       prefixCount.merge(sum, 1, Integer::sum);
     Time: O(n)   Space: O(n)

  4. GROUP BY KEY (Group Anagrams)
     Map<String, List<String>> groups = new HashMap<>();
     for (String s : strs):
       char[] arr = s.toCharArray(); Arrays.sort(arr);
       String key = new String(arr);
       groups.computeIfAbsent(key, k -> new ArrayList<>()).add(s);
     Time: O(n * k log k)   Space: O(n * k)

  5. MEMOIZATION (Top-Down DP)
     Map<Integer, Long> memo = new HashMap<>();
     long fib(int n):
       if (n <= 1) return n;
       if (memo.containsKey(n)) return memo.get(n);
       long result = fib(n-1) + fib(n-2);
       memo.put(n, result);
       return result;

  6. INDEX MAP (for binary search / sliding window problems)
     Store last seen index of each element:
     Map<Integer, Integer> lastIndex = new HashMap<>();
     for (int i = 0; i < nums.length; i++):
       if (lastIndex.containsKey(nums[i]))
         // use lastIndex.get(nums[i])
       lastIndex.put(nums[i], i);

INTERVIEW QUESTIONS
----------------------------------------------------------------

Q: What is the difference between HashMap and LinkedHashMap?
A: HashMap does not guarantee any ordering of keys.
   LinkedHashMap maintains insertion order (default) or access
   order (when constructed with accessOrder=true). Both have
   O(1) average operations. LinkedHashMap uses slightly more
   memory due to the doubly linked list connecting all entries.
   Use LinkedHashMap for LRU Cache, ordered output, or when
   predictable iteration order matters.

Q: How would you implement Insert, Delete, and GetRandom
   all in O(1)?
A: Use a HashMap (value -> index) and an ArrayList (values).
   Insert: add to ArrayList, store index in map.
   Delete: swap with last element, update map, remove last.
   GetRandom: return ArrayList.get(random index).
   The ArrayList enables O(1) random access; the HashMap
   enables O(1) lookup and O(1) swap-based deletion.

Q: What is the time complexity of HashMap.containsValue()?
A: O(n) -- it performs a linear scan through all buckets
   and all entries. There is no index on values, only on keys.
   If you need O(1) value lookup, maintain a reverse map.

Q: How does map.compute() differ from map.put()?
A: put(k, v) unconditionally stores v for key k.
   compute(k, (k, oldVal) -> newVal) calls a function with
   the current value (null if absent) and stores the result.
   If the function returns null, the key is removed.
   Use compute for atomic read-modify-write operations.

Q: Why is HashMap not thread-safe and what happens under
   concurrent modification?
A: HashMap's resize (rehash) operation is not atomic. Two
   threads resizing simultaneously can create a cycle in the
   bucket's linked list (in Java 7), causing an infinite loop
   on get(). In Java 8+, this was fixed to avoid cycles but
   concurrent modification still causes data loss and
   inconsistent state. Use ConcurrentHashMap for thread safety.

INTERVIEW TIPS
----------------------------------------------------------------
  1. map.getOrDefault(key, 0) and map.merge(key, 1, Integer::sum)
     are the cleanest ways to count frequencies -- use them
  2. computeIfAbsent is the cleanest way to initialize a list
     value: map.computeIfAbsent(key, k -> new ArrayList<>())
  3. Iterating map.entrySet() is more efficient than iterating
     keySet() and calling get() for each key
  4. TreeMap.floorKey() and ceilingKey() are powerful tools for
     range problems -- know them for senior-level interviews
  5. LinkedHashMap with accessOrder=true is a one-liner LRU Cache
     -- worth knowing even if interviewer wants custom DLL impl
  6. Never call map.get(key) twice when you can store the result:
     Integer val = map.get(key); if (val != null) use val
