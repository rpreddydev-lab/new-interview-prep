================================================================
  DISJOINT SET (UNION-FIND)
================================================================

----------------------------------------------------------------
WHAT IS UNION-FIND?
----------------------------------------------------------------
Union-Find (Disjoint Set Union, DSU) is a data structure that
tracks a collection of elements partitioned into non-overlapping
(disjoint) sets. It supports two primary operations:

  find(x)  -- returns the representative (root) of x's set
  union(x, y) -- merges the sets containing x and y

  Application: determining if two elements are in the same set,
  finding connected components, cycle detection, Kruskal's MST.

  Visualization (5 elements, initial state: each is its own set):
    parent: [0, 1, 2, 3, 4]  (each element is its own parent)

  After union(0, 1) and union(2, 3):
    parent: [0, 0, 2, 2, 4]  (0 is root of {0,1}, 2 is root of {2,3})

  After union(0, 2):
    parent: [0, 0, 0, 2, 4]  (0 is root of {0,1,2,3})

----------------------------------------------------------------
BASIC IMPLEMENTATION
----------------------------------------------------------------
  int[] parent;

  void init(int n) {
    parent = new int[n];
    for (int i = 0; i < n; i++) parent[i] = i;
  }

  int find(int x) {
    if (parent[x] != x) parent[x] = find(parent[x]);  // path compression
    return parent[x];
  }

  boolean union(int x, int y) {
    int rootX = find(x), rootY = find(y);
    if (rootX == rootY) return false;  // already in same set
    parent[rootX] = rootY;             // merge
    return true;
  }

  boolean connected(int x, int y) {
    return find(x) == find(y);
  }

----------------------------------------------------------------
OPTIMIZATION 1: PATH COMPRESSION
----------------------------------------------------------------
During find(), make every node on the path point directly to
the root. This flattens the tree for future operations.

  Without path compression: find() is O(n) worst case
  (deep tree from sequential unions)

  With path compression (recursive):
    int find(int x) {
      if (parent[x] != x) parent[x] = find(parent[x]);
      return parent[x];
    }

  Path compression makes the tree very flat after a few ops.

----------------------------------------------------------------
OPTIMIZATION 2: UNION BY RANK (OR UNION BY SIZE)
----------------------------------------------------------------
Always attach the smaller tree under the root of the larger tree.
This keeps the tree height bounded.

  Union by rank:
    int[] rank;  // upper bound on height

    void union(int x, int y) {
      int rootX = find(x), rootY = find(y);
      if (rootX == rootY) return;
      if (rank[rootX] < rank[rootY])
        parent[rootX] = rootY;
      else if (rank[rootX] > rank[rootY])
        parent[rootY] = rootX;
      else {
        parent[rootY] = rootX;
        rank[rootX]++;  // same rank -> new root gets rank + 1
      }
    }

  Union by size (often simpler):
    int[] size;  // number of nodes in component

    void union(int x, int y) {
      int rootX = find(x), rootY = find(y);
      if (rootX == rootY) return;
      if (size[rootX] < size[rootY]) { int tmp = rootX; rootX = rootY; rootY = tmp; }
      parent[rootY] = rootX;
      size[rootX] += size[rootY];
    }

----------------------------------------------------------------
COMPLEXITY
----------------------------------------------------------------
  Without optimizations:
    find: O(n) worst case
    union: O(n) worst case

  With path compression only:
    find: O(log n) amortized

  With union by rank only:
    find: O(log n) worst case

  With BOTH path compression + union by rank/size:
    find/union: O(alpha(n)) amortized
    alpha = inverse Ackermann function
    alpha(n) <= 4 for all practical n (n < 10^80)
    Effectively O(1) amortized

  Space: O(n)

----------------------------------------------------------------
APPLICATIONS
----------------------------------------------------------------

  1. CONNECTED COMPONENTS IN UNDIRECTED GRAPH
     Process all edges with union(u, v).
     Count distinct roots (components).

     int countComponents(int n, int[][] edges) {
       init(n);
       int count = n;
       for (int[] e : edges)
         if (union(e[0], e[1])) count--;
       return count;
     }

  2. CYCLE DETECTION IN UNDIRECTED GRAPH
     For each edge (u, v):
       if find(u) == find(v): CYCLE FOUND
       else: union(u, v)

  3. KRUSKAL'S MST
     Sort edges by weight.
     For each edge: add to MST if union returns true (no cycle).
     Stop when V-1 edges added.

  4. DYNAMIC CONNECTIVITY
     Add/remove connections dynamically.
     Answer "are x and y connected?" at any point.

  5. ACCOUNTS MERGE (LeetCode 721)
     Each account's emails in a set.
     Union emails by common account.
     Group emails by component root.

  6. REDUNDANT CONNECTION (LeetCode 684)
     For each edge: if already connected (find(u)==find(v))
     -> this is the redundant edge. Else union.

----------------------------------------------------------------
WEIGHTED UNION-FIND (for ratio problems)
----------------------------------------------------------------
Extended to track the ratio/weight from each node to its parent.
Used in problems like "Evaluate Division" (LeetCode 399):
  - Nodes represent variables
  - Edges represent known ratios
  - find() returns both root AND accumulated weight to root

  double[] weight;  // weight[i] = ratio from i to parent[i]

  int find(int x) {
    if (parent[x] != x) {
      int root = find(parent[x]);
      weight[x] *= weight[parent[x]];  // accumulate weight
      parent[x] = root;
    }
    return parent[x];
  }

----------------------------------------------------------------
INTERVIEW QUESTIONS
----------------------------------------------------------------

Q: What is path compression and why does it help?
A: During find(x), after finding the root, we set the parent of
   every node on the path directly to the root. This flattens
   the tree for all future find calls. Without compression, a
   chain of unions creates a linked-list-like tree with O(n)
   find. With path compression, the tree becomes nearly flat
   after a few operations, giving amortized O(alpha(n)) find.

Q: What is union by rank vs union by size?
A: Union by rank keeps an upper bound on tree height and always
   attaches the shorter tree under the taller one. Union by size
   keeps the number of nodes and always attaches the smaller
   component under the larger one. Both achieve the same O(log n)
   worst-case height. Union by size is often simpler to code
   because the size counter is directly useful (e.g., tracking
   component sizes). Both combined with path compression give
   O(alpha(n)) amortized.

Q: How do you use Union-Find to detect cycles in an undirected
   graph?
A: Process edges one at a time. For each edge (u, v): if
   find(u) == find(v), both endpoints are already in the same
   component, meaning this edge creates a cycle. If find(u) !=
   find(v), call union(u, v). This is used in Kruskal's MST to
   ensure only cycle-free edges are added.

Q: Can Union-Find be used for directed graph cycle detection?
A: No, Union-Find is designed for undirected graphs. For directed
   graphs, use DFS with 3 colors (WHITE/GRAY/BLACK) or Kahn's
   topological sort. Union-Find doesn't track edge direction.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. Always implement BOTH path compression AND union by rank/size
     for the O(alpha(n)) amortized bound
  2. union() returning a boolean (true if merged, false if already
     same set) is useful for counting components and cycle detection
  3. For Accounts Merge: use email strings as DSU keys with a
     HashMap<String, String> as parent map
  4. Union-Find is better than DFS for DYNAMIC connectivity
     (new edges added over time)
  5. Union by SIZE (not rank) lets you track component sizes,
     useful for problems asking for the largest component
  6. alpha(n) is effectively constant for all real-world inputs
     -- always say "nearly O(1) amortized per operation"
