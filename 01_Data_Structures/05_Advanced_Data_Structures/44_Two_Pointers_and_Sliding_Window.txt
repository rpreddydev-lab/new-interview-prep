================================================================
  TWO POINTERS & SLIDING WINDOW
================================================================

  NOTE: Two pointers is a technique, not a data structure.
  It is included here as it pairs naturally with array-based
  data structures and commonly appears alongside them.

  See also: 35_Monotonic_Stack.txt (for related window patterns)
            36_Monotonic_Queue.txt (for sliding window max/min)

----------------------------------------------------------------
TWO POINTER PATTERNS
----------------------------------------------------------------
Two pointers use two indices into a sequence, moving them
based on conditions to find a result without nested loops.

  PATTERN 1: OPPOSITE ENDS (left + right pointers)
    Used for: sorted arrays, palindrome, container problems.
    left starts at 0, right starts at n-1.
    Move based on comparison with target/condition.

    Template:
      int left = 0, right = n - 1;
      while (left < right) {
        if (condition_met(nums[left], nums[right]))
          process and possibly move both;
        else if (need_larger)
          left++;
        else
          right--;
      }

  PATTERN 2: SAME DIRECTION (fast + slow, or left + right)
    Used for: Floyd's cycle detection, middle of linked list,
    remove duplicates, partition, 3Sum.
    Both start at 0 (or one at 0, one slightly ahead).
    Fast pointer leads; slow pointer follows.

    Template:
      int slow = 0;
      for (int fast = 0; fast < n; fast++) {
        if (keep_condition(nums[fast]))
          nums[slow++] = nums[fast];
      }

----------------------------------------------------------------
TWO SUM (sorted array)
----------------------------------------------------------------
  int[] twoSum(int[] nums, int target) {
    int left = 0, right = nums.length - 1;
    while (left < right) {
      int sum = nums[left] + nums[right];
      if (sum == target) return new int[]{left, right};
      else if (sum < target) left++;
      else right--;
    }
    return new int[]{-1, -1};  // not found
  }
  Time: O(n)  Space: O(1)

----------------------------------------------------------------
3SUM (sorted + two pointers)
----------------------------------------------------------------
  List<List<Integer>> threeSum(int[] nums) {
    Arrays.sort(nums);
    List<List<Integer>> result = new ArrayList<>();
    for (int i = 0; i < nums.length - 2; i++) {
      if (i > 0 && nums[i] == nums[i-1]) continue;  // skip duplicates
      int left = i + 1, right = nums.length - 1;
      while (left < right) {
        int sum = nums[i] + nums[left] + nums[right];
        if (sum == 0) {
          result.add(Arrays.asList(nums[i], nums[left], nums[right]));
          while (left < right && nums[left] == nums[left+1]) left++;
          while (left < right && nums[right] == nums[right-1]) right--;
          left++; right--;
        } else if (sum < 0) left++;
        else right--;
      }
    }
    return result;
  }
  Time: O(n^2)  Space: O(1) extra (output not counted)

CONTAINER WITH MOST WATER
----------------------------------------------------------------
  Greedy: always move the pointer at the shorter side.
  Reason: moving the taller side can only decrease the width
          and cannot increase the height (still bounded by shorter).

  int maxArea(int[] height) {
    int left = 0, right = height.length - 1, max = 0;
    while (left < right) {
      max = Math.max(max, (right - left) * Math.min(height[left], height[right]));
      if (height[left] < height[right]) left++;
      else right--;
    }
    return max;
  }
  Time: O(n)  Space: O(1)

SLIDING WINDOW PATTERNS
----------------------------------------------------------------
Sliding window maintains a contiguous subarray [left, right]
and expands/shrinks based on constraints.

  FIXED SIZE WINDOW:
    for (int right = 0; right < n; right++) {
      add(nums[right]);
      if (right >= k) remove(nums[right - k]);  // shrink: drop left element
      if (right >= k - 1) process_window();
    }
    Time: O(n)  Space: O(k) if tracking window contents

  VARIABLE SIZE WINDOW (find longest):
    int left = 0;
    for (int right = 0; right < n; right++) {
      add(nums[right]);
      while (window_invalid()) remove(nums[left++]);
      result = Math.max(result, right - left + 1);
    }
    Time: O(n) amortized (each element added and removed at most once)

  VARIABLE SIZE WINDOW (find shortest):
    int left = 0;
    for (int right = 0; right < n; right++) {
      add(nums[right]);
      while (window_valid()) {  // shrink while still valid
        result = Math.min(result, right - left + 1);
        remove(nums[left++]);
      }
    }
    Time: O(n)

LONGEST SUBSTRING WITHOUT REPEATING CHARACTERS
----------------------------------------------------------------
  int lengthOfLongestSubstring(String s) {
    Map<Character, Integer> map = new HashMap<>();  // char -> last seen index
    int left = 0, result = 0;
    for (int right = 0; right < s.length(); right++) {
      char c = s.charAt(right);
      if (map.containsKey(c) && map.get(c) >= left)
        left = map.get(c) + 1;  // jump left past the duplicate
      map.put(c, right);
      result = Math.max(result, right - left + 1);
    }
    return result;
  }
  Time: O(n)  Space: O(min(n, 128)) for ASCII

  Key: jump left directly (not just left++) using last seen index.
  Guard: map.get(c) >= left ensures we don't move left backwards
  when a char was seen before the current window.

----------------------------------------------------------------
MINIMUM WINDOW SUBSTRING
----------------------------------------------------------------
  Find shortest substring containing all chars of pattern t.

  String minWindow(String s, String t) {
    int[] need = new int[128]; for (char c : t.toCharArray()) need[c]++;
    int have = 0, total = t.length();
    int left = 0, minLen = Integer.MAX_VALUE, start = 0;

    for (int right = 0; right < s.length(); right++) {
      char c = s.charAt(right);
      if (need[c]-- > 0) have++;
      while (have == total) {  // window is valid, try to shrink
        if (right - left + 1 < minLen) { minLen = right - left + 1; start = left; }
        char l = s.charAt(left++);
        if (++need[l] > 0) have--;  // removing needed char breaks validity
      }
    }
    return minLen == Integer.MAX_VALUE ? "" : s.substring(start, start + minLen);
  }
  Time: O(|s| + |t|)  Space: O(128) = O(1)

  Key insight:
    need[c] counts how many more of char c are still needed.
    Incrementing when we remove: if need[c] becomes positive again,
    we've lost a required char, so have decreases.

FRUIT INTO BASKETS (at most 2 distinct elements)
----------------------------------------------------------------
  Generalize: longest subarray with at most k distinct values.

  int totalFruit(int[] fruits) {
    Map<Integer, Integer> basket = new HashMap<>();
    int left = 0, result = 0;
    for (int right = 0; right < fruits.length; right++) {
      basket.merge(fruits[right], 1, Integer::sum);
      while (basket.size() > 2) {
        int f = fruits[left++];
        basket.merge(f, -1, Integer::sum);
        if (basket.get(f) == 0) basket.remove(f);
      }
      result = Math.max(result, right - left + 1);
    }
    return result;
  }
  Time: O(n)  Space: O(k)

----------------------------------------------------------------
INTERVIEW QUESTIONS
----------------------------------------------------------------

Q: What is the amortized time complexity of the variable
   sliding window and why?
A: O(n). Each element is added to the window exactly once
   (when right pointer passes over it) and removed at most
   once (when left pointer passes over it). So regardless
   of how many times the inner while loop runs for a given
   right pointer value, the total operations across ALL
   right pointer iterations is at most 2n.

Q: In the minimum window substring, why do you check
   `++need[l] > 0` when shrinking?
A: `need[c]` tracks how many more of character c we need.
   When we added characters to the window, we decremented
   need[c]. It can go negative (we have MORE than needed).
   When we remove character l from the window (left++),
   we increment need[l]:
   - If need[l] becomes 0 or stays <= 0: we still have
     enough of l, `have` stays the same.
   - If need[l] becomes > 0 (was 0, now 1): we've lost
     the last required instance of l, so we decrement `have`,
     making the window invalid and stopping the shrink loop.

Q: When should you use two pointers vs sliding window vs
   HashMap-based approach?
A: Two pointers (opposite ends): sorted array, need pair/triplet
   with a sum condition, or comparing ends (palindrome).
   Two pointers (same direction): partition/filter in-place,
   remove duplicates, fast/slow for cycle detection.
   Sliding window: contiguous subarray/substring with a constraint
   (longest with at most k distinct, minimum length with sum >= k).
   HashMap-based: sliding window where the constraint involves
   character/element frequency (substring matching, anagram).
   All three are O(n) techniques for different problem shapes.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. Opposite-ends two pointer requires the array to be SORTED
     or have a property that lets you make a greedy move
  2. Variable window expand/shrink: "longest" pattern expands,
     then shrinks WHILE invalid; "shortest" shrinks WHILE valid
  3. For fixed-size window: use a difference array approach --
     add right element, remove element at right-k each step
  4. Always verify: what does your window represent? What is
     the invalid condition? What is the valid condition?
  5. Sliding window NEVER uses a nested for loop that starts
     from i+1 -- that would be O(n^2). Always left/right single pass.
  6. For character frequency windows: use int[128] array, not
     HashMap -- faster and cleaner for ASCII problems
