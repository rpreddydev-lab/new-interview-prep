================================================================
  SPARSE TABLE
================================================================

----------------------------------------------------------------
WHAT IS A SPARSE TABLE?
----------------------------------------------------------------
A Sparse Table is a data structure for answering STATIC range
minimum/maximum queries (RMQ) in O(1) after O(n log n) preprocessing.

  Key properties:
    - Only works for IDEMPOTENT operations (min, max, GCD)
      (an operation f where f(x, x) = x)
    - Does NOT support updates (static array only)
    - O(1) query time for range min/max
    - O(n log n) build time and space

  Idempotent means: f(f(a,b), f(a,b)) = f(a,b)
    min(min(3,5), min(3,5)) = min(3,5) -- overlapping ranges OK
    sum(sum(a,b), sum(a,b)) = 2*sum(a,b) -- NOT idempotent
    Therefore: Sparse Table works for min/max/GCD, NOT for sum.
    For sum with updates, use Fenwick Tree or Segment Tree.

  Compare:
    Segment Tree:  O(n) build, O(log n) query, supports updates
    Fenwick Tree:  O(n) build, O(log n) query, supports updates (sum)
    Sparse Table:  O(n log n) build, O(1) query, NO updates, min/max/GCD only

----------------------------------------------------------------
STRUCTURE
----------------------------------------------------------------
st[i][j] = result of f over the range [j, j + 2^i - 1]
         = result for 2^i elements starting at index j

  i = 0: ranges of length 1 (each element itself)
  i = 1: ranges of length 2
  i = 2: ranges of length 4
  ...
  i = k: ranges of length 2^k

  Example for arr = [1, 3, 2, 7, 9, 5, 8]:
    i=0: [1, 3, 2, 7, 9, 5, 8]            (single elements)
    i=1: [min(1,3), min(3,2), min(2,7), min(7,9), min(9,5), min(5,8)]
       = [1, 2, 2, 7, 5, 5]
    i=2: [min(1,2,2,7), min(3,2,7,9), min(2,7,9,5), min(7,9,5,8)]
       = [1, 2, 2, 5]

----------------------------------------------------------------
IMPLEMENTATION
----------------------------------------------------------------
  int[][] st;
  int[] log2;  // precomputed floor(log2)

  BUILD (O(n log n)):
    int LOG = 1 + (int)(Math.log(n) / Math.log(2));
    st = new int[LOG][n];

    // Base case: ranges of length 1
    for (int j = 0; j < n; j++) st[0][j] = arr[j];

    // Build higher levels
    for (int i = 1; i < LOG; i++)
      for (int j = 0; j + (1 << i) <= n; j++)
        st[i][j] = Math.min(st[i-1][j], st[i-1][j + (1 << (i-1))]);

    // Precompute log2
    log2 = new int[n + 1];
    log2[1] = 0;
    for (int i = 2; i <= n; i++) log2[i] = log2[i/2] + 1;

  RANGE MINIMUM QUERY [l, r] (O(1)):
    int rmq(int l, int r) {
      int k = log2[r - l + 1];  // largest power of 2 fitting in window
      return Math.min(st[k][l], st[k][r - (1 << k) + 1]);
    }

    How O(1) works:
      Split [l, r] into two overlapping ranges of length 2^k:
      [l, l + 2^k - 1] and [r - 2^k + 1, r]
      These overlap but since min is idempotent, overlapping is fine.
      Return min of both range results.

  RANGE GCD QUERY:
    Same structure, replace Math.min with gcd(a, b).
    gcd is idempotent: gcd(gcd(a,b), gcd(a,b)) = gcd(a,b).

----------------------------------------------------------------
WHY O(1) QUERY WORKS (OVERLAP IS OK)
----------------------------------------------------------------
  Key insight: min(min(A), min(B)) = min(A union B) even if A and B
  overlap (as long as we're taking min, not sum).

  For range [3, 7] with k = floor(log2(5)) = 2 (2^2 = 4 fits in 5):
    Range 1: [3, 6]  (4 elements from index 3)
    Range 2: [4, 7]  (4 elements ending at index 7)
    These overlap at indices [4, 6] but:
    min([3,7]) = min(min([3,6]), min([4,7])) -- correct even with overlap

  This is why the sparse table ONLY works for idempotent operations.
  For sum: sum([3,6]) + sum([4,7]) = sum([3,7]) + sum([4,6]) -- wrong!

----------------------------------------------------------------
COMPLEXITY SUMMARY
----------------------------------------------------------------
  Operation         Time            Space
  -----------------------------------------
  Build             O(n log n)      O(n log n)
  Range min/max     O(1)            O(1)
  Range sum         NOT SUPPORTED   N/A
  Update            NOT SUPPORTED   N/A

COMMON INTERVIEW PROBLEMS
----------------------------------------------------------------
  Problem                             Technique           Complexity
  ---------------------------------------------------------------
  Range Minimum Query (static)        Sparse Table        O(1) query
  Lowest Common Ancestor (offline)    Euler tour + RMQ    O(1) after build
  Range GCD Query                     Sparse Table        O(1) query
  Maximum Sum Rectangle               Sparse table + DP   O(n^2 * m)
  Range Min of Array (many queries)   Sparse Table        O(1) each

----------------------------------------------------------------
INTERVIEW QUESTIONS
----------------------------------------------------------------

Q: Why can Sparse Table only be used for idempotent operations?
A: Sparse Table queries work by overlapping two ranges of size
   2^k to cover [l, r]. For an idempotent operation f (where
   f(x, x) = x for any x), the overlap doesn't change the result:
   f(f(a,b), f(b,c)) = f(a, b, c) correctly. For non-idempotent
   operations like sum, the overlapping elements are counted twice,
   giving wrong results. Min, max, GCD, LCM, AND, OR are all
   idempotent. Sum, product, XOR (XOR(a,a)=0, not a) are not.

Q: When should you use Sparse Table vs Segment Tree?
A: Use Sparse Table when:
   1. The array is STATIC (no updates)
   2. The query operation is IDEMPOTENT (min, max, GCD)
   3. You need O(1) per query (very fast query throughput)
   Use Segment Tree when:
   1. The array is DYNAMIC (updates required)
   2. The operation is not idempotent (range sum, range XOR)
   3. You need range update support (lazy propagation)
   If the problem says "static array, range min/max queries",
   Sparse Table is the optimal choice.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. Sparse Table is O(1) query but O(n log n) space -- for
     very large n this may matter; mention the trade-off
  2. The overlap trick works ONLY for idempotent operations --
     always verify this before suggesting Sparse Table
  3. Precomputing log2 values avoids repeated log computation
     in the query; do this in the build phase
  4. LCA (Lowest Common Ancestor) using Euler tour + Sparse
     Table RMQ is the O(1) LCA algorithm -- advanced topic
  5. In interviews, Sparse Table rarely appears as the primary
     topic -- it's more of a "did you know this?" bonus
     Segment Tree and BIT are much more common
