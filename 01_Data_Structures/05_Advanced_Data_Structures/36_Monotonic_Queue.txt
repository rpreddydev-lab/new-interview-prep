WHAT IS A MONOTONIC QUEUE?
----------------------------------------------------------------
A monotonic queue (implemented with a Deque) maintains its
elements in monotonically increasing or decreasing order.
Unlike a monotonic stack, elements can be removed from BOTH ends:
  - Front: expired elements (outside the window)
  - Back: elements violating the monotonic property

  DECREASING queue (back to front): [8, 5, 3]
    Front holds the MAXIMUM of the current window.
    Used for: sliding window maximum.

  INCREASING queue (back to front): [1, 3, 5]
    Front holds the MINIMUM of the current window.
    Used for: sliding window minimum.

  Amortized time: O(n) -- each element added and removed at most once.

----------------------------------------------------------------
SLIDING WINDOW MAXIMUM (key pattern)
----------------------------------------------------------------
Find the maximum in every window of size k.

  int[] slidingWindowMax(int[] nums, int k) {
    int n = nums.length;
    int[] result = new int[n - k + 1];
    Deque<Integer> dq = new ArrayDeque<>();  // stores INDICES, decreasing values

    for (int i = 0; i < n; i++) {
      // Remove expired elements (outside window)
      while (!dq.isEmpty() && dq.peekFirst() < i - k + 1)
        dq.pollFirst();

      // Maintain decreasing order: remove smaller elements from back
      while (!dq.isEmpty() && nums[dq.peekLast()] < nums[i])
        dq.pollLast();

      dq.offerLast(i);

      // Front holds index of max for current window
      if (i >= k - 1)
        result[i - k + 1] = nums[dq.peekFirst()];
    }
    return result;
  }

  Time: O(n)  Space: O(k)
  Each element added once and removed at most once.

JUMP GAME VI (DP + Monotonic Queue)
----------------------------------------------------------------
Find max score path with at most k jumps at each step.

  dp[i] = max(dp[i-k], ..., dp[i-1]) + nums[i]
  Use decreasing monotonic queue to find max in window [i-k, i-1].

  int maxResult(int[] nums, int k) {
    int n = nums.length;
    int[] dp = new int[n];
    dp[0] = nums[0];
    Deque<Integer> dq = new ArrayDeque<>();
    dq.offerLast(0);

    for (int i = 1; i < n; i++) {
      // Remove out-of-window indices
      while (!dq.isEmpty() && dq.peekFirst() < i - k)
        dq.pollFirst();

      dp[i] = dp[dq.peekFirst()] + nums[i];

      // Maintain decreasing dp values in deque
      while (!dq.isEmpty() && dp[dq.peekLast()] <= dp[i])
        dq.pollLast();
      dq.offerLast(i);
    }
    return dp[n - 1];
  }

  This pattern: DP optimization where we need window max/min
  over a sliding range of previous DP values.

----------------------------------------------------------------
0-1 BFS USING DEQUE
----------------------------------------------------------------
Shortest path in a graph where edges have weight 0 or 1.
Instead of Dijkstra's O((V+E) log V), use deque in O(V+E).

  0-weight edges: push to FRONT of deque (like Dijkstra with dist=0)
  1-weight edges: push to BACK of deque

  Deque<int[]> dq = new ArrayDeque<>();
  int[] dist = new int[V];
  Arrays.fill(dist, Integer.MAX_VALUE);
  dist[src] = 0;
  dq.offerFirst(new int[]{0, src});

  while (!dq.isEmpty()) {
    int[] curr = dq.pollFirst();
    int d = curr[0], u = curr[1];
    if (d > dist[u]) continue;  // stale
    for (int[] nb : adj[u]) {
      int v = nb[0], w = nb[1];
      if (dist[u] + w < dist[v]) {
        dist[v] = dist[u] + w;
        if (w == 0) dq.offerFirst(new int[]{dist[v], v});
        else        dq.offerLast(new int[]{dist[v], v});
      }
    }
  }

  Use cases: minimum operations where some moves are free,
  minimum obstacles to remove in a grid.

----------------------------------------------------------------
MONOTONIC STACK vs MONOTONIC QUEUE
----------------------------------------------------------------
  Feature              Monotonic Stack     Monotonic Queue (Deque)
  ---------------------------------------------------------------
  Removal from         Back only           Front AND back
  Window sliding?      No                  Yes (expire from front)
  Use case             Previous/next >/< in full array    Sliding window max/min
  Element expiry       N/A                 By index comparison
  DP optimization      No                  Yes (window max DP)
  Amortized time       O(n)                O(n)

----------------------------------------------------------------
INTERVIEW QUESTIONS
----------------------------------------------------------------

Q: Why is the sliding window maximum O(n) and not O(n*k)?
A: Each element is added to the deque exactly once and removed
   at most once (either from the back when a larger element
   arrives, or from the front when it expires). So total
   deque operations = O(2n) = O(n), even though we have n
   windows. This is the amortized argument: no element is
   processed more than twice regardless of window size k.

Q: What is the difference between the monotonic deque for
   sliding window max vs the Segment Tree approach?
A: Both achieve O(n) for sliding window max. The deque approach
   is O(n) time and O(k) space -- simpler to code. A Segment
   Tree achieves O(n log n) time (each query O(log n)) and O(n)
   space -- more complex but supports arbitrary range queries
   including non-sliding windows. For the specific sliding
   window max problem, always use the deque: simpler and faster.

Q: How does 0-1 BFS use a deque to achieve O(V+E)?
A: In 0-1 BFS, edges have weight 0 or 1. When we relax a
   0-weight edge, the neighbor has the same distance as the
   current node and should be processed next (like being at the
   front of a priority queue). When we relax a 1-weight edge,
   the neighbor has distance + 1 and goes to the back. This
   mimics Dijkstra's priority queue behavior without the log
   factor: addFirst for 0-cost, addLast for 1-cost.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. Always use ArrayDeque in Java, never LinkedList for deque --
     ArrayDeque is faster (O(1) all ops, cache friendly)
  2. Store INDICES in the deque, not values -- needed for
     expiry check (dq.peekFirst() < i - k + 1) and result
  3. Expiry check happens BEFORE the back-cleaning step
  4. Front = answer (max or min for current window)
  5. For DP + window max: same pattern as sliding window max
     but applied to the dp array instead of nums
  6. 0-1 BFS is faster than Dijkstra when all weights are 0 or 1 --
     mention this optimization when applicable
