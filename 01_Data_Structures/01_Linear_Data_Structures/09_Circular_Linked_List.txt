================================================================
  CIRCULAR LINKED LIST
================================================================

----------------------------------------------------------------
WHAT IS A CIRCULAR LINKED LIST?
----------------------------------------------------------------
A circular linked list is a linked list where the last node's
next pointer points back to the first node (head), forming
a circle. There is no null terminator at the end.

  Singly Circular Linked List:
    head
     |
    [1] --> [2] --> [3] --> [4]
     ^                       |
     +-----------------------+

  Doubly Circular Linked List:
    +--------------------------------------------+
    |                                            |
    v                                            |
   [1] <--> [2] <--> [3] <--> [4]
    |                           ^
    +---------------------------+

  Key properties:
    - No null in the list (every node has a next)
    - Can traverse the entire list from ANY node
    - Infinite loop risk if traversal termination is wrong
    - Natural fit for round-robin scheduling and cyclic problems

----------------------------------------------------------------
TYPES OF CIRCULAR LINKED LISTS
----------------------------------------------------------------

  Singly Circular Linked List
    - Each node has only a next pointer
    - Last node's next = head
    - Often maintained via a TAIL pointer (not head pointer),
      because tail.next = head gives O(1) access to both ends

  Doubly Circular Linked List
    - Each node has prev and next pointers
    - Last node's next = head, head's prev = last node
    - Used in Java's internal LinkedList implementation for
      certain deque operations and OS process scheduling

----------------------------------------------------------------
WHY USE TAIL POINTER INSTEAD OF HEAD POINTER
----------------------------------------------------------------
In a singly circular linked list, keeping a pointer to the
TAIL (not head) gives O(1) access to BOTH:
  - Tail: directly via tail
  - Head: via tail.next

  Insert at tail:   newNode.next = tail.next (= head)
                    tail.next = newNode
                    tail = newNode
                    Time: O(1)

  Insert at head:   newNode.next = tail.next (= head)
                    tail.next = newNode
                    (tail unchanged)
                    Time: O(1)

  With only a head pointer, insert at tail requires O(n)
  traversal to find the last node.

----------------------------------------------------------------
OPERATIONS AND COMPLEXITY
----------------------------------------------------------------
  Operation                   Complexity    Notes
  ---------------------------------------------------------------
  Traverse all nodes          O(n)          Stop when back at start
  Insert at head              O(1)          Via tail pointer
  Insert at tail              O(1)          Via tail pointer
  Insert after given node     O(1)          Given node reference
  Delete head                 O(1)          Via tail pointer
  Delete tail                 O(n)          Must find node before tail
  Delete given node           O(n)          Must find predecessor
  Search by value             O(n)
  Length                      O(n)          Unless tracked separately

----------------------------------------------------------------
TRAVERSAL — AVOIDING INFINITE LOOP
----------------------------------------------------------------
  The critical difference from a regular linked list:
  termination condition must check if we're back at the start,
  NOT if curr == null (there is no null).

  Method 1: Start at head, stop when we return to head
    ListNode curr = head;
    do {
      process(curr.val);
      curr = curr.next;
    } while (curr != head);

  Method 2: Use a count
    int count = 0;
    ListNode curr = head;
    while (count < size) {
      process(curr.val);
      curr = curr.next;
      count++;
    }

  Method 3: Via tail pointer (stop at tail.next = head)
    ListNode curr = tail.next;  // start at head
    do {
      process(curr.val);
      curr = curr.next;
    } while (curr != tail.next);

----------------------------------------------------------------
CORE OPERATIONS — CODE PATTERNS (with tail pointer)
----------------------------------------------------------------

  INITIALIZATION (empty list)
    ListNode tail = null;

  INSERT AT END (and handle empty list)
    ListNode newNode = new ListNode(val);
    if (tail == null) {
      tail = newNode;
      tail.next = tail;       // points to itself
    } else {
      newNode.next = tail.next;  // new node points to head
      tail.next = newNode;       // old tail points to new node
      tail = newNode;            // update tail
    }

  INSERT AT HEAD
    ListNode newNode = new ListNode(val);
    if (tail == null) {
      tail = newNode;
      tail.next = tail;
    } else {
      newNode.next = tail.next;  // new node points to current head
      tail.next = newNode;       // tail now points to new head
    }

  DELETE HEAD
    if (tail == null) return;         // empty list
    if (tail == tail.next) {          // only one node
      tail = null;
      return;
    }
    tail.next = tail.next.next;       // skip head node

  DETECT IF A NODE IS THE LAST
    node.next == tail.next  // i.e., node.next == head

----------------------------------------------------------------
DETECTING A CYCLE IN A REGULAR LINKED LIST
----------------------------------------------------------------
A cycle in a singly linked list creates a circular structure
unintentionally. This is different from a designed circular LL
but uses the same detection logic.

  Floyd's Cycle Detection (Fast & Slow Pointers):
    slow = head, fast = head
    while (fast != null && fast.next != null):
      slow = slow.next
      fast = fast.next.next
      if slow == fast: CYCLE EXISTS

  Is the list circular by design or has an unintended cycle?
    Designed circular: last node deliberately points to head
    Unintended cycle:  some node points to an earlier node
                       (not necessarily head)

  Find cycle entry point: see 07_Singly_Linked_List.txt

----------------------------------------------------------------
CIRCULAR LINKED LIST USE CASES
----------------------------------------------------------------

  1. ROUND-ROBIN SCHEDULING
     Operating systems use circular lists to cycle through
     processes. Each process gets CPU time, then the pointer
     moves to the next. After the last process, it wraps back
     to the first — naturally modeled by a circular LL.

  2. JOSEPHUS PROBLEM
     n people stand in a circle. Every kth person is eliminated.
     Model as a circular linked list. Remove every kth node
     until one remains.
     Time: O(n*k) with circular LL, O(n) with DP formula

  3. MEDIA PLAYERS / PLAYLISTS
     "Repeat all" in a music player: after last song, loops
     back to first. Circular LL models this naturally.

  4. BROWSER CACHE / CIRCULAR BUFFER
     Fixed-size circular buffers overwrite the oldest entry
     when full. The write pointer wraps around to the start.

  5. MULTIPLAYER TURN-BASED GAMES
     Player turns cycle in a circle. Circular LL lets you
     advance to the next player and wrap from last to first
     without special-casing the end.

  6. TOKEN RING NETWORK (legacy)
     Token passes node to node in a ring. A node can only
     transmit when it holds the token.

----------------------------------------------------------------
JOSEPHUS PROBLEM — CLASSIC CIRCULAR LL PROBLEM
----------------------------------------------------------------
  Problem: n people in a circle numbered 1 to n.
           Starting from person 1, every kth person is
           eliminated. Find the position of the survivor.

  Approach 1: Simulate with circular linked list
    Build circular LL of n nodes.
    Start at head, advance k-1 steps, remove that node.
    Repeat until 1 node remains.
    Time: O(n * k)   Space: O(n)

  Approach 2: Mathematical DP (O(n) time, O(1) space)
    josephus(1, k) = 0  (0-indexed)
    josephus(n, k) = (josephus(n-1, k) + k) % n
    Convert to 1-indexed: add 1 at the end.

  The circular LL simulation is the interview-expected solution
  when asked to implement it from scratch.

----------------------------------------------------------------
CIRCULAR LINKED LIST vs REGULAR LINKED LIST
----------------------------------------------------------------
  Feature                    Regular LL          Circular LL
  ---------------------------------------------------------------
  Last node points to        null                head (or any node)
  Traversal termination      curr == null        curr == start node
  Insert at head (O(1))      Yes                 Yes (via tail ptr)
  Insert at tail (O(1))      Only with tail ptr  Yes (via tail ptr)
  Null pointer risk           High (standard)     None (no null)
  Infinite loop risk          None                High if not careful
  Use cases                  General             Scheduling, games,
                                                  ring buffers

----------------------------------------------------------------
INTERVIEW QUESTIONS
----------------------------------------------------------------

Q: How does a circular linked list differ from a regular
   linked list with a cycle (bug)?
A: A circular linked list is a deliberate design where the
   last node's next pointer points to the head, enabling
   continuous traversal. A cycle bug is an unintended loop
   where a node's next pointer points to some earlier node
   (not necessarily head), preventing the list from reaching
   null. Both are detected by Floyd's algorithm, but the
   circular LL is designed this way — every traversal must
   stop after visiting n nodes rather than checking for null.

Q: Why is a tail pointer preferred over a head pointer in
   a circular linked list?
A: With a tail pointer, you get O(1) access to both the tail
   (directly) and the head (via tail.next). This allows O(1)
   insert at both ends. With only a head pointer, inserting
   at the tail requires O(n) traversal to find the last node.

Q: How would you split a circular linked list into two halves?
A: Use fast and slow pointers to find the middle.
   Slow moves 1 step, fast moves 2 steps.
   When fast.next == head (odd length) or
        fast.next.next == head (even length), slow is at middle.
   Second half starts at slow.next.
   Set slow.next = head (close first half circle).
   Traverse second half to find its last node, point it to
   slow.next (the original head) to close second half circle.
   Time: O(n)   Space: O(1)

Q: How do you traverse a circular linked list without
   falling into an infinite loop?
A: Use a do-while loop starting from head and stopping when
   the pointer returns to head:
     do { process(curr); curr = curr.next; } while (curr != head)
   Or track a count and stop after n iterations.
   Never use curr != null as termination — it will loop forever.

Q: Solve the Josephus Problem for n people, every kth eliminated.
A: Mathematical solution (O(n) time, O(1) space):
   f(1, k) = 0  (0-indexed survivor position)
   f(n, k) = (f(n-1, k) + k) % n
   Add 1 for 1-indexed answer.

   For simulation with circular LL (O(n*k)):
   Build a circular LL of n nodes, start at head, advance
   k-1 steps, remove that node, advance again, repeat until
   1 node remains.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. The single most critical rule: NEVER use curr != null
     as the loop condition — use curr != head (or startNode)
  2. Always maintain a tail pointer — it gives O(1) access
     to both ends and avoids common O(n) tail insertions
  3. Handle the single-node case explicitly: tail.next = tail
     is the base case for an empty-to-one-node transition
  4. Circular LLs appear in OS scheduling and ring buffer
     questions — know the real-world context to impress
  5. The Josephus problem is the canonical circular LL question
     — know both the O(n*k) simulation and O(n) DP solution
  6. When asked to detect if a list is circular, traverse
     with a visited set OR use Floyd's — both work, Floyd's
     is O(1) space
