----------------------------------------------------------------
WHAT IS AN ARRAY?
----------------------------------------------------------------
An array is a contiguous block of memory that stores elements
of the same type, accessible by index in O(1) time.

It is the most fundamental data structure — most other
structures are built on top of it or compared against it.

  Memory layout (int array of size 5):
  Index:  [0]   [1]   [2]   [3]   [4]
  Value:  [10]  [20]  [30]  [40]  [50]
  Addr:   1000  1004  1008  1012  1016  (4 bytes each for int)

  Element address = base_address + (index * element_size)
  This is why random access is O(1).

----------------------------------------------------------------
TYPES OF ARRAYS
----------------------------------------------------------------
  Static Array
    - Fixed size declared at creation time
    - Memory allocated on stack or heap
    - int[] arr = new int[5];  in Java

  Dynamic Array (ArrayList in Java)
    - Resizes automatically when capacity is exceeded
    - Internally backed by a static array
    - When full: allocates new array (2x size), copies all elements
    - Amortized O(1) for add at end
    - O(n) for worst-case single insertion (during resize)

  Multi-dimensional Array
    - Array of arrays (2D, 3D, etc.)
    - Covered in depth in 05_2D_Arrays_Matrix.txt

----------------------------------------------------------------
ARRAY OPERATIONS AND COMPLEXITY
----------------------------------------------------------------
  Operation           Complexity    Notes
  ---------------------------------------------------------------
  Access by index     O(1)          arr[i]
  Search (unsorted)   O(n)          linear scan
  Search (sorted)     O(log n)      binary search
  Insert at end       O(1)*         amortized for dynamic array
  Insert at index i   O(n)          shift elements right
  Insert at front     O(n)          shift all elements right
  Delete at end       O(1)
  Delete at index i   O(n)          shift elements left
  Delete at front     O(n)          shift all elements left
  Resize (dynamic)    O(n)          copy all elements to new array

  * Amortized O(1) — occasional O(n) resize

----------------------------------------------------------------
ARRAYS IN JAVA
----------------------------------------------------------------
  Declaration and Initialization:
    int[] arr = new int[5];           // default 0s
    int[] arr = {10, 20, 30, 40, 50};
    int[] arr = new int[]{1, 2, 3};

  Key Properties:
    arr.length      -- fixed length (not a method, it's a field)
    Arrays.sort(arr)          -- O(n log n), in-place dual-pivot quicksort
    Arrays.binarySearch(arr, key)  -- O(log n), array must be sorted
    Arrays.fill(arr, value)        -- O(n)
    Arrays.copyOf(arr, newLen)     -- O(n)
    Arrays.copyOfRange(arr, from, to)
    Arrays.equals(arr1, arr2)      -- O(n)
    Arrays.toString(arr)           -- O(n), for printing

  ArrayList (Dynamic Array):
    List<Integer> list = new ArrayList<>();
    list.add(10);             // amortized O(1)
    list.add(0, 10);          // O(n) - insert at front
    list.get(i);              // O(1)
    list.set(i, val);         // O(1)
    list.remove(i);           // O(n)
    list.size();              // O(1)
    list.contains(val);       // O(n)
    Collections.sort(list);   // O(n log n)

  Convert between array and list:
    int[] arr = {1, 2, 3};
    List<Integer> list = new ArrayList<>();
    for (int x : arr) list.add(x);   // manual boxing

    Integer[] boxed = {1, 2, 3};
    List<Integer> list = Arrays.asList(boxed);  // fixed-size view
    List<Integer> list = new ArrayList<>(Arrays.asList(boxed)); // mutable

KEY ARRAY TECHNIQUES FOR INTERVIEWS
----------------------------------------------------------------

  1. TWO POINTERS
     Use two indices (left, right) moving toward each other
     or in the same direction. Avoids nested loops.

     Example: Check if array has a pair that sums to target
       left = 0, right = n - 1
       while (left < right)
         sum = arr[left] + arr[right]
         if sum == target: found
         if sum < target:  left++
         if sum > target:  right--
     Time: O(n)   Space: O(1)

  2. SLIDING WINDOW
     Maintain a window [left, right] and slide it over the array.
     Used for subarray problems with a constraint.

     Example: Max sum subarray of size k
       Compute sum of first k elements
       Slide: add arr[right], remove arr[left]
     Time: O(n)   Space: O(1)

  3. PREFIX SUM
     Precompute cumulative sums so range queries are O(1).

     prefix[i] = arr[0] + arr[1] + ... + arr[i]
     Sum from index l to r = prefix[r] - prefix[l-1]
     Time to build: O(n)   Query: O(1)

  4. KADANE'S ALGORITHM (Maximum Subarray)
     Track current sum and reset when it goes negative.

     maxSum = arr[0], currentSum = arr[0]
     for i from 1 to n-1:
       currentSum = max(arr[i], currentSum + arr[i])
       maxSum = max(maxSum, currentSum)
     Time: O(n)   Space: O(1)

  5. BINARY SEARCH ON SORTED ARRAY
     Divide and conquer. Works when array is sorted.

     left = 0, right = n - 1
     while (left <= right):
       mid = left + (right - left) / 2    // avoid overflow
       if arr[mid] == target: return mid
       if arr[mid] < target:  left = mid + 1
       else:                  right = mid - 1
     Time: O(log n)   Space: O(1)
     NOTE: Use left + (right - left) / 2 instead of (left+right)/2
           to prevent integer overflow.

  6. DUTCH NATIONAL FLAG (3-WAY PARTITION)
     Partition array into 3 groups in one pass.
     Used for: sort colors (LeetCode 75), 3-way quicksort.

     low = 0, mid = 0, high = n - 1
     while (mid <= high):
       if arr[mid] == 0: swap(low, mid); low++; mid++
       if arr[mid] == 1: mid++
       if arr[mid] == 2: swap(mid, high); high--
     Time: O(n)   Space: O(1)

  7. CYCLIC SORT
     For arrays containing numbers in range [1, n].
     Place each number at its correct index (num - 1).
     Time: O(n)   Space: O(1)
     Used for: find missing number, find duplicate

----------------------------------------------------------------
ARRAY vs LINKED LIST — KEY TRADE-OFFS
----------------------------------------------------------------
  Feature              Array               Linked List
  ---------------------------------------------------------------
  Memory layout        Contiguous          Non-contiguous
  Random access        O(1)                O(n)
  Insert at front      O(n)                O(1)
  Insert at end        O(1)*               O(1) with tail pointer
  Insert at middle     O(n)                O(1) given reference
  Search               O(n) / O(log n)     O(n)
  Cache performance    Excellent           Poor (pointer chasing)
  Memory overhead      Low                 High (pointer per node)
  Size                 Fixed / amortized   Dynamic always

  Choose Array when:  random access needed, cache efficiency matters
  Choose Linked List: frequent insert/delete at front or middle

INTERVIEW QUESTIONS
----------------------------------------------------------------

Q: Why is array access O(1)?
A: Arrays are stored in contiguous memory. The address of any
   element can be calculated directly:
   address = base + (index * element_size)
   No traversal needed — it's a direct memory address calculation.

Q: What happens when an ArrayList runs out of capacity?
A: It creates a new array with double the capacity, copies all
   existing elements into the new array, and discards the old one.
   This costs O(n) for the resize operation, but happens so
   infrequently that the amortized cost per add is still O(1).

Q: Why should you use left + (right - left) / 2 instead of
   (left + right) / 2 in binary search?
A: (left + right) can overflow for large integer values in Java
   where int max is ~2.1 billion. left + (right - left) / 2
   avoids this by never summing two large numbers.

Q: What is the time complexity of Arrays.sort() in Java?
A: For primitive arrays (int[], double[], etc.) Java uses a
   dual-pivot quicksort: O(n log n) average, O(n²) worst.
   For object arrays (Integer[], String[]), Java uses TimSort:
   O(n log n) worst case, O(n) best case (nearly sorted).

Q: How would you find the majority element (appears > n/2 times)?
A: Use Boyer-Moore Voting Algorithm in O(n) time and O(1) space.
   Keep a candidate and a count. For each element:
   - If count == 0, set candidate = element
   - If element == candidate, count++
   - Else count--
   The surviving candidate is the majority element.
   (Verify with a second pass if majority is not guaranteed.)

Q: How do you rotate an array to the right by k positions
   in O(n) time and O(1) space?
A: Use the reverse trick (three reverses):
   1. Reverse entire array
   2. Reverse first k elements
   3. Reverse remaining n-k elements
   Example: [1,2,3,4,5], k=2
   After step 1: [5,4,3,2,1]
   After step 2: [4,5,3,2,1]
   After step 3: [4,5,1,2,3]  (correct)

Q: What is a prefix sum and when do you use it?
A: A prefix sum array where prefix[i] stores the sum of all
   elements from index 0 to i. It allows range sum queries in
   O(1) after O(n) preprocessing.
   Use it when you have multiple range sum queries on a
   static array, or when you need to count subarrays with a
   given sum (combine with HashMap).

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. Always check for null/empty array at the start
  2. Watch for off-by-one errors in loop bounds and index access
  3. For subarray problems, think prefix sum or sliding window first
  4. For sorted array problems, think binary search or two pointers
  5. When asked for O(1) space, think in-place: two pointers,
     Dutch National Flag, Boyer-Moore, cyclic sort
  6. ArrayList.remove(int index) is O(n) — mention this
  7. Arrays in Java are objects — they can be null
