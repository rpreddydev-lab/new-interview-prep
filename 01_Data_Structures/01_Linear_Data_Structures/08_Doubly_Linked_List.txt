================================================================
  DOUBLY LINKED LIST
================================================================

----------------------------------------------------------------
WHAT IS A DOUBLY LINKED LIST?
----------------------------------------------------------------
A doubly linked list is a linked list where each node holds
a reference to BOTH the next node and the previous node.
This enables traversal in both directions and O(1) deletion
given only a node reference (unlike singly linked lists).

  Structure of a Node:
    class ListNode {
      int val;
      ListNode prev;
      ListNode next;
      ListNode(int val) { this.val = val; }
    }

  Visualization:
    null <-- [1] <--> [2] <--> [3] <--> [4] --> null
             head                        tail

  Key properties:
    - Bidirectional traversal
    - O(1) delete given only the node reference
    - O(1) insert before a given node (not possible in SLL)
    - More memory per node (extra prev pointer)
    - More complex pointer management (must update prev AND next)

----------------------------------------------------------------
OPERATIONS AND COMPLEXITY
----------------------------------------------------------------
  Operation                     Complexity    Notes
  ---------------------------------------------------------------
  Access by index               O(n)          Traverse from head or tail
  Search by value               O(n)          Linear scan
  Insert at head                O(1)
  Insert at tail                O(1)          With tail pointer
  Insert before a given node    O(1)          Given node reference
  Insert after a given node     O(1)          Given node reference
  Delete head                   O(1)
  Delete tail                   O(1)          With tail pointer
  Delete a given node           O(1)          No need for prev traversal
  Delete by value               O(n)          Find node first

  Key advantage over singly linked list:
    Delete given node ref = O(1) vs O(n) in SLL
    Insert before given node = O(1) vs O(n) in SLL
    Reverse traversal = O(n) vs impossible in SLL

----------------------------------------------------------------
CORE OPERATIONS — CODE PATTERNS
----------------------------------------------------------------

  INSERT AT HEAD
    ListNode newNode = new ListNode(val);
    newNode.next = head;
    newNode.prev = null;
    if (head != null) head.prev = newNode;
    head = newNode;
    if (tail == null) tail = head;   // first node

  INSERT AT TAIL
    ListNode newNode = new ListNode(val);
    newNode.prev = tail;
    newNode.next = null;
    if (tail != null) tail.next = newNode;
    tail = newNode;
    if (head == null) head = tail;   // first node

  INSERT AFTER A GIVEN NODE
    ListNode newNode = new ListNode(val);
    newNode.next = node.next;
    newNode.prev = node;
    if (node.next != null) node.next.prev = newNode;
    node.next = newNode;
    if (newNode.next == null) tail = newNode;

  INSERT BEFORE A GIVEN NODE
    ListNode newNode = new ListNode(val);
    newNode.prev = node.prev;
    newNode.next = node;
    if (node.prev != null) node.prev.next = newNode;
    node.prev = newNode;
    if (newNode.prev == null) head = newNode;

  DELETE A GIVEN NODE (O(1) — key advantage)
    if (node.prev != null) node.prev.next = node.next;
    else head = node.next;           // node was head
    if (node.next != null) node.next.prev = node.prev;
    else tail = node.prev;           // node was tail
    node.prev = null;                // help GC
    node.next = null;

  REVERSE TRAVERSAL
    ListNode curr = tail;
    while (curr != null) {
      process(curr.val);
      curr = curr.prev;
    }

----------------------------------------------------------------
DOUBLY LINKED LIST WITH SENTINEL NODES
----------------------------------------------------------------
Many real-world implementations use two sentinel (dummy) nodes:
a head sentinel and a tail sentinel. This eliminates all
null checks and edge cases in insert/delete operations.

  Initialization:
    head = new ListNode(0);   // sentinel head
    tail = new ListNode(0);   // sentinel tail
    head.next = tail;
    tail.prev = head;

  Insert node between two nodes (addBetween):
    node.prev = predecessor;
    node.next = successor;
    predecessor.next = node;
    successor.prev = node;

  Delete a node (removeNode):
    node.prev.next = node.next;
    node.next.prev = node.prev;

  Note: With sentinels, no null checks needed — head.next is
  always the first real node, tail.prev is always the last.
  This is the pattern used internally by Java's LinkedList class.

----------------------------------------------------------------
JAVA'S LinkedList CLASS
----------------------------------------------------------------
Java's java.util.LinkedList is implemented as a doubly linked
list with sentinel nodes.

  Implements: List<E>, Deque<E>, Queue<E>

  Common methods:
    addFirst(e)   / addLast(e)       -- O(1)
    removeFirst() / removeLast()     -- O(1)
    getFirst()    / getLast()        -- O(1)
    get(i)                           -- O(n) -- NOT O(1)!
    add(i, e)                        -- O(n)
    remove(i)                        -- O(n)
    size()                           -- O(1)
    contains(e)                      -- O(n)
    peek() / poll() / offer()        -- O(1) (Queue interface)
    push() / pop()                   -- O(1) (Stack/Deque interface)

  IMPORTANT: LinkedList.get(i) is O(n), not O(1).
  If you need index-based access, use ArrayList instead.
  LinkedList is only faster than ArrayList for addFirst/removeFirst.

  When to use LinkedList over ArrayDeque:
    - You need to expose the List interface (not just Deque)
    - You need null elements (ArrayDeque does not allow nulls)
    - Otherwise, ArrayDeque is preferred for stack/queue usage

LRU CACHE — THE CLASSIC DLL INTERVIEW PROBLEM
----------------------------------------------------------------
LRU (Least Recently Used) Cache combines a HashMap with a
Doubly Linked List to achieve O(1) get and O(1) put.

  Design:
    - HashMap<key, Node> for O(1) key lookup
    - DLL maintains access order: most recent at head,
      least recent at tail
    - On get: move accessed node to head
    - On put: add new node at head; if capacity exceeded,
      remove node at tail and evict its key from map
    - Use sentinel head and tail to simplify edge cases

  Node structure:
    class Node {
      int key, val;
      Node prev, next;
    }

  Core operations:
    get(key):
      if key not in map: return -1
      node = map.get(key)
      moveToHead(node)
      return node.val

    put(key, val):
      if key in map:
        map.get(key).val = val
        moveToHead(map.get(key))
      else:
        node = new Node(key, val)
        map.put(key, node)
        addToHead(node)
        if map.size() > capacity:
          removed = removeTail()
          map.remove(removed.key)

  Time: O(1) for both get and put
  Space: O(capacity)

  This is one of the most frequently asked design problems
  in interviews (Google, Meta, Amazon, etc.)

----------------------------------------------------------------
SINGLY vs DOUBLY LINKED LIST — KEY DIFFERENCES
----------------------------------------------------------------
  Feature                    Singly LL       Doubly LL
  ---------------------------------------------------------------
  Node pointers              1 (next)        2 (prev + next)
  Memory per node            Less            More
  Traversal direction        Forward only    Both directions
  Delete given node ref      O(n)            O(1)
  Insert before given node   O(n)            O(1)
  Insert at tail (w/ ptr)    O(1)            O(1)
  Implementation complexity  Simpler         More complex
  Used in Java               Not directly    java.util.LinkedList
  Use cases                  Stacks, simple  LRU/LFU cache,
                             traversal       browser history,
                                             undo/redo systems

INTERVIEW QUESTIONS
----------------------------------------------------------------

Q: Why is deleting a node O(1) in a doubly linked list but
   O(n) in a singly linked list?
A: In a singly linked list, deleting a node requires updating
   the previous node's next pointer. Without a prev reference,
   you must traverse from head to find the predecessor — O(n).
   In a doubly linked list, each node has a prev pointer,
   so you can directly update both neighbors in O(1):
   node.prev.next = node.next;  node.next.prev = node.prev;

Q: How would you implement an LRU Cache?
A: Use a HashMap for O(1) key lookup and a doubly linked list
   to maintain access order (most recent at head, least recent
   at tail). On get: find node via map, move it to head.
   On put: add to head, evict tail if over capacity (remove from
   both DLL and map). Use sentinel head/tail nodes to avoid
   null checks. Both operations are O(1).

Q: How does Java's LinkedList differ from a custom DLL?
A: Java's LinkedList uses two sentinel (dummy) nodes (first and
   last), eliminating null checks. It implements both List and
   Deque interfaces. Internally, each node (Node<E>) holds
   item, next, and prev. The key gotcha: get(i) is O(n), not
   O(1), because there's no index-based access — it traverses
   from head or tail (whichever is closer).

Q: When would you choose a doubly linked list over an array
   for implementing a cache?
A: A cache requires O(1) eviction of the least-recently-used
   element. With an array, finding and removing an element is
   O(n). With a doubly linked list and a HashMap, you can
   locate any node in O(1) via the map, then remove it in O(1)
   via prev/next pointers. This is exactly the LRU Cache design.

Q: How do you reverse a doubly linked list in O(1) space?
A: Swap the prev and next pointers for every node, then swap
   head and tail pointers.
   ListNode curr = head;
   while (curr != null):
     swap(curr.prev, curr.next)
     curr = curr.prev   // move to what was next
   swap(head, tail)
   Time: O(n)   Space: O(1)

Q: What is a sentinel node and why is it used in DLL?
A: A sentinel (dummy) node is a placeholder node with no real
   data, placed at the head and/or tail of the list. It
   eliminates special cases: with sentinels, every real node
   always has a non-null prev and next. Insert and delete code
   becomes uniform — no separate handling for head/tail nodes.
   Java's LinkedList, browser history implementations, and
   LRU Cache designs all benefit from this pattern.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. When implementing DLL operations, always update BOTH
     prev and next pointers — forgetting one causes bugs
     that are hard to spot
  2. Use sentinel head and tail nodes in any DLL implementation
     during an interview — it shows maturity and eliminates
     edge case bugs cleanly
  3. LRU Cache is the most common DLL interview problem —
     memorize the pattern: HashMap + DLL with sentinels
  4. Draw the before/after pointer state for any insert or
     delete operation before coding — DLL pointer bugs are
     the #1 source of errors
  5. Know that Java's LinkedList.get(i) is O(n) — mentioning
     this shows you understand the internals
  6. For LFU Cache (harder variant): use a HashMap of frequency
     to DLL, plus a HashMap of key to node, plus track minFreq
