================================================================
  DEQUE (DOUBLE-ENDED QUEUE)
================================================================

----------------------------------------------------------------
WHAT IS A DEQUE?
----------------------------------------------------------------
A deque (pronounced "deck") is a double-ended queue that
supports insertion and deletion at BOTH the front and rear
in O(1) time.

It generalizes both Stack and Queue:
  - Use only the rear end  --> behaves like a Queue (FIFO)
  - Use only the front end --> behaves like a Stack (LIFO)
  - Use both ends          --> full deque functionality

  Visualization:
                    FRONT              REAR
    addFirst -->  [1] [2] [3] [4]  <-- addLast
    removeFirst <-- front           rear --> removeLast

  Key operations:
    addFirst(x)    / offerFirst(x)  -- add to front    O(1)
    addLast(x)     / offerLast(x)   -- add to rear     O(1)
    removeFirst()  / pollFirst()    -- remove front    O(1)
    removeLast()   / pollLast()     -- remove rear     O(1)
    peekFirst()                     -- view front      O(1)
    peekLast()                      -- view rear       O(1)
    isEmpty()                       -- check empty     O(1)
    size()                          -- count           O(1)

----------------------------------------------------------------
DEQUE IN JAVA
----------------------------------------------------------------
  Interface: java.util.Deque<E>
  Primary implementation: java.util.ArrayDeque<E>
  Alternative: java.util.LinkedList<E> (also implements Deque)

  ArrayDeque<Integer> dq = new ArrayDeque<>();

  AS A STACK:
    dq.push(x);       // addFirst
    dq.pop();         // removeFirst
    dq.peek();        // peekFirst

  AS A QUEUE:
    dq.offer(x);      // addLast
    dq.poll();        // removeFirst
    dq.peek();        // peekFirst

  AS A FULL DEQUE:
    dq.offerFirst(x); dq.offerLast(x);
    dq.pollFirst();   dq.pollLast();
    dq.peekFirst();   dq.peekLast();

  IMPORTANT METHOD PAIRS:
    Method          Throws exception    Returns null/false
    -----------------------------------------------------------
    addFirst(x)     offerFirst(x)
    removeFirst()   pollFirst()         -- null if empty
    getFirst()      peekFirst()         -- null if empty
    addLast(x)      offerLast(x)
    removeLast()    pollLast()          -- null if empty
    getLast()       peekLast()          -- null if empty

  Use offer/poll/peek variants in interviews to avoid
  exceptions on empty deque.

  ArrayDeque vs LinkedList:
    ArrayDeque:  backed by resizable array, better cache perf
                 does NOT allow null elements
    LinkedList:  node-based, allows null, slightly more memory
    Prefer ArrayDeque unless null elements are required.

----------------------------------------------------------------
INTERNAL IMPLEMENTATION OF ArrayDeque
----------------------------------------------------------------
  ArrayDeque uses a circular array (ring buffer) internally.
  - head and tail indices track the front and rear
  - Wraps around using modulo when indices hit array bounds
  - Doubles capacity when full (amortized O(1) per operation)

  Why circular array?
    A plain array would require O(n) shift for front operations.
    Circular indexing gives O(1) for both ends.

  head = (head - 1 + capacity) % capacity   // addFirst
  tail = (tail + 1) % capacity              // addLast

  Initial capacity: 16 (Java default)

----------------------------------------------------------------
KEY DEQUE PATTERNS FOR INTERVIEWS
----------------------------------------------------------------

  1. MONOTONIC DEQUE (Sliding Window Maximum/Minimum)
     The most important deque interview pattern.
     Maintain a deque of indices in decreasing order.
     Front always holds the index of the window's maximum.

     Sliding Window Maximum (window size k):
       dq stores indices, front = index of current max
       for i from 0 to n-1:
         // expire elements outside window from front
         while !dq.isEmpty() && dq.peekFirst() < i - k + 1:
           dq.pollFirst()
         // remove elements smaller than current from back
         // (they can never be the max while arr[i] exists)
         while !dq.isEmpty() && arr[dq.peekLast()] <= arr[i]:
           dq.pollLast()
         dq.offerLast(i)
         if i >= k - 1:
           result[i - k + 1] = arr[dq.peekFirst()]
       Time: O(n)   Space: O(k)

     Sliding Window Minimum: same logic, flip comparison
     (remove elements LARGER than current from back).

  2. DEQUE AS BOTH STACK AND QUEUE (Palindrome Check)
     Add all characters to deque.
     While size > 1: pollFirst() and pollLast(), compare.
     If any mismatch: not a palindrome.
     Time: O(n)   Space: O(n)

  3. DEQUE FOR SLIDING WINDOW WITH CONSTRAINTS
     Jump Game VI (maximize score reaching end in at most k steps):
       dp[i] = max score to reach index i
       dp[i] = arr[i] + max(dp[i-k..i-1])
       Use monotonic deque to get max of dp[i-k..i-1] in O(1).
       Total time: O(n)   Space: O(k)

  4. DEQUE FOR BFS WITH PRIORITY (0-1 BFS)
     In a graph where edge weights are 0 or 1:
       Weight 0 edge: addFirst (like a priority queue pop)
       Weight 1 edge: addLast
     Deque acts as a 0-1 priority queue.
     Time: O(V + E)   Space: O(V)
     Use case: shortest path where moves have cost 0 or 1

  5. UNDO/REDO NAVIGATION
     Back history: addFirst on navigate, pollFirst on back
     Forward history: cleared on new navigation
     Deque lets you go forward and backward efficiently.

  6. WORK-STEALING DEQUE (Fork/Join framework)
     Java's ForkJoinPool uses a work-stealing deque per thread.
     Thread pushes/pops from its own deque's front.
     Other threads steal from the back.
     Reduces contention in parallel task execution.

----------------------------------------------------------------
DEQUE vs STACK vs QUEUE
----------------------------------------------------------------
  Feature              Stack     Queue     Deque
  ---------------------------------------------------------------
  Add front            Yes*      No        Yes
  Add rear             Yes       Yes       Yes
  Remove front         Yes       Yes       Yes
  Remove rear          Yes       No        Yes
  Access front         Yes       Yes       Yes
  Access rear          Yes       No        Yes
  Primary use          LIFO      FIFO      Both + sliding window
  Java class           ArrayDeque ArrayDeque ArrayDeque

  * Stack's "front" and "rear" are the same end (top)

DESIGN CIRCULAR DEQUE (LeetCode 641)
----------------------------------------------------------------
  Design a circular deque with capacity k.

  Use a doubly linked list with sentinel head and tail,
  or a circular array with head/tail indices.

  Array-based:
    int[] data = new int[k];
    int head = 0, tail = k - 1, size = 0;

    insertFront(val):
      if isFull(): return false
      head = (head - 1 + k) % k
      data[head] = val
      size++
      return true

    insertLast(val):
      if isFull(): return false
      tail = (tail + 1) % k
      data[tail] = val
      size++
      return true

    deleteFront():
      if isEmpty(): return false
      head = (head + 1) % k
      size--
      return true

    deleteLast():
      if isEmpty(): return false
      tail = (tail - 1 + k) % k
      size--
      return true

    getFront(): return isEmpty() ? -1 : data[head]
    getRear():  return isEmpty() ? -1 : data[tail]
    isEmpty():  return size == 0
    isFull():   return size == k

  Time: O(1) for all operations   Space: O(k)

INTERVIEW QUESTIONS
----------------------------------------------------------------

Q: What is the difference between a Deque and a Queue?
A: A Queue supports insertion at the rear and removal from
   the front only (FIFO). A Deque (double-ended queue) supports
   insertion and removal at BOTH ends. A Deque is strictly more
   general — any Queue or Stack can be implemented with a Deque.
   In Java, ArrayDeque implements Deque and is the recommended
   implementation for both Stack and Queue use cases.

Q: Why is ArrayDeque preferred over LinkedList as a Deque?
A: ArrayDeque uses a circular resizable array internally, giving
   better cache performance (contiguous memory vs pointer-chased
   nodes). ArrayDeque has lower memory overhead (no node objects,
   no pointers). Operations are faster in practice. The only
   downside: ArrayDeque does not allow null elements, while
   LinkedList does.

Q: What is a monotonic deque and what problem does it solve?
A: A monotonic deque maintains elements in strictly increasing
   or decreasing order. It solves the Sliding Window Maximum /
   Minimum problem in O(n): for each new element, pop all
   elements from the back that are smaller (for max deque).
   The front always holds the maximum of the current window.
   Expired elements (outside window) are removed from the front.
   Each element is added and removed at most once: O(n) total.

Q: How does 0-1 BFS use a deque?
A: In a graph with edge weights of only 0 or 1, a deque
   replaces a priority queue for Dijkstra-style shortest path.
   When relaxing a neighbor via a weight-0 edge, add it to the
   FRONT of the deque (it's essentially "free" to reach).
   Via a weight-1 edge, add to the BACK.
   This maintains the invariant that the deque is always sorted
   by distance, giving O(V + E) shortest path without a heap.

Q: When would you use a deque over a stack or a queue?
A: Use a deque when:
   1. You need sliding window maximum/minimum (monotonic deque)
   2. You need to efficiently add/remove from both ends
   3. You're implementing a palindrome checker
   4. You need 0-1 BFS shortest path
   5. You're implementing browser history (back + forward)
   6. You want one class to serve as both stack and queue
      (e.g., in BFS/DFS hybrid algorithms)

Q: How do you find the maximum of every subarray of size k
   using a deque in O(n)?
A: Use a monotonic decreasing deque of indices.
   For each index i:
   1. Remove indices from front if they are outside [i-k+1, i]
   2. Remove indices from back while arr[back] <= arr[i]
      (they can never be the max with arr[i] in the window)
   3. Push i to back
   4. When i >= k-1, arr[dq.peekFirst()] is the window max
   Each element is pushed and popped at most once: O(n) total.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. Whenever you see "sliding window maximum/minimum",
     reach for a monotonic deque immediately
  2. Know that ArrayDeque is the go-to for stack, queue,
     AND deque in Java — one class handles all three
  3. The monotonic deque trick: elements popped from the back
     are permanently discarded — they can never be useful again
     because a later, larger element has arrived
  4. For the circular deque design problem, always use
     (index - 1 + capacity) % capacity for backward wrapping
     to avoid negative modulo results in Java
  5. ArrayDeque does NOT allow null — if you need null support,
     use LinkedList instead (rare in interviews)
  6. Practice the monotonic deque on: Sliding Window Max,
     Jump Game VI, and Shortest Subarray with Sum >= k —
     these cover all variants of the pattern
