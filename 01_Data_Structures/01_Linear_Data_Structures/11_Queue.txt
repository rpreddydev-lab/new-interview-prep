  QUEUE

----------------------------------------------------------------
WHAT IS A QUEUE?
----------------------------------------------------------------
A queue is a linear data structure that follows the
FIFO principle — First In, First Out.

The first element added is the first one removed.
Think of a line at a checkout counter: you join at the back
and leave from the front.

  Visualization:
    enqueue(1), enqueue(2), enqueue(3)

    FRONT --> [1] [2] [3] <-- REAR

    dequeue() returns 1   (front leaves first)
    peek()    returns 2   (next front, not removed)

  Key operations:
    enqueue(x) / offer(x)  -- add to rear         O(1)
    dequeue()  / poll()    -- remove from front    O(1)
    peek()                 -- view front element   O(1)
    isEmpty()              -- check if empty       O(1)
    size()                 -- number of elements   O(1)

----------------------------------------------------------------
QUEUE IMPLEMENTATIONS
----------------------------------------------------------------

  1. LINKED LIST-BACKED QUEUE
     Natural fit — O(1) add at tail, O(1) remove at head.
     Maintain head (front) and tail (rear) pointers.

     class Queue<T> {
       private LinkedList<T> data = new LinkedList<>();
       void enqueue(T val)  { data.addLast(val); }
       T dequeue()          { return data.removeFirst(); }
       T peek()             { return data.peekFirst(); }
       boolean isEmpty()    { return data.isEmpty(); }
       int size()           { return data.size(); }
     }

  2. ARRAY-BACKED CIRCULAR QUEUE
     Use a fixed-size array with head and tail indices.
     Wrap around using modulo to reuse freed space.
     Avoids O(n) shift that a naive array queue would need.

     int[] data = new int[capacity];
     int head = 0, tail = 0, size = 0;

     enqueue(x):
       data[tail] = x
       tail = (tail + 1) % capacity
       size++

     dequeue():
       val = data[head]
       head = (head + 1) % capacity
       size--
       return val

  3. IN JAVA — USE ArrayDeque (recommended)
     Queue<Integer> queue = new ArrayDeque<>();
     queue.offer(x);    // enqueue (returns false if full)
     queue.poll();      // dequeue (returns null if empty)
     queue.peek();      // front element (null if empty)
     queue.isEmpty();
     queue.size();

     DO NOT use LinkedList as Queue unless you specifically
     need null elements — ArrayDeque is faster and preferred.

     DO NOT use add/remove on Queue unless you want exceptions
     on failure. Use offer/poll for null-safe return values.

----------------------------------------------------------------
QUEUE vs STACK — CORE DIFFERENCE
----------------------------------------------------------------
  Stack: LIFO — last in, first out (think: call stack, undo)
  Queue: FIFO — first in, first out (think: BFS, task scheduler)

  Stack uses one end (top) for both push and pop.
  Queue uses two ends: rear for enqueue, front for dequeue.

----------------------------------------------------------------
TYPES OF QUEUES
----------------------------------------------------------------

  SIMPLE QUEUE (FIFO)
    Standard queue as described above.

  CIRCULAR QUEUE (Ring Buffer)
    Fixed-size queue using modular indexing.
    Head and tail wrap around. Full when (tail+1)%n == head.
    Used in: OS task scheduling, network buffers, audio streaming.

  DOUBLE-ENDED QUEUE (DEQUE)
    Can add/remove from both front and rear.
    Covered in detail in 12_Deque_Double_Ended_Queue.txt

  PRIORITY QUEUE
    Elements dequeued in priority order, not arrival order.
    Covered in detail in 13_Priority_Queue.txt

  BLOCKING QUEUE (Java concurrent)
    Thread-safe queue that blocks on empty dequeue or
    full enqueue. Used in producer-consumer patterns.
    java.util.concurrent.LinkedBlockingQueue
    java.util.concurrent.ArrayBlockingQueue

----------------------------------------------------------------
CIRCULAR QUEUE — DESIGN (LeetCode 622)
----------------------------------------------------------------
  Design a circular queue with fixed capacity k.
  Operations: enQueue, deQueue, Front, Rear, isEmpty, isFull

  int[] data = new int[k];
  int head = 0, tail = -1, size = 0;

  enQueue(val):
    if isFull(): return false
    tail = (tail + 1) % k
    data[tail] = val
    size++
    return true

  deQueue():
    if isEmpty(): return false
    head = (head + 1) % k
    size--
    return true

  Front(): return isEmpty() ? -1 : data[head]
  Rear():  return isEmpty() ? -1 : data[tail]
  isEmpty(): return size == 0
  isFull():  return size == k

  Time: O(1) for all operations   Space: O(k)

BFS — THE PRIMARY USE CASE FOR QUEUES
----------------------------------------------------------------
Breadth-First Search is the most important queue application
in interviews. BFS explores nodes level by level and
guarantees the SHORTEST PATH in unweighted graphs/grids.

  BFS Template (Graph):
    Queue<Integer> queue = new ArrayDeque<>();
    Set<Integer> visited = new HashSet<>();
    queue.offer(start);
    visited.add(start);
    int steps = 0;

    while (!queue.isEmpty()):
      int size = queue.size();         // process one level at a time
      for (int i = 0; i < size; i++):
        node = queue.poll()
        if node == target: return steps
        for each neighbor of node:
          if not visited:
            visited.add(neighbor)
            queue.offer(neighbor)
      steps++

  BFS Template (Grid):
    int[][] dirs = {{0,1},{0,-1},{1,0},{-1,0}};
    Queue<int[]> queue = new ArrayDeque<>();
    queue.offer(new int[]{startR, startC});
    visited[startR][startC] = true;

    while (!queue.isEmpty()):
      int[] curr = queue.poll();
      for (int[] d : dirs):
        int nr = curr[0] + d[0], nc = curr[1] + d[1];
        if inBounds(nr, nc) && !visited[nr][nc]:
          visited[nr][nc] = true;
          queue.offer(new int[]{nr, nc});

  CRITICAL: Mark nodes visited when ENQUEUED, not when
  dequeued. Otherwise, the same node may be added to the
  queue multiple times, causing O(V²) instead of O(V+E).

----------------------------------------------------------------
LEVEL-ORDER TRAVERSAL (BFS ON TREES)
----------------------------------------------------------------
  List<List<Integer>> result = new ArrayList<>();
  Queue<TreeNode> queue = new ArrayDeque<>();
  queue.offer(root);

  while (!queue.isEmpty()):
    int levelSize = queue.size();
    List<Integer> level = new ArrayList<>();
    for (int i = 0; i < levelSize; i++):
      TreeNode node = queue.poll();
      level.add(node.val);
      if node.left  != null: queue.offer(node.left);
      if node.right != null: queue.offer(node.right);
    result.add(level);

  The key trick: snapshot queue.size() at the START of each
  level iteration. This isolates exactly one level's nodes.

MONOTONIC DEQUE (Sliding Window Maximum)
----------------------------------------------------------------
A monotonic deque maintains elements in decreasing order.
Front always holds the maximum of the current window.

  Sliding Window Maximum (window size k):
    Deque<Integer> dq = new ArrayDeque<>();  // stores indices
    int[] result = new int[n - k + 1];

    for i from 0 to n-1:
      // remove indices outside window
      while !dq.isEmpty() && dq.peekFirst() < i - k + 1:
        dq.pollFirst()
      // remove smaller elements from back (they'll never be max)
      while !dq.isEmpty() && arr[dq.peekLast()] < arr[i]:
        dq.pollLast()
      dq.offerLast(i)
      if i >= k - 1:
        result[i - k + 1] = arr[dq.peekFirst()]

  Time: O(n)   Space: O(k)
  Each element added and removed from deque at most once.

----------------------------------------------------------------
PRODUCER-CONSUMER WITH BLOCKING QUEUE
----------------------------------------------------------------
  Classic concurrency pattern:
    Producer threads add to queue
    Consumer threads take from queue
    BlockingQueue handles synchronization automatically

  BlockingQueue<Task> queue = new LinkedBlockingQueue<>(100);

  Producer:
    queue.put(task);      // blocks if queue is full

  Consumer:
    Task t = queue.take(); // blocks if queue is empty

  Used in: thread pools (ExecutorService uses it internally),
           message passing, pipeline processing.

----------------------------------------------------------------
INTERVIEW QUESTIONS
----------------------------------------------------------------

Q: What is the difference between offer() and add() in Java Queue?
A: Both enqueue an element, but they handle failure differently.
   add() throws an IllegalStateException if the queue is full
   (relevant for capacity-bounded queues). offer() returns
   false instead of throwing. In interviews, prefer offer()
   and poll() (which returns null on empty) over add() and
   remove() (which throw exceptions).

Q: Why do we mark nodes visited when enqueued in BFS, not
   when dequeued?
A: If you mark visited on dequeue, a node can be added to the
   queue multiple times before it's ever processed. Each of
   its neighbors could enqueue it again. This causes redundant
   work and can degrade BFS to O(V²). Marking on enqueue
   ensures each node enters the queue exactly once.

Q: How does BFS guarantee the shortest path?
A: BFS explores nodes level by level (by distance from source).
   The first time a node is reached, it is reached via the
   shortest path — because BFS exhausts all paths of length k
   before trying paths of length k+1. This property only holds
   for unweighted graphs (all edges have equal cost).
   For weighted graphs, use Dijkstra's algorithm instead.

Q: What is the time and space complexity of BFS?
A: Time: O(V + E) — every vertex and edge is visited once.
   Space: O(V) — the queue holds at most one full "frontier"
   level, which in the worst case is all V vertices.
   For a grid of m×n: Time O(m*n), Space O(m*n).

Q: How would you find the minimum number of steps to convert
   one word to another (Word Ladder)?
A: BFS where each word is a node and edges connect words that
   differ by one character. Use a HashSet of all valid words
   for O(1) neighbor lookup. For each word at the current
   level, try replacing each character with a-z and check if
   the result is in the word set. The BFS level at which the
   target is found equals the minimum steps.
   Time: O(n * m²) where n = words, m = word length.

Q: What is multi-source BFS and when do you use it?
A: Multi-source BFS starts BFS simultaneously from multiple
   source nodes (all enqueued before the loop begins).
   It efficiently computes the minimum distance from ANY source
   to all other nodes in a single BFS pass.
   Use cases: Rotting Oranges (all rotten cells are sources),
   Walls and Gates (all gates are sources), 01 Matrix (all 0s
   are sources). Without multi-source BFS, you'd need to run
   BFS from each source separately — much slower.

Q: How do you design a Hit Counter that counts hits in the
   last 5 minutes?
A: Use a Queue<Integer> to store timestamps of hits.
   hit(timestamp): queue.offer(timestamp)
   getHits(timestamp):
     remove all entries where timestamp - entry >= 300
     return queue.size()
   Since timestamps are ordered, remove from front.
   Space: O(max hits in 300 seconds).
   If timestamps are always integers in [1, 300]:
   use a circular array of size 300 for O(1) space.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. BFS = Queue. DFS = Stack (or recursion). Recognize
     which traversal the problem needs before coding
  2. Always snapshot queue.size() at the start of each BFS
     level to correctly group nodes by level
  3. Mark visited on ENQUEUE not dequeue — this is a
     common bug that interviewers specifically look for
  4. For shortest path in unweighted graph/grid, BFS is
     optimal. For weighted, mention Dijkstra
  5. Multi-source BFS is a powerful technique — recognize
     problems where "distance from nearest X" is asked
  6. Use offer/poll (not add/remove) in Java to avoid
     exception-based control flow
  7. Monotonic deque (not just queue) is needed for
     sliding window maximum — know the distinction
