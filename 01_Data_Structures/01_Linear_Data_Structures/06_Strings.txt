  STRINGS

----------------------------------------------------------------
WHAT IS A STRING?
----------------------------------------------------------------
A string is a sequence of characters. In Java, String is an
immutable object backed by a char array (or byte array in
Java 9+ with compact strings).

  Immutability means: once created, a String cannot be changed.
  Any operation that "modifies" a string creates a NEW object.

  "hello" + "world"  creates a third String "helloworld"
  The originals are unchanged.

----------------------------------------------------------------
STRING INTERNALS IN JAVA
----------------------------------------------------------------
  String Pool (String Intern Pool)
    Java maintains a pool of string literals in the heap.
    When you write String s = "hello", Java checks the pool
    first. If "hello" exists, it reuses the reference.
    If not, it creates a new entry.

    String a = "hello";
    String b = "hello";
    a == b is TRUE  (same reference from pool)

    String c = new String("hello");
    a == c is FALSE (new object on heap, outside pool)
    a.equals(c) is TRUE (same content)

  CRITICAL RULE:
    Always use .equals() to compare string content in Java.
    Never use == for strings unless intentionally checking
    reference equality.

  Java 9+ Compact Strings:
    Strings using only Latin-1 characters are stored as
    byte[] (1 byte per char) instead of char[] (2 bytes).
    This reduces memory by ~50% for ASCII-only strings.

----------------------------------------------------------------
STRING vs StringBuilder vs StringBuffer
----------------------------------------------------------------
  Feature           String        StringBuilder   StringBuffer
  ---------------------------------------------------------------
  Mutability        Immutable     Mutable         Mutable
  Thread Safety     Yes           No              Yes (synchronized)
  Performance       Slow (concat) Fast            Slower than SB
  Use Case          Constants,    Building strings Concurrent string
                    literals      in loops        building

  String concatenation in a loop:
    BAD:  String s = "";
          for (int i = 0; i < n; i++) s += i;
          Time: O(n²) — creates new String object each iteration

    GOOD: StringBuilder sb = new StringBuilder();
          for (int i = 0; i < n; i++) sb.append(i);
          String s = sb.toString();
          Time: O(n) — amortized O(1) per append

KEY STRING METHODS IN JAVA
----------------------------------------------------------------
  s.length()                    -- O(1)
  s.charAt(i)                   -- O(1)
  s.indexOf(ch)                 -- O(n)
  s.indexOf(str)                -- O(n*m) naive, O(n) with KMP
  s.substring(start, end)       -- O(n) in Java 7u6+
  s.toLowerCase() / toUpperCase()  -- O(n)
  s.trim()                      -- O(n)
  s.strip()                     -- O(n), Unicode-aware (Java 11+)
  s.split(regex)                -- O(n)
  s.replace(old, new)           -- O(n)
  s.contains(str)               -- O(n)
  s.startsWith(prefix)          -- O(k), k = prefix length
  s.endsWith(suffix)            -- O(k)
  s.equals(other)               -- O(n)
  s.equalsIgnoreCase(other)     -- O(n)
  s.compareTo(other)            -- O(n), lexicographic
  s.toCharArray()               -- O(n), returns new char[]
  s.valueOf(int/char/etc.)      -- O(n), static method
  String.join(delim, parts)     -- O(n)
  String.format(template, args) -- O(n)

  StringBuilder methods:
  sb.append(x)      -- O(1) amortized
  sb.insert(i, x)   -- O(n)
  sb.delete(i, j)   -- O(n)
  sb.reverse()      -- O(n)
  sb.charAt(i)      -- O(1)
  sb.toString()     -- O(n)

CHARACTER OPERATIONS
----------------------------------------------------------------
  char c = s.charAt(i);

  Check type:
    Character.isLetter(c)       -- a-z, A-Z
    Character.isDigit(c)        -- 0-9
    Character.isLetterOrDigit(c)
    Character.isWhitespace(c)
    Character.isUpperCase(c)
    Character.isLowerCase(c)

  Convert:
    Character.toLowerCase(c)
    Character.toUpperCase(c)
    c - '0'             -- convert digit char to int (e.g. '5' - '0' = 5)
    c - 'a'             -- convert lowercase letter to 0-based index
    (char)('a' + i)     -- convert 0-based index to lowercase letter

  ASCII quick reference:
    '0' = 48,  '9' = 57
    'A' = 65,  'Z' = 90
    'a' = 97,  'z' = 122
    'a' - 'A' = 32  (lowercase = uppercase + 32)

KEY STRING TECHNIQUES FOR INTERVIEWS
----------------------------------------------------------------

  1. CHARACTER FREQUENCY WITH ARRAY (O(1) space for fixed charset)
     int[] freq = new int[26];
     for (char c : s.toCharArray())
       freq[c - 'a']++;
     Use for: anagram check, character counting, ransom note

  2. TWO POINTERS ON STRING
     Convert to char array or use indices.
     Palindrome check: left=0, right=n-1
       while (left < right)
         if s[left] != s[right]: not palindrome
         left++, right--

  3. SLIDING WINDOW ON STRING
     Use for: longest substring without repeats,
              minimum window substring, permutation in string
     Track window with HashMap or int[128] for ASCII

  4. STRING HASHING / ROLLING HASH
     Used in Rabin-Karp algorithm for pattern matching.
     hash(s[i..i+m-1]) computed in O(1) from previous hash.
     Full match confirmed by character comparison.

  5. SORT CHARACTERS FOR ANAGRAM GROUPING
     char[] arr = s.toCharArray();
     Arrays.sort(arr);
     String key = new String(arr);
     Use as HashMap key for grouping anagrams.

  6. REVERSE A STRING
     char[] arr = s.toCharArray();
     left=0, right=arr.length-1;
     while (left < right): swap arr[left++] and arr[right--]
     Or: new StringBuilder(s).reverse().toString()

  7. EXPAND AROUND CENTER (Palindrome)
     For each center (n centers for odd, n-1 for even length):
       expand left and right while chars match
     Track maximum palindrome found.
     Time: O(n²)   Space: O(1)
     Better: Manacher's algorithm = O(n)

  8. TRIE FOR PREFIX MATCHING
     Build a Trie when multiple prefix-based string queries
     are needed. O(k) per insert/search vs O(n*k) brute force.

  9. KMP ALGORITHM (Pattern Matching)
     Build failure function (LPS array) in O(m).
     Search in O(n). Total: O(n + m).
     Better than naive O(n*m) brute force.

SUBSTRING vs SUBSEQUENCE
----------------------------------------------------------------
  Substring: contiguous characters within a string
    "ace" is NOT a substring of "abcde"
    "abc" IS a substring of "abcde"

  Subsequence: characters in order but not necessarily contiguous
    "ace" IS a subsequence of "abcde" (a...c...e)
    "aec" is NOT a subsequence of "abcde" (order violated)

  Key problems:
    Longest Common Substring    --> DP, O(m*n)
    Longest Common Subsequence  --> DP, O(m*n)
    Is Subsequence              --> Two pointers, O(n)

----------------------------------------------------------------
STRING IMMUTABILITY TRAPS IN INTERVIEWS
----------------------------------------------------------------
  Trap 1: String concatenation in loop
    Concatenating n strings of length 1 = O(n²) NOT O(n)
    Fix: Use StringBuilder

  Trap 2: substring() memory
    In Java 7u6+, substring creates a new String (O(n) copy).
    In Java 6, it shared the backing array (memory leak risk).
    Know this distinction if asked about Java version specifics.

  Trap 3: == vs .equals()
    "abc" == "abc"            may be true (string pool)
    new String("abc") == "abc" is false
    Always use .equals() for content comparison

  Trap 4: charAt() on modified string
    String s = "hello";
    s.charAt(0) = 'H';  // COMPILE ERROR — strings are immutable
    Must convert to char[]: char[] arr = s.toCharArray(); arr[0] = 'H';

INTERVIEW QUESTIONS
----------------------------------------------------------------

Q: Why is String immutable in Java?
A: Security: String is widely used for sensitive data (passwords,
   file paths, network connections). Immutability prevents
   accidental modification after passing to a method.
   Thread safety: immutable objects can be safely shared across
   threads without synchronization.
   Caching/Hashcode: String caches its hashCode. Immutability
   guarantees the hashCode never changes, making Strings safe
   as HashMap keys.
   String pool: immutability allows JVM to safely intern strings
   and share references.

Q: What is the time complexity of s1 + s2 in Java?
A: O(n + m) for a single concatenation — a new string of length
   n+m is created. But in a loop: s += word for n words of
   length k each = O(n² * k) total because each concatenation
   copies the entire accumulated string. Use StringBuilder.

Q: How does String.hashCode() work in Java?
A: Java computes: h = 31 * h + char[i] for each character.
   The formula is: s[0]*31^(n-1) + s[1]*31^(n-2) + ... + s[n-1]
   It's cached after first computation. The value 31 is a prime
   chosen to minimize collisions and is efficient with bit shifts:
   31 * i == (i << 5) - i (JVM optimizes this).

Q: How would you check if two strings are anagrams?
A: Option A (O(n log n)): Sort both strings and compare.
   Option B (O(n) time, O(1) space for 26 letters):
     int[] freq = new int[26];
     for each char in s1: freq[c - 'a']++
     for each char in s2: freq[c - 'a']--
     return all freq values are 0.

Q: How do you find the longest substring without repeating chars?
A: Sliding window with a HashSet or int[128] array.
   left = 0, right = 0, maxLen = 0
   while right < n:
     while set contains s[right]: remove s[left], left++
     add s[right] to set
     maxLen = max(maxLen, right - left + 1)
     right++
   Time: O(n)   Space: O(min(n, charset_size))

Q: What is the difference between String.intern() and
   string literals?
A: String literals are automatically interned — they go into
   the string pool at compile time.
   String.intern() manually adds a runtime string to the pool
   or returns the existing pooled reference.
   Use case: when you have many duplicate strings at runtime
   (e.g., parsed from a file), interning reduces memory.
   Risk: String pool is in heap (Java 7+); excessive interning
   can still cause memory pressure.

Q: How would you reverse the words in a sentence in-place
   (no extra string)?
A: Two-step reverse trick:
   1. Reverse the entire string
   2. Reverse each individual word
   Example: "the sky is blue"
   After full reverse: "eulb si yks eht"
   After word reverses: "blue is sky the"
   Time: O(n)   Space: O(1) if working with char array

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. Convert to char[] when you need to modify characters
     (String is immutable — direct modification is impossible)
  2. Use int[26] or int[128] instead of HashMap for character
     frequency when charset is fixed — faster and less overhead
  3. Always clarify: "Is the input ASCII only or Unicode?"
     This affects your frequency array size (26, 128, or 256)
  4. Sliding window is the go-to for most substring problems —
     recognize the pattern: "longest/shortest subarray/substring
     with constraint k"
  5. StringBuilder.reverse() is a built-in O(n) operation —
     know it and use it
  6. For palindrome problems, "expand around center" is simpler
     to implement than Manacher's but O(n²) — state both and
     let the interviewer guide you
  7. String.split() uses regex by default — split(",") is slower
     than you think; for simple char delimiters, parse manually
