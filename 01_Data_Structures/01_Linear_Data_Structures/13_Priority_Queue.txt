================================================================
  PRIORITY QUEUE & HEAP
================================================================

----------------------------------------------------------------
WHAT IS A PRIORITY QUEUE?
----------------------------------------------------------------
A priority queue is an abstract data type where each element
has a priority. Elements are dequeued in priority order —
NOT in the order they were inserted.

  Standard Queue:  FIFO — first in, first out
  Priority Queue:  Highest (or lowest) priority out first

  Real-world analogies:
    - Hospital ER: critical patients treated before minor ones
    - CPU scheduling: high-priority processes run first
    - Dijkstra's algorithm: always process nearest node next

  In Java: java.util.PriorityQueue<E>
    Default: MIN-HEAP (smallest element polled first)
    For max-heap: use Collections.reverseOrder() or
                  Comparator.reverseOrder()

----------------------------------------------------------------
HEAP — THE UNDERLYING DATA STRUCTURE
----------------------------------------------------------------
A heap is a complete binary tree stored as an array where
the heap property is maintained:

  MIN-HEAP: parent <= both children  (root = smallest element)
  MAX-HEAP: parent >= both children  (root = largest element)

  Complete binary tree: all levels filled except possibly
  the last, which is filled left to right.

  Array representation (1-indexed):
    parent(i)      = i / 2
    leftChild(i)   = 2 * i
    rightChild(i)  = 2 * i + 1

  Array representation (0-indexed, used in Java):
    parent(i)      = (i - 1) / 2
    leftChild(i)   = 2 * i + 1
    rightChild(i)  = 2 * i + 2

  Example Min-Heap (array: [1, 3, 2, 7, 4, 5, 6]):
            1
          /   \
         3     2
        / \   / \
       7   4 5   6

----------------------------------------------------------------
HEAP OPERATIONS AND COMPLEXITY
----------------------------------------------------------------
  Operation           Complexity    Description
  ---------------------------------------------------------------
  peek / getMin       O(1)          Root element
  offer / insert      O(log n)      Add then sift up
  poll / extractMin   O(log n)      Remove root, sift down
  remove(element)     O(n)          Find + sift (linear search)
  contains            O(n)          Linear search
  heapify (build)     O(n)          Build heap from array
  size                O(1)
  Space               O(n)

  Key insight: peek is O(1) but poll is O(log n) because
  after removing root, the last element is placed at root
  and must be sifted down to restore heap property.

----------------------------------------------------------------
HEAP OPERATIONS — HOW THEY WORK
----------------------------------------------------------------

  INSERT (sift up / bubble up):
    Add new element at the end of the array.
    Compare with parent; if smaller (min-heap), swap.
    Repeat until parent <= child or root is reached.
    Time: O(log n)

  EXTRACT MIN (sift down / bubble down):
    Save root value (the minimum).
    Move last element to root position.
    Remove last element.
    Compare root with children; swap with smaller child.
    Repeat until heap property restored or leaf is reached.
    Time: O(log n)

  BUILD HEAP (heapify) from array:
    Start from last non-leaf node: index = n/2 - 1
    Sift down each node from n/2-1 down to 0.
    Time: O(n)  (NOT O(n log n) — proven by summation)
    This is used by Arrays.sort() (heapsort) and heap construction.

  Why heapify is O(n) not O(n log n):
    Most nodes are near the bottom and travel very few levels.
    Height-weighted sum converges to O(n).

----------------------------------------------------------------
JAVA PriorityQueue
----------------------------------------------------------------
  // Min-heap (default)
  PriorityQueue<Integer> minHeap = new PriorityQueue<>();

  // Max-heap
  PriorityQueue<Integer> maxHeap =
      new PriorityQueue<>(Collections.reverseOrder());

  // Custom comparator (sort by second element of int[])
  PriorityQueue<int[]> pq =
      new PriorityQueue<>((a, b) -> a[1] - b[1]);

  // With initial capacity
  PriorityQueue<Integer> pq = new PriorityQueue<>(16);

  Key methods:
    pq.offer(x)       -- insert, O(log n)
    pq.poll()         -- remove + return min, O(log n)
    pq.peek()         -- view min without removing, O(1)
    pq.remove(x)      -- remove specific element, O(n)
    pq.contains(x)    -- check membership, O(n)
    pq.size()         -- O(1)
    pq.isEmpty()      -- O(1)

  IMPORTANT: Java's PriorityQueue does NOT support
  decreaseKey operation directly (needed for Dijkstra).
  Workaround: use lazy deletion (add updated entry, skip
  stale entries when popped).

  IMPORTANT: Iterating over PriorityQueue does NOT give
  sorted order. Use poll() in a loop for sorted output.

----------------------------------------------------------------
KEY PATTERNS FOR INTERVIEWS
----------------------------------------------------------------

  1. TOP K ELEMENTS PATTERN
     Find k largest elements from n elements.

     Approach: maintain a MIN-HEAP of size k.
       for each element x:
         pq.offer(x)
         if pq.size() > k: pq.poll()  // remove smallest
       pq now contains k largest elements.
       Time: O(n log k)   Space: O(k)

     Why min-heap for k largest?
       The root of a min-heap is the smallest of the k largest.
       If a new element is bigger than root, it deserves a spot.
       Evict the root (smallest of k) and add the new element.

     For k SMALLEST: use a MAX-HEAP of size k.

  2. MERGE K SORTED LISTS / ARRAYS
     Add first element of each list to min-heap along with
     list index and element index.
     Poll min, add to result, push next element from same list.
     Time: O(n log k)   Space: O(k) where k = number of lists

  3. KTH LARGEST / SMALLEST ELEMENT
     Kth largest: min-heap of size k. Root = answer.
     Kth smallest: max-heap of size k. Root = answer.
     Or use QuickSelect for O(n) average, O(n²) worst.

  4. DIJKSTRA'S SHORTEST PATH
     Min-heap of (distance, node) pairs.
     Always process the node with the smallest current distance.
     Use lazy deletion to handle stale entries.
     Time: O((V + E) log V)

  5. TASK SCHEDULING / CPU SCHEDULING
     Max-heap by frequency for greedy task scheduling.
     Always schedule the most frequent remaining task.

  6. MEDIAN OF DATA STREAM
     Maintain two heaps:
       maxHeap (left half) and minHeap (right half)
       Invariant: maxHeap.size() == minHeap.size() or +1
       Invariant: maxHeap.peek() <= minHeap.peek()
     Median:
       If sizes equal: (maxHeap.peek() + minHeap.peek()) / 2.0
       If maxHeap larger: maxHeap.peek()
     Time: O(log n) per insert, O(1) for median

  7. SLIDING WINDOW MEDIAN
     Use two heaps (same as median stream) but also support
     removal of elements outside the window.
     Use lazy deletion: mark removed elements, skip on poll.

----------------------------------------------------------------
HEAP SORT
----------------------------------------------------------------
  1. Build a max-heap from the input array: O(n)
  2. Repeatedly extract max (swap root with last unsorted,
     reduce heap size, sift down): O(n log n)
  Total: O(n log n)   Space: O(1) in-place

  Heap sort is NOT stable. Not cache-friendly (poor locality).
  Rarely used in practice (QuickSort is faster in practice)
  but common in theory/interview questions.

  In Java: Arrays.sort() uses dual-pivot QuickSort for
  primitives and TimSort for objects — NOT HeapSort.

----------------------------------------------------------------
TWO-HEAP PATTERN — MEDIAN OF DATA STREAM
----------------------------------------------------------------
  PriorityQueue<Integer> maxHeap = new PriorityQueue<>(reverseOrder());
  PriorityQueue<Integer> minHeap = new PriorityQueue<>();

  addNum(num):
    maxHeap.offer(num)
    minHeap.offer(maxHeap.poll())      // balance: push max of left to right
    if maxHeap.size() < minHeap.size():
      maxHeap.offer(minHeap.poll())    // keep left >= right in size

  findMedian():
    if maxHeap.size() == minHeap.size():
      return (maxHeap.peek() + minHeap.peek()) / 2.0
    return maxHeap.peek()

  Invariants:
    All elements in maxHeap <= all elements in minHeap
    maxHeap.size() == minHeap.size() or maxHeap.size() + 1

----------------------------------------------------------------
INTERVIEW QUESTIONS
----------------------------------------------------------------

Q: What is the difference between a heap and a priority queue?
A: A priority queue is an abstract data type (ADT) — it defines
   the interface: insert with priority, extract min/max.
   A heap is the most common concrete implementation of a
   priority queue. Other implementations exist (Fibonacci heap,
   binomial heap) but the binary heap is standard in interviews.
   Java's PriorityQueue is implemented as a binary min-heap.

Q: Why is building a heap O(n) and not O(n log n)?
A: O(n log n) would be the cost of inserting n elements one
   by one. But heapify (Floyd's algorithm) builds the heap
   bottom-up starting from the last non-leaf. Nodes near the
   bottom sift down very little (most sift 0-1 levels). The
   total work is bounded by the sum: n/4*1 + n/8*2 + n/16*3...
   which converges to O(n) by geometric series analysis.

Q: How do you find the Kth largest element efficiently?
A: Use a min-heap of size k. Iterate through all n elements.
   For each element, add it to the heap. If heap size exceeds k,
   poll the minimum. After processing all elements, peek() is
   the Kth largest. Time: O(n log k). Space: O(k).
   Alternative: QuickSelect gives O(n) average but O(n²) worst.

Q: How do you find the median of a stream of numbers?
A: Maintain two heaps: a max-heap for the lower half and a
   min-heap for the upper half. Keep them balanced in size
   (max-heap can have at most one more element). On each insert,
   balance by moving the max of lower half to upper half or vice
   versa. Median is peek of max-heap (odd total) or average of
   both peeks (even total). Time: O(log n) per insert, O(1) median.

Q: How does lazy deletion work in a priority queue?
A: Java's PriorityQueue.remove(element) is O(n) because it
   searches for the element. For Dijkstra or problems where
   you update priorities, instead of removing and reinserting,
   you add a new entry with the updated priority and mark the
   old entry as stale. When polling, check if the entry is stale
   (e.g., distance > known shortest) and skip it. This avoids
   O(n) removal and keeps offer/poll at O(log n).

Q: What comparator do you use for a max-heap in Java?
A: PriorityQueue<Integer> maxHeap =
       new PriorityQueue<>(Collections.reverseOrder());
   Or: new PriorityQueue<>((a, b) -> b - a);
   For custom objects: (a, b) -> b.priority - a.priority
   WARNING: Use Integer subtraction comparators only when
   overflow is not a risk. For safety, use Integer.compare(b, a).

Q: What is the difference between PriorityQueue and TreeMap
   for maintaining sorted order?
A: PriorityQueue: O(log n) insert/delete, O(1) min peek,
   O(n) search, no random access, allows duplicates.
   TreeMap: O(log n) insert/delete/search, O(log n) min/max
   (firstKey/lastKey), supports floor/ceiling/range queries,
   no duplicates by key. Use PriorityQueue when you only need
   min/max repeatedly. Use TreeMap when you need sorted access,
   range queries, or floor/ceiling lookups.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. "Top K" or "Kth largest/smallest" --> immediately think
     heap of size k (O(n log k) beats O(n log n) sort)
  2. For k largest: use MIN-heap of size k (counterintuitive
     but correct — root is the smallest of the k largest)
  3. Iterating a PriorityQueue does NOT give sorted order —
     only repeated poll() gives sorted output
  4. Java's PriorityQueue.remove(Object) is O(n), not O(log n)
     — use lazy deletion for repeated priority updates
  5. Two-heap pattern (median stream) is a top-5 interview
     pattern — know it cold: max-heap left, min-heap right,
     size invariant, balance on each insert
  6. For Dijkstra, use (distance, node) pairs in the heap
     and use lazy deletion for stale entries
  7. Always check for comparator integer overflow:
     use Integer.compare(a, b) not a - b for safety
