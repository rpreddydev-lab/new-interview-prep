================================================================
  SINGLY LINKED LIST
================================================================

----------------------------------------------------------------
WHAT IS A SINGLY LINKED LIST?
----------------------------------------------------------------
A singly linked list is a linear data structure where each
element (node) holds a value and a reference (pointer) to
the NEXT node in the sequence. The last node points to null.

  Structure of a Node:
    class ListNode {
      int val;
      ListNode next;
      ListNode(int val) { this.val = val; }
    }

  Visualization:
    head
     |
    [1] --> [2] --> [3] --> [4] --> null

  Key properties:
    - No index-based access (must traverse from head)
    - Dynamic size (no pre-allocation needed)
    - Non-contiguous memory (nodes scattered on heap)
    - Only one direction of traversal (forward)

----------------------------------------------------------------
OPERATIONS AND COMPLEXITY
----------------------------------------------------------------
  Operation                   Complexity    Notes
  ---------------------------------------------------------------
  Access by index             O(n)          Must traverse from head
  Search by value             O(n)          Linear scan
  Insert at head              O(1)          Update head pointer
  Insert at tail              O(n)*         Must reach tail first
  Insert after a given node   O(1)          Given the node ref
  Delete head                 O(1)          Update head pointer
  Delete tail                 O(n)          Must reach node before tail
  Delete by value             O(n)          Find + remove
  Delete given node ref       O(n)**        Need previous node
  Get length                  O(n)          Unless tracked separately

  * O(1) if tail pointer is maintained
  ** Unless it's a doubly linked list (O(1) with prev pointer)

----------------------------------------------------------------
CORE OPERATIONS — CODE PATTERNS
----------------------------------------------------------------

  INSERT AT HEAD
    ListNode newNode = new ListNode(val);
    newNode.next = head;
    head = newNode;

  INSERT AT TAIL
    ListNode curr = head;
    while (curr.next != null) curr = curr.next;
    curr.next = new ListNode(val);

  INSERT AFTER A NODE
    ListNode newNode = new ListNode(val);
    newNode.next = prevNode.next;
    prevNode.next = newNode;

  DELETE HEAD
    if (head != null) head = head.next;

  DELETE A NODE BY VALUE
    if (head.val == val) { head = head.next; return; }
    ListNode curr = head;
    while (curr.next != null) {
      if (curr.next.val == val) {
        curr.next = curr.next.next;
        return;
      }
      curr = curr.next;
    }

  TRAVERSE / PRINT
    ListNode curr = head;
    while (curr != null) {
      process(curr.val);
      curr = curr.next;
    }

  LENGTH
    int count = 0;
    ListNode curr = head;
    while (curr != null) { count++; curr = curr.next; }
    return count;

----------------------------------------------------------------
KEY TECHNIQUES FOR INTERVIEWS
----------------------------------------------------------------

  1. RUNNER TECHNIQUE (Fast and Slow Pointers)
     Use two pointers moving at different speeds.
     Fast moves 2 steps, slow moves 1 step per iteration.

     a) Detect Cycle (Floyd's Algorithm)
        fast = head, slow = head
        while (fast != null && fast.next != null):
          slow = slow.next
          fast = fast.next.next
          if slow == fast: CYCLE DETECTED
        If fast reaches null: no cycle
        Time: O(n)   Space: O(1)

     b) Find Middle of Linked List
        slow = head, fast = head
        while (fast != null && fast.next != null):
          slow = slow.next
          fast = fast.next.next
        slow is now at the middle
        (For even length: slow is at second middle node)
        Time: O(n)   Space: O(1)

     c) Find Start of Cycle
        After detecting meeting point:
        Move one pointer to head, keep other at meeting point.
        Advance both one step at a time.
        Where they meet = start of cycle.
        Time: O(n)   Space: O(1)

     d) Kth Node From End
        Move fast pointer k steps ahead.
        Then move both slow and fast until fast reaches null.
        slow is now at kth node from end.
        Time: O(n)   Space: O(1)

  2. REVERSAL
     Standard in-place reversal (3 pointers):
       prev = null, curr = head
       while (curr != null):
         next = curr.next
         curr.next = prev
         prev = curr
         curr = next
       head = prev
     Time: O(n)   Space: O(1)

     Reverse between positions l and r (partial reversal):
       Use dummy node, find node before position l,
       then reverse l to r using same 3-pointer technique.
       Time: O(n)   Space: O(1)

  3. DUMMY HEAD NODE
     A dummy/sentinel node before head simplifies edge cases
     where head itself may be removed or relinked.

     ListNode dummy = new ListNode(0);
     dummy.next = head;
     // ... manipulate list using dummy.next
     return dummy.next;  // new head

     Use for: remove nth from end, merge lists, partition list

  4. MERGE TWO SORTED LISTS
     dummy = new ListNode(0), curr = dummy
     while (l1 != null && l2 != null):
       if l1.val <= l2.val: curr.next = l1; l1 = l1.next
       else:                curr.next = l2; l2 = l2.next
       curr = curr.next
     curr.next = (l1 != null) ? l1 : l2
     return dummy.next
     Time: O(n + m)   Space: O(1)

  5. DETECT AND FIND CYCLE START
     Phase 1: Fast/slow pointer to detect cycle (meeting point)
     Phase 2: Reset one pointer to head, advance both by 1
              until they meet — that's the cycle start.
     Mathematical proof:
       Let F = distance from head to cycle start
       Let C = cycle length
       At meeting point, slow traveled F + a steps
       Fast traveled F + a + nC steps (lapped slow n times)
       Fast = 2 * slow: F + a + nC = 2(F + a)
       Solving: F = nC - a  --> head to cycle start = meeting
       point to cycle start (after one more full loop).

  6. PALINDROME CHECK
     Step 1: Find middle using fast/slow pointers
     Step 2: Reverse the second half
     Step 3: Compare first half with reversed second half
     Step 4: Restore list (optional, if original must be kept)
     Time: O(n)   Space: O(1)

  7. SPLIT LIST / PARTITION
     Maintain two separate chains (e.g., less-than and
     greater-or-equal), then connect them at the end.
     Use dummy heads for both chains.
     Time: O(n)   Space: O(1)

----------------------------------------------------------------
LINKED LIST vs ARRAY — WHEN TO USE WHICH
----------------------------------------------------------------
  Scenario                          Choose
  ---------------------------------------------------------------
  Frequent access by index          Array (O(1) access)
  Frequent insert/delete at front   Linked List (O(1))
  Frequent insert/delete at middle  Linked List (O(1) given ref)
  Memory is contiguous / cache perf Array
  Unknown / dynamic size            Both; ArrayList amortizes
  Implement Stack                   Either (ArrayDeque preferred)
  Implement Queue                   Linked List or ArrayDeque
  Undo/redo history                 Doubly Linked List

----------------------------------------------------------------
INTERVIEW QUESTIONS
----------------------------------------------------------------

Q: What is the difference between an array and a linked list?
A: Arrays store elements in contiguous memory, allowing O(1)
   random access. Linked lists use non-contiguous nodes connected
   by pointers, requiring O(n) traversal to access any element.
   Arrays are better for read-heavy workloads; linked lists for
   frequent insert/delete at arbitrary positions. Arrays have
   better cache performance due to spatial locality.

Q: How does Floyd's cycle detection algorithm work?
A: Use two pointers: slow moves 1 step, fast moves 2 steps.
   If a cycle exists, fast will eventually lap slow and they
   will meet inside the cycle. If fast reaches null, no cycle.
   To find the cycle start: after meeting, reset one pointer
   to head and advance both one step at a time — they meet
   at the cycle start. This works due to the mathematical
   relationship: distance from head to cycle start equals
   distance from meeting point to cycle start.

Q: How do you reverse a singly linked list iteratively?
A: Use three pointers: prev = null, curr = head, next = null.
   In each step: save curr.next, point curr.next to prev,
   advance prev to curr, advance curr to saved next.
   After the loop, prev is the new head.
   Time: O(n)   Space: O(1)

Q: How do you find the nth node from the end in one pass?
A: Use two pointers. Advance the first pointer n steps ahead.
   Then advance both pointers simultaneously until the first
   reaches the end. The second pointer is now at the nth
   node from the end. Time: O(n)   Space: O(1).

Q: How would you detect the intersection point of two lists?
A: Method 1 (O(n) space): Add all nodes of list A to a HashSet.
   Traverse list B; first node found in the set is the intersection.
   Method 2 (O(1) space): Get lengths of both lists. Advance
   the pointer in the longer list by the difference. Then advance
   both simultaneously — first node where they're equal is the
   intersection. Uses reference equality (==), not value equality.

Q: How do you check if a linked list is a palindrome in O(1) space?
A: Step 1: Find middle using fast/slow pointers.
   Step 2: Reverse second half in-place.
   Step 3: Compare first half and reversed second half node by node.
   Step 4: Optionally restore the list.
   Time: O(n)   Space: O(1)

Q: What is the time complexity of deleting a node in a linked
   list if you're given only the node reference (not head)?
A: In a singly linked list, you need the previous node to delete
   a target node — but without head you can't find it.
   The trick: copy the value of the next node into the current
   node, then delete the next node. This effectively "deletes"
   the current node in O(1). This only works if the node is
   NOT the tail.

Q: How would you sort a linked list?
A: Merge sort is optimal for linked lists.
   1. Find middle using fast/slow pointers
   2. Split into two halves
   3. Recursively sort both halves
   4. Merge the two sorted halves
   Time: O(n log n)   Space: O(log n) recursion stack
   Quicksort is NOT ideal for linked lists — no random access
   means poor pivot selection and O(n²) worst case.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. Always handle edge cases: null head, single node list,
     two-node list — these break many naive implementations
  2. Use a dummy head node whenever you might remove or change
     the head — it eliminates special-case head logic
  3. Draw the pointer state before and after each operation —
     it prevents mistakes when rewiring next pointers
  4. When reversing, always save next before overwriting:
     next = curr.next BEFORE curr.next = prev
  5. For fast/slow pointer problems, be precise about the
     termination condition: fast != null && fast.next != null
  6. Linked list problems often have O(1) space solutions —
     interviewers specifically look for this
  7. Never use extra data structures (arrays, sets) if
     you can solve with pointer manipulation alone
