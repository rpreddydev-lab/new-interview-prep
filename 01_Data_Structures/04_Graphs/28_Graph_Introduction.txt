----------------------------------------------------------------
WHAT IS A GRAPH?
----------------------------------------------------------------
A graph G = (V, E) is a set of vertices (nodes) V connected
by edges E. It is the most general non-linear data structure.

  Trees are a special case of graphs:
    - A tree is a connected, acyclic, undirected graph
    - Every tree with n nodes has exactly n-1 edges

  Terminology:
    Vertex / Node    -- basic unit
    Edge / Arc       -- connection between two vertices
    Degree           -- number of edges incident to a vertex
    In-degree        -- edges coming IN (directed graph)
    Out-degree       -- edges going OUT (directed graph)
    Adjacent         -- two vertices connected by an edge
    Path             -- sequence of vertices with edges between them
    Cycle            -- path that starts and ends at same vertex
    Connected        -- there is a path between every pair of vertices
    Strongly connected -- directed: path exists in BOTH directions
    Component        -- maximal connected subgraph
    Sparse graph     -- E << V^2  (few edges)
    Dense graph      -- E ~= V^2  (many edges)

----------------------------------------------------------------
GRAPH CLASSIFICATION
----------------------------------------------------------------
  Directed vs Undirected:
    Directed (Digraph): edges have direction (A -> B != B -> A)
    Undirected: edges are bidirectional (A -- B = B -- A)

  Weighted vs Unweighted:
    Weighted: edges have associated values (distances, costs)
    Unweighted: all edges treated equally (weight = 1)

  Cyclic vs Acyclic:
    Cyclic: contains at least one cycle
    Acyclic: no cycles (DAG = directed acyclic graph)

  Connected vs Disconnected:
    Connected (undirected): all vertices reachable from any vertex
    Disconnected: some vertices unreachable from others

  Simple vs Multigraph:
    Simple: at most one edge between any two vertices, no self-loops
    Multigraph: multiple edges between same vertices allowed

----------------------------------------------------------------
GRAPH REPRESENTATIONS (summary)
----------------------------------------------------------------
  Three main representations:

  1. ADJACENCY MATRIX (V x V matrix)
     matrix[i][j] = 1 if edge i->j exists, else 0
     Space: O(V^2)
     Edge lookup: O(1)
     Best for: dense graphs
     See 29_Graph_Adjacency_Matrix.txt

  2. ADJACENCY LIST (array of lists)
     list[i] = all neighbors of vertex i
     Space: O(V + E)
     Edge lookup: O(degree)
     Best for: sparse graphs (most real-world graphs)
     See 30_Graph_Adjacency_List.txt

  3. EDGE LIST (list of (u, v) pairs)
     Space: O(E)
     Edge lookup: O(E)
     Best for: algorithms that process all edges (Kruskal's MST)

  Representation     Space     Edge check   Neighbor scan
  ---------------------------------------------------------------
  Adjacency Matrix   O(V^2)    O(1)         O(V)
  Adjacency List     O(V+E)    O(deg)       O(deg)
  Edge List          O(E)      O(E)         O(E)

----------------------------------------------------------------
CORE GRAPH ALGORITHMS
----------------------------------------------------------------
  TRAVERSAL:
    BFS (Breadth-First Search)  -- shortest path (unweighted)
    DFS (Depth-First Search)    -- connected components, cycles, topological sort

  SHORTEST PATH:
    BFS                         -- unweighted graphs, O(V+E)
    Dijkstra's                  -- non-negative weights, O((V+E) log V)
    Bellman-Ford                -- negative weights, O(V*E)
    Floyd-Warshall              -- all pairs, O(V^3)
    A* (A-star)                 -- heuristic, grid pathfinding

  MINIMUM SPANNING TREE:
    Kruskal's                   -- greedy edge sort, O(E log E)
    Prim's                      -- greedy vertex expand, O(E log V)

  CYCLE DETECTION:
    DFS (with color marking)    -- directed graph
    Union-Find                  -- undirected graph

  TOPOLOGICAL SORT (DAGs only):
    DFS postorder               -- O(V+E)
    Kahn's BFS (in-degree)      -- O(V+E)

  STRONGLY CONNECTED COMPONENTS:
    Kosaraju's (2 DFS passes)   -- O(V+E)
    Tarjan's (single DFS)       -- O(V+E)

  BRIDGES AND ARTICULATION POINTS:
    Tarjan's algorithm          -- O(V+E)

  BIPARTITE CHECK:
    BFS/DFS with 2-coloring     -- O(V+E)

  MAXIMUM FLOW:
    Ford-Fulkerson              -- O(V*E^2)
    Edmonds-Karp                -- O(V*E^2)

----------------------------------------------------------------
BFS TEMPLATE
----------------------------------------------------------------
  void bfs(int start, List<List<Integer>> adj) {
    boolean[] visited = new boolean[V];
    Queue<Integer> queue = new LinkedList<>();
    visited[start] = true;
    queue.offer(start);
    while (!queue.isEmpty()) {
      int node = queue.poll();
      process(node);
      for (int neighbor : adj.get(node)) {
        if (!visited[neighbor]) {
          visited[neighbor] = true;  // mark ON ENQUEUE, not dequeue
          queue.offer(neighbor);
        }
      }
    }
  }

  KEY: mark visited when ENQUEUING, not when processing.
  Marking on dequeue allows the same node to be enqueued
  multiple times -> wrong results, potential infinite loop.

  BFS gives SHORTEST PATH (fewest edges) in unweighted graphs.

----------------------------------------------------------------
DFS TEMPLATE
----------------------------------------------------------------
  Recursive:
    void dfs(int node, boolean[] visited, List<List<Integer>> adj) {
      visited[node] = true;
      process(node);
      for (int neighbor : adj.get(node)) {
        if (!visited[neighbor])
          dfs(neighbor, visited, adj);
      }
    }

  Iterative (using explicit stack):
    void dfsIter(int start, List<List<Integer>> adj) {
      boolean[] visited = new boolean[V];
      Stack<Integer> stack = new Stack<>();
      stack.push(start);
      while (!stack.isEmpty()) {
        int node = stack.pop();
        if (visited[node]) continue;  // handle duplicate pushes
        visited[node] = true;
        process(node);
        for (int neighbor : adj.get(node))
          if (!visited[neighbor])
            stack.push(neighbor);
      }
    }

  DFS explores as deep as possible before backtracking.
  Uses O(h) stack space where h = maximum DFS depth.

----------------------------------------------------------------
COMPLEXITY OF BFS AND DFS
----------------------------------------------------------------
  With adjacency list:   O(V + E) time, O(V) space
  With adjacency matrix: O(V^2) time, O(V) space

  V = number of vertices, E = number of edges

INTERVIEW QUESTIONS
----------------------------------------------------------------

Q: What is the difference between BFS and DFS and when
   do you use each?
A: BFS (Breadth-First Search) explores level by level using a
   queue. It finds the SHORTEST PATH in unweighted graphs and
   is optimal for level-order problems, minimum hops, and
   problems where the solution is likely close to the source.
   DFS (Depth-First Search) explores as deep as possible using
   a stack (or recursion). It's better for topological sort,
   cycle detection, finding all paths, connected components,
   and backtracking problems. DFS uses O(h) space vs BFS O(V).

Q: Why should you mark a node as visited when you ENQUEUE
   it rather than when you DEQUEUE it in BFS?
A: If you mark visited on dequeue, a node can be enqueued
   multiple times before it's dequeued (each unvisited neighbor
   can enqueue it). This inflates the queue size and causes
   nodes to be processed multiple times. In the worst case,
   it changes BFS time from O(V+E) to O(V*E). Always mark
   visited at the moment of enqueue.

Q: When is Dijkstra's algorithm incorrect?
A: Dijkstra's assumes non-negative edge weights. With negative
   weights, it can finalize a node's shortest path too early
   (before a negative-weight edge could improve it). Use
   Bellman-Ford for graphs with negative weights (but no
   negative cycles). Use Floyd-Warshall for all-pairs shortest
   paths in dense graphs.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. Determine graph type first: directed/undirected,
     weighted/unweighted, cyclic/acyclic
  2. Choose representation: adjacency list for sparse graphs
     (most interview problems), matrix for dense or O(1) lookup
  3. BFS = shortest path (unweighted), DFS = topology/components
  4. Mark visited on ENQUEUE in BFS -- the most common bug
  5. For grid problems, graph is implicit: 4-directional or
     8-directional neighbors, no need to build explicit graph
  6. Multi-source BFS: add all sources to queue initially --
     rotting oranges, walls and gates, Pacific Atlantic
