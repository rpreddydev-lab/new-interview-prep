================================================================
  DIRECTED vs UNDIRECTED GRAPHS
================================================================

----------------------------------------------------------------
UNDIRECTED GRAPHS
----------------------------------------------------------------
Edges have no direction. If there is an edge between u and v,
you can travel from u to v AND from v to u.

  Notation: (u, v) = (v, u)  (unordered pair)

  Representation:
    adj[u] contains v AND adj[v] contains u
    Matrix: matrix[u][v] == matrix[v][u] (symmetric)

  Properties:
    Degree of a node: number of edges incident to it
    Sum of all degrees = 2 * E (handshaking lemma)
    A connected undirected graph with n vertices has >= n-1 edges
    A tree: connected + acyclic undirected graph (exactly n-1 edges)

  Connectivity:
    Connected: path exists between every pair of vertices
    Number of connected components: count of disjoint subgraphs

  Cycle detection:
    DFS: if neighbor is visited and is NOT the parent -> cycle
    Union-Find: if adding edge (u,v) and find(u) == find(v) -> cycle

  Applications:
    Social networks (friendship is symmetric)
    Road networks (two-way roads)
    Molecular structures
    Communication networks

----------------------------------------------------------------
DIRECTED GRAPHS (DIGRAPHS)
----------------------------------------------------------------
Edges have direction. Edge (u, v) means u -> v (u to v only).

  Notation: (u, v) != (v, u) -- ordered pair

  Representation:
    adj[u] contains v but adj[v] does NOT contain u (for u -> v)
    Matrix: matrix[u][v] may differ from matrix[v][u]

  Properties:
    In-degree of v:  number of edges pointing INTO v
    Out-degree of u: number of edges going OUT from u
    Sum of in-degrees = Sum of out-degrees = E

  Connectivity:
    Weakly connected: underlying undirected graph is connected
    Strongly connected: path from u to v AND from v to u for ALL u,v
    Strongly Connected Component (SCC): maximal strongly connected subgraph

  Cycle detection:
    DFS with 3 colors (WHITE/GRAY/BLACK)
    Back edge (to GRAY node) = cycle
    Cross/forward edges (to BLACK node) = no cycle

  Applications:
    Web links (page A links to page B, not necessarily reverse)
    Twitter followers (A follows B, not symmetric)
    Build systems (A depends on B)
    Task scheduling (task A must run before task B)
    Currency exchange

----------------------------------------------------------------
COMPARISON
----------------------------------------------------------------
  Property             Undirected          Directed
  ---------------------------------------------------------------
  Edge notation        {u, v}              (u, v)
  adj list entry       Both u->v, v->u     Only u->v
  Matrix symmetry      Symmetric           Not symmetric
  Degree               Single degree       In-degree + out-degree
  Connectivity         Connected/disconn.  Weakly/strongly connected
  Cycle detection      Parent-check DFS    3-color DFS
  Minimum tree         Spanning tree       No simple analog
  Topological sort     Not applicable      Applicable (DAG only)
  SCC                  Not applicable      Kosaraju/Tarjan

----------------------------------------------------------------
CONNECTED COMPONENTS (undirected)
----------------------------------------------------------------
  DFS/BFS from each unvisited node:
    int count = 0;
    for (int i = 0; i < V; i++)
      if (!visited[i]) { dfs(i); count++; }
    return count;

  Union-Find alternative:
    Initialize each node as its own component.
    For each edge (u, v): union(u, v).
    Count distinct root nodes.

----------------------------------------------------------------
STRONGLY CONNECTED COMPONENTS (directed) — Kosaraju's
----------------------------------------------------------------
  Two-pass DFS algorithm:

  Pass 1:
    DFS on original graph, record finish order (post-order).
    Push nodes to stack in order of decreasing finish time.

  Pass 2:
    Transpose the graph (reverse all edges).
    DFS on transposed graph in the order given by the stack.
    Each DFS tree in pass 2 is one SCC.

  Time: O(V + E)   Space: O(V)

  Why it works:
    If u and v are in the same SCC, there is a path u->v in
    the original graph AND v->u in the transposed graph.
    The finishing order ensures we start each DFS in pass 2
    from the "source" SCC (no incoming edges from other SCCs).

----------------------------------------------------------------
BIPARTITE CHECK (applicable to both)
----------------------------------------------------------------
A graph is bipartite if vertices can be colored with 2 colors
such that no two adjacent vertices share the same color.

  BFS 2-coloring:
    color[] = -1 (uncolored)
    Assign color 0 to source, color 1 to all neighbors, etc.
    If any neighbor has the same color as current: NOT bipartite.

  boolean isBipartite(List<List<Integer>> adj) {
    int[] color = new int[V];
    Arrays.fill(color, -1);
    for (int i = 0; i < V; i++) {
      if (color[i] != -1) continue;
      Queue<Integer> q = new LinkedList<>();
      color[i] = 0; q.offer(i);
      while (!q.isEmpty()) {
        int node = q.poll();
        for (int nb : adj.get(node)) {
          if (color[nb] == -1) {
            color[nb] = 1 - color[node];
            q.offer(nb);
          } else if (color[nb] == color[node]) return false;
        }
      }
    }
    return true;
  }

  A graph with an ODD-LENGTH CYCLE is NOT bipartite.
  Trees are always bipartite.

----------------------------------------------------------------
INTERVIEW QUESTIONS
----------------------------------------------------------------

Q: How do you detect a cycle in a directed graph vs an
   undirected graph?
A: Directed: Use DFS with 3 states -- UNVISITED (0), IN_STACK (1),
   DONE (2). If you encounter an IN_STACK node while DFS, that's
   a back edge indicating a cycle. DONE nodes are already fully
   processed and safe.
   Undirected: Use DFS with a visited array and parent tracking.
   If a visited neighbor is NOT the current node's parent, it's
   a cycle. Alternatively, use Union-Find: if adding edge (u,v)
   and they're already in the same component, it creates a cycle.

Q: What is the difference between weakly and strongly connected
   directed graphs?
A: Weakly connected: if you ignore edge direction (treat all edges
   as undirected), the resulting graph is connected. There is an
   undirected path between any two vertices.
   Strongly connected: there is a DIRECTED path from u to v AND
   from v to u for every pair of vertices. This is a much stronger
   condition. Algorithms for SCCs: Kosaraju's (2 DFS) and
   Tarjan's (1 DFS with discovery time + low link values).

Q: How do you check if a graph is bipartite?
A: BFS 2-coloring. Assign color 0 to the source, then alternate
   colors level by level. If any neighbor has the same color as
   the current node, the graph is NOT bipartite. Must run this
   for each unvisited component (graph may be disconnected).
   A graph is NOT bipartite if and only if it contains an
   odd-length cycle.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. When building an undirected graph adjacency list, ALWAYS
     add both directions: adj[u].add(v) AND adj[v].add(u)
  2. For directed graphs, only add adj[u].add(v)
  3. Topological sort only applies to DIRECTED ACYCLIC graphs
  4. SCC problems rarely appear in standard interviews but are
     important for senior/system roles -- know Kosaraju's 2-pass
  5. Bipartite check = 2-coloring BFS -- odd cycle = not bipartite
  6. Sum of degrees = 2E is a useful sanity check when debugging
