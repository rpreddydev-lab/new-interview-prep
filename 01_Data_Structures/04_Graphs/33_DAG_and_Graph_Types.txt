================================================================
  DAG AND SPECIAL GRAPH TYPES
================================================================

----------------------------------------------------------------
DIRECTED ACYCLIC GRAPH (DAG)
----------------------------------------------------------------
A DAG is a directed graph with NO directed cycles.

  Properties:
    - At least one vertex with in-degree = 0 (source)
    - At least one vertex with out-degree = 0 (sink)
    - Can be topologically sorted
    - Cannot have negative-cycle issues
    - Shortest/longest paths can be computed in O(V+E)

  Applications:
    Task scheduling (A must complete before B)
    Build systems (Makefile, Maven dependency resolution)
    Git commit history
    Data pipelines (Airflow, Spark)
    Spreadsheet calculations
    Circuit evaluation
    Memoized recursion (DP recurrence DAG)

  Key fact: Every DP with a recurrence can be viewed as
  computing values in topological order of a DAG.

----------------------------------------------------------------
TOPOLOGICAL SORT
----------------------------------------------------------------
A linear ordering of vertices such that for every directed
edge u -> v, u comes before v in the ordering.

  Only defined for DAGs (if cycle exists, no valid ordering).

  METHOD 1: DFS POSTORDER
    DFS from every unvisited node.
    After fully exploring a node (all descendants done),
    push it to a stack.
    Result: reverse the stack = topological order.

    Stack<Integer> stack = new Stack<>();
    boolean[] visited = new boolean[V];
    for (int i = 0; i < V; i++)
      if (!visited[i]) dfsTopSort(i, visited, adj, stack);
    // stack.pop() gives topological order

    void dfsTopSort(int node, boolean[] visited,
                    List<List<Integer>> adj, Stack<Integer> stack) {
      visited[node] = true;
      for (int nb : adj.get(node))
        if (!visited[nb]) dfsTopSort(nb, visited, adj, stack);
      stack.push(node);  // push AFTER all descendants
    }

    Time: O(V + E)

  METHOD 2: KAHN'S BFS (IN-DEGREE)
    Start with all nodes of in-degree 0.
    Process them one by one; decrement in-degree of neighbors.
    When a neighbor's in-degree becomes 0, add to queue.

    int[] inDegree = new int[V];
    for (int u = 0; u < V; u++)
      for (int v : adj.get(u)) inDegree[v]++;

    Queue<Integer> q = new LinkedList<>();
    for (int i = 0; i < V; i++)
      if (inDegree[i] == 0) q.offer(i);

    List<Integer> topoOrder = new ArrayList<>();
    while (!q.isEmpty()) {
      int node = q.poll();
      topoOrder.add(node);
      for (int nb : adj.get(node))
        if (--inDegree[nb] == 0) q.offer(nb);
    }

    // If topoOrder.size() != V: cycle exists
    if (topoOrder.size() < V) // CYCLE DETECTED

    Time: O(V + E)

  DFS vs Kahn's:
    Kahn's naturally detects cycles (processed count < V).
    DFS requires a separate cycle-detection pass.
    Kahn's is easier to implement iteratively.
    DFS gives reverse topological order (need stack or reverse).
    Both are O(V + E).

----------------------------------------------------------------
LONGEST PATH IN A DAG
----------------------------------------------------------------
  In a general graph, longest path is NP-hard.
  In a DAG, it's solvable in O(V + E) using DP + topological sort.

  dist[src] = 0, all others = -INF
  Process vertices in topological order:
    for each vertex u in topo order:
      for each neighbor v of u with weight w:
        dist[v] = max(dist[v], dist[u] + w)

  Application: Critical path method (project scheduling),
  finding the makespan of a parallel task graph.

----------------------------------------------------------------
CRITICAL PATH
----------------------------------------------------------------
  In project scheduling:
    Tasks are vertices, dependencies are directed edges.
    Edge weight = duration of the task.
    Critical path = longest path from start to finish.
    Tasks on the critical path have NO slack -- any delay
    directly delays the project.

  Algorithm: longest path in DAG using topological sort.

----------------------------------------------------------------
SPECIAL GRAPH TYPES
----------------------------------------------------------------
  COMPLETE GRAPH (K_n):
    Every vertex connected to every other vertex.
    V vertices, V*(V-1)/2 edges (undirected).
    Dense by definition.

  BIPARTITE GRAPH:
    Vertices in two sets U and V.
    Every edge connects a vertex in U to a vertex in V.
    No edges within U or within V.
    Check: 2-coloring with BFS/DFS.
    Contains no odd-length cycles.
    Applications: matching, scheduling, network flow.

  PLANAR GRAPH:
    Can be drawn on a plane without edges crossing.
    Euler's formula: V - E + F = 2 (F = faces including outer face)
    Planar graphs: E <= 3V - 6.

  EULERIAN GRAPH:
    Eulerian circuit: cycle that visits every EDGE exactly once.
    Exists if: connected AND all vertices have EVEN degree.
    Eulerian path: visits every edge once (not necessarily circuit).
    Exists if: exactly 0 or 2 vertices have ODD degree.
    Algorithm: Hierholzer's algorithm O(E).

  HAMILTONIAN GRAPH:
    Hamiltonian cycle: cycle that visits every VERTEX exactly once.
    NP-hard to determine in general.
    (Note: Eulerian = edges, Hamiltonian = vertices)

  TOURNAMENT GRAPH:
    Complete directed graph where each pair has exactly one
    directed edge. Used in ranking/sorting theory.

  INTERVAL GRAPH:
    Vertices = intervals [l, r].
    Edges between intervals that overlap.
    Applications: scheduling, register allocation.

----------------------------------------------------------------
INTERVIEW QUESTIONS
----------------------------------------------------------------

Q: What is the difference between Kahn's algorithm and DFS
   topological sort?
A: Both produce a valid topological ordering in O(V+E). Kahn's
   is BFS-based: start with all in-degree-0 nodes, process one
   at a time, decrement neighbors' in-degrees. It naturally
   detects cycles: if the output has fewer than V nodes, a cycle
   exists. DFS-based topological sort uses postorder DFS: push
   nodes to a stack after all their descendants are fully explored,
   then reverse the stack. It requires a separate visited/in-stack
   check for cycle detection.

Q: Why is the longest path problem NP-hard in general but
   solvable in O(V+E) for DAGs?
A: In a general graph, finding the longest simple path is
   equivalent to finding a Hamiltonian path (NP-hard). However,
   in a DAG, there are no cycles so the problem reduces to DP:
   process vertices in topological order and propagate the
   longest distance. Since topological order exists in O(V+E),
   and DP propagation is also O(V+E), the overall complexity
   is O(V+E). This is why DP is so powerful for DAG-structured
   problems.

Q: How do you detect a cycle using Kahn's topological sort?
A: Run Kahn's algorithm to completion. Count how many nodes
   were added to the topological order. If the count equals V
   (all vertices), the graph is acyclic (valid DAG). If the
   count is less than V, at least one cycle exists -- nodes
   in the cycle never reach in-degree 0 and are never processed.
   This is the cleanest cycle detection approach for directed
   graphs.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. For course scheduling problems, build adjacency list +
     in-degree array, then run Kahn's
  2. Kahn's cycle detection (count < V) is cleaner than DFS
     3-coloring for interview settings
  3. Longest path in matrix (LeetCode 329) is a DFS+memo
     problem that uses the DAG structure of the grid implicitly
  4. When you see "ordering" or "dependencies" in a problem,
     think topological sort
  5. DP on trees and DAGs: always process in topological order
     (leaves/sources first, root/sinks last)
  6. Eulerian path: 0 or 2 odd-degree vertices; Eulerian circuit:
     all even-degree. Hamiltonian = NP-hard. Know the distinction.
