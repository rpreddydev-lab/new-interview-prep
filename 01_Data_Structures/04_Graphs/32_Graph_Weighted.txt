================================================================
  WEIGHTED GRAPHS AND SHORTEST PATH ALGORITHMS
================================================================

----------------------------------------------------------------
WHAT IS A WEIGHTED GRAPH?
----------------------------------------------------------------
A weighted graph assigns a numerical value (weight/cost/distance)
to each edge. The weight can represent:
  - Distance between locations
  - Cost of a connection
  - Time to travel
  - Capacity of a pipe
  - Probability

  Representation:
    Adjacency list: adj[u] = list of [neighbor, weight] pairs
    Adjacency matrix: matrix[u][v] = weight (INF if no edge)
    Edge list: (u, v, weight) triples

  Java adjacency list for weighted graph:
    List<int[]>[] adj = new ArrayList[V];  // int[] = {neighbor, weight}
    for (int i = 0; i < V; i++) adj[i] = new ArrayList<>();
    adj[u].add(new int[]{v, w});

----------------------------------------------------------------
DIJKSTRA'S ALGORITHM (non-negative weights)
----------------------------------------------------------------
Finds shortest paths from a source to all other vertices.
Assumption: all edge weights are NON-NEGATIVE.

  Algorithm:
    1. Initialize dist[src] = 0, all others = INF
    2. Use a min-heap PQ of (distance, vertex)
    3. Pop the vertex with minimum distance
    4. For each neighbor: if dist[node] + weight < dist[neighbor]:
       update dist[neighbor] and push to PQ
    5. Continue until PQ is empty

  Java implementation:
    int[] dijkstra(int src, List<int[]>[] adj, int V) {
      int[] dist = new int[V];
      Arrays.fill(dist, Integer.MAX_VALUE);
      dist[src] = 0;
      PriorityQueue<int[]> pq =
          new PriorityQueue<>((a, b) -> a[0] - b[0]);
      pq.offer(new int[]{0, src});
      while (!pq.isEmpty()) {
        int[] curr = pq.poll();
        int d = curr[0], u = curr[1];
        if (d > dist[u]) continue;  // stale entry skip
        for (int[] nb : adj[u]) {
          int v = nb[0], w = nb[1];
          if (dist[u] + w < dist[v]) {
            dist[v] = dist[u] + w;
            pq.offer(new int[]{dist[v], v});
          }
        }
      }
      return dist;
    }

  Time: O((V + E) log V) with binary heap
  Space: O(V)

  Stale entry: Java's PriorityQueue does not support decrease-key.
  When a shorter path is found, we add a new entry and later skip
  the old one with: if (d > dist[u]) continue.

  FAILS with negative weights: a later negative edge could
  improve the distance to an already-finalized node.

----------------------------------------------------------------
BELLMAN-FORD ALGORITHM (negative weights)
----------------------------------------------------------------
Finds shortest paths with negative weight edges.
Detects negative weight cycles.

  Algorithm:
    Relax all edges V-1 times:
    for i from 1 to V-1:
      for each edge (u, v, w):
        if dist[u] + w < dist[v]: dist[v] = dist[u] + w

    Check for negative cycles:
    for each edge (u, v, w):
      if dist[u] + w < dist[v]: NEGATIVE CYCLE EXISTS

  Why V-1 iterations?
    The shortest path between any two vertices has at most V-1 edges
    (in a graph with no negative cycles). After V-1 relaxations,
    all shortest paths are found. If iteration V still relaxes,
    there's a negative cycle (infinite shortest path).

  Time: O(V * E)   Space: O(V)
  Simpler to implement than Dijkstra but much slower.

  Use when: graph has negative edge weights but no negative cycles.
  LeetCode: "Cheapest Flights Within K Stops" -- modified Bellman-Ford
    (limit to K+1 iterations, use copy of dist array each iteration)

----------------------------------------------------------------
FLOYD-WARSHALL ALGORITHM (all-pairs)
----------------------------------------------------------------
Finds shortest paths between ALL pairs of vertices.

  Initialize:
    dist[i][j] = edge weight if edge (i,j) exists
    dist[i][i] = 0
    dist[i][j] = INF if no edge

  DP recurrence:
    dist[i][j] = min(dist[i][j], dist[i][k] + dist[k][j])
    (Can we go through vertex k to improve the i-to-j path?)

  for k from 0 to V-1:
    for i from 0 to V-1:
      for j from 0 to V-1:
        if dist[i][k] != INF && dist[k][j] != INF:
          dist[i][j] = min(dist[i][j], dist[i][k] + dist[k][j])

  Time: O(V^3)   Space: O(V^2)
  Detect negative cycle: dist[i][i] < 0 for some i.

  Use when: dense graph, all-pairs needed, may have negative weights.

----------------------------------------------------------------
MINIMUM SPANNING TREE (MST)
----------------------------------------------------------------
A spanning tree connects all V vertices using exactly V-1 edges
with minimum total weight. Only defined for connected, undirected,
weighted graphs.

  KRUSKAL'S ALGORITHM (edge-based, uses Union-Find):
    1. Sort all edges by weight.
    2. For each edge (u, v, w) in sorted order:
       If u and v are in different components:
         Add edge to MST, union their components.
    3. Stop when MST has V-1 edges.

    Time: O(E log E) for sorting + O(E * alpha(V)) for Union-Find
    Best for: sparse graphs

  PRIM'S ALGORITHM (vertex-based, uses min-heap):
    1. Start from any vertex, mark as visited.
    2. Add all edges from visited set to min-heap.
    3. Pop minimum weight edge where one endpoint is unvisited.
    4. Add to MST, mark new vertex as visited.
    5. Add new vertex's edges to heap.

    Time: O(E log V) with binary heap
    Best for: dense graphs

  Both produce MSTs with same total weight (MST may not be unique).

  Cut property: The minimum weight edge crossing any cut
  (partition of vertices) is always in the MST.

----------------------------------------------------------------
SHORTEST PATH ALGORITHM COMPARISON
----------------------------------------------------------------
  Algorithm        Weights       Time          Best for
  ---------------------------------------------------------------
  BFS              Unweighted    O(V+E)        Unit-weight graphs
  Dijkstra         Non-negative  O((V+E) logV) Single source
  Bellman-Ford     Any (detect)  O(V*E)        Negative weights
  Floyd-Warshall   Any (detect)  O(V^3)        All pairs
  A*               Non-negative  O(E log V)    Grid/heuristic

----------------------------------------------------------------
INTERVIEW QUESTIONS
----------------------------------------------------------------

Q: Why does Dijkstra's fail with negative edge weights?
A: Dijkstra's greedy assumption is that once a vertex is popped
   from the min-heap with distance d, that IS its final shortest
   distance. This holds when all weights are non-negative (the
   distance can only increase as we explore more). With a negative
   edge, a path that was longer early on might become shorter
   after traversing a negative edge later. Use Bellman-Ford
   (which relaxes ALL edges V-1 times) for negative weights.

Q: What is the stale entry problem in Dijkstra's with Java
   PriorityQueue?
A: Java's PriorityQueue doesn't support decrease-key. When we
   find a shorter path to v, we add a new (newDist, v) entry
   rather than updating the old one. The old (larger) entry
   remains in the queue. When it's eventually popped, we check:
   if (d > dist[u]) continue -- the stale entry is discarded.
   This lazy deletion approach is O((V+E) log V) time vs O((V+E)
   log V) for decrease-key (same asymptotic, similar in practice).

Q: How do Kruskal's and Prim's algorithms differ?
A: Kruskal's adds edges: sort all edges by weight, greedily add
   minimum-weight edges that don't form a cycle (checked with
   Union-Find). Works well on sparse graphs, processes edges.
   Prim's adds vertices: start from one vertex, repeatedly add
   the minimum-weight edge connecting the MST to an unvisited
   vertex. Works well on dense graphs, processes vertices.
   Both produce optimal MSTs. Kruskal's is O(E log E), Prim's
   is O(E log V) with a binary heap.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. For Dijkstra in Java: use PriorityQueue<int[]> with
     comparator (a,b) -> a[0] - b[0] and ALWAYS include the
     stale entry check: if (d > dist[u]) continue
  2. Bellman-Ford: "Cheapest Flights Within K Stops" is a key
     problem -- limit to K+1 iterations, copy dist array
  3. Know the constraint: BFS = unweighted, Dijkstra = positive
     weights, Bellman-Ford = negative weights
  4. For MST problems (connect all points with min cost),
     reach for Kruskal's + Union-Find or Prim's + PQ
  5. Floyd-Warshall is O(V^3) -- only feasible for small V
     (100-200 nodes maximum in practice)
