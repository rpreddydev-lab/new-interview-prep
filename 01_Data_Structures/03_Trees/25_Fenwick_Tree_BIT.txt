================================================================
  FENWICK TREE (BINARY INDEXED TREE / BIT)
================================================================

----------------------------------------------------------------
WHAT IS A FENWICK TREE?
----------------------------------------------------------------
A Fenwick Tree (Binary Indexed Tree, BIT) is a data structure
that supports:
  - Point update: update a single element         O(log n)
  - Prefix sum query: sum of arr[1..i]             O(log n)
  - Range sum query: sum of arr[l..r] = prefix(r) - prefix(l-1)

It is stored as a 1-indexed array of size n+1.

  Key insight:
    Each index i in the BIT array stores the sum of a
    specific range of elements. The range is determined by
    the lowest set bit of i:

    Range covered by tree[i] = arr[(i - lowbit(i) + 1) .. i]
    where lowbit(i) = i & (-i)   (isolates lowest set bit)

  Example for n = 8:
    i=1 (001): stores arr[1]         (range 1)
    i=2 (010): stores arr[1..2]      (range 2)
    i=3 (011): stores arr[3]         (range 1)
    i=4 (100): stores arr[1..4]      (range 4)
    i=5 (101): stores arr[5]         (range 1)
    i=6 (110): stores arr[5..6]      (range 2)
    i=7 (111): stores arr[7]         (range 1)
    i=8 (1000): stores arr[1..8]     (range 8)

----------------------------------------------------------------
CORE OPERATIONS
----------------------------------------------------------------
  int[] bit = new int[n + 1];  // 1-indexed

  LOWBIT (lowest set bit):
    int lowbit(int i) { return i & (-i); }
    Examples:
      lowbit(6) = lowbit(110) = 010 = 2
      lowbit(4) = lowbit(100) = 100 = 4
      lowbit(5) = lowbit(101) = 001 = 1

  POINT UPDATE (add delta to arr[i]):
    void update(int i, int delta) {
      for (; i <= n; i += lowbit(i))
        bit[i] += delta;
    }
    Traversal: add lowbit(i) to i to move to parent range
    Example: update(3):
      i=3 (011): update bit[3], then i = 3 + 1 = 4
      i=4 (100): update bit[4], then i = 4 + 4 = 8
      i=8 (1000): update bit[8], then i = 8 + 8 = 16 > n, stop

  PREFIX SUM QUERY (sum of arr[1..i]):
    int query(int i) {
      int sum = 0;
      for (; i > 0; i -= lowbit(i))
        sum += bit[i];
      return sum;
    }
    Traversal: subtract lowbit(i) from i to move to "previous" range
    Example: query(7):
      i=7 (111): add bit[7], then i = 7 - 1 = 6
      i=6 (110): add bit[6], then i = 6 - 2 = 4
      i=4 (100): add bit[4], then i = 4 - 4 = 0, stop
      Result: arr[7] + arr[5..6] + arr[1..4] = arr[1..7]

  RANGE SUM (arr[l..r]):
    int rangeSum(int l, int r) {
      return query(r) - query(l - 1);
    }

  BUILD FROM ARRAY (O(n) or O(n log n)):
    O(n log n): call update(i, arr[i]) for each i
    O(n) method:
      for (int i = 1; i <= n; i++) {
        bit[i] += arr[i];
        int parent = i + lowbit(i);
        if (parent <= n) bit[parent] += bit[i];
      }

----------------------------------------------------------------
WHY i & (-i) ISOLATES THE LOWEST SET BIT
----------------------------------------------------------------
  Two's complement: -i = ~i + 1
  Example: i = 6 = 0110
    ~6 = 1001
    -6 = 1010
    6 & (-6) = 0110 & 1010 = 0010 = 2 (lowest set bit of 6)

  This trick is fundamental to BIT traversal:
    query: clear the lowest set bit  (i -= lowbit)  moves left
    update: set next bit              (i += lowbit) moves to parent

----------------------------------------------------------------
COMPLEXITY
----------------------------------------------------------------
  Operation         Time        Space
  -----------------------------------------
  Build             O(n log n)  O(n)
  Point update      O(log n)    O(1)
  Prefix sum query  O(log n)    O(1)
  Range sum query   O(log n)    O(1)
  Space             O(n)        O(n)

  No extra space beyond the BIT array itself (O(1) per operation).

----------------------------------------------------------------
EXTENDED: POINT UPDATE + RANGE QUERY (standard BIT)
         RANGE UPDATE + POINT QUERY
         RANGE UPDATE + RANGE QUERY
----------------------------------------------------------------
  Standard BIT:
    update(i, delta): add delta to arr[i]
    query(i): prefix sum arr[1..i]

  Range Update + Point Query (using difference array BIT):
    To add val to arr[l..r]: update(l, val), update(r+1, -val)
    Point query arr[i]: query(i) gives the actual value at i

  Range Update + Range Query (two BITs):
    Maintain two BITs: B1 and B2
    Range add val to [l,r]:
      B1.update(l, val),    B1.update(r+1, -val)
      B2.update(l, val*(l-1)), B2.update(r+1, -val*r)
    Prefix sum [1..i]:
      B1.query(i) * i - B2.query(i)
    Range sum [l..r] = prefix(r) - prefix(l-1)

COMMON INTERVIEW PROBLEMS
----------------------------------------------------------------
  Problem                             Technique           Complexity
  ---------------------------------------------------------------
  Range Sum Query (Mutable)           BIT point upd+query O(log n)
  Count of Smaller Numbers After Self BIT + compress      O(n log n)
  Count Inversions                    BIT from right      O(n log n)
  Reverse Pairs                       BIT + compress      O(n log n)
  Range Sum with Updates              BIT standard        O(log n)
  2D BIT Range Sum                    2D BIT              O(log^2 n)

----------------------------------------------------------------
COUNT INVERSIONS PATTERN
----------------------------------------------------------------
Count pairs (i, j) where i < j and arr[i] > arr[j].

  Approach:
    Coordinate compress arr to range [1..n].
    Process arr from right to left.
    For each arr[i]: count how many already-processed values
    are less than arr[i] -> query(arr[i] - 1)
    Then update(arr[i], 1)
    Inversions += query(arr[i] - 1)

  This is the classic BIT interview pattern.
  Time: O(n log n)

----------------------------------------------------------------
FENWICK TREE vs SEGMENT TREE
----------------------------------------------------------------
  Feature                  Fenwick Tree      Segment Tree
  ---------------------------------------------------------------
  Point update             O(log n)          O(log n)
  Range sum query          O(log n)          O(log n)
  Range min/max query      Not supported     O(log n)
  Range update             Only with diff.   O(log n) + lazy
  Build                    O(n) or O(n log n) O(n)
  Space                    O(n)              O(4n)
  Code complexity          Very simple       Moderate-complex
  Constant factor          Smaller           Larger

  Choose Fenwick for range SUM with point updates (simpler).
  Choose Segment Tree for range MIN/MAX or range updates.

----------------------------------------------------------------
INTERVIEW QUESTIONS
----------------------------------------------------------------

Q: Why is the BIT (Fenwick Tree) faster in practice than a
   Segment Tree even though both are O(log n)?
A: Fenwick Tree has a smaller constant factor. The update and
   query loops are very simple (one addition/subtraction of
   lowbit per iteration). No branching, no recursion, and the
   array accesses exhibit good cache behavior. A Segment Tree
   requires 4n space, recursive calls, and more operations per
   level. For range sum queries, BIT is typically 2-3x faster.

Q: What is the i & (-i) trick and why does it work?
A: i & (-i) isolates the lowest set bit of i. In two's
   complement: -i = ~i + 1. When you AND i with -i, all bits
   above the lowest set bit are cleared (they differ between
   i and ~i), and the lowest set bit matches (adding 1 to ~i
   propagates carry up to that bit). This bit tells you the
   range size that tree[i] covers, and is used to move through
   the BIT in both update (i += lowbit) and query (i -= lowbit).

Q: How does BIT count inversions?
A: Process the array from right to left. For each element,
   count how many previously seen elements are smaller (using
   prefix sum query on the BIT). This gives the number of
   inversions with the current element as the larger value.
   Then add 1 to the BIT at the current element's position.
   Coordinate compression maps values to [1..n] first.
   Total time: O(n log n).

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. BIT is 1-indexed -- index 0 is unused, array size = n+1
  2. Always implement: update adds delta (not set), so to
     set arr[i] to new value, update with (newVal - oldVal)
  3. The two traversal directions:
     update goes UP  : i += lowbit(i)
     query  goes DOWN: i -= lowbit(i)
  4. Range query: sum(l,r) = prefix(r) - prefix(l-1)
  5. For competitive programming / inversion count problems,
     always coordinate-compress first if values are large
  6. 2D BIT: for matrix range sum, apply the same lowbit trick
     in both row and column dimensions
