================================================================
  TRIE (PREFIX TREE)
================================================================

----------------------------------------------------------------
WHAT IS A TRIE?
----------------------------------------------------------------
A Trie (from re-TRIE-val) is a tree where each path from the
root to a node represents a prefix. Each node holds children
for possible next characters.

  Key properties:
    - Root represents empty string
    - Each edge represents one character
    - Each node can be an end-of-word marker
    - Common prefixes share path in the tree

  Visualization for words: {"apple", "app", "apt", "bat"}:

    ROOT
     |
     a ------- b
     |         |
     p         a
    / \         |
   p   t        t*
   |*  |*
   l
   |
   e*

  (* = isEndOfWord = true)

  Java node structure:
    class TrieNode {
      TrieNode[] children = new TrieNode[26]; // a-z
      boolean isEnd = false;
    }

  For Unicode or larger alphabets:
    Map<Character, TrieNode> children = new HashMap<>();

----------------------------------------------------------------
COMPLEXITY
----------------------------------------------------------------
  Operation       Time            Space
  ---------------------------------------------------------------
  Insert          O(L)            O(L * 26) per word
  Search          O(L)            O(1) additional
  Prefix search   O(P)            O(1) additional
  Delete          O(L)            O(1) additional
  Space total     O(N * L * 26)   N=words, L=avg length

  L = length of the word/prefix
  Compare to HashMap approach:
    HashSet.contains(): O(L) to compute hash, O(1) lookup
    Trie search: O(L) -- same, BUT Trie enables prefix queries
    and range/autocomplete operations that HashMap cannot.

----------------------------------------------------------------
CORE IMPLEMENTATION
----------------------------------------------------------------
  class Trie {
    TrieNode root = new TrieNode();

    void insert(String word) {
      TrieNode node = root;
      for (char c : word.toCharArray()) {
        int i = c - 'a';
        if (node.children[i] == null)
          node.children[i] = new TrieNode();
        node = node.children[i];
      }
      node.isEnd = true;
    }

    boolean search(String word) {
      TrieNode node = root;
      for (char c : word.toCharArray()) {
        int i = c - 'a';
        if (node.children[i] == null) return false;
        node = node.children[i];
      }
      return node.isEnd;
    }

    boolean startsWith(String prefix) {
      TrieNode node = root;
      for (char c : prefix.toCharArray()) {
        int i = c - 'a';
        if (node.children[i] == null) return false;
        node = node.children[i];
      }
      return true;  // any continuation is valid
    }
  }

----------------------------------------------------------------
EXTENDED PATTERNS
----------------------------------------------------------------

  1. COUNT WORDS WITH PREFIX
     Add a count field to TrieNode.
     Increment on insert, check on prefix query.

  2. DELETE WORD
     Two approaches:
     a. Mark isEnd = false (lazy delete -- node stays)
     b. True delete: DFS, remove node only if no children AND
        not end of another word (post-order cleanup).

  3. AUTOCOMPLETE (Get all words with prefix)
     Find prefix end node via startsWith logic.
     DFS/BFS from that node to collect all words with isEnd=true.
     Collect words by backtracking the current path string.

     void collect(TrieNode node, StringBuilder path, List<String> result) {
       if (node.isEnd) result.add(path.toString());
       for (int i = 0; i < 26; i++) {
         if (node.children[i] != null) {
           path.append((char)('a' + i));
           collect(node.children[i], path, result);
           path.deleteCharAt(path.length() - 1);  // backtrack
         }
       }
     }

  4. WORD SEARCH WITH WILDCARDS
     '.' matches any character:
     boolean search(String word, int i, TrieNode node) {
       if (i == word.length()) return node.isEnd;
       char c = word.charAt(i);
       if (c == '.') {
         for (TrieNode child : node.children)
           if (child != null && search(word, i+1, child))
             return true;
         return false;
       }
       TrieNode next = node.children[c - 'a'];
       return next != null && search(word, i+1, next);
     }

  5. MAXIMUM XOR (Bit Trie)
     Build Trie of 32-bit binary representations of integers.
     For each number, greedily pick the opposite bit at each
     level to maximize XOR.
     Time: O(n * 32) = O(n)

  6. WORD BREAK PROBLEM WITH TRIE
     Build Trie from dictionary. DFS + memoization with Trie
     traversal is O(n^2) time vs O(n^2 * L) without Trie.

COMMON INTERVIEW PROBLEMS
----------------------------------------------------------------
  Problem                             Technique           Complexity
  ---------------------------------------------------------------
  Implement Trie                      Core insert/search  O(L)
  Search Suggestions System           Trie + autocomplete O(n*L)
  Word Search II (board + words)      Trie + DFS on grid  O(m*n*4^L)
  Add and Search Word (wildcards)     Trie + DFS on '.'   O(L * 26)
  Replace Words                       Trie prefix replace O(n*L)
  Maximum XOR of Two Numbers          Bit Trie            O(n)
  Palindrome Pairs                    Trie + palindrome   O(n*L^2)
  Concatenated Words                  Trie + DP           O(n*L^2)
  Longest Word in Dictionary          Trie level scan     O(n*L)
  Design Search Autocomplete          Trie + ranking      O(n*L)
  Short Encoding of Words             Trie suffix check   O(n*L)

----------------------------------------------------------------
TRIE vs HASHSET / HASHMAP
----------------------------------------------------------------
  Feature                  Trie          HashSet/HashMap
  ---------------------------------------------------------------
  Search word              O(L)          O(L) hash compute
  Prefix exists            O(P)          O(n) scan all keys
  Autocomplete             O(P + output) Not efficient
  Wildcard search          O(L * 26^W)   Not efficient
  Space                    O(N*L*26)     O(N*L)
  Sorted order             Yes (DFS)     No (HashMap)
  Implementation           Complex       Trivial

  Trie wins when:
    - Prefix queries needed
    - Autocomplete / search suggestions
    - Wildcard matching
    - Maximum XOR
    - Word Search on a 2D board

  HashSet wins when: only exact lookups needed.

----------------------------------------------------------------
INTERVIEW QUESTIONS
----------------------------------------------------------------

Q: What is the space complexity of a Trie and how can it
   be improved?
A: O(N * L * 26) in the worst case where N = number of words,
   L = average word length, and 26 = alphabet size (fixed-size
   children array). This is often much larger than a HashMap.
   To improve:
   1. Use Map<Character, TrieNode> for sparse children
      (saves space when alphabet is large or words share few prefixes)
   2. Compressed Trie (Patricia Trie): merge chains of nodes
      with only one child into a single edge labeled with a string.
   3. Ternary Search Trie: three children (less, equal, greater)
      instead of 26.

Q: How does Word Search II use a Trie?
A: Build a Trie from all target words. DFS on the 2D grid from
   each cell. At each step, navigate the Trie along the current
   character. If no Trie path exists, prune the DFS. When we
   reach an isEnd node, record the found word and mark isEnd=false
   to avoid duplicates. The Trie prunes branches early when the
   current board path doesn't match any word prefix, reducing
   the naive O(n * 4^L * W) brute force significantly.

Q: What is a Compressed Trie (Patricia Trie)?
A: A compressed Trie merges consecutive nodes that have only one
   child into a single edge with a string label. For example,
   if only one word starts with "qu", instead of two nodes
   (q -> u), there's one edge labeled "qu". This reduces space
   and traversal time for sparse dictionaries. Used in IP routing
   tables and compressed suffix arrays.

Q: How do you find maximum XOR of two numbers using a Trie?
A: Build a Trie using 32-bit binary representations of all numbers
   (from MSB to LSB). For each number, traverse the Trie greedily
   choosing the OPPOSITE bit at each level (to maximize XOR).
   If opposite bit path doesn't exist, take the same bit path.
   Time: O(32n) = O(n), Space: O(32n) = O(n).

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. The TrieNode children array size depends on alphabet:
     26 for lowercase letters, 128 for ASCII, HashMap for Unicode
  2. Always check if children[i] is null before traversing
  3. isEnd flag is what distinguishes a stored word from a prefix
  4. For Word Search II, mark isEnd=false after finding a word
     to avoid duplicate results
  5. Trie is not just for strings -- bit tries are powerful
     for XOR, AND, OR optimization problems
  6. When implementing autocomplete, use DFS from the prefix
     end node with a StringBuilder (backtrack after each branch)
