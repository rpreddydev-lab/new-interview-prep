  N-ARY TREE

----------------------------------------------------------------
WHAT IS AN N-ARY TREE?
----------------------------------------------------------------
An N-ary tree is a tree where each node can have AT MOST N
children (or any number of children in the general case).

  Binary tree: max 2 children per node
  Ternary tree: max 3 children per node
  N-ary tree: max N children per node
  General tree: unlimited children (represented as list)

  Common representations:
    1. List of children:
       class Node {
         int val;
         List<Node> children;
       }

    2. First child, next sibling (binary tree representation):
       class Node {
         int val;
         Node firstChild;   // leftmost child
         Node nextSibling;  // right sibling
       }
       Every N-ary tree can be represented as a binary tree
       using this trick -- space-efficient.

  Visualization:
    N-ary:          1
                 /  |  \
                3   2   4
               / \
              5   6

    First-child/next-sibling representation:
             1
            /
           3 -> 2 -> 4
          /
         5 -> 6

----------------------------------------------------------------
N-ARY TREE TRAVERSALS
----------------------------------------------------------------

  PREORDER (root first, then each child subtree):
    void preorder(Node root, List<Integer> result) {
      if (root == null) return;
      result.add(root.val);
      for (Node child : root.children)
        preorder(child, result);
    }
    Output for above tree: 1, 3, 5, 6, 2, 4

  POSTORDER (children first, then root):
    void postorder(Node root, List<Integer> result) {
      if (root == null) return;
      for (Node child : root.children)
        postorder(child, result);
      result.add(root.val);
    }
    Output: 5, 6, 3, 2, 4, 1

  LEVEL ORDER (BFS):
    List<List<Integer>> levelOrder(Node root) {
      List<List<Integer>> result = new ArrayList<>();
      if (root == null) return result;
      Queue<Node> q = new LinkedList<>();
      q.offer(root);
      while (!q.isEmpty()) {
        int size = q.size();
        List<Integer> level = new ArrayList<>();
        for (int i = 0; i < size; i++) {
          Node node = q.poll();
          level.add(node.val);
          q.addAll(node.children);
        }
        result.add(level);
      }
      return result;
    }

  HEIGHT:
    int height(Node root) {
      if (root == null) return 0;
      int max = 0;
      for (Node child : root.children)
        max = Math.max(max, height(child));
      return 1 + max;
    }

  SIZE (count nodes):
    int size(Node root) {
      if (root == null) return 0;
      int count = 1;
      for (Node child : root.children)
        count += size(child);
      return count;
    }

  SERIALIZE / DESERIALIZE (LeetCode format):
    Serialize: preorder DFS, write children count after each node
    Example: [1, null, 3, 2, 4, null, 5, 6]
    LeetCode uses null to delimit levels in the input format.

----------------------------------------------------------------
FIRST CHILD / NEXT SIBLING TRANSFORMATION
----------------------------------------------------------------
Any N-ary tree can be converted to a binary tree:
  firstChild  = leftmost child in N-ary tree
  nextSibling = right sibling in N-ary tree

  N-ary preorder on the original tree =
  Binary preorder on the transformed tree.

  N-ary postorder on the original tree =
  Binary INORDER on the transformed tree!
  (Surprising fact that comes up in interviews.)

  This representation is used in:
    Unix file system inodes
    DOM tree in browsers
    Compiler abstract syntax trees (AST)
    Huffman coding tree (variable children)

----------------------------------------------------------------
REAL-WORLD APPLICATIONS OF N-ARY TREES
----------------------------------------------------------------
  File system:        directories as nodes, files/dirs as children
  DOM tree:           HTML elements with any number of children
  Company hierarchy:  manager -> multiple direct reports
  JSON/XML tree:      objects/arrays with variable children
  Menu systems:       nested menus of arbitrary depth
  Game trees (Monte Carlo tree search): branching factor > 2
  B-Tree nodes:       M-way nodes in database indexes
  Trie nodes:         up to 26 or more children

COMMON INTERVIEW PROBLEMS
----------------------------------------------------------------
  Problem                             Technique           Complexity
  ---------------------------------------------------------------
  N-ary Tree Preorder Traversal       DFS children loop   O(n)
  N-ary Tree Postorder Traversal      DFS children loop   O(n)
  N-ary Tree Level Order              BFS + q.addAll()    O(n)
  Maximum Depth of N-ary Tree         Recursive height    O(n)
  Serialize / Deserialize N-ary       Preorder + null     O(n)
  Encode N-ary as Binary Tree         FirstChild/Sibling  O(n)
  Count Good Nodes in Binary Tree     DFS + max path      O(n)
  Sum of Nodes with Even-Value Grand  DFS parent tracking O(n)
  Directory Tree (file system)        DFS path sum        O(n)

----------------------------------------------------------------
INTERVIEW QUESTIONS
----------------------------------------------------------------

Q: How do you serialize and deserialize an N-ary tree?
A: One approach: DFS preorder. For each node, write its value
   and the NUMBER OF CHILDREN (not null markers). During
   deserialization, read value + child count, then recursively
   deserialize exactly that many children.
   LeetCode's approach: use null as a level/child-group
   separator, reading groups of siblings.
   Both are O(n) time and space.

Q: What is the first-child/next-sibling representation and
   why is it useful?
A: Every N-ary tree node has two pointers: firstChild (its
   leftmost child) and nextSibling (its right sibling). This
   transforms an N-ary tree into a binary tree using only 2
   pointers per node regardless of the original branching factor.
   It's memory-efficient and allows reuse of binary tree algorithms.
   Interesting fact: N-ary preorder = binary tree preorder;
   N-ary postorder = binary tree INORDER in this representation.

Q: How does an N-ary tree differ from a B-Tree?
A: Both have multiple children per node, but B-Trees have
   strict structural constraints: all leaves at the same level,
   nodes must be at least half full, keys in each node are sorted.
   B-Trees are specifically designed for disk-based storage with
   fixed-size pages and ordered keys. N-ary trees (general trees)
   have no such constraints -- children may be unsorted, the
   tree may be unbalanced, and nodes can have any number of
   children.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. N-ary tree traversals are identical to binary tree
     traversals, just loop over children instead of left/right
  2. BFS: use q.addAll(node.children) instead of individual
     if-null checks -- cleaner for N-ary trees
  3. For height/depth of N-ary tree, max over all children
     instead of max(left, right)
  4. The first-child/next-sibling transformation is a common
     interview trick question -- know that N-ary postorder
     maps to binary INORDER, not binary postorder
  5. Real-world N-ary trees: file systems, DOM, org charts --
     mention these for context in design discussions
