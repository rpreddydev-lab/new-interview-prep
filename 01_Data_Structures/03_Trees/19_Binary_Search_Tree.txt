================================================================
  BINARY SEARCH TREE (BST)
================================================================

----------------------------------------------------------------
WHAT IS A BST?
----------------------------------------------------------------
A Binary Search Tree is a binary tree where every node satisfies:

  LEFT subtree values < node.val < RIGHT subtree values

This property applies RECURSIVELY to every node in the tree.

  Visualization:
           8
          / \
         3   10
        / \    \
       1   6    14
          / \   /
         4   7 13

  BST property check at node 6:
    All nodes in left subtree (4) < 6 < all in right (7). YES.

  Common misconception: left child < root AND right child > root
  is NOT sufficient. The ENTIRE left subtree must be less.
  Counter-example:
           5
          / \
         3   7
          \
           6   <-- 6 > 5, BST property VIOLATED

Java node structure (same as Binary Tree):
  class TreeNode {
    int val;
    TreeNode left, right;
    TreeNode(int val) { this.val = val; }
  }

----------------------------------------------------------------
BST OPERATIONS AND COMPLEXITY
----------------------------------------------------------------
  Operation       Average Case    Worst Case (skewed/degenerate)
  ---------------------------------------------------------------
  Search          O(log n)        O(n)
  Insert          O(log n)        O(n)
  Delete          O(log n)        O(n)
  Min/Max         O(log n)        O(n)
  Inorder         O(n)            O(n)
  Predecessor     O(log n)        O(n)
  Successor       O(log n)        O(n)
  Space           O(n)            O(n)

  Average case assumes a balanced BST (height = O(log n)).
  Worst case: inserting sorted data creates a degenerate tree.

----------------------------------------------------------------
BST OPERATIONS \u2014 CODE PATTERNS
----------------------------------------------------------------

  SEARCH:
    TreeNode search(TreeNode root, int val) {
      if (root == null || root.val == val) return root;
      if (val < root.val) return search(root.left, val);
      return search(root.right, val);
    }

  INSERT (always inserts as a leaf):
    TreeNode insert(TreeNode root, int val) {
      if (root == null) return new TreeNode(val);
      if (val < root.val) root.left = insert(root.left, val);
      else if (val > root.val) root.right = insert(root.right, val);
      return root;  // duplicates ignored
    }

  DELETE (three cases):
    TreeNode delete(TreeNode root, int key) {
      if (root == null) return null;
      if (key < root.val)
        root.left = delete(root.left, key);
      else if (key > root.val)
        root.right = delete(root.right, key);
      else {
        // Case 1: No left child
        if (root.left == null) return root.right;
        // Case 2: No right child
        if (root.right == null) return root.left;
        // Case 3: Two children -> replace with inorder successor
        TreeNode successor = findMin(root.right);
        root.val = successor.val;
        root.right = delete(root.right, successor.val);
      }
      return root;
    }

    TreeNode findMin(TreeNode node) {
      while (node.left != null) node = node.left;
      return node;
    }

  INORDER (produces sorted output from BST):
    void inorder(TreeNode root, List<Integer> result) {
      if (root == null) return;
      inorder(root.left, result);
      result.add(root.val);
      inorder(root.right, result);
    }

  FIND KTH SMALLEST:
    int count = 0, result = 0;
    void kthSmallest(TreeNode root, int k) {
      if (root == null) return;
      kthSmallest(root.left, k);
      count++;
      if (count == k) { result = root.val; return; }
      kthSmallest(root.right, k);
    }

  FIND INORDER SUCCESSOR:
    TreeNode successor(TreeNode root, TreeNode p) {
      TreeNode succ = null;
      while (root != null) {
        if (p.val < root.val) {
          succ = root;       // potential successor
          root = root.left;
        } else {
          root = root.right;
        }
      }
      return succ;
    }

----------------------------------------------------------------
BST VALIDATION
----------------------------------------------------------------
  Common mistake: only check if left.val < root.val AND right.val > root.val
  This misses cases like the subtree violation shown above.

  Correct approach: pass min and max bounds down the tree.

    boolean isValidBST(TreeNode node, long min, long max) {
      if (node == null) return true;
      if (node.val <= min || node.val >= max) return false;
      return isValidBST(node.left, min, node.val) &&
             isValidBST(node.right, node.val, max);
    }
    // call as: isValidBST(root, Long.MIN_VALUE, Long.MAX_VALUE)

  Use long to handle Integer.MIN_VALUE / Integer.MAX_VALUE edge cases.

  Alternative (inorder traversal): verify strictly increasing sequence.
    TreeNode prev = null;
    boolean validate(TreeNode root) {
      if (root == null) return true;
      if (!validate(root.left)) return false;
      if (prev != null && root.val <= prev.val) return false;
      prev = root;
      return validate(root.right);
    }

----------------------------------------------------------------
BALANCED BSTs \u2014 WHY THEY MATTER
----------------------------------------------------------------
  A regular BST degenerates to O(n) if keys are inserted in
  sorted (or nearly sorted) order.

  Example: inserting 1, 2, 3, 4, 5 gives a right-skewed tree:
    1 -> 2 -> 3 -> 4 -> 5  (height = 4, not log 4 = 2)

  Self-balancing BSTs automatically maintain height O(log n):
    AVL Tree:        strict balance (|left_h - right_h| <= 1)
    Red-Black Tree:  relaxed balance, faster insertions
    Splay Tree:      amortized O(log n), recently accessed at root
    B-Tree / B+ Tree: multi-way, used in databases

  Java's TreeMap and TreeSet are backed by Red-Black Trees.
  All operations: O(log n) guaranteed.

----------------------------------------------------------------
BST vs ARRAY vs HASHMAP
----------------------------------------------------------------
  Operation     Sorted Array   HashMap     BST (balanced)
  ---------------------------------------------------------------
  Search        O(log n)       O(1) avg    O(log n)
  Insert        O(n)           O(1) avg    O(log n)
  Delete        O(n)           O(1) avg    O(log n)
  Min / Max     O(1)           O(n)        O(log n)
  Successor     O(log n)       N/A         O(log n)
  Range query   O(log n)+k     O(n)        O(log n)+k
  Sorted order  O(n)           O(n log n)  O(n) inorder

  Use BST when: ordered operations (range, floor, ceiling,
  predecessor, successor) AND dynamic insertions/deletions.

----------------------------------------------------------------
INTERVIEW QUESTIONS
----------------------------------------------------------------

Q: How do you delete a node with two children from a BST?
A: Replace the node's value with either its inorder predecessor
   (largest in left subtree) or inorder successor (smallest in
   right subtree). Then delete that predecessor or successor
   from the respective subtree (it has at most one child,
   making deletion simple). The standard approach uses the
   inorder successor (findMin on right subtree). This preserves
   the BST property because inorder successor > all nodes in
   left subtree and <= all nodes in right subtree.

Q: What is the BST validation gotcha that many candidates miss?
A: Checking only the immediate children (left.val < root.val and
   right.val > root.val) is incorrect. The entire LEFT subtree
   must contain values strictly less than the root, and the
   entire RIGHT subtree must contain values strictly greater.
   The correct solution passes min/max bounds down: every node
   must satisfy min < node.val < max, with bounds tightened at
   each step. Also: use Long bounds to handle nodes with values
   equal to Integer.MIN_VALUE or Integer.MAX_VALUE.

Q: What is the time complexity of BST operations and when
   does the worst case occur?
A: Average case is O(log n) for a balanced BST (height h = log n).
   Worst case is O(n) when the tree is degenerate (skewed) --
   this happens when you insert already-sorted data. For example,
   inserting 1, 2, 3, 4, 5 gives a right-linked list of height 4.
   Self-balancing BSTs (AVL, Red-Black) guarantee O(log n) in all
   cases through rotations after insert/delete.

Q: How is LCA different in a BST vs a general binary tree?
A: In a general binary tree, LCA requires O(n) traversal to find
   both nodes, then walk up to find the split point. In a BST,
   the BST property tells you where to go: if both p and q are
   less than root, LCA is in the left subtree; if both are
   greater, it's in the right subtree; if they split (one left,
   one right), the current node IS the LCA. This gives O(h) time
   and O(1) space iteratively.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. Validate BST using min/max bounds -- NOT just parent check
  2. Always use Long.MIN/MAX_VALUE as initial bounds to handle
     nodes whose values equal Integer.MIN/MAX_VALUE
  3. Inorder traversal of a BST gives sorted output -- use this
     for kth smallest, range sum, and sorted-output problems
  4. LCA in a BST is O(h) and O(1) space iteratively -- much
     simpler than general binary tree LCA
  5. For "sorted array to balanced BST", the recursive midpoint
     approach builds the answer naturally in O(n)
  6. When the interviewer says BST without "balanced", ask if
     balance is guaranteed -- it changes the complexity answer
