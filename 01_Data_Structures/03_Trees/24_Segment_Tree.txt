================================================================
  SEGMENT TREE
================================================================

----------------------------------------------------------------
WHAT IS A SEGMENT TREE?
----------------------------------------------------------------
A Segment Tree is a binary tree used to efficiently answer
range queries and support point/range updates on an array.

  Core use cases:
    - Range sum query:    sum(arr[l..r])  in O(log n)
    - Range min/max query: min(arr[l..r]) in O(log n)
    - Point update:        arr[i] = val   in O(log n)
    - Range update:        all in arr[l..r] += val in O(log n)

  Without segment tree:
    Range query: O(n), Update: O(1)  (naive array)
    Range query: O(1), Update: O(n)  (prefix sum array)
  Segment tree achieves O(log n) for BOTH simultaneously.

  Visualization for arr = [1, 3, 5, 7, 9, 11]:

    Level 0:       [0-5] sum=36
    Level 1:    [0-2]=9     [3-5]=27
    Level 2:  [0-1]=4 [2-2]=5  [3-4]=16  [5-5]=11
    Level 3: [0]=1 [1]=3      [3]=7 [4]=9

  Each node stores the aggregate (sum, min, max) of its range.

  Storage: array of size 4*n (2*nextPow2(n) is exact, 4*n safe)

----------------------------------------------------------------
IMPLEMENTATION — RANGE SUM WITH POINT UPDATE
----------------------------------------------------------------
  int[] tree;  // tree[1] = root (1-indexed)
  int n;

  BUILD:
    void build(int[] arr, int node, int start, int end) {
      if (start == end) {
        tree[node] = arr[start];
      } else {
        int mid = (start + end) / 2;
        build(arr, 2*node, start, mid);
        build(arr, 2*node+1, mid+1, end);
        tree[node] = tree[2*node] + tree[2*node+1];
      }
    }
    // call: build(arr, 1, 0, n-1)
    // Time: O(n)

  POINT UPDATE:
    void update(int node, int start, int end, int idx, int val) {
      if (start == end) {
        tree[node] = val;
      } else {
        int mid = (start + end) / 2;
        if (idx <= mid)
          update(2*node, start, mid, idx, val);
        else
          update(2*node+1, mid+1, end, idx, val);
        tree[node] = tree[2*node] + tree[2*node+1];
      }
    }
    // call: update(1, 0, n-1, i, newVal)
    // Time: O(log n)

  RANGE QUERY:
    int query(int node, int start, int end, int l, int r) {
      if (r < start || end < l) return 0;     // no overlap
      if (l <= start && end <= r) return tree[node]; // full overlap
      int mid = (start + end) / 2;
      int left = query(2*node, start, mid, l, r);
      int right = query(2*node+1, mid+1, end, l, r);
      return left + right;                    // partial overlap
    }
    // call: query(1, 0, n-1, l, r)
    // Time: O(log n)

----------------------------------------------------------------
LAZY PROPAGATION — RANGE UPDATE IN O(log n)
----------------------------------------------------------------
Without lazy propagation, range update (add val to all arr[l..r])
would require O(n) updates. Lazy propagation defers updates.

  Each node stores a "lazy" value = pending update not yet
  pushed to children.

  int[] lazy; // lazy[i] = pending add for node i's entire range

  PUSH DOWN (apply lazy to children):
    void pushDown(int node, int start, int end) {
      if (lazy[node] != 0) {
        int mid = (start + end) / 2;
        // apply to left child
        tree[2*node] += lazy[node] * (mid - start + 1);
        lazy[2*node] += lazy[node];
        // apply to right child
        tree[2*node+1] += lazy[node] * (end - mid);
        lazy[2*node+1] += lazy[node];
        lazy[node] = 0;
      }
    }

  RANGE UPDATE (add val to all elements in [l..r]):
    void rangeUpdate(int node, int start, int end, int l, int r, int val) {
      if (r < start || end < l) return;
      if (l <= start && end <= r) {
        tree[node] += val * (end - start + 1);
        lazy[node] += val;
        return;
      }
      pushDown(node, start, end);
      int mid = (start + end) / 2;
      rangeUpdate(2*node, start, mid, l, r, val);
      rangeUpdate(2*node+1, mid+1, end, l, r, val);
      tree[node] = tree[2*node] + tree[2*node+1];
    }
    // Time: O(log n)

----------------------------------------------------------------
COMPLEXITY
----------------------------------------------------------------
  Operation          Time        Space
  -----------------------------------------
  Build              O(n)        O(n)
  Point update       O(log n)    O(1)
  Range query        O(log n)    O(log n) stack
  Range update       O(log n)*   O(log n) stack
  Space              O(n)        O(n)

  * Range update with lazy propagation.
  Without lazy: range update is O(n).

COMMON INTERVIEW PROBLEMS
----------------------------------------------------------------
  Problem                             Technique           Complexity
  ---------------------------------------------------------------
  Range Sum Query (Mutable)           Point update + query O(log n)
  Range Min/Max Query                 Min segment tree    O(log n)
  Count Smaller Numbers After Self    Seg tree + compress  O(n log n)
  Number of Longest Inc. Subsequence  Seg tree + DP       O(n log n)
  Rectangle Area Union                Coordinate compress O(n log n)
  Falling Squares                     Lazy seg tree       O(n log n)
  My Calendar                         Seg tree / interval  O(n log n)
  Range Update Range Query            Lazy propagation    O(log n)

----------------------------------------------------------------
SEGMENT TREE vs FENWICK TREE (BIT)
----------------------------------------------------------------
  Feature                  Segment Tree      Fenwick Tree
  ---------------------------------------------------------------
  Point update             O(log n)          O(log n)
  Range sum query          O(log n)          O(log n)
  Range min/max query      O(log n)          NOT directly supported
  Range update             O(log n) + lazy   O(log n) (add-only)
  Build                    O(n)              O(n log n) or O(n)
  Space                    O(4n)             O(n)
  Code complexity          Higher            Lower
  Implementation           Recursive/array   Array + bit trick
  For range sum            Both work         BIT simpler
  For range min/max        Segment tree      Segment tree

  Rule of thumb:
    Range SUM + point update: use Fenwick Tree (simpler code)
    Range MIN/MAX: use Segment Tree
    Range update + range query: use Segment Tree + lazy

----------------------------------------------------------------
INTERVIEW QUESTIONS
----------------------------------------------------------------

Q: Why is range query O(log n) in a segment tree?
A: At each level of the tree, the query [l,r] can overlap with
   at most 2 nodes (one on the left boundary, one on the right).
   Since the tree has O(log n) levels, the total number of nodes
   visited is O(4 * log n) = O(log n). The key insight is that
   once a node's range is completely contained in [l,r], we
   return its stored value without descending further.

Q: What is lazy propagation and why is it needed?
A: Lazy propagation enables O(log n) range updates by deferring
   the propagation of updates to children until necessary.
   Without it, updating all elements in a range [l,r] would
   require visiting all O(n) leaf nodes. With lazy propagation,
   we mark entire subtrees as "pending update" when they're
   fully covered by [l,r], and only push the update down when
   we need to visit the children. This keeps range updates O(log n).

Q: How do you choose between a 4n array and a dynamic node
   implementation for segment trees?
A: The 4n array (1-indexed, with left child at 2*node and right
   at 2*node+1) is simpler, faster (cache-friendly), and
   sufficient for most interview problems. Use dynamic nodes
   (objects with left/right pointers) for: sparse segment trees
   (when the range is huge like [0, 10^9] but few actual elements),
   persistent segment trees, or when the tree is built dynamically.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. In interviews, the 4n array implementation is preferred
     for clarity -- state tree size = 4 * n
  2. Always handle the three query cases: no overlap (return 0
     or INF), full overlap (return stored value), partial overlap
     (recurse both children and combine)
  3. For range update problems, mention lazy propagation even
     if you implement the simpler point update version first
  4. Range min/max segment tree is identical to range sum --
     just change the combine operation from + to Math.min/max
  5. Coordinate compression + segment tree solves many
     "count of smaller/larger" problems in O(n log n)
