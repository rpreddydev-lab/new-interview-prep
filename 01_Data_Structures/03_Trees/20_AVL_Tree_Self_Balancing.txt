================================================================
  AVL TREE — SELF-BALANCING BST
================================================================

----------------------------------------------------------------
WHAT IS AN AVL TREE?
----------------------------------------------------------------
An AVL tree (Adelson-Velsky and Landis, 1962) is a self-
balancing Binary Search Tree where the heights of the left
and right subtrees of EVERY node differ by at most 1.

  Balance Factor of a node:
    BF = height(left subtree) - height(right subtree)
    Valid values: -1, 0, +1
    If BF = +2 or -2: tree is UNBALANCED, rotation required.

  Height of a node:
    0 for leaf nodes, -1 for null (empty)
    height(node) = 1 + max(height(left), height(right))

  Key guarantee:
    Height of an AVL tree with n nodes: h = O(log n)
    More precisely: h <= 1.44 * log2(n + 2) - 0.328
    This guarantees O(log n) for ALL operations.

  Visualization (balanced AVL):
           30                   BF(30) = 1 (left h=2, right h=1)
          /  \
        20    40                BF(20) = 0, BF(40) = 0
       /  \
     10    25                  BF(10) = 0, BF(25) = 0

----------------------------------------------------------------
WHY BALANCING IS NEEDED
----------------------------------------------------------------
  If we insert 1, 2, 3 into a plain BST:
    1 -> 2 -> 3  (right skewed, height = 2, O(n) ops)

  AVL detects imbalance at node 1 (BF = -2) and rotates:
        1           2
         \        / \
          2  -->  1   3
           \
            3
  Now height = 1, BF of all nodes valid.

----------------------------------------------------------------
ROTATIONS
----------------------------------------------------------------
AVL uses 4 rotation types to restore balance.
Rotations are O(1) — they just reassign pointers.

  CASE 1: RIGHT ROTATION (LL imbalance)
    When: node is left-heavy (BF = +2) AND left child is
          left-heavy or balanced (BF >= 0)

        z                   y
       / \                 / \
      y   T4     -->      x   z
     / \                 /\  /\
    x   T3              T1 T2 T3 T4
   / \
  T1  T2

    TreeNode rightRotate(TreeNode z) {
      TreeNode y = z.left;
      TreeNode T3 = y.right;
      y.right = z;
      z.left = T3;
      updateHeight(z);
      updateHeight(y);
      return y;   // new root of this subtree
    }

  CASE 2: LEFT ROTATION (RR imbalance)
    When: node is right-heavy (BF = -2) AND right child is
          right-heavy or balanced (BF <= 0)

        z                     y
       / \                   / \
      T1   y      -->        z   x
          / \               /\  /\
         T2  x            T1 T2 T3 T4
            / \
           T3  T4

    TreeNode leftRotate(TreeNode z) {
      TreeNode y = z.right;
      TreeNode T2 = y.left;
      y.left = z;
      z.right = T2;
      updateHeight(z);
      updateHeight(y);
      return y;
    }

  CASE 3: LEFT-RIGHT ROTATION (LR imbalance)
    When: BF = +2 AND left child BF = -1
    Fix: left-rotate left child, then right-rotate current node.

        z                 z               x
       / \               / \            /   \
      y   T4  -->       x   T4  -->   y      z
     / \               / \           / \    / \
    T1   x            y   T3        T1  T2 T3  T4
        / \          / \
       T2  T3       T1  T2

  CASE 4: RIGHT-LEFT ROTATION (RL imbalance)
    When: BF = -2 AND right child BF = +1
    Fix: right-rotate right child, then left-rotate current node.

  Summary table:
    BF of node  BF of child   Rotation
    -------------------------------------------
    +2          +1 or 0       Right Rotate
    +2          -1            Left-Right Rotate
    -2          -1 or 0       Left Rotate
    -2          +1            Right-Left Rotate

----------------------------------------------------------------
INSERT IN AVL TREE
----------------------------------------------------------------
  1. Insert as in a regular BST.
  2. On the way back up the recursion, update heights.
  3. Check balance factor at each ancestor.
  4. If unbalanced, apply the appropriate rotation.
  5. At most 1 rotation (or double rotation) needed per insert.

  TreeNode insert(TreeNode node, int val) {
    if (node == null) return new AVLNode(val);
    if (val < node.val)
      node.left = insert(node.left, val);
    else if (val > node.val)
      node.right = insert(node.right, val);
    else return node;  // no duplicates

    updateHeight(node);
    return balance(node);  // checks BF, applies rotation if needed
  }

  int getHeight(TreeNode node) {
    return node == null ? -1 : ((AVLNode)node).height;
  }

  void updateHeight(TreeNode node) {
    ((AVLNode)node).height =
        1 + Math.max(getHeight(node.left), getHeight(node.right));
  }

  int getBF(TreeNode node) {
    return getHeight(node.left) - getHeight(node.right);
  }

  TreeNode balance(TreeNode node) {
    int bf = getBF(node);
    if (bf > 1) {  // left heavy
      if (getBF(node.left) < 0)  // LR case
        node.left = leftRotate(node.left);
      return rightRotate(node);  // LL case
    }
    if (bf < -1) {  // right heavy
      if (getBF(node.right) > 0)  // RL case
        node.right = rightRotate(node.right);
      return leftRotate(node);  // RR case
    }
    return node;  // already balanced
  }

----------------------------------------------------------------
COMPLEXITY
----------------------------------------------------------------
  Operation     Time        Space
  -----------------------------------------
  Search        O(log n)    O(log n) stack
  Insert        O(log n)    O(log n) stack
  Delete        O(log n)    O(log n) stack
  Rotation      O(1)        O(1)
  Space total   O(n)        O(n)

  Rotations per insert: at most 1 (or double rotation)
  Rotations per delete: up to O(log n) rotations
  (unlike insert, delete may require rebalancing all ancestors)

----------------------------------------------------------------
AVL vs RED-BLACK TREE
----------------------------------------------------------------
  Feature                  AVL Tree          Red-Black Tree
  ---------------------------------------------------------------
  Balance guarantee        Strict (BF -1..1) Relaxed (~2x height)
  Height bound             1.44 * log n      2 * log n
  Lookup performance       Faster (shorter)  Slightly slower
  Insert rotations         At most 1         At most 2
  Delete rotations         O(log n)          At most 3
  Write-heavy workloads    Slower            Faster
  Read-heavy workloads     Faster            Slightly slower
  Used in Java             No                Yes (TreeMap/TreeSet)
  Used in Linux kernel     No                Yes
  Used in databases        Sometimes         Often

  AVL preferred for: read-heavy, lookup-dominated workloads
  Red-Black preferred for: write-heavy, insertions/deletions

----------------------------------------------------------------
INTERVIEW QUESTIONS
----------------------------------------------------------------

Q: Why does AVL use 1.44 * log n height and why does it matter?
A: The worst-case AVL tree is a "Fibonacci tree" -- minimum-node
   AVL tree of a given height. Solving the recurrence N(h) =
   N(h-1) + N(h-2) + 1 (similar to Fibonacci) gives height
   h <= 1.44 * log2(n + 2). This is a constant factor above
   the theoretical minimum log2(n), ensuring all operations
   stay O(log n) in the worst case.

Q: When is a Left-Right (LR) rotation needed?
A: LR rotation is needed when a node has balance factor +2
   (left-heavy) but its left child has balance factor -1
   (right-heavy). The LR rotation is a two-step process:
   first left-rotate the left child to convert it to the LL
   case, then right-rotate the unbalanced node. It arises when
   inserting into the RIGHT subtree of the LEFT child.

Q: How many rotations are needed for insert vs delete in AVL?
A: For insert: at most 1 rotation (single or double). After
   one rotation, the subtree's height is restored to what it
   was before the insert, so no further rebalancing is needed
   up the tree. For delete: up to O(log n) rotations may be
   needed because each rotation might not fully restore height,
   requiring rebalancing further up the tree.

Q: Does Java have a built-in AVL Tree?
A: No. Java's TreeMap and TreeSet are backed by Red-Black Trees,
   not AVL Trees. If you need an AVL tree in Java, you implement
   it yourself. For interview purposes, TreeMap gives you the
   sorted key operations (floor, ceiling, range) with O(log n)
   performance using a Red-Black Tree underneath.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. Know all 4 rotation cases by name (LL/RR/LR/RL) and
     which direction(s) to rotate for each
  2. The balance factor rule: BF = height(left) - height(right)
     must be in {-1, 0, +1} for every node
  3. Insert needs at most 1 rotation -- a common interview
     question distinguishes this from delete's O(log n)
  4. Height of null = -1 (not 0) to make leaf height = 0
  5. AVL vs Red-Black: AVL is faster for lookups, Red-Black
     for writes -- Java chose Red-Black for TreeMap
  6. In system design questions, AVL trees can be mentioned
     for in-memory sorted dictionaries requiring fast reads
