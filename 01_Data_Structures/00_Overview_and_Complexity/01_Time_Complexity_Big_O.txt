================================================================
  TIME COMPLEXITY & BIG-O NOTATION
================================================================

----------------------------------------------------------------
WHAT IS TIME COMPLEXITY?
----------------------------------------------------------------
Time complexity describes how the runtime of an algorithm
grows relative to the size of its input (n).

It does NOT measure actual time in seconds — it measures
the RATE OF GROWTH as input scales.

----------------------------------------------------------------
WHY IT MATTERS
----------------------------------------------------------------
  - n = 100 might feel fast for any algorithm
  - n = 1,000,000 will expose O(n²) algorithms immediately
  - Interviews test whether you can reason about scale

----------------------------------------------------------------
BIG-O NOTATION
----------------------------------------------------------------
Big-O expresses the UPPER BOUND (worst case) of an algorithm.

  O(1)        Constant     - does not depend on input size
  O(log n)    Logarithmic  - halves the problem each step
  O(n)        Linear       - one operation per input element
  O(n log n)  Linearithmic - typical for efficient sorts
  O(n²)       Quadratic    - nested loops over input
  O(n³)       Cubic        - triple nested loops
  O(2^n)      Exponential  - each step doubles work
  O(n!)       Factorial    - all permutations

----------------------------------------------------------------
COMPLEXITY GROWTH (n = 16 as example)
----------------------------------------------------------------
  Notation     Operations (approx)
  ---------------------------------------------------------------
  O(1)         1
  O(log n)     4
  O(n)         16
  O(n log n)   64
  O(n²)        256
  O(2^n)       65,536
  O(n!)        20,922,789,888,000

----------------------------------------------------------------
RULES FOR CALCULATING BIG-O
----------------------------------------------------------------

RULE 1 - Drop Constants
  O(2n)    --> O(n)
  O(500)   --> O(1)

RULE 2 - Drop Non-Dominant Terms
  O(n² + n)    --> O(n²)
  O(n + log n) --> O(n)

RULE 3 - Different Inputs = Different Variables
  Two separate arrays a and b:
    NOT O(n²) — it is O(a * b)

RULE 4 - Sequential steps ADD
  Step 1 is O(n), Step 2 is O(m)  --> O(n + m)

RULE 5 - Nested steps MULTIPLY
  Loop inside a loop              --> O(n * m) or O(n²)

----------------------------------------------------------------
COMMON EXAMPLES
----------------------------------------------------------------

  O(1)   - Array index access: arr[5]
           HashMap get/put
           Stack push/pop

  O(log n) - Binary search
             BST search (balanced)
             Heap insert/delete

  O(n)   - Linear search
           Iterating through array or list
           HashMap contains (worst case with collisions)

  O(n log n) - Merge Sort
               Heap Sort
               Quick Sort (average)

  O(n²)  - Bubble Sort, Selection Sort, Insertion Sort
           Nested loop over same input

  O(2^n) - Recursive subset generation
           Fibonacci with naive recursion

  O(n!)  - Generating all permutations

----------------------------------------------------------------
BEST / AVERAGE / WORST CASE
----------------------------------------------------------------
  Big-O  = worst case  (most commonly discussed)
  Big-Ω  = best case
  Big-Θ  = tight bound (both upper and lower)

  Example: Linear Search on array of n elements
    Best case    O(1)  - element is at index 0
    Average case O(n/2) --> O(n)
    Worst case   O(n)  - element is last or not found

  In interviews, default to discussing WORST CASE unless
  explicitly asked otherwise.

----------------------------------------------------------------
AMORTIZED COMPLEXITY
----------------------------------------------------------------
Amortized analysis looks at the average cost per operation
over a sequence of operations — not just the worst single call.

  Example: ArrayList dynamic resize
    Most add() calls are O(1)
    Occasional resize doubles capacity (O(n) copy)
    Amortized cost per add = O(1)

  Example: StringBuilder vs String concatenation
    String concat in loop = O(n²) total (new object each time)
    StringBuilder append  = O(n) total (amortized O(1) per call)

----------------------------------------------------------------
SPACE COMPLEXITY
----------------------------------------------------------------
Space complexity measures auxiliary memory used by the algorithm
(not counting the input itself, unless specified).

  O(1)   - No extra space (in-place operations)
  O(n)   - Store n elements (new array, recursion stack depth n)
  O(log n) - Recursion stack for binary search / divide & conquer

  Recursion depth contributes to space complexity.
  A recursive DFS on a tree of height h uses O(h) stack space.

----------------------------------------------------------------
COMPLEXITY OF SORTING ALGORITHMS
----------------------------------------------------------------
  Algorithm       Best        Average     Worst       Space
  ---------------------------------------------------------------
  Bubble Sort     O(n)        O(n²)       O(n²)       O(1)
  Selection Sort  O(n²)       O(n²)       O(n²)       O(1)
  Insertion Sort  O(n)        O(n²)       O(n²)       O(1)
  Merge Sort      O(n log n)  O(n log n)  O(n log n)  O(n)
  Quick Sort      O(n log n)  O(n log n)  O(n²)       O(log n)
  Heap Sort       O(n log n)  O(n log n)  O(n log n)  O(1)
  Counting Sort   O(n + k)    O(n + k)    O(n + k)    O(k)
  Radix Sort      O(nk)       O(nk)       O(nk)       O(n + k)

----------------------------------------------------------------
INTERVIEW QUESTIONS
----------------------------------------------------------------

Q: What is the difference between O(n) and O(log n)?
A: O(n) grows linearly — one step per element. O(log n) grows
   logarithmically — the problem is halved each step.
   Binary search on 1 million elements takes ~20 steps (log2 1M).

Q: Why do we drop constants in Big-O?
A: Big-O describes growth rate at scale. At large n, constant
   factors become irrelevant. O(2n) and O(n) have the same
   growth curve — both are linear.

Q: What is the time complexity of accessing an element in a
   HashMap vs a TreeMap?
A: HashMap: O(1) average, O(n) worst (hash collisions)
   TreeMap:  O(log n) always (backed by a Red-Black Tree)

Q: How do you calculate complexity for recursive algorithms?
A: Use the recurrence relation.
   T(n) = T(n/2) + O(1)   --> O(log n)   (binary search)
   T(n) = 2T(n/2) + O(n)  --> O(n log n) (merge sort)
   T(n) = T(n-1) + O(1)   --> O(n)       (linear recursion)
   T(n) = 2T(n-1)         --> O(2^n)     (naive fibonacci)

Q: What is amortized O(1)?
A: An operation that is occasionally expensive but cheap on
   average across many calls. ArrayList.add() is amortized O(1)
   because array resizing happens rarely.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. Always state time AND space complexity for your solution
  2. Mention best/average/worst if the interviewer probes
  3. Know why HashMap is O(1) avg but O(n) worst
  4. Understand that recursion adds to space complexity
  5. Practice explaining trade-offs: O(n log n) sort vs O(n²)
     with early termination — context matters
