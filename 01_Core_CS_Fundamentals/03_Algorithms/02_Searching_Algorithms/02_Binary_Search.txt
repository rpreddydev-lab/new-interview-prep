  BINARY SEARCH

----------------------------------------------------------------
WHAT IS BINARY SEARCH?
----------------------------------------------------------------
Binary Search finds a target in a SORTED array by repeatedly
halving the search space.

  Invariant: target, if exists, is always in [left, right].
  Each iteration: compare target with mid, eliminate half.

  Time:  O(log n)   Space: O(1) iterative, O(log n) recursive
  Requires: SORTED array or a MONOTONIC property

----------------------------------------------------------------
THREE TEMPLATES (the most important distinction)
----------------------------------------------------------------
  TEMPLATE 1: Basic (exact match)
    int binarySearch(int[] nums, int target) {
      int left = 0, right = nums.length - 1;
      while (left <= right) {
        int mid = left + (right - left) / 2;  // avoid overflow
        if (nums[mid] == target) return mid;
        else if (nums[mid] < target) left = mid + 1;
        else right = mid - 1;
      }
      return -1;
    }
    Exit condition: left > right (search space exhausted)
    Use when: exact match required

  TEMPLATE 2: Left boundary (first occurrence / lower bound)
    int lowerBound(int[] nums, int target) {
      int left = 0, right = nums.length;
      while (left < right) {
        int mid = left + (right - left) / 2;
        if (nums[mid] < target) left = mid + 1;
        else right = mid;   // include mid in right half (potential answer)
      }
      return left;  // first index where nums[index] >= target
    }
    Exit: left == right, points to first element >= target
    If left == nums.length: target not found
    If nums[left] != target: target not in array

  TEMPLATE 3: Right boundary (last occurrence / upper bound)
    int upperBound(int[] nums, int target) {
      int left = 0, right = nums.length;
      while (left < right) {
        int mid = left + (right - left) / 2;
        if (nums[mid] <= target) left = mid + 1;
        else right = mid;
      }
      return left - 1;  // last index where nums[index] <= target
    }
    Exit: left == right, return left-1 for last occurrence

----------------------------------------------------------------
OVERFLOW PREVENTION
----------------------------------------------------------------
  WRONG: mid = (left + right) / 2
    When left = 1.5B and right = 1.5B: left+right overflows int!

  CORRECT: mid = left + (right - left) / 2
    Equivalent but subtraction never overflows since right >= left.

  Also valid in Java: mid = (left + right) >>> 1
    Unsigned right shift handles overflow correctly.

----------------------------------------------------------------
BINARY SEARCH ON ROTATED SORTED ARRAY (LC 33)
----------------------------------------------------------------
  One half is always sorted. Determine which half target falls in.

  int search(int[] nums, int target) {
    int left = 0, right = nums.length - 1;
    while (left <= right) {
      int mid = left + (right - left) / 2;
      if (nums[mid] == target) return mid;
      if (nums[left] <= nums[mid]) {  // left half is sorted
        if (nums[left] <= target && target < nums[mid]) right = mid - 1;
        else left = mid + 1;
      } else {  // right half is sorted
        if (nums[mid] < target && target <= nums[right]) left = mid + 1;
        else right = mid - 1;
      }
    }
    return -1;
  }

----------------------------------------------------------------
FIND FIRST AND LAST POSITION (LC 34)
----------------------------------------------------------------
  int[] searchRange(int[] nums, int target) {
    return new int[]{
      lowerBound(nums, target),  // first occurrence
      upperBound(nums, target)   // last occurrence
    };
  }

----------------------------------------------------------------
INTERVIEW QUESTIONS
----------------------------------------------------------------

Q: Why use left + (right - left) / 2 instead of (left + right) / 2?
A: If left and right are both large (close to Integer.MAX_VALUE),
   left + right overflows a 32-bit int. left + (right - left) / 2
   is mathematically equivalent but safe because right - left >= 0
   and is much smaller than MAX_VALUE. In Java, Integer.MAX_VALUE
   is 2^31 - 1 = 2.147 billion. Two values near that overflow.

Q: What is the loop invariant for binary search?
A: The target, if it exists, always lies in the range [left, right]
   (or [left, right) for the lower/upper bound templates).
   Initially the full array satisfies this. Each iteration, we
   check mid. If nums[mid] == target: found. Otherwise we shrink
   the search space while preserving the invariant. When the
   loop terminates (left > right), the invariant guarantees
   the target is not present.

Q: How many iterations does binary search take for n = 10^9?
A: log2(10^9) ≈ 30 iterations. That's why binary search on the
   answer can solve problems with answer space up to 10^9 in
   30 * O(check) time. This is extremely fast.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. The #1 binary search bug: off-by-one errors in the boundary.
     Decide: right = length (exclusive) or right = length-1 (inclusive)
     and be CONSISTENT with your loop condition (< vs <=)
  2. Template 2 and 3 (lower/upper bound) use right = nums.length
     (exclusive), loop condition: left < right
  3. Always check: does your mid calculation avoid overflow?
  4. For "find minimum / maximum satisfying condition" problems:
     use Binary Search on Answer (see 02_Binary_Search_on_Answer.txt)
  5. When you see a sorted array in an interview problem,
     immediately think "can I binary search here?"
