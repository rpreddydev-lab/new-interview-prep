================================================================
  BINARY SEARCH ON ANSWER
================================================================

----------------------------------------------------------------
WHAT IS BINARY SEARCH ON ANSWER?
----------------------------------------------------------------
Instead of searching for a value in an array, we binary search
on the ANSWER SPACE itself when:

  1. The answer lies in a monotonic range [lo, hi]
  2. We can write a feasibility function: isFeasible(mid)
     that returns true/false in O(n) or O(n log n)
  3. The function is MONOTONIC: once true (or false), it stays
     that way as mid increases/decreases

  Pattern:
    int lo = minPossibleAnswer;
    int hi = maxPossibleAnswer;
    while (lo < hi) {
      int mid = lo + (hi - lo) / 2;
      if (isFeasible(mid)) hi = mid;   // can do better (find minimum)
      else lo = mid + 1;               // too small
    }
    return lo;  // minimum feasible answer

  For MAXIMUM feasible answer: flip the condition.

----------------------------------------------------------------
EXAMPLE 1: KOKO EATING BANANAS (LC 875)
----------------------------------------------------------------
  Problem: n piles of bananas, h hours. Find minimum eating speed
  k (bananas/hour) such that all piles eaten in h hours.

  Answer space: [1, max(piles)]
  Feasibility: can Koko eat all piles at speed k in h hours?
    -> ceil(pile/k) hours per pile, sum up, check <= h
    Time: O(n)

  boolean canFinish(int[] piles, int k, int h) {
    int hours = 0;
    for (int pile : piles) hours += (pile + k - 1) / k;  // ceil(pile/k)
    return hours <= h;
  }

  int minEatingSpeed(int[] piles, int h) {
    int lo = 1, hi = Arrays.stream(piles).max().getAsInt();
    while (lo < hi) {
      int mid = lo + (hi - lo) / 2;
      if (canFinish(piles, mid, h)) hi = mid;
      else lo = mid + 1;
    }
    return lo;
  }

  Time: O(n log(max_pile))  Space: O(1)

----------------------------------------------------------------
EXAMPLE 2: SPLIT ARRAY LARGEST SUM (LC 410)
----------------------------------------------------------------
  Problem: Split array into m subarrays to minimize the maximum sum.

  Answer space: [max(nums), sum(nums)]
  Feasibility: can we split into m parts each with sum <= mid?

  boolean canSplit(int[] nums, int m, int maxSum) {
    int parts = 1, current = 0;
    for (int n : nums) {
      if (current + n > maxSum) { parts++; current = 0; }
      current += n;
    }
    return parts <= m;
  }

  int splitArray(int[] nums, int m) {
    int lo = Arrays.stream(nums).max().getAsInt();
    int hi = Arrays.stream(nums).sum();
    while (lo < hi) {
      int mid = lo + (hi - lo) / 2;
      if (canSplit(nums, m, mid)) hi = mid;
      else lo = mid + 1;
    }
    return lo;
  }

  Time: O(n log(sum))  Space: O(1)

EXAMPLE 3: MINIMUM DAYS TO MAKE M BOUQUETS (LC 1482)
----------------------------------------------------------------
  Answer space: [1, max_day]
  Feasibility: on day `mid`, can we make m bouquets of k flowers
  from consecutive bloomed flowers?
  Binary search on the day.

----------------------------------------------------------------
COMMON PATTERNS TO RECOGNIZE
----------------------------------------------------------------
  Signal in problem:                        Technique
  ---------------------------------------------------------------
  "Minimum ... such that ..."               BS on answer (find minimum)
  "Maximum ... such that ..."               BS on answer (find maximum)
  "Minimize the maximum"                    BS on answer
  "Maximize the minimum"                    BS on answer
  "Can we complete in time t?"              BS on t
  "k workers/machines, minimize time"       BS on time
  Capacity assignment problems              BS on capacity

----------------------------------------------------------------
INTERVIEW QUESTIONS
----------------------------------------------------------------

Q: How do you set lo and hi for binary search on answer?
A: lo = smallest possible answer (usually 1 or min element)
   hi = largest possible answer (usually max element, sum, or n)
   The range must CONTAIN the answer. It's better to be wider
   (lo=0, hi=MAX) than to miss the answer.
   If hi is very large (like 10^9), the search still only takes
   log2(10^9) ≈ 30 iterations -- still fast.

Q: Why must the feasibility function be monotonic?
A: Binary search eliminates half the search space based on the
   mid value. This only works if the answer space has the property:
   all values <= answer are infeasible, all values >= answer are
   feasible (or vice versa). If the function alternates true/false,
   binary search might eliminate the correct answer.
   Monotonicity usually comes from the physical constraints of
   the problem (more time/capacity always helps, never hurts).

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. Recognition: "minimize maximum" or "maximize minimum" are
     almost always binary search on answer
  2. The feasibility check must be O(n) or O(n log n) for the
     overall solution to be efficient
  3. Setting lo/hi: be generous -- wider range doesn't hurt much
     (only a few extra iterations of log)
  4. Always verify monotonicity: "if mid works, does mid+1 also work?"
  5. The template for minimum: hi = mid when feasible
     The template for maximum: lo = mid+1 when infeasible
