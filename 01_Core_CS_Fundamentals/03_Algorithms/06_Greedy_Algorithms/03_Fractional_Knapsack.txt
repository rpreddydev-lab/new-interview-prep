================================================================
  FRACTIONAL KNAPSACK
================================================================

----------------------------------------------------------------
PROBLEM
----------------------------------------------------------------
Knapsack capacity W. Items: weight[i], value[i].
You can take FRACTIONS of items.
Maximize total value.

  Greedy: sort by VALUE/WEIGHT ratio (value density), descending.
  Take items greedily until bag is full.
  For the last partial item: take as much as fits.

  double fractionalKnapsack(int W, int[] weight, int[] value) {
    int n = weight.length;
    Integer[] idx = new Integer[n];
    for (int i = 0; i < n; i++) idx[i] = i;
    // Sort by value/weight ratio descending
    Arrays.sort(idx, (a, b) -> Double.compare((double)value[b]/weight[b],
                                              (double)value[a]/weight[a]));
    double totalValue = 0;
    int remaining = W;
    for (int i : idx) {
      if (weight[i] <= remaining) {
        totalValue += value[i];      // take full item
        remaining -= weight[i];
      } else {
        totalValue += (double)value[i] / weight[i] * remaining;  // take fraction
        break;
      }
    }
    return totalValue;
  }

  Time: O(n log n)  Space: O(n)

----------------------------------------------------------------
FRACTIONAL vs 0-1 KNAPSACK
----------------------------------------------------------------
  Feature             Fractional Knapsack    0-1 Knapsack
  -----------------------------------------------------------
  Items               Can split               Cannot split
  Algorithm           Greedy (sort by ratio)  Dynamic Programming
  Time                O(n log n)              O(nW)
  Correctness         Greedy is optimal       Greedy fails

  WHY GREEDY FAILS FOR 0-1:
  Items: (weight=10, value=60), (weight=20, value=100), (weight=30, value=120)
  W = 50
  Greedy by ratio: 6, 5, 4 -> pick item1(60)+item2(100)+partial_item3
    But 0-1: must pick whole items.
    Greedy picks item1+item2 = 160; optimal is item2+item3 = 220. WRONG!

  0-1 Knapsack requires DP:
    dp[i][w] = max value using first i items with capacity w
    dp[i][w] = max(dp[i-1][w], dp[i-1][w-weight[i]] + value[i])

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. Fractional = greedy by value/weight ratio (density)
  2. 0-1 = DP (greedy fails; cannot take fractions)
  3. Greedy choice proof: taking highest-density item first cannot
     be improved -- exchange argument with any other choice shows
     swapping to higher-density first improves or maintains value
  4. Fractional Knapsack is the textbook greedy problem;
     0-1 Knapsack is the textbook DP problem
  5. If asked in interview: always clarify fractional or 0-1 first
