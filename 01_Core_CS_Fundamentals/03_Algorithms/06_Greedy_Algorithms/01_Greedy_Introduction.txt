================================================================
  GREEDY ALGORITHMS -- INTRODUCTION
================================================================

----------------------------------------------------------------
WHAT IS A GREEDY ALGORITHM?
----------------------------------------------------------------
At each step, make the LOCALLY OPTIMAL choice hoping to reach
a GLOBALLY OPTIMAL solution.

  Key properties for correctness:
  1. GREEDY CHOICE PROPERTY: A global optimum can be reached
     by making locally optimal choices at each step
  2. OPTIMAL SUBSTRUCTURE: Optimal solution contains optimal
     solutions to subproblems

  Greedy works when: choosing the best option now doesn't
  prevent better options later.
  Greedy fails when: a locally good choice leads to a globally
  suboptimal outcome (use DP instead).

----------------------------------------------------------------
EXCHANGE ARGUMENT (PROOF TECHNIQUE)
----------------------------------------------------------------
To prove greedy correctness:
  1. Assume some optimal solution OPT exists that differs from
     greedy solution G
  2. Find the FIRST point where they differ
  3. Show you can exchange OPT's choice with G's choice
     without making the solution worse
  4. By repeated exchange, transform OPT into G
     without increasing cost (or decreasing value)
  5. Therefore G is also optimal

----------------------------------------------------------------
WHEN GREEDY WORKS (COMMON PATTERNS)
----------------------------------------------------------------
  Pattern                          Example
  -------------------------------------------------------
  Sort by value/ratio/end time     Activity Selection, Fractional Knapsack
  Always take minimum/maximum       Huffman encoding, Prim's MST
  Interval scheduling              Meeting Rooms, Non-overlapping Intervals
  Always move forward              Jump Game, Gas Station
  Locally obvious choice           Coin change (with specific coins like {1,5,10,25})

  WARNING: Coin change with arbitrary denominations -> DP not greedy!
  US coins (1,5,10,25): greedy works.
  Coins (1,3,4): greedy picks 4,1 for 6 (2 coins); optimal is 3,3 (2 coins -- tied).
  But coins (1,3,4) for target 6: greedy gets 4+1+1=3 coins vs optimal 3+3=2 coins. FAILS!

----------------------------------------------------------------
COMPARISON: GREEDY vs DP
----------------------------------------------------------------
  Feature              Greedy              DP
  --------------------------------------------------------
  Considers future     No                  Yes
  Revises decisions    No                  Yes (implicit)
  Time complexity      Usually O(n log n)  Usually O(n^2) or more
  Space                O(1) to O(n)        O(n) to O(n^2)
  Correctness          Only for certain    Always optimal
  Proof requirement    Exchange argument   Substructure + recurrence

  Decision: if you can prove greedy choice property -> use greedy
  Otherwise: DP or backtracking.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. Always justify WHY greedy works (greedy choice property)
     Not just "it seems right" -- interviewers will probe
  2. Common greedy signal: "maximize/minimize" + sort by some criteria
  3. Counterexamples kill greedy: coin change with arbitrary coins
  4. Greedy + priority queue: many greedy algorithms use a heap
     (Dijkstra, Prim's MST, Huffman, task scheduling)
  5. Most interval problems have elegant greedy solutions:
     sort by end time or start time
