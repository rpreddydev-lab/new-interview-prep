RANDOMIZED ALGORITHMS
======================

INTRODUCTION
-------------
  A randomized algorithm uses random numbers to make decisions during
  execution. Unlike deterministic algorithms, the output or runtime
  may vary across runs even for the same input.

  Two main types:
  1. Las Vegas:  Always correct, runtime is random (expected O(f(n)))
  2. Monte Carlo: Runs in fixed time, answer may be incorrect with
                  bounded probability (< ε for some small ε)

─────────────────────────────────────────────────────────────
1. RANDOMIZED QUICKSORT (Las Vegas)
─────────────────────────────────────────────────────────────
  Deterministic QuickSort: worst case O(n²) on sorted input (bad pivot).
  Randomized QuickSort: randomly choose pivot → expected O(n log n).

  Why it works:
  - Random pivot makes worst case extremely unlikely
  - Expected number of comparisons = O(n log n) — provable via indicator
    random variables

  Implementation:
    void quickSort(int[] arr, int lo, int hi, Random rand) {
        if (lo >= hi) return;
        // Randomly swap a pivot to position lo
        int pivotIdx = lo + rand.nextInt(hi - lo + 1);
        swap(arr, lo, pivotIdx);
        int p = partition(arr, lo, hi);
        quickSort(arr, lo, p - 1, rand);
        quickSort(arr, p + 1, hi, rand);
    }

    int partition(int[] arr, int lo, int hi) {
        int pivot = arr[lo], i = lo;
        for (int j = lo + 1; j <= hi; j++)
            if (arr[j] <= pivot) swap(arr, ++i, j);
        swap(arr, lo, i);
        return i;
    }

  Time: O(n log n) expected, O(n²) worst (exponentially unlikely with random pivot)
  Space: O(log n) expected stack depth

─────────────────────────────────────────────────────────────
2. QUICKSELECT / RANDOMIZED SELECTION (Las Vegas)
─────────────────────────────────────────────────────────────
  Find the k-th smallest element in O(n) expected time.
  (Deterministic median-of-medians: O(n) worst case but slow constant)

    int quickSelect(int[] arr, int lo, int hi, int k, Random rand) {
        if (lo == hi) return arr[lo];
        int pivotIdx = lo + rand.nextInt(hi - lo + 1);
        swap(arr, lo, pivotIdx);
        int p = partition(arr, lo, hi);
        if (p == k) return arr[p];
        else if (p < k) return quickSelect(arr, p + 1, hi, k, rand);
        else return quickSelect(arr, lo, p - 1, k, rand);
    }

  Expected: O(n)   Worst case: O(n²) — exponentially unlikely

─────────────────────────────────────────────────────────────
3. FISHER-YATES SHUFFLE (Las Vegas)
─────────────────────────────────────────────────────────────
  Produces a uniformly random permutation in O(n) time.

  Algorithm:
    for i from n-1 downto 1:
        j = random(0, i)   // inclusive
        swap(arr[i], arr[j])

  Java:
    void shuffle(int[] arr) {
        Random rand = new Random();
        for (int i = arr.length - 1; i > 0; i--) {
            int j = rand.nextInt(i + 1);
            int tmp = arr[i]; arr[i] = arr[j]; arr[j] = tmp;
        }
    }

  Proof: element at any original position has equal probability (1/n)
  of ending up at any final position. All n! permutations equally likely.

  LC 384 — Shuffle an Array uses this.

  ⚠️ Common mistake: j = random(0, n) instead of random(0, i)
     This produces a BIASED shuffle (not all permutations equally likely).

─────────────────────────────────────────────────────────────
4. RABIN-KARP ROLLING HASH (Monte Carlo)
─────────────────────────────────────────────────────────────
  Pattern matching using hashing. O(n+m) expected, O(nm) worst case.
  Small probability of hash collision giving a false positive.

  hash(s[i..i+m-1]) = (s[i]*p^(m-1) + s[i+1]*p^(m-2) + ... + s[i+m-1]) mod M

  Rolling update in O(1):
    hash_new = (hash_old - s[i]*p^(m-1)) * p + s[i+m]

  To reduce collision probability: use two different (p, M) pairs.

─────────────────────────────────────────────────────────────
5. RANDOMIZED PRIMALITY TESTING — MILLER-RABIN (Monte Carlo)
─────────────────────────────────────────────────────────────
  Test if n is prime. O(k log²n) time for k rounds.
  False positive probability: < 4^(-k). With k=40: negligible.

  Key idea: if n is prime, then for any a not divisible by n:
    a^(n-1) ≡ 1 (mod n)  [Fermat's little theorem]

  Miller-Rabin adds additional squaring tests to catch "Carmichael numbers"
  that fool simple Fermat test.

  Used in: RSA key generation, cryptographic libraries, competitive programming.

  Simple Fermat Primality Test (approximate):
    boolean isProbablyPrime(long n, int rounds) {
        if (n < 2) return false;
        Random rand = new Random();
        for (int i = 0; i < rounds; i++) {
            long a = 2 + (long)(rand.nextDouble() * (n - 3));
            if (modPow(a, n - 1, n) != 1) return false;  // definitely composite
        }
        return true;  // probably prime
    }

─────────────────────────────────────────────────────────────
7. SKIP LIST (Randomized Data Structure)
─────────────────────────────────────────────────────────────
  A probabilistic data structure — effectively a sorted linked list with
  multiple layers of "express lanes" added with probability p (usually 0.5).

  Expected time: O(log n) for search, insert, delete.
  No rotations needed (unlike AVL/Red-Black trees).

  Layer generation:
    Each new element gets a height h:
    h = 1 with prob 1-p
    h = 2 with prob p(1-p)
    h = k with prob p^(k-1)(1-p)

  Used in: Redis's sorted sets (ZSet), LevelDB, Java's ConcurrentSkipListMap.

ANALYSIS TECHNIQUE: EXPECTED VALUE VIA INDICATOR RANDOM VARIABLES
─────────────────────────────────────────────────────────────
  Linearity of Expectation:
    E[X₁ + X₂ + ... + Xₙ] = E[X₁] + E[X₂] + ... + E[Xₙ]
    (even if Xᵢ are NOT independent!)

  Powerful tool for analyzing randomized algorithms.

  Example: Expected comparisons in Randomized QuickSort
    For elements i < j, let Xᵢⱼ = 1 if they are compared.
    Elements i and j are compared iff one is the first pivot chosen
    from {i, i+1, ..., j}.

    P(Xᵢⱼ = 1) = 2 / (j - i + 1)

    Total expected comparisons:
    E[X] = Σᵢ<ⱼ 2/(j-i+1) = 2 Σₙ₌₂ⁿ n/n = O(n log n) ✅

─────────────────────────────────────────────────────────────
LAS VEGAS vs MONTE CARLO — SUMMARY
─────────────────────────────────────────────────────────────
  Property       | Las Vegas              | Monte Carlo
  ───────────────┼────────────────────────┼─────────────────────────────
  Correctness    | Always correct         | Probably correct (prob ≥ 1-ε)
  Runtime        | Random (expected fast) | Deterministic
  Examples       | QuickSort, QuickSelect | Miller-Rabin, Rabin-Karp hash
  Can repeat?    | Never wrong            | Repeat to reduce error prob

─────────────────────────────────────────────────────────────
COMMON INTERVIEW QUESTIONS
─────────────────────────────────────────────────────────────
  Q: What is the expected time complexity of randomized QuickSort?
  A: O(n log n). By choosing a random pivot, the probability of
     consistently picking bad pivots is exponentially small. The expected
     number of comparisons is 2n ln n ≈ 1.39 n log₂ n.

  Q: How does the Fisher-Yates shuffle differ from a naive shuffle?
  A: Naive: pick random index for each position from [0, n) — biased,
     not all n! permutations equally likely.
     Fisher-Yates: pick from [0, i] for position i — all n! permutations
     equally likely, provably uniform.

  Q: What is a Las Vegas algorithm?
  A: A randomized algorithm that always produces a correct result
     but whose runtime is a random variable. Examples: Randomized
     QuickSort, QuickSelect, Reservoir Sampling.

  Q: What is a Monte Carlo algorithm?
  A: A randomized algorithm with a fixed running time that may produce
     an incorrect result with bounded probability. Repeat k times to
     reduce error below 4^(-k). Examples: Miller-Rabin primality test.

  Q: Where does Java use randomized algorithms internally?
  A: Collections.shuffle() uses Fisher-Yates. HashMap's hash function
     mixes bits to distribute keys. Java's sort (TimSort) is deterministic,
     but Arrays.sort() on primitive arrays uses dual-pivot QuickSort
     with a small random element for pivot selection in some JVM versions.
