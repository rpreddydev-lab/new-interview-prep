----------------------------------------------------------------
WHAT IS TIMSORT?
----------------------------------------------------------------
TimSort is a hybrid stable sorting algorithm derived from Merge
Sort and Insertion Sort. Designed by Tim Peters for Python (2002),
also used in Java for object sorting.

  Key idea: real-world data often has RUNS (consecutive sequences
  that are already sorted or reverse-sorted).
  TimSort detects and exploits these natural runs.

----------------------------------------------------------------
TIMSORT ALGORITHM
----------------------------------------------------------------
  1. FIND RUNS:
     Scan for naturally ascending or descending sequences.
     Reverse descending runs to make them ascending.
     If a run is too short (< minRun), extend with Insertion Sort.
     minRun is typically 32-64 (ensures merge steps are balanced).

  2. PUSH RUNS ONTO STACK

  3. MERGE RUNS:
     Merge runs from the stack when size ratios trigger merge.
     Uses Galloping mode: when one array consistently wins many
     comparisons, switch to binary search to find run end (O(log n)).

  Time:
    Best: O(n) -- already sorted (detected as one run)
    Average: O(n log n)
    Worst: O(n log n)
  Space: O(n)  (temporary buffer for merging)
  Stable: Yes

  Galloping: when merge detects one side winning 7+ comparisons
  in a row, it switches to binary search to skip ahead.
  Reduces comparisons for data with many runs.

----------------------------------------------------------------
JAVA SORT INTERNALS
----------------------------------------------------------------
  Arrays.sort(int[])           -- DUAL-PIVOT QUICKSORT (Yaroslavskiy)
    Not stable. Fast in practice. Falls back to Insertion Sort for
    small subarrays (< 47 elements). Uses merge sort-like fallback
    for nearly-sorted input.

  Arrays.sort(Object[])        -- TIMSORT
  Collections.sort(List<T>)    -- TIMSORT (delegates to toArray + sort)
  List.sort(Comparator)        -- TIMSORT
    All object sorts: STABLE. O(n log n) worst. O(n) for sorted input.

  For parallel sorting:
  Arrays.parallelSort(int[])   -- Fork/Join parallel merge sort
    Better than sequential for n > ~8192 on multicore machines.

----------------------------------------------------------------
DUAL-PIVOT QUICKSORT (Java primitive sort)
----------------------------------------------------------------
  Choose two pivots: pivot1 <= pivot2.
  Partition into 3 regions:
    [< pivot1]  [pivot1 <= x <= pivot2]  [> pivot2]
  Recursively sort the 3 regions (middle is already "between" pivots).

  Advantages over single-pivot:
    ~10% fewer comparisons
    Better for modern CPUs (branch prediction)
    Falls back to Insertion Sort for small subarrays
    Uses Counting Sort for heavily duplicated byte/short arrays

  NOT stable: a requirement for comparisons (equal primitives don't
  have identity, so stability is irrelevant for primitives).

----------------------------------------------------------------
COMPARATOR PITFALLS IN JAVA
----------------------------------------------------------------
  DANGEROUS (overflow):
    Arrays.sort(arr, (a, b) -> a - b);  // if a = MIN_VALUE, b = 1: overflows!

  SAFE:
    Arrays.sort(arr, (a, b) -> Integer.compare(a, b));   // ascending
    Arrays.sort(arr, (a, b) -> Integer.compare(b, a));   // descending
    Arrays.sort(arr, Comparator.naturalOrder());
    Arrays.sort(arr, Comparator.reverseOrder());
    Arrays.sort(arr, Comparator.comparingInt(x -> x[1]).thenComparingInt(x -> x[0]));

  Comparator contract: must be transitive and consistent.
  Violating it (e.g., returning random values) leads to undefined behavior.

----------------------------------------------------------------
JAVA SORT API SUMMARY
----------------------------------------------------------------
  Arrays.sort(int[])             O(n log n) unstable  dual-pivot QS
  Arrays.sort(int[], from, to)   partial range sort
  Arrays.sort(Object[])          O(n log n) STABLE    TimSort
  Arrays.sort(T[], Comparator)   O(n log n) STABLE    TimSort
  Arrays.parallelSort(int[])     O(n log n) parallel  Fork/Join
  Collections.sort(List<T>)      O(n log n) STABLE    TimSort
  List.sort(Comparator)          O(n log n) STABLE    TimSort
  TreeSet / TreeMap              O(log n) per op       Red-Black Tree
  PriorityQueue                  O(log n) per op       Binary Heap

----------------------------------------------------------------
INTERVIEW QUESTIONS
----------------------------------------------------------------

Q: What is the time complexity of Java's Arrays.sort() and
   is it stable?
A: Arrays.sort(int[]) -- Dual-Pivot QuickSort, O(n log n) average,
   not stable (irrelevant for primitives).
   Arrays.sort(Object[]) -- TimSort, O(n log n) worst case,
   O(n) best case (sorted input), STABLE.
   The stability guarantee for object sorting is specified in the
   Java documentation and has been guaranteed since Java 7.

Q: Why does Java use different algorithms for primitive vs
   object arrays?
A: Primitives don't have identity -- two ints with value 5 are
   indistinguishable, so stability is meaningless. QuickSort
   (faster in practice, cache-friendly, in-place) is preferred.
   Objects have identity -- two objects equal by comparator may
   differ by other fields. Stability preserves relative order
   of equal-by-comparator objects, which is important for
   multi-key sorting. TimSort provides this stability with
   O(n log n) guarantee.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. Memorize: Arrays.sort(int[]) = unstable QuickSort;
     Arrays.sort(Object[]) = stable TimSort
  2. NEVER use (a-b) comparator -- always Integer.compare(a, b)
  3. TimSort is O(n) for sorted/reverse-sorted input -- a key advantage
     for real-world data that is often nearly sorted
  4. Arrays.parallelSort: mention for performance on multicore
     when n is large (> ~50K elements)
  5. Comparator.thenComparing() for multi-key sort:
     sort by age, then by name:
     Comparator.comparingInt(Person::getAge).thenComparing(Person::getName)
