================================================================
  RADIX SORT
================================================================

----------------------------------------------------------------
HOW IT WORKS
----------------------------------------------------------------
Sort integers digit by digit from LEAST significant to MOST
significant (LSD Radix Sort) using a stable sort (Counting Sort)
for each digit pass.

  Why LSD works: a stable sort of the more significant digit
  preserves the order of equal elements from previous passes.

  void radixSort(int[] arr) {
    int max = Arrays.stream(arr).max().getAsInt();
    for (int exp = 1; max / exp > 0; exp *= 10)
      countingSortByDigit(arr, exp);
  }

  void countingSortByDigit(int[] arr, int exp) {
    int n = arr.length;
    int[] output = new int[n];
    int[] count = new int[10];  // digits 0-9
    for (int x : arr) count[(x / exp) % 10]++;
    for (int i = 1; i < 10; i++) count[i] += count[i-1];
    for (int i = n - 1; i >= 0; i--) {  // right-to-left for stability
      int digit = (arr[i] / exp) % 10;
      output[--count[digit]] = arr[i];
    }
    System.arraycopy(output, 0, arr, 0, n);
  }

  Time:  O(d * (n + b))  where d = digits, b = base (10), n = count
         For integers: d = log10(max), b = 10 -> O(n * log(max))
  Space: O(n + b)
  Stable: Yes   Comparison-based: No

  For fixed-width integers (e.g., 32-bit): d is constant -> O(n)

----------------------------------------------------------------
MSD vs LSD RADIX SORT
----------------------------------------------------------------
  LSD (Least Significant Digit): sort from rightmost digit left.
    Simple, single pass per digit, non-recursive.
    Natural for fixed-length keys.

  MSD (Most Significant Digit): sort from leftmost digit right.
    Recursive partitioning by digit.
    Can terminate early for short strings.
    More complex; good for strings of variable length.
    Java's String sorting in libraries uses MSD-like approach.

----------------------------------------------------------------
RADIX SORT WITH BINARY (BASE 256)
----------------------------------------------------------------
Using base 256 instead of 10:
  - Each byte is a "digit" (256 values)
  - 32-bit integer: 4 passes only
  - 64-bit long: 8 passes
  - Faster in practice due to fewer passes

  Same algorithm; count array size = 256 instead of 10.

----------------------------------------------------------------
COMPARISON WITH COUNTING SORT
----------------------------------------------------------------
  Feature              Counting Sort     Radix Sort
  ---------------------------------------------------
  Key range            k must be small   Any integer
  Number of passes     1                 d (one per digit)
  Space                O(n + k)          O(n + b)
  Stability required   N/A               Yes (base sort must be stable)
  Good for             Small k           Large integers, strings

  Radix Sort effectively extends Counting Sort to handle large ranges
  by processing one digit (position) at a time.

----------------------------------------------------------------
INTERVIEW QUESTIONS
----------------------------------------------------------------

Q: Is Radix Sort always O(n)? What are its limitations?
A: For fixed-width integers, d is constant, so it's O(n). But in
   the general case, d = log_b(max), so it's O(n log(max) / log b).
   For 32-bit integers with b=256: 4 passes of O(n) = O(n).
   Limitations:
   1. Only works for integers or things that can be decomposed into
      digits/characters -- not directly applicable to floating point
      or arbitrary objects
   2. Space: requires O(n + b) auxiliary storage
   3. Constant factor: d * (n + b) > n log n for typical cases
      when n is small; comparison sorts often win in practice

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. Radix Sort requires a STABLE base sort (Counting Sort)
     -- stability of base sort is what makes it correct
  2. LSD is simpler; MSD is better for strings and variable-length keys
  3. For integers: base 256 (byte by byte) is common in production;
     base 10 is easier to explain in interviews
  4. Radix Sort breaks the O(n log n) lower bound because it's
     not comparison-based (like Counting Sort)
  5. Practical performance: often beaten by QuickSort due to
     constants and cache effects, except for huge datasets
