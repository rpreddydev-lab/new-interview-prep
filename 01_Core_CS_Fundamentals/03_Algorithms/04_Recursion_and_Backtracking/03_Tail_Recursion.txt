================================================================
  TAIL RECURSION
================================================================

----------------------------------------------------------------
WHAT IS TAIL RECURSION?
----------------------------------------------------------------
A recursive call is in TAIL POSITION if it is the LAST operation
in a function -- no pending computation after the recursive call.

  NOT tail recursive (pending multiplication after call):
    int factorial(int n) {
      if (n <= 1) return 1;
      return n * factorial(n - 1);   // multiply n AFTER call returns
    }

  IS tail recursive (no pending computation):
    int factTail(int n, int acc) {
      if (n <= 1) return acc;
      return factTail(n - 1, n * acc);  // call is the LAST thing
    }
    // Call: factTail(5, 1)

  In a tail-recursive function:
    - The accumulator carries the intermediate result
    - No work needs to happen AFTER the recursive call returns
    - The current stack frame can be REUSED for the next call

----------------------------------------------------------------
TAIL CALL OPTIMIZATION (TCO)
----------------------------------------------------------------
Languages that support TCO can convert tail recursion to a loop,
eliminating stack frame growth:

  Supports TCO:
    Scheme, Haskell, Scala (@tailrec), Kotlin (tailrec keyword),
    Lua, Elixir, JavaScript (ES6 strict mode -- rarely implemented)

  Does NOT support TCO:
    Java (JVM DOES NOT perform TCO)
    Python (CPython does not)
    C/C++ -- compiler may optimize as an extension, not guaranteed

  JAVA IMPORTANT: Even if you write a tail-recursive function in Java,
  the JVM does NOT eliminate stack frames. A tail-recursive factorial
  in Java still throws StackOverflowError for large n.
  Solution: convert to iteration manually.

----------------------------------------------------------------
CONVERTING TAIL RECURSION TO ITERATION (Java pattern)
----------------------------------------------------------------
  Tail-recursive:
    int factTail(int n, int acc) {
      if (n <= 1) return acc;
      return factTail(n - 1, n * acc);
    }

  Iterative equivalent (same logic):
    int factorial(int n) {
      int acc = 1;
      while (n > 1) { acc *= n; n--; }
      return acc;
    }

  General conversion: replace recursive call with loop,
  accumulator variables become loop variables.

----------------------------------------------------------------
CONVERTING NON-TAIL RECURSION TO ITERATIVE
----------------------------------------------------------------
For non-tail recursion (e.g., tree DFS, inorder traversal):
Use an EXPLICIT STACK to simulate the call stack.

  Recursive inorder:
    void inorder(TreeNode root) {
      if (root == null) return;
      inorder(root.left);
      process(root);
      inorder(root.right);
    }

  Iterative inorder with explicit stack:
    void inorderIter(TreeNode root) {
      Deque<TreeNode> stack = new ArrayDeque<>();
      TreeNode curr = root;
      while (curr != null || !stack.isEmpty()) {
        while (curr != null) { stack.push(curr); curr = curr.left; }
        curr = stack.pop();
        process(curr);
        curr = curr.right;
      }
    }

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. Java DOES NOT support TCO -- always mention this when
     discussing tail recursion in Java interviews
  2. Convert to iteration when stack overflow is a risk (deep recursion)
  3. The accumulator pattern: transform body result into a parameter
     -- this generalizes to many recursive-to-iterative conversions
  4. Scala's @tailrec annotation verifies at compile time
     that a function is tail-recursive -- useful knowledge
  5. Interview: if asked to make recursion iterative, use
     explicit stack (simulates call stack manually)
