INHERITANCE AND METHOD OVERRIDING
==================================

INHERITANCE
-----------
Inheritance allows a class (subclass/child) to acquire the fields and methods of another
class (superclass/parent). Java supports SINGLE inheritance for classes.

  class Animal {
      String name;
      void eat() { System.out.println(name + " is eating"); }
  }

  class Dog extends Animal {
      void bark() { System.out.println(name + " says woof"); }
  }

  Dog d = new Dog();
  d.eat();   // inherited from Animal
  d.bark();  // defined in Dog

  IS-A relationship: Dog IS-A Animal → valid upcasting: Animal a = new Dog();

WHAT IS INHERITED
-----------------
  ✅ Public and protected fields and methods
  ✅ Package-private members (if in same package)
  ❌ Private members (exist in parent but not accessible in child)
  ❌ Constructors (NOT inherited, but accessible via super())

EXTENDS vs IMPLEMENTS
----------------------
  extends    — used to inherit from a class (single inheritance only)
  implements — used to implement interfaces (multiple allowed)

  class FlyingBird extends Bird implements Flyable, Swimmable { ... }

THE Object CLASS
----------------
Every class in Java implicitly extends java.lang.Object.
Key methods inherited by ALL objects:
  equals(Object o)   — check logical equality
  hashCode()         — integer hash of the object
  toString()         — string representation
  clone()            — shallow copy (requires Cloneable)
  getClass()         — returns runtime Class object
  finalize()         — deprecated GC cleanup
  wait/notify/notifyAll — thread coordination (used with synchronized)

METHOD OVERRIDING
-----------------
Subclass provides its own implementation of a method already defined in the superclass.

Rules for overriding:
  1. Same method name, same parameter list (exact signature).
  2. Return type: same OR covariant (subtype of original return type) since Java 5.
  3. Access modifier: same or MORE permissive (can widen, not narrow).
     (can't override public with protected/private)
  4. Cannot throw broader checked exceptions than the original.
  5. Cannot override: static, final, or private methods.
  6. Use @Override annotation — compiler enforces rules.

  class Animal {
      public String sound() { return "..."; }
  }

  class Dog extends Animal {
      @Override
      public String sound() { return "Woof"; }  // runtime polymorphism
  }

  Animal a = new Dog();
  a.sound();  // "Woof" — Dog's version called at runtime (dynamic dispatch)

COVARIANT RETURN TYPE
---------------------
  class Animal {
      public Animal create() { return new Animal(); }
  }
  class Dog extends Animal {
      @Override
      public Dog create() { return new Dog(); }  // Dog is a subtype of Animal — valid
  }

CALLING SUPER METHOD
---------------------
  class Dog extends Animal {
      @Override
      public void eat() {
          super.eat();  // calls Animal's eat() first
          System.out.println("Dog eats kibble");
      }
  }

FINAL KEYWORD AND INHERITANCE
------------------------------
  final class     — cannot be subclassed (e.g., String, Integer)
  final method    — cannot be overridden
  final variable  — cannot be reassigned after initialization

  class Animal {
      public final void breathe() { System.out.println("breathing"); }
      // No subclass can override breathe()
  }

ABSTRACT CLASSES
----------------
  - Cannot be instantiated.
  - May have abstract methods (no body) that MUST be overridden by concrete subclasses.
  - May also have concrete methods.

  abstract class Shape {
      abstract double area();             // subclass must implement
      public void display() {             // concrete — inherited as-is
          System.out.println("Area: " + area());
      }
  }

  class Circle extends Shape {
      double radius;
      Circle(double r) { this.radius = r; }
      @Override
      double area() { return Math.PI * radius * radius; }
  }

CONSTRUCTOR CALL IN INHERITANCE
---------------------------------
When a subclass object is created, constructors are called top-down:
  Object() → Animal() → Dog()

If super() is not explicitly called, Java inserts an implicit super() call to the
no-arg parent constructor. If parent has no no-arg constructor, compilation fails.

  class Animal {
      Animal(String name) { ... }  // no default constructor
  }
  class Dog extends Animal {
      Dog() { super("Dog"); }  // MUST explicitly call super with arg
  }

COMMON INTERVIEW QUESTIONS
---------------------------
Q: What is the difference between method overriding and method overloading?
A: Overriding: subclass provides new implementation of parent's method (same signature, runtime).
   Overloading: same method name with DIFFERENT parameter lists in SAME class (compile-time).

Q: Can you override a static method?
A: No — static methods belong to the class, not instances. You can HIDE a static method
   (define same-named static in subclass), but that's not polymorphic overriding.
   Animal.sound() and Dog.sound() are two different static methods.

Q: What is dynamic dispatch (runtime polymorphism)?
A: When you call a method on a superclass reference pointing to a subclass object, the JVM
   decides WHICH implementation to call at runtime based on the actual object type, not the
   reference type. This is dynamic dispatch.
   Animal a = new Dog(); a.sound() → calls Dog.sound() at runtime.

Q: Can a subclass access private fields of its parent?
A: No — private members are accessible only within the declaring class. They exist in the
   object (are inherited in the memory sense) but are not accessible by name in the subclass.
   Use protected or provide public getters/setters.

Q: What is the diamond problem and how does Java avoid it?
A: In multiple class inheritance (e.g., C++), if two parents have the same method, the
   subclass doesn't know which to inherit — the diamond problem. Java avoids this by allowing
   single-class inheritance only. Multiple INTERFACE inheritance is allowed; if two interfaces
   have the same default method, the implementing class MUST override it to resolve ambiguity.
