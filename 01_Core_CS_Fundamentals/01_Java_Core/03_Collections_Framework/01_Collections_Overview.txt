COLLECTIONS FRAMEWORK OVERVIEW
================================

WHAT IS THE COLLECTIONS FRAMEWORK?
------------------------------------
The Java Collections Framework (JCF) is a unified architecture for representing and manipulating
groups of objects. It provides:
  - Interfaces   — abstract data types (List, Set, Map, Queue, Deque)
  - Implementations — concrete classes (ArrayList, HashMap, TreeSet, etc.)
  - Algorithms   — static utility methods (Collections.sort, Collections.shuffle, etc.)

CORE INTERFACES HIERARCHY
--------------------------
  Iterable<T>
      └── Collection<T>
              ├── List<T>         — ordered, duplicates allowed, index-based
              │     ├── ArrayList
              │     ├── LinkedList
              │     └── Vector → Stack
              ├── Set<T>          — unique elements, no duplicates
              │     ├── HashSet
              │     ├── LinkedHashSet
              │     └── SortedSet<T>
              │           └── NavigableSet<T>
              │                 └── TreeSet
              └── Queue<T>        — FIFO ordering
                    ├── LinkedList
                    ├── PriorityQueue
                    └── Deque<T>  — double-ended queue
                          ├── ArrayDeque
                          └── LinkedList

  Map<K,V>  — NOT a Collection (doesn't extend Collection), but part of JCF
      ├── HashMap
      ├── LinkedHashMap
      ├── Hashtable → Properties
      └── SortedMap<K,V>
            └── NavigableMap<K,V>
                  └── TreeMap

KEY INTERFACES SUMMARY
-----------------------
  List<T>    — ordered, allows nulls, allows duplicates, indexed access
  Set<T>     — unordered*, no duplicates, at most one null (except TreeSet — no null key)
  Map<K,V>   — key-value pairs, unique keys, values may duplicate
  Queue<T>   — FIFO; offer/poll/peek (non-throwing) vs add/remove/element (throwing)
  Deque<T>   — double-ended queue; addFirst/addLast, pollFirst/pollLast; stack replacement

CHOOSING THE RIGHT COLLECTION
-------------------------------
  Need ordered by insertion? Use LinkedList or LinkedHashSet/LinkedHashMap.
  Need sorted?              Use TreeSet or TreeMap.
  Need fast random access?  Use ArrayList.
  Need fast insert/delete?  Use LinkedList (but consider ArrayDeque for stack/queue).
  Need uniqueness?          Use Set (HashSet for O(1), TreeSet for sorted).
  Need key → value?         Use HashMap (O(1)), TreeMap (sorted), LinkedHashMap (insertion order).
  Need thread safety?       Use ConcurrentHashMap, CopyOnWriteArrayList, Collections.synchronizedX.

BIG-O COMPLEXITY CHEAT SHEET
------------------------------
  Data Structure     | Access   | Search   | Insert   | Delete   | Notes
  -------------------|----------|----------|----------|----------|------------------
  ArrayList          | O(1)     | O(n)     | O(1) amort| O(n)   | Fast random access
  LinkedList         | O(n)     | O(n)     | O(1)     | O(1)     | Fast at ends
  ArrayDeque         | O(1)     | O(n)     | O(1) amort| O(1)   | Best stack/queue
  HashSet / HashMap  | —        | O(1) avg | O(1) avg | O(1) avg | Hash-based
  TreeSet / TreeMap  | —        | O(log n) | O(log n) | O(log n) | Red-Black tree, sorted
  PriorityQueue      | O(n)     | O(n)     | O(log n) | O(log n) | Min-heap, poll = min

COLLECTION FACTORY METHODS (Java 9+)
--------------------------------------
  List.of("a", "b", "c")          // immutable, no nulls, fixed size
  Set.of("x", "y", "z")           // immutable, no nulls, no duplicates
  Map.of("k1", "v1", "k2", "v2")  // immutable, up to 10 entries
  Map.ofEntries(Map.entry("k", "v"), ...) // immutable, any size

  NOTE: These collections are UNMODIFIABLE — add/remove/set throws UnsupportedOperationException.
  They also don't allow null elements/keys/values.

  Pre-Java 9 immutable alternatives:
    Collections.unmodifiableList(new ArrayList<>(list))  // wraps, still mutable underneath
    Arrays.asList("a", "b", "c")  // fixed-size, allows set(), but not add/remove

COMMON INTERVIEW QUESTIONS
---------------------------
Q: What is the difference between Collection and Collections?
A: Collection (no s): the java.util.Collection interface — the root interface for all collections.
   Collections (with s): java.util.Collections — a utility class with static helper methods
   like sort(), shuffle(), unmodifiableList(), synchronizedList(), min(), max(), frequency().

Q: Why doesn't Map extend Collection?
A: Map stores key-value pairs — not single elements. Collection operations (add(element), remove(element))
   don't map naturally to Map's key-value model. Maps have their own separate hierarchy.

Q: What is the difference between fail-fast and fail-safe iterators?
A: Fail-fast: throws ConcurrentModificationException if collection is structurally modified
   during iteration (outside of iterator.remove()). Uses modCount. ArrayList, HashMap use this.
   Fail-safe: iterates over a snapshot/copy — no exception on modification. ConcurrentHashMap,
   CopyOnWriteArrayList use this. No guarantee of seeing latest modifications.

Q: What is the difference between ArrayList and LinkedList?
A: ArrayList: backed by array. O(1) random access. O(n) insert/delete in middle. Low memory overhead.
   LinkedList: doubly linked list. O(n) random access. O(1) insert/delete at known position.
   Implements both List and Deque. Higher memory (each node stores prev/next pointers).
   In practice: prefer ArrayList for most use cases; LinkedList for frequent head/tail operations.
