ITERATORS AND FAIL-FAST vs FAIL-SAFE
======================================

THE ITERATOR INTERFACE
-----------------------
  java.util.Iterator<E>
  Provides a way to traverse (iterate) any Collection without exposing its internal structure.

  Methods:
    boolean hasNext()  — returns true if more elements remain
    E next()           — returns next element (throws NoSuchElementException if none)
    void remove()      — removes last element returned by next() (optional, not all support)
    void forEachRemaining(Consumer<? super E> action) — Java 8+

  Example:
    List<String> list = new ArrayList<>(Arrays.asList("A", "B", "C"));
    Iterator<String> it = list.iterator();
    while (it.hasNext()) {
        String s = it.next();
        if (s.equals("B")) {
            it.remove(); // safe removal during iteration
        }
    }
    System.out.println(list); // [A, C]

LISTITERATOR
-------------
  java.util.ListIterator<E> extends Iterator<E>
  Only for Lists. Provides bidirectional traversal + modification.

  Additional methods:
    boolean hasPrevious()   — check backward
    E previous()            — move backward
    int nextIndex()         — index of next element
    int previousIndex()     — index of previous element
    void set(E e)           — replace last returned element
    void add(E e)           — insert element before next

  Example:
    ListIterator<String> lit = list.listIterator(list.size()); // start at end
    while (lit.hasPrevious()) {
        System.out.println(lit.previous()); // prints in reverse
    }

FOR-EACH LOOP (ENHANCED FOR)
------------------------------
  Syntactic sugar over Iterator. Any class implementing Iterable<T> supports for-each.
  Under the hood: calls iterator() and uses hasNext()/next().

  for (String s : list) { ... }
  // Equivalent to:
  Iterator<String> it = list.iterator();
  while (it.hasNext()) { String s = it.next(); ... }

  NOTE: You cannot call it.remove() directly inside a for-each loop.
        Use an explicit Iterator to remove safely, or use Collection.removeIf() (Java 8).

FAIL-FAST ITERATORS
--------------------
  Behavior: Throw ConcurrentModificationException if the collection is STRUCTURALLY modified
            during iteration (except via the iterator's own remove() method).

  Mechanism: Uses a modCount (modification count) field on the collection.
    - Every structural modification (add, remove, clear, etc.) increments modCount.
    - When the iterator is created, it captures expectedModCount = collection.modCount.
    - On each call to next(), iterator checks: if modCount != expectedModCount → throw CME.

  Collections that use fail-fast iterators:
    ArrayList, LinkedList, HashSet, LinkedHashSet, HashMap, TreeMap, TreeSet, etc.
    (basically all non-concurrent collections)

  Example:
    List<String> list = new ArrayList<>(Arrays.asList("A", "B", "C"));
    for (String s : list) {
        if (s.equals("B")) {
            list.remove(s); // ❌ throws ConcurrentModificationException
        }
    }

  Safe alternatives:
    // Option 1: Iterator.remove()
    Iterator<String> it = list.iterator();
    while (it.hasNext()) {
        if (it.next().equals("B")) it.remove(); // ✅ safe
    }

    // Option 2: Collection.removeIf() (Java 8+)
    list.removeIf(s -> s.equals("B")); // ✅ safe, uses internal iterator

    // Option 3: Collect to new list
    list = list.stream().filter(s -> !s.equals("B")).collect(Collectors.toList());

    // Option 4: Iterate over a copy
    for (String s : new ArrayList<>(list)) {
        if (s.equals("B")) list.remove(s); // ✅ safe (iterating copy)
    }

FAIL-SAFE ITERATORS
--------------------
  Behavior: Do NOT throw ConcurrentModificationException.
            They operate on a COPY or SNAPSHOT of the collection, or use lock-free techniques.

  Collections that use fail-safe iterators:
    ConcurrentHashMap        — uses internally consistent snapshots / split iterators
    CopyOnWriteArrayList     — iterator works on a snapshot of the array at creation time
    CopyOnWriteArraySet      — backed by CopyOnWriteArrayList
    ConcurrentLinkedQueue    — lock-free linked queue

  TRADE-OFF: Fail-safe iterators may NOT see modifications made after the iterator was created.
             They iterate over a snapshot — stale data is possible.

  Example — CopyOnWriteArrayList:
    CopyOnWriteArrayList<String> list = new CopyOnWriteArrayList<>(Arrays.asList("A", "B", "C"));
    for (String s : list) {
        if (s.equals("B")) {
            list.remove(s); // ✅ no CME — iterating over snapshot
        }
    }
    System.out.println(list); // [A, C] — modification happened but wasn't seen during iteration

  Example — ConcurrentHashMap:
    ConcurrentHashMap<String, Integer> map = new ConcurrentHashMap<>();
    map.put("a", 1); map.put("b", 2);
    for (Map.Entry<String, Integer> e : map.entrySet()) {
        map.put("c", 3); // ✅ no CME (weakly consistent iterator)
    }

COMPARISON TABLE
-----------------
  Feature                  | Fail-Fast                     | Fail-Safe
  -------------------------|-------------------------------|-------------------------------
  Exception on modification| ✅ ConcurrentModificationException| ❌ No exception
  Mechanism                | modCount check                | Snapshot / copy-on-write / lock-free
  Data freshness           | Always current                | May be stale (snapshot)
  Memory overhead          | Low                           | Higher (copy of data)
  Examples                 | ArrayList, HashMap, HashSet   | CopyOnWriteArrayList, ConcurrentHashMap
  Thread-safe?             | ❌ No                         | ✅ Yes (concurrent collections)

ITERABLE vs ITERATOR
---------------------
  Iterable<T>: interface that has one method: Iterator<T> iterator()
    - Collections implement Iterable to support for-each loops
    - Arrays do NOT implement Iterable (but work in for-each via language support)

  Iterator<T>: the actual cursor object that traverses the collection
    - Each call to iterator() returns a new Iterator positioned at the start

REMOVEIF (JAVA 8)
------------------
  boolean removeIf(Predicate<? super E> filter)
  Removes all elements satisfying the predicate. Uses internal iterator — no CME.

  list.removeIf(s -> s.startsWith("A")); // safe, clean, preferred over manual iteration

COMMON INTERVIEW QUESTIONS
---------------------------
Q: What is ConcurrentModificationException and when is it thrown?
A: It is thrown by fail-fast iterators when a collection is structurally modified during iteration
   (not through the iterator itself). Structural modification = adding or removing elements
   (not set/replace). It is a best-effort check using modCount — not guaranteed in all cases.
   It signals a programming bug, not a thread-safety issue per se (can happen in single-threaded code).

Q: What's the only safe way to remove elements from a collection during iteration?
A: Three safe options:
   1. Use Iterator.remove() during explicit iteration
   2. Use Collection.removeIf() (Java 8+) — concise and safe
   3. Iterate over a COPY of the collection and remove from the original

Q: ConcurrentHashMap's iterator is described as "weakly consistent" — what does that mean?
A: It means the iterator reflects the state of the map at some point during or after its creation.
   It may or may not reflect modifications made after the iterator was created, but it will never
   throw ConcurrentModificationException. Every element will be seen at most once.

Q: Does fail-safe guarantee thread safety?
A: No. "Fail-safe" just means the iterator won't throw CME. Thread safety of the collection
   itself is a separate concern. CopyOnWriteArrayList and ConcurrentHashMap happen to be both
   fail-safe AND thread-safe, but these are two separate properties.

Q: What happens if you call next() when hasNext() is false?
A: It throws java.util.NoSuchElementException. Always check hasNext() before calling next().
