TREEMAP AND NAVIGABLEMAP INTERNALS
====================================

WHAT IS TREEMAP?
-----------------
  java.util.TreeMap<K,V> implements NavigableMap<K,V>
  - Sorted map — keys are stored in SORTED ORDER at all times
  - Backed by a RED-BLACK TREE (self-balancing binary search tree)
  - All basic operations: O(log n)
  - Supports rich navigation: first/last, floor/ceiling, ranges
  - Does NOT allow null keys (comparisons would fail with NPE)
  - Allows null values
  - Not thread-safe

INTERNAL STRUCTURE: RED-BLACK TREE
------------------------------------
  A Red-Black tree is a balanced BST with these properties:
    1. Every node is RED or BLACK
    2. The root is BLACK
    3. Every leaf (null sentinel) is BLACK
    4. If a node is RED, both children are BLACK (no two consecutive reds)
    5. Every path from root to any leaf has the same number of BLACK nodes

  These rules guarantee: tree height ≤ 2 × log₂(n+1)
  → O(log n) guaranteed for all operations

  // TreeMap.Entry<K,V>
  static final class Entry<K,V> implements Map.Entry<K,V> {
      K key;
      V value;
      Entry<K,V> left, right, parent;
      boolean color = BLACK;
  }

ORDERING
---------
  1. Natural ordering (keys implement Comparable):
     TreeMap<Integer, String> map = new TreeMap<>(); // Integer implements Comparable
     map.put(3, "C"); map.put(1, "A"); map.put(2, "B");
     System.out.println(map.keySet()); // [1, 2, 3] — sorted

  2. Custom Comparator (passed in constructor):
     // Case-insensitive string map
     TreeMap<String, Integer> caseInsensitive = new TreeMap<>(String.CASE_INSENSITIVE_ORDER);
     caseInsensitive.put("Banana", 1);
     caseInsensitive.put("apple", 2);
     caseInsensitive.put("Cherry", 3);
     System.out.println(caseInsensitive.keySet()); // [apple, Banana, Cherry]

     // Reverse-order map
     TreeMap<Integer, String> descMap = new TreeMap<>(Comparator.reverseOrder());
     descMap.put(1, "A"); descMap.put(3, "C"); descMap.put(2, "B");
     System.out.println(descMap.keySet()); // [3, 2, 1]

SORTEDMAP METHODS
------------------
  firstKey()              → smallest key
  lastKey()               → largest key
  headMap(K toKey)        → submap with keys STRICTLY LESS than toKey (view)
  tailMap(K fromKey)      → submap with keys GREATER THAN OR EQUAL to fromKey (view)
  subMap(K from, K to)    → keys in [from, to) — from inclusive, to exclusive (view)

  Example:
    TreeMap<Integer, String> map = new TreeMap<>();
    for (int i = 1; i <= 10; i++) map.put(i, "v" + i);

    System.out.println(map.firstKey());        // 1
    System.out.println(map.lastKey());         // 10
    System.out.println(map.headMap(5));        // {1=v1, 2=v2, 3=v3, 4=v4}
    System.out.println(map.tailMap(8));        // {8=v8, 9=v9, 10=v10}
    System.out.println(map.subMap(3, 7));      // {3=v3, 4=v4, 5=v5, 6=v6}

NAVIGABLEMAP METHODS (JAVA 6+)
--------------------------------
  floor(K key)    → greatest key ≤ key (or null)
  ceiling(K key)  → smallest key ≥ key (or null)
  lower(K key)    → greatest key STRICTLY LESS than key (or null)
  higher(K key)   → smallest key STRICTLY GREATER than key (or null)

  floorKey / ceilingKey / lowerKey / higherKey — same but returns only key
  floorEntry / ceilingEntry / lowerEntry / higherEntry — same but returns Map.Entry

  pollFirstEntry()   → removes and returns entry with smallest key
  pollLastEntry()    → removes and returns entry with largest key

  descendingMap()    → returns NavigableMap with reverse order
  descendingKeySet() → returns NavigableSet with keys in reverse order

  headMap(K to, boolean inclusive)         → inclusive flag for boundary
  tailMap(K from, boolean inclusive)       → inclusive flag for boundary
  subMap(K from, boolean fromIncl, K to, boolean toIncl) → both inclusive flags

  Example:
    TreeMap<Integer, String> map = new TreeMap<>();
    map.put(1, "A"); map.put(3, "C"); map.put(5, "E"); map.put(7, "G"); map.put(9, "I");

    System.out.println(map.floorKey(4));      // 3 (greatest ≤ 4)
    System.out.println(map.ceilingKey(4));    // 5 (smallest ≥ 4)
    System.out.println(map.lowerKey(5));      // 3 (strictly less than 5)
    System.out.println(map.higherKey(5));     // 7 (strictly greater than 5)
    System.out.println(map.floorKey(0));      // null (no key ≤ 0)

    Map.Entry<Integer, String> entry = map.pollFirstEntry(); // removes {1=A}
    System.out.println(map.firstKey()); // 3

    // Inclusive subMap: [3, 7] (both inclusive)
    System.out.println(map.subMap(3, true, 7, true)); // {3=C, 5=E, 7=G}

VIEWS ARE BACKED BY THE ORIGINAL MAP
--------------------------------------
  headMap(), tailMap(), subMap() return views — modifications to the view modify the original:
    SortedMap<Integer, String> head = map.headMap(5);
    head.put(2, "B"); // also adds to original map!
    head.put(6, "F"); // ❌ throws IllegalArgumentException — 6 is not in the view range

TREESET USES TREEMAP INTERNALLY
---------------------------------
  TreeSet<E> is backed by a TreeMap<E, PRESENT> — just like HashSet is backed by HashMap.
  All TreeSet operations delegate to the TreeMap.

TREEMAP vs CONCURRENTSKIPLISTMAP
----------------------------------
  Feature                | TreeMap          | ConcurrentSkipListMap
  -----------------------|------------------|------------------------
  Thread-safe            | ❌ No            | ✅ Yes
  Internal structure     | Red-Black tree   | Skip list
  Ordering               | Sorted           | Sorted
  Operations             | O(log n)         | O(log n)
  Iterator               | Fail-fast        | Weakly consistent
  Null keys              | ❌ No            | ❌ No
  Use case               | Single-threaded  | Multi-threaded sorted map

COMMON INTERVIEW QUESTIONS
---------------------------
Q: What is a Red-Black tree and why does TreeMap use it?
A: A Red-Black tree is a self-balancing BST that maintains balance via color properties
   (red/black nodes with specific rules). Balance guarantees O(log n) height.
   TreeMap uses it to provide O(log n) put/get/remove AND maintain sorted key order.
   Unlike a plain BST (O(n) worst case), Red-Black trees are always balanced.

Q: What's the difference between headMap() and subMap()?
A: headMap(K to): returns all entries with keys STRICTLY LESS than `to`.
   subMap(K from, K to): returns entries with keys in [from, to) — from inclusive, to exclusive.
   tailMap(K from): returns all entries with keys ≥ from.
   NavigableMap versions add boolean inclusive flags for each boundary.

Q: What's the difference between floor() and lower()?
A: floor(k): returns greatest key LESS THAN OR EQUAL to k.
   lower(k): returns greatest key STRICTLY LESS THAN k.
   Same relationship: ceiling(k) ≥ k, while higher(k) > k.

Q: Can you use TreeMap without a Comparator if the key class doesn't implement Comparable?
A: No. TreeMap MUST be able to order keys. If the key class doesn't implement Comparable and
   no Comparator is provided, inserting the first entry succeeds (no comparison needed), but
   the second insert throws ClassCastException when it tries to compare using Comparable.
   Always provide a Comparator when using non-Comparable keys.

Q: When would you prefer TreeMap over HashMap?
A: When you need:
   - Keys in sorted order (for iteration or display)
   - Range queries: all entries between key1 and key2
   - Floor/ceiling navigation (nearest key queries)
   - First/last entry operations
   - Splitting the map into head/tail views
   HashMap is O(1) but gives no ordering; TreeMap is O(log n) with full ordering support.
