LINKEDHASHMAP AND LRU CACHE PATTERN
=====================================

WHAT IS LINKEDHASHMAP?
------------------------
  java.util.LinkedHashMap<K,V> extends HashMap<K,V>
  - Adds a doubly-linked list running through all entries IN ADDITION to the hash table
  - Maintains predictable iteration order (unlike HashMap)
  - All HashMap operations remain O(1)
  - Slight overhead: 2 extra pointers (before/after) per entry for the linked list

ORDERING MODES
---------------
  1. Insertion-order (default):
     Elements are iterated in the order they were first inserted.
     Re-inserting a key does NOT change its position.

  2. Access-order (constructor flag):
     new LinkedHashMap<>(capacity, loadFactor, true)
     Every time an entry is ACCESSED (get, put, or compute), it is moved to the END of the list.
     The HEAD of the list = LEAST recently accessed (oldest).
     This is the foundation for an LRU cache.

INSERTION-ORDER EXAMPLE
------------------------
  Map<String, Integer> map = new LinkedHashMap<>();
  map.put("banana", 1);
  map.put("apple", 2);
  map.put("cherry", 3);
  map.put("banana", 99);  // update — stays in original insertion position

  for (String key : map.keySet()) {
      System.out.print(key + " ");
  }
  // Output: banana apple cherry (insertion order preserved)
  System.out.println(map.get("banana")); // 99

ACCESS-ORDER EXAMPLE
---------------------
  Map<Integer, String> map = new LinkedHashMap<>(16, 0.75f, true);
  map.put(1, "A");
  map.put(2, "B");
  map.put(3, "C");
  // List state (head to tail, LRU to MRU): 1 → 2 → 3

  map.get(1);  // access key 1 — moves to tail (most recently used)
  // List state: 2 → 3 → 1

  map.get(2);  // access key 2 — moves to tail
  // List state: 3 → 1 → 2

  System.out.println(new ArrayList<>(map.keySet())); // [3, 1, 2] (LRU → MRU order)

REMOVEELDESTENTRY — LRU CACHE IMPLEMENTATION
---------------------------------------------
  LinkedHashMap has a hook method:
    protected boolean removeEldestEntry(Map.Entry<K,V> eldest)
    // Called after each put(). If returns true, the eldest (LRU) entry is removed.
    // Default: always returns false (no eviction).

  Override this to implement a bounded LRU cache:

  public class LRUCache<K, V> extends LinkedHashMap<K, V> {
      private final int capacity;

      public LRUCache(int capacity) {
          super(capacity, 0.75f, true);  // true = access order
          this.capacity = capacity;
      }

      @Override
      protected boolean removeEldestEntry(Map.Entry<K, V> eldest) {
          return size() > capacity;  // evict when over capacity
      }
  }

  Usage:
    LRUCache<Integer, String> cache = new LRUCache<>(3);
    cache.put(1, "A");
    cache.put(2, "B");
    cache.put(3, "C");
    // cache: {1=A, 2=B, 3=C}

    cache.get(1);      // access 1 → moves to tail
    // cache: {2=B, 3=C, 1=A}  (2 is now LRU)

    cache.put(4, "D"); // insert 4, cache over capacity → evict LRU (key 2)
    // cache: {3=C, 1=A, 4=D}

    System.out.println(cache.containsKey(2)); // false — evicted
    System.out.println(cache.containsKey(1)); // true  — still present

LEETCODE LRU CACHE (146) — STANDARD APPROACH
----------------------------------------------
  class LRUCache {
      private final int capacity;
      private final Map<Integer, Integer> cache;

      public LRUCache(int capacity) {
          this.capacity = capacity;
          this.cache = new LinkedHashMap<>(capacity, 0.75f, true) {
              @Override
              protected boolean removeEldestEntry(Map.Entry<Integer, Integer> eldest) {
                  return size() > capacity;
              }
          };
      }

      public int get(int key) {
          return cache.getOrDefault(key, -1);
      }

      public void put(int key, int value) {
          cache.put(key, value);
      }
  }
  // All operations O(1) amortized.

MANUAL DOUBLY-LINKED LIST + HASHMAP (INTERVIEW-GRADE)
------------------------------------------------------
  For interviews asking for O(1) put/get/evict without using LinkedHashMap:

  class LRUCache {
      class Node {
          int key, val;
          Node prev, next;
          Node(int k, int v) { key = k; val = v; }
      }

      private final int cap;
      private final Map<Integer, Node> map = new HashMap<>();
      private final Node head = new Node(0, 0); // dummy head (LRU side)
      private final Node tail = new Node(0, 0); // dummy tail (MRU side)

      public LRUCache(int cap) {
          this.cap = cap;
          head.next = tail;
          tail.prev = head;
      }

      public int get(int key) {
          if (!map.containsKey(key)) return -1;
          Node node = map.get(key);
          remove(node);
          insertAtTail(node);  // move to MRU
          return node.val;
      }

      public void put(int key, int val) {
          if (map.containsKey(key)) remove(map.get(key));
          Node node = new Node(key, val);
          insertAtTail(node);
          map.put(key, node);
          if (map.size() > cap) {
              Node lru = head.next; // least recently used = after dummy head
              remove(lru);
              map.remove(lru.key);
          }
      }

      private void remove(Node n) {
          n.prev.next = n.next;
          n.next.prev = n.prev;
      }

      private void insertAtTail(Node n) {
          tail.prev.next = n;
          n.prev = tail.prev;
          n.next = tail;
          tail.prev = n;
      }
  }

INTERNAL STRUCTURE
-------------------
  // LinkedHashMap adds before/after pointers to HashMap.Node:
  static class Entry<K,V> extends HashMap.Node<K,V> {
      Entry<K,V> before, after;  // doubly-linked list links
  }

  LinkedHashMap maintains:
    head → first (eldest / least recently accessed)
    tail → last (newest / most recently accessed)

  on access (if accessOrder=true):
    - Unlink node from its current position in the list
    - Append to tail

COMMON INTERVIEW QUESTIONS
---------------------------
Q: How does LinkedHashMap maintain insertion order internally?
A: It extends HashMap.Node with two extra pointers: before and after.
   A doubly-linked list runs through ALL entries in insertion order.
   head points to the oldest entry; tail points to the newest.
   On each insertion, the new node is appended to the tail.

Q: What is the difference between insertion-order and access-order LinkedHashMap?
A: Insertion-order (default): order determined by when each key was FIRST inserted.
   Re-putting an existing key does not change its position.
   Access-order (new LinkedHashMap<>(16, 0.75f, true)): every get() or put() moves
   the entry to the tail (most recently used). Head = least recently used.
   Access-order is the basis for implementing LRU caches.

Q: What is removeEldestEntry() and how is it used?
A: It's a protected hook method called after every put(). If it returns true,
   the eldest entry (head of the linked list = LRU entry) is automatically removed.
   Override it in an anonymous subclass to create a bounded LRU cache:
     return size() > capacity;

Q: Why is LinkedHashMap preferred for LRU cache over HashMap + separate LinkedList?
A: LinkedHashMap keeps the hash table and linked list in sync automatically.
   A separate HashMap + LinkedList implementation requires manually updating both
   structures and is error-prone. LinkedHashMap provides the same O(1) operations
   with all bookkeeping built in.
