PRIORITYQUEUE AND COMPARATOR
==============================

WHAT IS PRIORITYQUEUE?
-----------------------
  java.util.PriorityQueue<E> extends AbstractQueue<E>
  - An unbounded queue where elements are ordered by priority, NOT insertion order
  - Backed internally by a MIN-HEAP (binary heap in an array)
  - poll() always removes and returns the SMALLEST element (minimum priority)
  - Does NOT allow null elements
  - Thread-safe: NO (use PriorityBlockingQueue for concurrent use)

Internal Structure: Binary Min-Heap stored in an array
  - Parent at index i → children at 2i+1 and 2i+2
  - Every parent ≤ its children (min-heap property)
  - peek() → O(1): just look at index 0 (always the minimum)
  - poll() → O(log n): remove root, swap with last element, sift down
  - add()  → O(log n): insert at end, sift up (bubble up)

Key Operations:
  add(e) / offer(e)  → O(log n)
  peek()             → O(1) — minimum without removal
  poll()             → O(log n) — remove and return minimum
  remove(Object o)   → O(n) — linear scan + O(log n) heapify
  contains(o)        → O(n) — linear scan
  size()             → O(1)

NATURAL ORDERING (Comparable)
-------------------------------
  For types that implement Comparable (Integer, String, etc.),
  PriorityQueue uses natural ordering by default — smallest first.

  Example:
    PriorityQueue<Integer> minHeap = new PriorityQueue<>();
    minHeap.offer(5);
    minHeap.offer(1);
    minHeap.offer(3);
    System.out.println(minHeap.peek());  // 1 (minimum)
    System.out.println(minHeap.poll());  // 1
    System.out.println(minHeap.poll());  // 3
    System.out.println(minHeap.poll());  // 5

MAX-HEAP WITH COMPARATOR
-------------------------
  Reverse the ordering with Collections.reverseOrder() or Comparator.reverseOrder():

  PriorityQueue<Integer> maxHeap = new PriorityQueue<>(Collections.reverseOrder());
  maxHeap.offer(5);
  maxHeap.offer(1);
  maxHeap.offer(3);
  System.out.println(maxHeap.poll()); // 5 (maximum)
  System.out.println(maxHeap.poll()); // 3
  System.out.println(maxHeap.poll()); // 1

CUSTOM COMPARATOR
------------------
  PriorityQueue accepts a Comparator<E> to define custom ordering.

  // Min-heap by string length
  PriorityQueue<String> byLength = new PriorityQueue<>(Comparator.comparingInt(String::length));
  byLength.offer("banana");
  byLength.offer("fig");
  byLength.offer("kiwi");
  System.out.println(byLength.poll()); // "fig" (length 3, shortest)
  System.out.println(byLength.poll()); // "kiwi" (length 4)
  System.out.println(byLength.poll()); // "banana" (length 6)

  // Multi-field comparator — sort by last name, then first name
  PriorityQueue<Person> pq = new PriorityQueue<>(
      Comparator.comparing(Person::getLastName)
                .thenComparing(Person::getFirstName)
  );

COMPARATOR INTERFACE
---------------------
  @FunctionalInterface
  public interface Comparator<T> {
      int compare(T o1, T o2);
      // returns: negative if o1 < o2, 0 if equal, positive if o1 > o2
  }

  Comparator factory methods (Java 8+):
    Comparator.comparing(Person::getName)         // by field
    Comparator.comparingInt(String::length)        // by int field
    Comparator.comparingDouble(Product::getPrice)  // by double
    .reversed()                                    // reverse any comparator
    .thenComparing(...)                            // secondary sort key
    Comparator.naturalOrder()                      // default ordering
    Comparator.reverseOrder()                      // reverse of natural

TYPICAL INTERVIEW PATTERNS
----------------------------
1. Find Kth Largest element:
   // Use a min-heap of size k
   PriorityQueue<Integer> minHeap = new PriorityQueue<>(k);
   for (int num : nums) {
       minHeap.offer(num);
       if (minHeap.size() > k) minHeap.poll(); // remove smallest
   }
   return minHeap.peek(); // kth largest

2. Sort K-sorted array (each element at most K away from final position):
   PriorityQueue<Integer> pq = new PriorityQueue<>();
   for (int i = 0; i <= Math.min(k, nums.length - 1); i++) pq.offer(nums[i]);
   int idx = 0;
   for (int i = k + 1; i < nums.length; i++) {
       result[idx++] = pq.poll();
       pq.offer(nums[i]);
   }
   while (!pq.isEmpty()) result[idx++] = pq.poll();

3. Merge K sorted lists:
   PriorityQueue<int[]> pq = new PriorityQueue<>(Comparator.comparingInt(a -> a[0]));
   // [value, listIndex, elementIndex]

SORTING WITH ARRAYS AND COLLECTIONS
-------------------------------------
  Arrays.sort():
    int[] arr = {3, 1, 4, 1, 5};
    Arrays.sort(arr);  // natural order — uses dual-pivot quicksort for primitives

    Integer[] boxed = {3, 1, 4, 1, 5};
    Arrays.sort(boxed, Comparator.reverseOrder());  // requires boxed type

  Collections.sort() / List.sort():
    List<String> list = Arrays.asList("banana", "apple", "cherry");
    Collections.sort(list);                                     // natural order
    list.sort(Comparator.comparingInt(String::length).reversed()); // custom

  Note: Collections.sort uses TimSort (O(n log n), stable). Arrays.sort for primitives
  uses dual-pivot quicksort (O(n log n) avg, NOT stable).

COMPARISON TABLE — SORTED STRUCTURES
--------------------------------------
  Feature            | PriorityQueue      | TreeSet          | Arrays.sort
  -------------------|--------------------|------------------|------------------
  Ordering           | Heap (partial)     | Sorted set       | Fully sorted array
  Duplicates?        | ✅ Allowed         | ❌ No duplicates | ✅ Allowed
  peek/poll min      | O(1) / O(log n)    | O(log n)         | N/A
  Add element        | O(log n)           | O(log n)         | N/A
  Remove arbitrary   | O(n)               | O(log n)         | N/A
  Iteration order    | Not sorted!        | Sorted           | Sorted after sort
  Use case           | Top-K, streaming   | Unique + sorted  | Sort once & search

COMMON INTERVIEW QUESTIONS
---------------------------
Q: Does PriorityQueue iterate in sorted order?
A: NO. Iterating a PriorityQueue does NOT produce elements in priority order.
   Only poll() reliably returns elements in priority (min) order, one at a time.
   The underlying array is a heap — only the root is guaranteed to be the minimum.

Q: What's the difference between Comparable and Comparator?
A: Comparable<T>: implemented by the class itself (natural ordering).
   Method: int compareTo(T other). One ordering per class.
   Example: String, Integer, LocalDate implement Comparable.

   Comparator<T>: external, separate object defining custom ordering.
   Method: int compare(T o1, T o2). Multiple orderings possible for same class.
   Used when: you don't own the class, or need multiple sort strategies.

Q: How do you create a max-heap with PriorityQueue?
A: Pass Comparator.reverseOrder() (or Collections.reverseOrder()) in the constructor:
     PriorityQueue<Integer> maxHeap = new PriorityQueue<>(Comparator.reverseOrder());
   Or use a lambda: new PriorityQueue<>((a, b) -> b - a);
   WARNING: (a, b) -> b - a can overflow for extreme values. Prefer Comparator.reverseOrder().

Q: What is the time complexity of building a PriorityQueue from a Collection?
A: O(n) — using the constructor PriorityQueue(Collection<E> c). Java uses the Floyd
   heapify algorithm (bottom-up heap construction) which is O(n), not O(n log n).
