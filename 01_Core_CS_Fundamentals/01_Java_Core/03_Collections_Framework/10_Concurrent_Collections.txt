CONCURRENT COLLECTIONS
=======================

WHY CONCURRENT COLLECTIONS?
-----------------------------
  Regular collections (ArrayList, HashMap, HashSet) are NOT thread-safe.
  Naive solution: Collections.synchronizedList/Map — wraps with synchronized methods,
  but causes contention (all threads block on a single lock).

  Better solution: java.util.concurrent package — collections designed for high-concurrency
  with fine-grained locking, lock-free algorithms (CAS), and copy-on-write.

CONCURRENTHASHMAP
------------------
  java.util.concurrent.ConcurrentHashMap<K,V>
  - Thread-safe HashMap replacement with high concurrency
  - Java 7: divided into 16 segments (each segment is a separate lock)
  - Java 8+: per-bucket synchronized (CAS for first insert, synchronized for collision)
             → much finer granularity than Java 7

  Key properties:
  - Reads (get) are generally lock-free (non-blocking)
  - Writes (put) lock only the affected bucket
  - No null keys or null values (throws NullPointerException)
  - Iterator is weakly consistent — no ConcurrentModificationException

  Atomic operations (critical for thread safety):
    putIfAbsent(K key, V value)             // insert only if absent — atomic
    replace(K key, V oldValue, V newValue)  // conditional replace — atomic
    remove(K key, V value)                  // conditional remove — atomic
    compute(K key, BiFunction)              // atomic compute
    computeIfAbsent(K key, Function)        // atomic compute-if-absent
    merge(K key, V value, BiFunction)       // atomic merge
    getOrDefault(K key, V defaultVal)

  Example:
    ConcurrentHashMap<String, Integer> map = new ConcurrentHashMap<>();
    map.put("a", 1);
    map.put("b", 2);
    map.putIfAbsent("a", 99);  // no-op, "a" already exists
    map.putIfAbsent("c", 3);   // inserts "c" → 3

    // Thread-safe counter pattern
    map.merge("a", 1, Integer::sum); // a = 1 + 1 = 2
    map.merge("a", 1, Integer::sum); // a = 2 + 1 = 3

    // Concurrent word count
    ConcurrentHashMap<String, Long> wordCount = new ConcurrentHashMap<>();
    words.forEach(word -> wordCount.merge(word, 1L, Long::sum));

  Performance: ConcurrentHashMap is orders of magnitude faster than Hashtable or
               Collections.synchronizedMap() under concurrent load.

COPYONWRITEARRAYLIST
---------------------
  java.util.concurrent.CopyOnWriteArrayList<E>
  - Thread-safe List where all mutations (add/set/remove) create a fresh copy of the underlying array
  - Reads are non-blocking — always operate on a consistent snapshot
  - Writes are expensive — O(n) per modification (copy entire array)
  - Iterator operates on snapshot at creation time — never sees later modifications, no CME

  Best for: Read-heavy workloads with rare writes (e.g., event listener lists, observer lists)

  Example:
    CopyOnWriteArrayList<String> list = new CopyOnWriteArrayList<>();
    list.add("A"); list.add("B"); list.add("C");

    for (String s : list) {
        System.out.println(s);  // safe — iterating snapshot
        list.add("D");          // no CME — but "D" not seen in this iteration
    }

COPYONWRITEARRAYSET
--------------------
  java.util.concurrent.CopyOnWriteArraySet<E>
  - Thread-safe Set backed by CopyOnWriteArrayList
  - Same trade-offs: fast reads, slow writes
  - Uniqueness: uses equals() check (linear scan) — O(n) for add

BLOCKINGQUEUE AND BLOCKINGDEQUE
---------------------------------
  java.util.concurrent.BlockingQueue<E>
  - Thread-safe queue that supports blocking put() and take()
  - put(e): inserts, BLOCKS if queue is full (bounded queues)
  - take():  removes, BLOCKS if queue is empty
  - offer(e, timeout, unit): timed offer — returns false if timeout expires
  - poll(timeout, unit):     timed poll — returns null if timeout expires

  Implementations:
    ArrayBlockingQueue   — bounded, fair or non-fair ordering, backed by fixed-size array
    LinkedBlockingQueue  — optionally bounded (default: Integer.MAX_VALUE), backed by linked nodes
    PriorityBlockingQueue — unbounded priority queue; put never blocks; take blocks if empty
    SynchronousQueue     — zero capacity: each put must match a take (handoff)
    DelayQueue           — elements become available after a delay (schedule tasks)
    LinkedTransferQueue  — unbounded; transfer() blocks until consumer is ready

  Example — Producer-Consumer:
    BlockingQueue<Integer> queue = new ArrayBlockingQueue<>(5);

    Thread producer = new Thread(() -> {
        for (int i = 0; i < 10; i++) {
            try {
                queue.put(i);           // blocks if queue is full
                System.out.println("Produced: " + i);
            } catch (InterruptedException e) { Thread.currentThread().interrupt(); }
        }
    });

    Thread consumer = new Thread(() -> {
        for (int i = 0; i < 10; i++) {
            try {
                int val = queue.take();  // blocks if queue is empty
                System.out.println("Consumed: " + val);
            } catch (InterruptedException e) { Thread.currentThread().interrupt(); }
        }
    });
    producer.start(); consumer.start();

CONCURRENTLINKEDQUEUE / CONCURRENTLINKEDDEQUE
----------------------------------------------
  - Unbounded, non-blocking, thread-safe queue/deque
  - Uses lock-free CAS (Compare-And-Swap) operations
  - Does NOT block — use when you don't need backpressure
  - Good for high-throughput FIFO needs without blocking

  ConcurrentLinkedQueue<Integer> clq = new ConcurrentLinkedQueue<>();
  clq.offer(1); clq.offer(2);
  int val = clq.poll(); // 1

CONCURRENTSKIPLISTMAP AND CONCURRENTSKIPLISTSET
-------------------------------------------------
  - Thread-safe, sorted, concurrent alternatives to TreeMap and TreeSet
  - Use skip list internally (probabilistic data structure)
  - All operations O(log n) — concurrent reads/writes without global lock
  - Iterator is weakly consistent

  ConcurrentSkipListMap<String, Integer> skipMap = new ConcurrentSkipListMap<>();
  skipMap.put("banana", 2); skipMap.put("apple", 1);
  System.out.println(skipMap.firstKey()); // apple — sorted

COMMON INTERVIEW QUESTIONS
---------------------------
Q: What's the difference between ConcurrentHashMap and Collections.synchronizedMap()?
A: synchronizedMap(): wraps each method with a single lock — only one thread can access
   the map at a time, causing massive contention under load.
   ConcurrentHashMap (Java 8): locks individual buckets for writes; reads are lock-free.
   Allows multiple threads to read/write different buckets simultaneously. Much faster.

Q: Why doesn't ConcurrentHashMap allow null keys or values?
A: In a concurrent context, if get(key) returns null, it's ambiguous — it could mean the key
   doesn't exist, OR the mapped value is null. Without null, a null return from get() means
   "key not present." This is important for atomic operations like putIfAbsent.

Q: When would you use CopyOnWriteArrayList over ConcurrentHashMap?
A: CopyOnWriteArrayList is a List, not a Map — different data structures. Within lists,
   use CopyOnWriteArrayList when: reads greatly outnumber writes (read-heavy), you need
   safe iteration without locks (e.g., event listener lists), and write cost (O(n) copy) is acceptable.

Q: What's the difference between BlockingQueue.offer() and put()?
A: put() blocks indefinitely until space is available (bounded queue).
   offer() returns false immediately if no space; offer(e, timeout, unit) waits up to a timeout.
   Use put() for producer-consumer where blocking is desired behavior.
   Use offer() for time-bounded or non-blocking producers.
