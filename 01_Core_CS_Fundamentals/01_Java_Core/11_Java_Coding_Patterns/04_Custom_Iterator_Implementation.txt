CUSTOM ITERATOR IMPLEMENTATION
================================

PURPOSE
-------
  Implementing Iterator lets you create custom iteration behavior over your own data structures.
  This is the basis of the Iterator design pattern (GoF) and the Java Iterable/Iterator contracts.
  Understanding it demonstrates: design patterns, generics, inner classes, fail-fast behavior.

CORE INTERFACES
----------------
  // Iterator — how you iterate
  public interface Iterator<E> {
      boolean hasNext();   // returns true if more elements remain
      E next();            // returns next element; throws NoSuchElementException if none
      default void remove() {   // optional; removes the last element returned by next()
          throw new UnsupportedOperationException();
      }
  }

  // Iterable — makes your class usable in for-each loops
  public interface Iterable<T> {
      Iterator<T> iterator();
  }
  // A class implementing Iterable<T> can be used in enhanced for-each:
  // for (T item : myCollection) { ... }

COMPLETE CUSTOM STACK IMPLEMENTATION WITH ITERATOR
----------------------------------------------------
  public class Stack<E> implements Iterable<E> {
      private Object[] elements;
      private int size;
      private int modCount = 0;  // modification count for fail-fast detection

      @SuppressWarnings("unchecked")
      public Stack(int initialCapacity) {
          elements = new Object[initialCapacity];
      }

      public void push(E item) {
          ensureCapacity();
          elements[size++] = item;
          modCount++;  // structural modification
      }

      @SuppressWarnings("unchecked")
      public E pop() {
          if (size == 0) throw new EmptyStackException();
          E item = (E) elements[--size];
          elements[size] = null;  // prevent memory leak (null out popped slot)
          modCount++;  // structural modification
          return item;
      }

      @SuppressWarnings("unchecked")
      public E peek() {
          if (size == 0) throw new EmptyStackException();
          return (E) elements[size - 1];
      }

      public boolean isEmpty() { return size == 0; }
      public int size()         { return size; }

      private void ensureCapacity() {
          if (size == elements.length) {
              elements = Arrays.copyOf(elements, size * 2 + 1);
          }
      }

      // Return an Iterator — top-to-bottom iteration (most recently pushed first)
      @Override
      public Iterator<E> iterator() {
          return new StackIterator();
      }

      // Private inner class — has access to Stack's private fields
      private class StackIterator implements Iterator<E> {
          private int cursor = size - 1;               // start at top
          private int expectedModCount = modCount;     // snapshot of modCount at creation

          @Override
          public boolean hasNext() {
              return cursor >= 0;
          }

          @Override
          @SuppressWarnings("unchecked")
          public E next() {
              checkForComodification();  // fail-fast check
              if (!hasNext()) throw new NoSuchElementException();
              return (E) elements[cursor--];
          }

          // Fail-fast: detect if the stack was modified during iteration
          private void checkForComodification() {
              if (modCount != expectedModCount) {
                  throw new ConcurrentModificationException();
              }
          }

          // Optional remove() — removes the last element returned by next()
          // Not implementing here — stack semantics don't support arbitrary removal
      }
  }

  // Usage:
  Stack<String> stack = new Stack<>(10);
  stack.push("a");
  stack.push("b");
  stack.push("c");

  // Enhanced for-each (uses Iterable.iterator() implicitly)
  for (String s : stack) {
      System.out.println(s);  // prints: c, b, a (LIFO order)
  }

  // Direct Iterator usage:
  Iterator<String> it = stack.iterator();
  while (it.hasNext()) {
      System.out.println(it.next());
  }

CUSTOM RANGE ITERATOR (LAZY GENERATION)
-----------------------------------------
  // Iterator that generates values on-the-fly — no backing collection needed
  public class Range implements Iterable<Integer> {
      private final int start;
      private final int end;   // exclusive
      private final int step;

      public Range(int start, int end, int step) {
          if (step == 0) throw new IllegalArgumentException("step cannot be zero");
          this.start = start; this.end = end; this.step = step;
      }

      @Override
      public Iterator<Integer> iterator() {
          return new Iterator<>() {
              private int current = start;

              @Override
              public boolean hasNext() {
                  return step > 0 ? current < end : current > end;
              }

              @Override
              public Integer next() {
                  if (!hasNext()) throw new NoSuchElementException();
                  int value = current;
                  current += step;
                  return value;
              }
          };
      }
  }

  // Usage:
  for (int n : new Range(1, 10, 2)) {
      System.out.print(n + " ");  // 1 3 5 7 9
  }

TREE ITERATOR (PRE-ORDER TRAVERSAL)
-------------------------------------
  public class BinaryTree<E> implements Iterable<E> {
      private Node<E> root;

      static class Node<E> {
          E value; Node<E> left, right;
          Node(E v) { value = v; }
      }

      @Override
      public Iterator<E> iterator() {
          return new PreOrderIterator();
      }

      private class PreOrderIterator implements Iterator<E> {
          private final Deque<Node<E>> stack = new ArrayDeque<>();

          PreOrderIterator() {
              if (root != null) stack.push(root);
          }

          @Override public boolean hasNext() { return !stack.isEmpty(); }

          @Override
          public E next() {
              if (!hasNext()) throw new NoSuchElementException();
              Node<E> node = stack.pop();
              // Push right first so left is processed first (pre-order: root, left, right)
              if (node.right != null) stack.push(node.right);
              if (node.left  != null) stack.push(node.left);
              return node.value;
          }
      }
  }

ITERATOR VS ITERABLE VS LISTITERATOR
--------------------------------------
  Iterator:     forward-only, read (+ optional remove)
  ListIterator: bidirectional (hasPrevious/previous), can add/set — only for List
  Iterable:     factory for Iterator; enables for-each

  ListIterator<String> li = list.listIterator(list.size());  // start from end
  while (li.hasPrevious()) {
      System.out.println(li.previous());  // iterate backwards
  }

FAIL-FAST PATTERN EXPLAINED
-----------------------------
  ArrayList, HashMap, and most JDK collections are fail-fast.
  They maintain a modCount field incremented on every structural modification.
  The iterator captures expectedModCount at creation.
  On each next() call, if modCount != expectedModCount → ConcurrentModificationException.

  Why fail-fast not fail-safe?
  Fail-fast detects bugs early (concurrent or same-thread modification during iteration).
  Fail-safe (CopyOnWriteArrayList, ConcurrentHashMap) operates on a snapshot — no CME but
  may see stale data and has higher memory overhead.

INTERVIEW DISCUSSION POINTS
-----------------------------
  Q: How does for-each work under the hood?
  A: The Java compiler translates for (T item : iterable) into:
     Iterator<T> it = iterable.iterator();
     while (it.hasNext()) { T item = it.next(); /* body */ }
     Arrays have special handling (indexed loop); Iterable uses .iterator().

  Q: When would you implement a custom Iterator?
  A: When you have a custom data structure (tree, graph, skip list) and want to:
     (1) make it usable with for-each and Java Stream APIs (stream()/spliterator()),
     (2) hide the internal structure from callers,
     (3) support lazy/on-demand element generation (like Range above).

  Q: What is a Spliterator and how does it differ from Iterator?
  A: Spliterator (Java 8) is a special Iterator that can split itself for parallel
     processing. It reports characteristics (ORDERED, SORTED, SIZED, DISTINCT, etc.)
     and supports tryAdvance() (consume one element) and forEachRemaining() (consume all).
     Spliterators are used internally by Streams for parallel stream operations.
     Implementing Spliterator lets your custom collection participate in parallel streams.
