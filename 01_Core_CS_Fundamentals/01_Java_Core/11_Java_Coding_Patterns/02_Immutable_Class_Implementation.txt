IMMUTABLE CLASS IMPLEMENTATION
===============================

WHAT IS IMMUTABILITY?
---------------------
  An immutable object's state cannot change after construction.
  All reads are thread-safe by definition — no synchronization needed.
  Immutable objects can be freely shared, cached, and used as HashMap keys without defensive copies.
  Examples in JDK: String, Integer, LocalDate, BigDecimal, Path.

RULES FOR CREATING AN IMMUTABLE CLASS
--------------------------------------
  1. Declare the class final (prevents subclasses from adding mutable state).
  2. Make all fields private and final.
  3. No setter methods.
  4. Defensive copy on construction: if a mutable object is passed in, copy it.
  5. Defensive copy on return: if you return a mutable object field, return a copy.
  6. Initialize all fields in the constructor (or via initialization).

BASIC IMMUTABLE CLASS
----------------------
  public final class Money {
      private final String currency;
      private final BigDecimal amount;

      public Money(String currency, BigDecimal amount) {
          // Validate inputs
          Objects.requireNonNull(currency, "currency must not be null");
          Objects.requireNonNull(amount, "amount must not be null");
          if (amount.compareTo(BigDecimal.ZERO) < 0) {
              throw new IllegalArgumentException("amount must be non-negative");
          }
          this.currency = currency;
          this.amount = amount;  // BigDecimal is itself immutable — safe to assign directly
      }

      public String getCurrency() { return currency; }
      public BigDecimal getAmount()  { return amount; }

      // Transformations return new instances — "wither" pattern
      public Money add(Money other) {
          if (!this.currency.equals(other.currency)) {
              throw new IllegalArgumentException("Currency mismatch");
          }
          return new Money(this.currency, this.amount.add(other.amount));
      }

      @Override
      public boolean equals(Object o) {
          if (this == o) return true;
          if (!(o instanceof Money m)) return false;
          return currency.equals(m.currency) && amount.compareTo(m.amount) == 0;
      }

      @Override
      public int hashCode() {
          return Objects.hash(currency, amount.stripTrailingZeros());
      }

      @Override
      public String toString() {
          return amount + " " + currency;
      }
  }

IMMUTABLE CLASS WITH MUTABLE FIELDS (DEFENSIVE COPYING)
---------------------------------------------------------
  public final class Period {
      private final Date start;  // Date is MUTABLE — must defensively copy!
      private final Date end;

      public Period(Date start, Date end) {
          // Defensive copy IN constructor (before validation)
          this.start = new Date(start.getTime());
          this.end   = new Date(end.getTime());
          // Validate AFTER copying (prevents TOCTOU attack with shared Date)
          if (this.start.after(this.end)) {
              throw new IllegalArgumentException("start must be before end");
          }
      }

      // Defensive copy OUT of getters
      public Date getStart() { return new Date(start.getTime()); }
      public Date getEnd()   { return new Date(end.getTime()); }

      // Note: In modern Java, use LocalDate/LocalDateTime — they are immutable.
      // No defensive copying needed for immutable types.
  }

IMMUTABLE CLASS WITH COLLECTIONS
----------------------------------
  public final class ImmutableConfig {
      private final String host;
      private final int port;
      private final List<String> tags;  // List is mutable — must guard it

      public ImmutableConfig(String host, int port, List<String> tags) {
          this.host = Objects.requireNonNull(host);
          this.port = port;
          // Defensive copy: make an immutable copy of the input list
          this.tags = List.copyOf(tags);  // Java 10+ — creates an unmodifiable snapshot
          // Alternative (Java 8+): Collections.unmodifiableList(new ArrayList<>(tags))
      }

      public String getHost() { return host; }
      public int getPort()    { return port; }

      // Safe to return directly — tags is already an unmodifiable snapshot
      public List<String> getTags() { return tags; }
  }

LAZY INITIALIZATION IN IMMUTABLE CLASSES
-----------------------------------------
  Safe pattern: cache computed values using a non-final field (but must be safely published).
  This is safe because the value is derived deterministically from immutable state.

  public final class ImmutablePoint {
      private final double x, y;
      private int cachedHashCode;  // lazily computed; 0 means not computed

      public ImmutablePoint(double x, double y) { this.x = x; this.y = y; }

      @Override
      public int hashCode() {
          int result = cachedHashCode;
          if (result == 0) {
              result = Double.hashCode(x) * 31 + Double.hashCode(y);
              if (result == 0) result = 1;  // distinguish 0 (uncalculated) from 0 (hash is 0)
              cachedHashCode = result;       // benign race — same value always written
          }
          return result;
      }
      // Note: String uses the same pattern for its hashCode
  }

RECORD AS IMMUTABLE CLASS (JAVA 16+)
--------------------------------------
  record Money(String currency, BigDecimal amount) {
      // Compact canonical constructor for validation
      Money {
          Objects.requireNonNull(currency, "currency required");
          Objects.requireNonNull(amount, "amount required");
          if (amount.compareTo(BigDecimal.ZERO) < 0)
              throw new IllegalArgumentException("amount must be non-negative");
      }

      // Custom method — records are still classes!
      public Money add(Money other) {
          if (!this.currency.equals(other.currency)) throw new IllegalArgumentException("currency mismatch");
          return new Money(currency, amount.add(other.amount));
      }
  }
  // Records are automatically: final, all fields private final,
  // no setters, canonical constructor, equals/hashCode/toString generated.
  // Immutable if all component types are immutable (BigDecimal, String are).
  // If a component is mutable (e.g., Date), defensive copy in the compact constructor.

IMMUTABILITY IN CONCURRENT CONTEXTS
-------------------------------------
  JMM guarantees: final fields written in a constructor are safely published to all threads
  after the constructor completes — WITHOUT any synchronization!

  This means: you can safely share an immutable object between threads by handing off its
  reference after construction (e.g., via volatile, AtomicReference, synchronized publication).

  An immutable object shared between threads needs no locking — it is inherently thread-safe.

COMMON MISTAKES
----------------
  1. Returning internal mutable array directly:
     private final int[] data;
     public int[] getData() { return data; }  // WRONG — caller can mutate the array!
     Fix: return data.clone();   // or use List.of() / Collections.unmodifiableList()

  2. Storing passed-in mutable object directly:
     this.date = date;  // date is still mutable outside the class
     Fix: this.date = new Date(date.getTime());

  3. Class not final — subclass can add mutable state:
     class ImmutableBase { ... }
     class MutableSubclass extends ImmutableBase { int mutableField; }
     Fix: declare class final.

  4. Forgetting equals/hashCode — immutable objects frequently used as Map keys.
     Fix: always override both; use Objects.equals() and Objects.hash().
