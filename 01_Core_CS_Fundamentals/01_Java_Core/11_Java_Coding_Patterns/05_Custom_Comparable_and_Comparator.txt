CUSTOM COMPARABLE AND COMPARATOR
==================================

PURPOSE
--------
  Defining natural ordering (Comparable) or custom ordering (Comparator) is foundational
  for sorting, TreeMap/TreeSet usage, and priority queues. This pattern demonstrates:
  generics, lambda expressions, method references, and the Comparator API (Java 8+).

COMPARABLE — NATURAL ORDERING
-------------------------------
  Implement Comparable<T> to give your class a natural order that is used by:
  - Collections.sort() / Arrays.sort() without a Comparator
  - TreeSet / TreeMap (as the default comparator)
  - Stream.sorted() without a Comparator

  Contract (must be consistent with equals!):
  - compareTo(other) < 0  → this < other
  - compareTo(other) == 0 → this == other (ideally consistent with equals())
  - compareTo(other) > 0  → this > other
  - Antisymmetric: sgn(x.compareTo(y)) == -sgn(y.compareTo(x))
  - Transitive: if x > y and y > z, then x > z

  // Student ordered by GPA descending, then by name ascending
  public final class Student implements Comparable<Student> {
      private final String name;
      private final double gpa;
      private final int graduationYear;

      public Student(String name, double gpa, int graduationYear) {
          this.name = Objects.requireNonNull(name);
          this.gpa = gpa;
          this.graduationYear = graduationYear;
      }

      @Override
      public int compareTo(Student other) {
          // Primary: GPA descending (higher GPA first)
          int cmp = Double.compare(other.gpa, this.gpa);  // reversed for descending
          if (cmp != 0) return cmp;

          // Secondary: name ascending
          cmp = this.name.compareTo(other.name);
          if (cmp != 0) return cmp;

          // Tertiary: graduation year ascending
          return Integer.compare(this.graduationYear, other.graduationYear);
      }

      @Override
      public boolean equals(Object o) {
          if (this == o) return true;
          if (!(o instanceof Student s)) return false;
          // Must be consistent with compareTo!
          return Double.compare(gpa, s.gpa) == 0
              && name.equals(s.name)
              && graduationYear == s.graduationYear;
      }

      @Override
      public int hashCode() {
          return Objects.hash(name, gpa, graduationYear);
      }

      public String getName()           { return name; }
      public double getGpa()            { return gpa; }
      public int getGraduationYear()    { return graduationYear; }

      @Override
      public String toString() {
          return name + " (GPA=" + gpa + ", year=" + graduationYear + ")";
      }
  }

  // Usage:
  List<Student> students = new ArrayList<>(List.of(
      new Student("Alice", 3.9, 2024),
      new Student("Bob",   3.7, 2023),
      new Student("Carol", 3.9, 2023)
  ));
  Collections.sort(students);  // uses Comparable.compareTo()
  students.forEach(System.out::println);
  // Carol (3.9, 2023), Alice (3.9, 2024), Bob (3.7, 2023)  — GPA desc, then name asc

COMMON PITFALL: SUBTRACTION TRICK
-----------------------------------
  WRONG: return this.age - other.age;   // can overflow for large/negative int values!
  CORRECT: return Integer.compare(this.age, other.age);   // always correct

  WRONG: return (int)(this.salary - other.salary);  // loses precision for doubles!
  CORRECT: return Double.compare(this.salary, other.salary);

COMPARATOR — EXTERNAL/CUSTOM ORDERING
--------------------------------------
  Comparator<T> defines an ordering externally — you can have multiple for the same class.
  Java 8 made Comparator a functional interface with powerful static/default factory methods.

  // Three different Comparators for Student
  Comparator<Student> byGpaDesc   = Comparator.comparingDouble(Student::getGpa).reversed();
  Comparator<Student> byNameAsc   = Comparator.comparing(Student::getName);
  Comparator<Student> byYearDesc  = Comparator.comparingInt(Student::getGraduationYear).reversed();

  // Composed: GPA descending, then name ascending, then year descending
  Comparator<Student> fullOrder = Comparator
      .comparingDouble(Student::getGpa).reversed()
      .thenComparing(Student::getName)
      .thenComparingInt(Student::getGraduationYear).reversed();

  students.sort(fullOrder);
  students.stream().sorted(fullOrder).forEach(System.out::println);

  // Null-safe Comparators (Java 8+):
  Comparator<String> nullFirstAsc  = Comparator.nullsFirst(Comparator.naturalOrder());
  Comparator<String> nullLastDesc  = Comparator.nullsLast(Comparator.reverseOrder());

  // Custom lambda Comparator:
  Comparator<String> byLength = (a, b) -> Integer.compare(a.length(), b.length());
  Comparator<String> byLengthThenAlpha = Comparator
      .comparingInt(String::length)
      .thenComparing(Comparator.naturalOrder());

COMPARATOR API SUMMARY (JAVA 8+)
----------------------------------
  Static factory methods:
  Comparator.comparing(keyExtractor)           — compare by extracted key (natural order)
  Comparator.comparingInt/Long/Double(...)     — primitive-specialized (avoids boxing)
  Comparator.naturalOrder()                    — uses Comparable.compareTo()
  Comparator.reverseOrder()                    — reverses naturalOrder()
  Comparator.nullsFirst(comparator)            — null values come first
  Comparator.nullsLast(comparator)             — null values come last

  Default instance methods:
  .reversed()                                  — reverses this comparator
  .thenComparing(Comparator)                   — secondary comparator when this returns 0
  .thenComparing(keyExtractor)                 — secondary key extraction
  .thenComparingInt/Long/Double(keyExtractor)  — primitive-specialized secondary

TREEMAP AND TREESET WITH COMPARATOR
-------------------------------------
  TreeMap<String, Integer> map = new TreeMap<>(Comparator.reverseOrder());
  // Keys stored in reverse alphabetical order

  TreeSet<Student> set = new TreeSet<>(
      Comparator.comparingDouble(Student::getGpa)
                .reversed()
                .thenComparing(Student::getName)
  );
  // Set ordered by GPA descending; the comparator defines equality for the TreeSet!
  // Two students with same GPA and name would be considered "equal" and not both stored.

  Note: Comparator used by TreeSet/TreeMap defines both ORDER and EQUALITY.
  If comparator returns 0 for two objects, TreeSet treats them as the same element.
  This can produce unexpected results if comparator.compare(a,b)==0 but !a.equals(b).

PRIORITY QUEUE WITH COMPARATOR
--------------------------------
  PriorityQueue<Student> minGpa = new PriorityQueue<>(
      Comparator.comparingDouble(Student::getGpa)
  );
  PriorityQueue<Student> maxGpa = new PriorityQueue<>(
      Comparator.comparingDouble(Student::getGpa).reversed()
  );

  minGpa.offer(new Student("Alice", 3.9, 2024));
  minGpa.offer(new Student("Bob",   3.7, 2023));
  System.out.println(minGpa.poll().getName());  // "Bob" — lowest GPA first

COMPLETE EXAMPLE: SORTING A LIST OF EMPLOYEES
----------------------------------------------
  record Employee(String name, String dept, double salary, int yearsExp) {}

  List<Employee> employees = List.of(
      new Employee("Alice", "Engineering", 95000, 5),
      new Employee("Bob",   "Marketing",   72000, 3),
      new Employee("Carol", "Engineering", 88000, 7),
      new Employee("Dave",  "Marketing",   75000, 3)
  );

  // Sort: Engineering first, then by salary descending, then by name
  Comparator<Employee> sorter = Comparator
      .comparing(Employee::dept, (a, b) -> {
          // Custom: Engineering before Marketing
          if (a.equals(b)) return 0;
          return "Engineering".equals(a) ? -1 : 1;
      })
      .thenComparingDouble(Employee::salary).reversed()
      .thenComparing(Employee::name);

  employees.stream().sorted(sorter).forEach(System.out::println);

INTERVIEW DISCUSSION POINTS
-----------------------------
  Q: When would you use Comparable vs Comparator?
  A: Comparable when there's one clear, natural order intrinsic to the class (Date, Integer,
     String — always ordered by value). Comparator when you need multiple orderings, when
     you don't control the class (sorting third-party objects), or for ad-hoc orderings
     (e.g., "sort employees by salary for this one report").

  Q: What happens if compareTo() is inconsistent with equals()?
  A: Unexpected behavior in sorted collections. TreeMap/TreeSet use compareTo() for equality —
     if a.compareTo(b)==0 but !a.equals(b), one will silently overwrite the other in a TreeMap.
     SortedSet/SortedMap documentation states the comparator should be consistent with equals.
     For arrays/list sorting, inconsistency just means the equals-based behavior of contains()
     might not match the sort order.

  Q: How do you sort a list in reverse order?
  A: Three ways:
     (1) Collections.sort(list, Comparator.reverseOrder()); — if T is Comparable
     (2) list.sort(Comparator.comparingX(keyFn).reversed());
     (3) list.sort(Collections.reverseOrder(customComparator));
