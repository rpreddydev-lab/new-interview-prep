VAR — LOCAL VARIABLE TYPE INFERENCE (Java 10+)
================================================

INTRODUCTION
-------------
  Java 10 introduced `var` for local variable type inference.
  The compiler infers the type from the right-hand side of the assignment.
  `var` is NOT a keyword — it is a reserved type name (you can still use
  `var` as a variable name, though strongly discouraged).

  var x = 42;            // inferred as int
  var name = "Alice";    // inferred as String
  var list = new ArrayList<String>();  // inferred as ArrayList<String>

  The type is FIXED at compile time — var is NOT dynamic like JavaScript's var.
  It is purely syntactic sugar; the bytecode is identical to explicit typing.

─────────────────────────────────────────────────────────────
WHERE var CAN BE USED
─────────────────────────────────────────────────────────────
  ✅ Local variables with initializers
       var count = 0;

  ✅ For-each loop variables
       for (var entry : map.entrySet()) { ... }

  ✅ Traditional for loop variables
       for (var i = 0; i < 10; i++) { ... }

  ✅ Try-with-resources variables
       try (var conn = dataSource.getConnection()) { ... }

  ✅ Lambda parameter types (Java 11+)
       Consumer<String> c = (var s) -> System.out.println(s);
       // Useful when you need to add annotations to lambda params:
       Consumer<String> c = (@NotNull var s) -> process(s);

─────────────────────────────────────────────────────────────
WHERE var CANNOT BE USED
─────────────────────────────────────────────────────────────
  ❌ Method parameters
       void process(var x) { }  // compile error

  ❌ Return types
       var computeTotal() { }  // compile error

  ❌ Instance/static fields
       private var count = 0;  // compile error

  ❌ Catch variables
       catch (var e) { }  // compile error (Java 10-10; allowed from Java 11 in some contexts — but generally avoid)

  ❌ Without an initializer
       var x;  // compile error — cannot infer type

  ❌ Array initializers without new
       var arr = {1, 2, 3};  // compile error
       var arr = new int[]{1, 2, 3};  // ✅ OK

  ❌ Null literal
       var x = null;  // compile error — cannot infer type from null

─────────────────────────────────────────────────────────────
TYPE INFERENCE RULES AND TRICKY CASES
─────────────────────────────────────────────────────────────
  1. Infers the DECLARED type, not the runtime type:
     var list = new ArrayList<String>();
     // list is ArrayList<String>, NOT List<String>
     // You lose the interface abstraction — be cautious

  2. Diamond operator infers Object without help:
     var list = new ArrayList<>();   // inferred as ArrayList<Object> ⚠️
     var list = new ArrayList<String>();  // ✅ correct

  3. Anonymous class types can be captured:
     var obj = new Object() {
         int value = 42;
         String label = "hello";
     };
     System.out.println(obj.value);  // ✅ accessible — non-denotable type captured!
     // This is a rare but powerful use case — var captures the anonymous class type

  4. Intersection types (advanced):
     // Cannot express intersection types without var:
     // <T extends Serializable & Comparable<T>> — can be captured in var in some patterns

  5. With conditional expressions:
     var result = condition ? 1 : 2.0;  // inferred as double (widening)
     var result = condition ? "a" : 1;  // inferred as Object ⚠️ (common trap)

─────────────────────────────────────────────────────────────
READABILITY GUIDELINES (JEP 286 Style Guide)
─────────────────────────────────────────────────────────────
  USE var when:
  - The type is obvious from the right-hand side:
      var map = new HashMap<String, List<Integer>>();  // clear and shorter

  - The type name is long and adds no value:
      var entries = employeeRepository.findAllActiveEntries();

  - In for-each loops over typed collections

  AVOID var when:
  - The initializer does not make the type obvious:
      var result = compute();  // what type is returned?

  - When narrowing to a broader interface is intentional:
      List<String> list = new ArrayList<>();  // signals "program to interface"
      // var list = new ArrayList<>(); loses this intent

  - In public APIs or when the type is part of the documentation

─────────────────────────────────────────────────────────────
LAMBDA PARAMETERS WITH var (Java 11)
─────────────────────────────────────────────────────────────
  Java 11 extended var to lambda parameters, primarily to allow annotations:

  // Without var — no way to annotate:
  list.stream().filter(s -> s.startsWith("A"));

  // With var — annotations possible:
  list.stream().filter((@NonNull var s) -> s.startsWith("A"));

  ⚠️ All lambda parameters must consistently use either all var or no var:
      (var x, var y) -> x + y  // ✅
      (var x, y) -> x + y      // ❌ compile error
      (x, y) -> x + y          // ✅

─────────────────────────────────────────────────────────────
PERFORMANCE
─────────────────────────────────────────────────────────────
  Zero runtime overhead. var is resolved entirely at compile time.
  The compiled .class file is identical to code written with explicit types.

─────────────────────────────────────────────────────────────
COMMON INTERVIEW QUESTIONS
─────────────────────────────────────────────────────────────
  Q: Is var dynamically typed like JavaScript?
  A: No. var is statically typed. The type is inferred at compile time and
     is fixed. You cannot reassign a different type to a var variable.

  Q: Can var be used for fields?
  A: No — only local variables, for-loop variables, and try-with-resources.

  Q: What type is inferred for: var x = new ArrayList<>()?
  A: ArrayList<Object>. The diamond without type arguments defaults to Object
     when there is no other context for inference.

  Q: What does var = null infer?
  A: Compile error. The type cannot be inferred from null alone.

  Q: When is var capturing an anonymous class type useful?
  A: When you need to access fields/methods of an anonymous class that are
     not declared in any named interface or superclass. With an explicit type
     (Object), those members would be inaccessible.

  Q: Is var a keyword in Java?
  A: No, it is a reserved type name. This means existing code using 'var'
     as a variable name continues to compile (though it is bad practice).
