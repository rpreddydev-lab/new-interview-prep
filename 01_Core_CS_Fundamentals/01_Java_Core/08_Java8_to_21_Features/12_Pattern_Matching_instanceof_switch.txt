PATTERN MATCHING: instanceof AND switch
========================================

PATTERN MATCHING FOR instanceof (JAVA 16 — JEP 394)
------------------------------------------------------
  Before Java 16, every instanceof check required a separate cast:
  // Old:
  if (obj instanceof String) {
      String s = (String) obj;   // redundant cast
      System.out.println(s.length());
  }

  // New — pattern variable:
  if (obj instanceof String s) {
      System.out.println(s.length()); // s is a String, bound in this scope
  }

  The pattern variable s is:
  - Only accessible when the instanceof check succeeds
  - Automatically typed (no cast needed)
  - Effectively final (cannot be reassigned in the if block — actually can be reassigned in Java, but convention is not to)
  - Scoped to the true branch of the if (and else if the pattern can be disproven)

  // Combining with boolean logic:
  if (obj instanceof String s && s.length() > 5) {
      System.out.println("Long string: " + s);  // s in scope — && evaluates left-to-right
  }

  // Negation: variable NOT in scope in the false branch:
  if (!(obj instanceof String s)) {
      return; // early exit
  }
  // s IS in scope here (after the guard):
  System.out.println(s.toUpperCase());

PATTERN MATCHING FOR switch (JAVA 21 — JEP 441, PREVIEW FROM JAVA 17)
-----------------------------------------------------------------------
  Switch expressions gained type patterns — match on the type AND bind a variable:

  String describe(Object obj) {
      return switch (obj) {
          case Integer i   -> "Int: " + i;
          case Double d    -> "Double: " + d;
          case String s    -> "String: " + s;
          case null        -> "null";
          default          -> "Other: " + obj;
      };
  }

  // Previously required:
  // if (obj instanceof Integer) { Integer i = (Integer)obj; ... }
  // else if (obj instanceof Double) { ... }

GUARDED PATTERNS (WHEN CLAUSES — JAVA 21)
-------------------------------------------
  Add conditions to patterns using when:

  String classify(Object obj) {
      return switch (obj) {
          case Integer i when i > 0   -> "Positive int";
          case Integer i when i < 0   -> "Negative int";
          case Integer i              -> "Zero";
          case String s when s.isEmpty() -> "Empty string";
          case String s               -> "String: " + s;
          default                     -> "Other";
      };
  }

  // Multiple patterns can apply to the same type — order matters:
  // The first matching case wins.

RECORD PATTERNS (JAVA 21 — JEP 440)
--------------------------------------
  Destructure records directly in patterns:

  sealed interface Shape permits Circle, Rectangle {}
  record Circle(double radius) implements Shape {}
  record Rectangle(double w, double h) implements Shape {}

  double area(Shape s) {
      return switch (s) {
          case Circle(double r)         -> Math.PI * r * r;
          case Rectangle(double w, double h) -> w * h;
      };
  }

  // Nested record patterns:
  record Point(int x, int y) {}
  record ColoredPoint(Point p, String color) {}

  void print(Object obj) {
      if (obj instanceof ColoredPoint(Point(int x, int y), String color)) {
          System.out.println("x=" + x + " y=" + y + " color=" + color);
      }
  }

EXHAUSTIVENESS IN switch
--------------------------
  When switching on a sealed type with all permits covered, no default is required:

  sealed interface Result permits Success, Failure {}
  record Success(int code) implements Result {}
  record Failure(String msg) implements Result {}

  String show(Result r) {
      return switch (r) {
          case Success(int c) -> "OK: " + c;
          case Failure(String m) -> "ERR: " + m;
          // No default needed — compiler knows Result is only Success or Failure
      };
  }

  If a new permitted subclass is added, the switch above becomes a compile error —
  forcing the developer to handle the new case.

NULL HANDLING IN switch (JAVA 21)
-----------------------------------
  Historically, switch threw NullPointerException for null. Java 21 allows explicit
  null cases:

  switch (obj) {
      case null -> System.out.println("null value");
      case String s -> System.out.println("string: " + s);
      default -> System.out.println("other");
  }

SWITCH EXPRESSION vs SWITCH STATEMENT
---------------------------------------
  | Aspect               | Switch Statement           | Switch Expression                 |
  |----------------------|----------------------------|-----------------------------------|
  | Produces value       | No                         | Yes                               |
  | Arrow labels (->)    | Java 14+                   | Java 14+                          |
  | yield keyword        | N/A                        | In block arms                     |
  | Exhaustiveness       | Not required               | Required (for expressions)        |
  | Null handling        | NPE always                 | Explicit case null (Java 21)      |
  | Fall-through         | Yes with colon labels      | No with arrow labels              |
  | Pattern cases        | Java 21+                   | Java 21+                          |

PRACTICAL EXAMPLE — POLYMORPHISM WITHOUT METHODS
--------------------------------------------------
  // Traditional OOP approach:
  interface Animal { String speak(); }
  class Dog implements Animal { public String speak() { return "Woof"; } }
  class Cat implements Animal { public String speak() { return "Meow"; } }

  // Pattern matching approach (useful when you can't add methods):
  sealed interface Animal permits Dog, Cat {}
  record Dog(String name) implements Animal {}
  record Cat(String name) implements Animal {}

  String speak(Animal a) {
      return switch (a) {
          case Dog d -> d.name() + " says Woof";
          case Cat c -> c.name() + " says Meow";
      };
  }

COMMON INTERVIEW QUESTIONS
---------------------------
Q: What is pattern matching for instanceof and why is it better than the old approach?
A: Pattern matching (Java 16) extends instanceof to bind the matched value to a pattern
   variable in one step, eliminating the redundant cast. Old: if (obj instanceof String) {
   String s = (String) obj; ... }. New: if (obj instanceof String s) { ... }.
   It's safer (variable only exists when the match succeeds), less error-prone (no
   chance of mismatching the cast type), and more readable.

Q: What is a guarded pattern in switch?
A: A guarded pattern adds a boolean condition after a type pattern using the when clause
   (Java 21). Example: case Integer i when i > 0 -> "positive". If the type matches but
   the when condition is false, the case is skipped and the next case is tested. This
   replaces complex nested if-else inside case branches with a cleaner one-liner.

Q: How does pattern matching for switch improve upon chained if-instanceof?
A: Chained if-instanceof is verbose, error-prone (easy to forget a branch), and can't
   be used as an expression. Pattern matching for switch (Java 21) is concise, can
   produce a value (switch expression), supports guarded patterns (when), handles
   null explicitly, and when combined with sealed classes, provides compile-time
   exhaustiveness checks — the compiler warns if a case is missing.

Q: What is a record pattern and when is it useful?
A: A record pattern (Java 21) destructures a record's components directly inside a
   pattern, without calling accessor methods. Example: case Circle(double r) instead
   of case Circle c followed by double r = c.radius(). This is especially powerful for
   nested records: case ColoredPoint(Point(int x, int y), String color) extracts x, y,
   and color all at once, enabling highly expressive data-driven code.
