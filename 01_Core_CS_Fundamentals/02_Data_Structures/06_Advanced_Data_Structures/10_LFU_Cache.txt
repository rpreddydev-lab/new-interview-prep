================================================================
  LFU CACHE
================================================================

----------------------------------------------------------------
WHAT IS LFU CACHE?
----------------------------------------------------------------
LFU (Least Frequently Used) Cache evicts the entry that has been
accessed the FEWEST times when capacity is exceeded.

  Tie-breaking: among entries with the same minimum frequency,
  evict the LEAST RECENTLY USED (oldest in time).

  Requirements:
    get(key): return value if exists, else -1. O(1).
    put(key, value): insert or update. If full, evict LFU. O(1).

  Example (capacity = 2):
    put(1, 1)  -> freq: {1:1};  minFreq=1
    put(2, 2)  -> freq: {1:1, 2:1};  minFreq=1
    get(1)     -> freq: {1:2, 2:1};  minFreq=1 (2 is still freq 1)
    put(3, 3)  -> evict key 2 (freq=1, LRU among freq-1 items)
               -> freq: {1:2, 3:1};  minFreq=1
    get(2)     -> returns -1

----------------------------------------------------------------
DATA STRUCTURE DESIGN
----------------------------------------------------------------
Three data structures required for O(1):

  1. HashMap<Integer, Integer> keyToVal
     key -> value

  2. HashMap<Integer, Integer> keyToFreq
     key -> access frequency

  3. HashMap<Integer, LinkedHashSet<Integer>> freqToKeys
     frequency -> set of keys with that frequency
     (LinkedHashSet preserves insertion order -> LRU within same freq)

  4. int minFreq
     tracks the current minimum frequency (for O(1) eviction)

  Key insight for O(1):
    - On access: increment key's freq, move it from freqToKeys[f]
      to freqToKeys[f+1]. If freqToKeys[minFreq] is now empty,
      increment minFreq.
    - On eviction: remove from freqToKeys[minFreq] (LinkedHashSet
      gives LRU among same-freq keys), remove from both maps.
    - On insert: minFreq resets to 1 (new key always has freq=1).

----------------------------------------------------------------
FULL JAVA IMPLEMENTATION
----------------------------------------------------------------
  class LFUCache {
    Map<Integer, Integer> keyToVal  = new HashMap<>();
    Map<Integer, Integer> keyToFreq = new HashMap<>();
    Map<Integer, LinkedHashSet<Integer>> freqToKeys = new HashMap<>();
    int capacity;
    int minFreq = 0;

    LFUCache(int capacity) { this.capacity = capacity; }

    int get(int key) {
      if (!keyToVal.containsKey(key)) return -1;
      incrementFreq(key);
      return keyToVal.get(key);
    }

    void put(int key, int value) {
      if (capacity <= 0) return;
      if (keyToVal.containsKey(key)) {
        keyToVal.put(key, value);
        incrementFreq(key);
        return;
      }
      if (keyToVal.size() >= capacity) {
        removeMinFreqKey();
      }
      keyToVal.put(key, value);
      keyToFreq.put(key, 1);
      freqToKeys.computeIfAbsent(1, k -> new LinkedHashSet<>()).add(key);
      minFreq = 1;  // new key always has freq 1
    }

    private void incrementFreq(int key) {
      int freq = keyToFreq.get(key);
      keyToFreq.put(key, freq + 1);
      freqToKeys.get(freq).remove(key);
      if (freqToKeys.get(freq).isEmpty()) {
        freqToKeys.remove(freq);
        if (minFreq == freq) minFreq++;  // minFreq set is now empty, next freq is minFreq+1
      }
      freqToKeys.computeIfAbsent(freq + 1, k -> new LinkedHashSet<>()).add(key);
    }

    private void removeMinFreqKey() {
      LinkedHashSet<Integer> minFreqKeys = freqToKeys.get(minFreq);
      int evict = minFreqKeys.iterator().next();  // LRU among min-freq keys (first inserted)
      minFreqKeys.remove(evict);
      if (minFreqKeys.isEmpty()) freqToKeys.remove(minFreq);
      keyToVal.remove(evict);
      keyToFreq.remove(evict);
    }
  }

  Time: O(1) for both get and put
  Space: O(capacity)

  LinkedHashSet iterator().next() returns the OLDEST element
  (insertion order is preserved) -- this is the LRU tiebreaker.

----------------------------------------------------------------
CRITICAL DETAILS
----------------------------------------------------------------
  1. WHY LinkedHashSet?
     - O(1) add, remove (like HashSet)
     - Preserves insertion order (like LinkedList)
     - iterator().next() returns the LRU element (inserted first)
     -> Perfect for: O(1) add/remove + LRU ordering within same frequency

  2. minFreq UPDATE RULE:
     - After incrementFreq: minFreq increments ONLY if the old
       minFreq bucket becomes empty.
     - After put (new key): minFreq resets to 1 ALWAYS.
       A new key has freq=1, which is the new minimum.

  3. EDGE CASE: capacity == 0
     Return early; otherwise division by zero or wrong behavior.

  4. DIFFERENCE from LRU:
     LRU: one DLL + one map.
     LFU: three maps, more complex state management.

----------------------------------------------------------------
LFU vs LRU COMPARISON
----------------------------------------------------------------
  Feature               LRU                     LFU
  ---------------------------------------------------------------
  Eviction policy       Least recently used      Least frequently used
  Tie-breaking          N/A                      LRU among same freq
  Data structures       HashMap + DLL            3 HashMaps + LinkedHashSet
  Implementation complexity  Medium             High
  Time complexity       O(1)                    O(1)
  Space complexity      O(capacity)             O(capacity)
  Best for              General temporal access  Skewed frequency access
  Weakness              Cache pollution by one-time accesses  Frequency accumulation for old data
  Real use              CPU caches, web caches   DNS caches, CDN edge

----------------------------------------------------------------
INTERVIEW QUESTIONS
----------------------------------------------------------------

Q: Why do you use LinkedHashSet instead of a regular Set for
   freqToKeys?
A: freqToKeys maps a frequency to all keys with that frequency.
   When evicting, among all keys with minimum frequency we must
   evict the LEAST RECENTLY USED (the oldest). LinkedHashSet
   provides O(1) add, O(1) remove by key, and O(1) access to
   the "first" element (oldest insertion) via iterator().next().
   A regular HashSet doesn't preserve insertion order. A LinkedList
   gives O(n) removal by key. LinkedHashSet is the perfect
   combination of both: O(1) for everything needed.

Q: When is minFreq updated?
A: minFreq changes in two situations:
   1. New key insertion: minFreq = 1. A new key has frequency 1,
      which is the global minimum.
   2. incrementFreq: if the bucket at minFreq becomes empty after
      removing the key (because it moved to freq+1), we increment
      minFreq by 1. This is safe because no key has frequency
      less than minFreq (invariant), and the current minimum just
      moved up by 1. We never increment minFreq by more than 1
      in incrementFreq because the key moving from minFreq to
      minFreq+1 was the ONLY key at minFreq (otherwise the
      bucket wouldn't be empty).

Q: What is the space complexity of LFU?
A: O(capacity) -- each of the three maps stores at most `capacity`
   entries. freqToKeys has at most O(max_freq) keys, but the total
   size of all LinkedHashSets is also bounded by capacity. So
   total space is O(capacity).

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. This problem (LC 460) is hard -- interviewers know it is;
     clearly explain the three data structures before coding
  2. State the invariant: minFreq is always the minimum frequency
     among all currently cached keys
  3. The minFreq reset to 1 on put is a common bug to miss
  4. LinkedHashSet is the key insight -- explain why it's
     better than HashSet + DLL for this problem
  5. Dry-run the example before coding to confirm your design
  6. If asked about LFU vs LRU in design: LFU better handles
     "hot" items used repeatedly; LRU can evict a hot item
     if it wasn't accessed very recently
