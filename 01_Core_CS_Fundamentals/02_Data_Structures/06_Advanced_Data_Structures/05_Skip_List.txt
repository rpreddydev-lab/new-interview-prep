================================================================
  SKIP LIST
================================================================

----------------------------------------------------------------
WHAT IS A SKIP LIST?
----------------------------------------------------------------
A Skip List is a probabilistic data structure that allows fast
search, insertion, and deletion in a sorted linked list.

  A sorted linked list has O(n) search. A Skip List adds
  "express lanes" at multiple levels, allowing O(log n) average
  search by skipping over large portions.

  Visualization (4 levels for 7 elements):

  Level 3: head ----------------------> 6 -------> null
  Level 2: head -------> 3 ----------> 6 -------> null
  Level 1: head -> 1 -> 3 -> 4 ------> 6 -> 7 --> null
  Level 0: head -> 1 -> 2 -> 3 -> 4 -> 5 -> 6 -> 7 -> null

  Level 0 = base level (all elements)
  Level k = sparser "express lanes" with ~n/2^k elements

  Probabilistic promotion:
    Each element is promoted to the next level with probability p
    (typically p = 0.5).
    Expected number of levels: O(log n)

----------------------------------------------------------------
COMPLEXITY
----------------------------------------------------------------
  Operation       Average         Worst Case
  ---------------------------------------------------------------
  Search          O(log n)        O(n)  (extremely unlikely)
  Insert          O(log n)        O(n)
  Delete          O(log n)        O(n)
  Space           O(n log n)      O(n log n) expected

  Compare with balanced BST (AVL / Red-Black):
    Both have O(log n) average for all operations.
    BST: deterministic worst case O(log n)
    Skip List: probabilistic O(log n) average, O(n) worst
    Skip List: simpler to implement, easier to make concurrent
    BST: better worst-case guarantees

----------------------------------------------------------------
SEARCH ALGORITHM
----------------------------------------------------------------
  Start at head, highest level.
  At each level:
    If next node's key < target: advance right.
    If next node's key >= target: drop down one level.
  If bottom-level next node's key == target: FOUND.
  Otherwise: NOT FOUND.

  Example: search for 5 in the visualization above:
    Level 3: head -> 6 (> 5), drop to level 2
    Level 2: head -> 3 (< 5), advance right to 6 (> 5), drop to level 1
    Level 1: 3 -> 4 (< 5), advance right to 6 (> 5), drop to level 0
    Level 0: 4 -> 5: FOUND

----------------------------------------------------------------
JAVA IMPLEMENTATION (simplified)
----------------------------------------------------------------
  class SkipListNode {
    int val;
    SkipListNode[] next;  // next[i] = forward pointer at level i
    SkipListNode(int val, int level) {
      this.val = val;
      next = new SkipListNode[level + 1];
    }
  }

  class SkipList {
    static final int MAX_LEVEL = 16;
    static final double P = 0.5;
    SkipListNode head = new SkipListNode(Integer.MIN_VALUE, MAX_LEVEL);
    int level = 0;
    Random random = new Random();

    int randomLevel() {
      int lvl = 0;
      while (lvl < MAX_LEVEL && random.nextDouble() < P) lvl++;
      return lvl;
    }

    boolean search(int target) {
      SkipListNode curr = head;
      for (int i = level; i >= 0; i--) {
        while (curr.next[i] != null && curr.next[i].val < target)
          curr = curr.next[i];
      }
      curr = curr.next[0];
      return curr != null && curr.val == target;
    }

    void insert(int num) {
      SkipListNode[] update = new SkipListNode[MAX_LEVEL + 1];
      SkipListNode curr = head;
      for (int i = level; i >= 0; i--) {
        while (curr.next[i] != null && curr.next[i].val < num)
          curr = curr.next[i];
        update[i] = curr;
      }
      int newLevel = randomLevel();
      if (newLevel > level) {
        for (int i = level + 1; i <= newLevel; i++) update[i] = head;
        level = newLevel;
      }
      SkipListNode node = new SkipListNode(num, newLevel);
      for (int i = 0; i <= newLevel; i++) {
        node.next[i] = update[i].next[i];
        update[i].next[i] = node;
      }
    }
  }

  Time: O(log n) average for all operations.

----------------------------------------------------------------
SKIP LIST vs BALANCED BST
----------------------------------------------------------------
  Feature                  Skip List         AVL / R-B Tree
  ---------------------------------------------------------------
  Search                   O(log n) avg      O(log n) worst
  Insert                   O(log n) avg      O(log n) worst
  Delete                   O(log n) avg      O(log n) worst
  Worst-case guarantee     No (probabilistic) Yes
  Implementation           Simpler           Complex (rotations)
  Concurrent access        Easier to design  Harder (rebalancing)
  Lock-free concurrency    Possible          Difficult
  Space                    O(n log n) avg    O(n)
  Range queries            O(log n + k)      O(log n + k)

  Skip List advantages:
    - Simpler implementation than Red-Black Tree
    - Easier to support concurrent lock-free operations
    - Level-0 is a sorted linked list -> easy range queries

  Used in:
    Redis Sorted Set (ZSET)
    Lucene (Apache) index structure
    Java's ConcurrentSkipListMap, ConcurrentSkipListSet

  Java's ConcurrentSkipListMap:
    Thread-safe sorted map backed by skip list.
    All operations O(log n). Used when sorted + concurrent needed.

----------------------------------------------------------------
INTERVIEW QUESTIONS
----------------------------------------------------------------

Q: Why is a Skip List O(log n) on average despite being
   a linked list?
A: The key is the multi-level structure. Level 0 has all n
   elements. Level 1 has ~n/2 elements. Level k has ~n/2^k.
   When searching, you start at the highest level (fewest nodes)
   and skip large portions. On average you traverse O(log n)
   nodes per level and drop down O(log n) levels, giving
   O(log n) total comparisons -- similar to binary search.

Q: Where is Skip List used in real systems?
A: Redis uses Skip List for its ZSET (sorted set) data structure
   because it provides O(log n) insert/delete/search AND O(k)
   range queries by traversing level-0 from the found start.
   Java's concurrent collections include ConcurrentSkipListMap
   and ConcurrentSkipListSet, preferred over TreeMap in
   multi-threaded contexts because skip lists are more amenable
   to lock-free concurrent implementations.

Q: What is the LeetCode Skip List design problem?
A: LeetCode 1206 (Design Skiplist). You implement search(),
   add(), and erase() with expected O(log n) time.
   Implementation involves: sentinel head node with MAX_LEVEL
   forward pointers, randomLevel() for probabilistic promotion,
   and the `update[]` array technique to track where to splice
   in new nodes at each level.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. Skip lists are probabilistic -- say "expected O(log n)"
     not "O(log n) worst case"
  2. Redis uses skip lists for sorted sets -- mention this
     in system design (leaderboard, ranking systems)
  3. Java's ConcurrentSkipListMap is the concurrent alternative
     to TreeMap for sorted maps in multi-threaded code
  4. The design interview angle: skip list vs BST for a
     sorted set with range queries is a classic trade-off
  5. Implementation interviews rarely ask for skip list;
     more likely to ask about it conceptually or in a
     system design context
