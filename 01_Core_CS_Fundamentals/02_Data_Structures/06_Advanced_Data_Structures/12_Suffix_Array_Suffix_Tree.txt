SUFFIX ARRAY AND SUFFIX TREE
==============================

INTRODUCTION
-------------
  String indexing data structures that enable fast pattern matching,
  longest repeated substring, and many advanced string queries.

  Common in: top-tier interviews (Google, Amazon), competitive programming,
  bioinformatics, search engines.

─────────────────────────────────────────────────────────────
SUFFIX ARRAY
─────────────────────────────────────────────────────────────
  A SUFFIX ARRAY (SA) is an array of all suffixes of a string, sorted
  in lexicographic order. It stores the START INDICES of these sorted suffixes.

  Example: s = "banana"
  Suffixes:
    Index 0: "banana"
    Index 1: "anana"
    Index 2: "nana"
    Index 3: "ana"
    Index 4: "na"
    Index 5: "a"

  Sorted lexicographically:
    "a"      → index 5
    "ana"    → index 3
    "anana"  → index 1
    "banana" → index 0
    "na"     → index 4
    "nana"   → index 2

  SA = [5, 3, 1, 0, 4, 2]

NAIVE CONSTRUCTION: O(n² log n)
---------------------------------
  String s = "banana";
  Integer[] sa = IntStream.range(0, s.length()).boxed().toArray(Integer[]::new);
  Arrays.sort(sa, (a, b) -> s.substring(a).compareTo(s.substring(b)));

  Efficient construction (DC3/SA-IS): O(n) — complex to implement
  O(n log n) construction — practical for interviews:

  int[] buildSuffixArray(String s) {
      int n = s.length();
      Integer[] sa = new Integer[n];
      for (int i = 0; i < n; i++) sa[i] = i;
      Arrays.sort(sa, (a, b) -> s.substring(a).compareTo(s.substring(b)));
      int[] result = new int[n];
      for (int i = 0; i < n; i++) result[i] = sa[i];
      return result;
  }

LCP ARRAY (Longest Common Prefix)
-----------------------------------
  Often paired with Suffix Array.
  lcp[i] = length of the longest common prefix between SA[i] and SA[i-1].

  Example for "banana":
  SA  = [5, 3, 1, 0, 4, 2]
  LCP = [-, 1, 3, 0, 0, 2]
              "a"&"ana"=1
                 "ana"&"anana"=3
                       "anana"&"banana"=0

  With SA + LCP, you can answer:
  - Count of distinct substrings = n(n+1)/2 - sum(LCP)
  - Longest repeated substring = max(LCP)

KASAI'S ALGORITHM — LCP in O(n):
  int[] buildLCP(String s, int[] sa) {
      int n = s.length();
      int[] rank = new int[n], lcp = new int[n];
      for (int i = 0; i < n; i++) rank[sa[i]] = i;

      int h = 0;
      for (int i = 0; i < n; i++) {
          if (rank[i] > 0) {
              int j = sa[rank[i] - 1];
              while (i + h < n && j + h < n && s.charAt(i+h) == s.charAt(j+h))
                  h++;
              lcp[rank[i]] = h;
              if (h > 0) h--;
          }
      }
      return lcp;
  }

PATTERN SEARCH WITH SUFFIX ARRAY: O(m log n)
  To find if pattern P exists in text T:
  Binary search on SA — all occurrences of P are a contiguous range in SA.

  boolean search(String text, int[] sa, String pattern) {
      int lo = 0, hi = sa.length - 1;
      while (lo <= hi) {
          int mid = (lo + hi) / 2;
          String suffix = text.substring(sa[mid]);
          int cmp = suffix.startsWith(pattern) ? 0
                    : suffix.compareTo(pattern) < 0 ? -1 : 1;
          if (cmp == 0) return true;
          else if (cmp < 0) lo = mid + 1;
          else hi = mid - 1;
      }
      return false;
  }

SUFFIX TREE
─────────────────────────────────────────────────────────────
  A compressed trie of all suffixes of a string.
  Space: O(n). Build: O(n) with Ukkonen's algorithm (complex).

  Key property: any substring of s appears as a path from root.

  Advantages over Suffix Array:
  - O(m) pattern search (vs O(m log n) for SA)
  - Easier to find LCA for LCP queries
  - More intuitive for some problems

  Disadvantage: harder to implement; higher constant factor.

  In practice for interviews: Suffix Array + LCP is preferred.

CONCEPTUAL STRUCTURE for "banana$":
  ($ = sentinel character, ensures all suffixes are unique)

  root
  ├── a → "na"(→ "na$") leaf: 3, "na"(→ "$") leaf: 1, "$" leaf: 5
  ├── banana$ leaf: 0
  ├── na
  │   ├── na$ leaf: 2
  │   └── $ leaf: 4
  └── $ leaf: 6

─────────────────────────────────────────────────────────────
SUFFIX AUTOMATON (SAM)
─────────────────────────────────────────────────────────────
  A directed acyclic finite automaton that represents ALL substrings.
  - O(n) construction and space
  - Every path from root spells a distinct substring
  - Most powerful string structure but complex to implement

  Supports in O(n):
  - Count distinct substrings
  - Find shortest/longest repeated substring
  - String matching

  Not typically required in standard interviews — but can appear at
  senior roles in top product companies (Google, Bytedance).

─────────────────────────────────────────────────────────────
COMPLEXITY SUMMARY
─────────────────────────────────────────────────────────────
  Structure      | Build     | Space | Pattern Search | LCP Query
  ───────────────┼───────────┼───────┼────────────────┼──────────
  Suffix Array   | O(n log n)| O(n)  | O(m log n)     | O(1) with LCP
  Suffix Tree    | O(n)      | O(n)  | O(m)           | O(1) with LCA
  Suffix Automaton| O(n)     | O(n)  | O(m)           | O(m)

─────────────────────────────────────────────────────────────
PROBLEMS SOLVED WITH SUFFIX ARRAY
─────────────────────────────────────────────────────────────
  1. Longest Repeated Substring     = max(LCP)
  2. Longest Common Substring       = max(LCP between two strings merged with sentinel)
  3. Count of Distinct Substrings   = n(n+1)/2 - sum(LCP)
  4. Number of occurrences of P in T = binary search range on SA
  5. Smallest lexicographic rotation = SA[0] (for string + string)

COMMON INTERVIEW PROBLEMS:
  LC 1044 - Longest Duplicate Substring    → SA + LCP + binary search
  LC 718  - Maximum Length of Repeated Subarray → DP (SA overkill)
  LC 1062 - Longest Repeating Substring    → Binary search + rolling hash OR SA

─────────────────────────────────────────────────────────────
COMMON INTERVIEW QUESTIONS
─────────────────────────────────────────────────────────────
  Q: What is the difference between a Suffix Tree and a Suffix Array?
  A: Both index all suffixes of a string. Suffix Tree is a compressed trie —
     faster O(m) search but harder to build (Ukkonen's O(n)).
     Suffix Array is a sorted array of suffix indices — simpler to code,
     O(m log n) search, O(n log n) build. SA is preferred in interviews.

  Q: What is the LCP array used for?
  A: LCP[i] = length of longest common prefix between suffix SA[i] and SA[i-1].
     Used to count distinct substrings, find longest repeated substring,
     and enable O(1) LCP queries between any two suffixes using RMQ.

  Q: How would you find the longest repeated substring?
  A: Build the suffix array and LCP array. The answer is max(LCP).
     LC 1044 uses binary search on length + rolling hash as an alternative.

  Q: Why add a sentinel character when building suffix structures?
  A: To ensure no suffix is a prefix of another, guaranteeing all leaves
     in the suffix tree are distinct. Typically use '$' (ASCII < 'a').
