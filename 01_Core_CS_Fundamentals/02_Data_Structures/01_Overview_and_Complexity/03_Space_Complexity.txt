================================================================
  SPACE COMPLEXITY
================================================================

----------------------------------------------------------------
WHAT IS SPACE COMPLEXITY?
----------------------------------------------------------------
Space complexity measures the total amount of memory an
algorithm uses relative to its input size (n).

It includes:
  1. Input space    - memory to store the input itself
  2. Auxiliary space - extra memory used by the algorithm
                       (variables, call stack, data structures)

In most interviews, "space complexity" refers to AUXILIARY SPACE
unless stated otherwise.

----------------------------------------------------------------
WHY IT MATTERS
----------------------------------------------------------------
Time and space are often in tension. A faster algorithm may
use more memory. You must know how to communicate the trade-off.

  Example:
    Brute force string reversal with new array = O(n) space
    In-place two-pointer reversal             = O(1) space
    Both are O(n) time — but space differs significantly

----------------------------------------------------------------
SPACE COMPLEXITY CLASSES
----------------------------------------------------------------

  O(1)   Constant Space
    - Uses a fixed number of variables regardless of input size
    - No recursion, no extra data structures
    - Example: swapping two variables, iterating with a counter

  O(log n)  Logarithmic Space
    - Typically from recursion depth in divide-and-conquer
    - Example: binary search (recursive), balanced BST recursion
    - Each recursive call uses stack frame memory

  O(n)   Linear Space
    - Extra storage proportional to input size
    - Example: copying an array, BFS queue, DFS stack
    - Recursion on a linear structure (linked list) = O(n) stack

  O(n²)  Quadratic Space
    - Example: storing an adjacency matrix for n nodes
    - 2D DP table for n x n problems

----------------------------------------------------------------
CALL STACK AND RECURSION SPACE
----------------------------------------------------------------
Every recursive call adds a STACK FRAME to the call stack.
Stack frames hold: local variables, parameters, return address.

  Recursion depth = space used on call stack

  Example 1: factorial(n)
    Recurses n levels deep --> O(n) space

  Example 2: Binary search (recursive)
    Recurses log n levels deep --> O(log n) space
    Iterative version --> O(1) space

  Example 3: Merge Sort
    Recursion depth = O(log n) levels
    Temporary arrays at each level = O(n) total
    Total space = O(n)

  Example 4: DFS on a tree of height h
    Call stack depth = h
    Balanced tree: h = log n --> O(log n) space
    Skewed tree:   h = n     --> O(n) space

----------------------------------------------------------------
IN-PLACE vs OUT-OF-PLACE ALGORITHMS
----------------------------------------------------------------
  In-Place
    - Modifies input directly with O(1) extra space
    - Examples: bubble sort, quicksort (in-place partition),
                two-pointer array reversal

  Out-of-Place
    - Creates new data structures to store results
    - Examples: merge sort (needs temp arrays),
                creating a new array from filtered results

  Trade-off:
    In-place saves memory but may make the algorithm harder to
    reason about and can destroy the original input.

----------------------------------------------------------------
COMMON SPACE COMPLEXITIES BY ALGORITHM TYPE
----------------------------------------------------------------

  Algorithm / Structure              Space Complexity
  ---------------------------------------------------------------
  Iterative loop (no extra DS)       O(1)
  Recursive binary search            O(log n)
  Recursive linear traversal         O(n)
  Merge Sort                         O(n)
  Quick Sort (in-place)              O(log n) avg (stack)
  BFS (queue)                        O(n) - queue holds level
  DFS (stack or recursion)           O(h) - h = tree height
  HashMap / HashSet                  O(n)
  Adjacency list (graph)             O(V + E)
  Adjacency matrix (graph)           O(V²)
  DP table (1D)                      O(n)
  DP table (2D, n x m)               O(n * m)
  DP with space optimization         O(1) or O(min(n,m))

----------------------------------------------------------------
SPACE OPTIMIZATION TECHNIQUES
----------------------------------------------------------------

  1. Rolling Array / Two-Row DP
     When a 2D DP only looks at the previous row,
     reduce from O(n*m) to O(m) by keeping only 2 rows.

  2. Iterative vs Recursive
     Convert tail recursion to iteration to eliminate stack.
     Binary search: recursive O(log n) --> iterative O(1)

  3. Two-Pointer / Sliding Window
     Process input without storing intermediate results.
     Replaces O(n) extra storage with O(1) pointers.

  4. In-Place Transformations
     Modify the input array directly (if mutation is allowed)
     instead of creating a new array.

  5. Bit Manipulation
     Use a bitmask instead of a HashSet to track visited states.
     32 states --> 32-bit integer instead of Set<Integer>

----------------------------------------------------------------
REAL INTERVIEW EXAMPLES
----------------------------------------------------------------

  Problem: Find duplicates in an array of size n
  --------------------------------------------------
  Approach A: HashSet
    Time: O(n)    Space: O(n)  -- stores all seen elements

  Approach B: Sort then scan
    Time: O(n log n)  Space: O(1) -- no extra storage needed

  Approach C: Floyd's cycle detection (specific case)
    Time: O(n)    Space: O(1)  -- best of both worlds

  Problem: Reverse a string
  --------------------------------------------------
  Approach A: new char array
    Time: O(n)    Space: O(n)

  Approach B: two-pointer in-place swap
    Time: O(n)    Space: O(1)

  Problem: Fibonacci(n)
  --------------------------------------------------
  Naive recursion:     Time O(2^n)   Space O(n) stack
  Memoization:         Time O(n)     Space O(n) cache + O(n) stack
  Bottom-up DP:        Time O(n)     Space O(n) table
  Space-optimized DP:  Time O(n)     Space O(1) -- just prev two

----------------------------------------------------------------
INTERVIEW QUESTIONS
----------------------------------------------------------------

Q: What is the difference between time complexity and
   space complexity?
A: Time complexity measures how runtime grows with input size.
   Space complexity measures how memory usage grows. They often
   trade off — you can sometimes use more memory to go faster
   (memoization) or use less memory at the cost of speed.

Q: Does space complexity include the input?
A: Depends on context. Auxiliary space complexity excludes the
   input. Total space includes it. In interviews, "space
   complexity" usually means auxiliary space — always clarify.

Q: What is the space complexity of a recursive DFS?
A: O(h) where h is the height of the tree. For a balanced
   tree, h = log n so space is O(log n). For a skewed tree
   (worst case), h = n so space is O(n).

Q: How would you reduce space in a 2D DP problem?
A: If each cell only depends on the previous row, keep only
   two rows (current and previous), reducing space from
   O(n*m) to O(m). This is called the rolling array technique.

Q: What is tail recursion and how does it help space complexity?
A: Tail recursion is when the recursive call is the last
   operation in the function. Some compilers/runtimes optimize
   it to reuse the same stack frame (tail call optimization),
   reducing recursion space from O(n) to O(1).
   Note: Java does NOT perform TCO, so always verify the
   runtime environment before relying on this.

Q: Quicksort is in-place — does it use O(1) space?
A: No. In-place partitioning uses O(1) extra array space,
   but quicksort is recursive. The call stack uses O(log n)
   space on average and O(n) in the worst case (sorted input
   with bad pivot selection).

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. Always state BOTH time and space complexity — forgetting
     space is a red flag to interviewers
  2. When asked to optimize, ask: "Optimize for time or space?"
     Then discuss the trade-off explicitly
  3. Know that recursion always has implicit O(depth) space cost
  4. For DP problems, always mention if there's a space
     optimization available (rolling array, etc.)
  5. In-place algorithms impress interviewers but make sure
     you know if input mutation is allowed before applying them
