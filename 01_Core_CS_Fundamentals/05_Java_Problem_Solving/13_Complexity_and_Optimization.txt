PART 3: DP SPACE OPTIMIZATION (Rolling Array)
===================================================================

KEY INSIGHT: If dp[i] only depends on dp[i-1] (not dp[i-2] or earlier),
you only need to keep the PREVIOUS row, not the whole table.

--- 1D DP: O(n) → O(1) ---
// Fibonacci style
// Before: int[] dp = new int[n];  dp[0]=1; dp[1]=1;
//         for(i=2..n) dp[i] = dp[i-1] + dp[i-2];

int prev2 = 1, prev1 = 1;
for (int i = 2; i <= n; i++) {
    int cur = prev1 + prev2;
    prev2 = prev1;
    prev1 = cur;
}
return prev1;

// Climbing stairs, house robber, decode ways — same pattern

--- 2D DP: O(m×n) → O(n) ---
// When dp[i][j] depends only on dp[i-1][j] and dp[i][j-1]:

// Before: int[][] dp = new int[m+1][n+1];
// After: use a single 1D array, updated row by row

int[] dp = new int[n + 1];
for (int i = 1; i <= m; i++) {
    for (int j = 1; j <= n; j++) {
        // dp[j] currently holds dp[i-1][j]
        // dp[j-1] currently holds dp[i][j-1] (just updated)
        dp[j] = dp[j-1] + dp[j];   // unique paths example
    }
}
return dp[n];

// For LCS / edit distance (depends on dp[i-1][j-1] too):
int[] dp = new int[n + 1];
for (int i = 1; i <= m; i++) {
    int prev = 0;   // represents dp[i-1][j-1]
    for (int j = 1; j <= n; j++) {
        int tmp = dp[j];  // save dp[i-1][j] before overwriting
        if (s.charAt(i-1) == t.charAt(j-1)) dp[j] = prev + 1;
        else dp[j] = Math.max(dp[j], dp[j-1]);
        prev = tmp;       // update prev for next column
    }
}

--- Knapsack 0/1: O(n×capacity) → O(capacity) ---
// Iterate capacity BACKWARDS to prevent reuse of same item
int[] dp = new int[capacity + 1];
for (int[] item : items) {
    for (int c = capacity; c >= item[0]; c--) {   // RIGHT to LEFT
        dp[c] = Math.max(dp[c], dp[c - item[0]] + item[1]);
    }
}

// Unbounded knapsack (item can be reused): iterate LEFT to RIGHT
for (int[] item : items) {
    for (int c = item[0]; c <= capacity; c++) {   // LEFT to RIGHT
        dp[c] = Math.max(dp[c], dp[c - item[0]] + item[1]);
    }
}

PART 4: IN-PLACE TRICKS (Reduce O(n) space to O(1))
===================================================================

--- Mark visited using the array itself ---
// For arrays with values in range [1, n], use sign as visited marker
// (negating the value at index marks it as seen)
for (int i = 0; i < n; i++) {
    int idx = Math.abs(nums[i]) - 1;   // convert value to 0-index
    if (nums[idx] > 0) nums[idx] = -nums[idx];   // mark visited
}
// Check: nums[i] < 0 means (i+1) was present

--- Cyclic sort (for values 1..n in array of size n) ---
int i = 0;
while (i < n) {
    int correct = nums[i] - 1;   // where nums[i] should be
    if (nums[i] > 0 && nums[i] <= n && nums[i] != nums[correct]) {
        int tmp = nums[i]; nums[i] = nums[correct]; nums[correct] = tmp;
    } else i++;
}

PART 5: TRADING TIME FOR SPACE (and vice versa)
===================================================================

Situation                          | Time-Space Tradeoff
-----------------------------------|------------------------------------------
Repeated substring lookup          | Build HashMap of positions → O(n) space, O(1) query
Repeated sqrt(n) computations      | Precompute → O(sqrt(n)) space
Repeated range sums                | Prefix sum array → O(n) space, O(1) query
Repeated min/max in ranges         | Sparse table → O(n log n) space, O(1) query
Find duplicates in O(n), O(1) sp.  | Use sign-flip trick or cyclic sort
LRU cache                          | HashMap + LinkedList → O(capacity) space, O(1) ops
Top-K frequent                     | Bucket sort → O(n) space, O(n) time vs O(n log k) heap

PART 6: COMMON COMPLEXITY MISTAKES
===================================================================

MISTAKE 1: Thinking substring is O(1)
  String.substring() creates a NEW string → O(k) where k = substring length
  Comparing s.substring(i, j).equals(target) in a loop = O(n * target.length)
  FIX: use two pointers or rolling hash

MISTAKE 2: Thinking contains() on ArrayList is O(1)
  list.contains(x) = O(n) — it does a linear scan!
  FIX: convert to HashSet for O(1) lookup: Set<Integer> set = new HashSet<>(list)

MISTAKE 3: Building a string inside a loop with +
  result += s  in a loop of n iterations = O(n²) total
  FIX: StringBuilder

MISTAKE 4: Sorting when you don't need to
  Sorting = O(n log n); if you only need max/min, use O(n) scan
  If you only need top-K, use O(n log k) heap, not sort

MISTAKE 5: HashMap used with mutable keys
  If you mutate an object after inserting as a key, hashCode changes
  → HashMap can no longer find the key
  FIX: use immutable keys (String, Integer, etc.)

MISTAKE 6: Recursive DFS on large input without memoization
  Fibonacci with plain recursion = O(2^n)
  FIX: memoize with HashMap or int[] array

MISTAKE 7: Creating new ArrayList<>(list) thinking it's O(1)
  It copies all elements → O(n)
  If you just need a view: use Collections.unmodifiableList(list) or subList

Use this to quickly pick the right algorithm approach:

--------------------|---------------------|---------------------------
n ≤ 12              | O(n! or 2^n)        | Backtracking, bitmask DP

n ≤ 1,000,000       | O(n) or O(n log n)  | Linear scan, hash map, BFS
