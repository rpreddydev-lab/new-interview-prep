================================================================
  COMBINATION SUM (LC 39, 40, 77)
================================================================

  LC 39: Given candidates (distinct, unlimited reuse) and target.
         Find all unique combinations that sum to target.
  LC 40: Given candidates (may have duplicates, each used ONCE).
         Find all unique combinations that sum to target.
  LC 77: Given n and k. Return all combinations of k numbers from 1..n.

  Input (LC 39):  candidates = [2,3,6,7], target = 7
  Output: [[2,2,3],[7]]

  Input (LC 40):  candidates = [10,1,2,7,6,1,5], target = 8
  Output: [[1,1,6],[1,2,5],[1,7],[2,6]]

  Input (LC 77):  n=4, k=2
  Output: [[1,2],[1,3],[1,4],[2,3],[2,4],[3,4]]

----------------------------------------------------------------
LC 39: COMBINATION SUM (REUSE ALLOWED)
----------------------------------------------------------------

  Sorted candidates + start index. On recurse, pass i (not i+1) to allow reuse.
  Prune when remaining < 0.

  Java:
    public List<List<Integer>> combinationSum(int[] candidates, int target) {
        Arrays.sort(candidates);  // sorting enables early pruning
        List<List<Integer>> result = new ArrayList<>();
        backtrack(candidates, 0, target, new ArrayList<>(), result);
        return result;
    }

    private void backtrack(int[] candidates, int start, int remaining,
                            List<Integer> current, List<List<Integer>> result) {
        if (remaining == 0) {
            result.add(new ArrayList<>(current));  // found valid combination
            return;
        }
        for (int i = start; i < candidates.length; i++) {
            if (candidates[i] > remaining) break;  // pruning: sorted, so rest also too big
            current.add(candidates[i]);
            backtrack(candidates, i, remaining - candidates[i], current, result);  // i not i+1
            current.remove(current.size() - 1);
        }
    }

  Time: O(N^(T/M) * k) where N=candidates, T=target, M=min candidate, k=avg combo len
  Space: O(T/M) recursion depth

  KEY: pass `i` (not `i+1`) to allow reusing the same element.

----------------------------------------------------------------
TRACED EXAMPLE: candidates=[2,3,6,7], target=7
----------------------------------------------------------------

  backtrack(0, 7, []):
    i=0: cand=2. backtrack(0, 5, [2]):
           i=0: cand=2. backtrack(0, 3, [2,2]):
                  i=0: cand=2. backtrack(0, 1, [2,2,2]):
                         i=0: 2>1 → BREAK
                  i=1: cand=3. backtrack(1, 0, [2,2,3]):
                         remaining==0 → ADD [2,2,3] ✓
                  i=2: 6>3 → BREAK
           i=1: cand=3. backtrack(1, 2, [2,3]):
                  i=1: 3>2 → BREAK
           i=2: 6>5 → BREAK
    i=1: cand=3. backtrack(1, 4, [3]):
           i=1: 3. backtrack(1, 1, [3,3]): 3>1→BREAK
           i=2: 6>4→BREAK
    i=2: 6>7? No. backtrack(2, 1, [6]): 6>1→BREAK
    i=3: 7==7. backtrack(3, 0, [7]): ADD [7] ✓

  Result: [[2,2,3],[7]] ✓

LC 40: COMBINATION SUM II (NO REUSE, MAY HAVE DUPS)
----------------------------------------------------------------

  Sort first. Use i+1 (no reuse). Skip duplicates at same level.

  Java:
    public List<List<Integer>> combinationSum2(int[] candidates, int target) {
        Arrays.sort(candidates);
        List<List<Integer>> result = new ArrayList<>();
        backtrack(candidates, 0, target, new ArrayList<>(), result);
        return result;
    }

    private void backtrack(int[] candidates, int start, int remaining,
                            List<Integer> current, List<List<Integer>> result) {
        if (remaining == 0) {
            result.add(new ArrayList<>(current));
            return;
        }
        for (int i = start; i < candidates.length; i++) {
            if (candidates[i] > remaining) break;
            if (i > start && candidates[i] == candidates[i-1]) continue;  // skip dup
            current.add(candidates[i]);
            backtrack(candidates, i + 1, remaining - candidates[i], current, result);  // i+1
            current.remove(current.size() - 1);
        }
    }

  Example: candidates=[1,1,2,5,6,7,10] (sorted), target=8
    Starts: i=0 (1), then i=1 SKIP (1==1, i>start=0)...
    Finds: [1,1,6], [1,2,5], [1,7], [2,6] ✓

  Differences from LC 39:
    1. Use i+1 (each element at most once)
    2. Skip duplicates: `if (i > start && candidates[i] == candidates[i-1]) continue`

LC 77: COMBINATIONS (k NUMBERS FROM 1..n)
----------------------------------------------------------------

  Choose k numbers from 1 to n. Ascending order → use start index.
  Add to result when current.size() == k.

  Java:
    public List<List<Integer>> combine(int n, int k) {
        List<List<Integer>> result = new ArrayList<>();
        backtrack(1, n, k, new ArrayList<>(), result);
        return result;
    }

    private void backtrack(int start, int n, int k, List<Integer> current, List<List<Integer>> result) {
        if (current.size() == k) {
            result.add(new ArrayList<>(current));
            return;
        }
        // Pruning: need at least (k - current.size()) more elements.
        // Last valid start = n - (k - current.size()) + 1
        for (int i = start; i <= n - (k - current.size()) + 1; i++) {
            current.add(i);
            backtrack(i + 1, n, k, current, result);
            current.remove(current.size() - 1);
        }
    }

  Without pruning: `i <= n`
  With pruning: `i <= n - (k - current.size()) + 1`

  Example (n=4, k=2): upper bound at outer loop = 4 - (2-0) + 1 = 3 → [1..3]
    i=1: [1], inner i from 2 to 4-(2-1)+1=4 → [2],[3],[4] → [1,2],[1,3],[1,4]
    i=2: [2], inner i from 3 to 4 → [3],[4] → [2,3],[2,4]
    i=3: [3], inner i from 4 to 4 → [4] → [3,4]

  Result: [[1,2],[1,3],[1,4],[2,3],[2,4],[3,4]] ✓

  Time: O(C(n,k)*k)   Space: O(k)

COMPARISON TABLE
----------------------------------------------------------------

  Problem     Reuse?  Dups in input?  Loop start   Skip condition        Add when
  -------     ------  ------------    ----------   ---------------       --------
  LC 39       YES     No              i            None                  remaining==0
  LC 40       NO      YES             i+1          i>start && arr[i]==arr[i-1]   remaining==0

----------------------------------------------------------------
COMMON MISTAKES
----------------------------------------------------------------

  1. LC 39: using `i+1` instead of `i` — prevents reuse, wrong result.
  2. LC 40: using `i > 0` instead of `i > start` for skip condition.
     i > 0 skips valid first occurrence in deeper branches.
  3. Not copying current: `result.add(current)` vs `result.add(new ArrayList<>(current))`.
  4. Forgetting to sort before applying duplicate-skip logic.
  5. LC 77: off-by-one in pruning bound (should be `+1` at the end).

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: What's the only difference between LC 39 and LC 40?
  A: (1) pass i vs i+1 to allow/disallow reuse, and (2) skip duplicate
     condition in LC 40 to handle duplicate candidates.

  Q: Why sort candidates in LC 39?
  A: Enables the `if (candidates[i] > remaining) break;` pruning.
     Without sorting, we must check all elements instead of breaking early.

  Q: Time complexity of LC 39?
  A: O(N^(T/M)) where N=number of candidates, T=target, M=smallest candidate.
     In the worst case it's like a tree of depth T/M with branching factor N.

  Q: When would you use DP instead of backtracking for combination sum?
  A: When only the COUNT (not the actual combinations) is needed.
     LC 377 (Combination Sum IV) counts ordered sequences → DP.
     LC 518 (Coin Change II) counts unordered combos → DP.
