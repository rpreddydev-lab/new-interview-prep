================================================================
  PREFIX SUM -- INTRODUCTION
================================================================

Prefix Sum is a preprocessing technique that allows range sum
queries in O(1) after O(n) preprocessing. The idea is to store
the cumulative sum up to each index so any subarray sum can be
computed as the difference of two prefix sums.

----------------------------------------------------------------
CORE FORMULA
----------------------------------------------------------------

  prefix[i] = sum of elements from index 0 to i-1.
  (1-indexed, prefix[0] = 0 as a base case)

  prefix[0] = 0
  prefix[i] = prefix[i-1] + nums[i-1]   for i from 1 to n

  Sum of subarray [l, r] (0-indexed, inclusive):
    rangeSum(l, r) = prefix[r+1] - prefix[l]

  Why prefix has size n+1?
    prefix[0] = 0 handles the "sum from index 0" case cleanly.
    rangeSum(0, r) = prefix[r+1] - prefix[0] = prefix[r+1] - 0 = prefix[r+1].

----------------------------------------------------------------
VISUALIZATION
----------------------------------------------------------------

  nums    =  [3,  1,  2,  5,  4]
  indices =   0   1   2   3   4

  prefix  = [0,  3,  4,  6, 11, 15]
  indices    0   1   2   3   4   5

  prefix[i] = sum of nums[0..i-1]
  prefix[1] = nums[0] = 3
  prefix[3] = nums[0]+nums[1]+nums[2] = 6
  prefix[5] = all = 15

  rangeSum(1, 3) = prefix[4] - prefix[1] = 11 - 3 = 8
  (= nums[1]+nums[2]+nums[3] = 1+2+5 = 8) ✓

  rangeSum(0, 4) = prefix[5] - prefix[0] = 15 - 0 = 15 ✓

----------------------------------------------------------------
JAVA IMPLEMENTATION
----------------------------------------------------------------

  // Build prefix sum array
  public int[] buildPrefix(int[] nums) {
      int n = nums.length;
      int[] prefix = new int[n + 1];
      for (int i = 1; i <= n; i++) {
          prefix[i] = prefix[i - 1] + nums[i - 1];
      }
      return prefix;
  }

  // Query range sum [l, r] (0-indexed, inclusive)
  public int rangeSum(int[] prefix, int l, int r) {
      return prefix[r + 1] - prefix[l];
  }

----------------------------------------------------------------
WHEN TO USE PREFIX SUM
----------------------------------------------------------------

  1. RANGE SUM QUERIES (static array):
     Multiple queries on the same array. Preprocessing pays off.

  2. SUBARRAY SUM = K:
     Find how many subarrays have sum exactly k.
     Use prefix sum + HashMap.

  3. SUBARRAY WITH MAX/MIN SUM:
     Sometimes prefix sum simplifies the problem.

  4. 2D RANGE SUM QUERIES (matrix):
     2D prefix sum for O(1) rectangular queries.

  5. COUNT SUBARRAYS WITH PROPERTY:
     Use prefix XOR, prefix parity, etc.

  NOT useful when:
    - Array is dynamic (updates happen -- use Fenwick tree instead)
    - You only need one range sum (just compute directly O(n))

----------------------------------------------------------------
PREFIX SUM + HASHMAP PATTERN
----------------------------------------------------------------

  This is the most powerful prefix sum variant.
  Used for: "count subarrays with sum = k" (LC 560).

  Core idea:
    sum(l, r) = k
    prefix[r+1] - prefix[l] = k
    prefix[l] = prefix[r+1] - k

  So: for each index r, if (prefix[r+1] - k) was seen before,
  we found subarrays ending at r with sum k.

  Java (LC 560):
    public int subarraySum(int[] nums, int k) {
        Map<Integer, Integer> prefixCount = new HashMap<>();
        prefixCount.put(0, 1);  // empty prefix (sum=0 seen once)
        int sum = 0, count = 0;
        for (int num : nums) {
            sum += num;
            count += prefixCount.getOrDefault(sum - k, 0);
            prefixCount.merge(sum, 1, Integer::sum);
        }
        return count;
    }

  Why prefixCount.put(0, 1)?
    If the subarray starting from index 0 sums to k, we need
    prefix[0] = 0 to already be in the map.
    sum - k = 0 would find this entry.

  Time: O(n)  Space: O(n)

----------------------------------------------------------------
PREFIX XOR VARIANT
----------------------------------------------------------------

  For problems about XOR of subarrays:
    prefixXor[i] = XOR of nums[0..i-1]
    XOR of subarray [l, r] = prefixXor[r+1] ^ prefixXor[l]

  (XOR is its own inverse: A ^ A = 0, so prefix[r+1] ^ prefix[l]
  cancels out everything before l.)

  Used in: count subarrays with XOR = k, count pairs with XOR property.

----------------------------------------------------------------
COMPLEXITY
----------------------------------------------------------------

  Operation        Without Prefix  With Prefix
  ---------        --------------  -----------
  Build            --              O(n)
  Single query     O(n)            O(1)
  k queries        O(kn)           O(n + k)

  Prefix sum shines when there are multiple queries on the same data.

----------------------------------------------------------------
COMMON MISTAKES
----------------------------------------------------------------

  1. Off-by-one in formula:
     rangeSum(l, r) = prefix[r+1] - prefix[l]
     NOT prefix[r] - prefix[l-1] (though equivalent with 1-indexed original array)

  2. Forgetting to put (0, 1) in HashMap:
     The empty prefix (sum=0) must be counted once to handle
     subarrays starting from index 0.

  3. Computing prefix on 1-indexed array:
     Be consistent. If nums is 0-indexed and prefix is 0-indexed,
     use prefix[i] = sum of nums[0..i] (NOT nums[0..i-1]).
     Formula becomes: rangeSum(l,r) = prefix[r] - (l>0 ? prefix[l-1] : 0).
     The n+1 prefix with prefix[0]=0 avoids this ambiguity.

  4. Integer overflow:
     If nums contains large values, use long[] for prefix array.

  5. For 2D: iterating k before i and j in the prefix build:
     Build row-by-row, then column-by-column, or use the
     inclusion-exclusion formula correctly.

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: Why is prefix[0] = 0 and size n+1?
  A: To handle subarrays starting from index 0 without special cases.
     rangeSum(0, r) = prefix[r+1] - prefix[0] = prefix[r+1] - 0.
     If size were n (without the leading 0), we'd need to handle
     the l=0 case separately.

  Q: What's the key insight for "subarray sum = k"?
  A: We need prefix[r] - prefix[l] = k, i.e., prefix[l] = prefix[r] - k.
     As we scan left to right computing running prefix sums, we look
     up how many times (current_prefix - k) appeared before.

  Q: Can prefix sum handle arrays with negative numbers?
  A: Yes! The formula works for negative values too. Prefix sum is
     exact sum arithmetic, so signs don't matter.

  Q: What about "subarray sum divisible by k"?
  A: Use prefix[i] % k. Two positions with the same remainder have
     a subarray sum divisible by k. Use a frequency map of remainders.
     Handle negative remainders: ((sum % k) + k) % k.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------

  - Always draw the prefix array alongside the original to show
    how range queries work.
  - For the HashMap variant: explain put(0,1) BEFORE the loop.
  - Show the formula derivation: "I need sum[l..r]=k, which means
    prefix[r]-prefix[l]=k, so I look for prefix[r]-k in my map."
  - Mention that this is O(n) time and O(n) space with the HashMap.
