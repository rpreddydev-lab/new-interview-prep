================================================================
  MERGE INTERVALS PATTERN — INTRODUCTION
================================================================

----------------------------------------------------------------
WHAT IS THE INTERVALS PATTERN?
----------------------------------------------------------------

  An interval is a pair [start, end] representing a range.
  Interval problems involve: merging overlapping ranges, finding
  gaps, scheduling, detecting conflicts, or modifying interval lists.

  Core insight: SORT BY START TIME first.
  After sorting, overlapping intervals are adjacent in the list.
  This reduces a 2D problem to a linear scan.

----------------------------------------------------------------
OVERLAP CONDITION
----------------------------------------------------------------

  Two intervals [a,b] and [c,d] OVERLAP if and only if:
    a <= d  AND  c <= b
  (They overlap if neither ends before the other begins)

  Equivalently, they do NOT overlap if:
    b < c  (first ends before second starts)  OR
    d < a  (second ends before first starts)

  For sorted intervals (by start): after sorting, c >= a always.
  So overlap iff: c <= b  (second starts before first ends).

  Visualization:
    Case 1: [a----b]  [c-----d]   no overlap (b < c)
    Case 2: [a----[c--b]---d]     overlap (c <= b)
    Case 3: [a--[c------d]--b]    contained (c >= a, d <= b)
    Case 4: [c--[a------b]--d]    contained (reverse)

----------------------------------------------------------------
CORE ALGORITHM: MERGE OVERLAPPING INTERVALS
----------------------------------------------------------------

  1. Sort intervals by start time.
  2. Initialize result list with first interval.
  3. For each subsequent interval [c, d]:
       If c <= last.end (overlap):  merge by updating last.end = max(last.end, d)
       Else:                        add new interval to result.

  Java:
    public int[][] merge(int[][] intervals) {
        Arrays.sort(intervals, (a, b) -> a[0] - b[0]);
        List<int[]> result = new ArrayList<>();
        result.add(intervals[0]);

        for (int i = 1; i < intervals.length; i++) {
            int[] last = result.get(result.size() - 1);
            int[] curr = intervals[i];

            if (curr[0] <= last[1]) {
                last[1] = Math.max(last[1], curr[1]);  // merge
            } else {
                result.add(curr);  // no overlap, add new interval
            }
        }
        return result.toArray(new int[0][]);
    }

  Time: O(n log n) — dominated by sort
  Space: O(n) for result

----------------------------------------------------------------
VISUALIZATION: SORT AND MERGE
----------------------------------------------------------------

  Before sort: [[1,3],[2,6],[8,10],[15,18]]
    Already sorted by start.

  Process:
    result = [[1,3]]
    [2,6]: 2 <= 3 --> merge --> result = [[1,6]]
    [8,10]: 8 > 6 --> add   --> result = [[1,6],[8,10]]
    [15,18]: 15 > 10 --> add --> result = [[1,6],[8,10],[15,18]]

  Answer: [[1,6],[8,10],[15,18]] ✓

WHEN TO USE INTERVALS PATTERN
----------------------------------------------------------------

  Triggers:
    - Input is a list of [start, end] pairs
    - Keywords: "meeting rooms", "schedule", "overlap", "merge", "insert"
    - Finding free time, conflicts, total covered time
    - "Non-overlapping intervals" (count to remove to make non-overlapping)

  Problems:
    LC 56  - Merge Intervals
    LC 57  - Insert Interval
    LC 252 - Meeting Rooms (can attend all meetings?)
    LC 253 - Meeting Rooms II (minimum rooms needed)
    LC 435 - Non-Overlapping Intervals
    LC 986 - Interval List Intersections
    LC 1235 - Maximum Profit in Job Scheduling

----------------------------------------------------------------
COMMON OPERATIONS SUMMARY
----------------------------------------------------------------

  Operation                   Approach
  ---------                   --------
  Merge overlapping           Sort by start, linear scan
  Insert into sorted list     Find position, merge neighbors
  Find intersections          Two-pointer on both sorted lists
  Count overlaps at any point Sort events (start/end), sweep line
  Remove min to non-overlap   Sort by END, greedy (keep earliest end)

----------------------------------------------------------------
SWEEP LINE / EVENT APPROACH
----------------------------------------------------------------

  For problems like "minimum meeting rooms" or "maximum concurrent events":

  1. Create events: +1 for each start, -1 for each end.
  2. Sort events by time (ties: ends before starts).
  3. Sweep through, track running count, record maximum.

  This is the "sweep line" technique.

  For meeting rooms (LC 253):
    - Each start: one more room needed (+1)
    - Each end: one room freed (-1)
    - Max running sum = minimum rooms needed

  Java (using arrays):
    public int minMeetingRooms(int[][] intervals) {
        int n = intervals.length;
        int[] starts = new int[n], ends = new int[n];
        for (int i = 0; i < n; i++) {
            starts[i] = intervals[i][0];
            ends[i] = intervals[i][1];
        }
        Arrays.sort(starts);
        Arrays.sort(ends);

        int rooms = 0, maxRooms = 0, ei = 0;
        for (int i = 0; i < n; i++) {
            if (starts[i] < ends[ei]) {
                rooms++;
            } else {
                ei++;
            }
            maxRooms = Math.max(maxRooms, rooms);
        }
        return maxRooms;
    }

  Time: O(n log n)  Space: O(n)

----------------------------------------------------------------
INTERVAL SORTING COMPARATORS
----------------------------------------------------------------

  Sort by start:  Arrays.sort(intervals, (a, b) -> a[0] - b[0])
  Sort by end:    Arrays.sort(intervals, (a, b) -> a[1] - b[1])
  Sort by start, then end:
    Arrays.sort(intervals, (a, b) -> a[0] != b[0] ? a[0]-b[0] : a[1]-b[1])

  When to sort by END:
    - Greedy "keep intervals with earliest end" (activity selection / LC 435)

  When to sort by START:
    - Merging overlapping intervals (LC 56, 57)
    - Finding intersections (both lists sorted by start)

----------------------------------------------------------------
COMMON MISTAKES
----------------------------------------------------------------

  1. Forgetting to sort! Without sorting, adjacent intervals in the
     input may not actually be adjacent in time.

  2. Integer overflow in comparator: use Integer.compare(a[0], b[0])
     instead of a[0] - b[0] if values can be negative or very large.

  3. In merge: use Math.max(last.end, curr.end) when merging.
     Don't just set last.end = curr.end (curr might be contained in last).

  4. In sweep line: sort ends-before-starts at ties to avoid
     overcounting when a meeting ends and starts at the same time.

----------------------------------------------------------------
INTERVAL PROBLEM DECISION TREE
----------------------------------------------------------------

  Do intervals need to be merged?
    YES --> Sort by start, linear merge scan (LC 56)

  Need to insert one interval and re-merge?
    YES --> Find insertion point, merge left and right neighbors (LC 57)

  Can a person attend all meetings?
    YES --> Sort by start, check if prev.end > curr.start (LC 252)

  How many rooms / workers needed simultaneously?
    YES --> Sort starts and ends separately, two-pointer or sweep (LC 253)

  Need to find intersections of two interval lists?
    YES --> Two pointers, advance the one with smaller end (LC 986)

  Minimize number of removals to make non-overlapping?
    YES --> Sort by end, greedy: keep intervals with earliest end (LC 435)

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------

  - Always mention: "First, sort by start time. After sorting,
    overlapping intervals are adjacent."
  - Know the overlap condition cold: c <= last.end means overlap.
  - Know both variants: merge by end (max), and check only (for meeting rooms).
  - Sweep line is a powerful technique for "concurrent events" problems.
