================================================================
  MERGE OVERLAPPING INTERVALS
  (LC 56)
================================================================

----------------------------------------------------------------
PROBLEM STATEMENT
----------------------------------------------------------------

  Given an array of intervals [start, end], merge all overlapping
  intervals and return an array of non-overlapping intervals.

  Example 1:
    Input:  [[1,3],[2,6],[8,10],[15,18]]
    Output: [[1,6],[8,10],[15,18]]

  Example 2:
    Input:  [[1,4],[4,5]]
    Output: [[1,5]]
    Note: intervals touching at a point ARE considered overlapping.

----------------------------------------------------------------
ALGORITHM
----------------------------------------------------------------

  1. Sort by start time.
  2. Add first interval to result.
  3. For each remaining interval [c, d]:
       If c <= result.last.end:  update result.last.end = max(last.end, d)
       Else:                     append [c, d] to result.
  4. Return result.

  Why max(last.end, d)? Current interval might be fully contained in last.
    Example: last=[1,10], curr=[3,5] --> last.end stays 10 (don't shrink to 5).

----------------------------------------------------------------
JAVA SOLUTION
----------------------------------------------------------------

  public int[][] merge(int[][] intervals) {
      // Step 1: Sort by start time
      Arrays.sort(intervals, (a, b) -> Integer.compare(a[0], b[0]));

      List<int[]> merged = new ArrayList<>();
      merged.add(intervals[0]);

      for (int i = 1; i < intervals.length; i++) {
          int[] last = merged.get(merged.size() - 1);
          int[] curr = intervals[i];

          if (curr[0] <= last[1]) {
              // Overlapping: extend the last interval's end
              last[1] = Math.max(last[1], curr[1]);
          } else {
              // Non-overlapping: add as new interval
              merged.add(curr);
          }
      }

      return merged.toArray(new int[0][]);
  }

  Time: O(n log n) for sort + O(n) for scan = O(n log n)
  Space: O(n) for result list

----------------------------------------------------------------
TRACED EXAMPLE: [[1,3],[2,6],[8,10],[15,18]]
----------------------------------------------------------------

  After sort (already sorted):
    [1,3], [2,6], [8,10], [15,18]

  merged = [[1,3]]

  Process [2,6]:
    last = [1,3], curr = [2,6]
    curr[0]=2 <= last[1]=3 --> OVERLAP
    last[1] = max(3, 6) = 6
    merged = [[1,6]]

  Process [8,10]:
    last = [1,6], curr = [8,10]
    curr[0]=8 > last[1]=6 --> NO OVERLAP
    merged = [[1,6], [8,10]]

  Process [15,18]:
    last = [8,10], curr = [15,18]
    curr[0]=15 > last[1]=10 --> NO OVERLAP
    merged = [[1,6], [8,10], [15,18]]

  Answer: [[1,6],[8,10],[15,18]] ✓

----------------------------------------------------------------
TRACED EXAMPLE WITH CONTAINMENT: [[1,10],[2,5],[3,7],[8,12]]
----------------------------------------------------------------

  After sort: [1,10],[2,5],[3,7],[8,12]

  merged = [[1,10]]

  Process [2,5]:
    last = [1,10], curr = [2,5]
    2 <= 10 --> OVERLAP
    last[1] = max(10, 5) = 10 (no change — [2,5] is contained)
    merged = [[1,10]]

  Process [3,7]:
    last = [1,10], curr = [3,7]
    3 <= 10 --> OVERLAP
    last[1] = max(10, 7) = 10 (no change — contained)
    merged = [[1,10]]

  Process [8,12]:
    last = [1,10], curr = [8,12]
    8 <= 10 --> OVERLAP
    last[1] = max(10, 12) = 12 (extend!)
    merged = [[1,12]]

  Answer: [[1,12]] ✓

----------------------------------------------------------------
EDGE CASES
----------------------------------------------------------------

  Single interval:
    Input: [[1,5]]
    Output: [[1,5]] (no merging needed)

  All intervals identical:
    Input: [[1,5],[1,5],[1,5]]
    Output: [[1,5]]

  All intervals non-overlapping:
    Input: [[1,2],[3,4],[5,6]]
    Output: [[1,2],[3,4],[5,6]] (no merging)

  All intervals merge to one:
    Input: [[1,3],[2,5],[4,8]]
    Output: [[1,8]]

  Touch at endpoint (touching counts as overlap):
    Input: [[1,4],[4,5]]
    curr[0]=4 <= last[1]=4 --> OVERLAP
    Output: [[1,5]] ✓

----------------------------------------------------------------
COMPLEXITY
----------------------------------------------------------------

  Time:  O(n log n)
  Space: O(n) for result, O(log n) for sort stack
  Can be done in-place? Technically yes, but complex; not recommended.

----------------------------------------------------------------
COMMON MISTAKES
----------------------------------------------------------------

  1. Not sorting first.
     Without sorting: [8,10] and [1,3] in output would check incorrectly.

  2. Using last.end = curr.end instead of max(last.end, curr.end).
     If curr is contained in last, last.end should NOT shrink.

  3. Using a[0] - b[0] in comparator instead of Integer.compare(a[0], b[0]).
     Subtraction can overflow for negative integers.

  4. Modifying intervals array directly.
     Better to add to a new list. Note: merged.add(curr) reuses the
     original array reference — this is fine for the algorithm.

  5. Forgetting to seed the result with intervals[0].
     The loop starts at index 1, so index 0 must be added manually.

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: Why sort by start time?
  A: After sorting, overlapping intervals must be adjacent. An interval
     starting later cannot overlap with one that ends before it. Sorting
     lets us merge in a single linear pass.

  Q: Why use max(last.end, curr.end) and not just curr.end?
  A: If curr is fully contained within last (e.g., last=[1,10], curr=[3,5]),
     setting last.end = 5 would SHRINK our merged interval incorrectly.
     We always extend to the maximum end seen.

  Q: What's the time complexity and can we do better?
  A: O(n log n) dominated by sorting. We can't do better in the general
     case because comparison-based sorting is O(n log n). If the ranges
     are bounded integers, counting sort could give O(n + range).

  Q: What if the input is already sorted?
  A: O(n) — skip the sort step.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------

  - Draw the timeline visualization (horizontal lines showing intervals).
  - Always start with sorting and explain why.
  - Clearly distinguish the two cases: overlap vs no overlap.
  - Highlight the max(last.end, curr.end) point — it catches the
    containment case that beginners miss.
  - Mention the touching endpoint edge case (curr[0] == last[1] is overlap).
