SEGMENT TREE AND BINARY INDEXED TREE — INTERVIEW PATTERN
==========================================================

WHEN TO USE THIS PATTERN
--------------------------
  Trigger signals:
  ✅ Range queries (sum, min, max) with point or range updates
  ✅ "Query [l, r]" repeated many times after updates
  ✅ Need O(log n) per query AND update (not O(n))

  If updates are rare → prefix sum is simpler (O(1) query, O(n) update)
  If updates are frequent → Segment Tree or BIT is needed

─────────────────────────────────────────────────────────────
BINARY INDEXED TREE (BIT / FENWICK TREE)
─────────────────────────────────────────────────────────────
  Simpler than Segment Tree. Supports:
  ✅ Point update
  ✅ Prefix sum query (therefore range sum = prefix(r) - prefix(l-1))

  Key trick: uses lowbit(i) = i & (-i) to navigate the tree.

  1-indexed array. Size = n + 1.

  Java Implementation:
  class BIT {
      int[] tree;
      int n;

      BIT(int n) { this.n = n; tree = new int[n + 1]; }

      // Add val to index i (1-indexed)
      void update(int i, int val) {
          for (; i <= n; i += i & (-i))
              tree[i] += val;
      }

      // Sum from 1 to i (prefix sum, 1-indexed)
      int query(int i) {
          int sum = 0;
          for (; i > 0; i -= i & (-i))
              sum += tree[i];
          return sum;
      }

      // Range sum [l, r] (1-indexed)
      int rangeQuery(int l, int r) {
          return query(r) - query(l - 1);
      }
  }

  Build from array: O(n log n) via n calls to update()
  Time per operation: O(log n)
  Space: O(n)

─────────────────────────────────────────────────────────────
SEGMENT TREE
─────────────────────────────────────────────────────────────
  More powerful than BIT. Supports:
  ✅ Point update
  ✅ Range update (with lazy propagation)
  ✅ Range query (sum, min, max, GCD, etc.)

  Array-based implementation (1-indexed, tree size = 4n):
  - Node i: left child = 2i, right child = 2i+1

  Java Implementation (Range Sum + Point Update):
  class SegmentTree {
      int[] tree;
      int n;

      SegmentTree(int[] nums) {
          n = nums.length;
          tree = new int[4 * n];
          build(nums, 0, n - 1, 1);
      }

      void build(int[] nums, int l, int r, int node) {
          if (l == r) { tree[node] = nums[l]; return; }
          int mid = (l + r) / 2;
          build(nums, l, mid, 2 * node);
          build(nums, mid + 1, r, 2 * node + 1);
          tree[node] = tree[2 * node] + tree[2 * node + 1];
      }

      // Update index idx to val
      void update(int l, int r, int node, int idx, int val) {
          if (l == r) { tree[node] = val; return; }
          int mid = (l + r) / 2;
          if (idx <= mid) update(l, mid, 2*node, idx, val);
          else            update(mid+1, r, 2*node+1, idx, val);
          tree[node] = tree[2*node] + tree[2*node+1];
      }

      // Query sum in range [ql, qr]
      int query(int l, int r, int node, int ql, int qr) {
          if (ql <= l && r <= qr) return tree[node];
          if (qr < l || r < ql) return 0;
          int mid = (l + r) / 2;
          return query(l, mid, 2*node, ql, qr) +
                 query(mid+1, r, 2*node+1, ql, qr);
      }

      // Public API
      void update(int idx, int val) { update(0, n-1, 1, idx, val); }
      int query(int l, int r) { return query(0, n-1, 1, l, r); }
  }

  Time: O(n) build, O(log n) per update/query
  Space: O(n)

─────────────────────────────────────────────────────────────
LAZY PROPAGATION (RANGE UPDATE)
─────────────────────────────────────────────────────────────
  When you need to update a RANGE of elements (e.g., add 5 to all [l,r]),
  naive approach is O(n). Lazy propagation defers updates: O(log n).

  Key idea:
  - Store a "lazy" value per node = pending update not yet pushed to children
  - When visiting a node, push its lazy value down to children first

  class SegTreeLazy {
      int[] tree, lazy;
      int n;

      SegTreeLazy(int n) {
          this.n = n;
          tree = new int[4 * n];
          lazy = new int[4 * n];
      }

      void pushDown(int node, int l, int r) {
          if (lazy[node] != 0) {
              int mid = (l + r) / 2;
              int leftLen = mid - l + 1, rightLen = r - mid;
              tree[2*node]   += lazy[node] * leftLen;
              tree[2*node+1] += lazy[node] * rightLen;
              lazy[2*node]   += lazy[node];
              lazy[2*node+1] += lazy[node];
              lazy[node] = 0;
          }
      }

      // Add val to all elements in [ql, qr]
      void update(int l, int r, int node, int ql, int qr, int val) {
          if (ql <= l && r <= qr) {
              tree[node] += val * (r - l + 1);
              lazy[node] += val;
              return;
          }
          pushDown(node, l, r);
          int mid = (l + r) / 2;
          if (ql <= mid) update(l, mid, 2*node, ql, qr, val);
          if (qr > mid)  update(mid+1, r, 2*node+1, ql, qr, val);
          tree[node] = tree[2*node] + tree[2*node+1];
      }

      int query(int l, int r, int node, int ql, int qr) {
          if (ql <= l && r <= qr) return tree[node];
          if (qr < l || r < ql) return 0;
          pushDown(node, l, r);
          int mid = (l + r) / 2;
          return query(l, mid, 2*node, ql, qr) +
                 query(mid+1, r, 2*node+1, ql, qr);
      }
  }

─────────────────────────────────────────────────────────────
COMPARISON: BIT vs SEGMENT TREE
─────────────────────────────────────────────────────────────
  Feature                  | BIT (Fenwick) | Segment Tree (no lazy) | Seg Tree (lazy)
  ─────────────────────────┼───────────────┼────────────────────────┼────────────────
  Point update             | O(log n)      | O(log n)               | O(log n)
  Range update             | O(log n)*     | O(n) naive             | O(log n)
  Prefix sum query         | O(log n)      | O(log n)               | O(log n)
  Range query              | O(log n)      | O(log n)               | O(log n)
  Range min/max query      | ❌            | ✅                      | ✅
  Code complexity          | Simple        | Medium                  | High
  Space                    | O(n)          | O(n)                    | O(n)

  * BIT supports range update via difference array technique

─────────────────────────────────────────────────────────────
LEETCODE PROBLEMS USING THIS PATTERN
─────────────────────────────────────────────────────────────
  LC 307  - Range Sum Query - Mutable            → BIT or Segment Tree
  LC 315  - Count of Smaller Numbers After Self  → BIT (coordinate compression)
  LC 493  - Reverse Pairs                        → BIT or merge sort
  LC 327  - Count of Range Sum                   → Segment Tree / merge sort
  LC 2286 - Booking Concert Tickets in Groups    → Segment Tree (range max + update)
  LC 699  - Falling Squares                      → Segment Tree (range max)

  LC 307 Solution with BIT:
    class NumArray {
        int[] nums, bit;
        int n;

        NumArray(int[] nums) {
            this.n = nums.length;
            this.nums = new int[n];
            this.bit = new int[n + 1];
            for (int i = 0; i < n; i++) update(i, nums[i]);
        }

        void update(int i, int val) {
            int diff = val - nums[i];
            nums[i] = val;
            for (int j = i+1; j <= n; j += j & (-j)) bit[j] += diff;
        }

        int sumRange(int l, int r) {
            return prefix(r + 1) - prefix(l);
        }

        int prefix(int i) {
            int s = 0;
            for (; i > 0; i -= i & (-i)) s += bit[i];
            return s;
        }
    }

PATTERN IDENTIFICATION CHECKLIST
─────────────────────────────────────────────────────────────
  ✅ Need: repeated range queries with updates in between?
  ✅ Need: O(log n) for both query and update?
  ✅ Need: range min/max (not just sum)?  → Segment Tree (BIT can't do this)
  ✅ Need: range updates + range queries? → Segment Tree with lazy propagation
  ✅ Sum queries only + point updates?    → BIT (simpler)
