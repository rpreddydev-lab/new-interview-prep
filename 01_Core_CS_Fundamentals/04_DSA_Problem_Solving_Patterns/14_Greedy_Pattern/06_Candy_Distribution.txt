================================================================
  CANDY DISTRIBUTION (LC 135) AND TWO-PASS GREEDY
================================================================

  LC 135: n children in a row with ratings[].
          Each child gets at least 1 candy.
          Child with HIGHER rating than neighbor gets MORE candy.
          Find minimum total candy.

  Input:  ratings = [1,0,2]
  Output: 5  (2,1,2)

  Input:  ratings = [1,2,2]
  Output: 4  (1,2,1)

----------------------------------------------------------------
SOLUTION: TWO-PASS GREEDY
----------------------------------------------------------------

  Pass 1 (left to right):
    If ratings[i] > ratings[i-1], candy[i] = candy[i-1] + 1.
    Ensures each child has more than LEFT neighbor if higher rated.

  Pass 2 (right to left):
    If ratings[i] > ratings[i+1], candy[i] = max(candy[i], candy[i+1] + 1).
    Ensures each child has more than RIGHT neighbor if higher rated.
    Use max to not break left-pass constraint.

  Java:
    public int candy(int[] ratings) {
        int n = ratings.length;
        int[] candy = new int[n];
        Arrays.fill(candy, 1);  // everyone gets at least 1

        // Pass 1: left to right
        for (int i = 1; i < n; i++) {
            if (ratings[i] > ratings[i - 1]) candy[i] = candy[i - 1] + 1;
        }

        // Pass 2: right to left
        for (int i = n - 2; i >= 0; i--) {
            if (ratings[i] > ratings[i + 1]) {
                candy[i] = Math.max(candy[i], candy[i + 1] + 1);
            }
        }

        int total = 0;
        for (int c : candy) total += c;
        return total;
    }

  Time: O(n)   Space: O(n)

----------------------------------------------------------------
TRACED EXAMPLE: ratings = [1,3,2,4,1]
----------------------------------------------------------------

  Initial candy: [1, 1, 1, 1, 1]

  Pass 1 (L→R):
    i=1: 3>1 → candy[1]=2.     [1,2,1,1,1]
    i=2: 2<3 → no change.      [1,2,1,1,1]
    i=3: 4>2 → candy[3]=2.     [1,2,1,2,1]
    i=4: 1<4 → no change.      [1,2,1,2,1]

  Pass 2 (R→L):
    i=3: 4>1 → candy[3]=max(2,candy[4]+1)=max(2,2)=2.  [1,2,1,2,1]
    i=2: 2<4 → no change.
    i=1: 3>2 → candy[1]=max(2,candy[2]+1)=max(2,2)=2.  [1,2,1,2,1]
    i=0: 1<3 → no change.

  Total = 1+2+1+2+1 = 7 ✓

  Verify: [1,2,1,2,1]
    child 0(r=1): 1. left-ok(no left). right: ratings[0]<ratings[1], fine.
    child 1(r=3): 2 > 1(left) ✓, 2 > 1(right) ✓
    child 2(r=2): 1. ratings[2]<ratings[1] ✓, ratings[2]<ratings[3] ✓
    child 3(r=4): 2 > 1(right) ✓, 2 > 1(left-candy) ✓

----------------------------------------------------------------
EDGE CASES
----------------------------------------------------------------

  Equal ratings: no constraint between equal neighbors.
    ratings=[1,1,1] → candy=[1,1,1] → total=3.

  Strictly decreasing: [3,2,1]
    Pass 1: [1,1,1] (no increases)
    Pass 2: candy[1]=max(1,1+1)=2. candy[0]=max(1,2+1)=3.
    total=3+2+1=6. Each child more than right neighbor.

  Single peak: [1,2,3,2,1]
    Pass1: [1,2,3,1,1]
    Pass2: i=3: 2>1→candy[3]=max(1,2)=2. i=2: 3>2→candy[2]=max(3,3)=3.
           i=1: 2<3, no. i=0: 1<2, no.
    Result: [1,2,3,2,1]. Total=9 ✓

----------------------------------------------------------------
ONE-PASS APPROACH (ADVANCED, O(1) SPACE)
----------------------------------------------------------------

  Track ascending and descending slopes.
  up = current ascending run length, down = current descending run length.
  If down > up, the peak needs more candy → adjust.

  Java:
    public int candy(int[] ratings) {
        int n = ratings.length;
        if (n == 1) return 1;
        int total = 1, up = 0, down = 0, peak = 0;
        for (int i = 1; i < n; i++) {
            if (ratings[i] > ratings[i - 1]) {
                up++; down = 0; peak = up;
                total += up + 1;
            } else if (ratings[i] < ratings[i - 1]) {
                down++; up = 0;
                total += down + 1;
                if (peak >= down) total--;  // peak gets 'down' candies instead of 1
            } else {
                up = 0; down = 0; peak = 0;
                total++;
            }
        }
        return total;
    }

  Complex to reason about. Two-pass is preferred in interviews.

----------------------------------------------------------------
RELATED PROBLEM: TRAPPING RAIN WATER (LC 42)
----------------------------------------------------------------

  Two-pass pattern also used here.

  Approach 1 — Two-pass:
    Left pass: leftMax[i] = max height from 0 to i.
    Right pass: rightMax[i] = max height from i to n-1.
    Water at i = min(leftMax[i], rightMax[i]) - height[i].

  Java:
    public int trap(int[] height) {
        int n = height.length;
        int[] leftMax = new int[n], rightMax = new int[n];
        leftMax[0] = height[0];
        for (int i = 1; i < n; i++) leftMax[i] = Math.max(leftMax[i-1], height[i]);
        rightMax[n-1] = height[n-1];
        for (int i = n-2; i >= 0; i--) rightMax[i] = Math.max(rightMax[i+1], height[i]);
        int water = 0;
        for (int i = 0; i < n; i++) water += Math.min(leftMax[i], rightMax[i]) - height[i];
        return water;
    }

  Approach 2 — Two-pointer O(1) space:
    Left pointer from left, right pointer from right.
    If leftMax <= rightMax: water[left] = leftMax - height[left], advance left.
    Else: water[right] = rightMax - height[right], advance right.

  Java (two-pointer):
    public int trap(int[] height) {
        int left = 0, right = height.length - 1;
        int leftMax = 0, rightMax = 0, water = 0;
        while (left < right) {
            if (height[left] <= height[right]) {
                leftMax = Math.max(leftMax, height[left]);
                water += leftMax - height[left++];
            } else {
                rightMax = Math.max(rightMax, height[right]);
                water += rightMax - height[right--];
            }
        }
        return water;
    }

----------------------------------------------------------------
RELATED PROBLEM: CONTAINER WITH MOST WATER (LC 11)
----------------------------------------------------------------

  Two pointers. Area = min(height[l], height[r]) * (r - l).
  Shrink the shorter side inward (only chance to improve area is finding taller line).

  Java:
    public int maxArea(int[] height) {
        int left = 0, right = height.length - 1, maxWater = 0;
        while (left < right) {
            maxWater = Math.max(maxWater, Math.min(height[left], height[right]) * (right - left));
            if (height[left] < height[right]) left++;
            else right--;
        }
        return maxWater;
    }

----------------------------------------------------------------
COMMON MISTAKES
----------------------------------------------------------------

  1. Candy: not taking max in second pass (candy[i] = candy[i+1]+1 without max breaks left pass).
  2. Candy: forgetting initial fill of all 1s.
  3. Trapping Rain Water: computing water as leftMax - height[i] (not using min of both maxes).
  4. Container: advancing BOTH pointers instead of just the shorter one.

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: Why do we take max(candy[i], candy[i+1]+1) in the right-to-left pass?
  A: Pass 1 ensures candy[i] > left neighbor. Pass 2 must preserve that while also
     satisfying candy[i] > right neighbor. Using max ensures both constraints hold.

  Q: Why does two-pass greedy give minimum candies?
  A: Pass 1 sets minimum candies for left-neighbor constraint.
     Pass 2 adjusts for right-neighbor constraint using minimum necessary increase (candy[i+1]+1).
     Any lower assignment would violate a constraint.

  Q: Time/space for Trapping Rain Water two-pointer vs two-pass?
  A: Two-pass: O(n) time, O(n) space. Two-pointer: O(n) time, O(1) space. Prefer two-pointer.

  Q: Why shrink the shorter side in Container With Most Water?
  A: Current water = min(h[l],h[r]) * width. Width decreases when we shrink.
     To possibly find larger water, need taller min side. Shrinking shorter side
     (moving shorter pointer) is the only way to potentially increase min height.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------

  - Candy: clearly state both passes and what constraint each satisfies.
  - Draw the candy array after each pass for [1,3,2,4,1].
  - Trapping Rain Water: both approaches are important, but two-pointer is preferred.
  - Container: "the width always shrinks, so we must hope for taller walls → move shorter side."
