================================================================
  LONGEST SUBSTRING WITHOUT REPEATING CHARACTERS (LC 3)
  Deep Dive
================================================================

One of the most classic sliding window problems. Tests your
ability to maintain window state and handle character tracking.

----------------------------------------------------------------
PROBLEM STATEMENT
----------------------------------------------------------------

  Given a string s, find the length of the longest substring
  without repeating characters.

  Input:  s = "abcabcbb"
  Output: 3 ("abc")

  Input:  s = "bbbbb"
  Output: 1 ("b")

  Input:  s = "pwwkew"
  Output: 3 ("wke")

----------------------------------------------------------------
APPROACH: Variable Sliding Window
----------------------------------------------------------------

  Window: [l, r] contains only unique characters.
  Validity condition: all characters in window are distinct.

  When we add s[r] to the window:
    - If s[r] is NOT in window: window stays valid, expand.
    - If s[r] IS in window: shrink from left until s[r] is removed.

  After each r, record the window size as a candidate answer.

----------------------------------------------------------------
SOLUTION 1: HASHSET
----------------------------------------------------------------

  Java:
    public int lengthOfLongestSubstring(String s) {
        Set<Character> window = new HashSet<>();
        int l = 0, ans = 0;

        for (int r = 0; r < s.length(); r++) {
            char rc = s.charAt(r);
            while (window.contains(rc)) {
                window.remove(s.charAt(l));
                l++;
            }
            window.add(rc);
            ans = Math.max(ans, r - l + 1);
        }
        return ans;
    }

  Time: O(n) amortized  Space: O(min(n, alphabet_size))

  Note: The while loop might seem O(n) per step, but each character
  is added and removed at most once. Total work = O(2n) = O(n).

----------------------------------------------------------------
SOLUTION 2: HASHMAP (jump l to past duplicate, O(n) strict)
----------------------------------------------------------------

  Instead of removing one by one, store the last seen INDEX
  of each character. When duplicate found, jump l directly
  past the previous occurrence.

  Java:
    public int lengthOfLongestSubstring(String s) {
        Map<Character, Integer> lastSeen = new HashMap<>();
        int l = 0, ans = 0;

        for (int r = 0; r < s.length(); r++) {
            char rc = s.charAt(r);
            if (lastSeen.containsKey(rc) && lastSeen.get(rc) >= l) {
                l = lastSeen.get(rc) + 1;  // jump past duplicate
            }
            lastSeen.put(rc, r);
            ans = Math.max(ans, r - l + 1);
        }
        return ans;
    }

  Time: O(n)  Space: O(min(n, alphabet_size))

  Key: `lastSeen.get(rc) >= l` ensures we only jump if the
  duplicate is WITHIN the current window (not a stale entry
  from a previous window).

----------------------------------------------------------------
SOLUTION 3: ARRAY INSTEAD OF HASHMAP (ASCII optimization)
----------------------------------------------------------------

  For ASCII strings (128 chars), use int[] instead of HashMap.

  Java:
    public int lengthOfLongestSubstring(String s) {
        int[] lastSeen = new int[128];
        Arrays.fill(lastSeen, -1);
        int l = 0, ans = 0;

        for (int r = 0; r < s.length(); r++) {
            int c = s.charAt(r);
            if (lastSeen[c] >= l) {
                l = lastSeen[c] + 1;
            }
            lastSeen[c] = r;
            ans = Math.max(ans, r - l + 1);
        }
        return ans;
    }

  Time: O(n)  Space: O(1) -- array of fixed size 128

----------------------------------------------------------------
TRACE THROUGH: "abcabcbb"
----------------------------------------------------------------

  Using HashMap approach:

  r   rc   lastSeen(rc)  l    ans   Window
  0   a    -             0    1     [a]
  1   b    -             0    2     [a,b]
  2   c    -             0    3     [a,b,c]
  3   a    0 >= l=0      1    3     [b,c,a]  l=0+1=1
  4   b    1 >= l=1      2    3     [c,a,b]  l=1+1=2
  5   c    2 >= l=2      3    3     [a,b,c]  l=2+1=3
  6   b    4 >= l=3      5    3     [c,b]    l=4+1=5
  7   b    6 >= l=5      7    3     [b]      l=6+1=7

  Answer: 3

----------------------------------------------------------------
TRACE THROUGH: "dvdf"
----------------------------------------------------------------

  r   rc   lastSeen(rc)  l    ans   Window
  0   d    -             0    1     [d]
  1   v    -             0    2     [d,v]
  2   d    0 >= l=0      1    2     [v,d]  l=0+1=1
  3   f    -             1    3     [v,d,f]

  Answer: 3

  The key: 'd' was seen at index 0, but we jump l to 1 (past it).
  Then 'f' extends the window to [v,d,f] = length 3.

----------------------------------------------------------------
EDGE CASES
----------------------------------------------------------------

  1. Empty string:         return 0 (loop never executes)
  2. Single character:     return 1
  3. All same characters:  "aaaa" --> return 1 (l jumps each step)
  4. All unique characters: "abcde" --> return n (window never shrinks)
  5. Unicode characters:   Use HashMap (array may not be big enough)

----------------------------------------------------------------
SOLUTION COMPARISON
----------------------------------------------------------------

  Approach       Time  Space  Notes
  --------       ----  -----  -----
  HashSet        O(n)  O(k)   Simple, while loop may run multiple times
  HashMap        O(n)  O(k)   Strict O(n), jump l directly
  Array[128]     O(n)  O(1)   Fastest in practice for ASCII

  k = number of unique chars in s (at most alphabet size)

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: Why do we need `lastSeen.get(rc) >= l`?
  A: Without this check, we might jump l BACKWARD. For example:
     s = "abba". When we see the second 'a' at r=3:
       lastSeen['a'] = 0, but l is already at 2.
     Jumping to l = 0+1 = 1 would move l backward, incorrectly
     expanding the window to include the first 'b'. The check
     ensures we only move l forward.

  Q: Is the HashSet approach O(n) or O(n^2)?
  A: O(n) amortized. Each character is added to the set once and
     removed at most once. Total operations = O(2n) = O(n).

  Q: What if we need the actual substring, not just the length?
  A: Record `startIndex = l` when we update `ans = r - l + 1`.
     Then return s.substring(startIndex, startIndex + ans).

  Q: What about Unicode or special characters?
  A: Use HashMap<Character, Integer>. The char type in Java is
     UTF-16, so it handles Unicode BMP characters.

  Q: Can this be solved with DP?
  A: Yes, but sliding window is optimal. DP would be O(n^2) or
     require careful state definition. Sliding window is the
     intended approach.
