================================================================
  BINARY SEARCH PATTERN — INTRODUCTION
================================================================

----------------------------------------------------------------
WHAT IS BINARY SEARCH?
----------------------------------------------------------------

  Binary search is a divide-and-conquer algorithm that finds a target
  in a SORTED (or monotone-structured) search space in O(log n) time.

  At each step: eliminate HALF of the remaining search space.
  Key requirement: the search space must be MONOTONE.
    - Either: answers are ordered (false,false,...,true,true,...,true)
    - Or: values are sorted (directly or in some transformed sense)

----------------------------------------------------------------
THE THREE TEMPLATES
----------------------------------------------------------------

  TEMPLATE 1: Exact Search (standard textbook binary search)
  ----------------------------------------------------------
    Use when: looking for an exact value in a sorted array.

    int lo = 0, hi = nums.length - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;
        if (nums[mid] == target) return mid;
        else if (nums[mid] < target) lo = mid + 1;
        else hi = mid - 1;
    }
    return -1;

    Loop exits when lo > hi. Every step either finds target or
    shrinks the space by at least 1 on each side.

  TEMPLATE 2: Find Left Boundary (first true)
  -------------------------------------------
    Use when: finding leftmost position satisfying a condition.
    Predicate: false,false,...,true,true,...
    Find: FIRST true.

    int lo = 0, hi = nums.length;   // hi = length (exclusive)
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        if (condition(mid)) hi = mid;   // include mid, narrow right
        else lo = mid + 1;              // exclude mid, narrow left
    }
    return lo;   // lo == hi == first index where condition is true

    When loop ends: lo is the answer (or length if all false).
    Check: if (lo == nums.length || nums[lo] != target) return -1;

  TEMPLATE 3: Find Right Boundary (last true)
  -------------------------------------------
    Use when: finding rightmost position satisfying a condition.
    Predicate: true,true,...,false,false,...
    Find: LAST true.

    int lo = 0, hi = nums.length;
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        if (condition(mid)) lo = mid + 1;  // move past mid
        else hi = mid;
    }
    return lo - 1;   // last true position

  WHICH TO USE?
    Exact value?              --> Template 1 (lo <= hi)
    First occurrence / min?   --> Template 2 (hi = mid when true)
    Last occurrence / max?    --> Template 3 (lo = mid+1 when true)

----------------------------------------------------------------
MID CALCULATION
----------------------------------------------------------------

  NEVER use: mid = (lo + hi) / 2
  ALWAYS use: mid = lo + (hi - lo) / 2

  Why? When lo and hi are large ints (e.g., Integer.MAX_VALUE / 2),
  their sum overflows. lo + (hi - lo) / 2 is equivalent but overflow-safe.

  For binary search on integers (large range):
    lo = Integer.MIN_VALUE / 2, hi = Integer.MAX_VALUE / 2
    (or problem-specific bounds)

----------------------------------------------------------------
MONOTONE FUNCTION KEY INSIGHT
----------------------------------------------------------------

  Binary search works on ANY monotone function, not just sorted arrays.

  A function f is monotone if:
    f(x) = false, false, ..., false, true, true, ..., true
    (or the reverse, for Template 3)

  The boundary between false and true is the answer.

  Examples of monotone functions:
    - "Is x a valid answer to the minimization problem?" (false below threshold, true above)
    - "Can we fit capacity x?" (false small, true large)
    - "Does the subarray sum fit in k groups of max x?" (false small x, true large x)

  Concept: Binary Search on the ANSWER (not on array indices).

----------------------------------------------------------------
BINARY SEARCH ON ANSWER
----------------------------------------------------------------

  Pattern: The answer itself is in a range [lo, hi].
  The predicate "is mid a valid answer?" is monotone.
  Use binary search to find the boundary.

  Template:
    int lo = minPossibleAnswer, hi = maxPossibleAnswer;
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        if (isValid(mid)) hi = mid;    // if valid, maybe go lower
        else lo = mid + 1;             // if invalid, must go higher
    }
    return lo;

  Examples:
    LC 875: Koko Eating Bananas   (min speed to eat all in h hours)
    LC 1011: Ship Packages        (min capacity to ship in D days)
    LC 410: Split Array Largest Sum  (min largest sum of k subarrays)

----------------------------------------------------------------
COMPLEXITY
----------------------------------------------------------------

  Array binary search:  O(log n)  time,  O(1) space
  Binary search on ans: O(log(hi-lo) * isValid_cost)  time

  If isValid is O(n): total O(n log n), much better than brute O(n^2).

----------------------------------------------------------------
WHEN TO USE BINARY SEARCH
----------------------------------------------------------------

  Triggers:
    - Sorted (or partially sorted) input array
    - "Find first/last occurrence of..."
    - "Find minimum/maximum that satisfies..."
    - "Can we do it in X time/cost/size?" (minimize/maximize)
    - O(log n) requirement in the problem
    - Search space can be halved each step

  NOT suitable for:
    - Unsorted data (unless you can sort first)
    - Non-monotone conditions
    - Linked lists (no O(1) random access)

----------------------------------------------------------------
PITFALLS CHECKLIST
----------------------------------------------------------------

  [ ] Use mid = lo + (hi - lo) / 2 to avoid overflow
  [ ] Choose correct template (exact / left boundary / right boundary)
  [ ] Choose correct hi: nums.length vs nums.length - 1
  [ ] Set lo = mid + 1, NOT lo = mid (or infinite loop)
  [ ] Set hi = mid, NOT hi = mid - 1 (when using Template 2)
  [ ] Verify exit condition: lo == hi (correct) vs lo > hi (Template 1 only)
  [ ] Post-check when returning lo in Template 2 (lo might be out of range)

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: Why use lo + (hi - lo) / 2 instead of (lo + hi) / 2?
  A: Overflow prevention. If lo and hi are near Integer.MAX_VALUE,
     their sum overflows to a negative number. lo + (hi - lo) / 2
     avoids this by computing the offset from lo.

  Q: When does binary search work on non-sorted structures?
  A: Whenever the search space is monotone. E.g., rotated arrays have
     a monotone property per half; peak elements have a predictable
     slope direction; answer-space problems have monotone feasibility.

  Q: What's the difference between Template 1 and Template 2?
  A: Template 1 uses lo <= hi and shrinks both sides symmetrically — good
     for exact match. Template 2 uses lo < hi and converges to a boundary —
     good for finding the first/last valid position.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------

  - State your template choice upfront and why.
  - Draw the false/true predicate line on whiteboard.
  - Always show the loop invariant: [lo, hi) always contains the answer.
  - Trace a 3-element example (even/odd length) to confirm termination.
  - Mention overflow prevention for mid calculation.
