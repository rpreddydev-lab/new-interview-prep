================================================================
  UNION-FIND (DISJOINT SET UNION) PATTERN — INTRODUCTION
================================================================

  Union-Find (a.k.a. Disjoint Set Union / DSU) is a data structure
  that efficiently tracks a collection of elements partitioned into
  disjoint (non-overlapping) sets.

  Two core operations:
    find(x)  : return the REPRESENTATIVE (root) of x's set.
    union(x,y): merge the sets containing x and y.

  Key use: determining if two elements are in the SAME connected
           component, and merging components efficiently.

----------------------------------------------------------------
NAIVE IMPLEMENTATION (for understanding)
----------------------------------------------------------------

  parent[] array: parent[i] = parent of node i. Root: parent[i] = i.

  find(x):
    if parent[x] == x → x is root, return x.
    else return find(parent[x]).

  union(x, y):
    find root of x (rootX), find root of y (rootY).
    if rootX != rootY: parent[rootX] = rootY.

  Problem: find() can be O(n) for a chain (skewed tree).

----------------------------------------------------------------
OPTIMIZED IMPLEMENTATION
----------------------------------------------------------------

  Two optimizations:

  1. PATH COMPRESSION:
     After find(x), set parent of every node on path directly to root.
     find(x):
       if parent[x] != x → parent[x] = find(parent[x])  (one-liner recursive)
       return parent[x]

  2. UNION BY RANK (or SIZE):
     Always attach smaller tree under larger tree.
     rank[i] = upper bound on tree height.
     union: attach root with SMALLER rank under root with LARGER rank.
     If equal rank: attach either, increment winner's rank.

  Together: nearly O(1) amortized per operation (inverse Ackermann α(n)).

  Java:
    class UnionFind {
        int[] parent, rank;

        public UnionFind(int n) {
            parent = new int[n];
            rank   = new int[n];
            for (int i = 0; i < n; i++) parent[i] = i;
        }

        public int find(int x) {
            if (parent[x] != x) parent[x] = find(parent[x]); // path compression
            return parent[x];
        }

        public boolean union(int x, int y) {
            int rx = find(x), ry = find(y);
            if (rx == ry) return false;  // already same component
            if (rank[rx] < rank[ry]) { int tmp = rx; rx = ry; ry = tmp; }
            parent[ry] = rx;             // attach smaller under larger
            if (rank[rx] == rank[ry]) rank[rx]++;
            return true;
        }

        public boolean connected(int x, int y) {
            return find(x) == find(y);
        }
    }

  Note: return false from union() signals no merge happened (cycle detection).

----------------------------------------------------------------
UNION BY SIZE VARIANT (preferred by some)
----------------------------------------------------------------

  Replace rank[] with size[]: size[i] = number of nodes in subtree.
  init: size[i] = 1.
  union: attach smaller-size root under larger-size root.
         size[larger] += size[smaller].

  Java:
    public boolean union(int x, int y) {
        int rx = find(x), ry = find(y);
        if (rx == ry) return false;
        if (size[rx] < size[ry]) { int tmp = rx; rx = ry; ry = tmp; }
        parent[ry] = rx;
        size[rx] += size[ry];
        return true;
    }

  Size gives exact subtree size (useful for LC 323, 547 etc).

----------------------------------------------------------------
VISUALIZATION: UNION SEQUENCE
----------------------------------------------------------------

  n=6, operations: union(0,1), union(1,2), union(3,4), union(2,3)

  After union(0,1):
    parent: [0, 0, 2, 3, 4, 5]  (1 → 0)

  After union(1,2):
    find(1)=0, find(2)=2, union: parent[2]=0
    parent: [0, 0, 0, 3, 4, 5]

  After union(3,4):
    parent: [0, 0, 0, 3, 3, 5]  (4 → 3)

  After union(2,3):
    find(2)=0, find(3)=3. rank[0]=1, rank[3]=1 → tie, attach 3 under 0, rank[0]=2
    parent: [0, 0, 0, 0, 3, 5]  (3 → 0)

  Component roots: 0 (has {0,1,2,3,4}), 5 (has {5})
  Number of components = 2.

----------------------------------------------------------------
COUNTING COMPONENTS
----------------------------------------------------------------

  Initialize count = n.
  Each successful union (returns true) → count--.

  Java:
    int count = n;
    UnionFind uf = new UnionFind(n);
    for (int[] edge : edges) {
        if (uf.union(edge[0], edge[1])) count--;
    }
    return count;

----------------------------------------------------------------
APPLICATIONS TABLE
----------------------------------------------------------------

  Problem Type                 How UF Helps
  --------------------------   -----------------------------------------------
  Connected components         count merges, return remaining count
  Cycle detection              union returns false when already connected
  Merge groups dynamically     union as new connections arrive
  Kruskal's MST                process edges sorted by weight; skip if cycle
  Bipartite check              (unusual — BFS/DFS preferred)
  Grid connectivity            node = row*cols+col, union adjacent same-value
  Account merging              map emails to IDs, union emails of same account
  Redundant connection         first edge that returns false from union = cycle

----------------------------------------------------------------
COMPLEXITY SUMMARY
----------------------------------------------------------------

  Operation    Naive (chain)   With both optimizations
  ----------   -------------   -----------------------
  find(x)      O(n)            O(α(n)) ≈ O(1) amortized
  union(x,y)   O(n)            O(α(n)) ≈ O(1) amortized
  Space        O(n)            O(n)

  α(n) = inverse Ackermann function. For all practical n, α(n) ≤ 4.

----------------------------------------------------------------
WHEN TO USE UNION-FIND VS BFS/DFS
----------------------------------------------------------------

  Use Union-Find when:
    - Dynamically adding edges (online queries)
    - Only need to check connectivity (no need to traverse paths)
    - Cycle detection in undirected graph during edge addition
    - Kruskal's MST algorithm

  Use BFS/DFS when:
    - Need to find actual shortest path
    - Graph is given at once (not streamed)
    - Need to traverse or label connected components
    - Directed graph connectivity
