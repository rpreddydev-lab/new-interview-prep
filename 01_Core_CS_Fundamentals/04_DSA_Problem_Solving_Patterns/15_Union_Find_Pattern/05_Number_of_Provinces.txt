  NUMBER OF PROVINCES AND RELATED UNION-FIND PROBLEMS

  LC 547: n cities, isConnected[i][j]=1 means city i and j are directly connected.
          Return number of provinces (groups of directly OR indirectly connected cities).

  This file covers LC 547 in depth plus several related problems:
    - LC 990: Equations satisfiability
    - LC 1319: Number of operations to make network connected
    - LC 1061: Lexicographically smallest equivalent string
    - LC 839: Similar string groups

----------------------------------------------------------------
LC 547 — NUMBER OF PROVINCES
----------------------------------------------------------------

  Java (Union-Find):
    public int findCircleNum(int[][] isConnected) {
        int n = isConnected.length;
        int[] parent = new int[n], rank = new int[n];
        for (int i = 0; i < n; i++) parent[i] = i;
        int provinces = n;
        for (int i = 0; i < n; i++) {
            for (int j = i + 1; j < n; j++) {
                if (isConnected[i][j] == 1 && union(parent, rank, i, j)) {
                    provinces--;
                }
            }
        }
        return provinces;
    }

  Java (DFS):
    public int findCircleNum(int[][] isConnected) {
        int n = isConnected.length;
        boolean[] visited = new boolean[n];
        int count = 0;
        for (int i = 0; i < n; i++) {
            if (!visited[i]) { dfs(isConnected, visited, i); count++; }
        }
        return count;
    }

    void dfs(int[][] g, boolean[] visited, int i) {
        visited[i] = true;
        for (int j = 0; j < g.length; j++) {
            if (g[i][j] == 1 && !visited[j]) dfs(g, visited, j);
        }
    }

  Time: O(n²)   Space: O(n)

LC 990 — SATISFIABILITY OF EQUALITY EQUATIONS
----------------------------------------------------------------

  Given equations like "a==b", "b!=c", determine if all can be satisfied.

  Strategy:
    Pass 1: Union all "==" pairs.
    Pass 2: For "!=" pairs, if both sides have same root → CONTRADICTION → return false.

  Java:
    public boolean equationsPossible(String[] equations) {
        int[] parent = new int[26], rank = new int[26];
        for (int i = 0; i < 26; i++) parent[i] = i;

        // Pass 1: union equalities
        for (String eq : equations) {
            if (eq.charAt(1) == '=') {
                union(parent, rank, eq.charAt(0) - 'a', eq.charAt(3) - 'a');
            }
        }

        // Pass 2: check inequalities
        for (String eq : equations) {
            if (eq.charAt(1) == '!') {
                int a = eq.charAt(0) - 'a', b = eq.charAt(3) - 'a';
                if (find(parent, a) == find(parent, b)) return false;  // a==a contradiction
            }
        }
        return true;
    }

  Key: Process ALL equalities first, THEN check inequalities.
       Processing in mixed order can miss transitive equalities.

  Example: ["a==b","b==c","a!=c"]
    Union a-b, union b-c → a,b,c all same root.
    Check a!=c: find(a)==find(c) → false. Contradiction!

  Time: O(N * α(26)) = O(N)   Space: O(26) = O(1)

LC 1319 — NUMBER OF OPERATIONS TO MAKE NETWORK CONNECTED
----------------------------------------------------------------

  n computers, connections list. Find min operations to connect all computers.
  An operation: remove a cable from one place and add it elsewhere.

  Key insight:
    - Need at least n-1 cables to connect n computers.
    - If connections.length < n-1 → impossible, return -1.
    - Count number of components after UF. Need (components - 1) operations.
    - Also count redundant edges (cables that can be moved).

  Java:
    public int makeConnected(int n, int[][] connections) {
        if (connections.length < n - 1) return -1;
        int[] parent = new int[n], rank = new int[n];
        for (int i = 0; i < n; i++) parent[i] = i;
        int components = n;
        for (int[] c : connections) {
            if (union(parent, rank, c[0], c[1])) components--;
        }
        return components - 1;  // need to merge (components-1) pairs
    }

  Why components-1?
    Each merge operation reduces components by 1.
    To go from k components to 1, need k-1 operations.

  Time: O(E * α(N))   Space: O(N)

LC 1061 — LEXICOGRAPHICALLY SMALLEST EQUIVALENT STRING
----------------------------------------------------------------

  Given s1 and s2 of same length: for each i, s1[i] and s2[i] are equivalent.
  Equivalence is transitive. Find lexicographically smallest equivalent of baseStr.

  Strategy:
    Union each (s1[i], s2[i]) pair.
    BUT: always make the SMALLER character the root (not rank-based).
    For each char in baseStr, find its root (which is the smallest equivalent).

  Java:
    public String smallestEquivalentString(String s1, String s2, String baseStr) {
        int[] parent = new int[26];
        for (int i = 0; i < 26; i++) parent[i] = i;

        for (int i = 0; i < s1.length(); i++) {
            int a = s1.charAt(i) - 'a', b = s2.charAt(i) - 'a';
            int ra = find(parent, a), rb = find(parent, b);
            if (ra != rb) {
                // Always point LARGER root to SMALLER root
                if (ra < rb) parent[rb] = ra;
                else parent[ra] = rb;
            }
        }

        StringBuilder sb = new StringBuilder();
        for (char c : baseStr.toCharArray()) {
            sb.append((char)(find(parent, c - 'a') + 'a'));
        }
        return sb.toString();
    }

  Note: This uses a CUSTOM union strategy (smallest-wins, not rank-based).
        Must override standard rank union for this problem.

  Time: O((|s1| + |baseStr|) * α(26)) ≈ O(N)

LC 839 — SIMILAR STRING GROUPS
----------------------------------------------------------------

  Two strings are similar if they differ in exactly 0 or 2 positions
  (one is an anagram of the other, swapping 2 chars).
  Return number of groups.

  Java:
    public int numSimilarGroups(String[] strs) {
        int n = strs.length;
        int[] parent = new int[n], rank = new int[n];
        for (int i = 0; i < n; i++) parent[i] = i;
        int groups = n;
        for (int i = 0; i < n; i++) {
            for (int j = i + 1; j < n; j++) {
                if (similar(strs[i], strs[j]) && union(parent, rank, i, j)) {
                    groups--;
                }
            }
        }
        return groups;
    }

    boolean similar(String a, String b) {
        int diff = 0;
        for (int i = 0; i < a.length(); i++) {
            if (a.charAt(i) != b.charAt(i)) diff++;
            if (diff > 2) return false;
        }
        return diff == 0 || diff == 2;
    }

  Time: O(n² * L * α(n))   where L = string length. Space: O(n).

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: Why must equalities be processed before inequalities in LC 990?
  A: Equality forms transitive chains (a==b, b==c → a==c via UF).
     If we interleave, we might miss a transitive connection and
     incorrectly allow a contradiction to pass.

  Q: In LC 1319, why is connections.length < n-1 automatically -1?
  A: A connected graph of n nodes needs AT LEAST n-1 edges (tree structure).
     Fewer cables means impossible to ever connect all computers, regardless of rearrangement.

  Q: In LC 1061, why not use rank-based union?
  A: We need the SMALLEST character as root (lexicographic requirement).
     Rank-based would attach to the larger-rank node, which may not be smallest char.

----------------------------------------------------------------

  - LC 990 is the "must process == before !=" classic UF gotcha.
