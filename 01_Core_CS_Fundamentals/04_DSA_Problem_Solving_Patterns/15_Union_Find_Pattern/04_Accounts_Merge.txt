================================================================
  ACCOUNTS MERGE — LC 721
================================================================

  Given a list of accounts, each account is:
    [name, email1, email2, ...]
  Emails in the same account belong to the same person.
  Two accounts belong to the same person if they share at least one email.

  Merge all accounts belonging to the same person.
  Return merged accounts. Output each account's emails sorted.

  Input:
    [["John","johnsmith@mail.com","john_newyork@mail.com"],
     ["John","johnsmith@mail.com","john00@mail.com"],
     ["Mary","mary@mail.com"],
     ["John","johnnybravo@mail.com"]]

  Output:
    [["John","john00@mail.com","john_newyork@mail.com","johnsmith@mail.com"],
     ["Mary","mary@mail.com"],
     ["John","johnnybravo@mail.com"]]

  Key insight: Emails are nodes. Two emails in the same account are connected.
               Use Union-Find to group all emails of the same person.

----------------------------------------------------------------
APPROACH: UNION-FIND ON EMAILS
----------------------------------------------------------------

  Step 1: Map each email to an integer ID (emailToId).
  Step 2: For each account, union all its emails together (use first email as representative).
  Step 3: Track the NAME for each email ID (emailToName).
  Step 4: Group emails by their root (find(id)).
  Step 5: For each group, sort emails, prepend name, add to result.

  Java:
    public List<List<String>> accountsMerge(List<List<String>> accounts) {
        // Map email → id
        Map<String, Integer> emailToId = new HashMap<>();
        Map<String, String> emailToName = new HashMap<>();
        int id = 0;
        for (List<String> acc : accounts) {
            String name = acc.get(0);
            for (int i = 1; i < acc.size(); i++) {
                String email = acc.get(i);
                if (!emailToId.containsKey(email)) {
                    emailToId.put(email, id++);
                }
                emailToName.put(email, name);
            }
        }

        // Union-Find setup
        int[] parent = new int[id];
        int[] rank = new int[id];
        for (int i = 0; i < id; i++) parent[i] = i;

        // Union emails within same account
        for (List<String> acc : accounts) {
            for (int i = 2; i < acc.size(); i++) {
                union(parent, rank,
                      emailToId.get(acc.get(1)),
                      emailToId.get(acc.get(i)));
            }
        }

        // Group emails by root
        Map<Integer, List<String>> groups = new HashMap<>();
        for (String email : emailToId.keySet()) {
            int root = find(parent, emailToId.get(email));
            groups.computeIfAbsent(root, k -> new ArrayList<>()).add(email);
        }

        // Build result
        List<List<String>> result = new ArrayList<>();
        for (List<String> emails : groups.values()) {
            Collections.sort(emails);
            String name = emailToName.get(emails.get(0));
            List<String> merged = new ArrayList<>();
            merged.add(name);
            merged.addAll(emails);
            result.add(merged);
        }
        return result;
    }

    int find(int[] parent, int x) {
        if (parent[x] != x) parent[x] = find(parent, parent[x]);
        return parent[x];
    }

    void union(int[] parent, int[] rank, int x, int y) {
        int rx = find(parent, x), ry = find(parent, y);
        if (rx == ry) return;
        if (rank[rx] < rank[ry]) { int t = rx; rx = ry; ry = t; }
        parent[ry] = rx;
        if (rank[rx] == rank[ry]) rank[rx]++;
    }

  Time: O(E * α(E) + E log E)   where E = total emails
        (UF operations + sorting emails per group)
  Space: O(E)

----------------------------------------------------------------
TRACED EXAMPLE
----------------------------------------------------------------

  Accounts:
    acc0: John → [johnsmith, john_newyork]
    acc1: John → [johnsmith, john00]
    acc2: Mary → [mary]
    acc3: John → [johnnybravo]

  Email IDs:
    johnsmith→0, john_newyork→1, john00→2, mary→3, johnnybravo→4

  Unions:
    acc0: union(0, 1)    → parent[1]=0
    acc1: union(0, 2)    → parent[2]=0   (johnsmith=0 already, union johnsmith with john00)
    acc2: no union (only 1 email)
    acc3: no union (only 1 email)

  Groups by root after find:
    find(0)=0 → group 0: {johnsmith, john_newyork, john00}
    find(1)=0 → same as above
    find(2)=0 → same as above
    find(3)=3 → group 3: {mary}
    find(4)=4 → group 4: {johnnybravo}

  Result:
    ["John", "john00@...", "john_newyork@...", "johnsmith@..."]
    ["Mary", "mary@..."]
    ["John", "johnnybravo@..."]

----------------------------------------------------------------
ALTERNATIVE: DFS APPROACH
----------------------------------------------------------------

  Build a graph: email → list of emails in same account.
  DFS from each unvisited email, collecting all reachable emails.

  Java:
    public List<List<String>> accountsMerge(List<List<String>> accounts) {
        Map<String, Set<String>> graph = new HashMap<>();
        Map<String, String> emailToName = new HashMap<>();

        for (List<String> acc : accounts) {
            String name = acc.get(0);
            for (int i = 1; i < acc.size(); i++) {
                String email = acc.get(i);
                graph.computeIfAbsent(email, k -> new HashSet<>());
                emailToName.put(email, name);
                if (i > 1) {
                    graph.get(acc.get(1)).add(email);
                    graph.get(email).add(acc.get(1));
                }
            }
        }

        Set<String> visited = new HashSet<>();
        List<List<String>> result = new ArrayList<>();
        for (String email : graph.keySet()) {
            if (!visited.contains(email)) {
                List<String> group = new ArrayList<>();
                dfs(graph, visited, email, group);
                Collections.sort(group);
                group.add(0, emailToName.get(email));
                result.add(group);
            }
        }
        return result;
    }

    void dfs(Map<String, Set<String>> graph, Set<String> visited, String email, List<String> group) {
        visited.add(email);
        group.add(email);
        for (String nei : graph.get(email)) {
            if (!visited.contains(nei)) dfs(graph, visited, nei, group);
        }
    }

  Time: O(E * α(E) + E log E) similarly.

----------------------------------------------------------------
COMPARISON: UF vs DFS FOR ACCOUNTS MERGE
----------------------------------------------------------------

  Aspect           Union-Find                    DFS
  -----------      ----------------------------  --------------------------
  Code length      Slightly more setup            Cleaner graph building
  Intuitiveness    Union = merging accounts       Graph traversal per group
  Space            O(E) arrays + maps             O(E) graph + visited set
  Preferred        In UF-focused interviews       In graph traversal interviews
  Both correct     Yes                            Yes

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: Why not use names to merge accounts?
  A: Same name ≠ same person (many "John"s exist). Only shared emails indicate same person.

  Q: How do you handle accounts with only one email?
  A: They're still added to emailToId/emailToName. No union needed (can't form cycle).
     They appear as singleton groups in result.

  Q: Why sort emails in output?
  A: Problem requires sorted order within each account's email list.

  Q: What is the key UF insight here?
  A: Emails are nodes. An account with k emails has k-1 union operations
     (all union with first email). Two accounts sharing an email naturally
     end up in the same component.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------

  - Draw the email graph first: nodes = emails, edges = "same account".
  - Clearly explain: union all emails within one account using first email as pivot.
  - Edge case: account with 1 email (no union needed but must appear in result).
  - Note: Name goes to index 0, emails start at index 1 in input list — easy off-by-one.
  - For follow-up: this pattern extends to any "grouping by shared attribute" problem.
