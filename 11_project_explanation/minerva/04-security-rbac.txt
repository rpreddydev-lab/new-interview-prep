==============================

What to use this for: "How did you handle security?" / "Walk me through your auth flow" / "How does RBAC work?"

Authentication: ForgeRock SSO (Verizon's Enterprise IdP)
--------------------------------------------------------

Why ForgeRock?
- Verizon's enterprise standard — every internal app uses it (SSO across 50+ tools)
- We don't own identity management — ForgeRock team manages user provisioning, MFA, password policies
- Compliance: FedRAMP-aligned, SOC 2, Verizon's security team audits ForgeRock, not us

Protocol Stack
┌───────────────────────────────────────────────────────┐
│                    OIDC (Identity)                      │
│  id_token with user claims (name, email, roles)        │
├───────────────────────────────────────────────────────┤
│                    OAuth 2.0 (Authorization)            │
│  Authorization Code + PKCE (public SPA client)         │
├───────────────────────────────────────────────────────┤
│                    RS256 JWT (Token Format)             │
│  Asymmetric signing — ForgeRock holds private key,     │
│  we validate with public key from JWKS endpoint        │
└───────────────────────────────────────────────────────┘

Q: "Why PKCE? Why not just Authorization Code?"

"Because our React SPA is a public client — it runs in the user's browser and can't securely store a clientsecret. Without PKCE, an attacker who intercepts the authorization code could exchange it for tokens. PKCE adds a codeverifier / code_challenge pair that proves the token request came from the same client that initiated the login. It's the OAuth 2.1 recommendation for all SPAs."

Q: "Why RS256? Why not HS256?"

"RS256 uses asymmetric keys — ForgeRock signs with a private key, and all 6 of our microservices validate with the public key from the JWKS endpoint. With HS256, every service would need the shared secret, which is a single point of compromise. RS256 means our services never possess the signing key."

Q: "How do you avoid calling ForgeRock on every API request?"

"We cache the JWKS public keys at startup and refresh every 5 minutes. JWT validation is 100% local — parse token, check signature against cached public key, verify exp, iss, aud. That's ~1ms per request, zero network calls."

"By design. Executives need to see the data but should never export raw network data to their laptops. VIEWER role gives them dashboard access with zero export capability. This also satisfies Verizon's data handling policies — network performance data is classified as sensitive."

SecurityFilterChain (Each Microservice)

@Configuration
@EnableWebSecurity
public class SecurityConfig {

    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        http
            .csrf(csrf -> csrf.disable()) // SPA uses Bearer tokens, not cookies
            .sessionManagement(session ->
                session.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
            .oauth2ResourceServer(oauth2 -> oauth2
                .jwt(jwt -> jwt
                    .jwkSetUri("https://sso.verizon.com/openam/oauth2/jwks")
                    .jwtAuthenticationConverter(jwtAuthenticationConverter())
                ))
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/actuator/health").permitAll()
                .requestMatchers("/api/admin/tenants//users/").hasAnyRole("TENANTADMIN", "PLATFORMADMIN")
                .requestMatchers("/api/admin/tenants/**").hasRole("PLATFORM_ADMIN")
                .requestMatchers("/api/admin/dlt/**").hasRole("PLATFORM_ADMIN")
                .requestMatchers("/api/admin/cost/**").hasRole("PLATFORM_ADMIN")
                .requestMatchers(HttpMethod.POST, "/api/dashboards/**").hasAnyRole("CONFIGURATOR", "TENANTADMIN", "PLATFORMADMIN")
                .requestMatchers(HttpMethod.PUT, "/api/dashboards/**").hasAnyRole("CONFIGURATOR", "TENANTADMIN", "PLATFORMADMIN")
                .requestMatchers(HttpMethod.DELETE, "/api/dashboards/**").hasAnyRole("CONFIGURATOR", "TENANTADMIN", "PLATFORMADMIN")
                .requestMatchers("/api/reports/generate").hasAnyRole("ANALYST", "CONFIGURATOR", "TENANTADMIN", "PLATFORMADMIN")
                .requestMatchers(HttpMethod.GET, "/api/**").authenticated()
                .anyRequest().denyAll()
            )
            .addFilterBefore(tenantContextFilter, BearerTokenAuthenticationFilter.class)
            .addFilterBefore(jwtBlacklistFilter, BearerTokenAuthenticationFilter.class);

        return http.build();
    }

    private JwtAuthenticationConverter jwtAuthenticationConverter() {
        JwtGrantedAuthoritiesConverter authoritiesConverter = new JwtGrantedAuthoritiesConverter();
        // ForgeRock puts roles in "roles" claim, not "scope"
        authoritiesConverter.setAuthoritiesClaimName("roles");
        authoritiesConverter.setAuthorityPrefix("ROLE_");

        JwtAuthenticationConverter converter = new JwtAuthenticationConverter();
        converter.setJwtGrantedAuthoritiesConverter(authoritiesConverter);
        return converter;
    }
}

TenantContextFilter (Multi-Tenant Isolation)

@Component
@Order(Ordered.HIGHEST_PRECEDENCE + 10)
public class TenantContextFilter extends OncePerRequestFilter {

    @Override
    protected void doFilterInternal(HttpServletRequest request,
                                     HttpServletResponse response,
                                     FilterChain chain) throws ServletException, IOException {
        Authentication auth = SecurityContextHolder.getContext().getAuthentication();

        if (auth instanceof JwtAuthenticationToken jwtAuth) {
            String tenantId = jwtAuth.getToken().getClaimAsString("tenant_id");

            if (tenantId == null || tenantId.isBlank()) {
                response.sendError(HttpServletResponse.SCFORBIDDEN, "Missing tenantid claim");
                return;
            }

            TenantContext.setTenantId(tenantId);
        }

        try {
            chain.doFilter(request, response);
        } finally {
            TenantContext.clear(); // prevent ThreadLocal leak
        }
    }
}

// ThreadLocal holder
public class TenantContext {
    private static final ThreadLocal TENANT = new ThreadLocal<>();

    public static void setTenantId(String tenantId) { TENANT.set(tenantId); }
    public static String getTenantId() { return TENANT.get(); }
    public static void clear() { TENANT.remove(); }
}

JwtBlacklistFilter (Token Revocation)

@Component
public class JwtBlacklistFilter extends OncePerRequestFilter {

    private final RedisTemplate redisTemplate;

    @Override
    protected void doFilterInternal(HttpServletRequest request,
                                     HttpServletResponse response,
                                     FilterChain chain) throws ServletException, IOException {
        String token = extractBearerToken(request);

        if (token != null) {
            String jti = extractJti(token); // JWT ID claim
            Boolean isBlacklisted = redisTemplate.hasKey("jwt:blacklist:" + jti);

            if (Boolean.TRUE.equals(isBlacklisted)) {
                response.sendError(HttpServletResponse.SC_UNAUTHORIZED, "Token has been revoked");
                return;
            }
        }

        chain.doFilter(request, response);
    }

    // Called when ForgeRock revokes a token (e.g., admin disables user)
    public void blacklistToken(String jti, long expSeconds) {
        redisTemplate.opsForValue().set(
            "jwt:blacklist:" + jti,
            "revoked",
            Duration.ofSeconds(expSeconds) // TTL = token's remaining lifetime
        );
    }
}

Q: "Why a blacklist? JWTs are stateless."

"They are, and that's the problem. If ForgeRock revokes a user's access (e.g., employee termination), their JWT is still valid until expiry (60 minutes). The blacklist in Redis gives us immediate revocation capability. It's a small trade-off — one Redis lookup per request (~0.5ms) — for the ability to instantly cut off access. The TTL on the Redis key matches the JWT's remaining lifetime, so it self-cleans."

Tenant Isolation at Every Layer

JWT Forwarding (Service-to-Service)

// When Query Execution Service calls Dashboard Service to get chart config
@Component
public class JwtForwardingInterceptor implements ClientHttpRequestInterceptor {

    @Override
    public ClientHttpResponse intercept(HttpRequest request, byte[] body,
                                         ClientHttpRequestExecution execution) throws IOException {
        // Get the current user's JWT from SecurityContext
        Authentication auth = SecurityContextHolder.getContext().getAuthentication();
        if (auth instanceof JwtAuthenticationToken jwtAuth) {
            request.getHeaders().setBearerAuth(jwtAuth.getToken().getTokenValue());
        }
        return execution.execute(request, body);
    }
}

// Register with RestTemplate
@Bean
public RestTemplate serviceRestTemplate() {
    RestTemplate template = new RestTemplate();
    template.getInterceptors().add(new JwtForwardingInterceptor());
    return template;
}

Why forward the user's JWT instead of service accounts?
- Maintains the user identity chain → downstream service can log WHO requested the data
- No separate service account credentials to manage/rotate
- Downstream service enforces the same RBAC — no privilege escalation

WebSocket Security
------------------

Problem
WebSocket upgrade request carries the JWT, but subsequent STOMP frames don't have standard HTTP headers. How do we authenticate subscriptions?

Solution: STOMP ChannelInterceptor

@Configuration
@EnableWebSocketMessageBroker
public class WebSocketSecurityConfig implements WebSocketMessageBrokerConfigurer {

    @Override
    public void configureClientInboundChannel(ChannelRegistration registration) {
        registration.interceptors(new StompAuthInterceptor(jwtValidator, accessService));
    }
}

// Validates every SUBSCRIBE frame
public class StompAuthInterceptor implements ChannelInterceptor {

    @Override
    public Message preSend(Message message, MessageChannel channel) {
        StompHeaderAccessor accessor = StompHeaderAccessor.wrap(message);

        if (StompCommand.CONNECT.equals(accessor.getCommand())) {
            // Validate JWT on initial connect
            String token = accessor.getFirstNativeHeader("Authorization");
            Claims claims = jwtValidator.validate(token.replace("Bearer ", ""));
            accessor.setUser(new JwtPrincipal(claims));
        }

        if (StompCommand.SUBSCRIBE.equals(accessor.getCommand())) {
            String destination = accessor.getDestination();
            JwtPrincipal principal = (JwtPrincipal) accessor.getUser();

            // e.g., /topic/tenant/vz-network-eng/dashboard/dash-rf
            String channelTenant = extractTenant(destination);
            String dashboardId = extractDashboardId(destination);

            // Tenant check
            if (!principal.getTenantId().equals(channelTenant)) {
                throw new AccessDeniedException("Cross-tenant subscription blocked");
            }

            // Dashboard access check
            if (dashboardId != null && !accessService.canView(dashboardId, principal)) {
                throw new AccessDeniedException("No access to this dashboard's notifications");
            }
        }

        return message;
    }
}

Security Checklist (Interview-Ready)
------------------------------------

| Threat | Mitigation | Layer |
|--------|-----------|-------|
| XSS token theft | Tokens in memory (not localStorage), HttpOnly refresh cookie option | Frontend |
| CSRF | Disabled — we use Bearer tokens, not cookies for auth | API |
| SQL Injection | Parameterized queries (BigQuery @param), SELECT-only validation | Query Execution |
| Cross-tenant data leak | TenantContext ThreadLocal + PG RLS + BQ dataset IAM | Every layer |
| Privilege escalation | Server-side role check (not frontend), URL pattern + method level | Spring Security |
| Token replay | JWT expiry (60 min) + Redis blacklist for immediate revocation | All services |
| CQL injection (maps) | Server-side CQL_FILTER construction, never from browser | Map Service |
| WebSocket sniffing | TLS (wss://), STOMP ChannelInterceptor validates tenant/role | Notification |
| Service-to-service spoofing | JWT forwarding + K8s NetworkPolicy | Network |
| BigQuery cost attack | maximumBytesBilled cap + rate limiting + scan estimate warnings | Query Execution |
| Report abuse | 500K row cap, 60s timeout, VIEWER can't export | Report Service |
| Audit evasion | All actions → Kafka audit-events → immutable audit trail | Admin Service |
| DLT poison messages | Isolated DLT topics, PLATFORM_ADMIN-only DLT viewer | Kafka |

Q&A Bank (Security-Focused)
---------------------------

Q: "How do you handle user offboarding?"
"ForgeRock handles the identity lifecycle. When IT disables a user in ForgeRock, their JWT is no longer refreshable. For immediate revocation, we add the JWT's jti to our Redis blacklist. The token is blocked within seconds across all 6 services."

Q: "What if someone modifies the JWT claims (changes their role to PLATFORM_ADMIN)?"
"RS256 prevents this. The JWT is signed with ForgeRock's private key, which we don't have. Any modification invalidates the signature. Our JWKS-based validation catches this instantly."

Q: "How do you prevent a CONFIGURATOR from writing SQL that exfiltrates data?"
"Three layers: (1) SQL parser rejects anything that's not SELECT, (2) BigQuery dry-run validates column existence and syntax, (3) all queries are parameterized — the SQL template uses ${filter_name} placeholders that are bound to approved filter values at execution time, not string-concatenated."

Q: "Can a user see another tenant's dashboards?"
"No, enforced at 3 levels: (1) TenantContextFilter extracts tenantid from JWT and stores in ThreadLocal, (2) every repository query includes WHERE tenantid = :tenantId, (3) PostgreSQL RLS as defense-in-depth blocks cross-tenant queries even if our service code has a bug."

Q: "Why not use OAuth2 scopes instead of custom role claims?"
"Scopes in OAuth2 are typically coarse-grained (e.g., read, write). Our 5-role hierarchy with department-based dashboard visibility is more granular than what scopes naturally express. Custom claims in the JWT give us exactly what we need — roles[] and department — without overloading the scope mechanism."
