1. WHAT IS THE RENDER PROPS PATTERN?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Render Props is a technique where a component receives a FUNCTION as a prop
and calls that function to determine what to render. The function receives
the component's internal state/data as arguments.

  // The component with shared logic
  function MouseTracker({ render }) {
    const [position, setPosition] = useState({ x: 0, y: 0 });

    function handleMouseMove(e) {
      setPosition({ x: e.clientX, y: e.clientY });
    }

    return (
      <div onMouseMove={handleMouseMove} style={{ height: '100vh' }}>
        {render(position)}   // calls the render prop with current state
      </div>
    );
  }

  // Usage — consumer decides what to render with the shared state
  function App() {
    return (
      <MouseTracker render={({ x, y }) => (
        <h1>Mouse is at ({x}, {y})</h1>
      )} />
    );
  }

2. RENDER PROPS VIA children (children as function)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

A common variation uses 'children' as the render function instead of a 'render' prop:

  function Toggle({ children }) {
    const [on, setOn] = useState(false);
    return <>{children({ on, toggle: () => setOn(o => !o) })}</>;
  }

  // Usage
  <Toggle>
    {({ on, toggle }) => (
      <div>
        <button onClick={toggle}>{on ? 'Hide' : 'Show'}</button>
        {on && <Panel />}
      </div>
    )}
  </Toggle>

Both styles work — 'render prop' named 'render' vs 'children as function'.
The "children as function" (Function as Child Component / FaCC) style is
more ergonomic in JSX.

3. PRACTICAL EXAMPLE: Data Fetcher
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  function Fetcher({ url, children }) {
    const [data, setData] = useState(null);
    const [loading, setLoading] = useState(true);
    const [error, setError] = useState(null);

    useEffect(() => {
      fetch(url)
        .then(res => res.json())
        .then(data => { setData(data); setLoading(false); })
        .catch(err => { setError(err.message); setLoading(false); });
    }, [url]);

    return children({ data, loading, error });
  }

  // Usage 1: user list
  <Fetcher url="/api/users">
    {({ data: users, loading, error }) => {
      if (loading) return <Spinner />;
      if (error) return <p>Error: {error}</p>;
      return <UserList users={users} />;
    }}
  </Fetcher>

  // Usage 2: posts list — SAME Fetcher, different render
  <Fetcher url="/api/posts">
    {({ data: posts, loading }) =>
      loading ? <Skeleton /> : <PostList posts={posts} />
    }
  </Fetcher>

4. RENDER PROPS vs HOC vs CUSTOM HOOKS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  | Aspect           | HOC                     | Render Props             | Custom Hook         |
  |------------------|-------------------------|--------------------------|---------------------|
  | Pattern          | Wrap component          | Pass function as prop    | Composable function |
  | Code reuse       | Yes                     | Yes                      | Yes                 |
  | DevTools         | Wrapper nesting         | Nesting in render        | Clean, flat         |
  | Prop collision   | Possible                | Less likely              | None                |
  | Conditional use  | Difficult               | Possible                 | Easy                |
  | TypeScript       | Complex generics        | Medium                   | Straightforward     |
  | Modern usage     | Legacy + React.memo     | Legacy (some UI libs)    | PREFERRED           |

  Same logic as custom hook (the modern equivalent):
  function useMousePosition() {
    const [position, setPosition] = useState({ x: 0, y: 0 });
    useEffect(() => {
      const handler = (e) => setPosition({ x: e.clientX, y: e.clientY });
      window.addEventListener('mousemove', handler);
      return () => window.removeEventListener('mousemove', handler);
    }, []);
    return position;
  }

  function App() {
    const { x, y } = useMousePosition();
    return <h1>Mouse is at ({x}, {y})</h1>;
  }
  // Much cleaner! Same logic reused without wrapper components.

5. WHERE RENDER PROPS STILL SHINE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Even with hooks, render props are still valid for:
  - Compound components with render control
  - Libraries that can't use hooks (class component consumers)
  - When you want to isolate renders (Formik, React Final Form, Downshift)
  - Exposing render slots for layout flexibility

  // Downshift uses render props (or children as function):
  <Downshift>
    {({ getInputProps, getItemProps, isOpen, inputValue }) => (
      <div>
        <input {...getInputProps()} />
        {isOpen && items.map(item => (
          <div {...getItemProps({ item })}>{item}</div>
        ))}
      </div>
    )}
  </Downshift>

6. COMMON INTERVIEW QUESTIONS ON RENDER PROPS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: What is the Render Props pattern?
A: A component accepts a function prop (the "render prop") and calls it to
   determine what JSX to render. The function receives the component's internal
   state as arguments. It enables sharing stateful logic across components.

Q: What is "children as a function" (Function as Child Component)?
A: Instead of a named 'render' prop, the component calls props.children as a
   function. Usage: <Toggle>{({ on, toggle }) => <button onClick={toggle}>...</button>}</Toggle>

Q: How do Render Props compare to HOCs?
A: Both share stateful logic between components. Render Props avoid the implicit
   prop injection and wrapper-hell problem of HOCs. However, deeply nested render
   prop functions can create "callback hell." Custom Hooks are the modern,
   preferred solution for both.

Q: What replaced Render Props?
A: Custom Hooks. They achieve the same logic reuse more cleanly without
   component nesting or callback hell. Most modern React code uses hooks.

Q: Can you use Render Props with class components?
A: Yes. That was actually one of the main reasons for the pattern — to share
   logic between class components before hooks existed.
