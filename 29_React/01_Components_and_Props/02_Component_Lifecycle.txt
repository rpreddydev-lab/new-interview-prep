1. COMPONENT LIFECYCLE OVERVIEW
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Every React component goes through three phases:
  1. MOUNTING   — Component is created and inserted into the DOM
  2. UPDATING   — Component re-renders due to state/prop changes
  3. UNMOUNTING — Component is removed from the DOM

2. CLASS COMPONENT LIFECYCLE METHODS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

MOUNTING (in order):
  1. constructor(props)
     - Initialize state, bind event handlers
     - Call super(props) first
     - DO NOT: fetch data, setState (causes double render)

  2. static getDerivedStateFromProps(props, state)
     - Rarely needed; update state based on props
     - Returns new state object or null
     - Runs on EVERY render (mount + update)
     - Cannot access 'this'

  3. render()
     - REQUIRED. Returns JSX (or null)
     - Must be PURE — no side effects, no setState
     - Called on every mount and update

  4. componentDidMount()
     - Component is now in the DOM
     - SAFE place to: fetch data, add event listeners, access DOM, start timers
     - Can call setState here (triggers extra render, but before browser paints)

UPDATING (triggered by: setState, forceUpdate, new props, context change):
  1. static getDerivedStateFromProps(props, state)
  2. shouldComponentUpdate(nextProps, nextState) → boolean
     - Return false to skip re-render (optimization)
     - Not available in PureComponent (which auto-shallow-compares)
  3. render()
  4. getSnapshotBeforeUpdate(prevProps, prevState) → snapshot
     - Capture DOM state before changes (e.g., scroll position)
     - Return value is passed to componentDidUpdate as 3rd argument
  5. componentDidUpdate(prevProps, prevState, snapshot)
     - DOM has been updated
     - Can fetch data based on prop changes (compare prevProps)
     - AVOID infinite loops: always check prevProps/prevState before setState

UNMOUNTING:
  1. componentWillUnmount()
     - Clean up: cancel timers, subscriptions, cancel fetch requests
     - DO NOT setState here (component is being destroyed)

ERROR HANDLING:
  1. static getDerivedStateFromError(error)
     - Update state to show fallback UI
  2. componentDidCatch(error, info)
     - Log error details

DEPRECATED lifecycle methods (avoid):
  - componentWillMount         → use constructor or componentDidMount
  - componentWillReceiveProps  → use getDerivedStateFromProps or componentDidUpdate
  - componentWillUpdate        → use componentDidUpdate or getSnapshotBeforeUpdate
  (Renamed with UNSAFE_ prefix in React 16.3, will be removed in future)

3. FULL CLASS COMPONENT LIFECYCLE EXAMPLE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  class DataFetcher extends Component {
    state = { data: null, loading: true, error: null };

    componentDidMount() {
      this.fetchData();
    }

    componentDidUpdate(prevProps) {
      if (prevProps.userId !== this.props.userId) {
        this.fetchData(); // re-fetch when userId changes
      }
    }

    componentWillUnmount() {
      this.abortController?.abort(); // cancel ongoing requests
    }

    async fetchData() {
      this.abortController = new AbortController();
      try {
        const res = await fetch(`/api/users/${this.props.userId}`, {
          signal: this.abortController.signal
        });
        const data = await res.json();
        this.setState({ data, loading: false });
      } catch (err) {
        if (err.name !== 'AbortError') {
          this.setState({ error: err.message, loading: false });
        }
      }
    }

    render() {
      const { data, loading, error } = this.state;
      if (loading) return <Spinner />;
      if (error) return <Error message={error} />;
      return <Profile data={data} />;
    }
  }

4. FUNCTIONAL COMPONENT LIFECYCLE WITH useEffect
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

useEffect covers MOUNTING, UPDATING, and UNMOUNTING based on the dependency array:

  // componentDidMount — runs once after initial render
  useEffect(() => {
    console.log('mounted');
  }, []);  // empty deps = run once

  // componentDidUpdate — runs when deps change
  useEffect(() => {
    console.log('userId changed:', userId);
  }, [userId]);  // runs on mount AND whenever userId changes

  // componentWillUnmount — cleanup function
  useEffect(() => {
    const timer = setInterval(() => tick(), 1000);
    return () => clearInterval(timer);  // cleanup on unmount
  }, []);

  // componentDidUpdate with comparison (runs every render except initial)
  const isFirstRender = useRef(true);
  useEffect(() => {
    if (isFirstRender.current) {
      isFirstRender.current = false;
      return;
    }
    // Only on updates, not mount
  }, [someDep]);

  // Full data fetching pattern with cleanup:
  function DataFetcher({ userId }) {
    const [data, setData] = useState(null);
    const [loading, setLoading] = useState(true);
    const [error, setError] = useState(null);

    useEffect(() => {
      const controller = new AbortController();
      setLoading(true);
      setError(null);

      fetch(`/api/users/${userId}`, { signal: controller.signal })
        .then(res => res.json())
        .then(data => { setData(data); setLoading(false); })
        .catch(err => {
          if (err.name !== 'AbortError') setError(err.message);
          setLoading(false);
        });

      return () => controller.abort(); // cleanup: cancel request on unmount or userId change
    }, [userId]);

    if (loading) return <Spinner />;
    if (error) return <Error message={error} />;
    return <Profile data={data} />;
  }

5. EFFECT TIMING: useEffect vs useLayoutEffect
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  useEffect:
    - Runs AFTER the browser paints (async, non-blocking)
    - 99% of use cases: data fetching, subscriptions, analytics
    - Won't block visual update

  useLayoutEffect:
    - Runs BEFORE the browser paints (synchronous, after DOM mutation)
    - Equivalent to componentDidMount/componentDidUpdate timing
    - Use for: reading DOM measurements (getBoundingClientRect),
      preventing visual flicker, synchronous DOM mutations

  Timeline:
    Render → DOM Mutation → useLayoutEffect → Browser Paint → useEffect

  MOUNTING                UPDATING                  UNMOUNTING
  ─────────────────       ──────────────────────    ──────────────────
  constructor()
  ↓                       props change OR
  getDerivedStateFrom     setState() called
  Props()                 ↓
  ↓                       getDerivedStateFromProps()
  render()                ↓
  ↓                       shouldComponentUpdate()
  [DOM updated]           ↓
  ↓                       render()
  componentDidMount()     ↓                         componentWillUnmount()
                          [DOM updated]
                          ↓
                          getSnapshotBeforeUpdate()
                          ↓
                          componentDidUpdate()

7. COMMON INTERVIEW QUESTIONS ON LIFECYCLE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: What are the phases of a React component lifecycle?
A: Mounting (created + added to DOM), Updating (re-renders from state/prop changes),
   Unmounting (removed from DOM). Class components have explicit lifecycle methods
   for each phase; functional components use useEffect with the dependency array.

Q: Where should you perform API calls in React?
A: In componentDidMount() (class) or useEffect(() => {...}, []) (functional).
   NOT in the constructor or render — these may be called multiple times.
   In concurrent mode, the render phase can be run multiple times.

Q: What is the difference between componentDidMount and componentDidUpdate?
A: componentDidMount runs ONCE after the initial render/mount.
   componentDidUpdate runs after EVERY re-render (update). You must compare
   prevProps/prevState to avoid infinite loops.

Q: What does the dependency array in useEffect do?
A: It controls when the effect re-runs:
   - No array: runs after every render
   - Empty []: runs once on mount
   - [dep1, dep2]: runs when any dependency changes

Q: What is getSnapshotBeforeUpdate?
A: A lifecycle method that runs right before the DOM is updated. You can capture
   the current DOM state (e.g., scroll position) and the returned value is
   passed to componentDidUpdate. Use case: chat scroll preservation.

Q: Why should you clean up in useEffect?
A: To prevent memory leaks and stale state updates on unmounted components.
   E.g., if you set up a timer or subscription and the component unmounts,
   the timer/subscription continues running and tries to update unmounted state.
   The cleanup function (return value of useEffect) handles this.

Q: What happens if you setState in componentDidMount?
A: It's allowed and common (e.g., for data fetching). It causes a second render
   before the browser paints, so the user doesn't see the intermediate state.
   However, excessive use can hurt performance.

Q: What is shouldComponentUpdate?
A: A class lifecycle method that returns a boolean deciding whether to re-render.
   Default: true (always re-render). Override to optimize:
   return nextProps.value !== this.props.value;
   The hook equivalent is React.memo() for props comparison.
