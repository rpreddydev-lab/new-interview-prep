1. WHAT IS A HIGHER ORDER COMPONENT?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

A Higher Order Component (HOC) is a FUNCTION that:
  - Takes a component as input
  - Returns a NEW, enhanced component

  const EnhancedComponent = higherOrderComponent(WrappedComponent);

It's a pattern (not a React API) for cross-cutting concerns and code reuse.
HOCs follow the same pattern as Higher Order Functions in JS (like Array.map).

  // HOC signature:
  function withSomething(WrappedComponent) {
    return function EnhancedComponent(props) {
      // add logic here
      return <WrappedComponent {...props} />;
    };
  }

2. WHY USE HOCs?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

HOCs solve the problem of sharing stateful logic between components without
repeating it. Common use cases:
  - Authentication/authorization (withAuth)
  - Data fetching (withData)
  - Loading state (withLoading)
  - Logging/analytics (withLogger)
  - Theme injection (withTheme)
  - Feature flags (withFeatureFlag)

3. HOC EXAMPLES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

EXAMPLE 1: withLoading (add loading state to any component)
  function withLoading(WrappedComponent) {
    return function WithLoading({ isLoading, ...props }) {
      if (isLoading) return <Spinner />;
      return <WrappedComponent {...props} />;
    };
  }

  const UserListWithLoading = withLoading(UserList);
  // Usage:
  <UserListWithLoading isLoading={loading} users={users} />

EXAMPLE 2: withAuth (protect routes)
  function withAuth(WrappedComponent) {
    return function WithAuth(props) {
      const { isAuthenticated } = useAuth();
      if (!isAuthenticated) return <Redirect to="/login" />;
      return <WrappedComponent {...props} />;
    };
  }

  const ProtectedDashboard = withAuth(Dashboard);

EXAMPLE 3: withLogger (log prop changes for debugging)
  function withLogger(WrappedComponent) {
    return function WithLogger(props) {
      useEffect(() => {
        console.log(`${WrappedComponent.name} rendered with:`, props);
      });
      return <WrappedComponent {...props} />;
    };
  }

EXAMPLE 4: withTheme (inject theme into any component)
  function withTheme(WrappedComponent) {
    return function WithTheme(props) {
      const theme = useContext(ThemeContext);
      return <WrappedComponent {...props} theme={theme} />;
    };
  }

EXAMPLE 5: withData (generic data fetching HOC)
  function withData(url) {
    return function(WrappedComponent) {
      return function WithData(props) {
        const [data, setData] = useState(null);
        const [loading, setLoading] = useState(true);
        const [error, setError] = useState(null);

        useEffect(() => {
          fetch(url)
            .then(res => res.json())
            .then(data => { setData(data); setLoading(false); })
            .catch(err => { setError(err); setLoading(false); });
        }, [url]);

        return <WrappedComponent data={data} loading={loading} error={error} {...props} />;
      };
    };
  }

  const UserListWithData = withData('/api/users')(UserList);

4. HOC RULES AND BEST PRACTICES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

RULE 1: Pass through unrelated props
  // BAD: HOC swallows props
  return <WrappedComponent />;

  // GOOD: spread all props through
  return <WrappedComponent {...props} />;

RULE 2: Use displayName for better debugging
  function withSomething(WrappedComponent) {
    function WithSomething(props) { ... }
    WithSomething.displayName = `WithSomething(${
      WrappedComponent.displayName || WrappedComponent.name || 'Component'
    })`;
    return WithSomething;
  }
  // Now React DevTools shows: WithSomething(UserCard) instead of just Component

RULE 3: Don't create HOCs inside render (inside component body)
  // BAD: creates new enhanced component on every render → remounts every time
  function MyComponent() {
    const Enhanced = withSomething(OtherComponent); // WRONG!
    return <Enhanced />;
  }

  // GOOD: create HOC at module level
  const Enhanced = withSomething(OtherComponent);
  function MyComponent() {
    return <Enhanced />;
  }

RULE 4: Copy over static methods (HOC wraps the component, losing statics)
  import hoistNonReactStatics from 'hoist-non-react-statics';
  function withSomething(WrappedComponent) {
    function WithSomething(props) { ... }
    hoistNonReactStatics(WithSomething, WrappedComponent);
    return WithSomething;
  }

RULE 5: Refs don't pass through by default (use React.forwardRef)
  function withSomething(WrappedComponent) {
    const WithSomething = React.forwardRef((props, ref) => (
      <WrappedComponent {...props} forwardedRef={ref} />
    ));
    return WithSomething;
  }

5. HOC PROBLEMS (WHY HOOKS REPLACED THEM)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Problems with HOCs:
  1. WRAPPER HELL: Multiple HOCs create deeply nested component trees
     withA(withB(withC(withD(MyComponent))))
     DevTools shows: WithA > WithB > WithC > WithD > MyComponent (hard to debug)

  2. PROP COLLISIONS: Multiple HOCs may inject props with the same name
     withUser(withData(MyComponent)) — both inject 'data' prop?

  3. IMPLICIT CONTRACTS: It's not obvious which HOC injects which props

  4. NOT COMPOSABLE WITH HOOKS: Can't use HOCs conditionally

  5. LOSS OF STATICS: Static methods on the wrapped component are not automatically
     transferred (need hoist-non-react-statics)

  Modern alternative with Custom Hook:
  // Instead of withAuth HOC, write useAuth hook:
  function useAuth() {
    const { isAuthenticated, user } = useContext(AuthContext);
    return { isAuthenticated, user };
  }

  function Dashboard() {
    const { isAuthenticated } = useAuth();
    if (!isAuthenticated) return <Redirect to="/login" />;
    return <DashboardContent />;
  }
  // Cleaner, no wrapper hell, explicit about what data is used

6. REAL-WORLD HOC: React.memo()
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

React.memo is a built-in HOC that memoizes a component and skips re-render
if props haven't shallowly changed:

  const MyComponent = React.memo(function MyComponent({ name, age }) {
    return <div>{name}: {age}</div>;
  });

  // With custom comparison:
  const MyComponent = React.memo(
    function MyComponent({ user }) { return <div>{user.name}</div>; },
    (prevProps, nextProps) => prevProps.user.id === nextProps.user.id
    // return true → skip re-render; false → re-render
  );

7. COMMON INTERVIEW QUESTIONS ON HOCs
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: What is a Higher Order Component?
A: A function that takes a component and returns a new, enhanced component.
   Used for code reuse in cross-cutting concerns like authentication, loading
   states, theming. The pattern mirrors Higher Order Functions in JS.

Q: What are the disadvantages of HOCs?
A: Wrapper hell (deeply nested components), prop name collisions, implicit props
   (hard to know where they come from), statics not forwarded, refs don't pass
   through. Hooks largely solve these problems more elegantly.

Q: What replaced HOCs?
A: Custom Hooks. They achieve the same code reuse without the component nesting.
   A hook like useAuth() is clearer than withAuth(Component).

Q: How do you forward refs in a HOC?
A: Use React.forwardRef() inside the HOC to create a ref that's forwarded to
   the wrapped component:
   const WithRef = React.forwardRef((props, ref) => (
     <WrappedComponent {...props} ref={ref} />
   ));

Q: What is React.memo and is it a HOC?
A: Yes. React.memo is a built-in HOC that wraps a component and returns a new
   one that only re-renders if props shallowly changed.

Q: Why shouldn't you define a HOC inside a component's render method?
A: Each render would create a NEW component type, causing React to unmount and
   remount the old one (losing state) on every parent render.
