1. WHAT ARE PROPS?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Props (short for "properties") are the mechanism for passing data FROM a parent
component TO a child component. They are the primary way components communicate.

  // Parent passes props
  function App() {
    return <UserCard name="Alice" age={30} isAdmin={true} />;
  }

  // Child receives props
  function UserCard({ name, age, isAdmin }) {
    return (
      <div>
        <h2>{name}</h2>
        <p>Age: {age}</p>
        {isAdmin && <span>Admin</span>}
      </div>
    );
  }

Key characteristics of props:
  1. IMMUTABLE — A child component cannot modify its own props
  2. UNIDIRECTIONAL — Only flow from parent → child (one-way data binding)
  3. READ-ONLY — Treating props as read-only is a core React principle
  4. ANY JavaScript value can be passed as a prop: string, number, boolean,
     array, object, function, JSX, component, ref, etc.

2. PASSING DIFFERENT TYPES OF PROPS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  // String (no braces needed for string literals)
  <Button label="Submit" />
  <Button label={'Submit'} />  // equivalent

  // Number (use braces)
  <Progress value={75} max={100} />

  // Boolean (presence = true)
  <Input disabled />           // disabled={true}
  <Input disabled={false} />   // explicitly false

  // Object
  <Avatar user={{ name: 'Alice', avatar: 'alice.jpg' }} />

  // Array
  <List items={['a', 'b', 'c']} />

  // Function (callback)
  <Button onClick={() => console.log('clicked')} />
  <Form onSubmit={handleSubmit} />

  // JSX / React element
  <Modal header={<h1>Title</h1>} />

  // Component (React.ComponentType)
  <Route component={HomePage} />

  // Ref
  <Input ref={inputRef} />

3. THE CHILDREN PROP
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

'children' is a special prop that represents the content BETWEEN opening and
closing tags of a component.

  // Usage
  <Card>
    <h2>Title</h2>
    <p>Content here</p>
  </Card>

  // Card component receives children
  function Card({ children, className }) {
    return <div className={`card ${className}`}>{children}</div>;
  }

  // TypeScript type for children:
  interface Props {
    children: React.ReactNode;     // any renderable content (most permissive)
    children: React.ReactElement;  // single JSX element
    children: JSX.Element;         // same as ReactElement
    children: string;              // only strings
  }

React.Children utilities (for manipulating children):
  React.Children.count(children)          // count children
  React.Children.map(children, fn)        // map over children
  React.Children.forEach(children, fn)    // iterate children
  React.Children.toArray(children)        // convert to array with keys
  React.Children.only(children)           // assert single child (throws if not)

  // Example: adding props to all children
  function EnhancedList({ children }) {
    return (
      <ul>
        {React.Children.map(children, (child, index) =>
          React.cloneElement(child, { index })
        )}
      </ul>
    );
  }

  // Method 1: Default parameters in function (modern, preferred)
  function Button({ label = 'Click me', variant = 'primary', size = 'md' }) {
    return <button className={`btn btn-${variant} btn-${size}`}>{label}</button>;
  }

  // Method 2: Component.defaultProps (legacy, still works)
  Button.defaultProps = {
    label: 'Click me',
    variant: 'primary',
  };

  // Method 3: Nullish coalescing
  function Button({ label, variant }) {
    const displayLabel = label ?? 'Click me';
    const displayVariant = variant ?? 'primary';
    ...
  }

  // TypeScript approach: default parameter in destructuring
  const Button: React.FC<ButtonProps> = ({
    label = 'Click me',
    variant = 'primary'
  }) => { ... };

5. PROP DRILLING AND ITS PROBLEMS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Prop drilling = passing props through many intermediate components that don't
need them, just to reach a deeply nested child.

  App → Dashboard → Sidebar → UserInfo → Avatar  (needs user prop)
  // user must be passed through Dashboard, Sidebar, UserInfo even if
  // only Avatar needs it

  Problems:
    - Verbose, lots of boilerplate
    - Intermediate components are polluted with props they don't use
    - Refactoring becomes painful (must update every layer)

  Solutions:
    - Context API (for state that needs to be accessed deeply)
    - Component Composition (pass components as children/props instead of data)
    - State management library (Redux, Zustand)

6. PROPTYPES — RUNTIME TYPE CHECKING
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

PropTypes is a runtime type checking library (shipped separately as 'prop-types').
It validates prop types and shows console warnings in development.

Install: npm install prop-types

  import PropTypes from 'prop-types';

  function UserCard({ name, age, email, role, tags, onClick }) {
    return <div>...</div>;
  }

  UserCard.propTypes = {
    name:     PropTypes.string.isRequired,
    age:      PropTypes.number,
    email:    PropTypes.string,
    role:     PropTypes.oneOf(['admin', 'user', 'moderator']),
    tags:     PropTypes.arrayOf(PropTypes.string),
    onClick:  PropTypes.func,
    user:     PropTypes.shape({
      id:     PropTypes.number.isRequired,
      name:   PropTypes.string.isRequired,
    }),
    children: PropTypes.node,
    component: PropTypes.elementType,  // a React component class/function
  };

  UserCard.defaultProps = {
    age: 18,
    role: 'user',
  };

Common PropTypes:
  PropTypes.string
  PropTypes.number
  PropTypes.bool
  PropTypes.func
  PropTypes.object
  PropTypes.array
  PropTypes.node          // anything renderable: string, number, element, array
  PropTypes.element       // React element
  PropTypes.elementType   // Component class/function
  PropTypes.any
  PropTypes.symbol
  PropTypes.instanceOf(ClassName)
  PropTypes.oneOf(['a', 'b', 'c'])
  PropTypes.oneOfType([PropTypes.string, PropTypes.number])
  PropTypes.arrayOf(PropTypes.string)
  PropTypes.objectOf(PropTypes.number)
  PropTypes.shape({ id: PropTypes.number, name: PropTypes.string })
  PropTypes.exact({ ... })    // like shape but warns on extra props

Add .isRequired to any type to mark it as required.

7. TYPESCRIPT vs PROPTYPES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  | Aspect          | PropTypes                    | TypeScript                  |
  |-----------------|------------------------------|-----------------------------|
  | When checked    | Runtime (development only)   | Compile time                |
  | Errors caught   | Console warning              | Build error                 |
  | Coverage        | Props only                   | Entire codebase             |
  | IDE support     | Limited                      | Full autocomplete/IntelliSense|
  | Bundle size     | Small extra (~4KB)           | Zero (types stripped at build)|
  | Learning curve  | Low                          | Medium-High                 |
  | Industry trend  | Legacy (still used)          | Standard for new projects   |

  // TypeScript interface for props (most modern approach):
  interface ButtonProps {
    label: string;
    variant?: 'primary' | 'secondary' | 'danger';
    onClick: (event: React.MouseEvent<HTMLButtonElement>) => void;
    children?: React.ReactNode;
  }

  const Button: React.FC<ButtonProps> = ({ label, variant = 'primary', onClick }) => (
    <button className={`btn-${variant}`} onClick={onClick}>{label}</button>
  );

8. COMMON INTERVIEW QUESTIONS ON PROPS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: What are props in React?
A: Props are read-only data passed from parent to child components. They enable
   component reusability and unidirectional data flow. A component cannot modify
   its own props; it can only read them.

Q: What is the difference between props and state?
A: Props come from outside the component (passed by parent), are immutable within
   the component, and trigger re-render when the parent re-renders with new props.
   State is owned and managed by the component itself, is mutable (via setState/
   useState), and triggers re-render when changed.

Q: Can you modify props directly?
A: No. Props are read-only (immutable). Modifying props directly would break React's
   unidirectional data flow and make the app unpredictable. If a child needs to
   update data, it calls a callback function passed as a prop by the parent.

Q: What is prop drilling and how do you avoid it?
A: Prop drilling is passing props through multiple levels of components just to
   reach a deeply nested component. Solutions: Context API (for global/shared state),
   component composition (pass components as children), or state management (Redux, Zustand).

Q: What is the children prop?
A: The special 'children' prop represents the content passed between a component's
   opening and closing tags. It enables wrapper/container patterns and makes
   components more flexible.

Q: What is PropTypes?
A: A runtime prop validation library. It checks that props match expected types
   and logs warnings in development. TypeScript is preferred in modern projects
   as it provides compile-time type safety across the whole codebase.

Q: What is the difference between PropTypes.shape and PropTypes.exact?
A: shape validates that an object has at least the specified keys with the right types.
   exact validates the SAME AND ONLY those keys (warns if there are extra keys).

Q: How does React.cloneElement work?
A: React.cloneElement(element, props, ...children) creates a copy of a React element
   with new props merged in. Used in compound components to inject props into children.
   Example: parent renders children but needs to inject an 'index' or 'active' prop.
