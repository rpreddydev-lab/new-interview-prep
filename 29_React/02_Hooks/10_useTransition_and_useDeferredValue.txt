1. CONCURRENT RENDERING BACKGROUND
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Before React 18, all state updates were treated with equal priority.
If a heavy re-render was triggered (e.g., filtering 10,000 items), the UI
would block/freeze until the render finished.

React 18 introduced Concurrent Rendering, which allows React to:
  1. Start a render
  2. Pause it if something higher-priority needs to happen (e.g., a keypress)
  3. Resume or discard the paused render

Two hooks expose this capability to developers:
  - useTransition  → marks a state update as "non-urgent"
  - useDeferredValue → creates a deferred copy of a value

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
2. useTransition
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  const [isPending, startTransition] = useTransition();

  - isPending: boolean — true while the deferred update is still processing
  - startTransition: function — wrap state updates to mark them as non-urgent

  Basic Usage:
    function SearchPage() {
      const [query, setQuery] = useState('');
      const [results, setResults] = useState([]);
      const [isPending, startTransition] = useTransition();

      function handleInput(e) {
        const value = e.target.value;
        // URGENT: Update input immediately (user sees their typing)
        setQuery(value);

        // NON-URGENT: Update results list (can be interrupted)
        startTransition(() => {
          setResults(filterHugeList(value)); // expensive computation
        });
      }

      return (
        <div>
          <input value={query} onChange={handleInput} />
          {isPending && <Spinner />}
          <ResultsList results={results} />
        </div>
      );
    }

  What "non-urgent" means:
    - React will render the urgent update first (the input stays responsive)
    - React starts rendering the deferred update in the background
    - If a NEW urgent update arrives before the deferred one finishes,
      React INTERRUPTS and DISCARDS the deferred render, starts fresh
    - The user never sees a stale or intermediate state

3. REAL-WORLD EXAMPLE: Tab Switching With Slow Render
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  // WITHOUT useTransition: clicking tabs causes UI to freeze
  function TabContainer() {
    const [activeTab, setActiveTab] = useState('home');

    return (
      <div>
        <TabBar onSelect={setActiveTab} active={activeTab} />
        <TabContent tab={activeTab} /> {/* This might be slow to render */}
      </div>
    );
  }

  // WITH useTransition: tab bar stays responsive while content loads
  function TabContainer() {
    const [activeTab, setActiveTab] = useState('home');
    const [isPending, startTransition] = useTransition();

    function handleTabSelect(tab) {
      startTransition(() => {
        setActiveTab(tab);
      });
    }

    return (
      <div>
        <TabBar onSelect={handleTabSelect} active={activeTab} />
        {isPending && <div style={{ opacity: 0.5 }}><OldTabContent /></div>}
        {!isPending && <TabContent tab={activeTab} />}
      </div>
    );
  }

4. useTransition RULES AND LIMITATIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  MUST DO:
  - Wrap ONLY state updates inside startTransition (not other logic)
  - The update wrapped must be a React state setter or context update
  - Must use createRoot() (React 18 root) for concurrent features to work

  CANNOT DO:
  - You cannot mark a text input's own value update as a transition
    (input updates must always be urgent so user sees their typing)
  - Cannot wrap arbitrary async code — must be synchronous state setters
    (use startTransition with async → upcoming React 19 feature: async transitions)
  - Cannot read isPending from inside the startTransition callback

  // WRONG: Async inside startTransition (React 18)
  startTransition(async () => {          // ❌ React ignores async in 18
    const data = await fetchData();
    setData(data);
  });

  // CORRECT: Transition wraps only the setter
  const data = await fetchData();
  startTransition(() => {               // ✅
    setData(data);
  });

5. useDeferredValue
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  const deferredValue = useDeferredValue(value);

  - Takes a value and returns a deferred copy of it
  - When value changes, React keeps returning the old value until it can
    commit the new render without blocking urgent updates
  - The deferred copy "lags behind" the real value during high-load renders

  Basic Usage:
    function SearchResults({ query }) {
      const deferredQuery = useDeferredValue(query);

      // This expensive component uses the deferred (possibly stale) value
      // It won't block typing in the input above
      return <HeavyFilteredList query={deferredQuery} />;
    }

    function SearchPage() {
      const [query, setQuery] = useState('');

      return (
        <div>
          <input
            value={query}
            onChange={e => setQuery(e.target.value)}  // always urgent
          />
          <SearchResults query={query} />  {/* internally deferred */}
        </div>
      );
    }

6. useDeferredValue WITH React.memo FOR MAXIMUM PERFORMANCE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  For useDeferredValue to actually defer work, the child component
  must be memoized with React.memo. Otherwise, it re-renders on every parent
  render regardless.

    const HeavyList = React.memo(function HeavyList({ query }) {
      // This only re-renders when deferredQuery actually changes
      const filtered = filterHugeList(query); // expensive
      return <ul>{filtered.map(item => <li key={item.id}>{item.name}</li>)}</ul>;
    });

    function App() {
      const [query, setQuery] = useState('');
      const deferredQuery = useDeferredValue(query);
      const isStale = query !== deferredQuery; // true while deferred

      return (
        <div>
          <input value={query} onChange={e => setQuery(e.target.value)} />
          <div style={{ opacity: isStale ? 0.5 : 1 }}>
            <HeavyList query={deferredQuery} />
          </div>
        </div>
      );
    }

    // Pattern: Show dimmed stale content while new content loads
    // This is a common UX pattern from useDeferredValue

7. useTransition vs useDeferredValue: WHEN TO USE WHICH
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  | Scenario                              | Use                |
  |---------------------------------------|--------------------|
  | You control the state update          | useTransition      |
  | You only receive a value (as a prop)  | useDeferredValue   |
  | Showing a "loading" spinner           | useTransition (isPending) |
  | Dimming stale content                 | useDeferredValue   |
  | Navigating between tabs               | useTransition      |
  | Filtering/searching with prop query   | useDeferredValue   |

  useTransition → you OWN the state setter
  useDeferredValue → you receive the value from outside

  Both achieve the same goal: keeping the UI responsive during expensive renders.

8. COMMON INTERVIEW QUESTIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: What problem do useTransition and useDeferredValue solve?
A: They allow expensive renders to be marked as non-urgent so React can
   keep the UI responsive. Without them, heavy re-renders block user input
   and make the UI feel janky.

Q: What is the difference between useTransition and useDeferredValue?
A: useTransition wraps a state setter you control. useDeferredValue creates
   a deferred copy of a value you receive. Both defer heavy renders.

Q: What is isPending in useTransition?
A: A boolean that is true while the deferred render is still in progress.
   Use it to show a loading spinner or dim stale content.

Q: Does useDeferredValue delay the value by a fixed time?
A: No. It's not a debounce or throttle. React defers it only when the
   current render is too slow to finish synchronously. The deferred render
   is interruptible and can be abandoned if a new update arrives.

Q: When should you use useTransition vs debouncing?
A: Debouncing adds a fixed delay (e.g., wait 300ms before updating). 
   useTransition has no fixed delay — it defers only when needed and 
   immediately commits if the render is fast. Prefer useTransition for
   in-memory filtering and debouncing for API calls.

Q: Can useTransition wrap async functions?
A: Not in React 18 (async inside startTransition is ignored). React 19 is
   introducing async transitions where startTransition can wrap async actions.
