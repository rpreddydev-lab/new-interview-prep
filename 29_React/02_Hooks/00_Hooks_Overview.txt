1. WHAT ARE HOOKS?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Hooks are JavaScript functions that let you "hook into" React features (state,
lifecycle, context, refs, etc.) from FUNCTIONAL components.

Introduced in React 16.8 (Feb 2019) — the biggest API change in React history.

Before Hooks:
  - Only class components could have state, lifecycle, and context
  - Functional components were "stateless" (pure display only)
  - Sharing stateful logic required HOCs or Render Props (wrapper hell)

After Hooks:
  - Functional components can do EVERYTHING class components can
  - Logic can be extracted into reusable "custom hooks"
  - No 'this' binding, no lifecycle confusion

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
2. WHY HOOKS WERE INTRODUCED
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Three main problems hooks solve:

  1. HARD TO REUSE STATEFUL LOGIC:
     - Class components: must use HOC or Render Props → wrapper hell
     - Hooks: extract into a custom hook, reuse in any component

  2. COMPLEX COMPONENTS BECOME HARD TO UNDERSTAND:
     - componentDidMount, componentDidUpdate can mix unrelated logic:
       // componentDidMount does ALL of: fetch data, add listener, start timer
       // componentWillUnmount needs to undo ALL of those — fragmented logic
     - useEffect lets you co-locate related logic together

  3. CLASSES ARE CONFUSING:
     - 'this' binding is tricky and error-prone
     - Class syntax doesn't minify/optimize as well as functions
     - Harder for machines to dead-code eliminate

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
3. BUILT-IN HOOKS REFERENCE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

STATE HOOKS:
  useState(initialState)        — local component state
  useReducer(reducer, init)     — complex state with actions (like mini Redux)

EFFECT HOOKS:
  useEffect(fn, deps)           — side effects (data fetch, subscriptions, DOM)
  useLayoutEffect(fn, deps)     — same but fires before browser paint (sync)
  useInsertionEffect(fn, deps)  — for CSS-in-JS libraries (before DOM mutations)

CONTEXT HOOKS:
  useContext(Context)           — subscribe to a React context

REF HOOKS:
  useRef(initialValue)          — mutable ref object; access DOM nodes; persist values
  useImperativeHandle(ref, fn)  — customize ref exposed to parent via forwardRef

PERFORMANCE HOOKS:
  useMemo(fn, deps)             — memoize expensive calculation result
  useCallback(fn, deps)         — memoize function reference

CONCURRENT HOOKS (React 18+):
  useTransition()               — non-urgent state updates with isPending flag
  useDeferredValue(value)       — deferred version of a value

UTILITY HOOKS:
  useId()                       — generate stable unique IDs (SSR-safe)
  useSyncExternalStore(sub,get) — subscribe to external store safely
  useDebugValue(value)          — label custom hooks in React DevTools

4. RULES OF HOOKS (covered in detail in 08_Rules_of_Hooks.txt)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

RULE 1: Only call Hooks at the TOP LEVEL
  - Never inside loops, conditions, or nested functions
  - Ensures hooks are always called in the same order every render

RULE 2: Only call Hooks from REACT FUNCTIONS
  - Not from regular JavaScript functions
  - Call from: functional components or custom hooks

5. CUSTOM HOOKS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

A Custom Hook is a JavaScript function whose name starts with 'use' and that
can call other hooks. It extracts and reuses stateful logic between components.

  // Custom hook: useLocalStorage
  function useLocalStorage(key, initialValue) {
    const [storedValue, setStoredValue] = useState(() => {
      try {
        const item = window.localStorage.getItem(key);
        return item ? JSON.parse(item) : initialValue;
      } catch {
        return initialValue;
      }
    });

    const setValue = (value) => {
      try {
        setStoredValue(value);
        window.localStorage.setItem(key, JSON.stringify(value));
      } catch (err) {
        console.error(err);
      }
    };

    return [storedValue, setValue];
  }

  // Usage in any component:
  function Settings() {
    const [theme, setTheme] = useLocalStorage('theme', 'light');
    const [lang, setLang] = useLocalStorage('language', 'en');
    ...
  }

  // Each component that uses the hook gets its OWN isolated state
  // (hooks don't share state, they share logic)

6. HOOKS vs LIFECYCLE METHOD MAPPING
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Class lifecycle          →   Hook equivalent
  ─────────────────────────────────────────────
  constructor              →   useState(initial), useReducer
  componentDidMount        →   useEffect(() => {}, [])
  componentDidUpdate       →   useEffect(() => {}, [dep])
  componentWillUnmount     →   useEffect(() => { return cleanup }, [])
  shouldComponentUpdate    →   React.memo, useMemo
  componentDidCatch        →   (no hook equivalent — class only)
  getDerivedStateFromError →   (no hook equivalent — class only)
  getSnapshotBeforeUpdate  →   (no hook equivalent — class only)

7. COMMON INTERVIEW QUESTIONS ON HOOKS OVERVIEW
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: What are React Hooks?
A: Functions that let functional components use React features like state,
   lifecycle, context, and refs. Introduced in React 16.8 to solve reusability
   and class complexity problems.

Q: What problems do Hooks solve?
A: 1. Hard to share stateful logic (hooks extract logic into reusable functions)
   2. Complex components with mixed concerns (useEffect groups related logic)
   3. Class confusion with 'this' and lifecycle methods

Q: Do Hooks replace class components?
A: They replace most use cases of class components, but not all. Error Boundaries
   still require class components. React will not remove class component support.

Q: What is a custom hook?
A: A function starting with 'use' that calls other hooks. It extracts stateful
   logic for reuse across components. Each component using the hook gets its
   own independent state (not shared).

Q: Can you call hooks in class components?
A: No. Hooks only work in functional components and other custom hooks.

Q: Can hooks share state between components?
A: No. Each component that calls a hook gets its OWN isolated state.
   To share state, use Context or a state management library.
