1. useLayoutEffect
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

useLayoutEffect has the SAME signature as useEffect but fires SYNCHRONOUSLY
after all DOM mutations and BEFORE the browser paints.

  useLayoutEffect(setup, deps?)

Timing comparison:
  Render → DOM Mutation → useLayoutEffect runs → Browser Paints → useEffect runs
                                ↑
                         synchronous, blocks paint

  useEffect  = fires AFTER browser paint (async, non-blocking)
  useLayoutEffect = fires BEFORE browser paint (sync, blocks paint)

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
2. WHEN TO USE useLayoutEffect
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Use useLayoutEffect when you need to READ the DOM and SYNCHRONOUSLY RE-RENDER
before the user sees the intermediate state (prevents visual flicker).

  USE CASE 1: Measuring DOM element dimensions
    function Tooltip({ children, text }) {
      const tooltipRef = useRef(null);
      const [position, setPosition] = useState({ top: 0, left: 0 });

      useLayoutEffect(() => {
        const rect = tooltipRef.current.getBoundingClientRect();
        // Immediately adjust position BEFORE paint (no flicker)
        setPosition({
          top: rect.bottom + window.scrollY,
          left: rect.left + window.scrollX,
        });
      }, []);

      return (
        <div>
          {children}
          <div ref={tooltipRef} style={{ position: 'absolute', ...position }}>
            {text}
          </div>
        </div>
      );
    }
    // If useEffect were used, the tooltip would briefly appear in the wrong position (flicker)

  USE CASE 2: Scroll position restoration
    function ScrollableList({ items }) {
      const containerRef = useRef(null);
      const prevScrollRef = useRef(0);

      useLayoutEffect(() => {
        // Restore scroll position after items change (DOM already updated)
        containerRef.current.scrollTop = prevScrollRef.current;
      }, [items]);

      return (
        <div
          ref={containerRef}
          onScroll={e => { prevScrollRef.current = e.target.scrollTop; }}
        >
          {items.map(i => <Item key={i.id} item={i} />)}
        </div>
      );
    }

  USE CASE 3: Synchronizing with third-party non-React libraries
    useLayoutEffect(() => {
      const chart = new ChartLibrary(canvasRef.current, data);
      return () => chart.destroy();
    }, [data]);
    // Chart renders into DOM before browser paints — no flicker

3. useEffect vs useLayoutEffect: COMPARISON
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  | Feature              | useEffect              | useLayoutEffect           |
  |----------------------|------------------------|---------------------------|
  | When it fires        | After browser paint    | Before browser paint      |
  | Blocking             | Non-blocking           | Blocks paint (synchronous)|
  | Use for              | Most effects           | DOM reads + sync updates  |
  | SSR support          | Yes                    | Warning (no DOM on server)|
  | Performance impact   | Minimal                | Can cause jank if slow    |
  | Equivalent to        | N/A (newer pattern)    | componentDidMount/Update  |

  DEFAULT CHOICE: useEffect (99% of cases)
  Switch to useLayoutEffect ONLY when you see visual flicker with useEffect.

4. useLayoutEffect AND SSR
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

React generates a warning when useLayoutEffect is used during SSR:
  "Warning: useLayoutEffect does nothing on the server because its effect
  cannot be encoded into the server renderer's output format."

  This is because there's no DOM on the server — useLayoutEffect is a DOM-only concept.

  Solutions:
  1. Use useEffect instead (if possible)
  2. Use a custom hook that uses useIsomorphicLayoutEffect:
     const useIsomorphicLayoutEffect =
       typeof window === 'undefined' ? useEffect : useLayoutEffect;

  3. Dynamically import the component (client-only):
     const DOMComponent = dynamic(() => import('./DOMComponent'), { ssr: false });

5. useInsertionEffect (React 18)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

useInsertionEffect fires synchronously BEFORE any DOM mutations. It's designed
ONLY for CSS-in-JS libraries to inject style tags at the correct time.

  Timing:
  useInsertionEffect → DOM Mutation → useLayoutEffect → Browser Paint → useEffect

  // Used by CSS-in-JS libraries (styled-components, Emotion internals):
  useInsertionEffect(() => {
    const styleSheet = document.createElement('style');
    styleSheet.textContent = `.btn { color: red; }`;
    document.head.appendChild(styleSheet);
    return () => styleSheet.remove();
  });

  DO NOT use useInsertionEffect in application code.
  It's an escape hatch for library authors dealing with style injection.

  Limitations:
  - Cannot read from DOM (DOM hasn't been mutated yet)
  - Cannot update state (would cause infinite loop)

7. COMMON INTERVIEW QUESTIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: What is the difference between useEffect and useLayoutEffect?
A: useEffect fires AFTER the browser paints (async, non-blocking). useLayoutEffect
   fires BEFORE the browser paints (sync, after DOM mutation). Use useLayoutEffect
   when you need to read DOM measurements and prevent visual flicker.

Q: When should you use useLayoutEffect?
A: When you need to measure DOM elements and synchronously update the UI before
   the user sees it — e.g., positioning tooltips, popovers, measuring sizes,
   scroll restoration. Otherwise, use useEffect.

Q: What problem does useLayoutEffect solve?
A: It prevents "visual flicker" — the brief flash of incorrect UI that would
   appear if you did DOM measurement + state update in useEffect (which fires
   after paint), causing the user to see the wrong state for one frame.

Q: Why does useLayoutEffect cause SSR warnings?
A: Server-side rendering has no DOM. useLayoutEffect is DOM-only, so it cannot
   run on the server. React warns and skips it. Use a conditional
   (useIsomorphicLayoutEffect) or switch to useEffect.

Q: What is useInsertionEffect?
A: A hook that fires before DOM mutations, designed for CSS-in-JS libraries
   to inject styles at the right time. Not for application-level code.
