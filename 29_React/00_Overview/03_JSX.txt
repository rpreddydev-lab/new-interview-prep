1. WHAT IS JSX?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

JSX (JavaScript XML) is a syntax extension for JavaScript that lets you write
HTML-like markup directly inside JavaScript code.

  const element = <h1 className="title">Hello, World!</h1>;

JSX is NOT valid JavaScript — browsers cannot run it directly.
It must be compiled/transpiled by tools like Babel into regular JavaScript.

JSX is OPTIONAL but strongly recommended because:
  - More intuitive and readable for UI code
  - Closer to HTML structure
  - Better tooling support (syntax highlighting, linting)
  - Prevents XSS attacks (React escapes values by default)

2. HOW JSX IS TRANSFORMED
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

BEFORE TRANSFORM (JSX):
  function App() {
    return (
      <div className="app">
        <h1>Hello</h1>
        <p>World</p>
      </div>
    );
  }

AFTER TRANSFORM (React 17+ new JSX transform — no React import needed):
  import { jsx as _jsx, jsxs as _jsxs } from 'react/jsx-runtime';

  function App() {
    return _jsxs('div', {
      className: 'app',
      children: [
        _jsx('h1', { children: 'Hello' }),
        _jsx('p', { children: 'World' })
      ]
    });
  }

AFTER TRANSFORM (React 16 and below — old transform):
  function App() {
    return React.createElement('div', { className: 'app' },
      React.createElement('h1', null, 'Hello'),
      React.createElement('p', null, 'World')
    );
  }
  // THIS is why you needed "import React from 'react'" at the top of every file

React 17 introduced the new JSX transform which automatically imports from
'react/jsx-runtime' — no manual React import needed.

3. JSX RULES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

RULE 1: Return a single root element
  // BAD — multiple root elements
  return (
    <h1>Title</h1>
    <p>Text</p>   // Error!
  );

  // GOOD — wrap in a parent element
  return (
    <div>
      <h1>Title</h1>
      <p>Text</p>
    </div>
  );

  // BETTER — use Fragment (no extra DOM node)
  return (
    <>
      <h1>Title</h1>
      <p>Text</p>
    </>
  );
  // Or: <React.Fragment> ... </React.Fragment>
  // Fragment with key: <React.Fragment key={id}> ... </React.Fragment>

RULE 2: Close all tags (including self-closing)
  <img src="photo.jpg" />   // Must self-close
  <input type="text" />
  <br />

RULE 3: camelCase most attributes (JSX maps to JS props)
  HTML attribute   →   JSX prop
  class            →   className
  for              →   htmlFor
  tabindex         →   tabIndex
  onclick          →   onClick
  style="color:red" →  style={{ color: 'red' }}
  maxlength        →   maxLength

RULE 4: Expressions go in curly braces {}
  const name = "Alice";
  return <h1>Hello, {name}</h1>;
  return <h1>Sum: {2 + 2}</h1>;
  return <img src={user.avatar} alt={user.name} />;

RULE 5: No statements inside JSX (only expressions)
  // BAD — if statement is not an expression
  return <div>{if (x) 'yes'}</div>;   // Error!

  // GOOD — ternary (expression)
  return <div>{x ? 'yes' : 'no'}</div>;

  // GOOD — logical AND
  return <div>{isLoggedIn && <UserPanel />}</div>;

  // GOOD — move to variable
  const content = x ? 'yes' : 'no';
  return <div>{content}</div>;

4. JSX EXPRESSIONS AND RENDERING
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

What CAN be rendered in JSX:
  - Strings: {'hello'}
  - Numbers: {42}
  - Arrays of JSX: {[<li>a</li>, <li>b</li>]}
  - Other JSX: {<span>nested</span>}
  - null, undefined, false (render nothing — useful for conditional rendering)

  // These three all render NOTHING:
  {null}
  {undefined}
  {false}

What CANNOT be rendered directly:
  - Objects: {myObj}  →  Error: Objects are not valid as React children
    (Exception: style prop takes an object, ref, etc.)
  - Functions: must be called or used as event handlers

  // To render an object's content, access its properties:
  {user.name}         // String property ✓
  {JSON.stringify(obj)} // Debug only ✓

5. CONDITIONAL RENDERING IN JSX
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

METHOD 1: Ternary operator
  {isLoggedIn ? <UserPanel /> : <LoginForm />}

METHOD 2: Logical AND (&&)
  {isLoggedIn && <UserPanel />}
  // GOTCHA: if isLoggedIn is 0 (falsy number), React renders "0"!
  // Always use boolean check:
  {count > 0 && <List />}   // Safe
  {!!count && <List />}     // Also safe (double negation)

METHOD 3: Nullish coalescing (??):
  {value ?? <DefaultComponent />}

METHOD 4: IIFE (immediately invoked function expression):
  {(() => {
    if (status === 'loading') return <Spinner />;
    if (status === 'error') return <Error />;
    return <Content />;
  })()}

METHOD 5: External variable:
  let content;
  if (status === 'loading') content = <Spinner />;
  else if (status === 'error') content = <Error />;
  else content = <Content />;
  return <div>{content}</div>;

6. JSX AND SECURITY (XSS PREVENTION)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

React AUTOMATICALLY escapes all values embedded in JSX.

  const userInput = '<script>alert("XSS")</script>';
  return <div>{userInput}</div>;
  // Renders as text: <script>alert("XSS")</script>  (escaped, not executed)

This prevents Cross-Site Scripting (XSS) attacks by default.

dangerouslySetInnerHTML (escape hatch — use carefully!):
  return <div dangerouslySetInnerHTML={{ __html: htmlString }} />;
  // The name is intentionally scary. Only use with sanitized HTML.
  // Use a library like DOMPurify to sanitize: DOMPurify.sanitize(htmlString)

7. JSX SPREAD PROPS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

You can spread an object as props:
  const buttonProps = { onClick: fn, disabled: false, className: 'btn' };
  return <button {...buttonProps}>Click me</button>;

  // Useful for forwarding props in wrapper components:
  function Button({ children, ...rest }) {
    return <button className="btn" {...rest}>{children}</button>;
  }

CAUTION: Avoid spreading unknown props to DOM elements — causes React warnings.
  // BAD: passes custom 'isActive' prop to <div> DOM element
  <div {...props} />  // if props = { isActive: true } → DOM warning

  // GOOD: destructure and omit non-DOM props
  function Wrapper({ isActive, className, ...domProps }) {
    return <div className={isActive ? 'active ' + className : className} {...domProps} />;
  }

8. FRAGMENTS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

React Fragments let you return multiple elements without adding a DOM node.

  // Short syntax (cannot accept key or other props)
  return (
    <>
      <td>Cell 1</td>
      <td>Cell 2</td>
    </>
  );

  // Long syntax (can accept key prop — needed in lists)
  return (
    <React.Fragment key={item.id}>
      <dt>{item.term}</dt>
      <dd>{item.definition}</dd>
    </React.Fragment>
  );

Use case: Rendering table rows without wrapping in an extra <div>:
  function TableRow({ data }) {
    return (
      <>
        <td>{data.name}</td>
        <td>{data.age}</td>
      </>
    );
  }

9. COMMON INTERVIEW QUESTIONS ON JSX
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: What is JSX?
A: JSX is a syntax extension for JavaScript that looks like HTML. It must be
   compiled by Babel into React.createElement() calls (or jsx() calls in React 17+).
   It's syntactic sugar that makes component code more readable.

Q: Why do we use className instead of class in JSX?
A: JSX compiles to JavaScript objects. 'class' is a reserved keyword in JS.
   React uses 'className' for the HTML class attribute to avoid the conflict.
   Similarly, 'for' becomes 'htmlFor'.

Q: What is the new JSX transform in React 17?
A: Before React 17, JSX compiled to React.createElement(), requiring
   "import React from 'react'" in every JSX file. React 17 introduced a new
   transform that imports from 'react/jsx-runtime' automatically, so you no
   longer need to import React to use JSX.

Q: Why must JSX have a single root element?
A: JSX compiles to a function call that returns ONE value. A function can only
   return one thing. Multiple root elements = multiple return values = syntax error.
   React Fragments solve this by wrapping without adding a DOM element.

Q: What are React Fragments and why use them?
A: Fragments (<> </> or <React.Fragment>) let you return multiple JSX elements
   without adding a wrapping DOM node. Useful for table rows, definition lists,
   or anywhere where an extra wrapper div would break semantic HTML.

Q: How does JSX prevent XSS attacks?
A: React escapes all embedded values in JSX by default. If a user injects
   <script>alert('XSS')</script>, React renders it as text, not HTML.
   dangerouslySetInnerHTML is the opt-in escape hatch for raw HTML injection.

Q: Can you use if/else in JSX?
A: Not directly — if/else are statements, not expressions. You can:
   1. Use ternary: {cond ? <A /> : <B />}
   2. Use logical AND: {cond && <A />}
   3. Compute in a variable before the return
   4. Use IIFE inside JSX (less readable)

Q: What is the difference between {} and {{}} in JSX?
A: Single {} is used for any JavaScript expression in JSX.
   Double {{}} is used for object literals — the outer {} is JSX expression
   embedding, the inner {} is the object literal:
     style={{ color: 'red', fontSize: 16 }}
   This is just a style prop that takes a JS object value.
