1. WHAT IS REACT?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

React is an open-source JavaScript LIBRARY (not a framework) developed by
Facebook (Meta) in 2013. It is used for building user interfaces, particularly
Single Page Applications (SPAs).

Key distinction:
  - Library: React handles only the VIEW layer. You choose your own routing,
    state management, HTTP clients, etc. (unlike Angular which is a full framework).
  - Framework: Angular, Vue (to some extent) are more opinionated and provide
    built-in solutions for routing, forms, HTTP, etc.

Core Philosophy:
  1. Component-Based Architecture – UI is broken into small, reusable pieces.
  2. Declarative UI – You describe WHAT the UI should look like for a given state.
     React handles HOW to update the DOM efficiently.
  3. Unidirectional Data Flow – Data flows from parent → child via props.
     Children communicate back via callbacks.
  4. Learn Once, Write Anywhere – React Native for mobile, React DOM for web,
     React Three Fiber for 3D, etc.

3. DECLARATIVE vs IMPERATIVE PROGRAMMING
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

IMPERATIVE (vanilla JS):
  const el = document.getElementById('title');
  el.textContent = 'Hello';
  el.style.color = 'red';
  // You manually describe every step (HOW)

DECLARATIVE (React):
  function Title({ text }) {
    return <h1 style={{ color: 'red' }}>{text}</h1>;
  }
  // You describe WHAT the UI looks like; React figures out HOW to make it happen

Benefits of declarative:
  - Easier to reason about
  - Less error-prone
  - React can optimize DOM updates internally

4. COMPONENT-BASED ARCHITECTURE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Everything in React is a component. Components are the building blocks of UI.

Types of Components:
  1. Functional Components – JavaScript functions that return JSX (preferred)
  2. Class Components – ES6 classes extending React.Component (legacy)

Composition example:
  App
  ├── Header
  │   └── NavBar
  ├── Main
  │   ├── Sidebar
  │   └── Content
  │       └── PostList
  │           └── PostCard (×N)
  └── Footer

Benefits:
  - Reusability: Write once, use many times
  - Maintainability: Each component has a single responsibility
  - Testability: Components can be tested in isolation
  - Separation of concerns

5. REACT'S CORE CONCEPTS (THE BIG PICTURE)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  JSX → Babel → React.createElement() → Virtual DOM → Reconciliation → Real DOM

  Step-by-step:
  1. You write JSX: <Button onClick={fn}>Click me</Button>
  2. Babel transpiles to: React.createElement(Button, { onClick: fn }, "Click me")
  3. React builds a Virtual DOM tree (plain JS objects)
  4. On state/prop change, React re-renders and creates a NEW virtual DOM
  5. React's diffing algorithm (Fiber) compares old vs new virtual DOM
  6. Only the actual changed parts are updated in the real DOM (reconciliation)

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
6. REACT RENDERING PIPELINE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Two phases:
  RENDER PHASE (pure, no side effects):
    - React calls your component function
    - Builds a new fiber tree (virtual DOM)
    - Diffs old tree vs new tree
    - Can be interrupted / paused (Concurrent Mode)

  COMMIT PHASE (has side effects):
    - React actually applies changes to the real DOM
    - Runs useLayoutEffect
    - Browser paints
    - Runs useEffect (cleanup + setup)
    - Cannot be interrupted

7. REACT VERSIONS TIMELINE (KEY MILESTONES)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  React 0.14 (2015): Split into react + react-dom packages
  React 16   (2017): Fiber architecture, Error Boundaries, Portals, Fragments
  React 16.3 (2018): New Context API, createRef, getDerivedStateFromProps
  React 16.6 (2018): React.memo, Suspense, lazy()
  React 16.8 (2019): HOOKS introduced (useState, useEffect, etc.) — GAME CHANGER
  React 17   (2020): No new features; new JSX transform (no React import needed)
  React 18   (2022): Concurrent Mode stable, automatic batching, useTransition,
                      useDeferredValue, useId, Suspense for data fetching,
                      startTransition, createRoot

9. HOW REACT HANDLES STATE AND RENDERS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  - State = mutable data that belongs to a component
  - When state changes, React re-renders the component and all its children
  - React batches multiple state updates together (React 18) for performance
  - Props = immutable data passed from parent to child
  - Parent re-rendering causes children to re-render (unless memoized)

  Triggers for re-render:
    1. setState / useState setter called
    2. Parent component re-renders
    3. Context value changes
    4. forceUpdate() (class components)

10. COMMON INTERVIEW QUESTIONS ON REACT OVERVIEW
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: What is React and how is it different from a framework?
A: React is a JavaScript library for building UI. It only handles the view layer.
   Unlike Angular (a full framework), React doesn't prescribe routing, forms,
   or HTTP handling — you compose these yourself.

Q: What are the main features of React?
A: Virtual DOM, Component-based architecture, Unidirectional data flow, JSX,
   Hooks, Concurrent Mode (React 18), Server Components.

Q: Is React a library or a framework?
A: Library. React solves one specific problem: rendering UI. A framework like
   Angular provides an opinionated, full solution.

Q: What is the difference between React and ReactDOM?
A: 'react' contains the core logic (components, hooks, createElement).
   'react-dom' contains the rendering layer for web browsers (ReactDOM.render,
   createPortal, etc.). This separation allows React to target other platforms
   (React Native, React TV, etc.) by swapping the renderer.

Q: Why is React popular?
A: Large ecosystem, backed by Meta, JSX is intuitive, functional + hooks model
   is clean, huge community, performance with Virtual DOM, flexibility,
   widely used in industry.

Q: What is a Single Page Application (SPA)?
A: An app that loads a single HTML page and dynamically updates the DOM as the
   user interacts. Page transitions don't trigger full page reloads.
   Benefits: faster navigation, better UX. Downsides: SEO challenges (mitigated
   by Next.js SSR/SSG), initial bundle size.

Q: What does "unidirectional data flow" mean?
A: Data flows in one direction: from parent to child via props. Children cannot
   directly modify parent state. To communicate upward, children call callbacks
   passed as props. This makes data flow predictable and easier to debug.

Q: What is the significance of React 16.8?
A: The introduction of Hooks, which allowed functional components to have state
   and lifecycle capabilities, effectively replacing the need for class
   components in most scenarios. This was the biggest API change in React history.
