1. WHAT IS AN ERROR BOUNDARY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

An Error Boundary is a React component that catches JavaScript errors anywhere
in its child component tree during rendering, in lifecycle methods, and in
constructors of child components.

Without Error Boundaries: An uncaught error during rendering crashes the
entire React application and shows a blank white screen.

With Error Boundaries: The error is caught, a fallback UI is shown for just
that subtree, and the rest of the app continues working.

  Only class components can be Error Boundaries.
  (React 19 will introduce useErrorBoundary hook.)

2. IMPLEMENTING AN ERROR BOUNDARY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  class ErrorBoundary extends React.Component {
    constructor(props) {
      super(props);
      this.state = { hasError: false, error: null, errorInfo: null };
    }

    // Called during render phase when a descendant throws
    // Returns state update — must be a static method
    static getDerivedStateFromError(error) {
      return { hasError: true, error };
    }

    // Called in commit phase — use for logging to an error service
    componentDidCatch(error, errorInfo) {
      // errorInfo.componentStack: the component tree trace
      logErrorToService(error, errorInfo.componentStack);
    }

    handleReset = () => {
      this.setState({ hasError: false, error: null, errorInfo: null });
    };

    render() {
      if (this.state.hasError) {
        return (
          <div role="alert">
            <h2>Something went wrong.</h2>
            <details>
              <summary>Error details</summary>
              <pre>{this.state.error?.toString()}</pre>
            </details>
            <button onClick={this.handleReset}>Try Again</button>
          </div>
        );
      }
      return this.props.children;
    }
  }

3. USAGE PATTERNS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  // Wrap the entire app (last resort — broad catch):
  <ErrorBoundary>
    <App />
  </ErrorBoundary>

  // Wrap individual routes (independent sections):
  <Routes>
    <Route path="/dashboard" element={
      <ErrorBoundary fallback={<DashboardError />}>
        <Dashboard />
      </ErrorBoundary>
    } />
  </Routes>

  // Wrap specific widgets (most granular):
  <Page>
    <Header />
    <ErrorBoundary fallback={<WidgetPlaceholder />}>
      <ChartWidget />          {/* error here doesn't crash Header or rest of Page */}
    </ErrorBoundary>
    <ErrorBoundary>
      <DataTable />
    </ErrorBoundary>
  </Page>

4. WHAT ERROR BOUNDARIES DO NOT CATCH
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Error boundaries ONLY catch errors during rendering.
  They do NOT catch:

  - Event handler errors (use regular try/catch)
    button.onClick = () => {
      try { doSomething(); }
      catch (e) { setError(e.message); }  // handle yourself
    };

  - Errors in useEffect (use try/catch inside useEffect)
    useEffect(() => {
      try { doSomethingRisky(); }
      catch (e) { setError(e); }
    }, []);

  - Async errors (Promises are not caught)
    // NOT caught by Error Boundary:
    const data = await fetch('/api/data');  // rejected promise

  - Errors in the error boundary itself
  - SSR errors

5. react-error-boundary LIBRARY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  The react-error-boundary library provides a declarative Error Boundary:
  npm install react-error-boundary

  import { ErrorBoundary } from 'react-error-boundary';

  function ErrorFallback({ error, resetErrorBoundary }) {
    return (
      <div>
        <p>Error: {error.message}</p>
        <button onClick={resetErrorBoundary}>Retry</button>
      </div>
    );
  }

  <ErrorBoundary
    FallbackComponent={ErrorFallback}
    onError={(error, info) => logToService(error, info)}
    onReset={() => { /* clean up state before retry */ }}
    resetKeys={[userId]}  // auto-reset when userId changes
  >
    <UserProfile />
  </ErrorBoundary>

6. COMMON INTERVIEW QUESTIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: What is an Error Boundary in React?
A: A class component that implements getDerivedStateFromError and/or
   componentDidCatch. It catches rendering errors in its subtree and shows
   a fallback UI instead of crashing the whole app.

Q: Why can't functional components be Error Boundaries?
A: Error Boundaries need class lifecycle methods (getDerivedStateFromError,
   componentDidCatch) that have no equivalent hooks yet. React 19 plans to
   introduce a hook-based Error Boundary API.

Q: What errors does an Error Boundary NOT catch?
A: Event handlers (use try/catch), async code/Promises, errors in useEffect,
   SSR errors, and errors thrown by the Error Boundary itself.

Q: What is the difference between getDerivedStateFromError and componentDidCatch?
A: getDerivedStateFromError runs during the render phase and is used to update
   state to show the fallback UI. componentDidCatch runs in the commit phase
   and is used for logging errors to an external service. Both receive the
   error object; only componentDidCatch receives the component stack trace.

Q: How would you allow users to retry after an error?
A: Add a "Try Again" button in the fallback UI that resets hasError state.
   The ErrorBoundary re-renders its children after the reset.
