Browser extension (Chrome, Firefox, Edge) that adds two panels to DevTools:

  COMPONENTS tab:
  - Browse the component tree like DOM inspector
  - Select a component to inspect its props, state, context, hooks
  - Edit props/state live in the browser
  - Highlight components that re-render (Settings → Highlight Updates)
  - Inspect which hook values are stored per component

  PROFILER tab:
  - Record a session of interactions
  - See which components rendered and how long each took
  - See what triggered each render (state change, parent render, context)
  - Flame chart and ranked chart views
  - "Why did this render?" for each component

2. PROFILING WORKFLOW
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Step-by-step to find a performance issue:
  1. Open DevTools → Profiler tab
  2. Click "Record"
  3. Perform the interaction that feels slow (type in input, click button)
  4. Click "Stop"
  5. Examine the flame chart:
     - Wide bars = long render time
     - Grey bars = component did not render in this commit
     - Colored bars = component rendered (color = relative time)
  6. Click a component → see "Why did this render?"
     Common reasons:
       - "Props changed" (which prop?)
       - "State changed" (which state setter?)
       - "Context changed"
       - "Hooks changed"
  7. Apply optimization (React.memo, useMemo, split context, etc.)
  8. Record again to verify improvement

3. <Profiler> API (PROGRAMMATIC)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

React provides a <Profiler> component for programmatic performance tracking.
Use it to send timing data to an analytics service in production.

  import { Profiler } from 'react';

  function onRenderCallback(
    id,           // the "id" prop of the Profiler tree that just committed
    phase,        // "mount" | "update" | "nested-update"
    actualDuration,   // time spent rendering this commit (ms)
    baseDuration,     // estimated time if no memoization
    startTime,        // when React started rendering this update
    commitTime,       // when React committed this update
    interactions      // Set of interactions for this update (deprecated in v18)
  ) {
    if (actualDuration > 16) {   // > 16ms drops below 60fps
      analytics.track('slow-render', { id, phase, actualDuration });
    }
  }

  function App() {
    return (
      <Profiler id="Dashboard" onRender={onRenderCallback}>
        <Dashboard />
      </Profiler>
    );
  }

  Notes:
  - <Profiler> adds a small overhead; disable in production for most apps
  - Can nest multiple Profilers for different subtrees
  - baseDuration estimates how long WITHOUT memoization (compare to actualDuration)

4. DIAGNOSING COMMON PERFORMANCE PROBLEMS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Problem: Many components re-render unnecessarily
  Symptom: Profiler shows lots of components rendering on one interaction
  Fix: React.memo, useCallback for function props, split Context

  Problem: One component takes too long to render
  Symptom: One wide bar in flame chart
  Fix: useMemo for expensive computations, virtualize long lists

  Problem: Context causes too many re-renders
  Symptom: All Context consumers re-render even when unrelated data changes
  Fix: Split context by update frequency, memoize value object

  Problem: Stale data / infinite loops
  Symptom: Continuous renders in Profiler, "Re-renders: 100" in DevTools
  Fix: Fix useEffect dependency array, stabilize object/function references

5. COMMON INTERVIEW QUESTIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: How would you identify and fix a performance problem in a React app?
A: First, use React DevTools Profiler to record a session. Look at the flame
   chart for wide bars (slow renders) and components that re-render
   unnecessarily. Use "Why did this render?" to find the cause. Then apply
   React.memo, useMemo, useCallback, or context splitting as appropriate.
   Re-profile to confirm the fix.

Q: What is the difference between actualDuration and baseDuration in the Profiler?
A: actualDuration is the real time React spent rendering that commit.
   baseDuration is the estimated time if no memoization existed. If
   actualDuration << baseDuration, memoization is working. If they're close,
   memoization is not helping.

Q: What does "highlight updates" in React DevTools show?
A: It flashes a colored highlight around components whenever they re-render.
   Useful for quickly spotting components that re-render more than expected
   without having to use the Profiler recording.

Q: Why should you profile in production mode?
A: React development mode includes extra checks, warnings, and debugging
   overhead that make it slower than production. Profile in production-like
   builds (npm run build) to get accurate real-world render times.
