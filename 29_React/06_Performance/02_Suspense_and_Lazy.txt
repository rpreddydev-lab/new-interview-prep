1. WHAT IS SUSPENSE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

<Suspense> is a React component that catches "suspending" components — those
that throw a Promise to signal they're not ready to render yet.

  When a component suspends:
  1. React walks up the tree to find the nearest <Suspense> boundary
  2. Renders the fallback UI instead of the suspended tree
  3. When the promise resolves, React retries rendering the suspended component
  4. If successful, the fallback is replaced by the actual content

  Two uses of Suspense:
  a) Code splitting with React.lazy()   ← stable since React 16.6
  b) Data fetching (Suspense for data)  ← React 18, with TanStack Query / RSC

2. React.lazy + Suspense
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  import { lazy, Suspense } from 'react';

  const HeavyDashboard = lazy(() => import('./Dashboard'));

  function App() {
    return (
      <Suspense fallback={<LoadingSpinner />}>
        <HeavyDashboard />
      </Suspense>
    );
  }

  What lazy() requires:
  - The import() must point to a module with a DEFAULT export
  - The function passed to lazy() must return a Promise that resolves to { default: Component }

  For named exports:
    const Chart = lazy(() =>
      import('./charts').then(m => ({ default: m.BarChart }))
    );

3. NESTED SUSPENSE BOUNDARIES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Multiple Suspense boundaries provide granular loading states.

  function App() {
    return (
      // Outer: shows page shell spinner while layout loads
      <Suspense fallback={<PageShell />}>
        <Layout>
          <Suspense fallback={<SidebarSkeleton />}>
            <Sidebar />          {/* loads independently */}
          </Suspense>

          <main>
            <Suspense fallback={<ContentSkeleton />}>
              <MainContent />    {/* loads independently */}
            </Suspense>
          </main>
        </Layout>
      </Suspense>
    );
  }
  // Sidebar and MainContent load in parallel, show skeletons independently.
  // If Sidebar loads first, it appears without waiting for MainContent.

4. SUSPENSE + ERROR BOUNDARY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  If a lazy component fails to load (network error), it throws.
  Wrap it in an Error Boundary to handle the failure gracefully.

  class ErrorBoundary extends React.Component {
    state = { hasError: false };

    static getDerivedStateFromError() {
      return { hasError: true };
    }

    render() {
      if (this.state.hasError) {
        return <button onClick={() => this.setState({ hasError: false })}>
          Retry
        </button>;
      }
      return this.props.children;
    }
  }

  function App() {
    return (
      <ErrorBoundary>
        <Suspense fallback={<Spinner />}>
          <HeavyDashboard />
        </Suspense>
      </ErrorBoundary>
    );
  }

5. SUSPENSE FOR DATA FETCHING (React 18+)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  React 18 officially supports Suspense for data fetching when the data
  layer supports it (TanStack Query with Suspense mode, React Server Components).

  // With TanStack Query (v5 Suspense mode):
  import { useSuspenseQuery } from '@tanstack/react-query';

  function UserProfile({ userId }) {
    const { data: user } = useSuspenseQuery({
      queryKey: ['user', userId],
      queryFn: () => fetchUser(userId),
    });
    // No isLoading check needed — if we got here, data is available
    return <div>{user.name}</div>;
  }

  // Parent wraps with Suspense:
  function App() {
    return (
      <Suspense fallback={<UserSkeleton />}>
        <UserProfile userId={123} />
      </Suspense>
    );
  }

  With React Server Components (Next.js App Router):
    async function UserProfile({ userId }) {
      const user = await fetchUser(userId);  // await at the top level!
      return <div>{user.name}</div>;
    }
    // Next.js automatically wraps in Suspense

6. COMMON INTERVIEW QUESTIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: How does Suspense work internally?
A: When a component "suspends", it throws a Promise. React catches it,
   walks up the tree to find the nearest <Suspense> boundary, renders the
   fallback, and attaches a .then() to the thrown Promise. When the Promise
   resolves, React retries rendering the suspended component.

Q: What is the difference between Suspense for lazy loading vs data fetching?
A: For lazy loading, React.lazy() throws a Promise that resolves when the
   JS chunk loads. For data fetching, the data library (TanStack Query,
   useSuspenseQuery) throws a Promise that resolves when the data arrives.
   The Suspense mechanism is the same — it only needs a thrown Promise.

Q: Where should you place Suspense boundaries?
A: As granularly as needed for your desired UX. A single top-level Suspense
   blocks the whole page. Multiple nested boundaries allow independent loading
   states (sidebar loads separately from main content). Wrap each async
   boundary you want to display a skeleton for.

Q: What happens if a lazy component fails to load?
A: It throws an Error, not a Promise. This is caught by an Error Boundary,
   not Suspense. Always wrap lazy components in both an ErrorBoundary and
   Suspense for resilient loading.
