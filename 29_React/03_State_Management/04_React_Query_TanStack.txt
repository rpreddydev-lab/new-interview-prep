1. WHAT IS TANSTACK QUERY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

TanStack Query (formerly React Query) is a library for async state management
in React — specifically built for server state (fetching, caching, syncing).

  "Server state" is fundamentally different from client state:
  - It lives remotely, you don't own it
  - It can become stale (server changes it)
  - It requires async operations to fetch and update
  - Multiple parts of the app may need the same data

  Core capabilities:
  - Automatic caching and deduplication
  - Background refetching (stale-while-revalidate)
  - Window focus refetching
  - Infinite scroll / pagination
  - Optimistic updates
  - Request cancellation
  - Offline support
  - DevTools

  Install:
    npm install @tanstack/react-query
    npm install @tanstack/react-query-devtools   # optional devtools

  // main.jsx
  import { QueryClient, QueryClientProvider } from '@tanstack/react-query';
  import { ReactQueryDevtools } from '@tanstack/react-query-devtools';

  const queryClient = new QueryClient({
    defaultOptions: {
      queries: {
        staleTime: 5 * 60 * 1000,     // 5 minutes before data is considered stale
        retry: 3,                      // retry failed requests 3 times
        refetchOnWindowFocus: true,    // refetch when user returns to tab
      },
    },
  });

  ReactDOM.createRoot(document.getElementById('root')).render(
    <QueryClientProvider client={queryClient}>
      <App />
      <ReactQueryDevtools initialIsOpen={false} />
    </QueryClientProvider>
  );

3. useQuery — READING DATA
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  import { useQuery } from '@tanstack/react-query';

  // Basic usage:
  function UserList() {
    const {
      data,         // fetched data (undefined until first success)
      isLoading,    // true on first load (no cached data yet)
      isFetching,   // true on any background refetch
      isError,      // true if last request failed
      error,        // error object
      refetch,      // manual trigger function
    } = useQuery({
      queryKey: ['users'],            // cache key (array)
      queryFn: () => fetch('/api/users').then(res => res.json()),
    });

    if (isLoading) return <Spinner />;
    if (isError) return <Error message={error.message} />;

    return (
      <ul>
        {data.map(user => <li key={user.id}>{user.name}</li>)}
      </ul>
    );
  }

  Query Key rules:
  - Must be a serializable array
  - ['users']               → fetches all users (stable key)
  - ['user', userId]        → per-user cache entry (changes when userId changes)
  - ['posts', { page, tag }]→ per-page/tag cache entry

  // Query with variable key:
  function UserDetail({ userId }) {
    const { data: user } = useQuery({
      queryKey: ['user', userId],
      queryFn: () => fetch(`/api/users/${userId}`).then(r => r.json()),
      enabled: !!userId,    // don't run if userId is null/undefined
    });
    return <div>{user?.name}</div>;
  }

4. useMutation — CREATING / UPDATING / DELETING
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  import { useMutation, useQueryClient } from '@tanstack/react-query';

  function AddUserForm() {
    const queryClient = useQueryClient();

    const mutation = useMutation({
      mutationFn: (newUser) =>
        fetch('/api/users', {
          method: 'POST',
          headers: { 'Content-Type': 'application/json' },
          body: JSON.stringify(newUser),
        }).then(r => r.json()),

      // Invalidate cache after mutation succeeds → triggers refetch
      onSuccess: () => {
        queryClient.invalidateQueries({ queryKey: ['users'] });
      },

      onError: (error) => {
        console.error('Failed to add user:', error);
      },
    });

    const handleSubmit = (e) => {
      e.preventDefault();
      mutation.mutate({ name: 'Alice', email: 'alice@example.com' });
    };

    return (
      <form onSubmit={handleSubmit}>
        <button type="submit" disabled={mutation.isPending}>
          {mutation.isPending ? 'Saving...' : 'Add User'}
        </button>
        {mutation.isError && <p>Error: {mutation.error.message}</p>}
        {mutation.isSuccess && <p>User added!</p>}
      </form>
    );
  }

5. OPTIMISTIC UPDATES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Update the UI immediately before the server confirms, then roll back if it fails.

  const mutation = useMutation({
    mutationFn: updateTodo,
    onMutate: async (updatedTodo) => {
      // 1. Cancel any in-flight refetches
      await queryClient.cancelQueries({ queryKey: ['todos'] });

      // 2. Snapshot the previous value
      const previousTodos = queryClient.getQueryData(['todos']);

      // 3. Optimistically update the cache
      queryClient.setQueryData(['todos'], (old) =>
        old.map(t => t.id === updatedTodo.id ? { ...t, ...updatedTodo } : t)
      );

      // 4. Return context for rollback
      return { previousTodos };
    },
    onError: (err, variables, context) => {
      // Rollback on error
      queryClient.setQueryData(['todos'], context.previousTodos);
    },
    onSettled: () => {
      // Always refetch to sync with server
      queryClient.invalidateQueries({ queryKey: ['todos'] });
    },
  });

6. STALE TIME vs CACHE TIME
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  staleTime (default: 0):
    How long fetched data is considered "fresh". During this period, React Query
    will NOT refetch on component mount or window focus. After staleTime expires,
    data is "stale" and will be refetched in the background on next access.

  gcTime / cacheTime (default: 5 minutes):
    How long inactive query data stays in cache before being garbage collected.
    Even if stale, inactive (no subscriber) data is kept in cache for this long
    so it can be instantly shown if the query becomes active again.

  Example:
    useQuery({
      queryKey: ['users'],
      queryFn: fetchUsers,
      staleTime: 60_000,    // treat as fresh for 1 minute
      gcTime: 10 * 60_000,  // keep in cache for 10 minutes after last use
    });

7. COMMON INTERVIEW QUESTIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: What is the difference between isLoading and isFetching in React Query?
A: isLoading is true only on the FIRST fetch when there is no cached data yet.
   isFetching is true whenever a request is in-flight, including background
   refetches when data is stale. Use isLoading for the initial skeleton/spinner
   and isFetching for a subtle loading indicator on subsequent updates.

Q: What does query invalidation do?
A: It marks cached queries as stale and triggers an immediate background
   refetch for any queries that are currently being observed. Used after
   mutations to sync UI with the server's latest state.

Q: What is staleTime?
A: The duration for which fetched data is considered fresh. During this window,
   React Query will NOT refetch even if the window regains focus or a new
   subscriber mounts. Default is 0 (immediately stale).

Q: What is the queryKey and why does it matter?
A: The queryKey is the cache key for a query. React Query uses it to deduplicate
   requests, cache results, and identify which queries to invalidate. If the key
   changes (e.g., different userId), React Query treats it as a new query.

Q: How do optimistic updates work in React Query?
A: In onMutate, you save the previous cache value, update the cache optimistically,
   and return the snapshot as context. In onError, you restore the snapshot. In
   onSettled, you invalidate to refetch the real server state.

Q: When should you use React Query vs Redux for async data?
A: Use React Query for server/remote data — it handles caching, deduplication,
   background refetching, and optimistic updates automatically. Use Redux for
   complex client-side application state that doesn't come from a server.
   Many modern apps use BOTH — React Query for server data, Zustand/Redux for
   client state.
