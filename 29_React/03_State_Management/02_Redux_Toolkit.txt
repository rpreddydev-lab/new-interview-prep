1. REDUX CORE CONCEPTS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Redux = predictable state container for JavaScript apps.

Core principles:
  1. Single source of truth  — one global store
  2. State is read-only      — only actions can change state
  3. Changes via pure functions — reducers are pure functions

Data flow (unidirectional):
  User Action → dispatch(action) → Reducer(state, action) → New State → UI re-renders

  Action: { type: 'counter/increment', payload: 5 }
  Reducer: (state, action) => { ...state, count: state.count + action.payload }
  Store: holds the current state, notifies subscribers on change
  Selector: reads a slice of state in a component

2. WHY REDUX TOOLKIT (RTK)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Old Redux problems:
  - Too much boilerplate (action types, action creators, reducers)
  - Switch statements in reducers
  - Manual Immer/immutability
  - Verbose async with redux-thunk

Redux Toolkit (RTK) solves all of this:
  - createSlice — generates action creators AND reducers together
  - createAsyncThunk — standardized async actions
  - configureStore — auto setup with redux-thunk and devtools
  - Uses Immer under the hood (write "mutating" code that's actually immutable)
  - RTK Query — data fetching & caching built in

  Install:
    npm install @reduxjs/toolkit react-redux

3. createSlice
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  // store/counterSlice.js
  import { createSlice } from '@reduxjs/toolkit';

  const counterSlice = createSlice({
    name: 'counter',             // prefix for action type strings
    initialState: { value: 0, status: 'idle' },
    reducers: {
      increment(state) {
        state.value += 1;        // Immer: looks "mutating" but creates new state
      },
      decrement(state) {
        state.value -= 1;
      },
      incrementByAmount(state, action) {
        state.value += action.payload;
      },
      reset(state) {
        state.value = 0;
      },
    },
  });

  // Auto-generated action creators:
  export const { increment, decrement, incrementByAmount, reset } = counterSlice.actions;

  // Reducer to be added to store:
  export default counterSlice.reducer;

  // Selector:
  export const selectCount = (state) => state.counter.value;

4. configureStore
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  // store/index.js
  import { configureStore } from '@reduxjs/toolkit';
  import counterReducer from './counterSlice';
  import cartReducer from './cartSlice';
  import authReducer from './authSlice';

  const store = configureStore({
    reducer: {
      counter: counterReducer,
      cart: cartReducer,
      auth: authReducer,
    },
    // middleware: auto-includes redux-thunk + serializability checks
    // devTools: auto-enabled in development
  });

  export type RootState = ReturnType<typeof store.getState>;
  export type AppDispatch = typeof store.dispatch;
  export default store;

  // Provide store to React:
  // main.jsx
  import { Provider } from 'react-redux';
  ReactDOM.createRoot(document.getElementById('root')).render(
    <Provider store={store}>
      <App />
    </Provider>
  );

5. USING STATE IN COMPONENTS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  import { useSelector, useDispatch } from 'react-redux';
  import { increment, decrement, incrementByAmount, selectCount } from './counterSlice';

  function Counter() {
    const count = useSelector(selectCount);    // subscribe to a slice of state
    const dispatch = useDispatch();            // stable function, won't change

    return (
      <div>
        <button onClick={() => dispatch(decrement())}>-</button>
        <span>{count}</span>
        <button onClick={() => dispatch(increment())}>+</button>
        <button onClick={() => dispatch(incrementByAmount(5))}>+5</button>
      </div>
    );
  }

  useSelector:
  - Re-renders component only when the selected value changes
  - Takes a selector function (state) => value
  - Uses strict equality (===) by default; use shallowEqual for objects

6. createAsyncThunk — ASYNC ACTIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  // store/usersSlice.js
  import { createSlice, createAsyncThunk } from '@reduxjs/toolkit';

  // Async thunk: auto-dispatches pending/fulfilled/rejected actions
  export const fetchUsers = createAsyncThunk(
    'users/fetchAll',                    // action type prefix
    async (_, { rejectWithValue }) => {
      try {
        const res = await fetch('/api/users');
        if (!res.ok) throw new Error('Server error');
        return await res.json();         // becomes action.payload on fulfilled
      } catch (err) {
        return rejectWithValue(err.message);  // becomes action.payload on rejected
      }
    }
  );

  const usersSlice = createSlice({
    name: 'users',
    initialState: {
      list: [],
      status: 'idle',    // 'idle' | 'loading' | 'succeeded' | 'failed'
      error: null,
    },
    reducers: {},
    extraReducers(builder) {
      builder
        .addCase(fetchUsers.pending, (state) => {
          state.status = 'loading';
        })
        .addCase(fetchUsers.fulfilled, (state, action) => {
          state.status = 'succeeded';
          state.list = action.payload;
        })
        .addCase(fetchUsers.rejected, (state, action) => {
          state.status = 'failed';
          state.error = action.payload;
        });
    },
  });

  export default usersSlice.reducer;
  export const selectUsers = state => state.users.list;
  export const selectUsersStatus = state => state.users.status;

  // Component usage:
  function UserList() {
    const dispatch = useDispatch();
    const users = useSelector(selectUsers);
    const status = useSelector(selectUsersStatus);

    useEffect(() => {
      if (status === 'idle') dispatch(fetchUsers());
    }, [status, dispatch]);

    if (status === 'loading') return <Spinner />;
    return <ul>{users.map(u => <li key={u.id}>{u.name}</li>)}</ul>;
  }

7. RTK QUERY (DATA FETCHING)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

RTK Query is a powerful data fetching & caching library included in RTK.
Similar to React Query but integrated with Redux store.

  // store/apiSlice.js
  import { createApi, fetchBaseQuery } from '@reduxjs/toolkit/query/react';

  export const postsApi = createApi({
    reducerPath: 'postsApi',
    baseQuery: fetchBaseQuery({ baseUrl: '/api' }),
    endpoints: (builder) => ({
      getPosts: builder.query({
        query: () => '/posts',
        providesTags: ['Post'],
      }),
      addPost: builder.mutation({
        query: (newPost) => ({
          url: '/posts',
          method: 'POST',
          body: newPost,
        }),
        invalidatesTags: ['Post'],  // refetches getPosts after adding
      }),
    }),
  });

  export const { useGetPostsQuery, useAddPostMutation } = postsApi;

  // Add to store:
  const store = configureStore({
    reducer: {
      [postsApi.reducerPath]: postsApi.reducer,
    },
    middleware: (getDefaultMiddleware) =>
      getDefaultMiddleware().concat(postsApi.middleware),
  });

  // Component:
  function PostList() {
    const { data: posts, isLoading, error } = useGetPostsQuery();
    const [addPost] = useAddPostMutation();

    if (isLoading) return <Spinner />;
    if (error) return <Error />;
    return (
      <div>
        {posts.map(p => <Post key={p.id} post={p} />)}
        <button onClick={() => addPost({ title: 'New Post' })}>Add</button>
      </div>
    );
  }

8. COMMON INTERVIEW QUESTIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: What problem does Redux solve?
A: Redux provides a single source of truth for complex application state,
   with predictable state updates via pure reducers and a unidirectional
   data flow. Great for apps with complex state logic shared across many
   components.

Q: What is Redux Toolkit and why was it created?
A: RTK is the official opinionated toolset for Redux. It reduces boilerplate
   by providing createSlice (auto action creators + reducers), configureStore
   (auto middleware), and createAsyncThunk (standardized async handling).

Q: What is Immer and how does RTK use it?
A: Immer is a library that lets you write state mutations that produce
   immutable updates. RTK uses Immer in createSlice reducers — you can
   write state.value += 1 and Immer creates a new state object with that change.

Q: What is the difference between useSelector and useDispatch?
A: useSelector subscribes a component to a slice of Redux state (re-renders
   when selected value changes). useDispatch returns the stable dispatch
   function used to send actions to the store.

Q: How does createAsyncThunk work?
A: It creates an async action that auto-dispatches three actions:
   prefix/pending, prefix/fulfilled, and prefix/rejected. You handle these
   in extraReducers to update loading/error/data state accordingly.

Q: When would you use RTK Query vs TanStack Query?
A: RTK Query is ideal if you're already using Redux (avoids another library,
   shares the Redux store). TanStack Query is framework-agnostic, easier to
   set up without Redux, and has a slightly more powerful caching/invalidation
   model. Both are excellent; the choice depends on whether you're using Redux.
