1. WHY LAZY LOAD ROUTES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

By default, React bundles all components into one JavaScript file. For large
apps, this results in a large initial download even if the user never visits
most pages.

  Problems with eager (non-lazy) loading:
  - Large initial JS bundle → slow Time to Interactive (TTI)
  - User downloads code for /admin page even if they're never an admin
  - Poor performance on slow connections / mobile

  Solution: Code splitting + lazy loading
  - Bundle each page into its own chunk
  - Load the chunk only when the user navigates to that route
  - React.lazy + Suspense makes this easy

2. BASIC LAZY ROUTE LOADING
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  import { lazy, Suspense } from 'react';
  import { Routes, Route } from 'react-router-dom';

  // lazy() returns a component that loads its module on first render
  const Home = lazy(() => import('./pages/Home'));
  const About = lazy(() => import('./pages/About'));
  const Dashboard = lazy(() => import('./pages/Dashboard'));
  const AdminPanel = lazy(() => import('./pages/AdminPanel'));

  function App() {
    return (
      // Suspense shows fallback while the lazy component loads
      <Suspense fallback={<div>Loading...</div>}>
        <Routes>
          <Route path="/" element={<Home />} />
          <Route path="/about" element={<About />} />
          <Route path="/dashboard" element={<Dashboard />} />
          <Route path="/admin" element={<AdminPanel />} />
        </Routes>
      </Suspense>
    );
  }

  How it works:
  1. Vite/Webpack sees the dynamic import() call
  2. It creates a separate JS chunk for each imported module
  3. When <Home /> first renders, React fetches the chunk asynchronously
  4. During loading, <Suspense fallback> renders
  5. Once loaded, React renders the actual component

3. SUSPENSE PLACEMENT STRATEGY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Option A: One Suspense at the top (simplest)
    <Suspense fallback={<FullPageSpinner />}>
      <Routes>...</Routes>
    </Suspense>

  Option B: Suspense per route (granular loading UIs)
    <Routes>
      <Route path="/" element={
        <Suspense fallback={<PageSkeleton />}>
          <Home />
        </Suspense>
      } />
      <Route path="/dashboard" element={
        <Suspense fallback={<DashboardSkeleton />}>
          <Dashboard />
        </Suspense>
      } />
    </Routes>

  Option C: Suspense in a Layout (common pattern)
    function Layout() {
      return (
        <div>
          <Navbar />    {/* Always loaded (not lazy) */}
          <Suspense fallback={<ContentSpinner />}>
            <Outlet />  {/* Only page content is lazy */}
          </Suspense>
          <Footer />    {/* Always loaded */}
        </div>
      );
    }

4. PREFETCHING ON HOVER
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Load a chunk before the user navigates, triggered on hover for faster UX.

  const Dashboard = lazy(() => import('./pages/Dashboard'));

  // Calling the import() outside of lazy() pre-fetches the chunk
  function prefetchDashboard() {
    import('./pages/Dashboard');  // triggers chunk download without rendering
  }

  function Navbar() {
    return (
      <nav>
        <Link to="/dashboard" onMouseEnter={prefetchDashboard}>
          Dashboard
        </Link>
      </nav>
    );
  }

5. NAMED EXPORTS WITH lazy()
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

React.lazy() requires a default export. For named exports, wrap them:

  // Dashboard.jsx — named export (common in component libraries)
  export function Dashboard() { ... }

  // lazy import trick for named exports:
  const Dashboard = lazy(() =>
    import('./pages/Dashboard').then(module => ({ default: module.Dashboard }))
  );

Q: What is code splitting and why does it matter?
A: Code splitting breaks the JavaScript bundle into smaller chunks that are
   loaded on demand. Without it, users download JS for pages they never visit.
   With it, only the code needed for the current page is loaded, reducing
   Time to Interactive significantly.

Q: How does React.lazy work?
A: React.lazy takes a function that returns a dynamic import(). On first render,
   it suspends (throws a Promise), triggering the nearest Suspense fallback.
   When the chunk loads, React re-renders and shows the actual component.

Q: What is the difference between static import and dynamic import()?
A: Static imports (import x from 'y') are resolved at build time and bundled
   together. Dynamic imports (import('y')) are resolved at runtime — the
   bundler creates a separate chunk, and the browser fetches it on demand.

Q: What is Suspense and how does it work with lazy?
A: Suspense catches "suspending" components (those awaiting async data/modules).
   It renders the fallback UI while waiting and switches to the actual component
   once the Promise resolves. React.lazy uses this mechanism for code splitting.

Q: When should you lazy load a route?
A: For any page that is not on the critical initial path. Admin pages, settings,
   rarely-visited pages. Don't lazy-load the landing page or common navigation
   targets — the loading flicker on first paint can hurt UX.
