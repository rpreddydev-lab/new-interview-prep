================================================================
  DML — DATA MANIPULATION LANGUAGE OVERVIEW
================================================================

  DML commands operate on the DATA in tables (not the structure).
  All DML is transactional — can be rolled back.

  Commands:
  SELECT    — read/query data
  INSERT    — add new rows
  UPDATE    — modify existing rows
  DELETE    — remove rows
  MERGE     — upsert (insert or update based on match)

================================================================
DML WITHIN TRANSACTIONS
================================================================

  BEGIN;
  UPDATE accounts SET balance = balance - 100 WHERE id = 1;
  UPDATE accounts SET balance = balance + 100 WHERE id = 2;
  COMMIT;   -- or ROLLBACK; to undo all

  All DML changes within a transaction are:
  - Visible to the current session immediately
  - NOT visible to other sessions until COMMIT (default isolation level)
  - Rolled back entirely if ROLLBACK or error

================================================================
SQL EXECUTION ORDER (LOGICAL)
================================================================

  For SELECT statements, logical processing order:

  1. FROM          -- identify source tables
  2. ON            -- join condition evaluation
  3. JOIN          -- combine tables
  4. WHERE         -- filter rows (before grouping)
  5. GROUP BY      -- aggregate rows
  6. HAVING        -- filter groups (after grouping)
  7. SELECT        -- pick columns, apply expressions
  8. DISTINCT      -- remove duplicates
  9. ORDER BY      -- sort
  10. LIMIT/OFFSET -- paginate

  Critical: aliases defined in SELECT are NOT available in WHERE.
            aliases ARE available in ORDER BY.

================================================================
KEY DML PATTERNS
================================================================

  INSERT from SELECT:       INSERT INTO t SELECT ... FROM source;
  Update with JOIN:         UPDATE t SET ... FROM other WHERE t.id = other.t_id;
  Delete with subquery:     DELETE FROM t WHERE id IN (SELECT id FROM ...);
  Conditional update:       UPDATE t SET col = CASE WHEN ... THEN ... END;
  Upsert:                   INSERT ... ON CONFLICT (key) DO UPDATE SET ...;

================================================================
COMMON INTERVIEW TOPICS IN DML
================================================================

  - Difference between WHERE and HAVING
  - NULL handling (IS NULL, COALESCE, NULLIF)
  - CASE expressions in SELECT and WHERE
  - Pagination (LIMIT + OFFSET vs keyset pagination)
  - UPSERT / MERGE patterns
  - Correlated vs uncorrelated subqueries
  - UPDATE performance on large tables
