================================================================
  LEFT / RIGHT / FULL OUTER JOIN
================================================================

  OUTER JOINs preserve non-matching rows by filling missing
  columns with NULL instead of excluding the row.

================================================================
LEFT OUTER JOIN (most common)
================================================================

  Returns ALL rows from the LEFT table, plus matching rows from RIGHT.
  Non-matching right side columns become NULL.

  SELECT c.id, c.name, o.id AS order_id, o.total
  FROM customers c
  LEFT JOIN orders o ON o.customer_id = c.id;

  Result:
  id  name     order_id  total
  --  -------  --------  -----
  1   Alice    101       50.00
  2   Bob      NULL      NULL    -- Bob has no orders
  3   Carol    103       30.00

================================================================
FIND RECORDS WITH NO MATCH (Anti-Join Pattern)
================================================================

  Customers with NO orders (using NULL check):
  SELECT c.id, c.name
  FROM customers c
  LEFT JOIN orders o ON o.customer_id = c.id
  WHERE o.id IS NULL;   -- NULL means no matching row was found

  This is one of the most frequent interview patterns.
  Equivalent with NOT EXISTS:
  SELECT c.id, c.name
  FROM customers c
  WHERE NOT EXISTS (
      SELECT 1 FROM orders o WHERE o.customer_id = c.id
  );

================================================================
ON vs WHERE IN LEFT JOIN -- CRITICAL DIFFERENCE
================================================================

  Filter in ON (applied before join -- keeps all left rows):
  SELECT c.name, o.id
  FROM customers c
  LEFT JOIN orders o ON o.customer_id = c.id AND o.status = 'SHIPPED';
  -- Returns all customers; only SHIPPED orders joined (NULL for others)

  Filter in WHERE (applied after join -- turns LEFT into INNER):
  SELECT c.name, o.id
  FROM customers c
  LEFT JOIN orders o ON o.customer_id = c.id
  WHERE o.status = 'SHIPPED';
  -- Excludes customers with no orders (o.status IS NULL filtered out)

  Rule: to filter the RIGHT table while keeping all LEFT rows,
  put the condition in ON, not WHERE.

================================================================
RIGHT OUTER JOIN
================================================================

  Returns ALL rows from the RIGHT table, plus matching from LEFT.
  Non-matching left side columns become NULL.

  SELECT c.id, c.name, o.id AS order_id
  FROM customers c
  RIGHT JOIN orders o ON o.customer_id = c.id;
  -- Returns all orders; customers with no matching order show NULL

  RIGHT JOIN is rarely needed -- you can always rewrite as LEFT JOIN
  by swapping table order. Most style guides prefer LEFT JOIN.

================================================================
FULL OUTER JOIN
================================================================

  Returns ALL rows from BOTH tables.
  Non-matching columns on either side become NULL.

  SELECT c.id, c.name, o.id AS order_id
  FROM customers c
  FULL OUTER JOIN orders o ON o.customer_id = c.id;

  Useful for:
  - Finding unmatched rows on BOTH sides in one query
  - Merging two datasets where both may have non-overlapping rows

  MySQL does NOT support FULL OUTER JOIN natively.
  Workaround: UNION of LEFT JOIN and RIGHT JOIN:

  SELECT c.id, c.name, o.id
  FROM customers c
  LEFT JOIN orders o ON o.customer_id = c.id

  UNION

  SELECT c.id, c.name, o.id
  FROM customers c
  RIGHT JOIN orders o ON o.customer_id = c.id;

================================================================
MULTIPLE OUTER JOINS
================================================================

  SELECT
      e.name AS employee,
      d.name AS department,
      m.name AS manager
  FROM employees e
  LEFT JOIN departments d  ON e.department_id = d.id
  LEFT JOIN employees   m  ON e.manager_id    = m.id;
  -- Employees without dept or manager still appear with NULLs

================================================================
INTERVIEW Q&A
================================================================

  Q: What is the difference between INNER JOIN and LEFT JOIN?
  A: INNER JOIN returns only matching rows from both tables.
     LEFT JOIN returns all rows from the left table; unmatched rows
     from the right are shown as NULL. LEFT JOIN is a superset.

  Q: How do you find rows in table A that have no matching row in B?
  A: LEFT JOIN and check WHERE b.id IS NULL (anti-join pattern).
     Or use NOT EXISTS subquery. Both are equivalent; NOT EXISTS
     is often clearer in intent.

  Q: Why does moving a filter from ON to WHERE in a LEFT JOIN change results?
  A: ON filters before join (non-matching left rows still kept, right = NULL).
     WHERE filters after join (rows where right is NULL are removed,
     effectively converting LEFT JOIN into INNER JOIN for that filter).

  Q: Does MySQL support FULL OUTER JOIN?
  A: No. Simulate with UNION of LEFT JOIN and RIGHT JOIN.
