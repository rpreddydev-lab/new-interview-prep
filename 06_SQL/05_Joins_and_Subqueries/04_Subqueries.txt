================================================================
  SUBQUERIES (NON-CORRELATED)
================================================================

  A subquery is a SELECT inside another SQL statement.
  Non-correlated subqueries run ONCE and are independent of the outer query.

================================================================
SUBQUERY TYPES BY RETURN SHAPE
================================================================

  Scalar      Returns single value (1 row, 1 column)
  Row         Returns single row (1 row, multiple columns)
  Table       Returns multiple rows (derived table / inline view)
  Correlated  References outer query column (see next file)

================================================================
SCALAR SUBQUERY IN SELECT
================================================================

  SELECT
      id,
      name,
      (SELECT AVG(price) FROM products) AS catalog_avg,
      price - (SELECT AVG(price) FROM products) AS vs_avg
  FROM products;

================================================================
SCALAR SUBQUERY IN WHERE
================================================================

  Orders placed by the highest-spending customer:
  SELECT *
  FROM orders
  WHERE customer_id = (
      SELECT customer_id
      FROM orders
      GROUP BY customer_id
      ORDER BY SUM(total) DESC
      LIMIT 1
  );

  Products priced above average:
  SELECT name, price
  FROM products
  WHERE price > (SELECT AVG(price) FROM products);

================================================================
SUBQUERY IN FROM (DERIVED TABLE / INLINE VIEW)
================================================================

  SELECT dept, avg_salary
  FROM (
      SELECT department_id AS dept, AVG(salary) AS avg_salary
      FROM employees
      GROUP BY department_id
  ) AS dept_avg
  WHERE avg_salary > 70000;

  The inner SELECT creates a temporary named result set ("dept_avg").
  PostgreSQL/MySQL require alias. SQL Server also needs alias.

================================================================
CTE (WITH CLAUSE) -- CLEANER ALTERNATIVE TO DERIVED TABLE
================================================================

  WITH dept_avg AS (
      SELECT department_id, AVG(salary) AS avg_salary
      FROM employees
      GROUP BY department_id
  )
  SELECT d.name, da.avg_salary
  FROM departments d
  INNER JOIN dept_avg da ON d.id = da.department_id
  WHERE da.avg_salary > 70000;

  CTEs are not a separate topic but complement subqueries.
  They are generally more readable for complex multi-step queries.

================================================================
SUBQUERY IN HAVING
================================================================

  Departments with more employees than the company average:
  SELECT department_id, COUNT(*) AS emp_count
  FROM employees
  GROUP BY department_id
  HAVING COUNT(*) > (SELECT AVG(cnt) FROM (
      SELECT COUNT(*) AS cnt
      FROM employees
      GROUP BY department_id
  ) sub);

================================================================
SUBQUERY vs JOIN
================================================================

  The following are often equivalent:

  Subquery form:
  SELECT name FROM customers
  WHERE id IN (SELECT DISTINCT customer_id FROM orders);

  JOIN form:
  SELECT DISTINCT c.name
  FROM customers c
  INNER JOIN orders o ON c.id = o.customer_id;

  Prefer JOINs when:
  - You need columns from both tables in SELECT
  - The optimizer handles JOIN statistics better

  Prefer subqueries when:
  - Existence check is the goal (see EXISTS file)
  - The inner result is a clean derived table
  - Readability is improved

================================================================
INTERVIEW Q&A
================================================================

  Q: What is a scalar subquery?
  A: A subquery that returns exactly one row and one column.
     Can be used wherever an expression is expected (SELECT list, WHERE).
     Throws a runtime error if it returns more than one row.

  Q: What is a derived table?
  A: A subquery in the FROM clause with an alias. It acts as a
     temporary in-memory table for the outer query.

  Q: When would you use a CTE vs a derived table?
  A: CTEs are more readable for multi-step queries, can be referenced
     multiple times in the outer query, and can be recursive.
     Derived tables are inline and only usable once.
     Performance is usually identical (optimizer often treats them same).
