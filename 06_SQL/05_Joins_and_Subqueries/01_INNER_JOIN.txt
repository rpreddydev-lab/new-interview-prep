================================================================
  INNER JOIN
================================================================

  Returns only rows where the join condition matches in BOTH tables.
  Rows without a match are excluded from results.

================================================================
SYNTAX
================================================================

  SELECT a.col1, b.col2
  FROM   table_a a
  INNER JOIN table_b b ON a.id = b.a_id;

  INNER is optional: JOIN = INNER JOIN.

================================================================
EXAMPLES
================================================================

  Orders with customer info:
  SELECT
      o.id        AS order_id,
      c.name      AS customer_name,
      o.total
  FROM orders o
  INNER JOIN customers c ON o.customer_id = c.id;

  Three-table join:
  SELECT
      o.id,
      c.name    AS customer,
      p.name    AS product,
      oi.qty,
      oi.price
  FROM orders o
  INNER JOIN customers    c  ON o.customer_id  = c.id
  INNER JOIN order_items  oi ON oi.order_id    = o.id
  INNER JOIN products     p  ON oi.product_id  = p.id
  WHERE o.status = 'DELIVERED';

================================================================
JOIN vs WHERE CLAUSE (OLD SYNTAX)
================================================================

  Modern (ANSI SQL-92 join syntax -- preferred):
  SELECT o.id, c.name
  FROM orders o
  INNER JOIN customers c ON o.customer_id = c.id;

  Old (theta join / implicit join):
  SELECT o.id, c.name
  FROM orders o, customers c
  WHERE o.customer_id = c.id;

  Both produce same results. Prefer explicit JOIN for clarity.
  Implicit syntax makes it easy to accidentally produce a CROSS JOIN
  if you forget a WHERE condition.

================================================================
JOINING ON MULTIPLE CONDITIONS
================================================================

  JOIN on composite key:
  SELECT * FROM order_items oi
  INNER JOIN shipment_items si
      ON oi.order_id   = si.order_id
     AND oi.product_id = si.product_id;

  JOIN with inequality (non-equi join):
  SELECT p.name, d.discount_pct
  FROM products p
  INNER JOIN discounts d
      ON p.price BETWEEN d.min_price AND d.max_price;

================================================================
NULL BEHAVIOR IN INNER JOIN
================================================================

  A NULL FK never matches any PK value.
  Rows with NULL customer_id in orders are EXCLUDED from INNER JOIN.

  customers:  id=1 alice, id=2 bob
  orders:     customer_id=1, customer_id=NULL

  INNER JOIN result: only the row with customer_id=1 (alice's order).
  The NULL customer_id row is silently dropped.

================================================================
PERFORMANCE TIPS
================================================================

  1. Always index the JOIN column (especially FK columns)
  2. Filter early -- put WHERE conditions that reduce rows before joins
  3. Join on same data types -- type mismatch prevents index use
  4. Use EXPLAIN / EXPLAIN ANALYZE to check if index is used

================================================================
INTERVIEW Q&A
================================================================

  Q: What does INNER JOIN return?
  A: Only rows where the join condition matches in both tables.
     Rows from either table that have no match are excluded.

  Q: How many rows can INNER JOIN return?
  A: Between 0 and (rows_in_A * rows_in_B) if join condition matches many.
     If joining on a FK-PK relationship, typically at most rows_in_A.

  Q: What is a Cartesian product?
  A: Every row of table A combined with every row of table B.
     Happens if you accidentally omit the ON condition in a JOIN
     or use CROSS JOIN explicitly. For A(100 rows) x B(200 rows) = 20,000 rows.

  Q: What is the difference between ON and WHERE in a JOIN?
  A: ON is the join condition (which rows to pair).
     WHERE filters the result after joining.
     In INNER JOIN they are equivalent for equality conditions,
     but they differ significantly in OUTER JOINs (see LEFT JOIN file).
