================================================================
  PARTITION BY AND ORDER BY IN WINDOW FUNCTIONS
================================================================

  PARTITION BY divides rows into groups (like GROUP BY, but no reduction).
  ORDER BY within OVER defines row order inside each partition.

================================================================
NO PARTITION (ENTIRE RESULT SET AS ONE WINDOW)
================================================================

  SELECT name, salary,
         AVG(salary) OVER () AS company_avg,
         salary / AVG(salary) OVER () AS ratio_to_avg
  FROM employees;
  -- OVER () with no PARTITION = entire result set is the window

================================================================
PARTITION BY ONLY (NO ORDER)
================================================================

  SELECT name, department_id, salary,
         AVG(salary) OVER (PARTITION BY department_id) AS dept_avg,
         COUNT(*)    OVER (PARTITION BY department_id) AS dept_size
  FROM employees;
  -- Each row shows summary for its department, all rows preserved

================================================================
PARTITION BY + ORDER BY
================================================================

  Running total within each department:
  SELECT
      name, department_id, salary,
      SUM(salary) OVER (
          PARTITION BY department_id
          ORDER BY hire_date
      ) AS running_salary_budget
  FROM employees;
  -- For each employee: sum of salaries for all earlier hires in same dept

================================================================
ORDER BY ONLY (NO PARTITION)
================================================================

  Cumulative total across entire dataset:
  SELECT
      date, revenue,
      SUM(revenue) OVER (ORDER BY date) AS cumulative_revenue
  FROM daily_sales;
  -- No PARTITION = one global window, ordered by date

================================================================
WINDOW NAMED DEFINITION
================================================================

  If same window spec is used multiple times, name it:
  SELECT
      name, salary,
      AVG(salary)  OVER dept_window AS dept_avg,
      MIN(salary)  OVER dept_window AS dept_min,
      MAX(salary)  OVER dept_window AS dept_max
  FROM employees
  WINDOW dept_window AS (PARTITION BY department_id ORDER BY salary);

================================================================
INTERACTION BETWEEN PARTITION AND FRAME
================================================================

  PARTITION BY resets the frame at each partition boundary.
  Within each partition, ORDER BY controls the row sequence.
  The frame specification (ROWS BETWEEN ...) defines the sliding window
  within the ordered partition.

  3-row moving average (1 prev + current + 1 next):
  SELECT
      date, revenue,
      AVG(revenue) OVER (
          ORDER BY date
          ROWS BETWEEN 1 PRECEDING AND 1 FOLLOWING
      ) AS three_day_avg
  FROM daily_sales;

================================================================
INTERVIEW Q&A
================================================================

  Q: What happens if you use PARTITION BY without ORDER BY?
  A: All rows in the partition are in the window for each row.
     Good for aggregate values like department average.
     Ranking functions (ROW_NUMBER, RANK) require ORDER BY.

  Q: What is the default window frame?
  A: When ORDER BY is present: RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW.
     When ORDER BY is absent: ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING.
     (i.e., the entire partition)

  Q: Can you have multiple different window specifications in one SELECT?
  A: Yes. Each window function can have its own OVER clause, or you can
     name reusable window specs with the WINDOW clause.
