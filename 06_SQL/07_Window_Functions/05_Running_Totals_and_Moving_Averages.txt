================================================================
  RUNNING TOTALS AND MOVING AVERAGES
================================================================

  These are among the most practical uses of window functions
  in real business reporting and data analysis.

================================================================
RUNNING TOTAL (CUMULATIVE SUM)
================================================================

  SELECT
      date,
      revenue,
      SUM(revenue) OVER (ORDER BY date) AS running_total
  FROM daily_sales;

  date        revenue  running_total
  ----------  -------  -------------
  2024-01-01  1000     1000
  2024-01-02  1200     2200
  2024-01-03  800      3000

  Per-customer cumulative spend:
  SELECT
      customer_id,
      order_date,
      total,
      SUM(total) OVER (
          PARTITION BY customer_id
          ORDER BY order_date
      ) AS cumulative_spend
  FROM orders;

================================================================
RUNNING COUNT (CUMULATIVE COUNT)
================================================================

  SELECT
      order_date,
      COUNT(*) OVER (ORDER BY order_date
                     ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS running_count
  FROM orders;

================================================================
MOVING AVERAGE
================================================================

  7-day moving average of daily revenue:
  SELECT
      date,
      revenue,
      AVG(revenue) OVER (
          ORDER BY date
          ROWS BETWEEN 6 PRECEDING AND CURRENT ROW
      ) AS seven_day_avg
  FROM daily_sales;

  ROWS BETWEEN 6 PRECEDING AND CURRENT ROW
  = current row + 6 previous rows = 7-row window

  Centered 3-day moving average:
  AVG(revenue) OVER (
      ORDER BY date
      ROWS BETWEEN 1 PRECEDING AND 1 FOLLOWING
  )

================================================================
RUNNING MAX/MIN (PEAK VALUE TO DATE)
================================================================

  All-time high revenue up to each day:
  SELECT
      date,
      revenue,
      MAX(revenue) OVER (ORDER BY date) AS revenue_peak_to_date
  FROM daily_sales;

================================================================
PERCENTAGE OF TOTAL
================================================================

  Each day's revenue as % of total:
  SELECT
      date,
      revenue,
      ROUND(revenue * 100.0 / SUM(revenue) OVER (), 2) AS pct_of_total
  FROM daily_sales;

  Each product's sales as % of its category total:
  SELECT
      product_id,
      category_id,
      revenue,
      ROUND(revenue * 100.0 / SUM(revenue) OVER (PARTITION BY category_id), 2)
          AS pct_of_category
  FROM product_sales;

================================================================
CUMULATIVE PERCENTAGE (PARETO ANALYSIS)
================================================================

  SELECT
      product,
      revenue,
      SUM(revenue) OVER (ORDER BY revenue DESC) AS cumulative_revenue,
      SUM(revenue) OVER (ORDER BY revenue DESC) * 100.0
          / SUM(revenue) OVER () AS cumulative_pct
  FROM product_sales
  ORDER BY revenue DESC;
  -- Identify which products make up 80% of revenue (Pareto principle)

================================================================
EXPONENTIAL MOVING AVERAGE (NOT NATIVE SQL)
================================================================

  SQL does not have a built-in EMA. Approximate with weighted window:
  (2 * current_day + 1 * yesterday) / 3
  or use application-side calculation for true EMA.

================================================================
INTERVIEW Q&A
================================================================

  Q: How do you compute a running total in SQL?
  A: SUM(col) OVER (ORDER BY date_col). The default frame
     (UNBOUNDED PRECEDING to CURRENT ROW) accumulates values up to each row.

  Q: How do you compute a 7-day moving average?
  A: AVG(col) OVER (ORDER BY date ROWS BETWEEN 6 PRECEDING AND CURRENT ROW).
     ROWS counts physical rows; RANGE counts by value range.

  Q: What is the difference between ROWS and RANGE in frame spec?
  A: ROWS counts physical rows (e.g., exactly 6 preceding rows).
     RANGE uses value comparison (all rows with same ORDER BY value as current row
     are included). RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW is default
     and includes all rows with same ORDER BY value as the current row.
