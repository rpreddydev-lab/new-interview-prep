================================================================
  GRANT
================================================================

  GRANT gives a privilege to a user or role.

================================================================
SYNTAX
================================================================

  GRANT privilege [, ...]
  ON object_type object_name
  TO { user | role | PUBLIC }
  [ WITH GRANT OPTION ];

  WITH GRANT OPTION: recipient can further grant this privilege to others.

================================================================
EXAMPLES
================================================================

  Grant SELECT on one table:
  GRANT SELECT ON orders TO alice;

  Grant multiple privileges:
  GRANT SELECT, INSERT, UPDATE ON orders TO app_user;

  Grant on all tables in schema:
  GRANT SELECT ON ALL TABLES IN SCHEMA public TO analyst;

  Grant on future tables too (PostgreSQL ALTER DEFAULT PRIVILEGES):
  ALTER DEFAULT PRIVILEGES IN SCHEMA public
      GRANT SELECT ON TABLES TO analyst;

  Grant column-level SELECT:
  GRANT SELECT (id, email) ON customers TO support_agent;

  Grant EXECUTE on function:
  GRANT EXECUTE ON FUNCTION calculate_tax(numeric) TO app_user;

  Grant with pass-through:
  GRANT SELECT ON orders TO alice WITH GRANT OPTION;
  -- alice can now GRANT SELECT ON orders to others

  Grant to PUBLIC (everyone -- use with extreme caution):
  GRANT SELECT ON lookup_codes TO PUBLIC;

================================================================
GRANT ROLE TO USER
================================================================

  CREATE ROLE read_only_role;
  GRANT SELECT ON ALL TABLES IN SCHEMA public TO read_only_role;
  GRANT read_only_role TO alice;
  GRANT read_only_role TO bob;
  -- Both alice and bob now have SELECT on all tables

================================================================
GRANT IN DIFFERENT DATABASES
================================================================

  PostgreSQL:
  GRANT SELECT ON ALL TABLES IN SCHEMA app TO app_user;
  -- Must also: ALTER DEFAULT PRIVILEGES for future tables

  MySQL:
  GRANT SELECT, INSERT, UPDATE, DELETE ON mydb.* TO 'app_user'@'localhost';
  GRANT ALL PRIVILEGES ON mydb.* TO 'admin'@'%' WITH GRANT OPTION;
  FLUSH PRIVILEGES;   -- needed after some GRANT changes

  SQL Server (T-SQL):
  GRANT SELECT ON dbo.orders TO alice;
  GRANT SELECT, INSERT ON SCHEMA::dbo TO app_user;

================================================================
INTERVIEW Q&A
================================================================

  Q: What does WITH GRANT OPTION do?
  A: Allows the grantee to pass on the privilege to other users.
     Be careful -- creates a chain of permissions hard to revoke fully.

  Q: How do you grant permissions to all current and future tables?
  A: In PostgreSQL: GRANT on ALL TABLES IN SCHEMA for current tables,
     plus ALTER DEFAULT PRIVILEGES for future tables.

  Q: What is GRANT to PUBLIC?
  A: Makes the privilege available to every user in the database.
     Use only for truly non-sensitive lookup/reference data.
