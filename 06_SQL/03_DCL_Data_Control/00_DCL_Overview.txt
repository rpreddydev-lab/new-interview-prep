================================================================
  DCL — DATA CONTROL LANGUAGE: OVERVIEW
================================================================

  DCL manages WHO can do WHAT on database objects.
  Two commands: GRANT (give permission) and REVOKE (take it away).

================================================================
WHY DCL MATTERS
================================================================

  In production, you never connect as the superuser (postgres, root).
  Each application, user, and service gets the minimum permissions
  required to do its job -- Principle of Least Privilege.

  DCL enforces:
  - Data confidentiality (salary data only for HR)
  - Data integrity (read-only apps cannot modify data)
  - Auditing (each user has their own credentials)

================================================================
DCL COMMANDS SUMMARY
================================================================

  Command   Action
  --------  --------------------------------------------------
  GRANT     Give one or more privileges to a user or role
  REVOKE    Remove previously granted privileges

  Not transactional in most databases (MySQL, Oracle).
  PostgreSQL: DCL IS transactional -- ROLLBACK reverses GRANT.

================================================================
PRIVILEGE TYPES
================================================================

  Object-Level Privileges:
  Privilege   Applies To           What It Allows
  ---------   ------------------   ---------------------------------
  SELECT      table, view, col     Read rows
  INSERT      table, col           Add rows
  UPDATE      table, col           Modify rows
  DELETE      table                Remove rows
  REFERENCES  table, col           Create foreign key referencing it
  TRIGGER     table                Create triggers
  EXECUTE     function, procedure  Call the function/procedure
  USAGE       schema, sequence     Access schema or use sequence

  Database/Schema-Level Privileges:
  CREATE      database, schema     Create objects within
  CONNECT     database             Connect to the database
  TEMPORARY   database             Create temp tables

  Table-Level vs Column-Level:
  GRANT SELECT ON orders TO analyst;              -- whole table
  GRANT SELECT (id, status) ON orders TO analyst; -- only two columns

================================================================
ROLES (GROUPING PRIVILEGES)
================================================================

  Create a role with privileges, then assign role to users.
  Users inherit the role's privileges.

  CREATE ROLE read_only;
  GRANT SELECT ON ALL TABLES IN SCHEMA public TO read_only;
  GRANT read_only TO alice;   -- alice now has SELECT on all tables

  This is how production databases are managed:
  - Define roles per responsibility (app_user, analyst, admin)
  - Grant roles to individual accounts
  - Revoking from a role instantly affects all role members

================================================================
LEAST PRIVILEGE IN SPRING APPS
================================================================

  Typical Spring Boot datasource user should have:
  GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA app TO app_user;
  GRANT USAGE, SELECT ON ALL SEQUENCES IN SCHEMA app TO app_user;
  -- app_user should NOT have CREATE, DROP, TRUNCATE

  A read-only reporting service:
  GRANT SELECT ON ALL TABLES IN SCHEMA app TO reporting_user;

================================================================
INTERVIEW Q&A
================================================================

  Q: What is DCL?
  A: Data Control Language -- GRANT and REVOKE. Controls which users
     and roles have which privileges on database objects.

  Q: What is the Principle of Least Privilege in a database context?
  A: Each account gets only the minimum permissions needed for its function.
     An app user gets SELECT/INSERT/UPDATE/DELETE; not CREATE or DROP.

  Q: Are GRANT and REVOKE transactional?
  A: In PostgreSQL yes. In MySQL and Oracle they auto-commit immediately.
