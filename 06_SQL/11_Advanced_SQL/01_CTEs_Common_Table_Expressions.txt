================================================================
  CTEs -- COMMON TABLE EXPRESSIONS
================================================================

  A CTE defines a named temporary result set within a query.
  It exists only for the duration of that query.
  Introduced with the WITH keyword.

================================================================
BASIC SYNTAX
================================================================

  WITH cte_name AS (
      SELECT ...
  )
  SELECT *
  FROM cte_name
  WHERE ...;

================================================================
SIMPLE EXAMPLE -- HIGH VALUE ORDERS
================================================================

  WITH high_value_orders AS (
      SELECT id, customer_id, total
      FROM orders
      WHERE total > 1000
  )
  SELECT c.name, hvo.total
  FROM high_value_orders hvo
  JOIN customers c ON c.id = hvo.customer_id;

================================================================
MULTIPLE CTEs
================================================================

  CTEs can be chained, separated by commas.
  Later CTEs can reference earlier ones.

  WITH
  monthly_revenue AS (
      SELECT
          DATE_TRUNC('month', order_date) AS month,
          SUM(total)                      AS revenue
      FROM orders
      GROUP BY 1
  ),
  revenue_with_growth AS (
      SELECT
          month,
          revenue,
          LAG(revenue) OVER (ORDER BY month) AS prev_revenue
      FROM monthly_revenue
  )
  SELECT
      month,
      revenue,
      ROUND(100.0 * (revenue - prev_revenue) / NULLIF(prev_revenue, 0), 2) AS growth_pct
  FROM revenue_with_growth
  ORDER BY month;

================================================================
CTE vs SUBQUERY
================================================================

  Feature             CTE                     Subquery (inline)
  ----------------    --------------------    --------------------
  Readability         High (named)            Lower (nested)
  Reuse in query      Can reference multiple  Define inline each use
  Recursive?          Yes (RECURSIVE)         No
  Performance (PG12+) Inlined by default      Same as CTE
  Debuggable          Easier to isolate       Harder

  Prefer CTEs when:
  - The same subquery is needed more than once
  - The logic has multiple logical steps
  - You want to make the query readable and testable in parts

================================================================
CTE vs TEMPORARY TABLE
================================================================

  Feature             CTE                     Temp Table
  ----------------    --------------------    --------------------
  Scope               Single query only       Session-wide
  Index support       No                      Yes
  Persists after?     No                      Until session ends
  Materialized?       Optional in PostgreSQL  Always materialized
  Use case            Multi-step single query Multi-query workflows

  Use a temp table when:
  - You need to query the same intermediate result set multiple times
    across different queries in a session
  - The result set is large and benefits from an index

================================================================
POSTGRESQL MATERIALIZATION CONTROL
================================================================

  PostgreSQL 12+ inlines CTEs by default (treats them as subqueries).
  To force materialization (evaluate once, reuse result):

  WITH expensive_cte AS MATERIALIZED (
      SELECT ... FROM big_table WHERE ...
  )
  SELECT * FROM expensive_cte WHERE col = 'A'
  UNION ALL
  SELECT * FROM expensive_cte WHERE col = 'B';

  Use MATERIALIZED when:
  - CTE is referenced multiple times and the planner re-evaluates it
  - The CTE contains side-effectful operations

  Use NOT MATERIALIZED (default now) when:
  - Query planner should optimize it inline

================================================================
WINDOW FUNCTIONS INSIDE CTEs
================================================================

  CTEs are the clean way to use window functions in WHERE clauses.
  (You cannot use a window function directly in WHERE or HAVING.)

  WITH ranked AS (
      SELECT
          employee_id,
          department_id,
          salary,
          RANK() OVER (PARTITION BY department_id ORDER BY salary DESC) AS rnk
      FROM employees
  )
  SELECT employee_id, department_id, salary
  FROM ranked
  WHERE rnk <= 3;

================================================================
INTERVIEW Q&A
================================================================

  Q: What is a CTE and when would you use it?
  A: A CTE is a named temporary result set defined with WITH.
     Use it to break complex queries into readable steps,
     to reuse a subquery multiple times, or to enable recursion.

  Q: What is the difference between CTE and a derived table (inline subquery)?
  A: Functionally similar. CTEs are named and can be referenced multiple times.
     Derived tables are anonymous and inline. CTEs are more readable.
     PostgreSQL 12+ inlines CTEs like subqueries by default.

  Q: Why can't you use a window function in a WHERE clause?
  A: Window functions are evaluated after WHERE and HAVING but before ORDER BY.
     Wrap the window function in a CTE or subquery, then filter in the outer query.
