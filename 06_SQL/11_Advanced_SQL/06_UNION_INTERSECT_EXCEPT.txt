================================================================
  UNION, INTERSECT, EXCEPT
================================================================

  Set operations combine results from two or more SELECT statements.
  Both queries must have:
  - The same number of columns
  - Compatible data types per column (in order)
  - Column names come from the FIRST query

================================================================
UNION
================================================================

  Combines results of two queries. Removes duplicates by default.

  SELECT name FROM customers_us
  UNION
  SELECT name FROM customers_eu;

  UNION ALL -- keeps duplicates (faster, no dedup overhead)

  SELECT name FROM customers_us
  UNION ALL
  SELECT name FROM customers_eu;

  When to use UNION ALL over UNION:
  - You know there are no duplicates
  - You don't need deduplication
  - Performance matters (UNION does a sort/hash to dedup)

================================================================
INTERSECT
================================================================

  Returns only rows that appear in BOTH queries.

  -- Customers who placed orders in BOTH Q1 and Q2:
  SELECT customer_id FROM orders WHERE order_date BETWEEN '2024-01-01' AND '2024-03-31'
  INTERSECT
  SELECT customer_id FROM orders WHERE order_date BETWEEN '2024-04-01' AND '2024-06-30';

  INTERSECT ALL -- keeps duplicates (very rarely used)

================================================================
EXCEPT (MINUS in Oracle/SQL Server)
================================================================

  Returns rows in the FIRST query that are NOT in the second.
  Direction matters!

  -- Customers who purchased in January but NOT in February:
  SELECT customer_id FROM orders WHERE DATE_TRUNC('month', order_date) = '2024-01-01'
  EXCEPT
  SELECT customer_id FROM orders WHERE DATE_TRUNC('month', order_date) = '2024-02-01';

  Oracle / SQL Server use MINUS instead of EXCEPT.

================================================================
ORDERING AND LIMITING RESULTS
================================================================

  ORDER BY and LIMIT apply to the COMBINED result, not per query.
  Place ORDER BY at the very end.

  SELECT name, email FROM active_users
  UNION ALL
  SELECT name, email FROM archived_users
  ORDER BY name
  LIMIT 100;

  You cannot use ORDER BY inside individual subqueries in a UNION
  (without wrapping them in derived tables).

================================================================
SET OPERATIONS vs JOIN
================================================================

  Use UNION when:
  - Combining rows from similar tables (e.g., sharded tables)
  - Producing all rows from multiple queries

  Use EXCEPT when:
  - Finding rows that exist in one set but not another
  - Alternative to NOT IN / NOT EXISTS (often cleaner for set-based logic)

  Use INTERSECT when:
  - Finding common rows between two query results

  Note: EXCEPT is equivalent to:
    LEFT JOIN ... WHERE right_table.id IS NULL
  and:
    NOT IN (subquery)
  But EXCEPT handles NULLs correctly.

  UNION           Yes            Yes           Yes            Yes
  UNION ALL       Yes            Yes           Yes            Yes

  INTERSECT ALL   Yes            MySQL 8.0.31+ No             No
  EXCEPT          Yes            MySQL 8.0.31+ Yes            MINUS
  EXCEPT ALL      Yes            MySQL 8.0.31+ No             MINUS ALL

================================================================
INTERVIEW Q&A
================================================================

  Q: What is the difference between UNION and UNION ALL?
  A: UNION removes duplicate rows (requires extra sort/hash step).
     UNION ALL keeps all rows including duplicates. Faster.
     Use UNION ALL when you know results are distinct or don't need dedup.

  Q: How does EXCEPT differ from NOT IN?
  A: Both find rows not present in another set.
     EXCEPT handles NULLs safely (NULLs are treated as equal for set comparison).
     NOT IN returns empty set if the subquery contains a NULL (dangerous trap).
     Prefer EXCEPT or NOT EXISTS for safety.

  Q: Can you use ORDER BY in each part of a UNION?
  A: No. ORDER BY only applies to the final combined result.
     You cannot ORDER BY inside individual UNION parts unless wrapped in
     a derived table (subquery).
