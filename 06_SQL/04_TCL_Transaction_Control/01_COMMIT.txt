================================================================
  COMMIT
================================================================

  COMMIT makes all changes in the current transaction permanent.
  After COMMIT, changes are visible to all other sessions.

================================================================
SYNTAX
================================================================

  BEGIN;
    -- DML statements
  COMMIT;

  Or (MySQL / SQL standard):
  START TRANSACTION;
    -- DML statements
  COMMIT;

================================================================
WHAT HAPPENS DURING COMMIT
================================================================

  1. All changes are written to the WAL (Write-Ahead Log) on disk
  2. Transaction ID is marked as committed in the transaction log
  3. Locks held by the transaction are released
  4. Changes become visible to other sessions

  Data is NOT necessarily flushed to the main data files immediately --
  the WAL ensures durability; data files are updated asynchronously.

================================================================
EXAMPLES
================================================================

  Simple money transfer:
  BEGIN;
    UPDATE accounts SET balance = balance - 100 WHERE id = 1;
    UPDATE accounts SET balance = balance + 100 WHERE id = 2;
  COMMIT;

  Order placement:
  BEGIN;
    INSERT INTO orders (customer_id, total) VALUES (42, 99.99);
    INSERT INTO order_items (order_id, product_id, qty) VALUES (LASTVAL(), 7, 1);
    UPDATE inventory SET quantity = quantity - 1 WHERE product_id = 7;
  COMMIT;

================================================================
COMMIT IN JDBC (Java)
================================================================

  Connection conn = dataSource.getConnection();
  conn.setAutoCommit(false);            // disable auto-commit
  try {
      PreparedStatement debit  = conn.prepareStatement("UPDATE ...");
      PreparedStatement credit = conn.prepareStatement("UPDATE ...");
      debit.executeUpdate();
      credit.executeUpdate();
      conn.commit();                    // success: commit
  } catch (SQLException e) {
      conn.rollback();                  // failure: roll back
      throw e;
  } finally {
      conn.setAutoCommit(true);
      conn.close();
  }

  With Spring @Transactional:
  @Transactional
  public void transfer(long from, long to, BigDecimal amount) {
      accountRepo.debit(from, amount);
      accountRepo.credit(to, amount);
      // Spring commits automatically on method return
      // Spring rolls back automatically on RuntimeException
  }

================================================================
COMMIT AND ISOLATION
================================================================

  After COMMIT, changes are visible to:
  - READ COMMITTED transactions: immediately
  - REPEATABLE READ / SERIALIZABLE: only to new transactions
    that started after the commit (existing snapshots unchanged)

================================================================
INTERVIEW Q&A
================================================================

  Q: When exactly does COMMIT make data visible?
  A: Immediately after COMMIT completes for READ COMMITTED sessions.
     For REPEATABLE READ sessions, only new transactions started
     after the commit will see the changes.

  Q: What is a 2-Phase Commit (2PC)?
  A: A distributed commit protocol for transactions spanning multiple
     databases. Phase 1: all participants prepare and vote.
     Phase 2: if all vote yes, coordinator sends commit; else rollback.
     Used in XA transactions (JTA in Java EE / Jakarta EE).

  Q: Does COMMIT release locks?
  A: Yes. Row locks, table locks, and advisory locks held by the
     transaction are released upon COMMIT or ROLLBACK.
