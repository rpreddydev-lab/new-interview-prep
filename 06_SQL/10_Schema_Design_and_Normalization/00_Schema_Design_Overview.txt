================================================================
  SCHEMA DESIGN AND NORMALIZATION: OVERVIEW
================================================================

  Schema design determines how data is organized into tables.
  Good schema = minimal redundancy, clear relationships, easy queries.
  Normalization is the formal process of eliminating redundancy.

================================================================
GOALS OF GOOD SCHEMA DESIGN
================================================================

  1. Eliminate data redundancy (same data in multiple places)
  2. Ensure referential integrity (FK constraints)
  3. Minimize update anomalies (change one fact in one place)
  4. Support efficient queries (right indexes, appropriate denormalization)
  5. Model the domain accurately (table = real-world entity or relationship)

================================================================
ANOMALIES THAT NORMALIZATION PREVENTS
================================================================

  Table: orders(id, customer_name, customer_email, product, price)

  Insertion anomaly:
  Can't add a customer without an order (customer data tied to order).

  Update anomaly:
  Customer changes email --> must update every row for that customer.
  Miss one row --> data inconsistency.

  Deletion anomaly:
  Delete last order of a customer --> lose all customer data.

  Solution: Separate customers table with PK, referenced via FK from orders.

================================================================
NORMALIZATION FORMS SUMMARY
================================================================

  1NF    Atomic values; no repeating groups; each row unique (has PK)
  2NF    1NF + no partial dependencies (non-key attr depends on FULL PK)
  3NF    2NF + no transitive dependencies (non-key doesn't depend on non-key)
  BCNF   3NF + every determinant is a candidate key
  4NF    BCNF + no multi-valued dependencies
  5NF    4NF + no join dependencies

  Most applications target 3NF or BCNF.
  Further normalization (4NF, 5NF) only when specific anomalies arise.

================================================================
NORMALIZATION VS DENORMALIZATION
================================================================

  Normalize for:          Denormalize for:
  - OLTP (transactional)  - OLAP (analytical)
  - Write-heavy           - Read-heavy reporting
  - Data integrity        - Query simplicity
  - Storage efficiency    - Performance (fewer joins)

================================================================
INTERVIEW Q&A
================================================================

  Q: What is database normalization?
  A: The process of structuring a relational schema to reduce redundancy
     and eliminate update/insert/delete anomalies by organizing data
     into separate tables with clear relationships.

  Q: What is the difference between OLTP and OLAP schemas?
  A: OLTP (transactional): normalized (3NF), optimized for INSERT/UPDATE/DELETE,
     many small queries.
     OLAP (analytical): denormalized (star/snowflake schema), optimized for
     large aggregate queries over historical data.
