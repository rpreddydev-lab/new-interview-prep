  BCNF AND 4NF
================================================================

================================================================
BOYCE-CODD NORMAL FORM (BCNF)
================================================================

  Also called 3.5NF.
  Stricter than 3NF.

  Rule: For every functional dependency X --> Y, X must be a
  SUPERKEY (a key or superset of a key) of the table.

  3NF allows a non-key to be a determinant if the dependent is part of a key.
  BCNF does NOT allow this.

  VIOLATION EXAMPLE:
  Table: course_teacher(student, course, teacher)
  PK = (student, course)

  Assumptions:
  - Each teacher teaches only one course: teacher --> course
  - A course can have multiple teachers
  - A student takes a course from one teacher

  Functional dependencies:
  (student, course) --> teacher  (full PK determines teacher)
  teacher --> course             (non-superkey determines a non-key attribute)

  teacher --> course violates BCNF because teacher is NOT a superkey.

  FIX (BCNF):
  teacher_course(teacher, course)
  student_teacher(student, teacher)

  Join these to get original info.

================================================================
BCNF vs 3NF TRADE-OFF
================================================================

  BCNF removes ALL partial/transitive/non-superkey FDs.
  BUT: BCNF decomposition may lose lossless join property for FDs.
  In practice, most schemas achieve BCNF or are in 3NF by design.

================================================================
FOURTH NORMAL FORM (4NF)
================================================================

  Rule: In addition to BCNF, a table must have no non-trivial
  MULTI-VALUED DEPENDENCIES unless the determinant is a superkey.

  Multi-valued dependency: A ->> B means "for each value of A,
  there is a set of values of B, independent of other columns."

  VIOLATION EXAMPLE:
  Table: person_skills_languages(person, skill, language)
  A person can have multiple skills and multiple languages,
  and skills and languages are independent of each other.

  person   skill      language
  -------  ---------  --------
  Alice    Java       English
  Alice    Java       French
  Alice    Python     English
  Alice    Python     French

  person ->> skill (independent set of skills)
  person ->> language (independent set of languages)
  Skills and languages are independent -- no relationship between them.

  Problem: If Alice adds a new language (Spanish), you must add a row
  for each skill she has (Java+Spanish, Python+Spanish).

  FIX (4NF):
  person_skills(person, skill)
  person_languages(person, language)

================================================================
WHEN TO APPLY BCNF / 4NF
================================================================

  3NF is sufficient for most OLTP applications.
  BCNF: when anomalies persist after 3NF, check for non-superkey FDs.
  4NF: when independent multi-valued attributes are stored in one table.

  Interview tip: Know 1NF, 2NF, 3NF deeply. BCNF and 4NF for theory questions.

================================================================
INTERVIEW Q&A
================================================================

  Q: What is the difference between 3NF and BCNF?
  A: 3NF allows non-key --> non-key dependencies if the dependent is
     part of a candidate key. BCNF requires EVERY determinant to be
     a superkey. BCNF is strictly stronger.

  Q: What is a multi-valued dependency?
  A: When one attribute independently determines a SET of values for
     another attribute, regardless of other attributes in the table.
     4NF eliminates independent multi-valued attributes by splitting them
     into separate tables.
