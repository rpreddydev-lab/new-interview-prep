================================================================
  SQL SUBLANGUAGES: DDL, DML, DCL, TCL, DQL
================================================================

  SQL is divided into sublanguages based on the type of operation:

  DDL  — Data Definition Language     (define structure)
  DML  — Data Manipulation Language   (insert/update/delete data)
  DQL  — Data Query Language          (select/read data)
  DCL  — Data Control Language        (permissions)
  TCL  — Transaction Control Language (transactions)

================================================================
DDL — DATA DEFINITION LANGUAGE
================================================================

  Purpose: Define and modify database structure (schema).
  DDL commands auto-commit (no transaction needed — in most RDBMS).

  Commands:
  CREATE    — create table, index, view, schema, database
  ALTER     — modify existing structure
  DROP      — delete structure and all its data
  TRUNCATE  — delete all rows; faster than DELETE (can't rollback in some DBs)
  RENAME    — rename table or column

  EXAMPLES:

  CREATE TABLE customers (
      id         BIGSERIAL PRIMARY KEY,          -- auto-increment, PK
      email      VARCHAR(255) NOT NULL UNIQUE,   -- must be unique
      name       VARCHAR(100) NOT NULL,
      created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
      is_active  BOOLEAN DEFAULT TRUE,
      CHECK (LENGTH(name) >= 2)                  -- check constraint
  );

  CREATE TABLE orders (
      id          BIGSERIAL PRIMARY KEY,
      customer_id BIGINT NOT NULL
                  REFERENCES customers(id) ON DELETE RESTRICT,  -- FK
      total       DECIMAL(10,2) NOT NULL CHECK (total >= 0),
      status      VARCHAR(20) DEFAULT 'PENDING',
      created_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP
  );

  CREATE INDEX idx_orders_customer ON orders(customer_id);
  CREATE INDEX idx_orders_status ON orders(status, created_at DESC);

  ALTER TABLE customers ADD COLUMN phone VARCHAR(20);
  ALTER TABLE customers ALTER COLUMN name TYPE VARCHAR(200);
  ALTER TABLE customers ADD CONSTRAINT chk_email CHECK (email LIKE '%@%');

  DROP TABLE orders;          -- deletes table AND all data
  DROP TABLE IF EXISTS temp;  -- safe — no error if not exists

  TRUNCATE TABLE audit_log;   -- fast delete all rows

================================================================
DML — DATA MANIPULATION LANGUAGE
================================================================

  Purpose: Insert, update, and delete rows.
  Can be wrapped in a transaction and rolled back.

  Commands:
  INSERT    — add new rows
  UPDATE    — modify existing rows
  DELETE    — remove rows
  MERGE     — upsert (insert or update) — ANSI SQL

  EXAMPLES:

  INSERT INTO customers (email, name) VALUES ('alice@example.com', 'Alice');

  INSERT INTO customers (email, name) VALUES
      ('bob@example.com', 'Bob'),
      ('carol@example.com', 'Carol');

  INSERT INTO orders (customer_id, total, status)
      SELECT id, 0, 'PENDING'
      FROM customers
      WHERE is_active = TRUE;  -- insert from SELECT

  UPDATE orders
  SET status = 'SHIPPED', shipped_at = CURRENT_TIMESTAMP
  WHERE id = 42;

  UPDATE orders
  SET total = total * 0.9
  WHERE customer_id IN (SELECT id FROM customers WHERE tier = 'VIP');

  DELETE FROM orders WHERE status = 'CANCELLED' AND created_at < NOW() - INTERVAL '90 days';

  UPSERT (PostgreSQL ON CONFLICT):
  INSERT INTO counters (key, count) VALUES ('visits', 1)
  ON CONFLICT (key) DO UPDATE SET count = counters.count + 1;

DQL — DATA QUERY LANGUAGE
================================================================

  Purpose: Retrieve data. SELECT is the foundation.
  Covered extensively in 05_Joins_and_Subqueries and other subfolders.

  SELECT [DISTINCT] column_list
  FROM   table
  [JOIN  other_table ON condition]
  [WHERE filter_condition]
  [GROUP BY grouping_columns]
  [HAVING group_filter]
  [ORDER BY sort_columns]
  [LIMIT n OFFSET m]

  ORDER OF EXECUTION (logical, not textual):
  1. FROM / JOIN
  2. WHERE
  3. GROUP BY
  4. HAVING
  5. SELECT (including DISTINCT)
  6. ORDER BY
  7. LIMIT / OFFSET

  This matters: you CANNOT use a SELECT alias in WHERE (not yet evaluated).
  You CAN use SELECT alias in ORDER BY (already evaluated).

================================================================
DCL — DATA CONTROL LANGUAGE
================================================================

  Purpose: Manage database user permissions and access.

  Commands:
  GRANT   — give privileges to a user/role
  REVOKE  — remove privileges from a user/role

  EXAMPLES:

  GRANT SELECT, INSERT ON orders TO app_user;
  GRANT ALL PRIVILEGES ON DATABASE myapp TO admin_user;
  GRANT USAGE ON SCHEMA public TO readonly_role;
  GRANT SELECT ON ALL TABLES IN SCHEMA public TO readonly_role;
  REVOKE DELETE ON orders FROM app_user;

  Best practice: principle of least privilege.
  Application user: SELECT, INSERT, UPDATE on specific tables.
  Admin user: all privileges on the database.
  Readonly user: SELECT only.

================================================================
TCL — TRANSACTION CONTROL LANGUAGE
================================================================

  Purpose: Manage transactions — group operations atomically.
  Full coverage in 09_Transactions_and_Concurrency.

  Commands:
  BEGIN / START TRANSACTION  — start a transaction
  COMMIT                     — persist all changes in the transaction
  ROLLBACK                   — undo all changes since BEGIN
  SAVEPOINT name             — create a named checkpoint
  ROLLBACK TO SAVEPOINT name — undo to a savepoint (partial rollback)
  RELEASE SAVEPOINT name     — remove a savepoint

  EXAMPLE:

  BEGIN;

  UPDATE accounts SET balance = balance - 500 WHERE id = 1;
  -- Check something
  SAVEPOINT before_credit;
  UPDATE accounts SET balance = balance + 500 WHERE id = 2;

  -- If something goes wrong with the credit:
  ROLLBACK TO SAVEPOINT before_credit;
  -- Or commit everything:
  COMMIT;

================================================================
SUBLANGUAGE QUICK REFERENCE
================================================================

  Sublanguage  Commands                           Auto-commits?
  -----------  ---------------------------------  -------------
  DDL          CREATE ALTER DROP TRUNCATE RENAME  YES (most DBs)
  DML          INSERT UPDATE DELETE MERGE         NO (transactional)
  DQL          SELECT                             N/A (read-only)
  DCL          GRANT REVOKE                       YES (most DBs)
  TCL          BEGIN COMMIT ROLLBACK SAVEPOINT    N/A (controls tx)

================================================================
INTERVIEW Q&A
================================================================

  Q: What are the SQL sublanguages?
  A: DDL (define structure), DML (manipulate data), DQL (query data),
     DCL (control permissions), TCL (manage transactions).

  Q: What is the difference between DELETE and TRUNCATE?
  A: DELETE: removes specific rows with WHERE; transactional (can rollback);
     fires triggers; leaves table structure intact.
     TRUNCATE: removes ALL rows; faster (no row-by-row logging); usually
     auto-commits and can't be rolled back; doesn't fire row triggers.

  Q: What is the logical order of SQL query execution?
  A: FROM → JOIN → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT.
     Important: aliases defined in SELECT are not available in WHERE.

  Q: What does GRANT do?
  A: Gives a user or role specified privileges on a database object.
     GRANT SELECT ON orders TO app_user gives read access.
     Follows principle of least privilege — grant only what's needed.

  Q: What is a SAVEPOINT?
  A: A named point within a transaction to which you can rollback partially.
     Allows partial rollback without abandoning the entire transaction.
