================================================================
  WHAT IS SQL?
================================================================

  SQL = Structured Query Language
  Pronounced: "S-Q-L" or "sequel" (both accepted)

  SQL is a domain-specific language for managing and querying data
  stored in Relational Database Management Systems (RDBMS).

  Standardized by ANSI/ISO. Every major RDBMS implements the standard
  plus vendor-specific extensions.

================================================================
HISTORY
================================================================

  1970  - E.F. Codd publishes relational model paper at IBM
  1974  - IBM develops SEQUEL (Structured English Query Language)
  1979  - Oracle (Relational Software) ships first commercial RDBMS
  1986  - SQL becomes ANSI standard
  1992  - SQL-92 (SQL2) — widely implemented
  1999  - SQL:1999 (SQL3) — adds recursion, triggers, types
  2003  - SQL:2003 — adds window functions, XML
  2011  - SQL:2011 — temporal data
  2016+ - SQL:2016 — JSON support

================================================================
WHAT SQL CAN DO
================================================================

  Define structure:   CREATE TABLE, ALTER TABLE, DROP TABLE
  Manipulate data:    INSERT, UPDATE, DELETE
  Query data:         SELECT, WHERE, JOIN, GROUP BY, ORDER BY
  Control access:     GRANT, REVOKE
  Manage transactions: COMMIT, ROLLBACK, SAVEPOINT

================================================================
HOW SQL WORKS — DECLARATIVE LANGUAGE
================================================================

  SQL is DECLARATIVE: you describe WHAT you want, not HOW to get it.

  Imperative (pseudocode):
  for each row in orders:
    if row.status == 'SHIPPED':
      add row.total to sum

  Declarative SQL:
  SELECT SUM(total) FROM orders WHERE status = 'SHIPPED';

  The database query optimizer decides HOW to execute — index scan,
  hash join, sort merge — you just describe the result you need.

================================================================
SQL vs PROCEDURAL LANGUAGES
================================================================

  SQL:
  - Set-based operations (works on sets of rows at once)
  - Declarative
  - Optimized internally by query planner
  - No explicit looping (cursors exist but are rarely optimal)

  Java/Python (procedural):
  - Row-by-row thinking
  - Explicit loops
  - You control execution strategy

  Good SQL uses set-based thinking:
  BAD: update each row in a cursor (slow)
  GOOD: UPDATE table SET col = value WHERE condition (set-based, fast)

================================================================
MAJOR RDBMS SYSTEMS
================================================================

  Open Source:
  PostgreSQL  — feature-rich, ACID, JSON, extensible, enterprise-grade
  MySQL       — widely deployed, simple, strong for web apps
  MariaDB     — MySQL fork, more open-source focused
  SQLite      — embedded, serverless, great for dev/testing

  Commercial:
  Oracle DB   — enterprise leader, PL/SQL
  SQL Server  — Microsoft, T-SQL, Windows/Azure integration
  DB2         — IBM
  Aurora      — AWS cloud-native MySQL/PostgreSQL compatible

  SQL Variants / Dialects:
  Standard SQL is the base; each vendor adds:
  - PostgreSQL: LATERAL joins, RETURNING clause, array ops
  - MySQL: LIMIT/OFFSET syntax, ENGINE clauses
  - SQL Server: TOP, T-SQL procedural extensions
  - Oracle: ROWNUM, PL/SQL, CONNECT BY (hierarchy)

================================================================
CORE SQL CONCEPTS
================================================================

  TABLE: 2-dimensional structure of rows and columns.
         Also called "relation" (relational model term).

  ROW (TUPLE/RECORD): One data entry in a table.

  COLUMN (ATTRIBUTE): A named, typed data field in a table.

  SCHEMA: A logical namespace grouping tables.
          CREATE SCHEMA myapp; → myapp.orders, myapp.users

  DATABASE: Container for schemas, managed by RDBMS.

  NULL: Absence of a value. NOT zero, NOT empty string.
        NULL ≠ NULL in comparisons (use IS NULL / IS NOT NULL).

  PRIMARY KEY: Unique identifier for a row. NOT NULL + UNIQUE.

  FOREIGN KEY: Column that references a primary key in another table.
               Enforces referential integrity.

  INDEX: B-tree or hash structure for fast lookups.

  VIEW: Named saved query, acts like a virtual table.

  STORED PROCEDURE: Reusable SQL block stored in the DB.

  TRIGGER: SQL that runs automatically on INSERT/UPDATE/DELETE.

================================================================
SQL IN MODERN APPLICATIONS
================================================================

  Java + SQL:
  JDBC → direct SQL via Connection/PreparedStatement
  JPA/Hibernate → object-relational mapping (SQL generated automatically)
  Spring Data JPA → interface-based repositories
  jOOQ → typesafe fluent SQL in Java
  MyBatis → SQL mapped to Java methods

  ORMs translate object graphs to tables.
  Raw SQL still needed for: complex reports, batch operations,
  performance-critical queries, migrations.

================================================================
INTERVIEW Q&A
================================================================

  Q: What is SQL?
  A: Structured Query Language. A declarative, set-based language
     for managing data in relational databases. Used to define structure,
     manipulate data, query data, and control access.

  Q: What is declarative programming in SQL context?
  A: You describe what result you want, not how to compute it.
     The database query optimizer decides the execution plan.

  Q: What is the difference between NULL and empty string?
  A: NULL means absence of a value — unknown. Empty string "" is a
     value (zero-length string). NULL ≠ NULL in comparisons — use IS NULL.

  Q: Name five major RDBMS systems.
  A: PostgreSQL, MySQL, Oracle, SQL Server, SQLite. Cloud: Amazon Aurora,
     Google Cloud Spanner, Azure SQL.
