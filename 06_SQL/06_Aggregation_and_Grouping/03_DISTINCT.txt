================================================================
  DISTINCT
================================================================

  DISTINCT removes duplicate rows from the result set.
  Operates on the combination of ALL selected columns.

================================================================
BASIC SYNTAX
================================================================

  SELECT DISTINCT status FROM orders;

  SELECT DISTINCT customer_id, status FROM orders;
  -- Distinct (customer_id, status) pairs, not just one column

================================================================
DISTINCT vs GROUP BY
================================================================

  These often produce the same result:
  SELECT DISTINCT customer_id FROM orders;
  SELECT customer_id FROM orders GROUP BY customer_id;

  GROUP BY is preferred when:
  - You also need aggregates
  - Semantic clarity (you ARE grouping, not just deduplicating)

  DISTINCT is preferred for:
  - Quick deduplication with no aggregation
  - Getting unique values from a list

================================================================
COUNT(DISTINCT col)
================================================================

  SELECT COUNT(DISTINCT customer_id) AS unique_customers FROM orders;
  -- How many different customers have placed orders?

  Combined:
  SELECT
      COUNT(*)                         AS total_orders,
      COUNT(DISTINCT customer_id)      AS unique_customers,
      COUNT(DISTINCT product_id)       AS unique_products_ordered
  FROM order_items;

================================================================
DISTINCT ON (PostgreSQL only)
================================================================

  DISTINCT ON selects one row per combination of the DISTINCT ON columns,
  keeping the first row in ORDER BY order:

  SELECT DISTINCT ON (customer_id)
      customer_id, id AS order_id, created_at
  FROM orders
  ORDER BY customer_id, created_at DESC;
  -- Gets the LATEST order for each customer

  This is the PostgreSQL idiomatic way to "get first/last row per group."
  Standard SQL alternative: use ROW_NUMBER() window function.

================================================================
DISTINCT WITH NULL
================================================================

  NULL is treated as a distinct value:
  SELECT DISTINCT phone FROM customers;
  -- If 3 rows have NULL phone, they appear as ONE NULL row in result

================================================================
PERFORMANCE NOTE
================================================================

  DISTINCT requires sorting or hashing to find duplicates -- can be slow.
  If you find yourself writing DISTINCT on many columns, it often signals
  a JOIN producing duplicates that should be addressed at the JOIN level.

  Instead of: SELECT DISTINCT c.name FROM customers c JOIN orders o ON ...
  Use:        SELECT c.name FROM customers c WHERE EXISTS (...)
  Or:         SELECT c.name FROM customers c INNER JOIN orders o ON ... GROUP BY c.name

================================================================
INTERVIEW Q&A
================================================================

  Q: What does SELECT DISTINCT do?
  A: Removes duplicate rows from the result. Works on the combination
     of ALL columns in the SELECT list.

  Q: What is DISTINCT ON in PostgreSQL?
  A: Selects one row per group defined by the DISTINCT ON columns,
     keeping the first row per ORDER BY order. Useful for
     "first/last record per group" queries.

  Q: Why might DISTINCT be a code smell?
  A: Unnecessary DISTINCT often indicates duplicate rows introduced
     by a JOIN (e.g., one-to-many join without proper filtering).
     Fix the JOIN logic instead of masking duplicates with DISTINCT.
