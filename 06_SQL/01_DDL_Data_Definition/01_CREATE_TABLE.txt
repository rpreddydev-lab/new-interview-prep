================================================================
  CREATE TABLE — DDL
================================================================

  Creates a new table with its columns, data types, and constraints.
  Foundation of all relational database design.

================================================================
SYNTAX
================================================================

  CREATE TABLE [IF NOT EXISTS] table_name (
      column_name  data_type  [column_constraints],
      ...
      [table_constraints]
  );

================================================================
COMMON DATA TYPES
================================================================

  Integers:
  SMALLINT          2 bytes  -32768 to 32767
  INTEGER / INT     4 bytes  ~-2 billion to 2 billion
  BIGINT            8 bytes  ~-9 quintillion to 9 quintillion
  SERIAL            4 bytes  auto-increment integer (PostgreSQL)
  BIGSERIAL         8 bytes  auto-increment bigint (PostgreSQL)

  Decimals:
  DECIMAL(p,s)      exact; p=total digits, s=decimal places  — use for money
  NUMERIC(p,s)      same as DECIMAL (SQL standard)
  FLOAT / REAL      approximate floating point — do NOT use for money
  DOUBLE PRECISION  8-byte float

  Strings:
  CHAR(n)           fixed length, padded with spaces
  VARCHAR(n)        variable length up to n characters
  TEXT              unlimited length string (PostgreSQL, MySQL)

  Date/Time:
  DATE              date only: 2024-01-15
  TIME              time only: 14:30:00
  TIMESTAMP         date and time: 2024-01-15 14:30:00
  TIMESTAMPTZ       timestamp with time zone (PostgreSQL)
  INTERVAL          duration: '2 hours', '3 days'

  Other:
  BOOLEAN           TRUE / FALSE / NULL
  UUID              universally unique identifier
  JSON / JSONB      JSON (JSONB is binary, indexable in PostgreSQL)
  BYTEA / BLOB      binary data

================================================================
COLUMN CONSTRAINTS
================================================================

  NOT NULL          value cannot be NULL
  UNIQUE            value must be unique in the column (allows NULL)
  PRIMARY KEY       NOT NULL + UNIQUE; one per table
  DEFAULT value     default value if not provided
  CHECK (expr)      custom validation rule
  REFERENCES        foreign key reference
  AUTO_INCREMENT    MySQL auto-increment (SERIAL in PostgreSQL)

================================================================
FULL EXAMPLE — E-COMMERCE SCHEMA
================================================================

  CREATE TABLE customers (
      id          BIGSERIAL PRIMARY KEY,
      email       VARCHAR(255) NOT NULL UNIQUE,
      name        VARCHAR(200) NOT NULL,
      phone       VARCHAR(20),
      created_at  TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
      updated_at  TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
      is_active   BOOLEAN NOT NULL DEFAULT TRUE,
      CONSTRAINT chk_name_length CHECK (LENGTH(name) >= 2)
  );

  CREATE TABLE categories (
      id   SERIAL PRIMARY KEY,
      name VARCHAR(100) NOT NULL UNIQUE,
      slug VARCHAR(100) NOT NULL UNIQUE
  );

  CREATE TABLE products (
      id          BIGSERIAL PRIMARY KEY,
      sku         VARCHAR(50) NOT NULL UNIQUE,
      name        VARCHAR(300) NOT NULL,
      description TEXT,
      price       DECIMAL(10,2) NOT NULL CHECK (price >= 0),
      stock_qty   INTEGER NOT NULL DEFAULT 0 CHECK (stock_qty >= 0),
      category_id INT REFERENCES categories(id) ON DELETE SET NULL,
      created_at  TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
  );

  CREATE TABLE orders (
      id          BIGSERIAL PRIMARY KEY,
      customer_id BIGINT NOT NULL REFERENCES customers(id) ON DELETE RESTRICT,
      total       DECIMAL(12,2) NOT NULL DEFAULT 0 CHECK (total >= 0),
      status      VARCHAR(20) NOT NULL DEFAULT 'PENDING',
      created_at  TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
      shipped_at  TIMESTAMP WITH TIME ZONE,
      CONSTRAINT chk_order_status
          CHECK (status IN ('PENDING','CONFIRMED','SHIPPED','DELIVERED','CANCELLED'))
  );

  CREATE TABLE order_items (
      order_id   BIGINT NOT NULL REFERENCES orders(id) ON DELETE CASCADE,
      product_id BIGINT NOT NULL REFERENCES products(id) ON DELETE RESTRICT,
      quantity   INTEGER NOT NULL CHECK (quantity > 0),
      unit_price DECIMAL(10,2) NOT NULL CHECK (unit_price >= 0),
      PRIMARY KEY (order_id, product_id)    -- composite PK
  );

  -- Indexes for performance
  CREATE INDEX idx_orders_customer ON orders(customer_id);
  CREATE INDEX idx_orders_status ON orders(status, created_at DESC);
  CREATE INDEX idx_products_category ON products(category_id);
  CREATE INDEX idx_products_sku ON products(sku);

================================================================
CREATE TABLE AS SELECT (CTAS)
================================================================

  Creates a new table from a query result — copies structure and data:

  CREATE TABLE orders_archive AS
  SELECT * FROM orders
  WHERE created_at < '2023-01-01';

  Note: CTAS copies data but NOT constraints (indexes, FKs, checks).
  Add constraints separately after creation.

================================================================
TEMPORARY TABLES
================================================================

  Exist only for the duration of a session or transaction:

  CREATE TEMP TABLE staging_data (
      raw_line TEXT,
      processed BOOLEAN DEFAULT FALSE
  );

  Uses: intermediate results in complex ETL, session-specific calculations.
  Auto-dropped when session ends.

================================================================
ON DELETE / ON UPDATE REFERENCE ACTIONS
================================================================

  Action          Behavior when referenced PK row is deleted/updated
  --------------  --------------------------------------------------------
  RESTRICT        Prevents deletion if child rows exist (default in many DBs)
  CASCADE         Deletes/updates child rows automatically
  SET NULL        Sets FK column to NULL in child rows
  SET DEFAULT     Sets FK column to its DEFAULT value in child rows
  NO ACTION       Like RESTRICT but checked at end of statement (deferred)

  Example:
  REFERENCES customers(id) ON DELETE CASCADE ON UPDATE CASCADE

================================================================
INTERVIEW Q&A
================================================================

  Q: What data type should you use for money in SQL?
  A: DECIMAL(precision, scale) or NUMERIC. Never FLOAT or DOUBLE
     — floating-point types are approximate and cause rounding errors
     with money calculations.

  Q: What is the difference between CHAR and VARCHAR?
  A: CHAR(n) is fixed length — always uses n bytes (padded with spaces).
     VARCHAR(n) is variable — uses only as much space as the actual data.
     Use CHAR for fixed-length codes (state codes "CA", "NY").
     Use VARCHAR for everything else.

  Q: When would you use a composite primary key?
  A: For junction tables in many-to-many relationships where the combination
     of two foreign keys is the natural unique identifier.
     Example: (student_id, course_id) for enrollments.

  Q: What is ON DELETE CASCADE?
  A: When a parent row is deleted, all child rows referencing it are
     automatically deleted too. Use when child rows are meaningless without
     the parent (order_items without the order).

  Q: What is BIGSERIAL?
  A: PostgreSQL shorthand for BIGINT + DEFAULT nextval(sequence).
     Creates an auto-incrementing 8-byte integer primary key.
     MySQL equivalent: BIGINT AUTO_INCREMENT.
