================================================================
COMPONENT-LEVEL LAZY LOADING
================================================================

WHAT IS COMPONENT LAZY LOADING?
─────────────────────────────────
Component lazy loading splits individual heavy components — not at route
boundaries, but at the component level. Heavy components that are:
  - Not visible on initial render (below fold, in modals, in tabs)
  - Only needed for specific user actions (export, settings, help)
  - Very large libraries (chart libraries, rich text editors, maps)
  - Feature flags (some users never see certain features)

WHEN TO USE COMPONENT LAZY LOADING:
  ✅ Rich text editors (Quill, TipTap, Draft.js — 300-500KB each)
  ✅ Chart libraries (Recharts, Chart.js, D3 — 200-500KB)
  ✅ Data grids (AG Grid, React Table with all features — 300KB+)
  ✅ Maps (Mapbox, Google Maps, Leaflet — 200-400KB)
  ✅ Image/video editors
  ✅ PDF viewers
  ✅ Modals and dialogs (content not needed until opened)
  ✅ Below-the-fold sections (comments, related content)
  ✅ Tab content (only the active tab needs to load)

PATTERN 1: BASIC LAZY COMPONENT

const RichTextEditor = lazy(() => import('./RichTextEditor'));

function BlogPostEditor() {
  const [isEditing, setIsEditing] = useState(false);
  
  return (
    <div>
      <button onClick={() => setIsEditing(true)}>Edit Post</button>

  );

PATTERN 3: INTERSECTION OBSERVER LAZY LOADING
───────────────────────────────────────────────
// Load component when it enters the viewport
import { useIntersectionObserver } from './hooks/useIntersectionObserver';

const CommentsSection = lazy(() => import('./CommentsSection'));
const RelatedProducts = lazy(() => import('./RelatedProducts'));

function ProductPage() {
  const { ref: commentsRef, isIntersecting: showComments } = 
    useIntersectionObserver({ threshold: 0.1, rootMargin: '200px' });
  
  return (
    <div>
      <ProductDetails />
      <ProductImages />
      
      {/* Load comments when they're about to enter viewport */}
      <div ref={commentsRef}>
        {showComments && (
          <Suspense fallback={<CommentsSkeleton />}>
            <CommentsSection />
          </Suspense>
        )}
      </div>
    </div>
  );
}

// useIntersectionObserver hook
function useIntersectionObserver(options = {}) {
  const [isIntersecting, setIsIntersecting] = useState(false);
  const ref = useRef(null);
  
  useEffect(() => {
    const observer = new IntersectionObserver(([entry]) => {
      if (entry.isIntersecting) {
        setIsIntersecting(true);
        observer.disconnect(); // Stop observing once loaded
      }
    }, options);
    
    if (ref.current) observer.observe(ref.current);
    return () => observer.disconnect();
  }, []);
  
  return { ref, isIntersecting };
}

PATTERN 4: LAZY TABS
──────────────────────
const Tab1Content = lazy(() => import('./Tab1Content'));
const Tab2Content = lazy(() => import('./Tab2Content'));
const Tab3Content = lazy(() => import('./Tab3Content'));

function TabbedInterface() {
  const [activeTab, setActiveTab] = useState('tab1');
  
  return (
    <div>
      <div role="tablist">
        <button onClick={() => setActiveTab('tab1')}>Analytics</button>
        <button onClick={() => setActiveTab('tab2')}>Settings</button>
        <button onClick={() => setActiveTab('tab3')}>Reports</button>
      </div>
      
      <Suspense fallback={<TabContentSkeleton />}>
        {activeTab === 'tab1' && <Tab1Content />}
        {activeTab === 'tab2' && <Tab2Content />}
        {activeTab === 'tab3' && <Tab3Content />}
      </Suspense>
    </div>
  );
}

// Tab1Content only loads when tab 1 is first clicked
// Once loaded, React caches it — re-clicking tab 1 is instant

PATTERN 5: PRELOAD ON HOVER (Hover Intent)
────────────────────────────────────────────
// Start loading when user shows intent (hover before click)
const importChartLib = () => import('./ChartLibrary');
const LazyChart = lazy(importChartLib); // Share the same import promise

function AnalyticsButton() {
  const [showChart, setShowChart] = useState(false);
  
  return (
    <>
      <button
        onMouseEnter={() => importChartLib()} // Prefetch on hover
        onClick={() => setShowChart(true)}    // Show on click
      >
        Show Analytics
      </button>
      
      {showChart && (
        <Suspense fallback={<ChartSkeleton />}>
          <LazyChart />  {/* Already loading/loaded due to hover prefetch */}
        </Suspense>
      )}
    </>
  );
}

PATTERN 6: IMAGE LAZY LOADING
───────────────────────────────
// Native HTML lazy loading (best for most cases)
<img src="large-image.jpg" loading="lazy" alt="Description" />

// React with IntersectionObserver (for custom behavior)
function LazyImage({ src, alt, width, height }) {
  const [isLoaded, setIsLoaded] = useState(false);
  const [isInView, setIsInView] = useState(false);
  const imgRef = useRef(null);
  
  useEffect(() => {
    const observer = new IntersectionObserver(([entry]) => {
      if (entry.isIntersecting) {
        setIsInView(true);
        observer.disconnect();
      }
    }, { rootMargin: '200px' });
    
    if (imgRef.current) observer.observe(imgRef.current);
    return () => observer.disconnect();
  }, []);
  
  return (
    <div
      ref={imgRef}
      style={{ width, height, backgroundColor: '#f0f0f0' }}
    >
      {isInView && (
        <img
          src={src}
          alt={alt}
          width={width}
          height={height}
          onLoad={() => setIsLoaded(true)}
          style={{ opacity: isLoaded ? 1 : 0, transition: 'opacity 0.3s' }}
        />
      )}
    </div>
  );
}

================================================================
LAZY LOADING THIRD-PARTY SCRIPTS
================================================================

PROBLEM WITH THIRD-PARTY SCRIPTS:
  - Analytics (Google Analytics, Mixpanel): runs on load, blocks main thread
  - Chat widgets (Intercom, Zendesk): large JS, rarely used immediately
  - Social sharing buttons: heavy SDK for simple sharing
  - A/B testing libraries: runs on load, can cause CLS

STRATEGIES:
────────────

1. DEFER ATTRIBUTE (simple, effective for most scripts)
  <script src="https://analytics.example.com/script.js" defer></script>
  // Executes after HTML parsing, before DOMContentLoaded

2. ASYNC ATTRIBUTE (for independent scripts)
  <script src="https://cdn.widget.com/widget.js" async></script>
  // Downloads in parallel, executes as soon as downloaded

3. LOAD AFTER USER INTERACTION (partytown approach)
  // Load chat widget only when user first interacts with page
  document.addEventListener('first-interaction', () => {
    const script = document.createElement('script');
    script.src = 'https://widget.example.com/widget.js';
    document.body.appendChild(script);
  }, { once: true });

  // Track first interaction
  ['click', 'keydown', 'scroll', 'touchstart'].forEach(event => {
    document.addEventListener(event, () => {
      document.dispatchEvent(new Event('first-interaction'));
    }, { once: true, passive: true });
  });

4. PARTYTOWN (Run third-party scripts in Web Worker)
  // Partytown moves third-party scripts off main thread
  // Google Analytics, Facebook Pixel, etc. run in Web Worker
  // Main thread stays free for user interactions
  
  // Next.js with Partytown:
  import Script from 'next/script';
  
  <Script
    src="https://www.googletagmanager.com/gtag/js"
    strategy="worker" // Runs via Partytown
  />

5. NEXT.JS SCRIPT LOADING STRATEGIES:
  // strategy="beforeInteractive": loads before page becomes interactive
  // strategy="afterInteractive": loads after page interactive (DEFAULT)
  // strategy="lazyOnload": loads during idle time
  // strategy="worker": loads in Web Worker via Partytown
  
  import Script from 'next/script';
  
  // Analytics: load after interactive
  <Script
    src="https://www.googletagmanager.com/gtag/js"
    strategy="afterInteractive"
  />
  
  // Chat widget: load lazily (rarely needed immediately)
  <Script
    src="https://widget.intercom.io/widget.js"
    strategy="lazyOnload"
  />

================================================================
COMPONENT LAZY LOADING BEST PRACTICES
================================================================

✅ ALWAYS DO:
  - Wrap lazy components in Error Boundary + Suspense
  - Provide meaningful fallback UI (skeleton, not spinner)
  - Match fallback dimensions to avoid CLS
  - Test loading experience with network throttling
  - Name chunks with webpackChunkName for debugging

✅ SMART OPTIMIZATIONS:
  - Prefetch on hover for interactions with clear intent
  - Use Intersection Observer for below-fold content
  - Combine with SSR for above-fold content (SSR + lazy for rest)
  - Share the import() promise between React.lazy() and prefetch

❌ COMMON MISTAKES:
  - Lazy loading above-the-fold content → delays initial render
  - Not providing fallback → flash of blank content
  - Over-splitting into tiny chunks → too many network requests
  - Lazy loading content that's needed immediately on every page
  - Forgetting Error Boundary → app crashes on network failure

PERFORMANCE RULE OF THUMB:
  Lazy load any component/library that is:
  → > 30KB gzipped AND
  → Not needed in the initial viewport AND
  → Not needed for initial interactivity

================================================================
INTERVIEW ANSWERS
================================================================

Q: What components are good candidates for lazy loading?
A: Components that meet these criteria: (1) Large size (>30KB gzipped);
   (2) Not visible in the initial viewport; (3) Only needed for specific
   user actions. Great candidates: modals (not open on load), chart
   libraries (conditional display), rich text editors (only for creators),
   below-fold sections (comments, related products), tab content (only
   active tab needed), third-party widgets (chat, maps).

Q: What is the Intersection Observer pattern for lazy loading?
A: IntersectionObserver watches whether an element enters the viewport.
   When a placeholder element (div) enters the viewport, I trigger the
   import() to start loading the component. I often add rootMargin: '200px'
   to start loading slightly before the element is visible, giving it time
   to load. This works great for long-scroll pages (product listings, news
   feeds) where content below the fold shouldn't be loaded immediately.

Q: How do you handle third-party script performance?
A: (1) Use defer/async attributes to prevent render-blocking; (2) Load
   after user interaction for chat widgets (they're not needed until user
   wants to chat); (3) Use Next.js Script component with strategy="lazyOnload"
   for idle-time loading; (4) Partytown moves third-party scripts to a Web
   Worker, completely removing them from the main thread; (5) Consider if
   the third-party is worth its performance cost at all.

Q: What's the difference between loading="lazy" on img and React lazy loading?
A: loading="lazy" is a native browser attribute for images (and iframes) that
   delays loading until the image is near the viewport. It requires no
   JavaScript and has great browser support. React.lazy() is for JavaScript
   modules/components — it defers the download of JS code until a component
   renders. They solve different problems: one for media, one for code.
   Both should be used in a well-optimized React app.

Q: How do you preload a lazy component before the user needs it?
A: I call the import() function directly (not wrapped in React.lazy) when I
   want to start loading — like on mouseenter of a button. Since webpack
   deduplicates module fetches, the same Promise is used whether triggered
   by the prefetch or by the actual React.lazy() render. Example: I call
   importChartModule() on hover of "Show Chart" button, and React.lazy()
   also uses importChartModule. When the user clicks, the chunk is already
   loaded or loading.
