================================================================
CORE WEB VITALS - COMPLETE OVERVIEW
================================================================

WHAT ARE CORE WEB VITALS?
──────────────────────────
Core Web Vitals (CWV) are a subset of Web Vitals — Google's initiative to
provide unified signals for measuring web page quality as experienced by
real users. They are the key signals for measuring the user experience of
loading, interactivity, and visual stability.

Since June 2021, Core Web Vitals are part of Google's Page Experience
ranking signals. They influence search ranking.

THE THREE CORE WEB VITALS:
  1. LCP (Largest Contentful Paint) — Loading
  2. INP (Interaction to Next Paint) — Interactivity [replaced FID in March 2024]
  3. CLS (Cumulative Layout Shift) — Visual Stability

WHY THESE THREE?
  Google chose metrics that:
  - Reflect real user experience (not technical internals)
  - Can be measured in the field (real browsers, real users)
  - Are actionable (developers can actually improve them)
  - Map to distinct aspects of the user journey

================================================================
METRIC THRESHOLDS
================================================================

┌─────────────────────┬──────────────┬────────────────┬──────────────┐
│ Metric              │ Good         │ Needs Improve  │ Poor         │
├─────────────────────┼──────────────┼────────────────┼──────────────┤
│ LCP                 │ ≤ 2.5s       │ 2.5s – 4.0s    │ > 4.0s       │
│ INP                 │ ≤ 200ms      │ 200ms – 500ms  │ > 500ms      │
│ CLS                 │ ≤ 0.1        │ 0.1 – 0.25     │ > 0.25       │
└─────────────────────┴──────────────┴────────────────┴──────────────┘

Measurement rule: 75th percentile across all page visits
"To score 'Good', 75% of your page visits must meet the threshold."

================================================================
THE USER JOURNEY AND CWV MAPPING
================================================================

User Experience Timeline:
  ┌────────┬──────────┬──────────────────────────────────────────────┐
  │ 0ms    │ Navigate │ User clicks link / types URL                  │
  │ 200ms  │ TTFB     │ Server sends first byte                       │
  │ 1.2s   │ FCP      │ First text/image visible                      │
  │ 2.5s   │ LCP ✓   │ Main content loaded (LCP element painted)     │
  │ 3s     │ TTI      │ Page becomes interactive                      │
  │ ...    │ INP ✓   │ User interacts; measures responsiveness       │
  │ ...    │ CLS ✓   │ Layout stability throughout page life         │
  └────────┴──────────┴──────────────────────────────────────────────┘

================================================================
HOW CWV AFFECTS SEO
================================================================

PAGE EXPERIENCE RANKING:
  - CWV are a "tiebreaker" in search ranking
  - Great content + poor CWV loses to great content + good CWV
  - The signal is not overwhelming but measurable (especially on mobile)

GOOGLE SEARCH CONSOLE:
  - Shows Core Web Vitals report
  - Groups URLs into "Good", "Needs Improvement", "Poor"
  - Based on CrUX data (real users, P75)
  - Lags 28 days (data is 28-day rolling average)

CrUX (Chrome User Experience Report):
  - Dataset of CWV metrics from real Chrome users
  - Requires >= 1000 page visits in 28 days to appear
  - Available in Search Console, PageSpeed Insights, CrUX API

================================================================
MEASURING CORE WEB VITALS
================================================================

FIELD MEASUREMENT:
  - Google Search Console → Core Web Vitals report
  - PageSpeed Insights → shows both lab + CrUX field data
  - CrUX API → programmatic access to P75 field data
  - web-vitals JavaScript library → in-browser measurement

LAB MEASUREMENT:
  - Lighthouse (simulates conditions, good for development)
  - Chrome DevTools Performance panel
  - WebPageTest

NOTE: LCP and CLS are measured differently in lab vs field:
  - Lab: single page load, controlled environment
  - Field: averaged across all real user visits at P75
  CLS especially can differ — field includes user interactions

================================================================
WEB-VITALS LIBRARY IMPLEMENTATION
================================================================

// measure all CWVs and report to analytics
import { onLCP, onINP, onCLS, onFCP, onTTFB } from 'web-vitals';

function reportMetric(metric) {
  console.log(metric);
  // metric.name: 'LCP' | 'INP' | 'CLS' | 'FCP' | 'TTFB'
  // metric.value: number (ms for timing, unitless for CLS)
  // metric.rating: 'good' | 'needs-improvement' | 'poor'
  // metric.delta: change since last report
  // metric.id: unique ID for deduplication
  // metric.navigationType: 'navigate' | 'reload' | 'back-forward'
  
  navigator.sendBeacon('/analytics', JSON.stringify(metric));
}

onLCP(reportMetric);
onINP(reportMetric);
onCLS(reportMetric);
onFCP(reportMetric);
onTTFB(reportMetric);

================================================================
EVOLUTION OF CORE WEB VITALS
================================================================

2020: Initial Core Web Vitals announced
  - LCP (loading)
  - FID (First Input Delay - interactivity)
  - CLS (visual stability)

June 2021: CWV become ranking signals

2022-2023: INP introduced as "experimental" (replacing FID)
  - FID only measured first input delay
  - INP measures ALL interactions throughout page lifetime
  - INP is a much stricter, more comprehensive interactivity metric

March 2024: INP officially replaces FID
  - FID is retired from Core Web Vitals
  - INP becomes the official interactivity metric

UPCOMING CHANGES:
  Google has hinted at metrics for:
  - Smooth scrolling (Smoothness)
  - Responsiveness to the back/forward cache
  - Network Quality of Experience

================================================================
INTERVIEW ANSWERS
================================================================

Q: What are Core Web Vitals?
A: Core Web Vitals are three user-centric performance metrics defined by
   Google: LCP (Largest Contentful Paint) measures loading, INP (Interaction
   to Next Paint) measures interactivity, and CLS (Cumulative Layout Shift)
   measures visual stability. They're measured at the 75th percentile of real
   user visits and have been Google ranking signals since June 2021.

Q: Why does Google use P75 for Core Web Vitals?
A: P75 means 75% of your page visits meet the threshold. Using the mean
   (average) would hide outliers. P99 would be too strict. P75 balances
   capturing the experience of most users while accounting for the tail
   of bad experiences. It also means you can't have a tiny percentage of
   great visits mask widespread poor performance.

Q: What replaced FID and why?
A: INP (Interaction to Next Paint) replaced FID in March 2024. FID only
   measured the delay before the first input was processed — it ignored
   everything after the first interaction. INP measures the worst-case
   interaction latency for ALL interactions during the page lifetime.
   This gives a much more complete picture of interactivity.

Q: How do you track Core Web Vitals in production?
A: I use Google's web-vitals library to collect LCP, INP, CLS, FCP, and
   TTFB metrics from real users. Data is sent via navigator.sendBeacon() to
   an analytics endpoint. I aggregate at P75 to match CrUX methodology.
   I also check Google Search Console's CWV report for field data and
   PageSpeed Insights for a combined lab + field view.

Q: Can a page score 'Good' in Lighthouse but 'Poor' in CrUX?
A: Yes. Lighthouse runs in a controlled lab environment (simulated device,
   simulated 3G). CrUX is from real users with varied devices and networks.
   A page might look great in lab conditions but have poor real-user scores
   due to third-party scripts, user behavior patterns, or more varied device
   capabilities. This is why both lab and field data are important.
