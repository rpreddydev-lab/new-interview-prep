JUNIT 5 OVERVIEW — Complete Interview Preparation Guide
================================================================

1. WHAT IS JUNIT 5?
================================================================
JUnit 5 is the current generation of the JUnit testing framework for Java.
Released: September 2017 (JUnit 5.0.0)
Current: JUnit 5.10.x (2024)

It is the de facto standard for writing unit and integration tests in Java.
Used widely with Mockito (mocking), AssertJ (assertions), and Spring Boot Test.

JUnit 5 is NOT a single library — it is composed of 3 sub-projects:

  JUNIT PLATFORM
    - Foundation for launching testing frameworks on JVM
    - Provides TestLauncher API, TestEngine API
    - Plugin support for Maven (maven-surefire-plugin) and Gradle
    - Enables test discovery and execution in IDEs

  JUNIT JUPITER (the "new" API)
    - New programming model for writing tests (annotations, assertions)
    - New extension model (replaces JUnit 4 Rules)
    - This is what developers interact with most

  JUNIT VINTAGE
    - Backward compatibility for running JUnit 3/4 tests
    - Allows gradual migration from JUnit 4 to JUnit 5

3. BASIC TEST STRUCTURE
================================================================

Minimal test class:
  import org.junit.jupiter.api.Test;
  import static org.junit.jupiter.api.Assertions.*;
  
  class CalculatorTest {
      
      private final Calculator calculator = new Calculator();
      
      @Test
      void shouldAddTwoNumbers() {
          // Arrange
          int a = 5, b = 3;
          
          // Act
          int result = calculator.add(a, b);
          
          // Assert
          assertEquals(8, result);
      }
      
      @Test
      void shouldThrowExceptionForDivisionByZero() {
          assertThrows(ArithmeticException.class, 
              () -> calculator.divide(10, 0));
      }
  }

Key differences from JUnit 4:
  ✅ Test classes and methods do NOT need to be public
  ✅ @Test is from org.junit.jupiter.api (not org.junit)
  ✅ No test class runner needed (@RunWith → @ExtendWith)
  ✅ More expressive assertion messages (lambda-based)

4. JUNIT 5 KEY ANNOTATIONS — QUICK REFERENCE
================================================================

Lifecycle annotations:
  @Test             — marks a test method
  @BeforeEach       — setup before each test method
  @AfterEach        — teardown after each test method
  @BeforeAll        — setup once before all tests (must be static)
  @AfterAll         — teardown once after all tests (must be static)

Configuration annotations:
  @DisplayName      — custom readable test name
  @Tag              — categorize/filter tests
  @Disabled         — skip a test (with optional reason)
  @Timeout          — fail test if it exceeds duration
  @Order            — control test execution order (@TestMethodOrder)

Assertion-related:
  @ParameterizedTest   — data-driven tests
  @ValueSource         — simple value arrays for parameterized tests
  @CsvSource           — CSV-format parameters
  @MethodSource        — method providing Stream of arguments
  @EnumSource          — all or some enum values
  @NullSource          — null argument
  @EmptySource         — empty string/collection
  @NullAndEmptySource  — both null and empty

Structural:
  @Nested           — inner test class for grouping related tests
  @TestFactory      — dynamic test generation
  @RepeatedTest     — run the same test N times

Extension:
  @ExtendWith       — register JUnit 5 extension
  @RegisterExtension — programmatically register extension

5. ASSERTION METHODS — CORE API
================================================================

Basic assertions (org.junit.jupiter.api.Assertions):
  assertEquals(expected, actual)
  assertEquals(expected, actual, "message on failure")
  assertEquals(expected, actual, () -> "lazy message")  // evaluated only on failure
  
  assertNotEquals(unexpected, actual)
  assertTrue(condition)
  assertFalse(condition)
  assertNull(object)
  assertNotNull(object)
  
  assertSame(expected, actual)       // same object reference
  assertNotSame(expected, actual)
  
  assertArrayEquals(expected[], actual[])
  assertIterableEquals(expected, actual)  // deep equality for iterables

Exception assertions:
  // assertThrows returns the exception for further assertions
  IllegalArgumentException ex = assertThrows(
      IllegalArgumentException.class,
      () -> service.processOrder(null)
  );
  assertTrue(ex.getMessage().contains("order cannot be null"));
  
  // assertDoesNotThrow
  assertDoesNotThrow(() -> service.processOrder(validOrder));

Grouped assertions (assertAll):
  assertAll("person validation",
      () -> assertEquals("John", person.getFirstName()),
      () -> assertEquals("Doe", person.getLastName()),
      () -> assertEquals(30, person.getAge()),
      () -> assertNotNull(person.getEmail())
  );
  // ALL assertions run even if some fail
  // Reports ALL failures, not just the first

Timeout assertions:
  assertTimeout(Duration.ofMillis(100), () -> {
      Thread.sleep(50); // passes
  });
  
  assertTimeoutPreemptively(Duration.ofMillis(100), () -> {
      Thread.sleep(200); // fails — aborts immediately
  });

6. ASSERTJ — FLUENT ASSERTIONS (PREFERRED IN PRACTICE)
================================================================

AssertJ provides richer, more readable assertions than JUnit built-ins.

  import static org.assertj.core.api.Assertions.*;
  
  // String assertions
  assertThat(name).isEqualTo("Alice")
                  .isNotBlank()
                  .startsWith("Al")
                  .hasSize(5);
  
  // Number assertions
  assertThat(price).isGreaterThan(0)
                   .isLessThanOrEqualTo(1000)
                   .isCloseTo(29.99, offset(0.01));
  
  // Collection assertions
  assertThat(orders).isNotEmpty()
                    .hasSize(3)
                    .extracting(Order::getStatus)
                    .containsOnly(OrderStatus.PENDING);
  
  // Exception with AssertJ
  assertThatThrownBy(() -> service.findById(null))
      .isInstanceOf(IllegalArgumentException.class)
      .hasMessage("ID cannot be null");
  
  // Optional assertions
  assertThat(optionalOrder)
      .isPresent()
      .hasValueSatisfying(order -> {
          assertThat(order.getId()).isNotNull();
          assertThat(order.getStatus()).isEqualTo(CONFIRMED);
      });

7. PARAMETERIZED TESTS
================================================================

Run the same test with different inputs:

  @ParameterizedTest
  @ValueSource(ints = {1, 2, 3, 100, Integer.MAX_VALUE})
  void shouldReturnPositiveForPositiveNumbers(int number) {
      assertTrue(calculator.isPositive(number));
  }
  
  @ParameterizedTest
  @ValueSource(strings = {"", "  ", "\t", "\n"})
  void shouldRejectBlankInput(String input) {
      assertThrows(IllegalArgumentException.class, 
          () -> service.process(input));
  }
  
  @ParameterizedTest
  @CsvSource({
      "1,   1,   2",
      "10,  20,  30",
      "-5,  5,   0",
      "0,   0,   0"
  })
  void shouldAddTwoNumbers(int a, int b, int expected) {
      assertEquals(expected, calculator.add(a, b));
  }
  
  @ParameterizedTest
  @MethodSource("provideDiscountTestCases")
  void shouldApplyCorrectDiscount(MemberTier tier, double price, double expected) {
      assertEquals(expected, service.applyDiscount(tier, price), 0.001);
  }
  
  static Stream<Arguments> provideDiscountTestCases() {
      return Stream.of(
          Arguments.of(BASIC,    100.0, 100.0),
          Arguments.of(SILVER,   100.0, 95.0),
          Arguments.of(GOLD,     100.0, 90.0),
          Arguments.of(PLATINUM, 100.0, 80.0)
      );
  }

8. TEST LIFECYCLE AND EXTENSIONS
================================================================

Lifecycle methods:
  @BeforeAll  — static, runs once for entire class
  @BeforeEach — runs before EVERY test method
  @AfterEach  — runs after EVERY test method
  @AfterAll   — static, runs once after all tests

Custom order of test execution:
  @TestMethodOrder(MethodOrderer.OrderAnnotation.class)
  class OrderedTests {
      @Test @Order(1) void firstTest() { }
      @Test @Order(2) void secondTest() { }
      @Test @Order(3) void thirdTest() { }
  }
  
  // Other orderers:
  @TestMethodOrder(MethodOrderer.Random.class)
  @TestMethodOrder(MethodOrderer.DisplayName.class)
  @TestMethodOrder(MethodOrderer.MethodName.class)

Extensions (@ExtendWith):
  - Replace JUnit 4 Runners and Rules
  - Lifecycle hooks, test instance factories, parameter resolution
  
  @ExtendWith(MockitoExtension.class)     // enables @Mock, @InjectMocks
  @ExtendWith(SpringExtension.class)      // Spring context management
  @ExtendWith(TempDirExtension.class)     // provides temp directory
  
  Custom extension:
  class TimingExtension implements BeforeTestMethodCallback, AfterTestMethodCallback {
      @Override
      public void beforeTestMethod(TestMethodInvocationContext ctx, ExtensionContext ec) {
          ec.getStore(GLOBAL).put("startTime", System.currentTimeMillis());
      }
      
      @Override
      public void afterTestMethod(TestMethodInvocationContext ctx, ExtensionContext ec) {
          long start = (long) ec.getStore(GLOBAL).get("startTime");
          System.out.printf("Test %s took %dms%n", 
              ec.getDisplayName(), System.currentTimeMillis() - start);
      }
  }

9. NESTED TESTS
================================================================

@Nested allows organizing tests into a hierarchy:

  class OrderServiceTest {
      
      @Nested
      @DisplayName("when order is placed")
      class WhenOrderPlaced {
          
          @Test void shouldSaveOrderToDatabase() { }
          @Test void shouldSendConfirmationEmail() { }
          @Test void shouldDeductInventory() { }
      }
      
      @Nested
      @DisplayName("when order is cancelled")
      class WhenOrderCancelled {
          
          @Test void shouldUpdateStatusToCancelled() { }
          @Test void shouldRestoreInventory() { }
          @Test void shouldSendCancellationEmail() { }
      }
      
      @Nested
      @DisplayName("when order is not found")
      class WhenOrderNotFound {
          
          @Test void shouldThrowOrderNotFoundException() { }
          @Test void shouldReturn404StatusCode() { }
      }
  }

Benefits:
  - Clear hierarchical organization
  - Inner class can share setup with @BeforeEach in outer class
  - Test report shows hierarchy clearly
  - @DisplayName in @Nested classes reads as sentences in reports

10. DISABLED, TAGS, AND CONDITIONAL EXECUTION
================================================================

@Disabled:
  @Disabled("Waiting for bug fix in JIRA-1234")
  @Test void deprecatedFeatureTest() { }
  
  @Disabled
  class EntireTestClassDisabled { }

@Tag for filtering:
  @Tag("slow")
  @Tag("integration")
  @Test void expensiveDatabaseTest() { }
  
  // Run only unit tests (exclude slow):
  // Maven: -Dgroups="unit" or -DexcludedGroups="slow"
  
  // In surefire plugin config:
  <configuration>
      <groups>unit</groups>
      <excludedGroups>slow,integration</excludedGroups>
  </configuration>

Conditional execution:
  @EnabledOnOs(OS.MAC)          // only on macOS
  @EnabledOnOs({OS.LINUX, OS.MAC})
  @DisabledOnOs(OS.WINDOWS)
  
  @EnabledOnJre(JRE.JAVA_17)    // only on Java 17
  @EnabledForJreRange(min = JRE.JAVA_11, max = JRE.JAVA_17)
  
  @EnabledIfSystemProperty(named = "env", matches = "ci")
  @EnabledIfEnvironmentVariable(named = "CI_ENABLED", matches = "true")

11. DYNAMIC TESTS (@TestFactory)
================================================================

Generate tests at runtime:
  @TestFactory
  Stream<DynamicTest> dynamicTestsForCities() {
      List<String> cities = List.of("London", "Paris", "Tokyo", "New York");
      
      return cities.stream()
          .map(city -> dynamicTest(
              "Time zone should be valid for " + city,
              () -> assertNotNull(TimeZone.getTimeZone(city))
          ));
  }
  
  @TestFactory
  Collection<DynamicTest> multiplicationTable() {
      List<DynamicTest> tests = new ArrayList<>();
      for (int i = 1; i <= 10; i++) {
          final int n = i;
          tests.add(dynamicTest(
              "5 x " + n + " = " + (5 * n),
              () -> assertEquals(5 * n, calculator.multiply(5, n))
          ));
      }
      return tests;
  }

12. INTERVIEW QUESTIONS ON JUNIT 5
================================================================

Q: What are the three modules of JUnit 5?
A: JUnit Platform (test launching infrastructure), JUnit Jupiter (new
   test API), JUnit Vintage (backward compatibility with JUnit 3/4).

Q: What is the difference between @BeforeAll and @BeforeEach?
A: @BeforeAll runs ONCE before ALL test methods in the class (must be static).
   @BeforeEach runs before EVERY individual test method.

Q: What is assertAll() and why use it?
A: assertAll() groups multiple assertions and runs ALL of them, reporting
   every failure. Contrast with standalone assertions that stop at the first
   failure. Useful for validating multiple properties of an object.

Q: How do you run the same test with multiple inputs?
A: @ParameterizedTest with @ValueSource, @CsvSource, or @MethodSource.
   @MethodSource provides a Stream<Arguments> for complex multi-parameter tests.

Q: What replaces JUnit 4's @RunWith in JUnit 5?
A: @ExtendWith. Example: @ExtendWith(MockitoExtension.class) replaces
   @RunWith(MockitoJUnitRunner.class).

Q: What is @Nested used for?
A: Organizing related tests into hierarchical inner classes. Improves
   readability and test structure. Inner classes can be named with
   @DisplayName to read as documentation.

Q: What is the difference between @Disabled and @Tag?
A: @Disabled skips the test entirely. @Tag categorizes tests for
   selective execution (run only @Tag("unit"), exclude @Tag("slow")).

Q: How do you test that an exception is thrown in JUnit 5?
A: assertThrows(ExceptionType.class, () -> { code that throws });
   It returns the exception instance so you can verify the message too.

Q: What is @TestFactory?
A: Creates tests dynamically at runtime, returning Stream/Collection of
   DynamicTest objects. Useful when test cases are computed programmatically.
