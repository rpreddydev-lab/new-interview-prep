================================================================
JUNIT 5 PARAMETERIZED TESTS — Complete Interview Preparation Guide
================================================================

1. WHAT ARE PARAMETERIZED TESTS?
================================================================
Parameterized tests allow you to run the SAME test logic with
DIFFERENT inputs, reducing code duplication and improving coverage.

Instead of:
  @Test void add_1_1_equals_2() { assertEquals(2, calc.add(1, 1)); }
  @Test void add_5_3_equals_8() { assertEquals(8, calc.add(5, 3)); }
  @Test void add_0_0_equals_0() { assertEquals(0, calc.add(0, 0)); }

Write:
  @ParameterizedTest
  @CsvSource({"1, 1, 2", "5, 3, 8", "0, 0, 0", "-5, 5, 0"})
  void shouldAddCorrectly(int a, int b, int expected) {
      assertEquals(expected, calc.add(a, b));
  }

DEPENDENCY (standalone, not needed with spring-boot-starter-test):
  <dependency>
      <groupId>org.junit.jupiter</groupId>
      <artifactId>junit-jupiter-params</artifactId>
      <version>5.10.2</version>
      <scope>test</scope>
  </dependency>

ANNOTATION:
  @ParameterizedTest replaces @Test.
  It must be combined with an argument source annotation.

================================================================
2. @ValueSource — Single Value Arrays
================================================================

Provides simple arrays of primitive types or strings.

Supported types: short, byte, int, long, float, double, char, boolean,
                 String, Class

Examples:
  @ParameterizedTest
  @ValueSource(ints = {1, 2, 3, 100, Integer.MAX_VALUE})
  void shouldReturnTrueForPositiveNumbers(int number) {
      assertTrue(validator.isPositive(number));
  }
  
  @ParameterizedTest
  @ValueSource(strings = {"Alice", "Bob", "Charlie", "Dave"})
  void shouldFormatNameCorrectly(String name) {
      String formatted = formatter.format(name);
      assertTrue(formatted.startsWith(name.substring(0, 1).toUpperCase()));
  }
  
  // Testing INVALID inputs
  @ParameterizedTest
  @ValueSource(strings = {"", "  ", "\t", "\n"})
  void shouldRejectBlankInput(String input) {
      assertThrows(IllegalArgumentException.class, 
          () -> service.processInput(input));
  }
  
  @ParameterizedTest
  @ValueSource(doubles = {0.0, -1.0, Double.NaN, Double.NEGATIVE_INFINITY})
  void shouldRejectInvalidPrices(double price) {
      assertThrows(IllegalArgumentException.class,
          () -> new Product("Book", price, 1));
  }

3. @NullSource, @EmptySource, @NullAndEmptySource
================================================================

Test null and empty values:

  @ParameterizedTest
  @NullSource
  void shouldHandleNullName(String name) {
      assertThrows(NullPointerException.class, () -> user.setName(name));
  }
  
  @ParameterizedTest
  @EmptySource
  void shouldRejectEmptyName(String name) {
      assertThrows(IllegalArgumentException.class, () -> user.setName(name));
  }
  
  // Both null AND empty
  @ParameterizedTest
  @NullAndEmptySource
  void shouldRejectNullOrEmptyName(String name) {
      assertThrows(IllegalArgumentException.class, () -> user.setName(name));
  }
  
  // Combine with @ValueSource for comprehensive blank string testing
  @ParameterizedTest
  @NullAndEmptySource
  @ValueSource(strings = {" ", "\t", "\n", "   "})
  void shouldRejectNullOrBlankInput(String input) {
      assertThrows(IllegalArgumentException.class, 
          () -> service.validate(input));
  }

@EmptySource works for:
  - String (empty string "")
  - Collections (empty List, Set, etc.)
  - Arrays (empty array)
  - Optional (Optional.empty())

4. @EnumSource — Enum Values
================================================================

Test with enum constants:

  @ParameterizedTest
  @EnumSource(OrderStatus.class)  // ALL enum values
  void shouldHandleAllOrderStatuses(OrderStatus status) {
      Order order = new Order("o-1", "c-1", status);
      assertDoesNotThrow(() -> orderService.process(order));
  }
  
  // Only specific enum values
  @ParameterizedTest
  @EnumSource(value = OrderStatus.class, names = {"PENDING", "PROCESSING"})
  void shouldBeAbleToCancel(OrderStatus status) {
      assertTrue(orderService.canCancel(status));
  }
  
  // Exclude specific values
  @ParameterizedTest
  @EnumSource(value = OrderStatus.class, 
              names = {"DELIVERED", "CANCELLED"},
              mode = EnumSource.Mode.EXCLUDE)
  void shouldBeActive(OrderStatus status) {
      assertTrue(statusService.isActive(status));
  }
  
  // Mode.MATCH_ALL — regex matching
  @ParameterizedTest
  @EnumSource(value = OrderStatus.class, 
              names = {".*ING"},   // PENDING, PROCESSING, SHIPPING
              mode = EnumSource.Mode.MATCH_ALL)
  void shouldBeInProgressStates(OrderStatus status) {
      assertTrue(statusService.isInProgress(status));
  }

5. @CsvSource — Comma-Separated Values
================================================================

Define multiple parameters in a CSV format per row:

  @ParameterizedTest
  @CsvSource({
      "1,   1,   2",
      "10,  20,  30",
      "-5,  5,   0",
      "0,   0,   0",
      "100, -100, 0"
  })
  void shouldAddCorrectly(int a, int b, int expected) {
      assertEquals(expected, calculator.add(a, b));
  }
  
  // Strings with spaces — use single quotes
  @ParameterizedTest
  @CsvSource({
      "'Alice Smith', alice@example.com, ACTIVE",
      "'Bob Jones',   bob@example.com,   INACTIVE",
      "'Charlie',     charlie@test.com,  PENDING"
  })
  void shouldCreateUser(String name, String email, String status) {
      User user = userService.create(name, email, UserStatus.valueOf(status));
      assertThat(user).isNotNull();
      assertThat(user.getName()).isEqualTo(name);
  }
  
  // Null handling (empty string becomes null by default)
  @ParameterizedTest
  @CsvSource({
      "1, apple",
      "2,      ",     // ← this becomes null
      "3, cherry"
  })
  void testWithPossibleNull(int id, String name) {
      // name can be null
  }
  
  // Custom null placeholder
  @ParameterizedTest(name = "id={0}, name={1}")
  @CsvSource(value = {
      "1, apple",
      "2, NIL",
      "3, cherry"
  }, nullValues = "NIL")
  void testWithCustomNull(int id, String name) {
      // name is null when "NIL" is in CSV
  }

6. @CsvFileSource — CSV From External File
================================================================

Load test data from a CSV file on the classpath:

  @ParameterizedTest
  @CsvFileSource(resources = "/test-data/discount-test-cases.csv",
                 numLinesToSkip = 1)  // skip header row
  void shouldApplyDiscountCorrectly(String tier, double total, double expected) {
      double result = discountService.apply(MemberTier.valueOf(tier), total);
      assertEquals(expected, result, 0.001);
  }

File: src/test/resources/test-data/discount-test-cases.csv
  tier,total,expected
  BASIC,100.0,100.0
  SILVER,100.0,95.0
  GOLD,100.0,90.0
  PLATINUM,100.0,80.0

Benefits:
  - Keep large datasets in separate files
  - Business stakeholders can modify test data without touching code
  - Easy to add more test cases

7. @MethodSource — Method-Provided Arguments
================================================================

The most powerful source — a factory method provides a Stream of arguments.

SAME CLASS:
  @ParameterizedTest
  @MethodSource("provideAdditionArguments")
  void shouldAdd(int a, int b, int expected) {
      assertEquals(expected, calculator.add(a, b));
  }
  
  static Stream<Arguments> provideAdditionArguments() {
      return Stream.of(
          Arguments.of(1, 1, 2),
          Arguments.of(5, -3, 2),
          Arguments.of(0, 0, 0),
          Arguments.of(Integer.MAX_VALUE, 0, Integer.MAX_VALUE)
      );
  }

COMPLEX OBJECTS:
  @ParameterizedTest
  @MethodSource("provideOrderScenarios")
  void shouldCalculateOrderTotal(Order order, double expectedTotal) {
      double actual = pricingService.calculateTotal(order);
      assertEquals(expectedTotal, actual, 0.001);
  }
  
  static Stream<Arguments> provideOrderScenarios() {
      return Stream.of(
          Arguments.of(
              new Order("c-1", List.of(new Item("Book", 29.99, 2))),
              59.98
          ),
          Arguments.of(
              new Order("c-2", List.of(
                  new Item("Pen", 2.99, 5),
                  new Item("Notebook", 9.99, 1)
              )),
              24.94
          )
      );
  }

EXTERNAL CLASS SOURCE:
  @ParameterizedTest
  @MethodSource("com.example.TestDataProvider#provideValidEmails")
  void shouldAcceptValidEmails(String email) {
      assertTrue(validator.isValidEmail(email));
  }
  
  // In TestDataProvider.java:
  public static Stream<String> provideValidEmails() {
      return Stream.of(
          "user@example.com",
          "user+tag@example.co.uk",
          "user.name@subdomain.example.com"
      );
  }

SINGLE PARAMETER (no Arguments.of needed):
  @ParameterizedTest
  @MethodSource("provideInvalidEmails")
  void shouldRejectInvalidEmails(String email) {
      assertFalse(validator.isValidEmail(email));
  }
  
  static Stream<String> provideInvalidEmails() {
      return Stream.of("notanemail", "@nodomain", "no@", "double@@sign.com");
  }

8. @ArgumentsSource — Custom Argument Provider
================================================================

For maximum flexibility, implement ArgumentsProvider:

  public class PrimeNumberProvider implements ArgumentsProvider {
      @Override
      public Stream<? extends Arguments> provideArguments(ExtensionContext ctx) {
          return Stream.of(2, 3, 5, 7, 11, 13, 17, 19, 23)
              .map(Arguments::of);
      }
  }
  
  @ParameterizedTest
  @ArgumentsSource(PrimeNumberProvider.class)
  void shouldIdentifyPrimeNumbers(int number) {
      assertTrue(mathUtil.isPrime(number));
  }

9. PARAMETERIZED TEST DISPLAY NAMES
================================================================

Custom names for better reports:

  @ParameterizedTest(name = "{index}: add({0}, {1}) = {2}")
  @CsvSource({"1, 1, 2", "5, 3, 8"})
  void addTest(int a, int b, int expected) { }
  // Report: "1: add(1, 1) = 2", "2: add(5, 3) = 8"
  
  @ParameterizedTest(name = "[{index}] {displayName} - tier: {0}")
  @EnumSource(MemberTier.class)
  void discountTest(MemberTier tier) { }
  
  Name variables:
    {index}       — 1-based test index
    {displayName} — method display name
    {0}, {1}, ... — argument values
    {arguments}   — all arguments as string

10. COMBINING MULTIPLE SOURCES
================================================================

You can combine @NullAndEmptySource with @ValueSource:

  @ParameterizedTest
  @NullAndEmptySource
  @ValueSource(strings = {" ", "   ", "\t"})
  void allBlankInputsShouldFail(String input) {
      assertThrows(IllegalArgumentException.class, 
          () -> service.processInput(input));
  }

11. ARGUMENT CONVERSION
================================================================

JUnit 5 can automatically convert strings to types:

  @ParameterizedTest
  @ValueSource(strings = {"PENDING", "CONFIRMED", "SHIPPED"})
  void testWithEnumConversion(OrderStatus status) {
      // String "PENDING" is auto-converted to OrderStatus.PENDING
      assertNotNull(status);
  }
  
  @ParameterizedTest
  @ValueSource(strings = {"2024-01-15", "2024-06-30"})
  void testWithDateConversion(LocalDate date) {
      // String auto-converted to LocalDate via TypeConvertingArgumentConverter
      assertTrue(date.getYear() == 2024);
  }

12. PARAMETERIZED TESTS — BEST PRACTICES
================================================================

DO:
  ✅ Use for boundary values (0, -1, 1, MAX, MIN)
  ✅ Use for all enum values (@EnumSource)
  ✅ Use for happy + sad paths with the same structure
  ✅ Add custom display names for readability
  ✅ Put large datasets in CSV files (@CsvFileSource)
  ✅ Use @MethodSource for complex object scenarios

DON'T:
  ❌ Use when test logic differs significantly between cases
     (then they're separate tests, not parameterized)
  ❌ Use with too many parameters in @CsvSource (hard to read)
  ❌ Forget to test NULL and EMPTY inputs
  ❌ Mix unrelated scenarios in one parameterized test

Boundary value testing template:
  @ParameterizedTest
  @CsvSource({
      // boundary analysis for age validation (valid: 18-120)
      "-1,  false",   // below minimum
      "0,   false",
      "17,  false",   // one below minimum
      "18,  true",    // minimum
      "19,  true",    // one above minimum
      "100, true",    // typical valid
      "120, true",    // maximum
      "121, false",   // one above maximum
      "999, false"    // far above maximum
  })
  void shouldValidateAge(int age, boolean expected) {
      assertEquals(expected, validator.isValidAge(age));
  }

13. INTERVIEW QUESTIONS ON PARAMETERIZED TESTS
================================================================

Q: What is @ParameterizedTest and when should you use it?
A: Runs the same test method with different inputs from a data source.
   Use when you have the same test logic that should work (or fail)
   for multiple inputs — boundary values, enum values, invalid inputs.

Q: What is the difference between @CsvSource and @MethodSource?
A: @CsvSource: inline CSV data, good for simple primitive values.
   @MethodSource: factory method provides Stream<Arguments>, good for
   complex objects or when test data needs programmatic generation.

Q: How do you test null and empty inputs with parameterized tests?
A: @NullSource for null only, @EmptySource for empty, 
   @NullAndEmptySource for both.
   Combine with @ValueSource to cover all blank variants.

Q: How do you provide custom display names for parameterized tests?
A: @ParameterizedTest(name = "{index}: method({0}, {1}) = {2}")
   Use placeholders: {index}, {0}, {1}, {arguments}, {displayName}

Q: What are the available argument sources?
A: @ValueSource, @NullSource, @EmptySource, @NullAndEmptySource,
   @EnumSource, @CsvSource, @CsvFileSource, @MethodSource, @ArgumentsSource

Q: When would you use @CsvFileSource?
A: When test data is large or when it should be maintained separately
   from code (e.g., business stakeholders manage test data in CSV files).
