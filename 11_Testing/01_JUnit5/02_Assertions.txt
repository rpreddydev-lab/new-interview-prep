================================================================
JUNIT 5 ASSERTIONS — Complete Interview Preparation Guide
================================================================

1. ASSERTION LIBRARIES AVAILABLE
================================================================
JUnit 5 supports multiple assertion styles:

  1. JUnit 5 built-in (org.junit.jupiter.api.Assertions)
     - Standard, no extra dependency needed
     - Good for basic checks
  
  2. AssertJ (org.assertj.core.api.Assertions)
     - Fluent, chainable assertions
     - Much more readable error messages
     - PREFERRED in professional projects
  
  3. Hamcrest (org.hamcrest.MatcherAssert)
     - Matcher-based, used heavily in Spring MockMvc
     - Readable but less fluent than AssertJ
  
  4. Truth (Google)
     - Similar to AssertJ, less common in Java server-side

Recommendation: Use AssertJ for most assertions, Hamcrest where required by frameworks.

================================================================
2. JUNIT 5 BUILT-IN ASSERTIONS
================================================================

IMPORT:
  import static org.junit.jupiter.api.Assertions.*;

─────────────────────────────────────────────────────────
A. EQUALITY ASSERTIONS
─────────────────────────────────────────────────────────

  assertEquals(expected, actual)
  assertEquals(expected, actual, "failure message")
  assertEquals(expected, actual, () -> "lazy evaluated message")
  assertNotEquals(unexpected, actual)
  
  Example:
  assertEquals(42, calculator.add(40, 2));
  assertEquals("Alice", user.getName(), "User name should be Alice");
  assertEquals(3.14, Math.PI, 0.01);  // delta for doubles
  
  // Lazy message (computed only on failure — good for expensive messages)
  assertEquals(expected, actual, 
      () -> "Failed for input: " + input + ", expected: " + expected);

  // IMPORTANT: assertEquals(expected, actual) — expected ALWAYS first
  // Convention matters: "expected 5 but was 3" vs "expected 3 but was 5"

─────────────────────────────────────────────────────────
B. BOOLEAN ASSERTIONS
─────────────────────────────────────────────────────────

  assertTrue(condition)
  assertFalse(condition)
  assertTrue(condition, "message")
  assertTrue(() -> condition, "lazy message")
  
  Example:
  assertTrue(user.isActive());
  assertFalse(result.isEmpty());
  assertTrue(email.contains("@"), "Email should contain @ symbol");

─────────────────────────────────────────────────────────
C. NULL / NOT-NULL ASSERTIONS
─────────────────────────────────────────────────────────

  assertNull(object)
  assertNotNull(object)
  assertNull(object, "message")
  assertNotNull(object, "message")
  
  Example:
  assertNotNull(service.createOrder(request));
  assertNull(service.findByEmail("nonexistent@example.com"));

─────────────────────────────────────────────────────────
D. REFERENCE IDENTITY ASSERTIONS
─────────────────────────────────────────────────────────

  assertSame(expected, actual)     // same object reference (==)
  assertNotSame(expected, actual)  // different object references
  
  Example:
  // Verify singleton returns same instance
  Configuration config1 = Configuration.getInstance();
  Configuration config2 = Configuration.getInstance();
  assertSame(config1, config2);   // same object
  
  // Verify copy creates new object
  Order copy = originalOrder.copy();
  assertNotSame(originalOrder, copy);
  assertEquals(originalOrder, copy);  // same value but different instance

─────────────────────────────────────────────────────────
E. ARRAY AND ITERABLE ASSERTIONS
─────────────────────────────────────────────────────────

  assertArrayEquals(expected[], actual[])
  assertIterableEquals(expected, actual)  // deep equals for Iterables
  
  Example:
  int[] expected = {1, 2, 3, 4, 5};
  int[] actual = calculator.generateSequence(1, 5);
  assertArrayEquals(expected, actual);
  
  List<String> expectedNames = List.of("Alice", "Bob", "Charlie");
  List<String> actualNames = userService.getActiveUserNames();
  assertIterableEquals(expectedNames, actualNames);

─────────────────────────────────────────────────────────
F. EXCEPTION ASSERTIONS
─────────────────────────────────────────────────────────

  assertThrows(ExceptionType.class, executable)
  assertDoesNotThrow(executable)
  
  // assertThrows RETURNS the exception for further inspection
  IllegalArgumentException ex = assertThrows(
      IllegalArgumentException.class,
      () -> orderService.placeOrder(null)
  );
  
  // Verify exception message
  assertTrue(ex.getMessage().contains("order cannot be null"));
  assertEquals("order cannot be null", ex.getMessage());
  
  // Verify cause
  assertInstanceOf(IllegalStateException.class, ex.getCause());
  
  // Check no exception thrown
  assertDoesNotThrow(() -> orderService.placeOrder(validOrder));
  
  // WRONG way (doesn't capture exception for verification):
  // assertThrows(IllegalArgumentException.class, () -> {
  //     orderService.placeOrder(null);
  //     orderService.placeOrder(another);  // ← this makes test ambiguous
  // });
  // Better: one action per assertThrows

─────────────────────────────────────────────────────────
G. GROUPED ASSERTIONS — assertAll()
─────────────────────────────────────────────────────────

  Run ALL assertions and report ALL failures:
  
  assertAll("user validation",
      () -> assertEquals("Alice", user.getName()),
      () -> assertEquals("alice@example.com", user.getEmail()),
      () -> assertTrue(user.isActive()),
      () -> assertNotNull(user.getCreatedAt()),
      () -> assertEquals(Role.USER, user.getRole())
  );
  
  // Without assertAll, first failure stops execution
  // With assertAll, ALL 5 are checked, ALL failures reported
  
  Nested assertAll:
  assertAll("order",
      () -> assertNotNull(order.getId()),
      () -> assertAll("order items",
          () -> assertEquals(2, order.getItems().size()),
          () -> assertEquals("Book", order.getItems().get(0).getName())
      )
  );

─────────────────────────────────────────────────────────
H. TIMEOUT ASSERTIONS
─────────────────────────────────────────────────────────

  // Wait for completion then check
  assertTimeout(Duration.ofSeconds(1), () -> {
      slowService.process();
  });
  
  // Return value from executable
  String result = assertTimeout(Duration.ofMillis(500), () -> {
      return service.generateToken();
  });
  assertNotNull(result);
  
  // ABORT immediately if timeout exceeded (preemptive)
  assertTimeoutPreemptively(Duration.ofMillis(100), () -> {
      // Killed immediately at 100ms
      Thread.sleep(200);  // fails immediately
  });

─────────────────────────────────────────────────────────
I. TYPE ASSERTION
─────────────────────────────────────────────────────────

  assertInstanceOf(ExpectedType.class, object)
  
  Exception ex = assertThrows(Exception.class, () -> service.risky());
  assertInstanceOf(PaymentException.class, ex);
  
  // Combined:
  PaymentException payEx = assertInstanceOf(
      PaymentException.class,
      assertThrows(Exception.class, () -> service.charge(null))
  );
  assertEquals("CARD_DECLINED", payEx.getErrorCode());

3. ASSERTJ — FLUENT ASSERTION LIBRARY
================================================================

IMPORT:
  import static org.assertj.core.api.Assertions.*;
  import static org.assertj.core.api.AssertionsForClassTypes.assertThatThrownBy;

WHY ASSERTJ OVER JUNIT ASSERTIONS:
  JUnit: assertEquals("Alice", user.getName())
  → Failure: "expected: <Alice> but was: <Bob>"
  
  AssertJ: assertThat(user.getName()).isEqualTo("Alice")
  → Failure: "expected: "Alice" but was: "Bob""
  → Plus chaining: assertThat(user.getName()).isEqualTo("Alice").hasSize(5)

─────────────────────────────────────────────────────────
A. STRING ASSERTIONS
─────────────────────────────────────────────────────────

  assertThat(message)
      .isNotNull()
      .isNotEmpty()
      .isNotBlank()
      .isEqualTo("Hello World")
      .startsWith("Hello")
      .endsWith("World")
      .contains("lo W")
      .containsIgnoringCase("hello world")
      .doesNotContain("Error")
      .matches("Hello \\w+")     // regex
      .hasSize(11)
      .hasSizeBetween(5, 20)
      .isUpperCase()
      .isLowerCase();

─────────────────────────────────────────────────────────
B. NUMBER ASSERTIONS
─────────────────────────────────────────────────────────

  assertThat(price)
      .isNotNull()
      .isGreaterThan(0)
      .isLessThanOrEqualTo(1000)
      .isPositive()
      .isNegative()
      .isZero()
      .isNotZero()
      .isBetween(10.0, 200.0)
      .isCloseTo(29.99, offset(0.01))     // within 0.01
      .isCloseTo(29.99, withPercentage(1)); // within 1%

─────────────────────────────────────────────────────────
C. COLLECTION ASSERTIONS
─────────────────────────────────────────────────────────

  List<Order> orders = orderService.findByCustomer("c-1");
  
  assertThat(orders)
      .isNotNull()
      .isNotEmpty()
      .hasSize(3)
      .hasSizeGreaterThan(0)
      .hasSizeLessThanOrEqualTo(10)
      .contains(specificOrder)
      .containsExactly(order1, order2, order3)  // exact order
      .containsExactlyInAnyOrder(order3, order1, order2)  // any order
      .containsAnyOf(order1, order4)
      .doesNotContain(cancelledOrder)
      .containsOnly(order1, order2, order3)  // and nothing else
      .allMatch(o -> o.getCustomerId().equals("c-1"))
      .anyMatch(o -> o.getStatus() == CONFIRMED)
      .noneMatch(o -> o.getStatus() == CANCELLED);
  
  // Extracting properties
  assertThat(orders)
      .extracting(Order::getStatus)
      .containsOnly(OrderStatus.PENDING, OrderStatus.CONFIRMED);
  
  assertThat(orders)
      .extracting("id", "status")
      .containsExactly(
          tuple("o-1", PENDING),
          tuple("o-2", CONFIRMED)
      );
  
  // Filter then assert
  assertThat(orders)
      .filteredOn(o -> o.getStatus() == PENDING)
      .hasSize(1)
      .first()
      .extracting(Order::getId)
      .isEqualTo("o-1");

─────────────────────────────────────────────────────────
D. OBJECT / BEAN ASSERTIONS
─────────────────────────────────────────────────────────

  // Check specific fields
  assertThat(order)
      .isNotNull()
      .hasFieldOrProperty("id")
      .hasFieldOrPropertyWithValue("status", OrderStatus.PENDING)
      .hasFieldOrPropertyWithValue("customerId", "c-123");
  
  // Recursive equality (deep comparison, ignoring specific fields)
  assertThat(actualOrder)
      .usingRecursiveComparison()
      .ignoringFields("id", "createdAt")  // generated fields
      .isEqualTo(expectedOrder);
  
  // Soft assertions (like assertAll — run all, report all failures)
  SoftAssertions softly = new SoftAssertions();
  softly.assertThat(user.getName()).isEqualTo("Alice");
  softly.assertThat(user.getEmail()).contains("@");
  softly.assertThat(user.isActive()).isTrue();
  softly.assertAll();  // reports all failures

─────────────────────────────────────────────────────────
E. OPTIONAL ASSERTIONS
─────────────────────────────────────────────────────────

  Optional<Order> result = orderService.findById("o-123");
  
  // Present
  assertThat(result)
      .isPresent()
      .hasValueSatisfying(order -> {
          assertThat(order.getId()).isEqualTo("o-123");
          assertThat(order.getStatus()).isEqualTo(PENDING);
      });
  
  // Empty
  assertThat(emptyResult).isEmpty();
  
  // With value
  assertThat(result).contains(expectedOrder);

─────────────────────────────────────────────────────────
F. EXCEPTION ASSERTIONS WITH ASSERTJ
─────────────────────────────────────────────────────────

  // assertThatThrownBy — fluent exception testing
  assertThatThrownBy(() -> orderService.placeOrder(null))
      .isInstanceOf(IllegalArgumentException.class)
      .hasMessage("order cannot be null")
      .hasMessageContaining("null")
      .hasNoCause();
  
  // assertThatExceptionOfType — type-first style
  assertThatExceptionOfType(OrderNotFoundException.class)
      .isThrownBy(() -> orderService.findById("invalid"))
      .withMessage("Order not found: invalid")
      .withNoCause();
  
  // assertThatNoException
  assertThatNoException()
      .isThrownBy(() -> orderService.placeOrder(validOrder));
  
  // Convenience methods for common exceptions
  assertThatIllegalArgumentException()
      .isThrownBy(() -> new Order(null, null));
  
  assertThatNullPointerException()
      .isThrownBy(() -> service.process(null));

─────────────────────────────────────────────────────────
G. MAP ASSERTIONS
─────────────────────────────────────────────────────────

  Map<String, Integer> inventory = service.getInventory();
  
  assertThat(inventory)
      .isNotEmpty()
      .hasSize(3)
      .containsKey("apple")
      .containsValue(10)
      .containsEntry("apple", 10)
      .doesNotContainKey("banana");

4. HAMCREST MATCHERS (USED IN MOCKMVC)
================================================================

Hamcrest is heavily used in Spring MockMvc result assertions.

IMPORT:
  import static org.hamcrest.Matchers.*;
  import static org.hamcrest.MatcherAssert.assertThat;

Common matchers:
  equalTo("Alice")
  not(equalTo("Bob"))
  notNullValue()
  nullValue()
  
  containsString("Hello")
  startsWith("Hello")
  endsWith("World")
  
  hasSize(3)
  empty()
  not(empty())
  
  greaterThan(0)
  greaterThanOrEqualTo(10)
  lessThan(100)
  
  is(instanceOf(OrderNotFoundException.class))
  
  hasProperty("name", equalTo("Alice"))
  hasItem("apple")
  hasItems("apple", "banana")
  containsInAnyOrder("a", "b", "c")

In MockMvc (most common usage):
  mockMvc.perform(get("/api/orders"))
      .andExpect(status().isOk())
      .andExpect(jsonPath("$.content", hasSize(3)))
      .andExpect(jsonPath("$[0].status", equalTo("PENDING")))
      .andExpect(jsonPath("$.totalElements", greaterThan(0)));

5. WRITING GOOD ASSERTIONS — BEST PRACTICES
================================================================

1. ONE LOGICAL ASSERTION PER TEST (guideline, not strict rule)
   Bad: Three unrelated assertions in one test
   Good: Each test verifies one aspect of behavior
   
   // BAD
   @Test void testEverything() {
       assertEquals("Alice", user.getName());
       assertEquals(30, user.getAge());
       assertTrue(user.isActive());
       verify(repo, times(1)).save(user);
   }
   
   // BETTER: Split into focused tests

2. USE assertAll() FOR MULTIPLE PROPERTIES OF ONE OBJECT
   These are logically related — test them together with assertAll()
   
   @Test void userHasCorrectProperties() {
       assertAll(
           () -> assertEquals("Alice", user.getName()),
           () -> assertEquals(30, user.getAge()),
           () -> assertTrue(user.isActive())
       );
   }

3. PREFER ASSERTJ FOR READABILITY
   JUnit: assertTrue(list.isEmpty()) → Failure: "expected: true but was: false"
   AssertJ: assertThat(list).isEmpty() → Failure: "Expected empty but was: [a, b, c]"

4. ALWAYS PROVIDE FAILURE MESSAGES FOR UNCLEAR ASSERTIONS
   assertEquals(200, response.getStatusCode(), 
       "API call failed. Response body: " + response.getBody());

5. DON'T ASSERT IMPLEMENTATION DETAILS
   Bad: verify(repo, times(1)).findById(anyString())  // HOW it works
   Good: assertThat(result).isPresent()               // WHAT it returns

6. AVOID WEAK ASSERTIONS
   Bad:  assertNotNull(result)  // passes even if result is wrong
   Good: assertThat(result).isEqualTo(expectedSpecificValue)

6. INTERVIEW QUESTIONS ON ASSERTIONS
================================================================

Q: What is the difference between assertEquals and assertSame?
A: assertEquals: checks value equality (via .equals())
   assertSame: checks reference equality (same object, ==)
   Example: two "hello" strings — assertEquals passes, assertSame may fail.

Q: What is assertAll() and why use it?
A: Groups multiple assertions that ALL run, reporting every failure.
   Without assertAll, first failure stops the test. With assertAll,
   you see all failures at once, which is useful for validating objects.

Q: What is the advantage of AssertJ over JUnit assertions?
A: Fluent, chainable API for more readable tests.
   Better error messages that show actual vs expected context.
   Rich collection/string/exception assertions out of the box.

Q: How do you verify an exception message in JUnit 5?
A: Use assertThrows, capture the exception, then assert on its message:
   Exception ex = assertThrows(Exception.class, () -> service.call());
   assertEquals("expected message", ex.getMessage());
   Or with AssertJ: assertThatThrownBy(() -> ...).hasMessage("...");

Q: What is the difference between assertTimeout and assertTimeoutPreemptively?
A: assertTimeout waits for completion, then checks duration.
   assertTimeoutPreemptively aborts execution immediately if limit exceeded.
   (assertTimeoutPreemptively uses a separate thread which has implications
   for ThreadLocals and test framework state)

Q: What is usingRecursiveComparison in AssertJ?
A: Deep recursive equality check that compares field by field.
   Can ignore specific fields (like auto-generated IDs, timestamps).
   More robust than .equals() which requires custom implementation.
