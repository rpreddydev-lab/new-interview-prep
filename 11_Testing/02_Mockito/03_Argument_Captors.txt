MOCKITO — ARGUMENT CAPTORS
Complete Interview Preparation Guide
================================================================

1. WHAT IS AN ARGUMENT CAPTOR?
================================================================

ArgumentCaptor lets you CAPTURE arguments that were passed to a mock
method, so you can inspect and assert on them AFTER the fact.

Why use it?
  - The argument is created INSIDE the method under test (you can't pass it in)
  - The argument is a complex object and you want to verify specific fields
  - You want to assert on the argument WITHOUT needing to know it beforehand
  - Verify the EXACT content of something sent to a dependency

Classic use case:
  orderService.placeOrder(cart);
  
  // OrderService creates an Order internally and passes it to the repository.
  // You want to verify the Order's fields (total, status, customerId).
  // You don't have a reference to that Order object.
  // → Use ArgumentCaptor to capture what was passed to repo.save()

================================================================
2. CREATING AND USING AN ARGUMENTCAPTOR
================================================================

TWO WAYS TO CREATE:

  // 1. Annotation (recommended in class-level setup)
  @Captor
  ArgumentCaptor<Order> orderCaptor;
  
  // 2. Programmatic (inline, good for quick one-off captures)
  ArgumentCaptor<Order> orderCaptor = ArgumentCaptor.forClass(Order.class);

BASIC WORKFLOW:
  1. Run the method under test
  2. Verify the mock call AND capture the argument
  3. Extract captured value with .getValue()
  4. Assert on the captured value

EXAMPLE:
  @ExtendWith(MockitoExtension.class)
  class OrderServiceTest {
      
      @Mock OrderRepository orderRepository;
      @Mock EmailService emailService;
      @InjectMocks OrderService orderService;
      
      @Captor ArgumentCaptor<Order> orderCaptor;
      @Captor ArgumentCaptor<EmailRequest> emailCaptor;
      
      @Test
      void placeOrderShouldCreateCorrectOrder() {
          // Arrange
          Cart cart = new Cart("customer-1");
          cart.addItem(new CartItem("SKU-001", 2, BigDecimal.valueOf(49.99)));
          cart.addItem(new CartItem("SKU-002", 1, BigDecimal.valueOf(29.99)));
          
          when(orderRepository.save(any(Order.class))).thenAnswer(
              inv -> { Order o = inv.getArgument(0); o.setId("ord-123"); return o; }
          );
          
          // Act
          orderService.placeOrder(cart);
          
          // Assert — capture what was passed to save()
          verify(orderRepository).save(orderCaptor.capture());
          Order captured = orderCaptor.getValue();
          
          assertEquals("customer-1", captured.getCustomerId());
          assertEquals(2, captured.getItems().size());
          assertEquals(new BigDecimal("129.97"), captured.getTotal());
          assertEquals(OrderStatus.PENDING, captured.getStatus());
          assertNotNull(captured.getCreatedAt());
      }
  }

3. CAPTURING MULTIPLE CALLS
================================================================

If the mock method is called MULTIPLE TIMES, use getAllValues():

  @Test
  void processOrdersShouldSendEmailForEachOrder() {
      List<Order> orders = List.of(
          new Order("o-1", "alice@test.com"),
          new Order("o-2", "bob@test.com"),
          new Order("o-3", "carol@test.com")
      );
      
      orderService.processAll(orders);
      
      // Capture all 3 email calls
      verify(emailService, times(3)).send(emailCaptor.capture());
      
      List<EmailRequest> allEmails = emailCaptor.getAllValues();
      
      assertEquals(3, allEmails.size());
      assertEquals("alice@test.com", allEmails.get(0).getTo());
      assertEquals("bob@test.com",   allEmails.get(1).getTo());
      assertEquals("carol@test.com", allEmails.get(2).getTo());
      
      // All emails have the correct subject
      allEmails.forEach(email -> 
          assertEquals("Your order is confirmed", email.getSubject()));
  }

CAPTURING FROM atLeast() / atMost():
  verify(emailService, atLeast(1)).send(emailCaptor.capture());
  
  List<EmailRequest> captured = emailCaptor.getAllValues();
  assertTrue(captured.stream().allMatch(r -> r.getSubject() != null));

4. CAPTURING WITH GENERICS (TYPE-SAFE)
================================================================

Java generics with reflection can be tricky:

  // For generic types, use @Captor or forClass with raw type:
  @Captor ArgumentCaptor<List<User>> userListCaptor;  // @Captor handles generic
  
  // Programmatic: raw type + suppress warning
  @SuppressWarnings("unchecked")
  ArgumentCaptor<List<User>> captor = ArgumentCaptor.forClass((Class) List.class);
  
  // Modern Mockito: captor() method avoids unchecked warning
  ArgumentCaptor<List<User>> captor = ArgumentCaptor.captor();  // Mockito 5+

  @Test
  void shouldPublishBatchedEvents() {
      @Captor ArgumentCaptor<List<DomainEvent>> eventCaptor;
      
      eventBus.publishAll(userId, eventList);
      
      verify(eventPublisher).publish(eventCaptor.capture());
      List<DomainEvent> capturedBatch = eventCaptor.getValue();
      
      assertEquals(3, capturedBatch.size());
      assertTrue(capturedBatch.stream().allMatch(e -> e.getSource().equals(userId)));
  }

5. ARGUMENT CAPTOR vs ARGSTHAT (INLINE PREDICATE)
================================================================

ARGUMENTCAPTOR:
  ✅ Can inspect AFTER the call (useful for complex assertions)
  ✅ Can see ALL captured values (getAllValues())
  ✅ Works well with assertj or multiple field checks
  ❌ More verbose (capture then assert)
  ❌ Doesn't tell you WHY the verification failed inline

ARGTHAT (inline assertion):
  ✅ Concise — check and verify in one line
  ✅ Test fails immediately at verify() if predicate fails
  ✅ Good for simple, single-field checks
  ❌ Complex predicates can be hard to read
  ❌ Can't reuse the captured argument elsewhere

ARGSTHAT EXAMPLE:
  // Inline predicate — fails at verify if condition not met
  verify(emailService).send(argThat(email ->
      email.getTo().equals("alice@example.com") &&
      email.getSubject().contains("Confirmation")
  ));
  
  // More readable with named predicate:
  verify(orderRepository).save(argThat(order ->
      order.getStatus() == OrderStatus.PENDING &&
      order.getItems().size() == 3
  ));

WHEN TO PREFER CAPTOR:
  // When you need to chain multiple assertions with AssertJ:
  verify(notificationService).send(notifCaptor.capture());
  Notification n = notifCaptor.getValue();
  
  assertThat(n)
      .extracting(Notification::getType, Notification::getRecipient, 
                  Notification::getPriority)
      .containsExactly(NotificationType.EMAIL, "alice@test.com", Priority.HIGH);

  // When you need to assert the same captured object in multiple ways
  assertThat(n.getBody()).contains("Order #12345");
  assertThat(n.getBody()).contains("Total: $99.99");
  assertThat(n.getSentAt()).isBetween(before, after);

6. CAPTOR WITH COLLECTIONS AND NESTED OBJECTS
================================================================

  @Captor ArgumentCaptor<UserUpdatedEvent> eventCaptor;
  
  @Test
  void updateUserShouldPublishCorrectEvent() {
      UserUpdateRequest request = new UserUpdateRequest(
          "user-1", "New Name", "new@email.com"
      );
      
      userService.update(request);
      
      verify(eventBus).publish(eventCaptor.capture());
      UserUpdatedEvent event = eventCaptor.getValue();
      
      // Deep assertions on nested object
      assertThat(event.getUserId()).isEqualTo("user-1");
      assertThat(event.getChanges())
          .containsEntry("name", "New Name")
          .containsEntry("email", "new@email.com")
          .doesNotContainKey("password");  // sensitive field not included
      assertThat(event.getTimestamp())
          .isAfter(Instant.now().minusSeconds(5));
  }

NESTED CAPTOR USAGE:
  @Test
  void processBatchShouldCreateCorrectAuditLog() {
      batchProcessor.process(items);
      
      verify(auditService).logBatch(batchCaptor.capture());
      BatchAuditLog log = batchCaptor.getValue();
      
      // Assert on the complex nested structure
      assertThat(log.getItems())
          .hasSize(5)
          .extracting(AuditItem::getAction)
          .containsOnly(AuditAction.PROCESSED);
      
      assertThat(log.getMetadata())
          .extracting(BatchMetadata::getBatchId, BatchMetadata::getSize)
          .containsExactly(log.getId(), 5);
  }

7. CAPTOR IN PARAMETERIZED TESTS
================================================================

Captors work with @ParameterizedTest too, but reset between test runs:

  @ParameterizedTest
  @ValueSource(strings = {"alice@test.com", "bob@test.com"})
  void welcomeEmailSentWithCorrectRecipient(String email) {
      userService.register(new UserRegistration(email));
      
      ArgumentCaptor<EmailRequest> emailCaptor = ArgumentCaptor.forClass(EmailRequest.class);
      verify(emailService).send(emailCaptor.capture());
      
      assertEquals(email, emailCaptor.getValue().getTo());
      assertEquals("Welcome!", emailCaptor.getValue().getSubject());
      
      // Must reset mock between parameterized runs if using @Captor field
      // Or create new captor inline (as shown here)
  }

8. CAPTOR vs VERIFY — COMBINED PATTERN
================================================================

You can mix verify() constraints with capture:

  // Verify EXACTLY once AND capture
  verify(orderRepository, times(1)).save(orderCaptor.capture());
  
  // Verify AT LEAST once AND capture all
  verify(eventPublisher, atLeastOnce()).publish(eventCaptor.capture());
  List<Event> allPublished = eventCaptor.getAllValues();
  
  // Verify NEVER — no capture makes sense here
  verify(fraudService, never()).flag(any());

9. COMMON MISTAKES WITH ARGUMENTCAPTOR
================================================================

MISTAKE 1: Calling getValue() before verify()
  // WRONG:
  orderCaptor.getValue();  // IllegalStateException — nothing captured yet!
  verify(repo).save(orderCaptor.capture());
  
  // CORRECT: verify first, then getValue()
  verify(repo).save(orderCaptor.capture());
  Order captured = orderCaptor.getValue();  // ✅

MISTAKE 2: Calling getValue() when method called multiple times
  // Method called twice, but using getValue() — gets LAST value only
  verify(repo, times(2)).save(orderCaptor.capture());
  Order last = orderCaptor.getValue();  // only last value
  
  // CORRECT: getAllValues() for multiple captures
  List<Order> all = orderCaptor.getAllValues();  // [first, second]

MISTAKE 3: Not matching argument count in verify
  // If method is called 3 times but you verify(times(2)), 
  // you'll get a verification failure, not a capture issue
  verify(repo, times(3)).save(orderCaptor.capture()); // must match actual invocations

MISTAKE 4: Using captor with any() — redundant
  // Don't do this — just verify + capture without any():
  verify(repo).save(orderCaptor.capture());  // implicit any() 
  // No need for: verify(repo).save(any(orderCaptor.capture()));  // WRONG

10. REAL-WORLD EXAMPLE: PAYMENT PROCESSING
================================================================

  @ExtendWith(MockitoExtension.class)
  class PaymentServiceTest {
      
      @Mock PaymentGateway paymentGateway;
      @Mock OrderRepository orderRepository;
      @Mock NotificationService notificationService;
      
      @InjectMocks PaymentService paymentService;
      
      @Captor ArgumentCaptor<PaymentRequest> paymentRequestCaptor;
      @Captor ArgumentCaptor<OrderStatusUpdate> orderUpdateCaptor;
      @Captor ArgumentCaptor<Notification> notificationCaptor;
      
      @Test
      void processPaymentShouldChargeCaptureAndNotify() {
          // Arrange
          Order order = buildOrder("ord-999", "cust-1", new BigDecimal("149.99"));
          PaymentMethod card = new PaymentMethod("tok_visa_xxxx4242");
          
          when(paymentGateway.charge(any())).thenReturn(
              PaymentResult.success("ch_123456")
          );
          when(orderRepository.save(any())).thenAnswer(inv -> inv.getArgument(0));
          
          // Act
          paymentService.processPayment(order, card);
          
          // Assert payment request
          verify(paymentGateway).charge(paymentRequestCaptor.capture());
          PaymentRequest req = paymentRequestCaptor.getValue();
          
          assertEquals(new BigDecimal("149.99"), req.getAmount());
          assertEquals("USD", req.getCurrency());
          assertEquals("tok_visa_xxxx4242", req.getToken());
          assertEquals("ord-999", req.getOrderId());
          
          // Assert order status update
          verify(orderRepository).save(orderUpdateCaptor.capture());
          // Note: Adapting for polymorphism — capture Order, not OrderStatusUpdate
          
          // Assert notification
          verify(notificationService).send(notificationCaptor.capture());
          Notification notification = notificationCaptor.getValue();
          
          assertEquals("cust-1", notification.getRecipientId());
          assertEquals(NotificationType.PAYMENT_SUCCESS, notification.getType());
          assertThat(notification.getMessage()).contains("149.99");
      }
  }

11. INTERVIEW QUESTIONS
================================================================

Q: What is ArgumentCaptor and why is it useful?
A: ArgumentCaptor captures arguments passed to mock methods, allowing you
   to verify the CONTENT of objects created internally by the system under test.
   Useful when the SUT creates objects you don't have access to from the test.

Q: What is the difference between getValue() and getAllValues()?
A: getValue() returns the last (or only) captured argument.
   getAllValues() returns ALL arguments captured across multiple invocations
   as a List, in order of invocation.

Q: When should you use ArgumentCaptor vs argThat()?
A: argThat() — single inline predicate check, simpler code.
   ArgumentCaptor — multiple assertions on the same object, using AssertJ,
   or when you need the captured argument for other purposes in the test.

Q: Can you use @Captor annotation outside MockitoExtension?
A: @Captor requires MockitoAnnotations.openMocks(this) to be initialized.
   With @ExtendWith(MockitoExtension.class), it's automatic.

Q: What exception do you get if you call getValue() without verify()?
A: IllegalStateException: "No argument value was captured!"
   You must call verify(mock).method(captor.capture()) before getValue().

Q: How do you capture arguments from a void method?
A: The same way — void method calls can still be verified:
   doAnswer(inv -> { ... }).when(mock).voidMethod(captor.capture());
   OR: verify(mock).voidMethod(captor.capture()); — works fine!
