MockedStatic, MockedConstruction

1. WHY MOCK STATIC METHODS?
================================================================

Static methods are called on the CLASS, not on an object — so you
can't inject a mock in the normal way.

PROBLEMATIC CODE:
  public class OrderService {
      public Order createOrder(Cart cart) {
          String orderId = UUID.randomUUID().toString();  // static, untestable
          Instant now = Instant.now();                     // static, untestable
          String trackingCode = ShippingUtils.generateCode(); // static 3rd party
          
          return new Order(orderId, now, cart, trackingCode);
      }
  }
  
  // Without mocking statics, each test produces different orderId and timestamp.
  // You can't assert on them, making the test non-deterministic.

PREFERRED ALTERNATIVES (avoid the need for static mocking):
  1. Inject Clock instead of Instant.now()
  2. Inject IdGenerator instead of UUID.randomUUID()
  3. Wrap the static call in a non-static method/class you CAN inject
  
  // Better design:
  public class OrderService {
      private final Clock clock;
      private final IdGenerator idGenerator;
      
      public OrderService(Clock clock, IdGenerator idGenerator) { ... }
      
      public Order createOrder(Cart cart) {
          String id = idGenerator.generate();  // mockable interface
          Instant now = clock.instant();        // mockable Clock
          ...
      }
  }

When you CAN'T refactor (legacy code, 3rd party libs), use MockedStatic.

2. SETUP — MOCKITO INLINE / MOCKITO 5
================================================================

Mockito 4 and earlier:
  <!-- pom.xml -->
  <dependency>
      <groupId>org.mockito</groupId>
      <artifactId>mockito-inline</artifactId>
      <version>4.x.x</version>
      <scope>test</scope>
  </dependency>

Mockito 5+:
  <!-- mockito-core already includes inline mocking -->
  <dependency>
      <groupId>org.mockito</groupId>
      <artifactId>mockito-core</artifactId>
      <version>5.x.x</version>
      <scope>test</scope>
  </dependency>
  
  <!-- No mockito-inline needed in Mockito 5! -->

3. MOCKEDSTATIC — MOCKING STATIC METHODS
================================================================

BASIC USAGE — try-with-resources (REQUIRED):
  import org.mockito.MockedStatic;
  import static org.mockito.Mockito.mockStatic;
  
  @Test
  void shouldCreateOrderWithDeterministicId() {
      try (MockedStatic<UUID> uuidMock = mockStatic(UUID.class)) {
          UUID fixedId = UUID.fromString("123e4567-e89b-12d3-a456-426614174000");
          uuidMock.when(UUID::randomUUID).thenReturn(fixedId);
          
          Order order = orderService.createOrder(cart);
          
          assertEquals("123e4567-e89b-12d3-a456-426614174000", order.getId());
      }
      // Static mock is CLOSED after try-with-resources — UUID.randomUUID() works normally again
  }

IMPORTANT: MockedStatic MUST be closed after use.
  - Use try-with-resources or call .close() manually
  - If not closed, the static mock PERSISTS for the entire JVM session
  - Other tests will see the mock! — Major source of test pollution

4. MOCKING LocalDateTime.now() / Instant.now()
================================================================

  @Test
  void transactionTimestampShouldBeCurrentTime() {
      LocalDateTime fixedTime = LocalDateTime.of(2024, 6, 15, 12, 0, 0);
      
      try (MockedStatic<LocalDateTime> mockedTime = mockStatic(LocalDateTime.class)) {
          mockedTime.when(LocalDateTime::now).thenReturn(fixedTime);
          
          // Calls with zone argument need separate stubbing:
          mockedTime.when(() -> LocalDateTime.now(any(ZoneId.class)))
              .thenReturn(fixedTime);
          
          Transaction tx = transactionService.createTransaction(amount);
          
          assertEquals(fixedTime, tx.getTimestamp());
      }
  }

MOCKING Instant.now():
  @Test
  void eventTimestampShouldBeDeterministic() {
      Instant fixedInstant = Instant.parse("2024-01-15T10:30:00Z");
      
      try (MockedStatic<Instant> mockedInstant = mockStatic(Instant.class,
              CALLS_REAL_METHODS)) {  // ← call real methods by default
          
          mockedInstant.when(Instant::now).thenReturn(fixedInstant);
          // All other Instant methods (parse, of, etc.) still work normally
          
          DomainEvent event = eventFactory.createEvent("USER_CREATED", payload);
          
          assertEquals(fixedInstant, event.getOccurredAt());
      }
  }

CALLS_REAL_METHODS default answer:
  // Without it, ALL static methods return null/default
  // With it, only the ones you stub are overridden; the rest call real implementations
  try (MockedStatic<Files> mockedFiles = mockStatic(Files.class, CALLS_REAL_METHODS)) {
      mockedFiles.when(() -> Files.exists(Path.of("/config.yaml"))).thenReturn(true);
      // Files.readString(), Files.copy(), etc. still work normally
  }

5. MOCKING STATIC METHOD WITH ARGUMENTS
================================================================

  @Test
  void shouldHandleDifferentFilePaths() {
      try (MockedStatic<Files> mockedFiles = mockStatic(Files.class)) {
          // Stub with specific argument
          mockedFiles.when(() -> Files.readString(Path.of("/app/config.yaml")))
              .thenReturn("server:\n  port: 8080");
          
          // Stub with any argument
          mockedFiles.when(() -> Files.readString(any(Path.class)))
              .thenReturn("default config content");
          
          // Stub to throw
          mockedFiles.when(() -> Files.readString(Path.of("/missing.yaml")))
              .thenThrow(new IOException("File not found"));
          
          // Act
          Config config = configLoader.load("/app/config.yaml");
          
          assertEquals(8080, config.getPort());
          
          // Verify static was called
          mockedFiles.verify(() -> Files.readString(Path.of("/app/config.yaml")));
      }
  }

VERIFYING STATIC METHOD CALLS:
  try (MockedStatic<AuditLogger> mockedLogger = mockStatic(AuditLogger.class)) {
      service.performAction(user);
      
      // Verify static method was called
      mockedLogger.verify(() -> AuditLogger.log("PERFORM_ACTION", user.getId()));
      
      // Verify with times()
      mockedLogger.verify(
          () -> AuditLogger.log(anyString(), anyString()), 
          times(2)
      );
      
      // Verify never called
      mockedLogger.verify(
          () -> AuditLogger.logError(anyString()),
          never()
      );
  }

6. MOCKEDCONSTRUCTION — MOCKING NEW OPERATOR
================================================================

MockedConstruction intercepts new ClassName() calls.

BASIC USAGE:
  import org.mockito.MockedConstruction;
  import static org.mockito.Mockito.mockConstruction;
  
  @Test
  void shouldMockHttpClientConstruction() {
      try (MockedConstruction<HttpClient> httpClientMock = 
               mockConstruction(HttpClient.class, (mock, ctx) -> {
                   // Configure mock in context handler
                   when(mock.send(any(), any())).thenReturn(
                       HttpResponse.of(200, "{\"status\":\"ok\"}")
                   );
               })) {
          
          // When PaymentGateway internally does: new HttpClient()
          // it gets our configured mock
          PaymentGateway gateway = new PaymentGateway();
          PaymentResult result = gateway.charge(paymentRequest);
          
          assertEquals("ok", result.getStatus());
          
          // Verify the mock was constructed
          assertEquals(1, httpClientMock.constructed().size());
          
          // Verify interactions on the constructed mock
          HttpClient constructedMock = httpClientMock.constructed().get(0);
          verify(constructedMock).send(any(), any());
      }
  }

ACCESSING CONSTRUCTION ARGS:
  try (MockedConstruction<OrderId> mockConstruction = 
           mockConstruction(OrderId.class, (mock, ctx) -> {
               // ctx.arguments() gives the constructor args
               String prefix = (String) ctx.arguments().get(0);
               Integer counter = (Integer) ctx.arguments().get(1);
               
               when(mock.getValue()).thenReturn(prefix + "-" + counter + "-TEST");
           })) {
      
      // Code internally does: new OrderId("ORD", 42)
      String generatedId = idGenerator.generate();
      
      assertEquals("ORD-42-TEST", generatedId);
  }

MULTIPLE CONSTRUCTIONS:
  try (MockedConstruction<Connection> mockConn = 
           mockConstruction(Connection.class)) {
      
      connectionPool.initialize(5);  // creates 5 connections internally
      
      List<Connection> created = mockConn.constructed();
      assertEquals(5, created.size());
      
      // Verify each connection was used
      created.forEach(conn -> verify(conn).setAutoCommit(false));
  }

7. COMBINING STATIC AND CONSTRUCTION MOCKING
================================================================

  @Test
  void complexLegacyCodeTest() {
      try (MockedStatic<DatabaseUtils> dbUtilsMock = mockStatic(DatabaseUtils.class);
           MockedConstruction<LegacyRepo> repoMock = mockConstruction(LegacyRepo.class,
               (mock, ctx) -> when(mock.findUser(anyString())).thenReturn(testUser))) {
          
          dbUtilsMock.when(() -> DatabaseUtils.getConnectionString("prod"))
              .thenReturn("jdbc:test:mem");
          
          // LegacyService internally calls:
          //   DatabaseUtils.getConnectionString("prod")  (static)
          //   new LegacyRepo(connectionString)           (constructor)
          //   repo.findUser(userId)                      (instance)
          
          User result = legacyService.getUser("user-1");
          
          assertNotNull(result);
          dbUtilsMock.verify(() -> DatabaseUtils.getConnectionString("prod"));
          
          LegacyRepo constructedRepo = repoMock.constructed().get(0);
          verify(constructedRepo).findUser("user-1");
      }
  }

8. THREAD-SAFETY AND PARALLEL TESTS
================================================================

Static mocking is JVM-wide (thread-local in Mockito, but still risky):

  // Mockito's static mocking is thread-local — each thread has its own scope
  // But if tests share state (static variables), issues can arise

BEST PRACTICES FOR PARALLEL TESTS:
  1. Never share MockedStatic between test methods
  2. Always use try-with-resources — ensures cleanup
  3. If using @TestInstance(PER_CLASS) with static mocks — be careful
  4. Prefer test isolation: design code to avoid needing static mocks

9. FINAL CLASS MOCKING
================================================================

Mockito 5 (with inline mocking) can mock final classes:

  final class ImmutableUser {
      private final String id;
      private final String email;
      
      public ImmutableUser(String id, String email) { ... }
      public final String getId() { return id; }
  }
  
  @Test
  void canMockFinalClass() {
      ImmutableUser mockUser = mock(ImmutableUser.class);  // works in Mockito 5!
      when(mockUser.getId()).thenReturn("test-id");
      
      assertEquals("test-id", mockUser.getId());
  }

FINAL METHOD MOCKING:
  class SomeClass {
      public final String format(String input) {
          return input.trim().toUpperCase();
      }
  }
  
  SomeClass mock = mock(SomeClass.class);
  when(mock.format("hello")).thenReturn("HELLO");  // works with mockito-inline

10. WHEN NOT TO MOCK STATICS — DESIGN ALTERNATIVES
================================================================

ALTERNATIVE 1: Inject Clock for time
  // Instead of Instant.now() in code:
  public class EventService {
      private final Clock clock;
      
      public Event createEvent(String name) {
          return new Event(name, clock.instant());  // testable!
      }
  }
  
  // Test:
  Clock fixed = Clock.fixed(Instant.parse("2024-01-01T10:00:00Z"), ZoneOffset.UTC);
  EventService service = new EventService(fixed);

ALTERNATIVE 2: Facade/Wrapper for static utilities
  // Wrap static calls in an interface:
  interface IdGenerator {
      String generate();
  }
  
  @Component
  class UuidIdGenerator implements IdGenerator {
      public String generate() { return UUID.randomUUID().toString(); }
  }
  
  // Test:
  @Mock IdGenerator idGenerator;
  when(idGenerator.generate()).thenReturn("fixed-test-id");

ALTERNATIVE 3: Functional interface injection
  // Pass the static method as a function:
  public class OrderService {
      private final Supplier<String> idSupplier;
      
      public OrderService(Supplier<String> idSupplier) {
          this.idSupplier = idSupplier;
      }
  }
  
  // Test:
  OrderService service = new OrderService(() -> "fixed-test-id");

11. INTERVIEW QUESTIONS
================================================================

Q: How do you mock a static method in Mockito?
A: Use MockedStatic<T> with try-with-resources:
   try (MockedStatic<UUID> mock = mockStatic(UUID.class)) {
       mock.when(UUID::randomUUID).thenReturn(fixedUuid);
       // ... test code ...
   }
   Requires Mockito 5 (or mockito-inline in Mockito 4).

Q: Why must MockedStatic be used in a try-with-resources block?
A: If not closed, the static mock persists for the remainder of the JVM
   session and affects ALL subsequent tests in the suite. try-with-resources
   guarantees .close() is called even if an exception occurs.

Q: What is CALLS_REAL_METHODS and when would you use it with mockStatic?
A: Default answer for the MockedStatic — unstubbed static methods call
   their real implementations. Useful when you only want to override ONE
   static method (like now()) while letting all others work normally.

Q: How do you mock a constructor in Mockito?
A: Use MockedConstruction<T>:
   try (MockedConstruction<HttpClient> mock = mockConstruction(HttpClient.class,
            (m, ctx) -> when(m.send(any(), any())).thenReturn(response))) {
       // new HttpClient() inside production code returns the configured mock
   }

Q: What is the preferred alternative to mocking static methods?
A: Inject dependencies as interfaces or functional types:
   Instead of Instant.now(), inject Clock; instead of UUID.randomUUID(),
   inject IdGenerator. This makes code testable without static mocking.

Q: Can Mockito 5 mock final classes?
A: Yes. Mockito 5 includes inline mocking by default (no extra dependency).
   mock(FinalClass.class) works. Previously required the mockito-inline artifact.

Q: How do you verify a static method was called in Mockito?
A: Use the verify method on the MockedStatic object:
   mockedStatic.verify(() -> ClassName.staticMethod(args));
   mockedStatic.verify(() -> ClassName.staticMethod(any()), times(2));

Q: What happens if you forget to close a MockedStatic?
A: The static override persists across tests, causing non-deterministic
   failures — other tests that rely on the real static behavior will fail.
   Always use try-with-resources or manually call .close() in @AfterEach.
