================================================================
CODE QUALITY — JACOCO CODE COVERAGE
Complete Interview Preparation Guide
================================================================

1. WHAT IS JACOCO?
================================================================

JaCoCo (Java Code Coverage) is the de facto standard coverage tool for Java.
It instruments bytecode at runtime and measures which instructions,
lines, and branches were executed during tests.

Coverage Types:
  - Instruction  — individual bytecode instructions (finest granularity)
  - Line         — source lines executed
  - Branch       — if/switch branches taken (true/false)
  - Method       — methods called at least once
  - Class        — classes with at least one method tested

2. MAVEN CONFIGURATION
================================================================

  <plugin>
      <groupId>org.jacoco</groupId>
      <artifactId>jacoco-maven-plugin</artifactId>
      <version>0.8.11</version>
      <executions>
          <!-- bind agent: instruments code before tests run -->
          <execution>
              <id>prepare-agent</id>
              <goals><goal>prepare-agent</goal></goals>
          </execution>
          
          <!-- generate report: after tests, generate HTML/XML/CSV -->
          <execution>
              <id>report</id>
              <phase>test</phase>
              <goals><goal>report</goal></goals>
          </execution>
          
          <!-- enforce coverage thresholds -->
          <execution>
              <id>check</id>
              <goals><goal>check</goal></goals>
              <configuration>
                  <rules>
                      <rule>
                          <element>BUNDLE</element>    <!-- whole project -->
                          <limits>
                              <limit>
                                  <counter>LINE</counter>
                                  <value>COVEREDRATIO</value>
                                  <minimum>0.80</minimum>   <!-- 80% min -->
                              </limit>
                              <limit>
                                  <counter>BRANCH</counter>
                                  <value>COVEREDRATIO</value>
                                  <minimum>0.75</minimum>
                              </limit>
                          </limits>
                      </rule>
                  </rules>
              </configuration>
          </execution>
      </executions>
  </plugin>

  Maven commands:
    mvn test             # run tests, generate coverage
    mvn verify           # run tests + check coverage thresholds
    mvn jacoco:report    # generate report manually

  Reports at: target/site/jacoco/index.html

3. COVERAGE TYPES IN DEPTH
================================================================

LINE COVERAGE:
  Source: int result = a + b;          // line 15
  Test executes this line → line 15 covered ✅
  
BRANCH COVERAGE:
  Source:
    if (age >= 18) {                    // two branches
        return "adult";
    } else {
        return "minor";
    }
  
  Test 1: age = 20 → covers TRUE branch only (50% branch coverage)
  Test 2: age = 15 → covers FALSE branch
  Both tests → 100% branch coverage
  
PARTIAL BRANCH (yellow in JaCoCo report):
  Source:
    if (user != null && user.isActive()) {  // two conditions
        ...
    }
  Partial: tested user != null (false) but not user.isActive() (false)

INSTRUCTION COVERAGE:
  Bytecode: the real unit. One Java line may compile to many instructions.
  Most granular, less intuitive for developers.

4. EXCLUDING CLASSES FROM COVERAGE
================================================================

  <configuration>
      <excludes>
          <!-- Lombok-generated code -->
          <exclude>**/*$*</exclude>
          
          <!-- DTOs, entities (no logic to test) -->
          <exclude>com/example/model/**</exclude>
          <exclude>com/example/dto/**</exclude>
          
          <!-- Configuration classes -->
          <exclude>com/example/config/**</exclude>
          
          <!-- Main application class -->
          <exclude>com/example/Application.class</exclude>
          
          <!-- Generated code -->
          <exclude>com/example/generated/**</exclude>
      </excludes>
  </configuration>

  In-source annotation exclusion (JaCoCo respects this):
    @Generated   // javax.annotation.Generated or Lombok's @Generated
    public class MyDto { ... }

  Lombok: lombok.config file:
    lombok.addLombokGeneratedAnnotation = true
    # JaCoCo will skip Lombok-generated methods (equals, hashCode, toString)

5. JACOCO WITH MULTI-MODULE MAVEN PROJECTS
================================================================

  Each module generates its own report. To get an aggregate report:
  
  <!-- In parent pom.xml -->
  <plugin>
      <groupId>org.jacoco</groupId>
      <artifactId>jacoco-maven-plugin</artifactId>
      <executions>
          <execution>
              <id>report-aggregate</id>
              <phase>verify</phase>
              <goals><goal>report-aggregate</goal></goals>
          </execution>
      </executions>
  </plugin>
  
  <!-- In dedicated "coverage" module that depends on all other modules -->
  <!-- Or configure report-aggregate in parent pom -->
  
  Aggregate report: coverage-module/target/site/jacoco-aggregate/index.html

6. UNDERSTANDING THE JACOCO REPORT
================================================================

Color coding in HTML report:
  Green    — fully covered line/branch
  Red      — not covered at all
  Yellow   — partially covered (branch: one condition not tested)
  Diamond  — branch indicator (solid = covered, empty = not covered)

Class report columns:
  Missed Instructions | Cov. | Missed Branches | Cov. | Missed Lines | Cov. | ...

Reading the report:
  - Red methods → critical gap, write tests for these first
  - Yellow branches → add edge case tests (null, empty, false path)
  - Green but no assertions → mutation testing will catch this

8. INTERVIEW QUESTIONS
================================================================

Q: What is the difference between line coverage and branch coverage?
A: Line coverage measures whether a source line was executed at all.
   Branch coverage measures whether each conditional branch (true/false
   of if/switch) was taken. You can have 100% line coverage but only 50%
   branch coverage if you only test the "true" path of every condition.

Q: Your JaCoCo report shows 85% line coverage. Is your test suite good?
A: Not necessarily. High coverage doesn't mean meaningful tests. Tests
   can execute code without assertions. Check branch coverage (harder to
   game), look for yellow partial branches in the HTML report, and
   supplement with mutation testing (PIT) to assess test effectiveness.

Q: How do you exclude generated or boilerplate code from JaCoCo?
A: Three options: (1) Configure <excludes> in the JaCoCo plugin with
   class path patterns. (2) Add @Generated annotation on the class —
   JaCoCo respects this. (3) For Lombok, set
   lombok.addLombokGeneratedAnnotation=true in lombok.config.

Q: What are the Maven lifecycle phases for JaCoCo?
A: (1) prepare-agent (before test phase) — attaches the JaCoCo agent to
   the JVM for bytecode instrumentation. (2) report (after test phase) —
   generates HTML/XML/CSV reports. (3) check (during verify phase) —
   fails the build if thresholds aren't met.

Q: How do you set a minimum coverage threshold that fails the build?
A: Use the JaCoCo check goal bound to the verify phase. Configure a rule
   with element=BUNDLE (whole project), counter=LINE, value=COVEREDRATIO,
   and minimum=0.80 (80%). Run `mvn verify` — if coverage is below 80%,
   the build fails.
