CODE QUALITY — SONARQUBE
Complete Interview Preparation Guide
================================================================

1. WHAT IS SONARQUBE?
================================================================

SonarQube is a continuous code quality platform that:
  - Aggregates results from multiple static analysis tools
  - Tracks quality metrics over time
  - Enforces Quality Gates before deployment
  - Integrates with CI/CD pipelines, GitHub PRs, Jira

Variants:
  SonarQube Community  — free, self-hosted
  SonarQube Developer  — branch analysis, PRs (paid)
  SonarCloud           — SaaS version for GitHub/GitLab/Bitbucket

================================================================
2. WHAT SONARQUBE MEASURES
================================================================

Category        | Examples
----------------|------------------------------------------------------
Bugs            | Null dereference, resource leak, wrong equals()
Vulnerabilities | SQL injection, hardcoded credentials, XXE injection
Security Hotspots | Sensitive code needing manual review
Code Smells     | Long methods, deep nesting, god classes, dead code
Duplications    | Copy-pasted blocks across files
Complexity      | Cyclomatic complexity, cognitive complexity
Coverage        | JaCoCo coverage report integration
Technical Debt  | Sum of estimated fix time for all issues

RATINGS (A–E):
  A = 0 bugs/vulnerabilities     B = at least 1 minor
  C = at least 1 major           D = at least 1 critical
  E = at least 1 blocker

3. MAVEN SETUP AND RUNNING ANALYSIS
================================================================

  <plugin>
      <groupId>org.sonarsource.scanner.maven</groupId>
      <artifactId>sonar-maven-plugin</artifactId>
      <version>3.10.0.2594</version>
  </plugin>
  
  # Run analysis (self-hosted SonarQube):
  mvn clean verify sonar:sonar \
    -Dsonar.host.url=http://localhost:9000 \
    -Dsonar.login=my-token
  
  # For SonarCloud:
  mvn clean verify sonar:sonar \
    -Dsonar.host.url=https://sonarcloud.io \
    -Dsonar.organization=my-org \
    -Dsonar.projectKey=my-org_my-project \
    -Dsonar.token=$SONAR_TOKEN

  sonar-project.properties (project root):
    sonar.projectKey=com.example:my-app
    sonar.projectName=My Application
    sonar.sources=src/main/java
    sonar.tests=src/test/java
    sonar.java.binaries=target/classes
    sonar.coverage.jacoco.xmlReportPaths=target/site/jacoco/jacoco.xml
    sonar.exclusions=**/generated/**,**/model/**

4. QUALITY GATE CONFIGURATION
================================================================

Default Sonar Way Quality Gate:
  Condition                              | Operator   | Threshold
  ---------------------------------------|------------|----------
  Coverage on New Code                   | is less    | 80%
  Duplicated Lines on New Code           | is greater | 3%
  Maintainability Rating on New Code     | is worse   | A
  Reliability Rating on New Code         | is worse   | A
  Security Hotspots Reviewed on New Code | is less    | 100%
  Security Rating on New Code            | is worse   | A

Custom Quality Gate example (stricter):
  - Overall Code Coverage > 80% (not just new code)
  - No Blocker or Critical bugs
  - No Vulnerabilities
  - Cognitive Complexity per method < 15

Blocking in CI/CD:
  # SonarQube scans and reports gate status
  # Use sonar-quality-gate action or sonarqube-scan-action
  # The pipeline fails if "Quality Gate FAILED"

5. COMMON SONARQUBE FINDINGS IN JAVA
================================================================

BUG EXAMPLES:
  // BUG: Null dereference
  String name = user.getName();   // if user.getName() can return null
  if (name.equals("admin")) ...   // NullPointerException risk
  // Fix: use Objects.equals(name, "admin") or check for null first

  // BUG: Resource leak
  FileInputStream fis = new FileInputStream("file.txt");
  // If exception thrown before close() → resource leak
  // Fix: try-with-resources

  // BUG: Wrong equals() implementation
  if (myEnum == OtherEnum.VALUE) ...  // comparing incompatible enums
  
VULNERABILITY EXAMPLES:
  // SQL Injection
  String query = "SELECT * FROM users WHERE id = " + userId;  // VULNERABLE
  // Fix: use PreparedStatement / JPA parameterized queries

  // Hardcoded credentials
  String password = "admin123";  // Sonar flags this as a security hotspot
  
CODE SMELL EXAMPLES:
  // Too many parameters
  public Order createOrder(String custId, String sku, int qty,
      String address, String currency, ...) // 10+ params
  // Fix: extract to request object
  
  // High cognitive complexity
  if (...) {
      for (...) {
          if (...) {
              while (...) {
                  if (...) { ... }  // deeply nested → high complexity
              }
          }
      }
  }
  
  // Dead code
  private void unusedMethod() { ... }  // flagged as code smell

6. SUPPRESSING SONARQUBE ISSUES
================================================================

  // Suppress a specific rule
  @SuppressWarnings("java:S2696")  // use rule key
  public static String globalState;
  
  // Suppress in sonar config (project-wide)
  sonar.issue.ignore.multicriteria=e1
  sonar.issue.ignore.multicriteria.e1.ruleKey=java:S2696
  sonar.issue.ignore.multicriteria.e1.resourceKey=**/legacy/**/*.java
  
  // NOSONAR comment (suppresses all rules for that line)
  password = "admin"; // NOSONAR — intentionally hardcoded in test

  Best practice: suppress sparingly, with documented reason.
  Excessive suppression defeats the purpose of static analysis.

7. CI/CD INTEGRATION (GitHub Actions)
================================================================

  # .github/workflows/sonar.yml
  name: SonarCloud Analysis
  on: [push, pull_request]
  
  jobs:
    sonar:
      runs-on: ubuntu-latest
      steps:
        - uses: actions/checkout@v4
          with: {fetch-depth: 0}   # full history for blame info
        
        - name: Set up JDK 21
          uses: actions/setup-java@v4
          with: {java-version: '21', distribution: 'temurin'}
        
        - name: Build and analyze
          env:
            GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
            SONAR_TOKEN: ${{ secrets.SONAR_TOKEN }}
          run: |
            mvn -B verify sonar:sonar \
              -Dsonar.host.url=https://sonarcloud.io \
              -Dsonar.organization=my-org \
              -Dsonar.projectKey=my-org_my-project

8. INTERVIEW QUESTIONS
================================================================

Q: What is the difference between a bug and a code smell in SonarQube?
A: A bug is a confirmed defect that will likely cause incorrect behavior
   at runtime (e.g., null dereference, resource leak). A code smell is
   a maintainability issue that makes code harder to understand or change
   but doesn't necessarily cause a runtime failure (e.g., overly complex
   method, unused variable).

Q: What is Technical Debt in SonarQube?
A: Technical debt is the estimated time to remediate all code smells in the
   project. SonarQube calculates it in minutes/hours/days based on each
   issue's severity. The Maintainability Rating (A-E) is based on the ratio
   of tech debt to overall development time.

Q: What is a Security Hotspot?
A: A security hotspot is sensitive code that requires manual review to
   determine if it's actually a vulnerability. Unlike a Vulnerability (which
   Sonar is confident is a real issue), a hotspot might be intentional and
   safe. Example: using a weak hash algorithm for non-security purposes.

Q: How do you integrate JaCoCo with SonarQube?
A: Run JaCoCo to generate jacoco.xml during the test phase. Then in the
   Sonar analysis, point to the XML report via
   sonar.coverage.jacoco.xmlReportPaths=target/site/jacoco/jacoco.xml.
   Sonar reads this file and shows coverage within its dashboard.

Q: How can you block a PR from being merged if Sonar quality gate fails?
A: In SonarCloud/SonarQube, enable Pull Request decoration and branch analysis.
   In GitHub, configure branch protection rules to require the "SonarCloud"
   status check to pass. If the Quality Gate fails, the PR check fails and
   the merge is blocked.
