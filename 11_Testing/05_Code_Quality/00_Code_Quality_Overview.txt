CODE QUALITY — OVERVIEW
Complete Interview Preparation Guide

1. WHAT IS CODE QUALITY?
================================================================

Code quality encompasses multiple dimensions:
  - Correctness      — code does what it's supposed to
  - Readability      — easy to understand and maintain
  - Test Coverage    — how much code is exercised by tests
  - Reliability      — low bug density, handles edge cases
  - Security         — free from known vulnerabilities
  - Maintainability  — easy to change without introducing bugs
  - Performance      — efficient use of resources

================================================================
2. KEY CODE QUALITY METRICS
================================================================

Metric              | Description                          | Target
--------------------|--------------------------------------|--------
Line Coverage       | % of lines executed by tests         | > 80%
Branch Coverage     | % of if/switch branches tested       | > 75%
Instruction Coverage| % of bytecode instructions executed  | > 80%
Mutation Score      | % of code mutations caught by tests  | > 70%
Technical Debt      | Estimated time to fix all code smells| Low/None
Code Smells         | Violations of best practices         | 0 blockers
Bugs                | Known defect patterns detected       | 0 critical
Vulnerabilities     | Security issue patterns              | 0
Duplications        | Copy-pasted code blocks              | < 3%
Cyclomatic Complexity| Number of independent paths/method  | <= 10

================================================================
4. QUALITY GATE CONCEPT (SonarQube)
================================================================

A Quality Gate is a set of conditions that must pass before code
can be merged/deployed.

Typical conditions:
  - Coverage on new code >= 80%
  - Duplicated lines on new code < 3%
  - Maintainability rating on new code = A
  - Reliability rating = A (no new bugs)
  - Security rating = A (no new vulnerabilities)
  - Security hotspots reviewed = 100%

If the gate FAILS → merge is blocked or deployment is prevented.

6. INTERVIEW QUESTIONS
================================================================

Q: What is the difference between code coverage and code quality?
A: Coverage measures the percentage of code executed by tests — it's a
   quantity metric. Code quality is broader: it includes correctness, 
   readability, security, and maintainability. High coverage doesn't
   guarantee quality (tests can cover code without meaningful assertions).

Q: Can you have 100% coverage but still have bugs?
A: Yes. Coverage only means lines were executed, not that the behavior
   was correctly verified. A test that exercises code but has no assertions
   counts as 100% covered. Mutation testing addresses this gap.

Q: What is the "Quality Gate" concept?
A: A configurable set of conditions that code must meet before being
   considered "production-ready." In SonarQube, you can define thresholds
   for coverage, bugs, vulnerabilities, duplications, etc. A broken gate
   blocks merges or deployments in CI/CD.

Q: Name three tools you would add to a Java Maven build for code quality.
A: JaCoCo (coverage), SpotBugs (static bug detection), and SonarQube
   (aggregated quality gate with historical tracking). Add Checkstyle
   for style enforcement and PIT for mutation testing for full coverage.
