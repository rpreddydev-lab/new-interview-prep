================================================================================
CONTRACT TESTING WITH PACT
================================================================================

WHY CONTRACT TESTING?
----------------------
In microservices, Service A (consumer) calls Service B (provider).
They agree on an API contract (request/response shape).
Both teams evolve independently. Service B changes its API. Service A breaks.
This is discovered in production. 💥

Contract testing catches this early — before deployment.

Consumer-Driven Contract Testing (CDCT):
  - The CONSUMER defines what it needs from the provider
  - The consumer's test generates a contract (Pact file)
  - The provider verifies it can fulfill the contract
  - Neither team needs to know about the other's tests

  [Order Service]              [Inventory Service]
  Consumer                      Provider
  "I call GET /inventory/items/123"  "I provide GET /inventory/items/{id}"
  "I expect: {available: true, quantity: 100}"

PACT FRAMEWORK OVERVIEW
========================

Pact is the standard for Consumer-Driven Contract Testing.

Flow:
  1. Consumer writes a Pact test: defines interactions (what it sends, what it expects)
  2. Pact generates a pact file (JSON contract specification)
  3. Pact file is published to Pact Broker (central contract registry)
  4. Provider runs pact verification: replays consumer interactions, checks responses
  5. If verification fails → deployment blocked (breaking change detected!)

  Consumer Test → [Pact Broker] ← Provider Verification
                  (contracts)

CONSUMER SIDE — PACT TEST
===========================

Order Service (consumer) tests what it expects from Inventory Service:

  # pom.xml (consumer)
  <dependency>
    <groupId>au.com.dius.pact.consumer</groupId>
    <artifactId>junit5</artifactId>
    <version>4.6.12</version>
    <scope>test</scope>
  </dependency>

  @ExtendWith(PactConsumerTestExt.class)
  @PactTestFor(providerName = "inventory-service", port = "8090")
  class InventoryClientContractTest {

    @Pact(provider = "inventory-service", consumer = "order-service")
    public RequestResponsePact getInventoryItemPact(PactDslWithProvider builder) {
      return builder
        .given("product 100 exists and is in stock")
        .uponReceiving("a request for product 100 inventory")
          .path("/inventory/items/100")
          .method("GET")
          .headers("Accept", "application/json")
        .willRespondWith()
          .status(200)
          .body(new PactDslJsonBody()
            .integerType("productId", 100)
            .booleanValue("available", true)
            .integerType("quantity", 50)
          )
        .toPact();
    }

    @Test
    @PactTestFor(pactMethod = "getInventoryItemPact")
    void shouldGetInventoryItem(MockServer mockServer) {
      // Configure client to use Pact's mock server
      InventoryServiceClient client = InventoryServiceClient.builder()
        .baseUrl(mockServer.getUrl())
        .build();

      // When
      InventoryItem item = client.getInventory(100L);

      // Then — verify client correctly maps the response
      assertThat(item.getProductId()).isEqualTo(100L);
      assertThat(item.isAvailable()).isTrue();
      assertThat(item.getQuantity()).isGreaterThan(0);
    }

    @Pact(provider = "inventory-service", consumer = "order-service")
    public RequestResponsePact productNotFoundPact(PactDslWithProvider builder) {
      return builder
        .given("product 999 does not exist")
        .uponReceiving("a request for non-existent product 999")
          .path("/inventory/items/999")
          .method("GET")
        .willRespondWith()
          .status(404)
          .body(new PactDslJsonBody()
            .stringType("error", "Product not found")
          )
        .toPact();
    }

    @Test
    @PactTestFor(pactMethod = "productNotFoundPact")
    void shouldHandleProductNotFound(MockServer mockServer) {
      InventoryServiceClient client = InventoryServiceClient.builder()
        .baseUrl(mockServer.getUrl())
        .build();

      assertThatThrownBy(() -> client.getInventory(999L))
        .isInstanceOf(ProductNotFoundException.class);
    }
  }

PROVIDER SIDE — PACT VERIFICATION
=====================================

Inventory Service (provider) verifies it fulfills all consumer contracts:

  # pom.xml (provider)
  <dependency>
    <groupId>au.com.dius.pact.provider</groupId>
    <artifactId>junit5spring</artifactId>
    <version>4.6.12</version>
    <scope>test</scope>
  </dependency>

  @Provider("inventory-service")
  @PactBroker(
    url = "https://pact-broker.example.com",
    authentication = @PactBrokerAuth(username = "${PACT_BROKER_USER}", password = "${PACT_BROKER_PASSWORD}"),
    consumerVersionSelectors = @VersionSelector(mainBranch = true)
  )
  @SpringBootTest(webEnvironment = RANDOM_PORT)
  class InventoryServiceContractVerificationTest {

    @LocalServerPort
    private int port;

    @BeforeEach
    void setUp(PactVerificationContext context) {
      context.setTarget(new HttpTestTarget("localhost", port));
    }

    @TestTemplate
    @ExtendWith(PactVerificationInvocationContextProvider.class)
    void verifyPact(PactVerificationContext context) {
      context.verifyInteraction();
    }

    // State handlers — set up test data matching consumer's "given" states
    @State("product 100 exists and is in stock")
    public void productInStock() {
      // Insert test data into test DB (TestContainers)
      inventoryRepository.save(InventoryItem.builder()
        .productId(100L)
        .quantity(50)
        .available(true)
        .build()
      );
    }

    @State("product 999 does not exist")
    public void productNotFound() {
      // Ensure product 999 is not in DB
      inventoryRepository.deleteByProductId(999L);
    }
  }

PACT BROKER
============

Central contract registry for storing and sharing pact files.

  # docker-compose.yml — run Pact Broker locally
  pact-broker:
    image: pactfoundation/pact-broker:latest
    ports:
      - "9292:9292"
    environment:
      PACT_BROKER_DATABASE_URL: postgresql://pact:password@postgres/pact
    depends_on:
      - postgres

  # Publish pacts from consumer CI:
  mvn pact:publish -Dpact.broker.url=http://pact-broker:9292

  # CI/CD integration — deploy only if contracts verified:
  # can-i-deploy check before deploying
  pact-broker can-i-deploy \
    --pacticipant order-service \
    --version 1.2.3 \
    --to-environment production

INTERVIEW QUESTIONS
====================

Q: What is Consumer-Driven Contract Testing?
A: The consumer defines what it needs from the provider (the contract). The
   consumer's test generates a pact file. The provider verifies it fulfills
   every consumer's contract. Catches breaking API changes before deployment,
   without needing both services running simultaneously.

Q: What is the Pact Broker?
A: A central registry that stores pact files from consumers and verification
   results from providers. Enables `can-i-deploy` checks — blocks deployment
   if a service would break existing consumer contracts. Essential for CI/CD
   pipeline integration.

Q: What's the difference between contract testing and integration testing?
A: Integration testing: starts real services (or TestContainers) and verifies
   actual communication works. Slow but tests real behavior. Contract testing:
   uses stubs/mocks, verifies API agreements without running both services. Fast
   but focused on interface compatibility, not behavior.
