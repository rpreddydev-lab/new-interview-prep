KUBERNETES OVERVIEW
--------------------
Kubernetes (K8s) is the standard container orchestration platform.
It manages running, scaling, networking, and health of containerized services.

Key abstractions:
  Pod:          Smallest deployable unit. One or more containers sharing network/storage.
  Deployment:   Manages ReplicaSets for stateless services. Handles rolling updates.
  StatefulSet:  For stateful services (databases). Stable network IDs and storage.
  Service:      Stable network endpoint for a set of pods. Load balancing.
  ConfigMap:    Non-sensitive configuration key-value pairs.
  Secret:       Sensitive configuration (passwords, tokens) — base64 encoded.
  Ingress:      HTTP/HTTPS routing to services. API Gateway at cluster edge.
  Namespace:    Logical isolation. One namespace per microservice team/environment.
  HPA:          Horizontal Pod Autoscaler — scales based on CPU/memory/custom metrics.

COMPLETE MICROSERVICE DEPLOYMENT MANIFESTS
=============================================

# order-service-deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: order-service
  namespace: production
  labels:
    app: order-service
    version: "1.2.3"
spec:
  replicas: 3
  selector:
    matchLabels:
      app: order-service
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxSurge: 1        # Create 1 extra pod during update
      maxUnavailable: 0  # Never have less than desired replicas running
  template:
    metadata:
      labels:
        app: order-service
        version: "1.2.3"
      annotations:
        prometheus.io/scrape: "true"
        prometheus.io/path: "/actuator/prometheus"
        prometheus.io/port: "8080"
    spec:
      serviceAccountName: order-service-sa
      securityContext:
        runAsNonRoot: true
        runAsUser: 1000
        fsGroup: 2000

      # Anti-affinity: spread pods across nodes
      affinity:
        podAntiAffinity:
          preferredDuringSchedulingIgnoredDuringExecution:
          - weight: 100
            podAffinityTerm:
              labelSelector:
                matchExpressions:
                - key: app
                  operator: In
                  values:
                  - order-service
              topologyKey: kubernetes.io/hostname

      containers:
      - name: order-service
        image: myregistry.io/order-service:1.2.3
        imagePullPolicy: Always
        ports:
        - containerPort: 8080
          name: http

        env:
        - name: SPRING_PROFILES_ACTIVE
          value: "production"
        - name: SPRING_DATASOURCE_URL
          value: "jdbc:postgresql://postgres-service:5432/orders"
        - name: SPRING_DATASOURCE_USERNAME
          valueFrom:
            secretKeyRef:
              name: order-service-secrets
              key: db-username
        - name: SPRING_DATASOURCE_PASSWORD
          valueFrom:
            secretKeyRef:
              name: order-service-secrets
              key: db-password
        - name: JAVA_TOOL_OPTIONS
          value: "-XX:+UseContainerSupport -XX:MaxRAMPercentage=75.0"

        resources:
          requests:
            cpu: "250m"       # 0.25 CPU guaranteed
            memory: "256Mi"   # 256MB guaranteed
          limits:
            cpu: "1000m"      # Max 1 CPU
            memory: "512Mi"   # Max 512MB (OOM kill if exceeded)

        livenessProbe:
          httpGet:
            path: /actuator/health/liveness
            port: 8080
          initialDelaySeconds: 30
          periodSeconds: 10
          failureThreshold: 3
          timeoutSeconds: 5

        readinessProbe:
          httpGet:
            path: /actuator/health/readiness
            port: 8080
          initialDelaySeconds: 15
          periodSeconds: 5
          failureThreshold: 3

        startupProbe:
          httpGet:
            path: /actuator/health/liveness
            port: 8080
          failureThreshold: 30
          periodSeconds: 10

        lifecycle:
          preStop:
            exec:
              # Give load balancer time to remove pod before shutdown
              command: ["/bin/sh", "-c", "sleep 5"]

      terminationGracePeriodSeconds: 60

---
# Service
apiVersion: v1
kind: Service
metadata:
  name: order-service
  namespace: production
spec:
  selector:
    app: order-service
  ports:
  - port: 8080
    targetPort: 8080
    name: http
  type: ClusterIP  # Internal only; exposed via Ingress

---
# Ingress
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: order-service-ingress
  annotations:
    nginx.ingress.kubernetes.io/rewrite-target: /
    cert-manager.io/cluster-issuer: "letsencrypt-prod"
spec:
  tls:
  - hosts:
    - api.example.com
    secretName: api-tls
  rules:
  - host: api.example.com
    http:
      paths:
      - path: /api/orders
        pathType: Prefix
        backend:
          service:
            name: order-service
            port:
              number: 8080

STATEFULSETS FOR DATABASES
============================

# postgres-statefulset.yaml
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: postgres
  namespace: production
spec:
  serviceName: postgres-headless
  replicas: 1
  selector:
    matchLabels:
      app: postgres
  template:
    metadata:
      labels:
        app: postgres
    spec:
      containers:
      - name: postgres
        image: postgres:16-alpine
        ports:
        - containerPort: 5432
        env:
        - name: POSTGRES_DB
          value: orders
        - name: POSTGRES_PASSWORD
          valueFrom:
            secretKeyRef:
              name: postgres-secret
              key: password
        resources:
          requests:
            memory: "512Mi"
            cpu: "500m"
          limits:
            memory: "2Gi"
            cpu: "2000m"
        volumeMounts:
        - name: postgres-data
          mountPath: /var/lib/postgresql/data

  volumeClaimTemplates:  # Unique PVC per pod
  - metadata:
      name: postgres-data
    spec:
      accessModes: ["ReadWriteOnce"]
      storageClassName: fast-ssd
      resources:
        requests:
          storage: 100Gi

RESOURCE QUOTAS AND LIMITS
============================

# namespace-resource-quota.yaml
apiVersion: v1
kind: ResourceQuota
metadata:
  name: order-team-quota
  namespace: order-team
spec:
  hard:
    requests.cpu: "10"        # Total CPU requests across all pods
    requests.memory: "20Gi"   # Total memory requests
    limits.cpu: "20"
    limits.memory: "40Gi"
    pods: "50"
    services: "10"

# LimitRange (defaults for pods without explicit limits)
apiVersion: v1
kind: LimitRange
metadata:
  name: default-limits
  namespace: order-team
spec:
  limits:
  - type: Container
    default:        # Applied if not specified
      cpu: "500m"
      memory: "256Mi"
    defaultRequest:
      cpu: "100m"
      memory: "128Mi"
    max:
      cpu: "2"
      memory: "2Gi"

INTERVIEW QUESTIONS
====================

Q: What is the difference between a Deployment and a StatefulSet?
A: Deployment: manages stateless pods. Pods are interchangeable (any pod can be
   replaced). No stable identity or storage. StatefulSet: manages stateful pods.
   Each pod has a stable hostname (pod-0, pod-1), ordered startup/shutdown, and
   its own PersistentVolumeClaim. Use StatefulSet for databases, Kafka, Zookeeper.

Q: What are resource requests vs limits in Kubernetes?
A: Requests: minimum guaranteed resources. Used for scheduling (K8s places the
   pod on a node with sufficient available resources). Limits: maximum resources.
   If exceeded: CPU is throttled, memory causes OOM kill. Always set both —
   pods without limits can starve other pods on the same node.

Q: What is pod anti-affinity?
A: Scheduling rule that prefers/requires pods to be on different nodes. Prevents
   all replicas from being on the same node (single node failure = service down).
   `podAntiAffinity.preferredDuringSchedulingIgnoredDuringExecution` is soft
   (best effort), `requiredDuringScheduling...` is hard (pod won't schedule if
   no node available).

Q: What does maxSurge and maxUnavailable mean in rolling updates?
A: maxSurge: number of extra pods created above desired count during update.
   maxUnavailable: number of pods that can be unavailable during update.
   Common setting: maxSurge=1, maxUnavailable=0 means create one new pod first,
   verify it's healthy, then delete one old pod — zero-downtime rolling update.
