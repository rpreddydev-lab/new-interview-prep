RABBITMQ vs KAFKA vs AWS SQS
============================

AMQP Protocol (RabbitMQ's primary protocol):
- Advanced Message Queuing Protocol
- Binary protocol with built-in reliability features
- Version 0-9-1 most commonly used with RabbitMQ
- Defines: connections, channels, exchanges, queues, bindings, consumers

Detailed Comparison:

1. MESSAGE MODEL
   RabbitMQ: queue-based — message is consumed once and deleted
   Kafka:     log-based — message persisted, multiple consumer groups can replay
   SQS:       queue-based — message deleted after visibility timeout + ack

2. ROUTING FLEXIBILITY
   RabbitMQ: very flexible — 4 exchange types, header matching
   Kafka:     topic partitions only — producers control partition via key
   SQS:       none — send directly to queue or SNS fan-out

3. DELIVERY SEMANTICS
   RabbitMQ: at-most-once (auto-ack), at-least-once (manual ack)
   Kafka:     at-least-once by default, exactly-once with transactions
   SQS:       at-least-once (standard), FIFO supports exactly-once

4. ORDERING
   RabbitMQ: FIFO within a queue (single consumer); not guaranteed with multiple
   Kafka:     ordered within a partition
   SQS:       standard = no order; FIFO = ordered per message group

5. PERFORMANCE/THROUGHPUT
   RabbitMQ: ~50K-100K messages/sec per node
   Kafka:     millions/sec per cluster
   SQS:       managed, scales automatically

6. MESSAGE SIZE
   RabbitMQ: 128MB max (configurable)
   Kafka:     1MB default, configurable
   SQS:       256KB (standard), 2GB with S3 extended

7. USE CASES
   RabbitMQ: task queues, RPC, complex routing, workflows
   Kafka:     event streaming, audit logs, CQRS, ETL pipelines
   SQS:       cloud-native decoupling, serverless, AWS ecosystem

When to Choose RabbitMQ over Kafka:
- Short-lived messages (no replay needed)
- Complex routing requirements
- RPC-style request/reply communication
- Smaller scale, simpler infrastructure
- You need per-message acknowledgement control

When to Choose Kafka over RabbitMQ:
- High throughput event streaming
- Message replay / event sourcing
- Multiple consumer groups reading same data
- Long retention requirements
- Analytics pipelines

Interview Question: "Why would you choose RabbitMQ over Kafka?"
Answer: RabbitMQ is better for task queues, RPC, complex routing (topic/fanout/
header exchanges), and scenarios where messages are consumed once and don't 
need replay. Kafka is better for high-throughput event streaming with replay.
