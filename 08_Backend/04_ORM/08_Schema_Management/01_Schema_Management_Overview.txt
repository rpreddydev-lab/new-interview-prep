1. WHY SCHEMA MANAGEMENT MATTERS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Every application that uses a relational database needs a strategy to:
  1. Create the initial schema (tables, indexes, constraints)
  2. Evolve the schema as the application changes
  3. Maintain consistency across environments (dev, test, prod)

Three approaches:
  Hibernate DDL Auto  — auto-generates schema from entities (dev only)
  Flyway              — version-controlled SQL migrations
  Liquibase           — XML/YAML/SQL migrations with changelog tracking

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
2. HIBERNATE DDL-AUTO (Dev Only)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

spring.jpa.hibernate.ddl-auto controls what Hibernate does to the DB schema
on application startup.

Value      | Description                                      | Use
───────────|──────────────────────────────────────────────────|─────────────────────────
none       | Do nothing (no DDL)                              | Production (manual schema)
validate   | Validate schema matches entities; fail if not    | Pre-prod / staging
update     | Alter tables to match entities (add cols only)   | NEVER in production!
create     | Drop + create schema on startup                  | Testing (fresh DB each run)
create-drop| Create on start, drop on stop                    | Unit tests / H2

Production rule: NEVER use create, create-drop, or update in production.
Use none or validate + Flyway/Liquibase for actual migrations.

See: 01_Hibernate_DDL_Auto.txt

3. FLYWAY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Flyway runs versioned SQL scripts in order (V1, V2, V3...).
Each script runs exactly ONCE and is recorded in a flyway_schema_history table.

Migration file naming: V{version}__{description}.sql
  V1__create_users_table.sql
  V2__add_email_index.sql
  V3__add_orders_table.sql

Spring Boot auto-integration:
  flyway.locations=classpath:db/migration
  All scripts in db/migration run automatically on startup in order.

See: 02_Flyway_Database_Migrations.txt

4. LIQUIBASE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Liquibase uses a changelog file (XML/YAML/JSON/SQL) with changesets.
Each changeset has an author and ID; each runs once and is recorded.

Benefits over Flyway:
  - Database-agnostic changeset syntax (no SQL required for simple ops)
  - Rollback support built-in
  - Preconditions (run only if condition met)
  - YAML/XML/JSON format in addition to SQL

See: 03_Liquibase_Database_Migrations.txt

5. FLYWAY vs LIQUIBASE QUICK COMPARISON
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Aspect               | Flyway                      | Liquibase
─────────────────────|─────────────────────────────|──────────────────────────────
Migration format     | Plain SQL                   | XML/YAML/JSON/SQL
Learning curve       | Low (pure SQL)              | Medium (own DSL)
DB-agnostic syntax   | NO (SQL is DB-specific)     | YES (createTable, addColumn)
Rollback support     | Manual (Flyway Pro)         | Built-in
Spring Boot support  | Auto-configured             | Auto-configured
History table        | flyway_schema_history       | databasechangelog
Popularity           | Simpler, very popular       | More features, enterprise

6. INTERVIEW QUICK HITS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: Why should you NOT use spring.jpa.hibernate.ddl-auto=update in production?
A: "update" only adds new columns and creates new tables — it never drops
   columns, removes constraints, or handles complex schema changes. It can
   silently produce inconsistent schema states and has no audit trail.
   Use Flyway or Liquibase for controlled, versioned, auditable migrations.

Q: How does Flyway know which migrations have already been applied?
A: Flyway stores a checksum and version of each applied migration in the
   flyway_schema_history table. On each startup, it compares this history
   against the available migration files and runs only those not yet applied.

Q: Can Flyway and Hibernate DDL auto coexist?
A: Yes. Typically set ddl-auto=validate (Hibernate validates schema against
   entities) and let Flyway manage the actual DDL. This ensures your entities
   match the schema without Hibernate modifying it.
