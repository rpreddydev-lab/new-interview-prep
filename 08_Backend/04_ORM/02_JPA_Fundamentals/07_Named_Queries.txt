1. WHAT ARE NAMED QUERIES?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Named Queries are pre-defined, static JPQL or SQL queries registered
at startup with a unique name. They are:
  ✓ Compiled and validated when the application starts
  ✓ Parsed once, cached → slightly more efficient
  ✓ Reusable across the application by name
  ✓ Kept close to the entity (good for organization)

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
2. @NAMEDQUERY — JPQL NAMED QUERY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Define on the entity class:

@Entity
@Table(name = "users")
@NamedQuery(
    name = "User.findByEmail",
    query = "SELECT u FROM User u WHERE u.email = :email"
)
@NamedQuery(
    name = "User.findActiveUsers",
    query = "SELECT u FROM User u WHERE u.active = true ORDER BY u.lastName ASC"
)
public class User {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    private String email;
    private boolean active;
    private String lastName;
    // ...
}

// Multiple queries: use @NamedQueries wrapper
@Entity
@NamedQueries({
    @NamedQuery(name = "User.findByEmail",
                query = "SELECT u FROM User u WHERE u.email = :email"),
    @NamedQuery(name = "User.findByStatus",
                query = "SELECT u FROM User u WHERE u.active = :active")
})
public class User { ... }

Executing:
  User user = em.createNamedQuery("User.findByEmail", User.class)
                .setParameter("email", "alice@example.com")
                .getSingleResult();

  List<User> active = em.createNamedQuery("User.findActiveUsers", User.class)
                        .getResultList();

3. @NAMEDNATIVEQUERY — NATIVE SQL NAMED QUERY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

For database-specific SQL or complex queries:

@Entity
@NamedNativeQuery(
    name = "User.findTopSpenders",
    query = """
        SELECT u.id, u.email, SUM(o.total) as total_spent
        FROM users u
        JOIN orders o ON o.user_id = u.id
        GROUP BY u.id, u.email
        ORDER BY total_spent DESC
        LIMIT 10
        """,
    resultClass = User.class    // maps to User entity if columns match
)
public class User { ... }

// With custom result mapping:
@NamedNativeQuery(
    name = "User.topSpenderReport",
    query = "SELECT u.id, u.email, SUM(o.total) as total_spent " +
            "FROM users u JOIN orders o ON o.user_id = u.id " +
            "GROUP BY u.id, u.email ORDER BY total_spent DESC",
    resultSetMapping = "TopSpenderMapping"
)
@SqlResultSetMapping(
    name = "TopSpenderMapping",
    classes = @ConstructorResult(
        targetClass = TopSpenderDto.class,
        columns = {
            @ColumnResult(name = "id", type = Long.class),
            @ColumnResult(name = "email"),
            @ColumnResult(name = "total_spent", type = BigDecimal.class)
        }
    )
)
public class User { ... }

Executing:
  List<TopSpenderDto> result = em
      .createNamedQuery("User.topSpenderReport", TopSpenderDto.class)
      .getResultList();

4. NAMING CONVENTION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

JPA convention: "EntityName.methodName"
  ✓ "User.findByEmail"
  ✓ "Order.findByUserAndStatus"
  ✓ "Product.findActiveInCategory"

Spring Data JPA automatically maps named queries:
  If interface method findByEmail() exists AND @NamedQuery "User.findByEmail"
  is defined, Spring Data JPA uses the named query automatically.

5. NAMED QUERIES WITH QUERY HINTS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

@NamedQuery(
    name = "User.findActive",
    query = "SELECT u FROM User u WHERE u.active = true",
    hints = {
        @QueryHint(name = "org.hibernate.cacheable", value = "true"),
        @QueryHint(name = "org.hibernate.cacheRegion", value = "user.active"),
        @QueryHint(name = "org.hibernate.readOnly", value = "true"),
        @QueryHint(name = "jakarta.persistence.query.timeout", value = "5000")
    }
)

6. NAMED QUERIES vs @QUERY IN SPRING DATA JPA
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

@NamedQuery (on entity)             | @Query (on repository method)
────────────────────────────────────|─────────────────────────────────
Defined on entity class             | Defined on repository interface
Shared across whole app             | Local to repository
Validated at startup                | Validated at startup
Can add hints with @QueryHint       | Can add hints with @QueryHints
Kept close to entity model          | Kept close to query usage
Verbose (especially with many)      | Concise, inline
Legacy / Enterprise style           | Preferred in Spring Boot apps

Modern Spring Boot preference: use @Query on repository methods.
Named Queries are more common in Jakarta EE / legacy JPA.

7. USING NAMED QUERIES FROM SPRING DATA JPA REPOSITORY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

If you define @NamedQuery(name = "User.findByEmail", ...),
Spring Data JPA picks it up automatically for the method:

public interface UserRepository extends JpaRepository<User, Long> {
    // Spring Data looks for @NamedQuery "User.findByEmail" first
    Optional<User> findByEmail(String email);

    // Explicitly use a named query:
    @Query(name = "User.findActiveUsers")
    List<User> findActiveUsers();
}

8. INTERVIEW QUICK HITS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: What is a Named Query in JPA?
A: A pre-defined, named JPQL or native SQL query declared using @NamedQuery
   on an entity class. It is compiled and validated at application startup,
   cached, and reusable by name via em.createNamedQuery().

Q: What is the advantage of Named Queries over inline JPQL?
A: Named queries are validated at startup (fail fast), compiled once
   (slight performance benefit), and encourage organizing queries with the
   entity they belong to. However, @Query on Spring Data repositories is
   equally validated at startup and generally preferred in Spring apps.

Q: How does Spring Data JPA relate to Named Queries?
A: Spring Data JPA looks for a @NamedQuery matching the pattern
   "EntityName.methodName" before generating a query from the method name.
   If found, it uses the named query. If not, it derives the query from
   the method name or uses @Query.

Q: What is @SqlResultSetMapping?
A: A JPA annotation to map the result columns of a native query to a DTO
   or entity. Used with @NamedNativeQuery. Supports mapping to entity
   classes, constructor calls, and scalar column results.
