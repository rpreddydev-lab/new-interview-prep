JPA 2.1+ supports calling stored procedures via:
  - StoredProcedureQuery (JPA API)
  - @NamedStoredProcedureQuery (declarative)
  - Spring Data JPA @Procedure

When to use stored procedures:
  ✓ Legacy systems with existing business logic in DB
  ✓ Complex multi-step DB operations
  ✓ Performance-critical batch processing
  ✓ DBA-mandated data access policies

2. DATABASE STORED PROCEDURE EXAMPLES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

MySQL Procedure (simple):
  DELIMITER $$
  CREATE PROCEDURE get_user_by_email(IN p_email VARCHAR(255))
  BEGIN
      SELECT * FROM users WHERE email = p_email;
  END $$
  DELIMITER ;

MySQL Procedure (IN + OUT params):
  DELIMITER $$
  CREATE PROCEDURE count_user_orders(
      IN p_user_id BIGINT,
      OUT p_order_count INT
  )
  BEGIN
      SELECT COUNT(*) INTO p_order_count
      FROM orders WHERE user_id = p_user_id;
  END $$
  DELIMITER ;

PostgreSQL Procedure:
  CREATE OR REPLACE FUNCTION get_user_by_email(p_email VARCHAR)
  RETURNS SETOF users AS $$
  BEGIN
      RETURN QUERY SELECT * FROM users WHERE email = p_email;
  END;
  $$ LANGUAGE plpgsql;

3. CALLING STORED PROCEDURES VIA ENTITYMANAGER
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

// Simple IN parameter, returns result set mapped to entity
StoredProcedureQuery query = em.createStoredProcedureQuery(
    "get_user_by_email", User.class);
query.registerStoredProcedureParameter("p_email", String.class,
    ParameterMode.IN);
query.setParameter("p_email", "alice@example.com");
List<User> users = query.getResultList();

// IN + OUT parameters
StoredProcedureQuery countQuery = em.createStoredProcedureQuery(
    "count_user_orders");
countQuery.registerStoredProcedureParameter(1, Long.class, ParameterMode.IN);
countQuery.registerStoredProcedureParameter(2, Integer.class, ParameterMode.OUT);
countQuery.setParameter(1, userId);
countQuery.execute();
Integer count = (Integer) countQuery.getOutputParameterValue(2);

4. @NAMEDSTOREDPROCEDUREQUERY — DECLARATIVE APPROACH
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

@Entity
@NamedStoredProcedureQuery(
    name = "User.getByEmail",
    procedureName = "get_user_by_email",
    resultClasses = User.class,
    parameters = {
        @StoredProcedureParameter(
            name = "p_email",
            type = String.class,
            mode = ParameterMode.IN
        )
    }
)
@NamedStoredProcedureQuery(
    name = "User.countOrders",
    procedureName = "count_user_orders",
    parameters = {
        @StoredProcedureParameter(name = "p_user_id", type = Long.class, mode = ParameterMode.IN),
        @StoredProcedureParameter(name = "p_order_count", type = Integer.class, mode = ParameterMode.OUT)
    }
)
public class User { ... }

// Usage:
StoredProcedureQuery q = em.createNamedStoredProcedureQuery("User.getByEmail");
q.setParameter("p_email", email);
List<User> users = q.getResultList();

StoredProcedureQuery cq = em.createNamedStoredProcedureQuery("User.countOrders");
cq.setParameter("p_user_id", userId);
cq.execute();
Integer count = (Integer) cq.getOutputParameterValue("p_order_count");

5. SPRING DATA JPA @PROCEDURE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Spring Data JPA provides a clean @Procedure annotation:

@Repository
public interface UserRepository extends JpaRepository<User, Long> {

    // Calls stored procedure "get_user_by_email"
    // Method name (or @Procedure.value) matches procedure name
    @Procedure(name = "User.getByEmail")
    List<User> getUserByEmail(String p_email);

    // Or reference procedure by name directly:
    @Procedure(procedureName = "count_user_orders")
    Integer countUserOrders(Long p_user_id);

    // Simple case: procedure name = method name (by convention)
    @Procedure
    String myStoredProcedure(String param1);
}

6. CALLING STORED PROCEDURES VIA JDBC (ALTERNATIVE)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

For complex procedures, using JDBC directly via Spring's SimpleJdbcCall
is often cleaner:

@Service
public class UserStoredProcService {

    private final SimpleJdbcCall countOrdersProc;

    public UserStoredProcService(DataSource dataSource) {
        this.countOrdersProc = new SimpleJdbcCall(dataSource)
            .withProcedureName("count_user_orders")
            .declareParameters(
                new SqlParameter("p_user_id", Types.BIGINT),
                new SqlOutParameter("p_order_count", Types.INTEGER)
            );
    }

    public int countOrders(Long userId) {
        MapSqlParameterSource params = new MapSqlParameterSource()
            .addValue("p_user_id", userId);
        Map<String, Object> result = countOrdersProc.execute(params);
        return (Integer) result.get("p_order_count");
    }
}

Q: How do you call a stored procedure in JPA?
A: Using em.createStoredProcedureQuery("procedureName"), registering
   parameters with registerStoredProcedureParameter(), setting values,
   calling execute() or getResultList(), then reading OUT params.
   Alternatively use @NamedStoredProcedureQuery on the entity.

Q: What is @Procedure in Spring Data JPA?
A: A Spring Data JPA annotation on a repository method that maps the
   method to a stored procedure call. Works with @NamedStoredProcedureQuery
   or by convention (procedure name = method name).

Q: When would you use a stored procedure over JPQL/native query?
A: When the procedure already exists in a legacy system, when the DB logic
   is complex/multi-step and maintained by a DBA team, or when DB-side
   computation is significantly faster than application-level processing.
   Otherwise, prefer application-layer business logic for maintainability.
