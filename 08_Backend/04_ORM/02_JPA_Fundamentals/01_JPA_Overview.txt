1. WHAT IS JPA?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

JPA (Jakarta Persistence API, formerly Java Persistence API) is a
Java specification for object-relational mapping. It defines:
  - Annotations to map Java classes to DB tables
  - APIs to manage entity lifecycle
  - Query language (JPQL) and Criteria API
  - Transaction semantics and caching contracts

JPA is NOT an implementation. It is a set of interfaces + annotations.
You need a JPA provider (Hibernate, EclipseLink) to run it.

Package History:
  javax.persistence.*     → JPA 2.x (Java EE)
  jakarta.persistence.*   → JPA 3.x (Jakarta EE, used in Spring Boot 3+)

┌─────────────────────────────────────────────────────────────┐
│  EntityManagerFactory                                        │
│  - Created once at app startup (expensive)                   │
│  - Thread-safe, application-scoped                           │
│  - Corresponds to one persistence unit (one DB)              │
│                                                              │
│    ┌───────────────────────────────────────────────────┐     │
│    │  EntityManager                                    │     │
│    │  - Created per request/transaction (cheap)        │     │
│    │  - NOT thread-safe — never share between threads  │     │
│    │  - Manages the Persistence Context (1st lvl cache)│     │
│    │                                                   │     │
│    │  Persistence Context (1st Level Cache)            │     │
│    │  - Map<(Class, ID) → Entity Instance>             │     │
│    │  - All managed entities tracked here              │     │
│    │  - Flushed to DB on commit/flush                  │     │
│    └───────────────────────────────────────────────────┘     │
└─────────────────────────────────────────────────────────────┘

Without Spring (plain JPA configuration):

<!-- src/main/resources/META-INF/persistence.xml -->
<persistence xmlns="https://jakarta.ee/xml/ns/persistence" version="3.0">
    <persistence-unit name="myPU" transaction-type="RESOURCE_LOCAL">
        <provider>org.hibernate.jpa.HibernatePersistenceProvider</provider>
        <class>com.example.User</class>
        <class>com.example.Order</class>
        <properties>
            <property name="jakarta.persistence.jdbc.driver"
                      value="com.mysql.cj.jdbc.Driver"/>
            <property name="jakarta.persistence.jdbc.url"
                      value="jdbc:mysql://localhost:3306/mydb"/>
            <property name="jakarta.persistence.jdbc.user" value="root"/>
            <property name="jakarta.persistence.jdbc.password" value="secret"/>
            <property name="hibernate.hbm2ddl.auto" value="update"/>
            <property name="hibernate.show_sql" value="true"/>
        </properties>
    </persistence-unit>
</persistence>

// Bootstrap without Spring:
EntityManagerFactory emf =
    Persistence.createEntityManagerFactory("myPU");
EntityManager em = emf.createEntityManager();

Spring Boot auto-configures:
  - DataSource (via spring.datasource.*)
  - EntityManagerFactory
  - PlatformTransactionManager
  - LocalContainerEntityManagerFactoryBean

# application.yml
spring:
  datasource:
    url: jdbc:postgresql://localhost:5432/mydb
    username: postgres
    password: secret
  jpa:
    hibernate:
      ddl-auto: validate     # never change schema in production!
    show-sql: true
    properties:
      hibernate:
        format_sql: true
        jdbc:
          batch_size: 50
        order_inserts: true
        order_updates: true

6. JPA ENTITY — FULL EXAMPLE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

@Entity
@Table(name = "users",
       uniqueConstraints = @UniqueConstraint(columnNames = "email"),
       indexes = @Index(name = "idx_user_email", columnList = "email"))
@EntityListeners(AuditingEntityListener.class)
public class User {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(name = "first_name", nullable = false, length = 50)
    private String firstName;

    @Column(name = "email", nullable = false, unique = true)
    private String email;

    @Enumerated(EnumType.STRING)
    @Column(name = "role", nullable = false)
    private Role role;

    @Column(name = "active", nullable = false)
    private boolean active = true;

    @CreatedDate
    @Column(name = "created_at", updatable = false)
    private LocalDateTime createdAt;

    @LastModifiedDate
    @Column(name = "updated_at")
    private LocalDateTime updatedAt;

    @Version
    private Long version;

    @OneToMany(mappedBy = "user", cascade = CascadeType.ALL,
               orphanRemoval = true, fetch = FetchType.LAZY)
    private List<Order> orders = new ArrayList<>();

    // constructors, getters, setters, equals/hashCode based on id
}

Q: What is a persistence unit?
A: A named configuration block in persistence.xml that defines the DB
   connection, entity classes, and ORM properties for one DataSource.

Q: Is EntityManager thread-safe?
A: No. It must be scoped to a single thread/transaction. Spring manages
   this with @Transactional and thread-local proxies.

Q: What is the difference between EntityManagerFactory and EntityManager?
A: EMF is application-scoped, heavy, created once (like DataSource).
   EM is request/transaction-scoped, lightweight, proxied by Spring.

Q: What is a persistence context?
A: A first-level cache managed by EntityManager. Every entity you load
   or persist within a transaction is tracked here. On flush/commit,
   changes are synchronized to DB via generated SQL.

Q: How does JPA achieve database portability?
A: JPQL is compiled to database-specific SQL by the JPA provider.
   You write JPQL; Hibernate generates MySQL/PostgreSQL/Oracle SQL.
