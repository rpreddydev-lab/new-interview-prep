Column and Table Customization in JPA/Hibernate
================================================================

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1. @COLUMN ATTRIBUTES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

@Column(
    name            = "email_address",    // DB column name (default: field name, snake_case)
    nullable        = false,              // NOT NULL constraint
    unique          = true,               // UNIQUE constraint (single column)
    length          = 255,                // VARCHAR length (default 255)
    precision       = 15,                 // DECIMAL total digits
    scale           = 2,                  // DECIMAL decimal places
    columnDefinition = "TEXT",            // raw DDL type (overrides JPA defaults)
    insertable      = true,               // include in INSERT (default true)
    updatable       = false               // include in UPDATE (default true) — immutable after creation
)
private String email;

// Common examples:
@Column(name = "created_at", nullable = false, updatable = false)
private LocalDateTime createdAt;  // set once, never changed

@Column(name = "description", columnDefinition = "TEXT")
private String description;  // use TEXT instead of VARCHAR(255)

@Column(name = "price", precision = 10, scale = 2)
private BigDecimal price;  // DECIMAL(10,2)

@Column(name = "is_active", nullable = false)
private boolean active = true;  // BIT/BOOLEAN

2. @TABLE ATTRIBUTES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

@Entity
@Table(
    name    = "app_users",
    schema  = "public",                   // schema name (PostgreSQL)
    catalog = "mydb",                     // catalog name (MySQL)
    uniqueConstraints = {
        @UniqueConstraint(               // multi-column unique constraint
            name    = "uq_user_email_tenant",
            columnNames = {"email", "tenant_id"}
        )
    },
    indexes = {
        @Index(name = "idx_user_email",  columnList = "email"),
        @Index(name = "idx_user_status_created", columnList = "status, created_at DESC")
    }
)
public class User { ... }

// @UniqueConstraint on multiple columns — enforces uniqueness together
// @Index — creates a DB index (does NOT enforce uniqueness)
// Use name= for all constraints for readable SQL error messages

3. @JOINCOLUMN CUSTOMIZATION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

@ManyToOne(fetch = FetchType.LAZY)
@JoinColumn(
    name            = "user_id",          // FK column name in THIS table
    referencedColumnName = "id",          // PK column in referenced table (default: pk)
    nullable        = false,
    foreignKey      = @ForeignKey(name = "fk_order_user")   // named FK constraint
)
private User user;

// Named FK constraints give readable DB errors:
// ERROR: insert or update on table "orders" violates foreign key constraint "fk_order_user"

4. @SECONDARY TABLE — Split Entity Across Two Tables
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Map one entity's fields to a second table (joined by the PK).

@Entity
@Table(name = "users")
@SecondaryTable(
    name = "user_details",
    pkJoinColumns = @PrimaryKeyJoinColumn(name = "user_id")
)
public class User {
    @Id @GeneratedValue private Long id;
    private String email;              // stored in users.email

    @Column(table = "user_details")    // stored in user_details.bio
    private String bio;

    @Column(table = "user_details")
    private String avatarUrl;
}

// SELECT: JOIN users u ON u.id = user_details.user_id
// Use case: legacy schema split or separating infrequently-used columns (LOBs)

5. @LOB — Large Objects
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

@Lob
@Column(name = "content")
private String content;   // Maps to CLOB or TEXT

@Lob
@Column(name = "image_data")
private byte[] imageData;  // Maps to BLOB or BYTEA

// Caveat: @Lob with String can cause performance issues in some DBs.
// Consider using columnDefinition = "TEXT" with @Column instead.

6. @FORMULA — Derived (Computed) Column (Hibernate)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Hibernate-specific: compute a field value via a SQL expression at load time.

@Formula("(SELECT COUNT(*) FROM orders o WHERE o.user_id = id)")
private int orderCount;   // read-only, computed on every SELECT

// Note: uses raw SQL (column/table names, not JPQL)
// No corresponding DB column — only exists in SELECT result

7. NAMING STRATEGY (Spring Boot)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Spring Boot auto-applies SpringPhysicalNamingStrategy by default:
  camelCase Java field → snake_case DB column

  firstName     → first_name
  emailAddress  → email_address
  userId        → user_id
  UserProfile   → user_profile (table)

To override naming strategy:
  spring.jpa.hibernate.naming.physical-strategy=
    org.hibernate.boot.model.naming.PhysicalNamingStrategyStandardImpl
  # Uses field names literally (no conversion)

Or use @Column(name="...") to always be explicit regardless of naming strategy.

8. INTERVIEW QUICK HITS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: What does updatable=false on @Column do?
A: It excludes that column from JPA UPDATE statements. Used for
   immutable fields like createdAt — once set on INSERT, they
   can never be changed via JPA. The DB column value is still
   readable.

Q: What is the difference between @Index and @UniqueConstraint?
A: @Index creates a DB index (for faster lookups) but does not
   enforce uniqueness. @UniqueConstraint creates a unique index
   that enforces uniqueness across the specified columns. Both
   are declared on @Table.

Q: How do you create a multi-column unique constraint in JPA?
A: Use @Table(uniqueConstraints = @UniqueConstraint(columnNames = {"col1", "col2"})).
   Do NOT use @Column(unique=true) for multi-column — that only creates
   a single-column unique constraint.

Q: When would you use @SecondaryTable?
A: When you have a legacy schema that stores some entity data across
   two tables joined by PK (e.g., users + user_details). It lets you
   map both tables to a single Java entity class.

Q: What is @Formula in Hibernate?
A: A Hibernate-specific annotation that computes a read-only field using
   a raw SQL expression. It's executed as a subquery in the SELECT.
   Useful for derived values (counts, sums) without adding a real column.
   It does NOT generate an UPDATE or INSERT.
