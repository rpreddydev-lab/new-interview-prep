PROMETHEUS AND GRAFANA
=======================

=== PROMETHEUS ===

What is Prometheus?
- Open-source monitoring system and time-series database (TSDB)
- Pull-based: scrapes metrics endpoints at configured intervals
- Stores data locally in compressed format
- Has its own query language: PromQL
- CNCF project — de-facto standard for cloud-native monitoring

Architecture:
  Application (/actuator/prometheus)
       ↑ scrape
  Prometheus Server
       ↑ query
  Grafana → dashboards
  Alertmanager → alerts (email, Slack, PagerDuty)

prometheus.yml (scrape config):
  global:
    scrape_interval: 15s

  scrape_configs:
    - job_name: 'spring-app'
      static_configs:
        - targets: ['order-service:8080']
      metrics_path: '/actuator/prometheus'

=== PROMQL BASICS ===

Instant vector: current value
  http_server_requests_seconds_count

Range vector (last 5 min):
  http_server_requests_seconds_count[5m]

Rate (per-second rate over 5 min):
  rate(http_server_requests_seconds_count[5m])

Filter by label:
  http_server_requests_seconds_count{status="500"}

Error rate percentage:
  rate(http_server_requests_seconds_count{status=~"5.."}[5m]) /
  rate(http_server_requests_seconds_count[5m]) * 100

P99 latency (requires histogram):
  histogram_quantile(0.99, rate(http_server_requests_seconds_bucket[5m]))

JVM heap usage:
  jvm_memory_used_bytes{area="heap"} / jvm_memory_max_bytes{area="heap"} * 100

=== ALERTING WITH ALERTMANAGER ===

Alert rules (in Prometheus):
  groups:
    - name: spring-app-alerts
      rules:
        - alert: HighErrorRate
          expr: rate(http_server_requests_seconds_count{status=~"5.."}[5m]) > 0.05
          for: 5m
          labels:
            severity: critical
          annotations:
            summary: "High error rate on {{ $labels.instance }}"
            description: "Error rate is {{ $value | humanizePercentage }}"

        - alert: HighLatency
          expr: histogram_quantile(0.99, rate(http_server_requests_seconds_bucket[5m])) > 2
          for: 2m
          labels:
            severity: warning
          annotations:
            summary: "P99 latency above 2s"

Alertmanager routes alerts to: email, Slack, PagerDuty, OpsGenie, webhooks

=== GRAFANA ===

What is Grafana?
- Open-source visualization and analytics platform
- Connects to Prometheus (and many other data sources)
- Drag-and-drop dashboard builder
- Supports alerts, teams, annotations

Key Grafana features:
- Dashboards with time-series panels, stat panels, tables, heatmaps
- Variables (dropdowns) to filter by service, instance, environment
- Annotations: mark deployment events, incidents on graphs
- Team-based access control

Pre-built dashboards:
- JVM Micrometer dashboard (Grafana ID: 4701) — import directly
- Spring Boot Statistics (Grafana ID: 12685)
- Kafka dashboard (Grafana ID: 7589)

=== KEY METRICS TO MONITOR (Java Services) ===

Category          | Metric                        | Alert Threshold (example)
------------------+-------------------------------+---------------------------
HTTP              | error rate (5xx)              | > 1%
HTTP              | P99 latency                   | > 2 seconds
JVM               | heap usage                    | > 85%
JVM               | GC pause time                 | > 200ms
JVM               | thread count                  | > 500
DB Pool           | hikaricp.pending.threads      | > 0 sustained
DB Pool           | hikaricp.connections.active   | near max
Kafka             | consumer lag                  | > 1000
Cache             | cache hit rate                | < 80%
Disk              | disk free                     | < 10%

=== SERVICE LEVEL INDICATORS (SLIs) and OBJECTIVES (SLOs) ===

SLI: what you measure (e.g., availability, latency, error rate)
SLO: target for SLI (e.g., 99.9% availability, P99 < 500ms)
SLA: contractual agreement with customers based on SLOs

Error budget: 100% - SLO = allowed downtime/errors
- 99.9% SLO → 8.76 hours/year error budget
- Burn rate alerts: alert when consuming budget too fast

Prometheus + Grafana + Alertmanager is the standard OSS stack for SLO monitoring.
