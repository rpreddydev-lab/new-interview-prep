================================================================
  COMPONENT SCANNING AND ANNOTATIONS — IN DEPTH
================================================================

================================================================
WHAT IS COMPONENT SCANNING?
================================================================

  Spring can automatically discover and register beans by scanning
  the classpath for annotated classes — instead of manually
  declaring every bean in XML or @Configuration.

  Trigger: @ComponentScan (or @SpringBootApplication which includes it)

================================================================
@ComponentScan — CONFIGURATION
================================================================

  // Scan all classes in the package of AppConfig and sub-packages
  @Configuration
  @ComponentScan("com.example.myapp")
  public class AppConfig { }

  // Multiple base packages
  @ComponentScan(basePackages = {"com.example.service", "com.example.repo"})

  // Type-safe: use marker classes
  @ComponentScan(basePackageClasses = {ServiceMarker.class, RepoMarker.class})

  // Exclude certain types
  @ComponentScan(
      basePackages = "com.example",
      excludeFilters = @ComponentScan.Filter(
          type = FilterType.ASSIGNABLE_TYPE,
          classes = TestOnlyService.class))

  // Include only annotated with custom annotation
  @ComponentScan(
      basePackages = "com.example",
      includeFilters = @ComponentScan.Filter(
          type = FilterType.ANNOTATION,
          classes = MyCustomAnnotation.class),
      useDefaultFilters = false)

  FilterType options:
    ANNOTATION        -- classes annotated with given annotation
    ASSIGNABLE_TYPE   -- classes that are/extend given type
    ASPECTJ           -- AspectJ type expression
    REGEX             -- regex on class name
    CUSTOM            -- implements TypeFilter

================================================================
STEREOTYPE ANNOTATIONS — FULL DETAILS
================================================================

  ── @Component ──────────────────────────────────────────────────
  Generic bean stereotype. Use when no more specific stereotype fits.

  @Component
  public class XmlParser { ... }

  @Component("customName")          // explicit bean name
  public class JsonParser { ... }

  Bean name defaults to: camelCase of simple class name
    XmlParser → "xmlParser"
    JSONParser → "JSONParser"  (all-caps classes keep full name)

  ── @Service ────────────────────────────────────────────────────
  Marks business logic layer. Functionally identical to @Component
  but conveys intent. May gain special treatment in future Spring.

  @Service
  public class OrderService {
      public Order placeOrder(OrderRequest request) { ... }
  }

  ── @Repository ─────────────────────────────────────────────────
  Marks data access layer. Key extra feature:
    Spring translates SQL/JPA exceptions → DataAccessException hierarchy
    (via PersistenceExceptionTranslationPostProcessor)

  @Repository
  public class JdbcUserRepository {
      @Autowired JdbcTemplate jdbc;
      // SQLException becomes DataAccessException automatically
  }

  ── @Controller ─────────────────────────────────────────────────
  Marks Spring MVC controller. Detected by DispatcherServlet.

  @Controller
  public class HomeController {
      @GetMapping("/")
      public String home(Model model) {
          return "index";  // returns view name
      }
  }

  ── @RestController ─────────────────────────────────────────────
  = @Controller + @ResponseBody
  All methods return data (JSON/XML) directly, not view names.

  @RestController
  @RequestMapping("/api/users")
  public class UserController {
      @GetMapping("/{id}")
      public UserDto getUser(@PathVariable Long id) {
          return userService.findById(id);  // serialized to JSON
      }
  }

================================================================
@Configuration — FULL DETAILS
================================================================

  @Configuration classes are special @Component subclasses
  that declare @Bean methods. The class is enhanced by CGLIB
  to intercept @Bean method calls and return cached singletons.

  @Configuration
  public class AppConfig {

      @Bean
      public DataSource dataSource() {
          HikariDataSource ds = new HikariDataSource();
          ds.setJdbcUrl("jdbc:h2:mem:testdb");
          return ds;
      }

      @Bean
      public JdbcTemplate jdbcTemplate() {
          // Calls dataSource() but CGLIB intercepts →
          // returns the same DataSource singleton, not a new one
          return new JdbcTemplate(dataSource());
      }
  }

  LITE mode (@Bean on non-@Configuration class):
    @Bean method calls are NOT intercepted by CGLIB.
    Each call creates a new instance.
    Useful when full proxy overhead is unnecessary.

    @Component          // not @Configuration
    public class LiteConfig {
        @Bean
        public MyService myService() {
            return new MyService(helper()); // helper() creates NEW instance
        }
        @Bean
        public MyHelper helper() { return new MyHelper(); }
    }

================================================================
@Import — COMPOSING CONFIGURATIONS
================================================================

  @Configuration
  @Import({DatabaseConfig.class, SecurityConfig.class})
  public class AppConfig { }

  // All beans from DatabaseConfig and SecurityConfig are included

  // Import a non-@Configuration class (processed via ImportSelector):
  @Configuration
  @Import(MyImportSelector.class)
  public class AppConfig { }

  public class MyImportSelector implements ImportSelector {
      @Override
      public String[] selectImports(AnnotationMetadata metadata) {
          return new String[]{"com.example.ConditionalConfig"};
      }
  }

@PropertySource — LOADING EXTERNAL PROPERTIES
================================================================

  @Configuration
  @PropertySource("classpath:db.properties")
  @PropertySource("classpath:app-${spring.profiles.active}.properties")
  public class AppConfig {

      @Value("${db.url}")
      private String dbUrl;
  }

  # db.properties
  db.url=jdbc:postgresql://localhost/mydb
  db.username=admin

META-ANNOTATIONS AND COMPOSED ANNOTATIONS
================================================================

  Spring annotations are composable (meta-annotations):

  @Target(ElementType.TYPE)
  @Retention(RetentionPolicy.RUNTIME)
  @RestController
  @RequestMapping("/api/v1")
  public @interface ApiV1Controller { }

  // Usage:
  @ApiV1Controller
  public class UserController {
      @GetMapping("/users")
      public List<User> list() { ... }
  }

  Real Spring examples:
    @SpringBootApplication = @Configuration + @ComponentScan + @EnableAutoConfiguration
    @RestController        = @Controller + @ResponseBody
    @TransactionalService  = @Service + @Transactional (custom)

================================================================
ANNOTATION PROCESSING ORDER
================================================================

  1. @ComponentScan finds candidates
  2. AnnotationConfigApplicationContext registers BeanDefinitions
  3. AutowiredAnnotationBeanPostProcessor processes @Autowired
  4. CommonAnnotationBeanPostProcessor processes @PostConstruct/@PreDestroy
  5. PersistenceAnnotationBeanPostProcessor processes @PersistenceContext
  6. Spring Data: @EnableJpaRepositories creates repository proxies

================================================================
DETECTING BEANS PROGRAMMATICALLY
================================================================

  @Component
  public class BeanInspector implements ApplicationContextAware {

      @Autowired
      private ApplicationContext ctx;

      public void listBeans() {
          String[] names = ctx.getBeanDefinitionNames();
          for (String name : names) {
              Object bean = ctx.getBean(name);
              System.out.printf("%-40s → %s%n",
                  name, bean.getClass().getSimpleName());
          }
      }

      public <T> List<T> beansOfType(Class<T> type) {
          return new ArrayList<>(ctx.getBeansOfType(type).values());
      }
  }

================================================================
INTERVIEW QUESTIONS — COMPONENT SCANNING
================================================================

  Q: What does @ComponentScan do?
  A: It tells Spring to scan the specified packages for classes
     annotated with @Component, @Service, @Repository, @Controller
     (and their specializations) and register them as beans.

  Q: What is the default scan package in Spring Boot?
  A: The package of the class annotated with @SpringBootApplication
     and all its sub-packages.

  Q: What is the difference between @Component and @Bean?
  A: @Component is class-level, auto-detected via scanning.
     @Bean is method-level inside a @Configuration class, giving
     full programmatic control over instantiation (useful for
     third-party library classes).

  Q: What is the difference between @Configuration and @Component
     when used with @Bean?
  A: @Configuration classes are CGLIB-proxied — @Bean methods return
     the same singleton instance on repeated calls. @Component with
     @Bean methods (lite mode) call the factory method each time.

  Q: Can you have multiple @ComponentScan annotations?
  A: Yes, either as a @ComponentScans container or Java 8 repeated
     annotations. Each defines independent scan rules.

  Q: How do you exclude a specific class from component scanning?
  A: Use excludeFilters with FilterType.ASSIGNABLE_TYPE or
     FilterType.ANNOTATION in @ComponentScan.
