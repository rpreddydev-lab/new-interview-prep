================================================================
  CONDITIONAL BEANS AND @ConditionalOnProperty — IN DEPTH
================================================================

================================================================
WHAT ARE CONDITIONAL BEANS?
================================================================

  Spring allows you to control whether a bean is registered based
  on conditions evaluated at startup. This is the foundation of
  Spring Boot's auto-configuration.

  Core annotation: @Conditional(SomeCondition.class)
  Spring Boot adds many convenient @ConditionalOn* annotations.

================================================================
@Conditional — BUILDING YOUR OWN
================================================================

  // Define condition
  public class ProductionCondition implements Condition {

      @Override
      public boolean matches(ConditionContext context,
                             AnnotatedTypeMetadata metadata) {
          Environment env = context.getEnvironment();
          String profile = env.getProperty("spring.profiles.active", "");
          return profile.contains("prod");
      }
  }

  // Use it
  @Bean
  @Conditional(ProductionCondition.class)
  public MetricsCollector metricsCollector() {
      return new DatadogMetricsCollector();
  }

  ConditionContext gives access to:
    getBeanFactory()    -- registered bean definitions
    getClassLoader()    -- for class presence checks
    getEnvironment()    -- properties and profiles
    getRegistry()       -- bean definition registry
    getResourceLoader() -- file/classpath resources

================================================================
SPRING BOOT @ConditionalOn* ANNOTATIONS
================================================================

  ── @ConditionalOnProperty ──────────────────────────────────────

  Most commonly used. Register bean based on property value.

  // Register if property exists and is true (default)
  @Bean
  @ConditionalOnProperty("feature.payments.enabled")
  public PaymentGateway paymentGateway() { ... }

  // Full form with all options
  @Bean
  @ConditionalOnProperty(
      name    = "feature.payments.provider",
      havingValue = "stripe",       // exact match
      matchIfMissing = false        // don't create bean if property absent
  )
  public PaymentGateway stripeGateway() { ... }

  @Bean
  @ConditionalOnProperty(
      prefix  = "app.cache",
      name    = "enabled",
      havingValue = "true",
      matchIfMissing = true         // create bean even if property is absent
  )
  public CacheManager cacheManager() { ... }

  Multiple property check (all must match):
  @ConditionalOnProperty(
      name = {"feature.a.enabled", "feature.b.enabled"},
      havingValue = "true"
  )

  ── @ConditionalOnClass ─────────────────────────────────────────

  Register bean only if class is on the classpath.

  @Bean
  @ConditionalOnClass(name = "com.zaxxer.hikari.HikariDataSource")
  public DataSource hikariDataSource() { ... }

  @Bean
  @ConditionalOnClass(HikariDataSource.class)  // compile-time safe form
  public DataSource hikariDataSource() { ... }

  ── @ConditionalOnMissingClass ──────────────────────────────────

  Register bean only if a class is NOT on the classpath.

  @Bean
  @ConditionalOnMissingClass("org.springframework.kafka.core.KafkaTemplate")
  public MessagePublisher fallbackPublisher() { ... }

  ── @ConditionalOnBean ──────────────────────────────────────────

  Register bean only if another bean already exists.

  @Bean
  @ConditionalOnBean(DataSource.class)
  public JdbcTemplate jdbcTemplate(DataSource ds) { ... }

  @Bean
  @ConditionalOnBean(name = "specialDataSource")
  public ReportingService reportingService() { ... }

  ── @ConditionalOnMissingBean ───────────────────────────────────

  Register bean only if NO bean of this type exists.
  This is the key to auto-configuration extensibility.

  @Bean
  @ConditionalOnMissingBean(PasswordEncoder.class)
  public PasswordEncoder defaultPasswordEncoder() {
      return new BCryptPasswordEncoder();  // user can override
  }

  ── @ConditionalOnExpression ────────────────────────────────────

  Register based on a SpEL expression.

  @Bean
  @ConditionalOnExpression("${feature.enabled:false} and ${tier} == 'premium'")
  public PremiumService premiumService() { ... }

  ── @ConditionalOnProfile ───────────────────────────────────────

  @Bean
  @Profile("dev")                      // standard Spring approach
  public DataSource h2DataSource() { return ... }

  @Bean
  @Profile({"prod", "staging"})        // multiple profiles
  public DataSource postgresDataSource() { return ... }

  ── @ConditionalOnJava ──────────────────────────────────────────

  @Bean
  @ConditionalOnJava(JavaVersion.TWENTY_ONE)
  public VirtualThreadTaskExecutor virtualThreads() { ... }

  ── @ConditionalOnWebApplication ────────────────────────────────

  @Bean
  @ConditionalOnWebApplication
  public WebFilter requestLoggingFilter() { ... }

  @Bean
  @ConditionalOnNotWebApplication
  public CliRunner cliRunner() { ... }

  ── @ConditionalOnResource ──────────────────────────────────────

  @Bean
  @ConditionalOnResource(resources = "classpath:schema.sql")
  public DatabaseInitializer dbInit() { ... }

================================================================
COMPOSING CONDITIONS — @ConditionalOnAll (custom)
================================================================

  Spring doesn't have a built-in "and" combinator for
  @ConditionalOn* annotations, but you can create custom ones:

  @Target({ElementType.TYPE, ElementType.METHOD})
  @Retention(RetentionPolicy.RUNTIME)
  @Conditional(StripeAndEnabledCondition.class)
  public @interface ConditionalOnStripeEnabled { }

  public class StripeAndEnabledCondition extends AllNestedConditions {
      public StripeAndEnabledCondition() {
          super(ConfigurationPhase.REGISTER_BEAN);
      }

      @ConditionalOnProperty("stripe.api-key")
      static class HasApiKey { }

      @ConditionalOnProperty(name = "payments.enabled", havingValue = "true")
      static class PaymentsEnabled { }
  }

  AllNestedConditions: ALL inner conditions must match (AND logic).
  AnyNestedConditions: ANY inner condition must match (OR logic).
  NoneNestedConditions: NONE of the inner conditions must match.

================================================================
@ConditionalOnProperty IN AUTO-CONFIGURATION
================================================================

  Spring Boot auto-configuration uses @ConditionalOnMissingBean
  extensively to let users override defaults:

  // Spring Boot's DataSourceAutoConfiguration (simplified)
  @Configuration
  @ConditionalOnClass(DataSource.class)
  @ConditionalOnMissingBean(DataSource.class)  // only if user hasn't provided one
  public class DataSourceAutoConfiguration {

      @Bean
      @ConditionalOnProperty(
          prefix = "spring.datasource.hikari",
          name = "jdbc-url")
      public DataSource hikariDataSource() { ... }
  }

================================================================
@Profile — ENVIRONMENT-BASED BEANS
================================================================

  @Configuration
  public class DataSourceConfig {

      @Bean
      @Profile("dev")
      public DataSource embeddedDataSource() {
          return new EmbeddedDatabaseBuilder()
              .setType(EmbeddedDatabaseType.H2)
              .build();
      }

      @Bean
      @Profile("!dev")  // all non-dev profiles
      public DataSource productionDataSource(
              @Value("${db.url}") String url) {
          HikariDataSource ds = new HikariDataSource();
          ds.setJdbcUrl(url);
          return ds;
      }
  }

  Activate profiles:
    # application.properties
    spring.profiles.active=dev

    # Command line
    java -jar app.jar --spring.profiles.active=prod,metrics

    # Environment variable
    SPRING_PROFILES_ACTIVE=prod,metrics

================================================================
INTERVIEW QUESTIONS — CONDITIONAL BEANS
================================================================

  Q: How does @ConditionalOnMissingBean enable extensibility?
  A: Auto-configuration provides a default bean only if no user-defined
     bean of that type exists. Users override by declaring their own
     @Bean, and auto-configuration backs off automatically.

  Q: What is the difference between @Profile and @ConditionalOnProperty?
  A: @Profile activates beans based on active Spring profiles.
     @ConditionalOnProperty activates based on property values.
     They're complementary — profiles control environment groups;
     properties control feature flags.

  Q: What is AllNestedConditions?
  A: A base class for creating composite conditions where ALL inner
     conditions must be satisfied. It enables AND-logic across
     multiple @ConditionalOn* annotations.

  Q: Can @Conditional be used on @Configuration classes?
  A: Yes. If the condition fails, the entire @Configuration class
     (and all its @Bean methods) is excluded from the context.

  Q: What happens when @ConditionalOnBean references a bean that
     is defined in the same @Configuration class?
  A: Bean registration order matters. @ConditionalOnBean checks
     already-registered beans. If the target bean is defined after
     the conditional bean in the same class, the condition may fail.
     Use @AutoConfigureAfter or split into separate configs.
