  1. WHAT IS SPRING DATA?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Spring Data is an umbrella project that simplifies data access
for various persistence technologies under a unified, consistent
programming model.

Goals:
  - Eliminate boilerplate CRUD code
  - Consistent repository abstraction across stores
  - Auto-generated queries from method names
  - Pagination and sorting out of the box
  - Auditing support (@CreatedBy, @LastModifiedDate, etc.)

Sub-projects:
  Spring Data JPA        → JPA / Hibernate (RDBMS)
  Spring Data MongoDB    → MongoDB (document store)
  Spring Data Redis      → Redis (in-memory key-value)
  Spring Data Elasticsearch → Elasticsearch
  Spring Data R2DBC      → Reactive RDBMS (non-blocking)
  Spring Data Cassandra  → Cassandra (wide-column)
  Spring Data LDAP       → LDAP directories
  Spring Data REST       → Exposes repos as REST endpoints
  Spring Data KeyValue   → In-memory Map-based stores

  2. CORE REPOSITORY HIERARCHY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Repository<T, ID>               ← marker interface
      │
  CrudRepository<T, ID>           ← save, findById, findAll, delete
      │
  PagingAndSortingRepository      ← findAll(Pageable), findAll(Sort)
      │
  JpaRepository<T, ID>            ← flush, saveAllAndFlush, deleteInBatch
      │
  (custom extension)

  T   = Entity type
  ID  = Primary key type

Repository hierarchy allows coding to the smallest needed interface.

  3. AUTO-CONFIGURATION (Spring Boot)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Spring Boot auto-configures:
  - DataSource (from spring.datasource.* properties)
  - EntityManagerFactory
  - TransactionManager
  - Repository scanning (any interface extending Repository)

Add to pom.xml:
  <dependency>
      <groupId>org.springframework.boot</groupId>
      <artifactId>spring-boot-starter-data-jpa</artifactId>
  </dependency>
  <dependency>
      <groupId>com.h2database</groupId>
      <artifactId>h2</artifactId>
      <scope>runtime</scope>
  </dependency>

application.properties:
  spring.datasource.url=jdbc:postgresql://localhost:5432/mydb
  spring.datasource.username=postgres
  spring.datasource.password=secret
  spring.jpa.hibernate.ddl-auto=validate
  spring.jpa.show-sql=true
  spring.jpa.properties.hibernate.format_sql=true

  4. KEY ANNOTATIONS QUICK REFERENCE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Annotation                  | Purpose
  ────────────────────────────┼──────────────────────────────────────
  @Entity                     | Marks class as JPA entity
  @Table(name="...")          | Maps to a specific DB table
  @Id                         | Primary key field
  @GeneratedValue             | Auto-generated PK strategy
  @Column(name="...",nullable)| Column mapping
  @Transient                  | Not persisted
  @OneToMany / @ManyToOne     | Relationships
  @ManyToMany                 | Many-to-many relationship
  @JoinColumn                 | FK column name
  @Embedded / @Embeddable     | Value object embedding
  @CreatedDate                | Auditing — creation timestamp
  @LastModifiedDate           | Auditing — last update timestamp
  @CreatedBy / @LastModifiedBy| Auditing — user context
  @EnableJpaRepositories      | Enable repo scanning (auto in Boot)
  @EnableJpaAuditing          | Activate auditing support
  @Query                      | Custom JPQL/native query
  @Modifying                  | Marks @Query as update/delete
  @Transactional              | Transaction boundary

  5. SPRING DATA AUDITING
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

@Configuration
@EnableJpaAuditing(auditorAwareRef = "auditorProvider")
public class AuditConfig {
    @Bean
    AuditorAware<String> auditorProvider() {
        return () -> Optional.ofNullable(
            SecurityContextHolder.getContext()
                .getAuthentication()
                .getName());
    }
}

@MappedSuperclass
@EntityListeners(AuditingEntityListener.class)
public abstract class Auditable {
    @CreatedBy
    private String createdBy;

    @LastModifiedBy
    private String lastModifiedBy;

    @CreatedDate
    private LocalDateTime createdAt;

    @LastModifiedDate
    private LocalDateTime updatedAt;
}

@Entity
public class Order extends Auditable {
    @Id @GeneratedValue
    private Long id;
    // fields...
}

  6. PAGINATION AND SORTING
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Pageable:
  Pageable page = PageRequest.of(0, 10, Sort.by("name").ascending());
  Page<Product> result = productRepo.findAll(page);

  result.getContent()       // List<Product> for this page
  result.getTotalElements() // Total records across all pages
  result.getTotalPages()    // Total page count
  result.getNumber()        // Current page number (0-based)
  result.hasNext()          // more pages available?

Slice (lighter — doesn't fetch total count):
  Slice<Product> slice = productRepo.findByCategory("electronics", page);
  slice.hasNext()  // tells if there is a next page

Sort only:
  List<Product> sorted = productRepo.findAll(Sort.by(
      Sort.Order.asc("name"),
      Sort.Order.desc("price")
  ));

  7. SPRING DATA REST (BONUS)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Add spring-boot-starter-data-rest and Spring Data automatically
exposes repositories as hypermedia-driven REST endpoints (HAL).

  @RepositoryRestResource(collectionResourceRel = "products",
                           path = "products")
  public interface ProductRepository extends JpaRepository<Product, Long> {}

  → GET    /products        (list all, paginated HAL)
  → GET    /products/{id}   (single)
  → POST   /products        (create)
  → PUT    /products/{id}   (replace)
  → PATCH  /products/{id}   (partial update)
  → DELETE /products/{id}   (delete)

Use sparingly in production — can expose too much by default.

Q: What is the difference between CrudRepository and JpaRepository?
A: CrudRepository provides basic CRUD operations. JpaRepository extends
   PagingAndSortingRepository and adds JPA-specific operations like
   flush(), saveAllAndFlush(), deleteInBatch(), and getReferenceById().

Q: How does Spring Data generate repository implementations at runtime?
A: Spring Data uses JDK dynamic proxies (via ProxyFactory) or CGLIB to
   create runtime implementations that delegate to the appropriate store
   (e.g., SimpleJpaRepository for JPA). This happens during application
   context startup.

Q: What is the difference between Page and Slice?
A: Page executes an additional COUNT query to return totalElements and
   totalPages. Slice only fetches the current page + checks for next,
   making it more efficient when total count is not needed.

Q: How do you enable Spring Data JPA auditing?
A: Annotate a @Configuration class with @EnableJpaAuditing, provide an
   AuditorAware<T> bean, annotate entities extending a @MappedSuperclass
   with @EntityListeners(AuditingEntityListener.class), and use
   @CreatedDate, @LastModifiedDate, @CreatedBy, @LastModifiedBy fields.

Q: What does spring.jpa.hibernate.ddl-auto do?
A: Controls schema generation: none, validate (check schema matches
   entities), update (alter schema to match), create (drop+create on
   startup), create-drop (create on startup, drop on shutdown).
   Use validate or none in production.
