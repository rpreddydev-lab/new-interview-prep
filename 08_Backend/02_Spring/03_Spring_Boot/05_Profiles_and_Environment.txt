================================================================
  SPRING BOOT PROFILES AND ENVIRONMENT — IN DEPTH
================================================================

================================================================
WHAT ARE PROFILES?
================================================================

  Profiles allow you to register beans and configuration
  conditionally based on the active environment.

  Common profiles: dev, test, staging, prod, local, docker

================================================================
DEFINING PROFILE-SPECIFIC BEANS
================================================================

  // @Profile on @Component
  @Service
  @Profile("dev")
  public class MockPaymentGateway implements PaymentGateway {
      public PaymentResult charge(double amount) {
          return PaymentResult.success("mock-txn-" + UUID.randomUUID());
      }
  }

  @Service
  @Profile("!dev")   // all profiles except dev
  public class StripePaymentGateway implements PaymentGateway { ... }

  // @Profile on @Bean
  @Configuration
  public class DataSourceConfig {

      @Bean
      @Profile({"dev", "local"})
      public DataSource h2DataSource() {
          return new EmbeddedDatabaseBuilder()
              .setType(EmbeddedDatabaseType.H2)
              .addScript("classpath:schema.sql")
              .build();
      }

      @Bean
      @Profile("prod")
      public DataSource postgresDataSource(
              @Value("${spring.datasource.url}") String url,
              @Value("${spring.datasource.username}") String user,
              @Value("${spring.datasource.password}") String pass) {
          HikariDataSource ds = new HikariDataSource();
          ds.setJdbcUrl(url);
          ds.setUsername(user);
          ds.setPassword(pass);
          return ds;
      }
  }

================================================================
PROFILE EXPRESSION SYNTAX
================================================================

  @Profile("dev")           -- matches "dev" only
  @Profile("!dev")          -- matches anything except "dev"
  @Profile({"dev","test"})  -- matches "dev" OR "test"

  Spring 5.1+ logical operators:
  @Profile("dev & eu")      -- matches when BOTH "dev" AND "eu" active
  @Profile("dev | staging") -- matches when "dev" OR "staging" active
  @Profile("!prod & !staging") -- not prod AND not staging

================================================================
ACTIVATING PROFILES
================================================================

  1. application.properties
     spring.profiles.active=dev

  2. Command line
     java -jar app.jar --spring.profiles.active=prod,metrics

  3. Maven / Gradle
     mvn spring-boot:run -Dspring-boot.run.profiles=dev

  4. Environment variable
     export SPRING_PROFILES_ACTIVE=prod

  5. Programmatic
     SpringApplication app = new SpringApplication(MyApp.class);
     app.setAdditionalProfiles("metrics");
     app.run(args);

  6. SpringApplicationBuilder
     new SpringApplicationBuilder(MyApp.class)
         .profiles("dev", "local")
         .run(args);

  7. @ActiveProfiles in tests
     @SpringBootTest
     @ActiveProfiles("test")
     class MyServiceTest { ... }

================================================================
PROFILE-SPECIFIC PROPERTY FILES
================================================================

  application.properties            -- always loaded
  application-dev.properties        -- when "dev" active
  application-prod.properties       -- when "prod" active
  application-dev.yaml              -- YAML variant

  Profile-specific properties OVERRIDE default application.properties.

  Example:
  # application.properties
  server.port=8080
  spring.jpa.show-sql=false

  # application-dev.properties
  server.port=8081
  spring.jpa.show-sql=true
  spring.datasource.url=jdbc:h2:mem:devdb

  # application-prod.properties
  spring.datasource.url=jdbc:postgresql://prod-db:5432/myapp
  spring.jpa.hibernate.ddl-auto=validate

================================================================
DEFAULT PROFILE
================================================================

  If no profile is active, Spring uses the "default" profile.

  // Only registered when no profile active (or "default" profile)
  @Component
  @Profile("default")
  public class DefaultEventPublisher implements EventPublisher { ... }

  # Override in application.properties
  spring.profiles.default=local

================================================================
ENVIRONMENT INTERFACE
================================================================

  @Component
  public class EnvironmentUtil {

      @Autowired
      private Environment env;

      public void printInfo() {
          // Active profiles
          System.out.println(Arrays.toString(env.getActiveProfiles()));

          // Default profiles (if none active)
          System.out.println(Arrays.toString(env.getDefaultProfiles()));

          // Check specific profile
          boolean isDev = env.acceptsProfiles(Profiles.of("dev"));
          boolean isProdOrStage = env.acceptsProfiles(
              Profiles.of("prod | staging"));

          // Property access
          String dbUrl = env.getProperty("spring.datasource.url");
          int port = env.getProperty("server.port", Integer.class, 8080);
      }
  }

================================================================
SPRING BOOT ENVIRONMENT POST PROCESSOR
================================================================

  For advanced use cases — manipulate Environment before context refresh:

  public class SecretsLoader implements EnvironmentPostProcessor {

      @Override
      public void postProcessEnvironment(ConfigurableEnvironment env,
                                         SpringApplication app) {
          // Load secrets from vault, AWS SSM, etc.
          Map<String, Object> secrets = loadFromVault();
          env.getPropertySources().addFirst(
              new MapPropertySource("vault-secrets", secrets));
      }
  }

  // Register in META-INF/spring.factories:
  org.springframework.boot.env.EnvironmentPostProcessor=\
    com.example.SecretsLoader

================================================================
PROFILES IN TESTS
================================================================

  @SpringBootTest
  @ActiveProfiles("test")
  class OrderServiceIntegrationTest {

      @Autowired
      OrderService orderService;  // gets test-profile beans

      // Uses application-test.properties
  }

  // Profile-specific test config
  @TestConfiguration
  @Profile("test")
  public class TestDatabaseConfig {

      @Bean
      @Primary
      public DataSource testDataSource() {
          return new EmbeddedDatabaseBuilder()
              .setType(EmbeddedDatabaseType.H2)
              .build();
      }
  }

================================================================
PROFILE GROUPS (SPRING BOOT 2.4+)
================================================================

  # application.properties
  spring.profiles.group.local=dev,h2,mock-mail
  spring.profiles.group.ci=test,h2

  # Activate "local" → automatically activates dev + h2 + mock-mail
  spring.profiles.active=local

================================================================
SPRING BOOT CONFIG IMPORT (2.4+)
================================================================

  # application.properties
  spring.config.import=optional:file:./custom.properties
  spring.config.import=optional:classpath:/extra-config.yaml
  spring.config.import=configserver:http://config.example.com

  // Supports: file, classpath, vault, consul, configserver

================================================================
INTERVIEW QUESTIONS — PROFILES AND ENVIRONMENT
================================================================

  Q: What is the purpose of Spring profiles?
  A: Profiles allow registering beans and configuration values
     conditionally for different environments (dev, prod, test),
     eliminating environment-specific code and config.

  Q: How do you activate multiple profiles?
  A: spring.profiles.active=prod,metrics (comma-separated) or
     SPRING_PROFILES_ACTIVE env var or --spring.profiles.active CLI arg.

  Q: What happens if no profile is active?
  A: Spring uses the "default" profile. @Profile("default") beans
     and application-default.properties are loaded.

  Q: Can you combine profiles with AND logic in @Profile?
  A: Yes (Spring 5.1+): @Profile("dev & eu") activates only when
     both "dev" and "eu" profiles are active.

  Q: What is EnvironmentPostProcessor used for?
  A: It's a hook to manipulate the Environment before the application
     context is refreshed — used for loading secrets from Vault/SSM,
     custom property sources, etc.

  Q: What is a Profile Group in Spring Boot 2.4+?
  A: A named group that activates multiple profiles at once:
     spring.profiles.group.prod=cloud,metrics,tracing
     Setting spring.profiles.active=prod activates all three.
