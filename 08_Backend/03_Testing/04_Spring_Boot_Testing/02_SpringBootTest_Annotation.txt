================================================================
SPRING BOOT TESTING — @SpringBootTest ANNOTATION
Complete Interview Preparation Guide
================================================================

1. WHAT IS @SpringBootTest?
================================================================

@SpringBootTest is the primary annotation for INTEGRATION tests in
Spring Boot. It bootstraps the full ApplicationContext — loading all
beans, all configurations, all auto-configurations — exactly as in
production (minus any test-specific overrides).

  @SpringBootTest
  @ExtendWith(SpringExtension.class)  ← automatically added by @SpringBootTest
  class OrderServiceIntegrationTest {
      
      @Autowired OrderService orderService;  // REAL bean from context
      
      @Test
      void shouldPlaceOrder() { ... }
  }

Note: Since Spring Boot 2.1, @ExtendWith(SpringExtension.class) is
automatically included in @SpringBootTest, so you don't need to add it.

2. webEnvironment — FOUR OPTIONS
================================================================

@SpringBootTest(webEnvironment = SpringBootTest.WebEnvironment.MOCK)
  → Default when webEnvironment not specified
  → Creates a mock servlet environment (no real HTTP server)
  → Use with MockMvc for testing web layer
  → Fast — no port binding

@SpringBootTest(webEnvironment = SpringBootTest.WebEnvironment.RANDOM_PORT)
  → Starts a REAL embedded server on a random port
  → Inject @LocalServerPort to find the port
  → Use with TestRestTemplate or WebTestClient
  → For real end-to-end HTTP testing
  → Slightly slower (real server startup)

@SpringBootTest(webEnvironment = SpringBootTest.WebEnvironment.DEFINED_PORT)
  → Starts on the port defined in application.properties (default 8080)
  → Use when port must be stable (e.g., contract testing with fixed URLs)

@SpringBootTest(webEnvironment = SpringBootTest.WebEnvironment.NONE)
  → Does NOT load any web layer
  → Only loads the non-web application context
  → Use for service integration tests that don't need HTTP

EXAMPLES:

// Integration test with MockMvc (no real server)
@SpringBootTest(webEnvironment = WebEnvironment.MOCK)
@AutoConfigureMockMvc
class UserControllerIT {
    @Autowired MockMvc mockMvc;
    
    @Test
    void shouldReturnUser() throws Exception {
        mockMvc.perform(get("/users/1"))
            .andExpect(status().isOk());
    }
}

// Integration test with real HTTP server
@SpringBootTest(webEnvironment = WebEnvironment.RANDOM_PORT)
class UserControllerRealServerIT {
    @LocalServerPort
    int port;
    
    @Autowired TestRestTemplate restTemplate;
    
    @Test
    void shouldReturnUser() {
        ResponseEntity<User> response = restTemplate.getForEntity(
            "/users/1", User.class);
        assertEquals(HttpStatus.OK, response.getStatusCode());
    }
}

// Service-layer integration test (no web)
@SpringBootTest(webEnvironment = WebEnvironment.NONE)
class UserServiceIT {
    @Autowired UserService userService;
    
    @Test
    void shouldCreateAndFindUser() {
        userService.create(new UserRequest("alice@test.com"));
        User found = userService.findByEmail("alice@test.com");
        assertNotNull(found);
    }
}

3. LOADING SPECIFIC CONFIGURATION
================================================================

Load specific configuration classes instead of the full app:
  @SpringBootTest(classes = {UserService.class, UserRepository.class})
  class MinimalContextTest { ... }
  // Only loads specified beans — everything else must be mocked

Load with specific properties:
  @SpringBootTest(properties = {
      "app.feature.new-checkout=true",
      "spring.datasource.url=jdbc:h2:mem:testdb;MODE=PostgreSQL"
  })
  class CheckoutFeatureTest { ... }

Load with property files:
  @TestPropertySource(locations = "classpath:test-overrides.properties")
  @SpringBootTest
  class OverriddenPropertyTest { ... }

4. COMMON COMBINED ANNOTATIONS
================================================================

Full integration test setup:
  @SpringBootTest(webEnvironment = WebEnvironment.RANDOM_PORT)
  @ActiveProfiles("test")
  @Sql(scripts = "/sql/schema.sql", executionPhase = BEFORE_TEST_CLASS)
  @Sql(scripts = "/sql/test-data.sql", executionPhase = BEFORE_TEST_METHOD)
  @Sql(scripts = "/sql/cleanup.sql", executionPhase = AFTER_TEST_METHOD)
  class FullIntegrationTest {
      
      @LocalServerPort int port;
      @Autowired TestRestTemplate restTemplate;
      @MockBean ExternalPaymentGateway paymentGateway;
      
      @BeforeEach
      void configureMocks() {
          when(paymentGateway.charge(any())).thenReturn(
              PaymentResult.success("charge-test-123")
          );
      }
  }

5. @SpringBootTest WITH TESTCONTAINERS
================================================================

Real database integration test with Testcontainers:
  @SpringBootTest
  @Testcontainers
  class UserServiceWithRealDatabaseIT {
      
      @Container
      static PostgreSQLContainer<?> postgres = 
          new PostgreSQLContainer<>("postgres:15")
              .withDatabaseName("testdb")
              .withUsername("test")
              .withPassword("test");
      
      @DynamicPropertySource
      static void setDatasourceProperties(DynamicPropertyRegistry registry) {
          registry.add("spring.datasource.url", postgres::getJdbcUrl);
          registry.add("spring.datasource.username", postgres::getUsername);
          registry.add("spring.datasource.password", postgres::getPassword);
      }
      
      @Autowired UserService userService;
      @Autowired UserRepository userRepository;
      
      @Test
      @Transactional
      void createUserShouldPersistToDatabase() {
          UserRequest request = new UserRequest("alice@test.com", "Alice");
          
          User created = userService.create(request);
          
          assertNotNull(created.getId());
          
          Optional<User> found = userRepository.findById(created.getId());
          assertTrue(found.isPresent());
          assertEquals("alice@test.com", found.get().getEmail());
      }
  }

6. @SpringBootTest WITH @MockBean — SLICE STRATEGY
================================================================

Full context but mock selected external dependencies:
  @SpringBootTest
  class OrderProcessingIT {
      
      @Autowired OrderService orderService;    // REAL service
      @Autowired OrderRepository orderRepo;   // REAL repository
      
      @MockBean PaymentGateway paymentGateway;   // MOCKED — no real payment
      @MockBean InventoryService inventoryService; // MOCKED — no inventory calls
      @MockBean EmailService emailService;    // MOCKED — no real emails
      
      @BeforeEach
      void setUp() {
          when(paymentGateway.charge(any())).thenReturn(PaymentResult.success("ch_1"));
          when(inventoryService.isAvailable(anyString(), anyInt())).thenReturn(true);
      }
      
      @Test
      @Transactional
      void endToEndOrderFlow() {
          Cart cart = new Cart("cust-1");
          cart.addItem(new CartItem("SKU-001", 2, new BigDecimal("49.99")));
          
          Order placed = orderService.placeOrder(cart);
          
          // Real service + real DB, but mocked external calls
          assertNotNull(placed.getId());
          assertEquals(OrderStatus.CONFIRMED, placed.getStatus());
          
          verify(paymentGateway).charge(any());
          verify(emailService).sendOrderConfirmation(any(), any());
          verify(inventoryService).isAvailable("SKU-001", 2);
      }
  }

7. @SpringBootTest STARTUP VALIDATION
================================================================

Sometimes you just want to verify the context loads without errors:
  @SpringBootTest
  class ApplicationContextLoadsTest {
      
      @Test
      void contextLoads() {
          // Empty test — if context fails to load, this test fails
          // Verifies: no circular dependencies, valid config, etc.
      }
      
      @Autowired ApplicationContext context;
      
      @Test
      void allBeansShouldBeAvailable() {
          assertNotNull(context.getBean(UserService.class));
          assertNotNull(context.getBean(OrderService.class));
      }
  }

8. @SpringBootTest PERFORMANCE TIPS
================================================================

TIP 1: Use test slices when possible
  @WebMvcTest(UserController.class)   // loads in ~1s
  // vs
  @SpringBootTest                     // loads in ~5-10s

TIP 2: Share ApplicationContext with base class
  @SpringBootTest
  @ActiveProfiles("test")
  abstract class AbstractIT {
      @MockBean EmailService emailService;
      @MockBean PaymentGateway paymentGateway;
  }
  // All subclasses REUSE the same cached context

TIP 3: Avoid @DirtiesContext unless necessary
  // @DirtiesContext forces context recreation — very expensive
  // If test data isolation is needed, use @Transactional + rollback

TIP 4: Use @SQL scripts for reproducible state
  @Sql("/sql/test-users.sql")
  @Test
  void shouldFindUsers() { ... }

TIP 5: Run integration tests in a separate Maven phase
  <!-- surefire for unit tests (fast) -->
  <!-- failsafe for IT tests (@SpringBootTest) -->
  <artifactId>maven-failsafe-plugin</artifactId>
  <!-- Name IT classes as *IT.java or *IntegrationTest.java -->

9. FIELD INJECTION vs CONSTRUCTOR INJECTION IN TESTS
================================================================

  // PROBLEMATIC: @SpringBootTest with @Autowired
  @SpringBootTest
  class UserServiceTest {
      @Autowired UserService userService;  // null in constructor
      // Spring injects AFTER construction
  }
  
  // You can inject in @BeforeEach-style via constructor in test:
  @SpringBootTest
  class UserServiceTest {
      private final UserService userService;
      
      @Autowired
      UserServiceTest(UserService userService) {
          this.userService = userService;
          // Available immediately!
      }
  }
  // Note: JUnit 5 + Spring both support constructor injection in test classes

10. INTERVIEW QUESTIONS
================================================================

Q: What does @SpringBootTest do?
A: It bootstraps the full Spring ApplicationContext for integration testing,
   loading all beans, configurations, and auto-configurations — similar to
   how the production application starts.

Q: What are the webEnvironment options in @SpringBootTest?
A: MOCK (default) — mock servlet environment, use MockMvc;
   RANDOM_PORT — real embedded server on random port, use TestRestTemplate;
   DEFINED_PORT — real server on configured port;
   NONE — no web layer loaded, for service-level integration tests.

Q: How do you find the port used in RANDOM_PORT tests?
A: Inject it with @LocalServerPort:
   @LocalServerPort int port;

Q: What is @DynamicPropertySource and when do you use it?
A: Used to dynamically register Spring properties at runtime. Common with
   Testcontainers: the container starts, gets a random port/URL, and
   @DynamicPropertySource registers it so Spring connects to the container.

Q: How does Spring Boot cache test application contexts?
A: It hashes the test configuration (class, annotations, properties) and
   reuses the context if the hash matches. Different @MockBean declarations
   create different hashes → different context → slower tests.

Q: What is the difference between @SpringBootTest and @WebMvcTest?
A: @SpringBootTest loads all beans (full application context).
   @WebMvcTest loads only the web layer (Controller, ControllerAdvice).
   @WebMvcTest is much faster; services must be @MockBean'd.

Q: How do you set test-specific properties in @SpringBootTest?
A: Properties attribute: @SpringBootTest(properties = {"key=value"})
   Or @TestPropertySource(properties = {}) or locations of .properties files
   Or application-test.yml with @ActiveProfiles("test")
