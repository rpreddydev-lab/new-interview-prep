MOCKITO — WHEN / THEN_RETURN / THEN_THROW / THEN_ANSWER
Complete Interview Preparation Guide
================================================================

1. OVERVIEW OF STUBBING
================================================================

Stubbing = configuring what a mock/spy returns when called.

Two styles in Mockito:
  when/then  — readable, works for mocks, careful with spies
  do/when    — required for void methods, always safe for spies

The stubbing call:
  when( mock.method(args) ).thenXxx(...)

The do/when style:
  doXxx(...).when(mock).method(args)

================================================================
2. thenReturn — RETURNING VALUES
================================================================

BASIC USAGE:
  @Mock UserRepository userRepository;
  
  // Single value
  when(userRepository.findById("user-1"))
      .thenReturn(Optional.of(new User("user-1", "Alice")));
  
  // Return null explicitly
  when(userRepository.findById("unknown"))
      .thenReturn(Optional.empty());
  
  // Return a collection
  when(userRepository.findAll())
      .thenReturn(List.of(
          new User("u-1", "Alice"),
          new User("u-2", "Bob")
      ));
  
  // Return a primitive (auto-boxed)
  when(userRepository.countActiveUsers()).thenReturn(42L);

RETURNING MULTIPLE VALUES (consecutive stubbing):
  // Each call returns the next value; last value repeats
  when(clock.instant())
      .thenReturn(Instant.parse("2024-01-01T10:00:00Z"))  // 1st call
      .thenReturn(Instant.parse("2024-01-01T10:05:00Z"))  // 2nd call
      .thenReturn(Instant.parse("2024-01-01T10:10:00Z")); // 3rd+ calls (repeats)
  
  // Short form (varargs — only for thenReturn with same type)
  when(clock.instant()).thenReturn(
      Instant.parse("2024-01-01T10:00:00Z"),
      Instant.parse("2024-01-01T10:05:00Z"),
      Instant.parse("2024-01-01T10:10:00Z")
  );
  
  // Mix return and throw
  when(service.fetch())
      .thenReturn("first-result")
      .thenThrow(new TimeoutException("Timeout"))
      .thenReturn("recovered-result");

STUBBING WITH ARGUMENT MATCHERS:
  // Stub for any argument
  when(userRepository.findById(anyString()))
      .thenReturn(Optional.of(new User("default", "Default User")));
  
  // More specific matches
  when(emailService.sendTo(startsWith("admin@")))
      .thenReturn(true);
  
  when(orderService.calculateTax(doubleThat(d -> d > 1000.0)))
      .thenReturn(new Tax(BigDecimal.valueOf(0.20)));

STUBBING OVERRIDING:
  // Later stub for SAME arguments overrides the earlier one
  when(repo.findById("user-1")).thenReturn(Optional.of(userV1));
  
  // ... some time later, in the same test:
  when(repo.findById("user-1")).thenReturn(Optional.of(userV2));  // overrides!
  
  // Now findById("user-1") returns userV2

3. thenThrow — THROWING EXCEPTIONS
================================================================

BASIC USAGE:
  // Throw checked exception
  when(fileReader.read("missing.txt"))
      .thenThrow(new FileNotFoundException("File not found"));
  
  // Throw unchecked exception
  when(userRepository.findById(null))
      .thenThrow(new IllegalArgumentException("ID cannot be null"));
  
  // Throw using class (Mockito instantiates it)
  when(userRepository.findById("bad"))
      .thenThrow(DatabaseException.class);  // must have no-arg constructor
  
  // Chain: return then throw
  when(pollService.getStatus())
      .thenReturn("PENDING")
      .thenReturn("PENDING")
      .thenThrow(new TimeoutException("Job timed out"));

THROWING FROM VOID METHODS:
  // Void methods can't use when().thenThrow() — use doThrow()
  doThrow(new SmtpException("Connection refused"))
      .when(emailService).sendEmail(any(EmailRequest.class));
  
  // Verify exception propagates
  assertThrows(SmtpException.class, 
      () -> notificationService.notify(user));
  
  // doThrow with class
  doThrow(SmtpException.class)
      .when(emailService).sendEmail(any());

SIMULATING TRANSIENT FAILURES:
  // First call throws, second succeeds
  when(externalApi.getData(anyString()))
      .thenThrow(new HttpTimeoutException("Timeout"))
      .thenReturn(new ApiResponse(200, "OK", data));
  
  // Test retry logic
  ApiResponse result = retryService.getWithRetry("endpoint");
  
  assertEquals(200, result.getStatus());
  verify(externalApi, times(2)).getData(anyString());

4. thenAnswer — DYNAMIC RESPONSES
================================================================

Use when:
  - The return value depends on the input argument
  - You need to compute the return value dynamically
  - You want to capture arguments inline
  - You need to simulate complex behavior

BASIC ANSWER:
  when(idGenerator.generate()).thenAnswer(invocation -> 
      UUID.randomUUID().toString()  // new UUID on EVERY call
  );
  
  when(userRepository.save(any(User.class))).thenAnswer(invocation -> {
      User user = invocation.getArgument(0, User.class);
      user.setId("generated-" + user.getName());
      user.setCreatedAt(Instant.now());
      return user;
  });

ACCESSING INVOCATION DETAILS:
  when(repo.findByFilter(any(SearchFilter.class))).thenAnswer(invocation -> {
      SearchFilter filter = invocation.getArgument(0, SearchFilter.class);
      
      // Dynamic filter-based response
      if (filter.getStatus() == Status.ACTIVE) {
          return List.of(activeUser1, activeUser2);
      } else if (filter.getStatus() == Status.DELETED) {
          return Collections.emptyList();
      }
      return allUsers;
  });

SIMULATING STATEFUL BEHAVIOR:
  Map<String, User> fakeDb = new HashMap<>();
  
  // save → stores in map
  when(userRepository.save(any(User.class))).thenAnswer(inv -> {
      User user = inv.getArgument(0, User.class);
      fakeDb.put(user.getId(), user);
      return user;
  });
  
  // findById → looks up in map
  when(userRepository.findById(anyString())).thenAnswer(inv -> {
      String id = inv.getArgument(0, String.class);
      return Optional.ofNullable(fakeDb.get(id));
  });
  
  // Now you have a lightweight in-memory fake!

INVOCATION OBJECT METHODS:
  InvocationOnMock invocation:
    invocation.getArguments()              → Object[] of all arguments
    invocation.getArgument(0)              → first arg (Object)
    invocation.getArgument(0, String.class)→ first arg, cast to type
    invocation.getMock()                   → the mock object itself
    invocation.getMethod()                 → the Method being called
    invocation.callRealMethod()            → call actual implementation

ANSWER FOR VOID METHODS:
  // doAnswer for void methods
  doAnswer(invocation -> {
      EmailRequest req = invocation.getArgument(0, EmailRequest.class);
      capturedEmails.add(req);  // collect for assertion
      return null;              // void methods must return null
  }).when(emailService).sendEmail(any(EmailRequest.class));

PREDEFINED ANSWER STRATEGIES:
  // Answers enum contains common strategies:
  
  Answers.CALLS_REAL_METHODS   // call real implementation (like spy)
  Answers.RETURNS_DEEP_STUBS   // chain of mocks: a.getB().getC()
  Answers.RETURNS_SMART_NULLS  // return SmartNull (throws on use)
  Answers.RETURNS_MOCKS        // return new mock for each call
  Answers.RETURNS_SELF         // return the mock itself (builder chains)
  
  // Example: RETURNS_SELF for builder chains
  QueryBuilder builder = mock(QueryBuilder.class, RETURNS_SELF);
  
  when(builder.build()).thenReturn(query);
  
  // Now builder methods return themselves:
  Query q = builder.select("name").where("age > 18").limit(10).build();

5. thenCallRealMethod
================================================================

  // Call the real (non-mocked) implementation
  when(userService.formatName(anyString()))
      .thenCallRealMethod();
  
  // Or with doCallRealMethod():
  doCallRealMethod().when(userService).expensiveValidation(any());
  
  // Useful for:
  // - Testing abstract base classes with partial implementation
  // - Calling real logic for some methods while mocking others
  // - Testing default interface methods

  abstract class AbstractOrderProcessor {
      public String generateOrderId(String prefix) {
          return prefix + "-" + System.currentTimeMillis();  // real logic
      }
      
      abstract void processOrder(Order order);  // subclass specific
  }
  
  AbstractOrderProcessor mock = mock(AbstractOrderProcessor.class);
  when(mock.generateOrderId(anyString())).thenCallRealMethod();  // test real logic
  doNothing().when(mock).processOrder(any());  // abstract - do nothing

6. doReturn / doThrow / doNothing / doAnswer / doCallRealMethod
================================================================

These are EQUIVALENT to thenReturn/thenThrow but with different syntax.
REQUIRED in these cases:
  1. Stubbing void methods (can't use when().then_ for void)
  2. Stubbing spy methods (avoids calling real method during setup)
  3. Overriding an existing stubbing

COMPLETE REFERENCE:

doReturn(value).when(mock).method(args)
  → Equivalent to when(mock.method(args)).thenReturn(value)
  → SAFE for spies: does NOT call real method during setup

doThrow(exception).when(mock).method(args)
doThrow(ExceptionClass.class).when(mock).method(args)
  → Equivalent to when(mock.method(args)).thenThrow(exception)
  → ONLY option for void methods

doNothing().when(mock).voidMethod(args)
  → Make a void method do nothing (default for mocks, needed to override spy)
  
doAnswer(answer).when(mock).method(args)
  → Equivalent to when(mock.method(args)).thenAnswer(answer)
  → ONLY option for void methods needing custom logic

doCallRealMethod().when(mock).method(args)
  → Equivalent to when(mock.method(args)).thenCallRealMethod()

CHAINING do* stubs:
  doThrow(new NetworkException())
      .doReturn("second-response")
      .doReturn("cached-response")
      .when(httpClient).get(anyString());
  
  // 1st call → throws NetworkException
  // 2nd call → "second-response"
  // 3rd+ call → "cached-response"

STUBBING VOID METHOD EXAMPLE:
  // Without doNothing / doThrow, you can't use when() on void methods
  
  // This DOESN'T compile:
  // when(emailService.send(any())).thenReturn();  // compilation error
  
  // CORRECT:
  doNothing().when(emailService).send(any(EmailRequest.class));
  
  doThrow(new SmtpException("SMTP not available"))
      .when(emailService).send(any(EmailRequest.class));
  
  doAnswer(invocation -> {
      log.info("Would send: " + invocation.getArgument(0));
      return null;
  }).when(emailService).send(any(EmailRequest.class));

7. ARGUMENT MATCHERS IN STUBBING
================================================================

When you use ANY matcher in a call, ALL arguments must be matchers:

  // WRONG — mixing literal and matcher:
  // when(service.find("user", anyInt())).thenReturn(result);  // fails!
  
  // CORRECT — use eq() for literal values:
  when(service.find(eq("user"), anyInt())).thenReturn(result);
  when(service.find(eq("user"), eq(42))).thenReturn(result);

COMMON MATCHERS:
  any()                    // any object (including null in older versions)
  any(ClassName.class)     // any instance of specific class (not null)
  anyString()              // any non-null String
  anyInt() / anyLong()     // any primitive
  anyList() / anyMap()     // any collection
  
  eq(value)                // exact equality
  same(object)             // reference equality (==)
  
  isNull() / isNotNull()   // null checks
  notNull()                // alias for isNotNull()
  
  startsWith("prefix")     // String starts with
  endsWith("suffix")       // String ends with
  contains("substring")    // String contains
  matches("regex.*")       // regex match
  
  argThat(predicate)       // custom predicate
  intThat(predicate)       // for primitive int
  
  // Examples:
  when(service.search(argThat(filter -> filter.getAge() >= 18)))
      .thenReturn(adultUsers);
  
  when(repo.findByEmail(argThat(email -> email.contains("@company.com"))))
      .thenReturn(Optional.of(employee));

8. COMMON PATTERNS AND BEST PRACTICES
================================================================

PATTERN: Builder chain stubbing (RETURNS_SELF)
  JpaQueryBuilder builder = mock(JpaQueryBuilder.class, RETURNS_SELF);
  when(builder.build()).thenReturn(finalQuery);
  
  Query q = builder.from(User.class).where("active = true").build();

PATTERN: Capture-while-stubbing with Answer
  List<EmailRequest> sentEmails = new ArrayList<>();
  doAnswer(inv -> {
      sentEmails.add(inv.getArgument(0, EmailRequest.class));
      return null;
  }).when(emailClient).send(any());
  
  // ...run code under test...
  
  assertEquals(2, sentEmails.size());
  assertEquals("welcome@company.com", sentEmails.get(0).getTo());

PATTERN: Test first call fails, then succeeds (retry testing)
  AtomicInteger callCount = new AtomicInteger(0);
  when(externalService.call()).thenAnswer(inv -> {
      if (callCount.incrementAndGet() < 3) {
          throw new RetryableException("Temporary failure");
      }
      return successResponse;
  });
  
  Result result = retryableClient.callWithRetry();  // retries 3 times
  
  assertEquals(successResponse, result);
  verify(externalService, times(3)).call();

ANTI-PATTERN: Overly broad stubbing
  // BAD — stubs everything (will fail with STRICT_STUBS if unused)
  when(userRepository.findById(anyString())).thenReturn(Optional.of(testUser));
  when(userRepository.findAll()).thenReturn(List.of(testUser));
  when(userRepository.save(any())).thenReturn(testUser);
  
  // Only the first stub is used — STRICT_STUBS catches this!

ANTI-PATTERN: Returning mutable shared objects
  // BAD — tests sharing the same mutable object:
  User shared = new User("alice");
  when(repo.findById(any())).thenReturn(Optional.of(shared));
  
  // GOOD — new instance each time:
  when(repo.findById(any())).thenAnswer(inv -> 
      Optional.of(new User("alice")));

9. STRICT STUBS AND UNNECESSARY STUBBING
================================================================

With STRICT_STUBS (default in MockitoExtension):
  
  // This will FAIL the test because the stub is never called:
  when(repo.findById("unused-key")).thenReturn(Optional.empty());
  // ^ UnnecessaryStubbingException thrown at end of test
  
  // Solution 1: Remove the unused stub
  // Solution 2: If needed for documentation, use lenient():
  lenient().when(repo.findById("unused-key")).thenReturn(Optional.empty());

10. INTERVIEW QUESTIONS
================================================================

Q: What is the difference between thenReturn and thenAnswer?
A: thenReturn returns a fixed pre-configured value.
   thenAnswer executes a lambda/Answer object at call-time, allowing
   dynamic responses based on the actual arguments passed or computed state.

Q: How do you stub a void method in Mockito?
A: Use doNothing(), doThrow(), or doAnswer() with .when(mock).method():
   doNothing().when(emailService).sendEmail(any());
   doThrow(new SmtpException()).when(emailService).sendEmail(any());

Q: How do you make a mock return different values on successive calls?
A: Chain thenReturn/thenThrow:
   when(service.call()).thenReturn("first").thenReturn("second").thenThrow(ex);
   Or use varargs: when(service.call()).thenReturn("first", "second", "third");

Q: Why would you use doReturn instead of when/thenReturn?
A: For void methods (must use doReturn/doNothing/doThrow/doAnswer).
   For spies, to avoid calling the real method during stub setup.
   when(spy.method()) calls the real method; doReturn() does not.

Q: What is UnnecessaryStubbingException and how do you fix it?
A: Thrown by STRICT_STUBS when a stub is configured but never invoked
   during the test. Fix by removing the unused stub, or using lenient()
   if the stub is intentionally present for edge cases.

Q: How do you make a mock simulate stateful behavior?
A: Use thenAnswer with a shared data structure (e.g., HashMap):
   Map<String, User> db = new HashMap<>();
   when(repo.save(any())).thenAnswer(inv -> { 
       User u = inv.getArgument(0); db.put(u.getId(), u); return u; });
   when(repo.findById(anyString())).thenAnswer(inv ->
       Optional.ofNullable(db.get(inv.getArgument(0, String.class))));

Q: What is thenCallRealMethod used for?
A: Calling the real (non-mocked) implementation for specific methods
   on a mock. Useful for testing abstract base class concrete methods,
   or default interface methods, while mocking the abstract methods.
