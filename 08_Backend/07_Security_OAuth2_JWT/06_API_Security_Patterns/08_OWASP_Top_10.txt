OWASP TOP 10 — JAVA/SPRING PERSPECTIVE
========================================

=== OVERVIEW ===

OWASP Top 10 is the standard reference for web application security risks.
Updated regularly by OWASP (Open Web Application Security Project).
Current version: OWASP Top 10 2021.

=== A01: BROKEN ACCESS CONTROL ===

What: Users can access resources/actions they shouldn't.
Examples:
  - User changes URL from /users/123 to /users/456 to access another user's data
  - User elevates privileges by modifying JWT role claim
  - Missing authorization check on DELETE /admin/users/{id}

Java/Spring mitigations:
  @PreAuthorize("@userService.isOwner(authentication, #id)")
  public Resource getResource(@PathVariable Long id) { ... }

  // Method-level security
  @EnableMethodSecurity
  @PreAuthorize("hasRole('ADMIN')")
  @PostAuthorize("returnObject.userId == authentication.principal.id")

  // Always validate ownership, not just authentication

=== A02: CRYPTOGRAPHIC FAILURES ===

What: Weak or missing encryption of sensitive data.
Examples:
  - Passwords stored in plaintext or with MD5/SHA1
  - Sensitive data transmitted over HTTP
  - Weak random number generation (Math.random() for security tokens)

Java/Spring mitigations:
  // Passwords: always BCrypt (or Argon2, SCrypt)
  PasswordEncoder encoder = new BCryptPasswordEncoder(12);
  // In Spring Security:
  @Bean
  public PasswordEncoder passwordEncoder() {
      return new BCryptPasswordEncoder();
  }

  // Secure random
  SecureRandom random = new SecureRandom();
  byte[] token = new byte[32];
  random.nextBytes(token);

  // Force HTTPS
  http.requiresChannel().anyRequest().requiresSecure();

=== A03: INJECTION ===

What: Attacker injects malicious code (SQL, LDAP, OS commands).
Examples:
  - SQL: SELECT * FROM users WHERE name = 'admin'--'
  - JNDI injection (Log4Shell — Log4j vulnerability)
  - SpEL injection in Spring

Java/Spring mitigations:
  // SQL: use parameterized queries — NEVER string concatenation
  // Bad:
  String query = "SELECT * FROM users WHERE name = '" + name + "'";
  // Good:
  String query = "SELECT * FROM users WHERE name = ?";
  jdbcTemplate.queryForObject(query, new Object[]{name}, User.class);

  // Spring Data JPA (safe by default with @Query + params):
  @Query("SELECT u FROM User u WHERE u.name = :name")
  User findByName(@Param("name") String name);

  // Validate and sanitize all inputs
  // Use allowlists, not denylists
  // Log4j: update to 2.17.1+ (Log4Shell patch)

=== A04: INSECURE DESIGN ===

What: Missing or ineffective security controls at design level.
Examples:
  - No rate limiting on login endpoint (brute force attacks)
  - No email verification for account creation
  - Forgot password sends password in plaintext

Java/Spring mitigations:
  // Rate limiting on auth endpoints
  @RateLimiter(name = "login", fallbackMethod = "loginRateLimitFallback")
  public ResponseEntity<LoginResponse> login(@RequestBody LoginRequest req) { ... }

  // Account lockout after N failed attempts
  // Use security design patterns from day 1

=== A05: SECURITY MISCONFIGURATION ===

What: Insecure default settings, unnecessary features enabled.
Examples:
  - Spring Boot Actuator exposed without authentication
  - Stack traces exposed to end users
  - Default credentials not changed
  - CORS configured as allowedOrigins("*") with credentials

Java/Spring mitigations:
  # Actuator security
  management:
    endpoints:
      web:
        exposure:
          include: health, info  # NOT * in production
    endpoint:
      health:
        show-details: when-authorized

  # Hide error details from clients
  server:
    error:
      include-stacktrace: never
      include-message: never

  # Restrictive CORS
  @Bean
  public CorsConfigurationSource corsConfigurationSource() {
      CorsConfiguration config = new CorsConfiguration();
      config.setAllowedOrigins(List.of("https://myapp.com"));
      config.setAllowedMethods(List.of("GET", "POST", "PUT", "DELETE"));
      config.setAllowCredentials(true);
      // ...
  }

=== A06: VULNERABLE AND OUTDATED COMPONENTS ===

What: Using libraries with known vulnerabilities.
Examples:
  - Log4j 2.14.1 (Log4Shell — CVE-2021-44228)
  - Jackson with polymorphism enabled (deserialization attacks)
  - Old Spring versions with unpatched CVEs

Java/Spring mitigations:
  // OWASP Dependency Check Maven plugin
  <plugin>
      <groupId>org.owasp</groupId>
      <artifactId>dependency-check-maven</artifactId>
      <version>9.0.0</version>
  </plugin>
  // Run: mvn dependency-check:check

  // Snyk, GitHub Dependabot, JFrog Xray for automated CVE scanning
  // Keep all dependencies updated
  // Monitor CVE databases

=== A07: IDENTIFICATION AND AUTHENTICATION FAILURES ===

What: Weak authentication mechanisms.
Examples:
  - No multi-factor authentication
  - Session IDs in URLs
  - Weak password requirements

Java/Spring mitigations:
  // Session fixation protection (Spring Security default)
  http.sessionManagement()
      .sessionFixation().migrateSession()
      .invalidSessionUrl("/login?expired");

  // JWT expiry
  Claims claims = Jwts.parser()
      .setSigningKey(key)
      .parseClaimsJws(token)
      .getBody(); // throws ExpiredJwtException if expired

  // Use secure, HttpOnly, SameSite cookies
  server:
    servlet:
      session:
        cookie:
          http-only: true
          secure: true
          same-site: strict

=== A08: SOFTWARE AND DATA INTEGRITY FAILURES ===

What: Code/data not verified for integrity before use.
Examples:
  - Insecure deserialization (Java ObjectInputStream)
  - CI/CD pipeline without artifact signing

Java mitigations:
  // Avoid Java serialization for security-sensitive data
  // Use JSON/Protobuf instead of Java native serialization
  // Disable Java deserialization in JVM flags if not needed:
  -Djdk.serialFilter=*;!*

  // Jackson: disable dangerous polymorphic typing
  mapper.activateDefaultTyping(...) // AVOID unless necessary

=== A09: SECURITY LOGGING AND MONITORING FAILURES ===

What: Not detecting or logging security events.
Examples:
  - Failed login attempts not logged
  - No alerts for suspicious activity
  - Logs missing context (no IP, user, timestamp)

Java/Spring mitigations:
  @EventListener
  public void onAuthenticationFailure(AbstractAuthenticationFailureEvent event) {
      String username = event.getAuthentication().getName();
      String ip = getClientIp();
      log.warn("Login failure - user: {}, ip: {}, reason: {}",
               username, ip, event.getException().getMessage());
      // Increment failure counter, lock account after N failures
  }

  // Include: timestamp, user, IP, action, success/failure, resource

=== A10: SERVER-SIDE REQUEST FORGERY (SSRF) ===

What: Attacker makes server fetch an internal URL.
Example:
  POST /api/fetch?url=http://169.254.169.254/latest/meta-data/
  → Fetches AWS EC2 metadata → exposes instance credentials

Java/Spring mitigations:
  // Validate and sanitize URLs before making server-side requests
  public void fetchUrl(String url) {
      URL parsed = new URL(url);
      String host = parsed.getHost();
      // Allowlist of permitted hosts
      if (!ALLOWED_HOSTS.contains(host)) {
          throw new IllegalArgumentException("URL not allowed: " + host);
      }
      // Block private IP ranges: 10.x, 192.168.x, 169.254.x, 127.x
      InetAddress addr = InetAddress.getByName(host);
      if (addr.isSiteLocalAddress() || addr.isLoopbackAddress() ||
          addr.isLinkLocalAddress()) {
          throw new IllegalArgumentException("Private IP not allowed");
      }
      httpClient.get(url);
  }
