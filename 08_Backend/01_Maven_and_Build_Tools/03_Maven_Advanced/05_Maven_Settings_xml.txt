WHAT IS SETTINGS.XML?
──────────────────────
settings.xml is Maven's personal configuration file. Unlike pom.xml which is
project-specific and committed to source control, settings.xml contains
machine-specific or user-specific configuration that should NOT be in the project.

  Contains:
  • Credentials for private repositories
  • Proxy configuration for corporate networks
  • Mirror configuration
  • Local repository path
  • Active profiles
  • Plugin groups

─────────────────────────────────────────────────────────────────────────────────
FILE LOCATIONS
─────────────────────────────────────────────────────────────────────────────────

  1. User-level (most common):  ~/.m2/settings.xml
     Overrides global settings for the current user only.

  2. Global/installation-level: ${M2_HOME}/conf/settings.xml
     Applies to all users using this Maven installation.
     Where M2_HOME is the Maven installation directory.

  Maven merges both: user settings override global settings.

  Specify an explicit settings file at build time:
  mvn clean install -s /path/to/custom-settings.xml
  mvn clean install --settings /path/to/ci-settings.xml

─────────────────────────────────────────────────────────────────────────────────
COMPLETE SETTINGS.XML STRUCTURE
─────────────────────────────────────────────────────────────────────────────────

  <?xml version="1.0" encoding="UTF-8"?>
  <settings xmlns="http://maven.apache.org/SETTINGS/1.2.0"
            xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
            xsi:schemaLocation="http://maven.apache.org/SETTINGS/1.2.0
                                https://maven.apache.org/xsd/settings-1.2.0.xsd">

    <!-- 1. LOCAL REPOSITORY -->
    <localRepository>/custom/path/.m2/repository</localRepository>
    <!-- Default: ${user.home}/.m2/repository -->

    <!-- 2. INTERACTIVE / OFFLINE MODE -->
    <interactiveMode>false</interactiveMode>    <!-- false = batch mode always -->
    <offline>false</offline>                    <!-- true = never go to internet -->
    <usePluginRegistry>false</usePluginRegistry>

    <!-- 3. PLUGIN GROUPS (shorthand for plugin GAV) -->
    <pluginGroups>
      <pluginGroup>org.sonarsource.scanner.maven</pluginGroup>
      <!-- Allows: mvn sonar:sonar (instead of full plugin GAV) -->
    </pluginGroups>

    <!-- 4. PROXIES -->
    <proxies>
      <proxy>
        <id>corporate-proxy</id>
        <active>true</active>
        <protocol>https</protocol>
        <host>proxy.company.com</host>
        <port>8080</port>
        <username>user</username>                  <!-- optional -->
        <password>secret</password>                <!-- optional -->
        <nonProxyHosts>localhost|*.company.com|10.*</nonProxyHosts>
      </proxy>
    </proxies>

    <!-- 5. SERVERS (credentials) -->
    <servers>
      <server>
        <id>nexus-releases</id>           <!-- Must match <repository><id> in pom.xml -->
        <username>deploy-user</username>
        <password>{ENCRYPTED_PASSWORD}</password>
      </server>
      <server>
        <id>nexus-snapshots</id>
        <username>deploy-user</username>
        <password>{ENCRYPTED_PASSWORD}</password>
      </server>
      <!-- GitHub Packages uses token authentication: -->
      <server>
        <id>github</id>
        <username>YOUR_GITHUB_USERNAME</username>
        <password>ghp_YourPersonalAccessToken</password>
      </server>
    </servers>

    <!-- 6. MIRRORS -->
    <mirrors>
      <!-- Route ALL requests through corporate Nexus -->
      <mirror>
        <id>nexus-mirror</id>
        <name>Corporate Nexus (All repos)</name>
        <url>https://nexus.company.com/repository/maven-public/</url>
        <mirrorOf>*</mirrorOf>           <!-- All repositories -->
      </mirror>
      <!-- Or just mirror Maven Central -->
      <!--
      <mirror>
        <id>central-mirror</id>
        <url>https://nexus.company.com/repository/maven-central/</url>
        <mirrorOf>central</mirrorOf>
      </mirror>
      -->
    </mirrors>

    <!-- 7. PROFILES -->
    <profiles>
      <!-- Profile to configure corporate repo access -->
      <profile>
        <id>corporate</id>
        <repositories>
          <repository>
            <id>nexus-releases</id>
            <url>https://nexus.company.com/repository/maven-releases/</url>
            <releases><enabled>true</enabled></releases>
            <snapshots><enabled>false</enabled></snapshots>
          </repository>
          <repository>
            <id>nexus-snapshots</id>
            <url>https://nexus.company.com/repository/maven-snapshots/</url>
            <releases><enabled>false</enabled></releases>
            <snapshots><enabled>true</enabled></snapshots>
          </repository>
        </repositories>
        <pluginRepositories>
          <pluginRepository>
            <id>nexus-plugin-releases</id>
            <url>https://nexus.company.com/repository/maven-releases/</url>
            <releases><enabled>true</enabled></releases>
            <snapshots><enabled>false</enabled></snapshots>
          </pluginRepository>
        </pluginRepositories>
      </profile>
    </profiles>

    <!-- 8. ACTIVE PROFILES (always activated) -->
    <activeProfiles>
      <activeProfile>corporate</activeProfile>
    </activeProfiles>

  </settings>

PASSWORD ENCRYPTION
─────────────────────────────────────────────────────────────────────────────────

  Never store plain-text passwords in settings.xml. Use Maven's built-in
  password encryption:

  Step 1: Create master password (stored in ~/.m2/settings-security.xml)
  ────────────────────────────────────────────────────────────────────────
  mvn --encrypt-master-password

  Enter the master password at the prompt.
  Output: {3sA58Yk0EYfzRXDYjGJoEnkV9...=}

  ~/.m2/settings-security.xml:
  <settingsSecurity>
    <master>{3sA58Yk0EYfzRXDYjGJoEnkV9...=}</master>
  </settingsSecurity>

  Step 2: Encrypt each server password
  ──────────────────────────────────────
  mvn --encrypt-password myNexusPassword

  Output: {COQLCE6DU6GtcS5P=}

  Step 3: Use encrypted passwords in settings.xml
  ─────────────────────────────────────────────────
  <server>
    <id>nexus-releases</id>
    <username>deploy-user</username>
    <password>{COQLCE6DU6GtcS5P=}</password>
  </server>

─────────────────────────────────────────────────────────────────────────────────
CI/CD SETTINGS.XML PATTERN
─────────────────────────────────────────────────────────────────────────────────

  Pattern: Commit a template settings.xml to the repo that reads from
  environment variables. Inject secrets from CI/CD vault/secrets.

  .github/maven/settings.xml (committed to repo):
  ──────────────────────────────────────────────────
  <settings>
    <servers>
      <server>
        <id>nexus-releases</id>
        <username>${env.NEXUS_USER}</username>
        <password>${env.NEXUS_PASSWORD}</password>
      </server>
    </servers>
    <mirrors>
      <mirror>
        <id>nexus</id>
        <url>${env.NEXUS_URL}</url>
        <mirrorOf>*</mirrorOf>
      </mirror>
    </mirrors>
  </settings>

  CI command (GitHub Actions):
  ./mvnw deploy -s .github/maven/settings.xml
  env:
    NEXUS_USER: ${{ secrets.NEXUS_USER }}
    NEXUS_PASSWORD: ${{ secrets.NEXUS_PASSWORD }}
    NEXUS_URL: https://nexus.company.com/repository/maven-public/

DEBUGGING SETTINGS
─────────────────────────────────────────────────────────────────────────────────

  # Show which settings.xml is being used:
  mvn --version  (shows Maven home)

  # Show effective settings (merged global + user):
  mvn help:effective-settings

  # Show active profiles (from settings.xml):
  mvn help:active-profiles

  # Debug mirror resolution:
  mvn -X clean compile 2>&1 | grep -i mirror

─────────────────────────────────────────────────────────────────────────────────
COMMON SETTINGS.XML MISTAKES
─────────────────────────────────────────────────────────────────────────────────

  ❌ Committing settings.xml with plaintext passwords to source control
  ❌ Using <mirrorOf>*</mirrorOf> and then wondering why your local Nexus is hit
     for everything, including when offline
  ❌ Server <id> doesn't match repository <id> — authentication silently fails
  ❌ Forgetting <activeProfiles> — profile is defined but never activated
  ❌ Using mirrorOf>* but your Nexus doesn't proxy all needed repos
     (CI fails downloading from Spring Milestones, Confluent, etc.)

─────────────────────────────────────────────────────────────────────────────────
INTERVIEW QUICK-HITS
─────────────────────────────────────────────────────────────────────────────────

Q: What is settings.xml and what belongs in it vs pom.xml?
A: settings.xml is Maven's user/machine-specific configuration file (at ~/.m2/settings.xml
   or ${M2_HOME}/conf/settings.xml). It contains things that differ per developer
   or environment: credentials, proxy settings, mirror configurations, and local
   repo path. pom.xml is project-specific and committed to source control —
   it should never contain credentials or machine-specific paths.

Q: How do you avoid storing plain-text passwords in settings.xml?
A: Use Maven's built-in password encryption: "mvn --encrypt-master-password" creates
   a master key in settings-security.xml, then "mvn --encrypt-password" encrypts each
   server password. In CI/CD, use environment variables (${env.MY_SECRET}) in
   settings.xml and inject actual values from CI secrets.

Q: How do you make a settings.xml profile always active?
A: Use the <activeProfiles> section at the root of settings.xml:
   <activeProfiles><activeProfile>my-profile</activeProfile></activeProfiles>
   This activates the named profile for all builds without needing -P on the command line.

Q: What is the difference between a global settings.xml and a user settings.xml?
A: Global settings.xml is in ${M2_HOME}/conf/ and applies to all users of that
   Maven installation. User settings.xml is in ~/.m2/ and applies only to the
   current user. User settings override global settings for any overlapping config.
   User settings are personal; global settings are system-admin-managed.

Q: How do you specify a custom settings.xml for a CI/CD pipeline?
A: Use: mvn deploy -s /path/to/ci-settings.xml
   It's common to commit a non-sensitive settings.xml template to the project
   repository (e.g., .github/maven/settings.xml) that reads credentials from
   environment variables, then reference it in CI commands.
