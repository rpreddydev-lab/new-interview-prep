WHAT IS THE POM?
────────────────
The POM (Project Object Model) is the fundamental unit of Maven. It is an XML
file (pom.xml) that describes:
  • Project metadata (name, version, description, URL, licenses, developers)
  • Build configuration (source directories, plugins, goals)
  • Dependencies (libraries, their versions, scopes)
  • Reporting (documentation plugins)
  • Relationships (parent, modules, distributionManagement)

Every Maven project MUST have a pom.xml at its root.

─────────────────────────────────────────────────────────────────────────────────
MINIMAL POM
─────────────────────────────────────────────────────────────────────────────────

  <?xml version="1.0" encoding="UTF-8"?>
  <project xmlns="http://maven.apache.org/POM/4.0.0"
           xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
           xsi:schemaLocation="http://maven.apache.org/POM/4.0.0
                               http://maven.apache.org/xsd/maven-4.0.0.xsd">

    <modelVersion>4.0.0</modelVersion>   <!-- Always 4.0.0 for Maven 2/3 -->

    <groupId>com.example</groupId>
    <artifactId>my-application</artifactId>
    <version>1.0.0-SNAPSHOT</version>

  </project>

  These four elements (modelVersion + GAV) are the absolute minimum.
  Default packaging is "jar" if not specified.

─────────────────────────────────────────────────────────────────────────────────
COMPLETE POM STRUCTURE — ALL MAJOR SECTIONS
─────────────────────────────────────────────────────────────────────────────────

  <?xml version="1.0" encoding="UTF-8"?>
  <project>
    <modelVersion>4.0.0</modelVersion>

    <!-- ── 1. PROJECT IDENTITY ── -->
    <groupId>com.example</groupId>
    <artifactId>my-app</artifactId>
    <version>1.0.0-SNAPSHOT</version>
    <packaging>jar</packaging>          <!-- jar | war | ear | pom -->
    <name>My Application</name>
    <description>A sample Java application</description>
    <url>https://github.com/example/my-app</url>

    <!-- ── 2. PARENT ── (for child modules) -->
    <parent>
      <groupId>com.example</groupId>
      <artifactId>parent-pom</artifactId>
      <version>1.0.0</version>
      <relativePath>../pom.xml</relativePath>
    </parent>

    <!-- ── 3. PROPERTIES ── -->
    <properties>
      <java.version>17</java.version>
      <maven.compiler.source>${java.version}</maven.compiler.source>
      <maven.compiler.target>${java.version}</maven.compiler.target>
      <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
      <spring.boot.version>3.2.0</spring.boot.version>
    </properties>

    <!-- ── 4. DEPENDENCY MANAGEMENT ── (version locking, BOMs) -->
    <dependencyManagement>
      <dependencies>
        <dependency>
          <groupId>org.springframework.boot</groupId>
          <artifactId>spring-boot-dependencies</artifactId>
          <version>${spring.boot.version}</version>
          <type>pom</type>
          <scope>import</scope>
        </dependency>
      </dependencies>
    </dependencyManagement>

    <!-- ── 5. DEPENDENCIES ── -->
    <dependencies>
      <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-web</artifactId>
        <!-- version omitted — managed by BOM above -->
      </dependency>
      <dependency>
        <groupId>org.projectlombok</groupId>
        <artifactId>lombok</artifactId>
        <scope>provided</scope>
      </dependency>
      <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-test</artifactId>
        <scope>test</scope>
      </dependency>
    </dependencies>

    <!-- ── 6. BUILD ── -->
    <build>
      <!-- Override default source/resource directories -->
      <sourceDirectory>src/main/java</sourceDirectory>
      <testSourceDirectory>src/test/java</testSourceDirectory>

      <!-- Resource filtering -->
      <resources>
        <resource>
          <directory>src/main/resources</directory>
          <filtering>true</filtering>   <!-- Substitute ${property} in resources -->
        </resource>
      </resources>

      <!-- Plugin configuration -->
      <pluginManagement>
        <plugins>
          <plugin>
            <groupId>org.apache.maven.plugins</groupId>
            <artifactId>maven-compiler-plugin</artifactId>
            <version>3.11.0</version>
            <configuration>
              <source>${java.version}</source>
              <target>${java.version}</target>
              <encoding>UTF-8</encoding>
            </configuration>
          </plugin>
        </plugins>
      </pluginManagement>

      <plugins>
        <plugin>
          <groupId>org.springframework.boot</groupId>
          <artifactId>spring-boot-maven-plugin</artifactId>
          <configuration>
            <excludes>
              <exclude>
                <groupId>org.projectlombok</groupId>
                <artifactId>lombok</artifactId>
              </exclude>
            </excludes>
          </configuration>
        </plugin>
      </plugins>
    </build>

    <!-- ── 7. PROFILES ── (environment-specific builds) -->
    <profiles>
      <profile>
        <id>production</id>
        <properties>
          <spring.profiles.active>prod</spring.profiles.active>
        </properties>
        <activation>
          <property>
            <name>env</name>
            <value>prod</value>
          </property>
        </activation>
      </profile>
    </profiles>

    <!-- ── 8. REPOSITORIES ── (additional artifact sources) -->
    <repositories>
      <repository>
        <id>company-nexus</id>
        <url>https://nexus.company.com/repository/maven-public/</url>
        <releases><enabled>true</enabled></releases>
        <snapshots><enabled>false</enabled></snapshots>
      </repository>
    </repositories>

    <!-- ── 9. DISTRIBUTION MANAGEMENT ── (where to deploy artifacts) -->
    <distributionManagement>
      <repository>
        <id>company-releases</id>
        <url>https://nexus.company.com/repository/maven-releases/</url>
      </repository>
      <snapshotRepository>
        <id>company-snapshots</id>
        <url>https://nexus.company.com/repository/maven-snapshots/</url>
      </snapshotRepository>
    </distributionManagement>

    <!-- ── 10. PROJECT INFO ── -->
    <licenses>
      <license>
        <name>Apache License, Version 2.0</name>
        <url>https://www.apache.org/licenses/LICENSE-2.0</url>
      </license>
    </licenses>
    <developers>
      <developer>
        <id>jdoe</id>
        <name>John Doe</name>
        <email>jdoe@example.com</email>
      </developer>
    </developers>

  </project>

─────────────────────────────────────────────────────────────────────────────────
SUPER POM
─────────────────────────────────────────────────────────────────────────────────

  Every POM implicitly inherits from the Super POM (the "base" POM shipped with
  Maven itself). The Super POM defines:
  • Default source directories (src/main/java, src/test/java, etc.)
  • Central repository reference
  • Default plugin versions
  • Default resource directories

  To see what you actually get after inheritance merging:
  mvn help:effective-pom

  The effective POM is the merged result of: Super POM → Parent POM → Your POM

PROPERTIES — POWER AND PATTERNS
─────────────────────────────────────────────────────────────────────────────────

  Properties are key-value pairs used throughout the POM as ${propertyName}.

  Types of Properties:
  ────────────────────
  1. POM properties:        ${project.version}, ${project.artifactId}
  2. User-defined:          <properties><my.version>1.0</my.version></properties>
  3. System properties:     ${java.version} (JVM system properties)
  4. Environment variables: ${env.HOME}, ${env.JAVA_HOME}
  5. Settings properties:   ${settings.localRepository}

  Best Practices:
  • Define all dependency versions in <properties>
  • Use ${maven.compiler.source} and ${maven.compiler.target} for Java version
  • Use ${project.build.sourceEncoding} = UTF-8 to avoid platform encoding issues

  <properties>
    <java.version>21</java.version>
    <maven.compiler.source>${java.version}</maven.compiler.source>
    <maven.compiler.target>${java.version}</maven.compiler.target>
    <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
    <!-- Dependency versions -->
    <jackson.version>2.16.0</jackson.version>
    <mockito.version>5.8.0</mockito.version>
  </properties>

─────────────────────────────────────────────────────────────────────────────────
dependencyManagement vs dependencies
─────────────────────────────────────────────────────────────────────────────────

  <dependencyManagement>
  • Declares VERSIONS and SCOPE for dependencies
  • Does NOT actually add the dependency to the project
  • Used in parent POMs to centralize version control for child modules
  • Child modules can use the dependency without specifying a version

  <dependencies>
  • Actually adds the dependency to the project's classpath
  • If a version is in <dependencyManagement>, you don't need to repeat it here

  Pattern for parent POM:
  ─────────────────────────────────────────────────────────────
  Parent <dependencyManagement>   → defines versions
  Child  <dependencies>           → just declares usage (no version)

─────────────────────────────────────────────────────────────────────────────────
pluginManagement vs plugins
─────────────────────────────────────────────────────────────────────────────────

  <pluginManagement>
  • Defines plugin versions and configuration in a parent POM
  • Does NOT actually execute the plugin
  • Child modules inherit configuration without repeating it

  <plugins>
  • Actually activates/executes the plugin in the build
  • If you inherit from a parent with <pluginManagement>, the config is applied
    without needing to re-declare all settings

  Example pattern:
  Parent pom.xml:
  <pluginManagement>
    <plugins>
      <plugin>
        <groupId>org.apache.maven.plugins</groupId>
        <artifactId>maven-surefire-plugin</artifactId>
        <version>3.1.2</version>
        <configuration>
          <argLine>-Xmx512m</argLine>
        </configuration>
      </plugin>
    </plugins>
  </pluginManagement>

  Child pom.xml (inherits config automatically):
  <plugins>
    <plugin>
      <groupId>org.apache.maven.plugins</groupId>
      <artifactId>maven-surefire-plugin</artifactId>
      <!-- No version or config needed; inherited from parent pluginManagement -->
    </plugin>
  </plugins>

─────────────────────────────────────────────────────────────────────────────────
RESOURCE FILTERING
─────────────────────────────────────────────────────────────────────────────────

  When <filtering>true</filtering> is set, Maven substitutes ${property}
  placeholders in resource files at build time.

  Example: src/main/resources/application.properties
  app.version=${project.version}
  app.name=${project.name}
  db.url=${db.url}

  After filtering, target/classes/application.properties:
  app.version=1.0.0-SNAPSHOT
  app.name=My Application
  db.url=jdbc:mysql://localhost:3306/mydb   ← from -Ddb.url= or profile

  Note: Spring Boot uses @...@ delimiters instead of ${...} to avoid conflicts
  with Spring's own property resolution. Configure in pom.xml:
  <delimiter>@</delimiter>

INTERVIEW QUICK-HITS
─────────────────────────────────────────────────────────────────────────────────

Q: What is the POM?
A: POM (Project Object Model) is the XML descriptor (pom.xml) at the heart of
   every Maven project. It defines project coordinates (GAV), dependencies,
   plugins, build configuration, and project relationships.

Q: What is the Super POM?
A: The Super POM is Maven's built-in base POM that every project implicitly
   extends. It defines sensible defaults: standard directory structure, Maven
   Central repository, and default plugin versions. You can inspect the merged
   result using "mvn help:effective-pom".

Q: What is the difference between <dependencyManagement> and <dependencies>?
A: <dependencyManagement> centralizes version declarations without actually
   adding dependencies. <dependencies> actually adds dependencies to the
   classpath. The pattern is: parent POM manages versions in
   <dependencyManagement>, child POMs declare usage in <dependencies> without
   specifying versions.

Q: What is the difference between <pluginManagement> and <plugins>?
A: Same pattern as dependencies: <pluginManagement> centralizes plugin versions
   and configuration in a parent, while <plugins> actually activates the plugin
   in a project's build. Child modules inherit plugin configuration without
   repeating it.

Q: What are Maven properties and how are they referenced?
A: Properties are key-value pairs defined in <properties> (or system properties,
   environment variables, etc.) and referenced as ${propertyName}. Common ones:
   ${project.version}, ${java.version}, ${project.build.sourceEncoding}.

Q: What does <packaging>pom</packaging> mean?
A: It means this is a parent/aggregator POM with no artifact to compile or package.
   Used for multi-module root POMs and BOM files. Maven skips the compile/package
   lifecycle phases for pom-packaged projects.
