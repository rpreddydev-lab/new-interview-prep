================================================================
  REDIS BASICS
================================================================

  Redis (Remote Dictionary Server) is an in-memory data structure store
  used as a database, cache, message broker, and queue.

  - In-memory: all data in RAM. Extremely fast (sub-millisecond).
  - Persistent: RDB snapshots and/or AOF (Append-Only File) for durability.
  - Single-threaded command processing: no race conditions on commands.
  - Rich data types: strings, hashes, lists, sets, sorted sets, streams.

================================================================
CORE COMMANDS
================================================================

  SET key value            Store a value
  GET key                  Retrieve a value
  DEL key                  Delete a key
  EXISTS key               1 if exists, 0 if not
  KEYS pattern             List keys matching pattern (avoid in production)
  SCAN cursor              Safe incremental key scan
  TYPE key                 Get type of a key
  TTL key                  Time to live in seconds (-1 = no expiry, -2 = expired)
  EXPIRE key seconds       Set TTL on existing key
  EXPIREAT key timestamp   Set TTL as Unix timestamp
  PERSIST key              Remove TTL (make persistent)
  RENAME key newkey        Rename a key

================================================================
STRING COMMANDS
================================================================

  SET session:abc123 '{"user_id":42,"role":"admin"}'
  SET session:abc123 '{"user_id":42}' EX 3600      -- with 3600s TTL
  GET session:abc123
  SETNX key value                                   -- SET if Not eXists (atomic)
  SETEX key seconds value                           -- SET with expiry
  GETSET key newvalue                               -- return old, set new
  MSET k1 v1 k2 v2                                 -- multiple SET
  MGET k1 k2                                       -- multiple GET
  INCR counter:visits                               -- atomic increment
  INCRBY counter:visits 5                           -- increment by N
  DECR / DECRBY                                    -- decrement

================================================================
KEY EXPIRY (TTL)
================================================================

  Critical for caching and session management.

  SET token:xyz "payload" EX 900     -- expires in 900 seconds (15 min)
  TTL token:xyz                      -- returns remaining seconds
  PERSIST token:xyz                  -- removes expiry

  When key expires:
  - Lazy expiry: Redis deletes when next accessed
  - Active expiry: Redis periodically scans for expired keys

================================================================
REDIS PERSISTENCE OPTIONS
================================================================

  No persistence (pure cache):
    - restart = data loss
    - Fastest, best for ephemeral data

  RDB (Redis Database Backup):
    - Point-in-time snapshot to disk at configured intervals
    - Fast restarts
    - Risk: data since last snapshot is lost on crash

  AOF (Append-Only File):
    - Logs every write command
    - Can replay to recover full state
    - More durable, larger file, slower restarts

  Both (recommended for production):
    - RDB for fast restarts + AOF for durability

================================================================
REDIS REPLICATION
================================================================

  Master-Replica setup:
  - One primary (master) accepts writes
  - Replicas sync from master (async)
  - Reads can be served from replicas
  - Redis Sentinel: monitors master, auto-promotes replica on failure

  Redis Cluster:
  - Shards data across 16384 hash slots
  - Multiple masters + replicas
  - Automatic failover
  - Use for horizontal scaling beyond single-node memory

================================================================
SPRING BOOT REDIS INTEGRATION
================================================================

  <!-- Maven -->
  <dependency>
      <groupId>org.springframework.boot</groupId>
      <artifactId>spring-boot-starter-data-redis</artifactId>
  </dependency>

  # application.properties
  spring.redis.host=localhost
  spring.redis.port=6379
  spring.redis.password=yourpassword
  spring.redis.timeout=2000ms

  // Using StringRedisTemplate:
  @Autowired StringRedisTemplate redisTemplate;

  redisTemplate.opsForValue().set("key", "value", 10, TimeUnit.MINUTES);
  String val = redisTemplate.opsForValue().get("key");
  redisTemplate.delete("key");

  // Using @Cacheable with Redis:
  @Cacheable(value = "products", key = "#id")
  public Product getProduct(Long id) { ... }

  @CacheEvict(value = "products", key = "#product.id")
  public Product updateProduct(Product product) { ... }

================================================================
INTERVIEW Q&A
================================================================

  Q: Why is Redis so fast?
  A: All data is stored in RAM (no disk I/O per request).
     Commands are processed in a single thread (no lock contention).
     Simple data structures with O(1) operations.
     Sub-millisecond response times.

  Q: What are Redis persistence options?
  A: RDB: periodic snapshots (fast restart, may lose recent data).
     AOF: log every command (more durable, slower restart).
     Both: use RDB for backup + AOF for durability (recommended production).

  Q: What is the difference between SETNX and SET ... NX?
  A: Both are atomic SET-if-not-exists. SETNX is the old command.
     SET key value NX EX 30 is preferred in Redis 2.6+ as it combines
     the condition and TTL in one atomic command.
