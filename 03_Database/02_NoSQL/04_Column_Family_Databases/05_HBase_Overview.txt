================================================================
  HBASE OVERVIEW
================================================================

  Apache HBase is an open-source, distributed, column-family database
  modeled after Google Bigtable.
  Runs on HDFS (Hadoop Distributed File System).
  Provides strong consistency (CP in CAP).

================================================================
ARCHITECTURE
================================================================

  HMaster:
  - Coordinates cluster
  - Manages region assignments
  - Handles DDL (create/delete tables)
  - Single master (standby HA available)

  RegionServer:
  - Serves data for a set of regions
  - Each region = a contiguous range of row keys
  - Handles reads and writes for its regions

  Region:
  - A subset of a table's rows (by row key range)
  - Automatically splits when it grows too large

  ZooKeeper:
  - Cluster coordination and leader election
  - Clients contact ZooKeeper to find RegionServers

  HDFS:
  - Underlying storage for HBase files (HFiles)
  - Provides replication and fault tolerance

================================================================
DATA MODEL
================================================================

  Table --> Row Key --> Column Family --> Column:Value:Timestamp

  Row Key:       Unique string identifier. Sorted lexicographically.
  Column Family: Declared at table creation. Groups related columns.
                 Stored together on disk.
  Column:        column_family:qualifier (e.g., "profile:name")
  Timestamp:     Each cell value has a version timestamp.
                 Multiple versions per cell supported.

================================================================
EXAMPLE
================================================================

  Table: "users"
  Column Families: "profile", "orders"

  Row Key      CF:Column            Value
  ----------   --------------------  ---------------------
  user:1001    profile:name          Alice
  user:1001    profile:email         alice@example.com
  user:1001    profile:city          Austin
  user:1001    orders:ORD001:total   99.99
  user:1001    orders:ORD002:total   249.00
  user:1002    profile:name          Bob

================================================================
KEY DESIGN IN HBASE
================================================================

  Row keys are sorted lexicographically.
  Sequential keys (timestamps, auto-increment IDs) cause hot regions
  because all new writes go to the last region.

  Solutions:
  1. Salting: prepend a hash prefix
     key: "abc5_user:1001" (5 = hash(user_id) mod 10)

  2. Reverse timestamp: 
     key: "Long.MAX_VALUE - timestamp"
     Most recent entries come first alphabetically.

  3. Random key prefix: distribute writes across regions.

================================================================
READ/WRITE OPERATIONS
================================================================

  HBase Java API (low level):

  Configuration conf = HBaseConfiguration.create();
  Connection conn = ConnectionFactory.createConnection(conf);
  Table table = conn.getTable(TableName.valueOf("users"));

  // Write:
  Put put = new Put(Bytes.toBytes("user:1001"));
  put.addColumn(Bytes.toBytes("profile"), Bytes.toBytes("name"),
                Bytes.toBytes("Alice"));
  table.put(put);

  // Read:
  Get get = new Get(Bytes.toBytes("user:1001"));
  Result result = table.get(get);
  byte[] name = result.getValue(Bytes.toBytes("profile"),
                                Bytes.toBytes("name"));

  // Scan range:
  Scan scan = new Scan();
  scan.withStartRow(Bytes.toBytes("user:1000"));
  scan.withStopRow(Bytes.toBytes("user:1100"));
  ResultScanner scanner = table.getScanner(scan);

================================================================
HBASE vs CASSANDRA
================================================================

  Feature               HBase                       Cassandra
  --------------------  --------------------------  --------------------------
  Consistency           Strong (CP)                 Tunable (AP by default)
  Architecture          Master-based (HMaster)      Masterless ring
  Dependencies          Hadoop/HDFS + ZooKeeper     ZooKeeper only
  Query language        Java API / Phoenix SQL       CQL
  Secondary indexes     Limited (Phoenix)            Supported in CQL
  Hadoop integration    Excellent (co-located)      Separate
  Failure handling      Region reassignment         Automatic (peer-to-peer)
  Best for              Hadoop/Spark pipelines       Standalone high-write DB

================================================================
PHOENIX
================================================================

  Apache Phoenix is a SQL layer on top of HBase.
  Translates SQL queries into HBase API calls.
  Supports secondary indexes, transactions (limited).

  CREATE TABLE users (
      id VARCHAR NOT NULL PRIMARY KEY,
      name VARCHAR,
      email VARCHAR
  );

  SELECT * FROM users WHERE id = 'user:1001';

================================================================
INTERVIEW Q&A
================================================================

  Q: What is HBase and when would you use it?
  A: HBase is a strongly consistent distributed column-family database
     running on HDFS. Best used in Hadoop ecosystems for random
     read/write access to large datasets alongside MapReduce or Spark jobs.

  Q: How does HBase differ from Cassandra?
  A: HBase is strongly consistent (CP), requires Hadoop/HDFS,
     master-based architecture. Cassandra is masterless, tunable consistency,
     runs standalone. Cassandra is more commonly chosen for standalone
     high-write workloads; HBase for Hadoop data pipelines.

  Q: Why is sequential key design bad in HBase?
  A: Sequential keys (timestamps, auto-increments) cause all new writes
     to go to the same "hot region." Use salting or reverse timestamps
     to distribute writes evenly across regions.
