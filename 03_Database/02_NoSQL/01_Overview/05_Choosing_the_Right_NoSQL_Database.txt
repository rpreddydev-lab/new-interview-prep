================================================================
  CHOOSING THE RIGHT NOSQL DATABASE
================================================================

================================================================
DECISION FRAMEWORK
================================================================

  Ask these questions:

  1. What is the primary access pattern?
     Single key lookup    --> Key-Value (Redis, DynamoDB)
     Rich document search --> Document (MongoDB, Firestore)
     Relationship traversal --> Graph (Neo4j)
     High-write time series --> Time Series (InfluxDB, Cassandra)
     Full-text search    --> Search Engine (Elasticsearch)
     Column-scoped analytics --> Column-Family (Cassandra, HBase)

  2. What are the consistency requirements?
     Strong ACID          --> PostgreSQL, MongoDB (w:majority)
     Eventual OK          --> Cassandra, DynamoDB, CouchDB

  3. What is the scale?
     Millions of writes/sec --> Cassandra, DynamoDB
     Moderate read-heavy  --> MongoDB, Redis
     Cache/session        --> Redis, Memcached

  4. What does the team know?
     SQL experts          --> PostgreSQL (JSONB for semi-structured)
     JavaScript/JSON      --> MongoDB
     JVM ecosystem        --> Cassandra (Netflix/Facebook)

================================================================
DATABASE SELECTION GUIDE
================================================================

  Use Case                          Best Choice(s)
  --------------------------------  ---------------------------------
  Session/token caching             Redis (in-memory, TTL support)
  Rate limiting / counters          Redis (INCR, atomic)
  User profile with variable fields MongoDB, DynamoDB
  Product catalog                   MongoDB (flexible schema)
  Shopping cart                     Redis (hash per user)
  Order history (OLTP)              PostgreSQL (ACID required)
  Social network graph              Neo4j, Amazon Neptune
  IoT sensor data                   InfluxDB, TimescaleDB, Cassandra
  Full-text product search          Elasticsearch, OpenSearch
  Real-time recommendations         Redis + feature store
  Messaging / inbox                 Cassandra (time-ordered by user)
  Analytics / OLAP                  Redshift, BigQuery, Cassandra
  Config / coordination             Zookeeper, etcd
  Mobile app sync                   Firestore (real-time, offline)

================================================================
POLYGLOT PERSISTENCE
================================================================

  Modern systems use multiple databases, each for its strength:

  E-commerce platform example:
  - PostgreSQL        Orders, payments, users (ACID critical)
  - MongoDB           Product catalog (flexible schema, attributes vary)
  - Redis             Session cache, shopping cart, rate limiting
  - Elasticsearch     Product search, autocomplete
  - Cassandra         Click streams, event logs (high-volume time series)
  - Neo4j             Product recommendations ("customers also bought")

================================================================
MONGODB vs CASSANDRA TRADEOFFS
================================================================

  Feature               MongoDB                 Cassandra
  --------------------  ----------------------  ----------------------
  Data model            Documents (BSON/JSON)   Wide rows (CQL)
  Query flexibility     High (rich queries)     Limited (primary key)
  Joins                 $lookup                 Not supported
  Write throughput      Good                    Excellent
  Read pattern          Any field (indexed)     Must know partition key
  Consistency           Tunable (w:majority)    Tunable (ONE/QUORUM/ALL)
  Best for              Variable-schema docs    High-volume writes, logs

================================================================
RDBMS BEFORE NOSQL -- RULE OF THUMB
================================================================

  Default to PostgreSQL.
  PostgreSQL supports:
  - JSONB columns (schemaless document storage within a relational table)
  - Full-text search (tsvector, GIN indexes)
  - Arrays, HSTORE, complex types
  - Excellent horizontal read scaling with read replicas
  - Full ACID with window functions, CTEs, triggers

  Move to NoSQL when PostgreSQL genuinely cannot handle
  the scale, access pattern, or schema flexibility required.

================================================================
INTERVIEW Q&A
================================================================

  Q: How do you choose between MongoDB and Cassandra?
  A: MongoDB for flexible document queries, varied schemas, moderate writes.
     Cassandra for extremely high write throughput, time-series data,
     and append-heavy access patterns. Cassandra requires knowing your
     access pattern upfront; MongoDB is more flexible for ad-hoc queries.

  Q: What is polyglot persistence?
  A: Using multiple database technologies in the same system,
     each chosen for its strengths.
     Example: PostgreSQL for orders, Redis for caching, Elasticsearch for search.

  Q: When would you stick with PostgreSQL instead of adopting NoSQL?
  A: When data is relational, queries are complex with JOINs,
     ACID guarantees are required, the team knows SQL, and scale
     can be handled with read replicas + proper indexing.
     PostgreSQL's JSONB often covers semi-structured needs.
