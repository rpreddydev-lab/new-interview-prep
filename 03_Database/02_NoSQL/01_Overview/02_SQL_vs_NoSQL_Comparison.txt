================================================================
  SQL vs NoSQL COMPARISON
================================================================

================================================================
SIDE-BY-SIDE COMPARISON
================================================================

  Feature               SQL (RDBMS)                 NoSQL
  --------------------  --------------------------  --------------------------
  Data model            Tables, rows, columns       Documents/KV/Graph/Columns
  Schema                Fixed (DDL required)        Flexible (schema-on-read)
  Query language        SQL (standard)              Varies (MongoDB query / CQL / Gremlin)
  Joins                 First-class feature         Usually denormalized; $lookup
  ACID                  Full ACID by default        Varies; often eventual consistency
  Horizontal scaling    Hard (sharding complex)     Built-in sharding
  Vertical scaling      Easy                        Less common need
  Relationships         FK constraints              Embedded documents or application-side
  Transactions          Multi-row, multi-table      Often single-document; some multi-doc
  Best for              Complex queries, reports    High throughput, flexible schema
  Examples              PostgreSQL, MySQL, Oracle   MongoDB, Cassandra, Redis, Neo4j

================================================================
SCHEMA COMPARISON
================================================================

  SQL:
    CREATE TABLE products (
        id          SERIAL PRIMARY KEY,
        name        VARCHAR(255) NOT NULL,
        price       NUMERIC(10,2),
        category_id INT REFERENCES categories(id)
    );
    -- ALL rows must match this schema

  NoSQL (MongoDB document):
    {
        "_id": ObjectId("abc123"),
        "name": "Laptop",
        "price": 999.99,
        "specs": {
            "ram": "16GB",
            "cpu": "Intel i7"
        },
        "tags": ["electronics", "computers"]
    }
    -- Next product can have completely different fields

================================================================
SCALING COMPARISON
================================================================

  SQL -- Vertical Scaling (Scale-Up)
  - Add more RAM, faster CPU, SSD to the single server
  - Read replicas possible but limited
  - Sharding is complex and often requires application changes
  - Eventually hits physical limits

  NoSQL -- Horizontal Scaling (Scale-Out)
  - Add more nodes to the cluster
  - Data is automatically partitioned (sharded) by a shard key
  - Consistent hashing distributes data evenly
  - Theoretically infinite scale
  - Examples: Cassandra ring, MongoDB shards, DynamoDB partitions

================================================================
CONSISTENCY COMPARISON
================================================================

  SQL:
  - Full ACID by default
  - All reads see the latest committed write (strong consistency)
  - Expensive -- requires locking, WAL, coordination

  NoSQL:
  - Most NoSQL trades strong consistency for availability and scale
  - Eventual consistency: all replicas converge EVENTUALLY
  - Some NoSQL (MongoDB 4+, DynamoDB transactions) offer ACID now
  - Tunable consistency levels (Cassandra: ONE, QUORUM, ALL)

================================================================
WHEN TO CHOOSE EACH
================================================================

  Choose SQL (RDBMS) when:
  - Complex relationships between entities
  - Strong consistency and ACID required (banking, payments)
  - Complex reporting, ad-hoc queries, JOINs
  - Team is SQL-proficient and data model is stable
  - Compliance/audit requirements (transactions, constraints)

  Choose NoSQL when:
  - Massive scale (millions of writes/second)
  - Schema evolves rapidly (A/B test features, user-defined attributes)
  - Data maps naturally to a specific model (graph, time series, kv)
  - Geographic distribution with low-latency reads everywhere
  - Caching layer (Redis)

  Real-world: Most large systems use BOTH.
  PostgreSQL for orders/payments + MongoDB for product catalog +
  Redis for session caching + Elasticsearch for product search.

================================================================
INTERVIEW Q&A
================================================================

  Q: What are the main differences between SQL and NoSQL?
  A: SQL uses fixed schemas, tables, and JOINs with strong ACID guarantees.
     NoSQL uses flexible schemas designed for horizontal scaling
     and high throughput, often trading strong consistency for availability.

  Q: Can NoSQL replace SQL entirely?
  A: Rarely. They solve different problems. Use SQL for relational data with
     complex queries and strong consistency. Use NoSQL for specific access patterns
     (caching, time series, documents). Most production systems use both.

  Q: Is MongoDB ACID compliant?
  A: Since MongoDB 4.0, it supports multi-document ACID transactions.
     Single-document operations have always been atomic.
