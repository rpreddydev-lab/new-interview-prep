================================================================
  WHAT IS NOSQL?
================================================================

  NoSQL ("Not Only SQL") refers to a broad class of databases that
  do NOT use the traditional relational (table-based) model.

  They were built to address limitations of RDBMS when:
  - Data is semi-structured or schema-less
  - Scale is massive (billions of records, petabytes of data)
  - Read/write throughput must be extremely high
  - Flexible schema evolution is needed without downtime

================================================================
WHY NOSQL EMERGED
================================================================

  Problem with RDBMS at web scale:

  1. Vertical scaling limits: RDBMS scales up (bigger server), not out.
     NoSQL databases are built to scale horizontally (add more nodes).

  2. Rigid schema: Adding a column to a 500M row table is painful.
     NoSQL documents can have different shapes per record.

  3. JOIN performance at scale: Multi-table JOINs are expensive.
     NoSQL encourages embedding and denormalization for reads.

  4. Specific data models: Graphs, time series, key-value lookups
     are awkward in a relational model.

================================================================
NOSQL CATEGORIES
================================================================

  Category            Data Model              Examples
  ----------------    --------------------    --------------------------
  Document            JSON/BSON documents     MongoDB, CouchDB, Firestore
  Key-Value           Key --> Value blob      Redis, DynamoDB, Memcached
  Column-Family       Rows + dynamic columns  Cassandra, HBase, DynamoDB
  Graph               Nodes + Edges           Neo4j, Amazon Neptune
  Search Engine       Inverted index          Elasticsearch, OpenSearch, Solr
  Time Series         Timestamped measurements InfluxDB, TimescaleDB, Prometheus

================================================================
CHARACTERISTICS OF NOSQL DATABASES
================================================================

  1. Schema-flexible:
     Each document/record can have different fields.
     No ALTER TABLE migration needed.

  2. Horizontal Scaling (Scale-Out):
     Add more nodes to distribute data and traffic.
     Data is partitioned (sharded) across nodes.

  3. Eventual Consistency (often):
     Prioritizes availability and partition tolerance over
     immediate consistency (CAP theorem tradeoff).
     Some NoSQL databases offer tunable consistency levels.

  4. Designed for specific access patterns:
     Built around how you query data, not data relationships.

================================================================
NOSQL DOES NOT MEAN "NO JOINS EVER"
================================================================

  - MongoDB supports $lookup (JOIN-like aggregation)
  - Some NoSQL DBs support secondary indexes
  - But the design philosophy is to denormalize and embed

================================================================
WHEN TO USE NOSQL
================================================================

  Use NoSQL when:
  - Schema changes frequently (user-defined attributes, product catalog)
  - Data is inherently hierarchical (order with line items, user profile)
  - Read throughput is extreme (millions of reads per second)
  - Horizontal scaling is required (sharding across nodes)
  - The use case maps naturally: graphs --> Neo4j, caching --> Redis

  Do NOT use NoSQL when:
  - Strong ACID guarantees required across multiple entities
  - Complex reporting with ad-hoc JOINs required
  - Team knows SQL well and data model is stable
  - Data integrity constraints (FK, CHECK) are critical

================================================================
INTERVIEW Q&A
================================================================

  Q: What is NoSQL and why was it created?
  A: NoSQL is a class of databases that store data in non-relational formats.
     Created to address RDBMS limitations at web scale: rigid schemas,
     poor horizontal scaling, and high JOIN overhead for massive datasets.

  Q: Name the four main NoSQL categories.
  A: Document (MongoDB), Key-Value (Redis, DynamoDB), Column-Family (Cassandra),
     and Graph (Neo4j). Time Series and Search Engine are additional categories.

  Q: Is NoSQL always faster than SQL?
  A: Not necessarily. NoSQL is faster for specific access patterns it was
     designed for (e.g., Redis for key lookups, Cassandra for high-write time series).
     For complex queries with JOINs and aggregations, RDBMS can be faster.
