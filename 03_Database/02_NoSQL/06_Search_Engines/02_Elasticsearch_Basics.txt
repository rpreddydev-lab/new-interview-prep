================================================================
  ELASTICSEARCH BASICS
================================================================

  Elasticsearch is a distributed, RESTful full-text search
  and analytics engine built on Apache Lucene.

================================================================
CORE CONCEPTS
================================================================

  Index        Collection of documents with similar structure.
               Like a database or table (one index per use case).

  Document     A JSON object stored in an index.
               Each document has a unique _id.

  Field        Key-value pair within a document.

  Shard        A Lucene index instance.
               An index is split into shards distributed across nodes.
               Primary shard: original; Replica shard: copy.

  Mapping      Schema definition: field types, analyzers.
               Like a table schema for how fields are indexed.

  Analyzer     Text processing pipeline: tokenizer + token filters.
               Determines how text is broken into searchable terms.

================================================================
ELASTICSEARCH TERMINOLOGY vs SQL
================================================================

  Elasticsearch       SQL
  ---------------     ---------------
  Index               Table
  Document            Row
  Field               Column
  Mapping             Schema
  Shard               Partition
  _id                 Primary Key
  Query DSL           SQL SELECT ... WHERE

  }

================================================================
MAPPING (SCHEMA)
================================================================

  PUT /products
  {
    "mappings": {
      "properties": {
        "name":        { "type": "text",    "analyzer": "standard" },
        "brand":       { "type": "keyword" },
        "price":       { "type": "double" },
        "category":    { "type": "keyword" },
        "description": { "type": "text",    "analyzer": "english" },
        "tags":        { "type": "keyword" },
        "in_stock":    { "type": "boolean" },
        "created_at":  { "type": "date" }
      }
    }
  }

  text vs keyword:
  "text"    --> analyzed for full-text search (tokenized, lowercased, etc.)
  "keyword" --> stored as-is for exact matching, sorting, aggregations

================================================================
CLUSTER ARCHITECTURE
================================================================

  Node:
  - A single Elasticsearch instance (JVM process)
  - Roles: master, data, ingest, coordinating

  Master Node:
  - Manages cluster state: shard assignments, node membership
  - Does NOT serve user queries

  Data Node:
  - Stores shards and executes queries
  - Most nodes in production

  Coordinating Node:
  - Receives client requests, routes to data nodes, merges results
  - Any node can be coordinating by default

  Index Sharding:
  index "products" with 3 primary shards, 1 replica each:
  - 6 total shards distributed across nodes
  - Each query is broadcast to all shards, results merged

SPRING BOOT INTEGRATION
================================================================

  <!-- Maven: Spring Data Elasticsearch -->
  <dependency>
      <groupId>org.springframework.boot</groupId>
      <artifactId>spring-boot-starter-data-elasticsearch</artifactId>
  </dependency>

  # application.properties
  spring.elasticsearch.uris=http://localhost:9200

  @Document(indexName = "products")
  public class ProductDocument {
      @Id
      private String id;
      @Field(type = FieldType.Text, analyzer = "standard")
      private String name;
      @Field(type = FieldType.Keyword)
      private String category;
      @Field(type = FieldType.Double)
      private double price;
  }

  public interface ProductSearchRepository
      extends ElasticsearchRepository<ProductDocument, String> {
      List<ProductDocument> findByCategory(String category);
      List<ProductDocument> findByNameContaining(String keyword);
  }

================================================================
DUAL-WRITE PATTERN
================================================================

  Elasticsearch is usually a secondary store.
  Write to primary DB first, then sync to ES.

  Option 1: Dual write (application writes both)
  Option 2: Debezium CDC (capture DB changes, stream to ES)
  Option 3: Logstash JDBC input (poll DB and sync to ES)

================================================================
INTERVIEW Q&A
================================================================

  Q: What is the difference between text and keyword in Elasticsearch?
  A: text: analyzed field, tokenized and indexed for full-text search.
           Cannot sort or aggregate on text fields efficiently.
     keyword: stored as-is for exact match, filtering, sorting, aggregations.
           Use for category names, tags, status codes.

  Q: What are shards in Elasticsearch?
  A: An index is divided into shards (Lucene index instances) distributed
     across nodes. Each shard has one or more replica shards for redundancy.
     Sharding enables horizontal scaling of both storage and query throughput.

  Q: Why is Elasticsearch usually a secondary store?
  A: It provides no ACID guarantees and is optimized for search, not writes.
     The primary record of truth lives in PostgreSQL/MongoDB.
     Elasticsearch is kept in sync via CDC or dual writes for search queries.
