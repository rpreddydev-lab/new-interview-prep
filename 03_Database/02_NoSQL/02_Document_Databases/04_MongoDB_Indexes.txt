================================================================
  MONGODB INDEXES
================================================================

================================================================
WHY INDEXES?
================================================================

  Without an index, MongoDB does a COLLECTION SCAN --
  reads every document to find matches. O(n).

  With an index, MongoDB uses a B-tree lookup. O(log n).

================================================================
DEFAULT INDEX
================================================================

  MongoDB automatically creates a unique index on _id for every collection.

================================================================
CREATE SINGLE FIELD INDEX
================================================================

  -- Shell:
  db.products.createIndex({ category: 1 })       // ascending
  db.products.createIndex({ price: -1 })          // descending

  -- With options:
  db.products.createIndex({ email: 1 }, { unique: true })
  db.products.createIndex({ expireAt: 1 }, { expireAfterSeconds: 0 })  // TTL index

  -- Spring Data:
  @Document
  public class Product {
      @Indexed
      private String category;

      @Indexed(unique = true)
      private String sku;
  }

================================================================
COMPOUND INDEX
================================================================

  db.products.createIndex({ category: 1, price: -1 })

  Follows Equality-Sort-Range (ESR) rule:
  1. Equality fields first (category = ?)
  2. Sort fields next (ORDER BY price)
  3. Range fields last (price > ? AND price < ?)

  Leftmost prefix rule:
  Compound index { a, b, c } also supports:
  - Queries on { a }
  - Queries on { a, b }
  - Queries on { a, b, c }
  NOT { b } alone or { b, c } alone.

================================================================
INDEX TYPES
================================================================

  Single Field      { field: 1 }           Ascending B-tree
  Compound          { a:1, b:-1 }          Multi-field
  Multikey          Auto for array fields   Index each array element
  Text              { desc: "text" }        Full-text search
  Geospatial 2d/2dsphere { loc: "2dsphere" }  geo queries
  Hashed            { _id: "hashed" }       Hash-based sharding
  TTL               expireAfterSeconds       Auto-delete docs
  Partial           { filter: { price:{$gt:100} } }  Index subset
  Wildcard          { "$**": 1 }            All fields (flexible schema)
  Unique            { unique: true }         Enforce uniqueness

================================================================
TTL INDEX (AUTO-EXPIRE)
================================================================

  Used for sessions, tokens, cache entries with expiry.

  db.sessions.createIndex({ createdAt: 1 }, { expireAfterSeconds: 3600 })
  // Documents are deleted approx 1 hour after createdAt value

  // MongoDB background process (TTLMonitor) runs every 60 seconds.
  // Deletion is NOT immediate at expiry + 0.

================================================================
TEXT INDEX (FULL-TEXT SEARCH)
================================================================

  db.products.createIndex({ name: "text", description: "text" })

  db.products.find({ $text: { $search: "wireless bluetooth" } })

  db.products.find(
      { $text: { $search: "wireless" } },
      { score: { $meta: "textScore" } }
  ).sort({ score: { $meta: "textScore" } })

  Only one text index per collection.
  For production full-text search, use Elasticsearch.

================================================================
EXPLAIN PLAN
================================================================

  db.products.find({ category: "electronics", price: { $lt: 500 } })
             .explain("executionStats")

  Look for:
  - IXSCAN  --> index scan (good)
  - COLLSCAN --> full collection scan (bad, needs index)
  - totalDocsExamined vs nReturned (should be close for a good index)

================================================================
INTERVIEW Q&A
================================================================

  Q: What is the leftmost prefix rule in MongoDB compound indexes?
  A: A compound index { a, b, c } can support queries that filter on
     a, or a+b, or a+b+c, but not b alone or c alone.
     The query must start from the leftmost indexed field.

  Q: What is a multikey index?
  A: When indexing a field that holds an array, MongoDB creates a multikey index
     that indexes each element of the array separately.
     Allows efficient queries like { tags: "electronics" } on an array field.

  Q: What is a TTL index used for?
  A: Automatically deleting documents after a specified time.
     Useful for sessions, tokens, temp data, cache expiry.
     TTLMonitor background process runs every 60 seconds.

  Q: What is a partial index?
  A: An index over a subset of documents matching a filter.
     Smaller and faster than a full index.
     Example: index only active users:
     { active: true } as the partial filter expression.
