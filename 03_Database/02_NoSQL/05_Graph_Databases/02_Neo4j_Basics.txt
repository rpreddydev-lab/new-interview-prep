================================================================
  NEO4J BASICS
================================================================

  Neo4j is the most widely used graph database.
  Uses a property graph model: nodes and relationships with properties.
  Native graph storage: relationships are physically stored as pointers.
  ACID compliant. Cypher query language.

================================================================
DATA MODEL
================================================================

  Node:
  - Represents an entity
  - Has zero or more labels
  - Has properties (key-value pairs)

  Relationship:
  - Connects two nodes
  - Always has a direction (can query either direction)
  - Always has a type (name)
  - Has properties

  Property:
  - Key-value pair on node or relationship
  - Supported types: String, Integer, Float, Boolean, Date, DateTime,
                     Duration, Point, and arrays of these

================================================================
CREATING NODES
================================================================

  CREATE (:Person { name: 'Alice', age: 30, city: 'Austin' })
  CREATE (:Person { name: 'Bob',   age: 25, city: 'Dallas' })
  CREATE (:Product { name: 'Laptop', price: 999.99 })

  MERGE (:Person { name: 'Alice' })  -- create if not exists

================================================================
CREATING RELATIONSHIPS
================================================================

  MATCH (a:Person { name: 'Alice' }), (b:Person { name: 'Bob' })
  CREATE (a)-[:FOLLOWS { since: date('2023-01-01') }]->(b);

  MATCH (p:Person { name: 'Alice' }), (prod:Product { name: 'Laptop' })
  CREATE (p)-[:PURCHASED { date: date('2024-01-15'), amount: 999.99 }]->(prod);

================================================================
NEO4J NODE ID vs PROPERTY ID
================================================================

  Neo4j auto-assigns internal node IDs.
  These are NOT stable -- reused after deletes.
  Use a business key property (e.g., userId: "U001") as your logical ID.

  CREATE CONSTRAINT FOR (p:Person) REQUIRE p.userId IS UNIQUE;

================================================================
SPRING DATA NEO4J
================================================================

  <!-- Maven -->
  <dependency>
      <groupId>org.springframework.boot</groupId>
      <artifactId>spring-boot-starter-data-neo4j</artifactId>
  </dependency>

  # application.properties
  spring.neo4j.uri=bolt://localhost:7687
  spring.neo4j.authentication.username=neo4j
  spring.neo4j.authentication.password=password

  @Node("Person")
  public class Person {
      @Id @GeneratedValue
      private Long id;
      private String name;
      private int age;
      @Relationship(type = "FOLLOWS", direction = OUTGOING)
      private List<Person> follows;
  }

  public interface PersonRepository extends Neo4jRepository<Person, Long> {
      Optional<Person> findByName(String name);

      @Query("MATCH (p:Person {name:$name})-[:FOLLOWS*1..2]->(fof:Person) " +
             "RETURN DISTINCT fof")
      List<Person> findFriendsOfFriends(@Param("name") String name);
  }

================================================================
INDEXES IN NEO4J
================================================================

  CREATE INDEX personName FOR (p:Person) ON (p.name);
  CREATE INDEX productPrice FOR (p:Product) ON (p.price);

  Constraints automatically create indexes:
  CREATE CONSTRAINT FOR (p:Person) REQUIRE p.userId IS UNIQUE;

================================================================
BOLT PROTOCOL
================================================================

  Neo4j uses the Bolt protocol for client-server communication.
  Connection string: bolt://host:7687

  Browser UI: http://localhost:7474 (Neo4j Browser for Cypher REPL)

================================================================
INTERVIEW Q&A
================================================================

  Q: Why is Neo4j faster than a relational DB for relationship traversal?
  A: Neo4j uses native graph storage -- relationships are physically stored
     as pointers between nodes. Traversing a relationship is O(1).
     In RDBMS, each level of a relationship requires a JOIN with an index lookup.
     At depth 5+, the difference is orders of magnitude.

  Q: What is the property graph model?
  A: Nodes (entities) and typed, directed relationships,
     each with arbitrary key-value properties.
     The foundational model for Neo4j and most graph databases.
