================================================================
  GRAPH DATABASES OVERVIEW
================================================================

  A graph database stores data as nodes (entities) and edges (relationships).
  Designed to efficiently traverse relationships -- queries that
  would require many expensive JOINs in relational databases.

================================================================
CORE CONCEPTS
================================================================

  Node (Vertex):
    Represents an entity.
    Has labels (like a type/class) and properties (key-value pairs).
    Example: (:Person { name: "Alice", age: 30 })

  Edge (Relationship):
    Connects two nodes with a named, directed relationship.
    Has a type and properties.
    Example: (Alice)-[:FOLLOWS { since: "2023-01-01" }]->(Bob)

  Label:
    A tag on a node (like a type/category).
    A node can have multiple labels.
    Example: :Person, :Employee, :VIPCustomer

  Property:
    Key-value pair on a node or edge.
    Equivalent to a column in relational terms.

================================================================
GRAPH QUERY PATTERN
================================================================

  Relational (with JOINs):
  "Find all friends-of-friends of Alice who bought Product X"

  SELECT DISTINCT u3.name
  FROM users u1
  JOIN friendships f1 ON u1.id = f1.user_id
  JOIN users u2 ON f1.friend_id = u2.id
  JOIN friendships f2 ON u2.id = f2.user_id
  JOIN users u3 ON f2.friend_id = u3.id
  JOIN orders o ON o.user_id = u3.id
  JOIN order_items oi ON oi.order_id = o.id
  JOIN products p ON p.id = oi.product_id
  WHERE u1.name = 'Alice' AND p.name = 'Widget X';

  Graph (Cypher):
  MATCH (:Person { name: 'Alice' })-[:FRIEND*2]->(fof:Person)
        -[:PURCHASED]->(:Product { name: 'Widget X' })
  RETURN DISTINCT fof.name;

================================================================
GRAPH DATABASES VS RELATIONAL
================================================================

  Feature               Graph DB               RDBMS
  --------------------  ---------------------  ----------------------
  Relationship query    O(1) per hop           O(n log n) per JOIN
  Deep traversal        Efficient              Exponential JOINs
  Flexible schema       Yes (property graph)   No
  Data model            Nodes + Edges          Tables + Rows
  Best access pattern   Connected data queries Ad-hoc tabular queries
  ACID                  Yes (Neo4j)            Yes
  Examples              Neo4j, Amazon Neptune  PostgreSQL, MySQL

================================================================
POPULAR GRAPH DATABASES
================================================================

  Neo4j        Most popular. ACID. Cypher query language. 
               Causal clustering. Native graph storage.

  Amazon Neptune  Managed on AWS. Supports Gremlin (TinkerPop)
                  and SPARQL (RDF). Handles billions of edges.

  ArangoDB     Multi-model: document + graph + key-value.

  JanusGraph   Distributed graph on Cassandra or HBase backend.

  TigerGraph   Enterprise-grade. Very high performance on large graphs.

================================================================
WHEN TO USE A GRAPH DATABASE
================================================================

  Use when:
  - Data relationships are first-class citizens
  - Queries need to traverse many levels of relationships
  - Relationship patterns change often (adding new relationship types)
  - Use case: social networks, fraud detection, knowledge graphs,
              recommendation engines, access control, network topology

  Use RDBMS instead when:
  - Simple tabular data with limited relationships
  - Primary queries are aggregations (SUM, COUNT, GROUP BY)
  - Team has strong SQL skills
  - Relationships are shallow (one or two JOINs max)

================================================================
INTERVIEW Q&A
================================================================

  Q: What is a graph database?
  A: A database that stores data as nodes and directed, typed edges.
     Optimized for relationship traversal.
     Queries that need many JOINs in SQL become simple pattern matches.

  Q: What type of problems are graph databases best at?
  A: Social network queries (friend-of-friend), fraud detection
     (unusual transaction chains), recommendation engines,
     access control graphs, network topology analysis.
