================================================================
  CYPHER QUERY LANGUAGE
================================================================

  Cypher is Neo4j's declarative graph query language.
  Pattern-matching based: describe the graph pattern you want to find.

  ASCII art-like syntax makes queries readable:
  (node)-[:RELATIONSHIP]->(node)

================================================================
MATCH -- FIND PATTERNS
================================================================

  -- All people:
  MATCH (p:Person) RETURN p;

  -- Specific person:
  MATCH (p:Person { name: 'Alice' }) RETURN p;

  -- People Alice follows:
  MATCH (:Person { name: 'Alice' })-[:FOLLOWS]->(followed:Person)
  RETURN followed.name;

  -- Products Alice purchased:
  MATCH (:Person { name: 'Alice' })-[:PURCHASED]->(prod:Product)
  RETURN prod.name, prod.price;

================================================================
VARIABLE-LENGTH PATHS
================================================================

  -- Friends of friends (depth 2):
  MATCH (:Person { name: 'Alice' })-[:FOLLOWS*2]->(fof:Person)
  RETURN DISTINCT fof.name;

  -- Any depth 1 to 3:
  MATCH (:Person { name: 'Alice' })-[:FOLLOWS*1..3]->(connected:Person)
  RETURN DISTINCT connected.name;

  -- Shortest path:
  MATCH p = shortestPath(
      (:Person { name: 'Alice' })-[:FOLLOWS*]-(:Person { name: 'Charlie' })
  )
  RETURN p;

================================================================
WHERE CLAUSE
================================================================

  MATCH (p:Person)
  WHERE p.age > 25 AND p.city = 'Austin'
  RETURN p.name, p.age;

  -- Pattern in WHERE:
  MATCH (p:Person)
  WHERE EXISTS { MATCH (p)-[:PURCHASED]->(:Product) }
  RETURN p.name;

  -- String functions:
  MATCH (p:Person)
  WHERE toLower(p.name) STARTS WITH 'a'
  RETURN p.name;

================================================================
CREATE AND MERGE
================================================================

  CREATE:
  Always creates a new node/relationship, even if it already exists.
  CREATE (:Person { name: 'Alice' })

  MERGE:
  Create if not exists; match if exists.
  MERGE (p:Person { name: 'Alice' })
  ON CREATE SET p.created = datetime()
  ON MATCH  SET p.updated = datetime()
  RETURN p;

  MERGE is idempotent -- safe to call multiple times.

================================================================
SET AND REMOVE
================================================================

  -- Update properties:
  MATCH (p:Person { name: 'Alice' })
  SET p.age = 31, p.updatedAt = datetime()
  RETURN p;

  -- Remove a property:
  MATCH (p:Person { name: 'Alice' })
  REMOVE p.tempField;

  -- Add a label:
  MATCH (p:Person { name: 'Alice' })
  SET p:VIP;

  -- Remove a label:
  MATCH (p:Person:VIP { name: 'Alice' })
  REMOVE p:VIP;

================================================================
DELETE AND DETACH DELETE
================================================================

  -- Delete a node (only if it has no relationships):
  MATCH (p:Person { name: 'Bob' })
  DELETE p;

  -- Delete node AND all its relationships:
  MATCH (p:Person { name: 'Bob' })
  DETACH DELETE p;

  -- Delete a specific relationship:
  MATCH (:Person { name: 'Alice' })-[r:FOLLOWS]->(:Person { name: 'Bob' })
  DELETE r;

================================================================
AGGREGATION
================================================================

  MATCH (:Person)-[:PURCHASED]->(prod:Product)
  RETURN prod.name, COUNT(*) AS buyers, AVG(prod.price) AS avgPrice
  ORDER BY buyers DESC
  LIMIT 10;

  -- Count relationships per node:
  MATCH (p:Person)-[:FOLLOWS]->(followed)
  RETURN p.name, COUNT(followed) AS following_count
  ORDER BY following_count DESC;

================================================================
WITH CLAUSE
================================================================

  Chains query parts (like a CTE in SQL):

  MATCH (p:Person)-[:PURCHASED]->(prod:Product)
  WITH p, COUNT(prod) AS purchaseCount
  WHERE purchaseCount > 5
  RETURN p.name, purchaseCount
  ORDER BY purchaseCount DESC;

================================================================
UNWIND
================================================================

  Expands a list into individual rows (like $unwind in MongoDB):

  UNWIND ['Alice', 'Bob', 'Charlie'] AS name
  CREATE (:Person { name: name });

================================================================
COLLECT
================================================================

  Aggregate results into a list:

  MATCH (p:Person)-[:PURCHASED]->(prod:Product)
  RETURN p.name, COLLECT(prod.name) AS products;
  -- Returns: { name: "Alice", products: ["Laptop", "Mouse", "Pad"] }

================================================================
INTERVIEW Q&A
================================================================

  Q: What does MATCH do in Cypher?
  A: MATCH finds nodes and relationships matching a graph pattern.
     Like SELECT + FROM + JOIN in SQL but expressed as visual ASCII patterns.

  Q: What is the difference between CREATE and MERGE?
  A: CREATE always inserts a new node/relationship regardless of duplicates.
     MERGE matches existing or creates new -- like SQL upsert (ON CONFLICT).
     Use MERGE for idempotent operations.

  Q: How do you query variable-length paths in Cypher?
  A: Use *min..max notation: -[:FOLLOWS*1..3]->
     Means "follow FOLLOWS relationships 1 to 3 hops deep."
     shortestPath() finds the shortest connecting path.
