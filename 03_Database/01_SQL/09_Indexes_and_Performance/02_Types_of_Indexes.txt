================================================================
  TYPES OF INDEXES
================================================================

================================================================
B-TREE INDEX (DEFAULT)
================================================================

  - Default index type in PostgreSQL and MySQL
  - Self-balancing tree; O(log n) lookups
  - Supports: =, <, >, <=, >=, BETWEEN, IN, LIKE 'prefix%', ORDER BY
  - Does NOT support: LIKE '%suffix', full-text search

  CREATE INDEX idx_orders_customer ON orders(customer_id);

================================================================
HASH INDEX
================================================================

  - Hash map of column value --> row pointer
  - O(1) equality lookups (= only)
  - Does NOT support range queries (<, >, BETWEEN)
  - PostgreSQL: hash indexes are WAL-safe since PG 10
  - MySQL InnoDB: does not use hash indexes for persistent storage (only adaptive hash)

  CREATE INDEX idx_users_email ON users USING HASH (email);
  -- Only useful if column is only ever queried with =

================================================================
COMPOSITE INDEX (MULTI-COLUMN)
================================================================

  Index on multiple columns together.
  Column order matters: (a, b, c) index supports:
  - WHERE a = ?               -- leftmost prefix rule
  - WHERE a = ? AND b = ?
  - WHERE a = ? AND b = ? AND c = ?
  - ORDER BY a, b
  Does NOT support:
  - WHERE b = ?               -- skips leading column a
  - WHERE c = ?               -- skips a and b

  CREATE INDEX idx_orders_customer_status ON orders(customer_id, status);

================================================================
UNIQUE INDEX
================================================================

  Enforces uniqueness + enables fast lookups.
  NULL values are allowed (and each NULL is considered unique).

  CREATE UNIQUE INDEX idx_users_email ON users(email);
  -- Or created automatically by: UNIQUE constraint on column

================================================================
PARTIAL INDEX
================================================================

  Index only a subset of rows (where a condition is true).
  Smaller, faster for selective queries.

  CREATE INDEX idx_orders_pending ON orders(customer_id)
  WHERE status = 'PENDING';
  -- Only indexes pending orders; very efficient for:
  -- SELECT * FROM orders WHERE status = 'PENDING' AND customer_id = 42;

================================================================
FUNCTIONAL / EXPRESSION INDEX
================================================================

  Index the result of a function or expression.
  Allows index use when a function is applied to a column.

  -- Without index:  WHERE LOWER(email) = 'alice@example.com' --> full scan
  -- With index:
  CREATE INDEX idx_users_lower_email ON users(LOWER(email));
  -- Now: WHERE LOWER(email) = 'alice@example.com' uses the index

  CREATE INDEX idx_orders_year ON orders(EXTRACT(YEAR FROM created_at));

================================================================
GIN INDEX (GENERALIZED INVERTED INDEX)
================================================================

  For full-text search, arrays, JSONB, tsvector.
  PostgreSQL specific.

  Full-text search:
  CREATE INDEX idx_articles_search ON articles USING GIN(to_tsvector('english', body));

  JSONB containment:
  CREATE INDEX idx_events_data ON events USING GIN(data);
  -- SELECT * FROM events WHERE data @> '{"type": "click"}';

================================================================
GIST INDEX
================================================================

  Generalized Search Tree.
  PostgreSQL: geometric types, range types, full-text, nearest neighbor.

  CREATE INDEX idx_places_location ON places USING GIST(location);
  -- Enables: WHERE location <-> point(0,0) < 1000  (nearest neighbor)

================================================================
BRIN INDEX (BLOCK RANGE INDEX)
================================================================

  Very small index for large tables with natural sort order.
  Stores min/max values per block range, not per row.
  Ideal for time-series / append-only tables.

  CREATE INDEX idx_logs_created ON logs USING BRIN(created_at);
  -- Excellent for: WHERE created_at > '2024-01-01'
  -- NOT good for random-access lookups

================================================================
INDEX TYPE SUMMARY
================================================================

  Type      Supports              Best For
  --------  --------------------  ---------------------------------
  B-Tree    =, <, >, BETWEEN, IN  Default; most use cases
  Hash      = only                Equality-only columns
  Composite (a,b) prefix rules    Multi-column filter/sort
  Unique    Uniqueness check      Unique business keys
  Partial   Subset of rows        Sparse or filtered queries
  Function  Expression result     LOWER(), EXTRACT(), computed cols
  GIN       Arrays, JSONB, FTS    Full-text, JSONB, arrays
  GiST      Geometric, range      Spatial, range types
  BRIN      Min/max per block     Large time-series tables

================================================================
INTERVIEW Q&A
================================================================

  Q: What is a partial index and when would you use it?
  A: An index with a WHERE clause that only indexes rows meeting the condition.
     Use when queries always filter on a specific value (e.g., status='PENDING')
     -- keeps index small and fast.

  Q: Why would you create an index on LOWER(email)?
  A: To allow case-insensitive email lookups using an index.
     Without it, LOWER(email) = 'x' requires a full table scan
     because the function disables normal column index use.
