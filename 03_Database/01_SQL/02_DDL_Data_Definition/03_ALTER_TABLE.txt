================================================================
  ALTER TABLE — DDL
================================================================

  Modifies the structure of an existing table.
  The most common DDL in ongoing projects (schema evolves over time).

================================================================
SYNTAX
================================================================

  ALTER TABLE table_name action;

================================================================
COMMON ALTER OPERATIONS
================================================================

  ADD COLUMN:
  ALTER TABLE customers ADD COLUMN phone VARCHAR(20);
  ALTER TABLE orders ADD COLUMN discount DECIMAL(5,2) DEFAULT 0.00;
  ALTER TABLE products ADD COLUMN deleted_at TIMESTAMP;

  DROP COLUMN:
  ALTER TABLE customers DROP COLUMN legacy_field;
  ALTER TABLE customers DROP COLUMN IF EXISTS legacy_field;

  RENAME COLUMN:
  ALTER TABLE customers RENAME COLUMN fullname TO name;

  CHANGE COLUMN TYPE:
  -- PostgreSQL:
  ALTER TABLE products ALTER COLUMN price TYPE DECIMAL(12,2);
  ALTER TABLE customers ALTER COLUMN name TYPE VARCHAR(300);

  SET / DROP DEFAULT:
  ALTER TABLE orders ALTER COLUMN status SET DEFAULT 'PENDING';
  ALTER TABLE orders ALTER COLUMN status DROP DEFAULT;

  SET NOT NULL:
  -- Must ensure no NULLs exist first, then:
  ALTER TABLE products ALTER COLUMN sku SET NOT NULL;
  ALTER TABLE products ALTER COLUMN sku DROP NOT NULL;

  RENAME TABLE:
  ALTER TABLE order_details RENAME TO order_items;

================================================================
ADD/DROP CONSTRAINTS
================================================================

  ADD PRIMARY KEY:
  ALTER TABLE legacy_table ADD PRIMARY KEY (id);

  ADD FOREIGN KEY:
  ALTER TABLE orders
  ADD CONSTRAINT fk_orders_customer
      FOREIGN KEY (customer_id) REFERENCES customers(id) ON DELETE RESTRICT;

  ADD UNIQUE:
  ALTER TABLE products ADD CONSTRAINT uk_products_sku UNIQUE (sku);

  ADD CHECK:
  ALTER TABLE products ADD CONSTRAINT chk_price_positive CHECK (price >= 0);

  DROP CONSTRAINT:
  ALTER TABLE orders DROP CONSTRAINT fk_orders_customer;
  ALTER TABLE products DROP CONSTRAINT chk_price_positive;

================================================================
ADD/DROP INDEX
================================================================

  CREATE INDEX idx_orders_status ON orders(status);
  DROP INDEX idx_orders_status;

  -- PostgreSQL: indexes are separate objects, not via ALTER TABLE
  -- MySQL: ALTER TABLE orders ADD INDEX idx_status (status);
  --        ALTER TABLE orders DROP INDEX idx_status;

================================================================
SAFE MIGRATIONS — AVOIDING DOWNTIME
================================================================

  Large tables (millions of rows): ALTER TABLE can lock the table.
  Some operations are safe (no full table rewrite); others are not.

  SAFE (no full rewrite in PostgreSQL):
  - ADD COLUMN with nullable (no DEFAULT) — instant
  - ADD COLUMN with DEFAULT and NOT NULL — fast in PG 11+
  - DROP COLUMN — marks as dropped, no rewrite
  - ADD INDEX CONCURRENTLY — no table lock (PostgreSQL)

  POTENTIALLY SLOW:
  - Changing column type (requires full rewrite if incompatible)
  - ADD NOT NULL without a default (must scan entire table)
  - Adding a constraint that needs validation

  Production strategy for large tables:
  1. Add new column as nullable first
  2. Backfill data in batches
  3. Add NOT NULL constraint after backfill
  4. Use pt-online-schema-change (Percona) or gh-ost for MySQL

================================================================
MYSQL vs POSTGRESQL SYNTAX DIFFERENCES
================================================================

  Operation             PostgreSQL                   MySQL
  --------------------  ---------------------------  -----------------------------
  Change type           ALTER COLUMN x TYPE BIGINT   MODIFY COLUMN x BIGINT
  Rename column         RENAME COLUMN old TO new     RENAME COLUMN old TO new (8+)
  Add NOT NULL          ALTER COLUMN x SET NOT NULL  MODIFY COLUMN x ... NOT NULL
  Set default           ALTER COLUMN x SET DEFAULT v  ALTER COLUMN x SET DEFAULT v

================================================================
INTERVIEW Q&A
================================================================

  Q: How do you add a column to an existing table?
  A: ALTER TABLE table_name ADD COLUMN column_name data_type [constraints];

  Q: What are the risks of ALTER TABLE on large production tables?
  A: Many ALTER operations require a full table rewrite and can lock the table
     for minutes or hours, causing downtime. Use CONCURRENTLY for indexes in
     PostgreSQL, or tools like gh-ost/pt-osc for MySQL in production.

  Q: How do you rename a column without downtime?
  A: In PostgreSQL: ALTER TABLE t RENAME COLUMN old TO new;
     This is metadata-only and fast. But application code must be updated
     simultaneously or use a view/alias during transition.

  Q: What is a zero-downtime migration strategy for adding NOT NULL?
  A: 1. Add column as nullable, 2. Backfill existing rows in batches,
     3. Add NOT NULL constraint (or use NOT NULL DEFAULT after backfill).
     Avoids the table lock from a full scan.
