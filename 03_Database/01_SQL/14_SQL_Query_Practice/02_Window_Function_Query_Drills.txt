DRILL 1: Rank employees by salary within each department
===================================================================
Problem: Show each employee's name, department, salary, and their
         rank within the department (highest salary = rank 1).
         Ties should share the same rank, with no gaps.

Solution:
  SELECT
      name,
      department,
      salary,
      DENSE_RANK() OVER (PARTITION BY department ORDER BY salary DESC) AS dept_rank
  FROM employees
  ORDER BY department, dept_rank;

Key points:
  - PARTITION BY department   → reset rank for each department
  - ORDER BY salary DESC      → highest salary first
  - DENSE_RANK               → no gaps when salaries are tied
  - Use RANK if gaps are acceptable; ROW_NUMBER if you need exactly one row per rank

DRILL 2: Top-2 highest-paid employees per department
===================================================================
Problem: For each department, return the 2 employees with the
         highest salaries. If there is a tie for 2nd place, return
         only one of them (exact 2 rows per dept).

Solution:
  WITH ranked AS (
      SELECT
          name,
          department,
          salary,
          ROW_NUMBER() OVER (PARTITION BY department ORDER BY salary DESC) AS rn
      FROM employees
  )
  SELECT name, department, salary
  FROM ranked
  WHERE rn <= 2
  ORDER BY department, salary DESC;

Key points:
  - ROW_NUMBER used (not RANK) because we want EXACTLY 2 rows
  - Change ROW_NUMBER to RANK if "return all tied rows at position 2" is required

DRILL 3: Find the 3rd highest salary company-wide (distinct)
===================================================================
Problem: Return the 3rd highest distinct salary across all employees.
         If fewer than 3 distinct salaries exist, return NULL.

Solution:
  SELECT salary AS third_highest
  FROM (
      SELECT salary, DENSE_RANK() OVER (ORDER BY salary DESC) AS rnk
      FROM employees
  ) ranked
  WHERE rnk = 3
  LIMIT 1;

  -- Alternative without window functions:
  SELECT MAX(salary) AS third_highest
  FROM employees
  WHERE salary NOT IN (
      SELECT DISTINCT salary FROM employees ORDER BY salary DESC LIMIT 2
  );

Key points:
  - DENSE_RANK ensures "3rd distinct salary" (not 3rd row)
  - LIMIT 1 handles multiple employees at same 3rd salary level

DRILL 4: Running total of salary ordered by hire date
===================================================================
Problem: For each employee ordered by hire date, show a cumulative
         (running) total of salaries from the earliest hire onward.

Solution:
  SELECT
      name,
      hire_date,
      salary,
      SUM(salary) OVER (
          ORDER BY hire_date
          ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
      ) AS running_total
  FROM employees
  ORDER BY hire_date;

Key points:
  - No PARTITION BY → running total across ALL employees
  - ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW is explicit and safest
  - SUM() OVER (ORDER BY col) without frame clause defaults to RANGE, which
    includes all rows with equal ORDER BY value — can differ from ROWS!

DRILL 5: Running total per department
===================================================================
Problem: Same as Drill 4 but reset the running total for each dept.

Solution:
  SELECT
      name,
      department,
      hire_date,
      salary,
      SUM(salary) OVER (
          PARTITION BY department
          ORDER BY hire_date
          ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
      ) AS dept_running_total
  FROM employees
  ORDER BY department, hire_date;

DRILL 6: Compare each employee's salary to the department average
===================================================================
Problem: For each employee show their salary, their department's
         average salary, and the difference.

Solution:
  SELECT
      name,
      department,
      salary,
      ROUND(AVG(salary) OVER (PARTITION BY department), 2) AS dept_avg,
      ROUND(salary - AVG(salary) OVER (PARTITION BY department), 2) AS diff_from_avg
  FROM employees
  ORDER BY department, salary DESC;

Key points:
  - AVG() OVER (PARTITION BY department) with NO ORDER BY computes the
    average across the whole partition (every row in same dept gets same avg)
  - This is a non-moving aggregate window — no frame clause needed

DRILL 7: Percentage of department salary budget
===================================================================
Problem: For each employee, show what percentage of their department's
         total salary budget they represent.

Solution:
  SELECT
      name,
      department,
      salary,
      SUM(salary) OVER (PARTITION BY department)                 AS dept_total,
      ROUND(salary * 100.0 / SUM(salary) OVER (PARTITION BY department), 2) AS pct_of_dept
  FROM employees
  ORDER BY department, pct_of_dept DESC;

DRILL 8: LAG — Month-over-month revenue change
===================================================================
Problem: For each month, show total revenue and the change from the
         previous month (absolute and percentage).

Solution:
  WITH monthly AS (
      SELECT
          DATE_FORMAT(order_date, '%Y-%m') AS month,
          SUM(total)                       AS revenue
      FROM orders
      GROUP BY DATE_FORMAT(order_date, '%Y-%m')
  )
  SELECT
      month,
      revenue,
      LAG(revenue) OVER (ORDER BY month)            AS prev_revenue,
      revenue - LAG(revenue) OVER (ORDER BY month)  AS abs_change,
      ROUND(
          (revenue - LAG(revenue) OVER (ORDER BY month))
          * 100.0 / NULLIF(LAG(revenue) OVER (ORDER BY month), 0),
          2
      )                                              AS pct_change
  FROM monthly
  ORDER BY month;

Key points:
  - LAG(revenue) returns NULL for the first row → abs_change = NULL (correct)
  - NULLIF(..., 0) prevents division by zero

DRILL 9: LEAD — Days until next order per customer
===================================================================
Problem: For each order, show how many days until that customer
         places their next order (NULL if it's their last order).

Solution:
  SELECT
      id           AS order_id,
      customer_id,
      order_date,
      LEAD(order_date) OVER (
          PARTITION BY customer_id ORDER BY order_date
      )            AS next_order_date,
      DATEDIFF(
          LEAD(order_date) OVER (PARTITION BY customer_id ORDER BY order_date),
          order_date
      )            AS days_until_next
  FROM orders
  ORDER BY customer_id, order_date;

DRILL 10: FIRST_VALUE / LAST_VALUE — Highest earner in each dept
===================================================================
Problem: For every row, show the name of the highest-paid employee
         in that department alongside the current employee.

Solution:
  SELECT
      name,
      department,
      salary,
      FIRST_VALUE(name) OVER (
          PARTITION BY department ORDER BY salary DESC
          ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING
      ) AS top_earner_in_dept
  FROM employees
  ORDER BY department, salary DESC;

Key points:
  - FIRST_VALUE with ORDER BY salary DESC → first = highest paid
  - Frame ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING ensures
    LAST_VALUE works correctly (default frame for LAST_VALUE is up to current row!)
  - Alternative: use LAST_VALUE with ORDER BY salary ASC + same frame

DRILL 11: NTILE — Divide employees into salary quartiles
===================================================================
Problem: Assign each employee to a salary quartile (1=lowest, 4=highest)
         and label them accordingly.

Solution:
  SELECT
      name,
      department,
      salary,
      NTILE(4) OVER (ORDER BY salary) AS quartile,
      CASE NTILE(4) OVER (ORDER BY salary)
          WHEN 1 THEN 'Bottom 25%'
          WHEN 2 THEN 'Lower-Mid 25%'
          WHEN 3 THEN 'Upper-Mid 25%'
          WHEN 4 THEN 'Top 25%'
      END AS salary_band
  FROM employees
  ORDER BY salary;

DRILL 12: Find consecutive login streaks (ROW_NUMBER island trick)
===================================================================
Problem: From a logins table (user_id, login_date), find each
         user's longest consecutive login streak.

  -- Table: logins(user_id INT, login_date DATE)

Solution:
  WITH numbered AS (
      SELECT
          user_id,
          login_date,
          -- subtract row number to get an "island" group
          login_date - INTERVAL ROW_NUMBER() OVER (
              PARTITION BY user_id ORDER BY login_date
          ) DAY AS grp
      FROM logins
  ),
  streaks AS (
      SELECT
          user_id,
          grp,
          COUNT(*)       AS streak_len,
          MIN(login_date) AS streak_start,
          MAX(login_date) AS streak_end
      FROM numbered
      GROUP BY user_id, grp
  )
  SELECT
      user_id,
      MAX(streak_len)  AS longest_streak
  FROM streaks
  GROUP BY user_id
  ORDER BY longest_streak DESC;

Key insight:
  For consecutive dates, (date - row_number) is CONSTANT within each streak.
  Any gap in dates breaks the sequence → new grp value.

DRILL 13: Rolling 3-month average revenue
===================================================================
Problem: For each month, calculate the average revenue over
         the current month and the 2 preceding months.

Solution:
  WITH monthly AS (
      SELECT
          DATE_FORMAT(order_date, '%Y-%m') AS month,
          SUM(total)                       AS revenue
      FROM orders
      GROUP BY DATE_FORMAT(order_date, '%Y-%m')
  )
  SELECT
      month,
      revenue,
      ROUND(
          AVG(revenue) OVER (
              ORDER BY month
              ROWS BETWEEN 2 PRECEDING AND CURRENT ROW
          ), 2
      ) AS rolling_avg_3m
  FROM monthly
  ORDER BY month;

DRILL 14: Cumulative distribution — CUME_DIST and PERCENT_RANK
===================================================================
Problem: Show what percentage of employees earn less than or equal
         to each employee's salary (cumulative distribution).

Solution:
  SELECT
      name,
      salary,
      ROUND(CUME_DIST()    OVER (ORDER BY salary) * 100, 2) AS cume_dist_pct,
      ROUND(PERCENT_RANK() OVER (ORDER BY salary) * 100, 2) AS percent_rank_pct
  FROM employees
  ORDER BY salary;

Difference:
  CUME_DIST():    (rows with value <= current) / total rows  → range [1/n, 1]
  PERCENT_RANK(): (rank - 1) / (total rows - 1)             → range [0, 1]

DRILL 15: Full report — salary analysis per department
===================================================================
Problem: For each employee produce a single report row showing:
  - name, department, salary
  - rank within department (DENSE_RANK)
  - department's min, max, avg salary
  - employee's salary vs dept avg (above/below/equal)
  - employee's salary as % of dept total

Solution:
  SELECT
      e.name,
      e.department,
      e.salary,
      DENSE_RANK() OVER (PARTITION BY e.department ORDER BY e.salary DESC)    AS dept_rank,
      MIN(e.salary)  OVER (PARTITION BY e.department)                         AS dept_min,
      MAX(e.salary)  OVER (PARTITION BY e.department)                         AS dept_max,
      ROUND(AVG(e.salary) OVER (PARTITION BY e.department), 2)                AS dept_avg,
      CASE
          WHEN e.salary > AVG(e.salary) OVER (PARTITION BY e.department) THEN 'Above Avg'
          WHEN e.salary < AVG(e.salary) OVER (PARTITION BY e.department) THEN 'Below Avg'
          ELSE 'At Avg'
      END                                                                      AS vs_avg,
      ROUND(
          e.salary * 100.0 / SUM(e.salary) OVER (PARTITION BY e.department), 2
      )                                                                        AS pct_of_dept_total
  FROM employees e
  ORDER BY e.department, dept_rank;

===================================================================
WINDOW FUNCTION QUICK REFERENCE CARD
===================================================================

Function          | Returns                         | Common use
------------------|----------------------------------|---------------------------
ROW_NUMBER()      | Unique sequential int per partition | Top-N (exact rows)
RANK()            | Rank with gaps on ties           | Competitive ranking
DENSE_RANK()      | Rank without gaps on ties        | Nth highest value
NTILE(n)          | Bucket number 1..n               | Quartiles, percentiles
CUME_DIST()       | % of rows <= current             | Percentile position
PERCENT_RANK()    | Relative rank 0..1               | Relative standing
LAG(col, n, def)  | Value n rows before              | Compare to previous
LEAD(col, n, def) | Value n rows ahead               | Compare to next
FIRST_VALUE(col)  | First value in frame             | Min/top per partition
LAST_VALUE(col)   | Last value in frame              | Max/bottom per partition
SUM/AVG/MIN/MAX   | Aggregate over window frame      | Running totals, averages

FRAME CLAUSE (defaults if omitted with ORDER BY):
  RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
  → safest to write ROWS explicitly to avoid surprise with ties
