================================================================
  AGGREGATION AND GROUPING: OVERVIEW
================================================================

  Aggregation collapses many rows into summary values.
  GROUP BY splits rows into buckets before aggregating.

================================================================
THE AGGREGATION PIPELINE
================================================================

  Full query execution order:
  1. FROM / JOIN           --> load and join tables
  2. WHERE                 --> filter individual rows
  3. GROUP BY              --> group rows into buckets
  4. Aggregate functions   --> compute summary per bucket
  5. HAVING                --> filter buckets by aggregate result
  6. SELECT                --> choose output columns
  7. DISTINCT              --> remove duplicate rows (if any)
  8. ORDER BY              --> sort final result
  9. LIMIT / OFFSET        --> paginate

  Key rule: WHERE filters ROWS (before aggregation).
            HAVING filters GROUPS (after aggregation).

================================================================
AGGREGATE FUNCTIONS
================================================================

  Function         Returns
  ---------------  ------------------------------------------
  COUNT(*)         Number of rows (includes NULLs)
  COUNT(col)       Number of non-NULL values in col
  COUNT(DISTINCT)  Number of distinct non-NULL values
  SUM(col)         Total of numeric column
  AVG(col)         Mean of non-NULL values
  MIN(col)         Smallest value
  MAX(col)         Largest value
  STRING_AGG       Concatenate strings (PostgreSQL / SQL Server)
  GROUP_CONCAT     Concatenate strings (MySQL)
  ARRAY_AGG        Collect values into array (PostgreSQL)
  PERCENTILE_CONT  Continuous percentile (median, etc.)

================================================================
GOLDEN RULES FOR GROUP BY
================================================================

  1. Every column in SELECT must either:
     a) Be in GROUP BY, OR
     b) Be wrapped in an aggregate function

  SELECT department_id, COUNT(*), name   -- ILLEGAL: name not in GROUP BY
  FROM employees GROUP BY department_id;

  SELECT department_id, COUNT(*), MAX(name) AS top_name  -- OK
  FROM employees GROUP BY department_id;

  2. ORDER BY can reference aggregate results or group-by columns
  3. HAVING can use aggregate functions; WHERE cannot

================================================================
INTERVIEW Q&A
================================================================

  Q: What is the difference between WHERE and HAVING?
  A: WHERE filters individual rows before grouping (cannot use aggregates).
     HAVING filters the result groups after aggregation (can use aggregates).

  Q: When would you use HAVING without GROUP BY?
  A: To filter on an aggregate over the entire table.
     SELECT COUNT(*) FROM orders HAVING COUNT(*) > 1000;
     (Unusual but valid -- entire table is one implicit group)
