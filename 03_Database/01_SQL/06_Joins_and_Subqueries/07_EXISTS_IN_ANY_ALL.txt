================================================================
  EXISTS, IN, ANY, ALL
================================================================

  These operators test a value against a set or subquery result.

================================================================
IN OPERATOR
================================================================

  Matches if value equals ANY value in a list or subquery:
  SELECT * FROM orders WHERE status IN ('PENDING', 'CONFIRMED', 'SHIPPED');

  Subquery form:
  SELECT name FROM customers
  WHERE id IN (SELECT DISTINCT customer_id FROM orders);

  IN with subquery:
  - Subquery is executed ONCE (non-correlated)
  - Returns a set; outer query checks membership

  DANGER: IN with NULL:
  SELECT * FROM products WHERE category_id NOT IN (1, 2, NULL);
  -- category_id NOT IN (..., NULL) expands to:
  -- category_id <> 1 AND category_id <> 2 AND category_id <> NULL
  -- category_id <> NULL is UNKNOWN -- entire AND is UNKNOWN
  -- RETURNS ZERO ROWS

  Always make sure subquery for NOT IN returns no NULLs,
  or use NOT EXISTS instead.

================================================================
EXISTS OPERATOR
================================================================

  Returns TRUE if subquery returns AT LEAST ONE row.
  Does NOT need to retrieve any data -- SELECT 1 is conventional.

  Customers who have placed at least one order:
  SELECT name FROM customers c
  WHERE EXISTS (
      SELECT 1 FROM orders o WHERE o.customer_id = c.id
  );

  Customers with NO orders:
  SELECT name FROM customers c
  WHERE NOT EXISTS (
      SELECT 1 FROM orders o WHERE o.customer_id = c.id
  );

  EXISTS short-circuits: stops as soon as it finds the first matching row.
  Very efficient for large tables.

================================================================
EXISTS vs IN: COMPARISON
================================================================

  Feature          EXISTS                       IN
  ---------------  ---------------------------  ----------------------------
  Evaluation       Correlated (per outer row)   Usually non-correlated (once)
  NULLs in sub     Safe -- no NULL issue        NOT IN with NULLs returns 0
  Short-circuit    YES (stops at first match)   NO (full set comparison)
  Best for         Large subquery, existence    Small set, literal lists
  Performance      Better for large inner sets  Better for small inner sets

  For NOT EXISTS vs NOT IN: ALWAYS prefer NOT EXISTS if subquery
  might return NULLs (which is almost always the case for FK columns).

================================================================
ANY OPERATOR (SOME)
================================================================

  Returns TRUE if comparison is true for ANY value in the subquery:
  SELECT name, salary FROM employees
  WHERE salary > ANY (
      SELECT salary FROM employees WHERE department_id = 5
  );
  -- employees earning more than at least one person in dept 5

  ANY is equivalent to IN for = :
  col = ANY(subquery)  ===  col IN (subquery)

  SOME is a synonym for ANY.

================================================================
ALL OPERATOR
================================================================

  Returns TRUE if comparison is true for ALL values in the subquery:
  SELECT name, salary FROM employees
  WHERE salary > ALL (
      SELECT salary FROM employees WHERE department_id = 5
  );
  -- employees earning more than EVERYONE in dept 5

  col > ALL(subquery)  ===  col > MAX(subquery value)  (for most DBs)
  col < ALL(subquery)  ===  col < MIN(subquery value)

  If subquery returns empty set:
  col > ALL (empty set) --> TRUE (vacuously true)
  col > ANY (empty set) --> FALSE

================================================================
PRACTICAL SUMMARY
================================================================

  Task                                    Best Approach
  ------------------------------------    ---------------------------
  Check existence (large inner table)     EXISTS
  Check membership (small static list)    IN ('a','b','c')
  Negate existence safely                 NOT EXISTS
  Negate membership (no NULLs)            NOT IN
  Greater than any one value              > ANY  or  > (SELECT MIN...)
  Greater than all values                 > ALL  or  > (SELECT MAX...)

================================================================
INTERVIEW Q&A
================================================================

  Q: Why can NOT IN return no results when a NULL is in the subquery?
  A: NOT IN expands to col <> v1 AND col <> v2 ... AND col <> NULL.
     col <> NULL evaluates to UNKNOWN, making the entire AND UNKNOWN.
     Use NOT EXISTS to safely handle NULLs.

  Q: What is the performance difference between EXISTS and IN?
  A: EXISTS is correlated and short-circuits (stops at first match).
     IN evaluates the full subquery once and builds a set.
     EXISTS is usually faster when the inner table is large.
     IN with a static literal list is fast and clear.

  Q: What does ANY mean in SQL?
  A: col operator ANY(subquery) returns TRUE if the operator is TRUE
     for at least one value returned by the subquery.
     col = ANY(subquery) is equivalent to col IN (subquery).
