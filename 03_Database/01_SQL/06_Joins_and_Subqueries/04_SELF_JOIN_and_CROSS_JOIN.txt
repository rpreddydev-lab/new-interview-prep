================================================================
  SELF JOIN AND CROSS JOIN
================================================================

================================================================
SELF JOIN
================================================================

  A self join joins a table to itself.
  Must use aliases to distinguish the two "instances."
  Common for hierarchical / recursive data.

  Use cases:
  - Employee --> Manager (both in same employees table)
  - Category --> Parent Category
  - Finding duplicate rows
  - Comparing rows within same table

================================================================
SELF JOIN: EMPLOYEE-MANAGER EXAMPLE
================================================================

  employees table:
  id   name     manager_id
  --   -------  ----------
  1    Alice    NULL         (CEO, no manager)
  2    Bob      1            (reports to Alice)
  3    Carol    1            (reports to Alice)
  4    Dave     2            (reports to Bob)

  Query: list employees with their manager's name:
  SELECT
      e.name       AS employee,
      m.name       AS manager
  FROM employees e
  LEFT JOIN employees m ON e.manager_id = m.id;

  Result:
  employee   manager
  --------   -------
  Alice      NULL
  Bob        Alice
  Carol      Alice
  Dave       Bob

  Use INNER JOIN if you only want employees WITH a manager.

================================================================
SELF JOIN: FIND DUPLICATE EMAILS
================================================================

  SELECT a.id, a.email
  FROM customers a
  INNER JOIN customers b
      ON a.email = b.email
     AND a.id < b.id;   -- ensures each pair appears once

================================================================
SELF JOIN: COMPARE CONSECUTIVE ROWS
================================================================

  SELECT
      curr.date,
      curr.revenue,
      prev.revenue AS prev_day_revenue,
      curr.revenue - prev.revenue AS daily_change
  FROM daily_sales curr
  INNER JOIN daily_sales prev ON prev.date = curr.date - INTERVAL '1 day';

================================================================
CROSS JOIN
================================================================

  A CROSS JOIN returns the Cartesian product:
  every row from table A combined with every row from table B.
  No ON condition.

  Result row count = rows_in_A * rows_in_B.

  Syntax:
  SELECT a.color, b.size
  FROM colors a
  CROSS JOIN sizes b;

  Or (implicit, same result -- but avoid, harder to read):
  SELECT a.color, b.size FROM colors a, sizes b;

================================================================
CROSS JOIN USE CASES
================================================================

  Generate all combinations:
  - Product color × size variants
  - Day-of-week × hour-of-day time slots
  - Test data matrix generation

  Generate date series:
  -- PostgreSQL: use generate_series instead
  SELECT d::date
  FROM generate_series('2024-01-01', '2024-12-31', INTERVAL '1 day') AS d;

  Ensure all categories appear in a pivot:
  SELECT categories.name, COALESCE(SUM(o.total), 0)
  FROM categories
  CROSS JOIN (SELECT DISTINCT month FROM orders) months
  LEFT JOIN orders o ON o.category_id = categories.id
                     AND EXTRACT(MONTH FROM o.date) = months.month
  GROUP BY categories.name, months.month;

================================================================
ACCIDENTAL CROSS JOIN WARNING
================================================================

  SELECT * FROM a, b;          -- CROSS JOIN if no WHERE condition
  SELECT * FROM a INNER JOIN b; -- syntax error: missing ON in most DBs

  Always verify JOIN result count when debugging unexpected large results.

================================================================
INTERVIEW Q&A
================================================================

  Q: When would you use a SELF JOIN?
  A: When a table has a relationship with itself -- typically hierarchical
     data like employees/managers, categories/parent categories,
     or finding duplicate values within a single table.

  Q: What is a Cartesian product and when is it useful?
  A: Every row of A paired with every row of B -- n * m rows total.
     Useful for generating combinations (e.g., color x size variants).
     Dangerous if accidental (e.g., forget ON in JOIN) on large tables.

  Q: How do you list employees and their managers from a single table?
  A: SELF JOIN with two aliases (e and m), joining e.manager_id = m.id.
     Use LEFT JOIN to include top-level employees (manager_id IS NULL).
