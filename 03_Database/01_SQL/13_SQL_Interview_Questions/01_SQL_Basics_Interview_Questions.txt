SQL BASICS — INTERVIEW QUESTIONS & ANSWERS
(For Java Developers with 7+ Years Experience)
===========================================================================================================

Q1. What is the difference between WHERE and HAVING?
------------------------------------------------------
WHERE filters rows BEFORE grouping (works on individual rows).
HAVING filters groups AFTER GROUP BY (works on aggregated data).

Example:
  -- Wrong: Cannot use aggregate in WHERE
  SELECT dept, COUNT(*) FROM employees WHERE COUNT(*) > 5 GROUP BY dept; -- ERROR

  -- Correct:
  SELECT dept, COUNT(*) FROM employees GROUP BY dept HAVING COUNT(*) > 5;

Key Rule: If no GROUP BY, HAVING applies to the entire result set.

Q2. What is the difference between DELETE, TRUNCATE, and DROP?
---------------------------------------------------------------
| Feature        | DELETE          | TRUNCATE          | DROP              |
|----------------|-----------------|-------------------|-------------------|
| Type           | DML             | DDL               | DDL               |
| Rollback       | Yes (logged)    | No (or limited)   | No                |
| WHERE clause   | Yes             | No                | No                |
| Triggers fired | Yes             | No                | No                |
| Speed          | Slow            | Fast              | Fast              |
| Structure kept | Yes             | Yes               | No (table gone)   |

DELETE with WHERE removes specific rows.
TRUNCATE removes all rows instantly, resets auto-increment.
DROP removes the entire table structure.

Q3. What is a Primary Key vs Unique Key vs Foreign Key?
--------------------------------------------------------
PRIMARY KEY:
  - Uniquely identifies each row
  - Cannot be NULL
  - Only one per table
  - Automatically creates a clustered index (in most RDBMS)

UNIQUE KEY:
  - Ensures uniqueness but allows ONE NULL (varies by DB)
  - Multiple unique keys per table allowed
  - Creates a non-clustered index

FOREIGN KEY:
  - References Primary Key of another table
  - Enforces referential integrity
  - Can be NULL (unless constrained)
  - Can have ON DELETE CASCADE / ON UPDATE CASCADE

Q4. What is the difference between UNION and UNION ALL?
--------------------------------------------------------
UNION: Combines results of two SELECT statements, removes duplicates.
       Performs a sort/distinct operation — slower.

UNION ALL: Combines results, keeps ALL rows including duplicates.
           Faster — no deduplication step.

Use UNION ALL when you know there are no duplicates or don't care — better performance.

Q5. Explain the execution order of a SQL SELECT statement.
-----------------------------------------------------------
Logical order (not the order you write it):

1. FROM / JOIN       — identify source tables, apply joins
2. WHERE             — filter individual rows
3. GROUP BY          — group filtered rows
4. HAVING            — filter groups
5. SELECT            — compute expressions, apply aliases
6. DISTINCT          — remove duplicates (if specified)
7. ORDER BY          — sort the result
8. LIMIT / OFFSET    — restrict number of rows returned

Why it matters: You CANNOT use a SELECT alias in WHERE because WHERE is evaluated before SELECT.

Q6. What is the difference between INNER JOIN, LEFT JOIN, RIGHT JOIN, and FULL OUTER JOIN?
-------------------------------------------------------------------------------------------
INNER JOIN: Returns only rows with matching values in BOTH tables.
LEFT JOIN:  Returns all rows from LEFT table + matching rows from RIGHT (NULLs if no match).
RIGHT JOIN: Returns all rows from RIGHT table + matching rows from LEFT (NULLs if no match).
FULL OUTER JOIN: Returns all rows from BOTH tables (NULLs where no match).
CROSS JOIN: Returns Cartesian product — every combination of rows.
SELF JOIN: A table joined with itself (for hierarchical data).

Q7. What is a Correlated Subquery? How is it different from a regular subquery?
---------------------------------------------------------------------------------
Regular Subquery: Executes ONCE independently and its result is used by outer query.
  SELECT * FROM employees WHERE salary > (SELECT AVG(salary) FROM employees);

Correlated Subquery: References the outer query — executes ONCE PER ROW of the outer query.
  SELECT e.name FROM employees e
  WHERE salary > (SELECT AVG(salary) FROM employees WHERE dept = e.dept);

Correlated subqueries are generally slower due to repeated execution. 
Often replaceable with JOINs or window functions for better performance.

Q8. What is a NULL? How does NULL behave in comparisons?
---------------------------------------------------------
NULL represents the ABSENCE of a value — it is NOT zero, NOT empty string.

NULL comparisons:
  NULL = NULL  → FALSE (use IS NULL instead)
  NULL != NULL → FALSE
  NULL + 5     → NULL (any arithmetic with NULL = NULL)
  NULL OR TRUE → TRUE
  NULL AND FALSE → FALSE

Functions: COALESCE(val, default) returns first non-NULL value.
           NULLIF(a, b) returns NULL if a = b, else returns a.

Q9. What is a View? What are its advantages and limitations?
-------------------------------------------------------------
A View is a virtual table defined by a stored SQL query.

Advantages:
  - Encapsulates complex queries (abstraction)
  - Security: expose only specific columns to users
  - Reusability: avoids repeating complex SQL
  - Backward compatibility when schema changes

Limitations:
  - Does NOT store data (except Materialized Views)
  - Performance not always better (view is expanded inline)
  - Some views are NOT updatable (complex joins, GROUP BY, DISTINCT)

Materialized View: Physically stores the query result. Needs explicit REFRESH.
Use when the underlying query is expensive and data doesn't change frequently.

Q10. What is indexing? Explain different types of indexes.
-----------------------------------------------------------
An index is a data structure (B-Tree, Hash, etc.) that speeds up data retrieval.

Types:
  Clustered Index: Determines the physical order of data in the table.
                   Only ONE per table. Primary Key creates this by default.

  Non-Clustered Index: Separate structure with pointers to actual row data.
                       Multiple allowed per table.

  Composite Index: Index on multiple columns. Column ORDER matters.
                   Follows "leftmost prefix" rule for query matching.

  Covering Index: Index includes ALL columns needed by a query — avoids table lookup.

  Unique Index: Enforces uniqueness + acts as an index.

  Partial Index (PostgreSQL): Index on a subset of rows.

  Full-Text Index: For text search operations.

When NOT to index: Small tables, columns with low cardinality (e.g., boolean),
                   columns frequently updated.

Q11. What is query optimization? How do you approach it?
---------------------------------------------------------
1. Use EXPLAIN / EXPLAIN ANALYZE to view the execution plan
2. Check for full table scans → add appropriate indexes
3. Avoid SELECT * — select only needed columns
4. Use JOINs instead of subqueries where possible
5. Avoid functions on indexed columns in WHERE (defeats index use):
     BAD:  WHERE YEAR(created_at) = 2024
     GOOD: WHERE created_at BETWEEN '2024-01-01' AND '2024-12-31'
6. Use LIMIT to reduce result size early
7. Check for N+1 query patterns (especially in ORM usage)
8. Use covering indexes to avoid table lookups
9. Partition large tables
10. Analyze statistics — outdated statistics lead to bad query plans

Q12. What is a stored procedure? Difference between stored procedure and function?
-----------------------------------------------------------------------------------
Stored Procedure: Precompiled SQL statements stored in the database.
                  Can have IN, OUT, INOUT parameters.
                  Can contain DML, DDL, control flow.
                  Does NOT have to return a value.

Function: Must return a value (scalar or table).
          Can be used in SELECT statements.
          Generally cannot have side effects (DML varies by DB).

Key Differences:
  - Functions can be called in SELECT; procedures cannot.
  - Procedures can have OUT parameters; functions usually cannot.
  - Functions must return a value; procedures don't have to.

Q13. What is a trigger? When would you use one?
------------------------------------------------
A trigger is a database object that automatically executes in response to
INSERT, UPDATE, or DELETE on a table.

Types:
  BEFORE trigger: Executes before the DML operation
  AFTER trigger:  Executes after the DML operation
  INSTEAD OF:     Used on Views (replace the DML with custom logic)

Use Cases:
  - Audit logging (track changes to sensitive data)
  - Enforcing business rules that can't be done with constraints
  - Maintaining derived/summary tables
  - Cascading changes

Caution: Triggers are hard to debug, can slow DML, and hide business logic from the app.
In modern Java apps, prefer application-level auditing (e.g., Spring Data @EntityListeners).

Q14. What is normalization? Explain 1NF, 2NF, 3NF, BCNF.
----------------------------------------------------------
Normalization: Process of organizing data to reduce redundancy and improve integrity.

1NF (First Normal Form):
  - Each column contains atomic (indivisible) values
  - No repeating groups or arrays
  - Each row is unique

2NF (Second Normal Form):
  - Must be in 1NF
  - No partial dependency: every non-key column depends on the WHOLE primary key
  - Applies only when composite primary key exists

3NF (Third Normal Form):
  - Must be in 2NF
  - No transitive dependency: non-key columns depend ONLY on the primary key

BCNF (Boyce-Codd Normal Form):
  - Stricter version of 3NF
  - For every functional dependency X → Y, X must be a super key

Denormalization: Intentionally introducing redundancy for performance (e.g., caching totals).

Q15. What is the difference between optimistic and pessimistic locking?
------------------------------------------------------------------------
Pessimistic Locking:
  - Assumes conflicts will happen
  - Locks the row when reading to prevent others from modifying it
  - SQL: SELECT ... FOR UPDATE
  - Used when concurrent updates are very likely
  - Risk: Deadlocks, reduced throughput

Optimistic Locking:
  - Assumes conflicts are rare
  - No lock on read; at UPDATE time, checks if data was changed (using version/timestamp)
  - SQL: UPDATE SET ... WHERE id = ? AND version = ?
  - If version mismatch → optimistic lock failure → retry
  - Used in high-read, low-write scenarios
  - In JPA: @Version annotation handles this automatically
