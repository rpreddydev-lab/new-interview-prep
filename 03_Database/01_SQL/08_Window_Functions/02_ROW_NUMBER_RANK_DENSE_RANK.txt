================================================================
  ROW_NUMBER, RANK, DENSE_RANK
================================================================

  All three assign a number to rows based on ORDER BY within a partition.
  They differ in how they handle TIES.

================================================================
COMPARISON: TIED ROWS
================================================================

  salary: 5000, 5000, 4000, 3000, 3000

  ROW_NUMBER   1, 2, 3, 4, 5   -- unique, arbitrary tie-break
  RANK         1, 1, 3, 4, 4   -- ties get same rank; next rank SKIPS
  DENSE_RANK   1, 1, 2, 3, 3   -- ties get same rank; next rank DOES NOT skip

================================================================
SYNTAX
================================================================

  ROW_NUMBER()   OVER (PARTITION BY dept ORDER BY salary DESC)
  RANK()         OVER (PARTITION BY dept ORDER BY salary DESC)
  DENSE_RANK()   OVER (PARTITION BY dept ORDER BY salary DESC)

================================================================
TOP N PER GROUP — THE CLASSIC INTERVIEW QUESTION
================================================================

  "Get the top 2 highest-paid employees per department."

  WITH ranked AS (
      SELECT
          name,
          salary,
          department_id,
          ROW_NUMBER() OVER (PARTITION BY department_id ORDER BY salary DESC) AS rn
      FROM employees
  )
  SELECT name, salary, department_id
  FROM ranked
  WHERE rn <= 2;

  Use ROW_NUMBER when you want exactly N rows per group (no ties kept).
  Use RANK when you want all rows tied at rank N included.
  Use DENSE_RANK when you want rank N without gaps (common in reports).

================================================================
ASSIGN SEQUENTIAL ROW ID
================================================================

  Add row numbers to a result (useful for pagination or debugging):
  SELECT ROW_NUMBER() OVER (ORDER BY created_at) AS row_num, *
  FROM orders;

================================================================
PERCENTILE RANKING
================================================================

  NTILE(n): divides rows into n equal buckets (quartiles, deciles, etc.)
  SELECT name, salary,
         NTILE(4) OVER (ORDER BY salary) AS salary_quartile
  FROM employees;
  -- Quartile 1 = bottom 25%, Quartile 4 = top 25%

  PERCENT_RANK: relative position as 0.0 to 1.0
  SELECT name, salary,
         PERCENT_RANK() OVER (ORDER BY salary) AS pct_rank
  FROM employees;

  CUME_DIST: cumulative distribution (0 < value <= 1)
  -- What fraction of employees earn <= this salary?

================================================================
INTERVIEW Q&A
================================================================

  Q: Difference between RANK and DENSE_RANK?
  A: If two rows tie at rank 2, both get rank 2.
     RANK then assigns rank 4 to the next row (skips 3).
     DENSE_RANK assigns rank 3 to the next row (no gap).

  Q: How do you get the top N rows per group in SQL?
  A: Use ROW_NUMBER() OVER (PARTITION BY group_col ORDER BY sort_col)
     in a CTE or subquery, then WHERE rn <= N in the outer query.

  Q: When would you use ROW_NUMBER vs RANK?
  A: ROW_NUMBER for pagination and when you need exactly N rows.
     RANK/DENSE_RANK for rankings where ties should get the same position.
