================================================================
  RECURSIVE CTEs
================================================================

  A recursive CTE references itself to traverse hierarchical or
  graph-like data: org charts, category trees, bill-of-materials,
  network paths.

================================================================
SYNTAX
================================================================

  WITH RECURSIVE cte_name AS (
      -- Anchor member (base case, non-recursive)
      SELECT ...

      UNION ALL

      -- Recursive member (references cte_name)
      SELECT ...
      FROM cte_name
      WHERE <termination condition>
  )
  SELECT * FROM cte_name;

  Execution:
  1. Run anchor once --> initial result set R0
  2. Run recursive member with R0 --> R1
  3. Run recursive member with R1 --> R2
  4. Continue until recursive member returns 0 rows
  5. Result = R0 UNION ALL R1 UNION ALL R2 ...

================================================================
EXAMPLE 1 -- ORG CHART (TOP-DOWN)
================================================================

  Table: employees(id, name, manager_id)
  manager_id = NULL for the CEO.

  WITH RECURSIVE org_chart AS (
      -- Anchor: start at CEO (no manager)
      SELECT id, name, manager_id, 0 AS depth
      FROM employees
      WHERE manager_id IS NULL

      UNION ALL

      -- Recursive: find direct reports
      SELECT e.id, e.name, e.manager_id, oc.depth + 1
      FROM employees e
      JOIN org_chart oc ON e.manager_id = oc.id
  )
  SELECT LPAD(' ', depth * 2) || name AS name_with_indent, depth
  FROM org_chart
  ORDER BY depth, name;

  Output:
  name_with_indent     depth
  CEO                  0
    VP Engineering     1
      Team Lead A      2
        Engineer 1     3
    VP Marketing       1

================================================================
EXAMPLE 2 -- FIND PATH FROM ROOT TO NODE
================================================================

  WITH RECURSIVE path AS (
      SELECT id, name, manager_id, ARRAY[id] AS path_ids
      FROM employees
      WHERE id = 101  -- start at specific employee

      UNION ALL

      SELECT e.id, e.name, e.manager_id, p.path_ids || e.id
      FROM employees e
      JOIN path p ON e.id = p.manager_id
  )
  SELECT name, path_ids
  FROM path
  WHERE manager_id IS NULL;

================================================================
EXAMPLE 3 -- CATEGORY TREE (BOTTOM-UP)
================================================================

  Table: categories(id, name, parent_id)

  Find all ancestors of category id=42:

  WITH RECURSIVE ancestors AS (
      SELECT id, name, parent_id
      FROM categories
      WHERE id = 42

      UNION ALL

      SELECT c.id, c.name, c.parent_id
      FROM categories c
      JOIN ancestors a ON c.id = a.parent_id
  )
  SELECT * FROM ancestors;

================================================================
DEPTH LIMITING (AVOID INFINITE LOOPS)
================================================================

  If your data has cycles (graph, not tree), a plain recursive CTE
  loops forever. Add depth limit or cycle detection.

  WITH RECURSIVE traversal AS (
      SELECT id, source_id, dest_id, 1 AS depth
      FROM graph_edges
      WHERE source_id = 1

      UNION ALL

      SELECT e.id, e.source_id, e.dest_id, t.depth + 1
      FROM graph_edges e
      JOIN traversal t ON e.source_id = t.dest_id
      WHERE t.depth < 10  -- depth limit prevents infinite recursion
  )
  SELECT * FROM traversal;

================================================================
CYCLE DETECTION (POSTGRESQL 14+)
================================================================

  PostgreSQL 14 added CYCLE clause:

  WITH RECURSIVE traversal AS (
      SELECT id, parent_id
      FROM nodes
      WHERE id = 1

      UNION ALL

      SELECT n.id, n.parent_id
      FROM nodes n
      JOIN traversal t ON n.id = t.parent_id
  )
  CYCLE id SET is_cycle USING path
  SELECT * FROM traversal WHERE NOT is_cycle;

================================================================
GENERATING SERIES WITH RECURSIVE CTE
================================================================

  Portable way to generate a sequence (without generate_series):

  WITH RECURSIVE series AS (
      SELECT 1 AS n
      UNION ALL
      SELECT n + 1 FROM series WHERE n < 10
  )
  SELECT n FROM series;

  Output: 1, 2, 3, ..., 10

================================================================
INTERVIEW Q&A
================================================================

  Q: How does a recursive CTE work?
  A: It has two parts: an anchor (base case, runs once) and a recursive
     member (references the CTE, runs repeatedly).
     Each iteration feeds its output into the next run.
     Stops when the recursive member returns 0 rows.

  Q: When would you use a recursive CTE in practice?
  A: Traversing org charts, category trees, bill-of-materials hierarchies,
     finding connected nodes in a graph, generating sequences.

  Q: How do you prevent an infinite loop in a recursive CTE?
  A: Add a depth counter and a WHERE depth < N limit.
     Or use PostgreSQL 14's CYCLE clause to mark visited nodes.

  Q: What is the difference between UNION and UNION ALL in a recursive CTE?
  A: UNION removes duplicates (expensive). UNION ALL keeps all rows.
     Almost always use UNION ALL for performance unless you explicitly
     need deduplication.
