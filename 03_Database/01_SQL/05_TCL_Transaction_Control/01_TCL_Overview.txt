================================================================
  TCL — TRANSACTION CONTROL LANGUAGE: OVERVIEW
================================================================

  TCL controls when changes are permanently saved or undone.
  Commands: BEGIN, COMMIT, ROLLBACK, SAVEPOINT, RELEASE, SET TRANSACTION.

================================================================
WHAT IS A TRANSACTION
================================================================

  A transaction is a logical unit of work:
  - Either ALL its changes are saved (COMMIT)
  - Or ALL its changes are undone (ROLLBACK)
  - Never partial -- that is the Atomicity guarantee

  Classic example: bank transfer
  BEGIN;
    UPDATE accounts SET balance = balance - 500 WHERE id = 1;  -- debit
    UPDATE accounts SET balance = balance + 500 WHERE id = 2;  -- credit
  COMMIT;

  If anything fails between debit and credit, ROLLBACK undoes both.
  Money is never lost or duplicated.

================================================================
ACID PROPERTIES (RECAP)
================================================================

  Atomicity     All-or-nothing. Partial commits are impossible.
  Consistency   Transaction takes DB from one valid state to another.
  Isolation     Concurrent transactions do not see each other's interim state.
  Durability    Committed data survives crashes (written to WAL/redo log).

================================================================
TCL COMMANDS SUMMARY
================================================================

  Command               Description
  --------------------  -------------------------------------------------
  BEGIN / START TRANSACTION  Start a new transaction block
  COMMIT                Permanently save all changes in the transaction
  ROLLBACK              Undo all changes since last BEGIN or SAVEPOINT
  SAVEPOINT name        Create a named checkpoint within a transaction
  ROLLBACK TO name      Undo to the savepoint, keep earlier changes
  RELEASE SAVEPOINT     Remove a savepoint (changes stay, just no marker)
  SET TRANSACTION       Set isolation level before transaction begins

  Aliases:
  PostgreSQL: BEGIN = START TRANSACTION
  MySQL: BEGIN, START TRANSACTION, or SET autocommit = 0

================================================================
TRANSACTION STATES
================================================================

  ACTIVE      --> after BEGIN, before COMMIT/ROLLBACK
  PARTIALLY COMMITTED --> after last statement, before COMMIT written to disk
  COMMITTED   --> after COMMIT; data is permanent
  FAILED      --> after error; must ROLLBACK
  ABORTED     --> after ROLLBACK; DB restored to pre-transaction state

================================================================
ISOLATION LEVELS
================================================================

  READ UNCOMMITTED  Can read uncommitted changes from other transactions (dirty read)
  READ COMMITTED    Only see committed data (default in Oracle, SQL Server)
  REPEATABLE READ   Same row reads return same data (default in MySQL/InnoDB)
  SERIALIZABLE      Transactions appear to run one-at-a-time; strictest

  SET TRANSACTION ISOLATION LEVEL REPEATABLE READ;
  BEGIN;
    -- queries here use REPEATABLE READ
  COMMIT;

================================================================
INTERVIEW Q&A
================================================================

  Q: What is a transaction?
  A: A logical unit of work where all changes are either committed
     together or all rolled back. Guarantees atomicity.

  Q: What happens if a server crash occurs mid-transaction?
  A: The transaction is automatically rolled back on restart.
     Databases use a Write-Ahead Log (WAL/redo log) -- committed
     transactions are replayed; uncommitted are discarded.

  Q: What is the difference between READ COMMITTED and REPEATABLE READ?
  A: READ COMMITTED sees only committed rows, but if another transaction
     commits between your two reads of the same row, you may get different values.
     REPEATABLE READ guarantees the same row read twice in one transaction
     returns the same value (snapshot of start time).
