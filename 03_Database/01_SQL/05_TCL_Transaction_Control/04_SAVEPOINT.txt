================================================================
  SAVEPOINT
================================================================

  A SAVEPOINT creates a named bookmark within a transaction.
  Allows partial rollback without abandoning the entire transaction.

================================================================
SYNTAX
================================================================

  SAVEPOINT savepoint_name;
  ROLLBACK TO [SAVEPOINT] savepoint_name;
  RELEASE SAVEPOINT savepoint_name;   -- remove the marker (optional)

================================================================
USE CASE: RETRY-ABLE STEPS IN A BATCH
================================================================

  BEGIN;
    INSERT INTO batch_jobs (name) VALUES ('Job A');   -- step 1
    SAVEPOINT after_job_a;

    INSERT INTO batch_items (job_id, data) VALUES (1, 'item1');  -- step 2a
    INSERT INTO batch_items (job_id, data) VALUES (1, 'item2');  -- step 2b
    SAVEPOINT after_items;

    UPDATE batch_jobs SET status = 'DONE' WHERE id = 1;   -- step 3

    -- if step 3 fails for some reason:
    ROLLBACK TO SAVEPOINT after_items;
    -- steps 1 and 2 still intact, retry step 3 with different logic

  COMMIT;   -- commits whatever survived the SAVEPOINTs

================================================================
USE CASE: NESTED OPERATIONS WITH INDEPENDENT FAILURE HANDLING
================================================================

  BEGIN;
    -- main order insert
    INSERT INTO orders (customer_id, total) VALUES (42, 150);
    SAVEPOINT order_placed;

    -- try to apply discount coupon
    SAVEPOINT before_coupon;
    UPDATE coupons SET used = true WHERE code = 'SAVE10';
    -- if coupon does not exist or is expired:
    -- ROLLBACK TO SAVEPOINT before_coupon;  (coupon step undone)
    -- continue without discount

    -- finalize
    UPDATE inventory SET qty = qty - 1 WHERE product_id = 5;
  COMMIT;

================================================================
SAVEPOINT IN JDBC (Java)
================================================================

  Savepoint sp = null;
  try {
      conn.setAutoCommit(false);
      stmt.executeUpdate("INSERT INTO orders ...");
      sp = conn.setSavepoint("after_order");       // create savepoint

      stmt.executeUpdate("INSERT INTO order_items ...");
      conn.commit();

  } catch (SQLException e) {
      if (sp != null) {
          conn.rollback(sp);    // roll back to savepoint
          // retry order_items insert with corrected data
      } else {
          conn.rollback();      // full rollback
      }
  }

================================================================
NESTED TRANSACTIONS IN JPA / SPRING
================================================================

  Spring's @Transactional does NOT support true nested transactions
  (SAVEPOINT) by default.

  Use PROPAGATION_NESTED to get SAVEPOINT-backed behavior:
  @Transactional(propagation = Propagation.NESTED)
  public void innerOperation() { ... }
  -- if innerOperation() throws, only it is rolled back (to savepoint)
  -- outer transaction continues

  PROPAGATION_NESTED requires a database driver that supports savepoints
  (JDBC savepoints) and is NOT supported by JTA transaction managers.

  Most common propagation types:
  REQUIRED       Join existing or create new (default)
  REQUIRES_NEW   Suspend existing, create new independent transaction
  NESTED         Use savepoint within existing transaction
  SUPPORTS       Use transaction if exists, non-transactional if not
  NOT_SUPPORTED  Suspend transaction, run non-transactionally

================================================================
RELEASE SAVEPOINT
================================================================

  RELEASE SAVEPOINT name;
  -- Removes the savepoint marker. Does NOT commit or rollback changes.
  -- Useful to free resources if you know you no longer need the checkpoint.

================================================================
INTERVIEW Q&A
================================================================

  Q: What is the difference between SAVEPOINT and a nested transaction?
  A: A savepoint is a marker within a single transaction.
     Rollback to a savepoint undoes only the statements after it.
     True nested transactions (separate transaction logs) are rare in SQL;
     Spring NESTED propagation simulates them using JDBC savepoints.

  Q: When would you use SAVEPOINT in a Spring application?
  A: Propagation.NESTED on an inner @Transactional method. If the inner
     method fails, only that work is rolled back via savepoint; the outer
     transaction can catch the exception and continue.

  Q: Does RELEASE SAVEPOINT commit the transaction?
  A: No. It only removes the checkpoint marker. The transaction remains
     open until COMMIT or ROLLBACK.
