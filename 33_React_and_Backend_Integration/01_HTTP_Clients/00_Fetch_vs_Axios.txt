================================================================
FETCH API vs AXIOS — IN-DEPTH COMPARISON
================================================================

================================================================
1. FETCH API — NATIVE BROWSER
================================================================

The Fetch API is built into all modern browsers (and Node.js 18+).
It returns Promises and uses the Request/Response model.

BASIC USAGE:
  // GET
  fetch('https://api.example.com/users')
    .then(response => {
      if (!response.ok) {
        throw new Error(`HTTP error! status: ${response.status}`);
      }
      return response.json();
    })
    .then(data => console.log(data))
    .catch(err => console.error('Network error:', err));

  // POST with JSON
  fetch('https://api.example.com/users', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'Authorization': `Bearer ${token}`,
    },
    body: JSON.stringify({ name: 'Alice', email: 'alice@example.com' }),
  })
  .then(res => res.json())
  .then(data => console.log(data));

  // With async/await
  async function getUser(id) {
    const response = await fetch(`/api/users/${id}`);
    if (!response.ok) {
      throw new Error(`HTTP ${response.status}`);
    }
    return response.json();
  }

FETCH QUIRKS YOU MUST KNOW:
  1. Fetch only rejects on NETWORK errors. A 404 or 500 does NOT
     reject the promise. You must manually check response.ok.

  2. No automatic JSON parsing. You must call .json(), .text(), .blob().

  3. No built-in timeout. You need AbortController + setTimeout.

  4. No interceptors. You'd need to wrap fetch yourself.

  5. No upload progress. XHR or Axios needed for progress tracking.

FETCH WITH TIMEOUT:
  async function fetchWithTimeout(url, options = {}, timeout = 5000) {
    const controller = new AbortController();
    const id = setTimeout(() => controller.abort(), timeout);
    try {
      const response = await fetch(url, {
        ...options,
        signal: controller.signal,
      });
      if (!response.ok) throw new Error(`HTTP ${response.status}`);
      return await response.json();
    } finally {
      clearTimeout(id);
    }
  }

FETCH GOTCHAS:
  - credentials: 'include' must be set explicitly to send cookies
  - mode: 'cors' is the default but must be aware of it
  - No query string serialization — must build URL manually
  - No request cancellation without AbortController

================================================================
2. AXIOS — THE POPULAR CHOICE
================================================================

Axios is an HTTP client library that works in browser and Node.js.
It wraps XMLHttpRequest in browser (not fetch) and http in Node.js.

INSTALLATION:
  npm install axios

BASIC USAGE:
  import axios from 'axios';

  // GET
  axios.get('/api/users')
    .then(response => console.log(response.data))
    .catch(err => console.error(err));

  // POST
  axios.post('/api/users', { name: 'Alice', email: 'alice@example.com' })
    .then(response => console.log(response.data));

  // With async/await
  const { data } = await axios.get('/api/users/1');

AXIOS RESPONSE SHAPE:
  {
    data: {},          // the actual response body (already parsed)
    status: 200,       // HTTP status code
    statusText: 'OK',
    headers: {},       // response headers
    config: {},        // the config used for the request
    request: {}        // the XHR/http object
  }

  Note: you access data via response.data, not response.json()

AXIOS AUTOMATICALLY:
  - Parses JSON response body → no .json() needed
  - Serializes JS objects to JSON for request body
  - Throws errors for 4xx and 5xx responses
  - Sets Content-Type: application/json when sending objects

3. FEATURE COMPARISON TABLE
================================================================

Feature                       | Fetch API        | Axios
------------------------------|------------------|--------------------
Built-in                      | ✅ Yes           | ❌ npm install
JSON auto-parse (response)    | ❌ .json()       | ✅ response.data
JSON auto-serialize (request) | ❌ JSON.stringify| ✅ Automatic
4xx/5xx → Promise reject      | ❌ Must check ok | ✅ Auto-reject
Request Interceptors          | ❌               | ✅
Response Interceptors         | ❌               | ✅
Timeout support               | ❌ Need AbortCtrl| ✅ timeout option
Upload progress               | ❌               | ✅ onUploadProgress
Download progress             | ❌               | ✅ onDownloadProgress
Request cancellation          | AbortController  | AbortController
Works in Node.js              | ✅ (v18+)        | ✅
Query string serialization    | ❌ Manual        | ✅ params option
Concurrent requests           | Promise.all      | axios.all (same)
XSRF protection               | ❌               | ✅ Built-in
Browser support               | All modern       | All modern + IE11
Bundle size                   | 0 bytes          | ~15KB (gzipped)

================================================================
4. AXIOS KEY FEATURES IN DETAIL
================================================================

A) PARAMS (QUERY STRING)
  axios.get('/api/products', {
    params: {
      category: 'electronics',
      page: 1,
      size: 20,
    }
  });
  // Makes: GET /api/products?category=electronics&page=1&size=20

B) ERROR INSPECTION
  try {
    await axios.get('/api/users/999');
  } catch (error) {
    if (axios.isAxiosError(error)) {
      console.log(error.response?.status);    // 404
      console.log(error.response?.data);      // { message: 'Not found' }
      console.log(error.request);             // request was made but no response
    } else {
      console.log('Non-axios error', error);
    }
  }

  Three types of Axios errors:
    1. error.response — server responded with an error status (4xx, 5xx)
    2. error.request  — request was made but no response received
    3. Other          — something went wrong setting up the request

C) REQUEST CANCELLATION
  const controller = new AbortController();
  axios.get('/api/data', { signal: controller.signal });
  controller.abort(); // cancel
  // error.name === 'CanceledError'

D) CONCURRENT REQUESTS
  const [users, products] = await Promise.all([
    axios.get('/api/users'),
    axios.get('/api/products'),
  ]);

E) DEFAULTS
  axios.defaults.baseURL = 'https://api.example.com';
  axios.defaults.headers.common['Authorization'] = `Bearer ${token}`;
  axios.defaults.timeout = 5000;

  // Per-method defaults
  axios.defaults.headers.post['Content-Type'] = 'application/json';

F) UPLOAD PROGRESS
  axios.post('/api/upload', formData, {
    onUploadProgress: (progressEvent) => {
      const percent = Math.round(
        (progressEvent.loaded * 100) / progressEvent.total
      );
      setProgress(percent);
    },
  });

================================================================
5. FETCH vs AXIOS — WHEN TO CHOOSE WHICH
================================================================

USE FETCH WHEN:
  - Bundle size is critical (e.g., a tiny micro-frontend)
  - You don't need interceptors or advanced features
  - Working in a Node.js 18+ environment and don't want a dependency
  - Building a small utility with minimal dependencies

USE AXIOS WHEN:
  - Building a medium-to-large React application
  - Need request/response interceptors (auth token, error handling)
  - Need upload progress tracking
  - Want automatic JSON handling
  - Want robust error handling with status-code differentiation
  - Using TypeScript (Axios has excellent types built-in)
  - Using multiple environments with different base URLs

IN INTERVIEWS: Axios is by far the more common choice in enterprise
React apps. Knowing how to configure an Axios instance with
interceptors is a MUST for senior React roles.

================================================================
6. THE AXIOS INSTANCE (Best Practice)
================================================================

Never use the global axios object directly. Always create an instance:

  // src/api/axiosConfig.js
  import axios from 'axios';

  const apiClient = axios.create({
    baseURL: import.meta.env.VITE_API_BASE_URL || 'http://localhost:8080',
    timeout: 10000, // 10 seconds
    headers: {
      'Content-Type': 'application/json',
    },
  });

  export default apiClient;

Then in services:
  import apiClient from '../api/axiosConfig';
  export const getUsers = () => apiClient.get('/users');

Benefits:
  - Different instances for different APIs (internal, third-party)
  - Interceptors scoped to one instance
  - Base URL from environment variable
  - Shared timeout/headers config

================================================================
7. INTERVIEW QUESTIONS
================================================================

Q: Why would you use Axios over the built-in fetch API?
A: Axios provides automatic JSON parsing, automatic error rejection
   on 4xx/5xx, built-in interceptors, timeout support, upload progress,
   and TypeScript support out of the box. The main tradeoff is a ~15KB
   bundle size. For large enterprise apps, the DX and features
   justify the size.

Q: How does Axios handle errors differently from fetch?
A: Axios rejects the Promise for any HTTP status >= 400. fetch only
   rejects on network errors — you must manually check response.ok.
   Axios also structures errors with response, request, and message
   properties for granular error handling.

Q: What is the difference between axios.create() and using axios directly?
A: axios.create() returns a new Axios instance with its own config
   (baseURL, timeout, headers) and its own interceptors. This is best
   practice because it avoids polluting global axios defaults, allows
   multiple API configurations, and scopes interceptors.

Q: How do you handle request cancellation in Axios?
A: Use AbortController: create a controller, pass controller.signal
   to the Axios request config, call controller.abort() to cancel.
   The error thrown is a CanceledError (axios.isCancel(err) === true).
   This is essential in React to avoid state updates on unmounted components.

Q: Can you use fetch with React Query?
A: Yes. React Query is agnostic to the fetching library. The queryFn
   receives a signal for cancellation. You can use fetch or Axios or
   any async function. Axios is still preferred for its features.
