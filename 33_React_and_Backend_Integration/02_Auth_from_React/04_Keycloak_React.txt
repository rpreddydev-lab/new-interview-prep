================================================================
KEYCLOAK INTEGRATION WITH REACT
================================================================

Keycloak is an open-source Identity and Access Management solution
that supports SSO, OAuth2, OpenID Connect, and SAML.
It's widely used in enterprise Java (Spring Boot) environments.

================================================================
1. WHAT IS KEYCLOAK?
================================================================

Keycloak provides:
  - User authentication (username/password, MFA)
  - Social login (Google, GitHub, etc.)
  - SSO (Single Sign-On) across multiple apps
  - JWT access and refresh tokens
  - User management UI
  - Role-based access control (RBAC)
  - Realm-based multi-tenancy

Runs as a standalone server (or Docker container).
Default port: 8080 (usually put on separate port from Spring Boot)

================================================================
2. KEYCLOAK CONCEPTS
================================================================

REALM: An isolated namespace of users and applications.
       E.g., "myrealm" contains all users and clients for your app.

CLIENT: An application registered in Keycloak.
        Your React app is a public client.
        Your Spring Boot API is a confidential/bearer-only client.

USER: An account in Keycloak (username, email, credentials).

ROLE: Permissions assigned to users (ROLE_ADMIN, ROLE_USER).
      Realm roles (across all clients) vs client roles (per-client).

================================================================
3. INSTALLATION
================================================================

  npm install keycloak-js @react-keycloak/web

  keycloak-js: Official Keycloak JavaScript adapter
  @react-keycloak/web: React-specific bindings

================================================================
4. KEYCLOAK CLIENT SETUP IN ADMIN CONSOLE
================================================================

1. Log in to Keycloak admin console
2. Create a realm (e.g., "myrealm")
3. Create a client:
   - Client ID: react-app
   - Client Protocol: openid-connect
   - Access Type: public (React is a public client)
   - Valid Redirect URIs: http://localhost:3000/*
   - Web Origins: http://localhost:3000 (CORS)
   - Standard Flow: Enabled (Authorization Code)
   - Implicit Flow: Disabled

5. REACT INTEGRATION WITH @react-keycloak/web
================================================================

FILE: src/keycloak.js
  import Keycloak from 'keycloak-js';

  const keycloak = new Keycloak({
    url: 'http://localhost:8080',           // Keycloak server URL
    realm: 'myrealm',
    clientId: 'react-app',
  });

  export default keycloak;

FILE: src/main.jsx
  import { ReactKeycloakProvider } from '@react-keycloak/web';
  import keycloak from './keycloak';

  const initOptions = {
    onLoad: 'check-sso',         // 'check-sso' | 'login-required'
    // 'check-sso': user is redirected only if needed (silent check first)
    // 'login-required': always redirect to Keycloak if not authenticated
    silentCheckSsoRedirectUri: window.location.origin + '/silent-check-sso.html',
    pkceMethod: 'S256',          // Always use PKCE
    checkLoginIframe: false,     // Disable iframe check (optional, CORS issues)
  };

  root.render(
    <ReactKeycloakProvider
      authClient={keycloak}
      initOptions={initOptions}
      onTokens={(tokens) => console.log('tokens:', tokens)}
      onEvent={(event, error) => console.log('event:', event, error)}
    >
      <App />
    </ReactKeycloakProvider>
  );

FILE: public/silent-check-sso.html (Required for silent SSO check)
  <html>
  <body>
    <script>
      parent.postMessage(location.href, location.origin);
    </script>
  </body>
  </html>

6. USING KEYCLOAK IN COMPONENTS
================================================================

  import { useKeycloak } from '@react-keycloak/web';

  function App() {
    const { keycloak, initialized } = useKeycloak();

    if (!initialized) return <div>Loading Keycloak...</div>;

    return (
      <div>
        {keycloak.authenticated ? (
          <>
            <p>Welcome, {keycloak.tokenParsed?.preferred_username}</p>
            <button onClick={() => keycloak.logout()}>Logout</button>
          </>
        ) : (
          <button onClick={() => keycloak.login()}>Login</button>
        )}
      </div>
    );
  }

7. PROTECTED ROUTE WITH KEYCLOAK
================================================================

  import { useKeycloak } from '@react-keycloak/web';
  import { Navigate, Outlet } from 'react-router-dom';

  function KeycloakProtectedRoute({ roles = [] }) {
    const { keycloak, initialized } = useKeycloak();

    if (!initialized) return <div>Loading...</div>;

    if (!keycloak.authenticated) {
      keycloak.login(); // redirect to Keycloak
      return null;
    }

    // Role check
    if (roles.length > 0) {
      const hasRole = roles.some(role => keycloak.hasRealmRole(role));
      if (!hasRole) return <Navigate to="/forbidden" replace />;
    }

    return <Outlet />;
  }

  // Usage:
  <Route element={<KeycloakProtectedRoute roles={['admin']} />}>
    <Route path="/admin" element={<AdminPage />} />
  </Route>

8. SENDING TOKEN TO SPRING BOOT API
================================================================

OPTION A: Manual Axios Interceptor
  import keycloak from '../keycloak';

  apiClient.interceptors.request.use(async (config) => {
    // Auto-refresh token if expired (within 30 seconds of expiry)
    if (keycloak.isTokenExpired(30)) {
      try {
        await keycloak.updateToken(30);
      } catch {
        keycloak.login();
      }
    }

    if (keycloak.token) {
      config.headers.Authorization = `Bearer ${keycloak.token}`;
    }
    return config;
  });

OPTION B: keycloak.js built-in (using keycloak.updateToken)
  The Keycloak adapter handles token refresh automatically via
  keycloak.updateToken(minValidity) — refreshes if token expires
  within minValidity seconds.

9. TOKEN CONTENT (Keycloak JWT Payload)
================================================================

  {
    "exp": 1700000000,
    "iat": 1699996400,
    "jti": "uuid-here",
    "iss": "http://localhost:8080/realms/myrealm",
    "sub": "user-uuid",
    "preferred_username": "alice",
    "email": "alice@example.com",
    "given_name": "Alice",
    "family_name": "Smith",
    "realm_access": {
      "roles": ["default-roles-myrealm", "USER", "ADMIN"]
    },
    "resource_access": {
      "react-app": {
        "roles": ["manager"]
      }
    }
  }

Access roles in React:
  keycloak.hasRealmRole('ADMIN')         // realm role
  keycloak.hasResourceRole('manager')   // client role for 'react-app'
  keycloak.tokenParsed.realm_access.roles  // all realm roles

10. SPRING BOOT CONFIGURATION FOR KEYCLOAK
================================================================

pom.xml:
  <dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-oauth2-resource-server</artifactId>
  </dependency>

application.yml:
  spring:
    security:
      oauth2:
        resourceserver:
          jwt:
            issuer-uri: http://localhost:8080/realms/myrealm
            jwk-set-uri: http://localhost:8080/realms/myrealm/protocol/openid-connect/certs

Security Config:
  @Configuration
  @EnableWebSecurity
  public class SecurityConfig {

      @Bean
      public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
          http
              .authorizeHttpRequests(auth -> auth
                  .requestMatchers("/api/public/**").permitAll()
                  .requestMatchers("/api/admin/**").hasRole("ADMIN")
                  .anyRequest().authenticated()
              )
              .oauth2ResourceServer(oauth2 -> oauth2
                  .jwt(jwt -> jwt.jwtAuthenticationConverter(jwtConverter()))
              );
          return http.build();
      }

      private JwtAuthenticationConverter jwtConverter() {
          JwtGrantedAuthoritiesConverter grantedAuthoritiesConverter =
              new JwtGrantedAuthoritiesConverter();
          grantedAuthoritiesConverter.setAuthoritiesClaimName("realm_access.roles");
          grantedAuthoritiesConverter.setAuthorityPrefix("ROLE_");

          JwtAuthenticationConverter jwtConverter = new JwtAuthenticationConverter();
          jwtConverter.setJwtGrantedAuthoritiesConverter(grantedAuthoritiesConverter);
          return jwtConverter;
      }
  }

11. KEYCLOAK EVENTS (ReactKeycloakProvider)
================================================================

  onEvent={(event, error) => {
    switch (event) {
      case 'onReady':
        // Keycloak adapter is initialized
        break;
      case 'onAuthSuccess':
        // User successfully authenticated
        break;
      case 'onAuthError':
        console.error('Auth error:', error);
        break;
      case 'onAuthRefreshSuccess':
        // Token was refreshed successfully
        break;
      case 'onAuthRefreshError':
        // Token refresh failed → log out
        keycloak.logout();
        break;
      case 'onAuthLogout':
        // User was logged out
        break;
      case 'onTokenExpired':
        keycloak.updateToken(30);
        break;
    }
  }}

12. INTERVIEW QUESTIONS
================================================================

Q: What is Keycloak and why is it used with Spring Boot?
A: Keycloak is an open-source IAM server that handles authentication,
   SSO, token issuance, and user management. Spring Boot apps configure
   themselves as OAuth2 resource servers that validate Keycloak-issued
   JWTs without implementing auth logic themselves. This is preferred
   in enterprise environments for centralized user management.

Q: How do you protect a Spring Boot endpoint with Keycloak roles?
A: Add spring-boot-starter-oauth2-resource-server. Configure the
   issuer-uri to the Keycloak realm URL. In SecurityConfig, use
   hasRole('ADMIN') with a JwtAuthenticationConverter that maps
   realm_access.roles from the JWT to Spring Security GrantedAuthorities.

Q: What is the difference between realm roles and client roles?
A: Realm roles apply across all clients in the realm (global permissions).
   Client roles are specific to a single client (app). In the JWT,
   realm roles appear in realm_access.roles, client roles in
   resource_access.{clientId}.roles.

Q: How does the Keycloak JS adapter handle token refresh?
A: Call keycloak.updateToken(minValidity) — it refreshes the access
   token if it will expire within minValidity seconds. If refresh fails
   (refresh token also expired), it rejects, and you should call
   keycloak.login() to re-authenticate. This is called in the Axios
   request interceptor before adding the Authorization header.

Q: What is check-sso vs login-required initialization mode?
A: login-required immediately redirects to Keycloak if not authenticated.
   check-sso performs a silent SSO check using an iframe — if the user
   has an existing Keycloak session (from another app), they are silently
   logged in. If not, they land on the app unauthenticated (not redirected).
   check-sso is better for apps where some pages are public.
