================================================================
WEBSOCKETS IN REACT (NATIVE WEB API)
================================================================

WebSocket provides a full-duplex, persistent connection between
the browser and server. Unlike HTTP, either side can send messages
at any time after the connection is established.

================================================================
1. WHY WEBSOCKETS?
================================================================

HTTP is request-response: the client always initiates.
For real-time features (chat, notifications, live dashboards),
HTTP requires polling (repeated requests), which is wasteful.

WebSocket solves this:
  - Single TCP connection, kept open
  - Server can push data without a client request
  - Low overhead (small frames after the initial handshake)
  - Sub-millisecond latency vs polling delays

USE CASES:
  - Live chat / messaging
  - Real-time notifications
  - Collaborative editing (Google Docs style)
  - Live dashboards / financial tickers
  - Online games
  - Live order tracking

================================================================
2. THE WEBSOCKET HANDSHAKE
================================================================

1. Client sends an HTTP Upgrade request:
   GET /ws HTTP/1.1
   Upgrade: websocket
   Connection: Upgrade
   Sec-WebSocket-Key: <base64 random key>
   Sec-WebSocket-Version: 13

2. Server responds HTTP 101 Switching Protocols

3. The connection switches to the WebSocket protocol over the
   same TCP socket. No more HTTP overhead.

WebSocket URL uses ws:// (or wss:// for TLS — always use in prod).

================================================================
3. NATIVE WEBSOCKET API
================================================================

  const ws = new WebSocket('wss://api.example.com/ws');

  // Connection opened
  ws.onopen = (event) => {
    console.log('Connected');
    ws.send(JSON.stringify({ type: 'JOIN', room: 'general' }));
  };

  // Receive message
  ws.onmessage = (event) => {
    const data = JSON.parse(event.data);
    console.log('Received:', data);
  };

  // Connection closed
  ws.onclose = (event) => {
    console.log('Disconnected', event.code, event.reason);
    // event.wasClean: true if server closed gracefully
  };

  // Error
  ws.onerror = (error) => {
    console.error('WebSocket error', error);
  };

  // Send a message
  ws.send(JSON.stringify({ type: 'MESSAGE', text: 'Hello' }));

  // Close the connection
  ws.close(1000, 'Normal closure');

WS READY STATES:
  ws.readyState
  0 = CONNECTING
  1 = OPEN
  2 = CLOSING
  3 = CLOSED

================================================================
4. WEBSOCKET IN REACT — BASIC HOOK
================================================================

  // src/hooks/useWebSocket.js
  import { useEffect, useRef, useCallback } from 'react';

  export function useWebSocket(url, { onMessage, onOpen, onClose, onError } = {}) {
    const wsRef = useRef(null);

    useEffect(() => {
      const ws = new WebSocket(url);
      wsRef.current = ws;

      ws.onopen = (event) => {
        console.log('[WS] Connected');
        onOpen?.(event);
      };

      ws.onmessage = (event) => {
        const data = JSON.parse(event.data);
        onMessage?.(data);
      };

      ws.onclose = (event) => {
        console.log('[WS] Disconnected', event.code);
        onClose?.(event);
      };

      ws.onerror = (error) => {
        console.error('[WS] Error', error);
        onError?.(error);
      };

      // CRITICAL: cleanup on unmount
      return () => {
        ws.close(1000, 'Component unmounted');
      };
    }, [url]); // reconnect if URL changes

    const send = useCallback((data) => {
      if (wsRef.current?.readyState === WebSocket.OPEN) {
        wsRef.current.send(JSON.stringify(data));
      }
    }, []);

    return { send };
  }

  // Usage
  function ChatRoom({ roomId }) {
    const [messages, setMessages] = useState([]);

    const { send } = useWebSocket(`wss://api.example.com/ws/room/${roomId}`, {
      onMessage: (data) => {
        if (data.type === 'MESSAGE') {
          setMessages(prev => [...prev, data]);
        }
      },
    });

    const sendMessage = (text) => {
      send({ type: 'MESSAGE', text });
    };
  }

5. AUTO-RECONNECTION WITH EXPONENTIAL BACKOFF
================================================================

WebSocket connections drop due to network issues.
Always implement reconnection logic in production.

  // src/hooks/useReconnectingWebSocket.js
  export function useReconnectingWebSocket(url, { onMessage } = {}) {
    const wsRef = useRef(null);
    const reconnectAttemptRef = useRef(0);
    const reconnectTimerRef = useRef(null);
    const shouldReconnectRef = useRef(true);

    const connect = useCallback(() => {
      const ws = new WebSocket(url);
      wsRef.current = ws;

      ws.onopen = () => {
        reconnectAttemptRef.current = 0; // reset on successful connect
        console.log('[WS] Connected');
      };

      ws.onmessage = (event) => {
        onMessage?.(JSON.parse(event.data));
      };

      ws.onclose = (event) => {
        if (!shouldReconnectRef.current) return;
        if (event.code === 1000) return; // normal closure, no reconnect

        const attempt = reconnectAttemptRef.current;
        const delay = Math.min(1000 * 2 ** attempt, 30000); // max 30s
        console.log(`[WS] Reconnecting in ${delay}ms (attempt ${attempt + 1})`);
        reconnectTimerRef.current = setTimeout(() => {
          reconnectAttemptRef.current += 1;
          connect();
        }, delay);
      };

      ws.onerror = (error) => {
        console.error('[WS] Error', error);
        ws.close(); // triggers onclose which triggers reconnect
      };
    }, [url, onMessage]);

    useEffect(() => {
      shouldReconnectRef.current = true;
      connect();

      return () => {
        shouldReconnectRef.current = false;
        clearTimeout(reconnectTimerRef.current);
        wsRef.current?.close(1000, 'Component unmounted');
      };
    }, [connect]);

    const send = useCallback((data) => {
      if (wsRef.current?.readyState === WebSocket.OPEN) {
        wsRef.current.send(JSON.stringify(data));
      }
    }, []);

    return { send };
  }

6. REAL-WORLD CHAT COMPONENT
================================================================

  function ChatRoom({ roomId, token }) {
    const [messages, setMessages] = useState([]);
    const [input, setInput] = useState('');

    const wsUrl = `wss://api.example.com/ws?token=${token}&room=${roomId}`;

    const { send } = useReconnectingWebSocket(wsUrl, {
      onMessage: (data) => {
        switch (data.type) {
          case 'HISTORY':
            setMessages(data.messages);
            break;
          case 'MESSAGE':
            setMessages(prev => [...prev, data]);
            break;
          case 'USER_JOINED':
            // show notification
            break;
        }
      },
    });

    const submitMessage = (e) => {
      e.preventDefault();
      if (!input.trim()) return;
      send({ type: 'MESSAGE', text: input.trim(), roomId });
      setInput('');
    };

    return (
      <div>
        <div className="messages">
          {messages.map(m => (
            <p key={m.id}><strong>{m.sender}:</strong> {m.text}</p>
          ))}
        </div>
        <form onSubmit={submitMessage}>
          <input value={input} onChange={e => setInput(e.target.value)} />
          <button type="submit">Send</button>
        </form>
      </div>
    );
  }

7. PASSING AUTH TOKEN
================================================================

WebSocket connections can't carry custom headers (like Authorization).
Two common strategies:

A) Query param (simple but URL is logged):
   wss://api.example.com/ws?token=eyJhbGc...

B) First-message auth (more secure):
   1. Connect to the WebSocket
   2. Immediately send an AUTH message as the first message
   3. Server validates before processing any other messages

  ws.onopen = () => {
    ws.send(JSON.stringify({ type: 'AUTH', token: getToken() }));
  };

SPRING BOOT (approach B):
  @Component
  public class AuthChannelInterceptor implements ChannelInterceptor {
    @Override
    public Message<?> preSend(Message<?> message, MessageChannel channel) {
      StompHeaderAccessor accessor = StompHeaderAccessor.wrap(message);
      if (StompCommand.CONNECT.equals(accessor.getCommand())) {
        String token = accessor.getFirstNativeHeader("Authorization");
        // validate token...
      }
      return message;
    }
  }

================================================================
8. WEBSOCKET CLOSE CODES
================================================================

1000 — Normal closure (intentional)
1001 — Going away (page unload)
1002 — Protocol error
1003 — Unsupported data
1006 — Abnormal closure (connection dropped, no close frame)
1008 — Policy violation (e.g., auth failed)
1011 — Server internal error
3000-3999 — Library-defined
4000-4999 — Application-defined

Always check event.code in onclose to determine if reconnection
is appropriate (not for 1000, 1008, or auth failures).

================================================================
9. INTERVIEW QUESTIONS
================================================================

Q: What is the difference between WebSocket and HTTP?
A: HTTP is request-response (client always initiates, one-time).
   WebSocket upgrades the HTTP connection to a persistent,
   full-duplex channel. After the handshake, either side can send
   data at any time. WebSocket has much lower overhead per message
   since headers are sent only once.

Q: How do you clean up a WebSocket in React?
A: Return a cleanup function from useEffect that calls
   ws.close(1000, 'reason'). This prevents memory leaks and dangling
   connections. Passing 1000 as the code ensures onclose handlers know
   it was intentional and won't try to reconnect.

Q: How do you handle WebSocket reconnection?
A: In onclose, check event.code. If not 1000 (normal) and
   shouldReconnect is true, use setTimeout with exponential backoff
   (delay = min(1000 * 2^attempt, 30000)) to retry. Reset the attempt
   counter on successful reconnection.

Q: How do you authenticate a WebSocket connection?
A: WebSocket headers can't carry Authorization. Use either (a)
   include the token as a query parameter in the URL (simple,
   but token visible in logs), or (b) send an AUTH message as the
   first message after connecting and have the server reject
   unauthenticated clients.

Q: When would you use SSE over WebSocket?
A: Server-Sent Events (SSE) when you only need server-to-client
   updates (notifications, live feeds). SSE works over plain HTTP,
   automatically reconnects, and is simpler to implement.
   Use WebSocket when you need full-duplex (client also sends data
   frequently, e.g., chat, live collaboration).
