================================================================
API INTEGRATION INTERVIEW QUESTIONS
================================================================

Deep-dive Q&A covering HTTP clients, data fetching patterns,
CORS, error handling, and React-specific API integration topics.

================================================================
SECTION 1: FUNDAMENTALS
================================================================

Q: What is CORS and why does it exist?
A: CORS (Cross-Origin Resource Sharing) is a browser security mechanism
   that blocks JavaScript from making requests to a different origin
   (domain/port/protocol) than the page it's running on.
   It exists to prevent malicious sites from making authenticated
   requests to other origins using the user's cookies/credentials.

   The browser sends a preflight OPTIONS request for non-simple requests.
   The server must respond with the correct Access-Control-Allow-Origin
   header. Spring Boot:
     @CrossOrigin or CorsConfiguration in WebSecurityConfig.
   In development, use Vite's server.proxy to avoid CORS entirely.

Q: What is the difference between a simple request and a preflight request?
A: Simple requests (no preflight): GET/HEAD/POST with Content-Type
   of text/plain, application/x-www-form-urlencoded, or multipart/form-data.
   All other requests trigger a preflight: PUT, DELETE, PATCH, any
   custom header (Authorization), Content-Type: application/json.
   The preflight OPTIONS request checks whether the server allows the
   actual request before sending it.

Q: What happens when a fetch() call gets a 404?
A: Nothing — fetch does NOT throw on HTTP error status codes.
   You must check response.ok (true for 200-299) or response.status
   and throw manually. Axios DOES throw by default for 4xx/5xx.
   This is one of the most common fetch gotchas in interviews.

Q: What is the difference between axios.create() and importing axios directly?
A: axios.create() returns a new Axios instance with its own config
   (baseURL, timeout, headers). This allows multiple API clients in
   one app (e.g., separate instances for your backend and a third-party
   API), each with their own interceptors and base configuration.
   Importing axios directly uses the global singleton.

Q: When would you use React Query vs useState + useEffect for data fetching?
A: React Query (TanStack Query) for: server state with caching,
   deduplication, stale-while-revalidate, background refetch, pagination,
   retry, mutations with optimistic updates.
   useState + useEffect for: simple one-off fetches, non-server state,
   or when you want full manual control. React Query eliminates most
   custom data-fetching boilerplate.

================================================================
SECTION 2: AXIOS & HTTP CLIENTS
================================================================

Q: Explain the Axios request and response interceptors.
A: Request interceptors run before the request is sent. Use them to
   attach auth headers, add request IDs, or transform request data.
   Response interceptors run after the response is received. Use them
   for global error handling (e.g., redirect to login on 401, show
   toast on 500), token refresh, or data transformation (camelCase).

   client.interceptors.request.use(config => { ...attach token; return config; });
   client.interceptors.response.use(null, error => { ...handle 401; });

Q: How do you handle 401 Unauthorized with automatic token refresh?
A: In the response error interceptor, check error.response?.status === 401.
   Use a flag (isRefreshing) and a queue (failedQueue) to prevent
   multiple concurrent refresh calls. While refreshing, queue all
   other 401 requests. When the refresh resolves, drain the queue
   (retry all queued requests). If refresh fails, log out.

Q: How do you cancel an Axios request?
A: Use AbortController (modern, also works with fetch):
     const controller = new AbortController();
     axios.get(url, { signal: controller.signal });
     controller.abort();
   React cleanup: store controller in a ref, call abort() in the
   useEffect return. Alternatively, use React Query which cancels
   automatically on component unmount.

Q: What is the difference between timeout and a request cancellation?
A: timeout is set in Axios config (in ms). If the server doesn't
   respond within that duration, Axios throws with code ECONNABORTED.
   Cancellation via AbortController is explicit — you decide when to
   cancel (user action, component unmount). Both produce a thrown error
   but have different error codes.

Q: How does exponential backoff work?
A: On each retry, the wait time doubles: delay = min(base * 2^attempt, maxDelay).
   Example: 1s, 2s, 4s, 8s, 16s, capped at 30s.
   Add jitter (random offset) to prevent all retried clients from
   thundering back at the same time:
     delay = delay + Math.random() * 1000

Q: What are idempotency keys and why do you use them with retries?
A: For non-idempotent operations (POST, payment creation), retrying
   can create duplicates. Send a unique Idempotency-Key header with
   each request. The server caches responses by key; retried requests
   return the cached response instead of re-executing the operation.
   Typically a UUID (crypto.randomUUID()).

================================================================
SECTION 3: REACT-SPECIFIC PATTERNS
================================================================

Q: What is the service layer pattern in React?
A: Extract API calls from components into separate service modules:
     // userService.js
     export const getUser = (id) => apiClient.get(`/users/${id}`).then(r => r.data);
   Benefits: testable (mock the service, not Axios), reusable across
   components, single place to change API endpoints, keeps components
   clean.

Q: How do you implement infinite scroll with React Query?
A: useInfiniteQuery with getNextPageParam. The query function receives
   pageParam. On scroll bottom (IntersectionObserver), call
   fetchNextPage(). The data is structured as data.pages (array of
   pages), data.pageParams. Flatten with data.pages.flatMap(p => p.items).
   hasNextPage and isFetchingNextPage for loading state.

Q: How would you implement optimistic updates?
A: With React Query useMutation:
   - onMutate: cancel in-flight queries, snapshot old data, update
     cache immediately
   - onError: rollback using the snapshot
   - onSettled: always refetch to sync with server
   This shows instant UI feedback before the server responds.

Q: How do you deduplicate API calls when multiple components need the same data?
A: React Query deduplicates automatically: multiple useQuery calls
   with the same queryKey share one HTTP request (in-flight dedup)
   and the same cache. Without React Query, lift the fetch to a parent
   component (or context) and pass data as props.

Q: How do you prefetch data in React Query?
A: queryClient.prefetchQuery({ queryKey: [...], queryFn: ... })
   — typically called on hover/focus before navigation.
   Or use the <Link onMouseEnter> pattern. React Router's loader
   also integrates with React Query prefetching.

SECTION 4: ERROR HANDLING
================================================================

Q: What layers should a React app have for error handling?
A: 
  1. Service layer: catch Axios errors, extract error message, rethrow
  2. Component level: try/catch or React Query's isError/error state
  3. Response interceptor: global handling (logout on 401, toast on 500)
  4. Error Boundary (class component): catches render errors, shows fallback UI
  5. Global unhandledrejection event: last resort for uncaught promise errors

Q: How do you map server validation errors (Spring Boot) to React Hook Form?
A: Spring Boot returns 400 with:
     { "errors": [{ "field": "email", "message": "must be valid email" }] }
   In the catch block, iterate the errors and call:
     setError(fieldName, { type: 'server', message: fieldError.message })
   React Hook Form will show field-level errors next to each input.

Q: What is an Error Boundary?
A: A class component implementing componentDidCatch() and
   getDerivedStateFromError(). It catches JavaScript errors in its
   child component tree during rendering, lifecycle methods, and event
   handlers of class components.
   It does NOT catch: async errors (setTimeout, fetch), event handler
   errors, or errors in the ErrorBoundary itself.

================================================================
SECTION 5: PERFORMANCE & SECURITY
================================================================

Q: How do you avoid the "N+1 problem" in a React app?
A: Avoid fetching related data one-by-one inside a list loop.
   Strategies: (1) API endpoint returns embedded/nested data,
   (2) batch endpoint (POST /users/batch with IDs array), (3) GraphQL
   (request only what you need in one query), (4) React Query parallel
   queries (useQueries) to parallelize but still make N calls.

Q: How do you secure API keys/tokens in a React SPA?
A: You cannot fully secure secrets in a SPA (code is in the browser).
   Best practices: (1) store tokens in memory (not localStorage),
   (2) use httpOnly cookies for refresh tokens, (3) keep sensitive
   API keys on the backend (BFF pattern), (4) use short-lived tokens
   with refresh rotation, (5) rate limit the backend API.

Q: What is the Backend for Frontend (BFF) pattern?
A: A dedicated backend layer for the React app. Instead of React
   calling third-party APIs directly (exposing secrets), it calls
   the BFF, which holds all secrets and makes backend calls server-side.
   Benefits: hides secrets, shapes API responses for the frontend,
   handles server-side token exchange, simplifies frontend API calls.

Q: How does the Stale-While-Revalidate caching strategy work?
A: Return cached (stale) data immediately, then fetch fresh data in
   the background and update the UI when it arrives.
   React Query's staleTime controls when data is considered stale.
   Default staleTime is 0 (always stale = always refetch on focus).
   Set staleTime: 1000 * 60 to keep data fresh for 1 minute.

Q: How do you handle rate limiting (HTTP 429)?
A: Check error.response?.status === 429 in the interceptor.
   Read the Retry-After header for how long to wait.
   Implement a delay using setTimeout and then retry the request.
   Use axios-retry with retryCondition checking for 429.
