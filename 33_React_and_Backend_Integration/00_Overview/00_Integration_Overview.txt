================================================================
REACT AND BACKEND INTEGRATION — OVERVIEW
================================================================

WHAT IS REACT-BACKEND INTEGRATION?
------------------------------------
React is a frontend UI library. It has no built-in mechanism to talk
to a server. Integration refers to the collection of patterns, protocols,
libraries, and techniques used to connect a React application to one or
more backend services (REST APIs, GraphQL servers, WebSocket endpoints,
gRPC services, etc.).

Understanding integration is critical for senior/full-stack interviews
because it spans both ends of the stack.

================================================================
1. THE BIG PICTURE — HOW REACT TALKS TO A BACKEND
================================================================

  Browser (React App)
       │
       │  HTTP / WebSocket / SSE / gRPC-Web
       ▼
  Backend API  (Spring Boot / Node.js / Django / Go …)
       │
       │  JDBC / ORM / message broker / cache
       ▼
  Databases / Message Queues / External Services

Key insight: React never talks directly to a database. It only speaks
to an API layer over a network protocol.

3. DATA FLOW IN A TYPICAL CRUD OPERATION
================================================================

User clicks "Submit" in a React form
  ➜ React component calls a service function (e.g. createUser(data))
  ➜ Service uses Axios/fetch to POST /api/users with JSON body
      Headers: Content-Type: application/json, Authorization: Bearer <token>
  ➜ Browser sends HTTP request (CORS preflight if cross-origin)
  ➜ Spring Boot controller receives request, validates, persists
  ➜ Controller returns HTTP 201 with JSON body
  ➜ Axios resolves the Promise, returns response.data
  ➜ React state is updated (useState / Redux / React Query cache)
  ➜ UI re-renders to show the newly created resource

4. CORE CONCERNS IN FRONTEND-BACKEND INTEGRATION
================================================================

A) NETWORK LAYER
   - Choosing HTTP client (fetch vs Axios vs ky)
   - Request/Response interceptors
   - Base URL configuration per environment
   - Timeout and retry policies

B) AUTHENTICATION & AUTHORIZATION
   - Where to store tokens (memory vs localStorage vs cookie)
   - Sending tokens on every request (interceptors)
   - Token refresh flow
   - Role-based UI rendering

C) STATE MANAGEMENT OF SERVER DATA
   - Caching, de-duplication, background refresh
   - React Query (TanStack Query) / SWR / Apollo Client
   - Optimistic updates

D) ERROR HANDLING
   - Network errors vs HTTP errors (4xx, 5xx)
   - User-visible error messages
   - Retry logic

E) REAL-TIME COMMUNICATION
   - WebSocket (bi-directional)
   - Server-Sent Events (one-way push)
   - Long polling (fallback)

F) FILE OPERATIONS
   - Multipart upload, progress tracking
   - Blob download

G) SECURITY
   - CORS understanding (server-side config but frontend must know it)
   - CSRF tokens when using cookies
   - Content Security Policy awareness
   - Never trust client-side data

5. ENVIRONMENT STRATEGY (Very common interview question)
================================================================

React apps typically need different API base URLs per environment:

  Development  → http://localhost:8080/api
  Staging      → https://staging.example.com/api
  Production   → https://api.example.com/api

This is solved with:
  - .env files  (.env, .env.development, .env.production)
  - Environment variables prefixed with REACT_APP_ (CRA)
    or VITE_ (Vite)
  - Build-time injection: process.env.REACT_APP_API_URL

Example .env.production:
  REACT_APP_API_URL=https://api.example.com

Example usage:
  const apiClient = axios.create({
    baseURL: process.env.REACT_APP_API_URL,
  });

6. THE REQUEST LIFECYCLE — STEP BY STEP
================================================================

Step 1: Component renders, triggers data fetch
  - In useEffect or via React Query's useQuery hook
  - Or on user interaction (form submit, button click)

Step 2: API service function is called
  - Thin wrapper over Axios/fetch
  - Adds no business logic — only shapes the request

Step 3: HTTP client sends request
  - Request interceptor attaches Authorization header
  - Timeout is applied
  - CORS preflight (OPTIONS) may fire if cross-origin

Step 4: Response arrives
  - Response interceptor checks for 401 → triggers token refresh
  - On 5xx → retry logic kicks in (if configured)
  - On success → data is returned to caller

Step 5: State update
  - Component state, global store, or React Query cache updated
  - React schedules a re-render

Step 6: UI update
  - New data is displayed
  - Loading spinners hidden, error banners shown if needed

7. CROSS-CUTTING CONCERNS
================================================================

A) LOADING STATES
   Every async operation needs three states: loading, success, error.
   Pattern:
     const [data, setData] = useState(null);
     const [loading, setLoading] = useState(false);
     const [error, setError] = useState(null);

   Better pattern: React Query handles all three automatically.

B) CORS
   Cross-Origin Resource Sharing is a browser security mechanism.
   When React (localhost:3000) calls API (localhost:8080), the browser
   sends an OPTIONS preflight. The backend MUST respond with:
     Access-Control-Allow-Origin: http://localhost:3000
     Access-Control-Allow-Methods: GET, POST, PUT, DELETE
     Access-Control-Allow-Headers: Content-Type, Authorization

   Spring Boot: @CrossOrigin or global CORS config in WebMvcConfigurer
   Node.js: cors() middleware

C) SECURITY HEADERS
   When using JWT in Authorization header → not vulnerable to CSRF.
   When using cookies → MUST implement CSRF protection.

8. INTERVIEW TIPS
================================================================

Q: How do you manage API calls in a large React application?
A: Centralize all API calls in a /services or /api directory.
   Use Axios with a configured instance (base URL, interceptors).
   Use React Query for server-state management (caching, refetching).
   Never make raw fetch() calls inside components.

Q: What happens when a token expires mid-session?
A: The API returns 401. A response interceptor in Axios catches this,
   uses the refresh token to obtain a new access token, then retries
   the original request transparently.

Q: How do you prevent race conditions in React data fetching?
A: Use cleanup functions in useEffect or AbortController to cancel
   in-flight requests when the component unmounts or deps change.
   React Query handles this automatically.

Q: What is the difference between client-state and server-state?
A: Client state = UI state (modal open/close, form input values).
   Server state = data fetched from backend (users list, order).
   Server state has extra complexity: caching, staleness, background sync.
   React Query / SWR are specifically designed for server state.

================================================================

Concern              | Solution
---------------------|----------------------------------------------
HTTP calls           | Axios (configured instance)
Server state         | React Query / SWR
Auth token           | httpOnly cookie (preferred) or memory

Error handling       | Interceptors + Error Boundary

gRPC from browser    | gRPC-Web + protobuf JS
GraphQL              | Apollo Client / urql
