SPRING CLOUD GATEWAY — IN-DEPTH GUIDE
================================================================================

OVERVIEW
--------
Spring Cloud Gateway (SCG) is a reactive, non-blocking API Gateway and proxy
built on Spring WebFlux, Project Reactor, and Netty.

Key properties:
  - Built on Project Reactor (reactive, non-blocking)
  - Runs on Netty (not Servlet containers like Tomcat)
  - Replaces Netflix Zuul (which was blocking/servlet-based)
  - Tight Spring Boot ecosystem integration (Actuator, Eureka, Resilience4j)

IMPORTANT: Spring Cloud Gateway runs on Spring WebFlux.
           DO NOT add spring-boot-starter-web (it's incompatible).
           Use spring-boot-starter-webflux.

CORE CONCEPTS
==============

ROUTE:
  The basic unit of configuration. A route has:
  - id: Unique identifier
  - uri: Downstream service URI
  - predicates: When to apply this route
  - filters: What to do to request/response

PREDICATE:
  A condition that a request must match for the route to be applied.
  Built-in predicates: Path, Method, Header, Host, Query, Cookie,
                       Before/After/Between (time), Weight, RemoteAddr

FILTER:
  Processing applied to request (pre) or response (post).
  Built-in filters: AddRequestHeader, RemoveRequestHeader, StripPrefix,
                    RewritePath, RequestRateLimiter, CircuitBreaker,
                    Retry, RequestSize, SetStatus, DedupeResponseHeader

COMPLETE APPLICATION.YML
==========================

server:
  port: 8080

spring:
  application:
    name: api-gateway
  data:
    redis:
      host: localhost
      port: 6379
  cloud:
    gateway:
      # Global filters applied to every route
      default-filters:
        - DedupeResponseHeader=Access-Control-Allow-Credentials Access-Control-Allow-Origin
        - name: RequestRateLimiter
          args:
            redis-rate-limiter.replenishRate: 100
            redis-rate-limiter.burstCapacity: 200
            key-resolver: "#{@ipKeyResolver}"

      # CORS
      globalcors:
        cors-configurations:
          '[/**]':
            allowedOrigins:
              - "https://myapp.com"
              - "http://localhost:3000"
            allowedMethods: [GET, POST, PUT, DELETE, OPTIONS]
            allowedHeaders: ["*"]
            exposedHeaders: [Authorization]
            maxAge: 3600

      # Routes
      routes:
        # Order Service
        - id: order-service
          uri: lb://order-service              # lb:// = load-balanced via Eureka
          predicates:
            - Path=/api/v1/orders/**
          filters:
            - StripPrefix=2                    # /api/v1/orders → /orders
            - AddRequestHeader=X-Gateway, true
            - name: CircuitBreaker
              args:
                name: orderServiceCB
                fallbackUri: forward:/fallback/orders
            - name: Retry
              args:
                retries: 3
                statuses: BAD_GATEWAY,SERVICE_UNAVAILABLE
                backoff:
                  firstBackoff: 100ms
                  maxBackoff: 500ms

        # Inventory Service (v2 with header)
        - id: inventory-service-v2
          uri: lb://inventory-service-v2
          predicates:
            - Path=/api/v2/inventory/**
            - Header=X-Feature-Flag, new-inventory
          filters:
            - StripPrefix=2

        # User Service — strip and rewrite path
        - id: user-service
          uri: lb://user-service
          predicates:
            - Path=/api/v1/users/**
          filters:
            - RewritePath=/api/v1/users/(?<segment>.*), /users/$\{segment}

        # Canary: 10% traffic to payment-service-v2
        - id: payment-service-v2
          uri: lb://payment-service-v2
          predicates:
            - Path=/api/v1/payments/**
            - Weight=payment-group, 10
        - id: payment-service-v1
          uri: lb://payment-service
          predicates:
            - Path=/api/v1/payments/**
            - Weight=payment-group, 90

# Eureka config
eureka:
  client:
    service-url:
      defaultZone: http://eureka-server:8761/eureka/

# Resilience4j Circuit Breaker
resilience4j:
  circuitbreaker:
    instances:
      orderServiceCB:
        slidingWindowSize: 10
        failureRateThreshold: 50
        waitDurationInOpenState: 10s

# Actuator
management:
  endpoints:
    web:
      exposure:
        include: gateway,health,info,metrics
  endpoint:
    gateway:
      enabled: true

PROGRAMMATIC CONFIGURATION (Java)
===================================
@Configuration
public class GatewayConfig {

  @Bean
  public RouteLocator customRouteLocator(RouteLocatorBuilder builder) {
    return builder.routes()
      .route("order-service", r -> r
        .path("/api/v1/orders/**")
        .and().method(HttpMethod.GET, HttpMethod.POST)
        .filters(f -> f
          .stripPrefix(2)
          .addRequestHeader("X-Correlation-Id", UUID.randomUUID().toString())
          .circuitBreaker(c -> c
            .setName("orderCB")
            .setFallbackUri("forward:/fallback/orders")
          )
          .retry(retryConfig -> retryConfig
            .setRetries(3)
            .setStatuses(HttpStatus.BAD_GATEWAY, HttpStatus.SERVICE_UNAVAILABLE)
          )
        )
        .uri("lb://order-service")
      )
      .build();
  }
}

CUSTOM GLOBAL FILTER (JWT AUTHENTICATION)
==========================================
@Component
@Order(-1)  // Run before routing (highest priority)
public class AuthenticationFilter implements GlobalFilter {

  private static final String AUTH_HEADER = HttpHeaders.AUTHORIZATION;
  private final JwtService jwtService;

  // These paths don't require authentication
  private final List<String> openPaths = List.of(
    "/api/v1/auth/login",
    "/api/v1/auth/register",
    "/actuator/health"
  );

  @Override
  public Mono<Void> filter(ServerWebExchange exchange, GatewayFilterChain chain) {
    String path = exchange.getRequest().getURI().getPath();

    if (openPaths.stream().anyMatch(path::startsWith)) {
      return chain.filter(exchange);  // Skip auth for open paths
    }

    String authHeader = exchange.getRequest().getHeaders().getFirst(AUTH_HEADER);

    if (authHeader == null || !authHeader.startsWith("Bearer ")) {
      return onError(exchange, HttpStatus.UNAUTHORIZED, "Missing or invalid token");
    }

    String token = authHeader.substring(7);

    return Mono.fromCallable(() -> jwtService.validateAndExtract(token))
      .flatMap(claims -> {
        // Enrich request with user context for downstream services
        ServerHttpRequest mutatedRequest = exchange.getRequest().mutate()
          .header("X-User-Id", claims.getSubject())
          .header("X-User-Email", claims.get("email", String.class))
          .header("X-User-Roles", String.join(",", claims.get("roles", List.class)))
          .build();
        return chain.filter(exchange.mutate().request(mutatedRequest).build());
      })
      .onErrorResume(JwtException.class, e ->
        onError(exchange, HttpStatus.UNAUTHORIZED, "Invalid token: " + e.getMessage())
      );
  }

  private Mono<Void> onError(ServerWebExchange exchange, HttpStatus status, String message) {
    exchange.getResponse().setStatusCode(status);
    exchange.getResponse().getHeaders().setContentType(MediaType.APPLICATION_JSON);
    String body = String.format("{\"error\":\"%s\",\"status\":%d}", message, status.value());
    DataBuffer buffer = exchange.getResponse()
        .bufferFactory().wrap(body.getBytes(StandardCharsets.UTF_8));
    return exchange.getResponse().writeWith(Mono.just(buffer));
  }
}

RATE LIMITING CONFIGURATION
=============================
@Bean
public KeyResolver ipKeyResolver() {
  // Rate limit by IP address
  return exchange -> Mono.just(
    exchange.getRequest().getRemoteAddress().getAddress().getHostAddress()
  );
}

@Bean
public KeyResolver userKeyResolver() {
  // Rate limit by user ID (from JWT, injected by auth filter)
  return exchange -> Mono.justOrEmpty(
    exchange.getRequest().getHeaders().getFirst("X-User-Id")
  ).defaultIfEmpty("anonymous");
}

@Bean
public KeyResolver apiKeyResolver() {
  // Rate limit by API key
  return exchange -> Mono.justOrEmpty(
    exchange.getRequest().getHeaders().getFirst("X-API-Key")
  ).defaultIfEmpty("unknown");
}

FALLBACK CONTROLLER
====================
@RestController
public class FallbackController {

  @GetMapping("/fallback/orders")
  public ResponseEntity<Map<String, String>> ordersFallback(ServerWebExchange exchange) {
    return ResponseEntity.status(HttpStatus.SERVICE_UNAVAILABLE).body(Map.of(
      "status", "error",
      "message", "Order service is temporarily unavailable. Please try again later.",
      "timestamp", Instant.now().toString()
    ));
  }

  @PostMapping("/fallback/payments")
  public ResponseEntity<Map<String, String>> paymentsFallback() {
    return ResponseEntity.status(HttpStatus.SERVICE_UNAVAILABLE).body(Map.of(
      "status", "error",
      "message", "Payment service is temporarily unavailable."
    ));
  }
}

INTERVIEW QUESTIONS
====================

Q: What's the difference between Spring Cloud Gateway and Netflix Zuul?
A: Zuul 1 is blocking/servlet-based (synchronous threading model), while SCG is
   reactive/non-blocking built on Netty and WebFlux. SCG handles many more
   concurrent connections with the same hardware. Zuul 2 is reactive but has
   much less Spring ecosystem integration.

Q: How do you implement circuit breaking in Spring Cloud Gateway?
A: Using the CircuitBreaker filter (integrates with Resilience4j). Configure on
   a route with a name and fallbackUri. Define circuit breaker settings in
   resilience4j configuration. When the circuit opens, requests are forwarded to
   the fallback endpoint instead.

Q: How do you handle authentication centrally in Spring Cloud Gateway?
A: Implement a GlobalFilter that intercepts all requests (except open paths).
   Validate the JWT token, extract user claims, and inject them as request headers
   (X-User-Id, X-User-Roles). Downstream services trust these headers. Reject
   requests with 401 if token is missing or invalid.

Q: How do you do canary deployments with Spring Cloud Gateway?
A: Use the Weight predicate to split traffic between route groups. For example,
   Weight=payment-group,10 routes 10% to v2 and Weight=payment-group,90 routes
   90% to v1. Gradually increase the weight as confidence in v2 grows.

Q: What are the core building blocks of Spring Cloud Gateway?
A: Routes (the what — destination + rules), Predicates (the when — conditions
   to match), and Filters (the how — pre/post processing). Routes are composed
   of a URI, one or more predicates, and zero or more filters.
