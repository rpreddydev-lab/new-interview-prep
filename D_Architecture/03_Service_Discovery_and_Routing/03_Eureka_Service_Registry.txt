EUREKA SERVICE REGISTRY
================================================================================

WHAT IS EUREKA?
---------------
Netflix Eureka is a REST-based service that provides service discovery for
microservices. Services register themselves with the Eureka server, and other
services query Eureka to find registered service instances.

Part of the Netflix OSS stack, integrated into Spring Cloud Netflix.

Key components:
  - Eureka Server: The registry (holds all service registrations)
  - Eureka Client: Embedded in each microservice (registers, discovers)

HOW EUREKA WORKS — STEP BY STEP
=================================

1. STARTUP REGISTRATION
   Service starts → Eureka Client sends POST /eureka/apps/{appName}
   Registers: {
     "hostName": "10.0.0.5",
     "app": "ORDER-SERVICE",
     "ipAddr": "10.0.0.5",
     "port": { "$": 8080 },
     "status": "UP",
     "dataCenterInfo": { ... }
   }

2. HEARTBEAT / RENEWAL
   Every 30 seconds (default): Eureka Client sends PUT /eureka/apps/{appName}/{instanceId}
   If Eureka Server doesn't receive heartbeat for 90 seconds → instance marked DOWN
   Configurable: eureka.instance.lease-renewal-interval-in-seconds: 30
                 eureka.instance.lease-expiration-duration-in-seconds: 90

3. DISCOVERY / FETCH REGISTRY
   Consuming service fetches registry from Eureka every 30 seconds (default)
   Caches the list locally
   Uses cached list for actual calls
   Configurable: eureka.client.registry-fetch-interval-seconds: 30

4. DEREGISTRATION
   Service shuts down (graceful) → Eureka Client sends DELETE
   Eureka marks instance as DOWN immediately

5. SELF-PRESERVATION MODE
   If Eureka receives fewer heartbeats than expected (network partition):
   Eureka enters "self-preservation" mode — does NOT evict instances
   This prevents evicting healthy instances due to a temporary network issue
   Can be disabled for local dev: eureka.server.enable-self-preservation: false

EUREKA SERVER SETUP
====================

Dependencies (pom.xml):
  <dependency>
    <groupId>org.springframework.cloud</groupId>
    <artifactId>spring-cloud-starter-netflix-eureka-server</artifactId>
  </dependency>

Application:
  @SpringBootApplication
  @EnableEurekaServer
  public class EurekaServerApplication {
    public static void main(String[] args) {
      SpringApplication.run(EurekaServerApplication.class, args);
    }
  }

application.yml (standalone single-node Eureka):
  server:
    port: 8761
  spring:
    application:
      name: eureka-server
  eureka:
    client:
      register-with-eureka: false   # Don't register itself
      fetch-registry: false         # Don't fetch its own registry
    server:
      enable-self-preservation: false  # Disable for dev/test
      eviction-interval-timer-in-ms: 5000

Access Eureka Dashboard: http://localhost:8761

EUREKA CLIENT SETUP
====================

Dependencies:
  <dependency>
    <groupId>org.springframework.cloud</groupId>
    <artifactId>spring-cloud-starter-netflix-eureka-client</artifactId>
  </dependency>

Application:
  @SpringBootApplication
  @EnableDiscoveryClient  // or @EnableEurekaClient (same effect)
  public class OrderServiceApplication { ... }

application.yml:
  spring:
    application:
      name: order-service        # Service name used in Eureka registry

  eureka:
    client:
      service-url:
        defaultZone: http://eureka-server:8761/eureka/
      registry-fetch-interval-seconds: 30
    instance:
      prefer-ip-address: true    # Register with IP instead of hostname
      lease-renewal-interval-in-seconds: 30
      lease-expiration-duration-in-seconds: 90
      # Custom instance metadata
      metadata-map:
        version: "1.0.0"
        zone: "us-east"

SERVICE-TO-SERVICE CALLS WITH EUREKA
======================================

Option 1: @LoadBalanced RestTemplate
  @Configuration
  public class AppConfig {
    @Bean
    @LoadBalanced
    public RestTemplate restTemplate() { return new RestTemplate(); }
  }

  @Service
  public class InventoryClient {
    @Autowired private RestTemplate restTemplate;

    public InventoryDTO checkInventory(Long productId) {
      // "inventory-service" resolved via Eureka → actual IP:port
      return restTemplate.getForObject(
        "http://inventory-service/api/v1/inventory/{id}",
        InventoryDTO.class, productId
      );
    }
  }

Option 2: @LoadBalanced WebClient (reactive)
  @Bean
  @LoadBalanced
  public WebClient.Builder loadBalancedWebClientBuilder() {
    return WebClient.builder();
  }

  @Service
  public class InventoryClient {
    private final WebClient webClient;

    public InventoryClient(WebClient.Builder builder) {
      this.webClient = builder.baseUrl("http://inventory-service").build();
    }

    public Mono<InventoryDTO> checkInventory(Long productId) {
      return webClient.get()
        .uri("/api/v1/inventory/{id}", productId)
        .retrieve()
        .bodyToMono(InventoryDTO.class);
    }
  }

Option 3: Spring Cloud OpenFeign (declarative HTTP client)
  @FeignClient(name = "inventory-service")
  public interface InventoryClient {
    @GetMapping("/api/v1/inventory/{id}")
    InventoryDTO getInventory(@PathVariable("id") Long productId);
  }

  // Usage:
  @Autowired InventoryClient inventoryClient;
  InventoryDTO inv = inventoryClient.getInventory(123L);

  // Feign resolves "inventory-service" via Eureka automatically

OPENFEIGN IN DEPTH
===================

Dependencies:
  <dependency>
    <groupId>org.springframework.cloud</groupId>
    <artifactId>spring-cloud-starter-openfeign</artifactId>
  </dependency>

Enable:
  @EnableFeignClients
  @SpringBootApplication
  public class OrderServiceApplication { ... }

Full example with error handling and timeout:
  @FeignClient(
    name = "payment-service",
    fallback = PaymentClientFallback.class  // Circuit Breaker fallback
  )
  public interface PaymentClient {

    @PostMapping("/api/v1/payments")
    @Headers("Content-Type: application/json")
    PaymentDTO processPayment(@RequestBody PaymentRequest request);

    @GetMapping("/api/v1/payments/{id}")
    PaymentDTO getPayment(@PathVariable("id") Long paymentId);
  }

  // Fallback class (used when service is down / circuit open)
  @Component
  public class PaymentClientFallback implements PaymentClient {
    @Override
    public PaymentDTO processPayment(PaymentRequest request) {
      // Return a default or cached response
      return new PaymentDTO(null, "PENDING", "Payment service unavailable");
    }

    @Override
    public PaymentDTO getPayment(Long paymentId) {
      return new PaymentDTO(paymentId, "UNKNOWN", "Payment service unavailable");
    }
  }

Feign configuration:
  feign:
    client:
      config:
        payment-service:
          connect-timeout: 3000
          read-timeout: 5000
          logger-level: FULL   # NONE, BASIC, HEADERS, FULL
    circuitbreaker:
      enabled: true            # Integrate with Resilience4j

HIGH AVAILABILITY EUREKA
=========================

Peer-aware Eureka cluster (3 nodes for HA):

  eureka-server-1 ←→ eureka-server-2 ←→ eureka-server-3

Each Eureka server registers with the others:
  # eureka-server-1
  eureka:
    client:
      service-url:
        defaultZone: http://eureka-server-2:8761/eureka/,
                     http://eureka-server-3:8761/eureka/

  # eureka-server-2
  eureka:
    client:
      service-url:
        defaultZone: http://eureka-server-1:8761/eureka/,
                     http://eureka-server-3:8761/eureka/

Clients register with all Eureka servers:
  eureka:
    client:
      service-url:
        defaultZone: http://eureka-1:8761/eureka/,
                     http://eureka-2:8761/eureka/,
                     http://eureka-3:8761/eureka/

CAP properties of Eureka:
  - AP system (Availability + Partition Tolerance) — NOT consistent
  - Prefers availability over consistency
  - During network partition: Eureka keeps serving stale data rather than failing
  - Consul is CP (Consistent + Partition Tolerant)

EUREKA vs CONSUL vs KUBERNETES
================================

Feature              │ Eureka               │ Consul               │ Kubernetes
─────────────────────┼──────────────────────┼──────────────────────┼──────────────────
Language             │ Java-centric         │ Polyglot             │ Any (built-in)
Protocol             │ HTTP/REST            │ HTTP/DNS/gRPC        │ DNS + kube-proxy
Health checks        │ Heartbeat            │ HTTP/TCP/script      │ Probes
Config management    │ No (use Config Server)│ Yes (KV store)      │ ConfigMap/Secrets
Service mesh         │ No                   │ Yes (Consul Connect) │ Istio/Linkerd
CAP                  │ AP                   │ CP                   │ -
Kubernetes native    │ No (extra setup)     │ No (extra setup)     │ Yes (built-in)
Best for             │ Spring Boot/Java     │ Polyglot enterprise  │ K8s-native apps

INTERVIEW QUESTIONS
====================

Q: How does Eureka work?
A: Services register with Eureka Server on startup, sending their IP/port and
   metadata. They send heartbeats every 30s. Consuming services fetch the
   registry every 30s and cache it locally. @LoadBalanced clients resolve
   service names to IPs via this cache. Instances missing heartbeats for
   90s are evicted.

Q: What is Eureka's Self-Preservation mode?
A: If Eureka receives fewer renewals than expected (15% threshold), it enters
   self-preservation — stops evicting instances. This avoids mass eviction
   during temporary network issues. Disable in dev/test but keep enabled in prod.

Q: What is OpenFeign and how does it use Eureka?
A: OpenFeign is a declarative HTTP client. You define an interface with
   annotations matching the target service's API. @FeignClient(name="service-name")
   tells Feign to resolve the service name via Eureka and make load-balanced
   HTTP calls. It integrates with Resilience4j for circuit breaking and fallbacks.

Q: What's the difference between Eureka and Consul?
A: Eureka is Java-centric, AP system (available during partitions), heartbeat-
   based. Consul is polyglot, CP system (consistent), supports health checks,
   KV store for config, and has built-in service mesh (Consul Connect).
