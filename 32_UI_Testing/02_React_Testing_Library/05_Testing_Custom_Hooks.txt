1. WHY TEST CUSTOM HOOKS SEPARATELY
================================================================================

Custom hooks encapsulate reusable logic. Testing them directly lets you:
  - Verify the hook logic in isolation (without a component's render output)
  - Test all edge cases: initial state, state transitions, error states
  - Faster feedback — no need to render a UI to test logic

ALTERNATIVES TO renderHook:
  Option A: Test hooks via the component that uses them (indirect testing)
    ✅ Tests real integration
    ❌ Harder to test all hook states — tied to component rendering

  Option B: renderHook() (direct testing)
    ✅ Clean, focused tests for the hook logic
    ✅ Test every return value, every argument combination
    ✅ Best for: useCounter, useFetch, useLocalStorage, useDebounce, etc.

RULE OF THUMB:
  Simple hooks that are tightly coupled to one component → test via the component
  Reusable hooks in src/hooks/ → test directly with renderHook()

2. RENDERHOOK() — THE API
================================================================================

IMPORT:
  import { renderHook, act } from '@testing-library/react';

SYNTAX:
  const { result, rerender, unmount } = renderHook(hookFn, options?);

RETURN VALUES:
  result.current    → The current return value of the hook
  rerender(options) → Re-render the hook with new arguments
  unmount()         → Unmount the hook (triggers cleanup effects)

BASIC EXAMPLE — useCounter hook:
  // src/hooks/useCounter.ts
  function useCounter(initialValue = 0) {
    const [count, setCount] = useState(initialValue);
    const increment = () => setCount(c => c + 1);
    const decrement = () => setCount(c => c - 1);
    const reset = () => setCount(initialValue);
    return { count, increment, decrement, reset };
  }

  // src/hooks/useCounter.test.ts
  import { renderHook, act } from '@testing-library/react';
  import { useCounter } from './useCounter';

  describe('useCounter', () => {
    it('initializes with 0 by default', () => {
      const { result } = renderHook(() => useCounter());
      expect(result.current.count).toBe(0);
    });

    it('initializes with custom value', () => {
      const { result } = renderHook(() => useCounter(5));
      expect(result.current.count).toBe(5);
    });

    it('increments count', () => {
      const { result } = renderHook(() => useCounter());
      act(() => result.current.increment());
      expect(result.current.count).toBe(1);
    });

    it('decrements count', () => {
      const { result } = renderHook(() => useCounter(3));
      act(() => result.current.decrement());
      expect(result.current.count).toBe(2);
    });

    it('resets count to initial value', () => {
      const { result } = renderHook(() => useCounter(10));
      act(() => {
        result.current.increment();
        result.current.increment();
      });
      expect(result.current.count).toBe(12);
      act(() => result.current.reset());
      expect(result.current.count).toBe(10);
    });
  });

3. RENDERHOOK() WITH ACT()
================================================================================

State-updating operations (calling setters, calling functions that call setters)
MUST be wrapped in act() so React processes the state update.

WHY ACT() IS NEEDED:
  Without act(), React batches updates and result.current is still stale.
  act() flushes all pending state updates and effects.

SYNC STATE UPDATES → sync act():
  act(() => result.current.increment());
  expect(result.current.count).toBe(1); // Safe to read after act()

MULTIPLE UPDATES IN ONE act():
  act(() => {
    result.current.increment();
    result.current.increment();
    result.current.increment();
  });
  expect(result.current.count).toBe(3);

ASYNC STATE UPDATES → async act():
  it('fetches data', async () => {
    const { result } = renderHook(() => useFetch('/api/users'));

    expect(result.current.loading).toBe(true);

    await act(async () => {
      await Promise.resolve(); // Let pending promises resolve
    });

    expect(result.current.loading).toBe(false);
    expect(result.current.data).toEqual([{ id: 1, name: 'Alice' }]);
  });

USING waitFor INSTEAD OF ACT (often cleaner for async):
  import { renderHook, waitFor } from '@testing-library/react';

  it('fetches users', async () => {
    const { result } = renderHook(() => useFetch('/api/users'));

    await waitFor(() => {
      expect(result.current.loading).toBe(false);
    });

    expect(result.current.data).toHaveLength(2);
  });

RTL AUTO-WRAPS IN act() FOR COMMON OPERATIONS:
  waitFor, findBy* — these already wrap in act()
  So async hooks testing usually works best with waitFor.

4. TESTING HOOKS WITH ARGUMENTS (initialProps)
================================================================================

initialProps lets you pass initial arguments to the hook and change them via rerender.

SYNTAX:
  const { result, rerender } = renderHook(
    ({ initialValue }) => useCounter(initialValue),
    { initialProps: { initialValue: 5 } }
  );

RERENDER WITH NEW PROPS:
  rerender({ initialValue: 10 }); // Does NOT reset hook — just re-runs
  // NOTE: rerender with new initialProps changes what's passed to the hook
  // The hook's existing state persists (it's not a fresh render)

EXAMPLE — usePrevious hook:
  function usePrevious(value) {
    const ref = useRef(null);
    useEffect(() => { ref.current = value; }, [value]);
    return ref.current;
  }

  it('returns previous value', () => {
    const { result, rerender } = renderHook(
      ({ value }) => usePrevious(value),
      { initialProps: { value: 'first' } }
    );

    expect(result.current).toBeNull(); // No previous value yet

    rerender({ value: 'second' });
    expect(result.current).toBe('first'); // Previous was 'first'

    rerender({ value: 'third' });
    expect(result.current).toBe('second'); // Previous was 'second'
  });

EXAMPLE — useSort hook:
  const { result, rerender } = renderHook(
    ({ data, key }) => useSort(data, key),
    { initialProps: { data: [3, 1, 2], key: 'asc' } }
  );

  expect(result.current).toEqual([1, 2, 3]);

  rerender({ data: [3, 1, 2], key: 'desc' });
  expect(result.current).toEqual([3, 2, 1]);

5. TESTING HOOKS THAT UPDATE STATE
================================================================================

EXAMPLE — useToggle:
  function useToggle(initial = false) {
    const [state, setState] = useState(initial);
    const toggle = useCallback(() => setState(s => !s), []);
    const setOn = useCallback(() => setState(true), []);
    const setOff = useCallback(() => setState(false), []);
    return { state, toggle, setOn, setOff };
  }

  describe('useToggle', () => {
    it('starts false by default', () => {
      const { result } = renderHook(() => useToggle());
      expect(result.current.state).toBe(false);
    });

    it('toggles state', () => {
      const { result } = renderHook(() => useToggle());
      act(() => result.current.toggle());
      expect(result.current.state).toBe(true);
      act(() => result.current.toggle());
      expect(result.current.state).toBe(false);
    });

    it('sets on and off', () => {
      const { result } = renderHook(() => useToggle());
      act(() => result.current.setOn());
      expect(result.current.state).toBe(true);
      act(() => result.current.setOff());
      expect(result.current.state).toBe(false);
    });

    it('starts with custom initial value', () => {
      const { result } = renderHook(() => useToggle(true));
      expect(result.current.state).toBe(true);
    });
  });

EXAMPLE — useLocalStorage:
  describe('useLocalStorage', () => {
    beforeEach(() => window.localStorage.clear());

    it('reads initial value', () => {
      const { result } = renderHook(() => useLocalStorage('key', 'default'));
      expect(result.current[0]).toBe('default');
    });

    it('updates stored value', () => {
      const { result } = renderHook(() => useLocalStorage('key', ''));
      act(() => result.current[1]('new value'));
      expect(result.current[0]).toBe('new value');
      expect(window.localStorage.getItem('key')).toBe('"new value"');
    });

    it('reads from localStorage if already set', () => {
      window.localStorage.setItem('myKey', JSON.stringify('existing'));
      const { result } = renderHook(() => useLocalStorage('myKey', 'default'));
      expect(result.current[0]).toBe('existing');
    });
  });

6. TESTING HOOKS WITH SIDE EFFECTS (useEffect)
================================================================================

Hooks with useEffect need careful handling — RTL wraps render and updates in act()
but you may need to explicitly wait for effects to complete.

EXAMPLE — useDocumentTitle:
  function useDocumentTitle(title) {
    useEffect(() => {
      document.title = title;
      return () => { document.title = 'App'; }; // Cleanup
    }, [title]);
  }

  it('sets document title', () => {
    renderHook(() => useDocumentTitle('My Page'));
    expect(document.title).toBe('My Page');
  });

  it('resets title on unmount', () => {
    const { unmount } = renderHook(() => useDocumentTitle('Test'));
    expect(document.title).toBe('Test');
    unmount();
    expect(document.title).toBe('App');
  });

EXAMPLE — useFetch hook with MSW:
  function useFetch(url) {
    const [data, setData] = useState(null);
    const [loading, setLoading] = useState(true);
    const [error, setError] = useState(null);

    useEffect(() => {
      fetch(url)
        .then(res => res.json())
        .then(setData)
        .catch(setError)
        .finally(() => setLoading(false));
    }, [url]);

    return { data, loading, error };
  }

  // With MSW handling /api/users (configured in setupTests.ts):
  describe('useFetch', () => {
    it('fetches data successfully', async () => {
      const { result } = renderHook(() => useFetch('/api/users'));

      expect(result.current.loading).toBe(true);

      await waitFor(() => {
        expect(result.current.loading).toBe(false);
      });

      expect(result.current.data).toEqual([
        { id: 1, name: 'Alice' },
        { id: 2, name: 'Bob' },
      ]);
      expect(result.current.error).toBeNull();
    });

    it('handles fetch error', async () => {
      server.use(
        http.get('/api/users', () => HttpResponse.error())
      );

      const { result } = renderHook(() => useFetch('/api/users'));

      await waitFor(() => {
        expect(result.current.loading).toBe(false);
      });

      expect(result.current.error).not.toBeNull();
      expect(result.current.data).toBeNull();
    });
  });

CLEANUP TEST:
  it('cancels fetch on unmount', async () => {
    const { unmount } = renderHook(() => useFetch('/api/users'));
    unmount(); // Triggers cleanup
    // Verify no state updates happen after unmount (no "can't perform state update on unmounted component" warning)
    // If using AbortController, verify the request is aborted
  });

7. TESTING HOOKS THAT USE CONTEXT
================================================================================

Hooks that call useContext require the Provider to be present.
Use the wrapper option in renderHook to provide context.

EXAMPLE — useTheme hook:
  const ThemeContext = createContext({ theme: 'light', toggle: () => {} });
  export const useTheme = () => useContext(ThemeContext);

  it('reads theme from context', () => {
    const wrapper = ({ children }) => (
      <ThemeContext.Provider value={{ theme: 'dark', toggle: jest.fn() }}>
        {children}
      </ThemeContext.Provider>
    );

    const { result } = renderHook(() => useTheme(), { wrapper });
    expect(result.current.theme).toBe('dark');
  });

EXAMPLE — useAuth hook that uses Context:
  it('returns current user from AuthContext', () => {
    const mockUser = { id: 1, name: 'Alice', role: 'admin' };

    const wrapper = ({ children }) => (
      <AuthContext.Provider value={{ user: mockUser, logout: jest.fn() }}>
        {children}
      </AuthContext.Provider>
    );

    const { result } = renderHook(() => useAuth(), { wrapper });

    expect(result.current.user).toEqual(mockUser);
    expect(result.current.isAdmin).toBe(true);
  });

SHARED WRAPPER FACTORY:
  // test-utils.tsx
  export function createWrapper(contextValue) {
    return function Wrapper({ children }) {
      return (
        <ThemeContext.Provider value={contextValue}>
          {children}
        </ThemeContext.Provider>
      );
    };
  }

  // In test:
  const { result } = renderHook(() => useTheme(), {
    wrapper: createWrapper({ theme: 'dark', toggle: jest.fn() }),
  });

8. TESTING HOOKS WITH EXTERNAL DEPENDENCIES
================================================================================

EXAMPLE — useDebounce:
  function useDebounce(value, delay) {
    const [debouncedValue, setDebouncedValue] = useState(value);

    useEffect(() => {
      const timer = setTimeout(() => setDebouncedValue(value), delay);
      return () => clearTimeout(timer);
    }, [value, delay]);

    return debouncedValue;
  }

  describe('useDebounce', () => {
    beforeEach(() => jest.useFakeTimers());
    afterEach(() => jest.useRealTimers());

    it('returns initial value immediately', () => {
      const { result } = renderHook(() => useDebounce('initial', 500));
      expect(result.current).toBe('initial');
    });

    it('returns updated value after delay', () => {
      const { result, rerender } = renderHook(
        ({ value, delay }) => useDebounce(value, delay),
        { initialProps: { value: 'initial', delay: 500 } }
      );

      rerender({ value: 'updated', delay: 500 });
      // Value hasn't debounced yet:
      expect(result.current).toBe('initial');

      // Advance timers past debounce delay:
      act(() => jest.advanceTimersByTime(500));
      expect(result.current).toBe('updated');
    });

    it('cancels pending debounce on rerender', () => {
      const { result, rerender } = renderHook(
        ({ value }) => useDebounce(value, 500),
        { initialProps: { value: 'first' } }
      );

      rerender({ value: 'second' });
      act(() => jest.advanceTimersByTime(250)); // Halfway through debounce
      rerender({ value: 'third' }); // Reset timer
      act(() => jest.advanceTimersByTime(250)); // Not enough time yet
      expect(result.current).toBe('first'); // Still debouncing

      act(() => jest.advanceTimersByTime(250)); // Now 500ms from last change
      expect(result.current).toBe('third');
    });
  });

9. COMMON PATTERNS
================================================================================

PATTERN: ASSERT STABLE REFERENCES (useCallback, useMemo)
  it('does not recreate callbacks on re-render', () => {
    const { result, rerender } = renderHook(() => useStableCallbacks());

    const firstIncrement = result.current.increment;
    const firstDecrement = result.current.decrement;

    rerender();

    expect(result.current.increment).toBe(firstIncrement); // Same reference
    expect(result.current.decrement).toBe(firstDecrement);
  });

PATTERN: TEST HOOK CLEANUP
  it('clears interval on unmount', () => {
    const clearIntervalSpy = jest.spyOn(global, 'clearInterval');
    const { unmount } = renderHook(() => usePolling(jest.fn(), 1000));
    unmount();
    expect(clearIntervalSpy).toHaveBeenCalled();
    clearIntervalSpy.mockRestore();
  });

PATTERN: VERIFY EVENT LISTENER CLEANUP
  it('removes event listener on unmount', () => {
    const addEventListenerSpy = jest.spyOn(window, 'addEventListener');
    const removeEventListenerSpy = jest.spyOn(window, 'removeEventListener');

    const { unmount } = renderHook(() => useWindowResize());

    expect(addEventListenerSpy).toHaveBeenCalledWith('resize', expect.any(Function));
    unmount();
    expect(removeEventListenerSpy).toHaveBeenCalledWith('resize', expect.any(Function));
  });

PATTERN: TEST HOOK ERRORS
  it('throws when used outside required provider', () => {
    // Suppress console.error for this test
    jest.spyOn(console, 'error').mockImplementation(() => {});

    expect(() => {
      renderHook(() => useTheme()); // No ThemeProvider wrapper
    }).toThrow('useTheme must be used within a ThemeProvider');

    jest.restoreAllMocks();
  });

ANTI-PATTERN: Don't render a component just to test the hook
  ❌ render(<ComponentUsingHook />);
  expect(screen.getByText('count: 0')).toBeInTheDocument();
  fireEvent.click(screen.getByRole('button', { name: /increment/ }));
  expect(screen.getByText('count: 1')).toBeInTheDocument();
  // This tests the hook indirectly — brittle, tied to component's HTML

  ✅ const { result } = renderHook(() => useCounter());
  expect(result.current.count).toBe(0);
  act(() => result.current.increment());
  expect(result.current.count).toBe(1);
