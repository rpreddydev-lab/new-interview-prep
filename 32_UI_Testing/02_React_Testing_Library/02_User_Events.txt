1. FIREEVENT VS USEREVENT
================================================================================

RTL ships with two ways to simulate user interactions:

fireEvent (basic, from @testing-library/dom):
  - Dispatches a single DOM event
  - Low-level, does NOT simulate browser behavior chains
  - Doesn't move focus, doesn't type character by character
  - Use when testing raw event handlers in isolation

  import { fireEvent } from '@testing-library/react';
  fireEvent.click(button);
  fireEvent.change(input, { target: { value: 'hello' } });
  fireEvent.submit(form);
  fireEvent.keyDown(input, { key: 'Enter', code: 'Enter' });

userEvent (full simulation, from @testing-library/user-event):
  - Simulates realistic browser behavior (event chains)
  - click: mousedown → focus → mouseup → click → all the pointer events
  - type: key-by-key, updates selection, fires input events
  - Handles tab order, focus management correctly
  - ✅ Recommended for almost all tests

  import userEvent from '@testing-library/user-event';
  const user = userEvent.setup();
  await user.click(button);
  await user.type(input, 'hello');

KEY DIFFERENCE — EXAMPLE:
  // fireEvent.click — only dispatches click event
  fireEvent.click(checkboxInput); // checkbox does NOT toggle in jsdom!

  // userEvent.click — full interaction
  const user = userEvent.setup();
  await user.click(checkboxInput); // checkbox DOES toggle ✅

WHEN TO USE fireEvent:
  - Very simple tests where event simulation doesn't matter
  - Performance-sensitive (less overhead)
  - When you need fine-grained control over a single event
  - When testing that a component responds to a specific event type

  Example: testing an onFocus callback
  fireEvent.focus(input); // Fine for this use case

2. USEREVENT SETUP (v14 API)
================================================================================

In @testing-library/user-event v14, the API changed to a setup-based approach.

OLD WAY (v13, still works but deprecated pattern):
  import userEvent from '@testing-library/user-event';
  userEvent.click(element);       // Was synchronous
  await userEvent.type(input, 'hello'); // But type was async

NEW WAY (v14, recommended):
  import userEvent from '@testing-library/user-event';
  const user = userEvent.setup();

  it('submits form', async () => {
    const user = userEvent.setup();
    render(<LoginForm />);
    await user.type(screen.getByLabelText(/email/i), 'alice@example.com');
    await user.type(screen.getByLabelText(/password/i), 'secret');
    await user.click(screen.getByRole('button', { name: /sign in/i }));
    expect(screen.getByText(/welcome alice/i)).toBeInTheDocument();
  });

SETUP OPTIONS:
  const user = userEvent.setup({
    delay: null,       // No delay between keystrokes (default: null = fastest)
    skipHover: false,  // Whether to skip hover before click
    skipClick: false,  // Whether to skip clicking in type
    skipAutoClose: false, // Whether to skip closing menus automatically
    pointerEventsCheck: PointerEventsCheckLevel.EachApiCall, // How often to check pointer-events CSS
  });

WHY SETUP ONCE IN EACH TEST:
  Each userEvent.setup() creates an isolated "user session" with its own
  pointer/keyboard/clipboard state. This prevents state leaking between tests.

HELPER PATTERN — CREATE USER IN beforeEach:
  describe('LoginForm', () => {
    let user;
    beforeEach(() => {
      user = userEvent.setup();
    });

    it('validates email', async () => {
      render(<LoginForm />);
      await user.type(screen.getByLabelText(/email/i), 'notanemail');
      await user.click(screen.getByRole('button', { name: /submit/i }));
      expect(screen.getByRole('alert')).toHaveTextContent(/invalid email/i);
    });
  });

3. CLICK, DBLCLICK, HOVER, UNHOVER
================================================================================

CLICK:
  await user.click(element);
  // Fires: pointerover → pointerenter → mouseover → mouseenter
  //       → pointermove → mousemove
  //       → pointerdown → mousedown → focus
  //       → pointerup → mouseup → click

  // Click at specific coordinates:
  await user.click(element, { clientX: 100, clientY: 50 });

  // Skip hover before clicking (slight performance gain):
  const user = userEvent.setup({ skipHover: true });
  await user.click(button);

EXAMPLES:
  // Click a button
  await user.click(screen.getByRole('button', { name: /submit/i }));

  // Click a link
  await user.click(screen.getByRole('link', { name: /about/i }));

  // Click to toggle a checkbox
  await user.click(screen.getByRole('checkbox', { name: /agree/i }));
  expect(screen.getByRole('checkbox', { name: /agree/i })).toBeChecked();

  // Click to open a menu
  await user.click(screen.getByRole('button', { name: /open menu/i }));
  expect(screen.getByRole('menu')).toBeVisible();

DBLCLICK:
  await user.dblClick(element);
  // Fires: click → click → dblclick

  // Useful for components that open on double-click:
  await user.dblClick(screen.getByText('Edit me'));
  expect(screen.getByRole('textbox')).toBeInTheDocument();

HOVER AND UNHOVER:
  await user.hover(element);
  // Fires: pointerover → pointerenter → mouseover → mouseenter → pointermove → mousemove

  await user.unhover(element);
  // Fires: pointerout → pointerleave → mouseout → mouseleave

  // Testing tooltips:
  await user.hover(screen.getByRole('button', { name: /help/i }));
  expect(await screen.findByRole('tooltip')).toBeVisible();
  await user.unhover(screen.getByRole('button', { name: /help/i }));
  expect(screen.queryByRole('tooltip')).not.toBeInTheDocument();

4. TYPE, CLEAR, PASTE
================================================================================

TYPE:
  await user.type(element, text, options?);
  // Types text character by character
  // Fires: click (focus) → keydown → keypress → input → keyup (for each char)

  await user.type(input, 'Hello World');
  expect(input).toHaveValue('Hello World');

SPECIAL CHARACTERS IN TYPE:
  Use curly braces for special keys:
  {enter}     → Enter key
  {tab}       → Tab key (moves focus)
  {backspace} → Delete last character
  {delete}    → Delete key
  {arrowleft}, {arrowright}, {arrowup}, {arrowdown}
  {home}, {end}
  {shift}, {ctrl}, {alt}, {meta}
  {selectall}

  // Type and hit Enter:
  await user.type(searchInput, 'React Testing{enter}');

  // Type with modifier (select all then type to replace):
  await user.type(input, '{selectall}new value');

  // Use backspace:
  await user.type(input, 'helo{backspace}lo');
  expect(input).toHaveValue('hello');

TYPE ON PRE-FILLED INPUT:
  // If input already has a value, type APPENDS to it:
  render(<input defaultValue="existing" />);
  const input = screen.getByRole('textbox');
  await user.type(input, ' text');
  expect(input).toHaveValue('existing text');

  // To REPLACE content:
  await user.clear(input);
  await user.type(input, 'new value');
  // Or:
  await user.type(input, '{selectall}replacement');

CLEAR:
  await user.clear(element);
  // Clears the value of an input, textarea, or select

  await user.clear(screen.getByRole('textbox', { name: /name/i }));
  expect(screen.getByRole('textbox', { name: /name/i })).toHaveValue('');

PASTE:
  await user.paste('Pasted text');
  // Types text as if pasted — fires input event but not key events

  // More realistic clipboard paste:
  await user.click(input);
  await user.paste('Alice');
  expect(input).toHaveValue('Alice');

  // Paste to a selected input:
  await user.type(input, 'Hello');
  await user.keyboard('{Control>}a{/Control}'); // Select all
  await user.paste('World');
  expect(input).toHaveValue('World');

5. KEYBOARD — KEY SEQUENCES
================================================================================

user.keyboard(text) — simulate keyboard input without targeting a specific element.
Fires events on the currently focused element.
Uses the same special key syntax as type.

KEYBOARD SYNTAX:
  user.keyboard('Hello');           // Type "Hello" on focused element
  user.keyboard('{Enter}');         // Press Enter
  user.keyboard('{Tab}');           // Tab to next element
  user.keyboard('{Escape}');        // Dismiss dialogs, menus
  user.keyboard('{ArrowDown}');     // Navigate down
  user.keyboard('{Control>}a{/Control}'); // Ctrl+A (hold modifier)
  user.keyboard('[ShiftLeft>][KeyA][/ShiftLeft]'); // Shift+A using key codes

MODIFIER KEY SYNTAX:
  >    → key down (hold)
  /    → key up (release)
  [KeyCode] → specific key by code

  // Hold Shift and press A (uppercase):
  await user.keyboard('[ShiftLeft>]a[/ShiftLeft]');

  // Ctrl+Z (undo):
  await user.keyboard('{Control>}z{/Control}');

  // Cmd+Enter on Mac:
  await user.keyboard('{Meta>}{Enter}{/Meta}');

EXAMPLES:
  // Submit form with Enter key in input:
  const input = screen.getByRole('textbox', { name: /search/i });
  await user.click(input);
  await user.type(input, 'test query');
  await user.keyboard('{Enter}');
  expect(onSearch).toHaveBeenCalledWith('test query');

  // Dismiss a modal with Escape:
  await user.click(screen.getByRole('button', { name: /open modal/i }));
  expect(screen.getByRole('dialog')).toBeInTheDocument();
  await user.keyboard('{Escape}');
  expect(screen.queryByRole('dialog')).not.toBeInTheDocument();

  // Navigate dropdown with arrow keys:
  await user.click(screen.getByRole('combobox'));
  await user.keyboard('{ArrowDown}');
  await user.keyboard('{ArrowDown}');
  await user.keyboard('{Enter}');
  expect(screen.getByRole('combobox')).toHaveDisplayValue('Second Option');

6. TAB — FOCUS NAVIGATION
================================================================================

user.tab() simulates pressing Tab to move focus to the next tabbable element.

BASIC USAGE:
  await user.tab();         // Move forward (Tab)
  await user.tab({ shift: true }); // Move backward (Shift+Tab)

EXAMPLE — TESTING TAB ORDER:
  render(
    <form>
      <input name="email" />
      <input name="password" />
      <button type="submit">Submit</button>
    </form>
  );

  // Initially no focus
  expect(document.body).toHaveFocus();

  await user.tab();
  expect(screen.getByRole('textbox', { name: /email/i })).toHaveFocus();

  await user.tab();
  expect(screen.getByLabelText(/password/i)).toHaveFocus();

  await user.tab();
  expect(screen.getByRole('button', { name: /submit/i })).toHaveFocus();

  await user.tab({ shift: true }); // Shift+Tab goes back
  expect(screen.getByLabelText(/password/i)).toHaveFocus();

USEFUL FOR TESTING:
  - Custom focus management (modals should trap focus)
  - Skip navigation links
  - Keyboard-only navigation flows
  - Form tab order

FOCUS TRAP TESTING:
  render(<Modal isOpen={true} />);
  const dialog = screen.getByRole('dialog');

  // Tab through all focusable elements
  await user.tab(); // First focusable inside dialog
  expect(dialog).toContainElement(document.activeElement);

  // Tab enough times to cycle completely
  await user.tab();
  await user.tab();
  await user.tab();
  // Focus should still be inside the dialog (trapped):
  expect(dialog).toContainElement(document.activeElement);

7. SELECTOPTIONS, DESELECTOPTIONS
================================================================================

For <select> elements — both single and multi-select.

SELECTOPTIONS:
  await user.selectOptions(selectElement, value);
  await user.selectOptions(selectElement, [value1, value2]); // Multiple

  // Select by value:
  await user.selectOptions(screen.getByRole('combobox'), 'us');

  // Select by display text:
  await user.selectOptions(screen.getByRole('combobox'), 'United States');

  // Select by option element:
  const select = screen.getByRole('listbox', { name: /country/i });
  await user.selectOptions(select, screen.getByRole('option', { name: /france/i }));

DESELECTOPTIONS (for multi-select):
  const multiSelect = screen.getByRole('listbox', { name: /tags/i });
  await user.deselectOptions(multiSelect, 'javascript');

ASSERTIONS AFTER SELECT:
  await user.selectOptions(
    screen.getByRole('combobox', { name: /size/i }),
    'large'
  );
  expect(screen.getByRole('combobox', { name: /size/i }))
    .toHaveDisplayValue('Large');

  // Check selected option:
  expect(screen.getByRole('option', { name: /large/i })).toHaveAttribute('selected');
  // Or with jest-dom:
  expect(screen.getByRole('option', { name: /large/i })).toBeSelected();

MULTI-SELECT EXAMPLE:
  render(
    <select multiple aria-label="Skills">
      <option value="js">JavaScript</option>
      <option value="ts">TypeScript</option>
      <option value="react">React</option>
    </select>
  );

  const select = screen.getByRole('listbox', { name: /skills/i });
  await user.selectOptions(select, ['js', 'react']);
  expect(screen.getByRole('option', { name: 'JavaScript' })).toBeSelected();
  expect(screen.getByRole('option', { name: 'React' })).toBeSelected();
  expect(screen.getByRole('option', { name: 'TypeScript' })).not.toBeSelected();

8. UPLOAD — FILE INPUTS
================================================================================

user.upload(element, file | File[]) simulates file selection.

SINGLE FILE UPLOAD:
  const file = new File(['file content'], 'test.txt', { type: 'text/plain' });
  const input = screen.getByLabelText(/upload file/i);
  await user.upload(input, file);

  expect(input.files?.[0]).toBe(file);
  expect(input.files?.item(0)).toBe(file);
  expect(input.files).toHaveLength(1);

IMAGE UPLOAD:
  const imageFile = new File(['(⌐□_□)'], 'chucknorris.png', { type: 'image/png' });
  await user.upload(screen.getByLabelText(/profile picture/i), imageFile);

  // Test that preview appears
  expect(await screen.findByRole('img', { name: /preview/i })).toBeInTheDocument();

MULTIPLE FILE UPLOAD:
  // Input must have multiple attribute:
  // <input type="file" multiple accept=".jpg,.png" />

  const files = [
    new File(['img1'], 'photo1.jpg', { type: 'image/jpeg' }),
    new File(['img2'], 'photo2.jpg', { type: 'image/jpeg' }),
  ];

  await user.upload(screen.getByLabelText(/photos/i), files);
  expect(screen.getByLabelText(/photos/i).files).toHaveLength(2);

TESTING VALIDATION:
  // Upload a file of wrong type and test error:
  const wrongFile = new File(['data'], 'doc.pdf', { type: 'application/pdf' });
  await user.upload(screen.getByLabelText(/image/i), wrongFile);
  await user.click(screen.getByRole('button', { name: /upload/i }));
  expect(screen.getByRole('alert')).toHaveTextContent(/only images/i);

9. POINTER EVENTS
================================================================================

For more granular pointer control beyond click/hover:

user.pointer(input) - low-level pointer events

POINTER EXAMPLES:
  // Right-click (context menu):
  await user.pointer({ target: element, keys: '[MouseRight]' });
  // Or:
  await user.pointer([{ target: element }, '[MouseRight]']);

  // Middle-click:
  await user.pointer({ target: element, keys: '[MouseMiddle]' });

  // Touch events:
  await user.pointer({ target: element, keys: '[TouchA]' });

  // Pointer down without up (drag start):
  await user.pointer({ target: element, keys: '[MouseLeft>]' });
  // Pointer move while held down:
  await user.pointer({ target: otherElement, coords: { x: 100, y: 100 } });
  // Release:
  await user.pointer('[/MouseLeft]');

DRAG AND DROP (basic):
  const draggable = screen.getByTestId('draggable-item');
  const dropZone = screen.getByTestId('drop-zone');

  await user.pointer([
    { target: draggable, keys: '[MouseLeft>]' },  // mousedown on source
    { target: dropZone },                          // mousemove to target
    '[/MouseLeft]',                                // mouseup
  ]);

  expect(onDrop).toHaveBeenCalled();

10. COMMON PATTERNS AND PITFALLS
================================================================================

PATTERN: FULL FORM SUBMISSION TEST
  it('submits registration form with valid data', async () => {
    const onSubmit = jest.fn();
    const user = userEvent.setup();
    render(<RegistrationForm onSubmit={onSubmit} />);

    await user.type(screen.getByLabelText(/username/i), 'alice');
    await user.type(screen.getByLabelText(/email/i), 'alice@example.com');
    await user.type(screen.getByLabelText(/password/i), 'Password123!');
    await user.click(screen.getByRole('checkbox', { name: /agree to terms/i }));
    await user.click(screen.getByRole('button', { name: /register/i }));

    await waitFor(() => {
      expect(onSubmit).toHaveBeenCalledWith({
        username: 'alice',
        email: 'alice@example.com',
        password: 'Password123!',
        terms: true,
      });
    });
  });

PATTERN: AUTOCOMPLETE / COMBOBOX
  it('selects suggestion from dropdown', async () => {
    const user = userEvent.setup();
    render(<AutocompleteInput />);

    const input = screen.getByRole('combobox');
    await user.type(input, 'rea');
    const option = await screen.findByRole('option', { name: /react/i });
    await user.click(option);
    expect(input).toHaveValue('React');
  });

PITFALL 1: FORGETTING AWAIT
  ❌ user.click(button); // Returns a Promise — not awaited!
  ✅ await user.click(button);

PITFALL 2: USING OLD v13 DIRECT API WITH v14
  ❌ userEvent.click(button); // Old API — may work but inconsistent with v14
  ✅ const user = userEvent.setup(); await user.click(button);

PITFALL 3: TYPE ON DISABLED INPUT
  // Typing on a disabled input does nothing — don't expect value to change
  const disabledInput = screen.getByRole('textbox', { name: /readonly/i });
  await user.type(disabledInput, 'ignored');
  expect(disabledInput).toHaveValue(''); // Not 'ignored'

PITFALL 4: TYPE APPENDS BY DEFAULT
  ❌ Unexpected behavior if input has initial value:
  render(<input defaultValue="hello" />);
  await user.type(screen.getByRole('textbox'), ' world');
  // Expect "hello world" — not just " world"

  ✅ Clear first if you want to replace:
  await user.clear(input);
  await user.type(input, 'new value');

PITFALL 5: FIREEVENT.CHANGE VS USER.TYPE
  ❌ Not realistic:
  fireEvent.change(input, { target: { value: 'hello' } }); // Sets value directly

  ✅ Realistic character-by-character input:
  await user.type(input, 'hello');

PITFALL 6: MISSING TEST FOR KEYBOARD USERS
  // Test that interactive elements work without mouse:
  it('can submit with Enter key', async () => {
    const user = userEvent.setup();
    render(<SearchForm onSearch={jest.fn()} />);
    const input = screen.getByRole('textbox', { name: /search/i });
    await user.click(input);
    await user.type(input, 'testing');
    await user.keyboard('{Enter}');
    expect(onSearch).toHaveBeenCalledWith('testing');
  });

QUICK REFERENCE:
  user.click(el)                          → Single click
  user.dblClick(el)                       → Double click
  user.hover(el) / user.unhover(el)       → Mouse hover
  user.type(el, 'text')                   → Type text
  user.clear(el)                          → Clear input
  user.paste('text')                      → Paste text
  user.keyboard('{Enter}')                → Press key
  user.tab()                              → Tab forward
  user.tab({ shift: true })               → Tab backward
  user.selectOptions(el, 'value')         → Select option
  user.deselectOptions(el, 'value')       → Deselect option (multi)
  user.upload(el, file)                   → Upload file(s)
  user.pointer(...)                       → Raw pointer events
