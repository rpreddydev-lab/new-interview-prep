1. MODULE MOCKING DEEP DIVE
================================================================================

jest.mock(modulePath, factory?, options?) replaces a module in the test's
module registry with a mock version.

HOW IT WORKS INTERNALLY:
  1. jest.mock() is HOISTED to the top of the file before any imports
  2. When the test file's imports run, the mocked module is returned
  3. The real module code never runs
  4. All module consumers in the test get the mocked version

WHAT jest.mock() DOES WITHOUT A FACTORY:
  When called without a factory function, Jest auto-mocks the module:
  - Functions → jest.fn() returning undefined
  - Classes → Mock class with all methods as jest.fn()
  - Constants → Preserved (non-function values are kept)
  - Getters → Converted to jest.fn()

  jest.mock('./userService');
  // All exports from userService are now jest.fn()

  import { getUser, createUser } from './userService';
  // getUser is jest.fn(), createUser is jest.fn()

  // Configure them per-test:
  (getUser as jest.Mock).mockResolvedValue({ id: 1 });

VERIFYING THE MOCK:
  import { getUser } from './userService';
  jest.mock('./userService');

  it('calls getUser on mount', async () => {
    (getUser as jest.Mock).mockResolvedValue({ id: 1, name: 'Alice' });
    render(<UserProfile id={1} />);
    await screen.findByText('Alice');
    expect(getUser).toHaveBeenCalledWith(1);
    expect(getUser).toHaveBeenCalledTimes(1);
  });

2. MOCK HOISTING EXPLAINED
================================================================================

HOISTING is why jest.mock() works even when written AFTER imports:

  // This is what you write:
  import { getUser } from './userService';
  jest.mock('./userService');

  // This is what Babel/ts-jest transforms it to:
  jest.mock('./userService');    // MOVED TO TOP
  const { getUser } = require('./userService'); // Transformed import

This is implemented by babel-plugin-jest-hoist (used internally by Jest).

IMPLICATIONS OF HOISTING:
  1. Variables defined in the test file cannot be used in jest.mock() factory
     because they don't exist yet at the time jest.mock() runs:

     // ❌ THIS FAILS:
     const mockGetUser = jest.fn().mockResolvedValue({ id: 1 });
     jest.mock('./userService', () => ({
       getUser: mockGetUser,  // ReferenceError! mockGetUser is not defined yet
     }));

     // ✅ WORKAROUND: Use a variable with 'mock' prefix (babel allows these)
     const mockGetUser = jest.fn().mockResolvedValue({ id: 1 });
     jest.mock('./userService', () => ({
       getUser: jest.fn(), // Define here, configure in test
     }));

  2. Constants starting with 'mock' are allowed in factory functions:
     // babel-plugin-jest-hoist allows 'mock*' prefixed variables:
     const mockUser = { id: 1, name: 'Alice' };
     jest.mock('./userService', () => ({
       getUser: jest.fn().mockResolvedValue(mockUser), // This WORKS
     }));

3. FACTORY FUNCTIONS IN jest.mock()
================================================================================

The factory function returns the mock module implementation:

  jest.mock('./analytics', () => ({
    track: jest.fn(),
    identify: jest.fn(),
    page: jest.fn(),
  }));

ACCESSING MOCK FUNCTIONS IN TESTS:
  import { track } from './analytics';
  jest.mock('./analytics', () => ({ track: jest.fn() }));

  it('tracks page view on mount', () => {
    render(<HomePage />);
    expect(track).toHaveBeenCalledWith('page_view', { page: 'home' });
  });

USING jest.fn() WITH INITIAL IMPLEMENTATION:
  jest.mock('./dateUtils', () => ({
    formatDate: jest.fn((date) => date.toISOString().split('T')[0]),
    formatTime: jest.fn(() => '12:00'),
    isToday: jest.fn().mockReturnValue(true),
    isBefore: jest.fn().mockImplementation((d1, d2) => d1 < d2),
  }));

FACTORY WITH ASYNC FUNCTIONS:
  jest.mock('./apiClient', () => ({
    get: jest.fn().mockResolvedValue({ data: [] }),
    post: jest.fn().mockResolvedValue({ data: { id: 1 } }),
    put: jest.fn().mockResolvedValue({ data: {} }),
    delete: jest.fn().mockResolvedValue(null),
    interceptors: {
      request: { use: jest.fn() },
      response: { use: jest.fn() },
    },
  }));

DYNAMIC FACTORY VALUES PER TEST:
  import { getUser } from './userService';
  jest.mock('./userService');

  it('renders user name', async () => {
    (getUser as jest.Mock).mockResolvedValueOnce({ name: 'Alice' });
    render(<UserCard userId={1} />);
    expect(await screen.findByText('Alice')).toBeInTheDocument();
  });

  it('renders fallback for unknown user', async () => {
    (getUser as jest.Mock).mockRejectedValueOnce(new Error('Not found'));
    render(<UserCard userId={999} />);
    expect(await screen.findByText(/user not found/i)).toBeInTheDocument();
  });

4. PARTIAL MODULE MOCKING
================================================================================

Keep real implementations for most functions, mock only specific ones.

jest.requireActual() returns the real module implementation:

  jest.mock('./utils', () => ({
    ...jest.requireActual('./utils'),  // Keep all real functions
    formatDate: jest.fn().mockReturnValue('2024-01-01'), // Override this one
  }));

EXAMPLE USE CASE:
  // utils.ts exports: formatDate, formatCurrency, parseDate, calculateAge
  // You want real formatCurrency but mock formatDate (unstable due to timezones)

  jest.mock('./utils', () => {
    const actual = jest.requireActual('./utils');
    return {
      ...actual,
      formatDate: jest.fn().mockReturnValue('Jan 1, 2024'),
    };
  });

  // In test: formatCurrency uses real implementation, formatDate is mocked

PARTIAL MOCKING OF HOOKS:
  jest.mock('./hooks/useAuth', () => ({
    ...jest.requireActual('./hooks/useAuth'),
    useCurrentUser: jest.fn().mockReturnValue({
      user: { id: '1', name: 'Alice', role: 'admin' },
      isLoading: false,
    }),
    useLogout: jest.fn(),
  }));

5. MOCKING DEFAULT vs NAMED EXPORTS
================================================================================

NAMED EXPORTS (easier):
  // module.ts
  export const add = (a, b) => a + b;
  export const multiply = (a, b) => a * b;

  // test.ts
  jest.mock('./module', () => ({
    add: jest.fn().mockReturnValue(5),
    multiply: jest.fn().mockReturnValue(10),
  }));

DEFAULT EXPORTS (requires __esModule flag):
  // MyComponent.tsx
  export default function MyComponent() { ... }

  // test.tsx
  jest.mock('./MyComponent', () => ({
    __esModule: true,
    default: jest.fn().mockImplementation(() => <div>Mocked</div>),
  }));

BOTH DEFAULT AND NAMED:
  // auth.ts
  export default class AuthService { ... }
  export const isAuthenticated = () => { ... }
  export const getToken = () => { ... }

  // test.ts
  jest.mock('./auth', () => ({
    __esModule: true,
    default: jest.fn().mockImplementation(() => ({
      login: jest.fn().mockResolvedValue({ success: true }),
      logout: jest.fn(),
    })),
    isAuthenticated: jest.fn().mockReturnValue(true),
    getToken: jest.fn().mockReturnValue('mock-token'),
  }));

RE-MOCKING DEFAULT EXPORT IN TESTS:
  import MyComponent from './MyComponent';
  jest.mock('./MyComponent');

  it('renders loading state when isLoading prop is true', () => {
    (MyComponent as jest.Mock).mockImplementation(({ isLoading }) =>
      isLoading ? <div>Loading...</div> : <div>Content</div>
    );
    render(<Parent isLoading={true} />);
    expect(screen.getByText('Loading...')).toBeInTheDocument();
  });

6. jest.spyOn() DEEP DIVE
================================================================================

jest.spyOn(object, methodName, accessType?) creates a spy on an existing method.

KEY DIFFERENCES FROM jest.mock():
  - jest.mock():   Replaces the ENTIRE module
  - jest.spyOn():  Replaces a SINGLE method on an object

  - jest.mock():   Effect is file-wide
  - jest.spyOn():  Effect is scoped to where you restore it

  - jest.mock():   Real code never runs
  - jest.spyOn():  Real code runs by default (unless you mock the implementation)

BASIC SPY (track calls, run real code):
  const consoleSpy = jest.spyOn(console, 'error');

  // Trigger code that calls console.error:
  render(<BadComponent />);

  // Verify it was called:
  expect(consoleSpy).toHaveBeenCalledWith(
    expect.stringContaining('prop type error')
  );

  // Restore original implementation:
  consoleSpy.mockRestore();

SUPPRESS AND SPY:
  const consoleSpy = jest.spyOn(console, 'error').mockImplementation(() => {});
  // Now console.error() does nothing + we can track calls
  // Useful to suppress React warnings in tests

SPY ON MODULE FUNCTIONS:
  import * as dateUtils from './dateUtils';

  const formatSpy = jest.spyOn(dateUtils, 'formatDate').mockReturnValue('Jan 1');

  it('displays formatted date', () => {
    render(<DateComponent date={new Date()} />);
    expect(screen.getByText('Jan 1')).toBeInTheDocument();
    expect(formatSpy).toHaveBeenCalledTimes(1);
  });

  afterEach(() => formatSpy.mockRestore());

SPY ON CLASS METHODS:
  import UserService from './UserService';

  it('calls UserService.getUser on mount', async () => {
    const getUserSpy = jest.spyOn(UserService.prototype, 'getUser')
      .mockResolvedValue({ id: 1, name: 'Alice' });

    render(<UserProfile userId={1} />);
    await screen.findByText('Alice');

    expect(getUserSpy).toHaveBeenCalledWith(1);
    getUserSpy.mockRestore();
  });

7. SPY ON OBJECT METHODS
================================================================================

SPYING ON window METHODS:
  // window.open
  const openSpy = jest.spyOn(window, 'open').mockImplementation(() => null);
  await userEvent.click(screen.getByRole('link', { name: /external link/i }));
  expect(openSpy).toHaveBeenCalledWith('https://external.com', '_blank');
  openSpy.mockRestore();

  // window.scrollTo
  const scrollSpy = jest.spyOn(window, 'scrollTo').mockImplementation(() => {});
  await userEvent.click(backToTopButton);
  expect(scrollSpy).toHaveBeenCalledWith({ top: 0, behavior: 'smooth' });

  // history.pushState
  const pushStateSpy = jest.spyOn(window.history, 'pushState');
  // ... trigger navigation
  expect(pushStateSpy).toHaveBeenCalledWith({}, '', '/new-path');

SPYING ON GLOBAL OBJECTS:
  // Date
  const mockDate = new Date('2024-01-15');
  jest.spyOn(global, 'Date').mockImplementation(() => mockDate as any);

  // Math.random
  const randomSpy = jest.spyOn(Math, 'random').mockReturnValue(0.5);

  // fetch
  const fetchSpy = jest.spyOn(global, 'fetch').mockResolvedValue(
    new Response(JSON.stringify({ data: 'test' }), { status: 200 })
  );

SPYING ON REACT HOOKS:
  import * as React from 'react';

  const useStateSpy = jest.spyOn(React, 'useState');
  // Not recommended — tests implementation details
  // Better to test the component's visible output

8. SPY ON GETTERS AND SETTERS
================================================================================

jest.spyOn(object, property, 'get') spies on a getter.
jest.spyOn(object, property, 'set') spies on a setter.

GETTER SPY:
  // Spy on navigator.onLine getter:
  jest.spyOn(navigator, 'onLine', 'get').mockReturnValue(false);
  render(<OfflineIndicator />);
  expect(screen.getByText(/you are offline/i)).toBeInTheDocument();

  // Reset
  jest.spyOn(navigator, 'onLine', 'get').mockReturnValue(true);

  // Useful properties to spy on:
  // navigator.onLine        → connectivity
  // navigator.userAgent     → browser detection
  // document.hidden         → page visibility
  // window.innerWidth       → viewport width
  // performance.now()       → timing

SETTER SPY:
  const setterSpy = jest.spyOn(document, 'title', 'set');
  renderWithTitle(<Page title="Test Page" />);
  expect(setterSpy).toHaveBeenCalledWith('Test Page');

MULTIPLE GETTER VALUES:
  const onlineSpy = jest.spyOn(navigator, 'onLine', 'get');

  onlineSpy.mockReturnValueOnce(true);   // First call: online
  onlineSpy.mockReturnValueOnce(false);  // Second call: offline
  onlineSpy.mockReturnValue(true);       // Subsequent: online

9. AUTO-MOCKING vs MANUAL MOCKING
================================================================================

AUTO-MOCKING (jest.mock() without factory):
  Pros: Quick, no maintenance
  Cons: All methods return undefined, may need per-test configuration

  jest.mock('./emailService');
  // Everything in emailService is now jest.fn()
  // Must configure return values in each test

  USAGE:
    import { sendEmail } from './emailService';
    jest.mock('./emailService');

    it('sends welcome email on registration', async () => {
      (sendEmail as jest.Mock).mockResolvedValue({ success: true });
      await registerUser({ email: 'test@test.com' });
      expect(sendEmail).toHaveBeenCalledWith(
        'test@test.com', 'Welcome!', expect.any(String)
      );
    });

MANUAL MOCKING (__mocks__ directory):
  Create a file that mirrors the module structure:

  // src/services/__mocks__/emailService.ts
  export const sendEmail = jest.fn().mockResolvedValue({ success: true });
  export const validateEmail = jest.fn().mockReturnValue(true);

  // In test file:
  jest.mock('../services/emailService'); // Loads the __mocks__ version
  // No need to configure return values — defaults from __mocks__ file

FACTORY MOCKING (inline factory):
  Full control, explicit, reusable within the file:

  jest.mock('./emailService', () => ({
    sendEmail: jest.fn().mockResolvedValue({ success: true }),
    validateEmail: jest.fn().mockReturnValue(true),
  }));

WHICH TO USE?
  Auto-mock:     Quick tests, don't need to verify calls, just prevent real calls
  Manual mock:   Shared default behavior across many test files
  Factory mock:  Full control, custom behavior, most explicit

10. ADVANCED PATTERNS
================================================================================

TYPED MOCK HELPER (TypeScript):
  // Helper function to avoid (fn as jest.Mock) casting everywhere
  function asMock<T extends (...args: any[]) => any>(fn: T): jest.MockedFunction<T> {
    return fn as jest.MockedFunction<T>;
  }

  // Usage:
  asMock(getUser).mockResolvedValue({ id: 1 });
  // Instead of: (getUser as jest.Mock).mockResolvedValue({ id: 1 });

  // Or use jest.mocked() (built-in since Jest 27):
  jest.mocked(getUser).mockResolvedValue({ id: 1 });

MOCK CHAINING (fluent API):
  const mockService = {
    login: jest.fn().mockReturnThis(),
    withCredentials: jest.fn().mockReturnThis(),
    execute: jest.fn().mockResolvedValue({ token: 'abc' }),
  };

  jest.mock('./authService', () => ({ default: () => mockService }));

  it('chains method calls', async () => {
    await loginUser('user@test.com', 'pass');
    expect(mockService.login).toHaveBeenCalledWith('user@test.com', 'pass');
    expect(mockService.withCredentials).toHaveBeenCalled();
    expect(mockService.execute).toHaveBeenCalled();
  });

CAPTURING ARGUMENTS FOR COMPLEX ASSERTIONS:
  const mockSubmit = jest.fn();

  await userEvent.click(submitButton);

  // Access the actual arguments for complex inspection:
  const [firstArg] = mockSubmit.mock.calls[0];
  expect(firstArg.timestamp).toBeInstanceOf(Date);
  expect(firstArg.payload).toMatchObject({ userId: expect.any(String) });

VERIFYING CALL ORDER:
  const mockA = jest.fn();
  const mockB = jest.fn();

  await performOperation();

  // Ensure A was called before B:
  const aCallTime = mockA.mock.invocationCallOrder[0];
  const bCallTime = mockB.mock.invocationCallOrder[0];
  expect(aCallTime).toBeLessThan(bCallTime);

MOCK THAT CALLS A CALLBACK:
  const mockFetch = jest.fn().mockImplementation((url, options) => {
    // Call the onProgress callback if provided
    if (options?.onProgress) {
      options.onProgress(50);  // 50% progress
    }
    return Promise.resolve({ data: 'result' });
  });

  it('reports upload progress', async () => {
    const progressCallback = jest.fn();
    await uploadFile(file, { onProgress: progressCallback });
    expect(progressCallback).toHaveBeenCalledWith(50);
  });
