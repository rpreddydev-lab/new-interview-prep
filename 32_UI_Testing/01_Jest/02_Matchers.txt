1. WHAT ARE MATCHERS?
================================================================================

Matchers are the methods chained to expect() that verify a value meets
your expectations.

SYNTAX:
  expect(received).matcher(expected)

NEGATION:
  expect(received).not.matcher(expected)

EVERY ASSERTION USES THIS PATTERN:
  expect(2 + 2).toBe(4);
  expect('Hello World').toContain('World');
  expect(fetchData).rejects.toThrow('Not Found');

2. COMMON EQUALITY MATCHERS
================================================================================

toBe(value)
  → Checks STRICT equality using Object.is()
  → For primitives (numbers, strings, booleans)
  → Does NOT deep-compare objects

  expect(1 + 1).toBe(2);
  expect('hello').toBe('hello');
  expect(null).toBe(null);
  // ❌ This FAILS: expect({ a: 1 }).toBe({ a: 1 }); (different references)

toEqual(value)
  → Deep equality comparison
  → Checks object/array structure and values recursively
  → Ignores undefined properties

  expect({ name: 'Alice', age: 30 }).toEqual({ name: 'Alice', age: 30 });
  expect([1, 2, 3]).toEqual([1, 2, 3]);
  expect({ a: 1, b: undefined }).toEqual({ a: 1 }); // PASSES (ignores undefined)

toStrictEqual(value)
  → Like toEqual but STRICTER
  → Does NOT ignore undefined properties
  → Checks object type (class instances)

  class User { constructor(public name: string) {} }
  expect(new User('Alice')).toStrictEqual(new User('Alice')); // PASSES
  expect(new User('Alice')).toStrictEqual({ name: 'Alice' }); // FAILS (different class)
  expect({ a: 1, b: undefined }).toStrictEqual({ a: 1 }); // FAILS

WHEN TO USE EACH:
  toBe:          primitive comparisons (numbers, strings)
  toEqual:       plain objects and arrays
  toStrictEqual: class instances or when undefined matters


================================================================================
3. TRUTHINESS MATCHERS
================================================================================

toBeTruthy()
  → Passes if value is truthy in boolean context
  expect(1).toBeTruthy();
  expect('hello').toBeTruthy();
  expect({}).toBeTruthy();

toBeFalsy()
  → Passes if value is falsy in boolean context
  expect(0).toBeFalsy();
  expect('').toBeFalsy();
  expect(null).toBeFalsy();
  expect(undefined).toBeFalsy();

toBeNull()
  → Strictly checks for null (not undefined, not 0)
  expect(null).toBeNull();

toBeUndefined()
  → Strictly checks for undefined
  expect(undefined).toBeUndefined();

toBeDefined()
  → Passes if value is NOT undefined
  expect('hello').toBeDefined();
  expect(null).toBeDefined(); // PASSES (null is defined)

TRUTHY / FALSY VALUES IN JS:
  Truthy: non-zero numbers, non-empty strings, objects, arrays, true
  Falsy:  0, '', null, undefined, false, NaN, 0n (BigInt zero)

4. NUMBER MATCHERS
================================================================================

toBeGreaterThan(n)        → value > n
toBeGreaterThanOrEqual(n) → value >= n
toBeLessThan(n)           → value < n
toBeLessThanOrEqual(n)    → value <= n

  expect(5).toBeGreaterThan(3);
  expect(5).toBeGreaterThanOrEqual(5);
  expect(3).toBeLessThan(5);

toBeCloseTo(n, numDigits?)
  → For floating point comparison (avoids precision issues)
  → numDigits: number of decimal places to check (default: 2)

  expect(0.1 + 0.2).not.toBe(0.3);          // FAILS! floating point issue
  expect(0.1 + 0.2).toBeCloseTo(0.3);       // PASSES
  expect(0.1 + 0.2).toBeCloseTo(0.3, 5);    // Check 5 decimal places

NaN:
  expect(NaN).toBeNaN();
  expect(Number.isNaN(NaN)).toBe(true);


================================================================================
5. STRING MATCHERS
================================================================================

toContain(string)
  → Checks if string contains the substring
  expect('Hello World').toContain('World');
  expect('GitHub Copilot').toContain('Copilot');

toMatch(regex | string)
  → Checks string against a regex or substring
  expect('I am an error message').toMatch(/error/i);
  expect('test@example.com').toMatch(/^[\w.-]+@[\w.-]+\.\w+$/);
  expect('Hello World').toMatch('World');

toHaveLength(n)
  → Works for strings AND arrays
  expect('hello').toHaveLength(5);
  expect([1, 2, 3]).toHaveLength(3);

toStartWith(prefix)      [v29.2+]
  expect('Hello World').toStartWith('Hello');

toEndWith(suffix)        [v29.2+]
  expect('Hello World').toEndWith('World');


================================================================================
6. ARRAY AND ITERABLE MATCHERS
================================================================================

toContain(item)
  → Checks if array contains an item (uses ===)
  expect([1, 2, 3]).toContain(2);
  expect(['apple', 'banana']).toContain('apple');
  // Note: For objects, use toContainEqual

toContainEqual(item)
  → Checks if array contains an item (uses deep equality)
  expect([{ id: 1 }, { id: 2 }]).toContainEqual({ id: 1 });

toHaveLength(n)
  expect([1, 2, 3]).toHaveLength(3);
  expect([]).toHaveLength(0);

toEqual with expect.arrayContaining([...])
  → Array must contain ALL listed items (in any order, can have extra items)
  expect([1, 2, 3, 4]).toEqual(expect.arrayContaining([2, 4]));
  expect(['a', 'b', 'c']).toEqual(expect.arrayContaining(['c', 'a']));


================================================================================
7. OBJECT MATCHERS
================================================================================

toEqual(obj)
  → Deep equality for plain objects
  expect(user).toEqual({ name: 'Alice', role: 'admin' });

toMatchObject(obj)
  → Object must contain AT LEAST the specified properties
  → Extra properties in received are allowed (subset matching)

  const user = { name: 'Alice', age: 30, role: 'admin' };
  expect(user).toMatchObject({ name: 'Alice', role: 'admin' }); // PASSES
  expect(user).toMatchObject({ name: 'Alice', email: 'x' });    // FAILS

  // Works with arrays of objects too:
  expect([user1, user2]).toMatchObject([
    { name: 'Alice' },
    { name: 'Bob' },
  ]);

toHaveProperty(keyPath, value?)
  → Checks if object has a specific property path
  → Optionally checks the value

  const obj = { a: { b: { c: 42 } } };
  expect(obj).toHaveProperty('a');
  expect(obj).toHaveProperty('a.b.c');
  expect(obj).toHaveProperty('a.b.c', 42);
  expect(obj).toHaveProperty(['a', 'b', 'c'], 42); // Array path syntax

expect.objectContaining(obj)
  → Asymmetric matcher for partial object matching
  expect(response).toEqual(expect.objectContaining({
    status: 200,
    body: expect.any(Object),
  }));

8. EXCEPTION MATCHERS (toThrow)
================================================================================

toThrow(error?)
  → Tests that a function throws when called
  → Must wrap the function call in an arrow function!

  function divide(a, b) {
    if (b === 0) throw new Error('Division by zero');
    return a / b;
  }

  // ✅ CORRECT: Wrap in arrow function
  expect(() => divide(1, 0)).toThrow();
  expect(() => divide(1, 0)).toThrow('Division by zero');
  expect(() => divide(1, 0)).toThrow(/division by zero/i);
  expect(() => divide(1, 0)).toThrow(Error);

  // ❌ WRONG: Calling directly (throws before expect runs)
  expect(divide(1, 0)).toThrow(); // ERROR

TESTING ASYNC ERRORS:
  // Using rejects:
  await expect(asyncFunction()).rejects.toThrow('error message');
  await expect(asyncFunction()).rejects.toThrow(CustomError);
  await expect(asyncFunction()).rejects.toMatchObject({
    message: 'Not Found',
    statusCode: 404,
  });

TESTING SPECIFIC ERROR TYPES:
  class ValidationError extends Error {
    constructor(public field: string, message: string) {
      super(message);
      this.name = 'ValidationError';
    }
  }

  expect(() => validate(data)).toThrow(ValidationError);
  expect(() => validate(data)).toThrow(expect.objectContaining({
    name: 'ValidationError',
    field: 'email',
  }));

9. MOCK FUNCTION MATCHERS
================================================================================

toHaveBeenCalled()
  → Verifies mock was called at least once
  const mockFn = jest.fn();
  mockFn('hello');
  expect(mockFn).toHaveBeenCalled();

toHaveBeenCalledTimes(n)
  expect(mockFn).toHaveBeenCalledTimes(3);

toHaveBeenCalledWith(...args)
  → Verifies mock was called with specific arguments
  mockFn('hello', 42);
  expect(mockFn).toHaveBeenCalledWith('hello', 42);
  expect(mockFn).toHaveBeenCalledWith(expect.any(String), expect.any(Number));

toHaveBeenLastCalledWith(...args)
  → Checks only the MOST RECENT call
  mockFn('first');
  mockFn('second');
  expect(mockFn).toHaveBeenLastCalledWith('second');

toHaveBeenNthCalledWith(n, ...args)
  → Checks the nth call specifically
  mockFn('first');
  mockFn('second');
  expect(mockFn).toHaveBeenNthCalledWith(1, 'first');
  expect(mockFn).toHaveBeenNthCalledWith(2, 'second');

toHaveReturned()
  → Mock returned (didn't throw)
  expect(mockFn).toHaveReturned();

toHaveReturnedWith(value)
  → Mock returned a specific value
  const mock = jest.fn(() => 42);
  mock();
  expect(mock).toHaveReturnedWith(42);

toHaveReturnedTimes(n)
  → Mock returned (not thrown) n times

10. JEST-DOM MATCHERS (DOM-SPECIFIC)
================================================================================

Install: npm install --save-dev @testing-library/jest-dom
Import:  import '@testing-library/jest-dom'; (in setupTests.ts)

These matchers extend expect() for DOM elements:

PRESENCE:
  toBeInTheDocument()       → Element is in the document
  toBeVisible()             → Element is visible (not hidden, opacity>0, etc.)
  toBeEmptyDOMElement()     → Element has no children

FORM STATE:
  toBeDisabled()            → Input/button/etc. is disabled
  toBeEnabled()             → Input/button/etc. is enabled
  toBeChecked()             → Checkbox/radio is checked
  toHaveFocus()             → Element has keyboard focus

CONTENT:
  toHaveTextContent(text)   → Element has text (can be regex)
  toHaveValue(value)        → Input has specific value
  toHaveDisplayValue(value) → Select element shows specific option

ATTRIBUTES:
  toHaveAttribute(attr, value?) → Element has attribute (optionally with value)
  toHaveClass(className)        → Element has CSS class
  toHaveStyle(css)              → Element has specific inline styles

EXAMPLES:
  // After render(<Button disabled />)
  expect(screen.getByRole('button')).toBeDisabled();

  // After render(<input type="checkbox" checked />)
  expect(screen.getByRole('checkbox')).toBeChecked();

  // After render(<p>Hello <strong>World</strong></p>)
  expect(screen.getByText(/hello/i)).toHaveTextContent('Hello World');

  // After render(<input value="test" />)
  expect(screen.getByRole('textbox')).toHaveValue('test');

  // After render(<a href="/about">About</a>)
  expect(screen.getByRole('link')).toHaveAttribute('href', '/about');

  // After render(<div className="container active" />)
  expect(container.firstChild).toHaveClass('container');
  expect(container.firstChild).toHaveClass('container', 'active');

11. ASYMMETRIC MATCHERS
================================================================================

Used as expected values inside other matchers for flexible matching.

expect.any(constructor)
  → Matches any value of that type
  expect(user).toMatchObject({
    id: expect.any(Number),
    name: expect.any(String),
    createdAt: expect.any(Date),
  });

expect.anything()
  → Matches anything except null and undefined
  expect(mockFn).toHaveBeenCalledWith(expect.anything());

expect.stringContaining(str)
  → String that contains the substring
  expect(message).toEqual(expect.stringContaining('error'));

expect.stringMatching(regex)
  → String that matches the regex
  expect(email).toEqual(expect.stringMatching(/^[\w]+@[\w]+\.\w+$/));

expect.arrayContaining([...])
  → Array that contains all given items (in any order, can have more)
  expect(tags).toEqual(expect.arrayContaining(['react', 'testing']));

expect.objectContaining({...})
  → Object that contains at least the given properties
  expect(response).toEqual(expect.objectContaining({ status: 'success' }));

expect.not.stringContaining(str)
  → Negation of asymmetric matchers

COMBINING ASYMMETRIC MATCHERS:
  expect(apiResponse).toMatchObject({
    data: expect.arrayContaining([
      expect.objectContaining({ id: expect.any(Number) })
    ]),
    meta: expect.objectContaining({
      total: expect.any(Number),
    }),
  });

12. CUSTOM MATCHERS
================================================================================

You can extend expect with your own matchers using expect.extend():

  // In setupTests.ts or a custom matchers file
  expect.extend({
    toBeValidEmail(received: string) {
      const emailRegex = /^[\w.-]+@[\w.-]+\.\w+$/;
      const pass = emailRegex.test(received);
      return {
        pass,
        message: () =>
          pass
            ? `Expected "${received}" not to be a valid email`
            : `Expected "${received}" to be a valid email`,
      };
    },

    toBeWithinRange(received: number, floor: number, ceiling: number) {
      const pass = received >= floor && received <= ceiling;
      return {
        pass,
        message: () =>
          `Expected ${received} to be within range ${floor} - ${ceiling}`,
      };
    },
  });

  // Usage:
  expect('user@example.com').toBeValidEmail();
  expect(42).toBeWithinRange(1, 100);

TYPESCRIPT TYPES FOR CUSTOM MATCHERS:
  // global.d.ts or matchers.d.ts
  declare global {
    namespace jest {
      interface Matchers<R> {
        toBeValidEmail(): R;
        toBeWithinRange(floor: number, ceiling: number): R;
      }
    }
  }

13. QUICK REFERENCE CHEATSHEET
================================================================================

EQUALITY
  expect(x).toBe(y)                    Strict equality (===)
  expect(x).toEqual(y)                 Deep equality
  expect(x).toStrictEqual(y)           Strict deep equality

TRUTHINESS
  expect(x).toBeTruthy()               Truthy value
  expect(x).toBeFalsy()                Falsy value
  expect(x).toBeNull()                 Strictly null
  expect(x).toBeUndefined()            Strictly undefined
  expect(x).toBeDefined()              Not undefined

NUMBERS
  expect(n).toBeGreaterThan(x)
  expect(n).toBeLessThan(x)
  expect(n).toBeCloseTo(x, digits)     Floating point

STRINGS
  expect(s).toContain(substring)
  expect(s).toMatch(regex)
  expect(s).toHaveLength(n)

ARRAYS
  expect(arr).toContain(item)          Strict item check
  expect(arr).toContainEqual(item)     Deep item check
  expect(arr).toHaveLength(n)

OBJECTS
  expect(obj).toEqual({...})           Deep equality
  expect(obj).toMatchObject({...})     Partial match
  expect(obj).toHaveProperty(path)     Has property path

ERRORS
  expect(() => fn()).toThrow()
  expect(() => fn()).toThrow(Error)
  expect(() => fn()).toThrow('message')

MOCKS
  expect(mock).toHaveBeenCalled()
  expect(mock).toHaveBeenCalledTimes(n)
  expect(mock).toHaveBeenCalledWith(...args)
  expect(mock).toHaveReturnedWith(value)

DOM (jest-dom)
  expect(el).toBeInTheDocument()
  expect(el).toBeVisible()
  expect(el).toBeDisabled() / toBeEnabled()
  expect(el).toHaveTextContent(text)
  expect(el).toHaveValue(val)
  expect(el).toHaveAttribute(attr, val)
  expect(el).toHaveClass(className)
  expect(el).toHaveFocus()

ASYNC
  await expect(promise).resolves.toBe(value)
  await expect(promise).rejects.toThrow(error)
