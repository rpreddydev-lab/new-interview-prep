1. WHAT IS JEST?
================================================================================

Jest is a JavaScript testing framework created by Meta (Facebook).
It is the de facto standard test runner for JavaScript and TypeScript projects,
particularly for React applications.

CURRENT VERSION: Jest 29+ (as of 2024)
WEBSITE: https://jestjs.io

INSTALLATION:
  npm install --save-dev jest
  # For TypeScript:
  npm install --save-dev jest @types/jest ts-jest

WHAT JEST PROVIDES OUT OF THE BOX:
  ✅ Test runner (finds and executes .test.ts files)
  ✅ Assertion library (expect, matchers)
  ✅ Mocking (jest.fn(), jest.mock(), jest.spyOn())
  ✅ Snapshot testing (toMatchSnapshot, toMatchInlineSnapshot)
  ✅ Code coverage (Istanbul under the hood)
  ✅ jsdom (fake browser DOM environment)
  ✅ Parallel test execution (via worker processes)
  ✅ Watch mode (re-runs changed tests)


================================================================================
2. KEY FEATURES
================================================================================

ZERO CONFIGURATION:
  Many projects work without any Jest configuration.
  CRA (Create React App) ships with Jest pre-configured.

JSDOM ENVIRONMENT:
  Jest runs in Node.js but simulates a browser DOM via jsdom.
  This means you can test React components without a real browser.

  // Test environment options:
  // jsdom   → browser-like (default for React testing)
  // node    → pure Node.js (for API routes, server logic)

BUILT-IN MOCKING:
  Jest has first-class support for:
  - Mocking modules (jest.mock('module'))
  - Mocking functions (jest.fn())
  - Spying on existing functions (jest.spyOn())
  - Mocking timers (jest.useFakeTimers())
  - Mocking dates

SNAPSHOT TESTING:
  Capture output and detect unexpected changes:
  expect(component).toMatchSnapshot();

WATCH MODE:
  jest --watch            → Re-run tests related to changed files
  jest --watchAll         → Re-run all tests on any change
  jest --watch --verbose  → Show test names in output

PARALLEL EXECUTION:
  Jest runs test files in parallel using worker processes (child_process).
  Tests WITHIN a file run sequentially by default.


================================================================================
3. HOW JEST WORKS
================================================================================

STEP 1: DISCOVERY
  Jest searches for test files using glob patterns:
    - **/__tests__/**/*.{js,ts,tsx}
    - **/*.test.{js,ts,tsx}
    - **/*.spec.{js,ts,tsx}

STEP 2: TRANSFORMATION
  Jest transforms files before running them:
  - Babel (for JSX and modern JS syntax)
  - ts-jest or @swc/jest (for TypeScript)
  - Custom transformers for specific file types

STEP 3: ENVIRONMENT SETUP
  Jest sets up the jsdom environment (or Node.js env).
  Loads setupFiles and setupFilesAfterFramework.

STEP 4: EXECUTION
  Each test file runs in its own isolated module registry.
  Tests within a file run in order, sharing the same module cache.

STEP 5: REPORTING
  Results are collected from all workers and displayed in the terminal.
  Coverage data is aggregated if --coverage is enabled.

MODULE ISOLATION:
  Each test FILE gets a fresh module registry.
  jest.mock() hoists to the top of the file automatically.
  jest.resetModules() can be used to reset between tests within a file.


================================================================================
4. JEST ARCHITECTURE
================================================================================

COMPONENTS:

  jest-circus (default runner since Jest 27):
    Handles describe/it/test/beforeEach/afterEach organization.
    Replaced jest-jasmine2.

  jest-runtime:
    Module loading and mocking system.
    Implements require() with mock support.

  jest-environment-jsdom:
    Provides a fake DOM via jsdom.
    Required for React component testing.

  jest-snapshot:
    Snapshot serialization and comparison.

  @jest/reporters:
    Controls how test results are displayed.
    Options: default, verbose, json, lcov (coverage)

  jest-worker:
    Manages parallel execution of test files in worker processes.

EXECUTION FLOW:
  jest CLI → jest-core → jest-runtime (per file) → jest-circus
    → describe blocks collected → beforeAll/beforeEach run
    → test runs → afterEach/afterAll run → result reported

5. CORE API SUMMARY
================================================================================

GLOBAL FUNCTIONS (available in every test file):

  DESCRIBING TESTS:
    describe(name, fn)         → Group related tests
    describe.only(name, fn)    → Run ONLY this describe block
    describe.skip(name, fn)    → Skip this describe block

  DEFINING TESTS:
    it(name, fn, timeout)      → Define a single test (alias: test)
    it.only(name, fn)          → Run ONLY this test
    it.skip(name, fn)          → Skip this test
    it.todo(name)              → Placeholder for future test
    it.each(table)(name, fn)   → Run test with multiple inputs

  LIFECYCLE HOOKS:
    beforeAll(fn)              → Runs once before all tests in the block
    afterAll(fn)               → Runs once after all tests in the block
    beforeEach(fn)             → Runs before each test
    afterEach(fn)              → Runs after each test

  ASSERTIONS:
    expect(value).matcher()    → Assert a value meets expectations
    expect.assertions(n)       → Assert exactly n assertions run (useful for async)
    expect.hasAssertions()     → Assert at least 1 assertion ran

  MOCKING:
    jest.fn()                  → Create a mock function
    jest.mock(module)          → Auto-mock a module
    jest.spyOn(obj, method)    → Spy on an existing method
    jest.useFakeTimers()       → Replace real timers
    jest.useRealTimers()       → Restore real timers
    jest.clearAllMocks()       → Clear call history of all mocks
    jest.resetAllMocks()       → Reset mock implementation + call history
    jest.restoreAllMocks()     → Restore spied-on original functions

  SNAPSHOT:
    expect(value).toMatchSnapshot()
    expect(value).toMatchInlineSnapshot(`"snapshot string"`)


================================================================================
6. TEST LIFECYCLE HOOKS
================================================================================

HOOKS EXECUTE IN THIS ORDER:
  1. beforeAll (once per describe block)
  2. beforeEach (before every it/test)
  3. test body
  4. afterEach (after every it/test)
  5. afterAll (once per describe block)

NESTING BEHAVIOR:
  describe('Outer', () => {
    beforeAll(() => console.log('outer beforeAll'));
    beforeEach(() => console.log('outer beforeEach'));

    it('test 1', () => console.log('test 1'));

    describe('Inner', () => {
      beforeAll(() => console.log('inner beforeAll'));
      beforeEach(() => console.log('inner beforeEach'));

      it('test 2', () => console.log('test 2'));

      afterEach(() => console.log('inner afterEach'));
      afterAll(() => console.log('inner afterAll'));
    });

    afterEach(() => console.log('outer afterEach'));
    afterAll(() => console.log('outer afterAll'));
  });

  OUTPUT ORDER:
    outer beforeAll
    outer beforeEach → test 1 → outer afterEach
    inner beforeAll
    outer beforeEach → inner beforeEach → test 2 → inner afterEach → outer afterEach
    inner afterAll
    outer afterAll

COMMON USE CASES:

  // beforeAll: Start a server, seed a database
  beforeAll(async () => { await db.connect(); });
  afterAll(async () => { await db.disconnect(); });

  // beforeEach: Reset mocks, render component fresh
  beforeEach(() => { jest.clearAllMocks(); });

  // afterEach: Clean up DOM, clear storage
  afterEach(() => { localStorage.clear(); });

7. JEST CONFIGURATION
================================================================================

CONFIG FILE OPTIONS:
  - jest.config.js
  - jest.config.ts
  - jest.config.json
  - "jest" field in package.json

COMPLETE EXAMPLE jest.config.ts:
  import type { Config } from 'jest';

  const config: Config = {
    // Test environment
    testEnvironment: 'jsdom',  // or 'node'

    // Setup files
    setupFilesAfterFramework: ['<rootDir>/src/setupTests.ts'],

    // File transformations
    transform: {
      '^.+\\.tsx?$': ['ts-jest', { tsconfig: './tsconfig.json' }],
    },

    // Module name mapping (mocking CSS, SVGs, etc.)
    moduleNameMapper: {
      '\\.(css|scss|sass)$': 'identity-obj-proxy',
      '\\.(svg|png|jpg)$': '<rootDir>/src/__mocks__/fileMock.ts',
      '^@/(.*)$': '<rootDir>/src/$1',  // Path alias support
    },

    // Coverage
    collectCoverage: false,  // Use --coverage flag instead
    collectCoverageFrom: [
      'src/**/*.{ts,tsx}',
      '!src/**/*.d.ts',
      '!src/**/*.stories.{ts,tsx}',
      '!src/index.ts',
    ],
    coverageThreshold: {
      global: {
        branches: 80,
        functions: 80,
        lines: 80,
        statements: 80,
      }
    },
    coverageReporters: ['text', 'lcov', 'html'],

    // Test matching patterns
    testMatch: [
      '**/__tests__/**/*.{ts,tsx}',
      '**/*.{spec,test}.{ts,tsx}',
    ],

    // Ignore patterns
    testPathIgnorePatterns: ['/node_modules/', '/dist/', '/coverage/'],

    // Max workers for parallel execution
    maxWorkers: '50%',

    // Verbose output
    verbose: false,  // true shows each test name

    // Timeout per test (default: 5000ms)
    testTimeout: 10000,
  };

  export default config;

COMMON moduleNameMapper PATTERNS:
  // CSS Modules → return className as-is
  '\\.(css|scss)$': 'identity-obj-proxy',

  // Static files → empty module
  '\\.(jpg|png|svg|gif|woff2?)$': '<rootDir>/__mocks__/fileMock.js',

  // Path aliases (matching tsconfig paths)
  '^@components/(.*)$': '<rootDir>/src/components/$1',

8. RUNNING JEST
================================================================================

CLI COMMANDS:
  npx jest                         → Run all tests
  npx jest --watch                 → Watch mode (re-run changed)
  npx jest --watchAll              → Watch all tests
  npx jest --coverage              → Generate coverage report
  npx jest --verbose               → Show individual test names
  npx jest LoginForm               → Run tests matching "LoginForm"
  npx jest src/components/         → Run tests in a directory
  npx jest --testPathPattern=auth  → Run tests whose path matches "auth"
  npx jest --ci                    → CI mode (fail on new snapshots)
  npx jest --runInBand              → Run tests serially (no parallelism)
  npx jest --updateSnapshot        → Update all snapshots (-u shorthand)
  npx jest --testNamePattern="shows error"  → Run tests matching name

PACKAGE.JSON SCRIPTS:
  {
    "scripts": {
      "test": "jest",
      "test:watch": "jest --watch",
      "test:coverage": "jest --coverage --ci",
      "test:ci": "jest --ci --coverage --runInBand"
    }
  }
