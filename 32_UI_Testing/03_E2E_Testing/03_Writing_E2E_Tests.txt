1. E2E TEST ANATOMY
================================================================================

A well-structured E2E test follows AAA (Arrange, Act, Assert):

CYPRESS EXAMPLE:
  describe('Checkout Flow', () => {
    // ARRANGE — Set up state before test
    beforeEach(() => {
      cy.task('db:seed:products');
      cy.login('customer@example.com', 'password');
      cy.visit('/shop');
    });

    it('customer can complete a purchase', () => {
      // ACT — Simulate user actions
      cy.contains('Widget Pro').closest('[data-testid="product-card"]')
        .within(() => { cy.get('[data-testid="add-to-cart"]').click(); });

      cy.get('[data-testid="cart-icon"]').click();
      cy.get('[data-testid="checkout-btn"]').click();

      cy.get('[data-testid="card-number"]').type('4242424242424242');
      cy.get('[data-testid="card-expiry"]').type('12/28');
      cy.get('[data-testid="card-cvc"]').type('123');
      cy.get('[data-testid="place-order-btn"]').click();

      // ASSERT — Verify user-visible outcome
      cy.url().should('include', '/order-confirmation');
      cy.contains('Order placed successfully').should('be.visible');
      cy.get('[data-testid="order-id"]').should('not.be.empty');
    });
  });

PLAYWRIGHT EXAMPLE:
  import { test, expect } from '@playwright/test';

  test.describe('Checkout Flow', () => {
    test.beforeEach(async ({ page }) => {
      await page.goto('/shop');
    });

    test('customer can complete a purchase', async ({ page }) => {
      // Add to cart
      const productCard = page.getByTestId('product-card').filter({ hasText: 'Widget Pro' });
      await productCard.getByTestId('add-to-cart').click();

      // Go to checkout
      await page.getByTestId('cart-icon').click();
      await page.getByTestId('checkout-btn').click();

      // Fill payment
      await page.getByLabel('Card Number').fill('4242424242424242');
      await page.getByLabel('Expiry Date').fill('12/28');
      await page.getByLabel('CVC').fill('123');
      await page.getByTestId('place-order-btn').click();

      // Verify success
      await expect(page).toHaveURL(/order-confirmation/);
      await expect(page.getByText('Order placed successfully')).toBeVisible();
      await expect(page.getByTestId('order-id')).not.toBeEmpty();
    });
  });

2. IDENTIFYING WHAT TO TEST
================================================================================

FRAMEWORK: USER STORY → TEST
  "As a [role], I want to [action], so that [benefit]."
  → Becomes: "Test that a [role] can [action] and sees [expected result]"

USER STORIES THAT MAKE GREAT E2E TESTS:

  Authentication:
  - "As a new user, I can sign up with email and see welcome email"
  - "As a returning user, I can log in and access my profile"
  - "As a user, if I enter wrong password 5 times, my account is locked"
  - "As a user, I can reset my password via email link"

  Core Business Logic:
  - "As a shopper, I can search, filter, and purchase a product"
  - "As a content author, I can create, edit, and publish an article"
  - "As a project manager, I can create a project and invite team members"

  Navigation:
  - "As a user, all main navigation links take me to the correct page"
  - "As a user, the 404 page shows for unknown URLs"
  - "As a user, I am redirected to login when accessing protected pages"

AVOID TESTING THESE IN E2E:
  ❌ "The Submit button has the correct background color"
  ❌ "The error message says exactly 'Email is required'"
  ❌ "The dropdown shows 5 options"
  ❌ "The API returns 200 when given valid data"

3. TEST ISOLATION AND STATE MANAGEMENT
================================================================================

GOAL: Each test should be independent.
  - Tests should not rely on other tests having run first
  - Tests should not leave state that affects subsequent tests
  - Any test should be runnable in isolation and pass

STRATEGIES:

STRATEGY 1: Reset state in beforeEach (database, cache, storage)
  // Cypress:
  beforeEach(() => {
    cy.task('db:reset');         // Reset DB to clean state
    cy.clearCookies();
    cy.clearLocalStorage();
    cy.visit('/');
  });

  // Playwright:
  test.beforeEach(async ({ page, context }) => {
    await context.clearCookies();
    await page.evaluate(() => localStorage.clear());
  });

STRATEGY 2: Create isolated test data per test (don't rely on shared data)
  ❌ BAD — All tests depend on "Alice" existing:
  test('displays alice', async ({ page }) => {
    await page.goto('/users/alice');  // What if Alice doesn't exist?
  });

  ✅ GOOD — Create test data in the test:
  test('displays created user', async ({ page, request }) => {
    const user = await request.post('/api/users', {
      data: { email: `user_${Date.now()}@test.com`, name: 'Test User' }
    });
    const { id } = await user.json();
    await page.goto(`/users/${id}`);
    await expect(page.getByText('Test User')).toBeVisible();
  });

STRATEGY 3: API-level setup (faster than UI setup)
  // Don't navigate through UI to create test data — use API directly:
  cy.request('POST', '/api/products', { name: 'Test Widget', price: 9.99 })
    .then(({ body }) => { cy.visit(`/products/${body.id}`); });

STRATEGY 4: Use unique identifiers per test run
  const email = `test_${Date.now()}_${Math.random()}@example.com`;

4. SELECTORS BEST PRACTICES
================================================================================

PRIORITY ORDER:
  1. data-testid (most stable, not tied to visual/content)
  2. Accessible attributes (role, aria-label, label, placeholder)
  3. Text content (fragile if copy changes, but readable)
  4. CSS classes (very fragile — never use styling classes)

ADDING data-testid TO COMPONENTS:
  // React:
  <button data-testid="submit-btn" type="submit">Submit</button>
  <div data-testid="user-card">...</div>
  <form data-testid="login-form">...</form>

  // Convention: kebab-case, descriptive, unique within the page
  data-testid="search-results-list"
  data-testid="product-price"
  data-testid="delete-user-123"   // Include ID for dynamic lists

CYPRESS CUSTOM COMMAND FOR data-cy:
  Cypress.Commands.add('dataCy', (value) => cy.get(`[data-cy="${value}"]`));
  cy.dataCy('submit-btn').click();

DON'T USE:
  ❌ cy.get('.btn.btn-primary')        // CSS classes change
  ❌ cy.get('button:nth-child(2)')     // Position-based
  ❌ cy.get('#root > div > button')    // DOM structure dependent
  ❌ cy.get('[style="color: red"]')    // Style attributes

5. SMART WAITING (NEVER USE SLEEP)
================================================================================

E2E tests are asynchronous — you must wait for things to happen.
NEVER use hardcoded delays. ALWAYS use smart waits.

❌ NEVER DO THIS:
  cy.wait(3000); // Sleep 3 seconds — slow and flaky
  await page.waitForTimeout(3000); // Same problem in Playwright

✅ CYPRESS SMART WAITS:
  // Wait for element to appear:
  cy.get('[data-testid="success-message"]', { timeout: 5000 }).should('be.visible');

  // Wait for network request to complete:
  cy.intercept('POST', '/api/checkout').as('checkoutRequest');
  cy.get('[data-testid="place-order"]').click();
  cy.wait('@checkoutRequest');
  cy.get('[data-testid="confirmation"]').should('be.visible');

  // Wait for URL to change:
  cy.url().should('include', '/dashboard', { timeout: 10000 });

  // Wait for element to disappear:
  cy.get('[data-testid="loading-spinner"]').should('not.exist');

✅ PLAYWRIGHT SMART WAITS:
  // All expect() assertions auto-wait:
  await expect(page.getByText('Success')).toBeVisible(); // Waits up to 5s by default

  // Wait for navigation:
  await page.waitForURL('/dashboard');
  await expect(page).toHaveURL('/dashboard');

  // Wait for element to appear:
  await page.getByText('Loaded').waitFor();
  await page.getByText('Spinner').waitFor({ state: 'hidden' });

  // Wait for network:
  await page.waitForResponse('/api/users');
  await page.waitForLoadState('networkidle');

CYPRESS AUTO-WAITING:
  Cypress automatically waits for:
  - Elements to exist in the DOM
  - Elements to become visible
  - Animations to finish
  - XHR requests when using cy.wait('@alias')
  Default timeout: 4000ms (configurable)

6. DATA SETUP STRATEGIES
================================================================================

STRATEGY 1: Seed via API calls (fastest):
  // Playwright request context:
  test.beforeEach(async ({ request }) => {
    await request.post('http://localhost:3000/api/test/seed', {
      data: { preset: 'ecommerce-basic' }
    });
  });

  // Cypress:
  beforeEach(() => {
    cy.request('POST', '/api/test/seed', { preset: 'ecommerce-basic' });
  });

STRATEGY 2: cy.task() / globalSetup for DB operations:
  // Cypress task (runs Node.js):
  cy.task('db:createUser', { email: 'test@example.com', role: 'admin' })
    .then((user) => { cy.wrap(user.id).as('userId'); });

STRATEGY 3: Fixtures (static JSON data):
  // cypress/fixtures/checkout-product.json
  cy.fixture('checkout-product').then((product) => {
    cy.request('POST', '/api/products', product);
  });

STRATEGY 4: Factory helpers:
  // tests/helpers/factories.ts
  export async function createUser(request, overrides = {}) {
    const response = await request.post('/api/users', {
      data: { name: 'Test User', email: `test_${Date.now()}@example.com`, ...overrides }
    });
    return response.json();
  }

7. AUTHENTICATION IN E2E TESTS
================================================================================

❌ DON'T log in through the UI for every test — it's slow!

✅ STRATEGY 1: Programmatic login via API request
  // Cypress:
  Cypress.Commands.add('loginViaApi', (email, password) => {
    cy.request({
      method: 'POST',
      url: '/api/auth/login',
      body: { email, password },
    }).then(({ body }) => {
      window.localStorage.setItem('token', body.token);
      cy.setCookie('session', body.sessionId);
    });
    cy.visit('/dashboard');
  });

  beforeEach(() => {
    cy.loginViaApi('alice@example.com', 'password');
  });

✅ STRATEGY 2: Playwright storageState (save/reuse session)
  // Run once (global-setup.ts):
  const browser = await chromium.launch();
  const context = await browser.newContext();
  const page = await context.newPage();
  await page.goto('/login');
  await page.getByLabel('Email').fill('alice@example.com');
  await page.getByLabel('Password').fill('password123');
  await page.getByRole('button', { name: 'Sign In' }).click();
  await context.storageState({ path: './playwright/.auth/alice.json' });
  await browser.close();

  // playwright.config.ts:
  use: { storageState: './playwright/.auth/alice.json' }

✅ STRATEGY 3: Set cookies/localStorage directly
  // Cypress:
  beforeEach(() => {
    cy.window().then(w => {
      w.localStorage.setItem('auth', JSON.stringify(mockAuthToken));
    });
    cy.visit('/dashboard'); // No login redirect
  });

✅ STRATEGY 4: Mock auth state via API interception
  // Playwright:
  await page.route('/api/me', (route) => {
    route.fulfill({
      status: 200,
      body: JSON.stringify({ id: 1, name: 'Alice', role: 'admin' }),
    });
  });

8. TESTING FORMS
================================================================================

COMPLETE FORM TEST (Cypress):
  describe('Registration Form', () => {
    beforeEach(() => cy.visit('/register'));

    it('registers a new user with valid data', () => {
      cy.get('[data-testid="username"]').type('alice123');
      cy.get('[data-testid="email"]').type('alice@example.com');
      cy.get('[data-testid="password"]').type('SecurePass123!');
      cy.get('[data-testid="confirm-password"]').type('SecurePass123!');
      cy.get('[data-testid="terms-checkbox"]').check();
      cy.get('[data-testid="register-btn"]').click();

      cy.url().should('include', '/verify-email');
      cy.contains('Verification email sent').should('be.visible');
    });

    it('validates required fields', () => {
      cy.get('[data-testid="register-btn"]').click();
      cy.contains('Username is required').should('be.visible');
      cy.contains('Email is required').should('be.visible');
      cy.contains('Password is required').should('be.visible');
    });

    it('validates password confirmation mismatch', () => {
      cy.get('[data-testid="password"]').type('Password123!');
      cy.get('[data-testid="confirm-password"]').type('DifferentPass!');
      cy.get('[data-testid="register-btn"]').click();
      cy.contains('Passwords do not match').should('be.visible');
    });

    it('shows server-side validation errors', () => {
      cy.intercept('POST', '/api/register', {
        statusCode: 422,
        body: { errors: { email: 'Email already in use' } },
      });
      cy.get('[data-testid="email"]').type('existing@example.com');
      cy.get('[data-testid="password"]').type('Password123!');
      cy.get('[data-testid="confirm-password"]').type('Password123!');
      cy.get('[data-testid="register-btn"]').click();
      cy.contains('Email already in use').should('be.visible');
    });
  });

9. TESTING NAVIGATION AND ROUTING
================================================================================

SMOKE TEST FOR ALL MAIN ROUTES:
  const routes = [
    { path: '/', title: 'Home' },
    { path: '/about', title: 'About Us' },
    { path: '/products', title: 'Products' },
    { path: '/contact', title: 'Contact' },
  ];

  routes.forEach(({ path, title }) => {
    it(`${path} loads correctly`, () => {
      cy.visit(path);
      cy.get('h1').should('contain.text', title);
    });
  });

TESTING PROTECTED ROUTES (Redirect to Login):
  it('redirects to login when accessing protected route unauthenticated', () => {
    cy.visit('/dashboard'); // Not logged in
    cy.url().should('include', '/login');
    cy.get('[data-testid="redirect-message"]').should('contain', 'Please log in');
  });

TESTING 404 PAGE:
  it('shows 404 page for unknown routes', () => {
    cy.visit('/this-page-does-not-exist', { failOnStatusCode: false });
    cy.get('h1').should('contain.text', 'Page Not Found');
    cy.get('[data-testid="go-home-link"]').should('be.visible');
  });

TESTING BREADCRUMBS / NAVIGATION STATE:
  it('breadcrumb updates when navigating deep', async ({ page }) => {
    await page.goto('/shop');
    await page.getByRole('link', { name: 'Electronics' }).click();
    await page.getByRole('link', { name: 'Laptops' }).click();

    const breadcrumb = page.getByRole('navigation', { name: 'breadcrumb' });
    await expect(breadcrumb).toContainText('Shop');
    await expect(breadcrumb).toContainText('Electronics');
    await expect(breadcrumb).toContainText('Laptops');
  });

10. TESTING ERRORS AND EDGE CASES
================================================================================

NETWORK ERROR:
  it('shows error when API is down', () => {
    cy.intercept('GET', '/api/products', { forceNetworkError: true });
    cy.visit('/products');
    cy.get('[role="alert"]').should('contain', 'Failed to load products');
    cy.get('[data-testid="retry-btn"]').should('be.visible');
  });

SLOW NETWORK (LOADING STATE):
  it('shows loading state while fetching', () => {
    cy.intercept('GET', '/api/products', (req) => {
      req.on('response', (res) => { res.setDelay(2000); });
    }).as('slowFetch');

    cy.visit('/products');
    cy.get('[data-testid="loading-skeleton"]').should('be.visible');
    cy.wait('@slowFetch');
    cy.get('[data-testid="loading-skeleton"]').should('not.exist');
    cy.get('[data-testid="product-list"]').should('be.visible');
  });

EMPTY STATE:
  it('shows empty state when no results', () => {
    cy.intercept('GET', '/api/products*', { body: [] });
    cy.visit('/products');
    cy.contains('No products found').should('be.visible');
    cy.get('[data-testid="add-product-cta"]').should('be.visible');
  });

CONCURRENT EDITING:
  test('warns when another user modifies the record', async ({ page, context }) => {
    // User A opens document
    await page.goto('/documents/1/edit');

    // User B (different context) modifies it
    const page2 = await context.newPage();
    await page2.goto('/documents/1/edit');
    await page2.getByRole('textbox', { name: 'Title' }).fill('Updated Title');
    await page2.getByRole('button', { name: 'Save' }).click();
    await page2.close();

    // User A tries to save their version
    await page.getByRole('button', { name: 'Save' }).click();
    await expect(page.getByRole('dialog', { name: /conflict/i })).toBeVisible();
  });

11. COMMON REAL-WORLD TEST SCENARIOS
================================================================================

SCENARIO: SEARCH FUNCTIONALITY
  it('filters results as user types in search box', async ({ page }) => {
    await page.goto('/users');
    await expect(page.getByRole('listitem')).toHaveCount(10); // All users

    await page.getByRole('textbox', { name: /search/i }).fill('alice');
    await expect(page.getByRole('listitem')).toHaveCount(2); // Filtered

    await page.getByRole('textbox', { name: /search/i }).clear();
    await expect(page.getByRole('listitem')).toHaveCount(10); // Reset
  });

SCENARIO: PAGINATION
  it('navigates between pages', async ({ page }) => {
    await page.goto('/articles');
    await expect(page.getByRole('article')).toHaveCount(10);

    await page.getByRole('button', { name: 'Next page' }).click();
    await expect(page).toHaveURL(/page=2/);
    await expect(page.getByRole('article')).toHaveCount(10);

    await page.getByRole('button', { name: 'Previous page' }).click();
    await expect(page).toHaveURL(/page=1/);
  });

SCENARIO: REAL-TIME UPDATES (WebSocket)
  it('receives real-time notifications', async ({ page }) => {
    await page.goto('/notifications');
    const initialCount = await page.getByRole('listitem').count();

    // Trigger a server-side event (via API)
    await page.request.post('/api/test/trigger-notification');

    // Notification should appear without page reload:
    await expect(page.getByRole('listitem')).toHaveCount(initialCount + 1);
  });

SCENARIO: FILE DOWNLOAD
  test('downloads invoice as PDF', async ({ page }) => {
    await page.goto('/orders/123');

    const [download] = await Promise.all([
      page.waitForEvent('download'),
      page.getByRole('button', { name: 'Download Invoice' }).click(),
    ]);

    expect(download.suggestedFilename()).toBe('invoice-123.pdf');
    await download.saveAs('./test-downloads/invoice.pdf');
  });
