1. WHAT IS SSG?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Static Site Generation (SSG) pre-renders pages at BUILD TIME. The HTML is
generated once and stored on a CDN. Every user gets the same pre-built HTML —
no server computation needed per request.

  Build time → Server fetches data → React renders → HTML saved to disk
  Request time → CDN serves pre-built HTML immediately

Key properties:
  - Fastest possible page delivery (CDN edge, zero compute per request)
  - Content is the same for all users
  - Pages must be rebuilt to reflect new content (unless ISR)

Pages Router: getStaticProps() + optional getStaticPaths()
App Router:  async Server Component with caching (default behavior)

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  // pages/blog/index.tsx
  import type { GetStaticProps, NextPage } from 'next';

  interface Props {
    posts: Post[];
  }

  const BlogPage: NextPage<Props> = ({ posts }) => (
    <ul>
      {posts.map(post => (
        <li key={post.id}><a href={`/blog/${post.slug}`}>{post.title}</a></li>
      ))}
    </ul>
  );

  export const getStaticProps: GetStaticProps = async (context) => {
    const {
      params,       // dynamic route params (with getStaticPaths)
      locale,       // current locale
      locales,      // all locales
      defaultLocale,
      preview,      // is preview mode active?
      previewData,  // preview data
    } = context;

    const posts = await fetchAllBlogPosts();

    return {
      props: { posts },
      // revalidate: 60, // makes this ISR (see ISR file)
    };
  };

  export default BlogPage;

4. getStaticPaths — DYNAMIC ROUTES WITH SSG
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

When you have a dynamic route (pages/blog/[slug].tsx), Next.js must know
WHICH slugs to pre-render at build time. getStaticPaths provides this list.

  // pages/blog/[slug].tsx
  import type { GetStaticPaths, GetStaticProps } from 'next';

  export const getStaticPaths: GetStaticPaths = async () => {
    const posts = await fetchAllPosts();

    return {
      paths: posts.map(post => ({
        params: { slug: post.slug },
        // locale: 'en',  // optional for i18n
      })),
      fallback: false,  // or 'blocking' or true
    };
  };

  export const getStaticProps: GetStaticProps = async ({ params }) => {
    const post = await fetchPost(params!.slug as string);

    if (!post) return { notFound: true };

    return {
      props: { post },
      revalidate: 3600,  // re-generate every hour
    };
  };

5. FALLBACK OPTIONS EXPLAINED
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  fallback: false
    - Only paths from getStaticPaths exist; all others → 404
    - Use: small, finite set of pages (< 1000 pages)
    - Use: content that doesn't grow (old archived site)

  fallback: true
    - Unknown paths show a fallback UI while generating
    - router.isFallback === true while generating
    - Once generated, served statically for subsequent requests

    // pages/blog/[slug].tsx with fallback: true
    import { useRouter } from 'next/router';
    export default function BlogPost({ post }) {
      const router = useRouter();
      if (router.isFallback) return <div>Loading...</div>;
      return <article>{post.content}</article>;
    }

  fallback: 'blocking'
    - Unknown paths are server-side rendered (no fallback UI)
    - User waits for the page; once generated, cached as static
    - Use: content where you don't want a loading state (better SEO)
    - Like SSR for the first hit, then SSG for all subsequent

6. SSG IN APP ROUTER
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

In App Router, SSG is the DEFAULT behavior. An async Server Component that
fetches data is pre-rendered at build time automatically.

  // app/blog/page.tsx — SSG by default
  async function BlogPage() {
    const posts = await fetch('https://api.example.com/posts').then(r => r.json());
    // This fetch is cached at build time (SSG)
    return <ul>{posts.map(p => <li key={p.id}>{p.title}</li>)}</ul>;
  }

  // App Router: generateStaticParams (replaces getStaticPaths)
  // app/blog/[slug]/page.tsx
  export async function generateStaticParams() {
    const posts = await fetchAllPosts();
    return posts.map(post => ({ slug: post.slug }));
  }

  export default async function BlogPost({ params }) {
    const post = await getPost(params.slug);
    if (!post) notFound();
    return <article>{post.content}</article>;
  }

  // Control SSG/dynamic behavior:
  export const dynamic = 'force-static';   // force SSG even with dynamic data
  export const dynamic = 'force-dynamic';  // force SSR (no caching)
  export const revalidate = 3600;          // ISR: re-generate every hour

7. WHEN TO USE SSG
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  ✓ Marketing pages (/about, /pricing, /features)
  ✓ Blog posts (content changes rarely; use ISR for updates)
  ✓ Documentation sites
  ✓ Product pages with infrequent price/stock changes (use ISR)
  ✓ Landing pages and portfolios
  ✓ Any public content that is same for all users

  ✗ NOT for user-specific pages (dashboards, profiles with real-time data)
  ✗ NOT for pages with highly dynamic content (news tickers, stock prices)
  ✗ NOT when content changes so fast that builds can't keep up

8. PREVIEW MODE (Pages Router)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Preview mode allows editors to see draft content (from CMS) without publishing.
When enabled, Next.js bypasses the static page and runs getStaticProps fresh.

  // pages/api/preview.ts — enable preview
  export default function handler(req, res) {
    if (req.query.secret !== process.env.PREVIEW_SECRET) {
      return res.status(401).json({ message: 'Invalid token' });
    }
    res.setPreviewData({ userId: 'editor-id' });  // set preview cookie
    res.redirect(req.query.slug ?? '/');
  }

  // pages/api/exit-preview.ts — disable preview
  export default function handler(req, res) {
    res.clearPreviewData();
    res.redirect('/');
  }

  // In getStaticProps:
  export const getStaticProps = async ({ preview, previewData }) => {
    const post = await fetchPost({ draft: preview });  // fetch draft if preview
    return { props: { post } };
  };

  // App Router equivalent: Draft Mode (replaces Preview Mode)
  import { draftMode } from 'next/headers';

  export default async function Page() {
    const { isEnabled } = await draftMode();
    const post = await fetchPost({ draft: isEnabled });
    return <article>{post.content}</article>;
  }

9. LARGE SITE SSG STRATEGIES (100K+ pages)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Challenge: 100,000 pages at build time = very long builds.

Strategies:
  A) Build top N pages (popular/recent), fallback 'blocking' for rest:
     export const getStaticPaths = async () => ({
       paths: top1000Posts.map(p => ({ params: { slug: p.slug } })),
       fallback: 'blocking',  // on-demand generation for others
     });

  B) ISR (Incremental Static Regeneration) — build on demand, cache statically:
     export const revalidate = 3600;  // App Router

  C) Split builds — rebuild only changed content via ISR on-demand revalidation

  D) generateStaticParams with partial list (App Router):
     export const dynamicParams = true;  // default: on-demand for rest
     export async function generateStaticParams() {
       return top100Posts.map(p => ({ slug: p.slug }));
     }

10. COMMON INTERVIEW QUESTIONS & ANSWERS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q1: What is getStaticProps and when does it run?
A:  getStaticProps runs at BUILD TIME on the server. It fetches data and
    returns it as props to the page. The resulting HTML is pre-rendered once
    and served from CDN. It never runs in the browser. Use it for content
    that doesn't change per-user or per-request.

Q2: What is the difference between getStaticProps and getServerSideProps?
A:  getStaticProps runs once at build time → pre-rendered HTML on CDN (fastest)
    getServerSideProps runs on every request → fresh HTML per request (slower)
    Use getStaticProps for public, stable content; getServerSideProps for
    dynamic, user-specific, or frequently-changing content.

Q3: Why do you need getStaticPaths with getStaticProps?
A:  For dynamic routes ([slug].tsx), Next.js needs to know which URL variants
    to generate at build time. getStaticPaths returns the list of params to
    pre-render. Without it, Next.js doesn't know how many pages to create.

Q4: What is the fallback property in getStaticPaths and what are its options?
A:  false: 404 for unknown paths; true: show fallback UI while generating;
    'blocking': SSR-like behavior on first request (user waits), then cached.

Q5: Can you fetch data from a database in getStaticProps?
A:  Yes. It runs on the server, so you can use Prisma, direct SQL, file system,
    or any Node.js API. This code is NEVER included in the client bundle —
    it's completely tree-shaken out.

Q6: My blog site uses SSG. How do I handle a new post without rebuilding?
A:  Two approaches:
    (1) Add revalidate to getStaticProps → enables ISR (regenerates in background)
    (2) fallback: 'blocking' in getStaticPaths → new posts generate on first visit
    (3) ISR on-demand revalidation: trigger a revalidation webhook from CMS
        via router.revalidate('/blog/new-slug') from an API route.

  Combine with ISR to get freshness without losing SSG performance.
