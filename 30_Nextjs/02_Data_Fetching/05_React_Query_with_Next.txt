1. WHAT IS TANSTACK QUERY (REACT QUERY)?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

TanStack Query (formerly React Query) is a powerful async state management
library for React. It handles server state (data from APIs/databases) with
caching, background refetching, pagination, mutations, and more.

  Install: npm install @tanstack/react-query

Why React Query over plain useEffect:
  1. Automatic caching with stale-time control
  2. Background refetching (data stays fresh automatically)
  3. Request deduplication
  4. Loading, error, and stale states out of the box
  5. Mutation handling with rollback
  6. Devtools for debugging (critical for DX)
  7. Infinite queries / cursor-based pagination
  8. Optimistic updates
  9. Offline support

  import { useState } from 'react';

  export function QueryProvider({ children }: { children: React.ReactNode }) {
    const [queryClient] = useState(
      () =>
        new QueryClient({
          defaultOptions: {
            queries: {
              staleTime: 60 * 1000,     // 1 minute (data stays fresh)
              gcTime: 5 * 60 * 1000,    // 5 minutes garbage collection
              retry: 1,
              refetchOnWindowFocus: true,
            },
          },
        })
    );

    return (
      <QueryClientProvider client={queryClient}>
        {children}
        <ReactQueryDevtools initialIsOpen={false} />
      </QueryClientProvider>
    );
  }

  'use client';
  import { useQuery } from '@tanstack/react-query';

  interface Post { id: number; title: string; body: string; }

  // Define query functions separately for reuse
  const queryKeys = {
    posts: ['posts'] as const,
    post: (id: number) => ['posts', id] as const,
    userPosts: (userId: number) => ['posts', { userId }] as const,
  };

  async function fetchPosts(): Promise<Post[]> {
    const res = await fetch('/api/posts');
    if (!res.ok) throw new Error('Failed to fetch posts');
    return res.json();
  }

  async function fetchPost(id: number): Promise<Post> {
    const res = await fetch(`/api/posts/${id}`);
    if (!res.ok) throw new Error('Post not found');
    return res.json();
  }

  function PostsList() {
    const {
      data: posts,
      isLoading,
      isError,
      error,
      isFetching,       // true while fetching (even background)
      isStale,          // true if data is older than staleTime
      refetch,          // manually trigger refetch
    } = useQuery({
      queryKey: queryKeys.posts,
      queryFn: fetchPosts,
      staleTime: 5 * 60 * 1000,   // 5 mins; data fresh, won't re-fetch
      gcTime: 10 * 60 * 1000,     // 10 mins; cache kept this long after unmount
      refetchOnWindowFocus: false, // override global config
      select: (data) => data.filter(p => p.published),  // transform data
    });

    if (isLoading) return <PostsSkeleton />;
    if (isError) return <ErrorMessage error={error} />;

    return (
      <div>
        {isFetching && <div>Refreshing...</div>}
        {posts?.map(post => <PostCard key={post.id} post={post} />)}
        <button onClick={() => refetch()}>Refresh</button>
      </div>
    );
  }

4. useMutation — WRITING DATA
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  import { useMutation, useQueryClient } from '@tanstack/react-query';

  interface CreatePostData { title: string; body: string; }

  async function createPost(data: CreatePostData): Promise<Post> {
    const res = await fetch('/api/posts', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify(data),
    });
    if (!res.ok) throw new Error('Failed to create post');
    return res.json();
  }

  function CreatePostForm() {
    const queryClient = useQueryClient();

    const mutation = useMutation({
      mutationFn: createPost,

      // Optimistic update — update UI before server responds
      onMutate: async (newPost) => {
        await queryClient.cancelQueries({ queryKey: queryKeys.posts });
        const previousPosts = queryClient.getQueryData<Post[]>(queryKeys.posts);

        queryClient.setQueryData<Post[]>(queryKeys.posts, (old) => [
          ...(old ?? []),
          { id: Date.now(), ...newPost },
        ]);

        return { previousPosts }; // return context for rollback
      },

      // Rollback on error
      onError: (err, newPost, context) => {
        queryClient.setQueryData(queryKeys.posts, context?.previousPosts);
      },

      // Refetch after success or error
      onSettled: () => {
        queryClient.invalidateQueries({ queryKey: queryKeys.posts });
      },
    });

    const handleSubmit = (data: CreatePostData) => mutation.mutate(data);

    return (
      <form onSubmit={...}>
        {mutation.isPending && <p>Creating...</p>}
        {mutation.isError && <p>Error: {mutation.error.message}</p>}
        {mutation.isSuccess && <p>Post created!</p>}
      </form>
    );
  }

Prefetch queries on the server, hydrate client — no loading flash.

  // app/posts/page.tsx — Server Component
  import { dehydrate, HydrationBoundary, QueryClient } from '@tanstack/react-query';
  import { PostsList } from './posts-list';

  export default async function PostsPage() {
    const queryClient = new QueryClient();

    // Prefetch on server
    await queryClient.prefetchQuery({
      queryKey: ['posts'],
      queryFn: fetchPosts,
    });

    return (
      // Pass dehydrated state to client; React Query hydrates it
      <HydrationBoundary state={dehydrate(queryClient)}>
        <PostsList />
      </HydrationBoundary>
    );
  }

  // app/posts/posts-list.tsx — Client Component
  'use client';
  function PostsList() {
    // Data is already in cache from server prefetch — no loading state!
    const { data: posts } = useQuery({ queryKey: ['posts'], queryFn: fetchPosts });
    return <ul>{posts?.map(p => <li key={p.id}>{p.title}</li>)}</ul>;
  }

7. INFINITE QUERIES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  import { useInfiniteQuery } from '@tanstack/react-query';

  function InfinitePostList() {
    const {
      data,
      fetchNextPage,
      hasNextPage,
      isFetchingNextPage,
    } = useInfiniteQuery({
      queryKey: ['posts', 'infinite'],
      queryFn: ({ pageParam = 1 }) =>
        fetch(`/api/posts?page=${pageParam}&limit=10`).then(r => r.json()),
      getNextPageParam: (lastPage, pages) => {
        return lastPage.hasMore ? pages.length + 1 : undefined;
      },
      initialPageParam: 1,
    });

    const posts = data?.pages.flatMap(page => page.items) ?? [];

    return (
      <div>
        {posts.map(post => <PostCard key={post.id} post={post} />)}
        <button
          onClick={() => fetchNextPage()}
          disabled={!hasNextPage || isFetchingNextPage}
        >
          {isFetchingNextPage ? 'Loading...' : hasNextPage ? 'Load More' : 'End'}
        </button>
      </div>
    );
  }

8. staleTime vs gcTime (KEY CONCEPT)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  staleTime: how long data is considered "fresh"
    - While fresh: no background refetch even on focus/mount
    - After stale: background refetch triggered on next access
    - Default: 0 (always stale, always refetch in background)

  gcTime (was cacheTime in v4): how long inactive cache entries are kept
    - After component unmounts, cache entry lives for gcTime
    - After gcTime, cache is garbage collected
    - Default: 5 minutes

  Example:
    staleTime: 60_000   // 1 minute fresh
    gcTime: 300_000     // 5 minutes cache retention

    t=0: fetch, data fresh
    t=30s: component unmounts; cache kept for gcTime (5 min)
    t=60s: data becomes stale
    t=90s: component remounts; shows cached (stale) data, triggers refetch
    t=5min (unmounted): cache cleared

9. COMMON INTERVIEW QUESTIONS & ANSWERS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q1: What is the difference between staleTime and gcTime in React Query?
A:  staleTime controls when data is considered fresh vs stale (no refetch when
    fresh). gcTime (formerly cacheTime) controls how long the cache entry stays
    in memory after all subscribers unmount. staleTime affects refetch behavior;
    gcTime affects memory retention. staleTime can be ≤ gcTime.

Q2: How do you implement optimistic updates in React Query?
A:  In the useMutation onMutate callback:
    1. Cancel in-flight queries (cancelQueries)
    2. Snapshot current cache data (getQueryData)
    3. Optimistically update cache (setQueryData)
    4. Return snapshot as rollback context
    In onError: restore snapshot (setQueryData with context.previousData)
    In onSettled: invalidate query to refetch from server

Q3: What is the queryKey and why is it important?
A:  queryKey is the cache identifier for a query. Queries with the same key
    share cached data and refetch together. Keys should be hierarchical
    (['posts', { page: 1, filter: 'active' }]) so partial invalidation works.
    invalidateQueries({ queryKey: ['posts'] }) invalidates all queries whose
    key starts with 'posts'.

Q4: How do you prefetch React Query data on the server in App Router?
A:  Create a QueryClient in the Server Component, call prefetchQuery, dehydrate
    the state, and wrap the client component in HydrationBoundary with the
    dehydrated state. The client's React Query cache is pre-populated — no
    loading state for the initial render.

Q5: When would you choose React Query over SWR?
A:  React Query for: complex mutation workflows (optimistic updates, rollback),
    devtools (excellent visibility), offline support, cursor-based pagination,
    dependent queries, parallel queries. SWR for: simpler use cases where bundle
    size matters (<4KB vs ~13KB), Vercel ecosystem preference, minimal config.

Q6: What does invalidateQueries do?
A:  Marks matching queries as stale. If those queries have active subscribers
    (components mounted), they will immediately refetch in the background.
    If no active subscribers, they'll refetch on next access. This is the
    primary way to sync server state after a mutation.
