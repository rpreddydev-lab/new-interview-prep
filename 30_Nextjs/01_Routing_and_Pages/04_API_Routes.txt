1. WHAT ARE API ROUTES?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

API Routes allow you to build server-side API endpoints directly inside your
Next.js application — without a separate backend server. They run on Node.js
and are deployed as serverless functions.

  Pages Router: pages/api/*.ts     → Accessed at /api/*
  App Router:   app/api/*/route.ts → Accessed at /api/*

Use cases:
  - CRUD operations against a database
  - Proxying external APIs (hiding API keys)
  - Handling form submissions
  - Webhook receivers (Stripe, GitHub, etc.)
  - Auth callbacks (OAuth)
  - File uploads

  // Named exports for each HTTP method
  export async function GET(request: NextRequest) {

    return NextResponse.json(users);

  export async function POST(request: NextRequest) {
    const body = await request.json();

    { params }: { params: { id: string } }

  import { z } from 'zod';

  const CreateUserSchema = z.object({
    name: z.string().min(1, 'Name required').max(100),
    email: z.string().email('Invalid email'),
    age: z.number().int().min(0).max(150).optional(),
  });

  export async function POST(request: NextRequest) {
    const body = await request.json();
    const result = CreateUserSchema.safeParse(body);

    if (!result.success) {
      return NextResponse.json(
        { error: 'Validation failed', issues: result.error.flatten() },
        { status: 400 }
      );
    }

    const { name, email, age } = result.data;
    const user = await prisma.user.create({ data: { name, email, age } });
    return NextResponse.json(user, { status: 201 });
  }

  // app/api/webhooks/stripe/route.ts
  import Stripe from 'stripe';

  export async function POST(request: NextRequest) {
    const body = await request.text();  // raw text for signature verification
    const signature = request.headers.get('stripe-signature')!;

    let event: Stripe.Event;
    try {
      event = stripe.webhooks.constructEvent(body, signature, process.env.STRIPE_WEBHOOK_SECRET!);
    } catch (err) {
      return NextResponse.json({ error: 'Invalid signature' }, { status: 400 });
    }

    switch (event.type) {
      case 'payment_intent.succeeded':
        await handlePaymentSuccess(event.data.object as Stripe.PaymentIntent);
        break;
      case 'customer.subscription.deleted':
        await handleSubscriptionCanceled(event.data.object as Stripe.Subscription);
        break;
    }

    return NextResponse.json({ received: true });
  }

Q1: What are API routes in Next.js and when should you use them?
A:  API routes are server-side endpoint functions within the Next.js app.
    Use them for: CRUD operations, proxying external APIs (hiding secret keys),
    webhooks, auth callbacks. They replace a separate Express server for
    moderate-complexity apps. In App Router they're called Route Handlers and
    use the Web Request/Response API.

Q2: What is the difference between API routes and Server Actions?
A:  API routes are HTTP endpoints — accessed via fetch('/api/...') from client.
    Server Actions are functions called directly from components (no HTTP
    client code needed). Use Server Actions for form mutations (simple CRUD),
    and API routes for: external webhooks, requests from mobile apps/third
    parties, cases where you explicitly want an HTTP endpoint.

Q3: How do you handle different HTTP methods in App Router Route Handlers?
A:  Export named functions for each method: export async function GET() {},
    export async function POST() {}. Methods not exported automatically return
    405 Method Not Allowed.

Q4: Can you use Prisma in API routes?
A:  Yes. API routes run on Node.js (full runtime), so Prisma, fs, and other
    Node-specific packages work fine. This is different from Middleware which
    runs on the Edge Runtime and cannot use Prisma.

Q5: How do you prevent API routes from being called by unauthorized clients?
A:  (1) Check auth session/JWT in every route handler
    (2) Verify API keys in headers
    (3) Use middleware to block unauthorized requests before they reach handlers
    (4) CORS headers to restrict which origins can call the API
    (5) Rate limiting (Upstash Ratelimit)

Q6: What is the 'bodyParser' config option in Pages Router API routes?
A:  By default, Next.js parses the request body for API routes. You can disable
    this for raw body access (needed for webhook signature verification):
    export const config = { api: { bodyParser: false } };
    Then use getRawBody() or read request as a stream.
