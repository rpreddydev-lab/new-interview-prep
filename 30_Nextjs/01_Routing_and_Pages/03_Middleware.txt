1. WHAT IS NEXT.JS MIDDLEWARE?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Middleware is code that runs BEFORE a request is processed — before the page
renders, before the API route runs, before static files are served. It runs at
the Edge (CDN nodes), meaning it runs close to the user geographically.

Key characteristics:
  - Runs on the Edge Runtime (V8 isolates, NOT full Node.js)
  - Executes before the request reaches your page/API
  - Can read/modify request, set headers, redirect, rewrite URLs
  - File location: middleware.ts (or middleware.js) at the PROJECT ROOT
    (or src/ root if using src/ directory)
  - Extremely fast (no cold starts, runs in <1ms typically)

2. MIDDLEWARE BASICS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  // middleware.ts (at project root)
  import { NextResponse } from 'next/server';
  import type { NextRequest } from 'next/server';

  export function middleware(request: NextRequest) {
    // NextRequest extends the standard Request API
    const { pathname, searchParams, origin } = request.nextUrl;
    const url = request.nextUrl.clone();  // clone to modify

    // 1. Continue to the requested page (default behavior)
    return NextResponse.next();

    // 2. Redirect to another URL
    return NextResponse.redirect(new URL('/login', request.url));

    // 3. Rewrite (change the URL internally, browser URL stays same)
    return NextResponse.rewrite(new URL('/home', request.url));

    // 4. Return a response directly (e.g., for API rate limiting)
    return new NextResponse('Forbidden', { status: 403 });
  }

  // Matcher config — which paths middleware runs on
  export const config = {
    matcher: [
      '/dashboard/:path*',     // all paths under /dashboard
      '/api/:path*',           // all API routes
      '/((?!_next|favicon).*)', // all paths except Next.js internals
    ],
  };

3. MATCHER CONFIG (CRITICAL)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

The matcher controls which routes trigger your middleware function.
Without a matcher, middleware runs on EVERY request including static files
(_next/static, images, favicon) — this is usually wrong.

  export const config = {
    matcher: [
      // Match specific paths
      '/dashboard',
      '/dashboard/:path*',    // /dashboard, /dashboard/settings, etc.
      '/api/:path*',

      // Exclude Next.js internals and static files
      '/((?!_next/static|_next/image|favicon.ico).*)',

      // Multiple matchers as array
      ['/auth/:path*', '/admin/:path*'],
    ],
  };

Matcher regex:
  ':path*'  → zero or more path segments (greedy)
  ':path+'  → one or more
  ':path?'  → zero or one
  '(.*)'    → any characters
  '(?!...)' → negative lookahead (exclude pattern)

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
4. USE CASE 1: AUTHENTICATION & ROUTE PROTECTION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Most common use case. Check auth token before protected routes.

  // middleware.ts
  import { NextResponse } from 'next/server';
  import type { NextRequest } from 'next/server';
  import { jwtVerify } from 'jose';  // jose works in Edge Runtime

  export async function middleware(request: NextRequest) {
    const token = request.cookies.get('auth-token')?.value;

    // Paths that require authentication
    const protectedPaths = ['/dashboard', '/profile', '/settings'];
    const isProtected = protectedPaths.some(path =>
      request.nextUrl.pathname.startsWith(path)
    );

    if (!isProtected) return NextResponse.next();

    if (!token) {
      // Redirect to login, preserving the original URL
      const loginUrl = new URL('/login', request.url);
      loginUrl.searchParams.set('callbackUrl', request.nextUrl.pathname);
      return NextResponse.redirect(loginUrl);
    }

    try {
      await jwtVerify(token, new TextEncoder().encode(process.env.JWT_SECRET));
      return NextResponse.next();
    } catch {
      // Invalid token
      const loginUrl = new URL('/login', request.url);
      return NextResponse.redirect(loginUrl);
    }
  }

  export const config = {
    matcher: ['/dashboard/:path*', '/profile/:path*', '/settings/:path*'],
  };

A) Permanent URL migration:
  export function middleware(request: NextRequest) {
    // Old blog URL → new URL
    if (request.nextUrl.pathname.startsWith('/blog/posts/')) {
      const newPath = request.nextUrl.pathname.replace('/blog/posts/', '/articles/');
      return NextResponse.redirect(new URL(newPath, request.url), { status: 308 });
    }
    return NextResponse.next();
  }

B) A/B testing with rewrites (browser URL unchanged):
  export function middleware(request: NextRequest) {
    // Check which bucket this user is in
    const bucket = request.cookies.get('ab-test')?.value ?? (Math.random() < 0.5 ? 'a' : 'b');

    const url = request.nextUrl.clone();
    if (request.nextUrl.pathname === '/landing') {
      url.pathname = `/landing-${bucket}`;
      const response = NextResponse.rewrite(url);
      response.cookies.set('ab-test', bucket, { maxAge: 60 * 60 * 24 * 7 });
      return response;
    }
    return NextResponse.next();
  }

C) Locale-based routing:
  export function middleware(request: NextRequest) {
    const locale = getLocaleFromHeaders(request) ?? 'en';
    const { pathname } = request.nextUrl;

    // Skip if path already has a locale prefix
    if (pathname.startsWith(`/${locale}/`) || pathname === `/${locale}`) {
      return NextResponse.next();
    }

    return NextResponse.redirect(new URL(`/${locale}${pathname}`, request.url));
  }

7. USE CASE 4: RATE LIMITING (with Upstash Redis)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  import { Ratelimit } from '@upstash/ratelimit';
  import { Redis } from '@upstash/redis';

  const ratelimit = new Ratelimit({
    redis: Redis.fromEnv(),
    limiter: Ratelimit.slidingWindow(10, '10 s'),  // 10 req per 10s
  });

  export async function middleware(request: NextRequest) {
    const ip = request.ip ?? '127.0.0.1';
    const { success } = await ratelimit.limit(ip);

    if (!success) {
      return new NextResponse('Too Many Requests', { status: 429 });
    }
    return NextResponse.next();
  }

  export const config = { matcher: ['/api/:path*'] };

8. EDGE RUNTIME LIMITATIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Middleware runs on the Edge Runtime (NOT Node.js). This means:

  ✗ No Node.js built-in modules (fs, path, child_process, etc.)
  ✗ No native Node.js addons
  ✗ No Prisma client (uses native bindings)
  ✗ No heavy crypto operations (Node.js crypto API unavailable)
  ✓ Web standard APIs (fetch, Request, Response, URL, TextEncoder)
  ✓ Cookies, headers
  ✓ jose (JWT library — uses Web Crypto API)
  ✓ Lightweight HTTP calls with fetch
  ✓ Upstash Redis (HTTP-based, Edge-compatible)

If you need Node.js APIs in middleware, consider:
  - Moving logic to an API route handler (runs on Node.js)
  - Using Edge-compatible alternatives (jose instead of jsonwebtoken)

9. READING AND SETTING COOKIES & HEADERS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  export function middleware(request: NextRequest) {
    // Read cookies
    const token = request.cookies.get('session')?.value;
    const allCookies = request.cookies.getAll();

    // Read headers
    const authHeader = request.headers.get('authorization');

    // Build response and modify
    const response = NextResponse.next();

    // Set a response cookie
    response.cookies.set('new-cookie', 'value', {
      httpOnly: true,
      secure: process.env.NODE_ENV === 'production',
      sameSite: 'lax',
      maxAge: 60 * 60 * 24,  // 1 day
    });

    // Delete a cookie
    response.cookies.delete('old-cookie');

    // Set a custom header (pass data to page)
    response.headers.set('x-user-id', userId);

    return response;
  }

  // Reading the header in a Server Component:
  import { headers } from 'next/headers';
  const headersList = await headers();
  const userId = headersList.get('x-user-id');

When NOT to use middleware:
  - Complex DB queries (no Prisma/Node.js — use layout.tsx instead)
  - Long-running computations (Edge has execution time limits)
  - Operations needing Node.js-specific packages

11. COMMON INTERVIEW QUESTIONS & ANSWERS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q1: What is Next.js Middleware and where does it run?
A:  Middleware runs BEFORE a request reaches the page or API route. It runs on
    the Edge Runtime (V8 isolates on CDN nodes), meaning it executes
    geographically close to the user with no cold starts. It can redirect,
    rewrite, set headers/cookies, or return responses directly.

Q2: What is the difference between a redirect in next.config.js and in middleware?
A:  next.config.js redirects are static — configured at build time and cannot
    run dynamic logic. Middleware redirects can be conditional (check auth token,
    locale, IP, A/B bucket) and run actual code. next.config.js redirects are
    slightly faster since they're built-in to the framework's routing table.

Q3: Can you use Prisma or access a database in middleware?
A:  No. Middleware runs on the Edge Runtime which doesn't support Node.js native
    modules. Prisma uses native bindings and won't work. Use an HTTP-based
    approach (fetch to your own API), or Upstash Redis (HTTP-based) for
    lightweight lookups. For complex auth/DB checks, use layout.tsx or an API
    route handler.

Q4: How do you protect all routes under /dashboard with middleware?
A:  Add a matcher config for '/dashboard/:path*'. In the middleware function,
    check for a valid session cookie/JWT. If not present or invalid, redirect to
    /login with the original URL as a query param for redirect-after-login.

Q5: What is the difference between NextResponse.redirect() and
    NextResponse.rewrite()?
A:  redirect() changes the browser URL (client sees the new URL, makes a new
    request). Default is 307 (temporary). rewrite() changes the destination
    internally — the page served changes but the browser URL stays the same.
    Use redirect for URL migration; use rewrite for A/B testing, locale routing,
    or proxying without exposing internal URL structure.

Q6: What is the config.matcher and why is it important?
A:  matcher defines which paths trigger the middleware function. Without it,
    middleware runs on ALL requests including _next/static files and images,
    which wastes resources and can cause issues. Always set a matcher to only
    run on relevant paths.

================================================================================
  PERFORMANCE TIP: Middleware executes at the Edge with near-zero latency.
  Keep it lightweight (avoid large libraries, no DB queries). For heavy
  auth checks, use a quick JWT verify in middleware + re-validate in layout.
