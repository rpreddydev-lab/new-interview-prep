1. METADATA API OVERVIEW (APP ROUTER)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

The App Router provides a type-safe Metadata API to manage <head> content.
Two approaches:
  1. Static metadata — export a metadata object
  2. Dynamic metadata — export an async generateMetadata function

Both can be used in layout.tsx or page.tsx (not in Client Components).
Metadata is merged (deeper routes override parent routes for the same key).

  export const metadata: Metadata = {
    title: {
      template: '%s | My App',  // %s will be replaced by page titles
      default: 'My App',        // fallback when no title is set on a page
    },
    description: 'The best app on the internet',
    keywords: ['Next.js', 'React', 'TypeScript'],
    authors: [{ name: 'John Doe', url: 'https://johndoe.com' }],
    creator: 'John Doe',
    publisher: 'My Company',
    robots: {
      index: true,
      follow: true,
      googleBot: { index: true, follow: true },
    },
    openGraph: {
      type: 'website',
      locale: 'en_US',
      url: 'https://myapp.com',
      siteName: 'My App',
      title: 'My App',
      description: 'The best app on the internet',
      images: [{ url: '/og-image.jpg', width: 1200, height: 630 }],

    title: 'About Us',  // renders as "About Us | My App" (uses template)

3. DYNAMIC METADATA WITH generateMetadata
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  // app/blog/[slug]/page.tsx
  import type { Metadata, ResolvingMetadata } from 'next';

  type Props = {
    params: Promise<{ slug: string }>;
    searchParams: Promise<{ [key: string]: string | string[] | undefined }>;
  };

  export async function generateMetadata(
    { params }: Props,
    parent: ResolvingMetadata  // access parent metadata for merging
  ): Promise<Metadata> {
    const { slug } = await params;
    const post = await getPost(slug);

    // Access parent metadata:
    const parentTitle = (await parent).title?.absolute;

    if (!post) {
      return { title: 'Post Not Found' };
    }

    return {
      title: post.title,    // uses template from parent: "Post Title | My App"
      description: post.excerpt,
      openGraph: {
        title: post.title,
        description: post.excerpt,
        type: 'article',
        publishedTime: post.createdAt.toISOString(),
        authors: [post.author.name],
        images: [
          {
            url: post.coverImage ?? '/og-image.jpg',
            width: 1200,
            height: 630,
            alt: post.title,
          },
        ],
      },
      twitter: {
        card: 'summary_large_image',
        title: post.title,
        description: post.excerpt,
        images: [post.coverImage ?? '/twitter-image.jpg'],
      },
      alternates: {
        canonical: `/blog/${slug}`,  // canonical URL (relative, resolved against metadataBase)
      },
    };
  }

  // NOTE: generateMetadata and the page component can share fetch() calls.
  // Next.js deduplicates them automatically (Request Memoization).

  // Page — sets just the title
  export const metadata: Metadata = {
    title: 'Products',   // renders: "Products | Acme Corp"

  // Page — absolute title (ignores template)
  export const metadata: Metadata = {
    title: { absolute: 'Custom Title' }  // renders: "Custom Title"
  };

7. ROBOTS.TXT AND SITEMAP GENERATION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  // app/robots.ts — programmatic robots.txt
  import type { MetadataRoute } from 'next';

  export default function robots(): MetadataRoute.Robots {
    return {
      rules: {
        userAgent: '*',
        allow: '/',
        disallow: ['/admin/', '/api/'],
      },
      sitemap: 'https://myapp.com/sitemap.xml',
    };
  }

  // app/sitemap.ts — programmatic sitemap
  import type { MetadataRoute } from 'next';

  export default async function sitemap(): Promise<MetadataRoute.Sitemap> {
    const posts = await getPosts();
    const postEntries: MetadataRoute.Sitemap = posts.map(post => ({
      url: `https://myapp.com/blog/${post.slug}`,
      lastModified: post.updatedAt,
      changeFrequency: 'weekly' as const,
      priority: 0.8,
    }));

    return [
      { url: 'https://myapp.com', lastModified: new Date(), priority: 1.0 },
      { url: 'https://myapp.com/about', priority: 0.9 },
      { url: 'https://myapp.com/blog', priority: 0.9 },
      ...postEntries,
    ];
  }

  SEO checklist for each page:
    ✓ Unique, descriptive title (50-60 chars)
    ✓ Meta description (150-160 chars)
    ✓ Canonical URL (prevents duplicate content)
    ✓ Open Graph tags (og:title, og:description, og:image, og:url)
    ✓ Twitter Card tags
    ✓ Robots meta (index: true for public pages)
    ✓ metadataBase set for relative URL resolution
    ✓ Sitemap registered in robots.txt
    ✓ Alt text on all <Image> components

9. COMMON INTERVIEW QUESTIONS & ANSWERS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q1: How does the App Router handle metadata differently from Pages Router?
A:  Pages Router used <Head> from 'next/head' inside each page component —
    imperative, JSX-based, can conflict. App Router uses the Metadata API:
    export a metadata object or generateMetadata function from layout/page files.
    This is declarative, type-safe, automatically deduplicates, and merges from
    parent layouts to child pages.

Q2: What is the title template pattern and how does it work?
A:  In the root layout, set title: { template: '%s | My App', default: 'My App' }.
    Child pages export title: 'About' which renders as "About | My App".
    The %s is replaced by the page's title. The default is shown when a page
    doesn't export a title. Use absolute to completely override the template.

Q3: What is metadataBase and when is it required?
A:  metadataBase sets the base URL for resolving relative metadata URLs (e.g.,
    og:image paths). Without it, relative image paths in metadata don't resolve
    to full URLs, breaking Open Graph previews. Set it in the root layout using
    your production URL. Required for canonical URLs, OG images, sitemap URLs.

Q4: How do you generate dynamic Open Graph images in Next.js?
A:  Create opengraph-image.tsx (or .png for static) in a route segment folder.
    Export a default function that returns an ImageResponse from 'next/og'.
    ImageResponse renders JSX (with inline styles only, no Tailwind classes) to
    a PNG image. Dynamic route segments receive params as props, allowing
    per-page custom OG images.

Q5: Does generateMetadata block the page from rendering?
A:  No. Next.js streams the metadata to <head> as quickly as possible, but it
    does not block rendering the page. The page starts streaming before metadata
    resolves. However, generateMetadata and the page component share the same
    fetch() cache (Request Memoization), so DB calls are not duplicated.

Q6: How do you prevent certain pages from being indexed?
A:  In the metadata or generateMetadata, set robots: { index: false, follow: false }.
    Alternatively, use file-based robots.txt with app/robots.ts. For admin pages,
    set noindex via HTTP header (X-Robots-Tag: noindex) or in the robots.txt
    Disallow rule. Also use Middleware to redirect unauthenticated users before
    they can be crawled.
