1. WHAT IS THE EDGE RUNTIME?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

The Edge Runtime is a JavaScript runtime based on V8 (the JS engine in Chrome),
NOT Node.js. It runs as lightweight isolates at CDN edge locations worldwide
(Cloudflare Workers, Vercel Edge Network, etc.).

Key characteristics:
  - Runs code at CDN edge nodes (closest to user)
  - No cold starts (V8 isolates spin up in microseconds vs seconds for serverless)
  - Very small memory footprint (128MB limit typically)
  - Limited to Web Standard APIs (no Node.js built-ins like fs, path, crypto)
  - Designed for latency-sensitive operations

Where Edge Runtime is used in Next.js:
  - Middleware (always runs on Edge)
  - API Route Handlers (opt-in with export const runtime = 'edge')
  - Pages / App Router pages (opt-in)

2. EDGE vs NODE.JS RUNTIME COMPARISON
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Feature                     | Edge Runtime       | Node.js Runtime
  ─────────────────────────── | ────────────────── | ──────────────────────
  Underlying engine            | V8 isolate         | Node.js process
  Cold start                   | ~0ms (always warm) | 100-500ms (serverless)
  Run location                 | CDN edge globally  | Single/multi-region
  Memory limit                 | ~128MB             | 1-3GB (configurable)
  Node.js built-ins (fs,path)  | ✗                  | ✓
  npm packages requiring Node  | ✗                  | ✓
  Prisma / database drivers    | ✗ (TCP blocked)    | ✓
  Web Crypto API               | ✓                  | ✓ (Node 15+)
  Fetch API                    | ✓                  | ✓
  ReadableStream               | ✓                  | ✓
  Response streaming           | ✓                  | ✓
  Vercel KV/Edge Config        | ✓                  | ✓
  Upstash Redis (HTTP client)  | ✓                  | ✓
  jose (JWT, Edge-safe)        | ✓                  | ✓
  jsonwebtoken                 | ✗ (uses Node crypto)| ✓
  bcrypt                       | ✗ (uses Node crypto)| ✓
  bcryptjs                     | ✓ (pure JS)         | ✓

3. MIDDLEWARE (ALWAYS EDGE)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Middleware ALWAYS runs on Edge Runtime. No configuration needed.

  // middleware.ts (in project root, same level as app/)
  import { NextRequest, NextResponse } from 'next/server';
  import { jwtVerify } from 'jose'; // Edge-compatible JWT library

  const JWT_SECRET = new TextEncoder().encode(process.env.AUTH_SECRET);

  export async function middleware(request: NextRequest) {
    const token = request.cookies.get('session')?.value;

    if (!token) {
      return NextResponse.redirect(new URL('/login', request.url));
    }

    try {
      await jwtVerify(token, JWT_SECRET);
      return NextResponse.next();
    } catch {
      return NextResponse.redirect(new URL('/login', request.url));
    }
  }

  export const config = {
    matcher: ['/dashboard/:path*', '/admin/:path*'],
  };

  // app/api/geo/route.ts
  export const runtime = 'edge'; // opt into Edge runtime

  export async function GET(request: Request) {
    // Access Vercel geo headers (only available on Vercel Edge)
    const country = request.headers.get('x-vercel-ip-country');
    const city = request.headers.get('x-vercel-ip-city');
    const region = request.headers.get('x-vercel-ip-country-region');
    const timezone = request.headers.get('x-vercel-ip-timezone');

    return Response.json({ country, city, region, timezone });

5. WHAT WORKS AND WHAT DOESN'T ON EDGE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  ✓ AVAILABLE on Edge:
    - fetch() (HTTP requests, edge databases like Neon/PlanetScale)
    - Web Crypto API (crypto.subtle)
    - URL, URLSearchParams
    - Request, Response, Headers, ReadableStream
    - TextEncoder, TextDecoder
    - JSON, parseInt, etc.
    - Cookies (via NextResponse.cookies / request.cookies)
    - Environment variables (process.env)
    - setTimeout, setInterval (limited)
    - WebAssembly (on Cloudflare, limited on Vercel)

  ✗ NOT AVAILABLE on Edge:
    - Node.js fs (file system)
    - Node.js path, os, net, http, https modules
    - Node.js native crypto module (use Web Crypto API instead)
    - Prisma (uses TCP connections)
    - Any package with native binaries (bcrypt, sharp, etc.)
    - Persistent connections (no WebSocket server)

6. WHEN TO USE EDGE RUNTIME
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  ✓ Use Edge when:
    - Latency is critical (serving users globally)
    - Authentication/authorization checks (read JWT, redirect)
    - Geolocation-based routing/redirects
    - A/B testing routing
    - Rate limiting (with Upstash Redis)
    - Personalization headers
    - Lightweight request transformations
    - Streaming responses for LLM outputs (fast edge streaming)

  ✗ Avoid Edge when:
    - Need Prisma / traditional database connections
    - Heavy computation (ML inference, image processing)
    - Need Node.js libraries with native dependencies
    - Need large memory (ML models, large payloads)
    - Need to read from file system

  // PlanetScale (MySQL with HTTP driver):
  import { connect } from '@planetscale/database';
  const conn = connect({ url: process.env.DATABASE_URL });
  const results = await conn.execute('SELECT * FROM posts');

8. COMMON INTERVIEW QUESTIONS & ANSWERS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q1: What is the Edge Runtime in Next.js?
A:  A V8-based JavaScript runtime (not Node.js) that runs at CDN edge locations
    globally. It uses V8 isolates which start in microseconds (no cold starts),
    runs close to users, but has limitations: no Node.js built-ins, no Prisma,
    no native binaries. Available in Middleware and opt-in for Route Handlers/pages.

Q2: What is the key difference between Edge Runtime and Node.js Runtime?
A:  Edge Runtime: V8 isolate, runs at CDN edge, no cold starts, ~128MB memory,
    Web APIs only (no Node.js built-ins). Great for low-latency, lightweight
    operations. Node.js Runtime: full Node.js, runs in a single region, cold
    starts possible, larger memory, full Node.js ecosystem. Required for Prisma,
    file system, native modules.

Q3: Why can't you use Prisma in Edge Runtime?
A:  Prisma uses TCP connections to communicate with databases. Edge Runtime runs
    in V8 isolates that don't support TCP connections (only HTTP). Solutions:
    use HTTP-based database clients (Neon serverless, PlanetScale HTTP, Upstash),
    or use Prisma Accelerate (a proxy service that bridges HTTP to database TCP).

Q4: What JWT library should you use in Middleware (Edge)?
A:  Use jose (JavaScript Object Signing and Encryption). It's a pure JavaScript
    implementation of JWT that works with Web Crypto API. The popular jsonwebtoken
    package uses Node.js's crypto module and doesn't work in Edge Runtime.

Q5: Does Middleware always run on Edge Runtime?
A:  Yes. Middleware in Next.js always runs on Edge Runtime — you cannot opt
    it into Node.js Runtime. This is why you must use Edge-compatible packages
    (jose instead of jsonwebtoken, bcryptjs instead of bcrypt, fetch instead
    of axios for Node-http-dependent versions, etc.).

Q6: How do you rate-limit requests in Edge Middleware?
A:  Use Upstash Redis (HTTP-based, Edge-compatible) with its rate limiting
    library (@upstash/ratelimit). Store request counts in Redis by IP or user ID.
    Since Edge is stateless (no in-memory state between requests), you MUST use
    an external data store like Redis for rate limiting state.

================================================================================
  KEY INSIGHT: Edge = fastest path, but limited toolkit.
  Node.js = full power, occasional cold start.
  Middleware is ALWAYS Edge — design it to be lightweight and Edge-compatible.
