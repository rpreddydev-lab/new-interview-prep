1. WHY next/image?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Problems with plain <img> tags:
  ✗ No lazy loading by default (loads off-screen images)
  ✗ No automatic format conversion (WebP/AVIF smaller than JPEG/PNG)
  ✗ No size optimization (original 4MB image sent to mobile device)
  ✗ Cumulative Layout Shift (CLS) — images cause layout jumps without dimensions
  ✗ No responsive serving (same image for 320px and 2560px screens)

next/image solves all of these:
  ✓ Lazy loading by default (loads when entering viewport)
  ✓ Automatic WebP/AVIF conversion (smaller file sizes)
  ✓ On-demand resizing based on device and requested size
  ✓ Prevents CLS via required width/height (or fill)
  ✓ Responsive srcset generation
  ✓ Blur placeholder support
  ✓ Priority loading for LCP images

  import heroImage from '@/public/hero.jpg';

  export function Hero() {
    return (
      <Image
        src={heroImage}          // StaticImageData: includes width/height automatically
        alt="Hero banner"
        priority                 // above-the-fold: disable lazy load, preload
      />
    );
  }

  // Remote image (requires width + height, and domain in config)
  export function Avatar({ url }: { url: string }) {
    return (
      <Image
        src={url}
        alt="User avatar"
        width={80}     // required for remote images
        height={80}    // required for remote images
        className="rounded-full"
      />
    );
  }

3. REMOTE IMAGES CONFIGURATION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Remote images must be allowlisted in next.config.ts for security:

  // next.config.ts
  import type { NextConfig } from 'next';

  const config: NextConfig = {
    images: {
      remotePatterns: [
        {
          protocol: 'https',
          hostname: 'images.unsplash.com',
          port: '',
          pathname: '/**',
        },
        {
          protocol: 'https',
          hostname: '**.amazonaws.com', // wildcard subdomain
        },
        {
          protocol: 'https',
          hostname: 'cdn.example.com',
          pathname: '/uploads/**',      // only allow /uploads/ path
        },
      ],
    },
  };

  export default config;

  // Old syntax (deprecated): images.domains — only allows hostname, no path/port control
  // New syntax (recommended): images.remotePatterns — granular control

Use fill when the image should fill its parent container:

  // Full-width banner / cover image
  <div className="relative w-full h-64">
    <Image
      src="/banner.jpg"
      alt="Banner"
      fill                           // fills parent, no explicit width/height
      style={{ objectFit: 'cover' }} // or objectFit: 'contain'
      sizes="100vw"                  // hint for srcset selection
    />
  </div>

  // Product image card
  <div className="relative aspect-square">  {/* CSS aspect ratio */}
    <Image
      src={product.imageUrl}
      alt={product.name}
      fill
      style={{ objectFit: 'contain' }}
      sizes="(max-width: 768px) 50vw, 25vw"
    />
  </div>

  // IMPORTANT: Parent must have position: relative (or absolute/fixed)

5. THE sizes PROP — CRITICAL FOR PERFORMANCE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

The sizes prop tells the browser how wide the image will be at various
breakpoints. Used to generate and select the right image from srcset.

  // Without sizes: browser assumes image is 100vw → may request oversized image
  // With correct sizes: browser downloads only what it needs

  <Image
    src="/product.jpg"
    alt="Product"
    width={400}
    height={400}
    sizes="(max-width: 640px) 100vw,   // on mobile: full width
           (max-width: 1024px) 50vw,   // on tablet: half width
           33vw"                       // on desktop: 1/3 width
  />

  // Common patterns:
  sizes="100vw"                    // full-width images (hero banners)
  sizes="(max-width: 768px) 100vw, 50vw"  // responsive grid
  sizes="64px"                     // fixed small image (avatar)

  // Disables lazy loading and adds <link rel="preload"> in <head>

  <Image
    src="/hero-image.jpg"
    alt="Hero"
    width={1200}
    height={600}
    priority   // ← preloaded, not lazy loaded
  />

  // Rules:
  // - Only use priority on above-the-fold images (first screen view)
  // - Using priority on all images defeats the purpose (no lazy loading benefit)
  // - Next.js will warn if LCP image is lazy loaded without priority
  // - Typically: hero image, profile picture on profile page, first product image

  // next.config.ts — configure accepted formats
  const config: NextConfig = {
    images: {
      formats: ['image/avif', 'image/webp'],  // prefer AVIF (smaller), fallback WebP
      // Default: ['image/webp']
      // AVIF: ~50% smaller than WebP, ~70% smaller than JPEG, but slower to encode
      minimumCacheTTL: 60,          // cache optimized image for 60 seconds
      deviceSizes: [640, 750, 828, 1080, 1200, 1920, 2048, 3840],
      imageSizes: [16, 32, 48, 64, 96, 128, 256, 384],
    },
  };

  // Per-image quality (default: 75)
  <Image
    src="/photo.jpg"
    alt="Photo"
    width={800}
    height={600}
    quality={85}   // 1-100, higher = better quality but larger file
  />

9. COMMON INTERVIEW QUESTIONS & ANSWERS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q1: What does next/image do automatically that a plain <img> tag doesn't?
A:  next/image: (1) lazy loads images by default, (2) converts to WebP/AVIF format
    automatically, (3) resizes images on-demand for the requested display size,
    (4) generates srcset for responsive images, (5) prevents Cumulative Layout
    Shift (CLS) by reserving space with required width/height, (6) offers blur
    placeholder while loading.

Q2: When should you use the priority prop?
A:  Only on the Largest Contentful Paint (LCP) image — typically the hero image
    or the most prominent above-the-fold image. priority disables lazy loading
    and adds a preload link. Avoid using it on every image as it defeats lazy
    loading and can harm performance.

Q3: What's the difference between width/height props and fill?
A:  width and height specify fixed pixel dimensions — Next.js generates an
    img with those exact intrinsic dimensions. fill makes the image expand to
    cover its positioned parent container (must have position: relative). fill
    is used for responsive containers where you don't know the exact dimensions.

Q4: Why must you configure remotePatterns for external images?
A:  Security: without an allowlist, anyone could proxy any external image through
    your Next.js server (costing bandwidth). remotePatterns (previously domains)
    restricts which external hosts can serve images through the optimization API.
    It supports wildcards for subdomains and path restrictions.

Q5: What is the sizes prop and why does it matter?
A:  sizes tells the browser what width the image will occupy at various viewport
    sizes (media query syntax). The browser uses this to select the appropriate
    source from srcset. Without sizes, the browser assumes 100vw and downloads
    an unnecessarily large image. Correct sizes can save 50-80% of image bandwidth.

Q6: How does Next.js handle image optimization at the server level?
A:  Optimized images are generated ON DEMAND on first request. The result is
    cached (default: 60 seconds, configurable via minimumCacheTTL). The
    optimization uses Sharp library (included automatically). The original image
    is fetched from the source, resized, converted to WebP/AVIF, compressed,
    and the optimized version is served and cached.
