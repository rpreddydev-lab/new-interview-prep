1. PARALLEL ROUTES — OVERVIEW
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Parallel Routes allow rendering MULTIPLE pages simultaneously in the same layout.
Each parallel route is a "slot" rendered as props in the parent layout.

Use cases:
  - Dashboards with multiple independent panels
  - Split-view interfaces (list + detail)
  - Tabs where each tab is a full route
  - Admin interfaces with multiple panes

Syntax: Folders prefixed with @ define a slot.
  app/
    dashboard/
      layout.tsx        ← receives @team and @analytics as props
      page.tsx
      @team/
        page.tsx        ← /dashboard (team slot)
      @analytics/
        page.tsx        ← /dashboard (analytics slot)

2. PARALLEL ROUTES — IMPLEMENTATION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  // app/dashboard/layout.tsx
  export default function DashboardLayout({
    children,
    team,
    analytics,
  }: {
    children: React.ReactNode;
    team: React.ReactNode;       // from @team slot
    analytics: React.ReactNode; // from @analytics slot
  }) {
    return (
      <main>
        {children}
        <div className="grid grid-cols-2 gap-4">
          <section>{team}</section>
          <section>{analytics}</section>
        </div>
      </main>
    );
  }

  // app/dashboard/@team/page.tsx
  export default async function TeamPanel() {
    const members = await getTeamMembers();
    return <TeamList members={members} />;
  }

  // app/dashboard/@analytics/page.tsx
  export default async function AnalyticsPanel() {
    const stats = await getAnalytics();
    return <AnalyticsChart data={stats} />;
  }

  // Result: visiting /dashboard renders all three simultaneously:
  // - children (dashboard/page.tsx)
  // - team slot (@team/page.tsx)
  // - analytics slot (@analytics/page.tsx)

3. PARALLEL ROUTES — default.tsx (REQUIRED)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

When navigating to a sub-route of a parallel slot, other slots have no
active page for that URL. Next.js looks for default.tsx as the fallback.
Without it: 404 error.

  // app/dashboard/@analytics/default.tsx
  export default function AnalyticsDefault() {
    return null; // or a fallback UI
  }

  // Why this matters:
  // If you navigate to /dashboard/settings (matches dashboard/settings/page.tsx)
  // the @team and @analytics slots need to show SOMETHING.
  // Next.js uses @team/default.tsx and @analytics/default.tsx as fallbacks.

5. INTERCEPTED ROUTES — OVERVIEW
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Intercepted Routes allow rendering a route in a different context (like a modal)
while still allowing direct URL access to the full page.

Classic use case: Instagram/Twitter photo gallery
  - Click a photo in the feed → modal opens showing the photo
  - URL changes to /photos/42
  - Refresh or direct link to /photos/42 → full-page photo view
  - Browser back → returns to feed with modal closed

This is the "route interception" pattern: the same URL /photos/42 shows a
MODAL when navigated to from the feed, and a FULL PAGE when accessed directly.

Interception prefixes (matching segments from the calling location):
  (.)   intercept route in same directory level
  (..)  intercept route one level up
  (..)(..) intercept route two levels up
  (...) intercept route from the root app directory

6. INTERCEPTED ROUTES — FILE STRUCTURE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  app/
    layout.tsx
    page.tsx                  ← feed page (/)
    @modal/
      (.)photos/
        [id]/
          page.tsx            ← intercepted route (modal view)
      default.tsx             ← null (no modal when not intercepting)
    photos/
      [id]/
        page.tsx              ← full page photo view (/photos/42)

  // app/layout.tsx — receives @modal slot
  export default function RootLayout({
    children,
    modal,
  }: {
    children: React.ReactNode;
    modal: React.ReactNode;
  }) {
    return (
      <html><body>
        {children}
        {modal}   {/* renders the intercepted modal */}
      </body></html>
    );
  }

  // app/@modal/default.tsx
  export default function ModalDefault() {
    return null; // no modal by default
  }

  // app/@modal/(.)photos/[id]/page.tsx — INTERCEPTED VIEW (Modal)
  import { PhotoModal } from '@/components/photo-modal';

  export default async function PhotoModalPage({ params }) {
    const { id } = await params;
    const photo = await getPhoto(id);
    return <PhotoModal photo={photo} />;  // shows as a modal
  }

  // app/photos/[id]/page.tsx — FULL PAGE VIEW
  export default async function PhotoPage({ params }) {
    const { id } = await params;
    const photo = await getPhoto(id);
    return <FullPhotoView photo={photo} />; // shows as a full page
  }

7. MODAL COMPONENT WITH BACK NAVIGATION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  // components/photo-modal.tsx
  'use client';
  import { useRouter } from 'next/navigation';

  export function PhotoModal({ photo }: { photo: Photo }) {
    const router = useRouter();

    return (
      // Backdrop: click to close
      <div
        className="fixed inset-0 bg-black/60 z-50 flex items-center justify-center"
        onClick={() => router.back()}  // back navigation closes the modal
      >
        {/* Stop propagation to prevent closing when clicking content */}
        <div onClick={e => e.stopPropagation()} className="bg-white rounded-lg p-6">
          <img src={photo.url} alt={photo.title} />
          <h1>{photo.title}</h1>
          <p>{photo.description}</p>
          <button onClick={() => router.back()}>Close</button>
        </div>
      </div>
    );
  }

  // Navigation flow:
  // 1. User on / (feed)
  // 2. Clicks photo link to /photos/42
  // 3. (.) interception matches — @modal/(.)photos/42/page.tsx renders as modal
  // 4. URL shows /photos/42 but original page (feed) still visible behind modal
  // 5. router.back() → returns to feed, modal unmounts
  // 6. If user refreshes at /photos/42 → full page (photos/[id]/page.tsx)

8. INTERCEPTION LEVEL REFERENCE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Prefix  | What it intercepts
  ──────── | ──────────────────────────────────────────────────────────
  (.)     | Segments at the SAME level (folder in same directory)
  (..)    | Segments ONE level UP (parent directory)
  (..)(..)| Segments TWO levels UP
  (...)   | Segments from the APP ROOT (no matter the depth)

  Examples (intercept from app/feed/@modal/):
    (.)photos/[id]         → matches app/feed/photos/[id]     (same level)
    (..)photos/[id]        → matches app/photos/[id]          (one level up)
    (...)photos/[id]       → matches app/photos/[id]          (root level — same result here)

  Important: These match by FILE SYSTEM hierarchy, not URL path hierarchy.

9. COMBINING PARALLEL + INTERCEPTED ROUTES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

The modal pattern requires BOTH:
  - Parallel routes (@modal slot) to inject the modal into the layout
  - Intercepted routes to intercept the target URL and show modal instead

Without parallel routes: no slot to render the modal alongside the feed
Without intercepted routes: no way to show modal for /photos/42 while on feed

Together they create the "soft navigation shows modal, hard navigation shows page" pattern.

10. COMMON INTERVIEW QUESTIONS & ANSWERS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q1: What are Parallel Routes and when would you use them?
A:  Parallel Routes allow multiple independent pages to render simultaneously
    in the same layout using @slot convention. Use them for dashboards with
    multiple panels, split-view UIs, or tab interfaces where each tab is a
    separate route. Each slot receives its own loading/error states independently.

Q2: What is the purpose of default.tsx in parallel routes?
A:  When navigating to a URL that matches one slot but not others, Next.js
    needs a fallback for the unmatched slots. default.tsx provides that fallback.
    Without it, navigating to a sub-route would result in a 404 because the
    other slots have no page to render for that URL.

Q3: What are Intercepted Routes and what problem do they solve?
A:  Intercepted Routes allow the same URL to render different UI depending
    on the navigation context. Navigating to /photos/42 from the feed shows
    a modal (interception), while a direct URL or refresh shows the full page.
    This solves the UX pattern where you want overlay/modal navigation with
    proper URL updates and shareable deep links.

Q4: What's the difference between (.) and (..) in intercepted routes?
A:  They indicate file system levels for matching:
    (.) intercepts segments at the same directory level (sibling folders)
    (..) intercepts segments one level up (parent directory)
    (...) intercepts from the app root (absolute match)

Q5: If a user refreshes the page while on a modal (/photos/42), what happens?
A:  The interception only happens during CLIENT-SIDE navigation (soft nav).
    On a hard refresh or direct URL access, Next.js renders the actual page
    at that URL — the full photo page (photos/[id]/page.tsx) — not the modal.
    This is intentional: direct links should show full content.

Q6: Do parallel routes affect performance?
A:  Parallel routes render independently. Each slot can have its own loading.tsx
    and error.tsx boundaries. They fetch data in parallel, so they can actually
    improve perceived performance — if one slot is slow, others still render
    quickly. Under the hood they're separate RSC streams.

================================================================================
  KEY INSIGHT: Parallel routes = multiple pages in one layout (dashboard panels).
  Intercepted routes = same URL shows modal in-context, full page on direct access.
  Together = the "Instagram modal" pattern with proper URL semantics.
