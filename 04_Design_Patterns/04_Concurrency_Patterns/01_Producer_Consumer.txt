================================================================
  PRODUCER-CONSUMER PATTERN
================================================================

  Category:   Concurrency
  Intent:     Decouple producers that generate data from consumers that
              process it. A shared buffer absorbs rate mismatches between
              production and consumption.
  Also known: Bounded Buffer, Pipe and Filter

----------------------------------------------------------------
PROBLEM SOLVED
----------------------------------------------------------------

  Producer generates data/tasks at one rate.
  Consumer processes data at (potentially) a different rate.
  Without decoupling:
    If producer is faster: consumer overwhelmed, out of memory.
    If consumer is faster: producer and consumer must synchronize tightly.
    Tight coupling: producer must wait for consumer, or consumer spins.

  With Producer-Consumer:
    A bounded queue sits between producer and consumer.
    Producer: put items in queue (blocks if full).
    Consumer: take items from queue (blocks if empty).
    Rate mismatch absorbed by queue. Producer and consumer run independently.

----------------------------------------------------------------
JAVA BLOCKINGQUEUE IMPLEMENTATION
----------------------------------------------------------------

  BlockingQueue<T> is the standard Java mechanism:
    put(e)   -- blocks if queue full; waits until space available.
    take()   -- blocks if queue empty; waits until item available.
    offer(e, timeout, unit) -- try put with timeout; returns false if not inserted.
    poll(timeout, unit)     -- try take with timeout; returns null if nothing.

  // Shared buffer
  BlockingQueue<Task> queue = new ArrayBlockingQueue<>(100);  // bounded

  // Producer thread
  public class Producer implements Runnable {
      private final BlockingQueue<Task> queue;
      private final int id;

      public Producer(BlockingQueue<Task> queue, int id) {
          this.queue = queue;
          this.id    = id;
      }

      @Override
      public void run() {
          try {
              for (int i = 0; i < 10; i++) {
                  Task task = new Task("Producer-" + id + "-Task-" + i);
                  queue.put(task);   // blocks if full
                  System.out.println("Produced: " + task.getName());
                  Thread.sleep(100); // simulate production delay
              }
              // Poison pill to signal done (one per consumer thread)
              queue.put(Task.POISON_PILL);
          } catch (InterruptedException e) {
              Thread.currentThread().interrupt();
          }
      }
  }

  // Consumer thread
  public class Consumer implements Runnable {
      private final BlockingQueue<Task> queue;
      private final int id;

      public Consumer(BlockingQueue<Task> queue, int id) {
          this.queue = queue;
          this.id    = id;
      }

      @Override
      public void run() {
          try {
              while (true) {
                  Task task = queue.take();  // blocks if empty
                  if (task == Task.POISON_PILL) break;  // graceful shutdown
                  System.out.println("Consumer-" + id + " processing: " + task.getName());
                  Thread.sleep(200);  // simulate processing
              }
          } catch (InterruptedException e) {
              Thread.currentThread().interrupt();
          }
      }
  }

  // Task class
  public class Task {
      public static final Task POISON_PILL = new Task("POISON_PILL");
      private final String name;
      public Task(String name) { this.name = name; }
      public String getName()  { return name; }
  }

  // Main: 2 producers, 3 consumers
  public static void main(String[] args) throws InterruptedException {
      BlockingQueue<Task> queue = new ArrayBlockingQueue<>(50);
      int numConsumers = 3;

      // Start producers
      ExecutorService producerPool = Executors.newFixedThreadPool(2);
      producerPool.submit(new Producer(queue, 1));
      producerPool.submit(new Producer(queue, 2));
      producerPool.shutdown();

      // Start consumers
      ExecutorService consumerPool = Executors.newFixedThreadPool(numConsumers);
      for (int i = 1; i <= numConsumers; i++) {
          consumerPool.submit(new Consumer(queue, i));
      }

      // Wait for producers to finish, then send poison pills
      producerPool.awaitTermination(30, TimeUnit.SECONDS);
      for (int i = 0; i < numConsumers; i++) {
          queue.put(Task.POISON_PILL);   // one per consumer
      }
      consumerPool.shutdown();
      consumerPool.awaitTermination(30, TimeUnit.SECONDS);
  }

----------------------------------------------------------------
POISON PILL PATTERN (SHUTDOWN SIGNAL)
----------------------------------------------------------------

  How to signal consumers to stop:
  Option 1: POISON PILL — sentinel value that means "stop"
    Reliable, but must send one pill per consumer.
    Must be a singleton (== comparison, not equals).

  Option 2: Volatile flag
    volatile boolean running = true;
    Consumer checks: while(running) { task = queue.poll(1, SECONDS); }
    Simpler but can miss items if shutdown called during poll.

  Option 3: ExecutorService.shutdownNow()
    Interrupts all threads.
    Consumer must handle InterruptedException properly.

  Best practice: Use a combination of poison pill + interrupt handling.

----------------------------------------------------------------
QUEUE CHOICES
----------------------------------------------------------------

  ArrayBlockingQueue<T>(capacity):
    - Bounded. FIFO. Backed by array (predictable memory).
    - Fair mode available: new ArrayBlockingQueue<>(n, true) -- FIFO fairness.
    - Best for fixed-capacity scenarios.

  LinkedBlockingQueue<T>():
    - Optionally bounded (default: Integer.MAX_VALUE — effectively unbounded).
    - Separate head and tail locks → higher throughput than ArrayBlockingQueue.
    - Risk: unbounded use can cause OutOfMemoryError.
    - Best for high-throughput scenarios with bounded producers.

  PriorityBlockingQueue<T>:
    - Unbounded. Elements ordered by priority (Comparable or Comparator).
    - take() returns highest-priority element.
    - No blocking on put (unbounded).
    - Best for priority task queues.

  LinkedTransferQueue<T>:
    - Combines LinkedBlockingQueue and SynchronousQueue.
    - transfer(): blocks until a consumer is ready to receive.
    - tryTransfer(): hands off if consumer ready, else queues.
    - Best for handoff patterns.

  SynchronousQueue<T>:
    - Zero capacity. Each put() blocks until a take() happens.
    - Direct handoff between threads.
    - Used by CachedThreadPool — thread directly receives task.
    - Best for direct handoff with no buffering.

PRODUCER-CONSUMER WITH COMPLETABLEFUTURE
----------------------------------------------------------------

  Modern async alternative using CompletableFuture:

  // Async producer → consumer pipeline
  CompletableFuture
      .supplyAsync(() -> fetchData())         // produce async
      .thenApplyAsync(data -> process(data))  // consume/transform async
      .thenApplyAsync(result -> format(result))
      .thenAccept(output -> save(output))
      .exceptionally(ex -> { log(ex); return null; });

  // Parallel producers feeding one consumer
  List<CompletableFuture<Task>> producers = IntStream.range(0, 10)
      .mapToObj(i -> CompletableFuture.supplyAsync(() -> produceTask(i)))
      .collect(toList());

  CompletableFuture.allOf(producers.toArray(new CompletableFuture[0]))
      .thenRun(() -> producers.forEach(f -> consumeTask(f.join())));

----------------------------------------------------------------
PRODUCER-CONSUMER IN JAVA ECOSYSTEM
----------------------------------------------------------------

  Java Thread Pool (ExecutorService):
    Submitting Runnables IS the producer.
    Worker threads ARE the consumers.
    Internal task queue is the buffer.

  Spring @Async:
    Callers produce tasks.
    Async thread pool consumes (executes) tasks.
    Internally uses BlockingQueue in ThreadPoolTaskExecutor.

  Kafka / RabbitMQ:
    Producers write to topics/queues.
    Consumers subscribe and process.
    Broker = the bounded buffer.

  Java Stream parallel():
    Fork-Join pool uses work-stealing variant of producer-consumer.

  LMAX Disruptor:
    High-performance ring buffer replacing BlockingQueue.
    Single writer principle + cache-line padding → minimal contention.

RATE LIMITING WITH SEMAPHORE
----------------------------------------------------------------

  // Limit active producers to avoid queue overflow
  Semaphore semaphore = new Semaphore(10);  // at most 10 active producers

  public void produce(Task task) throws InterruptedException {
      semaphore.acquire();  // wait for slot
      try {
          queue.put(task);
      } finally {
          semaphore.release();  // always release
      }
  }

----------------------------------------------------------------
BACKPRESSURE
----------------------------------------------------------------

  Backpressure: consumer signals producer to slow down when overwhelmed.
  Java BlockingQueue implements backpressure naturally:
    put() blocks when queue is full — producer naturally slows down.

  Reactive Streams (Reactor, RxJava):
    Explicit backpressure with Flux.onBackpressureBuffer(), onBackpressureDrop().
    Subscriber controls demand: subscription.request(n) pulls n items.

----------------------------------------------------------------
COMPLEXITY
----------------------------------------------------------------

  Space: O(k) — k = queue capacity.
  Time:  O(1) per put()/take() in BlockingQueue.
         Producers/consumers run concurrently — throughput scales with thread count.

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: What is the Producer-Consumer pattern?
  A: Decouples producers (data generators) from consumers (data processors) via
     a shared bounded buffer (BlockingQueue). Producer blocks if queue full.
     Consumer blocks if queue empty. Absorbs rate mismatches between threads.

  Q: Which queue to use?
  A: ArrayBlockingQueue for bounded, predictable memory.
     LinkedBlockingQueue for higher throughput (optional bound).
     PriorityBlockingQueue for priority-based processing.
     SynchronousQueue for direct handoff (zero capacity).

  Q: How do you gracefully shut down consumers?
  A: Poison Pill pattern: produce a sentinel value that consumers check.
     Send one POISON_PILL per consumer thread. Consumers break their loop
     on receiving it. Also handle InterruptedException for forceful shutdown.

  Q: How does backpressure work with BlockingQueue?
  A: put() blocks when queue is at capacity. Producer thread is naturally
     throttled — it cannot outpace consumers. This IS backpressure.
     Reactive Streams make this explicit: Subscriber.request(n) signals demand.

  Q: How is ExecutorService related to Producer-Consumer?
  A: Submitting tasks to ExecutorService IS the Producer-Consumer pattern.
     Callers (producers) submit Runnable/Callable to the task queue.
     Worker threads (consumers) poll the queue and execute tasks.
     ThreadPoolExecutor uses a BlockingQueue internally.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------

  - Implement the pattern from scratch with BlockingQueue — very common ask.
  - Know all BlockingQueue implementations and their trade-offs.
  - Know the Poison Pill shutdown pattern.
  - Mention backpressure — BlockingQueue's put() blocks naturally.
  - Kafka/RabbitMQ are large-scale Producer-Consumer systems — mention them.
