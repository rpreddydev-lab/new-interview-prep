================================================================
  COMPOSITE PATTERN
================================================================

  Category:   Structural
  Intent:     Compose objects into tree structures to represent part-whole
              hierarchies. Lets clients treat individual objects and
              compositions of objects uniformly.
  GoF:        Yes — one of the original 23 patterns.
  Frequency:  Moderate. Asked when tree structures appear in design (file system,
              UI, org chart, expression trees).

----------------------------------------------------------------
PROBLEM SOLVED
----------------------------------------------------------------

  Client code needs to operate on both individual items AND groups of items
  using the same interface. Without Composite, client must check:
    "Is this a single file or a directory? Is this a single employee or a department?"

  With Composite:
    Both Leaf and Container implement the same Component interface.
    Client calls component.operation() on a leaf OR a tree — works uniformly.

  Examples:
    File system: File (leaf) + Directory (composite containing files/dirs).
    GUI: Button (leaf) + Panel (composite containing buttons/panels).
    Org chart: Employee (leaf) + Department (composite containing employees/depts).
    Math expressions: Number (leaf) + BinaryOperation (composite of two expressions).

----------------------------------------------------------------
PARTICIPANTS
----------------------------------------------------------------

  Component    -- Common interface for both leaves and composites.
  Leaf         -- No children. Implements actual behavior.
  Composite    -- Has children (List<Component>). Delegates to children.
                  Implements add(), remove(), getChild() for managing children.
  Client       -- Works only with Component interface.

----------------------------------------------------------------
STRUCTURE VISUALIZATION
----------------------------------------------------------------

  Component (interface)
    + operation()
    + add(Component)
    + remove(Component)
    + getChild(int)
         |
    _____|_____
    |         |
  Leaf      Composite
  operation()  - List<Component> children
               + operation()  <-- loops: children.forEach(c -> c.operation())
               + add(Component)
               + remove(Component)

  Client sees only Component. Whether it's a Leaf or Composite is transparent.

----------------------------------------------------------------
FULL JAVA EXAMPLE — FILE SYSTEM
----------------------------------------------------------------

  // Component
  public interface FileSystemComponent {
      String getName();
      int getSize();
      void display(String indent);
  }

  // Leaf
  public class File implements FileSystemComponent {
      private final String name;
      private final int size;

      public File(String name, int size) {
          this.name = name;
          this.size = size;
      }

      @Override public String getName()        { return name; }
      @Override public int    getSize()        { return size; }
      @Override public void   display(String indent) {
          System.out.println(indent + "File: " + name + " (" + size + "KB)");
      }
  }

  // Composite
  public class Directory implements FileSystemComponent {
      private final String name;
      private final List<FileSystemComponent> children = new ArrayList<>();

      public Directory(String name) { this.name = name; }

      public void add(FileSystemComponent c)    { children.add(c); }
      public void remove(FileSystemComponent c) { children.remove(c); }

      @Override public String getName() { return name; }

      @Override public int getSize() {
          return children.stream().mapToInt(FileSystemComponent::getSize).sum();
      }

      @Override public void display(String indent) {
          System.out.println(indent + "Dir: " + name + " (" + getSize() + "KB)");
          for (FileSystemComponent c : children) {
              c.display(indent + "  ");
          }
      }
  }

  // Client
  public class Main {
      public static void main(String[] args) {
          Directory root = new Directory("root");
          Directory docs = new Directory("docs");
          Directory src  = new Directory("src");

          docs.add(new File("readme.txt", 10));
          docs.add(new File("design.pdf", 200));

          src.add(new File("Main.java",  15));
          src.add(new File("Utils.java", 8));

          root.add(docs);
          root.add(src);
          root.add(new File("build.xml", 3));

          root.display("");
      }
  }

  Output:
    Dir: root (236KB)
      Dir: docs (210KB)
        File: readme.txt (10KB)
        File: design.pdf (200KB)
      Dir: src (23KB)
        File: Main.java (15KB)
        File: Utils.java (8KB)
      File: build.xml (3KB)

----------------------------------------------------------------
SAFE vs TRANSPARENT COMPOSITE
----------------------------------------------------------------

  TRANSPARENT (GoF default):
    Component interface includes add(), remove(), getChild().
    Both Leaf and Composite inherit these methods.
    Leaf throws UnsupportedOperationException for child management.
    + Client uses only Component; complete uniformity.
    - Leaf must implement or throw for methods that don't make sense for it.

  SAFE:
    add(), remove(), getChild() ONLY on Composite, not on Component.
    Client must cast to Composite to add children.
    + Leaf is clean — no inappropriate methods.
    - Less uniform; client needs instanceof checks.

  Common choice: Safe design in practice (avoids misleading API on Leaf).

----------------------------------------------------------------
COMPOSITE IN JAVA STANDARD LIBRARY
----------------------------------------------------------------

  Swing component hierarchy:
    java.awt.Component (Component)
      java.awt.Container extends Component (Composite)
        javax.swing.JPanel extends Container (Composite)
          javax.swing.JButton extends JComponent (Leaf)
          javax.swing.JLabel  extends JComponent (Leaf)

    panel.add(button);       // Container adds Component (Composite add)
    panel.paintAll(g);       // calls paint on all children recursively

  javax.faces.component.UIComponent:
    getChildren() returns child components.
    Uniform treatment of leaf and composite components.

  JSON/XML tree parsers:
    JsonNode in Jackson — ArrayNode (Composite) and ValueNode (Leaf).

----------------------------------------------------------------
COMPOSITE IN SPRING
----------------------------------------------------------------

  CompositeValidator:
    Wraps multiple Validator implementations.
    validate() calls validate() on each child validator.
    Client sees one Validator — transparent to the fact it's composite.

  ApplicationEventMulticaster:
    Multicasts events to all registered listeners (composite of listeners).

  Security: CompositeAuthenticationProvider (multiple providers as one).

----------------------------------------------------------------
ADDING OPERATIONS WITHOUT TOUCHING COMPOSITE
----------------------------------------------------------------

  VISITOR pattern with Composite:
    To add new operations (serialize, count, export) without touching
    the Component/Composite classes, use Visitor pattern alongside Composite.

    interface Visitor { void visit(File f); void visit(Directory d); }
    interface FileSystemComponent { void accept(Visitor v); }
    // File.accept(v) { v.visit(this); }
    // Directory.accept(v) { v.visit(this); children.forEach(c -> c.accept(v)); }

----------------------------------------------------------------
COMPOSITE WITH CACHING
----------------------------------------------------------------

  If getSize() on Directory is expensive (many children), cache the result:
    private Integer cachedSize = null;

    @Override
    public int getSize() {
        if (cachedSize == null) {
            cachedSize = children.stream().mapToInt(FileSystemComponent::getSize).sum();
        }
        return cachedSize;
    }

    // Invalidate cache on add/remove
    public void add(FileSystemComponent c) {
        children.add(c);
        cachedSize = null;
    }

----------------------------------------------------------------
COMPLEXITY
----------------------------------------------------------------

  display() / getSize() on Composite:
    Time: O(n) where n = total nodes in subtree.
    Space: O(h) call stack where h = tree height.

  Add/Remove: O(1) for ArrayList.

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: What is the Composite pattern?
  A: It composes objects into tree structures representing part-whole hierarchies.
     Both individual objects (Leaf) and groups (Composite) implement the same
     Component interface. Client can treat them uniformly without knowing which it has.

  Q: What's the difference between Composite and Decorator?
  A: Composite: tree structure — Composite has MANY children; used for part-whole hierarchies.
     Decorator: linear wrapping — wraps ONE component to add behavior; same interface.
     Both implement the same interface as what they wrap, but for different purposes.

  Q: What is "transparent" vs "safe" Composite?
  A: Transparent: add/remove on Component interface (uniform, Leaf throws UnsupportedOperationException).
     Safe: add/remove only on Composite (Leaf is clean, but client needs instanceof checks).

  Q: Give a Java standard library example of Composite.
  A: Swing's Container/Component hierarchy. JPanel (Composite) contains JButton, JLabel (Leaf).
     panel.paintAll(g) recursively paints all children. Both panels and buttons are Components.

  Q: When would you use Composite?
  A: When you need to work with tree structures (file system, UI, org chart, menus)
     and want to treat leaves and branches uniformly.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------

  - File system is the canonical example — know it cold.
  - Swing JPanel/JButton hierarchy is a solid Java standard library example.
  - Distinguish from Decorator: "tree with many children" vs "wrapping one component."
  - Know Visitor pattern alongside Composite for adding operations.
  - getSize() recursion trace shows you understand tree traversal.
