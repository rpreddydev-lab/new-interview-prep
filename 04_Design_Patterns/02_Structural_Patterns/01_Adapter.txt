================================================================
  ADAPTER PATTERN
================================================================

  Category:   Structural
  Intent:     Convert the interface of a class into another interface that
              clients expect. Lets classes work together that couldn't
              otherwise due to incompatible interfaces.
  Also known as: Wrapper
  GoF:        Yes — one of the original 23 patterns.
  Frequency:  Very common in interviews and in integration code.

----------------------------------------------------------------
PROBLEM SOLVED
----------------------------------------------------------------

  You have existing code (client) expecting interface A.
  You have a library/class with interface B.
  You cannot change either.
  You need them to work together.

  Real-world analogy:
    Power adapter: Your US laptop plug (2-pin) is incompatible with
    a European socket (2-round-pin). Adapter converts one to the other
    without changing either the laptop or the wall socket.

  Software example:
    Your app uses MediaPlayer interface to play audio.
    You want to use AdvancedMediaPlayer library (plays MP4 and VLC).
    AdvancedMediaPlayer has completely different method signatures.
    Adapter bridges them.

----------------------------------------------------------------
TWO FORMS
----------------------------------------------------------------

  Object Adapter (PREFERRED in Java):
    Adapter holds a REFERENCE to the Adaptee (composition).
    Translates calls from the Target interface to the Adaptee.
    Works even if Adaptee is final or otherwise non-subclassable.

  Class Adapter:
    Adapter INHERITS from both Target and Adaptee (multiple inheritance).
    Only possible in C++. NOT possible in Java (single inheritance).
    Java workaround: implement Target, extend Adaptee.

  In Java, always use Object Adapter (composition).

----------------------------------------------------------------
PARTICIPANTS
----------------------------------------------------------------

  Target     -- Interface that the client expects.
  Adaptee    -- Existing class with incompatible interface.
  Adapter    -- Wraps Adaptee; implements Target; translates calls.
  Client     -- Uses Target interface; unaware of Adaptee.

----------------------------------------------------------------
FULL JAVA EXAMPLE — MEDIA PLAYER
----------------------------------------------------------------

  // Target interface (what client uses)
  public interface MediaPlayer {
      void play(String audioType, String fileName);
  }

  // Adaptee interface (what the library provides)
  public interface AdvancedMediaPlayer {
      void playMp4(String fileName);
      void playVlc(String fileName);
  }

  // Concrete Adaptee implementations
  public class Mp4Player implements AdvancedMediaPlayer {
      public void playMp4(String fileName) { System.out.println("Playing MP4: " + fileName); }
      public void playVlc(String fileName) { /* not supported */ }
  }

  public class VlcPlayer implements AdvancedMediaPlayer {
      public void playMp4(String fileName) { /* not supported */ }
      public void playVlc(String fileName) { System.out.println("Playing VLC: " + fileName); }
  }

  // ADAPTER — bridges MediaPlayer and AdvancedMediaPlayer
  public class MediaAdapter implements MediaPlayer {
      private AdvancedMediaPlayer advancedPlayer;

      public MediaAdapter(String audioType) {
          if (audioType.equalsIgnoreCase("mp4")) {
              advancedPlayer = new Mp4Player();
          } else if (audioType.equalsIgnoreCase("vlc")) {
              advancedPlayer = new VlcPlayer();
          }
      }

      @Override
      public void play(String audioType, String fileName) {
          if (audioType.equalsIgnoreCase("mp4")) {
              advancedPlayer.playMp4(fileName);
          } else if (audioType.equalsIgnoreCase("vlc")) {
              advancedPlayer.playVlc(fileName);
          }
      }
  }

  // Client — only knows MediaPlayer
  public class AudioPlayer implements MediaPlayer {
      @Override
      public void play(String audioType, String fileName) {
          if (audioType.equalsIgnoreCase("mp3")) {
              System.out.println("Playing MP3: " + fileName);
          } else if (audioType.equalsIgnoreCase("mp4") || audioType.equalsIgnoreCase("vlc")) {
              MediaAdapter adapter = new MediaAdapter(audioType);
              adapter.play(audioType, fileName);
          } else {
              System.out.println("Invalid format: " + audioType);
          }
      }
  }

  // Usage
  AudioPlayer player = new AudioPlayer();
  player.play("mp3", "song.mp3");    // Playing MP3: song.mp3
  player.play("mp4", "movie.mp4");   // Playing MP4: movie.mp4
  player.play("vlc", "video.vlc");   // Playing VLC: video.vlc

SIMPLER EXAMPLE — LEGACY + NEW SYSTEM INTEGRATION
----------------------------------------------------------------

  // New system expects
  public interface NewPaymentService {
      void processPayment(String userId, double amount);
  }

  // Legacy system (Adaptee — can't change)
  public class LegacyPaymentSystem {
      public void makePayment(int customerId, float amount, String currency) {
          System.out.println("Legacy payment: " + customerId + " -> " + amount + " " + currency);
      }
  }

  // Adapter
  public class PaymentAdapter implements NewPaymentService {
      private final LegacyPaymentSystem legacy = new LegacyPaymentSystem();

      @Override
      public void processPayment(String userId, double amount) {
          int customerId = Integer.parseInt(userId);
          legacy.makePayment(customerId, (float) amount, "USD");
      }
  }

  // Client uses NewPaymentService — never knows about LegacyPaymentSystem
  NewPaymentService service = new PaymentAdapter();
  service.processPayment("42", 99.99);

ADAPTER IN JAVA STANDARD LIBRARY
----------------------------------------------------------------

  Arrays.asList(T[] arr)
    - Adapts a fixed-size array to the java.util.List interface.
    - Returns a fixed-size List backed by the array (no add/remove).

  Collections.enumeration(Collection c)
    - Adapts a Collection to the old Enumeration interface.

  Collections.list(Enumeration e)
    - Adapts old Enumeration to ArrayList.

  InputStreamReader(InputStream in)
    - Adapts byte-based InputStream to character-based Reader interface.

  OutputStreamWriter(OutputStream out)
    - Same: adapts byte stream to char Writer.

  java.io.PrintStream
    - Adapts raw OutputStream into a human-friendly print API.

----------------------------------------------------------------
ADAPTER IN SPRING
----------------------------------------------------------------

  HandlerAdapter (Spring MVC):
    - Spring DispatcherServlet calls HandlerAdapter.handle(request, response, handler).
    - Different HandlerAdapters for @Controller, Servlet, HttpRequestHandler.
    - Each adapts different controller types to a uniform handleRequest() interface.

  AuthenticationProvider adapter:
    - Multiple authentication strategies (LDAP, JDBC, OAuth) adapted to
      a common AuthenticationProvider interface.

  Spring Integration channel adapters:
    - Adapts external systems (JMS, HTTP, FTP) to Spring's MessageChannel interface.

----------------------------------------------------------------
ADAPTER vs DECORATOR vs FACADE
----------------------------------------------------------------

  Adapter:
    Changes the INTERFACE. Client talks to Target; Adapter wraps Adaptee.
    "Make incompatible things compatible."

  Decorator:
    Keeps the SAME interface. Adds behavior while preserving interface.
    "Same interface, extra behavior."

  Facade:
    Provides a SIMPLIFIED interface. May wrap many classes into one entry point.
    "Same or different interface, but simpler."

  Key: Adapter = interface translation. Decorator = behavior addition. Facade = simplification.

----------------------------------------------------------------
COMPLEXITY
----------------------------------------------------------------

  Time: O(1) per call — adapter just translates and delegates.
  Space: O(1) — stores one reference to Adaptee.
  No performance concern in practice.

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: What is the Adapter pattern?
  A: It converts one interface into another that clients expect.
     Wraps an existing class (Adaptee) with a new class (Adapter) that
     implements the Target interface. Client works with Adapter through
     the Target interface, unaware of the Adaptee.

  Q: What's the difference between Object Adapter and Class Adapter?
  A: Object Adapter uses composition — holds reference to Adaptee.
     Class Adapter uses multiple inheritance — inherits from both Target and Adaptee.
     In Java, only Object Adapter is possible (no multiple class inheritance).

  Q: How is Adapter different from Decorator?
  A: Adapter changes the interface (client uses a different interface than Adaptee).
     Decorator keeps the same interface and adds behavior transparently.

  Q: Give a real-world Java example of Adapter.
  A: InputStreamReader adapts InputStream (bytes) to Reader (chars).
     Arrays.asList adapts arrays to List interface.
     Spring HandlerAdapter adapts different controller types to DispatcherServlet.

  Q: When should I use Adapter?
  A: When you need to use an existing class but its interface doesn't match
     what your code expects, and you can't modify either side. Common in
     legacy integration, third-party library usage, and API migration.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------

  - Adapter = "translate the interface" — keep this one-liner ready.
  - InputStreamReader is the canonical Java standard library example.
  - Spring HandlerAdapter shows you know Spring internals.
  - Always distinguish from Decorator (same interface) and Facade (simplification).
  - Code the Object Adapter: implement Target interface + hold Adaptee as field.
