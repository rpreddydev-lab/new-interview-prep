================================================================
  FLYWEIGHT PATTERN
================================================================

  Category:   Structural
  Intent:     Use sharing to efficiently support a large number of
              fine-grained objects. Reduce memory overhead by sharing
              common state across many objects.
  GoF:        Yes — one of the original 23 patterns.
  Frequency:  Moderate in interviews. Often asked in context of memory
              optimization, string interning, or Integer caching.

----------------------------------------------------------------
PROBLEM SOLVED
----------------------------------------------------------------

  A large number of similar objects consume too much memory.
  Many of those objects share identical state.
  Rather than storing that state in each object, share it.

  Example: Word processor
    Document with 100,000 characters.
    Each character has: char value, font, size, color.
    Without Flyweight: 100,000 full objects, each storing all attributes.
    With Flyweight: font/size/color (intrinsic) shared across same chars.
                    Only position (extrinsic) stored per-instance context.

  Example: Game with 10,000 tree objects on a map.
    Without Flyweight: 10,000 objects each holding texture data (5MB each = 50GB!)
    With Flyweight: 5 tree types, shared texture. 10,000 context objects (position, scale).
                    5 × 5MB texture + 10,000 × tiny context = ~25MB total.

----------------------------------------------------------------
CORE CONCEPT: INTRINSIC vs EXTRINSIC STATE
----------------------------------------------------------------

  INTRINSIC STATE (shared):
    - Stored IN the Flyweight object.
    - Independent of context — same for all uses of this flyweight.
    - Examples: char value, font name, color, texture, sprite image.
    - Immutable.

  EXTRINSIC STATE (context-specific):
    - Stored OUTSIDE the flyweight (in client or context object).
    - Depends on context — different for each use.
    - Examples: position (x,y), timestamp, parent container.
    - Passed as parameter to flyweight's methods.

  KEY RULE: If state is context-independent and repeated → make it intrinsic (shared).
            If state varies per use → extrinsic (pass at call time).

----------------------------------------------------------------
PARTICIPANTS
----------------------------------------------------------------

  Flyweight (interface)    -- Interface for flyweight objects; operation(extrinsicState).
  ConcreteFlyweight        -- Stores intrinsic state. Implements operation().
  FlyweightFactory         -- Creates/manages flyweight pool. Returns shared instances.
  Client                   -- Holds extrinsic state. Gets flyweight from factory.
                              Calls flyweight.operation(extrinsicState).
  UnsharedConcreteFlyweight -- Not all flyweights must be shared (e.g., composite nodes).

----------------------------------------------------------------
FULL JAVA EXAMPLE — FOREST RENDERING
----------------------------------------------------------------

  // Flyweight — holds intrinsic state (tree type data)
  public class TreeType {
      private final String name;
      private final String color;
      private final String texture;   // large texture data

      public TreeType(String name, String color, String texture) {
          this.name = name; this.color = color; this.texture = texture;
      }

      // Render with extrinsic state (x, y) passed in
      public void draw(int x, int y) {
          System.out.println("Drawing " + name + " [" + color + "] at (" + x + "," + y + ")");
      }
  }

  // FlyweightFactory — manages shared pool
  public class TreeTypeFactory {
      private static final Map<String, TreeType> pool = new HashMap<>();

      public static TreeType get(String name, String color, String texture) {
          String key = name + color;
          pool.computeIfAbsent(key, k -> new TreeType(name, color, texture));
          return pool.get(key);
      }

      public static int count() { return pool.size(); }
  }

  // Context — holds extrinsic state + reference to flyweight
  public class Tree {
      private final int x, y;                  // extrinsic state
      private final TreeType type;             // shared flyweight

      public Tree(int x, int y, TreeType type) {
          this.x = x; this.y = y; this.type = type;
      }

      public void draw() {
          type.draw(x, y);
      }
  }

  // Client
  public class Forest {
      private final List<Tree> trees = new ArrayList<>();

      public void plantTree(int x, int y, String name, String color, String texture) {
          TreeType type = TreeTypeFactory.get(name, color, texture);
          trees.add(new Tree(x, y, type));
      }

      public void draw() {
          trees.forEach(Tree::draw);
      }

      public static void main(String[] args) {
          Forest forest = new Forest();
          // 10,000 trees but only 3 distinct types created
          for (int i = 0; i < 5000; i++) forest.plantTree(i, i*2, "Oak",   "Green",  "oak_texture");
          for (int i = 0; i < 3000; i++) forest.plantTree(i, i*3, "Pine",  "DarkGreen","pine_texture");
          for (int i = 0; i < 2000; i++) forest.plantTree(i, i*4, "Birch", "White",  "birch_texture");

          System.out.println("TreeType objects created: " + TreeTypeFactory.count()); // 3
          System.out.println("Tree objects created:     " + forest.trees.size());     // 10000
      }
  }

FLYWEIGHT IN JAVA STANDARD LIBRARY
----------------------------------------------------------------

  1. Integer Cache (Integer.valueOf(-128 to 127)):
     ---
     Integer a = Integer.valueOf(100);
     Integer b = Integer.valueOf(100);
     System.out.println(a == b);   // true  — same cached object
     Integer c = Integer.valueOf(200);
     Integer d = Integer.valueOf(200);
     System.out.println(c == d);   // false — new objects (outside cache range)

     JVM caches Integer objects for values -128 to 127.
     Also: Byte, Short, Long (-128..127), Character (0..127), Boolean.

  2. String Interning:
     ---
     String s1 = "hello";         // from string pool (interned)
     String s2 = "hello";         // same object from pool
     String s3 = new String("hello"); // new object on heap (NOT pooled)
     System.out.println(s1 == s2); // true
     System.out.println(s1 == s3); // false
     System.out.println(s1 == s3.intern()); // true — intern puts back in pool

     String.intern() forces a string into the pool for sharing.

  3. Font and Color in GUI (AWT/Swing):
     Font and Color objects are shared when the same values are requested.

----------------------------------------------------------------
FLYWEIGHT vs OBJECT POOL
----------------------------------------------------------------

  Flyweight:
    - Immutable intrinsic state.
    - Shared CONCURRENTLY by many clients simultaneously.
    - No "check out / return" — just reference and use.
    - Reduces MEMORY overhead.

  Object Pool:
    - Mutable objects.
    - EXCLUSIVE access — one client at a time.
    - Objects checked out and returned.
    - Reduces CREATION/DESTRUCTION overhead.

  Key: Flyweight = shared immutable state for memory savings.
       Object Pool = reuse expensive-to-create mutable objects.

----------------------------------------------------------------
WHEN TO USE FLYWEIGHT
----------------------------------------------------------------

  Use when ALL of the following are true:
    1. Application uses a large number of objects.
    2. Storage costs are high due to the sheer quantity.
    3. Most object state can be made extrinsic (context-dependent).
    4. Many groups of objects share common intrinsic state.
    5. Application does not depend on object identity (shared objects).

  DON'T use if:
    - Objects are few in number.
    - Adding extrinsic state management complexity outweighs savings.
    - Objects need to be distinct (identity matters).

----------------------------------------------------------------
COMPLEXITY
----------------------------------------------------------------

  Memory:      Reduced from O(n) to O(k + n) where k = distinct flyweights
               (k << n), n = context objects.
  Lookup:      O(1) with HashMap factory.
  Trade-off:   CPU increases slightly (extrinsic state must be computed/passed).
               Code complexity increases (extrinsic/intrinsic separation).

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: What is the Flyweight pattern?
  A: Share objects to reduce memory overhead when a large number of similar
     objects are needed. Separate shared (intrinsic) state from context-specific
     (extrinsic) state. Flyweight stores intrinsic state; extrinsic state is passed
     at operation time.

  Q: What's the difference between intrinsic and extrinsic state?
  A: Intrinsic state: stored in flyweight, same for all uses, immutable (e.g., font, texture).
     Extrinsic state: varies per use, passed as parameter (e.g., position, timestamp).

  Q: Give a Java standard library example of Flyweight.
  A: Integer.valueOf() cache for -128..127. String pool interning.
     Both cache/share objects to avoid redundant memory allocation.

  Q: Why is `Integer.valueOf(100) == Integer.valueOf(100)` true but `Integer.valueOf(200) == Integer.valueOf(200)` false?
  A: JVM caches Integer objects for -128 to 127. valueOf(100) returns the cached instance.
     valueOf(200) creates new objects each time since 200 is outside the cache range.

  Q: How is Flyweight different from Object Pool?
  A: Flyweight shares immutable objects concurrently. Object Pool reuses mutable objects
     exclusively (check out / check in). Flyweight saves memory; Pool saves creation time.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------

  - Integer cache and String interning are the go-to Java examples — know them cold.
  - Always explain intrinsic vs extrinsic state — core concept of the pattern.
  - Distinguish from Object Pool: shared immutable vs exclusive mutable reuse.
  - Game example (tree forest, bullets) is intuitive for large-scale use case.
  - Flyweight is often asked alongside memory optimization questions.
