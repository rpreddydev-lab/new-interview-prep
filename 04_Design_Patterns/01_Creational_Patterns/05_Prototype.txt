================================================================
  PROTOTYPE PATTERN
================================================================

  Category:   Creational
  Intent:     Create new objects by copying (cloning) an existing object
              (the prototype) rather than creating from scratch.
  GoF:        Yes — one of the original 23 patterns.
  Frequency:  Moderate in interviews. Commonly asked alongside clone(),
              shallow vs deep copy, and Java's Cloneable interface.

----------------------------------------------------------------
PROBLEM SOLVED
----------------------------------------------------------------

  Object creation is expensive or complex (heavy initialization, DB queries,
  network calls, complex calculations). If you need many similar objects,
  cloning an existing "template" object is cheaper than constructing fresh.

  Also useful when:
    - The exact class to instantiate is determined at runtime.
    - You need a copy of an object, tweaked slightly.
    - A class hierarchy of constructors is complex.

  Examples:
    - Game: Enemy prototype (stats loaded from DB once). Clone for each instance.
    - Document editor: template document cloned for new documents.
    - Spring: prototype-scope beans (new instance per injection, cloned from template).

----------------------------------------------------------------
PARTICIPANTS
----------------------------------------------------------------

  Prototype (interface/abstract class)
    Declares the clone() method.

  ConcretePrototype
    Implements clone(). Returns a copy of itself.

  Client
    Creates new objects by calling clone() on a prototype.
    Never calls new DirectlyOnConcreteClass.

----------------------------------------------------------------
JAVA IMPLEMENTATION — Cloneable INTERFACE
----------------------------------------------------------------

  Java's built-in mechanism: implement Cloneable marker interface + override clone().

  // Shallow Clone Example
  public class Circle implements Cloneable {
      private int radius;
      private Point center;            // reference type — SHALLOW copy copies reference

      public Circle(int radius, Point center) {
          this.radius = radius;
          this.center = center;
      }

      @Override
      public Circle clone() {
          try {
              return (Circle) super.clone();   // shallow copy
          } catch (CloneNotSupportedException e) {
              throw new RuntimeException("Clone not supported", e);
          }
      }
  }

  // SHALLOW CLONE PROBLEM:
  Circle c1 = new Circle(5, new Point(0, 0));
  Circle c2 = c1.clone();
  c2.center.x = 10;         // ALSO changes c1.center.x ! (shared reference)

----------------------------------------------------------------
DEEP CLONE — COPYING REFERENCE FIELDS
----------------------------------------------------------------

  public class Employee implements Cloneable {
      private String name;
      private List<String> skills;        // mutable reference — must deep copy

      public Employee(String name, List<String> skills) {
          this.name   = name;
          this.skills = new ArrayList<>(skills);
      }

      @Override
      public Employee clone() {
          try {
              Employee copy = (Employee) super.clone();
              copy.skills = new ArrayList<>(this.skills);   // deep copy of list
              return copy;
          } catch (CloneNotSupportedException e) {
              throw new RuntimeException(e);
          }
      }

      @Override
      public String toString() {
          return "Employee{name=" + name + ", skills=" + skills + "}";
      }
  }

  // Test
  Employee e1 = new Employee("Alice", new ArrayList<>(List.of("Java", "SQL")));
  Employee e2 = e1.clone();
  e2.skills.add("Python");

  System.out.println(e1.skills); // [Java, SQL]       -- unchanged
  System.out.println(e2.skills); // [Java, SQL, Python]

----------------------------------------------------------------
COPY CONSTRUCTOR APPROACH (PREFERRED OVER Cloneable)
----------------------------------------------------------------

  Josh Bloch (Effective Java): "The Cloneable interface is broken.
  Prefer copy constructors or copy factory methods."

  Problems with Cloneable:
    - clone() must return super.clone() — fragile contract.
    - CloneNotSupportedException is checked but Cloneable doesn't declare it.
    - clone() bypasses the constructor — doesn't call your constructor.
    - Final fields can't be assigned in clone() (they're already set by super.clone()).

  Copy Constructor (preferred):
    public Employee(Employee source) {
        this.name   = source.name;
        this.skills = new ArrayList<>(source.skills);
    }
    // Usage: Employee e2 = new Employee(e1);

  Copy Factory Method:
    public static Employee copyOf(Employee source) {
        return new Employee(source.name, new ArrayList<>(source.skills));
    }

----------------------------------------------------------------
PROTOTYPE REGISTRY
----------------------------------------------------------------

  When multiple prototype types exist, a registry stores named prototypes.
  Clients request a clone by name — no knowledge of concrete classes needed.

    public class ShapeRegistry {
        private static final Map<String, Shape> registry = new HashMap<>();

        static {
            registry.put("circle", new Circle(1, new Point(0,0)));
            registry.put("square", new Square(1, new Point(0,0)));
        }

        public static Shape get(String type) {
            Shape prototype = registry.get(type);
            if (prototype == null) throw new IllegalArgumentException("No prototype: " + type);
            return prototype.clone();
        }
    }

    // Client
    Shape c = ShapeRegistry.get("circle");   // cloned from registry prototype

----------------------------------------------------------------
SHALLOW vs DEEP COPY — DECISION TABLE
----------------------------------------------------------------

  Field Type            Shallow Copy Effect              Deep Copy Needed?
  --------------------  -----------------------------    -----------------
  Primitive (int, etc.) New copy automatically           No
  String (immutable)    Safe — strings are immutable     No
  Immutable objects     Safe                             No
  Mutable objects       Shared reference (DANGER!)       YES
  Collections (List etc.)  Same elements, same list obj  YES (new list + copy elements)
  Nested mutable objects    All nested shared             YES (recursive deep copy)

  Rule: If a field is mutable and shared, you need deep copy.

----------------------------------------------------------------
DEEP COPY VIA SERIALIZATION (QUICK BUT EXPENSIVE)
----------------------------------------------------------------

  For truly deep copies of complex object graphs, serialization is a quick approach.
  All referenced objects must be Serializable.

    public <T extends Serializable> T deepCopy(T obj) {
        try {
            ByteArrayOutputStream bos = new ByteArrayOutputStream();
            ObjectOutputStream oos = new ObjectOutputStream(bos);
            oos.writeObject(obj);
            ByteArrayInputStream bis = new ByteArrayInputStream(bos.toByteArray());
            ObjectInputStream ois = new ObjectInputStream(bis);
            return (T) ois.readObject();
        } catch (Exception e) {
            throw new RuntimeException("Deep copy failed", e);
        }
    }

  Downside: Very slow (serialization overhead). Don't use in performance-critical paths.

----------------------------------------------------------------
PROTOTYPE IN SPRING
----------------------------------------------------------------

  Spring @Scope("prototype"):
    @Component
    @Scope("prototype")
    public class ReportGenerator { ... }
    // Each injection point gets a NEW instance (not shared).

  Spring uses a prototype (template object) internally to create new instances.
  This is the Prototype pattern at the container level.

  Default vs Prototype scope:
    Singleton (default): one shared instance per ApplicationContext.
    Prototype:           new instance created each time it's requested/injected.

----------------------------------------------------------------
COMPLEXITY
----------------------------------------------------------------

  Shallow clone: O(1) — super.clone() is O(1).
  Deep clone:    O(n) where n = total size of all reference-type fields.
  Registry lookup: O(1) (HashMap) + clone cost.

  Space: O(1) additional for shallow; O(n) for deep clone.

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: What is the Prototype pattern?
  A: It creates new objects by cloning an existing "prototype" object instead of
     creating from scratch. Used when construction is expensive or complex.
     Prototype declares clone(); ConcretePrototype implements it.

  Q: What's the difference between shallow and deep copy?
  A: Shallow copy copies primitive values and copies references to objects
     (both copies point to the same nested objects). Deep copy recursively copies
     all nested mutable objects so the copy is fully independent.

  Q: Why does Josh Bloch recommend against Cloneable?
  A: Cloneable is a marker interface with a broken contract. clone() must call
     super.clone(), bypasses constructors, has final field issues, and throws
     a checked exception that Cloneable doesn't declare. Prefer copy constructors
     or copy factory methods instead.

  Q: How does Prototype differ from just calling new?
  A: "new" creates from scratch, running constructors and initialization.
     Prototype clones an existing object — faster when initialization is expensive
     or when you need a copy-then-customize workflow.

  Q: How is Spring @Scope("prototype") related to this pattern?
  A: Spring creates a new bean instance for each injection/request, acting like a
     prototype from which each "clone" (new instance) is derived. The name directly
     references the Prototype pattern.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------

  - Always distinguish shallow vs deep copy — interviewers frequently ask about this.
  - Know Josh Bloch's critique of Cloneable — shows Effective Java knowledge.
  - Recommend copy constructor as the modern Java approach.
  - Know the prototype registry for when multiple prototype types coexist.
  - Mention Spring @Scope("prototype") as a real-world usage.
  - When to use: "Object creation is expensive, or I need many copies with slight variations."
