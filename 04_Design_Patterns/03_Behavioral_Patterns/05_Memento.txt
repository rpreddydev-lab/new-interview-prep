================================================================
  MEMENTO PATTERN
================================================================

  Category:   Behavioral
  Intent:     Without violating encapsulation, capture and externalize an
              object's internal state so that the object can be restored to
              this state later. (Undo / Snapshot / Checkpoint)
  GoF:        Yes — one of the original 23 patterns.
  Frequency:  Moderate. Undo in editors, database transactions, game saves.

----------------------------------------------------------------
PROBLEM SOLVED
----------------------------------------------------------------

  You need undo/redo capability or checkpointing.
  You can't just expose the object's internals — breaks encapsulation.
  You need to save snapshots of state externally without the object
  losing control over its internal representation.

  Key tension: History/Undo needs access to state, but state should
               be private to the Originator.

  Memento solves this by creating an opaque snapshot object (Memento).
  Only the Originator knows how to read the Memento's content.
  The Caretaker stores Mementos but cannot (and need not) access their contents.

----------------------------------------------------------------
PARTICIPANTS
----------------------------------------------------------------

  Originator  -- The object whose state is being saved/restored.
                 Creates Memento snapshots.
                 Restores state from Memento.

  Memento     -- Stores the internal state of Originator.
                 Opaque to external objects.
                 Only Originator can read its contents.

  Caretaker   -- Requests Mementos from Originator.
                 Stores Mementos for future restoration.
                 Never operates on or examines Memento contents.

----------------------------------------------------------------
TEXT EDITOR UNDO/REDO EXAMPLE
----------------------------------------------------------------

  // Memento — opaque snapshot
  public final class EditorMemento {
      private final String text;    // package-private or inner class ensures opacity
      private final int    cursorPosition;

      // Only accessible within the same package or via Originator
      EditorMemento(String text, int cursorPosition) {
          this.text           = text;
          this.cursorPosition = cursorPosition;
      }

      String getText()   { return text; }
      int getCursor()    { return cursorPosition; }
  }

  // Originator
  public class TextEditor {
      private StringBuilder text   = new StringBuilder();
      private int cursorPosition   = 0;

      public void type(String chars) {
          text.insert(cursorPosition, chars);
          cursorPosition += chars.length();
      }

      public void delete(int count) {
          int end   = cursorPosition;
          int start = Math.max(0, end - count);
          text.delete(start, end);
          cursorPosition = start;
      }

      // Create a snapshot
      public EditorMemento save() {
          return new EditorMemento(text.toString(), cursorPosition);
      }

      // Restore from snapshot
      public void restore(EditorMemento memento) {
          text           = new StringBuilder(memento.getText());
          cursorPosition = memento.getCursor();
      }

      public String getText() { return text.toString(); }
  }

  // Caretaker — manages undo/redo stacks
  public class UndoManager {
      private final Deque<EditorMemento> undoStack = new ArrayDeque<>();
      private final Deque<EditorMemento> redoStack = new ArrayDeque<>();
      private final TextEditor editor;

      public UndoManager(TextEditor editor) { this.editor = editor; }

      public void saveState() {
          undoStack.push(editor.save());
          redoStack.clear();   // clear redo on new action
      }

      public void undo() {
          if (undoStack.isEmpty()) return;
          redoStack.push(editor.save());      // save current to redo
          editor.restore(undoStack.pop());    // restore previous
      }

      public void redo() {
          if (redoStack.isEmpty()) return;
          undoStack.push(editor.save());
          editor.restore(redoStack.pop());
      }
  }

  // Usage
  TextEditor  editor      = new TextEditor();
  UndoManager undoManager = new UndoManager(editor);

  undoManager.saveState();   // save initial state (empty)
  editor.type("Hello");
  undoManager.saveState();   // save after "Hello"
  editor.type(" World");
  undoManager.saveState();   // save after " World"

  System.out.println(editor.getText());   // Hello World

  undoManager.undo();
  System.out.println(editor.getText());   // Hello

  undoManager.undo();
  System.out.println(editor.getText());   // (empty)

  undoManager.redo();
  System.out.println(editor.getText());   // Hello

----------------------------------------------------------------
SHALLOW VS DEEP SNAPSHOT
----------------------------------------------------------------

  SHALLOW (copy references):
    Fast. Fine if state is immutable (String, Integer, etc.).
    Problem if state contains mutable objects — snapshot and original share references.

  DEEP (copy values):
    Copy all nested mutable objects.
    Use copy constructors, serialization, or manual deep copy.

    // Deep copy example in save()
    public EditorMemento save() {
        // StringBuilder is mutable — must create a new copy
        return new EditorMemento(text.toString(), cursorPosition);
    }

  Rule: If Originator's state contains mutable objects, ALWAYS deep copy in save().

----------------------------------------------------------------
JAVA IMPLEMENTATION OPTIONS
----------------------------------------------------------------

  1. INNER CLASS (classic GoF):
     Memento is a private inner class of Originator.
     Only Originator can access Memento's fields directly.
     Strongest encapsulation.

     public class Originator {
         private String state;

         private class Memento {         // private inner
             private final String savedState;
             private Memento(String state) { this.savedState = state; }
         }

         public Object save()  { return new Memento(state); }
         public void restore(Object o) {
             state = ((Memento)o).savedState;   // cast inside Originator — safe
         }
     }

  2. PACKAGE-PRIVATE (example above): fields only accessible in same package.

  3. INTERFACE: Memento implements an empty marker interface returned to Caretaker.
     Caretaker holds the interface; Originator casts to concrete type internally.

  4. RECORD (Java 16+):
     public record EditorMemento(String text, int cursorPosition) {}
     Immutable by default — safe for snapshots.

----------------------------------------------------------------
MEMORY MANAGEMENT — BOUNDED UNDO HISTORY
----------------------------------------------------------------

  // Limit undo stack size to prevent memory overflow
  public class BoundedUndoManager {
      private static final int MAX_HISTORY = 50;
      private final ArrayDeque<EditorMemento> undoStack = new ArrayDeque<>();
      private final TextEditor editor;

      public BoundedUndoManager(TextEditor editor) { this.editor = editor; }

      public void saveState() {
          if (undoStack.size() >= MAX_HISTORY) {
              undoStack.removeLast();    // remove oldest snapshot
          }
          undoStack.push(editor.save());
      }
  }

----------------------------------------------------------------
REAL-WORLD USAGE
----------------------------------------------------------------

  Database Transactions:
    BEGIN TRANSACTION = save state
    COMMIT           = discard memento
    ROLLBACK         = restore from memento

  Game Save/Checkpoint:
    Player state (position, health, inventory) saved as Memento.
    "Load from last checkpoint" restores saved Memento.

  Servlet Session:
    HttpSession stores serialized state — conceptually a Memento.

  Version Control:
    Each commit is a Memento (snapshot of project state).
    git stash = create Memento; git stash pop = restore.

  Hibernate/JPA:
    First-level cache (EntityManager persistence context) tracks original
    state to detect dirty changes — essentially a Memento mechanism.

----------------------------------------------------------------
COMPLEXITY
----------------------------------------------------------------

  Space: O(n * S) where n = number of snapshots, S = state size per snapshot.
         Can grow large for deep histories with large objects.
  Time:  O(S) to create snapshot (deep copy). O(S) to restore.
         O(1) to push/pop from undo stack.

----------------------------------------------------------------
MEMENTO vs COMMAND (UNDO)
----------------------------------------------------------------

  Both support undo — different approaches:

  Memento:                           Command:
  -----------------------------------------------
  Saves full state snapshot           Stores inverse operation
  Undo = restore snapshot             Undo = execute reverse command
  Simpler logic                       More memory-efficient (no full copy)
  Higher memory (full copies)         Requires inverse logic per command
  Always correct                      Bugs in undo logic possible
  -----------------------------------------------

  Memento preferred when: State is small, undo logic is complex/error-prone.
  Command preferred when: State is large, inverse operation is simple.

  Often COMBINED: Command pattern records Memento snapshots for each command.

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: What is the Memento pattern?
  A: Captures an object's internal state in a snapshot (Memento) without
     breaking encapsulation. The Originator creates and restores Mementos.
     The Caretaker stores Mementos without accessing their internals.
     Enables undo, checkpointing, and transactional rollback.

  Q: How does Memento preserve encapsulation?
  A: The Memento class is either a private inner class of Originator or
     has package-private accessors. Only the Originator can read the
     Memento's contents. The Caretaker only stores/returns the opaque object.

  Q: Memento vs Command for undo?
  A: Memento stores full state snapshots (simpler, more memory).
     Command stores inverse operations (more memory-efficient, requires
     correct inverse logic). Often combined: Command uses Memento internally.

  Q: How would you handle memory with undo history?
  A: Bound the undo stack size (remove oldest on overflow).
     For large state, use delta encoding (store only what changed).
     For very large objects, consider serialization and writing to disk.

  Q: Name real-world Memento examples.
  A: Database ROLLBACK, git commits, game checkpoints, browser back button,
     Hibernate dirty checking (original state tracking), serialization.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------

  - The text editor undo/redo with two stacks is a classic interview implementation.
  - Emphasize that Caretaker holds but cannot read Mementos — that's the key.
  - Mention the memory trade-off — bounded history or delta snapshots.
  - Know the Memento vs Command undo trade-off table.
  - Java Records (Java 16+) are a clean way to implement Mementos (immutable).
