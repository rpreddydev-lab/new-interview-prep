================================================================
  COMMAND PATTERN
================================================================

  Category:   Behavioral
  Intent:     Encapsulate a request as an object, thereby letting you
              parameterize clients with different requests, queue or log
              requests, and support undoable operations.
  GoF:        Yes — one of the original 23 patterns.
  Frequency:  High. Runnable, Callable, Spring @Scheduled are Command pattern.

----------------------------------------------------------------
PROBLEM SOLVED
----------------------------------------------------------------

  Caller (Invoker) should not need to know HOW an operation is performed —
  just THAT it should be performed. Request is treated as a first-class object.

  Benefits:
    1. Undo/redo — execute stores state; undo reverses it.
    2. Queueing — commands put in queue, executed later.
    3. Logging — commands logged before execution for audit/replay.
    4. Transactions — group commands; rollback on failure.
    5. Remote execution — send command object over network.
    6. Macro recording — record sequence of commands; replay.

----------------------------------------------------------------
PARTICIPANTS
----------------------------------------------------------------

  Command (interface)  -- execute(); optionally undo().
  ConcreteCommand      -- Implements execute(); knows receiver + action.
  Receiver             -- The object that performs the actual action.
  Invoker              -- Holds a command; calls execute() at the right time.
  Client               -- Creates ConcreteCommand, sets receiver, hands to Invoker.

  Key insight: Invoker DOESN'T know what the command does.
               ConcreteCommand knows HOW; Invoker knows WHEN.

----------------------------------------------------------------
FULL JAVA EXAMPLE — TEXT EDITOR WITH UNDO
----------------------------------------------------------------

  // Receiver
  public class TextEditor {
      private final StringBuilder content = new StringBuilder();

      public void write(String text) {
          content.append(text);
          System.out.println("Content: " + content);
      }

      public void delete(int length) {
          if (length > content.length()) length = content.length();
          content.delete(content.length() - length, content.length());
          System.out.println("Content: " + content);
      }

      public String getContent() { return content.toString(); }
  }

  // Command interface with undo support
  public interface Command {
      void execute();
      void undo();
  }

  // Concrete Commands
  public class WriteCommand implements Command {
      private final TextEditor editor;
      private final String text;

      public WriteCommand(TextEditor editor, String text) {
          this.editor = editor;
          this.text = text;
      }

      @Override
      public void execute() { editor.write(text); }

      @Override
      public void undo()    { editor.delete(text.length()); }
  }

  // Invoker with undo stack
  public class CommandHistory {
      private final Deque<Command> history = new ArrayDeque<>();

      public void execute(Command cmd) {
          cmd.execute();
          history.push(cmd);     // save for undo
      }

      public void undo() {
          if (!history.isEmpty()) {
              history.pop().undo();
          }
      }
  }

  // Client
  public class Main {
      public static void main(String[] args) {
          TextEditor editor = new TextEditor();
          CommandHistory history = new CommandHistory();

          history.execute(new WriteCommand(editor, "Hello"));
          // Content: Hello
          history.execute(new WriteCommand(editor, " World"));
          // Content: Hello World
          history.undo();
          // Content: Hello
          history.undo();
          // Content: (empty)
      }
  }

COMMAND WITH QUEUING — TASK QUEUE EXAMPLE
----------------------------------------------------------------

  // Simple task queue using Command pattern
  public class TaskQueue {
      private final Queue<Command> queue = new LinkedList<>();
      private final ExecutorService executor = Executors.newSingleThreadExecutor();

      public void submit(Command cmd) {
          queue.offer(cmd);
      }

      public void processAll() {
          while (!queue.isEmpty()) {
              Command cmd = queue.poll();
              executor.submit(cmd::execute);
          }
      }
  }

  // Usage
  TaskQueue taskQueue = new TaskQueue();
  taskQueue.submit(new WriteCommand(editor, "Task 1 "));
  taskQueue.submit(new WriteCommand(editor, "Task 2 "));
  taskQueue.processAll();

----------------------------------------------------------------
COMMAND IN JAVA STANDARD LIBRARY
----------------------------------------------------------------

  Runnable:
    The quintessential Command. execute() = run().
    Receiver is embedded in the lambda/anonymous class.

    Runnable task = () -> System.out.println("Running task");
    new Thread(task).start();         // Invoker = Thread

  Callable<V>:
    Command with a return value and exception declaration.

    Callable<Integer> task = () -> computeExpensive();
    Future<Integer> future = executor.submit(task);   // Invoker = ExecutorService

  javax.swing.Action:
    Command with metadata (name, icon, keystroke).
    actionPerformed(ActionEvent e) = execute().

  java.awt.event.ActionListener:
    Single-method interface = Command.

----------------------------------------------------------------
COMMAND IN SPRING
----------------------------------------------------------------

  @Scheduled (Invoker = Spring scheduler, Command = @Scheduled method):
    @Scheduled(fixedRate = 5000)
    public void runTask() { ... }    // Command executed by scheduler

  @Async (Invoker = Spring thread pool, Command = @Async method):
    @Async
    public void sendEmail(String to) { ... }   // executed asynchronously

  Spring Batch Tasklet:
    Tasklet.execute(contribution, chunkContext) = Command.execute()

  ApplicationEvent / ApplicationListener (combines Command + Observer):
    ApplicationEventPublisher.publishEvent(new OrderPlacedEvent(this));
    @EventListener void handle(OrderPlacedEvent e) { ... }

  Spring Integration MessageHandler:
    Each MessageHandler is a Command processing a message.

----------------------------------------------------------------
MACRO COMMAND (COMPOSITE COMMAND)
----------------------------------------------------------------

  A Macro Command is a command that executes a sequence of commands:

  public class MacroCommand implements Command {
      private final List<Command> commands;

      public MacroCommand(List<Command> commands) {
          this.commands = commands;
      }

      @Override
      public void execute() {
          commands.forEach(Command::execute);
      }

      @Override
      public void undo() {
          // Undo in reverse order
          ListIterator<Command> it = commands.listIterator(commands.size());
          while (it.hasPrevious()) {
              it.previous().undo();
          }
      }
  }

  // Start-of-day macro
  MacroCommand openApp = new MacroCommand(List.of(
      new LoginCommand(user),
      new LoadDashboardCommand(),
      new CheckNotificationsCommand()
  ));
  openApp.execute();

----------------------------------------------------------------
COMMAND vs STRATEGY
----------------------------------------------------------------

  Strategy:
    - Encapsulates an ALGORITHM to choose HOW to do something.
    - Swapped to change behavior. No undo.
    - Context uses strategy's algorithm.

  Command:
    - Encapsulates a REQUEST (what to do, to whom).
    - Supports undo, queueing, logging.
    - Invoker doesn't know the request details.

  Overlap: both encapsulate behavior as objects.
  Key difference: Command = encapsulate REQUEST (with undo). Strategy = encapsulate ALGORITHM.

----------------------------------------------------------------
COMPLEXITY
----------------------------------------------------------------

  execute(): O(1) — delegates to receiver.
  undo():    O(1) — reverses the change.
  Queue n commands: O(n) to process.
  History stack: O(h) space, h = number of undoable commands.

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: What is the Command pattern?
  A: It encapsulates a request as an object, decoupling the sender (Invoker)
     from the object that performs the work (Receiver). The command object
     knows the receiver and the action. Supports undo/redo, queuing, and logging.

  Q: How does Runnable relate to the Command pattern?
  A: Runnable is the Command pattern in Java. run() = execute(). The thread
     or ExecutorService is the Invoker. The lambda/anonymous class holds the
     receiver logic. It's the most common Command in Java.

  Q: How do you implement undo with Command?
  A: ConcreteCommand's execute() saves state before making changes.
     undo() reverts to the saved state. Invoker maintains a history stack.
     execute() pushes to stack; undo() pops and calls undo().

  Q: What is a Macro Command?
  A: A composite command that holds a list of commands and executes them all.
     undo() reverses them in reverse order. Used for batch operations,
     transaction rollback, macro recording.

  Q: How is Command used in Spring?
  A: @Scheduled methods are commands executed by a scheduler.
     @Async methods are commands submitted to a thread pool.
     Spring Batch Tasklets are Commands with execute() contracts.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------

  - Runnable is the most important Java example — Invoker = Thread/ExecutorService.
  - For coding: implement Command with undo() using a history Deque.
  - Distinguish from Strategy: "Command = encapsulate request + undo. Strategy = encapsulate algorithm."
  - Macro Command (composite of commands) is a nice extension to mention.
  - Spring @Scheduled and @Async are practical real-world Command pattern examples.
