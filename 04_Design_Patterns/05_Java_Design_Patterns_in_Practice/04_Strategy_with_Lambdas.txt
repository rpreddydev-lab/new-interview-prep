================================================================
  STRATEGY PATTERN WITH JAVA LAMBDAS AND FUNCTIONAL INTERFACES
================================================================

  Java 8+ transforms Strategy from heavyweight class hierarchies
  into concise functional expressions. Any @FunctionalInterface IS
  a Strategy. This file shows every practical form.

----------------------------------------------------------------
CLASSIC STRATEGY → LAMBDA TRANSFORMATION
----------------------------------------------------------------

  CLASSIC (pre-Java 8):

  interface SortStrategy {
      void sort(int[] arr);
  }

  class BubbleSort implements SortStrategy {
      @Override public void sort(int[] arr) { /* ... */ }
  }

  class QuickSort implements SortStrategy {
      @Override public void sort(int[] arr) { /* ... */ }
  }

  SortStrategy strategy = new BubbleSort();
  strategy.sort(data);


  LAMBDA (Java 8+):

  @FunctionalInterface
  interface SortStrategy {
      void sort(int[] arr);   // exactly ONE abstract method → SAM
  }

  SortStrategy bubble = arr -> { /* bubble sort */ };
  SortStrategy quick   = arr -> { /* quick sort  */ };
  SortStrategy jdk     = Arrays::sort;  // method reference as strategy

  SortStrategy strategy = jdk;
  strategy.sort(data);

  No extra class files. Strategy IS the lambda.

BUILT-IN FUNCTIONAL INTERFACES AS STRATEGIES
----------------------------------------------------------------

  java.util.function package — all @FunctionalInterface:

  Interface              Signature            Use as Strategy
  ---------------------  -------------------  ---------------------------
  Predicate<T>           T -> boolean         filter / validation rule
  Function<T,R>          T -> R               transformation / mapping
  Consumer<T>            T -> void            side effect (log, notify)
  Supplier<T>            () -> T              lazy factory / default value
  BiFunction<T,U,R>      (T,U) -> R           combines two inputs
  UnaryOperator<T>       T -> T               in-place transformation
  BinaryOperator<T>      (T,T) -> T           reduce / merge strategy
  Comparator<T>          (T,T) -> int         sort strategy (two-arg)

  // Predicate as validation strategy
  Predicate<String> notEmpty  = s -> !s.isBlank();
  Predicate<String> hasAt     = s -> s.contains("@");
  Predicate<String> validEmail = notEmpty.and(hasAt);

  boolean ok = validEmail.test("user@example.com");  // true

  // Function as transformation strategy
  Function<String, String> trim  = String::trim;
  Function<String, String> upper = String::toUpperCase;
  Function<String, String> normalize = trim.andThen(upper);

  String result = normalize.apply("  hello  ");  // "HELLO"

PAYMENT STRATEGY WITH LAMBDAS
----------------------------------------------------------------

  @FunctionalInterface
  public interface PaymentStrategy {
      PaymentResult pay(double amount);
  }

  public class Checkout {
      private PaymentStrategy paymentStrategy;

      public void setPaymentStrategy(PaymentStrategy strategy) {
          this.paymentStrategy = strategy;
      }

      public PaymentResult processPayment(double amount) {
          Objects.requireNonNull(paymentStrategy, "No payment strategy set");
          return paymentStrategy.pay(amount);
      }
  }

  // No CreditCardPayment class needed:
  Checkout checkout = new Checkout();

  checkout.setPaymentStrategy(amount ->
      creditCardGateway.charge(cardNumber, amount)
  );

  checkout.setPaymentStrategy(amount ->
      paypalGateway.sendPayment(paypalEmail, amount)
  );

  // Or use method references from service beans:
  checkout.setPaymentStrategy(cryptoService::payWithBitcoin);

MAP-BASED STRATEGY DISPATCH
----------------------------------------------------------------

  Pattern: Map<String, Strategy> for runtime lookup by key.
  Avoids if-else or switch chains entirely.

  @Service
  public class DiscountService {

      private final Map<String, DiscountStrategy> strategies;

      // Constructor injection — Spring auto-wires all DiscountStrategy beans
      public DiscountService(Map<String, DiscountStrategy> strategies) {
          this.strategies = strategies;
      }

      public double applyDiscount(String strategyKey, double price) {
          DiscountStrategy strategy = strategies.getOrDefault(
              strategyKey,
              price -> price   // identity = no discount
          );
          return strategy.apply(price);
      }
  }

  // Alternatively — hardcode the map:
  Map<String, Function<Double, Double>> discounts = Map.of(
      "STUDENT",    price -> price * 0.80,   // 20% off
      "VETERAN",    price -> price * 0.75,   // 25% off
      "EMPLOYEE",   price -> price * 0.50,   // 50% off
      "NONE",       price -> price           // no discount
  );

  Function<Double, Double> strategy = discounts.getOrDefault("STUDENT", d -> d);
  double final_price = strategy.apply(100.0);  // 80.0

SPRING BEAN MAP INJECTION (ENTERPRISE PATTERN)
----------------------------------------------------------------

  // Define the @FunctionalInterface
  public interface NotificationStrategy {
      void send(String recipient, String message);
  }

  // Concrete strategies as Spring beans — names become map keys
  @Component("emailNotification")
  public class EmailNotificationStrategy implements NotificationStrategy {
      public void send(String recipient, String message) {
          emailService.sendEmail(recipient, message);
      }
  }

  @Component("smsNotification")
  public class SmsNotificationStrategy implements NotificationStrategy {
      public void send(String recipient, String message) {
          smsGateway.sendSms(recipient, message);
      }
  }

  @Component("pushNotification")
  public class PushNotificationStrategy implements NotificationStrategy {
      public void send(String recipient, String message) {
          fcmService.push(recipient, message);
      }
  }

  // Spring injects Map<String, NotificationStrategy>
  // key = bean name, value = bean instance
  @Service
  @RequiredArgsConstructor
  public class NotificationService {
      private final Map<String, NotificationStrategy> strategies;

      public void notify(String channel, String recipient, String message) {
          NotificationStrategy strategy = strategies.get(channel + "Notification");
          if (strategy == null) throw new IllegalArgumentException("Unknown channel: " + channel);
          strategy.send(recipient, message);
      }
  }

  // Client code:
  notificationService.notify("email", "user@example.com", "Order shipped");
  notificationService.notify("sms",   "+1234567890",      "Order shipped");

COMPARATOR<T> — THE CANONICAL LAMBDA STRATEGY
----------------------------------------------------------------

  Comparator<T> is Java's most-used strategy pattern.

  // Natural + lambda strategies
  List<Employee> employees = ...;

  employees.sort(Comparator.comparing(Employee::getSalary));
  employees.sort(Comparator.comparing(Employee::getLastName)
                           .thenComparing(Employee::getFirstName));
  employees.sort(Comparator.comparing(Employee::getSalary).reversed());

  // Comparator.comparingInt (avoids boxing)
  employees.sort(Comparator.comparingInt(Employee::getYearsExperience));

  // NullsFirst / NullsLast
  employees.sort(Comparator.comparing(Employee::getDepartment,
                 Comparator.nullsFirst(String::compareTo)));

  // Multi-level sort: salary desc, then name asc
  Comparator<Employee> comp =
      Comparator.comparingDouble(Employee::getSalary).reversed()
                .thenComparing(Employee::getLastName);

  employees.sort(comp);

  Composable strategies: and(), then(), reversed() — chain without subclassing.

PREDICATE COMPOSITION AS STRATEGY
----------------------------------------------------------------

  // Build complex filter strategies by composing Predicates
  Predicate<Order> isHighValue  = order -> order.total() > 1000;
  Predicate<Order> isPaid       = order -> order.status() == PAID;
  Predicate<Order> isRecent     = order -> order.createdAt().isAfter(LAST_7_DAYS);

  // Compose strategies at runtime
  Predicate<Order> eligibleForReview = isHighValue.and(isPaid).and(isRecent);

  List<Order> reviewQueue = orders.stream()
      .filter(eligibleForReview)
      .collect(Collectors.toList());

  // Negate
  Predicate<Order> notCancelled = Predicate.not(Order::isCancelled);

  // Dynamic composition
  public List<Order> findOrders(List<Predicate<Order>> filters) {
      Predicate<Order> combined = filters.stream()
          .reduce(order -> true, Predicate::and);
      return orders.stream().filter(combined).toList();
  }

FUNCTION PIPELINE AS STRATEGY
----------------------------------------------------------------

  // Each transformation step = strategy
  Function<String, String>  clean     = String::trim;
  Function<String, String>  normalize = String::toLowerCase;
  Function<String, Boolean> validate  = s -> s.length() >= 3;

  // Compose pipeline
  Function<String, String> sanitize = clean.andThen(normalize);

  // andThen: f then g = g(f(x))
  // compose: f.compose(g) = f(g(x))

  List<String> pipeline = List.of("  Hello ", " WORLD ", " java ");
  List<String> result = pipeline.stream()
      .map(clean)
      .map(normalize)
      .filter(validate::apply)  // method ref to Predicate-like test
      .toList();

INTERVIEW Q&A
----------------------------------------------------------------

  Q: How does Java 8 lambda relate to Strategy pattern?
  A: A lambda IS an anonymous implementation of a @FunctionalInterface.
     Since Strategy's intent is to define an interchangeable algorithm,
     and a lambda is an interchangeable behavior with function signature,
     every lambda serving as an algorithm is a Strategy.

  Q: When to use Strategy class vs lambda?
  A: Lambda: stateless algorithm, simple logic, one method, ad-hoc composition.
     Class: algorithm needs state/fields, complex logic > 5 lines,
            multiple helper methods, need a name for documentation/tests,
            or need to unit test the strategy in isolation.

  Q: How do you select a strategy at runtime in Spring?
  A: Inject Map<String, StrategyInterface>. Spring fills it with all beans
     implementing the interface, keyed by bean name. Lookup by key at runtime.

  Q: Predicate vs Function vs Consumer — when to use each as strategy?
  A: Predicate: boolean decision (filter, validate).
     Function: data transformation (map, convert).
     Consumer: side effects (log, persist, notify) — returns nothing.

  Q: How do you compose multiple strategies?
  A: Predicate: .and() .or() .negate()
     Function:  .andThen() .compose()
     Comparator: .thenComparing() .reversed()
     Custom: reduce(identity, BinaryOperator) to fold list of strategies into one.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------

  - Know that Comparator, Predicate, Function, Comparator are all Strategy.
  - Spring Map<String, Bean> injection avoids if-else chains — show this.
  - Function.andThen() builds pipelines (mention Decorator overlap).
  - Predicate composition allows dynamic rule engines without reflection.
  - Lambda as strategy = no extra .class files, testable with method references.
