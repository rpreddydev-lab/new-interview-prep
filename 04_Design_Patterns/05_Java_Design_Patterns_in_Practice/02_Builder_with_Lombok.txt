================================================================
  BUILDER PATTERN WITH LOMBOK IN JAVA
================================================================

  Builder Pattern: construct complex objects step-by-step.
  Lombok @Builder: auto-generates the entire builder via annotation processing.
  Together: most common Java approach for immutable data objects.

----------------------------------------------------------------
MANUAL BUILDER (NO LOMBOK — BASELINE)
----------------------------------------------------------------

  public final class Order {
      private final String    customerId;
      private final List<Item> items;
      private final String    shippingAddress;
      private final PaymentType paymentType;
      private final boolean   giftWrapping;
      private final String    couponCode;

      private Order(Builder builder) {
          this.customerId     = builder.customerId;
          this.items          = List.copyOf(builder.items);
          this.shippingAddress = builder.shippingAddress;
          this.paymentType    = builder.paymentType;
          this.giftWrapping   = builder.giftWrapping;
          this.couponCode     = builder.couponCode;
      }

      // Getters (no setters — immutable)
      public String    getCustomerId()     { return customerId; }
      public List<Item> getItems()         { return items; }
      public String    getShippingAddress(){ return shippingAddress; }
      // ...

      // INNER STATIC BUILDER
      public static Builder builder() { return new Builder(); }

      public static class Builder {
          private String     customerId;
          private List<Item> items        = new ArrayList<>();
          private String     shippingAddress;
          private PaymentType paymentType = PaymentType.CREDIT_CARD;
          private boolean    giftWrapping = false;
          private String     couponCode;

          public Builder customerId(String customerId) {
              this.customerId = customerId;
              return this;
          }

          public Builder items(List<Item> items) {
              this.items = new ArrayList<>(items);
              return this;
          }

          public Builder addItem(Item item) {
              this.items.add(item);
              return this;
          }

          public Builder shippingAddress(String address) {
              this.shippingAddress = address;
              return this;
          }

          public Builder paymentType(PaymentType type) {
              this.paymentType = type;
              return this;
          }

          public Builder giftWrapping(boolean wrap) {
              this.giftWrapping = wrap;
              return this;
          }

          public Builder couponCode(String code) {
              this.couponCode = code;
              return this;
          }

          // Validation in build()
          public Order build() {
              if (customerId == null || customerId.isBlank())
                  throw new IllegalStateException("customerId required");
              if (items.isEmpty())
                  throw new IllegalStateException("At least one item required");
              if (shippingAddress == null || shippingAddress.isBlank())
                  throw new IllegalStateException("shippingAddress required");
              return new Order(this);
          }
      }
  }

  // Usage
  Order order = Order.builder()
      .customerId("CUST-001")
      .addItem(new Item("Book", 29.99))
      .addItem(new Item("Coffee", 12.50))
      .shippingAddress("123 Main St, NY")
      .paymentType(PaymentType.PAYPAL)
      .giftWrapping(true)
      .couponCode("SAVE10")
      .build();

----------------------------------------------------------------
LOMBOK @BUILDER
----------------------------------------------------------------

  // With Lombok — generates the exact same builder boilerplate automatically
  @Builder
  @Getter
  public final class OrderLombok {
      private final String    customerId;
      private final List<Item> items;
      private final String    shippingAddress;
      @Builder.Default
      private final PaymentType paymentType = PaymentType.CREDIT_CARD;
      @Builder.Default
      private final boolean   giftWrapping  = false;
      private final String    couponCode;
  }

  // Same usage syntax
  OrderLombok order = OrderLombok.builder()
      .customerId("CUST-001")
      .items(List.of(new Item("Book", 29.99)))
      .shippingAddress("123 Main St, NY")
      .couponCode("SAVE10")
      .build();

  // DELOMBOK view (what Lombok generates):
  // - OrderLombok.builder() → OrderLombokBuilder
  // - OrderLombokBuilder with all field setters returning this
  // - build() method creating OrderLombok

----------------------------------------------------------------
LOMBOK BUILDER KEY ANNOTATIONS
----------------------------------------------------------------

  @Builder:
    Generates: static builder() factory, inner static Builder class,
    field setter methods on builder, build() method.
    All fields are set via builder — no constructor exposed.

  @Builder.Default:
    Required for fields with default values.
    Without it: field defaults are IGNORED in builder (set to null/0).
    With it:    default value used when field not set in builder chain.

    @Builder.Default
    private final int quantity = 1;  // used if .quantity() not called

  @Builder(toBuilder = true):
    Generates toBuilder() method on the built object.
    Creates a new builder pre-populated with current object's values.
    Useful for "copy with modifications" (wither pattern).

    Order modified = order.toBuilder()
        .couponCode("NEWYEAR")  // only change what you need
        .build();

  @Singular:
    For collection fields — adds single-item adder method.
    + builder accumulates items one by one.
    + Generated collection is unmodifiable.

    @Singular("item")
    private final List<Item> items;   // generates .item(singleItem) on builder
    
    Order order = Order.builder()
        .customerId("X")
        .item(new Item("Book", 10))   // singular — one item
        .item(new Item("Pen", 2))     // add more
        .build();

  @NonNull:
    Lombok generates null-check in setter and constructor.
    Throws NullPointerException with field name in message.

    @NonNull private final String customerId;

  @EqualsAndHashCode:
    Generates equals() and hashCode() based on selected fields.
    Important for entities, DTOs, value objects.

    @EqualsAndHashCode(of = {"customerId"})  // only customerId for equality

  @ToString:
    Generates toString().
    @ToString(exclude = "password")  // don't include sensitive fields

  COMBINING COMMON ANNOTATIONS:
  @Data = @Getter + @Setter + @ToString + @EqualsAndHashCode + @RequiredArgsConstructor
  @Value = @Data but immutable (final fields, no setters)
  @Value @Builder — most common combination for immutable DTOs

  @Value
  @Builder
  public class CustomerDTO {
      String id;
      String name;
      String email;
      @Builder.Default
      LocalDateTime createdAt = LocalDateTime.now();
  }

LOMBOK @BUILDER vs RECORD (JAVA 16+)
----------------------------------------------------------------

  record is best for SIMPLE immutable data (no optional fields, no defaults):

  // Java Record
  public record Point(int x, int y) { }
  Point p = new Point(3, 5);

  // Compact: auto-generated equals, hashCode, toString, all-args constructor.
  // NO builder. NO optional fields. NO defaults out of the box.

  When to use RECORD:
    - All fields always required.
    - Simple value object with < 5 fields.
    - No complex validation.
    - Serialization-friendly (e.g., Jackson 2.12+ with records).

  When to use BUILDER:
    - Optional fields (skip fields you don't need).
    - Default values for optional fields.
    - Complex validation in build().
    - Many fields (>5 parameters → constructor becomes unreadable).
    - Need toBuilder() for copy-with-modification.

  Hybrid: use record for the immutable data + custom static builder:
  public record Order(String customerId, List<Item> items) {
      public static Builder builder() { return new Builder(); }

      public static class Builder { /* ... */ }
  }

----------------------------------------------------------------
BUILDER FOR IMMUTABLE ENTITIES (JPA WARNING)
----------------------------------------------------------------

  JPA entities NEED no-arg constructor (JPA reflection).
  Pure @Builder removes no-arg constructor.

  Fix:
    @Entity
    @Builder
    @AllArgsConstructor   // for Builder
    @NoArgsConstructor    // for JPA
    @Getter
    public class Customer {
        @Id private Long id;
        private String name;
    }

  Note: JPA entities should NOT be truly immutable — JPA needs to modify fields.
  For DTOs (Data Transfer Objects), full immutability is fine and recommended.
  Keep entities mutable (JPA managed), use immutable DTOs/Value Objects for
  cross-boundary data transfer.

JACKSON SERIALIZATION WITH BUILDER
----------------------------------------------------------------

  @JsonDeserialize(builder = Person.Builder.class)
  @Builder
  public class Person {
      private final String firstName;
      private final String lastName;

      @JsonPOJOBuilder(withPrefix = "")  // tells Jackson: builder setters have no "with" prefix
      public static class Builder { ... }
  }

  Or Jackson-Lombok integration:
  @JacksonLombok — not standard. Use:
    jackson-module-parameter-names
    jackson-databind
    @JsonProperty on fields

  // Simplest: use @Jacksonized (Lombok 1.18.14+)
  @Builder
  @Jacksonized
  public class Person {
      private final String firstName;
      private final String lastName;
  }

----------------------------------------------------------------
VALIDATION IN BUILDER
----------------------------------------------------------------

  Option 1: Validate in build() (shown earlier):
    Throw IllegalStateException / IllegalArgumentException.

  Option 2: Validate with @NonNull:
    @NonNull private final String customerId;
    Builder throws NullPointerException immediately on setter call.

  Option 3: Bean Validation in build():
    public Order build() {
        Order order = new Order(this);
        ValidatorFactory factory = Validation.buildDefaultValidatorFactory();
        Set<ConstraintViolation<Order>> violations = factory.getValidator().validate(order);
        if (!violations.isEmpty()) throw new ConstraintViolationException(violations);
        return order;
    }

  Option 4: Spring Validator injection — use Service layer to validate after build.

  Best practice: validate required fields in build() for fast-fail;
                 use Bean Validation (@NotNull, @Size) for constraint metadata.

----------------------------------------------------------------
COMPLEXITY
----------------------------------------------------------------

  Space:  O(f) — f fields per builder instance.
  Time:   O(1) per setter call; O(f) for build() (field copy).

  Builder creation: one Builder object per object to be built.
  Builders are NOT thread-safe — intended for single-thread use.

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: What problem does Builder solve?
  A: Telescoping constructor anti-pattern. When a class has many optional fields,
     you'd need many constructor overloads. Builder: set only what you need,
     validate at build(), produce an immutable object.

  Q: What does Lombok @Builder.Default do?
  A: Ensures default field values are used when a setter is not called on the builder.
     Without @Builder.Default, the default is overridden to null/0 by Lombok's builder.

  Q: When to use @Singular?
  A: For collection fields. Generates an add-one-item method (item()) and
     clearItems(). Generated collection is unmodifiable.

  Q: @Value vs @Data in Lombok?
  A: @Data: mutable — @Getter + @Setter + @ToString + @EqualsAndHashCode.
     @Value: immutable — all fields final, @Getter only (no @Setter).
     @Value is preferred for DTOs and value objects.

  Q: Record vs @Builder?
  A: Record: all fields required, compact, < 5 fields, no builder needed.
     @Builder: optional fields, defaults, complex validation, many fields.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------

  - Know @Builder, @Builder.Default, @Singular, toBuilder = true.
  - Know the JPA entity issue — @NoArgsConstructor needed alongside @Builder.
  - Know @Jacksonized for JSON deserialization with Lombok builders.
  - Record vs Builder decision criteria.
  - Show manual builder code FIRST, then show how Lombok replaces it.
