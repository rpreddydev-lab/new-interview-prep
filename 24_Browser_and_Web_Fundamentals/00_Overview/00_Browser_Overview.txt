1. WHAT IS A WEB BROWSER?
────────────────────────────────────────────────────────────────────────────────

A web browser is a software application that:
  • Retrieves resources from the web (HTML, CSS, JS, images, etc.)
  • Parses and processes those resources
  • Renders visual output for users
  • Provides APIs for JavaScript to interact with the platform

Popular browsers and their rendering engines:
  ┌──────────────────┬──────────────────────┬───────────────────┐
  │ Browser          │ Rendering Engine     │ JS Engine         │
  ├──────────────────┼──────────────────────┼───────────────────┤
  │ Chrome / Edge    │ Blink (forked WebKit)│ V8                │
  │ Firefox          │ Gecko                │ SpiderMonkey      │
  │ Safari           │ WebKit               │ JavaScriptCore    │
  │ Opera            │ Blink                │ V8                │
  └──────────────────┴──────────────────────┴───────────────────┘

2. HIGH-LEVEL BROWSER ARCHITECTURE
────────────────────────────────────────────────────────────────────────────────

Major components inside a browser:

  ┌─────────────────────────────────────────────────────────────────────┐
  │  User Interface (address bar, back/forward, bookmarks, tabs)        │
  ├─────────────────────────────────────────────────────────────────────┤
  │  Browser Engine (coordinates UI ↔ Rendering Engine)                │
  ├─────────────────────────────────────────────────────────────────────┤
  │  Rendering Engine                                                    │
  │   ┌──────────────┐  ┌───────────┐  ┌──────────────┐  ┌──────────┐  │
  │   │ HTML Parser  │  │CSS Parser │  │  Layout       │  │ Painter  │  │
  │   └──────────────┘  └───────────┘  └──────────────┘  └──────────┘  │
  ├─────────────────────────────────────────────────────────────────────┤
  │  Networking (DNS, TCP, HTTP, cache)                                  │
  ├─────────────────────────────────────────────────────────────────────┤
  │  JavaScript Interpreter (V8, SpiderMonkey, etc.)                    │
  ├─────────────────────────────────────────────────────────────────────┤
  │  UI Backend (draws basic widgets like combo boxes, windows)         │
  ├─────────────────────────────────────────────────────────────────────┤
  │  Data Storage (Cookies, localStorage, IndexedDB, Cache API)         │
  └─────────────────────────────────────────────────────────────────────┘

Each component has a distinct responsibility:

  User Interface:
    - Everything the user sees EXCEPT the page content area
    - Back/forward buttons, address bar, bookmarks, tabs, settings

  Browser Engine:
    - Marshals actions between UI and rendering engine
    - Handles navigation (back/forward), tab management
    - Passes URL requests to the networking layer

  Rendering Engine:
    - Parses HTML → DOM Tree
    - Parses CSS → CSSOM Tree
    - Merges into Render Tree → Layout → Paint → Composite
    - Triggers JS execution where needed

  Networking:
    - Manages HTTP/HTTPS requests
    - DNS resolution, TLS handshakes
    - Request caching (HTTP cache, service workers)
    - Connection pooling, keep-alive, HTTP/2 multiplexing

  JavaScript Engine:
    - Parses, compiles (JIT), and executes JavaScript
    - Manages the heap (memory allocation) and call stack
    - Implements the event loop (in combination with browser APIs)

  Data Storage:
    - Cookies, sessionStorage, localStorage
    - IndexedDB (structured data), Cache API (network responses)
    - WebSQL (deprecated)

3. MULTI-PROCESS ARCHITECTURE (MODERN BROWSERS)
────────────────────────────────────────────────────────────────────────────────

Modern browsers (Chrome / Edge) use a multi-process architecture:

  Browser Process (main process)
    - Controls chrome UI, coordinates everything
    - One per browser instance

  Renderer Process
    - Each tab gets its own renderer (Site Isolation)
    - Runs rendering engine + JS engine
    - Sandboxed — cannot directly access OS/disk

  GPU Process
    - Handles GPU commands for compositing
    - Shared across all renderer processes

  Network Process
    - Handles all network requests
    - Can be shared or per-tab

  Plugin/Extension Processes
    - Extensions run in isolated processes

  Utility Processes
    - Audio, print, etc.

WHY MULTI-PROCESS?
  1. Isolation: One tab crash doesn't kill others
  2. Security: Renderer is sandboxed, can't access system resources
  3. Performance: Parallelism, separate GC per renderer

SITE ISOLATION (Chrome 67+):
  - Each cross-site iframe gets its own renderer process
  - Mitigates Spectre/Meltdown attacks
  - Prevents cross-origin data leaks

────────────────────────────────────────────────────────────────────────────────
4. BROWSER PROCESS COMMUNICATION
────────────────────────────────────────────────────────────────────────────────

  IPC (Inter-Process Communication):
    - Mojo (Chromium's IPC system)
    - Browser process ↔ Renderer process via IPC pipes
    - Renderer cannot make direct system calls — must proxy through browser process

  MessageChannel / postMessage:
    - Used for communication between web workers, iframes, service workers
    - Asynchronous, structured clone algorithm for data serialization

5. BROWSER RENDERING OVERVIEW (THE BIG PICTURE)
────────────────────────────────────────────────────────────────────────────────

  Step-by-step from URL to pixels:

  1. DNS Resolution
       URL → IP address via DNS lookup chain

  2. TCP / TLS Connection
       3-way handshake → TLS handshake (HTTPS)

  3. HTTP Request
       GET /index.html HTTP/2

  4. Server Response
       HTML bytes arrive → incremental parsing begins

  5. HTML Parsing → DOM Construction
       Tokenizer → Tree Builder → DOM Tree

  6. CSS Parsing → CSSOM Construction
       CSS bytes → CSSOM Tree (render-blocking)

  7. JavaScript Execution
       <script> tags pause HTML parsing (unless async/defer)
       JS can modify DOM/CSSOM

  8. Render Tree Construction
       DOM + CSSOM = Render Tree (visible nodes only)

  9. Layout (Reflow)
       Calculate exact position and dimensions of each node

  10. Paint
        Draw pixels for each node (colors, borders, shadows)

  11. Composite
        Layers are combined by the GPU

  12. Frame displayed at 60fps target (~16.67ms per frame)

6. BROWSER STANDARDS AND GOVERNANCE
────────────────────────────────────────────────────────────────────────────────

  W3C (World Wide Web Consortium):
    - Standards: HTML, CSS, Web APIs, Accessibility (WCAG)
    - Process: Working Drafts → Candidate Recommendation → Recommendation

  WHATWG (Web Hypertext Application Technology Working Group):
    - Maintains the "living standards" for HTML, DOM, Fetch, Encoding
    - HTML spec is maintained jointly by W3C and WHATWG

  ECMA International / TC39:
    - ECMAScript (JavaScript) standard
    - Annual releases (ES2015, ES2016, …, ES2025)

  IETF (Internet Engineering Task Force):
    - HTTP/1.1 (RFC 7230-7235), HTTP/2 (RFC 7540), HTTP/3 / QUIC

  IEEE:
    - Networking standards (Ethernet, Wi-Fi)

7. KEY BROWSER APIs (HIGH-LEVEL LIST)
────────────────────────────────────────────────────────────────────────────────

  DOM API             → Manipulate document structure
  CSSOM API           → Read/write computed styles
  Fetch API           → HTTP requests from JavaScript
  XMLHttpRequest      → Legacy AJAX (still widely used)
  Web Storage API     → localStorage, sessionStorage
  IndexedDB           → Client-side structured storage
  Cache API           → Service worker network cache
  History API         → pushState / replaceState
  Navigator API       → User agent info, geolocation, etc.
  Screen / Window     → Viewport dimensions, scrolling
  Canvas 2D / WebGL   → Graphics rendering
  Web Workers         → Background threads
  Service Workers     → Offline, push notifications, background sync
  WebSockets          → Full-duplex communication
  Notifications API   → Push notifications
  Geolocation API     → Device location
  MediaDevices        → Camera, microphone access
  WebRTC              → Peer-to-peer communication
  Clipboard API       → Copy/paste
  Intersection Observer → Lazy loading, scroll tracking
  MutationObserver    → DOM change observation
  ResizeObserver      → Element size change observation
  Performance API     → High-resolution timestamps, marks, measures

8. INTERVIEW QUESTIONS & ANSWERS
────────────────────────────────────────────────────────────────────────────────

Q: What are the main components of a browser?
A: User Interface, Browser Engine, Rendering Engine, Networking layer,
   JavaScript Engine, UI Backend, and Data Storage.

Q: Why does Chrome use multiple processes per tab?
A: For isolation (a crashed tab doesn't crash others), security (renderer
   is sandboxed), and performance (parallel processing, separate GC).

Q: What is Site Isolation?
A: Chrome's feature (enabled since v67) where each cross-origin site gets
   its own renderer process, protecting against side-channel attacks like
   Spectre that could leak cross-origin data.

Q: What is the difference between the rendering engine and the JS engine?
A: The rendering engine processes HTML/CSS and builds the visual layout
   (DOM, CSSOM, render tree, layout, paint). The JS engine compiles and
   executes JavaScript code. They communicate — JS can read/write the DOM
   and trigger reflows.

Q: What is the Browser Engine?
A: An intermediary layer between the UI and the Rendering Engine. It
   marshals actions (navigation, history) and coordinates the rendering
   engine. In Chromium it's called "Content Shell"; in Firefox it's Gecko.

Q: Name the rendering engines of major browsers.
A: Chrome/Edge → Blink, Firefox → Gecko, Safari → WebKit.

Q: What is the significance of 60fps in browser rendering?
A: Humans perceive motion as smooth at ≥60fps. Each frame budget is
   ~16.67ms. If rendering (layout + paint + composite) exceeds this,
   frames are dropped causing jank/stutter.

Q: What is the role of the GPU process in the browser?
A: It handles rasterization and compositing of layers using hardware
   acceleration, offloading work from the CPU renderer process. This
   enables smooth scrolling and animations.

Q: How do browser extensions interact with the browser?
A: Extensions run in their own process (for isolation) and communicate
   with the browser process via Chrome's extension API. Content scripts
   can inject into page renderer processes but are still sandboxed.

Q: What happens when you type a URL and press Enter?
A: (Full pipeline) DNS resolution → TCP connection → TLS handshake →
   HTTP request → server response → HTML parsing → resource loading →
   DOM/CSSOM construction → Render tree → Layout → Paint → Composite →
   Frame displayed.

  • Browser = UI + Engine + Renderer + Networking + JS Engine + Storage
  • Modern browsers are multi-process for isolation, security, perf

  • Rendering pipeline: Parse → Style → Layout → Paint → Composite
  • Standards maintained by W3C, WHATWG, TC39, IETF
