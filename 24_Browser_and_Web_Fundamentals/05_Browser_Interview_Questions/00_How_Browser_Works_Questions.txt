SECTION 1: BROWSER ARCHITECTURE
────────────────────────────────────────────────────────────────────────────────

Q1: What happens when you type a URL and press Enter?
─────────────────────────────────────────────────────
Answer:
  1. URL Parsing: Browser parses the URL (protocol, host, path, query).
  2. HSTS Check: Check if domain is in HSTS preload list → force HTTPS.
  3. DNS Resolution:
     - Check browser DNS cache → OS cache → Router → ISP resolver → Recursive lookup.
     - Returns IP address.
  4. TCP Connection: 3-way handshake (SYN → SYN-ACK → ACK).
  5. TLS Handshake (HTTPS): Certificate validation, key exchange (ECDHE), session keys.
  6. HTTP Request: Browser sends GET / with Host, Accept, Cookie headers.
  7. Server Response: 200 OK with HTML body.
  8. HTML Parsing: Tokenization → DOM construction (incremental).
  9. Subresource Loading: CSS, JS, images fetched (blocking/non-blocking).
  10. CSSOM Construction: CSS parsed into CSSOM.
  11. Render Tree: DOM + CSSOM combined (visible nodes only).
  12. Layout: Calculate sizes and positions.
  13. Paint: Record drawing commands.
  14. Rasterize: Paint commands → pixels.
  15. Composite: GPU composites layers → display.

Q2: What is the browser's multi-process architecture?
────────────────────────────────────────────────────────
Answer:
  Modern browsers (Chrome) use a multi-process model for security and stability:
  
  • Browser Process: UI, address bar, tabs management, no web content rendering.
  • Renderer Process: One per site (Site Isolation). Runs Blink (rendering engine)
    and V8 (JS engine). Runs inside a OS sandbox.
  • GPU Process: GPU operations, compositing.
  • Network Process: All network requests (DNS, TLS, HTTP).
  • Utility Processes: Codecs, printing, etc.
  
  Benefits: A crashed tab doesn't crash the browser. Sandboxed renderers can't
  directly access OS/files. Site isolation prevents Spectre/Meltdown side channels.

Q3: What is Site Isolation?
────────────────────────────
Answer:
  Chrome's Site Isolation policy: each site runs in a separate Renderer Process.
  Implemented after Spectre/Meltdown (2018) — side-channel CPU attacks could read
  cross-process memory. With site isolation, process memory boundaries align with
  security boundaries. A compromised renderer can only read data for one site.
  
  Implementation: Out-of-Process iframes (OOPIFs) — iframes from different origins
  get their own process.

Q4: What is the Critical Rendering Path?
─────────────────────────────────────────
Answer:
  The sequence of steps the browser must complete to display the first pixel:
  
  1. Parse HTML → DOM
  2. Parse CSS → CSSOM
  3. Combine → Render Tree
  4. Layout: calculate element sizes and positions
  5. Paint: draw pixels to layers
  6. Composite: merge layers → display
  
  Optimization: Minimize render-blocking resources (inline critical CSS,
  defer JS), use resource hints (preload, preconnect), optimize CSS.

Q5: What is the difference between DOMContentLoaded and load events?
────────────────────────────────────────────────────────────────────
Answer:
  DOMContentLoaded:
    Fires when the HTML is fully parsed and DOM is constructed.
    Doesn't wait for images, iframes, stylesheets to finish loading.
    Usually much earlier than load.
  
  load:
    Fires when the ENTIRE page is fully loaded — all resources (images,
    CSS, scripts, iframes) have finished loading.
  
  Use DOMContentLoaded for DOM manipulation.
  Use load when you need all resources (e.g., measure image dimensions).

SECTION 2: RENDERING PIPELINE
────────────────────────────────────────────────────────────────────────────────

Q6: What is reflow vs repaint?
───────────────────────────────
Answer:
  Reflow (Layout): Triggered when the geometry/layout of elements changes.
    (width, height, margin, padding, font-size, display, DOM changes)
    Browser recalculates positions of affected elements and their ancestors/descendants.
    Expensive — cascades through the layout tree.
  
  Repaint: Triggered when visual appearance changes but layout doesn't.
    (color, background, visibility, border-radius, box-shadow)
    Only the changed pixels are repainted — cheaper than reflow.
  
  Composite-only: transform, opacity — only happen on GPU, no reflow or repaint.
  
  Cost order: Reflow > Repaint > Composite.

Q7: What is layout thrashing and how do you prevent it?
─────────────────────────────────────────────────────────
Answer:
  Layout thrashing occurs when JS alternates between writing layout properties
  and reading layout properties in a loop, forcing the browser to reflow multiple
  times per frame.
  
  // BAD: Forced synchronous layout (thrashing)
  elements.forEach(el => {
    el.style.width = container.offsetWidth + 'px'; // read then write!
  });
  
  // GOOD: Batch reads then writes
  const width = container.offsetWidth; // one read
  elements.forEach(el => {
    el.style.width = width + 'px'; // all writes
  });
  
  Prevention:
  - Batch DOM reads before writes
  - Use requestAnimationFrame to defer reads/writes
  - Use FastDOM library to batch automatically
  - Use CSS classes instead of inline style changes

Q8: What CSS properties trigger reflow vs repaint vs composite?
────────────────────────────────────────────────────────────────
Answer:
  Reflow (Layout + Paint + Composite):
    width, height, margin, padding, border, top, left, right, bottom,
    font-size, display, position, float, min/max-width/height
  
  Repaint (Paint + Composite):
    color, background-color, visibility, box-shadow, border-radius,
    outline, text-decoration
  
  Composite only (GPU — fastest!):
    transform (translate, scale, rotate)
    opacity
    filter (somewhat)
    will-change: transform (creates own layer)
  
  Best practice: Use transform/opacity for animations to avoid reflow/repaint.

Q9: How does requestAnimationFrame help with animations?
─────────────────────────────────────────────────────────
Answer:
  rAF schedules a callback to run before the next browser repaint.
  
  Benefits:
  • Synchronized with display refresh rate (60fps = every 16.67ms)
  • Automatically paused in background tabs (battery saving)
  • Reads/writes in rAF are batched before paint
  • Avoids layout thrashing compared to setTimeout-based animation
  
  function animate() {
    // update position
    element.style.transform = 'translateX(' + (x++) + 'px)';
    requestAnimationFrame(animate);
  }
  requestAnimationFrame(animate);

SECTION 3: JAVASCRIPT ENGINE
────────────────────────────────────────────────────────────────────────────────

Q10: How does V8 compile JavaScript?
──────────────────────────────────────
Answer:
  V8 pipeline:
  1. Tokenization: Source code → tokens
  2. Parsing: Tokens → AST (Abstract Syntax Tree). V8 uses lazy parsing (pre-parsing)
     to parse only what's needed immediately.
  3. Ignition (Interpreter): AST → bytecode. Runs immediately — fast startup.
  4. TurboFan (JIT Compiler): Hot bytecode paths → optimized machine code.
     Uses feedback (type information from interpreter runs) to specialize code.
  5. Deoptimization: If assumptions are violated (e.g., type changes), falls back
     to bytecode.
  
  Key optimizations: Hidden Classes (for fast property access), Inline Caching
  (IC), function inlining, escape analysis.

Q11: What are hidden classes in V8?
─────────────────────────────────────
Answer:
  V8 assigns internal "hidden classes" (also called Maps) to objects with the
  same structure. This allows property access to be as fast as accessing a
  field in a C++ struct (offset-based lookup).
  
  When two objects have identical property assignment order, they share a
  hidden class → V8 can optimize property access across them.
  
  // Good: consistent shape
  function Point(x, y) { this.x = x; this.y = y; } // always x, then y
  const p1 = new Point(1, 2);
  const p2 = new Point(3, 4); // same hidden class → optimizable
  
  // Bad: inconsistent shapes
  const a = { x: 1 };
  a.y = 2; // different hidden class than { x: 1, y: 2 }
  const b = { x: 1, y: 2 }; // different hidden class from a

================================================================================
  KEY TAKEAWAYS
================================================================================
  • URL → DNS → TCP → TLS → HTTP → Parse → CSSOM → Render Tree → Layout → Paint
  • Multi-process: Browser, Renderer (sandboxed), GPU, Network processes
  • Site Isolation: one site per Renderer process (Spectre mitigation)
  • Reflow > Repaint > Composite (cost order)
  • Layout thrashing: batch reads then writes; use rAF
  • V8: Ignition (interpreter) + TurboFan (JIT); hidden classes for fast property access
