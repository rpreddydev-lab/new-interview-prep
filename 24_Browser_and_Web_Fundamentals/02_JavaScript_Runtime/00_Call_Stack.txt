────────────────────────────────────────────────────────────────────────────────
1. WHAT IS THE CALL STACK?
────────────────────────────────────────────────────────────────────────────────

  The Call Stack is a LIFO (Last-In, First-Out) data structure that the
  JavaScript engine uses to keep track of function execution.

  Properties:
    • Single-threaded: JS has ONE call stack (in the main thread)
    • Synchronous: functions execute one at a time, in order
    • LIFO: the last function pushed is the first to execute/complete

  Each entry on the stack is called a STACK FRAME (or Execution Context).

────────────────────────────────────────────────────────────────────────────────
2. EXECUTION CONTEXTS
────────────────────────────────────────────────────────────────────────────────

  Types of Execution Contexts:
    1. Global Execution Context (GEC):
       - Created when JS starts executing
       - One per JS runtime
       - Creates global object (window in browser, global in Node.js)
       - Creates `this` binding (= window in non-strict, = undefined in strict module)
       - Set up as the bottom-most frame on the call stack

    2. Function Execution Context (FEC):
       - Created for EACH function call
       - Contains its own variable environment (local variables, arguments)
       - Contains outer environment reference (lexical scope chain)
       - Contains `this` binding (depends on how function was called)

    3. Eval Execution Context (rare, avoid)

  Each Execution Context has:
    a) Variable Environment:
       - var declarations (hoisted to function scope, initialized to undefined)
       - let/const (hoisted to block scope, in TDZ until initialized)
       - Function declarations (fully hoisted)
    b) Scope Chain (reference to outer environment)
    c) this binding

────────────────────────────────────────────────────────────────────────────────
3. HOW THE CALL STACK WORKS
────────────────────────────────────────────────────────────────────────────────

  Code example:
    function multiply(a, b) {
      return a * b;
    }
    function square(n) {
      return multiply(n, n);
    }
    function main() {
      const result = square(4);
      console.log(result);
    }
    main();

  Call Stack Evolution:
    Step 1: GEC pushed (script starts)
    ┌──────────────────┐
    │  Global Context  │
    └──────────────────┘

    Step 2: main() called
    ┌──────────────────┐
    │  main()          │
    ├──────────────────┤
    │  Global Context  │
    └──────────────────┘

    Step 3: square(4) called inside main()
    ┌──────────────────┐
    │  square(4)       │
    ├──────────────────┤
    │  main()          │
    ├──────────────────┤
    │  Global Context  │
    └──────────────────┘

    Step 4: multiply(4,4) called inside square()
    ┌──────────────────┐
    │  multiply(4,4)   │
    ├──────────────────┤
    │  square(4)       │
    ├──────────────────┤
    │  main()          │
    ├──────────────────┤
    │  Global Context  │
    └──────────────────┘

    Step 5: multiply returns 16 → popped
    ┌──────────────────┐
    │  square(4)       │
    ├──────────────────┤
    │  main()          │
    ├──────────────────┤
    │  Global Context  │
    └──────────────────┘

    Step 6: square returns 16 → popped
    ┌──────────────────┐
    │  main()          │
    ├──────────────────┤
    │  Global Context  │
    └──────────────────┘

    Step 7: console.log(16) called, returns → main() continues
    Step 8: main() returns → popped
    ┌──────────────────┐
    │  Global Context  │
    └──────────────────┘

────────────────────────────────────────────────────────────────────────────────
4. STACK OVERFLOW
────────────────────────────────────────────────────────────────────────────────

  What is it?
    When the call stack exceeds its maximum size.
    Occurs with infinite recursion or excessively deep call chains.

  Error:
    RangeError: Maximum call stack size exceeded

  Example:
    function infinite() {
      return infinite(); // recursive call, never returns
    }
    infinite(); // RangeError!

  Stack size limits (approximate):
    Chrome (V8):    ~10,000-15,000 frames
    Firefox:        ~10,000 frames
    Safari:         ~50,000+ frames
    Node.js (V8):   ~10,000-15,000 frames

  Solutions:
    1. Fix infinite recursion (add base case)
    2. Use trampolining (convert recursion to iteration):
       function trampoline(fn) {
         return function (...args) {
           let result = fn.apply(this, args);
           while (typeof result === 'function') {
             result = result();
           }
           return result;
         };
       }
    3. Use iteration instead of recursion for large data sets
    4. Use setTimeout/async to break up deep recursion
       (each async call clears the stack before next call)

────────────────────────────────────────────────────────────────────────────────
5. HOISTING
────────────────────────────────────────────────────────────────────────────────

  Hoisting: Variable and function declarations moved to the top of their
  scope DURING COMPILATION PHASE (before execution).

  Function declarations: FULLY hoisted (name + body available immediately)
    greet(); // "Hello" — works before declaration!
    function greet() { console.log("Hello"); }

  var: Hoisted and initialized to undefined
    console.log(x); // undefined (not ReferenceError)
    var x = 5;
    console.log(x); // 5

  let/const: Hoisted but NOT initialized → TEMPORAL DEAD ZONE (TDZ)
    console.log(y); // ReferenceError: Cannot access 'y' before initialization
    let y = 5;

  Function expressions:
    console.log(fn); // undefined (var hoisted, but = undefined)
    var fn = function() {};

    console.log(fn2); // ReferenceError (let TDZ)
    let fn2 = function() {};

  TDZ (Temporal Dead Zone):
    The period between when a let/const binding is created (hoisted)
    and when it's initialized. Accessing it during TDZ → ReferenceError.
    
    {
      // TDZ for x starts here
      console.log(x); // ReferenceError
      let x = 10;     // TDZ ends, x initialized
      console.log(x); // 10
    }

6. SCOPE AND THE SCOPE CHAIN
────────────────────────────────────────────────────────────────────────────────

  Types of Scope:
    Global scope:  Variables accessible everywhere
    Function scope: Variables declared with var inside functions
    Block scope:   Variables declared with let/const inside {}

  Lexical Scoping:
    - Scope is determined by WHERE code is WRITTEN, not where it's called
    - Inner functions can access outer function's variables
    - Called "lexical" or "static" scoping

  Scope Chain:
    When a variable is accessed, JS looks:
    1. Current function's scope
    2. Outer function's scope (continues up)
    3. Global scope
    4. ReferenceError if not found

  Example:
    let globalVar = 'global';
    function outer() {
      let outerVar = 'outer';
      function inner() {
        let innerVar = 'inner';
        console.log(innerVar);   // 'inner' — own scope
        console.log(outerVar);   // 'outer' — outer scope chain
        console.log(globalVar);  // 'global' — global scope
      }
      inner();
    }

  Closures:
    A function that retains access to its outer scope even after
    the outer function has returned.
    
    function makeCounter() {
      let count = 0;     // captured in closure
      return function() {
        return ++count;  // accesses outer scope
      };
    }
    const counter = makeCounter();
    counter(); // 1
    counter(); // 2
    // count persists in closure even after makeCounter() returned

7. THIS BINDING
────────────────────────────────────────────────────────────────────────────────

  `this` is determined by HOW a function is called:

  Default binding (non-strict):
    function f() { console.log(this); } // window (non-strict)
    f();

  Default binding (strict mode):
    'use strict';
    function f() { console.log(this); } // undefined

  Implicit binding (method call):
    const obj = { name: 'Alice', greet() { console.log(this.name); }};
    obj.greet(); // 'Alice' — this = obj

  Explicit binding:
    f.call(obj, arg1, arg2)     // this = obj, args individually
    f.apply(obj, [arg1, arg2])  // this = obj, args as array
    const bound = f.bind(obj)   // returns new function with this = obj

  new binding (constructor):
    function Person(name) { this.name = name; }
    const p = new Person('Bob'); // this = newly created object

  Arrow functions — NO own this:
    const obj = {
      name: 'Alice',
      greet: () => console.log(this.name), // this = surrounding context (NOT obj)
      greetMethod() {
        const inner = () => console.log(this.name); // this = obj (lexical)
        inner();
      }
    };

  Priority order: new > explicit > implicit > default

8. TAIL CALL OPTIMIZATION (TCO)
────────────────────────────────────────────────────────────────────────────────

  What is a tail call?
    A function call that is the LAST action of a function.
    
    function factorial(n, acc = 1) {
      if (n <= 1) return acc;
      return factorial(n - 1, n * acc); // TAIL CALL — last operation
    }

  TCO:
    In a proper tail call, the caller's stack frame is reused for the callee.
    No new frame pushed → constant stack space → no stack overflow.
    ES2015 spec requires TCO in strict mode.

  Reality:
    Only Safari/JSC fully implements TCO.
    V8/Chrome removed TCO (too complex to implement safely).

9. INTERVIEW QUESTIONS & ANSWERS
────────────────────────────────────────────────────────────────────────────────

Q: What is the call stack in JavaScript?
A: A LIFO data structure tracking function execution. When a function is
   called, a new frame (execution context) is pushed. When it returns,
   the frame is popped. JS has a single call stack — it's single-threaded.

Q: What causes a stack overflow?
A: Infinite or excessively deep recursion that exhausts the call stack's
   maximum size. Chrome's V8 limits to ~10,000-15,000 frames.
   Solution: add a base case, use iteration, or use trampolining.

Q: What is hoisting?
A: JS engine moves declarations to the top of their scope during the
   compilation phase. Function declarations are fully hoisted. var is
   hoisted and initialized to undefined. let/const are hoisted but not
   initialized (accessing them before their line → ReferenceError/TDZ).

Q: What is the Temporal Dead Zone?
A: The period between when a let/const variable is hoisted and when it
   is actually initialized. Accessing the variable in this window throws
   a ReferenceError. It enforces initialization-before-use.

Q: What is lexical scoping?
A: Scope is determined by where code is written (source position), not
   where it's called. Inner functions can access variables from outer
   functions via the scope chain. This enables closures.

Q: What is a closure?
A: A function that retains a reference to its outer scope's variables
   even after the outer function has returned. The closed-over variables
   persist as long as the closure exists. Used for: private state,
   factory functions, memoization, event handlers.

Q: How does `this` work in JavaScript?
A: `this` is determined by call-site: default binding (window/undefined),
   implicit binding (method call — this = object), explicit binding
   (call/apply/bind), new binding (constructor — this = new object).
   Arrow functions inherit `this` from lexical scope — no own binding.

Q: What is the difference between call, apply, and bind?
A: All three set `this` explicitly.
   call(thisArg, arg1, arg2): calls immediately, args individually.
   apply(thisArg, [arg1, arg2]): calls immediately, args as array.
   bind(thisArg): returns a NEW function with `this` permanently bound.

Q: What is the difference between var, let, and const in terms of hoisting?
A: var: function-scoped, hoisted and initialized to undefined.
   let: block-scoped, hoisted but in TDZ until declaration (ReferenceError if accessed early).
   const: block-scoped, same as let but must be initialized and cannot be reassigned.

================================================================================
  KEY TAKEAWAYS
================================================================================
  • Call stack: LIFO, single-threaded, one frame per function call
  • Execution context: Variable env + Scope chain + this binding
  • Stack overflow: infinite recursion → RangeError
  • Hoisting: function declarations fully hoisted; var → undefined; let/const → TDZ
  • TDZ: let/const inaccessible before initialization line
  • Lexical scoping: scope from WHERE code is written
  • Closures: functions retain access to outer scope after outer fn returns
  • this: determined by call site; arrow functions use lexical this
================================================================================
