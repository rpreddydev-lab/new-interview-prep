@Component (or @Bean) → makes it a Spring-managed bean (required!)

    private static final Logger log = LoggerFactory.getLogger(LoggingAspect.class);

    // Advice methods go here
}

  2. POINTCUT EXPRESSIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Pointcut syntax: execution(modifiers? returnType declaringType? methodName(params) throws?)

Wildcards:
  *   → matches any single element
  ..  → matches any number of elements (packages, params)
  +   → matches the class and all subclasses

Examples:

  // Any public method in OrderService
  execution(public * com.example.service.OrderService.*(..))

  // Any method in any class in the service package
  execution(* com.example.service.*.*(..))

  // Any method in service package or sub-packages
  execution(* com.example.service..*.*(..))

  // Methods named "get*" returning any type, any params
  execution(* get*(..))

  // Methods with a single String parameter
  execution(* *(String))

  // Methods returning String
  execution(String com.example..*(..))

  // All public methods (common broad pointcut)
  execution(public * *(..))

  // within — restricts to all methods in a type/package
  within(com.example.service.*)
  within(com.example.service..*)

  // @annotation — methods annotated with a custom annotation
  @annotation(com.example.annotation.Loggable)
  @annotation(org.springframework.transaction.annotation.Transactional)

  // @within — all methods in classes annotated with a type annotation
  @within(org.springframework.stereotype.Service)

  // bean — Spring-specific: matches by bean name
  bean(orderService)
  bean(*Service)      // all beans ending with "Service"

  // args — restricts by argument type
  args(String, ..)    // first arg is String, rest anything
  args(com.example.dto.CreateOrderRequest)

  // target — restricts to a specific type
  target(com.example.service.OrderService)

  3. NAMED POINTCUTS (REUSE)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Define once, reuse across multiple advice:

@Aspect
@Component
public class AppPointcuts {

    // All public methods in service layer
    @Pointcut("execution(public * com.example.service..*(..))")
    public void serviceLayer() {}

    // All repository methods
    @Pointcut("execution(* com.example.repository..*(..))")
    public void repositoryLayer() {}

    // Methods annotated with @Transactional
    @Pointcut("@annotation(org.springframework.transaction.annotation.Transactional)")
    public void transactional() {}

    // Combine with logical operators: && || !
    @Pointcut("serviceLayer() && !transactional()")
    public void nonTransactionalService() {}
}

// Using named pointcuts in advice (can be in different classes)
@Aspect @Component
public class LoggingAspect {

    @Before("com.example.aop.AppPointcuts.serviceLayer()")
    public void logServiceCall(JoinPoint jp) { ... }

    // Combined inline
    @Around("com.example.aop.AppPointcuts.serviceLayer() " +
            "&& !com.example.aop.AppPointcuts.transactional()")
    public Object aroundNonTx(ProceedingJoinPoint pjp) throws Throwable { ... }
}

  4. @Before ADVICE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Runs before the target method. Cannot stop execution (unless throws).

@Before("execution(* com.example.service..*(..))")
public void logBefore(JoinPoint jp) {
    String className = jp.getTarget().getClass().getSimpleName();
    String methodName = jp.getSignature().getName();
    Object[] args = jp.getArgs();

    log.info("Entering: {}.{}() with args: {}",
        className, methodName, Arrays.toString(args));
}

JoinPoint API:
  jp.getTarget()          → the target bean (original object)
  jp.getThis()            → the proxy object
  jp.getSignature()       → MethodSignature with method metadata
  jp.getArgs()            → method arguments array
  jp.getStaticPart()      → static join point info (signature, kind)

  5. @After, @AfterReturning, @AfterThrowing
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

// Runs after method (success or exception) — like finally
@After("com.example.aop.AppPointcuts.serviceLayer()")
public void logAfter(JoinPoint jp) {
    log.info("Exiting: {}.{}()",
        jp.getTarget().getClass().getSimpleName(),
        jp.getSignature().getName());
}

// Runs only after SUCCESSFUL return — access return value
@AfterReturning(
    pointcut = "execution(* com.example.service.OrderService.placeOrder(..))",
    returning = "result"    // must match parameter name
)
public void logOrderCreated(JoinPoint jp, Object result) {
    log.info("Order created: {}", result);
}

// Runs only when EXCEPTION thrown — access the exception
@AfterThrowing(
    pointcut = "com.example.aop.AppPointcuts.serviceLayer()",
    throwing = "ex"         // must match parameter name
)
public void logException(JoinPoint jp, Exception ex) {
    log.error("Exception in {}.{}(): {}",
        jp.getTarget().getClass().getSimpleName(),
        jp.getSignature().getName(),
        ex.getMessage());
}

  6. @Around ADVICE (MOST POWERFUL)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

@Around wraps the method. You MUST call pjp.proceed() to execute it.
Can modify args, return value, swallow exceptions.

@Around("com.example.aop.AppPointcuts.serviceLayer()")
public Object logExecutionTime(ProceedingJoinPoint pjp) throws Throwable {
    long start = System.currentTimeMillis();

    String methodName = pjp.getSignature().toShortString();
    log.info(">> {}", methodName);

    try {
        Object result = pjp.proceed();          // ← MUST call this!
        long elapsed = System.currentTimeMillis() - start;
        log.info("<< {} completed in {}ms", methodName, elapsed);
        return result;                           // return the original result
    } catch (Throwable ex) {
        log.error("<< {} threw: {}", methodName, ex.getMessage());
        throw ex;                                // re-throw the exception
    }
}

// Modify arguments:
Object[] args = pjp.getArgs();
args[0] = ((String) args[0]).toUpperCase();     // modify first arg
Object result = pjp.proceed(args);              // pass modified args

// Modify return value:
Object result = pjp.proceed();
if (result instanceof String s) {
    return s.toLowerCase();                     // transform return
}
return result;

// Skip method entirely (caching example):
String cacheKey = generateKey(pjp);
if (cache.contains(cacheKey)) {
    return cache.get(cacheKey);                 // no proceed() call
}
Object result = pjp.proceed();
cache.put(cacheKey, result);
return result;

ProceedingJoinPoint extends JoinPoint and adds:
  proceed()          → execute the method with original args
  proceed(Object[])  → execute with modified args

  7. BINDING PARAMETERS WITH args()
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

// Bind specific argument for type-safe access
@Before("execution(* com.example.service.UserService.createUser(..)) && args(request,..)")
public void auditUserCreation(JoinPoint jp, CreateUserRequest request) {
    auditLog.record("CREATE_USER", request.getEmail());
}

// Bind annotation
@Before("@annotation(loggable)")
public void processLoggable(JoinPoint jp, Loggable loggable) {
    if (loggable.logArgs()) {
        log.info("Args: {}", Arrays.toString(jp.getArgs()));
    }
}

  8. ADVICE ORDERING — @Order
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

When multiple aspects advise the same join point, use @Order
to control the order.

  @Aspect @Component @Order(1)   ← lower number = higher priority
  public class SecurityAspect { ... }

  @Aspect @Component @Order(2)
  public class LoggingAspect { ... }

  @Aspect @Component @Order(3)
  public class PerformanceAspect { ... }

For @Around: higher priority aspect forms the OUTER shell.
  SecurityAspect.around → LoggingAspect.around → PerformanceAspect.around
  → actual method execution

Q: What is a pointcut and how does it differ from advice?
A: A pointcut is an expression that defines WHICH methods the advice
   applies to (the "where"). Advice is the actual code to execute
   (the "what" and "when"). Example: pointcut = all service methods;
   advice = log execution time.

Q: What is the difference between @After and @AfterReturning?
A: @After runs regardless of whether the method succeeded or threw
   an exception (like a finally block). @AfterReturning runs only
   when the method returns normally (no exception). @AfterReturning
   has access to the return value via the returning parameter.

Q: What must you always do in @Around advice?
A: Call pjp.proceed() to execute the actual method. If you omit it,
   the target method never runs. The return value of proceed() must
   be returned (unless you intentionally want to change or suppress it).

Q: How do you pass modified arguments to the target method?
A: Use pjp.proceed(Object[] modifiedArgs) — pass a new args array with
   modified values to the overloaded proceed(). The original jp.getArgs()
   array should not be modified in place; create a copy first.

Q: When would you use @AfterThrowing vs catching in @Around?
A: Use @AfterThrowing when you only need to react to exceptions
   (log, alert) without modifying the exception or suppressing it.
   Use @Around when you need to catch, transform, suppress, or retry
   on exception — because @Around gives you full control via try-catch.
