  1. WHAT IS INTEGRATION TESTING?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Integration tests verify that multiple application layers work together
correctly against real or near-real infrastructure (DB, message broker, etc.)

Spring integration tests commonly cover:
  - Repository layer with a real database (@DataJpaTest or Testcontainers)
  - Controller → Service → Repository with real DB
  - Transactional behavior (rollback, commit)
  - Security with full filter chain
  - Messaging (Kafka consumer/producer)

@DataJpaTest loads: JPA auto-configuration, Spring Data repositories,
                    H2 in-memory DB (by default)
Does NOT load: @Service, @Controller, @Component outside JPA

@DataJpaTest
class OrderRepositoryTest {

    @Autowired
    private OrderRepository orderRepository;

    @Autowired
    private TestEntityManager testEntityManager;  // helper to persist test data

    @Test
    void shouldFindOrdersByStatus() {
        // Arrange: persist test data
        Order pending = Order.builder()
            .status(OrderStatus.PENDING)
            .total(new BigDecimal("49.99"))
            .customerId(1L)
            .build();
        testEntityManager.persistAndFlush(pending);

        // Act
        List<Order> results = orderRepository.findByStatus(OrderStatus.PENDING);

        // Assert
        assertThat(results).hasSize(1);
        assertThat(results.get(0).getTotal())
            .isEqualByComparingTo(new BigDecimal("49.99"));
    }

    @Test
    void shouldFindTopOrdersByTotalDesc() {
        testEntityManager.persistAndFlush(
            Order.builder().total(new BigDecimal("10.00")).build());
        testEntityManager.persistAndFlush(
            Order.builder().total(new BigDecimal("50.00")).build());
        testEntityManager.persistAndFlush(
            Order.builder().total(new BigDecimal("30.00")).build());

        List<Order> top2 = orderRepository.findTop2ByOrderByTotalDesc();

        assertThat(top2).hasSize(2);
        assertThat(top2.get(0).getTotal()).isEqualByComparingTo("50.00");
        assertThat(top2.get(1).getTotal()).isEqualByComparingTo("30.00");
    }

    @Test
    void shouldTransactionallyRollbackOnException() {
        // @DataJpaTest wraps each test in a transaction that rolls back after test
    }
}

Test the full service → repository flow with a real database.

@SpringBootTest
@Transactional          // rollback after each test — clean state
class OrderServiceIntegrationTest {

    @Autowired
    private OrderService orderService;

    @Autowired
    private OrderRepository orderRepository;

    @MockBean
    private PaymentService paymentService;   // external dependency

    @MockBean
    private EmailService emailService;

    @Test
    void shouldPersistOrderWhenPlaced() {
        // Given
        given(paymentService.charge(any())).willReturn("TX-001");
        CreateOrderRequest request = new CreateOrderRequest(1L, 2, new BigDecimal("49.99"));

        // When
        Order placed = orderService.placeOrder(request);

        // Then — verify persistence
        Order found = orderRepository.findById(placed.getId()).orElseThrow();
        assertThat(found.getStatus()).isEqualTo(OrderStatus.CONFIRMED);
        assertThat(found.getPaymentRef()).isEqualTo("TX-001");
    }

    @Test
    void shouldRollbackWhenPaymentFails() {
        // Given
        given(paymentService.charge(any())).willThrow(new PaymentException("declined"));
        long beforeCount = orderRepository.count();

        // When
        assertThatThrownBy(() ->
            orderService.placeOrder(new CreateOrderRequest(1L, 1, BigDecimal.TEN)))
            .isInstanceOf(PaymentException.class);

        // Then — no order saved due to @Transactional rollback
        assertThat(orderRepository.count()).isEqualTo(beforeCount);
    }
}

    // Test that @Transactional(readOnly=true) does NOT allow writes
    @Test
    void shouldNotAllowWriteInReadOnlyTransaction() {
        // Implemented via Hibernate: read-only flushes are suppressed
        // Any attempt to flush changes in a readOnly transaction is ignored or throws
    }

    // Test REQUIRES_NEW propagation
    @Test
    void shouldSaveAuditLogEvenIfMainTransactionRollsBack() {
        // AuditService uses PROPAGATION.REQUIRES_NEW
        assertThatThrownBy(() -> orderService.placeOrderWithFailure())
            .isInstanceOf(RuntimeException.class);

        // audit log was saved in its own transaction
        assertThat(auditRepository.count()).isGreaterThan(0);
    }

    // Test rollback for checked exceptions
    @Test
    void shouldNotRollbackForCheckedException() {
        // By default @Transactional rolls back ONLY for unchecked exceptions
        // Checked exceptions are committed unless rollbackFor specified
    }
}

@SpringBootTest
@EmbeddedKafka(
    partitions = 1,
    topics = {"orders", "order-notifications"},
    brokerProperties = {"listeners=PLAINTEXT://localhost:9092",
                        "port=9092"}
)
class OrderKafkaIntegrationTest {

    @Autowired
    private KafkaTemplate<String, OrderEvent> kafkaTemplate;

    @Autowired
    private OrderConsumer orderConsumer;

    @Value("${spring.kafka.bootstrap-servers}")
    private String bootstrapServers;

    @Test
    void shouldConsumeOrderEvent() throws InterruptedException {
        OrderEvent event = new OrderEvent("ORD-001", "CREATED");

        kafkaTemplate.send("orders", event.getOrderId(), event);

        // Wait for consumer to process
        CountDownLatch latch = orderConsumer.getLatch();
        boolean consumed = latch.await(10, TimeUnit.SECONDS);

        assertThat(consumed).isTrue();
        assertThat(orderConsumer.getLastEvent().getOrderId()).isEqualTo("ORD-001");
    }
}

// Consumer with CountDownLatch for test synchronization:
@Component
public class OrderConsumer {
    private final CountDownLatch latch = new CountDownLatch(1);
    private volatile OrderEvent lastEvent;

    @KafkaListener(topics = "orders")
    public void handleOrder(OrderEvent event) {
        this.lastEvent = event;
        latch.countDown();
    }
    public CountDownLatch getLatch() { return latch; }
    public OrderEvent getLastEvent() { return lastEvent; }
}

    private int wireMockPort;

    @Autowired
    private PaymentService paymentService;

    void shouldCallExternalPaymentGateway() {
        // Stub the external API
        stubFor(post(urlEqualTo("/payment/charge"))
            .withRequestBody(matchingJsonPath("$.amount"))
            .willReturn(aResponse()
                .withStatus(200)
                .withHeader("Content-Type", "application/json")
                .withBody("{\"transactionId\": \"TX-001\", \"status\": \"SUCCESS\"}")));

        // Call the service (which internally calls the mocked HTTP endpoint)
        PaymentResult result = paymentService.charge(new PaymentRequest("100.00", "USD"));

        assertThat(result.getTransactionId()).isEqualTo("TX-001");
        verify(1, postRequestedFor(urlEqualTo("/payment/charge")));
    }
}

Q: Why add @Transactional to integration tests?
A: It wraps each test method in a transaction that is rolled back after
   the test completes. This keeps the database clean between tests without
   needing to explicitly delete data. However, avoid it when testing that
   transactions themselves commit correctly — in that case, clean up manually.

Q: What is TestEntityManager and when is it used?
A: TestEntityManager is a Spring Test utility for @DataJpaTest. It provides
   a subset of EntityManager methods (persistAndFlush, find, etc.) designed
   for test data setup. It ensures test data is flushed to the in-memory
   DB before the repository query runs.

Q: What is the difference between H2 and Testcontainers for integration testing?
A: H2 is an in-memory database that is fast and easy but doesn't match
   production behavior (different SQL dialect, missing features).
   Testcontainers starts the actual database (PostgreSQL, MySQL) in Docker,
   matching production exactly. Use H2 for simple repository tests; use
   Testcontainers for accurate SQL dialect, stored procedures, migrations.

Q: What is WireMock and when do you use it?
A: WireMock is an HTTP mock server. It intercepts HTTP calls made by your
   application during tests and returns configured stub responses. Use it
   to test code that calls external HTTP APIs (payment gateways, third-party
   services) without making real network calls. It supports request matching,
   response stubbing, and verification.

Q: How do you test @Transactional with REQUIRES_NEW propagation?
A: The inner transaction runs in a separate, independent transaction. In
   a test, make the outer transaction fail (e.g., throw an exception after
   the inner call). Verify that the inner transaction's changes are committed
   to the DB even though the outer transaction rolled back.
