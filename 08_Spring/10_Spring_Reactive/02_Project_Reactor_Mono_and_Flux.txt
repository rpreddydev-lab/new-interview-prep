  1. CREATING MONO AND FLUX
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

// ─── Mono creation ────────────────────────────────────────
Mono<String> m1 = Mono.just("hello");           // single value
Mono<String> m2 = Mono.empty();                 // no value (completes)
Mono<String> m3 = Mono.error(new RuntimeException("oops")); // terminal error
Mono<String> m4 = Mono.fromCallable(() -> expensiveOp());   // lazy from Callable
Mono<String> m5 = Mono.defer(() -> Mono.just(currentTime())); // re-evaluated on each subscribe
Mono<Void>   m6 = Mono.fromRunnable(() -> sideEffect());    // returns empty after Runnable

// ─── Flux creation ────────────────────────────────────────
Flux<Integer> f1 = Flux.just(1, 2, 3, 4, 5);
Flux<Integer> f2 = Flux.fromIterable(List.of(1, 2, 3));
Flux<Integer> f3 = Flux.fromArray(new Integer[]{1, 2, 3});
Flux<Integer> f4 = Flux.range(1, 10);           // 1 through 10
Flux<Long>    f5 = Flux.interval(Duration.ofSeconds(1)); // emit 0,1,2... every second
Flux<String>  f6 = Flux.empty();
Flux<String>  f7 = Flux.error(new RuntimeException());

// Programmatic creation (for custom sources)
Flux<Integer> f8 = Flux.create(sink -> {
    sink.next(1);
    sink.next(2);
    sink.complete();
});

// Flux from Mono
Flux<String> fromMono = Mono.just("a").flux();

  2. TRANSFORMATION OPERATORS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

// map — synchronous 1:1 transformation
Mono.just("hello").map(String::toUpperCase)  // Mono<"HELLO">

Flux.just(1, 2, 3).map(n -> n * 2)          // Flux<2, 4, 6>

// flatMap — async 1:1 (returns Mono/Flux per element, subscribes concurrently)
Flux.just(1L, 2L, 3L)
    .flatMap(id -> productRepository.findById(id))  // Flux<Product> (concurrent)

// concatMap — async 1:1, preserves order (sequential, not concurrent)
Flux.just(1L, 2L, 3L)
    .concatMap(id -> productRepository.findById(id))  // Flux<Product> (ordered)

// flatMapMany — Mono → Flux
Mono.just("category")
    .flatMapMany(cat -> productRepository.findByCategory(cat))  // Flux<Product>

// switchMap — only subscribes to latest inner publisher (good for type-ahead)
searchInput.switchMap(term -> service.search(term))

// filter
Flux.just(1, 2, 3, 4, 5).filter(n -> n % 2 == 0)   // Flux<2, 4>

// take / skip
Flux.range(1, 100).take(5)     // Flux<1,2,3,4,5>
Flux.range(1, 100).skip(95)    // Flux<96,97,98,99,100>

// distinct
Flux.just(1, 1, 2, 2, 3).distinct()  // Flux<1, 2, 3>

// sort (buffers all elements — avoid on infinite streams)
Flux.just(3, 1, 2).sort()    // Flux<1, 2, 3>

  3. COMBINING OPERATORS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

// zip — wait for all, combine into Tuple
Mono<OrderDetails> details = Mono.zip(
    orderService.findById(id),         // Mono<Order>
    productService.findById(prodId),   // Mono<Product>
    customerService.findById(custId)   // Mono<Customer>
).map(tuple -> new OrderDetails(tuple.getT1(), tuple.getT2(), tuple.getT3()));

// zipWith
orderMono.zipWith(productMono)
    .map(tuple -> enrich(tuple.getT1(), tuple.getT2()));

// merge — subscribe to all, interleave as values arrive
Flux<Event> events = Flux.merge(
    streamA,   // Flux<Event>
    streamB,   // Flux<Event>
    streamC    // Flux<Event>
);  // order determined by emission time

// concat — subscribe sequentially, full first then second
Flux<Integer> all = Flux.concat(Flux.just(1, 2), Flux.just(3, 4)); // 1,2,3,4

// mergeWith
flux1.mergeWith(flux2)   // subscribes both concurrently, merges interleaved

// combineLatest — emits when any source emits, combining latest from each
Flux.combineLatest(priceFlux, quantityFlux,
    (price, qty) -> price.multiply(BigDecimal.valueOf(qty)));

// then — ignore upstream value, chain next operation
orderService.save(order)
    .then(emailService.sendConfirmation(order.getId()))   // Mono<Void> after save
    .then();

// thenMany
Mono.just(order).thenMany(Flux.just("a", "b", "c"))

  4. ERROR HANDLING OPERATORS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

// onErrorReturn — fallback value
Mono.just(id)
    .flatMap(repo::findById)
    .onErrorReturn(DatabaseException.class, Product.empty());

// onErrorResume — fallback publisher
productService.findById(id)
    .onErrorResume(ex -> fallbackService.findById(id));

// onErrorMap — transform exception
httpClient.get()
    .onErrorMap(ConnectException.class, ex -> new ServiceUnavailableException());

// doOnError — side effect, does NOT handle
Mono.fromCallable(this::riskyOp)
    .doOnError(ex -> log.error("Failed", ex));

// retry
externalService.call()
    .retry(3)                         // retry up to 3 times on any error

externalService.call()
    .retryWhen(Retry.backoff(3, Duration.ofSeconds(1))   // exponential backoff
                   .filter(ex -> ex instanceof TransientException)
                   .onRetryExhaustedThrow((spec, signal) ->
                       new ServiceException("exhausted")));

// timeout
service.call()
    .timeout(Duration.ofSeconds(5))
    .onErrorResume(TimeoutException.class, e -> Mono.just(fallback));

    .doOnSubscribe(sub -> log.debug("Subscribed"))
    .doOnNext(o     -> log.debug("Processing order {}", o.getId()))
    .doOnSuccess(o  -> log.debug("Success"))
    .doOnError(ex   -> log.error("Error", ex))
    .doFinally(type -> log.debug("Signal type: {}", type)); // COMPLETE/ERROR/CANCEL

Flux.just(1, 2, 3)
    .doOnRequest(n -> log.debug("Requested {} items", n))
    .doOnComplete(  () -> log.debug("Stream complete"))
    .doOnCancel(    () -> log.debug("Cancelled by downstream"));

  6. SCHEDULERS — THREADING MODEL
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Schedulers.immediate()         — current thread (no switch)
Schedulers.single()            — single reusable thread
Schedulers.parallel()          — CPU-bound (CPUs * 2 threads), Netty event loop
Schedulers.boundedElastic()    — elastic thread pool for blocking I/O (max 10*CPUs)
Schedulers.fromExecutorService(exec) — custom ExecutorService

// subscribeOn — affects which thread the source subscribes on
Mono.fromCallable(() -> blockingDB.query())
    .subscribeOn(Schedulers.boundedElastic())

// publishOn — affects which thread subsequent operators run on
Flux.just(1, 2, 3)
    .publishOn(Schedulers.parallel())  // downstream operators run on parallel
    .map(n -> compute(n));             // runs on parallel scheduler

  7. SUBSCRIBING AND BLOCKING
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

// subscribe — non-blocking, triggers the pipeline
Mono.just("hello")
    .subscribe(
        value -> log.debug("Got: {}", value),    // onNext
        error -> log.error("Error", error),      // onError
        ()    -> log.debug("Complete")           // onComplete
    );

// block — blocks current thread until Mono completes (avoid in WebFlux)
String result = Mono.just("hello").block();
List<Integer> list = Flux.range(1, 5).collectList().block();

// collectList — Flux → Mono<List>
Mono<List<Product>> products = productFlux.collectList();

// collectMap
Mono<Map<Long, Product>> map = productFlux
    .collectMap(Product::getId);

// reduce
Mono<BigDecimal> total = orderFlux
    .reduce(BigDecimal.ZERO, (acc, o) -> acc.add(o.getTotal()));

Q: What is the difference between map and flatMap in Project Reactor?
A: map applies a synchronous 1:1 transformation and returns the result directly.
   flatMap applies an async transformation — the function returns Mono/Flux, and
   flatMap subscribes to each inner publisher concurrently. Use map for CPU-bound
   transformations; use flatMap when the transformation involves I/O.

Q: What is the difference between flatMap and concatMap?
A: Both transform each element to a publisher and flatten the results. flatMap
   subscribes to all inner publishers concurrently — faster but order not
   guaranteed. concatMap subscribes sequentially (next only after previous
   completes) — order guaranteed but slower. Use concatMap when ordering matters
   (e.g., sequential DB inserts with dependencies).

Q: What is the difference between subscribeOn and publishOn?
A: subscribeOn determines which thread the source Subscriber subscribes on —
   affects the whole chain from source. publishOn switches the thread for
   downstream operators that come after it. Use subscribeOn for blocking I/O
   at the source; use publishOn to switch to a specific thread pool for
   downstream processing.

Q: Why should you avoid calling .block() inside a WebFlux handler?
A: WebFlux runs on a small event-loop thread pool (Netty). Calling .block()
   blocks one of these precious threads, making it unavailable to handle other
   requests. Under load, all event-loop threads can block, causing the service
   to freeze. Use .subscribeOn(Schedulers.boundedElastic()) for blocking I/O instead.

Q: What is Mono.defer and when is it useful?
A: Mono.just(value) captures the value at creation time (eager). Mono.defer(supplier)
   re-evaluates the supplier on each subscription (lazy). Use defer when the value
   depends on runtime state (e.g., current timestamp, current user), to avoid
   sharing mutable state across subscriptions, or to ensure fresh values per request.
