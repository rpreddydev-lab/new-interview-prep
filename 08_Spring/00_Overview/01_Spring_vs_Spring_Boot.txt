================================================================
  SPRING vs SPRING BOOT
================================================================

================================================================
WHAT IS THE SPRING FRAMEWORK?
================================================================

  The Spring Framework is a comprehensive Java framework providing:
  - IoC container (dependency injection)
  - AOP, Data access, Web MVC, Security, Messaging, Testing

  You configure everything explicitly:
  - XML or Java @Configuration
  - Declare every bean
  - Configure DataSource, TransactionManager, DispatcherServlet manually

================================================================
WHAT IS SPRING BOOT?
================================================================

  Spring Boot is an OPINIONATED layer on top of the Spring Framework.
  It does NOT replace Spring; it bootstraps Spring apps with:

  1. Auto-Configuration   -- configures beans automatically based on
                             classpath dependencies and properties
  2. Starter POMs         -- curated dependency bundles (no version conflicts)
  3. Embedded Servers     -- Tomcat / Jetty / Undertow bundled; no WAR deploy
  4. Actuator             -- built-in production metrics and health endpoints
  5. Spring Initializr    -- project scaffold generator (start.spring.io)

  Result: a Spring Boot app can start with a single @SpringBootApplication
  annotation and main() method.

================================================================
SIDE-BY-SIDE COMPARISON
================================================================

  Feature                    | Spring Framework        | Spring Boot
  ---------------------------|-------------------------|------------------------
  Setup effort               | High (manual config)    | Minimal (auto-config)
  Dependency management      | Manual versions         | Managed via BOM/starters
  Server deployment          | WAR to external server  | Embedded (JAR with main)
  Configuration approach     | XML or Java @Config     | application.yml + auto
  Production readiness       | DIY                     | Actuator endpoints built-in
  Opinionated defaults       | None                    | Yes (can override)
  Startup speed (config)     | Slower (more setup)     | Fast (pre-configured)
  Flexibility                | Full control            | Defaults + customization
  Testing                    | Manual context setup    | @SpringBootTest, slices
  Suitable for               | Fine-grained control    | Microservices, rapid dev

================================================================
HOW SPRING BOOT AUTO-CONFIGURATION WORKS
================================================================

  When you add spring-boot-starter-web to the classpath:

  1. @SpringBootApplication includes @EnableAutoConfiguration
  2. Spring Boot reads META-INF/spring/org.springframework.boot.
     autoconfigure.AutoConfiguration.imports (Boot 2.7+/3.x)
  3. Each AutoConfiguration class (e.g. DispatcherServletAutoConfiguration)
     has @ConditionalOnClass, @ConditionalOnMissingBean guards
  4. If conditions pass, Spring Boot registers the bean automatically

  Example:
    DataSourceAutoConfiguration kicks in when:
    - spring-jdbc or spring-data-jpa is on classpath
    - No DataSource bean is already manually defined
    - spring.datasource.url property is set

================================================================
@SpringBootApplication DEEP DIVE
================================================================

  @SpringBootApplication is a meta-annotation composed of:

  @SpringBootConfiguration       // = @Configuration; marks this class
  @EnableAutoConfiguration       // triggers auto-config mechanism
  @ComponentScan(basePackages)   // scans current package and sub-packages

  @SpringBootApplication
  public class MyApp {
      public static void main(String[] args) {
          SpringApplication.run(MyApp.class, args);
      }
  }

  SpringApplication.run():
    1. Creates a SpringApplication instance
    2. Determines application type (SERVLET, REACTIVE, NONE)
    3. Loads ApplicationContext (AnnotationConfigServletWebServerApplicationContext)
    4. Runs ApplicationContextInitializers
    5. Refreshes context (bean creation, auto-config)
    6. Starts embedded web server
    7. Publishes ApplicationReadyEvent

================================================================
SPRING BOOT STARTERS
================================================================

  Starters are dependency-management artifacts only (no code).
  They pull in the right transitive dependencies at compatible versions.

  Common starters:
    spring-boot-starter             -- core (logging, yaml, etc.)
    spring-boot-starter-web         -- Spring MVC + Tomcat
    spring-boot-starter-webflux     -- Spring WebFlux + Netty
    spring-boot-starter-data-jpa    -- JPA + Hibernate + HikariCP
    spring-boot-starter-data-redis  -- Redis + Lettuce
    spring-boot-starter-security    -- Spring Security
    spring-boot-starter-test        -- JUnit 5, Mockito, AssertJ
    spring-boot-starter-actuator    -- Micrometer, health, metrics
    spring-boot-starter-validation  -- Hibernate Validator

  Excluding a transitive dependency from a starter:
  <dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web</artifactId>
    <exclusions>
      <exclusion>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-tomcat</artifactId>
      </exclusion>
    </exclusions>
  </dependency>
  <dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-undertow</artifactId>
  </dependency>

================================================================
OVERRIDING SPRING BOOT AUTO-CONFIGURATION
================================================================

  Strategy 1: Define your own bean (most common)
    @Bean
    public DataSource dataSource() {
        // Spring Boot backs off because DataSource bean exists
        return new HikariDataSource(config);
    }

  Strategy 2: Use application.properties / .yml
    spring.datasource.url=jdbc:postgresql://localhost/mydb
    spring.datasource.username=user
    spring.datasource.password=pass
    server.port=9090

  Strategy 3: Exclude auto-configuration class
    @SpringBootApplication(
        exclude = { DataSourceAutoConfiguration.class })

  Strategy 4: spring.autoconfigure.exclude property
    spring.autoconfigure.exclude=\
      org.springframework.boot.autoconfigure.jdbc.DataSourceAutoConfiguration

================================================================
SPRING BOOT PRODUCTION FEATURES
================================================================

  Actuator endpoints (add spring-boot-starter-actuator):

  Endpoint               | Default | Purpose
  -----------------------|---------|-------------------------------------
  /actuator/health       | ON      | App + dependency health status
  /actuator/info         | ON      | Custom app metadata
  /actuator/metrics      | OFF*    | Micrometer metrics (JVM, HTTP, etc.)
  /actuator/env          | OFF*    | Environment properties
  /actuator/beans        | OFF*    | All registered beans
  /actuator/mappings     | OFF*    | All @RequestMapping routes
  /actuator/loggers      | OFF*    | Read/change log levels at runtime
  /actuator/threaddump   | OFF*    | Thread dump
  /actuator/heapdump     | OFF*    | Heap dump download
  /actuator/shutdown     | OFF     | Gracefully shut down app (opt-in)

  *Enable via: management.endpoints.web.exposure.include=*

================================================================
WHEN TO USE PLAIN SPRING vs SPRING BOOT
================================================================

  Use Spring Boot (default choice) when:
  - Building new microservices or REST APIs
  - Want rapid development / prototyping
  - Need embedded server (no ops team for app server deployment)
  - CI/CD pipeline produces self-contained JARs

  Use plain Spring Framework when:
  - Deploying to a corporate app server (WebLogic, JBoss) as WAR
  - Very specific, fine-grained container configuration required
  - Integrating into existing legacy Spring XML configuration

  Reality: most new projects (post 2015) use Spring Boot exclusively.
