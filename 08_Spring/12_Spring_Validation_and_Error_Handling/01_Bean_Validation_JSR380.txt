Annotation                   | Target       | Description
-----------------------------|--------------|-----------------------------------
@NotNull                     | Any          | Must not be null

@NotEmpty                    | String, Collection, Map, Array | Not null and not empty
@NotBlank                    | String       | Not null, not empty, not whitespace-only
@Size(min, max)              | String, Collection, Map, Array | Size in range [min, max]
@Min(value)                  | Numeric      | >= value

@DecimalMin(value)           | Numeric/String | >= value (supports inclusive flag)
@DecimalMax(value)           | Numeric/String | <= value

@Pattern(regexp)             | String       | Matches regex

@Past                        | Temporal     | Must be in the past
@PastOrPresent               | Temporal     | Past or now
@Future                      | Temporal     | Must be in the future
@FutureOrPresent             | Temporal     | Future or now
@AssertTrue                  | Boolean      | Must be true
@AssertFalse                 | Boolean      | Must be false

  2. ANNOTATING A DTO
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

public class CreateOrderRequest {

    @NotNull(message = "Customer ID is required")
    @Positive(message = "Customer ID must be positive")
    private Long customerId;

    @NotEmpty(message = "Order must contain at least one item")
    @Size(max = 50, message = "Too many items (max 50)")
    private List<@Valid OrderItemRequest> items;  // validate nested objects

    @NotBlank(message = "Shipping address is required")
    @Size(max = 255)
    private String shippingAddress;

    @Email(message = "Invalid email format")
    private String contactEmail;

    @FutureOrPresent(message = "Delivery date must be today or in the future")
    private LocalDate deliveryDate;
}

public class OrderItemRequest {

    @NotNull
    @Positive
    private Long productId;

    @NotNull
    @Positive
    @Max(value = 999, message = "Quantity cannot exceed 999")
    private Integer quantity;
}

  3. NESTED AND COLLECTION VALIDATION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

// Validate nested object — annotate field with @Valid
@Valid
@NotNull
private Address shippingAddress;

// Validate elements of a collection — put constraint on type argument
private List<@NotBlank @Size(max = 50) String> tags;

private Map<@NotBlank String, @Positive BigDecimal> priceMap;

// Cascade validation into nested DTOs — requires @Valid on the field
public class UserRequest {
    @Valid                  // triggers validation of Address fields
    @NotNull
    private Address address;
}

    @NotNull private LocalDate startDate;

  5. PROGRAMMATIC VALIDATION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Use the Validator directly (useful in services or tests):

@Service
public class OrderValidationService {

    private final jakarta.validation.Validator validator;

    public void validate(Object obj) {
        Set<ConstraintViolation<Object>> violations = validator.validate(obj);
        if (!violations.isEmpty()) {
            throw new ConstraintViolationException(violations);
        }
    }

    // Validate specific group
    public void validateForCreate(CreateOrderRequest request) {
        Set<ConstraintViolation<CreateOrderRequest>> violations =
            validator.validate(request, OnCreate.class);
        if (!violations.isEmpty()) {
            String errors = violations.stream()
                .map(v -> v.getPropertyPath() + ": " + v.getMessage())
                .collect(Collectors.joining(", "));
            throw new ValidationException("Validation failed: " + errors);
        }
    }
}

// In tests:
@SpringBootTest
class ValidationTest {
    @Autowired
    private Validator validator;

    @Test
    void shouldRejectNullCustomerId() {
        CreateOrderRequest req = new CreateOrderRequest();
        req.setCustomerId(null);
        req.setItems(List.of(new OrderItemRequest(1L, 1)));

        Set<ConstraintViolation<CreateOrderRequest>> violations = validator.validate(req);
        assertThat(violations).anyMatch(v -> v.getPropertyPath().toString().equals("customerId"));
    }
}

Default messages come from Hibernate Validator's built-in message descriptors.
Override with custom messages in ValidationMessages.properties:

# src/main/resources/ValidationMessages.properties
jakarta.validation.constraints.NotBlank.message=Field must not be blank
jakarta.validation.constraints.Size.message=Size must be between {min} and {max}

# Custom constraint message key
order.total.positive=Order total must be greater than zero

// Inline message override:
@NotBlank(message = "{order.shipping.required}")
private String shippingAddress;

Q: What is the difference between @NotNull, @NotEmpty, and @NotBlank?
A: @NotNull: value must not be null (allows empty strings/collections).
   @NotEmpty: value must not be null AND must not be empty (collections/strings
   with size > 0; empty string "" fails). @NotBlank: for String only — must not
   be null, must not be empty, must not be whitespace-only (" " fails).
   Recommendation: use @NotBlank for user-input strings, @NotEmpty for collections.

Q: How do you validate a nested object inside a DTO?
A: Annotate the nested field with @Valid. Without @Valid, only null/non-null is
   checked on the outer field but the nested object's own constraints are not
   evaluated. @Valid triggers cascaded validation recursively.

Q: Can Bean Validation validate across multiple fields simultaneously?
A: Not with standard annotations — each constraint applies to a single field.
   For cross-field validation (e.g., password == confirmPassword, endDate > startDate),
   create a custom class-level constraint annotation with a custom ConstraintValidator
   that receives the entire object and can compare any two fields.

Q: What is the difference between jakarta.validation.Validator and Spring's @Valid?
A: @Valid on a controller method parameter tells Spring MVC to automatically
   invoke the Validator before the method runs and throw MethodArgumentNotValidException
   on violations. jakarta.validation.Validator is the programmatic API you inject
   as a bean to manually validate any object from code (tests, services). Both
   use the same underlying Hibernate Validator implementation.

Q: How do you customize error messages for custom constraints?
A: Add a message attribute to your custom annotation defaulting to a key like
   "{com.example.MyConstraint.message}". Then define the message in
   src/main/resources/ValidationMessages.properties. The validation engine
   replaces the message interpolation key with the localized value.
