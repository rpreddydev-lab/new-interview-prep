================================================================
  ApplicationContext vs BeanFactory — IN DEPTH
================================================================

================================================================
CLASS HIERARCHY
================================================================

  BeanFactory  (org.springframework.beans.factory)
      │
      └─► HierarchicalBeanFactory
              └─► ConfigurableBeanFactory
                      └─► ConfigurableListableBeanFactory
                              │
  ApplicationContext  (org.springframework.context)
      ├─► ListableBeanFactory
      ├─► HierarchicalBeanFactory
      ├─► MessageSource
      ├─► ApplicationEventPublisher
      ├─► ResourcePatternResolver
      └─► EnvironmentCapable

  ApplicationContext EXTENDS BeanFactory functionality.

================================================================
BeanFactory — THE BASIC IoC CONTAINER
================================================================

  BeanFactory is the root interface for the Spring IoC container.
  It provides:
    • Bean retrieval by name/type: getBean(String name)
    • Type checking: isTypeMatch(), getType()
    • Singleton check: isSingleton(), isPrototype()

  Key implementation:
    DefaultListableBeanFactory (the underlying engine in all contexts)

  Characteristics:
    ✓ Lightweight — minimal startup overhead
    ✓ Lazy instantiation (beans created on first access)
    ✗ No AOP support
    ✗ No event publishing
    ✗ No i18n
    ✗ No annotation processing (@Autowired doesn't work automatically)
    ✗ No environment/profile support

  Direct usage (rare):
    DefaultListableBeanFactory factory = new DefaultListableBeanFactory();
    XmlBeanDefinitionReader reader = new XmlBeanDefinitionReader(factory);
    reader.loadBeanDefinitions("beans.xml");
    MyService svc = factory.getBean("myService", MyService.class);

  When to use BeanFactory directly: almost never in application code.
  Useful in lightweight frameworks, plugin systems, or testing.

================================================================
ApplicationContext — THE FULL ENTERPRISE CONTAINER
================================================================

  ApplicationContext adds these features on top of BeanFactory:

  Feature                     | How
  ----------------------------|----------------------------------------------
  Eager singleton init        | All singletons created at startup (fast fail)
  Annotation processing       | @Autowired, @Value, @PostConstruct via BPPs
  AOP auto-proxy creation     | BeanPostProcessors for @Aspect, @Transactional
  Event publishing            | ApplicationEventPublisher.publishEvent()
  i18n / MessageSource        | getMessage(code, locale)
  Resource loading            | classpath:, file:, http: URL patterns
  Environment & Profiles      | @Profile, @Value("${...}"), active profiles
  @PropertySource integration | External config file loading
  Bean factory post processing| PropertySourcesPlaceholderConfigurer etc.

================================================================
APPLICATIONCONTEXT IMPLEMENTATIONS
================================================================

  1. AnnotationConfigApplicationContext
     ────────────────────────────────────
     // Used in standalone / test apps (no web)
     ApplicationContext ctx =
         new AnnotationConfigApplicationContext(AppConfig.class);
     MyService svc = ctx.getBean(MyService.class);
     ctx.close();  // triggers @PreDestroy

  2. AnnotationConfigServletWebServerApplicationContext
     ──────────────────────────────────────────────────
     // Used internally by Spring Boot for web apps
     // You normally don't instantiate this directly

  3. ClassPathXmlApplicationContext (legacy)
     ─────────────────────────────────────────
     ApplicationContext ctx =
         new ClassPathXmlApplicationContext("applicationContext.xml");

  4. FileSystemXmlApplicationContext (legacy)
     ──────────────────────────────────────────
     ApplicationContext ctx =
         new FileSystemXmlApplicationContext("/etc/app/beans.xml");

  5. GenericWebApplicationContext
     ─────────────────────────────
     Used in Spring MVC integration tests and embedded configurations.

  6. WebApplicationContext (interface)
     ────────────────────────────────
     Extends ApplicationContext; knows about ServletContext.
     Implementations: XmlWebApplicationContext, AnnotationConfigWebApplicationContext

================================================================
PARENT-CHILD CONTEXT HIERARCHY
================================================================

  In classic Spring MVC apps, there are two contexts:

  Root WebApplicationContext (parent)
    ├── Service layer beans
    ├── Repository beans
    ├── Security beans
    └── Infrastructure beans (DataSource, TransactionManager)

  DispatcherServlet's WebApplicationContext (child)
    ├── @Controller beans
    ├── ViewResolvers
    └── HandlerMappings

  Rules:
    • Child context can access beans from parent context
    • Parent context CANNOT see child context beans
    • @Service beans in child context are NOT shared with parent

  Spring Boot collapses this to a SINGLE context by default.

================================================================
KEY METHODS ON ApplicationContext
================================================================

  // Retrieve a bean
  MyService svc = ctx.getBean(MyService.class);
  MyService svc = ctx.getBean("myService", MyService.class);

  // All bean names
  String[] names = ctx.getBeanDefinitionNames();

  // Check bean existence
  boolean exists = ctx.containsBean("myService");

  // Publish an event
  ctx.publishEvent(new UserCreatedEvent(this, user));

  // Load a resource
  Resource r = ctx.getResource("classpath:data/init.sql");

  // Get environment
  Environment env = ctx.getEnvironment();
  String profile = env.getProperty("spring.profiles.active");

  // Refresh (reload context — rarely used in production)
  ((ConfigurableApplicationContext) ctx).refresh();

  // Close (calls destroy callbacks)
  ((ConfigurableApplicationContext) ctx).close();

================================================================
REFRESHABLE vs CLOSEABLE CONTEXT
================================================================

  ConfigurableApplicationContext:
    void refresh()  -- (re)initialize all beans
    void close()    -- destroy all beans and release resources
    void registerShutdownHook() -- calls close() on JVM shutdown

  // Always close the context when done (or use try-with-resources)
  try (ConfigurableApplicationContext ctx =
          new AnnotationConfigApplicationContext(AppConfig.class)) {
      ctx.getBean(MyApp.class).run();
  }
  // Beans are destroyed here

================================================================
ENVIRONMENT AND PROPERTY SOURCES
================================================================

  ApplicationContext holds an Environment with:
    - Profiles (spring.profiles.active)
    - Property sources (application.properties, system props, env vars)

  // Access environment programmatically
  @Component
  public class EnvironmentInspector {

      @Autowired
      private Environment env;

      public void inspect() {
          boolean isProd = env.acceptsProfiles(Profiles.of("prod"));
          String db = env.getProperty("spring.datasource.url");
          int port = env.getProperty("server.port", Integer.class, 8080);
      }
  }

COMPARISON TABLE
================================================================

  Feature                         | BeanFactory | ApplicationContext
  --------------------------------|-------------|-------------------
  Bean retrieval                  | ✓           | ✓
  Lazy initialization             | ✓ (default) | Configurable
  Eager singleton initialization  | ✗           | ✓ (default)
  @Autowired / @PostConstruct     | Manual BPP  | ✓ automatic
  AOP proxy creation              | ✗           | ✓
  Event publishing                | ✗           | ✓
  i18n (MessageSource)            | ✗           | ✓
  Environment / Profiles          | ✗           | ✓
  Resource loading (classpath:)   | ✗           | ✓
  @PropertySource support         | ✗           | ✓
  Spring Boot compatible          | Partial     | ✓ fully

================================================================
INTERVIEW QUESTIONS
================================================================

  Q: Why prefer ApplicationContext over BeanFactory?
  A: ApplicationContext provides AOP, events, i18n, annotation
     processing, environment, and resource loading — everything
     needed in real apps. BeanFactory is too bare for production.

  Q: When would you use BeanFactory directly?
  A: In very lightweight, constrained environments (e.g., IoT,
     plugin frameworks) where startup overhead must be minimal and
     you don't need advanced features.

  Q: Explain parent-child context hierarchy in Spring MVC.
  A: Root context holds service/repository beans (shared). The
     DispatcherServlet's child context holds web layer beans.
     Child can see parent beans; parent cannot see child beans.
     Spring Boot uses a single flat context.

  Q: What does ctx.refresh() do?
  A: It (re)initializes the entire bean factory — loads bean
     definitions, instantiates singletons, runs post-processors.
     Calling it a second time destroys existing beans and recreates.

  Q: What is ConfigurableApplicationContext?
  A: The extension of ApplicationContext that adds refresh(), close(),
     registerShutdownHook(), and setEnvironment() — lifecycle control.
