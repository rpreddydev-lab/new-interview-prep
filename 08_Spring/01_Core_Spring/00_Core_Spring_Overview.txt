WHAT IS THE CORE SPRING FRAMEWORK?
================================================================

  The "Core Spring" is the heart of the entire Spring ecosystem.
  It provides:

    1. IoC Container       -- manages object creation and wiring
    2. Dependency Injection -- supplies dependencies to objects
    3. Bean Lifecycle Mgmt -- controls how beans are created/destroyed
    4. AOP Foundation      -- proxy-based aspect support
    5. Resource Abstraction-- uniform access to classpath/file/URL

  Everything else in Spring (MVC, Data, Security) builds on top
  of the core container.

================================================================
CORE CONTAINER MODULES
================================================================

  Module              | Artifact              | Role
  --------------------|----------------------|------------------------------
  spring-core         | spring-core.jar       | Utilities, resource loading
  spring-beans        | spring-beans.jar      | BeanFactory, DI engine
  spring-context      | spring-context.jar    | ApplicationContext, events
  spring-context-support | ...support.jar     | Caching, scheduling helpers
  spring-expression   | spring-expression.jar | SpEL

  Dependency: spring-context → spring-aop → spring-beans → spring-core

================================================================
IoC (INVERSION OF CONTROL) PRINCIPLE
================================================================

  Traditional code:
    OrderService svc = new OrderService(new PaymentService());

  With IoC:
    // Framework creates and injects; you just declare the need
    @Service
    public class OrderService {
        private final PaymentService paymentService;

        @Autowired
        public OrderService(PaymentService paymentService) {
            this.paymentService = paymentService;
        }
    }

  Control is INVERTED: Instead of you calling new,
  the framework is responsible for object instantiation.

================================================================
THREE TYPES OF DEPENDENCY INJECTION
================================================================

  1. CONSTRUCTOR INJECTION (PREFERRED)
     ─────────────────────────────────
     @Service
     public class OrderService {
         private final PaymentService paymentService;

         public OrderService(PaymentService paymentService) {
             this.paymentService = paymentService;
         }
     }

     Advantages:
       ✓ Immutability (final fields)
       ✓ Mandatory dependencies explicit
       ✓ Easier unit testing (no Spring needed)
       ✓ Detects circular dependencies at startup

  2. SETTER INJECTION
     ─────────────────
     @Service
     public class NotificationService {
         private EmailClient emailClient;

         @Autowired
         public void setEmailClient(EmailClient emailClient) {
             this.emailClient = emailClient;
         }
     }

     Use for: optional or reconfigurable dependencies.

  3. FIELD INJECTION (DISCOURAGED)
     ──────────────────────────────
     @Service
     public class ReportService {
         @Autowired
         private DataSource dataSource;  // bad practice
     }

     Disadvantages:
       ✗ Cannot use final
       ✗ Hard to unit test without Spring context
       ✗ Hides dependencies (not visible in constructor)

================================================================
SPRING BEAN
================================================================

  A "bean" is any object managed by the Spring IoC container.

  Ways to define a bean:
    1. @Component / @Service / @Repository / @Controller
       (auto-detected via component scanning)

    2. @Bean method inside @Configuration class

    3. XML <bean> declaration (legacy)

  Example:
    @Configuration
    public class AppConfig {

        @Bean
        public DataSource dataSource() {
            HikariDataSource ds = new HikariDataSource();
            ds.setJdbcUrl("jdbc:postgresql://localhost/mydb");
            return ds;
        }

        @Bean
        public UserRepository userRepository(DataSource ds) {
            return new UserRepositoryImpl(ds);
        }
    }

================================================================
APPLICATION CONTEXT vs BEAN FACTORY
================================================================

  BeanFactory (basic):
    - Lazy-loaded beans
    - Core DI only
    - Interface: org.springframework.beans.factory.BeanFactory

  ApplicationContext (extended):
    - Eager bean instantiation (singletons)
    - AOP, events, i18n, resource loading, environment
    - Interface: org.springframework.context.ApplicationContext
    - Implementations: AnnotationConfigApplicationContext,
                       ClassPathXmlApplicationContext,
                       GenericWebApplicationContext

  Prefer ApplicationContext in all real applications.

================================================================
COMPONENT STEREOTYPES
================================================================

  Annotation        | Semantics
  ------------------|------------------------------------------
  @Component        | Generic Spring-managed component
  @Service          | Business logic layer (same as @Component)
  @Repository       | Data access layer; translates SQL exceptions
  @Controller       | Spring MVC web controller
  @RestController   | @Controller + @ResponseBody combined

  All four are specializations of @Component and are
  auto-detected by @ComponentScan.

================================================================
BEAN SCOPES SUMMARY
================================================================

  Scope        | Lifecycle
  -------------|-----------------------------------------------
  singleton    | One per ApplicationContext (default)
  prototype    | New instance every injection/getBean()
  request      | One per HTTP request (web only)
  session      | One per HTTP session (web only)
  application  | One per ServletContext (web only)
  websocket    | One per WebSocket session

================================================================
KEY INTERVIEW QUESTIONS — CORE SPRING
================================================================

  Q1: What is IoC and how does Spring implement it?
  A:  IoC means the framework controls object creation instead of
      your code. Spring implements it via the BeanFactory/
      ApplicationContext container that reads bean definitions,
      instantiates objects, and injects dependencies.

  Q2: Constructor vs. field injection — which is preferred?
  A:  Constructor injection. It enables immutable fields, makes
      dependencies explicit, facilitates unit testing without
      Spring, and catches circular dependencies early.

  Q3: What is the difference between @Component and @Bean?
  A:  @Component is a class-level annotation for auto-detection.
      @Bean is a method-level annotation inside @Configuration
      used when you need programmatic control over instantiation
      (e.g., third-party classes).

  Q4: What happens when two beans of the same type exist?
  A:  Spring throws NoUniqueBeanDefinitionException. Fix with
      @Primary (default candidate) or @Qualifier("beanName").

  Q5: Can Spring inject a prototype-scoped bean into a
      singleton? What's the problem?
  A:  Yes, but the prototype won't work as expected because the
      singleton holds one reference. Fix: use ObjectProvider<T>,
      @Lookup, or ApplicationContextAware.

================================================================
CORE SPRING QUICK-REFERENCE ANNOTATIONS
================================================================

  @SpringBootApplication  = @Configuration + @ComponentScan
                          + @EnableAutoConfiguration

  @Autowired              = Inject by type; add @Qualifier for name
  @Qualifier("name")      = Disambiguate multiple beans of same type
  @Primary                = Default bean when multiple exist
  @Value("${prop}")       = Inject property from application.properties
  @Lazy                   = Delay bean initialization until first use
  @DependsOn("otherBean") = Ensure another bean initializes first
  @Scope("prototype")     = Set bean scope
