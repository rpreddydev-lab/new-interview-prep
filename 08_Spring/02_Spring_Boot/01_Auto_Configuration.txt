================================================================
  SPRING BOOT AUTO-CONFIGURATION — IN DEPTH
================================================================

================================================================
WHAT IS AUTO-CONFIGURATION?
================================================================

  Auto-configuration automatically configures Spring beans based on:
    • Classpath contents (which JARs are present)
    • Existing beans in the context
    • Property values in application.properties

  Goal: Zero boilerplate — add a dependency and it "just works."

  Example: Add spring-boot-starter-data-jpa to pom.xml →
    Spring Boot automatically configures:
      - DataSource (from properties)
      - JPA EntityManagerFactory
      - Spring Data JPA repositories
      - @Transactional support

================================================================
HOW AUTO-CONFIGURATION WORKS — INTERNALS
================================================================

  Step-by-step:

  1. @SpringBootApplication includes @EnableAutoConfiguration
  2. @EnableAutoConfiguration imports AutoConfigurationImportSelector
  3. AutoConfigurationImportSelector reads:
       META-INF/spring/org.springframework.boot.autoconfigure
           .AutoConfiguration.imports    (Spring Boot 2.7+)
       META-INF/spring.factories         (older versions)
  4. Returns list of @AutoConfiguration class names
  5. Each class is evaluated — its @Conditional* annotations must match
  6. Matching classes' @Bean methods register beans into context

  Key class:
    org.springframework.boot.autoconfigure.AutoConfigurationImportSelector

================================================================
@AutoConfiguration — WRITING YOUR OWN
================================================================

  // spring-boot 2.7+
  @AutoConfiguration
  @ConditionalOnClass(SomeLibraryClient.class)
  @EnableConfigurationProperties(SomeLibraryProperties.class)
  public class SomeLibraryAutoConfiguration {

      @Bean
      @ConditionalOnMissingBean
      public SomeLibraryClient someLibraryClient(
              SomeLibraryProperties props) {
          return new SomeLibraryClient(props.getApiKey());
      }
  }

  // Register it (META-INF/spring/...AutoConfiguration.imports):
  com.example.SomeLibraryAutoConfiguration

================================================================
SPRING BOOT 2.6 vs 2.7 AUTO-CONFIG REGISTRATION
================================================================

  Before 2.7 (META-INF/spring.factories):
    org.springframework.boot.autoconfigure.EnableAutoConfiguration=\
      com.example.MyAutoConfiguration,\
      com.example.OtherAutoConfiguration

  Spring Boot 2.7+ (META-INF/spring/
      org.springframework.boot.autoconfigure.AutoConfiguration.imports):
    com.example.MyAutoConfiguration
    com.example.OtherAutoConfiguration

  Spring Boot 3.x ONLY supports the new file.

================================================================
ORDERING AUTO-CONFIGURATION
================================================================

  @AutoConfiguration(after = DataSourceAutoConfiguration.class)
  public class MyRepoAutoConfiguration { ... }

  @AutoConfiguration(before = SecurityAutoConfiguration.class)
  public class MySecurityConfig { ... }

  @AutoConfigureOrder(Ordered.LOWEST_PRECEDENCE)
  public class LastAutoConfiguration { ... }

  Using @AutoConfigureAfter / @AutoConfigureBefore (older style):
    @AutoConfigureAfter(JacksonAutoConfiguration.class)
    @AutoConfigureBefore(WebMvcAutoConfiguration.class)

================================================================
KEY BUILT-IN AUTO-CONFIGURATIONS
================================================================

  Auto-Config Class                      | Activates when
  ---------------------------------------|----------------------------
  DataSourceAutoConfiguration           | DataSource on classpath
  JpaRepositoriesAutoConfiguration      | JPA + Spring Data JPA
  SecurityAutoConfiguration             | Spring Security on classpath
  WebMvcAutoConfiguration               | Spring MVC on classpath
  JacksonAutoConfiguration              | Jackson on classpath
  TransactionAutoConfiguration          | @Transactional support
  CacheAutoConfiguration                | spring.cache.type set
  KafkaAutoConfiguration                | spring-kafka on classpath
  RedisAutoConfiguration                | spring-data-redis present
  ActuatorAutoConfiguration             | spring-boot-actuator present
  ErrorMvcAutoConfiguration             | default /error endpoint

================================================================
EXCLUDING AUTO-CONFIGURATIONS
================================================================

  // Annotation-based exclusion
  @SpringBootApplication(exclude = {
      DataSourceAutoConfiguration.class,
      SecurityAutoConfiguration.class
  })
  public class MyApp { ... }

  // Properties-based exclusion
  spring.autoconfigure.exclude=\
    org.springframework.boot.autoconfigure.security.SecurityAutoConfiguration

  // Multiple
  spring.autoconfigure.exclude[0]=...DataSourceAutoConfiguration
  spring.autoconfigure.exclude[1]=...SecurityAutoConfiguration

================================================================
DEBUGGING AUTO-CONFIGURATION
================================================================

  # Print auto-configuration report on startup
  debug=true

  Output shows three sections:
    1. POSITIVE MATCHES   -- auto-configs that were applied and why
    2. NEGATIVE MATCHES   -- auto-configs that were skipped and why
    3. EXCLUSIONS         -- explicitly excluded configs
    4. UNCONDITIONAL      -- always applied

  Example output:
    DataSourceAutoConfiguration matched:
      - @ConditionalOnClass found required classes
        'javax.sql.DataSource', 'org.springframework.jdbc.datasource.embedded.EmbeddedDatabaseType'
      - @ConditionalOnMissingBean (types: javax.sql.DataSource) did not find any beans

  Programmatic access:
    @Component
    public class AutoConfigReport implements ApplicationContextAware {
        public void printReport() {
            // Check ConditionEvaluationReport bean
        }
    }

  // Use /actuator/conditions endpoint (exposes same info via HTTP)

CUSTOM STARTER — FULL EXAMPLE
================================================================

  // 1. Create library: my-awesome-starter
  // Structure:
  //   my-awesome-starter/
  //     pom.xml (scope: provided for spring-boot-autoconfigure)
  //     src/main/java/
  //       com/example/
  //         MyAwesomeClient.java
  //         MyAwesomeProperties.java
  //         MyAwesomeAutoConfiguration.java
  //     src/main/resources/
  //       META-INF/spring/
  //         ...AutoConfiguration.imports

  @ConfigurationProperties(prefix = "my.awesome")
  public class MyAwesomeProperties {
      private String apiKey;
      private String baseUrl = "https://api.example.com";
      private int timeout = 3000;
      // getters + setters
  }

  @AutoConfiguration
  @ConditionalOnClass(MyAwesomeClient.class)
  @EnableConfigurationProperties(MyAwesomeProperties.class)
  public class MyAwesomeAutoConfiguration {

      @Bean
      @ConditionalOnMissingBean          // allow user override
      public MyAwesomeClient myAwesomeClient(MyAwesomeProperties props) {
          return MyAwesomeClient.builder()
              .apiKey(props.getApiKey())
              .baseUrl(props.getBaseUrl())
              .timeout(props.getTimeout())
              .build();
      }
  }

  // META-INF/spring/
  //   org.springframework.boot.autoconfigure.AutoConfiguration.imports
  com.example.MyAwesomeAutoConfiguration

  // 2. Users just add dependency:
  // <dependency>
  //   <groupId>com.example</groupId>
  //   <artifactId>my-awesome-starter</artifactId>
  // </dependency>
  //
  // And configure:
  // my.awesome.api-key=abc123

================================================================
INTERVIEW QUESTIONS — AUTO-CONFIGURATION
================================================================

  Q: How does Spring Boot auto-configuration work?
  A: @EnableAutoConfiguration triggers AutoConfigurationImportSelector
     which reads class names from META-INF/spring/...AutoConfiguration
     .imports. Each listed class uses @Conditional* annotations to
     decide whether to register its @Bean methods.

  Q: How do you disable a specific auto-configuration?
  A: Use exclude attribute of @SpringBootApplication or
     spring.autoconfigure.exclude property.

  Q: What is @ConditionalOnMissingBean and why is it important?
  A: It makes a bean conditional on no existing bean of that type.
     This lets users override auto-configured beans by simply
     declaring their own @Bean — auto-config backs off gracefully.

  Q: How do you debug which auto-configurations are applied?
  A: Set debug=true in application.properties to print the
     conditions evaluation report. Or use /actuator/conditions endpoint.

  Q: How do you create a custom Spring Boot starter?
  A: Create an @AutoConfiguration class with @ConditionalOnClass,
     @ConditionalOnMissingBean, and @EnableConfigurationProperties.
     Register it in META-INF/spring/...AutoConfiguration.imports.
     Package it as a JAR that users add as a dependency.
