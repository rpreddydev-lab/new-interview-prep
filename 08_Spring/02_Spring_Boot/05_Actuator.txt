  SPRING BOOT ACTUATOR — IN DEPTH
================================================================

================================================================
WHAT IS ACTUATOR?
================================================================

  Spring Boot Actuator provides production-ready features for
  monitoring and managing applications:
    • Health checks
    • Metrics (CPU, memory, HTTP requests, custom)
    • Application info
    • Thread dumps, heap dumps
    • Environment inspection
    • Log level management at runtime
    • Bean and condition reports

================================================================
DEPENDENCY
================================================================

  <dependency>
      <groupId>org.springframework.boot</groupId>
      <artifactId>spring-boot-starter-actuator</artifactId>
  </dependency>

  Exposes HTTP endpoints under /actuator by default.

================================================================
BUILT-IN ENDPOINTS
================================================================

  ID              | URL                     | Description
  ----------------|-------------------------|-------------------------------
  health          | /actuator/health        | App health status
  info            | /actuator/info          | App metadata info
  metrics         | /actuator/metrics       | Micrometer metrics
  env             | /actuator/env           | All property sources
  beans           | /actuator/beans         | All Spring beans
  mappings        | /actuator/mappings      | All @RequestMapping routes
  conditions      | /actuator/conditions    | Auto-config conditions report
  configprops     | /actuator/configprops   | All @ConfigurationProperties
  loggers         | /actuator/loggers       | Log levels (GET + POST)
  threaddump      | /actuator/threaddump    | JVM thread dump
  heapdump        | /actuator/heapdump      | JVM heap dump (binary)
  httptrace       | /actuator/httptrace     | Last 100 HTTP requests
  auditevents     | /actuator/auditevents   | Security audit events
  caches          | /actuator/caches        | Cache info
  scheduledtasks  | /actuator/scheduledtasks| Scheduled task info
  shutdown        | /actuator/shutdown      | Graceful shutdown (disabled by default!)

================================================================
EXPOSING ENDPOINTS — CONFIGURATION
================================================================

  # Expose all endpoints over HTTP
  management.endpoints.web.exposure.include=*

  # Expose specific endpoints
  management.endpoints.web.exposure.include=health,info,metrics,loggers

  # Exclude specific
  management.endpoints.web.exposure.exclude=heapdump,shutdown

  # JMX exposure (separate control)
  management.endpoints.jmx.exposure.include=*

  # Custom base path (default: /actuator)
  management.endpoints.web.base-path=/management

  # Custom server port (separate from app port — security!)
  management.server.port=8081
  management.server.address=127.0.0.1  # only localhost

HEALTH ENDPOINT — DETAILS
================================================================

  # Show full health details (by default: only "UP"/"DOWN")
  management.endpoint.health.show-details=always
  # Options: never (default) | when-authorized | always

  Response example:
  {
    "status": "UP",
    "components": {
      "db": {
        "status": "UP",
        "details": { "database": "PostgreSQL", "validationQuery": "SELECT 1" }
      },
      "diskSpace": {
        "status": "UP",
        "details": { "total": 500GB, "free": 200GB, "threshold": 10MB }
      },
      "redis": {
        "status": "UP",
        "details": { "version": "7.0.11" }
      }
    }
  }

  Built-in health indicators:
    DataSourceHealthIndicator, DiskSpaceHealthIndicator,
    RedisHealthIndicator, MongoHealthIndicator,
    KafkaHealthIndicator, RabbitHealthIndicator, etc.

================================================================
CUSTOM HEALTH INDICATOR
================================================================

  @Component
  public class ExternalApiHealthIndicator implements HealthIndicator {

      @Autowired
      private ExternalApiClient apiClient;

      @Override
      public Health health() {
          try {
              boolean ok = apiClient.ping();
              if (ok) {
                  return Health.up()
                      .withDetail("url", apiClient.getBaseUrl())
                      .withDetail("responseTime", "45ms")
                      .build();
              } else {
                  return Health.down()
                      .withDetail("reason", "ping returned false")
                      .build();
              }
          } catch (Exception e) {
              return Health.down(e)
                  .withDetail("error", e.getMessage())
                  .build();
          }
      }
  }

  // Health status values: UP, DOWN, OUT_OF_SERVICE, UNKNOWN, custom

LIVENESS AND READINESS PROBES (KUBERNETES)
================================================================

  management.endpoint.health.probes.enabled=true
  management.health.livenessState.enabled=true
  management.health.readinessState.enabled=true

  Endpoints:
    /actuator/health/liveness   → UP (app is alive, not deadlocked)
    /actuator/health/readiness  → UP (app is ready to serve traffic)

  Kubernetes pod config:
    livenessProbe:
      httpGet:
        path: /actuator/health/liveness
        port: 8080
    readinessProbe:
      httpGet:
        path: /actuator/health/readiness
        port: 8080

  Programmatic state change:
    @Autowired ApplicationContext ctx;
    AvailabilityChangeEvent.publish(ctx, LivenessState.BROKEN);
    AvailabilityChangeEvent.publish(ctx, ReadinessState.REFUSING_TRAFFIC);

INFO ENDPOINT

  management.info.env.enabled=true   # Spring Boot 2.6+

  # spring-boot-maven-plugin generates build-info.properties

  management.info.git.enabled=true

  Custom InfoContributor:
  @Component
  public class JvmInfoContributor implements InfoContributor {
      @Override
      public void contribute(Info.Builder builder) {
          builder.withDetail("jvm", Map.of(
              "vendor", System.getProperty("java.vendor"),
              "version", System.getProperty("java.version")
          ));
      }
  }

METRICS ENDPOINT — MICROMETER
================================================================

  /actuator/metrics                  -- list all metric names
  /actuator/metrics/jvm.memory.used  -- specific metric
  /actuator/metrics/http.server.requests -- HTTP request counts

  With tags (drill-down):
  /actuator/metrics/http.server.requests?tag=uri:/api/users
  /actuator/metrics/http.server.requests?tag=status:200

  Custom metric:
  @Service
  public class OrderService {

      private final Counter orderCounter;
      private final Timer orderTimer;

      public OrderService(MeterRegistry registry) {
          this.orderCounter = Counter.builder("orders.created")
              .description("Number of orders created")
              .tag("currency", "USD")
              .register(registry);

          this.orderTimer = Timer.builder("orders.processing.time")
              .description("Order processing duration")
              .register(registry);
      }

      public Order createOrder(OrderRequest req) {
          return orderTimer.record(() -> {
              Order order = processOrder(req);
              orderCounter.increment();
              return order;
          });
      }
  }

================================================================
LOGGERS ENDPOINT — RUNTIME LOG LEVEL CHANGE
================================================================

  GET  /actuator/loggers             -- all logger levels
  GET  /actuator/loggers/com.example -- specific logger
  POST /actuator/loggers/com.example -- change level

  # Change log level via curl
  curl -X POST \
    -H "Content-Type: application/json" \
    -d '{"configuredLevel":"DEBUG"}' \
    http://localhost:8080/actuator/loggers/com.example

  # Reset to default
  curl -X POST \
    -H "Content-Type: application/json" \
    -d '{"configuredLevel":null}' \
    http://localhost:8080/actuator/loggers/com.example

SECURING ACTUATOR ENDPOINTS
================================================================

  @Configuration
  @EnableWebSecurity
  public class ActuatorSecurityConfig {

      @Bean
      public SecurityFilterChain actuatorSecurity(HttpSecurity http)
              throws Exception {
          http
              .securityMatcher("/actuator/**")
              .authorizeHttpRequests(auth -> auth
                  .requestMatchers("/actuator/health",
                                   "/actuator/health/**").permitAll()
                  .requestMatchers("/actuator/info").permitAll()
                  .anyRequest().hasRole("ACTUATOR_ADMIN")
              )
              .httpBasic(Customizer.withDefaults());
          return http.build();
      }
  }

CUSTOM ACTUATOR ENDPOINT
================================================================

  @Component
  @Endpoint(id = "features")
  public class FeaturesEndpoint {

      private final Map<String, Boolean> features = new HashMap<>();

      @ReadOperation                     // HTTP GET
      public Map<String, Boolean> features() {
          return features;
      }

      @WriteOperation                    // HTTP POST
      public void configureFeature(@Selector String name, boolean enabled) {
          features.put(name, enabled);
      }

      @DeleteOperation                   // HTTP DELETE
      public void deleteFeature(@Selector String name) {
          features.remove(name);
      }
  }

  // Access: GET /actuator/features
  //         POST /actuator/features/darkMode  body: {"enabled": true}

INTERVIEW QUESTIONS — ACTUATOR
================================================================

  Q: What is Spring Boot Actuator?
  A: A library providing production-ready HTTP endpoints for
     monitoring application health, metrics, configuration,
     beans, log levels, and more.

  Q: How do you expose all Actuator endpoints?
  A: management.endpoints.web.exposure.include=* in properties.
     By default only /health and /info are exposed.

  Q: What is the difference between liveness and readiness probes?
  A: Liveness: is the app alive (not deadlocked/corrupted)? If false,
     Kubernetes restarts the pod. Readiness: is the app ready to
     receive traffic? If false, Kubernetes removes it from load balancer.

  Q: How do you secure Actuator endpoints?
  A: Use Spring Security with a SecurityFilterChain matching /actuator/**,
     or run Actuator on a different port accessible only internally.

  Q: How do you add a custom health indicator?
  A: Implement HealthIndicator interface and annotate with @Component.
     Spring Boot auto-discovers it.

  Q: Can you change log levels at runtime?
  A: Yes — POST to /actuator/loggers/{logger} with
     {"configuredLevel":"DEBUG"} changes the level immediately
     without restarting.
