  1. WHAT IS SPRING CLOUD?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Spring Cloud provides tools for building distributed systems and
microservices. It solves the infrastructure problems that arise when
you decompose a monolith into many services:

  - How does Service A find Service B? → Service Discovery (Eureka)
  - How do clients reach internal services? → API Gateway
  - How do you manage config across 50 services? → Config Server
  - What if Service B is down? → Circuit Breaker (Resilience4j)
  - How do you trace a request across 10 services? → Distributed Tracing
  - How do you balance load between service instances? → Load Balancing

Spring Cloud is NOT a single library — it's an umbrella project with
many sub-projects, each addressing a specific distributed systems concern.

Problem                  | Spring Cloud Solution
-------------------------|--------------------------------------------
Service discovery        | Spring Cloud Netflix Eureka
                         | Spring Cloud Consul / Zookeeper
API Gateway              | Spring Cloud Gateway (WebFlux-based)
                         | Spring Cloud Gateway MVC (Servlet-based, newer)
Config management        | Spring Cloud Config Server (Git-backed)
                         | Spring Cloud Vault (secrets)
Circuit breaker          | Spring Cloud Circuit Breaker + Resilience4j
                         | (Hystrix — deprecated)
Load balancing           | Spring Cloud LoadBalancer (replaced Ribbon)
Declarative HTTP client  | Spring Cloud OpenFeign (or Spring 6 HttpInterface)
Distributed tracing      | Micrometer Tracing + Zipkin/Jaeger/OTLP
                         | (Spring Cloud Sleuth — deprecated in 2023)
Messaging                | Spring Cloud Stream (Kafka/RabbitMQ binder)
Service mesh             | Spring Cloud Kubernetes
Cloud functions          | Spring Cloud Function

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Spring Cloud uses a BOM (Bill of Materials) with release train names
(not semver). Import the BOM and get compatible versions of all modules.

  Spring Boot 3.x → Spring Cloud 2023.x (Leyton)
  Spring Boot 2.7  → Spring Cloud 2021.x (Jubilee)

<!-- pom.xml -->
<dependencyManagement>
    <dependencies>
        <dependency>
            <groupId>org.springframework.cloud</groupId>
            <artifactId>spring-cloud-dependencies</artifactId>
            <version>2023.0.3</version>
            <type>pom</type>
            <scope>import</scope>
        </dependency>
    </dependencies>
</dependencyManagement>

Then add individual starters without versions:
  spring-cloud-starter-netflix-eureka-client
  spring-cloud-starter-gateway
  spring-cloud-starter-openfeign
  spring-cloud-starter-circuitbreaker-resilience4j
  spring-cloud-config-server
  spring-cloud-config-client

  4. MICROSERVICES PATTERNS ADDRESSED
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Pattern               | Description
----------------------|-----------------------------------------------
Service Registry      | Services register themselves; clients discover
                      | by name (not IP/port)
Gateway               | Single entry point for all clients; handles
                      | routing, auth, rate limiting, SSL termination
Externalized Config   | Config stored outside the service binary;
                      | environment-specific values from central server
Circuit Breaker       | When a dependency fails, open the circuit to
                      | prevent cascading failures
Bulkhead              | Isolate failures — give each dependency its own
                      | thread pool / semaphore
Retry                 | Automatically retry transient failures with backoff
Time Limiter          | Fail fast if a call exceeds a timeout
Sidecar               | Attach infra concerns (tracing, mesh) as a
                      | separate container alongside the service

Q: What problems does Spring Cloud solve?
A: Spring Cloud solves distributed systems concerns for microservices:
   service discovery (how services find each other), centralized config,
   API routing and filtering, fault tolerance (circuit breakers), load
   balancing, and distributed tracing.

Q: What replaced Hystrix, Ribbon, and Zuul?
A: Hystrix → Resilience4j (circuit breaker)
   Ribbon → Spring Cloud LoadBalancer (client-side LB)
   Zuul → Spring Cloud Gateway (reactive, WebFlux-based)

Q: What replaced Spring Cloud Sleuth?
A: In Spring Boot 3.x, Sleuth was replaced by Micrometer Tracing
   (which is part of Micrometer Observation API). Same concepts
   (trace ID, span ID, MDC propagation) but integrated into
   Micrometer instead of being a standalone library.

Q: How do you version Spring Cloud with Spring Boot?
A: Use the Spring Cloud BOM (spring-cloud-dependencies) with the
   correct release train for your Spring Boot version. Import the BOM
   in dependencyManagement to get compatible versions of all Spring
   Cloud modules automatically.
