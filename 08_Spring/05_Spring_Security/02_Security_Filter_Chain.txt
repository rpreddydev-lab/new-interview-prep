  1. WHAT IS THE SECURITY FILTER CHAIN?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Spring Security is implemented as a chain of Servlet Filters.
Every HTTP request passes through this chain before reaching
the DispatcherServlet and your controllers.

The chain is managed by FilterChainProxy, which is itself a
standard servlet filter registered as "springSecurityFilterChain".

DelegatingFilterProxy  (bridges Servlet container to Spring context)
    │
FilterChainProxy       (Spring Security's entry point)
    │
SecurityFilterChain    (your configured filter list)
    │  (ordered filters applied in sequence)
    ▼
DispatcherServlet → Controllers

  2. DEFAULT FILTER ORDER (Spring Security 6)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Spring Security defines SecurityProperties.DEFAULT_FILTER_ORDER = -100
(higher priority than most other filters).

Key built-in filters in order:

  1.  DisableEncodeUrlFilter
  2.  WebAsyncManagerIntegrationFilter
  3.  SecurityContextHolderFilter          ← loads SecurityContext
  4.  HeaderWriterFilter                   ← adds security headers
  5.  CorsFilter                           ← CORS preflight handling
  6.  CsrfFilter                           ← validates CSRF token
  7.  LogoutFilter                         ← handles logout URL
  8.  UsernamePasswordAuthenticationFilter ← form login
  9.  DefaultLoginPageGeneratingFilter     ← auto-generates login page
  10. DefaultLogoutPageGeneratingFilter
  11. BasicAuthenticationFilter            ← HTTP Basic auth
  12. RequestCacheAwareFilter
  13. SecurityContextHolderAwareRequestFilter
  14. AnonymousAuthenticationFilter        ← creates anonymous auth
  15. SessionManagementFilter
  16. ExceptionTranslationFilter           ← converts exceptions to HTTP
  17. AuthorizationFilter                  ← performs access control

  Custom JWT filter:
  → Typically added BEFORE UsernamePasswordAuthenticationFilter

  3. KEY FILTERS EXPLAINED
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

SecurityContextHolderFilter:
  - Loads SecurityContext from the configured SecurityContextRepository
  - (Session-based: HttpSessionSecurityContextRepository)
  - (Stateless: NullSecurityContextRepository — nothing stored)
  - Sets it on SecurityContextHolder
  - After filter chain, saves context back (or clears for stateless)

CsrfFilter:
  - Reads CSRF token from session/cookie
  - Validates it against token in request header/parameter
  - Rejects (403) if token missing or invalid for state-changing methods
    (POST, PUT, DELETE, PATCH)

ExceptionTranslationFilter:
  - Wraps the AuthorizationFilter and downstream
  - Catches AuthenticationException → sends to AuthenticationEntryPoint (401)
  - Catches AccessDeniedException   → sends to AccessDeniedHandler (403)

AnonymousAuthenticationFilter:
  - If no Authentication is set by previous filters,
    creates an AnonymousAuthenticationToken
  - Allows hasRole('ANONYMOUS') checks in rules

  4. ADDING A CUSTOM FILTER
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

@Component
public class JwtAuthFilter extends OncePerRequestFilter {

    private final JwtService jwtService;
    private final UserDetailsService userDetailsService;

    @Override
    protected void doFilterInternal(HttpServletRequest request,
                                    HttpServletResponse response,
                                    FilterChain chain)
            throws ServletException, IOException {

        String authHeader = request.getHeader("Authorization");

        if (authHeader == null || !authHeader.startsWith("Bearer ")) {
            chain.doFilter(request, response);  // pass to next filter
            return;
        }

        String jwt = authHeader.substring(7);
        String username = jwtService.extractUsername(jwt);

        if (username != null &&
                SecurityContextHolder.getContext().getAuthentication() == null) {

            UserDetails userDetails = userDetailsService.loadUserByUsername(username);

            if (jwtService.isTokenValid(jwt, userDetails)) {
                UsernamePasswordAuthenticationToken authToken =
                    new UsernamePasswordAuthenticationToken(
                        userDetails, null, userDetails.getAuthorities());

                authToken.setDetails(
                    new WebAuthenticationDetailsSource().buildDetails(request));

                SecurityContextHolder.getContext().setAuthentication(authToken);
            }
        }

        chain.doFilter(request, response);
    }
}

// Register in SecurityConfig:
http.addFilterBefore(jwtAuthFilter,
    UsernamePasswordAuthenticationFilter.class);

  5. MULTIPLE SECURITY FILTER CHAINS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Define multiple SecurityFilterChain beans, ordered by @Order:

@Configuration
public class SecurityConfig {

    // API security (JWT, stateless) — higher priority
    @Bean
    @Order(1)
    public SecurityFilterChain apiFilterChain(HttpSecurity http) throws Exception {
        http
            .securityMatcher("/api/**")           // apply only to /api/**
            .csrf(csrf -> csrf.disable())
            .sessionManagement(s -> s.sessionCreationPolicy(STATELESS))
            .authorizeHttpRequests(a -> a
                .requestMatchers("/api/auth/**").permitAll()
                .anyRequest().authenticated())
            .addFilterBefore(jwtAuthFilter,
                UsernamePasswordAuthenticationFilter.class);
        return http.build();
    }

    // Actuator security — lower priority
    @Bean
    @Order(2)
    public SecurityFilterChain actuatorFilterChain(HttpSecurity http) throws Exception {
        http
            .securityMatcher("/actuator/**")
            .authorizeHttpRequests(a -> a
                .requestMatchers("/actuator/health").permitAll()
                .anyRequest().hasRole("ACTUATOR_ADMIN"))
            .httpBasic(Customizer.withDefaults());
        return http.build();
    }
}

  6. SECURITY HEADERS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Spring Security adds these headers by default:
  X-Content-Type-Options: nosniff         (prevent MIME-type sniffing)
  X-Frame-Options: DENY                   (prevent clickjacking)
  X-XSS-Protection: 0                    (modern browsers ignore, use CSP)
  Cache-Control: no-cache, no-store       (prevent caching of secure pages)
  Strict-Transport-Security               (HTTPS only — added only for HTTPS)

Custom headers:
  http.headers(headers -> headers
      .frameOptions(fo -> fo.sameOrigin())      // allow iframes from same origin
      .contentSecurityPolicy(csp -> csp
          .policyDirectives("default-src 'self'; script-src 'self'"))
      .httpStrictTransportSecurity(hsts -> hsts
          .includeSubDomains(true)
          .maxAgeInSeconds(31536000))
  );

Q: What is DelegatingFilterProxy?
A: A standard Servlet filter that delegates processing to a Spring-managed
   bean (FilterChainProxy). It bridges the servlet container lifecycle
   and the Spring application context lifecycle, allowing Spring Security
   filters to be Spring beans.

Q: What is FilterChainProxy?
A: The central Spring Security filter that manages one or more
   SecurityFilterChain instances. For each request, it selects the first
   matching SecurityFilterChain and delegates the request through its
   filter list.

Q: What is ExceptionTranslationFilter?
A: It wraps the AuthorizationFilter and converts Spring Security exceptions
   to HTTP responses: AuthenticationException → 401 (via AuthenticationEntryPoint),
   AccessDeniedException → 403 (via AccessDeniedHandler). Without it, exceptions
   would propagate as 500 Internal Server Error.

Q: What is OncePerRequestFilter and why use it?
A: A base class that guarantees a filter executes exactly once per
   request, even in async or forwarded request scenarios. All custom
   security filters should extend OncePerRequestFilter to prevent
   duplicate execution.

Q: How do you add a custom filter in Spring Security?
A: Use addFilterBefore, addFilterAfter, or addFilterAt in the
   HttpSecurity DSL. addFilterBefore(myFilter, FilterClass.class)
   runs myFilter before the specified filter. For JWT, add before
   UsernamePasswordAuthenticationFilter.

Q: What does AnonymousAuthenticationFilter do?
A: If no Authentication object exists in the SecurityContext when
   a request reaches this filter, it creates an anonymous
   Authentication token (AnonymousAuthenticationToken with
   ROLE_ANONYMOUS). This allows rules like .anyRequest().authenticated()
   to reject anonymous users consistently.
