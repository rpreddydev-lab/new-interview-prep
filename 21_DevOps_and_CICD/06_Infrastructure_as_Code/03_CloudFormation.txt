1. CLOUDFORMATION OVERVIEW
================================================================================

What is CloudFormation?
  AWS-native Infrastructure as Code service.
  Declare AWS resources in JSON or YAML templates.
  CloudFormation manages the create/update/delete lifecycle.
  
  Key concepts:
  Template:   YAML/JSON file describing desired resources
  Stack:      A deployed instance of a template (group of related resources)
  Change Set: Preview of changes before applying (like terraform plan)
  Drift:      Detect when real resources diverge from template definition

Advantages over Terraform for AWS:
  - Native AWS service: no version mismatch between CF and new AWS features
  - Free to use (pay only for resources created)
  - Deep IAM integration (CloudFormation service role)
  - Stack rollback: automatic rollback on failure
  - Stack policies: prevent accidental updates to critical resources

Disadvantages vs Terraform:
  - AWS-only (no multi-cloud)
  - Verbose JSON/YAML (more complex than HCL)
  - Slower change sets vs terraform plan
  - No equivalent to terraform import (limited import)

2. TEMPLATE STRUCTURE
================================================================================

Full template skeleton:

  AWSTemplateFormatVersion: '2010-09-09'
  Description: My application stack
  
  Metadata:
    # Additional info (not used by CloudFormation, for documentation)
    Author: DevOps Team
  
  Parameters:
    # User-supplied values at stack creation/update
    Environment:
      Type: String
      AllowedValues: [dev, staging, production]
      Default: dev
    InstanceType:
      Type: String
      Default: t3.micro
  
  Mappings:
    # Static lookup tables
    RegionAMI:
      us-east-1:
        AMI: ami-0c02fb55956c7d316
      us-west-2:
        AMI: ami-038a0ccaaedae6406
  
  Conditions:
    # Boolean conditions based on parameters
    IsProduction: !Equals [!Ref Environment, production]
  
  Resources:
    # REQUIRED — the actual AWS resources
    MyBucket:
      Type: AWS::S3::Bucket
      Properties:
        BucketName: !Sub "myapp-${Environment}-${AWS::AccountId}"
        VersioningConfiguration:
          Status: !If [IsProduction, Enabled, Suspended]
  
  Outputs:
    # Values to export for cross-stack reference
    BucketName:
      Value: !Ref MyBucket
      Export:
        Name: !Sub "${AWS::StackName}-BucketName"

3. CORE RESOURCE TYPES
================================================================================

EC2 Instance:
  MyEC2:
    Type: AWS::EC2::Instance
    Properties:
      ImageId: !FindInMap [RegionAMI, !Ref AWS::Region, AMI]
      InstanceType: !Ref InstanceType
      SubnetId: !Ref PrivateSubnet
      SecurityGroupIds:
        - !Ref AppSecurityGroup
      IamInstanceProfile: !Ref InstanceProfile
      Tags:
        - Key: Name
          Value: !Sub "${Environment}-app-server"

RDS Database:
  MyDatabase:
    Type: AWS::RDS::DBInstance
    DeletionPolicy: Retain        # Don't delete DB on stack delete
    UpdateReplacePolicy: Retain
    Properties:
      DBInstanceClass: db.t3.micro
      Engine: postgres
      EngineVersion: '15.3'
      MasterUsername: !Sub "{{resolve:secretsmanager:${DBSecret}:SecretString:username}}"
      MasterUserPassword: !Sub "{{resolve:secretsmanager:${DBSecret}:SecretString:password}}"
      StorageEncrypted: true
      MultiAZ: !If [IsProduction, true, false]
      DBSubnetGroupName: !Ref DBSubnetGroup

Security Group:
  AppSecurityGroup:
    Type: AWS::EC2::SecurityGroup
    Properties:
      GroupDescription: App server security group
      VpcId: !Ref VPC
      SecurityGroupIngress:
        - IpProtocol: tcp
          FromPort: 8080
          ToPort: 8080
          SourceSecurityGroupId: !Ref ALBSecurityGroup

4. INTRINSIC FUNCTIONS
================================================================================

Most commonly used:

  !Ref resourceName          Reference a resource (returns logical ID or physical ID)
                             For parameters: returns parameter value
  
  !GetAtt resource.attr      Get attribute of a resource
                             !GetAtt MyALB.DNSName
  
  !Sub "string ${var}"       String substitution
                             !Sub "https://${MyDomain}/api"
  
  !Join [delim, [list]]      Join list with delimiter
                             !Join [",", [!Ref Subnet1, !Ref Subnet2]]
  
  !Select [index, list]      Select item from list
                             !Select [0, !GetAZs !Ref AWS::Region]
  
  !If [cond, true, false]    Conditional value
                             !If [IsProduction, m5.xlarge, t3.micro]
  
  !Equals [a, b]             Comparison (for conditions)
  !And, !Or, !Not            Logical operators (for conditions)
  
  !FindInMap [map, key1, key2]  Lookup in Mappings
  
  !ImportValue name           Import Output exported from another stack

Pseudo Parameters (no need to declare):
  AWS::AccountId      Current account ID
  AWS::Region         Current region (us-east-1)
  AWS::StackName      Current stack name
  AWS::NoValue        Removes a property when used with !If

5. STACK MANAGEMENT
================================================================================

CLI commands:

  # Create stack:
  aws cloudformation create-stack \
    --stack-name myapp-production \
    --template-body file://template.yaml \
    --parameters ParameterKey=Environment,ParameterValue=production \
    --capabilities CAPABILITY_IAM \
    --role-arn arn:aws:iam::123456789:role/CloudFormationRole
  
  # Wait for completion:
  aws cloudformation wait stack-create-complete \
    --stack-name myapp-production
  
  # Update stack:
  aws cloudformation update-stack \
    --stack-name myapp-production \
    --template-body file://template.yaml \
    --parameters ParameterKey=Environment,UsePreviousValue=true
  
  # Delete stack:
  aws cloudformation delete-stack --stack-name myapp-production
  
  # Describe stack events (debugging failures):
  aws cloudformation describe-stack-events \
    --stack-name myapp-production \
    --query 'StackEvents[?ResourceStatus==`CREATE_FAILED`]'

Stack Policies (Prevent accidental updates):
  {
    "Statement": [{
      "Effect": "Deny",
      "Action": "Update:Replace",
      "Principal": "*",
      "Resource": "LogicalResourceId/ProductionDatabase"
    }]
  }

6. CHANGE SETS
================================================================================

Change Set = CloudFormation's equivalent of terraform plan.
Preview changes before applying them.

  # Create change set:
  aws cloudformation create-change-set \
    --stack-name myapp-production \
    --change-set-name update-instance-type \
    --template-body file://updated-template.yaml \
    --parameters ParameterKey=InstanceType,ParameterValue=m5.large
  
  # Review changes:
  aws cloudformation describe-change-set \
    --stack-name myapp-production \
    --change-set-name update-instance-type
  
  # Apply if approved:
  aws cloudformation execute-change-set \
    --stack-name myapp-production \
    --change-set-name update-instance-type
  
  # Discard:
  aws cloudformation delete-change-set \
    --stack-name myapp-production \
    --change-set-name update-instance-type

Change types in change set output:
  Add:     New resource being created
  Modify:  Existing resource being updated
  Remove:  Resource being deleted (⚠️ check carefully)
  
  Replacement: True — means resource will be DELETED and RECREATED (data loss risk!)
  Replacement: False — in-place update, no disruption

7. NESTED STACKS AND STACKSETS
================================================================================

Nested Stacks:
  Break large templates into manageable modules.
  Parent stack references child stacks via AWS::CloudFormation::Stack.
  
  # Parent template:
  Resources:
    VPCStack:
      Type: AWS::CloudFormation::Stack
      Properties:
        TemplateURL: https://s3.amazonaws.com/mybucket/vpc-template.yaml
        Parameters:
          Environment: !Ref Environment
    
    AppStack:
      Type: AWS::CloudFormation::Stack
      DependsOn: VPCStack
      Properties:
        TemplateURL: https://s3.amazonaws.com/mybucket/app-template.yaml
        Parameters:
          VpcId: !GetAtt VPCStack.Outputs.VpcId
          SubnetIds: !GetAtt VPCStack.Outputs.PrivateSubnetIds

StackSets (Multi-account, Multi-region):
  Deploy same template to multiple AWS accounts and regions.
  Used for: organization-wide security baselines, compliance controls.
  
  # Deploy to all accounts in an OU:
  aws cloudformation create-stack-set \
    --stack-set-name org-security-baseline \
    --template-body file://security-baseline.yaml \
    --permission-model SERVICE_MANAGED \
    --auto-deployment Enabled=true,RetainStacksOnAccountRemoval=false
  
  aws cloudformation create-stack-instances \
    --stack-set-name org-security-baseline \
    --deployment-targets OrganizationalUnitIds=ou-1234-abcdefgh \
    --regions us-east-1 us-west-2 eu-west-1

8. CLOUDFORMATION VS TERRAFORM
================================================================================

Aspect                CloudFormation         Terraform
─────────────────────────────────────────────────────────────
Cloud support         AWS only               Multi-cloud
Language              YAML/JSON              HCL (readable)
State management      AWS managed            You manage (S3 + DynamoDB)
Plan/preview          Change Sets            terraform plan
Module reuse          Nested stacks          Modules (better)
Import existing       Limited (CFN import)   terraform import (full)
Drift detection       Yes (native)           terraform plan -refresh-only
Auto-rollback         Yes (on failure)       No (manual intervention)
Cost                  Free                   Open source (free)
New AWS features      Immediate support      Slight lag (provider update)
Testing               cfn-lint, TaskCat      Terratest, checkov
CI/CD integration     CloudFormation action  Any (API-based)

When to choose CloudFormation:
- AWS-only organization
- Need automatic rollback on stack failures
- Multi-account StackSets deployment
- Organization mandates AWS-native tooling

When to choose Terraform:
- Multi-cloud or hybrid (AWS + GCP, AWS + Azure)
- Team prefers HCL over YAML verbosity
- Need advanced module patterns
- More mature testing ecosystem

9. COMMON INTERVIEW QUESTIONS & ANSWERS
================================================================================

Q1: What is a CloudFormation Stack Rollback and when does it happen?
A: Rollback occurs when a stack operation (create/update) fails.
   
   On CREATE failure:
   By default: stack rolls back to empty (all created resources deleted).
   Option --on-failure DO_NOTHING: keep resources for debugging.
   Option --on-failure ROLLBACK: default behavior (delete everything)
   Option --on-failure DELETE: same as ROLLBACK
   
   On UPDATE failure:
   Stack rolls back to previous stable state.
   Previously-existing resources remain intact.
   New resources added during failed update are deleted.
   
   Rollback failure (rare but serious):
   If rollback also fails → stack goes into UPDATE_ROLLBACK_FAILED state.
   Resolution: aws cloudformation continue-update-rollback
   Sometimes requires manually deleting failed resources in AWS console first.

Q2: How do you handle secrets in CloudFormation templates?
A: NEVER hardcode secrets in template. Three approaches:
   
   1. AWS Secrets Manager dynamic reference (recommended):
      Properties:
        MasterPassword: !Sub "{{resolve:secretsmanager:prod/db-password:SecretString:password}}"
      CloudFormation fetches the secret at deploy time. Secret never in template.
   
   2. SSM Parameter Store:
      Properties:
        DBPassword: !Sub "{{resolve:ssm-secure:/prod/db/password}}"
      ssm-secure: uses KMS-encrypted SecureString parameters.
   
   3. Parameters with NoEcho:
      Parameters:
        DBPassword:
          Type: String
          NoEcho: true    # Masked in console and API responses
      (But value is in deployment history — less secure than option 1)

10. QUICK REFERENCE CHEAT SHEET
================================================================================

INTRINSIC FUNCTIONS:
  !Ref             Resource logical ID or parameter value
  !GetAtt          Resource attribute (MyALB.DNSName)
  !Sub             String substitution ("${Var}-suffix")
  !If              Conditional (!If [Cond, TrueVal, FalseVal])
  !FindInMap       Lookup in Mappings section
  !ImportValue     Cross-stack output reference

PSEUDO PARAMETERS:
  AWS::AccountId / AWS::Region / AWS::StackName

KEY RESOURCE TYPES:
  AWS::EC2::Instance / VPC / Subnet / SecurityGroup
  AWS::S3::Bucket
  AWS::RDS::DBInstance
  AWS::ECS::Service / TaskDefinition
  AWS::CloudFormation::Stack (nested stacks)

DELETION POLICIES:
  Delete    (default) — destroy resource on stack delete
  Retain    — keep resource after stack delete
  Snapshot  — take snapshot before deleting (RDS, EBS)

STACK STATES:
  CREATE_COMPLETE / UPDATE_COMPLETE / DELETE_COMPLETE
  CREATE_FAILED / UPDATE_ROLLBACK_COMPLETE / UPDATE_ROLLBACK_FAILED
