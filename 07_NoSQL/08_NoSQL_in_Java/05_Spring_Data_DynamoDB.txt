INTERVIEW Q&A
================================================================

  Q: How do you model one-to-many relationships in DynamoDB (single table design)?
  A: Use composite PK/SK overloading. For users and their orders in one table:
     PK=USER#<userId>, SK=USER#<userId>   --> user record
     PK=USER#<userId>, SK=ORDER#<orderId> --> order record
     Query with PK=USER#<userId> returns both user and all orders in one request.
     To get just orders, add SK begins_with("ORDER#"). This eliminates the need
     for separate tables and JOINs.

  Q: What is the difference between a GSI and an LSI in DynamoDB?
  A: LSI (Local Secondary Index): same partition key, different sort key.
     Shares the same partition as the base table. Must be defined at table creation.
     Strong or eventually consistent reads.
     GSI (Global Secondary Index): different partition key and optional sort key.
     Data is projected and stored separately. Supports eventually consistent reads.
     Can be created after table creation. Use GSI for alternate query patterns.
