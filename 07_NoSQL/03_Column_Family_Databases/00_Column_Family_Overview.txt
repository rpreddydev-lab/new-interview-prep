================================================================
  COLUMN-FAMILY DATABASES OVERVIEW
================================================================

  Column-family databases store data in rows with dynamic, named columns
  grouped into column families.
  Each row can have a different set of columns.
  Designed for massive write throughput and horizontal scale.

================================================================
DATA MODEL
================================================================

  Table (Keyspace) --> Row Key --> Column Family --> Column:Value

  Row Key:  unique identifier for a row (partition key)
  Column Family:  group of related columns (defined at schema level)
  Column:   name:value:timestamp triple (dynamic per row)

  Unlike RDBMS where all rows have the same columns,
  each row can have entirely different columns.

  Example:
  Row Key: "user:1001"
  Column Family "profile":
    name: "Alice"
    email: "alice@example.com"
    city: "Austin"
  Column Family "activity":
    login:2024-01-01: "web"
    login:2024-01-15: "mobile"
    purchase:ORD001:  "99.99"

================================================================
WIDE ROWS (WIDE COLUMN MODEL)
================================================================

  A "wide row" has many columns (thousands to millions).
  Each column name encodes data (e.g., timestamp, event ID).
  This is the "wide column" or "column-family" design pattern.

  Effective for time-series and event storage:
  Row: "sensor:TEMP-01"
  Columns: "2024-01-15T10:00:01": "72.3"
            "2024-01-15T10:00:02": "72.5"
            "2024-01-15T10:00:03": "72.1"

================================================================
COLUMN FAMILY vs RELATIONAL
================================================================

  Feature               Column-Family           RDBMS
  --------------------  ----------------------  ----------------------
  Schema                Flexible per row        Fixed for all rows
  Storage               Column-oriented blocks  Row-oriented pages
  JOINs                 Not supported           First-class feature
  Scale                 Horizontal (sharding)   Vertical + limited shard
  Write throughput      Extremely high          Moderate
  Query pattern         Primary key + range     Any column (with indexes)
  Examples              Cassandra, HBase        PostgreSQL, MySQL

================================================================
POPULAR COLUMN-FAMILY DATABASES
================================================================

  Apache Cassandra
    Masterless ring topology. Tunable consistency.
    Used by Netflix, Apple, Discord.
    CQL (Cassandra Query Language) -- SQL-like syntax.
    Best for high write throughput, time-series, logs, messaging.

  Apache HBase
    Runs on HDFS (Hadoop Distributed File System).
    Strong consistency (CP).
    Random read/write access to big data.
    Used in Hadoop/Spark pipelines, big data analytics.

  Google Bigtable
    Managed by Google Cloud. Origin of the column-family concept.
    HBase is the open-source implementation of Bigtable.

  Amazon Keyspaces
    Managed Cassandra-compatible service on AWS.

================================================================
WHEN TO USE COLUMN-FAMILY DATABASES
================================================================

  Use when:
  - Extremely high write throughput (millions of writes/sec)
  - Time-series data (IoT sensors, metrics, logs)
  - Wide rows with many dynamic columns
  - Need for horizontal linear scale
  - Append-heavy workloads

  Avoid when:
  - Complex ad-hoc queries with multiple filters (use MongoDB)
  - ACID transactions across entities (use PostgreSQL)
  - Flexible document queries (use MongoDB)

================================================================
INTERVIEW Q&A
================================================================

  Q: What is a column-family database?
  A: A NoSQL database that groups columns into families.
     Each row can have different columns within a family.
     Designed for high write throughput and horizontal scale.
     Examples: Cassandra, HBase.

  Q: How is a column-family model different from a relational model?
  A: In RDBMS, all rows have the same fixed columns.
     In column-family, each row can have different columns dynamically.
     Column-family is schema-flexible, horizontally scalable, and
     optimized for sequential write and range reads by row key.
