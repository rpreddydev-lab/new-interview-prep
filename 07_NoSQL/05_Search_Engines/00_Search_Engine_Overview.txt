================================================================
  SEARCH ENGINE DATABASES OVERVIEW
================================================================

  Search engine databases are specialized for full-text search
  and real-time analytics on large document collections.
  They use inverted indexes for efficient text lookup.

================================================================
WHAT IS AN INVERTED INDEX?
================================================================

  A standard index: document --> words in document.
  An inverted index: word --> list of documents containing it.

  Documents:
    Doc1: "Redis is a fast in-memory database"
    Doc2: "MongoDB is a document database"
    Doc3: "Redis and MongoDB are NoSQL databases"

  Inverted Index:
    "redis"     --> [Doc1, Doc3]
    "mongodb"   --> [Doc2, Doc3]
    "database"  --> [Doc1, Doc2, Doc3]
    "fast"      --> [Doc1]
    "nosql"     --> [Doc3]

  Query "redis fast":
  - "redis" --> [Doc1, Doc3]
  - "fast"  --> [Doc1]
  - Intersection or scoring --> Doc1 most relevant

================================================================
KEY CAPABILITIES
================================================================

  Full-text search:
  - Tokenization (split text into terms)
  - Stemming ("running" --> "run")
  - Stop word removal ("the", "is", "and")
  - Fuzzy matching (typo tolerance)
  - Relevance scoring (TF-IDF, BM25)

  Real-time analytics:
  - Aggregations over large document sets
  - Faceted search (filter by category + color + price range)
  - Geo search (find stores within 10km)

  Structured queries:
  - Filter by exact values
  - Range queries
  - Nested document queries

================================================================
POPULAR SEARCH ENGINES
================================================================

  Elasticsearch   Most widely used. Distributed, RESTful.
                  Part of Elastic Stack (ELK: Elastic + Logstash + Kibana).
                  Built on Apache Lucene.

  OpenSearch      AWS fork of Elasticsearch (after licensing change).
                  Compatible API. Used on AWS.

  Apache Solr     Enterprise search on Lucene.
                  Predecessor to Elasticsearch.
                  Still used in large enterprise deployments.

  Typesense       Modern, easy-to-use search with typo tolerance.
                  Designed as Algolia alternative.

  Algolia         Managed search-as-a-service. Developer-friendly.
                  Used for e-commerce product search, autocomplete.

================================================================
SEARCH ENGINE vs DATABASE
================================================================

  Feature               Search Engine           RDBMS
  --------------------  ----------------------  ----------------------
  Full-text search      First-class             Limited (LIKE, tsvector)
  ACID transactions     No (Elasticsearch)      Yes
  Data freshness        Near real-time          Immediate
  Aggregations          Fast (pre-indexed)      SQL GROUP BY
  Storage               High (inverted indexes) Moderate
  Primary data store?   Usually secondary       Yes

  Search engines are usually a secondary store:
  Primary: PostgreSQL/MongoDB
  Secondary: Elasticsearch (synced via CDC / event stream)

================================================================
USE CASES
================================================================

  E-commerce product search (autocomplete, faceted filters, typo tolerance)
  Log analytics (ELK Stack: Logstash ingests, ES stores, Kibana visualizes)
  Full-text document search (legal, medical, knowledge base)
  Application performance monitoring (APM)
  Security analytics (SIEM)
  Autocomplete / typeahead suggestions

================================================================
INTERVIEW Q&A
================================================================

  Q: What is an inverted index?
  A: A data structure mapping terms to the list of documents containing them.
     Enables O(1) term lookup for full-text search.
     The opposite of a regular index (document to terms).

  Q: Why use Elasticsearch instead of PostgreSQL full-text search?
  A: Elasticsearch has richer full-text features (fuzzy, facets, relevance scoring),
     scales horizontally across many nodes, and handles hundreds of millions of
     documents with sub-second query times.
     PostgreSQL tsvector/GIN is good for moderate scale.
