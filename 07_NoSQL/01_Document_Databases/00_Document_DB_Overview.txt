================================================================
  DOCUMENT DATABASES OVERVIEW
================================================================

  A document database stores data as semi-structured documents,
  typically JSON or BSON.
  Each document is self-contained and can have different fields.

================================================================
KEY CONCEPTS
================================================================

  Document    A JSON-like record with key-value pairs.
              Can nest objects and arrays.
              Replaces a "row" in relational terms.

  Collection  A group of documents. No fixed schema.
              Replaces a "table" in relational terms.

  Database    Contains collections.

================================================================
EXAMPLE DOCUMENT
================================================================

  {
      "_id": "64a1b2c3d4e5f6a7b8c9d0e1",
      "name": "Alice Johnson",
      "email": "alice@example.com",
      "address": {
          "street": "123 Main St",
          "city": "Austin",
          "state": "TX"
      },
      "orders": [
          { "order_id": "ORD001", "total": 249.99, "status": "SHIPPED" },
          { "order_id": "ORD002", "total": 59.95,  "status": "PENDING" }
      ],
      "tags": ["premium", "newsletter"],
      "created_at": ISODate("2024-01-15T10:00:00Z")
  }

================================================================
DOCUMENT DB ADVANTAGES
================================================================

  1. Schema flexibility:
     New fields can be added per document.
     No ALTER TABLE or migration scripts.

  2. Hierarchical data:
     Embed related data inside a document (address inside user).
     Avoid JOINs -- one read gets all you need.

  3. Developer-friendly:
     JSON maps directly to objects in Java (Jackson), JavaScript, Python.
     Less impedance mismatch than relational tables.

  4. Horizontal scaling:
     Sharding by a document key distributes documents across nodes.

================================================================
DOCUMENT DB DISADVANTAGES
================================================================

  1. No JOINs (natively):
     Relationships between collections require multiple queries
     or application-side JOIN logic.

  2. Data duplication:
     Embedded data (e.g., product name in every order item)
     must be updated in all places if it changes.

  3. No multi-document ACID (pre-4.0):
     MongoDB 4.0+ supports multi-document transactions,
     but they carry overhead.

  4. Schema drift:
     Without discipline, collections accumulate inconsistent shapes.
     Use schema validation (JSON Schema in MongoDB) in production.

================================================================
POPULAR DOCUMENT DATABASES
================================================================

  MongoDB      Most popular. Rich query language, aggregation pipeline,
               Atlas cloud offering, ACID since 4.0.

  Firestore    Google Cloud. Real-time sync, offline support,
               designed for mobile/web apps.

  CouchDB      Apache. Peer-to-peer sync, HTTP API, conflict resolution.

  DynamoDB     AWS. Key-Value + document hybrid. Serverless scaling.

  RavenDB      .NET-focused. Full ACID, LINQ queries.

================================================================
INTERVIEW Q&A
================================================================

  Q: What is a document database?
  A: A NoSQL database that stores data as JSON-like documents.
     Documents are schema-flexible and can embed nested objects and arrays.
     Best for hierarchical data, variable attributes, and developer-friendly APIs.

  Q: What are the advantages of embedding vs referencing in documents?
  A: Embedding (nested documents): single read fetches all data, faster reads,
     no JOIN needed. Good for data that is always accessed together.
     Referencing (FK-like): avoids duplication, data updated in one place.
     Good for large sub-documents or data shared across many parents.
