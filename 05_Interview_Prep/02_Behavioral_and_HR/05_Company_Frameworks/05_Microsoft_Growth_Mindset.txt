MICROSOFT'S CORE VALUES — "GROWTH MINDSET"
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Satya Nadella transformed Microsoft with Carol Dweck's "Growth Mindset":
  → Believe intelligence and skills can be developed through dedication
  → Embrace failure as learning, not defeat
  → Seek challenges, persist through obstacles
  → Find inspiration in others' success
  → Collaborate over compete internally ("One Microsoft")

THREE CULTURAL PILLARS:
  1. Growth Mindset   — learning from failure, continuous improvement
  2. Customer Obsession — deeply understand and serve customer needs
  3. Diversity & Inclusion — diverse teams build better products

INTERVIEW PROCESS — TYPICAL STRUCTURE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Round 1: Recruiter Screen (experience, fit, comp)
  Round 2: Technical Phone Screen (1 coding problem + system discussion)
  Round 3-5: On-site / Virtual Loop (4-5 rounds, 45 min each)
    - 2-3 Coding rounds (LeetCode medium)
    - 1 System Design round
    - 1 Behavioral (Growth Mindset + leadership signals)
  [As Appropriate (As Appropriate interview)] — at some orgs, a panel
  decides culture fit at Principal level

BEHAVIORAL — GROWTH MINDSET QUESTIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Microsoft interviewers explicitly look for Growth Mindset signals.
Map every behavioral story to one of these:

  Q: Tell me about a time you failed and what you learned.
     → Growth Mindset: Can you own failure and extract learning?

  Q: Describe a time you had to learn something completely new to solve a problem.
     → Embracing challenges, learning velocity

  Q: Tell me about a time you received critical feedback. How did you respond?
     → Open to feedback = Growth Mindset; defensive = Fixed Mindset

  Q: Describe a time you helped a team member improve.
     → Finding inspiration in developing others (not competing)

  Q: Tell me about a time you changed your mind based on new information.
     → Intellectual humility, data-driven thinking

  Q: How do you stay current with technology?
     → Microsoft values engineers who are always learning
     → Mention: books, papers, open source, conferences, side projects

  Q: Tell me about a time you worked across teams to solve a problem.
     → "One Microsoft" — collaboration over silos

TECHNICAL — JAVA / AZURE FOCUS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Microsoft roles for Java engineers often involve Azure services:
  → Azure Service Bus (vs AWS SQS / Kafka)
  → Azure Cosmos DB (vs DynamoDB / MongoDB)
  → Azure Kubernetes Service (AKS)
  → Azure Event Hubs (Kafka-compatible protocol)
  → Spring Boot on Azure App Service / AKS

TECHNICAL QUESTIONS COMMONLY ASKED:
  Q: How does Java's garbage collector work? Which one would you choose for a
     low-latency Azure microservice and why?
  Q: How would you implement distributed caching in a Spring Boot service
     on Azure using Azure Cache for Redis?
  Q: Explain the difference between strong and eventual consistency.
     When would you use Cosmos DB's different consistency models?
  Q: How does Spring Security integrate with Azure Active Directory?
  Q: Design a real-time event processing pipeline using Azure Event Hubs
     and Spring Boot consumers.

CODING:
  → LeetCode Medium level, similar to Amazon/Google
  → Strong emphasis on Trees and Graphs
  → Expect follow-up complexity optimization questions
  → Popular: LC 146 (LRU Cache), LC 200 (Number of Islands),
             LC 297 (Serialize BST), LC 23 (Merge K Sorted Lists)

SYSTEM DESIGN:
  - Design a distributed configuration management service
  - Design a multi-tenant SaaS platform
  - Design an event-driven notification system at Microsoft Teams scale
  - Design a real-time collaborative document editing system (like Word Online)

TIPS FOR MICROSOFT INTERVIEWS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  1. GROWTH MINDSET is the meta-signal. Frame every story with:
     "I learned X from this," "I changed my approach after realizing Y."

  2. "One Microsoft" means collaboration. Show cross-team impact.
     Stories where you worked across org boundaries are gold.

  3. Interviewers WRITE DOWN your answers. Speak clearly and structured.
     They use a rubric — don't rush, be deliberate.

  4. Know Azure. Even if your background is AWS, show awareness of:
     Azure Service Bus, Cosmos DB, AKS, Azure Functions (serverless).

  5. Research the team. Microsoft has hundreds of product groups
     (Azure, Teams, Office, Xbox, Bing, GitHub).
     Tailor your "Why Microsoft / Why this team" answer specifically.

  6. The "As Appropriate" interviewer is often a Principal or Partner
     who tests culture fit at a deeper level. This is where Growth Mindset
     stories must shine.
