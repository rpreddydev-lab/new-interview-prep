GENERAL SENIOR JAVA DEVELOPER INTERVIEW TIPS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. ALWAYS discuss trade-offs, not just the solution.
2. START with requirements clarification in system design (5 min).
3. MENTION non-functional requirements: scale, latency, availability.
4. DO back-of-envelope calculations (DAU, QPS, storage) before designing.
5. NEVER say "I would use Redis" without explaining why vs alternatives.
6. KNOW your numbers: RAM ~100ns, disk seek ~10ms, network ~1ms local.
7. PRACTICE coding on a whiteboard or plain text editor (no IDE).
8. PREPARE 3-5 strong STAR stories for behavioral questions.
9. ASK clarifying questions — interviewers reward engagement.
10. KNOW your resume deeply — every project should have a story.

COMMONLY TESTED JAVA INTERNALS AT SENIOR LEVEL:
  ✅ HashMap internal: array + linked list + red-black tree (Java 8+)
  ✅ ConcurrentHashMap: segment locks (Java 7) → CAS + synchronized (Java 8+)
  ✅ volatile: visibility guarantee, not atomicity
  ✅ synchronized: mutual exclusion + visibility (memory barrier)
  ✅ ThreadLocal: thread-isolated storage, memory leak risk
  ✅ String.intern(): String pool in heap (Java 7+)
  ✅ equals/hashCode contract: must override both together
  ✅ Comparable vs Comparator
  ✅ @Transactional proxy: self-invocation doesn't work (internal calls bypass proxy)
  ✅ JPA N+1: detect with Hibernate stats, fix with JOIN FETCH or @EntityGraph
  ✅ CompletableFuture: understand which thread pool runs each stage
