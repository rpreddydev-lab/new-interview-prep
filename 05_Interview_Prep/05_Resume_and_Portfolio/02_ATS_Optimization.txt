================================================================================
ATS OPTIMIZATION FOR SENIOR JAVA DEVELOPERS
================================================================================
Purpose: Most companies use Applicant Tracking Systems (ATS) to filter
         resumes before a human ever sees them. At senior level, this is
         still a real barrier — especially at large companies.
================================================================================

HOW ATS WORKS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  ATS parses your resume and scores it against the job description (JD).
  It looks for:
    - Keyword matches (exact or near-match)
    - Relevant job titles
    - Years of experience (it reads dates)
    - Education requirements
    - Certifications

  If your resume doesn't hit a threshold score, it may be filtered out
  before any human reads it — regardless of your actual experience.

ATS-SAFE FORMATTING RULES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  ✅ Use standard section headers: "Experience", "Skills", "Education"
     (not creative names like "My Journey" or "What I've Built")

  ✅ Use plain text or simple single-column PDF/Word format
     (complex tables, two-column layouts, text boxes = ATS failure)

  ✅ Use standard date format: "Jan 2020 – Present" or "01/2020 – Present"

  ✅ Spell out abbreviations at least once:
     "Java Persistence API (JPA)", "Message Queue (MQ)"

  ✅ Use the exact job title from the JD in your experience if accurate
     (e.g., if the JD says "Senior Software Engineer" and your title
     was "Senior Developer", list it as "Senior Software Engineer
     (internally titled Senior Developer)")

  ❌ Avoid: Headers as images, icons, graphics, tables for skill bars
  ❌ Avoid: Text in headers/footers (many ATS can't read them)
  ❌ Avoid: Creative fonts or colors (submit plain, ATS-safe versions)

KEYWORD MATCHING STRATEGY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

STEP 1: Read the JD carefully
  → Extract: required skills, preferred skills, job title keywords,
    domain language, specific frameworks, methodologies (Agile, Scrum)

STEP 2: Mirror their language exactly
  → If JD says "Spring Boot" — say "Spring Boot" (not "Spring Framework")
  → If JD says "event-driven architecture" — use that exact phrase
  → If JD says "RESTful APIs" — don't just say "REST"

STEP 3: Inject keywords naturally
  → Don't stuff keywords randomly — put them in bullet points
    with actual context
  → Wrong: "Skills: Java, Spring Boot, Kafka, Redis, Kubernetes, AWS..."
  → Right: "Designed Kafka-based event pipeline on AWS EKS, reducing
            order processing latency by 70%"

STEP 4: Check with tools
  → jobscan.co — paste JD and resume, see keyword match score
  → resume.io / enhancv — ATS-friendly templates

TAILORING FOR DIFFERENT COMPANY TYPES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  FAANG / BIG TECH:
    → Emphasize scale (req/sec, DAU, TB of data)
    → Leadership principles alignment (Amazon LP, Google values)
    → DSA problem-solving experience (LeetCode, competitive programming)

  FINTECH / BANKS (Goldman, JPMC, Stripe):
    → Emphasize: ACID, idempotency, SAGA patterns, reconciliation
    → Mention: PCI-DSS awareness, audit logging, data integrity
    → Use terms: low-latency, high-availability, fault-tolerant

  STARTUPS:
    → Emphasize versatility and ownership
    → Mention full ownership of features end-to-end
    → Show you've worn multiple hats without sacrificing quality

  ENTERPRISE / CONSULTING:
    → Emphasize working with legacy systems, migration experience
    → Mention stakeholder management, documentation, knowledge transfer
