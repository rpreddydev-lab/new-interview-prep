EDGE CASES - FINDING AND HANDLING THEM LIKE A PRO
================================================================================
Last Updated: April 2026
Purpose: A complete guide to identifying, anticipating, and handling edge
         cases in coding interviews. Catching edge cases is what separates
         production-quality thinking from student-level thinking.
================================================================================

--------------------------------------------------------------------------------
1. WHY EDGE CASES ARE INTERVIEW GOLD
--------------------------------------------------------------------------------

An interviewer who sees you proactively handle edge cases thinks:
  "This person writes reliable production code."
  "This person thinks defensively."
  "This person won't ship bugs that cause 3 AM incidents."

An interviewer who sees you miss obvious edge cases thinks:
  "This person would require heavy code review."
  "This person has only written toy code, not production code."

EDGE CASES ARE NOT AN AFTERTHOUGHT. They are part of the problem.
At senior level, missing edge cases is a significant negative signal.

DEFINITION:
  An edge case is any input condition that:
  - Is at the boundary of valid/invalid input
  - Is a degenerate or trivial case of the problem
  - Could cause crashes, incorrect output, or undefined behavior
  - Was not explicitly covered in the problem examples

--------------------------------------------------------------------------------
2. THE UNIVERSAL EDGE CASE CHECKLIST
--------------------------------------------------------------------------------

Use this checklist for EVERY problem. It takes 60-90 seconds to run through.

[ ] NULL / NONE INPUT
    - Is the function being passed null?
    - What should happen? Return null? Throw exception? Return 0?
    - Java: always check array != null before array.length

[ ] EMPTY INPUT
    - Empty array []
    - Empty string ""
    - Empty tree (null root)
    - Empty graph (no nodes, or nodes with no edges)
    - Empty linked list
    - What should be returned? 0, -1, null, empty collection?

[ ] SINGLE ELEMENT
    - Array with 1 element [5]
    - String with 1 character "a"
    - Tree with 1 node
    - Does your algorithm work? (Off-by-ones often fail here)

[ ] TWO ELEMENTS
    - Often breaks algorithms that assume "at least 3 elements"
    - Comparison logic often has special behavior at size 2

[ ] ALL SAME ELEMENTS
    - [3, 3, 3, 3, 3]
    - "aaaaa"
    - Does your uniqueness/deduplication logic still work?

[ ] SORTED INPUT (ASCENDING)
    - [1, 2, 3, 4, 5]
    - Some algorithms accidentally break on sorted input

[ ] REVERSE SORTED INPUT (DESCENDING)
    - [5, 4, 3, 2, 1]
    - QuickSort pivot strategies, binary search edge cases

[ ] NEGATIVE NUMBERS
    - [-3, -1, -4, -1, -5]
    - Mixed negatives and positives [-5, 3, -2, 4]
    - Affects: sum initialization (can't start at 0 for max sum),
      multiplication (two negatives make positive), indices

[ ] ZERO VALUES
    - [0, 0, 0, 0]
    - Array containing zeros in key positions
    - Division by zero risk?

[ ] MAXIMUM VALUE
    - n = 10^5 or 10^9
    - Values at Integer.MAX_VALUE (2,147,483,647)
    - Sum of all elements might overflow int → use long

[ ] MINIMUM VALUE
    - n = 0 (empty)
    - Values at Integer.MIN_VALUE (-2,147,483,648)
    - Abs(Integer.MIN_VALUE) overflows int!

[ ] DUPLICATE VALUES
    - [1, 1, 2, 2, 3]
    - How does your deduplication work?
    - Does the problem want first/last/all occurrences?

[ ] ANSWER IS FIRST ELEMENT
    - Is your initialization correct to handle this?
    - e.g., max of array where max = nums[0]

[ ] ANSWER IS LAST ELEMENT
    - Does your loop reach the last element?
    - Off-by-one errors often miss the last element

[ ] k > n (WHEN k IS A PARAMETER)
    - k larger than array size
    - "Top k elements" when k > n: return all elements?

[ ] CIRCULAR / WRAPAROUND CONDITIONS
    - Circular array problems
    - String palindrome checks that wrap
    - Modular arithmetic

[ ] ALREADY VALID / TRIVIALLY SOLVED
    - Input is already sorted
    - Already in the desired state (0 operations needed)

[ ] ALL INVALID / NO ANSWER EXISTS
    - No valid path in a graph
    - No matching substring
    - Return -1, null, empty collection?

3. DATA STRUCTURE SPECIFIC EDGE CASES
--------------------------------------------------------------------------------

ARRAYS:
  - Length 0 or 1
  - All same elements
  - All negative
  - Sorted / reverse sorted
  - Values at INT_MAX or INT_MIN
  - k == 0 or k == n
  - Sum overflow (use long for cumulative sums)
  
  JAVA SPECIFIC:
  - arr == null vs arr.length == 0 (different checks!)
  - int[] vs Integer[] (primitives vs objects)
  - Array.copyOf() vs manual copy

STRINGS:
  - Empty string ""
  - Single character
  - All same characters "aaaa"
  - Mixed case (is comparison case-sensitive?)
  - Spaces and special characters (if applicable)
  - Unicode characters (if mentioned in problem)
  - Very long string (performance concern)
  
  JAVA SPECIFIC:
  - s == null vs s.isEmpty() vs s.isBlank()
  - s.equals() NOT s == (reference vs value equality)
  - StringBuilder when building result (don't use + in loop)

LINKED LISTS:
  - Empty list (head == null)
  - Single node
  - Two nodes
  - Cycle present (if not expected)
  - All nodes need to be processed (last node edge case)
  - Position k at end of list (kth from end)
  - k > length of list
  
  COMMON BUGS:
  - Not handling head modification separately
  - Losing reference to next before redirect
  - Forgetting to set last node's next to null

TREES:
  - Null/empty tree
  - Single node (root only)
  - Only left subtree (no right children)
  - Only right subtree (no left children)
  - Perfectly balanced vs extremely skewed (like a linked list)
  - Duplicate values in tree
  - Very deep tree (stack overflow in recursion)
  
  BST SPECIFIC:
  - All values on left subtree
  - BST with duplicate keys
  - Searching for a value not in tree

GRAPHS:
  - Empty graph (no nodes)
  - Single node, no edges
  - Disconnected components (not all nodes reachable)
  - Self-loops (node connected to itself)
  - Parallel edges (multiple edges between same pair)
  - Cycle detection (especially for DFS in topological sort)
  - Directed vs undirected handling
  
  COMMON BUGS:
  - Not marking nodes visited → infinite loop
  - Visiting same node in different components
  - Off-by-one in 0-indexed vs 1-indexed node IDs

HASH MAPS:
  - Key not found (use getOrDefault to avoid NPE)
  - Null keys (Java HashMap allows null keys; some don't)
  - Collision handling (usually abstracted, but mention it)
  - Very large number of unique keys (memory concern)

HEAPS / PRIORITY QUEUES:
  - Empty heap operations (peek() on empty throws exception)
  - Equal-priority elements (order undefined in standard heaps)
  - Size 1 heap

STACKS / QUEUES:
  - Empty stack pop (throws exception; check isEmpty() first)
  - Empty queue poll (returns null in Java; check first)
  - Unbalanced brackets (missing closing bracket at end of string)

--------------------------------------------------------------------------------
4. ALGORITHMIC EDGE CASES
--------------------------------------------------------------------------------

BINARY SEARCH:
  - Target not in array (return -1)
  - All elements equal to target
  - Target smaller than all elements
  - Target larger than all elements
  - Integer overflow in midpoint: use mid = lo + (hi - lo) / 2, NOT (lo+hi)/2
  - Infinite loop: ensure lo < hi or lo <= hi is correct for your template

SLIDING WINDOW:
  - Window size larger than array
  - All elements equal
  - Window that starts at index 0

DYNAMIC PROGRAMMING:
  - Base cases wrong (wrong initialization)
  - n=0 case (empty input)
  - dp[i] depends on dp[i-1] → need to handle dp[0] explicitly
  - Forgetting to return the final answer (return dp[n], not dp[n-1])

RECURSION:
  - Base case not reached (infinite recursion → StackOverflow)
  - Base case too early (missing actual base case)
  - Incorrect return in recursive case

SORTING:
  - Stable vs unstable sort requirement
  - Custom comparator: be careful of integer overflow in subtraction
    (use Integer.compare(a, b), NOT a - b)

TWO POINTERS:
  - Both pointers start at same index
  - Pointers cross each other
  - Answer is when left == right

BACKTRACKING:
  - Pruning condition fires on valid answer
  - Not restoring state after recursive call (missing undo step)
  - Generating duplicates (need to sort + skip duplicates)

--------------------------------------------------------------------------------
5. HOW TO COMMUNICATE EDGE CASES IN AN INTERVIEW
--------------------------------------------------------------------------------

APPROACH 1: ASK UPFRONT (DURING CLARIFICATION)
  "Before I start, let me identify the edge cases I'll need to handle.
   What should happen if the input is null or empty? What if k is larger
   than n?"

APPROACH 2: ANNOUNCE WHILE CODING
  "I'll add a null check at the start here - in production code I'd
   always validate inputs at the entry point..."
  
  "Here I'm handling the case where the array has only one element -
   my loop would be a no-op otherwise, so let me check explicitly..."

APPROACH 3: MENTION WHILE TESTING
  "Let me test this with a couple of edge cases. First, what if input
   is empty?... My code returns 0 here, which seems correct. What if
   all elements are negative?... The max sum would be the least negative
   element, which my code handles because I initialized result to nums[0]
   not to 0..."

BEST PRACTICE: USE ALL THREE APPROACHES

6. DEMONSTRATING EDGE CASE THINKING IN CODE
--------------------------------------------------------------------------------

JAVA TEMPLATE FOR EDGE CASE HANDLING:

```java
public int[] solve(int[] nums, int k) {
    // 1. Null/Empty input check
    if (nums == null || nums.length == 0) {
        return new int[]{};
    }
    
    // 2. k boundary check  
    if (k <= 0 || k > nums.length) {
        return new int[]{};  // or throw, per problem spec
    }
    
    // 3. Single element shortcut
    if (nums.length == 1) {
        return nums;
    }
    
    // 4. Main algorithm
    // ...
    
    return result;
}
```

WHAT THIS SHOWS:
  - Defensive coding instinct
  - Awareness of production realities
  - You've seen these bugs before (or you think like someone who has)

7. EDGE CASE PRACTICE PROBLEMS
--------------------------------------------------------------------------------

For each of these problems, list ALL edge cases BEFORE solving:

PROBLEM: "Find the maximum subarray sum" (Kadane's algorithm)
  Edge cases:
  [ ] All negative numbers → return the single least negative element
  [ ] Single element → return that element
  [ ] Empty array → return 0 or throw? (clarify)
  [ ] Array of zeros → return 0
  [ ] One very large negative number → result is the next smaller negative
  [ ] INT_MIN value → overflow possible when negating

PROBLEM: "Merge two sorted linked lists"
  Edge cases:
  [ ] Both lists null → return null
  [ ] One list null → return the other
  [ ] Lists of different lengths → handle when one runs out
  [ ] Both lists length 1 → just compare and order
  [ ] Duplicate values across lists → handle correctly
  [ ] Lists already in order → first element of l1 < first of l2

PROBLEM: "Check if a string is a valid palindrome (ignoring non-alphanumeric)"
  Edge cases:
  [ ] Empty string → true (or depends on definition)
  [ ] Single character → true
  [ ] All non-alphanumeric → true
  [ ] "A man, a plan, a canal: Panama" → true (classic)
  [ ] String with spaces only → true
  [ ] Mixed case: "Aa" → true (case-insensitive)

--------------------------------------------------------------------------------
8. QUICK REFERENCE - EDGE CASES BY PATTERN
--------------------------------------------------------------------------------

| Pattern        | Most Likely Edge Cases                              |
|----------------|-----------------------------------------------------|
| Array          | Empty, single elem, negatives, overflow, k>n        |
| String         | Empty, single char, all same, case sensitivity      |
| Tree           | Null root, single node, skewed tree                 |
| Graph          | Disconnected, self-loop, no edges, cycle            |
| Linked List    | Null head, single node, tail handling               |
| Binary Search  | Target not found, overflow in midpoint calc         |
| DP             | Base case initialization, n=0, return dp[n] not n-1 |
| Sliding Window | k > n, all same elements                            |
| Two Pointers   | Pointers cross, start at same index                 |
| Backtracking   | Undo step missing, duplicate pruning                |
