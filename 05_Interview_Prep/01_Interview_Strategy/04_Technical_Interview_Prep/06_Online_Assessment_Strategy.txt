================================================================================
ONLINE ASSESSMENT (OA) STRATEGY
================================================================================
Purpose: Online Assessments are the gatekeepers to phone screens.
         Most candidates fail here not because of skill, but because of
         poor time management, platform unfamiliarity, or minor bugs.
         This guide helps you pass OAs reliably.
================================================================================

--------------------------------------------------------------------------------
1. WHAT IS AN ONLINE ASSESSMENT?
--------------------------------------------------------------------------------

An OA is a timed coding challenge administered through a third-party platform
(HackerRank, HackerEarth, Codility, LeetCode Contest, Karat, CodeSignal)
before a live interview. It typically requires:
  - 2-3 algorithm/data structure problems
  - 60-120 minutes total
  - No interviewer present; automated grading
  - May include behavioral questions, debugging, or MCQ in addition to coding

OA PLATFORMS BY COMPANY:
  Amazon:            HackerRank (2 coding + leadership principles + work style survey)
  Google:            Internal OA platform / CodeSignal
  Meta:              HackerRank or CodeSignal
  Microsoft:         HackerRank
  Bloomberg:         Internal platform
  Goldman Sachs:     HireVue (coding + video questions)
  Startups:          Codility, LeetCode, or custom GitHub take-home

--------------------------------------------------------------------------------
2. BEFORE THE OA: PREPARATION
--------------------------------------------------------------------------------

KNOW YOUR PLATFORM (DO THIS 24 HOURS BEFORE):
  - Create an account on the platform and solve a practice problem
  - Test: code editor keybindings, dark mode, language selection, run vs. submit
  - Know: can you see test cases? Can you use custom input? Can you look at partial output?
  - Know: is there a penalty for wrong submissions? (Codility penalizes)

ENVIRONMENT SETUP:
  - Use a reliable computer (not a low-battery laptop)
  - Close all unnecessary tabs and apps
  - Good lighting and stable internet
  - Know where to start a timer (the platform usually has one; use it)
  - Keep a notepad and pen for scratch work

LANGUAGE SELECTION:
  - Use the language you are MOST fluent in, period.
  - For most candidates: Java or Python
  - Java pros: strong typing catches bugs; strong collections + sort APIs
  - Python pros: faster to write; less boilerplate; concise set/dict/heap operations
  - For Java OA specifically: know Collections.sort, PriorityQueue, HashMap, Arrays, StringBuilder

BEFORE THE OA MENTAL PREP:
  - Read the problem statement COMPLETELY before writing any code
  - Don't panic if you don't immediately know the solution
  - Solve it correctly first, then optimize if time permits

--------------------------------------------------------------------------------
3. DURING THE OA: TIME MANAGEMENT
--------------------------------------------------------------------------------

OA TIME BUDGET:
  For a 90-minute OA with 2 problems:
    - Problem 1 (likely easier): 35-40 minutes
    - Problem 2 (likely harder): 40-45 minutes
    - Review and edge cases: remaining time

  For a 90-minute OA with 3 problems:
    - Problem 1 (easy): 20 minutes
    - Problem 2 (medium): 35 minutes
    - Problem 3 (hard): 30 minutes
    - Buffer: 5 minutes

  CHECKPOINT RULE: If you've spent 30% of time on a problem with < 30% progress, skip ahead.
  PARTIAL CREDIT: Always submit something; partial test cases passing = partial credit.

READ THE PROBLEM CAREFULLY:
  - Re-read constraints: n ≤ 10^5 → O(n log n) allowed; n ≤ 10^3 → O(n²) allowed
  - Re-read examples: trace through them manually to confirm your understanding
  - Note: "return -1 if not found", "mod 10^9+7 if answer can be large"

DO NOT:
  - Start coding on line 1 without understanding the problem
  - Spend 15 minutes on a brute force that can't pass all test cases
  - Submit before running your own custom test cases
  - Ignore examples provided (trace through them first)

--------------------------------------------------------------------------------
4. STRATEGY FOR EACH PROBLEM
--------------------------------------------------------------------------------

PHASE 1: UNDERSTAND (2-3 min)
  - Read completely, note constraints
  - Trace through the example manually
  - Clarify to yourself: what is the input? what is the expected output?

PHASE 2: PATTERN RECOGNITION (2-3 min)
  Ask yourself:
  - Is this a sliding window? (subarray/substring with a condition)
  - Is this binary search? (sorted input + search for threshold)
  - Is this a graph problem? (cells/nodes with connections)
  - Is this a DP problem? (overlapping subproblems, optimal substructure)
  - Is this a greedy problem? (local optimal = global optimal)
  - Is this a heap problem? (k-th largest, merge sorted lists)

PHASE 3: PLAN (3-5 min for medium problems)
  - Write pseudocode or comments in the editor before code
  - Identify data structures needed
  - Identify edge cases to test

PHASE 4: CODE (15-25 min)
  - Code cleanly; use descriptive variable names
  - Write helper methods if logic is complex
  - Handle edge cases inline or in a separate check

PHASE 5: TEST (5-7 min)
  - Run provided examples first
  - Add custom test cases:
    - Empty input / null
    - Single element
    - All same elements
    - Maximum constraints (n=10^5): check time limit in your head
    - Negative numbers (if applicable)
  - Fix bugs; resubmit

--------------------------------------------------------------------------------
5. HACKERRANK-SPECIFIC TIPS
--------------------------------------------------------------------------------

CODE EDITOR:
  - Language selector: make sure Java or Python is selected BEFORE you start
  - HackerRank allows you to see partial test results on "Run" (sample cases)
    "Submit" runs all test cases
  - Custom input: use the "Custom Input" tab to test your own cases

JAVA ON HACKERRANK:
  - Main method in class "Solution":
    public class Solution {
        public static void main(String[] args) {
            Scanner scanner = new Scanner(System.in);
            // read input
        }
    }
  - Use BufferedReader for faster I/O on large inputs:
    BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
    int n = Integer.parseInt(br.readLine().trim());

HANDLING TIMEOUTS:
  - If your solution times out: first check if your algorithm is correct complexity
  - Java I/O bottleneck: replace Scanner with BufferedReader for large inputs
  - Check for unnecessary copies (StringBuilder over String concatenation)
  - Avoid System.out.println in loops; buffer output with StringBuilder, print once

COMMON JAVA PERFORMANCE TIPS FOR OA:
  - PriorityQueue: use (a, b) -> b - a for max-heap
  - HashMap vs. array: if keys are integers 0 to N, array is O(1) and cache-friendly
  - Sorting is O(n log n) with Arrays.sort() or Collections.sort()
  - StringBuilder for building strings in a loop (O(n) vs. O(n²) for + operator)

--------------------------------------------------------------------------------
6. CODILITY-SPECIFIC TIPS
--------------------------------------------------------------------------------

  - Codility scores based on: correctness AND performance separately
  - Each test case group earns points; partial credit is standard
  - Typical structure: "correctness tests" (small n) + "performance tests" (large n)

  STRATEGY:
    - Aim for 100% correctness on small inputs first
    - Then optimize for performance tests
    - A 75% (correct on small, TLE on large) is still passing at many companies

  EDGE CASES Codility tests:
    - Empty array
    - Single element
    - All negatives
    - Maximum value (n = 100,000)
    - Overflow (use long in Java if summing large numbers)

  CODILITY GOLDEN RULES:
    - Read problem statement for EXPECTED TIME COMPLEXITY (often given as hint)
    - Don't use floats; use integer arithmetic (divide at the end)
    - Watch for off-by-one errors in prefix sums

--------------------------------------------------------------------------------
7. CODESIGNAL-SPECIFIC TIPS (USED BY GOOGLE, COINBASE, etc.)
--------------------------------------------------------------------------------

  - Time-scored: faster correct solutions score higher
  - Four problems in 70 minutes (increasing difficulty)
  - Languages: Java, Python, C++, JavaScript supported

  STRATEGY:
    - Solve problems in order; don't skip ahead
    - Problem 1 is almost always trivial (warm-up); get it fast
    - Problem 4 is often hard; aim for a partial solution that passes some cases
    - CodeSignal shows test cases; use them to debug

  SPEED TIPS:
    - Python is faster to write but Java may pass time limits more reliably
    - Pre-type common code templates (main method, imports) as muscle memory

--------------------------------------------------------------------------------
8. BEHAVIORAL SECTION ON OAs (AMAZON LEADERSHIP PRINCIPLES)
--------------------------------------------------------------------------------

Amazon OAs typically include a behavioral survey + Work Style Assessment.
These are NOT optional; they are scored and considered in hiring decisions.

LEADERSHIP PRINCIPLES SURVEY (multiple choice):
  - Choose the option that BEST reflects Amazon's LPs
  - Common LP being tested: Customer Obsession, Ownership, Bias for Action
  - When in doubt: the answer that is most "customer first" and "biased toward action"
    tends to align with Amazon LPs

WORK STYLE ASSESSMENT:
  - Agreement scale on statements like "I prefer to work independently"
  - No single right answer; be authentic but skew toward: collaborative, data-driven,
    taking initiative, welcoming feedback

--------------------------------------------------------------------------------
9. AFTER THE OA: WHAT TO DO
--------------------------------------------------------------------------------

IF YOU FINISH EARLY:
  - Re-check edge cases on all problems
  - Verify output format exactly matches expected (spaces, newlines, trailing commas)
  - Run maximum constraint custom input to check for TLE

IF YOU RUN OUT OF TIME:
  - Submit what you have; partial credit is better than nothing
  - On next problems: at minimum write pseudocode or comments explaining approach
    (some platforms give partial credit for correct approach even without working code)

AFTER THE OA:
  - Write down the problems you struggled with (from memory)
  - Solve them cleanly the next day to reinforce the pattern
  - Track which topics you consistently miss in your mistake log
