1. WHAT IS REDISTEMPLATE?
───────────────────────────
  RedisTemplate<K, V> is Spring Data Redis's central class for Redis operations.
  It provides:
    - Type-safe operations via generic types K (key) and V (value)
    - Configurable serialization (key, value, hash key, hash value)
    - Operations objects for each Redis data structure
    - Pipeline, transaction, and Lua scripting support
    - Connection management (handles acquire/release automatically)


2. CORE VALUE OPERATIONS (STRINGS)
────────────────────────────────────
  ValueOperations<String, String> ops = stringRedisTemplate.opsForValue();

  // SET / GET
  ops.set("user:42:name", "Alice");
  ops.set("user:42:name", "Alice", 1, TimeUnit.HOURS);       // with TTL
  ops.set("user:42:name", "Alice", Duration.ofHours(1));     // Duration API
  ops.setIfAbsent("lock:resource", "token", 30, TimeUnit.SECONDS); // SET NX EX

  String name = ops.get("user:42:name");
  String old  = ops.getAndSet("user:42:name", "Bob");         // GETSET
  String prev = ops.getAndExpire("user:42:name", 1, TimeUnit.HOURS); // GETEX

  // INCR / DECR
  Long count = ops.increment("page:views");               // INCR
  Long count = ops.increment("page:views", 5L);           // INCRBY 5
  Long count = ops.decrement("inventory:item:42");         // DECR

  // Bulk operations
  ops.multiSet(Map.of("k1", "v1", "k2", "v2"));           // MSET
  List<String> values = ops.multiGet(List.of("k1", "k2")); // MGET

  // Size
  Long len = ops.size("user:42:bio");                     // STRLEN

7. PIPELINING WITH REDISTEMPLATE
──────────────────────────────────
  List<Object> results = redisTemplate.executePipelined(
      new SessionCallback<>() {
          @Override
          public Object execute(RedisOperations operations) {
              for (int i = 1; i <= 1000; i++) {
                  operations.opsForValue().set("key:" + i, "value:" + i);
              }
              return null; // ignored; results collected by executePipelined
          }
      }
  );
  // results.size() == 1000


8. TRANSACTIONS WITH REDISTEMPLATE
────────────────────────────────────
  // MULTI/EXEC via SessionCallback
  List<Object> txResults = redisTemplate.execute(new SessionCallback<>() {
      @Override
      public List<Object> execute(RedisOperations operations) {
          operations.multi();
          operations.opsForValue().set("key1", "val1");
          operations.opsForValue().increment("counter");
          operations.expire("key1", Duration.ofHours(1));
          return operations.exec();
      }
  });

  );

  // TTL operations
  redisTemplate.expire("session:abc", 30, TimeUnit.MINUTES);

  redisTemplate.delete(Set.of("key1", "key2", "key3"));  // bulk delete

  // Pattern-based (DANGEROUS in production — use SCAN)
  Set<String> keys = redisTemplate.keys("user:*");     // KEYS (blocking!)

  // Safe scan:
  Cursor<byte[]> cursor = redisTemplate.getConnectionFactory()
      .getConnection()
      .scan(ScanOptions.scanOptions().match("user:*").count(100).build());
  while (cursor.hasNext()) {
      String key = new String(cursor.next());
      // process key
  }
  cursor.close();


11. INTERVIEW QUESTIONS & ANSWERS
────────────────────────────────────
  Q: How do you configure RedisTemplate to store objects as JSON?
  A: Set the value serializer to GenericJackson2JsonRedisSerializer and the
     key serializer to StringRedisSerializer:
       template.setKeySerializer(new StringRedisSerializer());
       template.setValueSerializer(new GenericJackson2JsonRedisSerializer());
     This stores JSON with type info in Redis, making it readable in redis-cli
     and supporting deserialization without knowing the type at call time.

  Q: What's the difference between opsForValue() and boundValueOps()?
  A: opsForValue() returns a stateless operations object — you must pass the key
     on every method call. boundValueOps(key) returns an operations object bound
     to a specific key, so you don't repeat the key. Use BoundValueOperations
     when doing multiple operations on the same key for cleaner code.

  Q: Why should you avoid redisTemplate.keys("pattern") in production?
  A: KEYS command is O(N) and blocks the entire Redis server while scanning
     ALL keys. In production with millions of keys, this can cause latency
     spikes for all other clients. Use SCAN instead — it iterates in small
     batches (cursor-based) without blocking the server. Spring provides
     cursor-based scan via the connection's scan() method.

  Q: How does RedisTemplate handle connection management?
  A: RedisTemplate uses a ConnectionFactory (Lettuce or Jedis pool) to acquire
     and release connections automatically on each operation. You don't need to
     manually manage connections. For operations requiring the SAME connection
     (transactions, pipelines), use execute(SessionCallback) which guarantees
     all operations run on the same connection.
