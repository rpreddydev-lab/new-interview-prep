REDIS OVERVIEW — DEEP DIVE FOR INTERVIEWS

1. WHAT IS REDIS?
─────────────────
Redis (Remote Dictionary Server) is an open-source, in-memory data structure
store. It was created by Salvatore Sanfilippo in 2009 and is now maintained by
Redis Ltd. (formerly Redis Labs).

Key characteristics:
  • In-memory:     All data is stored in RAM → sub-millisecond latency
  • Persistent:    Optional disk persistence (RDB snapshots + AOF logs)
  • Single-threaded: Command execution is single-threaded (event loop model)
                     → no race conditions, no locking on commands
  • Rich data structures: Strings, Lists, Sets, Sorted Sets, Hashes, Streams,
                          Bitmaps, HyperLogLog, Geospatial indexes
  • High throughput: 100,000+ operations/second on commodity hardware
  • Replication: Master-replica replication built-in
  • Cluster-ready: Built-in horizontal partitioning (Redis Cluster)


2. ARCHITECTURE — HOW REDIS WORKS INTERNALLY
─────────────────────────────────────────────

2a. Single-Threaded Event Loop
  Redis uses a single-threaded event loop (based on libuv/epoll/kqueue) to
  process ALL client commands sequentially. This is why:
    - No mutexes or locks are needed per command
    - Commands are atomic by design
    - Long-running commands (e.g., KEYS *, SORT on large sets) can BLOCK
      the entire server

  Since Redis 4.0: Lazy freeing (DEL → UNLINK) runs in background threads
  Since Redis 6.0: Threaded I/O for reading requests & writing responses
                   (multi-threaded networking, single-threaded command execution)
  Since Redis 7.0: Redis Functions (replacement for Lua scripts)

2b. Memory Model
  Redis stores ALL data in a dict (hash table) mapped by key → value.
  Internally each value is a "robj" (Redis Object) with:
    - type field (string, list, set, zset, hash, stream)
    - encoding field (compact representation, e.g., ziplist vs skiplist)
    - ptr → actual data

  Memory-saving encodings (small data uses compact structures):
    Data type       | Compact encoding     | Full encoding
    ─────────────────────────────────────────────────────
    String (int)    | int (embedded)       | raw (SDS)
    List            | listpack             | quicklist
    Hash            | listpack             | hashtable
    Set             | listpack / intset    | hashtable
    Sorted Set      | listpack             | skiplist + hashtable
    Stream          | radix tree + listpack| (always)

2c. SDS — Simple Dynamic Strings
  Redis does NOT use C's null-terminated char* for strings.
  It uses SDS (Simple Dynamic Strings), which stores:
    - len:    actual length (O(1) STRLEN)
    - alloc:  allocated capacity
    - flags:  SDS type
    - buf[]:  byte array (binary-safe, can store \0)

  Benefits over C strings:
    - O(1) length retrieval
    - Binary-safe (can store arbitrary bytes)
    - Prevents buffer overflows
    - Efficient append/prepend


3. REDIS COMMAND EXECUTION FLOW
────────────────────────────────
  Client → TCP socket → input buffer → command parser
       → command table lookup → execute command
       → write response to output buffer → send to client

  All happening in a single-threaded event loop iteration (one tick).


4. WHY IS REDIS SO FAST?
────────────────────────
  1. In-memory storage — no disk I/O in the critical path
  2. Efficient data structures — O(1) or O(log N) for most operations
  3. Single-threaded command processing — no context switching, no lock overhead
  4. Non-blocking I/O multiplexing — handles thousands of connections via epoll
  5. Pipelining — clients send multiple commands without waiting for responses
  6. Optimized memory encoding — compact representations reduce memory, improve
     cache locality

6. REDIS LICENSE NOTE (IMPORTANT FOR INTERVIEWS)
──────────────────────────────────────────────────
  In March 2024, Redis Ltd. changed the license from BSD to:
    - RSALv2 (Redis Source Available License v2), OR
    - SSPLv1 (Server Side Public License)
  This means Redis 7.4+ is NO LONGER open-source by OSI definition.

  Community forks:
    - Valkey (Linux Foundation fork) — most popular drop-in replacement
    - Redict (LGPL fork)
  AWS, Google, Azure continue to offer "Redis-compatible" managed services.

8. REDIS CONFIGURATION ESSENTIALS (redis.conf)
───────────────────────────────────────────────
  # Memory limit and eviction
  maxmemory 4gb
  maxmemory-policy allkeys-lru

  # Persistence
  save 900 1          # RDB: save if 1 key changed in 900s
  appendonly yes      # Enable AOF
  appendfsync everysec

  # Replication
  replicaof <master-ip> <port>

  # Cluster
  cluster-enabled yes
  cluster-config-file nodes.conf
  cluster-node-timeout 5000

  # Security
  requirepass <password>
  rename-command FLUSHALL ""   # Disable dangerous commands


9. KEY REDIS CLI COMMANDS TO KNOW
───────────────────────────────────
  # Server info
  INFO [section]           # server, replication, memory, clients, stats
  CONFIG GET maxmemory
  CONFIG SET maxmemory 2gb
  DEBUG SLEEP 5            # simulate slow server (testing)
  MONITOR                  # stream all commands (debug only!)
  SLOWLOG GET 10           # last 10 slow commands

  # Key operations
  SET key value [EX seconds] [PX ms] [NX|XX] [GET]
  GET key
  DEL key [key …]
  UNLINK key [key …]       # async delete
  EXISTS key [key …]
  EXPIRE key seconds
  TTL key                  # -1 = no TTL, -2 = key doesn't exist
  PERSIST key              # remove TTL
  TYPE key
  RENAME key newkey
  SCAN cursor [MATCH pat] [COUNT count] [TYPE type]   # non-blocking iteration


10. INTERVIEW QUICK SUMMARY
────────────────────────────
  Q: What is Redis?
  A: An in-memory, single-threaded, key-value data store supporting rich data
     structures. Used for caching, sessions, queues, pub/sub, leaderboards.

  Q: Why is Redis fast?
  A: In-memory, non-blocking I/O (epoll), single-threaded command processing
     (no locking), efficient data structures.

  Q: Is Redis single-threaded?
  A: Command EXECUTION is single-threaded. Networking I/O is multi-threaded
     since Redis 6.0. Background tasks (persistence, lazy delete) use threads.

  Q: What happens when Redis runs out of memory?
  A: Depends on maxmemory-policy: can evict LRU/LFU keys, evict TTL keys,
     or return OOM errors to clients.
