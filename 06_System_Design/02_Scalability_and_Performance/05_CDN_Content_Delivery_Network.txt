================================================================
CDN — CONTENT DELIVERY NETWORK
================================================================

WHAT IS A CDN?
---------------
A CDN is a globally distributed network of servers (edge nodes / Points
of Presence — PoPs) that deliver content to users from the location
nearest to them.

Without CDN:  User in Tokyo → Origin Server in Virginia (150ms RTT)
With CDN:     User in Tokyo → Edge Node in Tokyo (5ms RTT)

Speedup: 10×–100× for static content

HOW A CDN WORKS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. CONTENT POPULATION (Caching):
   a) Pull CDN (on-demand):
      First request from a region triggers CDN to PULL content from origin.
      Subsequent requests served from CDN edge cache.
      Cache-Control headers determine TTL.
      Most common setup.
   
   b) Push CDN:
      You proactively PUSH content to CDN edge nodes.
      Good for large files you know will be popular (new video release).
      Requires you to invalidate/re-push when content changes.

2. REQUEST FLOW (Pull CDN):
   Client → DNS lookup (GeoDNS returns nearest edge IP)
         → Edge Node (cache HIT? serve directly)
         → (cache MISS) Edge → Origin Server → cache response → serve

3. DNS ROUTING TO NEAREST EDGE:
   CDN providers use GeoDNS or Anycast to route users to nearest PoP.
   Cloudflare uses Anycast: single IP, BGP routes to nearest PoP.
   CloudFront uses GeoDNS: different IPs for different regions.

WHAT TO PUT ON A CDN
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

IDEAL FOR CDN (static, read-heavy):
  ✓ Images (JPEG, PNG, WebP, AVIF)
  ✓ Videos (MP4, HLS segments)
  ✓ JavaScript bundles
  ✓ CSS stylesheets
  ✓ Web fonts
  ✓ Software downloads / APK files
  ✓ HTML pages (if they don't change per user)
  ✓ Publicly cacheable API responses

NOT IDEAL FOR CDN (dynamic, personalized):
  ✗ Personalized API responses (user-specific data)
  ✗ Real-time data (stock prices, live scores)
  ✗ Authenticated responses (user's feed, messages)
  ✗ Write operations (POST, PUT, DELETE) — these pass through to origin

BORDERLINE (use with care):
  ~ Semi-static pages (homepage, product pages) — CDN with short TTL
  ~ Public API responses — Cache if data is the same for all users
    (GET /products/123 → cacheable; GET /cart → not cacheable)

CDN CACHE CONTROL HEADERS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Origin server controls CDN behavior via HTTP headers:

Cache-Control: public, max-age=86400
  → CDN caches for 24 hours

Cache-Control: private, max-age=3600
  → Browser caches for 1 hour, CDN should NOT cache (private data)

Cache-Control: no-cache
  → Must revalidate with origin on each request (not "don't cache")

Cache-Control: no-store
  → Never cache, anywhere

Cache-Control: s-maxage=3600
  → CDN caches for 3600s; browser uses max-age (different from s-maxage)

Surrogate-Control: max-age=86400
  → CDN-specific header (Fastly uses this); not sent to browser

Vary: Accept-Encoding
  → Cache separate versions for different encodings (gzip vs br vs identity)

Vary: Accept-Language
  → Cache separate versions per language (use carefully — reduces hit rate)

CACHE BUSTING STRATEGY:
  Problem: You want long TTL (1 year) but need instant updates when code changes
  Solution: Content-addressable filenames with hash in the name
    app.js → app.a3f9c2.js  (hash of file content)
    When code changes → new hash → new filename → CDN miss → serves new file
    Old filename still cached — but no one requests it anymore

CDN FEATURES BEYOND CACHING
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. DDoS PROTECTION:
   Edge nodes absorb volumetric attacks (hundreds of Gbps).
   Cloudflare, AWS Shield Advanced, Fastly all provide this.

2. WAF (Web Application Firewall):
   Block SQL injection, XSS, malicious bots at the edge.
   Rules applied before traffic reaches origin.

3. SSL/TLS TERMINATION:
   CDN handles TLS handshake (expensive) at the edge.
   Reduces latency and offloads origin server.

4. IMAGE OPTIMIZATION:
   Automatically convert images to WebP/AVIF format.
   Resize images based on device (responsive images).
   Compress images without quality loss.
   (Cloudflare Images, AWS CloudFront + Lambda@Edge, Cloudinary)

5. EDGE COMPUTING:
   Run code at the CDN edge (Cloudflare Workers, Lambda@Edge).
   Use cases:
     - A/B testing decisions at the edge
     - Auth token validation without round-trip to origin
     - Personalization (inject user-specific headers)
     - Geo-blocking (block certain countries at edge)

6. VIDEO STREAMING:
   HLS/DASH video delivery via CDN.
   Adaptive bitrate streaming segments cached at edge.
   Live streaming: origin → CDN PoPs → viewers worldwide

CDN PROVIDERS COMPARISON
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Cloudflare:
  - 300+ PoPs globally, Anycast network
  - Free tier available (great for startups)
  - Excellent DDoS protection (industry leading)
  - Workers (edge computing), Images, Stream
  - Best for: General web apps, API acceleration

AWS CloudFront:
  - Deep AWS integration (S3, EC2, ALB, API Gateway)
  - Lambda@Edge for serverless at the edge
  - Shield + WAF integration
  - Best for: AWS-native applications

Fastly:
  - Real-time log streaming and analytics
  - Varnish-based, highly configurable
  - Instant purge (sub-second cache invalidation)
  - Best for: Media companies, developer-centric teams

Akamai:
  - Oldest, largest footprint (4,000+ PoPs)
  - Enterprise-grade, expensive
  - Best for: Enterprise with complex requirements

CDN IN SYSTEM DESIGN INTERVIEWS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

When designing a system with media (videos, images):
  ALWAYS add CDN for media delivery. Explain:
  "All media content is stored in S3 and served through CloudFront CDN.
   This ensures low-latency delivery globally and reduces load on our
   origin servers. TTL is set to 7 days for images; videos are
   immutable so TTL can be 1 year."

When designing a global API:
  "For read-heavy public APIs, we can use CDN caching with a 60-second
   TTL. This reduces origin load by 90%+ for popular endpoints."

CDN Failure Handling:
  "If CDN is unavailable, requests fall through to origin.
   This will increase latency and origin load but service remains
   available. We'd alert on CDN error rate > 5%."

Key points to mention:
  ✓ CDN reduces latency by serving from nearest edge
  ✓ CDN reduces origin load (offloads traffic)
  ✓ CDN provides resilience (absorbs traffic spikes)
  ✓ Cache invalidation strategy (TTL + hash-based filenames)
  ✓ What is NOT on CDN (dynamic, personalized content)
