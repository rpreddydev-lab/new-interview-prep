1. AGILE OVERVIEW
================================================================================

The Agile Manifesto (2001):
  Seventeen software thought leaders met in Snowbird, Utah and published the
  Agile Manifesto — 4 values and 12 principles for software development.

The Four Agile Values:
  1. Individuals and interactions OVER processes and tools
  2. Working software OVER comprehensive documentation
  3. Customer collaboration OVER contract negotiation
  4. Responding to change OVER following a plan

The 12 Principles (Key ones):
  - Deliver working software frequently (weeks rather than months)
  - Welcome changing requirements, even late in development
  - Build projects around motivated individuals
  - Working software is the primary measure of progress
  - Sustainable development (constant pace, indefinitely)
  - Continuous attention to technical excellence
  - Simplicity — maximizing the amount of work NOT done
  - Self-organizing teams
  - Regularly reflect and adjust behavior

What Agile Addresses:
  - The software development process (how teams plan and build)
  - Replaces "Waterfall" (requirements → design → code → test → deploy as
    sequential phases, often taking 12-18 months per cycle)
  - Focuses on iterative development, customer collaboration, and adaptability

Agile Scope:
  - Primarily concerns the DEV side of the house
  - Addresses the planning-to-code part of the lifecycle
  - Does NOT inherently address how software is deployed or operated

2. DEVOPS OVERVIEW (RECAP)
================================================================================

DevOps (emerged ~2009):
  - Addresses the gap between Development and Operations
  - Focuses on the entire lifecycle: code → build → test → deploy → operate →
    monitor
  - Cultural philosophy + automation practices + tooling

DevOps Scope:
  - Spans the entire software delivery lifecycle
  - Includes infrastructure, deployment, monitoring, and operations
  - Bridges Dev AND Ops

3. KEY DIFFERENCES
================================================================================

Dimension           | Agile                          | DevOps
--------------------|--------------------------------|---------------------------------
Primary Focus       | Software development process   | End-to-end delivery + operations
Origin              | 2001, Agile Manifesto          | ~2009, Patrick Debois
Addresses           | Dev vs. "Waterfall"            | Dev vs. Ops
Scope               | Planning through code          | Code through production + ops
Primary Audience    | Development teams              | Dev + Ops + everyone
Iteration Length    | Sprints (1-4 weeks)            | Continuous (daily or faster)
Feedback Source     | Customer/stakeholder           | System telemetry + customer
Key Practices       | Sprints, standups, retros      | CI/CD, IaC, monitoring
Key Metrics         | Velocity, sprint burndown      | DORA metrics, MTTR, uptime
Tools               | Jira, Trello, Confluence       | Jenkins, Kubernetes, Terraform
Output              | Working software every sprint  | Software in production
Team Size           | Small (5-9 people per team)    | Cross-functional (varies)
Change Management   | Embrace change in requirements | Automate change deployment
End Point           | "Done" = code in sprint        | "Done" = running in production

4. HOW THEY COMPLEMENT EACH OTHER
================================================================================

Agile and DevOps are NOT competing philosophies — they complement each other:

  Agile answers: HOW should we develop software?
  DevOps answers: HOW should we deliver and operate software?

Together, they cover the ENTIRE value chain:
  Requirements → Design → Development → Testing → Deployment → Operations → Monitoring

The Gap (Pre-DevOps Agile):
  - Agile teams delivered working software at the end of each sprint
  - But "working" meant "works in development"
  - Operations received code once every few sprints via a separate process
  - The deployment process was manual, slow, and error-prone
  - Despite Agile, time-to-production was still measured in weeks/months

DevOps Fills the Gap:
  - DevOps automation ensures that "done" means "deployed to production"
  - CI/CD pipelines connect the sprint output directly to production
  - Agile gives you the WHAT and WHEN; DevOps gives you the HOW to ship it

Example Flow (Agile + DevOps):
  1. Sprint Planning (Agile): Team picks user stories for the 2-week sprint
  2. Development (Agile): Developers code features with TDD
  3. Code Review + PR (DevOps): Automated CI pipeline runs on every PR
  4. Sprint Demo (Agile): Stakeholders see working software
  5. Continuous Deployment (DevOps): Approved code deploys automatically
  6. Monitoring + Feedback (DevOps): Metrics feed back into next sprint planning
  7. Retrospective (Agile): Team improves process based on data + feedback

5. AGILE FRAMEWORKS: SCRUM, KANBAN, SAFe
================================================================================

A. SCRUM
   ------
   Definition: An Agile framework for managing work in time-boxed iterations
   called "sprints" (typically 2-4 weeks).

   Key Roles:
     - Product Owner: Owns the backlog, prioritizes features, represents customer
     - Scrum Master: Facilitates the process, removes impediments, coaches team
     - Development Team: Self-organizing, cross-functional, builds the product

   Key Ceremonies:
     - Sprint Planning: Select stories from backlog, commit to sprint goal
     - Daily Standup (15 min): What did I do? What will I do? Any blockers?
     - Sprint Review: Demo working software to stakeholders
     - Sprint Retrospective: Reflect on process improvements
     - Backlog Refinement: Groom and estimate upcoming stories

   Key Artifacts:
     - Product Backlog: Prioritized list of all desired work
     - Sprint Backlog: Work committed to in the current sprint
     - Increment: The sum of completed work (potentially shippable product)
     - Definition of Done (DoD): Clear criteria for when work is "done"
       Example DoD: Code written, unit tests passing, code reviewed, deployed
       to staging, acceptance criteria verified, no P0/P1 bugs

   Velocity:
     - Story points completed per sprint
     - Used for forecasting (not performance measurement)
     - Important: Velocity is a planning tool, not a productivity metric

   DevOps + Scrum:
     - CI/CD pipelines should deploy every merged PR automatically
     - "Done" in Definition of Done should include deployed to staging/prod
     - Sprint metrics + production metrics combine for complete picture

B. KANBAN
   -------
   Definition: A visual workflow management system focused on continuous flow
   rather than time-boxed iterations.

   Key Principles:
     - Visualize the workflow (Kanban board with columns)
     - Limit Work in Progress (WIP limits per column)
     - Manage flow (measure and optimize)
     - Make policies explicit (clear rules for moving cards)
     - Feedback loops (regular reviews)
     - Improve collaboratively, evolve experimentally

   Kanban Board Example:
     [Backlog] → [Analysis] → [Development] → [Testing] → [Deployment] → [Done]
     WIP:  ∞         2           3               2            1

   Key Metrics:
     - Lead Time: Time from request creation to delivery
     - Cycle Time: Time from work started to work done
     - Throughput: Items completed per time period
     - Cumulative Flow Diagram (CFD): Visualizes flow and WIP over time

   Kanban vs Scrum:
     Scrum                     | Kanban
     --------------------------|--------------------------------------------
     Time-boxed sprints        | Continuous flow, no fixed iterations
     Sprint commitments        | Pull work as capacity allows
     Velocity in story points  | Throughput and lead time
     Dedicated ceremonies      | Regular cadence reviews (as needed)
     Best for: new products    | Best for: ongoing operations, support

   DevOps + Kanban:
     - Ops teams often use Kanban for incident management and support tickets
     - WIP limits in deployment pipeline prevent deployment bottlenecks
     - Visualization of deployment pipeline as a Kanban board

C. SAFE (Scaled Agile Framework)
   -------------------------------
   Definition: A framework for applying Agile at enterprise scale across many
   teams working on large, complex products.

   Levels:
     - Essential SAFe: Basic building blocks (Agile Release Train)
     - Large Solution SAFe: Multiple ARTs (Solution Trains)
     - Portfolio SAFe: Investment strategy, portfolio Kanban
     - Full SAFe: Complete configuration for large enterprises

   Key Concepts:
     - Agile Release Train (ART): 50-125 people aligned to a common mission
     - Program Increment (PI): 8-12 week planning cycle for an ART
     - PI Planning: 2-day event where all teams plan together
     - Release Train Engineer (RTE): Like a Scrum Master for the ART

   DevOps in SAFe:
     - SAFe includes a "CALMR" model (CALMS with an R for Recover)
     - Deployment pipeline is a shared capability across the ART
     - Continuous Delivery Pipeline is one of SAFe's core competencies

6. DEVOPS + AGILE = BETTER TOGETHER
================================================================================

The Virtuous Cycle:
  Agile enables frequent small releases.
  DevOps enables those releases to reach production safely and quickly.
  Production feedback informs the next Agile sprint.
  Repeat → Continuous improvement loop.

Business Outcomes:
  Agile alone (without DevOps):
    - Teams develop faster, but deployment bottleneck still exists
    - Sprint backlog is cleared but production deploy takes weeks
    - Customer value delayed despite Agile velocity

  DevOps alone (without Agile):
    - Fast deployments but waterfall development cycle
    - Big-bang releases even if automated

  Agile + DevOps:
    - Small features developed in sprints
    - Automatically deployed to production
    - Fast feedback from real users
    - Incorporated into next sprint
    - True continuous delivery of customer value

Spotify Model (Guilds, Squads, Tribes, Chapters):
  - Squads: Small, cross-functional teams (like Scrum teams)
  - Tribes: Collection of squads working on related areas
  - Chapters: Horizontal communities of practice (all frontend devs)
  - Guilds: Cross-tribe interest groups (DevOps guild, security guild)
  - Combines Agile (squad autonomy) with DevOps (shared tooling and culture)

7. WHERE AGILE ENDS AND DEVOPS BEGINS
================================================================================

The Agile Manifesto does NOT cover:
  - Infrastructure management
  - Deployment automation
  - Production operations
  - Monitoring and alerting
  - Incident management
  - Security in the pipeline

DevOps picks up where Agile leaves off:
  
  AGILE TERRITORY              BOUNDARY              DEVOPS TERRITORY
  ----------------------        ---------             -----------------------
  Product Backlog               [PR Merge]            CI Pipeline triggers
  Sprint Planning                                     Build + Test automation
  Story Writing                                       Artifact packaging
  Development                                         Deployment automation
  Sprint Review               [Release Gate]          Blue-Green deployment
  Retrospective                                       Production monitoring
                                                      On-call and incidents
                                                      Infrastructure scaling

Definition of Done Bridge:
  The key integration point is the "Definition of Done."
  A mature Definition of Done includes:
  - Code complete + reviewed (Agile)
  - Tests passing (Agile + DevOps)
  - Deployed to staging (DevOps)
  - Performance benchmarks met (DevOps)
  - Security scan passing (DevOps — DevSecOps)
  - Deployed to production (DevOps)
  - Monitoring in place (DevOps)

8. COMMON MISCONCEPTIONS
================================================================================

Misconception 1: "DevOps replaces Agile"
  Reality: They are complementary. DevOps extends Agile's reach to operations.
  You need both for truly continuous delivery of value.

Misconception 2: "Agile is only for software teams; DevOps is only for Ops"
  Reality: Both span the organization. Agile can apply to marketing and HR.
  DevOps spans Dev, Ops, Security, QA, and beyond.

Misconception 3: "If we do Scrum, we're doing DevOps"
  Reality: Scrum addresses the development process. DevOps additionally requires
  CI/CD automation, IaC, monitoring, and cultural changes in operations.

Misconception 4: "Kanban is less rigorous than Scrum"
  Reality: Kanban can be MORE rigorous with strict WIP limits and detailed flow
  metrics. Many high-performing ops teams use Kanban precisely because it
  provides better flow control than sprints for support/maintenance work.

Misconception 5: "DevOps means developers do all operations"
  Reality: It means developers have more operational awareness and ownership.
  Dedicated SRE/Platform teams still exist — the difference is collaboration
  and shared responsibility models.

9. COMMON INTERVIEW QUESTIONS & ANSWERS
================================================================================

Q1: What is the difference between Agile and DevOps?
A: Agile is a software development methodology focused on iterative development,
   customer collaboration, and embracing change. It primarily addresses how
   development teams plan and build software, replacing waterfall's sequential
   phases with short sprints.
   
   DevOps is a cultural and technical movement that bridges development and
   operations, focusing on automating and streamlining the entire delivery
   lifecycle from code to production. DevOps extends beyond where Agile ends —
   it addresses CI/CD pipelines, infrastructure automation, deployment
   strategies, monitoring, and incident management.
   
   They are complementary: Agile improves how software is developed; DevOps
   improves how that software is deployed and operated.

Q2: Can you practice both Agile and DevOps simultaneously?
A: Yes, and you should. They work best together. Agile teams develop small
   increments of working software in sprints. DevOps automation ensures those
   increments flow continuously to production. Without DevOps, Agile teams may
   develop fast but deploy slowly. Without Agile, DevOps automation deploys
   large infrequent releases. Together, they enable truly continuous delivery
   of value to customers.

Q3: What is Scrum and what are its key roles and ceremonies?
A: Scrum is an Agile framework using 2-4 week time-boxed iterations called
   sprints. Key roles: Product Owner (backlog prioritization), Scrum Master
   (facilitator and coach), Development Team (cross-functional builders).
   Key ceremonies: Sprint Planning, Daily Standup, Sprint Review, Sprint
   Retrospective, and Backlog Refinement. Key artifacts: Product Backlog,
   Sprint Backlog, and the Increment.

Q4: Scrum vs Kanban — when would you use each?
A: Scrum works best for product development with defined sprints and sprint
   goals — when you need velocity predictability and stakeholder demos.
   Kanban works best for continuous workflow without sprint boundaries —
   ideal for operations, support, and maintenance work where items arrive
   continuously and need immediate attention. Kanban's WIP limits and flow
   metrics provide better operational visibility.

Q5: What is the Definition of Done and how does it connect Agile and DevOps?
A: The Definition of Done is the shared agreement on what "complete" means for
   a work item. A basic Agile DoD might be "code written and unit tests pass."
   A DevOps-integrated DoD extends this: "code reviewed, automated tests pass,
   security scan clean, deployed to staging, performance benchmarks met, and
   deployed to production with monitoring in place." This bridge ensures that
   Agile's "working software" truly means working in production.

10. QUICK REFERENCE CHEAT SHEET
================================================================================

Agile Manifesto Values (4):
  1. Individuals & interactions > processes & tools
  2. Working software > comprehensive documentation
  3. Customer collaboration > contract negotiation
  4. Responding to change > following a plan

Key Agile Frameworks:
  Scrum: Time-boxed sprints, roles (PO/SM/Dev), ceremonies (planning/standup/review/retro)

  Sprint output → CI/CD pipeline → Production → Metrics → Next sprint plan

Critical interview takeaway:
  "Agile removes waste in the development process.
   DevOps removes waste in the delivery process.
   Together they form a complete, continuous loop."
