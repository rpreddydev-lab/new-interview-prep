NETWORKING AND COMMUNICATION — OVERVIEW
================================================================

WHY NETWORKING MATTERS IN SYSTEM DESIGN
-----------------------------------------
Modern systems are distributed — components communicate over networks.
Understanding networking protocols helps you choose the right
communication mechanism for each use case.

KEY QUESTION: How should component A talk to component B?
  - Is communication synchronous (request-response) or async (fire-and-forget)?
  - Is it real-time (low latency) or batched (high throughput)?
  - Is it internal (service-to-service) or external (client-to-server)?
  - What are the payload size and frequency characteristics?

NETWORKING FUNDAMENTALS REFERENCE:
  OSI Model (7 layers):
    Layer 7: Application (HTTP, DNS, SMTP)
    Layer 6: Presentation (TLS/SSL, encoding)
    Layer 5: Session (session management)
    Layer 4: Transport (TCP, UDP)
    Layer 3: Network (IP routing)
    Layer 2: Data Link (MAC addresses, Ethernet)
    Layer 1: Physical (cables, fiber, WiFi)

  TCP vs UDP:
    TCP: Reliable (ACKs), ordered, connection-oriented, congestion control
    UDP: Unreliable, unordered, connectionless, faster (no overhead)
    Use TCP: HTTP, databases, SSH, any data that must arrive
    Use UDP: Video streaming, gaming, DNS, VoIP (latency > reliability)

  Connection Lifecycle (TCP 3-way handshake):
    Client → SYN → Server
    Client ← SYN-ACK ← Server
    Client → ACK → Server
    [Connection established, ~1 RTT overhead]
    
    HTTP Keep-Alive: Reuse connection for multiple requests (critical!)
    Without: New TCP handshake per request = +1 RTT per request

  DNS Resolution:
    Client → Recursive Resolver → Root NS → TLD NS → Authoritative NS
    Cached at each level with TTL.
    TTL too long: Changes take time to propagate (stale)
    TTL too short: More DNS queries, higher latency

  HTTP/1.1 vs HTTP/2 vs HTTP/3:
    HTTP/1.1: One request per connection (Head-of-Line blocking)
              → Workaround: Open 6 connections per browser
    HTTP/2:   Multiplexing (many requests on one connection)
              Binary framing, header compression (HPACK)
              Server push (proactively send resources)
    HTTP/3:   QUIC (UDP-based, no TCP HOL blocking)
              Faster connection establishment (0-RTT for repeat visits)
              Better performance on lossy connections (mobile)
