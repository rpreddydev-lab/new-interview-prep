================================================================
DATA STORAGE — OVERVIEW
================================================================

OVERVIEW
---------
Choosing the right storage system is one of the most critical decisions
in system design. Different storage types have vastly different
performance characteristics, consistency guarantees, and query capabilities.

STORAGE TYPES:
  1. Relational (SQL) Databases
     - PostgreSQL, MySQL, Oracle, SQL Server
     - Structured data, ACID transactions, complex queries

  2. NoSQL Databases (many subtypes)
     - Document:    MongoDB, Couchbase
     - Key-Value:   Redis, DynamoDB, Riak
     - Wide-Column: Cassandra, HBase, Bigtable
     - Graph:       Neo4j, Amazon Neptune
     - Time-Series: InfluxDB, TimescaleDB, Prometheus

  3. Search Engines
     - Elasticsearch, OpenSearch, Solr
     - Full-text search, complex aggregations

  4. Object Storage
     - Amazon S3, Google Cloud Storage, Azure Blob
     - Unstructured data (images, videos, backups)

  5. File Storage
     - NFS, EFS, shared file systems

  6. Block Storage
     - AWS EBS, SAN
     - Low-level storage for databases, VMs

  7. Data Warehouses / OLAP
     - Snowflake, BigQuery, Redshift, ClickHouse
     - Analytics queries on huge datasets

  8. Data Streams / Queues
     - Kafka, Kinesis, RabbitMQ, SQS
     - Event streaming and message passing

KEY TRADE-OFFS:
  Consistency vs Availability:
    SQL (ACID) → strong consistency but limited horizontal scale
    NoSQL (BASE) → eventual consistency but excellent horizontal scale

  Structure vs Flexibility:
    SQL → fixed schema, migrations needed for changes
    Document DB → flexible schema, easy iteration

  Query Power vs Scale:
    SQL → complex JOINs, aggregations, transactions
    NoSQL → simple queries, range scans, no JOINs

  Read vs Write Performance:
    B-tree indexes (SQL/MongoDB) → fast reads, slower writes
    LSM-tree (Cassandra, RocksDB) → fast writes, slower reads

DECISION GUIDE SUMMARY:
  Use SQL when:
    - Data has clear relationships (users, orders, products)
    - ACID transactions required (payments, banking)
    - Complex queries (JOINs, aggregations, GROUP BY)
    - Data is structured and schema is stable

  Use NoSQL when:
    - Very large scale (> 10TB, > 100K writes/sec)
    - Schema is flexible or frequently changing
    - Simple access patterns (key lookups, range scans)
    - Specific data model fits (document, graph, time-series)
    - Globally distributed data with tunable consistency
