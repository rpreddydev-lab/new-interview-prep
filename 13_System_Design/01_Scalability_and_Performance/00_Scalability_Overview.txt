================================================================
SCALABILITY AND PERFORMANCE — OVERVIEW
================================================================

WHAT IS SCALABILITY?
---------------------
Scalability is the capability of a system to handle a growing amount
of work by adding resources. A scalable system performs well under
increased load without requiring redesign.

Types of Scaling:
  - Scale Up (Vertical): Add more CPU/RAM/disk to existing machine
  - Scale Out (Horizontal): Add more machines to distribute load
  - Scale In: Remove resources when load decreases (auto-scaling)

WHAT IS PERFORMANCE?
---------------------
Performance describes how efficiently a system uses resources to
deliver results. Key metrics:

  Latency:    Time to complete a single request (ms, μs)
  Throughput: Number of requests processed per unit time (req/s, TPS)
  Bandwidth:  Amount of data transferred per unit time (MB/s, Gbps)
  Error Rate: Percentage of failed requests

LATENCY vs THROUGHPUT TRADE-OFF:
  - Low latency: process each request as fast as possible (real-time)
  - High throughput: maximize requests per second (batch processing)
  - Batching improves throughput but hurts latency
  - Parallelism can improve both but adds complexity

PERFORMANCE PERCENTILES:
  P50 (median):  50% of requests complete within this time
  P95:           95% complete within this time
  P99:           99% complete within this time
  P99.9:         99.9% complete within this time

  P99 is usually the most important for SLA guarantees.
  The tail (P99, P99.9) represents your worst-case user experience.
  A single slow component in a chain of 100 services raises the P99
  of the entire chain significantly (tail latency amplification).

TAIL LATENCY AMPLIFICATION:
  If each service has P99 = 1ms, and a request fans out to 100 services:
  Probability of hitting the tail = 1 - (0.99)^100 = 1 - 0.366 = 63.4%
  → Over 60% of requests will be slow!
  Solution: Hedged requests (send duplicate, take the faster response)

PERFORMANCE BOTTLENECKS:
  CPU bound:     Complex computation (encryption, serialization)
  Memory bound:  Working set larger than RAM
  I/O bound:     Waiting for disk or network
  Network bound: Saturated bandwidth or high RTT

SCALABILITY DIMENSIONS:
  1. Request Volume:    Handle more requests per second
  2. Data Volume:       Store and retrieve more data
  3. Concurrent Users:  More simultaneous connections
  4. Geographic Reach:  Serve users in more regions with low latency

SCALABILITY CHECKLIST:
  □ Stateless services (enables horizontal scaling)
  □ Load balancer in front of service tier
  □ Cache hot data (reduce DB reads)
  □ Async processing for non-critical writes
  □ Database sharding for write-heavy workloads
  □ Read replicas for read-heavy workloads
  □ CDN for static/media content
  □ Auto-scaling groups based on CPU/memory metrics
  □ Connection pooling to avoid DB connection exhaustion
  □ Rate limiting to protect services from overload
