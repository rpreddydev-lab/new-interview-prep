AWS STORAGE — GLACIER AND ARCHIVAL STORAGE
Complete Interview Preparation Guide
================================================================

1. S3 GLACIER OVERVIEW
================================================================

  Amazon S3 Glacier is the archival tier of S3 — designed for data that
  is rarely accessed and requires long-term retention (compliance,
  regulatory, historical archives).
  
  Key characteristics:
    - Extremely low cost (as low as $0.00099/GB/month for Deep Archive)
    - Higher retrieval latency (minutes to hours vs milliseconds)
    - Minimum storage duration charges (30, 90, or 180 days)
    - Integrated directly into S3 as storage classes

================================================================
2. S3 GLACIER STORAGE CLASSES
================================================================

  S3 GLACIER INSTANT RETRIEVAL
    - Retrieval: Milliseconds (same as Standard)
    - Min duration: 90 days
    - Cost: ~$0.004/GB/month
    - Min object size: 128KB
    - Use case: Medical images, news media, user-generated content
               Accessed ~once per quarter but needs instant retrieval

  S3 GLACIER FLEXIBLE RETRIEVAL (formerly just "S3 Glacier")
    - Retrieval options:
        Expedited:  1–5 minutes (costs extra, limited capacity)
        Standard:   3–5 hours  (default)
        Bulk:       5–12 hours (cheapest retrieval)
    - Min duration: 90 days
    - Cost: ~$0.0036/GB/month
    - Use case: Backup and recovery, disaster recovery, data that can
               wait a few hours when needed

  S3 GLACIER DEEP ARCHIVE
    - Retrieval options:
        Standard:  12 hours
        Bulk:      48 hours
    - Min duration: 180 days
    - Cost: ~$0.00099/GB/month (the cheapest)
    - Use case: Long-term data retention (7-10+ years), compliance archives
               (SEC 17a-4, HIPAA, CJIS), digital media preservation

  COMPARISON TABLE:
  ┌─────────────────────────┬──────────────┬──────────────────────────┬─────────────┬────────────────┐
  │ Feature                 │ Instant      │ Flexible                 │ Deep Archive│ Standard       │
  ├─────────────────────────┼──────────────┼──────────────────────────┼─────────────┼────────────────┤
  │ Retrieval Speed         │ ms           │ 1-5 min / 3-5 hr / 12 hr│ 12 / 48 hr  │ ms             │
  │ Min Storage Duration    │ 90 days      │ 90 days                  │ 180 days    │ None           │
  │ Cost (approx $/GB/mo)   │ $0.004       │ $0.0036                  │ $0.00099    │ $0.023         │
  │ Use Frequency           │ Quarterly    │ 1-2x/year                │ Rarely/never│ Frequent       │
  └─────────────────────────┴──────────────┴──────────────────────────┴─────────────┴────────────────┘

3. RESTORING OBJECTS FROM GLACIER
================================================================

  Objects in Glacier Flexible or Deep Archive are NOT directly accessible.
  You must first RESTORE them to a temporary S3 copy.

  RESTORE PROCESS:
    1. Initiate restore with desired retrieval tier and restore duration
    2. AWS retrieves the data (takes 1-5 min / 3-5 hrs / 5-12 hrs / 12 hrs)
    3. A temporary S3 Standard copy is created for the specified "days"
    4. Download from the temporary copy
    5. After the restore period, the temporary copy is deleted
    6. Original Glacier copy remains

  CLI restore:
  aws s3api restore-object \
    --bucket my-archive-bucket \
    --key "archives/2020/data.csv" \
    --restore-request '{"Days":5,"GlacierJobParameters":{"Tier":"Standard"}}'

  Check restore status:
  aws s3api head-object \
    --bucket my-archive-bucket \
    --key "archives/2020/data.csv"
  # Look for "Restore" field in response
  # ongoing-request="false" means restore is complete

  Java SDK v2 restore:
  import software.amazon.awssdk.services.s3.S3Client;
  import software.amazon.awssdk.services.s3.model.*;
  
  S3Client s3 = S3Client.create();
  
  RestoreRequest restoreRequest = RestoreRequest.builder()
      .days(5)
      .glacierJobParameters(
          GlacierJobParameters.builder().tier(Tier.STANDARD).build()
      )
      .build();
  
  s3.restoreObject(RestoreObjectRequest.builder()
      .bucket("my-archive-bucket")
      .key("archives/2020/data.csv")
      .restoreRequest(restoreRequest)
      .build());

  // Poll for completion:
  HeadObjectResponse headResponse = s3.headObject(
      HeadObjectRequest.builder().bucket("my-archive-bucket").key("archives/2020/data.csv").build()
  );
  String restore = headResponse.restore();
  // "ongoing-request=\"false\"" → restore complete
  // "ongoing-request=\"true\""  → still in progress

4. S3 GLACIER VAULT LOCK
================================================================

  Vault Lock Policy enforces WORM (Write Once, Read Many) compliance.
  Once locked, the policy CANNOT be changed or deleted.
  
  Use case: Regulatory compliance (SEC Rule 17a-4, FINRA, HIPAA)
  
  Vault Lock policy example (retain objects for 10 years):
  {
    "Version": "2012-10-17",
    "Statement": [{
      "Sid": "deny-based-on-archive-age",
      "Principal": "*",
      "Effect": "Deny",
      "Action": "glacier:DeleteArchive",
      "Resource": "arn:aws:glacier:us-east-1:123456789012:vaults/my-vault",
      "Condition": {
        "NumericLessThan": { "glacier:ArchiveAgeInDays": "3650" }
      }
    }]
  }

  For S3 buckets: Use S3 Object Lock instead (same concept but for S3):
  
  S3 OBJECT LOCK:
    Modes:
      GOVERNANCE mode: Users with special IAM permission can override/delete
      COMPLIANCE mode: Nobody (not even root) can delete until retention period ends
    
    Retention options:
      Retention Period: Objects protected until a specific date
      Legal Hold: Infinite protection until explicitly removed

  # Enable Object Lock when creating bucket (cannot enable after creation)
  aws s3api create-bucket \
    --bucket my-compliant-bucket \
    --region us-east-1 \
    --object-lock-enabled-for-bucket

  # Put a retention policy on an object
  aws s3api put-object-retention \
    --bucket my-compliant-bucket \
    --key "reports/2023/q4.csv" \
    --retention '{"Mode":"COMPLIANCE","RetainUntilDate":"2034-01-01T00:00:00"}'

5. S3 GLACIER SELECT
================================================================

  Query Glacier-archived data WITHOUT restoring the full object.
  Uses SQL expressions to retrieve only the data you need.
  Reduces retrieval cost and time.
  
  Supported formats: CSV, JSON, Parquet (Parquet only for Glacier Flexible)

  How it works:
    1. S3 reads the compressed/encrypted Glacier object
    2. Evaluates your SQL expression
    3. Returns only matching rows
    4. You pay only for data scanned, not entire object

  CLI example:
  aws s3api select-object-content \
    --bucket my-archive-bucket \
    --key "data/2020/sales.csv.gz" \
    --expression "SELECT s.product, s.revenue FROM S3Object s WHERE s.region = 'us-east'" \
    --expression-type SQL \
    --input-serialization '{"CSV":{"FileHeaderInfo":"USE"}, "CompressionType":"GZIP"}' \
    --output-serialization '{"CSV":{}}' \
    output.csv

  For S3 Standard objects: Use S3 Select (same concept, faster)

6. GLACIER PRICING BREAKDOWN
================================================================

  Storage:
    Glacier Flexible:     $0.0036/GB/month
    Deep Archive:         $0.00099/GB/month
  
  Retrieval (per GB):
    Glacier Flexible — Expedited:   $0.03
    Glacier Flexible — Standard:    $0.01
    Glacier Flexible — Bulk:        $0.0025
    Deep Archive — Standard:        $0.02
    Deep Archive — Bulk:            $0.0025
  
  Expedited Retrieval Capacity:
    Provisioned Capacity Units: $100/month for guaranteed expedited retrieval
    (without provisioned capacity, expedited may fail under high load)
  
  PUT/COPY requests:
    Into Glacier Flexible: $0.05/1,000 requests
    Into Deep Archive:     $0.05/1,000 requests
  
  Early deletion charges:
    Glacier Flexible:  90-day minimum; early deletion charged for remaining days
    Deep Archive:      180-day minimum; early deletion charged for remaining days

7. COMPLIANCE STANDARDS AND USE CASES
================================================================

  SEC Rule 17a-4:
    - Financial records must be kept in WORM format
    - S3 Object Lock (COMPLIANCE mode) + Glacier Deep Archive
  
  HIPAA:
    - Medical records 7–10 years retention
    - Encryption (SSE-KMS) + Object Lock + Glacier Deep Archive
  
  CJIS (Criminal Justice Information Services):
    - Law enforcement data, 5+ year retention
    - Strong encryption + audit logs + restricted access
  
  GDPR:
    - Right to erasure (be careful with Object Lock!)
    - Consider GOVERNANCE mode instead of COMPLIANCE for personal data
    - Can delete with special IAM permission in governance mode

8. LIFECYCLE AUTOMATION TO GLACIER
================================================================

  Common lifecycle pattern:
    Day 0:    Object uploaded → S3 Standard
    Day 30:   Transition to S3 Standard-IA
    Day 90:   Transition to S3 Glacier Flexible Retrieval
    Day 365:  Transition to S3 Glacier Deep Archive
    Day 2555: Expire (delete) — 7 years total

  Lifecycle rule JSON:
  {
    "Rules": [{
      "ID": "ArchiveOldLogs",
      "Status": "Enabled",
      "Prefix": "logs/",
      "Transitions": [
        { "Days": 30,  "StorageClass": "STANDARD_IA" },
        { "Days": 90,  "StorageClass": "GLACIER" },
        { "Days": 365, "StorageClass": "DEEP_ARCHIVE" }
      ],
      "Expiration": { "Days": 2555 }
    }]
  }

9. INTERVIEW QUESTIONS
================================================================

Q: What is the difference between S3 Glacier Flexible Retrieval and Deep Archive?
A: Both are archival storage tiers, but Deep Archive is cheaper ($0.00099 vs $0.0036/GB/month)
   and slower. Glacier Flexible: retrieval in 1–5 min (expedited), 3–5 hours (standard),
   or 5–12 hours (bulk). Deep Archive: retrieval in 12 hours (standard) or 48 hours (bulk).
   Minimum storage duration: 90 days for Flexible, 180 days for Deep Archive.
   Use Glacier Flexible for infrequent access with occasional quick retrieval need.
   Use Deep Archive for pure compliance/long-term retention where you rarely (if ever) need the data.

Q: What is S3 Object Lock and when should you use it?
A: S3 Object Lock prevents objects from being deleted or overwritten for a defined period
   (WORM — Write Once, Read Many). Two modes: GOVERNANCE mode allows users with special
   IAM permission to bypass; COMPLIANCE mode is absolute — no one can delete including root
   until the retention period expires. Use for regulatory compliance where you must prove
   data hasn't been tampered with: financial records (SEC 17a-4), medical records (HIPAA),
   legal records. Must be enabled at bucket creation — cannot be added afterward.

Q: What is the difference between restoring from Glacier and moving between storage classes?
A: Lifecycle transitions (moving between storage classes) are permanent and automatic via
   lifecycle rules. Restoring from Glacier is a TEMPORARY copy operation — you initiate
   a restore, wait for retrieval, and get a temporary Standard-class copy for N days.
   The original Glacier object is NOT deleted. After the restore duration, the temporary
   copy is deleted automatically. Restoration is needed when you need to access Glacier
   Flexible or Deep Archive objects that were stored there.

Q: How does the minimum storage duration work in Glacier?
A: AWS charges a minimum storage duration even if you delete the object early.
   If you store an object in Glacier Flexible (90-day minimum) and delete it on day 30,
   you still pay for the remaining 60 days. This is important when designing lifecycle
   policies — don't transition objects to Glacier if they're likely to be deleted soon
   (e.g., temp files should expire in Standard/IA, not be transitioned to Glacier).

Q: What is S3 Glacier Select and when would you use it?
A: Glacier Select lets you run SQL queries directly against archived data in Glacier
   without having to restore the entire object first. You pay only for data scanned.
   Use it when you have large CSV/JSON archives in Glacier and need to extract specific
   records (e.g., find all transactions for a specific customer from a 10GB archive without
   restoring and downloading the whole file). Significantly reduces retrieval cost and time.
