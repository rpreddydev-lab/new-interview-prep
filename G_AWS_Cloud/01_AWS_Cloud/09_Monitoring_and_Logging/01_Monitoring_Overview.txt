2. CLOUDWATCH CONTAINER INSIGHTS
================================================================

  Container Insights collects metrics and logs from:
    - ECS (Fargate and EC2 launch types)
    - EKS (Kubernetes)
    - On-premises Kubernetes
  
  Collected metrics:
    - CPU, memory, network, disk utilization per container/task/service
    - GPU metrics
    - Container failures, restarts
  
  Data stored in CloudWatch using Embedded Metric Format (EMF)
  in the namespace: ContainerInsights
  
  Enable on EKS:
  aws eks update-addon \
    --cluster-name my-cluster \
    --addon-name amazon-cloudwatch-observability

================================================================
3. CLOUDWATCH LAMBDA INSIGHTS
================================================================

  Enhanced monitoring for Lambda functions:
    - Cold start frequency and duration
    - Memory utilization
    - CPU time
    - Init duration
    - Concurrent executions per function
  
  Enable:
  aws lambda update-function-configuration \
    --function-name my-function \
    --layers arn:aws:lambda:us-east-1:580247275435:layer:LambdaInsightsExtension:21

4. AWS TRUSTED ADVISOR
================================================================

  Trusted Advisor provides real-time best practice recommendations 
  across 5 categories:
  
  CATEGORIES:
  ┌────────────────────────┬────────────────────────────────────────────┐
  │ Category               │ Example Checks                             │
  ├────────────────────────┼────────────────────────────────────────────┤
  │ Cost Optimization      │ Idle EC2 instances, unassociated Elastic   │
  │                        │ IPs, underutilized EBS volumes             │
  │                        │ Reserved Instance coverage                 │
  │ Performance            │ EC2 instance type check, CloudFront TTL,   │
  │                        │ EBS throughput, high-utilization instances │
  │ Security               │ Open security groups (0.0.0.0/0 on SSH),   │
  │                        │ root account MFA, S3 bucket permissions,   │
  │                        │ IAM access key rotation                    │
  │ Fault Tolerance        │ EBS snapshots age, RDS Multi-AZ enabled,   │
  │                        │ ELB health checks, Auto Scaling enabled    │
  │ Service Limits         │ Nearing EC2, VPC, S3 service quotas        │
  └────────────────────────┴────────────────────────────────────────────┘
  
  PLAN TIERS:
    - Basic/Developer: 7 core security checks (free)
    - Business/Enterprise: ALL checks + programmatic access + weekly auto-refresh
    - Only Business/Enterprise gets Service Limits and Priority checks

  CLI (Business/Enterprise only):
  aws support describe-trusted-advisor-checks --language en
  aws support describe-trusted-advisor-check-result --check-id <id>
  aws support refresh-trusted-advisor-check --check-id <id>

5. AWS HEALTH DASHBOARD
================================================================

  Two parts:
  
  SERVICE HEALTH:
    - Global view of AWS service availability across regions
    - Shows active, historical, and planned maintenance
    - No account required
    - URL: health.aws.amazon.com

  PERSONAL HEALTH DASHBOARD:
    - Events that affect YOUR specific account and resources
    - Alerts when AWS is replacing an EC2 host under you
    - Scheduled maintenance notifications
    - Operational issues affecting your running resources
  
  EVENTBRIDGE INTEGRATION:
  Subscribe to AWS Health events via EventBridge:
  {
    "source": ["aws.health"],
    "detail-type": ["AWS Health Event"],
    "detail": {
      "service": ["EC2"],
      "eventTypeCategory": ["scheduledChange"]
    }
  }
  
  Use cases:
    - Automatically migrate EC2 to a new host before forced maintenance
    - Page on-call when your RDS instance is affected by an AWS infrastructure issue
    - Notify team of upcoming reserved instance renewals

6. SERVICE QUOTAS
================================================================

  AWS limits the number of resources and API calls per account.
  
  CLI: check current limits and usage
  aws service-quotas list-service-quotas --service-code ec2
  
  Request increase:
  aws service-quotas request-service-quota-increase \
    --service-code ec2 \
    --quota-code L-1216C47A \
    --desired-value 100
  
  Important quotas to monitor:
    - EC2 vCPU limit per instance family (default 32-64 vCPUs)
    - Lambda concurrent executions (default 1,000 per account)
    - API Gateway requests per second (10,000 RPS default)
    - VPCs per region (default 5)
    - Elastic IPs per region (default 5)
  
  CloudWatch Alarm on quota usage (automatic):
  Trusted Advisor Service Limits check flags when usage > 80% of quota

8. INTERVIEW QUESTIONS
================================================================

Q: What does AWS Trusted Advisor check for in the security category?
A: Key security checks:
   1. Security Groups — Specific Ports Unrestricted: flags SGs with port 22 (SSH), 
      3389 (RDP), 1433 (MSSQL), etc. open to 0.0.0.0/0 (internet-wide)
   2. Amazon S3 Bucket Permissions: flags buckets with public access
   3. IAM Use: warns if root account is used and no IAM users created
   4. Root Account MFA: warns if root account has no MFA enabled
   5. IAM Access Key Rotation: warns about keys older than 90 days
   6. AWS CloudTrail Logging: warns if CloudTrail is disabled in any region
   7. Amazon EBS Public Snapshots: flags EBS snapshots marked as public
   8. Amazon RDS Public Snapshots: flags RDS snapshots marked as public
   These checks are available on the free/Basic tier (7 core security checks).

Q: How does the AWS Personal Health Dashboard differ from the Service Health Dashboard?
A: Service Health Dashboard (health.aws.amazon.com) shows the health of AWS services 
   globally — it's a public page showing if S3, EC2, or RDS is experiencing issues 
   in any region. It's not account-specific.
   
   Personal Health Dashboard shows events relevant to YOUR account and resources:
   - An EC2 host retirement affecting your specific instances
   - RDS maintenance windows for your databases
   - Lambda runtime deprecation notices for your functions
   - Storage optimization recommendations for your EBS volumes
   
   Subscribe to Personal Health Dashboard events via EventBridge (source: aws.health) 
   to automate responses — e.g., automatically reboot an EC2 instance when AWS schedules 
   mandatory host retirement, rather than waiting for AWS to do it (which could be sudden).

Q: A Lambda function is getting throttled at peak hours. How do you detect and fix this?
A: Detection: 
   1. CloudWatch metric: Lambda/Throttles — create alarm when Throttles > 0 for 5 minutes
   2. X-Ray: throttled invocations appear as errors with 429 status
   3. CloudWatch Logs Insights: query REPORT lines for errors
   4. Trusted Advisor: does NOT check Lambda concurrency specifically — manual monitoring needed
   
   Fix options:
   1. Request Lambda concurrent execution limit increase (default 1,000 per account)
      via AWS Service Quotas console
   2. Provision Concurrency: pre-allocate N concurrent executions for the function
      (eliminates cold starts and reserves capacity even during account-wide throttling)
   3. Queue requests via SQS: instead of direct invocation, push to SQS; Lambda 
      scales at its own pace from the queue, retrying automatically
   4. Split workload across multiple AWS accounts if hitting hard account limits
   5. Add exponential backoff with jitter on the calling side
