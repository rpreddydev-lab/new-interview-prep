AWS DEVELOPER TOOLS — AWS CDK (Cloud Development Kit)
Complete Interview Preparation Guide

1. CDK OVERVIEW
================================================================

  AWS CDK lets you define cloud infrastructure using familiar 
  programming languages:
    - TypeScript (most common)
    - Python
    - Java (for Java developers!)
    - C# / .NET
    - Go
  
  CDK synthesizes your code into CloudFormation templates.
  You get: IDE autocompletion, type safety, loops, conditionals, 
  abstractions, unit tests — things YAML/JSON templates lack.
  
  ┌────────────────────────────────────────────────────────────────┐
  │  CDK CODE (Java) → cdk synth → CloudFormation Template        │
  │                             → cdk deploy → AWS Resources      │
  └────────────────────────────────────────────────────────────────┘

================================================================
2. CDK CONSTRUCTS (L1, L2, L3)
================================================================

  L1 CONSTRUCTS (Cfn*):
    - Direct 1:1 mapping to CloudFormation resources
    - All properties must be specified (no defaults)
    - Example: CfnBucket, CfnInstance, CfnSecurityGroup
    - Use when: no L2 exists for a resource, or you need CloudFormation-level control
  
  L2 CONSTRUCTS (default):
    - Higher-level abstractions with sensible defaults
    - Add security/best-practice defaults automatically
    - Example: Bucket, Function, RestApi, Table, Vpc
    - Most commonly used
  
  L3 CONSTRUCTS (Patterns):
    - Complete patterns combining multiple resources
    - Example: ApplicationLoadBalancedFargateService (ALB + ECS + IAM + CloudWatch)
    - Encapsulates entire architectural patterns in a few lines
  
  EXAMPLE L1 vs L2:
  
  // L1 — verbose, must specify everything
  new s3.CfnBucket(this, "MyBucket", {
      bucketEncryption: {
          serverSideEncryptionConfiguration: [{
              serverSideEncryptionByDefault: {
                  sseAlgorithm: "AES256"
              }
          }]
      },
      versioningConfiguration: { status: "Enabled" }
  });
  
  // L2 — concise, secure defaults, type-safe
  new s3.Bucket(this, "MyBucket", {
      encryption: s3.BucketEncryption.S3_MANAGED,
      versioned: true,
      removalPolicy: cdk.RemovalPolicy.RETAIN
  });

3. JAVA CDK — PROJECT SETUP
================================================================

  BOOTSTRAP CDK (one-time per account/region):
  cdk bootstrap aws://123456789012/us-east-1
  
  CREATE NEW CDK PROJECT:
  mkdir my-cdk-app && cd my-cdk-app
  cdk init app --language java
  
  PROJECT STRUCTURE:
  my-cdk-app/
  ├── pom.xml
  ├── src/
  │   └── main/java/com/mycompany/
  │       ├── MyCdkAppApp.java     ← Entry point
  │       └── MyCdkAppStack.java   ← Stack definition
  └── cdk.json

4. JAVA CDK — BASIC STACK
================================================================

  // MyCdkAppStack.java
  import software.amazon.awscdk.*;
  import software.amazon.awscdk.services.s3.*;
  import software.amazon.awscdk.services.lambda.*;
  import software.amazon.awscdk.services.dynamodb.*;
  import software.constructs.Construct;
  
  public class MyCdkAppStack extends Stack {
  
      public MyCdkAppStack(final Construct scope, final String id) {
          this(scope, id, null);
      }
  
      public MyCdkAppStack(final Construct scope, final String id,
                           final StackProps props) {
          super(scope, id, props);
  
          // S3 Bucket
          Bucket bucket = Bucket.Builder.create(this, "MyBucket")
              .encryption(BucketEncryption.S3_MANAGED)
              .versioned(true)
              .removalPolicy(RemovalPolicy.RETAIN)
              .build();
  
          // DynamoDB Table
          Table table = Table.Builder.create(this, "OrdersTable")
              .partitionKey(Attribute.builder()
                  .name("orderId")
                  .type(AttributeType.STRING)
                  .build())
              .sortKey(Attribute.builder()
                  .name("createdAt")
                  .type(AttributeType.STRING)
                  .build())
              .billingMode(BillingMode.PAY_PER_REQUEST)
              .pointInTimeRecovery(true)
              .removalPolicy(RemovalPolicy.RETAIN)
              .build();
  
          // Lambda Function
          Function orderProcessor = Function.Builder.create(this, "OrderProcessor")
              .runtime(Runtime.JAVA_17)
              .code(Code.fromAsset("../order-processor/target/order-processor.jar"))
              .handler("com.myapp.OrderHandler::handleRequest")
              .memorySize(512)
              .timeout(Duration.seconds(30))
              .environment(Map.of(
                  "TABLE_NAME", table.getTableName(),
                  "BUCKET_NAME", bucket.getBucketName()
              ))
              .build();
  
          // Grant permissions
          table.grantReadWriteData(orderProcessor);
          bucket.grantRead(orderProcessor);
  
          // CloudFormation Output
          CfnOutput.Builder.create(this, "TableName")
              .value(table.getTableName())
              .exportName("OrdersTableName")
              .build();
      }
  }
  
  // Entry point: MyCdkAppApp.java
  public class MyCdkAppApp {
      public static void main(final String[] args) {
          App app = new App();
          new MyCdkAppStack(app, "MyCdkAppStack", StackProps.builder()
              .env(Environment.builder()
                  .account("123456789012")
                  .region("us-east-1")
                  .build())
              .build());
          app.synth();
      }
  }

5. CDK COMMANDS
================================================================

  cdk synth                # Generate CloudFormation template
  cdk diff                 # Preview changes vs deployed stack
  cdk deploy               # Deploy stack
  cdk deploy --hotswap     # Quick Lambda/ECS code update (skips CFN for speed)
  cdk destroy              # Delete stack
  cdk list                 # List all stacks
  cdk doctor               # Check CDK environment

6. CDK GRANT METHODS
================================================================

  CDK L2 constructs have built-in grant methods for IAM:
  
  // S3
  bucket.grantRead(lambdaFn);           // s3:GetObject, s3:ListBucket
  bucket.grantReadWrite(lambdaFn);      // read + s3:PutObject, s3:DeleteObject
  bucket.grantPut(lambdaFn);           // s3:PutObject only
  
  // DynamoDB
  table.grantReadData(lambdaFn);        // dynamodb:GetItem, Query, Scan
  table.grantReadWriteData(lambdaFn);   // read + PutItem, UpdateItem, DeleteItem
  
  // SQS
  queue.grantSendMessages(lambdaFn);    // sqs:SendMessage
  queue.grantConsumeMessages(lambdaFn); // sqs:ReceiveMessage, DeleteMessage
  
  // Secrets Manager
  secret.grantRead(lambdaFn);           // secretsmanager:GetSecretValue

7. CDK ASPECTS (CROSS-CUTTING CONCERNS)
================================================================

  Aspects apply logic to ALL resources in a scope:
  
  // Enforce tagging on all resources
  class TaggingAspect implements IAspect {
      public void visit(IConstruct node) {
          if (node instanceof CfnResource) {
              Tags.of(node).add("CostCenter", "engineering");
              Tags.of(node).add("ManagedBy", "cdk");
          }
      }
  }
  
  // Apply to entire stack
  Aspects.of(app).add(new TaggingAspect());

8. CDK vs CLOUDFORMATION vs TERRAFORM
================================================================

  ┌────────────────────┬──────────────┬──────────────────┬─────────────────┐
  │ Feature            │ CloudFormation│ CDK              │ Terraform       │
  ├────────────────────┼──────────────┼──────────────────┼─────────────────┤
  │ Language           │ YAML/JSON    │ Java/TS/Python   │ HCL             │
  │ Abstraction        │ Low (verbose)│ High (L2/L3)     │ Medium          │
  │ Type safety        │ No           │ Yes (IDE support) │ Limited         │
  │ Reuse (modules)    │ Nested stacks│ Constructs/Libs  │ Modules         │
  │ Testing            │ Limited      │ Full unit tests   │ Terratest       │
  │ Multi-cloud        │ AWS only     │ AWS only         │ Yes             │
  │ State management   │ AWS managed  │ AWS managed      │ Separate state  │
  │ Drift detection    │ Yes          │ Yes (via CFN)    │ Yes             │
  │ Change preview     │ Change Sets  │ cdk diff         │ terraform plan  │
  │ Learning curve     │ Medium       │ Low (if Java dev) │ Medium         │
  └────────────────────┴──────────────┴──────────────────┴─────────────────┘

9. INTERVIEW QUESTIONS
================================================================

Q: What are the advantages of CDK over raw CloudFormation templates?
A: CDK advantages for Java developers:
   1. Programming language: use Java with IDE autocompletion, type checking, 
      refactoring — catch errors at compile time, not deploy time
   2. Abstraction: L2 constructs have secure defaults (auto-encryption, IAM best 
      practices, no need to know all 50 CFN properties for a Lambda)
   3. Reuse: create your own Construct library — define a "StandardLambda" construct 
      that always adds X-Ray, logging, and standard alarms, and use it everywhere
   4. Logic: loops to create 10 identical Lambda functions, conditions for 
      environment-specific config, no template copy-pasting
   5. Testing: unit test infrastructure code with JUnit — verify the stack has 
      expected resources without deploying
   6. Grant methods: bucket.grantRead(fn) is much less error-prone than manually 
      writing IAM policy statements

Q: What is CDK Bootstrap and why is it needed?
A: CDK Bootstrap creates resources in your AWS account that CDK needs to deploy:
   - An S3 bucket: stores CloudFormation templates and Lambda code assets
   - ECR repository: stores Docker image assets (for CDK apps with container images)
   - IAM roles: CDK deploy and execution roles with appropriate permissions
   - SSM parameter: stores CDK bootstrap version number
   
   Run once per account/region: cdk bootstrap aws://accountId/region
   Without bootstrapping, cdk deploy fails because there's no S3 bucket to upload 
   your assets to.

Q: How do you test CDK stacks without deploying to AWS?
A: Use CDK's built-in testing utilities with JUnit:
   1. Template assertions (CDK assertions module):
      Template template = Template.fromStack(new MyCdkAppStack(app, "TestStack"));
      template.hasResourceProperties("AWS::S3::Bucket", Map.of(
          "VersioningConfiguration", Map.of("Status", "Enabled")
      ));
      template.resourceCountIs("AWS::Lambda::Function", 1);
   
   2. This generates and inspects the CloudFormation template in memory — fast, 
      no AWS credentials needed, runs in CI/CD
   3. Test that security properties are correct (encryption, versioning, retention)
   4. Test that IAM permissions are as expected
   5. Use fine-grained assertions to check resource counts, properties, and outputs
