================================================================
AWS SECURITY — WAF & SHIELD
Complete Interview Preparation Guide
================================================================

1. AWS WAF OVERVIEW
================================================================

  AWS Web Application Firewall (WAF) protects web applications 
  from common exploits — SQL injection, XSS, bad bots, etc.
  
  WAF operates at Layer 7 (application layer).
  
  INTEGRATION POINTS:
    - CloudFront (global edge)
    - Application Load Balancer (regional)
    - API Gateway (regional)
    - AppSync (GraphQL)
    - Amazon Cognito User Pool

================================================================
2. WAF KEY CONCEPTS
================================================================

  WEB ACL (Access Control List):
    - Container for rules
    - Associated with a CloudFront distribution / ALB / API GW
    - Default action: ALLOW or BLOCK
    - Capacity: 1,500 WCUs (Web ACL Capacity Units)
  
  RULES (evaluated in priority order):
    - Rule Type: Regular Rule or Rate-Based Rule
    - Action: ALLOW, BLOCK, COUNT (monitor without blocking), or CAPTCHA
    - If no rule matches → Default action
  
  RULE GROUPS:
    - Reusable collection of rules
    - Managed Rule Groups (AWS managed, auto-updated): free or paid
    - Custom Rule Groups: you define

================================================================
3. WAF RULE TYPES
================================================================

  IP SET RULE:
    - Match specific IP addresses or CIDR ranges
    - Block known malicious IPs, allow only corporate IPs
  
  GEO MATCH RULE:
    - Match requests from specific countries
    - Block requests from countries you don't serve
  
  SQL INJECTION RULE (Managed):
    - AWSManagedRulesCommonRuleSet includes SQL injection protection
  
  XSS RULE (Managed):
    - AWSManagedRulesKnownBadInputsRuleSet
  
  RATE-BASED RULE:
    - Limit requests from a single IP within 5-minute window
    - Minimum: 100 requests per 5 minutes
    - Protect against brute force, credential stuffing, scraping
    - Auto-blocks IP when threshold exceeded, auto-unblocks when it drops
  
  STRING MATCH RULE:
    - Match on: URI, query string, headers, body, HTTP method
    - Match types: exact, starts with, ends with, contains, regex
  
  SIZE CONSTRAINT RULE:
    - Block requests with body > N bytes (e.g., block oversized payloads)

================================================================
4. MANAGED RULE GROUPS
================================================================

  AWS FREE Managed Rules:
    - AWSManagedRulesCommonRuleSet  — OWASP Top 10 protections (XSS, SQLi, LFI)
    - AWSManagedRulesKnownBadInputsRuleSet — known bad patterns
    - AWSManagedRulesAmazonIpReputationList — AWS-tracked malicious IPs
    - AWSManagedRulesAnonymousIpList — VPNs, Tor exit nodes, proxies
    - AWSManagedRulesLinuxRuleSet — Linux-specific attacks
    - AWSManagedRulesSQLiRuleSet — SQL injection
    - AWSManagedRulesBotControlRuleSet — bot management (additional cost)
    - AWSManagedRulesFraudControlAccountTakeoverPrevention (additional cost)
  
  Marketplace Rule Groups:
    - Third-party providers (Imperva, F5, Fortinet, etc.)

================================================================
5. WAF CLI EXAMPLES
================================================================

  CREATE WEB ACL:
  aws wafv2 create-web-acl \
    --name "MyWebACL" \
    --scope REGIONAL \
    --default-action Allow={} \
    --rules '[
      {
        "Name": "RateLimitRule",
        "Priority": 1,
        "Statement": {
          "RateBasedStatement": {
            "Limit": 2000,
            "AggregateKeyType": "IP"
          }
        },
        "Action": {"Block": {}},
        "VisibilityConfig": {
          "SampledRequestsEnabled": true,
          "CloudWatchMetricsEnabled": true,
          "MetricName": "RateLimitRule"
        }
      }
    ]' \
    --visibility-config SampledRequestsEnabled=true,CloudWatchMetricsEnabled=true,MetricName=MyWebACL \
    --region us-east-1
  
  CREATE IP SET (block list):
  aws wafv2 create-ip-set \
    --name "BlockedIPs" \
    --scope REGIONAL \
    --ip-address-version IPV4 \
    --addresses "203.0.113.0/24" "198.51.100.0/24"
  
  ASSOCIATE WAF WITH ALB:
  aws wafv2 associate-web-acl \
    --web-acl-arn arn:aws:wafv2:us-east-1:123456789012:regional/webacl/MyWebACL/abc123 \
    --resource-arn arn:aws:elasticloadbalancing:us-east-1:123456789012:loadbalancer/app/my-alb/abc123

6. AWS SHIELD
================================================================

  AWS Shield provides DDoS (Distributed Denial of Service) protection.

  │ Shield Standard     │ Shield Advanced                            │
  ├─────────────────────┼────────────────────────────────────────────┤
  │ Free, automatic     │ $3,000/month per organization              │
  │ Always on           │ Optional, opt-in                           │

  │ L3/L4 attacks       │ • L7 DDoS with WAF                         │
  │ (SYN flood, UDP     │ • DDoS Response Team (DRT) support         │
  │  reflection)        │ • Cost protection (service credits for     │
  │ Included with       │   scaling charges during DDoS)             │
  │ CloudFront, Route53 │ • Real-time attack visibility              │
  │                     │ • Advanced metrics in CloudWatch           │
  │                     │ • Proactive engagement                     │
  └─────────────────────┴────────────────────────────────────────────┘
  
  PROTECTED RESOURCES (Advanced):
    - CloudFront distributions
    - Route 53 hosted zones
    - Global Accelerator endpoints
    - ALBs, CLBs, Elastic IPs (EC2 NLB, EIP)
  
  SHIELD ADVANCED + WAF:
    - For L7 DDoS, Shield Advanced works WITH WAF
    - DRT can write WAF rules on your behalf during an attack

7. AWS FIREWALL MANAGER
================================================================

  Centrally manage WAF rules, Shield Advanced, and Security Groups 
  across multiple accounts and resources in AWS Organizations.
  
  Use case:
    - One security team manages WAF policies for all accounts
    - Automatically applies WAF rules to new ALBs/CloudFront dists
    - Ensures all accounts have Shield Advanced enabled
    - Remediates non-compliant security groups across the org
  
  Requires: AWS Organizations + Firewall Manager Admin Account

8. INTERVIEW QUESTIONS
================================================================

Q: A sudden spike of requests is overloading your API Gateway. How do you protect it?
A: Multi-layer approach:
   1. API Gateway throttling: Built-in 10,000 RPS account limit, set per-stage or 
      per-method throttling (UsagePlan + API Key or default throttle settings).
   2. WAF Rate-based rule: Associate WAF Web ACL with API Gateway, add a rate-based 
      rule (e.g., 2,000 requests/5 min per IP). IPs exceeding threshold are blocked.
   3. WAF Managed Rules: Add AWSManagedRulesAmazonIpReputationList to block known 
      malicious IPs at the edge.
   4. CloudFront in front of API Gateway: absorbs traffic spikes at edge locations, 
      WAF on CloudFront with rate limiting blocks before requests reach API Gateway.
   5. Shield Advanced: if this is a sustained DDoS attack, Shield Advanced + DRT 
      assistance provides additional protection and cost coverage.

Q: What is the difference between AWS WAF and AWS Shield?
A: WAF is an application firewall (Layer 7) — you write rules to inspect HTTP requests 
   and block based on patterns (SQL injection, XSS, geo, IP, rate limiting). WAF requires 
   configuration; it won't do anything without rules.
   
   Shield is a DDoS protection service. Shield Standard (free) automatically protects 
   against L3/L4 volumetric attacks (SYN floods, UDP reflection) for all AWS customers. 
   Shield Advanced ($3K/month) extends to L7 DDoS (coordinated with WAF), provides 
   DRT support, and reimburses scaling costs during attacks. 
   
   They complement each other: Shield handles volumetric attacks; WAF handles 
   application-layer attacks. For full protection, deploy both on CloudFront.

Q: How would you allow only corporate IPs to access an internal ALB and block everything else?
A: Two options:
   1. Security Group on ALB: Allow inbound HTTPS (443) from corporate IP ranges only. 
      This is network-level (L4), simple, no cost beyond normal SG limits.
   2. WAF on ALB: Create an IP Set with corporate CIDRs. Create a WAF rule to ALLOW 
      matching IPs. Set Web ACL default action to BLOCK. This handles L7 inspection 
      and can log blocked requests.
   For pure IP allowlisting, Security Groups are simpler and more cost-effective. 
   Use WAF when you also need L7 inspection, logging, or more complex rules (combine 
   IP + rate limiting + managed rules).
