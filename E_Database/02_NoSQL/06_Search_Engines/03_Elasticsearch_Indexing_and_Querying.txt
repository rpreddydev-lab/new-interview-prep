  ELASTICSEARCH INDEXING AND QUERYING
================================================================

================================================================
INDEXING DOCUMENTS
================================================================

  Create / replace (by ID):
  PUT /products/_doc/42
  { "name": "Laptop", "price": 999.99, "category": "electronics" }

  Create only (fail if ID exists):
  PUT /products/_create/42
  { "name": "Laptop", ... }

  Auto-generate ID:
  POST /products/_doc
  { "name": "Laptop", ... }

  Update specific fields:
  POST /products/_update/42
  { "doc": { "price": 899.99 } }

  Delete:
  DELETE /products/_doc/42

  Bulk API (efficient for large inserts):
  POST /_bulk
  { "index": { "_index": "products", "_id": "1" } }
  { "name": "Laptop", "price": 999.99 }
  { "index": { "_index": "products", "_id": "2" } }
  { "name": "Mouse", "price": 29.99 }

================================================================
QUERY DSL
================================================================

  GET /products/_search
  {
    "query": { ... },
    "sort": [ ... ],
    "from": 0,
    "size": 10,
    "aggs": { ... }
  }

================================================================
FULL-TEXT QUERIES
================================================================

  -- match: standard full-text search
  {
    "query": {
      "match": {
        "name": "wireless bluetooth headphones"
      }
    }
  }

  -- match_phrase: must be in order
  {
    "query": {
      "match_phrase": { "description": "noise cancelling" }
    }
  }

  -- multi_match: search across multiple fields
  {
    "query": {
      "multi_match": {
        "query": "wireless headphones",
        "fields": ["name^3", "description", "tags"]
      }
    }
  }
  -- ^3 means name field has 3x boost in relevance score

  -- fuzzy: typo tolerance
  {
    "query": {
      "fuzzy": { "name": { "value": "headphonse", "fuzziness": "AUTO" } }
    }
  }

================================================================
TERM-LEVEL QUERIES (EXACT MATCH, NO ANALYSIS)
================================================================

  -- term: exact keyword match
  { "query": { "term": { "category": "electronics" } } }

  -- terms: in list
  { "query": { "terms": { "category": ["electronics", "computers"] } } }

  -- range:
  { "query": { "range": { "price": { "gte": 50, "lte": 200 } } } }

  -- exists: field has a value
  { "query": { "exists": { "field": "discount_price" } } }

================================================================
BOOL QUERY -- COMBINING CONDITIONS
================================================================

  "must"    --> ALL must match (AND, affects score)
  "should"  --> AT LEAST ONE should match (OR, affects score)
  "must_not"--> NONE must match (NOT, does not affect score)
  "filter"  --> MUST match (AND, NO score effect, cached)

  Example: electronics under $200 that match "wireless":

  {
    "query": {
      "bool": {
        "must":    [ { "match": { "name": "wireless" } } ],
        "filter":  [
          { "term":  { "category": "electronics" } },
          { "range": { "price": { "lte": 200 } } }
        ],
        "must_not": [ { "term": { "in_stock": false } } ]
      }
    }
  }

  Use "filter" for non-scoring conditions (faster, cacheable).
  Use "must" when relevance score matters.

================================================================
AGGREGATIONS
================================================================

  -- Faceted search: count by category
  {
    "aggs": {
      "by_category": {
        "terms": { "field": "category", "size": 10 }
      }
    }
  }

  -- Average price per category:
  {
    "aggs": {
      "by_category": {
        "terms": { "field": "category" },
        "aggs": {
          "avg_price": { "avg": { "field": "price" } }
        }
      }
    }
  }

  -- Histogram: price distribution
  {
    "aggs": {
      "price_buckets": {
        "histogram": { "field": "price", "interval": 100 }
      }
    }
  }

================================================================
PAGINATION
================================================================

  From/Size (shallow pagination, max 10,000):
  { "from": 0, "size": 10 }
  { "from": 10, "size": 10 }

  Search After (deep pagination, uses sort values as cursor):
  {
    "sort": [ { "price": "asc" }, { "_id": "asc" } ],
    "search_after": [499.99, "42"],
    "size": 10
  }

  Scroll API (deprecated for deep pagination; use search_after instead).

================================================================
INTERVIEW Q&A
================================================================

  Q: What is the difference between must and filter in a bool query?
  A: "must": conditions MUST match and they contribute to the relevance score.
     "filter": conditions MUST match but do NOT affect the score.
     Filter clauses are cached for better performance.
     Use filter for exact matches (category, date ranges); must for text queries.

  Q: What is the difference between match and term queries?
  A: "match" is for analyzed text fields -- query is analyzed before searching.
     "term" is for keyword fields -- exact match, no analysis.
     Using term on a text field often returns no results because the field
     was indexed in lowercase, but term query is case-sensitive.

  Q: How do you implement faceted search in Elasticsearch?
  A: Use aggregations: "terms" aggregation on keyword fields gives counts
     per distinct value. Combine with bool filter to apply selected facets.
     Returns both filtered results and updated facet counts in one request.
