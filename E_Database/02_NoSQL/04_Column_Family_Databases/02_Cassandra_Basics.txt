================================================================
  APACHE CASSANDRA BASICS
================================================================

  Cassandra is a distributed, masterless NoSQL database.
  No single point of failure.
  Designed for high availability and linear horizontal scaling.

================================================================
ARCHITECTURE
================================================================

  Ring Topology:
  - All nodes are equal (no master/slave)
  - Data is distributed across nodes using consistent hashing
  - Each node owns a range of hash tokens
  - Replication factor (RF) controls how many copies per data item

  Virtual Nodes (vnodes):
  - Each physical node manages multiple token ranges
  - Enables better load balancing

  Replication Factor:
  - RF=3 means 3 copies of each row on 3 different nodes
  - Recommended RF=3 in production

  Coordinator:
  - Any node can receive a client request
  - That node acts as coordinator, routes to appropriate nodes

================================================================
KEYSPACE AND TABLE
================================================================

  Keyspace   = database in Cassandra. Contains tables.
               Defines replication strategy.

  CREATE KEYSPACE myapp
  WITH REPLICATION = {
      'class': 'NetworkTopologyStrategy',
      'dc1': 3
  };

  USE myapp;

  CREATE TABLE user_events (
      user_id   UUID,
      event_ts  TIMESTAMP,
      event_type TEXT,
      details   MAP<TEXT, TEXT>,
      PRIMARY KEY ((user_id), event_ts)
  ) WITH CLUSTERING ORDER BY (event_ts DESC);

================================================================
CQL -- CASSANDRA QUERY LANGUAGE
================================================================

  Similar to SQL but with important restrictions:
  - No JOINs
  - No subqueries
  - Filtering by non-primary-key column requires ALLOW FILTERING (avoid)
  - ORDER BY only allowed on clustering columns within a partition

  Basic CQL:

  INSERT INTO user_events (user_id, event_ts, event_type)
  VALUES (uuid(), toTimestamp(now()), 'PURCHASE');

  SELECT * FROM user_events WHERE user_id = ? ORDER BY event_ts DESC LIMIT 10;

  UPDATE user_events SET details = {'amount': '99.99'}
  WHERE user_id = ? AND event_ts = ?;

  DELETE FROM user_events WHERE user_id = ? AND event_ts = ?;

================================================================
TUNABLE CONSISTENCY
================================================================

  Cassandra allows you to set consistency per operation:

  Level         Behavior
  -----------   ---------------------------------------------------------
  ONE           1 replica must respond (fastest, least consistent)
  TWO           2 replicas must respond
  THREE         3 replicas must respond
  QUORUM        Majority: (RF/2)+1 replicas must respond
  ALL           All replicas must respond (slowest, most consistent)
  LOCAL_QUORUM  Quorum within local datacenter only
  LOCAL_ONE     Only 1 replica in local DC

  Read repair: if replicas disagree, Cassandra updates stale ones.

  QUORUM + QUORUM with RF=3:
  (3/2)+1 = 2 replicas on write, 2 on read.
  Overlapping quorums guarantee you always read the latest write.

SPRING DATA CASSANDRA
================================================================

  <!-- Maven -->
  <dependency>
      <groupId>org.springframework.boot</groupId>
      <artifactId>spring-boot-starter-data-cassandra</artifactId>
  </dependency>

  # application.properties
  spring.cassandra.keyspace-name=myapp
  spring.cassandra.contact-points=localhost
  spring.cassandra.port=9042

  @Table("user_events")
  public class UserEvent {
      @PrimaryKeyColumn(name="user_id", type=PARTITIONED)
      private UUID userId;
      @PrimaryKeyColumn(name="event_ts", type=CLUSTERED, ordering=DESCENDING)
      private Instant eventTs;
      private String eventType;
  }

  public interface UserEventRepository extends CassandraRepository<UserEvent, UUID> {
      List<UserEvent> findByUserId(UUID userId);
  }

================================================================
INTERVIEW Q&A
================================================================

  Q: What makes Cassandra masterless?
  A: All nodes are equal peers. Any node can accept reads or writes.
     A coordinator node routes requests to the appropriate replica nodes.
     No single point of failure -- if any node goes down, others continue.

  Q: What is a replication factor in Cassandra?
  A: The number of copies of each row stored across different nodes.
     RF=3 means 3 nodes hold each row. If one node fails,
     the other two still have the data.

  Q: What is tunable consistency in Cassandra?
  A: The ability to set the consistency level per read or write operation.
     ONE = fastest, least durable.
     QUORUM = balanced (majority must agree).
     ALL = strongest consistency, requires all replicas to respond.
