================================================================
  LEAD AND LAG
================================================================

  LAG  accesses a value from a PREVIOUS row in the window.
  LEAD accesses a value from a FUTURE row in the window.
  Neither requires a self-join.

================================================================
SYNTAX
================================================================

  LAG (col [, offset [, default]])  OVER (PARTITION BY ... ORDER BY ...)
  LEAD(col [, offset [, default]])  OVER (PARTITION BY ... ORDER BY ...)

  offset:  number of rows back (LAG) or forward (LEAD). Default = 1.
  default: value to return when no such row exists (first/last rows). Default = NULL.

================================================================
EXAMPLES
================================================================

  Day-over-day revenue change:
  SELECT
      date,
      revenue,
      LAG(revenue, 1, 0) OVER (ORDER BY date) AS prev_day_revenue,
      revenue - LAG(revenue, 1, 0) OVER (ORDER BY date) AS daily_change
  FROM daily_sales;

  Result:
  date        revenue  prev_day_revenue  daily_change
  ----------  -------  ----------------  ------------
  2024-01-01  1000     0                 1000
  2024-01-02  1200     1000              200
  2024-01-03  1100     1200              -100

================================================================
LEAD: NEXT ORDER DATE PER CUSTOMER
================================================================

  SELECT
      customer_id,
      order_date,
      LEAD(order_date) OVER (PARTITION BY customer_id ORDER BY order_date) AS next_order_date,
      LEAD(order_date) OVER (PARTITION BY customer_id ORDER BY order_date) - order_date AS days_between
  FROM orders;

================================================================
COMPARE CURRENT TO PREVIOUS IN SAME GROUP
================================================================

  Month-over-month growth per product:
  SELECT
      product_id,
      month,
      revenue,
      LAG(revenue) OVER (PARTITION BY product_id ORDER BY month) AS prev_month,
      ROUND(
          (revenue - LAG(revenue) OVER (PARTITION BY product_id ORDER BY month))
          / NULLIF(LAG(revenue) OVER (PARTITION BY product_id ORDER BY month), 0) * 100,
          2
      ) AS growth_pct
  FROM monthly_product_revenue;

================================================================
FIND GAPS IN SEQUENCES
================================================================

  Find orders where next order was more than 30 days later:
  WITH gaps AS (
      SELECT
          customer_id,
          order_date,
          LEAD(order_date) OVER (PARTITION BY customer_id ORDER BY order_date) AS next_date
      FROM orders
  )
  SELECT customer_id, order_date, next_date,
         next_date - order_date AS gap_days
  FROM gaps
  WHERE next_date - order_date > 30;

================================================================
INTERVIEW Q&A
================================================================

  Q: What is the difference between LAG and LEAD?
  A: LAG looks at the previous row (negative offset in time/order).
     LEAD looks at the next row (positive offset in time/order).
     Both require ORDER BY in the OVER clause to define previous/next.

  Q: What happens when LAG/LEAD goes beyond the partition boundary?
  A: Returns NULL by default (or the third argument if provided).
     E.g., LAG for the first row returns NULL (no previous row exists).

  Q: How would you compute month-over-month change without a self-join?
  A: Use LAG(revenue) OVER (PARTITION BY product ORDER BY month)
     to get previous month's value on the same row as current month.
