================================================================
  ROLLBACK
================================================================

  ROLLBACK undoes all changes made since the last BEGIN
  (or since the last SAVEPOINT if rolling back to a savepoint).

================================================================
SYNTAX
================================================================

  ROLLBACK;                   -- undo entire transaction
  ROLLBACK TO SAVEPOINT name; -- undo only to the named checkpoint

================================================================
WHAT HAPPENS DURING ROLLBACK
================================================================

  1. All uncommitted changes are reversed (using undo log / MVCC)
  2. Row/table locks are released
  3. Transaction is placed in ABORTED state
  4. Database returns to pre-transaction consistent state

================================================================
EXAMPLES
================================================================

  Explicit rollback on error:
  BEGIN;
    UPDATE accounts SET balance = balance - 500 WHERE id = 1;
    -- imagine application detects account is frozen
    ROLLBACK;   -- debit is undone

  In a stored procedure (PostgreSQL exception block):
  DO $$
  BEGIN
      UPDATE accounts SET balance = balance - 500 WHERE id = 1;
      UPDATE accounts SET balance = balance + 500 WHERE id = 2;
      -- if any error above, EXCEPTION block fires
  EXCEPTION
      WHEN OTHERS THEN
          RAISE NOTICE 'Transfer failed, rolling back';
          ROLLBACK;
  END;
  $$;

================================================================
ROLLBACK IN JDBC
================================================================

  try {
      conn.setAutoCommit(false);
      stmt1.executeUpdate("UPDATE ...");
      stmt2.executeUpdate("UPDATE ...");
      conn.commit();
  } catch (SQLException e) {
      conn.rollback();    // undo both updates
      throw e;
  }

================================================================
SPRING @TRANSACTIONAL ROLLBACK RULES
================================================================

  By default: rollback on RuntimeException and Error only.
  DOES NOT rollback on checked exceptions unless configured.

  @Transactional(rollbackFor = Exception.class)
  public void process() throws Exception { ... }

  No rollback for specific exception:
  @Transactional(noRollbackFor = BusinessValidationException.class)

  Common mistake: calling @Transactional method from same class
  bypasses Spring proxy -- no transaction, no rollback.

================================================================
PARTIAL ROLLBACK WITH SAVEPOINT
================================================================

  BEGIN;
    INSERT INTO orders ...        -- step 1
    SAVEPOINT after_order;
    INSERT INTO order_items ...   -- step 2
    ROLLBACK TO SAVEPOINT after_order;  -- undo step 2 only
    -- step 1 (INSERT orders) is still pending
    -- can retry step 2 with corrected data
  COMMIT;    -- commits step 1 only (or retried step 2)

================================================================
AUTOMATIC ROLLBACK SCENARIOS
================================================================

  Server crash         Transaction automatically rolled back on restart
  Client disconnects   Session-level transaction rolled back
  Statement error      In PostgreSQL, transaction is marked as aborted
                       (must ROLLBACK before any new statements)
  Deadlock detected    Database rolls back one of the deadlocked transactions

================================================================
INTERVIEW Q&A
================================================================

  Q: Can you partially rollback a transaction?
  A: Yes, using SAVEPOINT and ROLLBACK TO SAVEPOINT. This undoes
     statements after the savepoint while preserving earlier changes.

  Q: When does Spring automatically roll back a transaction?
  A: On unchecked exceptions (RuntimeException and Error) by default.
     For checked exceptions, you must specify rollbackFor = Exception.class.

  Q: What happens to a transaction when the JVM crashes?
  A: Uncommitted transactions are automatically rolled back when
     the database detects the connection was lost (on server restart,
     incomplete transactions in the WAL are discarded/undone).

  Q: What is a deadlock and how does the DB handle it?
  A: Two transactions each hold a lock the other needs, so both wait
     forever. The database detects the cycle and automatically rolls back
     one transaction (usually the one with less work done).
