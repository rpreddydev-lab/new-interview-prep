================================================================
  NULL HANDLING: COALESCE, NULLIF, IS NULL
================================================================

  NULL means "unknown" or "missing". It is NOT zero, NOT empty string.
  NULL infects every expression it touches -- any arithmetic or
  comparison with NULL returns NULL (not true, not false).

================================================================
THE THREE-VALUED LOGIC
================================================================

  SQL uses three-valued logic: TRUE, FALSE, UNKNOWN.
  NULL = NULL  --> UNKNOWN (not TRUE!)
  NULL <> NULL --> UNKNOWN
  1 + NULL     --> NULL
  CONCAT('a', NULL) --> NULL  (in most databases)

  That is why:
  WHERE id = NULL   -- returns no rows (always false)
  WHERE id IS NULL  -- correct way to check for NULL

================================================================
IS NULL / IS NOT NULL
================================================================

  SELECT * FROM customers WHERE phone IS NULL;
  SELECT * FROM customers WHERE phone IS NOT NULL;

  -- Wrong (never matches):
  SELECT * FROM customers WHERE phone = NULL;

================================================================
COALESCE
================================================================

  Returns the first non-NULL value in the list.
  Short-circuits: stops evaluating once non-NULL found.

  COALESCE(col1, col2, col3, 'default')

  Examples:
  SELECT
      COALESCE(display_name, username, email, 'Anonymous') AS name
  FROM users;

  Replace NULL with 0 in arithmetic:
  SELECT total - COALESCE(discount, 0) AS final_price FROM orders;

  Equivalent CASE form:
  CASE WHEN col IS NOT NULL THEN col ELSE 'default' END

================================================================
NULLIF
================================================================

  NULLIF(expr1, expr2)
  Returns NULL if expr1 = expr2, otherwise returns expr1.
  Useful to avoid division-by-zero:

  SELECT revenue / NULLIF(units, 0) AS avg_price FROM sales;
  -- If units = 0, NULLIF returns NULL --> NULL / anything = NULL, no error

  Remove empty strings:
  SELECT COALESCE(NULLIF(TRIM(phone), ''), 'N/A') AS phone FROM customers;
  -- '' becomes NULL, then COALESCE catches it with 'N/A'

================================================================
NVL / ISNULL / IFNULL (Database-Specific)
================================================================

  Oracle:        NVL(col, default)          -- 2 args only
  SQL Server:    ISNULL(col, default)        -- 2 args only
  MySQL:         IFNULL(col, default)        -- 2 args only
  PostgreSQL:    COALESCE(col, default)      -- standard, any number of args

  COALESCE is ANSI standard -- prefer it for portability.

================================================================
NULL IN AGGREGATES
================================================================

  Aggregate functions IGNORE NULL values:
  SUM(col)   -- ignores NULLs, returns NULL if all rows are NULL
  AVG(col)   -- ignores NULLs (denominator = non-NULL count, not total count)
  COUNT(col) -- ignores NULLs
  COUNT(*)   -- counts ALL rows including NULLs

  Table: values (1, 2, NULL, 4)
  SUM    --> 7     (not 7)
  AVG    --> 2.33  (3 non-NULL values: 7/3, not 7/4)
  COUNT(col) --> 3
  COUNT(*) --> 4

  Trap: AVG with NULLs may give inflated averages:
  AVG(COALESCE(rating, 0))  -- treats no-rating as 0 star

================================================================
NULL IN JOINS
================================================================

  NULL FK values do NOT match in INNER JOIN -- those rows are excluded.
  Only LEFT JOIN preserves rows where FK is NULL.

  SELECT c.name, o.id
  FROM customers c
  LEFT JOIN orders o ON c.id = o.customer_id
  WHERE o.id IS NULL;   -- customers with no orders

================================================================
NULL IN ORDER BY
================================================================

  By default:
  PostgreSQL: NULLs sort LAST for ASC, FIRST for DESC
  MySQL/SQL Server: NULLs sort first (smallest)

  Control explicitly:
  ORDER BY col ASC NULLS LAST
  ORDER BY col DESC NULLS FIRST

================================================================
NULL IN UNIQUE CONSTRAINTS
================================================================

  ANSI SQL: NULL is not equal to NULL, so multiple NULL values
  are allowed in a UNIQUE column.
  Exception: SQL Server allows only one NULL in a unique index.

================================================================
INTERVIEW Q&A
================================================================

  Q: What does NULL mean in SQL?
  A: Unknown or absent value. Not zero, not empty string.
     Any comparison or arithmetic with NULL returns NULL (UNKNOWN),
     which is why = NULL never works -- use IS NULL.

  Q: What is the difference between COALESCE and NULLIF?
  A: COALESCE returns the first non-NULL from a list of values.
     NULLIF returns NULL when two values are equal, otherwise first value.
     Often combined: COALESCE(NULLIF(col, ''), 'default')
     to treat empty string same as NULL.

  Q: How do aggregate functions handle NULL?
  A: They ignore NULLs. COUNT(*) counts all rows; COUNT(col) skips NULLs.
     AVG denominator = count of non-NULL rows, which can inflate the average.

  Q: Why does NOT IN return no rows when the subquery contains NULL?
  A: NOT IN is internally expanded to col <> v1 AND col <> v2 ... AND col <> NULL.
     col <> NULL is UNKNOWN, so the whole AND chain is UNKNOWN.
     Use NOT EXISTS instead when subquery may return NULLs.

  Q: Can a column with a UNIQUE constraint have multiple NULLs?
  A: In standard SQL and most databases yes (NULL != NULL).
     SQL Server is an exception -- allows only one NULL per unique index.
