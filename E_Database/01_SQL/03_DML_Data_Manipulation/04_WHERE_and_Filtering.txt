================================================================
  WHERE AND FILTERING
================================================================

  WHERE filters rows BEFORE aggregation (GROUP BY).
  Can use column values, expressions, and subqueries.
  Cannot use aggregate functions (use HAVING for that).

================================================================
COMPARISON OPERATORS
================================================================

  =         equal to
  <>  !=    not equal
  >         greater than
  <         less than
  >=        greater than or equal
  <=        less than or equal

  SELECT * FROM products WHERE price > 50;
  SELECT * FROM orders WHERE status <> 'CANCELLED';
  SELECT * FROM orders WHERE created_at >= '2024-01-01';

================================================================
LOGICAL OPERATORS
================================================================

  AND: both conditions must be true
  OR:  at least one condition must be true
  NOT: negates the condition

  SELECT * FROM orders
  WHERE status = 'PENDING' AND total > 100;

  SELECT * FROM products
  WHERE category_id = 3 OR category_id = 7;

  SELECT * FROM customers
  WHERE NOT is_active;

  Precedence: NOT > AND > OR
  Always use parentheses for clarity:
  WHERE (status = 'PENDING' OR status = 'CONFIRMED') AND total > 100;

================================================================
IN / NOT IN
================================================================

  SELECT * FROM orders WHERE status IN ('PENDING', 'CONFIRMED', 'SHIPPED');
  SELECT * FROM products WHERE category_id NOT IN (1, 2, 3);

  IN with subquery:
  SELECT * FROM customers
  WHERE id IN (SELECT DISTINCT customer_id FROM orders WHERE total > 500);

  NOT IN with NULL — DANGEROUS:
  If the subquery returns any NULL, NOT IN returns NO rows (NULL propagation).
  Fix: use NOT EXISTS instead of NOT IN when subquery might have NULLs.

  SAFE alternative:
  WHERE NOT EXISTS (
      SELECT 1 FROM orders WHERE orders.customer_id = customers.id
  );

================================================================
BETWEEN
================================================================

  SELECT * FROM orders WHERE total BETWEEN 100 AND 500;   -- inclusive both ends
  SELECT * FROM orders WHERE created_at BETWEEN '2024-01-01' AND '2024-12-31';
  -- Equivalent to: WHERE total >= 100 AND total <= 500

  SELECT * FROM orders WHERE total NOT BETWEEN 100 AND 500;

================================================================
LIKE — PATTERN MATCHING
================================================================

  % — zero or more characters wildcard
  _ — exactly one character wildcard

  SELECT * FROM customers WHERE email LIKE '%@gmail.com';      -- ends with
  SELECT * FROM customers WHERE name LIKE 'A%';               -- starts with
  SELECT * FROM products WHERE sku LIKE 'SKU-00_';            -- one char wildcard
  SELECT * FROM products WHERE description LIKE '%organic%';  -- contains

  Case sensitivity:
  MySQL LIKE: case-insensitive by default
  PostgreSQL LIKE: case-sensitive; use ILIKE for case-insensitive

  Performance: LIKE '%prefix' (leading wildcard) cannot use a B-tree index.
               LIKE 'prefix%' CAN use a B-tree index. Use full-text search for contains.

================================================================
IS NULL / IS NOT NULL
================================================================

  NULL cannot be compared with = — must use IS NULL / IS NOT NULL.

  SELECT * FROM orders WHERE shipped_at IS NULL;       -- not yet shipped
  SELECT * FROM orders WHERE shipped_at IS NOT NULL;   -- has been shipped

  WRONG (always returns empty):
  SELECT * FROM orders WHERE shipped_at = NULL;        -- never matches any row

================================================================
EXISTS / NOT EXISTS
================================================================

  EXISTS returns TRUE if the subquery returns at least one row.
  More efficient than IN for large subqueries.

  Customers who have placed at least one order:
  SELECT * FROM customers c
  WHERE EXISTS (
      SELECT 1 FROM orders o WHERE o.customer_id = c.id
  );

  Customers who have NEVER placed an order:
  SELECT * FROM customers c
  WHERE NOT EXISTS (
      SELECT 1 FROM orders o WHERE o.customer_id = c.id
  );

  NOT EXISTS vs NOT IN:
  Use NOT EXISTS — it handles NULL correctly.
  NOT IN can return 0 rows if subquery has any NULLs.

================================================================
FILTERING WITH DATES
================================================================

  SELECT * FROM orders WHERE DATE(created_at) = '2024-01-15';
  SELECT * FROM orders WHERE created_at >= '2024-01-01' AND created_at < '2024-02-01';

  -- PostgreSQL interval:
  SELECT * FROM orders WHERE created_at >= NOW() - INTERVAL '7 days';

  -- Extract for period filtering:
  SELECT * FROM orders WHERE EXTRACT(YEAR FROM created_at) = 2024;
  SELECT * FROM orders WHERE EXTRACT(MONTH FROM created_at) = 1;

================================================================
WHERE vs HAVING
================================================================

  WHERE   filters individual rows BEFORE aggregation.
  HAVING  filters aggregated groups AFTER GROUP BY.

  You cannot use aggregate functions in WHERE.

  WRONG:
  SELECT customer_id, SUM(total)
  FROM orders
  WHERE SUM(total) > 1000   -- ERROR: can't use aggregate in WHERE
  GROUP BY customer_id;

  CORRECT:
  SELECT customer_id, SUM(total) AS total_spent
  FROM orders
  GROUP BY customer_id
  HAVING SUM(total) > 1000;   -- HAVING filters groups

  Combined:
  SELECT customer_id, SUM(total) AS total_spent
  FROM orders
  WHERE status <> 'CANCELLED'      -- WHERE: filter rows first
  GROUP BY customer_id
  HAVING SUM(total) > 500          -- HAVING: then filter groups
  ORDER BY total_spent DESC;

================================================================
INTERVIEW Q&A
================================================================

  Q: What is the difference between WHERE and HAVING?
  A: WHERE filters rows before grouping; HAVING filters groups after GROUP BY.
     Aggregate functions (SUM, COUNT) can be used in HAVING, not in WHERE.

  Q: Why is NOT IN dangerous with NULLs?
  A: If the subquery returns any NULL, the entire NOT IN clause returns FALSE
     for all rows (NULL propagation). Use NOT EXISTS instead, which handles
     NULLs correctly and is often more efficient.

  Q: Why can't LIKE '%word' use an index?
  A: B-tree indexes scan from left to right. A leading wildcard means we
     can't determine a starting point in the index. Use full-text search
     (TSVECTOR/GIN index in PostgreSQL, FULLTEXT in MySQL) for contains searches.

  Q: How do you compare NULL values in SQL?
  A: Use IS NULL and IS NOT NULL. Never use = NULL — it never matches anything
     because NULL = NULL is also NULL (unknown), not TRUE.
