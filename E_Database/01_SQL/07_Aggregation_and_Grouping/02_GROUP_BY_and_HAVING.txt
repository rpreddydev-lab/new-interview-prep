================================================================
  GROUP BY AND HAVING
================================================================

  GROUP BY collapses rows sharing the same group-key values.
  HAVING filters those groups by an aggregate condition.

================================================================
BASIC GROUP BY
================================================================

  Orders per customer:
  SELECT customer_id, COUNT(*) AS order_count
  FROM orders
  GROUP BY customer_id;

  Revenue per product category:
  SELECT c.name, SUM(oi.qty * oi.price) AS revenue
  FROM order_items oi
  INNER JOIN products p  ON oi.product_id = p.id
  INNER JOIN categories c ON p.category_id = c.id
  GROUP BY c.name
  ORDER BY revenue DESC;

================================================================
MULTI-COLUMN GROUP BY
================================================================

  Revenue per customer per year:
  SELECT
      customer_id,
      EXTRACT(YEAR FROM created_at) AS year,
      SUM(total) AS annual_revenue
  FROM orders
  GROUP BY customer_id, EXTRACT(YEAR FROM created_at)
  ORDER BY customer_id, year;

================================================================
GROUP BY WITH HAVING
================================================================

  Customers who placed more than 3 orders:
  SELECT customer_id, COUNT(*) AS order_count
  FROM orders
  GROUP BY customer_id
  HAVING COUNT(*) > 3;

  Departments with average salary above 60,000:
  SELECT department_id, AVG(salary) AS avg_sal
  FROM employees
  GROUP BY department_id
  HAVING AVG(salary) > 60000
  ORDER BY avg_sal DESC;

================================================================
COMBINING WHERE AND HAVING
================================================================

  Average order value per customer (only DELIVERED orders,
  only customers with avg above 100):
  SELECT
      customer_id,
      AVG(total) AS avg_order
  FROM orders
  WHERE status = 'DELIVERED'         -- filter rows BEFORE grouping
  GROUP BY customer_id
  HAVING AVG(total) > 100            -- filter groups AFTER aggregating
  ORDER BY avg_order DESC;

================================================================
GROUP BY EXPRESSION
================================================================

  Group by computed expression:
  SELECT
      EXTRACT(MONTH FROM created_at) AS month,
      COUNT(*) AS order_count
  FROM orders
  WHERE EXTRACT(YEAR FROM created_at) = 2024
  GROUP BY EXTRACT(MONTH FROM created_at)
  ORDER BY month;

================================================================
GROUP BY NULL HANDLING
================================================================

  NULL is treated as its own group in GROUP BY:
  SELECT department_id, COUNT(*) FROM employees GROUP BY department_id;
  -- Employees with NULL department_id form a separate group

================================================================
GROUP BY WITH FILTER (PostgreSQL)
================================================================

  COUNT(*) FILTER (WHERE status = 'PENDING') AS pending_count,
  COUNT(*) FILTER (WHERE status = 'SHIPPED') AS shipped_count
  -- Cleaner than: COUNT(CASE WHEN status='PENDING' THEN 1 END)

================================================================
COMMON MISTAKES
================================================================

  1. Selecting non-aggregated column not in GROUP BY:
     SELECT customer_id, name, COUNT(*) FROM orders GROUP BY customer_id;
     -- name is not in GROUP BY and not aggregated --> error

  2. Using alias in HAVING:
     HAVING order_count > 5  -- alias defined in SELECT is not available in HAVING
     HAVING COUNT(*) > 5     -- correct

  3. Filtering aggregates in WHERE:
     WHERE COUNT(*) > 5    -- error: aggregates not allowed in WHERE
     HAVING COUNT(*) > 5   -- correct

================================================================
INTERVIEW Q&A
================================================================

  Q: What is the logical execution order of GROUP BY vs WHERE vs HAVING?
  A: FROM/JOIN --> WHERE (filter rows) --> GROUP BY (group rows)
     --> Aggregate functions --> HAVING (filter groups)
     --> SELECT --> ORDER BY --> LIMIT.

  Q: Can you HAVING without GROUP BY?
  A: Yes. Without GROUP BY, the entire table is one group.
     HAVING COUNT(*) > 100 would check if the total row count > 100.

  Q: Why can't you use a SELECT alias in HAVING?
  A: HAVING is evaluated before SELECT in the logical order.
     The alias doesn't exist yet. Use the full aggregate expression.
