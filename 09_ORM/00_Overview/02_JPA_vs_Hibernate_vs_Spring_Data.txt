2. JPA — Jakarta Persistence API
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

What it is:
  A Java EE / Jakarta EE SPECIFICATION that defines:
  - How to annotate entities (@Entity, @Table, @Id, @Column)
  - How to query objects (JPQL, Criteria API)
  - How to manage transactions (EntityManager, persistence context)
  - Entity lifecycle and states

Versions:
  JPA 1.0 (2006)  → Part of Java EE 5
  JPA 2.0 (2009)  → Criteria API added
  JPA 2.1 (2013)  → Named entity graphs, stored procedures
  JPA 2.2 (2017)  → Java 8 types (LocalDate, Optional)
  Jakarta Persistence 3.0 (2020) → namespace: jakarta.persistence.*
  Jakarta Persistence 3.1 (2022) → UUID support, numeric functions

Key Interfaces:
  EntityManagerFactory   → heavyweight, one per app, thread-safe
  EntityManager          → lightweight, one per request, NOT thread-safe
  EntityTransaction      → programmatic transaction control
  Query / TypedQuery     → JPQL query objects
  Criteria API           → type-safe programmatic queries

Key Annotations:
  @Entity, @Table, @Id, @GeneratedValue
  @Column, @JoinColumn, @JoinTable
  @OneToOne, @OneToMany, @ManyToOne, @ManyToMany
  @MappedSuperclass, @Embeddable, @Embedded
  @NamedQuery, @EntityListeners
  @Version (optimistic locking)

3. HIBERNATE — ORM Implementation
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

What it is:
  The most popular, feature-rich JPA implementation + extras
  beyond the JPA spec.

Hibernate-specific features (beyond JPA):
  Feature                         | Hibernate API
  ────────────────────────────────|──────────────────────────
  First-level cache               | Session (always on)
  Second-level cache              | @Cache, EhCache, Infinispan
  Query cache                     | @QueryHints
  HQL (Hibernate Query Language)  | session.createQuery(hql)
  Custom types                    | UserType, CompositeUserType
  Envers (audit history)          | @Audited
  Multi-tenancy                   | TenantIdentifierResolver
  Natural ID                      | @NaturalId
  Soft deletes                    | @SQLDelete, @Where
  Filters                         | @FilterDef, @Filter
  Batch processing config         | hibernate.jdbc.batch_size
  Spatial/GIS types               | hibernate-spatial
  Statistics                      | SessionFactory.getStatistics()

Hibernate Session vs JPA EntityManager:
  Session          ↔  EntityManager
  SessionFactory   ↔  EntityManagerFactory
  HQL              ↔  JPQL (compatible, HQL is superset)
  Transaction      ↔  EntityTransaction

  // Getting Session from EntityManager in Spring
  Session session = entityManager.unwrap(Session.class);
  session.enableFilter("activeFilter").setParameter("active", true);

4. SPRING DATA JPA — Repository Abstraction
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

What it is:
  A Spring module that wraps JPA (usually backed by Hibernate) and
  provides a repository abstraction. You define an interface; Spring
  generates the implementation at runtime.

Repository Hierarchy:
  Repository<T, ID>                    ← marker interface
  CrudRepository<T, ID>                ← save, findById, delete, count
  PagingAndSortingRepository<T, ID>    ← findAll(Pageable), findAll(Sort)
  JpaRepository<T, ID>                 ← flush, saveAll, deleteInBatch
  JpaSpecificationExecutor<T>          ← type-safe dynamic queries

Features:
  1. Derived Query Methods (method name → SQL):
     findByFirstNameAndLastName(String, String)
     findByAgeGreaterThanOrderByNameAsc(int)
     countByStatus(String)
     existsByEmail(String)
     deleteByCreatedAtBefore(LocalDate)

  2. @Query annotation (JPQL or native):
     @Query("SELECT u FROM User u WHERE u.active = true")
     @Query(value="SELECT * FROM users WHERE active=1", nativeQuery=true)

  3. Paging & Sorting:
     Page<User> findByDepartment(String dept, Pageable pageable);
     // Usage: PageRequest.of(0, 20, Sort.by("name"))

  4. @Modifying for UPDATE/DELETE:
     @Modifying
     @Query("UPDATE User u SET u.active = false WHERE u.lastLogin < :date")
     int deactivateOldUsers(@Param("date") LocalDate date);

  5. Specifications (dynamic predicates):
     Specification<User> spec = (root, query, cb) ->
         cb.equal(root.get("department"), "Engineering");
     userRepository.findAll(spec, pageable);

  6. Projections (select only needed columns):
     interface UserSummary {
         String getEmail();
         String getFirstName();
     }
     List<UserSummary> findAllProjectedBy();

Q: What is the difference between JPA and Hibernate?
A: JPA is a specification (set of interfaces and annotations).
   Hibernate is an implementation of that spec. If you use only JPA
   annotations/API, you can theoretically switch to EclipseLink.
   In practice, most apps use Hibernate-specific features.

Q: Can you use Hibernate without Spring?
A: Yes. Configure via hibernate.cfg.xml or programmatically via
   StandardServiceRegistryBuilder + MetadataSources + SessionFactory.
   Spring just makes configuration/injection convenient.

Q: What does Spring Data JPA add over raw JPA?
A: Repository interfaces (no impl needed), derived query methods,
   paging/sorting built-in, @Transactional by default on save/delete,
   audit support (@CreatedDate, @LastModifiedDate), Specification API.

Q: How does Spring Data JPA implement repository methods at runtime?
A: Spring uses JDK dynamic proxies (or CGLIB) to create an instance of
   SimpleJpaRepository<T, ID> at startup. Derived query methods are
   parsed by Spring's query parser and translated to JPQL at startup.

Q: What is JpaRepository vs CrudRepository?
A: JpaRepository extends CrudRepository and PagingAndSortingRepository.
   It adds JPA-specific methods: flush(), saveAllAndFlush(),
   deleteInBatch(), findAll(Sort), getReferenceById().
