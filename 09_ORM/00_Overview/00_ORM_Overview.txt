1. WHAT IS ORM?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

ORM (Object-Relational Mapping) is a programming technique that maps
objects in an object-oriented language to rows in a relational database.
It abstracts SQL away and lets developers work with domain objects instead
of tables and columns.

Core Idea:
  - Java class  ↔  Database table
  - Java object ↔  Database row
  - Java field  ↔  Database column
  - Java method ↔  SQL query / DML operation

The "impedance mismatch" problem:
  Relational databases and OOP languages model data differently.
  OOP has inheritance, composition, polymorphism.
  SQL has tables, joins, foreign keys.
  ORM bridges this gap.

3. HOW ORM WORKS — LIFECYCLE OVERVIEW
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Step 1: Map your Java class to a DB table (via annotations or XML)

@Entity
@Table(name = "users")
public class User {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(name = "email", nullable = false, unique = true)
    private String email;
}

Step 2: ORM creates/manages a SessionFactory (Hibernate) or
        EntityManagerFactory (JPA) at startup.

Step 3: Per request/transaction, a Session (Hibernate) or
        EntityManager (JPA) is obtained.

Step 4: Entities transition through states:
  Transient  → new Java object, not tracked
  Persistent → tracked by persistence context
  Detached   → was persistent, context closed
  Removed    → scheduled for DELETE

Step 5: On transaction commit, ORM performs dirty checking →
        generates and runs SQL → flushes to DB.

4. KEY CONCEPTS AT A GLANCE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Concept              | Description
─────────────────────|────────────────────────────────────────
Entity               | A class mapped to a table
Persistence Context  | 1st-level cache, tracks entities
EntityManager        | API to interact with persistence context
JPQL                 | Object-oriented query language
Dirty Checking       | Auto-detect changed fields, auto-UPDATE
Lazy Loading         | Load associations on demand
Eager Loading        | Load associations immediately
Cascade              | Propagate operations to child entities
Fetch Strategy       | LAZY or EAGER per relationship
Inheritance Strategy | How to store inheritance in tables
Optimistic Locking   | Version field to prevent lost updates
Pessimistic Locking  | DB-level locks (SELECT ... FOR UPDATE)

5. ORM IN SPRING BOOT QUICK START
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

<!-- pom.xml -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-data-jpa</artifactId>
</dependency>
<dependency>
    <groupId>com.h2database</groupId>
    <artifactId>h2</artifactId>
    <scope>runtime</scope>
</dependency>

# application.properties
spring.datasource.url=jdbc:mysql://localhost:3306/mydb
spring.datasource.username=root
spring.datasource.password=secret
spring.jpa.hibernate.ddl-auto=update
spring.jpa.show-sql=true
spring.jpa.properties.hibernate.format_sql=true

// Repository
public interface UserRepository extends JpaRepository<User, Long> {
    List<User> findByEmail(String email);
}

// Service
@Service
@Transactional
public class UserService {
    private final UserRepository repo;
    public User save(User user) { return repo.save(user); }
}

6. INTERVIEW QUICK HITS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: What is the difference between JPA and Hibernate?
A: JPA is a specification (interface/annotation standard). Hibernate is an
   implementation of that specification. You can swap Hibernate for
   EclipseLink without changing JPA code.

Q: What is the impedance mismatch?
A: The conceptual gap between OOP (inheritance, encapsulation, polymorphism)
   and relational DBs (tables, foreign keys, normalization). ORM solves this.

Q: What is a persistence context?
A: A first-level cache that tracks all managed entities within a unit of work
   (transaction). Changes are batched and flushed to DB at commit time.

Q: What is dirty checking?
A: Hibernate snapshots entity state at load time. On flush/commit, it compares
   current state to snapshot and issues UPDATEs automatically.

Q: When does ORM NOT make sense?
A: Bulk operations (UPDATE millions of rows), complex analytical SQL,
   reporting queries, ETL pipelines. Use native SQL or JDBC for these.
