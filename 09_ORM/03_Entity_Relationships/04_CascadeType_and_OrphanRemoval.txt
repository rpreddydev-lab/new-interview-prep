================================================================
CascadeType and orphanRemoval — Lifecycle Propagation
================================================================

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1. WHAT IS CASCADE?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Cascade means: propagate this JPA operation from the parent entity
to associated child entities automatically.

Without cascade:
  User user = em.find(User.class, 1L);
  Order order = new Order();
  user.getOrders().add(order);
  em.persist(order);   // must persist manually!

With cascade = CascadeType.PERSIST:
  user.addOrder(order);
  em.persist(user);    // auto-persists order too

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
2. ALL CASCADETYPE VALUES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Type              | JPA Operation | Effect
──────────────────|───────────────|──────────────────────────────────────────────
PERSIST           | persist()     | Child saved when parent is saved (new children)
MERGE             | merge()       | Child merged when parent is merged (updates)
REMOVE            | remove()      | Child deleted when parent is deleted
REFRESH           | refresh()     | Child reloaded when parent is reloaded from DB
DETACH            | detach()      | Child detached when parent is detached
ALL               | all above     | Short-hand for all 6 operations

Hibernate-specific (not in JPA spec):
  org.hibernate.annotations.CascadeType.REPLICATE   — Hibernate replication
  org.hibernate.annotations.CascadeType.SAVE_UPDATE — saveOrUpdate() cascade
  org.hibernate.annotations.CascadeType.LOCK        — lock() cascade

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
3. WHEN TO USE EACH CASCADETYPE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Relationship Type        | Recommended Cascade
─────────────────────────|────────────────────────────────────────────
Parent → Children        | CascadeType.ALL + orphanRemoval = true
  (e.g., Order → Items)  |
Parent → Dependent refs  | CascadeType.PERSIST, MERGE
  (e.g., Post → Tags)    | (do NOT cascade REMOVE — tag shared with others)
@ManyToOne               | NO CASCADE — do not cascade from child to parent
@ManyToMany              | PERSIST, MERGE only (never REMOVE or ALL)

// Example: Parent-child (full ownership)
@OneToMany(mappedBy = "order", cascade = CascadeType.ALL, orphanRemoval = true)
private List<OrderItem> items = new ArrayList<>();

// Example: Shared reference (@ManyToMany)
@ManyToMany(cascade = {CascadeType.PERSIST, CascadeType.MERGE})
private Set<Tag> tags = new HashSet<>();

4. ORPHAN REMOVAL
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

orphanRemoval = true means: when a child is removed from the collection,
DELETE it from the database automatically.

// Setup:
@OneToMany(mappedBy = "order", cascade = CascadeType.ALL, orphanRemoval = true)
private List<OrderItem> items;

// Usage:
Order order = orderRepo.findById(1L).get();
OrderItem itemToRemove = order.getItems().get(0);
order.getItems().remove(itemToRemove);  // triggers DELETE on flush
// orderItemRepo.delete(itemToRemove) is NOT needed!

orphanRemoval vs CascadeType.REMOVE:

| Feature              | orphanRemoval=true       | CascadeType.REMOVE         |
|─────────────────────|─────────────────────────|────────────────────────────|
| Triggered by         | Removing from collection | em.remove(parent)          |
| When parent deleted? | YES (deletes children)   | YES (deletes children)     |
| When child removed   | YES (deletes orphan)     | NO                         |
|   from collection?   |                          |                            |

orphanRemoval = true implies CascadeType.REMOVE.
CascadeType.ALL includes REMOVE but NOT orphanRemoval.

5. DANGEROUS CASCADE PATTERNS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Danger 1: CascadeType.ALL on @ManyToOne
  @ManyToOne(cascade = CascadeType.ALL)   // BAD!
  private User user;
  // Deleting an Order deletes the User! One order controls the user.

Danger 2: CascadeType.REMOVE on @ManyToMany
  @ManyToMany(cascade = CascadeType.ALL)  // BAD!
  private Set<Tag> tags;
  // Removing a Post deletes ALL Tag entities from the DB,
  // even if other Posts still reference them.

Danger 3: orphanRemoval=true on @ManyToMany
  // Not allowed by JPA spec — orphanRemoval only on @OneToOne and @OneToMany

Rule of thumb:
  Use CascadeType.ALL + orphanRemoval=true ONLY when the child
  cannot exist without the parent (@OneToMany where parent owns child).

6. FULL EXAMPLE — ORDER WITH ITEMS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

@Entity
public class Order {
    @Id @GeneratedValue private Long id;
    private String status;

    @OneToMany(mappedBy = "order",
               cascade = CascadeType.ALL,
               orphanRemoval = true)
    private List<OrderItem> items = new ArrayList<>();

    public void addItem(OrderItem item) {
        items.add(item);
        item.setOrder(this);
    }
    public void removeItem(OrderItem item) {
        items.remove(item);
        item.setOrder(null);
    }
}

@Entity
public class OrderItem {
    @Id @GeneratedValue private Long id;
    private String productName;
    private int quantity;

    @ManyToOne(fetch = FetchType.LAZY)   // NO cascade here!
    @JoinColumn(name = "order_id")
    private Order order;

    // equals/hashCode by productName for correct List/Set behavior
}

// Service:
@Transactional
public void processOrder(Long orderId) {
    Order order = orderRepo.findById(orderId).orElseThrow();

    // Add new item — cascade PERSIST saves it
    OrderItem newItem = new OrderItem("Widget", 2);
    order.addItem(newItem);

    // Remove an item — orphanRemoval deletes it
    OrderItem stale = order.getItems().get(0);
    order.removeItem(stale);  // DELETE FROM order_items WHERE id=?

    // Delete order — cascade REMOVE deletes all items
    orderRepo.delete(order);  // deletes order + all items
}

Q: What is the difference between CascadeType.REMOVE and orphanRemoval?
A: CascadeType.REMOVE only triggers when em.remove(parent) is called — it
   cascades the delete to children. orphanRemoval=true additionally fires
   a DELETE when an entity is removed from the parent collection.
   Use orphanRemoval when children's lifecycle is strictly owned by parent.

Q: Can you use orphanRemoval with @ManyToMany?
A: No. orphanRemoval is only allowed on @OneToOne and @OneToMany.
   JPA will throw a deployment/validation error if applied to @ManyToMany.

Q: Why is CascadeType.ALL on @ManyToOne dangerous?
A: It propagates all operations, including REMOVE. Deleting a child entity
   would cascade to the parent, potentially deleting data used by many
   other entities. Never cascade from the many side to the one side.

Q: Does CascadeType.ALL include orphanRemoval?
A: No. CascadeType.ALL covers all 5 JPA operations (PERSIST, MERGE,
   REMOVE, REFRESH, DETACH) but does NOT enable orphanRemoval.
   You must set orphanRemoval=true explicitly.

Q: What cascade types should you use for @ManyToMany?
A: Only PERSIST and MERGE.
   PERSIST: so new associated entities are saved when the owning entity is saved.
   MERGE: so updates propagate correctly.
   Never use REMOVE or ALL because it would delete shared entities.
