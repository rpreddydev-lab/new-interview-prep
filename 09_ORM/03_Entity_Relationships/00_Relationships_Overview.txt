1. TYPES OF RELATIONSHIPS

Annotation     | Cardinality       | Example
───────────────|──────────────────────────────────────────────
@OneToOne      | One A ↔ One B      | User ↔ UserProfile

2. KEY CONCEPTS TO UNDERSTAND FOR EVERY RELATIONSHIP
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

A. Owning Side vs Inverse Side
   - The OWNING side has the foreign key column / join column
   - The INVERSE side uses mappedBy="fieldNameOnOwner"
   - JPA only persists changes made on the OWNING side
   - mappedBy = "which field in the other entity points back"

B. FetchType (how/when the association is loaded)
   - LAZY:  load on first access (default for collections)
   - EAGER: load immediately with parent (default for @ManyToOne, @OneToOne)

   Default FetchType per annotation:
   @OneToOne   → EAGER (change to LAZY!)
   @ManyToOne  → EAGER (change to LAZY!)
   @OneToMany  → LAZY
   @ManyToMany → LAZY

C. CascadeType (propagate operations from parent to child)
   PERSIST, MERGE, REMOVE, REFRESH, DETACH, ALL

D. orphanRemoval (auto-delete orphaned children)
   orphanRemoval=true: if child removed from parent collection → DELETE it

3. FOREIGN KEY PLACEMENT RULE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  @ManyToOne  → FK is in MANY side's table
  @OneToMany  → FK is in the MANY side's table (no join table needed)
  @OneToOne   → FK can be in either table (use @JoinColumn to specify)
  @ManyToMany → FK is in a separate JOIN TABLE

4. RELATIONSHIP SUMMARY TABLE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Annotation   | FK Location              | Default Fetch | mappedBy side
─────────────|──────────────────────────|───────────────|──────────────
@OneToOne    | Owner side table         | EAGER         | Inverse
@ManyToOne   | Owner (@ManyToOne) table | EAGER         | N/A (no mappedBy)
@OneToMany   | Child table (FK→parent)  | LAZY          | Always use mappedBy
@ManyToMany  | Separate join table      | LAZY          | Inverse side

5. COMMON MISTAKES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Mistake 1: Bidirectional relationship not maintained
  order.getItems().add(item);   // ✓ collection side
  item.setOrder(order);         // ✓ FK side — MUST set both!

Mistake 2: Using @OneToMany without mappedBy (creates join table!)
  @OneToMany  // without mappedBy → Hibernate creates a JOIN TABLE
  private List<Order> orders;

Mistake 3: Eager loading on @ManyToOne causing N+1
  List<Order> orders = orderRepo.findAll();  // 1 query for orders
  // Each order.getUser() fires SELECT → N queries! (EAGER default)
  // Fix: change to FetchType.LAZY and use JOIN FETCH when needed

Mistake 4: CascadeType.ALL on @ManyToOne
  @ManyToOne(cascade = CascadeType.REMOVE)  // NEVER do this!
  private User user;
  // Deleting an Order would delete the User!

Mistake 5: equals/hashCode based on mutable collection membership
  Never put entities in Sets without proper equals/hashCode.

6. INTERVIEW QUICK HITS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: What is the owning side of a relationship?
A: The side that has the foreign key column in the database. It's the
   side WITHOUT mappedBy. JPA only looks at the owning side to determine
   what SQL to generate for inserts/updates of the FK.

Q: What does mappedBy mean?
A: It designates the INVERSE (non-owning) side of a bidirectional
   relationship. The value is the field name in the OWNING entity that
   maps back to this side. No FK column on this side.

Q: What is the default fetch type for @ManyToOne?
A: EAGER — which can cause N+1 if you have a list of entities each with
   a @ManyToOne. Best practice: change all @ManyToOne to LAZY, and use
   JOIN FETCH in queries when you need the association.

Q: What is orphanRemoval?
A: When true on a @OneToMany, removing an entity from the collection
   automatically issues a DELETE for that entity. Only works when the
   parent "owns" the lifecycle of its children (e.g., Order → OrderItems).
