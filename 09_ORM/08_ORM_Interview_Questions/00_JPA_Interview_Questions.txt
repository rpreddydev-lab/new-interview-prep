================================================================
JPA Interview Questions — 50 Essential Q&A
================================================================

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
BASICS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q1: What is JPA?
A: Jakarta Persistence API (formerly Java Persistence API) is a Java
   specification for mapping Java objects to relational database tables
   (ORM). It defines a standard API (EntityManager, JPQL, annotations)
   that implementations like Hibernate fulfill.

Q2: What is the difference between JPA, Hibernate, and Spring Data JPA?
A: JPA is the specification (interfaces/annotations). Hibernate is an
   ORM framework that implements the JPA spec (plus extra features).
   Spring Data JPA is an abstraction layer on top of JPA that provides
   Repository interfaces, derived query methods, and reduces boilerplate.
   Stack: Spring Data JPA → JPA → Hibernate → JDBC → Database.

Q3: What is an entity in JPA?
A: A Java class annotated with @Entity that maps to a DB table.
   Requirements: public/protected no-arg constructor, non-final class,
   at least one @Id field, Serializable (recommended).

Q4: What is the persistence context?
A: The persistence context is a first-level cache managed by the EntityManager.
   All entities loaded within a transaction are tracked here.
   Hibernate uses it for identity guarantee (same instance for same PK),
   dirty checking, and lazy association initialization.

Q5: What is EntityManagerFactory vs EntityManager?
A: EntityManagerFactory is application-scoped, thread-safe, expensive to create.
   EntityManager is request/transaction-scoped, NOT thread-safe, cheap to create.
   In Spring: EntityManagerFactory is created once; EntityManagers are injected
   as thread-local proxies via @PersistenceContext.

ENTITY LIFECYCLE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q6: What are the four entity states in JPA?
A: Transient — new object, not known to EntityManager.
   Persistent — managed by EntityManager in persistence context.
   Detached — was managed, but session ended or em.detach() called.
   Removed — scheduled for DELETE on next flush.

Q7: What is the difference between persist() and merge()?
A: persist() makes a transient entity persistent (new entity → INSERT).
   merge() updates a detached entity — copies its state into a new managed
   entity and returns the managed copy. persist() does NOT return anything;
   merge() returns the managed entity.

Q8: What happens when you call em.find() vs em.getReference()?
A: find() issues a SELECT immediately and returns null if not found.
   getReference() returns a proxy without hitting DB; the SELECT fires
   on first property access. getReference() throws EntityNotFoundException
   if the entity doesn't exist and a property is accessed.

Q9: What triggers a flush?
A: (1) Calling em.flush() explicitly; (2) Committing the transaction;
   (3) Before a query is executed when FlushMode is AUTO (default) and
   pending changes might affect the query result.

Q10: What is dirty checking?
A: Hibernate stores a snapshot of each entity's state when loaded.
    On flush, it compares current state to snapshot. Changed fields
    trigger an auto-generated UPDATE without requiring explicit save().

RELATIONSHIPS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q11: What is the owning side of a relationship?
A: The owning side is the entity whose field controls the FK column.
   For @OneToMany/@ManyToOne: the @ManyToOne side is the owner.
   For @ManyToMany: the entity with @JoinTable is the owner.
   The owner side determines what JPA writes to the DB for the FK.

Q12: What does mappedBy mean?
A: mappedBy on a @OneToMany or @ManyToMany (inverse side) tells JPA:
   "the FK is managed by the field named X on the other entity."
   Without mappedBy, JPA creates an extra join table.

Q13: Why should you always use helper methods in bidirectional relationships?
A: JPA writes the FK from the OWNING side. If you only set the inverse side
   (e.g., add to @OneToMany collection without setting @ManyToOne), the FK
   remains null. Helper methods set both sides atomically.

Q14: What is the default fetch type for @ManyToOne?
A: EAGER — JPA loads the associated entity in the same SELECT. This is
   a performance trap (unexpected queries). Always override to LAZY:
   @ManyToOne(fetch = FetchType.LAZY).

Q15: What is the LazyInitializationException?
A: Thrown when a LAZY proxy is accessed after the Hibernate Session has
   closed (outside @Transactional boundary). Fix with JOIN FETCH,
   @EntityGraph, or DTO projections.

QUERIES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q16: What is JPQL?
A: Java Persistence Query Language — an object-oriented query language
   that operates on entity names and field names (not table/column names).
   SELECT u FROM User u WHERE u.email = :email

Q17: What is the difference between JPQL and SQL?
A: JPQL uses entity class names and field names; SQL uses table and column
   names. JPQL is DB-agnostic (translated to SQL by Hibernate per dialect).
   JPQL supports polymorphic queries; SQL does not.

Q18: What is a DTO projection in JPQL?
A: Using the new keyword in JPQL constructor expression to return non-entity
   objects: SELECT new com.example.UserDto(u.id, u.email) FROM User u.
   Efficient for read-only operations — no entity lifecycle management.

Q19: What is the Criteria API?
A: A JPA API for building type-safe queries programmatically using Java
   objects (CriteriaBuilder, CriteriaQuery, Root, Predicate). Used for
   dynamic queries where conditions are determined at runtime.

Q20: What is a named query?
A: @NamedQuery on an entity class defines a JPQL query that is pre-compiled
   at startup. More efficient than createQuery() (parsed once at startup).
   Spring Data JPA auto-detects @NamedQuery by convention.

PRIMARY KEYS AND GENERATION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q21: What are the JPA ID generation strategies?
A: IDENTITY — DB auto-increment (disables JDBC batching).
   SEQUENCE — pre-allocated blocks from DB sequence (best for batching).
   AUTO — JPA picks (usually SEQUENCE or TABLE depending on DB).
   TABLE — uses a separate PK table (slowest, portable).
   UUID — generates UUID in application (v4 random or v7 time-ordered).

Q22: Why can't you use IDENTITY strategy with JDBC batch inserts?
A: IDENTITY requires the DB to generate the ID and return it immediately
   after each INSERT. Hibernate needs the ID to populate the entity in 1LC.
   This forces single-row INSERTs and prevents batch accumulation.

Q23: What is a composite key?
A: A primary key composed of multiple columns. JPA supports two approaches:
   @EmbeddedId (composite key as @Embeddable class, referenced by one field)
   @IdClass (separate key class, entity has multiple @Id fields).
   Both key classes must implement Serializable and override equals/hashCode.

INHERITANCE AND MAPPING
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q24: What are the JPA inheritance strategies?
A: SINGLE_TABLE — all in one table with discriminator column (fastest queries, nullable subtype cols).
   JOINED — one table per class joined by PK (most normalized, JOIN needed).
   TABLE_PER_CLASS — one table per concrete class, no shared parent table (UNION queries).

Q25: What is @MappedSuperclass?
A: A class annotated @MappedSuperclass is NOT an entity. It shares mapping
   metadata (fields, annotations) with subclasses but has no table and cannot
   be queried. Use it for common fields: id, createdAt, version.

Q26: What is @Embeddable?
A: A class that maps its fields into the OWNER entity's table. No @Id, no table.
   Represents value types (Address, Money). Supports @AttributeOverride for
   column renaming when embedding multiple times.

Q27: What is @ElementCollection?
A: Maps a collection of @Embeddable objects or primitives to a separate
   collection table. Any modification to the collection deletes all rows
   and re-inserts. Use @OneToMany to an @Entity instead for large, frequently
   modified collections.

CASCADE AND FETCH
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q28: What cascade types are available in JPA?
A: PERSIST, MERGE, REMOVE, REFRESH, DETACH, ALL.
   ALL = all 5 above. REMOVE and ALL should NEVER be on @ManyToOne or @ManyToMany.

Q29: What is the difference between CascadeType.REMOVE and orphanRemoval?
A: REMOVE cascades delete when parent entity is deleted.
   orphanRemoval additionally deletes children removed from the collection.
   orphanRemoval is only valid on @OneToOne and @OneToMany.

Q30: What is the N+1 problem?
A: Loading N entities and then accessing their LAZY associations triggers
   N additional SQL queries — one per entity. Fixes: JOIN FETCH, @EntityGraph,
   @BatchSize, DTO projections.

SPRING DATA JPA SPECIFIC
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q31: What is a Spring Data JPA repository?
A: An interface extending JpaRepository<T, ID> (or CrudRepository etc).
   Spring Data generates implementation at runtime. Provides: findAll, findById,
   save, delete, and derived query methods.

Q32: What are derived query methods?
A: Methods whose names are parsed by Spring Data to generate JPQL automatically.
   findByEmailAndStatus(String, String) → WHERE email=? AND status=?
   findTop5ByOrderByCreatedAtDesc() → LIMIT 5 ORDER BY created_at DESC

Q33: What is the difference between Page and Slice?
A: Page executes data query + COUNT(*). Slice executes data query + fetches
   size+1 to determine hasNext(). Slice is faster (no COUNT); use for
   infinite scroll. Page needed when total count is required for UI pagination.

Q34: What is @Modifying?
A: Required on @Query methods that execute UPDATE or DELETE JPQL/SQL.
   Use @Modifying(clearAutomatically=true) to clear 1LC after bulk
   operations to prevent stale entity data.

Q35: What is a Spring Data Specification?
A: An interface representing a predicate (WHERE clause fragment). Implements
   JPA Criteria API under the hood. Specifications can be composed with
   .and() and .or() for dynamic query building.

ADVANCED
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q36: What is an AttributeConverter?
A: Implements AttributeConverter<JavaType, DbType> to convert between a Java
   type and DB column type. Use for custom enum storage, encrypted fields,
   or mapping custom value types. autoApply=true applies globally.

Q37: How do you store an enum safely in JPA?
A: @Enumerated(EnumType.STRING) — stores enum name as VARCHAR.
   AVOID EnumType.ORDINAL — stores position, breaks if enum is reordered.
   Or implement AttributeConverter for custom DB codes.

Q38: What is @Version?
A: Marks a field as the optimistic locking version counter. Hibernate
   auto-increments it on UPDATE and includes AND version=? in the WHERE
   clause. Throws OptimisticLockException if version mismatches.

Q39: What is a second-level cache?
A: An application-scoped shared cache across all sessions/transactions
   (unlike 1LC which is session-scoped). Configured with EhCache, Caffeine,
   Infinispan, etc. Reduces repeated DB reads for frequently-accessed data.

Q40: What is JPA auditing in Spring?
A: @EnableJpaAuditing + @CreatedDate/@LastModifiedDate/@CreatedBy/@LastModifiedBy
   on fields in an @MappedSuperclass automatically populate timestamps
   and user info on entity create/update without explicit code.

BEHAVIORAL / SCENARIO QUESTIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q41: Two threads both load a User entity with balance 100 and both try
     to add 50. What's the problem and solution?
A: Lost update. Both read 100, both write 150. The second write overwrites
   the first. Fix: @Version (optimistic — one succeeds, other retries) or
   PESSIMISTIC_WRITE lock (SELECT FOR UPDATE blocks concurrent access).

Q42: Why might a @Transactional service method not roll back on exception?
A: If the exception is a checked exception, Spring defaults to COMMIT.
   Add rollbackFor = Exception.class. Also: if the method is called from
   within the same class (self-invocation), the proxy is bypassed entirely.

Q43: Your findAll() loads 1000 users and performance is poor. What do you do?
A: Check SQL logs: is there an N+1? Fix with JOIN FETCH or @BatchSize.
   Load only needed data with projections. Add pagination (Pageable).
   Check if associations are EAGER (make them LAZY).

Q44: You get a LazyInitializationException in a REST controller. How do you fix it?
A: Don't access lazy fields outside @Transactional. Fix options:
   (1) Join fetch in repository query; (2) @EntityGraph;
   (3) DTO projection (return data, not entity); (4) initialize inside @Transactional.
   Do NOT use open-in-view as a fix.

Q45: How would you implement soft delete with JPA?
A: Add @Column(name="deleted_at") LocalDateTime deletedAt field.
   Use @SQLRestriction("deleted_at IS NULL") (Hibernate 6) to auto-filter
   all queries. Override delete() in repository to set deletedAt instead.
   See also: @SQLDelete("UPDATE users SET deleted_at=NOW() WHERE id=?").

Q46: What is the difference between save() and saveAndFlush() in Spring Data?
A: save() persists the entity to the 1LC but may not flush to DB immediately
   (depends on FlushMode). saveAndFlush() explicitly calls em.flush() after
   save, sending the SQL to DB immediately. Use saveAndFlush() when you
   need the ID or need the change visible within the same transaction.

Q47: What is @Transient?
A: Marks a field to be ignored by JPA (not mapped to any column).
   Use for calculated/derived fields that should not be persisted.

Q48: Can two entities share the same table?
A: Yes, using @SecondaryTable (split one entity across two tables)
   or using inheritance strategies (multiple entities same table via
   SINGLE_TABLE). Also possible with @Table override in a subclass.

Q49: How do you handle a large result set efficiently?
A: Use ScrollableResults / JpaCursorItemReader for streaming.
   Use Pageable for pagination. Use StatelessSession for batch reads.
   Use DTO projections to avoid entity lifecycle overhead.

Q50: What is @EntityGraph and when do you use it over JOIN FETCH?
A: @EntityGraph declaratively specifies which associations to eagerly load
   for a specific query. Use it in Spring Data repositories where you're
   using derived queries and can't write JPQL. JOIN FETCH in @Query gives
   more explicit SQL-level control (INNER vs LEFT JOIN). Both generate
   similar SQL and solve N+1 for that specific query.
