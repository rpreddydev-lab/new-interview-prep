@Embeddable and @Embedded — Value Type Mapping
================================================================

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1. WHAT IS AN EMBEDDABLE?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

An @Embeddable is a class that:
- Has NO @Id (no identity of its own)
- Has NO separate table
- Has its fields mapped as columns in the OWNER entity's table
- Represents a VALUE OBJECT (semantically part of the owner)

Examples of good @Embeddable candidates:
  Address (street, city, zipCode, country)
  Money (amount, currency)
  DateRange (startDate, endDate)
  Name (firstName, lastName)
  GeoLocation (latitude, longitude)

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
2. BASIC EXAMPLE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

@Embeddable
public class Address {
    @Column(name = "street", length = 200)
    private String street;

    @Column(name = "city", length = 100)
    private String city;

    @Column(name = "zip_code", length = 20)
    private String zipCode;

    @Column(name = "country", length = 2)
    private String country;
    // No @Id needed!
    // Must have no-arg constructor (can be package-private)
    // Should implement equals/hashCode for value semantics
}

@Entity
@Table(name = "users")
public class User {
    @Id @GeneratedValue private Long id;
    private String email;

    @Embedded
    private Address address;   // columns embedded into users table
}

Generated table: users(id, email, street, city, zip_code, country)
No address table exists!

3. @ATTRIBUTEOVERRIDE — Rename Columns
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

When embedding the same @Embeddable multiple times, column names collide.
Use @AttributeOverride to rename them per usage.

@Entity
public class Order {
    @Id @GeneratedValue private Long id;

    @Embedded
    @AttributeOverrides({
        @AttributeOverride(name = "street",  column = @Column(name = "billing_street")),
        @AttributeOverride(name = "city",    column = @Column(name = "billing_city")),
        @AttributeOverride(name = "zipCode", column = @Column(name = "billing_zip")),
        @AttributeOverride(name = "country", column = @Column(name = "billing_country"))
    })
    private Address billingAddress;

    @Embedded
    @AttributeOverrides({
        @AttributeOverride(name = "street",  column = @Column(name = "shipping_street")),
        @AttributeOverride(name = "city",    column = @Column(name = "shipping_city")),
        @AttributeOverride(name = "zipCode", column = @Column(name = "shipping_zip")),
        @AttributeOverride(name = "country", column = @Column(name = "shipping_country"))
    })
    private Address shippingAddress;
}

Generated table: orders(id, billing_street, billing_city, billing_zip, billing_country,
                              shipping_street, shipping_city, shipping_zip, shipping_country)

4. NULL HANDLING
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

If the embedded object is null, all its columns are stored as NULL.
If ALL columns are NULL when reading, Hibernate returns null for the embedded field.

// Safe null check in code:
if (user.getAddress() != null) {
    System.out.println(user.getAddress().getCity());
}

// To avoid returning null, initialize in entity:
private Address address = new Address();  // always non-null; columns may be null

5. COLLECTION OF EMBEDDABLES — @ElementCollection
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

@ElementCollection stores a collection of value types in a separate
COLLECTION table (not the main entity table, but not an entity table either).

@Entity
public class User {
    @Id @GeneratedValue private Long id;

    @ElementCollection
    @CollectionTable(
        name = "user_addresses",
        joinColumns = @JoinColumn(name = "user_id")
    )
    private List<Address> addresses = new ArrayList<>();

    @ElementCollection
    @CollectionTable(name = "user_phone_numbers", joinColumns = @JoinColumn(name = "user_id"))
    @Column(name = "phone_number")
    private List<String> phoneNumbers = new ArrayList<>();   // collection of primitives
}

Generated tables:
  user_addresses(user_id, street, city, zip_code, country)  ← collection table
  user_phone_numbers(user_id, phone_number)

Important: @ElementCollection uses REPLACE ALL semantics.
Any change (add/remove) to the collection deletes and re-inserts all rows!
For large collections with frequent changes, prefer @OneToMany to an @Entity.

6. EMBEDDABLE WITH ASSOCIATIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

@Embeddable classes CAN have @ManyToOne associations:

@Embeddable
public class OrderItem {
    private int quantity;
    private BigDecimal unitPrice;

    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "product_id")
    private Product product;   // FK to products table
}

7. INTERVIEW QUICK HITS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: What is the difference between @Embeddable and @Entity?
A: @Entity has its own identity (@Id) and its own table. It represents
   a domain entity with independent lifecycle. @Embeddable is a value type:
   no @Id, no separate table, columns are embedded in the owner's table.
   Deleting the owner deletes the embedded data too (no separate lifecycle).

Q: Why would you use @Embeddable instead of just putting fields directly in the entity?
A: To group related fields into a reusable, semantically meaningful value object.
   Address (street, city, zip, country) can be reused across User, Order, Company.
   It also enables better encapsulation and equals/hashCode per value type.

Q: What is @ElementCollection and when do you use it?
A: @ElementCollection maps a collection of value types (@Embeddable or primitives)
   to a separate collection table without creating a full @Entity.
   Use it for simple collections (phone numbers, tags, addresses) where
   you don't need independent queries on the items. Caveat: any modification
   to the collection causes DELETE-ALL then RE-INSERT — avoid for large, mutable
   collections; use @OneToMany to an @Entity instead.

Q: How do you embed the same @Embeddable class twice in one entity?
A: Use @AttributeOverrides on each @Embedded field to rename the conflicting
   columns (e.g., billing_street vs shipping_street). Without @AttributeOverride,
   Hibernate throws a column name collision error.

Q: Does an @Embeddable object have its own transaction or lifecycle?
A: No. An @Embeddable is part of the owning entity's lifecycle entirely.
   You cannot persist, find, or delete an embedded object independently.
   It exists and is deleted with the owner.
