================================================================
Composite Keys — @EmbeddedId vs @IdClass
================================================================

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1. WHEN ARE COMPOSITE KEYS NEEDED?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Composite (multi-column) primary keys arise from:
- Legacy schemas: PK defined on multiple natural key columns
- Junction tables: (student_id, course_id) PK on enrollment table
- Business requirements: (region_id, product_code) composite business key

JPA offers two approaches:
  @EmbeddedId — composite key is an @Embeddable class, referenced by one field
  @IdClass   — composite key class declared separately; entity has multiple @Id fields

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
2. REQUIREMENTS FOR BOTH APPROACHES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

The key class MUST:
  1. Be public
  2. Have a public no-arg constructor
  3. Implement Serializable
  4. Override equals() and hashCode()
  5. All fields must be of the same type as the entity's PK fields

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
3. APPROACH 1: @EMBEDDEDID
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

@Embeddable
public class EnrollmentId implements Serializable {
    private Long studentId;
    private Long courseId;

    // Required no-arg constructor
    public EnrollmentId() {}

    public EnrollmentId(Long studentId, Long courseId) {
        this.studentId = studentId;
        this.courseId = courseId;
    }

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (!(o instanceof EnrollmentId)) return false;
        EnrollmentId that = (EnrollmentId) o;
        return Objects.equals(studentId, that.studentId) &&
               Objects.equals(courseId, that.courseId);
    }

    @Override
    public int hashCode() {
        return Objects.hash(studentId, courseId);
    }
}

@Entity
@Table(name = "enrollments")
public class Enrollment {
    @EmbeddedId
    private EnrollmentId id;

    @ManyToOne(fetch = FetchType.LAZY)
    @MapsId("studentId")               // maps EnrollmentId.studentId to this FK
    @JoinColumn(name = "student_id")
    private Student student;

    @ManyToOne(fetch = FetchType.LAZY)
    @MapsId("courseId")                // maps EnrollmentId.courseId to this FK
    @JoinColumn(name = "course_id")
    private Course course;

    private LocalDate enrolledOn;
    private String grade;
}

// Repository:
public interface EnrollmentRepository extends JpaRepository<Enrollment, EnrollmentId> {}

// Usage:
EnrollmentId id = new EnrollmentId(studentId, courseId);
Optional<Enrollment> enrollment = enrollmentRepo.findById(id);

// Save:
Enrollment e = new Enrollment();
e.setId(new EnrollmentId(student.getId(), course.getId()));
e.setStudent(student);
e.setCourse(course);
e.setEnrolledOn(LocalDate.now());
enrollmentRepo.save(e);

4. APPROACH 2: @IDCLASS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

// Separate ID class (no @Embeddable annotation)
public class EnrollmentId implements Serializable {
    private Long studentId;
    private Long courseId;

    public EnrollmentId() {}
    public EnrollmentId(Long studentId, Long courseId) {
        this.studentId = studentId;
        this.courseId = courseId;
    }
    // equals + hashCode required
}

@Entity
@Table(name = "enrollments")
@IdClass(EnrollmentId.class)    // declare the ID class
public class Enrollment {
    @Id
    @Column(name = "student_id")
    private Long studentId;     // mirror field name from EnrollmentId

    @Id
    @Column(name = "course_id")
    private Long courseId;      // mirror field name from EnrollmentId

    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "student_id", insertable = false, updatable = false)
    private Student student;

    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "course_id", insertable = false, updatable = false)
    private Course course;

    private LocalDate enrolledOn;
}

// Note: insertable=false, updatable=false on @ManyToOne prevents
// duplicate mapping conflict (both @Id and @ManyToOne share column)

// Usage:
EnrollmentId id = new EnrollmentId(studentId, courseId);
enrollmentRepo.findById(id);

5. COMPARISON: @EMBEDDEDID vs @IDCLASS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Aspect              | @EmbeddedId                          | @IdClass
────────────────────|──────────────────────────────────────|──────────────────────────────
Key class annotation| @Embeddable                          | Plain class (no annotation)
Entity field        | Single @EmbeddedId field             | Multiple @Id fields
JPQL syntax         | WHERE e.id.studentId = :sid          | WHERE e.studentId = :sid (flat)
@MapsId support     | YES (clean FK + composite key)       | Partial (insertable/updatable=false)
Readability         | Explicit (key is a field)            | Flat (key fields at entity level)
Spring Data         | findById(EnrollmentId id)            | findById(EnrollmentId id)
Recommendation      | PREFERRED for associations           | Better for legacy/simple schemas

6. JPQL WITH COMPOSITE KEYS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

// @EmbeddedId — navigate through the id object:
@Query("SELECT e FROM Enrollment e WHERE e.id.studentId = :sid AND e.grade IS NOT NULL")
List<Enrollment> findGradedEnrollmentsByStudent(@Param("sid") Long studentId);

// @IdClass — access fields directly:
@Query("SELECT e FROM Enrollment e WHERE e.studentId = :sid AND e.grade IS NOT NULL")
List<Enrollment> findGradedEnrollmentsByStudent(@Param("sid") Long studentId);

7. INTERVIEW QUICK HITS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: What are the two ways to define a composite primary key in JPA?
A: @EmbeddedId — define an @Embeddable class as the key and reference
   it with a single @EmbeddedId field. @IdClass — annotate the entity
   with @IdClass(KeyClass.class) and declare multiple @Id fields directly
   in the entity matching field names in the key class.

Q: What must the composite key class implement?
A: It must be Serializable, have a public no-arg constructor, and override
   both equals() and hashCode(). Without proper equals/hashCode, the
   persistence context cannot correctly track entities by identity.

Q: What is @MapsId used for?
A: In @EmbeddedId, @MapsId is used on a @ManyToOne field to share
   the FK column with the composite key field. It tells JPA: "the PK
   value for this component comes from this association's FK." This
   keeps the key and FK in sync without duplication.

Q: When would you use @EmbeddedId over @IdClass?
A: @EmbeddedId is preferred when you have @ManyToOne associations in
   the composite key (via @MapsId), because the key class neatly encapsulates
   the identity. @IdClass is simpler for legacy schemas where you just need
   multiple natural key columns without association mapping.

Q: Can you query by composite key in Spring Data JPA?
A: Yes. Use JpaRepository<Entity, CompositeKeyClass>.findById(keyObject).
   In JPQL, navigate through the key: "WHERE e.id.field1 = :val".
