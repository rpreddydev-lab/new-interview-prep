1. HQL vs JPQL
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

HQL (Hibernate Query Language) is Hibernate's native query language,
which is a SUPERSET of JPQL:
  - All valid JPQL is valid HQL
  - HQL adds additional functions and extensions
  - Used via session.createQuery() or entityManager.createQuery()

Key differences:
  JPQL: Standard JPA, works on any JPA provider
  HQL:  Hibernate-specific extensions (extra functions, syntax)

2. BASIC HQL SYNTAX
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

// SELECT all (HQL allows "FROM User" without SELECT)
session.createQuery("FROM User", User.class).list();

// Full JPQL syntax (also valid HQL)
session.createQuery("SELECT u FROM User u WHERE u.active = true", User.class)
       .list();

// Named parameter
session.createQuery("FROM User u WHERE u.email = :email", User.class)
       .setParameter("email", "alice@example.com")
       .getSingleResult();

// Positional parameter (legacy)
session.createQuery("FROM User u WHERE u.email = ?1", User.class)
       .setParameter(1, "alice@example.com")
       .list();

3. HQL-SPECIFIC EXTENSIONS (beyond JPQL)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

a) INSERT INTO ... SELECT (HQL only):
  // Bulk copy from one table/entity to another
  session.createMutationQuery(
      "INSERT INTO ArchivedOrder (id, total, status) " +
      "SELECT o.id, o.total, o.status FROM Order o " +
      "WHERE o.createdAt < :cutoff")
      .setParameter("cutoff", twoYearsAgo)
      .executeUpdate();

b) FROM ELEMENT OF (HQL collection element access):
  // Find orders that contain a specific product
  session.createQuery(
      "SELECT o FROM Order o, IN(o.items) i WHERE i.product.id = :productId",
      Order.class)
      .setParameter("productId", 5L)
      .list();

c) ELEMENTS() and INDICES() (collection functions):
  // Get all products in any order
  session.createQuery(
      "SELECT ELEMENTS(o.items) FROM Order o WHERE o.id = :id",
      OrderItem.class)
      .setParameter("id", orderId)
      .list();

d) HQL Dialect Functions:
  // YEAR, MONTH, DAY (Hibernate 6 adds many date functions)
  session.createQuery(
      "FROM Order o WHERE YEAR(o.createdAt) = :year", Order.class)
      .setParameter("year", 2025)
      .list();

  // CAST (explicit type casting)
  session.createQuery(
      "SELECT CAST(u.age AS String) FROM User u", String.class)
      .list();

  // NULLIF, COALESCE
  session.createQuery(
      "SELECT COALESCE(u.phone, 'N/A') FROM User u", String.class)
      .list();

  // FORMAT (Hibernate 6 date formatting)
  session.createQuery(
      "SELECT FORMAT(o.createdAt, 'yyyy-MM-dd') FROM Order o", String.class)
      .list();

4. PAGINATION AND LIMITING RESULTS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

// Standard JPA/HQL pagination
List<User> page = session.createQuery("FROM User u ORDER BY u.id", User.class)
    .setFirstResult(0)    // offset (0-based)
    .setMaxResults(20)    // limit
    .list();

// Scrollable results (server-side cursor — for large result sets)
ScrollableResults<User> scroll = session
    .createQuery("FROM User u ORDER BY u.id", User.class)
    .scroll(ScrollMode.FORWARD_ONLY);

while (scroll.next()) {
    User u = scroll.get();
    process(u);
    session.evict(u);  // free memory per iteration
}

5. AGGREGATES AND GROUPING
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

// Count
Long count = session.createQuery(
    "SELECT COUNT(u) FROM User u WHERE u.active = true", Long.class)
    .getSingleResult();

// Group by with having
List<Object[]> report = session.createQuery(
    "SELECT u.department, COUNT(u), AVG(u.salary) " +
    "FROM User u GROUP BY u.department HAVING COUNT(u) > 5 " +
    "ORDER BY AVG(u.salary) DESC")
    .list();

for (Object[] row : report) {
    String dept = (String) row[0];
    Long count  = (Long) row[1];
    Double avg  = (Double) row[2];
}

// DTO projection
List<DeptStats> stats = session.createQuery(
    "SELECT new com.example.DeptStats(u.department, COUNT(u), AVG(u.salary)) " +
    "FROM User u GROUP BY u.department", DeptStats.class)
    .list();

6. BULK UPDATE AND DELETE IN HQL
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

// Bulk UPDATE (Hibernate 6 uses createMutationQuery)
int rows = session.createMutationQuery(
    "UPDATE User u SET u.active = false WHERE u.lastLogin < :cutoff")
    .setParameter("cutoff", sixMonthsAgo)
    .executeUpdate();

// Bulk DELETE
int deleted = session.createMutationQuery(
    "DELETE FROM Session s WHERE s.expiredAt < :now")
    .setParameter("now", LocalDateTime.now())
    .executeUpdate();

// Hibernate 5 style (createQuery for DML):
session.createQuery(
    "UPDATE User u SET u.active = false WHERE u.lastLogin < :cutoff")
    .setParameter("cutoff", sixMonthsAgo)
    .executeUpdate();

// IMPORTANT: After bulk DML, clear the 1LC:
session.clear();

7. JOINS IN HQL
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

// Implicit join (navigation)
session.createQuery(
    "FROM Order o WHERE o.user.email = :email", Order.class)
    .setParameter("email", email)
    .list();

// Explicit inner join
session.createQuery(
    "SELECT o FROM Order o JOIN o.user u WHERE u.active = true", Order.class)
    .list();

// Left join with fetch (N+1 fix)
session.createQuery(
    "SELECT DISTINCT u FROM User u LEFT JOIN FETCH u.orders", User.class)
    .list();

// Join with on clause (HQL 5.1+)
session.createQuery(
    "FROM Order o JOIN o.items i ON i.quantity > :minQty", Order.class)
    .setParameter("minQty", 5)
    .list();

8. QUERY HINTS FOR HQL
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

session.createQuery("FROM User u WHERE u.active = true", User.class)
    // Timeout in milliseconds
    .setHint("jakarta.persistence.query.timeout", 5000)
    // Enable query cache
    .setHint("org.hibernate.cacheable", true)
    .setHint("org.hibernate.cacheRegion", "user.active")
    // Read-only (no dirty checking, no snapshot)
    .setHint("org.hibernate.readOnly", true)
    // Fetch size (JDBC hint)
    .setHint("org.hibernate.fetchSize", 100)
    .list();

Q: What is HQL and how does it differ from JPQL?
A: HQL is Hibernate's own query language; a superset of JPQL. All valid
   JPQL is valid HQL, but HQL adds Hibernate-specific functions and syntax
   (INSERT INTO SELECT, IN(collection), extra date/string functions).
   In Spring Boot with JPA API, createQuery() accepts both.

Q: How do you perform bulk UPDATE in HQL?
A: Use session.createMutationQuery("UPDATE Entity e SET...").executeUpdate()
   in Hibernate 6, or createQuery() in Hibernate 5. This bypasses the
   persistence context — call session.clear() afterwards to evict stale entities.

Q: What is ScrollableResults?
A: A Hibernate feature for processing very large result sets as a server-side
   cursor. Fetches rows one-by-one (or in batches), preventing all results
   from loading into memory at once. Ideal for batch exports or ETL.

Q: Can you use HQL for INSERT?
A: Only INSERT INTO ... SELECT (bulk copy). You cannot use HQL for inserting
   a specific set of values like SQL's INSERT INTO ... VALUES (...).
   For inserting a new entity, use session.persist() / em.persist().
