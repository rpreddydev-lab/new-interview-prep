2. DDL-AUTO SETTINGS — CRITICAL FOR PRODUCTION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

spring.jpa.hibernate.ddl-auto=???

Value        | Behavior
─────────────|────────────────────────────────────────────────────
none         | Do nothing to schema (for production with Flyway/Liquibase)
validate     | Validate schema matches entities; FAIL if mismatch (safe)
update       | Attempt to add missing columns/tables (RISKY, avoid production)
create       | Drop all tables and recreate at startup
create-drop  | Drop and recreate at startup; drop on shutdown (tests only)

RECOMMENDATION:
  Development:  create-drop (H2) or update (local DB)
  CI/Testing:   create-drop
  Production:   none (use Flyway/Liquibase for controlled migrations)

WARNING about update:
  - It only ADDS columns, never REMOVES or RENAMES
  - Can leave schema in inconsistent state
  - Does NOT handle complex migrations
  - Never use in production

3. OPEN-IN-VIEW PATTERN — DISABLE IN PRODUCTION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

spring.jpa.open-in-view (default: true in Spring Boot!)

What it does:
  Keeps the EntityManager open for the entire HTTP request lifecycle,
  including the view rendering (Thymeleaf/JSP template).
  This means lazy collections CAN be accessed in the view layer.

Why it's dangerous:
  ✗ Keeps DB connection open throughout entire HTTP request
  ✗ Hides LazyInitializationException problems
  ✗ Encourages lazy loading in views (N+1 in templates)
  ✗ DB connections held too long under load → connection pool exhaustion

Best Practice:
  spring.jpa.open-in-view=false

  Then fix LazyInitializationException properly:
  - Load everything in service layer (within @Transactional)
  - Use DTO projections
  - Use JOIN FETCH / @EntityGraph

hibernate.cfg.xml:
  <?xml version="1.0" encoding="UTF-8"?>
  <!DOCTYPE hibernate-configuration PUBLIC
      "-//Hibernate/Hibernate Configuration DTD 3.0//EN"
      "http://www.hibernate.org/dtd/hibernate-configuration-3.0.dtd">
  <hibernate-configuration>
      <session-factory>
          <property name="hibernate.connection.driver_class">
              com.mysql.cj.jdbc.Driver
          </property>
          <property name="hibernate.connection.url">
              jdbc:mysql://localhost:3306/mydb
          </property>
          <property name="hibernate.connection.username">root</property>
          <property name="hibernate.connection.password">secret</property>
          <property name="hibernate.dialect">
              org.hibernate.dialect.MySQL8Dialect
          </property>
          <property name="hibernate.hbm2ddl.auto">update</property>
          <property name="hibernate.show_sql">true</property>
          <property name="hibernate.format_sql">true</property>
          <mapping class="com.example.User"/>
          <mapping class="com.example.Order"/>
      </session-factory>
  </hibernate-configuration>

Programmatic configuration (no XML):
  Properties props = new Properties();
  props.put("hibernate.connection.url", "jdbc:mysql://localhost:3306/mydb");
  props.put("hibernate.connection.username", "root");
  props.put("hibernate.dialect", "org.hibernate.dialect.MySQL8Dialect");
  props.put("hibernate.hbm2ddl.auto", "update");

  Configuration config = new Configuration();
  config.setProperties(props);
  config.addAnnotatedClass(User.class);

  SessionFactory sf = config.buildSessionFactory(
      new StandardServiceRegistryBuilder()
          .applySettings(config.getProperties())
          .build()
  );

6. MULTIPLE DATASOURCES IN SPRING BOOT
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

// Primary DataSource
@Configuration
@EnableTransactionManagement
@EnableJpaRepositories(
    basePackages = "com.example.primary",
    entityManagerFactoryRef = "primaryEntityManagerFactory",
    transactionManagerRef = "primaryTransactionManager"
)
public class PrimaryDataSourceConfig {

    @Primary
    @Bean @ConfigurationProperties("spring.datasource.primary")
    public DataSource primaryDataSource() {
        return DataSourceBuilder.create().build();
    }

    @Primary
    @Bean
    public LocalContainerEntityManagerFactoryBean primaryEntityManagerFactory(
            EntityManagerFactoryBuilder builder) {
        return builder
            .dataSource(primaryDataSource())
            .packages("com.example.primary.entity")
            .persistenceUnit("primary")
            .build();
    }

    @Primary
    @Bean
    public PlatformTransactionManager primaryTransactionManager(
            @Qualifier("primaryEntityManagerFactory") EntityManagerFactory emf) {
        return new JpaTransactionManager(emf);
    }
}

Q: What does spring.jpa.hibernate.ddl-auto=validate do?
A: It validates that the database schema exactly matches the JPA entity
   definitions at startup. If any table or column is missing or mismatched,
   the application fails to start. Useful to catch schema drift in staging.

Q: Why should you set spring.jpa.open-in-view=false?
A: The default true keeps the EntityManager open for the entire HTTP
   request, holding a DB connection throughout view rendering. This
   encourages lazy loading in views (N+1 risk), and causes connection
   pool exhaustion under high load. Disable it and fix lazy loading properly.

Q: How do you see the actual SQL with bind parameter values in Spring?
A: Set logging.level.org.hibernate.orm.jdbc.bind=TRACE (Hibernate 6) or
   logging.level.org.hibernate.type.descriptor.sql.BasicBinder=TRACE
   (Hibernate 5). Alternatively, use P6Spy for fully substituted SQL.

Q: What is batch_size in Hibernate and what does it do?
A: hibernate.jdbc.batch_size=50 tells Hibernate to group multiple INSERT
   or UPDATE statements into a single batch sent to the DB. Reduces round-
   trips. Requires order_inserts=true and order_updates=true to be effective.
