AWS SECURITY — GUARDDUTY & INSPECTOR
Complete Interview Preparation Guide

1. AMAZON GUARDDUTY OVERVIEW
================================================================

  GuardDuty is an intelligent threat detection service using 
  ML, anomaly detection, and integrated threat intelligence.
  
  "Is something malicious happening in my AWS account right now?"
  
  KEY CHARACTERISTICS:
    - Fully managed (no agents, no infrastructure to manage)
    - Analyzes data sources, does NOT generate network traffic
    - Multi-account via AWS Organizations
    - Finding severity: LOW (1.0-3.9), MEDIUM (4.0-6.9), HIGH (7.0-8.9)
    - Free 30-day trial, then pay per GB of logs analyzed

================================================================

================================================================

  GuardDuty analyzes these data sources automatically (no config needed):
  
  ┌────────────────────────────────┬────────────────────────────────────────┐
  │ Data Source                    │ What GuardDuty Detects                 │
  ├────────────────────────────────┼────────────────────────────────────────┤
  │ VPC Flow Logs                  │ Port scanning, suspicious traffic      │
  │                                │ unusual geo, crypto-mining pools       │

  │ RDS Login Events               │ Brute force, unusual access            │

  └────────────────────────────────┴────────────────────────────────────────┘

3. GUARDDUTY FINDING TYPES
================================================================

  Finding format: ThreatPurpose:ResourceType/ThreatFamilyName.DetectorType.Artifact
  
  Common findings:
  
  UnauthorizedAccess:IAMUser/TorIPCaller
    → IAM API calls from a Tor exit node
  
  UnauthorizedAccess:EC2/SSHBruteForce
    → Brute force SSH attacks against EC2
  
  Discovery:S3/MaliciousIPCaller
    → S3 API calls from known malicious IPs
  
  CryptoCurrency:EC2/BitcoinTool.B
    → EC2 instance is communicating with Bitcoin mining pools
  
  Backdoor:EC2/C&CActivity.B
    → EC2 communicating with known C2 (command-and-control) server
  
  PrivilegeEscalation:IAMUser/AdministrativePermissions
    → IAM user trying to escalate privileges
  
  Impact:S3/MaliciousIPCaller.Custom
    → S3 operations from custom threat intelligence IP

4. GUARDDUTY — MULTI-ACCOUNT
================================================================

  ADMINISTRATOR ACCOUNT:
    - Delegated via AWS Organizations (preferred) or by invitation
    - Sees findings from ALL member accounts
    - Can manage GuardDuty settings for the org
  
  MEMBER ACCOUNTS:
    - Cannot disable GuardDuty if enrolled via Organizations
    - Findings visible to administrator
  
  BEST PRACTICE: 
    - Security/Audit account = GuardDuty administrator
    - Enable auto-enroll for new accounts via Organizations

================================================================
5. GUARDDUTY — AUTOMATION (EventBridge + Lambda)
================================================================

  GuardDuty publishes findings to EventBridge.
  
  Automated response workflow:
  
  GuardDuty Finding → EventBridge Rule → Lambda Function
                                       → SNS (alert)
                                       → SQS (ticket system)
                                       → Step Functions (remediation workflow)
  
  Example: Auto-isolate compromised EC2 instance
  
  EventBridge pattern:
  {
    "source": ["aws.guardduty"],
    "detail-type": ["GuardDuty Finding"],
    "detail": {
      "severity": [{ "numeric": [">=", 7] }],
      "type": [{ "prefix": "Backdoor:EC2" }]
    }
  }
  
  Lambda action: Attach restrictive security group (deny all inbound/outbound)
  to the EC2 instance identified in the finding's resource details.

6. AMAZON INSPECTOR OVERVIEW
================================================================

  Amazon Inspector is a vulnerability management service that 
  continuously scans workloads for software vulnerabilities and 
  unintended network exposure.
  
  "Does my infrastructure have known CVE vulnerabilities?"

================================================================
7. INSPECTOR — TARGETS AND FINDINGS
================================================================

  WHAT INSPECTOR SCANS:
  
  ┌──────────────────────┬──────────────────────────────────────────────────┐
  │ Target               │ What It Checks                                   │
  ├──────────────────────┼──────────────────────────────────────────────────┤
  │ EC2 Instances        │ OS/package CVEs, network reachability (open      │
  │                      │ ports accessible from internet)                  │
  │                      │ Requires SSM Agent on instance                   │
  │ ECR Container Images │ CVEs in container OS packages and language       │
  │                      │ dependencies (npm, pip, Maven)                   │
  │                      │ Scans on push, re-scans when new CVE published   │
  │ Lambda Functions     │ CVEs in Lambda function code packages and        │
  │                      │ dependencies                                     │
  └──────────────────────┴──────────────────────────────────────────────────┘
  
  FINDING SEVERITY: CRITICAL, HIGH, MEDIUM, LOW, INFORMATIONAL
  
  FINDING INCLUDES:
    - CVE ID and CVSS score
    - Affected package + version
    - Fixed-in version
    - Exploitability details
    - Remediation steps

9. AMAZON MACIE
================================================================

  Macie uses ML to discover and protect SENSITIVE DATA in S3.
  
  What it does:
    - Automatically discovers PII (names, SSNs, credit card numbers, etc.)
    - Detects unusual access patterns (large S3 data exfiltration)
    - Identifies S3 buckets with sensitive data that are publicly accessible
    - Findings sent to EventBridge for automated response
  
  Use cases:
    - GDPR/HIPAA compliance — find where PII is stored
    - Alert when sensitive data is put in a bucket not meant for it
    - Data discovery for data governance

10. AWS SECURITY HUB
================================================================

  Security Hub aggregates and normalizes security findings from:
    - GuardDuty
    - Inspector
    - Macie
    - IAM Access Analyzer
    - Firewall Manager
    - Third-party tools
  
  Features:
    - Consolidated view of security posture
    - Continuous compliance checks against benchmarks:
      * CIS AWS Foundations Benchmark
      * AWS Foundational Security Best Practices
      * PCI-DSS
    - Cross-account aggregation via Organizations
    - Automated findings routing via EventBridge

11. INTERVIEW QUESTIONS
================================================================

Q: What does Amazon GuardDuty do and how is it different from AWS Inspector?
A: GuardDuty is a threat detection service — it analyzes VPC Flow Logs, CloudTrail, 
   and DNS logs to detect ACTIVE threats in real time (compromised EC2 instances, 
   unusual API patterns, malicious IPs). It does NOT require agents and does NOT scan 
   for vulnerabilities.
   
   Inspector is a vulnerability scanning service — it checks EC2 instances (via SSM Agent), 
   container images in ECR, and Lambda functions for known CVEs in their software packages. 
   It finds POTENTIAL vulnerabilities (patches needed), not active attacks.
   
   Use both: GuardDuty for runtime threat detection; Inspector for proactive vulnerability 
   management. GuardDuty says "your EC2 is being attacked right now"; Inspector says 
   "your EC2 has an unpatched OpenSSL vulnerability that could be exploited."

Q: How would you automatically respond to a GuardDuty finding indicating an EC2 instance 
   is communicating with a cryptocurrency mining server?
A: Automated incident response:
   1. GuardDuty generates finding: CryptoCurrency:EC2/BitcoinTool.B
   2. GuardDuty sends finding to EventBridge
   3. Create EventBridge rule matching this finding type
   4. EventBridge triggers Lambda function with the finding detail (contains EC2 instance ID, VPC)
   5. Lambda actions:
      a. Create an "isolation" security group that denies all inbound/outbound (0 rules)
      b. Replace all security groups on the instance with the isolation SG (quarantine)
      c. Create EC2 snapshot of the instance for forensics
      d. Post notification to Slack/PagerDuty via SNS
      e. Optionally create an SSM incident
   6. Security team investigates while instance is isolated

Q: How does AWS Inspector help with container security?
A: Inspector integrates with ECR to scan container images continuously:
   1. On push: Inspector automatically scans the image for CVEs in OS packages 
      (apt/yum) and language packages (npm/pip/Maven/gem)
   2. Continuous re-scan: when new CVEs are published, Inspector re-evaluates all 
      existing images — you don't need to push a new image to get updated findings
   3. Findings include: CVE ID, CVSS score, affected package, fixed-in version, 
      and remediation steps
   4. ECR scan findings can gate CI/CD pipelines: if Inspector finds CRITICAL CVEs 
      in an image, fail the pipeline before deploying
   5. Security Hub aggregates Inspector findings across all ECR repos and accounts
