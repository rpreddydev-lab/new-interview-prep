1. CLOUDFORMATION OVERVIEW
================================================================

  AWS CloudFormation is Infrastructure as Code (IaC) — define and 
  provision AWS resources declaratively in YAML or JSON templates.
  
  KEY BENEFITS:
    - Reproducible infrastructure across environments
    - Version control your infrastructure
    - Preview changes before applying (Change Sets)
    - Automatic rollback on failure
    - Dependency management (handles creation order)
    - No cost for CloudFormation itself (only the resources it creates)

================================================================
2. TEMPLATE STRUCTURE
================================================================

  AWSTemplateFormatVersion: "2010-09-09"
  Description: "My application stack"
  
  Parameters:
    EnvironmentType:
      Type: String
      AllowedValues: [dev, staging, prod]
      Default: dev
    InstanceType:
      Type: String
      Default: t3.medium
  
  Mappings:
    RegionAMI:
      us-east-1:
        AMI: ami-0123456789abcdef0
      us-west-2:
        AMI: ami-0fedcba9876543210
  
  Conditions:
    IsProd: !Equals [!Ref EnvironmentType, prod]
  
  Resources:                          # REQUIRED — only required section
    MyEC2Instance:
      Type: AWS::EC2::Instance
      Properties:
        InstanceType: !Ref InstanceType
        ImageId: !FindInMap [RegionAMI, !Ref AWS::Region, AMI]
        SecurityGroupIds:
          - !Ref WebServerSG
        Tags:
          - Key: Environment
            Value: !Ref EnvironmentType
  
    WebServerSG:
      Type: AWS::EC2::SecurityGroup
      Properties:
        GroupDescription: Web server security group
        VpcId: !Ref MyVPC
        SecurityGroupIngress:
          - IpProtocol: tcp
            FromPort: 443
            ToPort: 443
            CidrIp: 0.0.0.0/0
  
    # Conditional resource — only in prod
    ProdAlarm:
      Type: AWS::CloudWatch::Alarm
      Condition: IsProd
      Properties:
        AlarmName: prod-high-cpu
        MetricName: CPUUtilization
        Namespace: AWS/EC2
        Statistic: Average
        Period: 300
        Threshold: 80
        ComparisonOperator: GreaterThanThreshold
        EvaluationPeriods: 2
        AlarmActions:
          - !Sub "arn:aws:sns:${AWS::Region}:${AWS::AccountId}:ops-alerts"
  
  Outputs:
    InstanceId:
      Description: EC2 Instance ID
      Value: !Ref MyEC2Instance
      Export:
        Name: !Sub "${AWS::StackName}-InstanceId"
    WebURL:
      Value: !Sub "https://${MyEC2Instance.PublicDnsName}"

3. PSEUDO PARAMETERS AND INTRINSIC FUNCTIONS
================================================================

  PSEUDO PARAMETERS (AWS-defined, no declaration needed):
    !Ref AWS::AccountId        → current account ID
    !Ref AWS::Region           → current region
    !Ref AWS::StackName        → current stack name
    !Ref AWS::NoValue          → omit a property (useful in conditions)
  
  INTRINSIC FUNCTIONS:
    !Ref LogicalId              → resource ID or parameter value
    !GetAtt Resource.Attr       → attribute of a resource
    !Sub "string ${Var}"        → string substitution
    !Join ["-", [a, b, c]]      → join strings: "a-b-c"
    !Select [0, [a, b, c]]      → select from list: "a"
    !Split [",", "a,b,c"]       → split string to list
    !If [Condition, IfTrue, IfFalse]
    !FindInMap [MapName, Key1, Key2]
    !ImportValue ExportName     → cross-stack reference
    !Base64 value               → base64 encode (UserData)
    !Cidr [ipBlock, count, mask]

4. STACKS AND STACK OPERATIONS
================================================================

  DEPLOY (CREATE/UPDATE):
  aws cloudformation deploy \
    --template-file template.yml \
    --stack-name my-app-prod \
    --parameter-overrides EnvironmentType=prod InstanceType=t3.large \
    --capabilities CAPABILITY_NAMED_IAM \
    --no-fail-on-empty-changeset
  
  CREATE CHANGE SET (preview changes):
  aws cloudformation create-change-set \
    --stack-name my-app-prod \
    --change-set-name update-instance-type \
    --template-body file://template.yml \
    --parameters ParameterKey=InstanceType,ParameterValue=t3.xlarge
  
  # Review changes
  aws cloudformation describe-change-set \
    --stack-name my-app-prod \
    --change-set-name update-instance-type
  
  # Apply change set
  aws cloudformation execute-change-set \
    --stack-name my-app-prod \
    --change-set-name update-instance-type
  
  DELETE STACK:
  aws cloudformation delete-stack --stack-name my-app-prod
  
  STACK STATUS:
  aws cloudformation describe-stacks --stack-name my-app-prod \
    --query "Stacks[0].StackStatus"

5. CAPABILITIES
================================================================

  CloudFormation requires explicit acknowledgment for sensitive operations:
  
  CAPABILITY_IAM:          Template creates/modifies IAM resources
  CAPABILITY_NAMED_IAM:    Template creates IAM resources with custom names
  CAPABILITY_AUTO_EXPAND:  Template uses macros or nested stacks with transforms

6. NESTED STACKS
================================================================

  Break large templates into modular, reusable stacks.
  
  Parent stack references child stacks via AWS::CloudFormation::Stack resource.
  
  # parent-template.yml
  Resources:
    NetworkStack:
      Type: AWS::CloudFormation::Stack
      Properties:
        TemplateURL: https://s3.amazonaws.com/my-templates/network.yml
        Parameters:
          VpcCidr: 10.0.0.0/16
    
    AppStack:
      Type: AWS::CloudFormation::Stack
      DependsOn: NetworkStack
      Properties:
        TemplateURL: https://s3.amazonaws.com/my-templates/app.yml
        Parameters:
          VpcId: !GetAtt NetworkStack.Outputs.VpcId
  
  Child template must be in S3 (not local file).
  Parent stack operations (update/delete) cascade to children.

7. STACK SETS
================================================================

  Deploy same template across MULTIPLE ACCOUNTS and REGIONS simultaneously.
  
  Use cases:
    - Create a CloudTrail trail in every account/region
    - Apply baseline security config org-wide
    - Deploy monitoring stack everywhere
  
  aws cloudformation create-stack-set \
    --stack-set-name org-cloudtrail \
    --template-url https://s3.amazonaws.com/templates/cloudtrail.yml \
    --permission-model SERVICE_MANAGED \
    --auto-deployment Enabled=true,RetainStacksOnAccountRemoval=false
  
  aws cloudformation create-stack-instances \
    --stack-set-name org-cloudtrail \
    --deployment-targets OrganizationalUnitIds=["ou-xxxx-yyyyyyyy"] \
    --regions us-east-1 us-west-2 eu-west-1

8. DRIFT DETECTION
================================================================

  Detect when actual resource state diverges from template definition
  (e.g., someone manually changed a security group).
  
  aws cloudformation detect-stack-drift --stack-name my-app-prod
  aws cloudformation describe-stack-drift-detection-status \
    --stack-drift-detection-id <id>
  aws cloudformation describe-stack-resource-drifts \
    --stack-name my-app-prod \
    --stack-resource-drift-status-filters MODIFIED DELETED

9. ROLLBACK BEHAVIOR
================================================================

  CREATE FAILURE:
    - By default: rollback and delete all created resources
    - DisableRollback flag: keep resources for debugging (troubleshoot)
  
  UPDATE FAILURE:
    - Rollback to previous successful state automatically
    - Failed resource shows UPDATE_FAILED, stack shows UPDATE_ROLLBACK_COMPLETE
  
  ROLLBACK TRIGGERS:
    - CloudWatch alarms: if alarm fires during update → automatic rollback
    - Monitor for N minutes after update (MonitoringTimeInMinutes)

10. INTERVIEW QUESTIONS
================================================================

Q: What is a CloudFormation Change Set and why is it important?
A: A Change Set is a preview of what CloudFormation will do before you apply an update.
   It shows: which resources will be Added, Modified, or Removed; whether the replacement 
   will cause interruption or replacement (creating a new resource and deleting the old one).
   
   Critical use: if a change requires REPLACEMENT of an RDS instance (e.g., changing 
   DB engine), Change Set shows "Replacement: True" — destroying and recreating the DB 
   with potential data loss. Without reviewing Change Sets in production, accidental 
   parameter changes could cause data loss or downtime. Always review Change Sets before 
   executing in production.

Q: What is the difference between CloudFormation Stacks and StackSets?
A: A Stack deploys resources in a single account and region. StackSets deploy the same 
   template across multiple accounts and/or regions from a single management account.
   
   StackSets have two permission models:
   - Self-managed: you manually create execution roles in target accounts
   - Service-managed: AWS Organizations manages the permissions automatically
   
   Use StackSets for org-wide baseline configurations: security monitoring, logging, 
   guardrails, and budget alerts that should exist in every account and region.

Q: How would you handle secrets in CloudFormation templates?
A: NEVER put secrets in plain text in CloudFormation templates:
   1. AWS Secrets Manager dynamic reference:
      !Sub '{{resolve:secretsmanager:prod/db:SecretString:password}}'
   2. SSM Parameter Store dynamic reference:
      !Sub '{{resolve:ssm-secure:/prod/db/password}}'
   3. NoEcho: true on Parameters with Type: String (hides from console, not truly secure)
   
   Dynamic references are resolved at deployment time by CloudFormation calling 
   the service. The value never appears in the template, change sets, or stack events.
   The IAM role running CloudFormation needs permission to access the secret.
