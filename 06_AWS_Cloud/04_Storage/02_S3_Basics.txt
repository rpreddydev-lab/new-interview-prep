AWS STORAGE — S3 BASICS
Complete Interview Preparation Guide

1. WHAT IS AMAZON S3?
================================================================

Amazon Simple Storage Service (S3) is a scalable, durable, and highly
available object storage service. Store and retrieve any amount of data
from anywhere.

Key facts:
  - Object storage (not block or file)
  - Unlimited storage capacity
  - Max object size: 5 TB (use multipart upload for > 5 GB)
  - 99.999999999% (11 nines) durability
  - Globally accessible via HTTP/REST APIs
  - Bucket names are GLOBALLY unique across ALL AWS accounts

================================================================
2. BUCKETS AND OBJECTS
================================================================

BUCKET:
  - Top-level container for objects
  - Created in a specific AWS region
  - Name must be globally unique (DNS-compatible, 3-63 chars, lowercase)
  - Max 100 buckets per AWS account (soft limit; can request increase to 1000)
  - Region-specific but accessible globally via HTTPS

  aws s3 mb s3://my-unique-bucket-name --region us-east-1

OBJECT:
  - A file + metadata stored in a bucket
  - Key: unique name within the bucket (behaves like a file path)
  - Max size: 5 TB per object
  - Metadata: HTTP headers (Content-Type, Cache-Control) + custom key-value pairs

EXAMPLE KEYS (simulate folders using prefixes):
  my-app/images/logo.png
  my-app/videos/intro.mp4
  logs/2024/01/15/app.log
  ← "folders" don't actually exist; key prefix just contains "/"

3. S3 OPERATIONS (CLI + SDK)
================================================================

CLI BASICS:
  # Upload a file
  aws s3 cp localfile.txt s3://my-bucket/path/localfile.txt
  
  # Download a file
  aws s3 cp s3://my-bucket/path/localfile.txt ./downloaded.txt
  
  # List objects
  aws s3 ls s3://my-bucket/
  aws s3 ls s3://my-bucket/my-app/ --recursive
  
  # Sync local folder to S3 (upload only changed files)
  aws s3 sync ./local-folder s3://my-bucket/remote-folder/
  
  # Delete an object
  aws s3 rm s3://my-bucket/path/file.txt
  
  # Generate a presigned URL (temporary access)
  aws s3 presign s3://my-bucket/private-file.pdf --expires-in 3600

AWS SDK v2 FOR JAVA:
  import software.amazon.awssdk.services.s3.S3Client;
  import software.amazon.awssdk.services.s3.model.*;
  import software.amazon.awssdk.core.sync.RequestBody;
  import software.amazon.awssdk.core.ResponseInputStream;
  
  S3Client s3 = S3Client.builder().region(Region.US_EAST_1).build();
  
  // Upload
  s3.putObject(PutObjectRequest.builder()
      .bucket("my-bucket")
      .key("path/file.txt")
      .contentType("text/plain")
      .build(),
      RequestBody.fromString("Hello, S3!"));
  
  // Download
  ResponseInputStream<GetObjectResponse> response = s3.getObject(
      GetObjectRequest.builder()
          .bucket("my-bucket")
          .key("path/file.txt")
          .build()
  );
  byte[] bytes = response.readAllBytes();
  
  // List objects
  ListObjectsV2Response listResponse = s3.listObjectsV2(
      ListObjectsV2Request.builder()
          .bucket("my-bucket")
          .prefix("my-app/")
          .build()
  );
  listResponse.contents().forEach(obj -> 
      System.out.println(obj.key() + " - " + obj.size()));
  
  // Delete
  s3.deleteObject(DeleteObjectRequest.builder()
      .bucket("my-bucket")
      .key("path/file.txt")
      .build());
  
  // Presigned URL
  import software.amazon.awssdk.services.s3.presigner.S3Presigner;
  import software.amazon.awssdk.services.s3.presigner.model.PresignedGetObjectRequest;
  
  S3Presigner presigner = S3Presigner.create();
  PresignedGetObjectRequest presignedRequest = presigner.presignGetObject(
      r -> r.signatureDuration(Duration.ofHours(1))
           .getObjectRequest(g -> g.bucket("my-bucket").key("private.pdf"))
  );
  URL url = presignedRequest.url();

4. MULTIPART UPLOAD
================================================================

For objects > 100 MB, use multipart upload:
  - Parallel uploads of parts (5 MB to 5 GB each)
  - Better performance on large files
  - Automatic retry on failed parts
  - REQUIRED for objects > 5 GB

  AWS SDK handles this automatically with TransferManager:
  
  import software.amazon.awssdk.transfer.s3.S3TransferManager;
  import software.amazon.awssdk.transfer.s3.model.UploadFileRequest;
  
  S3TransferManager transferManager = S3TransferManager.create();
  
  FileUpload upload = transferManager.uploadFile(
      UploadFileRequest.builder()
          .putObjectRequest(p -> p.bucket("my-bucket").key("large-file.zip"))
          .source(Path.of("/local/path/large-file.zip"))
          .build()
  );
  upload.completionFuture().join();  // Wait for completion

5. PRESIGNED URLS
================================================================

A presigned URL grants temporary access to a private S3 object without
requiring AWS credentials.

Use cases:
  - Allow users to download private content (reports, invoices)
  - Allow users to upload directly to S3 without going through your backend
  - Share large files with partners temporarily

How it works:
  1. Backend (with AWS credentials) generates a presigned URL
  2. URL contains HMAC signature, expiration, bucket, key
  3. Frontend/user uses the URL directly (up to expiration)
  4. No AWS credentials needed on client side

Security:
  - URL is time-limited (1 second to 7 days for signed GET)
  - Signed with the generating identity's credentials
  - If credentials expire (short-lived role), the presigned URL also becomes invalid

6. S3 STATIC WEBSITE HOSTING
================================================================

  Host a static website (HTML/CSS/JS) directly from S3:
  
  1. Create bucket with website name (e.g., www.example.com)
  2. Enable static website hosting on the bucket
  3. Set index document: index.html, error document: error.html
  4. Make content public (or use CloudFront OAI for private)
  5. Set DNS (Route 53) to point to S3 website endpoint
  
  Website endpoint format:
    http://bucket-name.s3-website.us-east-1.amazonaws.com
    (Note: HTTP only; for HTTPS use CloudFront in front of S3)
  
  aws s3 website s3://my-website-bucket/ \
    --index-document index.html \
    --error-document error.html

7. S3 EVENT NOTIFICATIONS
================================================================

  Trigger Lambda, SNS, or SQS on S3 events:
    - s3:ObjectCreated:* — any create event
    - s3:ObjectRemoved:* — any delete event
    - s3:ObjectRestore:* — Glacier restore events
    - s3:ReducedRedundancyLostObject
  
  Filter by prefix and/or suffix:
    Prefix: images/  → only trigger for objects in images/ folder
    Suffix: .jpg     → only trigger for JPEG files
  
  Use case: Upload image → S3 → triggers Lambda → resize/thumbnail → save back to S3
  
  CloudTrail data events + EventBridge can capture ALL S3 API calls for richer routing.

8. INTERVIEW QUESTIONS
================================================================

Q: What is an S3 object key and how is it related to "folders" in S3?
A: An S3 object key is the unique identifier for an object within a bucket.
   S3 is a flat key-value store — there are no real folders. However, keys
   can contain "/" characters, simulating a folder hierarchy. For example,
   the key "myapp/images/logo.png" looks like logo.png in an images folder,
   but it's actually just a key with slashes. The AWS console and CLI present
   these as folders for usability.

Q: What is the maximum size of an S3 object?
A: The maximum object size in S3 is 5 TB. However, a single PUT request can
   upload at most 5 GB. For objects larger than 5 GB, multipart upload is
   REQUIRED. AWS recommends using multipart upload for objects larger than 100 MB
   for better performance (parallel uploads) and resilience (retry individual parts).

Q: What is a presigned URL and when would you use it?
A: A presigned URL is a temporary URL with an embedded HMAC signature that grants
   time-limited access to a private S3 object. Use it when you want users to
   download private content (documents, reports) or upload files directly to S3
   without exposing your AWS credentials. The backend generates the URL, the client
   uses it directly. Common patterns: user downloads their invoice PDF, user uploads
   profile picture directly to S3 (presigned PUT URL).

Q: How does S3 event notification work and what can it trigger?
A: Configure event notifications on an S3 bucket to trigger when objects are
   created, deleted, or restored. You can filter by key prefix/suffix. Destinations:
   Lambda (process the object), SNS (fan-out notification), SQS (queue for async
   processing). Common pattern: upload CSV to S3 → S3 triggers Lambda → Lambda
   processes data → stores results in DynamoDB.

Q: What is the difference between S3 website endpoint and S3 REST API endpoint?
A: The REST API endpoint (s3.amazonaws.com) is for programmatic access (PUT, GET,
   DELETE objects). The website endpoint is for serving static websites and handles
   HTML redirects, index documents, and error documents. The website endpoint only
   supports GET and HEAD requests. The website endpoint is HTTP only — for HTTPS
   static websites, use CloudFront with an S3 origin.
