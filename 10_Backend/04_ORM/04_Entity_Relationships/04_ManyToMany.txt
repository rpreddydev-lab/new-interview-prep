1. OVERVIEW
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

@ManyToMany models a many-to-many relationship between two entities.
JPA creates (or expects) a join table that holds FK pairs.

Examples:
  Student ↔ Course         (a student takes many courses, a course has many students)
  Employee ↔ Project
  Tag ↔ Article

Schema:
  students(id, name)
  courses(id, title)
  student_courses(student_id, course_id)   ← join table (no extra columns)

Default fetch type for @ManyToMany: LAZY

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
2. BASIC BIDIRECTIONAL @MANYTOMANY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

@Entity
public class Student {
    @Id @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    private String name;

    @ManyToMany(cascade = {CascadeType.PERSIST, CascadeType.MERGE})
    @JoinTable(
        name = "student_courses",
        joinColumns = @JoinColumn(name = "student_id"),
        inverseJoinColumns = @JoinColumn(name = "course_id")
    )
    private Set<Course> courses = new HashSet<>();

    // Helper methods (always synchronize both sides)
    public void addCourse(Course course) {
        courses.add(course);
        course.getStudents().add(this);
    }

    public void removeCourse(Course course) {
        courses.remove(course);
        course.getStudents().remove(this);
    }
}

@Entity
public class Course {
    @Id @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    private String title;

    @ManyToMany(mappedBy = "courses")   // inverse side
    private Set<Student> students = new HashSet<>();
}

Notes:
- Use Set, not List, to avoid duplicate rows in the join table
- Do NOT cascade REMOVE or ALL on @ManyToMany — it can delete the other entity!
- The owner side (Student) has @JoinTable; inverse side uses mappedBy

3. JOIN TABLE WITH EXTRA COLUMNS (Junction Entity Pattern)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

When the join table has extra columns (e.g., enrolled_on, grade),
you CANNOT use @ManyToMany. Instead, model the join table as an entity.

Schema:
  student_courses(student_id, course_id, enrolled_on, grade)

Option A: @EmbeddedId composite key

@Embeddable
public class EnrollmentId implements Serializable {
    private Long studentId;
    private Long courseId;
    // equals + hashCode required
}

@Entity
@Table(name = "student_courses")
public class Enrollment {
    @EmbeddedId
    private EnrollmentId id;

    @ManyToOne(fetch = FetchType.LAZY)
    @MapsId("studentId")
    @JoinColumn(name = "student_id")
    private Student student;

    @ManyToOne(fetch = FetchType.LAZY)
    @MapsId("courseId")
    @JoinColumn(name = "course_id")
    private Course course;

    private LocalDate enrolledOn;
    private String grade;
}

// Student entity:
@OneToMany(mappedBy = "student", cascade = CascadeType.ALL, orphanRemoval = true)
private List<Enrollment> enrollments = new ArrayList<>();

// Course entity:
@OneToMany(mappedBy = "course", cascade = CascadeType.ALL, orphanRemoval = true)
private List<Enrollment> enrollments = new ArrayList<>();

Option B: Surrogate ID (simpler, less strict FK constraint)

@Entity
@Table(name = "student_courses")
public class Enrollment {
    @Id @GeneratedValue private Long id;

    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "student_id")
    private Student student;

    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "course_id")
    private Course course;

    private LocalDate enrolledOn;
    private String grade;
}

4. EQUALS/HASHCODE FOR @MANYTOMANY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

With Set<T>, equals and hashCode must be stable across lifecycle transitions.
Recommended: use business key (not surrogate ID — it's null before persist).

@Override
public boolean equals(Object o) {
    if (this == o) return true;
    if (!(o instanceof Course)) return false;
    Course c = (Course) o;
    return title != null && title.equals(c.title);  // business key
}

@Override
public int hashCode() {
    return getClass().hashCode();  // stable hash; title used only in equals
}

5. PERFORMANCE GOTCHAS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Problem: Using List instead of Set
  @ManyToMany
  private List<Course> courses;  // BAD
  // Adding or removing a course loads the entire list first,
  // then deletes ALL rows and re-inserts! (Hibernate bag behavior)

Fix: Always use Set for @ManyToMany:
  private Set<Course> courses = new HashSet<>();

Problem: Loading both collections in one JOIN FETCH
  @Query("SELECT DISTINCT s FROM Student s " +
         "JOIN FETCH s.courses JOIN FETCH s.tags")
  // FAILS: HibernateException: cannot simultaneously fetch multiple bags
  // Fix: fetch one collection per query, or use @BatchSize

Fix with @BatchSize:
  @ManyToMany
  @BatchSize(size = 25)
  private Set<Course> courses = new HashSet<>();

6. INTERVIEW QUICK HITS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: Why should you NOT use CascadeType.REMOVE or ALL on @ManyToMany?
A: Because removing a Student would cascade-delete the Course entity
   itself, not just the join table row. Only cascade PERSIST and MERGE
   for @ManyToMany.

Q: Why use Set instead of List for @ManyToMany?
A: With List (bag semantics), any modification to the collection causes
   Hibernate to DELETE all rows in the join table and re-INSERT them.
   Set uses individual DELETE/INSERT statements, which is far more
   efficient and correct.

Q: When should you stop using @ManyToMany and create a junction entity?
A: As soon as the join table needs any extra column (like enrolledOn,
   grade, status). At that point, model the join table as its own
   @Entity with @ManyToOne references to each side.

Q: Which side should be the owner in @ManyToMany?
A: By convention, pick the side that is typically saved first or
   makes semantic sense as the "primary" entity. The owner side has
   @JoinTable; the inverse uses mappedBy. The FK values are read
   from the owner's collection.

Q: Can you map @ManyToMany with a composite key?
A: Yes. Use a @EmbeddedId with @MapsId on each @ManyToOne inside the
   junction entity. This enforces a unique (student_id, course_id)
   constraint at the DB and JPA layers.
