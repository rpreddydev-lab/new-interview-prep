1. SESSIONFACTORY — APPLICATION-SCOPED
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

SessionFactory:
  - Application-scoped, created ONCE at startup
  - Thread-safe — safe to share across all threads
  - Heavyweight: scans entity classes, builds metadata, initializes 2LC
  - Corresponds to EntityManagerFactory in JPA
  - One SessionFactory per DataSource

Obtaining SessionFactory:
  // In Spring Boot (from EntityManagerFactory):
  @Autowired
  EntityManagerFactory emf;

  SessionFactory sf = emf.unwrap(SessionFactory.class);

  // Standalone (without Spring):
  Configuration config = new Configuration().configure("hibernate.cfg.xml");
  SessionFactory sf = config.buildSessionFactory();

  // Or via ServiceRegistry (Hibernate 5+):
  StandardServiceRegistry registry = new StandardServiceRegistryBuilder()
      .configure("hibernate.cfg.xml").build();
  Metadata metadata = new MetadataSources(registry)
      .addAnnotatedClass(User.class)
      .buildMetadata();
  SessionFactory sf = metadata.buildSessionFactory();

Shutdown:
  sf.close();  // releases connections, stops 2LC

2. SESSION — REQUEST/TRANSACTION-SCOPED
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Session:
  - Represents a "unit of work" (usually one transaction)
  - NOT thread-safe — one Session per thread
  - Lightweight: cheap to create and destroy
  - Contains the First-Level Cache (persistence context)
  - Corresponds to EntityManager in JPA

Obtaining Session:
  Session session = sessionFactory.openSession();
  // Or from EntityManager (preferred in Spring):
  Session session = entityManager.unwrap(Session.class);

Session lifecycle:
  Session s = sf.openSession();
  Transaction tx = s.beginTransaction();
  try {
      // work
      tx.commit();
  } catch (Exception e) {
      tx.rollback();
  } finally {
      s.close();  // must always close
  }

3. SESSION API — KEY METHODS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

// ─── CRUD ─────────────────────────────────────────────────

// save (legacy Hibernate — returns generated ID immediately)
Long id = (Long) session.save(user);       // deprecated in Hibernate 6

// persist (JPA standard — no immediate return)
session.persist(user);

// get (returns entity or null, hits DB or 1LC)
User user = session.get(User.class, 1L);   // = em.find()

// load (returns proxy; throws ObjectNotFoundException if not found)
User proxy = session.load(User.class, 1L); // = em.getReference()

// update (reattach detached entity — Hibernate-specific)
session.update(detachedUser);              // deprecated in Hibernate 6

// saveOrUpdate (insert if new, update if existing)
session.saveOrUpdate(user);                // deprecated in Hibernate 6

// merge (JPA standard - preferred over saveOrUpdate)
User managed = (User) session.merge(user);

// delete (remove entity)
session.delete(user);     // deprecated; use session.remove()
session.remove(user);     // JPA standard

// refresh (reload from DB)
session.refresh(user);

// ─── QUERIES ──────────────────────────────────────────────

// HQL query
List<User> users = session.createQuery(
    "FROM User u WHERE u.active = true", User.class
).list();

// Native SQL query
List<User> users = session.createNativeQuery(
    "SELECT * FROM users WHERE active = 1", User.class
).list();

// Criteria query (same as JPA)
CriteriaBuilder cb = session.getCriteriaBuilder();
// ...

// ─── CACHE CONTROL ─────────────────────────────────────────
session.evict(entity);                     // remove from 1LC
session.clear();                           // clear all from 1LC
session.contains(entity);                 // is entity managed?

// ─── TRANSACTION ───────────────────────────────────────────
Transaction tx = session.beginTransaction();
session.getTransaction().commit();
session.getTransaction().rollback();

// ─── HIBERNATE-SPECIFIC ────────────────────────────────────
session.setReadOnly(entity, true);
session.setDefaultReadOnly(true);
session.enableFilter("activeFilter").setParameter("isActive", true);
session.disableFilter("activeFilter");

4. CURRENTTRANSACTIONALSESSION (SPRING MANAGED)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

In Spring, you DON'T open/close Sessions manually.
Spring manages the Session lifecycle tied to the transaction.

// Accessing the current transaction-bound session:
Session session = sessionFactory.getCurrentSession();
// Equivalent to entityManager.unwrap(Session.class) in Spring context

@Service
public class UserService {

    @Autowired
    private EntityManagerFactory emf;

    @Transactional
    public void doHibernateWork() {
        Session session = emf.unwrap(SessionFactory.class).getCurrentSession();
        // session is the same as current EntityManager's backing session
        session.enableFilter("activeFilter");
        // ...
    }
}

5. STATELESS SESSION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

StatelessSession:
  - Bypasses ALL caching (1LC, 2LC, query cache)
  - No dirty checking
  - No cascading
  - Lower memory footprint — ideal for bulk operations
  - Must explicitly call insert/update/delete methods

Use case: Bulk ETL, data migration, large batch processing

@Autowired
EntityManagerFactory emf;

public void bulkInsert(List<Product> products) {
    SessionFactory sf = emf.unwrap(SessionFactory.class);
    try (StatelessSession stateless = sf.openStatelessSession()) {
        Transaction tx = stateless.beginTransaction();
        try {
            for (Product p : products) {
                stateless.insert(p);   // immediate INSERT, no 1LC
            }
            tx.commit();
        } catch (Exception e) {
            tx.rollback();
            throw e;
        }
    }
}

public void scrollAndProcess() {
    SessionFactory sf = emf.unwrap(SessionFactory.class);
    try (StatelessSession stateless = sf.openStatelessSession()) {
        ScrollableResults<User> results = stateless
            .createQuery("FROM User u", User.class)
            .scroll(ScrollMode.FORWARD_ONLY);

        while (results.next()) {
            User u = results.get();
            process(u);
            // No memory accumulation — no 1LC
        }
    }
}

Q: What is the relationship between Session and EntityManager?
A: Session is the Hibernate native API; EntityManager is the JPA standard.
   In Spring Boot, EntityManager is backed by a Hibernate Session.
   You can get the Session via entityManager.unwrap(Session.class).

Q: What is SessionFactory and when is it created?
A: SessionFactory is the Hibernate equivalent of EntityManagerFactory.
   It's created once at application startup, is thread-safe, and scans
   all entity classes. Spring Boot creates and manages it automatically.

Q: What is StatelessSession and when would you use it?
A: A Hibernate Session variant that bypasses all caching, dirty checking,
   and cascading. Used for bulk batch operations (millions of rows) where
   you want direct, low-overhead DB access without filling up memory with
   cached entities.

Q: What is the difference between session.get() and session.load()?
A: get() hits the DB (or 1LC) immediately and returns null if not found.
   load() returns a proxy without hitting the DB; an exception is thrown
   on first property access if the entity doesn't exist. Corresponds to
   em.find() and em.getReference() in JPA.
