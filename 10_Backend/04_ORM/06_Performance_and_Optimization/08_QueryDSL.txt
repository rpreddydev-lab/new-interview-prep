QUERYDSL — TYPE-SAFE JPA QUERIES
===================================

=== CONCEPT ===

QueryDSL generates type-safe query classes (Q-classes) from your JPA entities.
Queries are validated at compile time, not runtime.

Problems with @Query + JPQL strings:
  - Typos in field names: compile-time passes, runtime fails
  - Refactoring entities doesn't update query strings
  - Complex dynamic queries are hard to build safely

QueryDSL solution:
  - Q-classes generated from entities (QUser, QOrder, etc.)
  - IDE auto-completion for fields and predicates
  - Refactoring-safe: change entity field → compiler error in query
  - Dynamic queries built fluently

=== Q-CLASS GENERATION ===

Given entity:
  @Entity
  public class User {
      @Id private Long id;
      private String firstName;
      private String lastName;
      private String email;
      private Integer age;
      @ManyToOne private Department department;
  }

Generated class (QUser.java — don't edit, regenerated on build):
  public class QUser extends EntityPathBase<User> {
      public static final QUser user = new QUser("user");
      public final NumberPath<Long> id = createNumber("id", Long.class);
      public final StringPath firstName = createString("firstName");
      public final StringPath lastName = createString("lastName");
      public final StringPath email = createString("email");
      public final NumberPath<Integer> age = createNumber("age", Integer.class);
      public final QDepartment department;
  }

=== JPAQUERYRESULTFACTORY USAGE ===

@Repository
public class UserQueryRepository {

    @PersistenceContext
    private EntityManager em;

    private JPAQueryFactory queryFactory;

    @PostConstruct
    public void init() {
        this.queryFactory = new JPAQueryFactory(em);
    }

    // Simple query
    public List<User> findByDepartment(String deptName) {
        QUser user = QUser.user;
        QDepartment dept = QDepartment.department;

        return queryFactory
            .selectFrom(user)
            .join(user.department, dept)
            .where(dept.name.eq(deptName))
            .fetch();
    }

    // Dynamic query (build predicate conditionally)
    public List<User> search(String firstName, String email, Integer minAge) {
        QUser user = QUser.user;
        BooleanBuilder predicate = new BooleanBuilder();

        if (firstName != null) predicate.and(user.firstName.containsIgnoreCase(firstName));
        if (email != null)     predicate.and(user.email.eq(email));
        if (minAge != null)    predicate.and(user.age.goe(minAge));

        return queryFactory
            .selectFrom(user)
            .where(predicate)
            .orderBy(user.lastName.asc())
            .fetch();
    }

    // Projection (select specific fields)
    public List<UserDto> findUserDtos() {
        QUser user = QUser.user;
        return queryFactory
            .select(Projections.constructor(UserDto.class,
                user.firstName, user.email))
            .from(user)
            .fetch();
    }

    // Aggregation
    public Map<String, Long> countByDepartment() {
        QUser user = QUser.user;
        QDepartment dept = QDepartment.department;
        return queryFactory
            .select(dept.name, user.id.count())
            .from(user)
            .join(user.department, dept)
            .groupBy(dept.name)
            .fetch()
            .stream()
            .collect(Collectors.toMap(
                t -> t.get(dept.name),
                t -> t.get(user.id.count())
            ));
    }
}

=== SPRING DATA + QUERYDSL INTEGRATION ===

Extend QuerydslPredicateExecutor for automatic integration:

public interface UserRepository extends JpaRepository<User, Long>,
                                         QuerydslPredicateExecutor<User> {
}

Usage (in service/controller):
  @Autowired UserRepository repo;

  QUser user = QUser.user;
  Predicate predicate = user.age.between(25, 35)
      .and(user.email.endsWith("@company.com"));

  Iterable<User> users = repo.findAll(predicate);

  // With sorting
  repo.findAll(predicate, Sort.by("lastName"));

  // With pagination
  Page<User> page = repo.findAll(predicate, PageRequest.of(0, 10));

=== PREDICATES ===

// StringPath
user.firstName.eq("Alice")
user.firstName.ne("Alice")
user.firstName.startsWith("Al")
user.firstName.endsWith("ice")
user.firstName.containsIgnoreCase("ali")
user.firstName.isNull()
user.firstName.isNotNull()
user.firstName.in("Alice", "Bob", "Charlie")

// NumberPath
user.age.eq(25)
user.age.gt(18)       // greater than
user.age.goe(18)      // greater than or equal
user.age.lt(65)       // less than
user.age.loe(65)      // less than or equal
user.age.between(18, 65)

// Combining predicates
user.age.gt(18).and(user.email.isNotNull())
user.department.name.eq("HR").or(user.department.name.eq("IT"))

=== QUERYDSL VS JOOQ VS CRITERIA API ===

QueryDSL:
  + Type-safe, JPA-based, good Spring Data integration
  + Code generation from JPA entities
  - Build setup needed, generated sources can clutter IDE

jOOQ:
  + SQL-first, supports DB-specific features
  + Complete SQL type safety
  - Requires DB connection at build time (for code generation)
  - Commercial license for some DBs

Criteria API (JPA standard):
  + No extra dependency
  - Very verbose, hard to read
  - CriteriaBuilder.cb() boilerplate everywhere
