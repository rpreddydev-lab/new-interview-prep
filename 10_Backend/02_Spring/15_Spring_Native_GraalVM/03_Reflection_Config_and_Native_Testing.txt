======================================================
GRAALVM NATIVE IMAGE — REFLECTION CONFIG & NATIVE TESTING
======================================================

1. REFLECTION CONFIGURATION FILE
──────────────────────────────────
Location (auto-processed by GraalVM):
  src/main/resources/META-INF/native-image/<group-id>/<artifact-id>/
    reflect-config.json
    resource-config.json
    proxy-config.json
    serialization-config.json
    jni-config.json

reflect-config.json example:
  [
    {
      "name": "com.example.OrderDto",
      "allDeclaredConstructors": true,
      "allPublicConstructors": true,
      "allDeclaredMethods": true,
      "allPublicMethods": true,
      "allDeclaredFields": true,
      "allPublicFields": true
    },
    {
      "name": "com.example.PaymentRequest",
      "allDeclaredConstructors": true,
      "allPublicFields": true
    }
  ]

resource-config.json:
  {
    "resources": {
      "includes": [
        {"pattern": "\\Qdata/countries.json\\E"},
        {"pattern": "\\Qconfig/.*\\.yaml\\E"}
      ]
    }
  }

proxy-config.json:
  [
    ["com.example.service.OrderService", "org.springframework.transaction.interceptor.TransactionalProxy"]
  ]


2. NATIVE IMAGE TRACING AGENT
───────────────────────────────
Auto-generate config files by running the app with tracing agent.
The agent observes reflection, resource, and proxy usage and records it.

  # Run the app with tracing agent:
  java -agentlib:native-image-agent=config-output-dir=src/main/resources/META-INF/native-image \
       -jar target/app.jar

  # Then exercise all features (manually or via tests):
  curl http://localhost:8080/api/orders
  curl -X POST http://localhost:8080/api/payments

  # Stop the app → config files are generated

  # Build native image with generated configs:
  ./mvnw -Pnative native:compile

Merge existing configs:
  -agentlib:native-image-agent=config-merge-dir=...
  # Merges with existing files instead of overwriting


3. NATIVE IMAGE COMPATIBILITY ISSUES
──────────────────────────────────────
Common issues and fixes:

a) Missing reflection:
   Error: "Class not found" or "No such method" at runtime
   Fix: Add to reflect-config.json or use @RegisterReflectionForBinding

b) Dynamic class loading (Class.forName):
   Error: ClassNotFoundException in native
   Fix: Hint via RuntimeHints:
     hints.reflection().registerType(Class.forName("com.example.DynamicClass"),
         MemberCategory.INVOKE_PUBLIC_METHODS);

c) Resources not included:
   Error: getResourceAsStream returns null
   Fix: Add to resource-config.json or:
     hints.resources().registerPattern("data/config.json");

d) CGLIB proxies not supported (Spring uses CGLIB for @Configuration):
   Spring 6 switched to @interface proxies (interface-based) where possible.
   Fix: Use interface-based design; avoid CGLIB-requiring patterns in native.

e) Logback/Log4j2 — some appenders may not work natively:
   Fix: Use simple console logging in native profile.

f) Hibernate — extra hints needed for entity classes:
   Spring Boot auto-configures Hibernate native hints for known entities.
   Custom entity types may need explicit registration.


4. NATIVE PROFILE IN SPRING BOOT
──────────────────────────────────
Define native-specific properties:
  application-native.yml:
    spring:
      jmx:
        enabled: false       # JMX not needed in native
      datasource:
        hikari:
          maximum-pool-size: 5  # lower resource usage in native

  # Active during native build and runtime:
  @SpringBootApplication
  public class App {
      public static void main(String[] args) {
          SpringApplication.run(App.class, args);
      }
  }

  # Build native with profile:
  ./mvnw -Pnative spring-boot:build-image -Dspring.profiles.active=native


5. TESTING NATIVE COMPATIBILITY
────────────────────────────────
Level 1 — AOT mode on JVM (fastest feedback):
  ./mvnw test -Dspring.aot.enabled=true
  # Runs with AOT-generated code but on JVM — catches most issues

Level 2 — Native image test:
  ./mvnw -Pnative native:test
  # Builds native and runs JUnit tests against it
  # Slow (minutes) but most accurate

Level 3 — Integration test with Testcontainers:
  @SpringBootTest(webEnvironment = WebEnvironment.RANDOM_PORT)
  @ActiveProfiles("native")
  @Tag("native")
  class NativeIntegrationTest {
      // Full app running; test via HTTP
  }

Native-specific test utilities:
  @EnabledInNativeImage  — only run in native image
  @DisabledInNativeImage — skip in native image

Detecting environment:
  @Autowired
  private Environment env;
  boolean isNative = env.matchesProfiles("native");

  // Or:
  ImageInfo.inImageCode()  // GraalVM API


6. SPRING BOOT + GRAALVM SUPPORTED FEATURES
─────────────────────────────────────────────
Fully supported in native:
  ✅ Spring MVC, Spring WebFlux
  ✅ Spring Data JPA (with Hibernate)
  ✅ Spring Data Redis, MongoDB, Elasticsearch
  ✅ Spring Security
  ✅ Spring Kafka, Spring AMQP
  ✅ Spring Actuator (partial — some endpoints disabled)
  ✅ Spring Cache
  ✅ Flyway, Liquibase
  ✅ Micrometer, OpenTelemetry

Partially supported / needs hints:
  ⚠️ Jackson custom serializers (need hints)
  ⚠️ Dynamic SpEL expressions
  ⚠️ Groovy DSL
  ⚠️ Some third-party libraries (check GraalVM compatibility tracker)

Not supported / complex workarounds:
  ❌ Aspect-oriented programming with CGLIB in complex scenarios
  ❌ Truly dynamic code (runtime bytecode generation)
  ❌ JRebel-style hot reload


7. NATIVE IMAGE BUILD OPTIMIZATION
────────────────────────────────────
Reduce build time:
  # Increase memory for native build (needs 4–8GB):
  export MAVEN_OPTS="-Xmx8g"
  ./mvnw -Pnative native:compile

  # Use GraalVM's quick build option (less optimization, faster build):
  native-image -O0 ...   # O0 = no optimization (dev), Ob = quick build

  # Enable PGO (Profile-Guided Optimization) for peak performance:
  # Step 1: Build instrumented binary
  # Step 2: Run under load to collect profile data
  # Step 3: Rebuild with profile data

Size optimization:
  # Strip debug info:
  native-image -H:+BuildReport --no-fallback -Os ...
  # -Os = optimize for size


8. INTERVIEW QUESTIONS
──────────────────────
Q: How do you generate native image configuration files for a Spring Boot app?
A: Use the native-image tracing agent. Run the app with the agent attached
   (-agentlib:native-image-agent=config-output-dir=...) and exercise all
   code paths. The agent generates reflect-config.json, resource-config.json,
   proxy-config.json, etc. These are placed under META-INF/native-image/.

Q: How do you test native image compatibility without a full native build?
A: Run with -Dspring.aot.enabled=true on JVM — this uses AOT-generated code
   without native compilation, catching most compatibility issues quickly.
   Full native testing requires ./mvnw -Pnative native:test which is slow.

Q: What types of reflection need to be registered in native image config?
A: Any class accessed via: Class.forName(), reflection APIs, Jackson polymorphism,
   Hibernate entity introspection, Spring @ConditionalOn* logic that uses
   reflection. Spring Boot auto-registers many via AOT; custom types need
   explicit RuntimeHints or reflect-config.json entries.

Q: Why is CGLIB problematic in GraalVM native images?
A: CGLIB generates bytecode at runtime to create proxy subclasses. GraalVM
   native images have a closed-world constraint — all bytecode must be known
   at build time. Spring 6 minimizes CGLIB use by preferring interface-based
   proxies and AOT-generated proxy classes. @Configuration classes still use
   CGLIB but Spring handles this via AOT proxy generation.
