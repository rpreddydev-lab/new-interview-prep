  1. WHAT IS CONTENT NEGOTIATION?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Content Negotiation = the mechanism by which a client and server
agree on the format (media type) for the response.

Client signals preference via:
  - Accept header              (most common)
  - URL file extension         e.g. /users/1.json
  - Request parameter          e.g. /users/1?format=json
  - Path variable (custom)

Spring MVC resolves content type via ContentNegotiationStrategy
and delegates serialization to HttpMessageConverter implementations.

Flow:
  Client Request
      │  Accept: application/json
      ▼
  DispatcherServlet
      │
      ▼
  ContentNegotiationManager   ← determines best media type
      │
      ▼
  HandlerAdapter              ← invokes controller method
      │  Returns Object
      ▼
  HttpMessageConverter        ← serializes to JSON/XML/...
      │
      ▼
  Response body

  2. ACCEPT HEADER — HOW IT WORKS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

The Accept header carries a comma-separated list of media types
with optional quality factors (q-values, 0.0–1.0, default 1.0).

  Accept: application/json, application/xml;q=0.8, */*;q=0.5
                                              ↑ lower priority    ↑ wildcard fallback

Spring evaluates:
  1. Requested media types (from Accept header)
  2. Producible media types (from controller @RequestMapping produces)
  3. Best match via MimeType.isCompatibleWith() + q-value ordering

If no match → 406 Not Acceptable

  3. @RequestMapping — produces and consumes
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

produces — restricts which media types this method CAN return
consumes — restricts which Content-Type it CAN accept

@RestController
@RequestMapping("/api/v1/products")
public class ProductController {

    // Only serves JSON responses
    @GetMapping(produces = MediaType.APPLICATION_JSON_VALUE)
    public List<Product> listJson() { ... }

    // Only serves XML responses
    @GetMapping(produces = MediaType.APPLICATION_XML_VALUE)
    public List<Product> listXml() { ... }

    // Accepts both but produces only JSON
    @PostMapping(
        consumes = { MediaType.APPLICATION_JSON_VALUE,
                     MediaType.APPLICATION_XML_VALUE },
        produces = MediaType.APPLICATION_JSON_VALUE
    )
    public Product create(@RequestBody Product p) { ... }
}

  Spring maps the request to the correct method by matching
  the request's Accept header against each method's produces.

  4. HttpMessageConverter — THE SERIALIZATION ENGINE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

HttpMessageConverter<T> interface:
  boolean canRead(Class<?> clazz, MediaType mediaType)
  boolean canWrite(Class<?> clazz, MediaType mediaType)
  List<MediaType> getSupportedMediaTypes()
  T read(Class<? extends T> clazz, HttpInputMessage inputMessage)
  void write(T t, MediaType contentType, HttpOutputMessage outputMessage)

Built-in converters registered by Spring Boot auto-configuration:

  Converter                         | Handles
  ──────────────────────────────────┼──────────────────────────────────
  MappingJackson2HttpMessageConverter  application/json (Jackson)
  MappingJackson2XmlHttpMessageConverter application/xml (Jackson XML)
  Jaxb2RootElementHttpMessageConverter application/xml (JAXB)
  StringHttpMessageConverter           text/plain, text/*
  ByteArrayHttpMessageConverter        application/octet-stream
  ResourceHttpMessageConverter         Resource types (file download)
  FormHttpMessageConverter             application/x-www-form-urlencoded
  ProtobufHttpMessageConverter         application/x-protobuf

Selection order matters — Spring picks the FIRST converter that
canWrite(returnType, mediaType) == true.

  5. CONTENT NEGOTIATION STRATEGIES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Spring supports multiple strategies, evaluated in priority order:

  a) HeaderContentNegotiationStrategy    ← default, uses Accept header
  b) ParameterContentNegotiationStrategy ← ?format=json (disabled by default)
  c) PathExtensionContentNegotiationStrategy ← /users.json (deprecated Spring 5.3+)
  d) FixedContentNegotiationStrategy     ← always one media type

⚠️  Path extension and parameter strategies are DISABLED by default
    in modern Spring Boot (security concern — URL suffix mapping).
    Stick to Accept headers in REST APIs.

  6. CUSTOMIZING ContentNegotiationManager
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

// Option A: application.properties
spring.mvc.contentnegotiation.favor-parameter=true
spring.mvc.contentnegotiation.parameter-name=format
spring.mvc.contentnegotiation.media-types.json=application/json
spring.mvc.contentnegotiation.media-types.xml=application/xml

// Option B: Java config via WebMvcConfigurer
@Configuration
public class WebConfig implements WebMvcConfigurer {

    @Override
    public void configureContentNegotiation(ContentNegotiationConfigurer configurer) {
        configurer
            .favorParameter(true)            // enable ?format=json
            .parameterName("format")
            .ignoreAcceptHeader(false)        // still honor Accept header
            .defaultContentType(MediaType.APPLICATION_JSON)
            .mediaType("json", MediaType.APPLICATION_JSON)
            .mediaType("xml",  MediaType.APPLICATION_XML);
    }
}

  7. ADDING XML SUPPORT
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Spring Boot auto-configures JSON (Jackson) but NOT XML by default.

To enable XML support add the dependency:

  <!-- Maven -->
  <dependency>
      <groupId>com.fasterxml.jackson.dataformat</groupId>
      <artifactId>jackson-dataformat-xml</artifactId>
  </dependency>

After this, MappingJackson2XmlHttpMessageConverter is registered
and Accept: application/xml returns XML automatically.

For JAXB-style annotation support:
  @XmlRootElement(name = "product")
  @XmlAccessorType(XmlAccessType.FIELD)
  public class Product {
      @XmlElement
      private String name;
      // ...
  }

  8. CUSTOM HttpMessageConverter
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Example: CSV response converter

@Component
public class CsvHttpMessageConverter extends AbstractHttpMessageConverter<List<?>> {

    public CsvHttpMessageConverter() {
        super(new MediaType("text", "csv"));
    }

    @Override
    protected boolean supports(Class<?> clazz) {
        return List.class.isAssignableFrom(clazz);
    }

    @Override
    protected List<?> readInternal(Class<? extends List<?>> clazz,
                                    HttpInputMessage inputMessage) {
        throw new UnsupportedOperationException("CSV read not supported");
    }

    @Override
    protected void writeInternal(List<?> list,
                                  HttpOutputMessage outputMessage)
            throws IOException {
        Writer writer = new OutputStreamWriter(outputMessage.getBody());
        for (Object item : list) {
            writer.write(item.toString() + "\n");
        }
        writer.flush();
    }
}

// Register in WebMvcConfigurer
@Override
public void extendMessageConverters(List<HttpMessageConverter<?>> converters) {
    converters.add(new CsvHttpMessageConverter());
}

// Controller usage
@GetMapping(path = "/export", produces = "text/csv")
public List<Product> exportCsv() {
    return productService.findAll();
}

  9. ResponseEntity — FINE-GRAINED CONTROL
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

@GetMapping("/{id}")
public ResponseEntity<Product> getProduct(@PathVariable Long id,
                                          HttpServletRequest request) {
    Product p = productService.findById(id);

    // Return JSON or XML based on Accept
    return ResponseEntity.ok()
        .contentType(MediaType.APPLICATION_JSON)  // force explicit type
        .body(p);
}

// Return different types based on Accept header manually
@GetMapping(value = "/{id}",
            produces = { "application/json", "application/xml" })
public ResponseEntity<?> getFlexible(@PathVariable Long id,
                                      @RequestHeader("Accept") String accept) {
    Product p = productService.findById(id);
    return ResponseEntity.ok(p); // Let Spring pick converter
}

  10. Content-Type vs Accept Header
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Header        | Direction         | Purpose
  ──────────────┼───────────────────┼──────────────────────────────────
  Content-Type  | Request→Server    | Format of the REQUEST body
  Accept        | Request→Server    | Format client WANTS in response
  Content-Type  | Response→Client   | Format of the RESPONSE body

  // Client sends JSON body, expects XML response:
  POST /users
  Content-Type: application/json
  Accept: application/xml

  // Spring uses:
  //   Content-Type → reads body with MappingJackson2HttpMessageConverter
  //   Accept       → writes response with Jaxb2 or Jackson XML converter

  11. @RequestBody AND @ResponseBody
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

@RequestBody  — Spring reads request body using HttpMessageConverter
                matching request's Content-Type header

@ResponseBody — Spring writes return value using HttpMessageConverter
                matching response's Accept header
                (@RestController implies @ResponseBody on all methods)

@PostMapping("/users")
public @ResponseBody UserDto create(@RequestBody UserDto dto) { ... }

// @RestController = @Controller + @ResponseBody at class level

  13. COMMON PITFALLS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. 406 Not Acceptable
   Cause:  Accept header requests XML but no XML converter registered
   Fix:    Add jackson-dataformat-xml dependency

2. 415 Unsupported Media Type
   Cause:  Client sends Content-Type that no converter can read
   Fix:    Ensure correct consumes on @PostMapping, correct converter registered

3. Jackson serialization errors with XML
   Cause:  Missing @XmlRootElement on class
   Fix:    Annotate the DTO, or use Jackson XML annotations

4. Unexpected JSON instead of XML
   Cause:  Jackson XML converter registered AFTER Jackson JSON; Spring picks first
   Fix:    Order converters explicitly or specify produces on endpoint

5. Circular reference in JSON output
   Cause:  Bidirectional entity relationships
   Fix:    Use @JsonIgnore, @JsonManagedReference/@JsonBackReference, or DTOs

6. Spring Security intercepts before content negotiation
   Cause:  405/406 returned before reaching controller
   Fix:    Check security configuration — allow OPTIONS for CORS preflight

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: What is ContentNegotiationManager in Spring MVC?
A: It is the central component that coordinates multiple
   ContentNegotiationStrategy implementations to determine the
   best media type for a response based on the request.

Q: What happens when the client sends Accept: */*?
A: Spring returns the first producible media type from the
   controller's produces list, or the default (usually JSON
   in Boot apps).

Q: How does Spring pick the right HttpMessageConverter?
A: It iterates the registered converters in order and calls
   canWrite(returnType, acceptedMediaType). The first match is used.

Q: What is the difference between produces and consumes?
A: produces → filters which methods handle requests with a given
              Accept header (response format)
   consumes → filters which methods handle requests with a given
              Content-Type header (request body format)

Q: Why is path extension content negotiation deprecated?
A: It introduces security vulnerabilities (RFD attacks — Reflected
   File Download) and ambiguity in URL routing. Accept headers
   are the HTTP-spec-correct approach.

Q: How would you add CSV export to a Spring REST API?
A: Implement AbstractHttpMessageConverter<List<?>>, register it
   with WebMvcConfigurer.extendMessageConverters(), and use
   produces = "text/csv" on the endpoint.

Q: What causes 406 Not Acceptable?
A: The client's Accept header requests a media type that no
   registered HttpMessageConverter can produce for the return type.

Q: How do you support both JSON and XML in one endpoint?
A: Declare produces = {"application/json","application/xml"}, add
   jackson-dataformat-xml dependency, and annotate the DTO with
   @XmlRootElement. Spring auto-picks the right converter.

Q: What annotation is implied by @RestController?
A: @Controller + @ResponseBody — every method's return value is
   written directly to the HTTP response body via message converters
   rather than being resolved as a view name.

Q: Can you override the media type in the response body?
A: Yes — return ResponseEntity and call .contentType(MediaType.xxx)
   to explicitly set the Content-Type header.
