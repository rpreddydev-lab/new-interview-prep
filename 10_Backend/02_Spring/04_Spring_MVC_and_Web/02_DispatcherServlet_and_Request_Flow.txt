================================================================
  DISPATCHERSERVLET AND REQUEST FLOW — IN DEPTH
================================================================

================================================================
DISPATCHERSERVLET INTERNALS
================================================================

  DispatcherServlet extends FrameworkServlet → HttpServlet.
  Initialized once per web application (or per servlet mapping).

  Key fields initialized on startup:
    List<HandlerMapping>         handlerMappings
    List<HandlerAdapter>         handlerAdapters
    List<HandlerExceptionResolver> handlerExceptionResolvers
    ViewResolver                 viewResolver
    LocaleResolver               localeResolver
    ThemeResolver                themeResolver
    MultipartResolver            multipartResolver

================================================================
FULL REQUEST PROCESSING FLOW
================================================================

  1. HTTP request arrives at Servlet container (Tomcat)

  2. Tomcat calls DispatcherServlet.service()
       → FrameworkServlet.processRequest()
       → DispatcherServlet.doDispatch()

  3. doDispatch() — the core method:

     a. Check if multipart request
        if multipartResolver != null && isMultipart(request)
          request = multipartResolver.resolveMultipart(request)

     b. HandlerMapping.getHandler(request)
        → Returns HandlerExecutionChain
          (handler object + List<HandlerInterceptor>)

     c. HandlerAdapter selection
        Find adapter that supports handler
        (RequestMappingHandlerAdapter for @RequestMapping methods)

     d. Interceptors — preHandle()
        For each interceptor: if preHandle() returns false → abort

     e. HandlerAdapter.handle(request, response, handler)
        → Invokes @RequestMapping method
        → Argument resolution (path vars, request body, etc.)
        → Return value handling (ResponseEntity, @ResponseBody, view name)
        → Returns ModelAndView (null for @ResponseBody)

     f. Interceptors — postHandle()
        For each interceptor (reverse order)

     g. processDispatchResult()
        → If exception: handlerExceptionResolvers
        → If ModelAndView: render(mv, request, response)
            → viewResolver.resolveViewName()
            → view.render()

     h. Interceptors — afterCompletion()
        Always called (even on exception)

================================================================
HANDLERMAPPING IMPLEMENTATIONS
================================================================

  Implementation                       | Handles
  -------------------------------------|----------------------------------
  RequestMappingHandlerMapping         | @RequestMapping annotated methods
  BeanNameUrlHandlerMapping            | Bean names matching URL pattern
  RouterFunctionMapping                | RouterFunction-based (WebFlux style)
  SimpleUrlHandlerMapping              | Explicit URL → handler mapping
  WelcomePageHandlerMapping            | Maps / → index.html

  Priority order (lowest number first):
    RequestMappingHandlerMapping: order = 0  (first tried)
    BeanNameUrlHandlerMapping: order = 2

  RequestMappingHandlerMapping builds a map:
    (RequestMappingInfo → HandlerMethod) during startup
    by scanning all @RequestMapping annotations.

================================================================
HANDLERADAPTER IMPLEMENTATIONS
================================================================

  Implementation                     | Handles
  -----------------------------------|----------------------------------
  RequestMappingHandlerAdapter       | @RequestMapping methods (main)
  HttpRequestHandlerAdapter          | HttpRequestHandler interface
  SimpleControllerHandlerAdapter     | Legacy Controller interface

  RequestMappingHandlerAdapter:
    - Invokes the @RequestMapping method
    - Resolves method arguments via HandlerMethodArgumentResolver
    - Processes return value via HandlerMethodReturnValueHandler

================================================================
ARGUMENT RESOLVERS — HOW @RequestBody WORKS
================================================================

  HandlerMethodArgumentResolver implementations:

  Resolver                           | Handles
  -----------------------------------|------------------------------------
  PathVariableMethodArgumentResolver | @PathVariable
  RequestParamMethodArgumentResolver | @RequestParam
  RequestHeaderMethodArgumentResolver| @RequestHeader
  RequestResponseBodyMethodProcessor| @RequestBody / @ResponseBody
  ModelMethodProcessor               | Model
  SessionAttributeMethodArgumentResolver | @SessionAttribute
  MatrixVariableMethodArgumentResolver | @MatrixVariable
  HandlerMethodArgumentResolverComposite | Delegates to all resolvers

  @RequestBody flow:
  1. RequestResponseBodyMethodProcessor checks for @RequestBody
  2. Reads Content-Type header (e.g., application/json)
  3. Finds matching HttpMessageConverter (MappingJackson2HttpMessageConverter)
  4. Calls converter.read(type, request) → Java object
  5. If @Valid present → calls Validator

================================================================
MESSAGE CONVERTERS — HOW JSON WORKS
================================================================

  HttpMessageConverter<T> converts:
    Request body (bytes) → Java object
    Java object → Response body (bytes)

  Default converters registered by WebMvcConfigurationSupport:

  Converter                                 | Media Type
  ------------------------------------------|---------------------------
  ByteArrayHttpMessageConverter             | application/octet-stream
  StringHttpMessageConverter                | text/plain, */*, text/html
  ResourceHttpMessageConverter              | application/octet-stream
  FormHttpMessageConverter                  | application/x-www-form-urlencoded
  MappingJackson2HttpMessageConverter       | application/json (when Jackson on classpath)
  MappingJackson2XmlHttpMessageConverter    | application/xml (when Jackson XML present)
  Jaxb2RootElementHttpMessageConverter      | application/xml (when JAXB present)

  Jackson configuration:
  @Bean
  public Jackson2ObjectMapperBuilderCustomizer jacksonCustomizer() {
      return builder -> builder
          .serializationInclusion(JsonInclude.Include.NON_NULL)
          .featuresToDisable(SerializationFeature.WRITE_DATES_AS_TIMESTAMPS)
          .modules(new JavaTimeModule());
  }

================================================================
RETURN VALUE HANDLERS
================================================================

  Return type                 | Handler
  ----------------------------|------------------------------------------
  void                        | ResponseBody if @ResponseBody, else view
  String                      | ViewName or ResponseBody if annotated
  ModelAndView                | Rendered as view
  ResponseEntity<T>           | Full control: status + headers + body
  HttpEntity<T>               | Headers + body (no status control)
  @ResponseBody T             | Serialized via MessageConverter
  DeferredResult<T>           | Async processing
  Callable<T>                 | Async (runs in TaskExecutor)
  CompletableFuture<T>        | Async
  StreamingResponseBody       | Streaming response

================================================================
CONTENT NEGOTIATION BASICS
================================================================

  DispatcherServlet determines response format via:
  1. Accept header: Accept: application/json
  2. URL extension (deprecated): /users.json
  3. Request parameter: /users?format=json

  Spring selects the matching HttpMessageConverter.

================================================================
STATIC RESOURCE SERVING
================================================================

  Spring Boot auto-serves static resources from:
    /static/          → classpath:/static/
    /public/          → classpath:/public/
    /resources/       → classpath:/resources/
    /META-INF/resources/ → classpath:/META-INF/resources/

  URL: GET /logo.png  →  classpath:/static/logo.png

  Custom location:
  @Configuration
  public class StaticConfig implements WebMvcConfigurer {
      @Override
      public void addResourceHandlers(ResourceHandlerRegistry registry) {
          registry.addResourceHandler("/files/**")
                  .addResourceLocations("file:/opt/app/files/");
      }
  }

================================================================
MULTIPART FILE UPLOAD
================================================================

  @RestController
  public class FileController {

      @PostMapping("/upload")
      public ResponseEntity<String> upload(
              @RequestParam("file") MultipartFile file,
              @RequestParam("description") String description) {

          if (file.isEmpty()) {
              return ResponseEntity.badRequest().body("Empty file");
          }

          String filename = StringUtils.cleanPath(file.getOriginalFilename());
          Path target = Paths.get("/uploads").resolve(filename);
          Files.copy(file.getInputStream(), target, REPLACE_EXISTING);

          return ResponseEntity.ok("Uploaded: " + filename);
      }
  }

  # application.properties
  spring.servlet.multipart.enabled=true
  spring.servlet.multipart.max-file-size=10MB
  spring.servlet.multipart.max-request-size=50MB

================================================================
INTERVIEW QUESTIONS — DISPATCHERSERVLET
================================================================

  Q: Explain the Spring MVC request processing flow.
  A: Request → DispatcherServlet → HandlerMapping (find handler)
     → HandlerAdapter (invoke method) → argument resolution
     → @RequestMapping method → return value handling
     → MessageConverter (serialize) / ViewResolver (render)
     → Response. Interceptors wrap each step.

  Q: What does HandlerMapping do?
  A: Maps an incoming HTTP request (URL + method) to a handler
     object (usually a HandlerMethod wrapping a @RequestMapping method).

  Q: What is a HandlerExecutionChain?
  A: The result of HandlerMapping — it contains the handler
     plus a list of HandlerInterceptors to execute around it.

  Q: What is the role of HttpMessageConverter?
  A: Converts between Java objects and HTTP request/response bodies.
     MappingJackson2HttpMessageConverter handles JSON ↔ Java.

  Q: How does @RequestBody work?
  A: RequestResponseBodyMethodProcessor reads the request body bytes,
     selects the matching HttpMessageConverter based on Content-Type,
     and deserializes the bytes into the Java object type.
