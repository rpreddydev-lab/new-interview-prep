  1. OVERVIEW OF AOP ANNOTATIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Annotation          | When executed                  | Access to return/exception
--------------------|--------------------------------|---------------------------
@Before             | Before method execution        | No
@After              | After method (always)          | No
@AfterReturning     | After successful return        | Yes (returning param)
@AfterThrowing      | After exception thrown         | Yes (throwing param)
@Around             | Wraps entire method            | Yes (both)
@Pointcut           | Declares named pointcut        | —
@Aspect             | Marks class as an aspect       | —
@EnableAspectJAutoProxy | Enables AOP on @Configuration | —

  2. @Aspect and @Pointcut
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

@Aspect — marks the class as an AspectJ aspect.
           Must also be a Spring bean (@Component, @Service, or @Bean).

@Pointcut — marks a method as a pointcut declaration (method body
            must be empty, return type void). The method name becomes
            the pointcut ID.

@Aspect
@Component
public class CommonPointcuts {

    @Pointcut("execution(* com.example.service..*(..))")
    public void inServiceLayer() {}

    @Pointcut("execution(* com.example.repository..*(..))")
    public void inRepositoryLayer() {}

    @Pointcut("@annotation(com.example.annotation.Auditable)")
    public void auditableMethod() {}

    @Pointcut("inServiceLayer() || inRepositoryLayer()")
    public void inDataLayer() {}

    @Pointcut("execution(* com.example..*.*(..)) && !inDataLayer()")
    public void notInDataLayer() {}
}

@EnableAspectJAutoProxy — placed on a @Configuration class.
  Spring Boot auto-configures this when spring-boot-starter-aop is present.
  Supports proxyTargetClass = true/false attribute (discussed in proxy file).

@Configuration
@EnableAspectJAutoProxy
public class AopConfig {
    // Explicit config; not needed with Spring Boot
}

  3. @Before
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Executes BEFORE the target method. Receives JoinPoint.
Cannot prevent method from running (unless it throws an exception itself).

@Aspect
@Component
public class AuditAspect {

    @Autowired
    private AuditLogService auditService;

    // Pattern 1: basic — using inline pointcut
    @Before("execution(* com.example.service.ProductService.updatePrice(..))")
    public void beforePriceUpdate(JoinPoint jp) {
        MethodSignature sig = (MethodSignature) jp.getSignature();
        log.info("Method {} is about to be called", sig.getMethod().getName());
    }

    // Pattern 2: referencing named pointcut
    @Before("com.example.aop.CommonPointcuts.auditableMethod()")
    public void auditBefore(JoinPoint jp) {
        String user = SecurityContextHolder.getContext()
            .getAuthentication().getName();
        String method = jp.getSignature().toShortString();
        auditService.logEntry(user, method, Arrays.toString(jp.getArgs()));
    }

    // Pattern 3: bind annotation instance
    @Before("@annotation(auditable)")
    public void auditWithAnnotationData(JoinPoint jp, Auditable auditable) {
        String action = auditable.action();  // custom annotation attribute
        log.info("Auditing action: {}", action);
    }
}

  4. @After
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Runs AFTER the method always — whether it returned normally or threw.
Like a finally block in try-catch. Does NOT receive return value or exception.

@Aspect
@Component
public class CleanupAspect {

    @After("execution(* com.example.service.ReportService.generate*(..))")
    public void releaseResources(JoinPoint jp) {
        log.info("Cleanup after: {}", jp.getSignature().getName());
        // Release locks, close streams, clear ThreadLocal, etc.
    }
}

  5. @AfterReturning
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Runs only on SUCCESSFUL return. Can access the return value.
The returning attribute name MUST match the method parameter name.
Can specify a type in returning to only match methods returning that type.

@Aspect
@Component
public class ResultLoggingAspect {

    // Access return value as Object
    @AfterReturning(
        pointcut = "execution(* com.example.service.OrderService.placeOrder(..))",
        returning = "order"
    )
    public void afterOrderPlaced(JoinPoint jp, Order order) {
        log.info("Order placed: id={}, total={}", order.getId(), order.getTotal());
        notificationService.sendConfirmation(order);
    }

    // Only matches methods returning List<?>
    @AfterReturning(
        pointcut = "execution(* com.example.service.ProductService.search*(..))",
        returning = "results"
    )
    public void afterSearch(JoinPoint jp, List<?> results) {
        log.info("Search '{}' returned {} results",
            jp.getSignature().getName(), results.size());
    }

    // NOTE: You cannot CHANGE the return value with @AfterReturning.
    //       The reference you receive is the actual return value, but
    //       reassigning the parameter won't affect what the caller gets.
    //       Use @Around to modify return values.
}

  6. @AfterThrowing
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Runs only when an exception propagates out of the method.
The throwing attribute name MUST match the method parameter name.
You can type the exception parameter to only match specific exceptions.
The exception still propagates — @AfterThrowing cannot suppress it.

@Aspect
@Component
public class ExceptionLoggingAspect {

    // Catch all exceptions
    @AfterThrowing(
        pointcut = "com.example.aop.CommonPointcuts.inServiceLayer()",
        throwing = "ex"
    )
    public void logAllExceptions(JoinPoint jp, Throwable ex) {
        log.error("Exception in {}: {}",
            jp.getSignature().toShortString(), ex.getMessage());
        metricsService.incrementErrorCounter(jp.getSignature().getName());
    }

    // Only match DataAccessException and subtypes
    @AfterThrowing(
        pointcut = "com.example.aop.CommonPointcuts.inRepositoryLayer()",
        throwing = "ex"
    )
    public void logDatabaseException(JoinPoint jp, DataAccessException ex) {
        log.error("DB error in {}: SQL state={}",
            jp.getSignature().getName(), ex.getMessage());
        alertService.sendDbAlert(ex);
    }

    // NOTE: Exception continues to propagate after @AfterThrowing runs.
    //       To suppress or transform exceptions, use @Around with try-catch.
}

  7. @Around
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Most powerful advice. Receives ProceedingJoinPoint (extends JoinPoint).
Must call proceed() to invoke the target. Full control over execution.

@Aspect
@Component
@Order(1)
public class PerformanceAspect {

    // Use case 1: Execution time measurement
    @Around("com.example.aop.CommonPointcuts.inServiceLayer()")
    public Object measureTime(ProceedingJoinPoint pjp) throws Throwable {
        long start = System.nanoTime();
        try {
            return pjp.proceed();
        } finally {
            long elapsed = System.nanoTime() - start;
            log.info("{} took {} ms",
                pjp.getSignature().toShortString(),
                TimeUnit.NANOSECONDS.toMillis(elapsed));
        }
    }
}

@Aspect
@Component
public class RetryAspect {

    // Use case 2: Retry logic
    @Around("@annotation(retryable)")
    public Object retry(ProceedingJoinPoint pjp, Retryable retryable) throws Throwable {
        int maxAttempts = retryable.maxAttempts();
        long delay = retryable.delayMs();
        Throwable lastException = null;

        for (int attempt = 1; attempt <= maxAttempts; attempt++) {
            try {
                return pjp.proceed();
            } catch (Exception ex) {
                lastException = ex;
                log.warn("Attempt {}/{} failed: {}",
                    attempt, maxAttempts, ex.getMessage());
                if (attempt < maxAttempts) {
                    Thread.sleep(delay * attempt); // exponential backoff
                }
            }
        }
        throw lastException;
    }
}

@Aspect
@Component
public class SecurityCheckAspect {

    // Use case 3: Guard method with pre-check
    @Around("@annotation(requiresPermission)")
    public Object checkPermission(ProceedingJoinPoint pjp,
                                  RequiresPermission requiresPermission) throws Throwable {
        Authentication auth = SecurityContextHolder.getContext().getAuthentication();
        String required = requiresPermission.value();

        boolean hasPermission = auth.getAuthorities().stream()
            .anyMatch(a -> a.getAuthority().equals(required));

        if (!hasPermission) {
            throw new AccessDeniedException("Missing permission: " + required);
        }

        return pjp.proceed();
    }
}

  8. CUSTOM ANNOTATION + @Around — COMPLETE EXAMPLE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

// 1. Define the custom annotation
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
public @interface Timed {
    String value() default "";      // optional metric name
    boolean logArgs() default false;
}

// 2. Apply to methods
@Service
public class PaymentService {

    @Timed(value = "payment.process", logArgs = true)
    public PaymentResult process(PaymentRequest request) {
        // business logic
    }
}

// 3. Implement the aspect
@Aspect
@Component
public class TimedAspect {

    private final MeterRegistry meterRegistry;

    public TimedAspect(MeterRegistry meterRegistry) {
        this.meterRegistry = meterRegistry;
    }

    @Around("@annotation(timed)")
    public Object trackTime(ProceedingJoinPoint pjp, Timed timed) throws Throwable {
        String metricName = timed.value().isBlank()
            ? pjp.getSignature().getName()
            : timed.value();

        if (timed.logArgs()) {
            log.debug("Calling {} with args: {}", metricName,
                Arrays.toString(pjp.getArgs()));
        }

        Timer.Sample sample = Timer.start(meterRegistry);
        try {
            Object result = pjp.proceed();
            sample.stop(meterRegistry.timer(metricName, "status", "success"));
            return result;
        } catch (Throwable ex) {
            sample.stop(meterRegistry.timer(metricName, "status", "error"));
            throw ex;
        }
    }
}

  9. INTERVIEW Q&A
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: Can @AfterReturning change the return value?
A: No. You receive a reference to the return value but modifying the
   local parameter doesn't change what the caller receives. To transform
   a return value, use @Around: capture pjp.proceed(), transform it,
   and return the new value.

Q: Can @AfterThrowing suppress an exception?
A: No. @AfterThrowing executes after the exception is thrown, but the
   exception always continues to propagate. To suppress or wrap an
   exception, use @Around with a try-catch block and choose not to
   re-throw.

Q: When should you prefer @Before/@AfterReturning over @Around?
A: When simpler — @Before and @AfterReturning are cleaner and less
   error-prone. @Around is needed when: (1) you need to modify args
   or return value, (2) you need to measure elapsed time spanning the
   entire call, (3) you want to conditionally skip the method, or (4)
   you want to retry on exception.

Q: What happens if @Around never calls proceed()?
A: The target method never executes. The return value of the advice
   method (null if void) is returned to the caller. This can be
   intentional (caching, short-circuit) or a bug — always be explicit.

Q: What is the execution order of multiple advice types on the same method?
A: @Around (outer) → @Before → target method → @AfterReturning or
   @AfterThrowing → @After → @Around (inner return).
   More precisely: @Around begin → @Before → [method] → @After →
   @AfterReturning/@AfterThrowing → @Around end.
