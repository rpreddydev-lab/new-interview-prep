================================================================
WHAT IS SPRING?
================================================================

  Spring is a comprehensive open-source Java application framework
  initially created by Rod Johnson (2003). Its core mission:
  simplify enterprise Java development by promoting:

    - Inversion of Control (IoC) / Dependency Injection (DI)
    - Plain Old Java Objects (POJOs) over heavyweight EJBs
    - Modularity -- pick only what you need
    - Testability -- loose coupling enables easy unit testing

  Spring is NOT a single product; it is an ECOSYSTEM of projects
  all maintained under the Spring umbrella (Pivotal → VMware Tanzu).

================================================================
CORE MODULES OF THE SPRING FRAMEWORK
================================================================

  spring-core          -- Core IoC container, resource loading
  spring-beans         -- BeanFactory, bean definitions, DI
  spring-context       -- ApplicationContext, events, i18n, AOP
  spring-expression    -- SpEL (Spring Expression Language)
  spring-aop           -- Aspect-Oriented Programming support
  spring-jdbc          -- JDBC abstraction, JdbcTemplate
  spring-tx            -- Transaction management abstraction
  spring-orm           -- Integration with Hibernate, JPA
  spring-web           -- HTTP client/server foundation
  spring-webmvc        -- DispatcherServlet, REST controllers
  spring-webflux       -- Reactive web stack (Project Reactor)
  spring-test          -- Test support: SpringRunner, MockMvc
  spring-messaging     -- Messaging abstraction (STOMP, Kafka)
  spring-security      -- Authentication / Authorization framework

================================================================
SPRING vs JAKARTA EE (formerly Java EE)
================================================================

  Spring Framework is NOT Jakarta EE but is complementary to it.
  Spring implements many Jakarta EE specifications:

  Jakarta EE Spec       | Spring Implementation
  ----------------------|--------------------------------------------
  Servlet API           | DispatcherServlet, filters, listeners
  JPA (Hibernate)       | Spring Data JPA, @Transactional
  Bean Validation       | spring-boot-starter-validation (Hibernate Validator)
  JTA transactions      | JtaTransactionManager
  CDI (contexts/inject) | Spring IoC replaces CDI; @Component ≈ @Named
  JAX-RS (REST)         | Spring MVC / WebFlux replaces JAX-RS
  JMS                   | Spring Messaging / spring-jms

  Key distinction: Spring ships as plain JARs and runs in any
  Servlet container (Tomcat, Jetty) or standalone (Spring Boot).
  Jakarta EE requires a full application server (WildFly, Payara, GlassFish).

================================================================
SPRING FRAMEWORK VERSION HISTORY (HIGHLIGHTS)
================================================================

  Version | Year | Key Feature
  --------|------|----------------------------------------------------
  1.0     | 2004 | IoC container, JdbcTemplate, AOP
  2.0     | 2006 | XML namespaces, AspectJ integration
  2.5     | 2007 | Annotation-based DI (@Autowired, @Component)
  3.0     | 2009 | Java Config (@Configuration), REST support
  3.1     | 2011 | @Profile, cache abstraction
  4.0     | 2013 | Java 8 support, WebSocket, Spring Boot 1.x
  5.0     | 2017 | Reactive (WebFlux), Kotlin support
  5.3     | 2020 | Long-term support; last to support Java 8/11
  6.0     | 2022 | Java 17 baseline, Jakarta EE 9+, AOT compilation
  6.1     | 2023 | Virtual thread support (Project Loom), RestClient
  6.2     | 2024 | Structured concurrency, improved Observability

  Spring Boot 3.x requires Spring Framework 6.x and Java 17+.

================================================================
SPRING FRAMEWORK DESIGN PRINCIPLES
================================================================

  1. Non-invasive (POJO-based)
     Business logic has NO Spring API dependencies; framework wraps it.

  2. Modular
     Use only what you need; no bloated "all or nothing" containers.

  3. Consistent abstraction
     Uniform DAO exception hierarchy, resource handling, transaction
     management regardless of underlying technology.

  4. Convention over Configuration
     Spring Boot extends this with auto-configuration defaults.

  5. Embraces open standards
     Integrates with JPA, JTA, Servlet, Bean Validation, etc.

  6. Testability
     IoC enables constructor injection → easy unit testing with mocks.

QUICK REFERENCE: KEY ANNOTATIONS BY CATEGORY
================================================================

  IoC / DI:
    @Component, @Service, @Repository, @Controller, @RestController
    @Autowired, @Qualifier, @Primary, @Value, @Inject

  Configuration:
    @Configuration, @Bean, @ComponentScan, @Import, @PropertySource

  Web MVC:
    @RequestMapping, @GetMapping, @PostMapping, @PutMapping, @DeleteMapping
    @PathVariable, @RequestParam, @RequestBody, @ResponseBody, @ResponseStatus
    @RestControllerAdvice, @ExceptionHandler, @CrossOrigin

  Data:
    @Entity, @Table, @Id, @GeneratedValue, @Column, @OneToMany, @ManyToOne
    @Transactional, @Query, @Modifying, @Lock

  Security:
    @EnableWebSecurity, @PreAuthorize, @PostAuthorize, @Secured, @RolesAllowed

  AOP:
    @Aspect, @Before, @After, @Around, @AfterReturning, @AfterThrowing
    @Pointcut, @EnableAspectJAutoProxy

  Boot:
    @SpringBootApplication, @EnableAutoConfiguration, @ConditionalOnProperty
    @ConditionalOnClass, @ConditionalOnMissingBean, @ConfigurationProperties

  Testing:
    @SpringBootTest, @WebMvcTest, @DataJpaTest, @MockBean, @Mock, @InjectMocks
    @ExtendWith(SpringExtension.class), @Sql, @TestPropertySource
