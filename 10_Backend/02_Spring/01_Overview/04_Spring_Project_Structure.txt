================================================================
MULTI-MODULE MAVEN PROJECT STRUCTURE
================================================================

  parent-project/
  ├── pom.xml                    ← parent POM (<packaging>pom</packaging>)
  ├── common/                    ← shared utilities, DTOs
  │   ├── pom.xml
  │   └── src/...
  ├── domain/                    ← JPA entities, domain objects
  │   ├── pom.xml
  │   └── src/...
  ├── service/                   ← business logic, Spring @Service
  │   ├── pom.xml
  │   └── src/...
  ├── web/                       ← REST controllers, Spring MVC/Boot
  │   ├── pom.xml
  │   └── src/...
  └── integration-tests/         ← E2E / integration tests
      ├── pom.xml
      └── src/...

  Parent POM declares:
  <modules>
    <module>common</module>
    <module>domain</module>
    <module>service</module>
    <module>web</module>
  </modules>

  Benefits:
  - Separation of concerns; each module has clear responsibility
  - Independent compilation and testing
  - Reuse common/domain across multiple web modules

================================================================
LAYERED ARCHITECTURE PATTERNS
================================================================

  Classic 3-Layer:
  ┌──────────────────────────────────────┐
  │  Presentation Layer (@Controller)    │  HTTP in/out, DTOs
  ├──────────────────────────────────────┤
  │  Business / Service Layer (@Service) │  Business rules, orchestration
  ├──────────────────────────────────────┤
  │  Data Access Layer (@Repository)     │  DB queries, data persistence
  └──────────────────────────────────────┘

  Hexagonal Architecture (Ports & Adapters):
  ┌──────────────────────────────────────┐
  │           Domain (core)              │  Pure Java, no framework deps
  │  ┌────────────────────────────────┐  │
  │  │   Application Services         │  │  Use cases, orchestration
  │  └────────────────────────────────┘  │
  │   Ports (interfaces) ← → Adapters    │  Controllers, Repos, Kafka, etc.
  └──────────────────────────────────────┘

  Dependency Rule: inner layers never depend on outer layers.

================================================================
MAIN CLASS AND ENTRY POINT
================================================================

  @SpringBootApplication
  public class MyAppApplication {

      public static void main(String[] args) {
          SpringApplication app = new SpringApplication(MyAppApplication.class);
          app.setBannerMode(Banner.Mode.OFF);
          app.run(args);
      }
  }

  SpringApplication.run() returns:
    ConfigurableApplicationContext ctx = SpringApplication.run(...);
    // ctx.getBean(SomeService.class); -- access any bean programmatically

  Customize startup:
    app.setDefaultProperties(Map.of("server.port", "8081"));
    app.addListeners(new ApplicationStartedEventListener());

================================================================
KEY CONFIGURATION FILES
================================================================

  application.yml (preferred over .properties):
  ───────────────────────────────────────────────
  server:
    port: 8080
    servlet:
      context-path: /api

  spring:
    application:
      name: my-app
    datasource:
      url: jdbc:postgresql://localhost:5432/mydb
      username: ${DB_USER}          # env var injection
      password: ${DB_PASS}
      hikari:
        maximum-pool-size: 10
    jpa:
      hibernate:
        ddl-auto: validate
      show-sql: false
    profiles:
      active: dev

  logging:
    level:
      root: INFO
      com.company.myapp: DEBUG

  management:
    endpoints:
      web:
        exposure:
          include: health,info,metrics

================================================================
PACKAGE NAMING CONVENTIONS
================================================================

  Use reverse domain name:
    com.company.appname.layer.feature

  Examples:
    com.acme.orders.controller.OrderController
    com.acme.orders.service.OrderService
    com.acme.orders.repository.OrderRepository
    com.acme.orders.domain.Order
    com.acme.orders.dto.OrderRequest
    com.acme.orders.exception.OrderNotFoundException
    com.acme.orders.config.SecurityConfig

  Rule: @SpringBootApplication must be in the ROOT package
  (com.acme.orders) so @ComponentScan covers all sub-packages
  automatically.

================================================================
BUILD FILE: pom.xml SKELETON
================================================================

  <parent>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-parent</artifactId>
    <version>3.4.0</version>
  </parent>

  <dependencies>
    <dependency>
      <groupId>org.springframework.boot</groupId>
      <artifactId>spring-boot-starter-web</artifactId>
    </dependency>
    <dependency>
      <groupId>org.springframework.boot</groupId>
      <artifactId>spring-boot-starter-data-jpa</artifactId>
    </dependency>
    <dependency>
      <groupId>org.springframework.boot</groupId>
      <artifactId>spring-boot-starter-security</artifactId>
    </dependency>
    <dependency>
      <groupId>org.springframework.boot</groupId>
      <artifactId>spring-boot-starter-test</artifactId>
      <scope>test</scope>
    </dependency>
  </dependencies>

  <build>
    <plugins>
      <plugin>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-maven-plugin</artifactId>
      </plugin>
    </plugins>
  </build>

  spring-boot-starter-parent provides:
  - Dependency management BOM (no version on starters needed)
  - Default compiler plugin settings (Java version)
  - Resource filtering (application*.yml included)
  - Maven wrapper support
