  1. RELATIONSHIP TYPES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  @OneToOne      — one entity ↔ one entity
  @OneToMany     — one entity → many entities
  @ManyToOne     — many entities → one entity
  @ManyToMany    — many entities ↔ many entities

Ownership:
  The "owning side" holds the foreign key (or join table entry).
  The "inverse side" uses mappedBy to reference the owning side.
  Only the owning side matters for persistence — changes on
  the inverse side without updating the owning side are IGNORED.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  2. @OneToMany / @ManyToOne (most common)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

@Entity
public class Order {
    @Id @GeneratedValue
    private Long id;

    // Inverse side — mappedBy points to the field in OrderItem
    @OneToMany(mappedBy = "order",
               cascade = CascadeType.ALL,
               orphanRemoval = true,
               fetch = FetchType.LAZY)
    private List<OrderItem> items = new ArrayList<>();

    // Helper method to keep both sides in sync
    public void addItem(OrderItem item) {
        items.add(item);
        item.setOrder(this);        // must set owning side
    }

    public void removeItem(OrderItem item) {
        items.remove(item);
        item.setOrder(null);
    }
}

@Entity
public class OrderItem {
    @Id @GeneratedValue
    private Long id;

    // Owning side — has the foreign key column
    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "order_id", nullable = false)
    private Order order;

    private int quantity;
    private BigDecimal unitPrice;
}

  3. @OneToOne
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

@Entity
public class User {
    @Id @GeneratedValue
    private Long id;

    @OneToOne(mappedBy = "user",
              cascade = CascadeType.ALL,
              fetch = FetchType.LAZY,
              optional = false)
    private UserProfile profile;
}

@Entity
public class UserProfile {
    @Id @GeneratedValue
    private Long id;

    @OneToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "user_id", unique = true)  // FK column
    private User user;

    private String bio;
    private String avatarUrl;
}

⚠️  @OneToOne is NOT lazy by default in some Hibernate versions.
    To force lazy loading you need compile-time bytecode enhancement
    or shared primary key strategy.

Shared PK approach (avoids extra join):
  @Entity
  public class UserProfile {
      @Id
      private Long id;            // same PK as User

      @OneToOne
      @MapsId
      private User user;          // PK is same as user.id
  }

  4. @ManyToMany
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

@Entity
public class Student {
    @Id @GeneratedValue
    private Long id;

    @ManyToMany(cascade = { CascadeType.PERSIST, CascadeType.MERGE })
    @JoinTable(
        name = "student_course",
        joinColumns = @JoinColumn(name = "student_id"),
        inverseJoinColumns = @JoinColumn(name = "course_id")
    )
    private Set<Course> courses = new HashSet<>();
}

@Entity
public class Course {
    @Id @GeneratedValue
    private Long id;

    @ManyToMany(mappedBy = "courses")
    private Set<Student> students = new HashSet<>();
}

When you need extra columns on the join table:
  // Use an explicit join entity instead
  @Entity
  public class StudentCourse {
      @EmbeddedId
      private StudentCourseId id;

      @ManyToOne @MapsId("studentId")
      private Student student;

      @ManyToOne @MapsId("courseId")
      private Course course;

      private LocalDate enrolledAt;  // extra column
      private String grade;
  }

  5. FETCH TYPES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  FetchType.EAGER → load the association IMMEDIATELY with the entity
  FetchType.LAZY  → load the association only when ACCESSED (proxy)

Default fetch types per annotation:
  @ManyToOne    → EAGER  ← often causes N+1 problems; override to LAZY
  @OneToOne     → EAGER  ← same concern
  @OneToMany    → LAZY
  @ManyToMany   → LAZY

Best practice: Use LAZY everywhere, explicitly JOIN FETCH or
@EntityGraph when you need the association.

  @ManyToOne(fetch = FetchType.LAZY)   // ← always set this explicitly
  @JoinColumn(name = "customer_id")
  private Customer customer;

  @OneToOne(fetch = FetchType.LAZY, optional = false)
  private Address address;

LAZY loading requires an active persistence context (open session).
If an entity is detached or the session is closed before accessing
a lazy-loaded field → LazyInitializationException.

Solution:
  a) Ensure the association is fetched within the transaction
  b) Use JOIN FETCH in JPQL
  c) Use @EntityGraph
  d) Open Session In View pattern (Anti-pattern for APIs — avoid)

  6. CASCADE TYPES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  CascadeType.PERSIST   → persist child when parent is persisted
  CascadeType.MERGE     → merge child when parent is merged
  CascadeType.REMOVE    → delete child when parent is removed
  CascadeType.REFRESH   → refresh child when parent is refreshed
  CascadeType.DETACH    → detach child when parent is detached
  CascadeType.ALL       → all of the above

  orphanRemoval = true  → delete child if removed from parent's collection
                          (stronger than REMOVE — also handles de-association)

Common patterns:
  // Parent–child lifecycle (child has no meaning without parent)
  @OneToMany(cascade = CascadeType.ALL, orphanRemoval = true)

  // Independent entities that may be shared
  @ManyToMany(cascade = { CascadeType.PERSIST, CascadeType.MERGE })
  // DO NOT cascade REMOVE on @ManyToMany — would delete shared entities!

  7. BIDIRECTIONAL RELATIONSHIP PITFALLS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. Infinite recursion in JSON (Jackson):
   @JsonManagedReference  (on parent side — serialized)
   @JsonBackReference     (on child side — NOT serialized)
   OR use @JsonIgnore on one side
   OR use DTOs (recommended)

2. StackOverflow in toString/hashCode/equals:
   Do NOT include bidirectional references in these methods.
   Use only business key fields.

3. Forgetting to sync both sides:
   // Adding item to order.items without setting item.order
   // means Hibernate won't persist the FK column
   order.getItems().add(item);    // ← not enough!
   item.setOrder(order);          // ← owning side must be set

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: What is the owning side in a JPA relationship?
A: The owning side is the entity whose table or column holds the
   foreign key (or join table entry). In @OneToMany/@ManyToOne,
   the @ManyToOne side is the owner. Changes to the inverse side
   (mappedBy) are ignored by JPA — you must update the owning side.

Q: What is the difference between CascadeType.REMOVE and orphanRemoval?
A: CascadeType.REMOVE deletes children only when the parent is
   explicitly deleted. orphanRemoval = true additionally deletes a
   child when it is removed from the parent's collection
   (de-associated), even without deleting the parent.

Q: What causes LazyInitializationException?
A: Accessing a LAZY-loaded association after the Hibernate session
   (persistence context) has been closed. Typically happens when
   a detached entity's lazy field is accessed outside a @Transactional
   boundary. Fix: fetch the association within the transaction, use
   JOIN FETCH, or use @EntityGraph.

Q: Why should @ManyToOne default fetch be changed to LAZY?
A: By default @ManyToOne is EAGER, meaning every time you load an
   entity, it also loads its parent. In a chain (Order → Customer →
   Address), this escalates into many unexpected JOINs. Always set
   LAZY explicitly and load associations intentionally.

Q: What happens if you cascade REMOVE on @ManyToMany?
A: It can delete shared entities that other parents still reference,
   causing data loss. Never cascade REMOVE on @ManyToMany. Only
   cascade PERSIST and MERGE for associations to independent entities.

Q: What is the difference between LAZY and EAGER in terms of SQL?
A: EAGER: Hibernate issues a JOIN (or additional SELECT) to load the
   association immediately when the parent is loaded.
   LAZY: Hibernate creates a proxy object; the SQL for the association
   is issued only when a non-identifier field on the proxy is accessed.
