======================================================
SPRING BOOT 3.x — KEY CHANGES, MIGRATION & NEW FEATURES
======================================================

1. OVERVIEW
────────────
Spring Boot 3.0 released November 2022. Spring Boot 3.x requires:
  - Java 17 minimum (Java 21 recommended)
  - Spring Framework 6.x
  - Jakarta EE 9+ (javax.* → jakarta.*)
  - Hibernate 6.x
  - Flyway 9+ or Liquibase 4.17+
  - Spring Security 6.x

Spring Boot 3.x LTS timeline:
  3.0 → Nov 2022 (EOL May 2024)
  3.1 → May 2023 (EOL Nov 2024)
  3.2 → Nov 2023 (EOL May 2025)  — virtual threads, RestClient
  3.3 → May 2024 (EOL Nov 2025)  — CDS support, Service Connection
  3.4 → Nov 2024 (EOL May 2026)
  3.5 → May 2025 (EOL Nov 2026)


2. JAKARTA EE NAMESPACE MIGRATION (javax → jakarta)
─────────────────────────────────────────────────────
THE BIGGEST BREAKING CHANGE in Spring Boot 3.

All javax.* packages renamed to jakarta.*:

  Spring Boot 2.x         | Spring Boot 3.x
  ─────────────────────────────────────────────────────────
  javax.persistence.*     | jakarta.persistence.*
  javax.validation.*      | jakarta.validation.*
  javax.servlet.*         | jakarta.servlet.*
  javax.annotation.*      | jakarta.annotation.*
  javax.transaction.*     | jakarta.transaction.*
  javax.xml.bind.*        | jakarta.xml.bind.*

Common changes in code:
  // Entity classes
  import jakarta.persistence.Entity;        // was javax.persistence.Entity
  import jakarta.persistence.Id;
  import jakarta.persistence.Column;

  // Validation
  import jakarta.validation.constraints.NotNull;  // was javax.validation
  import jakarta.validation.Valid;

  // Servlets
  import jakarta.servlet.http.HttpServletRequest;  // was javax.servlet

Migration tool:
  OpenRewrite recipe: UpgradeSpringBoot_3_0
  mvn rewrite:run -Drewrite.recipeArtifactCoordinates=org.openrewrite.recipe:rewrite-spring:LATEST \
                  -Drewrite.activeRecipes=org.openrewrite.java.spring.boot3.UpgradeSpringBoot_3_0


3. SPRING SECURITY 6.x CHANGES
────────────────────────────────
Major breaking changes:

a) WebSecurityConfigurerAdapter REMOVED:
  // OLD (Spring Boot 2.x):
  @Configuration
  public class SecurityConfig extends WebSecurityConfigurerAdapter {
      @Override
      protected void configure(HttpSecurity http) throws Exception { ... }
  }

  // NEW (Spring Boot 3.x / Spring Security 6):
  @Configuration
  public class SecurityConfig {
      @Bean
      public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
          // ...
          return http.build();
      }
  }

b) authorizeRequests() replaced by authorizeHttpRequests():
  // OLD:
  http.authorizeRequests().antMatchers("/admin/**").hasRole("ADMIN")
  // NEW:
  http.authorizeHttpRequests(auth -> auth
      .requestMatchers("/admin/**").hasRole("ADMIN"))

c) antMatchers() → requestMatchers():
  // OLD: .antMatchers("/api/**")
  // NEW: .requestMatchers("/api/**")

d) @EnableGlobalMethodSecurity → @EnableMethodSecurity:
  // OLD:
  @EnableGlobalMethodSecurity(prePostEnabled = true, securedEnabled = true)
  // NEW:
  @EnableMethodSecurity  // prePostEnabled = true by default

e) HttpSecurity lambda DSL is now mandatory (was optional):
  http.csrf(csrf -> csrf.disable());  // lambda required


4. SPRING DATA / HIBERNATE 6 CHANGES
──────────────────────────────────────
Hibernate 6 (Spring Boot 3.x):
  - Uses SEQUENCE strategy by default (was TABLE in H5)
  - @GeneratedValue(strategy = GenerationType.AUTO) → now uses sequence
  - Schema changes if upgrading from Hibernate 5

  Old behavior restoration:
    spring.jpa.properties.hibernate.id.new_generator_mappings=false  # not recommended

  Native SQL types:
    @Column(columnDefinition = "jsonb")  # PostgreSQL JSON handled natively
    @JdbcTypeCode(SqlTypes.JSON)         # Hibernate 6 JSON support

  Improved type handling:
    UUID, JSON, Arrays natively supported
    @Type is mostly not needed for standard types


5. NEW FEATURES IN SPRING BOOT 3.2
────────────────────────────────────
a) Virtual Threads (Java 21):
     spring.threads.virtual.enabled=true
     (see separate file: Virtual_Threads_and_Async_Pitfalls.txt)

b) RestClient (New in 3.2):
     Replaces RestTemplate (synchronous, fluent API similar to WebClient)
     (see separate file: WebClient_RestTemplate_RestClient.txt)

c) Spring Boot SSL Bundles:
     Configure SSL/TLS centrally:
     spring.ssl.bundle.jks.mybundle.keystore.location=classpath:keystore.jks
     spring.ssl.bundle.jks.mybundle.keystore.password=secret

     // Use in RestClient, WebClient, DataSource:
     @Autowired SslBundles sslBundles;
     SslBundle bundle = sslBundles.getBundle("mybundle");

d) Improved Docker Compose support:
     spring-boot-docker-compose: auto starts docker-compose.yml services on startup
     spring.docker.compose.enabled=true

e) Micrometer Tracing improvements:
     spring.application.name used as service name in traces
     Auto-configured with OpenTelemetry or Brave

f) @ConditionalOnThreading:
     @ConditionalOnThreading(Threading.VIRTUAL)
     @Bean VirtualThreadExecutor virtualThreadExecutor() { ... }


6. NEW FEATURES IN SPRING BOOT 3.3
────────────────────────────────────
a) Class Data Sharing (CDS) support:
     ./mvnw spring-boot:process-aot       # AOT processing
     ./mvnw spring-boot:extract-classes   # extract classes for CDS
     Faster startup, especially in containers

b) @Fallback annotation (Spring MVC):
     @Fallback on @Component used as a fallback bean in tests

c) Service Connection improvements:
     @ServiceConnection for Testcontainers:
     @Container
     @ServiceConnection
     static PostgreSQLContainer<?> postgres = new PostgreSQLContainer<>("postgres:16");
     // Auto-configures DataSource for tests — no manual application.yml override needed

d) Improved actuator endpoint security defaults


7. DEPRECATIONS AND REMOVALS
──────────────────────────────
Removed in Spring Boot 3.x:
  - WebSecurityConfigurerAdapter
  - @EnableGlobalMethodSecurity
  - antMatchers(), mvcMatchers(), regexMatchers() → requestMatchers()
  - Spring Data repositories returning Optional<T> with null → now throws
  - logging.file → logging.file.name
  - spring.redis.* → spring.data.redis.* (Spring Boot 3.1+)

Property renames (Spring Boot 3.1+):
  OLD                                 | NEW
  ──────────────────────────────────────────────────────────
  spring.redis.host                  | spring.data.redis.host
  spring.redis.password              | spring.data.redis.password
  spring.kafka.bootstrap-servers     | spring.kafka.bootstrap-servers (same)
  server.max-http-header-size        | server.max-http-request-header-size
  spring.mvc.pathmatch.use-suffix-pattern | removed (suffix pattern deprecated)

Hibernate 6 removals:
  - @TypeDef → use @JdbcTypeCode
  - @Type(type = "json") → @JdbcTypeCode(SqlTypes.JSON)
  - CriteriaQuery.from() type changes

9. INTERVIEW QUESTIONS
──────────────────────
Q: What is the most significant breaking change in Spring Boot 3?
A: The Jakarta EE namespace migration — all javax.* packages renamed to jakarta.*.
   This affects JPA entities, Bean Validation, Servlets, and more.
   Code compiled for Spring Boot 2 is not binary compatible with Spring Boot 3.

Q: What replaced WebSecurityConfigurerAdapter in Spring Security 6?
A: WebSecurityConfigurerAdapter was removed. Instead, define a
   SecurityFilterChain @Bean in a @Configuration class, calling http.build()
   at the end. This component-based approach is more composable and testable.

Q: What changed about @GeneratedValue(AUTO) in Hibernate 6?
A: Hibernate 6 uses SEQUENCE strategy by default for AUTO, instead of TABLE.
   This can cause schema mismatches when migrating from Hibernate 5.
   Use explicit @GeneratedValue(strategy = GenerationType.SEQUENCE) to be clear.

Q: What is the RestClient introduced in Spring Boot 3.2?
A: RestClient is a synchronous, fluent HTTP client replacing RestTemplate.
   It has a WebClient-like API but is blocking. Suitable for simple REST calls
   without reactive programming. (See WebClient_RestTemplate_RestClient.txt)

Q: What is the spring.data.redis.* vs spring.redis.* change?
A: Spring Boot 3.1 moved Redis properties from spring.redis.* to spring.data.redis.*
   to align with other Spring Data properties (spring.data.mongodb, etc.).
   The old keys still work in 3.1 with a deprecation warning but are removed later.
