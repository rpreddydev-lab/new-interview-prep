================================================================
  EMBEDDED SERVERS: TOMCAT, JETTY, UNDERTOW — IN DEPTH
================================================================

================================================================
OVERVIEW
================================================================

  Spring Boot embeds an HTTP server directly into the application
  JAR. No external server installation needed.

  Supported servers:
    • Tomcat  (default for spring-boot-starter-web)
    • Jetty   (alternative; good for WebSocket-heavy apps)
    • Undertow (best throughput; recommended for reactive workloads)
    • Netty   (default for spring-boot-starter-webflux)
    • Reactor Netty (WebFlux reactive stack)

================================================================
HOW EMBEDDING WORKS
================================================================

  1. Spring Boot packages the server JARs inside the fat JAR
  2. @SpringBootApplication triggers ServletWebServerFactoryAutoConfiguration
  3. Detects TomcatServletWebServerFactory / JettyServletWebServerFactory
  4. Creates an EmbeddedWebServer and starts it
  5. Registers DispatcherServlet into the embedded container
  6. App listens on configured port (default: 8080)

  Key auto-config class:
    EmbeddedWebServerFactoryCustomizerAutoConfiguration

================================================================
TOMCAT — DEFAULT SERVER
================================================================

  Included by: spring-boot-starter-web (via spring-boot-starter-tomcat)

  # Basic configuration
  server.port=8080
  server.servlet.context-path=/api

  # Thread pool
  server.tomcat.threads.min-spare=10
  server.tomcat.threads.max=200          # default 200
  server.tomcat.accept-count=100         # queue size when all threads busy

  # Timeouts
  server.tomcat.connection-timeout=5s
  server.tomcat.keep-alive-timeout=20s

  # Request limits
  server.tomcat.max-swallow-size=2MB     # max request body Tomcat reads
  server.tomcat.max-http-form-post-size=2MB

  # Access log
  server.tomcat.accesslog.enabled=true
  server.tomcat.accesslog.directory=logs
  server.tomcat.accesslog.pattern=%t "%r" %s %b %D ms

================================================================
TOMCAT PROGRAMMATIC CUSTOMIZATION
================================================================

  @Bean
  public WebServerFactoryCustomizer<TomcatServletWebServerFactory>
          tomcatCustomizer() {
      return factory -> {
          factory.addConnectorCustomizers(connector -> {
              connector.setMaxPostSize(10 * 1024 * 1024); // 10MB
              ((AbstractHttp11Protocol<?>) connector.getProtocolHandler())
                  .setConnectionTimeout(10000);
          });

          // Add AJP connector (for Apache httpd reverse proxy)
          Connector ajpConnector = new Connector("AJP/1.3");
          ajpConnector.setPort(8009);
          ajpConnector.setSecure(false);
          factory.addAdditionalTomcatConnectors(ajpConnector);
      };
  }

SWITCHING TO JETTY
================================================================

  <!-- pom.xml -->
  <dependency>
      <groupId>org.springframework.boot</groupId>
      <artifactId>spring-boot-starter-web</artifactId>
      <exclusions>
          <exclusion>
              <groupId>org.springframework.boot</groupId>
              <artifactId>spring-boot-starter-tomcat</artifactId>
          </exclusion>
      </exclusions>
  </dependency>

  <dependency>
      <groupId>org.springframework.boot</groupId>
      <artifactId>spring-boot-starter-jetty</artifactId>
  </dependency>

  # Jetty configuration
  server.jetty.threads.min=8
  server.jetty.threads.max=200
  server.jetty.threads.idle-timeout=60000
  server.jetty.connection-idle-timeout=60s

  Jetty advantages:
    ✓ Supports HTTP/2 out of the box
    ✓ Lighter memory footprint
    ✓ Better for long-lived HTTP connections, WebSocket

================================================================
SWITCHING TO UNDERTOW
================================================================

  <dependency>
      <groupId>org.springframework.boot</groupId>
      <artifactId>spring-boot-starter-web</artifactId>
      <exclusions>
          <exclusion>
              <groupId>org.springframework.boot</groupId>
              <artifactId>spring-boot-starter-tomcat</artifactId>
          </exclusion>
      </exclusions>
  </dependency>

  <dependency>
      <groupId>org.springframework.boot</groupId>
      <artifactId>spring-boot-starter-undertow</artifactId>
  </dependency>

  # Undertow configuration
  server.undertow.threads.io=2           # IO threads (default: CPU cores)
  server.undertow.threads.worker=16      # worker threads (default: 8*IO)
  server.undertow.buffer-size=1024
  server.undertow.direct-buffers=true

  Undertow advantages:
    ✓ Non-blocking I/O model → highest throughput
    ✓ Very low memory per connection
    ✓ Best for reactive WebFlux apps (or high-concurrency servlet)
    ✓ HTTP/2 and HTTP/3 support

================================================================
COMPARISON TABLE
================================================================

  Feature            | Tomcat          | Jetty           | Undertow
  -------------------|-----------------|-----------------|------------------
  Default in          | spring-web      | Optional        | Optional
  Threading model     | Thread-per-req  | Thread-per-req  | Non-blocking NIO
  HTTP/2              | Yes             | Yes             | Yes
  WebSocket           | Yes             | Excellent       | Yes
  Memory footprint    | Higher          | Medium          | Low
  Throughput          | Good            | Good            | Best
  Config prefix       | server.tomcat   | server.jetty    | server.undertow
  Virtual threads*    | Yes (3.2+)      | Yes             | Limited

  * Spring Boot 3.2+ supports Project Loom virtual threads with Tomcat

HTTPS/TLS CONFIGURATION
================================================================

  # Generate self-signed (dev only):
  # keytool -genkeypair -alias myapp -keyalg RSA -keysize 2048
  #   -keystore keystore.jks -validity 365

  # application.properties
  server.ssl.enabled=true
  server.ssl.key-store=classpath:keystore.jks
  server.ssl.key-store-password=changeit
  server.ssl.key-store-type=JKS
  server.ssl.key-alias=myapp
  server.port=8443

  # PKCS12 (preferred over JKS):
  server.ssl.key-store=classpath:keystore.p12
  server.ssl.key-store-type=PKCS12

  # Redirect HTTP → HTTPS
  @Bean
  public ServletWebServerFactory servletContainer() {
      TomcatServletWebServerFactory tomcat =
          new TomcatServletWebServerFactory() {
              @Override
              protected void postProcessContext(Context context) {
                  SecurityConstraint constraint = new SecurityConstraint();
                  constraint.setUserConstraint("CONFIDENTIAL");
                  SecurityCollection collection = new SecurityCollection();
                  collection.addPattern("/*");
                  constraint.addCollection(collection);
                  context.addConstraint(constraint);
              }
          };
      tomcat.addAdditionalTomcatConnectors(redirectConnector());
      return tomcat;
  }

  private Connector redirectConnector() {
      Connector c = new Connector("org.apache.coyote.http11.Http11NioProtocol");
      c.setScheme("http");
      c.setPort(8080);
      c.setSecure(false);
      c.setRedirectPort(8443);
      return c;
  }

================================================================
HTTP/2 CONFIGURATION
================================================================

  server.http2.enabled=true

  Requires: HTTPS or h2c (cleartext HTTP/2) depending on server.
  Tomcat requires native APR library or Java 9+ ALPN support.
  Jetty and Undertow support it out of the box.

================================================================
GRACEFUL SHUTDOWN
================================================================

  # application.properties (Spring Boot 2.3+)
  server.shutdown=graceful
  spring.lifecycle.timeout-per-shutdown-phase=30s

  On shutdown:
    1. Server stops accepting new requests
    2. In-flight requests have 30s to complete
    3. Then server shuts down

================================================================
VIRTUAL THREADS (SPRING BOOT 3.2+ / JAVA 21)
================================================================

  # Replace thread pool with virtual threads (Project Loom)
  spring.threads.virtual.enabled=true

  Effect: Tomcat uses virtual threads instead of platform threads
  → can handle many more concurrent connections
  → better throughput for I/O-bound workloads

================================================================
INTERVIEW QUESTIONS — EMBEDDED SERVERS
================================================================

  Q: How does Spring Boot embed a server?
  A: Spring Boot auto-configuration creates a
     ServletWebServerFactory bean (TomcatServletWebServerFactory by
     default), which starts the server and registers DispatcherServlet.

  Q: How do you change the embedded server from Tomcat to Undertow?
  A: Exclude spring-boot-starter-tomcat from spring-boot-starter-web
     and add spring-boot-starter-undertow.

  Q: What is the difference between Tomcat and Undertow?
  A: Tomcat uses a thread-per-request model; Undertow uses a
     non-blocking NIO model, resulting in higher throughput and
     lower memory per connection.

  Q: How do you configure graceful shutdown?
  A: Set server.shutdown=graceful and optionally
     spring.lifecycle.timeout-per-shutdown-phase=30s.

  Q: What is the benefit of virtual threads with embedded Tomcat?
  A: Virtual threads (Java 21 / Spring Boot 3.2) allow Tomcat to
     handle far more concurrent requests without blocking OS threads,
     improving scalability for I/O-bound workloads.
