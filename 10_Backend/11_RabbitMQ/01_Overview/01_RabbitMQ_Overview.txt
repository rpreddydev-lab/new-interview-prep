RABBITMQ OVERVIEW
=================

What is RabbitMQ?
- Open-source message broker implementing AMQP (Advanced Message Queuing Protocol)
- Built in Erlang — known for high availability and fault tolerance
- Supports multiple messaging protocols: AMQP 0-9-1, AMQP 1.0, MQTT, STOMP
- Used for asynchronous communication between services

Core Value Proposition:
- Decouples producers from consumers
- Supports complex routing via exchanges
- Provides reliable delivery with acknowledgements and persistence
- Lightweight compared to Kafka — ideal for task queues and RPC patterns

When to Use RabbitMQ:
- Task queues and background job processing
- Request/reply (RPC) patterns
- Complex routing (fan-out, topic, header-based)
- Short-lived messages that don't need long retention
- Workflows and pipelines with acknowledged delivery

RabbitMQ vs Kafka (High Level):
+-----------------+------------------+------------------+
| Feature         | RabbitMQ         | Kafka            |
+-----------------+------------------+------------------+
| Message Model   | Queue-based      | Log-based        |
| Retention       | Until consumed   | Time/size-based  |
| Routing         | Exchange/Binding | Topics only      |
| Ordering        | Per-queue        | Per-partition    |
| Replay          | No               | Yes              |
| Throughput      | Moderate         | Very high        |
| Use Case        | Task queues, RPC | Event streaming  |
+-----------------+------------------+------------------+

RabbitMQ Architecture:
- Producer → Exchange → Queue → Consumer
- Exchange routes messages based on bindings and routing keys
- Queues buffer messages until consumers are ready
- Channels are lightweight connections within a TCP connection

Key Terms:
- Producer: sends messages to the exchange
- Exchange: routes messages to queues based on bindings
- Queue: stores messages for consumers
- Consumer: reads and processes messages
- Binding: rule connecting an exchange to a queue with an optional routing key
- Channel: virtual connection inside a TCP connection
- vHost: virtual host for isolation (multi-tenancy within one broker)

Management UI:
- RabbitMQ ships with a management plugin (default port 15672)
- Shows queues, exchanges, consumers, message rates, and connections
- Useful for debugging and monitoring

Interview Points:
- RabbitMQ uses push-based delivery (broker pushes to consumer)
- Kafka uses pull-based delivery (consumer pulls from broker)
- RabbitMQ supports acks, nacks, requeuing — fine-grained delivery control
- prefetchCount (QoS) controls how many unacknowledged messages a consumer can hold
