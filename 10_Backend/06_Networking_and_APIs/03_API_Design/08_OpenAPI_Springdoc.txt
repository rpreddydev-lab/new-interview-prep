======================================================
OPENAPI 3 & SPRINGDOC — API DOCUMENTATION IN SPRING BOOT
======================================================

1. OVERVIEW
────────────
OpenAPI 3.0 (formerly Swagger): industry-standard spec for describing REST APIs.
Springdoc OpenAPI: Spring Boot library that auto-generates OpenAPI 3 spec from code.

Key benefits:
  - Auto-generates API documentation from annotations
  - Swagger UI for interactive API testing
  - Machine-readable spec for client code generation
  - Contract-first or code-first development


2. DEPENDENCY
──────────────
Spring Boot 3.x:
  <dependency>
    <groupId>org.springdoc</groupId>
    <artifactId>springdoc-openapi-starter-webmvc-ui</artifactId>
    <version>2.5.0</version>
  </dependency>

For WebFlux (reactive):
  springdoc-openapi-starter-webflux-ui

Auto-configured endpoints:
  /v3/api-docs          → OpenAPI JSON spec
  /v3/api-docs.yaml     → OpenAPI YAML spec
  /swagger-ui.html      → Swagger UI (browser)
  /swagger-ui/index.html→ Alternative UI URL


3. BASIC CONFIGURATION
────────────────────────
application.yml:
  springdoc:
    api-docs:
      path: /v3/api-docs          # default
      enabled: true
    swagger-ui:
      path: /swagger-ui.html      # default
      enabled: true
      try-it-out-enabled: true    # enable "Try it out" button
      operations-sorter: method   # sort by HTTP method
      tags-sorter: alpha          # sort tags alphabetically
    show-actuator: true           # include actuator endpoints in docs
    default-produces-media-type: application/json


4. API INFO CUSTOMIZATION
──────────────────────────
  @Bean
  public OpenAPI customOpenAPI() {
      return new OpenAPI()
          .info(new Info()
              .title("Order Management API")
              .description("API for managing orders and payments")
              .version("2.0.0")
              .contact(new Contact()
                  .name("API Support")
                  .email("api@example.com"))
              .license(new License()
                  .name("Apache 2.0")
                  .url("https://www.apache.org/licenses/LICENSE-2.0")))
          .externalDocs(new ExternalDocumentation()
              .description("Full Documentation")
              .url("https://docs.example.com"))
          .addSecurityItem(new SecurityRequirement().addList("bearerAuth"))
          .components(new Components()
              .addSecuritySchemes("bearerAuth",
                  new SecurityScheme()
                      .type(SecurityScheme.Type.HTTP)
                      .scheme("bearer")
                      .bearerFormat("JWT")));
  }


5. CONTROLLER ANNOTATIONS
───────────────────────────
  @Tag(name = "Users", description = "User management operations")
  @RestController
  @RequestMapping("/api/v1/users")
  public class UserController {

      @Operation(
          summary = "Get user by ID",
          description = "Returns a single user by their unique identifier",
          responses = {
              @ApiResponse(responseCode = "200", description = "User found",
                  content = @Content(schema = @Schema(implementation = UserDto.class))),
              @ApiResponse(responseCode = "404", description = "User not found",
                  content = @Content(schema = @Schema(implementation = ErrorResponse.class))),
              @ApiResponse(responseCode = "401", description = "Unauthorized")
          }
      )
      @GetMapping("/{id}")
      public ResponseEntity<UserDto> getUser(
          @Parameter(description = "Unique ID of the user", required = true, example = "123")
          @PathVariable Long id) {
          ...
      }

      @Operation(summary = "Create a new user")
      @PostMapping
      public ResponseEntity<UserDto> createUser(
          @RequestBody(description = "User creation data", required = true,
              content = @Content(schema = @Schema(implementation = CreateUserRequest.class)))
          @Valid @org.springframework.web.bind.annotation.RequestBody CreateUserRequest request) {
          ...
      }
  }


6. MODEL ANNOTATIONS
──────────────────────
  @Schema(description = "User data transfer object")
  public class UserDto {

      @Schema(description = "Unique identifier", example = "123", accessMode = Schema.AccessMode.READ_ONLY)
      private Long id;

      @Schema(description = "User's full name", example = "John Doe", required = true)
      private String name;

      @Schema(description = "Email address", example = "john@example.com")
      private String email;

      @Schema(description = "Account status", allowableValues = {"ACTIVE", "INACTIVE", "SUSPENDED"})
      private String status;

      @Schema(description = "User creation timestamp", accessMode = Schema.AccessMode.READ_ONLY)
      private LocalDateTime createdAt;
  }


7. SECURITY IN SWAGGER UI
───────────────────────────
Add JWT auth to Swagger UI:
  @Bean
  public OpenAPI openAPI() {
      return new OpenAPI()
          .addSecurityItem(new SecurityRequirement().addList("JWT"))
          .components(new Components().addSecuritySchemes("JWT",
              new SecurityScheme()
                  .name("JWT")
                  .type(SecurityScheme.Type.HTTP)
                  .scheme("bearer")
                  .bearerFormat("JWT")
                  .in(SecurityScheme.In.HEADER)));
  }

Apply to all or specific operations:
  @SecurityRequirement(name = "JWT")
  @Operation(summary = "Protected endpoint")
  @GetMapping("/protected")
  public ResponseEntity<String> protectedEndpoint() { ... }

Allow Swagger UI through Spring Security (do NOT expose in production):
  http.authorizeHttpRequests(auth -> auth
      .requestMatchers("/swagger-ui/**", "/v3/api-docs/**").permitAll()
      .anyRequest().authenticated());

  // Protect in production with Basic Auth or IP allowlist
  // Disable entirely: springdoc.api-docs.enabled=false


8. MULTIPLE API GROUPS (VERSIONING)
─────────────────────────────────────
  springdoc:
    group-configs:
      - group: v1
        display-name: API v1 (Deprecated)
        paths-to-match: /api/v1/**
      - group: v2
        display-name: API v2
        paths-to-match: /api/v2/**

Or programmatically:
  @Bean
  public GroupedOpenApi v1Api() {
      return GroupedOpenApi.builder()
          .group("v1")
          .displayName("API v1")
          .pathsToMatch("/api/v1/**")
          .build();
  }

  @Bean
  public GroupedOpenApi v2Api() {
      return GroupedOpenApi.builder()
          .group("v2")
          .displayName("API v2")
          .pathsToMatch("/api/v2/**")
          .addOpenApiCustomizer(openApi ->
              openApi.info(new Info().title("Order API v2").version("2.0")))
          .build();
  }


9. CODE GENERATION FROM OPENAPI SPEC
──────────────────────────────────────
Contract-first: write OpenAPI YAML spec first, generate code.

  openapi-generator-maven-plugin:
    <plugin>
      <groupId>org.openapitools</groupId>
      <artifactId>openapi-generator-maven-plugin</artifactId>
      <configuration>
        <inputSpec>${project.basedir}/src/main/resources/api.yaml</inputSpec>
        <generatorName>spring</generatorName>
        <configOptions>
          <interfaceOnly>true</interfaceOnly>
          <useSpringBoot3>true</useSpringBoot3>
        </configOptions>
      </configuration>
    </plugin>

  Generates: interfaces that your controllers implement → spec stays as truth.


10. PRODUCTION BEST PRACTICES
───────────────────────────────
  - Disable Swagger UI in production (security risk)
  - Use spring profiles: springdoc.swagger-ui.enabled: false (in prod profile)
  - Alternatively: restrict by IP in API Gateway / load balancer
  - Expose API docs only in dev/staging environments
  - Generate static docs at build time: springdoc-openapi-maven-plugin
  - Include OpenAPI spec in CI/CD for contract testing (consumer-driven)


11. INTERVIEW QUESTIONS
──────────────────────
Q: What is Springdoc OpenAPI and how does it differ from old Springfox?
A: Springdoc is the replacement for Springfox (abandoned). Springdoc supports
   OpenAPI 3.0, Spring Boot 3 / Spring 6, WebFlux, and is actively maintained.
   Springfox only supported Swagger 2 (OpenAPI 2) and is incompatible with
   Spring Boot 3.

Q: How do you secure Swagger UI in a Spring Boot application?
A: Disable in production (springdoc.swagger-ui.enabled=false in prod profile).
   In staging: use Spring Security to require Basic Auth for /swagger-ui/** 
   and /v3/api-docs/**. Alternatively, expose only via VPN or API Gateway
   with IP allowlisting.

Q: What is the difference between code-first and contract-first API development?
A: Code-first: write controllers/DTOs, Springdoc generates the OpenAPI spec.
   Contract-first: write OpenAPI YAML spec first, generate controller interfaces
   from it (openapi-generator). Contract-first enforces API design before
   implementation and enables parallel frontend/backend development.

Q: How do you document paginated APIs with Springdoc?
A: Use @ParameterObject on Pageable parameters. Add dependency:
   springdoc-openapi-starter-webmvc-ui includes Pageable support.
   Springdoc converts Pageable to page, size, sort query params in Swagger UI.
