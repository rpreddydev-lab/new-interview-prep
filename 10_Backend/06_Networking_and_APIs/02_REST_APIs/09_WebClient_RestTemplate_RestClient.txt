======================================================
WEBCLIENT vs RESTTEMPLATE vs RESTCLIENT — COMPARISON
======================================================

1. OVERVIEW
────────────
Three HTTP client abstractions in Spring ecosystem:

  RestTemplate    → Classic synchronous client (Spring 3.0+, soft-deprecated)
  WebClient       → Reactive non-blocking client (Spring 5+)
  RestClient      → NEW synchronous, fluent client (Spring Boot 3.2 / Spring 6.1+)
                    Replaces RestTemplate as the recommended synchronous option


2. RESTTEMPLATE (Legacy — Spring 3.0+)
───────────────────────────────────────
Status: Soft-deprecated (not removed but no new features)

Basic usage:
  RestTemplate restTemplate = new RestTemplate();

  // GET
  User user = restTemplate.getForObject("https://api.example.com/users/{id}",
                                        User.class, 1);

  // POST
  HttpHeaders headers = new HttpHeaders();
  headers.setContentType(MediaType.APPLICATION_JSON);
  HttpEntity<CreateUserRequest> entity = new HttpEntity<>(request, headers);
  User created = restTemplate.postForObject("/users", entity, User.class);

  // Exchange (full control)
  ResponseEntity<User> response = restTemplate.exchange(
      "/users/{id}", HttpMethod.GET, null, User.class, 1);

Configure with connection pooling:
  @Bean
  public RestTemplate restTemplate() {
      PoolingHttpClientConnectionManager cm = new PoolingHttpClientConnectionManager();
      cm.setMaxTotal(100);
      cm.setDefaultMaxPerRoute(20);
      CloseableHttpClient client = HttpClients.custom()
          .setConnectionManager(cm)
          .setDefaultRequestConfig(RequestConfig.custom()
              .setConnectTimeout(3000).setSocketTimeout(5000).build())
          .build();
      return new RestTemplate(new HttpComponentsClientHttpRequestFactory(client));
  }

Limitations:
  - Verbose API (HttpEntity, ParameterizedTypeReference boilerplate)
  - No fluent builder API
  - No reactive support
  - Connection management manual


3. WEBCLIENT (Spring 5+ / Spring Boot 2+)
──────────────────────────────────────────
Reactive, non-blocking HTTP client built on Project Reactor + Netty.

Dependency:
  spring-boot-starter-webflux  (brings in Reactor Netty)
  // Can be used in servlet apps too (blocking subscribe)

Basic usage (reactive):
  WebClient client = WebClient.builder()
      .baseUrl("https://api.example.com")
      .defaultHeader(HttpHeaders.CONTENT_TYPE, MediaType.APPLICATION_JSON_VALUE)
      .build();

  // GET — returns Mono
  Mono<User> userMono = client.get()
      .uri("/users/{id}", 1)
      .retrieve()
      .bodyToMono(User.class);

  // POST — returns Mono
  Mono<User> created = client.post()
      .uri("/users")
      .bodyValue(request)
      .retrieve()
      .bodyToMono(User.class);

  // GET list — returns Flux
  Flux<User> users = client.get()
      .uri("/users")
      .retrieve()
      .bodyToFlux(User.class);

Error handling:
  client.get()
      .uri("/users/{id}", 1)
      .retrieve()
      .onStatus(HttpStatus::is4xxClientError, response ->
          response.bodyToMono(ErrorResponse.class)
              .flatMap(err -> Mono.error(new ClientException(err.getMessage()))))
      .onStatus(HttpStatus::is5xxServerError, response ->
          Mono.error(new ServerException("Server error")))
      .bodyToMono(User.class);

Use WebClient in servlet (blocking — not recommended for heavy use):
  User user = client.get()
      .uri("/users/{id}", 1)
      .retrieve()
      .bodyToMono(User.class)
      .block();  // blocks calling thread


4. RESTCLIENT (NEW — Spring Boot 3.2 / Spring 6.1)
────────────────────────────────────────────────────
Synchronous, fluent client. "WebClient API, RestTemplate internals."
Recommended replacement for RestTemplate in non-reactive apps.

Dependency: Included in spring-boot-starter-web (no extra needed).

Create:
  // Auto-configured builder:
  @Autowired
  RestClient.Builder builder;
  RestClient restClient = builder.baseUrl("https://api.example.com").build();

  // Or directly:
  RestClient restClient = RestClient.create("https://api.example.com");

  // From existing RestTemplate (migration):
  RestClient restClient = RestClient.create(existingRestTemplate);

Basic usage:
  // GET
  User user = restClient.get()
      .uri("/users/{id}", 1)
      .retrieve()
      .body(User.class);

  // GET with headers
  User user = restClient.get()
      .uri("/users/{id}", 1)
      .header(HttpHeaders.AUTHORIZATION, "Bearer " + token)
      .retrieve()
      .body(User.class);

  // GET list (ParameterizedTypeReference)
  List<User> users = restClient.get()
      .uri("/users")
      .retrieve()
      .body(new ParameterizedTypeReference<List<User>>() {});

  // POST
  User created = restClient.post()
      .uri("/users")
      .contentType(MediaType.APPLICATION_JSON)
      .body(createUserRequest)
      .retrieve()
      .body(User.class);

  // Full ResponseEntity
  ResponseEntity<User> response = restClient.get()
      .uri("/users/{id}", 1)
      .retrieve()
      .toEntity(User.class);

Error handling:
  restClient.get()
      .uri("/users/{id}", 1)
      .retrieve()
      .onStatus(HttpStatusCode::is4xxClientError, (request, response) -> {
          throw new UserNotFoundException("User not found: " + response.getStatusCode());
      })
      .onStatus(HttpStatusCode::is5xxServerError, (request, response) -> {
          throw new ServiceException("Service error");
      })
      .body(User.class);

Configure underlying HTTP client (Apache HttpComponents or JDK HttpClient):
  @Bean
  public RestClient restClient(RestClient.Builder builder) {
      return builder
          .baseUrl("https://api.example.com")
          .requestFactory(new HttpComponentsClientHttpRequestFactory(
              HttpClients.custom()
                  .setDefaultRequestConfig(RequestConfig.custom()
                      .setConnectionRequestTimeout(Timeout.ofSeconds(3))
                      .build())
                  .build()))
          .defaultHeader(HttpHeaders.ACCEPT, MediaType.APPLICATION_JSON_VALUE)
          .build();
  }


5. COMPARISON TABLE
────────────────────
Feature                | RestTemplate      | WebClient         | RestClient
─────────────────────────────────────────────────────────────────────────────────
Spring Version         | 3.0+              | 5.0+              | 6.1+ (Boot 3.2)
Blocking               | Yes               | No (reactive)     | Yes
Fluent API             | No                | Yes               | Yes
Reactive support       | No                | Yes               | No
Error handling         | Via ExceptionHandler | .onStatus()   | .onStatus()
WebFlux compatible     | Limited           | Native            | No
Dependency             | spring-web        | spring-webflux    | spring-web
Recommended for        | Legacy migration  | Reactive/WebFlux  | New servlet apps
Status                 | Soft-deprecated   | Active            | Active (new)


6. WHEN TO USE WHICH
─────────────────────
Use RestTemplate:
  → Only when migrating legacy code gradually
  → Wrap in RestClient: RestClient.create(restTemplate)

Use WebClient:
  → WebFlux (reactive) applications
  → When you need non-blocking I/O with Mono/Flux
  → Streaming responses (Server-Sent Events, large files)
  → When using Project Reactor in the calling code

Use RestClient:
  → New Spring Boot 3.2+ servlet applications
  → Replacing RestTemplate with modern, fluent API
  → Synchronous calls where reactive complexity is not needed
  → Simpler code than WebClient for synchronous use cases


7. SPRING BOOT AUTO-CONFIGURATION
───────────────────────────────────
Spring Boot auto-configures:
  RestTemplate.Builder — inject and customize:
    @Bean
    public RestTemplate restTemplate(RestTemplateBuilder builder) {
        return builder.connectTimeout(Duration.ofSeconds(3))
                      .readTimeout(Duration.ofSeconds(5))
                      .build();
    }

  RestClient.Builder — inject and customize (Spring Boot 3.2+):
    @Bean
    public RestClient orderServiceClient(RestClient.Builder builder) {
        return builder
            .baseUrl("https://order-service.internal")
            .build();
    }

  WebClient.Builder — inject (via spring-boot-starter-webflux):
    @Bean
    public WebClient userServiceClient(WebClient.Builder builder) {
        return builder.baseUrl("https://user-service.internal").build();
    }


8. INTERVIEW QUESTIONS
──────────────────────
Q: What is RestClient and why was it introduced in Spring 6.1?
A: RestClient is a synchronous HTTP client with a fluent API similar to WebClient.
   It was introduced to replace RestTemplate (which was verbose and lacked a fluent API)
   while keeping the simplicity of synchronous code for non-reactive applications.

Q: When would you use WebClient in a non-reactive Spring MVC application?
A: When you need concurrent outbound HTTP calls or want to compose async pipelines.
   However, calling .block() on Mono within Tomcat threads is wasteful.
   With Spring Boot 3.2 + virtual threads, prefer RestClient + virtual threads
   for simpler code with similar concurrency benefits.

Q: What is the recommended way to migrate from RestTemplate to RestClient?
A: RestClient can wrap an existing RestTemplate: RestClient.create(restTemplate).
   This preserves the underlying HTTP client configuration (connection pooling,
   timeouts) while providing the new fluent API.

Q: How does RestClient handle HTTP errors differently from RestTemplate?
A: RestTemplate throws HttpClientErrorException/HttpServerErrorException automatically.
   RestClient also throws RestClientException by default for 4xx/5xx but allows
   custom handling per-status via .onStatus() callback, similar to WebClient.

Q: Can you use WebClient in a Spring MVC (non-WebFlux) application?
A: Yes, but you need to add spring-boot-starter-webflux. You can use WebClient
   reactively or call .block() to get synchronous results. However, mixing reactive
   and servlet model can cause complications. For simple HTTP calls in Spring MVC,
   prefer RestClient (Spring Boot 3.2+).
