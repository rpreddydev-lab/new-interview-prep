MICROMETER — METRICS FACADE FOR JAVA
======================================

What is Micrometer?
- Vendor-neutral application metrics facade for JVM applications
- Like SLF4J but for metrics — write once, export to any backend
- Built into Spring Boot (auto-configured)
- Supports: Prometheus, Datadog, CloudWatch, InfluxDB, Dynatrace, New Relic, etc.

=== METER TYPES ===

1. COUNTER
   - Monotonically increasing value (never decreases)
   - Use: counting events (orders processed, errors thrown, logins)

   Counter counter = Counter.builder("orders.processed")
       .tag("status", "success")
       .description("Number of processed orders")
       .register(meterRegistry);
   counter.increment();
   counter.increment(5.0);  // increment by specific amount

2. GAUGE
   - Value that can go up and down
   - Use: current state (queue size, active connections, cache size)

   Gauge.builder("queue.size", queueService, QueueService::size)
       .register(meterRegistry);
   // Updated automatically when polled

3. TIMER
   - Measures latency and throughput (count, total time, max)
   - Creates a histogram automatically for percentile calculation
   - Use: HTTP request duration, DB query time

   Timer timer = Timer.builder("http.request.duration")
       .tag("method", "POST")
       .tag("uri", "/orders")
       .publishPercentileHistogram()   // enables p50, p95, p99
       .register(meterRegistry);

   timer.record(() -> processOrder());
   // or:
   Timer.Sample sample = Timer.start(meterRegistry);
   // ... do work ...
   sample.stop(timer);

4. DISTRIBUTION SUMMARY
   - Like Timer but for non-time values (payload size, response size)

   DistributionSummary.builder("response.size")
       .baseUnit("bytes")
       .register(meterRegistry);

5. LONG TASK TIMER
   - Measures tasks that are currently running (ongoing operations)
   - Use: batch job duration, long-running scheduled tasks

6. FUNCTION COUNTER / FUNCTION TIMER
   - Wraps a function that returns a count/time value
   - Use: wrap existing counter from a library

=== TAGS (DIMENSIONS) ===

Tags add dimensions to metrics — essential for filtering in dashboards.

Key principle: LOW CARDINALITY tags only!
- Good: tag("status", "200"), tag("region", "us-east")
- Bad:  tag("userId", userId) — infinite cardinality, breaks Prometheus

Common tags:
  .tag("service", "order-service")
  .tag("environment", "production")
  .tag("method", request.getMethod())
  .tag("status", String.valueOf(response.getStatus()))

Global tags (applied to all meters):
  management.metrics.tags.application=${spring.application.name}

=== SPRING BOOT AUTO-INSTRUMENTATION ===

Spring Boot auto-configures these meters:
- jvm.*        — heap, GC, threads, classes loaded
- process.*    — CPU usage, uptime
- system.*     — CPU count, file descriptors
- tomcat.*     — active sessions, request count
- http.server.requests — per-endpoint latency, count, errors
- spring.data.* — repository query times
- cache.*      — hit rate, miss rate
- hikaricp.*   — connection pool metrics

@Timed(value = "order.processing.time", percentiles = {0.5, 0.95, 0.99})
public Order processOrder(OrderRequest request) {
    // automatically timed
}

=== CUSTOM METRICS IN SPRING ===

@Component
public class OrderMetrics {

    private final Counter orderSuccessCounter;
    private final Counter orderFailureCounter;
    private final Timer orderTimer;
    private final AtomicInteger pendingOrders;

    public OrderMetrics(MeterRegistry registry) {
        orderSuccessCounter = registry.counter("orders.success");
        orderFailureCounter = registry.counter("orders.failure");
        orderTimer = Timer.builder("orders.duration")
            .publishPercentileHistogram()
            .register(registry);
        pendingOrders = registry.gauge("orders.pending", new AtomicInteger(0));
    }

    public void recordSuccess() { orderSuccessCounter.increment(); }
    public void recordFailure() { orderFailureCounter.increment(); }
    public void recordDuration(Runnable task) { orderTimer.record(task); }
    public void setPending(int count) { pendingOrders.set(count); }
}

=== PROMETHEUS ENDPOINT ===

Add dependency: micrometer-registry-prometheus

application.yml:
  management:
    endpoints:
      web:
        exposure:
          include: health,metrics,prometheus
    metrics:
      export:
        prometheus:
          enabled: true

Endpoint: GET /actuator/prometheus
Format: Prometheus text format (scraped by Prometheus server)

=== METER REGISTRY COMPOSITE ===

Can export to multiple backends simultaneously:
  @Bean
  public MeterRegistry compositeMeterRegistry() {
      CompositeMeterRegistry registry = new CompositeMeterRegistry();
      registry.add(new PrometheusMeterRegistry(PrometheusConfig.DEFAULT));
      registry.add(new DatadogMeterRegistry(config, Clock.SYSTEM));
      return registry;
  }
