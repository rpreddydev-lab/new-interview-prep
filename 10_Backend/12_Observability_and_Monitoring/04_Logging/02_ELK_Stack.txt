ELK STACK — ELASTICSEARCH, LOGSTASH, KIBANA
============================================

=== WHAT IS ELK? ===

ELK Stack = Elasticsearch + Logstash + Kibana
Modern: ELK + Beats = "Elastic Stack"

Elasticsearch: distributed search and analytics engine (stores logs)
Logstash:      log pipeline — ingest, parse, transform, ship logs
Kibana:        visualization UI for Elasticsearch — dashboards, search, alerts
Beats:         lightweight data shippers (Filebeat, Metricbeat, etc.)

=== LOG FLOW ===

Application → (writes) → Log Files
                              ↓
                         Filebeat (tail logs, ship to Logstash)
                              ↓
                         Logstash (parse, enrich, filter)
                              ↓
                       Elasticsearch (index and store)
                              ↓
                          Kibana (search and visualize)

Modern simplified flow (JSON logs):
Application (JSON logs) → Filebeat → Elasticsearch → Kibana
(Skip Logstash if logs are already structured JSON)

=== FILEBEAT ===

Lightweight agent running on each server/container
- Tails log files or reads from stdin
- Ships logs to Logstash or directly to Elasticsearch

filebeat.yml:
  filebeat.inputs:
    - type: log
      paths:
        - /var/log/myapp/*.log
      json.keys_under_root: true
      json.add_error_key: true

  output.logstash:
    hosts: ["logstash:5044"]

In Kubernetes: Filebeat as DaemonSet to collect logs from all pods.

=== LOGSTASH PIPELINE ===

logstash.conf:
  input {
    beats { port => 5044 }
  }

  filter {
    if [type] == "java" {
      # Parse stack traces (multiline)
      mutate { add_field => { "[@metadata][target_index]" => "java-logs" } }
    }
    # Enrich with geo-ip
    geoip { source => "clientIp" }
    # Parse date
    date { match => ["timestamp", "ISO8601"] }
  }

  output {
    elasticsearch {
      hosts => ["elasticsearch:9200"]
      index => "%{[@metadata][target_index]}-%{+YYYY.MM.dd}"
    }
  }

=== ELASTICSEARCH INDEX STRATEGY ===

Time-based indices (common for logs):
  logs-2024.01.15, logs-2024.01.16, ...
  Advantage: easy to delete old data (delete old index, not individual docs)

Index Lifecycle Management (ILM):
  Hot → Warm → Cold → Delete
  - Hot:  active writing + fast querying (SSD)
  - Warm: read-only, less frequently queried (HDD)
  - Cold: rarely accessed, compressed
  - Delete: after retention period

=== KIBANA FEATURES ===

Discover:
- Full-text search across logs
- Filter by time range, field values
- See individual log events with all fields

Visualize / Dashboard:
- Time series graphs (error rates over time)
- Pie charts (distribution of log levels)
- Data tables (slowest endpoints)

Lens:
- Drag-and-drop analytics builder
- Build complex visualizations without knowing query language

KQL (Kibana Query Language):
  level: "ERROR" and service: "order-service"
  message: "timeout" and NOT message: "connection"
  response_time > 2000

=== ELK WITH SPRING BOOT ===

Step 1: Add logstash-logback-encoder → structured JSON logs
Step 2: Filebeat collects logs from container stdout
Step 3: Ships to Elasticsearch
Step 4: Kibana queries with traceId, orderId, etc.

The power: given a traceId from a user complaint →
  Kibana: filter by traceId → see ALL log lines from ALL services for that request
  Jaeger: view the trace visually → see WHERE time was spent

=== ALTERNATIVES TO ELK ===

Loki (Grafana):
- Stores only log metadata (no full-text index) → much cheaper
- Queries by labels (like Prometheus) — LogQL
- Best when already using Grafana/Prometheus stack

Splunk:
- Enterprise-grade, very powerful, expensive
- Common in large enterprises and financial industry

AWS CloudWatch Logs:
- Managed — no infrastructure
- CloudWatch Logs Insights for querying
- Integrates with AWS ecosystem natively

Datadog Log Management:
- Fully managed, expensive
- Excellent correlation between logs, metrics, traces in one UI
