WHAT IS GRADLE?
───────────────
Gradle is a modern build automation tool designed to handle the build, testing,
and deployment of software. It combines Maven's convention-over-configuration
philosophy with Ant's flexibility and scripting power.

  Released: 2012
  Language: Groovy DSL (build.gradle) or Kotlin DSL (build.gradle.kts)
  Default build tool for: Android, Kotlin Multiplatform, Quarkus (gaining)
  Also popular in: Spring Boot, enterprise Java, Scala projects

─────────────────────────────────────────────────────────────────────────────────
KEY CONCEPTS
─────────────────────────────────────────────────────────────────────────────────

  Concept               Description
  ─────────────────────────────────────────────────────────────────────────────
  Project               The thing being built (maps to one build.gradle file)
  Task                  A unit of work (compile, test, jar, etc.)
  Plugin                Adds tasks and conventions to a project
  DAG                   Directed Acyclic Graph — task dependency graph
  Configuration         A named set of dependencies with a specific role
  Dependency            An artifact required during build or execution
  Repository            Where to find artifacts
  Build Cache           Stores task outputs for reuse across builds
  Incremental Build     Only re-run tasks whose inputs/outputs changed
  Build Script          build.gradle or build.gradle.kts
  Settings Script       settings.gradle / settings.gradle.kts (multi-project)
  Gradle Wrapper        Pinned Gradle version script (gradlew)

─────────────────────────────────────────────────────────────────────────────────
GRADLE EXECUTION MODEL
─────────────────────────────────────────────────────────────────────────────────

  Gradle's build lifecycle has THREE phases (NOT the same as Maven phases):

  1. INITIALIZATION PHASE
     ───────────────────────
     • Reads settings.gradle to determine which projects are in the build
     • Creates a Project object for each included project
     • For multi-project builds, determines the project hierarchy

  2. CONFIGURATION PHASE
     ────────────────────────
     • Executes all build scripts (build.gradle) for all projects
     • Builds the task graph (DAG) — determines what tasks exist and their relationships
     • Does NOT execute any task logic (only wires them up)
     • ALL build scripts run even if you only run one task
     • Note: Configuration cache (Gradle 7.4+) skips this phase on cache hit

  3. EXECUTION PHASE
     ─────────────────────
     • Executes the requested tasks in dependency order
     • Skips UP-TO-DATE tasks (incremental build)
     • Skips tasks with FROM-CACHE label (build cache)

  WHY THIS MATTERS: "Don't do I/O or heavy work during configuration phase"
  (i.e., avoid logic at the top level of build.gradle that runs during config)

─────────────────────────────────────────────────────────────────────────────────
GRADLE PROJECT STRUCTURE
─────────────────────────────────────────────────────────────────────────────────

  my-project/
  ├── build.gradle.kts           ← Build script (Kotlin DSL)
  ├── settings.gradle.kts        ← Project name + subproject declarations
  ├── gradle.properties          ← Gradle properties (JVM args, versions)
  ├── gradlew                    ← Gradle Wrapper script (Unix)
  ├── gradlew.bat                ← Gradle Wrapper script (Windows)
  ├── gradle/
  │   └── wrapper/
  │       ├── gradle-wrapper.properties  ← Wrapper config (Gradle version)
  │       └── gradle-wrapper.jar         ← Wrapper bootstrap JAR
  └── src/
      ├── main/
      │   ├── java/             ← Production Java code
      │   └── resources/        ← Production resources
      └── test/
          ├── java/             ← Test code
          └── resources/        ← Test resources

  Note: Gradle follows the same src/main/java structure as Maven by convention
  (when using the java plugin). This can be customized.

─────────────────────────────────────────────────────────────────────────────────
SIMPLE BUILD SCRIPT EXAMPLE
─────────────────────────────────────────────────────────────────────────────────

  settings.gradle.kts:
  ─────────────────────
  rootProject.name = "my-application"

  build.gradle.kts (Kotlin DSL):
  ──────────────────────────────
  plugins {
      java                                         // Apply Java plugin
      id("org.springframework.boot") version "3.2.0"
      id("io.spring.dependency-management") version "1.1.4"
  }

  group = "com.example"
  version = "1.0.0-SNAPSHOT"
  java.sourceCompatibility = JavaVersion.VERSION_21

  repositories {
      mavenCentral()                               // Use Maven Central
  }

  dependencies {
      implementation("org.springframework.boot:spring-boot-starter-web")
      implementation("org.springframework.boot:spring-boot-starter-data-jpa")
      testImplementation("org.springframework.boot:spring-boot-starter-test")
  }

  tasks.test {
      useJUnitPlatform()                           // Use JUnit 5
  }

COMMON GRADLE COMMANDS
─────────────────────────────────────────────────────────────────────────────────

  Command                           Description
  ─────────────────────────────────────────────────────────────────────────────
  ./gradlew tasks                   List all available tasks
  ./gradlew tasks --all             List ALL tasks including hidden ones
  ./gradlew clean                   Delete build/ directory
  ./gradlew compileJava             Compile main sources
  ./gradlew test                    Run unit tests
  ./gradlew build                   Compile + test + package (assemble + check)
  ./gradlew jar                     Create the JAR artifact
  ./gradlew assemble                Create all artifacts without running tests
  ./gradlew check                   Run all verification tasks (tests + analysis)
  ./gradlew dependencies            Show dependency tree
  ./gradlew dependencies --configuration runtimeClasspath  → Specific config
  ./gradlew bootRun                 Run Spring Boot app (spring-boot plugin)
  ./gradlew bootJar                 Build Spring Boot executable JAR
  ./gradlew build -x test           Build and skip tests
  ./gradlew test --tests "com.example.*Test"  → Run specific tests
  ./gradlew --scan                  Publish build scan to scans.gradle.com

GRADLE DAEMON
─────────────────────────────────────────────────────────────────────────────────

  Gradle starts a long-running JVM daemon process that stays alive between builds.
  Benefits:
  • Avoids JVM startup overhead (~1-2 seconds per build)
  • JIT-compiled Gradle code runs faster over time
  • Classloading is cached

  Commands:
  ./gradlew --status          # List running daemons
  ./gradlew --stop            # Stop all running daemons
  ./gradlew --no-daemon       # Run without daemon (useful for CI)

  gradle.properties:
  org.gradle.daemon=true      # Default: true
  org.gradle.daemon.idletimeout=10800000  # 3 hours (default)

  In CI: --no-daemon is often used to avoid stale daemon issues,
  though GitHub Actions' ephemeral runners make this less important.

─────────────────────────────────────────────────────────────────────────────────
gradle.properties — JVM AND BUILD CONFIGURATION
─────────────────────────────────────────────────────────────────────────────────

  gradle.properties (in project root):
  ──────────────────────────────────────
  # JVM args for Gradle itself
  org.gradle.jvmargs=-Xmx2g -XX:+UseG1GC -Dfile.encoding=UTF-8

  # Enable parallel builds
  org.gradle.parallel=true

  # Enable configuration cache (experimental but stable in Gradle 8+)
  org.gradle.configuration-cache=true

  # Enable build cache
  org.gradle.caching=true

  # Enable incubating features
  org.gradle.warning.mode=all

  # Custom project properties
  springBootVersion=3.2.0
  javaVersion=21

  These can be overridden on the command line: -Pkey=value
  ./gradlew build -PspringBootVersion=3.3.0

INTERVIEW QUICK-HITS
─────────────────────────────────────────────────────────────────────────────────

Q: What are the three phases of a Gradle build?
A: 1. Initialization: Reads settings.gradle, determines included projects.
   2. Configuration: Executes all build scripts, builds the task graph (DAG).
      Note: ALL scripts run, not just the requested project's.
   3. Execution: Runs the requested tasks in dependency order.

Q: What is the Gradle Daemon?
A: A long-running JVM process that remains active between builds. It eliminates
   JVM startup costs and keeps JIT-compiled code warm. The daemon is enabled by
   default and dramatically speeds up repeated builds.

Q: What is the difference between "assemble" and "build" in Gradle?
A: "assemble" compiles and packages the artifact but does NOT run tests.
   "build" = assemble + check (tests, code quality checks, etc.).
   Use "assemble" when you need the artifact but don't want to wait for tests.

Q: What is the build/ directory in Gradle (vs target/ in Maven)?
A: The build/ directory is Gradle's output directory, analogous to Maven's target/.
   It contains compiled classes (build/classes/), the JAR (build/libs/), test
   reports (build/reports/), and other generated files. Never commit it to VCS.

Q: How do you pass a property to a Gradle build?
A: Using the -P flag: ./gradlew build -Pkey=value
   Access in build script: project.findProperty("key") ?: "default"
   Or define in gradle.properties file for persistent values.
