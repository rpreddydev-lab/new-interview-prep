======================================================
RBAC vs ABAC — ROLE-BASED vs ATTRIBUTE-BASED ACCESS CONTROL
======================================================

1. OVERVIEW
───────────
RBAC (Role-Based Access Control):
  - Permissions are assigned to roles; users are assigned to roles
  - Simple, widely adopted
  - Example: ROLE_ADMIN, ROLE_USER, ROLE_MANAGER

ABAC (Attribute-Based Access Control):
  - Access decisions based on attributes of user, resource, and environment
  - Fine-grained, context-aware
  - Example: user.department == resource.department AND time < 18:00

When to use:
  RBAC → simpler apps, clear role boundaries
  ABAC → complex, multi-tenant, fine-grained access (banking, healthcare)


2. RBAC IN SPRING SECURITY
───────────────────────────

a) URL-based:
  http.authorizeHttpRequests(auth -> auth
      .requestMatchers("/admin/**").hasRole("ADMIN")
      .requestMatchers("/user/**").hasAnyRole("USER", "ADMIN")
      .anyRequest().authenticated());

b) Method-level:
  @EnableMethodSecurity  // on @Configuration class

  @PreAuthorize("hasRole('ADMIN')")
  public void deleteUser(Long id) { ... }

  @PreAuthorize("hasAnyRole('USER', 'MANAGER')")
  public List<Order> getOrders() { ... }

c) Role hierarchy:
  @Bean
  public RoleHierarchy roleHierarchy() {
      RoleHierarchyImpl hierarchy = new RoleHierarchyImpl();
      hierarchy.setHierarchy("ROLE_ADMIN > ROLE_MANAGER > ROLE_USER");
      return hierarchy;
  }
  // ADMIN automatically has all MANAGER and USER permissions


3. ABAC IN SPRING SECURITY
───────────────────────────

Spring Security supports ABAC via @PreAuthorize with SpEL expressions.

a) Built-in principal access:
  @PreAuthorize("#username == authentication.principal.username")
  public User getUser(String username) { ... }

b) Custom security expression:
  @PreAuthorize("@securityService.canAccess(authentication, #docId)")
  public Document getDocument(Long docId) { ... }

  @Component("securityService")
  public class SecurityService {
      public boolean canAccess(Authentication auth, Long docId) {
          User user = (User) auth.getPrincipal();
          Document doc = docRepo.findById(docId).orElseThrow();
          return doc.getOwnerId().equals(user.getId())
              || user.getDepartment().equals(doc.getDepartment());
      }
  }

c) @PostAuthorize — filter after method execution:
  @PostAuthorize("returnObject.ownerId == authentication.principal.id")
  public Document getDocument(Long id) { ... }

d) @PreFilter / @PostFilter — filter collections:
  @PostFilter("filterObject.ownerId == authentication.principal.id")
  public List<Document> getAllDocuments() { ... }


4. PERMISSION EVALUATOR (ACL-STYLE)
──────────────────────────────────────
Spring Security ACL module provides object-level permissions.

  @PreAuthorize("hasPermission(#doc, 'READ')")
  public Document readDocument(Document doc) { ... }

  @Bean
  public PermissionEvaluator permissionEvaluator() {
      return new CustomPermissionEvaluator(); // implement hasPermission()
  }

  public class CustomPermissionEvaluator implements PermissionEvaluator {
      @Override
      public boolean hasPermission(Authentication auth, Object target,
                                   Object permission) {
          // custom logic: check user attributes vs resource attributes
      }
  }


5. MULTI-TENANT RBAC
──────────────────────
Each tenant has its own set of roles. Tenant context stored in JWT claims.

JWT payload example:
  {
    "sub": "user123",
    "tenantId": "tenant-abc",
    "roles": ["ROLE_TENANT_ADMIN"]
  }

Tenant-aware @PreAuthorize:
  @PreAuthorize("@tenantSecurity.hasRoleInTenant(authentication, 'ADMIN', #tenantId)")
  public void adminAction(String tenantId) { ... }


6. BEST PRACTICES
──────────────────
- Prefer @PreAuthorize over URL-based rules for fine-grained control
- Use RoleHierarchy to avoid redundant role assignments
- Keep security logic out of business logic (use SecurityService beans)
- Test with @WithMockUser and @WithSecurityContext for ABAC tests
- Use short-lived tokens + claim-based ABAC for stateless microservices
- Audit all access decisions in production (use AOP + logging)


7. INTERVIEW QUESTIONS
──────────────────────
Q: What is the difference between RBAC and ABAC?
A: RBAC grants permissions based on static roles. ABAC uses dynamic attributes
   (user, resource, environment) for fine-grained, context-aware decisions.

Q: How do you implement field-level security in Spring Boot?
A: Use @PostFilter or @PostAuthorize with SpEL or PermissionEvaluator.
   For DTO-level, filter fields after fetching using custom logic or Jackson views.

Q: What is @EnableMethodSecurity and why was it introduced?
A: Replaced @EnableGlobalMethodSecurity (deprecated in Spring Security 5.6).
   Enables @PreAuthorize, @PostAuthorize, @PreFilter, @PostFilter with
   improved proxy mode and native support for @Secured and JSR-250 annotations.

Q: How do you test ABAC in Spring Boot?
A: Use @WithSecurityContext to create a custom SecurityContext with specific
   user attributes. Use MockMvc + @WithMockUser for role-based tests.
   For custom principal, implement WithSecurityContextFactory.
