================================================================
  PREFIX SUM WITH HASHMAP
  (Advanced Patterns and Problem Variants)
================================================================

----------------------------------------------------------------
CORE IDEA
----------------------------------------------------------------

  The prefix sum + HashMap pattern answers questions of the form:

    "How many/longest/exists subarrays with some PROPERTY
     involving prefix sum differences?"

  TEMPLATE:
    Map<Integer, ?> map = new HashMap<>();
    map.put(baseValue, baseEntry);   // seed for empty prefix
    int prefix = 0;

    for (int x : array) {
        prefix = update(prefix, x);
        // --- LOOK UP first ---
        answer = use(map, prefix);
        // --- THEN ADD ---
        map.put(prefix, mapEntry);
    }

  What varies: baseValue, baseEntry, look-up key, mapEntry, update function.

----------------------------------------------------------------
VARIANT 1: COUNT SUBARRAYS WITH SUM = K
----------------------------------------------------------------

  map stores: {prefixSum -> count}
  seed:        {0 -> 1}
  look-up key: prefix - k
  add to ans:  map.get(prefix - k)
  mapEntry:    increment count

  public int subarraySum(int[] nums, int k) {
      Map<Integer, Integer> map = new HashMap<>();
      map.put(0, 1);
      int prefix = 0, count = 0;

      for (int x : nums) {
          prefix += x;
          count += map.getOrDefault(prefix - k, 0);
          map.merge(prefix, 1, Integer::sum);
      }
      return count;
  }

----------------------------------------------------------------
VARIANT 2: LONGEST SUBARRAY WITH SUM = K
----------------------------------------------------------------

  map stores: {prefixSum -> first index}
  seed:        {0 -> -1}
  look-up key: prefix - k
  add to ans:  i - map.get(prefix - k)
  mapEntry:    store only if absent (maximize gap)

  public int maxSubArrayLen(int[] nums, int k) {
      Map<Integer, Integer> map = new HashMap<>();
      map.put(0, -1);
      int prefix = 0, maxLen = 0;

      for (int i = 0; i < nums.length; i++) {
          prefix += nums[i];
          if (map.containsKey(prefix - k)) {
              maxLen = Math.max(maxLen, i - map.get(prefix - k));
          }
          map.putIfAbsent(prefix, i);  // first occurrence only
      }
      return maxLen;
  }

  LC 325: Maximum Size Subarray Sum Equals k
  LC 525: Contiguous Array (equal 0s and 1s, reduce to sum=0)

----------------------------------------------------------------
VARIANT 3: COUNT SUBARRAYS SUM DIVISIBLE BY K
----------------------------------------------------------------

  KEY: sum(l,r) % k == 0  iff  prefix[r] % k == prefix[l-1] % k

  map stores: {remainder -> count}
  seed:        {0 -> 1}
  look-up key: (prefix % k + k) % k   (normalize negative)
  add to ans:  map.get(rem)

  public int subarraysDivByK(int[] nums, int k) {
      Map<Integer, Integer> map = new HashMap<>();
      map.put(0, 1);
      int prefix = 0, count = 0;

      for (int x : nums) {
          prefix += x;
          int rem = ((prefix % k) + k) % k;
          count += map.getOrDefault(rem, 0);
          map.merge(rem, 1, Integer::sum);
      }
      return count;
  }

  LC 974: Subarray Sums Divisible by K

----------------------------------------------------------------
VARIANT 4: LONGEST SUBARRAY WITH AT MOST K ZEROS (LC 1004 style)
----------------------------------------------------------------

  Given binary array, return length of longest subarray with at most k zeros.

  Transform: treat 0 as -1, 1 as +1. Convert "at most k zeros" to
  "subarray sum >= length - 2k" (but simpler: use sliding window for this).

  For PREFIX SUM angle: "longest subarray with sum >= n - 2k" where
  n is the subarray length. This is actually more naturally solved
  with sliding window. But the idea of transforming the array is the key.

  Similar transformation problems:
    Equal 0s and 1s:       replace 0 with -1, find longest sum=0
    Equal a and b in arr:  replace a with +1, b with -1, find sum=0
    More a than b:         replace a with +1, b with -1, find longest sum>0

----------------------------------------------------------------
VARIANT 5: PATH SUM III (LC 437) — TREE + PREFIX SUM
----------------------------------------------------------------

  Count paths in a binary tree that sum to targetSum.
  A path goes downward (from ancestor to descendant).

  KEY: Apply prefix sum + HashMap on each root-to-node path.
  DFS traversal maintains running prefix sum.
  At each node: count += map.get(prefix - target).

  public int pathSum(TreeNode root, int targetSum) {
      Map<Long, Integer> map = new HashMap<>();
      map.put(0L, 1);
      return dfs(root, 0L, targetSum, map);
  }

  private int dfs(TreeNode node, long prefix, int target,
                  Map<Long, Integer> map) {
      if (node == null) return 0;

      prefix += node.val;
      int count = map.getOrDefault(prefix - target, 0);

      map.merge(prefix, 1, Integer::sum);
      count += dfs(node.left, prefix, target, map);
      count += dfs(node.right, prefix, target, map);
      map.merge(prefix, -1, Integer::sum);  // BACKTRACK

      return count;
  }

  CRITICAL: Backtrack after each DFS node. We decrement the map entry
  when leaving a node because paths must go downward — when we leave
  a subtree, that prefix sum is no longer "above" us on the current path.

  Time: O(n)  Space: O(n) for DFS call stack + map

  Note: Use Long for prefix to avoid integer overflow (node values
  can be negative, paths can be long).

VARIANT 6: NICE SUBARRAYS (LC 1248)
----------------------------------------------------------------

  Count subarrays with exactly k odd numbers.

  Transform: odd numbers are "1", even numbers are "0".
  Replace each element: num % 2. Problem becomes: count subarrays
  with sum = k. Same as LC 560 with this transformation.

  Alternative: atMost(k) - atMost(k-1) with sliding window.

  public int numberOfSubarrays(int[] nums, int k) {
      Map<Integer, Integer> map = new HashMap<>();
      map.put(0, 1);
      int prefix = 0, count = 0;

      for (int x : nums) {
          prefix += x & 1;  // add 1 if odd, 0 if even
          count += map.getOrDefault(prefix - k, 0);
          map.merge(prefix, 1, Integer::sum);
      }
      return count;
  }

  Time: O(n)  Space: O(n)

----------------------------------------------------------------
VARIANT 7: MINIMUM OPERATIONS TO REDUCE TO TARGET (LC 1658)
----------------------------------------------------------------

  Given nums and x, each operation removes either leftmost or
  rightmost element and subtracts it from x. Find min operations
  to make x exactly 0. Return -1 if impossible.

  TRANSFORM: Instead of finding min elements to remove from ends,
  find MAXIMUM LENGTH subarray in the middle with sum = totalSum - x.

  public int minOperations(int[] nums, int x) {
      int target = 0;
      for (int n : nums) target += n;
      target -= x;

      if (target < 0) return -1;
      if (target == 0) return nums.length;

      // Find longest subarray with sum = target (all positives, use sliding window)
      int left = 0, sum = 0, maxLen = -1;
      for (int right = 0; right < nums.length; right++) {
          sum += nums[right];
          while (sum > target) sum -= nums[left++];
          if (sum == target) maxLen = Math.max(maxLen, right - left + 1);
      }

      return maxLen == -1 ? -1 : nums.length - maxLen;
  }

  Note: Here sliding window works because all values are positive.
  If values could be negative, use prefix sum + HashMap instead.

VARIANT 8: PREFIX XOR
----------------------------------------------------------------

  For XOR problems: prefix[i] = xor of nums[0..i-1].
  Range XOR: xor(l, r) = prefix[r+1] ^ prefix[l].

  Why? XOR is its own inverse: a ^ a = 0.
    prefix[r+1] ^ prefix[l]
    = (nums[0]^...^nums[r]) ^ (nums[0]^...^nums[l-1])
    = nums[l] ^ nums[l+1] ^ ... ^ nums[r]   ✓ (earlier terms cancel)

  Count subarrays with XOR = k:
    prefix[r] ^ prefix[l-1] = k
    prefix[l-1] = prefix[r] ^ k   (XOR both sides by prefix[r])

  public int countTriplets(int[] arr) {  // LC 1442 variant
      Map<Integer, Integer> map = new HashMap<>();
      map.put(0, 1);
      int prefix = 0, count = 0;

      for (int x : arr) {
          prefix ^= x;
          count += map.getOrDefault(prefix ^ k, 0);  // where k is target
          map.merge(prefix, 1, Integer::sum);
      }
      return count;
  }

  Key difference from sum: use ^= to update, and look up (prefix ^ k).

----------------------------------------------------------------
SUMMARY: LOOKUP KEY BY PROBLEM TYPE
----------------------------------------------------------------

  Problem Type                  Prefix Type    Lookup Key
  ------------                  -----------    ----------
  sum = k                       sum            prefix - k
  sum divisible by k            sum            prefix % k
  XOR = k                       XOR            prefix ^ k
  equal a and b                 +1/-1 sum      prefix - 0 = prefix
  k odd numbers                 count of odds  prefix - k
  longest sum = k               sum            prefix - k  (putIfAbsent)

----------------------------------------------------------------
COMMON MISTAKES
----------------------------------------------------------------

  1. Forgetting put(0, 1) or put(0, -1) initialization.
     Wrong: map starts empty -> empty-prefix subarrays missed.

  2. Putting to map BEFORE looking up.
     Wrong: same index used as both start and end of subarray.

  3. For length problems: using merge() instead of putIfAbsent().
     Wrong: overwrites first index with later index, reducing length.

  4. Tree path sum: forgetting to backtrack (map.merge(prefix, -1, ...)).
     Wrong: cross-branch paths counted (paths must only go downward).

  5. Integer overflow in tree path sum: use Long, not int.

  6. Java's negative modulo: always use ((prefix % k) + k) % k.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------

  - State the formula clearly before coding.
  - Know when to use count vs first-index variant.
  - Explain the "look up BEFORE add" rule and why it matters.
  - For tree problems, always mention backtracking.
  - The XOR variant is a good follow-up to mention: same template, just
    replace += with ^= and (prefix - k) with (prefix ^ k).
