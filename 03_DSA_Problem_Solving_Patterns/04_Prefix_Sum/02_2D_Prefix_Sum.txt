================================================================
  2D PREFIX SUM
  (Matrix Range Sum Query)
================================================================

----------------------------------------------------------------
CONCEPT
----------------------------------------------------------------

  Extend 1D prefix sum to 2D grids (matrices).
  Goal: answer rectangle-sum queries in O(1) after O(m*n) preprocessing.

  prefix[i][j] = sum of all elements in the rectangle
                 from (0,0) to (i-1, j-1) (exclusive upper-left boundary).

  Indexing (1-based to avoid boundary checks):
    prefix has size (m+1) x (n+1), with prefix[0][*] = 0 and prefix[*][0] = 0.

----------------------------------------------------------------
BUILDING THE 2D PREFIX SUM
----------------------------------------------------------------

  Inclusion-Exclusion to fill prefix[i][j]:

    prefix[i][j] = matrix[i-1][j-1]
                 + prefix[i-1][j]
                 + prefix[i][j-1]
                 - prefix[i-1][j-1]

  Visualization (building):

    For cell (i,j), we want the sum of the entire top-left rectangle.

      prefix[i-1][j]    ... already includes top rect to col j
      prefix[i][j-1]    ... already includes left rect to row i
      prefix[i-1][j-1]  ... counted TWICE in the two above, subtract once

        +--------+--------+
        | top    | top    |
        | left   | right  |
        +--------+--------+
        | bot    | THIS   |
        | left   | CELL   |
        +--------+--------+

    prefix[i][j] = cell + above + left - above-left + diagonal

----------------------------------------------------------------
RANGE SUM QUERY (2D)
----------------------------------------------------------------

  To query sum of rectangle with top-left (r1,c1) and bottom-right (r2,c2)
  (0-indexed in original matrix, convert to 1-indexed in prefix):

    sum = prefix[r2+1][c2+1]
        - prefix[r1][c2+1]
        - prefix[r2+1][c1]
        + prefix[r1][c1]

  Visualization:

      0   c1  c2+1
      +----+---+
   0  | A  | B |
      +----+---+
   r1 | C  | D |  <-- query region D
      +----+---+
  r2+1

    prefix[r2+1][c2+1] = A+B+C+D (full top-left)
    - prefix[r1][c2+1]  = A+B     (strip above D)
    - prefix[r2+1][c1]  = A+C     (strip left of D)
    + prefix[r1][c1]    = A       (added back because subtracted twice)

    Result = D ✓

----------------------------------------------------------------
JAVA IMPLEMENTATION: LC 304 (Range Sum Query 2D - Immutable)
----------------------------------------------------------------

  class NumMatrix {
      private int[][] prefix;

      public NumMatrix(int[][] matrix) {
          int m = matrix.length, n = matrix[0].length;
          prefix = new int[m + 1][n + 1];

          for (int i = 1; i <= m; i++) {
              for (int j = 1; j <= n; j++) {
                  prefix[i][j] = matrix[i-1][j-1]
                               + prefix[i-1][j]
                               + prefix[i][j-1]
                               - prefix[i-1][j-1];
              }
          }
      }

      public int sumRegion(int r1, int c1, int r2, int c2) {
          return prefix[r2+1][c2+1]
               - prefix[r1][c2+1]
               - prefix[r2+1][c1]
               + prefix[r1][c1];
      }
  }

  Time: O(m*n) constructor, O(1) per query
  Space: O(m*n)

----------------------------------------------------------------
TRACED EXAMPLE
----------------------------------------------------------------

  Matrix:
    3  0  1  4  2
    5  6  3  2  1
    1  2  0  1  5
    4  1  0  1  7
    1  0  3  0  5

  Build prefix (first few cells):
    prefix[1][1] = 3 + 0 + 0 - 0 = 3
    prefix[1][2] = 0 + 3 + 0 - 0 = 3
    prefix[2][1] = 5 + 3 + 0 - 0 = 8
    prefix[2][2] = 6 + 3 + 8 - 3 = 14

  Query: sumRegion(2, 1, 4, 3)
    r1=2, c1=1, r2=4, c2=3
    = prefix[5][4] - prefix[2][4] - prefix[5][1] + prefix[2][1]

    Submatrix (rows 2-4, cols 1-3):
      2  0  1
      1  0  1
      0  3  0
    Sum = 2+0+1+1+0+1+0+3+0 = 8

PROBLEM: SUBMATRIX SUM EQUAL K (Variant)
----------------------------------------------------------------

  Count the number of submatrices that sum to target.

  Approach: For each pair of rows (top, bottom), collapse columns
  into a 1D array of column sums. Then apply 1D subarray sum = k
  (HashMap approach) on that column-sum array.

  Java:
    public int numSubmatrixSumTarget(int[][] matrix, int target) {
        int m = matrix.length, n = matrix[0].length;
        int count = 0;

        // Build 1D prefix sum per row (in-place for colSum accumulation)
        for (int[] row : matrix) {
            for (int j = 1; j < n; j++) {
                row[j] += row[j - 1];
            }
        }

        for (int c1 = 0; c1 < n; c1++) {
            for (int c2 = c1; c2 < n; c2++) {
                // colSum[r] = sum of matrix[r][c1..c2]
                Map<Integer, Integer> prefixCount = new HashMap<>();
                prefixCount.put(0, 1);
                int sum = 0;

                for (int r = 0; r < m; r++) {
                    // row[c2] - (c1>0 ? row[c1-1] : 0) = column range sum
                    sum += matrix[r][c2] - (c1 > 0 ? matrix[r][c1-1] : 0);
                    count += prefixCount.getOrDefault(sum - target, 0);
                    prefixCount.merge(sum, 1, Integer::sum);
                }
            }
        }
        return count;
    }

  Time: O(m * n^2)
  Space: O(m) per inner loop (HashMap)

  Note: This modifies the input matrix (row prefix sums).
  If modification is not allowed, build a separate prefix row array.

----------------------------------------------------------------
PROBLEM: LARGEST RECTANGLE OF 1s (Variant)
----------------------------------------------------------------

  Given a binary matrix, find the largest rectangle containing only 1s.

  Approach: For each row, compute the "height" (consecutive 1s above).
  Then apply "Largest Rectangle in Histogram" on each row's heights.

  This uses the Monotonic Stack pattern. See 07_Stack section.

  Complexity: O(m * n) per histogram scan = O(m * n) total.

----------------------------------------------------------------
PROBLEM: COUNT SUBMATRICES WITH ALL ONES (LC 1504)
----------------------------------------------------------------

  Count submatrices with all 1s (must contain at least one 1).

  Key insight: at each cell (i,j), count is how many consecutive
  1s are to the left (including itself). For a height h at column j,
  the number of new submatrices ending at (i,j) is:
    min(height[j], height[j-1], ..., height[j-h+1]) accumulated.

  This reduces to a stack-based sweep but can also use DP.

----------------------------------------------------------------
COMPLEXITY SUMMARY
----------------------------------------------------------------

  Operation                     Time        Space
  ---------                     ----        -----
  Build 2D prefix               O(m*n)      O(m*n)
  Single range query            O(1)        O(1)
  Submatrix sum = target        O(m*n^2)    O(m) per pair
  Largest rectangle of 1s       O(m*n)      O(n)

----------------------------------------------------------------
COMMON MISTAKES
----------------------------------------------------------------

  1. Off-by-one in range formula: use 1-indexed prefix array.
     Query (r1,c1)-(r2,c2) --> prefix[r2+1][c2+1] - ... (always r+1, c+1).

  2. Forgetting to add back prefix[r1][c1] in range query (the +A term).

  3. Building prefix incorrectly: MUST add prefix[i-1][j] AND prefix[i][j-1]
     AND subtract prefix[i-1][j-1].

  4. For submatrix sum = k variant: reset HashMap for each (c1,c2) pair.

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: Explain the inclusion-exclusion principle used in 2D prefix sum.
  A: When adding top-block and left-block, the top-left corner block
     is counted twice. We subtract it once to correct.

  Q: For submatrix sum queries, why can't we just use 1D prefix sum?
  A: 1D prefix only answers row-range queries for a single row. For
     a rectangular query spanning multiple rows, we need 2D prefix.

  Q: What's the space tradeoff of 2D prefix sum?
  A: We use O(m*n) extra space. This is acceptable when we have many
     queries (q). Break-even: q = O(m*n / n) = O(m) roughly.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------

  - Draw the A+B+C+D diagram on whiteboard when explaining.
  - Always state the formula before coding: build and query separately.
  - Mention that both arrays are 1-indexed (prefix is size m+1 x n+1).
  - For submatrix sum = k, explain the row-column collapse idea clearly.
