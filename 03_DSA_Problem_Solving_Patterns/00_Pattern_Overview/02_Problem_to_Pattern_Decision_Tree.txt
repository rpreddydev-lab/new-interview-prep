================================================================
  PROBLEM TO PATTERN DECISION TREE
  Step-by-Step Flowchart for Choosing the Right Approach
================================================================

Start here every time you read a new problem.

================================================================
STEP 1 -- READ INPUT TYPE
================================================================

  Input is a STRING or ARRAY?
    --> go to STEP 2

  Input is a LINKED LIST?
    --> Cycle detection?         YES  --> Fast & Slow Pointers
    --> Find middle?             YES  --> Fast & Slow Pointers
    --> Reverse / sort?          YES  --> Two Pointers (in-place)
    --> Merge sorted lists?      YES  --> Heap (merge K sorted)

  Input is a TREE?
    --> go to STEP 5

  Input is a GRAPH / GRID?
    --> go to STEP 6

  Input is just NUMBERS (no collection)?
    --> go to STEP 7

================================================================
STEP 2 -- ARRAY OR STRING: WHAT IS THE GOAL?
================================================================

  Goal: FIND A PAIR / TRIPLET satisfying a condition?
    --> Array SORTED?    YES  --> Two Pointers (opposite ends)
    --> Array UNSORTED?       --> HashSet / HashMap
    --> 3Sum?                 --> Sort + Two Pointers inner loop

  Goal: SUBARRAY / SUBSTRING that is CONTIGUOUS?
    --> go to STEP 3

  Goal: COUNT or FIND subarrays with a SUM equal to k?
    --> Prefix Sum + HashMap (running sum - k in map)

  Goal: MAXIMUM / MINIMUM element or range query?
    --> Range query (static)?  --> Prefix Sum
    --> Dynamic updates?       --> Segment Tree / Fenwick Tree
    --> Sliding window max?    --> Monotonic Deque

  Goal: SEARCH for an element or THRESHOLD?
    --> Sorted array?      YES  --> Binary Search
    --> Rotated sorted?    YES  --> Binary Search (modified)
    --> Answer is a number (minimze/maximize)?
                           YES  --> Binary Search on Answer

  Goal: GENERATE all SUBSETS / PERMUTATIONS / COMBINATIONS?
    --> Backtracking (see Step 4)

  Goal: OPTIMAL (max/min) over choices, count ways?
    --> Overlapping subproblems? --> Dynamic Programming

  Goal: SORT + pick greedily?
    --> Greedy (see Step 4)

================================================================
STEP 3 -- CONTIGUOUS SUBARRAY / SUBSTRING
================================================================

  Is the WINDOW SIZE FIXED (k elements)?
    --> Fixed Sliding Window
    --> Maintain sum/count, subtract leftmost as window slides

  Is the WINDOW SIZE VARIABLE?
    --> Variable Sliding Window
    --> Expand right; shrink left when constraint violated

  Examples:
    Max sum of size k                --> Fixed Sliding Window
    Longest substring no repeat      --> Variable Sliding Window
    Min window substring             --> Variable Sliding Window
    Substring with k distinct chars  --> Variable Sliding Window

================================================================
STEP 4 -- EXHAUSTIVE vs OPTIMAL
================================================================

  "Find ALL solutions" or "Generate ALL combinations"?
    --> Backtracking
    --> Subsets:      pick or skip each element  O(2^n)
    --> Permutations: fix one, recurse on rest   O(n!)
    --> Combination Sum: allow repeats with start index
    --> Pruning: sort first, skip duplicates, prune by sum

  "Find BEST (min/max/count) solution" with OVERLAPPING subproblems?
    --> Dynamic Programming (NOT backtracking)
    --> First check: does brute force with memoization work?
    --> Then: convert to bottom-up tabulation

  "LOCAL choice leads to GLOBAL optimum" (provable)?
    --> Greedy
    --> Sort by end time (interval scheduling)
    --> Always extend reach (jump game)
    --> Always use largest change (gas station circular)

================================================================
STEP 5 -- TREE PROBLEMS
================================================================

  Level-by-level processing?
    --> BFS (queue + size snapshot per level)
    --> Level order, zigzag, right side view, connect next ptrs

  Path sum / all paths from root to leaf?
    --> DFS with running sum, backtracking

  Lowest Common Ancestor?
    --> LCA DFS: if both subtrees return non-null, curr is LCA

  BST property (sorted order)?
    --> Inorder traversal gives sorted sequence
    --> BST insert/delete/validate with bounds

  Height / diameter / balance?
    --> Post-order DFS: process children before parent
    --> Return (height, isBalanced) pair to avoid O(n^2)

  Serialize / Deserialize?
    --> Preorder DFS with null markers OR BFS level order

  Optimization over tree structure?
    --> DP on Trees: return tuple [takeRoot, skipRoot]
    --> House Robber III: dp[node] = int[2]{rob, notRob}

================================================================
STEP 6 -- GRAPH / GRID PROBLEMS
================================================================

  SHORTEST PATH?
    --> Unweighted graph / grid?     --> BFS (level = distance)
    --> Weighted, no negative edges? --> Dijkstra (PQ)
    --> Negative edges?              --> Bellman-Ford
    --> All pairs?                   --> Floyd-Warshall O(V^3)

  CONNECTIVITY / COMPONENTS?
    --> Static graph, offline?       --> Union-Find
    --> Dynamic?                     --> DFS/BFS component count

  CYCLE DETECTION?
    --> Directed graph?  --> DFS 3-color (WHITE/GRAY/BLACK)
    --> Undirected?      --> DFS + parent tracking OR Union-Find

  TOPOLOGICAL ORDER?
    --> Kahn's BFS: in-degree array + queue
    --> DFS post-order reversed

  MINIMUM SPANNING TREE?
    --> Kruskal: sort edges + Union-Find
    --> Prim: PQ + visited array

  FLOOD FILL / ISLAND COUNT?
    --> DFS or BFS marking visited cells

  MULTI-SOURCE SHORTEST PATH?
    --> Add ALL sources to BFS queue at t=0
    --> Rotten Oranges, 01-Matrix

================================================================
STEP 7 -- PURE NUMBER PROBLEMS
================================================================

  Counting set bits / subsets based on bitmask?
    --> Bit Manipulation

  GCD / LCM / Prime / Modular arithmetic?
    --> Math utilities (Euclidean, Sieve, Fast Exp)

  COMBINATION COUNT with mod?
    --> Pascal's Triangle DP or Fermat's little theorem

  Find single differing element?
    --> XOR (self-cancellation: a ^ a = 0, a ^ 0 = a)

  Power of 2 check?
    --> n > 0 && (n & (n-1)) == 0

  Range frequency / counting?
    --> Prefix sum on frequency array

================================================================
FULL DECISION TREE (COMPACT)
================================================================

  Is input SORTED?
       YES --> Two Pointers / Binary Search first
       NO  --> check if sorting helps (O(n log n) ok?)

  Is it about SUBSTRINGS/SUBARRAYS?
       YES --> Sliding Window (variable or fixed)
             + Prefix Sum for sum-based

  Does it ask for ALL solutions?
       YES --> Backtracking (with pruning)

  Does it ask for BEST solution with repeated sub-states?
       YES --> Dynamic Programming

  Does it involve a GRAPH or TREE?
       YES --> BFS (shortest / level) or DFS (exhaustive / topo)
             + Union-Find for connectivity

  Does it involve ORDER of events / INTERVALS?
       YES --> Sort + Greedy / Merge Intervals

  Does it need K-th element or K-largest?
       YES --> Heap (min-heap of size k)

  Does it involve PREFIX queries?
       YES --> Prefix Sum or Trie

  Is it a BIT-LEVEL problem?
       YES --> XOR / Bit Manipulation

================================================================
COMPLEXITY SANITY CHECK (after choosing pattern)
================================================================

  n <= 10        -->  O(n!)     Brute Force / Backtracking ok
  n <= 20        -->  O(2^n)    Bitmask DP / Backtracking ok
  n <= 300       -->  O(n^3)    Interval DP / Floyd-Warshall ok
  n <= 1,000     -->  O(n^2)    Nested loops ok, careful
  n <= 100,000   -->  O(n log n) Sort, BFS, Binary Search ok
  n <= 1,000,000 -->  O(n)      Two Pointers, Sliding Window, Hash
  n > 1,000,000  -->  O(log n)  Pure Binary Search / Math

  If your pattern gives worse complexity than the constraint allows,
  pick a different pattern before writing code.

================================================================
QUICK PATTERN LOOKUP BY PROBLEM KEYWORD
================================================================

  KEYWORD                   PATTERN
  --------                  --------
  "contiguous subarray"  --> Sliding Window / Prefix Sum
  "all subsets"          --> Backtracking
  "minimum window"       --> Sliding Window (variable)
  "K closest"            --> Heap
  "Kth largest"          --> Heap (quick select alternative)
  "shortest path"        --> BFS / Dijkstra
  "all paths"            --> DFS / Backtracking
  "intervals overlap"    --> Merge Intervals / Greedy
  "detect cycle"         --> Fast-Slow / Union-Find / DFS
  "count ways"           --> DP (usually 1D or 2D)
  "minimum cost"         --> DP or Dijkstra
  "connected components" --> Union-Find / BFS/DFS
  "prefix"               --> Trie / Prefix Sum
  "XOR"                  --> Bit Manipulation
  "palindrome"           --> Two Pointers / DP (expansion)
  "sorted rotated"       --> Binary Search (modified)
  "stream"               --> Heap (two heaps for median)
  "monotone"             --> Monotonic Stack
  "next greater"         --> Monotonic Stack
  "topological"          --> BFS (Kahn) / DFS post-order
  "word"                 --> Trie / BFS (word ladder)
  "phone digits"         --> Backtracking
  "parentheses"          --> Stack

================================================================
INTERVIEW TIP
================================================================

  Always verbalize your decision tree reasoning to the interviewer:

  "The input is a sorted array and we need pairs, so I'll try
   two pointers first. That gives O(n) which fits n=10^5."

  "This asks for all combinations, so backtracking is the right
   approach. I'll prune by sorting first to skip duplicates."

  "Overlapping subproblems + optimal substructure means DP.
   Let me define my state and transition before coding."

  Showing your reasoning is often worth as much as the code.
