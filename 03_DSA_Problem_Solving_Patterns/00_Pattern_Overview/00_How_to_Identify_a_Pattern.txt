================================================================
  HOW TO IDENTIFY A PATTERN
================================================================

When you see a new problem, your first job is not to code --
it is to RECOGNIZE which pattern applies. This file gives you
a systematic process to do that under interview pressure.

----------------------------------------------------------------
STEP 1 -- READ THE PROBLEM CAREFULLY (2 minutes)
----------------------------------------------------------------
Ask yourself these questions out loud:

  1. What is the INPUT?      (array, string, tree, graph, matrix?)
  2. What is the OUTPUT?     (value, index, boolean, list, count?)
  3. What CONSTRAINT exists? (sorted? contiguous? distinct? k-limit?)
  4. What OPERATION is needed? (find / count / min / max / build / validate?)

Restate the problem in one sentence before doing anything else.
This prevents solving the wrong problem.

----------------------------------------------------------------
STEP 2 -- MAP INPUT STRUCTURE TO PATTERN
----------------------------------------------------------------

  INPUT TYPE          FIRST PATTERNS TO CONSIDER
  ----------          --------------------------
  Sorted array        Binary Search, Two Pointers
  Unsorted array      Sliding Window, Prefix Sum, HashMap, Sorting
  Linked list         Two Pointers (fast/slow), Reverse in-place
  Binary tree         DFS (recursion), BFS (level order), Tree DP
  BST                 Inorder traversal (sorted), min/max bounds
  Graph               BFS (shortest path), DFS (connectivity), Union-Find
  Matrix/grid         BFS/DFS flood fill, DP, Two-pointer diagonal
  String              Sliding Window, HashMap, Two Pointers, Trie, DP
  Stack of elements   Monotonic Stack
  Heap needed         Top-K, Median, Priority Queue pattern

----------------------------------------------------------------
STEP 3 -- MAP THE GOAL TO A PATTERN
----------------------------------------------------------------

  GOAL                           PATTERN
  ----                           -------
  Shortest path (unweighted)     BFS
  Shortest path (weighted)       Dijkstra
  All paths / exhaustive search  Backtracking (DFS)
  Count / exists subset/combo    Backtracking OR DP (overlapping? -> DP)
  Maximize / minimize value      DP or Greedy (check greedy choice property)
  Contiguous subarray optimum    Sliding Window or Prefix Sum
  Pairs in sorted array          Two Pointers
  Cycle in list / graph          Fast-Slow Pointers or DFS (3-color)
  Top K elements                 Heap (PriorityQueue)
  Connected components           Union-Find or DFS/BFS
  Prefix queries on array        Prefix Sum
  Range queries                  Segment Tree / BIT (advanced)
  Prefix string match            Trie
  Ordering with dependencies     Topological Sort

----------------------------------------------------------------
STEP 4 -- SIGNAL WORDS IN PROBLEM STATEMENT
----------------------------------------------------------------

  SIGNAL WORD / PHRASE            LIKELY PATTERN
  ---------------------           --------------
  "sorted array"                  Binary Search, Two Pointers
  "contiguous subarray"           Sliding Window, Kadane's, Prefix Sum
  "substring"                     Sliding Window, Two Pointers, DP
  "subsequence"                   DP (LCS / LIS family)
  "all combinations / subsets"    Backtracking
  "minimum / maximum"             DP, Greedy, Binary Search on answer
  "k-th largest / smallest"       Heap, QuickSelect
  "connected / component"         Union-Find, BFS/DFS
  "cycle"                         Fast-Slow Pointers, DFS 3-color
  "interval"                      Sort by start/end, Merge Intervals
  "palindrome"                    Two Pointers, DP, Manacher's
  "next greater element"          Monotonic Stack
  "in-order" / "sorted output"    BST inorder, Merge Sort
  "matrix"                        BFS/DFS, DP on grid
  "prefix" / "starts with"        Trie
  "bitwise"                       XOR tricks, Bitmask DP

----------------------------------------------------------------
STEP 5 -- COMPLEXITY SANITY CHECK
----------------------------------------------------------------
Estimate expected complexity from constraints:

  n <= 20         --> O(2^n) or O(n!) OK  (backtracking, bitmask DP)
  n <= 100        --> O(n^3) OK           (Floyd-Warshall, interval DP)
  n <= 1,000      --> O(n^2) OK           (bubble sort, O(n^2) DP)
  n <= 100,000    --> O(n log n) needed   (sorting, heap, binary search)
  n <= 1,000,000  --> O(n) needed         (linear scan, two pointers)
  n <= 10^9       --> O(log n) needed     (binary search, fast power)

If your solution is slower than what the constraints allow,
you need a better pattern.

----------------------------------------------------------------
STEP 6 -- VERIFY WITH A SMALL EXAMPLE
----------------------------------------------------------------
Before coding, trace through the example by hand with 3-4 elements.
  - Did your pattern produce the right answer?
  - Does it handle edge cases? (empty, single element, all same, negatives)

----------------------------------------------------------------
COMMON MISTAKES IN PATTERN IDENTIFICATION
----------------------------------------------------------------
  1. Seeing "array" and immediately jumping to sorting -- ask if
     sorted order is actually needed or if HashMap is faster.

  2. Writing O(n^2) brute force without checking if n > 10^4
     (would TLE -- need sliding window or prefix sum).

  3. Confusing "subsequence" (non-contiguous, use DP) with
     "substring" (contiguous, use sliding window).

  4. Using DFS for shortest path when BFS is needed.

  5. Using backtracking when subproblems OVERLAP (use DP instead).

----------------------------------------------------------------
QUICK DECISION FLOWCHART
----------------------------------------------------------------

  Start
    |
    v
  Array or String?
    |-- YES --> Sorted? --> YES --> Binary Search / Two Pointers
    |                  --> NO  --> Subarray? --> Sliding Window / Prefix Sum
    |                          --> Pairs?    --> Two Pointers / HashMap
    |
    |-- Tree? --> Level info needed? --> YES --> BFS
    |                                --> NO  --> DFS / DP
    |
    |-- Graph? --> Shortest path? --> YES --> BFS / Dijkstra
    |                             --> NO  --> DFS / Union-Find / Topo Sort
    |
    |-- Top K? --> Heap
    |-- Count combos? --> Backtracking -> overlapping? -> DP
    |-- Intervals? --> Sort + merge / sweep line

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. ALWAYS state the pattern before coding:
     "This looks like a sliding window problem because we're asked
      for a contiguous subarray and the window moves one direction."

  2. Interviewers award points for PATTERN RECOGNITION as much as coding.

  3. If two patterns seem to fit: state both, discuss trade-offs,
     then pick the more optimal one.

  4. Practice stating the time and space complexity of YOUR chosen pattern
     immediately after identifying it.

  5. Know 10 patterns deeply rather than 30 patterns shallowly.
