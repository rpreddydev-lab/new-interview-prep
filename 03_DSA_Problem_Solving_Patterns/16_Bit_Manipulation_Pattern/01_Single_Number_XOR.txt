================================================================
  SINGLE NUMBER (XOR TRICKS) — LC 136 / LC 137 / LC 260
================================================================

  LC 136: Every element appears TWICE except one. Find the single one.
          Time O(n), Space O(1).

  LC 137: Every element appears THREE TIMES except one. Find the single one.
          Time O(n), Space O(1).

  LC 260: Every element appears TWICE except TWO elements. Find both.
          Time O(n), Space O(1).

  Core XOR trick: n ^ n = 0 and n ^ 0 = n.
  XOR all elements → pairs cancel out → only unique element remains.

----------------------------------------------------------------
LC 136 — SINGLE NUMBER (APPEARS ONCE, REST TWICE)
----------------------------------------------------------------

  Java:
    public int singleNumber(int[] nums) {
        int result = 0;
        for (int n : nums) result ^= n;
        return result;
    }

  Trace for [4, 1, 2, 1, 2]:
    0 ^ 4 = 4
    4 ^ 1 = 5
    5 ^ 2 = 7
    7 ^ 1 = 6  (1 ^ 1 = 0, so pairs cancel: 4 ^ 0 ^ 0 = 4)
    6 ^ 2 = 4  ✓

  Why: XOR is commutative and associative.
    [4,1,2,1,2] = 1^1 ^ 2^2 ^ 4 = 0 ^ 0 ^ 4 = 4.

  Time: O(n)  Space: O(1)

----------------------------------------------------------------
LC 137 — SINGLE NUMBER II (APPEARS ONCE, REST THREE TIMES)
----------------------------------------------------------------

  XOR alone doesn't work (3 copies of a bit → 1, not 0).
  Need to track bits modulo 3.

  Approach: Use two bitmasks — ones, twos.
    ones = bits that have appeared 1 mod 3 times.
    twos = bits that have appeared 2 mod 3 times.
    A bit in ones AND twos = appeared 3 times → reset both.

  Java:
    public int singleNumber(int[] nums) {
        int ones = 0, twos = 0;
        for (int n : nums) {
            ones = (ones ^ n) & ~twos;  // add to ones, but remove if already in twos
            twos = (twos ^ n) & ~ones;  // add to twos, but remove if already in ones
        }
        return ones;  // the single number is in 'ones' (appeared 1 time)
    }

  Trace for [2, 2, 3, 2]:
    n=2: ones=(0^2)&~0=2. twos=(0^2)&~2=0.
    n=2: ones=(2^2)&~0=0. twos=(0^2)&~0=2.
    n=3: ones=(0^3)&~2=(3)&(..11111101)=1. twos=(2^3)&~1=(1)&(..111110)=0.
    n=2: ones=(1^2)&~0=3. twos=(0^2)&~3=(2)&(..111100)=0.
    Wait — result should be 3. ones=3. ✓

  Alternative approach — bit by bit:
    Count bits at each position, mod 3. The remainder is the bit of the single number.

  Java (bit by bit):
    public int singleNumber(int[] nums) {
        int result = 0;
        for (int i = 0; i < 32; i++) {
            int sum = 0;
            for (int n : nums) sum += (n >> i) & 1;
            result |= (sum % 3) << i;
        }
        return result;
    }

  Time: O(32 * n) = O(n)  Space: O(1)  (easier to understand, slightly slower)

LC 260 — SINGLE NUMBER III (TWO UNIQUE ELEMENTS)
----------------------------------------------------------------

  XOR all nums → get a ^ b (XOR of the two unique numbers, nonzero).
  Find any set bit in a^b → call it diff = (a^b) & -(a^b) [lowest set bit].
  That bit differs between a and b.
  Partition all nums into two groups:
    Group 1: bit is set → XOR these → get a (or b)
    Group 2: bit is not set → XOR these → get b (or a)

  Java:
    public int[] singleNumber(int[] nums) {
        int xor = 0;
        for (int n : nums) xor ^= n;  // xor = a ^ b

        int diff = xor & (-xor);      // isolate lowest set bit that differs between a and b
        int a = 0;
        for (int n : nums) {
            if ((n & diff) != 0) a ^= n;  // XOR nums where this bit is set
        }
        return new int[]{a, xor ^ a};     // b = xor ^ a = a^b^a = b
    }

  Trace for [1, 2, 1, 3, 2, 5]:
    Unique: 3 and 5.
    xor = 1^2^1^3^2^5 = 3^5 = 011 ^ 101 = 110 = 6.
    diff = 6 & -6 = 6 & (..11111010) = 010 = 2 (bit 1 is set).
    Group "bit 1 set": 2(10), 3(11), 2(10). XOR = 2^3^2 = 3.
    a = 3. b = 6^3 = 5.  ✓

  Time: O(n)  Space: O(1)

LC 268 — MISSING NUMBER (XOR APPROACH)
----------------------------------------------------------------

  Array of n distinct numbers from 0 to n. One number is missing. Find it.

  Approach: XOR all indices 0..n with all array values.
            Pairs cancel → only missing number remains.

  Java:
    public int missingNumber(int[] nums) {
        int result = nums.length;
        for (int i = 0; i < nums.length; i++) {
            result ^= i ^ nums[i];
        }
        return result;
    }

  Alternative: Math approach — n*(n+1)/2 - sum(nums).

  Time: O(n)  Space: O(1)

FIND THE DUPLICATE (SIMILAR SPIRIT) — LC 287
----------------------------------------------------------------

  Array of n+1 integers where each integer is between 1 and n.
  Find the duplicate without modifying array, O(1) space.

  Approach: Floyd's Cycle Detection (not XOR, but O(1) space trick).

  Java:
    public int findDuplicate(int[] nums) {
        int slow = nums[0], fast = nums[0];
        // Phase 1: find meeting point
        do {
            slow = nums[slow];
            fast = nums[nums[fast]];
        } while (slow != fast);
        // Phase 2: find cycle entry (= duplicate)
        slow = nums[0];
        while (slow != fast) {
            slow = nums[slow];
            fast = nums[fast];
        }
        return slow;
    }

  Time: O(n)  Space: O(1)

LC 421 — MAXIMUM XOR OF TWO NUMBERS IN ARRAY
----------------------------------------------------------------

  Greedy bit-by-bit from MSB. At each bit position, check if we can achieve 1.

  Java:
    public int findMaximumXOR(int[] nums) {
        int max = 0, mask = 0;
        for (int i = 31; i >= 0; i--) {
            mask |= (1 << i);
            Set<Integer> prefixes = new HashSet<>();
            for (int n : nums) prefixes.add(n & mask);  // keep top i bits
            int candidate = max | (1 << i);
            for (int prefix : prefixes) {
                if (prefixes.contains(candidate ^ prefix)) {  // a ^ b = candidate → b = candidate ^ a
                    max = candidate;
                    break;
                }
            }
        }
        return max;
    }

  Time: O(32 * n)  Space: O(n)

LC 1310 — XOR QUERIES OF SUBARRAY
----------------------------------------------------------------

  Array nums, queries [li, ri]. Return XOR of nums[li..ri] for each query.
  Use prefix XOR: prefix[i] = nums[0] ^ nums[1] ^ ... ^ nums[i-1].
  Query answer = prefix[ri+1] ^ prefix[li].

  Java:
    public int[] xorQueries(int[] arr, int[][] queries) {
        int n = arr.length;
        int[] prefix = new int[n + 1];
        for (int i = 0; i < n; i++) prefix[i+1] = prefix[i] ^ arr[i];
        int[] result = new int[queries.length];
        for (int i = 0; i < queries.length; i++) {
            result[i] = prefix[queries[i][1] + 1] ^ prefix[queries[i][0]];
        }
        return result;
    }

  Time: O(n + q)  Space: O(n) for prefix.

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: Why does XOR work for LC 136?
  A: n ^ n = 0 (identical values cancel) and n ^ 0 = n (identity).
     All duplicated values cancel, leaving only the unique element.

  Q: Why not use a HashSet for LC 136?
  A: We can, but HashSet uses O(n) space. XOR gives O(1) space.

  Q: In LC 260, why does the lowest set bit separate the two uniques?
  A: Since a ≠ b, a^b ≠ 0. Any set bit in a^b is a bit where a and b differ.
     Using it to partition ensures a and b land in different groups.

  Q: What's the difference in approach between LC 136 and LC 137?
  A: LC 136: simple XOR (mod 2 tracking). LC 137: need mod 3 tracking with two bitmasks.
