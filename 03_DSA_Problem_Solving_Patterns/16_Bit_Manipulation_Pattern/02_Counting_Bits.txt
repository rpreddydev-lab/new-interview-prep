================================================================
  COUNTING BITS AND BIT COUNTING PATTERNS — LC 338 / LC 191 / LC 461
================================================================

  LC 338: Given n, return array ans of size n+1 where ans[i] = number
          of 1 bits in binary representation of i.
          Time O(n), Space O(n).

  LC 191: Count 1 bits in a single 32-bit unsigned integer (Hamming weight).
  LC 461: Hamming distance between two integers (number of positions with different bits).

----------------------------------------------------------------
LC 191 — NUMBER OF 1 BITS (HAMMING WEIGHT)
----------------------------------------------------------------

  Approach 1: n & (n-1) removes the lowest set bit. Count iterations.

  Java:
    public int hammingWeight(int n) {
        int count = 0;
        while (n != 0) {
            n = n & (n - 1);  // removes lowest set bit
            count++;
        }
        return count;
    }

  Approach 2: Shift and check.
  Java:
    public int hammingWeight(int n) {
        int count = 0;
        while (n != 0) {
            count += n & 1;
            n >>>= 1;  // unsigned right shift (handles sign bit)
        }
        return count;
    }

  Approach 3: Java built-in.
    Integer.bitCount(n)  // O(1) lookup + bit parallelism

  Time: O(number of 1 bits) for approach 1. O(32) for approach 2.
  Space: O(1).

  Note: Use >>> (unsigned right shift) not >> when dealing with potentially
        negative integers to avoid infinite loop (sign bit not extended).

  n & (n-1) trace for n=12 (1100):
    12 & 11 = 1100 & 1011 = 1000 = 8  (count=1)
     8 &  7 = 1000 & 0111 = 0000 = 0  (count=2)
    0 → done. Result: 2 ✓

----------------------------------------------------------------
LC 338 — COUNTING BITS (0 TO N)
----------------------------------------------------------------

  Goal: ans[i] = popcount(i) for i in 0..n.

  Key insight: ans[i] = ans[i >> 1] + (i & 1)
    The number of 1s in i = number of 1s in i/2, plus 1 if i is odd.
    (Right-shifting i removes the last bit; i & 1 tells us what that bit was.)

  Java:
    public int[] countBits(int n) {
        int[] ans = new int[n + 1];
        for (int i = 1; i <= n; i++) {
            ans[i] = ans[i >> 1] + (i & 1);
        }
        return ans;
    }

  Alternative: ans[i] = ans[i & (i-1)] + 1
    i & (i-1) removes lowest set bit. So popcount(i) = popcount(i without lowest bit) + 1.

  Java:
    for (int i = 1; i <= n; i++) {
        ans[i] = ans[i & (i - 1)] + 1;
    }

  Both are O(n) time and O(n) space.

  Traced for n=7:
    i=0: 0
    i=1: ans[0]+1=1
    i=2: ans[1]+0=1   (2>>1=1, 2&1=0)
    i=3: ans[1]+1=2   (3>>1=1, 3&1=1)
    i=4: ans[2]+0=1
    i=5: ans[2]+1=2
    i=6: ans[3]+0=2
    i=7: ans[3]+1=3
    Result: [0,1,1,2,1,2,2,3] ✓

LC 461 — HAMMING DISTANCE
----------------------------------------------------------------

  Number of positions where corresponding bits differ.
  XOR gives 1 at positions where bits differ → count 1 bits.

  Java:
    public int hammingDistance(int x, int y) {
        return Integer.bitCount(x ^ y);
    }

  or using n & (n-1):
    public int hammingDistance(int x, int y) {
        int xor = x ^ y, count = 0;
        while (xor != 0) { xor &= (xor - 1); count++; }
        return count;
    }

  Time: O(1) (fixed 32 bits)  Space: O(1)

  Example: x=1 (0001), y=4 (0100). x^y = 0101. Two 1 bits → distance = 2. ✓

LC 477 — TOTAL HAMMING DISTANCE
----------------------------------------------------------------

  Sum of Hamming distances between ALL pairs in the array.

  Naive: O(n²) — check each pair.
  Optimized: For each bit position, count how many numbers have that bit set (ones).
             Contribution = ones * (n - ones)   [ones paired with zeros].

  Java:
    public int totalHammingDistance(int[] nums) {
        int total = 0, n = nums.length;
        for (int i = 0; i < 32; i++) {
            int ones = 0;
            for (int num : nums) ones += (num >> i) & 1;
            total += ones * (n - ones);
        }
        return total;
    }

  Time: O(32 * n) = O(n)  Space: O(1)

  Why ones * (n - ones)?
    Each pair where one has the bit set and one doesn't contributes 1 to the total.
    Number of such pairs = (count with bit 1) × (count with bit 0).

LC 190 — REVERSE BITS
----------------------------------------------------------------

  Reverse bits of a 32-bit unsigned integer.

  Java:
    public int reverseBits(int n) {
        int result = 0;
        for (int i = 0; i < 32; i++) {
            result = (result << 1) | (n & 1);
            n >>>= 1;
        }
        return result;
    }

  At each step: shift result left (making room), OR the current last bit of n.
  Then right-shift n to process next bit.

  Example: n = 43261596 (00000010100101000001111010011100)
           Reversed:     00111001011110000010100101000000 = 964176192 ✓

----------------------------------------------------------------
BUILDING DP TABLE COMPARISON: TWO RECURRENCES
----------------------------------------------------------------

  Recurrence 1: ans[i] = ans[i >> 1] + (i & 1)
    Intuition: remove last bit, check if last bit was 1.
    "Shift right by 1 → already computed; add 1 if LSB was set."

  Recurrence 2: ans[i] = ans[i & (i-1)] + 1
    Intuition: remove lowest set bit → that's one 1 bit accounted for.
    "Previous state = me minus one 1-bit."

  Both O(n) and equivalent. Recurrence 1 is more commonly taught.

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: Why use >>> instead of >> in bit counting loops?
  A: Java's >> is arithmetic right shift (preserves sign bit).
     For negative int like -1 (all 1s), -1 >> 1 = -1 (infinite loop).
     -1 >>> 1 = Integer.MAX_VALUE (pads with 0, terminates loop).

  Q: What does n & (n-1) compute and why?
  A: It clears the lowest set bit of n.
     n-1 flips all bits from the lowest set bit downward.
     n & (n-1) thus turns off exactly the lowest set bit.

  Q: Time complexity for LC 338 — why is it O(n)?
  A: We compute ans[i] in O(1) using already-computed ans[i>>1].
     Total n+1 computations → O(n).

  Q: For LC 477, why can't we just use double-loop?
  A: Double loop is O(n²) which can be 10^10 for n=10^5. TLE.
     Per-bit approach is O(32n).

INTERVIEW TIPS
----------------------------------------------------------------

  - LC 191: Know both the `n & (n-1)` approach and the built-in `Integer.bitCount(n)`.
  - LC 338: recite the recurrence "ans[i] = ans[i >> 1] + (i & 1)" and explain intuitively.
  - LC 461: literally one line — `Integer.bitCount(x ^ y)`.
  - LC 477: "for each bit position, count ones and zeros, multiply" — this is a key insight.
  - Always mention >>> vs >> for unsigned behavior in Java.
