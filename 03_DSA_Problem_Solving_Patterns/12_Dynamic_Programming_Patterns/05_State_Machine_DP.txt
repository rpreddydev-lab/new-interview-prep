================================================================
  STATE MACHINE DP PATTERN
================================================================

  State Machine DP: the DP state includes not just position but also
  a discrete "mode" or "status" variable that transitions based on actions.

  Used for: stock trading problems, regex matching, string matching with
  wildcards, problems where the same position has multiple distinct behaviors.

  Core idea: define all states explicitly, write transitions between them.

----------------------------------------------------------------
BEST TIME TO BUY AND SELL STOCK — SERIES
----------------------------------------------------------------

  Stock series covers 6 problems. Each adds a constraint on trading.

  PRICES:    day 0, 1, 2, ..., n-1
  STATES:    hold (holding stock), rest/cash (not holding)

-------

  LC 121: AT MOST ONE TRANSACTION
    Two states: hold, cash.
    hold[i] = max(-prices[i], hold[i-1])      // buy today or keep holding
    cash[i] = max(hold[i-1] + prices[i], cash[i-1])  // sell today or do nothing
    Answer: cash[n-1]

    Java (space-optimized):
      public int maxProfit(int[] prices) {
          int hold = Integer.MIN_VALUE, cash = 0;
          for (int price : prices) {
              hold = Math.max(hold, -price);   // can only buy once: no prior profit
              cash = Math.max(cash, hold + price);
          }
          return cash;
      }

    The key: hold = max(hold, -price) (not max(hold, cash-price)) since only 1 buy allowed.

-------

  LC 122: UNLIMITED TRANSACTIONS
    hold[i] = max(cash[i-1] - prices[i], hold[i-1])  // buy using previous cash
    cash[i] = max(hold[i-1] + prices[i], cash[i-1])

    Java:
      public int maxProfit(int[] prices) {
          int hold = -prices[0], cash = 0;
          for (int i = 1; i < prices.length; i++) {
              int prevHold = hold;
              hold = Math.max(hold, cash - prices[i]);
              cash = Math.max(cash, prevHold + prices[i]);
          }
          return cash;
      }

    Note: use prevHold to avoid using same day's update.

-------

  LC 123: AT MOST 2 TRANSACTIONS
    Four states: buy1, sell1, buy2, sell2.
    buy1  = max(buy1, -price)                  // buy first stock
    sell1 = max(sell1, buy1 + price)           // sell first stock
    buy2  = max(buy2, sell1 - price)           // buy second stock (using sell1 profit)
    sell2 = max(sell2, buy2 + price)           // sell second stock

    Java:
      public int maxProfit(int[] prices) {
          int buy1 = Integer.MIN_VALUE, sell1 = 0;
          int buy2 = Integer.MIN_VALUE, sell2 = 0;
          for (int price : prices) {
              buy1  = Math.max(buy1,  -price);
              sell1 = Math.max(sell1, buy1 + price);
              buy2  = Math.max(buy2,  sell1 - price);
              sell2 = Math.max(sell2, buy2 + price);
          }
          return sell2;
      }

    Notice: buy2 uses sell1 (profit from first transaction already captured).

-------

  LC 188: AT MOST K TRANSACTIONS
    States: buy[j] and sell[j] for each transaction j from 1 to k.
    k >= n/2 means unlimited → use LC 122 solution.

    Java:
      public int maxProfit(int k, int[] prices) {
          int n = prices.length;
          if (k >= n / 2) {
              // unlimited transactions
              int hold = -prices[0], cash = 0;
              for (int i = 1; i < n; i++) {
                  int prev = hold;
                  hold = Math.max(hold, cash - prices[i]);
                  cash = Math.max(cash, prev + prices[i]);
              }
              return cash;
          }
          int[] buy = new int[k + 1];
          int[] sell = new int[k + 1];
          Arrays.fill(buy, Integer.MIN_VALUE);
          for (int price : prices) {
              for (int j = k; j >= 1; j--) {
                  sell[j] = Math.max(sell[j], buy[j] + price);
                  buy[j]  = Math.max(buy[j],  sell[j-1] - price);
              }
          }
          return sell[k];
      }

-------

  LC 309: COOLDOWN (1-DAY COOLDOWN AFTER SELLING)
    States: hold, sold, rest.
    hold: holding stock
    sold: sold today (must rest tomorrow)
    rest: not holding, not just sold (can buy tomorrow)

    Transitions:
      hold = max(hold, rest - price)   // buy from rest state
      sold = hold + price              // sell (previous hold, today's sell)
      rest = max(rest, sold)           // rest after selling or continuing rest

    Java:
      public int maxProfit(int[] prices) {
          int hold = Integer.MIN_VALUE, sold = 0, rest = 0;
          for (int price : prices) {
              int prevSold = sold;
              sold = hold + price;
              hold = Math.max(hold, rest - price);
              rest = Math.max(rest, prevSold);
          }
          return Math.max(rest, sold);
      }

-------

  LC 714: TRANSACTION FEE
    Same as unlimited, but subtract fee on sell.
    cash = max(cash, hold + price - fee)

    Java:
      public int maxProfit(int[] prices, int fee) {
          int hold = -prices[0], cash = 0;
          for (int i = 1; i < prices.length; i++) {
              int prev = hold;
              hold = Math.max(hold, cash - prices[i]);
              cash = Math.max(cash, prev + prices[i] - fee);
          }
          return cash;
      }

STATE MACHINE VISUALIZATION
----------------------------------------------------------------

  Stock general state machine (unlimited):

                  BUY (cash→hold)
    [CASH] ─────────────────────────────→ [HOLD]
      ↑                                     │
      └─────────────────────────────────────┘
                SELL (hold→cash)

  Cooldown state machine:

    [REST] ──buy──→ [HOLD] ──sell──→ [SOLD]
      ↑                                 │
      └─────────────────────────────────┘
                   (next day)

----------------------------------------------------------------
STATE MACHINE DP — GENERAL TEMPLATE
----------------------------------------------------------------

  1. Enumerate all states.
  2. For each state, enumerate all transitions.
  3. Build DP: dp[day][state] = max profit.
  4. Optimize space if only previous day's state is needed.

  Example (2-state, unlimited):
    dp[i][0] = max(dp[i-1][0], dp[i-1][1] + prices[i])  // cash: rest or sell
    dp[i][1] = max(dp[i-1][1], dp[i-1][0] - prices[i])  // hold: rest or buy
    Answer: dp[n-1][0]

----------------------------------------------------------------
OTHER STATE MACHINE PROBLEMS
----------------------------------------------------------------

  Regex Matching (LC 10):
    State: (pos_in_s, pos_in_p). Transitions depend on pattern char.

  Wildcard Matching (LC 44):
    '?' matches any char, '*' matches any sequence (including empty).
    dp[i][j] = s[0..i-1] matches p[0..j-1]:
      If p[j-1] == '*': dp[i][j] = dp[i-1][j] (match one char) || dp[i][j-1] (match zero)
      If p[j-1] == '?' or match: dp[i][j] = dp[i-1][j-1]

  Java (Wildcard LC 44):
    public boolean isMatch(String s, String p) {
        int m = s.length(), n = p.length();
        boolean[][] dp = new boolean[m+1][n+1];
        dp[0][0] = true;
        for (int j = 1; j <= n; j++) dp[0][j] = dp[0][j-1] && p.charAt(j-1)=='*';
        for (int i = 1; i <= m; i++) {
            for (int j = 1; j <= n; j++) {
                if (p.charAt(j-1) == '*') {
                    dp[i][j] = dp[i-1][j] || dp[i][j-1];
                } else if (p.charAt(j-1) == '?' || p.charAt(j-1) == s.charAt(i-1)) {
                    dp[i][j] = dp[i-1][j-1];
                }
            }
        }
        return dp[m][n];
    }

----------------------------------------------------------------
COMMON MISTAKES
----------------------------------------------------------------

  1. Stock problems: updating hold and cash in same iteration without saving prevHold.
     hold uses old cash, cash uses old hold. Save one of them first.

  2. Cooldown: sold uses old hold (before today's buy update). Save prevSold.

  3. LC 188: when k >= n/2, use greedy unlimited solution (otherwise TLE/MLE).

  4. At most 2 transactions: initializing buy1, buy2 as 0 instead of MIN_VALUE.
     They represent negative cost states, so MIN_VALUE ensures proper max logic.

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: How do you derive buy2 = max(buy2, sell1 - price) in LC 123?
  A: sell1 represents the profit after selling the first stock.
     buy2 represents the state of having bought the second stock, which
     "costs" price but we've already accumulated sell1 profit. So the
     net position is sell1 - price.

  Q: Why does k >= n/2 in LC 188 mean unlimited transactions?
  A: At most n/2 profitable transactions are possible (each needs buy + sell = 2 days).
     If k >= n/2, the k constraint is never binding → same as unlimited.

  Q: Cooldown: why must we save prevSold?
  A: `sold = hold + price` uses today's hold. But `rest = max(rest, sold)` should
     use YESTERDAY's sold (the cooldown day is after selling). So save before update.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------

  - Draw the state machine diagram first: circles = states, arrows = transitions.
  - For stock series, explicitly name all states in the solution.
  - In space-optimized code, carefully save previous-day values to avoid dependency issues.
  - Trace through 2-3 prices to verify each state updates correctly.
  - LC 123 can be extended to LC 188 by generalizing buy[]/sell[] arrays.
