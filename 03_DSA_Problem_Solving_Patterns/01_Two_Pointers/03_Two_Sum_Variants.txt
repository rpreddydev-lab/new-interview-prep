================================================================
  TWO SUM VARIANTS
  (The Most Common Two-Pointer Interview Problem Family)
================================================================

Two Sum is the foundation of all pair/triplet/sum problems.
Understanding all variants is essential for FAANG interviews.

----------------------------------------------------------------
VARIANT 1: TWO SUM (LC 1) -- Unsorted, return indices
----------------------------------------------------------------

  Input:  nums = [2, 7, 11, 15], target = 9
  Output: [0, 1]

  Approach: HashMap stores value -> index.
  For each num: if (target - num) in map, return pair.

  Java:
    public int[] twoSum(int[] nums, int target) {
        Map<Integer, Integer> map = new HashMap<>();
        for (int i = 0; i < nums.length; i++) {
            int comp = target - nums[i];
            if (map.containsKey(comp)) {
                return new int[]{map.get(comp), i};
            }
            map.put(nums[i], i);
        }
        return new int[]{};
    }

  Time: O(n)  Space: O(n)

  Key: add AFTER checking to avoid using same element twice.

----------------------------------------------------------------
VARIANT 2: TWO SUM II (LC 167) -- Sorted, return indices
----------------------------------------------------------------

  Input:  numbers = [2, 7, 11, 15], target = 9
  Output: [1, 2] (1-indexed)

  Approach: Two pointers (sorted enables this).

  Java:
    public int[] twoSum(int[] numbers, int target) {
        int l = 0, r = numbers.length - 1;
        while (l < r) {
            int sum = numbers[l] + numbers[r];
            if (sum == target) return new int[]{l + 1, r + 1};
            else if (sum < target) l++;
            else r--;
        }
        return new int[]{};
    }

  Time: O(n)  Space: O(1)

----------------------------------------------------------------
VARIANT 3: TWO SUM -- Count pairs with sum = target
----------------------------------------------------------------

  Input: nums = [1, 5, 3, 3, 2], target = 6
  Pairs: (1,5), (3,3) --> 2 pairs

  Approach: HashMap with frequency count.

  Java:
    public int countPairs(int[] nums, int target) {
        Map<Integer, Integer> freq = new HashMap<>();
        int count = 0;
        for (int num : nums) {
            int comp = target - num;
            count += freq.getOrDefault(comp, 0);
            freq.merge(num, 1, Integer::sum);
        }
        return count;
    }

  Time: O(n)  Space: O(n)

  Note: this handles duplicates naturally (e.g., two 3s for target=6).

----------------------------------------------------------------
VARIANT 4: TWO SUM -- Number of pairs with sum < target
----------------------------------------------------------------

  Must be sorted. Use two pointers.
  When nums[l] + nums[r] < target: ALL pairs (l, l+1), (l, l+2),
  ..., (l, r) are valid => add (r - l) pairs, then l++.

  Java:
    public int countPairsLess(int[] nums, int target) {
        Arrays.sort(nums);
        int l = 0, r = nums.length - 1, count = 0;
        while (l < r) {
            if (nums[l] + nums[r] < target) {
                count += r - l;  // all pairs with nums[l]
                l++;
            } else {
                r--;
            }
        }
        return count;
    }

  Time: O(n log n)  Space: O(1)

----------------------------------------------------------------
VARIANT 5: TWO SUM -- Closest sum to target (LC 16)
----------------------------------------------------------------

  3Sum Closest: Find three numbers whose sum is closest to target.
  (Two pointer inner loop for each fixed element.)

  Java:
    public int threeSumClosest(int[] nums, int target) {
        Arrays.sort(nums);
        int closest = nums[0] + nums[1] + nums[2];
        for (int i = 0; i < nums.length - 2; i++) {
            int l = i + 1, r = nums.length - 1;
            while (l < r) {
                int sum = nums[i] + nums[l] + nums[r];
                if (Math.abs(sum - target) < Math.abs(closest - target))
                    closest = sum;
                if (sum < target) l++;
                else if (sum > target) r--;
                else return sum;  // exact match
            }
        }
        return closest;
    }

  Time: O(n^2)  Space: O(1)

----------------------------------------------------------------
VARIANT 6: TWO SUM -- Multiple pairs (return all pairs)
----------------------------------------------------------------

  Sorted array. Collect all pairs. Avoid duplicates.

  Java:
    public List<List<Integer>> twoSumAllPairs(int[] nums, int target) {
        Arrays.sort(nums);
        List<List<Integer>> result = new ArrayList<>();
        int l = 0, r = nums.length - 1;
        while (l < r) {
            int sum = nums[l] + nums[r];
            if (sum == target) {
                result.add(Arrays.asList(nums[l], nums[r]));
                // skip duplicates
                while (l < r && nums[l] == nums[l + 1]) l++;
                while (l < r && nums[r] == nums[r - 1]) r--;
                l++; r--;
            } else if (sum < target) l++;
            else r--;
        }
        return result;
    }

  Time: O(n log n + n)  Space: O(k) where k = number of pairs

----------------------------------------------------------------
VARIANT 7: TWO SUM -- BST (tree structure)
----------------------------------------------------------------

  LC 653: Given a BST, find two nodes that sum to target.
  Inorder traversal --> sorted array --> two pointer.

  Java:
    public boolean findTarget(TreeNode root, int k) {
        List<Integer> sorted = new ArrayList<>();
        inorder(root, sorted);
        int l = 0, r = sorted.size() - 1;
        while (l < r) {
            int sum = sorted.get(l) + sorted.get(r);
            if (sum == k) return true;
            else if (sum < k) l++;
            else r--;
        }
        return false;
    }
    private void inorder(TreeNode node, List<Integer> list) {
        if (node == null) return;
        inorder(node.left, list);
        list.add(node.val);
        inorder(node.right, list);
    }

  Time: O(n)  Space: O(n)

----------------------------------------------------------------
VARIANT SUMMARY TABLE
----------------------------------------------------------------

  Variant                  Input      Approach         Time  Space
  --------                 -----      --------         ----  -----
  Return indices           Unsorted   HashMap          O(n)  O(n)
  Return indices           Sorted     Two Pointers     O(n)  O(1)
  Count all pairs          Any        HashMap freq     O(n)  O(n)
  Count pairs < target     Sort first Two Pointers     O(n)  O(1)
  Closest sum              Sort first Two Pointers     O(n^2) O(1)
  All pairs (no dup)       Sort first Two Pointers     O(n)  O(k)
  BST nodes                BST        Inorder+2ptr     O(n)  O(n)

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: Two Sum asks for indices. Can we sort and use two pointers?
  A: No, sorting destroys original indices. Use HashMap instead.
     If the problem is "find values" (not indices), sorting is fine.

  Q: What if the array can have the same element used twice?
  A: The HashMap approach naturally prevents this by checking BEFORE
     adding. map.containsKey(comp) only finds previously seen elements.

  Q: What if there are multiple valid answers?
  A: LC 1 guarantees exactly one. If multiple are needed, collect all
     with the all-pairs variant (with deduplication).

  Q: Two Sum vs Two Sum II -- which is more efficient?
  A: Both O(n) time. Two Sum uses O(n) space for HashMap.
     Two Sum II uses O(1) space with two pointers.
     If input is sorted, Two Sum II is strictly better.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------

  - Always clarify: "Are there duplicate values?" and
    "Is the input sorted?"
  - If sorted -> two pointers is the intended answer (O(1) space)
  - If unsorted -> HashMap is the intended answer
  - Mention the tradeoff: "HashMap is O(n) extra space, but
    avoids sorting. Two pointers needs sorted input but is O(1)."
