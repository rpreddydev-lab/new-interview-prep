================================================================
  THREE SUM AND FOUR SUM
  (LC 15 and LC 18)
================================================================

Both problems reduce to Two Sum via sorting + outer loops.
The critical challenge is DUPLICATE ELIMINATION efficiently.

================================================================
3SUM (LC 15)
================================================================

----------------------------------------------------------------
PROBLEM STATEMENT
----------------------------------------------------------------

  Given an integer array nums, return all triplets [a, b, c]
  such that a + b + c = 0 and a != b != c (different indices),
  with NO duplicate triplets in output.

  Input:  nums = [-1, 0, 1, 2, -1, -4]
  Output: [[-1, -1, 2], [-1, 0, 1]]

----------------------------------------------------------------
APPROACH: Sort + Two Pointers
----------------------------------------------------------------

  1. Sort the array.
  2. Fix nums[i] as the first element.
  3. Run two pointers l = i+1, r = n-1 looking for pair summing to -nums[i].
  4. Skip duplicates at every level.

  Why sorting helps:
    - Enables two pointers for the inner pair.
    - Groups duplicates together for easy skipping.

----------------------------------------------------------------
VISUALIZATION
----------------------------------------------------------------

  After sort: [-4, -1, -1, 0, 1, 2]
               0    1   2  3  4  5

  i=0 (nums[0]=-4): target=4
    l=1, r=5: -1+2=1 < 4 --> l++
    l=2, r=5: -1+2=1 < 4 --> l++
    l=3, r=5:  0+2=2 < 4 --> l++
    l=4, r=5:  1+2=3 < 4 --> l++
    l=5=r: stop. No triplets.

  i=1 (nums[1]=-1): target=1
    l=2, r=5: -1+2=1 == 1 --> add [-1,-1,2], skip dupes, l=3, r=4
    l=3, r=4:  0+1=1 == 1 --> add [-1,0,1], l=4, r=3, stop.

  i=2 (nums[2]=-1): SAME as nums[1] --> SKIP (i>0 && nums[i]==nums[i-1])

  i=3 (nums[3]=0): target=0
    l=4, r=5: 1+2=3 > 0 --> r--
    l=4, r=4: stop.

  Result: [[-1,-1,2], [-1,0,1]]

----------------------------------------------------------------
JAVA CODE
----------------------------------------------------------------

  public List<List<Integer>> threeSum(int[] nums) {
      Arrays.sort(nums);
      List<List<Integer>> result = new ArrayList<>();
      int n = nums.length;

      for (int i = 0; i < n - 2; i++) {
          // Skip duplicate first element
          if (i > 0 && nums[i] == nums[i - 1]) continue;

          // Early termination: smallest sum > 0
          if (nums[i] > 0) break;

          int l = i + 1, r = n - 1;
          while (l < r) {
              int sum = nums[i] + nums[l] + nums[r];
              if (sum == 0) {
                  result.add(Arrays.asList(nums[i], nums[l], nums[r]));
                  // Skip duplicates for l and r
                  while (l < r && nums[l] == nums[l + 1]) l++;
                  while (l < r && nums[r] == nums[r - 1]) r--;
                  l++; r--;
              } else if (sum < 0) {
                  l++;
              } else {
                  r--;
              }
          }
      }
      return result;
  }

  Time:  O(n^2) -- O(n log n) sort + O(n^2) two-pointer scan
  Space: O(1) extra (not counting output)

----------------------------------------------------------------
DUPLICATE SKIPPING -- DETAILED EXPLANATION
----------------------------------------------------------------

  Three places to skip duplicates:

  1. Outer loop (i):
     if (i > 0 && nums[i] == nums[i-1]) continue;
     --> Avoids starting the same triplet with the same value.

  2. Left pointer (l) after finding a triplet:
     while (l < r && nums[l] == nums[l+1]) l++;
     --> Moves past consecutive equal values on the left.

  3. Right pointer (r) after finding a triplet:
     while (l < r && nums[r] == nums[r-1]) r--;
     --> Moves past consecutive equal values on the right.

  Then do l++; r--; to actually advance past the found pair.

  Common mistake: skipping before checking (would miss valid answers).
  Always: find triplet FIRST, THEN skip duplicates.

================================================================
4SUM (LC 18)
================================================================

----------------------------------------------------------------
PROBLEM STATEMENT
----------------------------------------------------------------

  Given nums and target, return all unique quadruplets [a,b,c,d]
  such that a + b + c + d == target.

  Input:  nums = [1, 0, -1, 0, -2, 2], target = 0
  Output: [[-2,-1,1,2], [-2,0,0,2], [-1,0,0,1]]

----------------------------------------------------------------
APPROACH: Sort + Two Outer Loops + Two Pointers
----------------------------------------------------------------

  Add one more fixed outer loop compared to 3Sum.
  Skip duplicates at EVERY level (i, j, l, r).

  Java:
    public List<List<Integer>> fourSum(int[] nums, int target) {
        Arrays.sort(nums);
        List<List<Integer>> result = new ArrayList<>();
        int n = nums.length;

        for (int i = 0; i < n - 3; i++) {
            if (i > 0 && nums[i] == nums[i - 1]) continue;

            for (int j = i + 1; j < n - 2; j++) {
                if (j > i + 1 && nums[j] == nums[j - 1]) continue;

                int l = j + 1, r = n - 1;
                while (l < r) {
                    long sum = (long) nums[i] + nums[j] + nums[l] + nums[r];
                    if (sum == target) {
                        result.add(Arrays.asList(nums[i], nums[j], nums[l], nums[r]));
                        while (l < r && nums[l] == nums[l + 1]) l++;
                        while (l < r && nums[r] == nums[r - 1]) r--;
                        l++; r--;
                    } else if (sum < target) {
                        l++;
                    } else {
                        r--;
                    }
                }
            }
        }
        return result;
    }

  Time:  O(n^3)  -- two outer loops + two pointers
  Space: O(1) extra

  IMPORTANT: Use long for the sum to avoid integer overflow
  when nums contains large values.

----------------------------------------------------------------
GENERALIZATION: K-SUM
----------------------------------------------------------------

  For any k >= 2:
    - Sort the array once.
    - Fix k-2 outer loops with duplicate skipping.
    - Use two pointers for the innermost pair.

  Recursive approach:
    static List<List<Integer>> kSum(int[] nums, int target,
                                    int start, int k) {
        List<List<Integer>> result = new ArrayList<>();
        if (k == 2) {
            // base case: two pointers
            int l = start, r = nums.length - 1;
            while (l < r) {
                long sum = (long) nums[l] + nums[r];
                if (sum == target) {
                    result.add(new ArrayList<>(Arrays.asList(nums[l], nums[r])));
                    while (l < r && nums[l] == nums[l+1]) l++;
                    while (l < r && nums[r] == nums[r-1]) r--;
                    l++; r--;
                } else if (sum < target) l++;
                else r--;
            }
        } else {
            for (int i = start; i <= nums.length - k; i++) {
                if (i > start && nums[i] == nums[i-1]) continue;
                for (List<Integer> inner : kSum(nums, target - nums[i], i + 1, k - 1)) {
                    inner.add(0, nums[i]);
                    result.add(inner);
                }
            }
        }
        return result;
    }

    // Call: Arrays.sort(nums); return kSum(nums, target, 0, 4);

  Time: O(n^(k-1))

----------------------------------------------------------------
COMPLEXITY COMPARISON
----------------------------------------------------------------

  Problem   Time       Space   Method
  -------   ----       -----   ------
  2Sum      O(n)       O(n)    HashMap
  2Sum II   O(n)       O(1)    Two Pointers (sorted)
  3Sum      O(n^2)     O(1)    Sort + 2-pointer inner
  4Sum      O(n^3)     O(1)    Sort + two fixed + 2-pointer
  kSum      O(n^(k-1)) O(k)    Recursive reduce

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: Why is 3Sum O(n^2) and not O(n^3)?
  A: The two-pointer inner loop does the pair search in O(n) instead
     of a nested loop. Sorting is O(n log n), negligible vs O(n^2).

  Q: How do you avoid duplicate triplets without using a HashSet?
  A: Sort first. Then skip duplicates at each pointer level using
     the "if same as previous, continue/skip" checks.

  Q: Does LC 15 guarantee a solution exists?
  A: No. It asks for ALL valid triplets. If none exist, return [].

  Q: What if the constraint is sum >= target instead of == target?
  A: Use a counting approach with the "count pairs >= threshold" trick
     (add r-l when nums[i]+nums[j]+nums[l]+nums[r] >= target, then r--).

  Q: How do you extend to finding triplets in a matrix?
  A: Flatten to 1D array, then apply 3Sum.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------

  - Always sort first and state it explicitly.
  - Show the duplicate skipping logic on a small example.
  - Mention overflow for 4Sum (use long).
  - Optional: mention the kSum generalization to impress.
  - Early termination: if nums[i] > 0 in 3Sum (all positives, no way
    to sum to 0), break the outer loop.
