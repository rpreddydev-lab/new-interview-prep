================================================================
  TWO POINTERS -- INTRODUCTION
================================================================

The Two Pointers technique uses two index variables that move
through the data structure to avoid nested loops. Instead of
O(n^2) brute force, two pointers solve many problems in O(n).

----------------------------------------------------------------
WHEN TO USE TWO POINTERS
----------------------------------------------------------------

  Signal words:
    - "sorted array" + find pair/triplet with target sum
    - "remove duplicates in-place"
    - "partition array" (move zeros, segregate negatives)
    - "palindrome check"
    - "longest / shortest subarray / substring" (see also window)
    - "merge two sorted arrays / lists"

  NOT suitable when:
    - Array is unsorted AND sorting would alter correctness
    - You need all indices (not just existence)
    - Duplicates must each be counted separately

----------------------------------------------------------------
TWO VARIANTS
----------------------------------------------------------------

  A) OPPOSITE DIRECTION (converging)
     l starts at 0, r starts at n-1.
     Move inward based on comparison.
     Use for: pair sum, palindrome, container with most water.

  B) SAME DIRECTION (sliding)
     l and r both start at 0. r advances; l advances to shrink.
     Use for: remove duplicates, move zeros, slow/fast write pointer.
     (Note: overlaps with "sliding window" in some texts.)

----------------------------------------------------------------
VISUALIZATION -- OPPOSITE DIRECTION
----------------------------------------------------------------

  nums = [-3, -1, 0, 2, 4, 6],  target = 3
          l                  r

  Iteration 1:  -3 + 6 = 3  == target  --> FOUND  ✓

  nums = [-3, -1, 0, 2, 4, 6],  target = 1
          l                  r

  Iteration 1:  -3 + 6 = 3  > 1  --> r--
  Iteration 2:  -3 + 4 = 1  == 1  --> FOUND  ✓

----------------------------------------------------------------
VISUALIZATION -- SAME DIRECTION (remove element)
----------------------------------------------------------------

  nums = [3, 2, 2, 3],  val = 3
  slow = 0  (write pointer)
  fast = 0  (read pointer)

  fast=0: nums[0]=3 == val --> skip, fast=1
  fast=1: nums[1]=2 != val --> nums[slow]=2, slow=1, fast=2
  fast=2: nums[2]=2 != val --> nums[slow]=2, slow=2, fast=3
  fast=3: nums[3]=3 == val --> skip, fast=4

  Result: nums[0..1] = [2, 2], return slow=2

----------------------------------------------------------------
JAVA TEMPLATE -- OPPOSITE DIRECTION
----------------------------------------------------------------

  public int[] twoSum(int[] nums, int target) {
      int l = 0, r = nums.length - 1;
      while (l < r) {
          int sum = nums[l] + nums[r];
          if (sum == target) {
              return new int[]{l, r};
          } else if (sum < target) {
              l++;
          } else {
              r--;
          }
      }
      return new int[]{-1, -1};  // not found
  }

----------------------------------------------------------------
JAVA TEMPLATE -- SAME DIRECTION (write pointer)
----------------------------------------------------------------

  public int removeElement(int[] nums, int val) {
      int slow = 0;
      for (int fast = 0; fast < nums.length; fast++) {
          if (nums[fast] != val) {
              nums[slow++] = nums[fast];
          }
      }
      return slow;  // new length
  }

----------------------------------------------------------------
JAVA TEMPLATE -- PALINDROME CHECK
----------------------------------------------------------------

  public boolean isPalindrome(String s) {
      // clean the string first
      int l = 0, r = s.length() - 1;
      while (l < r) {
          while (l < r && !Character.isLetterOrDigit(s.charAt(l))) l++;
          while (l < r && !Character.isLetterOrDigit(s.charAt(r))) r--;
          if (Character.toLowerCase(s.charAt(l)) !=
              Character.toLowerCase(s.charAt(r))) return false;
          l++; r--;
      }
      return true;
  }

----------------------------------------------------------------
COMPLEXITY
----------------------------------------------------------------

  Time:  O(n)  -- each pointer moves at most n steps total
  Space: O(1)  -- no extra data structure

----------------------------------------------------------------
COMMON MISTAKES
----------------------------------------------------------------

  1. Forgetting to sort the array first when the problem is not
     already sorted (e.g., 3Sum requires sorting first).

  2. Using l <= r instead of l < r -- leads to index-out-of-bounds
     when both pointers land on the same element.

  3. Not handling duplicates in 3Sum/4Sum -- must skip
     while (l < r && nums[l] == nums[l-1]) l++;

  4. In same-direction: moving slow pointer when condition NOT met
     (should only advance slow when writing valid element).

  5. Applying two pointers to UNSORTED data expecting correct results.

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: Why do two pointers work on a sorted array for pair sum?
  A: Because the array is ordered, we know the only ways to
     increase the sum is to move l right, and to decrease it is
     to move r left. This eliminates cases systematically.

  Q: Is two pointer the same as sliding window?
  A: Conceptually related but different. Two pointers usually refers
     to the converging (opposite direction) approach or a simple
     write-pointer. Sliding window specifically means a dynamic-size
     window growing/shrinking based on a constraint.

  Q: What is the time complexity of 3Sum?
  A: O(n^2). Sort is O(n log n). Then for each of n elements, run
     a two-pointer pass in O(n). Total = O(n^2).

  Q: How do you handle duplicates in 3Sum?
  A: After sort, skip duplicates at the outer loop level
     (if i > 0 && nums[i] == nums[i-1]) and skip duplicates at
     inner level after finding a valid pair.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------

  - Always ask "Is the array sorted?" -- it gates whether you can
    use two pointers without preprocessing.

  - When demonstrating, trace through a small example manually
    showing both pointers moving.

  - Say explicitly: "Two pointers gives us O(n) instead of O(n^2)
    brute force because we eliminate a range of cases with each step."

  - For in-place problems (remove element, remove duplicates), use
    the slow/fast write-pointer variant and return the new length.
