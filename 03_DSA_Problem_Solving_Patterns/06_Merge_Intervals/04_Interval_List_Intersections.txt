PROBLEM (LC 986): INTERVAL LIST INTERSECTIONS
----------------------------------------------------------------

  Given two sorted lists of non-overlapping intervals A and B,
  return the intersection of the two lists.

  Example:
    A = [[0,2],[5,10],[13,23],[24,25]]
    B = [[1,5],[8,12],[15,24],[25,26]]

    Intersections:
      [0,2] ∩ [1,5]   = [1,2]
      [5,10] ∩ [1,5]  = [5,5]
      [5,10] ∩ [8,12] = [8,10]
      [13,23] ∩ [15,24] = [15,23]
      [24,25] ∩ [15,24] = [24,24]
      [24,25] ∩ [25,26] = [25,25]

    Output: [[1,2],[5,5],[8,10],[15,23],[24,24],[25,25]]

----------------------------------------------------------------
INTERSECTION OF TWO INTERVALS
----------------------------------------------------------------

  Given intervals [a,b] and [c,d]:

  They intersect if: a <= d AND c <= b
  (neither ends before the other starts)

  The intersection is: [max(a,c), min(b,d)]
  (the overlap is from the later start to the earlier end)

  If max(a,c) > min(b,d): no intersection (this won't happen if we
  only check pairs that actually overlap).

----------------------------------------------------------------
TWO-POINTER APPROACH
----------------------------------------------------------------

  Use two pointers i, j for lists A and B respectively.

  At each step:
    1. Compute intersection of A[i] and B[j] (if any).
    2. Advance the pointer of the interval with the SMALLER end time.
       (The interval that ends first cannot intersect any future interval
        on the other side, so we advance past it.)

  Why advance the smaller end?
    If A[i] ends first (A[i][1] < B[j][1]):
      B[j] might still intersect A[i+1], A[i+2], ...
      A[i] definitely can't intersect B[j+1] (starts even later).
      So advance i.
    Symmetric for B[j].

----------------------------------------------------------------
JAVA SOLUTION
----------------------------------------------------------------

  public int[][] intervalIntersection(int[][] A, int[][] B) {
      List<int[]> result = new ArrayList<>();
      int i = 0, j = 0;

      while (i < A.length && j < B.length) {
          int lo = Math.max(A[i][0], B[j][0]);
          int hi = Math.min(A[i][1], B[j][1]);

          if (lo <= hi) {
              result.add(new int[]{lo, hi});
          }

          if (A[i][1] < B[j][1]) {
              i++;  // A[i] ends first, advance A
          } else {
              j++;  // B[j] ends first (or equal), advance B
          }
      }

      return result.toArray(new int[0][]);
  }

  Time: O(m + n)  where m = A.length, n = B.length
  Space: O(m + n) for result

----------------------------------------------------------------
TRACED EXAMPLE
----------------------------------------------------------------

  A = [[0,2],[5,10],[13,23],[24,25]]
  B = [[1,5],[8,12],[15,24],[25,26]]

  i=0, j=0: A=[0,2], B=[1,5]
    lo=max(0,1)=1, hi=min(2,5)=2. 1<=2 --> add [1,2]
    A[0][1]=2 < B[0][1]=5 --> i=1

  i=1, j=0: A=[5,10], B=[1,5]
    lo=max(5,1)=5, hi=min(10,5)=5. 5<=5 --> add [5,5]
    A[1][1]=10 > B[0][1]=5 --> j=1

  i=1, j=1: A=[5,10], B=[8,12]
    lo=max(5,8)=8, hi=min(10,12)=10. 8<=10 --> add [8,10]
    A[1][1]=10 < B[1][1]=12 --> i=2

  i=2, j=1: A=[13,23], B=[8,12]
    lo=max(13,8)=13, hi=min(23,12)=12. 13>12 --> NO intersection
    A[2][1]=23 > B[1][1]=12 --> j=2

  i=2, j=2: A=[13,23], B=[15,24]
    lo=max(13,15)=15, hi=min(23,24)=23. 15<=23 --> add [15,23]
    A[2][1]=23 < B[2][1]=24 --> i=3

  i=3, j=2: A=[24,25], B=[15,24]
    lo=max(24,15)=24, hi=min(25,24)=24. 24<=24 --> add [24,24]
    A[3][1]=25 > B[2][1]=24 --> j=3

  i=3, j=3: A=[24,25], B=[25,26]
    lo=max(24,25)=25, hi=min(25,26)=25. 25<=25 --> add [25,25]
    A[3][1]=25 < B[3][1]=26 --> i=4

  i=4: i >= A.length --> stop

  Result: [[1,2],[5,5],[8,10],[15,23],[24,24],[25,25]] ✓

VARIANT: FIND EMPLOYEES FREE TIME (LC 759)
----------------------------------------------------------------

  Given a schedule of n employees (each a list of intervals),
  find the intervals where ALL employees are free.

  Approach:
    1. Flatten all intervals into one list.
    2. Sort by start time.
    3. Merge overlapping intervals (like LC 56).
    4. Find GAPS between consecutive merged intervals.
       Each gap is a free-time interval.

  Java:
    public List<Interval> employeeFreeTime(List<List<Interval>> schedule) {
        List<Interval> all = new ArrayList<>();
        for (List<Interval> person : schedule) all.addAll(person);
        all.sort((a, b) -> a.start - b.start);

        List<Interval> result = new ArrayList<>();
        Interval last = all.get(0);

        for (int i = 1; i < all.size(); i++) {
            Interval curr = all.get(i);
            if (curr.start <= last.end) {
                last.end = Math.max(last.end, curr.end);  // merge
            } else {
                result.add(new Interval(last.end, curr.start));  // gap = free time
                last = curr;
            }
        }
        return result;
    }

  Time: O(N log N) where N = total intervals across all employees
  Space: O(N)

----------------------------------------------------------------
VARIANT: INTERSECTION OF TWO SINGLE INTERVALS
----------------------------------------------------------------

  Simple utility function (used as building block):

    boolean overlaps(int[] a, int[] b) {
        return a[0] <= b[1] && b[0] <= a[1];
    }

    int[] intersect(int[] a, int[] b) {
        if (!overlaps(a, b)) return null;
        return new int[]{Math.max(a[0], b[0]), Math.min(a[1], b[1])};
    }

----------------------------------------------------------------
VARIANT: UNION OF TWO INTERVAL LISTS
----------------------------------------------------------------

  Combine both lists, sort by start, merge overlapping.
  Same as LC 56 applied to the combined list.

  Time: O((m+n) log(m+n))

----------------------------------------------------------------
COMMON MISTAKES
----------------------------------------------------------------

  1. Wrong intersection formula: lo = max(starts), hi = min(ends).
     NOT min(starts) and max(ends) — that would be the UNION.

  2. Wrong pointer advancement: must advance the pointer of the interval
     with the SMALLER end time (not the smaller start).

  3. Including empty intersections: check lo <= hi before adding.

  4. For employee free time: finding gaps correctly.
     Gap is from last.end to curr.start (in the sorted merged list).

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: Why advance the pointer with the smaller end?
  A: The interval that ends first cannot overlap with any future interval
     on the other side (future intervals start no earlier than current ones,
     and we already went past this interval's end). The other interval might
     still overlap with the next interval on our side.

  Q: What's the time complexity?
  A: O(m + n) — we advance i or j at each step, and each pointer goes from
     0 to its list length. Total steps = m + n.

  Q: How do you find the intersection vs the union of two interval lists?
  A: Intersection: max(starts), min(ends) for overlapping pairs.
     Union: merge all intervals from both lists (sort + merge overlap).

  Q: How do you find the "complement" of an interval list?
  A: Sort and merge, then find gaps. Include gaps from -inf to first start
     and last end to +inf (if needed by the problem).
