================================================================
  INSERT INTERVAL
  (LC 57)
================================================================

----------------------------------------------------------------
PROBLEM STATEMENT
----------------------------------------------------------------

  Given a sorted list of non-overlapping intervals and a new interval,
  insert the new interval and merge any overlapping intervals.
  Return the resulting list.

  Example 1:
    intervals = [[1,3],[6,9]], newInterval = [2,5]
    Output: [[1,5],[6,9]]

  Example 2:
    intervals = [[1,2],[3,5],[6,7],[8,10],[12,16]], newInterval = [4,8]
    Output: [[1,2],[3,10],[12,16]]

  Note: The input list is already sorted and non-overlapping.
  We insert ONE new interval and re-merge.

----------------------------------------------------------------
APPROACH: THREE-PHASE SCAN
----------------------------------------------------------------

  Phase 1: Add all intervals that END before newInterval starts.
           (These are completely to the left — no overlap.)
           Condition: intervals[i][1] < newInterval[0]

  Phase 2: Merge all intervals that OVERLAP with newInterval.
           (These overlap if they don't end before newInterval starts
            AND don't start after newInterval ends.)
           Condition: intervals[i][0] <= newInterval[1]
           Merge: expand newInterval to cover all overlapping intervals.

  Phase 3: Add all remaining intervals.
           (These are completely to the right — no overlap.)

  After Phase 2, insert the (possibly expanded) newInterval.

----------------------------------------------------------------
JAVA SOLUTION
----------------------------------------------------------------

  public int[][] insert(int[][] intervals, int[] newInterval) {
      List<int[]> result = new ArrayList<>();
      int i = 0, n = intervals.length;

      // Phase 1: intervals completely before newInterval
      while (i < n && intervals[i][1] < newInterval[0]) {
          result.add(intervals[i]);
          i++;
      }

      // Phase 2: merge overlapping intervals into newInterval
      while (i < n && intervals[i][0] <= newInterval[1]) {
          newInterval[0] = Math.min(newInterval[0], intervals[i][0]);
          newInterval[1] = Math.max(newInterval[1], intervals[i][1]);
          i++;
      }
      result.add(newInterval);  // add merged interval

      // Phase 3: intervals completely after newInterval
      while (i < n) {
          result.add(intervals[i]);
          i++;
      }

      return result.toArray(new int[0][]);
  }

  Time: O(n)  Space: O(n)
  (No sorting needed — input is already sorted!)

----------------------------------------------------------------
TRACED EXAMPLE 1: [[1,3],[6,9]], newInterval=[2,5]
----------------------------------------------------------------

  Phase 1: i=0, intervals[0]=[1,3]
    intervals[0][1]=3 < newInterval[0]=2? NO (3 < 2 is false) --> stop

  Phase 2: i=0, intervals[0]=[1,3]
    intervals[0][0]=1 <= newInterval[1]=5? YES --> merge
    newInterval[0] = min(2, 1) = 1
    newInterval[1] = max(5, 3) = 5
    i=1

    i=1, intervals[1]=[6,9]
    intervals[1][0]=6 <= newInterval[1]=5? NO --> stop

    Add newInterval=[1,5]

  Phase 3: i=1, add [6,9]

  Result: [[1,5],[6,9]] ✓

----------------------------------------------------------------
TRACED EXAMPLE 2: [[1,2],[3,5],[6,7],[8,10],[12,16]], newInterval=[4,8]
----------------------------------------------------------------

  Phase 1:
    i=0: [1,2] end=2 < start=4 --> add [1,2], i=1
    i=1: [3,5] end=5 < start=4? NO (5 < 4 is false) --> stop

  Phase 2:
    i=1: [3,5] start=3 <= end=8? YES
      newInterval = [min(4,3), max(8,5)] = [3,8], i=2
    i=2: [6,7] start=6 <= 8? YES
      newInterval = [min(3,6), max(8,7)] = [3,8], i=3
    i=3: [8,10] start=8 <= 8? YES
      newInterval = [min(3,8), max(8,10)] = [3,10], i=4
    i=4: [12,16] start=12 <= 10? NO --> stop
    Add newInterval=[3,10]

  Phase 3:
    i=4: add [12,16]

  Result: [[1,2],[3,10],[12,16]] ✓

----------------------------------------------------------------
EDGE CASES
----------------------------------------------------------------

  1. newInterval before all:
     intervals=[[3,5],[7,9]], newInterval=[1,2]
     Phase 1: skip (3 not < 2... wait, [1,2][1]=2 < [3,5][0]=3? YES)
     Actually Phase 1 checks: intervals[i][1] < newInterval[0] = 1 --> nothing
     Phase 2: intervals[0][0]=3 <= newInterval[1]=2? NO --> stop immediately
     Result: [[1,2],[3,5],[7,9]] ✓

  2. newInterval after all:
     intervals=[[1,3]], newInterval=[6,9]
     Phase 1: [1,3] end=3 < start=6 --> add [1,3]
     Phase 2: nothing (i=1=n)
     Phase 3: nothing
     Result: [[1,3],[6,9]] ✓

  3. newInterval covers all:
     intervals=[[1,3],[5,7]], newInterval=[0,10]
     Phase 1: nothing (0 not < 0)... wait: 3 < 0? No --> phase 1 skips
     Phase 2: merge all --> newInterval=[0,10]
     Result: [[0,10]] ✓

  4. Empty intervals:
     intervals=[], newInterval=[5,7]
     Phase 1,2,3 all skip/no-op
     Add newInterval=[5,7]
     Result: [[5,7]] ✓

----------------------------------------------------------------
ALTERNATIVE: BINARY SEARCH APPROACH
----------------------------------------------------------------

  Since intervals is sorted, use binary search to find the insertion point.

  1. Binary search for the first interval that starts after newInterval ends.
  2. Binary search for the last interval that ends before newInterval starts.
  3. Merge the range in between.

  This is O(log n) to find boundaries + O(n) to build result.
  In practice, the three-phase linear scan is simpler and equally O(n).

----------------------------------------------------------------
COMMON MISTAKES
----------------------------------------------------------------

  1. Phase 1 condition: intervals[i][1] < newInterval[0]
     (interval ends BEFORE new starts — no overlap)
     Common error: using <= instead of <
     If intervals[i][1] == newInterval[0]: they TOUCH (overlap)
     So use strict < in Phase 1.

  2. Phase 2 condition: intervals[i][0] <= newInterval[1]
     (interval starts before or at new interval's end — overlap)
     Use <= (touching at endpoint is overlap).

  3. Forgetting to add newInterval after Phase 2.
     The merged newInterval must be added explicitly.

  4. Not updating both sides of newInterval during merge:
     newInterval[0] = min(newInterval[0], intervals[i][0])
     newInterval[1] = max(newInterval[1], intervals[i][1])
     Both sides need to expand.

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: Why is this O(n) while LC 56 (Merge Intervals) is O(n log n)?
  A: The input is already sorted and non-overlapping. We skip the sort step.
     The three-phase scan is a single O(n) pass.

  Q: Why update newInterval[0] with min in Phase 2?
  A: The existing interval might start BEFORE the new interval.
     E.g., if newInterval=[4,8] and intervals[i]=[3,5], after merging
     the start should be 3 (not 4). We expand in both directions.

  Q: What if newInterval doesn't overlap with any existing interval?
  A: Phase 2 loop executes zero times. newInterval is inserted as-is
     between Phase 1 and Phase 3 intervals.

  Q: Can you do this in-place?
  A: Technically possible but complex (requires shifting elements).
     Building a new list is cleaner and still O(n) space.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------

  - Name the three phases clearly: "before", "merge", "after".
  - State the overlap conditions for each phase boundary upfront.
  - Trace through Example 2 (the multi-merge case) to show completeness.
  - Emphasize: no sort needed (input is already sorted) → O(n) vs O(n log n).
  - Mention the edge case of newInterval at the very start or very end.
