================================================================
  MEETING ROOMS
  (LC 252, LC 253)
================================================================

----------------------------------------------------------------
PROBLEM 1 (LC 252): CAN ATTEND ALL MEETINGS?
----------------------------------------------------------------

  Given a list of meeting intervals [start, end], determine if a
  person can attend ALL meetings (no two meetings overlap).

  Example 1:
    intervals = [[0,30],[5,10],[15,20]]
    Output: false  (0,30 overlaps with 5,10 and 15,20)

  Example 2:
    intervals = [[7,10],[2,4]]
    Output: true  (no overlap)

  Algorithm:
    1. Sort by start time.
    2. Check consecutive intervals: if any prev.end > curr.start, return false.
    3. Return true if all consecutive pairs are non-overlapping.

  Java:
    public boolean canAttendMeetings(int[][] intervals) {
        Arrays.sort(intervals, (a, b) -> Integer.compare(a[0], b[0]));
        for (int i = 1; i < intervals.length; i++) {
            if (intervals[i][0] < intervals[i-1][1]) {
                return false;  // overlap: second starts before first ends
            }
        }
        return true;
    }

  Time: O(n log n)  Space: O(1) extra

  Note: Condition is strict <  (not <=).
  Meetings that touch at the same time (end=start) are OK (one ends, other starts).
  If problem says touching also conflicts, use <=.

----------------------------------------------------------------
PROBLEM 2 (LC 253): MINIMUM MEETING ROOMS
----------------------------------------------------------------

  Given a list of meeting intervals, find the minimum number of
  conference rooms required to hold all meetings simultaneously.

  Example:
    intervals = [[0,30],[5,10],[15,20]]
    t=0:  room 1 starts [0,30]
    t=5:  room 2 starts [5,10] (room 1 still busy)
    t=10: room 2 ends
    t=15: room 2 reuses [15,20] (room 1 still busy)
    t=20: room 2 ends
    t=30: room 1 ends
    Maximum concurrent: 2 --> need 2 rooms

----------------------------------------------------------------
APPROACH 1: MIN-HEAP (Priority Queue)
----------------------------------------------------------------

  Keep a min-heap of end times of ongoing meetings.
  For each new meeting (sorted by start):
    - If the earliest-ending meeting ends before this one starts:
      reuse that room (pop from heap, push new end time).
    - Otherwise: allocate a new room (push new end time).

  Max heap size at any point = minimum rooms needed.

  Java:
    public int minMeetingRooms(int[][] intervals) {
        Arrays.sort(intervals, (a, b) -> Integer.compare(a[0], b[0]));
        PriorityQueue<Integer> minHeap = new PriorityQueue<>();  // min end times

        for (int[] interval : intervals) {
            if (!minHeap.isEmpty() && minHeap.peek() <= interval[0]) {
                minHeap.poll();  // reuse this room
            }
            minHeap.offer(interval[1]);  // assign room with this end time
        }
        return minHeap.size();  // rooms still occupied = rooms needed
    }

  Time: O(n log n)  Space: O(n)

  Trace: [[0,30],[5,10],[15,20]] (sorted by start)

    [0,30]: heap empty, add 30.  heap=[30]
    [5,10]: peek=30 <= 5? NO (30 > 5), add 10.  heap=[10,30]
    [15,20]: peek=10 <= 15? YES, poll 10, add 20.  heap=[20,30]

    heap.size() = 2 --> 2 rooms ✓

----------------------------------------------------------------
APPROACH 2: TWO-POINTER ON SORTED STARTS/ENDS
----------------------------------------------------------------

  Sort starts array and ends array separately.
  Use two pointers to sweep through time:
    - If next start < current earliest end: need a new room (rooms++)
    - Otherwise: reuse a room (advance end pointer)

  This is effectively counting the maximum overlap at any point.

  Java:
    public int minMeetingRooms(int[][] intervals) {
        int n = intervals.length;
        int[] starts = new int[n], ends = new int[n];
        for (int i = 0; i < n; i++) {
            starts[i] = intervals[i][0];
            ends[i] = intervals[i][1];
        }
        Arrays.sort(starts);
        Arrays.sort(ends);

        int rooms = 0, maxRooms = 0, ei = 0;
        for (int si = 0; si < n; si++) {
            if (starts[si] < ends[ei]) {
                rooms++;  // new meeting starts before earliest ongoing ends
            } else {
                ei++;     // reuse room (earliest meeting has ended)
            }
            maxRooms = Math.max(maxRooms, rooms);
        }
        return maxRooms;
    }

  Time: O(n log n)  Space: O(n)

  Trace: starts=[0,5,15], ends=[10,20,30]

    si=0: start[0]=0, end[0]=10. 0 < 10 --> rooms=1. max=1
    si=1: start[1]=5, end[0]=10. 5 < 10 --> rooms=2. max=2
    si=2: start[2]=15, end[0]=10. 15 >= 10 --> ei=1. rooms stays 2. max=2

  Answer: 2 ✓

----------------------------------------------------------------
APPROACH 3: SWEEP LINE WITH EVENTS
----------------------------------------------------------------

  Create events: +1 when a meeting starts, -1 when it ends.
  Sort by time (ties: end events before start events).
  Sweep, track running count, max = answer.

  Java:
    public int minMeetingRooms(int[][] intervals) {
        List<int[]> events = new ArrayList<>();
        for (int[] interval : intervals) {
            events.add(new int[]{interval[0], 1});   // start
            events.add(new int[]{interval[1], -1});  // end
        }
        // Sort: by time; for ties, end (-1) before start (+1)
        events.sort((a, b) -> a[0] != b[0] ? a[0] - b[0] : a[1] - b[1]);

        int rooms = 0, maxRooms = 0;
        for (int[] event : events) {
            rooms += event[1];
            maxRooms = Math.max(maxRooms, rooms);
        }
        return maxRooms;
    }

  Time: O(n log n)  Space: O(n)

  Tie-breaking: if a meeting ends at time t and another starts at t,
  end event comes first (sort by +1/-1: -1 < +1 comes first).
  This means we free the room BEFORE counting the new meeting → correct.

----------------------------------------------------------------
COMPARISON OF APPROACHES
----------------------------------------------------------------

  Approach         Time         Space    Clarity
  --------         ----         -----    -------
  Min-Heap         O(n log n)   O(n)     Intuitive (room assignment)
  Two Pointers     O(n log n)   O(n)     Compact (counting overlap)
  Sweep Line       O(n log n)   O(n)     Explicit (event-based)

  Prefer Min-Heap for interview: most intuitive to explain.
  Two-Pointer is elegant but the logic is subtle.

----------------------------------------------------------------
VARIANT: MEETING ROOMS III (LC 2402)
----------------------------------------------------------------

  n rooms. Each meeting assigned to the lowest-numbered available room.
  If no room available, wait until earliest-ending meeting, use that room.
  Find which room hosted the most meetings.

  Approach: Two heaps.
    - freeRooms: min-heap of available room numbers (initially 0..n-1)
    - usedRooms: min-heap of (end_time, room_number)

  For each meeting (sorted by start):
    1. Free rooms whose end_time <= start (move from usedRooms to freeRooms).
    2. If freeRooms empty: wait for earliest-ending room (pop from usedRooms,
       start new meeting at that end_time, push to freeRooms).
    3. Assign lowest-numbered free room (poll freeRooms), update count.

  Time: O(n log n)

----------------------------------------------------------------
COMMON MISTAKES
----------------------------------------------------------------

  1. LC 252 condition: use intervals[i][0] < intervals[i-1][1] (strict <).
     Meetings that END when next one starts are NOT overlapping
     (unless problem specifies otherwise).

  2. Min-Heap approach: compare minHeap.peek() <= interval[0]
     (meeting ends at or before current starts = room free).
     Using < would miss the case where they exactly touch.

  3. Sweep line tie-breaking: end events (-1) must come before start events (+1)
     at the same timestamp. Otherwise, a freed room isn't counted as available
     for the new meeting starting at the same time.

  4. Forgetting to track maxRooms separately in sweep/two-pointer.
     The final heap size (min-heap approach) directly gives max rooms.
     But in other approaches, need explicit max tracking.

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: Why does sorting by start time help?
  A: Meetings are processed in chronological order. When we encounter
     a new meeting, all previously processed meetings started earlier,
     so checking heap.peek() (earliest ending) tells us if a room is free.

  Q: Why does heap size equal minimum rooms needed?
  A: At any point, heap.size() = number of concurrent ongoing meetings.
     The maximum of this = peak concurrency = minimum rooms needed.

  Q: What's the difference between LC 252 and LC 253?
  A: LC 252 asks "can one person attend all?" (boolean). Just check pairwise.
     LC 253 asks "how many rooms?" (count concurrent meetings at peak).
