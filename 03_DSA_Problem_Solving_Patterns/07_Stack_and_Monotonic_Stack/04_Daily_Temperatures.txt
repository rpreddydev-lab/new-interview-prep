PROBLEM (LC 739): DAILY TEMPERATURES — DEEP DIVE
----------------------------------------------------------------

  Given an array of daily temperatures, for each day return the
  number of days until a warmer temperature.
  If no future warmer day, return 0.

  Input:  [73, 74, 75, 71, 69, 72, 76, 73]
  Output: [1,  1,  4,  2,  1,  1,  0,  0]

  Reading: Day 0 has temp 73. Next warmer day is day 1 (74). Gap = 1.
           Day 2 has temp 75. Next warmer day is day 6 (76). Gap = 4.

  Java:
    public int[] dailyTemperatures(int[] temperatures) {
        int n = temperatures.length;
        int[] result = new int[n];
        Deque<Integer> stack = new ArrayDeque<>();  // indices, decreasing temps

        for (int i = 0; i < n; i++) {
            while (!stack.isEmpty() && temperatures[stack.peek()] < temperatures[i]) {
                int j = stack.pop();
                result[j] = i - j;
            }
            stack.push(i);
        }
        return result;
    }

  Time: O(n)  Space: O(n)

----------------------------------------------------------------

PROBLEM (LC 901): ONLINE STOCK SPAN
----------------------------------------------------------------

  For each new stock price, find the span = consecutive days where
  price <= today's price (including today itself).

  Span = distance to previous strictly greater price.

  Example:
    prices:  100, 80, 60, 70, 60, 75, 85
    spans:     1,  1,  1,  2,  1,  4,  6

    Day 6: 85 > everything back to day 1 (80). Span = 6.

  Key insight: use a stack of (price, span) pairs.
  When new price >= stack.top price, absorb its span (it's part of our span).
  This avoids re-scanning.

  public class StockSpanner {
      private Deque<int[]> stack;  // [price, accumulated span]

      public StockSpanner() {
          stack = new ArrayDeque<>();
      }

      public int next(int price) {
          int span = 1;
          while (!stack.isEmpty() && stack.peek()[0] <= price) {
              span += stack.pop()[1];  // absorb span of dominated bar
          }
          stack.push(new int[]{price, span});
          return span;
      }
  }

  Time: O(1) amortized per call.
  Space: O(n) total for n calls.

  Trace: 100, 80, 60, 70, 60, 75, 85
    price=100: span=1. stack=[(100,1)]. return 1.
    price=80:  80<=100? NO. span=1. stack=[(100,1),(80,1)]. return 1.
    price=60:  60<=80? NO. span=1. stack=[(100,1),(80,1),(60,1)]. return 1.
    price=70:  70>=60? YES. span+=1=2. pop (60,1).
               70>=80? NO. stack=[(100,1),(80,1)]. push (70,2). return 2.
    price=60:  60<=70? NO. span=1. stack=[(100,1),(80,1),(70,2),(60,1)]. return 1.
    price=75:  75>=60? YES. span+=1=2. pop.
               75>=70? YES. span+=2=4. pop.
               75>=80? NO. stack=[(100,1),(80,1)]. push (75,4). return 4.
    price=85:  85>=75? YES. span+=4=5. pop.
               85>=80? YES. span+=1=6. pop.
               85<=100? YES (not strictly greater, so pop).
               Wait: condition is <=, so pop when price <=. 85<=100? NO (85<100). Stop.
               stack=[(100,1)]. push (85,6). return 6.

  Spans: [1,1,1,2,1,4,6] ✓

  Note: condition is stack.peek()[0] <= price (pop when new >= old, meaning new "covers" old).

PROBLEM (LC 1475): FINAL PRICES WITH A SPECIAL DISCOUNT
----------------------------------------------------------------

  For item at index i, find the first item j > i with prices[j] <= prices[i].
  Final price[i] = prices[i] - prices[j] (or prices[i] if no j exists).

  This is: find next smaller or equal element. Next smaller or equal
  = monotone INCREASING stack (pop when current <= top).

  Wait: We pop when current price <= top price (next smaller-or-equal breaks the increasing order).

  public int[] finalPrices(int[] prices) {
      int n = prices.length;
      int[] result = prices.clone();
      Deque<Integer> stack = new ArrayDeque<>();  // indices, increasing prices

      for (int i = 0; i < n; i++) {
          while (!stack.isEmpty() && prices[stack.peek()] >= prices[i]) {
              int j = stack.pop();
              result[j] = prices[j] - prices[i];  // apply discount
          }
          stack.push(i);
      }
      return result;
  }

  Time: O(n)  Space: O(n)

PROBLEM (LC 962): MAXIMUM WIDTH RAMP
----------------------------------------------------------------

  Find the maximum i - j (width) such that j <= i and nums[j] <= nums[i].

  Approach: Two-pass with monotone stack.
  Pass 1: Build a decreasing stack of indices from left (potential j values).
          Stack stores indices where nums[i] is strictly decreasing.
  Pass 2: Scan from right. For each index i, pop stack while nums[stack.top()] <= nums[i].
          Each pop gives a valid ramp; the last popped gives the widest.

  public int maxWidthRamp(int[] nums) {
      int n = nums.length;
      Deque<Integer> stack = new ArrayDeque<>();

      // Pass 1: build decreasing stack of left candidates
      for (int i = 0; i < n; i++) {
          if (stack.isEmpty() || nums[stack.peek()] > nums[i]) {
              stack.push(i);
          }
      }

      int maxWidth = 0;

      // Pass 2: scan from right, pop valid j's
      for (int i = n - 1; i >= 0; i--) {
          while (!stack.isEmpty() && nums[stack.peek()] <= nums[i]) {
              maxWidth = Math.max(maxWidth, i - stack.pop());
          }
      }

      return maxWidth;
  }

  Time: O(n)  Space: O(n)

  Key: why scan from right in pass 2?
  We want maximum width = maximum i - j. Scanning from rightmost i
  gives the largest possible i for each j.

COMPARISON TABLE
----------------------------------------------------------------

  Problem                  Stack Direction  Pop Condition     Result
  -------                  ---------------  -------------     ------
  Daily Temperatures       Decreasing       temp[top] < curr  result[top] = i-top
  Stock Span               Decreasing       price[top] <= cur span += top.span
  Final Prices             Increasing       price[top] >= cur result[top] -= curr
  Max Width Ramp           Decreasing (1)   nums[top] <= curr maxWidth = i - top

----------------------------------------------------------------
COMMON MISTAKES
----------------------------------------------------------------

  1. Stock Span: storing values not (value, span) pairs.
     Without the span, you'd have to scan backwards again (losing O(1) amortized).

  2. Forgetting <= vs < for "strictly greater" vs "greater or equal".
     Stock span: pop when price <= current (meaning current covers the top).
     Daily temps: pop when temp < current (strictly warmer, not equal).

  3. LC 962: pass 2 must scan from RIGHT to left (for maximum width).

  4. LC 962: building the stack in pass 1 ONLY pushes when value is smaller
     (strictly decreasing). This ensures only useful left endpoints are in stack.

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: Why use a stack for daily temperatures instead of brute force?
  A: Brute force is O(n^2). Stack processes each element at most twice (push/pop) = O(n).

  Q: In stock span, why accumulate span during pops?
  A: Because if prices [90, 85, 70, 80] appear, when 80 arrives, we pop 70 (span 1),
     then pop 85 (span 1). If next price 95 arrives, it would need to span back 4 days.
     By accumulating span=3 at 80's entry, the next comparison with 95 absorbs 3 at once,
     giving total span=4 in O(1).

  Q: What's the invariant of the monotone decreasing stack in daily temps?
  A: At any point, the temperatures corresponding to indices in the stack
     are in strictly decreasing order (from bottom to top). This ensures
     elements "waiting for a warmer day" are correctly managed.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------

  - Daily temperatures is the most commonly asked. Know the trace cold.
  - Stock spanner: explain the (price, accumulated span) pair design.
  - Emphasize amortized O(n) — each element pushed and popped at most once.
  - For circular or two-pass problems, draw the two passes separately.
