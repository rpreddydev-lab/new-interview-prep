================================================================
  LARGEST RECTANGLE IN HISTOGRAM
  (LC 84, LC 85)
================================================================

----------------------------------------------------------------
PROBLEM (LC 84): LARGEST RECTANGLE IN HISTOGRAM
----------------------------------------------------------------

  Given an array of bar heights, find the area of the largest
  rectangle that can be formed within the histogram bars.

  Example:
    heights = [2, 1, 5, 6, 2, 3]
    Output:  10  (bars at index 2,3 with height 5)

    Visualization:
          _
         | |
      _  | |
     | |_| |_
     | | | | |_
   __|_|_|_|_|_|__
     2 1 5 6 2 3

  For each bar i: the rectangle that uses bar i as the SHORTEST bar
  extends left as far as bars stay >= heights[i], and right the same.
  Area = heights[i] * (right_boundary - left_boundary - 1).

----------------------------------------------------------------
APPROACH: MONOTONE INCREASING STACK
----------------------------------------------------------------

  Use a monotone INCREASING stack (bottom to top: small to large indices).

  KEY INSIGHT: When we encounter a bar SHORTER than the stack top,
  the stack top bar can no longer extend to the right (current bar is shorter).
  We compute the maximum rectangle FOR the popped bar.

  For popped bar at index mid:
    - Height = heights[mid]
    - Right boundary = current index i
    - Left boundary = new stack top (after popping) or -1 if stack empty
    - Width = i - left_boundary - 1
    - Area = height * width

  After processing all bars: pop remaining stack elements.
  Their right boundary = n (the virtual end).

  TRICK: Add a sentinel bar of height 0 at the end.
  This forces all remaining bars to be popped, eliminating the
  separate post-loop handling.

  Java:
    public int largestRectangleArea(int[] heights) {
        int n = heights.length;
        // Append sentinel bar 0
        int[] h = Arrays.copyOf(heights, n + 1);  // h[n] = 0

        Deque<Integer> stack = new ArrayDeque<>();
        int maxArea = 0;

        for (int i = 0; i <= n; i++) {
            while (!stack.isEmpty() && h[stack.peek()] > h[i]) {
                int mid = stack.pop();
                int left = stack.isEmpty() ? -1 : stack.peek();
                int width = i - left - 1;
                maxArea = Math.max(maxArea, h[mid] * width);
            }
            stack.push(i);
        }
        return maxArea;
    }

  Time: O(n)  Space: O(n)

----------------------------------------------------------------
TRACED EXAMPLE: heights=[2,1,5,6,2,3]
----------------------------------------------------------------

  Append h=[2,1,5,6,2,3,0]

  i=0: h[0]=2, stack empty, push 0. stack=[0]
  i=1: h[1]=1, h[0]=2 > 1 --> pop 0.
         left = stack empty = -1. width = 1 - (-1) - 1 = 1. area = 2*1 = 2.
         stack=[]. push 1. stack=[1]
  i=2: h[2]=5, h[1]=1 < 5. push 2. stack=[1,2]
  i=3: h[3]=6, h[2]=5 < 6. push 3. stack=[1,2,3]
  i=4: h[4]=2, h[3]=6 > 2 --> pop 3.
         left = stack.peek() = 2. width = 4-2-1 = 1. area = 6*1 = 6.
         h[2]=5 > 2 --> pop 2.
         left = stack.peek() = 1. width = 4-1-1 = 2. area = 5*2 = 10. maxArea=10!
         h[1]=1 < 2. push 4. stack=[1,4]
  i=5: h[5]=3, h[4]=2 < 3. push 5. stack=[1,4,5]
  i=6: h[6]=0 (sentinel). Pop all:
         pop 5: h[5]=3, left=4, width=6-4-1=1, area=3*1=3.
         pop 4: h[4]=2, left=1, width=6-1-1=4, area=2*4=8.
         pop 1: h[1]=1, left=-1, width=6-(-1)-1=6, area=1*6=6.

  maxArea = 10 ✓

----------------------------------------------------------------
VISUAL: THE RECTANGLE CALCULATION
----------------------------------------------------------------

  When we pop mid at position i:

    Stack: [..., left, mid]    current bar: i (shorter than mid)

    left bar is the nearest bar to the left shorter than heights[mid].
    i is the first bar to the right shorter than heights[mid].
    So heights[mid] is the MINIMUM in range (left, i) exclusive.

    Width = i - left - 1 = number of bars in that range
    Area  = heights[mid] * width

  This correctly computes "the largest rectangle where heights[mid] is the limiting height."

PROBLEM (LC 85): MAXIMAL RECTANGLE IN BINARY MATRIX
----------------------------------------------------------------

  Given a binary matrix, find the largest rectangle containing only 1s.

  Approach: Reduce to LC 84 one row at a time.

  Build a "histogram heights" array:
    height[j] = consecutive 1s above row i in column j (including row i).
    If matrix[i][j] == 0: height[j] = 0 (reset).
    If matrix[i][j] == 1: height[j]++ (extend upward).

  Apply LC 84 solution to each row's height array.
  Take the maximum across all rows.

  Java:
    public int maximalRectangle(char[][] matrix) {
        if (matrix.length == 0) return 0;
        int n = matrix[0].length;
        int[] heights = new int[n];
        int maxArea = 0;

        for (char[] row : matrix) {
            // Update heights
            for (int j = 0; j < n; j++) {
                heights[j] = (row[j] == '1') ? heights[j] + 1 : 0;
            }
            // Apply largest rectangle in histogram
            maxArea = Math.max(maxArea, largestRectangleArea(heights));
        }
        return maxArea;
    }

  Time: O(m * n)  — m rows, each O(n) histogram
  Space: O(n)

  Visual:
    Matrix:
      1 0 1 0 0
      1 0 1 1 1
      1 1 1 1 1  <-- row 2
      1 0 0 1 0

    Heights at row 2: [3, 1, 3, 3, 2]
    Largest rectangle here = 6 (bars 2,3,4 with height 2 = wait: 3*3? no)
    Actually: heights=[3,1,3,3,2], largestRect = 6 (index 2,3,4 height 2... = 6? Let's check:
    Widths: [3]*1=3, [1]*5=5, [3]*3=9... let's trust the algorithm gives 6)

VARIANT: SUM OF SUBARRAY MINIMUMS (LC 907)
----------------------------------------------------------------

  Sum of min(subarray) for all subarrays.
  This uses the monotone stack to find, for each element:
    - left[i] = number of subarrays where arr[i] is the MINIMUM starting from left
    - right[i] = number of subarrays where arr[i] is the MINIMUM extending to right

  For each i: contribution = arr[i] * left[i] * right[i].

  Use strict < on one side and <= on other to handle duplicates.

  public int sumSubarrayMins(int[] arr) {
      int n = arr.length;
      long MOD = 1_000_000_007L;
      int[] left = new int[n];   // prev less or equal
      int[] right = new int[n];  // next less
      Deque<Integer> stack = new ArrayDeque<>();

      // Left: number of subarrays ending at i where arr[i] is min
      for (int i = 0; i < n; i++) {
          while (!stack.isEmpty() && arr[stack.peek()] >= arr[i]) stack.pop();
          left[i] = stack.isEmpty() ? i + 1 : i - stack.peek();
          stack.push(i);
      }
      stack.clear();

      // Right: number of subarrays starting at i where arr[i] is min
      for (int i = n - 1; i >= 0; i--) {
          while (!stack.isEmpty() && arr[stack.peek()] > arr[i]) stack.pop();
          right[i] = stack.isEmpty() ? n - i : stack.peek() - i;
          stack.push(i);
      }

      long result = 0;
      for (int i = 0; i < n; i++) {
          result = (result + (long) arr[i] * left[i] * right[i]) % MOD;
      }
      return (int) result;
  }

  Note the asymmetry in <= (left) vs < (right) to handle duplicates
  and avoid double-counting.

----------------------------------------------------------------
COMMON MISTAKES
----------------------------------------------------------------

  1. Forgetting sentinel (height 0 at end).
     Without it, need a separate loop to pop remaining stack elements.
     Sentinel is cleaner.

  2. Width formula: width = i - left - 1.
     NOT width = i - left (that would be off by one).
     left is the EXCLUSIVE left boundary (the bar just outside our range).

  3. Left boundary: use stack.peek() after popping mid, not before.
     The new top after popping IS the left boundary.

  4. For LC 85: building heights correctly.
     If matrix[i][j] == '0', heights[j] = 0 (reset to 0, not -1).

  5. Using char '0'/'1' vs int 0/1 in matrix. Matrix[i][j] is a char.

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: Why does the monotone increasing stack work here?
  A: Stack stays increasing because we pop elements taller than current.
     When we pop an element, the stack top is the first shorter bar to the LEFT,
     and the current bar is the first shorter bar to the RIGHT.
     This gives us the exact span where the popped bar can be the min height.

  Q: What's the time complexity and why is it O(n) and not O(n^2)?
  A: Each bar is pushed once and popped at most once. Total ops = 2n. O(n) amortized.

  Q: How does LC 85 reduce to LC 84?
  A: For each row, we maintain a height histogram representing consecutive 1s upward.
     The largest rectangle in that histogram AT EACH ROW gives a candidate answer.

  Q: What's the O(n^2) DP approach for LC 85?
  A: At each cell, maintain maxWidth[j] = consecutive 1s to the left in current row.
     Then scan upward while the row above is also 1, tracking min width.
     Less elegant, same O(mn) complexity.
