================================================================
  STACK AND MONOTONIC STACK PATTERN — INTRODUCTION
================================================================

----------------------------------------------------------------
WHAT IS A STACK?
----------------------------------------------------------------

  A stack is a LIFO (Last-In-First-Out) data structure.
  Elements are pushed on top and popped from the top.

  Java: Use Deque<Integer> as a stack (preferred over Stack class).
    Deque<Integer> stack = new ArrayDeque<>();
    stack.push(x);       // push onto top
    stack.pop();         // remove and return top
    stack.peek();        // view top without removing
    stack.isEmpty();     // check if empty

  Avoid: java.util.Stack (legacy, synchronized, slow).

----------------------------------------------------------------
WHEN TO USE A STACK
----------------------------------------------------------------

  Triggers:
    - "Last element seen" needs to be accessed
    - Nested structure (brackets, function calls, HTML tags)
    - "Undo" / "backtrack" to previous state
    - Matching pairs (open/close brackets, consecutive duplicates)
    - String manipulation (decoding, removing adjacent duplicates)
    - Evaluate expressions (RPN, infix to postfix)

  Key insight: use a stack when you need to DEFER processing
  of an element until you've seen what comes AFTER it.

----------------------------------------------------------------
WHAT IS A MONOTONIC STACK?
----------------------------------------------------------------

  A monotonic stack is a stack that maintains elements in sorted order
  (either monotonically increasing or decreasing from bottom to top).

  MONOTONE INCREASING stack (bottom to top: small to large):
    When pushing, pop all elements >= new element first.
    Stack always maintains: bottom < ... < top.

  MONOTONE DECREASING stack (bottom to top: large to small):
    When pushing, pop all elements <= new element first.
    Stack always maintains: bottom > ... > top.

  Template:
    Deque<Integer> stack = new ArrayDeque<>();
    for (int i = 0; i < n; i++) {
        while (!stack.isEmpty() && nums[stack.peek()] >= nums[i]) {
            // process the popped element if needed
            stack.pop();
        }
        stack.push(i);  // push index (not value, for position info)
    }

----------------------------------------------------------------
MONOTONIC STACK USE CASES
----------------------------------------------------------------

  1. Next Greater Element:
     Find the next element larger than each element.
     Use monotone decreasing stack.
     When we pop an element (because new element is bigger),
     the new element IS its "next greater element".

  2. Next Smaller Element:
     Find the next element smaller than each element.
     Use monotone increasing stack.
     Pop when new element is smaller; new element IS next smaller.

  3. Previous Greater Element:
     What's in the stack when we're about to push = the previous greater.

  4. Histogram / Area problems:
     Process bars, find span of each bar where it's the minimum.

  5. Stock span / Daily temperatures:
     How many days until a warmer temperature?

  Template pattern: monotone stack stores INDICES.
  Process each element, pop elements that are "dominated" by current.

----------------------------------------------------------------
AMORTIZED O(N) PROOF
----------------------------------------------------------------

  Each element is pushed ONCE and popped AT MOST ONCE.
  Total pushes = n, total pops <= n.
  Inner while loop may pop multiple times, but across the entire
  array, the total pops across all iterations = at most n.

  Amortized: O(1) per element = O(n) total. NOT O(n^2).

JAVA STACK TEMPLATE COMPARISON
----------------------------------------------------------------

  For general stack:
    Deque<Integer> stack = new ArrayDeque<>();
    Push: stack.push(x)  or  stack.addFirst(x)
    Pop:  stack.pop()    or  stack.removeFirst()
    Peek: stack.peek()   or  stack.peekFirst()

  For monotonic stack (store indices):
    Deque<Integer> stack = new ArrayDeque<>();
    for (int i = 0; i < n; i++) {
        while (!stack.isEmpty() && CONDITION(stack.peek(), i)) {
            int j = stack.pop();
            // j's "next ..." is i
            result[j] = nums[i];  // or (i - j), etc.
        }
        stack.push(i);
    }

  For NEXT GREATER: CONDITION = nums[stack.peek()] < nums[i]
    (pop if current is greater — decreasing stack, new element breaks monotonicity)

  For NEXT SMALLER: CONDITION = nums[stack.peek()] > nums[i]
    (pop if current is smaller — increasing stack)

----------------------------------------------------------------
CHOOSING INCREASING VS DECREASING STACK
----------------------------------------------------------------

  Want NEXT GREATER element:    Use DECREASING stack (pop when bigger arrives)
  Want NEXT SMALLER element:    Use INCREASING stack (pop when smaller arrives)
  Want PREVIOUS GREATER:        Stack contents at push time = previous greater
  Want LARGEST AREA / SPAN:     Depends on problem (usually min-based)

  Memory trick:
    "Decreasing stack reveals NEXT GREATER"
    (stack stores pending elements waiting for their next-greater to arrive)
    "Increasing stack reveals NEXT SMALLER"

----------------------------------------------------------------
COMMON MISTAKES
----------------------------------------------------------------

  1. Using Stack<> instead of Deque<> (legacy, slow).
  2. Storing values instead of indices (then can't compute distances/spans).
  3. Not handling remaining elements in stack after the loop.
     Elements left in the stack have no "next greater" (set to -1 or n).
  4. Wrong direction: for next greater, pop when CURRENT is GREATER
     (not when current is smaller).
  5. Off-by-one in circular next-greater (need two passes of the array).

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: Why use a monotonic stack instead of brute force for next-greater?
  A: Brute force is O(n^2). Monotonic stack is O(n) amortized, because
     each element is pushed once and popped at most once.

  Q: What's the space complexity of a monotonic stack?
  A: O(n) in the worst case (e.g., strictly increasing array — nothing is
     popped until the end, all n elements remain in the stack).

  Q: When should I use a stack vs a queue?
  A: Stack for LIFO (most recent first, undo, nesting). Queue for FIFO
     (oldest first, BFS, level-order processing).

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------

  - Visualize the stack as a vertical column with top at the right.
  - For next-greater, think: "I'm waiting for the next element
    big enough to 'answer' the elements in my stack."
  - Always trace through a small example showing stack state at each step.
  - Remember: each problem in this folder builds on the monotonic stack idea.
