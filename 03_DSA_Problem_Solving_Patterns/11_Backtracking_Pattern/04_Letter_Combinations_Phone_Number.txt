================================================================
  LETTER COMBINATIONS OF A PHONE NUMBER (LC 17)
================================================================

  Given a string of digits 2-9, return all possible letter combinations
  that the number could represent (T9 phone keyboard mapping).

  Input:  digits = "23"
  Output: ["ad","ae","af","bd","be","bf","cd","ce","cf"]

  Phone mapping:
    2 → "abc"    5 → "jkl"    8 → "tuv"
    3 → "def"    6 → "mno"    9 → "wxyz"
    4 → "ghi"    7 → "pqrs"

  Input:  digits = ""
  Output: []

----------------------------------------------------------------
SOLUTION: BACKTRACKING WITH INDEX
----------------------------------------------------------------

  Build combination character by character.
  At position `index`, try each letter mapped from digits[index].
  Base case: index == digits.length() → add current string.

  Java:
    private static final String[] MAPPING = {
        "", "", "abc", "def", "ghi", "jkl", "mno", "pqrs", "tuv", "wxyz"
    };

    public List<String> letterCombinations(String digits) {
        List<String> result = new ArrayList<>();
        if (digits == null || digits.isEmpty()) return result;
        backtrack(digits, 0, new StringBuilder(), result);
        return result;
    }

    private void backtrack(String digits, int index, StringBuilder current, List<String> result) {
        if (index == digits.length()) {
            result.add(current.toString());
            return;
        }
        String letters = MAPPING[digits.charAt(index) - '0'];
        for (char c : letters.toCharArray()) {
            current.append(c);                           // choose
            backtrack(digits, index + 1, current, result);  // explore
            current.deleteCharAt(current.length() - 1); // un-choose
        }
    }

  Time: O(4^n * n)  where n = digits.length, 4 = max letters per digit (7,9)
  Space: O(n) recursion depth

  Note: `current.deleteCharAt(current.length() - 1)` un-appends last char.
        Equivalent to using String concatenation, but StringBuilder is more efficient.

----------------------------------------------------------------
TRACED EXAMPLE: digits = "23"
----------------------------------------------------------------

  index=0, digit='2', letters="abc", current="":
    c='a': current="a"
      index=1, digit='3', letters="def", current="a":
        c='d': current="ad"
          index=2 == length → ADD "ad". delete 'd'. current="a"
        c='e': current="ae"
          index=2 → ADD "ae". delete 'e'. current="a"
        c='f': current="af"
          index=2 → ADD "af". delete 'f'. current="a"
      delete 'a'. current=""
    c='b': current="b"
      → ADD "bd","be","bf". delete 'b'. current=""
    c='c': current="c"
      → ADD "cd","ce","cf". delete 'c'. current=""

  Result: ["ad","ae","af","bd","be","bf","cd","ce","cf"] ✓

----------------------------------------------------------------
ALTERNATIVE: ITERATIVE BFS-STYLE
----------------------------------------------------------------

  Start with [""], for each digit, expand each existing string with all letters.

  Java:
    public List<String> letterCombinations(String digits) {
        if (digits.isEmpty()) return new ArrayList<>();
        String[] mapping = {"", "", "abc", "def", "ghi", "jkl", "mno", "pqrs", "tuv", "wxyz"};
        List<String> result = new ArrayList<>();
        result.add("");

        for (char d : digits.toCharArray()) {
            String letters = mapping[d - '0'];
            List<String> next = new ArrayList<>();
            for (String combo : result) {
                for (char c : letters.toCharArray()) {
                    next.add(combo + c);
                }
            }
            result = next;
        }
        return result;
    }

  Intuitive. At each digit step, multiply existing combinations by new letters.
  Downsides: creates many intermediate String objects; harder to prune.

----------------------------------------------------------------
EXTENSION VARIANTS
----------------------------------------------------------------

  1. LC 22 Generate Parentheses:
     Similar shape — choose '(' or ')' at each step with constraints.
     backtrack(open, close, n, current, result)
       if open < n: append '(', recurse with open+1
       if close < open: append ')', recurse with close+1
       if open==n && close==n: add to result

  2. Autocomplete / Prefix suggestions:
     Same backtracking over a Trie node instead of MAPPING array.

  3. Phone number spell-out (any length):
     Digits "2-9" → same approach, just longer digits string.

----------------------------------------------------------------
LC 22: GENERATE PARENTHESES (closely related)
----------------------------------------------------------------

  n pairs of parentheses. Generate all valid combinations.
  Input n=3: ["((()))","(()())","(())()","()(())","()()()"]

  Java:
    public List<String> generateParenthesis(int n) {
        List<String> result = new ArrayList<>();
        backtrack(0, 0, n, new StringBuilder(), result);
        return result;
    }

    private void backtrack(int open, int close, int n, StringBuilder sb, List<String> result) {
        if (sb.length() == 2 * n) {
            result.add(sb.toString());
            return;
        }
        if (open < n) {
            sb.append('(');
            backtrack(open + 1, close, n, sb, result);
            sb.deleteCharAt(sb.length() - 1);
        }
        if (close < open) {
            sb.append(')');
            backtrack(open, close + 1, n, sb, result);
            sb.deleteCharAt(sb.length() - 1);
        }
    }

  Pruning: open < n (can still add '('); close < open (can close what's open).
  Result count = Catalan(n) = C(2n,n)/(n+1). For n=3: 5.

----------------------------------------------------------------
COMMON MISTAKES
----------------------------------------------------------------

  1. Not checking empty digits → produces [""] instead of [].
  2. Using String concatenation in backtrack → O(n) copy at each step.
     Prefer StringBuilder + deleteCharAt for efficiency.
  3. Mapping array index: digits[i] - '0' gives 2..9, so mapping[2..9] must be valid.
     mapping[0] and mapping[1] are "" (unused).
  4. LC 22: condition is `close < open` (not `close < n`).
     If `close < n`, you might add extra ')' when open==close.

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: Time complexity of LC 17?
  A: O(4^n * n): 4 choices per digit (worst case for 7,9), n digits deep,
     then O(n) to copy string to result at each leaf.

  Q: How would you handle digit '1' or '0'?
  A: Set mapping[0]="" and mapping[1]="", and skip that digit.
     Or validate input to ensure only 2-9 are given.

  Q: Why is this backtracking and not just iterative expansion?
  A: Either approach works. Backtracking avoids storing large intermediate lists
     and is more naturally extensible with constraints (e.g., avoid specific patterns).

  Q: If '7' and '9' have 4 letters, why is the complexity 4^n not 3^n?
  A: Worst case uses 4-letter digits. For digits 2-6, 8 it's 3^n.

  Q: How does LC 22 relate to LC 17?
  A: Same shape: at each position choose from a set of options (letters vs '('/')').
     LC 22 has state-dependent options (open/close count), LC 17 has fixed options per digit.
