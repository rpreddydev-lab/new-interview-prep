================================================================
  SUBSETS (LC 78) AND SUBSETS II (LC 90)
================================================================

  LC 78: Given an array of UNIQUE integers, return all subsets (power set).
  LC 90: Given an array that MAY CONTAIN DUPLICATES, return unique subsets.

  Input (LC 78):  nums = [1,2,3]
  Output: [[],[1],[2],[1,2],[3],[1,3],[2,3],[1,2,3]]

  Input (LC 90):  nums = [1,2,2]
  Output: [[],[1],[1,2],[1,2,2],[2],[2,2]]

----------------------------------------------------------------
APPROACH 1: BACKTRACKING WITH START INDEX
----------------------------------------------------------------

  At each step, add current subset to result, then try each remaining element.
  Use start index to avoid revisiting earlier elements.

  Java (LC 78 — unique elements):
    public List<List<Integer>> subsets(int[] nums) {
        List<List<Integer>> result = new ArrayList<>();
        backtrack(nums, 0, new ArrayList<>(), result);
        return result;
    }

    private void backtrack(int[] nums, int start, List<Integer> current, List<List<Integer>> result) {
        result.add(new ArrayList<>(current));   // add at EVERY call (not just leaves)

        for (int i = start; i < nums.length; i++) {
            current.add(nums[i]);                        // choose
            backtrack(nums, i + 1, current, result);    // explore
            current.remove(current.size() - 1);          // un-choose
        }
    }

  Time: O(2^n * n)   Space: O(n)

  Key difference from combination/permutation: we ADD TO RESULT at EVERY call
  (not just when reaching a leaf), because every partial state IS a valid subset.

----------------------------------------------------------------
TRACED EXAMPLE: nums = [1,2,3]
----------------------------------------------------------------

  backtrack(0, []):    result=[[]]
    i=0: add 1. backtrack(1, [1]):  result=[[],[1]]

           i=2: add 3. backtrack(3, [1,3]):  result=..+[1,3]
                       remove 3. [1]

           i=2: add 3. backtrack(3,[2,3]):  result=..+[2,3]

           remove 2. []
    i=2: add 3. backtrack(3, [3]):  result=..+[3]
           remove 3. []

  Result: [[], [1], [1,2], [1,2,3], [1,3], [2], [2,3], [3]] ✓

----------------------------------------------------------------
LC 90: SUBSETS WITH DUPLICATES
----------------------------------------------------------------

  Sort first, then skip duplicates at the same level.

  Java:
    public List<List<Integer>> subsetsWithDup(int[] nums) {
        Arrays.sort(nums);  // CRITICAL: sort to group duplicates
        List<List<Integer>> result = new ArrayList<>();
        backtrack(nums, 0, new ArrayList<>(), result);
        return result;
    }

    private void backtrack(int[] nums, int start, List<Integer> current, List<List<Integer>> result) {
        result.add(new ArrayList<>(current));

        for (int i = start; i < nums.length; i++) {
            // Skip duplicate: same value as previous at the same level
            if (i > start && nums[i] == nums[i-1]) continue;
            current.add(nums[i]);
            backtrack(nums, i + 1, current, result);
            current.remove(current.size() - 1);
        }
    }

  Example trace for [1,2,2]:
    Sort: [1,2,2]
    backtrack(0, []):  result=[[]]
      i=0: add 1. backtrack(1, [1]):  result=..+[1]
        i=1: add 2. backtrack(2, [1,2]):  result=..+[1,2]
               i=2: add 2. backtrack(3,[1,2,2]):  result=..+[1,2,2]
               remove 2. [1,2]
               remove 2. [1]
        i=2: 2==2 AND i>start(1), SKIP
        remove 1. []
      i=1: add 2. backtrack(2, [2]):  result=..+[2]
        i=2: add 2. backtrack(3,[2,2]):  result=..+[2,2]
               remove 2. [2]
        remove 2. []
      i=2: 2==2 AND i>start(0), SKIP
    Result: [[],[1],[1,2],[1,2,2],[2],[2,2]] ✓

APPROACH 2: BITMASK (ITERATIVE)
----------------------------------------------------------------

  For n elements, there are 2^n subsets. Each is represented by a bitmask.
  Bit i set = element i included.

  Java:
    public List<List<Integer>> subsets(int[] nums) {
        int n = nums.length;
        List<List<Integer>> result = new ArrayList<>();

        for (int mask = 0; mask < (1 << n); mask++) {
            List<Integer> subset = new ArrayList<>();
            for (int i = 0; i < n; i++) {
                if ((mask >> i & 1) == 1) subset.add(nums[i]);
            }
            result.add(subset);
        }
        return result;
    }

  Time: O(2^n * n)   Space: O(n)

  Simple and iterative. But doesn't extend cleanly to LC 90 (duplicates).

----------------------------------------------------------------
APPROACH 3: CASCADING (ITERATIVE)
----------------------------------------------------------------

  Start with [[]], then for each num, add it to every existing subset.

  Java:
    public List<List<Integer>> subsets(int[] nums) {
        List<List<Integer>> result = new ArrayList<>();
        result.add(new ArrayList<>());

        for (int num : nums) {
            int size = result.size();
            for (int i = 0; i < size; i++) {
                List<Integer> newSubset = new ArrayList<>(result.get(i));
                newSubset.add(num);
                result.add(newSubset);
            }
        }
        return result;
    }

  Time: O(2^n * n)   Space: O(2^n * n)

  Elegant but high memory use.

----------------------------------------------------------------
COMMON MISTAKES
----------------------------------------------------------------

  1. Adding result.add(current) instead of result.add(new ArrayList<>(current)).
     Adds a reference that gets emptied during backtracking.

  2. For LC 90: forgetting to sort before deduplication.
     i > start, not i > 0: allows first occurrence in each branch.

  3. For LC 90: using i > 0 instead of i > start.
     "i > 0 && nums[i]==nums[i-1]" would incorrectly skip duplicates
     in deeper branches where that duplicate is the first at that level.

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: Why is i > start (not i > 0) in the duplicate skip condition?
  A: We only skip if the same value appeared earlier in the SAME RECURSIVE
     CALL's loop (same level of the decision tree). If i > 0 were used,
     we'd skip even in deeper calls where the duplicate is being used
     for the first time at that level.

  Q: Why do we add to result at every call, not just leaves?
  A: Because every partial path from root to current node IS a valid subset.
     Contrast with combination problems where we only add at certain depths.

  Q: Time complexity of subsets?
  A: O(2^n * n): 2^n subsets, each takes O(n) to copy into result.

  Q: What's the difference between subsets and combinations?
  A: Subsets: all possible subsets (all sizes). Combinations: subsets of
     exactly size k.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------

  - State: "Add to result at EVERY level, not just leaf."
  - For duplicates: sort first, then skip `if (i > start && nums[i] == nums[i-1])`.
  - Draw the decision tree for [1,2,3] -- shows all 8 subsets clearly.
  - Know all three approaches: backtracking, bitmask, cascading.
