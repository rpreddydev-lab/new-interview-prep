================================================================
  VARIABLE SIZE SLIDING WINDOW
================================================================

The window size is NOT fixed. It grows when valid and shrinks
when the constraint is violated. Used to find the
LONGEST or SHORTEST subarray/substring satisfying a condition.

----------------------------------------------------------------
TEMPLATE (LONGEST VALID)
----------------------------------------------------------------

  int l = 0, ans = 0;
  // window state (map, array, sum, count, etc.)

  for (int r = 0; r < n; r++) {
      // 1. Expand: add element at r to window
      addToWindow(arr[r]);

      // 2. Shrink: while window is invalid, remove left
      while (windowIsInvalid()) {
          removeFromWindow(arr[l]);
          l++;
      }

      // 3. Window is valid. Update answer.
      ans = Math.max(ans, r - l + 1);
  }
  return ans;

  Invariant: after the while loop, [l, r] is always valid.

----------------------------------------------------------------
TEMPLATE (SHORTEST VALID)
----------------------------------------------------------------

  int l = 0, ans = Integer.MAX_VALUE;

  for (int r = 0; r < n; r++) {
      addToWindow(arr[r]);

      // Shrink AS LONG AS window remains valid
      while (windowIsValid()) {
          ans = Math.min(ans, r - l + 1);  // update inside while
          removeFromWindow(arr[l]);
          l++;
      }
  }
  return ans == Integer.MAX_VALUE ? 0 : ans;

  Key difference: update answer INSIDE the while loop,
  since we want the smallest valid window.

----------------------------------------------------------------
LONGEST vs SHORTEST -- TEMPLATE DIFFERENCE
----------------------------------------------------------------

  LONGEST:
    - while (INVALID) shrink
    - update AFTER while (window is valid)
    - ans = max(ans, r - l + 1)

  SHORTEST:
    - while (VALID) update + shrink
    - update INSIDE while (while window is still valid)
    - ans = min(ans, r - l + 1) inside while

----------------------------------------------------------------
PROBLEM 1: LONGEST SUBARRAY WITH SUM <= K
----------------------------------------------------------------

  Java:
    public int longestSubarraySum(int[] nums, int k) {
        int l = 0, sum = 0, ans = 0;
        for (int r = 0; r < nums.length; r++) {
            sum += nums[r];
            while (sum > k) {
                sum -= nums[l++];
            }
            ans = Math.max(ans, r - l + 1);
        }
        return ans;
    }

----------------------------------------------------------------
PROBLEM 2: MINIMUM SIZE SUBARRAY SUM (LC 209)
----------------------------------------------------------------

  Find the minimum length subarray with sum >= target.

  Java:
    public int minSubArrayLen(int target, int[] nums) {
        int l = 0, sum = 0, ans = Integer.MAX_VALUE;
        for (int r = 0; r < nums.length; r++) {
            sum += nums[r];
            while (sum >= target) {
                ans = Math.min(ans, r - l + 1);
                sum -= nums[l++];
            }
        }
        return ans == Integer.MAX_VALUE ? 0 : ans;
    }

  Time: O(n)  Space: O(1)

  Trace:
    nums = [2,3,1,2,4,3], target = 7
    r=0: sum=2. Not >= 7.
    r=1: sum=5. Not >= 7.
    r=2: sum=6. Not >= 7.
    r=3: sum=8 >= 7. ans=4. remove 2, sum=6, l=1. Not >= 7 now.
    r=4: sum=10 >= 7. ans=4. remove 3, sum=7, l=2. ans=3. remove 1, sum=6, l=3. stop.
    r=5: sum=9 >= 7. ans=3. remove 2, sum=7, l=4. ans=2. remove 4, sum=3, l=5. stop.
    Answer = 2 ([4,3]).

----------------------------------------------------------------
PROBLEM 3: LONGEST SUBSTRING WITH AT MOST K DISTINCT CHARACTERS
----------------------------------------------------------------

  Track frequency of each character in window.
  Shrink when distinct count > k.

  Java:
    public int lengthOfLongestSubstringKDistinct(String s, int k) {
        Map<Character, Integer> freq = new HashMap<>();
        int l = 0, ans = 0;
        for (int r = 0; r < s.length(); r++) {
            char rc = s.charAt(r);
            freq.merge(rc, 1, Integer::sum);

            while (freq.size() > k) {
                char lc = s.charAt(l);
                freq.merge(lc, -1, Integer::sum);
                if (freq.get(lc) == 0) freq.remove(lc);
                l++;
            }
            ans = Math.max(ans, r - l + 1);
        }
        return ans;
    }

  Time: O(n)  Space: O(k)

----------------------------------------------------------------
PROBLEM 4: FRUITS INTO BASKETS (LC 904) -- At Most 2 Distinct
----------------------------------------------------------------

  Special case of "at most k distinct" with k=2.
  Same template.

  Java:
    public int totalFruit(int[] fruits) {
        Map<Integer, Integer> basket = new HashMap<>();
        int l = 0, ans = 0;
        for (int r = 0; r < fruits.length; r++) {
            basket.merge(fruits[r], 1, Integer::sum);
            while (basket.size() > 2) {
                int lf = fruits[l];
                basket.merge(lf, -1, Integer::sum);
                if (basket.get(lf) == 0) basket.remove(lf);
                l++;
            }
            ans = Math.max(ans, r - l + 1);
        }
        return ans;
    }

  Time: O(n)  Space: O(1) -- at most 3 entries in map

----------------------------------------------------------------
PROBLEM 5: SUBARRAYS WITH K DIFFERENT INTEGERS (LC 992)
----------------------------------------------------------------

  Count subarrays with EXACTLY k distinct integers.
  Use the trick: exactly(k) = atMost(k) - atMost(k-1)

  Java:
    public int subarraysWithKDistinct(int[] nums, int k) {
        return atMost(nums, k) - atMost(nums, k - 1);
    }

    private int atMost(int[] nums, int k) {
        Map<Integer, Integer> freq = new HashMap<>();
        int l = 0, count = 0;
        for (int r = 0; r < nums.length; r++) {
            freq.merge(nums[r], 1, Integer::sum);
            while (freq.size() > k) {
                int lv = nums[l];
                freq.merge(lv, -1, Integer::sum);
                if (freq.get(lv) == 0) freq.remove(lv);
                l++;
            }
            count += r - l + 1;  // all windows ending at r with at most k distinct
        }
        return count;
    }

  Time: O(n)  Space: O(n)

  Why count += r - l + 1?
    For each r, all sub-windows [l,r], [l+1,r], ..., [r,r] are valid.
    That's (r - l + 1) valid subarrays ending at r.

----------------------------------------------------------------
VALIDITY CONDITIONS CHEATSHEET
----------------------------------------------------------------

  Problem type                  Validity condition       Shrink when
  ------------                  ------------------       -----------
  Sum <= k                      sum <= k                 sum > k
  Sum >= k (shortest)           sum >= k                 window is valid
  At most k distinct chars      freq.size() <= k         freq.size() > k
  No repeating chars            max freq == 1            any freq > 1
  All chars in pattern present  formed == required       window is valid (shrink for shortest)

----------------------------------------------------------------
COMMON MISTAKES
----------------------------------------------------------------

  1. Updating answer before shrinking for LONGEST window:
     Must shrink FIRST to ensure validity, THEN update.

  2. Updating answer after shrinking for SHORTEST window:
     Must update WHILE window is valid (inside while), not after.

  3. Forgetting to remove key from HashMap when count reaches 0:
     map.get(key) == 0 --> map.remove(key) to keep size() correct.

  4. Using l < r instead of l <= r for the shrink condition:
     The window can become size 1 (l == r) and still be invalid.

  5. Not initializing ans = Integer.MAX_VALUE for "minimum" problems:
     Checking ans == Integer.MAX_VALUE at end means no valid window found.

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: When should I use while vs if for shrinking?
  A: Always use while. A single removal might not restore validity.
     Multiple elements may need to be removed before the window
     becomes valid again.

  Q: Can the window ever be size 0 (l > r)?
  A: No. When l == r (size 1), if still invalid, we'd do l++, making
     l > r. But then r++ immediately after restores r >= l. This means
     we might "miss" counting a window of size 0, but that's fine.

  Q: Why does count += r - l + 1 count all valid subarrays?
  A: For each r, the valid windows are those starting from any index
     in [l, r]. There are (r - l + 1) such windows. Summing over all
     r gives the total valid subarray count.

  Q: What's the difference between "at most k" and "exactly k"?
  A: "Exactly k" is harder to maintain directly. The trick
     exactly(k) = atMost(k) - atMost(k-1) avoids complex state management.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------

  - Always state the validity condition before coding.
  - Draw the window bounds: "[l=X, r=Y] contains Z distinct chars".
  - Explain the while loop: "We shrink while the window violates
    the constraint, removing the leftmost element each time."
  - For "count" problems, explain the +=(r-l+1) logic.
  - Mention that each element enters the window once and leaves once,
    giving O(n) total time.
