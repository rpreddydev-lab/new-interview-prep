================================================================
  SLIDING WINDOW WITH HASHMAP
  (Frequency-Based Window Problems)
================================================================

When the window state requires tracking CHARACTER FREQUENCIES
or ELEMENT COUNTS, use a HashMap (or array) as the window store.
This is the go-to approach for "how many distinct", "all chars
present", and "at most k of type X" window problems.

----------------------------------------------------------------
CORE WINDOW STATE PATTERN
----------------------------------------------------------------

  Map<Character, Integer> window = new HashMap<>();
  // OR int[] window = new int[26]; for lowercase letters

  // Add element to window:
  window.merge(c, 1, Integer::sum);   // window[c]++

  // Remove element from window:
  window.merge(c, -1, Integer::sum);
  if (window.get(c) == 0) window.remove(c);  // clean up 0-counts

  // Check distinct count:
  window.size()   // size() counts only keys with count > 0

  // Check if a char is satisfied (matches target):
  window.get(c) >= need.get(c)   // for minimum window substring

----------------------------------------------------------------
PROBLEM 1: LONGEST SUBSTRING WITH AT MOST 2 DISTINCT (LC 159)
----------------------------------------------------------------

  Java:
    public int lengthOfLongestSubstringTwoDistinct(String s) {
        Map<Character, Integer> window = new HashMap<>();
        int l = 0, ans = 0;

        for (int r = 0; r < s.length(); r++) {
            char rc = s.charAt(r);
            window.merge(rc, 1, Integer::sum);

            while (window.size() > 2) {
                char lc = s.charAt(l);
                window.merge(lc, -1, Integer::sum);
                if (window.get(lc) == 0) window.remove(lc);
                l++;
            }
            ans = Math.max(ans, r - l + 1);
        }
        return ans;
    }

  Time: O(n)  Space: O(1) -- at most 3 entries in map

----------------------------------------------------------------
PROBLEM 2: LONGEST SUBSTRING WITH AT MOST K DISTINCT (LC 340)
----------------------------------------------------------------

  Same pattern with variable k.

  Java:
    public int lengthOfLongestSubstringKDistinct(String s, int k) {
        Map<Character, Integer> window = new HashMap<>();
        int l = 0, ans = 0;

        for (int r = 0; r < s.length(); r++) {
            char rc = s.charAt(r);
            window.merge(rc, 1, Integer::sum);

            while (window.size() > k) {
                char lc = s.charAt(l);
                window.merge(lc, -1, Integer::sum);
                if (window.get(lc) == 0) window.remove(lc);
                l++;
            }
            ans = Math.max(ans, r - l + 1);
        }
        return ans;
    }

  Note: k=1 gives "longest substring with one distinct char".
  k=0 gives 0 (no window can have 0 distinct chars with elements).

----------------------------------------------------------------
PROBLEM 3: MAXIMUM NUMBER OF VOWELS IN WINDOW OF SIZE K (LC 1456)
----------------------------------------------------------------

  Fixed window. Check if char is a vowel.

  Java:
    public int maxVowels(String s, int k) {
        Set<Character> vowels = Set.of('a','e','i','o','u');
        int count = 0;
        for (int i = 0; i < k; i++)
            if (vowels.contains(s.charAt(i))) count++;
        int max = count;

        for (int i = k; i < s.length(); i++) {
            if (vowels.contains(s.charAt(i))) count++;
            if (vowels.contains(s.charAt(i - k))) count--;
            max = Math.max(max, count);
        }
        return max;
    }

  Time: O(n)  Space: O(1)

PROBLEM 4: COUNT SUBARRAYS WHERE MAX ELEMENT >= k TIMES (LC 2962)
----------------------------------------------------------------

  Count subarrays where the maximum element appears at least k times.
  Use sliding window: find smallest right boundary for each l.

  Key insight: Count using "at least k times" = n*(n+1)/2 - "less than k"
  OR: count valid windows directly.

  Java (count windows where max appears >= k times):
    public long countSubarrays(int[] nums, int k) {
        int maxVal = 0;
        for (int n : nums) maxVal = Math.max(maxVal, n);

        long count = 0;
        int l = 0, freq = 0;
        for (int r = 0; r < nums.length; r++) {
            if (nums[r] == maxVal) freq++;
            while (freq >= k) {
                count += nums.length - r;  // all extensions of this window to right are valid
                if (nums[l] == maxVal) freq--;
                l++;
            }
        }
        return count;
    }

  Time: O(n)  Space: O(1)

----------------------------------------------------------------
PROBLEM 5: LONGEST REPEATING CHARACTER REPLACEMENT (LC 424)
----------------------------------------------------------------

  Replace at most k characters to make longest substring with all
  same characters.

  Key insight: In a window of size (r-l+1), the minimum replacements
  needed = (window_size - count_of_most_frequent_char).
  Window is valid if this count <= k.

  Java:
    public int characterReplacement(String s, int k) {
        int[] freq = new int[26];
        int l = 0, maxFreq = 0, ans = 0;

        for (int r = 0; r < s.length(); r++) {
            freq[s.charAt(r) - 'A']++;
            maxFreq = Math.max(maxFreq, freq[s.charAt(r) - 'A']);

            // Window invalid if replacements needed > k
            while ((r - l + 1) - maxFreq > k) {
                freq[s.charAt(l) - 'A']--;
                l++;
                // Note: maxFreq might be stale (we don't decrease it)
                // But that's ok -- maxFreq only grows (we seek larger windows)
            }
            ans = Math.max(ans, r - l + 1);
        }
        return ans;
    }

  Time: O(n)  Space: O(26) = O(1)

  Key optimization: maxFreq is never decreased during shrinking.
  This is correct because: we only care about windows LARGER than
  the current best. If window shrinks, the answer doesn't change.

----------------------------------------------------------------
PROBLEM 6: MINIMUM OPERATIONS TO REDUCE X TO ZERO (LC 1658)
----------------------------------------------------------------

  Remove elements from left or right until sum of removed = x.
  Minimize total removed elements.

  Transform: removing from ends = finding longest middle subarray
  with sum = total - x.

  Java:
    public int minOperations(int[] nums, int x) {
        int target = -x;
        for (int n : nums) target += n;  // target = totalSum - x

        if (target < 0) return -1;
        if (target == 0) return nums.length;

        int l = 0, sum = 0, maxLen = -1;
        for (int r = 0; r < nums.length; r++) {
            sum += nums[r];
            while (sum > target) {
                sum -= nums[l++];
            }
            if (sum == target) maxLen = Math.max(maxLen, r - l + 1);
        }
        return maxLen == -1 ? -1 : nums.length - maxLen;
    }

  Time: O(n)  Space: O(1)

----------------------------------------------------------------
WINDOW STATE CHEATSHEET
----------------------------------------------------------------

  State needed              Data structure      Operation
  ------------              --------------      ---------
  Character frequency       int[26] or HashMap  [c]++ / [c]--
  Distinct count            HashMap size()      merge + remove at 0
  Any duplicates present    Set or freq array   size() or count > 1
  Running sum               int sum             sum += / -=
  Max in window (all time)  int maxFreq         only grows, no decrease
  Sorted window (for range) TreeMap             put/remove O(log k)

----------------------------------------------------------------
COMMON MISTAKES
----------------------------------------------------------------

  1. Not removing zero-count keys from HashMap:
     window.size() counts ALL keys including those with count 0.
     Always remove keys when their count reaches 0.

  2. In LC 424: trying to decrease maxFreq during shrink:
     It's not necessary and incorrect. maxFreq tracks the
     maximum frequency seen SO FAR (historical maximum).

  3. Confusion between distinct count and frequency count:
     distinct = how many DIFFERENT characters (window.size())
     frequency = how many times a specific char appears (window.get(c))

  4. Using HashMap when int[26] suffices:
     For lowercase English letters, int[26] is 10x faster
     and O(1) guaranteed.

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: When do you use HashMap vs int[] for the window?
  A: int[] for lowercase letters (26 chars), digits (10), or
     ASCII (128). HashMap for arbitrary keys, or when input
     range is unknown.

  Q: In LC 424, why does maxFreq not need to decrease?
  A: We seek longer windows. If we shrink, we're just maintaining
     the same window size as before, not improving. maxFreq captures
     the historical maximum, letting us find the first window that
     CAN be larger.

  Q: How do you count subarrays with EXACTLY k distinct?
  A: Use atMost(k) - atMost(k-1). This converts the "exactly"
     constraint into two "at most" problems which are easier
     to maintain.

  Q: What if the problem is about integers in a range, not chars?
  A: Use a HashMap<Integer, Integer> for frequency tracking.
     The window logic is identical.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------

  - Always state what your window tracks and what "valid" means.
  - For HashMap windows, show the cleanup: "I remove keys with
    count 0 so that size() accurately reflects distinct count."
  - LC 424 is a popular hard follow-up -- know the maxFreq trick.
  - Practice converting "exactly k" to "atMost(k) - atMost(k-1)".
