================================================================
  MINIMUM WINDOW SUBSTRING (LC 76)
  Deep Dive -- Hard Level
================================================================

Find the smallest window in s that contains ALL characters
of t (including duplicates). A classic "shrink when valid"
sliding window problem.

----------------------------------------------------------------
PROBLEM STATEMENT
----------------------------------------------------------------

  Given strings s and t, return the minimum window substring
  of s such that every character in t (including duplicates)
  is included in the window. If no window exists, return "".

  Input:  s = "ADOBECODEBANC", t = "ABC"
  Output: "BANC"

  Input:  s = "a", t = "a"
  Output: "a"

  Input:  s = "a", t = "aa"
  Output: "" (s doesn't contain two 'a's)

  Constraints: t can have duplicate characters.

----------------------------------------------------------------
KEY INSIGHT
----------------------------------------------------------------

  We need a window that "has" all characters of t.
  "Has" means: for every char c in t, freq_in_window[c] >= freq_in_t[c].

  Strategy:
    - "formed" counter tracks how many distinct chars in t are
      SATISFIED (window freq >= t freq).
    - "required" = number of distinct chars in t.
    - Window is valid when formed == required.

  Algorithm:
    Expand r until window is valid (formed == required).
    Then shrink l while window stays valid, recording minimum.
    Repeat.

----------------------------------------------------------------
JAVA CODE
----------------------------------------------------------------

  public String minWindow(String s, String t) {
      if (s.isEmpty() || t.isEmpty()) return "";

      // Count characters needed
      Map<Character, Integer> need = new HashMap<>();
      for (char c : t.toCharArray())
          need.merge(c, 1, Integer::sum);

      int required = need.size();  // distinct chars we must satisfy
      int formed = 0;              // distinct chars currently satisfied

      Map<Character, Integer> window = new HashMap<>();
      int l = 0;
      int minLen = Integer.MAX_VALUE;
      int minL = 0;

      for (int r = 0; r < s.length(); r++) {
          // Expand: add s[r] to window
          char rc = s.charAt(r);
          window.merge(rc, 1, Integer::sum);
          if (need.containsKey(rc) && window.get(rc).equals(need.get(rc))) {
              formed++;
          }

          // Shrink: while window is valid, try to minimize
          while (formed == required) {
              // Update answer
              if (r - l + 1 < minLen) {
                  minLen = r - l + 1;
                  minL = l;
              }
              // Remove s[l] from window
              char lc = s.charAt(l);
              window.merge(lc, -1, Integer::sum);
              if (need.containsKey(lc) && window.get(lc) < need.get(lc)) {
                  formed--;
              }
              l++;
          }
      }

      return minLen == Integer.MAX_VALUE ? "" : s.substring(minL, minL + minLen);
  }

  Time:  O(|s| + |t|)  -- each char enters and leaves window once
  Space: O(|s| + |t|)  -- for the hashmaps

----------------------------------------------------------------
OPTIMIZATION: FILTERED STRING
----------------------------------------------------------------

  If |t| is small but |s| is very large, filter s to only
  characters that appear in t. Reduces iterations significantly.

  Java (filtered):
    // Preprocess: only keep chars that are in t
    List<int[]> filtered = new ArrayList<>();  // [index, char]
    for (int i = 0; i < s.length(); i++) {
        if (need.containsKey(s.charAt(i)))
            filtered.add(new int[]{i, s.charAt(i)});
    }
    // Then run sliding window on filtered list
    // Substring is still extracted from original s using stored indices

  When useful: |s| = 10^6, |t| = 3. Filtered list is much smaller.

----------------------------------------------------------------
COMMON MISTAKES
----------------------------------------------------------------

  1. Using == instead of .equals() for Integer comparison:
     `window.get(rc) == need.get(rc)` fails for Integer values > 127
     due to auto-boxing. Always use .equals() for Integer objects.

  2. Not checking if char is in `need` before updating `formed`:
     Characters not in t should not affect formed.

  3. Updating minLen INSIDE shrink loop AFTER removing (should
     update BEFORE removing):
     Update ans first, then remove s[l] and increment l.

  4. Forgetting to initialize minL = 0:
     Return "" when no window found (check minLen == Integer.MAX_VALUE).

  5. The `formed` counter: increment only when window[c] == need[c]
     (goes from "not satisfied" to "satisfied"). Not on every add.

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: Why do we use a "formed" counter instead of comparing maps?
  A: Comparing maps is O(|need|) per step. "formed" is O(1) per step.
     We increment formed only when a character transitions from
     insufficient to sufficient count.

  Q: What if t has duplicate characters like "AAB"?
  A: The need map tracks {A:2, B:1}. formed only increments for A
     when window[A] reaches 2, and for B when window[B] reaches 1.
     This correctly handles duplicates.

  Q: How does the shrink correctly stop?
  A: When we remove s[l] and window[c] drops below need[c], formed
     decrements. The while condition (formed == required) fails, so
     we stop shrinking.

  Q: Can window characters not in t affect the result?
  A: They stay in the window map but don't affect `formed`. They do
     contribute to the window size, which is why we want to shrink
     them away to minimize the window.

  Q: What's the time complexity?
  A: O(|s| + |t|). Each character of s is added to window once (r++)
     and removed at most once (l++). Building the need map is O(|t|).

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------

  - Explain the "formed" and "required" counters before coding.
  - Trace through "ADOBECODEBANC" / "ABC" -- interviewers expect this.
  - Emphasize when you update the answer (before removing s[l]).
  - Note the .equals() vs == gotcha for Integer objects.
  - For the follow-up "find all minimum windows" -- collect all
    windows with length == minLen.
