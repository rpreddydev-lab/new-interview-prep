================================================================
  FIXED SIZE SLIDING WINDOW
================================================================

The window size k is given explicitly. Slide the window by 1
each step, adding the rightmost element and removing the leftmost.

----------------------------------------------------------------
CORE TEMPLATE
----------------------------------------------------------------

  // Initialize first window
  int windowVal = initial_value;
  for (int i = 0; i < k; i++) {
      windowVal = update(windowVal, nums[i]);
  }
  int ans = windowVal;

  // Slide the window
  for (int i = k; i < n; i++) {
      windowVal = add(windowVal, nums[i]);       // right element enters
      windowVal = remove(windowVal, nums[i-k]);  // left element leaves
      ans = best(ans, windowVal);
  }

  Key: outgoing element = nums[i - k]

----------------------------------------------------------------
PROBLEM 1: MAXIMUM SUM SUBARRAY OF SIZE K
----------------------------------------------------------------

  Input:  nums = [2, 1, 5, 1, 3, 2], k = 3
  Output: 9 (subarray [5, 1, 3])

  Java:
    public int maxSumSubarray(int[] nums, int k) {
        int n = nums.length;
        int windowSum = 0;
        for (int i = 0; i < k; i++) windowSum += nums[i];
        int maxSum = windowSum;

        for (int i = k; i < n; i++) {
            windowSum += nums[i] - nums[i - k];
            maxSum = Math.max(maxSum, windowSum);
        }
        return maxSum;
    }

  Trace:
    Window [2,1,5] sum=8. Slide: +1-2=7. Slide: +3-1=9. Slide: +2-5=6.
    Max = 9.

  Time: O(n)  Space: O(1)

----------------------------------------------------------------
PROBLEM 2: MAXIMUM AVERAGE SUBARRAY I (LC 643)
----------------------------------------------------------------

  Same as max sum -- divide by k at the end.

  Java:
    public double findMaxAverage(int[] nums, int k) {
        double sum = 0;
        for (int i = 0; i < k; i++) sum += nums[i];
        double maxAvg = sum / k;
        for (int i = k; i < nums.length; i++) {
            sum += nums[i] - nums[i - k];
            maxAvg = Math.max(maxAvg, sum / k);
        }
        return maxAvg;
    }

  Time: O(n)  Space: O(1)

PROBLEM 3: FIND ALL ANAGRAMS IN A STRING (LC 438)
----------------------------------------------------------------

  Find all starting indices where a substring of s is an anagram of p.
  Window size = p.length().

  Approach:
    - Track frequency difference between window and pattern.
    - "formed" counter = number of chars whose frequency in window
      matches p's frequency.
    - When formed == p's distinct chars count, we have an anagram.

  Java:
    public List<Integer> findAnagrams(String s, String p) {
        List<Integer> result = new ArrayList<>();
        if (s.length() < p.length()) return result;

        int[] pCount = new int[26];
        int[] wCount = new int[26];
        for (char c : p.toCharArray()) pCount[c - 'a']++;

        int k = p.length();
        // Initialize first window
        for (int i = 0; i < k; i++) wCount[s.charAt(i) - 'a']++;

        if (Arrays.equals(pCount, wCount)) result.add(0);

        for (int i = k; i < s.length(); i++) {
            wCount[s.charAt(i) - 'a']++;           // add right
            wCount[s.charAt(i - k) - 'a']--;       // remove left
            if (Arrays.equals(pCount, wCount)) result.add(i - k + 1);
        }
        return result;
    }

  Time: O(n * 26) = O(n)  Space: O(26) = O(1)

  Optimization with "formed" counter (avoids O(26) comparison each step):
    public List<Integer> findAnagrams(String s, String p) {
        List<Integer> result = new ArrayList<>();
        int[] need = new int[26], have = new int[26];
        for (char c : p.toCharArray()) need[c - 'a']++;

        int k = p.length(), formed = 0;
        int required = 0;
        for (int i = 0; i < 26; i++) if (need[i] > 0) required++;

        int l = 0;
        for (int r = 0; r < s.length(); r++) {
            int rc = s.charAt(r) - 'a';
            have[rc]++;
            if (have[rc] == need[rc]) formed++;

            if (r - l + 1 == k) {
                if (formed == required) result.add(l);
                int lc = s.charAt(l) - 'a';
                if (have[lc] == need[lc]) formed--;
                have[lc]--;
                l++;
            }
        }
        return result;
    }

  Time: O(n)  Space: O(1)

PROBLEM 4: PERMUTATION IN STRING (LC 567)
----------------------------------------------------------------

  Return true if s2 contains a permutation of s1 as a substring.
  Same as find anagrams -- return true if result is non-empty.

  Java:
    public boolean checkInclusion(String s1, String s2) {
        if (s2.length() < s1.length()) return false;
        int[] need = new int[26], have = new int[26];
        for (char c : s1.toCharArray()) need[c - 'a']++;

        int k = s1.length();
        for (int i = 0; i < k; i++) have[s2.charAt(i) - 'a']++;
        if (Arrays.equals(need, have)) return true;

        for (int i = k; i < s2.length(); i++) {
            have[s2.charAt(i) - 'a']++;
            have[s2.charAt(i - k) - 'a']--;
            if (Arrays.equals(need, have)) return true;
        }
        return false;
    }

  Time: O(n * 26) = O(n)  Space: O(1)

----------------------------------------------------------------
PROBLEM 5: CONTAINS DUPLICATE WITHIN K DISTANCE (LC 219)
----------------------------------------------------------------

  Return true if any two equal nums are at most k indices apart.
  Window of size k+1, check for duplicates within it.

  Java:
    public boolean containsNearbyDuplicate(int[] nums, int k) {
        Set<Integer> window = new HashSet<>();
        for (int i = 0; i < nums.length; i++) {
            if (window.contains(nums[i])) return true;
            window.add(nums[i]);
            if (window.size() > k) window.remove(nums[i - k]);
        }
        return false;
    }

  Time: O(n)  Space: O(k)

----------------------------------------------------------------
FIXED WINDOW PATTERNS SUMMARY
----------------------------------------------------------------

  Goal                     Window State      Complexity
  ----                     ------------      ----------
  Max/min sum of size k    int sum           O(n) O(1)
  Average of size k        double sum        O(n) O(1)
  Find anagram positions   int[26] freq      O(n) O(1)
  Check permutation exists int[26] freq      O(n) O(1)
  Duplicate within k dist  HashSet           O(n) O(k)

----------------------------------------------------------------
COMMON MISTAKES
----------------------------------------------------------------

  1. Off-by-one in the initial window setup:
     Loop from 0 to k-1 (inclusive), then slide from k to n-1.

  2. Array comparison O(26) each step:
     Use a "formed" counter to check validity in O(1) per step.

  3. Forgetting to handle edge case s.length() < k:
     Return early if input is smaller than window.

  4. Not resetting window state for each new window start:
     With sliding window, you update incrementally -- no reset needed.

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: What's the time complexity for find all anagrams?
  A: O(n) -- each character is added once (r++) and removed once
     (when the window slides past it). The freq comparison is O(26)
     per step which is O(1). Total O(n).

  Q: Can we use sorting instead of frequency arrays for anagram check?
  A: Sorting the window each step is O(k log k) per position =
     O(nk log k) total. Much worse. Frequency arrays are O(1) check
     after O(1) update.

  Q: What if the window needs to maintain a sorted order?
  A: Use a TreeMap (sorted). Adding/removing is O(log k) per step.
     Total O(n log k). Needed for problems like LC 220 (contains
     duplicate III with value range constraint).

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------

  - Initialize the first window separately, then slide from index k.
  - For string anagram problems, draw two frequency arrays and show
    how they change as the window slides.
  - Mention that the "formed" counter optimization avoids O(26)
    comparison to make it truly O(1) per step.
  - For max/min, just maintain a running sum -- no need for deque
    unless you need sliding window max/min (different problem).
