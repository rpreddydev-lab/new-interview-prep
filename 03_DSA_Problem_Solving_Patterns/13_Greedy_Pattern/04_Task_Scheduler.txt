================================================================
  TASK SCHEDULER (LC 621) AND CPU SCHEDULING
================================================================

  LC 621: Given tasks (letters, can repeat), and cooldown n.
          Same task must be n intervals apart.
          Find minimum intervals (including idle) to finish all tasks.

  Input:  tasks=["A","A","A","B","B","B"], n=2
  Output: 8

----------------------------------------------------------------
GREEDY INSIGHT
----------------------------------------------------------------

  Most frequent task determines the "framework" of the schedule.
  Let maxCount = frequency of most common task.
  There are (maxCount - 1) blocks of size (n + 1) = the "frames."
  Last block may be partial (just the maxCount-frequency tasks).

  Formula:
    partitions = maxCount - 1
    slots = partitions * (n + 1)  // n+1 because task + n idle slots
    result = max(tasks.length, slots + countOfMaxFrequency)

  Where countOfMaxFrequency = number of tasks with the max frequency.

  Java:
    public int leastInterval(char[] tasks, int n) {
        int[] freq = new int[26];
        for (char t : tasks) freq[t - 'A']++;
        int maxCount = 0;
        for (int f : freq) maxCount = Math.max(maxCount, f);

        int countOfMax = 0;
        for (int f : freq) if (f == maxCount) countOfMax++;

        int result = (maxCount - 1) * (n + 1) + countOfMax;
        return Math.max(result, tasks.length);
    }

  Time: O(n)   Space: O(1) (26 letter array)

----------------------------------------------------------------
TRACED EXAMPLE: tasks=["A","A","A","B","B","B"], n=2
----------------------------------------------------------------

  freq: A=3, B=3.
  maxCount = 3.
  countOfMax = 2 (both A and B appear 3 times).

  Framework:
    [ A B _ | A B _ | A B ]   (n+1=3 slots per frame, 2 frames, last partial)
     frame1   frame2  last

  slots = (3-1) * (2+1) = 6
  result = max(6, 6 + 2) = max(6, 8) = 8 ✓

  If tasks = ["A","A","A","B","B","B","C","C","C","D","D","E"]:
    Each task has enough variety to fill idle slots.
    tasks.length = 12 > formula result. Return tasks.length.

----------------------------------------------------------------
WHY `max(tasks.length, formula)`?
----------------------------------------------------------------

  If there are many distinct tasks and they fill all idle slots:
    Example: n=1, tasks = [A,A,B,B,C,C,D,D]: ABCDABCD needs 8 slots, no idle.
    Formula: (2-1)*(1+1)+4 = 6. But tasks.length=8 > 6.
    Return max(8,6) = 8 ✓

  The formula gives the minimum if idle slots are needed.
  If no idle slots needed, just run all tasks back-to-back: tasks.length.

----------------------------------------------------------------
SIMULATION APPROACH (ALTERNATIVE)
----------------------------------------------------------------

  Max-heap + queue simulation. Always execute the most frequent available task.
  If none available, idle.

  Java:
    public int leastInterval(char[] tasks, int n) {
        int[] freq = new int[26];
        for (char t : tasks) freq[t - 'A']++;
        PriorityQueue<Integer> heap = new PriorityQueue<>(Collections.reverseOrder());
        for (int f : freq) if (f > 0) heap.offer(f);

        int time = 0;
        Queue<int[]> cooldown = new LinkedList<>();  // [freq, available_at]

        while (!heap.isEmpty() || !cooldown.isEmpty()) {
            // Release tasks from cooldown
            if (!cooldown.isEmpty() && cooldown.peek()[1] <= time) {
                heap.offer(cooldown.poll()[0]);
            }
            if (!heap.isEmpty()) {
                int f = heap.poll() - 1;
                if (f > 0) cooldown.offer(new int[]{f, time + n + 1});
            }
            // else: idle
            time++;
        }
        return time;
    }

  Time: O(n * k) where k=tasks, less efficient but intuitive.
  Good to mention as alternative; formula solution is O(n) and preferred.

----------------------------------------------------------------
RELATED: REORGANIZE STRING (LC 767)
----------------------------------------------------------------

  Arrange string so no two adjacent chars are the same.
  Return empty string if impossible.

  Max-heap, interleave most frequent character.
  If most frequent char count > (n+1)/2 → impossible.

  Java:
    public String reorganizeString(String s) {
        int[] freq = new int[26];
        for (char c : s) freq[c - 'a']++;
        PriorityQueue<int[]> heap = new PriorityQueue<>((a, b) -> b[1] - a[1]);
        for (int i = 0; i < 26; i++) if (freq[i] > 0) heap.offer(new int[]{i, freq[i]});

        StringBuilder sb = new StringBuilder();
        while (heap.size() >= 2) {
            int[] first = heap.poll(), second = heap.poll();
            sb.append((char)('a' + first[0]));
            sb.append((char)('a' + second[0]));
            if (--first[1] > 0) heap.offer(first);
            if (--second[1] > 0) heap.offer(second);
        }
        if (!heap.isEmpty()) {
            int[] last = heap.poll();
            if (last[1] > 1) return "";
            sb.append((char)('a' + last[0]));
        }
        return sb.toString();
    }

  Check impossible: if any char frequency > (n+1)/2 return "".

----------------------------------------------------------------
RELATED: TASK SCHEDULER WITH FREQUENCIES (LC 358)
----------------------------------------------------------------

  LC 358: Rearrange string K distance apart (same char at least K apart).
  Same as Reorganize String but with K instead of 2.
  Heap + queue(size K): at each step, pick top from heap, push back to queue after K steps.

  Java:
    public String rearrangeString(String s, int k) {
        if (k == 0) return s;
        int[] freq = new int[26];
        for (char c : s) freq[c - 'a']++;
        PriorityQueue<int[]> heap = new PriorityQueue<>((a, b) -> b[1] - a[1]);
        for (int i = 0; i < 26; i++) if (freq[i] > 0) heap.offer(new int[]{i, freq[i]});

        StringBuilder sb = new StringBuilder();
        Queue<int[]> cooldown = new LinkedList<>();

        while (!heap.isEmpty()) {
            int[] curr = heap.poll();
            sb.append((char)('a' + curr[0]));
            curr[1]--;
            cooldown.offer(curr);
            if (cooldown.size() == k) {
                int[] front = cooldown.poll();
                if (front[1] > 0) heap.offer(front);
            }
        }
        return sb.length() == s.length() ? sb.toString() : "";
    }

----------------------------------------------------------------
COMMON MISTAKES
----------------------------------------------------------------

  1. Task Scheduler formula: forgetting to compare with tasks.length.
     When tasks are diverse enough, no idle needed → tasks.length is the answer.

  2. countOfMax: counting tasks with EXACT max frequency, not just any high frequency.

  3. Simulation: not properly releasing tasks from cooldown queue at the right time.

  4. Reorganize String: not checking impossibility (max_freq > (n+1)/2).

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: Why is the formula max(tasks.length, (maxCount-1)*(n+1)+countOfMax)?
  A: (maxCount-1)*(n+1)+countOfMax = minimum time if idle is needed.
     tasks.length = time if no idle needed (tasks fill all slots).
     Take max because answer is never less than total task count.

  Q: When is idle never needed?
  A: When the variety of tasks is high enough that no cooldown slot goes unfilled.
     This happens when total tasks >= (maxCount-1)*(n+1)+countOfMax.

  Q: How do you determine if Reorganize String is impossible?
  A: If any character appears more than ceil(n/2) times, you can't space them out.
     Check: max_freq > (n+1)/2.

  Q: Is the formula approach or simulation approach better in interviews?
  A: Formula is O(n) and elegant — use it if you can prove/explain it.
     Simulation is easier to arrive at (follows intuitively) — use as fallback.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------

  - Draw the frame diagram: [ A _ _ | A _ _ | A ] to show why (maxCount-1)*(n+1)+countOfMax.
  - Explain: "most frequent task determines the idle slots needed."
  - Mention the max with tasks.length — common oversight that fails edge cases.
  - For Reorganize String, the greedy invariant is: always pick the 2 most frequent chars next.
