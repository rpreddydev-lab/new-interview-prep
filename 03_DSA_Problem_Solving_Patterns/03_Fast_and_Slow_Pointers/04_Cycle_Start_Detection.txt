================================================================
  CYCLE START DETECTION (LC 142)
  Find Where a Linked List Cycle Begins
================================================================

----------------------------------------------------------------
PROBLEM STATEMENT
----------------------------------------------------------------

  Given a linked list with a cycle, return the node where
  the cycle begins (the entry node). If no cycle, return null.

  Input:  3 -> 2 -> 0 -> -4 -> (back to 2)
  Output: Node with value 2

  This is LC 142: Linked List Cycle II.

----------------------------------------------------------------
THE MATHEMATICAL INSIGHT
----------------------------------------------------------------

  Define:
    F = number of nodes BEFORE the cycle starts (the "tail")
    C = length of the cycle
    k = position where slow and fast first meet (inside cycle,
        measured from the cycle entry)

  Analysis:
    When slow has traveled F + k steps, fast has traveled 2(F + k) steps.
    Fast entered the cycle F steps in and has done at least one full cycle:
    2(F + k) = F + nC + k  for some integer n >= 1
    --> F + k = nC
    --> F = nC - k
    --> F = (n-1)C + (C - k)

  Reading the last equation:
    F = (n-1)C + (C - k)

  This means: starting from head, after F steps we reach the cycle entry.
  Starting from the meeting point (which is k steps into the cycle),
  after (C - k) more steps we also reach the cycle entry
  (since C - k steps from the meeting point = cycle entry).

  And (n-1)C accounts for extra laps which don't change the final position.

  CONCLUSION:
    If we put one pointer at HEAD and one at the MEETING POINT,
    and advance BOTH one step at a time, they meet at the CYCLE ENTRY.

----------------------------------------------------------------
ALGORITHM
----------------------------------------------------------------

  Phase 1: Detect cycle (fast & slow meet).
  Phase 2: Find cycle start (reset one pointer to head, advance both by 1).

  Java:
    public ListNode detectCycle(ListNode head) {
        // Phase 1: detect meeting point
        ListNode slow = head, fast = head;
        while (fast != null && fast.next != null) {
            slow = slow.next;
            fast = fast.next.next;
            if (slow == fast) break;  // found meeting point
        }

        // No cycle
        if (fast == null || fast.next == null) return null;

        // Phase 2: find cycle entry
        fast = head;  // reset fast to head
        while (slow != fast) {
            slow = slow.next;
            fast = fast.next;  // BOTH move 1 step now
        }
        return slow;  // or fast, same node
    }

  Time: O(n)  Space: O(1)

----------------------------------------------------------------
FULL TRACE THROUGH
----------------------------------------------------------------

  List: head -> A -> B -> C -> D -> E -> B (cycle entry = B)

  Let's label: head=0, A=1, B=2, C=3, D=4, E=5
  Cycle: B(2) -> C(3) -> D(4) -> E(5) -> B(2)
  F = 2 (nodes before cycle: head, A)
  C = 4 (cycle: B,C,D,E)

  PHASE 1: Detect meeting
    slow and fast both start at head (0).

    Step 1: slow=A(1), fast=C(3)
    Step 2: slow=B(2), fast=E(5)
    Step 3: slow=C(3), fast=C(3)  MEET at C(3)!

  Meeting point = C, which is position k=1 in the cycle from B.
  (B=0, C=1, D=2, E=3 in cycle offsets)

  Verify: F = nC - k = 1*4 - 1 = 3. But F should be 2...
  Hmm. Let me recount. head to B = 2 steps (head->A, A->B). F=2.
  When slow has traveled 3 steps (at C, position 1 in cycle):
    F + k = 3 = nC - 0? 3 = 4n? No.
  Let me re-derive:
    slow at step 3 = 3 total hops (head -> A -> B -> C). Position: C = k=1.
    fast at step 3 = 6 total hops. 6 mod (path length)?
    fast: head(0) -> A(1) -> B(2) -> C(3) -> D(4) -> E(5) -> B(2+6=? wait).
    Actually fast takes these nodes: head, skip-A, C, skip-D, B, skip-C, E.
    Let me re-trace:
    Step 1: slow=A, fast goes head->A->B = B.
    Step 2: slow=B, fast goes B->C->D = D.
    Step 3: slow=C, fast goes D->E->B = B. Not equal!
    Step 4: slow=D, fast goes B->C->D = D. MEET at D!

  Meeting point = D (position k=2 in cycle from B: B=0,C=1,D=2).
  slow distance = 4 (head->A->B->C->D).
  fast distance = 8 (=2*4).

  F + k = 4 = nC (with n=1): 4 = 1*4 = 4. ✓ (with F=2, k=2)
  F = nC - k = 4 - 2 = 2. ✓

  PHASE 2: Reset fast to head.
    fast=head, slow=D.
    Step 1: fast=A, slow=E.
    Step 2: fast=B, slow=B. MEET at B! ✓

  The cycle start is B (value 2) as expected.

----------------------------------------------------------------
SPECIAL CASE: CYCLE STARTS AT HEAD
----------------------------------------------------------------

  List: A -> B -> A (A is both head and cycle entry)
  F = 0, C = 2.

  Phase 1: fast/slow meet somewhere in cycle.
  Phase 2: reset fast to head = A.
    slow starts at meeting point.
    After F=0 steps, both are already at A.
    If slow == fast immediately: cycle entry = head. Return it.

  The algorithm handles this correctly: if F=0, the pointers
  meet immediately after reset.

----------------------------------------------------------------
EXTENSION: FIND DUPLICATE NUMBER (LC 287)
----------------------------------------------------------------

  Array contains n+1 integers in range [1, n].
  One number appears at least twice. Find it without modifying array.

  Insight: treat array as a function f(i) = nums[i].
  This creates a virtual linked list:
    0 -> nums[0] -> nums[nums[0]] -> ...

  The duplicate creates a cycle. The cycle entry = the duplicate.

  Java:
    public int findDuplicate(int[] nums) {
        int slow = nums[0], fast = nums[0];

        // Phase 1: find meeting point
        do {
            slow = nums[slow];
            fast = nums[nums[fast]];
        } while (slow != fast);

        // Phase 2: find cycle entry (= duplicate)
        fast = nums[0];
        while (slow != fast) {
            slow = nums[slow];
            fast = nums[fast];
        }
        return slow;
    }

  Time: O(n)  Space: O(1)

  Note: uses do-while to move BEFORE first comparison (since
  slow == fast initially at nums[0]).

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: Why does resetting one pointer to head and advancing both
     by 1 find the cycle start?
  A: Mathematical proof: if meeting point is k steps into the cycle,
     and F is the pre-cycle length, then F = nC - k. Starting from
     the meeting point and advancing F steps brings you to the cycle
     entry (F = nC-k = going C-k steps to complete the cycle, plus
     n-1 full cycles). Head is also F steps from the cycle entry.
     So both pointers converge to the cycle entry after F steps.

  Q: What if the cycle starts at head?
  A: F = 0. After the phase 1 meeting, both pointers are in the cycle.
     Resetting fast to head (= cycle entry) and slow stays somewhere
     in cycle. After 0 steps (F=0), they should immediately meet.
     But slow might not be at the entry yet. They will meet at the
     cycle entry since slow traverses C-k more steps = entry.

  Q: Does this handle cycles at the very first node?
  A: Yes. If head IS the cycle entry, fast (reset to head) and slow
     will both arrive at head in the same number of steps.

  Q: What's the difference between LC 141 and LC 142?
  A: LC 141: binary question (has cycle?). Return boolean.
     LC 142: return the actual node where cycle begins.
     LC 142 requires the phase 2 mathematical insight.
