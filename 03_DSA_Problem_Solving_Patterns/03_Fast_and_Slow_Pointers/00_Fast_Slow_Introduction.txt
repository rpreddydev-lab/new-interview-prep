================================================================
  FAST AND SLOW POINTERS -- INTRODUCTION
  (Floyd's Tortoise and Hare Algorithm)
================================================================

The Fast & Slow Pointer technique uses two pointers moving at
different speeds (usually 1 step vs 2 steps) through a sequence.
The key insight: if there is a cycle, the fast pointer will
eventually lap the slow pointer and they will meet.

----------------------------------------------------------------
WHEN TO USE FAST & SLOW POINTERS
----------------------------------------------------------------

  Signal words:
    - "Detect cycle in linked list"
    - "Find start of cycle"
    - "Find middle of linked list"
    - "Check if linked list is palindrome"
    - "Happy number" (any process with possible cycling)

  NOT suitable when:
    - Array/list has no cyclic structure
    - You need all elements (use BFS/DFS instead)
    - You need relative ordering of more than 2 elements

----------------------------------------------------------------
CORE MECHANICS
----------------------------------------------------------------

  Slow pointer: advances 1 step per iteration.
  Fast pointer: advances 2 steps per iteration.

  // Cycle detection:
  ListNode slow = head, fast = head;
  while (fast != null && fast.next != null) {
      slow = slow.next;
      fast = fast.next.next;
      if (slow == fast) {
          // Cycle detected!
      }
  }
  // If loop exits normally: fast hit null, no cycle.

----------------------------------------------------------------
WHY DO THEY MEET IF THERE IS A CYCLE?
----------------------------------------------------------------

  Suppose the cycle has length C.
  Once both pointers are inside the cycle, at each step:
    - fast moves 1 step closer to slow (gains 1 each iteration)
  So they meet after at most C steps.

  More precisely:
    - Let the pre-cycle length = F
    - Slow enters cycle at step F. At that point, fast is at
      position 2F, which is 2F mod C steps into the cycle.
    - Fast chases slow at net speed +1. They meet in C - (2F mod C) steps.

  The guarantee: if a cycle exists, they ALWAYS meet.

----------------------------------------------------------------
FOUR CLASSIC APPLICATIONS
----------------------------------------------------------------

  1. Cycle detection (does cycle exist?)
  2. Cycle start detection (where does the cycle begin?)
  3. Find middle of linked list
  4. Happy number (detect infinite loop)

----------------------------------------------------------------
VISUALIZATION -- CYCLE DETECTION
----------------------------------------------------------------

  List: 1 --> 2 --> 3 --> 4 --> 5 --> 3 (back to node 3)

  Step 0: slow=1, fast=1
  Step 1: slow=2, fast=3
  Step 2: slow=3, fast=5
  Step 3: slow=4, fast=4  <-- MEET! Cycle detected.

----------------------------------------------------------------
VISUALIZATION -- FIND MIDDLE
----------------------------------------------------------------

  List: 1 --> 2 --> 3 --> 4 --> 5 --> null

  Step 0: slow=1, fast=1
  Step 1: slow=2, fast=3
  Step 2: slow=3, fast=5
  Step 3: fast.next=null, stop. slow=3 is the MIDDLE.

  List: 1 --> 2 --> 3 --> 4 --> null (even length)

  Step 0: slow=1, fast=1
  Step 1: slow=2, fast=3
  Step 2: fast.next.next=null, stop. slow=2.
           slow=2 is the first of two midpoints.
           (For second midpoint, use slow.next = 3)

----------------------------------------------------------------
JAVA TEMPLATE -- CYCLE DETECTION (LC 141)
----------------------------------------------------------------

  public boolean hasCycle(ListNode head) {
      ListNode slow = head, fast = head;
      while (fast != null && fast.next != null) {
          slow = slow.next;
          fast = fast.next.next;
          if (slow == fast) return true;
      }
      return false;
  }

  Time: O(n)  Space: O(1)

  Why `fast.next != null`?
  Because we call fast.next.next. If fast.next is null,
  fast.next.next throws NullPointerException.

----------------------------------------------------------------
JAVA TEMPLATE -- FIND MIDDLE (LC 876)
----------------------------------------------------------------

  public ListNode middleNode(ListNode head) {
      ListNode slow = head, fast = head;
      while (fast != null && fast.next != null) {
          slow = slow.next;
          fast = fast.next.next;
      }
      return slow;
  }

  For ODD length (5 nodes): returns node 3 (exact middle).
  For EVEN length (4 nodes): returns node 3 (second of two midpoints).

  If you want the FIRST midpoint for even length:
    Use `while (fast.next != null && fast.next.next != null)`
    Returns node 2 for 4-node list.

----------------------------------------------------------------
COMPLEXITY
----------------------------------------------------------------

  Time:  O(n) -- slow pointer traverses at most n steps
  Space: O(1) -- only two pointer variables

  Compare to HashSet approach:
    HashSet: O(n) time, O(n) space
    Fast/Slow: O(n) time, O(1) space

  Fast/Slow is the optimal approach for cycle detection.

----------------------------------------------------------------
COMMON MISTAKES
----------------------------------------------------------------

  1. Checking `slow == fast` BEFORE moving:
     Initial state: slow = fast = head. Checking before move
     would always report a cycle. Always move FIRST, then check.

  2. Not checking `fast != null && fast.next != null`:
     Missing either check leads to NullPointerException on null lists
     or odd-length lists.

  3. Using fast.next.next directly without null checks:
     Always write: while (fast != null && fast.next != null)

  4. Moving slow 2 steps and fast 3 steps (uncommon variant):
     The standard is 1 and 2. Any two different speeds work, but
     1 and 2 gives the cleanest mathematical properties.

  5. For cycle START detection: forgetting to reset one pointer
     to head after detecting the meeting point.

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: Why use 1 and 2 steps? Can we use other speeds?
  A: Any two speeds where one is strictly faster work. 1 and 2 is
     the simplest. With different speeds, the gap at which they
     meet may change but they always meet in O(n).

  Q: What if the list has only one node with no cycle?
  A: fast = head, fast.next = null. While condition fails immediately.
     Return false. Correct.

  Q: What if the list is empty?
  A: fast = null. While condition `fast != null` fails immediately.
     Return false. Correct.

  Q: How is this O(n) -- doesn't fast move n times and slow n/2 times?
  A: Together they do at most O(n) total work. Slow moves n/2 steps
     max, fast moves n steps max. Both are O(n).

  Q: Is it possible for fast and slow to leapfrog without meeting?
  A: No. If fast is 2 steps ahead, after one iteration it's 1 step
     ahead. Then they meet next step. They always meet (if cycle exists).

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------

  - Always explain the mechanics first: "slow moves 1 step, fast moves 2"
  - State the invariant: "if a cycle exists, they will meet in O(n)"
  - For cycle start (LC 142): mention the mathematical insight
    (covered in 04_Cycle_Start_Detection.txt)
  - Emphasize O(1) space advantage over HashSet approach
  - Draw the linked list structure with the cycle loop visually
