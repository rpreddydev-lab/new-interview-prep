================================================================
  K CLOSEST POINTS TO ORIGIN (LC 973)
================================================================

  Given an array of points on the 2D plane, return the k closest
  points to the origin (0, 0).

  Distance: sqrt(x² + y²). We can compare x²+y² to avoid sqrt.

  Input:  points = [[1,3],[-2,2]], k = 1
  Output: [[-2,2]]  (dist²: 1+9=10 vs 4+4=8, so (-2,2) is closer)

  Input:  points = [[3,3],[5,-1],[-2,4]], k = 2
  Output: [[3,3],[-2,4]]

  The answer can be returned in any order.

----------------------------------------------------------------
APPROACH 1: MAX-HEAP OF SIZE K
----------------------------------------------------------------

  Maintain a max-heap of size k, ordered by distance.
  Max-heap: the FARTHEST of the k closest is at the top.
  If a new point is closer than the farthest (heap.peek()), swap it in.

  Java:
    public int[][] kClosest(int[][] points, int k) {
        // Max-heap by squared distance
        PriorityQueue<int[]> maxHeap = new PriorityQueue<>(
            (a, b) -> (b[0]*b[0] + b[1]*b[1]) - (a[0]*a[0] + a[1]*a[1])
        );

        for (int[] point : points) {
            maxHeap.offer(point);
            if (maxHeap.size() > k) maxHeap.poll();  // remove farthest
        }

        return maxHeap.toArray(new int[k][]);
    }

  Time: O(n log k)   Space: O(k)

----------------------------------------------------------------
APPROACH 2: SORT BY DISTANCE
----------------------------------------------------------------

  Java:
    public int[][] kClosest(int[][] points, int k) {
        Arrays.sort(points, (a, b) ->
            (a[0]*a[0] + a[1]*a[1]) - (b[0]*b[0] + b[1]*b[1])
        );
        return Arrays.copyOfRange(points, 0, k);
    }

  Time: O(n log n)   Space: O(log n) sort stack

  Simple and readable. Preferred when k is close to n.

----------------------------------------------------------------
APPROACH 3: QUICKSELECT (O(n) AVERAGE)
----------------------------------------------------------------

  Partition by distance. When pivot lands at index k, first k elements
  are the k closest (not sorted among themselves, but all closer).

  Java:
    public int[][] kClosest(int[][] points, int k) {
        quickSelect(points, 0, points.length - 1, k);
        return Arrays.copyOfRange(points, 0, k);
    }

    private void quickSelect(int[][] pts, int lo, int hi, int k) {
        if (lo >= hi) return;
        int pivot = partition(pts, lo, hi);
        if (pivot + 1 == k) return;
        else if (pivot + 1 < k) quickSelect(pts, pivot + 1, hi, k);
        else quickSelect(pts, lo, pivot - 1, k);
    }

    private int partition(int[][] pts, int lo, int hi) {
        long pivotDist = dist(pts[hi]);
        int i = lo;
        for (int j = lo; j < hi; j++) {
            if (dist(pts[j]) <= pivotDist) swap(pts, i++, j);
        }
        swap(pts, i, hi);
        return i;
    }

    private long dist(int[] p) { return (long)p[0]*p[0] + (long)p[1]*p[1]; }

    private void swap(int[][] pts, int i, int j) {
        int[] tmp = pts[i]; pts[i] = pts[j]; pts[j] = tmp;
    }

  Time: O(n) average   Space: O(1) (modifies input)

----------------------------------------------------------------
TRACED EXAMPLE: [[1,3],[-2,2],[5,0],[1,-1]], k=2
----------------------------------------------------------------

  Distances²:
    [1,3]   --> 1+9  = 10
    [-2,2]  --> 4+4  = 8
    [5,0]   --> 25+0 = 25
    [1,-1]  --> 1+1  = 2

  Sorted by dist²: [1,-1](2), [-2,2](8), [1,3](10), [5,0](25)
  K=2 closest: [1,-1], [-2,2]

  MAX-HEAP trace (k=2):
    offer [1,3] (10): heap=[10]
    offer [-2,2] (8): heap=[10,8]   (max=10 at top)
    offer [5,0] (25): size=3>2, heap peek=10 < 25? No, 25>10 so poll 25.
      Wait: 25 > heap peek(10), so after offer, poll removes 25? No.
      After offer(25): heap=[25,8,10], size=3>2, poll() removes max=25
      heap=[10,8]
    offer [1,-1] (2): heap=[10,8,2], size=3>2, poll() removes max=10
      heap=[8,2]

    Result: [[-2,2],[1,-1]] ✓

----------------------------------------------------------------
IMPORTANT: OVERFLOW CONSIDERATIONS
----------------------------------------------------------------

  If coordinates can be up to 10^4:
    x² + y² can be up to 2 * (10^4)² = 2 * 10^8 -- fits in int.

  If coordinates up to 10^5 or larger:
    x² + y² can exceed int range. Use long.

    private long dist(int[] p) {
        return (long)p[0]*p[0] + (long)p[1]*p[1];
    }

  Always cast to long BEFORE multiplication to prevent overflow.

----------------------------------------------------------------
VARIANT: K CLOSEST IN 1D (K Closest Elements, LC 658)
----------------------------------------------------------------

  Find k closest integers to x in a SORTED array.
  Answer is a contiguous subarray.

  Binary search for position of x, then two-pointer expand outward.

  Java:
    public List<Integer> findClosestElements(int[] arr, int k, int x) {
        int lo = 0, hi = arr.length - k;

        while (lo < hi) {
            int mid = lo + (hi - lo) / 2;
            // Compare left boundary vs right boundary of window
            if (x - arr[mid] > arr[mid + k] - x) {
                lo = mid + 1;  // window starting at mid is too far left
            } else {
                hi = mid;
            }
        }
        return Arrays.stream(arr, lo, lo + k).boxed().collect(Collectors.toList());
    }

  Key: We're binary searching for the START of the k-element window.
  Condition: x-arr[mid] > arr[mid+k]-x means the left end is farther from x
  than the right end, so shift window right.

  Time: O(log(n-k) + k)   Space: O(k)

----------------------------------------------------------------
COMPARISON TABLE
----------------------------------------------------------------

  Approach      Time         Space   Notes
  -------------------------------------------------------
  Max-Heap      O(n log k)   O(k)    Streaming, good for large n small k
  Sort          O(n log n)   O(n)    Simple, when k ≈ n
  QuickSelect   O(n) avg     O(1)    Fastest avg, modifies input
  LC 658 BS     O(log(n-k))  O(1)    Only for sorted 1D arrays

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: Why max-heap for k closest? Shouldn't min-heap give smallest distances?
  A: Min-heap would give us the globally smallest, but we can't limit size
     to k easily without losing track of the boundary. Max-heap of size k
     maintains exactly the k smallest seen so far. The farthest (top of
     max-heap) is our eviction candidate when a closer point arrives.

  Q: Do you need sqrt for distance comparison?
  A: No. Since sqrt is monotone, comparing x²+y² is equivalent to
     comparing sqrt(x²+y²). This avoids floating point issues.

  Q: What if coordinates are very large?
  A: Use long to avoid integer overflow: (long)x*x + (long)y*y.

  Q: For LC 658, why binary search on the start of window?
  A: The optimal window is contiguous in a sorted array. Binary searching
     for the start is O(log n) vs O(n) for two-pointer expansion from the
     insertion point.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------

  - Always mention the overflow concern with squaring coordinates.
  - For k closest problems, the key decision: max-heap (evict farthest) OR
    sort OR quickselect. Heap is usually the interview-expected answer.
  - Distinguish LC 973 (2D, any order) from LC 658 (1D, sorted, contiguous).
  - Quickselect gives O(n) but the constant is higher than heap for small k.
