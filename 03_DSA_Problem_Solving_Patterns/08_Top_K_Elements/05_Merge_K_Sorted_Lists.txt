================================================================
  MERGE K SORTED LISTS (LC 23)
================================================================

  Given an array of k linked-lists, each sorted in ascending order,
  merge all lists into one sorted linked list.

  Input:  lists = [[1,4,5],[1,3,4],[2,6]]
  Output: [1,1,2,3,4,4,5,6]

----------------------------------------------------------------
APPROACH 1: MIN-HEAP (OPTIMAL FOR K LISTS)
----------------------------------------------------------------

  Intuition: at any point, the next smallest element must be the
  head of one of the k lists. Use a min-heap to find it in O(log k).

  Algorithm:
    1. Initialize heap with the head of each non-null list.
    2. Poll the min node. Append to result.
    3. Push the polled node's next (if not null).
    4. Repeat until heap is empty.

  Java (with ListNode definition):
    public ListNode mergeKLists(ListNode[] lists) {
        PriorityQueue<ListNode> heap = new PriorityQueue<>(
            (a, b) -> a.val - b.val
        );

        for (ListNode head : lists) {
            if (head != null) heap.offer(head);
        }

        ListNode dummy = new ListNode(0);
        ListNode curr = dummy;

        while (!heap.isEmpty()) {
            ListNode node = heap.poll();
            curr.next = node;
            curr = curr.next;
            if (node.next != null) heap.offer(node.next);
        }

        return dummy.next;
    }

  Time: O(n log k)  -- n total nodes, log k per heap operation
  Space: O(k)       -- heap size

----------------------------------------------------------------
TRACED EXAMPLE: [[1,4,5],[1,3,4],[2,6]]
----------------------------------------------------------------

  Initial heap: [1(L0), 1(L1), 2(L2)]  (ties broken arbitrarily)

  Step 1: poll 1(L0), push 4(L0). result: 1. heap=[1(L1), 2(L2), 4(L0)]
  Step 2: poll 1(L1), push 3(L1). result: 1,1. heap=[2(L2), 4(L0), 3(L1)]
  Step 3: poll 2(L2), push 6(L2). result: 1,1,2. heap=[3(L1), 4(L0), 6(L2)]
  Step 4: poll 3(L1), push 4(L1). result: 1,1,2,3. heap=[4(L0), 6(L2), 4(L1)]
  Step 5: poll 4(L0), push 5(L0). result: 1,1,2,3,4. heap=[4(L1), 6(L2), 5(L0)]
  Step 6: poll 4(L1), L1.next=null. result: 1,1,2,3,4,4. heap=[5(L0), 6(L2)]
  Step 7: poll 5(L0), L0.next=null. result: 1,1,2,3,4,4,5. heap=[6(L2)]
  Step 8: poll 6(L2), L2.next=null. result: 1,1,2,3,4,4,5,6. heap=[]

  Final: 1->1->2->3->4->4->5->6 ✓

----------------------------------------------------------------
APPROACH 2: DIVIDE AND CONQUER
----------------------------------------------------------------

  Merge lists in pairs: round 1 gives k/2 lists, round 2 gives k/4, ...
  log k rounds. Each round processes all n elements.

  Time: O(n log k)   Space: O(log k) recursion stack

  Java:
    public ListNode mergeKLists(ListNode[] lists) {
        if (lists.length == 0) return null;
        return mergeRange(lists, 0, lists.length - 1);
    }

    private ListNode mergeRange(ListNode[] lists, int lo, int hi) {
        if (lo == hi) return lists[lo];
        int mid = lo + (hi - lo) / 2;
        ListNode left = mergeRange(lists, lo, mid);
        ListNode right = mergeRange(lists, mid + 1, hi);
        return mergeTwoLists(left, right);
    }

    private ListNode mergeTwoLists(ListNode a, ListNode b) {
        ListNode dummy = new ListNode(0);
        ListNode curr = dummy;
        while (a != null && b != null) {
            if (a.val <= b.val) { curr.next = a; a = a.next; }
            else { curr.next = b; b = b.next; }
            curr = curr.next;
        }
        curr.next = (a != null) ? a : b;
        return dummy.next;
    }

  Same time complexity as heap approach, but heap is simpler for k > 2.

----------------------------------------------------------------
APPROACH 3: SEQUENTIAL MERGE (SUBOPTIMAL)
----------------------------------------------------------------

  Merge list1 with list2, result with list3, etc.
  Time: O(kn) -- slower. Not recommended.

----------------------------------------------------------------
APPROACH 4: COLLECT ALL + SORT (NAIVE)
----------------------------------------------------------------

  Collect all values into a list, sort, rebuild.
  Time: O(n log n)   Space: O(n)

  Worse than divide & conquer for large k.

----------------------------------------------------------------
VARIANT: MERGE K SORTED ARRAYS
----------------------------------------------------------------

  Same heap approach. Store (value, array_index, element_index).

  Java:
    public int[] mergeKArrays(int[][] arrays, int k) {
        // Min-heap: [value, arrayIdx, elemIdx]
        PriorityQueue<int[]> heap = new PriorityQueue<>((a, b) -> a[0] - b[0]);

        int total = 0;
        for (int i = 0; i < k; i++) {
            if (arrays[i].length > 0) {
                heap.offer(new int[]{arrays[i][0], i, 0});
                total += arrays[i].length;
            }
        }

        int[] result = new int[total];
        int idx = 0;
        while (!heap.isEmpty()) {
            int[] top = heap.poll();
            result[idx++] = top[0];
            int ai = top[1], ei = top[2];
            if (ei + 1 < arrays[ai].length) {
                heap.offer(new int[]{arrays[ai][ei+1], ai, ei+1});
            }
        }
        return result;
    }

----------------------------------------------------------------
VARIANT: FIND K PAIRS WITH SMALLEST SUMS (LC 373)
----------------------------------------------------------------

  Given two sorted arrays nums1, nums2. Find k pairs (u,v) with smallest u+v.

  Approach: min-heap initialized with (nums1[i]+nums2[0], i, 0) for i in [0,min(k,n1)].
  Poll and push next (i, j+1) for each polled (i, j).

  Java:
    public List<List<Integer>> kSmallestPairs(int[] nums1, int[] nums2, int k) {
        List<List<Integer>> result = new ArrayList<>();
        if (nums1.length == 0 || nums2.length == 0) return result;

        // [sum, i, j]
        PriorityQueue<int[]> heap = new PriorityQueue<>((a, b) -> a[0] - b[0]);
        for (int i = 0; i < Math.min(k, nums1.length); i++) {
            heap.offer(new int[]{nums1[i] + nums2[0], i, 0});
        }

        while (!heap.isEmpty() && result.size() < k) {
            int[] top = heap.poll();
            int i = top[1], j = top[2];
            result.add(Arrays.asList(nums1[i], nums2[j]));
            if (j + 1 < nums2.length) {
                heap.offer(new int[]{nums1[i] + nums2[j+1], i, j+1});
            }
        }
        return result;
    }

  Time: O(k log k)   Space: O(k)

----------------------------------------------------------------
COMPLEXITY COMPARISON
----------------------------------------------------------------

  Approach           Time         Space   Notes
  -------------------------------------------------------
  Min-Heap           O(n log k)   O(k)    Best for k lists, streaming
  Divide & Conquer   O(n log k)   O(log k) Same time, less space
  Sequential Merge   O(kn)        O(1)    Slow, avoid
  Sort               O(n log n)   O(n)    OK for small k, wasteful

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: What is the time complexity of the heap approach?
  A: O(n log k) where n = total nodes across all lists, k = number of lists.
     Each node is inserted and polled from the heap once, each O(log k).

  Q: Why can't you just use one big min-heap and insert everything?
  A: That would be O(n log n) and O(n) space. The two-heap approach uses
     only O(k) space by only keeping current heads in the heap.

  Q: Is divide and conquer better than heap?
  A: Same time complexity O(n log k). Divide & conquer uses O(log k) space
     vs O(k) for heap. But heap is simpler to implement and handles
     dynamic/streaming cases.

  Q: How would you handle empty lists in the input?
  A: Skip null/empty lists when initializing the heap:
     if (head != null) heap.offer(head);

  Q: For LC 373 (K pairs smallest sums), why not initialize all pairs?
  A: There are n1*n2 pairs, potentially huge. We only need k.
     Start with n1 rows, each at column 0. When we poll (i,j), we push (i,j+1).
     This explores lazily.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------

  - Heap approach is the standard expected answer for merge-K problems.
  - For linked list version, note the comparator: (a,b) -> a.val - b.val
    (be careful with overflow if values can be negative large; use Integer.compare)
  - Mention the dummy node trick for clean list building.
  - For the "K pairs" variant, emphasize lazy expansion of the heap.
  - State space complexity: O(k) — much better than O(n).
