================================================================
  MEDIAN OF DATA STREAM (LC 295)
================================================================

  Design a data structure that supports:
    addNum(int num): add a number to the stream.
    findMedian(): return the median of all added numbers.

  Median:
    Odd count:  middle element
    Even count: average of two middle elements

  Input:
    addNum(1), addNum(2), findMedian()  --> 1.5
    addNum(3), findMedian()             --> 2

----------------------------------------------------------------
CORE IDEA: TWO HEAPS
----------------------------------------------------------------

  Maintain two heaps:
    small = max-heap  (left half, smaller numbers)
    large = min-heap  (right half, larger numbers)

  Invariant:
    1. All elements in small <= all elements in large.
    2. Sizes: |small.size() - large.size()| <= 1.
       (small can have at most one extra element)

  Median:
    If sizes equal:   (small.peek() + large.peek()) / 2.0
    If small is larger:  small.peek()

  Visualization:
    small (max-heap): [1, 3, 2] --> peek=3
    large (min-heap): [4, 6, 5] --> peek=4
    Median = (3+4)/2 = 3.5

  Java:
    class MedianFinder {
        // Max-heap for left half
        private PriorityQueue<Integer> small = new PriorityQueue<>(Collections.reverseOrder());
        // Min-heap for right half
        private PriorityQueue<Integer> large = new PriorityQueue<>();

        public void addNum(int num) {
            // Step 1: Add to small (max-heap)
            small.offer(num);

            // Step 2: Balance -- largest of small must be <= smallest of large
            if (!large.isEmpty() && small.peek() > large.peek()) {
                large.offer(small.poll());  // move max of small to large
            }

            // Step 3: Re-balance sizes (small can have at most 1 more than large)
            if (small.size() > large.size() + 1) {
                large.offer(small.poll());
            } else if (large.size() > small.size()) {
                small.offer(large.poll());
            }
        }

        public double findMedian() {
            if (small.size() == large.size()) {
                return (small.peek() + (double)large.peek()) / 2.0;
            }
            return small.peek();  // small has one extra
        }
    }

  Time: O(log n) per addNum, O(1) per findMedian
  Space: O(n)

----------------------------------------------------------------
TRACED EXAMPLE: addNum(1), addNum(2), findMedian, addNum(3), findMedian
----------------------------------------------------------------

  addNum(1):
    offer 1 to small: small=[1]
    large empty, skip balance check
    small.size()=1 <= large.size()+1=1, large.size()=0 <= small.size()=1 OK
    State: small=[1], large=[]

  addNum(2):
    offer 2 to small: small=[2,1]  (max-heap: 2 at top)
    small.peek()=2 > large.peek()? large empty, skip
    small.size()=2 > large.size()+1=1, YES: poll small (2), offer to large
    State: small=[1], large=[2]

  findMedian():
    equal sizes: (1 + 2) / 2.0 = 1.5 ✓

  addNum(3):
    offer 3 to small: small=[3,1]
    small.peek()=3 > large.peek()=2: move 3 to large: large=[2,3]
    large.size()=2 > small.size()=1: move 2 to small: small=[2,1]
    State: small=[2,1], large=[3]

  findMedian():
    small.size()=2 > large.size()=1: return small.peek() = 2 ✓

----------------------------------------------------------------
SIMPLER ALTERNATIVE ADDNUM LOGIC
----------------------------------------------------------------

  Some prefer always offer to large first, then rebalance:

    public void addNum(int num) {
        large.offer(num);              // always add to large first
        small.offer(large.poll());     // then move min of large to small
        // Now balance sizes
        if (large.size() < small.size() - 1) {
            large.offer(small.poll());
        }
    }

  This guarantees small.peek() <= large.peek() automatically.

VARIANT: SLIDING WINDOW MEDIAN (LC 480)
----------------------------------------------------------------

  Find median of each window of size k in array.

  Challenge: Need to efficiently remove elements leaving the window.

  Approach: Same two-heap structure + lazy deletion.
    - Use a HashSet or delay-counters to mark removed elements.
    - When polling, check if top is in "deleted" set; if so, skip it.

  Java skeleton:
    class SlidingWindowMedian {
        PriorityQueue<Integer> small = new PriorityQueue<>(Collections.reverseOrder());
        PriorityQueue<Integer> large = new PriorityQueue<>();
        Map<Integer, Integer> toDelete = new HashMap<>();

        private void addNum(int num) { /* same as above */ }

        private void removeNum(int num) {
            // Mark for lazy deletion
            toDelete.merge(num, 1, Integer::sum);
            // Rebalance if needed
            if (num <= small.peek()) {
                balance(-1, 0);  // small loses one
            } else {
                balance(0, -1);  // large loses one
            }
        }

        private void pruneHeap(PriorityQueue<Integer> heap) {
            while (!heap.isEmpty() && toDelete.containsKey(heap.peek())) {
                int top = heap.poll();
                if (toDelete.merge(top, -1, Integer::sum) == 0) toDelete.remove(top);
            }
        }
    }

  Full implementation is involved; mention the idea in interview.

VARIANT: MEDIAN OF SORTED ARRAYS (LC 4)
----------------------------------------------------------------

  Two sorted arrays nums1 and nums2. Find median of merged array.
  Binary search on smaller array to find correct partition.

  Time: O(log(min(m,n)))   (Different from streaming problem)

----------------------------------------------------------------
COMPLEXITY TABLE
----------------------------------------------------------------

  Operation      Two Heaps     Sorted List    Simple Array
  -------------------------------------------------------
  addNum         O(log n)      O(n)           O(n)
  findMedian     O(1)          O(1)           O(n) or O(1) with index

  Two heaps is clearly the optimal approach.

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: Why two heaps instead of one sorted structure?
  A: Insertion into a sorted structure (e.g., TreeMap) is O(log n),
     but so is heap insertion. The key advantage of two heaps is that
     findMedian is O(1): just peek at the tops. With a TreeSet, finding
     the median requires navigating to the middle, which is O(log n).

  Q: What is the invariant you maintain?
  A: (1) All elements in the max-heap (small) are <= all elements in
     the min-heap (large). (2) The size difference is at most 1,
     with small having the extra element if odd count.

  Q: What if elements are equal to each other?
  A: Heaps handle duplicates naturally. The invariant still holds.

  Q: Why does small hold the "max" and large hold the "min"?
  A: We need O(1) access to the top of the left half (max of left) and
     bottom of the right half (min of right). Max-heap gives left top.
     Min-heap gives right bottom.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------

  - Draw the two-heap diagram: [left max-heap | right min-heap]
  - State the invariant clearly: max(small) <= min(large), |sizes|<=1
  - Walk through the 3-step addNum logic:
      1. Add to small
      2. Check balance between heaps (move max of small to large if needed)
      3. Check sizes (keep them within 1)
  - This is a favorite design problem at top tech companies.
  - Mention LC 480 (sliding window) as a follow-up with lazy deletion.
