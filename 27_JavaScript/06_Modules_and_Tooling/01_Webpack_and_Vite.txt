1. WHY BUNDLERS?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  In modern web development, applications consist of hundreds of modules.
  Bundlers solve:
  - Module resolution (CommonJS, ESM, AMD)
  - Browser compatibility (transpiling modern JS)
  - Asset handling (CSS, images, fonts)
  - Performance optimization (minification, tree shaking, code splitting)

2. WEBPACK
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  The most widely used bundler since ~2012. Highly configurable.
  Processes everything as modules (JS, CSS, images).

  CORE CONCEPTS:
  - Entry       — starting point of the dependency graph
  - Output      — where to write bundles
  - Loaders     — transform non-JS files (CSS, TypeScript, images)
  - Plugins     — extend Webpack capabilities (HTML generation, env vars)
  - Mode        — "development" (readable) vs "production" (minified)

  // webpack.config.js (minimal):
  const path = require("path");
  const HtmlWebpackPlugin = require("html-webpack-plugin");

  module.exports = {
    entry: "./src/index.js",
    output: {
      path: path.resolve(__dirname, "dist"),
      filename: "[name].[contenthash].js"  // cache-busting hash
    },
    mode: "production",
    module: {
      rules: [
        {
          test: /\.tsx?$/,
          use: "ts-loader",
          exclude: /node_modules/
        },
        {
          test: /\.css$/,
          use: ["style-loader", "css-loader"]
        },
        {
          test: /\.(png|jpg|svg)$/,
          type: "asset/resource"
        }
      ]
    },
    plugins: [
      new HtmlWebpackPlugin({ template: "./public/index.html" })
    ],
    optimization: {
      splitChunks: { chunks: "all" }  // vendor chunk splitting
    }
  };

  KEY FEATURES:
  - Code splitting: dynamic import() creates separate chunks
  - Tree shaking: removes unused exports (requires ESM)
  - HMR (Hot Module Replacement): update modules without full page reload
  - Source maps: map bundled code back to source
  - Asset modules: handles images, fonts as modules
  - Caching: persistent caching speeds up rebuilds

3. VITE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Created by Evan You (Vue creator). Built for speed using native ESM.
  Uses esbuild for development and Rollup for production builds.

  WHY FASTER IN DEV?
  - No bundling in dev — serves source files directly as native ESM
  - Browser only requests modules it needs (lazy loading)
  - HMR is near-instant (no full bundle rebuild)
  - Pre-bundles node_modules with esbuild (10-100x faster than JS)

  // vite.config.js:
  import { defineConfig } from "vite";
  import react from "@vitejs/plugin-react";

  export default defineConfig({
    plugins: [react()],
    build: {
      outDir: "dist",
      rollupOptions: {
        output: {
          manualChunks: {
            vendor: ["react", "react-dom"]
          }
        }
      }
    },
    server: {
      port: 3000,
      proxy: {
        "/api": "http://localhost:8080"
      }
    }
  });

  async function loadAdminPanel() {
    const { AdminPanel } = await import("./AdminPanel.jsx");
    // AdminPanel.jsx is loaded as a separate chunk only when needed
    render(AdminPanel);
  }

  // React.lazy for route-level splitting:
  const LazyAdmin = React.lazy(() => import("./AdminPanel"));

6. COMMON INTERVIEW QUESTIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: What is Webpack and what problem does it solve?
A: Webpack is a module bundler that takes your source files (JS, CSS, images)
   and produces optimized output bundles. It resolves module dependencies,
   applies transforms (loaders), and optimizes output (minification, tree shaking).

Q: What is the difference between a Webpack loader and a plugin?
A: A loader transforms individual files before bundling (e.g. ts-loader
   compiles TypeScript → JS). A plugin operates on the full bundle/build
   process (e.g. HtmlWebpackPlugin generates HTML, MiniCssExtractPlugin
   extracts CSS into files).

Q: Why is Vite faster than Webpack in development?
A: Vite serves source files as native ESM directly to the browser without
   bundling. Webpack bundles everything first, then serves. Vite's HMR only
   invalidates the exact changed module; Webpack reprocesses larger chunks.

Q: What is tree shaking?
A: Dead code elimination — removing unused exports from the final bundle.
   Requires static import/export (ESM). Both Webpack and Vite support it.

Q: What is code splitting?
A: Splitting the bundle into multiple chunks that can be loaded on demand.
   Reduces initial load time. Triggered by dynamic import() statements.

Q: What is HMR (Hot Module Replacement)?
A: A technique where changed modules are replaced in the running app without
   a full page reload, preserving application state. Both Webpack and Vite
   support it; Vite's is significantly faster.
