1. WHAT IS TRANSPILING?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Transpiling = translating source code from one language/version to another.
  
  In JS: modern ES2020+ syntax → ES5 code that older browsers understand.
  
  Different from compilation (source → machine code) — transpiling is
  source-to-source transformation at the same abstraction level.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
2. BABEL
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Babel is the most widely used JS transpiler.
  Pipeline: Source Code → Parser (AST) → Transforms (plugins) → Generator → Output

  Three phases:
  1. PARSE    — source string → AST (Abstract Syntax Tree)
  2. TRANSFORM — plugins traverse/modify the AST
  3. GENERATE  — AST → output code string (+ source map)

  // Arrow function (ES6) → function (ES5):
  // Input:
  const add = (a, b) => a + b;
  // Output:
  var add = function(a, b) { return a + b; };

  // Class (ES6) → prototype (ES5):
  // Input:
  class Animal { constructor(name) { this.name = name; } }
  // Output:
  function Animal(name) { this.name = name; }

3. BABEL CONFIGURATION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  // babel.config.json:
  {
    "presets": [
      ["@babel/preset-env", {
        "targets": {
          "browsers": ["> 1%", "last 2 versions", "not ie <= 11"]
          // or: "node": "current"
        },
        "useBuiltIns": "usage",    // only polyfill what's actually used
        "corejs": 3
      }],
      "@babel/preset-react",       // JSX → React.createElement
      "@babel/preset-typescript"   // TypeScript → JS (type stripping)
    ],
    "plugins": [
      "@babel/plugin-proposal-class-properties",
      "@babel/plugin-transform-runtime"  // reduce duplication of helpers
    ]
  }

  // PRESETS — collections of plugins for specific goals:
  // @babel/preset-env      — targets specific browsers/Node versions
  // @babel/preset-react    — JSX, React Fast Refresh
  // @babel/preset-typescript — strips TS types (no type checking!)

  // PLUGINS — individual transforms:
  // @babel/plugin-proposal-optional-chaining
  // @babel/plugin-proposal-nullish-coalescing-operator
  // @babel/plugin-transform-runtime — avoids duplicating helpers

4. TRANSPILING vs POLYFILLING
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  TRANSPILING:
  - Converts SYNTAX (arrow functions, classes, destructuring)
  - Compile-time process — changes the code structure
  - Babel handles this via plugins/presets

  POLYFILLING:
  - Adds MISSING RUNTIME FEATURES (Promise, Array.from, fetch, Object.assign)
  - Runtime process — injects code that implements missing APIs
  - Tools: core-js, polyfill.io, @babel/polyfill (deprecated)

  // Syntax — Babel can transpile:
  const arr = [1, 2, 3];
  const doubled = arr.map(x => x * 2);  // arrow function → transpiled

  // Runtime feature — needs polyfill:
  new Promise(...)     // not available in IE11 → needs Promise polyfill
  fetch(...)           // not available in old browsers → needs polyfill
  arr.findIndex(...)   // older browsers → core-js polyfill

  // @babel/preset-env with "useBuiltIns": "usage" + corejs: 3
  // automatically imports only needed polyfills based on target browsers.

5. SOURCE MAPS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Source maps map minified/transpiled code back to original source.
  Lets you debug original code in DevTools even in production.

  // Enable in Babel:
  { "sourceMaps": true }

  // Webpack devtool options:
  // "source-map"        — full source map (production)
  // "eval-source-map"   — fast rebuild, inline (development)
  // "cheap-module-source-map" — moderate speed/quality

6. SWC AND esbuild — MODERN ALTERNATIVES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  SWC (Speedy Web Compiler) — written in Rust, drop-in Babel replacement.
  - 20-70x faster than Babel
  - Used by Next.js 12+, Vite
  - Handles transpilation and bundling

  esbuild — written in Go, extremely fast.
  - 100x faster than Webpack
  - Used as Vite's pre-bundler for node_modules
  - Less configurable for complex transforms

7. COMMON INTERVIEW QUESTIONS

Q: What is Babel and why is it used?
A: Babel is a JavaScript transpiler that converts modern JS (ES2015+) into
   older versions for browser compatibility. It converts syntax like arrow
   functions, classes, and destructuring into ES5-compatible code.

Q: What is the difference between transpiling and polyfilling?
A: Transpiling converts SYNTAX (arrow functions → functions) at compile time.
   Polyfilling adds missing RUNTIME APIs (Promise, fetch) by inserting
   JavaScript implementations. Both are needed for broad browser support.

Q: What is a Babel preset?
A: A collection of Babel plugins. @babel/preset-env targets specific browser
   versions and automatically includes needed transforms. @babel/preset-react
   handles JSX. @babel/preset-typescript strips TypeScript types.

Q: Does @babel/preset-typescript do type checking?
A: No. It only strips type annotations to produce JavaScript. Type checking
   must be done separately with tsc (TypeScript compiler). This makes Babel
   faster but doesn't catch type errors.

Q: What is the difference between Babel and SWC?
A: Both are JS transpilers. SWC is written in Rust and is 20-70x faster than
   Babel. Next.js 12+ switched from Babel to SWC. For most configs, SWC is
   a drop-in replacement.
