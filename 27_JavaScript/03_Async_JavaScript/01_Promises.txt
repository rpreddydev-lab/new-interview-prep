1. WHAT IS A PROMISE?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  A Promise is an object representing an eventual completion (or failure) of
  an async operation. It's a placeholder for a future value.

  States:
  ┌──────────────┬───────────────────────────────────────────────────────────┐
  │ State        │ Description                                               │
  ├──────────────┼───────────────────────────────────────────────────────────┤
  │ pending      │ Initial state — neither fulfilled nor rejected            │
  ├──────────────┼───────────────────────────────────────────────────────────┤
  │ fulfilled    │ Operation completed successfully (resolved with a value)   │
  ├──────────────┼───────────────────────────────────────────────────────────┤
  │ rejected     │ Operation failed (rejected with a reason/error)           │
  └──────────────┴───────────────────────────────────────────────────────────┘

  Rules:
  - A promise can only transition from pending → fulfilled OR pending → rejected
  - Once settled (fulfilled/rejected) it CANNOT change state
  - A promise can be settled only ONCE

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
2. CREATING PROMISES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  const promise = new Promise((resolve, reject) => {
    // executor function runs synchronously
    const success = Math.random() > 0.5;
    if (success) {
      resolve("Data fetched!");   // fulfill with value
    } else {
      reject(new Error("Failed")); // reject with error
    }
  });

  // Shorthand static methods:
  Promise.resolve(42);              // immediately fulfilled promise
  Promise.reject(new Error("oops")); // immediately rejected promise

3. CONSUMING PROMISES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  promise
    .then(value => {
      console.log("Success:", value);  // called on fulfill
      return value.toUpperCase();       // return to chain
    })
    .catch(err => {
      console.error("Error:", err.message);  // called on reject
    })
    .finally(() => {
      console.log("Always runs");  // cleanup
    });

  // .then() with both handlers:
  promise.then(
    value => console.log(value),   // onFulfilled
    err => console.error(err)      // onRejected (avoid — prefer .catch)
  );

4. PROMISE CHAINING
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Each .then() returns a NEW promise — allowing chaining:

  fetch("/api/user/1")
    .then(res => res.json())           // parse JSON (returns promise)
    .then(user => fetchPosts(user.id)) // fetch posts (returns promise)
    .then(posts => posts[0])           // get first post
    .then(post => console.log(post))
    .catch(err => console.error(err)); // catches any error in the chain

  // If .then() returns a plain value, it's wrapped in Promise.resolve()
  // If .then() returns a Promise, the chain waits for it

  // Common mistake — nesting instead of chaining:
  fetch("/api/user")
    .then(res => {
      return res.json().then(user => {  // WRONG: nesting
        return user.name;
      });
    });

  // Better — flat chaining:
  fetch("/api/user")
    .then(res => res.json())
    .then(user => user.name);

5. ERROR HANDLING IN CHAINS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  // .catch() catches ALL rejections above it in the chain:
  fetch(url)
    .then(res => {
      if (!res.ok) throw new Error(`HTTP ${res.status}`);  // throw from .then()
      return res.json();
    })
    .then(data => processData(data))   // if this throws, .catch() catches it too
    .catch(err => handleError(err));   // catches any rejection or throw

  // Recover from error and continue chain:
  fetch(url)
    .then(res => res.json())
    .catch(err => ({ defaultData: true }))  // recover with fallback
    .then(data => render(data));            // continues with fallback data

  // Re-throw to propagate:
  .catch(err => {
    if (err instanceof NetworkError) {
      return retry();    // handle it
    }
    throw err;           // re-throw unknown errors
  })

6. PROMISE STATIC METHODS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  A) Promise.all(iterable) — waits for ALL to fulfill:
     - Fulfills with array of all results (in order)
     - FAILS FAST: rejects immediately if any one rejects
     
     const [user, posts] = await Promise.all([
       fetch("/api/user").then(r => r.json()),
       fetch("/api/posts").then(r => r.json())
     ]);

  B) Promise.allSettled(iterable) — waits for ALL to settle:
     - Never rejects
     - Returns array of {status, value/reason} for each
     - Use when you want results from ALL, even failures
     
     const results = await Promise.allSettled([p1, p2, p3]);
     results.forEach(r => {
       if (r.status === "fulfilled") console.log(r.value);
       else console.error(r.reason);
     });

  C) Promise.race(iterable) — first to settle WINS:
     - Fulfills/rejects with the FIRST settled promise
     - Others are "abandoned" (still run, but result ignored)
     
     // Timeout pattern:
     const timeout = new Promise((_, reject) =>
       setTimeout(() => reject(new Error("Timeout")), 5000)
     );
     const result = await Promise.race([fetchData(), timeout]);

  D) Promise.any(iterable) — first to FULFILL wins (ES2021):
     - Ignores rejections unless ALL reject
     - If all reject → AggregateError
     - Best for: try multiple sources, take the fastest success
     
     const data = await Promise.any([fetchFromCDN1(), fetchFromCDN2()]);

  ┌────────────────────┬──────────────────┬────────────────────────────────┐
  │ Method             │ Resolves when    │ Rejects when                   │
  ├────────────────────┼──────────────────┼────────────────────────────────┤
  │ Promise.all        │ ALL fulfill      │ ANY one rejects (fail-fast)    │
  ├────────────────────┼──────────────────┼────────────────────────────────┤
  │ Promise.allSettled │ ALL settle       │ Never (always fulfills)        │
  ├────────────────────┼──────────────────┼────────────────────────────────┤
  │ Promise.race       │ FIRST settles    │ FIRST rejects                  │
  ├────────────────────┼──────────────────┼────────────────────────────────┤
  │ Promise.any        │ FIRST fulfills   │ ALL reject (AggregateError)    │
  └────────────────────┴──────────────────┴────────────────────────────────┘

7. PROMISE GOTCHAS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  A) Not returning the promise in .then():
  // WRONG — chain broken, next .then sees undefined
  .then(res => { res.json(); })     // forgot return!
  // CORRECT:
  .then(res => res.json())

  B) Unhandled rejections:
  const p = Promise.reject(new Error("oops"));  // no .catch() → warning/crash

  C) Promise executor is synchronous:
  new Promise((resolve) => {
    console.log("1");
    resolve("done");
    console.log("2");  // still runs after resolve!
  });
  // Output: "1", "2" (THEN the .then() callbacks run as microtasks)

  D) Promise.all vs sequential:
  // Parallel (fast):
  const [a, b] = await Promise.all([asyncOp1(), asyncOp2()]);

  // Sequential (slow):
  const a = await asyncOp1();
  const b = await asyncOp2();  // doesn't start until a is done

8. COMMON INTERVIEW QUESTIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: What is a Promise?
A: A Promise is an object representing an async operation's eventual result.
   It has 3 states: pending, fulfilled (resolved), rejected. Once settled,
   it's immutable.

Q: What is the difference between Promise.all and Promise.allSettled?
A: Promise.all rejects immediately if any promise rejects (fail-fast).
   Promise.allSettled waits for all to settle and returns all
   results/errors — never rejects.

Q: What is the difference between Promise.race and Promise.any?
A: Promise.race resolves/rejects with the FIRST settled (success or failure).
   Promise.any resolves with the FIRST FULFILLED promise, ignoring rejections
   unless ALL reject (then AggregateError).

Q: How do you handle errors in a promise chain?
A: Append .catch() at the end of the chain. It catches any rejection or
   thrown error from any preceding .then(). To recover, return a value
   from .catch(). To propagate, re-throw the error.

Q: What's the order of execution in a promise executor?
A: The executor function is SYNCHRONOUS. After the executor calls resolve/
   reject, the .then()/.catch() callbacks run as MICROTASKS (after the
   current synchronous code finishes).

Q: What is promise chaining and why is it useful?
A: Each .then() returns a new Promise, allowing operations to be chained
   in sequence. If a .then() returns a Promise, the chain waits for it.
   This avoids nested callbacks (callback hell) and enables linear flow.
