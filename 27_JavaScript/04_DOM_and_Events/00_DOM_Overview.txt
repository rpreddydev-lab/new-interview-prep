1. WHAT IS THE DOM?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  DOM = Document Object Model
  - A tree-structured, in-memory representation of an HTML/XML document
  - Created by the browser when it parses HTML
  - JavaScript can read and modify it to update the page without reloading
  - Not part of JavaScript itself — it's a Web API provided by browsers

3. DOM TRAVERSAL
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  const el = document.getElementById("app");

  // Parent:
  el.parentElement          // parent Element node
  el.parentNode             // parent Node (can be Document)

  // Children:
  el.children               // HTMLCollection of child ELEMENTS
  el.childNodes             // NodeList of ALL child nodes (incl. text/comment)
  el.firstElementChild      // first child Element
  el.lastElementChild       // last child Element
  el.firstChild             // first child Node (may be text node)
  el.lastChild              // last child Node

  // Siblings:
  el.nextElementSibling     // next sibling Element
  el.previousElementSibling // previous sibling Element
  el.nextSibling            // next sibling Node
  el.previousSibling        // previous sibling Node

  // Closest ancestor matching selector:
  el.closest(".container");  // walks up the DOM, returns matching ancestor

4. SELECTING ELEMENTS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  document.getElementById("id")                // Element | null
  document.getElementsByClassName("cls")       // HTMLCollection (live)
  document.getElementsByTagName("div")         // HTMLCollection (live)
  document.querySelector(".class > p")         // first match | null
  document.querySelectorAll("li.active")       // NodeList (static snapshot)

  // HTMLCollection vs NodeList:
  // HTMLCollection — live (updates when DOM changes)
  // NodeList from querySelectorAll — static (snapshot)
  // NodeList from childNodes — live

  // Convert to array for modern array methods:
  const items = [...document.querySelectorAll("li")];
  items.filter(el => el.classList.contains("done"));

5. REFLOW AND REPAINT
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  REFLOW (Layout):
  - Triggered when geometry changes (size, position)
  - Expensive — recalculates layout of affected elements
  - Caused by: offsetWidth, getBoundingClientRect, appendChild, style changes

  REPAINT:
  - Triggered by visual changes that don't affect geometry (color, visibility)
  - Cheaper than reflow but still costly

  // Performance anti-pattern — forces layout thrashing:
  for (let i = 0; i < 100; i++) {
    const w = el.offsetWidth;         // READ — flushes pending styles
    el.style.width = w + 1 + "px";   // WRITE — invalidates layout
  }

  // Better — batch reads first, then writes:
  const widths = items.map(el => el.offsetWidth);  // all reads
  items.forEach((el, i) => el.style.width = widths[i] + 1 + "px");  // all writes

6. COMMON INTERVIEW QUESTIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: What is the DOM?
A: The Document Object Model — a tree-structured, live representation of
   an HTML document. It is a browser Web API that JavaScript uses to read
   and modify page content, structure, and styles.

Q: What is the difference between HTMLCollection and NodeList?
A: HTMLCollection is always live (reflects DOM changes automatically).
   NodeList from querySelectorAll is a static snapshot. NodeList from
   childNodes is live. Both are array-like but not real arrays.

Q: What triggers reflow?
A: Any read of layout properties (offsetWidth, scrollTop, getBoundingClientRect)
   or writes that change geometry (style.width, appendChild). Mixing reads
   and writes in a loop causes layout thrashing.

Q: What is the difference between querySelector and getElementById?
A: getElementById accepts only an ID string and is faster (O(1) hash lookup).
   querySelector accepts any CSS selector and is more flexible but slightly
   slower. Both return a single element or null.

Q: What is a DocumentFragment?
A: A lightweight DOM node that exists in memory but not in the live document.
   Appending multiple elements to a fragment first, then appending the fragment
   to the DOM, causes only ONE reflow instead of one per element.
