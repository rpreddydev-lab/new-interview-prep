1. WHAT IS EVENT DELEGATION?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Instead of attaching an event listener to EACH child element,
  attach ONE listener to a common PARENT and use event.target to
  determine which child triggered the event.

  This is possible because events BUBBLE up from the target to the root.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
2. WITHOUT vs WITH DELEGATION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  // WITHOUT delegation — one listener per item (bad for large lists):
  const buttons = document.querySelectorAll(".action-btn");
  buttons.forEach(btn => {
    btn.addEventListener("click", (e) => {
      console.log("Action:", e.target.dataset.action);
    });
  });
  // Problems:
  // - 1000 items = 1000 listeners = high memory use
  // - Dynamically added buttons won't have listeners

  // WITH delegation — one listener on parent:
  const list = document.getElementById("action-list");
  list.addEventListener("click", (e) => {
    const btn = e.target.closest(".action-btn");  // find closest matching ancestor
    if (!btn) return;                              // click was not on a button
    console.log("Action:", btn.dataset.action);
  });
  // Benefits:
  // - Single listener regardless of child count
  // - Works for dynamically added children
  // - Less memory usage

3. PRACTICAL EXAMPLES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  // Todo list with delegated click:
  // HTML:
  // <ul id="todos">
  //   <li data-id="1"><span class="text">Buy milk</span><button class="delete">×</button></li>
  // </ul>

  document.getElementById("todos").addEventListener("click", (e) => {
    const li = e.target.closest("li");
    if (!li) return;

    if (e.target.matches(".delete")) {
      li.remove();
    } else if (e.target.matches(".text")) {
      li.classList.toggle("done");
    }
  });
  // New <li> elements added later will automatically work!

  // Delegated form handling:
  document.querySelector("form").addEventListener("change", (e) => {
    const input = e.target;
    if (input.matches("input[type='checkbox']")) {
      handleCheckbox(input);
    } else if (input.matches("select")) {
      handleSelect(input);
    }
  });

4. event.target vs closest() — HANDLING NESTED ELEMENTS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  // Problem with direct target check:
  // <button class="btn"><span class="icon">🗑</span> Delete</button>

  list.addEventListener("click", (e) => {
    if (e.target.matches(".btn")) {
      // If user clicks the <span> inside, e.target is <span>, not <button>!
      // This check would FAIL.
    }
  });

  // Solution — use closest():
  list.addEventListener("click", (e) => {
    const btn = e.target.closest(".btn");
    // closest() walks UP from clicked element, finds matching ancestor
    if (btn) handle(btn.dataset.id);
  });

  // closest() starts from the element itself, so:
  // clicking directly on .btn → btn = .btn ✓
  // clicking on .icon inside → btn = closest .btn ancestor ✓
  // clicking outside any .btn → btn = null, guarded by if check ✓

5. WHEN TO USE (AND NOT USE) DELEGATION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  USE delegation when:
  ✓ Many similar child elements (lists, tables, grids)
  ✓ Child elements are dynamically added/removed
  ✓ Performance is a concern (fewer listeners)
  ✓ Simplifying cleanup (remove one listener vs many)

  AVOID delegation when:
  ✗ Event doesn't bubble (focus, blur, mouseenter, mouseleave)
       → Use focusin/focusout and mouseover/mouseout instead (they bubble)
  ✗ Heavy per-event filtering would be slower than direct listeners
  ✗ Precise control needed that event.target inspection can't provide
  ✗ Checking if a delegated event matches a specific deep child is complex

6. COMMON INTERVIEW QUESTIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: What is event delegation?
A: A pattern where a single event listener on a parent element handles events
   from many children, using event.target to determine the originating element.
   It relies on event bubbling.

Q: Why is event delegation preferred for dynamic content?
A: Listeners are attached to the parent which already exists. New child elements
   added later automatically get handled without needing to attach new listeners.

Q: What is the problem with using e.target.matches() with nested elements?
A: If a button contains an icon span, clicking the icon sets e.target to the
   span, not the button. matches(".btn") on the span fails. Solution: use
   e.target.closest(".btn") which walks up the DOM to find the matching ancestor.

Q: Which events don't bubble and how do you handle them with delegation?
A: focus and blur don't bubble. Use focusin/focusout instead which do bubble.
   mouseenter/mouseleave don't bubble; use mouseover/mouseout instead.

Q: What are the performance benefits of event delegation?
A: One listener for 1000 items vs 1000 listeners. Fewer listener objects means
   less memory. Also avoids O(n) setup work when adding/removing many items.
