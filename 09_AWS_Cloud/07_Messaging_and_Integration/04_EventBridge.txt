AWS MESSAGING — AMAZON EVENTBRIDGE
Complete Interview Preparation Guide
================================================================

1. EVENTBRIDGE OVERVIEW
================================================================

  Amazon EventBridge is a serverless event bus service that enables
  event-driven application architectures.
  
  Use cases:
    - React to AWS service events (EC2 state changes, S3 uploads, CloudTrail API calls)
    - Integrate with SaaS applications (Zendesk, Datadog, etc.)
    - Schedule events (replace cron jobs)
    - Route events to multiple targets based on rules

================================================================
2. CORE CONCEPTS
================================================================

  EVENT BUS:
    - Default Event Bus:  Receives events from AWS services automatically
    - Custom Event Bus:   For your application's events
    - Partner Event Bus:  For SaaS partner events (Zendesk, PagerDuty, Shopify)

  EVENT:
    - JSON document describing what happened
    {
      "version": "0",
      "id": "12345678-1234-5678-abcd-1234567890ab",
      "source": "com.myapp.orders",
      "detail-type": "OrderPlaced",
      "time": "2024-01-15T12:00:00Z",
      "region": "us-east-1",
      "account": "123456789012",
      "detail": {
        "orderId": "order-123",
        "customerId": "cust-456",
        "amount": 99.99
      }
    }

  RULE:
    - Matches events based on event patterns (filter criteria)
    - Routes matching events to one or more TARGETS
    - Can also be a SCHEDULE rule (CRON or rate-based)

  TARGET:
    - What receives matched events
    - Lambda, SQS, SNS, Step Functions, ECS task, Kinesis, API Gateway,
      CodePipeline, CloudWatch Logs, Kinesis Firehose, EventBridge Archive

================================================================
3. EVENT PATTERNS
================================================================

  Rules match events using event patterns (partial JSON matching).
  
  Match by source and detail-type:
  {
    "source": ["com.myapp.orders"],
    "detail-type": ["OrderPlaced"]
  }

  Match specific field values:
  {
    "source": ["com.myapp.orders"],
    "detail": {
      "status": ["placed", "confirmed"],
      "amount": [{ "numeric": [">=", 100] }]
    }
  }

  Match AWS service events (EC2 instance state change):
  {
    "source": ["aws.ec2"],
    "detail-type": ["EC2 Instance State-change Notification"],
    "detail": { "state": ["stopped", "terminated"] }
  }

  Match CloudTrail API calls (S3 bucket created):
  {
    "source": ["aws.s3"],
    "detail-type": ["AWS API Call via CloudTrail"],
    "detail": {
      "eventSource": ["s3.amazonaws.com"],
      "eventName": ["CreateBucket"]
    }
  }

================================================================
4. SCHEDULING
================================================================

  RATE EXPRESSION:
    rate(5 minutes)
    rate(1 hour)
    rate(7 days)

  CRON EXPRESSION (UTC):
    cron(0 12 * * ? *)         # Every day at 12:00 UTC
    cron(0 8 ? * MON-FRI *)    # Weekdays at 8:00 UTC
    cron(0 0 1 * ? *)          # First of every month at midnight

  CLI:
  aws events put-rule \
    --name "daily-report" \
    --schedule-expression "cron(0 8 * * ? *)" \
    --state ENABLED

  aws events put-targets \
    --rule "daily-report" \
    --targets '[{
      "Id": "lambda-target",
      "Arn": "arn:aws:lambda:us-east-1:123456789012:function:generate-report"
    }]'

5. EVENT ROUTING AND TARGETS
================================================================

  CREATE RULE WITH PATTERN:
  aws events put-rule \
    --name "order-placed-rule" \
    --event-pattern '{"source":["com.myapp.orders"],"detail-type":["OrderPlaced"]}' \
    --state ENABLED \
    --event-bus-name my-custom-bus

  ADD MULTIPLE TARGETS (fan-out):
  aws events put-targets \
    --rule "order-placed-rule" \
    --event-bus-name my-custom-bus \
    --targets '[
      {"Id":"sqs","Arn":"arn:aws:sqs:us-east-1:123456789012:order-processing-queue"},
      {"Id":"lambda","Arn":"arn:aws:lambda:us-east-1:123456789012:function:order-analytics"},
      {"Id":"stepfunctions","Arn":"arn:aws:states:us-east-1:123456789012:stateMachine:OrderWorkflow","RoleArn":"arn:aws:iam::123456789012:role/events-role"}
    ]'

  PUBLISH CUSTOM EVENT:
  aws events put-events \
    --entries '[{
      "Source": "com.myapp.orders",
      "DetailType": "OrderPlaced",
      "Detail": "{\"orderId\":\"123\",\"amount\":99.99}",
      "EventBusName": "my-custom-bus"
    }]'

6. EVENTBRIDGE vs SNS vs SQS
================================================================

  ┌──────────────────────┬─────────────────────┬───────────────────────┬────────────────────┐
  │ Feature              │ EventBridge         │ SNS                   │ SQS                │
  ├──────────────────────┼─────────────────────┼───────────────────────┼────────────────────┤
  │ Model                │ Event bus           │ Pub/Sub (push)        │ Queue (pull)       │
  │ Sources              │ AWS services, SaaS, │ Your app code,        │ Your app code      │
  │                      │ custom apps         │ AWS services          │                    │
  │ Filtering            │ Rich event patterns │ Message attributes    │ None (consumer)    │
  │ Targets              │ 15+ service types   │ SQS, Lambda, HTTP,    │ Consumer polls     │
  │                      │                     │ Email, SMS            │                    │
  │ Delivery             │ At-least-once        │ At-least-once        │ At-least-once      │
  │ Retry                │ 24 hours            │ Built-in retry        │ Visibility timeout │
  │ Archive/Replay       │ Yes                 │ No                    │ No (just retention)│
  │ Schema Registry      │ Yes                 │ No                    │ No                 │
  │ Cost                 │ Per event           │ Per message           │ Per API call       │
  └──────────────────────┴─────────────────────┴───────────────────────┴────────────────────┘

7. ARCHIVE AND REPLAY
================================================================

  EventBridge can ARCHIVE all events and REPLAY them later.
  
  Use cases:
    - Replay events to test a new Lambda version against historical events
    - Recover from a bug by re-processing past events
    - Debug issues by replaying specific events

  Create archive:
  aws events create-archive \
    --archive-name order-events-archive \
    --event-source-arn arn:aws:events:us-east-1:123456789012:event-bus/my-bus \
    --event-pattern '{"source":["com.myapp.orders"]}' \
    --retention-days 30

  Replay:
  aws events start-replay \
    --replay-name replay-july-orders \
    --event-source-arn arn:aws:events:us-east-1:123456789012:archive/order-events-archive \
    --event-start-time "2024-07-01T00:00:00" \
    --event-end-time "2024-07-31T23:59:59" \
    --destination '{"Arn":"arn:aws:events:us-east-1:123456789012:event-bus/my-bus"}'

8. JAVA SDK v2 — EVENTBRIDGE OPERATIONS
================================================================

  import software.amazon.awssdk.services.eventbridge.EventBridgeClient;
  import software.amazon.awssdk.services.eventbridge.model.*;
  
  private static final EventBridgeClient ebClient = EventBridgeClient.create();
  
  // PUBLISH CUSTOM EVENT
  PutEventsRequestEntry entry = PutEventsRequestEntry.builder()
      .source("com.myapp.orders")
      .detailType("OrderPlaced")
      .detail("{\"orderId\":\"order-123\",\"amount\":99.99,\"status\":\"placed\"}")
      .eventBusName("my-custom-bus")
      .build();
  
  PutEventsResponse response = ebClient.putEvents(
      PutEventsRequest.builder()
          .entries(entry)
          .build()
  );
  
  // Check for failures
  for (PutEventsResultEntry result : response.entries()) {
      if (result.errorCode() != null) {
          System.err.println("Failed: " + result.errorMessage());
      }
  }

9. INTERVIEW QUESTIONS
================================================================

Q: What is the difference between SNS and EventBridge?
A: Both are pub/sub systems but at different levels. SNS is simpler — publish a message,
   filter by message attributes, push to subscribers. EventBridge is richer: integrates
   natively with 200+ AWS services and SaaS providers, rich event pattern matching on any
   JSON field, supports archiving and replay, schema registry, scheduled events, and 15+
   target types. EventBridge is the "modern" choice for event-driven architectures,
   especially when reacting to AWS service events. Use SNS for simple fan-out to SQS/Lambda
   with basic attribute-based filtering. Use EventBridge for complex routing, AWS service
   events, SaaS integrations, or when you need archive/replay.

Q: How would you trigger a Lambda function when an EC2 instance is terminated?
A: Use EventBridge Default Event Bus (receives all AWS service events automatically).
   Create a rule with the event pattern:
   {"source": ["aws.ec2"], "detail-type": ["EC2 Instance State-change Notification"],
    "detail": {"state": ["terminated"]}}
   Set the target as your Lambda function.
   This requires no changes to the application — AWS EC2 service automatically publishes
   state change events to the Default Event Bus.

Q: What is EventBridge Archive and Replay? When would you use it?
A: Archive records events matching a pattern to long-term storage. Replay re-publishes
   archived events to an event bus. Use cases: 1) A bug was deployed that dropped orders
   from 6-8 PM — replay those 2 hours of events after the bug fix. 2) Deploy a new Lambda
   version and test it against real historical events instead of synthetic test data.
   3) Audit compliance — prove what events occurred on a given date. Unlike SQS (14-day max
   retention) or SNS (no archive), EventBridge Archive retains events for days to years.
