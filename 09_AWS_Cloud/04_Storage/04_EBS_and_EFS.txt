AWS STORAGE — EBS AND EFS
Complete Interview Preparation Guide
================================================================

1. AMAZON EBS (ELASTIC BLOCK STORE)
================================================================

EBS provides persistent block storage volumes for EC2 instances.
It's like a USB drive or SSD for your virtual machine.

KEY CHARACTERISTICS:
  - Block-level storage (format with filesystem: ext4, xfs, NTFS)
  - Network-attached to EC2 (low latency, not as fast as local SSD)
  - Persistent: survives instance stop/restart (unlike instance store)
  - AZ-bound: attached to instances in the SAME AZ only
  - Single attachment: one EC2 at a time (except io1/io2 Multi-Attach)
  - Automatically replicated within the AZ

3. EBS SNAPSHOTS
================================================================

  - Point-in-time backup of an EBS volume
  - Stored in S3 (managed by AWS, not your bucket)
  - INCREMENTAL: first snapshot = full copy; subsequent = only changed blocks
  - Cross-AZ/region: snapshots can be used to create volumes in different AZs/regions
  - Encryption: encrypted volumes → encrypted snapshots (and vice versa)

  CREATE SNAPSHOT:
  aws ec2 create-snapshot \
    --volume-id vol-0a12345b678901234 \
    --description "Pre-upgrade backup"

  CREATE VOLUME FROM SNAPSHOT (different AZ):
  aws ec2 create-volume \
    --snapshot-id snap-0a1234567890abcde \
    --availability-zone us-east-1b \
    --volume-type gp3

  COPY SNAPSHOT TO ANOTHER REGION:
  aws ec2 copy-snapshot \
    --source-region us-east-1 \
    --source-snapshot-id snap-0a1234567890abcde \
    --destination-region eu-west-1

  AWS DATA LIFECYCLE MANAGER (DLM):
    Automates EBS snapshot creation and retention:
    - Create snapshots every N hours/days
    - Retain last N snapshots
    - Cross-region copy for DR
    
    aws dlm create-lifecycle-policy \
      --execution-role-arn arn:aws:iam::... \
      --policy-details file://policy.json

4. EBS MULTI-ATTACH (io1/io2 Only)
================================================================

  Allows a SINGLE EBS volume to be attached to MULTIPLE EC2 instances
  simultaneously (same AZ).

  Requirements:
    - Volume type: io1 or io2 only
    - All instances must be in the SAME AZ
    - Linux instances must use cluster-aware filesystem (not ext4!)
    - The filesystem must handle concurrent writes (e.g., Oracle Cluster FS, GFS2)

  Use cases:
    - High-availability clustered applications
    - Oracle RAC (Real Application Clusters)
    - Distributed logging systems

================================================================
5. EBS ENCRYPTION
================================================================

  - Encryption at rest using AWS KMS keys (or AWS-managed key)
  - Encrypted data in transit between EC2 and EBS
  - Snapshots of encrypted volumes are automatically encrypted
  - Volumes created from encrypted snapshots are encrypted

  ENABLE ENCRYPTION BY DEFAULT (account level):
  aws ec2 enable-ebs-encryption-by-default --region us-east-1
  # All new EBS volumes encrypted by default in this region

  ENCRYPT AN EXISTING UNENCRYPTED VOLUME:
    1. Create snapshot of unencrypted volume
    2. Copy snapshot with encryption enabled:
       aws ec2 copy-snapshot --encrypted --source-snapshot-id snap-xxx ...
    3. Create new volume from the encrypted snapshot
    4. Detach old, attach new volume to EC2

6. AMAZON EFS (ELASTIC FILE SYSTEM)
================================================================

EFS provides a fully managed, serverless, elastic NFS (Network File System)
for Linux workloads.

KEY CHARACTERISTICS:
  - Shared file system: mount on multiple EC2/ECS/EKS/Lambda simultaneously
  - Fully managed: no OS patching, capacity management
  - Elastic: automatically grows and shrinks (pay for what you use)
  - Standard POSIX-compliant filesystem (supports chmod, chown, symbolic links)
  - NFS v4.0 and v4.1 protocol
  - Available across multiple AZs in a region (Regional) or one AZ (One Zone)

================================================================
7. EFS STORAGE CLASSES AND PERFORMANCE
================================================================

STORAGE CLASSES:
  Standard:        Default; frequently accessed; highest availability (multi-AZ)
  Standard-IA:     Infrequently accessed; cheaper; automatic with Intelligent-Tiering
  One Zone:        Stores in one AZ; cheaper (20% discount); less durable
  One Zone-IA:     One AZ + infrequent access; cheapest EFS option

INTELLIGENT-TIERING:
  Enable EFS Lifecycle Management to automatically move files between
  Standard and IA based on access (7, 14, 30, 60, or 90 days without access)

PERFORMANCE MODES:
  General Purpose (default): Lowest latency; max 35,000 IOPS; most workloads
  Max I/O: Higher throughput; higher latency; for massively parallel workloads (deprecated in EFS Express)
  
THROUGHPUT MODES:
  Bursting: Scales with storage size; good for typical bursty workloads
  Provisioned: Set throughput independent of storage size; predictable performance
  Elastic (default): Auto-scales; no provisioned throughput needed; recommended

8. EFS MOUNTING
================================================================

  # Install NFS client (Amazon Linux 2)
  sudo yum install -y amazon-efs-utils
  
  # Mount via NFS
  sudo mount -t nfs4 \
    -o nfsvers=4.1,rsize=1048576,wsize=1048576,hard,timeo=600,retrans=2,noresvport \
    fs-12345678.efs.us-east-1.amazonaws.com:/ /mnt/efs
  
  # Mount via EFS mount helper (recommended — auto TLS, IAM auth)
  sudo mount -t efs -o tls fs-12345678 /mnt/efs
  
  # fstab entry (persistent mount across reboots):
  fs-12345678.efs.us-east-1.amazonaws.com:/ /mnt/efs efs tls,_netdev 0 0

EFS ACCESS POINTS:
  - Application-specific entry points into EFS
  - Set a root directory per application (app A sees /appA, app B sees /appB)
  - Set POSIX user/group (enforces specific UID/GID for all file operations)
  - Useful for multi-tenant setups and container workloads

10. INTERVIEW QUESTIONS
================================================================

Q: What is the difference between EBS gp2 and gp3?
A: gp2 (older) ties IOPS to volume size: 3 IOPS per GB (baseline up to 16,000 IOPS).
   If you need more IOPS, you must increase volume size (paying for storage you may
   not need). gp3 decouples IOPS from storage: baseline 3,000 IOPS regardless of
   size, and you can provision up to 16,000 IOPS independently. gp3 is 20% cheaper
   than gp2 for storage. For new volumes, always use gp3.

Q: What is an EBS snapshot and how does incremental backup work?
A: An EBS snapshot is a point-in-time backup stored in S3. The first snapshot
   copies all data. Subsequent snapshots are INCREMENTAL — only the blocks that
   changed since the last snapshot are saved. When you restore, AWS assembles all
   needed snapshots transparently. Deleting an incremental snapshot is safe; AWS
   merges the data if needed. Cross-region copy is supported for disaster recovery.

Q: When would you choose EFS over EBS?
A: EFS when multiple EC2 instances, ECS tasks, or Lambda functions need to
   read/write the same data simultaneously (NFS shared storage). EBS when you need
   very low latency block storage for a single EC2 instance (database, OS volume).
   EFS is perfect for: shared web content (multiple web servers read/write),
   machine learning training data, containerized microservices, and CMS files.

Q: What is an EFS Access Point and why would you use it?
A: An EFS Access Point creates an application-specific view of the file system
   with a configured root directory and POSIX user/group. Use it to: isolate
   different applications to their own root directory (app A can't see app B's
   files), enforce consistent ownership for container workloads, and simplify
   mounting in ECS/EKS (no need to configure UID/GID on each container).

Q: Can you attach the same EBS volume to multiple EC2 instances?
A: Only with io1/io2 volume types using EBS Multi-Attach. All instances must
   be in the same AZ. The filesystem must be cluster-aware (not standard ext4 —
   use GFS2, OCFS2, or Oracle Cluster FS). For most multi-instance shared storage
   needs, EFS is the better solution as it works with any instance type, any AZ,
   and doesn't require special filesystems.
