1. S3 STORAGE CLASSES
================================================================

S3 offers different storage classes optimized for cost vs access frequency vs latency.

  ┌──────────────────────────────────────────────────────────────────────────────────┐
  │ STORAGE CLASS        │ USE CASE             │ RETRIEVAL │ MIN DAYS │ DURABILITY │
  ├──────────────────────────────────────────────────────────────────────────────────┤
  │ S3 Standard          │ Frequently accessed  │ ms        │ None     │ 11 nines   │
  │                      │ default; web apps,   │           │          │ 3+ AZs     │
  │                      │ content distribution │           │          │            │
  ├──────────────────────────────────────────────────────────────────────────────────┤
  │ S3 Intelligent-      │ Unknown/variable     │ ms        │ None     │ 11 nines   │
  │ Tiering              │ access patterns;     │ (frequent)│          │ 3+ AZs     │
  │                      │ auto-moves objects   │ ms        │          │            │
  │                      │ between tiers        │ (infreq.) │          │            │
  ├──────────────────────────────────────────────────────────────────────────────────┤
  │ S3 Standard-IA       │ Infrequently accessed│ ms        │ 30 days  │ 11 nines   │
  │ (Infrequent Access)  │ backups, DR copies   │           │          │ 3+ AZs     │
  ├──────────────────────────────────────────────────────────────────────────────────┤
  │ S3 One Zone-IA       │ Infrequently accessed│ ms        │ 30 days  │ 11 nines   │
  │                      │ reproducible data,   │           │          │ 1 AZ only  │
  │                      │ secondary backup     │           │          │            │
  ├──────────────────────────────────────────────────────────────────────────────────┤
  │ S3 Glacier           │ Long-term archives,  │ Min–Hrs   │ 90 days  │ 11 nines   │
  │ Instant Retrieval    │ accessed once/quarter│ ms        │          │ 3+ AZs     │
  ├──────────────────────────────────────────────────────────────────────────────────┤
  │ S3 Glacier           │ Archives accessed    │ 1-5 min   │ 90 days  │ 11 nines   │
  │ Flexible Retrieval   │ 1-2x/year, medical   │ (Expedited│          │ 3+ AZs     │
  │ (old S3 Glacier)     │ records, compliance  │ 3-5 hrs   │          │            │
  │                      │                      │ Standard) │          │            │
  ├──────────────────────────────────────────────────────────────────────────────────┤
  │ S3 Glacier           │ Regulatory archives, │ 12-48 hrs │ 180 days │ 11 nines   │
  │ Deep Archive         │ financial records,   │ (Standard │          │ 3+ AZs     │
  │                      │ 7-10 year retention  │ retrieval)│          │            │
  └──────────────────────────────────────────────────────────────────────────────────┘

PRICING TRADE-OFFS:
  Storage cost: Standard > IA > Glacier Flexible > Glacier Deep Archive
  Retrieval cost: Standard (free) → IA (per GB) → Glacier (tiered per GB)
  Min duration billing: IA/Glacier/Deep Archive have minimum storage periods
  
  Rule of thumb:
    Access > 1x/month → Standard
    Access 1x/month → Standard-IA
    Access 1x/year → Glacier Flexible
    Almost never access → Glacier Deep Archive

2. S3 INTELLIGENT-TIERING
================================================================

  Automatically moves objects between tiers based on access patterns.
  No performance impact, no retrieval fees (within the service).
  Small monitoring fee per object (~$0.0025/1000 objects/month).

  TIERS:
    Frequent Access (FA): Standard performance, auto (default for new objects)
    Infrequent Access (IA): After 30 days of no access, moves here
    Archive Instant (AI): After 90 days of no access (optional)
    Archive Access (AA): After 90-180 days (optional, requires restore)
    Deep Archive (DA): After 180 days (optional, requires restore)

  When to use:
    - Objects with unpredictable access patterns
    - Large datasets where you don't know what will be accessed
    - When you want automated cost optimization without lifecycle rules

3. LIFECYCLE POLICIES
================================================================

  S3 Lifecycle Policies automate transitions between storage classes
  and deletion of objects based on rules.

  TWO TYPES OF ACTIONS:
    Transition Actions: Move objects to cheaper storage class after N days
    Expiration Actions: Delete objects (or versions) after N days

  EXAMPLE LIFECYCLE RULE:

  # Via AWS Console or JSON configuration:
  {
    "Rules": [{
      "ID": "LogArchiveRule",
      "Status": "Enabled",
      "Filter": { "Prefix": "logs/" },
      "Transitions": [
        { "Days": 30, "StorageClass": "STANDARD_IA" },
        { "Days": 90, "StorageClass": "GLACIER" },
        { "Days": 365, "StorageClass": "DEEP_ARCHIVE" }
      ],
      "Expiration": { "Days": 2555 }   // Delete after 7 years
    }]
  }

  CLI:
  aws s3api put-bucket-lifecycle-configuration \
    --bucket my-bucket \
    --lifecycle-configuration file://lifecycle.json

  TYPICAL PATTERNS:
  
  Application Logs:
    Day 0-30: Standard (frequent access for debugging)
    Day 30-90: Standard-IA (occasional lookups)
    Day 90-365: Glacier Flexible (compliance access rare)
    Day 365+: Delete (or Deep Archive for 7-year compliance)
  
  User Uploads:
    Day 0: Standard (active use)
    Day 180: Intelligent-Tiering (unknown future access)
    Day 1825 (5 years): Delete
  
  Database Backups:
    Day 0-7: Standard (recent backups for quick restore)
    Day 7-30: Standard-IA (monthly restore unlikely)
    Day 30-365: Glacier Flexible (annual restore for compliance)
    Day 365: Delete

4. VERSIONING AND LIFECYCLE
================================================================

  With Versioning ENABLED, deleted objects become a "delete marker"
  (old versions are kept). Lifecycle rules for versioned buckets:

  {
    "Rules": [{
      "Status": "Enabled",
      "Filter": {},
      "NoncurrentVersionTransitions": [
        { "NoncurrentDays": 30, "StorageClass": "STANDARD_IA" },
        { "NoncurrentDays": 90, "StorageClass": "GLACIER" }
      ],
      "NoncurrentVersionExpiration": { "NoncurrentDays": 365 },
      "AbortIncompleteMultipartUpload": { "DaysAfterInitiation": 7 }
    }]
  }

  AbortIncompleteMultipartUpload:
    - Cleans up incomplete multipart uploads (accumulate quietly)
    - Best practice: always set this to 7 days to prevent hidden costs

5. STORAGE CLASS ANALYSIS
================================================================

  Amazon S3 Analytics analyzes storage access patterns to recommend
  when to transition objects to Standard-IA.

  - AWS generates reports after 30 days of observation
  - Can then create lifecycle rules based on recommendations
  - Available per bucket or prefix

6. INTERVIEW QUESTIONS
================================================================

Q: What is the difference between S3 Standard-IA and S3 One Zone-IA?
A: Both are for infrequently accessed data with lower storage costs but
   per-GB retrieval fees. S3 Standard-IA replicates across at least 3 AZs
   (high durability 11 nines, available if an AZ fails). S3 One Zone-IA stores
   data in only ONE AZ — 20% cheaper but if that AZ fails, data is lost.
   Use One Zone-IA only for data you can recreate (thumbnails, derived files,
   secondary backups already stored elsewhere).

Q: When would you use S3 Intelligent-Tiering?
A: When access patterns are unpredictable or when managing large datasets
   with mixed access frequencies. For example, a user-generated content platform
   where some files are popular and others are never accessed again. Instead of
   manually configuring lifecycle rules, Intelligent-Tiering automatically moves
   objects to the appropriate tier based on access. There's a small monthly
   monitoring fee per object ($0.0025/1000), so it's most cost-effective for
   objects > 128KB.

Q: What is an S3 lifecycle policy and give a practical example?
A: A lifecycle policy is a set of rules that automate actions (transition to
   cheaper storage or deletion) on S3 objects based on age. Practical example:
   Application logs → Day 0: Standard (active debugging) → Day 30: Standard-IA
   (occasional compliance lookup) → Day 90: Glacier Flexible (rare access) →
   Day 2555 (7 years): Delete (legal retention period). This can reduce storage
   costs by 80-90% compared to keeping everything in Standard.

Q: What happens if you delete an object in S3 without versioning?
A: Without versioning, the object is PERMANENTLY and immediately deleted — unrecoverable.
   With versioning enabled, a "delete marker" is added instead, making the object
   appear deleted but preserving all previous versions. You can restore by deleting
   the delete marker. Enable versioning on important buckets and consider MFA Delete
   for critical data to prevent accidental permanent deletions.
