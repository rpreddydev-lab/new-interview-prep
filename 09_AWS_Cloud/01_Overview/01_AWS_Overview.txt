1. WHAT IS AWS?
================================================================

Amazon Web Services (AWS) is the world's most comprehensive and broadly
adopted cloud platform, offering 200+ fully featured services from data
centers globally.

Cloud Computing Definition:
  On-demand delivery of IT resources (compute, storage, databases, networking,
  AI/ML, etc.) over the internet with pay-as-you-go pricing.

AWS Market Position (2025):
  - ~31% public cloud market share (largest provider)
  - 4M+ active customers
  - 33 geographic regions, 105 Availability Zones

5. AWS ADVANTAGES OVER ON-PREMISES
================================================================

  1. Trade capital expense for variable expense
     - No upfront hardware purchase; pay per use
  
  2. Benefit from massive economies of scale
     - AWS buys hardware in bulk → lower prices for customers
  
  3. Stop guessing capacity
     - Scale up/down on demand; no over-provisioning
  
  4. Increase speed and agility
     - Provision resources in minutes, not weeks
  
  5. Focus on business differentiation
     - No data center management; AWS handles undifferentiated heavy lifting
  
  6. Go global in minutes
     - Deploy to multiple regions worldwide instantly

6. AWS CONSOLE, CLI, AND SDK
================================================================

AWS Management Console:
  - Web-based GUI at console.aws.amazon.com
  - Suitable for exploration and one-off tasks

AWS CLI:
  # Install
  brew install awscli    # macOS
  
  # Configure credentials
  aws configure
  # Prompts: Access Key ID, Secret Access Key, Region, Output format
  
  # Example commands
  aws s3 ls                              # list all buckets
  aws s3 cp file.txt s3://my-bucket/     # upload file
  aws ec2 describe-instances             # list EC2 instances
  aws lambda invoke --function-name myFn out.json  # invoke Lambda

AWS SDKs:
  - Available for Java, Python, JS/Node, .NET, Go, Ruby, PHP, etc.
  - Java SDK v2 example:
    S3Client s3 = S3Client.builder().region(Region.US_EAST_1).build();
    s3.listBuckets().buckets().forEach(b -> System.out.println(b.name()));

7. AWS ACCOUNT STRUCTURE
================================================================

  Root Account
  └── Organizations (multiple accounts for isolation)
      ├── Management Account (billing, policies)
      ├── Production Account
      ├── Development Account
      └── Security Account (log archive, audit)
  
  Best Practices:
  - Use root account ONLY for initial setup + billing
  - Create IAM users/roles for all operations
  - Use AWS Organizations for multi-account strategy
  - Enable MFA on root account immediately
  - Use SCPs (Service Control Policies) to restrict accounts

8. KEY AWS CONCEPTS
================================================================

Region:
  - Geographic area (us-east-1, eu-west-1, ap-southeast-1)
  - Each region is independent; data stays in the region unless you replicate

Availability Zone (AZ):
  - Isolated data center(s) within a region
  - Connected by low-latency fiber
  - Deploy across ≥2 AZs for high availability

Edge Location:
  - CloudFront CDN caching points worldwide (400+ globally)
  - Faster content delivery to end users

ARN (Amazon Resource Name):
  - Unique identifier for every AWS resource
  - Format: arn:aws:service:region:account-id:resource
  - Example: arn:aws:s3:::my-bucket
  - Example: arn:aws:iam::123456789012:role/MyRole

Tags:
  - Key-value metadata on resources
  - Used for cost allocation, access control, automation
  - Best practice: tag everything (Environment, Team, Project, Owner)

9. INTERVIEW QUESTIONS
================================================================

Q: What is the difference between a Region, Availability Zone, and Edge Location?
A: Region: geographic area with multiple AZs (us-east-1 = N. Virginia).
   Availability Zone: one or more physically separate data centers in a region
   with independent power, cooling, and networking. Multi-AZ = high availability.
   Edge Location: CloudFront CDN points of presence for caching content
   close to users. 400+ globally, many more than regions.

Q: What is the Shared Responsibility Model?
A: AWS is responsible for security OF the cloud (hardware, global infrastructure,
   managed service software). Customers are responsible for security IN the cloud
   (IAM configurations, data encryption, OS patching on EC2, application security).
   The boundary shifts based on service type: EC2 (IaaS) → more customer
   responsibility; RDS (managed) → less customer responsibility.

Q: What are the main cloud service models (IaaS, PaaS, SaaS)?
A: IaaS — you manage OS, apps, data; provider manages hardware (EC2, S3).
   PaaS — you manage only apps and data; provider manages runtime and OS
   (Elastic Beanstalk, RDS).
   SaaS — provider manages everything; you just use the software (WorkMail, Chime).

Q: Why would a company choose AWS over running their own data center?
A: Pay-as-you-go (no upfront capital), on-demand scaling (handle spikes without
   over-provisioning), global reach (deploy worldwide in minutes), managed
   services (AWS handles patching/backups/maintenance), security certifications
   (SOC2, ISO 27001, HIPAA, PCI DSS), and ability to focus engineering resources
   on differentiating features instead of infrastructure management.

Q: What is an ARN?
A: Amazon Resource Name — unique identifier for every AWS resource.
   Format: arn:aws:service:region:account-id:resource
   Used in IAM policies to specify which resource to allow/deny access to.
   Example: arn:aws:s3:::my-bucket grants access to an S3 bucket.
   Some global services (IAM, S3) omit the region and account-id.
