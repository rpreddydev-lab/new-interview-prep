1. NETWORKING BUILDING BLOCKS ON AWS
================================================================

  Every AWS resource that communicates over a network operates within
  one of these constructs:
    VPC → Subnets → Route Tables → Internet/NAT Gateways → Security Groups / NACLs

  Key networking services:
    VPC (Virtual Private Cloud)       — Isolated network environment
    Subnets                           — Sub-divisions of a VPC (public/private)
    Route Tables                      — Define where network traffic goes
    Internet Gateway (IGW)            — VPC connection to the internet
    NAT Gateway                       — Private subnet instances reach internet
    Security Groups                   — Stateful firewall at instance level
    Network ACLs (NACLs)              — Stateless firewall at subnet level
    VPC Peering                       — Private connection between two VPCs
    Transit Gateway                   — Hub-and-spoke connecting many VPCs
    VPN (Site-to-Site)                — Encrypted tunnel: on-premises ↔ AWS
    Direct Connect                    — Dedicated physical line: on-premises ↔ AWS
    Route 53                          — DNS service
    CloudFront                        — CDN (Content Delivery Network)
    Elastic Load Balancer (ALB/NLB)   — Distribute traffic (covered in Compute)
    VPC Endpoints (Gateway/Interface) — Private access to AWS services without internet

2. AWS NETWORKING LAYERS
================================================================

  LAYER 3 (Network): VPC, Subnets, Route Tables, IGW, NAT
  LAYER 4 (Transport): Security Groups (TCP/UDP/port), NACLs, NLB (TCP/UDP)
  LAYER 7 (Application): ALB (HTTP/HTTPS/gRPC), WAF, CloudFront, API Gateway

4. CIDR NOTATION QUICK REFERENCE
================================================================

  IP/prefix determines how many IP addresses in a block:
    /8   → 16,777,216 IPs  (255.0.0.0)
    /16  → 65,536 IPs      (255.255.0.0)   ← Typical VPC size
    /24  → 256 IPs         (255.255.255.0) ← Typical subnet size
    /28  → 16 IPs          (minimum for AWS subnets)
    /32  → 1 IP            (single host)

  AWS reserves 5 IPs per subnet:
    x.x.x.0:   Network address
    x.x.x.1:   AWS reserved (VPC router)
    x.x.x.2:   AWS reserved (DNS)
    x.x.x.3:   AWS reserved (future use)
    x.x.x.255: Broadcast address (unusable in VPC)
  
  So /24 = 256 - 5 = 251 usable IPs

  Private IP ranges (RFC 1918):
    10.0.0.0/8          (Class A — most common for VPCs)
    172.16.0.0/12       (172.16.0.0 – 172.31.255.255)
    192.168.0.0/16      (home networks — avoid in enterprise AWS)

5. INTERVIEW QUESTIONS
================================================================

Q: What is a VPC and why do you need one?
A: A VPC (Virtual Private Cloud) is a logically isolated section of the AWS cloud
   where you define your own network (IP range, subnets, route tables, gateways).
   You need it to: isolate resources from other AWS customers and the public internet,
   control network access (which resources can communicate with each other and the internet),
   and define security at the network layer (NACLs). All AWS resources like EC2, RDS,
   ECS launch inside a VPC. If no VPC is specified, the default VPC is used.

Q: What is the difference between a public and private subnet?
A: A public subnet has a route to the Internet Gateway (0.0.0.0/0 → IGW) in its
   route table, and resources in it can have public IP addresses directly reachable
   from the internet. A private subnet has NO direct route to the internet; instead,
   it routes internet-bound traffic through a NAT Gateway in a public subnet. Private
   subnet resources are not directly reachable from the internet. Databases and app
   servers should be in private subnets; only load balancers/bastion hosts go in public.

Q: How does a NAT Gateway work?
A: A NAT Gateway sits in a public subnet and allows resources in PRIVATE subnets to
   make OUTBOUND requests to the internet (e.g., download OS updates, call external APIs)
   WITHOUT being reachable from the internet. The private instance's private IP is
   translated to the NAT Gateway's Elastic IP for outbound traffic. Return traffic
   flows back through NAT to the private instance. The private instance is never
   directly exposed.
