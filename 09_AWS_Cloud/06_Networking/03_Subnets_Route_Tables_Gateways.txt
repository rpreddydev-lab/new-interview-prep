================================================================
AWS NETWORKING — SUBNETS, ROUTE TABLES, AND GATEWAYS
Complete Interview Preparation Guide
================================================================

1. SUBNETS
================================================================

  A subnet is a sub-range of a VPC's IP CIDR block, bound to ONE AZ.
  
  Rules:
    - Each subnet belongs to exactly one AZ (cannot span AZs)
    - CIDR block must be a subset of the VPC CIDR
    - Subnet CIDRs within a VPC cannot overlap
    - AWS reserves 5 IPs per subnet (network, router, DNS, future, broadcast)
    - Recommended: create at least 2 subnets (one per AZ) for HA

  PUBLIC SUBNET:
    - Route table has a route: 0.0.0.0/0 → Internet Gateway
    - Resources can have public IPs
    - Use for: load balancers, bastion hosts, NAT Gateways

  PRIVATE SUBNET:
    - No direct route to the internet
    - Route table has: 0.0.0.0/0 → NAT Gateway (for outbound internet)
    - Resources NOT directly reachable from internet
    - Use for: app servers, databases, internal services

  Create subnet:
  aws ec2 create-subnet \
    --vpc-id vpc-12345678 \
    --cidr-block 10.0.1.0/24 \
    --availability-zone us-east-1a

  # Enable auto-assign public IPs for instances in this subnet
  aws ec2 modify-subnet-attribute \
    --subnet-id subnet-12345678 \
    --map-public-ip-on-launch

2. ROUTE TABLES
================================================================

  A route table contains a set of rules (routes) that determine where
  network traffic is directed.
  
  Each subnet must be associated with a route table.
  If no explicit association: the subnet uses the VPC's MAIN route table.
  
  ROUTE PRIORITY:
    Most specific route wins (longest prefix match):
    - 10.0.1.0/24 beats 10.0.0.0/16 beats 0.0.0.0/0

  TYPICAL ROUTE TABLE EXAMPLES:

  Public Subnet Route Table:
    Destination    │ Target
    ───────────────┼─────────────────
    10.0.0.0/16    │ local (VPC traffic — always present, cannot delete)
    0.0.0.0/0      │ igw-12345678 (Internet Gateway — makes subnet public)

  Private Subnet Route Table:
    Destination    │ Target
    ───────────────┼─────────────────
    10.0.0.0/16    │ local
    0.0.0.0/0      │ nat-12345678 (NAT Gateway — for outbound internet only)

  Isolated Subnet Route Table (no internet access at all):
    Destination    │ Target
    ───────────────┼─────────────────
    10.0.0.0/16    │ local

  AWS CLI:
  aws ec2 create-route-table --vpc-id vpc-12345678

  aws ec2 create-route \
    --route-table-id rtb-12345678 \
    --destination-cidr-block 0.0.0.0/0 \
    --gateway-id igw-12345678

  aws ec2 associate-route-table \
    --route-table-id rtb-12345678 \
    --subnet-id subnet-12345678

3. INTERNET GATEWAY (REVIEW)
================================================================

  Enables bidirectional internet access for public subnet resources.
  
  Architecture:
    EC2 (10.0.1.10) → Route: 0.0.0.0/0 → IGW → Internet
    Internet → IGW → EC2's Elastic IP → translated to 10.0.1.10

  One IGW per VPC maximum.
  
  aws ec2 create-internet-gateway
  aws ec2 attach-internet-gateway \
    --internet-gateway-id igw-12345678 \
    --vpc-id vpc-12345678

================================================================
4. NAT GATEWAY (REVIEW + ADDITIONAL DETAIL)
================================================================

  Placed in PUBLIC subnet. Private subnet instances initiate outbound only.
  
  Traffic flow for private instance reaching internet:
    EC2 (10.0.3.5) → Private Route Table → NAT GW (10.0.1.10, EIP: 52.x.x.x)
    NAT GW → Public Route Table → IGW → Internet
    Return: Internet → IGW → NAT GW → EC2 (source NAT maintained in connection table)

  NAT Gateway does NOT have Security Groups — traffic is controlled by the
  Security Groups of the source EC2 instances.

  # For HA: Create one NAT GW per AZ
  aws ec2 create-nat-gateway --subnet-id subnet-public-az1 --allocation-id eip-az1
  aws ec2 create-nat-gateway --subnet-id subnet-public-az2 --allocation-id eip-az2
  
  # Route private subnet in AZ-1 to NAT GW in AZ-1
  aws ec2 create-route --route-table-id rtb-private-az1 \
    --destination-cidr-block 0.0.0.0/0 --nat-gateway-id nat-az1
  aws ec2 create-route --route-table-id rtb-private-az2 \
    --destination-cidr-block 0.0.0.0/0 --nat-gateway-id nat-az2

================================================================
5. EGRESS-ONLY INTERNET GATEWAY
================================================================

  For IPv6 traffic — equivalent to NAT Gateway but for IPv6.
  
  IPv6 addresses are globally unique (no private ranges in IPv6).
  If you assign IPv6 to private resources and don't want inbound connections:
    → Use Egress-Only Internet Gateway (allows outbound IPv6 only)
  
  Note: NAT Gateway works for IPv4 only.

6. COMPLETE VPC SETUP EXAMPLE
================================================================

  # Step 1: Create VPC
  vpc_id=$(aws ec2 create-vpc --cidr-block 10.0.0.0/16 --query 'Vpc.VpcId' --output text)

  # Step 2: Enable DNS
  aws ec2 modify-vpc-attribute --vpc-id $vpc_id --enable-dns-hostnames

  # Step 3: Create Internet Gateway
  igw_id=$(aws ec2 create-internet-gateway --query 'InternetGateway.InternetGatewayId' --output text)
  aws ec2 attach-internet-gateway --internet-gateway-id $igw_id --vpc-id $vpc_id

  # Step 4: Create subnets
  pub_az1=$(aws ec2 create-subnet --vpc-id $vpc_id --cidr-block 10.0.1.0/24 --availability-zone us-east-1a --query 'Subnet.SubnetId' --output text)
  priv_az1=$(aws ec2 create-subnet --vpc-id $vpc_id --cidr-block 10.0.3.0/24 --availability-zone us-east-1a --query 'Subnet.SubnetId' --output text)

  # Step 5: Create and attach Elastic IP + NAT Gateway
  eip=$(aws ec2 allocate-address --domain vpc --query 'AllocationId' --output text)
  nat_id=$(aws ec2 create-nat-gateway --subnet-id $pub_az1 --allocation-id $eip --query 'NatGateway.NatGatewayId' --output text)

  # Step 6: Create public route table
  pub_rt=$(aws ec2 create-route-table --vpc-id $vpc_id --query 'RouteTable.RouteTableId' --output text)
  aws ec2 create-route --route-table-id $pub_rt --destination-cidr-block 0.0.0.0/0 --gateway-id $igw_id
  aws ec2 associate-route-table --route-table-id $pub_rt --subnet-id $pub_az1

  # Step 7: Create private route table
  priv_rt=$(aws ec2 create-route-table --vpc-id $vpc_id --query 'RouteTable.RouteTableId' --output text)
  aws ec2 create-route --route-table-id $priv_rt --destination-cidr-block 0.0.0.0/0 --nat-gateway-id $nat_id
  aws ec2 associate-route-table --route-table-id $priv_rt --subnet-id $priv_az1

7. INTERVIEW QUESTIONS
================================================================

Q: How does a subnet become "public"?
A: A subnet is "public" when its associated route table has a route for
   0.0.0.0/0 pointing to an Internet Gateway. Without this route, traffic
   can't leave the VPC to reach the internet even if the instance has a
   public IP. Both conditions must be met: 1) route to IGW in route table,
   2) instance must have a public or Elastic IP. The subnet itself doesn't
   have a "public" flag — it's determined entirely by the route table.

Q: What happens to private subnet instances if the NAT Gateway in their AZ fails?
A: If there's only one NAT Gateway in the whole VPC (even if in a different AZ),
   private instances in that AZ lose outbound internet access when the NAT GW's
   AZ fails. Cross-AZ routing to the NAT GW would also stop. This is why the
   best practice is one NAT Gateway per AZ, with each AZ's private subnets routing
   to their local NAT Gateway. This prevents cross-AZ dependency.

Q: Can you have multiple route tables in a VPC?
A: Yes. Each VPC has one Main Route Table (automatically created). You can create
   additional custom route tables. Each SUBNET is associated with exactly one
   route table (if no explicit association, it uses the main route table). Different
   subnets can use different route tables — this is how you make some subnets
   public (route to IGW) and others private (route to NAT GW) within the same VPC.
