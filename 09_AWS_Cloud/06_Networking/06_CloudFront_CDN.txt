AWS NETWORKING — CLOUDFRONT CDN
Complete Interview Preparation Guide
================================================================

1. CLOUDFRONT OVERVIEW
================================================================

  Amazon CloudFront is a global Content Delivery Network (CDN) service.
  It caches content at 450+ Edge Locations worldwide, reducing latency for
  end users by serving content from the nearest edge location.
  
  Benefits:
    - Low latency: serve static content from 30–40ms globally
    - Reduced origin load: cache hits don't reach your origin
    - Security: DDoS protection via AWS Shield Standard (free)
    - HTTPS by default: free TLS certificate via ACM
    - Cost: cheaper data transfer rates vs direct S3/EC2 transfer

================================================================
2. CLOUDFRONT ARCHITECTURE
================================================================

  COMPONENTS:
    Origin:         Source of truth — S3 bucket, ALB, EC2, or any HTTP endpoint
    Distribution:   Configuration that maps origins, behaviors, and edge locations
    Edge Location:  AWS datacenter that caches content closest to users
    Regional Cache: Middle tier between edge and origin (larger cache, longer TTL)

  REQUEST FLOW:
    User in Tokyo
         ↓
    Edge Location (Tokyo) — Cache HIT? → return content (fast!)
         ↓ Cache MISS
    Regional Cache (Tokyo region) — HIT? → return and cache at edge
         ↓ Cache MISS
    Origin (S3 in us-east-1) → fetch content, cache at regional + edge

================================================================
3. CLOUDFRONT ORIGINS
================================================================

  S3 BUCKET ORIGIN:
    - Serve static files, websites, video
    - Secure with Origin Access Control (OAC) — bucket only accessible via CloudFront
    - Block S3 public access; only CloudFront can read

    OAC bucket policy:
    {
      "Statement": [{
        "Effect": "Allow",
        "Principal": { "Service": "cloudfront.amazonaws.com" },
        "Action": "s3:GetObject",
        "Resource": "arn:aws:s3:::my-bucket/*",
        "Condition": {
          "StringEquals": {
            "AWS:SourceArn": "arn:aws:cloudfront::123456789012:distribution/DIST_ID"
          }
        }
      }]
    }

  ALB / EC2 ORIGIN:
    - Dynamic content, API responses, server-rendered pages
    - CloudFront terminates TLS, forwards to ALB over HTTP or HTTPS
    - Can cache GET/HEAD responses

  CUSTOM ORIGIN:
    - Any publicly reachable HTTPS endpoint
    - On-premises web server, third-party API

  MULTIPLE ORIGINS:
    - One distribution can have multiple origins
    - Route to different origins based on path pattern (behaviors)

================================================================
4. CLOUDFRONT BEHAVIORS
================================================================

  A behavior defines how CloudFront handles requests for a specific path pattern.
  
  CACHE BEHAVIOR SETTINGS:
    Path pattern:    /api/* → no-cache; /static/* → cache 1 year
    Allowed methods: GET/HEAD only, or include POST/PUT/DELETE (for APIs)
    Cache key:       What defines a unique cached object (URL, headers, query strings, cookies)
    TTL:             Min, default, max TTL for cache
    Compress:        Gzip/Brotli compression for text content
    Viewer Protocol: HTTP only, HTTPS only, Redirect HTTP to HTTPS
    Forward headers: Which request headers to pass to origin

  CACHE INVALIDATION:
    - Force CloudFront to remove cached objects before TTL expires
    aws cloudfront create-invalidation \
      --distribution-id DIST_ID \
      --paths "/*"        # Invalidate all
    
    aws cloudfront create-invalidation \
      --distribution-id DIST_ID \
      --paths "/images/*" "/index.html"
    
    Cost: First 1,000 paths per month free; $0.005 per path after

5. CLOUDFRONT SSL/TLS AND HTTPS
================================================================

  DEFAULT DOMAIN: https://d1234567.cloudfront.net (free TLS cert from Amazon)
  
  CUSTOM DOMAIN:
    1. Create or import TLS certificate in ACM (us-east-1 ONLY for CloudFront)
    2. Add alternate domain name (CNAME) in CloudFront distribution
    3. Create DNS CNAME record: cdn.myapp.com → d1234567.cloudfront.net

  SNI (Server Name Indication):
    - Default: free, uses SNI (most modern browsers support SNI)
    - Dedicated IP: $600/month per distribution (for legacy clients without SNI)
    - Use SNI for all modern applications

  VIEWER PROTOCOL POLICY:
    Redirect HTTP to HTTPS (recommended): auto-upgrade users to HTTPS
    HTTPS only: reject HTTP entirely
    HTTP and HTTPS: allow both (not recommended)

6. CLOUDFRONT CACHING BEST PRACTICES
================================================================

  CACHE CONTROL HEADERS (from origin):
    Cache-Control: max-age=31536000 (1 year for versioned assets like bundle.abc123.js)
    Cache-Control: no-cache, no-store (for dynamic/private content)
    Cache-Control: max-age=300 (5 minutes for semi-dynamic content)

  VERSIONED FILENAMES:
    - bundle.abc123.js, main.v2.css — unique name per version
    - Set TTL = 1 year; deploy new version = new filename → new URL
    - Old URL still in cache but users are directed to new URL (via HTML)
    - Much cheaper than cache invalidation

  QUERY STRING CACHING:
    - /search?q=laptop → /search?q=phone = different cache keys
    - Enable if query strings affect content
    - Disable if they don't (merge into same cache key) to maximize hit rate

================================================================
7. CLOUDFRONT SECURITY
================================================================

  SIGNED URLs:
    - Provide time-limited access to private content
    - For individual files (e.g., premium video downloads)
    - Works with: S3 origins and custom origins

  SIGNED COOKIES:
    - Provide time-limited access to MULTIPLE private files
    - Good for: streaming, allowing access to all files in a directory
    - Client stores cookie, CloudFront validates it

  GEOGRAPHIC RESTRICTIONS:
    - Allowlist (only listed countries can access)
    - Blocklist (deny access to listed countries)
    - Uses MaxMind IP-to-location database

  WAF INTEGRATION:
    - Attach AWS WAF to CloudFront distribution
    - Filter malicious requests at the edge (before reaching origin)
    - Rules: rate limiting, SQL injection, XSS, IP blocking

  FIELD-LEVEL ENCRYPTION:
    - Encrypt specific form fields (e.g., credit card) at the edge
    - Only services with the private key can decrypt
    - Protects sensitive data even from your own origin servers

================================================================
8. CLOUDFRONT + S3 STATIC WEBSITE HOSTING
================================================================

  Architecture:
    [User] → [CloudFront] → [S3 Bucket with static files]
  
  S3 static hosting gives you a public URL but:
    - No HTTPS by default (or uses S3's certificate, not your domain)
    - No DDoS protection
    - Higher latency for global users
  
  With CloudFront:
    - HTTPS with your custom domain and ACM cert
    - Global edge caching
    - DDoS protection
    - S3 bucket stays PRIVATE (only CloudFront can read via OAC)

9. INTERVIEW QUESTIONS
================================================================

Q: What is CloudFront and how does it reduce latency?
A: CloudFront is a CDN with 450+ edge locations worldwide. When a user requests
   content, CloudFront routes the request to the nearest edge location. If the
   content is cached there (cache hit), it's returned immediately with minimal
   latency. If not (cache miss), CloudFront fetches from the origin, caches it
   at the edge, and serves it. For static assets (images, JS, CSS), a user in
   Tokyo gets content from a Tokyo edge location in ~30ms instead of ~200ms from
   a US-east origin. This significantly improves page load times globally.

Q: What is Origin Access Control (OAC) and why is it important?
A: OAC allows CloudFront to access a private S3 bucket without making it publicly
   accessible. You configure OAC on the distribution, and add a bucket policy that
   allows only that CloudFront distribution to read objects. This way: the S3 bucket
   has Block Public Access enabled, end users can't access S3 directly (bypassing CDN),
   and all traffic flows through CloudFront (DDoS protection, HTTPS, caching benefits).
   Without OAC, you'd need to make the S3 bucket public, exposing it to direct access.

Q: What is the difference between CloudFront Signed URLs and Signed Cookies?
A: Both restrict access to private content. Signed URLs are for INDIVIDUAL files —
   generate one URL per file that expires at a set time. Use for: one file at a time,
   when the user doesn't have cookie support. Signed Cookies grant access to MULTIPLE
   files under a URL pattern — the user gets a cookie that allows access to all
   matching resources (e.g., /premium/*). Use for: streaming (multiple segments),
   allowing access to a library of files.

Q: How would you deploy a React SPA on AWS with low latency globally?
A: 1) Build the React app (bundle.abc123.js with content-hashed filenames),
   2) Upload to S3 bucket with static website hosting disabled (keep private),
   3) Create CloudFront distribution pointing to S3 with OAC,
   4) Set Cache-Control: max-age=31536000 for versioned assets (bundle.abc123.js),
   5) Set Cache-Control: no-cache for index.html (so new versions are always fetched),
   6) Configure custom domain with ACM certificate (us-east-1 region),
   7) On new deploys: upload files with new hash, then invalidate /index.html only.
   This gives: HTTPS globally, CDN caching, S3 stays private, fast deploys.
