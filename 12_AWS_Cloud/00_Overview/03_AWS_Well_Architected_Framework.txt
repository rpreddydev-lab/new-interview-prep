AWS OVERVIEW — WELL-ARCHITECTED FRAMEWORK
Complete Interview Preparation Guide
================================================================

1. WHAT IS THE AWS WELL-ARCHITECTED FRAMEWORK?
================================================================

The AWS Well-Architected Framework provides a set of best practices and
guiding principles for designing and operating reliable, secure, efficient,
cost-effective, and sustainable systems in the cloud.

Components:
  - 6 Pillars (OSRPCS)
  - Design Principles per pillar
  - Questions to evaluate workloads
  - AWS Well-Architected Tool (free in AWS Console)
  - Well-Architected Reviews with AWS partners

================================================================
2. THE SIX PILLARS
================================================================

Pillar 1: OPERATIONAL EXCELLENCE
  Definition: Run and monitor systems to deliver business value and continuously
  improve processes and procedures.
  
  Key Principles:
    - Perform operations as code (IaC: CloudFormation, CDK)
    - Make frequent, small, reversible changes
    - Anticipate failure (chaos engineering, runbooks)
    - Learn from operational events and failures
    - Measure everything with metrics
  
  AWS Services: CloudWatch, Systems Manager, CodePipeline, X-Ray

---

Pillar 2: SECURITY
  Definition: Protect data, systems, and assets while delivering business value
  through risk assessment and mitigation strategies.
  
  Key Principles:
    - Implement a strong identity foundation (least privilege IAM)
    - Enable traceability (CloudTrail, CloudWatch Logs)
    - Apply security at all layers (VPC, security groups, WAF, encryption)
    - Automate security best practices
    - Protect data in transit and at rest
    - Keep people away from data (use automation, not human access to prod)
    - Prepare for security events (incident response plans)
  
  AWS Services: IAM, KMS, CloudTrail, WAF, Shield, GuardDuty, Macie

---

Pillar 3: RELIABILITY
  Definition: Ensure a workload performs its intended function correctly and
  consistently when expected. Recover quickly from failures.
  
  Key Principles:
    - Automatically recover from failure
    - Test recovery procedures (chaos monkey, fault injection)
    - Scale horizontally (many small resources > one large)
    - Stop guessing capacity (use Auto Scaling)
    - Manage change through automation
  
  AWS Services: Auto Scaling, Multi-AZ RDS, Route 53, ELB, SQS, S3

---

Pillar 4: PERFORMANCE EFFICIENCY
  Definition: Use computing resources efficiently to meet requirements and
  maintain that efficiency as demand changes.
  
  Key Principles:
    - Democratize advanced technologies (use managed services)
    - Go global in minutes (multi-region with CloudFront)
    - Use serverless architectures (no server management)
    - Experiment more often (easy to test different instance types)
    - Consider mechanical sympathy (use right tool for right job)
  
  AWS Services: Lambda, DynamoDB, ElastiCache, CloudFront, Auto Scaling

---

Pillar 5: COST OPTIMIZATION
  Definition: Run systems to deliver business value at the lowest price point.
  
  Key Principles:
    - Implement cloud financial management (FinOps)
    - Adopt a consumption model (pay only for what you use)
    - Measure overall efficiency
    - Stop spending money on undifferentiated heavy lifting
    - Analyze and attribute expenditure (tagging)
  
  AWS Services: Cost Explorer, Budgets, Trusted Advisor, Spot Instances,
                Reserved Instances, S3 Intelligent-Tiering

---

Pillar 6: SUSTAINABILITY (added 2021)
  Definition: Minimize environmental impact of running cloud workloads.
  
  Key Principles:
    - Understand your impact (CO2 footprint)
    - Establish sustainability goals
    - Maximize utilization (right-size resources)
    - Anticipate and adopt new hardware/software offerings
    - Use managed services (shared resources = more efficient)
    - Reduce downstream impact of your cloud workloads
  
  AWS Services: Graviton processors, S3 lifecycle, AWS Customer Carbon
                Footprint Tool

3. WELL-ARCHITECTED REVIEW PROCESS
================================================================

  1. Identify the workload to review
  2. Answer questions in each pillar (AWS Console → Well-Architected Tool)
  3. AWS identifies High Risk Issues (HRIs) and Medium Risk Issues
  4. Create improvement plan
  5. Implement improvements
  6. Re-review periodically

  Well-Architected Tool (free):
    - Console: AWS → Well-Architected Tool
    - Define workloads → answer questions → get prioritized recommendations

4. COMMON DESIGN ANTI-PATTERNS
================================================================

  Anti-Pattern                     | Well-Architected Fix
  ---------------------------------|----------------------------------------
  Single AZ deployment             | Multi-AZ for HA
  Hardcoded credentials in code    | IAM roles + Secrets Manager
  No monitoring / alerts           | CloudWatch + SNS alerts
  Manual deployments               | CodePipeline + IaC (CloudFormation)
  S3 bucket public access ON       | Block Public Access + bucket policies
  No encryption at rest/transit    | KMS + TLS/HTTPS everywhere
  Oversized instances              | Right-size with Compute Optimizer
  On-Demand for everything         | Savings Plans / Reserved Instances
  No backup/recovery testing       | AWS Backup + test restores

5. INTERVIEW QUESTIONS
================================================================

Q: What are the 6 pillars of the AWS Well-Architected Framework?
A: Operational Excellence (run and improve systems), Security (protect data
   and systems), Reliability (recover from failures), Performance Efficiency
   (use resources efficiently), Cost Optimization (deliver value at lowest cost),
   and Sustainability (minimize environmental impact). Mnemonic: OSRPCS.

Q: A client asks you to design a highly available, cost-effective architecture
   for a web application. Which Well-Architected pillars apply?
A: Primarily Reliability (multi-AZ, auto scaling, ELB), Cost Optimization
   (Savings Plans for EC2, S3 lifecycle, right-sizing), and Performance
   Efficiency (caching with ElastiCache/CloudFront, right instance types).
   Also Security (IAM roles, encryption, WAF) and Operational Excellence
   (IaC, CI/CD pipeline, CloudWatch monitoring).

Q: What is the principle of "least privilege" and which pillar does it belong to?
A: Least privilege means granting only the minimum permissions required to
   perform a task — nothing more. It belongs to the Security pillar. In AWS,
   implement via IAM policies that restrict actions, resources, and conditions.
   Avoid wildcard (*) permissions in production. Use IAM Access Analyzer to
   find overly permissive policies.

Q: What does "stop guessing capacity" mean in the Well-Architected Framework?
A: This principle from the Reliability pillar means you should NOT pre-provision
   fixed capacity guessing what you'll need. Instead, use Auto Scaling to
   automatically adjust EC2 instances based on actual demand. This eliminates
   both under-provisioning (performance issues) and over-provisioning (wasted cost).
