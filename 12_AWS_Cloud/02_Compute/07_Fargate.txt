AWS COMPUTE — FARGATE (SERVERLESS CONTAINERS)
Complete Interview Preparation Guide
================================================================

1. WHAT IS AWS FARGATE?
================================================================

AWS Fargate is a serverless compute engine for containers. It removes the
need to provision, manage, and scale EC2 instances for your containers.

Key principle: You define the container requirements (CPU, memory) and AWS
manages the underlying infrastructure.

Works with:
  - Amazon ECS (ECS on Fargate)
  - Amazon EKS (EKS Fargate Profiles)

================================================================
2. FARGATE vs EC2 LAUNCH TYPE
================================================================

  ┌─────────────────────────────────────────────────────────────────┐
  │ ASPECT             │ EC2 LAUNCH TYPE       │ FARGATE            │
  ├─────────────────────────────────────────────────────────────────┤
  │ Server management  │ You manage EC2        │ AWS manages all    │
  │ OS patches         │ You patch             │ AWS patches        │
  │ Scaling            │ You scale EC2 + tasks │ Only scale tasks   │
  │ Cost model         │ EC2 + ECS overhead    │ Per vCPU + memory  │
  │ Visibility         │ Full EC2 access       │ No host access     │
  │ Network mode       │ awsvpc, bridge, host  │ awsvpc ONLY        │
  │ Persistent storage │ EBS, EFS, instance    │ EFS only (no EBS)  │
  │ Long-running       │ Yes                   │ Yes                │
  │ GPU support        │ Yes                   │ No                 │
  │ Custom daemon      │ Yes (DaemonSet in EKS)│ No                 │
  └─────────────────────────────────────────────────────────────────┘

3. FARGATE PRICING MODEL
================================================================

  Charge: per vCPU-hour + per GB-memory-hour (only while task runs)
  
  No charge for:
    - Idle capacity
    - EC2 instances
    - ECS control plane
  
  Example Cost (us-east-1 approximate):
    vCPU: ~$0.04048/vCPU-hour
    Memory: ~$0.004445/GB-hour
    
    Task: 1 vCPU + 2 GB RAM running 24 hrs/day:
    = (0.04048 × 1 × 720) + (0.004445 × 2 × 720)
    = $29.15 + $6.40 = ~$35.55/month
    
    vs t3.medium (2 vCPU, 4GB) On-Demand: ~$30/month
    → For always-on tasks, EC2 may be cheaper
    → For bursty or variable workloads, Fargate saves money (no idle EC2)

  SAVINGS: Use Fargate Savings Plans (1 or 3 year) for up to 52% savings
           on Fargate compute

4. ECS ON FARGATE — ARCHITECTURE
================================================================

  DEPLOYMENT ARCHITECTURE:
  
  Internet
     │
     ▼
  ALB (Public Subnets: us-east-1a, us-east-1b)
     │
     ▼
  ECS Service (Fargate)
  ┌─────────────────────────────────────────────────────────────┐
  │  Private Subnet us-east-1a │  Private Subnet us-east-1b    │
  │  ┌──────────────────────┐  │  ┌──────────────────────┐     │
  │  │  Fargate Task        │  │  │  Fargate Task        │     │
  │  │  [Java App Container]│  │  │  [Java App Container]│     │
  │  │  ENI: 10.0.1.x       │  │  │  ENI: 10.0.2.x       │     │
  │  └──────────────────────┘  │  └──────────────────────┘     │
  └─────────────────────────────────────────────────────────────┘
     │
     ▼
  RDS (Private Subnet)

  KEY POINTS:
    - Each Fargate task gets its own ENI (awsvpc mode is required)
    - Tasks run in private subnets (no direct internet access needed)
    - Tasks use NAT Gateway to pull images from ECR / call AWS APIs
    - ALB routes traffic to task ENI IPs

5. EKS FARGATE PROFILES
================================================================

  EKS Fargate Profiles tell EKS which pods should run on Fargate vs EC2.
  Match is by namespace + labels.

  # Create Fargate profile
  eksctl create fargateprofile \
    --cluster my-cluster \
    --name my-fargate-profile \
    --namespace my-namespace \
    --labels app=my-app

  ARCHITECTURE with Fargate Profile:
    - Pods matching the profile → scheduled on Fargate nodes
    - Pods NOT matching → scheduled on EC2 managed node groups
    - Useful for: burst capacity (keep small EC2 base, burst to Fargate)

  LIMITATIONS with EKS Fargate:
    - No DaemonSets (can't run something on every node)
    - No GPU support
    - No Stateful workloads with EBS (use EFS)
    - No privileged containers
    - Each pod is isolated on its own compute (no pod co-location)

6. FARGATE STORAGE
================================================================

  EPHEMERAL STORAGE:
    - Each task gets 20 GB of ephemeral storage (expandable to 200 GB)
    - Lost when the task stops
    - Use for temp files, logs, etc.

  PERSISTENT STORAGE — EFS (Elastic File System):
    - Mount an EFS file system into a Fargate task
    - Data persists beyond task lifecycle
    - Shared across multiple tasks simultaneously
    - Use for: shared configuration files, persistent data, content
    
    Task Definition (EFS volume):
    {
      "volumes": [{
        "name": "shared-data",
        "efsVolumeConfiguration": {
          "fileSystemId": "fs-12345678",
          "rootDirectory": "/",
          "transitEncryption": "ENABLED",
          "authorizationConfig": {
            "accessPointId": "fsap-12345678",
            "iam": "ENABLED"
          }
        }
      }],
      "containerDefinitions": [{
        "mountPoints": [{
          "sourceVolume": "shared-data",
          "containerPath": "/app/data"
        }]
      }]
    }

7. NETWORKING DEEP DIVE (awsvpc)
================================================================

  EVERY Fargate task gets its own:
    - Elastic Network Interface (ENI)
    - Private IP address from the subnet
    - Security group (separate from other tasks!)
    
  This means:
    - Fine-grained security group per task (not per EC2 host)
    - Direct IP routing (no port mapping complexity)
    - Tasks in different subnets can have different network rules
  
  PRIVATE SUBNET + ECR ACCESS:
    For Fargate tasks in private subnets to pull ECR images, you need either:
    Option 1: NAT Gateway in public subnet → internet route to ECR
    Option 2: VPC Endpoints for ECR (ecr.api and ecr.dkr) + S3 Gateway endpoint
              (ECR stores layers in S3 behind the scenes)
              → More secure, no NAT Gateway cost

8. INTERVIEW QUESTIONS
================================================================

Q: What is the difference between Fargate and EC2 launch type for ECS?
A: With EC2 launch type, you provision and manage EC2 instances as ECS container
   hosts — you're responsible for EC2 capacity, patching, and scaling the instances
   (in addition to scaling the tasks). With Fargate, AWS manages all infrastructure;
   you only specify CPU/memory per task and pay for what you use. Fargate is simpler
   (no EC2 management), but EC2 may be cheaper for always-on, high-density workloads.

Q: Can Fargate tasks use EBS for persistent storage?
A: No. Fargate does NOT support EBS volumes (EBS must attach to a specific EC2 instance).
   For persistent storage in Fargate, use Amazon EFS (Elastic File System), which
   can be mounted by multiple tasks simultaneously and persists beyond task lifecycle.
   Each task also gets 20-200GB of ephemeral storage for temporary use.

Q: Why do Fargate tasks in private subnets need a NAT Gateway or VPC endpoints?
A: Fargate tasks in private subnets have no direct internet access, but they need to:
   pull container images from ECR, call AWS APIs (Secrets Manager, CloudWatch), etc.
   A NAT Gateway in a public subnet provides internet access for egress traffic.
   Alternatively, VPC Endpoints for ECR API, ECR DKR, and S3 gateway endpoint provide
   private routing to AWS services without internet traffic — more secure and avoids
   NAT Gateway data processing costs.

Q: When would you choose Fargate over EC2 for running containers?
A: Choose Fargate when: you want zero EC2 management, workloads are variable/bursty
   (pay only for running tasks), you're running multiple small microservices
   (efficient resource utilization), or you prioritize security isolation (each task
   has its own compute). Choose EC2 when: you need GPUs, need DaemonSets (EKS),
   need very specific instance types, run continuously at high density where EC2
   Reserved Instances are more cost-effective, or need access to instance-level features.

Q: What network mode does Fargate use and what are the implications?
A: Fargate requires awsvpc network mode. This means each task gets its own ENI
   (Elastic Network Interface) with a unique private IP from the VPC subnet.
   Implications: security groups apply per task (fine-grained security),
   direct IP routing (no docker networking or port mapping complexity),
   but you consume VPC IPs quickly with many tasks (plan subnet sizing carefully).
