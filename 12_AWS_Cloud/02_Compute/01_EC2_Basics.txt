AWS COMPUTE — EC2 BASICS
Complete Interview Preparation Guide
================================================================

1. WHAT IS AMAZON EC2?
================================================================

Amazon Elastic Compute Cloud (EC2) provides resizable virtual machines
(instances) in the cloud. You have full control over the operating system,
networking, storage, and software.

Key characteristics:
  - IaaS: Infrastructure as a Service
  - Virtual machines running on physical AWS hardware
  - Available in dozens of instance types for different workloads
  - Pay per second (Linux) or per hour (Windows) when running

================================================================
2. EC2 INSTANCE LIFECYCLE
================================================================

  STATES:
    pending      → Instance is launching
    running      → Instance is running (billing starts here)
    stopping     → Instance is stopping (EBS-backed)
    stopped      → Instance is stopped (EBS preserved, no CPU/RAM billing)
    shutting-down → Instance terminating
    terminated   → Instance deleted (cannot restart)
    rebooting    → Instance rebooting (stays on same host)
  
  KEY BILLING RULES:
    - RUNNING: Full instance + EBS charges
    - STOPPED: EBS storage charges only (no compute)
    - TERMINATED: No charges (EBS deleted unless set to retain)
    - REBOOTING: Continues billing (instance stays on same host)
  
  STOP vs TERMINATE vs HIBERNATE:
    Stop:      EBS data preserved; public IP changes; RAM lost
    Terminate: EBS deleted (unless DeleteOnTermination=false); everything gone
    Hibernate: RAM contents saved to EBS; fast startup; requires encrypted EBS

3. LAUNCHING AN EC2 INSTANCE
================================================================

REQUIRED CHOICES:
  1. AMI (Amazon Machine Image) — OS + pre-installed software
  2. Instance Type — CPU, RAM, network specs (e.g., t3.micro)
  3. Network (VPC + Subnet) — where in your network
  4. IAM Role (optional but recommended) — permissions for the instance
  5. Storage (EBS root volume + additional volumes)
  6. Security Group — firewall rules
  7. Key Pair — SSH access (Linux) or RDP password decryption (Windows)

CLI EXAMPLE:
  aws ec2 run-instances \
    --image-id ami-0c55b159cbfafe1f0 \
    --instance-type t3.micro \
    --key-name MyKeyPair \
    --security-group-ids sg-0123456789abcdef0 \
    --subnet-id subnet-0123456789abcdef0 \
    --iam-instance-profile Name=EC2AppRole \
    --user-data file://bootstrap.sh \
    --count 1 \
    --tag-specifications 'ResourceType=instance,Tags=[{Key=Name,Value=WebServer}]'

USER DATA (Bootstrap Script):
  #!/bin/bash
  yum update -y
  yum install -y java-17-amazon-corretto
  aws s3 cp s3://my-bucket/app.jar /home/ec2-user/app.jar
  java -jar /home/ec2-user/app.jar &

4. EC2 INSTANCE TYPES — FAMILIES
================================================================

  FAMILY FORMAT: [family][generation].[size]
  Example: t3.micro, m5.xlarge, r6g.2xlarge

  ┌──────────────────────────────────────────────────────────────┐
  │ FAMILY │ DESCRIPTION            │ USE CASE                   │
  ├────────┼───────────────────────────────────────────────────── │
  │  T     │ Burstable performance  │ Dev/test, low-traffic web  │
  │        │ (T2, T3, T4g)          │ apps, microservices        │
  │  M     │ General purpose        │ App servers, databases,    │
  │        │ (M5, M6i, M7g)         │ backend services           │
  │  C     │ Compute optimized      │ HPC, batch processing,     │
  │        │ (C5, C6i, C7g)         │ media encoding, ML         │
  │  R     │ Memory optimized       │ In-memory caches,          │
  │        │ (R5, R6i, X1)          │ big data, SAP HANA         │
  │  X     │ Extreme memory         │ SAP HANA, in-memory DB     │
  │  I     │ Storage optimized      │ High IOPS, NoSQL DBs,      │
  │        │ (I3, I4i)              │ data warehousing           │
  │  D     │ Dense storage          │ Hadoop, data lakes, NFS    │
  │  P/G   │ GPU compute            │ ML training, inference,    │
  │        │ (P3, P4, G4, G5)       │ video transcoding          │
  │  Inf   │ AWS Inferentia         │ ML inference (cost-optimized)│
  │  Trn   │ AWS Trainium           │ ML training on AWS silicon  │
  └────────┴───────────────────────┴────────────────────────────┘

  SIZE SCALE (within a family):
    nano → micro → small → medium → large → xlarge → 2xlarge → 4xlarge → ... → 32xlarge

  ARM/Graviton:
    - AWS Graviton (g suffix): t4g, m6g, c6g, r6g
    - Up to 40% better price/performance for many workloads
    - Requires ARM-compatible AMI and software

5. KEY PAIRS AND SSH ACCESS
================================================================

  KEY PAIR:
  - RSA or ED25519 key pair
  - Private key (.pem file) stored by you
  - Public key stored on the EC2 instance (in ~/.ssh/authorized_keys)
  - Used to SSH into Linux instances or decrypt Windows admin password

  CREATE KEY PAIR:
    aws ec2 create-key-pair \
      --key-name MyKeyPair \
      --query 'KeyMaterial' \
      --output text > MyKeyPair.pem
    chmod 400 MyKeyPair.pem

  SSH TO EC2 (Linux):
    ssh -i MyKeyPair.pem ec2-user@PUBLIC_IP_ADDRESS
    # Amazon Linux: ec2-user
    # Ubuntu: ubuntu
    # RHEL: ec2-user or root
    # CentOS: centos

  ALTERNATIVE (AWS Systems Manager Session Manager):
    - No key pair needed
    - No inbound SSH port 22 needed
    - Full audit trail in CloudTrail
    - aws ssm start-session --target i-1234567890abcdef0

6. SECURITY GROUPS
================================================================

  WHAT IT IS: Virtual firewall for EC2 instances (stateful)

  STATEFUL: If you allow inbound traffic, the response is automatically allowed
            even if there's no explicit outbound rule (and vice versa)

  RULES:
    - Inbound: controls traffic coming TO the instance
    - Outbound: controls traffic LEAVING the instance (default: all outbound allowed)
    - No "Deny" rules — only Allow
    - Default: all inbound DENIED, all outbound ALLOWED

  COMMON RULES:
    Type         Protocol  Port  Source
    SSH          TCP       22    Your IP (0.0.0.0/0 is INSECURE)
    HTTP         TCP       80    0.0.0.0/0
    HTTPS        TCP       443   0.0.0.0/0
    Custom TCP   TCP       8080  Application Load Balancer SG ID
    MySQL        TCP       3306  App Server SG ID (reference by SG, not IP)

  SECURITY GROUP REFERENCING:
    Instead of allowing specific IP, allow another security group.
    Example: DB security group allows inbound 3306 from App SG.
    Any instance in App SG can connect to DB. Dynamic — scales with Auto Scaling.

7. ELASTIC IP ADDRESSES
================================================================

  - A static public IPv4 address you can allocate to your AWS account
  - Persists through instance stop/start (normal public IP changes on restart)
  - Can be remapped to different instances (useful for failover)
  - Max 5 Elastic IPs per region (can request increase)
  - COST: Free while attached to running instance. CHARGED when not associated!

  # Allocate and associate
  aws ec2 allocate-address --domain vpc
  aws ec2 associate-address --instance-id i-1234567890abcdef0 \
    --allocation-id eipalloc-12345678

  Best Practice: Use DNS (Route 53) and Load Balancers instead of Elastic IPs
  to avoid the per-IP cost and management overhead.

================================================================
8. EC2 PLACEMENT GROUPS
================================================================

  CLUSTER:
    - All instances in the SAME rack in the SAME AZ
    - Lowest latency, highest throughput (10 Gbps+ network)
    - Risk: If rack fails, all instances fail
    - Use case: HPC, big data processing, ML training

  SPREAD:
    - Each instance on a DIFFERENT physical rack
    - Max 7 instances per AZ per placement group
    - Reduces correlated hardware failures
    - Use case: Critical applications needing high availability

  PARTITION:
    - Groups instances into "partitions" (racks)
    - Each partition is on different hardware
    - Up to 7 partitions per AZ, hundreds of instances per partition
    - Use case: Hadoop, Cassandra, Kafka (distributed systems that
      understand topology — can spread replicas across partitions)

9. INTERVIEW QUESTIONS
================================================================

Q: What is the difference between stopping and terminating an EC2 instance?
A: Stopping an EC2 instance (EBS-backed) halts computation while preserving the
   EBS root volume. You're only charged for EBS storage, not compute. When restarted,
   the instance may land on different hardware, and the public IP changes.
   Terminating permanently deletes the instance — EBS root volume is deleted
   by default (unless DeleteOnTermination=false). Data on instance store volumes
   is always lost on stop/terminate. Use stop for instances you want to restart;
   terminate when done permanently.

Q: What is the difference between a Security Group and a NACL?
A: Security Groups are stateful (return traffic automatically allowed) firewalls
   at the INSTANCE level — they only have Allow rules. NACLs (Network ACLs) are
   stateless (must explicitly allow return traffic) firewalls at the SUBNET level
   — they have both Allow and Deny rules and evaluate rules in numbered order
   (lowest number first). Security groups are the primary access control;
   NACLs are an additional subnet-level layer, useful for blocking specific IPs.

Q: What is EC2 user data used for?
A: User data is a script that runs once at instance first launch for bootstrapping.
   It's used to install software (Java, web servers), download application code from
   S3, configure services, set environment variables, etc. It runs as root on the
   instance. For production, prefer building "golden AMIs" with software pre-installed
   instead of bootstrapping at launch (faster startup, more predictable).

Q: What are EC2 placement groups and when would you use each type?
A: Cluster placement puts all instances in the same rack for ultra-low latency and
   high network throughput — use for HPC and ML training. Spread placement puts each
   instance on different racks — use for critical applications where hardware failure
   of one instance shouldn't affect others (max 7 per AZ). Partition placement creates
   partition groups of instances on different racks — use for distributed systems like
   Kafka or Cassandra that spread replicas across partitions for fault tolerance.

Q: What are the differences between instance types t3, m5, c5, and r5?
A: T3 is burstable — baseline CPU with ability to burst using accumulated CPU credits.
   Good for workloads with variable CPU (dev, test, small web apps). M5 is balanced
   general purpose (equal CPU/memory ratio). C5 is compute-optimized (more CPU per RAM)
   for CPU-intensive workloads (encoding, HPC). R5 is memory-optimized (more RAM per CPU)
   for memory-intensive workloads (Redis, SAP HANA, large JVM heaps).
