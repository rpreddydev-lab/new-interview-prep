2. CHOOSING THE RIGHT STORAGE
================================================================

  Is data accessed as OBJECTS (files, blobs)? → S3 or Glacier
    - Large files, images, videos: S3 Standard
    - Infrequently accessed: S3 IA
    - Archive (rarely accessed): S3 Glacier
  
  Does your EC2 instance need a DISK? → EBS
    - Root OS volume
    - Database on EC2 (MySQL, PostgreSQL)
    - High IOPS database: io2 Block Express
    - General purpose: gp3
  
  Need SHARED access across multiple EC2/ECS instances? → EFS or FSx
    - Linux shared filesystem: EFS
    - Windows shared filesystem: FSx for Windows
    - High-performance computing: FSx for Lustre

================================================================
3. OBJECT vs BLOCK vs FILE STORAGE
================================================================

  OBJECT STORAGE (S3):
    - Flat namespace — no directory hierarchy (prefix simulates it)
    - Access via HTTP/REST API (get/put/delete objects)
    - Versioning, lifecycle policies, cross-region replication
    - Cannot be mounted as a filesystem natively
    - Unlimited scale

  BLOCK STORAGE (EBS):
    - Works like a physical hard disk attached to EC2
    - Formatted with a filesystem (ext4, NTFS)
    - Low-latency, random read/write
    - Single attachment (one EC2 at a time, except io1/io2 Multi-Attach)
    - Size limited (EBS max 64 TB per volume)

  FILE STORAGE (EFS):
    - Standard filesystem (NFS protocol)
    - Mounted on multiple EC2 instances simultaneously
    - Shared read/write access
    - Automatically grows/shrinks
    - Higher latency than EBS (network file system)

================================================================
4. KEY CONCEPTS
================================================================

  S3 KEY CONCEPTS:
    Bucket: top-level container (globally unique name)
    Object: file + metadata stored in bucket
    Key: unique identifier for object within bucket (like a path)
    Region: bucket is created in a specific region
    Prefix: simulates folder hierarchy (myapp/2024/01/logs.txt)
    
  EBS KEY CONCEPTS:
    Volume: block storage device
    Snapshot: point-in-time backup stored in S3 (incremental)
    IOPS: input/output operations per second (performance metric)
    Throughput: MB/s (sequential read/write)
    
  EFS KEY CONCEPTS:
    File system: regional or one-zone, serverless NFS
    Mount target: NFS endpoint in each AZ
    Access point: application-specific entry point with user/group

================================================================
5. DURABILITY AND AVAILABILITY
================================================================

  S3 Standard:
    - Durability: 99.999999999% (11 nines) — designed for 0.000000001% loss per year
    - Availability: 99.99%
    - Replicated across ≥3 AZs

  EBS:
    - Durability: 99.8-99.9% (depending on type) per year
    - Replicated WITHIN a single AZ
    - To protect from AZ failure: use EBS Snapshots to S3

  EFS:
    - Standard class: replicated across ≥3 AZs
    - One Zone: replicated within one AZ (cheaper, lower durability)
    - Availability: 99.99% (Standard)

================================================================
6. INTERVIEW QUESTIONS
================================================================

Q: What is the difference between S3, EBS, and EFS?
A: S3 is object storage — accessed via HTTP/REST API, unlimited scale, globally
   accessible, not mountable as filesystem. Used for files, backups, data lakes.
   EBS is block storage — works like a hard disk attached to a single EC2 instance
   (formattes as ext4/NTFS), low-latency, AZ-specific. Used for EC2 OS volumes,
   databases. EFS is shared file storage — NFS filesystem mounted across multiple
   EC2/ECS instances simultaneously, auto-scales. Used for shared content,
   multi-instance applications.

Q: What is S3's durability guarantee?
A: S3 Standard provides 99.999999999% (11 nines) durability. This means if you
   store 10 million objects, you might lose one object every 10,000 years on average.
   S3 achieves this by replicating data across at least 3 Availability Zones
   automatically. This is one of the strongest durability guarantees in cloud storage.

Q: What storage should you use for an EC2 database that needs high IOPS?
A: Amazon EBS with the io2 Block Express type for the highest IOPS (up to 256,000
   IOPS) and sub-millisecond latency. For most production databases, gp3 EBS provides
   good performance at lower cost (3,000 IOPS baseline, provisioned up to 16,000 IOPS
   independent of size). The EBS volume lives in the same AZ as the EC2 instance.
   For cross-AZ durability, use automated EBS snapshots to S3 or RDS with Multi-AZ.
