AWS NETWORKING — VPC BASICS
Complete Interview Preparation Guide
================================================================

1. VPC FUNDAMENTALS
================================================================

  VPC (Virtual Private Cloud) = your own private network inside AWS.
  
  Key properties:
    - Region-scoped (a VPC spans all AZs in a region)
    - IP range defined by CIDR block (e.g., 10.0.0.0/16)
    - Min CIDR: /28 (16 IPs), Max CIDR: /16 (65,536 IPs)
    - Can have up to 5 additional CIDR blocks associated
    - Default VPC exists in every region (172.31.0.0/16)
    - Soft limit: 5 VPCs per region (can request increase)

  DEFAULT VPC:
    - Created automatically in every region
    - CIDR: 172.31.0.0/16
    - One /20 public subnet per AZ
    - Internet Gateway attached by default
    - All instances get public IPs by default
    - Good for quick testing; NOT for production workloads

================================================================
2. CREATING A VPC
================================================================

  aws ec2 create-vpc \
    --cidr-block 10.0.0.0/16 \
    --region us-east-1

  # Enable DNS hostname resolution in the VPC (required for ECS, EKS, etc.)
  aws ec2 modify-vpc-attribute \
    --vpc-id vpc-12345678 \
    --enable-dns-hostnames

  # Enable DNS resolution
  aws ec2 modify-vpc-attribute \
    --vpc-id vpc-12345678 \
    --enable-dns-support

================================================================
3. INTERNET GATEWAY (IGW)
================================================================

  Allows communication between VPC and the internet.
  
  Properties:
    - One IGW per VPC (1:1 relationship)
    - Scales horizontally, redundant, highly available by AWS
    - No bandwidth limits, no per-hour cost (data transfer costs still apply)
    - Two functions:
        1. Target in route tables for internet-bound traffic
        2. Performs 1:1 NAT for instances with Elastic IPs

  Attach IGW to VPC:
  aws ec2 create-internet-gateway
  aws ec2 attach-internet-gateway \
    --internet-gateway-id igw-12345678 \
    --vpc-id vpc-12345678

  For a subnet to be "public": it needs a route to the IGW:
  Route: 0.0.0.0/0 → igw-12345678

================================================================
4. NAT GATEWAY
================================================================

  Allows PRIVATE subnet instances to initiate OUTBOUND internet connections.
  Inbound connections from internet to private instances are NOT allowed.
  
  Properties:
    - MUST be placed in a PUBLIC subnet
    - Requires an Elastic IP address
    - Managed service (highly available within one AZ)
    - Bandwidth: up to 100 Gbps
    - Cost: ~$0.045/hour + $0.045/GB processed
    - NOT free tier eligible

  For High Availability:
    - Create one NAT Gateway PER AZ
    - Private subnets in AZ-a route to NAT-a; AZ-b private subnets → NAT-b
    - If you use ONE NAT Gateway in AZ-a and it fails, ALL private subnets lose internet

  Create NAT Gateway:
  aws ec2 create-nat-gateway \
    --subnet-id subnet-public-12345678 \
    --allocation-id eipalloc-12345678

  Private subnet route table:
  0.0.0.0/0 → nat-gateway-id

  NAT Gateway vs NAT Instance (legacy):
  ┌────────────────────┬───────────────────────┬─────────────────────┐
  │ Feature            │ NAT Gateway           │ NAT Instance        │
  ├────────────────────┼───────────────────────┼─────────────────────┤
  │ Managed            │ Yes (AWS-managed)     │ No (self-managed EC2)│
  │ Availability       │ HA within AZ          │ Single instance     │
  │ Bandwidth          │ 100 Gbps              │ Depends on EC2 type │
  │ Security Groups    │ No (no SG applied)    │ Yes                 │
  │ Bastion host       │ Cannot use as bastion │ Can use as bastion  │
  │ Cost               │ Pay per hour + data   │ EC2 instance cost   │
  │ Recommendation     │ Always prefer         │ Legacy, avoid       │
  └────────────────────┴───────────────────────┴─────────────────────┘

5. VPC ENDPOINTS
================================================================

  Connect to AWS services PRIVATELY without going through the internet.
  No internet, no NAT Gateway, no data transfer cost for endpoint traffic.
  
  GATEWAY ENDPOINTS:
    - Supported services: S3 and DynamoDB ONLY
    - Free to use
    - Adds a route in your route table pointing to the endpoint
    - S3 traffic from EC2: private network → S3 (never leaves AWS network)
    
    aws ec2 create-vpc-endpoint \
      --vpc-id vpc-12345678 \
      --service-name com.amazonaws.us-east-1.s3 \
      --route-table-ids rtb-12345678

  INTERFACE ENDPOINTS (AWS PrivateLink):
    - Supported services: Almost ALL AWS services (EC2, STS, Secrets Manager, SNS, SQS, etc.)
    - Creates an ENI (Elastic Network Interface) in your subnet with a private IP
    - Hourly cost + data processing cost (~$0.01/hour per AZ per endpoint)
    - Use when: EC2 in private subnet needs to call AWS APIs without internet/NAT
    - Security: can attach Security Groups to the ENI

6. FLOW LOGS
================================================================

  Captures IP traffic information going to/from network interfaces in VPC.
  
  Capture levels: VPC, Subnet, ENI
  Destinations: CloudWatch Logs, S3, Kinesis Data Firehose
  
  Fields captured:
    srcaddr dstaddr srcport dstport protocol packets bytes start end action
  
  Create VPC flow logs:
  aws ec2 create-flow-logs \
    --resource-type VPC \
    --resource-ids vpc-12345678 \
    --traffic-type ALL \
    --log-destination-type cloud-watch-logs \
    --log-group-name /vpc/flowlogs \
    --deliver-logs-permission-arn arn:aws:iam::123456789012:role/FlowLogsRole

  Use cases:
    - Troubleshoot connectivity issues (check if traffic is REJECT or ACCEPT)
    - Security investigation (find unusual traffic patterns)
    - Compliance logging

================================================================
7. ELASTIC NETWORK INTERFACE (ENI)
================================================================

  A virtual network card that can be attached to EC2 instances.
  
  Properties:
    - Bound to a specific AZ
    - Has primary private IP, can have secondary private IPs
    - Can have Elastic IP (public IP that persists)
    - Can have Security Groups (multiple)
    - Can be detached from one EC2 and attached to another (useful for failover)
  
  Use case for multiple ENIs:
    - Create an ENI on each subnet, attach to EC2 for dual-homing
    - Management network on one ENI, production traffic on another
    - Network appliances (firewalls) that need separate interfaces

8. INTERVIEW QUESTIONS
================================================================

Q: What is the difference between a NAT Gateway and an Internet Gateway?
A: Internet Gateway (IGW) enables two-way internet communication for resources
   WITH public IPs in public subnets. It's bidirectional — internet traffic
   can reach your instances (inbound) and your instances can reach the internet
   (outbound). NAT Gateway is one-directional: private subnet instances can
   initiate OUTBOUND connections to the internet (for updates, API calls), but
   the internet cannot initiate connections INTO your private instances. NAT
   Gateway itself sits in a public subnet and routes private traffic through the IGW.

Q: Why place a NAT Gateway per AZ instead of one shared NAT Gateway?
A: Cross-AZ data transfer costs money ($0.01/GB). If you have one NAT Gateway
   in AZ-a and private subnets in AZ-b and AZ-c, their traffic crosses AZs
   to reach the NAT Gateway — you pay cross-AZ data transfer fees. More critically,
   if the single NAT Gateway's AZ fails, all private subnets in other AZs lose
   internet access. Best practice: create a NAT Gateway in EACH AZ, and each
   AZ's private subnets route to their local NAT Gateway.

Q: What are VPC endpoints and why would you use them?
A: VPC endpoints let services in your VPC communicate with AWS services over
   the AWS private network instead of the internet. Benefits: more secure
   (no internet exposure), cheaper (no data transfer charges through NAT for
   S3/DynamoDB Gateway endpoints), lower latency. Gateway endpoints (free) work
   for S3 and DynamoDB. Interface endpoints (PrivateLink, hourly cost) work for
   nearly all AWS services. Use them when: EC2 instances in private subnets need
   to access S3 or DynamoDB (use gateway), or call AWS APIs like STS, Secrets
   Manager, etc., without routing through NAT Gateway.

Q: What information does VPC Flow Logs capture?
A: Flow logs capture metadata about IP traffic — source/dest IPs, ports, protocol,
   packet/byte counts, action (ACCEPT/REJECT), start/end time. They don't capture
   the actual packet contents. Use cases: debug connectivity issues (REJECT records
   show what's being blocked), security incident investigation, identify unusual
   traffic patterns, compliance logging. Flow logs do have a small delay — not
   real-time, typically available within minutes.
