================================================================
AWS NETWORKING — VPN AND DIRECT CONNECT
Complete Interview Preparation Guide
================================================================

1. HYBRID CONNECTIVITY OPTIONS
================================================================

  When you need to connect your on-premises network to AWS:
    Site-to-Site VPN:   Encrypted tunnel over the PUBLIC internet
    Direct Connect:     Dedicated PRIVATE physical connection (not internet)
    Direct Connect + VPN: Direct Connect for bandwidth, VPN for encryption fallback

  Use VPN when: quick setup needed, moderate bandwidth, cost-sensitive
  Use Direct Connect when: high bandwidth, low latency, consistent performance, compliance

================================================================
2. SITE-TO-SITE VPN
================================================================

  Creates an encrypted IPSec tunnel between:
    - AWS: Virtual Private Gateway (VGW) attached to your VPC
    - On-premises: Customer Gateway (your router/firewall)

  COMPONENTS:
    Virtual Private Gateway (VGW):
      - AWS-side VPN endpoint
      - Attached to your VPC
      - Highly available within AWS

    Customer Gateway (CGW):
      - On-premises router or firewall (physical or software)
      - You configure the CGW device with the AWS tunnel settings
      - Represents your side of the VPN

    VPN Connection:
      - Links VGW to CGW
      - Creates TWO IPSec tunnels (for redundancy — each to a different AZ)
      - Each tunnel: 1.25 Gbps max bandwidth

  ROUTING:
    Static routing:  You manually configure routes on both sides
    Dynamic routing: BGP (Border Gateway Protocol) — recommended for automatic route propagation

  Enable VGW route propagation to VPC route table:
  aws ec2 enable-vgw-route-propagation \
    --route-table-id rtb-12345678 \
    --gateway-id vgw-12345678
  # This automatically adds on-premises CIDR routes

  Create VPN:
  # 1. Create Virtual Private Gateway
  aws ec2 create-vpn-gateway \
    --type ipsec.1 \
    --amazon-side-asn 64512

  # 2. Attach to VPC
  aws ec2 attach-vpn-gateway \
    --vpn-gateway-id vgw-12345678 \
    --vpc-id vpc-12345678

  # 3. Create Customer Gateway (your on-premises device)
  aws ec2 create-customer-gateway \
    --type ipsec.1 \
    --public-ip 203.0.113.1 \
    --bgp-asn 65000

  # 4. Create VPN connection
  aws ec2 create-vpn-connection \
    --type ipsec.1 \
    --customer-gateway-id cgw-12345678 \
    --vpn-gateway-id vgw-12345678 \
    --options '{"StaticRoutesOnly":false}'

  CONSIDERATIONS:
    - Traffic goes over public internet (encrypted)
    - Latency varies based on internet congestion
    - Setup time: minutes to hours
    - Cost: ~$0.05/hour per VPN connection + data transfer

================================================================
3. AWS CLIENT VPN (Remote Access VPN)
================================================================

  Different from Site-to-Site — for individual users (employees) to connect
  to AWS VPC resources from their laptops.
  
  Uses OpenVPN-based protocol.
  Authentication: Active Directory, SAML, certificate-based.
  
  Use case: Remote employees need secure access to private VPC resources
  (databases, internal apps) from home/coffee shop.

================================================================
4. AWS DIRECT CONNECT (DX)
================================================================

  A DEDICATED physical network connection from your data center to AWS.
  Does NOT use the public internet.
  
  Benefits:
    - Consistent, predictable network performance
    - High bandwidth: 1 Gbps, 10 Gbps, 100 Gbps
    - Lower data transfer rates (vs internet)
    - Required for: financial services, healthcare, high-bandwidth data migrations

  CONNECTION TYPES:
    Dedicated Connection:
      - Direct physical connection at a DX location
      - 1 Gbps, 10 Gbps, or 100 Gbps
      - Ordered through AWS; takes weeks to provision

    Hosted Connection (via DX Partners):
      - Connection through an AWS Direct Connect Partner
      - Speeds: 50 Mbps to 10 Gbps
      - Faster to provision than dedicated
      - Partners: AT&T, Verizon, Equinix, Colt, etc.

  VIRTUAL INTERFACES (VIFs):
    Private VIF:   Access resources in your VPC (private IPs)
    Public VIF:    Access AWS public endpoints (S3, DynamoDB) without internet
    Transit VIF:   Connect to AWS Transit Gateway (many VPCs at once)

  ARCHITECTURE:
    [On-Premises Data Center]
           │ Physical cross-connect (router)
    [AWS Direct Connect Location (colocation facility)]
           │ Direct Connect Link
    [AWS Region]
           ↓
    [Private VIF → Virtual Private Gateway → VPC]
    or
    [Public VIF → AWS Public Services (S3, DynamoDB)]

================================================================
5. DIRECT CONNECT RESILIENCE
================================================================

  Single DX Connection = SINGLE POINT OF FAILURE

  HIGH AVAILABILITY OPTIONS:
    Resilient (recommended for non-critical):
      - Two connections at two different DX locations
    
    Maximum Resiliency (for mission-critical):
      - Two DX locations
      - Two connections per location
      - Four total connections, completely independent
    
    VPN as failover:
      - Primary: Direct Connect
      - Failover: Site-to-Site VPN (uses internet — slower but stays up)
      - Configure with BGP route preferences

================================================================

  │ Feature                  │ Site-to-Site VPN        │ Direct Connect           │
  ├──────────────────────────┼─────────────────────────┼──────────────────────────┤
  │ Connection type          │ Over public internet    │ Dedicated physical line  │
  │ Encryption               │ Yes (IPSec)             │ No (must add VPN on top) │
  │ Bandwidth                │ Up to 1.25 Gbps         │ 1 / 10 / 100 Gbps        │
  │ Latency                  │ Variable (internet)     │ Consistent, predictable  │
  │ Setup time               │ Minutes to hours        │ Weeks to months          │
  │ Cost                     │ Low                     │ High (port + data fees)  │
  │ Availability             │ Internet-dependent      │ High (with redundancy)   │
  │ Use case                 │ Quick setup, low cost   │ High throughput, compliance│

7. INTERVIEW QUESTIONS
================================================================

Q: What is the difference between Site-to-Site VPN and Direct Connect?
A: Site-to-Site VPN creates an encrypted IPSec tunnel over the PUBLIC internet
   between your on-premises router and AWS Virtual Private Gateway. Quick to set
   up (minutes/hours), cheaper, but bandwidth is limited (~1.25 Gbps) and latency
   varies with internet congestion. Direct Connect is a dedicated physical connection
   at an AWS DX location — private network, NOT the internet. Provides predictable
   low latency, up to 100 Gbps bandwidth, consistent performance. Takes weeks to
   provision, higher cost. Use VPN for quick connectivity or as DX failover.
   Use Direct Connect for high-bandwidth, latency-sensitive, or compliance workloads.

Q: Why are there TWO tunnels in an AWS Site-to-Site VPN?
A: AWS creates two IPSec tunnels for each VPN connection, each with a different
   public IP endpoint on the AWS side (in different AZs). This provides redundancy —
   if one tunnel fails, traffic fails over to the second tunnel automatically.
   Best practice: configure your on-premises VPN device to use BOTH tunnels (BGP routing
   handles automatic failover). If you only configure one tunnel, you have a single
   point of failure on the AWS side.

Q: What is Direct Connect and when would a company use it over VPN?
A: Direct Connect is a dedicated, private network connection from your facility to AWS
   via an AWS DX colocation facility. Traffic never traverses the public internet.
   Use Direct Connect when: you need high bandwidth (data migrations of TBs/day,
   large media uploads), consistent/predictable latency (financial trading, real-time
   data processing), compliance requires no public internet exposure (PCI-DSS, HIPAA),
   or lower data transfer costs at scale (DX data transfer rates are lower than internet).

Q: How do you achieve high availability with Direct Connect?
A: A single DX connection is a single point of failure (physical cable). For HA:
   use at least two connections at different DX locations (different physical paths).
   For maximum resilience: two connections at two locations (four total). For cost-
   effective HA: use Direct Connect as primary and Site-to-Site VPN as failover —
   configure BGP to prefer DX routes, and VPN takes over automatically if DX fails.
