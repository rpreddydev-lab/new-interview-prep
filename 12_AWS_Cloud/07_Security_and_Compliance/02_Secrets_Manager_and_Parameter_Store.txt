AWS SECURITY — SECRETS MANAGER & PARAMETER STORE
Complete Interview Preparation Guide
================================================================

1. SECRETS MANAGER OVERVIEW
================================================================

  AWS Secrets Manager stores, rotates, and retrieves secrets 
  (database credentials, API keys, OAuth tokens, etc.)
  
  Key features:
    - Automatic secret rotation via Lambda
    - Native rotation for RDS, Aurora, Redshift, DocumentDB
    - Cross-account access via resource-based policies
    - Versioning with AWSCURRENT / AWSPREVIOUS labels
    - CloudTrail audit of every GetSecretValue call
    - Cost: ~$0.40/secret/month + $0.05 per 10,000 API calls

================================================================
2. SECRETS MANAGER — CORE CONCEPTS
================================================================

  SECRET STRUCTURE:
    - Name: e.g., prod/myapp/database
    - SecretString (or SecretBinary for binary)
    - Versions: each rotation creates a new version
    - Version labels: AWSCURRENT, AWSPREVIOUS (custom labels too)
  
  ROTATION:
    - Schedule: e.g., every 30 days
    - Rotation Lambda function (4 steps: createSecret → setSecret → testSecret → finishSecret)
    - During rotation: both AWSPREVIOUS and AWSCURRENT are valid
      (zero-downtime rotation — your app uses AWSCURRENT)
    - Native rotation: built-in support for RDS MySQL/PostgreSQL/Oracle/SQLServer/Aurora
    
  CLI:
  # Create a secret
  aws secretsmanager create-secret \
    --name prod/myapp/db \
    --description "RDS credentials" \
    --secret-string '{"username":"admin","password":"MyP@ss123"}'
  
  # Get secret value
  aws secretsmanager get-secret-value \
    --secret-id prod/myapp/db \
    --query SecretString \
    --output text
  
  # Enable automatic rotation (every 30 days)
  aws secretsmanager rotate-secret \
    --secret-id prod/myapp/db \
    --rotation-lambda-arn arn:aws:lambda:us-east-1:123456789012:function:SecretsManagerRDSRotation \
    --rotation-rules AutomaticallyAfterDays=30
  
  # Update secret value (manual)
  aws secretsmanager update-secret \
    --secret-id prod/myapp/db \
    --secret-string '{"username":"admin","password":"NewP@ss456"}'

3. SECRETS MANAGER — JAVA SDK v2
================================================================

  import software.amazon.awssdk.services.secretsmanager.SecretsManagerClient;
  import software.amazon.awssdk.services.secretsmanager.model.*;
  import com.fasterxml.jackson.databind.ObjectMapper;
  
  private static final SecretsManagerClient secretsClient =
      SecretsManagerClient.create();
  private static final ObjectMapper mapper = new ObjectMapper();
  
  // GET SECRET AS STRING
  public String getSecret(String secretName) {
      GetSecretValueResponse response = secretsClient.getSecretValue(
          GetSecretValueRequest.builder()
              .secretId(secretName)
              .build()
      );
      return response.secretString();
  }
  
  // GET SECRET AS OBJECT (JSON parsing)
  public DatabaseCredentials getDbCredentials(String secretName) {
      String secret = getSecret(secretName);
      return mapper.readValue(secret, DatabaseCredentials.class);
  }
  
  // CACHE SECRET (recommended pattern — avoid calling API on every request)
  // Use AWS Secrets Manager Caching Client:
  // dependency: software.amazon.secretsmanager:aws-secretsmanager-caching-java
  
  import com.amazonaws.secretsmanager.caching.SecretCache;
  
  private static final SecretCache cache = new SecretCache();
  
  public String getCachedSecret(String secretName) {
      return cache.getSecretString(secretName);
      // Caches for TTL (default 1 hour), refreshes on rotation
  }

4. SSM PARAMETER STORE OVERVIEW
================================================================

  AWS Systems Manager Parameter Store stores configuration data 
  and secrets in a hierarchical key-value store.
  
  TYPES:
    - String:       Plain text value
    - StringList:   Comma-separated list
    - SecureString: Encrypted with KMS key
  
  TIERS:
  ┌──────────────────┬─────────────────────┬──────────────────────┐
  │ Feature          │ Standard Tier       │ Advanced Tier        │
  ├──────────────────┼─────────────────────┼──────────────────────┤
  │ Max size         │ 4 KB                │ 8 KB                 │
  │ Parameters       │ 10,000 per account  │ 100,000 per account  │
  │ Cost             │ Free (SecureString  │ $0.05/parameter/month│
  │                  │ charges KMS cost)   │                      │
  │ Policies         │ No                  │ Yes (expiry alerts)  │
  │ TTL/Expiry       │ No                  │ Yes                  │
  └──────────────────┴─────────────────────┴──────────────────────┘

================================================================
5. PARAMETER STORE — CLI
================================================================

  PUT PARAMETER:
  aws ssm put-parameter \
    --name "/myapp/prod/db/url" \
    --value "jdbc:mysql://prod-db.cluster.rds.amazonaws.com:3306/mydb" \
    --type String \
    --overwrite
  
  PUT SECURE PARAMETER (encrypted with KMS):
  aws ssm put-parameter \
    --name "/myapp/prod/db/password" \
    --value "MyP@ss123" \
    --type SecureString \
    --key-id alias/my-app-key \
    --overwrite
  
  GET PARAMETER (decrypt SecureString automatically):
  aws ssm get-parameter \
    --name "/myapp/prod/db/password" \
    --with-decryption
  
  GET PARAMETERS BY PATH (all params under a prefix):
  aws ssm get-parameters-by-path \
    --path "/myapp/prod/" \
    --recursive \
    --with-decryption

6. PARAMETER STORE — JAVA SDK v2
================================================================

  import software.amazon.awssdk.services.ssm.SsmClient;
  import software.amazon.awssdk.services.ssm.model.*;
  
  private static final SsmClient ssmClient = SsmClient.create();
  
  // GET SINGLE PARAMETER
  public String getParameter(String name) {
      GetParameterResponse response = ssmClient.getParameter(
          GetParameterRequest.builder()
              .name(name)
              .withDecryption(true)    // decrypt SecureString
              .build()
      );
      return response.parameter().value();
  }
  
  // GET ALL PARAMETERS UNDER A PATH
  public Map<String, String> getParametersByPath(String path) {
      Map<String, String> params = new HashMap<>();
      String nextToken = null;
  
      do {
          GetParametersByPathResponse response = ssmClient.getParametersByPath(
              GetParametersByPathRequest.builder()
                  .path(path)
                  .recursive(true)
                  .withDecryption(true)
                  .nextToken(nextToken)
                  .build()
          );
  
          response.parameters().forEach(p ->
              params.put(p.name(), p.value())
          );
  
          nextToken = response.nextToken();
      } while (nextToken != null);
  
      return params;
  }
  
  // PUT PARAMETER
  public void putParameter(String name, String value, boolean secure) {
      ssmClient.putParameter(
          PutParameterRequest.builder()
              .name(name)
              .value(value)
              .type(secure ? ParameterType.SECURE_STRING : ParameterType.STRING)
              .overwrite(true)
              .build()
      );
  }

7. SECRETS MANAGER vs PARAMETER STORE
================================================================

  ┌─────────────────────────┬──────────────────────────┬──────────────────────────┐
  │ Feature                 │ Secrets Manager          │ Parameter Store          │
  ├─────────────────────────┼──────────────────────────┼──────────────────────────┤
  │ Primary use case        │ Secrets that rotate      │ App config & secrets     │
  │ Cost                    │ ~$0.40/secret/month      │ Free (Standard tier)     │
  │ Auto-rotation           │ Yes (native + custom)    │ No                       │
  │ Value size              │ 64 KB                    │ 4 KB (8 KB Advanced)     │
  │ Versioning              │ Yes (with labels)        │ Yes (version number only)│
  │ Cross-account access    │ Yes (resource policy)    │ Limited                  │
  │ Hierarchical paths      │ No                       │ Yes (/app/env/key)       │
  │ IAM condition by path   │ No                       │ Yes (ssm:Path)           │
  │ Native RDS rotation     │ Yes                      │ No                       │
  │ CloudFormation dynamic  │ Yes                      │ Yes                      │
  │ reference               │                          │                          │
  └─────────────────────────┴──────────────────────────┴──────────────────────────┘
  
  DECISION GUIDE:
    Use Secrets Manager when:
      - Secret needs automatic rotation
      - RDS/Aurora database credentials
      - Cross-account secret sharing
      - Compliance requires rotation audit trail
    
    Use Parameter Store when:
      - Non-sensitive config (URLs, feature flags, environment names)
      - Simple encrypted strings that don't rotate
      - Hierarchical config structure needed
      - Cost-sensitive (many parameters)
      - Lambda function config injection (free)

8. SPRING BOOT INTEGRATION
================================================================

  AWS Spring SDK can inject Parameter Store or Secrets Manager 
  values automatically as Spring @Value properties.
  
  # application.yml
  aws:
    paramstore:
      enabled: true
      prefix: /myapp
      profile-separator: _
      fail-fast: true
  
  Spring Cloud AWS automatically loads:
    /myapp/prod/db/url → injected as ${db.url}
    /myapp/prod/db/password → injected as ${db.password}

9. INTERVIEW QUESTIONS
================================================================

Q: How would you securely store and rotate RDS database credentials for a Lambda function?
A: Use AWS Secrets Manager:
   1. Create a secret in Secrets Manager with username/password as JSON.
   2. Enable automatic rotation with the native RDS rotation Lambda (AWS provides this 
      pre-built). Set rotation interval (e.g., 30 days).
   3. Lambda IAM role gets secretsmanager:GetSecretValue permission for that specific ARN.
   4. In Lambda code, call GetSecretValue at startup (outside the handler for warm reuse).
      Use the Secrets Manager caching client to avoid API calls on every invocation.
   5. During rotation, Secrets Manager manages AWSCURRENT and AWSPREVIOUS versions — 
      Lambda always gets the latest by requesting AWSCURRENT label.
   6. RDS password is changed automatically; Lambda picks up new password next cache refresh.

Q: What is the difference between Secrets Manager and SSM Parameter Store?
A: Parameter Store is primarily for configuration — hierarchical storage (e.g., 
   /app/prod/db-url), supports Standard tier free, good for non-sensitive config and 
   SecureString values that don't need rotation. Secrets Manager is purpose-built for 
   secrets that rotate — it has native rotation Lambda functions for RDS/Aurora, stores 
   up to 64 KB, has versioning with labels (AWSCURRENT/AWSPREVIOUS), and supports 
   cross-account access. Cost is higher ($0.40/secret/month). Rule of thumb: use 
   Secrets Manager for rotating credentials; Parameter Store for config with optional 
   encryption.

Q: How does automatic secret rotation work in Secrets Manager?
A: When rotation is triggered (scheduled or manual), Secrets Manager invokes a Lambda 
   function in four steps:
   1. createSecret — generate a new credential, store as AWSPENDING
   2. setSecret — update the actual service (RDS password) with the new credential
   3. testSecret — verify the new credential works against the service
   4. finishSecret — move AWSPENDING to AWSCURRENT, old AWSCURRENT to AWSPREVIOUS
   Both current and previous versions are valid during and after rotation, ensuring 
   zero downtime even if some clients haven't refreshed yet. AWS provides native Lambda 
   functions for RDS engines that implement all four steps automatically.
