1. WHAT ARE DECLARATION FILES?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Declaration files (.d.ts) are TypeScript files that contain ONLY type
information — no implementation/executable code.

They act as a "type blueprint" for:
  • JavaScript libraries (so TypeScript understands their shape)
  • Third-party packages that don't ship TypeScript source
  • Module augmentation (extending existing types)
  • Global variables injected by environments (e.g., window.myLib)

Key characteristics:
  • Extension: .d.ts (NOT .ts — cannot contain implementation)
  • Purpose: Describes the type shape of a JS module or global API
  • Not compiled: .d.ts files are never compiled to .js
  • Consumed by: TypeScript compiler for type checking only
  • Erased: Never included in the final JavaScript bundle

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
2. HOW DECLARATION FILES ARE GENERATED
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

a) Auto-generated by the TypeScript compiler:
   With "declaration": true in tsconfig.json:

   // Source: src/utils.ts
   export function add(a: number, b: number): number {
     return a + b;
   }

   // Generated: dist/utils.d.ts
   export declare function add(a: number, b: number): number;

   The .d.ts file mirrors the API surface with types only.

b) Manually written:
   For JavaScript files or external APIs without TypeScript source.

c) From DefinitelyTyped:
   Community-maintained .d.ts for thousands of libraries.
   Install: npm install --save-dev @types/lodash

3. ANATOMY OF A DECLARATION FILE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

// math-lib.d.ts — describes the shape of math-lib.js

// Variables
declare const PI: number;

// Functions
declare function add(a: number, b: number): number;
declare function subtract(a: number, b: number): number;

// Classes
declare class Vector {
  x: number;
  y: number;
  constructor(x: number, y: number);
  add(other: Vector): Vector;
  magnitude(): number;
}

// Interfaces
interface MathOptions {
  precision?: number;
  roundingMode?: "ceil" | "floor" | "round";
}

// Type aliases
declare type Scalar = number;

// Enums
declare enum Shape {
  Circle,
  Rectangle,
  Triangle
}

// Namespaces (for organizing declarations)
declare namespace MathUtils {
  function clamp(value: number, min: number, max: number): number;
  function lerp(a: number, b: number, t: number): number;
}

// Module default export
declare function mathLib(options?: MathOptions): void;
export default mathLib;

// Named exports
export { add, subtract, Vector, PI, MathUtils };

4. TYPES OF DECLARATION FILES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

a) Module Declaration Files:
   ──────────────────────────
   Describe the exports of a module (has imports/exports at the top level).

   // utils.d.ts
   export declare function formatDate(date: Date): string;
   export declare interface Config {
     locale: string;
     timezone: string;
   }

b) Global Declaration Files:
   ──────────────────────────
   No import/export — describe global variables and functions available
   in a specific environment (browser, Node.js, etc.).

   // globals.d.ts
   declare const __VERSION__: string;  // injected by webpack
   declare const ENV: "development" | "production" | "test";

   // Extend global interfaces:
   interface Window {
     analytics: { track: (event: string) => void };
   }

c) Ambient Module Declarations:
   ──────────────────────────────
   Declare types for modules that have no types at all.

   // In any .d.ts file (e.g., typings.d.ts):
   declare module "legacy-lib" {
     export function doSomething(input: string): string;
     export const version: string;
   }

   // Wildcard module declarations (for CSS/SVG/image imports):
   declare module "*.css" {
     const styles: { [className: string]: string };
     export default styles;
   }
   declare module "*.svg" {
     const content: string;
     export default content;
   }
   declare module "*.png" {
     const url: string;
     export default url;
   }

5. DEFINITELYTYPED AND @types
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

DefinitelyTyped is a community repository of .d.ts type definitions for
JavaScript libraries that don't ship their own types.

GitHub: https://github.com/DefinitelyTyped/DefinitelyTyped
NPM scope: @types/

Installation:
  npm install --save-dev @types/react
  npm install --save-dev @types/node
  npm install --save-dev @types/lodash
  npm install --save-dev @types/express

TypeScript automatically finds @types packages in node_modules/@types.
Control which ones are included with the `types` option in tsconfig.json.

Which packages need @types?
  ┌──────────────────────────────────────────────────────────────────────────┐
  │ Package ships its own types   │ Package needs @types                     │
  │ (no @types needed)            │                                          │
  ├───────────────────────────────┼──────────────────────────────────────────┤
  │ TypeScript-written packages:  │ Legacy JavaScript packages:              │
  │ • Zod                         │ • lodash → @types/lodash                 │
  │ • Prisma                      │ • react → @types/react                   │
  │ • tRPC                        │ • express → @types/express               │
  │ • Vitest                      │ • node → @types/node                     │
  │ • Vite                        │ • jquery → @types/jquery                 │
  └───────────────────────────────┴──────────────────────────────────────────┘

  Tip: Check package.json "types" or "typings" field — if present, types are
  bundled. If not, look for @types/package-name.

6. WRITING A DECLARATION FILE — PRACTICAL EXAMPLE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

SCENARIO: You have a JavaScript library `currency.js` with no types.

// currency.js (the JavaScript library — no types)
function formatCurrency(amount, options) {
  const { symbol = "$", decimals = 2 } = options || {};
  return `${symbol}${amount.toFixed(decimals)}`;
}

function parseCurrency(str) {
  return parseFloat(str.replace(/[^0-9.-]/g, ""));
}

module.exports = { formatCurrency, parseCurrency };

You write the declaration file:

// currency.d.ts (your hand-written type declaration)
interface CurrencyOptions {
  symbol?: string;
  decimals?: number;
}

export declare function formatCurrency(
  amount: number,
  options?: CurrencyOptions
): string;

export declare function parseCurrency(str: string): number;

Now TypeScript consumers get full type safety:
  import { formatCurrency } from "./currency";
  formatCurrency(9.99);                       // ✅ "$9.99"
  formatCurrency(9.99, { symbol: "€" });      // ✅
  formatCurrency("hello");                    // ❌ Error: string not assignable to number

7. MODULE AUGMENTATION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Module augmentation lets you ADD types to existing modules.

Use case: Extending Express Request to include custom properties:

  // types/express.d.ts
  import "express";

  declare module "express" {
    interface Request {
      user?: { id: string; role: "admin" | "user" };
    }
  }

  // Now in your route handlers:
  app.get("/profile", (req, res) => {
    if (req.user) {          // ✅ TypeScript knows about req.user
      res.json(req.user.id); // ✅
    }
  });

Use case: Extending Window:
  // types/window.d.ts
  export {};  // Make this a module (required for augmentation)

  declare global {
    interface Window {
      gtag: (event: string, ...args: unknown[]) => void;
    }
  }

Use case: Extending String prototype:
  // types/string.d.ts
  export {};

  declare global {
    interface String {
      toTitleCase(): string;
    }
  }

8. TRIPLE-SLASH DIRECTIVES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Triple-slash directives are single-line XML comments that provide compiler
instructions. Must appear at the TOP of a file (before any code).

/// <reference types="..." />
  References a type package (similar to @types imports).
  /// <reference types="node" />      // Include @types/node
  /// <reference types="react" />     // Include @types/react
  Used in .d.ts files to declare dependencies on @types packages.

/// <reference path="..." />
  References another .d.ts file.
  /// <reference path="./globals.d.ts" />
  Older pattern — prefer ES module imports when possible.

/// <reference lib="..." />
  Include a built-in library.
  /// <reference lib="es2020" />
  /// <reference lib="dom" />

Modern Practice: Triple-slash directives are mostly obsolete for application
code. The tsconfig.json `types`, `lib`, and `include` options handle this.
They're still used in .d.ts files for library authoring.

9. PUBLISHING TYPES WITH YOUR LIBRARY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

When publishing an npm package, point to your types in package.json:

  {
    "name": "my-lib",
    "version": "1.0.0",
    "main": "./dist/index.js",
    "types": "./dist/index.d.ts",   // or "typings"
    "exports": {
      ".": {
        "import": "./dist/index.mjs",
        "require": "./dist/index.cjs",
        "types": "./dist/index.d.ts"
      }
    },
    "files": ["dist"]
  }

  tsconfig.json for library:
  {
    "compilerOptions": {
      "declaration": true,        // Generate .d.ts
      "declarationMap": true,     // Generate .d.ts.map for IDE go-to-def
      "outDir": "./dist"
    }
  }

10. COMMON INTERVIEW QUESTIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q1: What is a .d.ts file?
    A TypeScript declaration file that contains ONLY type information (no
    executable code). It describes the shape of JavaScript code so TypeScript
    can type-check against it. They're used for JS libraries without TS source.

Q2: What is DefinitelyTyped?
    A community repository (github.com/DefinitelyTyped/DefinitelyTyped) that
    contains hand-written TypeScript declaration files for thousands of popular
    JavaScript libraries. Packages are published under the @types npm scope.

Q3: How does TypeScript find type declarations?
    In order:
    1. `types` field in the package's package.json
    2. `index.d.ts` in the package root
    3. node_modules/@types/package-name
    4. Paths from tsconfig's `typeRoots` and `types` options

Q4: What is the difference between a regular .ts file and a .d.ts file?
    .ts files can contain both types AND implementation code.
    .d.ts files contain ONLY type declarations — no implementation.
    .d.ts files use `declare` keyword and are never compiled to JS.

Q5: What does `declare module` do?
    `declare module "module-name"` tells TypeScript about the shape of a module
    that has no type information. It's an "ambient module declaration" that
    you write when @types doesn't exist for a package.

Q6: How do you add types for non-TypeScript assets like CSS or SVG files?
    Create wildcard module declarations in a .d.ts file:
    declare module "*.css" { const styles: { [key: string]: string }; export default styles; }
    declare module "*.svg" { const src: string; export default src; }

Q7: What is module augmentation and how is it used?
    Module augmentation lets you add to the types of existing modules without
    modifying the original declaration. Common use: adding custom properties
    to Express's Request interface, extending Window, extending String prototype.

Q8: What is the `declare` keyword?
    `declare` tells TypeScript that a symbol exists and has a specific type,
    but was implemented elsewhere (usually in JavaScript). It's used in .d.ts
    files and for global declarations. No code is emitted for `declare` statements.

Q9: When would you write a .d.ts file manually?
    • When using a JS library with no @types package
    • When adding types for non-JS assets (CSS, images, env vars)
    • When declaring global variables (webpack DefinePlugin, etc.)
    • When performing module augmentation

Q10: How do you publish a TypeScript library with types?
     1. Add "declaration": true to tsconfig.json → generates .d.ts files
     2. Add "declarationMap": true → generates source maps for IDE
     3. In package.json, set "types": "./dist/index.d.ts"
     4. Include dist folder in "files" array
     Consumers can then import your library with full type safety.
