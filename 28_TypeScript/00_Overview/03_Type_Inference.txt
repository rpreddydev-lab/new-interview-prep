1. WHAT IS TYPE INFERENCE?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Type inference is TypeScript's ability to AUTOMATICALLY determine the type of
a value based on context — without requiring explicit type annotations.

TypeScript infers types from:
  • Variable initializations
  • Function return values
  • Default parameter values
  • Object and array literals
  • Contextual types (callbacks, assignments)

Key principle: "If TypeScript can figure out the type, you don't need to
              annotate it. Annotate only where inference fails or is unclear."

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
2. BASIC TYPE INFERENCE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

a) Variable Initialization:
   ─────────────────────────
   let count = 42;          // inferred: number
   let name = "Alice";      // inferred: string
   let active = true;       // inferred: boolean
   let nothing = null;      // inferred: null (with strictNullChecks)
   let undef = undefined;   // inferred: undefined

   // TypeScript locks the type based on initial value:
   count = "hello";  // ❌ Error: Type 'string' is not assignable to type 'number'

b) Array Inference:
   ─────────────────
   let nums = [1, 2, 3];         // inferred: number[]
   let mixed = [1, "two", true]; // inferred: (string | number | boolean)[]
   let empty = [];               // inferred: never[] (widened to any[] — be careful!)

   // Best practice: annotate empty arrays
   let ids: number[] = [];

c) Object Literal Inference:
   ──────────────────────────
   let user = { id: 1, name: "Bob", active: true };
   // inferred: { id: number; name: string; active: boolean; }

   user.id = "abc"; // ❌ Error: Type 'string' is not assignable to type 'number'
   user.age = 30;   // ❌ Error: Property 'age' does not exist on type '{...}'

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
3. FUNCTION TYPE INFERENCE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

a) Return Type Inference:
   ──────────────────────
   // TypeScript infers return type from the return statement(s)
   function add(a: number, b: number) {
     return a + b;  // inferred return type: number
   }

   function getUser() {
     return { id: 1, name: "Alice" }; // inferred: { id: number; name: string }
   }

   // Multiple return paths → union
   function parse(value: string) {
     if (!value) return null;       // null
     return parseInt(value);        // number
   }
   // inferred return type: number | null

b) Parameter Inference (Contextual):
   ────────────────────────────────────
   // TypeScript infers parameter types from context (callbacks)
   const nums = [1, 2, 3];
   nums.forEach((n) => {         // n is inferred as number (from number[])
     console.log(n.toFixed(2));  // ✅ .toFixed is available on number
   });

   const handler: (event: MouseEvent) => void = (e) => {
     e.clientX; // ✅ inferred as MouseEvent
   };

c) Default Parameter Inference:
   ─────────────────────────────
   function greet(name = "World") {  // name inferred as: string
     return `Hello, ${name}`;
   }
   greet(42); // ❌ Error: Argument of type 'number' is not assignable to 'string'

4. BEST COMMON TYPE ALGORITHM
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

When TypeScript infers the type of a collection (array or return with multiple
types), it uses the "best common type" algorithm — the most specific type that
all values share.

  let arr = [1, 2, null];
  // TypeScript examines: number, number, null
  // Best common type: (number | null)[]

  class Animal {}
  class Dog extends Animal {}
  class Cat extends Animal {}

  let animals = [new Dog(), new Cat()];
  // TypeScript: infers (Dog | Cat)[] NOT Animal[]
  // To get Animal[]: annotate explicitly
  let animals: Animal[] = [new Dog(), new Cat()]; // ✅

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
5. CONTEXTUAL TYPING
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Contextual typing occurs when the TYPE of an expression is determined by its
location/context in the code.

  // Button click handler: TypeScript infers event type from context
  document.addEventListener("click", (event) => {
    // event is MouseEvent — inferred from "click" event type
    console.log(event.clientX); // ✅
  });

  // Typed callback parameter
  type Transformer = (input: string) => string;
  const transform: Transformer = (s) => s.toUpperCase(); // s inferred as string

  // Object method contextual typing
  interface Config {
    onLoad: (data: string[]) => void;
  }
  const config: Config = {
    onLoad: (data) => {  // data inferred as string[]
      data.forEach((item) => console.log(item));
    }
  };

6. TYPE WIDENING AND NARROWING
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

a) Type Widening (default inference behavior):
   TypeScript widens literal types to broader types for `let` declarations.

   let x = "hello";     // widened to: string (not "hello")
   let n = 42;          // widened to: number (not 42)

   // Why? Because let values can change:
   x = "world";  // ✅ allowed (x is string, not "hello")

b) Literal Type Inference with const:
   `const` declarations are NOT widened — they stay as literal types.

   const x = "hello";  // type: "hello" (literal type, not string)
   const n = 42;       // type: 42 (literal type, not number)
   const obj = { status: "active" }; // BUT object properties ARE widened!
   // obj.status is string, not "active"

   // To get literal types in objects, use `as const`:
   const obj = { status: "active" } as const;
   // obj.status is "active" (readonly "active")

c) Type Narrowing (TypeScript narrows wide types in conditional blocks):
   After type guards, TypeScript knows a more specific type.

   function printId(id: number | string) {
     if (typeof id === "string") {
       id.toUpperCase(); // id is string here (narrowed)
     } else {
       id.toFixed();     // id is number here (narrowed)
     }
   }

7. `as const` — CONST ASSERTION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

`as const` tells TypeScript to infer the narrowest possible (literal) types
and make all properties readonly.

  const config = {
    host: "localhost",
    port: 3000,
    env: "production"
  } as const;

  // Without as const:
  // config.host: string, config.port: number, config.env: string

  // With as const:
  // config.host: "localhost" (readonly)
  // config.port: 3000 (readonly)
  // config.env: "production" (readonly)

  config.host = "remotehost"; // ❌ Error: Cannot assign to 'host' because it is a read-only property

Use Case — Literal Union from Array:
  const DIRECTIONS = ["north", "south", "east", "west"] as const;
  type Direction = typeof DIRECTIONS[number]; // "north" | "south" | "east" | "west"

Use Case — Tuple Inference:
  function useState(initial: number) {
    return [initial, (v: number) => {}] as const;
    // Inferred as: readonly [number, (v: number) => void]
    // Without as const: (number | ((v: number) => void))[]
  }

8. GENERIC TYPE INFERENCE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

TypeScript infers generic type parameters from arguments:

  function identity<T>(value: T): T { return value; }

  identity(42);        // T inferred as: number
  identity("hello");   // T inferred as: string
  identity([1, 2, 3]); // T inferred as: number[]

  // With multiple generics:
  function pair<A, B>(a: A, b: B): [A, B] { return [a, b]; }

  pair(1, "hello");    // A = number, B = string → [number, string]
  pair(true, [1, 2]);  // A = boolean, B = number[] → [boolean, number[]]

  // TypeScript can infer from object shape:
  function getProperty<T, K extends keyof T>(obj: T, key: K): T[K] {
    return obj[key];
  }
  getProperty({ name: "Alice", age: 30 }, "name"); // return type: string
  getProperty({ name: "Alice", age: 30 }, "age");  // return type: number
  getProperty({ name: "Alice", age: 30 }, "id");   // ❌ Error: "id" not in type

9. RETURN TYPE INFERENCE vs EXPLICIT ANNOTATION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

TypeScript can infer return types, but there are cases where explicit
annotation is preferred:

  // Inferred return type (good for simple functions)
  function add(a: number, b: number) {
    return a + b; // TypeScript infers: number
  }

  // Explicit return type (preferred in these cases):
  // 1. Complex functions with multiple return paths
  function processData(data: unknown): ProcessedData {
    // If you accidentally return wrong type, TS catches it immediately
    ...
  }

  // 2. Public API / library functions (documents intent)
  export function createUser(name: string): User {
    ...
  }

  // 3. Recursive functions (TypeScript can't infer recursive return types)
  function flatten(arr: any[]): any[] { // must annotate
    return arr.flatMap(item => Array.isArray(item) ? flatten(item) : item);
  }

  // 4. When inference produces unwanted type
  function getConfig() {
    return { debug: false, level: 1 };
    // Inferred: { debug: boolean; level: number }
    // If you want: { debug: false; level: 1 } → use as const
  }

10. typeof OPERATOR IN TYPES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Use `typeof` in type position to extract the type of a value:

  const config = {
    host: "localhost",
    port: 3000,
  };

  type Config = typeof config;
  // { host: string; port: number; }

  function createServer(cfg: typeof config) { ... }

  // Extract return type of a function:
  function getUser() { return { id: 1, name: "Alice" }; }
  type UserType = ReturnType<typeof getUser>;
  // { id: number; name: string }

  // Extract parameter types:
  type Params = Parameters<typeof getUser>; // []

11. INFERRED TYPE PREDICATES (TypeScript 5.5+)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Before TS 5.5 (manual type predicate required):
    function isString(x: unknown): x is string {
      return typeof x === "string";
    }

  TS 5.5+ (inferred automatically):
    function isString(x: unknown) {
      return typeof x === "string"; // TypeScript infers: x is string
    }

  Practical usage:
    const items = [1, null, 2, null, 3];
    const nums = items.filter((x) => x !== null); // TS 5.5: inferred as number[]
    // Before TS 5.5: inferred as (number | null)[] — filter doesn't narrow

12. COMMON INTERVIEW QUESTIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q1: What is type inference in TypeScript?
    Type inference is TypeScript's ability to automatically determine types
    without explicit annotations. TypeScript infers from initializers, return
    statements, default parameters, and contextual usage.

Q2: What is the difference between `let` and `const` type inference?
    With `let`: TypeScript widens to the general type (e.g., "hello" → string)
    With `const`: TypeScript keeps the literal type (e.g., "hello" → "hello")
    This is because `let` values can change, `const` cannot.

Q3: What is `as const` and why is it useful?
    `as const` creates a "const assertion" that:
    1. Infers narrowest literal types (not widened)
    2. Makes all properties readonly
    3. Prevents array widening to the element type
    Useful for creating union types from arrays, defining config objects,
    and ensuring object shapes aren't accidentally widened.

Q4: What is type widening?
    Type widening is when TypeScript infers a broader type than the literal
    value. For example, `let x = "hello"` → x gets type `string` not `"hello"`.
    This happens because `let` values are expected to change.

Q5: What is contextual typing?
    Contextual typing is when TypeScript infers parameter types from context —
    e.g., in callbacks, the parameter type is inferred from the higher-order
    function's signature. 
    arr.forEach((item) => ...) // item type inferred from arr's element type

Q6: When should you explicitly annotate return types instead of relying on inference?
    • Public API/library functions (documents the contract)
    • Complex functions with multiple code paths
    • Recursive functions (TypeScript can't infer these)
    • When you want the compiler to verify the return type matches your intent

Q7: What does the `typeof` type operator do?
    In type position, `typeof` extracts the TypeScript type of a value or variable:
    const x = { a: 1 };
    type T = typeof x; // { a: number }
    Used with ReturnType<>, Parameters<>, etc.

Q8: What is the "best common type" algorithm?
    When TypeScript needs to infer a type from multiple values (array elements,
    multiple return statements), it picks the type that all values are compatible
    with. E.g., [1, 2, null] → (number | null)[]

Q9: How does generic type inference work?
    TypeScript infers generic type parameters from the arguments passed.
    function wrap<T>(val: T): T[] { return [val]; }
    wrap(42) → T is inferred as number → returns number[]
    You rarely need to explicitly pass <number> when inference works.

Q10: What is the difference between inference and annotation?
     - Annotation: explicit, developer-written types (string, User, etc.)
     - Inference: TypeScript deduces types automatically from context
     Best practice: rely on inference for local variables and simple functions,
     annotate for function parameters, public APIs, and complex return types.
