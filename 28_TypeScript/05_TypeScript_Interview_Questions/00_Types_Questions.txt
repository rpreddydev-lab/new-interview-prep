SECTION 1: PRIMITIVE TYPES AND BASICS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: What is the difference between `any` and `unknown`?
A: Both accept any value, but `unknown` requires you to narrow the type before
   using it — TypeScript won't let you call methods or access properties on
   `unknown` without a check. `any` silently bypasses all type checking. Use
   `unknown` when accepting external/untyped data, `any` only as a last resort.

Q: What is the `never` type and when does it appear?
A: `never` represents values that never occur. It appears in:
   - Functions that never return (infinite loop or always throw)
   - Exhaustiveness checking (default branch after handling all union members)
   - As the intersection of incompatible types: string & number = never
   - When a union is narrowed to zero remaining members

Q: What is the difference between `null` and `undefined` in TypeScript?
A: `undefined` = variable declared but not assigned; function didn't return.
   `null` = explicit absence of a value (must be assigned intentionally).
   With `strictNullChecks: true`, both are their own types and cannot be
   assigned to other types without explicit handling. Optional properties
   become `T | undefined`, not `T | null`.

Q: What is the `void` type and when would you use it?
A: `void` means the function doesn't return a useful value (returns undefined).
   It's the return type of event handlers and callbacks. Unlike `undefined`,
   a function typed as `() => void` CAN return a value — TypeScript just ignores it.
   This allows .forEach(callback) to work even if callback returns something.

Q: What is type widening and when does it occur?
A: When TypeScript infers a broader type than the literal value. `let x = "hello"`
   widens to `string` because let allows reassignment. `const x = "hello"` keeps
   the literal type "hello". Widening also happens in arrays and object literals.
   Use `as const` to prevent widening: `const x = ["a", "b"] as const` gives
   readonly ["a", "b"] instead of string[].

Q: What is structural typing vs nominal typing?
A: TypeScript uses structural typing: types are compatible if they have the same
   shape (same properties), regardless of their name or declared type. Two
   unrelated classes with the same properties are compatible. Most other languages
   (Java, C#) use nominal typing where compatibility is based on explicit
   declarations (extends, implements).

   class A { name: string = "" }
   class B { name: string = "" }
   const a: A = new B(); // ✅ structural typing — same shape

Q: What are tuple types and how do they differ from arrays?
A: Tuples have a fixed length and fixed type for each position:
   type Pair = [string, number]; // exactly [string, number]
   Arrays: string[] can have any length.
   Tuples support optional elements ([string, number?]) and rest elements
   ([string, ...number[]]). TypeScript 4+ supports labeled tuples:
   type Point = [x: number, y: number].

Q: What is the difference between `type` and `interface`?
A: Both describe object shapes. Key differences:
   - `interface` supports declaration merging; `type` does not
   - `type` can alias primitives, unions, tuples, mapped/conditional types
   - `interface` uses `extends`, `type` uses `&` for composition
   - Recursive types both support (but `interface` was historically better for it)
   Use `interface` for object shapes in libraries/APIs; `type` for unions,
   tuples, and complex type transformations.

SECTION 2: UNION AND INTERSECTION TYPES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: What is the difference between union types (A | B) and intersection types (A & B)?
A: Union A | B means "either A or B" — only the shared properties are accessible.
   Intersection A & B means "both A and B" — all properties from both are required.
   Set analogy: union is wider (more values, fewer guaranteed properties),
   intersection is narrower (fewer values, more guaranteed properties).

Q: How do you narrow a union type?
A: - typeof: for primitives (typeof x === "string")
   - instanceof: for class instances (x instanceof Date)
   - `in` operator: for object shapes ("key" in obj)
   - discriminant property: switch(shape.kind)
   - type predicates: isUser(x): x is User functions
   - truthiness: if (x) narrows away null/undefined/0/""

Q: What is a discriminated union?
A: A union where every member has a common property (the discriminant) with a
   unique literal type value. TypeScript uses the discriminant to narrow the type:
   type Shape = { kind: "circle"; radius: number } | { kind: "rect"; width: number; height: number }
   Checking `shape.kind === "circle"` narrows shape to the circle variant.

Q: Why does `string & number` evaluate to `never`?
A: A value cannot be both string and number simultaneously. The intersection of
   incompatible types is the empty set (no values satisfy both), represented as `never`.

SECTION 3: ENUMS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: What is the difference between a numeric and string enum in TypeScript?
A: Numeric enums have auto-incremented number values and support reverse mapping
   (Direction[0] === "Up"). String enums have explicit string values, no reverse
   mapping, and are safer — numeric enums accept any number due to JS interop.

Q: What is a const enum and when would you use it?
A: const enum is inlined at compile time — TypeScript replaces references with
   their literal values in the output JS. This produces zero runtime code.
   Use it for performance-critical code or when the enum doesn't need to be
   iterated. Limitation: const enums can't be used in certain setups (isolatedModules,
   Babel transpilation).

Q: What is the alternative to enums in TypeScript?
A: Use a `const` object with `as const` and derive the union type:
   const DIRECTION = { Up: "Up", Down: "Down", Left: "Left", Right: "Right" } as const;
   type Direction = typeof DIRECTION[keyof typeof DIRECTION]; // "Up" | "Down" | ...
   This has better tree-shaking, works with all bundlers, and is more idiomatic.

SECTION 4: GENERICS AND UTILITY TYPES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: What is the difference between Omit and Exclude?
A: Omit<T, K> removes keys K from an object type T — works on objects.
   Exclude<T, U> removes union members from T that are assignable to U — works on unions.
   type A = Omit<User, "password"> — removes the password property
   type B = Exclude<"a" | "b" | "c", "a"> — gives "b" | "c"

Q: What is the difference between Pick and Extract?
A: Pick<T, K> keeps only keys K from object type T.
   Extract<T, U> keeps only union members of T that extend U.
   type C = Pick<User, "name" | "email"> — keeps those properties
   type D = Extract<string | number | boolean, string | number> — gives string | number

Q: How does Partial<T> differ from DeepPartial<T>?
A: Partial<T> makes only the TOP-LEVEL properties optional.
   DeepPartial<T> (not built-in) recursively makes ALL nested object properties optional.
   type DeepPartial<T> = { [K in keyof T]?: T[K] extends object ? DeepPartial<T[K]> : T[K] }

Q: What does NonNullable<T> do?
A: Removes null and undefined from T:
   NonNullable<string | null | undefined> → string
   Equivalent to: T extends null | undefined ? never : T

Q: What is ReturnType and when is it useful?
A: ReturnType<T> extracts the return type of a function type T.
   type R = ReturnType<typeof someFunction>; — useful for deriving types from
   functions you don't control, or keeping return types in sync when a function
   changes. Implemented as: T extends (...args: any[]) => infer R ? R : never

SECTION 5: KEY INTERVIEW GOTCHAS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: What is the excess property check?
A: TypeScript checks for extra properties when assigning an OBJECT LITERAL
   directly to a type. Assigning via a variable bypasses this check:
   const user: User = { name: "Alice", extra: "oops" }; // ❌ excess property error
   const obj = { name: "Alice", extra: "oops" };
   const user2: User = obj; // ✅ no error — structural, obj has at least User's shape

Q: Why does `keyof any` give `string | number | symbol`?
A: JavaScript object keys can be strings, numbers, or symbols.
   `keyof any` is the type of all possible object key types.
   It's used in utility types: type Record<K extends keyof any, V> = { [P in K]: V }

Q: What is declaration merging?
A: TypeScript allows multiple declarations of the same name to be merged.
   Only interfaces (not types) support merging:
   interface User { name: string }
   interface User { age: number }
   // Merged: { name: string; age: number }
   Used to extend third-party types (module augmentation).

Q: What is a type assertion and when should you use it?
A: `value as Type` tells TypeScript to treat value as Type, bypassing normal
   type checking. Use it when YOU know more than TypeScript does — e.g., after
   an instanceof check that TypeScript can't automatically narrow, or when
   working with DOM APIs. Avoid using it to silence legitimate type errors.

Q: What is `satisfies` (TypeScript 4.9+)?
A: `satisfies` validates that a value matches a type without widening the inferred
   type. Unlike `as Type` (which changes the type), `satisfies Type` checks the
   type but keeps the more specific inferred type:
   const config = { port: 3000, host: "localhost" } satisfies Config;
   // config.port is still number (not Config["port"] which might be wider)
   config.port.toFixed(); // ✅ TypeScript knows it's number, not string | number
