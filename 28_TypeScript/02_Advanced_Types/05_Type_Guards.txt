1. WHAT ARE TYPE GUARDS?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Type guards are expressions that NARROW the type of a variable within a
  conditional block. TypeScript uses control flow analysis to track what type
  a variable can be after each check.

  function greet(val: string | number) {
    if (typeof val === "string") {
      console.log(val.toUpperCase()); // ✅ TypeScript knows val is string here
    } else {
      console.log(val.toFixed(2));    // ✅ TypeScript knows val is number here
    }
  }

2. BUILT-IN TYPE GUARDS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  a) typeof guard — for primitives:
     ─────────────────────────────
     Works with: "string" | "number" | "bigint" | "boolean" | "symbol" |
                 "undefined" | "function" | "object"

     function process(x: string | number | boolean) {
       if (typeof x === "string")  { return x.split(""); }  // string
       if (typeof x === "number")  { return x * 2; }        // number
       if (typeof x === "boolean") { return !x; }           // boolean
     }

     IMPORTANT: typeof null === "object" — a historical JS quirk!
     Always null-check separately: if (x !== null && typeof x === "object")

  b) instanceof guard — for class instances:
     ─────────────────────────────────────────
     class Dog { bark() {} }
     class Cat { meow() {} }

     function speak(animal: Dog | Cat) {
       if (animal instanceof Dog) {
         animal.bark(); // ✅ narrowed to Dog
       } else {
         animal.meow(); // ✅ narrowed to Cat
       }
     }

     Works for: anything created with `new`, including built-in classes
     (Date, Error, Array, Map, Set, RegExp, etc.)

     function isDate(val: unknown): boolean {
       return val instanceof Date;
     }

  c) `in` operator guard — for object shapes:
     ─────────────────────────────────────────
     Checks if a property exists in an object at runtime:

     type Admin = { role: "admin"; permissions: string[] };
     type User  = { role: "user"; email: string };

     function describe(person: Admin | User) {
       if ("permissions" in person) {
         console.log(person.permissions); // ✅ narrowed to Admin
       } else {
         console.log(person.email);       // ✅ narrowed to User
       }
     }

  d) Truthiness guard — for null/undefined:
     ───────────────────────────────────────
     function printLength(str: string | null | undefined) {
       if (str) {
         console.log(str.length); // ✅ str is string here
       }
     }

     // Double negation for type coercion:
     const hasValue = !!maybeNull; // boolean

     // Nullish checks:
     if (x != null) { /* x is not null AND not undefined */ }
     if (x !== null && x !== undefined) { /* same */ }

  e) Equality narrowing:
     ───────────────────
     function check(x: string | number, y: string | boolean) {
       if (x === y) {
         // x and y must both be `string` (the common type)
         x.toUpperCase(); // ✅
       }
     }

     // Useful with null checks:
     if (val === null) { /* val is null */ }
     if (val === undefined) { /* val is undefined */ }

3. USER-DEFINED TYPE GUARDS (TYPE PREDICATES)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  When built-in guards aren't enough, write a function with the special return
  type `paramName is Type`:

  Syntax: function fn(x: unknown): x is SpecificType { ... }

  a) Basic type predicate:
     type Fish = { swim: () => void };
     type Bird = { fly: () => void };

     function isFish(pet: Fish | Bird): pet is Fish {
       return (pet as Fish).swim !== undefined;
     }

     function move(animal: Fish | Bird) {
       if (isFish(animal)) {
         animal.swim(); // ✅ TypeScript knows it's Fish
       } else {
         animal.fly();  // ✅ TypeScript knows it's Bird
       }
     }

  b) Validating unknown data (very common with API responses):
     function isString(val: unknown): val is string {
       return typeof val === "string";
     }

     function isUser(val: unknown): val is User {
       return (
         typeof val === "object" &&
         val !== null &&
         "id" in val &&
         "name" in val &&
         typeof (val as any).id === "number" &&
         typeof (val as any).name === "string"
       );
     }

     const data = JSON.parse(response);
     if (isUser(data)) {
       console.log(data.name); // ✅ safely typed as User
     }

  c) Array filter with type guard:
     const mixed: (string | number)[] = ["a", 1, "b", 2, "c"];

     // Without type guard — returns (string | number)[]:
     const nums1 = mixed.filter(x => typeof x === "number");

     // With type guard — returns number[]:
     const isNumber = (x: string | number): x is number =>
       typeof x === "number";
     const nums2 = mixed.filter(isNumber); // number[] ✅

     // Inline (TypeScript 5.5+ infers this automatically in many cases):
     const nums3 = mixed.filter((x): x is number => typeof x === "number");

4. ASSERTION FUNCTIONS (TypeScript 3.7+)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Assertion functions narrow the type in all subsequent code — they THROW if
  the condition is not met instead of returning boolean.

  Return type syntax: asserts x is Type  OR  asserts condition

  a) asserts x is Type:
     function assertString(val: unknown): asserts val is string {
       if (typeof val !== "string") {
         throw new Error(`Expected string, got ${typeof val}`);
       }
     }

     let x: unknown = getUserInput();
     assertString(x);
     console.log(x.toUpperCase()); // ✅ x is narrowed to string after call

  b) asserts condition (for boolean-based assertions):
     function assert(condition: unknown, msg?: string): asserts condition {
       if (!condition) throw new Error(msg ?? "Assertion failed");
     }

     let val: string | null = getValue();
     assert(val !== null, "val must not be null");
     val.toUpperCase(); // ✅ val is string here

  c) Node.js assert module works similarly:
     import assert from "node:assert";
     assert(typeof x === "string");
     x.toUpperCase(); // ✅ narrowed after assertion

5. DISCRIMINATED UNION GUARD
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Using a literal discriminant property is the most reliable and recommended
  approach for narrowing union types:

  type Shape =
    | { kind: "circle"; radius: number }
    | { kind: "rect"; width: number; height: number }
    | { kind: "triangle"; base: number; height: number };

  function area(shape: Shape): number {
    switch (shape.kind) {
      case "circle":   return Math.PI * shape.radius ** 2;  // Circle
      case "rect":     return shape.width * shape.height;   // Rect
      case "triangle": return 0.5 * shape.base * shape.height;
      default:
        const _exhaustive: never = shape; // Exhaustiveness check!
        throw new Error(`Unknown: ${JSON.stringify(_exhaustive)}`);
    }
  }

6. TYPESCRIPT 5.5: INFERRED TYPE PREDICATES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  TypeScript 5.5 can automatically infer type predicates for functions that
  narrow via `===` or `typeof` checks, especially in `.filter()` callbacks:

  const arr: (string | null)[] = ["a", null, "b", null, "c"];

  // TS 5.5+: TypeScript infers this is (x: string | null) => x is string:
  const strings = arr.filter(x => x !== null);
  // type: string[]  ✅  (previously was (string | null)[])

  // Only works for simple, analyzable predicates inside filter/find etc.

7. COMMON GOTCHAS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  a) Type predicates are a PROMISE to TypeScript — if wrong, it's unsafe:
     function isString(x: unknown): x is string {
       return (x as any).length > 0; // ❌ Wrong! numbers have no .length but
     }                               // TypeScript will trust this predicate

  b) typeof null === "object" (always check null explicitly):
     function isObject(x: unknown) {
       if (typeof x === "object") {
         // x could still be null!
         x.toString(); // ❌ Error: x is possibly null
       }
       if (typeof x === "object" && x !== null) {
         x.toString(); // ✅
       }
     }

  c) instanceof doesn't work across frames (iframes / VM contexts):
     // Array from another iframe:
     const arr = otherFrame.someArray;
     arr instanceof Array; // may be false in old browsers!
     Array.isArray(arr);   // ✅ more reliable

  d) A type predicate only narrows in the TRUE branch (return true → narrows):
     function check(x: unknown): x is string {
       return typeof x === "string";
     }
     if (!check(x)) {
       // x is still unknown — not narrowed to "not string"
     }

8. INTERVIEW QUESTIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q1: What is a type guard in TypeScript?
    A type guard is a runtime check that narrows the type of a variable inside
    a conditional block. TypeScript's control flow analysis tracks what type a
    variable can be after each check and adjusts autocomplete and safety.

Q2: What are the built-in type guard mechanisms?
    typeof (primitives), instanceof (class instances), `in` operator (property
    existence), equality/strict equality checks, and truthiness checks.

Q3: What is a user-defined type guard / type predicate?
    A function with return type `x is Type` that tells TypeScript to narrow
    the parameter to that type when the function returns true:
    function isString(x: unknown): x is string { return typeof x === "string"; }

Q4: How do type predicates improve array filtering?
    Array.prototype.filter is typed to return the same element type as the
    original array. With a type predicate, it returns a narrowed array:
    arr.filter((x): x is number => typeof x === "number") returns number[]

Q5: What is the difference between a type predicate and an assertion function?
    A type predicate (returns boolean) narrows the type only in the if-branch.
    An assertion function (returns asserts x is Type) narrows for ALL subsequent
    code in the function and throws if the condition fails.

Q6: What does `asserts condition` mean?
    The function declares that if it returns normally (doesn't throw), the
    passed condition is true. TypeScript uses this to narrow the type in all
    code after the call.

Q7: Why is the `in` operator useful as a type guard?
    It checks for property existence at runtime, which lets TypeScript
    distinguish between object union members that have different properties:
    "swim" in pet narrows pet to the type that has a `swim` property.

Q8: What is wrong with this type guard: `typeof null === "object"`?
    In JavaScript (and TypeScript), typeof null === "object" is true due to a
    legacy bug. Always add a null check: typeof x === "object" && x !== null.

Q9: What new type guard feature did TypeScript 5.5 add?
    TypeScript 5.5 can infer type predicates automatically in many cases,
    particularly for simple narrowing expressions in .filter() callbacks.
    arr.filter(x => x !== null) now correctly infers a non-null array type.

Q10: When would you use an assertion function over a regular type predicate?
     When you want the narrowing to persist after the function call rather than
     just inside an if-block. Common in setup code, test fixtures, or
     validation middleware where you either proceed safely or throw immediately.
