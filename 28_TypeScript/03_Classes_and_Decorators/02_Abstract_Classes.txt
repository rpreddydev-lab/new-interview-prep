1. WHAT IS AN ABSTRACT CLASS?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  An abstract class is a class that:
  - CANNOT be instantiated directly
  - CAN contain a mix of implemented methods and abstract methods
  - Abstract methods declare a signature but provide NO implementation
  - Subclasses MUST implement all abstract methods

  Declared with the `abstract` keyword.

  abstract class Animal {
    abstract makeSound(): string; // No implementation — subclasses must provide

    move(): void {                // Concrete method — provided to all subclasses
      console.log("Moving...");
    }
  }

  const animal = new Animal(); // ❌ Error: cannot create an instance of abstract class
  
  class Dog extends Animal {
    makeSound(): string { return "Woof!"; } // ✅ must implement abstract method
  }

  const dog = new Dog();
  dog.makeSound(); // "Woof!"
  dog.move();      // "Moving..."

2. ABSTRACT PROPERTIES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Abstract classes can also declare abstract properties and getters/setters:

  abstract class Shape {
    abstract readonly name: string;   // abstract property
    abstract area(): number;          // abstract method
    abstract get perimeter(): number; // abstract getter

    describe(): string {
      return `${this.name}: area=${this.area()}, perimeter=${this.perimeter}`;
    }
  }

  class Circle extends Shape {
    readonly name = "Circle";
    constructor(public radius: number) { super(); }
    area(): number { return Math.PI * this.radius ** 2; }
    get perimeter(): number { return 2 * Math.PI * this.radius; }
  }

  class Rectangle extends Shape {
    readonly name = "Rectangle";
    constructor(public width: number, public height: number) { super(); }
    area(): number { return this.width * this.height; }
    get perimeter(): number { return 2 * (this.width + this.height); }
  }

  const shapes: Shape[] = [new Circle(5), new Rectangle(3, 4)];
  shapes.forEach(s => console.log(s.describe()));

3. ABSTRACT CLASS vs INTERFACE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  ┌────────────────────────────┬──────────────────────┬────────────────────────┐
  │ Feature                    │ Abstract Class       │ Interface              │
  ├────────────────────────────┼──────────────────────┼────────────────────────┤
  │ Can be instantiated        │ No                   │ No                     │
  │ Can have implementations   │ Yes                  │ No (default props only)│
  │ Can have constructors      │ Yes                  │ No                     │
  │ Access modifiers           │ Yes                  │ No (all public)        │
  │ Multiple inheritance       │ No (extends 1 only)  │ Yes (implements many)  │
  │ Runtime presence           │ Yes (JS class)       │ No (erased at compile) │
  │ Can use abstract keyword   │ Yes                  │ N/A (all abstract)     │
  │ Can have static members    │ Yes                  │ No                     │
  └────────────────────────────┴──────────────────────┴────────────────────────┘

  When to use which:
  - Use ABSTRACT CLASS when you want to share implementation + enforce a contract
  - Use INTERFACE when you only need to define a shape/contract (no implementation)

4. TEMPLATE METHOD PATTERN (Classic Use Case)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  The Template Method pattern defines a skeleton algorithm in an abstract class
  and lets subclasses fill in the varying steps:

  abstract class DataProcessor {
    // Template method — skeleton algorithm:
    process(data: string[]): string[] {
      const validated = this.validate(data);
      const transformed = this.transform(validated);
      const sorted = this.sort(transformed);
      return sorted;
    }

    // Concrete shared behavior:
    protected sort(data: string[]): string[] {
      return [...data].sort();
    }

    // Abstract steps — subclasses must implement:
    protected abstract validate(data: string[]): string[];
    protected abstract transform(data: string[]): string[];
  }

  class EmailProcessor extends DataProcessor {
    protected validate(data: string[]): string[] {
      return data.filter(s => s.includes("@"));
    }
    protected transform(data: string[]): string[] {
      return data.map(s => s.toLowerCase().trim());
    }
  }

  class NameProcessor extends DataProcessor {
    protected validate(data: string[]): string[] {
      return data.filter(s => s.length > 0);
    }
    protected transform(data: string[]): string[] {
      return data.map(s => s.charAt(0).toUpperCase() + s.slice(1));
    }
  }

5. USING ABSTRACT CLASS AS A TYPE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Even though abstract classes cannot be instantiated, they CAN be used as
  type annotations for variables and parameters:

  abstract class Logger {
    abstract log(msg: string): void;
    abstract error(msg: string): void;
  }

  class ConsoleLogger extends Logger {
    log(msg: string): void   { console.log(`[LOG] ${msg}`); }
    error(msg: string): void { console.error(`[ERR] ${msg}`); }
  }

  class FileLogger extends Logger {
    log(msg: string): void   { /* write to file */ }
    error(msg: string): void { /* write to file */ }
  }

  // Use abstract class as the type:
  function createService(logger: Logger) {
    logger.log("Service started"); // ✅
  }

  createService(new ConsoleLogger()); // ✅
  createService(new FileLogger());    // ✅

  // typeof AbstractClass — the constructor type:
  function createLogger(LoggerClass: typeof Logger): Logger {
    return new LoggerClass(); // ❌ Error! Cannot new an abstract class
  }

  // Correct way — use abstract constructor signature:
  type AbstractConstructor<T> = abstract new (...args: any[]) => T;
  function createLogger<T extends Logger>(Ctor: new () => T): T {
    return new Ctor();
  }

6. ABSTRACT CLASS WITH GENERICS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  abstract class Repository<T, ID> {
    protected items = new Map<ID, T>();

    save(id: ID, item: T): void {
      this.items.set(id, item);
    }

    findById(id: ID): T | undefined {
      return this.items.get(id);
    }

    findAll(): T[] {
      return [...this.items.values()];
    }

    // Abstract — each repository may validate differently:
    abstract validate(item: T): boolean;
  }

  interface User { id: number; name: string; email: string; }

  class UserRepository extends Repository<User, number> {
    validate(user: User): boolean {
      return user.name.length > 0 && user.email.includes("@");
    }
  }

  const repo = new UserRepository();
  repo.save(1, { id: 1, name: "Alice", email: "alice@example.com" });
  console.log(repo.findAll()); // [{ id: 1, ... }]

7. INTERVIEW QUESTIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q1: What is an abstract class in TypeScript?
    A class marked with `abstract` that cannot be directly instantiated.
    It can have both concrete (implemented) and abstract (unimplemented) methods.
    Subclasses extending it MUST provide implementations for all abstract members.

Q2: What is an abstract method?
    A method declared with `abstract` inside an abstract class — it has a
    signature but no body. All concrete subclasses must override and implement it.
    Abstract methods are only allowed in abstract classes.

Q3: Can you instantiate an abstract class directly?
    No. `new AbstractClass()` is a compile-time error. You can only instantiate
    concrete subclasses. However, you CAN use an abstract class as a TYPE for
    variables and parameters.

Q4: What is the difference between an abstract class and an interface?
    Abstract classes can have implemented methods, constructors, access modifiers,
    and static members. Interfaces are purely structural and are erased at runtime.
    A class can only extend ONE abstract class but implement MULTIPLE interfaces.

Q5: What is the Template Method design pattern and how do abstract classes enable it?
    The Template Method pattern defines a skeleton algorithm in an abstract base
    class with some steps implemented (shared behavior) and some abstract
    (customizable). Subclasses fill in the abstract steps. TypeScript abstract
    classes model this directly with abstract + concrete method combinations.

Q6: Can abstract classes have constructors?
    Yes. An abstract class constructor runs when a subclass calls `super()`.
    It's useful for sharing initialization logic across all subclasses.

Q7: Can abstract members have access modifiers like protected?
    Yes. `protected abstract validate(): boolean` means the method is abstract
    AND only accessible within the class hierarchy (not from outside).

Q8: How do you use an abstract class as a type parameter constraint?
    Use the `abstract new` construct or a type alias:
    type Constructor<T> = abstract new (...args: any[]) => T;
    function applyMixin<T>(Base: Constructor<T>) { ... }
    Regular `typeof AbstractClass` cannot be used with `new` since it's abstract.

Q9: Can abstract classes be generic?
    Yes. abstract class Repository<T, ID> { ... } is valid. The type parameters
    are inherited by subclasses and must be specified when extending:
    class UserRepo extends Repository<User, number> { ... }

Q10: When should you use an abstract class vs an interface?
     Use abstract class when: you need shared implementation, want to enforce
     subclass contracts, need constructors or access modifiers, or want to model
     a base type in a class hierarchy.
     Use interface when: you only need structural typing, you want multiple
     inheritance, you don't need runtime presence, or you're defining a pure shape.
