1. WHAT ARE DECORATORS?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Decorators are special declarations that can be attached to classes, methods,
  accessors, properties, or parameters. They add metadata, modify behavior, or
  wrap functionality using the `@expression` syntax.

  There are TWO versions of decorators:
  - LEGACY decorators — experimentalDecorators: true (TypeScript < 5.0 style)
  - TC39 decorators — the new JavaScript standard, TypeScript 5.0+

  Both are useful to know; this guide covers both.

2. ENABLING DECORATORS (tsconfig.json)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  // Legacy decorators (for Angular, NestJS, TypeORM, etc.):
  {
    "compilerOptions": {
      "experimentalDecorators": true,
      "emitDecoratorMetadata": true  // for design:type metadata (reflect-metadata)
    }
  }

  // TC39 / Stage 3 decorators (TypeScript 5.0+):
  // No special flag needed if NOT using experimentalDecorators.
  // Just use target: "ES2022" or higher.

3. LEGACY DECORATORS (experimentalDecorators)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  a) CLASS DECORATOR
     ─────────────────
     Receives the constructor. Can observe, modify, or replace the class:

     function sealed(constructor: Function) {
       Object.seal(constructor);
       Object.seal(constructor.prototype);
     }

     @sealed
     class BugReport {
       type = "report";
       title: string;
       constructor(t: string) { this.title = t; }
     }

     // Class decorator that adds a property:
     function addTimestamp<T extends new (...args: any[]) => {}>(constructor: T) {
       return class extends constructor {
         createdAt = new Date();
       };
     }

     @addTimestamp
     class User { constructor(public name: string) {} }

     const u = new User("Alice");
     (u as any).createdAt; // Date ✅

     // Decorator factory (configurable):
     function Component(config: { selector: string; template: string }) {
       return function(constructor: Function) {
         constructor.prototype.selector = config.selector;
         constructor.prototype.template = config.template;
       };
     }

     @Component({ selector: "app-button", template: "<button>Click</button>" })
     class ButtonComponent {}

  b) METHOD DECORATOR
     ──────────────────
     Arguments: (target, propertyKey, descriptor)
     - target: class prototype (or constructor for static methods)
     - propertyKey: method name
     - descriptor: PropertyDescriptor

     function log(target: any, key: string, descriptor: PropertyDescriptor) {
       const original = descriptor.value;
       descriptor.value = function (...args: any[]) {
         console.log(`Calling ${key} with`, args);
         const result = original.apply(this, args);
         console.log(`${key} returned`, result);
         return result;
       };
       return descriptor;
     }

     class Calculator {
       @log
       add(a: number, b: number): number { return a + b; }
     }

     new Calculator().add(2, 3);
     // "Calling add with [2, 3]"
     // "add returned 5"

  c) PROPERTY DECORATOR
     ───────────────────
     Arguments: (target, propertyKey)
     Cannot directly set the property descriptor; often used with reflect-metadata:

     function validate(target: any, propertyKey: string) {
       let value: any;
       Object.defineProperty(target, propertyKey, {
         get() { return value; },
         set(val: any) {
           if (typeof val !== "string") throw new Error("Must be string");
           value = val;
         }
       });
     }

     class Person {
       @validate
       name: string = "";
     }

  d) ACCESSOR DECORATOR
     ───────────────────
     Applied to get/set accessor. Same signature as method decorator.

     function configurable(value: boolean) {
       return function(target: any, key: string, descriptor: PropertyDescriptor) {
         descriptor.configurable = value;
         return descriptor;
       };
     }

     class Point {
       private _x = 0;
       @configurable(false)
       get x() { return this._x; }
     }

  e) PARAMETER DECORATOR
     ────────────────────
     Arguments: (target, methodName, parameterIndex)
     Commonly used for dependency injection metadata:

     function inject(token: string) {
       return function(target: any, key: string, index: number) {
         Reflect.defineMetadata(`inject:${index}`, token, target, key);
       };
     }

     class Service {
       constructor(@inject("DATABASE") private db: any) {}
     }

  f) DECORATOR EXECUTION ORDER
     ──────────────────────────
     1. Parameter decorators, then Method/Accessor/Property decorators
        for each member (inner-to-outer for stacked decorators on same member)
     2. Class decorator runs last

     @classDecorator
     class Example {
       @propertyDecorator
       prop: string = "";

       @methodDecorator
       method(@paramDecorator arg: string) {}
     }
     // Order: @paramDecorator → @methodDecorator → @propertyDecorator → @classDecorator

4. TC39 / STANDARD DECORATORS (TypeScript 5.0+)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  The new standard decorators are simpler and more type-safe. Key differences:
  - Receive a context object instead of prototype/descriptor directly
  - Can return a replacement value or void
  - No emitDecoratorMetadata needed

  a) Class decorator:
     function frozen<T extends new (...args: any[]) => object>(
       target: T,
       context: ClassDecoratorContext
     ): T {
       return class extends target {
         constructor(...args: any[]) {
           super(...args);
           Object.freeze(this);
         }
       };
     }

     @frozen
     class Config { url = "https://example.com"; }

  b) Method decorator:
     function bound(
       originalMethod: Function,
       context: ClassMethodDecoratorContext
     ) {
       context.addInitializer(function (this: any) {
         this[context.name] = originalMethod.bind(this);
       });
     }

     class Timer {
       @bound
       tick() { console.log("tick"); }
     }
     const { tick } = new Timer();
     tick(); // works without losing `this` ✅

5. PRACTICAL DECORATOR EXAMPLES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  a) Memoize (cache return values):
     function memoize(target: any, key: string, descriptor: PropertyDescriptor) {
       const cache = new Map<string, any>();
       const original = descriptor.value;
       descriptor.value = function (...args: any[]) {
         const cacheKey = JSON.stringify(args);
         if (cache.has(cacheKey)) return cache.get(cacheKey);
         const result = original.apply(this, args);
         cache.set(cacheKey, result);
         return result;
       };
     }

  b) Throttle (rate-limit a method):
     function throttle(delay: number) {
       return function(target: any, key: string, descriptor: PropertyDescriptor) {
         let lastCall = 0;
         const original = descriptor.value;
         descriptor.value = function (...args: any[]) {
           const now = Date.now();
           if (now - lastCall >= delay) {
             lastCall = now;
             return original.apply(this, args);
           }
         };
       };
     }

     class UI {
       @throttle(200)
       onScroll() { console.log("Scrolled"); }
     }

  c) Readonly property decorator:
     function immutable(target: any, key: string) {
       Object.defineProperty(target, key, { writable: false });
     }

  d) NestJS-style Route decorator:
     const routes: { method: string; path: string; handler: string }[] = [];
     function Get(path: string) {
       return function(target: any, key: string) {
         routes.push({ method: "GET", path, handler: key });
       };
     }
     class UserController {
       @Get("/users")
       getUsers() { return []; }
     }
     console.log(routes); // [{ method: "GET", path: "/users", handler: "getUsers" }]

6. INTERVIEW QUESTIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q1: What are decorators in TypeScript?
    Decorators are special `@expression` annotations that modify or annotate
    classes, methods, properties, accessors, or parameters at definition time.
    They're applied using `@decoratorName` syntax and are used heavily in
    frameworks like Angular, NestJS, and TypeORM.

Q2: What tsconfig flags are needed for legacy decorators?
    experimentalDecorators: true enables decorator support.
    emitDecoratorMetadata: true enables design-time type metadata
    (requires `reflect-metadata` package for DI frameworks).

Q3: What arguments does a method decorator receive?
    (target, propertyKey, descriptor)
    - target: prototype of the class (or constructor for static methods)
    - propertyKey: name of the decorated method
    - descriptor: PropertyDescriptor (writable, value, enumerable, configurable)

Q4: What is a decorator factory?
    A function that RETURNS a decorator. It's used to parameterize decorators:
    @Component({ selector: "app-root" }) — Component is a decorator factory
    that takes a config and returns the actual decorator function.

Q5: In what order do multiple decorators on the same class member execute?
    Top-to-bottom for evaluation (like function calls), but bottom-to-top for
    application. For @A @B on a method, @B's value is applied first, then @A.

Q6: What is the overall order of decorator execution in a class?
    1. Parameter decorators on each method (innermost first)
    2. Method / accessor / property decorators (declaration order, inner-to-outer)
    3. Class decorator last

Q7: What is emitDecoratorMetadata used for?
    When enabled, TypeScript emits design-time type information as metadata
    (e.g., `design:type`, `design:paramtypes`) using `Reflect.metadata`.
    Dependency injection frameworks use this to know what types to inject.

Q8: What is the difference between legacy decorators and TC39 decorators?
    Legacy (experimentalDecorators) use (target, key, descriptor) API.
    TC39/standard (TS 5.0+) use (value, context) API where context has
    name, kind, addInitializer, etc. TC39 decorators don't need emitDecoratorMetadata.

Q9: Can decorators be used on plain functions or just classes?
    In TypeScript, decorators can only be applied to class declarations and their
    members (methods, properties, accessors, parameters). They cannot be applied
    to standalone functions, variables, or modules.

Q10: Give a real-world example of a useful method decorator.
     A `@memoize` decorator caches the result of expensive function calls:
     function memoize(target, key, descriptor) {
       const cache = new Map();
       const original = descriptor.value;
       descriptor.value = function(...args) {
         const k = JSON.stringify(args);
         if (!cache.has(k)) cache.set(k, original.apply(this, args));
         return cache.get(k);
       };
     }
     Applied to a pure method, it automatically caches by arguments.
