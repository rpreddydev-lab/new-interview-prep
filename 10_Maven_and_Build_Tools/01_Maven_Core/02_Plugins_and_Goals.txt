WHAT IS A MAVEN PLUGIN?
────────────────────────
A Maven plugin is a collection of Goals. Each goal is a specific task that can
be executed either directly or bound to a lifecycle phase.

Plugins are themselves Maven artifacts with GAV coordinates. They are declared
in the <build><plugins> or <build><pluginManagement> sections of the POM.

  Plugin GAV format:  groupId:artifactId:version
  Goal format:        pluginPrefix:goalName  (e.g., compiler:compile)

Plugin prefix is typically the artifactId without "maven-" and "-plugin":
  maven-compiler-plugin → compiler
  maven-surefire-plugin → surefire
  maven-jar-plugin      → jar

─────────────────────────────────────────────────────────────────────────────────
PLUGIN DECLARATION IN POM.XML
─────────────────────────────────────────────────────────────────────────────────

  <build>
    <plugins>
      <plugin>
        <groupId>org.apache.maven.plugins</groupId>   <!-- optional for maven plugins -->
        <artifactId>maven-compiler-plugin</artifactId>
        <version>3.11.0</version>                      <!-- always pin the version! -->
        <configuration>
          <!-- Plugin-wide configuration -->
          <release>21</release>
        </configuration>
        <executions>
          <!-- Bind additional goals to specific phases -->
          <execution>
            <id>my-extra-compile</id>
            <phase>compile</phase>
            <goals><goal>compile</goal></goals>
            <configuration>
              <!-- Execution-specific config overrides plugin-wide config -->
            </configuration>
          </execution>
        </executions>
      </plugin>
    </plugins>
  </build>

  Note: org.apache.maven.plugins is the default groupId and can be omitted for
  official Maven plugins, but it's best practice to always include it for clarity.

─────────────────────────────────────────────────────────────────────────────────
ESSENTIAL MAVEN PLUGINS REFERENCE CARD
─────────────────────────────────────────────────────────────────────────────────

  COMPILATION
  ───────────
  maven-compiler-plugin
    Compiles Java source code.
    Key goals: compile, testCompile
    Key config: <release>, <source>, <target>, <annotationProcessorPaths>
    Version: 3.11.0+

  TESTING
  ───────
  maven-surefire-plugin
    Runs unit tests during the "test" phase.
    Matches: **/*Test.java, **/Test*.java, **/*Tests.java
    Key config: <skipTests>, <parallel>, <argLine>, <includes>, <excludes>
    Version: 3.1.2+

  maven-failsafe-plugin
    Runs integration tests during "integration-test" and reports at "verify".
    Matches: **/*IT.java, **/IT*.java, **/*ITCase.java
    Key goals (must be explicitly bound): integration-test, verify
    Version: 3.1.2+

  PACKAGING
  ─────────
  maven-jar-plugin
    Creates the JAR file.
    Key config: <archive><manifest> for MANIFEST.MF entries (main class, classpath)
    
  maven-war-plugin
    Creates the WAR file.
    Key config: <webResources>, <packagingExcludes>, <failIfNoWebXml>

  maven-shade-plugin
    Creates a "fat JAR" / "uber JAR" by bundling all dependencies into one JAR.
    Key goals: shade (bound to package phase)
    Handles class relocation to avoid namespace conflicts.

  maven-assembly-plugin
    Creates custom distribution archives (ZIP, TAR, etc.) with configurable content.
    Key goals: single (bound to package phase)
    Configures via assembly descriptors.

  spring-boot-maven-plugin
    Creates an executable Spring Boot JAR/WAR.
    Key goals: repackage, run, build-image
    Adds a nested JAR loader so all deps are embedded correctly.

  RESOURCES
  ─────────
  maven-resources-plugin
    Copies and optionally filters resources.
    Key goals: resources, testResources, copy-resources
    Key config: <filtering>, <encoding>, <delimiters>

  CODE QUALITY
  ────────────
  maven-checkstyle-plugin
    Enforces coding standards (Google style, Sun style, or custom rules).
    Key goals: check (fails build), checkstyle (just reports)
    Config: <configLocation> pointing to checkstyle XML

  maven-pmd-plugin
    Static analysis for common code bugs and bad practices.
    Key goals: check, pmd, cpd (copy-paste detection)

  spotbugs-maven-plugin (replaces FindBugs)
    Finds bug patterns in bytecode (null pointer dereferences, etc.).
    Key goals: check, spotbugs

  jacoco-maven-plugin
    Code coverage instrumentation and reporting.
    Key goals: prepare-agent, report, check
    Generates HTML, XML, CSV reports in target/site/jacoco/

  DEPENDENCY MANAGEMENT
  ─────────────────────
  maven-dependency-plugin
    Utilities for working with dependencies.
    Key goals:
      dependency:tree       — print dependency tree
      dependency:analyze    — find unused/undeclared deps
      dependency:copy       — copy specific JAR to output
      dependency:unpack     — extract JAR contents
      dependency:resolve    — list resolved dependency versions

  versions-maven-plugin
    Manages version numbers in poms.
    Key goals:
      versions:display-dependency-updates  — show available upgrades
      versions:use-latest-releases         — update POM to latest releases
      versions:set -DnewVersion=2.0.0      — update project version

  RELEASE / DEPLOYMENT
  ────────────────────
  maven-release-plugin
    Automates the release process.
    Key goals: prepare (tag in VCS, update version), perform (deploy to remote repo)
    Typically used with: mvn release:prepare release:perform
    Key config: <tagNameFormat>, <autoVersionSubmodules>

  maven-deploy-plugin
    Deploys artifacts to a remote repository.
    Key goals: deploy
    Requires <distributionManagement> in POM and credentials in settings.xml

  DOCUMENTATION
  ─────────────
  maven-javadoc-plugin
    Generates Javadoc documentation.
    Key goals: javadoc, jar (for -sources.jar), test-javadoc
    
  maven-source-plugin
    Creates a JAR of source code (for IDE "attach sources" feature).
    Key goals: jar, test-jar

  maven-site-plugin
    Generates a project website with reports.
    Key goals: site, deploy

  UTILITIES
  ─────────
  exec-maven-plugin
    Executes external programs or Java classes.
    Key goals: exec:exec (shell commands), exec:java (Java main class)

  build-helper-maven-plugin
    Various build helpers.
    Key goals: add-source (add extra source directories), parse-version,
               attach-artifact

PLUGIN CONFIGURATION IN DEPTH
─────────────────────────────────────────────────────────────────────────────────

  1. Global Configuration (applies to all executions of the plugin):
  ────────────────────────────────────────────────────────────────────
  <plugin>
    <artifactId>maven-surefire-plugin</artifactId>
    <configuration>
      <argLine>-Xmx512m</argLine>  <!-- All test executions get this -->
    </configuration>
  </plugin>

  2. Execution-Specific Configuration:
  ──────────────────────────────────────
  <plugin>
    <artifactId>maven-surefire-plugin</artifactId>
    <executions>
      <execution>
        <id>default-test</id>           <!-- default-test is the ID of the default binding -->
        <configuration>
          <argLine>-Xmx1024m</argLine>  <!-- Overrides global config for this execution -->
        </configuration>
      </execution>
    </executions>
  </plugin>

  3. Combining global + execution (execution config wins):
     If both are present, execution-specific config takes precedence.

─────────────────────────────────────────────────────────────────────────────────
MAVEN SHADE PLUGIN — FAT JAR EXAMPLE
─────────────────────────────────────────────────────────────────────────────────

  <plugin>
    <groupId>org.apache.maven.plugins</groupId>
    <artifactId>maven-shade-plugin</artifactId>
    <version>3.5.0</version>
    <executions>
      <execution>
        <phase>package</phase>
        <goals><goal>shade</goal></goals>
        <configuration>
          <!-- Set the main class in MANIFEST.MF -->
          <transformers>
            <transformer
              implementation="org.apache.maven.plugins.shade.resource.ManifestResourceTransformer">
              <mainClass>com.example.MainApplication</mainClass>
            </transformer>
            <!-- Merge META-INF/services files (for SPI) -->
            <transformer
              implementation="org.apache.maven.plugins.shade.resource.ServicesResourceTransformer"/>
          </transformers>
          <!-- Relocate classes to avoid namespace conflicts -->
          <relocations>
            <relocation>
              <pattern>com.google.guava</pattern>
              <shadedPattern>com.example.shaded.guava</shadedPattern>
            </relocation>
          </relocations>
          <!-- Exclude signature files (required for some signed JARs) -->
          <filters>
            <filter>
              <artifact>*:*</artifact>
              <excludes>
                <exclude>META-INF/*.SF</exclude>
                <exclude>META-INF/*.DSA</exclude>
                <exclude>META-INF/*.RSA</exclude>
              </excludes>
            </filter>
          </filters>
        </configuration>
      </execution>
    </executions>
  </plugin>

  NOTE: For Spring Boot apps, use spring-boot-maven-plugin instead of Shade.
  Shade is more appropriate for non-Spring libraries or command-line tools.

ENFORCER PLUGIN — BUILD PREREQUISITES
─────────────────────────────────────────────────────────────────────────────────

  Enforce rules about the build environment:

  <plugin>
    <groupId>org.apache.maven.plugins</groupId>
    <artifactId>maven-enforcer-plugin</artifactId>
    <version>3.4.1</version>
    <executions>
      <execution>
        <id>enforce</id>
        <goals><goal>enforce</goal></goals>
        <configuration>
          <rules>
            <!-- Require minimum Maven version -->
            <requireMavenVersion>
              <version>[3.8.0,)</version>
            </requireMavenVersion>
            <!-- Require minimum Java version -->
            <requireJavaVersion>
              <version>[17,)</version>
            </requireJavaVersion>
            <!-- Ban SNAPSHOT dependencies in release builds -->
            <requireReleaseDeps>
              <onlyWhenRelease>true</onlyWhenRelease>
              <message>No SNAPSHOT deps allowed in release builds!</message>
            </requireReleaseDeps>
            <!-- Prevent duplicate dependencies -->
            <banDuplicatePomDependencyVersions/>
          </rules>
        </configuration>
      </execution>
    </executions>
  </plugin>

DISCOVERING PLUGIN INFORMATION
─────────────────────────────────────────────────────────────────────────────────

  # List all goals of a plugin:
  mvn help:describe -Dplugin=compiler
  mvn help:describe -Dplugin=org.apache.maven.plugins:maven-compiler-plugin

  # Describe a specific goal:
  mvn help:describe -Dplugin=compiler -Dgoal=compile

  # Describe a goal with all parameters:
  mvn help:describe -Dplugin=compiler -Dgoal=compile -Ddetail

  # Show effective plugin configuration:
  mvn help:effective-pom  (includes plugin configuration from parent inheritance)

INTERVIEW QUICK-HITS
─────────────────────────────────────────────────────────────────────────────────

Q: What is the difference between maven-jar-plugin and maven-shade-plugin?
A: maven-jar-plugin creates a standard JAR containing only the project's compiled
   classes and resources (no dependencies). maven-shade-plugin creates a "fat JAR"
   or "uber JAR" by merging all dependencies into a single executable JAR. The fat
   JAR can be run with "java -jar" without needing external dependencies.

Q: What does the maven-enforcer-plugin do?
A: It enforces build prerequisites and policies. Common rules include requiring a
   minimum Maven/Java version, banning SNAPSHOT dependencies in releases, and
   preventing duplicate dependency declarations.

Q: How do you pass JVM arguments to tests in Maven?
A: In the maven-surefire-plugin configuration, use <argLine>-Xmx512m</argLine>.
   Note: When JaCoCo is used, it injects its agent into argLine, so you need to
   use @{argLine} to append rather than overwrite: <argLine>@{argLine} -Xmx512m</argLine>

Q: What is the difference between the Shade plugin and the Spring Boot Maven plugin?
A: Both create fat JARs, but the Spring Boot plugin creates a "layered" JAR where
   the application classes and dependencies are stored in a nested structure
   (not merged). This enables Docker layer caching optimizations and class loading
   isolation. The Shade plugin merges everything into a flat JAR. Use the Spring Boot
   plugin for Spring Boot apps; Shade for other scenarios.

Q: How do you skip a specific plugin execution?
A: Most plugins support a <skip> configuration property:
   <configuration><skip>true</skip></configuration>
   Or use command-line properties like -DskipTests, -Dcheckstyle.skip, -Djacoco.skip.
