================================================================================
  MAVEN IN CI/CD PIPELINES
================================================================================

OVERVIEW
────────
CI/CD (Continuous Integration / Continuous Delivery) pipelines automate building,
testing, and deploying software. Maven is the backbone of most Java CI/CD pipelines.

Key Maven commands used in CI/CD:
  ./mvnw clean verify              → Most common CI command (build + test)
  ./mvnw clean deploy              → Build, test, and publish to artifact repo
  ./mvnw clean verify -B --errors  → CI-friendly (no color, errors only)

─────────────────────────────────────────────────────────────────────────────────
IMPORTANT MAVEN FLAGS FOR CI/CD
─────────────────────────────────────────────────────────────────────────────────

  Flag                    Meaning
  ─────────────────────── ──────────────────────────────────────────────────────
  -B, --batch-mode        Non-interactive mode. Prevents Maven from prompting for input.
                          Required in CI to avoid hanging builds.
  --errors, -e            Print exception stack traces for errors.
  --fail-at-end, -fae     Run all modules even if some fail; report all failures at end.
                          Useful for multi-module builds to see all failures at once.
  --fail-never, -fn       Never fail the build even if tests fail (rare, for reports).
  -T 4, -T 1C             Parallel build with 4 threads (or 1 thread per CPU core).
  -o, --offline           Build offline using only local repository.
  -U, --update-snapshots  Force update of SNAPSHOT dependencies.
  -X, --debug             Enable debug output (verbose; for troubleshooting).
  -q, --quiet             Suppress all output except errors.
  --no-transfer-progress  Suppress download progress bars (cleaner CI logs in Maven 3.6.1+).

  Recommended CI command:
  ./mvnw clean verify -B --errors --no-transfer-progress

─────────────────────────────────────────────────────────────────────────────────
GITHUB ACTIONS — COMPLETE EXAMPLE
─────────────────────────────────────────────────────────────────────────────────

  .github/workflows/ci.yml:
  ─────────────────────────
  name: CI

  on:
    push:
      branches: [ main, develop ]
    pull_request:
      branches: [ main ]

  jobs:
    build:
      runs-on: ubuntu-latest
      strategy:
        matrix:
          java: [ '17', '21' ]   # Test against multiple Java versions

      steps:
        - name: Checkout code
          uses: actions/checkout@v4

        - name: Set up JDK ${{ matrix.java }}
          uses: actions/setup-java@v4
          with:
            java-version: ${{ matrix.java }}
            distribution: 'temurin'
            cache: 'maven'                    # Cache ~/.m2/repository automatically!

        - name: Build and test
          run: ./mvnw clean verify -B --errors --no-transfer-progress

        - name: Upload test results
          if: always()                        # Upload even if tests fail
          uses: actions/upload-artifact@v4
          with:
            name: test-results-java-${{ matrix.java }}
            path: '**/target/surefire-reports/**'

        - name: Upload coverage report
          uses: actions/upload-artifact@v4
          with:
            name: coverage-java-${{ matrix.java }}
            path: '**/target/site/jacoco/**'

  deploy:
    needs: build
    runs-on: ubuntu-latest
    if: github.ref == 'refs/heads/main'       # Only deploy from main branch

    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-java@v4
        with:
          java-version: '21'
          distribution: 'temurin'
          cache: 'maven'

      - name: Deploy to Nexus
        run: ./mvnw clean deploy -B -DskipTests --no-transfer-progress
        env:
          MAVEN_USERNAME: ${{ secrets.NEXUS_USER }}
          MAVEN_PASSWORD: ${{ secrets.NEXUS_PASSWORD }}

  For the above to work, settings.xml must read from env vars:
  ─────────────────────────────────────────────────────────────
  .github/maven/settings.xml:
  <settings>
    <servers>
      <server>
        <id>nexus-releases</id>
        <username>${env.MAVEN_USERNAME}</username>
        <password>${env.MAVEN_PASSWORD}</password>
      </server>
    </servers>
  </settings>

  Run: ./mvnw deploy -s .github/maven/settings.xml

GITLAB CI — COMPLETE EXAMPLE
─────────────────────────────────────────────────────────────────────────────────

  .gitlab-ci.yml:
  ─────────────────
  image: eclipse-temurin:21-jdk

  variables:
    MAVEN_OPTS: "-Dmaven.repo.local=$CI_PROJECT_DIR/.m2/repository"
    MAVEN_CLI_OPTS: "-B --errors --no-transfer-progress"

  cache:
    key: "${CI_JOB_NAME}"
    paths:
      - .m2/repository     # Cache Maven local repo between pipeline runs

  stages:
    - build
    - test
    - deploy

  build:
    stage: build
    script:
      - chmod +x mvnw
      - ./mvnw $MAVEN_CLI_OPTS compile

  test:
    stage: test
    script:
      - ./mvnw $MAVEN_CLI_OPTS verify
    artifacts:
      when: always
      reports:
        junit:
          - "**/target/surefire-reports/TEST-*.xml"
          - "**/target/failsafe-reports/TEST-*.xml"
      paths:
        - "**/target/site/jacoco/"

  deploy:
    stage: deploy
    script:
      - ./mvnw $MAVEN_CLI_OPTS deploy -DskipTests
    only:
      - main
    environment:
      name: production

JENKINS PIPELINE — COMPLETE EXAMPLE
─────────────────────────────────────────────────────────────────────────────────

  Jenkinsfile (Declarative Pipeline):
  ─────────────────────────────────────
  pipeline {
      agent any

      tools {
          jdk 'JDK-21'        // Configured in Jenkins > Global Tool Configuration
          maven 'Maven-3.9.6' // Or use Maven Wrapper instead
      }

      environment {
          MAVEN_OPTS = '-Xmx2g -XX:+UseG1GC'
      }

      stages {
          stage('Checkout') {
              steps { checkout scm }
          }

          stage('Build') {
              steps {
                  sh './mvnw clean compile -B --no-transfer-progress'
              }
          }

          stage('Test') {
              steps {
                  sh './mvnw verify -B --no-transfer-progress'
              }
              post {
                  always {
                      junit '**/target/surefire-reports/*.xml'
                      jacoco execPattern: '**/target/jacoco.exec'
                  }
              }
          }

          stage('SonarQube Analysis') {
              when { branch 'main' }
              steps {
                  withSonarQubeEnv('SonarQube') {
                      sh './mvnw sonar:sonar -B'
                  }
              }
          }

          stage('Deploy') {
              when { branch 'main' }
              steps {
                  withCredentials([usernamePassword(
                      credentialsId: 'nexus-deploy-creds',
                      usernameVariable: 'NEXUS_USER',
                      passwordVariable: 'NEXUS_PASS'
                  )]) {
                      sh '''
                          ./mvnw deploy -B -DskipTests \
                            -Dusername=$NEXUS_USER \
                            -Dpassword=$NEXUS_PASS \
                            --no-transfer-progress
                      '''
                  }
              }
          }
      }

      post {
          failure { emailext subject: 'Build Failed', body: '...', to: 'team@example.com' }
          success { echo 'Build succeeded!' }
      }
  }

CACHING MAVEN DEPENDENCIES IN CI
─────────────────────────────────────────────────────────────────────────────────

  Maven downloads all dependencies on every CI run (slow) unless you cache ~/.m2.

  GitHub Actions (using actions/setup-java cache):
  - uses: actions/setup-java@v4
    with:
      cache: 'maven'    # Automatically caches ~/.m2/repository

  Manual caching (if not using setup-java auto-cache):
  - uses: actions/cache@v4
    with:
      path: ~/.m2/repository
      key: ${{ runner.os }}-maven-${{ hashFiles('**/pom.xml') }}
      restore-keys: ${{ runner.os }}-maven-

  Invalidate cache when pom.xml changes (using hashFiles):
  key: maven-${{ hashFiles('**/pom.xml') }}

  GitLab CI (using local path caching):
  cache:
    paths: .m2/repository
    # Use local repo via MAVEN_OPTS:
    # MAVEN_OPTS: "-Dmaven.repo.local=$CI_PROJECT_DIR/.m2/repository"

SONARQUBE INTEGRATION
─────────────────────────────────────────────────────────────────────────────────

  POM configuration:
  <plugin>
    <groupId>org.sonarsource.scanner.maven</groupId>
    <artifactId>sonar-maven-plugin</artifactId>
    <version>3.10.0.2594</version>
  </plugin>

  Running SonarQube analysis:
  ./mvnw clean verify sonar:sonar \
    -Dsonar.projectKey=my-project \
    -Dsonar.host.url=https://sonarqube.company.com \
    -Dsonar.login=$SONAR_TOKEN

  JaCoCo + SonarQube — coverage must be run before Sonar:
  ./mvnw clean verify sonar:sonar
  (JaCoCo generates report during verify, Sonar picks it up)

DOCKER BUILD IN CI WITH MAVEN
─────────────────────────────────────────────────────────────────────────────────

  Option A: Spring Boot Buildpacks (no Dockerfile needed):
  ./mvnw spring-boot:build-image \
    -Dspring-boot.build-image.imageName=myregistry/my-app:${VERSION}

  Option B: Jib Maven Plugin (faster, no Docker daemon needed):
  <plugin>
    <groupId>com.google.cloud.tools</groupId>
    <artifactId>jib-maven-plugin</artifactId>
    <version>3.4.0</version>
    <configuration>
      <to>
        <image>myregistry/my-app:${project.version}</image>
      </to>
      <container>
        <jvmFlags>-Xmx512m</jvmFlags>
        <mainClass>com.example.Application</mainClass>
      </container>
    </configuration>
  </plugin>

  ./mvnw compile jib:build   # Build and push to registry (no local Docker needed)
  ./mvnw compile jib:dockerBuild  # Build to local Docker daemon

─────────────────────────────────────────────────────────────────────────────────
CI/CD BEST PRACTICES WITH MAVEN
─────────────────────────────────────────────────────────────────────────────────

  ✔ Always use ./mvnw (wrapper) instead of global mvn
  ✔ Always use -B (batch mode) in CI
  ✔ Use --no-transfer-progress for cleaner logs (Maven 3.6.1+)
  ✔ Cache ~/.m2/repository keyed on pom.xml hash
  ✔ Run "mvn clean verify" (not just "install") in CI — verify includes ITs
  ✔ Never use -DskipTests in production CI pipelines
  ✔ Keep credentials in CI secrets, never in pom.xml
  ✔ Use distributionManagement + settings.xml for deployments
  ✔ Run SonarQube AFTER verify (needs JaCoCo data)
  ✔ Upload test and coverage reports as pipeline artifacts
  ✔ Use -fae for multi-module builds to see all failures at once
  ✔ Set MAVEN_OPTS=-Xmx2g for large projects

INTERVIEW QUICK-HITS
─────────────────────────────────────────────────────────────────────────────────

Q: What Maven command would you use in a CI/CD pipeline?
A: ./mvnw clean verify -B --errors --no-transfer-progress
   - clean: Remove previous build artifacts
   - verify: Compile + test + integration test + verify
   - -B: Batch mode (non-interactive, required for CI)
   - --errors: Print stack traces on failures
   - --no-transfer-progress: Suppress download noise in logs

Q: What is the -B flag in Maven?
A: --batch-mode. Disables interactive prompts. Essential in CI/CD because without
   it, Maven might pause waiting for user input, hanging the pipeline indefinitely.

Q: How do you cache Maven dependencies in GitHub Actions?
A: Use the cache parameter in actions/setup-java: "cache: 'maven'".
   This automatically caches ~/.m2/repository and invalidates when pom.xml files change.

Q: Why should you use "mvn verify" rather than "mvn install" in CI?
A: "mvn install" installs artifacts to the local repository (~/.m2), which is
   unnecessary in CI (other jobs typically don't share the local repo). More
   importantly, "mvn verify" includes integration tests and all verify-phase checks
   (coverage thresholds, enforcer rules) which "mvn package" skips.

Q: How do you integrate SonarQube with Maven?
A: Add the sonar-maven-plugin to the POM, ensure JaCoCo coverage data is generated
   first (run "mvn verify"), then run "mvn sonar:sonar" with the Sonar server URL
   and authentication token. JaCoCo generates the coverage report that SonarQube reads.
