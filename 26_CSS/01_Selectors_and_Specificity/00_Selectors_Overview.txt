1. WHAT IS A SELECTOR?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

A CSS selector identifies which HTML element(s) a rule applies to.
CSS Selectors Level 4 defines a comprehensive set of selectors.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
2. BASIC SELECTORS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Universal Selector:
  * { box-sizing: border-box; }
  • Matches every element
  • Low performance if nested: .container * { ... }
  • Specificity: 0,0,0,0

Type Selector (element):
  p { line-height: 1.6; }
  h1, h2, h3 { font-weight: bold; }
  • Matches by tag name
  • Specificity: 0,0,0,1

Class Selector:
  .button { ... }
  .btn.primary { ... }   /* element must have BOTH classes */
  • Matches elements with the specified class
  • Specificity: 0,0,1,0

ID Selector:
  #header { ... }
  • Matches element with the specified ID (should be unique per page)
  • Specificity: 0,1,0,0 (very high — avoid for styling, prefer classes)

Attribute Selectors:
  [type]               /* has type attribute */
  [type="text"]        /* type equals "text" */
  [type~="text"]       /* type contains word "text" in space-separated list */
  [lang|="en"]         /* lang starts with "en" or "en-" (e.g., en, en-US) */
  [href^="https"]      /* href starts with "https" */
  [href$=".pdf"]       /* href ends with ".pdf" */
  [href*="example"]    /* href contains "example" */
  [type="text" i]      /* case-insensitive match (i flag) */

  Examples:
    a[href^="https"] { color: green; }
    a[href$=".pdf"]::after { content: " (PDF)"; }
    input[type="email"] { border-color: blue; }

3. GROUPING SELECTORS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Selector list (comma):
  h1, h2, h3, h4, h5, h6 {
    font-family: 'Georgia', serif;
  }
  /* Each selector is independent — if one is invalid, all are ignored */

:is() — forgiving selector list (CSS4):
  :is(h1, h2, h3, h4) { color: navy; }
  /* Invalid selectors in list are ignored, rest still apply */
  /* Specificity = highest specificity argument in the list */

:where() — zero specificity forgiving list:
  :where(h1, h2, h3) { color: navy; }
  /* Like :is() but specificity is always 0,0,0,0 */
  /* Perfect for base/reset styles you want to easily override */

:has() — relational selector (CSS4, "parent selector"):
  a:has(img) { border: 2px solid; }   /* <a> that contains an <img> */
  .card:has(.badge) { padding-top: 2rem; }
  li:has(+ li) { border-bottom: 1px solid; } /* li that has a sibling after it */
  form:has(input:invalid) { border-color: red; }

4. COMBINATOR SELECTORS (Covered in depth in 03_Combinators.txt)

A B         → Descendant: B inside A (any depth)
A > B       → Child: B is direct child of A
A + B       → Adjacent sibling: B immediately follows A
A ~ B       → General sibling: B follows A (any position, same parent)

7. SELECTOR PERFORMANCE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

CSS selectors are evaluated RIGHT TO LEFT by the browser:
  nav ul li a { ... }
  Browser reads: find all <a>, then filter those inside <li>, then <ul>, then <nav>

Performance tips:
  • Avoid deep selectors: nav > ul > li > a > span → use a class
  • Avoid universal selector (*) inside selectors: .nav * { ... }
  • Avoid overly broad descendant selectors
  • ID selectors are fast but avoid for styling (specificity issues)
  • Class selectors are the sweet spot (fast + reusable)

Modern browsers are very good at selector optimization, so this rarely matters
in practice — maintainability is more important than micro-optimizations.

8. SELECTOR CHAINING
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Multiple selectors without a space = AND (element must match ALL):
  a.external         /* <a> with class "external" */
  input[type]:focus  /* <input> with type attr that is focused */
  .btn.btn--primary  /* element with BOTH classes */
  p.intro:first-child/* <p> with class "intro" AND is first child */

9. :not() SELECTOR
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

:not() selects elements that do NOT match the argument:

  a:not(.active) { color: grey; }
  li:not(:last-child) { border-bottom: 1px solid #eee; }
  input:not([type="submit"]) { border: 1px solid; }

CSS4 :not() accepts a full selector list:
  :not(.hidden, .disabled) { display: block; }

  /* Specificity: :not() itself = 0, but argument contributes its specificity */
  :not(#foo) has same specificity as an ID selector (0,1,0,0)

10. KEY INTERVIEW QUESTIONS — SELECTORS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: What is the difference between .foo.bar and .foo .bar?
A: .foo.bar selects elements that have BOTH classes (chaining = AND logic).
   .foo .bar selects .bar elements that are DESCENDANTS of .foo (descendant combinator).

Q: What does the :is() pseudo-class do?
A: :is() takes a selector list and matches elements that match any selector in it.
   Unlike a plain comma list, invalid selectors inside :is() are forgiven (don't
   break the whole rule). Specificity = highest specificity argument inside :is().

Q: What is :where() and how does it differ from :is()?
A: Both accept a forgiving selector list. Difference: :where() always has zero
   (0,0,0,0) specificity, making it perfect for base/utility styles that should
   never win specificity battles.

Q: What is :has() and why is it important?
A: :has() is a relational/parent selector. a:has(img) selects <a> elements that
   CONTAIN an <img>. CSS previously had no way to style a parent based on its
   children. :has() changes that — it's one of the most powerful new selectors.
   It's fully supported in modern browsers as of 2023.

Q: How does CSS selector direction work?
A: Browsers evaluate compound selectors right-to-left for matching:
   div p a → browser finds all <a>, then checks if inside <p>, then inside <div>.
   This is why a flat class is faster than deep descendant selectors.

Q: What are attribute selectors and give examples?
A: Attribute selectors target elements based on presence/value of HTML attributes.
   [attr]        → has attr
   [attr="val"]  → attr equals val
   [attr^="val"] → starts with val
   [attr$="val"] → ends with val
   [attr*="val"] → contains val
   [attr~="val"] → space-separated list contains val
   [attr|="val"] → equals val or starts with val-
