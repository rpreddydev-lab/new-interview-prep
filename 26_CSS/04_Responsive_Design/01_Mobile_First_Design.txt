1. WHAT IS MOBILE-FIRST DESIGN?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Mobile-first design means writing your base CSS for the SMALLEST screen first,
then using min-width media queries to progressively enhance the layout for
larger screens.

  /* Mobile-first approach */
  .container {
    width: 100%;         /* mobile base */
    padding: 0 16px;
  }

  @media (min-width: 768px) {
    .container { max-width: 960px; margin: 0 auto; }
  }

  @media (min-width: 1200px) {
    .container { max-width: 1200px; }
  }

Contrast with desktop-first (max-width):
  .container {
    max-width: 1200px;   /* desktop base */
    margin: 0 auto;
  }
  @media (max-width: 768px) {
    .container { width: 100%; padding: 0 16px; }
  }

2. WHY MOBILE-FIRST? — THE ARGUMENTS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  1. PERFORMANCE:
     Mobile devices are slower and have weaker GPUs. Writing minimal base styles
     means mobile downloads less CSS. Complex desktop styles only load when
     the viewport is large enough to need them.

  2. PROGRESSIVE ENHANCEMENT:
     Start with the essential content and functionality. Add enhancements
     as screen space and capability grows. Forces you to think about CONTENT
     priority rather than decoration first.

  3. GLOBAL TRAFFIC:
     Over 55% of global web traffic is mobile (2024). Mobile-first aligns
     with real-world usage patterns.

  4. FEWER OVERRIDES:
     In desktop-first, you write desktop CSS then override it for mobile.
     In mobile-first, you write mobile CSS and ADD to it for desktop.
     Adding is cleaner and leads to less specificity conflicts.

  5. GOOGLE'S MOBILE-FIRST INDEXING:
     Google indexes the mobile version of your site first. Better mobile
     experience = better SEO.

3. THE VIEWPORT META TAG
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Without this tag, mobile browsers assume a desktop viewport (~980px) and
scale down — media queries won't work as intended.

  <meta name="viewport" content="width=device-width, initial-scale=1">

  Attributes:
    width=device-width   — viewport = actual device width (not 980px)
    initial-scale=1      — no zoom on load (100% zoom)
    maximum-scale=1      — ⚠️ prevents user zoom (AVOID — accessibility issue)
    minimum-scale=1      — prevents user from zooming out
    user-scalable=no     — ⚠️ disables pinch-zoom (AVOID — accessibility issue)

  Never set maximum-scale=1 or user-scalable=no — WCAG 2.1 requires
  that users can resize text up to 200% without loss of content/functionality.

4. MOBILE-FIRST LAYOUT PATTERNS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  /* Navigation: hamburger menu → horizontal navbar */
  nav {
    display: flex;
    flex-direction: column;  /* mobile: stacked menu */
    gap: 8px;
  }

  @media (min-width: 768px) {
    nav {
      flex-direction: row;   /* tablet+: horizontal */
      gap: 24px;
      align-items: center;
    }
  }

  /* Typography: smaller base → scale up */
  h1 { font-size: 1.75rem; }         /* mobile */
  @media (min-width: 768px)  { h1 { font-size: 2.5rem; } }
  @media (min-width: 1200px) { h1 { font-size: 3.5rem; } }

  /* Grid: single column → multi column */
  .cards {
    display: grid;
    grid-template-columns: 1fr;           /* mobile */
    gap: 16px;
  }

  @media (min-width: 640px) {
    .cards { grid-template-columns: repeat(2, 1fr); }
  }

  @media (min-width: 1024px) {
    .cards { grid-template-columns: repeat(3, 1fr); }
  }

5. FLUID TYPOGRAPHY WITH clamp()
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Instead of multiple media query breakpoints for font size,
  use clamp() for fluid scaling:

  /* clamp(min, preferred, max) */
  h1 { font-size: clamp(1.75rem, 5vw, 3.5rem); }
  /*               ^ mobile min  ^ scales  ^ desktop max */

  /* Paragraph — subtle scaling */
  p { font-size: clamp(1rem, 1.5vw, 1.25rem); }

  /* Fluid spacing */
  .section { padding: clamp(1rem, 5vw, 4rem); }

6. TOUCH TARGETS AND ACCESSIBILITY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Google and Apple guidelines: touch targets should be at least 44×44 CSS pixels.
  WCAG 2.5.5 (Level AAA): 44×44px. WCAG 2.5.8 (Level AA, 2.2+): 24×24px.

  button, a, input, [role="button"] {
    min-height: 44px;
    min-width: 44px;
    padding: 10px 16px;
  }

  /* Spacing between tap targets */
  nav a {
    padding: 12px 16px;   /* larger tap area without visual size change */
    display: inline-block;
  }

7. COMMON MOBILE-FIRST MISTAKES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  ❌ Missing viewport meta tag — media queries won't match on mobile
  ❌ Using max-width in CSS while calling it "mobile-first"
  ❌ Only testing on emulators — test on real devices
  ❌ Hiding mobile content with display:none — still downloads
  ❌ Using hover styles that don't work on touch (no hover on touch)
  ❌ Fixed widths (px) — use relative units (%, vw, rem)
  ❌ Tiny font sizes — minimum 16px for body text (prevents iOS auto-zoom)
  ❌ Disabling user-scalable — accessibility violation

  /* iOS auto-zoom prevention (input font-size < 16px triggers zoom) */
  input, select, textarea { font-size: 16px; }

8. KEY INTERVIEW QUESTIONS — MOBILE-FIRST DESIGN
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: What is mobile-first design and why is it recommended?
A: Mobile-first means writing base CSS for mobile and enhancing with min-width
   media queries for larger screens. It's recommended because: mobile traffic
   dominates globally, it improves performance on slow/constrained devices,
   it enforces content prioritization, and Google indexes the mobile version
   of sites first (mobile-first indexing).

Q: What is the difference between mobile-first (min-width) and desktop-first (max-width)?
A: Mobile-first starts with minimal styles and uses min-width to ADD complexity
   as screen size grows. Desktop-first starts with full desktop styles and uses
   max-width to strip/simplify for mobile. Mobile-first leads to cleaner,
   smaller base CSS and fewer style overrides.

Q: Why is the viewport meta tag critical for responsive design?
A: Without it, mobile browsers simulate a ~980px viewport and scale the entire
   page down. This makes min-width media queries useless on mobile because
   the browser thinks it's a wide viewport. `width=device-width` tells the
   browser to use the actual device width.

Q: What causes iOS to auto-zoom on form inputs?
A: When an input's font-size is less than 16px, iOS Safari auto-zooms the
   viewport to make it readable. Setting font-size: 16px on inputs prevents this.

Q: How do you create fluid typography without media query breakpoints?
A: Using clamp(): `font-size: clamp(1rem, 2.5vw, 2rem)` — the font scales
   fluidly with the viewport between the min (1rem) and max (2rem) values.
