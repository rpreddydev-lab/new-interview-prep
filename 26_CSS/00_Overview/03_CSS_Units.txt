1. OVERVIEW: ABSOLUTE vs RELATIVE UNITS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

CSS units fall into two categories:

ABSOLUTE — Fixed, do not change based on context:
  px, cm, mm, in, pt, pc, Q

RELATIVE — Scale relative to some reference point:
  em, rem, %, vw, vh, vmin, vmax, svh/lvh/dvh (new viewport units),
  ch, ex, ic, lh, rlh

2. ABSOLUTE UNITS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

px — Pixel:
  • 1px = 1 device-independent pixel
  • On high-DPI (Retina) screens, 1px CSS = 2 or 3 physical pixels
  • The most common absolute unit on screens
  • Use for: borders (1px), shadows, icon sizes, precise fine-grained control
  
  Note: Pixels are NOT truly "absolute" on screens with different pixel densities,
  but are considered absolute in CSS specification terms.

pt — Point:
  • 1pt = 1/72 inch (typography unit)
  • Primarily for print stylesheets
  • 1pt ≈ 1.333px

cm, mm — Centimeters, Millimeters:
  • For print layouts
  • 1cm = 37.8px approximately

in — Inch:
  • 1in = 96px (on screen), 1in = 1 inch (on print)
  • Only use for print

pc — Pica:
  • 1pc = 12pt = 16px

Q — Quarter-millimeter:
  • 1Q = 0.25mm
  • Rare, mostly for print

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
3. RELATIVE UNITS — FONT-BASED
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

em — Relative to the ELEMENT'S OWN font-size:
  • When used for font-size: relative to PARENT's font-size
  • When used for other properties: relative to the ELEMENT'S own font-size
  • COMPOUNDS through nesting (can cause "em cascade" issues)

  html { font-size: 16px; }
  .parent { font-size: 1.5em; }     /* 24px (1.5 × 16) */
  .child  { font-size: 1.5em; }     /* 36px (1.5 × 24) — COMPOUNDING! */
  .child  { padding: 1em; }         /* 36px (1 × 36 — element's own font-size) */

  Best for: padding/margin relative to font-size, media queries, component scaling

rem — Relative to the ROOT element (<html>) font-size:
  • Does NOT compound — always relative to :root / html
  • Default html font-size = 16px in most browsers
  • Changing html font-size scales the ENTIRE page

  html { font-size: 16px; }
  h1 { font-size: 2rem; }     /* 32px always */
  p  { font-size: 1rem; }     /* 16px always */
  .container { padding: 1.5rem; } /* 24px always */

  Trick for easy rem math:
  html { font-size: 62.5%; }   /* 62.5% of 16px = 10px */
  /* Now 1.6rem = 16px, 2.4rem = 24px, etc. */

ch — Width of the "0" (zero) character in the element's font:
  • Useful for setting textarea/input widths proportional to expected content
  • Rough proxy for "characters wide"
  input { width: 20ch; }   /* roughly fits 20 characters */

ex — Height of the lowercase "x" character (x-height):
  • Rarely used in practice

ic — Width of the "水" (CJK water) character:
  • For CJK text sizing

lh — Line height of the element:
  • Rarely used; useful for spacing relative to current line-height

rlh — Line height of the root element:

4. RELATIVE UNITS — PERCENTAGE (%)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

% is always relative to the PARENT element's corresponding property:

  width: 50%;          /* 50% of parent's width */
  height: 50%;         /* 50% of parent's HEIGHT (parent must have defined height!) */
  margin-top: 10%;     /* 10% of parent's WIDTH (not height!) */
  padding-bottom: 10%; /* 10% of parent's WIDTH */
  font-size: 80%;      /* 80% of parent's font-size */
  line-height: 150%;   /* 150% of element's own font-size */

⚠ margin/padding percentages are always calculated from parent WIDTH (even vertically!)
   This is used to create aspect-ratio boxes:
   .aspect-16-9 {
     width: 100%;
     padding-top: 56.25%;  /* 9/16 = 56.25% — maintains 16:9 ratio */
     position: relative;
   }

5. VIEWPORT UNITS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

vw  — 1% of the viewport WIDTH
vh  — 1% of the viewport HEIGHT
vmin — 1% of the smaller of vw or vh
vmax — 1% of the larger  of vw or vh

  .hero {
    width: 100vw;    /* full viewport width */
    height: 100vh;   /* full viewport height */
  }

  .square {
    width: 50vmin;
    height: 50vmin;  /* always square, fits in viewport */
  }

  /* Large fluid typography: */
  h1 { font-size: 5vw; }   /* scales with viewport width */

⚠ 100vh on mobile:
  Mobile browsers (especially iOS Safari) have a dynamic address bar.
  100vh doesn't account for the address bar → content gets clipped.
  
  Solution: New viewport units (CSS 2022+):

svh / svw — Small Viewport:
  • Based on the smallest viewport (address bar fully visible)
  • 100svh = height when address bar is shown

lvh / lvw — Large Viewport:
  • Based on the largest viewport (address bar hidden)
  • 100lvh = height when address bar is hidden

dvh / dvw — Dynamic Viewport:
  • Updates dynamically as address bar shows/hides
  • 100dvh = current visible height (reflows on scroll)
  • ⚠ Can cause layout shifts; use sparingly

  .hero { height: 100dvh; }   /* modern mobile-safe full height */

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
6. CONTAINER QUERY UNITS (CSS 2023+)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

cqw  — 1% of the container's width
cqh  — 1% of the container's height
cqi  — 1% of the container's inline size (usually width)
cqb  — 1% of the container's block size (usually height)
cqmin — smaller of cqi/cqb
cqmax — larger  of cqi/cqb

  .card-container {
    container-type: inline-size;
    container-name: card;
  }

  .card-title {
    font-size: clamp(1rem, 4cqw, 2rem);
  }

7. CALC(), MIN(), MAX(), CLAMP()
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

calc() — Perform math with mixed units:
  width: calc(100% - 64px);
  padding: calc(1rem + 4px);
  font-size: calc(var(--base-size) * 1.25);
  /* Operators: + - * / — spaces required around + and - */

min() — Use the smallest value:
  width: min(100%, 600px);   /* responsive, never exceeds 600px */
  font-size: min(4vw, 24px); /* scale with viewport, cap at 24px */

max() — Use the largest value:
  width: max(300px, 50%);    /* never shrinks below 300px */
  font-size: max(1rem, 2vw); /* ensures minimum readable size */

clamp(MIN, PREFERRED, MAX) — Fluid value between min and max:
  font-size: clamp(1rem, 2.5vw, 2rem);
  /* At small screens → 1rem, grows with viewport, caps at 2rem */

  width: clamp(300px, 50%, 900px);
  /* Preferred 50%, but never below 300px or above 900px */

  Fluid typography formula:
  font-size: clamp(
    1rem,
    0.875rem + 0.5vw,  /* grows with viewport */
    1.5rem
  );

8. WHEN TO USE WHICH UNIT — PRACTICAL GUIDE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Property             | Recommended Units
─────────────────────┼──────────────────────────────────────────────────────
font-size (root)     | px or % (usually left to browser default 16px)
font-size (body)     | rem (scales with user preferences)
font-size (headings) | rem or clamp() for fluid type
line-height          | unitless (e.g., 1.5) — scales with font-size
spacing (margin/pad) | rem (consistent across elements) or em (component)
border               | px (always 1px or 2px, not relative)
border-radius        | px or % (50% for circles)
width (layout)       | %, fr (grid), vw, calc()
width (component)    | rem, px, min/max/clamp
height (layout)      | avoid fixed heights when possible; use min-height
height (hero/section)| 100vh or 100dvh
media query          | em (most accessible) or px
icon size            | em (scales with surrounding text) or px
shadows              | px
z-index              | unitless integer
opacity/flex         | unitless (0–1, or integer)

9. ASPECT RATIO (modern)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Modern CSS has a native aspect-ratio property (no more padding-hack needed):

  .video-wrapper {
    aspect-ratio: 16 / 9;
    width: 100%;
  }

  .avatar {
    aspect-ratio: 1;      /* square */
    width: 48px;
  }

  .card {
    aspect-ratio: 4 / 3;
  }

10. KEY INTERVIEW QUESTIONS — CSS UNITS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: What is the difference between em and rem?
A: em is relative to the ELEMENT'S OWN font-size (or parent font-size when
   setting font-size itself). It compounds through nesting.
   rem is relative to the ROOT element's font-size (usually html) and does not
   compound. rem is more predictable for consistent sizing across components.

Q: What is 1rem by default?
A: 16px in most browsers (the default html font-size). If the user changes their
   browser font-size preference, rem units will adapt accordingly — px will not.
   This makes rem better for accessibility.

Q: What is the difference between vw/vh and %?
A: % is relative to the parent element.
   vw/vh are relative to the viewport (browser window) size.
   vw/vh are useful for full-screen layouts that don't depend on parent sizing.

Q: Why is 100vh problematic on mobile?
A: Mobile browsers have a dynamic toolbar (address bar) that shows/hides on scroll.
   100vh is calculated based on the MAXIMUM viewport (toolbar hidden), causing
   content to be cut off by the toolbar when visible.
   Solution: Use 100dvh (dynamic viewport height) which updates as the toolbar
   appears/disappears, or 100svh (small viewport = toolbar always shown).

Q: What is clamp() and how does it enable fluid typography?
A: clamp(min, preferred, max) returns the preferred value clamped between min
   and max. With a viewport-relative preferred value (e.g., 2.5vw), the font-size
   scales with the viewport but never goes below min or above max.
   This eliminates the need for font-size media query breakpoints.

Q: Why should you avoid fixed heights?
A: Fixed heights (e.g., height: 200px) cause overflow issues when content grows
   (more text, user-changed font-size). Prefer min-height to set a minimum while
   allowing growth, and avoid height unless absolutely necessary.

Q: What is the ch unit?
A: ch is equal to the width of the "0" (zero) character in the element's current
   font. It's useful for sizing text inputs: width: 20ch roughly fits 20 chars.
   Note: varies by font (monospace is more predictable).

Q: Can you use different units in calc()?
A: Yes. calc() can mix units: calc(100% - 80px), calc(1rem + 4px),
   calc(50vw - 2rem). This is one of its most powerful features.
   ⚠ + and - require spaces around them; * and / do not but should still use them.
