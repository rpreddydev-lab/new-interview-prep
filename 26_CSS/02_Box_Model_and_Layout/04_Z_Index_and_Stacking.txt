1. WHAT IS Z-INDEX?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

z-index controls the stacking order of overlapping positioned elements along
the Z axis (depth — which element is "on top").

  z-index: auto;      /* default — no new stacking context created */
  z-index: 1;         /* higher value = closer to viewer */
  z-index: 100;
  z-index: -1;        /* behind parent's stacking context */
  z-index: 9999;      /* common for modals/overlays */

Rules:
  • Only works on POSITIONED elements (position != static)
  • Higher z-index = on top
  • Elements with same z-index: later in DOM = on top (document order)
  • z-index is LOCAL to a stacking context — not global!

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
2. DEFAULT STACKING ORDER (without z-index)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

In normal flow (no z-index), elements are painted in this order (back to front):

  1. Background and borders of root element
  2. Negative z-index elements and their children (most negative first)
  3. Block-level elements in normal flow
  4. Floating elements and their children
  5. Inline elements in normal flow
  6. Positioned elements (position != static) with z-index: auto or z-index: 0
  7. Positive z-index elements (lowest first)

3. STACKING CONTEXT
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

A stacking context is a three-dimensional conceptual environment in which an
element and its descendants are stacked. It's self-contained: z-index inside
a stacking context is LOCAL — cannot "escape" to compare with z-index outside.

The root (<html>) creates the root stacking context.

What creates a new stacking context:
  • position: absolute/relative/fixed/sticky WITH z-index != auto
  • position: fixed or sticky (always, even without z-index)
  • opacity < 1 (e.g., opacity: 0.99)
  • transform != none
  • filter != none
  • perspective != none
  • backdrop-filter != none
  • isolation: isolate    ← explicit, clean way
  • mix-blend-mode != normal
  • will-change (when specifying any property that creates stacking context)
  • contain: layout | paint | strict | content
  • clip-path != none
  • mask != none

4. THE Z-INDEX TRAP (Most Common Bug)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

The most confusing aspect: z-index values only compete within the SAME stacking
context. A z-index: 9999 inside a low stacking context won't beat z-index: 1
in a higher stacking context.

Example:
  <div class="parent-a" style="position:relative; z-index: 1">
    <div class="child-a" style="position:relative; z-index: 9999">
      I appear to be on top...
    </div>
  </div>

  <div class="parent-b" style="position:relative; z-index: 2">
    <div class="child-b" style="position:relative; z-index: 1">
      But I cover child-a!
    </div>
  </div>

  Explanation:
  • parent-a (z-index: 1) vs parent-b (z-index: 2) → parent-b is on top
  • child-a's z-index: 9999 only matters within parent-a's stacking context
  • Since parent-a is BELOW parent-b, everything in parent-a is below parent-b

  Fix: Increase z-index of parent-a so its stacking context is above parent-b.

5. ISOLATION PROPERTY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

isolation: isolate creates a new stacking context explicitly, without any
visual side effects (unlike opacity or transform).

Use case: Prevent children from bleeding through other elements in complex UIs:
  .modal-container {
    isolation: isolate;   /* all z-index inside is contained here */
  }

  .component {
    isolation: isolate;   /* prevent mix-blend-mode from affecting outside */
  }

6. Z-INDEX BEST PRACTICES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. Use a z-index scale with meaningful names:
   :root {
     --z-below:   -1;
     --z-base:     0;
     --z-dropdown: 100;
     --z-sticky:   200;
     --z-overlay:  300;
     --z-modal:    400;
     --z-toast:    500;
     --z-tooltip:  600;
   }

   .sticky-nav   { z-index: var(--z-sticky); }
   .modal        { z-index: var(--z-modal); }
   .tooltip      { z-index: var(--z-tooltip); }

2. Don't use arbitrarily large numbers (z-index: 999999) — creates escalation
3. Use isolation: isolate to contain stacking contexts in components
4. Debug with browser DevTools — 3D view shows stacking order
5. Understand which parent creates a stacking context when debugging

7. COMMON STACKING CONTEXT BUGS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Bug 1 — Modal hides behind sticky header:
  /* Sticky header inadvertently creates stacking context */
  .header { position: sticky; top: 0; z-index: 10; }
  .modal-overlay { position: fixed; z-index: 9999; }
  /* Modal appears above header ✓ */
  /* But if .modal-overlay is inside a parent with opacity < 1 → fails */
  /* Fix: Move modal to direct child of body */

Bug 2 — Dropdown hides behind next section:
  .dropdown { position: absolute; z-index: 100; }
  /* Next sibling has position: relative; z-index: 1 */
  /* Dropdown appears behind — sibling's stacking context is "above" */
  /* Fix: Add z-index to the dropdown's parent container */

Bug 3 — transform kills fixed positioning:
  .parent { transform: scale(1); }  /* creates stacking context */
  .child  { position: fixed; }      /* now fixed to .parent, not viewport */

Bug 4 — opacity creates unintended stacking context:
  .card { opacity: 0.99; }  /* creates stacking context! */
  .tooltip-in-card { z-index: 9999; }  /* trapped inside .card's context */
  /* Fix: Remove opacity or use a different visual technique */

8. KEY INTERVIEW QUESTIONS — Z-INDEX AND STACKING
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: What is z-index and when does it work?
A: z-index controls the stack order of overlapping elements (which one appears
   on top). It only works on POSITIONED elements (position != static). Higher
   z-index = on top. Elements with the same z-index are ordered by DOM position.

Q: What is a stacking context?
A: An isolated 3D rendering environment. z-index values inside a stacking context
   compete only within that context and cannot "escape" to compare with elements
   outside. Each stacking context is treated as a unit by its parent context.

Q: What creates a stacking context?
A: Any element with: position + z-index != auto, position:fixed/sticky, opacity<1,
   transform != none, filter != none, isolation:isolate, will-change, backdrop-filter,
   mix-blend-mode != normal, and others. The root <html> always creates one.

Q: Why does my z-index:9999 element appear below z-index:1?
A: The element with z-index:9999 is likely inside a stacking context that has
   a lower z-index than the stacking context of the z-index:1 element.
   z-index values only compete within the same stacking context. The parent
   stacking context's z-index determines the overall order.

Q: What is isolation:isolate and when would you use it?
A: It creates a new stacking context without any visual effects. Use it to:
   (1) Prevent children's mix-blend-modes from affecting elements outside the component
   (2) Contain z-index values within a component so they don't escape
   (3) Debug stacking order issues by explicitly scoping contexts

Q: How do you debug z-index issues?
A: (1) Check all ancestor elements for stacking context creators (transform, opacity<1,
      position+z-index, filter, etc.)
   (2) Use browser DevTools → Layers panel (3D view of stacking contexts)
   (3) Ensure the element has a position value set (z-index requires positioned element)
   (4) Use isolation: isolate to intentionally contain a stacking context
