JAVA RELEASE HISTORY AND LTS VERSIONS
======================================

RELEASE CADENCE
---------------
  Before Java 9:   Major releases every 2–3 years (feature-driven)
  Java 9+:         6-month release cadence (time-driven, every March and September)
  LTS versions:    Long-Term Support — Oracle provides 8+ years of support
                   Released every 2 years (previously 3): 8, 11, 17, 21, 25 (upcoming)

LTS vs NON-LTS
--------------
  LTS:     Production-grade, long support lifecycle. Use for enterprise applications.
  Non-LTS: 6 months of support only. Good for experimenting with new features.

COMPLETE VERSION HISTORY
------------------------

  Java 1.0  (Jan 1996)   — Initial release. Applets, AWT, basic IO.
  Java 1.1  (Feb 1997)   — Inner classes, JDBC, JavaBeans, reflection.
  Java 1.2  (Dec 1998)   — Collections Framework, Swing, JIT compiler. "Java 2" brand.
  Java 1.3  (May 2000)   — HotSpot JVM default, RMI over IIOP.
  Java 1.4  (Feb 2002)   — assert keyword, regex, NIO (java.nio), XML.
  Java 5    (Sep 2004)   — Generics, autoboxing, enums, for-each, varargs, annotations,
                           java.util.concurrent, Scanner. MAJOR release.
  Java 6    (Dec 2006)   — Performance boost, scripting API (javax.script), JAXB.
  Java 7    (Jul 2011)   — Try-with-resources, diamond operator (<>), NIO2,
                           switch on Strings, multi-catch, fork/join framework.
  Java 8    (Mar 2014)   ★ LTS — Lambda expressions, Stream API, Optional, default methods,
                           java.time (JSR-310), method references, CompletableFuture,
                           Nashorn JS engine. MOST WIDELY DEPLOYED VERSION.
  Java 9    (Sep 2017)   — Module system (Project Jigsaw), JShell (REPL),
                           Collection factory methods (List.of, Map.of), HTTP/2 client (incubating),
                           private interface methods, improved Javadoc.
  Java 10   (Mar 2018)   — Local variable type inference (var keyword), G1 GC improvements.
  Java 11   (Sep 2018)   ★ LTS — var in lambda params, HTTP Client (stable),
                           String methods (isBlank, strip, lines), Files.readString,
                           removed Java EE/CORBA modules, ZGC (experimental).
  Java 12   (Mar 2019)   — Switch expressions (preview), JVM Constants API.
  Java 13   (Sep 2019)   — Text blocks (preview), switch expressions (preview 2).
  Java 14   (Mar 2020)   — Records (preview), instanceof pattern matching (preview),
                           helpful NullPointerExceptions, switch expressions (standard).
  Java 15   (Sep 2020)   — Sealed classes (preview), text blocks (standard), ZGC (standard).
  Java 16   (Mar 2021)   — Records (standard), instanceof pattern matching (standard),
                           vector API (incubating).
  Java 17   (Sep 2021)   ★ LTS — Sealed classes (standard), pattern matching switch (preview),
                           removal of Security Manager, removal of RMI Activation,
                           strong encapsulation of JDK internals. CURRENT WIDELY USED LTS.
  Java 18   (Mar 2022)   — UTF-8 as default charset, simple web server, code snippets in Javadoc.
  Java 19   (Sep 2022)   — Virtual threads (preview), structured concurrency (incubating),
                           pattern matching for switch (preview 3).
  Java 20   (Mar 2023)   — Virtual threads (preview 2), scoped values (incubating).
  Java 21   (Sep 2023)   ★ LTS — Virtual threads (standard), structured concurrency (preview),
                           sequenced collections, record patterns, pattern matching for switch
                           (standard), string templates (preview). LATEST LTS.
  Java 22   (Mar 2024)   — Unnamed variables/patterns, stream gatherers (preview),
                           class-file API (preview), foreign function & memory API (standard).
  Java 23   (Sep 2024)   — Markdown in Javadoc, primitive patterns in switch (preview).
  Java 24   (Mar 2025)   — Ahead-of-time class loading & linking, quantum-resistant crypto.
  Java 25   (Sep 2025)   ★ LTS (upcoming) — Next LTS after Java 21.

KEY FEATURES BY ERA
-------------------
  Java 5   → Generics, annotations, concurrency utilities (the modern Java foundation)
  Java 7   → Try-with-resources, NIO2, fork/join
  Java 8   → Functional programming (lambdas, streams) — the biggest shift in Java history
  Java 9   → Modularity (JPMS)
  Java 11  → HTTP Client, String improvements, cleaned-up JDK
  Java 17  → Sealed classes, records finalized, strong encapsulation
  Java 21  → Virtual threads (Project Loom) — massive concurrency scalability shift

COMMON INTERVIEW QUESTIONS
---------------------------
Q: What is an LTS version and why does it matter?
A: LTS (Long-Term Support) versions receive extended security and bug-fix updates (8+ years from
   Oracle, 3 years from OpenJDK community). Most enterprises standardize on LTS: 8, 11, 17, 21.
   Non-LTS versions only get 6 months of support.

Q: What are the most important Java versions to know for interviews?
A: Java 8 (lambdas/streams — still dominant in enterprise), Java 11 (HTTP Client, String methods),
   Java 17 (sealed/records — current stable LTS at many companies), Java 21 (virtual threads).

Q: What was introduced in Java 8 that fundamentally changed the language?
A: Lambda expressions + Stream API + functional interfaces — these brought functional programming
   into Java, enabling declarative data processing, reducing boilerplate, and making parallel
   stream processing trivial. Also: Optional, default methods, new Date/Time API.

Q: What is Project Loom?
A: Project Loom delivered Virtual Threads (java.lang.VirtualThread) in Java 21. Virtual threads
   are lightweight JVM-managed threads (not OS threads) — you can create millions of them cheaply.
   This eliminates the need for reactive/async programming in most IO-bound workloads.

Q: Why is Java 8 still so widely used despite newer LTS versions?
A: Enterprise software has long upgrade cycles due to compatibility concerns, dependency chain
   updates, and regulatory requirements. Java 8 introduced the most impactful changes
   (lambdas/streams), has massive ecosystem support, and upgrade to 11/17 requires migrating
   away from deprecated/removed APIs (e.g., sun.* packages, Java EE modules removed in Java 11).
