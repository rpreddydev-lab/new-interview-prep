JAVA PLATFORM: JDK vs JRE vs JVM
=================================

THE THREE-LAYER MODEL
---------------------
  ┌─────────────────────────────────────────────────────┐
  │                       JDK                          │  ← Developer tool (compile + run)
  │  ┌───────────────────────────────────────────────┐  │
  │  │                   JRE                         │  │  ← Runtime environment (run only)
  │  │  ┌─────────────────────────────────────────┐  │  │
  │  │  │                JVM                      │  │  │  ← Executes bytecode
  │  │  └─────────────────────────────────────────┘  │  │
  │  │  + Java Class Libraries (rt.jar / java.*)     │  │
  │  └───────────────────────────────────────────────┘  │
  │  + javac, javadoc, jar, jdb, jconsole, jshell       │
  └─────────────────────────────────────────────────────┘

JVM — Java Virtual Machine
---------------------------
- An abstract computing machine / runtime specification.
- NOT a physical machine — it is a software layer that runs on the OS.
- Responsibilities:
    1. Load .class files (class loader subsystem)
    2. Verify bytecode (bytecode verifier — security)
    3. Execute bytecode (interpreter + JIT compiler)
    4. Manage memory (heap, stack, metaspace, GC)
    5. Provide runtime services (exception handling, threading)

- JVM is platform-specific (there's a Windows JVM, Linux JVM, macOS JVM).
- The BYTECODE it executes is platform-independent → WORA principle.

- Popular JVM implementations:
    • HotSpot    — Oracle's reference JVM (OpenJDK default)
    • GraalVM    — Polyglot JVM, ahead-of-time native compilation
    • OpenJ9     — IBM's JVM (used in Eclipse)
    • Azul Zing  — Low-latency JVM for financial systems

JRE — Java Runtime Environment
--------------------------------
- Contains the JVM + the Java Class Libraries (standard library).
- Everything needed to RUN a Java application.
- Does NOT include the compiler (javac) or development tools.
- End users who only run Java apps need the JRE.
- Note: Since Java 9, JRE as a standalone download was discontinued.
  The JDK now serves as both development and runtime package.

JDK — Java Development Kit
----------------------------
- Contains the JRE + development tools.
- Tools included:
    javac     — Java compiler (.java → .class)
    java      — JVM launcher
    javadoc   — Documentation generator
    jar       — Archive tool (.jar files)
    jdb       — Java debugger
    jconsole  — JMX monitoring console
    jshell    — Interactive REPL (Java 9+)
    jmap      — Heap dump tool
    jstack    — Thread dump tool
    javap     — Class file disassembler

MEMORY AREAS IN JVM (Overview — detailed in 09_JVM_Internals)
--------------------------------------------------------------
  Method Area (Metaspace) — class metadata, static variables, constants
  Heap                    — object instances, arrays (GC managed)
  Stack                   — per-thread; method frames, local variables
  PC Register             — per-thread; tracks current instruction
  Native Method Stack     — for native (C/C++) method calls

COMMON INTERVIEW QUESTIONS
---------------------------
Q: What is the difference between JDK, JRE, and JVM?
A: JVM is the runtime engine that executes bytecode. JRE = JVM + standard class libraries
   (enough to run a Java app). JDK = JRE + development tools like javac, jdb, jar (needed
   to write and compile Java code). A developer needs JDK; an end user only needs JRE/JDK.

Q: Is JVM platform independent?
A: No — the JVM itself is platform-specific. There are different JVM binaries for Windows,
   Linux, macOS. What is platform-independent is the BYTECODE (.class files) that runs on
   any JVM.

Q: What is JIT compilation?
A: Just-In-Time (JIT) compilation is a JVM optimization where frequently executed bytecode
   ("hot" methods) are compiled to native machine code at runtime. This eliminates repeated
   interpretation overhead and brings performance close to natively compiled languages.
   HotSpot uses tiered compilation: C1 (fast, less optimized) → C2 (slower, highly optimized).

Q: What happened to JRE after Java 9?
A: Oracle removed the standalone JRE download from Java 9+ because of the module system
   (Project Jigsaw). Instead, developers use jlink to create custom runtime images with only
   the modules their application needs. The JDK now serves as the single distribution.

Q: What is GraalVM?
A: An advanced JVM from Oracle that supports:
   - Polyglot execution (Java, JavaScript, Python, Ruby on one JVM)
   - Ahead-of-time (AOT) native compilation via GraalVM Native Image
     → produces small, fast-starting native executables with no JVM overhead
   - Used heavily in frameworks like Quarkus and Micronaut for cloud-native Java.
