SET: HASHSET vs LINKEDHASHSET vs TREESET
==========================================

THE SET INTERFACE
------------------
  java.util.Set<E> extends Collection<E>
  - No duplicate elements — based on equals() and hashCode()
  - At most one null element (TreeSet does NOT allow null)
  - No guaranteed order (except LinkedHashSet and TreeSet)
  - No indexed access (no get(int index))

  Key operations: add(), remove(), contains(), size(), isEmpty(), iterator()
  Set-specific: retainAll (intersection), removeAll (difference), addAll (union)

HASHSET
--------
Internal Structure: Backed by a HashMap<E, PRESENT>
  - Every element is stored as a key in a HashMap with a dummy value (static Object PRESENT)
  - Hashes the element → computes bucket index → stores there
  - Default initial capacity: 16, load factor: 0.75
  - Resizes (doubles) when size > capacity × loadFactor

Key Operations:
  add(e)       → O(1) average, O(n) worst (hash collision)
  remove(e)    → O(1) average
  contains(e)  → O(1) average
  size()       → O(1)

Order: NONE — iteration order is unpredictable

Example:
  Set<String> set = new HashSet<>();
  set.add("banana");
  set.add("apple");
  set.add("cherry");
  set.add("apple");   // ignored — duplicate
  System.out.println(set.size()); // 3
  System.out.println(set.contains("apple")); // true

  // Set operations
  Set<Integer> a = new HashSet<>(Arrays.asList(1, 2, 3, 4));
  Set<Integer> b = new HashSet<>(Arrays.asList(3, 4, 5, 6));
  a.retainAll(b);  // intersection: a = [3, 4]
  a.removeAll(b);  // difference:   a = [1, 2]
  a.addAll(b);     // union:        a = [1, 2, 3, 4, 5, 6]

Contract: Objects stored in HashSet MUST correctly implement equals() and hashCode().
  - If two objects are equal (equals() returns true), they MUST have the same hashCode.
  - Violating this breaks HashSet — both duplicates will be stored.

LINKEDHASHSET
--------------
Internal Structure: Backed by a LinkedHashMap<E, PRESENT>
  - Maintains a doubly-linked list through all entries in addition to hash buckets
  - Preserves INSERTION ORDER during iteration

Key Operations: Same O(1) as HashSet (slightly slower due to linked list overhead)
Order: Insertion order preserved

Example:
  Set<String> linked = new LinkedHashSet<>();
  linked.add("banana");
  linked.add("apple");
  linked.add("cherry");
  System.out.println(linked); // [banana, apple, cherry] — insertion order

Use case: When you need Set uniqueness + predictable iteration order.

TREESET
--------
Internal Structure: Backed by a TreeMap<E, PRESENT> — a Red-Black tree
  - Elements are stored in sorted order (natural ordering via Comparable,
    or custom ordering via Comparator provided at construction time)

Key Operations:
  add(e)       → O(log n)
  remove(e)    → O(log n)
  contains(e)  → O(log n)
  first()      → O(log n) — smallest element
  last()       → O(log n) — largest element
  headSet(e)   → view of elements < e
  tailSet(e)   → view of elements >= e
  subSet(a, b) → view of elements in [a, b)
  floor(e)     → greatest element ≤ e
  ceiling(e)   → smallest element ≥ e

Order: SORTED (natural or custom comparator)
NULL: NOT allowed — throws NullPointerException (can't compare null)

Example:
  TreeSet<Integer> tree = new TreeSet<>();
  tree.add(5); tree.add(1); tree.add(3); tree.add(7);
  System.out.println(tree);          // [1, 3, 5, 7]
  System.out.println(tree.first());  // 1
  System.out.println(tree.last());   // 7
  System.out.println(tree.floor(4)); // 3
  System.out.println(tree.ceiling(4)); // 5
  System.out.println(tree.headSet(5)); // [1, 3]

  // Custom ordering with Comparator
  Set<String> byLength = new TreeSet<>(Comparator.comparingInt(String::length)
                                                  .thenComparing(Comparator.naturalOrder()));
  byLength.add("banana"); byLength.add("fig"); byLength.add("apple");
  System.out.println(byLength); // [fig, apple, banana]

SORTEDSET AND NAVIGABLESET
----------------------------
  SortedSet<E>:    first(), last(), headSet(to), tailSet(from), subSet(from, to), comparator()
  NavigableSet<E>: floor(), ceiling(), lower(), higher(), pollFirst(), pollLast(), descendingSet()

  TreeSet implements NavigableSet → has all these methods.

COMPARISON TABLE
-----------------
  Feature              | HashSet        | LinkedHashSet    | TreeSet
  ---------------------|----------------|------------------|------------------
  Internal structure   | HashMap        | LinkedHashMap    | TreeMap (R-B tree)
  Ordering             | None (random)  | Insertion order  | Sorted (natural/comparator)
  add/remove/contains  | O(1) avg       | O(1) avg         | O(log n)
  Allows null?         | ✅ One null    | ✅ One null      | ❌ No null
  Range operations?    | ❌ No          | ❌ No            | ✅ headSet/tailSet/subSet
  Memory overhead      | Low            | Moderate         | High (R-B tree nodes)
  Thread-safe          | ❌ No          | ❌ No            | ❌ No

UNIQUENESS CONTRACT
--------------------
  For HashSet/LinkedHashSet: equality defined by equals() + hashCode()
  For TreeSet: equality defined by compareTo() (or Comparator.compare())

  TRAP: If compareTo() says two objects are equal, TreeSet treats them as duplicates —
        even if equals() would say they differ.

  Example:
    TreeSet<String> set = new TreeSet<>(String.CASE_INSENSITIVE_ORDER);
    set.add("Apple");
    set.add("apple"); // Not added! compareTo with CASE_INSENSITIVE sees them as equal
    System.out.println(set.size()); // 1

COMMON INTERVIEW QUESTIONS
---------------------------
Q: How does HashSet prevent duplicates?
A: HashSet is backed by a HashMap. When you call add(e):
   1. Compute e.hashCode() to find the bucket.
   2. Check all elements in that bucket using equals().
   3. If an equal element exists, the add is rejected (returns false).
   4. Otherwise, the element is stored as a key in the internal HashMap.
   Both equals() and hashCode() must be correctly implemented for this to work.

Q: What happens if two different objects have the same hashCode in a HashSet?
A: They go into the same bucket (hash collision). The Set then uses equals() to distinguish them.
   If equals() returns false, both are stored in the same bucket (as a linked list or tree).
   This degrades performance from O(1) to O(n) or O(log n) in extreme cases.

Q: When should you use TreeSet instead of HashSet?
A: Use TreeSet when you need:
   - Elements in sorted order (for iteration or display)
   - Range operations: find all elements between X and Y
   - First/last/floor/ceiling queries
   - Custom sort order via Comparator
   Otherwise, prefer HashSet for O(1) performance.

Q: Can you store null in a TreeSet?
A: No. TreeSet sorts elements by calling compareTo() or the Comparator. Comparing null throws
   NullPointerException. HashSet allows one null (it hashes null as bucket 0).

Q: What's the difference between LinkedHashSet and TreeSet ordering?
A: LinkedHashSet preserves insertion order — elements come out in the order they were added.
   TreeSet preserves sorted order — elements come out in natural order (or comparator order),
   regardless of insertion order.
