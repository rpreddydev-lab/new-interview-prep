COLLECTIONS UTILITY CLASS
==========================

OVERVIEW
---------
  java.util.Collections is a utility class with static methods for operating on Collection objects.
  (Not to be confused with java.util.Collection the interface.)

  Cannot be instantiated — all methods are static.
  Covers: sorting, searching, shuffling, reversing, frequency counting, min/max,
          thread-safe wrappers, unmodifiable wrappers, and more.

SORTING METHODS
----------------
  Collections.sort(List<T> list)                    // natural order, in-place
  Collections.sort(List<T> list, Comparator<T> c)   // custom order, in-place

  // Java 8+ — List has its own sort method:
  list.sort(Comparator.comparing(String::length));

  Algorithm: TimSort (stable, O(n log n))
  NOTE: Only works on List — not Set or Map directly.

  Example:
    List<String> names = Arrays.asList("Charlie", "Alice", "Bob");
    Collections.sort(names);                          // [Alice, Bob, Charlie]
    Collections.sort(names, Comparator.reverseOrder()); // [Charlie, Bob, Alice]

SEARCHING
----------
  Collections.binarySearch(List<T> list, T key)             // natural order (list must be sorted)
  Collections.binarySearch(List<T> list, T key, Comparator<T> c) // custom order

  Returns: index if found; -(insertion point) - 1 if not found
  NOTE: List MUST be sorted in the same order as the comparator before calling binarySearch.

  Example:
    List<Integer> nums = Arrays.asList(1, 3, 5, 7, 9);
    int idx = Collections.binarySearch(nums, 5);   // returns 2
    int notFound = Collections.binarySearch(nums, 4); // returns -3 (would be at index 2)

REORDERING
-----------
  Collections.reverse(List<T> list)       // reverses order in-place
  Collections.shuffle(List<T> list)       // random order (uses random source)
  Collections.shuffle(List<T> list, Random r) // with seed for reproducibility
  Collections.rotate(List<T> list, int distance) // rotate right by distance

  Example:
    List<Integer> list = new ArrayList<>(Arrays.asList(1,2,3,4,5));
    Collections.reverse(list);  // [5, 4, 3, 2, 1]
    Collections.shuffle(list);  // random order
    Collections.rotate(list, 2); // e.g., [4, 5, 1, 2, 3] (last 2 moved to front)

MIN/MAX
--------
  Collections.min(Collection<T> c)                     // minimum using natural order
  Collections.max(Collection<T> c)                     // maximum using natural order
  Collections.min(Collection<T> c, Comparator<T> comp) // minimum with comparator
  Collections.max(Collection<T> c, Comparator<T> comp) // maximum with comparator

  Example:
    List<Integer> nums = Arrays.asList(3, 1, 4, 1, 5, 9);
    System.out.println(Collections.min(nums)); // 1
    System.out.println(Collections.max(nums)); // 9

FREQUENCY AND DISJOINT
-----------------------
  Collections.frequency(Collection<?> c, Object o) // count occurrences of o
  Collections.disjoint(Collection<?> c1, Collection<?> c2) // true if no common elements

  Example:
    List<String> words = Arrays.asList("a", "b", "a", "c", "a");
    System.out.println(Collections.frequency(words, "a")); // 3
    System.out.println(Collections.disjoint(words, Arrays.asList("x", "y"))); // true

FILL AND COPY
--------------
  Collections.fill(List<T> list, T obj)            // replace all elements with obj
  Collections.copy(List<T> dest, List<T> src)      // copy src into dest (dest must be >= src size)
  Collections.nCopies(int n, T obj)                // immutable List of n copies of obj
  Collections.replaceAll(List<T> list, T oldVal, T newVal) // replace occurrences

  Example:
    List<String> list = new ArrayList<>(Arrays.asList("a", "b", "c"));
    Collections.fill(list, "x"); // ["x", "x", "x"]

    List<String> template = Collections.nCopies(5, "hello"); // [hello, hello, hello, hello, hello]

UNMODIFIABLE WRAPPERS
----------------------
  Return a view that throws UnsupportedOperationException on mutation attempts.
  The underlying collection CAN still be mutated directly (the wrapper is just a view).

  Collections.unmodifiableList(List<T> list)
  Collections.unmodifiableSet(Set<T> set)
  Collections.unmodifiableMap(Map<K,V> map)
  Collections.unmodifiableSortedSet(SortedSet<T> s)
  Collections.unmodifiableSortedMap(SortedMap<K,V> m)
  Collections.unmodifiableCollection(Collection<T> c)

  Example:
    List<String> mutable = new ArrayList<>(Arrays.asList("a", "b", "c"));
    List<String> immutable = Collections.unmodifiableList(mutable);
    immutable.add("d"); // throws UnsupportedOperationException
    mutable.add("d");   // OK — and immutable.size() is now 4 (it's a view!)

  PREFER Java 9+ List.of() / Map.of() / Set.of() for true immutability
  (not backed by mutable collection):
    List<String> truly = List.of("a", "b", "c"); // completely immutable

SYNCHRONIZED WRAPPERS
-----------------------
  Wrap any collection to make it thread-safe (all methods synchronized).
  ⚠️ Compound operations still need external synchronization!

  Collections.synchronizedList(List<T> list)
  Collections.synchronizedSet(Set<T> set)
  Collections.synchronizedMap(Map<K,V> map)
  Collections.synchronizedSortedSet(SortedSet<T> s)
  Collections.synchronizedSortedMap(SortedMap<K,V> m)

  Example:
    List<String> syncList = Collections.synchronizedList(new ArrayList<>());
    // Individual operations are thread-safe:
    syncList.add("a");
    // But iteration must be manually synchronized:
    synchronized (syncList) {
        for (String s : syncList) { ... } // must hold the lock
    }

  PREFER: CopyOnWriteArrayList (read-heavy), ConcurrentHashMap (high concurrency)
  over synchronizedX wrappers — better concurrent performance.

SINGLETON AND EMPTY COLLECTIONS
---------------------------------
  Collections.singleton(T o)        // immutable Set with one element
  Collections.singletonList(T o)    // immutable List with one element
  Collections.singletonMap(K k, V v) // immutable Map with one entry
  Collections.emptyList()           // immutable empty List (same instance reused)
  Collections.emptySet()            // immutable empty Set
  Collections.emptyMap()            // immutable empty Map

  // Useful for returning empty results:
  return Collections.emptyList();   // better than return new ArrayList<>();

ADDALL
-------
  Collections.addAll(Collection<T> c, T... elements)  // add multiple elements at once

  Example:
    List<String> list = new ArrayList<>();
    Collections.addAll(list, "a", "b", "c", "d"); // adds all varargs

COMMON INTERVIEW QUESTIONS
---------------------------
Q: What's the difference between Collections.unmodifiableList() and List.of()?
A: unmodifiableList(): returns a view of the original list. The original list can still be
   modified, and changes are reflected in the unmodifiable view. The view itself blocks mutations.
   List.of() (Java 9+): returns a completely independent immutable list. No backing list.
   Cannot be modified at all. Does not allow null elements.
   Prefer List.of() for true immutability.

Q: When should you use Collections.synchronizedList() vs CopyOnWriteArrayList?
A: synchronizedList(): wraps any list with synchronized methods. Good for mixed read/write.
   Requires manual synchronization for iteration. Blocks on every operation.
   CopyOnWriteArrayList: creates a new copy of the array on every write. Iteration is never
   blocked and sees a consistent snapshot. Good for read-heavy workloads with rare writes.
   Use CopyOnWriteArrayList when reads >> writes (e.g., listener lists).

Q: What does Collections.sort() guarantee that Arrays.sort() for objects doesn't in Java 6?
A: Both now use TimSort (since Java 7), which is stable (equal elements maintain relative order).
   Arrays.sort() for PRIMITIVE arrays uses dual-pivot quicksort (NOT stable).
   Collections.sort() has always been guaranteed stable.

Q: How is binarySearch() return value interpreted when element is not found?
A: Returns -(insertionPoint) - 1.
   If the element would be inserted at index 2, binarySearch returns -(2)-1 = -3.
   Convert back to insertion point: -(result) - 1 or ~result (bitwise NOT).
