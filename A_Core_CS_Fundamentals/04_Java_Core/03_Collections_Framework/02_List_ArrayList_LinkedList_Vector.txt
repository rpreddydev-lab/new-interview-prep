LIST: ARRAYLIST vs LINKEDLIST vs VECTOR
=========================================

THE LIST INTERFACE
-------------------
  java.util.List<E> extends Collection<E>
  - Ordered (maintains insertion order)
  - Allows duplicate elements
  - Allows null elements
  - Provides indexed access: get(int index), set(int index, E e)
  - Common implementations: ArrayList, LinkedList, Vector, CopyOnWriteArrayList

ARRAYLIST
----------
Internal Structure: Dynamic array (Object[])
  - Backed by a resizable array internally
  - Default initial capacity: 10
  - Grows by ~50% when full: newCapacity = oldCapacity + (oldCapacity >> 1)
  - shrink: trimToSize() releases unused memory

Key Operations:
  add(e)         → O(1) amortized (O(n) on resize, rare)
  add(i, e)      → O(n) — shifts elements right
  get(i)         → O(1) — direct array index
  remove(i)      → O(n) — shifts elements left
  contains(e)    → O(n) — linear scan
  size()         → O(1)

Example:
  List<String> list = new ArrayList<>();
  list.add("Alpha");
  list.add("Beta");
  list.add(1, "Gamma");       // ["Alpha", "Gamma", "Beta"]
  String s = list.get(0);     // "Alpha"
  list.remove("Beta");        // ["Alpha", "Gamma"]

  // Pre-sized ArrayList to avoid resize:
  List<String> sized = new ArrayList<>(100);

Iteration (preferred for ArrayList):
  for (String item : list) { ... }   // uses iterator
  list.forEach(System.out::println); // Java 8+

LINKEDLIST
-----------
Internal Structure: Doubly-linked list of Node objects
  - Each node: Object item, Node prev, Node next
  - Maintains first and last pointers
  - Implements both List AND Deque — can be used as a stack or queue

Key Operations:
  add(e) / addLast(e) → O(1)
  addFirst(e)          → O(1)
  get(i)               → O(n) — traverses from nearest end
  remove(i)            → O(n) find + O(1) unlink
  removeFirst()        → O(1)
  removeLast()         → O(1)
  contains(e)          → O(n)

Example:
  LinkedList<String> deque = new LinkedList<>();
  deque.addFirst("A");
  deque.addLast("B");
  deque.addFirst("Z");      // ["Z", "A", "B"]
  String head = deque.peekFirst();  // "Z"
  deque.pollFirst();        // removes "Z" → ["A", "B"]

Memory: Each node uses ~48 bytes (object header + 3 references).
        ArrayList uses ~16 bytes per element (just a reference in an array).
        → LinkedList has significant memory overhead

VECTOR (LEGACY — AVOID)
------------------------
  - Synchronized version of ArrayList (all methods are synchronized)
  - Thread-safe but very slow due to coarse-grained locking
  - Default capacity doubles on resize (vs 1.5x in ArrayList)
  - Part of Java 1.0 (before Collections Framework)
  - Replaced by: Collections.synchronizedList(new ArrayList<>())
                 or CopyOnWriteArrayList for concurrent read-heavy use

STACK (LEGACY — AVOID)
-----------------------
  - Extends Vector — inherits all the synchronized overhead
  - Has push/pop/peek/empty/search methods
  - Bad design: can use get(index) — violates stack semantics
  - Replace with: Deque<T> stack = new ArrayDeque<>();
                  stack.push("item");    // same as addFirst
                  stack.pop();           // same as removeFirst

COMPARISON TABLE
-----------------
  Feature              | ArrayList       | LinkedList         | Vector
  ---------------------|-----------------|--------------------|-----------------
  Internal structure   | Dynamic array   | Doubly-linked list | Dynamic array
  Random access O(1)?  | ✅ Yes          | ❌ No (O(n))       | ✅ Yes
  Insert at head/tail  | O(n) / O(1) am  | O(1)               | O(n) / O(1) am
  Insert at middle     | O(n)            | O(n) find + O(1)   | O(n)
  Memory overhead      | Low             | High (prev+next)   | Low
  Thread-safe          | ❌ No           | ❌ No              | ✅ Yes (slow)
  Implements Deque?    | ❌ No           | ✅ Yes             | ❌ No
  Preferred?           | ✅ General use  | Queue/Deque use    | ❌ Legacy

WHEN TO USE WHAT
-----------------
  ArrayList:    default choice for List. Fast iteration, fast random access, low memory.
  LinkedList:   when you need Deque behavior (addFirst/removeFirst) OR frequent insert/delete
                at both ends. Not recommended for random access patterns.
  Vector/Stack: never in modern code. Replace with ArrayList + ArrayDeque.

SUBLIST AND LIST OPERATIONS
-----------------------------
  List<Integer> nums = new ArrayList<>(Arrays.asList(1,2,3,4,5));

  // subList returns a view — backed by original list
  List<Integer> sub = nums.subList(1, 3);  // [2, 3]
  sub.clear();                             // modifies nums → [1, 4, 5]

  // Sorting
  Collections.sort(nums);
  nums.sort(Comparator.reverseOrder());

  // Searching (list must be sorted)
  int idx = Collections.binarySearch(nums, 4);  // returns index

  // Converting array to List
  String[] arr = {"a", "b", "c"};
  List<String> fromArr = Arrays.asList(arr);     // fixed-size, backed by array
  List<String> mutable = new ArrayList<>(Arrays.asList(arr)); // truly mutable

  // Java 9+
  List<String> immutable = List.of("a", "b", "c"); // unmodifiable, no nulls

COMMON INTERVIEW QUESTIONS
---------------------------
Q: When would you use LinkedList over ArrayList?
A: Rarely in practice. LinkedList is useful when:
   1. You need Deque operations (frequent addFirst/removeFirst) — though ArrayDeque is faster.
   2. You're implementing a queue and need O(1) enqueue/dequeue at both ends.
   In most cases, ArrayList is preferred due to better cache locality and lower memory overhead.
   Random access on LinkedList is O(n), making it terrible for indexed access.

Q: How does ArrayList grow internally?
A: When the internal array is full, ArrayList creates a new array with capacity
   oldCapacity + (oldCapacity >> 1) ≈ 1.5× the original. Then it copies all elements
   to the new array using System.arraycopy(). This is O(n) but happens rarely (amortized O(1)).

Q: Why is Vector considered legacy?
A: Vector was Java 1.0. Its synchronization is coarse-grained — every method is synchronized,
   causing massive contention in concurrent environments. Modern alternatives:
   - Single-threaded: ArrayList
   - Multi-threaded reads: CopyOnWriteArrayList
   - Multi-threaded writes: Collections.synchronizedList() or explicit locking

Q: What's the difference between Arrays.asList() and List.of()?
A: Arrays.asList(): Returns a fixed-size list backed by the array. You can set() elements
   but not add() or remove(). Allows null. Backed by original array — mutations reflect both ways.
   List.of() (Java 9+): Returns a truly immutable list. Cannot add/remove/set.
   Does NOT allow null. Not backed by any mutable structure.
