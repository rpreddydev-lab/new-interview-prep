OOP OVERVIEW — THE FOUR PILLARS
================================

WHAT IS OOP?
------------
Object-Oriented Programming (OOP) is a programming paradigm that organizes software design around
data (objects) rather than functions and logic. An object is a self-contained unit bundling:
  - State      → fields / attributes
  - Behavior   → methods / operations
  - Identity   → unique memory reference

THE FOUR PILLARS
----------------

1. ENCAPSULATION
   - Bundling data (fields) and behavior (methods) together inside a class.
   - Hiding internal implementation details; exposing only what's necessary.
   - Achieved via access modifiers: private, protected, public, package-private.
   - Benefits: reduced complexity, controlled access, easy to change internals without
     breaking external code.
   Example:
     public class BankAccount {
         private double balance;  // hidden — can't be accessed directly
         public void deposit(double amount) { balance += amount; }
         public double getBalance() { return balance; }
     }

2. ABSTRACTION
   - Hiding complex implementation behind a simple interface.
   - Show WHAT an object does, not HOW it does it.
   - Achieved via: abstract classes, interfaces.
   - Benefits: reduces coupling, enables polymorphism, simplifies the user's mental model.
   Example:
     interface Shape {
         double area();      // what it does — abstract
         double perimeter(); // how it's done — left to implementing classes
     }

3. INHERITANCE
   - A class (subclass) acquires the fields and methods of another class (superclass).
   - Promotes code reuse; models IS-A relationships.
   - Java supports single-class inheritance (extends) and multiple interface inheritance.
   - Use sparingly — prefer composition over inheritance when possible.
   Example:
     class Animal { void eat() { System.out.println("eating"); } }
     class Dog extends Animal { void bark() { System.out.println("woof"); } }

4. POLYMORPHISM
   - The ability of a reference to behave differently depending on the actual object type.
   - Two forms:
       Compile-time (static)  — Method Overloading (same name, different parameters)
       Runtime (dynamic)      — Method Overriding (subclass redefines superclass method)
   - Enables writing generic code that works with any subtype.
   Example:
     Animal a = new Dog();  // Animal reference → Dog object
     a.makeSound();         // calls Dog's makeSound() — runtime polymorphism

WHY OOP? (KEY BENEFITS)
------------------------
  1. Modularity     — Objects are self-contained; easier to develop and maintain.
  2. Reusability    — Inheritance and composition allow code reuse.
  3. Scalability    — New features via new classes without touching existing code (Open/Closed).
  4. Maintainability— Encapsulation localizes changes; less ripple effect.
  5. Abstraction    — Users work with high-level APIs, not raw implementations.

OOP IN JAVA — CORE FACTS
-------------------------
  - Everything is a class (except primitives).
  - All classes implicitly extend java.lang.Object.
  - Java uses single inheritance for classes, multiple inheritance for interfaces.
  - Java is "nearly" pure OOP (primitives are the exception).

COMMON INTERVIEW QUESTIONS
---------------------------
Q: What are the four pillars of OOP?
A: Encapsulation (bundling + hiding), Abstraction (hiding complexity), Inheritance (IS-A reuse),
   Polymorphism (one interface, many behaviors).

Q: What is the difference between abstraction and encapsulation?
A: Abstraction hides COMPLEXITY — you know what an object does but not how (think: interface, abstract class).
   Encapsulation hides DATA — internal state is private, accessed only via public methods (think: private fields + getters/setters).
   Abstraction is a design concept; encapsulation is an implementation technique.

Q: Why is Java not 100% object-oriented?
A: Java has 8 primitive types (int, long, double, float, boolean, char, byte, short) which are
   not objects — they're stored directly on the stack, not on the heap. They have no methods.
   Java provides wrapper classes (Integer, Long, etc.) to use primitives in object contexts.

Q: What is the difference between IS-A and HAS-A relationships?
A: IS-A → Inheritance: Dog IS-A Animal. Implemented via extends/implements.
   HAS-A → Composition: Car HAS-A Engine. Implemented by holding a field reference.
   Prefer HAS-A (composition) over IS-A (inheritance) in most cases — it's more flexible
   and avoids the fragile base class problem.
