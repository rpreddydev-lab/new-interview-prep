CLASSES, OBJECTS, AND CONSTRUCTORS
====================================

CLASS
-----
A class is a blueprint/template for creating objects. It defines:
  - Fields (state/data)
  - Methods (behavior)
  - Constructors (initialization)
  - Nested types, static members

  public class Person {
      // Fields
      private String name;
      private int age;

      // Constructor
      public Person(String name, int age) {
          this.name = name;
          this.age = age;
      }

      // Method
      public String getName() { return name; }
      public int getAge() { return age; }

      @Override
      public String toString() {
          return "Person{name=" + name + ", age=" + age + "}";
      }
  }

OBJECT
------
An object is an instance of a class created with the `new` keyword.
  Person p = new Person("Alice", 30);

What happens at `new Person("Alice", 30)`:
  1. Memory allocated on the heap for the Person object.
  2. Fields initialized to defaults (null, 0, false).
  3. Constructor called to set field values.
  4. Reference to the object returned and stored in variable `p`.

Variable `p` stores a REFERENCE (memory address), not the object itself.
Primitives store the actual value; objects store a reference.

CONSTRUCTORS
------------
A constructor is a special method used to initialize an object.
Rules:
  - Same name as the class.
  - No return type (not even void).
  - Called once per object at creation time.
  - Can be overloaded (multiple constructors with different params).

Types of Constructors:
1. Default Constructor (no-args):
   - Automatically provided by compiler if NO constructor is defined.
   - Initializes fields to defaults: null, 0, false.
     public Person() {}

2. Parameterized Constructor:
     public Person(String name, int age) {
         this.name = name;
         this.age = age;
     }

3. Copy Constructor (Java doesn't provide automatically, unlike C++):
     public Person(Person other) {
         this.name = other.name;
         this.age = other.age;
     }

CONSTRUCTOR CHAINING
--------------------
  this(...)  — calls another constructor in the SAME class (must be first statement)
  super(...) — calls constructor in the PARENT class (must be first statement)

  public class Employee extends Person {
      private String role;

      public Employee(String name, int age, String role) {
          super(name, age);     // calls Person(String, int)
          this.role = role;
      }
      public Employee(String name, String role) {
          this(name, 0, role);  // calls Employee(String, int, String)
      }
  }

THE `this` KEYWORD
------------------
  - Refers to the current object instance.
  - Disambiguates between field and parameter with same name:
      this.name = name;
  - Calls another constructor in the same class: this(...)
  - Passes current object as argument: doSomething(this)
  - Returns current object (builder pattern): return this;

STATIC vs INSTANCE MEMBERS
----------------------------
  Instance members: belong to each individual object.
  Static members:   belong to the CLASS itself, shared across all instances.

  public class Counter {
      private static int count = 0;  // class-level, shared
      private int id;                // instance-level, per object

      public Counter() {
          count++;
          this.id = count;
      }

      public static int getCount() { return count; }  // static method
      public int getId() { return id; }               // instance method
  }

  Counter c1 = new Counter(); // count = 1, id = 1
  Counter c2 = new Counter(); // count = 2, id = 2
  Counter.getCount();         // returns 2

OBJECT LIFECYCLE
-----------------
  1. Created with new → JVM allocates heap memory, calls constructor.
  2. Used — methods called, fields read/written via reference.
  3. Eligible for GC — when no more live references point to it.
  4. GC collects — JVM reclaims the heap memory.
  Note: finalize() is deprecated (Java 9+), removed (Java 18+). Don't rely on it.

COMMON INTERVIEW QUESTIONS
---------------------------
Q: What is the difference between a class and an object?
A: A class is a blueprint/template. An object is an instance of that class — a concrete
   entity in memory created with new. A class exists once in the method area (metaspace);
   objects are created on the heap and can exist in many copies.

Q: What happens if you don't define a constructor?
A: The compiler automatically inserts a public no-arg default constructor. But if you define
   ANY constructor (even a parameterized one), the compiler does NOT add a default constructor.
   So if you need both, you must explicitly define both.

Q: What is constructor chaining and why is it useful?
A: Calling one constructor from another using this() or super() — this() for same-class,
   super() for parent class. It avoids code duplication in initialization logic. Must be the
   first statement in the constructor.

Q: Can a constructor be private?
A: Yes — used in the Singleton pattern to prevent external instantiation:
     private Singleton() {}
     public static Singleton getInstance() { ... }
   Also used in utility classes (e.g., java.lang.Math has a private constructor).

Q: What is the difference between `this` and `super`?
A: `this` refers to the current object instance; used to access current class members or
   call another constructor in the same class.
   `super` refers to the parent class; used to call parent class constructor or access
   parent class methods/fields that have been overridden.

Q: What is object reference vs primitive value in Java?
A: Primitives (int, double, etc.) store the actual value directly in the variable (on the stack).
   Object variables store a REFERENCE (pointer to heap memory), not the object itself.
   This is why: String s1 = "hi"; String s2 = s1; — both point to the same object.
   Modifying through one reference affects what the other sees (for mutable objects).
