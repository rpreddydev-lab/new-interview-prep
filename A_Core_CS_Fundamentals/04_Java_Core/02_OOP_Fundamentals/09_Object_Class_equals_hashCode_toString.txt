THE Object CLASS — equals, hashCode, toString
==============================================

java.lang.Object IS THE ROOT OF ALL CLASSES
--------------------------------------------
Every Java class implicitly extends Object. All objects can be treated as Object references.
Object provides the foundational methods every object inherits.

KEY METHODS OF Object
----------------------
  1. equals(Object o)
  2. hashCode()
  3. toString()
  4. clone()
  5. getClass()
  6. finalize() — deprecated
  7. wait(), notify(), notifyAll() — thread coordination

1. equals(Object o)
--------------------
  Default behavior (Object's): compares REFERENCES (identity) — same as ==.
  Override when you need VALUE equality (same logical content = equal).

  Default: obj1.equals(obj2) is true ONLY if obj1 == obj2 (same object in memory).

  Override:
    @Override
    public boolean equals(Object o) {
        if (this == o) return true;           // reference equality shortcut
        if (!(o instanceof Person)) return false;  // type check
        Person p = (Person) o;
        return age == p.age && Objects.equals(name, p.name);
    }

  equals CONTRACT (must satisfy all five):
    1. Reflexive:   x.equals(x) == true
    2. Symmetric:   x.equals(y) == y.equals(x)
    3. Transitive:  x.equals(y) && y.equals(z) → x.equals(z)
    4. Consistent:  same result on repeated calls (if no state change)
    5. Null-safe:   x.equals(null) == false (never throw NPE)

2. hashCode()
--------------
  Returns an integer hash value for the object.
  Default: based on object's memory address (identity hash code).
  Override whenever you override equals.

  hashCode CONTRACT:
    1. If equals() returns true, hashCode() MUST return the same value.
    2. If equals() returns false, hashCode() SHOULD (but doesn't have to) differ.
       (different hash = must be different objects; same hash ≠ equal objects)

  Override:
    @Override
    public int hashCode() {
        return Objects.hash(name, age);  // utility — computes hash from fields
    }

  WHY: HashMap, HashSet use hashCode to find the bucket, then equals to confirm.
  If you override equals but NOT hashCode → objects that are "equal" end up in
  different buckets → HashMap/HashSet can't find them → broken behavior.

3. toString()
--------------
  Default: ClassName@hexHashCode (e.g., "Person@1a2b3c")
  Override to return a human-readable representation.

  @Override
  public String toString() {
      return "Person{name=" + name + ", age=" + age + "}";
  }

  Automatically called when:
    - Printing: System.out.println(person) → person.toString()
    - String concatenation: "User: " + person → "User: " + person.toString()
    - Logging: logger.info("User: {}", person)

4. clone()
-----------
  Creates a shallow copy of the object.
  Class must implement Cloneable (marker interface) or CloneNotSupportedException is thrown.
  Shallow copy: primitive fields copied by value; object references copied (same object shared).
  Deep copy: must be implemented manually by also cloning referenced objects.

  Better alternative: copy constructor or serialization-based clone.

5. getClass()
--------------
  Returns the runtime Class object.
  Cannot be overridden (final method).
  Usage:
    person.getClass().getName()        // "com.example.Person"
    person.getClass().getSimpleName()  // "Person"

  Used in equals() pattern (instanceof preferred over getClass() check in equals).

OBJECTS UTILITY CLASS (java.util.Objects — Java 7+)
------------------------------------------------------
  Objects.equals(a, b)     — null-safe equals: handles null without NPE
  Objects.hash(f1, f2, f3) — compute hashCode from multiple fields
  Objects.toString(o, def) — null-safe toString with default
  Objects.requireNonNull(o, "msg") — throw NPE with message if null
  Objects.isNull(o)        — null check
  Objects.nonNull(o)       — non-null check

  // null-safe equals
  Objects.equals(null, "hi")  // false — no NPE
  Objects.equals(null, null)  // true

COMPLETE equals + hashCode EXAMPLE
-------------------------------------
  public class Person {
      private String name;
      private int age;

      public Person(String name, int age) {
          this.name = name;
          this.age = age;
      }

      @Override
      public boolean equals(Object o) {
          if (this == o) return true;
          if (!(o instanceof Person)) return false;
          Person p = (Person) o;
          return age == p.age && Objects.equals(name, p.name);
      }

      @Override
      public int hashCode() {
          return Objects.hash(name, age);
      }

      @Override
      public String toString() {
          return "Person{name='" + name + "', age=" + age + "}";
      }
  }

COMMON INTERVIEW QUESTIONS
---------------------------
Q: What is the default behavior of equals() and when should you override it?
A: Default equals() (from Object) checks reference equality (same object in memory == same as ==).
   Override when you need value/logical equality — two separate objects should be "equal" if they
   have the same data. Always override hashCode() together with equals().

Q: Why must you override hashCode() when you override equals()?
A: The equals-hashCode contract requires: if a.equals(b) then a.hashCode() == b.hashCode().
   HashMap/HashSet use hashCode to find the bucket, then equals to confirm. If two "equal"
   objects have different hashCodes, HashMap can't find the second one — it will be in the
   wrong bucket, causing silent bugs (duplicates in Set, failed Map lookups).

Q: What is the equals-hashCode contract?
A: 1. Equal objects MUST have the same hashCode.
   2. Objects with the same hashCode are NOT necessarily equal (hash collision is allowed).
   3. hashCode must be consistent: same result on repeated calls if object state hasn't changed.

Q: What does Objects.hash() do?
A: It computes a combined hash code from multiple values — essentially Arrays.hashCode(new Object[]{f1, f2, f3}).
   It handles nulls safely. Convenient shorthand for complex hashCode implementations.
