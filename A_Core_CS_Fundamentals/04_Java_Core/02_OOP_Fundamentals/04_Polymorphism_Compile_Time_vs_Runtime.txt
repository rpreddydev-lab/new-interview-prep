POLYMORPHISM — COMPILE-TIME vs RUNTIME
=======================================

WHAT IS POLYMORPHISM?
---------------------
Polymorphism = "many forms." One reference/method name can behave differently depending on
the object type or the arguments passed.

Two types in Java:
  1. Compile-time polymorphism  →  Method Overloading
  2. Runtime polymorphism       →  Method Overriding + Dynamic Dispatch

1. COMPILE-TIME POLYMORPHISM — METHOD OVERLOADING
--------------------------------------------------
Same method name with DIFFERENT parameter lists within the same class (or inherited).
The compiler resolves which method to call at compile time based on:
  - Number of arguments
  - Types of arguments
  - Order of argument types

  class Calculator {
      int add(int a, int b) { return a + b; }
      double add(double a, double b) { return a + b; }
      int add(int a, int b, int c) { return a + b + c; }
      String add(String a, String b) { return a + b; }
  }

Rules:
  - Return type alone does NOT distinguish overloaded methods (compile error).
  - @Override is NOT used for overloading.
  - Can overload constructors too.

Promotion in overloading (widening):
  If exact match not found, Java widens: byte → short → int → long → float → double
  calc.add(5, 3.0) → matched to add(double, double) after widening int to double.

Autoboxing and overloading edge case:
  void test(Integer i) { ... }
  void test(int i) { ... }
  test(5) → calls test(int i) first (exact match before autoboxing).

2. RUNTIME POLYMORPHISM — METHOD OVERRIDING + DYNAMIC DISPATCH
---------------------------------------------------------------
Subclass provides its own implementation of a superclass method.
JVM decides WHICH version to call at RUNTIME based on the actual object type.

  class Animal {
      public void sound() { System.out.println("..."); }
  }
  class Dog extends Animal {
      @Override
      public void sound() { System.out.println("Woof"); }
  }
  class Cat extends Animal {
      @Override
      public void sound() { System.out.println("Meow"); }
  }

  Animal[] animals = { new Dog(), new Cat(), new Dog() };
  for (Animal a : animals) {
      a.sound();  // "Woof", "Meow", "Woof" — decided at runtime per object
  }

  The reference type is Animal, but the actual object type determines which sound() is called.
  This is DYNAMIC DISPATCH (late binding).

UPCASTING vs DOWNCASTING
------------------------
  Upcasting (implicit, safe):
    Animal a = new Dog();  // Dog reference stored in Animal variable — always safe

  Downcasting (explicit, risky):
    Dog d = (Dog) a;  // valid ONLY if a actually refers to a Dog object
                      // throws ClassCastException if it doesn't

  Safe downcasting with instanceof:
    if (a instanceof Dog) {
        Dog d = (Dog) a;
        d.bark();
    }

  Pattern matching (Java 16+):
    if (a instanceof Dog d) {  // d is declared and cast in one step
        d.bark();
    }

POLYMORPHISM WITH INTERFACES
-----------------------------
  interface Drawable {
      void draw();
  }
  class Circle implements Drawable {
      @Override public void draw() { System.out.println("Drawing circle"); }
  }
  class Square implements Drawable {
      @Override public void draw() { System.out.println("Drawing square"); }
  }

  List<Drawable> shapes = List.of(new Circle(), new Square());
  shapes.forEach(Drawable::draw);  // polymorphic calls via interface reference

STATIC METHODS AND POLYMORPHISM
---------------------------------
  Static methods are NOT polymorphic. They are resolved at compile time.
  This is called METHOD HIDING, not overriding.

  class Animal {
      static void info() { System.out.println("Animal"); }
  }
  class Dog extends Animal {
      static void info() { System.out.println("Dog"); }
  }

  Animal a = new Dog();
  a.info();           // prints "Animal" — compile-time resolution (reference type)
  Dog.info();         // prints "Dog"

FIELDS AND POLYMORPHISM
------------------------
  Fields are also NOT polymorphic — they are resolved at compile time by reference type.

  class Parent { int x = 10; }
  class Child extends Parent { int x = 20; }

  Parent p = new Child();
  System.out.println(p.x);  // prints 10 — field resolved by reference type, not runtime type

COMMON INTERVIEW QUESTIONS
---------------------------
Q: What is the difference between compile-time and runtime polymorphism?
A: Compile-time (static) polymorphism = overloading — method resolved at compile time by
   signature. Runtime (dynamic) polymorphism = overriding — method resolved at runtime by
   actual object type via dynamic dispatch.

Q: Can you override a static method? Why not?
A: No. Static methods belong to the class, not instances. They are resolved at compile time
   using the reference type (no dynamic dispatch). You can define a static method with the
   same name in a subclass (method hiding), but it's not polymorphic.

Q: What is dynamic dispatch?
A: The JVM mechanism that determines which overridden method implementation to execute at
   runtime based on the actual (runtime) type of the object, not the declared (reference) type.
   Implemented via virtual method tables (vtable) in the JVM.

Q: What will this print?
     Animal a = new Dog();
     a.sound();
A: Dog's sound() — dynamic dispatch uses the actual object type (Dog) at runtime, not the
   reference type (Animal).

Q: What is the difference between method hiding and method overriding?
A: Overriding: instance methods — resolved at runtime by actual object type (polymorphic).
   Hiding: static methods — resolved at compile time by reference type (not polymorphic).
