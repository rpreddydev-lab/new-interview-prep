WRAPPER CLASSES AND AUTOBOXING
================================

PRIMITIVE TYPES AND THEIR WRAPPERS
------------------------------------
Java has 8 primitive types. Each has a corresponding wrapper class in java.lang:

  Primitive   | Wrapper Class | Size
  ------------|---------------|------
  byte        | Byte          | 8-bit
  short       | Short         | 16-bit
  int         | Integer       | 32-bit
  long        | Long          | 64-bit
  float       | Float         | 32-bit
  double      | Double        | 64-bit
  char        | Character     | 16-bit
  boolean     | Boolean       | 1-bit

WHY WRAPPER CLASSES?
---------------------
  1. Collections require objects: List<int> is invalid; List<Integer> is valid.
  2. Generics only work with reference types.
  3. Null representation: int can't be null; Integer can be null.
  4. Utility methods: Integer.parseInt(), Integer.toBinaryString(), Double.isNaN(), etc.
  5. Constants: Integer.MAX_VALUE, Integer.MIN_VALUE.

AUTOBOXING AND UNBOXING (Java 5+)
-----------------------------------
Autoboxing:   automatic conversion from primitive → wrapper object
Unboxing:     automatic conversion from wrapper object → primitive

  // Autoboxing
  Integer i = 42;          // same as: Integer i = Integer.valueOf(42);
  List<Integer> list = new ArrayList<>();
  list.add(100);           // int 100 → Integer.valueOf(100) automatically

  // Unboxing
  int x = i;               // same as: int x = i.intValue();
  int sum = list.get(0) + 5;  // Integer unboxed to int automatically

AUTOBOXING INTERNALS: Integer.valueOf() CACHING
-------------------------------------------------
Integer.valueOf(n) CACHES values from -128 to 127 (configurable via JVM flag).
Values in this range always return the SAME cached object — == comparisons can mislead:

  Integer a = 100;
  Integer b = 100;
  a == b           // TRUE — both refer to cached Integer object

  Integer x = 200;
  Integer y = 200;
  x == y           // FALSE — outside cache range, two new objects on heap
  x.equals(y)      // TRUE — compare values

  THE TRAP: ALWAYS use .equals() to compare Integer/Long/Short/Byte/Character objects.

  Other wrappers:
    Boolean: caches TRUE and FALSE (only 2 values).
    Long, Short, Byte: same -128 to 127 cache as Integer.
    Double, Float: NO caching — new objects always.

UNBOXING AND NullPointerException
------------------------------------
Unboxing a null wrapper causes NullPointerException:
  Integer i = null;
  int x = i;   // NullPointerException! — tries to call null.intValue()

  Always null-check before unboxing:
    if (i != null) { int x = i; }

  Common in method parameters and return types:
    Integer getScore() { return null; }  // returns null
    int score = getScore();  // NPE on unboxing!

PERFORMANCE CONSIDERATIONS
---------------------------
  Autoboxing/unboxing in tight loops creates many short-lived heap objects → GC pressure:

  // BAD: 10M Integer objects created
  Long sum = 0L;
  for (long i = 0; i < 10_000_000; i++) {
      sum += i;  // sum is Long → unboxed to long → add → autoboxed back to Long
  }

  // GOOD: no boxing/unboxing
  long sum = 0L;
  for (long i = 0; i < 10_000_000; i++) {
      sum += i;
  }

KEY WRAPPER METHODS
--------------------
  Integer:
    Integer.parseInt("42")         → int 42
    Integer.valueOf("42")          → Integer 42 (cached if in range)
    Integer.toBinaryString(10)     → "1010"
    Integer.toHexString(255)       → "ff"
    Integer.toOctalString(8)       → "10"
    Integer.bitCount(7)            → 3 (bits set in 0111)
    Integer.reverse(1)             → reverses bits
    Integer.MAX_VALUE              → 2147483647
    Integer.MIN_VALUE              → -2147483648
    Integer.compare(a, b)          → negative/0/positive
    Integer.sum(a, b)              → a + b (useful as method reference)

  Double:
    Double.parseDouble("3.14")     → 3.14
    Double.isNaN(Double.NaN)       → true
    Double.isInfinite(1.0/0.0)     → true

  Character:
    Character.isDigit('5')         → true
    Character.isLetter('a')        → true
    Character.isLetterOrDigit('3') → true
    Character.isWhitespace(' ')    → true
    Character.toUpperCase('a')     → 'A'
    Character.toLowerCase('A')     → 'a'

COMMON INTERVIEW QUESTIONS
---------------------------
Q: What is autoboxing and what are its pitfalls?
A: Autoboxing = automatic conversion of primitive to wrapper (int → Integer).
   Unboxing = automatic conversion of wrapper to primitive (Integer → int).
   Pitfalls:
   1. NullPointerException on unboxing null.
   2. == comparison doesn't work reliably for Integer outside -128..127.
   3. Performance: autoboxing in loops creates many heap objects.
   Always use .equals() for wrapper comparisons; use primitives in performance-critical loops.

Q: Why does Integer a = 127; Integer b = 127; a == b return true, but Integer a = 128; Integer b = 128; a == b return false?
A: Integer.valueOf() caches Integer objects for values -128 to 127. When you autobox 127,
   both a and b receive the SAME cached object → == is true. For 128, new Integer objects
   are created each time → different references → == is false. Always use .equals().

Q: Can int be null? Can Integer be null?
A: int (primitive): NO — primitives always have a value (default 0).
   Integer (wrapper/object): YES — object references can be null.
   This matters in: Map<String, Integer>.get() can return null (key absent);
   int result = map.get(key) → NPE if key not in map.

Q: When would you use Integer over int?
A: When you need null representation, generics, Collections (List<Integer>),
   utility methods (Integer.parseInt), or Optional<Integer>.
   Use int for performance-critical arithmetic, local variables, array indices.
