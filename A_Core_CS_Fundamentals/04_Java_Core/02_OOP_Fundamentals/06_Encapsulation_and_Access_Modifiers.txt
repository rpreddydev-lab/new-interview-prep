ENCAPSULATION AND ACCESS MODIFIERS
====================================

WHAT IS ENCAPSULATION?
----------------------
Encapsulation = bundling state (fields) and behavior (methods) inside a class AND restricting
direct access to internal state from outside. External code interacts only through a controlled
public API.

  "Hide what changes, expose what's stable."

BENEFITS:
  - Prevents invalid state (validate in setters)
  - Internal implementation can change without affecting users
  - Easier testing and maintenance
  - Thread safety easier to achieve (control access points)

CLASSIC ENCAPSULATION PATTERN
------------------------------
  public class BankAccount {
      private String owner;
      private double balance;  // hidden — not directly accessible

      public BankAccount(String owner, double initialBalance) {
          this.owner = owner;
          if (initialBalance < 0) throw new IllegalArgumentException("Negative balance");
          this.balance = initialBalance;
      }

      // Getter — read-only access
      public double getBalance() { return balance; }
      public String getOwner() { return owner; }

      // Controlled mutation — validates before changing state
      public void deposit(double amount) {
          if (amount <= 0) throw new IllegalArgumentException("Amount must be positive");
          balance += amount;
      }

      public void withdraw(double amount) {
          if (amount > balance) throw new IllegalStateException("Insufficient funds");
          balance -= amount;
      }
  }

ACCESS MODIFIERS
----------------
Java has four levels of access control:

  ┌────────────────────┬───────────┬─────────┬─────────────┬────────────────────┐
  │ Modifier           │ Same class│ Same pkg│ Subclass    │ Everywhere (world) │
  ├────────────────────┼───────────┼─────────┼─────────────┼────────────────────┤
  │ private            │    ✅     │   ❌    │     ❌      │         ❌         │
  │ (package-private)  │    ✅     │   ✅    │     ❌      │         ❌         │
  │ protected          │    ✅     │   ✅    │     ✅      │         ❌         │
  │ public             │    ✅     │   ✅    │     ✅      │         ✅         │
  └────────────────────┴───────────┴─────────┴─────────────┴────────────────────┘

  private         — most restrictive; only within the same class
  (default/pkg)   — no keyword written; accessible within the same package
  protected       — package + subclasses (even in different packages)
  public          — fully accessible from anywhere

NOTE: For top-level classes, only public and package-private are valid.
      private and protected apply to fields, methods, and nested classes.

ENCAPSULATION BEST PRACTICES
------------------------------
  1. Make fields private by default.
  2. Provide getters/setters only when truly needed.
  3. Prefer immutable objects (no setters, all-args constructor, final fields).
  4. Validate in setters/constructors to maintain invariants.
  5. Avoid exposing mutable internal objects directly:
       // BAD:
       public List<String> getItems() { return items; }   // caller can mutate list
       // GOOD:
       public List<String> getItems() { return Collections.unmodifiableList(items); }

IMMUTABLE CLASSES (Encapsulation at its strongest)
---------------------------------------------------
  Immutable objects cannot change state after construction.
  Rules for immutable classes:
    1. Declare class as final (prevents subclassing to add mutability).
    2. All fields private and final.
    3. No setters.
    4. Initialize all fields in constructor.
    5. For mutable field types (List, Date), return defensive copies.

  public final class ImmutablePoint {
      private final int x;
      private final int y;

      public ImmutablePoint(int x, int y) {
          this.x = x;
          this.y = y;
      }

      public int getX() { return x; }
      public int getY() { return y; }
  }

  Benefits: Thread-safe by design, easy to reason about, hashCode/equals are stable.
  Examples: String, Integer, LocalDate, UUID

JAVA BEAN CONVENTION
---------------------
  A JavaBean is a class that:
    - Has a public no-arg constructor
    - Has private fields
    - Has public getters/setters following naming convention:
        getXxx() / setXxx() for non-boolean fields
        isXxx() / setXxx() for boolean fields
    - Implements Serializable (optional, but traditional)

COMMON INTERVIEW QUESTIONS
---------------------------
Q: What is encapsulation and why is it important?
A: Encapsulation bundles data and methods in a class and hides the data behind an access-
   controlled API. It protects invariants (e.g., balance can't go negative), allows
   internal changes without breaking callers, and improves testability.

Q: What is the difference between private and protected?
A: private — accessible only within the declaring class.
   protected — accessible in the same package AND in subclasses (even different packages).
   protected is often used for "hook" methods in abstract classes that subclasses should
   override but outside callers shouldn't see.

Q: What is package-private and when is it useful?
A: No access modifier keyword = package-private. Accessible only within the same package.
   Useful for internal helper classes/methods that should be shared within a module but
   hidden from external users. Often used in library code.

Q: Why make fields private and provide getters instead of just making them public?
A: Private fields let you:
   1. Change the field type/name/structure without breaking callers.
   2. Add validation logic (in setter).
   3. Make the class immutable (no setter).
   4. Compute the value lazily or derive it.
   5. Control thread-safety at the access point.
   Public fields expose implementation details and can't be changed without breaking callers.

Q: How do you make a class immutable?
A: 1. Declare class final. 2. All fields private final. 3. No setters. 4. Initialize in constructor.
   5. For mutable fields (List, Date, array), store defensive copies in constructor and return
   defensive copies in getters. Example: String is immutable; new String(str) copies the chars.
