GENERICS OVERVIEW
==================

WHAT ARE GENERICS?
-------------------
  Generics allow you to write classes, interfaces, and methods that work with TYPE PARAMETERS —
  placeholders for types that are specified by the user when they use the class or method.

  Introduced in Java 5 to achieve:
    1. Type safety at compile time — catch type errors early
    2. Elimination of casts — no explicit (Type) casting needed
    3. Code reuse — write once, work with any type

WITHOUT GENERICS (pre-Java 5):
  List list = new ArrayList();
  list.add("hello");
  list.add(42);               // No error — any Object accepted
  String s = (String) list.get(0); // Cast required
  String bad = (String) list.get(1); // ClassCastException at RUNTIME

WITH GENERICS:
  List<String> list = new ArrayList<>();
  list.add("hello");
  list.add(42);               // ❌ Compile-time error — type mismatch
  String s = list.get(0);     // No cast needed — compiler knows it's String

GENERIC CLASS
--------------
  // T is the type parameter — can be named anything, but convention:
  //   T = Type, E = Element, K = Key, V = Value, N = Number, R = Return type

  public class Box<T> {
      private T content;

      public Box(T content) { this.content = content; }

      public T getContent() { return content; }

      public void setContent(T content) { this.content = content; }

      @Override
      public String toString() { return "Box[" + content + "]"; }
  }

  // Usage:
  Box<String> strBox = new Box<>("Hello");
  String s = strBox.getContent();  // No cast needed

  Box<Integer> intBox = new Box<>(42);
  int n = intBox.getContent();  // auto-unboxing

  // strBox = intBox;  // ❌ compile error — incompatible types

MULTIPLE TYPE PARAMETERS
-------------------------
  public class Pair<K, V> {
      private final K first;
      private final V second;

      public Pair(K first, V second) { this.first = first; this.second = second; }
      public K getFirst() { return first; }
      public V getSecond() { return second; }
  }

  Pair<String, Integer> p = new Pair<>("Alice", 30);
  String name = p.getFirst();  // "Alice"
  int age = p.getSecond();     // 30

GENERIC METHOD
---------------
  A method can declare its own type parameters independently of the class.
  Type parameters are declared BEFORE the return type.

  public class Utils {
      // Generic method — T inferred from argument
      public static <T> T firstElement(List<T> list) {
          if (list == null || list.isEmpty()) throw new NoSuchElementException();
          return list.get(0);
      }

      // Swap two array elements generically
      public static <T> void swap(T[] arr, int i, int j) {
          T temp = arr[i];
          arr[i] = arr[j];
          arr[j] = temp;
      }

      // Multiple type parameters on method
      public static <K, V> Map<V, K> invertMap(Map<K, V> map) {
          Map<V, K> result = new HashMap<>();
          map.forEach((k, v) -> result.put(v, k));
          return result;
      }
  }

  // Calling generic methods — type usually inferred:
  String first = Utils.firstElement(List.of("a", "b", "c")); // T inferred as String
  Utils.<Integer>firstElement(List.of(1, 2, 3));              // explicit type witness

TYPE ERASURE
-------------
  Java generics are COMPILE-TIME ONLY. At runtime, type parameters are erased.
  The bytecode uses raw types (Object by default, or the bound type if bounded).

  // At compile time:       | After type erasure (bytecode):
  List<String> list;        | List list;
  list.get(0)               | (String) list.get(0)  ← cast inserted by compiler
  Box<T> content;           | Object content;

  CONSEQUENCES OF ERASURE:
  - Cannot create arrays of generic types: new T[10] — ❌ compile error
  - Cannot use instanceof with generic types: obj instanceof List<String> — ❌
  - Cannot create instances of type parameters: new T() — ❌
  - Generic types cannot be used in static context directly (static T value — ❌)
  - Cannot catch or throw type-parameterized exceptions

RAW TYPES (AVOID)
------------------
  Using a generic class without type arguments = RAW TYPE.
  Raw types bypass type checking — dangerous. Only exists for backward compatibility.

  List raw = new ArrayList();  // raw type
  raw.add("hello");
  raw.add(42);                 // no error — but unsafe!
  String s = (String) raw.get(1); // ClassCastException at runtime

  // Compiler warning: "unchecked" warning on raw type usage
  List<String> typed = raw;   // compiles with warning — unsafe assignment

DIAMOND OPERATOR (<>)
----------------------
  Java 7 introduced <> (diamond operator) — compiler infers type arguments from context.

  // Before Java 7:
  Map<String, List<Integer>> map = new HashMap<String, List<Integer>>();

  // Java 7+:
  Map<String, List<Integer>> map = new HashMap<>();  // type inferred

NAMING CONVENTIONS
-------------------
  T   — generic Type
  E   — Element (collections)
  K   — Key (maps)
  V   — Value (maps)
  N   — Number
  R   — Return type (functions)
  S, U, V — 2nd, 3rd, 4th types in multi-parameter declarations

COMMON INTERVIEW QUESTIONS
---------------------------
Q: What is type erasure and what are its consequences?
A: Type erasure is the process by which generic type parameters are removed at compile time
   and replaced with Object (or the bound type). This ensures backward compatibility with
   pre-Java 5 bytecode. Consequences: cannot use instanceof on parameterized types, cannot
   create arrays of generic types (new T[]), cannot instantiate type parameters (new T()),
   and runtime reflection cannot see actual type arguments.

Q: What is a raw type and why should it be avoided?
A: A raw type is a generic class used without type arguments (e.g., List instead of List<String>).
   Raw types bypass generics type checking — the compiler loses track of element types,
   leading to potential ClassCastException at runtime. Raw types exist only for backward
   compatibility with pre-generics code. Always use parameterized types.

Q: Can you create a generic array? (new T[10])
A: No. Because of type erasure, the array type T is not known at runtime, and Java arrays
   are covariant and carry runtime type information. Creating new T[] would be unsafe.
   Workaround: use @SuppressWarnings("unchecked") with (T[]) new Object[size], or
   use ArrayList<T> instead, which handles this internally.

Q: What is the difference between List<Object> and List<?>?
A: List<Object>: a specific parameterized type that holds Objects. You CAN add anything to it
   (since everything is an Object). But List<String> is NOT assignable to List<Object> (not covariant).
   List<?>: unbounded wildcard — can hold a list of ANY type. You CANNOT add anything (except null)
   to List<?> because the type is unknown. Useful for read-only operations on lists of unknown type.
