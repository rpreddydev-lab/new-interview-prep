JAVA RECORDS
=============

WHAT ARE RECORDS?
------------------
  Records (Java 16 — JEP 395, preview in Java 14/15) are transparent, immutable data
  carriers. They reduce boilerplate for classes whose primary purpose is storing data.

  A record is a restricted form of class that automatically generates:
  - A canonical constructor (all components as parameters)
  - Private final fields for each component
  - Public accessor methods (not getX() — just x())
  - equals() based on all components
  - hashCode() based on all components
  - toString() including all components

  // Declaration:
  public record Point(int x, int y) {}

  // Usage:
  Point p = new Point(3, 4);
  p.x()             // 3 — accessor, not field
  p.y()             // 4
  p.equals(new Point(3, 4))  // true — compares x and y
  p.toString()      // "Point[x=3, y=4]"

CANONICAL CONSTRUCTOR
----------------------
  The automatically generated constructor takes all components in order.
  You can customize it or define compact canonical constructors:

  // Explicit canonical constructor (full):
  public record Range(int min, int max) {
      public Range(int min, int max) {
          if (min > max) throw new IllegalArgumentException("min > max");
          this.min = min;
          this.max = max;
      }
  }

  // Compact canonical constructor (preferred — shorter):
  public record Range(int min, int max) {
      public Range {
          // Parameters are in scope; assignments auto-generated at end
          if (min > max) throw new IllegalArgumentException("min > max");
          // No explicit "this.min = min" needed — compiler adds it
      }
  }

  // Additional constructors must delegate to the canonical constructor:
  public record Name(String first, String last) {
      public Name(String full) {
          this(full.split(" ")[0], full.split(" ")[1]);  // delegate
      }
  }

STATIC MEMBERS AND METHODS
----------------------------
  Records can have static fields, static methods, and instance methods.
  Instance methods can add behavior; they cannot mutate state (fields are final).

  public record Circle(double radius) {
      // Derived value:
      public double area() { return Math.PI * radius * radius; }

      // Static factory:
      public static Circle unit() { return new Circle(1.0); }

      // Static constant:
      static final double TWO_PI = 2 * Math.PI;
  }

IMPLEMENTING INTERFACES
------------------------
  Records can implement interfaces:

  public interface Measurable {
      double measure();
  }

  public record Rectangle(double width, double height) implements Measurable {
      @Override
      public double measure() { return width * height; }
  }

RESTRICTIONS
-------------
  Records CANNOT:
  - Extend other classes (implicitly extends java.lang.Record — no other extends)
  - Declare instance fields other than the components
  - Declare abstract methods
  - Be non-final (records are implicitly final — cannot be subclassed)
  - Have mutable components (the fields are final, though the referenced objects may be mutable)

  // ❌ Not allowed:
  record Point(int x, int y) extends SomeClass {}  // cannot extend
  record Point(int x, int y) { int z = 0; }        // extra instance field

  // ⚠️ Components can hold mutable objects — record is NOT deeply immutable:
  record Container(List<String> items) {}
  Container c = new Container(new ArrayList<>(List.of("a","b")));
  c.items().add("c");  // The List inside is mutable — record only prevents reassignment

RECORD WITH GENERICS
---------------------
  public record Pair<A, B>(A first, B second) {
      public Pair<B, A> swap() { return new Pair<>(second, first); }
  }

  Pair<String, Integer> p = new Pair<>("hello", 42);
  Pair<Integer, String> swapped = p.swap();

RECORD VS PLAIN CLASS VS LOMBOK
---------------------------------
  | Aspect               | Plain Class     | Lombok @Value   | Record (Java 16+)   |
  |----------------------|-----------------|-----------------|----------------------|
  | Boilerplate          | High            | Low (annotation)| Zero                 |
  | equals/hashCode      | Manual          | Auto            | Auto                 |
  | toString             | Manual          | Auto            | Auto                 |
  | Accessors            | getX()          | getX()          | x() (no "get")       |
  | Mutability           | Configurable    | Immutable       | Immutable            |
  | Extends              | Any class       | Any class       | Cannot extend        |
  | Extra instance fields| Yes             | Yes             | No                   |
  | Generics             | Yes             | Yes             | Yes                  |
  | Reflection/introspect| Via reflection  | Via reflection  | getRecordComponents()|
  | Annotation support   | Yes             | Yes             | Yes                  |

USE CASES
----------
  Records shine for:
  - DTOs (Data Transfer Objects)
  - Return multiple values from a method
  - Configuration data holders
  - Value objects in Domain-Driven Design
  - Pattern matching targets (Java 21 record patterns)
  - Map keys (since equals/hashCode are auto-generated correctly)

  // Multi-value return:
  record Result(int code, String message) {}
  Result r = processRequest(req);
  System.out.println(r.code() + ": " + r.message());

  // As map key:
  Map<Point, String> grid = new HashMap<>();
  grid.put(new Point(0, 0), "origin");
  grid.get(new Point(0, 0));  // works correctly because equals/hashCode are value-based

RECORD PATTERNS (JAVA 21 — JEP 440)
--------------------------------------
  Records participate in pattern matching — you can destructure them in instanceof
  and switch:

  if (obj instanceof Point(int x, int y)) {
      System.out.println("x=" + x + " y=" + y);
  }

  String describe(Object obj) {
      return switch (obj) {
          case Point(int x, int y) -> "Point at " + x + "," + y;
          case Circle(double r)    -> "Circle r=" + r;
          default                  -> "Unknown";
      };
  }

COMMON INTERVIEW QUESTIONS
---------------------------
Q: What is a record in Java and what does it auto-generate?
A: A record (Java 16) is a concise, immutable data class. For each component declared
   in the header, the compiler auto-generates: a private final field, a public accessor
   method (component name, no "get" prefix), and equals(), hashCode(), and toString()
   based on all components. A canonical constructor is also generated. Records are
   implicitly final and cannot extend other classes.

Q: What is the difference between a compact canonical constructor and a regular constructor in a record?
A: In a compact canonical constructor, you omit the parameter list (it is inferred from
   the record components). The component parameters are in scope for validation and
   normalization, and the compiler automatically generates the field assignments (this.x = x)
   at the end. In a regular canonical constructor, you write the full parameter list and
   must explicitly assign each field.

Q: Are records truly immutable?
A: Records provide shallow immutability — component fields are private and final, so they
   cannot be reassigned. However, if a component's type is mutable (e.g., List), the
   referenced object can still be mutated. To achieve deep immutability, defensively copy
   mutable components: store List.copyOf(items) in the compact constructor.

Q: When would you use a record vs a regular class?
A: Use a record when the class's purpose is purely to hold data — no complex behavior,
   no inheritance, and immutability is acceptable. Ideal for DTOs, return types,
   configuration holders, and map keys. Use a regular class when you need: inheritance,
   additional instance fields beyond the record components, mutability, or complex
   construction logic that doesn't fit the record model.
