VIRTUAL THREADS (JEP 444 — FINALIZED)
---------------------------------------
  (Full concurrency detail in 07_Multithreading_and_Concurrency/15_Virtual_Threads_Project_Loom.txt)

  Virtual threads are JVM-managed, lightweight threads — not tied 1:1 to OS threads.
  Millions can exist concurrently; each consumes only a few KB of heap (vs ~1 MB for
  platform threads).

  // Create virtual threads:
  Thread.ofVirtual().start(() -> System.out.println("Virtual!"));

  // Virtual thread executor (one virtual thread per task — replaces thread pools for I/O):
  try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
      for (int i = 0; i < 100_000; i++) {
          executor.submit(() -> handleRequest());
      }
  }

  Key rules:
  - Ideal for I/O-bound tasks (HTTP calls, DB queries, file reads)
  - NOT for CPU-bound work (use platform thread pools or ForkJoinPool)
  - Avoid pinning: synchronized blocks pin VT to carrier; use ReentrantLock instead
  - ThreadLocal works but consider ScopedValue for better performance

  // Comparison:
  // Platform thread: 1-1 with OS thread, ~1MB stack
  Thread platform = Thread.ofPlatform().start(() -> { ... });
  // Virtual thread: M:N mapping, few KB, millions possible
  Thread virtual  = Thread.ofVirtual().start(() -> { ... });

SEQUENCED COLLECTIONS (JEP 431)
---------------------------------
  Java 21 adds new interfaces to fix a gap: no uniform way to access first/last elements
  across List, Deque, LinkedHashSet, LinkedHashMap, etc.

  New interfaces in java.util:
  - SequencedCollection<E>   — extends Collection<E>
  - SequencedSet<E>          — extends Set<E> and SequencedCollection<E>
  - SequencedMap<K,V>        — extends Map<K,V>

  SequencedCollection<E> adds:
  - E getFirst()           — first element (NoSuchElementException if empty)
  - E getLast()            — last element
  - void addFirst(E e)     — insert at beginning
  - void addLast(E e)      — insert at end
  - E removeFirst()        — remove and return first
  - E removeLast()         — remove and return last
  - SequencedCollection<E> reversed()  — reverse-order view

  // Before Java 21 — inconsistent API:
  List<String> list = new ArrayList<>(List.of("a","b","c"));
  String first = list.get(0);                    // List
  String first2 = deque.peekFirst();             // Deque
  String first3 = sortedSet.first();             // SortedSet — different method!

  // After Java 21 — uniform via SequencedCollection:
  SequencedCollection<String> seq = new ArrayList<>(List.of("a","b","c"));
  String first = seq.getFirst();  // "a"
  String last  = seq.getLast();   // "c"
  seq.addFirst("z");              // ["z","a","b","c"]
  seq.addLast("x");               // ["z","a","b","c","x"]
  SequencedCollection<String> rev = seq.reversed(); // view: ["x","c","b","a","z"]

  // SequencedMap:
  SequencedMap<String, Integer> map = new LinkedHashMap<>();
  map.put("one", 1); map.put("two", 2); map.put("three", 3);
  map.firstEntry();    // Map.Entry<String,Integer> "one"=1
  map.lastEntry();     // "three"=3
  map.pollFirstEntry(); // removes and returns first entry
  map.pollLastEntry();  // removes and returns last entry
  map.reversed();       // reversed SequencedMap view

  // Inheritance hierarchy (simplified):
  // Collection
  //   └── SequencedCollection
  //         ├── List              (ArrayList, LinkedList)
  //         ├── Deque             (ArrayDeque, LinkedList)
  //         └── SequencedSet
  //               ├── SortedSet
  //               │     └── NavigableSet (TreeSet)
  //               └── LinkedHashSet

PATTERN MATCHING FOR switch (JEP 441 — FINALIZED)
----------------------------------------------------
  (Detail in 12_Pattern_Matching_instanceof_switch.txt)
  Finalized in Java 21. Key capabilities:
  - Type patterns in switch: case Integer i -> ...
  - Guarded patterns: case String s when s.isEmpty() -> ...
  - Record patterns: case Point(int x, int y) -> ...
  - Null handling: case null -> ...
  - Exhaustive switch with sealed types — no default needed

RECORD PATTERNS (JEP 440 — FINALIZED)
----------------------------------------
  (Detail in 12_Pattern_Matching_instanceof_switch.txt)
  Destructure records in instanceof and switch patterns:
  if (obj instanceof Point(int x, int y)) { ... }

STRING TEMPLATES (PREVIEW — JEP 430)
--------------------------------------
  Safely embed expressions in strings without string concatenation or format() calls:

  // Traditional:
  String s = "Hello, " + name + "! You are " + age + " years old.";
  String s2 = String.format("Hello, %s! You are %d years old.", name, age);

  // String template (preview — Java 21):
  String s3 = STR."Hello, \{name}! You are \{age} years old.";
  // STR is a template processor; \{expr} interpolates any expression

  // Multi-line:
  String json = STR."""
      {
        "name": "\{name}",
        "age": \{age}
      }
      """;

  Note: String templates are still preview as of Java 21. The STR processor HTML-escapes
  nothing — there are safer processors for SQL/HTML planned in future releases.

STRUCTURED CONCURRENCY (PREVIEW — JEP 453)
-------------------------------------------
  (Detail in 07_Multithreading_and_Concurrency/19_Structured_Concurrency_Java21.txt)
  Treats concurrent subtasks as a unit — if one fails, others are cancelled.
  API: StructuredTaskScope.ShutdownOnFailure, ShutdownOnSuccess.

SCOPED VALUES (PREVIEW — JEP 446)
------------------------------------
  Immutable, context-local values propagated to child threads (virtual thread-friendly
  replacement for ThreadLocal):

  static final ScopedValue<User> CURRENT_USER = ScopedValue.newInstance();

  ScopedValue.where(CURRENT_USER, user).run(() -> {
      // CURRENT_USER.get() returns user in this scope and all child virtual threads
      processRequest();
  });

COMMON INTERVIEW QUESTIONS
---------------------------
Q: What are the most important features finalized in Java 21?
A: Java 21 (LTS) finalized: Virtual Threads (JEP 444) — lightweight, JVM-managed threads
   enabling high-concurrency I/O-bound apps; Sequenced Collections (JEP 431) — uniform
   first/last access API for ordered collections; Pattern Matching for switch (JEP 441) —
   type patterns with guarded clauses in switch; and Record Patterns (JEP 440) —
   structural decomposition of records in patterns.

Q: What are Sequenced Collections and what problem do they solve?
A: Sequenced Collections (Java 21) add three new interfaces — SequencedCollection,
   SequencedSet, SequencedMap — to provide a uniform API for collections with a defined
   encounter order. Previously, accessing the first element of a List used get(0), a Deque
   used peekFirst(), and a SortedSet used first() — no common method. SequencedCollection
   adds getFirst(), getLast(), addFirst(), addLast(), removeFirst(), removeLast(), and
   reversed() as standard across all ordered collections.

Q: What is the difference between Virtual Threads and platform threads in Java 21?
A: Platform threads map 1:1 to OS threads — creating thousands is expensive (~1 MB stack
   each, OS scheduling overhead). Virtual threads are JVM-managed and multiplexed onto a
   small pool of carrier (platform) threads. They consume only a few KB of heap, can be
   created in the millions, and automatically suspend when blocking on I/O (freeing the
   carrier). Virtual threads are ideal for I/O-bound concurrent tasks; for CPU-bound work,
   platform thread pools (ForkJoinPool) are still preferred.
