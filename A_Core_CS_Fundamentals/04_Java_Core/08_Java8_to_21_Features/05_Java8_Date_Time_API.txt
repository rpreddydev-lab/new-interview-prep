JAVA 8 DATE AND TIME API (JSR-310)
====================================

WHY A NEW API?
---------------
  The original java.util.Date and java.util.Calendar had many flaws:
  - Mutable — thread-unsafe, values could be changed after creation
  - Poor API design — months 0-indexed, years 1900-offset, etc.
  - No timezone support in Date (despite the name)
  - Difficult formatting (SimpleDateFormat was also mutable and not thread-safe)
  - No concept of date-only or time-only types

  Java 8 introduced java.time (JSR-310, inspired by Joda-Time):
  - Immutable and thread-safe
  - Clear, fluent API
  - Distinct classes for date, time, date+time, zoned, instant
  - ISO-8601 standard by default

CORE CLASSES
-------------
  LocalDate       — date without time: 2024-07-15
  LocalTime       — time without date: 14:30:00.000
  LocalDateTime   — date + time, no timezone: 2024-07-15T14:30:00
  ZonedDateTime   — date + time + timezone: 2024-07-15T14:30:00+05:30[Asia/Kolkata]
  OffsetDateTime  — date + time + UTC offset: 2024-07-15T14:30:00+05:30
  Instant         — machine timestamp — nanoseconds from epoch (UTC)
  Duration        — time-based amount (hours, minutes, seconds, nanos)
  Period          — date-based amount (years, months, days)
  ZoneId          — timezone identifier (e.g., "America/New_York")
  ZoneOffset      — UTC offset (+05:30)

LOCALDATE
----------
  LocalDate today = LocalDate.now();
  LocalDate specific = LocalDate.of(2024, 7, 15);
  LocalDate parsed = LocalDate.parse("2024-07-15");  // ISO-8601

  today.getYear()         // 2024
  today.getMonthValue()   // 7 (1-12, not 0-11!)
  today.getMonth()        // Month.JULY
  today.getDayOfMonth()   // 15
  today.getDayOfWeek()    // DayOfWeek.MONDAY

  // Manipulation — returns NEW instance (immutable):
  LocalDate tomorrow = today.plusDays(1);
  LocalDate lastMonth = today.minusMonths(1);
  LocalDate nextYear = today.plusYears(1);
  LocalDate firstOfMonth = today.withDayOfMonth(1);

  // Comparison:
  today.isBefore(tomorrow)          // true
  today.isAfter(lastMonth)          // true
  today.isEqual(LocalDate.now())    // true

LOCALTIME
----------
  LocalTime now = LocalTime.now();
  LocalTime t = LocalTime.of(14, 30, 0);          // 14:30:00
  LocalTime t2 = LocalTime.of(14, 30, 0, 500_000); // with nanoseconds

  t.getHour()      // 14
  t.getMinute()    // 30
  t.getSecond()    // 0
  t.getNano()      // 500000

  t.plusHours(2)    // 16:30:00
  t.minusMinutes(5) // 14:25:00

LOCALDATETIME
--------------
  LocalDateTime ldt = LocalDateTime.now();
  LocalDateTime ldt2 = LocalDateTime.of(2024, 7, 15, 14, 30);
  LocalDateTime ldt3 = LocalDateTime.of(LocalDate.of(2024, 7, 15), LocalTime.of(14, 30));

  ldt.toLocalDate()   // extract LocalDate
  ldt.toLocalTime()   // extract LocalTime

ZONEDDATETIME
--------------
  ZoneId zone = ZoneId.of("America/New_York");
  ZonedDateTime zdt = ZonedDateTime.now(zone);
  ZonedDateTime zdt2 = ZonedDateTime.of(LocalDateTime.now(), zone);

  // Convert between zones:
  ZonedDateTime nyTime = ZonedDateTime.now(ZoneId.of("America/New_York"));
  ZonedDateTime londonTime = nyTime.withZoneSameInstant(ZoneId.of("Europe/London"));

  // List all available zone IDs:
  Set<String> zones = ZoneId.getAvailableZoneIds();

INSTANT
--------
  Instant represents a point on the timeline in UTC (nanosecond precision from epoch).
  Use Instant for machine-readable timestamps, storing in databases, logging, etc.

  Instant now = Instant.now();
  Instant epoch = Instant.EPOCH;     // 1970-01-01T00:00:00Z
  Instant specific = Instant.ofEpochSecond(1721000000L);

  now.toEpochMilli()           // milliseconds since epoch
  now.getEpochSecond()         // seconds since epoch

  // Convert between Instant and ZonedDateTime:
  ZonedDateTime zdt = instant.atZone(ZoneId.of("UTC"));
  Instant instant = zdt.toInstant();

DURATION AND PERIOD
--------------------
  // Duration — time-based (hours, minutes, seconds, nanos):
  Duration d = Duration.between(startTime, endTime);
  Duration twoHours = Duration.ofHours(2);
  Duration parsed = Duration.parse("PT2H30M");  // ISO-8601: 2 hours 30 min

  d.toMinutes()    // total minutes
  d.toHours()      // total hours
  d.isNegative()   // true if end before start

  // Period — date-based (years, months, days):
  Period p = Period.between(startDate, endDate);
  Period oneMonth = Period.ofMonths(1);
  Period parsed2 = Period.parse("P1Y2M3D");     // 1 year 2 months 3 days

  p.getYears()    // years component
  p.getMonths()   // months component
  p.getDays()     // days component

DATETIMEFORMATTER
------------------
  // Predefined formatters:
  String s = LocalDate.now().format(DateTimeFormatter.ISO_LOCAL_DATE); // "2024-07-15"
  String s2 = LocalDateTime.now().format(DateTimeFormatter.ISO_LOCAL_DATE_TIME);

  // Custom pattern (thread-safe, unlike SimpleDateFormat):
  DateTimeFormatter fmt = DateTimeFormatter.ofPattern("dd/MM/yyyy HH:mm");
  String formatted = LocalDateTime.now().format(fmt);   // "15/07/2024 14:30"
  LocalDateTime parsed = LocalDateTime.parse("15/07/2024 14:30", fmt);

  // Locale-aware:
  DateTimeFormatter localeFmt = DateTimeFormatter
      .ofLocalizedDate(FormatStyle.LONG)
      .withLocale(Locale.US);

OLD API VS NEW API
-------------------
  | java.util.Date (old)         | java.time (new)               |
  |------------------------------|-------------------------------|
  | Mutable                      | Immutable                     |
  | Not thread-safe              | Thread-safe                   |
  | Month 0-indexed              | Month 1-indexed               |
  | No date-only or time-only    | LocalDate, LocalTime, etc.   |
  | SimpleDateFormat not thread-safe | DateTimeFormatter is     |
  | No timezone in Date class    | ZoneId/ZonedDateTime          |
  | Poor API design              | Fluent, consistent            |

  // Interoperability (converting between old and new):
  Instant instant = oldDate.toInstant();
  ZonedDateTime zdt = instant.atZone(ZoneId.systemDefault());
  LocalDate ld = zdt.toLocalDate();

  Date backToOld = Date.from(zdt.toInstant());

COMMON INTERVIEW QUESTIONS
---------------------------
Q: What are the key improvements in the Java 8 Date/Time API over java.util.Date?
A: (1) Immutable and thread-safe — no more race conditions with SimpleDateFormat.
   (2) Clear separation of concerns: LocalDate (date-only), LocalTime (time-only),
   LocalDateTime, ZonedDateTime, Instant. (3) Months are 1-indexed (Jan = 1), years
   are actual years. (4) DateTimeFormatter is thread-safe. (5) Rich API: fluent
   manipulation, Duration/Period, timezone support via ZoneId. (6) ISO-8601 by default.

Q: What is the difference between LocalDateTime and ZonedDateTime?
A: LocalDateTime represents a date and time without any timezone information —
   it's like the clock on the wall in a specific location. ZonedDateTime adds a
   ZoneId and handles DST (daylight saving time) transitions. Use LocalDateTime
   when timezone doesn't matter (e.g., appointment time in a local calendar app).
   Use ZonedDateTime or Instant when dealing with times across timezones or needing
   to convert between them.

Q: What is the difference between Duration and Period?
A: Duration is time-based — it represents an amount in terms of seconds and nanoseconds
   (hours, minutes, seconds). Use Duration for measuring elapsed time between two instants
   or times. Period is date-based — it represents an amount in terms of years, months,
   and days. Use Period for calendar arithmetic (how many months between two dates, add
   1 month, etc.). Period doesn't convert months to days because months have variable lengths.

Q: What is an Instant and when should you use it?
A: Instant is a point in time on the timeline, measured as nanoseconds from the Unix
   epoch (1970-01-01T00:00:00Z). It's always in UTC with no timezone concept. Use
   Instant for: recording timestamps in logs, event stores, databases; computing
   elapsed time between events; serializing time in a portable format. Convert to
   ZonedDateTime when you need to display the time in a specific timezone.
