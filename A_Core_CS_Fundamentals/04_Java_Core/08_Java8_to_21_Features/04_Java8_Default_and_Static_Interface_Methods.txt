JAVA 8 DEFAULT AND STATIC INTERFACE METHODS
============================================

MOTIVATION
-----------
  Before Java 8, interfaces could only declare abstract methods and constants.
  This made it impossible to add new methods to published interfaces without
  breaking all existing implementations.

  Java 8 introduced:
  1. Default methods  — methods with an implementation in the interface itself
  2. Static methods   — utility methods on the interface type

  This enabled the Java API to evolve (adding forEach, stream, etc. to Collection)
  without breaking existing code.

DEFAULT METHODS
----------------
  A default method provides a body in the interface. Implementing classes inherit
  the default implementation and may override it.

  interface Greeter {
      String greet(String name);  // abstract — must implement

      default String greetAll(List<String> names) {  // default — optional to override
          return names.stream()
                      .map(this::greet)
                      .collect(Collectors.joining(", "));
      }
  }

  class FriendlyGreeter implements Greeter {
      @Override
      public String greet(String name) { return "Hi, " + name + "!"; }
      // greetAll inherited from interface — no override needed
  }

  // Real example: Comparator.thenComparing()
  Comparator<String> byLength = Comparator.comparingInt(String::length);
  Comparator<String> byLenThenAlpha = byLength.thenComparing(Comparator.naturalOrder());

  // forEach was added to Iterable as a default method in Java 8:
  default void forEach(Consumer<? super T> action) {
      Objects.requireNonNull(action);
      for (T t : this) { action.accept(t); }
  }

STATIC METHODS IN INTERFACES
------------------------------
  Static interface methods are utility/helper methods. They belong to the interface
  type itself (not to instances). They are NOT inherited by implementing classes.

  interface Validator<T> {
      boolean validate(T value);

      static <T> Validator<T> noOp() {        // factory
          return value -> true;
      }

      static <T> Validator<T> compose(Validator<T> a, Validator<T> b) {
          return value -> a.validate(value) && b.validate(value);
      }
  }

  // Call via interface name only:
  Validator<String> v = Validator.noOp();
  // Cannot call via implementing class — unlike static methods in classes

  // Real example: Predicate.not() (Java 11), Comparator.naturalOrder(), etc.
  List<String> nonBlanks = list.stream()
      .filter(Predicate.not(String::isBlank))  // Java 11+
      .collect(Collectors.toList());

DIAMOND PROBLEM
----------------
  When a class implements two interfaces that both provide a default method with the
  same signature, the compiler requires the class to explicitly override and resolve
  the conflict.

  interface A {
      default String hello() { return "Hello from A"; }
  }
  interface B {
      default String hello() { return "Hello from B"; }
  }

  // ❌ Compile error without override:
  class C implements A, B { }  // error: C inherits unrelated defaults for hello()

  // ✅ Must override:
  class C implements A, B {
      @Override
      public String hello() {
          return A.super.hello();  // explicitly choose A's version
          // or: return B.super.hello();
          // or: return "Hello from C";
      }
  }

INTERFACE VS ABSTRACT CLASS (POST-JAVA 8)
-------------------------------------------
  Default methods close some of the gap between interfaces and abstract classes, but
  key differences remain:

  | Aspect                   | Interface (Java 8+)          | Abstract Class                |
  |--------------------------|------------------------------|-------------------------------|
  | Multiple inheritance     | ✅ Yes (implements many)     | ❌ No (extends one)           |
  | State (instance fields)  | ❌ Only public static final  | ✅ Yes                        |
  | Constructors             | ❌ No                        | ✅ Yes                        |
  | Access modifiers (methods)| Only public + private [J9]  | Any (private/protected/public)|
  | Default methods          | ✅ Yes                       | N/A — use concrete methods    |
  | Static methods           | ✅ Yes                       | ✅ Yes                        |
  | is-a semantic            | Type contract/capability     | Partial implementation/state  |

  Rule of thumb: Use interfaces to express capabilities (Comparable, Runnable, Closeable).
                 Use abstract classes when you need shared state or constructor logic.

DEFAULT METHOD CONFLICTS — CLASS WINS OVER INTERFACE
------------------------------------------------------
  If a class inherits a method from a superclass AND a default method with the same
  signature from an interface, the class's method always wins (no override needed):

  class Base {
      public String hello() { return "Hello from Base"; }
  }
  interface A {
      default String hello() { return "Hello from A"; }
  }
  class Child extends Base implements A {
      // Base.hello() wins — no conflict, no override required
  }
  new Child().hello(); // "Hello from Base"

PRIVATE INTERFACE METHODS (JAVA 9)
------------------------------------
  Java 9 added private methods in interfaces to allow default methods to share
  helper code without exposing it to implementing classes.

  interface Processor {
      default void process(String input) {
          String cleaned = clean(input);  // private helper
          doProcess(cleaned);
      }
      default void processAll(List<String> inputs) {
          inputs.forEach(i -> {
              String cleaned = clean(i);
              doProcess(cleaned);
          });
      }
      private String clean(String s) {   // private — not visible to implementers
          return s.trim().toLowerCase();
      }
      void doProcess(String cleaned);  // abstract
  }

COMMON INTERVIEW QUESTIONS
---------------------------
Q: Why were default methods introduced in Java 8?
A: To allow existing interfaces to be extended with new methods without breaking
   backward compatibility. The Java Collections framework needed to add stream()
   and forEach() to Collection/Iterable. Without default methods, every existing
   implementation (millions of classes) would have broken at compile time. Default
   methods let interface authors add new API with a fallback implementation that
   existing implementors inherit automatically.

Q: How is the diamond problem resolved with default methods?
A: When a class implements two interfaces that both define a default method with the
   same signature, the compiler forces the class to explicitly override the method and
   resolve the conflict. The class can delegate to a specific interface's version using
   InterfaceName.super.methodName(), provide its own implementation, or call both.
   If a concrete method is inherited from a superclass, it always wins over any default
   method from interfaces — no override required.

Q: What is the difference between a default method and a static method in an interface?
A: A default method belongs to instances — implementing classes inherit it and can
   override it. A static method belongs to the interface type itself, must be called
   via InterfaceName.method(), and is NOT inherited by implementing classes. Default
   methods extend instance behavior; static interface methods provide utility functions.

Q: Can an interface extend another interface and override its default method?
A: Yes. A sub-interface can override a default method from a parent interface, provide
   its own default implementation, or redeclare it as abstract (forcing concrete
   implementors to provide the body even if the parent had a default).
