JAVA 8 OPTIONAL
================

WHY OPTIONAL?
--------------
  Before Java 8, methods returned null to indicate "no value." This caused widespread
  NullPointerExceptions because callers forgot to null-check. Optional<T> is a container
  that explicitly signals "this value may or may not be present," forcing callers to
  handle the absent case in a type-safe way.

  Optional is NOT a silver bullet for nulls everywhere — it's designed for return types
  of methods that legitimately might have no result (like search operations).

CREATING OPTIONALS
-------------------
  Optional<String> present = Optional.of("Hello");         // throws NPE if null
  Optional<String> nullable = Optional.ofNullable(value);  // safe — handles null
  Optional<String> empty   = Optional.empty();             // explicit empty

  // Optional.of vs Optional.ofNullable:
  Optional.of(null)           // ❌ throws NullPointerException immediately
  Optional.ofNullable(null)   // ✅ returns Optional.empty()

CHECKING AND EXTRACTING VALUES
--------------------------------
  Optional<String> opt = Optional.ofNullable(getValue());

  // Check presence:
  if (opt.isPresent()) {
      String value = opt.get(); // throws NoSuchElementException if empty
  }
  if (opt.isEmpty()) { ... }    // Java 11+: inverse of isPresent()

  // Modern (preferred):
  opt.ifPresent(v -> System.out.println(v));                // do nothing if empty
  opt.ifPresentOrElse(v -> use(v), () -> handleEmpty());   // Java 9+

  // Get with fallback:
  String value = opt.orElse("default");                     // always evaluated
  String value = opt.orElseGet(() -> computeDefault());     // lazy — only if empty
  String value = opt.orElseThrow();                         // NoSuchElementException (Java 10+)
  String value = opt.orElseThrow(() -> new NotFoundException("Not found"));

TRANSFORMING OPTIONALS
-----------------------
  // map: apply function if present, returns Optional<R>
  Optional<Integer> length = opt.map(String::length);

  // flatMap: when the mapping function itself returns Optional<R>
  // (avoids Optional<Optional<T>>)
  Optional<String> upper = opt.flatMap(s -> Optional.of(s.toUpperCase()));

  // filter: keep value only if predicate matches, else empty
  Optional<String> longOnly = opt.filter(s -> s.length() > 5);

  // stream(): Java 9+ — returns a Stream of 0 or 1 element
  // Useful for flatMapping Optional into a Stream pipeline:
  List<Optional<String>> opts = ...;
  List<String> present2 = opts.stream()
      .flatMap(Optional::stream)   // filters out empties, unwraps presents
      .collect(Collectors.toList());

CHAINING OPTIONALS
-------------------
  // Real-world chain: find city of customer's shipping address
  Optional<String> city = Optional.ofNullable(order)
      .map(Order::getCustomer)
      .map(Customer::getAddress)
      .map(Address::getCity)
      .filter(c -> !c.isBlank())
      .orElse("Unknown");

  // Equivalent null-check chain (pre-Java 8):
  String city = "Unknown";
  if (order != null && order.getCustomer() != null
      && order.getCustomer().getAddress() != null
      && order.getCustomer().getAddress().getCity() != null
      && !order.getCustomer().getAddress().getCity().isBlank()) {
      city = order.getCustomer().getAddress().getCity();
  }

OR — FALLBACK TO ANOTHER OPTIONAL (JAVA 9+)
---------------------------------------------
  // or() returns another Optional if empty:
  Optional<String> result = primary.or(() -> secondary).or(() -> tertiary);

  // vs orElse which returns a plain value:
  String result2 = primary.orElse("default");

OPTIONAL ANTI-PATTERNS
------------------------
  // ❌ Don't use Optional as a field type:
  class User {
      private Optional<String> nickname; // bad — adds overhead, not serializable
  }
  // ✅ Use null as a field, wrap in Optional on access if needed

  // ❌ Don't use Optional as a method parameter:
  void sendEmail(String email, Optional<String> subject) { ... } // confusing API
  // ✅ Use method overloading or nullable param with null check

  // ❌ Don't use Optional<T> in collections:
  List<Optional<String>> list; // just use a sparse list or filter nulls
  // ✅ List<String> with filtering

  // ❌ Don't call get() without checking isPresent() first:
  String s = opt.get(); // may throw NoSuchElementException
  // ✅ Use orElse, orElseGet, orElseThrow, ifPresent, or map

  // ❌ Don't use Optional to wrap every possible null in existing code:
  // Optional is for return types of operations that may semantically have no result.
  // Internal null-checks are still fine.

  // ❌ Don't use Optional<int> — primitive versions exist:
  OptionalInt    optInt    = OptionalInt.of(5);
  OptionalLong   optLong   = OptionalLong.of(5L);
  OptionalDouble optDouble = OptionalDouble.of(3.14);
  // These avoid boxing overhead

OPTIONAL QUICK REFERENCE
--------------------------
  | Method                   | Behavior                                      |
  |--------------------------|-----------------------------------------------|
  | of(value)                | Wrap value; NPE if null                       |
  | ofNullable(value)        | Wrap; empty() if null                         |
  | empty()                  | Empty Optional                                |
  | get()                    | Value or NoSuchElementException               |
  | isPresent()              | true if value present                         |
  | isEmpty() [Java 11]      | true if empty                                 |
  | ifPresent(Consumer)      | Run consumer if present                       |
  | ifPresentOrElse() [J9]   | Consumer if present, Runnable if empty        |
  | orElse(T)                | Value or provided default (always evaluated)  |
  | orElseGet(Supplier)      | Value or computed default (lazy)              |
  | orElseThrow()            | Value or NoSuchElementException [Java 10]     |
  | orElseThrow(Supplier)    | Value or custom exception                     |
  | map(Function)            | Transform if present → Optional<R>            |
  | flatMap(Function)        | Transform to Optional<R> (avoids nesting)     |
  | filter(Predicate)        | Keep if predicate holds, else empty           |
  | stream() [Java 9]        | Stream of 0 or 1 elements                     |
  | or(Supplier) [Java 9]    | This or fallback Optional                     |

COMMON INTERVIEW QUESTIONS
---------------------------
Q: What is Optional and why was it introduced?
A: Optional<T> is a container class introduced in Java 8 to represent a value that
   may or may not be present. It was introduced to reduce NullPointerExceptions by
   making "no value" scenarios explicit in the type system, forcing callers to handle
   the absent case. It's intended primarily as a return type for methods like find
   operations where not finding a result is a valid outcome — not as a general-purpose
   null replacement.

Q: What is the difference between orElse and orElseGet?
A: orElse(T) always evaluates its argument, even when the Optional is present. This is
   wasteful (and potentially buggy) if the argument involves an expensive computation
   or side effects. orElseGet(Supplier<T>) is lazy — the supplier is only invoked if
   the Optional is empty. Prefer orElseGet when the default value involves computation.

Q: What is the difference between map and flatMap in Optional?
A: map(Function<T,R>) wraps the result in another Optional, so applying a function that
   itself returns Optional<R> would give Optional<Optional<R>>. flatMap(Function<T,Optional<R>>)
   flattens the nesting — the function must return Optional<R>, and flatMap returns
   Optional<R> directly. Use flatMap when chaining operations that themselves return Optionals.

Q: Why should Optional not be used as a method parameter?
A: It makes the API confusing and forces callers to wrap values. The caller is better
   served by overloaded methods or @Nullable documentation. Optional is designed to
   communicate "no result" in return types, not to replace method overloading for
   optional parameters.
