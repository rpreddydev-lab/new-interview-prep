JAVA 8 STREAM API
==================

WHAT IS A STREAM?
------------------
  A Stream<T> is a sequence of elements supporting sequential or parallel aggregate
  operations. Streams are NOT data structures — they don't store elements. They
  carry data from a source (collection, array, I/O) through a pipeline of operations.

  Key characteristics:
  - Lazy evaluation: intermediate operations don't execute until a terminal operation is called
  - Single-use: a stream can only be traversed once; reuse requires a new stream
  - Internal iteration: the library controls the loop; you provide what to do per element
  - Optional parallelism: call .parallelStream() or .parallel() for parallel execution

STREAM PIPELINE
----------------
  Source → [Zero or more Intermediate Operations] → Terminal Operation

  List<String> result = collection   // Source
      .stream()                       // Stream creation
      .filter(s -> s.length() > 3)   // Intermediate (lazy)
      .map(String::toUpperCase)       // Intermediate (lazy)
      .sorted()                       // Intermediate (lazy)
      .collect(Collectors.toList());  // Terminal (triggers execution)

CREATING STREAMS
-----------------
  // From a Collection:
  Stream<String> s1 = list.stream();
  Stream<String> s2 = list.parallelStream();

  // From an array:
  Stream<String> s3 = Arrays.stream(array);
  IntStream      s4 = Arrays.stream(intArray);

  // From values:
  Stream<String> s5 = Stream.of("a", "b", "c");

  // Empty stream:
  Stream<String> s6 = Stream.empty();

  // Infinite streams:
  Stream<Integer> natural  = Stream.iterate(1, n -> n + 1);
  Stream<Double>  randoms  = Stream.generate(Math::random);
  Stream<Integer> range    = Stream.iterate(0, n -> n < 10, n -> n + 1); // Java 9+

  // Primitive streams (avoid boxing overhead):
  IntStream    range2 = IntStream.range(0, 10);      // 0..9
  IntStream    range3 = IntStream.rangeClosed(1, 5); // 1..5
  LongStream   ls     = LongStream.of(1L, 2L, 3L);
  DoubleStream ds     = DoubleStream.of(1.0, 2.0);

INTERMEDIATE OPERATIONS (LAZY)
--------------------------------
  filter(Predicate<T>)      — keep elements matching predicate
  map(Function<T,R>)        — transform T to R
  mapToInt/Long/Double()    — transform to primitive stream
  flatMap(Function<T,Stream<R>>) — flatten nested streams
  flatMapToInt/Long/Double() — flatten to primitive stream
  distinct()                — remove duplicates (uses equals/hashCode)
  sorted()                  — natural order sort
  sorted(Comparator<T>)     — custom sort
  peek(Consumer<T>)         — inspect/debug each element (does not modify)
  limit(long n)             — take first n elements
  skip(long n)              — skip first n elements
  takeWhile(Predicate<T>)   — take while condition holds (Java 9+)
  dropWhile(Predicate<T>)   — drop while condition holds, then take rest (Java 9+)

  // flatMap example: flatten List<List<String>> to Stream<String>
  List<List<String>> nested = List.of(List.of("a","b"), List.of("c","d"));
  List<String> flat = nested.stream()
      .flatMap(Collection::stream)
      .collect(Collectors.toList());  // [a, b, c, d]

  // flatMap with Optional (Java 8 idiom):
  Stream<Optional<String>> opts = ...;
  Stream<String> present = opts.flatMap(Optional::stream); // Java 9+

TERMINAL OPERATIONS (EAGER — TRIGGERS PIPELINE)
-------------------------------------------------
  collect(Collector<T,A,R>) — mutable reduction to Collection, Map, String, etc.
  toList()                  — Java 16+: Stream.toList() (unmodifiable)
  forEach(Consumer<T>)      — consume each element (no return value)
  forEachOrdered()          — ordered forEach (important in parallel)
  count()                   — returns long count of elements
  findFirst()               — Optional<T> — first element (ordered)
  findAny()                 — Optional<T> — any element (faster in parallel)
  anyMatch(Predicate<T>)    — returns true if any element matches (short-circuits)
  allMatch(Predicate<T>)    — returns true if ALL elements match
  noneMatch(Predicate<T>)   — returns true if NO elements match
  min(Comparator<T>)        — Optional<T> minimum
  max(Comparator<T>)        — Optional<T> maximum
  reduce(T identity, BinaryOperator<T>) — fold all elements
  reduce(BinaryOperator<T>) — fold without identity → Optional<T>
  toArray()                 — Object[] (or typed: toArray(String[]::new))
  sum()/average()/summaryStatistics() — on primitive streams

COMMON PATTERNS
----------------
  // Count elements matching a condition:
  long count = list.stream().filter(x -> x > 5).count();

  // Find first element:
  Optional<String> first = list.stream().filter(s -> s.startsWith("A")).findFirst();

  // Sum of mapped values:
  int totalLen = names.stream().mapToInt(String::length).sum();

  // Group by a property:
  Map<Integer, List<String>> byLength = names.stream()
      .collect(Collectors.groupingBy(String::length));

  // Join strings:
  String csv = names.stream().collect(Collectors.joining(", "));

  // Map to new collection:
  Set<String> upper = names.stream()
      .map(String::toUpperCase)
      .collect(Collectors.toSet());

  // Sorting with multiple criteria:
  list.stream()
      .sorted(Comparator.comparing(Person::getLastName)
                        .thenComparing(Person::getFirstName))
      .collect(Collectors.toList());

REDUCE AND COLLECT
-------------------
  // reduce — general-purpose fold:
  Optional<Integer> sum = Stream.of(1, 2, 3, 4).reduce(Integer::sum);
  Integer sum2 = Stream.of(1, 2, 3, 4).reduce(0, Integer::sum);

  // Custom mutable reduction with collect:
  // - use collect() instead of reduce() when the result type is a mutable container
  // - Collectors.toList() is much more efficient than reduce to build a list

PARALLEL STREAMS
-----------------
  list.parallelStream()       // parallel from source
  stream.parallel()           // switch existing stream to parallel
  stream.sequential()         // switch back to sequential

  Rules for parallel safety:
  - Stateless intermediate operations (map, filter) are safe
  - Avoid shared mutable state in lambdas — will cause race conditions
  - forEach order NOT guaranteed; use forEachOrdered if order matters
  - Use parallel when: large data, compute-heavy operations, independent tasks
  - Avoid parallel when: small datasets (overhead > benefit), I/O operations, sequential dependencies

  // Parallel sum:
  long sum = LongStream.rangeClosed(1, 1_000_000).parallel().sum();

STREAM VS COLLECTION
---------------------
  | Aspect          | Collection              | Stream                      |
  |-----------------|-------------------------|------------------------------|
  | Storage         | Stores elements in RAM  | Does not store elements      |
  | Evaluation      | Eager                   | Lazy (intermediate ops)      |
  | Reuse           | Can iterate many times  | Single-use; recreate needed  |
  | Modification    | Can add/remove          | Cannot modify source         |
  | Parallelism     | External (manual)       | Built-in (.parallel())       |
  | Primary use     | Hold and access data    | Process and transform data   |

COMMON INTERVIEW QUESTIONS
---------------------------
Q: What is the difference between map and flatMap?
A: map applies a function to each element and returns a Stream<R>. flatMap applies
   a function that returns a Stream<R> for each element, then flattens those streams
   into one. Use flatMap when each element maps to zero or more elements:
   Stream<List<T>> → flatMap → Stream<T>.

Q: Explain lazy evaluation in streams. Why does it matter?
A: Intermediate operations (filter, map, sorted, etc.) are lazy — they don't execute
   until a terminal operation is invoked. The pipeline is assembled as a recipe of
   operations and then executed all at once. This matters for (1) short-circuit
   optimization: if anyMatch finds a result early, the rest of the stream isn't
   processed; (2) infinite streams: Stream.iterate produces an infinite sequence, but
   limit() makes it practical by stopping early; (3) efficiency: elements are processed
   one at a time through the entire pipeline, not stage by stage.

Q: What is the difference between findFirst and findAny?
A: findFirst returns the first element in encounter order (important for ordered sources
   like lists). findAny returns any element — in parallel streams it picks whichever
   element is found first by any thread, which is faster. For sequential streams, both
   typically return the first element, but findAny makes no guarantee.

Q: When should you use parallel streams?
A: Parallel streams help when: the dataset is large (hundreds of thousands+ elements),
   operations are CPU-bound and independent, and the source supports efficient splitting
   (ArrayList is good; LinkedList is not). Avoid parallel streams for: small data
   (thread coordination overhead exceeds benefit), I/O-bound tasks (use async/reactive
   instead), operations with shared mutable state, or operations requiring ordering.
