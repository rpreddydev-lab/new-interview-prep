JAVA 9 TO 11 FEATURES
======================

JAVA 9
-------

  1. JAVA PLATFORM MODULE SYSTEM (JPMS) — "Project Jigsaw"
  ----------------------------------------------------------
  The module system introduces modules — named, self-describing collections of
  code with declared dependencies and exports.

  // module-info.java (in root of module source tree)
  module com.myapp.core {
      requires java.sql;                   // dependency on another module
      requires transitive java.logging;    // transitive — callers of core also get logging
      exports com.myapp.core.api;          // only this package is visible to others
      opens com.myapp.core.model;          // allows reflection (needed for frameworks)
      uses com.myapp.core.spi.Plugin;      // ServiceLoader consumer declaration
      provides com.myapp.core.spi.Plugin   // ServiceLoader provider declaration
          with com.myapp.core.DefaultPlugin;
  }

  Benefits:
  - Strong encapsulation: internal packages inaccessible without exports
  - Reliable configuration: missing/cyclic dependencies caught at startup, not runtime
  - Smaller runtimes: jlink can create custom JREs with only required modules

  Key module types:
  - Named module: has module-info.java
  - Automatic module: a jar on the module path without module-info (name from jar filename)
  - Unnamed module: classpath content — can read all, not readable by named modules

  2. JShell (REPL)
  -----------------
  Interactive Java REPL for quick experimentation without writing full programs:
    $ jshell
    jshell> var x = 42
    jshell> x * 2 + " is the answer"

  3. PRIVATE INTERFACE METHODS
  -----------------------------
  Allows sharing helper code between default methods in an interface without exposing it:

  interface Shape {
      double area();
      default String describe() { return "Shape with area: " + format(area()); }
      private String format(double d) { return String.format("%.2f", d); }
  }

  4. COLLECTION FACTORY METHODS (List.of, Set.of, Map.of)
  --------------------------------------------------------
  Concise, unmodifiable collection creation:

  List<String> list = List.of("a", "b", "c");         // unmodifiable, null-disallowed
  Set<Integer> set = Set.of(1, 2, 3);
  Map<String, Integer> map = Map.of("one", 1, "two", 2);
  Map<String, Integer> map2 = Map.ofEntries(
      Map.entry("one", 1),
      Map.entry("two", 2)
  );
  // Collections.unmodifiableList wraps; List.of is natively unmodifiable

  5. STREAM ADDITIONS
  --------------------
  takeWhile(Predicate): take elements while condition holds, stop at first failure:
    Stream.of(1,2,3,4,5,1).takeWhile(n -> n < 4).collect(...) // [1,2,3]
  dropWhile(Predicate): inverse of takeWhile
  iterate(seed, hasNext, next): bounded infinite stream (like for-loop):
    Stream.iterate(0, n -> n < 10, n -> n + 2) // [0,2,4,6,8]
  Stream.ofNullable(value): empty stream if null, stream of one if not:
    Stream.ofNullable(null).count() // 0

  6. Optional ADDITIONS (Java 9)
  --------------------------------
  optional.ifPresentOrElse(consumer, runnable);
  optional.or(() -> Optional.of("fallback"));
  optional.stream();  // Stream of 0 or 1 elements

  7. REACTIVE STREAMS (java.util.concurrent.Flow)
  -------------------------------------------------
  Standardized Publisher/Subscriber/Subscription/Processor interfaces for reactive programming.
  Integrated with CompletableFuture ecosystem.

JAVA 10
--------

  1. LOCAL VARIABLE TYPE INFERENCE (var)
  ---------------------------------------
  var allows the compiler to infer the type of local variables:

  var list = new ArrayList<String>();   // inferred as ArrayList<String>
  var map = Map.of("a", 1);            // inferred as Map<String,Integer>
  var x = 42;                           // inferred as int

  Rules and restrictions:
  - Only for local variables with an initializer
  - NOT for fields, method parameters, or return types
  - Cannot be var x;  (null initializer — no type to infer)
  - Cannot be var x = null;  (ambiguous type)
  - Type is fixed at compile time — no dynamic typing; still statically typed

  // Good use — clarifies instead of obscures:
  var entries = new HashMap<String, List<Integer>>();  // cleaner than full generic

  // Bad use — hides important type information:
  var result = someOpaqueMmethod();  // reader doesn't know the type

  2. Collectors.toUnmodifiableList/Set/Map
  -----------------------------------------
  Stream.collect(Collectors.toUnmodifiableList());
  Stream.collect(Collectors.toUnmodifiableMap(k, v));

  3. Optional.orElseThrow() (no arg)
  ------------------------------------
  Previously: orElseThrow(NoSuchElementException::new)
  Now:        orElseThrow()  // throws NoSuchElementException

JAVA 11 (LTS)
--------------

  1. NEW STRING METHODS
  ----------------------
  "  hello  ".strip()           // like trim() but Unicode-aware (removes all whitespace)
  "  hello  ".stripLeading()    // remove leading whitespace
  "  hello  ".stripTrailing()   // remove trailing whitespace
  "hello".isBlank()             // true if empty or only whitespace
  "a\nb\nc".lines()             // Stream<String> of lines
  "java".repeat(3)              // "javajavajava"

  2. HTTP CLIENT (java.net.http)
  --------------------------------
  New standard HTTP client supporting HTTP/1.1, HTTP/2, WebSocket, and async requests:

  HttpClient client = HttpClient.newBuilder()
      .version(HttpClient.Version.HTTP_2)
      .connectTimeout(Duration.ofSeconds(10))
      .build();

  HttpRequest request = HttpRequest.newBuilder()
      .uri(URI.create("https://api.example.com/data"))
      .header("Accept", "application/json")
      .GET()
      .build();

  // Synchronous:
  HttpResponse<String> response = client.send(request, BodyHandlers.ofString());
  System.out.println(response.statusCode());  // 200
  System.out.println(response.body());

  // Asynchronous:
  CompletableFuture<HttpResponse<String>> future =
      client.sendAsync(request, BodyHandlers.ofString());
  future.thenApply(HttpResponse::body).thenAccept(System.out::println);

  3. FILES UTILITY METHODS (Java 11)
  ------------------------------------
  Path.of("file.txt");                          // equivalent to Paths.get()
  Files.readString(Path.of("file.txt"));        // read entire file to String
  Files.writeString(Path.of("out.txt"), "Hello");
  Files.readString(path, StandardCharsets.UTF_8);

  4. var IN LAMBDA PARAMETERS (Java 11)
  ---------------------------------------
  // Allows @NotNull annotation on lambda parameters:
  list.stream()
      .map((@NotNull var s) -> s.toUpperCase())
      .collect(Collectors.toList());

  5. Predicate.not (Java 11)
  ---------------------------
  list.stream().filter(Predicate.not(String::isBlank));

  6. RUNNING JAVA PROGRAMS DIRECTLY (Java 11)
  ---------------------------------------------
  Can run a single-file Java program without explicitly compiling first:
    $ java HelloWorld.java  // compiles in-memory and runs

COMMON INTERVIEW QUESTIONS
---------------------------
Q: What is the Java module system and why was it introduced?
A: JPMS (Project Jigsaw, Java 9) introduces named modules — units of code with explicit
   dependencies (requires) and encapsulated exports. It was introduced to: (1) fix the
   "JAR hell" where classpath ordering caused unpredictable behavior; (2) enforce strong
   encapsulation of internal JDK APIs (sun.misc.Unsafe, etc.); (3) enable smaller runtime
   images via jlink by including only the modules an application actually uses; and
   (4) detect missing/circular dependencies at application startup instead of runtime.

Q: What is var and how does it work?
A: var (Java 10) enables local variable type inference — the compiler deduces the type
   from the right-hand side expression at compile time. The variable is still statically
   typed; var is syntactic sugar. Restrictions: only for local variables with initializers,
   not for fields or method signatures. Best used to reduce redundancy with complex generic
   types. Avoid when the inferred type is non-obvious and would confuse readers.

Q: What are the new String methods in Java 11?
A: strip() and its variants are Unicode-aware versions of trim() (trim only removes ASCII
   whitespace, character <= 32). isBlank() returns true if the string is empty or contains
   only whitespace. lines() returns a Stream<String> from a multi-line string. repeat(n)
   returns the string repeated n times.

Q: How does the Java 11 HttpClient differ from the old HttpURLConnection?
A: HttpClient supports HTTP/2, async (non-blocking) requests via CompletableFuture,
   WebSocket, fluent builder pattern, and is easier to use. HttpURLConnection only supports
   HTTP/1.1, is synchronous only, has a verbose API, and lacks built-in HTTP/2 or async
   support. The new client is the modern standard replacement.
