COLLECTIONS QUESTIONS
=====================

Q1: What is the difference between ArrayList and LinkedList?
------------------------------------------------------------
A:
  ArrayList:
  - Backed by a resizable array (Object[])
  - O(1) random access by index (get/set)
  - O(n) insert/delete in the middle (must shift elements)
  - O(1) amortized add at end (grows by 50% when full)
  - Better cache performance (contiguous memory)
  - Prefer for: read-heavy, index access, end-only modification

  LinkedList:
  - Doubly-linked list; each node holds prev/next references
  - O(n) random access (must traverse from head or tail)
  - O(1) insert/delete at head or tail; O(n) in middle (traverse + O(1) node manipulation)
  - Higher memory per element (two additional references per node)
  - Also implements Deque (use as queue/stack)
  - Prefer for: frequent insertion/removal at both ends; implementing queue/deque

  In practice: ArrayList is almost always preferred. LinkedList's O(1) insert/remove
  only helps at known nodes; getting to the node is O(n). CPU cache effects often make
  ArrayList faster for iteration too.

Q2: How does HashMap work internally?
--------------------------------------
A:
  Internal structure: an array of "buckets" (Node[]) — default capacity 16.
  Each bucket is a linked list (or red-black tree when chain length > 8, Java 8+).

  put(key, value) steps:
  1. Compute key.hashCode() — apply secondary hash spreading (key.hashCode() XOR its upper 16 bits)
  2. Index = hash & (capacity - 1) — maps to bucket
  3. If bucket empty: insert new Node
  4. If bucket has entries: traverse chain comparing with .equals()
     - Key found (equals) → update value
     - Not found → append new Node
  5. If chain length > 8 AND table.length >= 64 → treeify (convert to red-black tree)
  6. After insertion: check load factor (default 0.75). If size > capacity * 0.75 → resize:
     double capacity, rehash all entries (expensive!)

  get(key) steps:
  1. Compute hash and bucket index
  2. Traverse bucket's chain/tree using .equals() to find the key
  3. Return value or null if not found

  Time complexity: O(1) average; O(n) worst case (all keys hash to same bucket; unlikely with good hashCode)
  Java 8 improvement: O(log n) worst case for a bucket when tree-ified.

  Key points:
  - equals() and hashCode() MUST be consistent
  - Key must be effectively immutable (mutating a key after insertion corrupts the map)
  - Not thread-safe — use ConcurrentHashMap for concurrent access

Q3: What is the difference between HashMap and ConcurrentHashMap?
----------------------------------------------------------------
A:
  HashMap:
  - Not thread-safe — concurrent modification without synchronization causes corruption
  - null keys and null values allowed (one null key)
  - No synchronization overhead → fastest single-threaded performance

  ConcurrentHashMap (Java 8+):
  - Thread-safe without locking the entire map
  - Java 8 implementation: synchronized on individual bucket nodes during updates
    (head of each bucket chain is the lock) — highly concurrent
  - Lock-free reads using volatile for field reads
  - Does NOT allow null keys or null values (null is ambiguous: key absent vs value=null)
  - computeIfAbsent, merge, compute — atomic compound operations
  - size() is approximate (not strongly consistent); use mappingCount() if precision matters

  Synchronized Collections alternatives:
  Collections.synchronizedMap(map) — wraps the entire map in a lock → coarse-grained, slower
  ConcurrentHashMap — fine-grained locking → much better concurrency

  Use ConcurrentHashMap whenever a map is accessed from multiple threads.

Q4: How do HashSet and TreeSet differ?
--------------------------------------
A:
  HashSet:
  - Backed by a HashMap (values are dummy Object instances)
  - O(1) average add/remove/contains
  - No ordering guarantee — iteration order is arbitrary
  - Allows one null element
  - Uses equals() + hashCode() for uniqueness

  TreeSet:
  - Backed by a TreeMap (red-black tree)
  - O(log n) add/remove/contains
  - Elements maintained in sorted order (natural ordering or provided Comparator)
  - No null elements (Comparable.compareTo(null) would throw NPE)
  - Additional navigation methods: first(), last(), floor(), ceiling(), headSet(), tailSet()
  - Use when you need sorted set operations or range queries

  LinkedHashSet:
  - Backed by a LinkedHashMap
  - O(1) operations (like HashSet)
  - Maintains INSERTION ORDER during iteration

Q5: What is the difference between fail-fast and fail-safe iterators?
---------------------------------------------------------------------
A:
  Fail-fast iterators (ArrayList, HashMap iterators):
  - Track a modCount field; if the collection is structurally modified during iteration
    (outside the iterator's own remove()), immediately throw ConcurrentModificationException
  - Detects concurrent modification quickly (but not reliably — it's best-effort)
  - Not safe for concurrent modification even in single-threaded code (except via iterator.remove())

  Fail-safe iterators (ConcurrentHashMap, CopyOnWriteArrayList iterators):
  - Operate on a snapshot / weakly consistent view of the collection
  - Never throw ConcurrentModificationException
  - May not reflect modifications made after iterator was created
  - CopyOnWriteArrayList: iterator operates on a copy of the array made at iterator creation

  Best practice: if you must modify a collection while iterating, use iterator.remove()
  (for single-threaded code) or switch to a concurrent collection with fail-safe iteration.

Q6: When would you use LinkedHashMap vs HashMap?
------------------------------------------------
A:
  HashMap: no ordering guarantee — iterate in arbitrary order. Use when insertion/access
  order doesn't matter. Fastest.

  LinkedHashMap:
  - Maintains a doubly-linked list alongside the hash table
  - Two modes:
    1. Insertion order (default): iteration reflects the order keys were first inserted
    2. Access order: most-recently-accessed entry comes last (enable with constructor arg)

  Common use case for access-order LinkedHashMap: build an LRU (Least Recently Used) cache.
  Override removeEldestEntry() to evict old entries when size exceeds threshold:

  Map<K, V> lruCache = new LinkedHashMap<>(16, 0.75f, true) {
      @Override
      protected boolean removeEldestEntry(Map.Entry<K, V> eldest) {
          return size() > MAX_SIZE;  // evict when over capacity
      }
  };

Q7: What is the difference between Comparable and Comparator?
-------------------------------------------------------------
A:
  Comparable<T> (java.lang.):
  - Interface with single method: int compareTo(T other)
  - Defines the NATURAL ordering of a class (built into the class itself)
  - A class implements it to be self-comparable
  - Used by TreeMap/TreeSet by default; Arrays.sort() / Collections.sort() without a Comparator

  Comparator<T> (java.util.):
  - Functional interface: int compare(T o1, T o2)
  - Defines an EXTERNAL ordering — can compare any two objects of any type
  - Multiple different orderings for the same class can be defined as separate Comparators
  - Java 8: Comparator.comparing(), thenComparing(), reversed() — composable

  When to use:
  - Comparable: you control the class and there's a clear, natural order (Integer, String, Date)
  - Comparator: you don't control the class; you need multiple sort orders; comparing on derived properties

  Example:
  // Comparable — natural order by age
  class Person implements Comparable<Person> {
      public int compareTo(Person other) { return this.age - other.age; }
  }

  // Comparators — multiple orderings
  Comparator<Person> byName = Comparator.comparing(Person::getName);
  Comparator<Person> byNameThenAge = Comparator.comparing(Person::getName).thenComparingInt(Person::getAge);

Q8: What is the Java Collections Framework hierarchy?
-----------------------------------------------------
A:
  Iterable
  └── Collection
      ├── List (ordered, allows duplicates)
      │   ├── ArrayList
      │   ├── LinkedList
      │   └── Vector → Stack
      ├── Set (unique elements)
      │   ├── HashSet → LinkedHashSet
      │   ├── TreeSet (SortedSet, NavigableSet)
      │   └── EnumSet
      └── Queue / Deque
          ├── LinkedList (also implements Deque)
          ├── ArrayDeque
          ├── PriorityQueue
          └── BlockingQueue family (ConcurrentLinkedQueue, LinkedBlockingQueue, etc.)

  Map (NOT part of Collection):
  ├── HashMap → LinkedHashMap
  ├── TreeMap (SortedMap, NavigableMap)
  ├── Hashtable → Properties
  ├── EnumMap
  └── ConcurrentHashMap

  Key interfaces:
  - List: positional access (get(i)), ordered, duplicates OK
  - Set: uniqueness guarantee, unordered (HashSet) or ordered (TreeSet)
  - Queue: FIFO ordering; offer/poll/peek (null-safe) vs add/remove/element (exception-throwing)
  - Deque: double-ended queue; stack and queue operations
  - Map: key-value pairs, unique keys
