CREATING THREADS: RUNNABLE, CALLABLE, THREAD
==============================================

THREE WAYS TO CREATE A THREAD
-------------------------------
  1. Extend Thread
  2. Implement Runnable
  3. Implement Callable<V> (with ExecutorService)

1. EXTENDING THREAD
---------------------
  public class MyThread extends Thread {
      @Override
      public void run() {
          System.out.println("Running in: " + Thread.currentThread().getName());
      }
  }

  MyThread t = new MyThread();
  t.start();   // ← start(), NOT run() — run() executes in the CURRENT thread!

  Limitations:
  - Java only has single inheritance — extending Thread blocks other inheritance
  - Tightly couples task logic to thread management
  - Cannot return a value or throw checked exceptions

2. IMPLEMENTING RUNNABLE
--------------------------
  public class MyTask implements Runnable {
      @Override
      public void run() {
          System.out.println("Task running in: " + Thread.currentThread().getName());
      }
  }

  Thread t = new Thread(new MyTask());
  t.start();

  // Or with lambda (Runnable is a functional interface):
  Thread t2 = new Thread(() -> System.out.println("Lambda task"));
  t2.start();

  // With ExecutorService (preferred):
  ExecutorService executor = Executors.newFixedThreadPool(4);
  executor.submit(() -> System.out.println("Submitted runnable"));
  executor.shutdown();

  Advantages over extending Thread:
  ✅ Separation of task logic from thread management
  ✅ Works with thread pools (ExecutorService)
  ✅ Can implement other interfaces

  Limitations:
  - run() returns void — cannot return a result
  - run() cannot throw checked exceptions

3. IMPLEMENTING CALLABLE<V>
-----------------------------
  Callable is like Runnable but:
  - Returns a value (generic type V)
  - Can throw checked exceptions

  public class SumTask implements Callable<Integer> {
      private final int[] data;
      public SumTask(int[] data) { this.data = data; }

      @Override
      public Integer call() throws Exception {
          int sum = 0;
          for (int n : data) sum += n;
          return sum;
      }
  }

  // Must be submitted to ExecutorService — returns a Future<V>:
  ExecutorService executor = Executors.newFixedThreadPool(2);

  Future<Integer> future = executor.submit(new SumTask(new int[]{1,2,3,4,5}));

  try {
      Integer result = future.get();           // blocks until done
      Integer result2 = future.get(5, TimeUnit.SECONDS); // with timeout
      System.out.println("Sum = " + result);
  } catch (InterruptedException e) {
      Thread.currentThread().interrupt();
  } catch (ExecutionException e) {
      System.err.println("Task threw: " + e.getCause());
  } catch (TimeoutException e) {
      future.cancel(true);  // cancel if taking too long
  } finally {
      executor.shutdown();
  }

FUTURE<V> METHODS
------------------
  Method                          | Description
  --------------------------------|---------------------------------------------
  get()                           | Block until result available; rethrows as ExecutionException
  get(long, TimeUnit)             | Block with timeout; throws TimeoutException
  cancel(boolean mayInterrupt)    | Attempt to cancel; if running, interrupt if true
  isCancelled()                   | True if successfully cancelled
  isDone()                        | True if completed (normally, cancelled, or exception)

THREAD NAMING AND METADATA
-----------------------------
  Thread t = new Thread(task, "worker-thread-1");  // name in constructor
  t.setName("custom-name");
  t.getName();
  t.getId();
  t.getPriority();
  t.isDaemon();
  Thread.currentThread();  // get the currently executing thread

THREAD FACTORY PATTERN
------------------------
  For creating consistently configured threads (name, daemon, priority):

  ThreadFactory factory = new ThreadFactory() {
      private final AtomicInteger count = new AtomicInteger(0);
      @Override
      public Thread newThread(Runnable r) {
          Thread t = new Thread(r);
          t.setName("custom-worker-" + count.incrementAndGet());
          t.setDaemon(true);
          t.setPriority(Thread.NORM_PRIORITY);
          return t;
      }
  };

  // Or with Java 19+ Thread.Builder (preferred):
  Thread t = Thread.ofPlatform()
      .name("worker-", 0)
      .daemon(true)
      .start(() -> doWork());

  // Virtual thread (Java 21+):
  Thread vt = Thread.ofVirtual()
      .name("virtual-worker")
      .start(() -> doWork());

RUNNABLE vs CALLABLE vs THREAD
---------------------------------
  Aspect                | Thread         | Runnable         | Callable<V>
  ----------------------|----------------|------------------|-----------------------
  Return value          | None           | None (void)      | Yes (generic V)
  Checked exceptions    | No             | No               | Yes (throws Exception)
  Works with pools      | No             | Yes              | Yes
  Functional interface  | No             | Yes (lambda OK)  | Yes (lambda OK)
  Result via Future     | No             | No (unless wrapped)| Yes (Future<V>)
  Inheritance needed    | Yes (extends)  | No               | No

COMMON INTERVIEW QUESTIONS
---------------------------
Q: What is the difference between Runnable and Callable?
A: Both represent a task to execute. Runnable's run() returns void and cannot throw
   checked exceptions. Callable's call() returns a value (type parameter V) and can
   throw checked exceptions. Callable is used with ExecutorService.submit(), which
   returns a Future<V> to retrieve the result asynchronously.

Q: Why should you implement Runnable rather than extend Thread?
A: Separation of concerns — Runnable separates the task logic from thread management.
   It also avoids Java's single-inheritance limitation (if you extend Thread, you can't
   extend another class). Runnable tasks work cleanly with thread pools (ExecutorService),
   while Thread subclasses do not. The recommended pattern is to never extend Thread
   directly.

Q: What is the difference between start() and run()?
A: start() creates a NEW OS thread and executes run() on that thread.
   Calling run() directly executes the method on the CURRENT thread — no new thread
   is created. This is a very common interview trap. Always call start() to get actual
   concurrency. Calling start() twice on the same Thread throws IllegalThreadStateException.

Q: What is Future.get() and what exceptions can it throw?
A: Future.get() blocks the calling thread until the task completes, then returns the result.
   It can throw: InterruptedException (if the waiting thread is interrupted),
   ExecutionException (wraps any exception thrown inside the Callable's call() method),
   and TimeoutException (if using the timed variant get(timeout, unit) and the task
   doesn't finish in time). The original task exception is wrapped in ExecutionException —
   access it with e.getCause().
