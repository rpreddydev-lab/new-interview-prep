THREAD LIFECYCLE AND STATES
==============================

THE SIX THREAD STATES (java.lang.Thread.State)
------------------------------------------------
  NEW           — Thread object created but start() not yet called
  RUNNABLE      — start() called; thread is running OR ready to run (waiting for CPU)
  BLOCKED       — waiting to acquire an intrinsic lock (synchronized block/method)
  WAITING       — waiting indefinitely for another thread's signal (Object.wait(), join())
  TIMED_WAITING — waiting with a timeout (sleep(), wait(timeout), join(timeout), parkNanos)
  TERMINATED    — run() method has completed (normally or via exception)

STATE DIAGRAM
--------------
                         start()
  NEW ─────────────────────────────────► RUNNABLE
                                           │  ▲
                  synchronized(lock) {     │  │ lock acquired
                  // lock contended        │  │
                  ──────────────────────► BLOCKED
                                           │
                  Object.wait() ──────────►│
                  thread.join() ──────────►├──► WAITING
                  LockSupport.park() ─────►│
                                           │
                  sleep(n) ───────────────►│
                  wait(n) ────────────────►├──► TIMED_WAITING
                  join(n) ────────────────►│
                  parkNanos(n) ───────────►│
                                           │
                  run() returns ──────────►│
                  run() throws  ──────────►▼
                                       TERMINATED

CHECKING THREAD STATE PROGRAMMATICALLY
-----------------------------------------
  Thread t = new Thread(() -> {
      try { Thread.sleep(1000); } catch (InterruptedException e) {}
  });
  System.out.println(t.getState());  // NEW
  t.start();
  System.out.println(t.getState());  // RUNNABLE or TIMED_WAITING
  t.join();
  System.out.println(t.getState());  // TERMINATED

STATE DETAILS
--------------
  NEW:
    Thread object exists. No OS thread allocated yet.
    Calling start() twice throws IllegalThreadStateException.

  RUNNABLE:
    The JVM umbrella state for both "actually running on CPU" and "ready in run queue."
    Java does not distinguish between running and ready-to-run.

  BLOCKED:
    Thread tried to enter a synchronized block/method but the intrinsic lock is held
    by another thread. Thread is parked by the OS until the lock is released.
    BLOCKED is specifically for intrinsic locks (synchronized). Waiting on a
    java.util.concurrent.Lock shows as WAITING, not BLOCKED.

  WAITING:
    Thread is indefinitely suspended until another thread takes a specific action:
    - Object.wait()            → until Object.notify() / notifyAll()
    - Thread.join()            → until the target thread terminates
    - LockSupport.park()       → until LockSupport.unpark(thread) or interrupt

  TIMED_WAITING:
    Like WAITING but with a timeout — the thread wakes automatically after the duration:
    - Thread.sleep(millis)
    - Object.wait(millis)
    - Thread.join(millis)
    - LockSupport.parkNanos(nanos)
    - LockSupport.parkUntil(deadline)

  TERMINATED:
    Thread has finished execution. Cannot be restarted (start() throws IllegalThreadStateException).
    Thread object still exists — its state can be inspected — but the OS thread is gone.

THREAD INTERRUPTION
---------------------
  Interruption is a cooperative mechanism to request a thread stop what it's doing.
  The interrupted thread decides how/whether to respond.

  t.interrupt()                 — set the interrupt flag on thread t
  Thread.interrupted()          — checks AND CLEARS the current thread's flag
  thread.isInterrupted()        — checks WITHOUT clearing the flag

  How blocking methods respond to interruption:
    sleep(), wait(), join()     → throw InterruptedException and CLEAR the flag
    LockSupport.park()          → returns (without exception), flag remains set

  Correct pattern for handling InterruptedException:
    // Option 1: Let it propagate
    public void doWork() throws InterruptedException {
        Thread.sleep(1000);  // just declare throws
    }

    // Option 2: Restore interrupted status (don't swallow silently)
    public void doWork() {
        try {
            Thread.sleep(1000);
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt(); // restore the flag
            // now handle graceful shutdown
        }
    }

    // ❌ NEVER DO THIS — silently swallows the interrupt:
    catch (InterruptedException e) { /* ignore */ }

THREAD JOIN
------------
  thread.join() — current thread waits until the target thread TERMINATES.
  Useful for coordinating results from spawned threads.

  Thread worker = new Thread(() -> heavyComputation());
  worker.start();
  // main thread can do other work here...
  worker.join();        // wait for worker to finish
  worker.join(5000);    // wait at most 5 seconds — timed join

SLEEP vs WAIT
--------------
  Aspect           | Thread.sleep(n)                   | Object.wait(n)
  -----------------|-----------------------------------|---------------------------
  Releases lock?   | NO — holds all locks it owns      | YES — releases object monitor
  Called on        | Thread.sleep(...) (static)        | obj.wait() (on object)
  Woken by         | Timeout / interrupt               | notify()/notifyAll()/timeout/interrupt
  Requires sync?   | No                                | Yes — must own the monitor
  Package          | java.lang.Thread                  | java.lang.Object

COMMON INTERVIEW QUESTIONS
---------------------------
Q: What are the 6 thread states in Java?
A: NEW (created, not started), RUNNABLE (running or ready to run), BLOCKED (waiting
   for a synchronized lock), WAITING (indefinitely waiting for notify/join/park),
   TIMED_WAITING (waiting with a timeout — sleep/wait(n)/join(n)), and TERMINATED (finished).

Q: What is the difference between BLOCKED and WAITING?
A: BLOCKED means the thread is waiting to acquire an intrinsic lock (synchronized keyword).
   WAITING means the thread is waiting for a specific action from another thread
   (Object.wait(), Thread.join(), LockSupport.park()) — no lock contention involved.
   When using java.util.concurrent locks (ReentrantLock), a waiting thread appears
   as WAITING, not BLOCKED.

Q: What happens when you call Thread.sleep()? Does it release locks?
A: Thread.sleep() suspends the current thread for the specified time, putting it in
   TIMED_WAITING state. It does NOT release any locks the thread holds. This is different
   from Object.wait(), which DOES release the monitor lock. Calling sleep() inside a
   synchronized block keeps the lock held for the entire sleep duration.

Q: How does thread interruption work?
A: Interruption is cooperative. Calling t.interrupt() sets an interrupt flag on the
   target thread. If the thread is blocked in sleep(), wait(), or join(), it throws
   InterruptedException and clears the flag. Otherwise the flag stays set until the
   thread checks it with isInterrupted() or interrupted(). The key rule: never silently
   swallow InterruptedException — either propagate it or restore the flag with
   Thread.currentThread().interrupt().
