BLOCKINGQUEUE AND PRODUCER-CONSUMER PATTERN
=============================================

WHY BLOCKINGQUEUE?
-------------------
  The producer-consumer pattern requires:
  - A shared buffer with capacity limits
  - Producers to block when full
  - Consumers to block when empty
  - Thread-safe handoff

  BlockingQueue<E> provides all of this out-of-the-box — no manual wait/notify needed.

BLOCKINGQUEUE INTERFACE
------------------------
  Key methods (four groups):

  Group          | Throws exception | Returns special val | Blocks     | Times out
  ---------------|------------------|---------------------|------------|-------------------
  Insert         | add(e)           | offer(e)            | put(e)     | offer(e, t, unit)
  Remove head    | remove()         | poll()              | take()     | poll(t, unit)
  Examine head   | element()        | peek()              | —          | —

  put(e)   — block until space is available, then insert
  take()   — block until an element is available, then remove and return it
  offer(e, t, unit) — try insert with timeout, return true/false
  poll(t, unit)     — try remove with timeout, return null on timeout

IMPLEMENTATIONS
----------------
  ArrayBlockingQueue(int capacity):
    - Bounded FIFO backed by array
    - Optional fairness (queue waiting producers/consumers in FIFO order)
    - Fixed capacity, configured at construction

  LinkedBlockingQueue(int capacity):
    - Bounded or unbounded (default Integer.MAX_VALUE — caution!)
    - Separate locks for head and tail → higher throughput than ArrayBlockingQueue
    - Good for high-throughput producer-consumer

  PriorityBlockingQueue:
    - Unbounded, elements sorted by natural order or Comparator
    - take() returns highest-priority element
    - No capacity limit — producers never block

  DelayQueue<E extends Delayed>:
    - Elements become available after a delay
    - Used for scheduling: task schedulers, retries, cache expiry

  SynchronousQueue:
    - ZERO capacity — every insert blocks until a consumer is ready (hand-off queue)
    - High-performance direct producer→consumer transfer
    - Used internally by Executors.newCachedThreadPool()

  LinkedTransferQueue (Java 7+):
    - Combines LinkedBlockingQueue and SynchronousQueue
    - transfer() — blocks until consumer receives; offer() — non-blocking

CLASSIC PRODUCER-CONSUMER
---------------------------
  BlockingQueue<Task> queue = new ArrayBlockingQueue<>(100); // bounded buffer

  // Producer thread(s):
  Runnable producer = () -> {
      while (true) {
          try {
              Task task = generateTask();
              queue.put(task);            // blocks if queue full (100 items)
              System.out.println("Produced: " + task);
          } catch (InterruptedException e) {
              Thread.currentThread().interrupt();
              break;
          }
      }
  };

  // Consumer thread(s):
  Runnable consumer = () -> {
      while (true) {
          try {
              Task task = queue.take();   // blocks if queue empty
              process(task);
              System.out.println("Consumed: " + task);
          } catch (InterruptedException e) {
              Thread.currentThread().interrupt();
              break;
          }
      }
  };

  ExecutorService pool = Executors.newFixedThreadPool(6);
  pool.submit(producer);
  pool.submit(producer);  // 2 producers
  pool.submit(consumer);
  pool.submit(consumer);
  pool.submit(consumer);
  pool.submit(consumer);  // 4 consumers

POISON PILL SHUTDOWN
---------------------
  A common pattern to signal consumers to stop is the POISON PILL:

  final Task POISON = new Task("POISON");

  // Shutdown: send one poison pill per consumer thread
  for (int i = 0; i < NUM_CONSUMERS; i++) {
      queue.put(POISON);
  }

  // Consumer:
  while (true) {
      Task task = queue.take();
      if (task == POISON) break;  // identity comparison
      process(task);
  }

DELAYQUEUE EXAMPLE (SCHEDULED TASK EXECUTION)
-----------------------------------------------
  public class DelayedTask implements Delayed {
      private final String name;
      private final long executeAt; // System.nanoTime() + delay

      public DelayedTask(String name, long delayMs) {
          this.name = name;
          this.executeAt = System.nanoTime() + delayMs * 1_000_000L;
      }

      @Override
      public long getDelay(TimeUnit unit) {
          return unit.convert(executeAt - System.nanoTime(), TimeUnit.NANOSECONDS);
      }

      @Override
      public int compareTo(Delayed other) {
          return Long.compare(this.getDelay(NANOSECONDS), other.getDelay(NANOSECONDS));
      }
  }

  DelayQueue<DelayedTask> dq = new DelayQueue<>();
  dq.offer(new DelayedTask("cleanup", 5000));   // available after 5s
  dq.offer(new DelayedTask("report", 1000));    // available after 1s

  DelayedTask task = dq.take();  // blocks until earliest-expiring task is ready

BLOCKINGQUEUE vs MANUAL wait/notify
--------------------------------------
  Aspect               | Manual wait/notify          | BlockingQueue
  ---------------------|-----------------------------|---------------------------------
  Thread safety        | Must implement carefully     | Built-in, well-tested
  Blocking behavior    | wait() + notify()            | put() / take() built-in
  Code verbosity       | High                        | Very low
  Error risk           | High (spurious wakeup, etc.)| Low
  Capacity control     | Manual                      | Built-in (bounded queue)
  Fairness             | Hard to guarantee           | Optional fair mode
  Multiple producers   | Complex                     | Just call put()

COMMON INTERVIEW QUESTIONS
---------------------------
Q: What is the difference between put() and offer() in BlockingQueue?
A: put(e) blocks indefinitely until space is available. offer(e) returns immediately
   with false if the queue is full (non-blocking). offer(e, t, unit) attempts for up to
   the given timeout before returning false. Use put() for true blocking producer behavior,
   offer() for non-blocking or time-limited attempts.

Q: What is a SynchronousQueue?
A: SynchronousQueue has zero capacity — it's a pure hand-off mechanism. A put() blocks
   until another thread is ready to take(), and vice versa. Each producer directly
   "hands off" to a consumer. It's used by Executors.newCachedThreadPool() so that
   tasks are handed directly to idle threads without queueing. Extremely low latency
   for direct transfer, but provides no buffering.

Q: How do you gracefully stop consumer threads that are blocked on take()?
A: Use the poison pill pattern: add a sentinel value to the queue (one per consumer thread).
   Consumers check for the sentinel and exit their loop when they receive it. Alternatively,
   use offer() instead of take() with a short timeout and check an AtomicBoolean stop flag:
     while (!stopped.get()) {
         Task t = queue.poll(100, MILLISECONDS);
         if (t != null) process(t);
     }
   This avoids blocking indefinitely, allowing clean shutdown checks.
