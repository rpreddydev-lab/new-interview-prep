================================================================
  INTERVAL / RANGE STRUCTURES
================================================================

----------------------------------------------------------------
CORE INTERVAL PATTERNS
----------------------------------------------------------------
An interval is a pair [start, end] representing a range.

  Common tasks:
    1. Merge overlapping intervals
    2. Insert a new interval into a sorted list
    3. Find minimum number of non-overlapping intervals to remove
    4. Check if intervals can be attended (Meeting Rooms)
    5. Find minimum rooms needed (Meeting Rooms II)
    6. Sweep line for more complex range problems

  Two intervals [a, b] and [c, d] overlap if: a <= d && c <= b
  They do NOT overlap if: b < c or d < a

----------------------------------------------------------------
1. MERGE INTERVALS (LC 56)
----------------------------------------------------------------
  Algorithm:
    1. Sort intervals by start time: O(n log n)
    2. Iterate and merge when current overlaps with last merged.

  int[][] merge(int[][] intervals) {
    Arrays.sort(intervals, (a, b) -> a[0] - b[0]);
    List<int[]> result = new ArrayList<>();
    for (int[] interval : intervals) {
      if (result.isEmpty() || result.get(result.size()-1)[1] < interval[0])
        result.add(interval);
      else
        result.get(result.size()-1)[1] = Math.max(result.get(result.size()-1)[1], interval[1]);
    }
    return result.toArray(new int[0][]);
  }

  Time: O(n log n)  Space: O(n)

----------------------------------------------------------------
2. INSERT INTERVAL (LC 57)
----------------------------------------------------------------
  Given a sorted non-overlapping list, insert a new interval.

  int[][] insert(int[][] intervals, int[] newInterval) {
    List<int[]> result = new ArrayList<>();
    int i = 0, n = intervals.length;

    // Add all intervals that come before newInterval
    while (i < n && intervals[i][1] < newInterval[0])
      result.add(intervals[i++]);

    // Merge all overlapping intervals
    while (i < n && intervals[i][0] <= newInterval[1]) {
      newInterval[0] = Math.min(newInterval[0], intervals[i][0]);
      newInterval[1] = Math.max(newInterval[1], intervals[i][1]);
      i++;
    }
    result.add(newInterval);

    // Add remaining intervals
    while (i < n) result.add(intervals[i++]);
    return result.toArray(new int[0][]);
  }

  Time: O(n)  Space: O(n)

----------------------------------------------------------------
3. MEETING ROOMS I (LC 252) -- can one person attend all?
----------------------------------------------------------------
  Sort by start. Check if any interval starts before prev ends.

  boolean canAttend(int[][] intervals) {
    Arrays.sort(intervals, (a, b) -> a[0] - b[0]);
    for (int i = 1; i < intervals.length; i++)
      if (intervals[i][0] < intervals[i-1][1]) return false;
    return true;
  }

  Time: O(n log n)

----------------------------------------------------------------
4. MEETING ROOMS II (LC 253) -- minimum rooms needed
----------------------------------------------------------------
  Two approaches:

  APPROACH A: Separate sorted start/end arrays
    Sort starts and ends independently.
    Use two pointers. A new room is needed when the next start
    is before the earliest end.

  int minMeetingRooms(int[][] intervals) {
    int n = intervals.length;
    int[] starts = new int[n], ends = new int[n];
    for (int i = 0; i < n; i++) { starts[i] = intervals[i][0]; ends[i] = intervals[i][1]; }
    Arrays.sort(starts); Arrays.sort(ends);
    int rooms = 0, endPtr = 0;
    for (int i = 0; i < n; i++) {
      if (starts[i] < ends[endPtr]) rooms++;
      else endPtr++;  // one meeting ended, reuse the room
    }
    return rooms;
  }

  APPROACH B: Priority Queue (min-heap of end times)
    Sort by start. Use min-heap of end times.
    If heap top <= current start: reuse room (poll, add new end).
    Else: need a new room (just add new end).
    Heap size = number of rooms in use = answer.

  int minMeetingRoomsHeap(int[][] intervals) {
    Arrays.sort(intervals, (a, b) -> a[0] - b[0]);
    PriorityQueue<Integer> heap = new PriorityQueue<>();
    for (int[] interval : intervals) {
      if (!heap.isEmpty() && heap.peek() <= interval[0])
        heap.poll();
      heap.offer(interval[1]);
    }
    return heap.size();
  }

  Time: O(n log n)  Space: O(n)

  Both approaches give the same result. Approach A is faster
  in practice (no heap), Approach B is more intuitive.

----------------------------------------------------------------
5. NON-OVERLAPPING INTERVALS (LC 435) -- min removals
----------------------------------------------------------------
  Greedy: sort by END time. Keep intervals with the earliest end.
  (This maximizes remaining space for future intervals.)

  int eraseOverlapIntervals(int[][] intervals) {
    Arrays.sort(intervals, (a, b) -> a[1] - b[1]);  // sort by END
    int count = 0, end = Integer.MIN_VALUE;
    for (int[] interval : intervals) {
      if (interval[0] >= end) end = interval[1];  // keep it
      else count++;  // overlap, remove current (keep the one with smaller end)
    }
    return count;
  }

  Time: O(n log n)  Space: O(1)

  Key insight: sorting by END (not start) is the greedy
  choice. Keeping the interval that ends earliest leaves
  maximum room for future intervals.

----------------------------------------------------------------
6. SWEEP LINE ALGORITHM
----------------------------------------------------------------
Used for: employee free time, calendar intersection,
          the number of concurrent events.

  Create events: for each interval [s, e]:
    Add +1 at time s (event starts)
    Add -1 at time e (event ends)
  Sort events by time (break ties: end before start, or vice versa
  depending on problem -- whether [1,2] and [2,3] conflict).
  Sweep through, tracking running count. Peak = max rooms needed.

  int[][] employeeFreeTime(List<List<int[]>> schedule) {
    List<int[]> events = new ArrayList<>();
    for (List<int[]> emp : schedule)
      for (int[] slot : emp) {
        events.add(new int[]{slot[0], 1});
        events.add(new int[]{slot[1], -1});
      }
    events.sort((a, b) -> a[0] != b[0] ? a[0] - b[0] : a[1] - b[1]);
    int count = 0, prev = -1;
    List<int[]> result = new ArrayList<>();
    for (int[] e : events) {
      if (count == 0 && prev != -1 && prev < e[0])
        result.add(new int[]{prev, e[0]});
      count += e[1];
      if (count == 0) prev = e[0];
    }
    // convert result list to 2D array
    return result.toArray(new int[0][]);
  }

TREEMAP FOR INTERVAL QUERIES
----------------------------------------------------------------
When intervals are dynamically inserted and you need to query
which interval covers a point:
  Use TreeMap<Integer, Integer> where key=start, value=end.

  boolean overlaps(TreeMap<Integer,Integer> map, int start, int end) {
    Integer lo = map.floorKey(start);   // interval starting before 'start'
    Integer hi = map.ceilingKey(start); // interval starting after 'start'
    return (lo != null && map.get(lo) > start)    // lo's end > start
        || (hi != null && hi < end);              // hi starts before end
  }

  Used in: Non-overlapping intervals with dynamic insertions,
           Range Module (LC 715).

COMMON INTERVIEW PROBLEMS
----------------------------------------------------------------

  ---------------------------------------------------------------
  Merge Intervals (56)                  Sort + merge      O(n log n)
  Insert Interval (57)                  Linear scan       O(n)

  Meeting Rooms II (253)                Sort + heap       O(n log n)
  Non-overlapping Intervals (435)       Greedy by end     O(n log n)
  Employee Free Time (759)              Sweep line        O(n log n)

  Minimum Interval Containing Query     Sort+heap         O((n+q) log n)

----------------------------------------------------------------
INTERVIEW QUESTIONS
----------------------------------------------------------------

Q: Why does sorting by END (not start) work for the greedy
   remove-minimum-intervals problem?
A: The goal is to keep the maximum number of non-overlapping
   intervals. This is equivalent to the "Activity Selection"
   problem. The greedy insight: among all intervals that don't
   conflict with what we've kept so far, always pick the one
   that ends earliest. This leaves the most room for future
   intervals. Sorting by end time makes this greedy choice
   easy: process each interval in end-time order and keep it
   if it doesn't overlap with the last kept interval.

Q: What is the difference between Meeting Rooms II heap
   approach and sweep line?
A: Meeting Rooms II heap: Sort by start, simulate assigning
   rooms. Heap holds end times of active meetings.
   O(n log n). Intuitive and direct.
   Sweep line: Create +1/-1 events at start/end times,
   sort, track running count. Peak count = answer.
   O(n log n). More general -- works for arbitrary event-based
   range counting. Sweep line is more flexible when the problem
   involves multiple types of range events.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. Sort key matters: by start for merging/attending,
     by end for activity selection/min removals
  2. For "minimum rooms needed": both heap and sweep line
     work -- heap is more commonly expected in interviews
  3. Overlap check: [a,b] and [c,d] overlap iff a<=d && c<=b
     (remember this inequality; a common source of bugs)
  4. TreeMap is the right tool when intervals are dynamically
     added and range queries must be answered (Range Module)
  5. Sweep line generalizes to: number of events at time t,
     employee free time, any concurrent-range-counting problem
  6. When comparing start/end events in sweep line, ties
     matter: if a meeting ends at t=5 and another starts at t=5,
     do they conflict? Read the problem carefully.
