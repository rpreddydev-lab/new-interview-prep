WHAT IS A MONOTONIC STACK?
----------------------------------------------------------------
A monotonic stack is a stack that maintains its elements in
either strictly increasing or strictly decreasing order from
bottom to top.

  INCREASING (bottom to top): [1, 3, 5, 8]
    Used to find: PREVIOUS GREATER element, NEXT SMALLER element

  DECREASING (bottom to top): [8, 5, 3, 1]
    Used to find: PREVIOUS SMALLER element, NEXT GREATER element

  Key insight:
    When you push a new element, you pop all elements that
    violate the monotonic property. The moment an element is
    POPPED, it means you've found something important:

    Increasing stack:
      When x causes y to be popped: x is the NEXT GREATER of y
      When x is pushed and stack[top] is y: y is PREVIOUS GREATER of x

    Decreasing stack:
      When x causes y to be popped: x is the NEXT SMALLER of y
      When x is pushed and stack[top] is y: y is PREVIOUS SMALLER of x

  Amortized time: O(n) -- each element pushed and popped at most once.

----------------------------------------------------------------
NEXT GREATER ELEMENT (decreasing stack)
----------------------------------------------------------------
  int[] nextGreater(int[] nums) {
    int n = nums.length;
    int[] result = new int[n];
    Arrays.fill(result, -1);
    Stack<Integer> stack = new Stack<>();  // stores INDICES

    for (int i = 0; i < n; i++) {
      while (!stack.isEmpty() && nums[stack.peek()] < nums[i]) {
        result[stack.pop()] = nums[i];  // nums[i] is next greater
      }
      stack.push(i);
    }
    return result;  // remaining in stack have no next greater -> -1
  }

  Important: store INDICES, not values. You need the index to
  store the result and sometimes compute distances.

----------------------------------------------------------------
PREVIOUS SMALLER ELEMENT (increasing stack)
----------------------------------------------------------------
  int[] prevSmaller(int[] nums) {
    int n = nums.length;
    int[] result = new int[n];
    Stack<Integer> stack = new Stack<>();

    for (int i = 0; i < n; i++) {
      while (!stack.isEmpty() && nums[stack.peek()] >= nums[i])
        stack.pop();
      result[i] = stack.isEmpty() ? -1 : nums[stack.peek()];
      stack.push(i);
    }
    return result;
  }

----------------------------------------------------------------
CIRCULAR ARRAY (next greater in circle)
----------------------------------------------------------------
  Trick: traverse the array TWICE (size 2n) using index % n.
  First pass fills the stack; second pass resolves remaining.

  int[] nextGreaterCircular(int[] nums) {
    int n = nums.length;
    int[] result = new int[n];
    Arrays.fill(result, -1);
    Stack<Integer> stack = new Stack<>();

    for (int i = 0; i < 2 * n; i++) {
      while (!stack.isEmpty() && nums[stack.peek()] < nums[i % n])
        result[stack.pop()] = nums[i % n];
      if (i < n) stack.push(i);
    }
    return result;
  }

LARGEST RECTANGLE IN HISTOGRAM (classic pattern)
----------------------------------------------------------------
For each bar, find how far left and right it can extend at
its height. Width = (right boundary - left boundary - 1).

  For each bar i: find:
    left[i]  = index of previous bar that is SHORTER
    right[i] = index of next bar that is SHORTER
    area = height[i] * (right[i] - left[i] - 1)

  Efficient O(n) approach using single increasing stack pass:

  int largestRectangleArea(int[] heights) {
    int n = heights.length;
    int maxArea = 0;
    Stack<Integer> stack = new Stack<>();

    for (int i = 0; i <= n; i++) {
      int h = (i == n) ? 0 : heights[i];  // sentinel 0 at end
      while (!stack.isEmpty() && heights[stack.peek()] > h) {
        int height = heights[stack.pop()];
        int width = stack.isEmpty() ? i : i - stack.peek() - 1;
        maxArea = Math.max(maxArea, height * width);
      }
      stack.push(i);
    }
    return maxArea;
  }

  Why sentinel 0 at end? Flushes remaining stack elements.
  Why i - stack.peek() - 1? The element at stack.peek() is
  the first bar to the left that is SHORTER -> the boundary.

----------------------------------------------------------------
MAXIMAL RECTANGLE IN BINARY MATRIX
----------------------------------------------------------------
Build histogram row by row (cumulative height above current row)
and apply largestRectangleArea to each row.

  For row r:
    height[j] = consecutive 1s above (including row r) if matrix[r][j] == 1
    height[j] = 0 if matrix[r][j] == 0

  Time: O(m * n)  where m = rows, n = columns

----------------------------------------------------------------
TRAP RAIN WATER (two approaches)
----------------------------------------------------------------
  Monotonic stack approach:
    Decreasing stack of indices.
    When we find a taller bar: the current bar and top of stack
    form the right wall; the new stack top is the left wall.
    Water trapped = (min(leftWall, rightWall) - floor) * width

  Two-pointer approach (simpler O(n)/O(1)):
    Water at position i = min(maxLeft[i], maxRight[i]) - height[i]
    Precompute maxLeft and maxRight or use two pointers.

  Stack approach:
    int trap(int[] height) {
      Stack<Integer> stack = new Stack<>();
      int water = 0;
      for (int i = 0; i < height.length; i++) {
        while (!stack.isEmpty() && height[i] > height[stack.peek()]) {
          int floor = height[stack.pop()];
          if (stack.isEmpty()) break;
          int left = stack.peek();
          int h = Math.min(height[left], height[i]) - floor;
          water += h * (i - left - 1);
        }
        stack.push(i);
      }
      return water;
    }

----------------------------------------------------------------
SUM OF SUBARRAY MINIMUMS / MAXIMUMS
----------------------------------------------------------------
For each element, find how many subarrays it is the minimum of.

  For arr[i]:
    left[i]  = number of consecutive elements to the LEFT
               that are >= arr[i] (arr[i] is still the min)
    right[i] = number of consecutive elements to the RIGHT
               that are > arr[i]

  Contribution of arr[i] = arr[i] * left[i] * right[i]

  Use two monotonic stack passes (or one pass with careful handling)
  to compute left[] and right[] in O(n).

  Time: O(n)  MOD arithmetic when required.

----------------------------------------------------------------
INTERVIEW QUESTIONS
----------------------------------------------------------------

Q: What is the amortized complexity of monotonic stack
   operations and why?
A: O(n) total for processing n elements. Each element is pushed
   onto the stack exactly once and popped at most once. So the
   total number of operations is at most 2n, giving O(n) amortized
   regardless of how many pops happen per iteration. Some elements
   may cause many pops, but since each pop corresponds to an
   element being processed exactly once, the total pops across
   all iterations cannot exceed n.

Q: In the largest rectangle histogram problem, why do you
   use the previous element in the stack as the left boundary
   when a bar is popped?
A: When a bar at index `mid` is popped because `heights[i] < heights[mid]`,
   it means `heights[i]` is the first bar to the RIGHT shorter than `mid`.
   The new stack top after popping is the first bar to the LEFT
   that is also shorter than `mid` (because the stack is increasing,
   so everything between stack top and `mid` was already popped
   as taller elements). So the rectangle of height `heights[mid]`
   spans from (stack.peek() + 1) to (i - 1), width = i - stack.peek() - 1.

Q: How do you decide whether to use a monotonic increasing
   or decreasing stack?
A: Think about what event triggers a pop and what information
   it gives you:
   Decreasing stack: pop happens when a LARGER element arrives.
     Popped element gets next GREATER element = current element.
     Stack top after push = previous GREATER element.
   Increasing stack: pop happens when a SMALLER element arrives.
     Popped element gets next SMALLER element = current element.
     Stack top after push = previous SMALLER element.
   For histogram (need previous/next SMALLER), use increasing.
   For next greater element, use decreasing.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. Always store INDICES in the stack, not values -- you need
     the index to compute widths, distances, and store results
  2. The amortized O(n) argument: each element pushed once,
     popped at most once -> total ops = 2n = O(n)
  3. For circular arrays: traverse 2n, use i % n, only push for i < n
  4. Add a sentinel (0 or INF) at the end of the array to flush
     all remaining elements from the stack cleanly
  5. When popping, the popped element's relationship to current
     (new) element is the key result: current = next greater/smaller
  6. Sum of subarray min/max: contribution of each element =
     element * leftCount * rightCount (handle ties carefully)
