================================================================
  SUBARRAY SUM EQUALS K
  (LC 560 — Core HashMap + Prefix Sum Problem)
================================================================

----------------------------------------------------------------
PROBLEM STATEMENT
----------------------------------------------------------------

  Given an integer array nums and an integer k, return the number
  of contiguous subarrays whose sum equals k.

  Example 1:
    Input:  nums = [1, 1, 1], k = 2
    Output: 2

  Example 2:
    Input:  nums = [1, 2, 3], k = 3
    Output: 2  (subarrays [1,2] and [3])

  Constraints:
    - nums can contain NEGATIVE numbers
    - Sliding window DOES NOT WORK (negatives break the monotonic property)
    - Must use prefix sum + HashMap

----------------------------------------------------------------
WHY SLIDING WINDOW FAILS
----------------------------------------------------------------

  Sliding window works when: as window grows, sum increases;
  as window shrinks, sum decreases. This requires all positives.

  With negatives: [1, -1, 1, -1, 1], k = 1
    After sum > k, shrinking doesn't guarantee sum decreases.
    Window approach cannot find all subarrays.

  ALWAYS use prefix sum + HashMap when negatives are possible.

----------------------------------------------------------------
APPROACH: PREFIX SUM + HASHMAP
----------------------------------------------------------------

  KEY INSIGHT:
    sum(l, r) = k
    prefix[r] - prefix[l-1] = k
    prefix[l-1] = prefix[r] - k

  So for each index r, we need to count how many previous prefix
  sums equal (prefix[r] - k). Store prefix sum frequencies in a map.

  ALGORITHM:
    1. Initialize map with {0: 1}  (one empty prefix sum of value 0)
    2. Maintain running sum.
    3. For each element: sum += num.
    4. Look up (sum - k) in map. Add map.get(sum-k) to count.
    5. Add current sum to map.

  ORDER MATTERS: always look up BEFORE adding current sum to map.
  (Prevents counting [0..i] subarray using its own prefix as both ends.)

----------------------------------------------------------------
JAVA SOLUTION
----------------------------------------------------------------

  public int subarraySum(int[] nums, int k) {
      Map<Integer, Integer> prefixCount = new HashMap<>();
      prefixCount.put(0, 1);
      int sum = 0, count = 0;

      for (int num : nums) {
          sum += num;
          count += prefixCount.getOrDefault(sum - k, 0);
          prefixCount.merge(sum, 1, Integer::sum);
      }
      return count;
  }

  Time: O(n)
  Space: O(n)

----------------------------------------------------------------
DETAILED TRACE: nums=[1,2,3], k=3
----------------------------------------------------------------

  Step    num    sum    sum-k    map                count
  ----    ---    ---    -----    ---                -----
  init     -      0      -      {0:1}              0
  i=0      1      1     1-3=-2  {0:1}     get(-2)=0   0
                               {0:1, 1:1}
  i=1      2      3     3-3=0   {0:1,1:1} get(0)=1   1
                               {0:1, 1:1, 3:1}
  i=2      3      6     6-3=3   {0:1,1:1,3:1} get(3)=1  2
                               {0:1, 1:1, 3:1, 6:1}

  Answer: 2 ✓
  Subarrays found:
    - At i=1: sum=3, looked up 0, found prefix[0]=0 meaning subarray [0,1]=[1,2]
    - At i=2: sum=6, looked up 3, found prefix[2]=3 meaning subarray [2,2]=[3]

VARIANT: SUBARRAY SUM DIVISIBLE BY K (LC 974)
----------------------------------------------------------------

  Count subarrays where sum % k == 0.

  KEY INSIGHT:
    sum(l,r) % k == 0
    (prefix[r] - prefix[l-1]) % k == 0
    prefix[r] % k == prefix[l-1] % k

  Count pairs with equal remainder. Store remainder frequencies.

  Java:
    public int subarraysDivByK(int[] nums, int k) {
        Map<Integer, Integer> remainderCount = new HashMap<>();
        remainderCount.put(0, 1);
        int sum = 0, count = 0;

        for (int num : nums) {
            sum += num;
            int rem = ((sum % k) + k) % k;  // normalize negative remainders
            count += remainderCount.getOrDefault(rem, 0);
            remainderCount.merge(rem, 1, Integer::sum);
        }
        return count;
    }

  Note: ((sum % k) + k) % k handles Java's negative modulo behavior.
    In Java: -7 % 3 = -1 (wrong), we want 2 (correct).
    Fix: (-7 % 3 + 3) % 3 = (-1 + 3) % 3 = 2 % 3 = 2 ✓

VARIANT: BINARY SUBARRAY WITH SUM (LC 930)
----------------------------------------------------------------

  Binary array (only 0s and 1s). Count subarrays with sum = goal.

  Same as LC 560 but input is binary. Same solution works directly.

  Alternative with sliding window (since all non-negative):
    exactlyK(goal) = atMost(goal) - atMost(goal - 1)

  atMost helper:
    public int atMost(int[] nums, int goal) {
        if (goal < 0) return 0;
        int left = 0, sum = 0, count = 0;
        for (int right = 0; right < nums.length; right++) {
            sum += nums[right];
            while (sum > goal) sum -= nums[left++];
            count += right - left + 1;  // all subarrays ending at right
        }
        return count;
    }

    public int numSubarraysWithSum(int[] nums, int goal) {
        return atMost(nums, goal) - atMost(nums, goal - 1);
    }

----------------------------------------------------------------
VARIANT: CONTINUOUS SUBARRAY SUM (LC 523)
----------------------------------------------------------------

  Check if there exists a subarray of length >= 2 with sum
  divisible by k.

  TRICK: two prefix sums have same remainder AND are at least
  2 indices apart.

  Java:
    public boolean checkSubarraySum(int[] nums, int k) {
        Map<Integer, Integer> firstSeen = new HashMap<>();
        firstSeen.put(0, -1);  // empty prefix at index -1
        int sum = 0;

        for (int i = 0; i < nums.length; i++) {
            sum += nums[i];
            int rem = sum % k;
            if (firstSeen.containsKey(rem)) {
                if (i - firstSeen.get(rem) >= 2) return true;
            } else {
                firstSeen.put(rem, i);  // store first occurrence only
            }
        }
        return false;
    }

  Note: We store FIRST occurrence to maximize the potential gap.

----------------------------------------------------------------
VARIANT: LONGEST SUBARRAY WITH SUM = 0 (Classic)
----------------------------------------------------------------

  Find length of longest subarray with sum = 0.

  Same as finding two indices i < j with prefix[i] == prefix[j].
  Length = j - i. Maximize this.

  Java:
    public int longestSubarrayWithSumZero(int[] nums) {
        Map<Integer, Integer> firstSeen = new HashMap<>();
        firstSeen.put(0, -1);
        int sum = 0, maxLen = 0;

        for (int i = 0; i < nums.length; i++) {
            sum += nums[i];
            if (firstSeen.containsKey(sum)) {
                maxLen = Math.max(maxLen, i - firstSeen.get(sum));
            } else {
                firstSeen.put(sum, i);  // first occurrence only
            }
        }
        return maxLen;
    }

----------------------------------------------------------------
PATTERN DECISION TABLE
----------------------------------------------------------------

  Goal                          HashMap Value      When to Put
  ----                          -------------      -----------
  Count subarrays sum=k         count              Always (even if seen before)
  Longest subarray sum=k        first index        Only if NOT already in map
  Exists subarray sum=k len>=2  first index        Only if NOT already in map

  Rule:
    COUNT problem  --> use merge(sum, 1, Integer::sum), count += map.get(sum-k)
    LENGTH problem --> use putIfAbsent(sum, i),         length = i - map.get(sum)
    EXISTS problem --> use containsKey + gap check

----------------------------------------------------------------
COMMON MISTAKES
----------------------------------------------------------------

  1. Forgetting to initialize map with {0: 1}.
     Without it, subarrays starting from index 0 (the entire prefix)
     will never be counted.

  2. Adding to map BEFORE looking up.
     This would allow using the same index for both l and r,
     effectively counting a single element as its own subarray
     in a self-referential way.

  3. For length problems: using merge instead of putIfAbsent.
     We need the FIRST occurrence to maximize length.

  4. Not handling negative remainders in Java for divisibility problems.

  5. Confusing (sum-k) lookup (for count) vs same-remainder lookup (for divisibility).

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: Why does this work with negative numbers when sliding window doesn't?
  A: Sliding window relies on monotonicity (adding elements only increases sum).
     Prefix sum + HashMap has no such assumption — it works for any integers.

  Q: What's the time complexity and why?
  A: O(n) — single pass through the array. Each element contributes one
     HashMap put and one get, both O(1) average.

  Q: What does put(0, 1) represent?
  A: The empty prefix (before any element). If the running sum equals k at
     index r, then the subarray nums[0..r] has sum k. We need prefix[r] - k = 0
     to be in the map. The put(0,1) ensures this is counted.

  Q: Can there be duplicate prefix sums in the map?
  A: Yes, especially with negatives. The map counts ALL occurrences. If
     prefix[0] = prefix[3] = prefix[7] = 5, and at some index r we have
     sum - k = 5, we count 3 subarrays (ending at r, starting from 1, 4, 8).

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------

  - Derive the formula sum(l,r) = prefix[r] - prefix[l-1] = k first.
  - Show that we need to count occurrences of (prefix[r] - k) seen so far.
  - Trace through [1,1,1] k=2 to show the map growing step by step.
  - Clearly state: look up THEN add to map (not the other way).
  - Mention: this pattern generalizes — any time you need "count of pairs with
    property on prefix sums", use a HashMap.
