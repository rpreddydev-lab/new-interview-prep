================================================================
  SLIDING WINDOW -- INTRODUCTION
================================================================

The Sliding Window technique maintains a "window" (contiguous
subarray or substring) and slides it across the input to find
a subarray satisfying some constraint efficiently.

Instead of recomputing from scratch for every window (O(n^2)),
we ADD the new element entering the window and REMOVE the
element leaving it (O(1) update each step), giving O(n) total.

----------------------------------------------------------------
WHEN TO USE SLIDING WINDOW
----------------------------------------------------------------

  Signal words:
    - "Contiguous subarray" or "substring"
    - "Longest / shortest / maximum / minimum" subarray
    - "Subarray of size k"
    - "Subarray containing at most / exactly k distinct elements"
    - "Find all anagrams" / "find all permutations in string"

  NOT sliding window:
    - Non-contiguous subarray (use DP or divide/conquer)
    - Sum of any subset (use prefix sum + HashMap)
    - When the constraint involves ordering non-consecutively

----------------------------------------------------------------
TWO VARIANTS
----------------------------------------------------------------

  A) FIXED SIZE WINDOW
     Window size k is given. Slide by exactly 1 each step.
     Use for: max/min/avg of size-k subarray, anagram count.

  B) VARIABLE SIZE WINDOW (Two Pointer Window)
     Window size changes based on a constraint.
     Expand right when valid; shrink left when invalid.
     Use for: longest substring with constraint, min window, etc.

----------------------------------------------------------------
FIXED WINDOW TEMPLATE
----------------------------------------------------------------

  int windowSum = 0;
  for (int i = 0; i < k; i++) windowSum += nums[i];  // initial window
  int maxSum = windowSum;

  for (int i = k; i < n; i++) {
      windowSum += nums[i];         // add incoming element
      windowSum -= nums[i - k];     // remove outgoing element
      maxSum = Math.max(maxSum, windowSum);
  }

  Key: outgoing element index = i - k (current right - window size)

----------------------------------------------------------------
VARIABLE WINDOW TEMPLATE
----------------------------------------------------------------

  int l = 0;
  // window state: map, count, sum, etc.
  for (int r = 0; r < n; r++) {
      // ADD nums[r] to window state

      while (window is INVALID) {
          // REMOVE nums[l] from window state
          l++;
      }

      // window is valid: update answer
      ans = Math.max(ans, r - l + 1);  // or whatever metric
  }

  Key insight:
    - The window [l, r] is ALWAYS valid after the while loop.
    - r - l + 1 = current window size.
    - Maximum window size is tracked over all valid windows.

----------------------------------------------------------------
VISUALIZATION -- VARIABLE WINDOW (Longest Subarray Sum <= k)
----------------------------------------------------------------

  nums = [2, 1, 5, 2, 3, 2],  k = 7

  r=0: add 2, sum=2 <= 7, valid. len=1.
  r=1: add 1, sum=3 <= 7, valid. len=2.
  r=2: add 5, sum=8 > 7.  shrink: remove 2 (l=0), sum=6, l=1. len=2.
  r=3: add 2, sum=8 > 7.  shrink: remove 1 (l=1), sum=7, l=2. len=2.
  r=4: add 3, sum=10 > 7. shrink: remove 5 (l=2), sum=5, l=3. len=2.
       sum=5 <= 7. valid. len=2.
  r=5: add 2, sum=7 <= 7, valid. len=3.

  Max length = 3 (window [2,3,2])

----------------------------------------------------------------
WINDOW STATE MANAGEMENT
----------------------------------------------------------------

  What you track in the window depends on the problem:

  Problem type                  Track in window
  ------------                  ---------------
  Sum-based (fixed window)      int sum
  Sum-based (variable)          int sum, compare to k
  Character frequency (fixed)   int[] freq
  Distinct count (variable)     HashMap<char, count> + distinct counter
  "At most k distinct"          HashMap + count variable
  "Exactly k X"                 Use: atMost(k) - atMost(k-1) trick

  The window state must support:
    1. ADD element (when r advances)
    2. REMOVE element (when l advances, i.e., window shrinks)
    3. CHECK validity (is constraint satisfied?)

----------------------------------------------------------------
SHRINKING THE WINDOW
----------------------------------------------------------------

  Two approaches for the while loop condition:

  A) while (INVALID) shrink:
     --> Used for "longest valid window"
     --> Window is guaranteed valid after while loop
     --> ans = r - l + 1 after while loop (current valid window)

  B) if (size > k) shrink once:
     --> Used for "fixed window" or "exactly k"
     --> Window stays exactly size k after the if block
     --> ans updated inside the if block (when window is full)

  Example of (B) -- Fixed window:
    if (r - l + 1 > k) {
        removeFromWindow(nums[l]);
        l++;
    }
    if (r - l + 1 == k) {
        // full window, update answer
    }

----------------------------------------------------------------
COMPLEXITY
----------------------------------------------------------------

  Time:  O(n)
    - r moves from 0 to n-1: n iterations.
    - l only moves forward (never backward): at most n total moves.
    - Total work: O(2n) = O(n).

  Space: O(k) or O(alphabet_size)
    - For char frequency windows: O(26) for lowercase = O(1)
    - For arbitrary key windows: O(window size) = O(k)

----------------------------------------------------------------
COMMON MISTAKES
----------------------------------------------------------------

  1. Forgetting to update window state when shrinking:
     Must remove nums[l] from your window tracking BEFORE l++.

  2. Using for loop instead of while for shrinking:
     while is needed because multiple shrinks may be required.

  3. Updating answer INSIDE the shrink loop:
     Answer should be updated AFTER the while loop (window is valid then).

  4. For fixed window: initializing window before the sliding loop:
     Fill first k elements separately, then slide from index k.

  5. Integer overflow: if sum can exceed int range, use long.

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: Why is sliding window O(n) and not O(n^2)?
  A: Both l and r each move at most n steps (l only goes forward,
     r only goes forward). Total pointer movement = O(2n) = O(n).

  Q: How is sliding window different from two pointers?
  A: They're closely related. Sliding window focuses on the WINDOW
     (a contiguous range) and its STATE. Two pointers typically refers
     to converging pointers or simple fast/slow pointers. Variable
     sliding window IS a form of two pointers applied to windows.

  Q: When do you use fixed vs variable window?
  A: Fixed: when the window size k is explicitly given.
     Variable: when you need to FIND the optimal window size.

  Q: What's the "at most k" trick for "exactly k"?
  A: count(exactly k) = count(at most k) - count(at most k-1).
     This avoids the complexity of maintaining "exactly k" state.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------

  - Identify the "window" and its "validity condition" first.
  - State what you're adding/removing as r/l move.
  - Draw the window bounds and show the invariant: [l, r] is always valid.
  - Mention the O(n) proof: each element enters window once (r++) and
    leaves window at most once (l++).
