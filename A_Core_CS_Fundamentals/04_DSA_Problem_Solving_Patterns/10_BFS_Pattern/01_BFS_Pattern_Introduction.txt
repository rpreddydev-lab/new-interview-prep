================================================================
  BFS PATTERN — INTRODUCTION
  (Breadth-First Search)
================================================================

  BFS explores all neighbors at the current depth before going deeper.
  It uses a QUEUE (FIFO) as its core data structure.

  Key properties:
    - Finds the SHORTEST PATH in unweighted graphs/trees.
    - Processes nodes level by level.
    - Guaranteed to find the minimum number of steps.

----------------------------------------------------------------
CORE BFS TEMPLATE
----------------------------------------------------------------

  Java:
    Queue<Node> queue = new LinkedList<>();
    Set<Node> visited = new HashSet<>();

    queue.offer(start);
    visited.add(start);

    while (!queue.isEmpty()) {
        Node curr = queue.poll();
        // process curr

        for (Node neighbor : getNeighbors(curr)) {
            if (!visited.contains(neighbor)) {
                visited.add(neighbor);
                queue.offer(neighbor);
            }
        }
    }

  CRITICAL: Mark visited WHEN ADDING TO QUEUE, not when processing.
  If you mark when processing, duplicates can pile up in the queue.

----------------------------------------------------------------
LEVEL-BY-LEVEL BFS (Track Depth / Level)
----------------------------------------------------------------

  Java:
    int level = 0;
    while (!queue.isEmpty()) {
        int size = queue.size();  // FREEZE the current level size
        for (int i = 0; i < size; i++) {
            Node curr = queue.poll();
            // process curr -- it's at 'level' depth
            for (Node neighbor : getNeighbors(curr)) {
                if (!visited.contains(neighbor)) {
                    visited.add(neighbor);
                    queue.offer(neighbor);
                }
            }
        }
        level++;
    }

  The inner for-loop processes exactly one level at a time.
  After the inner loop, level++ means all nodes at the NEXT level
  are in the queue.

----------------------------------------------------------------
BFS vs DFS DECISION
----------------------------------------------------------------

  Use BFS when:
    - Need SHORTEST PATH (fewest edges/steps)
    - Level-order processing
    - Find all nodes at distance k
    - Minimum moves/steps to reach target

  Use DFS when:
    - Need to explore all paths (backtracking)
    - Connected components, cycle detection
    - Topological sort
    - Tree: inorder/preorder/postorder

----------------------------------------------------------------
MULTI-SOURCE BFS
----------------------------------------------------------------

  Start BFS from multiple sources simultaneously.
  All sources are added to the queue BEFORE the BFS begins.
  This finds the minimum distance from ANY source.

  Java:
    for (Cell source : sources) {
        queue.offer(source);
        visited.add(source);
    }
    // Then standard BFS

  Examples:
    - Rotting Oranges: all rotten oranges are sources
    - Matrix distances: all 0s are sources (LC 542)
    - Nearest gate: all gates are sources

----------------------------------------------------------------
BIDIRECTIONAL BFS (OPTIMIZATION)
----------------------------------------------------------------

  Search from BOTH start and end simultaneously.
  Meet in the middle. Reduces search space from O(b^d) to O(b^(d/2)).

  Used in: Word Ladder, Shortest Word Transformation.

  Java:
    Set<String> beginSet = new HashSet<>(), endSet = new HashSet<>();
    beginSet.add(beginWord); endSet.add(endWord);

    while (!beginSet.isEmpty() && !endSet.isEmpty()) {
        if (beginSet.size() > endSet.size()) {
            Set<String> tmp = beginSet; beginSet = endSet; endSet = tmp;
        }
        Set<String> nextSet = new HashSet<>();
        for (String word : beginSet) {
            // generate neighbors, if in endSet --> found!
            // else add to nextSet
        }
        beginSet = nextSet;
        steps++;
    }

----------------------------------------------------------------
BFS ON GRAPH vs TREE vs MATRIX
----------------------------------------------------------------

  Graph:
    - Use adjacency list or map.
    - MUST track visited (cycles possible).
    - BFS finds shortest path in unweighted graph.

  Tree:
    - No cycles, no visited set needed.
    - Level-order traversal (LC 102, 103, 107).
    - Common: collect nodes per level into list of lists.

  Matrix (2D grid):
    - Neighbors: 4-directional or 8-directional.
    - Use a visited 2D array (boolean[][] or modify in-place).
    - State = (row, col). Queue holds int[] {row, col}.

  int[][] dirs = {{0,1},{0,-1},{1,0},{-1,0}};  // 4-directional

  for (int[] dir : dirs) {
      int nr = row + dir[0], nc = col + dir[1];
      if (nr >= 0 && nr < rows && nc >= 0 && nc < cols && !visited[nr][nc]) {
          visited[nr][nc] = true;
          queue.offer(new int[]{nr, nc});
      }
    }

----------------------------------------------------------------
QUEUE IMPLEMENTATION CHOICE
----------------------------------------------------------------

  LinkedList<>():   Most common. Implements Queue. offer/poll/peek work.
  ArrayDeque<>():   Faster in practice (no null checks, array-backed).
                    Preferred for performance.

  Both work for BFS. Use ArrayDeque for best performance.

  Queue<Integer> q = new ArrayDeque<>();
  q.offer(x);      // enqueue
  q.poll();        // dequeue
  q.peek();        // view front

----------------------------------------------------------------
STATE REPRESENTATION IN BFS
----------------------------------------------------------------

  The "state" is what you put in the queue and visited set.
  Can be complex:

  Simple:   node reference, (row, col)
  String:   word in word ladder, lock combination
  Tuple:    (x, y, steps), (pos, fuel_remaining)
  Integer:  encoded from multiple values (e.g., r*cols + c)

  Key: the visited set tracks STATES, not just nodes.
  If state includes more than position (e.g., number of obstacles removed),
  visited must include the full state.

----------------------------------------------------------------
COMPLEXITY
----------------------------------------------------------------

  Time: O(V + E)   -- vertices + edges explored
  Space: O(V)      -- queue and visited set

  For m x n matrix:
  Time: O(m * n)   Space: O(m * n)
