================================================================
  TOP K FREQUENT ELEMENTS (LC 347)
================================================================

  Given an integer array nums and an integer k, return the k most
  frequent elements.

  Input:  nums = [1,1,1,2,2,3], k = 2
  Output: [1,2]

  Input:  nums = [1], k = 1
  Output: [1]

  Guarantee: the answer is unique (no ambiguity in top-k boundary).

----------------------------------------------------------------
APPROACH 1: HASHMAP + MIN-HEAP
----------------------------------------------------------------

  Step 1: Count frequencies using a HashMap.
  Step 2: Use a min-heap of size k, keyed by frequency.
          Min-heap keeps the k most frequent. When a new element has
          higher frequency than the heap min, it displaces it.

  Java:
    public int[] topKFrequent(int[] nums, int k) {
        Map<Integer, Integer> freq = new HashMap<>();
        for (int num : nums) freq.merge(num, 1, Integer::sum);

        // Min-heap by frequency
        PriorityQueue<Integer> heap = new PriorityQueue<>(
            (a, b) -> freq.get(a) - freq.get(b)
        );

        for (int num : freq.keySet()) {
            heap.offer(num);
            if (heap.size() > k) heap.poll();  // remove least frequent
        }

        int[] result = new int[k];
        for (int i = k - 1; i >= 0; i--) result[i] = heap.poll();
        return result;
    }

  Time: O(n log k)   Space: O(n + k)

  Note: freq.merge(num, 1, Integer::sum) is equivalent to:
    freq.put(num, freq.getOrDefault(num, 0) + 1);

----------------------------------------------------------------
APPROACH 2: BUCKET SORT (O(n))
----------------------------------------------------------------

  Key insight: frequency of any element is between 1 and n.
  Create buckets[0..n] where buckets[f] = list of elements with frequency f.
  Walk from n down to 1, collect until we have k elements.

  Java:
    public int[] topKFrequent(int[] nums, int k) {
        Map<Integer, Integer> freq = new HashMap<>();
        for (int num : nums) freq.merge(num, 1, Integer::sum);

        // Buckets: index = frequency
        List<Integer>[] buckets = new List[nums.length + 1];
        for (int num : freq.keySet()) {
            int f = freq.get(num);
            if (buckets[f] == null) buckets[f] = new ArrayList<>();
            buckets[f].add(num);
        }

        int[] result = new int[k];
        int idx = 0;
        for (int f = nums.length; f >= 1 && idx < k; f--) {
            if (buckets[f] != null) {
                for (int num : buckets[f]) {
                    result[idx++] = num;
                    if (idx == k) break;
                }
            }
        }
        return result;
    }

  Time: O(n)   Space: O(n)

----------------------------------------------------------------
TRACED EXAMPLE: [1,1,1,2,2,3], k=2
----------------------------------------------------------------

  Frequency map: {1:3, 2:2, 3:1}

  BUCKET SORT trace:
    buckets[1] = [3]
    buckets[2] = [2]
    buckets[3] = [1]

    Walk from f=6 down to f=1:
      f=6: null
      f=5: null
      f=4: null
      f=3: [1] --> result[0]=1, idx=1
      f=2: [2] --> result[1]=2, idx=2 (idx==k=2, stop)

    Result: [1,2] ✓

  HEAP trace:
    Add 3 (freq=1): heap=[3]
    Add 2 (freq=2): heap=[3,2]  -- min-heap by freq
    Add 1 (freq=3): heap=[3,2,1], size>2, poll() removes 3 (freq=1)
                    heap=[2,1]
    Poll twice for result: 2 (freq=2), 1 (freq=3)
    Result: [1,2] (reverse order for descending freq) ✓

----------------------------------------------------------------
VARIANT: SORT CHARACTERS BY FREQUENCY (LC 451)
----------------------------------------------------------------

  Same pattern. Count char frequencies, sort by descending frequency.

  Java:
    public String frequencySort(String s) {
        Map<Character, Integer> freq = new HashMap<>();
        for (char c : s.toCharArray()) freq.merge(c, 1, Integer::sum);

        // Max-heap by frequency
        PriorityQueue<Character> heap = new PriorityQueue<>(
            (a, b) -> freq.get(b) - freq.get(a)  // max-heap
        );
        heap.addAll(freq.keySet());

        StringBuilder sb = new StringBuilder();
        while (!heap.isEmpty()) {
            char c = heap.poll();
            for (int i = 0; i < freq.get(c); i++) sb.append(c);
        }
        return sb.toString();
    }

  Input: "tree" --> "eert" or "eetr" (e:2, t:1, r:1)

----------------------------------------------------------------
VARIANT: TOP K FREQUENT WORDS (LC 692)
----------------------------------------------------------------

  Same pattern but with lexicographic tiebreaker:
    - Primary sort: frequency (descending)
    - Secondary sort: alphabetical (ascending)

  Java:
    public List<String> topKFrequent(String[] words, int k) {
        Map<String, Integer> freq = new HashMap<>();
        for (String w : words) freq.merge(w, 1, Integer::sum);

        // Min-heap: lowest priority at top (gets evicted)
        // Lower freq = lower priority; equal freq: lex later = lower priority
        PriorityQueue<String> heap = new PriorityQueue<>((a, b) -> {
            int fa = freq.get(a), fb = freq.get(b);
            if (fa != fb) return fa - fb;        // lower freq first (min-heap)
            return b.compareTo(a);               // lex later first (so lex earlier stays)
        });

        for (String w : freq.keySet()) {
            heap.offer(w);
            if (heap.size() > k) heap.poll();
        }

        List<String> result = new ArrayList<>();
        while (!heap.isEmpty()) result.add(0, heap.poll());  // reverse order
        return result;
    }

----------------------------------------------------------------
BUCKET SORT APPROACH FOR TOP K FREQUENT WORDS
----------------------------------------------------------------

  Same bucket idea, but within each bucket sort words lexicographically.

  List<String>[] buckets = new List[words.length + 1];
  // ... fill buckets as before ...
  Collections.sort(buckets[f]);  // lex sort within same-frequency bucket

----------------------------------------------------------------
COMPLEXITY TABLE
----------------------------------------------------------------

  Approach       Time          Space    Notes
  ----------------------------------------------------------
  HashMap+Sort   O(n log n)    O(n)     Simple, but slow
  HashMap+Heap   O(n log k)    O(n+k)   Best when k << n
  Bucket Sort    O(n)          O(n)     Best overall for integers

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: Why bucket sort can achieve O(n) while heap is O(n log k)?
  A: Frequency is bounded by n, so we can use an array indexed by
     frequency. Walking buckets from high to low is O(n). No comparison
     sorting needed.

  Q: For heap approach, why is it a MIN-heap not MAX-heap?
  A: We want to evict the LEAST frequent element when heap exceeds size k.
     A min-heap gives O(1) access to the element with lowest frequency.

  Q: What's the space complexity of bucket sort?
  A: O(n): HashMap for frequencies + n+1 bucket slots + result array.

  Q: Can you do this with a TreeMap?
  A: Yes: TreeMap<Integer, List<Integer>> sorted by frequency.
     But building it is O(n log n), not better than sorting.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------

  - Mention both heap (O(n log k)) and bucket (O(n)) solutions.
  - For bucket sort, emphasize that frequency ≤ n bounds the bucket array size.
  - For words variant, be careful with the min-heap comparator: the ordering
    must be REVERSED (what you want last is at the top of the min-heap).
  - Trace the bucket sort approach — it's elegant and impresses interviewers.
