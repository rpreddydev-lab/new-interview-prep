LC 13 — ROMAN TO INTEGER
----------------------------------------------------------------

  Roman values:
    I=1, V=5, X=10, L=50, C=100, D=500, M=1000

  Subtractive notation: if a smaller value appears BEFORE a larger one, subtract it.
    IV=4, IX=9, XL=40, XC=90, CD=400, CM=900.

  Algorithm: scan right-to-left. If current < previous → subtract, else add.

  Java:
    public int romanToInt(String s) {
        Map<Character, Integer> map = new HashMap<>();
        map.put('I', 1); map.put('V', 5); map.put('X', 10);
        map.put('L', 50); map.put('C', 100); map.put('D', 500); map.put('M', 1000);
        int result = 0, prev = 0;
        for (int i = s.length() - 1; i >= 0; i--) {
            int curr = map.get(s.charAt(i));
            if (curr < prev) result -= curr;   // subtractive case
            else result += curr;
            prev = curr;
        }
        return result;
    }

  Alternative (left-to-right): if s[i] < s[i+1], subtract s[i], else add.

  Java (left-to-right):
    public int romanToInt(String s) {
        Map<Character, Integer> map = Map.of(
            'I',1,'V',5,'X',10,'L',50,'C',100,'D',500,'M',1000);
        int result = 0;
        for (int i = 0; i < s.length(); i++) {
            int curr = map.get(s.charAt(i));
            int next = i + 1 < s.length() ? map.get(s.charAt(i + 1)) : 0;
            if (curr < next) result -= curr;
            else result += curr;
        }
        return result;
    }

  Time: O(n)  Space: O(1) (map is constant size).

  Trace for "MCMXCIV" = 1994:
    M(1000): prev=0 → add. result=1000.
    C(100):  prev=1000. 100 < 1000 → subtract. result=900.
    M(1000): 1000 >= 100 → add. result=1900.
    X(10):   prev=1000. 10 < 1000 → subtract. result=1890.
    C(100):  100 >= 10 → add. result=1990.
    I(1):    prev=100. 1 < 100 → subtract. result=1989.
    V(5):    5 >= 1 → add. result=1994. ✓

LC 12 — INTEGER TO ROMAN
----------------------------------------------------------------

  Strategy: Greedy — subtract the largest possible Roman value repeatedly.

  Value table (including subtractive combos):
    1000→M, 900→CM, 500→D, 400→CD, 100→C, 90→XC, 50→L, 40→XL, 10→X, 9→IX, 5→V, 4→IV, 1→I

  Java:
    public String intToRoman(int num) {
        int[] values   = {1000,900,500,400,100,90,50,40,10,9,5,4,1};
        String[] syms  = {"M","CM","D","CD","C","XC","L","XL","X","IX","V","IV","I"};
        StringBuilder sb = new StringBuilder();
        for (int i = 0; i < values.length; i++) {
            while (num >= values[i]) {
                sb.append(syms[i]);
                num -= values[i];
            }
        }
        return sb.toString();
    }

  Trace for 1994:
    1994 >= 1000 → append M, num=994.
    994 >= 900 → append CM, num=94.
    94 < 500. 94 < 400. 94 < 100.
    94 >= 90 → append XC, num=4.
    4 < 50, 4 < 40, 4 < 10, 4 < 9, 4 < 5.
    4 >= 4 → append IV, num=0.
    Result: "MCMXCIV" ✓

  Time: O(1) — at most O(13 * max_repeats) = O(13*3999) ≈ O(constant).
  Space: O(1).

LC 7 — REVERSE INTEGER
----------------------------------------------------------------

  Reverse digits of integer. Return 0 if overflow (outside 32-bit signed range).

  Java:
    public int reverse(int x) {
        int rev = 0;
        while (x != 0) {
            int digit = x % 10;
            x /= 10;
            // Check overflow BEFORE updating rev
            if (rev > Integer.MAX_VALUE / 10 || (rev == Integer.MAX_VALUE / 10 && digit > 7)) return 0;
            if (rev < Integer.MIN_VALUE / 10 || (rev == Integer.MIN_VALUE / 10 && digit < -8)) return 0;
            rev = rev * 10 + digit;
        }
        return rev;
    }

  Why check against 7 and -8?
    Integer.MAX_VALUE = 2147483647 (last digit 7).
    Integer.MIN_VALUE = -2147483648 (last digit 8 in absolute).
    If rev already equals MAX/10 = 214748364, next digit > 7 would overflow.

  Time: O(log |x|) = O(10) = O(1) for 32-bit.

LC 9 — PALINDROME NUMBER
----------------------------------------------------------------

  An integer is a palindrome if it reads the same forwards and backwards.
  Negative numbers are NOT palindromes. Numbers ending in 0 (except 0 itself) are NOT.

  Approach: Reverse HALF of the number, compare.
  (Avoids full reversal and potential overflow.)

  Java:
    public boolean isPalindrome(int x) {
        if (x < 0 || (x != 0 && x % 10 == 0)) return false;
        int reversed = 0;
        while (x > reversed) {              // stop when reversed catches up to x
            reversed = reversed * 10 + x % 10;
            x /= 10;
        }
        return x == reversed || x == reversed / 10;  // odd digit count: x == reversed/10
    }

  Why reversed/10 for odd count?
    For 121: after loop, x=1, reversed=12. x != reversed.
    But x == reversed/10 → 1 == 1. ✓

  Trace for 1221:
    x=1221, rev=0.
    rev=1, x=122. 122>1, continue.
    rev=12, x=12. 12 not > 12, stop.
    x==rev → 12==12. ✓ palindrome.

  Trace for 123:
    rev=3, x=12. rev=32, x=1. 1 not > 32, stop.
    x==rev? 1==32? No. x==rev/10? 1==3? No. Return false. ✓

LC 202 — HAPPY NUMBER
----------------------------------------------------------------

  Process: replace n by sum of squares of its digits.
  Repeat until: n==1 (happy) or enters a cycle (not happy).
  Cycle detection: Floyd's algorithm OR track seen numbers.

  Java (HashSet):
    public boolean isHappy(int n) {
        Set<Integer> seen = new HashSet<>();
        while (n != 1 && !seen.contains(n)) {
            seen.add(n);
            n = sumOfSquares(n);
        }
        return n == 1;
    }

    int sumOfSquares(int n) {
        int sum = 0;
        while (n > 0) { int d = n % 10; sum += d * d; n /= 10; }
        return sum;
    }

  Java (Floyd — O(1) space):
    public boolean isHappy(int n) {
        int slow = n, fast = sumOfSquares(n);
        while (fast != 1 && slow != fast) {
            slow = sumOfSquares(slow);
            fast = sumOfSquares(sumOfSquares(fast));
        }
        return fast == 1;
    }

  Time: O(log n) per step, O(1) cycles before detection.  Space: O(1).

  Fun fact: All non-happy numbers eventually cycle through 4→16→37→58→89→145→42→20→4.

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: In LC 13, why scan right-to-left instead of left-to-right?
  A: Right-to-left: compare current with previous → simpler logic.
     Left-to-right: compare current with next → works too but need bounds check.
     Both are valid; choose based on preference.

  Q: Why include 900, 400, 90, 40, 4 in the LC 12 table?
  A: These are the 6 subtractive Roman numeral forms. Greedy correctly handles
     them because they appear in decreasing order in the table.

  Q: In LC 7, why not just cast to long, reverse, and cast back?
  A: That works too but interviewers often want overflow detection logic.
     The check `rev > MAX/10` is the canonical approach.

  Q: In LC 9, why does reversing half avoid overflow?
  A: The reversed half is at most n/10 which fits in int.
     Full reversal of large number (e.g., 1999999999) would overflow.
