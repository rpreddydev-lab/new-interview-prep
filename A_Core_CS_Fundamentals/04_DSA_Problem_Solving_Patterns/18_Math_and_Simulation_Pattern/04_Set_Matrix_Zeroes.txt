================================================================
  SET MATRIX ZEROES AND RELATED IN-PLACE MATRIX PROBLEMS
  LC 73 / LC 74 / LC 240
================================================================

  LC 73: If an element in an m×n matrix is 0,
         set its entire row AND column to 0. Do it IN PLACE.

  Challenge: can't use O(m+n) extra space for naive marking.
  Optimal: use the FIRST ROW and FIRST COLUMN as markers → O(1) extra space.

----------------------------------------------------------------
LC 73 — SET MATRIX ZEROES
----------------------------------------------------------------

  Naive O(m+n) space:
    Collect all (r,c) with 0. Then zero out those rows/cols.

  O(1) space approach:
    Use matrix[0][c] to mark if column c should be zeroed.
    Use matrix[r][0] to mark if row r should be zeroed.
    But we must handle row 0 and col 0 separately (they serve as markers AND data).

  Java:
    public void setZeroes(int[][] matrix) {
        int m = matrix.length, n = matrix[0].length;
        boolean firstRowZero = false, firstColZero = false;

        // Check if first row has a zero
        for (int c = 0; c < n; c++) if (matrix[0][c] == 0) firstRowZero = true;
        // Check if first col has a zero
        for (int r = 0; r < m; r++) if (matrix[r][0] == 0) firstColZero = true;

        // Use first row/col as markers for the rest of the matrix
        for (int r = 1; r < m; r++) {
            for (int c = 1; c < n; c++) {
                if (matrix[r][c] == 0) {
                    matrix[r][0] = 0;  // mark row r
                    matrix[0][c] = 0;  // mark col c
                }
            }
        }

        // Zero out based on markers (excluding first row/col)
        for (int r = 1; r < m; r++) {
            for (int c = 1; c < n; c++) {
                if (matrix[r][0] == 0 || matrix[0][c] == 0) matrix[r][c] = 0;
            }
        }

        // Handle first row
        if (firstRowZero) for (int c = 0; c < n; c++) matrix[0][c] = 0;
        // Handle first col
        if (firstColZero) for (int r = 0; r < m; r++) matrix[r][0] = 0;
    }

  Time: O(m*n)  Space: O(1)

----------------------------------------------------------------
TRACED EXAMPLE: LC 73
----------------------------------------------------------------

  Input:
    1  1  1
    1  0  1
    1  1  1

  Step 1: Check first row for zeros → none. firstRowZero=false.
  Step 2: Check first col for zeros → none. firstColZero=false.

  Step 3: Scan r=1..2, c=1..2:
    (1,1)=0 → mark matrix[1][0]=0, matrix[0][1]=0.

  Matrix after marking:
    1  0  1    ← matrix[0][1] marked
    0  0  1    ← matrix[1][0] marked
    1  1  1

  Step 4: Zero out r=1..2, c=1..2 based on markers:
    r=1: matrix[1][0]=0 → zero entire row 1 (except [1][0]):
         [1][1]=0, [1][2]=0.
    r=2: matrix[2][0]=1 (no mark).
    c=1: matrix[0][1]=0 → zero entire col 1:
         [1][1]=0 (already), [2][1]=0.

  Result:
    1  0  1
    0  0  0
    1  0  1  ✓

  Step 5: firstRowZero=false → don't zero row 0.
  Step 6: firstColZero=false → don't zero col 0.

----------------------------------------------------------------
WHY HANDLE FIRST ROW AND COL SEPARATELY?
----------------------------------------------------------------

  If we don't save firstRowZero/firstColZero upfront,
  and a zero is found elsewhere in row 1 (r=1..m-1), we mark matrix[0][c].
  Then when processing first row, we'd erroneously zero it.

  Saving flags BEFORE marking ensures we only zero first row/col
  if they ORIGINALLY contained a zero — not because they were used as markers.

----------------------------------------------------------------
LC 74 — SEARCH A 2D MATRIX
----------------------------------------------------------------

  m×n matrix, integers in each row sorted left-to-right,
  first integer of each row > last integer of previous row.
  Find if target exists.

  Treat as 1D sorted array of size m*n. Binary search.

  Java:
    public boolean searchMatrix(int[][] matrix, int target) {
        int m = matrix.length, n = matrix[0].length;
        int lo = 0, hi = m * n - 1;
        while (lo <= hi) {
            int mid = (lo + hi) / 2;
            int val = matrix[mid / n][mid % n];  // map 1D index to 2D
            if (val == target) return true;
            else if (val < target) lo = mid + 1;
            else hi = mid - 1;
        }
        return false;
    }

  Key: index `mid` maps to row=mid/n, col=mid%n.
  Time: O(log(m*n))  Space: O(1).

----------------------------------------------------------------
LC 240 — SEARCH A 2D MATRIX II
----------------------------------------------------------------

  m×n matrix, integers sorted left-to-right in each row
  AND top-to-bottom in each column (but rows don't start > prev row end).

  Strategy: Start at top-right corner (0, n-1).
    If matrix[r][c] == target → found.
    If matrix[r][c] > target → go left (c--). [eliminate column]
    If matrix[r][c] < target → go down (r++). [eliminate row]

  Java:
    public boolean searchMatrix(int[][] matrix, int target) {
        int r = 0, c = matrix[0].length - 1;
        while (r < matrix.length && c >= 0) {
            if (matrix[r][c] == target) return true;
            else if (matrix[r][c] > target) c--;
            else r++;
        }
        return false;
    }

  Time: O(m + n)  Space: O(1).

  Why top-right corner?
    - Going left decreases value (row is sorted).
    - Going down increases value (column is sorted).
    - Can deterministically eliminate a row or column at each step.

  Why NOT top-left?
    - Both right and down increase values → can't decide direction.

----------------------------------------------------------------
LC 74 vs LC 240 — KEY DIFFERENCES
----------------------------------------------------------------

  Feature           LC 74                      LC 240
  ---------------   -----------------------    --------------------------
  Matrix property   Fully sorted (1D like)     Row + col sorted (not 1D)
  Algorithm         Binary search O(log m*n)   Start top-right O(m+n)
  Stronger sort     Yes (whole matrix 1D)      No (row/col only)
  Best algorithm    Binary search              "Staircase search"

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: In LC 73, why save firstRow/firstColZero before starting the marking?
  A: Otherwise, marking matrix[0][c] in Step 3 could interfere with
     the first-row check we'd do later, giving incorrect zeroing.

  Q: What if we could use O(m+n) space in LC 73?
  A: Collect rows/cols to zero in two sets, then zero them. Simpler but violates constraint.

  Q: In LC 240, why start at top-RIGHT (not top-left or bottom-right)?
  A: Top-right: moving left decreases value, moving down increases value. Binary decision.
     Top-left: moving right or down both increase. Can't eliminate.
     Bottom-right: would need to go left or up → similar logic works but reversed.

  Q: What's the time complexity of LC 240?
  A: O(m+n) — at each step, either row or column index moves by 1, bounded by m+n total steps.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------

  - LC 73 O(1) space: draw the "first row/col as markers" technique on paper.
  - Always mention "save firstRow/firstColZero flags BEFORE using row/col as markers."
  - LC 74: say "treat it as a 1D array — index row=mid/n, col=mid%n."
  - LC 240: say "staircase search starting from top-right corner."
  - Common mistake: using top-left instead of top-right in LC 240.
