================================================================
  REDUNDANT CONNECTION — LC 684 / LC 685
================================================================

  LC 684: Undirected graph with n nodes (1..n) and n edges.
          Originally a tree (n-1 edges). One extra edge was added.
          Find and return that extra (redundant) edge.
          If multiple answers, return the one appearing last in input.

  LC 685: Same but DIRECTED graph.

  Core insight for LC 684: Process edges in order.
          First edge that connects two nodes ALREADY in the same component
          is the redundant edge (it forms a cycle).

----------------------------------------------------------------
LC 684 — UNDIRECTED SOLUTION (UNION-FIND)
----------------------------------------------------------------

  Java:
    public int[] findRedundantConnection(int[][] edges) {
        int n = edges.length;
        int[] parent = new int[n + 1];  // nodes 1-indexed
        int[] rank = new int[n + 1];
        for (int i = 1; i <= n; i++) parent[i] = i;

        for (int[] edge : edges) {
            if (!union(parent, rank, edge[0], edge[1])) {
                return edge;  // union failed → both already connected → redundant
            }
        }
        return new int[]{};  // should never reach
    }

    int find(int[] parent, int x) {
        if (parent[x] != x) parent[x] = find(parent, parent[x]);
        return parent[x];
    }

    boolean union(int[] parent, int[] rank, int x, int y) {
        int rx = find(parent, x), ry = find(parent, y);
        if (rx == ry) return false;  // CYCLE DETECTED
        if (rank[rx] < rank[ry]) { int t = rx; rx = ry; ry = t; }
        parent[ry] = rx;
        if (rank[rx] == rank[ry]) rank[rx]++;
        return true;
    }

  Time: O(N * α(N))   Space: O(N)

----------------------------------------------------------------
TRACE EXAMPLE: LC 684
----------------------------------------------------------------

  edges = [[1,2],[1,3],[2,3]]
  n = 3, parent = [_, 1, 2, 3]  (1-indexed, _ is unused)

  Process [1,2]: find(1)=1, find(2)=2. Different → union. parent[2]=1. OK.
  Process [1,3]: find(1)=1, find(3)=3. Different → union. parent[3]=1. OK.
  Process [2,3]: find(2)=find(parent[2])=find(1)=1. find(3)=find(parent[3])=find(1)=1.
                 Same (both=1) → CYCLE → return [2,3]. ✓

----------------------------------------------------------------
WHY "LAST EDGE" IN PROBLEM CONSTRAINTS?
----------------------------------------------------------------

  For tree + 1 edge, there is exactly ONE cycle.
  Any edge on the cycle could be the "redundant" one.
  Problem asks for the last one in input order on the cycle.

  Since we process edges in order and return immediately on cycle,
  we return the last edge on the cycle that was processed.
  This automatically satisfies "last in input order among all correct answers."

----------------------------------------------------------------
LC 685 — DIRECTED GRAPH (MORE COMPLEX)
----------------------------------------------------------------

  In a directed graph (rooted tree + 1 edge), there are two possible situations:

  Case 1: One node has two parents (in-degree = 2). No cycle or there's a cycle.
  Case 2: There's a cycle but all nodes have exactly one parent.

  Strategy:
    1. Find if any node has in-degree 2. If so, there are two candidate edges
       (cand1 = first edge pointing to that node, cand2 = second).
    2. Disable cand2 first (try removing it). Check if remaining graph is valid tree.
       If yes, return cand2.
       If no (still has cycle), return cand1.
    3. If no node has in-degree 2, there's a pure cycle → find the edge in the cycle.

  Java:
    public int[] findRedundantDirectedConnection(int[][] edges) {
        int n = edges.length;
        int[] parent = new int[n + 1];
        int[] inDeg = new int[n + 1];
        int[] cand1 = null, cand2 = null;

        // Find node with two parents
        for (int[] e : edges) {
            inDeg[e[1]]++;
            if (inDeg[e[1]] == 2) {
                // Find the two edges pointing to e[1]
                for (int[] prev : edges) {
                    if (prev[1] == e[1]) {
                        if (cand1 == null) cand1 = prev;
                        else cand2 = e;
                    }
                }
            }
        }

        // Initialize UF for cycle detection
        for (int i = 1; i <= n; i++) parent[i] = i;
        int[] rank = new int[n + 1];

        for (int[] e : edges) {
            if (e == cand2) continue;  // try removing cand2
            if (!union(parent, rank, e[0], e[1])) {
                // Cycle found while cand2 is removed
                return cand1 != null ? cand1 : e;
            }
        }
        return cand2 != null ? cand2 : new int[]{};
    }

  Time: O(N * α(N))   Space: O(N)

----------------------------------------------------------------
LC 684 VS LC 685 — COMPARISON
----------------------------------------------------------------

  Feature           LC 684 (Undirected)        LC 685 (Directed)
  ---------------   ------------------------   ----------------------------
  Graph type        Undirected                 Directed (rooted tree + 1)
  Cycle detection   Simple UF                  UF + in-degree check
  Edge cases        None                       Cycle-only vs two-parent cases
  Complexity        O(N * α(N))                O(N * α(N)) but more logic
  Code difficulty   Simple                     Moderate

----------------------------------------------------------------
RELATED: GRAPH VALID TREE (LC 261)
----------------------------------------------------------------

  Given n nodes and edges, determine if they form a valid tree.
  A valid tree: (1) exactly n-1 edges, (2) all nodes connected (no cycle).

  Java:
    public boolean validTree(int n, int[][] edges) {
        if (edges.length != n - 1) return false;  // must have exactly n-1 edges
        int[] parent = new int[n], rank = new int[n];
        for (int i = 0; i < n; i++) parent[i] = i;
        for (int[] e : edges) {
            if (!union(parent, rank, e[0], e[1])) return false;  // cycle detected
        }
        return true;  // n-1 edges + no cycle = tree
    }

----------------------------------------------------------------
KRUSKAL'S MST (UF APPLICATION)
----------------------------------------------------------------

  Find Minimum Spanning Tree by greedily adding minimum weight edges
  that don't form a cycle.

  Java:
    public int minimumSpanningTree(int n, int[][] edges) {
        Arrays.sort(edges, (a, b) -> a[2] - b[2]);  // sort by weight
        int[] parent = new int[n], rank = new int[n];
        for (int i = 0; i < n; i++) parent[i] = i;
        int totalWeight = 0, edgesUsed = 0;
        for (int[] e : edges) {
            if (union(parent, rank, e[0], e[1])) {
                totalWeight += e[2];
                edgesUsed++;
                if (edgesUsed == n - 1) break;  // MST complete
            }
        }
        return totalWeight;
    }

  Time: O(E log E) for sorting. O(E * α(N)) for UF operations.

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: Why does UF find the redundant edge naturally?
  A: A tree has no cycles. When we add the n-th edge, it creates exactly one cycle.
     The first union() that returns false (can't merge) is the edge causing the cycle.

  Q: Why 1-indexed in LC 684?
  A: Problem uses 1..n node labels. Allocate parent[n+1] with index 0 unused,
     or remap to 0..n-1. Either works.

  Q: Can DFS find the redundant edge?
  A: Yes: build graph, DFS, detect back edge. But UF is cleaner and O(N) vs O(N+E).

  Q: Difference between tree and valid tree?
  A: A tree (n nodes) has n-1 edges and is connected with no cycles.
     Check: edge count == n-1 AND UF finds no cycle.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------

  - State clearly: "union returns false when two nodes are already connected → cycle."
  - For LC 684: one liner solution—iterate edges, first failed union is answer.
  - For LC 685: explain the two cases (two-parent node vs pure cycle) before coding.
  - Kruskal's MST is a famous UF application worth mentioning in system design context.
