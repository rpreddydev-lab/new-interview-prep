================================================================
  GREEDY PATTERN — INTRODUCTION
================================================================

  A greedy algorithm makes the locally optimal choice at each step
  with the hope that local optimum leads to global optimum.

  Unlike DP (considers all possibilities), greedy commits to a choice and never revises it.

----------------------------------------------------------------
WHEN DOES GREEDY WORK?
----------------------------------------------------------------

  Greedy works when the problem has:

  1. GREEDY CHOICE PROPERTY:
     A globally optimal solution can be reached by making locally optimal choices.
     Choosing the best option now doesn't prevent future optimal choices.

  2. OPTIMAL SUBSTRUCTURE:
     Optimal solution contains optimal solutions to subproblems.
     (Also required by DP, but greedy doesn't solve all subproblems.)

  How to identify greedy problems:
    - After sorting, choices become monotone
    - One variable tracks a running "state" (reach, balance, current end)
    - Exchange argument: swapping any two adjacent choices doesn't improve result
    - Problem says "maximum", "minimum", "earliest", "latest"
    - Greedy choice is obvious once you sort the input

----------------------------------------------------------------
GREEDY vs DP
----------------------------------------------------------------

  GREEDY                           DP
  ------                           --
  Make one optimal choice          Consider all choices
  Irrevocable                      Revises (memoizes all paths)
  O(n log n) typical               O(n^2) or O(n*W) typical
  Optimal substructure needed      Optimal substructure + overlapping subproblems
  Works on specific structure      More general
  Interval scheduling, Huffman     Knapsack, LCS, Edit Distance

  Key question: "Does making the greedy choice at step i preclude
  a better solution later?" If no → greedy works.

----------------------------------------------------------------
COMMON GREEDY PATTERNS
----------------------------------------------------------------

  SORT + SWEEP:
    Sort input, then iterate making locally optimal choices.
    Examples: Meeting Rooms, Activity Selection, Merge Intervals

  GREEDY WITH PRIORITY QUEUE:
    Use heap to always pick best available option.
    Examples: Task Scheduler, Connect Ropes, Huffman Coding

  GREEDY SCAN (ONE PASS):
    Track running variable (farthest reach, current sum, balance).
    Examples: Jump Game, Gas Station, Candy Distribution

  TWO-PASS GREEDY:
    First pass left-to-right, second right-to-left, combine.
    Examples: Candy Distribution, Trapping Rain Water

----------------------------------------------------------------
EXCHANGE ARGUMENT (PROOF TECHNIQUE)
----------------------------------------------------------------

  To prove greedy is correct: show that any solution not following
  the greedy choice can be transformed into one that does,
  without worsening the objective.

  Example (Activity Selection):
    Greedy: always pick activity with earliest finish time.
    Proof: If optimal solution picks activity A over B (B finishes earlier),
    swap B in. B finishes no later than A, so subsequent choices unaffected.
    Greedy solution is at least as good.

  Common proof techniques:
    - Exchange argument (swap adjacent choices)
    - Induction on greedy steps
    - Show optimal solution "agrees" with greedy at each step

----------------------------------------------------------------
CLASSIC GREEDY PROBLEMS OVERVIEW
----------------------------------------------------------------

  PROBLEM                             GREEDY STRATEGY
  -------                             ---------------
  Activity Selection                  Sort by end time, always pick earliest ending
  Meeting Rooms II (min rooms)        Sort starts, use min-heap for end times
  Jump Game (can reach end)           Track max reachable index
  Jump Game II (min jumps)            Track current range, expand greedily
  Gas Station                         Running sum; if negative, restart
  Candy Distribution                  Two-pass: left increasing, right increasing
  Task Scheduler                      Most frequent task determines idle slots
  Partition Labels                    Last occurrence of each char defines partition
  Non-overlapping Intervals           Sort by end time, greedily remove conflicts
  Minimum Number of Arrows            Sort by end, one arrow per non-overlapping set
  Lemonade Change                     Always give largest denomination change first
  Queue Reconstruction by Height      Sort desc by height, insert by position

----------------------------------------------------------------
GREEDY CORRECTNESS CHECKLIST
----------------------------------------------------------------

  Before committing to greedy approach:
    1. Is sorting meaningful here? (Usually sort by end, start, ratio, etc.)
    2. Can I show that always choosing X leads to optimal result?
    3. Draw a counterexample attempt. If none exists, greedy likely works.
    4. Is DP needed because previous choices affect future? (Use DP instead)

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------

  - When you identify greedy, state the key insight: "Sorting by X and then
    choosing Y greedily is optimal because..."
  - Always mention why local choice doesn't hurt global optimality.
  - Typical FAANG greedy: Jump Game, Gas Station, Intervals, Task Scheduler.
  - If greedy seems to work but is hard to prove, try small examples to validate.
  - Most greedy problems need O(n log n) sort + O(n) sweep = O(n log n) total.
