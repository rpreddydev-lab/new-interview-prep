================================================================
  JUMP GAME (LC 55, 45, 1345, 1340)
================================================================

  LC 55:   Can you reach the last index?
  LC 45:   Minimum number of jumps to reach last index.
  LC 1345: Minimum jumps with additional same-value jumps.
  LC 1340: Jump Game V (jump to higher adjacent values).

----------------------------------------------------------------
LC 55: CAN YOU REACH THE LAST INDEX?
----------------------------------------------------------------

  nums[i] = max jump length from position i.
  Track maxReach: farthest index reachable so far.
  If current index > maxReach → stuck, return false.

  Java:
    public boolean canJump(int[] nums) {
        int maxReach = 0;
        for (int i = 0; i < nums.length; i++) {
            if (i > maxReach) return false;
            maxReach = Math.max(maxReach, i + nums[i]);
        }
        return true;
    }

  Time: O(n)   Space: O(1)

  Example: [2,3,1,1,4] → maxReach: 2→4→... (always forward) → true ✓
  Example: [3,2,1,0,4] → maxReach: 3→3→3→3, i=4 > 3 → false ✓

  Greedy insight: track the maximum index we can reach. If we reach an index
  that we cannot even access, we'll never get past it.

----------------------------------------------------------------
LC 45: MINIMUM JUMPS TO REACH LAST INDEX
----------------------------------------------------------------

  Greedy with BFS-like levels.
  Track: `curEnd` (end of current jump range), `farthest` (best we can reach in current range), `jumps`.
  When we reach curEnd, we MUST jump. The best next position is `farthest`.

  Java:
    public int jump(int[] nums) {
        int jumps = 0, curEnd = 0, farthest = 0;
        for (int i = 0; i < nums.length - 1; i++) {  // don't need to jump from last
            farthest = Math.max(farthest, i + nums[i]);
            if (i == curEnd) {          // forced to jump
                jumps++;
                curEnd = farthest;
            }
        }
        return jumps;
    }

  Time: O(n)   Space: O(1)

  Example: [2,3,1,1,4]
    i=0: farthest=max(0,2)=2. i==curEnd(0)→jumps=1, curEnd=2.
    i=1: farthest=max(2,4)=4. i≠curEnd.
    i=2: farthest=max(4,3)=4. i==curEnd(2)→jumps=2, curEnd=4.
    i=3: farthest=max(4,4)=4. i≠curEnd.
    return 2 ✓

  Example: [2,3,0,1,4]
    i=0: farthest=2. i==curEnd→jumps=1, curEnd=2.
    i=1: farthest=4. i≠curEnd.
    i=2: farthest=4. i==curEnd(2)→jumps=2, curEnd=4.
    return 2 ✓

  Why stop at nums.length-1? We don't need to jump from the last index.

  BFS interpretation:
    Level 0: [index 0]
    Level 1: [indices reachable in 1 jump from 0]
    Level 2: [indices reachable in 2 jumps]
    ...
    jumps = level at which we first reach n-1.

----------------------------------------------------------------
VISUALIZATION: BFS LEVELS
----------------------------------------------------------------

  nums = [2,3,1,1,4], indices 0..4

  Level 0:   [0]               (start)
             reach = 0+2 = 2
  Level 1:   [1,2]             (from index 0, reach indices 1..2)
             reach = max(1+3, 2+1) = max(4,3) = 4
  Level 2:   [3,4]             (from level 1, reach indices 3..4)
             → index 4 = last. done in 2 jumps.

  jumps tracks how many "BFS levels" (jumps) needed.

----------------------------------------------------------------
GREEDY INSIGHT: WHY IT WORKS
----------------------------------------------------------------

  At each "level" (jump), we want to maximize how far we can reach.
  Choosing the cell in current range that extends reach furthest is always optimal.

  Formal: suppose we need k jumps in optimal solution. Greedy uses <= k jumps
  because at each step it picks the most "extending" cell — never worse than optimal.

LC 1345: JUMP GAME IV (MINIMUM JUMPS WITH SAME-VALUE TELEPORT)
----------------------------------------------------------------

  From index i, can jump to i-1, i+1, or any index j where arr[j] == arr[i].
  Find minimum jumps to reach last index.

  BFS. Precompute sameVal map: value → list of indices.
  State: current index. Process level by level.
  CRITICAL: after visiting a group, remove from map to avoid re-processing (O(n^2) → O(n)).

  Java:
    public int minJumps(int[] arr) {
        int n = arr.length;
        if (n == 1) return 0;

        Map<Integer, List<Integer>> sameVal = new HashMap<>();
        for (int i = 0; i < n; i++) {
            sameVal.computeIfAbsent(arr[i], k -> new ArrayList<>()).add(i);
        }

        Queue<Integer> q = new LinkedList<>();
        boolean[] visited = new boolean[n];
        q.offer(0);
        visited[0] = true;
        int steps = 0;

        while (!q.isEmpty()) {
            int size = q.size();
            steps++;
            for (int k = 0; k < size; k++) {
                int i = q.poll();
                // Neighbors: i-1, i+1, all same-value indices
                List<Integer> neighbors = new ArrayList<>();
                if (i - 1 >= 0) neighbors.add(i - 1);
                if (i + 1 < n) neighbors.add(i + 1);
                List<Integer> same = sameVal.getOrDefault(arr[i], new ArrayList<>());
                neighbors.addAll(same);
                sameVal.remove(arr[i]);  // CRITICAL: avoid revisiting same group

                for (int next : neighbors) {
                    if (next == n - 1) return steps;
                    if (!visited[next]) {
                        visited[next] = true;
                        q.offer(next);
                    }
                }
            }
        }
        return -1;
    }

  Time: O(n)   Space: O(n)

  Why remove from sameVal? Without removal, every time we visit a repeated-value group,
  we'd re-add all same-value indices to the queue, making it O(n^2) in worst case.

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: Why does the greedy approach for LC 45 work?
  A: The minimum number of jumps is equivalent to the BFS level. At each level,
     greedy maximizes the reach (farthest we can get to), ensuring we don't
     need extra jumps. Any other choice would give same or worse coverage.

  Q: Why iterate only to nums.length-1 in LC 45?
  A: When we're at the last index, no jump is needed. Including it would trigger
     an unnecessary jump increment.

  Q: What happens if jumps === n-1 in worst case (LC 45)?
  A: Like [1,1,1,...,1] — every index allows jump of 1. O(n) greedy still works.

  Q: Why is sameVal.remove() critical in LC 1345?
  A: When multiple indices share the same value, they form a "hub." Once we've
     expanded from any one of them, all others are already in the queue.
     Keeping the map would re-expand the same hub every time we reach it, O(n^2).
