================================================================
  INTERVAL SCHEDULING (GREEDY)
================================================================

  Interval problems: given a set of intervals, apply greedy to schedule,
  merge, or count them optimally.

  Core problems:
    LC 56  Merge Intervals
    LC 57  Insert Interval
    LC 252 Meeting Rooms I
    LC 253 Meeting Rooms II
    LC 435 Non-overlapping Intervals (minimum removals)
    LC 452 Minimum Arrows to Burst Balloons

----------------------------------------------------------------
MEETING ROOMS I (LC 252)
----------------------------------------------------------------

  Can a person attend all meetings? (No two overlap)

  Sort by start time. If any interval starts before previous ends → false.

  Java:
    public boolean canAttendMeetings(int[][] intervals) {
        Arrays.sort(intervals, (a, b) -> a[0] - b[0]);
        for (int i = 1; i < intervals.length; i++) {
            if (intervals[i][0] < intervals[i-1][1]) return false;
        }
        return true;
    }

  Time: O(n log n)   Space: O(1) (excluding sort)

----------------------------------------------------------------
MEETING ROOMS II (LC 253)
----------------------------------------------------------------

  Find minimum number of conference rooms required.

  Approach: sort starts and ends separately, two-pointer sweep.
  At each start: if it's >= min end, a room frees up.

  Java:
    public int minMeetingRooms(int[][] intervals) {
        int n = intervals.length;
        int[] starts = new int[n], ends = new int[n];
        for (int i = 0; i < n; i++) { starts[i] = intervals[i][0]; ends[i] = intervals[i][1]; }
        Arrays.sort(starts);
        Arrays.sort(ends);

        int rooms = 0, endIdx = 0;
        for (int i = 0; i < n; i++) {
            if (starts[i] >= ends[endIdx]) endIdx++;  // room freed
            else rooms++;                              // new room needed
        }
        return rooms;
    }

  Alternatively: min-heap of end times.
    Sort by start. At each meeting, if heap.peek() <= start, poll (room freed).
    Always push current end. Answer = heap.size().

  Java (heap):
    public int minMeetingRooms(int[][] intervals) {
        Arrays.sort(intervals, (a, b) -> a[0] - b[0]);
        PriorityQueue<Integer> heap = new PriorityQueue<>();
        for (int[] interval : intervals) {
            if (!heap.isEmpty() && heap.peek() <= interval[0]) heap.poll();
            heap.offer(interval[1]);
        }
        return heap.size();
    }

  Example: [[0,30],[5,10],[15,20]]
    Sort: [[0,30],[5,10],[15,20]]
    Heap after [0,30]: [30]. No room free.
    Heap after [5,10]: 30>5, new room. [10,30].
    Heap after [15,20]: 10<=15, room freed. Poll 10. Push 20. [20,30].
    heap.size() = 2 ✓

NON-OVERLAPPING INTERVALS (LC 435)
----------------------------------------------------------------

  Minimum intervals to REMOVE so remaining are non-overlapping.

  Greedy: sort by END time. Keep interval with earliest end, remove conflicting.
  (Same as Activity Selection problem.)

  Java:
    public int eraseOverlapIntervals(int[][] intervals) {
        Arrays.sort(intervals, (a, b) -> a[1] - b[1]);  // sort by END
        int removed = 0, end = Integer.MIN_VALUE;
        for (int[] interval : intervals) {
            if (interval[0] >= end) {
                end = interval[1];  // keep this interval
            } else {
                removed++;          // remove (conflict with current end)
            }
        }
        return removed;
    }

  Why sort by end? We want to keep as many intervals as possible.
  Keeping the interval with the earliest end leaves most room for future intervals.

  Example: [[1,2],[2,3],[3,4],[1,3]]
    Sorted by end: [[1,2],[2,3],[1,3],[3,4]]
    end=MIN, removed=0:
      [1,2]: 1>=MIN → keep. end=2.
      [2,3]: 2>=2 → keep. end=3.
      [1,3]: 1<3 → REMOVE. removed=1.
      [3,4]: 3>=3 → keep. end=4.
    return 1 ✓

MINIMUM ARROWS TO BURST BALLOONS (LC 452)
----------------------------------------------------------------

  Each balloon is [start, end]. Arrow shot at x bursts all balloons containing x.
  Minimum arrows needed.

  Greedy: sort by end. Arrow at `end` of first balloon bursts all overlapping.
  Next unshot balloon defines next arrow.

  Java:
    public int findMinArrowShots(int[][] points) {
        Arrays.sort(points, (a, b) -> Integer.compare(a[1], b[1]));
        int arrows = 1, arrowPos = points[0][1];
        for (int i = 1; i < points.length; i++) {
            if (points[i][0] > arrowPos) {  // balloon starts after current arrow
                arrows++;
                arrowPos = points[i][1];
            }
        }
        return arrows;
    }

  Key difference from LC 435: overlapping means start <= arrowPos (not start < end).
  Here we check if balloon is NOT hit: start > arrowPos.

  Example: [[10,16],[2,8],[1,6],[7,12]]
    Sorted by end: [[1,6],[2,8],[7,12],[10,16]]
    arrows=1, arrowPos=6:
      [2,8]: 2<=6 → same arrow. (not > arrowPos)
      [7,12]: 7>6 → new arrow. arrows=2, arrowPos=12.
      [10,16]: 10<=12 → same arrow.
    return 2 ✓

  Non-overlapping intervals removed = n - minimum_arrows (if arrows = non-overlapping kept).
  Actually: LC 435 removed = n - (arrows in LC 452 style count) when intervals are same.

MERGE INTERVALS (LC 56)
----------------------------------------------------------------

  Already covered in 06_Merge_Intervals folder, but recap:

  Sort by start. If current.start <= prev.end → merge (update end = max(prev.end, curr.end)).
  Else add new interval.

  Java:
    public int[][] merge(int[][] intervals) {
        Arrays.sort(intervals, (a, b) -> a[0] - b[0]);
        List<int[]> result = new ArrayList<>();
        int[] curr = intervals[0];
        for (int i = 1; i < intervals.length; i++) {
            if (intervals[i][0] <= curr[1]) curr[1] = Math.max(curr[1], intervals[i][1]);
            else { result.add(curr); curr = intervals[i]; }
        }
        result.add(curr);
        return result.toArray(new int[0][]);
    }

----------------------------------------------------------------
INSERT INTERVAL (LC 57)
----------------------------------------------------------------

  Non-overlapping sorted intervals. Insert new interval and merge.

  Three phases:
    1. Add all intervals BEFORE new interval (end < newStart).
    2. Merge all overlapping intervals (start <= newEnd → update newEnd).
    3. Add remaining intervals.

  Java:
    public int[][] insert(int[][] intervals, int[] newInterval) {
        List<int[]> result = new ArrayList<>();
        int i = 0, n = intervals.length;
        // Phase 1: before
        while (i < n && intervals[i][1] < newInterval[0]) result.add(intervals[i++]);
        // Phase 2: merge overlapping
        while (i < n && intervals[i][0] <= newInterval[1]) {
            newInterval[0] = Math.min(newInterval[0], intervals[i][0]);
            newInterval[1] = Math.max(newInterval[1], intervals[i][1]);
            i++;
        }
        result.add(newInterval);
        // Phase 3: after
        while (i < n) result.add(intervals[i++]);
        return result.toArray(new int[0][]);
    }

  Time: O(n)   Space: O(n) output.

SUMMARY TABLE
----------------------------------------------------------------

  Problem                   Sort by    Key logic
  -------                   -------    ---------
  Meeting Rooms I           start      consecutive overlap check
  Meeting Rooms II          both       two-pointer or min-heap end times
  Non-overlapping (435)     end        keep earliest-end, remove conflicts
  Min Arrows (452)          end        shoot at end, skip until past arrow
  Merge Intervals (56)      start      extend end greedily
  Insert Interval (57)      none       three-phase sweep

  KEY: Sort by END → maximize kept intervals (435) or minimize arrows (452).
  KEY: Sort by START → merge intervals (56), check overlaps (252).

----------------------------------------------------------------
COMMON MISTAKES
----------------------------------------------------------------

  1. Sorting by wrong field. 435 and 452 require sort by END, not start.
  2. Integer overflow in comparator: use Integer.compare(a[1], b[1]) not a[1]-b[1].
     For large values (Long.MIN_VALUE, Long.MAX_VALUE), subtraction overflows.
  3. Off-by-one in overlap check:
     Merge: start <= prevEnd (touching counts as merge, problem-dependent)
     Arrows: start > arrowPos (strict: touching means same arrow)
  4. Not initializing arrows=1 or result with first interval.

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: Why does sorting by end time give optimal activity selection?
  A: Exchange argument: if we have a solution using activity A (not earliest ending)
     when B (earliest ending) also fits, swap A for B. B ends no later than A,
     so all subsequent choices remain valid. Greedy = at least as good.

  Q: Difference between LC 435 and LC 452?
  A: Both sort by end. 435 removes intervals to make non-overlapping (count removals).
     452 shoots arrows through overlapping balloons (count arrows = count non-overlapping groups).
     LC 452 answer = n - LC 435 maximum_kept = number of non-overlapping groups.

  Q: Why use Integer.compare instead of subtraction in comparator?
  A: Subtraction can overflow for Integer.MIN_VALUE values.
     Integer.compare(a, b) is always safe.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------

  - Always clarify: does "overlapping" include touching endpoints?
  - State the greedy insight upfront: "Sorting by end time lets us keep the most intervals."
  - For Meeting Rooms II, the heap approach is cleaner to explain than two-pointer.
  - Trace a small example (3-4 intervals) to verify sort order and edge cases.
