================================================================
  DYNAMIC PROGRAMMING — PATTERN INTRODUCTION
================================================================

  Dynamic Programming (DP) solves problems by breaking them into overlapping
  subproblems, storing solutions to avoid redundant computation.

  Applies when a problem has:
    1. Optimal substructure:  optimal solution uses optimal solutions to subproblems
    2. Overlapping subproblems:  same subproblems appear multiple times

----------------------------------------------------------------
TWO APPROACHES
----------------------------------------------------------------

  TOP-DOWN (Memoization):
    - Recursive solution + cache (HashMap or array)
    - Natural recursive structure
    - Only computes needed states

    Template:
      Map<State, Value> memo = new HashMap<>();
      int dp(State state) {
          if (base case) return base value;
          if (memo.containsKey(state)) return memo.get(state);
          // compute result using recursive calls
          int result = ...;
          memo.put(state, result);
          return result;
      }

  BOTTOM-UP (Tabulation):
    - Iterative, fill DP table in dependency order
    - No recursion overhead
    - More cache-friendly

    Template:
      int[] dp = new int[n + 1];
      dp[0] = base value;
      for (int i = 1; i <= n; i++) {
          dp[i] = recurrence using dp[i-1], dp[i-2], ...;
      }
      return dp[n];

----------------------------------------------------------------
DP PROBLEM CLASSIFICATION
----------------------------------------------------------------

  CATEGORY              EXAMPLES                       STATE DIMENSIONS
  --------              --------                       ----------------
  Linear DP             Climbing Stairs, House Robber  1D: index
  Interval DP           Burst Balloons, Matrix Chain   2D: [i][j] range
  Knapsack              0/1 Knapsack, Coin Change       2D: [item][capacity]
  String DP             Edit Distance, LCS, LPS        2D: [i][j] positions
  State Machine DP      Stock Problems, Regex Match    State + index
  Bitmask DP            TSP, Assignment Problem        2D: [mask][node]
  Grid DP               Unique Paths, Min Path Sum     2D: [row][col]
  Tree DP               House Robber III               DFS with subtree states

----------------------------------------------------------------
IDENTIFYING A DP PROBLEM
----------------------------------------------------------------

  Signals:
    - "minimum/maximum number of..."
    - "how many ways to..."
    - "is it possible to..."
    - Choices at each step, results accumulate
    - Recursive structure with overlapping subproblems

  Not DP:
    - Simple greedy (no overlapping subproblems)
    - Just recursion without repeated sub-calls

  Decision flow:
    Can I define state s.t. dp[state] = optimal answer for that subproblem?
    → YES: write recurrence, identify base cases, choose top-down or bottom-up.
    → NO: try greedy, divide & conquer, or other patterns.

----------------------------------------------------------------
DEFINING STATE
----------------------------------------------------------------

  1D state: dp[i] — answer considering first i elements / up to position i
    Fibonacci, Climbing Stairs, Decode Ways, House Robber

  2D state: dp[i][j] — answer for subproblem involving i and j
    String match: dp[i][j] for first i chars of s1, first j of s2
    Knapsack: dp[i][w] for first i items with weight limit w
    Grid: dp[r][c] for cell (r,c)

  State with extra dimension:
    dp[i][k]: with at most k transactions (Stock III)
    dp[i][holding]: holding stock or not (State Machine)
    dp[mask][i]: visited set mask, current node i (TSP)

----------------------------------------------------------------
SPACE OPTIMIZATION
----------------------------------------------------------------

  Many DP problems use dp[i] = f(dp[i-1], dp[i-2]).
  When current row only depends on previous row, reduce O(n^2) to O(n).

  Example (Knapsack):
    Original: dp[i][w] = max(dp[i-1][w], dp[i-1][w-wt[i]] + val[i])
    Optimized: 1D dp[w], iterate w in REVERSE to avoid using same item twice.

  Example (LCS):
    Only need dp[i-1][j-1], dp[i-1][j], dp[i][j-1]
    → Roll to 1D array (careful about overwrite order).

----------------------------------------------------------------
COMMON RECURRENCES
----------------------------------------------------------------

  Fibonacci:         dp[i] = dp[i-1] + dp[i-2]
  Climbing Stairs:   dp[i] = dp[i-1] + dp[i-2]   (1 or 2 steps)
  House Robber:      dp[i] = max(dp[i-1], dp[i-2] + nums[i])
  Coin Change:       dp[i] = min(dp[i-k] + 1) for each coin k <= i
  Knapsack (0/1):    dp[i][w] = max(dp[i-1][w], dp[i-1][w-wt]+val)
  Knapsack (unbnd):  dp[w] = max(dp[w], dp[w-wt]+val)  (iterate w forward)
  LCS:               dp[i][j] = dp[i-1][j-1]+1 if match, else max(dp[i-1][j],dp[i][j-1])
  Edit Distance:     dp[i][j] = dp[i-1][j-1] if match, else 1+min(3 operations)
  Palindrome:        dp[i][j] = dp[i+1][j-1] && s[i]==s[j]
  Burst Balloons:    dp[i][j] = max over k of dp[i][k]+dp[k][j]+val[i]*val[k]*val[j]

----------------------------------------------------------------
TIME AND SPACE COMPLEXITY PATTERNS
----------------------------------------------------------------

  1D DP:             O(n) time, O(n) or O(1) space (rolling)
  2D DP:             O(n*m) time, O(n*m) or O(n) space (rolling row)
  Knapsack (n,W):    O(n*W) time, O(W) space
  LCS (m,n):         O(m*n) time, O(min(m,n)) space
  Bitmask (n):       O(2^n * n) time, O(2^n * n) space
  Interval DP:       O(n^3) time, O(n^2) space (typical)

----------------------------------------------------------------
MEMOIZATION vs TABULATION
----------------------------------------------------------------

                    Memoization              Tabulation
                    -----------              ----------
  Style             Top-down recursive       Bottom-up iterative
  State computation On demand                All states
  Overflow risk     Yes (deep recursion)     No
  Cache             HashMap or array         Array
  Space             Only visited states      All states
  Speed             Slightly slower (map)    Slightly faster (array)
  Easier for        Interval DP, Tree DP     Linear, 2D DP

  Recommendation: Start with memoization to verify correctness,
  then convert to tabulation for optimization.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------

  - Always define state clearly: "dp[i] represents..."
  - Write base cases first before recurrence.
  - Trace a small example to verify recurrence (n=3 or 4).
  - Mention space optimization if applicable (rolling array, 1D reduction).
  - For 2D string DP, be careful about 0-indexed strings vs 1-indexed dp array.
  - If in doubt: top-down with memoization is safer to code correctly.
