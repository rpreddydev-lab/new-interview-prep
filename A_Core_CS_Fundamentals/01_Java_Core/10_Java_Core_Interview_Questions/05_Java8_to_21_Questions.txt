JAVA 8 TO 21 QUESTIONS
======================

Q1: What is a functional interface? What are the main ones in Java 8?
---------------------------------------------------------------------
A:
  A functional interface has exactly one abstract method (SAM — Single Abstract Method).
  It can have default and static methods (Java 8+) and private methods (Java 9+).
  Annotated with @FunctionalInterface (optional but recommended for compiler enforcement).
  Enables lambda expressions and method references.

  Core functional interfaces (java.util.function):
  Function<T, R>      — T in → R out: apply(T t) → R
  Predicate<T>        — T in → boolean: test(T t)
  Consumer<T>         — T in → void: accept(T t)
  Supplier<T>         — nothing in → T out: get()
  BiFunction<T,U,R>   — T, U in → R out
  UnaryOperator<T>    — extends Function<T,T> — same type in/out
  BinaryOperator<T>   — extends BiFunction<T,T,T>

  Primitive variants avoid boxing:
  IntFunction<R>, ToIntFunction<T>, IntUnaryOperator, IntBinaryOperator,
  LongSupplier, DoubleConsumer, etc.

Q2: What is the difference between map(), flatMap(), and filter() in Java streams?
-----------------------------------------------------------------------------------
A:
  filter(Predicate<T>): removes elements not matching the predicate.
    Stream<T> → Stream<T> (only elements where predicate returns true)
    stream.filter(s -> s.startsWith("A"))

  map(Function<T, R>): transforms each element — one-to-one mapping.
    Stream<T> → Stream<R>
    stream.map(String::toUpperCase)
    stream.map(Person::getAge)   // Stream<Person> → Stream<Integer>

  flatMap(Function<T, Stream<R>>): transforms each element to a STREAM, then flattens
    all resulting streams into one stream — one-to-many then flatten.
    Stream<T> → Stream<R>
    stream.flatMap(line -> Arrays.stream(line.split(" ")))
    // [["a","b"], ["c","d"]] → flatMap → ["a","b","c","d"]

  Key distinction: map produces Stream<Stream<R>> if the function returns Stream<R>.
  flatMap flattens those inner streams. Essential for processing nested/multi-valued results.

Q3: What are default methods in interfaces and why were they introduced?
-----------------------------------------------------------------------
A:
  Java 8 added default methods — interface methods with a body (default keyword).
  They are inherited by implementing classes and can be overridden.

  interface Collection<E> {
      default boolean isEmpty() { return size() == 0; }
  }

  Why introduced:
  - Backward compatibility: add new methods to existing interfaces without breaking all
    existing implementations. If Collection.stream() had been abstract, all existing
    Collection implementations would need to implement it — breaking billions of lines of code.
  - Java team needed to add stream(), parallelStream(), forEach(), removeIf(), etc. to
    existing JDK interfaces (Collection, List, Map, Iterable) in Java 8.

  Diamond problem resolution: if a class inherits two default methods with the same signature
  from different interfaces, it MUST explicitly override the method (or call one with
  InterfaceName.super.methodName()).

Q4: What are virtual threads (Project Loom) and how do they differ from platform threads?
------------------------------------------------------------------------------------------
A:
  Platform threads (traditional): each Java thread maps 1-to-1 to an OS thread.
  - OS threads are expensive: ~1 MB stack, OS scheduling overhead
  - Blocking a platform thread blocks the underlying OS thread (waste of OS resource)
  - Practical limit: ~tens of thousands of threads (OS limit)

  Virtual threads (Java 21, JEP 444 — GA):
  - Managed by the JVM, not the OS
  - Many virtual threads multiplexed onto a few carrier (platform) threads (fork-join pool)
  - When a virtual thread blocks (I/O, sleep, lock), the carrier thread is released
    and can run other virtual threads — NO OS thread waste
  - Can create MILLIONS of virtual threads cheaply
  - Created via: Thread.ofVirtual().start(task) or Executors.newVirtualThreadPerTaskExecutor()

  Programming model: same as platform threads (blocking code is fine — no callbacks/reactive needed).
  Virtual threads enable thread-per-request model for I/O-bound servers at massive scale.

  When NOT to use: CPU-bound work (parallel streams / ForkJoinPool still better);
  pinned virtual threads (when holding a synchronized monitor — avoid native sync inside VT code).

Q5: What is Optional and when should you use it?
------------------------------------------------
A:
  Optional<T> is a container that may or may not hold a non-null value.
  It represents an explicit "value may be absent" return type — an alternative to returning null.

  Creation:
  Optional.of(value)          — value must be non-null (NPE otherwise)
  Optional.ofNullable(value)  — value may be null (returns empty Optional)
  Optional.empty()            — empty Optional

  Access:
  .isPresent() / .isEmpty()           — check presence
  .get()                              — get value (throws if empty — avoid!)
  .orElse(defaultValue)               — value or default
  .orElseGet(Supplier)                — value or lazily computed default
  .orElseThrow(Supplier<Exception>)   — value or throw custom exception
  .map(Function)                      — transform if present
  .filter(Predicate)                  — filter if present
  .flatMap(Function<T, Optional<R>>)  — chain Optional-returning functions

  When to use: as a return type when a method may legitimately not return a value.
  When NOT to use: Optional fields (use null, avoid serialization issues), Optional parameters
  (overloading is clearer), Collection returns (return empty collection instead).

Q6: What are records in Java? How do they compare to regular classes?
---------------------------------------------------------------------
A:
  Records (Java 16 final, JEP 395): a concise way to declare transparent, immutable
  data carriers. Auto-generated: constructor (canonical), getters (accessor methods —
  name without "get" prefix), equals(), hashCode(), toString().

  record Point(int x, int y) {}  // that's the entire class!

  // Equivalent (manual):
  class Point {
      private final int x, y;
      public Point(int x, int y) { this.x = x; this.y = y; }
      public int x() { return x; }
      public int y() { return y; }
      public boolean equals(Object o) { ... }
      public int hashCode() { ... }
      public String toString() { ... }
  }

  Restrictions: all fields are implicitly final (records are immutable data carriers);
  cannot extend a class (but can implement interfaces); cannot add instance fields
  outside the record header.

  Use for: DTOs, value objects, structured data, multi-value method returns, domain events.

Q7: What is the difference between sealed classes and abstract classes?
----------------------------------------------------------------------
A:
  Abstract class: open to extension by anyone; any class in any package can subclass it.
  Sealed class: restricts which classes may extend it; subclasses must be declared in the
  permits clause (Java 17 final, JEP 409).

  sealed class Shape permits Circle, Rectangle, Triangle {}
  final class Circle extends Shape {}
  final class Rectangle extends Shape {}

  Key difference: exhaustiveness for switch.
  With a sealed hierarchy, the compiler knows all possible subtypes.
  A switch expression over a sealed type can be exhaustive — no default needed.

  String describe(Shape s) {
      return switch (s) {
          case Circle c    -> "circle r=" + c.radius();
          case Rectangle r -> "rect";
          case Triangle t  -> "triangle";
          // no default needed — compiler verifies exhaustiveness!
      };
  }

  Use case: algebraic data types (ADTs), Result<T>/Option<T> patterns,
  closed domain models where you control all variants.

Q8: What are text blocks and what problem do they solve?
--------------------------------------------------------
A:
  Text blocks (Java 15 final, JEP 378): a multi-line string literal that avoids
  the need for most escaping and indentation management.

  Before text blocks:
  String json = "{\n" +
                "  \"name\": \"Alice\",\n" +
                "  \"age\": 30\n" +
                "}";

  With text blocks:
  String json = """
          {
            "name": "Alice",
            "age": 30
          }
          """;

  Key rules:
  - Opening """ must be followed by a newline (no content on the same line)
  - Closing """ position determines common leading whitespace to strip (incidental whitespace)
  - Incidental whitespace (indent for code readability) is stripped; intentional extra indentation preserved
  - Embedded double quotes don't need escaping (unless three in a row — use \")
  - \s escape: keep trailing whitespace on a line; \ escape: join with next line (no newline)

  Use for: SQL queries, JSON/XML payloads, HTML, GraphQL queries, multiline log templates.
