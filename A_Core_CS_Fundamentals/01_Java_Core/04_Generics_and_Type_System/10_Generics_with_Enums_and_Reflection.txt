GENERICS WITH ENUMS AND REFLECTION
=====================================

GENERICS AND ENUMS
-------------------
  Enums in Java use a recursive generic type bound:
    public abstract class Enum<E extends Enum<E>> implements Comparable<E>, Serializable { }

  Every enum class implicitly extends Enum<itself>:
    public enum Day extends Enum<Day> { ... }  // conceptually (not written in code)

  Why the recursive bound?
  - Comparable<E> ensures each enum can only be compared with instances of the SAME enum type
  - Day.compareTo(Day other) ✅, not Day.compareTo(Color other) ❌

  Using EnumSet and EnumMap — highly efficient generic collections for enums:
    EnumSet<Day> weekdays = EnumSet.of(Day.MON, Day.TUE, Day.WED, Day.THU, Day.FRI);
    EnumMap<Day, String> schedule = new EnumMap<>(Day.class);
    schedule.put(Day.MON, "Meeting");
    schedule.put(Day.FRI, "Review");

    // EnumSet operations
    EnumSet<Day> weekend = EnumSet.complementOf(weekdays); // SAT, SUN
    boolean isFriday = weekdays.contains(Day.FRI); // ✅

  Performance: EnumSet backed by bit vector — O(1) all operations, minimal memory.
               EnumMap backed by array indexed by enum ordinal — O(1) all operations.

GENERIC ENUM PATTERN
---------------------
  // Generic enum for typed operations
  public enum Operation {
      PLUS { @Override public int apply(int x, int y) { return x + y; } },
      MINUS { @Override public int apply(int x, int y) { return x - y; } },
      TIMES { @Override public int apply(int x, int y) { return x * y; } };

      public abstract int apply(int x, int y);
  }

  for (Operation op : Operation.values()) {
      System.out.printf("3 %s 2 = %d%n", op, op.apply(3, 2));
  }

GENERICS AND REFLECTION
------------------------
  Reflection can inspect some generic type information that survives erasure.
  This is NOT the type-parameter values (those are erased), but the DECLARED
  type signatures in class/method/field definitions (stored in bytecode).

  java.lang.reflect provides:
    - Class<?>                — for raw type info
    - ParameterizedType       — represents a parameterized type like List<String>
    - TypeVariable<D>         — a type variable like T in class Box<T>
    - WildcardType            — represents ? extends Foo or ? super Foo
    - GenericArrayType        — represents T[] or List<String>[]
    - Type (interface)        — common supertype for all of the above

  Example — reading generic type information from a field:
    class Container {
        List<String> items;
    }

    Field field = Container.class.getDeclaredField("items");
    Type genericType = field.getGenericType();          // List<String> (ParameterizedType)
    System.out.println(genericType);                     // java.util.List<java.lang.String>

    if (genericType instanceof ParameterizedType pt) {
        Type[] typeArgs = pt.getActualTypeArguments();   // [String]
        System.out.println(typeArgs[0]);                 // class java.lang.String
    }

  Example — reading generic type information from a method:
    class Service {
        public List<String> getNames() { return null; }
    }

    Method method = Service.class.getMethod("getNames");
    Type returnType = method.getGenericReturnType();     // List<String>

    if (returnType instanceof ParameterizedType pt) {
        Type[] args = pt.getActualTypeArguments();       // [String]
    }

  Example — reading class type parameters:
    class Pair<A, B> { A first; B second; }

    TypeVariable<?>[] typeParams = Pair.class.getTypeParameters(); // [A, B]
    System.out.println(typeParams[0].getName()); // A
    System.out.println(typeParams[1].getName()); // B
    // Note: actual runtime arguments (String, Integer) are ERASED — only names remain

SUPER TYPE TOKEN PATTERN (PRESERVING TYPE AT RUNTIME)
-------------------------------------------------------
  Problem: Type erasure means Map<String, Integer> loses its type args at runtime.
  Solution: Store the type in a subclass — subclass type relationship is stored in bytecode.

  // Super Type Token — captures type at declaration time (not erased)
  abstract class TypeToken<T> {
      private final Type type;
      protected TypeToken() {
          // getClass() returns the anonymous/concrete subclass
          // getSuperclass() returns TypeToken<T>
          // getGenericSuperclass() returns the ParameterizedType with T
          Type superclass = getClass().getGenericSuperclass();
          this.type = ((ParameterizedType) superclass).getActualTypeArguments()[0];
      }
      public Type getType() { return type; }
  }

  // Usage:
  TypeToken<Map<String, Integer>> token = new TypeToken<Map<String, Integer>>() {};
  System.out.println(token.getType()); // java.util.Map<java.lang.String, java.lang.Integer>
  // Type information is preserved because it's in the declaration, not at runtime

  // Used by Jackson, Gson, Spring:
  TypeReference<List<Person>> typeRef = new TypeReference<List<Person>>() {};
  List<Person> persons = objectMapper.readValue(json, typeRef); // knows element type!

  // Spring's ParameterizedTypeReference:
  ResponseEntity<List<User>> response = restTemplate.exchange(
      url, HttpMethod.GET, null,
      new ParameterizedTypeReference<List<User>>() {}
  );

CLASS<T> AS TYPE TOKEN
-----------------------
  Class<T> itself is a type token for simple (non-parameterized) types.
  Cannot represent List<String> (only List.class = Class<List>).

  // Works for simple types:
  Class<String> strClass = String.class;
  String instance = strClass.cast(someObject); // safe cast via reflection

  // For parameterized types — must use TypeToken pattern above
  // (Jackson, Spring, Guava all provide TypeToken-like solutions)

COMMON INTERVIEW QUESTIONS
---------------------------
Q: How can you preserve generic type information at runtime despite type erasure?
A: Using the Super Type Token pattern: create an anonymous subclass of a generic class.
   The subclass's generic supertype is stored in bytecode as a ParameterizedType.
   Access via getClass().getGenericSuperclass(). This is how Jackson's TypeReference,
   Spring's ParameterizedTypeReference, and Guava's TypeToken work.

Q: What is ParameterizedType in reflection?
A: java.lang.reflect.ParameterizedType represents a parameterized type like List<String>
   or Map<String, Integer>. Accessible via Field.getGenericType(),
   Method.getGenericReturnType(), etc. Has methods:
   getRawType() — the raw class (List.class)
   getActualTypeArguments() — the type arguments ([String.class])
   These are the DECLARED type arguments in source code (preserved in bytecode),
   not runtime instances (which are erased).

Q: Can you use Class<T> to represent List<String> as a type token?
A: No. Class<T> can only represent raw types (Class<List>, Class<String>).
   It cannot represent parameterized types like List<String>.
   For parameterized types, use the Super Type Token pattern (TypeToken, TypeReference)
   which captures the type in a subclass declaration that is preserved in bytecode.

Q: What is EnumSet and why is it faster than HashSet<Enum>?
A: EnumSet is a specialized Set implementation for enum types backed by a bit vector
   (long or long[] depending on enum size). Each enum constant maps to a bit position.
   add/remove/contains: bitwise operations — O(1) and extremely fast.
   Iteration: sequential bit scan — faster than hash table traversal.
   Memory: minimal — just a long (or small array of longs) for the bit vector.
   RegularEnumSet handles enums with ≤ 64 values; JumboEnumSet handles more.
