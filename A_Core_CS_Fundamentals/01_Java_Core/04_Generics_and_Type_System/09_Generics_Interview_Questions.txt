GENERICS INTERVIEW QUESTIONS
==============================

TOP GENERICS INTERVIEW QUESTIONS AND ANSWERS
---------------------------------------------

Q1: What are Java Generics? Why were they introduced?
A: Generics allow writing type-safe, reusable code using type parameters (T, E, K, V, etc.)
   that are specified at compile time. Introduced in Java 5 to:
   1. Eliminate ClassCastException at runtime — errors caught at compile time
   2. Eliminate manual casting — compiler inserts casts automatically
   3. Enable code reuse — write once, work with any type
   Before generics: List stored Object — everything required explicit (Type) casting,
   and any type could be added to any list.

Q2: What is type erasure in Java Generics?
A: Type erasure is the process where generic type parameters are removed at compile time.
   The compiled bytecode contains no type parameters:
   - Unbounded T → replaced by Object
   - Bounded <T extends Foo> → replaced by Foo
   - Compiler inserts casts at call sites
   This maintains backward compatibility with pre-Java 5 JVMs.
   Key consequences: cannot use instanceof with parameterized types, cannot create new T[],
   cannot instantiate T, method overloads that differ only in type parameter are rejected.

Q3: What is the difference between List<Object> and List<?>?
A: List<Object>:
   - Specific parameterization — only List<Object> is assignable to it
   - Can add any Object to it: list.add("hello"), list.add(42)
   - List<String> is NOT assignable to List<Object> (generics are invariant)
   List<?>:
   - Wildcard — any List (List<String>, List<Integer>, etc.) is assignable to it
   - CANNOT add anything (except null) — type is unknown
   - Only reads as Object
   Key difference: List<String> → List<?> ✅, but List<String> → List<Object> ❌

Q4: What is PECS? Give a real example.
A: PECS = Producer Extends, Consumer Super:
   - If you READ from a collection (it produces values for you): use <? extends T>
   - If you WRITE to a collection (it consumes your values): use <? super T>
   Real example — Collections.copy:
     public static <T> void copy(List<? super T> dest, List<? extends T> src) { ... }
     src is the producer (we read from it) → extends
     dest is the consumer (we write to it) → super
   Another: stack.push uses <? super T>, stack.pop uses <? extends T>

Q5: Can you use generics with static fields?
A: No. A static field is shared by ALL instances of the class.
   But Box<String> and Box<Integer> are different uses of the same class.
   If static T field were allowed, it would be ambiguous — is it String or Integer?
   Static methods can declare their OWN type parameters, independent of the class:
     class Box<T> {
         static <E> Box<E> of(E val) { ... } // method's own E, not class's T
     }

Q6: Why is List<String> not a subtype of List<Object>?
A: Generics are INVARIANT — no subtype relationship between different parameterizations.
   If it were allowed:
     List<Object> obj = new ArrayList<String>(); // if this compiled
     obj.add(42);  // would insert Integer into what's really a List<String>!
   Java prevents this at compile time. Arrays have this problem at runtime (ArrayStoreException).
   Use List<? extends Object> for read-only covariant access.

Q7: What is the wildcard capture error?
A: When you try to write to a List<?>, you get a "capture" error because the compiler
   cannot determine the actual type:
     List<?> list = new ArrayList<String>();
     list.add("hello"); // ❌ error: cannot add to wildcard
   Fix: use a wildcard capture helper method:
     private <T> void helper(List<T> list) { list.add(list.get(0)); }
     public void duplicate(List<?> list) { helper(list); } // type captured as T

Q8: What is the difference between ? extends T and ? super T for Comparator?
A: For sorting and Comparable, the pattern is:
     <T extends Comparable<? super T>>
   Using ? super T allows Dog (extends Animal) to use Animal's compareTo method
   (defined on Animal), without Dog explicitly implementing Comparable<Dog>.
   This is more flexible — a subclass inherits the natural ordering from its supertype.

Q9: How do you create a generic method that returns the minimum of a collection?
A: 
   public static <T extends Comparable<? super T>> T min(Collection<? extends T> coll) {
       Iterator<? extends T> iter = coll.iterator();
       T min = iter.next();
       while (iter.hasNext()) {
           T next = iter.next();
           if (next.compareTo(min) < 0) min = next;
       }
       return min;
   }
   The <? super T> in Comparable bound allows subtypes to use supertype's compareTo.
   The <? extends T> in Collection allows passing Collection<Integer> for T=Number.

Q10: What are bridge methods and why does the compiler generate them?
A: Bridge methods are synthetic methods generated by the compiler to maintain
   polymorphism after type erasure.
   Example: StringList extends ArrayList<String> with override add(String).
   After erasure, ArrayList has add(Object). StringList overrides add(String).
   The compiler generates a bridge method add(Object) in StringList that delegates to add(String).
   This allows a StringList reference held as ArrayList to correctly dispatch the add call.

Q11: What is heap pollution and @SafeVarargs?
A: Heap pollution: a variable of parameterized type holds an object of wrong parameterization.
   Causes unexpected ClassCastException. Common cause: generic vararg parameters.
   @SafeVarargs: annotation that tells the compiler (and callers) that a generic vararg method
   is safe — the vararg array is not stored or exposed unsafely.
   Apply only when: you only read from the vararg array and don't pass it to other code.

Q12: Can you explain recursive type bounds?
A: Recursive type bound: a type parameter is bounded by a generic type involving itself.
   Most common: <T extends Comparable<T>> — T can compare with instances of its own type.
   More flexible: <T extends Comparable<? super T>> — T's compareTo can be defined on
   a supertype of T, allowing subclasses to inherit natural ordering.
   Another example: <E extends Enum<E>> — each enum class E IS-A Enum<E> (self-referential).

Q13: What is a type token (Class<T>) and what is it used for?
A: A type token carries type information at runtime, working around type erasure.
   Class<T> is a parameterized type — Class<String> is different from Class<Integer>.
   Uses:
   1. Type-safe heterogeneous containers (Map<Class<?>, Object> — insert with Class<T> key)
   2. Reflective instantiation: type.getDeclaredConstructor().newInstance()
   3. Safe cast: type.cast(object) — throws ClassCastException instead of warning
   4. Frameworks (Jackson, Spring) use Class<T> as type hints for deserialization.

Q14: What happens if you mix raw types and generics?
A: You get "unchecked" compiler warnings, and potentially heap pollution at runtime.
   Raw types bypass ALL generic type checking.
     List<String> strings = new ArrayList<>();
     List rawList = strings;  // raw assignment
     rawList.add(42);          // no compile error! pollutes strings
     String s = strings.get(0); // ClassCastException at runtime
   Never mix raw types and generics. Enable -Xlint:unchecked to see all warnings.

Q15: How does Java handle generic exceptions?
A: You can:
   - Declare a generic class that extends Throwable/Exception
   - Store a type parameter in the exception object
   You CANNOT:
   - Catch a parameterized exception: catch (MyException<String> e) — type erased
   - Throw a type parameter: throw new T() — can't instantiate T
   Workaround for typed exceptions:
     class TypedResult<T, E extends Exception> {
         Either<T, E> compute() throws E { ... }
     }
