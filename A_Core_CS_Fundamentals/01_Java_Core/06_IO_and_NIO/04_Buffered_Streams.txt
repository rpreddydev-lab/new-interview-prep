BUFFERED STREAMS
==================

WHY BUFFERING MATTERS
-----------------------
  Every call to read()/write() on an unbuffered stream (FileInputStream, FileOutputStream)
  typically translates to a SYSTEM CALL — a context switch from user space to kernel space.
  System calls are expensive (~1–5 microseconds each).

  For a 1MB file read byte-by-byte: ~1,000,000 system calls.
  For the same file with 8KB buffering: ~125 system calls. (~8000x fewer)

  Buffered streams maintain an internal byte[] or char[] buffer.
  - BufferedInputStream fills the buffer from the underlying stream in one read.
    Subsequent reads are served from the in-memory buffer (no system call).
  - BufferedOutputStream accumulates writes in the buffer.
    The underlying stream is written only when the buffer is full or flush() is called.

BUFFEREDINPUTSTREAM
--------------------
  Wraps any InputStream. Default buffer: 8192 bytes.

  // Usage pattern — always wrap FileInputStream:
  try (InputStream is = new BufferedInputStream(new FileInputStream("large.bin"), 16384)) {
      byte[] data = new byte[1024];
      int read;
      while ((read = is.read(data)) != -1) {
          process(data, 0, read);
      }
  }

  // Supports mark/reset:
  try (InputStream is = new BufferedInputStream(new FileInputStream("data.bin"))) {
      is.mark(100);          // mark current position, allow looking ahead up to 100 bytes
      byte[] peek = new byte[4];
      is.read(peek);         // read 4 bytes to identify format
      is.reset();            // jump back to the marked position
      // now re-read with full context
  }

BUFFEREDOUTPUTSTREAM
---------------------
  Wraps any OutputStream. Default buffer: 8192 bytes.

  // Usage pattern:
  try (OutputStream os = new BufferedOutputStream(new FileOutputStream("output.bin"))) {
      for (byte b : data) {
          os.write(b);  // fast — writes to buffer, not disk
      }
      // flush() called automatically by close()
  }

  // IMPORTANT: flush() before close when chaining streams:
  BufferedOutputStream bos = new BufferedOutputStream(socket.getOutputStream());
  bos.write(requestData);
  bos.flush();  // ← send data over the network NOW (before waiting for response)
  // then read response...

BUFFEREDREADER
---------------
  Wraps any Reader. Default buffer: 8192 characters.
  Adds readLine() — reads a complete line, stripping the newline character.

  // Read file line by line:
  try (BufferedReader br = new BufferedReader(
          new FileReader("data.csv", StandardCharsets.UTF_8))) {
      String line;
      while ((line = br.readLine()) != null) {
          String[] parts = line.split(",");
          // process each CSV row
      }
  }

  // Java 8+: lines() returns a lazy Stream<String>:
  try (BufferedReader br = Files.newBufferedReader(Path.of("file.txt"), StandardCharsets.UTF_8)) {
      long wordCount = br.lines()
          .flatMap(line -> Arrays.stream(line.split("\\s+")))
          .filter(word -> !word.isEmpty())
          .count();
  }

  // readLine() returns null at EOF:
  String line = br.readLine();  // null = end of stream (not -1, not "")

BUFFEREDWRITER
---------------
  Wraps any Writer. Default buffer: 8192 characters.
  Adds newLine() — writes the platform-specific line separator.

  try (BufferedWriter bw = new BufferedWriter(
          new FileWriter("output.txt", StandardCharsets.UTF_8))) {
      bw.write("Line 1");
      bw.newLine();        // \n on Unix, \r\n on Windows
      bw.write("Line 2");
      bw.newLine();
  }
  // close() calls flush() automatically

  // Java 7+: Files.newBufferedWriter (preferred):
  try (BufferedWriter bw = Files.newBufferedWriter(
          Path.of("output.txt"), StandardCharsets.UTF_8,
          StandardOpenOption.CREATE, StandardOpenOption.TRUNCATE_EXISTING)) {
      bw.write("Content");
      bw.newLine();
  }

BUFFER SIZE TUNING
-------------------
  Default buffer size is 8192 bytes (8KB).
  For large sequential file reads, larger buffers can improve throughput:
  - 16KB or 64KB: good for most cases
  - Larger buffers rarely help beyond OS page size (usually 4KB–64KB)
  - Profile before tuning — default is usually fine

  // Custom buffer size:
  new BufferedInputStream(fis, 65536);   // 64KB
  new BufferedReader(reader, 32768);     // 32K chars

FLUSH SEMANTICS
-----------------
  flush() on a BufferedOutputStream/BufferedWriter:
  - Forces all buffered data to the underlying stream
  - Does NOT guarantee data is written to disk (the OS may buffer it further)
  - For guaranteed disk persistence, use FileChannel.force(true) or RandomAccessFile.getFD().sync()

  When is flush() needed?
  - Writing to network sockets — data must be sent before reading the response
  - Writing to another process via PipedStream — the reading thread needs the data
  - Logging in long-running applications — ensure log entries are written even if program doesn't terminate normally
  - close() always calls flush() first — so normal close covers most cases

DECORATOR CHAIN SUMMARY
-------------------------
  Typical read chain:
    FileInputStream (file data)
      └── BufferedInputStream (buffering)
            └── DataInputStream (primitive reading)  OR
            └── ObjectInputStream (deserialization)

  Typical write chain:
    FileOutputStream (file destination)
      └── BufferedOutputStream (buffering)
            └── DataOutputStream (primitive writing)  OR
            └── ObjectOutputStream (serialization)

  Typical text read chain:
    FileInputStream (file data)
      └── InputStreamReader (bytes → chars with charset)
            └── BufferedReader (buffering + readLine())

  Typical text write chain:
    FileOutputStream (file destination)
      └── OutputStreamWriter (chars → bytes with charset)
            └── BufferedWriter (buffering + newLine())

COMMON INTERVIEW QUESTIONS
---------------------------
Q: What is the purpose of BufferedInputStream?
A: BufferedInputStream wraps another InputStream and maintains an internal byte buffer
   (default 8KB). When data is requested, it reads a full buffer from the underlying
   stream (1 system call), then serves subsequent reads from this in-memory buffer.
   This dramatically reduces system call overhead. For sequential file reading,
   BufferedInputStream can provide 10–100x faster throughput compared to unbuffered reading.

Q: When must you call flush() explicitly on a BufferedOutputStream?
A: When you need buffered data to be written to the underlying stream BEFORE close() is called.
   Common cases: after writing a request to a network socket before reading the response;
   writing progress to a log file before the program might crash; writing to a PipedOutputStream
   before the reader thread processes data. Note: close() always calls flush() first.

Q: What does BufferedReader.readLine() return at end of file? How is it different from read()?
A: readLine() returns null at EOF. The raw read() methods return -1 at EOF.
   readLine() strips the newline characters from the returned string.
   If the file ends without a newline, the last line is still returned normally (not as null).
   null is returned ONLY when there are no more lines at all.
