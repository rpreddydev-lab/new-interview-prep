JAVA I/O OVERVIEW
==================

WHAT IS JAVA I/O?
------------------
  Java I/O (Input/Output) is the mechanism by which Java programs communicate with
  external systems: file system, network sockets, standard streams (stdin/stdout),
  memory buffers, and inter-process communication.

  Java provides three generations of I/O APIs:
  1. java.io   — stream-based, blocking (original I/O, Java 1.0+)
  2. java.nio  — channel/buffer-based, non-blocking capable (NIO, Java 1.4+)
  3. java.nio.file — modern file API with Path (NIO.2, Java 7+)

STREAM FUNDAMENTALS (java.io)
-------------------------------
  A Stream is a sequential, one-directional flow of data.
  Streams are unidirectional: you READ from an InputStream or WRITE to an OutputStream.

  Two fundamental categories:
    Byte Streams   — read/write raw binary data (InputStream / OutputStream hierarchy)
    Character Streams — read/write text, handling character encoding (Reader / Writer hierarchy)

  The 4 abstract base classes:
    java.io.InputStream     — abstract base for reading bytes
    java.io.OutputStream    — abstract base for writing bytes
    java.io.Reader          — abstract base for reading characters
    java.io.Writer          — abstract base for writing characters

BYTE STREAM HIERARCHY
-----------------------
  InputStream
  ├── FileInputStream            — read bytes from a file
  ├── ByteArrayInputStream       — read from a byte[] in memory
  ├── BufferedInputStream        — wrap any InputStream with a buffer
  ├── DataInputStream            — read Java primitives from a stream
  ├── ObjectInputStream          — deserialize Java objects
  ├── FilterInputStream          — base for decorator streams
  └── PipedInputStream           — inter-thread communication

  OutputStream
  ├── FileOutputStream           — write bytes to a file
  ├── ByteArrayOutputStream      — write to a byte[] in memory
  ├── BufferedOutputStream       — wrap any OutputStream with a buffer
  ├── DataOutputStream           — write Java primitives to a stream
  ├── ObjectOutputStream         — serialize Java objects
  ├── PrintStream                — print text (used by System.out)
  └── PipedOutputStream          — inter-thread communication

CHARACTER STREAM HIERARCHY
-----------------------------
  Reader
  ├── FileReader                 — read characters from a file (uses default charset)
  ├── InputStreamReader          — bridge: convert byte stream to character stream
  ├── BufferedReader             — buffered reading, provides readLine()
  ├── StringReader               — read from a String in memory
  └── CharArrayReader            — read from a char[] in memory

  Writer
  ├── FileWriter                 — write characters to a file
  ├── OutputStreamWriter         — bridge: convert character stream to byte stream
  ├── BufferedWriter             — buffered writing, provides newLine()
  ├── PrintWriter                — formatted text output (println, printf)
  ├── StringWriter               — write to a String (via StringBuffer)
  └── CharArrayWriter            — write to a char[] in memory

THE DECORATOR PATTERN IN java.io
-----------------------------------
  java.io streams use the Decorator Pattern extensively:
  you wrap a basic stream with additional functionality.
  Each wrapper adds a feature (buffering, data conversion, compression, etc.)
  while maintaining the same stream interface.

  // Layer by layer — each adds a capability:
  FileInputStream fis      = new FileInputStream("data.bin");       // raw bytes from file
  BufferedInputStream bis  = new BufferedInputStream(fis);          // adds buffering
  DataInputStream dis      = new DataInputStream(bis);              // adds readInt/readDouble

  // Read a primitive:
  int value = dis.readInt();

  // Closing the outermost stream closes all wrapped streams:
  dis.close(); // closes DataInputStream → BufferedInputStream → FileInputStream

  Text example:
  FileReader fr            = new FileReader("log.txt");
  BufferedReader br        = new BufferedReader(fr);  // adds readLine()
  String line;
  while ((line = br.readLine()) != null) {
      process(line);
  }
  br.close();

STANDARD STREAMS
-----------------
  System.in   — InputStream connected to keyboard / stdin
  System.out  — PrintStream connected to stdout (usually terminal)
  System.err  — PrintStream connected to stderr (error output)

  // Read a line from keyboard:
  BufferedReader console = new BufferedReader(new InputStreamReader(System.in));
  String input = console.readLine();

  // Or use Scanner (convenience wrapper):
  Scanner scanner = new Scanner(System.in);
  String line = scanner.nextLine();
  int number  = scanner.nextInt();

ENCODING AWARENESS
-------------------
  FileReader / FileWriter use the PLATFORM DEFAULT charset — a portability hazard.
  Always specify charset explicitly when dealing with text:

  // ❌ Platform-dependent — breaks on different OS/locales:
  Reader r = new FileReader("file.txt");

  // ✅ Explicit charset — portable:
  Reader r = new InputStreamReader(new FileInputStream("file.txt"), StandardCharsets.UTF_8);

  // ✅ Using Files API (Java 7+) — clean and charset-explicit:
  List<String> lines = Files.readAllLines(Path.of("file.txt"), StandardCharsets.UTF_8);

GENERATION COMPARISON TABLE
-----------------------------
  Feature                | java.io (Streams)    | java.nio (Channels)   | java.nio.file (NIO.2)
  -----------------------|----------------------|-----------------------|----------------------
  Introduced             | Java 1.0             | Java 1.4              | Java 7
  Abstraction            | Stream               | Channel + Buffer      | Path + Files
  Blocking               | Yes (always)         | Optional (Selector)   | Yes (but async option)
  File operations        | File class (limited) | FileChannel           | Files, Path (rich)
  Directory watching     | No                   | No                    | WatchService
  Symbolic links         | No                   | No                    | Yes
  File attributes        | Basic                | Basic                 | Rich (owner, ACL, etc.)
  Byte ordering          | N/A                  | ByteBuffer.order()    | N/A
  Scatter/gather I/O     | No                   | Yes                   | No
  Memory-mapped files    | No                   | MappedByteBuffer      | No
  Use today for files    | Legacy               | High-perf I/O         | ✅ Preferred (simple API)

COMMON INTERVIEW QUESTIONS
---------------------------
Q: What is the difference between byte streams and character streams?
A: Byte streams (InputStream/OutputStream) work with raw 8-bit bytes and are used for
   binary data (images, audio, serialized objects). Character streams (Reader/Writer)
   work with 16-bit Unicode characters and automatically handle charset encoding/decoding,
   making them appropriate for text files. Use character streams when dealing with text
   to avoid charset issues.

Q: What design pattern does java.io use?
A: The Decorator Pattern. Basic streams (FileInputStream, FileWriter) provide the core
   data source/sink. Decorator classes (BufferedInputStream, DataInputStream, ObjectInputStream)
   wrap basic or other decorator streams, adding functionality while conforming to the same
   interface. You compose a stack of decorators: new DataInputStream(new BufferedInputStream(
   new FileInputStream("file.bin"))).

Q: What are the three generations of Java I/O?
A: 1) java.io — original, stream-based, always blocking, introduced in Java 1.0.
   2) java.nio — introduced in Java 1.4; channel and buffer abstractions; supports
      non-blocking I/O via Selectors (multiplexed I/O for scalable servers).
   3) java.nio.file (NIO.2) — introduced in Java 7; modern file system API with
      Path, Files utility class, WatchService, and rich file attributes. For most file
      operations today, NIO.2 is the preferred choice.
