StringBuilder vs StringBuffer
==============================

THE PROBLEM WITH STRING CONCATENATION
--------------------------------------
String is immutable — every + creates a new String object:
  String s = "";
  for (int i = 0; i < 1000; i++) s += i;  // 1000 String objects created on heap

Solution: use a mutable character buffer → StringBuilder or StringBuffer.

StringBuilder (java.lang.StringBuilder — Java 5+)
--------------------------------------------------
  - MUTABLE sequence of characters.
  - NOT thread-safe (no synchronization).
  - Backed by a char[] that grows dynamically.
  - Default capacity: 16 characters; grows when needed.
  - PREFERRED choice in single-threaded contexts.

  StringBuilder sb = new StringBuilder();           // capacity 16
  StringBuilder sb = new StringBuilder(64);         // initial capacity 64
  StringBuilder sb = new StringBuilder("Hello");    // from String

  KEY METHODS:
    append(x)          — adds to end (supports all types: int, char, String, Object...)
    insert(index, x)   — inserts at position
    delete(start, end) — removes characters from start (inclusive) to end (exclusive)
    deleteCharAt(i)    — removes single character at index
    replace(s, e, str) — replaces s to e with str
    reverse()          — reverses content
    charAt(i)          — get char at index
    setCharAt(i, c)    — set char at index
    indexOf(str)       — find first occurrence
    length()           — current length
    capacity()         — current buffer capacity
    toString()         — convert to immutable String

  Example:
    StringBuilder sb = new StringBuilder();
    sb.append("Hello").append(", ").append("World").append("!");
    String result = sb.toString();  // "Hello, World!"

  Reverse a String using StringBuilder:
    String reversed = new StringBuilder("abcde").reverse().toString();  // "edcba"

StringBuffer (java.lang.StringBuffer — Java 1.0)
-------------------------------------------------
  - MUTABLE sequence of characters.
  - THREAD-SAFE: all methods are synchronized.
  - Slower than StringBuilder due to synchronization overhead.
  - Same API as StringBuilder.
  - Use only when shared across multiple threads.

COMPARISON TABLE
-----------------
| Feature           | StringBuilder       | StringBuffer        | String              |
|-------------------|---------------------|---------------------|---------------------|
| Mutability        | Mutable             | Mutable             | Immutable           |
| Thread Safety     | ❌ Not thread-safe  | ✅ Thread-safe       | ✅ Immutable = safe  |
| Performance       | Fast                | Slower (sync)       | Slow for concat loop|
| Introduced        | Java 5              | Java 1.0            | Java 1.0            |
| Use case          | Single-thread build | Multi-thread build  | Fixed strings       |

WHEN TO USE WHAT
-----------------
  String:        Use for fixed text, literals, keys, constants.
  StringBuilder: Use for dynamic string building in loops, parsers, builders — single thread.
  StringBuffer:  Use when a mutable string is shared and modified across multiple threads.
                 (Rare in practice — use StringBuilder + external sync or ConcurrentLinkedQueue.)

STRING BUILDER CAPACITY MANAGEMENT
-------------------------------------
  StringBuilder doubles capacity + 2 when full:
    new capacity = (old capacity * 2) + 2

  Pre-sizing avoids reallocations:
    // Good: if you know final size
    StringBuilder sb = new StringBuilder(items.size() * 20);

JAVA COMPILER AND StringBuilder
---------------------------------
  The Java compiler automatically converts + concatenation to StringBuilder:
    "Hello" + name + "!"
    → new StringBuilder().append("Hello").append(name).append("!").toString()

  But it cannot optimize ACROSS loop iterations:
    String s = "";
    for (int i = 0; i < n; i++) s += i;  // NEW StringBuilder every iteration!

  This is why explicit StringBuilder in loops is critical for performance.

COMMON INTERVIEW QUESTIONS
---------------------------
Q: What is the difference between String, StringBuilder, and StringBuffer?
A: String: immutable — every modification creates new object. Ideal for fixed text.
   StringBuilder: mutable, not thread-safe, fast. Use in single-threaded string building.
   StringBuffer: mutable, thread-safe (synchronized methods), slower. Use when mutable string
   shared across threads (rare scenario in modern code).

Q: Why is String concatenation in a loop bad?
A: Each s = s + something creates a new String object and discards the old one.
   For n iterations, this creates O(n) objects and copies O(n²) characters in total.
   StringBuilder.append() is O(n) total — amortized O(1) per append.

Q: Is StringBuffer still useful in modern Java?
A: Rarely. Modern concurrent code uses higher-level constructs (streams, concurrent collections).
   If you truly need a thread-safe mutable string, StringBuffer is valid, but you can often
   use StringBuilder with proper external synchronization (synchronized block / lock).

Q: How do you reverse a String in Java?
A: new StringBuilder(str).reverse().toString()
   — the simplest one-liner using StringBuilder.reverse().

Q: What is the initial capacity of StringBuilder and how does it grow?
A: Default initial capacity is 16 characters. When full, it grows to (current * 2) + 2.
   You can set initial capacity via constructor: new StringBuilder(expectedSize) to avoid
   repeated reallocations for performance-critical code.
