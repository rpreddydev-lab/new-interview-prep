ABSTRACTION — ABSTRACT CLASSES vs INTERFACES
=============================================

WHAT IS ABSTRACTION?
--------------------
Abstraction means hiding implementation complexity and exposing only the essential behavior.
"What it does" not "how it does it."

Achieved in Java via:
  1. Abstract classes (partial abstraction)
  2. Interfaces (full abstraction — pre-Java 8)

ABSTRACT CLASS
--------------
  - Declared with the `abstract` keyword.
  - Cannot be instantiated — only subclassed.
  - Can have:
      • Abstract methods (no body — MUST be implemented by concrete subclasses)
      • Concrete methods (with body — inherited as-is or overridden)
      • Fields (any access level, including private)
      • Constructors (used by subclass via super())
      • Static methods

  abstract class Vehicle {
      private String brand;  // can have state

      Vehicle(String brand) { this.brand = brand; }  // constructor

      abstract void startEngine();  // MUST override

      void honk() {                 // concrete — inherited
          System.out.println(brand + " beep!");
      }
      String getBrand() { return brand; }
  }

  class Car extends Vehicle {
      Car(String brand) { super(brand); }
      @Override
      void startEngine() { System.out.println("Car engine vroom"); }
  }

INTERFACE
---------
  - Declared with the `interface` keyword.
  - Cannot be instantiated.
  - All fields are implicitly: public static final (constants).
  - Pre-Java 8: All methods implicitly public abstract.
  - Java 8+: Can have default methods (concrete) and static methods.
  - Java 9+: Can have private methods (for reuse within the interface).
  - A class can implement MULTIPLE interfaces.

  interface Flyable {
      int MAX_ALTITUDE = 40000;  // implicitly public static final

      void fly();                // implicitly public abstract

      default void land() {      // Java 8+ default method
          System.out.println("Landing...");
      }

      static void checkWeather() {  // Java 8+ static method
          System.out.println("Checking weather...");
      }
  }

  class Bird implements Flyable {
      @Override
      public void fly() { System.out.println("Bird flying"); }
  }

ABSTRACT CLASS vs INTERFACE — COMPARISON TABLE
----------------------------------------------
| Feature                   | Abstract Class              | Interface                        |
|---------------------------|-----------------------------|----------------------------------|
| Keyword                   | abstract class              | interface                        |
| Instantiation             | No                          | No                               |
| Extends/Implements        | extends (single)            | implements (multiple)            |
| Fields                    | Any type                    | public static final only         |
| Constructors              | Yes                         | No                               |
| Abstract methods          | Optional                    | All (pre-Java8), optional now    |
| Concrete methods          | Yes                         | Yes (default/static, Java 8+)    |
| Access modifiers          | Any                         | public only (pre-Java9)          |
| State                     | Yes (instance fields)       | No instance state                |
| Multiple inheritance      | No (single extends)         | Yes (multiple implements)        |
| IS-A relationship         | Yes                         | Yes (contract)                   |

WHEN TO USE WHICH?
------------------
  Use ABSTRACT CLASS when:
    - You want to share code (concrete methods) among closely related classes.
    - You need constructor logic or instance state.
    - Classes share a common base with partial implementation (Template Method pattern).
    - Example: AbstractList, HttpServlet

  Use INTERFACE when:
    - Defining a contract/capability for unrelated classes.
    - You need multiple inheritance of type.
    - You want to define a role/behavior independent of class hierarchy.
    - Example: Comparable, Runnable, Serializable, Iterable

INTERFACE DEFAULT METHOD CONFLICTS
------------------------------------
  If two interfaces provide the same default method, the implementing class MUST override it:

  interface A { default void hello() { System.out.println("A"); } }
  interface B { default void hello() { System.out.println("B"); } }

  class C implements A, B {
      @Override
      public void hello() {
          A.super.hello();  // explicit choice to call A's version
      }
  }

FUNCTIONAL INTERFACE
---------------------
  An interface with exactly ONE abstract method is a functional interface.
  Can be used with lambdas and method references.
  @FunctionalInterface annotation enforces this (optional but recommended).

  @FunctionalInterface
  interface Greeter {
      void greet(String name);
  }
  Greeter g = name -> System.out.println("Hello, " + name);
  g.greet("Alice");  // Hello, Alice

COMMON INTERVIEW QUESTIONS
---------------------------
Q: What is the difference between abstract class and interface?
A: Abstract class: can have state (instance fields), constructors, concrete methods, any access
   modifiers; single inheritance only. Interface: no instance state, no constructors, all fields
   are constants; supports multiple implementation. Use abstract class for IS-A with shared code;
   use interface for capability/contract across unrelated classes.

Q: Can an interface have a constructor?
A: No. Interfaces cannot be instantiated, so constructors make no sense. They have no instance
   state to initialize.

Q: Can abstract classes have concrete methods?
A: Yes — abstract classes can have any mix of abstract and concrete methods. The concrete methods
   are inherited by all subclasses. This is the Template Method pattern: define the algorithm
   skeleton in abstract class, let subclasses fill in the abstract steps.

Q: What changed in interfaces from Java 8?
A: Java 8 added default methods (concrete methods with default implementation) and static methods.
   Java 9 added private methods (for code reuse within the interface itself).
   These changes enabled backwards-compatible additions to existing interfaces (e.g., adding
   forEach to Iterable without breaking all existing implementations).

Q: Can you instantiate an abstract class?
A: No directly. But you can create an anonymous class that extends it:
     Vehicle v = new Vehicle("Anon") {
         @Override void startEngine() { System.out.println("anon start"); }
     };
