NESTED AND INNER CLASSES
=========================

OVERVIEW
--------
Java allows defining a class inside another class. These are called nested classes.

Four types:
  1. Static Nested Class       — static member of outer class
  2. Non-static Inner Class    — instance member of outer class (has outer reference)
  3. Local Class               — defined inside a method
  4. Anonymous Class           — defined and instantiated inline (no name)

1. STATIC NESTED CLASS
-----------------------
  - Declared with `static` inside another class.
  - Does NOT hold a reference to the enclosing outer class instance.
  - Behaves like a top-level class that happens to be nested (for packaging purposes).
  - Can access outer class STATIC members directly; NOT instance members.

  class Outer {
      private static int outerStatic = 10;
      private int outerInstance = 20;

      static class StaticNested {
          void display() {
              System.out.println(outerStatic);     // OK — static member
              // System.out.println(outerInstance); // ERROR — instance member
          }
      }
  }

  // Instantiation: no outer object needed
  Outer.StaticNested nested = new Outer.StaticNested();
  nested.display();

  Common use: Builder pattern (MyClass.Builder), Entry in Map.Entry.

2. NON-STATIC INNER CLASS
--------------------------
  - Regular non-static member of the outer class.
  - Holds an implicit reference to the enclosing outer class instance.
  - Can access ALL outer class members (including private instance fields).
  - Cannot have static members (except static final constants).

  class Outer {
      private String name = "Outer";

      class Inner {
          void display() {
              System.out.println(name);      // accesses outer's private field directly
              System.out.println(Outer.this.name);  // explicit outer reference
          }
      }
  }

  // Instantiation: REQUIRES outer class instance
  Outer outer = new Outer();
  Outer.Inner inner = outer.new Inner();
  inner.display();

  Use case: Iterator implementations — inner class accesses the outer collection's fields.

  MEMORY CONCERN: Inner class holds a reference to the outer class — can cause memory leaks
  in Android and long-lived contexts (outer can't be GC'd while inner is alive).
  Prefer static nested class unless you need outer class state.

3. LOCAL CLASS
---------------
  - Defined inside a method, constructor, or block.
  - Visible only within that block.
  - Can access: local variables of the enclosing method IF they are effectively final.
  - Can access all members of the enclosing class.

  void greetAll(List<String> names) {
      final String greeting = "Hello";  // effectively final

      class Greeter {
          void greet(String name) {
              System.out.println(greeting + ", " + name);
          }
      }

      Greeter g = new Greeter();
      names.forEach(g::greet);
  }

  Use case: Complex logic localized to a method. Rare in modern code (lambdas replaced most uses).

4. ANONYMOUS CLASS
-------------------
  - A class defined and instantiated in a single expression.
  - No class name.
  - Must extend a class or implement an interface.
  - Cannot have a constructor (has no name).
  - Can access effectively final local variables.
  - Replaced mostly by lambdas (Java 8+), but still used for abstract classes.

  // Pre-Java 8: anonymous Runnable
  Runnable r = new Runnable() {
      @Override
      public void run() {
          System.out.println("Running anonymously");
      }
  };

  // Java 8+: lambda (cleaner for functional interfaces)
  Runnable r = () -> System.out.println("Running anonymously");

  // Anonymous class still needed for non-functional abstractions:
  abstract class Template {
      abstract void execute();
      void prepare() { System.out.println("Preparing..."); }
  }

  Template t = new Template() {
      @Override
      void execute() { System.out.println("Custom execution"); }
  };
  t.prepare();
  t.execute();

COMPARISON TABLE
-----------------
| Type             | static | Has outer ref | Can access outer instance | Instantiation         |
|------------------|--------|---------------|---------------------------|------------------------|
| Static Nested    | Yes    | No            | Static members only       | new Outer.Nested()     |
| Non-static Inner | No     | Yes           | All members               | outer.new Inner()      |
| Local            | No     | Yes           | Effectively final locals  | Inside method only     |
| Anonymous        | No     | Yes           | Effectively final locals  | new Interface() { }    |

COMMON USE CASES
----------------
  Static Nested:  Builder (Person.Builder), Map.Entry<K,V>, configuration holder classes
  Inner:          Iterator implementations, event listeners (Swing legacy)
  Local:          Rare; complex local logic (use lambda instead)
  Anonymous:      Inline interface/abstract class implementation, test doubles

COMMON INTERVIEW QUESTIONS
---------------------------
Q: What is the difference between a static nested class and a non-static inner class?
A: Static nested: no implicit reference to outer class, can only access outer's static members,
   instantiated without outer object (new Outer.Nested()).
   Non-static inner: holds implicit reference to outer instance, can access all outer members
   including private, requires outer instance to instantiate (outer.new Inner()).

Q: Why might a non-static inner class cause a memory leak?
A: An inner class holds an implicit strong reference to its enclosing outer class instance.
   As long as the inner class object is alive (e.g., held by a listener), the outer class
   object cannot be garbage collected — even if you think you've "released" it. Use static
   nested class + explicit reference (WeakReference) to avoid this.

Q: When would you use an anonymous class vs a lambda?
A: Use a lambda for functional interfaces (single abstract method).
   Use an anonymous class when: you need to extend an abstract class, implement multiple
   methods of an interface, maintain state with multiple fields, or use the `this` keyword
   to refer to the anonymous class itself (in lambda, `this` refers to enclosing class).

Q: What does "effectively final" mean in the context of local/anonymous classes?
A: A variable is effectively final if it's never reassigned after initialization, even without
   the `final` keyword. Local/anonymous classes and lambdas can capture effectively final
   variables. This ensures the captured value doesn't change underneath them.
