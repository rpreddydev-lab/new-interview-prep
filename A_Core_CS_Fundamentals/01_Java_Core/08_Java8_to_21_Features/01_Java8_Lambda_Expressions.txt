JAVA 8 LAMBDA EXPRESSIONS
===========================

WHAT ARE LAMBDAS?
------------------
  A lambda expression is an anonymous function — a concise way to represent a
  functional interface (an interface with exactly one abstract method).
  Lambdas enable treating behavior (code) as data.

  Syntax:
    (parameters) -> expression
    (parameters) -> { statements; }

  // No parameters:
  () -> System.out.println("Hello")

  // One parameter (parens optional):
  x -> x * 2

  // Multiple parameters:
  (x, y) -> x + y

  // Multi-statement block:
  (x, y) -> {
      int sum = x + y;
      return sum * 2;
  }

FUNCTIONAL INTERFACE
---------------------
  A functional interface has exactly ONE abstract method (SAM — Single Abstract Method).
  @FunctionalInterface annotation enforces this at compile time (optional but good practice).
  Lambdas are instances of functional interfaces.

  @FunctionalInterface
  interface Transformer<T> {
      T transform(T input);  // single abstract method
  }

  Transformer<String> upper = s -> s.toUpperCase();
  System.out.println(upper.transform("hello"));  // HELLO

  // Built-in functional interfaces in java.util.function:
  Runnable          — ()   → void
  Callable<V>       — ()   → V (throws Exception)
  Supplier<T>       — ()   → T
  Consumer<T>       — T    → void
  Function<T,R>     — T    → R
  BiFunction<T,U,R> — T,U  → R
  Predicate<T>      — T    → boolean
  UnaryOperator<T>  — T    → T (extends Function<T,T>)
  BinaryOperator<T> — T,T  → T (extends BiFunction<T,T,T>)

BEFORE AND AFTER LAMBDAS
--------------------------
  // Before Java 8 — anonymous class:
  Runnable r = new Runnable() {
      @Override
      public void run() {
          System.out.println("Running");
      }
  };

  // After Java 8 — lambda:
  Runnable r = () -> System.out.println("Running");

  // Comparator — before:
  Collections.sort(list, new Comparator<String>() {
      @Override
      public int compare(String a, String b) { return a.compareTo(b); }
  });

  // Comparator — after:
  list.sort((a, b) -> a.compareTo(b));
  // Even simpler with method reference:
  list.sort(String::compareTo);

VARIABLE CAPTURE (CLOSURES)
-----------------------------
  Lambdas can capture variables from the enclosing scope, but those variables must be
  effectively final — not reassigned after initial assignment.

  // ✅ Effectively final:
  String prefix = "Hello, ";
  Consumer<String> greeter = name -> System.out.println(prefix + name);

  // ❌ Compile error — prefix is not effectively final:
  String prefix = "Hello";
  prefix = "Hi";   // reassigned
  Consumer<String> greeter = name -> System.out.println(prefix + name); // error!

  Why effectively final? Lambda capture makes a copy of the variable.
  If it could change, the lambda would see a stale copy — confusing behavior.
  Instance/static fields can be freely modified (they're not captured by copy).

LAMBDA SCOPE
-------------
  Lambdas do NOT introduce a new scope for variables. Variables in the lambda
  body share the same scope as the enclosing method — no shadowing of local variables.

  // ❌ Compile error — cannot redeclare local variable already in scope:
  int x = 5;
  Function<Integer, Integer> f = x -> x * 2;  // 'x' already defined

  // this in a lambda refers to the ENCLOSING object, not the lambda itself
  // (unlike anonymous inner classes where 'this' refers to the inner class instance)
  class Foo {
      int value = 10;
      void method() {
          Runnable r = () -> System.out.println(this.value); // this = Foo instance
      }
  }

TYPE INFERENCE
---------------
  The compiler infers parameter types from the functional interface's context:

  // Explicit types (rarely needed):
  BinaryOperator<Integer> add = (Integer a, Integer b) -> a + b;

  // Inferred types (typical):
  BinaryOperator<Integer> add = (a, b) -> a + b;

LAMBDAS AS HIGHER-ORDER FUNCTIONS
------------------------------------
  Lambdas enable passing behavior as arguments (higher-order functions):

  public static <T> List<T> filter(List<T> list, Predicate<T> predicate) {
      return list.stream()
                 .filter(predicate)
                 .collect(Collectors.toList());
  }

  List<String> names = List.of("Alice", "Bob", "Charlie", "Dave");
  List<String> shortNames = filter(names, n -> n.length() <= 4);  // [Bob, Dave]

COMMON FUNCTIONAL PATTERNS
----------------------------
  // Map: transform each element
  List<Integer> lengths = names.stream()
      .map(String::length)
      .collect(Collectors.toList());

  // Filter: keep matching elements
  List<String> capitalized = names.stream()
      .filter(n -> Character.isUpperCase(n.charAt(0)))
      .collect(Collectors.toList());

  // Reduce: accumulate to single result
  int totalLength = names.stream()
      .mapToInt(String::length)
      .sum();

  // Compose predicates:
  Predicate<String> longName   = n -> n.length() > 4;
  Predicate<String> startsWithA = n -> n.startsWith("A");
  List<String> result = names.stream()
      .filter(longName.and(startsWithA))
      .collect(Collectors.toList());  // [Alice]

COMMON INTERVIEW QUESTIONS
---------------------------
Q: What is a lambda expression and what does it require?
A: A lambda expression is an anonymous function that implements a functional interface
   (one with exactly one abstract method). It provides a concise syntax for passing
   behavior as data. The target type must be a functional interface — the lambda's
   parameter types and return type must match the interface's abstract method signature.
   The compiler infers these types from context.

Q: What does "effectively final" mean in the context of lambdas?
A: A variable is effectively final if it is never reassigned after its initial assignment.
   Lambda expressions can only capture local variables from the enclosing scope if they
   are effectively final (or explicitly final). This ensures the captured value is stable —
   the lambda captures a copy, and if the variable could change, the copy would be stale.
   Instance fields and static fields can be freely mutated inside lambdas (they're not captured).

Q: What is the difference between a lambda and an anonymous class?
A: (1) Scope: In an anonymous class, this refers to the inner class instance; in a lambda,
   this refers to the enclosing object. (2) Variables: Anonymous classes can shadow local
   variables; lambdas cannot. (3) Instance creation: Each anonymous class instantiation
   creates a distinct object; lambdas may be optimized to avoid object creation (invokedynamic).
   (4) Size: Lambdas are far more concise. (5) Interface: Lambdas work only with functional
   interfaces; anonymous classes work with any interface or abstract class.
