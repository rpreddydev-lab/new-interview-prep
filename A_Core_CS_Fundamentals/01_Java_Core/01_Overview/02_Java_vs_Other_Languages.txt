JAVA vs OTHER LANGUAGES
=======================

JAVA vs C++
-----------
| Feature               | Java                          | C++                              |
|-----------------------|-------------------------------|----------------------------------|
| Memory management     | Automatic (GC)                | Manual (new/delete)              |
| Pointers              | No raw pointers               | Full pointer arithmetic          |
| Platform              | JVM-based (WORA)              | Platform-specific compiled binary|
| Multiple inheritance  | Via interfaces only           | Full class multiple inheritance  |
| Operator overloading  | Not supported                 | Supported                        |
| Compilation           | .java → .class (bytecode)     | .cpp → native machine code       |
| Performance           | Near-native (JIT)             | Faster (direct native)           |
| Standard library      | Comprehensive (JDK)           | STL                              |
| Destructor            | No destructor (finalize dep.) | Yes (deterministic)              |
| Templates vs Generics | Generics (type erasure)       | Templates (code generation)      |

JAVA vs PYTHON
--------------
| Feature               | Java                          | Python                           |
|-----------------------|-------------------------------|----------------------------------|
| Typing                | Static (compile-time)         | Dynamic (runtime)                |
| Performance           | Faster (compiled bytecode)    | Slower (interpreted)             |
| Verbosity             | Verbose, explicit types       | Concise, duck typing             |
| Concurrency           | Excellent (java.util.concurrent)| GIL limits true threading      |
| Use case              | Enterprise, Android, backend  | ML/AI, scripting, data science   |
| OOP                   | Pure OOP (class required)     | Multi-paradigm (OOP + functional)|
| Memory                | JVM managed                   | CPython reference counting + GC  |

JAVA vs KOTLIN
--------------
| Feature               | Java                          | Kotlin                           |
|-----------------------|-------------------------------|----------------------------------|
| Null safety           | NullPointerException possible | Null-safe by design (?. operator)|
| Verbosity             | More boilerplate              | Concise (data classes, etc.)     |
| Interoperability      | 100% with Kotlin              | 100% with Java                   |
| Coroutines            | Virtual threads (Java 21)     | Native coroutine support         |
| Functional            | Streams, lambdas              | First-class function support     |
| Android               | Supported                     | Preferred by Google              |
| Extension functions   | Not supported                 | Supported                        |

JAVA vs JAVASCRIPT
------------------
| Feature               | Java                          | JavaScript                       |
|-----------------------|-------------------------------|----------------------------------|
| Typing                | Statically typed              | Dynamically typed                |
| Execution             | JVM                           | Browser engine / Node.js         |
| OOP model             | Class-based                   | Prototype-based (+ ES6 classes)  |
| Concurrency           | True multithreading           | Single-threaded event loop       |
| Use case              | Backend, enterprise, Android  | Frontend, full-stack (Node.js)   |
| Name similarity       | No relation to JavaScript     | Completely different language    |

KEY INTERVIEW POINTS
--------------------
- Java is statically typed → catches more errors at compile time vs Python/JS.
- Java has no GIL like Python — true OS-level threads with java.util.concurrent.
- Java and JavaScript share no relation beyond marketing similarity in names (1995 Netscape deal).
- Java vs Kotlin: Kotlin is the preferred Android language since 2017 (Google I/O announcement).
  Both compile to JVM bytecode and are 100% interoperable.
- Java generics use type erasure (removed at runtime) vs C++ templates (code generated per type).

COMMON INTERVIEW QUESTIONS
---------------------------
Q: Why is Java not 100% object-oriented?
A: Primitives (int, long, double, boolean, char, byte, short, float) are not objects.
   However, Java provides wrapper classes to box them when needed.

Q: Why choose Java over Python for a high-traffic backend?
A: Java is statically typed (fewer runtime bugs), compiled (faster execution), has
   true multithreading (no GIL), mature ecosystem (Spring Boot, Hibernate), and strong
   tooling (IntelliJ, Maven, Gradle). Python's GIL prevents true parallel thread execution.

Q: Can you call Java code from Kotlin?
A: Yes — Kotlin compiles to JVM bytecode and is 100% interoperable with Java. You can
   call Java libraries from Kotlin and vice versa with no bridging layer.
