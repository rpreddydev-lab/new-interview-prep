BUILDER PATTERN IN JAVA
========================

PURPOSE
-------
  The Builder pattern constructs complex objects step-by-step without a telescoping
  constructor (constructor with many optional parameters). It:
  - Improves readability (named setters vs positional args)
  - Enforces invariants at build time
  - Supports optional fields naturally (unset = default)
  - Creates immutable objects (the built object has no setters)

  Use when: a class has 4+ parameters, many are optional, or combinations must be validated.

CLASSIC BUILDER PATTERN
------------------------
  public final class HttpRequest {
      // Final fields — immutable after construction
      private final String method;
      private final String url;
      private final Map<String, String> headers;
      private final String body;
      private final int timeoutMs;

      private HttpRequest(Builder b) {
          this.method    = b.method;
          this.url       = b.url;
          this.headers   = Map.copyOf(b.headers);  // defensive copy — immutable
          this.body      = b.body;
          this.timeoutMs = b.timeoutMs;
      }

      public String getMethod()              { return method; }
      public String getUrl()                 { return url; }
      public Map<String, String> getHeaders(){ return headers; }
      public String getBody()                { return body; }
      public int getTimeoutMs()              { return timeoutMs; }

      // Static nested Builder class
      public static class Builder {
          // Required fields
          private final String method;
          private final String url;
          // Optional fields with defaults
          private final Map<String, String> headers = new HashMap<>();
          private String body = null;
          private int timeoutMs = 5000;

          // Constructor requires mandatory fields
          public Builder(String method, String url) {
              Objects.requireNonNull(method, "method required");
              Objects.requireNonNull(url, "url required");
              this.method = method;
              this.url    = url;
          }

          public Builder header(String name, String value) {
              headers.put(name, value);
              return this;  // fluent API — enables method chaining
          }

          public Builder body(String body) {
              this.body = body;
              return this;
          }

          public Builder timeoutMs(int timeoutMs) {
              if (timeoutMs <= 0) throw new IllegalArgumentException("timeout must be positive");
              this.timeoutMs = timeoutMs;
              return this;
          }

          public HttpRequest build() {
              // Cross-field validation at build time
              if ("GET".equals(method) && body != null) {
                  throw new IllegalStateException("GET requests cannot have a body");
              }
              return new HttpRequest(this);
          }
      }
  }

  // Usage — fluent, readable:
  HttpRequest request = new HttpRequest.Builder("POST", "https://api.example.com/data")
      .header("Content-Type", "application/json")
      .header("Authorization", "Bearer token123")
      .body("{\"name\": \"Alice\"}")
      .timeoutMs(3000)
      .build();

BUILDER WITH INHERITANCE (RECURSIVE GENERIC BUILDER)
------------------------------------------------------
  The "Simulated Self-Type" pattern allows builder inheritance:

  // Base class builder
  public abstract class Vehicle {
      private final String make;
      private final int year;

      protected Vehicle(Builder<?> b) {
          this.make = b.make;
          this.year = b.year;
      }

      public abstract static class Builder<B extends Builder<B>> {
          private String make;
          private int year;

          @SuppressWarnings("unchecked")
          protected B self() { return (B) this; }

          public B make(String make)  { this.make = make; return self(); }
          public B year(int year)     { this.year = year; return self(); }

          public abstract Vehicle build();
      }
  }

  // Subclass builder
  public class Car extends Vehicle {
      private final int doors;

      private Car(Builder b) { super(b); this.doors = b.doors; }

      public static class Builder extends Vehicle.Builder<Builder> {
          private int doors = 4;
          public Builder doors(int doors) { this.doors = doors; return self(); }
          @Override public Car build() { return new Car(this); }
          @Override protected Builder self() { return this; }
      }
  }

  // Usage:
  Car car = new Car.Builder().make("Toyota").year(2023).doors(4).build();
  // Returns Car (not Vehicle.Builder) — thanks to recursive generic

LOMBOK @Builder
----------------
  Lombok generates builder boilerplate via annotation:

  @Builder
  @Getter
  public class Person {
      private final String firstName;
      private final String lastName;
      @Builder.Default private final int age = 18;   // default value
      private final List<String> hobbies;
  }

  // Usage:
  Person p = Person.builder()
                   .firstName("Alice")
                   .lastName("Smith")
                   .age(30)
                   .hobbies(List.of("reading", "coding"))
                   .build();

  @Singular on a collection: adds individual-element adder methods:
  @Singular private final List<String> hobbies;
  // Then: .hobby("reading").hobby("coding") instead of .hobbies(List.of(...))

RECORD WITH BUILDER (JAVA 16+)
--------------------------------
  Records + builders: records provide immutability; builder provides optional parameters.
  Common to write a manually-coded builder for complex records, or use Lombok with records.

  record ServerConfig(String host, int port, boolean tls) {
      static Builder builder() { return new Builder(); }

      static final class Builder {
          private String host = "localhost";
          private int port = 8080;
          private boolean tls = false;

          Builder host(String host) { this.host = host; return this; }
          Builder port(int port)   { this.port = port; return this; }
          Builder tls(boolean tls) { this.tls = tls;   return this; }
          ServerConfig build()     { return new ServerConfig(host, port, tls); }
      }
  }

  ServerConfig cfg = ServerConfig.builder().host("example.com").port(443).tls(true).build();

BUILDER VS ALTERNATIVES
------------------------
  | Approach                | Pros                          | Cons                                |
  |-------------------------|-------------------------------|-------------------------------------|
  | Telescoping constructor | Fast                          | Unreadable; positional args confusing|
  | JavaBean (setters)      | Familiar                      | Mutable; invariants hard to enforce  |
  | Builder                 | Readable, immutable, safe     | Verbose (mitigated by Lombok)        |
  | Record (Java 16+)       | Compact, immutable, auto-gen  | No optional params without builder  |
  | Lombok @Builder         | Best of both worlds           | Requires annotation processor       |

INTERVIEW DISCUSSION POINTS
-----------------------------
  Q: Why put the Builder as a static nested class?
  A: So it can be used without an instance of the outer class (new HttpRequest.Builder(...)
     not someRequest.new Builder()). It also has access to the outer class's private
     constructor — allowing the outer class to have no public constructors (forcing use
     of the builder).

  Q: How do you make a Builder thread-safe?
  A: The Builder object itself is typically used by a single thread, so thread safety
     in the Builder is usually unnecessary. The built object should be immutable (final fields,
     defensive copies) — it's then safe to share across threads after being handed off.

  Q: How does Lombok's @Builder differ from a manual builder?
  A: Lombok generates the same structure (inner static Builder class with setters and build()).
     Differences: @Builder.Default for default values, @Singular for collections, and
     @Builder(toBuilder=true) to create a builder pre-populated from an existing instance.
