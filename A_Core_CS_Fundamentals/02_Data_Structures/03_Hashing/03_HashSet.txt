  HASHSET

----------------------------------------------------------------
WHAT IS A HASHSET?
----------------------------------------------------------------
A HashSet is a collection that stores UNIQUE elements with
O(1) average-case add, remove, and contains operations.

It is backed by a HashMap internally — elements are stored
as keys with a dummy value (Boolean.TRUE in Java).

  Key properties (Java HashSet):
    - No duplicate elements
    - One null element allowed
    - NO guaranteed order of iteration
    - NOT thread-safe
    - O(1) average for add/remove/contains
    - Backed by a HashMap<E, Object>

  Visualization:
    Set = {"alice", "bob", "carol"}
    Internally: HashMap keys = {"alice", "bob", "carol"}
                HashMap values = {PRESENT, PRESENT, PRESENT}

----------------------------------------------------------------
JAVA SET IMPLEMENTATIONS
----------------------------------------------------------------
  HashSet<E>        -- O(1) ops, no order, backed by HashMap
  LinkedHashSet<E>  -- O(1) ops, insertion order, backed by LinkedHashMap
  TreeSet<E>        -- O(log n) ops, sorted order, backed by TreeMap
  EnumSet<E>        -- O(1) ops, for enum types, backed by bit vector

  Feature          HashSet    LinkedHashSet    TreeSet
  ---------------------------------------------------------------
  Add              O(1) avg   O(1) avg         O(log n)
  Remove           O(1) avg   O(1) avg         O(log n)
  Contains         O(1) avg   O(1) avg         O(log n)
  Null element     Yes        Yes              No (compareTo fails)
  Order            None       Insertion order  Sorted (natural/comparator)
  Duplicates       No         No               No
  Use when         Fast lookup Ordered unique  Sorted unique

----------------------------------------------------------------
JAVA HASHSET — KEY METHODS
----------------------------------------------------------------
  Set<Integer> set = new HashSet<>();

  ADD / REMOVE:
    set.add(x)                  -- O(1) avg, returns false if dup
    set.remove(x)               -- O(1) avg
    set.addAll(collection)      -- O(n)
    set.removeAll(collection)   -- O(n) intersection removal
    set.retainAll(collection)   -- O(n) keep only intersection
    set.clear()                 -- O(n)

  QUERY:
    set.contains(x)             -- O(1) avg
    set.size()                  -- O(1)
    set.isEmpty()               -- O(1)
    set.containsAll(collection) -- O(n)

  CONVERT:
    new HashSet<>(list)         -- list to set (deduplicate) O(n)
    new ArrayList<>(set)        -- set to list O(n)

  ITERATION:
    for (int x : set) process(x)
    set.forEach(x -> process(x))
    set.stream().filter(...).collect(Collectors.toList())

  SET OPERATIONS:
    Union:        setA.addAll(setB)
    Intersection: setA.retainAll(setB)
    Difference:   setA.removeAll(setB)
    Subset check: setA.containsAll(setB)

  TREESET EXTRAS:
    TreeSet<Integer> ts = new TreeSet<>();
    ts.first()          -- smallest element
    ts.last()           -- largest element
    ts.floor(x)         -- largest element <= x
    ts.ceiling(x)       -- smallest element >= x
    ts.lower(x)         -- largest element < x
    ts.higher(x)        -- smallest element > x
    ts.headSet(x)       -- elements < x
    ts.tailSet(x)       -- elements >= x
    ts.subSet(a, b)     -- elements in [a, b)
    ts.pollFirst()      -- remove and return smallest
    ts.pollLast()       -- remove and return largest

KEY INTERVIEW PATTERNS USING HASHSET
----------------------------------------------------------------

  1. DUPLICATE DETECTION
     Set<Integer> seen = new HashSet<>();
     for (int x : nums):
       if (!seen.add(x)) return true;  // add() returns false on dup
     return false;
     Time: O(n)   Space: O(n)

  2. LOOKUP IN O(1) (replace O(n) contains on list)
     Set<Integer> numSet = new HashSet<>(Arrays.asList(arr));
     for each query q:
       if numSet.contains(q): ...    // O(1) vs O(n) on array

  3. LONGEST CONSECUTIVE SEQUENCE
     Set<Integer> numSet = new HashSet<>(all elements);
     for each x in numSet:
       if !numSet.contains(x - 1):  // x is sequence start
         count = 1
         while numSet.contains(x + count): count++
         maxLen = max(maxLen, count)
     Time: O(n)   Space: O(n)
     Why O(n)? Each element starts a sequence at most once.

  4. TWO SUM WITH SET (distinct values check)
     Set<Integer> seen = new HashSet<>();
     for int x in nums:
       if seen.contains(target - x): return true
       seen.add(x)

  5. SLIDING WINDOW WITH SET
     Set<Character> window = new HashSet<>();
     left = 0
     for right from 0 to n-1:
       while window.contains(s[right]):
         window.remove(s[left++])
       window.add(s[right])
       maxLen = max(maxLen, right - left + 1)

  6. CYCLE DETECTION IN LINKED LIST
     Set<ListNode> visited = new HashSet<>();
     while node != null:
       if visited.contains(node): CYCLE
       visited.add(node)
       node = node.next
     Time: O(n)   Space: O(n)
     (Floyd's is preferred for O(1) space)

  7. GRAPH VISITED SET (DFS/BFS)
     Set<Integer> visited = new HashSet<>();
     visited.add(start);
     queue.offer(start);
     while !queue.isEmpty():
       node = queue.poll()
       for neighbor of node:
         if !visited.contains(neighbor):
           visited.add(neighbor)
           queue.offer(neighbor)

HASHSET vs HASHMAP — WHEN TO USE WHICH
----------------------------------------------------------------
  Use HashSet when:
    - You only care about existence (membership test)
    - Deduplication of a collection
    - Fast O(1) lookup without associated value
    - Set operations (union, intersection, difference)

  Use HashMap when:
    - You need key-value association
    - Counting frequencies
    - Caching / memoization
    - Grouping items by key

  HashSet IS a HashMap:
    Internally HashSet<E> wraps HashMap<E, Object>.
    set.add(e) calls map.put(e, PRESENT)
    set.contains(e) calls map.containsKey(e)
    set.remove(e) calls map.remove(e)
    This means HashSet has the same performance as HashMap.

----------------------------------------------------------------
INTERVIEW QUESTIONS
----------------------------------------------------------------

Q: How is HashSet implemented internally in Java?
A: HashSet<E> is backed by a HashMap<E, Object>. Each element
   is stored as a key in the HashMap with a shared dummy value
   (static final Object PRESENT = new Object()). This means
   all HashSet operations delegate to HashMap: add() calls
   put(), contains() calls containsKey(), remove() calls
   map.remove(). The equals/hashCode contract of the element
   type must be correctly implemented for HashSet to work.

Q: What is the time complexity of set.contains() and
   why is it O(1) average but O(n) worst case?
A: contains() computes the hash, finds the bucket in O(1),
   then compares with entries in that bucket. Average case:
   few collisions, bucket has 1-2 entries -> O(1).
   Worst case: all elements hash to the same bucket -> O(n)
   traversal of the chain. Java 8+ converts long chains to
   Red-Black Trees -> O(log n) worst case.

Q: How do you find the intersection of two arrays efficiently?
A: Convert the smaller array to a HashSet. Iterate the larger
   array; if an element is in the set, add it to the result
   and remove it from the set (to handle duplicates correctly).
   Time: O(n + m)   Space: O(min(n, m))

Q: TreeSet.floor(x) vs TreeSet.lower(x) — what's the difference?
A: floor(x) returns the largest element <= x (includes x itself).
   lower(x) returns the largest element strictly < x (excludes x).
   Similarly: ceiling(x) >= x, higher(x) > x.
   These are critical for range problems and binary-search-like
   queries on dynamic sorted sets.

Q: When would you use TreeSet over HashSet?
A: Use TreeSet when you need:
   1. Elements in sorted order
   2. Floor/ceiling/range queries (floor, ceiling, headSet, tailSet)
   3. Getting min or max in O(log n)
   4. Iterating in sorted order
   Trade-off: TreeSet is O(log n) vs HashSet's O(1) average.
   For strict membership tests without ordering, prefer HashSet.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. set.add(x) returns false if x already exists -- use this
     as a one-liner duplicate check instead of contains() + add()
  2. new HashSet<>(list) is the fastest way to deduplicate
     a list and convert it to a set for O(1) lookups
  3. For graph DFS/BFS always use a Set for visited, not a
     boolean array, unless nodes are integers in a known range
  4. Know TreeSet's floor/ceiling -- they come up in interval
     and calendar problems (Meeting Rooms II, etc.)
  5. addAll/retainAll/removeAll implement union/intersection/
     difference -- mention these when asked about set operations
  6. For XOR-based problems (Single Number, Missing Number),
     no Set is needed -- O(1) space is achievable
