================================================================
  BINARY TREE
================================================================

----------------------------------------------------------------
WHAT IS A BINARY TREE?
----------------------------------------------------------------
A binary tree is a hierarchical data structure in which each
node has at most two children, called left and right.

  Vocabulary:
    Root         -- top node, no parent
    Leaf         -- node with no children
    Height       -- longest path from root to leaf
    Depth        -- distance from root to a node
    Level        -- all nodes at the same depth
    Subtree      -- a node and all its descendants
    Edge         -- connection between parent and child
    Ancestor     -- any node on the path to root
    Descendant   -- any node in the subtree below

  Visualization:
            1          Level 0 (root)   height = 3
           / \
          2   3        Level 1
         / \   \
        4   5   6      Level 2
           /
          7            Level 3 (leaf)

  Java node structure:
    class TreeNode {
      int val;
      TreeNode left, right;
      TreeNode(int val) { this.val = val; }
    }

----------------------------------------------------------------
TYPES OF BINARY TREES
----------------------------------------------------------------
  Full Binary Tree:
    Every node has 0 or 2 children. No node has exactly 1 child.
    Nodes: 2L - 1 where L = number of leaves.

  Complete Binary Tree:
    All levels fully filled except possibly the last.
    Last level filled from left to right.
    Used in heaps. Can be stored in an array efficiently.

  Perfect Binary Tree:
    All interior nodes have 2 children AND all leaves at same level.
    Nodes at level k: 2^k.  Total nodes: 2^(h+1) - 1.

  Balanced Binary Tree:
    Height of left and right subtrees differ by at most 1
    for EVERY node. Height = O(log n).
    Examples: AVL tree, Red-Black tree.

  Degenerate (Skewed) Binary Tree:
    Every node has only one child (essentially a linked list).
    Height = n - 1. Operations degrade to O(n).

  Properties:
    Max nodes at level i:     2^i
    Max nodes in tree h:      2^(h+1) - 1
    Min height for n nodes:   floor(log2(n))
    Max height for n nodes:   n - 1 (degenerate)

----------------------------------------------------------------
TREE TRAVERSALS
----------------------------------------------------------------
  Four standard traversals -- know all of them cold:

  INORDER (Left -> Root -> Right):
    For BST: visits nodes in SORTED order
    Use: BST validation, kth smallest, recover BST

    void inorder(TreeNode root) {
      if (root == null) return;
      inorder(root.left);
      process(root.val);
      inorder(root.right);
    }

  PREORDER (Root -> Left -> Right):
    Use: serialize/deserialize tree, copy tree, path problems
    Root visited BEFORE children -> useful for top-down work

    void preorder(TreeNode root) {
      if (root == null) return;
      process(root.val);
      preorder(root.left);
      preorder(root.right);
    }

  POSTORDER (Left -> Right -> Root):
    Use: delete tree, compute subtree sizes, bottom-up results
    Root visited AFTER children -> useful for bottom-up work

    void postorder(TreeNode root) {
      if (root == null) return;
      postorder(root.left);
      postorder(root.right);
      process(root.val);
    }

  LEVEL ORDER (BFS — left to right, level by level):
    Use: minimum depth, right side view, zigzag traversal

    List<List<Integer>> levelOrder(TreeNode root) {
      List<List<Integer>> result = new ArrayList<>();
      if (root == null) return result;
      Queue<TreeNode> q = new LinkedList<>();
      q.offer(root);
      while (!q.isEmpty()) {
        int size = q.size();   // SNAPSHOT: current level size
        List<Integer> level = new ArrayList<>();
        for (int i = 0; i < size; i++) {
          TreeNode node = q.poll();
          level.add(node.val);
          if (node.left != null) q.offer(node.left);
          if (node.right != null) q.offer(node.right);
        }
        result.add(level);
      }
      return result;
    }

  Time/Space for all traversals:
    Time:  O(n) -- each node visited once
    Space: O(h) recursive (call stack), O(n) worst case (skewed)
           O(n) for BFS (queue holds one level)

----------------------------------------------------------------
ITERATIVE TRAVERSALS (must know for interviews)
----------------------------------------------------------------
  ITERATIVE INORDER:
    Stack<TreeNode> stack = new Stack<>();
    TreeNode curr = root;
    while (curr != null || !stack.isEmpty()) {
      while (curr != null) {
        stack.push(curr);
        curr = curr.left;
      }
      curr = stack.pop();
      process(curr.val);
      curr = curr.right;
    }

  ITERATIVE PREORDER:
    Stack<TreeNode> stack = new Stack<>();
    stack.push(root);
    while (!stack.isEmpty()) {
      TreeNode node = stack.pop();
      process(node.val);
      if (node.right != null) stack.push(node.right);  // push right first
      if (node.left != null) stack.push(node.left);    // so left pops first
    }

  ITERATIVE POSTORDER (two-stack trick):
    Stack<TreeNode> s1 = new Stack<>(), s2 = new Stack<>();
    s1.push(root);
    while (!s1.isEmpty()) {
      TreeNode node = s1.pop();
      s2.push(node);
      if (node.left != null) s1.push(node.left);
      if (node.right != null) s1.push(node.right);
    }
    // s2 now contains postorder in reverse -> pop s2 for result

  MORRIS TRAVERSAL (O(1) space inorder):
    Threads the tree using null right pointers.
    No stack or recursion needed.
    Used when O(1) space inorder traversal is required.

----------------------------------------------------------------
KEY TREE PATTERNS AND TECHNIQUES
----------------------------------------------------------------

  1. RECURSIVE POSTORDER (bottom-up results)
     Most tree problems return a value from subtrees to parent.
     Pattern: compute left result, compute right result,
              combine at current node.
     Use for: height, diameter, balanced check, path sums.

     int height(TreeNode root) {
       if (root == null) return 0;
       int lh = height(root.left);
       int rh = height(root.right);
       return 1 + Math.max(lh, rh);
     }

  2. RECURSIVE PREORDER (top-down parameters)
     Pass information DOWN to children.
     Use for: path sum, max depth with target, serialization.

     void findPaths(TreeNode node, int remaining) {
       if (node == null) return;
       remaining -= node.val;
       if (node.left == null && node.right == null
           && remaining == 0) {
         // found leaf-to-root path with target sum
       }
       findPaths(node.left, remaining);
       findPaths(node.right, remaining);
     }

  3. DIAMETER PATTERN (max path through or not through root)
     int maxDiameter = 0;
     int depth(TreeNode node) {
       if (node == null) return 0;
       int left = depth(node.left);
       int right = depth(node.right);
       maxDiameter = Math.max(maxDiameter, left + right);
       return 1 + Math.max(left, right);
     }
     Key insight: the answer may NOT pass through the root;
     track global max inside the recursive helper.

  4. LOWEST COMMON ANCESTOR (LCA) PATTERN
     TreeNode lca(TreeNode root, TreeNode p, TreeNode q) {
       if (root == null || root == p || root == q) return root;
       TreeNode left = lca(root.left, p, q);
       TreeNode right = lca(root.right, p, q);
       if (left != null && right != null) return root; // split
       return left != null ? left : right;             // both same side
     }

  5. SERIALIZE / DESERIALIZE
     Preorder with null markers:
     Serialize: "1,2,null,null,3,null,null"
     Deserialize: use a queue of tokens.

  6. CONSTRUCT TREE FROM TRAVERSALS
     Given inorder + preorder: preorder[0] is root.
       Find root in inorder -> splits into left and right subtrees.
       Recursively build left and right.
     Given inorder + postorder: postorder[-1] is root.
     NOTE: inorder alone or preorder alone is NOT sufficient.

COMMON INTERVIEW PROBLEMS
----------------------------------------------------------------
  Problem                             Technique           Complexity
  ---------------------------------------------------------------
  Maximum Depth of Binary Tree        Recursive postorder O(n)
  Minimum Depth                       BFS (first leaf)    O(n)
  Balanced Binary Tree                Height + check      O(n)
  Diameter of Binary Tree             Depth + global max  O(n)
  Binary Tree Paths                   DFS preorder        O(n)
  Path Sum                            DFS, decrement      O(n)
  Path Sum II (all paths)             DFS + backtrack     O(n^2)
  Max Path Sum (any path)             Postorder + global  O(n)
  Level Order Traversal               BFS + snapshot size O(n)
  Zigzag Level Order                  BFS + flip flag     O(n)
  Right Side View                     BFS last per level  O(n)
  Invert Binary Tree                  Swap L/R            O(n)
  Symmetric Tree                      Mirror check        O(n)
  Same Tree                           DFS compare         O(n)
  Flatten Tree to Linked List         Preorder/Morris     O(n)
  Serialize/Deserialize               Preorder + null     O(n)
  LCA                                 Postorder split     O(n)
  Construct from inorder+preorder     Divide + conquer    O(n^2)/O(n)
  Count Complete Tree Nodes           Binary search       O(log^2 n)
  Vertical Order Traversal            BFS + column track  O(n log n)

----------------------------------------------------------------
INTERVIEW QUESTIONS
----------------------------------------------------------------

Q: What is the difference between height and depth of a node?
A: Depth is the distance from the root to the node (root has
   depth 0). Height is the length of the longest path from the
   node down to a leaf. A leaf has height 0. The height of a
   tree is the height of its root. In many problems, "height"
   refers to the number of edges; in others, the number of nodes.
   Clarify with the interviewer -- Java convention is usually
   height = number of nodes on longest path.

Q: Why does the diameter problem require a global variable?
A: The diameter is the longest path between any two nodes,
   which may not pass through the root. A purely return-value
   recursion can only return one value per call. We need to
   both return the depth to the parent (for parent's diameter
   calculation) AND track the widest path seen so far.
   The global variable (or instance variable) captures the
   maximum across all nodes in a single O(n) traversal.

Q: Can you reconstruct a binary tree from only inorder or
   only preorder traversal?
A: No. You need TWO traversals: either inorder+preorder or
   inorder+postorder. Inorder alone cannot distinguish between
   different tree shapes (e.g., root-left vs root-right).
   Preorder or postorder alone also cannot -- but if the tree
   is a BST, inorder alone uniquely determines it (sorted order).

Q: What is Morris Traversal and when do you use it?
A: Morris traversal achieves O(1) space inorder traversal by
   temporarily modifying the tree: it threads null right pointers
   to point back to the node's inorder successor. After visiting,
   it restores these pointers. Used when the problem requires
   O(1) space. Normal recursion uses O(h) stack space, which is
   O(n) for a skewed tree. Morris avoids this entirely.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. Always handle the base case: `if (root == null) return ...`
  2. Identify traversal type from the problem: bottom-up info
     -> postorder; top-down params -> preorder; level info -> BFS
  3. For path sum problems, pass remaining sum down,
     check at leaf (both children null)
  4. The snapshot trick in BFS (int size = q.size() BEFORE
     the inner loop) is key to level-by-level processing
  5. Diameter, max path sum, and balanced check all require
     a global variable updated in a depth-returning recursion
  6. Know iterative inorder cold -- it tests stack + pointer
     management and comes up frequently
