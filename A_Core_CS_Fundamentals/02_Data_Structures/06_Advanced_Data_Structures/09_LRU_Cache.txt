WHAT IS LRU CACHE?
----------------------------------------------------------------
LRU (Least Recently Used) Cache is a fixed-capacity cache that
evicts the LEAST RECENTLY USED item when full.

  "Recently used" means: any get OR put operation on a key.

  Requirements:
    get(key): return value if exists, else -1. O(1).
    put(key, value): insert or update. If full, evict LRU. O(1).

  Example (capacity = 2):
    put(1, 1)  -> cache: {1=1}
    put(2, 2)  -> cache: {2=2, 1=1}
    get(1)     -> returns 1; cache: {1=1, 2=2}  (1 is now most recent)
    put(3, 3)  -> evict key 2 (LRU); cache: {3=3, 1=1}
    get(2)     -> returns -1 (not found)

----------------------------------------------------------------
DATA STRUCTURE DESIGN
----------------------------------------------------------------
Achieving O(1) get AND O(1) eviction requires:

  HashMap<Integer, Node>  -- O(1) key lookup
  Doubly Linked List      -- O(1) remove/add at any position

  Map gives O(1) lookup; DLL gives O(1) ordering (MRU at head,
  LRU at tail).

  Dummy sentinel nodes (head and tail) eliminate all null
  pointer checks for empty list.

  head <-> [MRU node] <-> ... <-> [LRU node] <-> tail

  On get(key):
    1. Look up in map: O(1)
    2. Move node to front (after dummy head): O(1)
    3. Return value

  On put(key, value):
    1. If key exists: update value, move to front: O(1)
    2. If new: create node, add to front, add to map
    3. If over capacity: remove tail's prev node, remove from map

----------------------------------------------------------------
FULL JAVA IMPLEMENTATION
----------------------------------------------------------------
  class LRUCache {
    class Node {
      int key, val;
      Node prev, next;
      Node(int k, int v) { key = k; val = v; }
    }

    Map<Integer, Node> map = new HashMap<>();
    Node head = new Node(0, 0);  // dummy head (most recent side)
    Node tail = new Node(0, 0);  // dummy tail (least recent side)
    int capacity;

    LRUCache(int capacity) {
      this.capacity = capacity;
      head.next = tail;
      tail.prev = head;
    }

    void addToFront(Node node) {
      node.prev = head;
      node.next = head.next;
      head.next.prev = node;
      head.next = node;
    }

    void remove(Node node) {
      node.prev.next = node.next;
      node.next.prev = node.prev;
    }

    int get(int key) {
      if (!map.containsKey(key)) return -1;
      Node node = map.get(key);
      remove(node);
      addToFront(node);
      return node.val;
    }

    void put(int key, int value) {
      if (map.containsKey(key)) {
        Node node = map.get(key);
        node.val = value;
        remove(node);
        addToFront(node);
      } else {
        if (map.size() == capacity) {
          Node lru = tail.prev;   // least recently used
          remove(lru);
          map.remove(lru.key);   // key stored in node for O(1) map removal
        }
        Node newNode = new Node(key, value);
        addToFront(newNode);
        map.put(key, newNode);
      }
    }
  }

  Time: O(1) for both get and put
  Space: O(capacity)

  Critical detail: Node must store KEY (not just value) so that
  when we evict the LRU node from the DLL, we can remove it
  from the map in O(1) without searching the entire map.

----------------------------------------------------------------
JAVA LINKEDHASHMAP SHORTCUT
----------------------------------------------------------------
  class LRUCacheShort extends LinkedHashMap<Integer, Integer> {
    int capacity;
    LRUCacheShort(int capacity) {
      super(capacity, 0.75f, true);  // true = accessOrder (not insertionOrder)
      this.capacity = capacity;
    }
    int get(int key)     { return getOrDefault(key, -1); }
    void put(int key, int value) { super.put(key, value); }

    @Override
    protected boolean removeEldestEntry(Map.Entry<Integer,Integer> e) {
      return size() > capacity;
    }
  }

  LinkedHashMap with accessOrder=true maintains entries in
  access order (most recently accessed at end).
  removeEldestEntry is called after each put() -- evict when over capacity.

  This is a shortcut but interviewers usually want the manual DLL implementation.

----------------------------------------------------------------
LRU CACHE vs LFU CACHE
----------------------------------------------------------------
  Feature               LRU Cache               LFU Cache
  ---------------------------------------------------------------
  Eviction policy       Least recently used      Least frequently used
  Tie-breaking          N/A (time-based)          Least recently used among same freq
  Implementation        HashMap + DLL             HashMap + HashMap + DLL per freq
  Complexity            O(1) get/put             O(1) get/put
  When preferred        Temporal locality        Frequency locality
  Real use              General-purpose caches   Browser caches, CDN caches

----------------------------------------------------------------
INTERVIEW QUESTIONS
----------------------------------------------------------------

Q: Why do you use a DOUBLY linked list (not singly linked)?
A: To remove a node in O(1), you need access to both its
   predecessor and successor. In a singly linked list, removing
   a node requires traversing from the head to find its
   predecessor, which is O(n). With a doubly linked list,
   each node has direct pointers to both neighbors, so
   removal is O(1) once you have the node reference.

Q: Why does the Node need to store the key?
A: When we evict the LRU entry (tail.prev in the DLL), we
   need to remove it from the HashMap. HashMap.remove() needs
   the KEY, not the value or node itself. Since we're accessing
   the node from the DLL (not from the map), we need the key
   stored in the node to do map.remove(lruNode.key) in O(1).
   Without the key, we'd need to search the entire map to
   find which entry to remove -- O(n).

Q: How would you extend LRU to support a TTL (time-to-live)?
A: In addition to the DLL for LRU ordering, maintain a separate
   sorted structure (e.g., priority queue or sorted DLL) by
   expiration time. On each get/put, also check if the entry
   has expired. A background thread can periodically clean up
   expired entries. Java's ConcurrentHashMap + ScheduledExecutorService
   is one approach. Guava Cache provides this out of the box with
   expireAfterAccess() and expireAfterWrite().

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. Always use DUMMY head and tail sentinel nodes -- eliminates
     null checks and greatly simplifies remove/add logic
  2. Store the KEY in each DLL node -- critical for O(1) map removal on eviction
  3. The map stores node REFERENCES (pointers), not copies --
     so moving a node in DLL (remove + addToFront) is O(1)
  4. Both get() and put() on existing keys must update order --
     a common bug is forgetting to call remove + addToFront in put()
  5. When asked "how would you make this thread-safe?": wrap
     get/put with synchronized or use ReadWriteLock
  6. LinkedHashMap(capacity, 0.75f, true) with removeEldestEntry
     is acceptable as a shortcut but know the manual impl too
