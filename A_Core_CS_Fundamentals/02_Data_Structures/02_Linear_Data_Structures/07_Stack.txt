----------------------------------------------------------------
WHAT IS A STACK?
----------------------------------------------------------------
A stack is a linear data structure that follows the
LIFO principle — Last In, First Out.

The last element added is the first one removed.
Think of a stack of plates: you add to the top and
remove from the top.

  Visualization:
    push(1), push(2), push(3)

    TOP --> [3]
            [2]
            [1]  <-- BOTTOM

    pop()  returns 3
    peek() returns 2 (next on top, not removed)

  Key operations:
    push(x)  -- add element to top         O(1)
    pop()    -- remove and return top       O(1)
    peek()   -- return top without removing O(1)
    isEmpty()-- check if stack is empty     O(1)
    size()   -- number of elements          O(1)

----------------------------------------------------------------
STACK IMPLEMENTATIONS
----------------------------------------------------------------

  1. ARRAY-BACKED STACK (ArrayList or fixed array)
     Fastest in practice (cache-friendly).
     push = add to end, pop = remove from end.

     class Stack<T> {
       private List<T> data = new ArrayList<>();
       void push(T val)  { data.add(val); }
       T pop()           { return data.remove(data.size() - 1); }
       T peek()          { return data.get(data.size() - 1); }
       boolean isEmpty() { return data.isEmpty(); }
       int size()        { return data.size(); }
     }

  2. LINKED LIST-BACKED STACK
     Dynamic size, no resizing cost.
     push = add at head, pop = remove from head.

     class Stack<T> {
       private LinkedList<T> data = new LinkedList<>();
       void push(T val)  { data.addFirst(val); }
       T pop()           { return data.removeFirst(); }
       T peek()          { return data.peekFirst(); }
       boolean isEmpty() { return data.isEmpty(); }
     }

  3. IN JAVA — USE ArrayDeque (recommended)
     Deque<Integer> stack = new ArrayDeque<>();
     stack.push(x);     // addFirst
     stack.pop();       // removeFirst
     stack.peek();      // peekFirst
     stack.isEmpty();
     stack.size();

     DO NOT use java.util.Stack — it extends Vector,
     is synchronized (slow), and is considered legacy.
     ArrayDeque is the standard replacement.

----------------------------------------------------------------
OPERATIONS AND COMPLEXITY
----------------------------------------------------------------
  Operation       Array Stack     Linked List Stack
  ---------------------------------------------------------------
  push            O(1) amortized  O(1)
  pop             O(1)            O(1)
  peek            O(1)            O(1)
  isEmpty         O(1)            O(1)
  size            O(1)            O(1)
  Space           O(n)            O(n) + pointer overhead

  All core operations are O(1) — this is what makes stacks
  powerful for interview problems.

KEY STACK PATTERNS FOR INTERVIEWS
----------------------------------------------------------------

  1. MONOTONIC STACK
     Maintain a stack where elements are always in
     increasing (or decreasing) order. Pop elements that
     violate the order before pushing a new one.

     Monotonic Increasing Stack (smallest at bottom):
       for each element x:
         while stack not empty AND stack.top() >= x:
           pop()     // x is the "next smaller" for popped elements
         push(x)

     Used for:
       - Next Greater Element
       - Next Smaller Element
       - Largest Rectangle in Histogram
       - Trapping Rain Water
       - Daily Temperatures
     Time: O(n) — each element pushed and popped at most once

  2. BALANCED PARENTHESES / BRACKET MATCHING
     Push opening brackets, pop and match on closing brackets.
       for each char c:
         if c is '(' '[' '{': push c
         if c is ')' ']' '}':
           if stack empty OR top doesn't match: return false
           pop()
       return stack.isEmpty()
     Time: O(n)   Space: O(n)

  3. EVALUATE EXPRESSIONS
     Two-stack approach (operators + operands):
       Stack for numbers, stack for operators
       On operator with higher/equal precedence: evaluate top
       Apply PEMDAS rules with precedence map
     Or: convert to postfix (RPN) then evaluate

     Evaluate Postfix (RPN):
       for each token:
         if number: push
         if operator: pop two operands, apply, push result
     Time: O(n)   Space: O(n)

  4. FUNCTION CALL STACK SIMULATION
     DFS iteratively uses an explicit stack to simulate
     recursion. Push nodes to visit, pop and process.
       stack.push(root)
       while not empty:
         node = stack.pop()
         process(node)
         push right child, then left child
         (right pushed first so left is processed first)

  5. MIN STACK (O(1) getMin)
     Maintain a second stack that tracks the current minimum.
     On push: push to main stack; push min(val, minStack.top())
              to minStack
     On pop: pop from both stacks
     getMin: return minStack.peek()
     Time: O(1) for all ops   Space: O(n)

  6. BACKTRACKING STATE MANAGEMENT
     Save state before exploring a branch, restore on backtrack.
     Use a stack to save and restore state explicitly when
     not using recursion.

  7. UNDO/REDO
     Two stacks: undoStack and redoStack
     Action: push to undoStack, clear redoStack
     Undo: pop from undoStack, push to redoStack
     Redo: pop from redoStack, push to undoStack

MONOTONIC STACK — DEEP DIVE
----------------------------------------------------------------
The monotonic stack is the most important stack pattern
for interviews. It solves "nearest greater/smaller" problems
in O(n) instead of O(n²) brute force.

  NEXT GREATER ELEMENT (to the right):
    result = [-1] * n
    stack = []   // stores indices
    for i from 0 to n-1:
      while stack not empty AND arr[stack.top()] < arr[i]:
        idx = stack.pop()
        result[idx] = arr[i]    // arr[i] is next greater for idx
      stack.push(i)
    // remaining elements in stack have no next greater (-1)
    Time: O(n)   Space: O(n)

  PREVIOUS SMALLER ELEMENT (to the left):
    result = [-1] * n
    stack = []
    for i from 0 to n-1:
      while stack not empty AND arr[stack.top()] >= arr[i]:
        stack.pop()
      result[i] = stack.isEmpty() ? -1 : arr[stack.top()]
      stack.push(i)
    Time: O(n)   Space: O(n)

  LARGEST RECTANGLE IN HISTOGRAM:
    Key insight: for each bar, find the nearest smaller bar
    to its left and right. Width = right - left - 1.
    Area = height[i] * width.
    Use monotonic stack to find both boundaries in O(n).
    Time: O(n)   Space: O(n)

IMPLEMENT QUEUE USING TWO STACKS
----------------------------------------------------------------
  Use two stacks: inbox (for push) and outbox (for pop).

  enqueue(x):  inbox.push(x)   -- O(1)

  dequeue():
    if outbox is empty:
      while inbox not empty: outbox.push(inbox.pop())
    return outbox.pop()
    -- Amortized O(1), worst case O(n)

  Why amortized O(1)?
    Each element is moved from inbox to outbox exactly once.
    Total work across n operations = O(n), so O(1) per op.

----------------------------------------------------------------
IMPLEMENT STACK USING TWO QUEUES
----------------------------------------------------------------
  Method 1 (push O(n), pop O(1)):
    push(x):
      enqueue x to q2
      while q1 not empty: enqueue q1.dequeue() to q2
      swap q1 and q2
    pop(): return q1.dequeue()

  Method 2 (push O(1), pop O(n)):
    push(x): enqueue to q1
    pop():
      while q1.size() > 1: enqueue q1.dequeue() to q2
      result = q1.dequeue()
      swap q1 and q2
      return result

INTERVIEW QUESTIONS
----------------------------------------------------------------

Q: Why should you use ArrayDeque instead of Stack in Java?
A: java.util.Stack extends Vector, which is synchronized on
   every operation — even in single-threaded code. This makes
   it unnecessarily slow. ArrayDeque is unsynchronized, backed
   by a resizable array, and has better cache performance.
   It implements the Deque interface which is the recommended
   abstraction for stack usage in Java.

Q: What is a monotonic stack and when do you use it?
A: A monotonic stack maintains elements in strictly increasing
   or decreasing order. Elements violating the monotonic
   property are popped before insertion. It solves "next
   greater / next smaller element" style problems in O(n)
   by ensuring each element is pushed and popped at most once.
   Use it whenever you need the nearest element satisfying
   some comparison (greater, smaller, equal) to the left or right.

Q: How would you design a Min Stack with O(1) getMin()?
A: Use two stacks: main and minTracker.
   On push(x): push x to main; push min(x, minTracker.top())
   to minTracker (or x if minTracker is empty).
   On pop(): pop from both stacks.
   getMin(): return minTracker.peek().
   This ensures minTracker always holds the current minimum
   at each level of the main stack.

Q: How do you evaluate "3 + 2 * 2" with a stack?
A: Use two stacks (nums and ops) or convert to postfix first.
   With inline evaluation:
   - Parse left to right
   - Numbers go to nums stack
   - For operators: while top of ops has >= precedence,
     evaluate (pop 2 nums, apply top op, push result)
   - Push current operator
   - After full scan: evaluate remaining ops
   Precedence: * and / are higher than + and -
   Time: O(n)   Space: O(n)

Q: How would you implement an iterative inorder traversal
   of a binary tree using a stack?
A: Use an explicit stack to simulate the recursion.
   curr = root
   while curr != null OR stack not empty:
     while curr != null:       // go left as far as possible
       stack.push(curr)
       curr = curr.left
     curr = stack.pop()        // visit node
     process(curr.val)
     curr = curr.right         // move to right subtree
   Time: O(n)   Space: O(h)

Q: What is the time complexity of the monotonic stack approach
   and why?
A: O(n). Though there is a nested while loop that pops elements,
   each element is pushed onto the stack exactly once and popped
   at most once across the entire iteration. Total push + pop
   operations = 2n = O(n). This is amortized analysis — the
   inner loop doesn't run n times per outer iteration on average.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. Reach for a stack whenever you see:
     - "nearest", "next greater/smaller", "previous"
     - Nested structures (parentheses, HTML tags, paths)
     - Undo/redo, backtracking, DFS
  2. Monotonic stack is O(n) even with a nested loop —
     always explain the amortized reasoning to the interviewer
  3. Use ArrayDeque in Java, never java.util.Stack
  4. For expression evaluation, clarify: infix? postfix? prefix?
     Does it have parentheses? Does it have unary minus?
  5. Min Stack is a common warm-up problem — know it cold
  6. When using stack for DFS, push RIGHT child before LEFT
     so LEFT is processed first (LIFO)
  7. Edge case: always check stack.isEmpty() before peek/pop
     to avoid EmptyStackException / NoSuchElementException
