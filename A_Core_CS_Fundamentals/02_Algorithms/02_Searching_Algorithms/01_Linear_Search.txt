  LINEAR SEARCH
================================================================

----------------------------------------------------------------
WHAT IS LINEAR SEARCH?
----------------------------------------------------------------
Linear Search (Sequential Search) scans every element from left
to right until the target is found or the array is exhausted.

  int linearSearch(int[] arr, int target) {
    for (int i = 0; i < arr.length; i++)
      if (arr[i] == target) return i;
    return -1;  // not found
  }

  Time:  O(n) worst/average, O(1) best (first element)
  Space: O(1)
  Works on: unsorted AND sorted arrays, any data type

----------------------------------------------------------------
WHEN LINEAR SEARCH IS THE ONLY OPTION
----------------------------------------------------------------
  - Array is unsorted
  - Array is a linked list (no random access -> binary search
    would still be O(n) even with O(log n) comparisons)
  - Small arrays where overhead of sorting > O(n) search cost
  - Searching for a pattern in a string (covered in KMP)

----------------------------------------------------------------
SENTINEL LINEAR SEARCH (minor optimization)
----------------------------------------------------------------
Places the target at the end to eliminate the bounds check,
reducing the number of comparisons per iteration from 2 to 1.

  int sentinelSearch(int[] arr, int target) {
    int n = arr.length;
    int last = arr[n-1];
    arr[n-1] = target;  // sentinel
    int i = 0;
    while (arr[i] != target) i++;
    arr[n-1] = last;  // restore
    if (i < n-1 || last == target) return i;
    return -1;
  }

  Saves one comparison per iteration but doesn't change O(n).
  Rarely used in practice.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. Linear search is almost never the answer -- mention it
     only when the array is unsorted or no random access
  2. Linked list search: O(n) unavoidable regardless of sort order
  3. O(n) is acceptable when n is small (n < 1000 in hot path)
  4. For sorted arrays: ALWAYS use binary search O(log n)
