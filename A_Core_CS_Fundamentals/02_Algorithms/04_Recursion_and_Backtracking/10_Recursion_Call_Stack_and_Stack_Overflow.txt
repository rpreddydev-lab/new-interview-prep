================================================================
  RECURSION: CALL STACK & STACK OVERFLOW
================================================================

----------------------------------------------------------------
CALL STACK INTERNALS
----------------------------------------------------------------
Each thread in Java has a dedicated call stack (separate from heap).
Each method invocation pushes a STACK FRAME containing:
  - Local variables
  - Method parameters
  - Return address
  - Reference to containing object (`this`)
  - Partial results of expressions

  Default JVM thread stack size:
    Client JVM: ~320KB
    Server JVM: ~512KB to 1MB
    Each frame size depends on local variable count and type

  Typical usable recursion depth before StackOverflowError:
    Simple functions (few locals): ~10,000-15,000 frames
    Complex functions (many locals): ~5,000 frames or less

----------------------------------------------------------------
STACK OVERFLOW IN JAVA
----------------------------------------------------------------
  java.lang.StackOverflowError is thrown when the stack limit
  is exceeded. It extends Error (not Exception) -- cannot
  recover gracefully in most cases.

  Common causes:
  1. Infinite recursion (missing base case)
  2. Deep recursion on large inputs (n = 10^5 with O(n) depth)
  3. Mutual recursion with excessive depth

  Example: DFS on a skewed binary tree (n = 100K nodes)
    --> StackOverflowError at ~10K depth
    --> Solution: iterative DFS with explicit stack

  Increasing stack size: java -Xss4m MyProgram
  But this only delays the problem; iteration is the real fix.

----------------------------------------------------------------
CONVERTING RECURSION TO ITERATION -- EXPLICIT STACK
----------------------------------------------------------------
Any recursive algorithm can be converted to iterative using
an explicit stack (Deque in Java).

  Recursive DFS:
    void dfs(Node node) {
      if (node == null) return;
      process(node);
      for (Node child : node.children) dfs(child);
    }

  Iterative DFS:
    void dfs(Node root) {
      if (root == null) return;
      Deque<Node> stack = new ArrayDeque<>();
      stack.push(root);
      while (!stack.isEmpty()) {
        Node node = stack.pop();
        process(node);
        // Push in reverse order to maintain left-to-right processing
        for (int i = node.children.size()-1; i >= 0; i--)
          stack.push(node.children.get(i));
      }
    }

  For postorder (children before parent) -- need to track state:
    Use a pair (node, visited) on the stack.
    When popped with visited=false: re-push with visited=true, then push children.
    When popped with visited=true: process node.

----------------------------------------------------------------
WHEN TO USE RECURSION vs ITERATION
----------------------------------------------------------------
  Use recursion when:
    - Problem is naturally recursive (trees, graphs, divide-and-conquer)
    - Recursion depth is small (O(log n) or bounded constant)
    - Code clarity is prioritized and stack depth is safe

  Use iteration when:
    - Recursion depth can be O(n) with large n (linked list, skewed tree)
    - Performance is critical (avoid function call overhead)
    - Explicit control of ordering is needed
    - Tail recursion (Java doesn't optimize, so convert to loop)

----------------------------------------------------------------
INTERVIEW QUESTIONS
----------------------------------------------------------------

Q: How would you handle a DFS on a tree with 10^6 nodes?
A: A recursive DFS would cause StackOverflowError for a skewed
   tree (linear chain) since the depth would be 10^6 frames.
   Solution: convert to iterative DFS using an explicit Deque.
   Push root, then repeatedly pop and push children. This uses
   O(n) heap memory (Deque) instead of O(n) stack frames,
   which is much safer since heap is much larger (typically
   256MB to several GB vs ~1MB stack).
   Alternatively, use BFS (iterative by nature) if order doesn't matter.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. Always mention stack overflow risk for O(n)-depth recursion
     when n can be large (>10K)
  2. Iterative DFS with explicit stack is the production solution
     for deep trees/graphs
  3. Java StackOverflowError vs OutOfMemoryError:
     SOE = call stack exhausted; OOM = heap exhausted
  4. Heap memory >> Stack memory in JVM: explicit stack (heap-based)
     handles depths that recursion cannot
  5. For binary trees: guaranteed O(log n) depth only if BALANCED;
     unbalanced tree can be O(n) depth
