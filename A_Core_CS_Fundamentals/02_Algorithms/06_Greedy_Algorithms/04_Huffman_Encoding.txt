================================================================
  HUFFMAN ENCODING
================================================================

----------------------------------------------------------------
WHAT IS HUFFMAN ENCODING?
----------------------------------------------------------------
A lossless data compression algorithm.
Assigns shorter binary codes to more frequent characters,
longer codes to less frequent ones.

  Optimal prefix code: no code is a prefix of another.
  Huffman gives the OPTIMAL prefix-free binary code.

  Example: 'a'(freq=5), 'b'(freq=9), 'c'(freq=12), 'd'(freq=13)
           'e'(freq=16), 'f'(freq=45)
  Huffman tree:
          100
         /    \
        f(45)  55
              /    \
            25      30
           / \      / \
          12  13  14   16
          c   d  /\    e
               b  a
  Codes: f=0, c=100, d=101, b=1100, a=1101, e=111
  Total bits = 45*1 + 16*3 + 13*3 + 12*3 + 9*4 + 5*4 = 224
  vs fixed 3-bit encoding: 300 bits (25% savings)

----------------------------------------------------------------
ALGORITHM (GREEDY USING MIN-HEAP)
----------------------------------------------------------------
  1. Create leaf node for each character; add to min-heap
  2. While heap has > 1 node:
     a. Extract two minimum-frequency nodes (left, right)
     b. Create internal node with frequency = left.freq + right.freq
     c. Add new node back to heap
  3. Remaining node is the root

  HuffmanNode buildTree(int[] freq, char[] chars) {
    PriorityQueue<HuffmanNode> pq = new PriorityQueue<>(
      Comparator.comparingInt(n -> n.freq));
    for (int i = 0; i < chars.length; i++)
      pq.offer(new HuffmanNode(chars[i], freq[i]));
    while (pq.size() > 1) {
      HuffmanNode left = pq.poll();
      HuffmanNode right = pq.poll();
      HuffmanNode parent = new HuffmanNode('\0', left.freq + right.freq);
      parent.left = left;
      parent.right = right;
      pq.offer(parent);
    }
    return pq.poll();
  }

  void buildCodes(HuffmanNode node, String code, Map<Character, String> codes) {
    if (node.left == null && node.right == null) { codes.put(node.ch, code); return; }
    buildCodes(node.left, code + "0", codes);
    buildCodes(node.right, code + "1", codes);
  }

  Time: O(n log n)  Space: O(n)

----------------------------------------------------------------
CORRECTNESS: GREEDY CHOICE
----------------------------------------------------------------
The two LEAST frequent symbols always appear at the deepest level
of the optimal tree (they have the longest codes).
Proof by exchange argument: if some pair at deepest level has
higher frequency than the two minimums, swapping them decreases
total bit cost -> contradiction.

----------------------------------------------------------------
APPLICATIONS
----------------------------------------------------------------
  DEFLATE: ZIP / GZIP use Huffman coding
  JPEG: uses Huffman for entropy coding of DCT coefficients
  MP3: uses Huffman for quantized spectral data
  HTTP/2: HPACK header compression uses Huffman

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. Greedy: always merge the two SMALLEST frequency nodes first
  2. Data structure: min-heap (PriorityQueue in Java)
  3. n characters -> n-1 merges -> O(n log n) total
  4. The resulting code is optimal: no other prefix-free code
     has a smaller expected code length
  5. Decoding: traverse tree with bits -- 0 = left, 1 = right
     until leaf reached; no ambiguity because prefix-free
