================================================================
  ACTIVITY SELECTION PROBLEM
================================================================

----------------------------------------------------------------
PROBLEM
----------------------------------------------------------------
Given n activities each with start[i] and end[i],
select the MAXIMUM number of non-overlapping activities.

  Classic greedy: sort by END TIME, always pick the activity
  that finishes earliest among remaining compatible activities.

  Why end time? Finishing early leaves maximum room for future activities.

----------------------------------------------------------------
IMPLEMENTATION
----------------------------------------------------------------
  int activitySelection(int[] start, int[] end) {
    int n = start.length;
    Integer[] idx = new Integer[n];
    for (int i = 0; i < n; i++) idx[i] = i;
    Arrays.sort(idx, (a, b) -> end[a] - end[b]);  // sort by end time
    int count = 1;
    int lastEnd = end[idx[0]];
    for (int i = 1; i < n; i++) {
      if (start[idx[i]] >= lastEnd) {  // non-overlapping
        count++;
        lastEnd = end[idx[i]];
      }
    }
    return count;
  }

  Time: O(n log n)  Space: O(n) for index array

  LeetCode: Non-overlapping Intervals (LC 435) --
  same idea, count minimum removals = n - maxNonOverlapping

  int eraseOverlapIntervals(int[][] intervals) {
    Arrays.sort(intervals, (a, b) -> a[1] - b[1]);  // sort by end
    int count = 1, lastEnd = intervals[0][1];
    for (int i = 1; i < intervals.length; i++)
      if (intervals[i][0] >= lastEnd) { count++; lastEnd = intervals[i][1]; }
    return intervals.length - count;
  }

----------------------------------------------------------------
RELATED: INTERVAL SCHEDULING VARIANTS
----------------------------------------------------------------
  Non-overlapping Intervals (LC 435):
    Sort by end. Count max non-overlapping. Answer = n - count.

  Meeting Rooms (LC 252):
    Can one person attend all meetings?
    Sort by start. Check if end[i-1] > start[i].

  Meeting Rooms II (LC 253):
    Minimum conference rooms for all meetings.
    Sort by start. Use min-heap of end times.
    When next meeting starts after heap.peek(), reuse that room.

    int minMeetingRooms(int[][] intervals) {
      Arrays.sort(intervals, (a, b) -> a[0] - b[0]);  // by start
      PriorityQueue<Integer> heap = new PriorityQueue<>();  // min-heap of end times
      for (int[] interval : intervals) {
        if (!heap.isEmpty() && heap.peek() <= interval[0])
          heap.poll();  // reuse room
        heap.offer(interval[1]);
      }
      return heap.size();
    }

  Minimum Number of Arrows (LC 452):
    Sort by end. Arrow at end[0] hits all overlapping balloons.
    Greedy: advance arrow when start[i] > current arrow position.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. "Sort by end time" is the greedy choice for activity selection
  2. Overlapping intervals: [s1,e1] and [s2,e2] overlap if s2 < e1
     (strictly less than for open/closed distinction)
  3. For LC 435: answer = n - maxNonOverlapping (remove the rest)
  4. Meeting Rooms II: heap size at end = number of rooms needed
  5. All these variants start with: sort by end time (or start time
     for meeting rooms II)
