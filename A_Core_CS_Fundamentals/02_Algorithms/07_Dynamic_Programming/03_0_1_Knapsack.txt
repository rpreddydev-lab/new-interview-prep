================================================================
  0/1 KNAPSACK
================================================================

----------------------------------------------------------------
PROBLEM
----------------------------------------------------------------
Capacity W. n items: weight[i], value[i].
Each item used at most once. Maximize total value.

----------------------------------------------------------------
DP FORMULATION
----------------------------------------------------------------
  State: dp[i][w] = max value using first i items with capacity w
  Transition:
    Don't take item i: dp[i][w] = dp[i-1][w]
    Take item i (if weight[i] <= w): dp[i][w] = dp[i-1][w-weight[i]] + value[i]
    dp[i][w] = max(dp[i-1][w], dp[i-1][w-weight[i]] + value[i])
  Base: dp[0][w] = 0 for all w; dp[i][0] = 0 for all i
  Answer: dp[n][W]

  int knapsack(int W, int[] weight, int[] value) {
    int n = weight.length;
    int[][] dp = new int[n + 1][W + 1];
    for (int i = 1; i <= n; i++) {
      for (int w = 0; w <= W; w++) {
        dp[i][w] = dp[i-1][w];  // don't take item i
        if (weight[i-1] <= w)
          dp[i][w] = Math.max(dp[i][w], dp[i-1][w - weight[i-1]] + value[i-1]);
      }
    }
    return dp[n][W];
  }

  Time: O(nW)  Space: O(nW)  [pseudo-polynomial]

----------------------------------------------------------------
SPACE OPTIMIZATION -- O(W)
----------------------------------------------------------------
Only need previous row. Use 1D array, iterate W in REVERSE.
  Why reverse? dp[w] = old dp[w-weight[i]] (not yet updated).
  If forward: dp[w-weight[i]] already updated -> item used twice!

  int knapsack1D(int W, int[] weight, int[] value) {
    int[] dp = new int[W + 1];
    for (int i = 0; i < weight.length; i++)
      for (int w = W; w >= weight[i]; w--)  // REVERSE!
        dp[w] = Math.max(dp[w], dp[w - weight[i]] + value[i]);
    return dp[W];
  }

  Reverse iteration is the KEY difference between 0-1 and unbounded knapsack.

----------------------------------------------------------------
VARIANTS: SUBSET SUM, PARTITION
----------------------------------------------------------------
  Subset Sum (LC 416 variant):
    Can we select items with exact sum S?
    dp[w] = true if sum w is achievable.
    dp[0] = true. For each item: dp[w] |= dp[w - weight[i]] (reverse).

  Partition Equal Subset Sum (LC 416):
    Divide array into two equal-sum subsets.
    total must be even; target = total/2.
    boolean[] dp = new boolean[target + 1];
    dp[0] = true;
    for (int num : nums)
      for (int w = target; w >= num; w--)  // reverse (0-1)
        dp[w] |= dp[w - num];
    return dp[target];

  Target Sum (LC 494):
    Assign + or - to each number; count ways to reach target.
    Reduce to subset sum: sum(P) - sum(N) = target,
    sum(P) + sum(N) = total -> sum(P) = (target + total) / 2
    Count subsets with sum (target + total)/2.
    dp[w] += dp[w - num] (count versions, reverse order)

----------------------------------------------------------------
INTERVIEW QUESTIONS
----------------------------------------------------------------

Q: Why is 0-1 Knapsack "pseudo-polynomial"?
A: Time is O(nW) which looks polynomial in n and W. But W is
   the NUMERIC VALUE of capacity, not its input size. In terms
   of input bits: W requires log(W) bits to represent, so W
   is exponential in the number of bits. This means the algorithm
   is NOT polynomial in input size -- hence "pseudo-polynomial."
   For W = 10^9, O(nW) = O(n * 10^9) which is impractical.

Q: What is the difference between 0-1 and unbounded knapsack
   and how does it manifest in code?
A: 0-1: each item used at most once. 1D array, iterate W REVERSE.
   Unbounded: items can be reused unlimited times. 1D array, iterate W FORWARD.
   The direction of iteration is the ONLY code difference:
   Reverse = each item considered at most once per capacity.
   Forward = each item can be re-included at larger capacities.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. 0-1: iterate W in REVERSE; Unbounded: iterate W FORWARD
  2. Always start with 2D formulation to get the recurrence right,
     then optimize to 1D
  3. Subset sum variations: boolean dp[] instead of int dp[]
  4. Target Sum (LC 494): recognize the algebraic transformation
     to convert to counting subset sum
  5. Time O(nW): if W is large (>10^6), this DP is impractical;
     consider meet-in-the-middle for exact subset sum
