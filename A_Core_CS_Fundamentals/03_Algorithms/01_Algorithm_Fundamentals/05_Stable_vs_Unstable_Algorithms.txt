================================================================
  STABLE vs UNSTABLE SORTING ALGORITHMS
================================================================

----------------------------------------------------------------
DEFINITION
----------------------------------------------------------------
A sorting algorithm is STABLE if equal elements maintain their
original relative order after sorting.

  Example: Sort [{name:"Alice", age:30}, {name:"Bob", age:30}, {name:"Carol", age:25}]
  by age:

  Stable result:   [{"Carol",25}, {"Alice",30}, {"Bob",30}]   Alice before Bob (original order)
  Unstable result: [{"Carol",25}, {"Bob",30}, {"Alice",30}]   could swap Bob and Alice

----------------------------------------------------------------
STABLE vs UNSTABLE CLASSIFICATION
----------------------------------------------------------------
  Stable:                           Unstable:
  --------------------------------  --------------------------------
  Insertion Sort                    Selection Sort
  Merge Sort                        Quick Sort (standard)
  Bubble Sort                       Heap Sort
  Counting Sort (careful impl)      Shell Sort
  Radix Sort (with stable base sort)
  TimSort (Java Arrays.sort for objects)

  Memory aid: "I MBC are stable" (Insertion, Merge, Bubble, Counting)

----------------------------------------------------------------
WHY STABILITY MATTERS
----------------------------------------------------------------
  MULTI-KEY SORTING:
    Sort records by (department, then salary) stably:
    1. Sort by salary (stable)
    2. Sort by department (stable)
    Result: within each department, salaries are in order.

    If either sort is unstable, the salary order within
    departments would be scrambled.

  DATABASE QUERY RESULTS:
    SELECT * FROM employees ORDER BY department, salary;
    Requires stable sort to maintain secondary ordering.

  JAVA PRACTICAL IMPACT:
    Arrays.sort(primitives): dual-pivot QuickSort -- UNSTABLE
      (doesn't matter for primitives since all 5s are identical)
    Arrays.sort(objects) and Collections.sort(): TimSort -- STABLE
      (matters for objects since equal-keyed objects have identity)
    Java's contract for object sorting: guaranteed stable.

----------------------------------------------------------------
MAKING AN UNSTABLE SORT STABLE
----------------------------------------------------------------
Add the original index as a tiebreaker:
  Sort by (key, original_index).
  Equal keys are then ordered by original position -> stable.

  In Java: Arrays.sort with comparator:
    int[][] withIndex = new int[n][2];
    for (int i = 0; i < n; i++) { withIndex[i][0] = nums[i]; withIndex[i][1] = i; }
    Arrays.sort(withIndex, (a, b) -> a[0] != b[0] ? a[0]-b[0] : a[1]-b[1]);

----------------------------------------------------------------
INTERVIEW QUESTIONS
----------------------------------------------------------------

Q: Why does Java use QuickSort for primitives but TimSort for objects?
A: For primitives, stability is meaningless -- all 5s are
   identical so there's nothing to preserve. QuickSort is
   faster in practice (better cache performance, no extra
   memory for merging). For objects, stability matters because
   two objects can be equal by the comparison key but different
   by identity. Java guarantees Arrays.sort(Object[]) is stable
   so multi-key sorting and database-like operations work
   correctly. TimSort is a hybrid merge/insertion sort that is
   stable, O(n log n) worst case, and O(n) on nearly-sorted data.

Q: Is QuickSort always unstable?
A: Standard QuickSort with in-place partitioning is unstable.
   A stable variant can be created by using extra space for
   partitioning (like a merge step), but this adds O(n) space.
   In practice, when stability is needed, Merge Sort or TimSort
   is used instead.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. Stability question arises when sorting objects by ONE field
     while other fields matter -- always ask "is stability required?"
  2. Java guarantees: Collections.sort() and Arrays.sort(Object[])
     are STABLE (TimSort). Arrays.sort(int[]) is NOT stable (QuickSort)
     but irrelevant for primitives.
  3. Merge Sort is the classic stable comparison-based sort
  4. Radix Sort is stable only if the digit sort (counting sort) is stable
  5. When designing a sorting system: prefer TimSort-like hybrid
     for real data (often nearly sorted, has runs)
