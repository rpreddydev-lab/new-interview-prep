  SORTING ALGORITHMS -- INTRODUCTION & COMPARISON
================================================================

----------------------------------------------------------------
SORTING ALGORITHM COMPARISON TABLE
----------------------------------------------------------------
  Algorithm       Best        Average     Worst       Space   Stable?
  -----------------------------------------------------------------------
  Bubble Sort     O(n)        O(n^2)      O(n^2)      O(1)    Yes
  Selection Sort  O(n^2)      O(n^2)      O(n^2)      O(1)    No
  Insertion Sort  O(n)        O(n^2)      O(n^2)      O(1)    Yes
  Merge Sort      O(n log n)  O(n log n)  O(n log n)  O(n)    Yes
  Quick Sort      O(n log n)  O(n log n)  O(n^2)      O(log n) No
  Heap Sort       O(n log n)  O(n log n)  O(n log n)  O(1)    No
  Counting Sort   O(n+k)      O(n+k)      O(n+k)      O(k)    Yes
  Radix Sort      O(nk)       O(nk)       O(nk)       O(n+k)  Yes
  Bucket Sort     O(n+k)      O(n+k)      O(n^2)      O(n+k)  Yes (with stable sort)
  Tim Sort        O(n)        O(n log n)  O(n log n)  O(n)    Yes

  k = range of values (Counting/Radix), number of buckets (Bucket)

----------------------------------------------------------------
JAVA SORTING IN PRACTICE
----------------------------------------------------------------
  Arrays.sort(int[])         -- Dual-Pivot QuickSort, O(n log n), NOT stable
  Arrays.sort(Object[])      -- TimSort, O(n log n), STABLE
  Collections.sort(List<T>)  -- TimSort, O(n log n), STABLE

  Custom comparator:
    Arrays.sort(arr, (a, b) -> a[0] - b[0]);         // by first element (ascending)
    Arrays.sort(arr, (a, b) -> b[0] - a[0]);         // descending
    Arrays.sort(arr, Comparator.comparingInt(a -> a[0]));

  WARNING: comparator returning a-b can overflow for large integers!
  Safer: return Integer.compare(a, b) or (a < b) ? -1 : (a > b) ? 1 : 0

----------------------------------------------------------------
LOWER BOUND ON COMPARISON-BASED SORTING
----------------------------------------------------------------
For algorithms that sort ONLY using comparisons:
  Minimum comparisons needed = Omega(n log n)
  Proof: decision tree has n! leaves, height >= log2(n!) = Theta(n log n)

  Therefore: Merge Sort and Heap Sort are OPTIMAL for comparison-based sort.
  Beating O(n log n) requires NON-comparison sorting (counting, radix).

----------------------------------------------------------------
WHEN TO USE EACH
----------------------------------------------------------------
  Small arrays (n < 10-20):   Insertion Sort (low overhead)
  General purpose:            Java's Arrays.sort (TimSort / dual-pivot QS)
  Need stability:             Merge Sort or TimSort
  Limited memory:             Heap Sort (O(1) space)
  Known small integer range:  Counting Sort or Radix Sort
  Nearly sorted data:         TimSort or Insertion Sort
  Uniform distribution:       Bucket Sort

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. ALWAYS know: Java Arrays.sort(int[]) uses QuickSort (not stable),
     Arrays.sort(Object[]) uses TimSort (stable)
  2. O(n log n) is the optimal comparison sort -- Merge, Heap, Quick (avg)
  3. QuickSort wins in practice despite O(n^2) worst case:
     cache friendly, small constant, O(n^2) essentially impossible with random pivot
  4. Comparator a-b pattern is DANGEROUS for large ints (overflow)
  5. If the problem constrains the value range: consider counting/radix sort
