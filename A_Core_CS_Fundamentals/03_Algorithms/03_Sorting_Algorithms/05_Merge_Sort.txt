================================================================
  MERGE SORT
================================================================

----------------------------------------------------------------
HOW IT WORKS
----------------------------------------------------------------
Divide and Conquer:
  1. Divide array into two halves
  2. Recursively sort each half
  3. Merge the two sorted halves

  Time:  O(n log n) all cases   Space: O(n) auxiliary
  In-place: No (requires temp array)   Stable: Yes

  void mergeSort(int[] arr, int left, int right) {
    if (left >= right) return;
    int mid = left + (right - left) / 2;
    mergeSort(arr, left, mid);
    mergeSort(arr, mid + 1, right);
    merge(arr, left, mid, right);
  }

  void merge(int[] arr, int left, int mid, int right) {
    int[] temp = new int[right - left + 1];
    int i = left, j = mid + 1, k = 0;
    while (i <= mid && j <= right)
      temp[k++] = (arr[i] <= arr[j]) ? arr[i++] : arr[j++];  // <= for stability
    while (i <= mid)  temp[k++] = arr[i++];
    while (j <= right) temp[k++] = arr[j++];
    System.arraycopy(temp, 0, arr, left, temp.length);
  }

  Stability: `arr[i] <= arr[j]` -- prefer left half on tie (preserves order).

----------------------------------------------------------------
RECURRENCE ANALYSIS
----------------------------------------------------------------
  T(n) = 2T(n/2) + O(n)
  By Master Theorem: a=2, b=2, f(n)=n, log_b(a)=log2(2)=1, f(n)=n^1
  Case 2 (c == k): T(n) = O(n log n)

  Space: O(n) for temp array + O(log n) call stack = O(n) total.

----------------------------------------------------------------
COUNT INVERSIONS (key application)
----------------------------------------------------------------
An inversion is a pair (i, j) where i < j but arr[i] > arr[j].
Count inversions = O(n log n) using modified merge sort.

  long count = 0;
  // In merge step: when arr[j] < arr[i] (right < left element)
  // All remaining elements in left half (mid - i + 1) form inversions with arr[j]
  long mergeCount(int[] arr, int left, int mid, int right) {
    long cnt = 0;
    int[] temp = new int[right - left + 1];
    int i = left, j = mid + 1, k = 0;
    while (i <= mid && j <= right) {
      if (arr[i] <= arr[j]) {
        temp[k++] = arr[i++];
      } else {
        cnt += (mid - i + 1);  // all left[i..mid] are > arr[j]
        temp[k++] = arr[j++];
      }
    }
    // ... complete merge
    return cnt;
  }

----------------------------------------------------------------
BOTTOM-UP MERGE SORT (iterative)
----------------------------------------------------------------
Avoids recursion overhead by merging subarrays of increasing size.

  void mergeSortBottomUp(int[] arr) {
    int n = arr.length;
    for (int size = 1; size < n; size *= 2)
      for (int left = 0; left < n - size; left += 2 * size)
        merge(arr, left, left + size - 1, Math.min(left + 2*size - 1, n-1));
  }

  Time: O(n log n)  Space: O(n)  -- no recursion stack

----------------------------------------------------------------
INTERVIEW QUESTIONS
----------------------------------------------------------------

Q: When would you choose Merge Sort over Quick Sort?
A: 1. When STABILITY is required (Merge Sort is stable, Quick Sort is not)
   2. For LINKED LISTS -- Merge Sort doesn't need random access;
      QuickSort's random pivot doesn't work well on linked lists
   3. When WORST-CASE O(n log n) is required -- Merge Sort guarantees
      O(n log n) while QuickSort can degrade to O(n^2)
   4. External sorting (data too large for RAM): Merge Sort's
      sequential I/O pattern is ideal for disk merging

Q: How does Merge Sort sort a linked list efficiently?
A: Split the list at mid using slow/fast pointers. Recursively sort
   both halves. Merge by pointer manipulation (no extra space needed
   for the merge step itself). Total: O(n log n) time, O(log n)
   stack space. Quick Sort is O(n^2) for linked lists without
   random access, so Merge Sort is the standard choice.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. Stability: `<=` in merge condition (prefer left on tie) = stable
  2. Merge Sort on linked list is a classic question
  3. Count inversions via merge sort = O(n log n) vs O(n^2) brute force
  4. Bottom-up merge sort avoids stack overflow for very large n
  5. Space O(n): the aux array is the main cost; cannot easily make it O(1)
     (In-place merge sort exists but is complex and rarely asked)
