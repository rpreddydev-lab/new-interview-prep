----------------------------------------------------------------
COIN CHANGE I (LC 322) -- Min coins to reach target
----------------------------------------------------------------
  dp[i] = min coins to make amount i
  dp[0] = 0; dp[1..amount] = INF initially
  Transition: dp[i] = min(dp[i], dp[i - coin] + 1) for each coin <= i

  int coinChange(int[] coins, int amount) {
    int[] dp = new int[amount + 1];
    Arrays.fill(dp, amount + 1);    // INF = amount + 1 (can't exceed)
    dp[0] = 0;
    for (int i = 1; i <= amount; i++)
      for (int coin : coins)
        if (coin <= i) dp[i] = Math.min(dp[i], dp[i - coin] + 1);
    return dp[amount] > amount ? -1 : dp[amount];
  }

  Time: O(n * amount)  Space: O(amount)  Unbounded knapsack type.

  Loop order: amount outer, coins inner -- correct for unbounded reuse.

----------------------------------------------------------------
COIN CHANGE II (LC 518) -- Count combinations (order doesn't matter)
----------------------------------------------------------------
  dp[i] = count of ways to make amount i using any coins
  dp[0] = 1 (one way to make 0: use nothing)

  CRITICAL: iterate coins OUTER, amounts INNER to count combinations.
  (If amounts outer: same combination counted multiple times in
   different orderings = permutations, not combinations)

  int change(int amount, int[] coins) {
    int[] dp = new int[amount + 1];
    dp[0] = 1;
    for (int coin : coins)
      for (int i = coin; i <= amount; i++)
        dp[i] += dp[i - coin];
    return dp[amount];
  }

  Time: O(n * amount)  Space: O(amount)

----------------------------------------------------------------
COMBINATION SUM IV (LC 377) -- Count permutations (order matters)
----------------------------------------------------------------
  Same recurrence but amounts outer, coins inner:

  int combinationSum4(int[] nums, int target) {
    int[] dp = new int[target + 1];
    dp[0] = 1;
    for (int i = 1; i <= target; i++)
      for (int num : nums)
        if (i >= num) dp[i] += dp[i - num];
    return dp[target];
  }

  Why amounts outer = permutations: at each amount i, we pick
  any num as LAST element -- different orderings of same set
  are counted separately because the position varies.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------
  1. Coin Change (LC 322) is the #1 most asked DP interview problem
  2. Combinations (LC 518): coins outer; Permutations (LC 377): amounts outer
     -- this distinction is FREQUENTLY asked and tricky
  3. No solution: dp[amount] > amount means unreachable; return -1
  4. INF initialization: use `amount + 1` (not Integer.MAX_VALUE)
     to avoid overflow when adding 1
  5. Trace: coinChange([1,2,5], 11):
     dp[5]=1, dp[7]=2, dp[10]=2, dp[11]=3
