----------------------------------------------------------------
CORE MATH CONCEPTS
----------------------------------------------------------------

  GCD (Greatest Common Divisor):
    Euclidean algorithm: gcd(a, b) = gcd(b, a % b). Base: gcd(n, 0) = n.

    Java:
      int gcd(int a, int b) { return b == 0 ? a : gcd(b, a % b); }

    Time: O(log(min(a,b)))

  LCM (Least Common Multiple):
    lcm(a, b) = a * b / gcd(a, b).
    Use long to avoid overflow: (long)a / gcd(a,b) * b.

  Modular Arithmetic:
    (a + b) % m = ((a % m) + (b % m)) % m
    (a * b) % m = ((a % m) * (b % m)) % m
    (a - b) % m = ((a % m) - (b % m) + m) % m  ← add m to handle negative
    Division: requires modular inverse (only for prime m with Fermat's little theorem)

  Modular Exponentiation (fast power):
    a^n mod m in O(log n):
    Java:
      long modPow(long base, long exp, long mod) {
          long result = 1; base %= mod;
          while (exp > 0) {
              if ((exp & 1) == 1) result = result * base % mod;
              base = base * base % mod;
              exp >>= 1;
          }
          return result;
      }

----------------------------------------------------------------
SIEVE OF ERATOSTHENES
----------------------------------------------------------------

  Find all primes up to n in O(n log log n).

  Java:
    boolean[] sieve(int n) {
        boolean[] isPrime = new boolean[n + 1];
        Arrays.fill(isPrime, true);
        isPrime[0] = isPrime[1] = false;
        for (int i = 2; (long)i * i <= n; i++) {
            if (isPrime[i]) {
                for (int j = i * i; j <= n; j += i) isPrime[j] = false;
            }
        }
        return isPrime;
    }

  Space: O(n). Use bit array for space optimization.

----------------------------------------------------------------
DIGIT MANIPULATION
----------------------------------------------------------------

  Extract digits: n % 10 (last digit), n / 10 (remove last digit).
  Sum of digits: while (n > 0) { sum += n % 10; n /= 10; }
  Reverse digits: while (n > 0) { rev = rev * 10 + n % 10; n /= 10; }
  Number of digits: (int) Math.log10(n) + 1 (for n > 0). Or convert to string.

  Common uses:
    - LC 202 Happy Number: digit²sum cycle detection
    - LC 7 Reverse Integer: reverse and check overflow
    - LC 9 Palindrome Number: compare with reversed

IMPORTANT NUMBER THEORY FACTS
----------------------------------------------------------------

  Integer overflow checks:
    n > Integer.MAX_VALUE / 10  → overflow if you multiply by 10
    n < Integer.MIN_VALUE / 10  → underflow
    Always use long when intermediate results might overflow.

  Ceiling division (integer division rounding up):
    (a + b - 1) / b   OR   (int) Math.ceil((double) a / b)

  Check if n is perfect square:
    int sqrt = (int) Math.sqrt(n); return sqrt * sqrt == n;

  Fibonacci (matrix exponentiation for O(log n)):
    Simpler: O(n) iterative or O(1) with Binet's formula (floating point issues).

----------------------------------------------------------------
COORDINATE ROTATION
----------------------------------------------------------------

  Rotate point (x, y) by 90° clockwise:   (x, y) → (y, -x)
  Rotate point (x, y) by 90° counter-CW:  (x, y) → (-y, x)
  Rotate matrix 90° clockwise:
    Step 1: Transpose (swap matrix[i][j] and matrix[j][i]).
    Step 2: Reverse each row.

  Rotate matrix 90° counter-clockwise:
    Step 1: Transpose.
    Step 2: Reverse each column (or reverse rows then transpose).

----------------------------------------------------------------
COMMON EDGE CASES IN MATH/SIMULATION
----------------------------------------------------------------

  - Overflow: result exceeds int range → use long or check before multiply.
  - Division by zero: check denominators.
  - Negative numbers: modulo behavior differs (Java: -7 % 3 = -1, not 2).
  - Empty input: empty array, empty string, n=0.
  - Single element: ensure loops handle n=1.
  - Square vs rectangle: don't assume matrix is square.

----------------------------------------------------------------
INTERVIEW TIPS FOR MATH/SIMULATION
----------------------------------------------------------------

  - Always mention overflow potential and use long defensively.
  - For in-place matrix problems: drawing the transformation on paper is essential.
  - Simulation: define state variables explicitly before coding.
  - For boundary conditions: add +1/-1 carefully, use half-open vs closed intervals consistently.
  - GCD/LCM: always know Euclidean algorithm.
