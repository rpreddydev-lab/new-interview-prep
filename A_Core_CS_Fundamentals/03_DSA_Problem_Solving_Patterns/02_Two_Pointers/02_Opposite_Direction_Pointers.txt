================================================================
  OPPOSITE DIRECTION TWO POINTERS
  (Converging Pointers)
================================================================

Pointers start at both ends and move toward each other.
The key insight: the array must be sorted (or the problem must
have a monotone property that allows systematic elimination).

----------------------------------------------------------------
CORE INSIGHT
----------------------------------------------------------------

  When l < r:
    - If the "result" is too small  --> advance l (increase left value)
    - If the "result" is too large  --> retreat r (decrease right value)
    - If exact match                --> record answer, then move both

  Each step eliminates one candidate. Total steps = O(n).
  This only works if you can definitively eliminate options.

----------------------------------------------------------------
PROBLEM 1: TWO SUM II (LC 167)
----------------------------------------------------------------

  Input:  sorted array, find indices i,j where nums[i]+nums[j]=target
  Output: [i+1, j+1] (1-indexed)

  nums = [2, 7, 11, 15],  target = 9
          l               r
  2+15=17 > 9  --> r--
  2+11=13 > 9  --> r--
  2+7 = 9 == 9 --> return [1, 2]

  Java:
    public int[] twoSum(int[] numbers, int target) {
        int l = 0, r = numbers.length - 1;
        while (l < r) {
            int sum = numbers[l] + numbers[r];
            if (sum == target) return new int[]{l + 1, r + 1};
            else if (sum < target) l++;
            else r--;
        }
        return new int[]{-1, -1};
    }

  Time: O(n)  Space: O(1)

----------------------------------------------------------------
PROBLEM 2: CONTAINER WITH MOST WATER (LC 11)
----------------------------------------------------------------

  Area = min(height[l], height[r]) * (r - l)
  Greedy choice: move the SHORTER side inward.
  Reason: keeping the shorter side can never increase the area
  (width decreases, height can only stay <= current min).

  height = [1,8,6,2,5,4,8,3,7]
             l                r

  area = min(1,7) * 8 = 8   move l (shorter)
  area = min(8,7) * 7 = 49  move r
  ... continue until l >= r

  Java:
    public int maxArea(int[] height) {
        int l = 0, r = height.length - 1, max = 0;
        while (l < r) {
            max = Math.max(max, Math.min(height[l], height[r]) * (r - l));
            if (height[l] < height[r]) l++;
            else r--;
        }
        return max;
    }

  Time: O(n)  Space: O(1)

----------------------------------------------------------------
PROBLEM 3: VALID PALINDROME (LC 125)
----------------------------------------------------------------

  Skip non-alphanumeric. Compare lowercase chars.
  Stop if mismatch found.

  Java:
    public boolean isPalindrome(String s) {
        int l = 0, r = s.length() - 1;
        while (l < r) {
            while (l < r && !Character.isLetterOrDigit(s.charAt(l))) l++;
            while (l < r && !Character.isLetterOrDigit(s.charAt(r))) r--;
            if (l < r) {
                if (Character.toLowerCase(s.charAt(l)) !=
                    Character.toLowerCase(s.charAt(r)))
                    return false;
                l++; r--;
            }
        }
        return true;
    }

  Time: O(n)  Space: O(1)

----------------------------------------------------------------
PROBLEM 4: REVERSE ARRAY / STRING (classic)
----------------------------------------------------------------

  Swap elements from both ends, working inward.

  Java:
    public void reverse(int[] arr) {
        int l = 0, r = arr.length - 1;
        while (l < r) {
            int tmp = arr[l];
            arr[l++] = arr[r];
            arr[r--] = tmp;
        }
    }

  Time: O(n)  Space: O(1)

----------------------------------------------------------------
PROBLEM 5: TRAPPING RAIN WATER (LC 42) -- Two-Pointer Version
----------------------------------------------------------------

  Key insight: water at position i = min(maxLeft[i], maxRight[i]) - height[i]
  Instead of precomputing, track running maxLeft and maxRight as
  pointers converge.

  Rule: process the side with the SMALLER max.
    - If maxL <= maxR: water[l] = maxL - height[l]; l++
    - Else:           water[r] = maxR - height[r]; r--

  Java:
    public int trap(int[] height) {
        int l = 0, r = height.length - 1;
        int maxL = 0, maxR = 0, water = 0;
        while (l < r) {
            if (height[l] <= height[r]) {
                if (height[l] >= maxL) maxL = height[l];
                else water += maxL - height[l];
                l++;
            } else {
                if (height[r] >= maxR) maxR = height[r];
                else water += maxR - height[r];
                r--;
            }
        }
        return water;
    }

  Time: O(n)  Space: O(1)

----------------------------------------------------------------
PATTERN: SORTED ARRAY + ELIMINATE HALF EACH STEP
----------------------------------------------------------------

  All opposite-direction two pointer problems share:

    1. A sorted (or structured) input
    2. A value to optimize or match (sum, area, difference)
    3. A clear rule to move l or r
    4. Termination when l >= r

  The "which pointer to move" rule is always derived from:
  "Which move gives me more information / can still improve?"

  - Sum < target: l++ (current right is useless with this left)
  - Sum > target: r-- (current left is useless with this right)
  - Area: move shorter side (longer can never improve with smaller width)
  - Water: move smaller max (the other side is the bottleneck)

----------------------------------------------------------------
COMPLEXITY COMPARISON
----------------------------------------------------------------

  Approach           Time     Space
  ---------          ----     -----
  Brute Force        O(n^2)   O(1)
  Two Pointers       O(n)     O(1)

  Sorting for preprocessing: O(n log n) -- usually still worth it.

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: Why move the shorter bar in Container With Most Water?
  A: Because the area is limited by the shorter bar. Moving it
     inward is the only chance to find a taller bar that might
     yield more area. Moving the taller bar guarantees smaller width
     with no chance of increasing the limiting height.

  Q: When can't you use opposite two pointers?
  A: When the array isn't sorted and sorting changes meaning,
     OR when you need positions in the original array (sorting
     destroys original indices), OR when order matters.

  Q: Two Sum II vs Two Sum I -- what's different?
  A: Two Sum II guarantees sorted input -> two pointers O(n) O(1).
     Two Sum I is unsorted -> needs HashMap for O(n) O(n).

  Q: Can two pointers ever fail on a sorted array?
  A: No, as long as there's exactly one valid pair. If multiple
     pairs are needed, collect and continue (or handle carefully).

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------

  - Confirm the array is sorted before applying this pattern.
  - State your movement rule explicitly: "I move l when X because Y."
  - Trace 2-3 iterations on the whiteboard to show correctness.
  - For palindrome, clean the string mentally before explaining.
