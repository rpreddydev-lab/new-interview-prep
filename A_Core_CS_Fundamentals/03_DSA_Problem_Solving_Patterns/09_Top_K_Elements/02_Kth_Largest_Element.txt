================================================================
  KTH LARGEST ELEMENT IN AN ARRAY (LC 215)
================================================================

  Find the kth largest element in an unsorted array.
  Note: kth largest means kth in sorted descending order.
  NOT the kth distinct element.

  Input:  nums = [3,2,1,5,6,4], k = 2
  Output: 5

  Input:  nums = [3,2,3,1,2,4,5,5,6], k = 4
  Output: 4

----------------------------------------------------------------
APPROACH 1: MIN-HEAP OF SIZE K
----------------------------------------------------------------

  Maintain a min-heap of size k.
  Min-heap invariant: all k elements are larger than any element not in heap.
  The root (min of heap) is the kth largest.

  Java:
    public int findKthLargest(int[] nums, int k) {
        PriorityQueue<Integer> minHeap = new PriorityQueue<>();

        for (int num : nums) {
            minHeap.offer(num);
            if (minHeap.size() > k) {
                minHeap.poll();   // remove smallest, keep only k largest
            }
        }
        return minHeap.peek();   // min of the k largest = kth largest
    }

  Time: O(n log k)   Space: O(k)

  Trace for [3,2,1,5,6,4], k=2:
    add 3 --> heap=[3]          size=1
    add 2 --> heap=[2,3]        size=2
    add 1 --> heap=[2,3,1], pop 1 --> heap=[2,3]   wait, recheck...
             offer(1) size=3 > k=2, poll() removes min=1 --> heap=[2,3]
    add 5 --> offer(5) size=3 > 2, poll() removes 2 --> heap=[3,5]
    add 6 --> offer(6) size=3 > 2, poll() removes 3 --> heap=[5,6]
    add 4 --> offer(4) size=3 > 2, poll() removes 4 --> heap=[5,6]
    peek() = 5 ✓

----------------------------------------------------------------
APPROACH 2: QUICKSELECT (O(n) AVERAGE)
----------------------------------------------------------------

  Based on QuickSort's partition step.
  After partitioning around pivot, the pivot is in its final sorted position.
  If pivot is at the target index, done. Otherwise recurse on one side only.

  Target: kth largest = index (n - k) in ascending sorted order.

  Java:
    public int findKthLargest(int[] nums, int k) {
        int n = nums.length;
        return quickSelect(nums, 0, n - 1, n - k);
    }

    private int quickSelect(int[] nums, int lo, int hi, int target) {
        if (lo == hi) return nums[lo];
        int pivot = partition(nums, lo, hi);
        if (pivot == target) return nums[pivot];
        else if (pivot < target) return quickSelect(nums, pivot + 1, hi, target);
        else return quickSelect(nums, lo, pivot - 1, target);
    }

    private int partition(int[] nums, int lo, int hi) {
        int pivot = nums[hi];
        int i = lo;
        for (int j = lo; j < hi; j++) {
            if (nums[j] <= pivot) swap(nums, i++, j);
        }
        swap(nums, i, hi);
        return i;
    }

    private void swap(int[] nums, int i, int j) {
        int tmp = nums[i]; nums[i] = nums[j]; nums[j] = tmp;
    }

  Time: O(n) average, O(n²) worst   Space: O(1) iterative / O(log n) recursive

  RANDOM PIVOT (avoids worst case):
    int randIdx = lo + new Random().nextInt(hi - lo + 1);
    swap(nums, randIdx, hi);
    // then partition as normal

----------------------------------------------------------------
QUICKSELECT TRACE: [3,2,1,5,6,4], k=2, target=4
----------------------------------------------------------------

  quickSelect(0,5,4)
    partition: pivot=4, final position?
      j=0: 3<=4, swap(0,0), i=1
      j=1: 2<=4, swap(1,1), i=2
      j=2: 1<=4, swap(2,2), i=3
      j=3: 5>4, skip
      j=4: 6>4, skip
      swap(3,5): [3,2,1,4,6,5]  pivot at index 3
    pivot=3 < target=4 --> recurse right: quickSelect(4,5,4)
  quickSelect(4,5,4)
    partition: pivot=nums[5]=5
      j=4: 6>5, skip
      swap(4,5): [3,2,1,4,5,6]  pivot at index 4
    pivot=4 == target=4 --> return nums[4] = 5 ✓

----------------------------------------------------------------
APPROACH 3: SORTING (SIMPLE BUT SLOWER)
----------------------------------------------------------------

    Arrays.sort(nums);
    return nums[nums.length - k];

  Time: O(n log n)   Space: O(log n) sort overhead

----------------------------------------------------------------
APPROACH 4: PARTIAL SORT WITH BUCKET (When Range is Bounded)
----------------------------------------------------------------

  If nums are bounded (e.g., [-10^4, 10^4]):
    Use counting array, walk from max down to find kth.
    Time: O(n + range)   Space: O(range)

----------------------------------------------------------------
VARIANTS
----------------------------------------------------------------

  LC 703 Kth Largest Element in a Stream:
    Constructor initializes min-heap with first k elements.
    add(val): offer val, if size > k then poll, return peek.

    class KthLargest {
        private PriorityQueue<Integer> heap = new PriorityQueue<>();
        private int k;

        public KthLargest(int k, int[] nums) {
            this.k = k;
            for (int n : nums) add(n);
        }

        public int add(int val) {
            heap.offer(val);
            if (heap.size() > k) heap.poll();
            return heap.peek();
        }
    }

  LC 378 Kth Smallest Element in Sorted Matrix:
    Use min-heap of (val, row, col). Start with first column.
    Poll k times, each time push (row+1, col) and right neighbor if needed.

  LC 414 Third Maximum Number:
    TreeSet (sorted set), keep max 3. Third max = first (least) of set.

----------------------------------------------------------------
COMPLEXITY COMPARISON
----------------------------------------------------------------

  Method         Time             Space    Notes
  --------------------------------------------------------
  Min-Heap       O(n log k)       O(k)     Streaming, k << n
  QuickSelect    O(n) avg, O(n²)  O(1)     Modifies array, random pivot
  Sort           O(n log n)       O(log n) Simple, when sorting anyway
  Counting       O(n + range)     O(range) Bounded integers only

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: Why use a MIN-heap for kth largest (not max-heap)?
  A: A min-heap of size k always has the k largest elements seen so far.
     The min of those k elements is the kth largest.
     If we used a max-heap, we'd need to pop k times to get the answer.

  Q: When would you prefer QuickSelect over heap?
  A: QuickSelect is O(n) average vs O(n log k) for heap.
     Prefer QuickSelect when: k is large, n is large, and array can be modified.
     Prefer heap when: streaming data, k is small, array is immutable.

  Q: QuickSelect worst case is O(n²). How to avoid?
  A: Use a random pivot to avoid sorted/reverse-sorted worst case.
     Or use median-of-medians for guaranteed O(n), but that's complex.

  Q: What's kth largest vs kth in sorted order?
  A: [3,1,4,1,5,9], k=3: sorted desc=[9,5,4,3,1,1], 3rd largest=4.
     Not 3rd distinct — kth largest counts duplicates.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------

  - State both heap and QuickSelect upfront, explain tradeoffs.
  - For heap: draw the heap invariant (k elements = k largest).
  - For QuickSelect: explain it's like partition in QuickSort.
  - Use random pivot in production code for safety.
  - LC 215 is a very common FAANG interview question — know both approaches cold.
