================================================================
  FIND MIDDLE OF LINKED LIST (LC 876)
  And Related: Palindrome LL, Reorder List
================================================================

----------------------------------------------------------------
PROBLEM STATEMENT
----------------------------------------------------------------

  Given the head of a singly linked list, return the middle node.
  If there are two middle nodes (even length), return the second one.

  Input:  1 -> 2 -> 3 -> 4 -> 5
  Output: Node 3 (the middle node, value 3)

  Input:  1 -> 2 -> 3 -> 4
  Output: Node 3 (second of two midpoints)

----------------------------------------------------------------
APPROACH: FAST & SLOW POINTERS
----------------------------------------------------------------

  When fast reaches the end, slow is at the middle.
  - Odd length: fast reaches last node (fast.next == null)
  - Even length: fast reaches beyond last node (fast == null)
  Both cases terminate with the same condition:
    while (fast != null && fast.next != null)

  Java:
    public ListNode middleNode(ListNode head) {
        ListNode slow = head, fast = head;
        while (fast != null && fast.next != null) {
            slow = slow.next;
            fast = fast.next.next;
        }
        return slow;
    }

  Time: O(n)  Space: O(1)

----------------------------------------------------------------
TRACE THROUGH -- ODD LENGTH
----------------------------------------------------------------

  List: 1 -> 2 -> 3 -> 4 -> 5

  Start: slow=1, fast=1
  Step 1: slow=2, fast=3   (fast: 1->2->3)
  Step 2: slow=3, fast=5   (fast: 3->4->5)
  Check: fast.next = null. While condition: fast != null is true,
         fast.next != null is false. STOP.
  Return slow = 3 ✓ (middle of 5 elements)

----------------------------------------------------------------
TRACE THROUGH -- EVEN LENGTH
----------------------------------------------------------------

  List: 1 -> 2 -> 3 -> 4

  Start: slow=1, fast=1
  Step 1: slow=2, fast=3   (fast: 1->2->3)
  Step 2: slow=3, fast=null (fast: 3->4->null)
  Check: fast = null. While condition fails. STOP.
  Return slow = 3 ✓ (second of two midpoints)

  If we want the FIRST midpoint (node 2):
  Use: while (fast.next != null && fast.next.next != null)

----------------------------------------------------------------
VARIANT: GET FIRST MIDPOINT FOR EVEN LENGTH
----------------------------------------------------------------

  For even-length lists, this returns the first middle node.

  Java:
    public ListNode middleNodeFirst(ListNode head) {
        ListNode slow = head, fast = head;
        while (fast.next != null && fast.next.next != null) {
            slow = slow.next;
            fast = fast.next.next;
        }
        return slow;
    }

  Comparison:
    List: 1->2->3->4
    Standard:    returns 3 (second middle)
    FirstMiddle: returns 2 (first middle)

  Use "first middle" variant when you need to SPLIT the list in half.

----------------------------------------------------------------
APPLICATION: PALINDROME LINKED LIST (LC 234)
----------------------------------------------------------------

  Determine if a linked list is a palindrome.

  Algorithm:
    1. Find middle of list (fast/slow)
    2. Reverse the second half
    3. Compare first half with reversed second half
    4. (Optional) Restore the list

  Java:
    public boolean isPalindrome(ListNode head) {
        // Step 1: Find middle
        ListNode slow = head, fast = head;
        while (fast != null && fast.next != null) {
            slow = slow.next;
            fast = fast.next.next;
        }
        // slow is now at the middle (second half start)

        // Step 2: Reverse second half
        ListNode prev = null, curr = slow;
        while (curr != null) {
            ListNode next = curr.next;
            curr.next = prev;
            prev = curr;
            curr = next;
        }
        // prev is now the head of reversed second half

        // Step 3: Compare
        ListNode left = head, right = prev;
        while (right != null) {  // second half might be shorter (odd length)
            if (left.val != right.val) return false;
            left = left.next;
            right = right.next;
        }
        return true;
    }

  Time: O(n)  Space: O(1)

  Example: 1->2->2->1
    Middle after fast/slow: slow=2 (third node)
    Reverse [2,1]: 1->2
    Compare [1,2] with [1,2]: equal --> palindrome ✓

  Example: 1->2->3->2->1
    Middle: slow=3
    Reverse [3,2,1]: 1->2->3
    Compare [1,2] with [1,2,3]: only check right.length=3 iterations... Wait.
    Actually right traverses: 1,2,3 and left traverses 1,2,3. All match. ✓

APPLICATION: REORDER LIST (LC 143)
----------------------------------------------------------------

  Reorder: 1->2->3->4->5 --> 1->5->2->4->3

  Algorithm:
    1. Find middle with slow/fast
    2. Split into two halves
    3. Reverse second half
    4. Merge two halves alternately

  Java:
    public void reorderList(ListNode head) {
        if (head == null || head.next == null) return;

        // Step 1: Find middle (use first-middle variant for even lists)
        ListNode slow = head, fast = head;
        while (fast.next != null && fast.next.next != null) {
            slow = slow.next;
            fast = fast.next.next;
        }

        // Step 2: Split (slow is end of first half)
        ListNode secondHalf = slow.next;
        slow.next = null;  // cut the list

        // Step 3: Reverse second half
        ListNode prev = null, curr = secondHalf;
        while (curr != null) {
            ListNode next = curr.next;
            curr.next = prev;
            prev = curr;
            curr = next;
        }
        // prev = head of reversed second half

        // Step 4: Merge alternately
        ListNode first = head, second = prev;
        while (second != null) {
            ListNode tmp1 = first.next;
            ListNode tmp2 = second.next;
            first.next = second;
            second.next = tmp1;
            first = tmp1;
            second = tmp2;
        }
    }

  Time: O(n)  Space: O(1)

----------------------------------------------------------------
MIDDLE NODE -- COMPARISON OF APPROACHES
----------------------------------------------------------------

  Approach      Time  Space  Notes
  --------      ----  -----  -----
  Count length  O(n)  O(1)   Two passes (count, then traverse to n/2)
  HashSet all   O(n)  O(n)   Store all nodes, access by index
  Fast/Slow     O(n)  O(1)   One pass, preferred

  Fast/Slow is optimal: single pass, O(1) space.

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: Why does slow end up at the middle when fast ends at null?
  A: Fast moves 2x the speed. When fast has covered all n nodes
     (or n-1 nodes), slow has covered n/2. At n/2 from the start
     = the middle. Mathematical invariant: slow = fast/2 always.

  Q: For even length, why does the standard approach return the
     SECOND middle?
  A: With fast starting at head and moving 2 steps, for n=4:
     fast covers nodes 1,3 (step 1) then 3,5 but 5 doesn't exist.
     Actually fast = head after step 2 is at null (4.next = null).
     slow is at node 3. Node 3 is the second of [2,3] midpoints.

  Q: When do we need the first middle vs second?
  A: For palindrome: second middle works (compare halves).
     For reorder/split: first middle needed to correctly divide.
     Using second middle for split would put more nodes in second half.

  Q: Can we find the 1/3 point or 2/3 point?
  A: Not directly with fast/slow (2x speed). For 1/3: use one pointer
     moving 1 step and another moving 3 steps.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------

  - Know both variants: standard (returns second middle) and
    first-middle (for splitting).
  - For LC 234 (palindrome): trace through the three-step algorithm
    (find middle, reverse, compare).
  - For LC 143 (reorder): mention all four steps.
  - Emphasize O(1) space -- no converting to array needed.
  - The "find middle" step is used as a building block in many
    other linked list problems.
