================================================================
  HAPPY NUMBER (LC 202)
  Fast & Slow Pointers on an Abstract Sequence
================================================================

----------------------------------------------------------------
PROBLEM STATEMENT
----------------------------------------------------------------

  A happy number is defined by the following process:
    1. Starting with any positive integer, replace the number
       by the sum of the squares of its digits.
    2. Repeat the process until the number either equals 1
       (where it will stay), or it loops endlessly in a cycle
       that does not include 1.

  Return true if the number is happy.

  Input:  n = 19
  Output: true
    19 -> 1^2 + 9^2 = 82
    82 -> 64 + 4    = 68
    68 -> 36 + 64   = 100
    100 -> 1        = 1 ✓

  Input:  n = 2
  Output: false (enters a cycle that doesn't include 1)

----------------------------------------------------------------
KEY INSIGHT
----------------------------------------------------------------

  This problem is disguised cycle detection.
  The sequence of numbers either:
    A) Eventually reaches 1 (happy number), OR
    B) Enters a cycle and never reaches 1.

  Both cases are detected by fast & slow pointers:
    - If happy: slow or fast will hit 1.
    - If unhappy: slow and fast will meet at some number != 1.

  We treat the sequence of numbers as a VIRTUAL linked list
  where each number's "next" is its digit-square sum.

----------------------------------------------------------------
JAVA CODE
----------------------------------------------------------------

  public boolean isHappy(int n) {
      int slow = n;
      int fast = getNext(n);

      while (fast != 1 && slow != fast) {
          slow = getNext(slow);
          fast = getNext(getNext(fast));
      }
      return fast == 1;
  }

  private int getNext(int n) {
      int sum = 0;
      while (n > 0) {
          int digit = n % 10;
          sum += digit * digit;
          n /= 10;
      }
      return sum;
  }

  Time: O(log n) per getNext call, O(log n) total iterations
  Space: O(1)

----------------------------------------------------------------
ALTERNATIVE: HASHSET
----------------------------------------------------------------

  Simpler to understand, but O(n) space.

  public boolean isHappy(int n) {
      Set<Integer> seen = new HashSet<>();
      while (n != 1) {
          if (seen.contains(n)) return false;
          seen.add(n);
          n = getNext(n);
      }
      return true;
  }

  Use fast/slow for O(1) space in interviews.

----------------------------------------------------------------
TRACE THROUGH: n = 2 (unhappy)
----------------------------------------------------------------

  The sequence for 2 is:
  2 -> 4 -> 16 -> 37 -> 58 -> 89 -> 145 -> 42 -> 20 -> 4 (cycle!)

  Fast/slow detection:
    slow starts at 2, fast starts at getNext(2) = 4.

  Iter  slow       fast
  0     2          4
  1     4          37       (slow: 2->4, fast: 4->16->37)
  2     16         145      (slow: 4->16, fast: 37->58->145)
  3     37         42       (slow: 16->37, fast: 145->42->...wait
                             145 -> 1^2+4^2+5^2 = 1+16+25 = 42
                             42  -> 4^2+2^2 = 16+4 = 20
                             fast at step: 145->42, then 42->20? No.
                             fast = getNext(getNext(145)) = getNext(42)
                             getNext(42) = 16+4 = 20. fast=20.

  Let me simplify: the algorithm terminates when slow==fast OR fast==1.
  Both stop conditions are correct.

  The important point: if n is not happy, the sequence MUST cycle
  (all values are bounded by some small range for large n, and the
  set of possible values is finite). The cycle is always reached.

  Known cycle for unhappy numbers (always enters this cycle):
  4 -> 16 -> 37 -> 58 -> 89 -> 145 -> 42 -> 20 -> 4 (loop)

----------------------------------------------------------------
WHY THE SEQUENCE IS BOUNDED
----------------------------------------------------------------

  For a number with d digits, the maximum digit-square sum is:
    d * 81 (if all digits are 9)

  For any 3-digit number (100-999):
    max digit sum = 3 * 81 = 243
  So all 3-digit numbers map to values <= 243.

  For 4-digit (1000-9999): max = 4*81 = 324.
  The sequence will always eventually be under 1000 and stay bounded.

  This guarantees the sequence either reaches 1 or enters a finite cycle.

----------------------------------------------------------------
GETNEXT IMPLEMENTATION DETAIL
----------------------------------------------------------------

  private int getNext(int n) {
      int sum = 0;
      while (n > 0) {
          int digit = n % 10;    // last digit
          sum += digit * digit;  // add digit squared
          n /= 10;               // remove last digit
      }
      return sum;
  }

  For n = 19:
    digit = 9, sum = 81, n = 1
    digit = 1, sum = 82, n = 0
    return 82 ✓

  For n = 100:
    digit = 0, sum = 0, n = 10
    digit = 0, sum = 0, n = 1
    digit = 1, sum = 1, n = 0
    return 1 ✓

----------------------------------------------------------------
WHY fast/slow WORKS HERE (VIRTUAL LIST)
----------------------------------------------------------------

  Conceptually, create a virtual linked list:
    2 -> 4 -> 16 -> 37 -> ... (each value's "next" is getNext(value))

  This virtual list either:
    - Has a "tail" ending in 1 (for happy numbers)
    - Has a cycle (for unhappy numbers)

  Fast & slow pointers on this virtual list work exactly like
  cycle detection on a real linked list:
    - If fast reaches 1: number is happy, return true
    - If fast == slow: cycle detected, return false

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: Why is this fast & slow pointers and not just a HashSet?
  A: Both work. Fast & slow is O(1) space. The interviewer might
     ask for optimal space, so knowing fast & slow is important.

  Q: What's the time complexity?
  A: The number of steps before reaching 1 or a cycle is O(log n).
     Each getNext call is O(log n) (number of digits). Total O(log^2 n).
     In practice treated as O(log n).

  Q: Can we prove that unhappy numbers always end up in the
     4->16->37->... cycle?
  A: Yes, by exhaustive enumeration of small values (under 1000 are
     all bounded). All unhappy numbers eventually enter this specific
     cycle. It's mathematically provable but not required for interview.

  Q: What if n = 1 is given directly?
  A: fast = getNext(1) = 1. While condition: fast != 1 is immediately
     false. Return fast == 1 = true. Correct.

  Q: Can n ever be 0?
  A: Problem states n >= 1, so no.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------

  - Start by explaining the key insight: "This is cycle detection
    on a virtual sequence."
  - Explain the while termination condition: "fast == 1 means happy,
    slow == fast means we entered a cycle."
  - If the interviewer asks for the O(1) space solution first, go
    directly to fast/slow without mentioning HashSet.
  - The getNext helper should be shown clearly (digit extraction).
  - Mention the intuition: "Any sequence of digit-square sums either
    terminates at 1 or cycles -- there's no other possibility."
