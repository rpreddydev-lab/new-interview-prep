================================================================
  DETECT CYCLE IN LINKED LIST (LC 141)
  Deep Dive
================================================================

----------------------------------------------------------------
PROBLEM STATEMENT
----------------------------------------------------------------

  Given the head of a linked list, determine if the linked list
  has a cycle in it.

  A cycle exists if a node can be reached again by continuously
  following the next pointer.

  Return true if cycle exists, false otherwise.

  Space constraint: O(1) memory solution required.

----------------------------------------------------------------
APPROACH 1: HASHSET (O(n) space -- NOT preferred)
----------------------------------------------------------------

  Store all visited nodes. If we see a node we've visited, cycle exists.

  Java:
    public boolean hasCycle(ListNode head) {
        Set<ListNode> visited = new HashSet<>();
        ListNode curr = head;
        while (curr != null) {
            if (visited.contains(curr)) return true;
            visited.add(curr);
            curr = curr.next;
        }
        return false;
    }

  Time: O(n)  Space: O(n) -- NOT O(1)

  Problem: uses O(n) extra space. Interviewers expect O(1).

----------------------------------------------------------------
APPROACH 2: FAST & SLOW POINTERS (O(1) space -- PREFERRED)
----------------------------------------------------------------

  Two pointer move through the list at different speeds.
  If there's a cycle, fast will eventually lap slow and they meet.
  If no cycle, fast reaches the end (null).

  Java:
    public boolean hasCycle(ListNode head) {
        ListNode slow = head, fast = head;
        while (fast != null && fast.next != null) {
            slow = slow.next;
            fast = fast.next.next;
            if (slow == fast) return true;
        }
        return false;
    }

  Time: O(n)  Space: O(1)

----------------------------------------------------------------
WHY THEY ALWAYS MEET (PROOF)
----------------------------------------------------------------

  Let:
    F = distance from head to cycle entry
    C = length of the cycle

  When slow enters the cycle, fast is already inside it.
  At that moment, fast is at position (2F mod C) in the cycle.
  Slow is at position 0 (just entered).

  The gap between fast and slow = 2F mod C steps (fast is ahead).
  But we measure "how far slow is behind fast" as:
    C - (2F mod C)  positions ahead of slow.

  Each step, fast gains 1 on slow. They meet in:
    C - (2F mod C) steps.

  Since this is a finite positive number, they ALWAYS meet.

  After meeting, they are at position (C - (2F mod C)) in the cycle.
  This meeting point is used in LC 142 to find the cycle start.

----------------------------------------------------------------
TRACE THROUGH
----------------------------------------------------------------

  Linked list: 3 -> 2 -> 0 -> -4 -> (back to 2, pos=1)
  pos=0 (3), pos=1 (2), pos=2 (0), pos=3 (-4), tail connects to pos=1 (2)

  Node addresses for clarity:
  A(3) -> B(2) -> C(0) -> D(-4) -> B  (back to B)

  Step 0: slow=A, fast=A
  Step 1: slow=B, fast=C    (slow: A->B, fast: A->B->C)
  Step 2: slow=C, fast=B    (slow: B->C, fast: C->D->B)
  Step 3: slow=D, fast=D    (slow: C->D, fast: B->C->D)
  MEET! slow==fast==D --> return true.

----------------------------------------------------------------
EDGE CASES
----------------------------------------------------------------

  1. Empty list (head == null):
     fast=null, while (null != null) is false, return false. ✓

  2. Single node, no cycle (head.next == null):
     fast=head, fast.next=null, while fails, return false. ✓

  3. Single node, self-loop (head.next == head):
     Step 1: slow=head, fast=head (fast jumps head->head->head=head)
     slow==fast? YES. Return true. ✓

  4. Two nodes, no cycle (A -> B -> null):
     Step 1: slow=B, fast=null (fast: A->B->null)
     Wait: fast.next.next = B.next = null.
     Actually: fast = fast.next.next. fast.next = B, B.next = null.
     So fast = null. While condition: fast != null fails. Return false. ✓

  5. Two nodes, cycle (A -> B -> A):
     Step 1: slow=B, fast=B (fast: A->B->A->B=B, wait...)
     fast = A.next.next = B.next = A. So fast=A.
     slow=B, fast=A. Not equal.
     Step 2: slow=A, fast=A. MEET! Return true. ✓

----------------------------------------------------------------
IMPLEMENTATION DETAILS
----------------------------------------------------------------

  Comparison: `slow == fast` compares OBJECT REFERENCES (memory
  addresses), not values. This is correct for cycle detection --
  we want to know if both pointers point to the SAME NODE OBJECT.

  In Java, always use == for reference comparison with nodes.
  Using .equals() would require custom implementation.

  ListNode definition:
    class ListNode {
        int val;
        ListNode next;
        ListNode(int x) {
            val = x;
            next = null;
        }
    }

----------------------------------------------------------------
FOLLOW-UP: DESTROY THE CYCLE
----------------------------------------------------------------

  If after detecting a cycle you need to unlink it (rare problem):
  Find the node JUST BEFORE the cycle start and set its next to null.
  (See cycle start detection for locating the entry point.)

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: What's the time complexity and why?
  A: O(n). If no cycle: fast reaches null in n/2 steps.
     If cycle: once both are in the cycle, fast closes the gap at
     1 node per step. Cycle length <= n. Total steps <= n.

  Q: Can you detect a cycle without modifying the list?
  A: Yes -- fast/slow pointers don't modify anything. The HashSet
     approach also doesn't modify. Modification would be marking
     visited nodes, which is destructive.

  Q: What's the simplest follow-up question?
  A: LC 142 -- Find where the cycle starts. Uses the same meeting
     point with a mathematical insight to find the entry node.

  Q: What if two separate lists both point to the same node?
  A: That's a different problem (Intersection of Two Linked Lists,
     LC 160). Not a cycle -- it's a Y-shaped merge.

  Q: Can you solve this without two pointers?
  A: With O(n) space: yes (HashSet). With O(1) space: fast/slow
     is the only classical approach.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------

  - Lead with the O(1) space solution (fast/slow), not the HashSet.
  - Explain the intuition before the code: "Like two runners on a
    circular track -- the faster one will always lap the slower one."
  - Trace 3-4 steps of the example on whiteboard.
  - Mention the null check: "fast != null AND fast.next != null to
    prevent NullPointerException."
  - The follow-up is always LC 142 -- be ready to extend to finding
    the cycle start.
