================================================================
  BFS ON GRAPHS
================================================================

  Graph BFS requires tracking visited nodes to avoid revisiting.
  Key difference from tree BFS: graphs can have cycles.

  MARK VISITED WHEN ADDING TO QUEUE (not when processing).
  Failing to do so causes the same node to be added multiple times.

----------------------------------------------------------------
CORE TEMPLATE: GRAPH BFS
----------------------------------------------------------------

  Java:
    public void bfs(int start, List<List<Integer>> adj) {
        int n = adj.size();
        boolean[] visited = new boolean[n];

        Queue<Integer> queue = new ArrayDeque<>();
        queue.offer(start);
        visited[start] = true;

        while (!queue.isEmpty()) {
            int curr = queue.poll();
            // process curr

            for (int neighbor : adj.get(curr)) {
                if (!visited[neighbor]) {
                    visited[neighbor] = true;   // mark BEFORE adding to queue
                    queue.offer(neighbor);
                }
            }
        }
    }

PROBLEM: NUMBER OF ISLANDS (LC 200)
----------------------------------------------------------------

  Given a 2D grid of '1' (land) and '0' (water), count islands.
  An island is surrounded by water and is formed by connecting
  adjacent lands horizontally or vertically.

  Input:
    11110
    11010
    11000
    00000
  Output: 1

  Input:
    11000
    11000
    00100
    00011
    Output: 3

  BFS Approach: iterate cells. When '1' found (unvisited), start BFS,
  flood-fill all connected land to visited, increment count.

  Java:
    public int numIslands(char[][] grid) {
        int rows = grid.length, cols = grid[0].length;
        int count = 0;
        int[][] dirs = {{0,1},{0,-1},{1,0},{-1,0}};

        for (int r = 0; r < rows; r++) {
            for (int c = 0; c < cols; c++) {
                if (grid[r][c] == '1') {
                    count++;
                    bfs(grid, r, c, rows, cols, dirs);
                }
            }
        }
        return count;
    }

    private void bfs(char[][] grid, int r, int c, int rows, int cols, int[][] dirs) {
        Queue<int[]> queue = new ArrayDeque<>();
        queue.offer(new int[]{r, c});
        grid[r][c] = '0';   // mark visited by sinking land

        while (!queue.isEmpty()) {
            int[] curr = queue.poll();
            for (int[] dir : dirs) {
                int nr = curr[0] + dir[0], nc = curr[1] + dir[1];
                if (nr >= 0 && nr < rows && nc >= 0 && nc < cols && grid[nr][nc] == '1') {
                    grid[nr][nc] = '0';   // mark before adding
                    queue.offer(new int[]{nr, nc});
                }
            }
        }
    }

  Time: O(m * n)   Space: O(min(m,n)) -- queue size bounded by shorter dimension

  Note: modifying grid avoids a separate visited array. If grid must
  be preserved, use boolean[][] visited.

PROBLEM: CLONE GRAPH (LC 133)
----------------------------------------------------------------

  Deep copy a graph. Each node has a val and a list of neighbors.

  Approach: BFS + HashMap<Node, Node> (original --> clone).

  Java:
    public Node cloneGraph(Node node) {
        if (node == null) return null;

        Map<Node, Node> cloneMap = new HashMap<>();
        Queue<Node> queue = new ArrayDeque<>();

        cloneMap.put(node, new Node(node.val));
        queue.offer(node);

        while (!queue.isEmpty()) {
            Node curr = queue.poll();
            for (Node neighbor : curr.neighbors) {
                if (!cloneMap.containsKey(neighbor)) {
                    cloneMap.put(neighbor, new Node(neighbor.val));
                    queue.offer(neighbor);
                }
                cloneMap.get(curr).neighbors.add(cloneMap.get(neighbor));
            }
        }
        return cloneMap.get(node);
    }

  Time: O(V + E)   Space: O(V)

PROBLEM: COURSE SCHEDULE — TOPOLOGICAL SORT BFS (LC 207)
----------------------------------------------------------------

  Given n courses and prerequisites (a, b) meaning b -> a,
  determine if all courses can be finished (no cycle).

  Kahn's Algorithm (BFS-based topological sort):
    1. Build adjacency list and in-degree array.
    2. Initialize queue with all nodes having in-degree 0.
    3. Process each node: reduce neighbors' in-degree by 1.
       If neighbor's in-degree becomes 0, add to queue.
    4. If we processed all n nodes, no cycle exists.

  Java:
    public boolean canFinish(int numCourses, int[][] prerequisites) {
        List<List<Integer>> adj = new ArrayList<>();
        int[] inDegree = new int[numCourses];

        for (int i = 0; i < numCourses; i++) adj.add(new ArrayList<>());
        for (int[] pre : prerequisites) {
            adj.get(pre[1]).add(pre[0]);   // pre[1] must come before pre[0]
            inDegree[pre[0]]++;
        }

        Queue<Integer> queue = new ArrayDeque<>();
        for (int i = 0; i < numCourses; i++) {
            if (inDegree[i] == 0) queue.offer(i);
        }

        int processed = 0;
        while (!queue.isEmpty()) {
            int course = queue.poll();
            processed++;
            for (int next : adj.get(course)) {
                if (--inDegree[next] == 0) queue.offer(next);
            }
        }
        return processed == numCourses;
    }

  Time: O(V + E)   Space: O(V + E)

  LC 210 Course Schedule II: same algorithm, but collect the processed
  nodes as the topological order.

PROBLEM: PACIFIC ATLANTIC WATER FLOW (LC 417)
----------------------------------------------------------------

  Water flows from a cell to adjacent cells with equal or lower height.
  Find cells that can reach BOTH the Pacific and Atlantic oceans.

  Multi-source BFS from all border cells:
    - Pacific border: top row + left column
    - Atlantic border: bottom row + right column

  BFS "uphill" (reverse direction): flow upward >= current height.

  Java:
    public List<List<Integer>> pacificAtlantic(int[][] heights) {
        int m = heights.length, n = heights[0].length;
        boolean[][] pac = new boolean[m][n], atl = new boolean[m][n];

        Queue<int[]> pQueue = new ArrayDeque<>(), aQueue = new ArrayDeque<>();
        for (int i = 0; i < m; i++) {
            pQueue.offer(new int[]{i, 0}); pac[i][0] = true;
            aQueue.offer(new int[]{i, n-1}); atl[i][n-1] = true;
        }
        for (int j = 0; j < n; j++) {
            pQueue.offer(new int[]{0, j}); pac[0][j] = true;
            aQueue.offer(new int[]{m-1, j}); atl[m-1][j] = true;
        }

        bfsOcean(pQueue, pac, heights, m, n);
        bfsOcean(aQueue, atl, heights, m, n);

        List<List<Integer>> result = new ArrayList<>();
        for (int i = 0; i < m; i++)
            for (int j = 0; j < n; j++)
                if (pac[i][j] && atl[i][j])
                    result.add(Arrays.asList(i, j));
        return result;
    }

    private void bfsOcean(Queue<int[]> queue, boolean[][] reach, int[][] h, int m, int n) {
        int[][] dirs = {{0,1},{0,-1},{1,0},{-1,0}};
        while (!queue.isEmpty()) {
            int[] curr = queue.poll();
            for (int[] dir : dirs) {
                int nr = curr[0]+dir[0], nc = curr[1]+dir[1];
                if (nr>=0 && nr<m && nc>=0 && nc<n && !reach[nr][nc]
                    && h[nr][nc] >= h[curr[0]][curr[1]]) {
                    reach[nr][nc] = true;
                    queue.offer(new int[]{nr, nc});
                }
            }
        }
    }

  Time: O(m*n)   Space: O(m*n)

----------------------------------------------------------------
COMMON MISTAKES
----------------------------------------------------------------

  1. Marking visited AFTER polling (not when offering):
     Same node added multiple times, causing TLE or wrong results.

  2. Forgetting to initialize all components in disconnected graphs:
     Iterate over ALL nodes and BFS from each unvisited one.

  3. For Course Schedule: confusing which direction edges go.
     prereq[0] depends on prereq[1], so edge goes prereq[1] -> prereq[0].

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: Why mark visited when adding to queue, not when popping?
  A: Consider two nodes both adjacent to node X. If X isn't marked when
     added, both can add X to the queue. Then X is processed twice,
     causing incorrect results or infinite loops in undirected graphs.

  Q: How is Kahn's algorithm different from DFS topological sort?
  A: Kahn's (BFS): iteratively removes sources (nodes with in-degree 0).
     DFS: post-order DFS, reverse the post-order gives topological order.
     Both detect cycles. Kahn's is often more intuitive.

  Q: Can BFS detect a cycle?
  A: For undirected graphs: if a visited neighbor is not the parent.
     For directed graphs: Kahn's detects cycle if processed < n.
     DFS with WHITE/GRAY/BLACK coloring is more common for directed cycles.

----------------------------------------------------------------
INTERVIEW TIPS
----------------------------------------------------------------

  - State the visited-before-add rule explicitly.
  - For island problems: sinking the cell in-place is a common trick.
  - For clone graph: HashMap maps original to clone, preventing re-cloning.
  - For topological sort (Kahn's), emphasize the in-degree approach.
