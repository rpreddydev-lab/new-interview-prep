  AUTOCOMPLETE SYSTEM AND DESIGN PROBLEMS — LC 642 / LC 1268 / LC 14
================================================================

  LC 642: Design Search Autocomplete System.
          Initialize with a list of sentences and their "times" typed.
          As user types character by character, return top 3 hot sentences
          (highest times). Tie-break: ASCII order.

  LC 1268: Search Suggestions System.
           Given products list and searchWord typed character by character,
           return 3 products with matching prefix (lexicographically sorted).

  LC 14: Longest Common Prefix of a list of strings.

----------------------------------------------------------------
LC 14 — LONGEST COMMON PREFIX (WARMUP)
----------------------------------------------------------------

  Find the longest common prefix string amongst an array of strings.

  Approach 1 — Vertical scanning (character by character):
  Java:
    public String longestCommonPrefix(String[] strs) {
        if (strs.length == 0) return "";
        for (int i = 0; i < strs[0].length(); i++) {
            char c = strs[0].charAt(i);
            for (int j = 1; j < strs.length; j++) {
                if (i >= strs[j].length() || strs[j].charAt(i) != c) {
                    return strs[0].substring(0, i);
                }
            }
        }
        return strs[0];
    }

  Time: O(S) where S = total characters across all strings. Space: O(1).

  Approach 2 — Trie-based:
    Insert all strings. Traverse trie from root: follow single child until
    branch (>1 child) or isEnd encountered.

  Approach 3 — Sort + compare first and last:
    Sort array. Longest common prefix of all = LCP(first, last after sort).

  Java:
    public String longestCommonPrefix(String[] strs) {
        Arrays.sort(strs);
        String first = strs[0], last = strs[strs.length - 1];
        int i = 0;
        while (i < first.length() && i < last.length() && first.charAt(i) == last.charAt(i)) i++;
        return first.substring(0, i);
    }

  Time: O(N log N + L). Fast in practice.

LC 1268 — SEARCH SUGGESTIONS SYSTEM
----------------------------------------------------------------

  Input: products = ["mobile","mouse","moneypot","monitor","mousepad"]
         searchWord = "mouse"

  Output: After typing 'm':     [mobile, moneypot, monitor]
          After typing 'mo':    [mobile, moneypot, monitor]
          After typing 'mou':   [mouse, mousepad]
          After typing 'mous':  [mouse, mousepad]
          After typing 'mouse': [mouse, mousepad]

  Approach 1 — Sort + Binary Search:
    Sort products. For each prefix, binary search for first product >= prefix,
    then collect at most 3 products that start with prefix.

  Java:
    public List<List<String>> suggestedProducts(String[] products, String searchWord) {
        Arrays.sort(products);
        List<List<String>> result = new ArrayList<>();
        String prefix = "";
        for (char c : searchWord.toCharArray()) {
            prefix += c;
            int start = lowerBound(products, prefix);
            List<String> suggestions = new ArrayList<>();
            for (int i = start; i < Math.min(start + 3, products.length); i++) {
                if (products[i].startsWith(prefix)) suggestions.add(products[i]);
                else break;
            }
            result.add(suggestions);
        }
        return result;
    }

    int lowerBound(String[] arr, String prefix) {
        int lo = 0, hi = arr.length;
        while (lo < hi) {
            int mid = (lo + hi) / 2;
            if (arr[mid].compareTo(prefix) < 0) lo = mid + 1;
            else hi = mid;
        }
        return lo;
    }

  Time: O(N log N + L * (log N + result))   Space: O(1) extra (result only).

  Approach 2 — Trie:
    Insert all products. For each prefix, traverse trie to prefix node,
    then DFS to collect up to 3 words (DFS in sorted order naturally).

  Java (Trie approach):
    class AutoSuggest {
        TrieNode root = new TrieNode();

        void insert(String word) {
            TrieNode cur = root;
            for (char c : word.toCharArray()) {
                int i = c - 'a';
                if (cur.ch[i] == null) cur.ch[i] = new TrieNode();
                cur = cur.ch[i];
            }
            cur.isEnd = true;
        }

        List<String> suggest(String prefix) {
            TrieNode cur = root;
            for (char c : prefix.toCharArray()) {
                int i = c - 'a';
                if (cur.ch[i] == null) return new ArrayList<>();
                cur = cur.ch[i];
            }
            List<String> result = new ArrayList<>();
            dfsCollect(cur, new StringBuilder(prefix), result);
            return result;
        }

        void dfsCollect(TrieNode node, StringBuilder path, List<String> result) {
            if (result.size() == 3) return;
            if (node.isEnd) result.add(path.toString());
            for (int i = 0; i < 26; i++) {
                if (node.ch[i] != null) {
                    path.append((char)('a' + i));
                    dfsCollect(node.ch[i], path, result);
                    path.deleteCharAt(path.length() - 1);
                }
            }
        }
    }

  Note: DFS in order (i=0..25 = 'a'..'z') gives lexicographically sorted results.

LC 642 — DESIGN SEARCH AUTOCOMPLETE SYSTEM
----------------------------------------------------------------

  Constraints:
    - Constructor: list of sentences + their times.
    - input(char c): if c != '#', add to current input, return top 3.
    - if c == '#', save current sentence with incremented count, reset.
    - Top 3: by times (descending). Tie: ASCII order (ascending).

  Java:
    class AutocompleteSystem {
        private static class TrieNode {
            TrieNode[] ch = new TrieNode[128];  // ASCII range
            Map<String, Integer> sentences = new HashMap<>();  // sentence → count at this prefix
        }

        private TrieNode root = new TrieNode();
        private String current = "";

        private void insert(String s, int times) {
            TrieNode cur = root;
            for (char c : s.toCharArray()) {
                if (cur.ch[c] == null) cur.ch[c] = new TrieNode();
                cur = cur.ch[c];
                cur.sentences.merge(s, times, Integer::sum);  // accumulate count
            }
        }

        public AutocompleteSystem(String[] sentences, int[] times) {
            for (int i = 0; i < sentences.length; i++) {
                insert(sentences[i], times[i]);
            }
        }

        public List<String> input(char c) {
            if (c == '#') {
                insert(current, 1);  // save new sentence
                current = "";
                return new ArrayList<>();
            }
            current += c;
            // Navigate to current prefix node
            TrieNode cur = root;
            for (char ch : current.toCharArray()) {
                if (cur.ch[ch] == null) return new ArrayList<>();
                cur = cur.ch[ch];
            }
            // Get top 3 from sentences map at this node
            return cur.sentences.entrySet().stream()
                .sorted((a, b) -> a.getValue().equals(b.getValue())
                        ? a.getKey().compareTo(b.getKey())
                        : b.getValue() - a.getValue())
                .limit(3)
                .map(Map.Entry::getKey)
                .collect(Collectors.toList());
        }
    }

  Time per input: O(P * sort) where P = prefix length, sort = O(K log K) for K sentences.
  Space: O(N * L * L) — each prefix node stores all matching sentences.

  Note: At each TrieNode, we store ALL sentences that have this prefix.
        This is space-heavy but gives fast retrieval.
        Alternative: store nothing at node, DFS at query time — slower but less space.

----------------------------------------------------------------
AUTOCOMPLETE DESIGN COMPARISON
----------------------------------------------------------------

  Approach          Space                   Query Time              Notes
  ---------------   ---------------------   ---------------------   -----------------
  Brute force       O(N*L)                  O(N*L) scan all         Simple but slow
  Sort + BinSearch  O(N*L) (sorted arr)     O(log N + L)            Clean, practical
  Trie (basic)      O(alphabet*N*L)         O(L + output_size)      Good prefix lookup
  Trie+sentence map O(N*L + prefix*K)       O(L + K log K)          Fast but space-heavy
  Trie+TopK cached  O(N*L + N*3)            O(L)                    Cache top-3 at each node

----------------------------------------------------------------
LC 642 FOLLOW-UP: CACHING TOP-3 AT EACH NODE
----------------------------------------------------------------

  Instead of sorting at query time, maintain a sorted list of top-3 at every TrieNode.
  Update on insert: potentially modify top-3 lists along the path.

  Trade-off: O(1) query for top-3, but O(L * 3) update per insert.
             More complex to implement but fast for high query volume.

----------------------------------------------------------------
INTERVIEW Q&A
----------------------------------------------------------------

  Q: Why store the full sentence map at each TrieNode in LC 642?
  A: Avoids DFS at query time. Each node knows exactly which sentences pass through it
     and their counts. Query = navigate to prefix node + sort map.

  Q: LC 1268 — which approach is better, sort+binary search or trie?
  A: Sort+binary search is simpler to code and O(N log N) upfront.
     Trie is better when you have many queries on the same products set (O(1) after build).
     For single searchWord, sort+binary search is preferred.

  Q: Why does DFS in alphabetical order (i=0..25) give lex-sorted output?
  A: Children are stored in array[26]. Iterating i=0 ('a') to i=25 ('z') guarantees
     alphabetical traversal. No sorting needed for output.

  Q: In LC 14 (LCP), why does comparing only first and last (after sort) work?
  A: After lexicographic sorting, any pair of strings in the array has an LCP that is
     >= LCP(first, last). So the overall LCP equals LCP(first, last).

INTERVIEW TIPS
----------------------------------------------------------------

  - LC 14: know all 3 approaches. Sort+compare first/last is the slickest.
  - LC 1268: sort+binary search is the go-to solution, mention trie for follow-up.
  - LC 642: this is a design problem — discuss trade-offs before coding.
    "I'll store sentences with counts at each node for O(L) navigation,
     then sort the K matches at the prefix node for top-3."
  - Always clarify: does 'input' return for '#' character? (No, return empty list and reset.)
